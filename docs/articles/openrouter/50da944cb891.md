# 推出 Extractions API

William Kofski ·11/10/2026

Extractions API 现已在 OpenRouter 上线，处于 alpha 阶段。你只需描述需要的字段，就能从文本、图片和 PDF 里抽出具体信息，比如邮件里的人名，或收据上的总金额。

首发带来三个抽取模型，分别来自 Cloudflare、Inception 和 ScaleDown。可以先读 [docs](https://openrouter.ai/docs/guides/community/extractions)，或到 [Playground](https://openrouter.ai/cloudflare/clairic#playground) 里试一试。

## 什么是 Extractions？

一次 extraction 就是一个请求：你点名要从文档里取哪些字段，每个字段拿回一个带类型的值。`state` 承载文本（或 `assets` 里某张图片、某个 PDF 的键），`fields` 把每个字段名映射到一份规格：一个 `type`，以及可选的、说明该字段含义的 `instructions`。

共有九种字段类型，每种都返回可直接存储、无需解析的 JSON 类型。下面这张发票问到了其中六种，以 `state` 发送；表里示例是 Clairic 返回的结果，高亮的词就是值的来源：

state · 发票，以文本形式

Invoice INV-4417 from Larkspur Studio, issued 2026-10-14, payment terms net 45. Bill to: Harbor & Pine LLC. Contacts: Dana Ruiz (dana@harborpine.example), Priya Shah. Line items: brand audit 2,400.00; icon set 1,150.00; rush fee 300.00. Total due $3,850.00. Late payments accrue 1.5% per month.

请求的字段是 `invoice_number: text`、`total: number`、`due_date: date`、`contacts: list`、`po_number: text` 和 `days_to_pay: estimate`。

| 类型 | 你会得到 | 示例 |
| --- | --- | --- |
| `text` | 从文档读出的字符串 | `"INV-4417"` |
| `number` | 一个数字，带由你指定的 `decimals` 和 `unit` | `3850` |
| `date` | 一个 ISO 日期，读出或算出 | `"2026-11-28"` |
| `time` | 一个 ISO 时刻 | 这张发票未问到 |
| `datetime` | 一个 ISO 日期加时间 | 这张发票未问到 |
| `list` | 一个由 `text`、`number` 或 `date` 组成的数组（由 `items` 选定哪种） | `["Dana Ruiz", "Priya Shah"]` |
| `duration` | 一个以你选定 `unit` 计的数字，从秒到年 | `45` 带 `unit: "days"` |
| `estimate` | 针对文档隐含某个量的分布，介于你设定的 `min` 和 `max` 之间 | `median 45, p10 42, p90 47` |
| `forecast` | 同上，但按你设定的 `interval` 向未来推 `horizon` 步；`value`、`mean`、`median`、`p10` 和 `p90` 都是每步一个元素的数组 | 这张发票未问到 |

每个答案都带 `value`；此外还带什么，取决于字段类型和模型。在 Clairic 上，从文本读出的值会带 `span`，即指向 state 的 `[start, end)`（按 Unicode 码点计数），这样你就能切出文档片段、展示值的来源（`list` 带的是 `spans`，每项一个）。单值带 `p_null`，即文档在该字段上「什么都没有」的概率；当它超过 0.5 时值就变成 `null`（可按字段设 `null_threshold` 来挪动这条线），而 `guess` 是即便如此也最可能的值。它们还带 `confidence`，即模型对该值的把握；从图片读出的字符串会额外带 `spell_confidence`，表示拼写的可信度。`estimate` 或 `forecast` 不带置信度；`mean`、`median`、`p10` 和 `p90` 描述其分布，`p10` 到 `p90` 的宽度就是不确定性。Extract 每个值返回 `confidence`、不返回 `p_null`；对文本它也返回 spans，对 PDF 则不返回（第 3 节）。

这些字段构成了信任模型。设一条置信度下限，低于它的送人工处理，其余的直接存储。`null` 是一个答案，不是低分：模型判定该字段不存在（它的 `p_null` 过了阈值），而 `guess` 说的是它本来会取到的值。像 estimate 这样没有 `confidence` 的值，则改由它的分布来评判。

## 1：从文本抽取

输入是文档和一组带名字、带类型的字段。输出是每个字段一个值、从文本读出值时的 `span`、单值上的 `confidence` 与 `p_null`，以及 estimate 的分布。

在 Clairic 上以 $0.00011 跑出的请求：

```
curl https://openrouter.ai/api/alpha/extractions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "cloudflare/clairic",
    "state": "Invoice INV-4417 from Larkspur Studio, issued 2026-10-14, payment terms net 45. Bill to: Harbor & Pine LLC. Contacts: Dana Ruiz (dana@harborpine.example), Priya Shah. Line items: brand audit 2,400.00; icon set 1,150.00; rush fee 300.00. Total due $3,850.00. Late payments accrue 1.5% per month.",
    "fields": {
      "invoice_number": { "type": "text" },
      "total": { "type": "number", "decimals": 2, "unit": "USD" },
      "due_date": { "type": "date", "instructions": "Issue date plus the net payment days" },
      "contacts": { "type": "list", "items": "text", "instructions": "People named as contacts" },
      "po_number": { "type": "text", "instructions": "Purchase order number, if any" },
      "days_to_pay": { "type": "estimate", "min": 0, "max": 120, "step": 1, "instructions": "How many days after issue this invoice will actually be paid" }
    },
    "reference_date": "2026-11-06"
  }'
```

Clairic 读了 1,138 个 input token，回答如下（响应里省去了 `model` 那一行）：

```
{
  "answers": {
    "invoice_number": { "type": "text", "value": "INV-4417", "span": [8, 16], "p_null": 4.9e-6, "confidence": 0.9999 },
    "total": { "type": "number", "value": 3850, "p_null": 1.6e-5, "confidence": 0.9999 },
    "due_date": { "type": "date", "value": "2026-11-28", "p_null": 4.4e-5, "confidence": 0.9994 },
    "contacts": { "type": "list", "value": ["Dana Ruiz", "Priya Shah"], "spans": [[118, 127], [155, 165]] },
    "po_number": { "type": "text", "value": null, "guess": "INV-4417", "p_null": 0.9999 },
    "days_to_pay": { "type": "estimate", "value": 45, "mean": 44.79, "median": 45, "p10": 42, "p90": 47 }
  },
  "truncated": false,
  "usage": { "input_tokens": 1138, "output_tokens": 0, "cost": 0.0001138, "state_tokens": 118, "schema_tokens": 666, "passes": 4 },
  "id": "gen-dec-1794000212-JVtrkaQ2JbqaR59u2bjZ",
  "provider": "Cloudflare"
}
```

`due_date` 在文本里没有日期，于是模型根据开票日和账期算了出来；`po_number` 返回 `null`，`guess` 显示了它本来会取到的值；`days_to_pay` 是 `estimate`，因此返回的不是单点而是分布，80% 的概率质量落在 42 到 47 天之间。用每个 `span` 切 state，就能把证据摆在值旁边。在 Python 里，用 `r` 表示上面那次调用的 `requests` 响应：

```
state = "Invoice INV-4417 from Larkspur Studio, issued 2026-10-14, payment terms net 45. Bill to: Harbor & Pine LLC. Contacts: Dana Ruiz (dana@harborpine.example), Priya Shah. Line items: brand audit 2,400.00; icon set 1,150.00; rush fee 300.00. Total due $3,850.00. Late payments accrue 1.5% per month."
answers = r.json()["answers"]

for name, answer in answers.items():
    spans = answer.get("spans") or ([answer["span"]] if answer.get("span") else [])
    evidence = [state[start:end] for start, end in spans]
    print(f"{name}: {answer['value']!r} <- {evidence!r}")
```

## 2：从图片抽取

输入是放在 `assets` 里、由 `state` 通过键引用的图片，外加同样形式的字段清单。输出是同样结构的记录，模型判定为「从图上读出」的值会带 `source: "image"`（`source` 是可选的，下面的 `paid_on` 就没有，所以别拿它当键），文本还带 `spell_confidence`。视频里照片上的框是为演示画的；API 返回的是值，不是图片坐标。

在 Clairic 上以 $0.00025 跑出的请求：

```
import base64
import os

import requests

API = "https://openrouter.ai/api/alpha/extractions"
HEADERS = {"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"}

with open("receipt.png", "rb") as f:
    receipt = base64.b64encode(f.read()).decode()

r = requests.post(
    API,
    headers=HEADERS,
    json={
        "model": "cloudflare/clairic",
        "state": "receipt",
        "assets": {"receipt": {"type": "image", "format": "png", "data_base64": receipt}},
        "fields": {
            "merchant": {"type": "text"},
            "total": {"type": "number", "decimals": 2},
            "paid_on": {"type": "date"},
            "tax": {"type": "number", "decimals": 2, "instructions": "Sales tax charged"},
            "tip": {"type": "number", "decimals": 2, "instructions": "Gratuity, if any"},
        },
    },
)
r.raise_for_status()
print(r.json()["answers"])
```

Clairic 读了 1,064 个图片 token、合计 2,532 个，回答如下（响应里省去了 `model` 那一行）：

```
{
  "merchant": { "type": "text", "value": "NORTH HAROR C", "p_null": 8.0e-5, "confidence": 0.733, "source": "image", "spell_confidence": 0.733 },
  "total": { "type": "number", "value": 29.04, "p_null": 5.3e-8, "confidence": 0.9995, "source": "image" },
  "paid_on": { "type": "date", "value": "2026-10-24", "p_null": 0.0061, "confidence": 0.9999 },
  "tax": { "type": "number", "value": 3.79, "p_null": 2.8e-4, "confidence": 0.9982, "source": "image" },
  "tip": { "type": "number", "value": null, "guess": 0, "p_null": 0.9999, "confidence": 0.8923 }
}
```

每个非 null 的数字和日期字段，置信度都在 0.99 以上，`tip` 是明确的 `null` 而非编造的零，`p_null` 达到 0.9999。商户名是错的（收据上写的是「NORTH HARBOR CAFE」），Clairic 也如实说明了：`spell_confidence` 为 0.73，比响应里其它所有值低了三分之一。这正是你该转给人工的那个字段，而响应已经替你指出了是哪一个。

## 3：从文件抽取

PDF 也放进 `assets`，用 `"type": "document"` 和 `"format": "pdf"`。Clairic 只读图片，所以 PDF 会交给 [ScaleDown Extract](https://openrouter.ai/scaledown/extract)，它每次请求读一个 PDF 或一张图片，回答 `text` 和 `list` 字段。视频里页面上的框是为演示画的；Extract 返回的是值和置信度，不是页面坐标。

在 Extract 上以 $0.00016 跑出的请求：

```
curl https://openrouter.ai/api/alpha/extractions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d @- <<EOF
{
  "model": "scaledown/extract",
  "state": "po",
  "assets": { "po": { "type": "document", "format": "pdf", "data_base64": "$(base64 < purchase-order.pdf | tr -d '\n')" } },
  "fields": {
    "po_number": { "type": "text" },
    "vendor": { "type": "text", "instructions": "The supplier the order is placed with" },
    "total": { "type": "text", "instructions": "Order total including shipping" },
    "delivery_date": { "type": "text", "instructions": "Requested delivery date" },
    "items": { "type": "list", "items": "text", "instructions": "Ordered line items" },
    "approver": { "type": "text", "instructions": "Who approved the order" }
  }
}
EOF
```

Extract 从 PDF 读了 3,972 个 input token，在 2.9 秒内回答（响应里省去了 `model` 那一行）：

```
{
  "answers": {
    "po_number": { "type": "text", "value": "PO-20931", "confidence": 1, "source": "document" },
    "vendor": { "type": "text", "value": "Meridian Office Supply", "confidence": 1, "source": "document" },
    "total": { "type": "text", "value": "$4,200.00", "confidence": 0.814, "source": "document" },
    "delivery_date": { "type": "text", "value": "November 18, 2026", "confidence": 0.979, "source": "document" },
    "items": { "type": "list", "value": ["Standing desk, 60 in, walnut", "Task chair, mesh back", "Monitor arm, dual"], "confidences": [0.994, 0.999, 1], "source": "document" },
    "approver": { "type": "text", "value": "Priya Shah", "confidence": 1, "source": "document" }
  },
  "truncated": false,
  "usage": { "input_tokens": 3972, "output_tokens": 0, "cost": 0.00015888 },
  "id": "gen-dec-1794274074-RzjUzkyrf7WfR9LpFUTO",
  "provider": "ScaleDown"
}
```

每个值都对，包括从表格里取出的三个行项目。相比 Clairic 有两点差异需要留意：Extract 没有 `number` 或 `date` 类型，所以总金额和交货日期按页面上的字符串原样返回；它逐值（以及逐 list 项）报置信度，但不给 `p_null` 或 `span`。总金额 0.81 是值得扫一眼的字段，其余都在 1 或接近 1。

## 模型清单

首发提供 [三个模型](https://openrouter.ai/models?endpoints=/api/alpha/extractions)，同一个请求对三者都适用，你可以挑最贴合任务的那一个。图片（比如收据照片）以及需要拿回数字、日期或 estimate 时用 Clairic；从 PDF 里抽文本（比如合同里的各方）用 ScaleDown Extract；从纯文本里抽名字或短语（比如邮件、工单）用 Mercury Decide。

| 模型 | 读取内容 | 字段类型 | 输入价格 | 供应商选项 |
| --- | --- | --- | --- | --- |
| [Clairic](https://openrouter.ai/cloudflare/clairic) (`cloudflare/clairic`) | 文本，及最多 4 张 PNG 或 JPEG 图片 | 全部类型 | $0.10/M | `provider.options.cloudflare` 下的 `include_quantiles`、`return_state_text` |
| [Extract](https://openrouter.ai/scaledown/extract) (`scaledown/extract`) | 文本，或一个 PDF / 一张图片 | `text`，及由 `text` 组成的 `list` | $0.04/M | `provider.options.scaledown` 下的 `threshold`、`top_n` |
| [Mercury Decide](https://openrouter.ai/inception/mercury-decide) (`inception/mercury-decide`) | 仅文本 | `text`，及由 `text` 组成的 `list` | $0.02/M | `provider.options.inception` 下的 `snap_to_words`、`threshold`、`group_fields` |

三者的输出都免费。价格是 2026 年 11 月 6 日的目录价；当前价见各模型页面。

### Cloudflare 的 Clairic

[Clairic](https://openrouter.ai/cloudflare/clairic)（`cloudflare/clairic`）是 Cloudflare 在 Workers AI 上的抽取模型，建议从它入手。它每次请求读文本加最多四张 PNG 或 JPEG 图片，支持全部字段类型，也是首发模型中唯一返回 `p_null`、spans 以及 `estimate` 和 `forecast` 分布的。上面第 1、2 节就是在它上面跑的。两个供应商选项能扩展响应：`include_quantiles: true` 为每个 `estimate` 和 `forecast` 返回 99 个分位数，`return_state_text: true` 回显 span 偏移量所指向的确切文本，方便你拿切片去对照。

### ScaleDown Extract

[Extract](https://openrouter.ai/scaledown/extract)（`scaledown/extract`）每次请求读文本，或一个 PDF / 一张图片，回答 `text` 和 `list` 字段并逐值给置信度。它是当下处理 PDF 的模型（第 3 节）。它不报空值概率，因此拒绝 `null_threshold`；`provider.options.scaledown` 下的 `threshold` 和 `top_n` 用来调它挑值的方式。

### Inception 的 Mercury Decide

[Mercury Decide](https://openrouter.ai/inception/mercury-decide)（`inception/mercury-decide`）只读文本，回答 `text` 和 `list` 字段，输入价是三者中最低的。它拒绝 `reference_date`；`provider.options.inception` 下的 `snap_to_words`、`threshold` 和 `group_fields` 是它的选项。

纯文本字段在哪儿都能跑。我们把第 1 节发票的 `text` 和 `list` 字段发给 Mercury Decide 和 Extract：两者返回的值相同，文本上的 spans 也与 Clairic 一致，花费分别为 $0.000015 和 $0.000014。Extract 对 PDF 不返回 spans（第 3 节）。

## Decisions 与 Extractions

两条路径用同一个信封（`model`、`state`、`assets`、`provider`），区别在于你交给模型什么、模型还给你什么。

**Decisions：答案由你来写，模型负责权衡。** Decisions 请求带 `questions`，每个问题自带答案空间：`noul` 是一个非真即假的命题，`choice` 列出选项，`score` 命名一个量表，`box` 要求图片里的一个区域。对于 `noul`、`choice` 或 `score`，模型绝不会产出你没写下的值；它只是在你写的答案之间分配概率（`box` 返回你所描述区域的坐标）。正因如此，它适合一切需要判断的事：这是不是发票、这五条条款里哪条适用、严重程度如何、这张图里有没有收据。输出是一个可设阈值的、经过校准的数字，而「答错」也只是你早已处理的选项之一。

**Extractions：字段由你来命名，模型负责找值。** Extractions 请求带 `fields`，每个字段是一个名字加一个类型：`text`、`number`、`date`、`list`、`duration`、`estimate`、`forecast`。答案空间是类型本身，而不是你写下的清单，因此模型得在文档里定位这个值（或算出来，比如由开票日和账期推出到期日；或估出来，比如付款要几天）。因为值是开放的，答案会附带证据：读出它的 `span`、文档里究竟有没有该字段的 `p_null`，以及 `confidence`。当答案本身就是内容时——收据上的数字、合同里的名字、表单上的日期——它就是对的工具。

同一张第 1 节的发票，通过 Decisions 在 [Clef Flash](https://openrouter.ai/cloudflare/clef-flash) 上跑：

```
{
  "questions": {
    "overdue": { "type": "noul", "instructions": "The invoice is past due as of 2026-11-06." },
    "terms": { "type": "choice", "instructions": "What are the payment terms?", "criteria": { "net 15": null, "net 30": null, "net 45": null, "net 60": null, "due on receipt": null } },
    "has_late_fee": { "type": "noul", "instructions": "The invoice states a penalty for late payment." }
  }
}
```

```
{
  "answers": {
    "overdue": { "type": "noul", "noul": 0.2069 },
    "terms": { "type": "choice", "choice": "net 45", "probabilities": { "net 15": 0.0096, "net 30": 0.0131, "net 45": 0.9623, "net 60": 0.0096, "due on receipt": 0.0055 }, "confidence": 0.908 },
    "has_late_fee": { "type": "noul", "noul": 0.9358 }
  },
  "usage": { "input_tokens": 466, "output_tokens": 0, "cost": 0.000008854 }
}
```

对同一张发票，Decisions 判定账期是 net 45、置信度 0.96，且这张发票并未逾期。Extractions（第 1 节）则返回发票号 INV-4417（位于第 8 到 16 个字符）以及总金额 3850。

一条经验法则：能在发请求前就列出所有可能答案时用 Decisions；答案是写在文档里的某个值时用 Extractions。

两者也可以搭配使用。Decisions 先判断某文档是不是发票，Extractions 再从判定为是的那些里把字段抽出来。

两个 API 的请求几乎一样。差别在于 Decisions 问的是有固定答案集的问题（是或否、或在若干选项里选），而 Extractions 要的是由文档填写的字段。要把一个请求从 Decisions 切到 Extractions，把 `questions` 改名为 `fields`，并将每一项重写成字段即可。

拿一个 [API key](https://openrouter.ai/settings/keys)，在 [Clairic 模型页](https://openrouter.ai/cloudflare/clairic) 打开 Playground，用你自己的字段跑一遍上面那张发票，然后读 [Extractions guide](https://openrouter.ai/docs/guides/community/extractions) 和 [API reference](https://openrouter.ai/docs/api/api-reference/alphaextractions/submit-an-extractions-request)。同一个任务在 Responses API 上用 ScaleDown Extract 的做法，见 [cookbook](https://openrouter.ai/docs/cookbook/evaluate-and-optimize/extract-invoice-fields-with-scaledown)。

## 常见问题

### API 稳定吗？

目前是 alpha。结构可能会变，变动会先落在 [guide](https://openrouter.ai/docs/guides/community/extractions) 上。

### 请求写错会怎样？

校验在 OpenRouter 一侧完成，之后才会到供应商：未知的键、Mercury Decide 上的 `date` 字段、Clairic 上的第五张图片、Clairic 上的 PDF，或没有任何地方引用的 asset，都会得到 `400`，消息里点明问题所在。把 `questions` 发到这条路径，会得到一个指向 `/api/alpha/decisions` 的 `400`。

### 字段什么时候会变成 `null`？

在 Clairic 上，是 `p_null` 超过 0.5 时。可按字段设 `null_threshold` 来挪动这条线，`guess` 里是模型本来会取到的值。Extract 不报 `p_null`，所以它给出的 `null` 就是模型直接的答案，而且它拒绝 `null_threshold`。

### 文档里的日期没写年份怎么办？

传 `reference_date`，模型会以它为锚点。没有 `date` 类型的模型会拒绝它：Mercury Decide 和 Extract 即是。

### 文档很长怎么办？

响应里 `truncated: true` 表示供应商只读了 state 的前缀。字段一次装不下时，`usage.passes` 记下所需的上游调用次数，`schema_tokens` 是每次请求里字段规格的花费。

### 能把 Decisions 请求搬过来吗？

信封一样；把 `questions` 改名为 `fields` 并重写每份规格即可，因为带选项的 `choice` 与 `text` 字段是不同的问法。

### spans 怎么计数？

按 Unicode 码点，是指向 `state` 的 `[start, end)`。在以 UTF-16 单元索引字符串的语言里，要按码点切：在 JavaScript 里用 `Array.from(state).slice(start, end).join('')`，而不是 `state.slice(start, end)`。Clairic 上的 `return_state_text: true` 会回显偏移量所指向的确切文本，方便你核对切片。

### Playground 支持它吗？

支持：[Clairic 模型页](https://openrouter.ai/cloudflare/clairic) 上的 Playground 接收 `state` 和 `fields`，并展示带类型的答案。
