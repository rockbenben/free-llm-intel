OpenRouter 现在有两个专属音频端点：用于文本转语音的 `/api/v1/audio/speech`，以及用于语音转文本的 `/api/v1/audio/transcriptions`。

这些新端点提供专门化模型，通常比我们已支持的[通用音频模型](https://openrouter.ai/models?output_modalities=audio)更快、更具成本效益，但只适用于特定的音频任务。

现在你可以用 OpenAI、Google 或 Mistral 的声音从文本生成语音，并用 OpenAI Whisper 转录音频文件。全部沿用你在文本、视频和图像生成中已使用的相同路由、计费和密钥管理。

[Speech 模型](https://openrouter.ai/models?output_modalities=speech) · [Transcription 模型](https://openrouter.ai/models?output_modalities=transcription) · [Speech 文档](https://openrouter.ai/docs/features/multimodal/tts) · [Transcription 文档](https://openrouter.ai/docs/guides/overview/multimodal/stt)

## 选择模型：Audio vs. Speech vs. Transcription

模型选择是专门化、成本和速度之间的平衡。我们把所有选项都开放给你，让你为每个用例选择正确的路径：

|  | **Audio 模型** | **Speech 模型** | **Transcription 模型** |
| --- | --- | --- | --- |
| **做什么** | 理解音频输入并对其进行推理，像一个语音原生的 LLM | 把文本转换为逼真的语音音频 | 把音频转换为文本 |
| **输入 → 输出** | 文本/音频 → 文本/音频 | 文本 → 音频 | 音频 → 文本 |
| **最适合** | 语音 agent、混合模态对话、音频问答 | 用内置声音朗读文本并流式输出 | 会议纪要、字幕、把语音输入接入文本管道 |
| **端点** | `/chat/completions` | `/audio/speech` | `/audio/transcriptions` |
| **权衡** | 更强大，但更重、更贵 | 更简单、更快、更便宜（无需推理） | 为跨语言跨口音的准确率而生 |
| **浏览模型** | [Audio 模型](https://openrouter.ai/models?output_modalities=audio) | [Speech 模型](https://openrouter.ai/models?output_modalities=speech) | [Transcription 模型](https://openrouter.ai/models?output_modalities=transcription) |
| **文档** | [音频输出指南](https://openrouter.ai/docs/guides/overview/multimodal/audio#audio-output) | [Speech 文档](https://openrouter.ai/docs/features/multimodal/tts) | [Transcription 文档](https://openrouter.ai/docs/guides/overview/multimodal/stt) |

## 在 Playground 中试用

Speech 和 Transcription 都在模型页面有专属的 Playground 标签页（例如 [GPT-4o Mini TTS 的 Playground](https://openrouter.ai/openai/gpt-4o-mini-tts-2025-12-15/playground) 和 [GPT-4o Transcribe 的 Playground](https://openrouter.ai/openai/gpt-4o-transcribe/playground)）。对 speech 模型，从下拉菜单选一个声音、输入文本、听结果。对 transcription 模型，拖放一个音频文件即可看到转录结果。

每个模型页面还提供 Python、TypeScript、curl 和 OpenRouter SDK 的快速上手代码，复制一个可运行的示例，几分钟内就能让你的 app 跑起音频。

## Speech 模型上手

发送文本，返回音频。响应是一个原始字节流，可以直接写入文件或喂给音频播放器。

```
curl https://openrouter.ai/api/v1/audio/speech \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  --output output.mp3 \
  -d '{
    "model": "openai/gpt-4o-mini-tts-2025-12-15",
    "input": "Hello from OpenRouter.",
    "voice": "alloy",
    "response_format": "mp3"
  }'
```

Speech 服务商目前包括 **OpenAI**（[GPT-4o Mini TTS](https://openrouter.ai/openai/gpt-4o-mini-tts-2025-12-15)）、**Google**（[Gemini Flash TTS](https://openrouter.ai/google/gemini-3.1-flash-tts-preview)）和 **Mistral**（[Voxtral Mini TTS](https://openrouter.ai/mistralai/voxtral-mini-tts-2603)）。每个模型自带声音集合，可在各模型页面浏览可用声音。输出为 MP3 或 PCM 格式。

服务商特有的选项可以干净地透传。例如 OpenAI 的 speech 模型接受用于语气控制的 `instructions` 字段（如 “speak in a warm, friendly tone”）。

## Transcription 模型上手

转录端点接受两种格式的音频：通过 `input_audio` 字段以 JSON 传入 base64 编码的音频，或按 OpenAI 风格的 `multipart/form-data` 文件上传。支持 WAV、MP3、FLAC 及其他常见格式。

```
AUDIO_BASE64=$(base64 < recording.wav | tr -d '\n')

curl https://openrouter.ai/api/v1/audio/transcriptions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/whisper-large-v3",
    "input_audio": {
      "data": "'"$AUDIO_BASE64"'",
      "format": "wav"
    }
  }'
```

Transcription 服务商目前包括 **OpenAI**（[Whisper](https://openrouter.ai/openai/whisper-large-v3)、[GPT-4o Transcribe](https://openrouter.ai/openai/gpt-4o-transcribe)、[GPT-4o Mini Transcribe](https://openrouter.ai/openai/gpt-4o-mini-transcribe)）、**Google**（[Chirp 3](https://openrouter.ai/google/chirp-3)）和 **Groq**（以其快速的 [Whisper](https://openrouter.ai/openai/whisper-large-v3) 推理著称）。你可以选择性地传入 `language` 提示，以提高非英文音频的准确率。
