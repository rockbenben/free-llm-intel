# 我们如何重建提供者路由以实现更好、更快的推理

斯科特·莫尔斯 ·10/28/2026

![我们如何重建提供者路由以实现更好、更快的推理](https://openrouter.ai/blog/images/new-provider-routing.png)

今天，我们宣布自 OpenRouter 成立以来对我们的提供商路由算法进行的最大改进。

到目前为止，我们的默认路由器主要奖励提供商一件事：低价。新的路由器奖励实际上最适合您的推理：便宜，而且快速、高吞吐量且可靠。提供更多价值的提供商会自动赢得更多流量，因此每个提供商都有理由不断改进。这意味着您通过 OpenRouter 获得的推理会变得更快、更可靠且更具成本效益，而且您无需更改一行代码。

它已经开始工作了。新算法在 TTFT (16.9%)、吞吐量 (16.3%) 和容量错误（显着降低 67%！）方面实现了显着改进，而成本仅略有增加 (6.0%)。那是在提供商有时间优化新算法之前。有关更多详细信息，请参阅我们完整的[实验结果](https://openrouter.ai/blog/announcements/how-we-rebuilt-provider-routing/#results)。

工作原理：

- **它衡量您实际获得的内容。** 对于每个模型，它都会跟踪每个端点的实现价格、延迟、吞吐量和错误率，并为每个请求选择成本和性能的最佳组合。
- **它实时反应。** 当端点出现问题时，流量会远离它，直到它恢复。
- **它奖励更好的推理。** 创新的提供商会自动获得更多流量的奖励。

路由仍然是缓存感知的，因此一旦我们将您发送到提供商，只要缓存还热，您的会话就会保持不变。

想要纯价格路由吗？你仍然可以拥有它。请参阅[保持不变](https://openrouter.ai/blog/announcements/how-we-rebuilt-provider-routing/#what-stays-the-same)中的固定和排序提供商。

## 我们所处的位置：仅价格路由的局限性

OpenRouter 上的大部分流量（约 77% 的请求）都会流向由多个提供商提供服务的模型。当请求不包含显式排序或提供程序列表时，我们需要选择一个提供程序将其发送到。到目前为止，我们几乎完全根据输入代币价格做出选择。提供商越便宜，收到的流量百分比就越大，任何失败的请求都会重新路由到下一个最便宜的选项。

这种只考虑价格的方法为用户提供了生态系统中的最低价格，但它产生了一些意想不到的后果：

- **即使情况很糟糕，便宜也能获胜。** 回退会发现失败，但用户会等待失败，而速度的提高并没有得到回报。
- **静态排名。** 该算法对实时性能变化视而不见，因此提供商必须降级到完全降级的地步，然后才能反映在流量分配中。
- **利润消失。** 提供商赢得流量的唯一方法是降价，这给他们施加压力，要求他们减少对确保可靠性和质量的基础设施的投资。
- **定价游戏。** 我们排名的价格几乎都是即时输入价格，因此提供商可以通过奇怪的定价鸡尾酒来保持流量份额，例如列出人为压低的输入价格，然后使用定价过高的缓存或完成令牌来弥补差额。

我们希望确保市场上的竞争提供商通过提供更好的推理而不仅仅是更便宜的推理来赢得流量。

## 新算法：针对好的答案“成本”进行优化

新的路由算法不断监控每个提供商的性能，以计算实时路由成本，从而捕获用户为获得良好答案而支付的费用。路由成本包括以实际美元和美分计算的价格、等待响应所花费的时间成本以及提供商失败或提供不可用响应时重试的成本。

简单地说：一次尝试的成本是多少？尝试的频率是多少？

## 一次尝试的成本：价格加上等待

对于每个请求，路由器会根据模型最近的流量估计将使用多少个输入和输出令牌。这一估算决定了尝试的两个部分：您将支付的价格和您将等待的时间。

### 有效价格

有效价格是提供商实际向您收取的价格，根据最近测量的流量计算得出。它反映了提供商的真实缓存命中率以及模型输入和输出令牌的平均组合，因此它可能与标价有很大差异。这确保了提供商无法通过在低输入价格背后隐藏昂贵的缓存或输出令牌来赢得流量。

路由器按照每个提供商的有效价格对您的请求进行定价，并优先考虑最便宜的选项。

### 吞吐量

吞吐量是与价格进行权衡的：速度更快的提供商可以收取更高的费用，但仍然会赢得您的请求。它以每秒端到端的输出令牌数来衡量，因此它包括第一个令牌的时间加上提供程序传输整个输出响应所需的时间。路由器补充说，等待路由成本使用每个模型设置的转换率，基于其提供商通常收取的费用及其速度。

### 第一个令牌的时间

首次令牌时间 (TTFT) 是响应开始流式传输之前您需要等待的时间。它本身会增加路由成本，即使它已经计入吞吐量，因为交互式使用最依赖它。在代理会话中，模型可能会连续进行许多工具调用，并且每个工具都会等待第一个令牌。

### 速率限制

速率限制 (HTTP 429) 意味着提供商的能力不足并拒绝了您的请求。您必须等待拒绝，然后您的完整请求将发送给另一个提供商。路由器添加了等待加上提供商路由成本的惩罚，按限制请求速率的频率加权，因此影响通常很小。通过下面描述的流量上限和退避，重复的速率限制更加重要。

## 工作频率：可靠性和质量

失败的尝试仍然需要付出代价和等待，因此路由成本计算必须重试直到成功为止的预期成本。如果五分之一的尝试失败，则为每个正确答案支付 1.25 次尝试费用。

### 可靠性

可靠性错误是指由于提供者的原因而失败的请求。您将失去这次尝试并必须重试，因此每个错误都会导致路由成本的严重损失。

![可靠性示例：1% 的错误率乘以每个错误 8 倍的惩罚，会使路由成本提高约 8%。 （轻型模式）](https://openrouter.ai/blog/images/new-provider-routing-reliability-light.png)

![可靠性示例：1% 的错误率乘以每个错误 8 倍的惩罚，会使路由成本提高约 8%。 （深色模式）](https://openrouter.ai/blog/images/new-provider-routing-reliability-dark.png)

如果某个提供商的错误率远远高于同一模型的其他提供商，则路由器将停止向其发送请求，直到其恢复。

### 质量

质量衡量提供者的响应是否可用。今天的主要检查是工具调用是否返回格式正确，我们正在添加更多内容。每个错误的响应都会增加提供商的路由成本，因为廉价的错误答案代价高昂。

![质量示例：95% 的工具调用结构良好，使路由成本提高约 5%。 （灯光模式）](https://openrouter.ai/blog/images/new-provider-routing-quality-light.png)

![质量示例：95% 的工具调用结构良好，使路由成本提高约 5%。 （深色模式）](https://openrouter.ai/blog/images/new-provider-routing-quality-dark.png)

被标记为工具调用损坏或基准准确性远低于模型应得分的提供商，会远远落后，并且仅获得少量测试流量，直到标记清除为止。

## 接近越来越接近：流量如何共享

将每个请求发送给单个最佳提供商会使其过载，因此流量是共享的。更快的提供商可以承受更高的路由成本并保持竞争力。 **竞争优势**内的所有内容都共享大部分流量，稍微落后于最好的会付出一些代价。越过边缘，流量份额迅速下降。

- **楼层：** 每个提供商都会保持一定的流量，因此我们可以注意到陷入困境的端点何时有所改善。新端点从模型的典型数字开始，因此不需要流量历史记录。
- **退避：** 开始出现故障或速率限制的提供商在恢复之前会得到更少的资源。
- **Cap：** 路由器在返回 429 之前了解每个提供者可以承受多少负载，并将其余的传递给其他提供者。添加容量后上限会自行上升。

## 什么保持不变

- 设置“provider.order”的请求绕过新的路由逻辑，提供商按指定顺序排序（默认与以前一样基于价格）。如果有多个提供商，则设置“provider.only”或“provider.ignore”将使用新算法从剩余的提供商中进行选择。
- 显式的“provider.sort”（“price”、“throughput”或“latency”）使用该排序而不是新算法。
- 只有对话中的第一个请求才会通过算法选择提供商。正在进行的对话被固定到其原始提供者，以便提示缓存保持温暖。如果该提供商不可用，对话将自动退回到另一个提供商。
- 如果尝试失败，则会向排名第二的提供商重试该请求。

## 我们如何测量它

为了衡量新路由算法的影响，我们必须超越标准 A/B 测试，因为路由行为的变化很难与对照组隔离。例如，如果新算法能够更好地将流量从陷入困境的提供商处路由出去，则旧算法向该提供商发出的请求将找到更多可用容量并变得更快，从而扭曲结果。请求形状和体积模式的巨大变化进一步加剧了困难。单个鲸鱼用户向单个提供商自动发起一系列高强度请求，可以人为地夸大该提供商的指标，无论我们使用哪种算法来路由他们的请求。

因此，我们进行了一次折返实验：我们将每天分成 3 小时的块，并在新旧路由器之间翻转每对匹配的块，每次转换时丢弃数据的一小时老化期，并在一整周内测量开源模型代表性样本中每个模型的影响。

## 开始吧

如果您使用默认路由，就完成了。为每个请求提供服务的提供商位于响应和您的活动页面上。

要保留旧的仅价格路由，请将`provider.sort`设置为`"price"`，将`:floor`附加到模型段，或在[帐户设置](https://openrouter.ai/settings/preferences)中将默认排序设置为价格。要自己选择提供商，请使用“provider.order”或“provider.only”。请参阅[提供商路由指南](https://openrouter.ai/docs/guides/routing/provider-selection)。

## 常见问题

### 我需要更改代码才能使用新路由吗？

不会。没有明确提供程序排序且没有提供程序顺序的请求，仅或忽略列表会在启用它的模型上自动使用新路由器。您的 API 密钥、请求正文和模型 ID 保持不变。

### 如何保留仅价格路由？

在请求正文中将provider.sort设置为price，将:floor附加到模型slug，或者在帐户设置中将默认提供程序排序设置为price。任何显式排序都会绕过新路由器。

### 新路由是否会覆盖我的提供商订单或仅覆盖我的提供商订单？

provider.order 绕过新路由器并按照您指定的顺序进行路由。 provider.only 和provider.ignore 仍然过滤候选集，但新算法会在剩余的提供程序中进行选择。

### 新路由的成本会比纯价格路由更高吗？

它可以，因为它有时会选择更快或更可靠的提供商而不是最便宜的提供商。在我们的现场实验中，每个请求的成本增加了 6.0%，同时 TTFT 提高了 16.9%，吞吐量提高了 16.3%，429 错误率降低了 67%。

### 提供商如何在新路由下获得更多流量？

提高路由器评分的信号：有效价格、第一个令牌的时间、吞吐量、错误和速率限制率以及输出质量。
