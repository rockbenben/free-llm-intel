# 跨任何模型的工具调用：编写一次循环，交换模型字符串

OpenRouter ·8/12/2026 · 更新于 9/24/2026

工具调用（也叫函数调用）让模型用结构化 JSON 请求一个函数。你的代码执行这个函数、返回结果，模型用结果完成它的回答。每家大提供商都支持这个机制的某个版本，但多数教程只讲一家——按 OpenAI 教程写的代码，搬到 Claude 就得重写。用我们的 API 什么都不用重写：循环写一次，换模型字符串，工具代码原样不动。

本指南覆盖完整循环：定义工具、发请求、读 `tool_calls` 响应、执行函数、返回结果、拿到最终答案。然后你会靠改一个字符串，让同一份代码跑在三个提供商上。

每个字段列在我们的[工具调用文档](https://openrouter.ai/docs/guides/features/tool-calling)里；本文把整个过程从头到尾走一遍。

## 太长不看

- 一个工具 `get_weather(location, unit)`，以 OpenAI 兼容 JSON schema 定义一次。
- 一个循环，用 cURL、Python 和 JavaScript/TypeScript 展示：发送 `tools`、读 `tool_calls`、本地执行、返回结果、拿最终答案。
- 跨三个模型的一次测试：同一循环跑 Claude、GPT 和一个开放权重模型，只换模型字符串。任何支持工具的模型都行——支持情况因模型而异，切换前先查。
- `tool_calls` 是一个参数为 JSON 字符串的数组，每个参数串都要解析，别假定只有一次调用。

## 什么是工具调用，为什么"函数调用"是同一件事

工具调用和函数调用是一个机制的两个名字。你用 JSON schema——一份写明函数名和输入的规格——向模型描述函数；模型随后可以请求你的代码带着具体参数调用它。你的代码执行函数、返回结果，模型用这个结果完成回答。

"function calling"这个旧名字是 OpenAI 叫开的，如今多数 API 都说"tool calling"，含义相同。你发 `tools` 字段，模型返回 `tool_calls`；我们对 Claude、GPT 和 Llama 接受同一份 OpenAI 兼容 schema，所以名字差异不改你的代码。本指南统一说"工具调用"——API 字段就是这么命名的——你在老文档和 SDK 里仍会看到"函数调用"。

循环有四个步骤：

- 发送对话和你的工具定义。
- 模型返回一个带名字和 JSON 参数的 `tool_calls` 请求。
- 你的代码执行工具，把结果追加进对话。
- 再发一次对话。模型读结果，返回最终答案。

### 工具调用 vs 模型"运行"工具

模型从不亲自执行工具。它返回一个 `tool_calls` 请求，执行发生在你这边。

它不会调你的天气 API、不会查你的数据库、不会跑你的代码。它发出 `get_weather(location="Paris")` 这样的结构化请求，然后停下。你的应用执行函数、决定返回什么——密钥、副作用和校验都握在你手里，模型只决定什么时候开口要。

## 定义一个工具

动手前需要一个 OpenRouter 账户和一个 API key，在[控制台](https://openrouter.ai/keys)创建。导出为 `OPENROUTER_API_KEY`，下面的示例从环境里读它。

还需要一个 SDK：Python 3.10+ 配 `pip install openai`，或 Node 22+ 配 `npm install openai`。别的都不用。天气函数返回固定值而不是调真实 API，所以 OpenRouter key 是你唯一需要的 key。

指南里每个示例都用同一个工具 `get_weather(location, unit)`。以 OpenAI 兼容 JSON schema 定义它：

```
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a location.",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "City name, e.g. 'Paris'",
                    },
                    "unit": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                    },
                },
                "required": ["location"],
            },
        },
    }
]
```

接着写模型可以请求的那个函数。真实应用会调天气 API；这里返回固定值，跟着做不需要第二个 key：

```
import json

def get_weather(location, unit="celsius"):
    # Real code would call a weather API here.
    return {"location": location, "temperature": 18, "unit": unit, "sky": "clear"}
```

现在把 SDK 指向我们的端点。我们接受 OpenAI API 格式——已在用 OpenAI SDK 的话，只需要换 `base_url` 和 key：

```
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key=os.environ["OPENROUTER_API_KEY"],
)
```

想在看清裸请求后再接 SDK，同一个首次调用的 cURL 长这样：

```

      "function": {
        "name": "get_weather",
        "description": "Get the current weather for a location.",
        "parameters": {
          "type": "object",
          "properties": {
            "location": {"type": "string", "description": "City name, e.g. Paris"},
            "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]}
          },
          "required": ["location"]
        }
      }
    }]
  }'
```

### 代码里的请求/响应循环

这个函数就是整个循环，本指南后面不会再改它。它发送消息和工具、检查 `tool_calls`、逐个执行工具、追加结果，再向模型要最终答案：

```
def run_tool_loop(model, user_message):
    messages = [{"role": "user", "content": user_message}]
    # First call: the model may ask for a tool.
    response = client.chat.completions.create(
        model=model, messages=messages, tools=tools,
    )
    msg = response.choices[0].message
    # No tool call? The model answered directly.
    if not msg.tool_calls:
        return msg.content
    # Append the assistant's tool-call turn verbatim, then execute each call.
    messages.append(msg)
    for call in msg.tool_calls:
        args = json.loads(call.function.arguments)  # arguments arrive as a JSON string
        result = get_weather(**args)
        messages.append({
            "role": "tool",
            "tool_call_id": call.id,
            "content": json.dumps(result),
        })
    # Second call: the model reads the tool result and writes the final answer.
    final = client.chat.completions.create(
        model=model, messages=messages, tools=tools,
    )
    return final.choices[0].message.content
```

Node 22+ 的 JavaScript/TypeScript 版同一循环，用指向我们端点的 `openai` 包：

```
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://openrouter.ai/api/v1",
  apiKey: process.env.OPENROUTER_API_KEY,
});

// Same schema as the Python `tools` array above.
const tools = [
  {
    type: "function",
    function: {
      name: "get_weather",
      description: "Get the current weather for a location.",
      parameters: {
        type: "object",
        properties: {
          location: { type: "string", description: "City name, e.g. 'Paris'" },
          unit: { type: "string", enum: ["celsius", "fahrenheit"] },
        },
        required: ["location"],
      },
    },
  },
];

function getWeather(location, unit = "celsius") {
  return { location, temperature: 18, unit, sky: "clear" };
}

async function runToolLoop(model, userMessage) {
  const messages = [{ role: "user", content: userMessage }];
  const response = await client.chat.completions.create({ model, messages, tools });
  const msg = response.choices[0].message;
  if (!msg.tool_calls) return msg.content;

  messages.push(msg);
  for (const call of msg.tool_calls) {
    const args = JSON.parse(call.function.arguments);
    const result = getWeather(args.location, args.unit);
    messages.push({
      role: "tool",
      tool_call_id: call.id,
      content: JSON.stringify(result),
    });
  }

  const final = await client.chat.completions.create({ model, messages, tools });
  return final.choices[0].message.content;
}
```

上生产前请补一件事：`arguments` 是模型生成的字符串，不是校验过的载荷。模型有时会返回非法 JSON，或发明你 schema 里从未声明的参数。解析外面要包错误处理，传给你的函数之前按键对照 schema 检查。这里的示例为了保持简短跳过了这步。

下文所有调用都只是用不同的模型字符串调 `run_tool_loop` 或 `runToolLoop`。

## 在 Claude 上跑

第一次运行只需要一个模型名。传入 Anthropic 模型，四个步骤在 `run_tool_loop` 的一次调用里全部发生：

```
answer = run_tool_loop(
    "anthropic/claude-opus-4.8",
    "What's the weather in Paris?",
)
print(answer)
# → "It's currently 18°C and clear in Paris."
```

这一次 `run_tool_loop` 调用跑完了四步、发了两次 API 请求。第一次请求返回 `tool_calls`，你的代码执行 `get_weather` 并追加结果；第二次请求返回完成的答案。

模型 slug 随发布会变，依赖之前在我们的[模型目录](https://openrouter.ai/models)确认确切字符串。

### 解读响应

函数名和参数在 `tool_calls` 数组里。第一次响应中，`choices[0].message` 长这样：

```
{
  "role": "assistant",
  "content": null,
  "tool_calls": [
    {
      "id": "call_abc123",
      "type": "function",
      "function": {
        "name": "get_weather",
        "arguments": "{\"location\": \"Paris\", \"unit\": \"celsius\"}"
      }
    }
  ]
}
```

两个细节要紧。第一，`arguments` 是 JSON 编码的字符串、不是对象，用 `json.loads` 或 `JSON.parse` 解析。第二，`tool_calls` 是数组，你的代码必须能处理一次响应里的多个调用。

## 在 GPT 上跑

Claude 那次证明了循环能跑，下一次证明同样的代码在另一家提供商上也能跑。唯一的编辑是一个字符串：

```
answer = run_tool_loop(
    "openai/gpt-4o",
    "What's the weather in Paris?",
)
print(answer)
# → "The weather in Paris is 18°C and clear right now."
```

与 Claude 示例唯一的区别是 `anthropic/claude-opus-4.8` → `openai/gpt-4o`。工具 schema、循环、解析和结果消息全都原样不动，因为两家我们返回的都是同一个 `tool_calls` 格式。这对任何支持工具的模型都成立——切换前先查工具支持。

## 在开源模型上跑

专有模型之间格式常常相通，开放权重模型才是更硬的考验。再换一次字符串：

```
answer = run_tool_loop(
    "meta-llama/llama-3.3-70b-instruct",
    "What's the weather in Paris?",
)
print(answer)
# → "Right now in Paris it's 18°C with clear skies."
```

三个提供商、一份代码、零重写。开放权重模型返回的和 Claude、GPT 同样的 `tool_calls` 结构。模型名可以放进配置，在路由器、测试或回退里改，不动工具代码。

## 边界情况与坑

上面的循环覆盖了常见情形。生产中四件事可能打破它：并行工具调用、流式、不支持工具的模型，以及控制模型何时调工具。

### 并行工具调用

有些模型一次响应里返回多个工具调用。问两个城市时，模型可能同时返回 `get_weather("Paris")` 和 `get_weather("Tokyo")`。这就是循环要遍历 `msg.tool_calls` 而不是只读 `[0]` 的原因：下一次请求发出之前，每个调用都要各自追加一条带自己 `tool_call_id` 的结果。示例循环已经这么做。也可以在请求里设 `parallel_tool_calls: false`，让模型一次只请求一个调用。

### 流式工具调用

流式响应时，工具调用以叫 delta 的分片到达。模型可能把参数串拆散到多个 chunk 里、逐个索引地拼装 `tool_calls` 数组。流结束前别执行工具：按索引收集 delta、等结束信号、解析完整的参数串，再执行。

### 不支持工具的模型

不是所有模型都支持工具。向没有"支持工具端点"的模型发 `tools`，我们返回 404，说明没有端点支持工具使用。回退路径上，不支持工具的模型也可能直接忽略该字段、返回没有 `tool_calls` 的纯文本——这种失败不报错，所以往循环里加模型之前先查支持。浏览我们的[工具调用合集](https://openrouter.ai/collections/tool-calling-models)，或在[目录](https://openrouter.ai/models)里打开任何模型页、确认 `supported_parameters` 含 `tools`。

### 强制或禁用工具调用

用 `tool_choice` 控制模型到底要不要调工具：

| `tool_choice` 值 | 行为 |
| --- | --- |
| `"auto"` | 模型自己决定是否调工具。请求里有 `tools` 时这就是默认。 |
| `{"type": "function", "function": {"name": "get_weather"}}` | 模型必须调用那个指定工具。 |
| `"none"` | 本次请求禁用工具调用。 |

OpenAI 兼容 schema 还定义了 `"required"`，要求模型至少发起一次工具调用。更严格取值的支持情况因模型而异——生产依赖之前，在我们的[工具调用文档](https://openrouter.ai/docs/guides/features/tool-calling)确认行为并对着目标模型实测。

## 结论

你定义了一个工具、写了一个工具调用循环，只改一个字符串就让同一份代码跑在 Claude、GPT 和开源模型上。模型变，工具定义和循环不变——换提供商从此是配置编辑，不是重写。

三件事记住：

- **工具定义和循环跨模型通用。**写一次即可。每个支持工具的模型都拿到同样的 `tools` 和 `tool_calls` 格式，换提供商是一行改动。
- **`tool_calls` 是 JSON 字符串参数的数组。**遍历数组、逐个解析，永远别假定响应里恰好一个调用。
- **工具支持因模型而异。**对着某个模型上线之前，先确认它支持工具。

要接自己的工具，从[工具调用文档](https://openrouter.ai/docs/guides/features/tool-calling)的字段参考开始，并从[工具调用合集](https://openrouter.ai/collections/tool-calling-models)任选模型。

## 常见问题

### LLM 里的工具调用是什么？

工具调用让模型请求你的代码代它执行某个东西——最通常是一个函数。模型返回一个点名工具和参数的结构化 JSON 请求，你的应用执行它，你把结果发回去让模型完成回答。模型自己从不执行任何东西。

### 工具调用和函数调用有什么区别？

没有功能差别，两个名字指同一机制。"函数调用"是 OpenAI 叫开的旧词，"工具调用"是如今多数 API 的叫法。在我们的 API 里，两者都映射到同一请求/响应形态——`tools` 字段和 `tool_calls` 字段——为一种写的代码另一种照样能跑。

### 怎么用 API 实现函数调用？

把函数描述成 JSON schema，与消息一起放进 `tools` 字段发送。响应包含 `tool_calls` 时，解析参数串、执行函数；然后把结果作为携带对应 `tool_call_id` 的消息追加进去，再发一次对话拿最终答案。

### 不同模型上的工具调用行为一样吗？

支持工具的模型上，一样。我们接受一份 OpenAI 兼容 schema、对 Claude、GPT 和开放权重模型返回同一种 `tool_calls` 格式——同一工具定义和循环不改一行就能跨它们运行，变的只有模型字符串。工具支持因模型而异，请逐个确认。

### 哪些模型支持工具调用？

工具支持是按模型的，不是普适的。受支持的策划清单见[工具调用合集](https://openrouter.ai/collections/tool-calling-models)；或打开[目录](https://openrouter.ai/models)里任何模型页，看 `supported_parameters` 是否含 `tools`。没有支持工具端点的模型会收到说明情况的 404；回退路径上不支持工具的模型可能忽略该字段、以纯文本作答。

### 开源模型能做函数调用吗？

能。Llama 3.3 70B Instruct 这类支持工具的开放权重模型返回与专有模型相同的 `tool_calls` 结构，同一循环不改即可工作。先看模型页 `supported_parameters` 里有没有 `tools`——开放权重家族和微调模型之间的支持差异很大。

### 什么是并行工具调用？

模型在一次响应里返回多个工具请求，例如对两个城市各一个 `get_weather` 调用。你的代码必须遍历 `tool_calls` 数组、每个调用追加一条带自己 `tool_call_id` 的结果消息，然后再把对话发回去。
