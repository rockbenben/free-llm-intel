现在你可以在 chat completions、responses、messages 或 embeddings 请求中加上 `X-OpenRouter-Cache: true`，开始对完全相同的调用做缓存。第一次调用会打到服务商并正常计费。之后的每一次相同调用都会在极短的时间内返回同样的响应，且不收取任何 token 费用。

[查看 response caching 文档](https://openrouter.ai/docs/guides/features/response-caching)

## 它是做什么的

Response caching 位于模型服务商之前。当你发送启用缓存的请求时，OpenRouter 会把请求体、模型、API key 和流式模式哈希成一个缓存键。如果之前发过完全相同的请求且尚未过期，缓存的响应会立即返回——不调用服务商、不消耗 token、不收费。

流式和非流式请求都支持。缓存的流式响应会经过同一条管道重放，因此你的客户端代码无需改动。文本、图像、音频、文档和 tool calls 都能正常缓存。多模态输入（base64 图像、音频片段、文件附件）也计入缓存键哈希。唯一的例外：那些在内部被卸载（offload）处理的超大 payload 不适合缓存，标准大小的请求缓存没问题。

Response caching 与 prompt caching 是两回事。Prompt caching（许多服务商原生提供）在消息共享公共前缀时降低 prompt 部分的成本；而 response caching 直接跳过服务商，从 OpenRouter 的边缘缓存返回完整响应。

## 响应时间从秒级降到毫秒级

缓存响应的返回时间为 80-300ms，其中大部分是序列化和网络开销，缓存查找本身平均只有 4ms。作为对比，一个典型的未缓存请求：Gemini 2.5 Flash 约 1.3 秒，Kimi K2.6 约 4.6 秒，GPT-5.5 约 9.1 秒。缓存命中按零计费：无 prompt token、无补全 token、不收费。

## 用请求头或 Presets 启用

在你希望纳入缓存的每次 API 调用中加上 `X-OpenRouter-Cache: true` 头：

```
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -H "X-OpenRouter-Cache: true" \
  -d '{
    "model": "google/gemini-2.5-flash",
    "messages": [{"role": "user", "content": "What is the meaning of life?"}]
  }'
```

**Presets。** 在 [preset 配置](https://openrouter.ai/workspaces/default/presets)中设置 `cache_enabled: true`，即可为该 preset 的所有请求启用缓存，单个请求无需加头。

你可以用 `X-OpenRouter-Cache-TTL` 控制响应缓存多久（1 秒到 24 小时，默认 5 分钟）。需要全新响应？发送 `X-OpenRouter-Cache-Clear: true` 即可清除该特定请求的缓存。

响应头会告诉你发生了什么：`X-OpenRouter-Cache-Status: HIT` 或 `MISS`，外加 `X-OpenRouter-Cache-Age` 和 `X-OpenRouter-Cache-TTL`，让你精确掌握缓存表现。

## 最有用的场景

**Agent 重试。** 当 agent 工作流中途失败时，你可以从头重试。缓存的步骤即时、免费地返回，你只需为新的工作付费。

**测试套件。** 反复跑你的 LLM 测试而不烧 token。第一次运行填充缓存后，后续运行既确定又免费。

**重复的上下文处理。** 如果你的 app 把同一个 prompt 发给同一个模型（同 system prompt、同用户输入、同参数），只有第一次调用产生费用。

## 现已覆盖大多数生成端点

缓存以你的 API key 为作用域。不同的 key（即使在同一账户下）不共享缓存条目。

该功能适用于 `/chat/completions`、`/responses`、`/messages` 和 `/embeddings`。其他端点——旧的 `/completions`、`/audio/speech`（TTS）、`/audio/transcriptions`（STT）、`/rerank` 和视频生成——暂不支持。功能目前处于 beta，我们会在锁定 API 表面之前观察其表现。

缓存命中不计入服务商限速（因为请求根本没到服务商），并且会带缓存标识显示在你的 [Activity 日志](https://openrouter.ai/activity)中，方便监控。

完整细节见[文档](https://openrouter.ai/docs/guides/features/response-caching)。
