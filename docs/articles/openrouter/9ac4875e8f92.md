# 如何将 Hermes Agent 与 OpenRouter 结合使用：设置、模型和路由

OpenRouter ·6/12/2026 · 更新于 9/24/2026

按 token 量计，Hermes Agent 是 OpenRouter 上被使用最多的应用，迄今已处理超过 17 万亿 token。OpenRouter 是人们运行 Hermes Agent 的主要方式之一，这套配置成熟、被广泛使用、且获得完整支持。

Hermes Agent 是 [Nous Research](https://github.com/NousResearch/hermes-agent) 的开源自主 agent，直接在终端里运行，可以用你选择的任何模型。把它接上 [OpenRouter](https://openrouter.ai)，你得到一个 API key 换来 70 多家提供商的 400 多个模型，外加自动故障转移和一张账单。

在讲其他之前先把一件事说清：Hermes Agent 和 Hermes 模型家族（Hermes 3 和 Hermes 4）是 Nous Research 同一生态里的不同部分。Hermes Agent 是应用，Hermes 3 和 Hermes 4 是它可以跑在上面的语言模型。本指南先讲清区分，再走一遍完整设置和路由配置。

## 太长不看

- Hermes Agent 是 Nous Research 的开源自主 CLI agent。Hermes 3 和 Hermes 4 模型是另一回事；agent 可以跑在这两个模型上，也可以经网关跑在任何模型上。
- 基础配置的默认模型是 `~anthropic/claude-sonnet-latest`。`openrouter/auto` 和 `openrouter/pareto-code` 是面向特定用途的可选路由模式。
- 多数配置需要至少 64K 上下文 token 的模型。更小的窗口可能直接被拒——系统提示词加工具 schema 就把它填满了。选之前到 [openrouter.ai/models](https://openrouter.ai/models) 查上下文长度。
- 一个 OpenRouter key 让 agent 接入 70 多家提供商的 400 多个模型，受支持的模型还有自动故障转移，单家提供商宕机不会中断会话。同一个 key 在[任意编码 agent 或 AI 工具](https://openrouter.ai/blog/tutorials/any-coding-agent/)里通用。
- 路由配置、回退链和辅助模型分流都住在 `~/.hermes/config.yaml`。起标题、视觉这类边任务可以跑在比主循环便宜的模型上。
- 运行 agent 本身免费（MIT 许可证）；你只为它花掉的模型 token 付钱。最新计费细节见 [openrouter.ai/pricing](https://openrouter.ai/pricing)。

## Hermes Agent 是什么（以及不是什么）

围绕 Hermes 的许多混淆，来自 Nous Research 同时做了一个 agent 和一个共享同名的语言模型家族。Hermes Agent 是一个命令行应用，Hermes 3 和 Hermes 4 是可以作为 agent 后端的语言模型。

人们搜"Hermes 3""Hermes 4""Hermes 4 405B"时，多半在找语言模型。Hermes Agent 是应用，Hermes 3 和 Hermes 4 是可以充当其后端的模型。

### agent 与模型：消歧表

|  | Hermes Agent | Hermes 3 / Hermes 4 |
| --- | --- | --- |
| 是什么 | 自主 CLI agent（一个应用） | 语言模型（大脑） |
| 出品方 | Nous Research | Nous Research |
| 你怎么运行它 | 安装 CLI，把它指向一个模型 | 通过提供商以模型 ID 调用 |
| 许可证 | 开源（MIT） | Nous Research 模型权重，按各自条款 |
| 关系 | 需要一个模型来思考 | 可以充当 Hermes Agent 跑在上面的模型后端 |

### Hermes Agent 实际做什么

Hermes Agent 自带 40 多个内置工具，覆盖网页搜索、浏览器自动化和图像理解等任务。它还包括一个消息网关，可连接 20 多个平台：Telegram、Discord、Slack、WhatsApp、Signal、Matrix 等。

让它区别于普通聊天界面的是持久记忆系统。它能跨会话记住信息，你不必每次开新对话都重讲项目细节和上下文。

agent 对运行地点也很灵活。可以部署在你本机，也可以用 Docker、SSH、Daytona、Modal、Singularity 等环境。

### 为什么 Hermes Agent 要配 OpenRouter？

跟多家 AI 提供商打过交道就知道事情多快变乱：每家一个账户、一个 API key、一套计费、一份模型目录。OpenRouter 用一个 API key 和一个计费账户，给你 70 多家提供商的 400 多个模型。

OpenRouter 本来就是 Hermes Agent 最流行的后端。截至 2026 年 6 月，Hermes Agent 在 OpenRouter 的[应用榜](https://openrouter.ai/apps)上按总 token 用量排名第一，处理量超过 17 万亿 token。这个集成被广泛使用、经过充分测试、在规模上得到验证。

| 没有网关 | 有 OpenRouter |
| --- | --- |
| 每家提供商一个账户、一个 key、一张账单 | 一个 key 接入 70 多家提供商的 400 多个模型 |
| 提供商 5xx 或限流时人工重试 | 会话中途自动故障转移，零运维 |
| 某些提供商失败调用照收费 | 失败的请求不计费 |
| 各家面板分开看用量 | 一个 activity 面板看全部模型 |
| 提供商列表价加自己的换算 | 零加价；目录价加一笔平台费 |

换模型就是改一个字符串。agent 做的一切都在你的用量视图 [openrouter.ai/activity](https://openrouter.ai/activity) 里留痕。

![Hermes Agent 请求经 OpenRouter 路由的示意图：提供商 A 服务请求，失败时 OpenRouter 回退到提供商 B](https://openrouter.ai/blog/images/hermes-agent-request-flow.png)

OpenRouter 自动在各提供商之间负载均衡，某家返回 5xx 或撞上限流时自动切换，长时间运行的 agent 任务不会因为一家提供商宕机被打断。失败请求的计费规则见[零补全保险](https://openrouter.ai/docs/guides/features/zero-completion-insurance)。

## 设置：把 Hermes Agent 连上 OpenRouter

还没装 Hermes 的话，从这一步开始：

```
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

Linux、macOS、WSL2 和 Termux 都可用。Windows 的原生 PowerShell 支持还在早期 beta。

装好后，把 Hermes Agent 连到 OpenRouter 只要两步：创建一个 API key，然后配置 Hermes 使用它。配置完成后，Hermes Agent 向 OpenRouter 认证，并用你在配置里指定的模型 slug 处理所有任务。

上下文长度是硬约束：多数配置至少需要 64K token 上下文，窗口更小 agent 可能拒绝启动。

系统提示词和工具 schema 在任何对话开始之前就已占掉上下文窗口的相当一部分。任何模型支持的上下文大小可在 [openrouter.ai/models](https://openrouter.ai/models) 查询。

### 推荐：交互式设置

[OpenRouter cookbook](https://openrouter.ai/docs/cookbook/coding-agents/hermes-integration) 建议从交互式模型选择器开始：

```
hermes model
```

它会引导你选提供商、配模型。Hermes CLI 仍在快速演进，确切流程以最新的集成 cookbook 为准；交互步骤可能随版本变化。

![Hermes Agent 终端展示交互式提供商选择器，OpenRouter 被选中](https://openrouter.ai/blog/images/hermes-agent-provider-select.png)

选模型时确认上下文至少 64K。推荐的起始项通常是 `~anthropic/claude-sonnet-latest`。动手前可以到 [openrouter.ai/models](https://openrouter.ai/models) 按上下文长度筛选确认。

配置成功很好辨认。运行 `hermes chat` 后，应看到 Hermes Agent 提示符显示已连接的提供商和所选模型。

如果拿到 401 错误或 "provider not found"，多半是 API key 没保存正确，或提供商名字有拼写错误。重跑一遍设置命令通常就好。

### 快捷：直接配置路径

想跳过交互流程，保存 key 立刻开聊：

```
hermes config set OPENROUTER_API_KEY sk-or-...
hermes chat --provider openrouter --model '~anthropic/claude-sonnet-latest'
```

`sk-or-...` 换成你的真实 OpenRouter API key。这会保存 key 并用 `~anthropic/claude-sonnet-latest` 别名开一场聊天。`~` 前缀告诉 OpenRouter 解析到该家族的最新模型。

编程式地给 agent 开配置、想避开交互流程时，这种方式好用。

### 手动配置（进阶）

密钥存 `~/.hermes/.env`，模型和提供商设置住 `~/.hermes/config.yaml`。压缩、辅助模型等高级特性直接在 `config.yaml` 里配。

把 API key 加进 `~/.hermes/.env`，从环境变量或密钥管理器加载。别提交进版本控制：

```
OPENROUTER_API_KEY=<your-api-key>
```

模型和提供商写进 `~/.hermes/config.yaml`：

```
model:
  provider: openrouter
  default: ~anthropic/claude-sonnet-latest
```

当你要对配置做版本管理、或程序化拉起 agent 时，这种方式顺手。

## 选模型

给 Hermes Agent 选模型时，最重要的要求是上下文长度：多数配置需要至少 64K token 才能正常运行。

上下文窗口更小的模型常常起不来。选之前到 [openrouter.ai/models](https://openrouter.ai/models) 按上下文长度筛选，确认所选支持至少 64K token。

### 模型 ID 如何工作

OpenRouter 的模型 ID 使用 `provider/model-name` 格式。`~` 前缀是一个路由快捷方式：它告诉 OpenRouter 自动解析到该模型家族可用的最新版本，而不是锁死在某个具体发布上。

| 模型 ID | 解析结果 |
| --- | --- |
| `~anthropic/claude-sonnet-latest` | 最新的 Claude Sonnet 别名（基础配置的默认） |
| `~google/gemini-flash-latest` | 最新的 Gemini Flash 别名（便宜、快，适合边任务） |
| `deepseek/deepseek-v4-flash` | DeepSeek 的快速聊天模型（性价比高） |
| `openrouter/auto` | 全目录自动路由，由此类任务上市场的支出份额驱动 |

完整目录可以在[模型页面](https://openrouter.ai/models)浏览，按上下文长度、价格和能力筛选。就本指南的这些工作流而言，64K 以下的基本跑不起来。

### 不想选时：自动路由

`openrouter/auto` 是一个可选路由模式。它根据 OpenRouter 社区过去滚动 7 天在此类任务上的总支出，为每个请求自动挑一个强模型。没有偏好模型、也不想做基准测试、只想要可靠结果时，它是好起点。

需要更多控制时，下面的路由一节有更细的选项。

## 提供商路由、回退与辅助模型

Hermes Agent 连上之后，`~/.hermes/config.yaml` 里的路由决定成本、可靠性和失败如何处理。

这个文件的三大控制（提供商路由、回退链、辅助模型分流）彼此独立，可以自由组合。

高层视角：模型选择决定哪项任务发给哪个模型；`provider_routing` 决定哪个提供商真正执行请求；该提供商失败时，`fallback_providers` 接管，把请求重路由而不打断会话、不丢上下文。

### 提供商路由控制

`provider_routing` 段控制哪个提供商处理每个请求：

| 字段 | 控制什么 | 示例值 |
| --- | --- | --- |
| `sort` | 优化轴 | `throughput`、`price`、`latency` |
| `only` | 提供商白名单 | `[anthropic]` |
| `ignore` | 提供商黑名单 | `[novita]` |
| `order` | 显式提供商优先级 | `[anthropic, google]` |
| `data_collection` | 提供商能否记录提示词 | `deny` |

设 `data_collection: deny` 阻止提供商记录你的提示词。其他合法取值见[提供商路由文档](https://openrouter.ai/docs/guides/routing/provider-selection)。

`:nitro` 和 `:floor` 后缀是 `sort` 设置的请求级快捷方式：`:nitro` 对应 `sort: throughput`，让该次请求优先速度；`:floor` 对应 `sort: price`，选可用的最便宜提供商。它们只对这一次调用覆盖 `provider_routing`，适合临时改行为而不动配置文件。

### 回退链

主力模型失败时 `fallback_providers` 接管。每个条目是一个提供商加模型的配对；某个触发时，Hermes 在会话中途切换过去，对话不丢。

```
fallback_providers:
  - provider: openrouter
    model: ~anthropic/claude-sonnet-latest
  - provider: openrouter
    model: ~google/gemini-flash-latest
```

主力报错时请求转到下一个条目，Hermes Agent 的记忆和上下文完好。对一个要跑几个小时的 agent，这就是"提供商打个小嗉"和"会话死了"的区别。

### 辅助模型

辅助模型负责生成标题、处理视觉请求、执行压缩这类边任务，让主力模型专注于真正的推理和编码。

```
auxiliary:
  title:
    provider: openrouter
    model: ~google/gemini-flash-latest
  vision:
    provider: openrouter
    model: ~google/gemini-flash-latest
  compression:
    provider: openrouter
    model: ~google/gemini-flash-latest
```

生成一个会话标题这种简单任务，没有理由动用 Claude Sonnet 这种高价模型。把它们分流给更便宜的模型（如 Gemini Flash），成本降了，主工作流一点不变。

一个好记的经验法则：每项辅助任务，指向你信任的里面最便宜的那个模型。

### 用 Pareto Code 路由器砍成本

想控成本又不想手动测试比较模型，[openrouter/pareto-code](https://openrouter.ai/docs/guides/routing/routers/pareto-router) 让 OpenRouter 自动挑"仍达到最低质量线"的最便宜模型：

```
model:
  provider: openrouter
  model: openrouter/pareto-code

openrouter:
  min_coding_score: 0.65
```

开启后，每个编码任务 OpenRouter 都选满足你所设阈值的最低成本模型。集成自动处理请求格式，你不用自己管路由逻辑。

编码分数范围 0.0 到 1.0，越高代表越强也越贵的模型。好的起点是 0.65：

- 例常小改、速度成本比精度要紧时，调低
- 复杂重构、正确性比省 token 要紧时，调高

### 把便宜选项叠起来

`openrouter/pareto-code` 管主编码循环，`auxiliary` 管标题、视觉和压缩等边任务。两者协同，还能再叠 `:floor` 路由进一步省钱。

OpenRouter 另外在多家提供商上提供 25 个以上免费模型。挑一个 64K+ 上下文的免费模型，爱好用途就能跑一个低成本甚至零成本的配置，把 Pareto 路由留给真正需要更强模型的任务。当前定价和免费档可用性见 [openrouter.ai/pricing](https://openrouter.ai/pricing)。

## 监控用量与排障

agent 用的一切都在同一个 API key 下，意味着所有活动在一处可见。你可以在 [openrouter.ai/activity](https://openrouter.ai/activity) 追踪所有 Hermes Agent 会话的请求、成本和 token 用量，支持按模型和时间范围筛选。

### 常见错误与修法

设置问题大多落进两类：

- Hermes 根本找不到你的 API key——问题在本地，通常意味着 key 从未存进 `~/.hermes/.env`。
- key 存在但认证仍失败——问题在账户侧：key 无效、过期，或 OpenRouter 账户没有剩余额度。

| 问题 | 修法 |
| --- | --- |
| "No API key" / provider not found | 确认 `~/.hermes/.env` 里有 key，或重跑设置命令 |
| 401 / 403 错误 | 在 [openrouter.ai/keys](https://openrouter.ai/settings/keys) 检查 key 有效性，并确认额度余额 |
| 模型不响应 | 核对 `~/.hermes/config.yaml` 里的模型 ID 在 [openrouter.ai/models](https://openrouter.ai/models) 上是合法的 `provider/model-name` |
| 启动时报上下文错误 | 换成上下文至少 64K 的 OpenRouter 模型 |

某个模型在别处能用、在 Hermes Agent 里却拒绝启动，通常是 64K 上下文要求作怪而不是配置错了。直接换一个模型，别去调 YAML。

如果你在探索其他终端原生 agent，OpenRouter 也为 [OpenClaw](https://openrouter.ai/docs/cookbook/coding-agents/openclaw-integration)（一个用同样后端的跨平台聊天 agent）提供了 cookbook 集成。

## 常见问题

### Hermes Agent 和 Hermes 3 / Hermes 4 模型是同一个东西吗？

不是。Hermes Agent 是 Nous Research 的开源自主 CLI 应用；Hermes 3 和 Hermes 4 是同一团队的独立模型家族。你可以让 Hermes Agent 以 Hermes 模型为后端运行——通过 OpenRouter 也可以用任何模型。

### Hermes Agent 免费吗？

agent 开源（MIT）、运行免费。你只为它经提供商用掉的模型 token 付钱。当前费率含免费档模型见 [openrouter.ai/pricing](https://openrouter.ai/pricing)。

### 在 OpenRouter 上该给 Hermes Agent 配什么模型？

从 `~anthropic/claude-sonnet-latest` 开始：它是文档里基础配置的默认，满足 64K 上下文要求。跑起来之后，`openrouter/auto` 替你自动路由到强模型不用选，`openrouter/pareto-code` 专为编码任务优化成本。

### 需要单独的提供商账户吗？

对多数受支持的模型不需要。一个 OpenRouter key 就给 Hermes Agent 接入 70 多家提供商的 400 多个模型，带自动故障转移。

某个模型上遇到访问错误时，到 [openrouter.ai/models](https://openrouter.ai/models) 查它的页面——有些模型需要提供商侧的特定资格。多数情况下换一个模型就解决。

### 为什么 Hermes Agent 启动时拒绝我的模型？

多数配置需要至少 64K 上下文 token，更小的窗口装不下系统提示词加工具 schema。换一个更大上下文的模型——到 [openrouter.ai/models](https://openrouter.ai/models) 按上下文长度筛候选。

### OpenRouter 跑 Hermes Agent 要额外收费吗？

不对提供商定价加价。平台费等最新计费细节——包括失败请求如何处理——见 [openrouter.ai/pricing](https://openrouter.ai/pricing)。
