视频生成功能现已在 OpenRouter 上线。一个 API 就能访问顶尖视频模型。视频与文本、图像、音频、embedding 和 reranker 并列，共享同一套路由、治理与计费层。

[![Watch our launch video](https://imagedelivery.net/Xq3eUzdKO2-MoBklzEEuMQ/4b5e6f7a-8c9d-4e1f-2a3b-5c6d7e8f9a0b/w=1200)](https://www.youtube.com/watch?v=bUQjWkW4-LU)

首日我们即支持 Seedance 2.0 / 1.5、Veo 3.1、Wan 2.7 / 2.6 和 Sora 2 Pro 的文生视频与图生视频，更多模型在路上。[浏览所有支持的模型](https://openrouter.ai/models?fmt=cards&output_modalities=video)，[了解功能详情](https://openrouter.ai/docs/guides/overview/multimodal/video-generation)，或直接查阅新 `/api/v1/videos` 的 [API 文档](https://openrouter.ai/docs/api/api-reference/videos)。

视频 API 是碎片化的。各家服务商使用不同的请求结构、参数名和计费单位。我们围绕这些差异设计了这套 API：

- **异步生成**：这些生成任务需要几分钟，所以我们按作业（job）跟踪。提交 prompt，拿到 job ID，生成完毕后取回视频。
- **参数归一化**：我们提供一套跨所有模型通用的 schema，包括分辨率、时长、宽高比、音频生成、首尾帧图像和参考图像。
- **能力发现**：在调用之前以编程方式确定每个模型支持什么。
- **透传参数**：需要时直接使用模型特有的功能。

## 一个统一 API

视频模型通常以一个端点家族发布，每个端点提供一种特定能力，如 text-to-video、image-to-video 或 reference-to-video。我们简化了这一点：根据你的参数自动路由到正确的端点。

视频模型的差异往往不那么显而易见。单是 `duration` 就能轻易让请求失败——Veo 3.1 支持 4、6 或 8 秒短片，而 Wan 2.6 支持 5 或 10 秒。我们还统一了传入参考图像（如角色）和帧图像（如首帧与尾帧）的方式。

每个模型也可以暴露自己的特性。例如 Veo 3.1 有一个独特的 `personGeneration` 参数，控制输出中是否出现人物。`/api/v1/videos/models` 端点会精确告诉你有哪些模型专属参数可用。

你不必自己跟踪这些差异，可以调用 [video models 端点](https://openrouter.ai/docs/api/api-reference/videos)，在一处查看支持的分辨率、宽高比、定价、输入图像和时长：`/api/v1/videos/models`。这个端点非常适合交给你的 coding agent，它所需的全部细节都在这里，无需为可接受输入参数的报错反复搏斗。

为了直观预览，我们还在模型页面新增了 Playground 标签页，你可以试用每个模型、看看它们能做出什么。

## 多模态工作流

最让我们兴奋的，是看到视频与其他生成类型结合时的成果。LLM 可以把粗糙的想法变成详细 prompt，图像模型可以生成主角，视频模型再把这个角色变成一个场景——全程通过同一个 API。

我们很快认识到这些模型很吃“具体性”。镜头运动、光线、质感、节奏、动作风格，全都重要。你提供的细节越多，获得的控制就越多。这让视频生成天然适合由 LLM 生成 prompt。

我们构建了一个开源演示应用，展示这种多模态工作流的实际效果：[multimedia-explorer.openrouter.ai](http://multimedia-explorer.openrouter.ai)。全部代码在 [GitHub](https://github.com/OpenRouterTeam/multimedia-explorer) 上。
