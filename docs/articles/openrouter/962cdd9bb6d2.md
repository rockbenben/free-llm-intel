# AI 代理的服务器端代码执行工具比较

OpenRouter ·10/5/2026

假设你在做一个 agent，回答客户上传的 CSV 的问题。模型需要运行 Python 才能得出答案。这段代码跑在哪里？

一个选项是自己跑。这意味着要上 [E2B](https://e2b.dev/) 或 [Modal](https://modal.com/) 这样的沙箱平台，或者 Docker 里自己的容器，外加一堆杂活：把它和你的数据库、互联网隔开，限制运行时长，给镜像打补丁。

服务器端代码执行工具是另一个选项。你在 API 请求里加上这个工具，模型自己决定什么时候需要跑东西，提供商在它自己的沙箱里执行命令，并在同一个请求内把输出还给模型。这里的沙箱指的是一个隔离的 Linux 容器：自带文件系统、有时间上限、默认没有网络访问。

本文覆盖当前提供服务器端代码执行的四家提供商、每家沙箱能做什么不能做什么、在延迟和金钱上的代价，以及那些仍然需要你自己运营沙箱的活。

## 太长不看

- 服务器端代码执行工具在你的 API 请求期间，在提供商的沙箱里运行模型的命令。你不用配置、打补丁或加固任何容器。
- OpenAI、Anthropic、Google 各自只为自己的模型跑代码。我们的 [openrouter:shell](https://openrouter.ai/docs/guides/features/server-tools/shell) 工具在 Responses 和 Messages API 上为任何模型跑命令，[openrouter:bash](https://openrouter.ai/docs/guides/features/server-tools/bash) 工具只在 Messages API 上做同样的事。两个工具都在 beta。
- 我们的沙箱是隔离容器，归属到你的账户和 workspace，出站网络默认关闭，每条命令有运行时间和输出大小的硬限。沙箱时间按每秒 $0.0001 计费，新建或休眠中的容器最低收 30 秒。
- 需要自定义基础镜像、GPU 工作或跑几个小时的会话时，你自己运营的沙箱平台依然是正确选择。

## 服务器端代码执行是什么意思

模型从不亲自运行任何东西。它调用工具时，发出的只是一个写着工具名和参数的请求，总得有东西去执行。客户端工具里，那个"东西"是你的应用代码或你所依托的 agent 框架：你的应用收到调用、执行、把结果放进后续请求发回去。服务器端工具里，提供商在自己的基础设施上执行调用，并在同一个请求内把结果还给模型，你的应用不需要为它写任何 handler。服务器端代码执行就是后一种。

你可能已经在用这样工作的工具了。[Web search](https://openrouter.ai/docs/guides/features/server-tools/web-search) 让模型在实时网络上查东西，[web fetch](https://openrouter.ai/docs/guides/features/server-tools/web-fetch) 让它读取某个 URL 的内容。两种情况都是你在请求里加一个条目，剩下的交给提供商。代码执行只是把同一模式用在"跑命令"上。

### 一次工具调用如何变成一条被执行的命令

以下步骤适用于任何服务器端代码执行工具。出现字段名的地方，是我们 shell 工具用的名字。

- 你把工具放进请求的 `tools` 数组。
- 模型决定需要跑点什么，发出一个携带一条或多条 shell 命令的调用。
- 提供商在一个沙箱容器里按顺序执行这些命令。
- 每条命令的标准输出、标准错误和结果都还给模型。结果要么是一个退出码，要么是超时。
- 模型读结果，然后要么回答你，要么在同一个请求里再跑更多命令。

第 2 到第 5 步不断重复，直到模型作答。模型跑点东西、读输出、判断要不要再来一条命令、继续。代码执行工具的价值就在这个循环里——模型可以拿真实输出校验自己的工作，而不是靠猜。

我们给这个循环封顶。`max_tool_calls` 字段设定一个请求最多能走多少步服务器工具。我们的[服务器工具参考](https://openrouter.ai/docs/guides/features/server-tools#tool-call-limits)把默认值和最大值都定为 30。

### 托管沙箱和你自跑的沙箱有何不同

自己跑沙箱，意味着提供商原本负责的那些部分全归你：选基础镜像、配算力、接一个 SDK 来启动运行和读输出、管理每次运行的生命周期，安全边界也归你。

托管工具把这些控制权换成 JSON 数组里的一个条目。你不用给容器定规格、打补丁或运营它。我们造 openrouter:shell，针对的就是"每个请求跑几条短命令"这种活。

## 现在谁提供托管代码执行

本文覆盖 OpenAI、Anthropic、Google 和 OpenRouter。Agent SDK 和专职沙箱平台是另外的类别，都会在文章后面出现。区分这四家提供商的关键，是各自为哪些模型跑代码。

### OpenAI 为 OpenAI 模型跑托管 shell

OpenAI 的 [shell 工具](https://developers.openai.com/api/docs/guides/tools-shell)在 OpenAI 管理的容器里执行命令，跑在 Responses API 上。OpenAI 文档写的托管运行时是 Debian 12，默认工作目录 `/mnt/data`。命令不带 `sudo` 运行，不支持交互式 TTY 会话。文档列出的预装语言包括 Python 3.11、Node.js 22.16、Java 17、PHP 8.2、Ruby 3.1 和 Go 1.23。

托管容器默认没有出站网络。要开通，需要组织管理员在 OpenAI 控制台配置白名单，并在请求的容器环境里设置 `network_policy`。容器可以在多个请求之间复用——通过 `container_reference` 环境传入它的 id，过期时间在容器创建时设定。OpenAI 另有一个专门跑 Python 的 [code interpreter 工具](https://developers.openai.com/api/docs/guides/tools-code-interpreter)。

### Anthropic 为 Claude 模型跑 Python 和 Bash

Anthropic 的 [code execution 工具](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool)在 Anthropic 管理的沙箱里运行 Python 和 Bash，跑在 Messages API 上。文档描述的环境是 Linux x86_64 容器：Python 3.11、5 GiB 内存、5 GiB 工作区存储、单 CPU。互联网访问禁用、不允许任何出站连接，所以 Claude 只能用预装库，运行中装不了新包。

[工具版本](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool#tool-versions)有三个，所有受支持的模型三个都接受。`code_execution_20250825` 支持 Bash 命令和文件操作。`code_execution_20260120` 增加了跨请求持久的 Python 解释器状态，这依赖 Anthropic 的 programmatic tool calling，Claude Haiku 4.5 上不可用。容器创建于 30 天后过期。闲置约 5 分钟后容器被 checkpoint，30 天窗口内带其 id 的请求可以恢复它。

### Google 为 Gemini 模型跑 Python

Google 的 [code execution 工具](https://ai.google.dev/gemini-api/docs/code-execution)在 Google 管理的沙箱里运行 Python，在请求的 tools 里加一条 `code_execution` 即启用。文档写明模型只能生成并执行 Python，代码环境最长运行 30 秒，你不能安装自己的库。Google 公布了环境包含的库清单。

### 我们为任何模型跑托管 shell

上面三个工具各自只配一家的模型用。我们的工具在 Responses 和 Messages API 上对任何模型都有效，因为我们把沙箱做在路由层，而不是某一家模型提供商内部。

我们出货两个代码执行工具。[openrouter:shell](https://openrouter.ai/docs/guides/features/server-tools/shell) 对齐 OpenAI 托管 shell 工具的形态，在 [Responses API](https://openrouter.ai/docs/api_reference/responses/overview) 和 Messages API 上都能用。[openrouter:bash](https://openrouter.ai/docs/guides/features/server-tools/bash) 对齐 Anthropic bash 工具的形态，只在 Messages API 上可用。

两个工具都处于 beta，API 可能变化。沙箱执行只在全局的 `openrouter.ai` 端点上运行。[in-region 端点](https://openrouter.ai/docs/guides/features/in-region-routing#feature-availability)不提供 shell 工具，Chat Completions 会对两个工具都返回 400，并说明支持它们的 API 是哪两个。

在任一工具上把 `engine` 设为 `openrouter`，命令就跑在我们的沙箱里。`engine` 默认是 `auto`。对 openrouter:shell，`auto` 的含义是：某提供商存在原生托管 shell 时保留用它，否则落到我们的沙箱。对 openrouter:bash，`auto` 会把工具调用返回给你的应用去客户端执行，我们的服务器上什么都不跑。

### 在我们的沙箱里跑一条命令

下面是一个完整的请求：跑两条命令并读回结果。

```
import os
import requests

response = requests.post(
    "https://openrouter.ai/api/v1/responses",
    headers={"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"},
    json={
        "model": "anthropic/claude-sonnet-4.5",
        "input": "Run `cat /etc/os-release` and `python3 --version`, then tell me the OS and Python version in one sentence.",
        "tools": [
            {"type": "openrouter:shell", "parameters": {"engine": "openrouter"}}
        ],
    },
)

for item in response.json()["output"]:
    if item["type"] == "openrouter:shell":
        print(item["container_id"], item["action"]["commands"])
        for result in item["output"]:
            print(result["stdout"], result["outcome"])
```

2026 年 9 月 22 日我们实际跑了这个请求。模型把两条命令放进一个 shell 调用发出，每条命令带各自的结果返回。完整的 `os-release` 输出有好几行，这里截取头两行。

```
{
  "type": "openrouter:shell",
  "container_id": "sess_art10-418b8597e044",
  "action": { "commands": ["cat /etc/os-release", "python3 --version"] },
  "output": [
    {
      "stdout": "PRETTY_NAME=\"Ubuntu 22.04.5 LTS\"\nNAME=\"Ubuntu\"\n",
      "stderr": "",
      "outcome": { "type": "exit", "exit_code": 0 }
    },
    {
      "stdout": "Python 3.11.14",
      "stderr": "",
      "outcome": { "type": "exit", "exit_code": 0 }
    }
  ]
}
```

那天沙箱报告的是 Ubuntu 22.04.5 LTS、Python 3.11.14。运行时镜像可能变动，版本信息请从容器里读，别写死。其余参数见[服务器工具参考](https://openrouter.ai/docs/guides/features/server-tools)。

### 替你包好沙箱的 Agent SDK

如果你基于 agent SDK 构建而不是直接调 API，有些 SDK 已经包了这类工具。

[OpenAI Agents SDK](https://openai.github.io/openai-agents-python/tools/) 自带 `CodeInterpreterTool`（在 OpenAI 沙箱里跑代码）和 `ShellTool`（根据你的环境配置，在你本地运行时或 OpenAI 托管容器里跑，二选一）。别默认命令跑在远端，先确认你配的是哪种模式。我们这边，openrouter:shell 就是 `tools` 数组里普通的一条，进 [OpenRouter Agent SDK](https://openrouter.ai/docs/agent-sdk/overview) 循环的方式和进原始请求完全一样。

### 哪些情况仍然需要你自己的沙箱

托管工具适合短小、有边界的工作：跑个脚本、转换一个文件、校验一个结果。凡需要特定基础镜像或 GPU 的，都超出这四个托管工具的能力，需要你自运营的沙箱平台。

## 我们的沙箱强制什么

沙箱的意义在于你不必信任模型。一条你从没打算让它跑的命令碰不到网络、也碰不到别人的容器，而且它会在"跑多久、打多少字"的硬限制处停下。本节所有内容描述的都是我们的沙箱，其他三家差异见上表。

### 对每条命令生效的限制

我们在隔离容器里执行每条命令——与服务你请求的基础设施隔离、与你的机器隔离，归属到你的账户和 workspace。你自己设上限：`timeout_ms` 管一条命令能跑多久，[max_output_length](https://openrouter.ai/docs/guides/features/server-tools/shell#call-arguments) 管它能打多少字。`timeout_ms` 默认 120,000 毫秒，不能超过 300,000 毫秒。`max_output_length` 默认每路流 16,384 字符，不能超过 65,536。超过 100 条命令的 shell 调用会被拒绝。

出站网络默认不通，你不开就不通。2026 年 9 月 22 日我们验证过：发一个不带 `network_policy` 的请求，让模型用 `curl` 抓 `https://example.com`，只打印 HTTP 状态码，5 秒放弃。命令打印了 `000`——`curl` 收不到任何响应时打印的就是它——退出码 28，一个 `curl` 超时。

```
{ "stdout": "000", "stderr": "curl: (28) Failed to connect to example.com port 443 after 5206 ms: Connection timed out", "outcome": { "type": "exit", "exit_code": 28 } }
```

要开网络，设一个最多 50 个主机名或通配模式的 `network_policy` 白名单。只有 80 和 443 端口可达，策略在容器启动时就固定。`pip install` 需要 `pypi.org` 和 `files.pythonhosted.org` 都在白名单里。

### 提示词注入，以及沙箱限制住什么

给模型一个 shell，就把你暴露在[提示词注入](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)之下。如果你的 agent 读网页、支持工单或某人上传的文件，攻击者可以把指令藏进文本，叫模型无视你的提示词去跑别的东西。

上面那些限制不分场景——模型在执行你的指令还是攻击者的指令，它们照样生效。一条被注入指令驱动的命令，够不到你配置的 `network_policy` 之外的任何主机；策略关闭时它根本没有网络。它够不到其他租户的容器，同样在超时处停下。白名单会扩大注入命令能触达的范围，`allowed_domains: ["*"]` 等于放行任意出站，所以白名单只放这份工作需要的宿主。

请求里到来的尝试也可以被检测。[workspace guardrail](https://openrouter.ai/docs/guides/features/guardrails) 中的 [Prompt-injection detection](https://openrouter.ai/docs/guides/features/guardrails/prompt-injection) 会在请求转发给模型之前，用常见注入技术的正则模式检查每个入站请求的用户消息内容。它不检查服务器工具在此之后抓取的内容，所以模型通过工具读到的页面、文件或命令输出需要你自己的控制手段，比如审阅你的应用收到的沙箱输出。命中时按你配置的动作三选一。

- Flag：记录检测结果，请求原样转发。
- Redact：把命中的片段替换成 `[PROMPT_INJECTION]`，转发净化后的请求。
- Block：请求还没到模型就被 403 拒绝。

多条 guardrail 同时生效时，最严格的动作优先，顺序是 block、redact、flag。检测并不穷尽，也可能误报，所以在启用 redact 或 block 之前，先用 flag 模式在你自己的流量上测量命中率。误报可以在 Logs 页面举报。

## 托管沙箱在秒数和金钱上的代价

托管沙箱会给请求加上几秒，代价换的是你没有任何基础设施要跑。它还给你一个随时能回来的容器。

### 文件跨请求存活

命令在 `/workspace/home` 里运行，每条命令之后我们保存该目录下发生变化的文件。发送一个稳定的 `session_id`，或在工具[环境](https://openrouter.ai/docs/guides/features/containers#container-ids)配置里设一个容器 id，带这个 id 的每个请求都会到达同一个容器、同一批文件。`session_id` 只能使用字母、数字、`_` 和 `-`。含其他字符的 id 会被忽略，我们按你没发 `session_id` 来选容器——即取回放会话里最近的 `container_id`（如果有），否则为该请求开新容器。`session_id` 超过 20 个字符时我们只用最后 20 个，所以两个结尾相同的长 id 会共享容器。`container_reference` 的 id 可以是同一字符集的 1 到 40 个字符且不做截断，需要精确 id 时用它。2026 年 9 月 22 日我们验证过：第一个请求写一个文件，第二个请求用同一个 `session_id` 把它读回来。

容器闲置 5 分钟后休眠，空闲时间不可配置。休眠不删文件。带同一 id 的请求稍后到达时，会启动一个新沙箱并先加载保存的文件。打开的进程、环境变量和安装过的系统状态不会恢复，所以请把唤醒后的容器当作"装了你的文件的新机器"。保存的文件在容器最后使用之后保留 30 天。要取出产物，`GET /api/v1/containers/{container_id}/files` 列出容器生成了什么，[promote 端点](https://openrouter.ai/docs/guides/features/containers#save-a-container-file-to-your-workspace)把文件复制进你的 workspace 文档区，那里不会过期。

### 事后能复查什么

响应里每个 shell 工具结果都带着模型跑过的命令和每条命令的 stdout、stderr 和结果，你的应用可以像记录响应其他部分一样记录它们。[Input & Output Logging](https://openrouter.ai/docs/guides/features/input-output-logging) 把提示词和补全存在 OpenRouter 上供 Logs 页面复查，guardrail 检测结果也在那里出现。生产监控方面，[Broadcast](https://openrouter.ai/docs/guides/features/broadcast) 在请求完成时把 trace 流到外部可观测平台。

如果你走 [in-region](https://openrouter.ai/docs/guides/features/in-region-routing#feature-availability) 路由，shell 工具不可用，Input & Output Logging 即使开启也会被跳过。Broadcast 支持 in-region 路由，每个目的地自行配置它接收哪些数据区域来的 trace。

### 一次往返的代价

跑沙箱命令的请求比不带它的同一个请求慢。2026 年 9 月 22 日我们发的一组单请求里，不带 shell 工具的请求约 2 秒返回，做一次 shell 调用的请求视模型不同在 8 到 21 秒之间返回。那只是同一会话里的单次样本，不是基准。按每次 shell 调用几秒的开销做预算。

沙箱时间按每秒 $0.0001 计费。计时从请求首次跑沙箱命令开始，到响应完成停止。启动新建或休眠容器的请求最低收 30 秒；之后复用同一个热容器的请求只按实际计量付费。上面那个请求启动了一个新容器，它的 usage 对象报告 `server_tool_cost` 为 0.003——就是 30 秒最低消费。容器在请求之间空闲时不计费。

### 什么时候你想要自己的沙箱平台

当托管工具给不了你要的东西时，选专职沙箱平台。[Modal](https://modal.com/docs/guide/sandbox) 文档支持用自定义镜像构建沙箱、生命周期最长可配 24 小时、可上 GPU。[Daytona](https://www.daytona.io/docs/en/sandboxes/) 支持从公共容器镜像创建沙箱，也有 GPU 沙箱。[E2B](https://e2b.dev/docs/sandbox) 的 Pro 计划沙箱最长运行 24 小时、基础计划 1 小时，长任务可用暂停和恢复。

## 结论

模型请求内部的短小有界命令，用托管工具。你在 `tools` 数组加一个条目，得到出站网络关闭的隔离容器，付费是推理加沙箱运行的秒数。按每次 shell 调用几秒的开销做预算，尽量复用容器。

当工作需要自定义基础镜像、GPU、运行数小时的会话，或需要安全边界本身的所有权时，迁移到你自运营的沙箱平台。无论哪种，承诺之前先查提供商最新文档——我们的两个工具还在 beta，另外三家的工具也一直在变。

## 常见问题

### 有没有模型可以在请求期间直接调用的托管沙箱 shell 工具？

有。我们的 openrouter:shell 服务器工具在请求期间于我们的基础设施上给模型一个沙箱化 Linux shell，Responses API 和 Messages API 都支持。把 `engine` 设为 `openrouter`，命令就在隔离容器里执行，每条命令的 stdout、stderr 和退出/超时结果都返回给模型。OpenAI、Anthropic 和 Google 也各自为自己的模型提供托管代码执行工具。

### 我能给模型一个可以跑命令的沙箱 shell 吗？

能。在 Responses 或 Messages API 请求的 `tools` 数组里加 `{"type": "openrouter:shell", "parameters": {"engine": "openrouter"}}`。模型随后就能发出 shell 调用，我们在隔离容器里执行命令并把每条命令的输出交还模型。除非你配置 `network_policy` 白名单，容器没有出站网络。

### 哪些 SDK 或平台开箱即用地提供服务器端代码执行？

我们的 openrouter:shell 在 Responses 和 Messages API 上为任何模型跑命令，openrouter:bash 只在 Messages API 上做同样的事。OpenAI、Anthropic、Google 分别通过 Responses API 的 shell 工具、code execution 工具和 Gemini API 的 code execution 工具为自己的模型跑代码。OpenAI Agents SDK 把 OpenAI 的托管工具包成了 `CodeInterpreterTool` 和 `ShellTool`。E2B、Modal 和 Daytona 是需要你自己集成和运营的沙箱平台，不是提供商在 API 调用内部运行的工具。

### 哪种沙箱最适合 AI agent？

取决于工作跑多久、你对运行时的控制需求有多大。请求内部的短命令，用 openrouter:shell 这样的托管工具意味着你什么都不用自己跑。需要自定义基础镜像、GPU 或数小时的会话，用 Modal、Daytona 这类自运营沙箱平台才能拿到这些控制权。

### 怎么给 AI agent 做沙箱？

让 agent 的命令在一个与你自有系统隔离的环境里运行，并限制这个环境能触达什么。用托管工具时，这些由提供商完成。在 OpenRouter，容器与我们的基础设施和你的机器都隔离、归属到你的账户和 workspace；出站网络默认关闭；每条命令受 `timeout_ms` 约束；输出受 `max_output_length` 截顶。Workspace guardrail 还在模型前面加了提示词注入检测。

### 什么叫沙箱化 AI 工具？

指副作用被关在隔离环境里、而不是落在你生产系统上的工具。就代码执行而言，模型的命令跑在一个自带文件系统、受限网络访问、有时间上限的容器里，只有命令输出会回到模型手上。我们的 shell 和 bash 服务器工具就是这么工作的。
