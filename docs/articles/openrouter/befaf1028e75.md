# 如何在编辑器里实时选择最佳 AI 模型

OpenRouter ·8/25/2026 · 更新于 9/24/2026

选 AI 模型的流程是：定义任务，从实时用量和基准数据里缩小候选，比较各提供商的价格和延迟，然后在你自己的提示词上测试入围者。评判标准用"每个完成任务的成本"而不是"每 token 成本"，并且要预期答案会随新模型发布而变化。

我们不会点名一个最佳模型。任何我们印出来的名字一个月内就会过时，而且正确的模型取决于你在构建什么、愿意为正确结果付多少钱。

本文描述我们用来回答这个问题的那套框架，以及如何在不出编辑器的情况下运行它。我们的 [MCP server](https://openrouter.ai/docs/guides/overview/mcp-server) 把你的助手接到实时用量排行、第三方基准、逐提供商定价，以及一个向候选模型发测试提示词的方式上。

## 太长不看

- "最佳"意味着你的任务、你的每完成任务成本、你的延迟预算。榜单排名不在三者之内。
- 基准用来建候选名单，你自己的提示词用来定胜负。[Ori Eval](https://openrouter.ai/docs/guides/ori/eval) 可以替你写并运行这个对比。
- 通过 MCP 在编辑器里查询实时排行和价格，再用 `get-generation` 量出每次测试调用的实际成本。
- 没有模型能明显胜出时，用 `openrouter/auto-beta` 按请求路由，而不是硬选一个。

![六步框架流程：定义任务，然后经 OpenRouter MCP server 缩小候选、比较、测试、测量，最后决定或用 openrouter/auto-beta 路由](https://openrouter.ai/blog/images/choose-best-ai-model-framework.png)

## 为什么不存在唯一的最佳 AI 模型

没有唯一的最佳 AI 模型，只有在给定任务、预算和时间点下最佳的模型。

不同的任务要不同的强项。摘要和编码对模型的要求不同；抽取任务更需要每次调用都输出合法 JSON，而不是漂亮的散文；聊天功能取决于第一个 token 多快到达——这和完整答案的质量是两回事。编码基准榜首的模型，照样可能在长文档上表现糟糕，并对日常抽取贵得离谱。

更有用的问题会带上具体的活。别问"最佳 AI 模型是什么"，问"从扫描的发票里抽取行项目的最佳模型是什么"，或"评审 TypeScript pull request 的最佳模型"，或"总结 90 分钟会议转写的最佳模型"。写下你自己版本的问题，然后用当下的数据来回答，而不是用一份旧榜单。

我们的流量展示了答案随任务变化有多大。我们把请求样本分类成 29 种任务类型并[公布市场份额](https://openrouter.ai/rankings)。仅编码就占九类：代码生成、调试、代码评审、仓库扫描、SQL 工作和 DevOps 配置。这九类并不共享同一个领跑者。在截至 2026 年 7 月 25 日的七天窗口里，一个模型领跑其中八类，而代码评审和安全类的领跑者是另一个。"最适合编码的最佳模型"哪怕在编码内部都问得太宽了。

## 基准是过滤器，不是答案

基准的价值在于把上百个选项收窄成几个你可以好好测的候选。我们把 [Artificial Analysis](https://artificialanalysis.ai) 和 [Design Arena](https://designarena.ai) 的第三方分数与自己的用量数据并排呈现。

排行榜替不了最终选择：分数有噪声，热门基准招针对性调优，而且没有一个跑过你的提示词。用排行榜建候选，用你自己的测试定夺。

不同任务要不同强项。编码要推理质量和可靠的工具调用；摘要要大上下文窗口和低输入价；抽取更需要对 schema 的一致遵守而非流畅；聊天要低延迟；视觉需要一个根本接受图像的模型——在谈质量之前就先筛掉一批。

没有一个模型领跑所有类别。选一个模型包打一切，得到的就是一个昂贵的默认值：演示里表现不错，你真跑的工作上表现不佳。

## 配置 OpenRouter MCP server

下面每一步都通过 MCP server 跑，所以先把它接上。

[OpenRouter MCP server](https://openrouter.ai/docs/guides/overview/mcp-server) 由我们托管，本地什么都不用装，任何 MCP 客户端都能连。下面的配置覆盖 Claude Code、Cursor 和 Codex CLI，文档里还有 OpenCode 和 Claude Desktop。连接一次，你的助手就能拉取实时的模型、价格、额度、排行、基准和文档，还能发测试提示词——人不用离开编辑器。选模型的过程中用它；上线时照常调 [API](https://openrouter.ai/docs/api_reference/overview)。

**Claude Code：**

```
claude mcp add --transport http openrouter https://mcp.openrouter.ai/mcp
claude mcp login openrouter
```

也可以在会话里运行 `/mcp`、选中 **openrouter**、点击 **Authenticate** 完成认证。

**Cursor：** 把下面这段加进 `~/.cursor/mcp.json`，然后用 `cursor-agent mcp list` 验证。

```
{
  "mcpServers": {
    "openrouter": { "url": "https://mcp.openrouter.ai/mcp" }
  }
}
```

**Codex CLI：**

```
codex mcp add openrouter --url https://mcp.openrouter.ai/mcp
codex mcp login openrouter
```

认证是浏览器里的一步，三个编辑器里的方式完全一样。Cursor 下它在第一个请求时触发而不是靠登录命令。未认证的请求返回 401 并启动我们的 OAuth 流程，授权页在你同意之前会写清你同意的是什么。

![OpenRouter 的 MCP 连接授权页面（来自 Claude Code），显示账户、$10 的默认额度上限、key 标签，以及请求将重定向到本地应用的警告](https://openrouter.ai/blog/images/choose-best-ai-model-oauth.png)

我们会签发一个标签为 `OpenRouter MCP: <app name>` 的 key，作用域限定到该客户端，七天过期，带一个可以在该页面上修改的 $10 额度上限（[MCP 公告](https://openrouter.ai/blog/announcements/openrouter-mcp-server/)）。这个 key 短命、默认限额、随时可断开，也可以在你的 [keys 控制台](https://openrouter.ai/settings/keys)吊销。

流程会重定向到 localhost——对 Claude Code、Cursor 这类桌面客户端是正常的，但也意味着我们无法验证接收 key 的是哪个本地应用。只有几分钟前确实是你本人发起的连接，才点同意。

### 你会用到的工具

多数是对实时数据的只读查询。例外是 `send-message`、`generate-image`、`transcribe-audio`、`generate-speech`——它们会产生计费的推理调用——以及 `send-feedback`，它在你自己的一次生成上写反馈（[MCP 文档](https://openrouter.ai/docs/guides/overview/mcp-server)）。

| 工具 | 返回什么 |
| --- | --- |
| `list-task-classifications` | 按任务类型的流量份额，以及每类的领跑模型 |
| `list-benchmarks` | Artificial Analysis 和 Design Arena 的第三方分数，可按任务类型筛选 |
| `list-daily-model-rankings` | 前 50 模型的逐日 token 总量，看趋势而非任务适配 |
| `list-models` / `get-model` | 搜索实时目录；单个模型的完整详情 |
| `list-model-endpoints` | 服务某模型的每家提供商，含价格、延迟、吞吐和数据政策 |
| `search-docs` | 工具内直接取我们现行文档的答案 |
| `send-message` *（计费）* | 用你的提示词跑候选。支持 `:online`、`:nitro`、`:floor`、`:free` |
| `get-generation` | 单次调用的精确成本、token 数、提供商和延迟 |

## 选模型的六步框架

按顺序跑。第 2 到第 5 步各自对应一个助手可以对实时数据发起的调用。第 1 和第 6 步是你的判断：你定义需要什么，再决定发什么。

### 第 1 步：按你要上线的样子定义任务

从活开始，不是从模型名开始。写下输入、期望的输出、什么算好、你的延迟目标，以及成本与质量冲突时你偏向哪边。

最后一条影响后面每一步。给客户看的摘要值更高的价格；跨一百万条记录的夜间抽取任务值更低的价格——哪怕牺牲一点质量，因为量决定账单。说清楚你在建哪一种。

### 第 2 步：从实时数据建候选

候选名单来自两个问题：人们在这件活上用什么？什么在这件活上分数高？

第一个问题调 `list-task-classifications`：它返回我们 29 个任务标签在滚动七天窗口上的数据，每个标签带用量份额和真实流量中服务它的模型排名。第二个问题调 `list-benchmarks`，`task_type` 设 coding、intelligence 或 agentic，返回 Artificial Analysis 和 Design Arena 分数加价格。这三个基准类别是有意比 29 个流量标签更粗的，两个调用要配合使用：基准过滤先在一个大类别里剔除低分模型，流量标签再告诉你在这一类的具体哪个部分人们实际用什么。

`list-daily-model-rankings` 用来看趋势。默认返回全体前 50 模型的逐日 token 总量，外加每天一行聚合的 `other`。可以按 `programming`、`roleplay` 这类用途类别、模态或工具调用活跃度收窄，但类别切片来自按周聚合的抽样数据集，这些总量请当估算。它告诉你什么在涨，不是谁在你的活上表现好。同样的视图在 [openrouter.ai/rankings](https://openrouter.ai/rankings)。

### 第 3 步：比较成本、提供商和延迟

对每个入围模型调 `list-model-endpoints`。你会拿到服务它的每家提供商的价格、上下文长度、近三十分钟的吞吐和延迟、在线率、量化和支持参数。同一个模型在不同提供商之间价格、速度和可靠性会有差——这些差异最好在这里发现，而不是在生产里。

需要分享给别人时，[compare 页面](https://openrouter.ai/compare)在浏览器里展示同一批数据。

### 第 4 步：在你自己的数据上测试候选

基准给了你候选名单，最终选择要靠你自己的提示词。

拿你手头真实的东西跑 `send-message`：真实工单、真实文档、真实 schema——包括平时会出故障的那些。一份干净的评测集会让每个模型都显得能干，因此它分不出高下。

测试期间三个变体有帮助。[`:floor`](https://openrouter.ai/docs/guides/routing/provider-selection#floor-price-shortcut) 路由到该模型最便宜的提供商，压低评估成本。[`:nitro`](https://openrouter.ai/docs/guides/routing/model-variants/nitro) 路由到最快的，用它检查延迟预算。[`:online`](https://openrouter.ai/docs/guides/routing/model-variants/online) 在任务需要当下上下文时加上网页搜索。

留意 `:online` 的花费。同一条无关紧要的提示词三种跑法：`:floor` $0.0000030，`:nitro` $0.0000024，`:online` $0.0052576。单条提示词大约是裸调用的两千倍——有意识地用它，别常开。

#### 用 Ori Eval 让对比可复现

临时测试调用只回答一次问题。[Ori Eval](https://openrouter.ai/docs/guides/ori/eval) 让这一步可复现。你用 plain words 提一个问题，例如"我的客服 agent 用哪个模型最好"，你的编码 agent 会在你项目里找测试材料、把评估写成 `*.eval.ts` 文件、跑候选模型，并连同分数、耗时和成本给出推荐。要从编辑器里启动它，把这条指令发给你的编码 agent：

```
run curl -fsSL https://openrouter.ai/skills/spawn-ori-eval and follow the instructions in its output to get started
```

Ori 在一次运行中解析出一套 harness 和一个模型，并为该运行的每个测试保持它们，同一批 eval 文件跑两次用的是同一配置。它通过 OpenRouter 发请求，一次对比可以包含多家提供商的模型。上面这条指令在临时目录里工作。改走[手动步骤](https://openrouter.ai/docs/guides/ori/eval)的话，eval 文件作为普通代码留在你项目里——新模型发布时你可以重跑，用 `--baseline` 和更早的运行对比，并在 CI 里按计划跑。

### 第 5 步：测量每完成任务的成本

每次测试调用之后，把 generation ID 传给 `get-generation`。你拿到精确成本、提示词和补全 token 数、实际服务的提供商和延迟。在一组代表性提示词上取平均，按任务成功率调整，把这个数字记进决策文档。

两点注意。generation 记录不是调用返回的瞬间就可查的，紧接着查会拿到 404，几秒后就通了——重试，别把第一个 404 当失败。另外补全响应本身已经带 `usage.cost`，只要价格的话不必多跑一趟。想要提供商、延迟或原生 token 数时才用 `get-generation`。

### 第 6 步：决定，或者按请求路由

有一个模型在你实际跑的工作上明显胜出，就用它。

结果接近、你的流量混合多种活，或者你不想每次出更好的模型就重审一遍决定——把模型字符串指向 [Auto Router](https://openrouter.ai/docs/guides/routing/routers/auto-router) 的 `openrouter/auto-beta`。老的 `openrouter/auto` 还能解析，但文档已标注弃用，用当前这个。

路由器不是瞎选：它把每个请求分类到约 30 种细粒度任务类型，按滚动七天窗口上真实世界支出份额给候选排名，应用你的成本与质量偏好，带回退路由（[Auto Router 文档](https://openrouter.ai/docs/guides/routing/routers/auto-router)）。这就是上面那套框架逐请求运行，用的正是你第 2 步查过的那份任务分类数据。

## 按每任务成本思考，而不是每 token 成本

比较模型经济账的正确单位是每任务成本，不是每 token 成本。

人们按 token 单价比，因为它好比，而满载成本过去很难测。有了 `get-generation` 在每次调用上返回真实数字，这个难度没有了。

一个单价低的模型，在它开始重试、产出超出你 token 预算的补全、或需要更强的模型兜它的失败时，就不再便宜。一个更贵的模型若第一次就完成任务，总账常常更便宜。

2026 年一项针对推理模型定价的研究测到了这一点：32% 的模型对比较中，标价更低的那个实际总成本更高，极端情况反转达 28 倍（[Chen 等，《The Price Reversal Phenomenon》](https://arxiv.org/abs/2603.23971)）。作者把它归因于模型在"思考"上花 token 的方式差异巨大：同一个查询，一个模型能比另一个多用 900%；同一条查询的重复运行之间也能差到 9.7 倍。标价反映不了这些中的任何一点。

```
cost per task = ((input tokens × input price) + (output tokens × output price)) × expected attempts
```

多数对比漏掉了 expected attempts（期望尝试次数），而这一项通常决定结果。

下面这笔账用真实价格算，核查于 2026 年 7 月 27 日。[GPT-5.4 mini](https://openrouter.ai/openai/gpt-5.4-mini) 标价输入 $0.75/百万、输出 $4.50/百万；[Claude Sonnet 5](https://openrouter.ai/anthropic/claude-sonnet-5) 标价 $2.00 和 $10.00，贵约 2.4 倍。取一个 2,000 输入 token、800 输出 token 的任务。若 Sonnet 5 有 95% 的概率一次成功，每千个完成任务约 $12.63。mini 要追平这个数，一次成功率必须达到 40%。低于 40% 时，那个每 token 便宜 2.4 倍的模型反而是把活干完的更贵方式。

向别人汇报时用"每千个完成任务的成本"。token 最便宜的模型常常不是最便宜的交付方式。

下面这张图不画一个点而画整条曲线。曲线更值得留着，因为盈亏平衡的成功率随两个候选间的价差移动——价差越宽，便宜模型可以在输掉之前容忍越低的成功率。

## 逐任务：该优化什么

这是起点不是排名。每一行告诉你该优化什么、该调哪个调用，名字由实时数据提供。我们不印赢家，因为任何赢家清单到下一次发布就过期。

| 任务 | 优化目标 | 怎么建候选 |
| --- | --- | --- |
| 编码 | 推理质量、工具调用可靠性，然后延迟 | `list-benchmarks` 取 `task_type=coding`，与 `list-task-classifications` 的 `code:` 标签交叉验证 |
| 摘要与长上下文 | 上下文窗口和输入价——两者决定账单 | `list-model-endpoints` 查上下文长度和提示词定价 |
| 结构化抽取 | schema 遵守、每次调用的合法 JSON | `list-model-endpoints` 查支持参数，再用你的真实 schema 跑 `send-message` |
| 聊天与助手 | 延迟优先，其次质量 | `list-model-endpoints` 查提供商延迟和吞吐；用 `:nitro` 测 |
| 视觉与多模态 | 图像输入支持，然后领域适配 | `list-models` 按输入模态筛选，再上你自己的图 |
| Agentic 工具使用 | 跨多步的指令遵循 | `list-benchmarks` 取 `task_type=agentic`，然后做多步测试 |

**编码：**先确定你说的是哪种编码。我们的任务标签把代码生成与调试、评审、前端、仓库扫描分开，领跑者各不同。拿你 backlog 里的真实工单测候选，别用玩具题。

**摘要：**输入价和上下文长度要一起读，单看任何一个都会骗人。窗口大的便宜模型常常赢过高价输入更强的模型。

**抽取：**一个每次都能返回合法 JSON 的小模型，赢过一天出错两次字段的更强模型。专测困难输入：缺字段、含糊记录、残缺源文本。

**视觉：**多模态质量随领域波动很大，先按图像输入筛选，再跑你自己的截图。素材库演示集会让每个候选都好看。

每种情形都一样：发查询，看本周的数字，从数字里选。

## 为什么这套循环要在 OpenRouter 上跑

你根本不必把选择押死在一个模型上。

一份集成拿到整个跨提供商[目录](https://openrouter.ai/models)。下个月出更好的模型时，你改一个模型字符串，而不是再集成一个 SDK、再回归测试一条集成路径。选择和执行在同一个平台上，有了 MCP，选择所需的数据就在你天天用的编辑器里。你还获得[提供商冗余和自动回退](https://openrouter.ai/docs/guides/routing/model-fallbacks)，以及一个精确到能让上面每任务成本计算"是测量不是估算"的逐请求成本数字。

如果你确定只要一个地方恰好一个模型、且永远不变，直连提供商也是合理选择。新模型一直在发，先掂量掂量你的确定程度。

## 选模型时的常见错误

糟糕的模型决策多半来自测错了东西，或者测对了但测得太晚。这是我们见得最多的五个。

**把排行榜位置当成生产决策：**公开榜的高位挣到的是候选名单的一个座位，不是生产流量。先拿你的提示词跑模型。

**按每 token 价格采购：**低单价掩盖着重试、长补全和回退。在 `get-generation` 告诉你每完成任务的成本之前，你并不知道自己付了什么。

**无视上下文形态：**上下文长度和在那个长度上的价格要一起看。长上下文模型能干也贵。用能可靠完成工作的最小上下文策略，考虑更大的窗口之前先考虑检索。

**选完一次不再回头：**1 月里最适合你任务的模型到 7 月未必还是。截至 2026 年 7 月 27 日的三十天里我们加了约 40 个模型——你类别里有重大发布就重跑这六步；在仓库里留一份 Ori eval 按计划重跑；或干脆把问题交给 Auto Router。

**把延迟和可靠性留到上线再看：**查 `list-model-endpoints` 的延迟、吞吐和在线率，然后按生产的方式压这个端点。上线之后才发现提供商不靠谱，是一场本可避免的事故。

## 为任务而选，让选择保持新鲜

正确的问题不是"哪个模型最好"，而是"在当下的你、你的预算、你正在构建的东西上，哪个模型最好"。

任务定义清楚、有实时数据、有一批真实提示词，一个下午就能回答这个问题；发生变化时，几分钟就能重答。

- "最佳"绑定任务、也绑定时间。用每完成任务成本和延迟判断，不用排名。
- 基准建候选，你自己的数据选赢家。`send-message` 和 `get-generation` 说了算。
- MCP server 接上之后，整个循环在编辑器里跑完。

添加 [OpenRouter MCP server](https://openrouter.ai/docs/guides/overview/mcp-server)，让你的助手为本周要上线的活建候选、报价。拿不定主意，或者任务很混杂，就用 `openrouter/auto-beta` 的 [Auto Router](https://openrouter.ai/docs/guides/routing/routers/auto-router)，让它逐请求替你选。

## 常见问题

### 我怎么选最佳 AI 模型？

精确定义任务，从实时用量和基准数据建候选，跨服务该模型的各提供商比较价格和延迟，再用你自己的提示词测入围者。赢家按每完成任务成本而非每 token 成本评判。在 OpenRouter 上，每一步都能在编辑器里通过 MCP server 完成。

### 编码的最佳 AI 模型是什么？

没有固定答案，而且编码不是一个任务。我们把编码流量分成九个标签：代码生成、调试、文件读写、shell 执行、代码评审与安全、前端与 UI、仓库扫描、SQL 与数据库、DevOps 配置——领跑者各不相同。用 `list-benchmarks`（`task_type=coding`）建候选，用 `list-task-classifications` 与真实流量交叉核对，最后拿你自己 backlog 里的真实工单测候选。

### OpenRouter MCP server 是什么？

是我们托管的远程 MCP server，本地零安装。连上之后，你的 AI 助手可以查询实时模型数据、逐提供商定价、用量排行、第三方基准和文档，并向候选模型发测试消息——全程不出编辑器。任何 MCP 客户端都能连。我们为 Claude Code、Codex CLI、OpenCode、Cursor CLI 和 Claude Desktop 写了配置文档。

### 在 Claude Code 或 Cursor 里怎么配置 OpenRouter MCP server？

Claude Code 运行 `claude mcp add --transport http openrouter https://mcp.openrouter.ai/mcp`，接着 `claude mcp login openrouter`。Cursor 把 server URL 加进 `~/.cursor/mcp.json`，用 `cursor-agent mcp list` 验证。认证是浏览器里的一步，完成后我们签发一个专用 API key：七天过期、$10 消费上限。

### 每 token 成本和每任务成本有什么区别？

每 token 成本是标出来的输入输出单价。每任务成本是拿到一个成功结果的开销，包含重试、更长的补全和落到更强模型的回退。token 单价更低的模型，每完成任务可能反而更贵。`get-generation` 返回每次调用的实际成本和 token 数，让你测量而不是估算。

### 我该怎么比较 AI 模型？

三个轴同时比：你的任务上的质量、每完成任务成本、延迟。第三方基准建候选；`list-model-endpoints` 比较服务每个模型的各提供商的价格、延迟和吞吐；最终选择用你自己的提示词。并排比较的网页视图在 [openrouter.ai/compare](https://openrouter.ai/compare)。

### 模型选择该多久重新评估一次？

你任务类别里有重大发布就重跑这套框架；成本、延迟或失败率漂移时也重跑。截至 2026 年 7 月 27 日的三十天里我们加了约 40 个模型，所以模型选择是运营决定，不是一次性配置。不想跟这个节奏，就用 Auto Router 逐请求路由。

### 怎么让模型评估可复现？

用 [Ori Eval](https://openrouter.ai/docs/guides/ori/eval)。用大白话提问题，你的编码 agent 在项目里找测试材料、把评估写成 `*.eval.ts` 文件、通过 OpenRouter 跑候选模型、连同分数耗时成本给出推荐。eval 文件是普通代码，新模型发布时可重跑、可用 `--baseline` 对比运行、可在 CI 里按计划跑。

### 该用一个模型还是在几个之间路由？

任务窄、提示词稳定、有一个候选大幅越过你的评估线——用一个模型。请求复杂度参差不齐、可靠性比模型一致性重要、不想每个发布周期重审决定——用路由。Auto Router 把每个请求分类到约 30 种任务类型，按社区滚动七天支出份额逐请求挑选。
