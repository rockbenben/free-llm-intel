# 在分类任务上 Jev 能与前沿模型同样准确吗？

Kenny Rogers · 2026-09-22 · 更新于 2026-09-24

[Jev](https://openrouter.ai/typesafe/jev-1.13) 是 TypeSafe 的 "System One" 决策模型。给它一个应用状态对象和一个带类型的问题，它返回一个带类型的答案、一个置信度分数，以及每个候选选项的概率（是 [Decisions API](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-request) 的响应类型，不是 chat endpoint）。按 TypeSafe 的说法，在诸如本文测试的分类任务上，你可以用 Jev 这样的小型判断模型替换前沿 chat 模型，在成本和延迟上都获得大幅下降。那么你要牺牲多少准确率？

我们把 3,080 条 [Banking77](https://github.com/PolyAI-LDN/task-specific-datasets/tree/master/banking_data) 客服用户话语分别送入 Jev 1.13 和 [Claude Opus 5](https://openrouter.ai/anthropic/claude-opus-5)——后者是截至 2026 年 9 月 22 日 OpenRouter 用户在 [rankings 页面](https://openrouter.ai/rankings)的 Task 支出分类上花费最多的模型。每条话语要归入 77 个银行意图之一，两个模型拿到的每个意图的一行描述完全相同。

下图把 Jev 和 Opus 并排对比，展示二者在准确率、中位延迟和每千请求成本上的差距。

![三张柱状图对比 Jev 1.13 与 Claude Opus 5 在 Banking77 测试集上的表现。准确率：Jev 81.0%，Opus 84.4%。中位延迟：Jev 175 ms，Opus 2,266 ms。每千请求成本：Jev $0.11，Opus $2.42。标题写着 Jev 落后 Claude Opus 5 3.3 个百分点，但速度快 13 倍、成本只有 1/22。](https://openrouter.ai/blog/images/jev-vs-claude-opus-5-banking77.png)

Jev 的准确率比 Opus 低 3.3 个百分点，但中位速度快 13 倍，成本只有 Opus 的 1/22。

## Jev 对比 Claude Opus 5 一览

细看结果。Macro-F1 对每个意图赋予同等权重。

|  | Jev 1.13 | Claude Opus 5 |
| --- | --- | --- |
| 准确率 | 81.0%（79.6 到 82.3） | 84.4%（83.1 到 85.6） |
| Macro-F1 | 80.5% | 83.6% |
| 无效响应 | 3,080 中 0 | 3,080 中 0 |
| 延迟 p50 | 175 ms | 2,266 ms |
| 延迟 p95 | 270 ms | 3,004 ms |
| 延迟 p99 | 353 ms | 3,835 ms |
| 整轮运行计费 | $0.34 | $7.44 |
| 每千请求成本 | $0.11 | $2.42 |
| 平均输入 token | 2,605 | 3,750（3,725 命中缓存） |
| 平均输出 token | 826 | 17 |

括号中的数字是用 3,080 个样本计算的 95% bootstrap 置信区间。两个模型都没有返回格式错误的响应，每个错误都是标错了标签，而不是解析失败。

## 我们如何跑的

Banking77 是 PolyAI 的话语级客服意图数据集，采用 CC BY 4.0 许可。话语很短（中位数九个词），每条标注 77 个意图之一。我们在 Banking77 上运行 Jev 和 Opus 时使用了完整测试集——3,080 个样本，每个意图 40 条。有些意图彼此足够接近，模型不能只抓几个关键词就草草收工，比如 `card_arrival` 对 `card_delivery_estimate`。

我们只根据标签名称为每个意图写了一行判定准则，全程没有看测试数据，并把完全相同的这份准则列表同时给到 Jev 和 Opus。为给 Jev 评分，我们把每条话语作为 Decisions API 的 Choice 问题发送，77 条准则即候选项。为 Opus，我们构造了一个 prompt：system 消息列出全部准则，随后 user 消息只含话语本身。Opus 以 temperature 为 0、关闭 reasoning 运行，并使用带 77 个标签 enum 的严格 JSON schema 响应格式。由于 system 消息在每个请求中完全一致，我们为它开启了 [prompt 缓存](https://openrouter.ai/docs/guides/best-practices/prompt-caching)。两个模型都从同一台机器运行，我们每次并发发送 8 个请求，延迟按客户端观测的经 OpenRouter 往返时间测量。

## Jev 有多准？

来谈数字。在 Banking77 上，Jev 为 81.0%，Opus 为 84.4%。配对 bootstrap 给出 2.3 到 4.4 个百分点的 95% 置信区间，所以 Opus 领先约三个点不太可能是噪声。

好消息是两者高度一致：它们在 89.3% 的话语上给出相同答案。在分歧处，Opus 独立答对 175 条，Jev 独立答对 72 条。

坏消息是两者都明显低于在全部 10,003 条 Banking77 训练样本上微调的编码器所报告的 90% 出头——这就是只靠一行准则、不做完整微调的代价。

按类别看，77 个意图中 Opus 在 35 个上领先 Jev，Jev 赢 15 个，27 个打平。Opus 最大的优势在 `receiving_money`：它 80.0%，Jev 只有 52.5%。而 Jev 在 `compromised_card` 上表现出色：95.0%，Opus 只有 70.0%——Opus 倾向于把被盗卡信息误认成一笔无法识别的付款。

## Jev 有多快、多便宜？

快得惊人：Jev 的中位往返 175 ms，p95 为 270 ms。Opus 一方，即便关闭 reasoning 模式，中位往返也有 2,266 ms、p95 为 3,004 ms。也就是说 Jev 最慢的调用（约 1.6s）比 Opus 最快的调用（约 1.9s）还快。

Jev 总价 $0.34，即每千请求 $0.11；Opus 总价 $7.44，即每千请求 $2.42。Opus 这个数字已把 3,700 token 的 system prompt 缓存，所有请求都按缓存读取费率而非目录价。若不缓存，Opus 的目录价约为每千请求 $19。所以如果你在带标签体系上使用前沿模型，请务必缓存那个 system prompt。

## 依据 Jev 的置信度路由

Jev 给你一个置信度分数，但它不是经过校准的概率。在本次测试中，它的中段区间高估了自身准确率。不过它的排序很好：置信度 ≥0.99 的 58% 话语上准确率为 96.3%；低于 0.5 的 3.5% 上准确率只有 29.6%。

有这个排序就够你做[级联（cascade）](https://openrouter.ai/docs/cookbook/evaluate-and-optimize/jev-verified-cascade)了：置信度高于某个阈值的接受 Jev 的答案，其余发给 Opus。下面是在每个阈值下的准确率与每千请求成本，从"只用 Jev"一直排到"只用 Opus"。

| 阈值 | 由 Jev 处理 | 准确率 | 每千请求成本 |
| --- | --- | --- | --- |
| 只用 Jev | 100% | 81.0% | $0.11 |
| 0.99 | 57.8% | 84.3% | $1.13 |
| 0.95 | 68.1% | 84.2% | $0.88 |
| 0.90 | 75.9% | 84.0% | $0.69 |
| 0.80 | 82.7% | 83.6% | $0.53 |
| 0.70 | 87.3% | 83.2% | $0.42 |
| 只用 Opus | 0% | 84.4% | $2.42 |

在阈值 0.90 处，76% 的流量绕开了 Opus。换来的是：相对纯 Opus 准确率至多降低 0.4 个百分点，而成本降为约 1/3.5。Opus 答对了 175 条 Jev 答错的话语，这些案例的置信度中位数是 0.67，其中 85% 低于 0.90。所以 Jev 通常知道自己什么时候是在瞎猜。

## 注意事项

先就这次实际测试做狭义说明：一个数据集、一个领域、一种 prompt 设计、一个下午的十五分钟窗口。

如果 Opus 在这里存在记忆优势，它的分数可能被略微抬高，因为 Banking77 早在 2020 年就发布了。但仅凭这一次运行无法判断。

另一点：两个模型都在同一个类别上栽了跟头，因为准则只根据标签名称编写、没有见过示例消息。其中一个标签是 `get_physical_card`，涵盖"PIN 码是否分开邮寄"这类咨询——光看名字几乎不可能猜出来。每个模型在该类别 40 条中得 0 分，把大多数消息路由到了 `change_pin`。仅剔除这个类别，Jev 得 82.1%，Opus 得 85.5%。但一个要上线的团队会用留出的训练数据（而不是测试集）迭代准则，两个模型都会变好。

上面展示的级联表用的是与准确率测量完全相同的 3,080 个样本，因此这是一个上界。请基于你自己的流量选择阈值。

最后，这些测试是在 Opus "reasoning off" 模式并启用 structured outputs 下跑的。没有测试 Opus 的 "reasoning on" 模式，也没有测试其他 schema 或 few-shot 示例。

## 这意味着什么

如果 3 个百分点的准确率比每千请求 $2.42 更值钱，就用 Opus。如果你面对的是高吞吐、低延迟场景，或者需要一个 fallback 档位，Jev 单用就能追到 Opus 3.3 个百分点以内。更好的是，基于 Jev 置信度分数运行级联后，我们以不到 30% 的成本追到了距 Opus 0.4 个百分点以内。

[Decisions API 参考](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-request)讲解基本请求形态。[Jev cookbook](https://openrouter.ai/docs/cookbook/evaluate-and-optimize/classify-reddit-comments-with-jev)带你用 TypeScript 跑通一个可用的 Choice 问题。[Jev-verified cascade cookbook](https://openrouter.ai/docs/cookbook/evaluate-and-optimize/jev-verified-cascade)给出升级模式的代码：便宜模型起草、Jev 检查草稿、前沿模型只处理未通过的。Banking77 测试集是 [PolyAI 仓库](https://github.com/PolyAI-LDN/task-specific-datasets/tree/master/banking_data)里一个 3,080 行的 CSV。

要在你自己的存量数据上跑类似的标注任务，[用 Jev 大规模分类与打标签 cookbook](https://openrouter.ai/docs/cookbook/evaluate-and-optimize/jev-classification)覆盖速率限制内的批处理、从有标签样本为每个标签挑选阈值、以及计算每千条成本。如果你刚接触 Jev，先读[什么是 Jev？](https://openrouter.ai/blog/insights/what-is-jev/)，再读 [Jev vs LLM](https://openrouter.ai/blog/tutorials/jev-vs-llm-when-to-use-each/) 了解决策模型何时能取代生成式调用。[Jev 文档中心](https://openrouter.ai/docs/guides/community/jev)列出了 OpenRouter 上所有 Jev 指南与 cookbook。

## 常见问题

### 在意图分类上 Jev 与 Claude Opus 5 相比准确率如何？

在 2026 年 9 月 22 日对由 77 个意图、3,080 条话语组成的 Banking77 测试集的运行中，Claude Opus 5 准确率 84.4%、macro-F1 83.6%；Jev 1.13 准确率 81.0%、macro-F1 80.5%。配对差距为 3.3 个百分点，95% bootstrap 区间为 2.3 到 4.4 个百分点。两个模型在 89.3% 的话语上一致。

### 在分类上 Jev 比前沿模型快多少？

以客户端观测的往返延迟计，Jev 中位 175 ms、p95 270 ms；Claude Opus 5（reasoning 关闭）中位 2,266 ms、p95 3,004 ms——中位约为 13 倍差距。这些数字来自同一客户端在 8 个并发请求下的测量，包含网络时间以及 provider 系统中推理前的排队时间。

### 在 OpenRouter 上用 Jev 分类文本花多少钱？

Banking77 的全部 3,080 个请求在 typesafe/jev-1.13 上总计计费 $0.34，即每千请求 $0.11、每请求约 $0.0001。对 77 标签的 system prompt 启用 prompt 缓存后，同样的请求在 anthropic/claude-opus-5 上总计计费 $7.44，即每千请求 $2.42。不缓存时，Opus 按目录价约每千请求 $19。

### 我能用 Jev 的置信度分数决定何时回退到更大的模型吗？

能，在我们的数据里它作为排序信号是有效的。Jev 在置信度不低于 0.99 的 58% 话语上准确率 96.3%，在置信度低于 0.5 的 3.5% 话语上准确率 29.6%。把所有置信度低于 0.9 的请求路由给 Claude Opus 5 后，准确率达到 84.0%——距纯 Opus 只差 0.4 个百分点——成本为每千请求 $0.69。由于该分数不是按概率校准的，请根据你自己的数据挑选阈值。
