# 图像生成模型：选型与错误修复

OpenRouter ·7/27/2026 · 更新于 9/24/2026

[图像生成教程](https://openrouter.ai/blog/tutorials/image-generation/)走的是请求本身：向 `POST /api/v1/images` 发一个模型和一个提示词，解码 `data[0].b64_json`，把字节写到磁盘。本文讲那个教程留给你的两个决定：`model` 字段里放哪个模型，以及 API 返回错误而不是图片时怎么办。

端点背后的[模型目录](https://openrouter.ai/docs/guides/overview/models)覆盖主流图像实验室，slug 随每次发布而变。目录的这种变化，正是模型选择需要一套方法而不是一个书签的原因，也是几条错误信息反复出现的原因。

## 太长不看

- 先按活选模型（文生图、编辑参考图、矢量输出、可读文字），再按参数支持，最后按价格。`GET /api/v1/images/models` 列出 Image API 服务的每个模型及其各提供商 `supported_parameters` 的并集，每条都链到逐提供商明细。
- 数据方面：我们的[对比](https://openrouter.ai/blog/insights/image-generation-models-compared/)把一条提示词跑了 20 个模型并记录每次账单；[图像基准](https://openrouter.ai/blog/announcements/image-benchmarks/)对 39 个模型用 15 条提示词打分。
- 没有图像模型带 `:free` 后缀，每次生成都消耗你的额度。低成本模型大约一分一张起。
- "No endpoints found that support image input" 意思是你把图片发给了 `/chat/completions` 上一个不接受图像输入的模型。换成 `input_modalities` 含 `image` 的模型。
- 在 `/api/v1/images` 上，引用了你模型 slug 的 400 或 404 是 slug、能力或提供商过滤的问题。[排障一节](https://openrouter.ai/blog/tutorials/image-generation-models/#how-do-i-fix-image-api-errors)把每条信息对到修法。
- 选定模型后，[教程](https://openrouter.ai/blog/tutorials/image-generation/)有可直接运行的 Python 和 JavaScript 调用代码。

## 有哪些图像模型可用？

目录包括 Google（Gemini 图像家族）、OpenAI（GPT Image）、Black Forest Labs（FLUX）、xAI（Grok Imagine）、ByteDance（Seedream）、Microsoft（MAI-Image）、Recraft、Krea 和 Sourceful（Riverflow）。具体模型名随每次发布变动，当前阵容、能力和逐模型定价请用[图像模型目录](https://openrouter.ai/collections/image-models)。

找图像模型有三个途径：

- **从代码：**`GET /api/v1/images/models` 列出 `POST /api/v1/images` 接受的所有模型。`GET /api/v1/models?output_modalities=image` 返回更广的图像输出模型集，包括只能通过 `/chat/completions` 生成的那批。
- **从界面：**[Models 页面的筛选器](https://openrouter.ai/models?output_modalities=image)可视化呈现同样结果，价格一眼可见。
- **从 Chatroom：**图像按钮让你不写代码就把提示词先在模型上试一把，再接进应用。

## 如何在它们之间选？

从活开始。目录沿几条能力线切分，每条线对应模型记录里一个可以在花额度之前检查的字段。除非该行另有说明，字段都来自 `GET /api/v1/images/models`。

| 你需要 | 找什么 |
| --- | --- |
| 从文本提示词生成新图 | `GET /api/v1/images/models` 列表里的任何模型。[图像合集](https://openrouter.ai/collections/image-models)展示同一批模型和价格，外加少数只能经 `/chat/completions` 生成的 |
| 对已有图片做编辑或变体 | `supported_parameters` 里的 `input_references` |
| 图里的可读文字 | [图像基准](https://openrouter.ai/blog/announcements/image-benchmarks/)里的文字渲染分数 |
| 可编辑的矢量输出 | `output_format` 里的 `svg`（Recraft 矢量模型） |
| 特定尺寸或比例 | 端点接受的 `resolution` 和 `aspect_ratio` 值 |
| 一次调用多张图 | `n` 的范围（不是每家提供商都接受 `n > 1`） |
| 生成过程中的渐进图像 | `supports_streaming: true` |
| 一轮同时返回图片和文字回复 | `output_modalities` 同时有 `image` 和 `text`，经 `/chat/completions` 调用 |

然后是价格。在我们的[对比](https://openrouter.ai/blog/insights/image-generation-models-compared/)里，默认设置一张图在 20 个模型间的账单从 $0.006 到 $0.134，22 倍差距；OpenAI 模型上光 `quality` 设置就能把同一张图从 $0.006 推到 $0.211。计价单位也不同：有的端点按图、有的按百万像素、有的按 token——token 计价的模型上更长的提示词更贵，按图计价的则不加钱。响应带 `usage` 时其 `cost` 字段报告该次调用的账单，测试时把它记在模型 slug 旁边，是搭自己价目表最快的办法。`usage` 在响应 schema 里是可选的，缺它的调用回[activity 页面](https://openrouter.ai/activity)查。

然后是在你自己的提示词上看质量。基准和对比是候选名单，不是终审。承诺之前，拿三四条你的生产提示词在 [Chatroom](https://openrouter.ai/chat) 里过一遍两三个入围者。专说编辑工作，[Nano Banana 教程](https://openrouter.ai/blog/tutorials/nano-banana/)端到端演示参考图流程。

## 怎么查一个模型支持什么？

`GET /api/v1/images/models` 是权威来源。每个模型顶层的 `supported_parameters` 是其各提供商的并集——`input_references`、`n` 或某个 `aspect_ratio` 如果不在那里，说明没有任何提供商支持它，请求会失败。如果在，至少一家提供商接受它，你发出该参数时路由就收窄到这些提供商。要看哪家提供商接受什么，访问该模型的 `endpoints` URL（`GET /api/v1/images/models/{author}/{slug}/endpoints`），那里列出每家提供商自己的 `supported_parameters`。用 `provider.only` 或 `provider.order` 钉提供商之前先查它。

```
curl https://openrouter.ai/api/v1/images/models \
  -H "Authorization: Bearer $OPENROUTER_API_KEY"
```

你最常用来过滤的参数：

| 字段 | 作用 |
| --- | --- |
| `resolution` | 归一化档位：`512`、`1K`、`2K` 或 `4K` 之一 |
| `aspect_ratio` | 从 `1:1` 到 `21:9` 等扩展值，钳制在各提供商支持的子集内 |
| `quality` | `auto`、`low`、`medium` 或 `high` |
| `output_format` | `png`、`jpeg`、`webp` 或 `svg`（仅矢量模型） |
| `input_references` | 图生图用的参考图（URL 或 base64） |
| `n` | 每次请求的图片数，提供商允许时最多 10 |

提供商还可以通过 `provider.options` 接受提供商特定选项；`supports_streaming: true` 的模型可以用 `stream: true` 通过 SSE 流式输出渐进图像。完整请求 schema 见[图像生成文档](https://openrouter.ai/docs/guides/overview/multimodal/image-generation)。

## 我需要的是图像模型还是视觉模型？

两种不同的活跑在同一个 base URL 和 key 上，把它们搞混就产生了本文被搜索最多的那条错误。

| 图像任务 | 端点 | 模型需要 | 教程 |
| --- | --- | --- | --- |
| 生成（提示词到图片） | `POST /api/v1/images` | `output_modalities` 含 `image` | [图像生成](https://openrouter.ai/blog/tutorials/image-generation/) |
| 理解（图片到文本） | `POST /api/v1/chat/completions` | `input_modalities` 含 `image` | [把图片发给 LLM](https://openrouter.ai/blog/tutorials/send-image-to-llm/) |

输出是新的视觉素材时用生成；已有图片、需要 OCR、alt 文本、分类或描述时用理解。有些模型两者都行——它们就是能在单个聊天轮里同时返回图片和文字回复的那批。

还有第三种选项，适合"由对话自己决定何时需要图"的应用。`openrouter:image_generation` 服务器工具（beta）让聊天模型在对话中途生成图片，不需要你的应用代码显式发起该调用。在请求的 `tools` 数组加 `{ "type": "openrouter:image_generation" }`，由模型决定何时调用。默认是 `openai/gpt-5-image`。可用参数见[服务器工具文档](https://openrouter.ai/docs/guides/features/server-tools/image-generation)。

## 有免费的图像生成方式吗？

暂时没有。[免费档](https://openrouter.ai/pricing)覆盖带 `:free` 后缀的模型：每天 50 次请求、20 RPM、无需信用卡（充值 $10 及以上后每天 1,000 次），目前没有图像生成模型带这个后缀。免费池随模型上下架变化，值得回去查 [/models?output_modalities=image](https://openrouter.ai/models?output_modalities=image)。

因此生成消耗你的额度余额，但测试花不了多少。低成本模型的按图定价一美分左右起，端点返回 usage 时每个响应的 `usage.cost` 报告该请求的费用。文本模型的免费档机制见[免费模型指南](https://openrouter.ai/blog/tutorials/free-llm-apis-compared/)。

## 路由和故障转移对图像调用有效吗？

有效。在 `/api/v1/images` 上，`provider` 对象接受 `order`、`only`、`ignore`、`sort` 和 `allow_fallbacks`。由多家提供商服务的图像模型，第一家不可用或慢时可以在它们之间转移。

```
{
  "model": "google/gemini-2.5-flash-image",
  "prompt": "A minimalist logo for a coffee roaster",
  "provider": {
    "order": ["google-ai-studio", "google-vertex"],
    "allow_fallbacks": true
  }
}
```

这个请求偏好一家提供商、失败时落到下一家。你按目录价付费、[我们不加价](https://openrouter.ai/pricing)；在零补全保险下，转移后仍未完成的图像调用不计费。路由器如何选提供商见 [OpenRouter 模型路由的工作原理](https://openrouter.ai/blog/insights/model-routing/)。

同一个 `provider` 对象也是"原本能用的请求开始报 No endpoint found"的最常见原因，下一节讲它。

## 如何修复 Image API 错误？

记录 HTTP 状态码；只在状态非 2xx 时记录响应体。成功的响应体把图片以 base64 装在 `data[].b64_json` 里，动辄几兆，不该进应用日志。下面每条错误都点名了没匹配上的东西，修法从消息出发。

### "No endpoints found that support image input"

这是 `/chat/completions` 的错误，不是 Image API 的错误。你把一个 `image_url` 内容部件发给了不接受图像输入的模型。我们[按请求内容过滤可用端点](https://openrouter.ai/docs/guides/overview/multimodal/overview)，当所指模型没有任何支持图像的端点时，请求以这个 404 失败，而不是悄悄丢掉图片。

三步修好：

- **确认模型支持图像输入。**其 `input_modalities` 必须含 `image`。纯文本模型永远不会有。
- **找一个有视觉能力的模型。**运行 `GET /api/v1/models?input_modalities=image`，或用 Models 页面的输入模态筛选器。
- **更新请求里的模型字符串**重发。

两个变体能进一步收窄原因。"No endpoints found that support base64 image input" 表示模型收图、但可用端点只接受 URL——把文件托管出去发 URL。"No endpoints found that support image URLs" 相反——把文件抓下来以 base64 data URL 发送。

生成模型也会撞上这条。图像生成在 `/chat/completions` 上仍然可用，那里的图生图请求在你指定的生成模型不接受图像输入时会报这条消息。选一个 `input_modalities` 含 `image` 的生成模型，或把请求移到 `/api/v1/images`、经 `input_references` 传参考图。

### `No model found for "<slug>"`

来自 `/api/v1/images` 的 404。slug 不在目录里。先查拼写，再查模型是否已下架或改名——图像目录里这是常事。slug 请从 `GET /api/v1/images/models` 或[合集](https://openrouter.ai/collections/image-models)里模型页面复制，别靠记忆。

### `Model "<slug>" does not support image output`

来自 `/api/v1/images` 的 400。slug 存在，但它是文本或视觉模型，不是生成模型。`google/gemini-2.5-flash` 读图，`google/gemini-2.5-flash-image` 生成图，目录里处处是这个模式。请从 `GET /api/v1/images/models` 里选——那份列表是有 Image API 适配器的图像输出模型，不含少数只能经 `/chat/completions` 生成的图像输出模型。

### `No endpoint found for model "<slug>"`

来自 `/api/v1/images` 的 404。模型存在、能生成图像，但服务它的每家提供商都在请求发出前被过滤掉了。常见原因按检查顺序：

- **`provider.only` 或带 `allow_fallbacks: false` 的 `provider.order`** 点名了不服务该模型的提供商。删掉列表，或把 `allow_fallbacks` 设 `true`。
- **`provider.ignore`** 覆盖了该模型的全部提供商。
- **账户的数据政策**排除了剩余的端点。Image API 的 `provider` 对象不接受 `data_collection`，这一项是在[隐私设置](https://openrouter.ai/settings/privacy)里配的，不在请求里。
- **模型此刻没有活动端点。**模型页面显示其提供商和状态。

逐个移除过滤器、每改一次重发一次。第一个让调用成功的，就是要认真修的那个。

### `No provider for <slug> supports the requested parameter(s)`

来自 `/api/v1/images` 的 400。你要的 `resolution`、`aspect_ratio`、`n`、`output_format` 或其他参数没有任何端点接受。消息会列出它无法满足的参数和每家提供商拒绝的原因。去掉该参数、改成支持的值，或选一个 `supported_parameters` 包含它的模型。

### `Streaming is not supported with n > 1`

来自 `/api/v1/images` 的 400。渐进流式一次只对一张图有效。把 `n` 设 1，或去掉 `stream`。

### 401 与 402

401 意味着请求到达我们时没有有效的 key。检查进程能否在不打印值的情况下读到 `OPENROUTER_API_KEY`，以及头是否为 `Authorization: Bearer <key>`。402 意味着你的可用余额低于等于 Image API 固定的 $1 预授权线。每个付费图像请求在运行前都检查是否有多于 $1 的额度——无论这张图将花多少钱——实际扣款在之后结算。余额 $0.50 的账户连一分钱的生成都会拿 402，所以充值要冲过 $1，而不是按图片价格配金额。没有免费的图像模型，能在 `:free` 文本模型上用的 key 做图像生成仍需额度。

### 调用成功了但图不对

- **缺 `data[0].b64_json`。**先看响应体。确认请求发到了 `/api/v1/images`；要求了 `n > 1` 的话请遍历 `data`，别写死下标 0。
- **文件格式意外。**读响应里的 `media_type`。有些模型返回 JPEG 或 WebP 而不是 PNG，Recraft 矢量模型返回 `image/svg+xml`。
- **参考图被忽略或拒绝。**确认 `input_references` 出现在模型 `endpoints` URL 里该提供商的 `supported_parameters` 中；本地文件要以正确前缀的 data URL 发送，如 `data:image/jpeg;base64,`。
- **成本意外。**跑批前先查端点计价单位。token 计价的模型对更长提示词收更多，`quality` 设置能在同一模型上把账单移动一个数量级。

请求跑通之后，[图像生成教程](https://openrouter.ai/blog/tutorials/image-generation/)讲保存输出、加参考图和让请求可复用。

## 常见问题

### OpenRouter 上有哪些图像生成模型？

目录包括 Google（Gemini 图像家族）、OpenAI（GPT Image）、Black Forest Labs（FLUX）、xAI（Grok Imagine）、ByteDance（Seedream）、Microsoft（MAI-Image）、Recraft、Krea 和 Sourceful（Riverflow）。用 [/models?output_modalities=image](https://openrouter.ai/models?output_modalities=image) 筛选，或浏览[图像模型合集](https://openrouter.ai/collections/image-models)看当前阵容和定价。

### 怎么选图像生成模型？

先定活（文生图、编辑参考图、矢量输出、可读文字），再筛 `supported_parameters` 覆盖需求的模型，然后比较单图价格。`GET /api/v1/images/models` 返回逐端点的参数支持，每个响应的 `usage.cost` 报告调用账单。

### 怎么修 "no endpoints found that support image input"？

你把 `image_url` 发给了 `/chat/completions` 上一个不接受图像输入的模型。确认模型 `input_modalities` 含 `image`，用 `GET /api/v1/models?input_modalities=image` 找有视觉能力的模型，更新请求里的模型字符串。

### Image API 为什么说 "No endpoint found for model"？

服务该模型的每家提供商都在请求发出前被过滤掉了。常见原因：带 `allow_fallbacks: false` 的 `provider.only`/`provider.order` 点名了不服务该模型的提供商；`provider.ignore` 覆盖了全部；或端点不满足的数据政策。逐个移除过滤器直到调用成功。

### OpenRouter 上有免费的图像生成方式吗？

暂时没有。免费档（每天 50 次、20 RPM、无需信用卡）只覆盖带 `:free` 后缀的模型，目前没有图像生成模型带它，所以生成消耗额度余额。低成本模型一美分一张左右起。

### 路由和故障转移对图像调用有效吗？

有效。`/api/v1/images` 端点接受 `provider.order`、`only`、`ignore`、`sort` 和 `allow_fallbacks`——排序、成本/延迟排序和跨提供商故障转移与聊天上完全一样。
