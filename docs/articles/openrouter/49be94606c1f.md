# 如何将 OpenAI Codex CLI 与 OpenRouter 结合使用

OpenRouter ·6/17/2026 · 更新于 9/24/2026

Codex CLI 在你终端里跑一个 agentic 编码循环，而且本来就支持自定义的 OpenAI 兼容提供商。接上 OpenRouter 需要的就是那个钩子。

回报是一个 API key 挡在 300 多个模型前面、自动提供商故障转移、统一的用量追踪——Codex 本体不用改。配置是一小段 `config.toml`，但 Codex 有两个要求，漏掉的人会被绊住。本文走一遍完整配置和你最可能撞上的两个错误。同一个 key 在 Claude Code、Cursor 及其他工具上也通用，见[如何把 OpenRouter 接入任意编码 agent](https://openrouter.ai/blog/tutorials/any-coding-agent/)。

## 五步把 Codex 指向 OpenRouter

从 [openai/codex](https://github.com/openai/codex) 仓库安装 Codex CLI，然后在你的 [API Keys 页面](https://openrouter.ai/settings/keys)创建一个 key，它以 `sk-or-` 开头。

打开 `~/.codex/config.toml`（不存在就创建），加上这段：

```
# ~/.codex/config.toml
model = "openai/gpt-5.6-sol"
model_provider = "openrouter"
model_reasoning_effort = "high"

[model_providers.openrouter]
name = "OpenRouter"
base_url = "https://openrouter.ai/api/v1"
wire_api = "responses"

[model_providers.openrouter.auth]
command = "sh"
args = ["-c", "echo $OPENROUTER_API_KEY"]
```

Windows 上 auth 块改用 PowerShell：

```
[model_providers.openrouter.auth]
command = "powershell"
args = ["-NoProfile", "-Command", "Write-Output $env:OPENROUTER_API_KEY"]
```

三个字段需要留意。`model` 必须是完整的 OpenRouter slug、含提供商前缀，从 [models 页面](https://openrouter.ai/models)原样复制。`wire_api` 如果设置就必须是 `"responses"`，下面讲为什么。`auth` 块是运行一条命令来取 key，而不是直接读 `env_key`——命令式 auth 正是触发 Codex 向 OpenRouter 刷新模型目录的东西，非 OpenAI 模型因此能拿到正确的上下文窗口和推理元数据，并出现在 `/model` 选择器里。

**普通的 `env_key = "OPENROUTER_API_KEY"` 也能完成认证**，但那种模式下 Codex 不会使用 OpenRouter 模型目录：非 OpenAI 模型会显示 "Unknown model … fallback metadata" 警告并按假设的默认值运行。请优先用上面的命令式 `auth` 块。

还有一条位置规则：`model_provider` 和 `model_providers` 只在用户级 `~/.codex/config.toml` 里生效。Codex 会忽略项目本地 `.codex/config.toml` 里的这两项并打印启动警告。

然后在 Codex 会加载的 shell profile 里导出 key，在项目目录运行 `codex`，发一个测试提示词：

```
export OPENROUTER_API_KEY="sk-or-..."
cd /path/to/your/project
codex
```

打开 [Activity 面板](https://openrouter.ai/activity)，确认请求带着正确的模型名和 token 数出现。出现了，就说明路由通了。

## wire_api 设为 responses

Codex 过去说旧的 `chat/completions` 协议，但 OpenAI [已弃用该路径并于 2026 年 2 月移除](https://github.com/openai/codex/discussions/7782)。现在 `wire_api = "chat"` 的自定义提供商会在启动时失败；老配置里带着这行的，改成 `"responses"`。

Responses API 是 OpenRouter 期望的协议，当前 Codex 版本上也默认用它——省略 `wire_api` 也行，上面配置里那行显式声明只是把选择记录下来。相关的坑：提供商 ID `openai`、`ollama`、`lmstudio` 是保留字，你不能靠覆盖内置 `openai` 提供商的 base URL 来接入 OpenRouter。请新定义一个像 `openrouter` 这样的提供商。

## 钉住模型，盯住支出

专用的 Codex 模型大多已弃用，Codex CLI 更好的默认是 GPT-5.6 家族。5.6 各型号共享 1M token 上下文窗口，选择就落到价格与任务难度的配比上。平台费前的当前费率（来自[模型目录](https://openrouter.ai/models?q=gpt-5.6)）：

| OpenRouter slug | 输入 $/M | 输出 $/M |
| --- | --- | --- |
| `openai/gpt-5.6-sol` | $2 | $10 |
| `openai/gpt-5.6-terra` | $2 | $12 |
| `openai/gpt-5.6-luna` | $0.20 | $1.20 |

迭代探索型工作用 `gpt-5.6-luna`，最难的硬活用 `gpt-5.6-sol`。`model` 也可以指向任何非 Codex slug，比如 `anthropic/claude-sonnet-4.6`，其他什么都不用动。

Agentic 会话烧的 token 比提示词长度暗示的多得多——模型每一轮都在重新处理仓库文件、工具输出和推理轨迹。三个控制项让它保持可预测：给 key 设一条[支出 guardrail](https://openrouter.ai/docs/guides/features/guardrails)，到达每日或每月上限后请求直接拒绝；模型配任务，`gpt-5.6-sol` 每输出 token 贵过 `gpt-5.6-luna` 8 倍以上；例行小改把 `model_reasoning_effort` 降到 `"low"` 或 `"medium"`。

费用账很轻。OpenRouter 不加价提供商定价，你付上面的费率加额度购买上 5.5% 手续费。一次专注的会话，`gpt-5.6-sol` 读 200K 输入 token、写 50K 输出，token 成本约 $0.90，额度手续费再加约 5 美分。失败的请求不计费。

## 修 model_not_found

`model_not_found` 是另一个常见错误。按顺序检查：

- **slug 不是逐字的。**它必须和 OpenRouter 的 slug 一字不差。直接从 [openrouter.ai/models](https://openrouter.ai/models) 复制。
- **少了前缀。**OpenAI 的 slug 形如 `openai/gpt-5.6-sol`。`openai/` 前缀是必需的，光 `gpt-5.6-sol` 匹配不到。
- **简写指向了别处。**`~openai/gpt-latest` 别名追踪的是 OpenAI 最新通用模型，未必是你想要的变体——请显式钉一个 slug。
- **配置放错了文件。**把 `model_provider` 和 `model_providers` 移到用户级 `~/.codex/config.toml`。
- **Codex 警告 "Unknown model" 或 fallback metadata。**你的提供商块在用 `env_key` 认证，Codex 因此没拉 OpenRouter 模型目录。换成上文配置里的命令式 `auth` 块。

## 什么时候经 OpenRouter 路由是划算的

当你想快速切换多模型、在 OpenAI 默认之外试开源模型、要跨 [70 多家提供商](https://openrouter.ai/models)的故障转移、要实时[用量可视性](https://openrouter.ai/activity)，或要在一个控制台里做团队成本控制时，OpenRouter 在 Codex 工作流里就值回票价。换模型是 `config.toml` 里 `model` 一行改动——不换新 key、不重装。你也可以跑 [BYOK](https://openrouter.ai/docs/guides/overview/auth/byok)：用自己的提供商 key 路由，在按套餐而定的免费额度之后，对等价的 OpenRouter 成本收 5% 费用；最新细则见[定价页](https://openrouter.ai/pricing)。

## 常见问题

### Codex CLI 能配 OpenRouter 用吗？

能。在用户级 `~/.codex/config.toml` 加一个 `[model_providers.openrouter]` 块，`base_url` 指向 `https://openrouter.ai/api/v1`，设 `model_provider = "openrouter"`，加一个回显 `OPENROUTER_API_KEY` 的命令式 `auth` 块，再钉一个模型 slug。从那一刻起 Codex 就经 OpenRouter 路由。

### 为什么 Codex 加 OpenRouter 报 model_not_found？

`model` 值必须是逐字的 OpenRouter slug 并含提供商前缀，如 `openai/gpt-5.6-sol`。裸写 `gpt-5.6-sol` 是最常见原因。提供商块也必须住在用户级 `~/.codex/config.toml`，不是项目本地的。

### 通过 OpenRouter 用 Codex CLI 需要 OpenAI 订阅吗？

不需要。配好自定义提供商并导出 `OPENROUTER_API_KEY` 后，请求经 OpenRouter 路由并在 OpenRouter 计费，不需要另开 OpenAI 套餐。

### Codex 经 OpenRouter 要花多少钱？

提供商每 token 单价加额度购买上 5.5% 手续费，提供商价格零加价。例如 `gpt-5.6-sol` 在该费用之前是每百万输入 $2、每百万输出 $10。失败的请求不计费。

### 为什么 Codex 在 OpenRouter 下警告 unknown model 或 fallback metadata？

你的提供商块用 `env_key` 认证，Codex 因此不获取 OpenRouter 模型目录。改用命令式 `auth` 块。
