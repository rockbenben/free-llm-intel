# Claude Opus vs Sonnet vs Haiku：你该用哪个？

OpenRouter ·10/30/2026

![Claude Opus vs Sonnet vs Haiku：你该用哪个？](https://openrouter.ai/blog/images/claude-opus-vs-sonnet-vs-haiku.png)![Claude Opus vs Sonnet vs Haiku：你该用哪个？](https://openrouter.ai/blog/images/claude-opus-vs-sonnet-vs-haiku-dark.png)

把 [Claude Sonnet 5.5](https://openrouter.ai/anthropic/claude-sonnet-5.5) 用作你的默认模型，[Claude Haiku 5.5](https://openrouter.ai/anthropic/claude-haiku-5.5) 用于大批量和 sub-agent 工作，而当任务很长、很模糊、或者出错的代价很高时用 [Claude Opus 5.5](https://openrouter.ai/anthropic/claude-opus-5.5)。

对大多数团队来说，选择是在 Opus 和 Sonnet 之间，而问题在于 Opus 每 token 两倍于 Sonnet 的价格是否值得。在我们测试的编程任务上，不值得。我们给每个模型同样的 11 道带隐藏测试的编程题，以及 [Claude Code](https://code.claude.com/docs/en/overview) 里同样的修 bug 任务。每个模型都通过了全部测试，所以把它们区分开的是成本。按每道任务计，Haiku 比 Opus 便宜 19 到 30 倍，而 Sonnet 的成本是 Opus 的一半到三分之二。

这些结果告诉你三者在我们的任务上表现如何。要知道哪一个最适合你的工作流，唯一的办法是在你自己的工作上测试它们。[Ori Eval](https://openrouter.ai/docs/guides/ori/eval) 可以代你做这件事：你问你的编程智能体哪个模型最适合你的项目，它就会在你的代码里找出测试材料、写出 eval、跑完你想比较的模型，并连同背后的分数、耗时和成本推荐一个。讲如何在它们之间切换的那一节会说明如何把它指向全部三档。

## Tl;dr

- 把 Claude Sonnet 5.5 作为默认。它在我们的 GPQA Diamond 和 τ-bench 运行里得分与 Opus 5.5 持平或更高，并通过了每一道编程测试，而每 token 的价格只有后者的一半。
- 把 Haiku 5.5 用于大批量工作和 sub-agent。它同样通过了每一道编程测试，成本只有 Sonnet 的十二分之一到十六分之一。
- 把 Opus 5.5 留给又长又模糊、一次出错的损失大于 token 成本的任务。我们的短任务无法排除它在这方面的优势。
- 我们的任务不是你的任务。在定下用哪一个之前，先用 Ori Eval 在你自己的工作上演一遍三者。
- 在 OpenRouter 上，三者只差一个模型字符串，而 Claude Code 可以为每个角色指定不同的模型。

## Opus、Sonnet 和 Haiku 有什么不同？

Opus 5.5、Sonnet 5.5 和 Haiku 5.5 是同一代模型的三档。Anthropic 于 2026 年 9 月 22 日发布 [Opus 5.5](https://www.anthropic.com/claude-opus-5-5)，9 月 28 日发布 [Sonnet 5.5](https://www.anthropic.com/claude-sonnet-5-5)，10 月 7 日发布 [Haiku 5.5](https://www.anthropic.com/claude-haiku-5-5)。三者都有 [100 万 token 的上下文窗口](https://platform.claude.com/docs/en/about-claude/models/overview)，都接受文本、图片和 PDF。它们的差别主要在价格，以及 Haiku 更低的基准分数。

| 模型属性 / 指标 | Opus 5.5 | Sonnet 5.5 | Haiku 5.5 |
| --- | --- | --- | --- |
| 输入，每百万 token | $4.00 | $2.00 | $0.10 |
| 输出，每百万 token | $20.00 | $10.00 | $0.50 |
| 缓存读取，每百万 token | $0.20 | $0.10 | $0.01 |
| Artificial Analysis Intelligence Index | 57.6 | 56.0 | 43.4 |
| GPQA Diamond（我们的运行） | 90.4% | 92.4% | 86.6% |
| τ-bench airline（我们的运行） | 75.5% | 78.7% | 76.0% |
| OpenRouter 上的 token 量，10 月 12 日至 18 日 | 6.18T | 2.45T | 2.07T |

价格是我们 2026 年 10 月 21 日的牌价，来自 [Opus 5.5](https://openrouter.ai/anthropic/claude-opus-5.5)、[Sonnet 5.5](https://openrouter.ai/anthropic/claude-sonnet-5.5) 和 [Haiku 5.5](https://openrouter.ai/anthropic/claude-haiku-5.5) 的模型页面。基准那几行来自我们的[基准接口](https://openrouter.ai/docs/api/api-reference/benchmarks/list-benchmarks)，取自 10 月 21 日（其中我们自己的运行是 10 月 17 日那次）。[Artificial Analysis Intelligence Index](https://artificialanalysis.ai/methodology/intelligence-benchmarking) 是独立基准测评公司 Artificial Analysis 在 10 项评测上的综合分数。T 表示万亿 token，来自我们的[每日排名数据集](https://openrouter.ai/docs/api/api-reference/datasets/daily-token-totals-for-top-50-models)。

## Opus 比 Sonnet 更强吗？

在我们运行的基准上，Claude Opus 5.5 并没有赢过 Claude Sonnet 5.5。在我们跑的 [GPQA Diamond](https://arxiv.org/abs/2311.12022)——一套 198 道研究生水平的科学题——上，Sonnet 得分更高（92.4% 对 90.4%）。它在 [τ-bench](https://github.com/sierra-research/tau2-bench) airline 这个多轮客服 agent 基准上得分也更高（78.7% 对 75.5%）。Opus 只在 Artificial Analysis 指数上领先 1.6 分。在我们这两次运行里，Sonnet 的每任务成本都不足它的一半：每道 GPQA 题 $0.025，而 Opus 是 $0.054；每个 τ-bench 任务 $0.16，而 Opus 是 $0.34。

在 10 月 12 日那一周，Opus 5.5 在 OpenRouter 上承载的 token 量约为 Sonnet 的 2.5 倍。Opus 也是 Claude Code 在多数套餐下的[默认模型](https://code.claude.com/docs/en/model-config)，而在我们的测试里，没有设置模型时 Claude Code 通过 OpenRouter 用的就是 Opus 5.5。如果你没有改过模型，你现在跑的就是 Opus。

## Haiku 足够好，可以替代 Sonnet 吗？

对于要求明确的常规工作，Haiku 5.5 可以替代 Sonnet。它在 τ-bench airline 上得到 76.0%，比 Opus 高半分，比 Sonnet 低 2.7 分，每个任务 $0.011，约为 Sonnet 成本的十四分之一。我们每次运行每个模型只有 100 到 200 个任务，所以这个基准上几分之差可能只是噪声。Haiku 在 GPQA Diamond 上落后 Sonnet 5.8 分，在 Artificial Analysis 指数上落后 12.6 分——该指数给 agentic 任务和通用知识各 30% 权重，给编程和科学推理各 20% 权重。在常规编程上，我们下面的测试没有发现差距。

## 我们的编程测试说明了什么？

我们测了两件事：按规格写一个函数，以及用 Claude Code 修一个仓库。三个模型在这两项里都通过了每一道测试。

### 带隐藏测试的函数题

我们写了 11 道 Python 题，每题配一个隐藏的测试文件。八道日常题是：解析时长、合并区间、LRU cache、不用 `eval` 的算术求值器、cron 表达式的下一次运行时间、文字折行、[Semantic Versioning](https://semver.org/) 的排序顺序，以及一个 JSON path 读取器。三道难题是：不用 `re` 模块的正则引擎、带三值 NULL 逻辑的 SQL WHERE 过滤器，以及在夏令时切换日跨时区查找日历空档。每个模型把每道日常题做两遍、每道难题做三遍，都用模型的默认设置，因此每个模型共 25 次尝试。

| 指标 | Opus 5.5 | Sonnet 5.5 | Haiku 5.5 |
| --- | --- | --- | --- |
| 通过的尝试数 | 25 中 25 | 25 中 25 | 25 中 25 |
| 每道日常题成本 | $0.0211 | $0.0112 | $0.0007 |
| 每道难题成本 | $0.0739 | $0.0380 | $0.0027 |
| 每道难题秒数 | 32.1 | 25.7 | 22.6 |

Haiku 用了最多的推理，却仍然最快完成难题。在难题上它平均用了 3,202 个 [reasoning token](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)，而 Opus 是 1,252 个。reasoning token 指的是模型在写出答案之前，用来推演问题的 token。即使多做了这些推理，Haiku 每道难题的成本也只有 Opus 的二十七分之一。

### 在 Claude Code 里修一个 bug

我们给 Claude Code 一个小型发票库，里面有三个 bug 和五个测试。这三个 bug 分别是：用了 [banker’s rounding](https://docs.python.org/3/library/functions.html#round)（四舍六入五成双）的取整、一个在引号内的逗号处切分的 CSV 解析器，以及一个把数量覆盖掉而不是累加起来的汇总。我们通过 OpenRouter 每个模型跑三次，用 [`ANTHROPIC_MODEL` 环境变量](https://code.claude.com/docs/en/model-config)来选择模型。

| 指标 | Opus 5.5 | Sonnet 5.5 | Haiku 5.5 |
| --- | --- | --- | --- |
| 修好全部三个 bug 的运行数 | 3 中 3 | 3 中 3 | 3 中 3 |
| 每场会话中位成本 | $0.098 | $0.062 | $0.0052 |
| 轮数 | 5 | 5 | 6 到 8 |
| 实际耗时 | 24 到 30 秒 | 18 到 25 秒 | 22 到 31 秒 |

一轮就是这场会话里模型的一次响应。我们用我们自己的价格、按各场会话的 token 数来算会话成本，因为 Claude Code 自己给出的数字对 Haiku 是错的。

Claude Code 自带的 [`total_cost_usd` 字段](https://code.claude.com/docs/en/headless)没有认出我们的 Haiku slug，把每场会话报成 $0.16 到 $0.31，而我们算出的中位数是 $0.0052，等于高了 30 到 60 倍。在 print 模式（`claude -p`）下，Claude Code 认不出模型 slug 时会记录一条警告。在通过 Haiku 要一个单词回复的请求里我们又一次见到它：Claude Code 报 $0.107，而按我们的价格这次请求只花约 $0.002。

```
[claude-code:unrecognized_model] {"model":"anthropic/claude-haiku-5.5","query_source":"sdk"}
```

如果你通过 OpenRouter 运行 Claude Code，改到 [Activity 页面](https://openrouter.ai/activity)核对支出，需要上限时使用我们的[支出控制](https://openrouter.ai/blog/insights/governing-team-ai-spend/)。

这些都是细小、要求明确的任务。在这类任务上，三档同样可靠，而它们的成本相差很大。它们没有覆盖 Anthropic 打造 Opus 所要对付的工作，也就是[长时间运行的 agentic 编程与知识工作](https://platform.claude.com/docs/en/about-claude/models/overview)——在那类工作里，一次错误的损失比 token 成本高得多。

## 你该用哪个？

- 如果你只想定一个默认，就用 Claude Sonnet 5.5。它在我们两次基准运行上得分与 Opus 持平或更高，在我们全部测试中与 Opus 表现一致，而每 token 价格只有后者的一半。
- 如果你要跑大量请求，比如分类、抽取、sub-agent 或批量改代码，就用 Haiku 5.5。它通过了我们给它的每一道测试，成本只有 Sonnet 的十二分之一到十六分之一、Opus 的十九分之一到三十分之一。把 prompt 控制在 100,000 token 以内，才能一直用上它的[较低价格](https://openrouter.ai/blog/tutorials/how-to-get-the-lowest-cost-llm-inference-on-openrouter/)。在 Claude Code 之外，我们的 [Subagent 服务器工具](https://openrouter.ai/docs/guides/features/server-tools/subagent)可以让较大的模型把自成一体的任务交给较小的模型。
- 长任务、而且出错的代价很高，就用 Opus 5.5。那就是它为之而生的工作，而我们的短任务无法排除它在那里的优势。
- 如果你分不清自己的工作负载属于哪一类，就按下一节说的，测你自己的任务而不是我们的。

## 怎么在它们之间切换？

我们通过[一个 API](https://openrouter.ai/docs/quickstart)、一个 key、一种请求格式来服务全部三个模型，所以切换就意味着改模型字符串。下面这个循环把同一条 prompt 发给每一档，并打印输出的 token 数以及[我们在每个响应里返回的成本](https://openrouter.ai/docs/cookbook/administration/usage-accounting)。

```
import os
import requests
for model in ["anthropic/claude-opus-5.5", "anthropic/claude-sonnet-5.5", "anthropic/claude-haiku-5.5"]:
    r = requests.post(
        "https://openrouter.ai/api/v1/chat/completions",
        headers={"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"},
        json={"model": model, "messages": [{"role": "user", "content": "Write a Python function that merges overlapping intervals."}]},
        timeout=300,
    )
    usage = r.json()["usage"]
    print(f"{model}: {usage['completion_tokens']} output tokens, ${usage['cost']:.4f}")
```

这是我们在 2026 年 10 月 13 日那次运行得到的输出。

```
anthropic/claude-opus-5.5: 1190 output tokens, $0.0239
anthropic/claude-sonnet-5.5: 876 output tokens, $0.0088
anthropic/claude-haiku-5.5: 852 output tokens, $0.0004
```

用 [Ori Eval](https://openrouter.ai/docs/guides/ori/eval) 把[你自己的任务](https://openrouter.ai/blog/tutorials/building-a-golden-eval-dataset-from-production-traffic/)在每一档上跑一遍。Ori Eval 的测试是 TypeScript 的 `*.eval.ts` 文件。把三个 slug 分别传给同一个文件里的 `setupAgent({ model })`，同一套测试就会在每一档上跑起来。

在 Claude Code 里，你可以把 Opus 留给规划，而把常规工作交给更便宜的模型。按我们的[配置指南](https://openrouter.ai/docs/cookbook/coding-agents/claude-code-integration)把 Claude Code 指向 OpenRouter，然后为每个角色设置模型。

```
export ANTHROPIC_DEFAULT_OPUS_MODEL="anthropic/claude-opus-5.5"
export ANTHROPIC_DEFAULT_SONNET_MODEL="anthropic/claude-sonnet-5.5"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="anthropic/claude-haiku-5.5"
export CLAUDE_CODE_SUBAGENT_MODEL="anthropic/claude-haiku-5.5"
```

Claude Code 2.1.307 认得 Opus 和 Sonnet 的 slug，会给出它们 100 万 token 的上下文窗口。它还不认得 Haiku 的 slug，会假定是 200,000 token。要给 Haiku 完整的窗口，就在它的 slug 后面加上 `[1m]`——我们在路由之前会去掉这个后缀。不加的话，Haiku 的会话就会被压在约 200,000 token 以内。

这些变量设定的是每个名字指向哪个模型，并不会改变你用的是哪一个。要把 Sonnet 变成你的主模型，就在会话里运行 `/model sonnet`，或者在启动 Claude Code 之前设置 `ANTHROPIC_MODEL=sonnet`。想用 Opus 规划、用 Sonnet 写代码，就改跑 [`/model opusplan`](https://code.claude.com/docs/en/model-config)。由于设置了 `CLAUDE_CODE_SUBAGENT_MODEL`，那些没有指定自己模型的 [sub-agent](https://code.claude.com/docs/en/sub-agents) 会跑在 Haiku 上。

如果你更想让我们[按请求挑选](https://openrouter.ai/blog/insights/model-routing/)，[Auto Router](https://openrouter.ai/docs/guides/routing/routers/auto-router)（`openrouter/auto`）会为每条 prompt 选一个模型。编程方面，[Pareto Router](https://openrouter.ai/docs/guides/routing/routers/pareto-router) 会挑一个达到你设定的最低编程分数的模型。

## 常见问题

### Claude Haiku 比 Sonnet 便宜吗？

是的。在 OpenRouter 上，对 100,000 token 以内的 prompt，Haiku 5.5 每输入和输出 token 的价格比 Claude Sonnet 5.5 便宜 20 倍——每百万输入 token $0.10，而 Sonnet 是 $2.00。在我们的 Claude Code 运行里，每场会话的差距小一些，约为 12 倍，部分原因是 Haiku 用了更多轮才达到同样的结果。

### 编程上 Sonnet 5.5 比 Opus 5.5 更好吗？

在我们的 Claude Sonnet 对 Opus 的编程测试中，两者打平。它们都通过了全部 25 次隐藏测试尝试，以及通过 OpenRouter 跑的三场 Claude Code 运行，而 Sonnet 更快、成本只有后者的一半到三分之二。Opus 在 Artificial Analysis 指数上领先 1.6 分，而且 Anthropic 把它定位给[长时间运行的 agentic 编程](https://platform.claude.com/docs/en/about-claude/models/overview)，所以在又长又模糊的会话里它是更稳妥的选择。

### Claude Haiku 适合做什么？

Haiku 5.5 适合大批量、要求明确的工作，例如[分类、抽取、路由](https://platform.claude.com/docs/en/about-claude/models/overview)、sub-agent 任务以及常规代码改动。在我们通过 OpenRouter 做的测试里，它通过了每一道编程题，包括一个正则引擎和 SQL 的三值 NULL 逻辑，并在 τ-bench airline 上比 Opus 高半分。

### Claude Code 用的是哪个 Claude 模型？

按 [Anthropic 的模型配置文档](https://code.claude.com/docs/en/model-config)，Claude Code 在 Pro、Max、Team、Enterprise 以及 Anthropic API 账号上默认使用 Opus 5.5。当你通过 OpenRouter 运行 Claude Code 时，可以用 `ANTHROPIC_MODEL` 更换主模型，并用上面的环境变量设置各个角色。
