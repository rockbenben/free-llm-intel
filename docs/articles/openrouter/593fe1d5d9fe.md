# Claude Opus、十四行诗、俳句：您应该使用哪一个？

开放路由器·10/30/2026

![Claude Opus vs Sonnet vs Haiku: 你应该使用哪个？](https://openrouter.ai/blog/images/claude-opus-vs-sonnet-vs-haiku.png)![Claude Opus vs Sonnet vs Haiku: 你应该使用哪个？](https://openrouter.ai/blog/images/claude-opus-vs-sonnet-vs-haiku-dark.png)

使用 [Claude Sonnet 5.5](https://openrouter.ai/anthropic/claude-sonnet-5.5) 作为默认值，[Claude Haiku 5.5](https://openrouter.ai/anthropic/claude-haiku-5.5) 用于大容量和子代理工作，[Claude Opus] 5.5](https://openrouter.ai/anthropic/claude-opus-5.5) 当任务很长、不明确或出错代价高昂时。

对于大多数团队来说，选择是在 Opus 和 Sonnet 之间，问题是 Opus 的每个代币价格是否是 Sonnet 价格的两倍。在我们测试的编码任务中，事实并非如此。我们为每个模型提供了相同的 11 个编码任务，其中包含隐藏测试以及 [Claude Code](https://code.claude.com/docs/en/overview) 中相同的错误修复任务。每个模型都通过了所有的测试，所以它们之间的区别在于成本。每项任务的俳句比 Opus 便宜 19 到 30 倍，而 Sonnet 的成本是 Opus 的一半到三分之二。

这些结果告诉您这三个人在我们的任务上的表现如何。了解哪一个最适合您的工作流程的唯一方法是在您自己的工作中测试它们。 [Ori Eval](https://openrouter.ai/docs/guides/ori/eval) 会为您做到这一点。您询问编码代理哪种模型最适合您的项目，它会在您的代码中找到测试材料，编写评估，运行您想要比较的模型，并推荐一个模型及其背后的分数、时间和成本。关于它们之间切换的部分展示了如何将其指向所有三个层。

## Tl;博士

- 使用Claude Sonnet 5.5 作为默认值。它在我们的 GPQA Diamond 和 τ-bench 运行中的得分与 Opus 5.5 一样甚至更好，并通过了所有编码测试，而每个代币价格只有一半。
- 使用 Haiku 5.5 进行大批量和分代理工作。它也通过了所有编码测试，成本只有 Sonnet 的 12 到 16 分之一。
- 保留 Opus 5.5 来执行长期、模糊的任务，其中错误的代价比代币还要高。我们的短期任务不能排除那里的优势。
- 我们的任务不是你的。在您决定其中一项之前，请先与 Ori Eval 一起测试这三项。
- 在 OpenRouter 上，这三者都是一个模型字符串，Claude Code 可以为每个角色使用不同的模型字符串。

## Opus、十四行诗和俳句有何不同？

Opus 5.5、Sonnet 5.5 和 Haiku 5.5 是同一代车型的三个级别。 Anthropic 于 2026 年 9 月 22 日发布了 [Opus 5.5](https://www.anthropic.com/claude-opus-5-5)，于 9 月 28 日发布了 [Sonnet 5.5](https://www.anthropic.com/claude-sonnet-5-5)，并于 10 月 7 日发布了 [Haiku 5.5](https://www.anthropic.com/claude-haiku-5-5)。这三个都有一个 [100 万代币上下文窗口](https://platform.claude.com/docs/en/about-claude/models/overview) 并接受文本、图像和 PDF。它们的差异主要在于价格，对于俳句来说，差异在于较低的基准分数。

| ---| ---| ---| ---|
|输入，每百万代币 | 4.00 美元 | 2.00 美元 | 0.10 美元 |
|产出，每百万代币 | 20.00 美元 | 10.00 美元 | 0.50 美元 |
|缓存读取，每百万个令牌 | 0.20 美元 | 0.10 美元 | 0.01 美元 |
|人工智能分析智能指数| 57.6 | 57.6 56.0 | 56.0 43.4 | 43.4
| GPQA 钻石级（我们的运行）| 90.4% | 92.4% | 86.6% |
| τ-长凳航空公司（我们的运营）| 75.5% | 78.7% | 76.0% |
| OpenRouter 上的代币，10 月 12 日至 18 日 | 6.18T | 2.45吨| 2.07T |

价格是我们 2026 年 10 月 21 日的标价，来自 [Opus 5.5](https://openrouter.ai/anthropic/claude-opus-5.5)、[Sonnet 5.5](https://openrouter.ai/anthropic/claude-sonnet-5.5) 和 [Haiku] 的模型页面5.5](https://openrouter.ai/anthropic/claude-haiku-5.5)。基准行来自我们的 [基准端点](https://openrouter.ai/docs/api/api-reference/benchmarks/list-benchmarks)，于 10 月 21 日提取（我们的运行时间为 10 月 17 日）。 [人工分析智能指数](https://artificialanalysis.ai/methodology/intelligence-benchmarking) 是独立基准测试公司 Artificial Analysis 的 10 项评估的综合得分。 T 表示数万亿代币，来自我们的[每日排名数据集](https://openrouter.ai/docs/api/api-reference/datasets/daily-token-totals-for-top-50-models)。

## Opus 比 Sonnet 更好吗？

在我们运行的基准测试中，Claude Opus 5.5 并未击败 Claude Sonnet 5.5。 Sonnet 在我们运行的 [GPQA Diamond](https://arxiv.org/abs/2311.12022) 中得分更高，这是一组 198 个研究生水平的科学问题（92.4% 与 90.4%）。它还在 [τ-bench](https://github.com/sierra-research/tau2-bench) 航空公司（多轮客户服务代理基准）上得分更高（78.7% vs 75.5%）。 Opus 在人工分析指数上领先 1.6 个点。在我们的两次运行中，Sonnet 每个任务的成本不到一半，每个 GPQA 问题的成本为 0.025 美元，而每个 τ-bench 任务的成本为 0.054 美元；每个 τ-bench 任务的成本为 0.16 美元，而每个任务的成本为 0.34 美元。

10 月 12 日当周，Opus 5.5 在 OpenRouter 上的代币交易量约为 Sonnet 的两倍半。在大多数计划中，Opus 也是 Claude Code 的[默认模型](https://code.claude.com/docs/en/model-config)，在我们的测试中，当未设置模型时，Claude Code 通过 OpenRouter 使用 Opus 5.5。如果您没有更改模型，那么您正在运行的是 Opus。

## 俳句是否足以取代十四行诗？

Haiku 5.5 可以替代 Sonnet 来完成明确的日常工作。它在 τ-bench Airlines 上的得分为 76.0%，比 Opus 高 0.5 分，比 Sonnet 低 2.7 分，每项任务的成本为 0.011 美元。这大约是十四行诗成本的四分之一。我们的运行每个模型有 100 到 200 个任务，因此该基准测试中的几个点的差距可能是噪音。 Haiku 在 GPQA Diamond 上落后 Sonnet 5.8 分，在人工分析指数上落后 Sonnet 12.6 分，其中代理任务和一般知识的权重各为 30%，编码和科学推理的权重各为 20%。在常规编码方面，我们的以下测试没有发现差距。

## 我们的编码测试显示了什么？

我们测试了两件事，根据规范编写函数并使用 Claude Code 修复存储库。所有三个模型都通过了所有测试。

### 带有隐藏测试的函数

我们编写了 11 个 Python 任务，每个任务都有一个隐藏的测试文件。八个日常任务是解析持续时间、合并间隔、LRU 缓存、不带“eval”的算术评估器、cron 表达式的下一次运行时间、自动换行、[语义版本控制](https://semver.org/) 排序顺序和 JSON 路径读取器。这三个艰巨的任务是不带“re”模块的正则表达式引擎、具有三值 NULL 逻辑的 SQL WHERE 过滤器以及夏令时过渡日跨时区的空闲日历槽。每个模型使用模型的默认设置回答每个日常任务两次，每个困难任务回答三次，每个模型尝试 25 次。

|公制|作品 5.5 |十四行诗 5.5 |俳句 5.5 |
| ---| ---| ---| ---|
|尝试通过了| 25 共 25 | 25 共 25 | 25 共 25 |
|每项日常任务的成本| 0.0211 美元 | 0.0112 美元 | 0.0007 美元 |
|每项艰巨任务的成本| 0.0739 美元 | 0.0380 美元 | 0.0027 美元 |
|每项艰巨任务的秒数| 32.1 | 32.1 25.7 | 25.7 22.6 | 22.6

俳句使用了最多的推理，并且仍然以最快的速度完成了困难的任务。在困难任务中，它平均使用 3,202 个推理令牌（https://openrouter.ai/docs/guides/best-practices/reasoning-tokens），而 Opus 则使用 1,252 个。推理标记是模型在写出答案之前用于解决问题的标记。即使有额外的推理，俳句的每项艰巨任务的成本也只有 Opus 的 27 分之一。

### Claude Code中的错误修复

我们给了 Claude Code 一个小型的发票库，其中包含三个错误和五个测试。这些错误是使用[银行家舍入](https://docs.python.org/3/library/functions.html#round)（四舍五入到偶数）的舍入、在引号内以逗号分隔的 CSV 解析器以及覆盖数量而不是相加的摘要。我们通过 OpenRouter 对每个模型运行 3 次，选择带有 [`ANTHROPIC_MODEL` 环境变量](https://code.claude.com/docs/en/model-config) 的模型。

|公制|作品 5.5 |十四行诗 5.5 |俳句 5.5 |
| ---| ---| ---| ---|
|修复了所有三个错误的运行 | 3 共 3 | 3 共 3 | 3 共 3 |
|每次会话费用中位数 | 0.098 美元 | 0.062 美元 | 0.0052 美元 |
|转 | 5 | 5 | 6 至 8 |
|挂钟时间 | 24 至 30 秒 | 18 至 25 秒 | 22 至 31 秒 |

回合是会话中的一种模型响应。我们根据每个会话的代币计数以我们的价格计算会话成本，因为 Claude Code 自己的数字对于 Haiku 来说是错误的。

Claude Code 自己的 [`total_cost_usd` 字段](https://code.claude.com/docs/en/headless) 无法识别我们的 Haiku slug，并报告每次会话 0.16 到 0.31 美元，是我们计算的中位数 0.0052 美元的 30 到 60 倍。在打印模式（“claude -p”）下，Claude Code 在无法识别模型段时会记录一条警告。我们在 Haiku 的一个字回复中再次看到了这一点，其中 Claude Code 报告为 0.107 美元，而按我们的价格计算，该请求的成本约为 0.002 美元。

如果您通过 OpenRouter 运行 Claude Code，请在[活动页面](https://openrouter.ai/activity) 上检查支出，如果需要上限，请使用我们的[支出控件](https://openrouter.ai/blog/insights/governing-team-ai-spend/)。

这些都是小而明确的任务。在这些任务上，这三层同样可靠，但它们的成本却相差很大。它们不包括 Anthropic 构建 Opus 的工作，这是[长期运行的代理编码和知识工作](https://platform.claude.com/docs/en/about-claude/models/overview)，其中错误的成本比代币还要高。

## 您应该使用哪一个？

- 如果您想要一个默认值，请使用 Claude Sonnet 5.5。在我们的两次基准测试中，它的得分与 Opus 一样甚至更好，并且在我们所有的测试中都与 Opus 相匹配，而每个代币的价格只有一半。
- 如果您运行大量请求，例如分类、提取、子代理或批量代码编辑，请使用 Haiku 5.5。它通过了我们给予它的每项测试，成本仅为 Sonnet 的 12 至 16 分之一，Opus 的 19 至 30 分之一。将提示保持在 100,000 个代币以下，以保持其[较低价格](https://openrouter.ai/blog/tutorials/how-to-get-the-lowest-cost-llm-inference-on-openrouter/)。在 Claude Code 之外，我们的 [Subagent 服务器工具](https://openrouter.ai/docs/guides/features/server-tools/subagent) 可以让较大的模型将独立的任务交给较小的模型。
- 使用 Opus 5.5 执行耗时较长的任务，一旦出错就会付出高昂的代价。这就是它的目的，我们的短期任务不能排除这方面的优势。
- 如果您无法判断您的工作负载属于哪一组，请测试您自己的任务而不是我们的任务，如下一节所述。

## 如何在它们之间切换？

我们通过[一个API](https://openrouter.ai/docs/quickstart)、一个密钥和一种请求格式来服务所有三个模型，因此切换意味着更改模型字符串。此循环向每一层发送相同的提示，并打印输出令牌和[我们在每个响应中返回的成本](https://openrouter.ai/docs/cookbook/administration/usage-accounting)。
```
import os
import requests
for model in ["anthropic/claude-opus-5.5", "anthropic/claude-sonnet-5.5", "anthropic/claude-haiku-5.5"]:
    r = requests.post(
        "https://openrouter.ai/api/v1/chat/completions",
        headers={"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"},
        json={"model": model, "messages": [{"role": "user", "content": "Write a Python function that merges overlapping intervals."}]},
        timeout=300,
    )
    usage = r.json()["usage"]
    print(f"{model}: {usage['completion_tokens']} output tokens, ${usage['cost']:.4f}")
```
这是我们 2026 年 10 月 13 日运行的输出。
```
anthropic/claude-opus-5.5: 1190 output tokens, $0.0239
anthropic/claude-sonnet-5.5: 876 output tokens, $0.0088
anthropic/claude-haiku-5.5: 852 output tokens, $0.0004
```
使用 [Ori Eval](https://openrouter.ai/docs/guides/ori/eval) 在每一层运行[您自己的任务](https://openrouter.ai/blog/tutorials/building-a-golden-eval-dataset-from-production-traffic/)。 Ori Eval 测试是 TypeScript `*.eval.ts` 文件。将三个 slugs 中的每一个传递给一个文件中的“setupAgent({ model })”，并在每一层上运行相同的测试。

在 Claude Code 中，您可以保留 Opus 进行规划，并将日常工作发送给更便宜的模型。使用我们的[设置指南](https://openrouter.ai/docs/cookbook/coding-agents/claude-code-integration)将Claude Code指向OpenRouter，然后为每个角色设置模型。
```
export ANTHROPIC_DEFAULT_OPUS_MODEL="anthropic/claude-opus-5.5"
export ANTHROPIC_DEFAULT_SONNET_MODEL="anthropic/claude-sonnet-5.5"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="anthropic/claude-haiku-5.5"
export CLAUDE_CODE_SUBAGENT_MODEL="anthropic/claude-haiku-5.5"
```
Claude Code 2.1.307 可以识别 Opus 和 Sonnet slugs，并为它们提供 100 万个令牌的上下文窗口。它还无法识别 Haiku slug，并假设有 200,000 个令牌。要为俳句提供完整窗口，请在其 slug 中添加“[1m]”。我们在路由之前去掉后缀。如果不启用它，俳句会话的令牌数将低于 200,000 个。

这些变量设置每个名称指向哪个模型。它们不会改变您使用哪一个。要使 Sonnet 成为主要模型，请在会话中运行“/model sonnet”或在启动 Claude Code 之前设置“ANTHROPIC_MODEL=sonnet”。要使用 Opus 进行规划并使用 Sonnet 编写代码，请运行 [`/model opusplan`](https://code.claude.com/docs/en/model-config)。由于设置了“CLAUDE_CODE_SUBAGENT_MODEL”，因此未命名自己模型的子代理在 Haiku 上运行。

如果您希望我们[根据请求选择](https://openrouter.ai/blog/insights/model-routing/)，[自动路由器](https://openrouter.ai/docs/guides/routing/routers/auto-router) (`openrouter/auto`) 会为每个提示选择一个模型。对于编码，[Pareto Router](https://openrouter.ai/docs/guides/routing/routers/pareto-router) 选择满足您设置的最低编码分数的模型。

## 常见问题

### Claude Haiku比十四行诗便宜吗？

是的。在 OpenRouter 上，对于 100,000 个令牌以下的提示，Haiku 5.5 每个输入和输出令牌的成本比 Claude Sonnet 5.5 低 20 倍，每百万个输入令牌为 0.10 美元，而每百万个输入令牌为 2.00 美元。在我们的 Claude Code 运行中，每次会话的差距较小，约为 12 倍，部分原因是俳句需要更多轮次才能达到相同的结果。

### Sonnet 5.5 比 Opus 5.5 更适合编码吗？

在我们的 Claude Sonnet 与 Opus 编码测试中，两者是相同的。两者都通过了所有 25 次隐藏测试尝试，所有三个 Claude 代码都通过 OpenRouter 运行，而 Sonnet 速度更快，成本也只有 OpenRouter 的一半到三分之二。 Opus 在人工分析指数上领先 1.6 个点，Anthropic 将其定位为[长时间运行的代理编码](https://platform.claude.com/docs/en/about-claude/models/overview)，因此对于长时间、模糊的会话来说，它是更安全的选择。

### Claude Haiku有什么用处？

Haiku 5.5 适合大批量、明确的工作，例如分类、提取、路由、子代理任务和例行代码更改。在我们通过 OpenRouter 进行的测试中，它通过了所有编码任务，包括正则表达式引擎和 SQL 三值 NULL 逻辑，并且在 τ-bench 航空公司上的得分比 Opus 高出半分。

### Claude Code 使用哪种 Claude 模型？

根据 [Anthropic 的模型配置文档](https://code.claude.com/docs/en/model-config)，Claude Code 在 Pro、Max、Team、Enterprise 和 Anthropic API 帐户上默认使用 Opus 5.5。当您通过 OpenRouter 运行 Claude Code 时，您可以使用“ANTHROPIC_MODEL”更改主模型，并使用上面的环境变量设置每个角色。
