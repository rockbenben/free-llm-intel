# 图生视频 AI 模型对比：成本、分辨率与控制力

OpenRouter · 2026-09-29

如果你已经有了视频应当起始的那张图，那么选择图生视频模型的关键就在于第一帧之后必须发生什么：片段可能需要结束于另一张精确的图像、可能要比几秒钟更长、可能需要包含生成音频，或者必须把每秒单价压在某条线以下。

我们服务的视频模型对这些需求的处理方式各不相同。本文覆盖四条模型线：[Veo 3.1](https://openrouter.ai/google/veo-3.1)、[Seedance](https://openrouter.ai/bytedance/seedance-2.5)、[Kling](https://openrouter.ai/kwaivgi/kling-v3.0-pro) 和 [Grok Imagine Video](https://openrouter.ai/x-ai/grok-imagine-video-1.5)。它们不是图生视频目录的全部，完整列表见[视频模型合集](https://openrouter.ai/collections/video-models)。

所有模型都通过同一个[视频生成 API](https://openrouter.ai/docs/guides/overview/multimodal/video-generation)调用：提交、轮询、下载的生命周期对每个模型都一样，但各模型接受的时长、分辨率、帧角色、音频选项和价格并非如此。本文对比这些设置，然后演示如何用 [TypeScript SDK](https://openrouter.ai/docs/client-sdks/typescript/overview) 提交一个图生视频任务。

## 摘要

- Veo 3.1、Fast 和 Lite 生成 4、6 或 8 秒片段，支持首帧与尾帧控制，并有生成音频。Veo 3.1 和 Fast 最高到 4K，Lite 止步 1080p。
- Seedance 2.5 生成 4 到 30 秒片段，480p 或 720p，接受首帧与尾帧，并可接受最多 50 个图像、视频和音频参考素材。Seedance 2.0 线覆盖 4 到 15 秒。
- Kling v3.0 Standard 和 Pro 生成 3 到 15 秒、720p 片段，支持首帧与尾帧控制。音频可选，并且会改变价格。
- Grok Imagine Video 1.5 仅凭首帧生成 1 到 15 秒片段，支持 480p、720p 或 1080p，带生成音频。
- 本文所有模型都走 `POST /api/v1/videos`。`GET /api/v1/videos/models` 返回每个模型支持的设置与定价 SKU。

## 图像在视频请求中可以扮演的角色

图像既可以定义成片视频中的某一帧，也可以作为参考素材。我们用两个不同的请求字段处理这两种情形。

### 文生视频、图生视频与参考生视频

在[文生视频](https://openrouter.ai/docs/cookbook/video-generation/text-to-video)中，模型只凭你的 prompt 构建场景。除了 prompt 描述的内容，你控制不了开场帧。

在[图生视频](https://openrouter.ai/docs/cookbook/video-generation/image-to-video)中，图像成为第一帧、最后一帧，或两者皆是。如果一支产品视频必须精确开场在某个产品镜头上，就用这个模式。

在[参考生视频](https://openrouter.ai/docs/cookbook/video-generation/reference-to-video)中，模型收到的是素材，但不被钉在某个帧位置上。例如你可以提供某个角色的多张图片，让模型在构图新镜头时保持其外观。

如果图像必须出现在片段的某个确切位置，用图生视频；如果它只需要引导结果，用参考生视频。

### `frame_images` 与 `input_references` 字段

我们在 `POST /api/v1/videos` 上把两种模式暴露为独立字段。

字段

作用

frame_images

把图像用作精确的第一帧、最后一帧或两者

input_references

给模型图像、视频或音频素材作为遵循依据，而不钉在某一帧

每个 `frame_images` 条目携带一个取值为 `first_frame` 或 `last_frame` 的 `frame_type`。并非每个模型都支持两种角色。视频模型目录中的 `supported_frame_images` 数组会告诉你某个模型接受哪些角色。

如果你在同一个请求里同时传入两个字段，`frame_images` 优先，我们按图生视频处理该任务。

关于如何读这些表格的三点说明。

- **可选音频**指模型暴露 `generate_audio` 请求参数。Grok Imagine Video 系列不暴露它。Grok Imagine Video 1.5 的描述称该模型会生成音效、环境声和对白，因此表格标为"支持"。较早的 Grok Imagine Video 描述未提及音频，因此表格标为"未列明"。
- **参考输入**反映模型在其 OpenRouter 页面描述中写明的内容。**未列明**表示描述没有提及参考图像、视频或音频，并不表示我们实测过参考会被拒绝。在你依赖之前如何确认支持，见 [reference-to-video cookbook](https://openrouter.ai/docs/cookbook/video-generation/reference-to-video)。
- **Seedance 的价格**按视频 token 计，不按秒。Seedance 2.0 各模型页面写明 token 数等于高 × 宽 × 时长 × 24 再除以 1,024。表中的每秒数字是模型页面对 480p 输出展示的起始费率。Seedance 2.5 列出每百万视频 token $10.70；Seedance 2.0 在 480p 和 720p 列出 $7.00，1080p 与 4K 另有费率；Fast 为 $4.20；Mini 为 $3.50。带视频输入的请求按更低的每 token 费率计费。

由于多数模型按秒计费，时长同时也是一个成本决策。按 Seedance 2.5 的起始费率 $0.1028/s，一个 4 秒片段起价约 $0.41，一个 30 秒片段起价约 $3.08。720p 或不同输入配置下费用会更高。

## 如何选择

先用时长和帧控制过滤候选。确定片段必须多长、需要固定首帧、尾帧还是两者之后，再就音频、分辨率和成本比较剩下的模型。

### 8 秒以内、带生成音频的片段

Veo 3.1、Veo 3.1 Fast 和 Veo 3.1 Lite 生成 4、6 或 8 秒片段，支持 16:9 或 9:16，具备首帧与尾帧控制和 `generate_audio` 选项。Veo 3.1 和 Fast 接受 720p、1080p 和 4K；Lite 接受 720p 和 1080p。

Lite 的 720p 无音频起价 $0.03/s，Veo 3.1 无音频起价 $0.20/s——在 prompt 和运动方案还在反复调整的阶段，Lite 或 Fast 更省钱。[image-to-video cookbook](https://openrouter.ai/docs/cookbook/video-generation/image-to-video) 正是因此选用 `google/veo-3.1-lite`。

Veo 3.1 Fast 和 Lite 的模型描述列出了 [SynthID](https://deepmind.google/models/synthid/) 水印——Google 用于 AI 生成内容的不可感知标记。如果你的工作流有溯源或水印要求，请核对拟用 Veo 变体的模型描述。

### 最长 30 秒、大量参考素材的片段

Seedance 2.5 生成 4 到 30 秒片段，480p 或 720p，接受首帧与尾帧，并可接受最多 50 个图像、视频和音频参考素材。它是本对比中唯一能一次生成产出 20 或 30 秒镜头的模型。

Seedance 2.0 线以更低的起始费率覆盖 4 到 15 秒。Seedance 2.0 接受 480p、720p、1080p 和 4K；Fast 和 Mini 接受 480p 和 720p。三者的描述都列出了图像、视频和音频参考。

如果你不需要 30 秒窗口和 50 个素材的额度，2.0 线以更低的费率覆盖同样的首帧与尾帧工作流。

所有 Seedance 模型只能通过托管 API 运行。我们没有找到任何已发布的权重或模型许可证，因此它们都无法本地或离线（air-gapped）运行。

### 3 到 15 秒的首帧与尾帧控制

Kling v3.0 Standard 和 Pro 生成 3 到 15 秒、720p 片段，支持 16:9、9:16 或 1:1，具备首帧与尾帧控制，音频可选。Standard 无音频 $0.084/s、含音频 $0.126/s；Pro 分别为 $0.112 和 $0.168。快手将 Pro 描述为更高视觉质量档。

Kling Video O1 生成 5 或 10 秒、720p 片段，帧角色相同，价格为 $0.112/s。当这两个时长中恰好有一个适合你的镜头时使用它。

### 单一起始帧、最长 15 秒的片段

Grok Imagine Video 1.5 生成 1 到 15 秒片段，支持 480p、720p 或 1080p 和七种宽高比。其 `supported_frame_images` 数组只列 `first_frame`，所以你能固定开场图像但固定不了结尾。模型描述称它会生成音效、环境声和对白。

较早的 Grok Imagine Video 止步 720p、每秒更便宜。其描述列出了最多七张参考图的参考生视频，而 1.5 的描述没有提及。

如果片段必须结束于另一张精确图像，请改用 Veo、Seedance 或 Kling。

## 提交一个图生视频任务

选定模型后，先确认源图像可以通过一个稳定、可直接下载的 HTTPS URL 访问，并且模型支持你需要的帧角色。

一个 URL 在你的浏览器里可用，provider 抓取时却可能失败——例如它依赖会话 cookie、经过 HTML 页面重定向，或挡在机器人校验之后。在花 credit 生成之前，直接检查这个 URL。

```
curl -I "$FIRST_FRAME_URL"
```

你要看到 `200` 状态码和 `image/jpeg`、`image/png` 或 `image/webp` 之类的图像 content type。

下面的示例用 `google/veo-3.1-lite` 生成一个 4 秒、720p 片段：提供图像为首帧，音频关闭。REST API 使用 snake_case 字段名，TypeScript SDK 会映射为 camelCase：`frame_images` 变成 `frameImages`，`frame_type` 变成 `frameType`，`image_url` 变成 `imageUrl`，`generate_audio` 变成 `generateAudio`。`first_frame`、`image_url` 这类取值保持不变。

示例还把 `{ retries: { strategy: "none" } }` 作为第二个参数传给 `generate`。默认情况下，SDK 会对返回 `5XX` 的请求以指数退避重试最多一小时。视频提交会启动计费工作：如果服务器接受了任务、却在你拿到 job ID 之前返回瞬时错误，自动重试会提交第二个付费任务，而客户端只能看到第二个。提交环节关闭重试后，失败的提交会以错误形式浮出，由你决定是否重新提交。这个单次调用级选项保留了只读 `getGeneration` 轮询调用的默认重试——重复轮询是安全的。

```
import { OpenRouter } from "@openrouter/sdk";

const apiKey = process.env.OPENROUTER_API_KEY;
const firstFrameUrl = process.env.FIRST_FRAME_URL;

if (!apiKey) {
  throw new Error("Set OPENROUTER_API_KEY first.");
}

if (!firstFrameUrl) {
  throw new Error("Set FIRST_FRAME_URL to a directly downloadable image URL.");
}

const openRouter = new OpenRouter({ apiKey });

const job = await openRouter.videoGeneration.generate(
  {
    videoGenerationRequest: {
      model: "google/veo-3.1-lite",
      prompt:
        "The camera slowly pushes in as the subject turns toward warm window light, cinematic, realistic motion",
      duration: 4,
      resolution: "720p",
      aspectRatio: "16:9",
      generateAudio: false,
      frameImages: [
        {
          type: "image_url",
          imageUrl: { url: firstFrameUrl },
          frameType: "first_frame",
        },
      ],
    },
  },
  { retries: { strategy: "none" } },
);

console.log(job.id, job.status);
```

成功的提交返回的是任务（job），不是成品 MP4。保存 job ID 并轮询 `GET /api/v1/videos/{jobId}`，直到状态变为 `completed`，然后在 `Authorization` 头带上你的 API key，从任务的 `unsigned_urls` 数组（SDK 暴露为 `unsignedUrls`）下载视频。状态为 `failed`、`cancelled` 或 `expired` 时停止轮询。我们的[视频生成指南](https://openrouter.ai/docs/guides/overview/multimodal/video-generation)建议轮询间隔 30 秒。

```
let current = job;

while (!["completed", "failed", "cancelled", "expired"].includes(current.status)) {
  await new Promise((resolve) => setTimeout(resolve, 30_000));
  current = await openRouter.videoGeneration.getGeneration({ jobId: job.id });
}

if (current.status !== "completed") {
  throw new Error(current.error ?? `Video generation ${current.status}.`);
}
```

如果模型支持传入尾帧，再加一个 `frameType: "last_frame"` 的 `frameImages` 条目。

```
frameImages: [
  {
    type: "image_url",
    imageUrl: { url: firstFrameUrl },
    frameType: "first_frame",
  },
  {
    type: "image_url",
    imageUrl: { url: lastFrameUrl },
    frameType: "last_frame",
  },
],
```

如果你的应用允许用户切换模型，请在构建请求前查询 `GET /api/v1/videos/models`。响应包含每个模型的 `supported_durations`、`supported_resolutions`、`supported_aspect_ratios`、`supported_frame_images`、`generate_audio` 标志和 `pricing_skus`。带不支持的时长、分辨率或宽高比的请求会返回一个列出支持值的 `400`。

## FAQ

### OpenRouter 上有哪些可用的图生视频模型？

视频目录包括 Veo 3.1 及其 Fast 与 Lite 变体、Seedance 2.5 与 Seedance 2.0 线、Kling v3.0 Standard 与 Pro、Kling Video O1，以及 Grok Imagine Video 1.5 与其前代等。当前集合见[视频模型合集](https://openrouter.ai/collections/video-models)和 `GET /api/v1/videos/models`。

### 图生视频与参考生视频有什么区别？

图生视频使用 `frame_images`，图像成为精确的第一帧、最后一帧或两者。参考生视频使用 `input_references`，模型把图像、视频或音频用作引导而不放在固定帧上。如果请求同时包含两个字段，`frame_images` 优先，我们按图生视频处理该请求。

### 图生视频生成的成本是多少？

多数视频模型按输出秒数计价，费率会随分辨率、是否生成音频、请求是否包含视频输入而变化。Seedance 模型按视频 token 计价。各模型页面列出当前费率，`GET /api/v1/videos/models` 返回每个模型的定价 SKU。

### 一个图生视频任务要跑多久？

视频生成是异步的。`POST /api/v1/videos` 立即返回一个任务，你轮询 `GET /api/v1/videos/{jobId}` 直到状态为 `completed`。我们的文档建议轮询间隔 30 秒。完成时间随模型、时长和分辨率而异。

### 视频生成任务失败了怎么办？

任务可能以 `failed`、`cancelled` 或 `expired` 结束。状态到达其中之一时停止轮询并读取 `error` 字段。轮询请求本身的瞬时错误不等于任务失败——请对同一 job ID 重试状态请求，而不是提交一个新的付费任务。
