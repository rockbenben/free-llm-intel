[Agent SDK](https://openrouter.ai/docs/sdks/typescript/call-model/overview) 支持第四种工具类型：**human-in-the-loop（HITL）工具**。它们让你的 agent 自动处理常规调用，而在风险高时暂停等待人工，全部由一个 hook 控制。

安装 SDK，定义你的 HITL 工具，然后按照 [cookbook 食谱](https://openrouter.ai/docs/cookbook/building-agents/hitl-tools)即可得到一个可运行的实现。

```
npm install @openrouter/agent
```

## 按调用决定：自动解决还是升级人工

普通工具总是执行，manual 工具总是暂停，HITL 工具两者皆可：由你的 `onToolCalled` hook 检查输入并做出决定。

```
import { tool } from '@openrouter/agent/tool';
import { z } from 'zod';

const approvePayment = tool({
  name: 'approve_payment',
  description: 'Approve a payment, escalating large amounts to a human',
  inputSchema: z.object({
    amount: z.number(),
    recipient: z.string(),
  }),
  outputSchema: z.object({
    approved: z.boolean(),
    reviewedAt: z.number().optional(),
  }),
  onToolCalled: async (input) => {
    if (input.amount < 100) {
      return { approved: true };
    }
    // Pause for human review
    return null;
  },
});
```

返回一个值，agent 就继续跑（像普通工具一样）。返回 `null`，循环就会以 `status: 'awaiting_hitl'` 暂停，把待处理的调用呈现给你的应用。恢复方式是把人类的决定作为 `function_call_output` 条目，再次调用 `callModel`。

这种模式适合任何决定取决于数据的场合：金额阈值、风险评分、内容政策标记、合规检查。分支逻辑集中在一个函数里，而不是散落在你的应用代码中。

## 在模型看到之前后处理人类的回复

可选的第二个 hook `onResponseReceived` 在人工为暂停的调用提供结果时触发。它在把结果传给模型之前对原始输入做转换。

```
onResponseReceived: async (raw) => {
  return { ...(raw as Record<string, unknown>), reviewedAt: Date.now() };
},
```

可以用它打元数据戳、规范格式、按业务规则校验，或补充人类无需手动提供的上下文。如果它抛出异常，错误会以 `{ error: ..., originalOutput: ... }` 的形式呈现给模型，不会有任何东西被静默吞掉。

## 暂停与恢复循环如何运作

完整生命周期如下：

- 模型在 agent 循环中调用你的 HITL 工具。
- 运行 `onToolCalled`。返回值则 agent 继续；返回 `null` 则循环暂停。
- 你的应用通过 `getToolCalls()` 读取待处理的调用并呈现给用户。
- 用户做出决定。
- 你把该决定作为 `function_call_output` 条目再次调用 `callModel`。
- `onResponseReceived`（如果定义了）对回复做转换。
- 模型收到结果，agent 循环恢复。

```
const result = openrouter.callModel({
  model: 'openai/gpt-4o',
  input: 'Pay $500 to Acme Corp for the May invoice',
  tools: [approvePayment] as const,
  state,
});

const response = await result.getResponse();

if (response.state?.status === 'awaiting_hitl') {
  const pending = response.state.pendingToolCalls ?? [];
  // Present pending[0] to your user, collect their decision, then resume:
  const resumed = openrouter.callModel({
    model: 'openai/gpt-4o',
    input: [{
      type: 'function_call_output' as const,
      callId: pending[0].id,
      output: JSON.stringify({ approved: true }),
    }],
    tools: [approvePayment] as const,
    state,
  });
}
```

SDK 处理了全部状态跟踪、hook 派发和 schema 校验。你没有写一行循环代码。

## 何时用 HITL，何时用 requireApproval

两者都会为人工输入而暂停。区别在决策逻辑。

|  | HITL (`onToolCalled`) | `requireApproval` |
| --- | --- | --- |
| **何时暂停** | 仅当你的 hook 返回 `null` | 总是，在执行之前 |
| **决策类型** | 数据驱动（阈值、评分、政策） | 二元的是/否同意 |
| **自动解决** | 返回值即可跳过人工审核 | 不支持 |
| **后处理** | `onResponseReceived` 转换回复 | 不支持 |

当每次调用无论输入如何都需要明确的人工同意时（想想“删除这个数据库”“发送这封邮件”），用 `requireApproval`。当某些调用可以自动继续、另一些需要人工时（想想“如果低于 $100 就自动批准这笔付款”），用 HITL。
