# Claude Code 要多少钱？按模型划分的实际会话成本

OpenRouter ·10/30/2026

![Claude Code 要多少钱？按模型划分的实际会话成本](https://openrouter.ai/blog/images/claude-code-cost.png)![Claude Code 要多少钱？按模型划分的实际会话成本](https://openrouter.ai/blog/images/claude-code-cost-dark.png)

Claude Code 免费安装。你要付费的是它调用的模型。如果你用 API key 运行 Claude Code，一场 2 到 9 轮的短会话在 Claude Opus 5.5 上的中位成本是 $0.31，而一场 10 到 49 轮的长会话是 $1.39。同样的会话在 Claude Sonnet 5.5 上分别是 $0.16 和 $0.60。

这些中位数来自 2026 年 10 月 18 日之前 30 天内 OpenRouter 上真实的 Claude Code 会话。[Claude Code](https://openrouter.ai/apps/claude-code) 在 10 月 21 日的每日应用排行中位列第一，因此背后有大量使用量。下文我们先用这些数据说明每个模型上一场会话要花多少钱，再讲如何在 OpenRouter 上运行 Claude Code，好让你为每场会话挑选模型、看到它实际花了多少，并给支出设上限。

## Tl;dr

- Claude Code 本身免费。你付费的是它调用的模型，付费方式要么是 Claude 订阅，要么是用 API key 按 token 计费。
- 用 API key 时，2 到 9 轮的会话中位成本在 Opus 5.5 上是 $0.31，在 Sonnet 5.5 上是 $0.16，在 Haiku 5.5 上不到一美分。
- 成本的大头是 Claude Code 自身的上下文：第一次请求把它写入 prompt cache，之后的每一轮再读回来。
- 把 Sonnet 设为默认，把后台任务和 sub-agent 都交给 Haiku，保持会话简短，并给 key 设一个额度上限。
- 用 `ori claude --model <model>` 在 OpenRouter 上运行 Claude Code，就能为每场会话选择模型。你的 Activity 页面会显示每场会话的真实花费。

## Claude Code 要花钱吗？

CLI 本身不要钱。它发出的每个请求都会打到一个模型上，而这些请求的付费方式有两种：Claude 订阅在用量限额之内把它们覆盖掉，API key 则按 token 计费。本文讲的是 API key 这条路，因为只有在这条路上你能看见并控制每场会话的花费。通过 OpenRouter，同一个 key 既能用于 Claude 系列模型，也能用于 Claude Code 可以调用的其他模型。

在 OpenRouter 上运行 Claude Code 最快的方式是 [Ori Harness](https://openrouter.ai/docs/guides/ori/harness)。它会启动你机器上已经装好的 Claude Code，把 OpenRouter 的配置就位，并通过浏览器完成登录，所以不需要粘贴任何 key：

```
curl -fsSL https://openrouter.ai/labs/ori/install.sh | bash
ori claude --model anthropic/claude-sonnet-5.5
```

只有你用 `ori claude` 启动的会话才跑在 OpenRouter 上。直接敲 `claude` 仍然用的是你的订阅。

## 一场 Claude Code 会话要花多少钱？

我们在[会话成本数据集](https://openrouter.ai/docs/api/api-reference/datasets/cost-per-session-by-harness-and-model)中，按模型和会话长度公布了 Claude Code 会话成本的中位数。下面是该数据集中的 Claude 模型，以及几款常用的替代模型：

| 模型 | 1 轮 | 2–9 轮 | 10–49 轮 |
| --- | --- | --- | --- |
| Claude Fable 5.1 | $0.342 | $1.049 | $3.734 |
| Claude Opus 5.5 | $0.136 | $0.305 | $1.390 |
| Claude Sonnet 5.5 | $0.071 | $0.155 | $0.596 |
| Claude Haiku 5.5 | $0.002 | $0.007 | $0.053 |
| Kimi K3 | $0.040 | $0.117 | $0.825 |
| GLM-5.3 | $0.010 | $0.044 | $0.363 |
| [DeepSeek V4.1 Flash](https://openrouter.ai/deepseek/deepseek-v4.1-flash) | $0.003 | $0.009 | $0.047 |
| GPT-6 Luna | $0.002 | $0.005 | $0.024 |

*2026 年 10 月 18 日之前 30 天内，按模型和轮数划分的每场 Claude Code 会话成本中位数。*

你选的模型对成本影响最大。一场单轮的 Fable 5.1 会话，比一场很长的 Haiku 5.5 会话还要贵。选定模型之后，会话长度就是最关键的因素。一场 10 到 49 轮的 Opus 会话大约是单轮会话的十倍，而 Sonnet 5.5 在每一种长度上都只有 Opus 5.5 的一半甚至更低。

## 为什么单轮会话要花 14 美分？

成本的大头是 Claude Code 自身的上下文，而不是你的 prompt。我们在一个空文件夹里、用 Claude Code 2.1.307 通过 OpenRouter 对着 Opus 5.5 跑了 `claude -p "Reply with exactly: ok"`。回复只有四个 token，但这场会话向 prompt cache 写入了 17,047 个 token。这些 token 是 Claude Code 的 system prompt 和工具定义。按 Opus 5.5 每百万 token $5 的缓存写入价计算，它们值 $0.085。真实项目还会加上自己的指令以及 Claude Code 读到的文件，这就是数据集中单轮中位数更高、为 $0.136 的原因。启动 token 的数量也会随 Claude Code 的版本和设置而变化。

一旦这些上下文进入缓存，后续请求就按每百万 token $0.20 把它读回来，比写入便宜 25 倍。这就是第一轮之后的每一轮新增费用都比第一轮低的原因。而随着上下文变大，费用会重新上升，因为 Claude Code 会把它读到的每个新文件一次性写入缓存，然后在此后的每一轮再读回来。我们的 [prompt 缓存指南](https://openrouter.ai/docs/guides/best-practices/prompt-caching)说明了写入与读取如何计费。

## 我们自己的会话花了多少？

数据集显示的是别人的会话花了多少。为了在一个我们可控的任务上比较模型，我们给 Claude Code 一个小型发票库，里面有三个 bug 和五个失败的测试。我们通过 OpenRouter 在每个模型上各跑三次，每一次都修好了全部三个 bug。

| 模型 | 每场会话中位成本 | 轮数 | 从缓存读取的 token | 写入缓存的 token |
| --- | --- | --- | --- | --- |
| Opus 5.5 | $0.098 | 5 | 111,000 | 9,800–10,300 |
| Sonnet 5.5 | $0.062 | 5 | 125,000–154,000 | 15,000–43,500 |
| Haiku 5.5 | $0.0052 | 6–8 | 126,000–199,000 | 16,400–45,800 |

这些成本低于数据集中 2 到 9 轮的中位数，有两个原因。一是我们的任务很小；二是每个模型的三场会话是紧挨着跑的，因此共用了一个热缓存。这也是 Opus 各次运行写入缓存的 token 比我们的单轮测试还少的原因。如果是真实项目上的一场全新会话，上面数据集中的中位数更值得参考。这些模型的先后顺序并没有变：Sonnet 大约是 Opus 的三分之二，Haiku 大约是 Sonnet 的十二分之一。

如果你自己去核验这类数字，不要依赖 Claude Code 自带的 `total_cost_usd`。它用的是 Anthropic 内置的价格表，遇到无法识别的 OpenRouter 模型名时就会猜。在我们的运行里，它对实际只花约半美分的 Haiku 会话报出 $0.16 到 $0.31，并把 Opus 会话高估了约 50%。你的 [Activity 页面](https://openrouter.ai/activity)显示的是你实际付了多少。如果想在 Claude Code 里面看累计总额，可以加上我们的[成本跟踪 statusline](https://openrouter.ai/docs/cookbook/coding-agents/claude-code-integration#cost-tracking-statusline)，它会从 OpenRouter 读取每场会话的支出。

## Claude Code 每月要多少钱？

把你运行的会话场次，乘以你典型会话长度对应的中位数。下面是三个例子，用的是数据集中的中位数和每月 22 个工作日：

| 用量 | Opus 5.5 | Sonnet 5.5 |
| --- | --- | --- |
| 轻量：每个工作日 5 场短会话（2–9 轮） | $34 | $17 |
| 常规：每个工作日 20 场短会话 | $134 | $68 |
| 重度：每个工作日 10 场长会话（10–49 轮） | $306 | $131 |

这些只是估算。你自己的会话会更贵或更便宜，取决于代码库的规模，以及 Claude Code 会读取其中多少内容。

## 怎样降低 Claude Code 的成本？

你能控制决定账单的那两件事：每场会话跑在哪个模型上，以及一场会话持续多久。

### 把 Sonnet 设为默认

如果你所有事情都用 Opus，把默认换成 Sonnet 大致能让账单减半。在我们的测试里，Sonnet 修好了同样的 bug。把 Opus 留给确实需要它的会话。

### 把后台工作和 sub-agent 交给 Haiku

Claude Code 会用一个快速模型来处理小型后台任务，也能把任务的部分内容交给 sub-agent。Haiku 5.5 通过了我们的 bug 修复测试，成本只是 Sonnet 的一小部分，所以这两类活儿都适合它。下面的设置会把 Sonnet 5.5 设为默认，并把后台任务和 sub-agent 路由到 Haiku 5.5：

```
export ANTHROPIC_BASE_URL="https://openrouter.ai/api"
export ANTHROPIC_AUTH_TOKEN="$OPENROUTER_API_KEY"
export ANTHROPIC_API_KEY=""
export ANTHROPIC_MODEL="anthropic/claude-sonnet-5.5"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="anthropic/claude-haiku-5.5"
export CLAUDE_CODE_SUBAGENT_MODEL="anthropic/claude-haiku-5.5"
```

前三行把 Claude Code 连到 OpenRouter；后三行设置模型。我们的 [Claude Code 集成指南](https://openrouter.ai/docs/cookbook/coding-agents/claude-code-integration)和[配置教程](https://openrouter.ai/blog/tutorials/claude-code-openrouter/)覆盖了其余的配置步骤。

### 保持会话简短

一场 10 到 49 轮的会话大约是 2 到 9 轮会话的四到五倍。当你转到一个不相关的任务时，开一场新会话，或者运行 `/compact`，而不是把旧上下文一路背着。

### 常规工作试试更便宜的模型

通过 OpenRouter，Claude Code 可以调用其他实验室的模型，而数据集显示确实有人在这么做。在每一种长度上，GLM-5.3 和 Kimi K3 的会话都比 Opus 会话便宜，我们的[在 OpenRouter 上拿到最低成本 LLM 推理](https://openrouter.ai/blog/tutorials/how-to-get-the-lowest-cost-llm-inference-on-openrouter/)指南讲了如何找到更便宜的选项。想试某一个，就把它传给 Ori Harness：

```
ori claude --model z-ai/glm-5.3
```

不过 Claude Code 是为 Anthropic 的模型构建的，所以在换成其他模型之前，先在你自己的任务上测一测。[Ori Eval](https://openrouter.ai/docs/guides/ori/eval) 可以代你做这件事：你的编程智能体会在你的项目里找出测试材料，用你想比较的模型跑一遍，然后连同分数和成本一起推荐一个。

### 设置支出上限

你可以给一个 API key 设置额度上限，这样失控的会话会在你选定的数字处停下。在组织里，带预算上限的 [guardrail](https://openrouter.ai/docs/guides/features/guardrails) 可以按天、周或月限制每个成员或每个 key，OpenRouter 对用 Ori Harness 启动的会话同样会执行它。在 Enterprise 套餐上，[工作区预算](https://openrouter.ai/docs/guides/features/workspaces/workspace-budgets)可以按天、周、月或整个周期限制[一个团队的全部支出](https://openrouter.ai/blog/insights/governing-team-ai-spend/)。

## 常见问题

### Claude Code 每个 token 多少钱？

Claude Code 的费用就是它调用的模型按 token 报的价。Claude Opus 5.5 是每百万输入 token $4、每百万输出 token $20、每百万写入 prompt cache 的 token $5、每百万从缓存读取的 token $0.20。Claude Sonnet 5.5 的费率是这些的一半。Claude Haiku 5.5 是每百万输入 token $0.10、每百万输出 token $0.50，缓存读取为每百万 $0.01。一场 Claude Code 会话的大部分 token 都是缓存读取。

### 用 Sonnet 还是 Opus 更便宜？

Sonnet 更便宜。在我们的会话成本数据里，Claude Sonnet 5.5 上的 Claude Code 会话在每一种会话长度上都只有 Claude Opus 5.5 上会话成本的一半左右。在我们自己的 bug 修复测试中，Sonnet 修好了和 Opus 一样的 bug。

### 我能用其他模型跑 Claude Code 吗？

可以。当你把 Claude Code 指向 OpenRouter，它就能调用其他实验室的模型。我们的会话成本数据里包含 GLM、Kimi、DeepSeek、Qwen 和 GPT 模型上的 Claude Code 会话。Claude Code 是为 Anthropic 的模型构建的，所以在换用别的模型之前，先在你自己的任务上测一测。

### 为什么我第一次 Claude Code 请求这么贵？

第一个请求会把 Claude Code 的 system prompt、工具定义和项目上下文写入 prompt cache。我们在空文件夹里用 Claude Opus 5.5 做的测试中，这部分约为 17,000 个 token，花掉约 $0.085，而真实项目会添加更多。后续请求从缓存读取同样的上下文，价格低得多——在 Opus 5.5 上低 25 倍。
