# 如何使用 OpenRouter 预设：配置即代码指南

OpenRouter ·9/10/2026 · 更新于 9/24/2026

你在一个 web 应用、一个批处理脚本和一个 notebook 里放了同一个模型名、同一个系统提示词和同一个 temperature。现在你想改 temperature 或模型，就得三处一起改。

我们造 preset（预设）正是解决这个问题。Preset 是给 LLM 调用的"配置即代码"：一份有名字、有版本的模型、系统提示词、提供商路由和采样参数集合。定义一次，到处用它的名字。preset 一改，每个用到它的应用都随之生效。

本文在 [presets 文档参考](https://openrouter.ai/docs/guides/features/presets)和[发布公告](https://openrouter.ai/blog/announcements/introducing-presets-manage-llm-configs-from-your-dashboard/)之外补充实践：你会创建一个 preset、在 API 调用里用它，并过两个配置——一个图像提示词增强 preset，和一个固定的 Fusion 配置。

## 太长不看

- 一个 preset 在同一个名字下存着模型或回退数组、系统提示词、提供商路由和采样参数。
- 在任何请求里用 `"model": "@preset/你的preset名"` 即可。
- 在控制台里更新它，每个使用它的应用都变了，不用改代码。

## OpenRouter Preset 是什么

OpenRouter preset 是一份有名字、有版本的配置，存着你的模型选择、一个系统提示词、提供商路由偏好和采样参数。我们通过 slug 让它可用于任何 API 请求，把你的 LLM 设置搬出应用代码。

把 preset 当作 `.env` 文件或 Terraform 模块来理解：配置住在应用逻辑之外，按名字引用而不是抄进去。区别在于它住在哪、谁能改。`.env` 仍然随你的仓库分发，更新需要重新部署；我们把 preset 存在 OpenRouter 控制台里，改一次，引用它的每个应用立刻生效。

[单个 preset 可以装](https://openrouter.ai/docs/guides/features/presets)：

- **模型选择**：一个模型，或一个有序的回退模型列表。
- **系统提示词**：每次请求前追加的指令。
- **提供商路由**：按价格或延迟排序，纳入或排除提供商。
- **采样参数**：temperature、`top_p` 等设置。
- **工具**：包括 [OpenRouter 服务器工具](https://openrouter.ai/docs/guides/features/server-tools)，如网页搜索、图像生成、顾问（advisors）和子 agent。

### Preset vs 硬编码请求体

|  | **硬编码请求** | **@preset/name** |
| --- | --- | --- |
| 配置住在哪 | 每个代码库里 | 控制台里一次 |
| 改系统提示词 | 每个应用改代码重新部署 | 改 preset，不重新部署 |
| 模型回退 | 每个地方重复那个数组 | 在 preset 里定义一次 |
| 谁能改 | 能发布代码的人 | 有控制台访问权的人 |

## 创建你的第一个 preset

### 第 1 步：打开 preset 编辑器

去 [openrouter.ai/settings/presets](https://openrouter.ai/settings/presets) 创建 preset。挑一个记得住的 slug，你会用它作为 `@preset/你的slug`。

![OpenRouter preset 编辑器，展示 Basic Info 区的名称、slug 和描述字段，preset 名为 image-enhancer](https://openrouter.ai/blog/images/presets-editor-basic-info.png)

### 第 2 步：选模型和路由

挑一个模型，或加一个[有序列表](https://openrouter.ai/docs/guides/routing/model-fallbacks)。第一个模型因限流、宕机或上下文超长失败时，我们试下一个。回退顺序在 preset 里设一次，不用每个请求重复。

![OpenRouter preset 编辑器，Models 区选中 Claude Opus 4.8，Provider Routing 区 sort 设为 latency](https://openrouter.ai/blog/images/presets-editor-models-routing.png)

[提供商路由](https://openrouter.ai/docs/guides/routing/provider-selection)也在这里设，如上屏所示。你可以[按价格或延迟排序](https://openrouter.ai/blog/insights/model-routing/)，或把某家提供商从你的请求中拉黑。

### 第 3 步：加系统提示词和采样设置

写下系统提示词，设好 temperature、`top_p` 及其他采样参数。它们成为使用这个 preset 的每个请求的默认值。

![OpenRouter preset 编辑器，System Prompt 字段写着把用户请求扩写成详细图像提示词的指令](https://openrouter.ai/blog/images/presets-editor-system-prompt.png)

### 第 4 步：在 API 调用里引用它

把 model 字段设成你的 preset。对比下面两个请求。

**之前，每个参数都写在请求里：**

```
from openrouter import OpenRouter

client = OpenRouter(api_key=OPENROUTER_API_KEY)

resp = client.chat.send(
    model="anthropic/claude-opus-4.8",
    provider={"sort": "price"},
    temperature=0.7,
    messages=[
        {"role": "system", "content": "You are a concise technical writer..."},
        {"role": "user", "content": "Explain preset versioning."},
    ],
)
```

**之后，一个 preset 引用：**

```
resp = client.chat.send(
    model="@preset/tech-writer",
    messages=[
        {"role": "user", "content": "Explain preset versioning."},
    ],
)
```

也可以通过 API 向 preset 端点发 POST 创建 preset。我们保存属于 preset 配置的字段，忽略 `messages`、`stream`、`prompt` 这类瞬态字段。

```
curl https://openrouter.ai/api/v1/presets/tech-writer/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-opus-4.8",
    "temperature": 0.7,
    "messages": [
      {"role": "system", "content": "You are a concise technical writer."}
    ]
  }'
```

每次请求可以覆盖 preset 设置。请求体里带了 `temperature`，这个值就压过 preset 值。合并是浅合并：请求字段替换 preset 中的对应字段，你没发的 preset 字段保留。`tools` 是例外：preset 的工具和请求的工具合并，同名时请求工具替换 preset 工具。也可以用独立的 preset 字段（`"preset": "@preset/tech-writer"`）或合并形态（`"model": "anthropic/claude-opus-4.8@preset/tech-writer"`）。`preset` 字段需要完整的 `@preset/` 前缀，裸 slug 会被忽略。

## 能设一个默认 preset 吗？

对 API 不能。Preset 有版本：保存已有 slug 会创建新版本并设为 active，但没有面向 API 的全局默认 preset——每个请求都必须点名 preset。Chatroom 倒是有个 Settings > Preferences 下的 Default Preset 设置，作用于新的聊天消息。

API 侧，把你的默认行为放进一个 preset，然后到处用它。想要短回答，就把这条规则写进 preset 的系统提示词（"除非被要求展开，回答不超过三句"）并设好采样参数。每个使用 `@preset/short-answers` 的服务都会遵守这些默认值，直到某个请求覆盖它。

按名字用 preset，给你的是"可在一处改变的稳定行为"。同一模式可扩展到更复杂的配置，下面两个实例。

## 用例 1：图像提示词增强 preset

图像模型通常在提示词详细时表现更好。与其每次手工加细节，不如在 preset 里[把文本模型和图像生成工具配对](https://openrouter.ai/docs/guides/features/server-tools/image-generation)：文本模型在提示词到达图像模型之前先加工它。

这个 preset 存一个文本模型、一条把简短请求变成覆盖主体、构图、光线、色板和风格的完整视觉简报的系统提示词，以及 image-generation 工具。

```
curl https://openrouter.ai/api/v1/presets/image-enhancer/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-opus-4.8",
    "messages": [
      {"role": "system", "content": "You are an expert visual prompt engineer. Expand the user request into a detailed image prompt covering subject, composition, lighting, palette, and style, then call the image tool."}
    ],
    "tools": [
      {"type": "openrouter:image_generation",
       "parameters": {"model": "google/gemini-3.1-flash-image"}}
    ],
    "tool_choice": "required",
    "temperature": 0.7
  }'
```

Preset 保存后，打开该 preset 选 "Test in Chat" 就能在 Chatroom 里直接测。发一条短提示词，比如"a cozy reading nook by a rainy window"（雨窗边的舒适阅读角），preset 会应用它的系统提示词和图像工具：文本模型把你的短提示词扩成完整视觉简报，再自动调用图像工具。效果如下。

![OpenRouter Chatroom 展示 image-enhancer preset 把提示词 'A cozy reading nook by a rainy window' 扩成详细视觉简报并生成一张写实图像](https://openrouter.ai/blog/images/presets-chat-demo.png)

Preset 连同模型、系统提示词和采样参数一起，也存着 `tools` 数组和 `tool_choice`。

每个使用 `@preset/image-enhancer` 的应用都拿到同样的行为。完整流程走查见 [preset-enhanced images cookbook](https://openrouter.ai/docs/cookbook/image-generation/preset-enhanced-images)。

## 用例 2：把 Fusion 配置钉成 preset

Fusion 配置在你的主力模型旁边跑一个模型评审团，主力模型用评审团的输出写最终回答。整套配置存进 preset，然后靠一个引用使用它。

把 `openrouter:fusion` 工具——连同其 `analysis_models` 评审团和分析师 `model`——存进 preset 的 tools，之后随处调 `@preset/fusion-panel`。你的 web 应用、评估工具和 Slack 机器人用的是同一个评审团。调整在控制台里做，不用改三个代码库。Fusion 配置的确切字段和评审团工作机制见 [Fusion 文档](https://openrouter.ai/docs/guides/features/server-tools/fusion)。

这也给 ML 工程师提供了一份可复现的评估配置：同一个稳定 slug 下同样的模型、采样设置和路由。

## 随时间管理 preset

每次用已有 slug 保存 preset，我们的系统就创建一个新版本并设为 active。使用该 preset 的 API 请求拿到 active 版本。

![三个 preset 版本依次排列的示意图：版本 3 标为 active 并接收 API 请求，一条标注 'restore an earlier version' 的虚线箭头指回版本 1](https://openrouter.ai/blog/images/presets-versioning.png)

在控制台里改系统提示词，用这个 slug 的每个应用在下一个请求就拿到变更，无需重新部署。改动伤到质量时，在控制台恢复某个早期版本，新请求立即使用它。

产品经理可以在控制台里改系统提示词或模型，不用请工程师改代码、发新构建。

## 跨应用、跨团队的 Preset

一个 preset 可以同时服务一个 API 集成、一个批处理任务和一个支持 OpenAI 兼容 API 的第三方应用。因为 preset 用标准 model 字段，任何能设模型字符串的客户端都能用。

[对更大的团队](https://openrouter.ai/blog/insights/governing-team-ai-spend/)，preset 给模型选择、路由和提示词一个有版本管理的家，替代散落在几个仓库里的常量。

组织账户下，所有成员都能访问组织 preset——跨团队分享最佳实践的好办法。

## 结论

三件事要记住：

- Preset 在同一个名字下存模型、系统提示词、路由规则和采样设置，请求里用 `@preset/name`。
- 更新 preset 改变每个使用它的应用，无需重新部署；必要时可以恢复早期版本。
- 同一份共享配置可以跨多个应用支撑图像提示词增强和 Fusion 评审团。

去 [openrouter.ai/settings/presets](https://openrouter.ai/settings/presets) 创建你的第一个 preset，然后试试 [preset-enhanced images cookbook](https://openrouter.ai/docs/cookbook/image-generation/preset-enhanced-images)。

## 常见问题

### OpenRouter 里怎么换模型？

在 [openrouter.ai/settings/presets](https://openrouter.ai/settings/presets) 里改 preset 的模型。每个使用 `@preset/你的preset名` 的调用，下一个请求就用新模型。不用 preset 的话，你得在每个请求体里改 model 字段。

### OpenRouter 的模型用量是什么？

我们给一个 API 端点，通 Anthropic、OpenAI、Google、Meta 等多家提供商的数百个模型。每个请求挑一个模型或用 preset，按各模型的 token 费率付费。当前选项和价格见[模型列表](https://openrouter.ai/models)。

### OpenRouter 的 API 限制是多少？

速率限制随模型和提供商而变，preset 不改变它们。Preset 只存配置——模型、提示词、路由和采样设置。无论用 preset 还是把参数直接写进请求，限制都一样。当前数字见[限制文档](https://openrouter.ai/docs/api_reference/limits)。

### OpenRouter 兼容 OpenAI 吗？

兼容。我们提供 OpenAI 兼容 API。Preset 用标准 model 字段，任何 OpenAI SDK 客户端设 `"model": "@preset/你的preset名"` 就能用。

### Preset 里能包含回退模型吗？

能。Preset 可以存一个有序模型列表。第一个因限流、宕机或上下文超长失败时，我们试下一个。顺序在 preset 里设一次，不用每个请求重复。

### 能按请求覆盖 preset 的设置吗？

能。请求体里的参数优先于 preset 值。合并是浅合并：请求字段替换 preset 对应字段，未发送的保留。工具则合并，同名时请求工具替换 preset 工具。

### Preset 走 API 还是只能在 Chatroom 里用？

Preset 通过 OpenAI 兼容 API 工作。model 字段里用 `@preset/slug`，或用独立的 `preset` 字段填 `@preset/slug`，或合并形态 `model@preset/slug`。
