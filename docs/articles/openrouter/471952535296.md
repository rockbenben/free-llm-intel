# OpenRouter 图像生成：代码优先 API 教程

OpenRouter ·8/17/2026 · 更新于 9/24/2026

给应用加图像生成，一旦需要支持不止一家提供商就开始变难。几十家提供商的众多图像模型用着不同的端点、数据格式、控制项和计费模型，按图片、百万像素或 token 收费不一而足。

我们用专用的 [Image generation API](https://openrouter.ai/docs/guides/overview/multimodal/image-generation) 解决这个集成问题：一种请求格式、一个 key，贯通所有受支持模型。

## 太长不看

- 一个 API、一个 key，经 `POST /api/v1/images` 触达受支持的图像模型。
- 缓冲响应把生成的图片放在 `data[0].b64_json`，你解码后保存到本地。
- 兼容的模型可通过 `input_references` 接受一张可选的参考图。

本指南你会搭出可运行的 Python 和 JavaScript 流程：发送提示词、解码并保存返回的图片，然后给端点传一张参考图、保存生成的变体。

## 前置条件

动手前备好这些：

- 一个有余额的 OpenRouter 账户。没有图像模型在免费档上，每次请求都消耗额度。API key 在第 1 步创建。
- Python 3 加 `requests` 包，或 Node 18+（内置 `fetch`）。

## 第 1 步：拿 key 并选一个图像模型

在 [keys 页面](https://openrouter.ai/settings/keys)创建 key，然后在你要跑脚本的同一个终端里导出它。

```
export OPENROUTER_API_KEY="sk-or-v1-..."
```

从[图像模型合集](https://openrouter.ai/collections/image-models)里选模型。第一次就用 `bytedance-seed/seedream-4.5`。

改模型字符串就能在各个支持图像的模型之间切换。分辨率、多输出、参考输入这类可选控制因模型而异，加之前先查能力记录。怎么按任务、参数支持和价格收窄目录，见[选择图像生成模型](https://openrouter.ai/blog/tutorials/image-generation-models/)。

运行时发现方面，`GET /api/v1/images/models` 返回支持图像的 slug 和支持的参数。每个模型还有带提供商特定能力与定价的端点记录。本教程用不到那些端点，但当脚本变成产品功能时它们很有用。

## 第 2 步：发出第一个图像请求

向 `https://openrouter.ai/api/v1/images` 发 POST 请求。Image API 需要两个请求体字段：`model` 选一个支持图像的模型，`prompt` 描述你要的图。认证用 Bearer 头里你的 OpenRouter key。

### Python

```
import os
import requests

response = requests.post(
    "https://openrouter.ai/api/v1/images",
    headers={
        "Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "bytedance-seed/seedream-4.5",
        "prompt": "A studio product photo of a matte black travel mug on a light gray background",
    },
    timeout=120,
)

if not response.ok:
    raise RuntimeError(f"{response.status_code}: {response.text}")

result = response.json()
```

解析之前先查 `response.ok`，能让 API 错误保持可见，而不是之后变成令人困惑的缺字段错误。

### JavaScript

```
const response = await fetch("https://openrouter.ai/api/v1/images", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.OPENROUTER_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "bytedance-seed/seedream-4.5",
    prompt: "A studio product photo of a matte black travel mug on a light gray background",
  }),
});

if (!response.ok) {
  throw new Error(`${response.status} ${await response.text()}`);
}

const result = await response.json();
```

显式的错误检查保住了响应体——里面通常正是你修正请求需要的细节。

### 图片在响应的哪里？

成功的缓冲响应是这个简化形态：

```
{
  "data": [
    {
      "b64_json": "iVBORw0KGgoAAA...",
      "media_type": "image/png"
    }
  ],
  "usage": {
    "cost": 0.0123
  }
}
```

示例成本只演示字段形态，不是当前价格。

`data` 是数组，因为一个请求可以返回多个结果。第一张图在 `data[0].b64_json`。那个值是 base64 编码的字节，不是托管 URL。`media_type` 在我们能识别输出格式时出现。可选的 `usage.cost` 在可用时报告这次完成请求的成本。

眼下，非空的 `b64_json` 就确认生成成功。下一步把这些字节变成本地图片文件。

## 第 3 步：解码并保存 output.png

响应说明生成成功了，但图片还是 JSON 里的 base64 文本。下一步把 `b64_json` 解码成字节、写到磁盘。下面两个脚本都重新发一遍请求，两个文件可以各自独立运行。

### Python

存为 `generate.py`：

```
import base64
import os
import requests

response = requests.post(
    "https://openrouter.ai/api/v1/images",
    headers={
        "Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "bytedance-seed/seedream-4.5",
        "prompt": "A studio product photo of a matte black travel mug on a light gray background",
    },
    timeout=120,
)

if not response.ok:
    raise RuntimeError(f"{response.status_code}: {response.text}")

result = response.json()
images = result.get("data") or []

if not images or not images[0].get("b64_json"):
    raise RuntimeError("The response did not contain image data")

image_bytes = base64.b64decode(images[0]["b64_json"])

with open("output.png", "wb") as output_file:
    output_file.write(image_bytes)

print("Saved output.png")

cost = result.get("usage", {}).get("cost")
if cost is not None:
    print(f"Request cost: ${cost}")
```

`base64.b64decode` 把响应字符串还原成原始二进制图像数据。用 `wb` 打开目标文件，防止 Python 把这些字节当文本处理。

### JavaScript

存为 `generate.mjs`：

```
import { writeFile } from "node:fs/promises";

const response = await fetch("https://openrouter.ai/api/v1/images", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.OPENROUTER_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    model: "bytedance-seed/seedream-4.5",
    prompt: "A studio product photo of a matte black travel mug on a light gray background",
  }),
});

if (!response.ok) {
  throw new Error(`${response.status} ${await response.text()}`);
}

const result = await response.json();

if (!result.data?.[0]?.b64_json) {
  throw new Error("The response did not contain image data");
}

await writeFile("output.png", Buffer.from(result.data[0].b64_json, "base64"));

console.log("Saved output.png");
if (result.usage?.cost !== undefined) {
  console.log(`Request cost: $${result.usage.cost}`);
}
```

`Buffer.from(..., "base64")` 做同样的转换，`writeFile` 保存 resulting 字节。

在文件所在目录运行任意一个：

```
python3 generate.py
```

JavaScript 用：

```
node generate.mjs
```

成功运行会打印 `Saved output.png`。成本那一行只在响应带 `usage.cost` 时出现。

输出格式随模型而变，有些模型返回 JPEG 或 WebP 字节而不是 PNG。格式对你的用途重要时，读响应里的 `media_type`、据此选文件扩展名。

## 第 4 步：加一张参考图

参考图给模型可依据的视觉材料，而不只靠提示词。它通过 `input_references` 传入。

本地文件：读字节、base64 编码、前面拼上正确的媒体类型做成 data URL。

把图片文件 `product.jpg` 放到脚本同目录，创建 `reference.py`：

```
import base64
import os

import requests

with open("product.jpg", "rb") as reference_file:
    reference_base64 = base64.b64encode(reference_file.read()).decode("utf-8")

reference_data_url = f"data:image/jpeg;base64,{reference_base64}"

response = requests.post(
    "https://openrouter.ai/api/v1/images",
    headers={
        "Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "openai/gpt-image-1",
        "prompt": (
            "Keep the product shape and materials. Place it on a warm stone "
            "surface with soft morning light and a clean commercial style."
        ),
        "input_references": [
            {
                "type": "image_url",
                "image_url": {
                    "url": reference_data_url,
                },
            }
        ],
    },
    timeout=120,
)

if not response.ok:
    raise RuntimeError(f"{response.status_code}: {response.text}")

result = response.json()
images = result.get("data") or []

if not images or not images[0].get("b64_json"):
    raise RuntimeError("The response did not contain image data")

variation_bytes = base64.b64decode(images[0]["b64_json"])

with open("variation.png", "wb") as output_file:
    output_file.write(variation_bytes)

print("Saved variation.png")
```

同目录运行：

```
python3 reference.py
```

这个模式很适合产品照变体：源图保住那个可辨认的物体，提示词改场景、光线或呈现方式。

参考图支持和可接受的参考数随模型端点而异。依赖这个特性之前，检查端点记录、确认 `input_references` 出现在 `supported_parameters` 里。

## 第 5 步：让请求可复用

请求稳定之后，把很少变的设置挪进一个本地配置文件：模型 slug、提供商路由、超时和输出目录放一起。提示词、参考图和用户控制留在请求里，让它们随每张图变化。

## 排障与成本说明

多数失败在你记录 HTTP 状态码、以及非 2xx 时的响应体之后会一目了然——在读任何图像字段之前。成功时跳过响应体，因为它整幅图都是 base64。下面五个是本教程请求可能撞到的。Image API 错误信息的完整清单和各自含义，见[模型指南的排障一节](https://openrouter.ai/blog/tutorials/image-generation-models/#how-do-i-fix-image-api-errors)。

- **缺 `data[0].b64_json`。**先看响应体。确认你向 `/api/v1/images` 发的是 POST、且选的是支持图像的模型。
- **401 响应。**确保进程能读到 `OPENROUTER_API_KEY`。不打印值地确认变量存在，然后从跑脚本的终端导出。
- **402 响应。**你的可用余额低于等于 Image API 每次请求前检查的固定 $1 下限——无论这张图本身多少钱。充过 $1 再重试。
- **参考请求失败。**确认模型支持 `input_references` 并检查图片 URL。本地 JPEG 必须用从 `data:image/jpeg;base64,` 开头的合法 data URL。
- **成本意外。**跑批之前先查端点定价。测试期间把 `usage.cost` 连同模型 slug 和输出文件名一起记录。

## 常见问题

### 能用 OpenRouter 生成图像吗？

能。向 `/api/v1/images` 发 POST，带一个支持图像的模型、一个提示词和你的 OpenRouter API key。响应含 base64 图像数据，解码后保存到本地即可。

### 怎么用 API 生成图像？

用 Bearer 头认证，发送模型和提示词。检查响应状态，解码 `data[0].b64_json`，把得到的字节写进图像文件。

### 怎么用提示词生成 AI 图像？

在提示词里描述主体、场景、构图、光线和风格。只有当兼容模型应当编辑或变体一张已有图片时，才用 `input_references`。

### 图像生成最好的 API 是哪个？

比较图像质量、控制项、参考图支持、延迟和定价。当你想要一个 API key、一种请求格式覆盖多个图像模型时，OpenRouter 最合适。
