# 开放权重模型与闭源权重模型：有什么区别？

OpenRouter ·10/31/2026

![开放权重模型与闭源权重模型：有什么区别？](https://openrouter.ai/blog/images/open-weight-vs-closed-weight-models.png)![开放权重模型与闭源权重模型：有什么区别？](https://openrouter.ai/blog/images/open-weight-vs-closed-weight-models-dark.png)

开放权重模型会把训练好的权重公开，任何人都能下载它、在自己的硬件上运行它、微调它，或者把它作为服务提供给别人。闭源权重模型不把权重公开，用它只能通过打造它的公司，或者它授权到的那几朵云。

在 OpenRouter 全站，开放权重模型占前 50 个模型 token 量的比例，从 2025 年 10 月的 27% 涨到了 2026 年 9 月底的 72%。

## 太长不看

- 开放权重模型会把权重公开，因此任何人都能运行、微调或对外提供服务。闭源权重模型只能从它的开发方以及它授权的云那里拿到。
- 2026 年 9 月底，OpenRouter 前 50 个模型的 token 有 72% 由开放权重模型承接，而一年前这个比例是 27%。
- 按 token 算它们的成本大约只有四分之一，这主要是因为许多 provider 在争着服务同一个模型。
- 最好的闭源权重模型在 Artificial Analysis Intelligence Index 上仍然高出约 11 分。先用一个开放权重模型起步、拿它做测试，只在确实需要的步骤上用闭源权重模型。

## 什么是开放权重模型？

模型的权重是它在训练中学到的那些数字，也就是你下载一个模型时下载到的东西。把它们公开（通常是在 Hugging Face 上），任何人都能运行这个模型。DeepSeek V4.1 Flash、GLM-5.3、Kimi K3 和 MiMo-V2.6-Pro 都是开放权重的。Claude、GPT 和 Gemini 系列模型是闭源权重的。

公开权重并不意味着你可以随意处置它们。许可证差别很大。正如我们在 [6 月的开放权重模型盘点](https://openrouter.ai/blog/insights/the-open-weight-models-that-matter-june-2026/)里提到的，DeepSeek V4 Flash 以 MIT 许可证发布，而 MiniMax M3 的社区许可证要求署名，并且要求规模较大的商业产品事先取得书面许可。在基于某个模型动工之前，先查它的许可证。

## 开放权重和开源有什么区别？

按 [Open Source Initiative](https://opensource.org/ai/open-weights) 意义上的开源，是指你能拿到研究和重建它所必需的一切：对一个模型来说，这包括训练数据（以及在数据因法律原因不能共享时的详细信息）、代码和权重。

多数开放权重模型并不发布训练数据，所以对它们而言「开放权重」是更准确的叫法。不过搜索结果和模型页面用词都很宽松，因此你看到「open-source LLM」时，它几乎总是指开放权重。

## 两类各能得到什么？

|  | 开放权重 | 闭源权重 |
| --- | --- | --- |
| 自己运行 | 可以，用你自己的 GPU | 不行 |
| 微调权重 | 可以 | 只能通过厂商的微调 API，前提是它有这个 API |
| 由谁来服务 | 任何人都行——热门模型在 OpenRouter 上有 20 到 31 个 provider | 厂商以及少数几家获授权的云 |
| OpenRouter 上的标价（按 token 加权，近 4 周） | 输入 $0.28 / 输出 $1.62 每百万 tokens | 输入 $1.27 / 输出 $6.36 每百万 tokens |
| Artificial Analysis Intelligence Index 最高分 | 46.3（MiMo-V2.6-Pro） | 57.6（Claude Opus 5.5） |

前两张行就是一些团队必须要开放权重的原因：他们的数据不能离开自己的基础设施，或者他们想要一个用自家数据微调出来的模型。对其他所有人来说，选择取决于最后三行，而通常是价格说了算。用量数据解释了原因。

## 开发者用开放权重模型用到什么量级了？

用量每个季度都在增长。2026 年初，[MIT Sloan 发表了一项研究](https://mitsloan.mit.edu/ideas-made-to-matter/ai-open-models-have-benefits-so-why-arent-they-more-widely-used)，基于 2025 年 5 月到 9 月的 OpenRouter 流量，发现闭源模型承接了将近 80% 的 token。我们自己 2025 年末的数据看起来也差不多，而此后变化很大。

我们按每周 token 量把 OpenRouter 前 50 的每一个模型都归类为开放权重或闭源权重，判据是它的目录条目是否链接到已公开的权重：

| 所在周 | 开放权重占比 | 开放权重 token | 闭源权重 token |
| --- | --- | --- | --- |
| 2025 年 10 月 6 日 | 26.8% | 1.3T | 3.4T |
| 2026 年 1 月 26 日 | 35.1% | 2.6T | 4.9T |
| 2026 年 4 月 20 日 | 47.7% | 8.9T | 9.8T |
| 2026 年 7 月 20 日 | 77.5% | 41.1T | 11.9T |
| 2026 年 9 月 28 日 | 71.7% | 83.5T | 33.0T |

两类都在增长。闭源权重的用量涨了将近十倍，从每周 3.4 万亿 token 涨到 33 万亿 token，而开放权重的用量涨了 60 倍还不止。开放占比在 7 月冲到 77.5% 的峰值，此后一直保持在三分之二以上。

近四周用得最多的开放权重模型是 DeepSeek V4.1 Flash、GLM-5.3 Flash、Hunyuan 4 Preview 和 DeepSeek V4 Flash。闭源这一侧，GPT-5.6 Luna 大幅领先，其后是 Gemini 3.8 Flash 和 GPT-6 Luna。两侧都是便宜、快的模型拿走大部分用量，而不是分数最高的那批。

## 开放权重模型更便宜吗？

通常是的。近四周，开放权重模型按 token 加权的价格是每百万输入 token $0.28、每百万输出 token $1.62。闭源权重模型则是 $1.27 和 $6.36，大约高出四倍。

主要原因是竞争。任何人都能服务一个开放权重模型，于是多家 provider 会为同一个模型在价格上竞争。下面是 2026 年 10 月 21 日 OpenRouter 上六个热门模型各有多少 provider 在服务，以及它们的输入价在各端点之间的跨度：

| 模型 | 权重 | Provider 数 | 输入价区间，每百万 tokens |
| --- | --- | --- | --- |
| z-ai/glm-5.3-flash | 开放 | 30 | $0.04 到 $1.15 |
| deepseek/deepseek-v4.1-flash | 开放 | 31 | $0.03 到 $0.60 |
| moonshotai/kimi-k3 | 开放 | 20 | $0.24 到 $4.50 |
| anthropic/claude-sonnet-5.5 | 闭源 | 5 | $2.00 到 $2.20 |
| openai/gpt-6-luna | 闭源 | 3 | $0.05 到 $0.20 |
| google/gemini-3.8-flash | 闭源 | 2 | $0.38 到 $1.35 |

开放权重模型的区间之所以宽，是因为各家 provider 的硬件、量化、速度和数据政策都不一样。最便宜的端点并不总是你想要的那一个，我们那篇[评估 provider 性能](https://openrouter.ai/blog/insights/evaluate-llm-provider-performance/)的指南讲了怎么比较它们。[Provider 路由](https://openrouter.ai/docs/guides/routing/provider-selection)可以让你[按价格排序](https://openrouter.ai/blog/tutorials/how-to-get-the-lowest-cost-llm-inference-on-openrouter/)、按量化或数据政策筛选，或者设一个价格上限。

这两个类别也有重叠。Kimi K3 最便宜的端点比 Claude Sonnet 5.5 还便宜，但它最贵的那个大约贵出两倍。GPT-6 Luna 的标价是每百万输入 token $0.10，比任何一家 Kimi K3 provider 收的都低。要比的是你在考虑的那些具体模型，而不是比类别。

做这种比较时我们的捷径是先设好价格上限，再把剩下的按吞吐量排序。只需要一个 `provider` 对象，`{"max_price": {"prompt": 1, "completion": 4}, "sort": "throughput"}`。超出你预算的端点会被剔除，而你能负担得起的最快的那个会先被尝试。

## 开放权重模型和闭源权重模型一样好吗？

价格是权衡的一半，另一半是质量。这一项上，开放权重模型还没站到最顶上。在 Artificial Analysis Intelligence Index 上——也就是经我们的[基准端点](https://openrouter.ai/docs/api/api-reference/benchmarks/list-benchmarks)汇总的数据——闭源权重的最高分是 Claude Opus 5.5 的 57.6 和 Claude Sonnet 5.5 的 56.0。开放权重的最高分是 MiMo-V2.6-Pro 的 46.3、GLM-5.3 的 44.8 和 Step 5 Preview 的 43.7，Kimi K3 以 43.6 紧随其后。每个分数都是模型在其最高 reasoning effort 设置下的成绩。

这个设置会挪动这些数字，所以要按你打算实际运行模型时用的 effort 来比较它们。

这 11 分的差距是在该指数所衡量的最难任务上、由两侧最强的模型拉开的，它并不能告诉你这个差距对你自己的工作负载有多要紧。我们那篇 [6 月盘点](https://openrouter.ai/blog/insights/the-open-weight-models-that-matter-june-2026/)在指数的较早版本上量出的是大约 5 分，所以请把确切的数字当作一次快照。

质量差 11 分、价格差 4 倍，我们的默认做法是用一个开放权重模型起步，并在你自己的任务上测试它。只有在测试显示多出来的质量会改变结果的那些步骤上，才换到闭源权重模型。那通常是一条工作流里最难的步骤，比如 agent 里的规划，而不是每一次调用。

## 怎么在同一个 app 里同时用上两者？

两类模型我们都通过同一个 API 提供，所以不用重写 app 就能混着用。在 `models` 数组里把闭源权重模型列在第一个，后面再列一个开放权重模型作为兜底。

我们那篇讲[模型路由如何工作](https://openrouter.ai/blog/insights/model-routing/)的指南解释了我们按什么顺序去尝试它们。这个请求还把价格上限设为每百万输入 token $1、每百万输出 token $4。Claude Sonnet 5.5 比这更贵，所以我们跳过它，把请求路由给 GLM-5.3 Flash：

```
import os
import requests

r = requests.post(
    "https://openrouter.ai/api/v1/chat/completions",
    headers={"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"},
    json={
        "models": ["anthropic/claude-sonnet-5.5", "z-ai/glm-5.3-flash"],
        # USD per million tokens
        "provider": {"max_price": {"prompt": 1, "completion": 4}},
        "messages": [
            {"role": "user", "content": "In one sentence: what is an open-weight model?"}
        ],
    },
    timeout=120,
)

data = r.json()
print(r.status_code, data.get("model"), data.get("provider"))
print(data["choices"][0]["message"]["content"] if "choices" in data else data)
print(f"${data.get('usage', {}).get('cost', 0):.6f}")
```

```
200 z-ai/glm-5.3-flash Relace
An open-weight model is a machine learning model whose trained parameters (weights) are publicly released for anyone to download, run, inspect, and fine-tune, though typically without the training data or full development details that would make it fully "open-source."
$0.000023
```

响应里的 `model` 字段显示是哪一个模型作出的回答，而计费就是按那个模型来算。如果你把 GLM-5.3 Flash 从这个列表里去掉，同一个请求就会失败，因为没有任何端点能满足这个上限：

```
404 {'error': {'message': 'No endpoints found that satisfy the max price for this request', 'code': 404,
  'metadata': {..., 'failed_routing_step': 'Filter by Max Price'}}}
```

价格上限只是触发条件之一。[模型兜底](https://openrouter.ai/docs/guides/routing/model-fallbacks)在遇到限流、宕机、上下文长度报错和审核拒绝时也会切到下一个模型。主用闭源权重、兜底用开放权重，这样即使主力厂商出了故障，你的 app 也照样能回答。

## 我们是怎么测的

本文里每一个用量、价格和基准数字都来自我们自己的 API，这一节说明我们如何拉取并分类它们。用量数字来自我们公开的[排行数据集](https://openrouter.ai/docs/api/api-reference/datasets/daily-token-totals-for-top-50-models)，它给出前 50 个模型的每周 token 总量。我们取的是 2025 年 10 月 6 日到 2026 年 9 月 28 日。只要一个模型的 OpenRouter 目录条目链接到某个 Hugging Face 仓库，我们就把它算作开放权重。对已经离开目录的退役模型，我们按发布方来分类，且只在发布方没有歧义时才这样判。

有两类用量没有计入这些占比。数据集里的「other」行汇总了前 50 之外的一切，它的量在每周 0.3 万亿到 10.8 万亿 token 之间。stealth 模型尚未公布，所以我们没法分类，而它们在最近一周达到了 38.7 万亿 token。token 计数来自各家 provider 自己的 tokenizer，所以适合用来比较趋势，但不是严格的同口径计数。按 token 加权的价格是 2026 年 10 月 8 日从我们的 models 和 endpoints API 取到的标价。provider 数量和价格区间是 2026 年 10 月 21 日拉取的。

## 常见问题

### Llama 是开源的吗？

Llama 是开放权重，按 Open Source Initiative 的定义并不算开源。Meta 公开权重但不公开训练数据，而且 Llama 许可证要求月活跃用户超过 7 亿的公司向 Meta 另行申请许可证。多数被描述为开源的 LLM 都是以同样的方式做到开放权重。

### 我可以免费运行开放权重模型吗？

在你自己的硬件上，模型是免费的，但 GPU 不是。走 API 的话，好几个开放权重模型在 OpenRouter 上有免费变体，并带有限流，我们的[免费 LLM API 对比](https://openrouter.ai/blog/tutorials/free-llm-apis-compared/)有覆盖。热门开放权重模型的付费端点，输入价从每百万 token 几美分起。

### 用开放权重模型我的数据会更安全吗？

只有当你自己运行它、数据从不离开你的服务器时才会。经过托管 provider 时，要紧的是那家 provider 的数据政策，跟它服务的是哪一类模型无关。在 OpenRouter 上，你可以按单次请求或整个账户，把请求限制在[零数据保留](https://openrouter.ai/docs/guides/features/zdr)端点，两类模型都适用。

### 我该从哪个开放权重模型开始？

我们会从 DeepSeek V4.1 Flash 开始。它是 OpenRouter 上用得最多的开放权重模型，而且有 31 家 provider 在服务它，所以[通过 OpenRouter 路由它](https://openrouter.ai/blog/insights/why-openrouter-for-deepseek/)能在某一家 provider 宕机时保持可用。它除文本外也接受图片。当你需要更强的能力时，试试 GLM-5.3 或 Kimi K3。[排行页面](https://openrouter.ai/rankings)显示开发者此刻在用哪些模型。
