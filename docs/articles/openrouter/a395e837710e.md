# ElevenLabs 现已上线 OpenRouter

Sasha Blumenfeld ·10/7/2026

ElevenLabs 已上线 OpenRouter，带来九个 Text to Speech 模型和两个 Speech to Text 模型。

如果你的应用已经通过 OpenRouter 调用语言模型，那它现在也能开口、也能听了。用 Eleven v4 为长内容做解说，并对语气和演绎下达指令；用 v4 Turbo 让智能体的语音回复更快；或用 Scribe v2 转写对话并标出说话人。你不需要另外买一个 ElevenLabs 套餐，只要用你的 OpenRouter API key 调用 `POST /api/v1/audio/speech` 和 `POST /api/v1/audio/transcriptions`。

*10 月 19 日 8am（太平洋时间）之前，所有 OpenRouter 客户调用任意 ElevenLabs 模型，都按 OpenRouter 标价的 50% 计费*

## 该用哪个模型

先从三个模型上手，等具体活儿需要时再取用其余的：

- **旁白、角色配音、产品视频：** Eleven v4。音频标签让脚本自己承载表演。
- **语音智能体和实时回复：** Eleven v4 Turbo，ElevenLabs 就是为实时场景造的它，费率是 v4 的一半。
- **转写稿、会议纪要、字幕：** Scribe v2，带说话人标签和逐词时间戳。

长音频需要控制语速时用 Multilingual v2；大批量语音、单次请求最多 40,000 字符时用 Flash v2.5。Scribe v2 Medical 针对医学术语做过微调。

### Text to Speech

| 模型 | OpenRouter ID | 单次请求最大字符数 | 适用于 |
| --- | --- | --- | --- |
| Eleven v4 | `elevenlabs/eleven-v4` | 10,000 | ElevenLabs 质量最高、最富情感的语音。富有表现力的旁白和角色演绎，支持 [whispering] 和 [laughing] 这类音频标签 |
| Eleven v4 Turbo | `elevenlabs/eleven-v4-turbo` | 10,000 | 语音智能体的低延迟回复 |
| Eleven v3 | `elevenlabs/eleven-v3` | 5,000 | 富有表现力/戏剧化的旁白与角色演绎，支持音频标签 |
| Eleven v3 Conversational | `elevenlabs/eleven-v3-conversational` | 5,000 | 一来一往的对话，费率是 v3 的一半。戏剧张力齐全，为实时对话调校过。 |
| Eleven Multilingual v2 | `elevenlabs/eleven-multilingual-v2` | 10,000 | 跨多种语言都稳定的长音频，带语速控制。 |
| Eleven Flash v2.5 | `elevenlabs/eleven-flash-v2.5` | 40,000 | 大批量下快速、低成本的多语言语音。可用语言 32 种。 |
| Eleven Flash v2 | `elevenlabs/eleven-flash-v2` | 30,000 | 快速的纯英语语音 |
| Eleven Turbo v2.5 | `elevenlabs/eleven-turbo-v2.5` | 40,000 | ElevenLabs 的第一代低延迟模型，现已被 Flash 取代 |
| Eleven Turbo v2 | `elevenlabs/eleven-turbo-v2` | 30,000 | ElevenLabs 的第一代低延迟模型，现已被 Flash 取代 |

ElevenLabs 的模型分两档计价。Eleven v4、v3 和 Multilingual v2 按每字符全价计费，v4 Turbo、v3 Conversational、Flash 和 Turbo 按半价计费。当前的每字符单价见 [Text to Speech 合集](https://openrouter.ai/collections/text-to-speech-models)里各模型的页面。

### Speech to Text

| 模型 | OpenRouter ID | 适用于 |
| --- | --- | --- |
| Scribe v2 | `elevenlabs/scribe-v2` | 通用转写，带逐词时间戳、说话人标签和音频事件标签，支持 90 多种语言 |
| Scribe v2 Medical | `elevenlabs/scribe-v2-medical` | 医学术语，在临床语音上比 Scribe v2 错误少 35% |

两个 Scribe 模型用同一种请求结构、同样的按秒单价。基于 WebSocket 的 Realtime Scribe v2 不在这次上线范围内。

## 实操：从第一个 MP3 到语音智能体

我们分三步做一个小的产品导览。先由 Eleven v4 为它解说，然后让一个语音智能体回答关于导览的问题，最后用 Scribe v2 把团队的评审会议变成一份能看出谁说了什么的纪要。如果有请求的行为不符合你的预期，看文末的提示。

先把 key 设好：

```
export OPENROUTER_API_KEY="your-api-key"
```

### 第 1 步：用 Eleven v4 为产品导览配音

先配一句解说：

```
curl https://openrouter.ai/api/v1/audio/speech \
  --fail-with-body \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "elevenlabs/eleven-v4",
    "input": "[cheerfully] Welcome to the tour. [whispering] Let me show you the shortcut first.",
    "voice": "george",
    "response_format": "mp3"
  }' \
  --output intro.mp3
```

`voice` 按名字接收 ElevenLabs 的 21 个预置音色中的任意一个（这里用的是 `george`）；名字不区分大小写。注意这里显式写了 `response_format`——这两点的缘由见**首批请求的提示**。

方括号里的词是音频标签。Eleven v4 和 v3 把 `[whispering]`、`[laughing]`、`[sighs]`、`[curious]` 这类标签当作演绎指令，而不是念出来。标签计入你的字符上限，也计入你付费的字符数。

完整的导览稿比一次请求能装的更长（v4 是 10,000 字符，v3 是 5,000），所以要按段落边界切开。只有 ElevenLabs 才有的设置放在 `provider.options.elevenlabs` 下面。把相邻的文本作为 `previous_text` 和 `next_text` 传过去，接缝处的语调才连贯；再固定一个 `seed`，重跑时结果更可复现：

```
import os

import requests

API = "https://openrouter.ai/api/v1"
HEADERS = {"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"}
NARRATOR = "george"


def split_paragraphs(text: str, limit: int = 9000) -> list[str]:
    chunks, current = [], ""
    for para in text.split("\n\n"):
        if current and len(current) + len(para) + 2 > limit:
            chunks.append(current)
            current = para
        else:
            current = f"{current}\n\n{para}" if current else para
    return chunks + [current] if current else chunks


chunks = split_paragraphs(open("tour-script.txt").read())

with open("tour.mp3", "wb") as out:
    for i, chunk in enumerate(chunks):
        options = {"seed": 7}
        if i > 0:
            options["previous_text"] = chunks[i - 1][-500:]
        if i + 1 < len(chunks):
            options["next_text"] = chunks[i + 1][:500]
        r = requests.post(
            f"{API}/audio/speech",
            headers=HEADERS,
            json={
                "model": "elevenlabs/eleven-v4",
                "input": chunk,
                "voice": NARRATOR,
                "response_format": "mp3",
                "provider": {"options": {"elevenlabs": options}},
            },
        )
        r.raise_for_status()
        out.write(r.content)
```

### 第 2 步：用语音智能体回答问题

现在让用户开口向导览提问。一个语音智能体把三个模型串起来：用 Scribe v2 处理提问，用一个聊天模型给出答案，再用 Eleven v4 Turbo 说出回复。ElevenLabs 造 v4 Turbo 就是为实时场景用的，计费是 v4 的一半。

```
import base64


def transcribe(path: str) -> str:
    with open(path, "rb") as f:
        audio_b64 = base64.b64encode(f.read()).decode()
    r = requests.post(
        f"{API}/audio/transcriptions",
        headers=HEADERS,
        json={
            "model": "elevenlabs/scribe-v2",
            "input_audio": {"data": audio_b64, "format": "wav"},
        },
    )
    r.raise_for_status()
    return r.json()["text"]


def answer(question: str) -> str:
    r = requests.post(
        f"{API}/chat/completions",
        headers=HEADERS,
        json={
            "model": "openai/gpt-5-mini",
            "messages": [
                {"role": "system", "content": "You are the product tour guide. Answer in one or two sentences."},
                {"role": "user", "content": question},
            ],
        },
    )
    r.raise_for_status()
    return r.json()["choices"][0]["message"]["content"]


def speak(text: str, out_path: str) -> None:
    r = requests.post(
        f"{API}/audio/speech",
        headers=HEADERS,
        json={
            "model": "elevenlabs/eleven-v4-turbo",
            "input": text,
            "voice": NARRATOR,
            "response_format": "mp3",
        },
    )
    r.raise_for_status()
    with open(out_path, "wb") as f:
        f.write(r.content)


speak(answer(transcribe("question.wav")), "reply.mp3")
```

转写的响应是一段 JSON，转写文本在 `text` 里，`usage` 对象会报出音频秒数和这次请求的美元 `cost`。把 `openai/gpt-5-mini` 换成 [目录](https://openrouter.ai/models)里的任意聊天模型，都不用改动音频调用；`voice` 保持不变，智能体听起来就还是第 1 步里的那位解说。

### 第 3 步：把评审会议变成带说话人标签的纪要

团队开会评审导览时，Scribe v2 能告诉你谁说了什么。用 multipart 上传录音，要求返回带逐词时间戳的 `verbose_json`，并在 `provider.options.elevenlabs` 下设置 `diarize`。这样响应里的每个词都带着一个说话人。如果你知道会里有几个人，就传 `num_speakers`，让切分更准。

```
curl https://openrouter.ai/api/v1/audio/transcriptions \
  --fail-with-body \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -F file="@tour-review.mp3" \
  -F model="elevenlabs/scribe-v2" \
  -F response_format="verbose_json" \
  -F "timestamp_granularities[]=word" \
  -F provider='{"options": {"elevenlabs": {"diarize": true, "num_speakers": 3, "tag_audio_events": true}}}'
```

`words` 里的每个条目都有 `word`、`start`、`end`、`confidence`、`speaker`（一个整数）和 `speaker_label`（`speaker_0`、`speaker_1`，依次类推）。`tag_audio_events` 会在词之间加上 `(laughter)` 这类条目。按 `speaker` 把连续的词归并成发言轮次，再把这些轮次交给聊天模型做摘要和行动项：

```
def to_turns(words: list[dict]) -> list[str]:
    turns: list[tuple[int, list[str]]] = []
    for w in words:
        if turns and turns[-1][0] == w.get("speaker"):
            turns[-1][1].append(w["word"])
        else:
            turns.append((w.get("speaker"), [w["word"]]))
    return [f"Speaker {s}: {' '.join(ws)}" for s, ws in turns]
```

上传上限是 25 MB，大约相当于 128 kbps MP3 的 27 分钟。

更长的录音可以传一个公开 URL，由 ElevenLabs 直接下载文件，这样就不受 25 MB 上限约束：

```
"input_audio":{ "url": "https://example.com/tour-review.mp3" }
```

特别长的文件仍可能撞上上游 180 秒的请求超时，所以时长很久的录音要切开。

## 首批请求的提示

- **按名字或 ID 选音色。**对于 `voice`，按名字传 ElevenLabs 的 21 个预置音色中任意一个：`george`、`sarah`、`adam`、`alice`、`bella`、`brian`、`charlie`、`daniel`、`jessica`、`roger`、`will`，还有更多（完整清单在各模型页面）。名字不区分大小写。要用其他音色，就把它的 ElevenLabs voice ID 作为 `voice` 传进来——从 [ElevenLabs 音色库](https://elevenlabs.io/app/voice-library)里复制。你自己克隆或设计的音色存在你自己的 ElevenLabs 账号里，要用那些得配 [BYOK](https://openrouter.ai/docs/guides/overview/auth/byok)。
- **想要能直接播放的文件就指定 `mp3`** 如果不写 `response_format`，我们的语音端点返回的是原始 PCM（24 kHz、16 位小端单声道）。这适合接进音频流水线，但大多数播放器打不开。设置 `"response_format": "mp3"`，拿到的就是可播放的 44.1 kHz、128 kbps 文件。
- **要控制语速就用 Multilingual v2 或 Flash** Multilingual v2 和 Flash 接受 0.7 到 1.2 的 `speed`。Eleven v4 和 v4 Turbo 没有语速控制，传入非默认的 `speed` 会被拒绝，所以在这两个模型上不要写它，改用音频标签来调整节奏。
- **长脚本要切开** 每个模型都有单次请求的字符上限（见模型表）。音频标签既计入上限，也计入你付费的字符数。像第 1 步那样按段落边界切开，并把 `previous_text` 和 `next_text` 传过去，接缝处才自然。
- **ElevenLabs 专属设置放在 `provider.options.elevenlabs` 下** Text to Speech 接受 `seed`、`previous_text`、`next_text`、`language_code`、`apply_text_normalization`、`apply_language_text_normalization`、`pronunciation_dictionary_locators`、`voice_settings`（`stability`、`similarity_boost`、`style`、`use_speaker_boost`、`speed`）和 `output_format`（ElevenLabs 的格式名，例如 `mp3_22050_32` 或 `pcm_16000`；它必须与你 `response_format` 的编解码器一致）。Speech to Text 接受 `diarize`、`num_speakers`、`diarization_threshold`、`tag_audio_events`、`no_verbatim` 和 `seed`。`num_speakers` 和 `diarization_threshold` 都需要 `diarize: true`，而且只能设其中一个，不能两个都设。字段名请照列出的原样使用。不在这两份清单里的键会被忽略；清单里的键给了错误的值会返回 400。
- **Scribe 返回三字母语言代码** 你可以传一个两字母的 `language` 提示（`en`）。检测到的语言以 ISO 639-3 代码返回（`eng`）。

## 开始使用

- 创建一个 [OpenRouter API key](https://openrouter.ai/settings/keys)。
- 用上面第 1 步的 curl 示例发出第一个请求。
- 所有参数见 [Text to Speech](https://openrouter.ai/docs/guides/overview/multimodal/tts) 和 [Speech to Text](https://openrouter.ai/docs/guides/overview/multimodal/stt) 指南。

Text to Speech 按输入字符计费，以 Unicode 码点计数，所以一个 emoji 或一个中日韩字符都只算一个。音频标签同样计入字符。Scribe 按音频秒数计费，每次转写响应里的 usage.cost 字段会告诉你这次请求花了多少。我们原样透传 ElevenLabs 的定价，不加价；当前单价见各模型页面。

*已经有 ElevenLabs 账号了？*

用 [BYOK](https://openrouter.ai/docs/guides/overview/auth/byok) 配上你的 key，就能使用你自己克隆的音色、发音词典，以及 mp3_44100_192 这类更高质量的格式。

创建一个 [OpenRouter API key](https://openrouter.ai/settings/keys)，或先在 [Playground](https://openrouter.ai/playground) 里试一个模型。[Text to Speech](https://openrouter.ai/docs/guides/overview/multimodal/tts) 和 [Speech to Text](https://openrouter.ai/docs/guides/overview/multimodal/stt) 指南有完整的请求参考。
