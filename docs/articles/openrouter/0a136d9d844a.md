# OpenRouter 与 LiteLLM：哪款 LLM 网关适合您的技术栈？

OpenRouter ·6/19/2026 · 更新于 9/24/2026

如果生产环境的网关要在 OpenRouter 和 LiteLLM 之间二选一，决策就归结为一件事：路由层应该跑在哪里。

两者都提供跨多家提供商的单一 OpenAI 兼容 API。OpenRouter 替你运营这一层，没有任何基础设施要管。LiteLLM 跑在你自己的基础设施里，数据留在你的网络上、也不用交平台费，代价是 PostgreSQL、Redis 和 Docker 都得你自己运维。

当数据不能离开你的网络、需要在自己基础设施内做基于角色的访问控制（RBAC），或者模型支出已经高到 5.5% 的平台费比自跑代理还贵时，选 LiteLLM。大多数其他情况更偏向托管方案。

## 先决定路由层住在哪

OpenRouter 站在你的应用和 70 多家提供商之间，运行在 Cloudflare 边缘。你的应用调用 `https://openrouter.ai/api/v1`，OpenRouter 施加路由和故障转移，再把请求转发给上游提供商。你不用管理任何服务器、数据库或各提供商的凭证。

LiteLLM 是你自己部署的代理，以 Docker 容器或 Kubernetes pod 的形态存在。它在你的网络内暴露同样的 OpenAI 兼容端点，把每个请求重写成提供商的原生格式再转发。PostgreSQL 存支出数据和 key；生产环境里 Redis 负责缓存和速率限制。这三样都得你来跑。

合规团队第一个问的就是这个差别。用 LiteLLM，请求数据在到达提供商之前从不离开你的网络。用 OpenRouter，请求会先经过一个托管层，所以有严格数据驻留规则的团队应当审查可用的路由和零数据保留（ZDR）控制。

```
OpenRouter:  app -> OpenRouter (Cloudflare edge) -> provider
LiteLLM:     app -> LiteLLM proxy (your infra: Docker + PostgreSQL) -> provider
```

## 两个网关各要花多少钱

OpenRouter 按 0% 加价透传提供商定价，然后对按量充值的额度收 [5.5% 平台费](https://openrouter.ai/pricing)，单笔最低 $0.80。自带 key（BYOK）在按套餐而定的免费额度之后，对等价的 OpenRouter 成本收 5% 费用；最新细则见[定价页](https://openrouter.ai/pricing)。失败的请求不计费。

LiteLLM 自托管免费，你付的是基础设施：PostgreSQL 数据库、可选的 Redis 和计算资源，生产部署通常是每月几百美元量级。[LiteLLM Enterprise](https://www.litellm.ai/enterprise) 增加 SSO、SCIM、RBAC、审计日志和 Prometheus 指标，定价走他们的销售团队。

临界点就是一道算术题。用你的月度基础设施成本除以 5.5% 费率。基础设施约每月 $200 时，模型支出超过约每月 $3,600，LiteLLM 就更便宜；基础设施每月 $500 时，这条线移到约每月 $9,100。低于这条线，托管费比跑代理的工程时间还划算。

## 对比路由、故障转移和延迟

OpenRouter 的默认路由就很好用。它的 [Auto Router](https://openrouter.ai/docs/guides/routing/routers/auto-router) 以市场智慧为动力，给每个提示词分类，再按 OpenRouter 社区过去滚动 7 天在该任务类型上的总支出给候选排名。提供商级路由会把[最近 30 秒](https://openrouter.ai/docs/features/provider-routing)出现过宕机的提供商降权。你可以用 provider 对象按价格、吞吐、延迟、数据政策、ZDR 和量化精度来约束路由。

LiteLLM 给你更多策略和完全自定义的逻辑。它内置六种路由模式：加权随机、基于延迟、感知速率限制、最空闲、最低成本，以及一个你自己写 Python 的自定义模式。回退列表让代理在一个模型失败时试下一个。需要按团队或按模型的规则在代理层强制执行时，LiteLLM 提供这些钩子。

延迟取决于你调得多勤。LiteLLM 自报在 4 实例（各 4 CPU、8GB）部署、对着 mock 端点测试时中位开销约 2ms（P95 8ms，P99 13ms）；降到 2 实例，中位开销升到约 12ms（[LiteLLM 自报基准](https://docs.litellm.ai/docs/benchmarks)）。OpenRouter 在 Cloudflare 边缘增加一个你不需要调优或扩容的网络跳转。一个是归你握的旋钮，一个是不归你的常数。

## 把合规需求和正确的网关对上

OpenRouter 带来第三方审计。它符合 SOC 2 Type 2，完整报告在 [trust.openrouter.ai](https://trust.openrouter.ai)，支持 GDPR，提供按请求或全账户的零数据保留，企业账户还能经由位于 EU 的提供商路由。Workspaces 在此之上增加按团队的组织、预算和成本归属。

LiteLLM 带来数据主权。因为是你自己托管，请求在到达提供商之前从不出你的基础设施，控制由你自己执行。LiteLLM Enterprise 增加 RBAC、SSO/JWT 认证、审计日志和按团队预算。它本身没有独立的 SOC 2、ISO 27001 或 HIPAA 认证，所以你的部署要自己负责达到这些标准。

## 两个都用，或者几行代码切换

两者并不互斥。LiteLLM 可以把 OpenRouter 当作上游提供商，这样你在本地享受 LiteLLM 的 RBAC 和日志，同时让 OpenRouter 处理多提供商故障转移和模型广度。

```
model_list:
  - model_name: or-claude
    litellm_params:
      model: openrouter/anthropic/claude-opus-4.6
      api_key: "your-openrouter-key"
      api_base: "https://openrouter.ai/api/v1"
  - model_name: or-gpt4o
    litellm_params:
      model: openrouter/openai/gpt-4o
      api_key: "your-openrouter-key"
      api_base: "https://openrouter.ai/api/v1"
```

反向切换只是改 base URL 和 key，因为两边都说 OpenAI 格式。

```
from openai import OpenAI

# OpenRouter
client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key="your-openrouter-key",
)

# LiteLLM
client = OpenAI(
    base_url="http://your-litellm-host:4000",
    api_key="your-litellm-master-key",
)
```

这样两个网关都能藏在同一个客户端后面。如果你不打算标准化到 OpenAI SDK，OpenRouter 也有自己的 SDK（Python 的 `openrouter`、TypeScript 的 `@openrouter/sdk`），原生调用 OpenRouter 一侧，不用设 base URL。

```
from openrouter import OpenRouter
import os

with OpenRouter(api_key=os.environ["OPENROUTER_API_KEY"]) as client:
    response = client.chat.send(
        model="anthropic/claude-opus-4.6",
        messages=[{"role": "user", "content": "Hello"}],
    )
```

如果你在比较的不止这两家，我们的 [LLM 网关对比](https://openrouter.ai/blog/insights/llm-gateway/) 覆盖了 Portkey、Helicone、Cloudflare AI Gateway 等更多选项。

## 常见问题

### LiteLLM 和 OpenRouter 是一类东西吗？

它们都提供跨多提供商的 OpenAI 兼容 API，但构建方式不同。LiteLLM 是你自托管的开源代理；OpenRouter 是运行在你不需要运营的基础设施上的托管网关。这个分野体现在数据驻留、运维开销和费用上。

### 能同时用 LiteLLM 和 OpenRouter 吗？

能。LiteLLM 支持把 OpenRouter 作为上游提供商，你可以在本地经 LiteLLM 路由做 RBAC 和审计日志，同时让 OpenRouter 负责多提供商故障转移和模型广度。

### OpenRouter 免费吗？

OpenRouter 有 20 多个免费模型可用于评估。付费用量按 0% 加价透传提供商定价，另对额度购买收 5.5% 平台费。自带 key 在按套餐而定的免费额度之后，对等价的 OpenRouter 成本收 5% 费用；最新细则见[定价页](https://openrouter.ai/pricing)。

### OpenRouter 会存储我的提示词吗？

默认不会。OpenRouter 不保留提示词或响应。零数据保留可以通过请求头按请求开启，也可以在设置里全账户开启。

### OpenRouter 和 LiteLLM 的延迟开销各是多少？

LiteLLM 自报在调优过的 4 实例部署、对 mock 端点测试时中位开销约 2ms；2 实例配置升到约 12ms。OpenRouter 增加一个 Cloudflare 边缘的网络跳转，不需要你自己调优或扩容。
