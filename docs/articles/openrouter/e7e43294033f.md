# MCP、CLI 与技能：各自的成本

开放路由器 ·11/11/2026

![MCP vs CLI vs Skills: 在上下文中各自的成本](https://openrouter.ai/blog/images/mcp-vs-cli-vs-skills.png)![MCP vs CLI vs Skills: 在上下文中各自的成本](https://openrouter.ai/blog/images/mcp-vs-cli-vs-skills-dark.png)

您为代理提供的每个工具都会根据每个请求将其定义发送到模型，并且您将其作为输入令牌进行支付。 [模型上下文协议](https://modelcontextprotocol.io/specation/2026-07-28/server/tools) (MCP) 服务器可以向上下文窗口添加数万个令牌。通常的替代方案是命令行工具 (CLI) 或 [skill](https://agentskills.io/specification)。

我们在 [Claude Haiku 5.5](https://openrouter.ai/anthropic/claude-haiku-5.5)、[Claude Sonnet] 上使用 [GitHub MCP 服务器](https://github.com/github/github-mcp-server)、[gh CLI](https://cli.github.com/manual/) 和 gh 技能在一项 GitHub 任务上进行了测量5.5](https://openrouter.ai/anthropic/claude-sonnet-5.5)、[GPT-6 Luna](https://openrouter.ai/openai/gpt-6-luna)和[Gemini 3.8 Flash](https://openrouter.ai/google/gemini-3.8-flash)。在 Sonnet 5.5 上，三个人都回答正确，但他们使用的输入标记却截然不同。 CLI 使用了 1,421 个，技能使用了 3,315 个，MCP 服务器在加载默认工具的情况下使用了 59,417 个。这是令牌的去向以及如何使用我们的[工具搜索](https://openrouter.ai/docs/guides/features/server-tools/tool-search)服务器工具来切割它们。

## 长篇大论；博士

- The GitHub MCP server’s 46 default tools add 19,436 tokens to every request on Claude Sonnet 5.5.
- 在 Sonnet 5.5 上，一个工具结果（GitHub 的发布对象）花费了约 20,400 个代币，超过了所有 46 个定义。
- Tool Search cut the up-front cost of 46 tools to under 600 tokens.在整个任务中，它将 Sonnet 5.5 的成本减少了一半，并在 Claude Haiku 5.5 上提高了成本。

## What is the difference between MCP, a CLI, and a skill?

这三者都赋予模型一种能力。 They differ in what the model reads before it can use it.

|  | **模型预先看到的内容** | **当它行动时它看到什么** |
| --- | --- | --- |
| MCP服务器| Every tool’s name, description, and JSON schema, on every request | The tool’s result, in whatever shape the server returns |
|命令行 |一个 shell 工具和一行表示 CLI 存在 |命令的输出，您可以使用诸如 —json | 之类的标志来调整输出
|技能|每项技能的一行描述 |技能的 SKILL.md 文件，一次，然后命令输出 |

A CLI relies on the model already knowing the tool. A skill teaches the model how to use a tool, and the model loads the full instructions only when a task needs them.

## How many tokens does an MCP server add to every request?

计算它们的可靠方法是询问模型。每个提供者在计算标记之前都以自己的格式将工具定义写入提示中，而本地标记生成器会忽略这一点。使用和不使用工具发送相同的请求，usage.prompt_tokens 的差异是工具每次的成本。

将其保存为 mcp_cost.py。它使用 GitHub 服务器接受的 MCP [2025-06-18 版本](https://modelcontextprotocol.io/specation/2025-06-18/basic/lifecycle)。
```
"""How many prompt tokens does an MCP server add to every request? Ask the model."""
import json
import os
import subprocess
import sys

import requests

API = "https://openrouter.ai/api/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"}

def list_mcp_tools(command):
    """Start a stdio MCP server, run the handshake, and return its tools/list result."""
    proc = subprocess.Popen(command, stdin=subprocess.PIPE, stdout=subprocess.PIPE,
                            stderr=subprocess.DEVNULL, text=True)

    def rpc(method, params, id=None):
        msg = {"jsonrpc": "2.0", "method": method, "params": params}
        if id is not None:
            msg["id"] = id
        proc.stdin.write(json.dumps(msg) + "\n")
        proc.stdin.flush()
        while id is not None:
            reply = json.loads(proc.stdout.readline())
            if reply.get("id") == id:
                return reply["result"]

    rpc("initialize", {"protocolVersion": "2025-06-18", "capabilities": {},
                       "clientInfo": {"name": "mcp-cost", "version": "1"}}, id=1)
    rpc("notifications/initialized", {})
    tools, cursor, id = [], None, 2
    while True:  # follow nextCursor so servers that paginate tools/list are fully counted
        page = rpc("tools/list", {"cursor": cursor} if cursor else {}, id=id)
        tools += page["tools"]
        cursor, id = page.get("nextCursor"), id + 1
        if not cursor:
            break
    proc.kill()
    return tools

def prompt_tokens(model, tools=None):
    body = {"model": model, "max_tokens": 16, "messages": [{"role": "user", "content": "Say ok."}]}
    if tools:
        body["tools"] = tools
    if model.startswith("google/"):
        # Google Vertex and Google AI Studio count the same tools differently, so pin one.
        body["provider"] = {"only": ["google-vertex"]}
    r = requests.post(API, headers=HEADERS, json=body, timeout=120)
    r.raise_for_status()
    return r.json()["usage"]["prompt_tokens"]

if __name__ == "__main__":
    mcp_tools = list_mcp_tools(sys.argv[1:])
    # What an MCP client sends the model: each tool's name, description and input schema.
    tools = [{"type": "function", "function": {"name": t["name"], "description": t.get("description", ""),
                                               "parameters": t["inputSchema"]}} for t in mcp_tools]
    print(f"{len(tools)} tools")
    for model in ["anthropic/claude-haiku-5.5", "openai/gpt-6-luna", "google/gemini-3.8-flash"]:
        added = prompt_tokens(model, tools) - prompt_tokens(model)
        print(f"{model:30} +{added:,} prompt tokens on every request")
```
将服务器的启动命令作为参数传递，如此处的 GitHub MCP 服务器 v2.0.2 所示。
```
$ python mcp_cost.py github-mcp-server stdio --toolsets=default
46 tools
anthropic/claude-haiku-5.5     +19,436 prompt tokens on every request
openai/gpt-6-luna              +8,903 prompt tokens on every request
google/gemini-3.8-flash        +8,525 prompt tokens on every request
```
成本随着您添加的每个工具而增加。在 Haiku 5.5 上，问题工具集有 10 个工具并添加了 5,801 个标记。用户工具集有一个工具，并添加了 619 个工具。

您使用的模型也会改变计数。同样的 46 个工具在 Haiku 5.5 上花费 19,436 个代币，但在 GPT-6 Luna 上花费 8,903 个代币，因此请根据您计划运行的模型进行衡量。

即使是为模型提供服务的提供商也可以更改它。在 Gemini 3.8 Flash 上，这 46 个工具通过 Google Vertex 花费了 8,525 个代币，通过 Google AI Studio 花费了 13,010 个代币。这就是为什么脚本总是向 Google Vertex 发送 Gemini 请求。

## 使用 CLI、技能和 MCP 执行相同任务的成本是多少？

我们询问每个模型，“GitHub 存储库 cli/cli 的最新版本是什么，该存储库中最近打开的带有标签 bug 的三个未解决问题是什么？”每种方法都作为工具调用循环在我们的 [Responses API](https://openrouter.ai/docs/api_reference/responses/overview) 上运行，并且我们在请求之间添加了 use.input_tokens。

- **CLI。** 一个 run_shell 工具和“GitHub CLI gh 已安装并经过身份验证”这一行。
- **技能。** 相同的工具，加上指向 gh 食谱的 1,492 个字符的 SKILL.md 的单行索引。
- **MCP.** 服务器的工具，范围为任务需要的 2 个，默认 46 个，或全部 91 个。

我们于 2026 年 10 月 20 日对每个组合运行了 3 次，并显示了中位数。 Haiku 5.5 与 Sonnet 5.5 一样计算提示，但在某些运行中需要额外的轮次，因此我们展示了 Sonnet 更稳定的标记和计费成本。

## 为什么 MCP 工具结果的成本与定义的成本一样高？

get_latest_release 返回了 GitHub 的完整发布对象，42,182 个字符，其中 87% 描述了 22 个下载文件。该模型需要标签和日期，这些都是 gh 发布视图返回的。
```
$ gh release view -R cli/cli --json tagName,publishedAt
{"publishedAt":"2026-09-30T02:40:02Z","tagName":"v2.102.0"}
```
该对象保留在上下文窗口中，并在以后的每个请求中重新发送，在 Sonnet 5.5 上它添加了大约 20,400 个标记。将服务器范围限定为两个工具将第一个请求从 19,487 个令牌减少到 1,406 个。整个任务还是花费了23,228。

该表显示了两个修复。首先，仅公开代理所需的工具，使用 —tools=get_latest_release,list_issues 或 —toolsets=issues,repos。其次，在模型看到结果之前缩小客户的结果。 4,000 个字符的上限使每次运行正确时范围路由达到 5,357 个令牌，因为 GitHub 将标签和日期放在顶部附近。

帽子之所以起作用，只是因为田地恰好位于这里。结合工具搜索，这一上限使得 Gemini 3.8 Flash 和 Haiku 5.5 在 3 次运行中各有一个正确答案，并且 Gemini 在重试时一度达到了 12 个请求的限制。

而是保留整个字段，就像 CLI 中的 —json 所做的那样。 GitHub 服务器的 list_issues 采用 fields 参数，并且仅要求编号、标题和创建日期，将其结果从 8,336 个字符减少到 714 个。没有它，模型将决定大小。在加载了 46 或 91 个工具的六次运行中的四次中，GPT-6 Luna 要求提供 100 个问题及其全文，并返回 281,963 个字符。

## Tool Search 是否解决了 MCP 的上下文问题？

工具搜索消除了工具定义的大部分成本。您将工具标记为 defer_loading: true 并添加 {“type”: “openrouter:tool_search”}。我们保留延迟的定义并发送搜索工具以及您留下加载的任何工具。该模型使用正则表达式搜索工具名称和描述，并在下一轮调用匹配。它处于测试阶段，可在响应和消息 API 上与[任何模型和提供商](https://openrouter.ai/docs/guides/features/server-tools/tool-search) 配合使用。

由于所有 46 个 GitHub 工具都被推迟，因此在 Claude 模型上进行任何搜索之前的成本为 578 个代币，在 GPT-6 Luna 上为 144 个代币，在 Gemini 3.8 Flash 上为 130 个代币。

该脚本发送一个问题，并加载所有 46 个工具，然后推迟。将其保存在 mcp_cost.py 旁边，因为它重用了 list_mcp_tools。
```
"""Send the same MCP tools with defer_loading and openrouter:tool_search, and compare prompt tokens."""
import os
import sys

import requests

from mcp_cost import list_mcp_tools

API = "https://openrouter.ai/api/v1/responses"
HEADERS = {"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"}
QUESTION = "What is the latest release of the GitHub repository cli/cli?"

def ask(model, tools):
    r = requests.post(API, headers=HEADERS, timeout=300,
                      json={"model": model, "input": QUESTION, "tools": tools})
    r.raise_for_status()
    return r.json()

mcp_tools = list_mcp_tools(sys.argv[1:])
# The Responses API takes function tools flat: type, name, description, parameters.
tools = [{"type": "function", "name": t["name"], "description": t.get("description", ""),
          "parameters": t["inputSchema"]} for t in mcp_tools]
deferred = [{"type": "openrouter:tool_search"}] + [{**t, "defer_loading": True} for t in tools]

for model in ["anthropic/claude-haiku-5.5", "openai/gpt-6-luna"]:
    for label, tool_list in [("all loaded", tools), ("tool search", deferred)]:
        res = ask(model, tool_list)
        steps = [f"search {o['query']!r}" if o["type"] == "openrouter:tool_search" else f"call {o['name']}"
                 for o in res["output"] if o["type"] in ("openrouter:tool_search", "function_call")]
        print(f"{model:28} {label:12} {res['usage']['input_tokens']:>6,} input tokens  {' -> '.join(steps)}")
```

工具搜索行随模型搜索方式的不同而变化。在该脚本的五次单独运行中，Haiku 5.5 使用了 2,134 到 13,225 个标记，并且随着每次搜索而增加。 GPT-6 Luna 编写了短语而不是模式，进行了三到六次搜索，并一度放弃而没有调用该工具。 [我们的文档](https://openrouter.ai/docs/guides/features/server-tools/tool-search)建议保持三到五个最常用的工具加载。

Haiku 5.5 包含 46 个延迟工具的成本比全部加载的成本更高。在所有三次运行中，它都会向 list_issues 询问该工具未提供的字段，然后使用错误类型的参数重试三到四次，例如标签作为字符串而不是数组。加载所有工具后，Haiku 在三次运行中有两次犯了同样的错误，并在下一次调用时修复了该错误。限制循环中的请求，并在运行成本跳跃时检查工具错误。

工具搜索通过扩大 tool_choice 来显示工具，因此强制工具调用的请求也会失败。

400 `tool_choice` 与 `openrouter:tool_search` 冲突。延迟工具通过“tool_choice”显示，因此必须省略或设置为“{“type”：“allowed_tools”，...}”。删除“tool_choice”，或从工具中删除“defer_loading”以按原样使用它。

聊天完成不接受 openrouter:tool_search 并返回 400，因此首先将该代理移至响应或消息 API。

## MCP、CLI 与技能：您应该使用哪个？

如果存在 CLI 并且您的代理可以运行命令，请使用 CLI。如果不能，请使用 MCP，范围有限且结果较小。

| **您的情况** | **使用** | **来自我们在 Sonnet 5.5 上的运行** |
| --- | --- | --- |
|存在众所周知的 CLI，代理可以运行命令 | CLI |每个任务 1,421 个代币 |
|您自己的 CLI，或者模型使用不一致的 CLI | CLI 加一项技能 | 3,315 个令牌，每次运行都使用相同的命令 |
|没有 CLI，没有 shell，或者您需要服务器的身份验证和权限 | MCP，涵盖您需要的工具 |使用 2 种工具可获取 23,228 个代币，而使用 46 个工具可获取 59,417 个代币 |
|跨多台服务器的大型工具库 |带工具搜索的 MCP |在 Sonnet 5.5 上，91 个延迟工具的成本与 46 个工具的成本相当 |
|任何 MCP 路线 |将工具结果修剪为您需要的字段 | 23,228 个代币减少至 5,357 个代币 |

如果您的代理没有 shell，我们的 [Shell 服务器工具](https://openrouter.ai/docs/guides/features/server-tools/shell) 会为任何模型提供沙盒模型。在我们的 Agent SDK 中，[MCP 工具](https://openrouter.ai/docs/agent-sdk/call-model/mcp-tools) 连接远程 MCP 服务器，[技能加载示例](https://openrouter.ai/docs/agent-sdk/call-model/examples/skills-loader) 仅在模型要求后添加技能指令。

我们在一项任务上测试了一台服务器，因此在您做出决定之前，请在您的服务器上运行 mcp_cost.py。

## 常见问题

### AI 代理上下文中的 CLI 是什么？

CLI（命令行界面）是使用键入命令运行的程序。代理获取 shell 工具并自行编写命令。在我们的测试中，gh CLI 在 GitHub 任务上使用了 1,421 个输入令牌，而 GitHub MCP 服务器则使用了 59,417 个输入令牌。

### MCP 服务器和连接器有什么区别？

MCP 服务器通过模型上下文协议公开工具。连接器是 Claude 等应用程序所称的到[远程 MCP 服务器](https://support.claude.com/en/articles/11175166-getting-started-with-custom-connectors-using-remote-mcp) 的链接。我们的 Agent SDK 可以通过 MCP Tools 连接远程 MCP 服务器。

### 技能会取代 MCP 吗？

不。技能是指令，通常用于 CLI，仅在任务需要时加载。 MCP 为类型化工具提供了自己的身份验证，并且无需 shell 即可工作。在 OpenRouter 上，工具搜索可让您保留 MCP 并仅在需要时加载每个工具。

### 提示缓存是否可以修复 MCP 的代币成本？

它降低了这些代币的价格，但并没有删除它们。截至 2026 年 10 月，根据我们的[实时模型价格](https://openrouter.ai/api/v1/models)，在 OpenRouter 上，[缓存输入](https://openrouter.ai/docs/guides/best-practices/prompt-caching) 的成本是 Claude Haiku 5.5 和 GPT-6 Luna 正常费率的十分之一，并且仍然填充上下文窗口。

### 多少个 MCP 工具才算太多？

我们的工具搜索文档建议，一旦定义传递了大约 10,000 个标记或大约 10 个工具，就推迟使用工具。 GitHub MCP 服务器的 46 个默认工具在 Claude 上获得了 19,436 个代币。
