OpenRouter workspaces 现在有了 **guardrails**：一整套可配置的安全与治理工具，用于预算强制、零数据保留（ZDR）、模型与服务商限制、prompt 注入防御和数据防泄漏。把这些规则逐层叠进一个 guardrail 来治理整个 workspace，或为团队成员组和 API key 创建定制化 guardrail——全程无需改代码。

前往主页面的 [Workspaces > Guardrails](https://openrouter.ai/workspaces)，或使用[管理 API](https://openrouter.ai/docs/api/api-reference/guardrails/create-guardrail)创建 guardrails。更多细节请[阅读文档](https://openrouter.ai/docs/guides/features/guardrails)。

## 预算强制

设置支出上限，可选每日、每周或每月的重置窗口。超出该时段限制的请求将以 `402` 响应失败。用它来封顶每个成员或每把密钥的支出，这样一个失控的脚本就烧不掉整月预算。

Guardrail 预算是按实体计的，不共享。把一个每天 $50 上限的 guardrail 分配给三名成员，每人各有自己的 $50 预算。API key 预算在成员预算之上独立叠加。如果 Audrey 的成员限额是每天 $100，她的密钥限额是每天 $30，那么该密钥封顶 $30，而 Audrey 在该 workspace 所有密钥的总花费封顶 $100。两者在每个请求上都会被检查。

## 零数据保留（ZDR）与模型/服务商限制

强制零数据保留（ZDR），让请求只路由到不存储你数据的端点；屏蔽个别模型或服务商；或把 workspace 限制在模型/服务商白名单内。每个端点都有自己的保留政策，ZDR 要求按模型组设置（Anthropic、OpenAI、Google、SpaceXAI 及所有其他模型），你可以全局要求，也可以只对有需要的组要求。不被允许的请求以 `404` 响应失败。用它把流量留在你审核过的服务商上，以及各项目应有的模型价格档位上。

你的[账户级隐私政策与服务商限制](https://openrouter.ai/settings/privacy)默认被继承。Guardrails 只能*更*严格。若只想对单个请求要求 ZDR，在请求体中设置 `"provider": {"zdr": true}`。[ZDR 文档](https://openrouter.ai/docs/guides/features/zdr)列出了按组的 guardrail 字段和所有 ZDR 端点。

## Prompt 注入防御

用一组源自 [OWASP LLM Prompt Injection Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) 及其他资料、超过 30 条的 regex 模式扫描输入，识别 prompt 注入与越狱企图。检测系统包含捕捉常见规避策略的技术：typoglycemia（字母错位）、编码类规避、字符加空格规避。它是确定性的，延迟开销可忽略。

检测发生在请求发送给模型服务商之前，因此被拦截的流量从不会离开 OpenRouter。用它捕捉常见的注入与越狱模式，尤其适用于原样传递用户输入的 agent。

检测到模式时可选择处理方式：

- **Flag：** 请求原样通过；检测结果仅为可观测性被记录，不做强制执行。适合在切换到 **redact** 或 **block** 之前评估对你流量的影响。
- **Redact：** 输入中被匹配的部分被替换为 **`[PROMPT_INJECTION]`**，净化后的请求发送给模型。
- **Block：** 整个请求在到达模型前被 **`403`** 拒绝。**`403`** 响应带有所检测模式类型的元数据。

阅读 [prompt 注入检测文档](https://openrouter.ai/docs/guides/features/guardrails/prompt-injection)。

## 数据防泄漏（DLP）

检测并处理请求中的 PII 及其他敏感信息。内置七种敏感信息类型。你也可以为领域特定数据（内部项目代号、专有 IP）添加自定义 regex 模式。每种都可配置为 **Redact**（脱敏）敏感信息或 **Block**（完全拒绝）请求。被阻止的请求返回 **`403`** 响应，携带检测到的内容类型信息。用它把 PII 和敏感标识挡在供应商日志之外，符合你的数据处理承诺。

多数内置模式和全部自定义模式使用正则匹配，是确定性的、几乎不增加延迟。姓名和地址通过 [Presidio](https://microsoft.github.io/presidio/) 使用自然语言处理（NLP），延迟与输入规模成比例。

| Built-in pattern | Method | Redacted as |
| --- | --- | --- |
| 电子邮箱 | Regex | `[EMAIL]` |
| 电话号码 | Regex | `[PHONE]` |
| 社会安全号 | Regex | `[SSN]` |
| 信用卡号 | Regex | `[CREDIT_CARD]` |
| IP 地址 | Regex | `[IP_ADDRESS]` |
| 人名 | NLP | `[PERSON_NAME]` |
| 地址 | NLP | `[ADDRESS]` |

阅读[敏感信息保护文档](https://openrouter.ai/docs/guides/features/guardrails/sensitive-info)。

## 分配给 API key 或组织成员

一个 guardrail 可以分配给多个 API key 或成员。分配到成员时，该 guardrail 适用于其在该 workspace 的所有密钥。

每个 workspace 都有一个你可以配置的默认 guardrail，适用于该 workspace 中的每个 API key 和成员。你可以创建额外的 guardrail，进一步限制特定的 API key 或成员。workspace 默认 guardrail 设定基线，任何额外 guardrail 在其上层叠加。

## 开始使用 guardrails

前往主页面的 [Workspaces > Guardrails](https://openrouter.ai/workspaces)，配置你的 workspace guardrail，或为特定 API key/成员创建 guardrails。

也可以编程配置。Management API 支持所有 guardrail 操作——创建、更新、删除、列表、分配给密钥或成员——让你能在团队入职或密钥轮换期间自动开通。

```
curl https://openrouter.ai/api/v1/guardrails \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "production-safety",
    "limit_usd": 100,
    "reset_interval": "daily",
    "allowed_models": [
      "anthropic/claude-sonnet-4.6",
      "openai/gpt-5.4",
      "google/gemini-3.1-pro-preview"
    ],
    "content_filter_builtins": [
      {"slug": "regex-prompt-injection", "action": "block"},
      {"slug": "email", "action": "redact"},
      {"slug": "credit-card", "action": "block"}
    ]
  }'
```
