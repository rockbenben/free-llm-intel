# 如何把 OpenRouter 接入任意编码智能体或 AI 工具

OpenRouter ·6/16/2026 · 更新于 9/24/2026

OpenRouter 挡在你的编码工具和它调用的模型提供商之间。请求照旧由你的工具发出，提供商关系、模型目录、用量可视性、计费和路由由 OpenRouter 在一个 API key 背后处理。

从你使用第二个工具、第二个模型、第二家提供商的那一刻起，这就重要了。没有它，你要为 OpenAI、Anthropic、Google 和其他每家各管一个 key、一块计费面板、一条配置路径。有了它，每个受支持的工具用的都是同一个 `sk-or-...` key、同一个模型 slug 格式、同一个 base URL。

一个工具接一次，之后换模型只需改一个字符串，所有支出在一处查看，某家提供商倒下时 agent 还能继续跑。下面是这套配置模式和已经会说这套语言的工具。

## 到处都适用的三步配置

任何会说 OpenAI Chat Completions API 的工具都能用 OpenRouter，因为 OpenRouter 暴露的就是同一个 API。你只改两个值——base URL 和 key，再选一个模型，代码其他部分原地不动。这一个端点挡在 70 多家提供商的 [300 多个模型](https://openrouter.ai/models)前面。

三步：

- **拿一个 key。**在你的 [keys 页面](https://openrouter.ai/keys)创建。OpenRouter 的 key 以 `sk-or-` 开头，工具靠这个前缀知道自己在跟 OpenRouter 说话而不是直连 OpenAI。存进环境变量，别写进源码。裸的 `sk-...` 是 OpenAI key，走不了路由。
- **把 base URL 指向** `https://openrouter.ai/api/v1`。API 兼容 OpenAI，官方 OpenAI SDK 只需替换这一个值就能工作。
- **挑一个模型 slug**，格式是 `provider/model`，如 `openai/gpt-4o` 或 `anthropic/claude-sonnet-4`。换模型要改的就只有这个 slug。目录在 [openrouter.ai/models](https://openrouter.ai/models)。

多数工具把这几个设置放在不同地方——环境变量、配置文件或设置界面——但值到哪都一样。同一个调用，三种写法：

```
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-4",
    "messages": [{"role": "user", "content": "Refactor this function."}]
  }'
```

```
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key=os.environ["OPENROUTER_API_KEY"],
)
resp = client.chat.completions.create(
    model="openai/gpt-4o",
    messages=[{"role": "user", "content": "Refactor this function."}],
)
```

```
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://openrouter.ai/api/v1",
  apiKey: process.env.OPENROUTER_API_KEY,
});
const resp = await client.chat.completions.create({
  model: "anthropic/claude-sonnet-4",
  messages: [{ role: "user", content: "Refactor this function." }],
});
```

后两个用的是 OpenAI SDK，多数项目里本来就装着。OpenRouter 自己也发 SDK，发同一个调用不用设 base URL：Python 的 `openrouter` 和 TypeScript 的 `@openrouter/sdk`。

```
from openrouter import OpenRouter
import os

with OpenRouter(api_key=os.environ["OPENROUTER_API_KEY"]) as client:
    resp = client.chat.send(
        model="anthropic/claude-sonnet-4",
        messages=[{"role": "user", "content": "Refactor this function."}],
    )
```

```
import { OpenRouter } from "@openrouter/sdk";

const client = new OpenRouter({
  apiKey: process.env.OPENROUTER_API_KEY,
});
const resp = await client.chat.send({
  model: "anthropic/claude-sonnet-4",
  messages: [{ role: "user", content: "Refactor this function." }],
});
```

两个可选的请求头 `HTTP-Referer` 和 `X-Title` 用来给你的应用打标签，它会因此出现在 OpenRouter 的排行榜里。一个能工作的请求不需要它们。细节见[应用署名](https://openrouter.ai/docs/app-attribution)。

## 路由如何让 agent 活下来

单一端点买来的不只是接入，还有路由——这对 agent 比对一次性脚本重要得多。

单次 API 调用失败很好办：捕获错误、重试。跑多步任务的 agent 就没这么宽容，因为它在多次调用之间持有状态。提供商在中途失败，可能留下半应用的一次编辑、一个永远没返回结果的工具调用，或者一份 agent 还以为是做完了的计划。当故障转移发生在路由层底下，agent 根本看不到这次失败——它拿到补全，继续干活。干这件事的机制有两个，可以叠加。

### 自动提供商故障转移

零配置。一个模型通常由多家提供商服务，OpenRouter 先试的那家宕机或对你限流时，它就把同一个模型路由给另一家服务的提供商。你只为落地的调用付费。

### 手动模型回退

这层需要你主动开启。你不指定备用提供商，而是指定备用模型：传一个 `models` 数组（用 OpenAI SDK 时放进 `extra_body={"models": [...]}`）。OpenRouter 先试主力，再依次试每个回退，按实际跑起来的那个模型计费，结果在响应的 `model` 字段返回。这覆盖了"某模型背后只有一家提供商、而它熄灯"的情形——那正是提供商级故障转移无处可路由的时刻。

连选都不想选的话，Auto Router（`openrouter/auto`）按提示词逐个挑模型：简单请求发给便宜模型，难题发给强模型。选中谁就按谁的标准费率付费，没有额外路由费。原型阶段、还没弄清哪个模型适配任务时，它很好用。

## 用 SDK 构建你自己的 agent

如果你是把现成工具接进来，上面的步骤就够了。如果你要自己写 agent，OpenRouter 给你两个 SDK。

[Client SDK](https://openrouter.ai/docs/client-sdks/overview)（TypeScript 和 Python）是 REST API 之上的薄类型安全层：生成类型和自动补全，取代手写 HTTP。

[Agent SDK](https://openrouter.ai/docs/agent-sdk/overview) 替你跑循环。一个 `callModel` 原语管多轮对话、执行你的工具、跟踪状态。轮次之间可以换模型，所以"读个文件"这种便宜步骤可以走便宜模型，代码生成走更强的模型，全在同一个循环里。

下面是带工具调用的形态。这一次 `callModel` 调用发出提示词，让模型调 `get_weather`，执行它，把结果喂回去，返回最终文本。

```
import { callModel, tool } from "@openrouter/agent";
import { z } from "zod";

const weatherTool = tool({
  name: "get_weather",
  description: "Get the current weather for a location",
  inputSchema: z.object({ location: z.string() }),
  execute: async ({ location }) => ({ temperature: 72, condition: "sunny", location }),
});

const result = await callModel({
  model: "anthropic/claude-sonnet-4",
  messages: [{ role: "user", content: "What is the weather in San Francisco?" }],
  tools: [weatherTool],
});

const text = await result.getText();
```

## 成本与速率限制

OpenRouter 有免费档。[20 多个模型](https://openrouter.ai/models?max_price=0)按 $0 运行，每天上限 50 次请求、每分钟 20 次；充值 $10 后每天升到 1,000 次。指望它之前有两个注意点：失败的尝试照样消耗每日配额，热门免费模型在高峰期可能被上游提供商限流。即便如此，它已经够你在一分钱推理费不花的情况下把一个 agent 从头到尾走一遍。

付费用量上，OpenRouter 不给模型定价加价。你付的每 token 单价和直接付给提供商的一样——就是[模型目录](https://openrouter.ai/models)显示的价格。在此之外，额度购买收 5.5% 手续费，最低 $0.80。所以推理保持在提供商价，OpenRouter 抽的就是额度那笔手续费。当前数字在[定价页](https://openrouter.ai/pricing)；[Activity 面板](https://openrouter.ai/activity)实时显示每个请求的模型和成本，是发现"agent 在用比任务需要的更重的模型烧额度"的最快方式。

## 常见问题

### 每个工具需要一个单独的 API key 吗？

不需要。一个 OpenRouter key 在这份清单的每个工具里通用。在 [openrouter.ai/keys](https://openrouter.ai/keys) 生成一次，把同一个 `sk-or-...` 贴进 Claude Code、Codex CLI、Cursor 或任何其他受支持的工具。

### OpenRouter 能配 OpenAI SDK 用吗？

能。把 `base_url`（Python）或 `baseURL`（TypeScript）指向 `https://openrouter.ai/api/v1`，传入你的 OpenRouter key。OpenRouter 是 OpenAI Chat API 的直接替代品，官方 SDK 不需要任何其他改动。

### 怎么免费使用 OpenRouter？

用免费模型、待在免费档限额内。免费模型——[模型页](https://openrouter.ai/models?max_price=0)上的 `:free` 变体——每天最多 50 次请求，充值 $10 额度后升到每天 1,000 次。

### 能在 VS Code 里用 OpenRouter 吗？

能。用暴露了 OpenRouter 提供商的 agent 扩展（如 Cline 或 Kilo Code），或任何允许设置自定义 OpenAI base URL 的扩展。base URL 设为 `https://openrouter.ai/api/v1`，贴上 key，选个模型。

### OpenRouter 的模型 slug 是什么格式？

格式是 `provider/model`，例如 `openai/gpt-4o` 或 `anthropic/claude-sonnet-4`。在作者前加 `~`，如 `~anthropic/claude-sonnet-latest`，永远解析到该家族最新版本。完整清单在 [openrouter.ai/models](https://openrouter.ai/models)。

### OpenRouter 会记录我的代码或提示词吗？

默认不记录，请求出错也不记录，除非你明确开启。有一个可选开关，用记录换一点用量折扣。细节见[隐私政策](https://openrouter.ai/privacy)。
