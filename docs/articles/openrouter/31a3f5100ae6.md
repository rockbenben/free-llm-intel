# 管理密钥的访问控制更加严格

Sasha Blumenfeld ·11/16/2026

![管理密钥的访问控制更加严格](https://openrouter.ai/blog/images/scoped-management-keys.png)![管理密钥的访问控制更加严格](https://openrouter.ai/blog/images/scoped-management-keys-dark.png)

管理密钥不再必须拥有整个组织的完整管理员权限。现在，你可以将密钥设为只读、限制其只能访问一个工作区，或同时设置这两项限制，从而让每个密钥只能执行其创建时指定的任务。只读密钥可以查看 API 密钥、活动和用量；读写密钥还可以创建、更新和删除 API 密钥。如果密钥泄露或被滥用，损害范围仍可被控制在限定范围内。

即日起，所有组织、所有套餐均可使用此功能。你可以从工作区的 Keys 页面或 [Management API Keys](https://openrouter.ai/settings/management-keys) 页面创建密钥，并查阅[管理 API 密钥指南](https://openrouter.ai/docs/guides/overview/auth/management-api-keys)，了解每种密钥可以调用哪些路由。

![“创建管理密钥”对话框，作用范围限定为 Production 工作区，填写了名称、90 天有效期，并在访问级别下选择了“只读”](https://openrouter.ai/blog/images/scoped-management-keys/create-management-key-dialog.png)

## 团队运营自己的工作区，现在他们的自动化也能如此

随着组织在 OpenRouter 上发展壮大，它们会将工作拆分到多个工作区，通常每个团队一个工作区。每个团队运营自己的工作区，组织管理员则负责管理所有人共用的内容：额度、预算和组织设置。

在此之前，管理密钥始终拥有整个组织的完整读写权限。想要自动化自己工作区的团队，不得不使用一个能够访问其他所有工作区的密钥。

现在，每个密钥有两个设置。[*作用范围*](https://openrouter.ai/docs/guides/overview/auth/management-api-keys#scope)决定密钥在何处生效：一个工作区，还是整个组织。[*访问级别*](https://openrouter.ai/docs/guides/overview/auth/management-api-keys#permissions)决定密钥在该范围内能做什么：只读，还是读写。工作区管理员可以为自己所在的工作区创建密钥，因此部署流水线可以轮换团队的 API 密钥，agent 可以设置 guardrails，脚本可以将队友添加到工作区，而这些操作都不会触及另一个团队的工作区。

## 作用范围将密钥限制在一个工作区内

限定到工作区的密钥只能在其所属工作区中生效。如果请求指定了另一个工作区，或指定了属于另一个工作区的资源，OpenRouter 会拒绝访问。有缺陷的 agent 或泄露的密钥无法触及组织的其他部分。

在其工作区内，该密钥可以管理 API 密钥、成员、guardrails 与 guardrail 策略、你自己的提供商密钥、可观测性目标以及预设。它可以读取该工作区的预算、活动和分析数据。

**预算限额、额度与组织设置仍由组织管理员掌控。** 团队可以自动化其工作区内的一切，但仍然无法提高自己工作区的预算。设置工作区预算、创建或删除工作区、管理组织成员以及私有端点，仍然需要组织级密钥，其工作方式一如既往。

## 只读访问让工具只能查看，不能更改任何内容

访问级别是第二个设置，它同样适用于工作区密钥和组织级密钥。只读密钥可以调用其作用范围允许的读取路由，包括分析查询。任何会创建、更改或删除内容的请求都会返回错误。

这适合那些只需要查看的工具。成本仪表板可以拉取用量数据，监控 agent 可以观察活动，审计脚本可以列出密钥、guardrails 和提供商密钥。你可以接入新的报表或审计工具，而无需授予其写入账户的权限。

## 为每项任务分配一个仅具备所需权限的密钥

作用范围和访问级别组合起来，形成四种密钥：

- 为某个团队创建和轮换 API 密钥的 agent，获得该团队工作区的读写密钥。
- 某个团队的用量仪表板，获得该团队工作区的只读密钥。
- 组织范围的审计或成本工具，获得组织级只读密钥。
- 任何创建工作区或设置预算限额的工具，继续使用组织级读写密钥。

这两个设置在你创建密钥时固定下来，因此密钥之后无法获得更多访问权限。若要更改其中任一设置，请创建新密钥并删除旧密钥。

## 在仪表板中创建密钥

![工作区 Keys 页面上的“管理密钥”标签页，列出了三个密钥及其访问级别、有效期和状态，并有一个“新建管理密钥”按钮](https://openrouter.ai/blog/images/scoped-management-keys/workspace-management-keys-tab.png)

- 打开工作区，进入 **Keys**，选择 **Management keys** 标签页。工作区管理员可以为自己所在的工作区创建密钥，组织管理员可以为任意工作区创建密钥。
- 点击 **New management key**。对话框会显示该密钥限定到哪个工作区。
- 输入名称，选择有效期，并在 **Access level** 下选择 **Read only** 或 **Read and write**。
- 密钥显示出来时请立即复制。之后你将无法再次看到它。

若要创建覆盖整个组织的密钥，组织管理员可使用 [Management API Keys](https://openrouter.ai/settings/management-keys) 页面。

你的 agent 和工具使用该密钥的方式与今天使用管理密钥相同：将其作为管理 API 上的 Bearer token：

```
curl https://openrouter.ai/api/v1/keys \
  -H "Authorization: Bearer $MANAGEMENT_KEY"
```

要查看你已有的管理密钥，请打开 [Security settings](https://openrouter.ai/settings/security)，进入 **Key safety**，打开 **Filter keys**，然后选择 **Show management keys**。每个有效密钥都会列出其所有者、最后使用时间和有效期。[管理 API 密钥指南](https://openrouter.ai/docs/guides/overview/auth/management-api-keys)列出了每种密钥可以调用的所有路由。
