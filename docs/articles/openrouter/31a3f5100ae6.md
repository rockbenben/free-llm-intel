# 管理密钥的访问控制收紧

Sasha Blumenfeld ·11/16/2026

![管理密钥的访问控制收紧](https://openrouter.ai/blog/images/scoped-management-keys.png)![管理密钥的访问控制收紧](https://openrouter.ai/blog/images/scoped-management-keys-dark.png)

管理密钥不再必须附带整个组织的完整管理员权限。现在你可以把一把密钥设为只读、限制在单个工作区，或者两者同时设，让每把密钥只做它被创建时该做的事。只读密钥可以查看 API 密钥、活动和用量，读写密钥还可以创建、更新和删除 API 密钥。密钥一旦泄露或被误用，影响范围也被圈在里面。

即日起所有组织、所有套餐均可用。你可以从工作区的 Keys 页面或 [Management API Keys](https://openrouter.ai/settings/management-keys) 创建密钥；每种密钥能调用哪些路由，请看[管理 API 密钥指南](https://openrouter.ai/docs/guides/overview/auth/management-api-keys)。

![“创建管理密钥”对话框，作用域为 Production 工作区，包含名称、90 天有效期，访问级别下选中 Read only](https://openrouter.ai/blog/images/scoped-management-keys/create-management-key-dialog.png)

## 团队自己运营工作区，现在他们的自动化也可以

组织在 OpenRouter 上长大，就会把工作拆进工作区，通常一个团队一个。每个团队运营自己的工作区，组织管理员则照看所有人共用的东西：额度、预算和组织设置。

在此之前，管理密钥总是拥有整个组织的完整读写权限。一个团队想自动化自己的工作区，就得用一把能伸到其他所有工作区的密钥。

现在每把密钥有两个设置。[*Scope*](https://openrouter.ai/docs/guides/overview/auth/management-api-keys#scope) 决定密钥在哪里生效：单个工作区，还是整个组织。[*Access level*](https://openrouter.ai/docs/guides/overview/auth/management-api-keys#permissions) 决定它在那个范围里能做什么：只读，还是读写。工作区管理员可以为自己所在的工作区创建密钥，于是部署流水线能轮换团队的 API 密钥，agent 能配置 guardrails，脚本能把队友加进工作区，而这些都碰不到其他团队的工作区。

## Scope 把密钥限制在一个工作区内

限定到工作区的密钥只在自己那个工作区生效。如果请求点名了别的工作区，或点名了属于别的工作区的资源，OpenRouter 一律拒绝。一个有 bug 的 agent 或一把泄露的密钥，碰不到组织的其余部分。

在自己的工作区里，这把密钥可以管理 API 密钥、成员、guardrails 与 guardrail 策略、你自己的提供商密钥、可观测性目标以及预设。它可以读取该工作区的预算、活动和分析数据。

**预算上限、额度和组织设置仍然归组织管理员。** 团队可以把工作区内的一切自动化，却依然无法提高自己工作区的预算。设置工作区预算、创建或删除工作区、管理组织成员，以及私有端点，仍然需要组织级密钥，它的工作方式与以往相同。

## 只读权限让工具只能看，不能改

Access level 是第二个设置，对工作区密钥和组织级密钥同样适用。只读密钥可以调用其 Scope 允许的读取路由，包括分析查询。任何会创建、修改或删除内容的请求都会返回错误。

这正好适合那些只需要看的工具。成本仪表板可以拉取用量，监控 agent 可以盯活动，审计脚本可以列出密钥、guardrails 和提供商密钥。你可以接入一个新的报表或审计工具，而不必给它写入账户的权限。

## 给每项工作一把只够用的密钥

Scope 与 Access level 组合出四种密钥：

- 为某个团队创建并轮换 API 密钥的 agent，拿该团队工作区的读写密钥。
- 某个团队的用量仪表板，拿该团队工作区的只读密钥。
- 组织范围的审计或成本工具，拿组织级只读密钥。
- 任何要创建工作区或设置预算上限的东西，继续用组织级读写密钥。

两个设置都在创建密钥时固定下来，事后无法追加权限。要改其中任何一个，请新建一把密钥并删掉旧的。

## 在仪表板中创建密钥

![工作区 Keys 页面上的 Management keys 标签页，列出三把密钥及其访问级别、有效期和状态，并有一个 New management key 按钮](https://openrouter.ai/blog/images/scoped-management-keys/workspace-management-keys-tab.png)

- 打开工作区，进入 **Keys**，选择 **Management keys** 标签页。工作区管理员可以为自己所在的工作区创建密钥，组织管理员可以为任意工作区创建。
- 点击 **New management key**。对话框会显示这把密钥限定在哪个工作区。
- 填写名称，选择有效期，在 **Access level** 下选 **Read only** 或 **Read and write**。
- 密钥只在显示出来的那一刻复制一次，之后再也看不到。

要一把覆盖整个组织的密钥，组织管理员使用 [Management API Keys](https://openrouter.ai/settings/management-keys) 页面。

你的 agent 和工具使用它的方式与今天的管理密钥相同：作为管理 API 上的 Bearer token：

```
curl https://openrouter.ai/api/v1/keys \
  -H "Authorization: Bearer $MANAGEMENT_KEY"
```

要复核已有的管理密钥，打开 [Security settings](https://openrouter.ai/settings/security)，进入 **Key safety**，打开 **Filter keys**，选择 **Show management keys**。每把有效密钥都会列出所有者、最后使用时间和有效期。[管理 API 密钥指南](https://openrouter.ai/docs/guides/overview/auth/management-api-keys)列出了每种密钥可以调用的全部路由。
