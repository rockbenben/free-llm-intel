我们把之前对 [Opus 做的成本分析](https://openrouter.ai/announcements/opus-47-tokenizer-analysis)在新 GPT-5.5 模型上复现了一遍。GPT-5.5 发布时相对 GPT-5.4 价格翻倍：输入 token 从 $2.50/M 涨到 $5.00/M，输出 token 从 $15/M 涨到 $30/M。OpenAI 同时指出该模型更简洁，同一任务产生的补全更短。和我们对 Opus 4.7 的分析一样，我们想通过研究从 GPT-5.4 迁移到 GPT-5.5 的用量，了解对用户成本的实际净影响。

**我们观察到成本上涨 49%-92%。对较长 prompt，模型生成的补全 token 减少 19-34%，部分抵消了涨价。**

## 方法：同样的“迁移用户群组”思路

我们沿用了 Opus 4.7 分析的同一套方法。我们识别出那些在 5.5 发布前按请求数计的首选模型是 GPT-5.4、随后首选模型切换为 GPT-5.5 的用户。这个“迁移群组”给了我们同一批用户在不同模型版本间受控的前后对比。

由于 GPT-5.4 和 5.5 使用同一 tokenizer 家族，我们无需控制 tokenizer 差异。对比是直接的：同一批用户、同样的工作流、不同的模型版本。

## GPT-5.5 更简洁，但仅限长 prompt

利用 OpenRouter 一致的 token 计数，我们测量了两个模型间补全长度的变化：

| Prompt Size | Median Completion (5.4) | Median Completion (5.5) | Change |
| --- | --- | --- | --- |
| < 2K tokens | 121 | 129 | **+7%** |
| 2K – 10K | 140 | 213 | **+52%** |
| 10K – 25K | 211 | 143 | **-32%** |
| 25K – 50K | 185 | 150 | **-19%** |
| 50K – 128K | 188 | 136 | **-28%** |
| 128K+ | 215 | 143 | **-34%** |

对超过 10K token 的 prompt，GPT-5.5 的输出少 19-34%。而对较短 prompt，模式反转：2K token 以下补全长度大致不变，2K-10K 区间反而长了 52%。

## 实际成本影响

使用迁移群组请求的计费成本，我们计算了平均每百万 OpenRouter token 的费用。这消除了 prompt 长度的影响，可以直接比较成本效率。

| Prompt Size | Avg $/M OR Tokens (5.4) | Avg $/M OR Tokens (5.5) | Change |
| --- | --- | --- | --- |
| < 2K tokens | $4.89 | $9.37 | **+92%** |
| 2K – 10K | $2.25 | $3.81 | **+69%** |
| 10K – 25K | $1.42 | $2.15 | **+51%** |
| 25K – 50K | $1.02 | $1.65 | **+62%** |
| 50K – 128K | $0.74 | $1.10 | **+49%** |
| 128K+ | $0.71 | $1.31 | **+85%** |

我们的分析显示，GPT-5.5 的实际成本上涨了 49% 到 92%。超过 10K token 的长 prompt，成本被更短的补全部分抵消；10K 以下的短 prompt，由于补全没有变短，成本涨幅更高。

## 方法说明

- **来源**：OpenRouter 的请求日志
- **群组**：按请求数计首选模型为 GPT-5.4、随后切换为首选 GPT-5.5 的用户
- **样本量**：纯文本、未取消的请求，按 5.4 和 5.5 划分
- **时间窗**：GPT-5.4：2026 年 4 月 21-23 日（发布前）；GPT-5.5：2026 年 4 月 25-28 日（发布后，剔除发布当天）
- **归一化**：按百万 OpenRouter token 计费用，并按 prompt token 数分桶。OpenRouter 的 token 计数独立于 OpenAI，在各模型版本间提供一致的基准。
- **控制项**：剔除媒体（图像、文件、音频、视频）、已取消请求和零 token 请求
