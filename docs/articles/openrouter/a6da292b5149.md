# Guardrails 现在将组织限制与工作空间默认值分开

萨莎·布卢门菲尔德 ·2026 年 10 月 30 日

![Guardrails 现在将组织限制与工作空间默认值分开](https://openrouter.ai/blog/images/guardrail-policies.png)

一年前，OpenRouter 上的大多数公司在少数团队中使用了人工智能。现在它已经扩展到各个部门。在 10 人或更多的团队中使用 OpenRouter 的人数增长了 70 倍，随着更多工作转移到代理，平均组织运行的活动 API 密钥数量是原来的三倍。

管理所有这些的管理员不断要求同样的事情：为整个组织制定一套规则，并为需要更多规则的人提供例外空间。

我们重建了 Guardrails 的配置方式，以便管理员现在可以设置组织范围的限制，为人们提供不同的预算和模型访问权限，并自行更改每项策略。

首先，打开工作区的 [Guardrails 页面](https://openrouter.ai/workspaces) 以设置策略，或阅读 [Guardrail 策略文档](https://openrouter.ai/docs/guides/features/guardrails/policies)。

## 为什么我们改变护栏

我们针对早期模式构建了 Guardrails 的第一个版本：几个团队，一些 API 密钥。如今，我们看到成百上千的员工通过 SSO 登录，编码代理在每个工程师的笔记本电脑上运行，平台团队负责所有成本。

![选择护栏类型：预算、模型和提供商访问或内容审核。](https://openrouter.ai/blog/images/guardrail-policies-approval-workflow.png)

这种转变体现在客户对我们的要求中：

- **每人的预算，有例外。** 团队希望为每个人提供默认的每月或每周预算，并为有需要的人提供更高的预算。由于每个预算水平都有一个护栏，一位客户有望为其大约 1,200 名员工每人创建一个单独的护栏。
- **开始时的默认设置是保守的。**客户希望新成员从最保守的设置开始，并随着时间的推移获得更多。旧模型的工作方式相反：工作区默认值是任何人都可以获得的最大工作区，而其他所有护栏只能收紧它。
- **一条规则跨越多个工作区。** 拥有多个业务部门的公司希望一次性设置 ZDR、提供商和区域规则，而不是将相同的护栏复制到每个工作区。
- **一种处理请求的方法。** 管理员不断被要求提供更大的预算或访问项目的新模型，并希望批准这是一个快速更改，而不是重建。

一些客户现在已经在 Guardrails 之上构建了自己的内部工作流程。员工要求更高的预算或访问项目的特定模型，并解释原因，然后管理员批准。通过组织设置单独的策略类型和限制，批准该请求只需一次更改。他们只是为该人员分配不同的预算或模型访问策略，并且它会自动保持在组织的限制范围内。

## 组织限制与工作区默认值是分开的

组织管理员现在可以为整个工作区设置限制，例如最大预算、零数据保留要求或可以使用哪些模型和提供程序。这些限制适用于工作区中的每个成员和 API 密钥，包括拥有自己的预算或模型政策的人员。

在这些限制内，工作区管理员设置默认值。新会员加入后会立即获得默认预算和型号列表，管理员可以为特定人员提供更高的预算或访问更多型号的权限。所有这些都不能超越组织的限制。

![配置预算护栏，每月信用额度为 2,000 美元，并包含 BYOK 支出。](https://openrouter.ai/blog/images/guardrail-policies-limits-defaults.png)

实际上，组织管理员将工程工作空间限制为每人每月 2,000 美元，仅限 ZDR 提供商，并且无法访问特定的高成本模型。工作区管理员将团队标准模型的新成员默认设置为每月 200 美元。新加入的工程师会自动获得 200 美元的违约金。领导代理项目的高级工程师每月可以获得 1,500 美元，并可以使用更多模型。工作场所中的任何人每月的费用不得超过 2,000 美元，也不得使用非 ZDR 提供商。

## 预算、模型访问和审核是单独的政策

一种护栏，用于将预算、模型和提供商访问以及内容审核捆绑到一个命名对象中。它们现在是三种不同的保单类型：

- **预算**设置美元支出上限，每天、每周或每月重置。
- **模型和提供程序访问**控制可以使用哪些模型和提供程序、ZDR 和数据区域。
- **内容审核**涵盖提示注入保护、敏感信息检测和自定义内容过滤器。

我们将它们分开，因为它们不会一起改变。一个人的预算可能会随着每个新项目的变化而变化，而团队的模型列表和审核规则可能会在几个月内保持不变。

现在，团队共享一种模型访问策略和一项审核策略，您可以更改一个人的预算，而无需触及其他任何内容。

## 向后兼容

您无需更改任何内容即可保持当前设置。现有的 Guardrails 保留其 ID 并执行相同的规则，并且 Guardrails API 和 Terraform 资源像以前一样工作。现在，每个护栏还显示为单独的预算、模型访问和审核策略，因此您可以在准备好时一次移动一个工作区。

如果您通过 API 或 Terraform 管理 Guardrail，请首先阅读[迁移到 Guardrail 策略](https://openrouter.ai/docs/guides/features/guardrails/policies-migration)，因为在仪表板中所做的更改不会同步回您的配置。

## 开始使用

要尝试它，请在您管理的任何工作区中打开 Guardrails 页面。您现有的护栏已经作为单独的策略存在。良好的第一步是提高一个人的预算而不触及其他任何东西。组织管理员可以通过工作区范围的护栏设置组织范围的限制。有关完整设置，请参阅 [Guardrail 策略文档](https://openrouter.ai/docs/guides/features/guardrails/policies)。

## 常见问题解答

### 什么是 OpenRouter Guardrail？

Guardrails 允许组织控制其成员和 API 密钥的支出、模型和提供商访问以及内容审核。

### 我可以为不同的人设置不同的人工智能预算吗？

是的。将预算政策分配给成员或 API 密钥。它每天、每周或每月重置，并且不能超出组织管理员设置的限制。

### 预算是否在整个工作区共享？

否。每个预算适用于每个成员或每个 API 密钥，而不是作为共享池。每月 100 美元的限额意味着每个人最多可以花费 100 美元。

### 我现有的护栏会怎样？

他们继续执行相同的规则并保留自己的身份证件。每一项现在还显示为最多三项单独的政策。

### 我需要迁移到新的 API 吗？

不会。现有的 Guardrails API 和 Terraform 资源将继续工作。新的策略端点与它们一起位于“/api/v1/guardrails/policies”下。

### 谁可以管理护栏政策？

组织管理员可以管理每项策略，包括组织范围的限制。工作区管理员管理工作区中的策略。
