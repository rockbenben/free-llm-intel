# OpenRouter Now Powers Inference on Hugging Face

Sasha Blumenfeld ·11/16/2026

![OpenRouter Now Powers Inference on Hugging Face](https://openrouter.ai/blog/images/hugging-face-inference-providers.jpg)![OpenRouter Now Powers Inference on Hugging Face](https://openrouter.ai/blog/images/hugging-face-inference-providers-dark.jpg)

We built OpenRouter so developers can reach many models and providers through one API, use the best model for each task, and count on it to respond. Starting today, that extends to everyone building on Hugging Face. Chat models on Hugging Face Inference Providers now run through OpenRouter, with the same routing across providers that OpenRouter customers already rely on.

The integration also runs the other way. OpenRouter can now send a trace of each request to a Hugging Face Storage Bucket you own, so the prompts and responses from your real traffic sit next to the models and datasets you would use to evaluate or fine-tune on them. The [setup guide](https://openrouter.ai/docs/guides/features/broadcast/hugging-face) has the steps.

![The Inference Providers widget on a Hugging Face model page answering a chat message, with a Powered by OpenRouter label](https://openrouter.ai/blog/images/hugging-face-inference-providers/inference-widget.gif)

## What you get on Hugging Face

Many chat models on Hugging Face are served by more than one provider. OpenRouter’s provider routing now powers routing on Hugging Face Inference Providers, and it picks the provider for each request based on live price, speed, and reliability. You don’t have to set anything up, and your existing Hugging Face token and code keep working.

You also get automatic failover. If a provider slows down or starts failing, requests go to other providers until it recovers. If a provider returns an error, the request is retried on the next one inside the same call.

When we [rebuilt this routing in October](https://openrouter.ai/blog/how-we-rebuilt-provider-routing), a live experiment measured 46% fewer requests hitting a capacity error, 16.9% faster time to first token, and 16.3% higher throughput, for 6.0% higher cost per request. Everyone building on Hugging Face now gets the same routing.

You stay in control of the trade-off. Adding a suffix to the model ID, such as `:fastest`, `:cheapest`, or a provider name, tells OpenRouter what to prioritize, and requests work through OpenAI’s Chat Completions and Responses APIs or Anthropic’s Messages API. A conversation also stays on the provider that holds its prompt cache.

Each model page has a new Providers tab with live price, speed, and uptime for every provider. You can see your spend by provider and turn off any provider you don’t want to use.

## Your traces can live on the Hub

Add Hugging Face Storage Buckets as a Broadcast destination (it’s in beta) and OpenRouter sends each request as a JSON file to a bucket you own. Each file holds the input messages, the model’s output, token counts, and cost. Images and other media are left out.

That’s the raw material for an evaluation set or a fine-tuning run on an open-weight model. You can organize the files by date or by API key.

![The new Hugging Face Storage Buckets destination form in OpenRouter's Observability settings, with fields for namespace, bucket name, access key ID, and secret access key.](https://openrouter.ai/blog/images/hugging-face-inference-providers/storage-buckets-destination.png)

## Get started

On Hugging Face:

- Create a token at [hf.co/settings/tokens](https://hf.co/settings/tokens) with the “Make calls to Inference Providers” permission.
- Open any supported model’s page on the Hub. Chat with it there, or click View code for setup steps for your code or your coding agent, including Claude Code, Codex, OpenCode, Pi, and Hermes Agent.
- To choose which providers can serve your requests, go to [Inference Providers](https://huggingface.co/settings/inference-providers) in your Hugging Face settings.

To send traces to a Storage Bucket:

- Create a Storage Bucket on Hugging Face.
- Create an access token with Write permission and generate S3 credentials from it.
- In OpenRouter, go to [Settings > Observability](https://openrouter.ai/settings/observability), turn on Broadcast, and open Hugging Face Storage Buckets.
- Enter your namespace, bucket name, access key ID, and secret access key. A path template such as `{apiKeyName}/{date}` is optional.
- Click Test Connection, then save.

The [full setup guide](https://openrouter.ai/docs/guides/features/broadcast/hugging-face) covers path templates and the trace file format.

[Try a model in the Hugging Face Playground](https://huggingface.co/playground), or [send your traces to a Storage Bucket](https://openrouter.ai/docs/guides/features/broadcast/hugging-face).
