# 什么是 Nemotron 3.5 Lightning

OpenRouter ·9/22/2026 · 更新于 9/24/2026

一个 agent 可能为规划任务做一次高难度调用，再为执行任务做几十次调用。后面这些调用读文件、选工具、校验结果、决定下一步做什么。NVIDIA 为工作流中这个高量的部分打造了 Nemotron 3.5 Lightning。

Nemotron 3.5 Lightning 是一个 300 亿参数的混合专家（mixture-of-experts）模型，每个 token 只激活约 30 亿参数。它支持工具调用、编码任务、指令遵循，以及其他范围明确的 agent 步骤。

这个名字很容易和 [Nemotron 3 Ultra](https://openrouter.ai/nvidia/nemotron-3-ultra-550b-a55b) 搞混，但两个模型是为 agent 工作流的不同部分构建的。在两者之间怎么选，会影响整次运行的成本、延迟和可靠性。

## Nemotron 3.5 Lightning 一览

| 规格 | Nemotron 3.5 Lightning |
| --- | --- |
| 模型类型 | Mamba-2、注意力与混合专家融合的混合架构语言模型 |
| 模型规模 | 总参数 30B，激活 3B |
| 输入与输出 | 文本到文本 |
| 模型上下文上限 | 按 NVIDIA 模型卡，最高 100 万 token |
| OpenRouter 标准模型 | 当前所有提供商均为 262,144 token 上下文。补全上限因提供商而异，从 32,768 到 235,929 token |
| OpenRouter 免费模型 | 1,000,000 token 上下文，补全最多 65,536 token |
| 工具调用 | 两个模型都列出该能力。当前四家标准提供商中有两家列出 |
| 结构化输出 | 标准模型在当前全部四家提供商上都列出。免费模型未列出 |
| OpenRouter 模型 ID | `nvidia/nemotron-3.5-lightning` 和 `nvidia/nemotron-3.5-lightning:free` |
| 权重 | BF16 参考权重，另有优化过的 NVFP4 和 GGUF 版本 |
| 许可证 | OpenMDW-1.1 |
| 发布日期 | 2026 年 8 月 11 日 |

表中各端点的限制和特性来自我们 2026 年 9 月 11 日的模型页面。围绕某个具体限制做设计之前，请先查[标准模型页](https://openrouter.ai/nvidia/nemotron-3.5-lightning)或[免费模型页](https://openrouter.ai/nvidia/nemotron-3.5-lightning:free)。

## "30B MoE、3B 激活参数"是什么意思？

Nemotron 3.5 Lightning 是稀疏混合专家模型。它总共包含 300 亿参数，但并不是每个 token 都用上全部专家。模型处理每个 token 时，一个路由器会选择一小撮专家，把激活参数量压到约 30 亿。你也会看到写成 30B-A3B 的形式，意思是总参数 300 亿、激活参数约 30 亿。

这个设计让模型拥有比 3B 稠密模型大得多的总容量，又不用为每个 token 跑全部 300 亿参数。Lightning 就是这样把相对大的检查点和高频 agent 调用所需吞吐量结合起来的。

激活参数量不是完整的算力或内存规格。整个模型仍然要存下来，共享层在推理时也照样运行。硬件需求取决于精度、上下文长度、推理引擎、批处理策略和缓存配置。

Lightning 还采用了混合架构，而不是纯 Transformer 堆栈。[NVIDIA 模型卡](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16)描述了交错的 Mamba-2 和 MoE 层，并穿插若干注意力层。它还支持可配置推理，自带多 token 预测以及 DSpark、DFlash 两个投机解码草稿模型以加速生成，并附带一个为推理调优的 NVFP4 检查点。

## Nemotron 3.5 Lightning 为什么场景设计？

长时间运行的 agent 会发起很多次模型调用。有的调用需要高难度规划，更多的工作其实范围更窄：选一个工具、生成参数、检查结果、编辑一个文件、决定下一步。

NVIDIA 把 Lightning 定位在执行这一层。当你的工作负载符合下面这些特征时，这个模型值得考虑：

- agent 调用次数多，延迟或成本在整次运行中不断累积。
- 每次调用目标清晰，且有足够上下文去完成。
- 模型需要使用工具、遵循指令或返回结构化数据。
- 你想要可以针对领域或部署目标做定制的开放权重。

举个例子：一个编码 agent 可以用更大的推理模型来检查代码仓库、决定实现方案；Lightning then 处理一个个具体步骤，比如定位某个符号、编辑一个文件、运行一个工具、解读结果。

## Nemotron 3.5 Lightning 对比 Nemotron 3 Ultra

NVIDIA [从 Nemotron 3 Ultra 蒸馏出了 Lightning](https://vllm.ai/blog/2026-08-10-nemotron-3-5-lightning-vllm)，但两者不能互换。Lightning 是负责高量 agent 执行的小模型，Ultra 是负责复杂推理和编排的大模型。

|  | Nemotron 3.5 Lightning | Nemotron 3 Ultra |
| --- | --- | --- |
| OpenRouter 模型 ID | `nvidia/nemotron-3.5-lightning` | `nvidia/nemotron-3-ultra-550b-a55b` |
| 总参数 | 30B | 550B |
| 激活参数 | 3B | 55B |
| 主要角色 | 高量执行和专项任务 | 复杂推理和编排 |
| OpenRouter 上下文 | 当前所有提供商均为 262,144 token | 视提供商而定，202,800 到 262,144 token |
| 工具调用 | 当前四家提供商中两家列出 | 当前所有提供商都列出 |
| 结构化输出 | 当前所有提供商都列出 | 当前四家提供商中一家列出 |
| 2026 年 9 月 11 日提供商价格 | 输入 $0.065–$0.10/M，输出 $0.18–$0.25/M | 输入 $0.50–$0.625/M，输出 $2.20–$3.125/M |

NVIDIA 报告 Lightning 的吞吐量最高可达同等规模开放模型的 4 倍。在 NVIDIA 的 PinchBench 测试中，它完成 10,000 个 agent 任务的速度最高快 30%，而准确率持平。这些是厂商自报的结果，请在自己的工作负载上实测吞吐和任务完成。

区分点是调用的难度和后果。当某一步需要对模糊问题做深度推理、要为长工作流产出方案、或要做一个很难撤回的决定时，Ultra 更合适。当任务范围明确、且重复到延迟和成本开始变得重要时，Lightning 更合适。

你不必把整个 agent 绑定在一个模型上。复杂调用路由给 Ultra，高频执行调用路由给 Lightning。然后度量这种组合是否降低了每个完成任务的成本、同时没有牺牲可靠性。

### 在 OpenRouter 上于两个模型之间路由

愿意把模型选择交给我们的话，用 [Auto Router](https://openrouter.ai/docs/guides/routing/routers/auto-router)。把 `openrouter/auto` 作为模型 ID 发过来，Auto Router 会给提示词分类，再基于任务类型、模型能力、工具支持和成本选择模型。`cost_tier` 设置选一个成本档位，从 `low` 到 `max`。它不会把对话从便宜的模型升级到更贵的模型。如果只想让 Auto Router 在 Lightning 和 Ultra 之间选，用 `allowed_models` 限制候选。

### 在 OpenRouter 之外于两个模型之间路由

NVIDIA 的 [NeMo Switchyard](https://developer.nvidia.com/blog/route-ai-agent-workloads-across-models-with-nvidia-nemo-switchyard/) 把这个路由模式实现为一个开源编排层。它的升级路由器让每个对话从更低成本的模型开始，LLM 裁判在检测到持续困难时把会话切到更强的模型。在 [LangChain 对 145 个多步 agent 任务的评估](https://www.langchain.com/blog/switchyard-agent-routing-benchmark)中，在 Lightning 和 Claude Opus 4.8 之间路由，相比只用前沿模型的基线省了 74% 成本，其中约 7% 的调用发给了前沿模型，准确率低了约六个百分点。这个结果展示的是该基准上的路由取舍，并不是 Lightning 加 Ultra 组合的基准测试。任何路由配置请先在自己的任务上测过再指望它省钱。

## 上下文窗口有多长？

Nemotron 3.5 Lightning 在模型层面支持最高 100 万 token。你的应用实际可用的上下文取决于服务它的端点。

2026 年 9 月 11 日，标准模型 ID 背后的每家提供商都暴露 262,144 token 的上下文窗口。补全上限因提供商而异，从 32,768 到 235,929 token。`:free` 模型暴露完整的 100 万 token 上下文，补全上限 65,536 token。

如果请求超过 262,144 token，目前只有免费端点在 OpenRouter 上暴露模型完整的 100 万 token 上下文。NVIDIA 在该端点上的声明指出：使用情况会被记录，用于安全和改进 NVIDIA 产品与服务，并请不要上传机密信息或个人数据。涉及敏感的或生产级的长上下文负载，请选别的端点或模型。

在两个模型 ID 之间切换时，这个差异就重要了。在免费端点上成功的请求，可能超出标准端点的上下文限制。免费端点也列出了工具调用，但没有列 `response_format` 或结构化输出。

请看模型页面，别把架构上的最大上下文当成每家提供商的承诺。模型页面上展示了每个端点当前的限制和支持的参数。

## 开放权重与本地部署

NVIDIA 以 OpenMDW-1.1 许可证发布了 [BF16 参考检查点](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16)。模型卡把 BF16 版本描述为后训练、领域适配、研究以及制作优化变体的起点。NVIDIA 还发布了用于定制和评估的训练数据与配方，模型卡称该发布可直接商用。

直接推理时，NVIDIA 推荐其 NVFP4 版本；同时提供适配受支持本地系统的 GGUF 检查点。BF16 指引列出的单卡部署硬件是 H100 80GB 或 A100 80GB。优化版本面向 RTX 5090、RTX PRO 6000 和 DGX Spark 这类硬件。

本地跑这个模型，不等于每台机器都能服务完整的 100 万 token 上下文。按 NVIDIA 当前的 Ollama 指引，默认上下文随可用显存缩放：低于 24GB 是 4K，24GB 到不足 48GB 是 32K，48GB 及以上是 256K。llama.cpp 示例用了约 40K。你可以把上限调高，但那可能需要更多内存或 CPU 卸载。

权重是公开可得的，"开放权重"是最贴切的描述。在再分发修改后的模型、或依据条款做部署决策之前，请先读 OpenMDW-1.1 许可证。

## 如何在 OpenRouter 上调用 Nemotron 3.5 Lightning

不想配置 GPU、不想管推理引擎的话，通过 OpenRouter 调用 Lightning。标准模型 ID 保持 API 不变，我们在该模型的可用提供商之间替你路由请求。

安装 OpenRouter TypeScript SDK。

```
npm install @openrouter/sdk
```

在环境里设置 `OPENROUTER_API_KEY`，然后用 Lightning 模型 ID 发请求。标准模型列出了结构化输出，你可以要求 JSON schema，让响应严格符合它。

```
import { OpenRouter } from "@openrouter/sdk";

const openRouter = new OpenRouter({
  apiKey: process.env.OPENROUTER_API_KEY,
});

const result = await openRouter.chat.send({
  chatRequest: {
    model: "nvidia/nemotron-3.5-lightning",
    messages: [
      {
        role: "user",
        content:
          'Ticket: "Checkout returns a 500 after I click Pay. Started this morning, three customers affected." Return its category and priority.',
      },
    ],
    responseFormat: {
      type: "json_schema",
      jsonSchema: {
        name: "triage",
        strict: true,
        schema: {
          type: "object",
          properties: {
            category: { type: "string" },
            priority: { type: "string", enum: ["low", "medium", "high"] },
          },
          required: ["category", "priority"],
          additionalProperties: false,
        },
      },
    },
    provider: {
      requireParameters: true,
    },
  },
});

if (!("choices" in result)) {
  throw new Error("Expected a non-streaming response");
}

console.log(result.choices[0]?.message.content);
```

2026 年 9 月 11 日我们运行这个请求时，模型返回了 `{"category": "Bug (Payment Checkout)", "priority": "medium"}`。采样输出每次运行会有不同，请求保证的是 schema，不是具体值。

同一个模型内，各提供商对 `response_format` 和结构化输出的支持并不一致。默认我们优先支持你所发 `tools` 和 `response_format` 参数的提供商，不支持某参数的提供商会忽略它。像示例那样把 `require_parameters` 设为 `true`，就把请求限制在支持其中每个参数的提供商上。完整行为见[提供商路由文档](https://openrouter.ai/docs/guides/routing/provider-selection)。

想试免费端点，把模型 ID 改成 `nvidia/nemotron-3.5-lightning:free`。免费端点没有列 `response_format`，在那里请去掉这个字段、自己校验 JSON。它适合评估和低量实验，限制和可用性都与标准端点不同。

不要通过免费端点提交机密信息或个人数据。它的模型页面带有 NVIDIA 的声明：使用情况会被记录，用于安全和改进 NVIDIA 产品与服务。决定发哪些提示词之前请先看这份声明。

默认情况下，标准模型在其各提供商之间按价格排序做负载均衡。两个变体会改变这个顺序：`nvidia/nemotron-3.5-lightning:nitro` 按吞吐给提供商排序，`nvidia/nemotron-3.5-lightning:exacto` 优先工具调用质量信号更强的提供商。对于一个因延迟和工具使用而被选中的模型，[Nitro](https://openrouter.ai/docs/guides/routing/model-variants/nitro) 和 [Exacto](https://openrouter.ai/docs/guides/routing/model-variants/exacto) 是值得一记的两个变体。

Lightning 接受 `tools` 和 `tool_choice`，所以你也可以把它放进 agent 循环里用。完整的请求、工具执行和迭代流程见我们的[工具调用 agent 循环指南](https://openrouter.ai/blog/tutorials/build-tool-calling-agent-loop/)。

## 你该用 Nemotron 3.5 Lightning 吗？

当你需要一个快速、开放权重的模型来跑高频、定义清晰的 agent 步骤时，Nemotron 3.5 Lightning 值得评估。它的 30B-A3B 架构、工具支持和低廉的挂牌 token 价格，使它成为执行模型的有力候选——否则这些 agent 会把每次调用都发给一个大得多的推理模型。

把模型名当起点而不是结论。用你的 agent 实际会做的工具调用和任务搭一个评估集。度量整次运行的任务成功率、重试、延迟和总成本。如果 agent 频繁重试或频繁把结果升级上报，便宜的调用并不能帮你省钱。

从 `nvidia/nemotron-3.5-lightning` 开始，或先用 `nvidia/nemotron-3.5-lightning:free` 在接付费流量之前测一测这个模型。

## 常见问题

### Nemotron 3.5 Lightning 是什么？

Nemotron 3.5 Lightning 是 NVIDIA 的开放权重 30B 混合专家语言模型，每个 token 激活约 3B 参数。NVIDIA 把它定位在高量 agent 执行、工具使用、编码、指令遵循和专项任务上。

### Nemotron 3.5 Lightning 和 Nemotron 3 Ultra 是同一个吗？

不是。Nemotron 3.5 Lightning 总参数 30B、激活 3B；Nemotron 3 Ultra 总参数 550B、激活 55B。Lightning 面向高频执行步骤，Ultra 面向复杂推理和编排。

### 30B-A3B 是什么意思？

30B-A3B 指模型总参数 300 亿、每个 token 激活约 30 亿参数。混合专家路由器为每个 token 挑选模型专家的一个子集，而不是运行全部专家。

### Nemotron 3.5 Lightning 支持工具调用和结构化输出吗？

标准 OpenRouter 模型 `nvidia/nemotron-3.5-lightning` 的支持参数里列出了 `tools`、`tool_choice`、`response_format` 和结构化输出。支持情况因提供商而异，请求依赖其中某项时请把 `require_parameters` 设为 `true`。免费模型列出了 `tools` 和 `tool_choice`，但没有 `response_format` 或结构化输出。

### 有免费的 Nemotron 3.5 Lightning API 吗？

有。我们上架了 `nvidia/nemotron-3.5-lightning:free`，由 NVIDIA 提供服务、token 免费。免费模型的速率限制和可用性与付费模型不同，而且这个端点带有 NVIDIA 的数据声明。请别通过它发送机密信息或个人数据。

### 我能在本地跑 Nemotron 3.5 Lightning 吗？

能。NVIDIA 以 OpenMDW-1.1 许可证发布了 BF16、NVFP4 和 GGUF 权重。BF16 参考检查点面向单张 80GB 的 H100 或 A100；NVFP4 和 GGUF 版本面向 RTX 5090、RTX PRO 6000、DGX Spark 等受支持的本地硬件。选择部署方案前请核对 NVIDIA 最新的模型卡和许可证。
