在 tools 数组里加上 `openrouter:subagent`，你的模型就能在生成过程中把自包含的任务委派给一个更小、更便宜、更快的 worker 模型。总结文档、抽取结构化数据、起草模板代码、重排文本格式——worker 处理完把结果传回来。你的前沿模型继续做编排，而不必在例行工作上烧昂贵的 token。

在 [chatroom](https://openrouter.ai/chat) 中试用、[阅读文档](https://openrouter.ai/docs/guides/features/server-tools/subagent)，或按 [cookbook 食谱](https://openrouter.ai/docs/cookbook/building-agents/subagent-server-tool)把它接入你的应用。

```
{
  "model": "anthropic/claude-opus-4.8",
  "messages": [{ "role": "user", "content": "Audit this release: summarize the changelog, list breaking changes, and draft the announcement." }],
  "tools": [
    {
      "type": "openrouter:subagent",
      "parameters": { "model": "z-ai/glm-5.2" }
    }
  ]
}
```

由模型决定何时委派。它只在不需自身全部能力时才调用 subagent。

## 在你的代码库中寻找 subagent 机会

把这段 prompt 粘贴给你的 coding agent，让它扫描你的项目、找出 subagent 委派能省钱的地点：

```
Read through this codebase and identify places where an OpenRouter API call
could benefit from the openrouter:subagent server tool. Look for patterns where
a frontier model is doing mechanical sub-tasks inline: summarization, data
extraction, reformatting, boilerplate generation, or schema conversion.

For each candidate, explain:
1. Which file and function
2. What the sub-task is
3. Why it's a good fit for delegation (self-contained, predictable output, doesn't need the full conversation context)
4. A code snippet showing how to add the subagent tool to that call

Reference docs: https://openrouter.ai/docs/guides/features/server-tools/subagent
Cookbook recipe: https://openrouter.ai/docs/cookbook/building-agents/subagent-server-tool
```

## 前沿的大脑，预算的双手

Claude Opus 4.8 每百万输入 token $5，GPT-5.5 也是 $5，GLM 5.2 是 $1.40。前沿与 worker 之间输入价差 3.6 倍，输出 5.7 倍。（Claude Fable 5 被撤下前是每 M tokens $10/$50，RIP。）

一个前沿模型做代码评审，不需要亲自花自己的 token 去总结 2,000 行的 changelog 或重排一个 JSON blob。那些是指令清晰、输出可预期的机械任务。subagent 用 GLM 的价格处理它们，让编排者专注于真正需要推理的部分。

在一个有 20 次工具调用的复杂 agentic 工作流中，也许有 5-8 次可以是 subagent 委派：总结、数据抽取、模板填充、格式转换。前沿模型负责编排和判断。你在不触碰难题质量上限的前提下砍掉了单次请求的成本。

## 底层如何工作

worker 模型只能看到委派模型在 `task_description` 中显式传入的内容。没有父对话、没有先前上下文、任务之间没有记忆。每次委派都是干净、隔离的工作单元。

- **任何模型都能当 worker。** 用 `parameters.model` 钉住它（[模型目录](https://openrouter.ai/models)里的任何模型都行）。像 `z-ai/glm-5.2` 这样的开源模型很适合机械任务。不指定模型时，回退到外层请求模型。
- **Worker 有自己的工具。** 给 worker 配上 `openrouter:web_search`，它就能在回答前用新鲜来源为输出打底。worker 在内部运行自己的工具循环；只有最终文本回到你的模型。
- **递归被禁止。** subagent 不能调用自己。深度头和自引用检查防止无限嵌套，且每个请求最多 10 次委派。

```
{
  "tools": [
    {
      "type": "openrouter:subagent",
      "parameters": {
        "model": "z-ai/glm-5.2",
        "instructions": "You are a fast, focused worker. Complete the task exactly as described.",
        "tools": [{ "type": "openrouter:web_search" }]
      }
    }
  ]
}
```

## Subagent vs. advisor

这两个工具指向相反的方向。[advisor](https://openrouter.ai/docs/guides/features/server-tools/advisor)把困难决策升级给更强的模型；subagent 把例行工作下放给更便宜的模型。

|  | Advisor | Subagent |
| --- | --- | --- |
| **方向** | 向上（咨询更强的模型） | 向下（委派给更便宜的模型） |
| **Worker 选择** | 模型按每次调用挑选 | 由工具定义固定 |
| **用例** | “帮我一起想清楚这个问题” | “帮我把这个机械任务做掉” |
| **记忆** | 跨请求的对话记录重放 | 无（每个任务隔离） |

两者可以在同一请求中使用。你的前沿模型在架构决策上咨询 advisor，把总结工作委派给 subagent。不同的工作用不同的工具。

## 计费

Subagent 的 token 按 **worker 模型**的费率计费，与编排者分开。如果编排者是 Claude Opus 4.8（每 M tokens $5/$25）而 worker 是 GLM 5.2（每 M tokens $1.40/$4.40），每个模型的 token 按各自价格计费。两者都会显示在你的 [activity 页面](https://openrouter.ai/activity)上。

## 开始使用

tools 数组里加一行：

```
{ "type": "openrouter:subagent", "parameters": { "model": "z-ai/glm-5.2" } }
```

何时使用由模型决定。阅读[完整文档](https://openrouter.ai/docs/guides/features/server-tools/subagent)了解所有参数、worker 工具与递归细节，或按 [cookbook 食谱](https://openrouter.ai/docs/cookbook/building-agents/subagent-server-tool)做一个可运行的集成。
