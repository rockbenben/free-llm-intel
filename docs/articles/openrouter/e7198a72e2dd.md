# LLM API 速率限制：如何修复 OpenAI 和 Claude 429 错误

开放路由器 ·11/11/2026

![LLM API 速率限制：如何修复 OpenAI 和 Claude 429 错误](https://openrouter.ai/blog/images/llm-api-rate-limits.png)![LLM API 速率限制：如何修复 OpenAI 和 Claude 429 错误](https://openrouter.ai/blog/images/llm-api-rate-limits-dark.png)

429 Too Many Requests 错误意味着您发送的请求或令牌数量超出了当前时间窗口允许的限制。 OpenAI、Anthropic 和 [OpenRouter](https://openrouter.ai/docs/api_reference/limits) 都会返回它，并且它通常会在应用程序首次在实际负载下运行或批处理作业分散到多个工作人员时显示。

大多数人都会尝试重试，而默认设置通常是不够的。当我们通过 OpenAI Python SDK 针对每分钟的限制运行 60 个提示批处理时，在 SDK 重试后，仍有 23 个请求失败。 SDK 放弃每个窗口后 4 到 8 秒，窗口会重置。

本指南从真正的 429 开始，读取其标头，并通过三种方式修复它：在错误给您的重置时间重试，将溢出发送到后备模型，并让另一个提供者提供相同的模型。我们针对 OpenRouter API 运行了每个示例，每个代码块下的输出就是我们得到的。

## Tl;博士

- 429 表示您达到了当前窗口的限制。在 OpenRouter 上，error.metadata.limit_source 告诉您它是谁的限制。
- 使用默认设置，OpenAI Python SDK 会重试每个 429 两次，并在大约 2 秒内放弃。相对于每分钟的限制，我们批次中的 60 个请求中有 23 个仍然失败。
- 等待 Retry-After 或 X-RateLimit-Reset 的重试在每次运行中完成全部 60 次，在 Python 中需要 89 到 92 秒，在 TypeScript 中需要 106 到 218 秒。
- 模型后备在 13 秒内完成全部 60 场比赛，费用为 0.000066 美元，无需等待。
- 固定到一个提供程序并关闭故障转移，每次运行 150 个请求中最多有 32 个失败。启用故障转移后，每次运行 150 次都成功。

## 429 速率限制错误是什么样的？

我们一次向 poolside/laguna-s-2.1:free 发送 40 个请求，这是一个免费模型，每分钟限制 20 个请求。 38 次成功，其中 2 次从为模型提供服务的提供商返回 429：
```
200: 38  429: 2  other: 0
429 limit_source: {'upstream_provider_shared_pool': 2}
```
我们自己的免费套餐限制中的 429 带有不同的 limit_source。这是单独运行的一个：
```
{
  "message": "Rate limit exceeded: free-models-per-min. ",
  "code": 429,
  "metadata": {
    "headers": {
      "X-RateLimit-Limit": "20",
      "X-RateLimit-Remaining": "0",
      "X-RateLimit-Reset": "1792448640000"
    },
    "limit_source": "openrouter_free_tier_per_minute",
    "remedy_hint": "Slow down requests to free models, or retry after the per-minute window resets.",
    "provider_name": null
  }
}
```
标头包含您需要的数字。 X-RateLimit-Limit 是上限，X-RateLimit-Remaining 是剩下的内容，X-RateLimit-Reset 是重试可以成功的最早时间，以毫秒为单位的 Unix 时间戳。正文添加了 limit_source ，它表示您达到了谁的限制，以及为阅读日志的人编写的remediate_hint 。在代码中的 limit_source 上分支，而不是在提示文本上分支。

OpenAI 和 Anthropic 以不同的名称发送相同的信息。 [OpenAI 的](https://developers.openai.com/api/docs/guides/rate-limits) x-ratelimit-reset-requests 是一个持续时间，例如 1 秒，并且[两个提供商](https://platform.claude.com/docs/en/api/rate-limits) 可以发送重试后的秒数。

## 为什么速率限制会在不同的请求计数时触发？

40 个请求中的 38 个超过了 20 的限制。限制器可以接受在计数赶上之前同一时刻到达的请求，并且大多数限制器不会在每分钟结束时完全重置。 Anthropic 使用不断补充的令牌桶。当您的流量增长过快时，即使您低于每分钟限制，[OpenAI 也会返回 429](https://developers.openai.com/docs/guides/error-codes)，代码为 Slow_down。

为了了解我们的免费模型限制如何计算，我们以不同的模式发送了 161 个请求。以下是其中三个：

| **测试** | **那一刻就成功了** |
| --- | --- |
|连续，空闲两分钟后 | 30|
|连续的，紧接 | 之后的一分钟30|
| 30个并发| 29 | 29

由此产生了两件事。我们测试的每分钟都有超过 20 个请求成功，因此将 20 视为 429 可以开始的点，而不是精确的计数。当我们在窗口还剩 58 秒时在 poolside/laguna-s-2.1:free 上点击它时，对 minimax/minimax-m3.1-flash:free 的五个请求立即通过，而 Laguna 仍然被阻止。但这并不构成每个型号的上限。 OpenRouter 对帐户上的所有免费模型应用一个每分钟限制器，因此对不同免费模型的请求可以获得相同的 429。

## 第 1 步：了解您达到了谁的限制

仅当限制按计划重置时，等待才能修复 429，因此在选择修复之前请检查 limit_source：

| **限制来源** | **状态** | **谁的限制** | **什么解决了这个问题** |
| --- | --- | --- | --- |
| openrouter_free_tier_per_分钟 | 429 | 429我们的免费模型帽子 |等待 X-RateLimit-Reset（第 2 步），或退回到付费模式（第 3 步）|
|上游供应商共享池 | 429 | 429为模型提供服务的提供商 |另一个提供商（步骤 4）或后备模型（步骤 3） |
| openrouter_in_flight_budget | openrouter_in_flight_budget | 402 | 402您的机上消费预算|等待 Retry-After 并重试 |
| openrouter_key_limit、openrouter_credits | 402 | 402您钥匙的信用额度或余额 |提高密钥限制或添加积分 |

![429 决策流程：读取 error.metadata.limit_source。 openrouter_free_tier_per_minute (429)：等待 X-RateLimit-Reset 或回退到付费模型。 upload_provider_shared_pool (429)：让 OpenRouter 路由到另一个提供商或添加后备模型。 openrouter_in_flight_budget (402)：等待Retry-After并重试。 openrouter_key_limit 或 openrouter_credits (402)：提高密钥的限制或添加积分。](https://openrouter.ai/blog/images/llm-api-rate-limits-1.png)

上游 429 意味着为该模型提供服务的提供商已超出容量。提供商没有说明该容量何时会释放，因此这些错误在我们的运行中没有携带重置标头。 Gemma 4 31B 的免费版本返回以下内容：
```
google/gemma-4-31b-it:free is temporarily rate-limited upstream. Please retry shortly, or add your own key to accumulate your rate limits.
```
使用付费变体作为后备的相同请求使用了不同提供商的容量，并在 DeepInfra 上以 0.0000037 美元的价格成功。

一些看起来像速率限制的错误与金钱有关。当您达到每月支出上限时，OpenAI 和 Anthropic 都会返回 429，并且在上限重置之前重试不会修复该问题。在 OpenRouter 上，信用问题返回为 [402](https://openrouter.ai/docs/api_reference/errors-and-debugging)。

## 步骤 2：在错误提示的重置时间重试

OpenAI 和 Anthropic Python SDK 默认重试 429 两次，并有一个从 0.5 秒开始的短暂退避，并且永远不会等待超过 8 秒。当服务器发送 429 时，它们会遵循 Retry-After 标头。

我们的免费套餐 429 发送的是 X-RateLimit-Reset，而 SDK 不会读取该内容，因此两次重试都在同一整分钟内完成。以下是使用默认设置通过 OpenAI SDK (openai 3.26.1) 进行的 60 个提示批次，一次 10 个：
```
openai 3.26.1 | max_retries default: 2
finished in 12s  (HTTP requests sent: 112)
succeeded: 37  RateLimitError after retries: 23
slowest failure gave up after 2.3s
message: Rate limit exceeded: free-models-per-min.  | limit_source: openrouter_free_tier_per_minute
  limit_source=openrouter_free_tier_per_minute  x-ratelimit-reset: 1792444980000  retry-after: None  window reset 8s after the SDK gave up
  limit_source=openrouter_free_tier_per_minute  x-ratelimit-reset: 1792444980000  retry-after: None  window reset 7s after the SDK gave up
  ...
  limit_source=openrouter_free_tier_per_minute  x-ratelimit-reset: 1792444980000  retry-after: None  window reset 4s after the SDK gave up
```
SDK 发送了 112 个 HTTP 请求，出现了 60 条提示，仍有 23 条失败。提高 max_retries 最终会通过，但只能通过每 8 秒向整个窗口发送一个请求，并且 [OpenAI 的文档说明](https://developers.openai.com/api/docs/guides/rate-limits) 失败的请求仍然计入每分钟的限制。更好的重试方法是等待服务器给您的时间。要运行所有 60 个提示，请使用当天至少剩余 60 个免费模型请求的帐户，因为未购买 10 个积分的帐户每天会获得 50 个积分：
```
import email.utils
import os
import random
import time
from concurrent.futures import ThreadPoolExecutor

import requests

URL = "https://openrouter.ai/api/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"}

def retry_delay(headers, attempt):
    """Seconds to wait after a 429: Retry-After, then X-RateLimit-Reset, then backoff."""
    retry_after = headers.get("Retry-After")
    if retry_after:
        if retry_after.replace(".", "", 1).isdigit():
            return float(retry_after)
        when = email.utils.parsedate_to_datetime(retry_after).timestamp()
        return max(0.0, when - time.time())
    reset = headers.get("X-RateLimit-Reset")  # Unix time in milliseconds
    if reset:
        # Spread clients over a few seconds after the reset, so they don't all retry at once.
        return max(0.0, int(reset) / 1000 - time.time()) + random.uniform(1, 5)
    return min(2 ** attempt, 60) * random.uniform(0.5, 1)  # exponential backoff with jitter

def chat(body, max_attempts=6):
    for attempt in range(max_attempts):
        r = requests.post(URL, headers=HEADERS, json=body, timeout=120)
        source = None
        if r.status_code in (402, 429):
            source = r.json()["error"].get("metadata", {}).get("limit_source")
        if source == "openrouter_free_tier_daily":  # resets at UTC midnight, so don't sleep until then
            r.raise_for_status()
        # A 402 from the in-flight budget clears after Retry-After; other 402s need credits.
        if r.status_code != 429 and source != "openrouter_in_flight_budget":
            r.raise_for_status()
            return r.json()
        if attempt == max_attempts - 1:
            break  # out of attempts, so don't wait before failing
        wait = retry_delay(r.headers, attempt)
        print(f"{r.status_code} ({source}), attempt {attempt + 1}: waiting {wait:.1f}s")
        time.sleep(wait)
    r.raise_for_status()

if __name__ == "__main__":
    def job(i):
        return chat({
            "model": "poolside/laguna-s-2.1:free",
            "messages": [{"role": "user", "content": f"Reply with the number {i}."}],
            "max_tokens": 16,
        })

    t0 = time.time()
    with ThreadPoolExecutor(max_workers=10) as pool:  # the same batch job: 60 prompts, 10 at a time
        results = list(pool.map(job, range(60)))
    print(f"{len(results)} of 60 completed in {time.time() - t0:.0f}s")
```

所有 60 个请求均已完成，但该批处理花费了 89 秒而不是 12 秒。这种方法不会失败，并且每个达到限制的请求都会等待到窗口之外。

retry_delay 首先检查 Retry-After，因为它是服务器的直接指令，而 X-RateLimit-Reset 仅标记窗口何时滚动。随机的 1 到 5 秒可以防止 10 个工作人员同时重试并立即填充新窗口。

即便如此，这次运行中的四个请求在新窗口填满后重试，因此他们第二次等待。如果您将 SDK 调用包装在这样的循环中，请在客户端上设置 max_retries=0，否则每次尝试都会变成三个请求。

### 在 TypeScript 中进行相同的重试

retry.ts 遵循相同的顺序：Retry-After，然后 X-RateLimit-Reset，然后退避。它使用内置的 fetch，因此不需要包。我们使用 npx tsx retry.ts 在节点 24 上运行它：
```
const URL = "https://openrouter.ai/api/v1/chat/completions";
const HEADERS = {
  Authorization: `Bearer ${process.env.OPENROUTER_API_KEY}`,
  "Content-Type": "application/json",
};

const sleep = (ms: number) => new Promise((resolve) => setTimeout(resolve, ms));
const randomBetween = (min: number, max: number) => min + Math.random() * (max - min);

/** Seconds to wait after a 429: Retry-After, then X-RateLimit-Reset, then backoff. */
export function retryDelay(headers: Headers, attempt: number): number {
  const retryAfter = headers.get("Retry-After");
  if (retryAfter) {
    const seconds = Number(retryAfter);
    if (!Number.isNaN(seconds)) return seconds;
    const when = Date.parse(retryAfter); // HTTP date
    if (!Number.isNaN(when)) return Math.max(0, (when - Date.now()) / 1000);
  }
  const reset = headers.get("X-RateLimit-Reset"); // Unix time in milliseconds
  if (reset) {
    // Spread clients over a few seconds after the reset, so they don't all retry at once.
    return Math.max(0, (Number(reset) - Date.now()) / 1000) + randomBetween(1, 5);
  }
  return Math.min(2 ** attempt, 60) * randomBetween(0.5, 1); // exponential backoff with jitter
}

export async function chat(body: object, maxAttempts = 6): Promise<any> {
  let res: Response | undefined;
  for (let attempt = 0; attempt < maxAttempts; attempt++) {
    res = await fetch(URL, { method: "POST", headers: HEADERS, body: JSON.stringify(body) });
    if (res.status !== 402 && res.status !== 429) {
      if (!res.ok) throw new Error(`HTTP ${res.status}: ${await res.text()}`);
      return res.json();
    }
    const error = (await res.json()).error;
    const source = error?.metadata?.limit_source;
    // A 402 from the in-flight budget clears after Retry-After; other 402s need credits.
    if (res.status === 402 && source !== "openrouter_in_flight_budget") {
      throw new Error(`HTTP 402: ${JSON.stringify(error)}`);
    }
    if (source === "openrouter_free_tier_daily") {
      throw new Error(`HTTP 429: ${JSON.stringify(error)}`); // resets at UTC midnight, so don't sleep until then
    }
    if (attempt === maxAttempts - 1) break; // out of attempts, so don't wait before failing
    const wait = retryDelay(res.headers, attempt);
    console.log(`${res.status} (${source}), attempt ${attempt + 1}: waiting ${wait.toFixed(1)}s`);
    await sleep(wait * 1000);
  }
  throw new Error(`Still rate limited after ${maxAttempts} attempts`);
}

// The same batch job: 60 prompts, 10 at a time.
async function main() {
  const prompts = Array.from({ length: 60 }, (_, i) => i);
  const results: any[] = [];
  const worker = async () => {
    for (let i = prompts.shift(); i !== undefined; i = prompts.shift()) {
      results[i] = await chat({
        model: "poolside/laguna-s-2.1:free",
        messages: [{ role: "user", content: `Reply with the number ${i}.` }],
        max_tokens: 16,
      });
    }
  };

  const t0 = Date.now();
  await Promise.all(Array.from({ length: 10 }, worker));
  const completed = results.filter(Boolean).length;
  console.log(`${completed} of 60 completed in ${Math.round((Date.now() - t0) / 1000)}s`);
}

main();
```

429 (openrouter_free_tier_per_minute), attempt 1: waiting 34.9s
429 (openrouter_free_tier_per_minute), attempt 1: waiting 34.6s
429 (openrouter_free_tier_per_minute), attempt 1: waiting 35.1s
429 (openrouter_free_tier_per_minute), attempt 1: waiting 33.5s
429 (openrouter_free_tier_per_minute), attempt 2: waiting 60.5s
429 (openrouter_free_tier_per_minute), attempt 2: waiting 58.6s
429 (openrouter_free_tier_per_minute), attempt 2: waiting 60.6s

```
总时间取决于批处理开始时窗口的位置以及模型提供者的繁忙程度。我们的两次 TypeScript 运行花费了 218 和 106 秒，我们的两次 Python 运行花费了 92 和 89 秒。所有四个人都完成了每个请求。

## 步骤 3：将溢出发送到后备模型

如果第二个模型的答案可以接受，那么您根本不必等待。提供商速率限制适用于一个提供商的一种模型，因此不同的模型使用单独的容量。免费套餐上限是一个例外，因为您帐户上的每个 :free 模型都共享它。使用 models 参数，我们按顺序尝试每个模型，并在出现任何错误（包括 429）时移至下一个模型，[在任何内容到达您的代码之前](https://openrouter.ai/docs/guides/routing/model-fallbacks)：
```
import os
import time
from collections import Counter
from concurrent.futures import ThreadPoolExecutor

import requests

URL = "https://openrouter.ai/api/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"}

def job(i):
    r = requests.post(URL, headers=HEADERS, timeout=120, json={
        # Try the free model first; if it is rate limited, OpenRouter sends the request to the next one.
        "models": ["poolside/laguna-s-2.1:free", "deepseek/deepseek-v4.1-flash"],
        "messages": [{"role": "user", "content": f"Reply with the number {i}."}],
        "max_tokens": 16,
    })
    data = r.json()
    return r.status_code, data.get("model"), data.get("usage", {}).get("cost", 0)

t0 = time.time()
with ThreadPoolExecutor(max_workers=10) as pool:  # the same batch job: 60 prompts, 10 at a time
    results = list(pool.map(job, range(60)))
print(f"finished in {time.time() - t0:.0f}s")
print(Counter((status, model) for status, model, _ in results))
print(f"total cost: ${sum(cost for *_, cost in results):.6f}")
```

```
finished in 13s
Counter({(200, 'poolside/laguna-s-2.1:free'): 52, (200, 'deepseek/deepseek-v4.1-flash'): 8})
total cost: $0.000066
```
免费模型服务了 52 个请求，付费模型服务了另外 8 个请求。没有请求等待，您只需为付费请求付费。响应的模型字段记录了哪个模型进行了回答，这就是您需要付费的模型。

选择具有自身容量的后备。您帐户上的每个 :free 模型都共享免费模型上限，因此当该上限是原因时，另一个免费模型并不是可靠的后备方案。免费模型也经常会耗尽提供商的容量，因此付费后备方案是更可靠的选择。

以下是同一批次的三个并排运行：

| **运行** | **已完成** | **时间** | **成本** |
| --- | --- | --- | --- |
| OpenAI SDK，默认重试 | 37 共 60 | 12 秒 | 0 美元 |
|等待重置重试 | 60 共 60 | 89 年代 | 0 美元 |
|模型后备 | 60 共 60 | 13 秒 | $0.000066 |

如果作业可以等待，请重试重置。如果不能，并且第二个模型的答案足够好，请添加后备。

## 步骤 4：让另一个提供商提供相同的模型

第 2 步和第 3 步处理我们的自由模型上限。付费模式遇到了另一种限制：为它们提供服务的提供商的容量。 OpenRouter 上的大多数模型由多个提供商提供服务，每个提供商都有自己的速率限制。当一个提供商返回 429 时，我们会在错误到达您之前在下一个提供商处重试请求。默认情况下此功能处于启用状态。

我们向 google/gemma-4-31b-it 发送了 300 个请求，一次 50 个，并检查每个请求的 GET /api/v1/ Generation 记录中的provider_responses 列表，其中显示了我们尝试过的每个提供程序：
```

status codes: Counter({200: 300})

served by: {'CoreWeave': 177, 'DeepInfra': 118, 'Novita': 1, 'Venice': 1, 'ModelRun': 1, 'Parasail': 2}
requests that needed more than one provider: 0
failed attempts, by provider and status: []
total cost: $0.00130
```
Spread across six providers, no request needed a second try. Then we pinned the same model to Crusoe with “provider”: {“order”: [“crusoe”]} and sent 150 requests, 50 at a time.这是一个带有后备的运行：

total cost: $0.00056
```
Crusoe 对 79 个请求进行了速率限制，CoreWeave 回答了全部 79 个请求，客户看到了 150 个成功。我们在allow_fallbacks关闭和打开的情况下重复固定运行几次：

| **允许回退** | **运行** | **每次运行成功** | **每次运行 429 秒** |
| --- | --- | --- | --- |
|假 | 4 | 150、147、118、136 | 0、3、32、14 |
|真实 | 3 | 150, 150, 150 | 150, 150, 150 | 0 |

Crusoe 的容量每分钟都在变化，因此关闭回退的失败次数从无到 32 不等。打开回退后，Crusoe 在这三次运行中将请求限制为 21、41 和 79 个，而客户端从未看到过其中一个。任何缩小提供者可以服务请求的范围都会导致吸收突发的能力减少。如果您仍然在 OpenRouter 上看到提供商 429，请检查 allowed_fallbacks: false、简短的列表或严格的 max_price。要在不丢失故障转移的情况下首选一个提供程序，请设置顺序并将allow_fallbacks 保留为默认值。

同样的 300 个请求突发到 anthropic/claude-haiku-5.5 和 openai/gpt-6-luna 没有失败的尝试。当封闭模型自己的 API 耗尽容量时，错误通常是 529 而不是 429，[Claude 529 重载指南](https://openrouter.ai/blog/tutorials/claude-529-overloaded/) 涵盖了这一点。

## 如何避免达到速率限制？

上面的修复可以在 429 发生后进行处理。这些习惯会降低以下可能性：

- **将并发限制在限制允许的范围内。** 并发是我们的第一个测试超出限制的原因。与在 429 后等待整个窗口相比，调整刚好低于限制的请求所损失的时间要少。
- **将 max_tokens 设置为接近您期望的答案长度。** OpenAI 将 max_tokens 计入您的每分钟令牌限制，因此慷慨的值会比答案更快地耗尽限制。
- **在进行大型作业之前检查您的密钥。** GET /api/v1/key 报告每日自由模型计数器。在这些运行之后，我们的读数为 {‘used’: 585, ‘limit’: 1000, ‘remaining’: 415}。在您购买至少 10 个积分之前，每日限制为 50 个免费模型请求，之后为 1,000 个。
- **在生产中使用付费变体。** 每分钟 20 次的上限仅适用于 :free [models](https://openrouter.ai/docs/api_reference/limits)。

## 常见问题

### 如何提高 OpenAI API 速率限制？

当您组织的信用购买总额超过每个使用层阈值时，OpenAI 会自动提高您的限制。您可以在 OpenAI 仪表板中的“设置”>“组织”>“限制”下查看当前限制。通过 OpenRouter，提供商路由将模型的流量分散到为其提供服务的每个提供商，因此单个提供商的限制不会限制您。

### 为什么Claude说“达到速率限制”？

在 Claude API 上，这意味着您的组织用完该模型每分钟的请求或令牌，并且 retry-after 标头表示要等待多少秒。如果 429 来自您的每月支出上限，则没有重试标头，并且在访问恢复之前重试不会有帮助。在订阅的 Claude Code 中，该消息通常表示该计划的使用限制。请参阅[达到您的Claude Code使用限制？](https://openrouter.ai/blog/tutorials/claude-code-usage-limit/)。

### 更多 API 密钥是否可以绕过速率限制？

不会。在 OpenRouter 上，额外的 API 密钥或帐户不会改变您的速率限制，因为我们在全球范围内管理容量。提供商限制适用于每个模型，这就是后备模型起作用的原因，但您帐户上的每个 :free 模型共享一个免费套餐上限。使用 [BYOK](https://openrouter.ai/docs/guides/overview/auth/byok)，使用您自己的提供商密钥的请求将计入​​该提供商的限制。

### Retry-After 是以秒还是毫秒为单位？

秒或 HTTP 日期。我们的 X-RateLimit-Reset 是不同的。这是一个以毫秒为单位的 Unix 时间戳。步骤 2 中的 retry_delay 函数处理所有三种形式。
