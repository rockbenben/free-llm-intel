# 介绍新的自动和自动代码路由器

布莱恩·托马斯 ·11/6/2026

![介绍新的自动和自动代码路由器](https://openrouter.ai/blog/images/auto-and-auto-code-routers.png)

今天我们推出下一代自动路由器。借鉴过去 3 年运行 Auto Router 所学到的一切，我们在全新的技术基础上从头开始重建了它，根据基准测试，其性能比旧路由器高出 4 倍，在我们的实时测试中，p90 的路由步骤快了 3 倍（0.65 秒对 1.96 秒）。

路由器在基准测试中取得好成绩比在实践中表现良好更容易。 Auto Router 每月会收到来自超过 10 万人的超过 2.5T 代币，因此它必须在现实世界中保持稳定。

此次发布包括一款专门用于编码工作的全新路由器，[自动代码](https://openrouter.ai/openrouter/auto-code) (`openrouter/auto-code`)，以及我们的旗舰通用[自动路由器](https://openrouter.ai/openrouter/auto) (`openrouter/auto`)。

现在就尝试一下，在任何请求中将“model”设置为“openrouter/auto”或“openrouter/auto-code”，或者打开[聊天室中的自动路由器](https://openrouter.ai/chat?models=openrouter%2Fauto)。查看 [自动路由器文档](https://openrouter.ai/docs/guides/routing/routers/auto-router) 了解所有详细信息。

## 这一代有什么新鲜事

以前的自动路由器依赖于一些不精确的信号（例如任务类型）来驱动模型选择、保持低延迟和判断一致所需的限制。新的自动路由器和自动代码通过权衡每个请求的 11 个因素并将其与实时定价、提供商运行状况和缓存状态相结合来选择模型。

这个新流程让自动布线器可以与任何模型集配合使用。您可以应用任何治理策略，包括护栏、零数据保留要求、提供商限制、允许的模型列表和 BYOK 密钥。自动路由器可以从可用的型号中进行有效的选择。

我们根据有关在编码工具中使用通用路由器的反馈，推出了新的自动编码路由器。该路由器通过包含更高层的编码模型并优化延迟来从头开始调整编码性能。在以下五个基准测试中，Auto Code 的得分与 Claude Opus 5.5 一致，同时每项任务的成本降低了 74%。

## 基于多年运行自动路由器的经验教训

Auto Router 即将迎来其三岁生日。如果您几年前在代理中设置了“openrouter/auto”，那么今天您仍然可以获得最新的成本最优选择。我们已经了解了很多关于自动模型选择出错的地方，并构建了新一代模型来避免这些问题。一些例子：

**我们分离出自动代码来优化线束。** 对以前版本的自动布线器最常见的抱怨是它在编码线束中的表现。 Auto Code 偏爱稍贵一点的模型，其优点与编码工作相匹配。它更注重速度，因为在构建时响应能力很重要。它还对失败的惩罚更加严厉，因此在成功和失败明确的工作中，它的纠正速度会更快。

**为了保护缓存优势，切换受到限制。** 当新模型重建输入令牌缓存时，切换模型会产生额外成本。当足够时，自动路由器倾向于改变推理工作，并且仅当增益值得其放弃的缓存时才进行切换。在我们的测试期间，每十个代理轮换中有近九个都保持相同的模型。

**它适应失败。** 当会话以指向模型的方式出错时，例如返回相同的错误或编辑后测试失败，这些信号会增加切换的可能性。这使得会话不太可能陷入早期选择错误的模型。

**它根据实际使用情况和基准进行调整。** 自动路由器随着每次基准运行和它看到的每个实际路由决策而变得更好。通过“typesafe/jev-router”和“openrouter/auto-beta”，我们已经在生产工作负载上对其进行了验证，同时始终保持零数据保留。在我们的测试版中，与之前的路由器相比，无效工具调用减少了 4 倍，代理响应被切断的频率减少了一半。

## 基于领先的提供商路由基础构建的模型路由

**模型路由器**（例如自动路由器和自动代码）选择哪个模型将处理请求。 **提供商路由**选择谁将为该模型提供服务。 OpenRouter 从一开始就对每个请求执行此操作：一旦选择了模型，[provider router](https://openrouter.ai/docs/guides/routing/provider-selection) 就会使用您的提供商首选项、实时正常运行时间和延迟、价格以及提供商是否已保存您的提示缓存来在托管它的提供商中进行选择。

模型路由器只能与底层提供商路由器一样好。我们构建自动路由器是为了了解我们的整个目录，因此它可以适应治理限制、基准测试结果以及新模型发布时发出的市场信号。 OpenRouter 上的 600 多个模型中的每一个模型在添加之日都会进入考虑范围，基准和流行度信号决定它是否在成本最优模型中赢得一席之地。

## 请求如何通过自动路由器移动

- 自动路由器缩小了模型池。护栏、零数据保留、模型功能、提供商限制、BYOK 密钥以及任何允许或排除的模型列表决定了考虑哪些模型。
- 快速决策模型处理请求。在一项调查中，它对十一项进行了评估，例如这是什么类型的任务，任务是否刚刚改变，任务有多困难，速度是否重要，是否需要代码库的愿景或知识，以及更大的模型、更多的思考或更便宜的模型是否能更好地服务于它。
- 路由策略选择模型。它权衡实时价格、缓存状态和基准性能来选择模型和推理工作。
- 请求通过同一个提供商，将直接请求路由到该模型，因此它会到达该模型的最佳提供商。
- 每轮的结果告知下一轮的模型选择。路由器携带诸如模型是否陷入困境以及已缓存到下一个决策中的信号等信号。

## 路由器与单一型号

基准测试一致表明，市场上没有任何路由器在成本和质量曲线上的每个点上都击败了单一最佳前沿模型。新的自动路由器也不例外，我们发布了它的基准测试以清楚地展示它的优点和缺点。

当工作多样化时，当组织需要保持成本稳定时，以及对于那些没有时间或兴趣跟上持续不断的模型发布流的人来说，路由器就会赢得一席之地。在单一模型上选择自动路由器或自动代码会牺牲一点峰值性能，以换取随着时间的推移保持一致、经济高效的性能。

如果您知道最适合您的特定工作的模型，请继续使用它。如果您宁愿选择一次并专注于工作本身，那么路由器就是您的最佳选择。

## 开始吧

无论您在何处放置模型字符串，自动路由器和自动代码都可以工作：
```
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openrouter/auto-code",
    "messages": [{"role": "user", "content": "Add a retry with backoff to fetchUser in api/users.ts"}]
  }'
```
阅读 [自动路由器文档](https://openrouter.ai/docs/guides/routing/routers/auto-router) 了解完整设置，或打开 [聊天室中的自动路由器](https://openrouter.ai/chat?models=openrouter%2Fauto) 并向其发送您通常手动选择型号的提示。请在 Discord 上的 [#feedback](https://discord.gg/fVyRaUDgxW) 中告诉我们哪些是对的，哪些是错的。

## 常见问题

### 我需要更改什么才能从旧的自动路由器切换？

什么都没有。 slug 仍然是 `openrouter/auto` 并且 `auto-router` 插件设置 `cost_tier`、`allowed_models` 和 `excluded_models` 仍然有效。

### 自动路由器和自动代码有什么区别？

两者都运行在相同的路由引擎上。自动路由器是用于混合流量和一般代理的通用路由器，并且支持经济高效的模型层。 Auto Code 专门用于编码代理和工具，从较高的成本层开始，并权衡模型和推理工作中每个已解决任务的测量通过率、速度和成本。

### 模型路由与提供者路由相同吗？

否。模型路由选择哪个模型处理请求；提供者路由选择哪个提供者为该模型提供服务。自动路由器和自动代码执行第一个操作，然后 OpenRouter 的提供商路由使用您的提供商首选项、正常运行时间数据和提示缓存状态执行第二个操作。

### 路由器是否尊重我的护栏和数据策略？

是的。 Guardrail 策略、零数据保留要求、提供商限制、允许和排除的模型列表以及 BYOK 密钥定义模型池，路由器会在其中选择成本最优模型。

### 路由器需要额外付费吗？

不会。您只需支付满足请求的型号的标准价格，响应的“型号”字段就会告诉您是哪一款。

### 什么是 openrouter/auto-beta？

Auto Router Beta 是下一版本 Auto Router 的发布渠道。新的路由更改首先发布到“openrouter/auto-beta”，一旦验证成功，就会升级到“openrouter/auto”，因此请使用它来提前查看即将发生的情况。如果您尝试一下，请在 Discord 上的 [#feedback](https://discord.gg/fVyRaUDgxW) 中告诉我们哪些是对的，哪些是错的。
