# Advisor：给任意模型一条通往更强模型的求助线

在你的 tools 数组里加上 `openrouter:advisor`，你的模型就能在生成过程中向更强的模型求助。当执行模型遇到艰难决策、卡住了，或在收尾前想要一次把关，它会带着一个 prompt 调用 advisor。advisor 思考后把指导意见作为 tool result 返回，执行模型拿着更好的信息继续干。

两个角色都是开放的：OpenRouter 上的任意模型都能当执行模型（executor），任意 provider 的任意模型都能当顾问（advisor）。可以让 Gemini 执行、Claude 出主意，也可以让 GPT 执行、DeepSeek 出主意。搭配由你定。

在 [chatroom](https://openrouter.ai/chat) 里试试，或[阅读文档](https://openrouter.ai/docs/guides/features/server-tools/advisor)获取完整 API 参考。

```
{
  "model": "openai/gpt-4o-mini",
  "messages": [{ "role": "user", "content": "Design a rate limiter for a distributed API gateway." }],
  "tools": [
    {
      "type": "openrouter:advisor",
      "parameters": { "model": "anthropic/claude-fable-5" }
    }
  ]
}
```

## 67 倍价差，选择性咨询

Claude Fable 5 的输入价格是每百万 token $10，GPT-4o Mini 是每百万 $0.15，价差 67 倍。

大多数请求并不需要前沿级别的推理。中档模型处理绝大部分负载毫无压力。但涉及架构决策、含糊的边界情况或多步推理链的那 10-20%，恰恰是便宜模型容易翻车的地方。

advisor 工具精准地补上这个缺口。你的快模型主导全局，只有遇到真正难的东西才开口求助。你只为需要前沿思考的时刻支付前沿价格。

在一个有 50 次 tool call 的 agentic 编码会话里，也许只有 2-3 次是 advisor 咨询，其余都按 mini 价格跑。你把单次会话的成本抹平了，同时保住了质量上限。

## 服务端执行，一次 tool call

advisor 在生成期间于服务端运行。你的模型像调用其他工具一样调用它：传一个描述所需帮助的 `prompt`，拿回 advisor 的文本作为 tool result。然后由模型自己参考建议写出最终答案。advisor 是顾问，不是代笔。

四点值得了解：

- **任意 provider 的任意模型都能当 advisor。**在工具配置里用 `parameters.model` 固定（[模型目录](https://openrouter.ai/models)中的任何一个都行），或让执行模型逐次自选。用 `~anthropic/claude-fable-latest` 可始终解析到最新的 Fable。
- **advisor 是单轮的。**它从咨询中返回聚焦的指导，不会运行嵌套的 tool loop。如果你需要带工具的子 agent，请改用 `openrouter:subagent`。
- **禁止递归。**每次内层 advisor 调用都携带 `x-openrouter-advisor-depth` 头，且子调用中会剥离 advisor 工具，防止无限嵌套。单次请求的咨询次数也有上限，以约束成本。
- **advisor 有记忆。**在后续请求中重放会话记录（包含 advisor 的调用与结果），每个 advisor 会重建它此前的咨询内容，后续提问可以建立在 advisor 已给出的建议之上。记忆按 advisor 隔离（你的安全审查员和架构师各留各的线索），且跨 Chat Completions、Responses 和 Anthropic Messages 均可用。[完整细节](https://openrouter.ai/docs/guides/features/server-tools/advisor#cross-request-memory)。

## 具名 advisor

对于复杂工作流，你可以配置一组专家。每个 advisor 一条 `openrouter:advisor` 记录，各自有自己的名字、模型和 instructions：

```
{
  "tools": [
    {
      "type": "openrouter:advisor",
      "parameters": {
        "name": "security-reviewer",
        "model": "anthropic/claude-fable-5",
        "instructions": "You are a security engineer. Find vulnerabilities."
      }
    },
    {
      "type": "openrouter:advisor",
      "parameters": {
        "name": "architect",
        "model": "openai/gpt-5.5",
        "instructions": "You are a systems architect. Prioritize simplicity and scalability."
      }
    }
  ]
}
```

执行模型会为每个 advisor 看到一个独立的工具，只需传一个 `prompt` 就能调用适合当前任务的那位。鉴权流程的审查会交给带安全人设的 Claude Fable；架构问题则交给 GPT-5.5。名字可使用字母、数字、空格、下划线和短横线（“Lead Architect”也行），且在各条目间必须唯一。允许有一条记录省略 `name`，作为默认 advisor。

建议也可以流式返回。在 advisor 条目上设置 `"stream": true`，你就能随着 advisor 撰写逐步收到建议。在 Responses API 中，这意味着建议生成期间会发出 `response.output_text.delta` 事件；完成后的输出项仍携带全文，忽略 delta 的消费者不会感到任何差别。（Chat Completions 会忽略该标志，Messages API 的流式支持是后续项。）

## 与其他家的 advisor 工具对比

一些 provider 在自己的 API 里也提供了类似的 advisor 概念，但局限于自家模型家族：执行模型和 advisor 都必须来自同一厂商，往往还锁死在固定的搭配矩阵里，有时甚至要 beta 门槛。OpenRouter 的 advisor 移除了这些约束，还额外加了几样东西：

- **两侧都任意模型、任意 provider。**执行模型和 advisor 都可以是[目录](https://openrouter.ai/models)中数百个模型里的任何一个：便宜的开源权重模型咨询前沿模型、Gemini 执行咨询 Claude，或 Claude 执行时跨出自家家族向 GPT-5.5 要第二意见。
- **一组具名 advisor。**在单个请求里配置多位各自带模型和 instructions 的专家，让执行模型把每个问题路由给对的那位。单厂商版本只给你一位无名 advisor。
- **单轮咨询。**每位 advisor 直接把聚焦的指导返回给执行模型。需要带工具的子 agent 请用 `openrouter:subagent`。
- **跨 API 格式可用，无 beta 门槛。**同一个工具可通过 Chat Completions、Responses 和 Anthropic Messages 使用（三者都支持跨请求记忆），且已正式可用（GA）。没有 beta 头，不用申请团队白名单。

如果你已经在通过我们的兼容 API 外壳使用 provider 原生的 advisor，切换到 `openrouter:advisor` 即可打开整个目录，请求的其他部分不用改。

## 计费

advisor 的 token 按 **advisor 模型**的费率计费，与执行模型分开。如果执行模型是 GPT-4o Mini（每百万 token $0.15/$0.60），advisor 是 Claude Fable 5（每百万 $10/$50），各模型的 token 按各自价格计费。两者都会出现在你的 [activity 页面](https://openrouter.ai/activity)上。

## 开始使用

在 tools 数组里加一行：

```
{ "type": "openrouter:advisor", "parameters": { "model": "anthropic/claude-fable-5" } }
```

何时使用由模型自己决定。大多数请求不会触发咨询；触发了的那些会因此变得更好。参数、具名 advisor、跨请求记忆等[完整文档在这里](https://openrouter.ai/docs/guides/features/server-tools/advisor)。需要带工具的子 agent，请用 `openrouter:subagent`。
