Deloitte 的 [State of AI 报告](https://www.deloitte.com/us/en/about/press-room/state-of-ai-report-2026.html)调查了 24 个国家的 3,235 位领导者，发现 77% 的公司如今在挑选 AI 供应商时会把原产国纳入考量。近五分之三的人表示，他们的 AI 技术栈主要用本地供应商构建。

如果你的采购团队已经提出这一点，通常的假设是：合规意味着自建或租用本地基础设施。对于通过 API 消费模型的团队来说并非如此。你的真实需求是地理化的推理路由，而这是在一个请求里就能设定的约束。

“自建基础设施”这套思路适合政府、国防承包商和需要拥有整个技术栈的隔离网络环境。对于调用第三方 API 的应用团队，问题其实更窄：证明对受监管数据的推理发生在特定地理区域，且没有任何服务商保留或用这些数据训练。

## 把驻留当作一个路由决策

路由层位于你的应用和模型服务商之间。与其和每家服务商分别配置驻留（每家对它的定义都不同），你只需设定一次地理和数据政策，让这一层只挑选符合条件的服务商。

OpenRouter 的 [provider 对象](https://openrouter.ai/docs/guides/routing/provider-selection)暴露了这些控制项。`order` 和 `only` 决定哪些服务商可以服务一个请求，`data_collection` 决定服务商能否存储你的数据或用于训练，`zdr` 要求 [Zero Data Retention](https://openrouter.ai/blog/insights/zero-data-retention/)。这些都按请求生效，也可以在[隐私设置](https://openrouter.ai/settings/privacy)里设为整个账户的默认值。

这会把你的信任从众多独立服务商转移到路由层。在用这种方式路由受监管负载之前，请先审计 OpenRouter 自身的[数据处理政策](https://openrouter.ai/docs/guides/privacy/provider-logging)，并确认路由行为符合你的要求。

## 一个请求强制地理约束

下面是单次调用中的地理强制：优先尝试 Anthropic 直连 API，其次 Amazon Bedrock，其余一概拒绝：

```
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-4.6",
    "messages": [
      {"role": "user", "content": "Summarize this compliance report."}
    ],
    "provider": {
      "order": ["anthropic", "amazon-bedrock"],
      "allow_fallbacks": false,
      "data_collection": "deny",
      "zdr": true
    }
  }'
```

`order` 设定服务商优先级；`allow_fallbacks` 设为 `false` 会阻断向列表之外的路由；`data_collection` 设为 `"deny"` 会排除存储或训练输入数据的服务商；`zdr` 设为 `true` 确保 prompt 和补全在请求后不被保留。对受监管负载，请显式设置这些项，不要依赖默认值。

每个字段对应不同的合规层。`order` 和 `only` 控制推理在哪里运行；`data_collection` 和 `zdr` 控制数据事后会发生什么。它们不可互换，请按你的政策真正需要的来设置。

## 需要时钉住 EU 司法辖区

对于 EU 要求，你可以把路由限制在总部设于欧盟的服务商并拒绝数据收集。总部在法国的 Mistral 是一个有用的 EU 辖区锚点，其余可以通过 `only` 和数据政策过滤器来表达。服务商数据中心位置的独立确认，仍应直接来自该服务商。

当请求绝不能离开 EU 时，Business 和 Enterprise 账户可以把请求发往 `eu.openrouter.ai` 使用 [EU 区内路由](https://openrouter.ai/docs/guides/features/sovereign-ai)。请求经 `eu.openrouter.ai` 在欧洲联盟境内完成解密与处理，且只有符合 EU 条件的服务商提供服务。

## 处理“无合规服务商可用”的情况

如果你列表中的服务商都不可用且 `allow_fallbacks` 为 `false`，API 会返回错误，而不是路由到不合规的服务商——这正是受监管数据应有的行为。

接下来怎么办由你的应用选择：排队重试、对不敏感内容回退到非受监管路径，或把失败暴露给调用方。失败模式由你决定，不由路由器决定。

数据驻留只是更大治理蓝图中的一行。[AI 治理清单](https://openrouter.ai/blog/insights/ai-governance-checklist/)覆盖其余部分：支出、模型访问、服务商溯源和审计线索。

## 常见问题

### 为了 AI 数据驻留，我需要自建本地基础设施吗？

如果你通过 API 消费模型，就不需要。拥有整个技术栈对政府和隔离网络环境是正确答案，但对应用团队而言，需求是地理化推理路由：证明对受监管数据的推理在特定区域运行，且没有服务商保留或使用它。这是按请求设定的路由约束。

### 如何把 OpenRouter 限制在特定服务商或区域？

在请求中使用 provider 对象。`order` 或 `only` 控制哪些服务商可以服务该请求；`data_collection` 设为 `deny` 会屏蔽存储或用你的数据训练的服务商；`zdr` 设为 `true` 要求 Zero Data Retention 端点。也可以在隐私设置中设为账户级默认。

### 没有合规服务商可用怎么办？

把 `allow_fallbacks` 设为 `false`，OpenRouter 会返回错误而不是路由到列表外的服务商。失败模式由你的应用决定：排队重试、对非敏感内容回退到非受监管路径，或抛出错误。

### OpenRouter 能保证请求留在 EU 吗？

在 Business 和 Enterprise 套餐上，EU 区内路由通过 `eu.openrouter.ai` 在欧盟境内完成请求的解密与处理。其他账户仍可把路由限制在总部设于欧盟的服务商并拒绝数据收集，但服务商数据中心位置的独立验证应来自该服务商本身。

### OpenRouter 会存储我的 prompt 吗？

由你控制。把 `zdr` 设为 `true` 会把路由限制在 Zero Data Retention 端点；`data_collection` 设为 `deny` 会屏蔽存储或训练输入数据的服务商。在运行受监管负载之前，请先审阅服务商日志文档和你的隐私设置。
