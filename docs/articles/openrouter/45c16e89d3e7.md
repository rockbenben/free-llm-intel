# Gemini 2.5 Flash API - 定价、快速入门和提供商比较

OpenRouter ·6/9/2026 · 更新于 6/24/2026

## Gemini 2.5 Flash 是什么？

Gemini 2.5 Flash 是 Google 面向高流量、对延迟敏感又需要推理的任务的主力模型。它是第一个内置 thinking 的 Flash 级模型——一个可以随意开关的混合推理模式。这一点使它和 2.0 Flash 有实质区别，也值得拿出来和那些贵得多的模型比一比。

### 关键能力

Gemini 2.5 Flash 支持的输入类型：文本、代码、图像、音频、视频和文档。文档输入在生产中有两条约束：单个文档最大 50MB（超过的文件必须先切成小于 50MB 的分块再提交）；支持的文档 MIME 类型仅限 `application/pdf` 和 `text/plain`。

它不支持的：音频生成、图像生成和 Live API。需要图像生成的话，用 [Gemini 2.5 Flash Image](https://openrouter.ai/google/gemini-2.5-flash-image)——那是一个独立模型。

### "Thinking" 在实践中意味着什么

thinking 预算是一个控制模型在生成响应前做多少内部推理的参数，内建在模型推理架构里。预算设 0 彻底关闭，产出最快、最便宜。设 -1 开启动态模式，模型按提示词复杂度自行调整推理深度。Google 直连 API 上 -1 是默认。经 OpenRouter，除非显式请求，thinking 是关的（见下文"通过 OpenRouter 配置"）。更高的固定预算会提升复杂任务的输出质量，代价是额外延迟和 token 开销——按输出费率计费。

### Thinking Token 计费

Thinking token 按与输出 token 相同的费率计费。预算 0 时没有 thinking 成本。最大预算（24,576 token）时，thinking 开销可能超过可见响应本身的成本。估算某个工作负载的成本：把预期的 thinking token 数乘以输出费率，加到常规输出 token 成本上。

### 免费接入选项

## API 快速上手：5 分钟发出第一个请求

OpenRouter 路径不需要 Google Cloud 账户，任何 OpenAI 兼容 SDK 都能用。Google 直连路径需要 Google 账户和 `google-genai` SDK。更多 SDK 示例和配置项见 [OpenRouter 快速上手](https://openrouter.ai/docs/quickstart)。

### 第 1 步：拿到 API key

**OpenRouter 路径：**[获取 OpenRouter API key](https://openrouter.ai/settings/keys)，不需要 Google Cloud 账户。

**Google 直连路径：**在 [aistudio.google.com/apikey](https://aistudio.google.com/apikey) 拿 key。

### 第 2 步：设置 base URL（OpenRouter 路径）

OpenRouter 的 base URL 是 `https://openrouter.ai/api/v1`。下面三个代码示例都用这个端点。

### 第 3 步：发出第一个请求

**cURL：**

```
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer <your-openrouter-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "google/gemini-2.5-flash",
    "messages": [{"role": "user", "content": "Explain the difference between attention mechanisms in transformers."}]
  }'
```

**Python（OpenAI SDK）：**

```
from openai import OpenAI

client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key="<your-openrouter-key>",
)

response = client.chat.completions.create(
    model="google/gemini-2.5-flash",
    messages=[{"role": "user", "content": "Explain the difference between attention mechanisms in transformers."}]
)

print(response.choices[0].message.content)
```

**TypeScript（OpenAI SDK）：**

```
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://openrouter.ai/api/v1",
  apiKey: "<your-openrouter-key>",
});

const response = await client.chat.completions.create({
  model: "google/gemini-2.5-flash",
  messages: [{ role: "user", content: "Explain the difference between attention mechanisms in transformers." }],
});

console.log(response.choices[0].message.content);
```

### Google 直连路径

已有 Google AI Studio API key、想要无中间商的直连路径：

```
from google import genai

client = genai.Client(api_key="<your-google-api-key>")

response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents="Explain the difference between attention mechanisms in transformers.",
)

print(response.text)
```

直连路径用 `google-genai` SDK，不兼容 OpenAI。从 OpenRouter 换到直连，客户端库和请求结构都要改。直连路径没有提供商故障转移。

## Thinking 预算：控制推理质量与成本

thinking 预算是你在这个模型上要做的最重要配置决定。设错了，要么为不需要的推理多付钱，要么在需要准确的任务上丢分。完整参数参考见[配置 thinking 预算](https://ai.google.dev/gemini-api/docs/thinking)。

### 预算档位与取舍

在请求配置里设 `thinkingBudget` 参数，范围 0 到 24,576 token。

**预算 0：**关闭 thinking。响应最快、成本最低、没有推理开销。用于大量级的分类、抽取和摘要——这些不需要结构化推理。

**预算 -1（动态）：**模型按提示词复杂度自选推理深度。Google 直连 API 的默认值。经 OpenRouter 时，必须显式把 `max_tokens` 设为 -1 才得到动态模式；整个 reasoning 配置不写则 thinking 关闭。推荐给大多数需要推理的工作负载：简单提示词不浪费重推理，任务需要时再开。

**预算 1,024 到 8,192：**中等到重度推理。用于多步分析、结构化编码任务和研究型问题。

**预算 24,576（最大）：**最深推理、最高成本。用于复杂数学、科学问题和准确性值得这份开销的硬核编码。

### 关键约束

两个约束不知道的话会在生产里报错，请在写第一个请求前了解：

- `thinkingBudget` 和 `thinkingLevel` 不能出现在同一个请求里。`thinkingBudget` 属于 Gemini 2.5 系列，`thinkingLevel` 属于 Gemini 3 系列。两个都传返回 400。
- 结构化 JSON 输出和 Search Grounding 互斥，同一个请求不能同时开。

### 通过 OpenRouter 配置

用 `extra_body` 参数带 `reasoning` 键，即可通过 OpenRouter 的 API 设置 thinking 预算：

```
from openai import OpenAI

client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key="<your-openrouter-key>",
)

response = client.chat.completions.create(
    model="google/gemini-2.5-flash",
    messages=[{"role": "user", "content": "Solve this step by step: if f(x) = 3x^2 + 2x - 5, find all roots."}],
    extra_body={"reasoning": {"max_tokens": 8192}}
)

print(response.choices[0].message.content)
```

彻底关闭 thinking 把 `max_tokens` 设 0；动态模式设 -1。

## Gemini 2.5 Flash vs Flash Lite vs Pro

按你的工作负载要求选：

**用 [Gemini 2.5 Flash](https://openrouter.ai/google/gemini-2.5-flash)** 处理大多数 agentic 和推理负载。需要 thinking 能力又不想付 Pro 级成本时，它是默认推荐。

**用 [Gemini 2.5 Flash Lite](https://openrouter.ai/google/gemini-2.5-flash-lite)** 做不需要 thinking、以单请求成本为首要约束的大流量分类、抽取或翻译。Flash Lite 上 thinking 默认关闭。

**用 [Gemini 2.5 Pro](https://openrouter.ai/google/gemini-2.5-pro)** 做准确性值得 5 到 10 倍于 Flash 成本溢价的复杂推理任务：前沿数学、硬核编码挑战和多步科学分析。

## 常见问题

### Gemini 2.5 Flash 免费吗？

Google AI Studio 提供带速率限制的免费档。免费档上你的提示词和响应会被用于改进 Google 的产品，拿用户数据使用前先看[服务条款](https://ai.google.dev/gemini-api/terms)。OpenRouter 的免费档不含 Gemini 2.5 Flash，需要至少 $5 额度余额。Vertex AI 给新 Google Cloud 账户提供 $300 试用额度。

### Gemini 2.5 Flash 的 thinking 预算是什么？

`thinkingBudget` 参数（范围 0 到 24,576 token，或 -1 动态）控制模型在作答前做多少内部推理。预算 0 关闭 thinking：最快最便宜。预算 -1 开启动态模式：模型按提示词复杂度自动调。Google 直连 API 上 -1 是默认。经 OpenRouter 除非显式请求（如 `extra_body={"reasoning": {"max_tokens": -1}}` 取动态，或任何正预算）否则 thinking 是关的。更高的固定预算提升复杂任务质量，但增加延迟和成本，按输出 token 费率计费。

### Gemini 2.5 Flash 和 GPT-4o 怎么比？

Flash 支持 1M token 上下文窗口，GPT-4o 是 128K；Flash 还带 GPT-4o 没有的可配置 thinking。Flash 的每 token 定价更低。GPT-4o 有更广的第三方生态支持和更长的生产履历。本文没有两套模型在同一批评估上的直接基准对比，当前第三方评测数据用 [OpenRouter 排行榜](https://openrouter.ai/rankings)。

### 能用 Gemini 2.5 Flash 做图像生成吗？

不能。Gemini 2.5 Flash 只输出文本。图像输入是支持的——模型可以处理和推理图像。图像生成请去 [Gemini 2.5 Flash Image](https://openrouter.ai/google/gemini-2.5-flash-image)，那是一个有独立定价的模型。

### 哪些提供商在 OpenRouter 上服务 Gemini 2.5 Flash？

三家：Google AI Studio、Google Vertex Global 和 Google Vertex。OpenRouter 按实时的吞吐和在线率自动路由到最健康的提供商。你也可以用 OpenRouter 的[提供商路由控制](https://openrouter.ai/docs/guides/routing/provider-selection)钉定某一家。

### Gemini 2.5 Flash 和 Flash Lite 有什么区别？

Flash 带可配置的 thinking（预算 0 到 24,576）和更高质量的输出。Flash Lite 为超低延迟和成本优化，thinking 默认关闭（但可以开启）。推理能力重要时用 Flash；单请求成本是首要约束的大流量任务用 Lite。
