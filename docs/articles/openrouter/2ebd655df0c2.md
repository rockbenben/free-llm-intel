对于大批量的工作或不需立即完成的请求，你现在可以使用新的 [batch API](https://openrouter.ai/docs/batch-quickstart)。提交批次时，服务商可以在 24 小时窗口内自行选择何时完成请求，作为交换，他们通常只收正常 per-token 价格的 50%（有时更低）。

目前适用于 [70 多个模型](https://openrouter.ai/models?variant=batch)。使用方法见 [Batch API 文档](https://openrouter.ai/docs/batch-quickstart)。

实践中我们观察到，你几乎从不等接近 24 小时。在我们两周 beta 期间完成的 23 万+ 批次中，中位数 7 分钟完成，90% 在一小时内完成。

Batch 是一个异步 API，适合你能接受高度可变响应时间的负载，例如给语料打标签、回填 embeddings、给 eval 集打分、总结积压工单，或在夜间对几千行数据跑同一个 prompt。

## Batch API 如何工作

带上你的请求列表调用 `api/v1/batches`，并指定使用哪种端点形态。Chat completions、responses、messages 和 embeddings 都支持。例如：

```
curl https://openrouter.ai/api/v1/batches \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -d '{
  "endpoint": "/v1/chat/completions",
  "model": "google/gemini-3.8-flash",
  "requests": [
    { "custom_id": "ticket-0001", "body": { "messages": [{ "role": "user", "content": "Summarize this ticket in one sentence." }] } },
    { "custom_id": "ticket-0002", "body": { "messages": [{ "role": "user", "content": "Summarize this ticket in one sentence." }] } }
  ]
}'
```

请求之后，开始轮询 `GET /api/v1/batches/:id`，直到状态变为 `completed`、`failed`、`expired` 或 `cancelled`。完成的批次会在同一响应中内联返回结果。

## 大多数批次几分钟就完成

我们查看了两周 beta 期间完成的批次，测量从受理到结果完成的时间。中位数是 7 分钟，90 分位是 1.0 小时，99 分位是 10.3 小时。我们还发现：一天中的提交时刻比你发送的请求数量影响更大。

## 批次支持什么

- 请求形态：你已经在发给 OpenRouter 的任何文本请求体形态都受支持，包括 chat completions、responses、messages 和 embeddings。
- 路由：每个批次在单一服务商上执行。默认情况下，在应用你的服务商白名单、数据政策和 BYOK 设置后，我们会为该模型选择最便宜的 batch 端点。
- BYOK：配置了[服务商密钥](https://openrouter.ai/docs/guides/overview/auth/byok)后，在支持该功能的服务商上，批次会经由你的密钥路由，你只需支付 BYOK 费用。
- 按请求的结果：每个结果独立返回，少数坏行不会让其余作业失败。
- 保留期：输入和结果保留 30 天，或直到你 `DELETE` 该批次。
- 日志：每个批次都会出现在你[日志的 Batches 标签页](https://openrouter.ai/logs)中，含模型、服务商、状态和成本。
- 定价：折扣适用于 per-token 定价，且因模型而异。Web 搜索调用按标准费率计费。
- 输入：图像和文件必须是公开 URL。音频、视频以及 OpenRouter 自己的 web search 插件在 batch 中不可用（见文档的[限制章节](https://openrouter.ai/docs/batch-quickstart#limitations)）。

## 开始使用

选一个[支持 batch 的模型](https://openrouter.ai/models?variant=batch)，取一个 [API key](https://openrouter.ai/settings/keys)，把你的第一个批次 POST 到 `https://openrouter.ai/api/v1/batches`。[Quickstart](https://openrouter.ai/docs/batch-quickstart) 有完整的请求与响应结构。

在 Discord 的 [#feedback](https://discord.gg/fVyRaUDgxW) 告诉我们你在用批次做什么。
