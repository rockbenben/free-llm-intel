Kilo Code 负责运行编码会话：聊天、编辑、上下文、模式和编辑器/终端里的模型选择器。它不自带模型，而是指望你自带服务商。

OpenRouter 就是那层服务商。接入之后，Kilo 用一枚 API key 就能访问来自 [70+ 服务商](https://openrouter.ai/models)的 300+ 模型，外加路由规则、故障转移和统一计费。Kilo 也提供自己的 Kilo Gateway——其托管计费路径，下文会做对比。整个配置只有三步，而路由控制都集中在一个配置文件里。同一枚 key 在 Kilo 之外也能用，参见[如何在任意 coding agent 中使用 OpenRouter](https://openrouter.ai/blog/tutorials/any-coding-agent/)。

## 三步把 OpenRouter 加入 Kilo Code

第一，在你的 [API Keys 页面](https://openrouter.ai/settings/keys)创建 key。用 Google 或 GitHub 登录。除非你只用免费模型，否则在[定价页](https://openrouter.ai/pricing)充值。按量付费没有最低消费。

第二，从齿轮图标打开 Kilo Code 的 Settings，进入 **Providers** 标签页，在 OpenRouter 上点 Connect，粘贴 key 并保存。

第三，打开模型选择器，输入名称或 slug 来切换模型。实时清单见 [openrouter.ai/models](https://openrouter.ai/models)——目录会随服务商上新而变化。

Kilo 会把该服务商配置写入 `kilo.json`（或 `~/.config/kilo/kilo.json`），因此 VS Code 扩展和 CLI 共享同一份配置。Providers 标签页会替你编辑该文件；CLI 用户也可直接改文件。已保存但没有额度的 key 在第一次付费请求时仍会失败，所以测试付费模型前先充值。

## 用 kilo.json 控制路由与超长 prompt

Kilo 会把模型 `options` 下的任何内容原样转发给 OpenRouter 作为 `providerOptions.openrouter`，不做校验。正是这个透传让你在 Kilo 内用上 OpenRouter 的[服务商路由](https://openrouter.ai/docs/guides/routing/provider-selection)。把 `provider` 块放在 `models.{modelId}.options` 下：

```
{
  "provider": {
    "openrouter": {
      "models": {
        "anthropic/claude-sonnet-4.5": {
          "options": {
            "provider": {
              "sort": "price",
              "order": ["Anthropic", "Google"],
              "only": ["Anthropic"],
              "data_collection": "deny",
              "zdr": true
            }
          }
        }
      }
    }
  }
}
```

每个字段都对应一个 OpenRouter 路由参数：`sort` 按 `price`、`throughput` 或 `latency` 排序；`order` 设置服务商偏好；`only` 用于宁失败也不越出白名单；`data_collection` 与 `zdr` 用于数据政策。嵌套层级必须精确——把 `provider` 块放在根级 `provider.openrouter` 下不起任何作用；而且因为 Kilo 透传字段不校验，拼错的字段会被无声忽略。请严格照上面的路径写。

对超出模型上下文窗口的 prompt，OpenRouter 的 [middle-out transform](https://openrouter.ai/docs/guides/features/message-transforms) 会从模型注意力最低的中间部分删减内容，而不是拒绝请求。在同一个 `options` 块中开启：

```
{ "options": { "transforms": ["middle-out"] } }
```

## 在 Kilo 内运行免费模型

OpenRouter 有 [20+ 免费模型](https://openrouter.ai/models?max_price=0)。在 Kilo 的模型选择器里输入 `free` 即可筛选。未充值时，免费模型为每天 50 次请求、每分钟 20 次。充值 $10 以上后，每日上限升至 1,000。

分清两条免费路径。OpenRouter 免费模型用的是你的 OpenRouter 账户和限速；而经 Kilo Gateway 提供的 Kilo `kilo-auto/free` 不会碰你的 OpenRouter 额度或路由规则。

私有代码有一个注意点：免费端点可能记录 prompt，因此除非其数据政策对你合适，否则不适合专有源码。加上 `data_collection: "deny"` 可收窄可用的服务商。

## 选 OpenRouter 还是 Kilo Gateway

两者都能把模型送到 Kilo Code 面前，选择取决于你的团队已经在用什么。

当你已经跨多个工具使用 OpenRouter、想要服务商路由控制，或希望一个账户一张账单覆盖你运行的所有 AI 工具时，选 OpenRouter。它对充值收 5.5% 且不加价服务商价格；[BYOK](https://openrouter.ai/docs/guides/overview/auth/byok) 让你通过自己的服务商密钥路由，在按套餐区分的免费额度之外，按等效 OpenRouter 成本收取 5% 费用；当前细节见[定价页](https://openrouter.ai/pricing)。

Kilo Gateway 是原生路径：Kilo 宣传它零加价，账单落在你的 Kilo 账户，路由由 Kilo 管理。如果 Kilo Code 是你唯一的 AI 界面且上面正好有你要的模型，可以先在 Kilo Gateway 比价那个模型，再决定是否承担 OpenRouter 的费用。这主要取决于账户引力——如果 OpenRouter 已在你的技术栈里，把它加进 Kilo，保持一套路由政策即可。

## 常见问题

### OpenRouter 配 Kilo Code 是免费的吗？

部分是。OpenRouter 有 20+ 免费模型可以在 Kilo Code 里用，未充值时上限为每天 50 次请求、每分钟 20 次。充值 $10 以上后，免费模型上限升到每天 1,000 次。Kilo 自己的 `kilo-auto/free` 是另一回事，走 Kilo Gateway。

### Kilo Code 和 OpenRouter 有什么区别？

Kilo Code 是在你的编辑器或终端里运行的 coding agent。OpenRouter 是你在 Kilo Code 内部添加的服务商，用一枚 API key 触达 70+ 服务商的 300+ 模型。两者配合使用。

### 我在 Kilo Code 里如何设置 OpenRouter 的服务商顺序？

在 `kilo.json` 的 `models.{modelId}.options.provider` 下添加 `order` 数组，按偏好顺序列出服务商名，如 `["Anthropic", "Google"]`。再加 `only` 可把请求限制在白名单内。Kilo 会原样转发这些字段而不校验。

### OpenRouter 比 Kilo 自己的 Gateway 更贵吗？

OpenRouter 对充值收 5.5% 费用，但不对服务商价格加价。Kilo 宣传 Kilo Gateway 零加价。如果你已跨工具使用 OpenRouter、或需要路由控制，OpenRouter 通常是运营上更好的选择。

### 我能在 Kilo CLI 里用 OpenRouter 吗？

能。CLI 读取同一份 `kilo.json` 配置，可直接添加 OpenRouter 的服务商配置块和路由选项。VS Code 的 Providers 标签页写的也是同一个文件。
