随着越来越多的应用加入 AI 功能，在面对[超过 500 个模型](https://openrouter.ai/models)可选时，为你的构建选择哪个模型依然很难，甚至更难了。

实践中，这个选择往往没有系统方法：来自社交媒体的一条推荐、一张基准测试榜单，或者一种“某个模型当前最强”的模糊感觉。

这些资源确实有用，但都有同一个局限。基准测试衡量的是固定任务集，推荐反映的是别人的应用。它们都无法告诉你：一个模型在你的 app 里、在你的 harness 上、在你的数据上、在你的 prompt 下会如何表现。

与此同时，新模型每周都在发布，而手动重新评估它们的成本高到让许多团队推迟决策，或者继续用一个已经不再合适的模型。

在 OpenRouter，我们对模型多少有些了解。

我们学到的是：没有绝对最好的模型——只有最适合你正在构建之物的模型。

[Ori Eval](https://openrouter.ai/ori/eval) 帮你找到那个模型，并用证据向你证明。

开始之前，告诉你的 agent：

```
run curl -fsSL https://openrouter.ai/skills/spawn-ori-eval and follow the instructions in its output to get started
```

Ori Eval 会像一位友好而有经验的工程朋友那样，带你找出适合你构建目标的最佳模型——不需要任何 eval 经验。

## Tl;dr

- Ori Eval 用你自己的 prompt 运行你的 agent，对它调用的工具做断言，并用 LLM judge 为开放式回答打分。
- Ori 在运行期间钉住 harness 和模型。环境保持不变，所以如果 eval 结果变了，你知道这个变化只能归因于模型的变化。
- Ori Eval 经由 OpenRouter 路由，因此模型比较覆盖所有模型和实验室。
- 你不需要会写 eval。Ori Eval 会找到你代码中每一处调用模型的地方，问你在乎什么，并写好 eval 文件。
- Eval 文件就是代码。把它放进 CI 阻断回归，新模型发布时再跑一遍。
- 开始时，告诉你的 coding agent：`run curl -fsSL https://openrouter.ai/skills/spawn-ori-eval and follow the instructions in its output to get started`。

## 问一个问题，得到一个带证据的答案

使用 Ori Eval，你只需告诉你喜欢的 coding agent：

> run curl -fsSL https://openrouter.ai/skills/spawn-ori-eval and follow the instructions in its output

你的 agent 把请求交给 Ori Eval。Ori Eval 探索你的代码库，然后带着问题回来。在运行任何评估之前，它先与你一起弄清什么对你重要——是成本、性能、延迟、速度、工具调用准确率，还是别的。然后它选出符合你要求的 5 个最新模型，并与你确认。

收集齐所有必要的需求后，Ori Eval 写一个 `review.eval.ts` 文件，让你的 agent 并行跑过所有候选模型，并返回一张表：

| model | catch | p50 | $/PR | result |
| --- | --- | --- | --- | --- |
| anthropic/claude-opus-5 | 94% | 38s | $0.041 | pass |
| openai/gpt-5.6-sol | 92% | 44s | $0.038 | pass |
| moonshotai/kimi-k3 | 90% | 31s | $0.019 | pass |
| z-ai/glm-5.2 | 86% | 26s | $0.008 | pass |
| google/gemini-3-pro | 84% | 52s | $0.062 | fail (cost) |

推荐自带理由：比如，在你的模型成本标准内 bug 捕获率最高者；而若 bug 审阅量增长，则性价比之选是另一个。

## 从没写过 eval 也没关系

写好 eval 并不容易，所以我们替你把烦人的部分干了。

Ori Eval 扫描你的代码库，找出模型运行的每一处，并展示它的发现：用例全景、确切文件、以及该处当前使用的模型。然后它问你希望 eval 覆盖哪里，以及你最在乎什么：准确率、速度、成本，还是别的？

Ori Eval 对你“采访”结束后，就根据你的回答写出 eval 文件并运行它。

就这么简单。

## 一次又一次，分数始终一致

因为 Ori Eval 本身是一个 agent，它能在整个运行期间钉住 harness、模型和 effort。它还是预调好的：我们已经选定了最适合做评估工作的 harness 和模型，你不必自己操心。

## 一份 eval 检查三件事

Eval 文件是一个用 `bun test` 运行的 `*.eval.ts` 文件。它检查 agent 调用了哪些工具、避开了哪些工具，以及回答的质量：

```
const run = await agent.run("dinner in Lisbon?");
run.tool("search").toBeCalled();
run.tool("delete_file").toNotBeCalled();
run.toComplete();
```

对开放式回答，由 LLM-as-a-judge 打分。Ori Eval 帮你设定评分标准和最低分，于是连棘手的开放式问题也能被评估。

## 每个 bug 都变成可测试的东西

用平实的语言把一个 bug 告诉 Ori Eval：比如，一个客服 agent 连订单都没查就直接退款——相当大的问题。

Ori Eval 写一个断言 `lookup_order` 必须被调用的 eval。这个 eval 失败，证明 bug 存在。然后你修复 agent，eval 通过。断言留在你的测试套件里，你以后总能抓住它。

## 阻断回归，并在格局变化时重跑

把 `ori eval` 加进 GitHub Actions workflow。它像 `bun test` 一样退出，失败的 eval 会让构建失败，回归永远到不了生产。

由于 Ori Eval 写出来的就是普通代码，你也可以轻松地把它安排为定期运行。我们的一位早期 beta 测试者现在每月跑一次模型比较。当新模型发布且表现优于你代码库里的现有模型时，一个 PR 会自动开出，你只需要合并，就能在不经意间收获全部好处。

## 开始使用

告诉你的 coding agent：

```
run curl -fsSL https://openrouter.ai/skills/spawn-ori-eval and follow the instructions in its output to get started
```

就这样。

该 skill 会安装 Ori（我们预调好的 coding agent）、请你登录、对你做访谈，然后运行 eval。如果你使用 [OpenRouter MCP server](https://openrouter.ai/docs/guides/overview/mcp-server)，改为运行 `/spawn-ori-eval`，可跳过 URL。

手动安装 Ori：

```
curl -fsSL https://openrouter.ai/labs/ori/install.sh | bash
```

然后运行 `ori login`。运行 eval 还需要 [Bun](https://bun.sh)。

更多内容见 [Ori Eval 页面](https://openrouter.ai/ori/eval)或 [Ori Eval 文档](https://openrouter.ai/docs/guides/ori/eval)。
