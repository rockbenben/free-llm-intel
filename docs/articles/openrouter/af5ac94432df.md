# In-Region Routing：让你的数据留在美国或欧盟

Cailee Moberg · 2026-09-09

今天我们在去年 10 月上线的 EU 路由之外，正式推出 US In-Region Routing（区域内路由），让你对 AI 工作负载的处理地点拥有可保证的掌控权。发往 `us.openrouter.ai` 的请求在美国境内解密，并且只路由到美国境内的 provider endpoint，因此你的 prompt 和补全内容在请求的整个生命周期内都留在该区域内。`eu.openrouter.ai` 对欧盟做同样的事。

企业对数据驻留和处理地点需要更强的保证。OpenRouter 的 In-Region Routing 让美国或欧盟的配置变得简单。

## 工作原理

通过区域专属的 base URL 发送 API 请求，代替 `openrouter.ai`：

```
https://us.openrouter.ai/api/v1
https://eu.openrouter.ai/api/v1
```

你的 API key、请求体和模型 ID 都无需改动，账号中的 provider 偏好、fallback 和隐私设置也会一并沿用。你可以让某一个服务指向 `us.openrouter.ai`，其余流量继续走 `openrouter.ai`。

发往 `us.openrouter.ai` 或 `eu.openrouter.ai` 的请求会在该区域内解密和处理，只有运行在该区域内的 provider 才能为其服务。如果该区域内没有 provider 提供所请求的模型，请求会以 404 失败（`No endpoints found supporting your data region.`），而不会被路由到区域之外。

区域 endpoint 在同一批模型 ID 下提供全球目录的一个子集。只要至少有一家 provider 能从该区域内部服务某个模型，该模型就会出现在该区域的列表里。要获取实时列表，请通过区域域名调用 [`/api/v1/models`](https://us.openrouter.ai/api/v1/models)，或在 models 页面按 In-Region Routing 筛选（[US](https://openrouter.ai/models?region=us) 或 [EU](https://openrouter.ai/models?region=eu)）。我们会持续为两个区域增加模型和 provider。请到 Discord 的 [#feedback](https://discord.gg/fVyRaUDgxW) 告诉我们接下来希望哪些模型进入区域内。

你也可以用 [Guardrails](https://openrouter.ai/docs/guides/features/guardrails) 对特定 workspace、团队或 API key 强制启用 In-Region Routing。把 guardrail 的允许数据区域设为某一个区域后，OpenRouter 会拒绝任何受覆盖的、从其他主机名到达的请求。可在设置中的 Guardrails 下或通过 [Management API](https://openrouter.ai/docs/api/api-reference/guardrails/list-guardrails) 配置。

In-Region Routing 适用于 Business 和 Enterprise 套餐。

## 在区域内服务的美国/欧盟模型

没有 In-Region Routing 时，使用一家总部位于美国或欧盟的实验室的模型，并不能保证由该区域的数据中心来处理请求。在全球 endpoint 上，来自 OpenAI、Anthropic、Google、xAI、Meta、NVIDIA、Thinking Machines 或 Mistral 的模型可能在服务该请求的 provider 运营的任何地方运行。数据驻留审查关注的是你的请求在哪里被解密、推理在哪里进行，因此一个美国团队即使在全球 endpoint 上使用 [GPT-5.6](https://openrouter.ai/openai/gpt-5.6-terra)、[Claude Opus 5](https://openrouter.ai/anthropic/claude-opus-5) 或 [Gemini 3.6 Flash](https://openrouter.ai/google/gemini-3.6-flash)，也可能通不过合规审查。OpenRouter In-Region Routing 确保请求全程留在你指定的区域：美国或欧盟。

## 区域内可用的中国开放权重模型

开放权重模型进步飞快，把流量转向它们可以显著降低成本。在 OpenRouter 上，无论源自美国还是欧盟的请求，流向开放权重模型的 token 占比都在稳步上升：

![两张 100% 堆叠条形图，展示 2025 年 9 月至 2026 年 8 月开放权重与闭源模型的月度 token 占比。源自美国的请求中开放权重占比从 26% 升至 60%；源自欧盟的请求中该占比从 16% 升至 65%。两者都在 2026 年初越过 50%。](https://openrouter.ai/blog/images/us-in-region-routing-open-weight-share.png)

来自美国实验室的模型，如 NVIDIA 的 [Nemotron 3 Ultra](https://openrouter.ai/nvidia/nemotron-3-ultra-550b-a55b) 和 Thinking Machines 的 [Inkling](https://openrouter.ai/thinkingmachines/inkling)，也是这一增长的一部分。但来自中国实验室的模型仍占绝大部分流量，而这些模型的采购审批可能比较困难。

In-Region Routing 让有数据驻留要求的团队也能获得中国开放权重模型带来的价格和性能优势。当美国或欧盟的 provider 托管某个模型时，请求会发往该 provider，实验室并不参与其中。[DeepSeek V4 Pro](https://openrouter.ai/deepseek/deepseek-v4-pro)、[Kimi K3](https://openrouter.ai/moonshotai/kimi-k3) 和 [GLM 5.2](https://openrouter.ai/z-ai/glm-5.2) 都可通过 US In-Region Routing 使用，因为 Baseten、Fireworks 和 Azure 在美国数据中心为其提供服务。通过 `us.openrouter.ai` 向其中任何一个发送 prompt，都会在美国境内解密和运行。GLM 5.2 也可在 `eu.openrouter.ai` 上使用，由 Mistral 的欧盟数据中心提供服务。

## 确保端到端的区域路由

当一个网关提供区域路由时，可能意味着两件事之一。区别在于：你的 prompt 是否曾在区域之外以明文形式存在。

- **仅推理层的区域路由。** 网关把 provider 的推理固定在你的区域。但请求本身会在网关所在的任何地方被解密和处理，然后才转发给 provider。在这部分链路上，你的 prompt 位于区域之外的明文状态。Server tools 的区域化常常被忽视，这可能导致你的 prompt 数据离开司法辖区。例如，web search 有时会在区域化推理 endpoint 上使用全球实例。
- **端到端的区域路由。** OpenRouter 的 In-Region Routing 就是这样工作的。它让数据在完整链路上都留在区域内。发往 `us.openrouter.ai` 或 `eu.openrouter.ai` 的请求在区域内解密，每一步都在区域内处理，只有运行在该区域内的 provider 会收到它们。如果区域内没有 provider 能服务该模型，请求以 404 失败（`No endpoints found supporting your data region.`），数据绝不会离开该区域。在某个司法辖区内提供 server tools 之前，我们会全面评估这些工具及其数据运行所在的司法辖区。会把数据送出区域的工具会被禁用，而不是回退到全球基础设施。

当你评估任何网关的数据驻留声明时，请问两个问题。请求在哪里被解密和处理？它的工具在哪里运行？

## 开始使用

In-Region Routing 适用于我们的 Business 和 Enterprise 套餐。可以从你的 [plan settings](https://openrouter.ai/settings/manage-plan) 升级到 Business，或[联系企业团队](https://openrouter.ai/enterprise/form)。

然后从 [US](https://openrouter.ai/models?region=us) 或 [EU](https://openrouter.ai/models?region=eu) 列表中挑选一个模型，把你的请求发送到 `https://us.openrouter.ai/api/v1` 或 `https://eu.openrouter.ai/api/v1`。

[阅读文档了解更多信息](https://openrouter.ai/docs/guides/features/in-region-routing)。
