我们推出了 workspaces，把你的 OpenRouter 项目组织成彼此独立的环境，每个环境有自己的 API key、路由默认值、guardrails 和可观测性。

Workspaces 带给你组织性、灵活性和控制力。如果你属于以下情况，就值得考虑：

- 在一个 OpenRouter 账户上构建多个不同项目的开发者
- 跨多个团队交付的企业
- 拥有多套环境（如 staging 和 production）的 agent

[![Watch the Workspaces launch video](https://img.youtube.com/vi/ZPQil3VlK9Q/maxresdefault.jpg)](https://www.youtube.com/watch?v=ZPQil3VlK9Q)

## 为项目、团队或 agent 设立独立 workspace

每个 workspace 的以下设置互相独立：

| Setting | Description |
| --- | --- |
| [API keys](https://openrouter.ai/workspaces/default/keys) | 创建和管理以 workspace 为作用域的密钥。 |
| [Guardrails](https://openrouter.ai/workspaces/default/guardrails) | 在账户级限制之内，设置约束该 workspace 所有密钥和成员的政策。 |
| [BYOK](https://openrouter.ai/workspaces/default/byok) | 按 workspace 自带服务商密钥，或跨 workspace 共享。 |
| [Routing](https://openrouter.ai/workspaces/default/routing) | 按成本、延迟、吞吐量或 tool-calling 质量优化服务商路由。 |
| [Presets](https://openrouter.ai/workspaces/default/presets) | 保存 system prompt、模型配置和请求参数的快捷方式。 |
| [Plugins](https://openrouter.ai/workspaces/default/plugins) | 为每个 workspace 的 API 请求配置不同的默认插件行为。 |
| [Observability](https://openrouter.ai/workspaces/default/observability) | 按 workspace 连接不同集成，或把所有 trace 发到同一个集成。 |
| [Members](https://openrouter.ai/workspaces/default/members) | 控制哪些团队成员可以访问每个 workspace。 |

**你现有的 OpenRouter 配置位于 Default workspace。** 如果你不需要多 workspace，照常工作即可。

要创建新 workspace，进入你的[主仪表盘](https://openrouter.ai/workspaces)，点击 workspace 选择器 → [**Create Workspace**](https://openrouter.ai/workspaces/new) → 命名并添加描述。你也可以用[管理 API](https://openrouter.ai/docs/api/api-reference/workspaces/list-workspaces)以编程方式创建和管理 workspaces。

更多细节见我们的[文档](https://openrouter.ai/docs/guides/features/workspaces)。

## 账户级的可见性、计费与管控

你的一些 OpenRouter 设置仍会对所有 workspace 生效，把它们当作全局账户设置。以下是各 workspace 共享的内容：

- [Activity](https://openrouter.ai/activity) 与 [Logs](https://openrouter.ai/logs)：纵览一切，可按 workspace 选择性筛选。
- [Credits & Billing](https://openrouter.ai/settings/credits)：所有 workspace 一张账单。
- [Organization](https://openrouter.ai/settings/organization-members)：管理角色和 workspace 分配。
- [Management Keys](https://openrouter.ai/settings/management-keys)：用于跨 workspace 配置的 API key。
- [Privacy](https://openrouter.ai/settings/privacy)：顶层限制适用于所有 workspace，不能被 workspace 级覆盖。

## 常见问题

**1. 我的 workspace 成员能看到该 workspace 的什么？**

在 workspace 内，成员可以创建和管理自己的 API key，并查看其他成员及其角色。成员可以属于多个 workspace。所有组织成员自动有权访问 Default workspace。在账户层面，成员可以查看 Activity 和 Logs。

**2. 我的组织管理员能看到什么？能编辑什么？**

组织管理员在所有 workspace 拥有管理员权限：可以查看和管理每个 workspace 的一切，包括 API key、guardrails、BYOK、路由、presets、插件、可观测性、成员和设置。只有组织管理员可以创建或删除 workspace，并控制成员对各 workspace 的访问。在账户层面，组织管理员管理账单与额度、组织成员与角色、管理 API key，以及账户级的数据政策和允许的服务商/模型。

**3. Management key 可以跨 workspace 使用吗？**

可以。Management key 作用于账户级，可以通过[管理 API](https://openrouter.ai/docs/api/api-reference/workspaces/list-workspaces)在所有 workspace 上执行管理操作。

**4. 不同 workspace 可以有不同的数据政策吗？**

Workspaces 继承账户级数据政策和允许的服务商/模型。在这些约束内，每个 workspace 可以设置更细粒度的 guardrails，进一步限制 API key 和成员活动。账户级政策是天花板；单个 workspace 只能更严格。

**5. 我把某人从 workspace 移除会发生什么？**

成员被移出 workspace 后即失去访问权。移除之前，你必须先删除其在该 workspace 创建的所有 API key。其对其他 workspace 的访问不受影响。注意：只要仍在组织内，所有组织成员都保留 Default workspace 的访问权。

**6. 我的 chatroom/fusion 使用会归属到某个 workspace 吗？**

会。使用 Chat 和 Fusion 侧边栏底部的 workspace 切换器，选择你的使用归属哪个 workspace。切换 workspace 会取消正在进行的 chat 流（Fusion 运行会在后台继续）。你当前的 workspace 通过 cookie 持久化，跨会话保持。
