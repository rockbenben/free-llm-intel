# 当模型消失时保持智能体运行

Kenny Rogers 和 Alex Atallah ·6/15/2026 · 更新于 9/24/2026

提供商下架和限制模型是家常便饭。过去几年里已有 70 多个模型被提供商撤下或弃用。Anthropic 的 [Fable](https://openrouter.ai/anthropic/claude-fable-5) 最近被撤，是我们见过最瞩目、影响最大的一例，但这个模式不新鲜，也不会消失。

OpenRouter 已经替你处理了其中一层。一个模型跑在多家提供商上、其中一家失败或限流时，市场自动把请求转到另一家，零配置。这套[故障转移如何工作](https://openrouter.ai/blog/insights/reliability-failover/)在另一篇文章里讲。

这让单个模型熬得过提供商层面的麻烦，但模型本体消失时它无能为力。那需要的是模型故障转移——首选模型消失时，请求转到另一个模型。实现方式是 Preset（预设）。

把模型 slug 硬编码，等于把你的选择在每个用到它的服务里钉死。模型消失时，唯一的修法是逐个改代码、重新部署，在那之前请求会一直失败。

[Presets](https://openrouter.ai/docs/guides/features/presets)把这个选择从代码里拿走。它是一份有名字的服务器端配置（模型、回退模型、提供商规则、参数和系统提示词），你按 slug 引用它。模型住在 preset 里而不是代码里——你改一处，每个调用该 preset 的服务就自动生效，不用重新部署。

这是一个最简单的 preset 定义，复制过去改模型即可：

```
{
  "models": [
    "anthropic/claude-fable-5",
    "anthropic/claude-opus-4.8",
    "openai/gpt-5.5"
  ],
  "provider": { "allow_fallbacks": true }
}
```

`models` 数组就是你的回退链，按优先级排列。第一个模型不可用时，OpenRouter 试下一个。

## 硬编码 slug vs preset 引用

| 问题 | 硬编码模型字符串 | Preset 引用 |
| --- | --- | --- |
| 提供商限制了模型 | 每个服务都挂，直到你改代码重新部署 | preset 改一次；调用方继续运行 |
| 谁来发布修复 | 每个代码库的负责人 | preset 的负责人 |
| 变更的影响半径 | 每个仓库、每个服务各改一遍 | 改一处，处处生效 |
| 数据政策（ZDR、保留） | 每个请求都要重述 | 在 preset 上设一次 |
| 回滚 | revert 一次 commit 再重新部署 | 重新指定一个历史版本 |

## 直接交给你的 agent

想让编码 agent 把这套接好？复制下面这个提示词：

```
I want to stop hard-coding model slugs so one provider change can't take down my app. Set up an OpenRouter preset and route my calls through it.

1. Create a preset named "customer-support" with a fallback chain: a primary model plus 2 backups in priority order, using the models array.
2. Set provider rules on the preset: allow_fallbacks true, and zdr true if my data policy requires Zero Data Retention.
3. Capture it by POSTing a known-good chat/completions body to https://openrouter.ai/api/v1/presets/customer-support/chat/completions with my OpenRouter API key.
4. Replace the model field in my inference calls with "@preset/customer-support".
5. Keep my OpenRouter API key in an environment variable. Never hard-code it.

Use these references for current shapes:
- Presets: https://openrouter.ai/docs/guides/features/presets
- Provider routing and fallbacks: https://openrouter.ai/docs/guides/routing/provider-selection
```

## 把一个能用的请求捕获成 preset

Preset 可以在[控制台](https://openrouter.ai/settings/presets)里搭，也可以从一个你已经信得过的请求体直接捕获。

把一个已知可用的 chat/completions 请求体发到 [preset 捕获端点](https://openrouter.ai/docs/guides/features/presets)。OpenRouter 持久化其中与 preset 配置重叠的字段（`models`、`provider`、`temperature` 等），忽略 `messages` 这类瞬态字段：

```
curl https://openrouter.ai/api/v1/presets/customer-support/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "models": [
      "anthropic/claude-fable-5",
      "anthropic/claude-opus-4.8",
      "openai/gpt-5.5"
    ],
    "provider": { "allow_fallbacks": true },
    "messages": [
      { "role": "system", "content": "You are a concise support assistant." },
      { "role": "user", "content": "Summarize this ticket in one sentence." }
    ]
  }'
```

该 slug 的 preset 已存在时，这会创建一个新版本并指定为 active；不存在时就创建 preset。请挑一个没被占用的 slug——往已有 slug 上捕获，会用新 active 版本覆盖它的线上配置。响应返回 preset 及其指定版本（此处有删节）：

```
{
  "data": {
    "name": "customer-support",
    "slug": "customer-support",
    "status": "active",
    "designated_version": {
      "version": 1,
      "system_prompt": "You are a concise support assistant.",
      "config": {
        "models": [
          "anthropic/claude-fable-5",
          "anthropic/claude-opus-4.8",
          "openai/gpt-5.5"
        ],
        "provider": { "allow_fallbacks": true }
      }
    }
  }
}
```

## 在代码里引用 preset

现在把推理调用指向 `@preset/customer-support`。模型选择住在 preset 里，底层模型怎么换，这一行都不用动。

先装 SDK：

```
pip install openrouter        # Python
npm install @openrouter/sdk   # TypeScript
```

```
from openrouter import OpenRouter
import os

client = OpenRouter(api_key=os.getenv("OPENROUTER_API_KEY"))

response = client.chat.send(
    model="@preset/customer-support",
    messages=[
        {"role": "user", "content": "Summarize this ticket in one sentence."}
    ],
)
print(response.choices[0].message.content)
```

```
import { OpenRouter } from '@openrouter/sdk';

const client = new OpenRouter({ apiKey: process.env.OPENROUTER_API_KEY });

const response = await client.chat.send({
  chatRequest: {
    model: '@preset/customer-support',
    messages: [
      { role: 'user', content: 'Summarize this ticket in one sentence.' },
    ],
  },
});
console.log(response.choices[0]?.message.content);
```

默认用上面这种 `@preset/slug` 形态。当你想指定一个基座模型、再把 preset 的配置叠在它上面时，用合并形态 `model@preset/slug`；想让两者作为独立请求字段，就用与 `model` 并列的 `preset` 字段。三种形态[Presets 文档](https://openrouter.ai/docs/guides/features/presets)都有。

## 加上回退模型，让请求保持流动

`models` 数组就是熬得过下架的那部分。按优先级传模型，一个不可用时 OpenRouter 顺次往下走。

把你最信任的模型放在最后一个条目，让最终回退是你放心上线的地板。一个倚重 Fable 5 的编码负载，链子排成 `anthropic/claude-fable-5`、然后 `anthropic/claude-opus-4.8`、然后 `openai/gpt-5.5`，就始终留着强模型兜底。

下面是回退真实触发的样子。Fable 5 被限制时，带上述链子的请求照样成功，响应的 `model` 和 `provider` 字段点名了实际服务者：

```
{
  "model": "anthropic/claude-4.8-opus-20260528",
  "provider": "Anthropic",
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "Customer cannot log in because password reset emails are not being received, despite checking spam and confirming the correct email address."
      }
    }
  ]
}
```

OpenRouter 跳过被限制的主力，服务了数组里的下一个模型。你的代码一行没改。

`model` 字段报告实际服务请求的具体版本，所以读起来和你发的 slug 不一样：这里 `anthropic/claude-opus-4.8` 解析到 Anthropic 上的带日期构建 `anthropic/claude-4.8-opus-20260528`。

这里是两层恢复的叠加。提供商层故障转移是自动的：一个模型多家提供商服务时，5xx 或限流就转去下一家提供商。模型层回退靠 `models` 数组，整个主力消失时移到另一个模型。每层的机制见[可靠性与自动故障转移](https://openrouter.ai/blog/insights/reliability-failover/)和[模型路由](https://openrouter.ai/blog/insights/model-routing/)。

## 把数据政策写进 preset

提供商规则就在同一个 preset 里，一条路由政策对所有调用方生效，不用改代码。

```
{
  "models": [
    "anthropic/claude-fable-5",
    "anthropic/claude-opus-4.8",
    "openai/gpt-5.5"
  ],
  "provider": {
    "zdr": true,
    "data_collection": "deny",
    "allow_fallbacks": true
  }
}
```

`zdr: true` 把请求保持在遵守零数据保留的端点上；`data_collection: "deny"` 屏蔽会拿提示词训练或存储的提供商。你还可以用 `only`、`ignore`、`order` 钉住或排除特定提供商，完整列表见[提供商路由](https://openrouter.ai/docs/guides/routing/provider-selection)。

Fable 5 的事在这里变得具体。它的模型页注明 Anthropic 的政策"不允许零数据保留"。preset 上设了 `zdr: true` 后，路由会跳过无法满足规则的 Fable 5，落到数组里下一个能满足的模型。一个开关，服务器端强制执行，覆盖每个引用该 preset 的请求。

## 团队范围的发布与回滚

组织账户下，每个成员都能使用组织 preset——路由决定做一次，全组织共享，而不是抄进每个仓库。

每次捕获或编辑都创建一个新版本并标记为 active。版本历史被保留，一次坏改动离回滚只差一次重新指定。走 API 时，最新被指定的版本永远是运行的那个。重新指定版本和删除 preset 请在[控制台](https://openrouter.ai/settings/presets)操作——API 能捕获和读取 preset，但没有删除端点。

请求里传入的参数会以浅合并覆盖 preset 的值：请求字段优先，你没发的 preset 字段保留。这让单次调用可以只抬一下 `temperature`，不用给 preset 分叉。

## 全部接起来

上面这份数据政策配置已经包含全部三层：模型链、提供商政策，以及（加上之后）系统提示词。用那条 curl 捕获一次，到处引用 `@preset/customer-support`——下次提供商限制某个模型时，你改一份配置，而不是在各个服务里追 slug。

根本不想钉主力模型的话，把链子指向[自更新别名](https://openrouter.ai/docs/guides/routing/routers/latest-resolution)，如 `~anthropic/claude-opus-latest`——它永远解析到该家族最新的模型。

## 从第一个 preset 开始

挑你流量最大的那类调用，在 [openrouter.ai/settings/presets](https://openrouter.ai/settings/presets) 给它建一个 preset、配上回退链，把模型字符串换成 `@preset/你的slug`。这一个动作，就把一次被迫的大迁移变成一次配置编辑。

Preset 和治理工作也很搭：这个熬得过下架的控制点，正是你执行数据处理规则的地方——详见[AI 智能体的人工监督](https://openrouter.ai/blog/tutorials/human-oversight-eu-ai-act-compliance-agent-sdk/)。

> 注：本文讲工程模式，不构成法律建议。出口管制、数据驻留或保留义务，请就你的具体用例和辖区咨询法律顾问。

## 常见问题

### 模型被弃用或限制时我的应用会怎样？

代码硬编码了模型 slug 的话，对该模型的请求开始失败，用过它的每个服务都挂，直到你改代码重新部署。走 preset 路由，你只改一份配置，调用方无需重新部署就能拿到变更。`models` 回退数组还能在你拿主意的期间让请求继续靠备用模型成功。

### Preset 和代码里传 models 数组有什么区别？

`models` 数组设定的是一次请求的回退顺序；preset 把这个数组连同提供商规则、参数和系统提示词存到服务器上的一个 slug 下。你用 `@preset/slug` 引用它，配置就活在一个地方、横跨所有服务，改动不需要编辑代码。

### 请求参数会覆盖 preset 的值吗？

会。请求参数优先于 preset 的值，按浅合并处理：请求级字段覆盖 preset 中的对应字段，你没发送的 preset 字段被保留。

### 能用 preset 强制执行零数据保留吗？

能。把 `provider.zdr` 设为 `true`。OpenRouter 只会路由到遵守零数据保留的端点，跳过无法满足的模型或提供商，并沿你的 `models` 数组落到下一个合格选项。

### preset 改坏了怎么回滚？

每次捕获或编辑都会创建一个新版本并指定为 active。版本历史被保留，你可以重新指定某个历史版本为 active。走 API 时，最新被指定的版本始终是使用的那个。
