# OpenRouter 文本转语音：5 分钟 API 教程

OpenRouter ·9/11/2026 · 更新于 9/24/2026

我们通过 OpenAI 兼容的 `POST /api/v1/audio/speech` 端点支持文本转语音（TTS）。发送文本、一个模型和一个受支持的音色，然后保存或流式接收音频。一个 API key 用同一套请求结构触达[多家提供商](https://openrouter.ai/blog/insights/every-modality-one-api/)的 TTS 模型。

本教程覆盖认证、合成、响应校验、流式，以及模型与音色的更换。

## 太长不看

- TTS 请求发到 `https://openrouter.ai/api/v1/audio/speech`。
- 用 OpenAI Python SDK 时把 `base_url` 设为 `https://openrouter.ai/api/v1`。
- 模型支持别的音色时，改音色的那一行即可；换提供商时，把配套的模型和音色一起改。

![示意图：带文本、音色和输出格式的请求进入 POST /api/v1/audio/speech，到达 Mistral Voxtral Mini TTS 模型——xAI 和 Microsoft 的语音模型是可用备选——返回一个 MP3 音频响应](https://openrouter.ai/blog/images/text-to-speech-routing.png)

*模型在请求体里点名。端点、认证和响应处理不管你选哪家提供商的语音模型都保持不变。*

[音频 API 公告](https://openrouter.ai/blog/announcements/announcing-audio-apis/)覆盖更广的发布内容。语音转文本见我们的[转录指南](https://openrouter.ai/blog/tutorials/transcription-on-openrouter/)。

## 使用 OpenRouter 文本转语音需要什么

创建一个 [OpenRouter API key](https://openrouter.ai/settings/keys)，存进环境变量，别放进源码。

macOS 或 Linux 上，为当前终端会话设变量：

```
export OPENROUTER_API_KEY="your-api-key"
```

所有示例都用 `https://openrouter.ai/api/v1` 作为 base URL，并按 [`Authorization: Bearer` 头](https://openrouter.ai/docs/api/reference/authentication)发 key。

端点接受两个必填字段，外加一个多数模型都要求的音色：

- `model` 选语音模型。
- `input` 装你要朗读的文本。
- `voice` 选该模型支持的音色。只有提供商[文档写明有默认音色](https://openrouter.ai/docs/guides/overview/multimodal/tts)时才能省略，实践上请当必填。

`response_format` 和 `speed` 可选，但显式设输出格式能让响应更可预测——格式支持因模型而异。省略 `response_format` 时我们的端点默认返回 PCM；Mistral Voxtral Mini TTS 只接受 MP3；`speed` 只在支持的模型上改变语速。

成功的请求返回原始音频字节，失败的请求返回 JSON。写入音频文件之前先校验响应。

key 和响应行为都清楚了，就可以生成第一个音频文件。

## 用 cURL 生成你的第一个 MP3

下面这个请求用 Mistral Voxtral Mini TTS 和它的 `en_paul_neutral` 音色，把返回的字节直接存进 `output.mp3`。

```
curl --silent \
  --show-error \
  --fail-with-body \
  --request POST \
  --url https://openrouter.ai/api/v1/audio/speech \
  --header "Authorization: Bearer $OPENROUTER_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "mistralai/voxtral-mini-tts-2603",
    "input": "OpenRouter turns this text into speech through one API endpoint.",
    "voice": "en_paul_neutral",
    "response_format": "mp3"
  }' \
  --dump-header output.headers \
  --output output.mp3
```

这些参数帮你正确处理失败请求。`--fail-with-body` 让 cURL 在 4xx/5xx 响应时以错误退出；因为设了 `--output`，它会服务端的 JSON 错误体写进 `output.mp3` 而不是终端。命令失败时，用 `cat output.mp3` 读错误、重试前删掉文件——别把 JSON 文件当音频播。`--dump-header` 保存响应头，方便你确认内容类型、拿到生成 ID。

播放之前确认 `output.mp3` 存在且有内容：

```
ls -lh output.mp3
```

macOS 上 `afplay output.mp3` 即可播放；Linux 用 `ffplay` 等已装播放器。

把请求搬进应用代码时，先确认请求成功、响应里是音频，再保存。这些检查能防止 JSON 错误响应被写成 MP3 文件。

## 用 Python 生成并保存语音

项目里还没有 `requests` 就先装：

```
python -m pip install requests
```

这个示例先查 HTTP 状态、确认返回的是 MP3 数据，再保存文件：

```
import os
from pathlib import Path

import requests

response = requests.post(
    "https://openrouter.ai/api/v1/audio/speech",
    headers={
        "Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "mistralai/voxtral-mini-tts-2603",
        "input": (
            "OpenRouter turns this text into speech through one API endpoint."
        ),
        "voice": "en_paul_neutral",
        "response_format": "mp3",
    },
    timeout=60,
)

response.raise_for_status()

content_type = response.headers.get("Content-Type", "").split(";")[0]
if content_type != "audio/mpeg":
    raise RuntimeError(f"Expected audio/mpeg, received {content_type}")

Path("output.mp3").write_bytes(response.content)

generation_id = response.headers.get("X-Generation-Id")
print(f"Saved output.mp3. Generation ID: {generation_id}")
```

API 返回 4xx 或 5xx 时 `raise_for_status()` 抛异常，防止应用把错误体当音频存下来。请求成功时，content-type 检查在写文件前确认响应里是音频。记录 `X-Generation-Id`，追踪请求或联系支持时它就是凭据。

SDK 代管响应流时同样的校验依然适用。下一个例子保持 OpenRouter base URL，把文件处理交给 OpenAI Python 客户端。

## 用 OpenAI Python SDK 流式接收响应

我们的 TTS 端点遵循 OpenAI Audio Speech API 的形态。把 OpenAI 客户端指向我们的 base URL，就能把 HTTP 响应边流边写文件：

```
import os
from pathlib import Path

from openai import OpenAI

client = OpenAI(
    api_key=os.environ["OPENROUTER_API_KEY"],
    base_url="https://openrouter.ai/api/v1",
)

with client.audio.speech.with_streaming_response.create(
    model="mistralai/voxtral-mini-tts-2603",
    voice="en_paul_neutral",
    input="OpenRouter can stream this response into an audio file.",
    response_format="mp3",
) as response:
    response.stream_to_file(Path("output.mp3"))
```

这个模式在读响应的同时增量保存文件。渐进播放需要一个能缓冲传入分块的播放器。

JavaScript 用 `arrayBuffer()` 读同一个响应。这个示例在创建文件前先检查状态和 content type：

```
import { writeFile } from "node:fs/promises";

const response = await fetch(
  "https://openrouter.ai/api/v1/audio/speech",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.OPENROUTER_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      model: "mistralai/voxtral-mini-tts-2603",
      input: "OpenRouter returns audio bytes to JavaScript.",
      voice: "en_paul_neutral",
      response_format: "mp3",
    }),
  },
);

if (!response.ok) {
  throw new Error(`HTTP ${response.status}: ${await response.text()}`);
}

const contentType = response.headers.get("content-type")?.split(";")[0];
if (contentType !== "audio/mpeg") {
  await response.body?.cancel();
  throw new Error(`Expected audio/mpeg, received ${contentType}`);
}

await writeFile("output.mp3", Buffer.from(await response.arrayBuffer()));
console.log(response.headers.get("x-generation-id"));
```

要更小的文件、兼容标准播放器时选 MP3。PCM 免去压缩开销，在兼容的实时流式管线里能降延迟。我们以 `audio/mpeg` 返回 MP3、以 `audio/pcm` 返回 PCM——后者可选带 `rate` 和 `channels` 参数，可用格式取决于所选模型。Mistral Voxtral Mini TTS 只接受 MP3，请求 PCM 会得 400。播放裸 PCM 还需要正确的音频参数——把扩展名改成 `.mp3` 并不会转换音频格式。

传输代码在所有受支持模型之间保持不变，而模型与音色两个字段必须保持合法配对。

## 更换 TTS 模型与音色

音色标识符归属于具体模型。同一模型内比较音色可以只改一行。例如当前 [Grok Voice TTS 1.0 模型页](https://openrouter.ai/x-ai/grok-voice-tts-1.0)列了五个内置音色：`eve`、`ara`、`rex`、`sal` 和 `leo`。

从这个模型加音色组合出发：

```
"model": "x-ai/grok-voice-tts-1.0",
"voice": "eve"
```

之后只改音色那一行：

```
- "voice": "eve"
+ "voice": "ara"
```

Grok 的例子同时演示了从 Mistral 换到 xAI 的提供商切换。模型和音色要一起更新——每家提供商暴露自己的模型和音色 ID——而端点、认证、输入和响应检查都不变：

```
- "model": "mistralai/voxtral-mini-tts-2603",
- "voice": "en_paul_neutral"
+ "model": "x-ai/grok-voice-tts-1.0",
+ "voice": "eve"
```

发送请求前请在所选模型页确认两个值——模型可用性和音色目录都会变。

用 Models API 拉取当前的 TTS 模型：

```
curl "https://openrouter.ai/api/v1/models?output_modalities=speech"
```

也可以浏览我们的[文本转语音模型合集](https://openrouter.ai/collections/text-to-speech-models)。

| **模型 ID** | **示例音色** | **值得注意的选项** |
| --- | --- | --- |
| [`mistralai/voxtral-mini-tts-2603`](https://openrouter.ai/mistralai/voxtral-mini-tts-2603) | `en_paul_neutral` | 经 OpenRouter 语音端点输出 MP3 |
| `x-ai/grok-voice-tts-1.0` | `eve`、`ara`、`rex`、`sal`、`leo` | 五个内置音色，覆盖 20 多种语言 |
| [`microsoft/mai-voice-2`](https://openrouter.ai/microsoft/mai-voice-2) | `en-US-Harper:MAI-Voice-2` | `speed`、Azure `style` 与 `styledegree` |

我们的 [TTS 文档](https://openrouter.ai/docs/guides/overview/multimodal/tts)描述了可以通过 [`provider.options.<provider>`](https://openrouter.ai/docs/guides/routing/provider-selection)传给支持它的模型的提供商专属选项。截至 2026 年 9 月，实时目录里没有 OpenAI 的语音模型——依赖提供商专属字段之前先查当前模型列表。

Microsoft MAI-Voice-2 接受 Azure 音色名，还支持文档写明的 0.5 到 2.0 的 `speed` 区间和表现力选项：

```
{
  "model": "microsoft/mai-voice-2",
  "input": "Welcome to the product update.",
  "voice": "en-US-Harper:MAI-Voice-2",
  "response_format": "mp3",
  "speed": 1.0,
  "provider": {
    "options": {
      "azure": {
        "style": "cheerful",
        "styledegree": 1.2
      }
    }
  }
}
```

这些控制保持提供商专属。不支持的提供商可能直接忽略 `speed`，style 也取决于所选音色。请把提供商选项放在与其匹配的模型配置旁边。

模型与音色的选择决定了哪些格式和表现力控制可用，生产路径要把这些设置随每条生成记录一起保留。

## 为生产准备集成

长输入在句子或段落边界切分，按顺序请求每个片段，再用懂格式的工具合并音频。这提升可靠性，也让第一个片段更早返回。

对每个片段应用同样的响应检查：

- 非成功的 HTTP 状态码立即停下。
- 确认 `Content-Type` 与请求的格式一致。
- 拒绝空响应。
- 把 `X-Generation-Id` 连同模型、音色、格式和你的应用请求 ID 一起记录。
- 重试前先给响应分类，让永久性的请求缺陷不会进入退避循环。

429、502、503、524 和 529 值得重试——[速率限制](https://openrouter.ai/docs/api/reference/limits)、提供商错误、临时不可用、超时和提供商过载可能在后续尝试中恢复。响应带 `Retry-After` 头时遵循它，否则用带上限的指数退避，并在少量尝试后放弃。400、401、402 在修正请求、凭证或额度之前不要重试。

多数 TTS 模型按输入文本字符计费，Gemini TTS 按输入输出 token 计费。也有 `deepgram/flux-tts:free` 这样标零成本的模型。估算生产成本前请查当前模型页或 Models API。

这些控制覆盖了可靠性、可追溯性和成本。剩下的失败通常是两类：把错误体存成了音频，或把模型配上了不受支持的音色或格式。

## 排查 OpenRouter TTS 常见错误

### 为什么 MP3 里是 JSON？

API 返回了错误，而你的程序没查状态就把响应体存了。写响应之前调用 `raise_for_status()` 或检查状态码。

### 为什么音频文件是空的或损坏的？

空文件或不可读，通常是请求没返回音频数据，或响应被存成了错误格式。保存前检查响应大小和 `Content-Type`：`audio/mpeg` 存为 MP3；`audio/pcm` 按裸 PCM 处理并配对正确的播放器参数——把扩展名改成 `.mp3` 并不会转换音频。

### OpenRouter 为什么拒绝这个音色？

音色标识符因模型而异。查所选模型页，用它支持的音色之一；每次换模型都重新核对音色。

### 提供商选项为什么没效果？

提供商控制只到达与之匹配的提供商，按提供商 slug 为键。MAI-Voice-2 的 style 控制要放在 `provider.options.azure` 下。有些提供商会静默忽略不受支持的 `speed` 值。

响应检查和提供商专属设置都覆盖后，剩下的问题集中在端点、OpenAI SDK 兼容性和查找当前 TTS 模型上。

## 常见问题

### OpenRouter 有文本转语音吗？

有。向 `https://openrouter.ai/api/v1/audio/speech` 发 POST，带模型、文本输入和该模型支持的音色。我们按所选模型支持的格式返回原始音频字节。

### OpenRouter 的 TTS 兼容 OpenAI SDK 吗？

兼容。SDK base URL 设 `https://openrouter.ai/api/v1`、用你的 OpenRouter API key。模型 ID、音色 ID 和提供商专属控件仍需与所选模型匹配。

### 怎么使用文本转语音 API？

向 `https://openrouter.ai/api/v1/audio/speech` 发带认证的 POST，包含 `model`、`input` 和 `voice`。设一个受支持的 `response_format`，检查 HTTP 状态和 content type，然后把音频字节写入文件或交给兼容播放器。

### OpenAI API 里的 TTS 是什么？

文本转语音通过 Audio Speech API 把文本输入转成生成的音频。我们用同一套请求结构，OpenAI SDK 客户端改一下 base URL、提供 OpenRouter API key，就能调受支持的 OpenRouter TTS 模型。

### 怎么找 OpenRouter 当前的 TTS 模型？

请求 `GET /api/v1/models?output_modalities=speech`，或浏览[文本转语音合集](https://openrouter.ai/collections/text-to-speech-models)。用模型页确认支持的音色和当前定价。

端点、认证和响应检查在这些工作流中保持一致；模型特有的音色、格式和控制，是每次集成或对比前你要确认的值。

## 用 OpenRouter 生成语音

端点、模型、音色和响应检查都就位后，用 cURL、Python、JavaScript 或 OpenAI SDK 都能产出一个可播放的音频文件。请求结构在所有 TTS 模型间保持一致，可用音色、格式和提供商控制则由每个模型决定。

准备好生成第一个文件时就[创建 API key](https://openrouter.ai/settings/keys)。比较模型、为生产做准备时，浏览[文本转语音模型合集](https://openrouter.ai/collections/text-to-speech-models)和 [TTS 参考](https://openrouter.ai/docs/guides/overview/multimodal/tts)。
