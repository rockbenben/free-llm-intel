# Claude 529 过载：这意味着什么以及如何修复它

开放路由器 ·10/28/2026

![Claude 529 过载：这意味着什么以及如何修复它](https://openrouter.ai/blog/images/claude-529-overloaded.png)![Claude 529 过载：这意味着什么以及如何修复它](https://openrouter.ai/blog/images/claude-529-overloaded-dark.png)

来自 Claude 的 529 `overloaded_error` 意味着 Anthropic 的 API 暂时无法满足您所要求的模型。您的密钥、计划和请求都很好，相同的请求通常会在几秒钟后得到处理。为了让应用程序继续正常运行，请先使用退避重试，然后将请求发送到服务相同 Claude 模型的另一个提供商。

大多数人在 Claude Code 中遇到此错误，其中会话因“API 错误：重复 529 过载错误”而停止。我们使用 API 的本地替代来模拟重试示例中的过载，因为真实的重试示例无法按需触发。指南中的每个 OpenRouter 请求都是真实的。

## Tl;博士

- 529 `overloaded_error` 意味着 Anthropic 的 API 超出了所有用户的该模型的容量。 429 是您自己使用时出现的错误。
- 首先使用指数退避和一些随机性重试。 Anthropic 的 SDK 和 Claude Code 已经做到了这一点。
- 当过载持续时，将相同的模型发送给另一个提供商。在 OpenRouter 上，Claude Sonnet、Opus 和 Haiku 5.5 分别由五个提供商提供服务，并且默认路由会为您进行故障转移。
- 对于每个提供商都很忙的罕见情况，请使用“models”列出后备模型。
- 在 Claude 代码中，运行 `ori claude` 在 OpenRouter 上启动会话并获得相同的故障转移。

## 529 超载是什么意思？

当 Anthropic 的 API 的模型流量超出其所能提供的服务时，它会返回 529。响应正文如下所示：
```
{"type": "error", "error": {"type": "overloaded_error", "message": "Overloaded"}}
```
该错误与您无关。 Anthropic 的[错误参考](https://platform.claude.com/docs/en/api/errors) 表示，当 API 在所有用户中具有高流量时，就会发生这种情况，因此此时调用该模型的任何人都可以获取它，无论他们采取什么计划。一位 Max-plan 用户 [报告 Claude Code 重试了八分钟以上](https://github.com/anthropics/claude-code/issues/40134)，然后才放弃。

来自您这边的错误是 429 `rate_limit_error`。这意味着您的组织已经达到了自己的速率限制或支出上限，您可以通过放慢或提高限制来解决它。 529 不是您的使用限制，Claude Code 的[错误参考](https://code.claude.com/docs/en/errors) 表示它不会计入您的配额。当 Anthropic 再次有容量时它会清除，因此您要么等待它，要么将请求发送到现在有容量的地方。接下来的三个步骤两者兼而有之。

## 第 1 步：使用指数退避重试

大多数 529 会在几秒钟内清除，因此请先重试。每次尝试后等待一段时间并添加一些随机性，以便许多客户端不会同时重试。我们将此循环指向一个小型本地服务器，该服务器为前三个请求返回实形 529，然后成功：
```
import random
import time
import requests

# The local stand-in. In production, use https://api.anthropic.com/v1/messages
URL = "http://127.0.0.1:8529/v1/messages"

def call_with_backoff(body, attempts=5):
    for attempt in range(attempts):
        r = requests.post(URL, json=body, timeout=60)
        if r.status_code != 529:
            return r
        if attempt == attempts - 1:
            r.raise_for_status()  # out of attempts: fail now instead of sleeping again
        wait = min(2 ** attempt, 30) + random.uniform(0, 1)
        print(f"attempt {attempt + 1}: 529 {r.json()['error']['type']}, retrying in {wait:.1f}s")
        time.sleep(wait)

r = call_with_backoff({
    "model": "claude-sonnet-5-5",
    "max_tokens": 64,
    "messages": [{"role": "user", "content": "hi"}],
})
print(r.status_code, r.json()["content"][0]["text"])
```

```
attempt 1: 529 overloaded_error, retrying in 1.9s
attempt 2: 529 overloaded_error, retrying in 2.3s
attempt 3: 529 overloaded_error, retrying in 4.0s
200 Hello! How can I help you today?
```
第四次尝试成功了，距离第一次尝试大约八秒。如果你使用 Anthropic 的官方 SDK，那么你已经有了这个。它们[使用指数退避重试 5xx 错误](https://platform.claude.com/docs/en/api/errors)，默认情况下两次，并且您可以使用“max_retries”来提高该次数。

重试涵盖短峰值。当模型持续过载几分钟时，它们没有帮助，并且每次等待都会增加用户感受到的延迟。为此，您需要第二个地方来发送请求。

## 步骤 2：将相同的模型发送给另一个提供商

Anthropic 的 API 并不是 Claude 运行的唯一地方。在 OpenRouter 上，Claude Sonnet 5.5 由五个提供商提供服务，Opus 5.5 和 Haiku 5.5 也是如此。以下是我们的 [endpoints API](https://openrouter.ai/docs/api/api-reference/endpoints/list-all-endpoints-for-a-model) 于 2026 年 10 月 21 日为 Sonnet 5.5 返回的内容：

|供应商|蛞蝓 |每百万代币的输入价格 |
| --- | --- | --- |
|Anthropic | ‘Anthropic’ | 2.00 美元 |
|Amazon Bedrock | `Amazon Bedrock` | 2.00 美元 |
|谷歌顶点人工智能 | `谷歌顶点` | 2.00 美元（全球），2.20 美元（美国或欧洲）|
|天蓝色| `天蓝色` | 2.00 美元（全球），2.20 美元（美国）|
| AWS 上的 Claude 平台 |Claude-AWS 2.00 美元 |

将请求发送到全局端点而不是 Anthropic 不会改变您为此支付的费用。不同提供商之间的延迟和正常运行时间仍然存在差异，[如何评估 LLM 提供商性能](https://openrouter.ai/blog/insights/evaluate-llm-provider-performance/) 展示了如何比较它们。

您无需配置任何内容即可使用它们。当您调用“anthropic/claude-sonnet-5.5”时，我们的[默认路由](https://openrouter.ai/docs/guides/routing/provider-selection)会在为其提供服务的提供商之间传播请求，降低过去 30 秒内出现严重中断的任何提供商的优先级，并在下一个提供商处重试失败的请求。

如果您想选择先选择哪个提供商，请设置“order”：
```
import os

import requests

body = {
    "model": "anthropic/claude-sonnet-5.5",
    "provider": {
        "order": ["anthropic", "amazon-bedrock", "google-vertex"],
        "allow_fallbacks": True,
    },
    "messages": [{"role": "user", "content": "Reply with the word ok."}],
    "max_tokens": 16,
}

r = requests.post(
    "https://openrouter.ai/api/v1/chat/completions",
    json=body,
    timeout=120,
    headers={"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"},
)
data = r.json()
print(r.status_code, data["model"], data["provider"])
```

```
200 anthropic/claude-sonnet-5.5 Anthropic
```
Anthropic 回答了，所以没有发生故障转移。每个响应中的“provider”字段都会命名为其提供服务的提供商，因此您的日志会显示流量何时离开 Anthropic。设置“order”确实会关闭默认的负载平衡。请求遵循您的列表而不是我们的健康排名，并且仅在您列出的提供商失败后才会转移到其余的提供商。

有两个设置可以停止故障转移，如果您仍然看到 529，则值得检查它们：

- `"allow_fallbacks": false` 将请求保留在您列出的提供商上。如果它们都超载，您就会收到错误消息。
- `"only": [...]` 限制哪些提供者可以满足请求。如果它们都没有为模型提供服务，则请求在开始之前就会失败。

我们将 `only` 设置为 `["openai"]` 以查看失败情况：
```
import json
import os

import requests

body = {
    "model": "anthropic/claude-sonnet-5.5",
    "provider": {"only": ["openai"]},
    "messages": [{"role": "user", "content": "Reply with the word ok."}],
    "max_tokens": 16,
}

r = requests.post(
    "https://openrouter.ai/api/v1/chat/completions",
    json=body,
    timeout=120,
    headers={"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"},
)
print(r.status_code)
print(json.dumps(r.json(), indent=2))
```

## 步骤 3：添加后备模型

如果某个模型的每个提供者都同时忙碌，例如在新版本发布后的需求高峰期间，则可以由第二个模型代替。使用“models”按顺序列出模型，并以与步骤 2 相同的方式发送请求：
```
body = {
    "models": ["anthropic/claude-sonnet-5.5", "anthropic/claude-haiku-5.5"],
    "provider": {
        "order": ["anthropic", "amazon-bedrock", "google-vertex"],
        "allow_fallbacks": True,
    },
    "messages": [{"role": "user", "content": "Reply with the word ok."}],
    "max_tokens": 16,
}
```

```
200 anthropic/claude-sonnet-5.5 Anthropic
```
十四行诗是可用的，所以它回答了。如果每个提供者都失败了，我们就会将请求发送到 Haiku 5.5，响应的“model”字段会为其命名。 [模型回退](https://openrouter.ai/docs/guides/routing/model-fallbacks) 会触发第一个模型的任何错误，包括速率限制、停机时间和上下文长度错误。如果列表中的最后一个模型也失败，您将收到其错误消息。

选择一个足以完成您的任务的后备模型。像 Haiku 5.5 这样的较小模型适合日常工作，例如简短摘要或分类，我们的[最低成本推理指南](https://openrouter.ai/blog/tutorials/how-to-get-the-lowest-cost-llm-inference-on-openrouter/)涵盖了如何找到仍然可以完成工作的最便宜模型。对于只有较大模型才能很好处理的工作，请依赖第二个提供商并重试，而不是较小的后备。

## 如何修复 Claude 代码中的 529 错误？

Claude Code 已经为您完成了步骤 1。它[重试瞬态故障最多 10 次](https://code.claude.com/docs/en/errors)，并具有指数退避功能，并且一旦重试结束，它仅显示“API 错误：重复 529 过载错误”。您可以使用“CLAUDE_CODE_MAX_RETRIES”更改计数，但是当模型保持繁忙时，更多重试意味着更长的等待时间。无需任何设置的最快修复方法是运行“/model”并切换模型，因为 Anthropic 会跟踪每个模型的容量。

要保留您选择的模型，请在 OpenRouter 上运行 Claude Code，这会添加步骤 2。最快的方法是 [Ori Harness](https://openrouter.ai/docs/guides/ori/harness)，它会在 OpenRouter 设置到位的情况下启动计算机上已有的 Claude Code：
```
curl -fsSL https://openrouter.ai/labs/ori/install.sh | bash
ori claude --model anthropic/claude-sonnet-5.5
```
Ori 打开浏览器，以便您可以使用 OpenRouter 帐户登录，因此无需创建或粘贴 API 密钥。只有以 `ori claude` 启动的会话才会在 OpenRouter 上运行，并且普通的 `claude` 会像以前一样工作。

要手动设置，请设置三个环境变量：
```
export ANTHROPIC_BASE_URL="https://openrouter.ai/api"
export ANTHROPIC_AUTH_TOKEN="$OPENROUTER_API_KEY"
export ANTHROPIC_API_KEY=""  # must be empty
```
如果您使用 Claude 帐户登录，请运行一次“/logout”并重新启动，以便变量生效。我们的 [Claude Code 指南](https://openrouter.ai/docs/cookbook/coding-agents/claude-code-integration) 建议将 Anthropic 作为您的首要提供商，因为这是 Claude Code 保证可以使用的提供商。当 Anthropic 过载时，请求会故障转移到服务同一模型的其他提供者。

我们以这种方式用 Opus、Sonnet 和 Haiku 5.5 在一个小的错误修复任务上运行了 Claude Code 九次，并且每个会话都完成了。 [Claude Code 与 OpenRouter](https://openrouter.ai/blog/tutorials/claude-code-openrouter/) 涵盖了其余的设置，包括为每个角色选择一个模型。

## 常见问题

### 529 错误是我的错吗？

不会。529 表示 Anthropic 的 API 已能够满足所有用户的该模型的需求。你的钥匙、计划和要求都很好。 429是您自己使用导致的错误。

### Claude 529 能持续多久？

通常需要几秒钟，这就是为什么使用退避重试可以修复大多数问题。在需求量很大的情况下，过载可能会持续几分钟，此时将请求发送给另一个提供商会有所帮助。

### 付费计划或更高级别是否可以防止 529 错误？

不会。更高的级别会提高您的速率限制，这会阻止 429，但 529 来自模型的总需求。从多个提供商处提供模型服务可以减少您的曝光率。

### 如何检查Claude是否已宕机？

Anthropic 在 [status.claude.com](https://status.claude.com) 上发布事件，旧的 status.anthropic.com 地址会重定向到那里。在 OpenRouter 上，每个模型的页面都会显示为其提供服务的每个提供商的最近正常运行时间，例如 [Claude Sonnet 5.5](https://openrouter.ai/anthropic/claude-sonnet-5.5)。
