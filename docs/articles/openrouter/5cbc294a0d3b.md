处理泄露的密钥令人压力山大。旧密钥越少，能泄露的就越少。这就是我们构建 Security Center 的原因。它是一个统一的地方：看到你所有 workspace 的每一个密钥，发现有风险的那些，并一次性禁用、归档或限制数百个。

所有 OpenRouter 套餐类型均可使用。在 [Settings > Security](https://openrouter.ai/settings/security) 下试用。

## 85 名员工，1,000+ 密钥

对泄露密钥最显而易见的防御就是少留密钥。于是我们审计了自己的 OpenRouter 组织——而因为我们用 OpenRouter 构建 OpenRouter，可审计的东西相当多。

我们发现 85 名员工共有超过 1,000 个活跃密钥。很多没有支出上限，还有 168 个已经好几个月没用过——属于早已把它们忘到脑后的员工。

如果一个我们规模的团队都会积累出这么多密钥蔓延，你大概率也有一些。

## Security Center 能告诉你什么

Security Center 有三个标签页：Overview、Key safety 和 IP allowlist。

Overview 把你的密钥分四组计数：无支出上限、永不过期、90 天以上未使用或闲置、可安全移除。数字下方列出优先处理建议：

- 移除未使用的密钥。请每位属主确认后，再归档。
- 设置支出上限。上限能封顶泄露密钥可花掉的钱。
- 复查无过期时间的密钥。换成会过期的密钥，或移除没人需要的。
- 开启密钥支出提醒。当某个密钥跨过其支出上限的一定比例时收到邮件。
- 强制密钥最长生命周期。来自永不过期或超出时限的密钥的请求会被拒绝（包括已有密钥）。

如果没有需要处理的事项，页面会直接告诉你。

![Security Center Overview tab showing four summary cards (No spend limit, Never expires, Never used or idle 90+ days, Safe to remove) and a Recommendations list with actions to remove unused keys, set spend limits, review keys without expiration, and enforce a maximum key lifetime.](https://openrouter.ai/blog/images/security-center-overview.png)

## Key safety：所有密钥一张清单

Key safety 列出你账户下每个 workspace 中仍能发起请求的所有密钥。此前，密钥分散在各 workspace 自己的页面里。清单包含 MCP 和管理密钥，属主、最后使用时间、支出上限和过期时间并排展示。管理员看到所有密钥；成员看到自己创建的密钥。

每个密钥基于泄露副本能造成什么获得一个风险分，归结起来就是它的支出上限和过期时间。

![Key safety tab listing six keys with owner, risk label, status, last used, usage, limit, expiration, and created columns. One key is marked Safe to remove, others In use, Review before removing, or Unknown, with quick filters for keys missing a spend limit or an expiration date.](https://openrouter.ai/blog/images/security-center-key-safety.png)

使用情况决定单独的状态标签。没有记录用量、或闲置六个月且累计花费不足 $1 的密钥，被标记为可“Safe”移除。最近或有实质用量的是“In use”。介于其间的标为“Review”——被用过，但不多、也不是最近。例如累计花费 $3 且五个月没有请求。大概有人曾经把它接到过某个东西上，所以归档前先查清楚谁在依赖它。

## 批量清理

你也可以执行批量操作。按风险或闲置时间筛选，然后选择最多 500 个密钥，一次性全部禁用、归档或添加支出上限。禁用可逆，归档不可逆；添加上限永远不会覆盖别人已经设置过的值。

管理员还可以把任何一条建议对应的密钥和属主复制为 CSV，交给脚本或 agent。

Security Center 只基于密钥元数据、支出、上限和过期时间工作，从不读取你的 prompt 或补全内容。

## 把密钥锁定到你自己的网络

[IP allowlist](https://openrouter.ai/docs/guides/overview/auth/security-settings#ip-allowlist)以前藏在隐私设置里，现在有了自己的标签页。它控制密钥可以在哪里工作。把你的服务器、办公网络和 CI runner 的出口地址加进去，OpenRouter 就会以 `403 Forbidden` 拒绝来自清单之外地址的任何请求。

该清单适用于你账户或组织里的每一个密钥，包括多年前创建的，变更立即生效。每条可以是单个 IPv4 或 IPv6 地址，或一段 CIDR 范围，各自带标签方便你记住它覆盖什么。

![IP allowlist tab listing three entries with address, type, and label columns: a production API server IP, an office network CIDR range, and a cloud VPC IPv6 range, with an Add address button.](https://openrouter.ai/blog/images/security-center-ip-allowlist.png)

IP allowlist 面向 Enterprise 套餐的组织管理员开放。

## 我们如何控制自己的密钥风险

自审计以来，我们落实了一些最佳实践来管住密钥：

- **按计划清理。** 从标记“可安全移除”的密钥开始，与其属主确认后归档。
- **员工离职时查密钥。** 按属主筛选，归档或通过 [SCIM](https://openrouter.ai/docs/guides/features/scim-mappings) 自动吊销没人接手的密钥。
- **给每个密钥设上限和过期时间。**
- **把生产密钥钉在已知地址上。** 如果你在 Pro 或 Enterprise 套餐，把你的服务器和 CI runner 加入 IP allowlist。
- **轮换仍在持续使用的密钥。** [密钥轮换指南](https://openrouter.ai/docs/cookbook/administration/api-key-rotation)讲明了操作顺序。

## 开始使用

Security Center 对所有套餐类型开放。你可以在 [Settings > Security](https://openrouter.ai/settings/security) 找到它。
