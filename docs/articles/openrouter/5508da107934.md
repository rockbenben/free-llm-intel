# 使用 OpenRouter 与 LangChain：ChatOpenRouter 设置指南

OpenRouter ·7/29/2026

你想把 OpenRouter 的 400 多个模型加进现有 LangChain 应用，又不想重建任何东西。这个集成现在有了专用包：PyPI 上的 `langchain-openrouter` 和 npm 上的 `@langchain/openrouter`，但不少老教程还在教 `ChatOpenAI` 加 `base_url` 覆盖的老路子。本指南走现行路径。

把 LangChain 链指向 `ChatOpenRouter` 后，我们的路由层自动处理提供商负载均衡、宕机规避和跨提供商故障转移。你的链代码永远看不到重试，没完成的请求也不收一分钱。参数细节 LangChain 文档有；本指南补上参数背后的路由行为。

![LangChain 应用架构图：链、agent 和一个 ChatOpenRouter 构造器向 OpenRouter 路由层发起一次调用，路由层做负载均衡、自动回退，扇出到 Anthropic、OpenAI、Google、Meta 等多家提供商](https://openrouter.ai/blog/images/langchain-openrouter-architecture.png)

## 快速上手：5 分钟把 OpenRouter 装进 LangChain 应用

三步拿到能用的模型调用：安装、认证、调用。

[OpenRouter](https://openrouter.ai/models) 是一个藏在 OpenAI 兼容 API 背后的模型路由器：一个端点、400 多个模型、70 多家提供商。`ChatOpenRouter` 像其他任何 LangChain 聊天模型一样插进你的链或 agent。模型字符串是唯一 OpenRouter 特有的部分。

### 第 1 步：安装并认证

安装 `langchain-openrouter`，把 key 放进环境。key 在 [openrouter.ai/settings/keys](https://openrouter.ai/settings/keys) 生成。

```
pip install -U langchain-openrouter
export OPENROUTER_API_KEY="sk-or-..."
```

用 `-U` 参数。这个包还在 beta、迭代很快，永远拉最新版。`ChatOpenRouter` 会自动从环境读取 `OPENROUTER_API_KEY`；你管密钥的方式不同的话，也可以显式传 `api_key`。

### 第 2 步：实例化并调用

```
from langchain_openrouter import ChatOpenRouter

model = ChatOpenRouter(
    model="anthropic/claude-sonnet-4.5",
    temperature=0,
    max_tokens=1024,
    max_retries=2,
)

response = model.invoke("Summarize this support ticket in one sentence.")
print(response.content)
```

`temperature`、`max_tokens`、`max_retries` 的表现和任何 LangChain 聊天模型完全一致。`model` 参数就是我们的 `provider/model` 格式 slug。

想在接进 LangChain 之前先确认 key 能用，端点直接说 OpenAI Chat 格式：

```
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "anthropic/claude-sonnet-4.5",
    "messages": [{"role": "user", "content": "Summarize this support ticket in one sentence."}]
  }'
```

同一个 key、同一个模型字符串、同一种响应形态。`ChatOpenRouter` 就是这个端点之上的 LangChain 类型化封装。

### 第 3 步：TypeScript

TypeScript 路径用 `@langchain/openrouter`，形态相同：

```
import { ChatOpenRouter } from '@langchain/openrouter';

const model = new ChatOpenRouter('anthropic/claude-sonnet-4.5', {
  temperature: 0.8,
});

const response = await model.invoke('Summarize this support ticket in one sentence.');
console.log(response.content);
```

用 `npm install @langchain/openrouter` 安装，当前版本在 [npm](https://www.npmjs.com/package/@langchain/openrouter) 上。

完整配置细节在 [OpenRouter 的 LangChain 集成页面](https://openrouter.ai/docs/guides/community/langchain)和 [LangChain 的 ChatOpenRouter 参考](https://docs.langchain.com/oss/python/integrations/chat/openrouter)。

## 选模型：provider/model 字符串

`model` 参数是 OpenRouter 的 `provider/model` 格式 slug，换模型就是一次字符串改动。链里其他任何东西都不用动：提示词、工具定义、输出原样保持。

今天设 `model="anthropic/claude-sonnet-4.5"`，明天换成 `openai/gpt-5-mini` 或 `deepseek/deepseek-r1`，你的链一点不变。

当前的 `provider/model` 字符串从 [openrouter.ai/models](https://openrouter.ai/models) 拿。那个页面展示哪些模型可用、哪些提供商提供、每个每 token 多少钱。本文里的 slug 只是示例，目录才是 source of truth。

LangChain agent 还有一个跳过构造器的简写：

```
from langchain.agents import create_agent

agent = create_agent(model="openrouter:anthropic/claude-sonnet-4.5")
```

`openrouter:provider/model` 前缀告诉 `create_agent` 通过 `ChatOpenRouter` 解析。同样是一次字符串替换，只是高了一层。

## 流式响应

用 `stream_events` 在模型产出的同时拿 token。异步版 `astream_events` 在异步链里做同样的事。

流式和非流式的每 token 费率相同。你为体验流式，不为账单流式。

```
for event in model.stream_events(
    "Explain provider routing in three sentences.",
    version="v3"
):
    if event["event"] == "on_chat_model_stream":
        print(event["data"]["chunk"].text, end="", flush=True)
```

传 `version="v3"` 拿到当前事件 schema。异步形态把 `stream_events` 换成 `astream_events`、加 `async for`：

```
async for event in model.astream_events(
    "Explain provider routing in three sentences.",
    version="v3"
):
    if event["event"] == "on_chat_model_stream":
        print(event["data"]["chunk"].text, end="", flush=True)
```

`usage_metadata` 在最终聚合消息上可用，你不用二次调用就能读 token 计数。

## 工具调用与结构化输出

工具调用用 `bind_tools`，有类型响应用 `with_structured_output`。两者都接受 `strict=True` 强制 schema 遵守。`strict` 对 `function_calling` 和 `json_schema` 方法有效，对 `json_mode` 无效。

### 用 Pydantic schema 绑定工具

```
from pydantic import BaseModel, Field

class GetWeather(BaseModel):
    """Get the current weather for a city."""
    city: str = Field(description="City name, e.g. 'Lisbon'")

model_with_tools = model.bind_tools([GetWeather], strict=True)
result = model_with_tools.invoke("What's the weather in Lisbon?")
print(result.tool_calls)
```

`strict=True` 让模型遵守工具 schema 而不是即兴发挥参数。

### 获取结构化输出

`with_structured_output` 把 schema 绑到整个响应：

```
class TicketSummary(BaseModel):
    sentiment: str
    priority: int
    summary: str

structured = model.with_structured_output(TicketSummary, method="json_schema")
summary = structured.invoke("Customer is furious the export button is broken again.")
print(summary.priority, summary.summary)
```

默认方法是 `function_calling`。传 `method="json_schema"` 在模型支持时使用原生 JSON schema 强制。

不是每个模型都支持每种方法，逐模型能力请查[模型目录](https://openrouter.ai/models)。在 provider 对象里设 `require_parameters: true`（下一节）可以把请求保持在遵守你所发参数的提供商上。

## 提供商路由与回退

`ChatOpenRouter` 通过 `openrouter_provider` 和 `route` 暴露我们的路由层，单条链就能熬过一家提供商宕机，应用里不用加任何额外韧性代码。

默认情况下一次调用会发生什么：我们在服务你所选模型的提供商之间按价格负载均衡，远离过去 30 秒内宕过的提供商，其余作为热回退。你的链代码看不到重试。最终无法完成的请求不计费。

### 用 openrouter_provider 引导提供商

```
model = ChatOpenRouter(
    model="anthropic/claude-sonnet-4.5",
    openrouter_provider={
        "order": ["Anthropic", "Google"],
        "allow_fallbacks": True,
        "data_collection": "deny",
        "sort": "throughput",
    },
)
```

`order` 设定你的提供商偏好；`allow_fallbacks: True` 允许在你偏好的提供商不可用时继续往下落。`sort` 接受 `"throughput"` 或 `"latency"`（速度比价格要紧时）。`data_collection: "deny"` 远离拿你的提示词训练的提供商。`only` 和 `ignore` 放行或排除特定提供商。`require_parameters: True` 把请求保持在支持你正在发送的确切参数的提供商上。

provider 对象的完整参考在 [openrouter.ai/docs/guides/routing/provider-selection](https://openrouter.ai/docs/guides/routing/provider-selection)。

### 跨模型故障转移，不只跨提供商

提供商故障转移默认开启，`route="fallback"` 只是把它显式声明。要同时向不同模型转移，通过 `model_kwargs` 传一个 `models` 数组，我们依序尝试每个模型：

```
model = ChatOpenRouter(
    model="anthropic/claude-sonnet-4.5",
    route="fallback",
    model_kwargs={
        "models": [
            "anthropic/claude-sonnet-4.5",
            "openai/gpt-5-mini",
            "google/gemini-3-flash-preview",
        ],
    },
)
```

`models` 不是具名构造参数，所以搭 `model_kwargs` 的车——后者把额外参数原样转发给 API。主力无法服务请求时，我们先试下一家提供商，再试数组里的下一个模型。给数组配上 `openrouter_provider` 里的 `sort: {by, partition: "none"}`，端点会在所有列出模型上做全局排名而不是逐模型排名。

![自动回退流程图：应用调用 OpenRouter，主提供商因宕机失败，请求在下一家提供商上成功，只对成功的那次计费、零加价](https://openrouter.ai/blog/images/langchain-automatic-fallback.png)

你的 LangChain 链只对一个 `ChatOpenRouter`，我们把请求铺开在各提供商上，你只为成功的那次付费。

## 推理、多模态、缓存与可观测性

每一项都是一个构造参数或请求参数。

### 推理

用 `reasoning` 参数设推理预算：

```
model = ChatOpenRouter(
    model="anthropic/claude-sonnet-4.5",
    reasoning={"effort": "high", "summary": "auto"},
)
```

`effort` 从 `xhigh` 往下到 `high`、`medium`、`low`、`minimal`、`none`。推理 token 数出现在 `usage_metadata.output_token_details.reasoning`，思考花了多少钱一目了然。

### 多模态输入

图像、音频、视频和 PDF 输入通过 `HumanMessage` 内容块传入，和 LangChain 处理多模态模型的方式一致。支持哪些模态取决于模型，逐模型能力请查[目录](https://openrouter.ai/models)。

### 提示词缓存

在消息内容块上放一个 `cache_control: {"type": "ephemeral"}` 断点即可启用缓存。缓存命中体现在 `usage_metadata.input_token_details.cache_read`，每次调用省了多少看得见。成本一侧见[提示词缓存指南](https://openrouter.ai/docs/guides/best-practices/prompt-caching)。

### 可观测性

传 `session_id`（最长 256 字符）归组相关请求，传 `trace` 对象带逐请求元数据。两者都会被转发到你配置的 Broadcast 目的地，trace 直接落进你现有的技术栈，不需要额外埋点。

这些都不要求改动链结构——全是叠加在你已有构建之上的构造参数或请求参数。

## 常见问题与修法

四个问题经常出现，每个都有修法。

### beta 包的版本兼容

`langchain-openrouter` 很新、处于 beta，需要较新的 LangChain，与老版本不向后兼容。请钉到 [PyPI](https://pypi.org/project/langchain-openrouter/) 上的版本、同步升级 LangChain，别从老教程里抄版本号。

### ChatOpenAI + base_url 的老写法

如果你在用早于专用包的 LangChain 版本，把 `ChatOpenAI` 的 `base_url` 指向 `https://openrouter.ai/api/v1`、用你的 OpenRouter key，仍然可用。升不了级时可以这么办。在当前 LangChain 上，专用 `ChatOpenRouter` 包对提供商路由、推理和结构化输出的访问更干净；但现有配置跑得通的话，迁移不必着急。

### 模型每次都返回同一个答案

模型老是给同一个回答，几乎总是 temperature 或缓存行为，不是缺陷。设一个非零 temperature，并检查提示词缓存是否开着。

### 逐模型的参数支持

不是每个模型都支持你能传的每个参数。拿不准时，在 `openrouter_provider` 里设 `require_parameters: true`，我们只路由到接受你参数的提供商；或者先去目录里的模型页核对。

统一到 `ChatOpenRouter` 包、从 PyPI 或 npm 钉版本、模型字符串保持与 [openrouter.ai/models](https://openrouter.ai/models) 同步。设一次 `openrouter_provider`，链里的每次调用都继承跨提供商故障转移——只为成功的运行付费。

## 常见问题

### OpenRouter 和 LangChain 是一回事吗？

不是，它们是组合关系不是竞争关系。OpenRouter 是藏在 OpenAI 兼容 API 背后的模型提供商和路由器，给你 70 多家提供商的 400 多个模型。LangChain 是你构建链和 agent 的编排框架。通过 `ChatOpenRouter`，OpenRouter 作为 LangChain 里的模型来用。

### 怎么把 OpenRouter 用在 LangChain 里？

安装 `langchain-openrouter`，设置 `OPENROUTER_API_KEY`，实例化 `ChatOpenRouter(model="provider/model")`。之后 `.invoke(...)`、`.stream_events(...)`、`.bind_tools(...)`、`.with_structured_output(...)` 都按任何 LangChain 聊天模型的用法调用即可。包还在 beta，版本请从 PyPI 或 npm 钉住。TypeScript 路径用 `@langchain/openrouter`，形态相同。

### LangChain 支持 OpenRouter 的工具调用和结构化输出吗？

支持。工具用 `model.bind_tools([...])`，有类型响应用 `model.with_structured_output(Schema, method="json_schema")`，两者都可加 `strict=True` 强制 schema。这两个是当前 `ChatOpenRouter` 包的一等方法，取代了在老 `ChatOpenAI` 路径上凑 JSON schema 的种种绕行方案。

### 能从 LangChain 设置提供商路由或回退吗？

能。传 `openrouter_provider={...}` 引导提供商，传 `model_kwargs={"models": [...]}` 跨模型故障转移。提供商故障转移默认开启：OpenRouter 按价格负载均衡，并远离过去 30 秒内宕过的提供商。失败请求不计费，只为成功的运行付费。

### 还需要 ChatOpenAI + base_url 那套吗？

在当前 LangChain 上不需要。专用 `ChatOpenRouter` 包是现行路径，对提供商路由、推理和结构化输出的访问更干净。`ChatOpenAI` 覆盖法（base_url 指向 `https://openrouter.ai/api/v1`、用 OpenRouter key）仍然可用，是给早于该包的旧 LangChain 版本的退路。

### 我能用哪些模型？

目录里的 400 多个模型任何一个，用 `provider/model` slug。当前字符串、逐模型能力和定价查 [openrouter.ai/models](https://openrouter.ai/models)。可用模型和每 token 价格都在变，请以目录为准。
