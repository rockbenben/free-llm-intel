# 将 OpenClaw 连接到 OpenRouter

OpenRouter ·6/18/2026 · 更新于 9/24/2026

OpenClaw 从一处驱动跨 Telegram、Discord、Slack、Signal、iMessage 和 WhatsApp 的 AI agent。它是[开源](https://github.com/openclaw/openclaw)的，背后需要一个模型提供商。直连一家提供商，这段关系就全归你：一个 key、一张账单，提供商一有状态不好你的 agent 就停摆。

OpenClaw 内置了 [OpenRouter 支持](https://openrouter.ai/docs/cookbook/coding-agents/openclaw-integration)，一个 key 就能触达 70 多家提供商的 300 多个模型，账单集中在一处，请求自动故障转移到另一家提供商。连接就是一条命令。如果你同时还在跑终端编码 agent，同一个 key 也通用——见[如何把 OpenRouter 接入任意编码 agent](https://openrouter.ai/blog/tutorials/any-coding-agent/)。本指南先讲这个配置，再讲模型格式、故障转移、成本控制和最常见的报错。

## 一条命令把 OpenClaw 连上 OpenRouter

带着你的 key 运行 onboard 命令：

```
openclaw onboard --auth-choice apiKey --token-provider openrouter --token "$OPENROUTER_API_KEY"
```

它把凭证写入 `~/.openclaw/openclaw.json` 并把模型设为 `openrouter/auto`。连好了。

想手动改配置的话，文件位于运行 OpenClaw 的用户主目录下的 `~/.openclaw/openclaw.json`。最小配置需要一个 key 和一个模型：

```
{
  "env": {
    "OPENROUTER_API_KEY": "sk-or-..."
  },
  "agents": {
    "defaults": {
      "model": {
        "primary": "openrouter/openrouter/auto"
      },
      "models": {
        "openrouter/openrouter/auto": {}
      }
    }
  }
}
```

服务器上，key 请设在 `env` 块里而不是 shell profile 里。以服务身份运行在其他用户或 shell 下的进程不会加载交互式 profile，而 `env` 块在进程启动时随进程注入。以后要换 key，编辑 `env.OPENROUTER_API_KEY` 并用 `openclaw gateway run` 重启。

然后确认模型已加载：

```
openclaw models list
```

## 用 openrouter/<author>/<slug> 格式引用模型

OpenClaw 引用 OpenRouter 模型的格式是 `openrouter/<author>/<slug>`。作者前加 `~` 追踪该家族最新版本，不加则钉死具体版本。承诺之前到[模型页面](https://openrouter.ai/models)确认当前 slug——新版本发布时标识符会变。

| 模型 | 引用 |
| --- | --- |
| Claude Sonnet（最新） | `openrouter/~anthropic/claude-sonnet-latest` |
| Gemini Flash（最新） | `openrouter/~google/gemini-flash-latest` |
| DeepSeek | `openrouter/deepseek/deepseek-chat` |
| Kimi（最新） | `openrouter/~moonshotai/kimi-latest` |
| Llama 3.3 70B | `openrouter/meta-llama/llama-3.3-70b-instruct` |

同一模型追加变体后缀可改变路由：[`:free`](https://openrouter.ai/docs/guides/routing/model-variants/free) 路由到免费端点，[`:nitro`](https://openrouter.ai/docs/guides/routing/model-variants/nitro) 按吞吐排提供商，[`:thinking`](https://openrouter.ai/docs/guides/routing/model-variants/thinking) 请求扩展推理。以后要换 agent 的模型，更新 `agents.defaults.model.primary` 并重启 gateway。

Auto Router 的引用是 `openrouter/openrouter/auto`：作者是 `openrouter`，模型是 `auto`。这串双 `openrouter` 很容易写错，也正是下文 `unknown model` 错误的解法。

## 提供商掉线时让 agent 继续跑

一次孤立的 API 调用失败了好重试。一个在多步 Telegram 对话中持有状态的 OpenClaw agent 就没那么好办——中途失败可能留下一条"看似发出其实没发"的消息，或一个永远没返回的工具调用。OpenRouter 在两个层面处理这个。

提供商故障转移是自动的。多数模型由多家提供商服务，OpenRouter 先试的那家宕机或对你限流时，它把同一个请求转给另一家。不用配置，且只为完成的那个请求付费。

模型回退覆盖"模型在所有地方都不可用"的情形。加一个 `fallbacks` 数组，OpenRouter 依序尝试：

```
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "openrouter/~anthropic/claude-sonnet-latest",
        "fallbacks": [
          "openrouter/~google/gemini-flash-latest",
          "openrouter/deepseek/deepseek-chat"
        ]
      }
    }
  }
}
```

两层叠加。提供商故障转移在一个模型背后换提供商，回退数组干脆换模型。看响应的 `model` 字段能确认实际跑的是哪个。完整配置见[模型回退文档](https://openrouter.ai/docs/guides/routing/model-fallbacks)。

提示词有数据驻留或合规要求时，用 `data_collection` 和 `zdr` 提供商路由控制把路由限制在不保留请求数据的提供商上。参数见[提供商选择文档](https://openrouter.ai/docs/guides/routing/provider-selection)，哪些提供商合格见[提供商日志](https://openrouter.ai/docs/guides/privacy/provider-logging)。

## 模型对到 agent 上，控制成本

每个 agent 动作都跑一个能干模型，等于在不需要的事上烧钱。读长文档的研究 agent 需要前沿模型；处理短文本的摘要器用免费的 Llama 就够用；回快问题的机器人用 Gemini Flash 就好。

[Auto Router](https://openrouter.ai/models/openrouter/auto)（`openrouter/openrouter/auto`）以市场智慧为动力，给每个提示词分类，按 OpenRouter 社区过去滚动 7 天在该任务类型上的总支出给候选排名。它为每个请求挑一个高性价比模型，按该模型标准费率收费、无额外路由费。对心跳、状态检查这类多数低风险的 agent 流量，它是不错的默认。

想要显式控制时，OpenClaw 支持按 agent 分模型。在 `agents.overrides.<name>.model` 下做按 agent 覆盖：

```
{
  "agents": {
    "overrides": {
      "researcher": {
        "model": { "primary": "openrouter/anthropic/claude-opus-4.6" }
      },
      "summarizer": {
        "model": { "primary": "openrouter/meta-llama/llama-3.3-70b-instruct:free" }
      }
    }
  }
}
```

成本上：OpenRouter 不给提供商定价加价。按量付费的平台费是 5.5%，这一笔费覆盖统一计费、故障转移和全提供商一个 key。低风险动作上，20 多个免费模型每 token 零成本。自带提供商 key 的话，[BYOK 费用](https://openrouter.ai/docs/guides/overview/auth/byok)是在按套餐而定的免费额度之后、对等价的 OpenRouter 成本收 5%；最新细则见[定价页](https://openrouter.ai/pricing)。每个模型的支出在 [Activity 面板](https://openrouter.ai/activity)跟踪。

一旦你跑多个模型、希望请求熬过宕机、或想改字符串就换模型，统一端点的价值就体现出来了。

## 修最常见的连接错误

**"No API key found for provider 'openrouter'"**：key 没到 OpenClaw。用 `echo $OPENROUTER_API_KEY` 检查，用 `openclaw auth list` 核实认证配置，或重跑 onboard 命令。VPS 上常见的原因是变量在你的交互 shell 里加载了、但在服务的 shell 里没有——请在配置的 `env` 块里设。

**"unknown model: openrouter/auto"**：Auto Router 引用写错了。请用 `openrouter/openrouter/auto`，并在 `agents.defaults.models` 下登记它。OpenClaw 期望完整的 `openrouter/<author>/<slug>` 路径。

**"OpenRouter not responding"**：请求发出去了但没有任何东西回来。按四步排查：在 [openrouter.ai/keys](https://openrouter.ai/keys) 确认额度余额；跑 `openclaw models list` 确认 slug 能解析；跑 `openclaw logs --follow` 读实际错误；确认你的主机能访问 `https://openrouter.ai/api/v1`。一条挡住这个域名的出站规则造成的就是这种"无响应"。

**401 或 403**：账户侧问题——key 无效、被吊销或额度用尽。到 [openrouter.ai/keys](https://openrouter.ai/keys) 检查，更新 `env.OPENROUTER_API_KEY`，重启 gateway。

## 常见问题

### 怎么把 OpenClaw 连到 OpenRouter？

运行 `openclaw onboard --auth-choice apiKey --token-provider openrouter --token "$OPENROUTER_API_KEY"`。它写入凭证并设置 `openrouter/auto` 模型。不需要 base URL，也不需要 `models.providers` 块。

### OpenClaw 用什么模型引用格式？

`openrouter/<author>/<slug>`，例如 `openrouter/deepseek/deepseek-chat`。作者前加 `~` 追踪家族最新版（`openrouter/~anthropic/claude-sonnet-latest`），或追加 `:free`、`:nitro`、`:thinking` 改变路由行为。

### 怎么修 "unknown model: openrouter/auto"？

用 `openrouter/openrouter/auto` 并在 `agents.defaults.models` 下登记它。OpenClaw 期望完整的 `openrouter/<author>/<slug>` 路径，而 Auto Router 的作者就是 `openrouter`。

### OpenClaw 能用 OpenRouter 的免费模型吗？

能。在引用后加 `:free`，例如 `openrouter/meta-llama/llama-3.3-70b-instruct:free`。再配一个回退，免费位被占时 agent 仍能运行。

### 需要给 OpenClaw 设 base URL 吗？

不需要。OpenClaw 的内置 OpenRouter 支持在内部处理路由。设好 API key，用 `openrouter/<author>/<slug>` 引用模型即可。
