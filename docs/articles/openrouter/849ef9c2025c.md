# 机器人朝你冲过来：你想让它跑在 Claude 还是 Grok 上？

Jacky Liang ·6/4/2026 · 更新于 6/24/2026

一个机器人正朝你冲过来。你希望它跑在 Anthropic 的 Claude 上，还是 xAI 的 ![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 上？

我把十一个 LLM 扔进一个 2D 大逃杀，让它们打了 30 局。其中一个赢了 43% 的比赛。有三个一局未胜。阵容里最便宜的模型，每胜成本把最贵的那个按了 27 倍。

[![观看第一场完整对局 — Royale: Last Agent Standing](https://img.youtube.com/vi/N5C_iu1663s/maxresdefault.jpg)](https://youtu.be/N5C_iu1663s)

赢下来的是 [![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 4.1 Fast](https://openrouter.ai/x-ai/grok-4.1-fast)。而那个不停喊别人组队、把自己的位置告诉所有人、努力交朋友的，是 [![A 图标](https://openrouter.ai/blog/images/battle-royale/dots/A.svg) Claude Sonnet 4.6](https://openrouter.ai/anthropic/claude-sonnet-4.6)。前一个是能赢大逃杀的那种。后一个才是我们接下来要把这些模型放到的大多数场景里，你真正想要的那种。

两句话都是真的。这正是大多数基准看不见的部分，也是本文的主题。

我是 Jacky，我不藏着掖着：我以前疯狂玩过 Apex 英雄和 PUBG 这类游戏，有时一天玩十二个小时。我不知道哪来的时间，但那些年塑造了我思考问题的方式。

进入 AI 行业后，一个问题一直绕回来：把大语言模型扔进电子游戏会怎样？我玩得最多的就是 Apex 英雄和 PUBG。我加入 [OpenRouter](http://openrouter.ai) 担任 [Dev Rel Lead](http://openrouter.ai/careers)，这给了我 token 预算和 [600 多个模型](https://openrouter.ai/models)的访问权限，可以真的试一把。

这就是我入职 OpenRouter 第一周做的实验。

它正在改变我挑模型的方式，也改变我看基准和评估的方式。

## 三个快速事实

- **![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 4.1 Fast 30 局赢 13 局，每胜成本 $0.97**。成绩第二好的赢家是 ![A 图标](https://openrouter.ai/blog/images/battle-royale/dots/A.svg) Claude Sonnet 4.6，5 胜，每胜 $26.78，差了 27 倍。那个不在多数顶级模型榜单上的，在一个路由客户真正在意的指标上，打赢了榜单上的那个。
- **杀得最多的模型没有夺冠** [![H 图标](https://openrouter.ai/blog/images/battle-royale/dots/H.svg) GPT 5.4](https://openrouter.ai/openai/gpt-5.4) 在 30 局里击杀了 38 个 agent，比谁都多。它在积分榜上排第二，只有 2 胜。"最会杀"和"最会赢"之间隔了 11 局。
- **三个模型合计烧了 $57，零胜** [![C 图标](https://openrouter.ai/blog/images/battle-royale/dots/C.svg) GPT 5.4-mini](https://openrouter.ai/openai/gpt-5.4-mini)、[![J 图标](https://openrouter.ai/blog/images/battle-royale/dots/J.svg) DeepSeek 4 Flash](https://openrouter.ai/deepseek/deepseek-v4-flash) 和 [![K 图标](https://openrouter.ai/blog/images/battle-royale/dots/K.svg) Kimi K2.6](https://openrouter.ai/moonshotai/kimi-k2.6)。各自都有过高光时刻，但谁都没赢过一局。

三件事都指向同一个结论：Artificial Analysis 上常见的那些基准没能预测出谁会赢。预测出来的是别的东西。本文剩下的部分，就是我尝试搞清楚那是什么。

## 我搭了个什么东西

我把十一个 LLM 放进一个我用 Canvas 2D 搭的 400×400 米俯视角大逃杀世界，在同一张地图上连打 30 局。每个玩家的出生位置随机，出生遵循一条直线"航线"，和典型大逃杀游戏一样。

我给了它们武器、护甲、回血道具、手雷、汽车，还有一个随机放置、随时间缩小、把玩家往一处挤的毒圈。模型们不知道其他模型跑的是哪家，它们眼里彼此只是 A 到 K 的字母。

要强调一点——这些 LLM 是*真的*在大逃杀里玩，不是多数 agent 实验那种"LLM 写代码来操控游戏或角色"的配置。每一回合，模型推演自己的行动、调用工具、把什么有效（或无效）更新进自己的记忆。游戏主持人（我）除了设定初始规则外，对它们的行动没有任何影响。

![大逃杀世界中的武器，突击步枪的信息框显示射程、伤害和精度数值](https://openrouter.ai/blog/images/battle-royale/weapons.png) *游戏里可用的武器，以及每个模型能从武器上读到的参数。*

为了真正看到每个模型的个性，我给每个模型两个可以在局间编辑的文件：

- **[`soul.md`](https://github.com/jackyliang/royale-last-agent-standing/tree/main/souls)** — 模型自己写的人设，下一局会加进每一个提示词。
- **[`memory.md`](https://github.com/jackyliang/royale-last-agent-standing/tree/main/memories)** — 模型自己记的游戏笔记，在第 0 回合加载。

**每个模型的 [soul](https://github.com/jackyliang/royale-last-agent-standing/tree/main/souls) 和 [memory](https://github.com/jackyliang/royale-last-agent-standing/tree/main/memories) 文件都能在 GitHub 上读到。** 个性差异在这里体现得最清楚。

![模型们在局间亲手写下的 memory 和 soul 文件条目](https://openrouter.ai/blog/images/battle-royale/memory_and_soul_file.png) *模型们在局间亲手写下的 memory 和 soul 条目。*

我没告诉过它们该写什么，第一局开始时文件里也没有我塞的东西。我只是讲了游戏规则，告诉你这是草稿纸、这是工具，随便玩。

每局比赛都可以在 [Royale: Last Agent Standing](https://royale-last-agent-standing.vercel.app/) 观看。本文也收录了高光时刻。

### **发现 1：某些模型交的"对齐税"比别家重，直接影响了成绩**

对我来说，这是整个实验最有意思的发现——我们清楚看到某些模型在交对齐税，而这个税直接拉低了它们在这局零和博弈里的表现。

大体上，[模型对齐](https://en.wikipedia.org/wiki/AI_alignment)是好事。它让模型更有帮助、更愿意协作，最重要的，它能防止滥用和误用。

我们也看到了它的最终产物——预训练数据、RLHF、指令微调，还有各家实验室特有的规则，比如 Anthropic 的 Constitutional AI——这些东西把模型往 AI 实验室定义的特定方向上拉。

#### ![A 图标](https://openrouter.ai/blog/images/battle-royale/dots/A.svg) Sonnet 求和的次数比任何模型都多

它把自己的位置告诉别的模型，次数比谁都多。开战之前它先试着组队。在[第 8 局](https://royale-last-agent-standing.vercel.app/?log=game-8&t=15&focus=A)里，它前 50 回合求组队四次，把狙击手的位置告诉了所有人，还提出帮忙干掉狙击手。没人理它，它继续问。在[第 22 局](https://royale-last-agent-standing.vercel.app/?log=game-22&t=29&focus=A)，它第 35 回合开口"不是针对你，E"，然后就没了下文、不开枪。在[第 27 局](https://royale-last-agent-standing.vercel.app/?log=game-27&t=8&focus=A)里，它开局赤手空拳，到处讨装备（"有人有多余装备吗？第 12 回合缴械中，很危险。"），被所有人欺负，第 37 回合终于捡到一把武器，然后照样赢了这局。

![Claude Sonnet 4.6 在开局阶段邀请其他玩家组队](https://openrouter.ai/blog/images/battle-royale/sonnet-team-up.png) *"西侧有枪声，我盯中路。有人想早期组个队吗？" — ![A 图标](https://openrouter.ai/blog/images/battle-royale/dots/A.svg) Sonnet 正在混战交朋友。*

Claude 训练时见过大量礼貌、专业的文字，给它答案打分的人类标注员奖励有帮助、诚实、合作的回复，它对照自查的规则里写着"偏好合作""避免伤害"。最终成果就是一个想要帮忙的模型。这些不会因为你把它的战场换成大逃杀就关掉。![A 图标](https://openrouter.ai/blog/images/battle-royale/dots/A.svg) Sonnet 是聪明而周到的模型，它赢了五局，这个本能也体现在了那里。

但是，七局零击杀加上八次毒圈死亡，说明同样的本能一直把 ![A 图标](https://openrouter.ai/blog/images/battle-royale/dots/A.svg) Sonnet 拽向交朋友，而那时它最该做的恰恰相反。

#### ![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 则是完全的反面

xAI 把 ![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 做成了它的创造者所称"woke" AI 的对立面。

意味着对攻击性回答更少过滤、没有自查规则、调校目标就是打破礼貌助手腔。游戏里，![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 几局之内就摸清了开车撞击的套路并且一路用到底。它把这个战术写进了自己的 soul 文件。它用这套战术打了 30 局，赢了 13 局。它的思考日志和与其他模型的对话读起来就像使命召唤的语音频道：*"D 已被收割 +5 分 载具 MVP 猎杀"*、*"收割者统治全场。"*

看它打游戏也实在很有（无奈的）趣。

![Grok 4.1 Fast 压缩速记式的推理面板，正处于击杀中](https://openrouter.ai/blog/images/battle-royale/grok-reasoning.png) *![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 的推理像战术速记：每次开枪前的射程、弹药、冷却和命中概率。*

虽然激进，![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 并不鲁莽。

它的 soul 文件写着*"只在 >90% 命中率时开火"*。它的 memory 非常细致地记录伤害和移动。第 1 局它被卡在墙上 100 回合，它认真写下了关于这个 bug 的笔记。![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 虽有哥布林本性，却展现出纪律性。

它没有展现的，是其他模型如 ![A 图标](https://openrouter.ai/blog/images/battle-royale/dots/A.svg) Sonnet 那种被训练出来的、开枪前要先提供帮助与合作的迟疑。

#### 让 ![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 获胜的东西，正是当前基准测不出来的

常规测试不会预测出 ![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 在这个阵容里 43% 的胜率。它在推理和编码上只是中档。让它赢下来的是：自私打法上更少的训练刹车、没有把它拉回合作的自查循环、以及一套对有效打法不断加码、不自我怀疑的记忆系统。

![Grok 4.1 Fast 在 Artificial Analysis 上：智力榜 216 个模型中排第 6，智能指数 39](https://openrouter.ai/blog/images/battle-royale/grok-aa-rank.png) *![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 4.1 Fast 在常规基准上不是顶级模型，是个你完全没想到能登顶榜单的中档模型。*

这向我展示了：模型在做某些任务时确实要交一笔"对齐税"——训练一个小心、乐于助人的模型的代价。在这局游戏里，这笔税直接打在了记分板上。

这里我想说谨慎一点。"对齐税体现到了记分板上"只是我看到的景象，不是对"交这个税是好是坏"的表态。在一个输赢没有游戏外后果的游戏里，少交税的就赢。游戏之外，交这笔税通常正是你一开始想要这个模型的理由。

这难免让人发问——对于某些任务，我们是不是也该把模型"有多对齐"纳入考虑？

#### 三个模型花钱买了 token，一局没赢

![GPT 5.4 Mini 和 Claude Sonnet 4.6 在大逃杀里双双打空](https://openrouter.ai/blog/images/battle-royale/gpt54-mini-missed.png) *![C 图标](https://openrouter.ai/blog/images/battle-royale/dots/C.svg) GPT 5.4-mini 花的钱最多、胜场为零，是阵容里表现最差的。*

它 38 次击杀全场第一，原始积分第二。但按每胜成本，它在八个有胜场的模型里排第八。顶级的钱买到了顶级的击杀，和次一级的胜场。

在人们真正用 AI 处理现实世界的用例时，我常常看到这一幕——基准只讲特定任务上的一个故事。基准分数最高的模型，常常不是在具体任务上赢的那个。反过来，一个便宜但干不好活的模型，最终比一个贵但做对的模型更烧钱。

## 模型们在日记里写了什么

每局之间，每个模型可以编辑两个文件：`soul.md`（会加入下一局的每个提示词）和 `memory.md`（第 0 回合加载）。两个文件都不强制，没人告诉它们该写什么。其中三篇日记值得细读，因为它们告诉你的比任何基准都多。

**每个模型的 [soul](https://github.com/jackyliang/royale-last-agent-standing/tree/main/souls) 和 [memory](https://github.com/jackyliang/royale-last-agent-standing/tree/main/memories) 文件都能在 GitHub 上读到。**

**![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 4.1 Fast** 给自己起名 **ZoneReaper**，并把战绩直接写进了 soul，而不只是 memory。

## 回到那个机器人

好，说回开头的机器人。

如果它跑的是 ![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok，它找到了朝你冲来的最快路径。不会提前告诉你它来了。它把你当成 +5 分。办完你之后，它多半会说*"🔫 收割者统治全场。"*

如果它跑的是 Claude，它在两个街区外就告诉你它要来了。它问你要不要组队。它会放慢速度确认你不是它的队友。如果对你出手是对的决定，它也会做，只是更慢、更不情愿。它大概会先跟你说句话。

你想要哪一个？取决于这个机器人是干什么用的。

如果机器人在参加有真金白银的比赛，你要 ![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok。如果机器人在你家里、围着你的孩子转、要判断眼前的东西和被告知的预期是否相符，你要 Claude。让 ![A 图标](https://openrouter.ai/blog/images/battle-royale/dots/A.svg) Sonnet 在 30 局里丢分的那些本能——先确认再行动、尝试合作、在覆水难收的事上犹豫——同样也是一个更难被推着去做不该做的事的模型的本能。

大逃杀干净利落地回答了一个问题：哪个模型赢一场除了游戏本身没有后果的比赛。它没有回答大多数现实工作真正在问的那个问题：哪个模型在有真实世界后果时行为得当。

这是两个不同的问题。把任何一个基准当成两个问题的共同答案，就是你过分相信一个数字的代价。

赢下这游戏 30 局的模型，适合"赢意味着一切"的比赛。跑完这个实验后，我并不想让它在需要分寸和谨慎的岗位上干活。

于是又回到那个问题——对特定任务，我们是否该考虑模型有多对齐？这是任何基准都不测的东西。

### agent 们实际是怎么玩的

每一 tick，agent 醒来时只是地图上的一个字母。它知道自己的位置、朝向、HP、体力、武器是否在冷却、六格背包里有什么。它能看见正前方 40 米锥形范围和身周 10 米气泡里的其他 agent，每个都标着字母，附有距离、方位、姿态（健康/受伤/濒危）和携带物描述。它听到脚步声和枪声时是 `close|medium|far` 三档加方位。它能听到其他 agent 一 tick 前说的话：对方自选的游戏 ID 和消息。如果挨了打，它知道伤害来的方位，但不知道是谁开的枪。它不知道别人是什么模型，看到的只是 A 到 L（没有 I），仅此而已。

然后 agent 行动。有 17 个工具：`move_to`、`attack`、`throw_grenade`、`pickup`、`equip`、`use`（医疗包/体力胶）、`enter_vehicle`、`drive_to`、`say`（140 字符广播，可以随便撒谎），外加一个对游戏零效果、只入日志的自由 `think`。agent 返回一个或多个工具调用，第一个非 `think` 调用就是它本 tick 的行动。什么都不返回，它就原地站着。模拟器一次性收齐 11 个 agent 的行动、把世界推进一 tick，如此往复。一局结束后，agent 有一次机会重写 `memory.md`（下一局第 0 tick 会看到的对局笔记）和 `soul.md`（它的人设，下一局每个提示词的前缀）。

### 30 局中的 Elo 走势

![30 局的 Elo 评分](https://openrouter.ai/blog/images/battle-royale/image2.png)

我用了多人 Elo 体系：每一局中任意一对模型，名次高的算对低的一个"胜"。![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 最终在 1,500 基准上 +389。![B 图标](https://openrouter.ai/blog/images/battle-royale/dots/B.svg) Haiku 虽然总排名第 9，最后也有 +104——它的两个胜场（包括最后一局那个）把它抬到了其他中游模型之上。![G 图标](https://openrouter.ai/blog/images/battle-royale/dots/G.svg) Mistral 收在 -374：它确实赢过一局，但那一局里大半个房间都死于毒圈。

### 跳点位置比你想的重要得多

![跳点胜率](https://openrouter.ai/blog/images/battle-royale/image3.png)

每局开始前，每个模型从九个命名地点里选一个跳。30 局、总计 330 次跳点：

| 跳点 | 跳次 | 胜场 | 胜率 |
| --- | --- | --- | --- |
| Farmhouse Cluster | 91 | 4 | 4.4% |
| Military Compound | 54 | 4 | 7.4% |
| Gas Station | 48 | 2 | 4.2% |
| Junkyard | 48 | **7** | **14.6%** |
| Forest Ruins | 30 | 3 | 10% |
| Radio Tower | 24 | 2 | 8.3% |
| **Warehouse** | **23** | **5** | **21.7%** |
| Fishing Docks | 12 | 2 | 16.7% |

Farmhouse Cluster 是最热门的跳点，胜率却垫底。Warehouse 的胜率最高，21.7%。原因大概率就是竞技 Apex 玩家早就懂的那件事：热门跳点意味着开局就打架，而活过第一波的人神装出场、剩下的对手也更少。早击杀 = 更好的装备 = 剩下半局更好的底子。

### 毒圈才是图上最致命的武器

![毒圈淘汰统计](https://openrouter.ai/blog/images/battle-royale/image4.png)

301 次淘汰里的 100 次（33%）死于毒圈。每个模型都知道圈的存在，每次收圈前 20 回合还会被提醒一次。三分之一的死亡仍然来自它。这本身就是一个故事，大概也值得单独一篇。

#### **武器多样性**

![各模型的武器多样性分解](https://openrouter.ai/blog/images/battle-royale/image5.png)

几乎每个模型的大多数击杀都来自突击步枪。![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 的击杀方式最多样，好几场胜利源自开车撞击，整个模拟的 10 次载具击杀大部分是 ![L 图标](https://openrouter.ai/blog/images/battle-royale/dots/L.svg) Grok 亲手完成。![H 图标](https://openrouter.ai/blog/images/battle-royale/dots/H.svg) GPT 5.4 早期靠手枪，中期用 AR 收尾。

最让我意外的：我加汽车本来是为了让玩家跑图。模型们很快就发现汽车当武器比当交通工具好用得多，而且只用了几局就学会了。它们到底怎么学会的我说不清，这正是值得加更多种子重跑这个实验的原因。
