# 由市场智慧驱动的模型路由

市场的魅力在于：庞大而多元的独立个体集体做出的判断和决策，会优于任何单一专家。OpenRouter 每天承载数万亿 token，我们一直在研究一种新方式，来分享这数百万做模型决策的人的集体智慧。

今天我们为 [Auto router](https://openrouter.ai/openrouter/auto)（`openrouter/auto`）推出重大更新，其决策依据是 OpenRouter 每周超过 55T 的 token 支出。我们发现，由市场支出驱动的模型选择，在广泛的任务类型和成本档位上都优于旧版 Auto router 的选择。通过参考过去 7 天的 OpenRouter 用量，它总能跟上最新模型发布。

过去几周我们已和数千人一起 beta 测试这一方案，今天它已对所有使用 Auto router 的用户上线。现在就可以向我们的任意推理端点发送 `"model": "openrouter/auto"` 试试，或阅读[文档](https://openrouter.ai/docs/guides/routing/routers/auto-router)了解详情。

为驱动这个路由器，我们把在代表性 prompt 抽样上运行的任务分类，转化为一条 Pareto 最优路由曲线。这正是我们在[按任务支出排名的模型榜](https://openrouter.ai/rankings#task-spend)上展示的底层数据。你可以通过 `cost_tier` 参数指定期望的成本档位，选模型时它还会遵守你账户的 guardrails/隐私设置。

## 我们用跨领域基准验证了新 Auto router 的表现

我们为通用性设计这个路由器，因此用一组刻意多样的基准评估它：MMLU Pro（知识）、τ³-bench Banking（agent）、WideSearch（搜索）、DSQA（研究），以及 [SWE-Atlas QnA](https://github.com/scaleapi/SWE-Atlas)（编程）。

要有信心确认新路由器在默认成本档位的选择，我们需要看到它在降低成本的同时达到与旧路由器同级的表现。在多数领域我们都看到了这一点，少数例外是旧版 Auto router 跑不过现代平价模型。在 max 成本档位，我们的标准是前沿级表现，即便最终比旧路由器更贵。

![Two-row comparison of the new router's Default and Max results against corresponding old router settings across MMLU Pro, τ³-bench Banking, WideSearch, DSQA, and SWE-Atlas QnA.](https://openrouter.ai/blog/images/auto-router-comparison-heatmap.png)

新路由器的 Default 对应旧路由器的 `cost_tier=low` 且 `cost_quality_tradeoff=7`。Max 对比 `cost_tier=max` 与 `cost_quality_tradeoff=0`。

| 基准 | 新 *Default* | 旧 *Default* | 新 *Max* | 旧 *Max* |
| --- | --- | --- | --- | --- |
| MMLU Pro (Knowledge) | **85.2% ±0.3** | 86.6% ±0.1 | **91.4% ±0.3** | 88.8% ±0.3 |
| τ³-bench Banking (Agents) | **20.6% ±1.0** | 21.0% ±1.0 | **31.6% ±1.6** | 7.2% ±2.7 |
| WideSearch (Search) | **61.6% ±2.6** | 53.1% ±2.6 | **61.9% ±2.4** | 54.8% ±2.6 |
| DSQA (Research) | **62.9% ±1.6** | 43.2% ±1.7 | **63.0% ±1.6** | 42.3% ±1.7 |
| SWE-Atlas QnA (Coding) | **30.4% ±2.0** | 30.4% ±2.3 | **60.7% ±1.7** | 2.4% ±0.0 |

这些结果反映的是某个时间点的状态，会随社区偏好变化而移动。我们用基准测试来理解不同路由策略之间的相对表现，以建立信心：群体智慧确实能带来更好的结果。我们的假设是，随着更多人采用 OpenRouter，高效的模型选择会随时间持续改进。

## 成本对比

新路由器的默认成本档位在多种负载下都具备成本效率，而 max 允许更大范围的高成本模型参与，适用于性能比支出更重要的场景。

| 基准 | 新 *Default* | 旧 *Default* | 新 *Max* | 旧 *Max* |
| --- | --- | --- | --- | --- |
| MMLU Pro (Knowledge) | **$140.93** | $393.34 | **$255.71** | $449.61 |
| τ³-bench Banking (Agents) | **$155.89** | $320.04 | **$168.41** | $99.36 |
| WideSearch (Search) | **$30.75** | $31.83 | **$36.89** | $31.60 |
| DSQA (Research) | **$276.00** | $147.11 | **$248.83** | $144.18 |
| SWE-Atlas QnA (Coding) | **$297.23** | $463.73 | **$1,325.08** | $205.52 |

任何在多个模型之间切换的路由策略，都会在输入缓存重建时产生一些额外成本。为迁移到更适合新任务的模型，这笔开销通常值得，但如果模型切换过于频繁就会浪费。Auto router 实现了「粘性」行为，在多轮对话中尽量把会话留在同一个模型上，直到当前模型不再是该任务的领先选择。

## 新 Auto router 如何工作

新 Auto router 的决策依据是：所有使用 OpenRouter 的用户在整体上，对你 prompt 所代表的那一类任务实际在用什么模型。可以把它想象成一个始终保鲜的市场指数，用 OpenRouter 的人越多它就越有效。

下面的模型组合图展示了新 Auto router 的路由曲线如何把每类任务映射到 `cost_tier` 设置：low、medium、high、xhigh 和 max。这是某一时点的快照：随着新模型发布和社区用量模式变化，路由曲线会移动。

![New Auto router routing grid showing model selections for code, agents, data, and writing and chat task types across low (cheapest fifth), medium, high, xhigh, and max (priciest fifth) cost tiers, with a provider color legend along the bottom](https://openrouter.ai/blog/images/auto-beta-cost-tier-model-grid.png) *此快照截至 8 月 10 日。最新数据见[榜单页](https://openrouter.ai/rankings)。*

它使用的排名由聚合的匿名支出统计计算而来，保护所有客户的隐私与数据政策。你的 prompt 在传输过程中被分类，无需留存。工作机制如下：

- **分类任务。**一个快速轻量的分类器为每个 prompt 分配约 30 种细粒度任务类型之一，例如代码调试、多步 agent 规划、知识问答、数学、客服、研究报告。
- **按真实支出份额排名。**针对该任务类型，新 Auto router 查找过去 7 天 OpenRouter 社区实际在哪些模型上花钱，类似于我们[榜单页](https://openrouter.ai/rankings)的「Share of Spend」视图。这是实时信号：当人们把工作负载迁移到新模型时，路由器几天内就会跟上。
- **应用你的成本档位。**`cost_tier` 设置（low、medium、high、xhigh 或 max）决定你愿意花多少钱，并选取匹配成本带的候选。low 档路由到每种任务最便宜的可用模型；max 档则从最强、最贵的模型中挑选。
- **带兜底的路由。**选出的模型按用量份额排序，构成首选加备用。路由会遵守你请求和账户上的模型与 provider 限制，如允许的模型、guardrails 和 ZDR 政策。如果分类或排名不可用，路由器会回退到默认模型集合，请求绝不会因路由问题而失败。

跨轮次方面，路由器会记住对话落在哪个模型上，并在后续轮次优先沿用。它通过显式 `session_id`（如有提供）识别对话，否则用消息指纹。每一轮候选仍会从头排名，而被记住的模型只有在仍是顶级候选之一时才会被复用，因此当任务变化时，更合适的模型可以接管。

## 立即试用新 Auto router

Auto router 可以用在你平时放 model 字符串的任何地方：

```
{
  "model": "openrouter/auto",
  "messages": [
    { "role": "user", "content": "Explain quantum entanglement in simple terms" }
  ]
}
```

或设置成本档位并限制候选集：

```
{
  "model": "openrouter/auto",
  "messages": [{ "role": "user", "content": "..." }],
  "plugins": [{
    "id": "auto-router",
    "cost_tier": "max",
    "allowed_models": ["anthropic/*", "openai/*"]
  }]
}
```

`cost_tier` 参数接受 low、medium、high、xhigh 或 max，设定你愿意花的钱：low 路由到最便宜的可用模型，max 始终从最强的模型中挑选。旧版 Auto router 暴露一个数值型 `cost_quality_tradeoff` 设置，0 是高质量档、数值越高越成本敏感，默认为 7。`cost_quality_tradeoff` 参数为向后兼容仍被接受并保留其原有的成本上限行为，若两者同时发送则它优先。

响应中的 `model` 字段会告诉你选中了哪个模型，且没有额外费用：无论哪个模型运行，你都按标准费率付费。细节见[新 Auto router 文档](https://openrouter.ai/docs/guides/routing/routers/auto-router)，包括多轮对话的会话粘性。

## 用 `openrouter/auto-beta` 抢先体验新改进

我们会持续优化这个路由器，改进模型选择与缓存性能。想最先尝试最新路由行为的人可以使用 `openrouter/auto-beta`，这些改动会先落地于此，之后才进入 `openrouter/auto`。新路由器已经在这里运行了几周，数千人在真实负载上使用它。欢迎在我们的 [Discord](https://discord.gg/openrouter) 或通过你的客户经理告诉我们你的体验。
