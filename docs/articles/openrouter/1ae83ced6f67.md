# 测量的扫描文档的最佳 OCR 模型

肯尼·罗杰斯 ·11/10/2026

![扫描文档的最佳 OCR 模型，测量](https://openrouter.ai/blog/images/best-ocr-model.jpg)![扫描文档的最佳 OCR 模型，测量](https://openrouter.ai/blog/images/best-ocr-model-dark.jpg)

将扫描文档转换为可靠的文本很困难。 Tesseract 等经典 OCR 引擎无法处理褪色的打印、手写和传真。视觉模型可以很好地读取这些页面，但有时会写入页面上没有的值。我们根据自己编写的文本制作了 8 个测试页，以便可以检查每个字符，并通过 OpenRouter 上的 15 个视觉模型和 Mistral OCR 以及 Tesseract 来运行它们。

我们测试中最好的 OCR 模型是 Claude Opus 5.5，具有 264 个键值中的 262 个，每 1,000 页价格为 16.42 美元。 Mistral OCR 性价比最高：264 个中的 258 个，售价 2.02 美元。这篇文章展示了结果、需要注意的错误以及捕获这些错误的代码。

这些结果是一个起点。我们的八页不是您的文档，因此了解哪种模型最适合您的工作流程的唯一真正方法是在您自己的扫描中测试候选模型。

## Tl;博士

- 最准确：“anthropic/claude-opus-5.5”。最佳价值：“mistral-ocr”。最便宜的好结果：“inclusionai/ling-3.0-flash-vl”，推理关闭，264 个中的 254 个，每 1,000 页 0.04 美元。
- 在一张褪色的收据上，GPT-6 Luna 和 GPT-6.1 Sol 组成了卡号、wifi 密码和服务器名称。错误率不会显示这一点，因此请检查您实际使用的值。
- 关闭推理使我们测试的五个模型中的四个更快、更便宜，并且没有丢失关键值。
- 标记来自不同实验室的两个廉价模型不一致的单词，捕获 35 个错误单词中的 34 个，每 1,000 页 0.62 美元。

## 我们如何测试

我们根据已知文本渲染每个页面，然后像扫描一样对其进行降级：小幅旋转、模糊、噪声和 JPEG 压缩。五页很普通：一张收据、一封有两个故意拼写错误的信、一张带有勾选框的表格、一份两栏的时事通讯和一张工整的手写便条。其中三个是很困难的：褪色的热敏收据、快速狭窄的手写体和由 12 个由相似字符（0/O、1/I/L、5/S、8/B）组成的序列号的低分辨率传真，因此模型无法从上下文中猜测它们。

![Cafe Verdigris 的扫描热敏收据，向底部褪色，卡号和 wifi 密码几乎难以辨认](https://openrouter.ai/blog/images/best-ocr-model-faded-receipt-scan.jpg)

我们以两种方式对每个成绩单进行评分。字符错误率 (CER) 是与真实文本的编辑距离除以其长度，忽略换行符和 Markdown。键值是管道将使用的 88 个字符串，每页 10 到 15 个，例如总计、日期、卡号、序列号和拼写错误的单词。每个模型都必须在 3 次运行中准确出现，这为每个模型提供了 264 次检查。成本是每个请求的计费“usage.cost”。模型来自截至 2026 年 10 月 8 日的 OpenRouter 目录。

## 当视觉模型读取硬扫描时会出现什么问题？

最严重的错误是一个看起来合理但不在页面上的值。这是打印的褪色收据底部，后面是一次 GPT-6 Luna 运行：
```
CONTACTLESS 32.95
CARD ****9026
SERVED BY: PRIYA
WIFI: verdigris-guest / tide2026
```

```
NET                                 27.46

CONTACTLESS
CARD **** 9027

SERVED BY: SHEVA
WIFI: verdigris_guest / 1freecoffee
```
收据上没有“NET”行。该卡以9026结尾，名称和密码已发明。 GPT-6 Luna 在所有三轮运行中更改了服务器的名称和年份。 GPT-6.1 Sol 在每次运行中编写了不同的虚构密码（“flatwhite24”、“flat9am！”、“flatleaf”）。我们还要求模型写“[?]”而不是猜测。但这并没有帮助：七个模型中有四个从未使用过标记。

重复出现的其他错误：

- O 和 0：15 个型号中的 13 个型号中至少有一个运行中两个传真序列是错误的。只有 Claude Sonnet 5.5 和 GPT-6.1 Sol 每次都能正确读取它们。
- 拼写修复：这封信的签名是“Senior Assosiate”，提示要求准确复制拼写。不管怎样，45 份记录中有 16 份“纠正”了它。
- 勾选框：Claude Sonnet 5.5 和 Haiku 5.5 复制了表单的复选框标签，但删除了勾选的框。

## 步骤 1：将扫描发送到视觉模型

视觉模型生成文本的方式与语言模型生成任何文本的方式相同，因此它倾向于写出文本通常所说的内容，而不是准确地打印出的内容。提示要求它准确复制。这减少了问题，但并没有消除它：45 份记录中的 16 份仍然纠正了这封信故意的拼写错误。您需要`OPENROUTER_API_KEY`中的[OpenRouter API密钥](https://openrouter.ai/docs/quickstart)。图像作为 base64 `image_url` 部分输入（请参阅[图像输入](https://openrouter.ai/docs/guides/overview/multimodal/image-understanding)），因此 OpenRouter 上的每个视觉模型都会接受相同的请求。将其保存为 `transcribe.py`，因为步骤 3 和 4 是从其中导入的：
```
import base64
import mimetypes
import os

import requests

API = "https://openrouter.ai/api/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"}
PROMPT = ("Transcribe all of the text in this scanned document, in reading order. "
          "Copy spelling, numbers and punctuation exactly as they appear, even if they "
          "look wrong. Return plain text only, with no Markdown and no commentary.")


def transcribe(path, model="deepseek/deepseek-v4.1-flash", reasoning={"effort": "none"}):
    mime = mimetypes.guess_type(path)[0] or "image/jpeg"
    with open(path, "rb") as f:
        image = f"data:{mime};base64," + base64.b64encode(f.read()).decode()
    body = {
        "model": model,
        "max_tokens": 16000,
        "messages": [{"role": "user", "content": [
            {"type": "text", "text": PROMPT},
            {"type": "image_url", "image_url": {"url": image}},
        ]}],
    }
    if reasoning:
        body["reasoning"] = reasoning
    response = requests.post(API, headers=HEADERS, json=body, timeout=300)
    response.raise_for_status()
    data = response.json()
    choice = data["choices"][0]
    if choice["finish_reason"] != "stop":
        raise ValueError(f"finish_reason={choice['finish_reason']}: the transcript is incomplete")
    return choice["message"]["content"], data["usage"]["cost"]


if __name__ == "__main__":
    text, cost = transcribe("receipt.jpg")
    print(text)
    print(f"\n${cost:.5f}")
```

```
HARBOR LANE MARKET
1180 Harbor Lane, Unit 4
Portland OR 97209
Tel (503) 555-0148
...
TOTAL 62.86
VISA ****4471 62.86
AUTH 08813C
...

$0.00022
```
每个角色都正确返回，费用约为百分之二美分。数据 URL 从文件扩展名中获取其类型，因此 PNG 和 WebP 扫描也可以工作。要比较模型，请仅更改“model”字符串，并为步骤 2 中无法关闭推理的模型传递“reasoning=None”。

之所以存在“finish_reason”检查，是因为推理标记会根据“max_tokens”进行计数。由于限制为 4,000，Gemini 3.8 Flash 在每次运行时都花费了 3,841 个令牌来推理传真，并在序列号 4 的中途停止。请求仍然返回“200 OK”和“finish_reason: "length"”，因此在没有检查的情况下，管道会在没有注意到的情况下存储简短的记录。

## 步骤 2：关闭转录推理

当模型必须计划答案时，推理会有所帮助。从页面复制文本不需要计划，因此额外的标记主要会增加成本和时间。这就是为什么 `transcribe` 默认发送 `"reasoning": {"effort": "none"}` （参见 [reasoning tokens](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)）。我们重新运行完整的测试，并对每个允许它的模型进行推理：

|型号|键值，开 → 关 | CER，开 → 关 |每 1,000 页成本，开启 → 关闭 |中位秒，开 → 关 |
| --- | --- | --- | --- | --- |
| `米斯特拉莱/Mistral-大-4-0` | 240 → 249 | 4.61% → 0.15% | 6.80 美元 → 1.68 美元 | 47.9 → 5.6 |
| `inclusionai/ling-3.0-flash-vl` | 254 → 254 | 1.05% → 0.19% | 0.12 美元 → 0.04 美元 | 7.2 → 4.0 |
| `openai/gpt-6-luna` | 232 → 232 | 1.49% → 1.08% | 0.54 美元 → 0.22 美元 | 7.8 → 3.8 |
| `deepseek/deepseek-v4.1-flash` | 248 → 249 | 0.20% → 0.23% | 0.20 美元 → 0.16 美元 | 4.8 → 4.5 |
| `qwen/qwen3.8-27b` | 246 → 244 | 0.92% → 2.28% | 1.54 美元 → 0.77 美元 | 10.8 → 8.9 |

在推理开启的情况下，一个 Mistral Large 4 请求推理了 626 秒并且没有返回任何文本（“finish_reason：“错误””）。 Qwen3.8 27B 在推理方面表现更好，因此请测试您自己的页面。 Gemini 3.8 Flash、Grok 4.7 和 GLM 5.3 FlashX 不允许关闭推理，因此通过 `reasoning=None` 来忽略该字段。否则请求失败并显示：
```
400 {"error":{"message":"Reasoning is mandatory for this endpoint and cannot be disabled.","code":400,"metadata":{"provider_name":null}}}
```
## 步骤 3：交叉检查来自不同实验室的两个模型

O 和 0 等相似字符在模糊图像中很难区分。每个模型都根据自己的训练做出决定，因此来自不同实验室的两个模型很少会做出相同的错误选择。他们的文字记录不同的地方通常是图像不清楚的地方。我们测试了六种型号中的每一对。最好的是由 DeepSeek V4.1 Flash 检查的 Claude Haiku 5.5。 Haiku 在 2,964 个单词中出现了 35 个单词错误，而 DeepSeek 按照步骤 2 中的推理，对其中 34 个单词产生了分歧，其中有 10 个错误警报。该对的成本为每 1,000 页 0.62 美元，是 Mistral OCR 的三分之一。两者都使用相同的 API，因此检查是一次额外的调用。 Haiku 被称为“reasoning=None”，因为它在我们的表中是这样运行的：
```
import difflib

from transcribe import transcribe  # the function from step 1

a, _ = transcribe("fax.jpg", model="anthropic/claude-haiku-5.5", reasoning=None)
b, _ = transcribe("fax.jpg", model="deepseek/deepseek-v4.1-flash")
a, b = a.split(), b.split()
for tag, i1, i2, j1, j2 in difflib.SequenceMatcher(None, a, b, autojunk=False).get_opcodes():
    if tag != "equal":
        print("check:", " ".join(a[i1:i2]), "vs", " ".join(b[j1:j2]))
```

```
check: 8LI5-QS0B5O vs 8LI5-QS0B50
check: 30HY-1OHLG7 vs 30HY-10HLG7
```
这是大多数模型出错的两个系列。如果两个模型以相同的方式误读字符，则不会标记任何内容。这种情况在我们的运行中发生过一次，O 都读取为零，因此请尽可能根据列表或校验和验证 ID。该比较还假设两个模型以相同的顺序读取页面。在三轮运行中的一次中，模型以不同的顺序列出了传真的两列，并且每个序列都显示为不一致。

## 步骤4：使用Mistral OCR作为专用引擎

Mistral OCR 是仅针对文档 OCR 训练的模型。在 OpenRouter 上，它作为文件解析器插件中的引擎运行，该插件接受 PDF，每 1,000 页 2 美元。该插件会在模型看到文件之前对其进行 OCR。它返回文本作为响应的文件注释，因此您命名的模型只需回复。将扫描件封装在一页 PDF 中，然后使用任何便宜的型号发送：
```
import base64
import html
import io
import os

import requests
from PIL import Image, ImageSequence

from transcribe import API, HEADERS  # from step 1


def mistral_ocr(path):
    if path.lower().endswith(".pdf"):  # scanned PDFs go as they are
        with open(path, "rb") as f:
            raw = f.read()
    else:  # wrap an image in a PDF in memory, one page per frame of a multipage TIFF
        pages = [p.convert("RGB") for p in ImageSequence.Iterator(Image.open(path))]
        buf = io.BytesIO()
        pages[0].save(buf, "PDF", save_all=True, append_images=pages[1:])
        raw = buf.getvalue()
    pdf = "data:application/pdf;base64," + base64.b64encode(raw).decode()
    pdf_name = os.path.splitext(os.path.basename(path))[0] + ".pdf"
    body = {
        "model": "upstage/solar-mini4",  # any cheap text model; it only has to reply
        "max_tokens": 5,
        "messages": [{"role": "user", "content": [
            {"type": "text", "text": "Reply OK."},
            {"type": "file", "file": {"filename": pdf_name, "file_data": pdf}},
        ]}],
        "plugins": [{"id": "file-parser", "pdf": {"engine": "mistral-ocr"}}],
    }
    response = requests.post(API, headers=HEADERS, json=body, timeout=300)
    response.raise_for_status()
    data = response.json()
    parts = data["choices"][0]["message"]["annotations"][0]["file"]["content"]
    texts = [p["text"] for p in parts if p.get("type") == "text"]  # skip extracted image parts
    text = "\n".join(t for t in texts if not t.startswith(("<file", "</file")))
    return html.unescape(text), data["usage"]["cost"]


text, cost = mistral_ocr("receipt_faded.jpg")
print(text)
print(f"\n${cost:.5f}")
```

```
CAFE VERDIGRIS
22 Quayside Row
Bristol BS1 4QA
VAT No. GB 318 7742 09

27/09/2026 08:17 TILL 2 CHK 0193
...
|  CONTACTLESS | 32.95  |
|  CARD ***9026 |   |

SERVED BY: PRIYA
WIFI: verdigris-guest / tide2026

$0.00202
```
褪色的收据上的每个值都正确显示，包括卡号和密码。 Mistral OCR 旨在保持布局，因此其输出为 Markdown：收据行变为表格，标题为“##”，“&”返回为“&”。这就是该函数对 HTML 实体进行转义的原因。如果您需要纯文本，则删除 Markdown，或者如果LLM接下来读取结果，则保留它。

## 在 OCR 方面，LLM 比 Tesseract 更好吗？

是的，除了干净的打字页面。 Tesseract 5.5 逐行读取字符形状，因此它可以保持清晰的打印效果，并消除噪音和手写体。它完美地转录了这封信和时事通讯。对于褪色的收据，它没有返回任何内容，凌乱的笔迹返回了 11 个值中的 1 个，传真上返回了 15 个值中的 4 个。

## 常见问题

### 哪个LLM最适合 OCR？

我们的测试中使用的是 Claude Opus 5.5。 Gemini 3.8 Flash 和 Grok 4.7 的错误率几乎一样低，但错过了更多连续剧。 DeepSeek V4.1 Flash 和 Ling 3.0 Flash VL 的价格接近每 1,000 页不到 0.20 美元。

### 如何 OCR 扫描的 PDF？

如步骤 4 中所示，使用“mistral-ocr”引擎发送它。或者，将每个页面渲染为视觉模型的图像，或将 PDF 直接发送到读取 PDF 的模型。自由文本解析器不适用于扫描，因为扫描没有文本层。

### 最准确的 OCR 模型是什么？

Claude Opus 5.5 在 264 个键值中有 262 个正确，并且在我们的八次扫描中字符错误率为 0.02%。 Mistral OCR 排名第二，共 264 项，占 258 项，成本仅为其八分之一。

### LLM的 OCR 费用是多少？

在我们的测试中，其价格从每 1,000 页 0.04 美元（Ling 3.0 Flash VL，推理关闭）到 16.42 美元（Claude Opus 5.5）不等。 Mistral OCR 每 1,000 页的成本为 2 美元。模型对图像令牌的计数方式不同，因此请在您自己的页面上衡量成本。

### Mistral OCR 比视觉模型更好吗？

这是我们测试中的最佳价值：264 个键值中的 258 个，每 1,000 页 2.02 美元，仅落后于 Claude Opus 5.5。它返回保留布局的 Markdown，而视觉模型返回您要求的任何格式。

### LLM可以阅读笔迹吗？

是的。所有 15 个视觉模型都完美地记录了我们简洁的笔记。在凌乱的笔迹上，大多数字符准确度都保持在 99% 以上，而漏写的大多是名字（“Ackterberg”代表“Achterberg”）。
