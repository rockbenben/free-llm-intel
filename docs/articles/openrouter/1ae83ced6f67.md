# 扫描文档最佳 OCR 模型实测

Kenny Rogers ·11/10/2026

![扫描文档最佳 OCR 模型实测](https://openrouter.ai/blog/images/best-ocr-model.jpg)![扫描文档最佳 OCR 模型实测](https://openrouter.ai/blog/images/best-ocr-model-dark.jpg)

把扫描文档转成可靠的文本并不容易。Tesseract 这类经典 OCR 引擎遇到褪色打印、手写和传真就会失灵。视觉模型能把这些页面读得很准，但有时会写出页面上根本没有的值。我们用自己写的文本做了 8 个测试页，每个字符都能核对，再把它们交给 OpenRouter 上的 15 个视觉模型和 Mistral OCR，以及 Tesseract 各跑一遍。

我们测试中表现最好的 OCR 模型是 Claude Opus 5.5，264 个键值里对了 262 个，每 1,000 页 $16.42。Mistral OCR 性价比最高：264 个里对了 258 个，只要 $2.02。这篇文章给出结果、需要留意的错误，以及用来抓出这些错误的代码。

这些结果只是个起点。我们的 8 页不是你的文档，所以真要知道哪个模型最适合你的工作流，唯一的办法就是在自己的扫描件上把候选模型跑一遍。

## TL;DR

- 最准的是 `anthropic/claude-opus-5.5`。性价比最高的是 `mistral-ocr`。最便宜又好用的结果是关闭 reasoning 的 `inclusionai/ling-3.0-flash-vl`，264 个里对了 254 个，每 1,000 页 $0.04。
- 在一张褪色的收据上，GPT-6 Luna 和 GPT-6.1 Sol 凭空编出了卡号、wifi 密码和服务器名。错误率反映不出这一点，所以要核对那些你真正会用到的值。
- 关闭 reasoning 让我们测试的 5 个模型里有 4 个更快、更便宜，而且没丢键值。
- 把来自不同实验室的两个便宜模型读数不一致的词标出来，35 个错词里抓到了 34 个，每 1,000 页 $0.62。

## 测试方法

我们用已知文本渲染出每一页，再按扫描件的样子把它做旧：轻微旋转、模糊、噪点和 JPEG 压缩。其中 5 页很普通：一张收据、一封故意带两处拼写错误的信、一张勾了选项的表单、一份双栏简报，以及一张字迹工整的手写便条。另外 3 页是特意做难的：一张褪色的热敏收据、写得又急又挤的手写体，还有一张低分辨率传真，上面 12 个序列号全用形近字符拼成(0/O, 1/I/L, 5/S, 8/B)，模型没法靠上下文猜出来。

![Cafe Verdigris 的扫描热敏收据，越往底部越褪色，卡号和 wifi 密码几乎难以辨认](https://openrouter.ai/blog/images/best-ocr-model-faded-receipt-scan.jpg)

我们用两种方式给每份转录文本打分。字符错误率（CER）是与正确文本之间的编辑距离除以文本长度，忽略换行和 Markdown。键值是流水线真正会用到的 88 个字符串，每页 10 到 15 个，比如金额合计、日期、卡号、序列号和那些拼错的词。每个字符串都必须在 3 次运行里原样出现，这样每个模型就有 264 项检查。成本取每次请求计费的 `usage.cost`。模型取自截至 2026 年 10 月 8 日的 OpenRouter 目录。

## 视觉模型读难扫描件时会出什么错？

最严重的错误，是写出一个看着合理、页面上却根本没有的值。下面是那张褪色收据底部的印刷内容，接着是 GPT-6 Luna 的一次运行输出：

```
CONTACTLESS 32.95
CARD ****9026
SERVED BY: PRIYA
WIFI: verdigris-guest / tide2026
```

```
NET                                 27.46

CONTACTLESS
CARD **** 9027

SERVED BY: SHEVA
WIFI: verdigris_guest / 1freecoffee
```

收据上并没有 `NET` 这一行。卡号尾数是 9026，服务员名字和密码都是编出来的。GPT-6 Luna 在 3 次运行里都改了服务员名字和年份。GPT-6.1 Sol 每次运行都编出一个不同的密码（`flatwhite24`、`flat9am!`、`flatleaf`）。我们还让模型遇到拿不准的地方写 `[?]` 而不要猜。没用：7 个模型里有 4 个从头到尾没用过这个标记。

反复出现的其他错误：

- O 和 0：15 个模型里有 13 个，至少一次运行把两个传真序列号读错了。只有 Claude Sonnet 5.5 和 GPT-6.1 Sol 每次都读对。
- 自作主张改拼写：那封信的署名是“Senior Assosiate”，prompt 要求原样照抄拼写。45 份转录里仍有 16 份把它“纠正”了。
- 勾选框：Claude Sonnet 5.5 和 Haiku 5.5 照抄了表单里复选框的文字，却漏掉了到底是哪个框被勾上。

## 步骤 1：把扫描件发给视觉模型

视觉模型生成转录文本的方式，和语言模型生成任何文本一样，所以它容易写出“这类文本通常长什么样”，而不是页面上印的原字。prompt 要求它原样照抄，这能缓解问题，却消不掉：45 份转录里还是有 16 份把信里那个故意拼错的词改了。你需要一个 [OpenRouter API 密钥](https://openrouter.ai/docs/quickstart)，放在 `OPENROUTER_API_KEY` 里。图片以 base64 的 `image_url` 部分传入（见[图像输入](https://openrouter.ai/docs/guides/overview/multimodal/image-understanding)），所以 OpenRouter 上的每个视觉模型都接受这同一份请求。把它存成 `transcribe.py`，因为步骤 3 和 4 要从它导入：

```
import base64
import mimetypes
import os

import requests

API = "https://openrouter.ai/api/v1/chat/completions"
HEADERS = {"Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}"}
PROMPT = ("Transcribe all of the text in this scanned document, in reading order. "
          "Copy spelling, numbers and punctuation exactly as they appear, even if they "
          "look wrong. Return plain text only, with no Markdown and no commentary.")


def transcribe(path, model="deepseek/deepseek-v4.1-flash", reasoning={"effort": "none"}):
    mime = mimetypes.guess_type(path)[0] or "image/jpeg"
    with open(path, "rb") as f:
        image = f"data:{mime};base64," + base64.b64encode(f.read()).decode()
    body = {
        "model": model,
        "max_tokens": 16000,
        "messages": [{"role": "user", "content": [
            {"type": "text", "text": PROMPT},
            {"type": "image_url", "image_url": {"url": image}},
        ]}],
    }
    if reasoning:
        body["reasoning"] = reasoning
    response = requests.post(API, headers=HEADERS, json=body, timeout=300)
    response.raise_for_status()
    data = response.json()
    choice = data["choices"][0]
    if choice["finish_reason"] != "stop":
        raise ValueError(f"finish_reason={choice['finish_reason']}: the transcript is incomplete")
    return choice["message"]["content"], data["usage"]["cost"]


if __name__ == "__main__":
    text, cost = transcribe("receipt.jpg")
    print(text)
    print(f"\n${cost:.5f}")
```

```
HARBOR LANE MARKET
1180 Harbor Lane, Unit 4
Portland OR 97209
Tel (503) 555-0148
...
TOTAL 62.86
VISA ****4471 62.86
AUTH 08813C
...

$0.00022
```

每个字符都没错，花费大约百分之二美分。data URL 的类型取自文件扩展名，所以 PNG 和 WebP 扫描件也能用。要比较模型，只改 `model` 字符串就行；步骤 2 里那些关不掉 reasoning 的模型，传 `reasoning=None`。

之所以要查 `finish_reason`，是因为 reasoning token 会算进 `max_tokens`。上限设成 4,000 时，Gemini 3.8 Flash 每次运行都花 3,841 个 token 对那张传真做推理，写到第 4 个序列号就停了。请求照样返回 `200 OK`、`finish_reason: "length"`，所以不做这个检查，流水线会不知不觉把残缺的转录存下来。

## 步骤 2：转录时关掉 reasoning

模型需要规划答案时，reasoning 才有帮助。从页面上抄字不需要规划，多出来的 token 主要只是增加成本和时间。所以 `transcribe` 默认发送 `"reasoning": {"effort": "none"}`（见 [reasoning tokens](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)）。我们对每个允许关掉 reasoning 的模型，都把整套测试重跑了一遍：

| 模型 | 键值，开 → 关 | CER，开 → 关 | 每 1,000 页成本，开 → 关 | 中位秒数，开 → 关 |
| --- | --- | --- | --- | --- |
| `mistralai/mistral-large-4-0` | 240 → 249 | 4.61% → 0.15% | $6.80 → $1.68 | 47.9 → 5.6 |
| `inclusionai/ling-3.0-flash-vl` | 254 → 254 | 1.05% → 0.19% | $0.12 → $0.04 | 7.2 → 4.0 |
| `openai/gpt-6-luna` | 232 → 232 | 1.49% → 1.08% | $0.54 → $0.22 | 7.8 → 3.8 |
| `deepseek/deepseek-v4.1-flash` | 248 → 249 | 0.20% → 0.23% | $0.20 → $0.16 | 4.8 → 4.5 |
| `qwen/qwen3.8-27b` | 246 → 244 | 0.92% → 2.28% | $1.54 → $0.77 | 10.8 → 8.9 |

开着 reasoning 时，有一次 Mistral Large 4 请求推理了 626 秒，一个字也没返回（`finish_reason: "error"`）。Qwen3.8 27B 反而是开着 reasoning 表现更好，所以要拿自己的页面试。Gemini 3.8 Flash、Grok 4.7 和 GLM 5.3 FlashX 不允许关掉 reasoning，传 `reasoning=None` 把这个字段省掉即可。否则请求会失败，报：

```
400 {"error":{"message":"Reasoning is mandatory for this endpoint and cannot be disabled.","code":400,"metadata":{"provider_name":null}}}
```

## 步骤 3：用不同实验室的两个模型交叉核对

O 和 0 这类形近字符，在模糊图像里很难分清。每个模型都按自己训练出来的判断走，所以不同实验室的两个模型很少犯同一个错。两份转录对不上的地方，往往就是图像不清楚的地方。我们把 6 个模型两两配对都试了，最好的是 Claude Haiku 5.5 配 DeepSeek V4.1 Flash 复核。Haiku 在 2,964 个词里错了 35 个词，DeepSeek 按步骤 2 关掉 reasoning 后，对其中的 34 个给出了不同读法，另有 10 次误报。这一对每 1,000 页 $0.62，是 Mistral OCR 的三分之一。两者用同一个 API，所以核对只多一次调用。Haiku 调用时传 `reasoning=None`，因为它在我们的表格里就是这么跑的：

```
import difflib

from transcribe import transcribe  # the function from step 1

a, _ = transcribe("fax.jpg", model="anthropic/claude-haiku-5.5", reasoning=None)
b, _ = transcribe("fax.jpg", model="deepseek/deepseek-v4.1-flash")
a, b = a.split(), b.split()
for tag, i1, i2, j1, j2 in difflib.SequenceMatcher(None, a, b, autojunk=False).get_opcodes():
    if tag != "equal":
        print("check:", " ".join(a[i1:i2]), "vs", " ".join(b[j1:j2]))
```

```
check: 8LI5-QS0B5O vs 8LI5-QS0B50
check: 30HY-1OHLG7 vs 30HY-10HLG7
```

这正是多数模型读错的那两个序列号。如果两个模型把同一个字符错成一样，就不会被标出来。我们的运行里出过一次：两者都把一个 O 读成了 0，所以只要能，就拿名单或校验和去核对 ID。这个比对还有个前提：两个模型按相同顺序读页面。3 次运行里有 1 次，两个模型把传真两列的顺序列反了，结果每个序列号都成了不一致。

## 步骤 4：把 Mistral OCR 当专用引擎用

Mistral OCR 是只针对文档 OCR 训练的模型。在 OpenRouter 上，它作为 [file-parser 插件](https://openrouter.ai/docs/guides/overview/multimodal/pdfs) 里的一个引擎运行，该插件接收 PDF，每 1,000 页 $2。插件会在你的模型看到文件之前先做 OCR，并把文本作为响应里的文件注释返回，所以你指定的模型只需要回一句话。把扫描件包进一页 PDF，用任意便宜的模型发出去：

```
import base64
import html
import io
import os

import requests
from PIL import Image, ImageSequence

from transcribe import API, HEADERS  # from step 1


def mistral_ocr(path):
    if path.lower().endswith(".pdf"):  # scanned PDFs go as they are
        with open(path, "rb") as f:
            raw = f.read()
    else:  # wrap an image in a PDF in memory, one page per frame of a multipage TIFF
        pages = [p.convert("RGB") for p in ImageSequence.Iterator(Image.open(path))]
        buf = io.BytesIO()
        pages[0].save(buf, "PDF", save_all=True, append_images=pages[1:])
        raw = buf.getvalue()
    pdf = "data:application/pdf;base64," + base64.b64encode(raw).decode()
    pdf_name = os.path.splitext(os.path.basename(path))[0] + ".pdf"
    body = {
        "model": "upstage/solar-mini4",  # any cheap text model; it only has to reply
        "max_tokens": 5,
        "messages": [{"role": "user", "content": [
            {"type": "text", "text": "Reply OK."},
            {"type": "file", "file": {"filename": pdf_name, "file_data": pdf}},
        ]}],
        "plugins": [{"id": "file-parser", "pdf": {"engine": "mistral-ocr"}}],
    }
    response = requests.post(API, headers=HEADERS, json=body, timeout=300)
    response.raise_for_status()
    data = response.json()
    parts = data["choices"][0]["message"]["annotations"][0]["file"]["content"]
    texts = [p["text"] for p in parts if p.get("type") == "text"]  # skip extracted image parts
    text = "\n".join(t for t in texts if not t.startswith(("<file", "</file")))
    return html.unescape(text), data["usage"]["cost"]


text, cost = mistral_ocr("receipt_faded.jpg")
print(text)
print(f"\n${cost:.5f}")
```

```
CAFE VERDIGRIS
22 Quayside Row
Bristol BS1 4QA
VAT No. GB 318 7742 09

27/09/2026 08:17 TILL 2 CHK 0193
...
|  CONTACTLESS | 32.95  |
|  CARD ***9026 |   |

SERVED BY: PRIYA
WIFI: verdigris-guest / tide2026

$0.00202
```

那张褪色收据上的每个值都对了，卡号和密码也在内。Mistral OCR 天生要保留版式，所以输出是 Markdown：收据行变成表格，标题带上 `##`，`&` 会回来成 `&amp;`。所以这个函数才要把 HTML 实体反转义。要纯文本就把 Markdown 去掉；如果接下来由 LLM 读结果，留着就好。

## 做 OCR，LLM 比 Tesseract 更强吗？

是，干净的打印页除外。Tesseract 5.5 逐行辨认字形，清晰印刷还撑得住，一遇到噪点和手写就垮了。那封信和简报它转得一字不差；褪色收据则什么都没返回，潦草手写的 11 个值只对 1 个，传真的 15 个值只对 4 个。

## 常见问题

### 做 OCR 哪个 LLM 最好？

我们的测试里是 Claude Opus 5.5。Gemini 3.8 Flash 和 Grok 4.7 的错误率几乎一样低，但漏掉更多序列号。DeepSeek V4.1 Flash 和 Ling 3.0 Flash VL 很接近，每 1,000 页还不到 $0.20。

### 怎么对扫描 PDF 做 OCR？

按步骤 4，用 `mistral-ocr` 引擎发出去。也可以把每页渲染成图片交给视觉模型，或者把 PDF 直接发给能读 PDF 的模型。免费的文本解析器对扫描件没用，因为扫描件没有文本层。

### 最准的 OCR 模型是哪个？

Claude Opus 5.5 在 264 个键值里对了 262 个，8 张扫描件上的字符错误率是 0.02%。Mistral OCR 以 258 / 264 排第二，成本只有它的八分之一。

### 用 LLM 做 OCR 要花多少钱？

我们的测试里，从每 1,000 页 $0.04（关掉 reasoning 的 Ling 3.0 Flash VL）到 $16.42（Claude Opus 5.5）不等。Mistral OCR 是每 1,000 页 $2。各模型对图像 token 的计数方式不同，成本要在自己的页面上量。

### Mistral OCR 比视觉模型更好吗？

它在我们的测试里性价比最高：每 1,000 页 $2.02，264 个键值里对 258 个，只输给 Claude Opus 5.5。它返回保留版式的 Markdown，视觉模型则你要什么格式就给什么格式。

### LLM 能读手写吗？

能。15 个视觉模型都把那张工整便条转得一字不差。潦草手写上，大多数模型的字符准确率仍在 99% 以上，错的主要是名字（把“Achterberg”写成“Ackterberg”）。
