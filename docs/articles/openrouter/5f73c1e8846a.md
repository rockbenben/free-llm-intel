今天我们推出新的 [Model Router Benchmarks](https://openrouter.ai/benchmarks/routers) 页面，用于在越来越多的路由器选项之间比较性能。每个路由器都跑过一组来自不同领域的基准，按质量、速度和成本打分。

同时展示在成本效率与智能两方面都属顶尖的单个模型，作为对照基线。请长期关注这个页面——我们会持续加入新路由器，并随路由器改进而更新分数。

![Benchmark matrix on the Model Router Benchmarks page showing Router Index scores for Auto cost tiers, Auto Beta, Fugu Max, Fugu Ultra v2, and Jev Router across six benchmarks](https://openrouter.ai/blog/images/model-router-benchmarks/router-index-matrix.png)

OpenRouter 凭借 [Auto Router](https://openrouter.ai/openrouter/auto) 和 [Free Models Router](https://openrouter.ai/openrouter/free) 推出了最早的两类模型路由器。创建它们，是为了让你有一个可靠选项，始终跟进最新模型，并匹配你偏好的[成本档位](https://openrouter.ai/docs/guides/routing/routers/auto-router#cost-tier)。此后我们不断改进它们，包括[利用市场的集体智慧](https://openrouter.ai/blog/announcements/introducing-the-new-auto-router/)来指导路由决策。

近几个月，许多路由器相继发布，它们利用模型版图中的不同优势来优化性能。

**成本差异：** 例如，比较 DeepSeek v4 Flash 和 GPT-6 Astra，GPT-6 Astra 的平均每 token 实付价格高出 48 倍以上，在 Codex 里跑一个 10 到 49 轮的典型会话要贵 21 倍。路由器可以把任务的一部分切换给更便宜的模型来省钱。

**任务多样性：** 例如，法律研究表现最好的模型，未必是编码最好的模型。路由器可以在它们之间切换，用足每个模型的长处。

**会话阶段：** agentic 会话的不同部分可能需要不同的智能水平。路由器可以在模型或推理强度之间切换，为需要复杂规划的环节和只需例行执行的环节分别调配。

实践中，这些技术各有难点，有时反而比直接使用单一模型表现更差：

- 在模型之间切换，意味着输入缓存需要重建，期间请求变得更贵。
- 路由器往往只凭 prompt 得不到足够信息来判断任务复杂度。
- 基于启发式的会话阶段信号，可能与模型的下一步不一致。
- 在路由决策上做的处理越多，引入的延迟就越多。

我们提供这些 [Model Router Benchmarks](https://openrouter.ai/benchmarks/routers)，展示哪些路由器克服了这些固有难题，让你能判断何时（以及是否）该使用它们。它们的设计目标是帮你找到与你所需性能特征匹配的路由器与模型组合。

## 路由器的类型

“router”这个词被混用来指许多不同的东西。我们来拆解一下。

**服务商路由：** 模型通常由多家推理服务商提供，因此服务商路由器会按你对[价格、速度、可用性、数据政策](https://openrouter.ai/docs/guides/routing/provider-selection)的偏好挑选一家，失败时再回退到另一家。这正是 OpenRouter 自第一天起就做的事。

**模型路由：** 你不直接选定单一模型，而是把请求发给像 [Auto Router](https://openrouter.ai/openrouter/auto) 这样的路由器，由它决定该由哪个模型回答。它们的行为和模型一样，但可能用一个或多个模型来响应你的请求。

我们评测的模型路由器采用了几种不同思路：

**执行模型混合的路由器：** [Unbiased 的 Pareto](https://openrouter.ai/unbiased/pareto) 和 [Sakana 的 Fugu](https://openrouter.ai/sakana/fugu-max) 是推理服务商，使用多个模型的混合，有时会升级到前沿模型。它们不披露所用模型，也不说明切换频率，按标准化的 per-token 费率计费。

**选择模型的路由器：** [Auto Router](https://openrouter.ai/openrouter/auto) 和 [Jev Router](https://openrouter.ai/typesafe/jev-router) 为每一轮选一个模型。选择过程透明，按被选中模型的标准费率计费。

**在预定义模型集合间切换的路由器：** [NVIDIA 的 Switchyard](https://openrouter.ai/nvidia/switchyard) 把一个较便宜的模型与一个更强的模型配对，在 agent 完成任务的过程中在两者之间切换。我们评测了若干配对以展示哪些模型搭配最好，但你也可以用任意你想要的配对来运行。

还有另外几种风格，例如 [Pareto Code](https://openrouter.ai/docs/guides/routing/routers/pareto-router) 或 [`-latest` 模型 slug](https://openrouter.ai/docs/guides/routing/routers/latest-resolution)，它们别名指向单一模型。Pareto Code 为你想要的智能水平挑选成本最优的模型，而 `-latest` slug 指向某个家族里最新的模型。[Fusion](https://openrouter.ai/docs/guides/routing/routers/fusion-router) 则是另一种风格：把同一请求发给一组模型评议并综合出最佳答案。这些风格没有被纳入基准测试，因为它们服务于专门用途，需要不同的比较方法。

## Router Index 融合质量、速度与成本

基准测试在多个维度上揭示性能，让人难以判断哪个路由器整体最好。Router Index 把质量、速度和成本综合成 0 到 10 的分数，每个基准一个。默认权重是：质量（基准分数）60%，单任务耗时 20%，成本 20%。你的优先级可能不同，页面上有滑块可以调整权重。

![Router Frontier chart plotting Router Index against cost per task with Pareto, Switchyard, and Auto points on the efficiency line and hollow single model points for reference](https://openrouter.ai/blog/images/model-router-benchmarks/router-frontier.png)

## 直接替换模型即可试用任何路由器

和所有基准测试一样，我们的 [Model Router Benchmarks](https://openrouter.ai/benchmarks/routers) 只具有代表性，不能替代你自己的工作任务。列出的所有路由器都在 OpenRouter 上可用。在任意应用或 harness 中用它们替换你的模型即可，API 同样支持。
