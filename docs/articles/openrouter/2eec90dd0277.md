# OpenRouter 现在为 Hugging Face 提供推理支持

Sasha Blumenfeld ·11/16/2026

![OpenRouter 现在为 Hugging Face 提供推理支持](https://openrouter.ai/blog/images/hugging-face-inference-providers.jpg)![OpenRouter 现在为 Hugging Face 提供推理支持](https://openrouter.ai/blog/images/hugging-face-inference-providers-dark.jpg)

我们打造 OpenRouter，是为了让开发者通过一个 API 就能触达众多模型与提供商，为每个任务选用最合适的模型，并且可以指望它稳定响应。从今天起，这一点也覆盖所有在 Hugging Face 上构建的开发者。Hugging Face Inference Providers 上的聊天模型现在通过 OpenRouter 运行，并沿用 OpenRouter 客户已经依赖的那套跨提供商路由。

这次集成也是双向的。OpenRouter 现在可以把每个请求的 trace 发送到你自己的 Hugging Face Storage Bucket，这样真实流量里的 prompt 和响应，就和你用来评估、微调模型的模型与数据集放在了一起。[设置指南](https://openrouter.ai/docs/guides/features/broadcast/hugging-face)里有具体步骤。

![Hugging Face 模型页面上的 Inference Providers 小部件正在回答一条聊天消息，带有 Powered by OpenRouter 标签](https://openrouter.ai/blog/images/hugging-face-inference-providers/inference-widget.gif)

## 在 Hugging Face 上你能得到什么

Hugging Face 上的许多聊天模型都由不止一个提供商提供服务。OpenRouter 的提供商路由现在为 Hugging Face Inference Providers 的路由提供支持，它会根据实时价格、速度和可靠性为每个请求挑选提供商。你无需做任何配置，现有的 Hugging Face token 和代码照常可用。

你还能获得自动故障转移。如果某个提供商变慢或开始出错，请求会转到其他提供商，直到它恢复。如果某个提供商返回错误，请求会在同一次调用内交给下一家提供商重试。

我们在 10 月[重建这套路由](https://openrouter.ai/blog/how-we-rebuilt-provider-routing)时，一次线上实验测得：命中容量错误的请求减少了 46%，首 token 时间快了 16.9%，吞吐量提高 16.3%，代价是每请求成本上升 6.0%。现在，所有在 Hugging Face 上构建的人都能用上同一套路由。

权衡的主动权仍在你手里。在模型 ID 后加后缀，比如 `:fastest`、`:cheapest` 或某个提供商的名字，就能告诉 OpenRouter 优先考虑什么；请求既可以通过 OpenAI 的 Chat Completions 和 Responses API 发出，也可以走 Anthropic 的 Messages API。同一段对话还会始终留在持有其 prompt cache 的提供商上。

每个模型页面都新增了一个 Providers 标签页，列出每个提供商的实时价格、速度和正常运行时间。你可以查看自己在各提供商上的花费，也可以关掉任何不想用的提供商。

今天通过这种方式可用的有来自 38 个实验室的 160 个模型，也就是 OpenRouter 所服务、且在 Hub 上有页面的全部模型。其中包括开发者在 OpenRouter 上最常用的 open-weight 模型——10 月，open-weight 模型承载了[约 70% 的付费 token](https://openrouter.ai/data/october-2026)：

## 你的 trace 可以存放在 Hub 上

把 Hugging Face Storage Buckets 添加为 Broadcast 目的地（目前处于 beta），OpenRouter 就会把每个请求以 JSON 文件的形式发到你自己拥有的 bucket。每个文件包含输入消息、模型的输出、token 数量和成本。图片及其他媒体不会包含在内。

这是构建评测集、或在 open-weight 模型上做微调的原材料。你可以按日期或按 API key 来组织文件。

![OpenRouter 的 Observability 设置里新增的 Hugging Face Storage Buckets 目的地表单，包含 namespace、bucket 名称、access key ID 和 secret access key 字段。](https://openrouter.ai/blog/images/hugging-face-inference-providers/storage-buckets-destination.png)

## 开始使用

在 Hugging Face 上：

- 在 [hf.co/settings/tokens](https://hf.co/settings/tokens) 创建一个 token，并勾选“Make calls to Inference Providers”权限。
- 在 Hub 上打开任意受支持模型的页面。可以直接在那里和模型聊天，也可以点击 View code，查看针对你的代码或编程 agent 的设置步骤，包括 Claude Code、Codex、OpenCode、Pi 和 Hermes Agent。
- 如果你想选择哪些提供商可以服务你的请求，请到 Hugging Face 设置的 [Inference Providers](https://huggingface.co/settings/inference-providers) 中配置。

要把 trace 发送到 Storage Bucket：

- 在 Hugging Face 上创建一个 Storage Bucket。
- 创建一个带 Write 权限的 access token，并用它生成 S3 凭证。
- 在 OpenRouter 中进入 [Settings > Observability](https://openrouter.ai/settings/observability)，打开 Broadcast，再打开 Hugging Face Storage Buckets。
- 填入 namespace、bucket 名称、access key ID 和 secret access key。像 `{apiKeyName}/{date}` 这样的路径模板是可选项。
- 点击 Test Connection，然后保存。

[完整设置指南](https://openrouter.ai/docs/guides/features/broadcast/hugging-face)涵盖了路径模板和 trace 文件格式。

[在 Hugging Face Playground 里试一个模型](https://huggingface.co/playground)，或者[把你的 trace 发到 Storage Bucket](https://openrouter.ai/docs/guides/features/broadcast/hugging-face)。
