# 2026 年最佳 Embedding 模型

Embedding 模型决定你的检索系统能找到什么。它把每个输入变成向量，让相关的输入彼此靠近，于是你的应用可以按语义而不是按字面措辞检索。

最佳选择取决于你要搜索的材料。英文知识库、多语言支持档案、源代码仓库、图文混合集合，要求各不相同。向量维度、上下文长度、公开权重和价格也会改变决策。

我们针对英文 RAG、多语言检索、代码搜索、图文检索和低成本索引拟定了候选模型，然后通过我们的 embeddings 端点向每一个发送了真实请求。

**最后核验时间：**2026 年 9 月 11 日。我们的 [embedding 模型目录](https://openrouter.ai/models?fmt=cards&output_modalities=embeddings)当日返回 37 个条目，含部分模型的 batch 和 preview variant。

Provider 会增删路由，prompt 价格也会变化。启动大规模索引或重建索引之前，请先查看当前的模型页面。若模型页面与本文不一致，以模型页面为准。

## TL;DR

- 英文 RAG 从 `openai/text-embedding-3-small` 开始。
- 当你的输入超过 8,192 tokens，或想在 Voyage 4 各档之间切换而不重建索引时，测试 `voyageai/voyage-4-large`。若你想要开源权重的替代，`qwen/qwen3-embedding-8b` 以更低的 prompt 价格提供更长的上下文窗口。
- 多语言检索 + 公开权重用 `qwen/qwen3-embedding-8b`，代码搜索用 `voyageai/voyage-code-4`，图文检索用 `google/gemini-embedding-2` 或 `voyageai/voyage-multimodal-3.5`。
- 在我们候选的付费文本模型中，`perplexity/pplx-embed-v1-0.6b` 的 prompt 价格最低。`nvidia/nemotron-3-embed-1b:free` 是一条免费文本 embedding 路由，上下文窗口 32,768 tokens。
- 我们的 API 检查确认的是请求与响应行为，不是检索质量。在构建或重建完整索引前，用你应用中的带标注查询和文档至少比较两个候选。

## 我们如何挑选这些模型

我们用实时目录确认可用性、上下文窗口、输入类型和 prompt 价格。我们查阅模型 provider 的文档了解能力与基准结果，然后通过 embeddings 端点发送真实请求确认请求与响应行为。

我们向 19 个模型发送了双字符串批量请求，共执行 28 项检查，覆盖批量输入、可配置维度、图像输入、图文组合输入和错误处理。16 个付费模型每个输入返回一个向量。响应确认了下表中的默认维度，并表明 `dimensions` 参数对 OpenAI Text Embedding 3 Small、Gemini Embedding 2 和 Voyage 4 Large 有效。对不存在模型的请求返回 400 错误，消息为 `Model openai/does-not-exist does not exist`。

三个免费路由在我们的测试账户上返回 404 错误，因为该账户的隐私设置不允许路由到可能在免费模型 prompt 上训练的 provider。我们在下文免费选项部分描述该设置。我们为这些模型列出的默认维度来自其模型卡，而非我们的响应。

这些请求确认的是 API 兼容性，没有测量检索质量。我们排除了响应时间，因为每个模型只收到一次小请求，服务条件各不相同。我们把每个用例匹配到一项有文档的能力，再用语言覆盖、上下文长度、输出维度、公开权重和 prompt 价格收窄候选。包括 MTEB 和 CoIR 在内的公开评估帮助我们确定待测模型。最终部署哪个，应由你的带标注检索结果决定。

## 英文 RAG 的最佳默认选项

当你的英文知识库需要托管模型时，从 `openai/text-embedding-3-small` 开始。它的默认向量有 1,536 个值，是 `openai/text-embedding-3-large` 默认值的一半。在相同数值格式下，Small 用的原始向量存储只有一半。首轮评估保持 1,536 默认值，只有在默认值已达标而存储或搜索成本仍是约束时才下调。

你可以用 `dimensions` 参数缩短向量。我们发送 `"dimensions": 256` 的请求返回了 256 个值的向量。更小的向量占用更少数据库存储、减少相似度搜索的开销，但也可能降低检索质量。更改现有索引之前先测试小尺寸。

OpenAI 把 [text-embedding-3-large](https://developers.openai.com/api/docs/guides/embeddings) 描述为其面向英文和非英文任务最强的 embedding 模型。当 Small 漏掉相关结果时测试它，尤其是用户跨语言搜索时。换到 Large 会改变向量尺寸和 prompt 价格，所以在重新嵌入语料前，用留出的问题对比两个模型。

如果你的输入超过 Small 的 8,192-token 限制，测试 Voyage 4 Large。对更短的输入，用相同的块、查询和相关性标签对比两个模型。

## 适合更长输入的 Voyage 4 家族

当你需要一个可调维度、跨 Voyage 4 档位兼容的托管 32,000-token 模型时，测试 `voyageai/voyage-4-large`。它最多接受 32,000 tokens，支持 256、512、1,024 和 2,048 维度。在我们的 API 检查中，把 `dimensions` 设为 512 返回了 512 个值的向量。

该家族还包括 `voyageai/voyage-4` 和 `voyageai/voyage-4-lite`，使用同样的上下文窗口。[Voyage 声明](https://docs.voyageai.com/docs/embeddings)4 系列创建的所有 embeddings 相互兼容。这让你可以对着现有索引测试另一个 Voyage 4 档位。部署前先在代表性样本上验证档位切换。兼容的向量空间免除了重建需求，但并不保证检索结果一致。

用 Large 和至少一个更低的 Voyage 4 档位跑同一评估集。如果它们在相同截断下检索出相同的段落，更低档位可能已满足需求。

Voyage 模型是托管服务。如果你需要公开权重来自建部署或掌控部署，本候选中的开源权重替代是 Qwen3 Embedding 8B。

## 多语言检索的最佳开源权重模型

`qwen/qwen3-embedding-8b` 是我们的开源权重多语言之选。它支持 100+ 语言，你可以从 Hugging Face 下载权重，也可以通过我们的 API 调用托管模型。我们的默认 API 请求返回 4,096 个值。在相同数值格式下，4,096 值的向量占用 1,024 值向量的 4 倍原始存储。估算索引大小时要算上这个差异。我们的 API 检查无法确立 Qwen3 Embedding 8B 是否比 `nvidia/nemotron-3-embed-1b:free` 检索得更好。当路由成本和向量尺寸影响决策时，先在同一个带标注集合上测试两者再做承诺。

[Qwen 模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-8B)报告该模型在 2025 年 6 月 5 日的 Massive Text Embedding Benchmark（MTEB）上多语言得分 70.58。这是供应商报告的公开基准结果。用它把 Qwen 列入候选，然后对你应用支持的每种语言和每个领域做测试，因为你的语料可能给出不同的排名。

模型页面列出 32,768-token 上下文窗口，但限制是按端点设置的。2026 年 9 月 11 日，Qwen3 Embedding 8B 的 DeepInfra 和 SiliconFlow 端点列出 32,768 tokens，Nebius 端点列出 32,000。如果你要发送超过 32,000 tokens 的输入，请检查[端点列表](https://openrouter.ai/qwen/qwen3-embedding-8b)并固定到限制更大的 provider，或把输入控制在 32,000 tokens 以内。

4B 版本使用同样的模型级上下文窗口，在我们的检查中返回 2,560 个值。自己运行时占用资源更少。托管价格取决于可用的 provider，选择前请对比 Qwen3 Embedding 8B 和 4B 的当前模型页面。

`baai/bge-m3` 给你第二个开源多语言模型，可以在你自己的数据集上与 Qwen3 对比。其[模型卡](https://huggingface.co/BAAI/bge-m3)覆盖 100+ 语言、输入最长 8,192 tokens，我们的请求返回 1,024 值的向量。上游模型可以返回多种表示类型，包括稠密向量和稀疏向量。我们的标准 embeddings 响应返回稠密向量。如果你的检索设计依赖其它表示类型，请使用上游实现。

## 代码搜索的最佳 embedding 模型

当查询需要检索一个函数、文件或一段代码文档时，用 `voyageai/voyage-code-4`。Voyage 为代码检索和 coding-agent 负载构建了这个模型。它的 32,000-token 上下文窗口可以接收长文件或长查询，尽管索引块仍应划分为检索时有用的代码单元。

`mistralai/codestral-embed-2505` 是我们目录中的主要代码专用替代品。它在我们的文本请求检查中返回 1,536 个值。其上下文窗口为 8,192 tokens，对 Voyage Code 4 是 32,000。先测 Voyage Code 4，把 Codestral Embed 作为对照模型。

公开评估可帮助你对比候选。[Code Information Retrieval Benchmark（CoIR）](https://arxiv.org/abs/2407.02883)包含十个数据集，覆盖七个领域的八类代码检索任务。先用它比较模型，再在你自己仓库的工作上测试最强候选。一个有用的内部评估是把 issue 描述或开发者问题映射到解决它们所需的文件和代码块。

## 图文检索的最佳模型

当同一个索引需要同时检索文本和图像时，用 `google/gemini-embedding-2`。它把两种输入放进一个 embedding 空间，文本查询可以检索出语义相关的图像，图像查询也能检索出相关文本。

我们通过 embeddings 端点核验了文本、base64 编码 PNG 图像、以及图文组合请求。每个请求返回一个 3,072 值的向量。我们还发送了带 `"dimensions": 768` 的文本请求，收到 768 值的向量。在我们的检查中，一张 64×64 像素的 PNG 计为 258 个 prompt tokens，花费 $0.000128。我们的目录对该模型的图像输入单独计价，截至 2026 年 9 月 18 日[模型页面](https://openrouter.ai/google/gemini-embedding-2)为每百万图像 token $0.45，所以在索引大型图像集合前先查模型页面。本指南把推荐限定于文本和图像输入，因为我们核验的只有这两类请求。

`voyageai/voyage-multimodal-3.5` 是我们核验的第二款图文模型。其图像请求和图文组合请求各返回一个 1,024 值的向量，同一张 64×64 像素 PNG 计为 89 个 prompt tokens，花费 $0.00003。它有 32,000-token 上下文窗口，prompt 价格每百万 token $0.12。Gemini Embedding 2 和 Voyage Multimodal 3.5 使用不同的向量空间，索引前选定其一。

`google/gemini-embedding-001` 是另一个独立的纯文本模型，上下文窗口 20,000 tokens。两款 Gemini 模型使用不同向量空间，在它们之间切换需要重建索引。

`nvidia/llama-nemotron-embed-vl-1b-v2:free` 是我们目录中一条免费图文路由，上下文窗口 131,072 tokens。我们的测试账户因下文的隐私设置原因无法调用它，所以我们把它排除在推荐之外。

## 最佳低成本与免费选项

`perplexity/pplx-embed-v1-0.6b` 在我们的候选中付费文本价格最低，每百万输入 token $0.004。它最多接受 32,000 tokens，返回 1,024 值的向量。更大的 `perplexity/pplx-embed-v1-4b` 返回 2,560 个值，prompt 价格每百万输入 token $0.03。

Perplexity 把 0.6B 定位为轻量、低延迟检索，4B 定位为更高质量检索。我们的 API 检查确认的是默认向量尺寸，不是哪个 Perplexity 模型检索更好。把供应商的定位当作候选筛选信号，在带标注查询上对比两个模型。

免费路由用于评估，而不是大型生产索引的唯一通道。当你需要一个免费候选来测试时，从 `nvidia/nemotron-3-embed-1b:free` 开始。它有 32,768-token 上下文窗口，[NVIDIA 的模型卡](https://huggingface.co/nvidia/Nemotron-3-Embed-1B-BF16)报告 2,048 值的输出向量、跨 34 种语言的评估，以及支持把向量切片到更小尺寸并做 L2 重归一化。NVIDIA 以 OpenMDW-1.1 许可发布权重。在生产索引任务中使用免费路由前，先查当前模型页面的可用性和速率限制。可用性和速率限制可能在批次进行中变化。

我们目录中的免费路由由数据政策可能允许在你的 prompt 上训练的 provider 服务。你的[账户隐私设置](https://openrouter.ai/settings/privacy)对付费和免费模型有独立开关。当免费模型开关关闭时，对这些路由的请求会返回 404 错误，指明免费模型训练设置并列出被排除的端点。我们的测试账户关了这个开关，这就是三个免费路由在我们检查中失败的原因。禁用免费模型训练的 [workspace guardrail](https://openrouter.ai/docs/guides/features/guardrails)，或请求中 `provider.data_collection` 设为 `deny`，会排除同样的端点并产生同样的 404 错误。这些设置如何生效见 [provider 日志与训练政策](https://openrouter.ai/docs/guides/privacy/provider-logging)。

`liquid/lfm-2.5-embedding-350m:free` 是候选中另一条免费文本路由。其 512-token 上下文窗口把每个输入限制在短段落，因此长文档要比本指南中其他模型切更小的块。只有当每个被嵌入的段落适合 512 tokens 时才用它，如短 FAQ 条目、标题或句子级片段。当你的检索单元需要更长上下文时排除它。

## 在你自己的数据上评估 embedding 模型

对每个候选使用相同的语料、查询、相关性标签、分块策略和检索指标。只换模型、保持评估其余部分固定，结果才可比。

### 评估英文 RAG

对每个候选使用相同的分块策略。从约 512 到 1,024 tokens 的带重叠分块开始，然后根据文档结构和检索结果调整大小。

从你的用户会问的问题开始，标注包含答案的块。用你的应用实际送给生成模型的检索块数量来度量 recall。当多个块都相关、但其中一些比另一些更有用时，加入归一化折损累计增益 nDCG。

### 评估多语言检索

纳入你计划支持的每种语言。如果用户可能用一种语言写查询、检索另一种语言的文档，加入跨语言用例。把每种语言与总体平均值分开报告，让一种语言的强结果不会掩盖另一种语言的弱结果。

### 评估代码搜索

用开发者问题或 issue 描述，标注能解决它们的文件或代码块。CoIR 可以补充这个集合。你仓库专属的标注应占更大权重，因为它反映你的应用实际会跑的搜索。

### 计算向量存储

把向量存储纳入比较。一百万个 4,096 维 float32 向量需要约 16.4 GB（不含索引开销）。一百万个 1,024 维向量需要约 4.1 GB。原始存储可用这个公式估算：

```
vector storage in bytes = number of vectors x dimensions x bytes per value
```

在该模型支持的每个向量尺寸上比较检索质量，然后选择满足你目标的最小尺寸。索引和查询都使用选定的模型与维度。

## 索引与查询使用兼容的模型

不同模型家族的向量不共享坐标系。如果你用 `openai/text-embedding-3-small` 索引文档，每个查询也要用同一模型和配置做 embedding。混用模型会产生不可靠的检索结果。同样的规则适用于 `google/gemini-embedding-2` 和 `google/gemini-embedding-001`。在两者间切换需要重建索引。

更换模型通常需要重新嵌入语料。Voyage 设计 Voyage 4 文本模型时让向量相互兼容，这在该家族内部构成一个有文档的例外。更改查询或索引路径前先测一个样本，因为所选档位仍可能影响检索质量。

把模型 slug、输出维度、prompt 格式和创建日期与索引元数据一起存储。一些 embedding 模型使用 `input_type` 值区分查询（如 `search_query`）与被索引内容（如 `search_document`）。把两侧使用的值与索引元数据一起存储。这些字段让后续部署在查询索引前能够核对嵌入配置。

在我们的模型目录中端点保持不变，但模型 slug 和输出维度必须与建索引时的配置一致。如果你用非默认维度建了索引，为查询做 embedding 时要带上相同的 `dimensions` 值。

## 通过我们的 API 调用 embedding 模型

向 `https://openrouter.ai/api/v1/embeddings` 发送请求。这个 Python 示例使用与我们验证时相同的批量请求结构：

```
import os

import requests

response = requests.post(
    "https://openrouter.ai/api/v1/embeddings",
    headers={
        "Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "openai/text-embedding-3-small",
        "input": [
            "Reset a password from the account settings page.",
            "Refunds are available within 14 days of purchase.",
        ],
    },
    timeout=90,
)

response.raise_for_status()
result = response.json()
vectors = [item["embedding"] for item in result["data"]]

print(len(vectors))
print(len(vectors[0]))
```

响应按相同顺序为每个输入返回一个向量。当所选模型支持可调维度时，在请求中加 `"dimensions": 256` 或其它受支持尺寸，并把该值与索引元数据一起存储。

对 Gemini Embedding 2 和 Voyage Multimodal 3.5，把图像输入放进 `input` 列表内的 `content` 数组。我们已用这两个模型核验了该请求结构：

```
payload = {
    "model": "google/gemini-embedding-2",
    "input": [
        {
            "content": [
                {"type": "text", "text": "A purple square"},
                {
                    "type": "image_url",
                    "image_url": {"url": "data:image/png;base64,BASE64_IMAGE_DATA"},
                },
            ]
        }
    ],
    "encoding_format": "float",
}
```

省略文本部分即可单独为图像做 embedding。完整请求与响应 schema 见我们的 [Embeddings API 文档](https://openrouter.ai/docs/api_reference/embeddings)。

## FAQ

### 我该用哪个 embedding 模型？

按你检索的材料和影响部署的约束来选。从支持你的输入类型、语言覆盖、上下文长度和权重要求的候选开始。在同一批带标注查询上至少比较两个，然后选择在可接受的存储与索引成本下达到你检索目标的模型。

### 能换 embedding 模型但不重建索引吗？

换到另一个模型家族需要重建索引，因为文档和查询必须使用同一模型、同一配置产出的向量。Voyage 声明 Voyage 4 Large、Voyage 4 和 Voyage 4 Lite 的 embeddings 相互兼容。换档位前先在样本上测试检索质量。

### 最快的 embedding 模型是哪个？

本指南没有做受控延迟基准。延迟随输入长度、批量大小、provider 负载和路由变化。用你应用实际的输入和批量大小测试端点。

### 该用最大的 embedding 维度吗？

从你的检索结果和存储约束选择 embedding 维度。更高维度需要更多存储、每次相似度搜索的开销也更大。当模型支持降维时，在你的评估集上用能达到检索目标的最小维度。

### text-embedding-ada-002 还是好的默认选择吗？

新的基于 OpenAI 的索引我们不会把 text-embedding-ada-002 作为默认。先评估 text-embedding-3-small，如果你的检索结果证明更高的 prompt 价格和更大的向量值得，再与 text-embedding-3-large 比较。

### 为什么免费 embedding 模型返回 404 错误？

我们目录中的免费 embedding 路由由数据政策可能允许在你的 prompt 上训练的 provider 服务。如果你的账户隐私设置、workspace guardrail，或请求字段 `provider.data_collection` 设为 `deny` 排除了会在免费模型 prompt 上训练的 provider，就没有端点可用，请求会返回一个指明免费模型训练限制的 404 错误。在把模型 ID 判定为无效之前，先检查你账户的隐私页面和应用于该 API key 的 guardrail。
