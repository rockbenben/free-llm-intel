# 撞到 Claude Code 的用量上限？教你如何继续写代码

OpenRouter ·10/28/2026

![撞到 Claude Code 的用量上限？教你如何继续写代码](https://openrouter.ai/blog/images/claude-code-usage-limit.png)![撞到 Claude Code 的用量上限？教你如何继续写代码](https://openrouter.ai/blog/images/claude-code-usage-limit-dark.png)

当你撞上 Claude Code 的用量上限时，可以改用 OpenRouter 的 API key 跑 Claude Code，从而继续写代码。通过 OpenRouter，Claude Code 用的是按 token 计费的 API key，模型还是同样的 Claude 模型，也没有五小时窗口。你只要设置三个环境变量，等方案额度重置后再切回来就行。

我们用 Claude Code 测试了这套配置。下面的输出和成本都来自那些实测。

## 摘要

- 你的 Claude 方案同时有五小时上限和每周上限，而 OpenRouter 的 API key 两者都没有。你改为按实际使用的 tokens 付费。
- 最快的配置方式是 Ori Harness：`ori claude` 会为当前会话在 OpenRouter 上启动 Claude Code，通过浏览器登录，不用粘贴任何 key。
- 想手动配置，三个环境变量就能把 Claude Code 指向 OpenRouter。我们把它们放进一个叫 `claude-or` 的 shell 函数，这样 `claude` 仍然走你的方案。
- 从 Claude Sonnet 5.5 起步。一次典型的短 Claude Code 会话，在 Sonnet 5.5 上约 $0.16，在 Opus 5.5 上约 $0.31，在 Haiku 5.5 上不到一美分。
- 别信 Claude Code 打印出来的成本。在我们的测试里，它显示了一次运行 $0.375，而我们实际被计费 $0.008。请改看你的 key 或 Activity 页面。
- 等方案重置后，再输入一次 `claude` 就行，不用做任何回退操作。

## Claude Code 为什么会撞上用量上限？

Claude 方案有两个同时生效的上限。第一个在你发出第一条 prompt 五小时后重置，第二个每七天重置一次。Anthropic 没有公布两者各自确切对应多少次 prompt。Claude Code 消耗的 tokens 远多于普通聊天，所以很可能在一个任务中途就用完了。这时 Claude Code 会停下，并告诉你上限何时重置。[Anthropic 关于用量上限的帮助文档](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work)对这两个上限都有说明。

OpenRouter 的 API key 不是这个逻辑。你用多少 token 付多少钱，账户里还有额度就可以一直用下去。

## 最快的做法：通过 Ori Harness 运行 Claude Code

[Ori Harness](https://openrouter.ai/docs/guides/ori/harness) 会直接在你机器上启动 Claude Code，并预先把 OpenRouter 的设置配好。安装之后，通过它启动 Claude Code：

```
curl -fsSL https://openrouter.ai/labs/ori/install.sh | bash
ori claude --model anthropic/claude-sonnet-5.5
```

Ori 会打开浏览器，让你用 OpenRouter 账号登录。它使用 OAuth，所以不需要创建或粘贴任何 key。只有你用 `ori claude` 启动的会话才会跑在 OpenRouter 上，所以直接输入 `claude` 仍然走你的方案，等方案重置后再输入 `claude` 就能切回来。产生的用量会记在你的 OpenRouter 账单上。如果你身处某个组织，账号上的预算上限 [guardrail](https://openrouter.ai/docs/guides/features/guardrails) 会限制它能花多少钱，OpenRouter 对 Ori 会话同样适用这条限制。

下面的步骤用 API key 和一个 shell 函数手动完成同样的事。如果你想用一个自带额度上限的 key（任何账号都可以这样用），就照着做。第 4 步里的成本建议，两种方式都适用。

## 第 1 步：获取 OpenRouter API key 并设置上限

在 [API keys 页面](https://openrouter.ai/settings/keys)创建一个 key，并给它设一个额度上限。我们自己设的是 $4。这样一来，再长的会话也花不到 $4 以上。额度上限是控制 OpenRouter 花费的几种方式之一。[我们关于管控团队 AI 支出的指南](https://openrouter.ai/blog/insights/governing-team-ai-spend/)讲了其他几种。

想查看上限，就向我们的 API 查询你的 key：

```
curl https://openrouter.ai/api/v1/key \
  -H "Authorization: Bearer $OPENROUTER_API_KEY"
```

响应中值得关注的是这一段：

```
{
  "data": {
    "limit": 4,
    "limit_remaining": 4,
    "usage": 0
  }
}
```

`limit_remaining` 这个数字告诉你 key 上还剩多少钱。你随时可以跑这个检查。发出请求之后，新总额可能需要几秒才会显示出来。

## 第 2 步：加一个切换到你的 key 的命令

你当然可以把这些变量加进 shell 的配置文件里，但那样每次 Claude Code 会话都会记在你的 key 上。我们希望平时输入 `claude` 仍然走你的方案，所以把这些变量放进一个小小的 shell 函数。把下面这段加到 `~/.zshrc` 或 `~/.bashrc`：

```
claude-or() {
  ANTHROPIC_BASE_URL="https://openrouter.ai/api" \
  ANTHROPIC_AUTH_TOKEN="$OPENROUTER_API_KEY" \
  ANTHROPIC_API_KEY="" \
  ANTHROPIC_DEFAULT_SONNET_MODEL="anthropic/claude-sonnet-5.5" \
  ANTHROPIC_DEFAULT_OPUS_MODEL="anthropic/claude-opus-5.5" \
  ANTHROPIC_DEFAULT_HAIKU_MODEL="anthropic/claude-haiku-5.5" \
  CLAUDE_CODE_SUBAGENT_MODEL="anthropic/claude-haiku-5.5" \
  claude "$@"
}
```

前面三行是关键：

- `ANTHROPIC_BASE_URL` 告诉 Claude Code 把请求发给我们。
- `ANTHROPIC_AUTH_TOKEN` 存放你的 OpenRouter key。
- `ANTHROPIC_API_KEY` 必须为空。如果不为空，Claude Code 可能会改为尝试登录 Anthropic。

后面四行是可选的。它们告诉 Claude Code 在 Sonnet、Opus 和 Haiku 上分别使用哪个 Claude 模型，同时把 子 agent（sub-agent，即 Claude Code 自行启动的那些小型辅助任务）也放到 Haiku 5.5 上跑。

这些变量只在你输入 `claude-or` 时才生效。保存文件，再开一个新的终端窗口，函数就可以用了。

![示意图：在终端里输入 claude 会使用你的 Claude 方案，带着五小时和每周上限；输入 claude-or 则把同一个会话通过你的 API key 发给 OpenRouter，按 token 计费、没有用量窗口，由 OpenRouter 从 Anthropic、Amazon Bedrock 和 Google Vertex 提供同样的 Claude 模型。](https://openrouter.ai/blog/images/claude-code-usage-limit-claude-or.png)

## 第 3 步：确认 Claude Code 用的是你的 key

正式开始干活之前，先确认 Claude Code 把请求发给了 OpenRouter，而不是你的方案。最快的办法是发一条简短的 prompt，然后看是哪个模型回答的。在终端里运行：

```
claude-or --model sonnet -p "Reply with exactly: ok" --output-format json
```

我们的响应中值得关注的是这一段：

```
{
  "is_error": false,
  "result": "ok"
}
```

回复正常返回，没有错误。完整输出里的 `modelUsage` 字段会写明是哪个模型回答的；我们这次跑出来的是 `anthropic/claude-sonnet-5.5`。我们用 `--model haiku` 跑了同一条 prompt，`modelUsage` 显示的是 `anthropic/claude-haiku-5.5`。

然后再跑一次第 1 步的 key 检查。如果 `usage` 涨了，说明请求计费在你的 key 上而不是方案上；如果没涨，说明 Claude Code 没有读到这些变量。开一个新的终端再试一次。

## 第 4 步：把成本压下来

用 key 的话，每条消息都要付费。下表是我们三个 Claude 5.5 模型的价格，也给出了在 OpenRouter 上一次真实的 Claude Code 会话（两到九条消息）的中位成本。

| 模型 | 每 100 万输入 tokens 价格 | 每 100 万输出 tokens 价格 | 会话成本中位数（2 到 9 条消息） |
| --- | --- | --- | --- |
| Claude Opus 5.5 | $4.00 | $20.00 | $0.305 |
| Claude Sonnet 5.5 | $2.00 | $10.00 | $0.155 |
| Claude Haiku 5.5 | $0.10 | $0.50 | $0.007 |

*价格截至 October 21, 2026。会话成本来自我们的[会话成本数据集](https://openrouter.ai/docs/api/api-reference/datasets/cost-per-session-by-harness-and-model)，覆盖截至 October 18, 2026 的 30 天。*

先从 Sonnet 5.5 起步。它的单次会话成本约为 Opus 5.5 的一半，日常编码基本够用。遇到难题时，输入 `/model opus` 切换过去，做完再切回来。如果你在我们的 API 上自建应用，还可以在便宜的模型对自己的答案没有把握时，[把请求自动转给更强的模型](https://openrouter.ai/blog/insights/confidence-thresholds-for-model-escalation-routing/)。

每个新会话一开始都要带上 Claude Code 自己的指令和工具列表，大约 28,000 个 tokens（我们在 Claude Code 2.1.307 上跑出来是 28,156，这个数字在版本之间会变）。它们会在第一次请求时写入 prompt cache，所以第 3 步那条一个词的 prompt 在 Sonnet 5.5 上约 $0.07，在 Haiku 5.5 上不到半分钱。

子 agent 放在 Haiku 上很便宜。我们让 Sonnet 5.5 启动一个 子 agent 时，主 agent 跑在 Sonnet 5.5 上，子 agent 跑在 Haiku 5.5 上，正如这个函数所设置的。

Haiku 也能自己处理小修小补。我们给 Haiku 5.5 一个带两个 bug、三个失败测试的购物车文件。它把两个 bug 都修好了，三个测试全部通过，这次运行我们被计费 $0.008。

别依赖 Claude Code 打印出来的成本。那次 Haiku 运行，Claude Code 报的是 $0.375，而我们被计费 $0.008。Claude Code 是用 Anthropic 自己的价格表给会话定价的，遇到它不认识的 OpenRouter 模型名就靠猜。想看你实际花了多少，用第 1 步的命令查 `limit_remaining`，或者打开 [Activity 页面](https://openrouter.ai/activity)。

## 第 5 步：等方案重置后切回来

等方案上限重置后，输入 `claude` 而不是 `claude-or`。你不需要改动任何东西，因为 OpenRouter 的设置只存在于那个函数内部。在我们的测试中，直接输入 `claude` 时回答来自方案里的模型，我们 OpenRouter key 上的用量没有变化。

## 如果 API key 用完了会怎样？

当你的 key 达到额度上限，或者你的账户余额耗尽时，我们会在请求到达模型之前就把它拦下来并返回一个错误。错误里带有 `limit_source` 字段，告诉你原因：

- `openrouter_key_limit` 表示这个 key 已经用完了它的上限。
- `openrouter_credits` 表示你的账户余额已经用完。

想继续用，就在 API keys 页面上调高这个 key 的上限，或者给账户充值。我们的[上限说明页](https://openrouter.ai/docs/api_reference/limits)解释了各种类型的上限，包括团队管理员可以设置的那些。

## 常见问题

### OpenRouter 对 Claude Code 有用量限制吗？

没有五小时上限，也没有每周上限。唯一的限制在花费上：你有多少余额、你给 key 设的上限，以及团队管理员设置的任何预算。

### 模型和我的 Claude 方案里的一样吗？

一样。它们就是 Anthropic 的 Claude 模型。我们从 Anthropic 以及 Amazon Bedrock、Google Vertex 这样的云服务商那里拿到这些模型；如果某个 provider 出问题，[我们会把你的请求发给另一个](https://openrouter.ai/docs/guides/routing/provider-selection)。对 Claude Code 来说，我们建议[把 Anthropic 设为首选 provider](https://openrouter.ai/docs/guides/routing/provider-selection)，因为只有 Anthropic 能保证 Claude Code 正常工作。

### 撞上上限时，我能用更便宜的模型吗？

可以。Sonnet 5.5 的单次会话成本约为 Opus 5.5 的一半，Haiku 5.5 的单次会话不到一美分。你也可以在函数的某个变量里换成别的模型。很多人通过 OpenRouter 在 Claude Code 里用其他模型。这个月，在我们的[应用页面上的 Claude Code](https://openrouter.ai/apps/claude-code)里，GLM 5.3 Flash 是仅次于 Claude Opus 5.5 的第二大使用模型。不过 Claude Code 本来就是为 Claude 模型打造的，所以换任何别的模型都先拿一个小任务试试。如果你在自己的代码里调用我们的 API，还可以[列出 fallback 模型](https://openrouter.ai/docs/guides/routing/model-fallbacks)，让第一个模型失败时请求转到第二个。想进一步降低每次请求的花费，可以看[我们在 OpenRouter 上实现最低成本 LLM 推理的指南](https://openrouter.ai/blog/tutorials/how-to-get-the-lowest-cost-llm-inference-on-openrouter/)。

### Claude Code 的用量上限什么时候重置？

五小时上限在那个窗口的第一条 prompt 发出五小时后重置；每周上限在开始七天后重置。Claude Code 拦下你时会显示重置时间，你就知道什么时候可以再输入 `claude`。

### 我怎么查看自己还剩多少用量？

在你的 Claude 方案上，Claude Code 拦下你时会告诉你上限何时重置。在 OpenRouter 上，用 `GET /api/v1/key` 查 `limit_remaining`，或者打开你的 Activity 页面。
