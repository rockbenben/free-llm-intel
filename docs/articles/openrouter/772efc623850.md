# 如何在 OpenRouter 上获得最低成本的 LLM 推理

OpenRouter ·6/12/2026 · 更新于 9/24/2026

既然你来了，说明你已经知道模型不是唯一的成本变量。同一个模型在一家提供商可能比另一家贵好几倍，这个价差在规模上会迅速复利。

本指南给你自动拿最低价的确切配置，外加那些漏掉就会让账单变高的坑。

已经被账单惊吓过的，先从"成本陷阱"一节开始。想知道 5.5% 平台费值不值，算账在底部的决策表里。只想为你已经选好的模型找最便宜提供商的，给 slug 加 `:floor`，直接跳到那一节。

## 太长不看

- 从免费模型开始。OpenRouter 有 [20 多个 $0 token 成本的模型](https://openrouter.ai/models?max_price=0)。免费账户每天 50 次请求；充一次 $10 后升到每天 1,000 次。
- 默认路由器已经偏向更便宜的提供商，不用配置任何东西就能受益。
- 任何模型 slug 后加 `:floor`，永远路由到该模型最便宜的提供商。
- 需要硬性预算封顶时用 `max_price`。没有提供商达标时请求直接失败，而不是超支。
- 最低标价有时是量化端点。精度要紧时用 `quantizations` 过滤或 `provider.ignore`。

## :floor 成本快捷方式是什么？

OpenRouter 上每个模型都有多家提供商可用，价格并不一致。仅 [Llama 3.3 70B](https://openrouter.ai/meta-llama/llama-3.3-70b-instruct)，输入价就随服务提供商从 $0.10 到超过 $1.00/百万 token。

模型 slug 后加 `:floor`，告诉路由器永远选最便宜的一家。它和请求体里设 `provider.sort: "price"` 完全等价。改一个字符串：

```
from openai import OpenAI

client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key="$OPENROUTER_API_KEY",
)

resp = client.chat.completions.create(
    model="meta-llama/llama-3.3-70b-instruct:floor",  # routes to the cheapest provider
    messages=[{"role": "user", "content": "Classify this ticket."}],
)
```

TypeScript 版：

```
import { OpenRouter } from '@openrouter/sdk';

const openRouter = new OpenRouter({ apiKey: process.env.OPENROUTER_API_KEY });

const completion = await openRouter.chat.send({
  model: 'meta-llama/llama-3.3-70b-instruct:floor',
  messages: [{ role: 'user', content: 'Classify this ticket.' }],
  stream: false,
});
```

它的 counterpart 是 `:nitro`，按吞吐而不是价格排序。两个值得放在一起记：

| 后缀 | 等价于 | 优化目标 |
| --- | --- | --- |
| `:floor` | `provider.sort: "price"` | 最低价格 |
| `:nitro` | `provider.sort: "throughput"` | 最高吞吐 |

`:floor` 的代价：它关掉负载均衡、锁死在最便宜的端点上，而那端点未必是某天最可靠的那个。

批处理、文档处理、离线负载——多花几秒无所谓的场景，这笔交换划算。实时面向用户的调用要三思。最便宜的端点恰好是个退化的端点时，下面"成本陷阱"一节教你排除它。

## OpenRouter 默认如何挑便宜提供商

伸手拿路由配置之前，先理解现在就已经替你运行着什么。即使完全不设置，OpenRouter 的默认也已经偏向更便宜的提供商。

[确切策略](https://openrouter.ai/docs/guides/routing/provider-selection)：

- 跳过过去 30 秒内发生过显著宕机的提供商。
- 在稳定的提供商中，从成本最低的候选里按价格平方倒数加权挑选。
- 其余作为回退。

平方倒数加权是这里真正有用的部分。设提供商 A $1/M、提供商 B $2/M、提供商 C $3/M，且 B 最近宕过几次。你的请求先去 A——先于 C 的概率约是 9 倍，因为 1 除以 3 的平方等于 1/9。A 失败则下一个是 C。B 因宕机记录排最后。便宜和稳定自动平衡。

我们之所以做这个加权，是吃过"按平价路由"的亏：把所有流量都给最便宜的提供商听着合理，直到那家最先在负载下饱和、最先退化、恢复最慢。我们在 80 多家提供商、每月约 100 万亿 token 上跑这套，平方倒数正是让省钱不牺牲可靠性的东西。

要记住的一点：在提供商偏好里设 `sort` 或 `order` 会彻底关掉这个负载均衡。什么时候值得覆盖它，见下一节。

## 如何用 max_price 设硬性价格上限

`:floor` 路由到最便宜的提供商；`max_price` 干的是相反的事：阻止请求去任何高于你设定价格的提供商。`:floor` 找地板，`max_price` 封天花板。

要预算保证，就在 `provider` 字段里用 [`max_price` 对象](https://openrouter.ai/docs/guides/routing/provider-selection#maximum-price)给每百万 token 封顶：

```
resp = client.chat.completions.create(
    model="meta-llama/llama-3.3-70b-instruct",
    messages=[{"role": "user", "content": "Draft a release note."}],
    extra_body={
        "provider": {
            "max_price": {"prompt": 1, "completion": 2}
        }
    },
)
```

这只路由到输入不高于 $1/M、输出不高于 $2/M 的提供商。所有可用提供商都更贵时，请求失败。这是故意的：你宁愿看到报错，也不是一笔没计划过的扣款。

最有用的一组搭配是 `max_price` 配 `sort: "throughput"`：

```
"provider": {
    "sort": "throughput",
    "max_price": {"prompt": 1, "completion": 2}
}
```

这给你最快的可用提供商——前提是输入不高于 $1/M、输出不高于 $2/M。一份配置，速度优化的路由加硬预算保证。

## "够用就行"里最便宜的模型是哪个？

提供商路由降低的是你已选定模型的成本，选更便宜的模型才是更大的杠杆。前沿模型和能干的开放权重模型之间，常常是每 token 10 到 50 倍的差距。

DeepSeek V4、Llama 3.3 70B、Qwen、Mistral 这类开放权重模型能很好地处理多数生产任务：文档处理、分类、摘要、代码生成、结构化抽取。对大多数工作负载，它们才是正确选择。

同一模型在各提供商间的价差，让"该让路由器选"的论点变得具体。[Llama 3.3 70B](https://openrouter.ai/meta-llama/llama-3.3-70b-instruct) 在四家提供商：

| 提供商（Llama 3.3 70B） | 输入 $/M | 输出 $/M |
| --- | --- | --- |
| DeepInfra | $0.10 | $0.32 |
| Novita | $0.135 | $0.40 |
| Groq | $0.59 | $0.79 |
| Together | $1.04 | $1.04 |

光是输出价，同一个模型就从 $0.32 摆动到超过 $1/百万 token，有的端点在 $2 以上。这就是让路由器替你在合格提供商里挑最便宜、而不是写死一家的全部理由。

### 进阶打法：越过性能地板的最便宜模型

哪个模型来处理请求都行的话，你可以给 OpenRouter 一组可接受的模型，让它在所有模型里找满足吞吐阈值的最便宜端点。设 [`partition: "none"`](https://openrouter.ai/docs/guides/routing/provider-selection#provider-sorting)，是告诉路由器按价格跨全部模型做全局排序，而不是永远先试第一个：

```
const completion = await openRouter.chat.send({
  models: [
    'anthropic/claude-sonnet-4.5',
    'openai/gpt-5-mini',
    'google/gemini-3-flash-preview',
  ],
  messages: [{ role: 'user', content: 'Summarize this PR.' }],
  provider: {
    sort: { by: 'price', partition: 'none' },
    preferredMinThroughput: { p90: 50 },
  },
  stream: false,
});
```

这会在三个模型的所有"模型 x 提供商"组合里，选 p90 至少 50 tok/s 中最便宜的。编码任务上，DeepSeek V4 和 Qwen3 Coder 这类开放权重模型的性价比很强。

## BYOK 如何省钱？

你已经和某家提供商有 API key——直接合同、协议价或已有额度——[BYOK（自带 key）](https://openrouter.ai/docs/guides/overview/auth/byok)让你用这些 key 经 OpenRouter 路由。提供商关系和定价保持，OpenRouter 在其上加路由、故障转移和可观测性。

费用是"同一模型同一家提供商在 OpenRouter 的正常价格"的 5%。当前免费额度按套餐而定、按列表价推理成本计量；细则见[定价页](https://openrouter.ai/pricing)。

我们见过团队想当然认为 BYOK 一定更便宜——"毕竟用的是自己的 key"。只有当你的直连提供商费率、减去免费额度之上那 5% 费用后，低于 OpenRouter 零加价的目录价时，它才赢过标准按量付费。假设能省钱之前，先拿你预期的列表价推理支出对照当前额度。

BYOK 配回退集时，`partition: "none"` 在这里也好用。主力模型没配 BYOK 提供商而某个回退配了时，它让 OpenRouter 路由到用你 key 的那个回退，让更多流量留在你自己的价格上：

```
const completion = await openRouter.chat.send({
  models: ['anthropic/claude-sonnet-4.5', 'openai/gpt-5-mini'],
  messages: [{ role: 'user', content: 'Hello' }],
  provider: { sort: { by: 'price', partition: 'none' } },
  stream: false,
});
```

## 爱好项目有免费的 LLM 模型吗？

有。OpenRouter 有 20 多个免费模型，用的就是你平时那个端点和 API key，token 成本 $0。副业项目或周末原型，一分钱不花就能开工。

阵容里有 Llama 3.3 70B、Qwen3 Coder、GPT-OSS 120B、NVIDIA Nemotron 3 Super 等。这些是扎实的模型，做原型和早期验证绰绰有余。

免费模型的请求形态和付费的一模一样。把模型字符串换成免费 slug 就完事：

```
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "meta-llama/llama-3.3-70b-instruct:free",
    "messages": [{"role": "user", "content": "Summarize this changelog in two lines."}]
  }'
```

完整清单在 [openrouter.ai/models?max_price=0](https://openrouter.ai/models?max_price=0)，或者让 [Free Models Router](https://openrouter.ai/openrouter/free) 自动替你挑。

### 代价：免费档速率限制

免费账户每天 50 次请求、每分钟 20 次。充值 $10 及以上后，免费模型上限升到每天 1,000 次，仍是 20 RPM。这笔一次性充值永不过期。

| 账户状态 | 请求/天（免费模型） | 请求/分钟 |
| --- | --- | --- |
| 免费账户 | 50 | 20 |
| 充值 $10+ | 1,000 | 20 |

在免费模型上动工之前还要知道：免费端点的上下文窗口有时比付费版小——长上下文任务在付费端点能用、在免费端点可能被截断。而且失败的请求照样消耗每日配额，配置错误的重试循环能在产出任何有用东西之前烧光你的额度。基于免费端点开发时请加带退避的重试逻辑。

## 值得知道的成本陷阱

最低挂牌价不等于最低实际成本。几件事不提前规划就会推高账单。

### 最便宜的端点可能是量化的

输出质量意外下降时，多数开发者以为是模型变了或提供商更新了设置。一个可能的原因是量化：有些提供商以更低价服务量化权重——FP8、FP4、INT8。你的应用照样返回响应，只是和全精度权重产出的不一样，而日志不会告诉你为什么。

平心而论，量化不是必然更差。我们自己的[基准分析](https://openrouter.ai/blog/announcements/auto-exacto/)发现过与全精度对手打平的激进量化端点。但你的负载对精度敏感时，有两个杠杆。

排除特定提供商：

```
"provider": {
    "sort": "price",
    "ignore": ["provider-slug"]
}
```

或用 [`quantizations` 过滤](https://openrouter.ai/docs/guides/routing/provider-selection#quantization)要求更高精度：

```
"provider": {
    "sort": "price",
    "quantizations": ["fp16", "bf16"]
}
```

### 5.5% 平台费要进每一笔成本计算

我们不给提供商 token 定价加价，但按量充值额度收 5.5% 平台费。充 $100，就有 $5.50 从你的推理预算里出去。它写在[定价页](https://openrouter.ai/docs/faq#pricing-and-fees)上、没有藏，但正是那个让一些对比失真的数字。

拿 OpenRouter token 价格和直连提供商比价、却不含这笔费用的成本算账，都不完整。

### 取消流不总是停止计费

响应到一半 abort 流式请求时，支持[流取消](https://openrouter.ai/docs/api/reference/streaming#stream-cancellation)的提供商上 OpenRouter 会停止计费。Bedrock、Groq、Google、Mistral 等好几家不支持。

你的应用经常取消流——用户点取消、超时、agent 循环提前短路——在把"取消"当成本控制手段之前，先查清哪些提供商支持。

### 免费档的失败请求照样消耗配额

免费模型请求因限流、提供商宕机或超时而失败时，照样烧掉你 50 或 1,000 次日配额里的一次。误触发的重试循环可能在产出任何东西之前耗尽配额。基于免费端点开发请加带退避的重试。

## 合起来：一条成本决策规则

全部内容一张"什么情况用什么"表：

| 你的处境 | 怎么做 | 配置 |
| --- | --- | --- |
| 只是测试或爱好项目 | 免费模型，$0 | `model: "...:free"` |
| 要某个特定模型的最低价 | 加 `:floor` | `model: "...:floor"` |
| 任何能干的模型都行 | 回退集，价格排序加吞吐地板 | `sort: { by: "price", partition: "none" }` + `preferredMinThroughput` |
| 硬性预算上限 | 加价格封顶 | `provider: { max_price: { prompt: 1, completion: 2 } }` |
| 已经在给某家提供商直付费 | BYOK | 配置你的 key；免费额度见定价页 |
| 要便宜但担心质量 | 排除提供商或按精度过滤 | `ignore: ["provider"]` 或 `quantizations: ["fp16", "bf16"]` |
| 要便宜又保可靠性 | 保持默认不动 | 无需配置 |

主线：在 OpenRouter 上，"便宜"是一次性做出的配置决定。如果你的负载在多轮之间重复同一条长提示词，[提示词缓存加粘性路由](https://openrouter.ai/blog/tutorials/prompt-caching-sticky-routing/)能在以上任何一种路由选择之上再砍输入成本。

这些杠杆背后的完整路由机制见[提供商路由参考](https://openrouter.ai/docs/guides/routing/provider-selection)和[模型回退](https://openrouter.ai/docs/guides/routing/model-fallbacks)。

## 常见问题

### OpenRouter 比直连提供商便宜吗？

token 定价上不是——提供商费率零加价透传。省钱的地方在路由：接入你可能没有账户的更便宜提供商；自动故障转移让失败的请求不浪费算力；批处理自动路由到可用的最便宜端点，逻辑不用你自己维护。真正要算进去的成本是额度购买上 5.5% 平台费：每月推理 $500，就是 $27.50。值不值，取决于否则你要花多少工程时间在管理提供商上。

### OpenRouter 上最便宜的模型是哪个？

免费模型 token $0。阵容包括 Llama 3.3 70B、Qwen3 Coder、GPT-OSS 120B、NVIDIA Nemotron 3 Super——无额度时每天 50 次请求，充过 $10 后每天 1,000 次。付费推理上，开放权重模型配 `:floor` 路由自动给你该模型最便宜的提供商。

### OpenRouter 的免费模型真免费吗？

真 $0 每 token。限制是免费账户每天 50 次请求，充 $10 额度后每天 1,000 次，都是 20 RPM。免费端点的上下文窗口有时比付费版小。

### 怎么永远用最便宜的提供商？

模型 slug 后加 `:floor`，或请求体里设 `provider.sort: "price"`。两个是同一件事。

### 最便宜的 LLM API 干编码活够用吗？

例行编码任务，够。Qwen3 Coder、DeepSeek V4 这类开放权重模型以前沿模型一小部分的价格处理样板代码、重构、评审和文档。复杂架构设计和疑难调试上前沿模型仍占明显优势，把贵调用留给那里。

### OpenRouter 对失败的请求收费吗？

不。只为成功的补全付费，失败和回退请求不计费。
