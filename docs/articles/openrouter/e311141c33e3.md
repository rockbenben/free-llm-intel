OpenRouter 的图像生成现在有了专属 API，统一接入 30+ 模型。

和我们所有的媒体生成 API 一样，我们标准化了接口以便轻松切换模型、允许透传模型独有能力，并提供以编程方式发现每个模型细节的途径。我们支持来自 Google、OpenAI、Black Forest Labs、Recraft、ByteDance、Sourceful、Microsoft 和 xAI 的模型，并且一直在新增。

[浏览图像模型](https://openrouter.ai/models?output_modalities=image) | [API 文档](https://openrouter.ai/docs/guides/overview/multimodal/image-generation) | [在 playground 中试用](https://openrouter.ai/playground)

## 了解每个模型能做什么

图像模型的差异会让请求失败。Seedream 4.5 支持 18 种宽高比；Gemini 3.1 Flash Image 支持 14 种（有重叠但不相同）。有些模型单次调用最多生成 10 张；另一些上限为 1 张。有些接受 16 个输入参考；另一些只接受 4 个。

`/api/v1/images/models` 端点为每个模型返回带类型的描述符：

```
{
  "id": "bytedance-seed/seedream-4.5",
  "supported_parameters": {
    "resolution": { "type": "enum", "values": ["1K", "2K", "4K"] },
    "aspect_ratio": { "type": "enum", "values": ["1:1", "16:9", "9:16", "..."] },
    "n": { "type": "range", "min": 1, "max": 10 },
    "input_references": { "type": "range", "min": 0, "max": 14 },
    "seed": { "type": "boolean" }
  },
  "supports_streaming": false
}
```

你的代码可以适配任何模型，无需硬编码服务商差异，也不必因参数不被接受而和 400 错误搏斗。

这对 agent 尤其有用。把 `/api/v1/images/models` 的响应交给你的 coding agent，它就拥有了选择模型、校验输入、免于试错地生成图像所需的一切。

## 按服务商的细粒度信息

每个模型可能由多个服务商提供。按端点的记录（`/api/v1/images/models/{id}/endpoints`）给出每个端点的权威事实：*这个具体端点*接受哪些参数、允许哪些透传键、是否支持流式，以及细粒度定价。

```
curl "https://openrouter.ai/api/v1/images/models/google/gemini-3.1-flash-image/endpoints"
```

每个端点还会返回一个 `pricing` 数组，写明精确的计费结构。不同服务商使用不同的计费单位：

```
"pricing": [
  { "billable": "output_image", "unit": "image", "cost_usd": 0.04 }
]
```

Seedream 4.5 按每张图固定 $0.04 收费；FLUX.2 Pro 按每百万像素 $0.03 计费（因此分辨率影响成本）；GPT-5.4 Image 2 和 Gemini 3.1 Flash Image 按 token 计费。再也不用猜一次生成为什么是那个价——每个响应的 `usage` 对象都包含以 USD 计的精确成本。

## 一种请求结构，任意模型

这个 API 把图像生成碎片化的世界归一化成一个 schema：

```
curl -X POST "https://openrouter.ai/api/v1/images" \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "bytedance-seed/seedream-4.5",
    "prompt": "a red panda astronaut floating in space, studio lighting",
    "resolution": "2K",
    "aspect_ratio": "16:9"
  }'
```

分辨率、宽高比、质量、输出格式、背景透明、输入参考、流式：跨所有服务商全部归一化。当你需要服务商特有功能（如 Black Forest Labs 的 `steps` 或 `guidance`）时，通过 `provider.options` 透传，以 endpoints API 中的 provider slug 作为键。

## GPT Image 模型的流式预览

OpenAI 的 GPT Image 模型（GPT-5 Image、GPT-5 Image Mini、GPT-5.4 Image 2）支持通过 Image API 的原生 SSE 流式输出。设置 `"stream": true`，你会在渲染过程中收到图像的部分预览，让用户看到进度而不是等待完整生成。检查任意端点的 `supports_streaming` 字段即可确认是否可用。

## FAQ

### 通过 chat completions 的图像生成会怎样？

在此之前，我们通过 completions 和 responses 支持图像生成。所有现有图像模型仍会在此得到支持，但新的图像模型将只加入专属的 Image API。

如果你在用 `openai/gpt-5-image`、`openai/gpt-5-image-mini` 或 `openai/gpt-5.4-image-2`，我们建议切换到某个专属图像模型。GPT 5 和 5.4 版本是通过 LLM 生成图像的，因此无法访问全部受支持的参数，还可能产生额外的推理成本。

### 我能使用服务商特有功能吗？

可以。每个端点都暴露一个 `allowed_passthrough_parameters` 列表。在 `provider.options` 下以 provider slug 为键传入服务商特有的键。endpoints API 会精确告诉你哪些键被接受。

### 计费如何运作？

每个端点返回细粒度的定价行，包含计费项、USD 成本和可选的分档（如按分辨率定价）。每个响应的 `usage` 对象包含精确成本。
