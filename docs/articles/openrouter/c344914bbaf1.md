# OpenRouter 上的转录

OpenRouter · 2026/7/22 · 更新于 2026/9/24

你手上有 40 分钟的销售通话录音、一文件夹的语音备忘，或者用户正按住麦克风按钮，而你需要的是一份文字转录。常规做法是专门搭一个 Whisper 服务器，或者在已经处理聊天流量的技术栈之外再引入第二家供应商的 SDK，只为做语音转文字。在 OpenRouter 上，你可以把音频直接发送到 `POST /api/v1/audio/transcriptions`，拿回的 JSON 里就有转录文本和一个 usage 对象，而且用的还是和 Chat Completions 完全相同的 API key 与鉴权方式。

你不需要新的 SDK，也不需要另一套独立服务。因为转录和你的聊天流量跑在同一个平台上，当某个模型由多家供应商托管时，请求会自动在它们之间做负载均衡，而不是被锁死在单一厂商身上。

## Tl;dr

- 转录的方式是：把 base64 编码的音频发送到 `POST /api/v1/audio/transcriptions`，然后从响应的 JSON 里读取文本和一个 `usage` 对象。它使用与 Chat Completions 相同的 Bearer key。
- Whisper 系列模型可以在这里用：`openai/whisper-1`、`openai/whisper-large-v3` 和 `openai/whisper-large-v3-turbo`。按 token 计费的更新的语音转文字（STT）模型也有。要用 `?output_modalities=transcription` 来发现它们，而不是默认的模型目录。
- 当某个转录模型被不止一家供应商托管时，我们会自动在它们之间做负载均衡。你在聊天请求里习惯用的那些按请求路由控制（`order`、`allow_fallbacks`、`data_collection`、`sort`）目前在这个端点上不生效；这里的 provider 块只承载供应商专属的选项。自带 key（BYOK）会路由到你自己的供应商 key，只收取平台费。
- 真正需要围绕其做设计的限制是：60 秒的上游超时、不支持音频 URL（要么发 base64 JSON，要么发 OpenAI 风格的 multipart 文件且不超过 25 MB）、以及不支持 SRT/VTT 输出。在包括 OpenAI、Groq、Deepgram、Mistral 在内的大多数供应商上，用 `response_format: "verbose_json"` 可以拿到词级和段落级的时间戳。
- 计费方式因模型而异，要么按音频时长、要么按 token，且[没有供应商加价](https://openrouter.ai/pricing)。`usage.cost` 字段会返回每次请求的实际成本，方便你核算支出。

## 如何在 OpenRouter 上转录音频？

把 base64 编码的音频发送到 `POST /api/v1/audio/transcriptions`，然后从响应的 JSON 里读取 `text` 字段。你把 OpenRouter API key 作为 Bearer token 传进去——和聊天调用完全一样——指定一个模型，把音频交给它就行。

响应是一段 JSON：`text` 字符串装着转录内容，`usage` 对象报告音频时长（秒）、token 数量和这次请求的美元成本。你发起一次请求，转录结果就在响应体里返回，因此没有轮询，也不需要追踪什么任务 ID。

![在 OpenRouter 上转录音频的三步示意图：请求体中的 base64 编码音频，POST /api/v1/audio/transcriptions 在多家供应商之间自动负载均衡，以及带 text 与 usage 字段的 JSON 响应](https://openrouter.ai/blog/images/transcription-request-flow.png)

请求体里带一个 `model` 和一个 `input_audio` 对象。在 `input_audio` 内部，你放入文件的 base64 数据和一个格式字符串。可选地，你还可以加上语言提示、temperature 和一个 provider 块。下面是端到端的完整示例：

```
# Encode the file to base64, then POST it.
AUDIO_B64=$(base64 -i meeting.mp3 | tr -d '\n')

curl https://openrouter.ai/api/v1/audio/transcriptions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/whisper-1",
    "input_audio": { "data": "'"$AUDIO_B64"'", "format": "mp3" },
    "language": "en"
  }'
```

```
import base64
import os

import requests

with open("meeting.mp3", "rb") as f:
    audio_b64 = base64.b64encode(f.read()).decode("utf-8")

api_key = os.environ["OPENROUTER_API_KEY"]

response = requests.post(
    "https://openrouter.ai/api/v1/audio/transcriptions",
    headers={"Authorization": f"Bearer {api_key}"},
    json={
        "model": "openai/whisper-1",
        "input_audio": {"data": audio_b64, "format": "mp3"},
        "language": "en",
    },
)

print(response.json()["text"])
```

```
import { OpenRouter } from '@openrouter/sdk';
import { readFileSync } from 'fs';

const openRouter = new OpenRouter({ apiKey: process.env.OPENROUTER_API_KEY });

const audioB64 = readFileSync('meeting.mp3').toString('base64');

const result = await openRouter.stt.createTranscription({
  sttRequest: {
    model: 'openai/whisper-1',
    inputAudio: { data: audioB64, format: 'mp3' },
    language: 'en',
  },
});

console.log(result.text);
```

## 有哪些可用的语音转文字模型？

你可以从两类模型中挑选。像 [`openai/whisper-1`](https://openrouter.ai/docs/guides/overview/multimodal/stt) 这样的 Whisper 级模型按音频时长计费（每秒），而较新的语音转文字模型按 token 计费。哪个更合适，取决于你的准确率要求、语言组合和预算。

STT 模型 ID 不会出现在默认的 `/api/v1/models` 目录里。这属于预期行为，因为转录是一种需要显式筛选的输出模态。

```
curl "https://openrouter.ai/api/v1/models?output_modalities=transcription" \
  -H "Authorization: Bearer $OPENROUTER_API_KEY"
```

这条请求会返回语音转文字模型及其当前各模型的实时价格。如果你更喜欢当网页来阅读，同样的列表也在 [Speech-to-Text 合集](https://openrouter.ai/collections/speech-to-text-models)里；而[模型目录](https://openrouter.ai/models)则保有各模型的实时费率。

如果你想先试试某个模型再接入代码，[OpenRouter Playground](https://openrouter.ai/playground) 可以在浏览器里直接转录你上传的文件。

## 逐字段的请求契约

整个流程分三步。你把文件做 base64 编码，连同模型和格式一起 POST 出去，然后从响应里读取 `text` 和 `usage`。`data` 字段接受的是原始 base64 字节，而不是 `data:` URI，所以不要给它加 `data:audio/mp3;base64,` 前缀。`format` 字段是必填的，它告诉上游模型如何解码这些字节。

| 参数 | 是否必填 | 是什么 |
| --- | --- | --- |
| `model` | 是 | STT 模型 slug，例如 `openai/whisper-1` |
| `input_audio.data` | 是 | base64 形式的音频（原始字节，**不是** `data:` URI） |
| `input_audio.format` | 是 | `wav`、`mp3`、`flac`、`m4a`、`ogg`、`webm`、`aac` 之一 |
| `language` | 否 | ISO-639-1 语言码（`en`、`es`……）。省略时自动检测 |
| `temperature` | 否 | 采样温度，0 到 1 |
| `response_format` | 否 | `json`（默认）或 `verbose_json`；后者会在支持的供应商上额外给出 `language`、`duration` 和段落时间戳 |
| `timestamp_granularities` | 否 | 配合 `verbose_json` 使用 `["segment"]` 或 `["word"]`；`word` 会在 `words` 数组里给出词级时间戳 |
| `provider` | 否 | 供应商专属选项透传（例如 Groq 的 `prompt`）。按请求的路由控制在此端点不生效 |

该端点也接受 OpenAI 风格的 `multipart/form-data` 上传（`file` 加 `model`），上限 25 MB。如果你已经有为 OpenAI 的 `/v1/audio/transcriptions` 写好的客户端，把它的 base URL 指向 `https://openrouter.ai/api/v1` 就能原样使用。超过 25 MB 的文件请走 base64 JSON 路径。

语言提示是可选的。省略时模型会自行检测语言；对于较短或嘈杂的音频片段，设置它可以消除一些歧义。有些供应商通过 `provider` 接受自己的额外参数。比如 Groq 允许在 `provider.options.groq.prompt` 里传入预期词汇表的 `prompt`，这对模型容易听错的专有名词和行话很有帮助。

### 响应及其用量核算

响应是一段 JSON，含一个 `text` 字符串和一个 `usage` 对象。usage 对象让你能够按请求核算支出，而不是靠估算。

```
{
  "text": "Thanks everyone for joining. Let's start with the Q3 numbers.",
  "usage": {
    "seconds": 9.2,
    "total_tokens": 113,
    "input_tokens": 83,
    "output_tokens": 30,
    "cost": 0.000508
  }
}
```

这个 `cost` 值取自我们文档里的示例，不是报价；你的实际成本取决于模型和音频长度。usage 对象报告 `seconds`（音频时长）、token 数量以及美元计的 `cost`。响应还会带一个 `X-Generation-Id` 头，你可以把它记下来，以便之后追踪或调试某个具体请求。

## 什么时候用转录，什么时候用音频输入或语音合成？

想把音频变成文本就用 `/audio/transcriptions`；想让模型对音频本身进行推理，就用聊天接口里的音频输入。

转录端点适合会议纪要、语音指令、字幕，以及通话或播客的全文可搜索归档。如果你想对客服通话做情感分析、就谈话内容进行问答，或者在同一个提示词里把音频和其他模态混合处理，请在 `/chat/completions` 上使用 `input_audio` 内容类型。把文本变成语音则是第三个独立的端点。

![转录端点与聊天音频输入的对比图：POST /api/v1/audio/transcriptions（音频转文本，返回 JSON 文本加 usage）对比 /chat/completions 上的 input_audio（对音频进行推理，返回一次聊天补全），并列出各自的用例](https://openrouter.ai/blog/images/transcription-two-endpoints.png)

| 你想要…… | 用什么 | 得到什么 |
| --- | --- | --- |
| 把音频转成文本（一份转录） | `POST /api/v1/audio/transcriptions` | JSON 文本加 usage |
| 让模型对音频进行推理（情感、问答、多模态） | `/chat/completions` 上的 `input_audio` | 一次聊天补全 |

关于音频分析和语音合成，请参阅[音频 API 发布公告](https://openrouter.ai/blog/announcements/announcing-audio-apis/)。

## 转录的供应商路由是如何工作的？

转录使用和聊天相同的路由层。当一个模型被不止一家供应商托管时，我们会把你的请求分配到它们之间，按价格做负载均衡，这样你就不会被锁死在单一厂商上。转录目前不开放的是按请求的路由控制。你在聊天调用里会设置的 `order`、`only`、`allow_fallbacks`、`data_collection` 和 `sort` 字段，在 `/api/v1/audio/transcriptions` 上并不生效。这个端点上的 provider 块承载的是供应商专属选项，例如：

```
{
  "model": "openai/whisper-large-v3",
  "input_audio": { "data": "<base64>", "format": "wav" },
  "provider": {
    "options": {
      "groq": { "prompt": "Expected vocabulary: OpenRouter, API, transcription" }
    }
  }
}
```

这条请求给 Groq 传了一个词汇提示，帮助它处理本来容易听错的专有名词。这些选项以供应商 slug 为键，只有匹配到的那家供应商的选项会被转发。如果你需要在转录上锁定某个特定供应商或强制某个按请求的数据策略，这个端点目前还没有提供这种控制。完整的 provider 对象在[供应商路由文档](https://openrouter.ai/docs/guides/routing/provider-selection)里有说明。

OpenRouter[不会在供应商价格上加价](https://openrouter.ai/pricing)，所以目录上标多少你就付多少；再加上零补全保险（Zero Completion Insurance），失败的转录不会计费。如果你已经有供应商协议，[BYOK](https://openrouter.ai/docs/guides/overview/auth/byok) 让你通过自己的供应商 key 路由，在按套餐而定的免费额度用尽后，只支付我们 5% 的平台费而不是按用量的模型费用；当前细节请见[定价页](https://openrouter.ai/pricing)。

## 有哪些需要提前规划的限制？

有四个约束决定了转录调用怎么组织：

![支持的音频格式（wav、mp3、flac、m4a、ogg、webm、aac）与三条需要规划绕开的限制示意图：60 秒处理超时、不支持音频 URL、不支持 SRT/VTT 输出](https://openrouter.ai/blog/images/transcription-formats-limits.png)

| 限制 | 对你意味着什么 |
| --- | --- |
| 60 秒上游超时 | 约 60 秒的处理时间，不是音频长度的硬性上限。超时的大多是大型或未压缩的录音。请把长音频切分成片段、分别转录，再把文本拼接起来。 |
| 不支持音频 URL | 在这个端点上不能用 URL 传音频。请发 base64 JSON，或不超过 25 MB 的 OpenAI 风格 multipart 文件。压缩格式（mp3、aac）生成的负载更小、更快。 |
| 不支持 SRT/VTT 输出 | `srt`、`vtt` 和 `text` 这些响应格式会直接返回 400。时间戳可以通过 `verbose_json` 获得；字幕文件请你用这些时间戳自己构建。 |
| 格式支持因供应商而异 | 通用列表是 wav/mp3/flac/m4a/ogg/webm/aac，但某个具体模型或供应商未必全部接受。wav 是最稳妥的默认选择。 |

因为超时限制的是处理时间而不是音频长度，光看片段时长并不能告诉你它能否成功。像通宵游戏录像这样一跑就是几小时的录音，就必须走切分处理；单次请求是搞不定的。

对于字幕，默认响应只有文本加 usage，不带时间信息。把 `response_format` 设为 `verbose_json`，你就能拿到段落级时间戳；如果再传 `timestamp_granularities: ["word"]`，还能拿到词级时间戳。OpenRouter 只会向能够返回时间戳的端点发出 `verbose_json` 请求，这包括 OpenAI、Groq、Deepgram、Mistral 和 Azure。如果某模型的所有端点都做不到——比如 `openai/gpt-4o-transcribe`——请求会以 400 失败。没有内置的 `.srt`/`.vtt` 输出，所以字幕文件需要你用时间戳自己构建。

## 一次转录请求要花多少钱？

你支付的就是模型在目录上的费率，我们不加价，而 `usage.cost` 字段会告诉你每次请求的确切数字。Whisper 级模型按音频秒数计费，较新的模型按 token 计费。

费率会变，所以我们把实时数字放在[目录](https://openrouter.ai/models)中每个模型的页面上，而不是写在这里。从响应中读取 `usage.cost` 就能知道每个请求实际花了多少。STT 模型都是付费的，所以通过 API 转录会消耗你的信用余额。

上手建议：先在 [Playground](https://openrouter.ai/playground) 里确认某个模型适合你的音频，然后接好调用，并从第一天起就通过读取每次请求的 `usage.cost` 来核算支出。

## 常见问题

### 我如何用 OpenRouter 转录音频文件？

把 base64 编码的音频发送到 `POST /api/v1/audio/transcriptions`，带上一个 `model` 和一个 `input_audio` 对象（`data` 加 `format`）。响应是 JSON，包含一个 `text` 字符串（转录内容）和一个 `usage` 对象（秒数、token 和成本）。它使用与 Chat Completions 相同的 Bearer API key 和鉴权。

### OpenRouter 支持 Whisper 吗？

支持。有三个 Whisper 模型可用：`openai/whisper-1`、`openai/whisper-large-v3` 和 `openai/whisper-large-v3-turbo`。STT 模型 ID 不在默认的 `/api/v1/models` 列表里，所以你需要用 `?output_modalities=transcription` 筛选，或者浏览 [Speech-to-Text 合集](https://openrouter.ai/collections/speech-to-text-models)来发现它们。Whisper 按音频时长计费（每秒）；较新的 STT 模型则改为按 token 计费。

### OpenRouter 转录接受哪些音频格式？

通用的一组是 `wav`、`mp3`、`flac`、`m4a`、`ogg`、`webm` 和 `aac`，通过必填的 `input_audio.format` 字段传入。支持情况因模型和供应商而异，并非每个模型都接受每种格式。要追求最广兼容性，`wav` 是最稳妥的默认选择；`mp3` 这类压缩格式能带来更小、更快的负载。

### OpenRouter 能返回时间戳或 SRT/VTT 字幕吗？

时间戳可以。把 `response_format` 设为 `verbose_json` 可获得段落级时间戳，再加上 `timestamp_granularities: ["word"]` 就能在 `words` 数组里拿到词级时间戳。大多数供应商都支持，包括 OpenAI、Groq、Deepgram、Mistral 和 Azure；而没有任何能返回时间戳的端点的模型（例如 `openai/gpt-4o-transcribe`）会以 400 拒绝该请求。SRT/VTT 输出不受支持，所以字幕文件需要你用时间戳自行构建。

### 音频可以有多长？

实际限制是约 60 秒的上游处理超时，而不是固定的音频长度上限。短和中等长度的片段一次调用即可返回。对于长录音，请把音频切成片段、分别转录，再把文本拼接起来。

### OpenRouter 转录的费用是多少？

你支付模型在目录上的费率，我们不加价。Whisper 级模型按音频秒数计费；较新的 STT 模型按 token 计费。`usage.cost` 字段会在响应中报告该请求确切的美元成本。
