# OpenRouter 与 Portkey：哪个 LLM 网关适合您的团队？

OpenRouter ·6/19/2026 · 更新于 9/24/2026

比较 OpenRouter 和 Portkey 时，真正要回答的问题是：你想要一个替你路由请求的东西，还是一个治理你已有请求的东西。

OpenRouter 是托管路由网络。你买额度，调一个 OpenAI 兼容端点，它在 [70 多家提供商](https://openrouter.ai/models)之间路由并自动故障转移，你从头到尾不用持有提供商 key。Portkey 是一个 AI 控制平面，在 [2026 年被收购](https://www.paloaltonetworks.com/company/press/2026/palo-alto-networks-to-acquire-portkey-to-secure-the-rise-of-ai-agents)后已成为 Palo Alto Networks 的一部分。它挡在你已有的提供商 key 前面，加上治理、提示词管理、护栏和可观测性。

想要零基础设施拿到模型接入和故障转移，选 OpenRouter。需要在你已经在运营的提供商账户之上加一层治理，选 Portkey。

## 跨提供商路由，还是治理你自己的 key

OpenRouter 拥有通往模型的路径。你的应用调用 `https://openrouter.ai/api/v1`，OpenRouter 挑一家提供商，用你已经买好的额度把请求转出去。没有一家家的提供商账户要管，一家提供商上失败的请求会自动转到另一家。

Portkey 拥有的是 key 前面那一层。你自带提供商凭证（OpenAI、Anthropic、Azure 等），把它们存成虚拟 key，Portkey 对每次调用做路由、缓存和日志。它的[开源网关](https://github.com/Portkey-AI/gateway)在 GitHub 上有 12K+ star，3 行代码即可安装，可以自己托管，也可以用托管版。

用 OpenRouter，提供商关系你整体外包；用 Portkey，你保留它们，再用政策把它们包起来。

## 比模型数量，但要比对的东西

Portkey 宣称通过其统一 API 可接入 [1,600 多个 LLM](https://portkey.ai)。OpenRouter 上架 [70 多家提供商的 300 多个模型](https://openrouter.ai/models)，含 20 多个供评估的免费模型。原始数字偏向 Portkey，但它们衡量的不是一回事。

Portkey 的数字是你供好 key 之后可以寻址的模型广度。OpenRouter 的数字是它主动路由到的模型——额度、负载均衡和跨提供商故障转移都替你处理好了。它的 [Auto Router](https://openrouter.ai/docs/guides/routing/routers/auto-router) 以市场智慧为动力，给每个提示词分类，再按 OpenRouter 社区过去滚动 7 天在该任务类型上的总支出给候选排名；[提供商路由](https://openrouter.ai/docs/features/provider-routing)允许你按价格、吞吐、延迟、数据政策和量化精度过滤。

数字你想比哪个就比哪个。决策仍然落在：你要的是一个替你路由的网络，还是你自运营的提供商账户上面的一个统一前端。

## 把可观测性和治理匹配到你的团队

Portkey 以治理为核心。产品内置日志、追踪和仪表盘，按档位设保留期（免费 Developer 计划 3 天，Production 30 天，Enterprise 自定义），另有带 playground 的提示词模板、基于角色的访问控制、预算和速率限制，护栏包含 PII 脱敏。对一个要把众多内部应用标准化的平台团队，这个控制平面就是卖点。

OpenRouter 的可观测性做法更轻。它不长期存储你的日志，[Broadcast](https://openrouter.ai/docs/guides/features/broadcast) 会把 trace 流转给你已经在用的平台，包括 Datadog、Langfuse、LangSmith、Braintrust、OpenTelemetry 和 S3。Workspaces 为想在多个内部应用之间建立结构的团队补上按团队的组织与预算。

合规方面，两家都持有 SOC 2 Type 2 并支持 GDPR。OpenRouter 在 Business 和 Enterprise 计划上额外提供[零数据保留](https://openrouter.ai/docs/guides/features/zdr)和 [EU 域内路由](https://openrouter.ai/docs/guides/features/in-region-routing)，报告在 [trust.openrouter.ai](https://trust.openrouter.ai)。Portkey 在企业版提供 HIPAA 和定制 BAA，另有 VPC 托管和数据隔离。想要数据驻留但又不想自己运营基础设施的团队，往往指向 OpenRouter。

## 选一个与你量级匹配的价格模式

两家定价的坐标轴不同。OpenRouter 按 0% 加价透传提供商定价，然后对额度购买收 [5.5% 平台费](https://openrouter.ai/pricing)，单笔最低 $0.80。自带 key（BYOK）在按套餐而定的免费额度之后，对等价的 OpenRouter 成本收 5% 费用；最新细则见[定价页](https://openrouter.ai/pricing)。你只为用量付费，别的都不付。

Portkey 按日志量和功能定价。它的 [Developer 档](https://portkey.ai/pricing)免费、每月记录 10K 条日志，但 Portkey 自己标注不适合生产。Production 档 $49/月含 10 万条日志（每加 10 万条 $9，至 300 万条封顶），并解锁 RBAC 和护栏。Enterprise 定制报价，含 HIPAA、SSO、私有部署和更长保留期。开源网关愿意自己跑的话免费。

净成本取决于你的重量压在哪边。模型支出很高、提供商 key 已经握在手里的场景往往更适合 Portkey 的自托管网关；不想要计量也不想运维的用量，更适合 OpenRouter 的按量付费。

## 两个都用，或者从痛点开始

两者不互斥。你可以把 OpenRouter 作为上游提供商挂到 Portkey 后面，让 Portkey 的治理和提示词管理挡在 OpenRouter 的路由网络前面。OpenRouter 也把 Portkey 列为[即将支持的广播目的地](https://openrouter.ai/docs/guides/features/broadcast)，届时 trace 也会反方向流动。

如果你在权衡更多选项，我们的 [LLM 网关对比](https://openrouter.ai/blog/insights/llm-gateway/) 覆盖了 LiteLLM、Helicone、Cloudflare AI Gateway 等。

## 常见问题

### Portkey 和 OpenRouter 是同类工具吗？

它们在统一 API 上有重叠，但解决的是不同的问题。OpenRouter 是托管路由网络：你买额度，它在 70 多家提供商之间路由、自动故障转移，不需要提供商 key。Portkey 是控制平面，挡在你已有的提供商 key 前面，加上治理、提示词管理和产品内可观测性。

### Palo Alto Networks 收购 Portkey 了吗？

收购了。Palo Alto Networks 在 2026 年完成对 Portkey 的收购，将其并入公司的 AI 安全产品线。Portkey 继续运营其网关，包括开源版本。

### OpenRouter 和 Portkey 在合规上怎么比？

两家都持有 SOC 2 Type 2 并支持 GDPR。OpenRouter 在 Business 和 Enterprise 计划上另有零数据保留和 EU 域内路由。Portkey 在企业版提供 HIPAA 和定制 BAA。具体认证要求请查各平台的信任中心。

### 哪个更便宜？

取决于量。OpenRouter 对额度购买收 5.5% 平台费（自带 key 在按套餐而定的免费额度后收 5%），提供商价格 0% 加价；最新额度细则见[定价页](https://openrouter.ai/pricing)。Portkey 自托管或 Developer 档免费，之后 Production 档 $49/月。已经持有提供商 key 的高量团队常跑 Portkey 的开源网关；想要托管路由、什么都不用自己运营的团队选 OpenRouter。

### OpenRouter 和 Portkey 能一起用吗？

能。你可以把 OpenRouter 作为上游提供商之一指向 Portkey，让 Portkey 的治理和可观测性挡在 OpenRouter 路由网络的前面。OpenRouter 也把 Portkey 列为即将支持的广播目的地，用于发送 trace。
