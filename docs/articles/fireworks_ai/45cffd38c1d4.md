> 这是面向「对训练浅尝辄止、或好奇训练究竟需要什么」的工程师的专用智能系列文章的第一篇。

## TL;DR

- •用专用智能训练自己的模型，意味着拥有让贵公司独一无二的那些东西
- •通往专用智能的路可以先从租用闭源前沿开始，但必然通向训练开源模型
- •公司为何转向自训模型，存在几种常见模式

## 通往专用智能之路

团队决定训练自己的模型，原因不外乎几条：

- •担心某个闭源前沿实验室侵入自己的领域
- •通用模型达不到自己垂直行业的质量线
- •对于实际需要的智能，API 账单太高

所有这些之下是同一个本能：拥有定义自己业务的专用智能。这篇文章讲的就是通往那里的路。

你先从租用能拿到的最强大（通常也是最贵的）闭源 LLM 开始，围绕该模型工程化专用的 harness、系统与组件，来提升它在你的任务上的表现。等这些组件榨干之后，你迁移到更便宜但依然有效的开源模型，在最大化效用的同时削减成本。最后，如果这个问题真正是你自己的问题，你会决定通过训练一个定制模型来完全拥有这份智能。

## 阶段 1：租用闭源前沿

几乎每个人都从 API 后面的闭源前沿模型开始。这有道理**：**这些供应商砸巨资把模型营销到每一个角落，**试图拉你上车。这些模型很强大，而且因为别人在承担训练与服务成本，你按用量付 token 费。

缺点很深，但你会遇到的主要有三个：

模型过于通用，必须在其上叠加提示工程才能以专业化的方式做事。能用的时候确实好用，但模型是被别人塑造的，是为所有人塑造的。

闭源 API 在一切意义上都是租用。你不控制模型权重、价格、延迟、弃用时间表，而且在多数情况下，你不控制你的数据。

你的 token 溢价和发给团队的企业订阅，供养着这一切：你从未碰过的基础设施、营销活动、给营销活动提咨询建议的顾问，以及让实验室留在前沿的研发。你在补贴一台你既不拥有、也无力驾驶的机器。

在他们为模型投入这么多之后，闭源前沿 LLM 确实强大，但出厂时过于泛化，需要投喂相关上下文才在日常中可用。于是 AI 工程登场。

## 阶段 2：AI 工程——提示词、上下文与 harness，一样都不能少！

过去几年的 AI 工程遵循一条清晰的升级路径，每一层都是为了从我们租来的现成模型里多挤一点。**prompt engineering（提示工程）**先行：few-shot 示例和 chain-of-thought 证明了改变提问方式能诱发更强、更一致的行为。随着我们往上下文窗口里灌入越来越多内容——通常是为检索增强生成（RAG），让模型跟上变化的信息——它演变为**上下文工程**。而提示词和上下文都搞定后，智能体来了，用工具调用循环塞满同一个窗口，于是我们转向 **harness 工程：**对话压缩、工具优化、MCP 等等，把上下文窗口当成预算而不是水桶。

整条弧线，一直是人类在为一个永不变的模型收拾工程的残局。

多数认真做事的团队长期停留在这一阶段，而这是你第一次真正感觉在拥有自己的 AI。提示、工具使用和 RAG 能带你走得惊人地远；但有一层天花板。你 harness 里的每个模型仍旧是出厂货架上的那个模型。你的提示词和 harness 在引导模型，却没有教给它任何东西。而且 harness 知道的关于你业务的一切，都在每一个请求里用你要付费的 token 重新解释一遍，贴进一个下周可能就宣布弃用的模型的 prompt 里。

每个 AI 系统实际上都在三个轴上被优化：**质量**（够好吗？）、**成本**（规模上付得起吗？）、**延迟**（够快吗？）。AI 工程就是在不碰模型本身的前提下同时推进这三项的努力，在撞上任何一项天花板之前它可以带你很远。解决性能天花板很难，所以多数人会先朝成本与延迟开刀，而最有效的方法之一，就是把开源模型混进来。

## 阶段 3：把开源模型加入组合

如今，前沿开源模型往往能以闭源前沿模型一小部分的成本把活干完，而且视任务而定，质量差距很小甚至不存在。

这个阶段由**单位经济与掌控权**定义，而非意识形态。到了这个阶段，你会想要决定模型跑在哪、响应多快、你的数据会怎样、每个 token 每个任务付多少钱。要选对模型（开源或闭源），你要么依赖公开的基准，要么——更好的做法——在你自己的任务上评估候选。

基准未必代表你实际在做的工作。也许你的金融科技用例比基准的示例更小众，或者你的法律问题横跨十几个领域、不断变化的理念。基准是不错的初筛手段；你自己的 **evals**（针对你的具体任务、系统化的自建 AI 测试）永远是表现的最佳指标。

| 基准 | Kimi K3（max reasoning） | GPT 5.6 Sol（max reasoning） |
| --- | --- | --- |
| 基准 | Kimi K3（max reasoning） | GPT 5.6 Sol（max reasoning） |
| OSWorld 2.0 | 58.3 | 62.6 |
| UIPad | 87.7 | 87.7 |

假设你在构建需要浏览 UI 的智能体——以提取信息、与屏幕上的元素交互，或者只是回答问题。这叫 **computer use**（电脑操作），而且有对应基准。例如看 [**OSWorld 2.0**](https://osworld-v1.xlang.ai/) 排行榜——一个多模态 computer use 基准（意味着 AI 在视觉上看浏览器并实际导航它来解题），GPT 5.6 Sol 只比 Kimi K3 高几个百分点。你完全可以说这算平局、选更便宜的 Kimi K3，但我们总可以再挖深一层。

再拿另一个 computer use 数据集举例。它叫 [**MacPaw UIPad**](https://huggingface.co/datasets/macpaw-research/UiPad)，包含 1,000 多个截图配问题及答案的样本。它不是常见基准，而是作为公开可用的 computer use 测试存在。当我在这个数据集上跑 K3 和 Sol 时，两者在 UIPad 上得到相同分数，但 Sol 跑完数据集花了 $115，K3 只花 $56（便宜 2 倍多）。

到目前为止，结果似乎与 OSWorld 一样：两个模型表现相当，一个更便宜——决定好做了。但这个数据集有个有意思的地方：它分成四个类别，而如果我们深入每个类别，就有意思了：

- **yes/no** 问题——K3 赢
- 答案是**数字**的问题——K3 赢
- 答案是自然语言的问题——平
- **坐标**问题（AI 必须在所问物品周围画框）——Sol 赢

K3 和 Sol 在 UIPad 测试集上以 87.7 打平，但类别分布一边倒：四个类别中 K3 赢或平三个，而 Sol 以 13 分拿下坐标类。这个差距就是路由的论据。

提前知道 K3 在 3/4 类别上打平或获胜、而且更便宜，你就可以把坐标任务路由给 Sol、其他全部路由给 K3，最终得到一个更强也更便宜的系統。

以能实验全球最强大 AI 模型的自由，工程化出尽可能强的系统——这确实令人陶醉，但同样，有一层天花板。AI 工程是拥有智能的创可贴，不是真正的解法。

## 阶段 4：训练——拥有你的专用智能

到了某个时点，你的业务逻辑、你的分类体系、你的内部风格、你客户的怪癖，就是产品本身。在这里，前面那三个动机、加上其下的拥有本能，会从「考虑训练的理由」变成「动手训练的理由」。**训练**（又称微调，即就地改变模型的智能）是你停止在每个请求上重新规定这些东西、把它们搬进你可控的模型权重的方法。模型不再是你按 token 租的通用工具，而变成你拥有的资产。

实践中，训练模型呈现为五种常见模式。这些模式的前提是现成 AI 模型已具备基础智能，它们负责把模型的智能塑造成专属于你的数据与工作流。

### “教会模型我们的分类体系”

这是最宽泛、覆盖面最大的一种模式。笼统地说，我们需要模型从对任务的通用理解（通常以公开基准检验），转向对任务的更具体版本（用内部测试集上的 eval 检验）。

分类与抽取是两个经典例子。想象把一张工单归入 17 个主题之一（那是分类）、升级到正确的团队（也是分类）、读收据做费用报销（抽取）。听着简单，但模型不知道你的决策边界，也不知道只有你懂的两个主题之间的细微差别。你可以拼命写 prompt、堆 few-shot，但你要永远为那些 token 付费，而且灰区仍然在赌。给模型几百到几千个「输入 → 我们实际使用的标签」的例子，它就不再猜你的分类体系，而是真正认识它。

我们的 UIPad 例子也落在这个模式里。它既不是抽取也不是分类，但我们想让模型理解我们对某个任务的特定版本。那就把它测一测（双关）。计划如下：

- 把 UIPad 数据集切分为训练集 / 测试集这样我们能更有信心：模型能把训练集上的收获泛化到测试集上未见的数据
- 在测试集上跑 Kimi K3 和 GPT 5.6 Sol，得到基线分事先展示给你的是**整个**数据集上的分数，没做切分，所以为了公平比较得重来一遍
- 只在训练集上训练 K3，**不要**用测试集我用的是 Fireworks [Serverless Training API](https://docs.fireworks.ai/fine-tuning/training-api/serverless)我把我的编码智能体指向我们 [cookbook 的 training skill](https://github.com/fw-ai/cookbook) 文件，让它搞定其余
- 用同一个测试集跑新训练出的模型，得到最终分数

基座 K3 在保留测试集上落后于 Sol；大约三小时训练后，调优版 K3 反超了它。

Et voilà！我们的调优 K3 模型现在**只训练了 3 小时就超过了 GPT 5.6 Sol。**这只是「把独特数据与现成模型结合、造出真正拥有专用智能的模型」的一个例子。

### “按我们的方式写作”

如果你在用 AI 写营销 brief、临床笔记、法律文书、博客，你可能注意到 AI 的输出谈不上错，但就是不像你写笔记的方式、不像你们律所组织 brief 的方式。风格是一种行为，不是事实；提示词能短时间 hold 住风格，但在长视野上它会漂移。

例如 [Heidi](https://fireworks.ai/blog/Heidi-Health) 为每个医学专科训练不同模型，因为精神科笔记和骨科笔记是不同文体的写作——哪怕来自同一事实源。我们在法律（[Harvey](https://fireworks.ai/blog/post-training-kimi-k3-with-harvey-for-long-horizon-legal-work)、Legora）和监管文书起草（Ritivel）中观察到同样的风格模式：知识是共享的，但形式是专门的，而形式正是你要训练进模型的东西。

### **“大模型好使，只是规模上付不起”**

也许你走到这一步，心想“呼，我的模型已经够我用了，哪怕是闭源的。”如果是，那很好！如果前沿模型已经达到你的质量线，疼的是账单和延迟，那适合你的动作可能是**蒸馏**：用那个大前沿模型去引导并训练一个更小的模型，以远更低的成本和延迟复现它的质量。

你已经知道自己的质量线和账单，所以能在花出训练预算前估算回报——坦率说这不总是容易——而最终的评估反倒**更**容易，因为“小模型追得上大模型吗？”比“这东西抽象地好吗？”是个简单得多、可回答得多的问题。

### “让智能体真正把活干完”

智能体是今天 LLM 最常见的应用。大多数人要么在用现成的智能体 harness，要么为了更有竞争力、构建针对自家业务调优的自有 harness。要让多步工具调用智能体可靠地端到端完工，我们常常诉诸**强化学习**：让智能体在模拟任务与环境中跑，并按结果（答案对了吗？）、轨迹（路径高效吗？）和行为（守规矩了吗？）打分。

这种训练方式已被证明能灌输各种行为，某些情况下甚至能注入知识。难怪越来越多的公司转向强化学习来提高他们的智能体能做什么的标准。当智能体执行的任务是程序化可校验的——单元测试通过、查询返回正确的行、工单被解决——这类工作尤其可行。我们与 [Vercel](https://fireworks.ai/blog/vercel) 的工作就是一个很好的例子，cookbook 里就有这种工作的现成配方（链接见文末）。

### “我们的领域变化频繁”

上面的模式里，任务空间的变化通常不至于要求不停重训。例如，我们训练一个模型操作某个特定 UI 集，只要那个 UI 不常改，你就可以把训好的模型用上一阵，不必太担心性能漂移。

最后这个模式是一种运营模型，不是一次性项目。漂移（drift）这个概念在 AI 界已有数十年：你训练一个模型一次、它表现很好，但它周围的数据持续变化。ICD 编码被修订，客户问出新问题，支付方政策改变，新药进入市场。如果你的智能是租来的，你能做的最好是等别人的模型赶上来。如果你拥有它，你可以建一个持续训练循环、保持领先——这一收益值得最后再单独说一句。

## **迈向专用智能的第一步**

租用前沿是正确的起点，无论开源还是闭源。AI 工程会带你很远，配合开源模型尤其如此。微调，则是把你业务独有的东西（数据、专业知识）变成你拥有的智能的方式。

但真正的回报不是单个训练出的模型，而是那个循环。当你拥有模型、配方和训练循环，你的专用智能就不再是一张会衰减的快照，而变成能复利的东西：你领域的每一次变动、生产中的每一次新故障、每一代更强的基座模型，都成为下一圈的燃料，而不是等待别人路线图的理由。这才是拥有你的智能真正买到的东西。租来的版本只能追赶；拥有的版本才能保持领先。
