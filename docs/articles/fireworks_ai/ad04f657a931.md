在我们此前的 [Kimi K3 工作](https://fireworks.ai/blog/K3-LoRA-Training)中，LoRA 快、便宜，对有界目标很有效，我们划了一条线：宽泛或真正新颖的目标，才是更该测试 FullFT 的理由。

在你伸手去拿更贵的 FullFT 之前，你应该知道：在我们的实验中，当一次 FullFT 击败一次简单 LoRA 运行时，我们很难分辨究竟是适配器需要更好的数据、更好的训练配方、更多的 rank 来补差距，还是 FullFT 从头到尾就是更好的方法。

## 用 LoRA 做实验

LoRA 冻结基座模型，转而训练一个小适配器。FullFT 更新每一个模型权重。当 FullFT 表现更好时，人们很容易下结论说适配器就是太小。我们的实验探究了三种可能的解释：

- •**覆盖（Coverage）：**训练数据没有展示任务足够多的多样性。检验：扩充数据再测。
- •**优化（Optimization）：**训练配方——尤其是学习率，即每次训练调整幅度——调得不好。检验：扫描学习率与调度。
- •**适配器容量（Adapter capacity）：**LoRA 适配器需要更高的 rank——一个更大的适配器。检验：在固定更新缩放与配方其余部分的前提下提高 rank，看有效性与质量是否一起改善。

一个干预展示的是在测试条件下哪个改动有帮助。它不能证明该杠杆是唯一原因，也不能排除其他促成因素。

## 试验台：Qwen3.5-9B

我们使用监督微调（SFT）在 Qwen3.5-9B 上比较 LoRA 与 FullFT。在每组对比中，两种方法接收相同的 prompts、targets 和评估代码。

我们测试了三个带自动检查器的合成任务：每个任务都相当于一套单元测试，因此每个回答无需人类评审就能打分：

- •**布局（Placement，取自芯片设计）：**把组件摆到一条直线上，在满足硬约束的同时最小化布线。违反一条约束即令整个答案无效。
- •**寄存器分配（Register allocation，取自编译器）：**分配处理器寄存器，使同时存活的值绝不共用一个。
- •**Nexa VM：**执行一段用合成指令语言写的程序并报告每一个中间状态。程序“深度”即其指令条数。

我们挑的是对有效性、解质量和精确执行都有程序化检查的任务。这很要紧，因为模型可以把训练损失降到接近零，却仍然在一个错误决定让全答案作废的任务上失败。

## 与已有工作的关系

Biderman 等人（LoRA Learns Less and Forgets Less, 2024）报告 LoRA 在代码、数学等高要求领域落后于 FullFT，但保留更多基座能力。Thinking Machines（LoRA Without Regret, 2025）报告一个配置得当的 LoRA 可以在后训练的大部分场景与 FullFT 打平，且其最优学习率大约比 FullFT 的高一个数量级。我们的结果指向同一方向：这里最好的 LoRA 学习率 8e-5，远高于最好的 FullFT 学习率（Nexa 上的 1e-6）。我们补充的更窄：一套按差距逐一检验的协议，用来判断是覆盖、优化还是适配器容量解释了某个特定的 FullFT 优势。

## Placement：rank 测试 → 数据覆盖 → 调好的学习率

Placement 要求模型把单元摆到一条线上、最小化总线长。困难版本里，一处禁位或间距违规就令答案作废，而这种全有全无的检查暴露出一个清楚的 LoRA–FullFT 差距。我们先测 rank，再测数据覆盖：

| Placement 覆盖测试 | LoRA-r32 | LoRA-r128 | FullFT |
| --- | --- | --- | --- |
| Placement 覆盖测试 | LoRA-r32 | LoRA-r128 | FullFT |
| 2k 行，原始 seed | 34.33% | 31.67% | 57.00% |
| 2k 行，新数据与训练 seed | 37.33% | 36.67% | 61.67% |
| 20k 行，默认配方 | 68.33% | 69.33% | 80.33% |

每个保留集含 300 个样例，一个另行生成的数据集与训练 seed 复现了 rank-32 与 rank-128 打平的结果，也复现了 FullFT 差距的方向。两个适配器在采样的训练 prompt 上都达到 100% 有效性，但更高的 rank 并没有改善保留集泛化。我们把**有效性（validity）**定义为最终输出通过任务的检查器。**精确序列（exact sequence）**或**精确轨迹（exact trace）**指与参考答案逐步一致。

> 练习题全对，不等于新考试能过。

在同样的 6,000 步预算下，十倍的独特数据使 LoRA 有效性大约翻倍、把与 FullFT 的差距砍半；而 rank 扩大四倍只让结果动了一个点。

覆盖只是故事的一部分。在一个公共选择集上，默认 rank-32 LoRA 达到 76.33% 有效性，FullFT 达到 83.00%。固定数据与训练预算，我们提高 LoRA 的峰值学习率：

| 20k placement 配方，公共测试集 | 有效性 |
| --- | --- |
| 20k placement 配方，公共测试集 | 有效性 |
| LoRA-r32, 2e-5 | 76.33% |
| LoRA-r128, 2e-5 | 74.00% |
| LoRA-r32, 8e-5 | 82.67% |
| LoRA-r128, 8e-5 | 82.00% |
| FullFT | 83.00% |

在这个样本量下，评估无法区分调好率的 rank-32 LoRA 与 FullFT：0.33 个百分点的差距，其 95% 置信区间为 −4.33 到 +5.00，这不构成两法等同的证据。选出的 rank-32 配方随后在一个未动过的最终测试集上达到 81.67%，对应 FullFT 的 80.33%。

**结论：**适配器不是太小。差距来自训练数据和学习率。更多样的数据加更高的学习率补上了差距；把适配器放大四倍只让结果动了一个点。

## 寄存器分配：rank 在这里推动了结果

寄存器分配把互相干扰的虚拟寄存器映射到不同的物理寄存器。一处冲突就令分配无效。主评估含 400 个保留图。

Placement 说明了为什么 rank 未必是答案。而在这里，rank 确实推动了观测结果。

| 方法 | 有效分配 | 与参考寄存器数一致 | 精确决策序列 |
| --- | --- | --- | --- |
| 方法 | 有效分配 | 与参考寄存器数一致 | 精确决策序列 |
| LoRA-r8 | 80.50% | 65.75% | 3.50% |
| LoRA-r32 | 82.50% | 69.00% | 6.00% |
| LoRA-r128 | 90.50% | 81.00% | 25.50% |
| FullFT | 93.00% | 83.75% | 35.50% |

从 rank 32 到 128，有效性提升八个点，且解质量与精确策略模仿同向改善。Rank 128 收复了与 FullFT 之间大部分操作层面的差距。FullFT 在精确轨迹复现上保留优势。注意最后这个指标度量的是什么。

> 两个有效分配，是到达同一目的地的两条路线。精确序列要求走参考的那条路。

在精确序列上领先，是模仿上的领先，并不一比一地转化为实用质量。

一个独立的 60 图对照复现了方向：r32/r128/FullFT 的有效性为 83.33%/90.00%/90.00%。样本太小，无法精确估计效应，而且我们尚未在这里完成 placement 式的覆盖与学习率对照。在所测配方下 rank 确实推动了有效性与质量，而我们尚未像对 placement 那样排除覆盖或优化的作用。

所有寄存器分配的 LoRA 都适配了注意力与前馈权重矩阵。Alpha 随 rank 成比例增加，保持 **alpha/rank = 2**，在提高适配器容量的同时保持标称更新缩放不变。

**结论：**这里，适配器大小就是那根杠杆。更大的适配器同时改善了有效性与解质量——正是指向「大小」的模式。而能确认这一点的覆盖与学习率检查仍有待完成。

## Nexa VM：固定配方 → 调好的学习率 → rank 扫描 → 更广的课程

Nexa VM 要求模型执行短程序并复现精确状态轨迹。它在一个任务里给了我们全部三种测试（配方、rank 和覆盖）。

一个最小的保留程序展示精确执行格式：

```
12345678910Execute the Nexa VM program using the learned opcode semantics.Return each bound register in order, then the final output.program {input r0 := -0027.input r1 := -0025.input r2 := +0012.bind r3 := baf<r0>.yield r3.}trace
```

精确轨迹是：

text

Copy

```
12r3 = -0027.output -0027.
```

更长的 depth-24 测试集把同一格式应用到 24 条相互依赖的指令上——一次越界错误就能沿余下部分放大。

### 首先，配方调优抹平了固定配方下 FullFT 的优势

早期一次 10,000 行的比较让 FullFT 看起来样本效率高得多。在各自原始配方下，它比 LoRA 在 depth-eight 最终答案上高 20 个点、在精确轨迹上高 31 个点。

同套测试集上的学习率扫描反转了这一解释：

| 调优后的 10k 配方，depth-8 子集 (n=64) | 峰值 LR | 最终答案 | 精确轨迹 |
| --- | --- | --- | --- |
| 调优后的 10k 配方，depth-8 子集 (n=64) | 峰值 LR | 最终答案 | 精确轨迹 |
| LoRA-r64 | 8e-5 | 98.44% | 96.88% |
| FullFT | 1e-6 | 96.88% | 95.31% |

表中报告的是 64 样例的 depth-8 子集。在整个 480 样例的测试集上，LoRA 与 FullFT 的最终答案正确数为 478 对 476，精确轨迹为 475 对 474。学习率调优消除了固定配方下 FullFT 的优势。

**结论：**一个看起来像 FullFT 学得更快的 31 点差距，其实是一个没调过的学习率。调它是这个阶梯上最便宜的一步，也消除了本研究中最大的表观方法差异。

### 在受支持的行为上，rank 阶梯碰到了天花板

随后我们在 100,000 个 depth-1–8 程序上训练，并扫描 LoRA rank **{64, 32, 16, 8, 4, 2, 1}**。精确轨迹准确率稳定在 99.17% 到 100% 之间。受支持的行为没有区分开所测的 rank。

一个用相同 token 数训练的独立对照落在同样的天花板附近：

| Token 匹配的 Nexa 对照 | 最终答案准确率 | 精确轨迹准确率 | 深度外推精确率 | 采样训练拟合 |
| --- | --- | --- | --- | --- |
| Token 匹配的 Nexa 对照 | 最终答案准确率 | 精确轨迹准确率 | 深度外推精确率 | 采样训练拟合 |
| LoRA-r32 | 99.17% | 97.92% | 92.97% | 100% |
| LoRA-r128 | 99.17% | 98.33% | 94.53% | 100% |
| FullFT | 96.88% | 95.42% | 82.81% | 100% |

在这个对照里，r128 相对 r32 在 480 个样例中多了 2 例精确。所有 rank 已近天花板，因此受支持的 Nexa 行为没有暴露活跃的适配器容量瓶颈。FullFT 较低的结果描述的是其所测配方；这不是 LoRA 本质更好的证据。

### 越过视野边界后，课程覆盖推动了结果

失败模式在更长的程序上改变了。在固定寄存器位置范围内训练的模型，当 depth-16 程序引入新位置时变得不可靠。提高 rank 并没有带来单调恢复。训练期间随机化寄存器起始位置带来了：

| Depth-16 精确轨迹 | 固定寄存器范围 | 随机寄存器起始 |
| --- | --- | --- |
| Depth-16 精确轨迹 | 固定寄存器范围 | 随机寄存器起始 |
| LoRA-r64 | 96.09% | 100.00% |
| FullFT | 64.84% | 99.22% |

> 覆盖边界：固定课程只在熟悉的寄存器位置教授状态转移。提高 rank 补不出缺失的样例；随机寄存器起始扩展了支持集、修复了 depth-16 轨迹。

更广的寄存器位置覆盖让 FullFT 移动了 34.38 个点、LoRA 移动 3.91 个点。Rank 没有产生单调恢复。Depth-24 的精确率仍然更低（LoRA 89.84%，FullFT 80.47%），因此覆盖是延伸了可靠性边界，而非消除它。

这些是方法特定的配方：FullFT 没有在随机偏移课程上重新扫过学习率。而且与寄存器分配的扫描不同，Nexa 的 rank 阶梯固定了绝对 alpha，因此 rank 与有效更新缩放一起变化；Nexa 的 rank 结果没有那么干净地隔离适配器容量。这些结果确立了针对优化与覆盖的响应，但并未排除每一种 rank-配方交互。

Nexa 把中心教训讲得很具体。在这里，一条平坦的 rank 曲线，既可能标记天花板下的富余容量，也可能标记覆盖边界处的支持缺失。是干预响应区分了两者；曲线本身做不到。

**模型只学到了它在训练中见过的寄存器位置上的规则。完美的训练分数和无瑕的逐步轨迹都没能揭示这一点。差距只有当新位置出现时才浮现。**

**结论：**在这个任务上三根杠杆都被测试了，其中两根起了作用：先是学习率，然后是更广的训练数据。FullFT 从更广数据中获得的 34 点跃升，是本研究中最大的单一效应。

## 三任务混合：匹配曝光 → 固定预算 → 配方扫描

到此，每个实验都只适配一个有界任务。当一个模型必须同时学会三个任务时会怎样？

我们把 placement、寄存器分配和 Nexa 合成一个带标签的混合集。

首先，我们保留每个任务原始的 token 曝光量。这需要 18,000 步，是单任务预算的三倍。

下面的三任务平均对 placement 有效性、寄存器分配有效性和 Nexa 精确轨迹准确率赋予相等权重；它不是所有样例的合并准确率。

| 曝光匹配的混合 | LoRA-r32 | LoRA-r128 | FullFT |
| --- | --- | --- | --- |
| 曝光匹配的混合 | LoRA-r32 | LoRA-r128 | FullFT |
| 三任务平均 | 86.92% | 86.11% | 84.58% |
| Placement 有效性 | 70.33% | 73.33% | 75.00% |
| 寄存器分配有效性 | 96.67% | 93.33% | 88.33% |
| Nexa 精确轨迹准确率 | 93.75% | 91.67% | 90.42% |

在保留每任务曝光的情况下，更高的 rank 和被测的 FullFT 配方都没有改善宏平均。这个混合没有暴露广度引发的容量瓶颈。

然后我们把总 token 与步数预算固定在单任务水平。每个任务只得到约三分之一的曝光。

| 固定预算混合 | LoRA-r32 | LoRA-r128 | FullFT |
| --- | --- | --- | --- |
| 固定预算混合 | LoRA-r32 | LoRA-r128 | FullFT |
| 三任务平均 | 69.64% | 71.65% | 80.89% |
| Placement 有效性 | 61.00% | 59.33% | 62.67% |
| 寄存器分配有效性 | 60.00% | 66.67% | 85.00% |
| Nexa 精确轨迹准确率 | 87.92% | 88.96% | 95.00% |

这一协议问的是同样的数据、同样的优化步数下哪种方法表现更好，而不是在匹配训练 FLOPs 下谁更计算高效。FullFT 领先，而配方质量仍是一个混杂，于是我们扫描了混合集上折中的 LoRA 学习率与调度。

在 rank 32 上，**8e-5** 相对原始配方加了 5.61 个点。在那个调优学习率上，rank 128 再加 1.35 个点，达到 76.60%。合起来，配方与 rank 收复了原始 r32 11.25 点缺口中 6.96 点。FullFT 仍领先最佳适配器 4.29 个点。

响应取决于配方。低学习率的 r128 比其原始结果低 12.05 个点，而 constant **4e-5** 只到 70.86%。调优后的 r128 在三个任务所有采样的训练样例上都产生有效输出，但 FullFT 在每个保留任务——placement、寄存器分配和 Nexa——上仍然领先。

固定预算结果为单 seed；一个复现 seed 已排期，届时我们会更新本节。相对所测的最佳 LoRA 配方：

> 在固定多任务预算下，就我们所测配方而言，FullFT 对每任务曝光被稀释更不敏感。优化解释了原始 r32 缺口的大部分，rank 提供了较小的次级收复。相对所测最佳 LoRA 配方仍有 4.29 点领先未消。这个残余差距并不能证明 LoRA 本身缺容量。

当每任务曝光被保留时，被测 LoRA 配方追平或超过被测 FullFT 配方。当预算固定、每任务曝光被稀释时，就迄今尝试过的配方而言，FullFT 是更宽容的方法。两行都不是普适答案；协议本身就是结果的一部分。

什么能解决剩下的 4.29 个点？我们尚未运行的候选：调优学习率下的 rank-256 臂、混合集上按 rank 的 alpha 与 LR 扫描、多个按任务适配器并排服务而非共享一个适配器，以及在混合集层面重新做一遍 FullFT 学习率扫描以确认它的配方没有同样欠调。这是后续的那组实验，无论结果如何我们都会发布。

Serverless 计费统计的是训练数据 token，即训练行中的每个 token，这就是该数字（62.74M）大于上文 12.02M 响应 token 的原因。这是牌价估计，而上文的专用数字是活跃时间下界、并非账单总额。

训练成本只是对比的一半。这里训练出的适配器可以共享一个基座模型部署：多个 LoRA 并发服务在同一副本上，每个请求换入各自的。FullFT 模型需要自己的专用部署。对一个同时运行几种专门行为的团队，服务侧的差异可能盖过单次训练差额，所以下面阶梯中的成本闸门应当比较「训练 + 服务」在你实际计划运行的整个机群上的总账——而一点微小的质量领先，得先付得起一个专用部署的成本才算赢。

## 是什么推动了结果

有针对性的数据覆盖、配方优化、提高适配器 rank，都曾在弥合与 FullFT 的质量差距中发挥作用，但当每任务曝光被稀释时 FullFT 保留了领先，而且没有单一干预能在所有场景下消除差距。

| 场景 | 推动结果的干预 | 证据 | 残余结果 |
| --- | --- | --- | --- |
| 场景 | 推动结果的干预 | 证据 | 残余结果 |
| Placement | 更多样的数据，然后是更好的学习率 | 数据集扩大 10 倍把 LoRA 有效性从 34.33% 提到 68.33%。提高学习率在公共比较集上又加 6.34 点。 | FullFT 以 0.33 个有效性点领先，落在置信区间内。 |
| 寄存器分配 | 更大的适配器 | rank 从 8 增至 128 加了 10 个有效性点。解质量与精确序列准确率同向移动。 | FullFT 在精确序列上保留 10 点领先——那是更严的模仿指标。覆盖与学习率对照待做。 |
| Nexa VM 在已训练程序长度上 | 更好的学习率 | 学习率扫描反转了一个表观的 FullFT 31 点优势。 | 调优 LoRA 略胜收尾：480 例中多 2 个正确最终答案、多 1 条精确轨迹。 |
| Nexa VM 超出已训练程序长度 | 更具代表性的数据 | 随机化寄存器起始位置把 FullFT 提了 34.38 点、LoRA 提 3.91 点。 | LoRA 达到 100% 精确轨迹，FullFT 99.22%。 |
| 一个模型学全部三个任务，训练预算相当于单任务 | 更好的学习率，然后更大的适配器 | 学习率调优在三任务宏平均上收复 5.61 点。rank 增至 128 又收复 1.35 点。 | FullFT 在三任务平均上保留 4.29 点领先，所测干预无一消除。 |
| 同样的三任务混合，数据曝光匹配 | 比较协议本身 | 匹配数据曝光改变了谁最终领先。 | LoRA 领先。 |

在四个单任务场景中，数据覆盖或优化在三个里消除了表观的 FullFT 优势。更高的 rank 实质改善了第四个，尽管覆盖与学习率对照仍未做完。

在组合任务实验中，结果取决于比较固定了什么。在相当于单任务的训练预算下，FullFT 在三任务平均上保留 4.29 点领先。在数据曝光匹配时，LoRA 领先。

> FullFT 的一次胜利告诉你性能差距存在，却不告诉你差距因何而来。在用 FullFT 取代 LoRA 之前，先审视你的覆盖、配方和 LoRA rank。

## 从 LoRA 换到 FullFT 之前

- **评估你要交付的输出。**这意味着不要只盯训练损失。模型可以拟合训练数据，却在新样例、硬约束或多步执行上失败。
- **从窄而可测的任务上的 LoRA 开始。**你要能清楚描述目标行为，并度量模型是否学会了它。
- **当失败聚集在缺失情形周围时，先扩充数据。**增加模型答错的组合、边缘案例与任务变体。
- **当更多数据有帮助但差距仍在时，调训练配方。**测试学习率与调度，而不是复用 FullFT 的默认值。LoRA 常常偏好高得多的学习率。
- **最后再测适配器容量。**如果更高 rank 同时改善有效性与质量，那么较小的适配器就是约束的一部分。
- **当多个方法都达到质量线后，比较总经济账。**包括训练、迭代速度、服务，以及维护一个独立 FullFT 部署的成本。

当 FullFT 的质量优势经受住这些测试并证明额外成本值得时，再用 FullFT。

这些实验覆盖一个模型与三个合成的、可验证的任务，更像风洞而非生产工作负载。

> 诊断流程可以带走，具体数字未必。
