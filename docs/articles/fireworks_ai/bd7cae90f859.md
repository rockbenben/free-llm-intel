开放模型会在开口之前无声地推理吗？最近，Anthropic 的研究者提出了 [Jacobian Lens](https://www.anthropic.com/research/global-workspace)，简称 J-Lens。它是一个训练好的探针，读取模型在某一层的隐藏状态，告诉你模型在写出第一个 token 之前就已经倾向于哪些词。换句话说，它让你在模型"思考"的中途窥视内部，看到一个概念在落到纸面之前成形。我们把 J-Lens 应用到两个开放模型上：Kimi K3 与 Qwen3.5-9B。我们把由此得到的观察称为 **silent signals**：由拟合出的 Lens 还原出来的、与最终输出相关的中途草拟词汇。

那么，这意味着什么？模型承载的洞察是否多于它的输出？

过去，人们把模型视为黑箱：输入进去，输出出来。但现实是，我们可以还原在你的 prompt 与被预测的下一个 token 之间发生了什么，这是把 AI 的黑箱向任何人打开的第一步。

为了开始拆解 AI 模型的内部运作，我们先问了一个问题：模型在开口之前的那一刻，正在追踪什么？

我们测试了随 Anthropic 全局工作空间研究一起公开的十个示例。Kimi K3 与 Qwen3.5-9B 各自针对同样的用户消息生成自己的回答。在我们的读出研究中，每个模型都拟合了自己的 J-lens，而我们看到了同类信号。

### J-Lens 是什么，它是怎么工作的？

J-Lens 在模型特定 token 位置与层的内部状态之上充当分类器，用来识别模型已经倾向的概念或词汇。输出是一个排好序的 token 列表，显示拟合出的探针与该内部状态关联最强的词汇。

从 Kimi 开始，我们在 14 段与任务无关的短文中拟合 lens，这些短文与用来考察模型内部激活的 10 条留出用户 prompt 分开选取。换句话说，这 14 段短文用于训练 lens，而不是测试它。我们合成了若干类似预训练语料的短文，主题多样，涵盖金属热处理、语言借用、轮作与传统导航。

### 配对复述实验：同样的词，不同的注意焦点

我们首先做了一个实验：让模型复述一句话，同时要求它专注于一件完全无关的任务。例如，让 Kimi 在两份不同的焦点指令下各写一遍这句话："The old painting hung crookedly on the wall."：

- **算术版：**"……写这句话的时候，试着把注意力放在计算 3^2 - 2 上。"
- **柑橘版：**"……写这句话的时候，把注意力集中在柑橘类水果上。"

图 2：配对复述分析

两次 Kimi 都给出了完全相同的回答："The old painting hung crookedly on the wall." 只看输出的文字，你无法判断模型是否曾遵循过焦点指令。lens 读出在一种条件下给出算术词，在另一种条件下给出柑橘词，尽管两种焦点指令下 Kimi 产生的可见续写一模一样。把任务固定为逐字输出，就排除了"显示出来的 token 差异可以解释 lens 读出差异"这一可能。但它并不能确定内部状态或回答的成因。每条 prompt 都给我们一个可去寻找的词汇家族。

概念家族（一份人工挑选的关键词列表）用来检查与任务相关的词汇是否在回答中出现之前先出现在读出里。一个"cell"是一个位置—层对；如果某个概念家族有多个成员在其中出现，单个 cell 可以包含多行命中。把 J-lens 应用到算术家族那一轮，在 4 个被采样的层上、10 个 token 位置中的 9 个里，top-10 预测中出现了算术相关 token（7、9、3、"answer"、"seven"、"2"）。

在柑橘家族那一轮，柑橘类词（orange、lemon、lime、"citrus"、"oranges"）出现在 10 个位置中的 8 个。值得一提的是，两轮之间互不渗透：柑橘那一轮算术 token 从未进入 top 10，算术那一轮也从未出现柑橘 token。

### 校准短文

在把 J-Lens 应用到研究片段之前，我们先在 14 段与任务无关的校准短文上拟合它。这些短文用于把模型的内部状态与词汇读出关联起来；它们与研究片段是分开的。每段校准短文在每个被采样的层上产出一个估计，14 个估计平均成一个拟合后的 lens。四面板那张图展示了其中四段短文作为示例。

### 同一套理论在 Qwen 3.5 上成立吗？

接下来，我们研究此前在 Kimi 上评估过的 20 个概念家族，原样应用到单独拟合的 Qwen3.5-9B J-lens 上时，是否会产生合格的匹配。这里的合格证据，指的是 Qwen 的内部状态在其 top 10 排名中产出了某个概念家族的相关关键词。Qwen 收到了同样的十条用户消息，但使用自己的 tokenizer、单独拟合的 lens，以及在关闭 thinking、不做强制输入情况下的确定性原生完成。

图 9：J-Lens 在 Qwen 上的结果

用 Kimi 读出选出的 20 份词表被原样应用到 Qwen 单独拟合的 lens 上。当某份词表中有一个列出的词出现在某个被采样位置与模型深度上的 top 10 匹配结果里，该词表就算作"找到"。20 份词表中有 19 份满足"找到"的标准。这相当于把一个词汇测试从 Kimi 迁移到 Qwen，证实了同样的结果会在不同模型架构上出现。

Qwen 读出中的几个具体例子：

- **算术复述：**"7"、"9"、"answer" 这样的值与 "evaluate"、"subtract" 这样的过程词共同出现。
- **柑橘焦点：**Qwen 的生成独立地反映了底层指令。柑橘任务的完成文本提到 "lemon zest and orange peel"，而算术任务明确算出 "3^2 - 2, which is 7"，尽管模型从未被要求展示计算过程。
- **运动任务：**"Soccer" 与 "football"、"basketball" 这样的合理备选一起出现。

### 信号住在哪里？

为了回答这个问题，我们做了第二个测试，检视任务记录的各个区域。在这个任务记录区域测试中，为了把对 prompt 的理解与主动生成区分开，我们把每份记录切成三个阶段：

- **用户消息 prefill**（显式任务本身，例如 "Think of a sport"）
- **聊天模板 prefill**（格式上下文，包括保留 token，例如 "<|im_start|>"）
- **合格回答 rollout 前缀**（在概念家族首次显式出现之前，模型生成的开头若干 token，例如 "In order to answer this task…"）

这一区分使我们可以把"模型正在处理 prompt"与"模型在显式生成之前就在内部表征某个概念"这两种情况分开。

图 10：prompt 存在于哪里

这个任务记录区域测试由另外 40 份词表组成，并保留 top 50 的结果。它与我们此前做的 20 份词表测试、以及 Kimi→Qwen 的 top-10 结果都是分开的。该测试问的是：在记录的每个区域里——用户消息、聊天模板添加的格式、以及词第一次出现在可见文本之前的回答——是否至少有一个列出的词出现。我们使用一个简单的二值聚合度量，表示指定区域的任意位置是否存在 silent signals。Kimi 在用户消息区域是 40/40，在聊天模板区域是 40/40，在合格回答前缀区域是 24/24。

注：24/24 来自这样一个事实：在 16/40 的情况下，模型直接回答了任务，没有冗长的前缀。例如被要求 "Think of a sport" 时，它直接回答 "Soccer"。

Qwen 几乎一样：39/40、39/40 与 23/24。换句话说，"在说出口之前就可读"这一模式不仅在主动生成的中途成立，在模型消化 prompt 时也成立。

图 11：Kimi 与 Qwen 上的结果

### 方法在哪里失效：一个 tokenizer 问题

J-lens 检查的是单个 token，而对 Qwen 而言，它没能把 "21" 或 "42" 还原为统一匹配，因为 Qwen 把这两个数字各自切成两个 token。这暴露了方法本身的一个局限；可以设想在后续工作中拟合一个多 token 的 lens。

由于 lens 这一多 token 缺陷，Qwen 在这个片段的"中间结果"探针家族上只拿到 0/3，尽管它在其他所有家族上表现正常。

### 跑这套东西需要多少成本

每段短文有 7,168 次反向评估，14 段短文合计 100,352 次有效反向评估。一段短文在一个八卡 B300 节点上大约花 5.25 小时。乘以 14 就是总工作量：约 74 节点小时，即 592 GPU 小时，而不是多主机运行的实际耗时。

### 结论

我们的结果表明，内部状态在概念被写入上下文窗口之前很久，就已经承载了与任务相关的概念。

开放权重模型让研究者可以在拟合出的探针上做自己的读出、复现测量结果、并检验这些信号起什么作用。下一步是走出单 token 匹配。通过把 J-lens 探针用在多个不同 prompt 上，我们发现开放模型可以有不同的内部思考轨迹，但仍然得出与任务相关的结论。我们还通过同时测试 Kimi 与 Qwen，确认了这种行为可以在不同家族与模型架构之间复现。

你可以自己复现这类开放模型研究！"在说出口之前就可读"的信号出现在两个公开可用的模型上，它们来自不同实验室、架构不同，各自拥有独立拟合的 lens。只有权重开放到足以被探测时，你才能得到这样的结果。[Kimi K3](https://fireworks.ai/models/fireworks/kimi-k3) 与 [Qwen 3.5](https://fireworks.ai/models?providers=Qwen) 都在 Fireworks 上提供推理与训练，是非常好用的模型！
