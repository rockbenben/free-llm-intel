## TL;DR

- •Genspark 与 Fireworks Lab 合作，将 MiniMax M3 后训练成 Gen-1 Slides——一个能端到端规划、撰写并自查幻灯片的模型。
- •在 Genspark 的评估上，Gen-1 Slides 的幻灯片质量追平 Opus 5，而输入 token 牌价约为 Opus 5 的 1/17。** 每份成品幻灯片，Gen-1 Slides 的成本比 Opus 5 低约 90%。** 在生产环境中，它在每项指标上与 Opus 5 并驾齐驱，且相对基座模型把低评分幻灯片从 18% 压到 **3.6%**。
- •Genspark 研究团队定义了什么是一份好幻灯片、把它编码成评估标准、主导了把该标准训练进模型的算法设计，并在真实流量上验证。Fireworks Lab 管理了把模型训练到位的全过程：奖励工程、上百次实验，以及让 10 万 token 轨迹保持数值稳定的系统工作。

> 内部评审器聚合分数，200 个真实任务。对比对象主要是 Opus 5——在该任务上规模化服务的前沿模型；Claude Fable 5 / 5.1 仅作参考。

## 为智能体工作构建专用智能

幻灯片是 Genspark 高吞吐量的智能体工作负载之一。用户为季度评审、客户提案、董事会汇报生成它们，需要的是能当着观众拿得出手的输出，而不是还得手动修的草稿。

现成模型——包括最好的专有模型——做出的幻灯片乍看没问题，细看就露馅：文字溢出文本框、空白渲染、内容编造。在闭源模型上，Genspark 无法为该工作负载所需的质量做调优，而且以每月超过一万亿 token 的量，也无法控制成本。把模型握在自己手里，意味着两者都握住。

## 为什么这是一个强化学习问题

幻灯片不是一次可以直接喂给模型模仿的输出。产出一份好幻灯片，意味着在一个实时工作区里跨几十轮工作：规划叙事线、写 HTML、渲染、复查渲染结果、发现布局缺陷并修复——一次会话内就是几十万个 token。

一份成品幻灯片并不记录这些过程，只有结果。样例能向模型展示好幻灯片长什么样，却无法展示产出它的判断序列，所以单靠模仿教不出这种行为。这正是它成为一个强化学习（RL）问题的原因，而且在三点上很难：

- **长视野。**单次 episode 跑几十轮。每 token 的小误差会累积成坏掉的布局、被截断的文件和被放弃的幻灯片。
- **是判断，不只是正确性。**一份幻灯片可能语法完美却在视觉上不连贯。奖励必须捕获设计质量，而不只是任务完成。
- **跨轮的信用分配。**早期某轮的一个布局决定当时看着没事，直到几十轮之后才产出一个坏掉的渲染。信号必须从失败回溯到导致它的那个决定。

## **训练合作关系**

同时翻越这三座山，正是横在 Genspark 与一个可自主掌控的模型之间的障碍。**而这恰恰是 Fireworks Lab 设立的初衷：它把一个前沿实验室的训练与推理基础设施、算力、研究人才带到客户最难的训练问题上，让他们能在质量、成本与性能上竞争。**其研究人员嵌入 Genspark 团队，把开放权重的多模态模型 MiniMax M3 后训练成 Gen-1 Slides。

Genspark 塑造目标与算法。他们把真实生产环境直接引入训练，并定义了背后的标准：什么样的幻灯片算好的判断、背后的设计原则，以及打磨这一标准的流程。他们还主导了把该标准训练进模型的算法设计。

Fireworks Lab 共同开发算法并管理训练过程。除基础设施之外，其研究人员深度参与为效率、为与 Genspark 目标对齐而优化过程。他们推动了 100 多次实验，并通读轨迹以捕捉模型「钻分数空子」。有一个例子：模型把视觉设计分提高了，任务完成度却下滑了，于是总分上去了，但幻灯片并没有更好。让一个 episode 超过 10 万 token 的运行稳定到能收敛，既是研究问题，也是系统问题。

## **编码 Genspark 的标准**

RL 朝评估优化，所以它度量什么，模型就变成什么。Genspark 的方法论按真正要紧的质量维度给每份幻灯片打分，并惩罚现实中会毁掉一份幻灯片的缺陷：空白渲染、文字越界、内容编造。分数来自真实生产行为。随着训练推进，质量分上升而惩罚下降。

> 训练全程的奖励。Gen-1 Slides 在整个运行中从 MiniMax M3 基座一路攀升到 Opus 5 的水平。

## **一套课程，而不是一次运行**

Fireworks Lab 把训练组织成一串阶段，每个阶段提高上下文长度，并修复上一阶段暴露出的失败。

- **学好设计长什么样。**Fireworks Lab 先在精选幻灯片上跑一遍 SFT，在任何 RL 之前给模型好幻灯片的视觉词汇表。
- **从短上下文开始 RL。**过早用长上下文会产生冗长、满是错误的 rollouts 和嘈杂的梯度，所以他们从短 episode 开始 RL 以保持信号干净，随策略稳定再拉长。第一个像样的 checkpoint 能生成更好的幻灯片，但布局仍不可靠。
- **扩展上下文窗口。**一旦奖励携带上干净的信号，他们就加宽窗口，把更长、更丰富的轨迹纳入训练，布局随之变得可靠。

随着轨迹变长，紧约束从奖励变成了一个超长 episode 的数值问题。

## **保持运行稳定**

RL 更新只有在环内的两个引擎一致时才是正确的。推理栈采样一个 rollout，训练器给它打分，而更新是无偏的，只有当两者对同一个 token 赋予相同概率时才成立。它们跑在不同的代码路径上，所以这种一致从不是自动的。短 episode 上差异可忽略；超过 10 万 token 的轨迹上，它会累积成有偏的梯度。

Fireworks 每一步都度量这种一致性，而该度量捕捉到了这次运行中最糟的故障——它不报任何错，其他一切看起来也都正常。训练器与采样器在长轨迹上越拉越开，Fireworks Lab 把它追到了 token 流。

分词不能干净地往返（round-trip），于是训练器打分的序列与模型采样出的序列略有不同，重要性比（importance ratio）是对着错误的 token 算的。这让每一步的梯度都有偏。对齐两条 token 流修好了它，再配合 token 级和 batch 级过滤清除剩下的罕见极端分歧。

这样的故障不抛错误，却给每次更新引入偏差。要抓住它，需要一个把推理与训练作为同一个对齐系统的训练栈，而不是把训练器硬接到一个分离的推理引擎上。

## **以一小部分成本追平 Opus 5**

Gen-1 Slides 现已作为 Genspark AI Slides Standard 模式的默认模型上线。在 Genspark 的评估上它追平 Opus 5：在视觉设计与聚合分数上领先，并且**在横跨三个独立评审器的九个评审列中有八列排名第一、九列全部位居前二**，而输入 token 牌价约为 Opus 5 的 1/17。

**按每份成品幻灯片计，Gen-1 Slides 的运行成本约为 Opus 5 的十分之一。**对一个每月产出 1,000 份幻灯片的团队，意味着开支下降约 90%（从约 $4,200 降到 $400）。过去只够以一个用户前沿质量服务的预算，现在能服务大约十个。

在生产中，Gen-1 Slides 每项指标与 Opus 5 并驾齐驱，并相对基座模型把低评分幻灯片从 18% 降到 3.6%。因为它是在完整智能体会话上训练的，而非在某个基准上，所以它学到的规划、自查与错误恢复，正是呈现在用户面前的那些。

## **给跑长视野 RL 的团队的几点考量**

设计奖励是一个研究问题。让运行足够稳定以便针对它优化是一个系统问题，而随着轨迹变长，最难、最隐蔽的故障恰恰藏在那里。其中三个值得提前规划。

- •**最难的 bug 是数值性的。**上述分词不一致是破坏性最大的，修好它又引出一个新谜题：一种更精确的对齐方法产生了近乎完美的一致性指标，却让训练不稳定。
- •**长上下文下序列级目标胜过 token 级目标。**沿整条轨迹对重要性比取平均，能压低个别离群 token 的影响——一旦轨迹跑到几十万个 token，那些离群 token 的每-token 比本可以支配整个更新。
- •**视觉质量随输出长度上升，但有上限。**更长的回答意味着更丰富的布局和更多 HTML 元素，设计质量随之上升，直到训练后期，增加的长度不再提升质量，反而开始制造不稳定。

Gen-1 Slides 是 Genspark 自主掌控的专用智能：一个调到他们领域的模型，在他们吞吐量最高的一个工作负载上追平前沿。让它经久的是背后的标准。Genspark 对「好幻灯片」的定义活在奖励与评估里，因此它能迁移到他们训练的每一代基座模型，并在更强基座到来时产出下一代。
