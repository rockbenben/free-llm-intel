## **今日面向工程组织开放：Fireworks Nexus**

Fireworks Nexus 把你开发者已在使用的 AI 工具连到一层受管的开放权重模型上，带企业级管控与智能路由。工程团队在降低成本、保持他们熟悉开发者体验的同时，获得了为工作负载供能的 AI 的可见性与控制权。

它由三个主要组件构成：

#### **1. 企业级管控与成本可观测性**

Fireworks Nexus 为工程与 IT 团队提供对整个组织 AI 使用方式的集中控制。在团队或公司层面设预算、跨模型与工具追踪 ROI、在一个地方执行策略。在幕后，每个请求都跑在受领先 AI 原生公司信任的同一生产推理平台上，具备[美国托管端点](https://docs.fireworks.ai/deployments/regions)、[零数据保留](https://docs.fireworks.ai/guides/security_compliance/data_handling)，以及横跨 20 个全球数据中心的企业级性能。

#### **2. 工作流连续性**

[FireConnect](https://github.com/fw-ai/fireconnect) 是一行安装，它依据 harness 配置直观地映射合适的模型。继续用你现有的工具和 harness，如 Claude Code、Codex、OpenCode。它确保开发者零打扰，同时受益于优化过的基础设施——包括能带来实质成本节省的更高缓存命中率。FireConnect 通过我们兼容 Anthropic 与 OpenAI API 的 Fireworks Serverless API 工作，因此多数工具只需一个 base URL 和一个 model ID 就能连上。上手方式：FireConnect 以 Apache 2.0 开源，可以从 [Fireworks Dashboard](https://app.fireworks.ai/connect) 用单条命令安装。

图 2：FireConnect API Key

#### **3. 智能流量管理与迁移**

我们为已有 AI 合同的大型组织构建了一个自定义路由端点。一个专门训练出的模型为每个请求打难度分。日常任务走 Fireworks 服务的、成本效益高的开放权重模型；困难任务用你自己的 key 透传回你现有供应商，而 key 从不存储在服务端。它作为一个中间层，依据复杂度与最优缓存动态路由任务。这通常带来 3–5 倍的成本降低而不牺牲质量。该功能处于研究预览阶段，今天在 Claude Opus 5 与 GLM 5.2 之间路由，所以透传路径需要一个 Anthropic key。想完全留在开放权重模型上？我们也在 K3 与 GLM 5.2 之间路由。

### **在真实工程工作上得到验证**

Fireworks Nexus 的价值不只是更低的 token 价格，而是花更少的钱得到同等或更好的工程结果。

独立评估佐证了这一点。[Faros](https://www.faros.ai/blog/open-models-vs-frontier-models) 从客户仓库跑了 211 个真实工程任务、覆盖七种模型与 harness 组合，并公开了完整方法论。在 GLM-5.2 上运行的 Claude Code 略微超过在 Opus 4.8 上的 Claude Code，而每个完成任务的成本约为其一半。[Arize](https://arize.com/blog/cost-per-successful-task-ai-model-benchmark) 评估了 2,400 次智能体运行，发现前沿定价的模型在日常工作上几乎没有优势，而智能路由在最需要之处保留了它们的强项。其评估框架是[开源的](https://github.com/Arize-ai/fireworks-cost-benchmark)，你可以在自己的工作负载上跑同样的分析。

Fireworks Nexus 让工程组织掌控为其已用 AI 工具供能的智能。你不再被锁死在单一供应商的价格、模型和路线图里，而是可以为每个任务选最合适的模型、集中管理开支，并随着新模型涌现持续度量质量。
