## 长篇大论；博士

- 用专业智能训练您自己的模型意味着拥有让您的公司独一无二的东西
- 通向专业智能的道路可以从租用封闭边界开始，但不可避免地会导致训练开放模型
- 关于公司为何转向训练自己的模型的常见模式出现

> 这是针对正在涉足培训或对培训需要什么感到好奇的工程师的专业情报系列中的第一篇文章。

## 专业智能之路

团队决定训练自己的模型有以下几个原因：

- 担心封闭的前沿实验室会进入他们的领域
- 一般模型在垂直方向上无法达到的质量标准
- API 账单对于他们实际需要的情报来说太高

所有这些背后都有着相同的本能：拥有定义其业务的专业情报。这篇文章是关于让你到达那里的道路。

首先，您可以租用最强大（通常是最昂贵）的封闭式LLM，围绕该模型设计专门的线束、系统和组件，以提高其任务性能。一旦这些组件达到极限，您就可以迁移到更便宜但仍然有效的开放模型，以降低成本，同时最大限度地提高效用。最后，如果问题确实是您的问题，您决定通过训练自定义模型来完全拥有智能。

## 第一阶段：租用封闭边界

几乎每个人都从 API 背后的封闭边界模型开始。这是有道理的**：**这些提供商花费巨额资金在尽可能的地方营销他们的模型**，**试图让你加入。这些模型非常强大，并且由于其他人承担了培训和服务它们的成本，因此您需要通过代币成本按使用量付费。

缺点很深，但您可能会遇到以下三个主要缺点：

该模型过于笼统，需要提示才能以专门的方式做任何事情。当它有效时，它就有效，但这个模型是由其他人为其他所有人塑造的。

封闭式 API 从任何意义上来说都是一种租赁。您无法控制模型权重、价格、延迟、弃用时间表，并且在大多数情况下，您无法控制数据。

您向团队支付的代币溢价和企业订阅是所有费用的来源：您从未接触过的基础设施、营销活动、为这些活动提供建议的顾问以及使实验室保持领先地位的研发。您正在补贴一台您不拥有且无法驾驶的机器。

经过他们在模型中投入的所有工作之后，封闭前沿LLM确实非常强大，但它们也过于笼统，需要提供相关的背景信息才能在日常工作中发挥作用。进入人工智能工程。

## 第 2 阶段：人工智能工程 - 提示、背景和利用，天哪！

过去几年，人工智能工程经历了明显的升级，每一层的添加都可以从我们租用的现成模型中挤出更多东西。首先是**即时工程**：少数例子和思路表明，改变我们的要求方式会引发更强大、更一致的行为。随着我们越来越多地通过管道进入上下文窗口（通常用于检索增强生成（RAG）），这变成了**上下文工程**，以使模型与不断变化的信息保持同步。一旦处理了提示和上下文，代理就会到达并用工具调用循环填充同一窗口，因此我们转向**利用工程：**对话压缩、工具优化、MCP 等，将上下文窗口视为预算而不是桶。

整个过程都是人类在弥补一个永远不会改变的模型的工程缺陷。

这是大多数严肃团队长期处于的阶段，也是你第一次开始真正感受到自己拥有自己的人工智能。提示、工具使用和 RAG 可以让你走得更远；但有一个上限。您安全带中的每个型号仍然与货架上的型号相同。你的提示和工具可以指导模型，但它们不会教给他们任何东西。该工具了解有关您业务的所有信息，它会以您支付的代币形式重新解释每个请求，并提示您重新粘贴到下周可能会弃用的模型中。

每个人工智能系统实际上都在三个轴上进行优化：**质量**（是否足够好？）、**成本**（你能大规模承受吗？）和**延迟**（是否足够快？）。人工智能工程是在不触及模型本身的情况下推动这三者的努力，在你达到其中任何一个的上限之前，它可以让你走很长的路。解决性能上限很困难，这就是为什么大多数人首先致力于优化成本和延迟，而实现这一目标的最有效方法之一是混合开放模型。

## 第三阶段：添加开放模型

如今，前沿开放模型往往以前沿封闭模型成本的一小部分来完成工作，并且根据任务的不同，质量差距很小或不存在。

这个阶段是由**单位经济和控制**定义的，而不是意识形态。到了这个阶段，您现在需要决定模型的运行位置、响应速度、数据会发生什么情况，以及为每个令牌和每个任务支付的费用。要选择正确的模型（开放式或封闭式），您可以依靠报告的基准，或者更好的是，根据您自己的任务评估候选人。

基准并不总是代表您实际所做的工作。也许您的金融科技用例比基准示例更小众，或者您的法律问题跨越十几个领域不断变化的理念。基准是一种不错的入围方式。您自己的**评估**（针对您的特定任务对人工智能系统进行系统的本土测试）将始终是最好的性能指标。

假设您正在构建需要导航 UI 来提取信息、与屏幕上的元素交互或只是回答问题的代理。这称为**计算机使用**，并且有这方面的基准。例如，如果您查看 [**OSWorld 2.0**](https://osworld-v1.xlang.ai/) 的排行榜，这是多模式计算机使用的基准（意味着人工智能在视觉上查看浏览器并实际导航它来解决任务），GPT 5.6 Sol 仅击败 Kimi K3 几个百分点。你可以简单地称其为平局，并选择更便宜的 Kimi K3，但我们总有更深层次的选择。

让我们以另一个供计算机使用的数据集为例。它名为 [**MacPaw UIPad**](https://huggingface.co/datasets/macpaw-research/UiPad)，其中包含 1,000 多个屏幕截图示例以及问题和答案。该数据集不是通用基准，而是作为计算机使用的公开测试而存在。当我在这个数据集上运行 K3 和 Sol 时，它们在 UIPad 上都获得了相同的等级，但 Sol 在该数据集上运行的成本为 115 美元，而 K3 的成本为 56 美元（便宜超过 2 倍）。

到目前为止，这似乎与 OSWorld 的结果相同。两种模型的表现与另一种模型一样好，但其中一种更便宜：做出决定。但该数据集有一些有趣的地方：它分为四个类别，如果我们深入研究每个类别，就会出现一些有趣的情况：

- **是/否**问题 - K3 获胜
- 答案为 **数字** 的问题 - K3 获胜
- 有自然语言答案的问题 - 平局
- **协调**问题，其中人工智能必须在所要求的项目周围画一个方框 - Sol 获胜

K3 和 Sol 在 UIPad 测试集上的总得分为 87.7，但类别划分是不平衡的：K3 获胜或平局四分之三，而 Sol 则领先 13 分。这个差距是路由的一个论点。

提前知道 K3 在 3/4 类别上平局或获胜，同时更便宜意味着您可以将协调任务路由到 Sol，将其他所有任务路由到 K3，并最终得到一个更强大、更便宜的整体系统。

设计出最强大的系统，并可以自由地试验地球上最强大的人工智能模型，这确实令人陶醉，但同样，这是有上限的。人工智能工程是自有智能的创可贴，而不是真正的解决方案。

## 第四阶段：训练——拥有你的专业智力

在某些时候，你的业务逻辑、你的分类、你的内部风格、你的客户的怪癖都是产品。这就是这三种动机，加上它们背后的主人翁本能，不再是考虑培训的理由，而是开始成为这样做的理由。 **训练**（又名微调，即适当更改模型智能的行为）是您如何停止在每个请求上重新指定这些参数并将它们移至您控制的模型权重中。该模型不再是您通过代币租用的通用工具，而是成为您拥有的资产。

在实践中，训练模型表现为五种常见模式。通过在现成的 AI 模型已经具有基础智能水平的前提下进行操作，这些模式可以塑造模型的智能，使其专门针对您的数据和工作流程。

### “教授模型我们的分类法”

这是最广泛、最包容的模式。一般来说，我们需要我们的模型从任务的通用解释（通常通过公共基准测试）转变为任务的更具体版本（通过内部测试集的评估进行测试）。

分类和提取是两个典型的例子。想象一下，将支持票分为 17 个主题之一（即分类），升级到正确的团队（也是分类），读取费用跟踪收据（提取）。这些听起来很简单，但模型不知道您的决策边界，也不知道只有您理解的两个主题之间的细微差别。你可以及时提出建议，但你却要永远为这些代币付出代价，而且仍然在灰色地带赌博。给模型几百到几千个“输入→我们实际使用的标签”的例子，它就会停止猜测你的分类法并开始了解它。

我们的 UIPad 示例也符合这种模式。它既不是提取也不是分类，但我们试图让我们的模型理解任务的特定版本。那么让我们来测试一下（双关语）。计划如下：

- 将 UIPad 数据集拆分为训练/测试集这样我们就可以更有信心模型可以将其学习内容从训练集推广到测试集上未见过的数据
- 在测试集上运行 Kimi K3 和 GPT 5.6 Sol 以获得基线分数注意，我之前向您展示了 **整个** 数据集的分数，而不是分割的，所以我们需要再次执行此操作以获得公平的比较
- 在训练集上训练 K3，**不是**测试集我使用了 Fireworks [无服务器训练 API](https://docs.fireworks.ai/fine-tuning/training-api/serverless)我将我的编码代理指向我们的 [cookbook 的训练技能](https://github.com/fw-ai/cookbook) 文件并让它完成其余的工作
- 针对相同的测试集运行新的训练模型以获得最终分数

Base K3 在持续测试中落后于 Sol；经过大约三个小时的训练后，tuned K3 清除了它。

瞧！经过仅 3 小时的训练，我们经过调整的 K3 模型现在**优于 GPT 5.6 Sol。** 这只是如何将独特数据与现成模型相结合以创建具有真正专业智能的模型的示例之一。

### “按照我们的方式写作”

如果你使用人工智能来撰写营销简报、临床笔记、法律草案、博客文章等内容，你可能会注意到人工智能的输出本身可能并没有错，但它们只是不是你写笔记的方式或你的公司如何构建简报的方式。风格是一种行为，而不是事实，提示可以在短时间内保持风格，但它会随着时间的推移而漂移。

例如，[Heidi](https://fireworks.ai/blog/Heidi-Health)，每个医学专业训练不同的模型，因为精神病学笔记和骨科笔记是不同的写作体裁，即使它们来自相同的事实来源。我们在法律（[Harvey](https://fireworks.ai/blog/post-training-kimi-k3-with-harvey-for-long-horizo​​n-legal-work)、Legora）和监管起草（Ritivel）中观察到相同的风格模式：知识是共享的，但形式是专门化的，而形式就是您要训练到模型中的内容。

### “大模型是有效的，但我们只是无法大规模承担”

也许您已经走到这一步并想“唷，我的模型对我来说已经足够好了，即使它已经关闭了。”如果是这样，那就太好了！如果前沿模型已经达到了您的质量标准，但受到费用和延迟的影响，那么您的举措可能是“蒸馏”：使用该大型前沿模型来指导和训练较小的模型，以更低的成本和延迟重现其质量。

你已经知道你的质量标准和你的账单，所以你可以在花费培训费用之前估计回报，坦率地说，这并不总是容易的，但最后的评估**更容易，因为“小模型与大模型匹配吗？”这是一个比“这在抽象上好吗？”更容易回答的问题。

### “让代理真正完成工作”

迄今为止，代理是LLM最常见的应用。大多数人要么使用现有的代理工具，要么为了更具竞争力，根据自己的业务构建自己的代理工具。为了使多步骤工具调用代理可靠地完成端到端，我们经常求助于**强化学习**：让代理运行模拟任务和环境，并根据结果（它是否得到了正确的答案？）、轨迹（路径是否有效？）和行为（是否遵循规则？）进行评分。

这种培训方式已被证明可以灌输各种不同的行为，甚至在某些情况下传授知识。毫不奇怪，越来越多的公司正在转向强化学习来提高他们的代理的能力。当代理正在执行的任务可以通过编程方式进行检查时，这项工作尤其可行：单元测试通过，查询返回正确的行，票证得到解决。我们与 [Vercel](https://fireworks.ai/blog/vercel) 的合作就是一个很好的例子，我们的烹饪书中有针对此类工作的食谱（链接在最后）。

### “我们的域名经常变化”

在上述模式中，任务空间的变化速度通常不够快，不足以需要不断的再训练。例如，如果我们训练一个模型在一组特定的 UI 上运行一次，并且该 UI 不会经常更改，那么您可以将训练好的模型保留一段时间，而不必担心性能出现太大偏差。

最终的模式是一种运营模式，而不是一次性项目。漂移的概念在人工智能中已经存在了几十年：你训练一个模型一次，它的表现就很好，但它周围的数据不断变化。 ICD 代码被修改，客户提出新问题，付款人政策发生变化，新药物进入市场。如果你的智力是租来的，你能做的最好的事情就是等待别人的模型赶上。如果你拥有它，你可以建立一个持续的培训循环并保持领先，最终的好处是值得的。

## 迈出专业智能的第一步

租用边境是正确的起点，无论它是开放的还是封闭的。人工智能工程会让你走得更远，尤其是在开放模型方面。微调是指您如何利用您业务的独特之处（数据、专业知识）并将其转化为您拥有的情报。

但真正的回报不是单一的训练模型，而是循环。当你拥有模型、配方和训练循环时，你的专业智能就不再是一个会衰减的快照，而是成为复合的东西：你领域中的每一次转变、每一个新的生产失败、每一个更好的基础模型都会成为下一个回合的燃料，而不是等待别人路线图的理由。这就是拥有你的智力实际上能给你带来的东西。租用的版本只能迎头赶上；拥有的版本保持领先。

现在我们有一张关于如何拥有您的专业智慧的地图。本系列的其余部分将穿过维修站、路边景点，并最终到达终点线。我们将了解如何诊断人工智能系统中实际存在的问题，决定是否进行训练，并在准备好后决定在哪里进行训练。在此过程中，我们将看到完整的端到端培训LLM和代理人的示例。
