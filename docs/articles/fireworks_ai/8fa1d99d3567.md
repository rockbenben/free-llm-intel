# Fireworks 在 Forge 发布新产品，帮企业构建专用智能

关于未来有两种愿景：一个世界，所有智能都由少数封闭的前沿实验室拥有；或者，一个世界，每家公司都拥有让自己组织独一无二的那份智能。

[Fireworks Forge](https://fireworks.ai/forge) 正是为打造第二种未来的人准备的。我们的首届年度大会今天开幕，汇聚了来自 AI 原生初创公司、全球企业、开放权重模型实验室等的领导者。

开放权重模型的进步——包括 NVIDIA、Meta 与 Reflection AI 的模型（均可在 Fireworks 上使用）——正在为企业提供更多构建 AI 的选择。在大会上，我们发布了新产品，帮助企业把开放模型的进步转化为围绕其自身专业知识、数据与任务构建的智能。

这些发布直面团队在把 AI 带入日常工作时遇到的现实障碍：agent 响应太慢、模型需要在公司专属任务上表现更好，以及基础设施必须满足企业在成本、控制与安全方面的要求。

## 更快的 agent，成本与负载相匹配

AI agent 完成一项任务往往要发起多次模型调用。每次调用都在拉长客户或员工等待结果的时间，而同时运行更多 agent 又会加剧容量压力、推高成本。团队既需要面向时效敏感工作的速度，也需要为可以等待的任务提供更经济的选项。

Fireworks Ultra-fast 由 NVIDIA Blackwell GPU 驱动，为这些时效敏感的负载加速。它现已进入公开预览，在 [DeepSeek V4.1 Flash](https://fireworks.ai/blog/deepseek-v4-1-flash-vs-astra-benchmarks) 上的演示速度高达每秒 1,500 tokens。当延迟在多个步骤间不断累积时，这种速度尤为宝贵：在一个经过基准测试的 30 轮 agent 任务中，完成时间从 1 分钟降到了 ultra-fast 下的 8 秒。

对于成本比立即完成更重要的负载，Background Mode 提供了一个半价档的更低成本运行时选项。这一模式为可以等待的合规工作降低单任务成本，比如为评估生成数据和夜间研究。多日 Prompt Caching 降低重复上下文的成本，而更高的速率限制支持更多并发 agent。

![多日 prompt caching 与 Background Mode 如何降低 agent 成本](https://fireworks.ai/_next/image?url=https%3A%2F%2Fcdn.sanity.io%2Fimages%2Fpv37i0yn%2Fhorizon%2F2d8ddf4821e259fb68070ea79fb66d05cb4a4adf-1650x584.png%3Fauto%3Dformat&w=3840&q=75)

图 1：常驻 agent 每次暂停后恢复运行，都要为重新处理上下文付费；后台 agent 则在为本可等待的工作支付峰值价格。多日 prompt caching 与 Background Mode 分别降低这两类成本。

专用模型同样可以改善推理经济性。[Ember-1](https://fireworks.ai/blog/ember-1) 是 Fireworks 的一款模型，可通过 serverless 与专属部署使用，在我们的评估中，它在保持与 Kimi K3 相当质量的同时少用了约 40% 的 tokens。

图 2：在五个行业基准上，Ember-1 位于质量-成本前沿，得分与 Claude Opus 5 相差约一个点，而每任务成本约为其五分之一。来源：Introducing Ember-1 博客

这些能力结合起来，帮助团队让推理性能与支出匹配每个负载的实际需求。

## Fireworks Nexus：在员工已在使用的工具中提供更多模型选择

员工日益依赖 AI 来编码和处理日常工作，但换模型可能意味着离开熟悉的工具，或再多管理一份订阅。企业需要在保持支出可见性的同时，给人们更多模型选择。

[Fireworks Nexus](https://fireworks.ai/product/nexus) 把开放模型带进人们已在使用的 AI 编码与协同办公工具，与其现有 AI 订阅并存。它将开放与闭源模型相结合，配合个性化模型选择与缓存感知，帮助人们使用契合其工作的模型，同时为组织提供集中的支出可见性与控制。

图 3：Fireworks Nexus 逐日跟踪按模型划分的支出，并与估算的全量 Opus 5.5 基线对比，让财务看清每一美元花在了哪里、路由又省下了什么。

今天我们发布了 [Nexus Desktop](https://docs.fireworks.ai/nexus/desktop)，与 Nexus CLI 并列。Nexus 现已运行在 Codex 应用、Claude Desktop 和 OpenCode 中，把个性化模型选择从编码扩展到日常知识工作。新的 Pro 计划每月 $8 起，Teams 计划每席位每月 $10 起。Enterprise 计划增加 SSO、治理、共享预算与访问控制。

图 4：Nexus Desktop 用一个开关把你每天使用的工具接入 Nexus，让团队无需碰终端即可获得模型路由。

随着负载增长，现已正式可用的更高 serverless 速率限制让团队并行运行更多工作，而无需预留专属容量。同样已正式可用的 [Elastic Burst](https://docs.fireworks.ai/serverless/rate-limits#elastic-burst) 允许客户在有空闲容量时突破常规用量上限，无需改动任何代码或定价。

## 训练：把你的专业知识变成更好的模型

选对模型可以改善结果、降低成本。而训练更进一步——教会模型在你的特定任务上什么才算好。这可能意味着超越现有模型的质量，或从一个更小、更快的模型上拿到你需要的性能，而且往往两者兼得。在 Forge 大会上，我们让这些收益更容易交付、更容易带入生产。

这一切始于知道该改进什么。No Eval（现已进入私有预览）帮助把生产跟踪数据与产品信号转化为任务专属评估，让团队能找出模型在哪里力不从心，并衡量训练是否弥合了差距。这解决了自建模型训练的最大障碍之一——自己写评估可能要花上数周的数据标注，然后还要评分。

图 5：把生产反馈变成你训练循环的一部分。

[Specialized Model Inference](https://docs.fireworks.ai/serverless/specialized-model-inference/overview)**，**现已进入公开预览，将 serverless 的服务方式扩展到 LoRA adapter，从 GLM 5.3 Flash 起步。团队可以评估一个训练好的模型，并通过 Fireworks Serverless API 为其提供服务：按 token 计价、无需为专属部署测算容量、闲置时不产生服务费用。他们可以让模型持续服役，同时试验下一个版本。

团队可以从 [Muse Glimmer 30B 免费训练](https://fireworks.ai/blog/train-muse-glimmer-for-free)入手，活动持续至 11 月 30 日，涵盖监督微调、直接偏好优化与强化学习。

## 企业级控制，在模型需要运行的任何地方

随着 AI 进入关键业务工作流，企业需要治理模型使用、控制支出并留存活动记录。还有一些企业需要更强的控制——决定 AI 基础设施运行在哪里、数据如何受到保护。

Fireworks 现已正式提供模型治理、支出控制与可导出的审计日志。集中化账户管理、区域数据控制与客户自管加密的预览，为运营要求更高的组织扩展了这些能力。

对于想利用自有基础设施的企业，[Fireworks Sovereign](https://fireworks.ai/product/sovereign)（现已进入私有预览）把公司的推理引擎带进客户的云、neocloud 或数据中心。它将能够让每 GPU 美元产出的 tokens 翻倍甚至更多的技术，与能降低总体拥有成本的专家管理相结合，帮助客户在自选的基础设施内运行开放模型。

推理与训练都在客户环境内运行，受其已在执行的安全与变更控制策略约束。受监管的企业可以在自己治理的基础设施上满足数据驻留与模型访问要求，AI 容量留在他们选定的司法辖区。因为基础设施由客户拥有、模型由客户挑选，供应商的调价或模型退役左右不了他们的路线图。Fireworks 已在客户环境中管理着超过 25,000 块 GPU。
