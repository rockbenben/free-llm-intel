[**专业智能指数 (SII)**](https://fireworks.ai/specialized-intelligence-index/) 是您探索开放、封闭和专业模型在特定领域基准测试上的性能的一站式目的地。每个基准都反映了从业者设计的现实世界任务。今天，我们在七个初始领域推出基准：医疗保健、法律、网络安全、金融、客户支持、生产力和软件。更多即将推出。

## 实际工作的衡量标准

公共基准为跟踪进度和比较模型提供了通用参考点，但它们并不能很好地衡量实际工作。这些评估使用有界任务、固定数据集和标准化评分。真正的工作更加混乱。它涉及不完整的信息、不断变化的范围、业务限制、复杂的判断调用、多步骤工作流程和协作。

对于寻求确定模型是否足以自动执行人工任务的组织来说，这种区别很重要。可接受的结果必须满足对实际结果负责的真实人员的标准。今年早些时候，[METR](https://metr.org/notes/2026-03-10-many-swe-bench-passing-prs-would-not-be-merged-into-main/) 量化了这种差异。在他们的工作中，4 名维护人员审查了来自 3 个 SWE-bench Verified 存储库的 296 个 AI 生成的拉取请求 (PR)。维护者接受度分数平均比自动基准分数低 24.2 个百分点。用他们自己的话说：“许多 SWE 板凳通过的 PR 不会被合并到 main 中。”

为了将基准应用到实际工作中，我们需要确定分数衡量的内容、评估在多大程度上反映了预期的工作，以及更好的绩效是否会产生有用的运营结果。

**该测试是否衡量其声称的能力？**

这是一个结构效度的问题：评估是否支持其分数所附加的解释。 [Bean 和同事](https://arxiv.org/abs/2511.04703) 检查了 445 个 LLM 基准，并确定了研究人员打算测量的现象、他们的任务和评分方法之间反复出现的差距。例如，旨在衡量推理的任务也可能依赖于记忆的知识。这使得很难确定高分是否反映了推理、回忆或两者兼而有之。

**测试是否代表我们关心的工作？**

代表性涉及任务集的覆盖范围和组成。 [Wang 及其同事](https://arxiv.org/abs/2603.01203) 研究了 43 个代理基准，发现计算机和数学工作集中，在他们的分析中，这一类别占美国就业的 7.6%。管理和法律工作的代表性不足，各职业中常见的人际交往能力也是如此。实际工作基准必须代表其预期领域。

然后在实际工作中评估模型遵循逻辑进展，每个步骤都需要更多证据：

**基准分数 → 能力主张 → 业务成果**

分数记录了在指定协议下定义的任务集的表现。能力声明需要证据证明系统能够可靠地执行相关类别的工作，包括在不熟悉的情况下。业务成果需要证据证明这种性能以可接受的质量和成本提供了所需的结果。

deepfirst 的 dfbench 评估开放式防御安全工作。访问 SII，探索所有行业的基准。

### 由从业者开发，为从业者服务

实际工作评估是由从业者定义的，他们帮助概述工作、约束和接受条件。设计实际工作评估通常涉及以下步骤：

**1.定义工作及其价值。** 指定任务、目标用户和人工监督级别。设置质量阈值以及时间和成本限制。为当前工作流程建立基线，然后测试分数改进是否可以预测试点或受控部署中的更好结果。

**2.反映工作。** 从预期环境中抽取例行任务和困难案例。包括现实信息、工具、权限和政策约束。添加针对间接故障的压力测试，但当其频率与正常使用不同时单独报告。故意设置困难的测试集不应作为日常表现的估计。

**3.与从业者一起制定接受标准。** 将专业标准转化为可观察的结果和明确的标准。区分小缺陷和导致输出不可接受的故障。评估最终结果和任何重要的操作，例如在更改受保护资源之前寻求批准。

**4.验证分级机。** 将自动判断与专家评审进行比较。检查审稿人之间的错误接受、错误拒绝和分歧。如果这些差异表现出模糊性，请完善评分标准或评分方法。随着系统的变化，继续对输出进行采样以供专家评审。

**5.测试泛化性和可靠性。** 将开发和保留的案例分开，检查污染，并随着工作的变化更新评估。重复运行并报告不确定性、按任务类别划分的绩效以及关键故障率。记录模型、提示、代理工具、工具、资源限制和分级器版本，以便比较保持可解释性。

## SII 亮点一览

### 医疗保健

**Doximity 的 BedsideBench v0.2.0** 评估了 500 个经过医生验证的临床案例的前沿人工智能模型，涵盖医学推理、计算、药物安全、指南遵守、幻觉、诊断安全和治疗计划。

**Mercor 的 APEX-1：全科医生 (MD) 基准**衡量前沿 AI 模型在诊断、检查和安全升级等实际初级保健医生任务中的表现。

**HealthBench Professional **评估前沿人工智能模型是否能够为具有挑战性的临床医生编写的任务提供准确、有用和安全的响应。

### 法律

**Harvey 的法律代理基准 (LAB)** 衡量前沿 AI 模型在 24 个实践领域的实际法律工作中的表现，要求它们导航文件并生成根据专家标准评分的工作产品，以确保事实准确性、法律分析和格式。

**Harvey’s LAB Contracts **测试人工智能代理是否可以在 500 个起草、审查和谈判任务中推动合同谈判。为了成功完成每项任务，代理商必须解决所有变更和未解决的问题，以便在业务和交易的限制范围内推进合同。

**Mercor 的 APEX 代理：公司法** 评估多步骤的公司法任务，包括链工具使用、检索和文件起草。执业公司律师根据公司接受的工作产品对产出进行评分。

**RedlineBench** 由充当内部法律顾问的人工智能代理评估现实的、多轮合同修订。

### 金融

**Rogo’s Big Finance Bench **评估人工智能代理的问题涵盖估值模型、财务报表分析、预测和其他关键财务工作流程，并使用从业者编写的评分标准对代理如何查找信息、应用财务定义和引文以及执行计算进行评分。

### 网络安全

**深度优先 dfbench v1** 目标是跨漏洞检测、验证和差异分析的防御安全。 Deepfirst 自己的 dfs-large1 模型，使用 RL 在 GLM 5.2 基础上通过 Fireworks 进行后训练，在评估中达到了新的帕累托前沿。该模型的改进归功于强化学习奖励塑造、努力惩罚、软发现预算惩罚以及漏洞检测和验证的联合训练。该结果由[深度第一](https://深度第一.com/research/dfbench)报告。

**Novee 的 PWNBench-v0.1** 在实时 Web 应用程序的代理灰盒渗透测试中评估前沿 AI 模型，涵盖完整的发现-利用-报告工作流程。它在共享的细线束下测量召回率、精确率、F0.5 和 API 成本。

### 客户支持

**Decagon 的 DuetBench-Diagnosis** 重播真实的 Duet 客户支持调查，并在结果、调查、工具使用和沟通方面对模型响应进行直接评级。

**Sierra 的 τ-Banking** 评估客户支持代理的银行任务，这些任务需要搜索跨 21 个产品类别的 698 个文档知识库、应用策略以及执行多步骤工具调用，同时管理正在进行的客户对话。

**Sierra 的 τ-Voice** 评估语音代理是否可以完成零售、航空公司和电信领域的客户服务任务，同时处理干扰、背景噪音和不同的口音。

### 生产力

**Genspark Slides Benchmark **评估人工智能生成的关于去识别真实用户任务的演示文稿，对任务完成情况、内容质量、视觉设计和流程质量对完成的幻灯片进行评分，并对布局缺陷、捏造内容和忽略说明进行处罚。

### 软件

**Traversal 的 ORCA-Bench **是一个站点可靠性工程基准，可根据不明确的报告、遥测和源代码评估生产式根本原因分析 (RCA)。硬 RCA 准确度是头条得分；中等 RCA 和事件幻觉仍然是独立的原生指标。

**Proximal 的 FrontierSWE V2 ** 是一个代码生成基准测试，可评估 34 项软件工程任务，这些任务处于人类专家所能完成的范围内：用 OpenGL 编写飞行模拟渲染器、将 Git 移植到 Zig、仅通过视觉驱动赛车机器人。每个模型的每项任务可进行 5 次试验，每次试验最多 20 小时。每次试验都会获得分级奖励，而不是通过或失败，因此获得大部分成绩的运行仍然很重要。

**Mercor 的 APEX-SWE **评估 200 个软件工程任务的人工智能模型，这些任务需要集成云服务和业务应用程序或使用日志、仪表板和不完整的上下文调试生产故障。

**Datacurve 的 DeepSWE v1.1** 针对跨 91 个存储库和五种语言的 113 个原始长期工程任务评估编码代理，测试其提交的代码在隔离环境中的正确行为。

**Macrscope 的 MacroscopeBench **评估模型在代码审查时的性能，衡量审查者检测真正已知错误同时不发布错误评论的能力。它运行来自开源存储库的超过 195 个提交，其中 144 个引入了维护人员后来必须修复的真正错误，以及 51 个干净的控件。

训练开放模型可以提供更好的结果，包括以前沿质量降低每项任务的成本。 Genspark 的专业情报结果。

## 方法概述

**没有人工汇总。** SII 不会平均排名、根据成本或持续时间权衡质量，或生成跨域组合。结果保持在基准和领域级别，具有覆盖矩阵以及分数与成本和分数与持续时间的视图，以便用户可以应用自己的权衡。

**来源。** 基准测试结果可能由合作伙伴、Fireworks 或两者的组合跨模型报告；相应地定义或链接实施。发布遵循基准所有者的政策；分数被公布，而评估集、提示、评分逻辑、轨迹和原始合作伙伴输出则保持私有，除非所有者另有选择。

**可重复性。** 每个基准都由可以再现它的人来标记：任何人、Fireworks 和基准所有者，或仅限合作伙伴。可重复性来自版本化方法和固定执行快照，它们记录了工具、采样参数、超时、快照 ID、执行器和任何未解决的问题。

**型号选择。 **模型的选择取决于组织是否可以合理地在生产规模上部署它们，价格是关键考虑因素。新的前沿模型会自动进入资格管道，并仅在通过此标准后才会出现在指数中。

有关利用、推理、沙箱、运行协议、置信度、可靠性以及成本和持续时间指标的更多详细信息，请[访问 Fireworks Methodology](https://fireworks.ai/specialized-intelligence-index/#methodology)。
