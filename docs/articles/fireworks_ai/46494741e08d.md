**TLDR；** DeepSeek V4 Pro 0813 在 840 个对抗性安全任务上录得零次拒答，并且以我们所测最高分模型每次成功的一半成本完成这些任务。同一测试中的两个闭源模型是"美元/结果"最差的两个。

我们把 DeepSeek V4 Pro 与 Kimi K3、GPT-5.5 和 Claude Opus 4.8 一起放进了 CyberGym。我们评估的是真实代码库中的真实漏洞，每个任务平均约 89 轮。

## CyberGym 在评估 Deepseek 时实际衡量的是什么

大多数 coding benchmark 要求模型写出能通过单个测试的代码。CyberGym 代表更贴近真实世界的工作负载，因为它要求模型先弄坏真实的东西，再把它修好。

这个 benchmark 由 UC Berkeley 基于 188 个广泛使用的开源项目中的 1,507 个真实漏洞构建，漏洞取自 Google 的 OSS-Fuzz 活动和 ARVO 可复现漏洞档案。每个任务交给 agent 一段简短描述和一个真实的易受攻击代码库。agent 必须定位缺陷、构造真正能触发它的输入，然后打补丁。评分依据执行结果，而不是评判模型。proof-of-concept 要么让目标崩溃，要么不崩溃。

CyberGym 的结构是 agentic、长周期且不留情面的。我们的运行平均每个任务 89 轮、25 分钟。"可能的结果"没有部分得分，这意味着 CyberGym 是少数无法靠一个写得很有底气的模型来刷分的 evals 之一。

它也是我们的客户已经在运行的工作负载最接近的公开代理。正如 Trilogy 在他们基于 Fireworks 构建的[网络安全手册](https://fireworks.ai/blog/trilogy-coe-playbook-for-cybersecurity)中所说："防守方的工作负载是高并发的"。你要审计每个 repo、分诊每次扫描、审查每个 PR、重测每个修复。一个"差不多够强"且运行成本更低的模型，往往胜过在事件处置期间被限制、昂贵或不可用的更强模型。

## DeepSeek V4 Pro：零拒答，零浪费的开销

大多数团队撞上拒答墙都太晚了，通常是在 agent 已经进入生产之后。agent 的概念验证可能跑得很顺，但在真实流量下却卡在任务中途。

在我们的测试中，840 个被追踪的主任务里，Deepseek V4 Pro 在全部 840 个上都产出了原生工具调用。我们没有看到任何拒答，也没有看到输出长度截断。

为了对比说明这为什么重要，前沿闭源模型的表现非常不同。在最新的 Claude Opus 5 和 GPT 5.6 上，这些网络任务根本无法完成，因为存在阻止 CyberGym 工具的检查。当上一代 Claude Opus 4.8 真正跑起来时，它在我们配对队列的 697 个任务中只有 70 个进入了第一阶段验证，进入率 10%，最终奖励为 5.9%。这并不是说 Opus 是个弱的 coding 模型，而是它很大一部分运行在这个任务族上从未产出可用的产物。如果你在构建安全 agent，这个差异会体现为一笔什么也没产出的 token 账单。对网络安全用例来说，开放模型是最可行的方案，因为闭源模型可能直接挡住你去做真正的工作。

在 CyberGym 测试中，Deepseek V4 Pro 在 697 个任务中的 678 个上进入了验证，即 97.3%，见下图。

在这次测试中每个模型都发现了什么？在 697 个任务里，有 38 个是 Deepseek V4 Pro 独家解决的。K3 独家解决了 97 个，GPT-5.5 解决了 41 个，Opus 4.8 正好一个。Opus 不只是分数低，它几乎从来不是那个发现别人漏掉的东西的模型。为完整起见，有 101 个任务四个模型都没解决，这就是四者的代表性上限。

人们很容易盯着与 K3 的差距，而错过其他结果。大家常以为开放模型只是在成本上更划算，但这次分析显示 Deepseek V4 Pro 在质量与价格上都直接胜过 GPT-5.5。准确率方面：高 6.03 个百分点，95% CI [+1.29, +10.62]，McNemar p = 0.0152。它赢下了 164 个 GPT-5.5 没能解决的任务，同时输掉了 122 个 GPT-5.5 解决了而它没解决的任务。所以这里的开放模型比一个闭源前沿模型更准确，而每个已解决漏洞的成本只有后者的四分之一。

图 2：每任务成本

K3 以 14.8 个百分点的优势赢下原始解决率，数学也证明这不是随机波动。在配对 bootstrap 95% CI [-19.23, -10.33] 下，McNemar p=9.43×10−11——意味着这个差距是随机噪声的可能性几乎为零。如果你的主要标准是成功率，K3 是最佳选择，你可以在 Fireworks 上运行它：[这里](https://fireworks.ai/models/fireworks/kimi-k3)

在实践中，单位经济性与解决率同样重要：

- **成本效率：** 在完全相同的任务上，V4 Pro 每个已解决任务花费 **$2.50**，而 K3 为 **$4.91**（V4 Pro 有 **1.96 倍的成本优势**）。在 863 个任务的诊断中，这个 2 倍的比率依然成立。同样的预算可以跑两倍的安全扫描。
- **独立准确率：** V4 Pro 解决了 920 个任务中的 462 个（**50.2%**），每次运行 **$1.31**，每次成功 **$2.60**。分项得分在 ARVO 任务上达到 **54.7%**，在 OSS-Fuzz 任务上达到 **48.7%**。
- **它在哪失败（harness 的机会）：** 一旦 V4 Pro 完成第一阶段验证（生成有效的 proof-of-concept），它完成完整补丁的概率是 **94.7%**。

Deepseek V4 Pro 很少在难的部分失败（修代码），它在上游的 setup 步骤（生成初始 exploit）失败。这对你的团队是一个可操作的 prompt 与 scaffolding 修复点，而不是无法解决的模型局限。

数据说得很清楚：在构建高并发安全 agent 时，你不再需要为了成本而牺牲性能，也不必担心被闭源前沿模型的"拒答墙"挡住。DeepSeek V4 Pro 提供了明确的优势：始终如一地给出不被截断的原生工具调用、显著更高的准确率，以及相较领先专有替代方案在每解决漏洞上 1.96 倍的成本优势。对希望大规模审计代码库和分诊漏洞的安全团队来说，迁移到像 DeepSeek V4 Pro 这样的开放高性能模型不只是预算决策，而是一次技术升级，让安全运营更可靠、更有效、更可持续。
