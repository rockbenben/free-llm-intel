## 训练 API，现已普遍可用

我们与世界各地的 ML 团队合作，了解现有训练工作流程的不足之处：模型和方法选择受限、对参数和训练循环的控制有限、计算僵化且未得到充分利用、训练和部署基础设施分散，导致成本膨胀、产生同步开销并引入数值漂移。这些合作伙伴关系塑造了我们的培训 API。

Fireworks Training API 将您的自定义训练循环连接到 Fireworks 管理的分布式训练和部署基础设施。您可以从您选择的任何地方用 Python 编排循环，并完全控制您的损失或奖励、数据和环境。 Fireworks 管理高性能计算：训练器计算梯度并更新模型，以及从训练模型生成样本的部署部署。 Fireworks 还管理这两者之间的交互，从权重同步到失败的交换恢复，以及列车推出对齐。所有这些使您能够专注于完善学习信号，而不是基础设施挑战。

## 为什么团队在 Fireworks 上训练

Fireworks 是前沿实验室之外少数几个在 10,000 多个 GPU 上运行强化学习 (RL) 的组织之一。强化学习将训练和推理变成一个连续耦合的系统；每一步都从当前策略的推出开始，更新权重，并将这些权重反馈到下一轮采样的推理中。在前沿规模上，算法只是挑战的一部分。有效的强化学习取决于三个要求：正确性、性能效率和开发速度。

### 正确性：训练和推理对齐

为了保证 RL 训练的正确性，推出引擎和训练器需要共享相同的数值定义。当一切似乎都正常时，小的数值漂移可能会破坏学习信号，从令牌剪切到奖励崩溃。伴随着烟花，

- **数字格式端到端匹配。** 训练和推理之间的精度或量化差异可能会改变模型计算的值，即使权重相同。 Fireworks 会对齐训练器和推出数字格式（例如 BF16、逐块 FP8 和 NVFP4），因此训练器保存的模型就是推出部署运行的模型。
- **内核也匹配。** 相同的数字格式并不能保证相同的计算。即使精度相同，浮点缩减、内核选择和并行性也会产生不同的数字，因此 Fireworks 会跨两条路径对齐底层实现。
- **MoE 执行保持一致。** 微小的数值差异可以改变哪些专家触发并沿着不同的计算路径发送令牌。 Fireworks 使用 Router Replay 来保留推出和向后传递之间的专家选择，以及支持的前沿 MoE 的批处理不变内核和确定性缩减。

Fireworks 通过在 rollout 引擎和训练器中运行相同的序列并测量训练推断 KL 散度 (KLD) 来直接验证这种对齐。所有在 Fireworks 训练中启动的模型都会不断得到验证，以确保 KLD 最小化。

### 性能效率：强化学习循环的吞吐量最大化

从规模上看，强化学习很大程度上是一个生成问题。大部分挂钟时间都花在生成 rollout 而不是更新权重，因此 rollout 吞吐量和 GPU 利用率成为训练时间和成本的主要决定因素。完成长度也有很大差异，这意味着严格的批处理可能会使 GPU 在少数长时间运行的轨迹完成时处于空闲状态。

Fireworks 可以运行异步 RL，将推出集合与训练重叠，而不是强制循环的两侧按顺序执行。 Rollout GPU 可以开始生成下一批，同时训练器更新前一批，当算法允许更多重叠时，可以使用有限权重陈旧性。目标很简单：让 GPU 继续做有用的工作，而不是在同步障碍处等待。

一旦循环完成训练步骤，必须传输更新的模型并将其加载到部署部署中。 Fireworks 不会在每一步后拆除部署部署并重新加载完整模型，而是将新权重热加载到正在运行的部署中。对于全参数检查点，采用新颖的压缩技术来降低权重传输的带宽和存储要求。在当前权重和先前权重之间计算 XOR Diff，并使用 zstd 压缩来减小此有效负载的大小。这导致传输带宽减少多达 10 倍，从而显着加快训练循环。

### 开发速度：压缩迭代周期

生产的瓶颈通常不是训练工作，而是迭代之间的时间。在分散的堆栈中，每个周期都意味着在训练和推理系统之间移动检查点、重新部署、协调差异、运行评估以及重新开始。

Fireworks 将这一过程转变为一个持续的开发循环：在一个平台上训练→部署→评估→再训练。检查点直接进入服务，而生产跟踪、评估和反馈则为下一次训练运行提供信息。由于我们负责 GPU 调配、容量和配置，因此客户可以跳过采购、模型启用和基础设施规模调整工作，这些工作会减慢迭代速度和上市时间。团队报告说，在相同的培训预算下，迭代次数增加了 2-4 倍，将模型开发从几周压缩到几小时，并加快了生产时间。

## 入门：Fireworks Lab 可以提供帮助

通过平台内置的正确性、性能效率和迭代速度，团队可以专注于他们的培训策略。该策略包括塑造模型质量的决策：训练循环、数据、奖励、评估者和工具设计。它还包括确定工作负载如何大规模运行的系统选择，例如同步与异步 RL、可接受的权重过时性、部署到训练器分配、并行性以及检查点和热加载策略。
