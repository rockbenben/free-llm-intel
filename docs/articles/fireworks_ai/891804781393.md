**TLDR；** 了解何时应利用 `GLOBAL` 选项，以及我们如何架构多区域路由，把全球工作负载放置移出推理热路径，优化低延迟、韧性与运维简易性。

没有任何单一区域是取之不尽的 GPU 池。

Fireworks 拥有完整谱系的服务选项，并在 30 多个区域、跨数十家云厂商上全球运营，构成业内最大的独立 GPU 集群之一。然而，庞大的全球足迹只有在调度器真正被授权动用它时才能保护你的可用性。把工作负载钉死在单一区域，等于施加一个人造的容量天花板。当区域资源紧张时，下一块可用的兼容 GPU 可能坐在大洋彼岸——美国、欧洲、加拿大或 APAC 的另一个数据中心。

传统做法是，团队被迫手动配置冗余的多区域端点、拼凑自定义区域路由器、无休止地腾挪 failover 逻辑。Fireworks 现已支持 `GLOBAL` 选项，让你跨地域运行工作负载。这让你的架构统一在一个部署身份、一个端点之下，卸下管理一张全球地图的运维负担。

## 不交延迟税的智能路由

Fireworks 对多区域放置与路由做了工程设计，让全球调度永远不会成为你实时推理流水线的瓶颈。

当你的工作负载被标记为 **GLOBAL**，调度器会在最广的合格容量池上动态映射请求，同时严格尊重你的独特参数：

- •加速卡类型与硬件要求
- •配额与成本护栏
- •可靠性等级与合规边界
- •数据驻留与放置约束

你保有完全的治理权与单端点的简洁，而 Fireworks 吸收驾驭全球基础设施的复杂性。

> “有了 Fireworks，我们不必用延迟换可靠性。跨多个集群运行让我们能通过自动伸缩适应区域波动，确保持续顺滑的体验。即便扩展到多区域之后，我们的响应时间仍是行业领先水平。”

> — Ishan Gupta，Juicebox CEO

- •**多区域能买到什么？**更多兼容容量可以汇入同一个部署。当在线节点分散各处，某个分片故障时另一分片仍可用。放置可以改变，而不需要新的公开端点。
- •**`GLOBAL` 会让每个请求变慢吗？**它不会增加一次全局调度器往返或一次全区域探测。在正常的公开 API 网关路径上，DNS 按就近原则在健康网关池之间引导，网关把首次尝试发给按控制面发布的 router record 构建的顺序中的第一个候选。到所选算力的网络距离依然要紧；这个设计消除的是每请求一次的全局路由步骤，而不是宣称物理距离消失了。
- •**部署能跑在哪？**Fireworks 支持 `GLOBAL`、`US`、`EUROPE`、`APAC`、`CANADA` 多区域范围。实时位置与硬件列表见[当前区域目录](https://docs.fireworks.ai/deployments/regions)。在你的本地性与数据驻留要求允许的范围内，选择最宽的边界。

## 生产中 99.99% 的成功率

在为期七天的生产研究中，信号指向了架构设计的初衷：可全球放置的部署组与更高的就绪节点满足率相关联，而实际形成的多集群足迹与更低的每请求响应数相关联。

在带外部客户标签、可全球放置的组中，那些观测到有 2 个及以上服务集群的部署日里，请求成功率从单区域部署的 99.269% 提升到多区域部署的 99.992%。这帮助我们为可全球放置的客户部署达成 99.99% 的可靠性目标。

这些是观察性信号，不是 A/B 测试，也不是普适的正常运行时间承诺。服务集群标签指基础设施集群，并非归一化后的区域；流量集中在少数账户上，且配对账户的结果互有胜负。敏感性检查保持了总体方向，但没有使其成为因果。

这些数字说明了项目为何重要。而实现的故事，始于一个我们的架构解不出的等式。

## 为什么我们必须重写部署看待基础设施的方式

一次推理部署要 8 个节点。Virginia 有 4 个合格节点位。Iowa 还有 4 个。

整个集群有 8 个。我们的旧调度器仍然拒绝这个部署。

它的行为是正确的。问题就在这里。

调度器问的不是“集群里有 8 个合格节点吗？”而是“有某个区域一次拿得出全部 8 个吗？”两个区域都拿不出，于是部署以 `RESOURCE_EXHAUSTED` 收场。

```
12legacy:  max(4, 4) < 8  → rejectglobal:      4 + 4 = 8  → place
```

这个约束嵌在架构里：每个部署只属于单一区域。

在新架构下，一个部署可以通过单一端点从多个区域汲取兼容容量。调度器尊重硬件要求、区域限制、可靠性策略与地理边界。

## 把全球调度移出请求路径

Fireworks 在流量到来之前就规划好放置，因此请求无需咨询调度器或探测每个区域。

- •从就近的健康网关开始。DNS 按就近原则把请求导向健康的网关。
- •路由到可用算力。网关使用提前准备好的路由信息来决定把每个请求发去哪里。
- •合格就重试。出现符合条件的失败时，若路由策略允许且请求可重试，网关可以尝试另一个目标。

网络距离依然要紧：就近的网关也可能把请求路由到更远的算力。这个设计避开了每请求一次的全局路由步骤；它并不能消除地理延迟。

## 选择你的工作负载允许的最宽边界

本地性与数据驻留要求可能需要 US、EUROPE 或 APAC。对于没有这类要求的工作负载，GLOBAL 给调度器最大的空间去寻找兼容容量，或在范围内别处存在兼容供给时重新安置一个卡住的节点。
