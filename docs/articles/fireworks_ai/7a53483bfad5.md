**TLDR；** DeepSeek V4 Pro 0813 在我们的 SWE-Bench 和 LiveCodeBench 运行中位居榜首，每解决一个任务的成本只有 Fable 5 的三分之一，并且事实证明它是比 Kimi K3 更好的路由伙伴。训练功能已上线。

上周我们在 Fireworks 上上线了 DeepSeek，支持 serverless 端点、专用部署和训练支持。该模型提供 100 万 token 上下文窗口、原生工具调用以及可保留的推理历史，面向长周期的智能体工作负载。

我们让 DeepSeek V4 Pro 0813 跑了一遍与 [7 月评测 Kimi K3](https://fireworks.ai/blog/kimik3-fable) 时相同的评测套件。我们在四大基准家族上对比 DeepSeek 与 Kimi K3、Fable 5：SWE-Bench Verified、LiveCodeBench v6、Aider Polyglot v1 和 Terminal-Bench 2.1。在这套组合评测中，DeepSeek V4 Pro 是四个家族里两个家族上最强的单一模型。

在标准代码任务上，DeepSeek V4 Pro 相对 Fable 5 具有压倒性的成本优势：SWE-Bench 上每解决一个任务 $0.309（Fable 5 为 $0.808），LiveCodeBench 上为 $0.040（Fable 5 为 $0.225）。

在 Terminal-Bench 上，关于 Fable 5 的性能和成本有两点值得注意：

- •Fable 5 得分相同，但需要多次尝试，使每任务成本升至 $16.85。我们展示这一设置是为了与我们已发布的 K3 基准保持一致。
- •若只算首次尝试，Fable 5 得分为 74.2%，而每任务成本飙升到 $75.40。内部评估以此首轮基线为准。

DeepSeek V4 Pro 不够强的地方是多语言的广度。正如我们在 [K3 对比 Fable 5 的分析](https://fireworks.ai/blog/kimik3-fable)中展示的，模型的专业化程度因生态系统而异，差异巨大。在 Aider Polyglot 上，V4 Pro 在 Rust（90.0%）和 C++（80.8%）上保持强势，但在 Java（最大的切片，47 个任务）上跌到 48.9%，而 Fable 5 是 74.5%。

Java 表现几乎解释了全部的差距。如果你维护的是 Java 为主的代码库，只用单一模型可能会遇到瓶颈。正如我们在 K3 测试中发现的，多模型方案优于单模型架构。把任务动态路由给各自的专家模型，能以一小部分成本获得更好的整体准确率。

## **路由会改变你的账单**

我们测试了 DeepSeek V4 Pro 与 Fable 5 之间的 oracle 路由：每个任务选表现更好的模型，打平时偏向成本更低的那个。快速回顾：oracle 路由是一种测量理论上最佳性能的方法——让每个模型都跑一遍任务，然后挑选成本最优的正确答案，从而确定成本与性能的上界。

在 409 个任务的组合任务组上，路由方案的准确率达到 92.4%，而单独使用 Fable 5 为 86.6%。这比前沿模型高 5.9 个百分点，且每任务成本 $0.279，对应 Fable 的 $4.510。成本低了十六倍，效果还更好。而且 86.3% 的任务被路由给了 V4 Pro——这才是真正的发现：昂贵的模型是例外，不是默认。

V4 Pro 的每一种配对都胜过对应的 K3 配对。LiveCodeBench 达到 94.0% 对 92.0%，Aider 达到 93.3% 对 91.6%，组合任务组为 92.5% 对 91.1%。V4 Pro 是比 K3 更好的路由伙伴——尽管 K3 在 CyberGym 上得分更高——因为 V4 Pro 赢下的恰恰是 Fable 5 答错的任务。

值得说明 oracle 路由是什么：它是事后计算出的上界，不是你今天就能部署的策略。真实的路由器只能吃到其中的一部分。这一点很重要，因为差距的大小告诉你还有多少提升空间。

## **DeepSeek V4 Pro 训练现已开放**

想构建一个为你的特定领域定制的专用模型？DeepSeek V4 Pro 训练已在 Fireworks 上线，完整支持 SFT、DPO 和 RFT。你获得前沿级基础设施来推高模型性能，而不必撞上平台人为设定的限制。训练任务完成后，你可以一键把微调后的 checkpoint 部署到生产。由于训练与服务运行在同一套协同优化的后端上，你的生产性能与训练基准的表现始终一致。

## **关于 Deepseek 的 Harness 你应该知道什么**

DeepSeek 自己发布的基准运行使用的是 DeepSeek Harness（dsh），这是一个原生智能体运行时，负责从模型适配器一直到核心执行循环的一切。它直接说 DeepSeek V4 的原生工具语义，而不是通过通用的 OpenAI 风格接口转发调用。对于这个模型，DeepSeek 也没有提供标准 chat template，因此微小的序列化不一致可能悄悄损失模型性能。

在 Fireworks 上的测试期间，我们发现「最小化优先」的配置比直接上完整标准工具目录能带来明显更稳定的工具调用。先从裸露的 bash 和编辑器工具面开始，再升级到 dsh 标准配置，能让 DeepSeek V4 Pro 更接近 DeepSeek 自己跑基准时所用的设置。
