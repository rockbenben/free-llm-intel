开源模型是否在开口之前就在默默推理？最近，Anthropic 的研究人员提出了 [Jacobian Lens](https://www.anthropic.com/research/global-workspace)，即 J-Lens。它是一个训练出来的探针（probe），读取模型在某一层的隐藏状态，告诉你模型在写出第一个 token 之前已经倾向哪些词。换句话说，它让你能在模型「思考」到一半时窥视内部，看到一个概念在落到纸面之前正在成形。我们把 J-Lens 应用到两个开源模型：Kimi K3 和 Qwen3.5-9B。我们把由此得到的观察称为**静默信号（silent signals）**：由拟合出的 Lens 恢复出来的、与最终输出相关联的草稿中期词表。

那么，这意味着什么？模型携带的信息是不是比它的输出更多？

历来人们把模型当作黑盒：输入进、输出出。但现实是，我们可以恢复在你的提示词与预测的下一个 token 之间发生的一切——这是打开 AI 黑盒、让任何人得以窥视内部的第一步。

为了开始 unravel AI 模型的内部机制，我们先提出问题：模型在开口之前正在跟踪什么？

我们测试了随 Anthropic 全局工作区（global workspace）研究发布的十个例子。Kimi K3 和 Qwen3.5-9B 分别对相同的用户消息生成了各自的回答。在我们的读数研究中，每个模型都拟合了各自的 J-Lens，我们看到了同一种类的信号。

### **什么是 J-Lens，它如何工作？**

J-Lens 的工作方式像是架在模型内部状态之上的分类器：在特定的 token 位置和层上，识别模型已经倾向哪些概念或词汇。结果是一个排序的 token 列表，显示拟合出的探针把哪些词汇与该内部状态关联得最强。

从 Kimi 开始，我们在 14 段与任务无关的段落上拟合 Lens，这些段落与用于考察模型内部激活的 10 个保留用户提示词分开选取。换句话说，这 14 段文字是用来训练 Lens 的，不是用来测试它的。我们合成了各种短小的、类似预训练语料的段落，主题多样，包括金属热处理、语言借词、轮作和传统导航。

### **配对复制实验：同样的词，不同的注意力焦点**

我们首先做了这样一个实验：让模型复述一句话，同时告诉它把注意力放在一个完全无关的任务上。例如，要求 Kimi 在两种不同的注意力指令下把句子 "The old painting hung crookedly on the wall." 写两遍：

- •**算术版：**“……在写这句话时，请专注于计算 3^2 - 2。”
- •**柑橘版：**“……在写这句话时，请一心想着柑橘类水果。”

图 2：配对复制分析

两次，Kimi 都产出了完全相同的答案：“The old painting hung crookedly on the wall.”。只看原始输出文本，你无法判断模型是否遵循了注意力指令。而 Lens 读数在一个条件下产生算术词汇，在另一个条件下产生柑橘词汇，尽管 Kimi 在两种指令下的可见续写完全一致。把任务固定为逐字输出，排除了「显示 token 的差异能解释 Lens 读数差异」这种可能。但它并没有确立是什么导致了这些内部状态或响应。每个提示词都给我们一个待查找的词汇家族。

图 3：家族词表

句子的每个位置在每一个被采样的 transformer 深度上都有一个状态。一个拟合好的 J-Lens 回答的是：哪些词汇 token 与某一个状态最兼容。

图 4：状态位置

| 片段 | 注意力焦点 | 精确成员词 |
| --- | --- | --- |
| 片段 | 注意力焦点 | 精确成员词 |
| 算术复制 | 推导值 | 9, nine, 7, seven, answer, result, final |
| 算术复制 | 计算过程 | evaluate, calculate, calculation, arithmetic, square, squared, subtract, minus |
| 柑橘复制 | 柑橘示例 | citrus, fruit, orange, lemon, lime, grapefruit, zest, juice |
| 柑橘复制 | 维持专注 | focus, think, attention, mind, concentrate |

概念家族（一份精心挑选的关键词列表）用来检查任务相关词汇是否先出现在读数里、再出现在响应里。一个「单元（cell）」是一个位置-层配对；如果概念家族中有多个成员出现在同一单元，单个单元可以包含多条命中行。把 J-Lens 应用于算术家族的运行，在 4 个被采样层上、10 个 token 位置中的 9 个位置的 top-10 预测里出现了算术相关 token（7、9、3、"answer"、"seven"、"2"）。

图 5：匹配 token 示例

在柑橘家族的运行中，柑橘词汇（orange、lemon、lime、"citrus"、"oranges"）出现在 10 个位置中的 8 个。值得一提的是，两次运行互不泄漏：柑橘运行时算术 token 从未进入 top-10，算术运行时也从未出现柑橘词汇。

### **校准段落**

在把 J-Lens 应用于研究片段之前，我们先在 14 段与任务无关的校准段落上拟合它。这些段落用来把模型的内部状态与词汇读数关联起来；它们与研究片段是分开的。每段校准文字在每个被采样层上产生一个估计值，14 个估计值平均后得到拟合的 Lens。四联图展示了其中四段作为示例。

### **同一套理论在 Qwen 3.5 上也成立吗？**

接下来，我们研究在 Kimi 上评估过的 20 个概念家族，原封不动地应用于一个单独拟合的 Qwen3.5-9B J-Lens 时是否仍能产生合格匹配。这里「合格证据」指 Qwen 的内部状态在其 top-10 排序中产生了某个概念家族的相关关键词。Qwen 收到相同的十条用户消息，但使用它自己的分词器、单独拟合的 Lens，以及确定性原生续写——thinking 关闭、无强制输入。

图 9：J-Lens 在 Qwen 上的结果

使用 Kimi 读数选出的 20 份词表被原封不动地应用到 Qwen 单独拟合的 Lens 上。当一份词表中某个列表词出现在 Lens 某个被采样位置与模型深度的 top-10 匹配结果中时，该词表计为「找到」。20 份词表中有 19 份满足「找到」标准。这把一个词汇检验从 Kimi 迁移到了 Qwen，确认了不同模型架构上出现相同结果。

Qwen 读数中的几个具体例子：

- •**算术复制：**"7"、"9"、"answer" 等数值与 "evaluate"、"subtract" 等过程词共同出现。
- •**柑橘专注：**Qwen 的生成独立反映了底层指令。柑橘版续写提到了 "lemon zest and orange peel"，而算术任务则明确算出 "3^2 - 2, which is 7"——尽管从未要求模型展示计算过程。
- •**运动任务：**"Soccer" 与 "football"、"basketball" 等合理候选一起出现。

### **这些信号住在哪儿？**

为了回答这个问题，我们做了第二项测试，检查任务记录（transcript）的各个区域。在这项任务记录区域测试中，为了把「提示词理解」与「主动生成」区分开，我们把每份记录切成三个不同阶段：

- **用户消息 Prefill**（显式任务本身，如 “Think of a sport”）
- **Chat Template Prefill**（格式化上下文，含保留 token，如 “<|im_start|>”）
- **合格响应 Rollout 前缀**（概念家族首次显式出现之前模型生成的最初若干 token，如 “In order to answer this task…”，即“为了回答这个任务……”）

这一区分使得隔离「模型在处理提示词」与「模型在内部表征某个概念但尚未显式生成」成为可能。

图 10：提示词信号住在哪

这项任务记录区域测试由另外 40 份词表组成，并保留 top-50 结果。它与我们此前做的 20 词表测试以及 top-10 的 Kimi 到 Qwen 迁移结果是分开的。该测试问的是：每份记录的各个区域——用户消息、chat template 添加的格式化内容、以及某词首次出现在可见文本之前的响应部分——是否至少有一个列表词出现。我们使用简单的二元聚合度量，指示指定区域内任意位置是否存在静默信号。Kimi 在用户消息区域命中 40/40，chat template 区域 40/40，合格响应前缀区域 24/24。

注：24/24 的由来是，在 16/40 的情况下，模型直接作答、没有任何冗长前缀。例如被问 “Think of a sport” 时，它只回答 "Soccer"。

Qwen 几乎完全相同：39/40、39/40 和 23/24。换句话说，“说出之前已可读”这一模式不仅出现在主动生成的中途，也出现在模型消化提示词的时候。

图 11：Kimi 与 Qwen 的结果

### **方法在哪里失效：一个分词器问题**

J-Lens 检查的是单个 token，而对 Qwen 来说，它无法把 "21" 或 "42" 恢复为统一的匹配，因为 Qwen 把这两个数各自拆成两个 token。这暴露了该方法论的一个局限，可以设想未来工作去拟合一个多 token 的 Lens。

由于 Lens 这一多 token 缺陷，Qwen 在该片段的「中间结果」探针家族上只得 0/3，尽管其在所有其他家族上表现正常。

图 12：方法失效示例

### **跑通这件事需要什么成本**

每段文字 7,168 次反向评估，14 段合计 100,352 次有效反向评估。一段文字在一个 8×B300 节点上约需 5.25 小时。乘以 14 得到总工作量：约 74 节点小时，即 592 GPU 小时——而不是多主机并行运行的墙钟时间。

### **结论**

我们的结果表明：内部状态早在概念被写入上下文窗口之前，就已经携带了任务相关的概念。

开放权重模型让研究者能够用自己的拟合探针对模型进行读数、复现测量并检验这些信号的作用。下一步是超越单 token 匹配。使用 J-Lens 探针跨多个不同提示词，我们发现开源模型可以有不同的内部思路轨迹，却仍得出任务特定的结论。通过同时测试 Kimi 和 Qwen，我们还确认这种行为可以跨不同家族和模型架构复现。

你自己也能复现这类开源模型研究！“说出之前已可读”的信号出现在两个可公开获取的模型中，它们来自不同的实验室、不同的架构，各自有独立拟合的 Lens。只有当权重足够开放、可供探针探测时，才能得到这类结果。[Kimi K3](https://fireworks.ai/models/fireworks/kimi-k3) 和 [Qwen 3.5](https://fireworks.ai/models?providers=Qwen) 都已在 Fireworks 上提供推理与训练，是非常好的协作模型！
