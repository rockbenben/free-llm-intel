[Fireworks Nexus](https://fireworks.ai/nexus) 使工程团队能够在他们已经使用的工具中放弃领先的开放模型，并在不牺牲速度或质量的情况下将支出减少一半。该解决方案包括 FireRouter，这是市场上第一个缓存感知路由器，它在速度和成本方面有很大的不同。

今天，我们推出 [FireRouter with Opus](https://fireworks.ai/models/fireworks/firerouter-opus)，它针对 Opus 系列进行了优化，现在在我们的 CLI 中提供，并且首次作为独立路由器模型提供。任何 Fireworks 帐户都可以将其作为无服务器端点，就像任何其他模型一样。

经过一个多月的内部 A/B 测试，与单独使用 Opus 相比，FireRouter 与 Opus 一起执行编码任务的准确率达到 98.1%，成本降低了 57%。

## FireRouter 是什么

如今，带有 Opus 的 FireRouter 在 Claude Opus 5.5、GLM 5.3 和 GLM 5.3 Flash 之间进行路由

每个点击 FireRouter 的用户回合都会根据集合中的每个模型适合该任务的程度进行评估。然后，它会估计每个模型处理任务的成本，包括提示缓存的成本以及丢失它以切换到不同模型是否值得。最后，它会选择最能平衡质量与成本的模型。

目前，用户轮流将在 Claude Opus 5.5、GLM 5.3 和 GLM 5.3 Flash 之间路由。随着新型号和版本的推出，模型集将发生变化。

＃＃ 结果

我们的内部编码流量位于随机分配给带有 Opus 的 FireRouter 或仅限 Opus 的对照组的会话上，跨相同的工作负载和用户。

每次会话成本下降 57%（±19 个百分点），从 15.36 美元降至 6.63 美元。

为了对准确性进行评分，我们验证了智能体是否完成了工作，是否得出了正确的答案，以及用户是否需要在下一回合进行任何更正。

带有 Opus 的 FireRouter 的分级转弯得分为 78.7%，而仅使用 Opus 的 FireRouter 得分为 80.2%，即总体准确度为 98.1%。

我们的大部分流量来自内部编码工作，其中开放模型可以处理许多常规转弯。 FireRouter 的缓存感知路由权衡了切换模型所节省的成本与丢失缓存命中的成本。结果是，FireRouter 和 Opus 的缓存命中率为 94.2%，而单独使用 Opus 的缓存命中率为 97.8%——这是一个经过深思熟虑的小权衡，大大降低了总体成本。
