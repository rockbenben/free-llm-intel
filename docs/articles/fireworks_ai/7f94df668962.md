**TLDR；** DeepSeek V4 Pro 0813 在我们的 SWE-Bench 和 LiveCodeBench 运行中登顶，每个已解决任务的成本只有 Fable 5 的三分之一，而且事实证明它是比 Kimi K3 更好的路由搭档。训练已上线。

上周我们在 Fireworks 上启用了 Deepseek，提供 serverless endpoint、专用部署和训练支持。该模型提供 1M token 上下文窗口，具备原生工具调用和保留推理历史的能力，面向长周期 agentic 工作负载。

我们用与[七月评测 Kimi K3](https://fireworks.ai/blog/kimik3-fable)相同的评测套件跑了 DeepSeek V4 Pro 0813。我们在四个 benchmark 族上把 Deepseek 与 Kimi K3、Fable 5 做对比：SWE-Bench Verified、LiveCodeBench v6、Aider Polyglot v1 和 Terminal-Bench 2.1。在这套组合评测中，Deepseek V4 Pro 在四族中的两族上是最强的单一模型。

在标准代码任务上，Deepseek V4 Pro 相对 Fable 5 有巨大的成本优势：SWE-bench 上每个已解决任务 $0.309（Fable 5 为 $0.808），LiveCodeBench 上为 $0.040（对比 $0.225）。

在 Terminal-Bench 上，关于 Fable 5 的表现和成本有两点值得注意：

- Fable 5 得分相同，但需要多次尝试，使每任务成本达到 $16.85。我们保留这个设置，以便与已发布的 K3 benchmark 保持一致。
- 按首次尝试计分，Fable 5 达到 74.2%，而每任务成本跃升至 $75.40。内部评估采用这一首轮运行的基线。

Deepseek V4 Pro 不够强的地方是多语言广度。正如我们在[K3 与 Fable 5 的对比分析](https://fireworks.ai/blog/kimik3-fable)中所展示的，模型的专长在不同生态之间差异很大。在 Aider Polyglot 上，V4 Pro 在 Rust（90.0%）和 C++（80.8%）上依然很强，但在 Java 上掉到 48.9%（Java 是最大的一块，共 47 个任务），而 Fable 5 为 74.5%。

Java 表现几乎解释了整个差距。如果你运行的是以 Java 为主的代码库，只用单一模型可能会遇到瓶颈。正如我们在 K3 测试中发现的，多模型方案优于单模型架构。把任务动态路由到专家模型，能以极低的成本换来更好的整体准确率。

## 路由会改变你的账单

我们在 DeepSeek V4 Pro 和 Fable 5 之间测试了 oracle 路由，为每个任务挑选更好的模型，平局时倾向于成本更低的那一个。快速回顾一下：oracle 路由是一种衡量最佳理论表现的方法——让任务经过每个模型运行，然后挑出成本更优的正确选项，以此确定成本与性能的上限。

在 409 个任务的合并队列上，路由达到 92.4%，而单用 Fable 5 为 86.6%。这比前沿模型高 5.9 个百分点，每任务成本 $0.279，而 Fable 为 $4.510。成本低十六倍，而且更好。而 86.3% 的任务被路由到 V4 Pro，这才是真正的发现：贵模型是例外，而不是默认。

每一个 V4 Pro 配对都胜过对应的 K3 配对。LiveCodeBench 达到 94.0%（对比 92.0%），Aider 达到 93.3%（对比 91.6%），合并队列落在 92.5%（对比 91.1%）。尽管 K3 在 CyberGym 上得分更高，V4 Pro 仍是更好的路由搭档，因为 V4 Pro 的胜场正好落在 Fable 5 失手的任务上。

值得说明 oracle 路由是什么：它是事后计算出的上限，而不是你今天就能部署的策略。真实 router 只能拿到其中一部分。这一点很重要，因为差距的大小告诉你还有多少空间。

## Deepseek v4 Pro 的训练现已可用

想构建针对你特定领域的专业化模型？DeepSeek V4 Pro 的训练已在 Fireworks 上线，完整支持 SFT、DPO 和 RFT。你获得的是前沿级的基础设施，可以在不撞上人为平台限制的情况下推高模型表现。训练跑完之后，一次点击就能把微调后的 checkpoint 部署到生产。因为训练和 serving 运行在同一套协同优化的后端上，你的生产表现每次都与训练基准一致。

## 关于 Deepseek 的 Harness，你应该知道的事

Deepseek 自己发布的 benchmark 运行使用的是 DeepSeek Harness（dsh），这是一个原生 agent runtime，从模型适配器一直处理到核心执行循环。它说的是 Deepseek V4 的原生工具语义，而不是通过通用的 OpenAI 风格接口来路由调用。对这个模型，Deepseek 也还没有发布标准 chat template，所以微小的序列化不匹配就可能悄悄拉低模型表现。

在 Fireworks 上测试时，我们发现"minimal-first"的配置比直接跳到完整的标准目录能带来一致得多的工具调用。先从最基础的 bash 和编辑器界面开始，再提升到 dsh 标准，能让 DeepSeek V4 Pro 更接近 DeepSeek 在自己 benchmark 运行中使用的配置。

## 开始使用

无论你是想降低自主 agent 的单位成本、运行零拒答的安全审计，还是构建领域专用模型，DeepSeek V4 Pro 都以每个已解决任务一半的成本提供前沿级能力。在 840 次被追踪的对抗性安全运行中，它录得零拒答和零输出长度截断，保证你的 agent 能完成工作负载，不会撞上意外的 guardrail。

下面是你今天就能开始构建的方式：
