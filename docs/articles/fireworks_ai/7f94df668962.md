**TLDR；** DeepSeek V4 Pro 0813 在我们的 SWE-Bench 和 LiveCodeBench 运行中表现最佳，每个解决任务的成本是 Fable 5 的三分之一，并且事实证明它是比 Kimi K3 更好的路由合作伙伴。培训是直播的。

上周，我们在 Fireworks 上启用了 Deepseek，提供无服务器端点、专用部署和培训支持。该模型提供了一个 1M 令牌上下文窗口，具有本机工具调用和保留的推理历史记录，针对长期代理工作负载。

我们通过[7 月份的 Kimi K3](https://fireworks.ai/blog/kimik3-fable) 所用的相同评估套件运行 DeepSeek V4 Pro 0813。我们在四个基准系列中针对 Kimi K3 和 Fable 5 评估了 Deepseek：SWE-Bench Verified、LiveCodeBench v6、Aider Polyglot v1 和 Terminal-Bench 2.1。 Deepseek V4 Pro 是对四个系列中的两个进行的联合评估中最强的单一模型。

Deepseek V4 Pro 在标准代码任务上为《神鬼寓言 5》带来了巨大的成本优势，在 SWE-bench 上每个解决的任务运行 0.309 美元（相对于《神鬼寓言 5》的 0.808 美元），在 LiveCodeBench 上运行 0.040 美元（相对于 0.225 美元）。

在 Terminal-Bench 上，关于《神鬼寓言 5》的性能和成本，有两点需要注意：

- 《神鬼寓言 5》得分相同，但需要多次尝试，使任务成本达到 16.85 美元。我们展示此设置是为了与我们发布的 K3 基准保持一致。
-《神鬼寓言 5》首次尝试的得分就达到了 74.2%，而每项任务的成本则跃升至 75.40 美元。内部评估依赖于该初步运行基线。

Deepseek V4 Pro 的不足之处在于多语言广度。正如我们在[K3 分析与寓言 5](https://fireworks.ai/blog/kimik3-fable) 中所演示的，模型专业化因生态系统而异。在 Aider Polyglot 上，V4 Pro 在 Rust (90.0%) 和 C++ (80.8%) 方面保持强劲，但在 Java 方面下降至 48.9%（47 项任务中最大的部分），而《神鬼寓言 5》的得分为 74.5%。

Java 性能几乎占据了全部差距。如果您运行 Java 密集型代码库，并且使用单一模型，则可能会遇到瓶颈。正如我们通过 K3 测试发现的那样，多个模型是比使用单模型架构更好的解决方案。将任务动态路由到专业模型可以以较低的成本获得更高的整体准确性。

## 路由更改您的账单

我们测试了 DeepSeek V4 Pro 和 Fable 5 之间的预言机路由，为每个任务选择更好的模型，并打破与成本更低的模型的联系。快速回顾一下：预言机路由是一种通过每个模型运行任务来测量最佳理论性能的方法，然后选择成本优化的正确选项来建立成本和性能上限。

在 409 项任务的综合队列中，路由命中率为 92.4%，而仅《神鬼寓言 5》的命中率为 86.6%。这比前沿模型好 5.9 个百分点，每个任务的价格为 0.279 美元，而 Fable 的价格为 4.510 美元。成本降低十六倍，效果更好。 86.3% 的任务都会路由到 V4 Pro，这是真正的发现：昂贵的型号是例外，而不是默认型号。

每个 V4 Pro 配对都优于同等的 K3 配对。 LiveCodeBench 的得分为 94.0%，对 92.0%，Aider 的得分为 93.3%，对 91.6%，合并后的得分为 92.5%，对 91.1%。尽管 K3 在 Cyber​​Gym 上的得分更高，但 V4 Pro 是比 K3 更好的路由器搭档，因为 V4 Pro 的胜利落在了神鬼寓言 5 未完成的任务上。

值得注意的是，预言机路由是什么：事后计算的上限，而不是您今天可以部署的策略。真正的路由器捕获其中的一小部分。这很重要，因为间隙大小告诉您存在多少净空。

## Deepseek v4 Pro 培训现已推出

想要构建适合您的特定领域的专门模型吗？ DeepSeek V4 Pro 训练在 Fireworks 上实时进行，完全支持 SFT、DPO 和 RFT。您可以获得前沿级基础设施来提升模型性能，而不会遇到人为的平台限制。运行完成后，您只需单击一下即可将微调的检查点部署到生产环境中。由于培训和服务在同一共同优化的后端上运行，因此您的生产性能每次都与您的培训基准相匹配。

## 关于 Deepseek 安全带您应该了解的内容

Deepseek 自己发布的基准测试运行使用 DeepSeek Harness (dsh)，它是一个本机代理运行时，处理从模型适配器到核心执行循环的所有内容。它使用 Deepseek V4 的本机工具语义，而不是通过通用 OpenAI 风格的接口路由调用。对于这个模型，Deepseek 也没有提供标准的聊天模板，因此小的序列化不匹配可能会默默地降低模型性能。

在 Fireworks 测试过程中，我们发现“最小优先”设置比直接跳转到完整标准目录产生更加一致的工具调用。从裸 bash 和编辑器界面开始，然后升级到 dsh 标准，使 DeepSeek V4 Pro 更接近于其自己的基准测试运行中使用的设置 DeepSeek。
