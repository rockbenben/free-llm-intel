## TL;DR

- •Harvey [最近发布了其首个模型](https://www.harvey.ai/blog/post-training-update-harvey-tenet) Tenet——与 Fireworks 协作，以 Kimi K3 为基座，用[异步强化学习](https://docs.fireworks.ai/fine-tuning/training-api/introduction)在 Fireworks Training API 上为长视野法律工作做后训练。
- •初步工作在性能与成本效率上都显示出可观的结果：Tenet 完成的保留（held-out）Legal Agent Benchmark（LAB）任务几乎是基座 Kimi K3 的两倍。
- •Tenet 的性能增益能迁移到模型训练期间从未见过的智能体基准上，且法律知识基准上没有显著退化。

## LAB 度量什么，为什么 all-pass 是标尺

法律工作是复杂而严苛的。它要求律师综合信息、运用判断，并按最高标准产出工作成果。

[Legal Agent Benchmark（LAB）](https://www.harvey.ai/blog/introducing-harveys-legal-agent-benchmark)正是为达到这些高标准而建。LAB 把智能体放进带真实法律文档与工具的沙箱工作区，要求它们产出成品交付物：备忘录、带批注的合同、尽调摘要。随后由一个 LLM 评审打开每份交付物，对照几十条具体标准评分。

只有满足每一条标准的交付物才算通过。要紧的指标是 all-pass：端到端越过全部标准的任务占比。一个模型平均分可以很好看，却仍可能栽在一条会破坏整份交付物的标准上。

## 结果

### 性能

Harvey Tenet 在 LAB 上取得 19.7% 的 all-pass，基座 Kimi K3 为 10.8%；在 Lab Contracts 上为 11.3%，基座 Kimi K3 为 9.3%——分别提升 9 和 2 个百分点，完成的保留 LAB 任务接近两倍。Harvey 报告这些改进建立在与答案细节和引用相关的广泛标准增益之上。Tenet 在 Lab Contracts 上达到 state-of-the-art，在 LAB 上排名第二。

### 泛化

增益迁移到了模型训练期间从未见过的智能体基准。相对基座 Kimi K3，Tenet 在 [Mercor 的 Apex Agents](https://www.mercor.com/apex/apex-agents-leaderboard/corporate-lawyer-agent/)（Corporate Law）上从 58.8% 提升到 74.0%，在 [Crosby 的 Redline Bench](https://intelligence.crosby.ai/) 上从 49.3% 提升到 55.5%。两个基准都没有出现在训练中，而且 Redline Bench 运行的 harness 与模型训练所用的完全不同。训练中学到的行为跨过了基准与 harness 的双重差异。

### 极小退化

Tenet 在法律知识与参数化推理（而非智能体能力）的基准上稳住了表现，包括 LegalBench、CUAD、MAUD 和 Mercor 的 Apex-v1。以基座 Kimi K3 为参照衡量，智能体能力的提升没有以牺牲基座模型更广泛的法律理解为代价。

### 成本

此外，性能没有附带成本惩罚。Harvey Tenet 每个 LAB 任务花 $5.92，基座 Kimi K3 为 $5.62——基本持平，而完成的任务数接近两倍。两件事让这成为可能：(1) 开放权重的每 token 定价，(2) 下文所述的奖励塑形。基线分数来自 Vals LAB 排行榜。

## 运行背后的基础设施

这个规模的后训练是一个基础设施问题。每个 checkpoint 数万次长视野 rollout，每一次在真实沙箱里跑过 50 轮、10 万个生成 token，对训练栈施加了短视野负载不会造成的压力。

对这类强化学习，Fireworks 平台的两个特性最要紧。

### 数值对齐

我们把训练栈与推理栈一起构建，因此训练与服务共享同一套数值语义。你后训练出的那个 checkpoint 就是运行的那个。这不只是运维上的便利。当训练与推理在数值上分叉，这种分叉会以 token 截断的形式浮现，越过某个阈值后就是运行中段的奖励崩塌。压低训练-推理之间的 KL，正是让长 RL 运行保持稳定之道。

### 批不变性

无论同一批里还有什么，请求返回完全一致的结果——这靠注意力归约顺序、稀疏注意力 token 选择、专家矩阵乘 kernel 选择、路由打平处理和跨 GPU all-reduce 上的确定性选择实现。temperature 为 0 的可复现性意味着一个评估结果是 checkpoint 的属性，而不是它恰好落入的那个批次的属性。

由于训练与服务在同一平台上，一个有前景的 checkpoint 可以在训练继续进行时被晋升并验证，然后不离平台直接移入生产。
