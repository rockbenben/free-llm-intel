# Ray 中的模型批量推理：Actor、ActorPool 与 Dataset

作者：Eric Liang、Jules S. Damji、Zhe Zhang 和 Richard Liaw | 2022 年 11 月 3 日

本文介绍在 Ray 中做[批量推理](https://docs.ray.io/en/latest/ray-overview/use-cases.html#batch-inference)（分布式模型评估）的三种方式：从低层的 Ray Actor 到高层的 Ray Data。我们会看到低层 Ray API 让你精确控制 Ray 执行计算的"怎么做（How）"，而 Ray 的库让你只声明"做什么（What）"——获得开箱即用的可扩展体验。

*Ray 中批量推理的 3 种方式。*

从一个本地 Python 类定义你的训练好的模型出发，Ray 让用其中任何一种方式并行化模型推理都很容易。接下来我们会以 NYC 出租车数据模型为例，走一遍在 Ray 上做并行模型推理的示例。

## 引言

批量推理指对一批输入观测生成模型预测。模型可以是回归模型、神经网络，或干脆是一个 Python 函数。当模型很贵或待评估数据很大时，批量推理能从 Ray 扩展中获益。Ray 常被用于在单机和数千 GPU 的集群上并行化批量推理作业。

在任何系统里搭建分布式批量推理，都需要以下步骤：

1. 创建模型的若干副本。在 Ray 中，副本以 Actor（即有状态的[1]进程）表示，可以分配到 GPU 并持有实例化的模型对象。

2. 并行地把数据喂入这些模型副本，并取回推理结果。

来看几个例子：先从低层的开始，建立对 Ray 执行计算"怎么做"的理解，然后再展示高层 API。

## Ray Core 中的可扩展批量推理

[Ray 的 Actor API](https://docs.ray.io/en/latest/ray-core/actors.html)是批量推理的天然原语。先看如何用 Actor 直接分布式地做批量推理。为简化向大量同类 Actor 分发任务的工作，Ray 还提供了 [ActorPool](https://docs.ray.io/en/latest/ray-core/package-ref.html#ray-util-actorpool) 工具。

## 用 Ray Actor 从零开始

所有这些例子假设 S3 的 `s3://air-example-data/ursa-labs-taxi-data/ `路径下有大量记录，我们要用自定义模型对其做推理。先定义一个简单的"预训练"模型，以及一个可由模型引用构造的 Ray Actor：

```
1import pandas as pd
2import pyarrow.parquet as pq
3import ray
4
5def load_trained_model():
6    # A fake model that predicts whether tips were given based on
7    # the number of passengers in the taxi cab.
8    def model(batch: pd.DataFrame) -> pd.DataFrame:
9        # Give a tip if 2 or more passengers.
10        predict = batch["passenger_count"] >= 2 
11        return pd.DataFrame({"score": predict})
12    return model    
13
14@ray.remote
15class NYCBatchPredictor:
16    def __init__(self, model):
17        self.model = model
18
19    def predict(self, split_path: str):
20        # read each split and convert to pandas
21        df = pq.read_table(split_path).to_pandas()
22
23        # do the inference with our model and return the result
24        result = self.model(df)
25        return result
```

用 Ray 把它并行化：先把模型放进 Ray 对象存储，然后启动若干个预测 actor：

```
1model = load_trained_model()
2model_ref = ray.put(model)
3actors = [NYCBatchPredictor.remote(model_ref) for _ in range(5)]
```

Ray 会自动取回并解引用传给 actor 构造函数的 `model_ref` 参数，因此 NYCPredictorActor 看到的是物化后的模型对象而非引用。接着定义输入文件：

```
1input_splits = [f"s3://anonymous@air-example-data/ursa-labs-taxi-data/downsampled_2009_full_year_data.parquet"
2                f"/fe41422b01c04169af2a65a83b753e0f_{i:06d}.parquet"
3                for i in range(12) ]
```

我们可以用一个 `ray.wait` 循环向这些 actor 分发任务并取回结果。基本上，我们希望保持一定数量的任务"在飞"给 actor：取回就绪的结果，并在 actor 完成上一份工作后立即派发新任务：

```
1def process_result(r):
2    print(f"Predictions dataframe size: {len(r)} | Total score for tips: {r['score'].sum()}")
3
4idle_actors = actors.copy()
5future_to_actor = {}
6while input_splits:
7    if idle_actors:
8       actor = idle_actors.pop()
9       future = actor.predict.remote(input_splits.pop())
10       future_to_actor[future] = actor
11    else:
12       [ready], _ = ray.wait(list(future_to_actor.keys()), num_returns=1)
13       actor = future_to_actor.pop(ready)
14       idle_actors.append(actor)
15       process_result(ray.get(ready))
16
17# Process any leftover results at the end.
18for future in future_to_actor:
19    process_result(ray.get(future))
```

运行会产生类似这样的输出：

```

2Predictions dataframe size: 136394 | Total score for tips: 43234
3Predictions dataframe size: 141981 | Total score for tips: 45188
4Predictions dataframe size: 148108 | Total score for tips: 47713
5Predictions dataframe size: 143087 | Total score for tips: 45510
6Predictions dataframe size: 144014 | Total score for tips: 45175
7Predictions dataframe size: 133932 | Total score for tips: 42175
8Predictions dataframe size: 145976 | Total score for tips: 48036
9Predictions dataframe size: 142893 | Total score for tips: 46112
10Predictions dataframe size: 156198 | Total score for tips: 49909
11Predictions dataframe size: 139985 | Total score for tips: 44138
12Predictions dataframe size: 141062 | Total score for tips: 46360
```

上面的例子实现了（1）把任务分布式地分发给大量 actor，（2）流式地处理 actor 结果并派发新工作。对一个分布式程序来说代码不算多，但还能更好！Ray 提供了一个 ActorPool 工具，让这件事轻松得多。

### 把 ActorPool 用作批量推理的工具库

假设我们已经创建了 actor 列表，可以把它包进 ActorPool 类：

```
1from ray.util.actor_pool import ActorPool
2actor_pool = ActorPool(actors)
```

要处理数据，只需调用 `actor_pool.map`。实际上我们用 `.map_unordered` 获得稍高的效率，因为我们不关心结果顺序：

```
1def actor_call(actor, data):
2    return actor.predict.remote(data)
3
4for result in actor_pool.map_unordered(actor_call, input_splits):
5    process_result(result)
```

这段代码与最初的循环逻辑完全一致，只是把繁琐的 future 管理藏进了一个便利的工具类。你可以查看 `ActorPool` 的[源码](https://github.com/ray-project/ray/blob/7d5df19275519e17e0cda05d551a1da934fdf286/python/ray/util/actor_pool.py#L247)，看看它底层熟悉的 `ray.wait` 原语。

## 常见优化

上面代码有几处未优化的地方值得指出。首先，我们一次只分发一个文件切片：切片太小（例如在 GPU 上）可能低效，太大又可能 OOM。此外，你可能想把任务提交流水线化（同时向一个 actor 发多个在飞任务），并并行化数据拉取与必要的预处理。

我们可以在上面示例代码的基础上实现这些优化——例如用 Ray 任务并行化数据拉取——但 [Ray Data](https://docs.ray.io/en/latest/data/data.html) 把这些优化内建了，还附带其他特性，例如为计算所用的 actor 池做动态自动扩缩。

以上要点总结如下：

1. 你可以用 Ray Actor 与 ActorPool 构建分布式批量推理。

2. 你可以精确控制 Ray 如何执行你的代码。

3. 你会理解 Ray 底层如何工作——任务、actor、对象与 `ray.wait` 等核心原语。

然而，这些优化都逼你自己实现常见的性能优化：你获得了控制权，也要求对 Ray 的内部了解。

但存在更好的方式：通过 [Ray Data](https://docs.ray.io/en/latest/data/data.html) 告诉 Ray 你要做什么，而无需深谙 Ray core 原语。这就是我们的下一个方法。

## Ray Data 中的可扩展批量推理

为分布式程序实现并测试优化可能既棘手又耗时。[Ray Data](https://docs.ray.io/en/latest/data/data.html) 的目标是为批量推理这类常见 ML 任务提供更高层的数据处理抽象，负责：

1. actor 池的动态自动扩缩。

2. 数据的自动批处理与流水线化。

3. 数据拉取与预处理的并行化。

*batch-inference-on-ray-data*

第一步，用 `ray.data.read_parquet` 把数据加载为 Ray Data 数据集：

```
1ds = ray.data.read_parquet(input_splits)
2
3# -> Dataset(num_blocks=12, num_rows=1710629, schema={vendor_id: string, pickup_at: timestamp[us], dropoff_at: timestamp[us], passenger_count: int8, trip_distance: float, pickup_longitude: float, pickup_latitude: float, rate_code_id: null, store_and_fwd_flag: string, dropoff_longitude: float, dropoff_latitude: float, payment_type: string, fare_amount: float, extra: float, mta_tax: float, tip_amount: float, tolls_amount: float, total_amount: float})
```

也可以用简单的变换 API（如 [map_batches](https://docs.ray.io/en/latest/data/performance-tips.html?highlight=map_batches#batching-transforms)）对 Dataset 做预处理。下面通过 Dataset 变换把 `num_passengers` 字段减 1.0：

```
1# Define our preprocessing function
2def preprocess(batch):
3    batch["passenger_count"] -= 1.0
4    return batch
5
6ds = ds.map_batches(preprocess)
```

继续定义要用的模型类（注意：我们实现类的 `__call__` 方法使其可调用，并指定目标方法）：

```
1class CallableCls:
2    def __init__(self, model):
3        self.model = model
4
5    def __call__(self, batch):
6        result = self.model(batch)
7        return result
```

最后，用 Dataset 的 `map_batches()` 函数把模型并行应用到 Dataset 上。我们可以指定传给模型的 batch size、GPU 资源，以及 Dataset 底层 actor 池的自动扩缩选项。

```
1results = ds.map_batches(
2    CallableCls,
3    num_gpus=0,
4    batch_size=1024,
5    compute=ray.data.ActorPoolStrategy(min_size=1, max_size=5),
6    fn_constructor_args=(model_ref,))
7# -> Dataset(num_blocks=12, num_rows=1710629, schema={score: bool})
```

与最初的版本相比，Ray Data 版本有几个优势：其一，允许对源数据进行并行读取与[预处理](https://docs.ray.io/en/master/data/transforming-datasets.html)。其二，Ray Data 库负责管理推理所用 ActorPool 的自动扩缩。其三，我们只用一组声明式键值参数声明了要做什么，而不是怎么做——避免了上面为指挥 Ray 如何并行与扩展而写的所有繁琐代码。

关于用 Ray Data 做批量推理场景的更多内容见[文档](https://docs.ray.io/en/latest/data/quickstart.html)。

## 结语

我们探索了在 Ray 中实现可扩展批量推理的三种方式，分别使用 Ray 的低层原语与 Ray Data 的高层表达性 API。每种方式各有优点。如果你想控制并决定 Ray 应如何执行批量推理，就用 ray 任务与 actor 或 ActorPool 工具；反之，如果你希望 Ray 代你管理扩展、分发与大规模推理，就用 Ray Data。

这些 API 彼此分层——底层都是 Ray 的任务、actor 与对象。按需选择即可。

要点在于：Ray Core 给你"怎么做"的控制权，把用 Ray 原语自行实现推理、理解 Ray 底层机制的责任交给你；而 Ray Data 凭借 `map_batches` API 提供自动扩缩、表达直观、易于理解的抽象来做大规模批量推理，后者还意味着更少代码与更简洁。

对更关心让模型规模化跑批量推理、而不关心中层原语与执行细节的数据科学家与机器学习从业者，Ray Data 是更称心的选项。
