# Ray Summit 2026：物理 AI、RL，以及承载它们的一切基础设施

作者：Philip Wang | 2026 年 9 月 8 日

8 月 24-26 日的 Ray Summit 2026 在旧金山 Marriott Marquis 汇集了 2,000 多名与会者，进行了两天的主题演讲、分组会议与动手培训，贯穿一条主线：

8 月 24-26 日的 Ray Summit 2026 在旧金山 Marriott Marquis 汇集了 2,000 多名与会者，进行了两天的主题演讲、分组会议与动手培训，贯穿一条主线：强化学习已从研究课题升级为生产工程问题，而把 RL 流水线粘合在一起的基础设施，其重要性如今不亚于它训练出的模型。

Ray 共同创造者、Anyscale 联合创始人 Robert Nishihara 在第一天开场时，为整场大会锚定了这一前提。当今驱动前沿 AI 的负载包含持续运行的 RL 训练循环、agentic rollout 和规模化物理仿真——这些全都需要横跨异构硬件的计算环境，需要在 CPU worker 与 GPU 池之间协调，需要在故障后恢复，而不强迫研究者从头重建编排层。

## 第一天主题演讲

### Lila Sciences：为科学构建规模化验证器

演讲人：Lila Sciences CTO Andrew Beam

Andrew Beam 从科学 RL 核心的验证器（verifier）问题讲起。RLVR 在编程与数学领域奏效，是因为这些领域有廉价、自动的验证器；但在生物、化学与材料文献中，只有约 5% 的论断能完全在 silico（计算机模拟内）判定。Lila 给出的答案是 AI Science Factory：一座位于剑桥、15,000 平方英尺的设施，把 AI 模型、把每台仪器包装到单一 API 之后的软件，以及昼夜不停运行实验的机器人结合起来——物理工作单元本身成为奖励信号。他们的模型 IRIS 跨蛋白质、RNA、小分子、催化剂与涂层训练，其中 RL 部分与 SkyRL 团队基于 Ray 联合开发。迄今的成果包括：CAR-T 项目以约低 30 倍的成本拿到非人灵长类药效数据（对比传统时间表）；设计并在体内测试了超过 100 万条 mRNA，对标领先临床基准；五周内（而非七个月）筛选了 719 种防护涂层合金。

### Torc Robotics：构建 AV 3.0

演讲人：Torc Robotics 负责人 Felix Heide

Felix Heide 展示了 AV 3.0——Torc 的安全自动驾驶卡车方案：感知与规划端到端学习，由仿真中的闭环 RL 驱动策略改进。城市驾驶基准正在饱和，难题已经转移：卡车运输需要超长距离探测、高速自车速度，以及现有数据集本未覆盖的轨迹长度。Torc 开发的 TruckDrive 数据集填补了这一空白。他们的规划模型 Alpamayo 在 6.4 秒时域上 zero-shot 的 min-of-6 平均位移误差为 5.84 米，加入物理 AI 推理轨迹后降到 0.87 米。流水线的每个阶段都运行在一个 Ray 集群上，由 Ray Data、Ray Train、Ray Serve 与 Ray Actors 在 Anyscale 的 CPU 节点、Kepler GPU 与 Blackwell GPU 之间协调。把五套彼此独立的训练系统合并到这一引擎的结果：每个训练作业的数据量提升 20 倍；在更便宜的算力上 epoch 快 3 到 3.4 倍；GPU 利用率从 30-40% 提升到约 90%；每周运行 10 亿英里仿真里程。

### Inferact 与 vLLM 社区

演讲人：Inferact 联合创始人兼 CEO、vLLM 的 Simon Mo

推理问题已长成组合爆炸问题。vLLM 社区如今要应对 1,000 多种硬件配置、5,000 多个模型，以及从单轮补全转向多轮 agentic 交互的持续扩展的负载模式。Inferact 团队与 vLLM 维护者说明了项目的投入方向：day-zero 硬件支持覆盖 NVIDIA Blackwell 与 Vera Rubin、AMD MI355X 与 MI455X、Google Ironwood 及未来的 TPU 世代。技术路线图包括采用扁平模型接口的 Model Runner V2、面向分离式服务的 llm-d 与 Dynamo，以及为削减入口层开销的 Rust 前端。拥有 3,000 多名贡献者的 vLLM 已成长为生态核心的开放推理基座之一，Nob Hill 厅的 vLLM 专场贯穿两天全部分组会议。

## 第二天主题演讲

### 用 Ray 构建与后训练开放模型：来自 NVIDIA Nemotron 的经验

演讲人：NVIDIA 应用深度学习研究副总裁 Bryan Catanzaro

Bryan Catanzaro 重新定义了"构建开放模型"的含义。Nemotron 是一整套体系：从 Lightning 到 Ultra 的模型 checkpoint、在 Hugging Face 发布的 9 万亿 token 数据集、用于 RL 对齐（NeMo-RL）、模型压缩（Minitron）与架构搜索的开放库——设计目标是让任何组织都能基于自己的数据构建专门的 AI。技术核心是规模化 RL：训练 Nemotron 3 Ultra（总参数 5,500 亿、激活 550 亿、预训练超 20 万亿 token）需要在 Ray Core 上同时协调超过 3,000 块 GPU 上的 rollout 引擎、环境 worker 与策略训练。一个具体发现：在 GB300 硬件上做拓扑感知放置，让互相通信的 actor 留在同一 NVLink domain 内，RL 迭代吞吐提升 13%，而硬件与模型均未改动。下游方面，CrowdStrike 报告安全调查完成速度快至 5 倍，Synopsys 验证 RTL 的时间快至 50 倍，CodeRabbit 在把预估服务成本砍半的同时提升了路由准确率。

### Bedrock Robotics：为建造工地提供高级自治

演讲人：Bedrock Robotics 技术基础负责人 Vincent Gonguet

Bedrock 在为工地设备构建自治能力。在这样的环境中，相机、激光雷达、GNSS、IMU 与 CAN 遥测持续产生传感器流，但任意时刻的"标签"并不预先定义。他们的核心洞见是：工地数据与任务定义的机器人数据根本不同——在 pick-and-place 系统里，任务在数据采集开始前就已确立；而在建筑工地上，弄清发生了什么（哪种操作动作、哪种地形交互、哪种故障模式）本身就是分布式计算图的输出，而 Ray 运行这张图。流水线的每个阶段——从传感器解码到 agentic 标注，再到感知与策略训练，再到仿真扫描——CPU 与 GPU 负载的搭配各不相同；他们的全栈仿真器每晚运行真实的自治栈，规模化生成地形、物理、传感器流与指标，让每次模型改动在抵达现场机器之前先经过仿真检验。

### 闭合循环：Periodic Labs 构建 AI 科学家

演讲人：Periodic Labs 联合创始人兼联席 CEO Liam Fedus

Periodic Labs 区分了"懂科学的 AI"与"懂如何做科学的 AI"，并围绕这一差异构建基础设施。他们的模型在科学过程本身上训练——假设、实验计划、工具调用、测量，以及测量带来的更新——而不是在已发表成果的成品记录上。在物理世界跑 RL 比在数字世界更难：rollout 以天而非分钟计，可并行的 agent 更少，奖励信号更嘈杂。Periodic 的应对是一套组合栈：编排用 Ray、训练用 Megatron、推理用 SGLang，之上是自研的 RL 循环层、GPU 同置沙箱与服务层。与开源基线相比的基准成绩：推理吞吐 3 倍、权重同步快 10 倍、权重转换快 30 倍、整体训练快 4.5 倍，作业内 P2P 数据平面比同类 SOTA 方案快 50 倍。

## 分组会议

### 在 GKE 上用 Ray 扩展 TPU 上的 LLM 负载：从预训练到推理

演讲人：Google Kubernetes Engine 软件工程师 Ryan O'Leary；Anyscale Ray Train 软件工程师 Lehui Liu

Ryan 与 Lehui 介绍了 TPU 作为 Ray on GKE 一等公民加速器的现状。两个新 API 让 TPU 拓扑管理在规模下变得可控：SlicePlacementGroup 用于预留和编排整个专用 TPU slice，SubslicePlacementGroup 用于在不物理重配集群的情况下把大的物理拓扑动态切成更小子集。Ray Train 在多 slice 配置下同时支持 JAX 与 PyTorch，内建 worker 故障的弹性恢复与抢占信号处理。服务侧，Ray Serve 搭配 vllm-tpu 现已支持单机与多机 TPU 推理及自动扩缩；TPU profiling 直接集成进 Ray dashboard，无需外部工具即可暴露编译死锁、设备延迟与内存碎片。

### Lightning 联合 vLLM、Verda、Novita 与 Anyscale 谈 agentic 服务

演讲人：Embedded LLM 首席软件工程师、vLLM 维护者 Tan Tun Jian；Anyscale 软件工程师 Jeffrey Wang；Verda MLOps 工程师 Ananth Mahadevan；Novita 资深 Kernel 开发工程师 Danny An

Tan Tun Jian 与团队展示了 Agentic API——一个 Rust 驱动的 serving 层，填补一个特定空缺：vLLM 负责执行模型推理，但一个 agent 轮次还需要恢复对话历史、跨多次模型调用执行工具循环、持久化状态让下一个请求能接着上一个停止的地方继续。没有这一层，每个 agent 客户端都要各自搭建这套基础设施。Agentic API 把它作为共享服务提供，同时支持 OpenAI Responses API 与 Anthropic Messages API——这意味着 Codex 与 Claude Code 可以直接指向 vLLM 服务的开放模型，而无须各自管理状态层。MCP 与网页搜索在网关内运行；函数调用返回给客户端执行，用 continuation ID 继续。Agentic API v0.1.0 在 Ray Summit 发布，已上架 crates.io。

### Microsoft AI 的 Ray 扩展实践

演讲人：Microsoft AI 技术专员 Cheng Liu、Paweł Bęza 和 Shaowei Su

Microsoft AI 团队在横跨 Kubernetes 与 Slurm 双调度器、统一 GPU 机群的共享 Ray 底座上运行数据生成、预训练与 RL。其核心贡献是 RELAY——一个 Ray GCS 的批处理代理，针对 Ray Client proxy 在 MAI 运作规模下会变得严重的瓶颈。旧技术栈下，actor 创建时间从 8,000 worker 时的 42.6 秒劣化到 32,000 时的 89.4 秒；同一区间的稳态 RPC P99 从 18.3 秒涨到 55.3 秒。RELAY 把两条曲线都压平了：创建时间在全区间稳定在 32.7 到 34.5 秒（32,000 worker 时快 2.85 倍），稳态 RPC 稳定在约 3.6 秒（32,000 时快 16.4 倍），分层 relay 树还把 driver 侧开销从 O(K×S) 降到 O(S)。

### 在 Ray 上构建虚拟生物学平台：Recursion 的多模态药物发现引擎

演讲人：Recursion 机器学习工程师 Aleksandar Djuric 与 Ayla Khan

Recursion 展示了 Ray 如何垫在其整个科学循环之下。跨模态嵌入流水线整合基因表达、表型组学与转录组学数据；预测化学作业训练小分子性质模型并回填化合物评估；一个构建在 FastAPI 与 Ray Serve 之上、运行于 Anyscale 的生产在线服务为 Boltz-2 预测蛋白质结构与配体结合亲和力——输入是蛋白序列与配体化学结构。他们的 Virtual Cells 工作（训练模型预测未见细胞扰动的表型与转录谱）用 Ray 做分布式训练扫描、跨 checkpoint 与细胞类型的并行评估、跨加速器的并行数据加载。他们最终确立的关键架构原则是：把工作负载而非集群当作工作单元，路由决策基于成本、可用性与数据局部性。

### 生产中的 Ray：Spotify Hendrix 平台的工程教训

演讲人：Spotify 平台工程师 Aamir Anwar、Staff 机器学习工程师 Shawn Lin

Hendrix 是 Spotify 覆盖完整模型生命周期的 ML 平台，运行在跨多个 GKE 集群与区域的共享 GPU 机群上，各团队在自己的 namespace 中彼此隔离。过去一年，平台支持团队数增长 2.5 倍、GPU 算力增长 30 倍，每月 GPU 时超过 100 万，同时每月运行约 21,000 个批量 LLM 作业。Aamir 与 Shawn 走查了 Ray 上可组合的训练工作流：Ray Data 负责无状态、可 pickle 的数据集阶段；Ray Train 用 TorchTrainer 包装自定义循环，循环自身持有前向计算；评估流水线则在 CPU worker 上串接 Ray Data 处理器，向 vLLM 与 SGLang sidecar worker 组发异步请求。他们还分享了两种集群设计模式：单集群多运行时——每个 worker 池自带容器镜像，配一个轻量 Ray sidecar；以及 workflow 感知弹性——在一次训练运行内伸缩资源。

### Capital One 用统一 KubeRay 基础设施扩展巨型 Transformer 训练

演讲人：Capital One 管理副总裁 Maulin Patel，机器学习工程师 Raja Chawat 与 Yifei Wang

Capital One 的 ML 团队为表格化金融事件序列构建 Transformer，撞上经典的扩展难题：5 亿多条记录、3.5TB 数据、512 个时间步、每步数百特征——一个训练 epoch 要 32 小时，瓶颈在数据加载而非计算。解法是统一的 KubeRay 技术栈：Ray Data（惰性分布式 Parquet 加载、零拷贝分片传递）、Ray Train（TorchTrainer 跨 64 个 GPU worker、自动故障恢复）、Ray Tune 搭配 Optuna 的 TPE 采样器与 ASHA 剪枝跑 200 个并发超参数实验。HPO 墙上时间从 3-5 天降到约 4 小时，提速 16 倍；完整 3.5TB 数据端到端流过流水线，阶段之间零次 S3 中转。
