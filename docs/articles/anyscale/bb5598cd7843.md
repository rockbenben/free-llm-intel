# 用 Ray 以创纪录时间训练一百万个机器学习模型

作者：Eric Liang 和 Robert Nishihara | 2022 年 12 月 17 日

Ray 与 Anyscale 正被 Instacart 这样的公司用于把机器学习训练负载（常常是需求预测）相比 Celery、AWS Batch、SageMaker、Vertex AI、Dask 等工具提速 10 倍。

本文聚焦**多模型训练**的扩展。虽然大部分热度围绕大模型训练，但近年来，越来越多公司发现自己需要训练和部署大量较小的机器学习模型——动辄数百或数千个。

我们的团队服务过数百家寻求规模化生产 ML 的公司，本文旨在介绍多模型训练的动机与一些最佳实践。使用本文介绍的方法，各公司相比 Celery、AWS Batch、AWS SageMaker、Vertex AI、Dask 等框架取得了数量级的性能与扩展性提升（例如 [Instacart 的 12 倍](https://www.youtube.com/watch?v=3t26ucTy0Rs)、[Anastasia 的 9 倍](https://www.anyscale.com/blog/how-anastasia-implements-ray-and-anyscale-to-speed-up-ml-processes-9x)）。

本文涵盖：

- 为什么公司在做多模型训练
- 如何用 Ray 训练多个模型
- 让高效多模型训练成为可能的 Ray 特性

## 为什么要训练许多 ML 模型？

虽然机器学习的前沿应用正带来模型规模的爆炸，但对多模型的需求横跨各行各业。

举几个例子：

- **Instacart 按地理分区的模型：** Instacart 把机器学习用于五花八门的任务：配送 ETA 预测、配送员供给规划、购物者路径优化模型等。每个用例都为每个分区训练一个模型——分区常常是邮编这样的地理位置，另外还会为一天中的不同时段等属性分别训练。这产生了数万个模型。采用本文的方法，[Instacart 把这些模型的训练时间相比 AWS Batch 与 Celery 缩短 12 倍](https://www.youtube.com/watch?v=3t26ucTy0Rs)——从天级降到小时级。
- **电商搜索与排序：** 我们合作的电商公司把机器学习从查询建议用到排序、个性化。最重要的用例之一是商品分类：网站上每件新商品都要打上成百上千个属性标签（柔软、绿色、厨房、节日……），常常基于商品图片。这些属性用于改善商品搜索。为每个属性用一个模型是非常普遍的做法，导致被训练和部署的模型数量爆炸。
- **按客户、按产品的预测与建模：** 我们合作的一家 B2B 分析公司为每个客户训练模型来预测增长与流失，因此需要频繁重训并重新部署数千个模型。另一家跨国制造企业为数万个产品中的每一个训练预测模型。采用本文方法，两家公司相比原有方案都取得了显著的可扩展性与性能收益，往往是数量级的。另一个预测的例子：[Nixtla 跑过训练 30,000 个模型的基准](https://nixtla.github.io/statsforecast/examples/ets_ray_m5.html)，并在另一次实验里[用 30 分钟训练了一百万个模型](https://www.anyscale.com/blog/how-nixtla-uses-ray-to-accurately-predict-more-than-a-million-time-series)。
- **在海量模型中找到最优（超参数调优）：** 另一家 B2B 分析公司会试验上千种模型（既包括不同模型类型，也包括不同超参数），为每一个客户挑出最优模型。这本质上是一个超大规模的超参数调优作业。

下面来看这些公司达成结果的技巧，介绍两种最常用的方法。

这些方法用 Ray 扩展多模型训练。想先了解 Ray，请看 [Ray 文档](https://docs.ray.io/en/latest/)或[这篇入门博客](https://towardsdatascience.com/modern-parallel-and-distributed-python-a-quick-tutorial-on-ray-99f8d70369b8?gi=55808edf2eda)。文末附有 OpenAI、Uber、Shopify、Instacart、Netflix、Lyft、Cruise、字节跳动等公司如何用 Ray 扩展机器学习负载的链接。

## 如何规模化训练许多模型

关于训练**大** ML 模型的挑战，[博客](https://www.uber.com/blog/horovod-ray/)与[教程](https://docs.ray.io/en/master/train/examples.html)越来越多，但讲训练**多**个 ML 模型的细节与方法的内容要少得多。我们见过五花八门的做法：从 AWS Batch、SageMaker、Vertex AI 这类服务，到围绕 Celery、Redis 等开源工具自建方案。

Ray 消掉了处理这些棘手用例的大量性能开销，因此用户切换到 Ray 后往往报告显著的性能提升。下面再深入一层讲它如何做到。

## 方法 1：使用 Ray Core（每个文件一个任务）

假设你已经有一份庞大的模型训练配置列表（例如每个邮编或 SKU 对应一个模型数据文件的路径），只需并行执行模型训练函数。我们用 Ray 来跑。下面的例子将在不同输入文件上训练 100 万个 scikit-learn 模型。

首先是串行实现：

```
1# For reading from cloud storage paths.
2from smart_open import smart_open
3import pandas as pd
4
5def train_model(file_path: str):
6    data = pd.read_csv(smart_open(file_path, "r"))
7
8    ## Train your model here.
9    from sklearn.linear_model import LinearRegression
10    lr = LinearRegression()
11    # (Column names are anonymized)
12    lr.fit(data[["id4", "id5"]], data["v3"])
13
14    ## Write outputs.
15    # smart_open(output, "w").write(pickle.dumps(lr))
16
17models_to_train = [
18	f"s3://air-example-data/h2oai_1m_files/file_{i:07}.csv"
19	for i in range(1000000)
20]
21
22# This will take much too long serially.
23for file in models_to_train:
24    print("Training model serially", file)
25    train_model(file)
```

我们可以直接用 `ray.remote` 函数把它并行化，但为更省事，这里用 Ray 的多进程库——Ray 分布式库之一：

```
1from ray.util.multiprocessing import Pool
2import tqdm
3
4# Create a pool, where each worker is assigned 1 CPU by Ray.
5pool = Pool(ray_remote_args={"num_cpus": 1})
6
7# Use the pool to run `train_model` on the data, in batches of 10.
8iterator = pool.imap_unordered(train_model, models_to_train, chunksize=10)
9
10# Track the progress using tqdm and retrieve the results into a list.
11list(tqdm.tqdm(iterator, total=1000000))
```

把对 pool 的调用包一层，我们就有了一个漂亮的进度条。内部由 Ray 把任务派发到集群 worker，自动处理容错、批处理优化等问题：

在 [Ray dashboard](https://docs.ray.io/en/latest/ray-core/ray-dashboard.html)中可以看到，上述作业在 10 节点集群上只要几分钟即可跑完。每个任务从 S3 读取输入文件后再训练模型（上面的示例代码中训练是 no-op）：

*多模型基准综合图*

用 Ray 的多进程库，从各自独立的数据文件训练 100 万个模型大约需要 10 分钟。这相当简单。但如果你的数据没有按模型组织好呢？

## 方法 2：使用 Ray Data（按 key 对数据分组）

你的数据常常是别的格式——例如 parquet 文件（比如独立 ETL 作业的输出），并且没有按模型预先分区。你可能会另起一个 Spark 集群来生成方法 1 里那种一模型一文件的漂亮布局。

为了把一切留在同一个脚本里，这里演示如何用 [Ray 的 Dataset 库](https://docs.ray.io/en/latest/data/dataset.html)在按客户训练模型之前把数据集按客户 ID 分组。首先用 Ray Datasets 的 `read_csv` 方法加载数据，再按目标分组键分组：

```
1import ray
2
3ds = ray.data.read_csv("s3://air-example-data/h2oai_benchmark")
4# Repartition the single CSV into 500 blocks to increase the parallelism.
5ds = ds.repartition(500)
6
7# Compute our (dummy) `customer_id` key as the concatenation of the
8# `id3` and `v1` columns and then group the dataset by it.
9ds = ds.add_column("customer_id", lambda r: r["id3"] + r["v1"].astype(str))
10ds = ds.groupby("customer_id")
```

我们会用 GroupedDataset 上的特殊函数 `map_groups()`：它接收一批数据、返回一个或多个结果。这里对每批数据返回一个训练好的模型：

```
1def train_model(data):
2    ## Train your model here.
3    from sklearn.linear_model import LinearRegression
4    lr = LinearRegression()
5    lr.fit(data[["id4", "id5"]], data["v3"])
6
7    # Return a single dict of the model and stats, etc.
8    return [{
9        "coef": lr.coef_,
10        "intercept": lr.intercept_,
11        "customer_id": data["customer_id"][0],
12    }]
13
14# Execute the model training.
15ds = ds.map_groups(train_model)
16
17# Write the results to destination files.
18# ds.write_parquet("s3://path/to/output")
```

执行时，Ray 的 Dataset 库会运行把数据按客户 ID 分组所需的分布式 shuffle 操作，然后并行应用给定的模型训练函数产出模型。

这里的要点是：Ray 的瑞士军刀式库组合，让我们仅用 Python 就能把这个任务扩展到集群，无需摆弄多个分布式系统或服务。

## 如何训练多个更大的模型

假设我们要训练多个更大的模型，每个需要一块 GPU，或者甚至需要多个进程并行训练。Ray 基于资源的调度可以无缝处理。

对需要 GPU 的模型，可以在 remote 参数里指定 `num_gpus=1`，让 Ray 把任务调度到 GPU。例如：

```
1# Create a pool that assigns each worker a GPU.
2Pool(ray_remote_args={"num_gpus": 1})
3
4# Execute the model training, telling Ray to assign 1 GPU per task.
5ds = ds.map_groups(train_model, num_gpus=1)
```

类似地，如果想每个模型用多个 CPU（例如让 sklearn 每个模型用 8 个 CPU），可以设置 remote 参数 `num_cpus=8`，让 Ray 为每个训练任务预留 8 个 CPU 槽位：

```
1# Create a pool that assigns each worker 8 CPUs.
2Pool(ray_remote_args={"num_cpus": 8})
3
4# Execute the model training, telling Ray to reserve 8 CPUs per task.
5ds = ds.map_groups(train_model, num_cpus=8)
```

## 用 Ray AIR 做分布式训练

若要更高层的分布式训练 API，可以选择 [Ray AIR](https://docs.ray.io/en/latest/ray-air/getting-started.html)* 中的 [Ray Train](https://docs.ray.io/en/latest/train/train.html)、[Ray Tune](https://docs.ray.io/en/latest/tune/index.html) 等库，它们专为管理多个计算密集型模型训练作业的执行而设计。Train 运行[单个分布式训练作业](https://docs.ray.io/en/latest/train/train.html)，并可与 Tune 配合同时运行多个这样的作业。

Tune 也能跑许多简单的模型训练作业，但在这一维度上不如其他方法可扩展（量级是数百个模型而非百万）。下面是用 Tune 执行前面方法 1 示例的例子（另见 [Tune Experiments 用户指南](https://docs.ray.io/en/latest/tune/tutorials/tune-run.html)）：

```
1from ray import tune
2
3# For reading from cloud storage paths.
4from smart_open import smart_open
5import pandas as pd
6
7def trainable_func(config: dict):
8    data = pd.read_csv(smart_open(config["file_path"], "r"))
9
10    ## Train your model here.
11    from sklearn.linear_model import LinearRegression
12    lr = LinearRegression()
13    lr.fit(data[["id4", "id5"]], data["v3"])
14
15    # Return a single dict of the model and stats, etc.
16    return {
17        "coef": lr.coef_,
18        "intercept": lr.intercept_,
19        "customer_id": data["customer_id"][0],
20    }
21
22# Tune is designed for up to thousands of trials.
23param_space = {
24    "file_path": tune.grid_search([
25	f"s3://air-example-data/h2oai_1m_files/file_{i:07}.csv"
26	for i in range(1000)
27    ])
28}
29
30tuner = tune.Tuner(trainable_func, param_space=param_space)
31print(tuner.fit())
```

与直接使用 Ray 任务相比，Tune [额外提供](https://docs.ray.io/en/latest/tune/tutorials/tune-run.html#comparison-to-ray-remote)：

- 状态汇报与跟踪，包括与常见监控工具的集成与回调。
- trial 的检查点，实现细粒度容错。
- 多 worker trial 的 gang 调度。

**想开始用 Ray 训练大量模型，请按[端到端教程](https://docs.ray.io/en/master/ray-overview/use-cases.html)构建你的项目。**

## 为什么 Ray 适合训练大量模型

总结，Ray 在多模型训练上的优势有几方面。

- **灵活调度**：Ray 的单模型训练任务开销更低（毫秒级，而不是秒级到分钟级）。这与 SageMaker 这类为每个任务拉起 docker 容器或节点的训练框架形成对比。在上面例子中，Ray 可以把任务多路复用进各个进程，降低单任务开销。
- **统一性**：Ray 的内建库组合让你仅用几行 Python 就能高性能地搞定数据预处理与训练，而不必新起分布式系统。这正是方法 2 的例子能作为单个 Ray 脚本运行的原因。

Ray 同样擅长其他突破现有框架边界的用例，例如单个大模型的分布式训练、或众多不同模型的分布式服务。这些主题留待后续博客。
