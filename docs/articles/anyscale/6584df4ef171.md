# Ray Spotlight 系列：用 Runtime Env 即容器构建多租户 Serve 应用

作者：Sam Chan 和 Cindy Zhang | 2024 年 6 月 13 日

访谈人：

Sam Chan，技术项目经理

## **概览 ⚡**

在这场富有启发性的对话中，Sam Chan 与 Cindy Zhang 深入探讨依赖各不相同的多应用 serve 集群的进展与挑战。继续读下去，了解如今如何把不同容器部署到同一个服务集群上。

## **基础概念 🔎**

**Sam Chan：** 能否先大致解释一下什么是多应用支持、为什么它重要？

**Cindy Zhang：** 当然。简单来说，多应用支持让不同的应用运行在同一集群上，每个应用把 runtime environment 当容器用。多应用支持有助于更高效地管理资源，并降低运维复杂度——因为不同应用可以独立升级。

**S：** 我们此前是如何支持同一集群上的多个应用的？有什么缺点吗？

**C：** 去年夏天我们在 Ray Serve 上推出了多应用支持，让你在单个 Ray 集群上服务多个*相互独立*的应用。然而，许多不愿在运行时用 Ray runtime environments 安装依赖的用户，仍然必须把所有模型依赖打包进一个大 Docker 镜像。一些客户告诉我们这很痛苦，尤其是当他们有许多各自独立的应用想一起跑在同一 Ray 集群上时。

**S：** 用一个大镜像的痛点是什么？

**C：** 它导致镜像膨胀得离谱，所有依赖混在一起，维护起来相当头疼。例如我们的一位客户有许多不同的研究团队各自开发模型，他们希望把每个团队的代码部署进各自干净的小镜像（更好维护、迭代更快等）。

最重要的是，支持独立镜像能让团队解决不同 Serve 应用依赖互相冲突的情况。

**S：** 我们构建多应用支持时只支持单一容器，是有什么原因吗？我们考虑过不同场景吗？

**C：** 历史上，对多容器的需求并不普遍，训练负载尤其如此。但随着应用变得更动态，我们看到了对这一特性更大的需求。

## **Runtime Env 即容器 🧑‍💻**

**S：** 这个新的"runtime envs as containers"特性如何提供帮助？

**C：** 有了它，现在可以为每个团队的应用指定不同的 Docker 镜像！当 Ray 需要为某应用启动一个 replica 时，它会直接用该应用的镜像起一个容器，在里面运行 worker 进程。应用之间的隔离非常干净。

**S：** 除隔离之外还有什么好处？它如何支撑多个 Serve 应用的多租户？

**C：** 当然有，它真正释放了 Ray 多租户能力的威力。由于应用各自在独立容器中、但仍运行在同一集群上，它们能以高得多的效率共享资源。

例如，你可以把 8 个应用塞进一台带 8 块 GPU 的大 VM，并把每个 Ray Serve 应用配置为各用一块 GPU。

这让用户能更细粒度、更精准地利用 GPU 容量，单台 VM 上不留闲置资源。

运维复杂度也降低了，因为你只需要管理一个 Ray 集群；你现在可以在更多场景使用 Ray Serve 的[原地更新（in-place updates）](https://docs.anyscale.com/preview/platform/services/update-a-service/#:~:text=To%20performance%20an%20in%2Dplace,to%20match%20the%20new%20configuration.&text=You%20can't%20update%20the,using%20an%20in%2Dplace%20update.)。

## **技术细节与挑战 ‼️**

**S：** 能讲讲底层发生了什么吗？

**C：** 其实相当直接！我们把 Ray 与 Podman 集成，用于拉取镜像并启动容器。现在，当需要启动新的 Ray Worker 时，Ray 会调用 Podman 来编排相关镜像的拉取与容器的启动。随后 Ray 编排的是在那个容器内运行 Ray Worker 代码，而不是直接在宿主机上运行。为了让 Ray Serve 的生命周期事件正确挂接，我们下了不少功夫。

**S：** 这些好处与增强听起来很棒，但在单个 Ray 集群上使用多个 Docker 镜像有缺点吗？

**C：** 首先提醒一句：该特性很新，仍处于实验阶段。最大的一点是首次拉取镜像时会有启动延迟。我们也还没在超大规模下测试过。

另一点是，至少目前，container runtime env 不支持其他 runtime env 字段，例如 Python 环境或工作目录。一切都必须在容器内声明好。

## **展望未来 ⏩**

**S：** 接下来这一特性将如何演进？

**C：** 好问题。短期内我们想把容器与其他 runtime env 字段组合的使用体验理顺，例如你希望为每个应用单独解释的特定环境变量。

我们仍在收集用户反馈，弄清哪些字段该纳入、哪些不该。随着大家开始试用，我们也计划增加更多可扩展性测试，并整体性地收敛用户反馈。
