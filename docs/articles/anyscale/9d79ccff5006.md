# Ray Train V2：在 Ray 上统一的分布式训练

作者：[Matthew Deng](https://www.anyscale.com/blog?author=matthew-deng)、[Justin Yu](https://www.anyscale.com/blog?author=justin-yu)、[Timothy Seah](https://www.anyscale.com/blog?author=timothy-seah)、[Jason Li](https://www.anyscale.com/blog?author=jason-li)、[Lehui Liu](https://www.anyscale.com/blog?author=lehui-liu)、[Xinyuan Gui](https://www.anyscale.com/blog?author=xinyuan-gui) 与 [Richard Liaw](https://www.anyscale.com/blog?author=richard-liaw) | 2025 年 11 月 4 日

过去几个版本里，Ray Train 团队一直在改进分布式训练负载的开发体验和运行时稳定性。

**Ray Train V2** 就建立在这个基础之上——它带来更好的可用性、更强的可靠性保证，以及更干净的 API 表面，让整个技术栈上的新功能都能开发得更快。

为此，本季度引入的所有新功能都构建在 **Ray Train V2** 之上，我们强烈建议用户开始迁移。完整细节见 [Train Tune API Revamp REP](https://github.com/ray-project/enhancements/blob/main/reps/2024-10-18-train-tune-api-revamp/2024-10-18-train-tune-api-revamp.md) 和 [Migration Guide](https://github.com/ray-project/ray/issues/49454)。

### 异步 checkpoint

Ray Train 本来就有一整套管理模型 checkpoint 的能力。默认情况下，调用 train.report API 时，checkpoint 会同步上传到目标目录。可一旦 checkpoint 很大或者存得很频繁，GPU 利用率就会被拖低。

为了解决这个问题，Ray Train V2 现在内置了异步 checkpoint 上传。开启之后，checkpoint 可以在一个独立的 CPU 线程上上传到云存储，GPU 训练任务不会因为 I/O 而停下来。checkpoint 又大又密的时候，这个做法能把 GPU 利用率维持在高位。异步 checkpoint 的更多说明见[文档](https://docs.ray.io/en/releases-2.51.1/train/user-guides/checkpoints.html#asynchronous-checkpoint-uploading)。

```
1def train_fn(config):
2    ...
3    metrics = {...}
4    tmpdir = tempfile.mkdtemp()
5    ...  # Save checkpoint to tmpdir
6    checkpoint = Checkpoint.from_directory(tmpdir)
7    train.report(
8        metrics,
9        checkpoint=checkpoint,
10        checkpoint_upload_mode=train.CheckpointUploadMode.ASYNC,
11    )
```

### 异步验证

训练过程中定期验证模型很常见，用来衡量模型表现、防止过拟合。常规做法是在训练循环里周期性地在训练和验证之间来回切换。

在 Ray 2.51 里，Ray Train 支持你把模型验证放进一个独立的 Ray task 异步执行。这意味着你可以

- 并行跑验证而不阻塞训练循环，拿到更高的训练有效吞吐
- 用和训练不同的（更便宜、效率更低的）硬件跑验证
- 用 Ray Data 或 Ray Train 轻松把验证横向扩展开
- 借助自动伸缩，只在验证这段时间拉起机器

异步 checkpoint 验证的更多说明见[文档](https://docs.ray.io/en/master/train/user-guides/asynchronous-validation.html)。

```
1def validate_fn(checkpoint, config):
2    ...
3    return {"score": ...}
4
5def train_fn(config):
6    ...
7    ray.train.report(
8        metrics,
9        checkpoint=checkpoint,
10        checkpoint_upload_mode=ray.train.CheckpointUploadMode.ASYNC,
11        validate_fn=validate_fn,
12        validate_config={"dataset": ...},
13    )
```

### TPU 上的 JaxTrainer

Ray Train 现在提供 **JaxTrainer** API，能把分布式 **JAX** 训练无缝扩展到 **TPU 上。**

分布式 JAX 过去一直要求你在多 controller（multi-controller）配置下运行，在每块设备上派生出并行进程。但这种执行方式一旦失败很难恢复，也很难迭代着开发。

有了这个新 API，用户现在可以在 TPU 上原生扩展 JAX 负载，并且用上和 Ray Train 的 TorchTrainer、TensorFlowTrainer 这些常用 API 一样的单 controller 编排与容错。文档里有 Ray Train 上 [JAX](https://docs.ray.io/en/master/train/getting-started-jax.html) 的更多说明。

```
1from ray.train.v2.jax import JaxTrainer
2from ray.train import ScalingConfig
3
4def train_func():
5    # Your JAX training code here.
6
7scaling_config = ScalingConfig(num_workers=4, use_tpu=True, topology="4x4", accelerator_type="TPU-V6E")
8trainer = JaxTrainer(train_func, scaling_config=scaling_config)
9result = trainer.fit()
```

### 用于顺畅调试的 Local Mode

Ray Train v2 现在提供一种「local」执行模式。在 `local mode` 下，不再采用默认那套「把训练代码跨多个 Ray actor 并行跑」的执行策略，而是直接在当前进程里执行你的训练函数，而且不需要改动代码。这给你一个更简单的调试环境，可以快速迭代训练逻辑。

Local mode 支持两种执行模式：

- 单进程模式：在单个进程里跑你的训练函数，适合快速迭代和调试。
- 带 torchrun 的多进程模式：拉起多个进程做多 GPU 训练，适合用熟悉的工具来调试分布式训练逻辑。

更多说明见 [Ray Train 文档里的 local mode](https://docs.ray.io/en/master/train/user-guides/local_mode.html)。

## 往后看

Ray Train V2 为下一代分布式训练打下了地基——一个**更模块化、性能更好、也更贴合开发者习惯**的地基。后续的发布会在这块基础上继续增强容错、加深框架集成，并把 Train 和 Tune 的实验管理统一起来。
