# Announcing Ray 1.0

By

Eric Liang

|

September 30, 2020

### LinkAnnouncing Ray 1.0

Today, we’re happy to announce the release of [Ray 1.0](https://github.com/ray-project/ray). Ray 1.0 brings a [stable API](https://docs.ray.io/en/master/package-ref.html) and new [general purpose serverless](https://ray2020.sched.com/event/dhCy/ray-a-general-purpose-serverless-substrate-eric-liang-anyscale) features, both important steps towards the goal of providing a universal API for distributed computing. This past release has seen 67 contributors and 458 commits, making it the among the [largest yet](https://github.com/ray-project/ray/releases) for Ray. In addition, 1.0 brings many new community [library integrations](https://docs.ray.io/en/master/ray-libraries.html) to the growing Ray ecosystem.

### LinkNew Features

Ray 1.0 makes it easier than ever to build and compose highly scalable libraries, applications, and services. Here are the highlights:

**Resources, Not Machines: **Building distributed applications that run portably across different machine types, clusters, and clouds is a challenging task. Ray 1.0 makes this easy with an [autoscaler](https://docs.ray.io/en/master/cluster/autoscaling.html) that intelligently selects the best [node types](https://docs.ray.io/en/master/cluster/autoscaling.html#multiple-node-type-autoscaling) for an application’s [resource requests](https://docs.ray.io/en/master/advanced.html#accelerator-types). In addition, Ray 1.0 introduces [a placement group API](https://docs.ray.io/en/master/placement-group.html) for fine-grained control over scheduling.

**Production Serving: **A general purpose serverless framework hosts both offline batch and online serving workloads. Ray 1.0 ships with [Ray Serve](https://docs.ray.io/en/master/serve/), a production microservice and ML serving library. For custom serving applications, Ray 1.0 also introduces [detached](https://docs.ray.io/en/master/actors.html?highlight=lifetime#actor-lifetimes) actor lifetimes, [AsyncIO](https://docs.ray.io/en/master/async_api.html) actors, and application-level metrics via [Prometheus](https://docs.ray.io/en/master/ray-metrics.html?highlight=prometheus). Ray serving applications can be deployed in various [cloud providers](https://docs.ray.io/en/master/cluster/cloud.html) and on [Kubernetes](https://docs.ray.io/en/master/cluster/kubernetes.html).

**Automatic Memory Management**: Users of Ray 1.0 can say goodbye to “object evicted” errors, thanks to fully automated [memory management](https://docs.ray.io/en/master/memory-management.html). Application performance and memory usage can be debugged in the [Ray dashboard](https://docs.ray.io/en/master/ray-dashboard.html). To learn more about how Ray implements distributed reference counting with high-performance, reliability, and fault tolerance, check out the new [Ray 1.0 whitepaper](https://docs.ray.io/en/master/whitepaper.html).

**Java and Windows Support: **Ray 1.0 brings native support for the Java and Windows platforms. This means that you can now use Ray to build [cross-language](https://docs.ray.io/en/master/cross-language.html) and [distributed Java](https://medium.com/distributed-computing-with-ray/build-distributed-java-applications-with-ray-90b381eff564) applications, and [install Ray on Windows](https://docs.ray.io/en/master/installation.html#windows-support).

### LinkCommunity Update

**Community Integrations**: There are a growing number of [community libraries](https://docs.ray.io/en/master/ray-libraries.html) that integrate with Ray 1.0 for distributed execution: [ClassyVision](https://classyvision.ai/tutorials/ray_aws), [Dask](https://docs.ray.io/en/master/dask-on-ray.html), [Flambe](https://github.com/asappresearch/flambe), [Horovod](https://horovod.readthedocs.io/en/stable/ray_include.html), [HuggingFace](https://huggingface.co/transformers/master/main_classes/trainer.html#transformers.Trainer.hyperparameter_search), [Intel Analytics Zoo](https://analytics-zoo.github.io/master/#ProgrammingGuide/rayonspark/), [MARS](https://docs.ray.io/en/master/mars-on-ray.html), [Modin](https://github.com/modin-project/modin), [RayDP](https://github.com/Intel-bigdata/oap-raydp), [Seldon Alibi](https://github.com/SeldonIO/alibi), and [SpaCy](https://pypi.org/project/spacy-ray/). This means users of these libraries can now scale their applications with Ray, and Ray users can easily leverage these libraries in their distributed applications.

**Open Source**: At Anyscale, we’re proud to develop Ray along with the open source community. Many key Ray contributions are driven by the community — for example, ongoing projects around high availability, multi-tenancy, and placement groups are led by [Ant Group](https://www.antgroup.com/en), and improved autoscaler support for different Clouds has come from [Amazon](https://aws.amazon.com/) and [Microsoft](https://azure.microsoft.com/en-us/).
