# 推出 Anyscale Agent Skills：更快构建、更聪明调试、优化运行在 Ray 上的 AI 工作负载

作者：Kunling Geng、Aydin Abiar、Philip Wang、Goku Mohandas、Stephen Offer、Jason Ding、Ankur Khurana、Bryce Huang 和 Mickey Heynen | 2026 年 4 月 22 日

今天我们宣布 **Anyscale Agent Skills 正式全面可用（GA）**，为主流 AI 编程智能体装备编写、部署、调试和规模化优化工作负载所需的 Ray 与 Anyscale 专业知识。Agent Skills 作为 Anyscale CLI 的第一方功能分发，现已支持 Claude Code 和 Cursor。

三个技能组即日全面可用，覆盖从生成工作负载到生产部署与调试的完整开发生命周期：

- **Workload Skills →** 为 LLM 服务、多模态数据处理、分布式训练、批量推理和嵌入生成生成代码与配置
- **Platform Skills →** 利用日志、指标和托管工作区（managed workspaces）调试、修复并重新部署运行中的工作负载
- **Infra Skills →** 以引导式、生产就绪的方式在 Kubernetes 或虚拟机上部署 Ray

Workload 与 Platform Skills 协同工作时，相比 Claude Code、Cursor 等通用智能体可实现 5 倍开发速度。

**通过 Anyscale CLI 安装这些技能开始使用：**

```
pip install -U anyscale
anyscale login

anyscale skills install --platform claude-code
# or
anyscale skills install --platform cursor
```

同时，**Anyscale 推出 Ray 优化服务计划（Optimization Services Program）**，由 AI 智能体与前置部署工程师（FDE）配合分析吞吐量瓶颈与 GPU 浪费，产出调优建议，帮助优化生产 AI 工作负载的成本与性能。

- 在[这里](https://www.anyscale.com/asset/anyscale-agent-skills-optimization-services-program)**申请优化服务计划的早期访问**。

## 为什么推出 Anyscale Agent Skills

> "通过让我们的编程智能体深度原生地了解 Anyscale Platform——从计算配置到集群行为——我们把分布式 AI 的全部能力交到每位开发者手中，而不只是基础设施专家。" ——Emin Mammadov，Geotab AI 平台高级软件开发者

基础模型的兴起使大规模 GPU 加速计算成为行业标配。不仅用于训练，也用于以 AI 模型大规模清洗和处理多模态数据集（视频、图像、文本等）的数据流水线。Ray 每周下载量超过 1200 万次，已成为处理这类 AI 计算复杂度采用最广泛的计算框架。

但规模化运行 AI 工作负载不只是用 Ray 扩展 Python，还需要让应用代码与合适的基础设施对齐，并给出正确的设置与配置以优化性能和成本。以部署一个 LLM endpoint 为例：你需要为模型匹配合适的 GPU、配置张量并行、调优 vLLM 等推理引擎以及用于扩缩容等基础设施操作的 Ray Serve 库。一旦出问题，你就得在分布式日志和指标中排查 OOM。结果调试和修错的时间比交付创新的时间还多。

Ray 的创造者 Anyscale 在数百个生产部署中积累了这套专业知识。Agent Skills 把过去只有我们的前置部署工程师（FDE）才具备的构建与调试知识，按需带给每个 AI 团队。

## 为什么通用编程智能体会失效

通用智能体虽然会写 Python，但分布式计算这类复杂领域需要 AI 编程智能体根本不具备的专门知识：如何规划 GPU 显存、如何跟上最新的 Ray API、如何调试集群故障。具体到 Ray 和 Anyscale，它们会引入四种系统性失败模式，拖慢甚至阻断从开发到生产的道路：

- **资源规划**：智能体生成配置时不考虑硬件约束，设置错误的张量并行、在权重、KV cache 与运行时开销之间错误估算 GPU 显存，导致只在运行时才暴露的 OOM 错误。
- **过时 API**：通用智能体的预训练数据中含有大量旧版 Ray 代码，因此会自信地生成与当前 Ray 版本不再匹配的陈旧模式和已弃用接口，产出运行时即报错的 vLLM 参数、Ray Serve 配置和自动扩缩容设置。
- **损坏的配置**：生成的配置文件缺少字段、结构错误或资源引用与你的部署环境不符，导致作业静默失败或行为异常且难以追踪。
- **没有调试闭环**：作业运行中途失败时，智能体无法查询实时集群状态、查看 Ray Dashboard 指标，或将故障与引发它的工作负载条件关联起来，只能让你手动在几百个日志里 grep 然后从头再来。

若不加纠正，这些缺口会让工作负载困在开发阶段无法进入生产，白白浪费分布式计算本应节省的 GPU 时长、计算成本和工程时间。

Skills 概念于 2025 年末兴起，Anthropic 推出了一个模块化框架，为 AI 智能体装备实用的专门能力。开发者无需依赖冗长的一次性提示词，而是可以把指令、脚本和上下文打包成可复用的技能文件夹，由智能体按需动态加载。这一路线很快演变为被 OpenAI、Cursor 和 GitHub Copilot 采纳的开放行业标准，改变了领域专业知识注入 AI 智能体的方式。

## Anyscale Agent Skills 概览

Anyscale Agent Skills 赋予 AI 编程智能体来自 Ray 与 Anyscale 创造团队的平台知识与经验，用于在 Anyscale 上编写、部署、调试和优化 Ray 工作负载。每个技能引导 AI 依次完成需求收集、约束校验、基于成熟模板的代码生成，并使用当前 API 进行部署。

**Workload Skills：从一句提示到运行中的工作负载**

搞清楚正确配置、验证你的 GPU 档位能否支撑模型、弥合文档说法与你环境实际情况的差距，往往占据大部分时间。Workload Skills 提前处理这一切。智能体会问对问题、在生成任何内容前先检查约束，并基于当前 Ray API 的成熟模板生成代码。

| 技能 | 功能 |
| --- | --- |
| `/anyscale-workload-llm-serving` | 用 Ray Serve LLM 部署 LLM：模型规模测算、GPU 规划、多 LoRA、OpenAI 兼容 endpoint、自动扩缩容 |
| `/anyscale-workload-ray-serve` | 将非 LLM 模型作为可扩展 REST endpoint 提供服务：sklearn、XGBoost、PyTorch、TensorFlow、多模型组合、异步推理 |
| `/anyscale-workload-ray-data` | 通过 `ray.data.llm`（vLLM）或自定义 `map_batches` 设计离线批量推理流水线：CV、音频、NLP、表格数据 |
| `/anyscale-workload-batch-embedding` | 用 Ray Data 大规模生成嵌入：文本、图像、多模态、向量数据库集成 |
| `/anyscale-workload-ray-train` | 分布式训练与微调：PyTorch、Lightning、HF Transformers、XGBoost |

**Platform Skills：部署、调试并修复运行中的工作负载**

当 Ray 作业在生产中失败，你需要的是实时集群状态，而不仅是代码。Platform Skills 把智能体直接连到 Anyscale API 和 Ray Dashboard，因此一旦出问题，`/anyscale-platform-inspect` 可以从实时集群读取日志、指标和事件，弄清到底发生了什么。`/anyscale-platform-fix` 拿着这些上下文修补代码、重新部署，并在同一会话中验证修复。

| 技能 | 功能 |
| --- | --- |
| `/anyscale-platform-run` | 生成 Anyscale 配置并通过 CLI 执行工作负载（workspaces、jobs、services） |
| `/anyscale-platform-inspect` | 对运行中工作负载做只读诊断：经 Anyscale API 和 Ray Dashboard 读取日志、指标、事件 |
| `/anyscale-platform-fix` | 完整调试-修复-验证闭环：用 `/anyscale-platform-inspect` 诊断、修补代码、用 `/anyscale-platform-run` 重新部署并端到端验证 |
| `/anyscale-platform-ask` | 基于文档与源码，回答 Ray 内部机制、架构建议和 API 用法等有出处的问题 |

**Infrastructure Skills：在任意基础设施上端到端搭建 Anyscale**

在 Kubernetes 或云虚拟机上搭建 Anyscale 涉及一长串决策：Helm、Terraform、IAM、网络、GPU 配置，每一项都必须正确，后续才能正常工作。Infra Skills 引导智能体按顺序完成每一步，生成针对你的具体环境验证过的配置，而不是套用可能与你的 CUDA 版本、实例类型或网络拓扑不符的通用示例。

| 技能 | 功能 |
| --- | --- |
| `/anyscale-infra-kubernetes` | 在 EKS、GKE 或 AKS 上的引导式部署：Helm operator、网络、GPU 配置 |
| `/anyscale-infra-aws-vm` | 在 AWS 虚拟机上部署 Anyscale：VPC、IAM、S3、安全组、EFS、MemoryDB |
| `/anyscale-infra-gcp-vm` | 在 GCP 虚拟机上部署 Anyscale：VPC、IAM、GCS、防火墙、Memorystore、Workload Identity Federation |

**优化服务计划：降低成本、榨取性能**

Anyscale 全新的优化服务计划让 AI 智能体与前置部署工程师协同分析 Ray on Anyscale 上的工作负载。二者结合识别吞吐量瓶颈、发现 GPU 低效之处，并生成针对性的调优建议以提升性能、降低成本。

该计划从第一天起就面向真实世界的影响。把自动化分析与一线专长结合，团队可以为生产工作负载验证优化方案，确保改动转化为可靠性、吞吐量与成本效率上可度量的提升。

## 通过 Anyscale CLI 安装

技能直接经 Anyscale CLI 安装，无需手动管理文件，也不需要额外凭证。选好你的 AI 编程工具并运行：

```
# Browse the skills catalog
anyscale skills list

# Install for your AI coding tool
anyscale skills install --platform claude-code
anyscale skills install --platform cursor
anyscale skills install --platform all

# Update to the latest version
anyscale skills update

# Clean removal
anyscale skills remove
```

## 默认安全

对于在受监管环境运营或管理共享基础设施的团队，技能会强制执行 AI 智能体无法绕过的安全策略：

- **安全确认门**：首次使用时，智能体会展示完整安全策略，任何操作前必须显式接受
- **破坏性命令拦截**：pre-tool-use 钩子检查每一条 shell 命令，拒绝危险操作：`rm -r`、AWS `terminate-instances`、`kubectl delete`、`terraform apply`、`anyscale cloud delete` 等数十种
- **只读 Terraform**：仅允许 show、validate、state list 等非变更子命令
- **权限最小化**：`/anyscale-platform-inspect` 严格只读；只有 `/anyscale-platform-fix` 可以启动工作负载，且它会事先声明

## 分钟级部署，而不是小时级

设想一个常见场景：部署一个 70B 模型结果撞上 OOM。这正是技能要预防的。

**没有技能**时，在 Anyscale 上部署 Llama 3.1 70B 是这样的：

- 阅读 vLLM 与 Ray Serve 集成文档
- 搜索配置示例并改造以适配你的 GPU 档位
- 编写 `service.yaml`，在试错部署中反复迭代
- 撞上 OOM → 手动查日志 → 调整张量并行
- 研究 `vLLM --tool-call-parser` 的工具调用解析器
- 重新部署、验证，并希望这次能行

**有了 Anyscale Skills：**

```
/anyscale-workload-llm-serving deploy Llama 3.1 70B on L40S GPUs 
with autoscaling from 1 to 4 replicas
```

对比：没有技能时，智能体把 Llama 70B 错误地按单张 L40S 规划，撞上 OOM，需要人工修复（数小时）。有了 Anyscale 技能，它会规划显存、设置 TP=8，几分钟内成功部署。

智能体收集定向需求（LoRA adapter、自定义路由与延迟 SLA），核算模型权重、KV cache 和运行时开销后确认 70B 模型无法放进单张 L40S，设置 TP=8，生成完整的 Ray Serve + vLLM 部署与 `service.yaml`，并移交 `/anyscale-platform-run`。若服务失败，`/anyscale-platform-fix` 经 Anyscale API 收集日志、诊断根因、修补配置并重新部署——全部在同一处完成。

同样的模式适用于整个技能集。大规模运行 LLM 批量推理：

```
/anyscale-workload-ray-data generate LLM BATCH INFERENCE using the data 
from https://llm-guide.s3.us-west-2.amazonaws.com/data/ray-data-llm/customers-2000000.csv 
and Qwen/Qwen3-30B-A3B-Instruct-2507-FP8 (HuggingFace) using L40S GPUs
```

或者，诊断一个失败的作业：

```
/anyscale-platform-inspect prodjob_abc123 - focus on OOM errors 
and memory usage
```

## 组合使用技能

技能开箱即用、相互协作。在一条提示中引用多个技能，智能体会依次执行每一个，并把上下文从一个带到下一个。

**用 `/anyscale-workload-ray-data` 构建数据处理流水线，再用 `/anyscale-platform-run` 部署并验证：**

```
Use /anyscale-workload-ray-data to create a batch pipeline that extracts 
text from PDF files and generates a one-paragraph summary per page 
using Qwen3-8B-instruct model. 

Then use /anyscale-platform-run to launch it in an Anyscale workspace 
and verify it runs end-to-end.

The PDF files are located in s3://anyscale-rag-application/100-docs/.
```

智能体从 `/anyscale-workload-ray-data` 开始，收集模型、输入格式与输出 schema 的需求，选择 `ray.data.llm` 模板做 vLLM 后端推理，生成一条从 S3 读取 PDF、按页分块并经 Qwen3-8B 摘要的完整流水线。随后移交给 `/anyscale-platform-run`，后者生成带正确 GPU 实例类型的 `workspace.yaml`，提交作业并流式输出日志直到完成。
