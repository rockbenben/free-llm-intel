# Ray Summit 2022 故事集——ML 平台

作者：Anyscale Ray Team | 2023 年 3 月 3 日

我们 Ray Summit 故事集的[第一篇博客](https://www.anyscale.com/blog/ray-summit-2022-stories-large-language-models)聚焦各公司如何用 Ray 训练大语言模型。这是系列第二篇，精选几场关于公司如何在其 ML 平台中扩展 ML 负载的演讲。看看 Uber、Spotify、Shopify 如何在 Ray 之上构建下一代平台。

## Uber——用 Ray 进行大规模深度学习训练与调优

Uber 的 ML 平台 Michelangelo 于 2016 年以一个单体 Spark 应用起步。两年后，为容纳深度学习用例，它以"外挂"方式引入了 Horovod。最终它构建在 Ray 之上，成为一个统一、可扩展的 ML 计算平台，带来更好的灵活性与成本性能。

*Uber - Michelangelo 的演进之路*

在最新一代 ML 平台中，Uber 的 ML 平台团队正在把端到端 ML 流水线重构到 Ray 上，并逐步下线 Spark estimator 与 MLlib 依赖。

*异构 Ray 集群*

通过在 Ray 异构（CPU + GPU）集群上实现大规模深度学习，Uber 团队在训练大规模深度学习作业的 ML 计算部分节省了 50%。

*Uber - 异构 Ray 性能*

Uber 内部的 Autotune 服务现在使用 Ray Tune，其超参数调优作业获得了最高 4 倍提速。

## Spotify 如何用 Ray 加速 ML 研究与原型开发

Spotify ML 团队的使命是让 ML 平台大众化（democratize），让工程师、数据科学家、研究员等各种背景的 Spotify 员工都能用自己独特的视角、技能与专长推进 ML、在 Spotify [激发创新](https://engineering.atspotify.com/2023/02/unleashing-ml-innovation-at-spotify-with-ray/)。

ML 平台的 2-3 年愿景，是演进得更易用、更灵活、框架无关、Python 原生。

*Spotify - ML 平台焦点*

上图展示了 Spotify 更广义的 ML 从业者群体，涵盖研究科学家、数据科学家、数据工程师以及聚焦 ML 相关任务的 ML 工程师等角色。

Spotify 选择 Ray 的理由是："它专为 ML 开发而生，拥有丰富的 ML 生态集成。它能轻松扩展计算密集型负载——特征预处理、深度学习、超参数调优、批量预测——且几乎无需改动代码。"

团队发现 Ray 比最初支撑其 ML 平台的框架 TensorFlow Extended（TFX）更简单直观，并且免除了学习其他框架、API 或 Kubernetes 的需要。ML 平台团队挑选了几个用例，在 Ray 上做了若干 POC 来解决各种 Spotify 问题，例如训练播客推荐的 GNN 嵌入、为 Radio 扩展强化学习。比如，图神经网络的 POC 从构想到落地仅用 2.5 个月，并在两周内完成生产化。在 RL 用例中，Ray 解除了 RL agent 训练的性能瓶颈，为离线 RL 负载的生产化奠定了基础。

## Merlin 的魔法——Shopify 的新机器学习平台

Shopify 的 ML 平台团队经历了多轮迭代：最初使用自研 Pyspark 方案，随后在 Google AI 平台上做原型，最终选择在 Kubernetes 与 Ray 等开源项目之上构建。ML 平台的目标围绕三条信条：

- **可扩展性** —— 能为机器学习工作流扩容的强健基础设施
- **快速迭代** —— 为数据科学家与 ML 工程师减少摩擦、提升生产力的工具，把原型与生产之间的差距压到最小
- **灵活性** —— 用户可以使用模型所需的任何库或包

ML 平台团队认识到围绕真实用例构建的重要性——它让他们能在数据量最大的场景下扩展。团队还体会到，建平台与养平台是两回事。ML 平台团队学会了如何有效把用户迁移到新平台上，并设定促成平稳过渡的目标。一个关键结论是：良好的用户体验是成功的关键。
