## 上下文感知推理应用的基础

构建上下文感知推理应用，始于理解驱动其功能的关键组件。这类应用通常依赖强大的语言模型来处理和生成自然语言文本。正如 Harrison Chase 所解释的，这是一个多层面的过程，涉及：

**1. 数据工程**

构建上下文感知推理应用的很大一部分工作是数据工程。开发者必须确保语言模型收到正确的上下文。这些上下文大多是文本数据，准确处理数据预处理至关重要——去除 XML 或 HTML 标签等干扰只是挑战的一部分。Harrison 强调需要连接各种数据源的连接器，并在数据进入语言模型前做好格式化。

**2. 提示工程**

语言模型与用户互动主要靠提示（prompt）。打磨有效的提示是一门艺术，需要尝试不同的提示变体，并确保提供给模型的上下文与预期输出对齐。这一步往往与数据工程交织在一起，因为数据必须先正确格式化才能并入提示。

**3. 复杂系统中的调试**

随着上下文感知推理应用复杂度上升，调试成为一项艰巨的挑战。数据在这些系统中的流转错综复杂，各环节还夹杂着非确定性的语言模型。Harrison 介绍 LangSmith 作为高效调试的解法：它提供方式查看流程中每一步的输入输出，让开发者有效定位并解决问题。

**4. 评估：一项艰巨任务**

评估上下文感知推理应用的性能是又一道坎。这类应用的输出往往是自然语言文本，使评估成为一个独特难题。与传统机器学习不同，没有容易度量的指标，可靠的 ground truth 数据也难以获得。Harrison 建议为评估创建自定义数据集，但强调这是一项繁重的任务。评估实时数据（例如回答当前温度的问题）又带来另一重挑战。Harrison 讨论了多种方法，包括记录中间状态与指令集，以便在此类场景下完成评估。

## 检索机制的不断演进

上下文感知推理的一个重要部分是检索机制，它决定应用如何从各种来源获取相关信息。Harrison 讨论了传统检索机制的局限，以及更高级方案的需求。他指出，理想的检索系统仍然是一个挑战，因为它因应用而异。

### 高级检索机制

Harrison 介绍了 LangChain 开发的一些高级检索机制，旨在克服传统检索方法的局限。以下是两个代表作：

**1. Parent Document Retriever**

Parent Document Retriever 旨在弥合"对小数据块做语义搜索"与"给语言模型提供更广泛上下文"之间的鸿沟。它基于语义搜索检索更大的父文档并传给模型，在精确性与上下文丰富度之间取得平衡。

**2. Self-Query Retriever**

当查询涉及与主问题语义上并不相关的具体细节时，Self-Query Retriever 特别有用。它把工作拆成语义查询和元数据过滤两部分，从而在向量数据库中实现更精确的检索。

Harrison 强调，检索机制仍然高度依赖具体应用，不存在放之四海皆准的方案。

## 复杂系统中的协作

上下文感知推理应用日益复杂，往往涉及不同团队的协作。Harrison 谈到了各团队分别负责系统不同部分（如提示工程与数据工程）的挑战。这些团队技能和目标各异，使协作变得关键。
