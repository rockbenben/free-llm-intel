# 宣布 Ray 在 Google TPU 上支持 PyTorch

作者：[Lehui Liu](https://www.anyscale.com/blog?author=lehui-liu)、[Richard Liaw](https://www.anyscale.com/blog?author=richard-liaw)、[Andrew Sy Kim (Google)](https://www.anyscale.com/blog?author=andrew-sy-kim-google)、[Nisha Mariam Johnson](https://www.anyscale.com/blog?author=nisha-mariam-johnson) 和 [Ryan O'Leary (Google)](https://www.anyscale.com/blog?author=ryan-oleary-google) | 2026 年 10 月 20 日

今年早些时候，在 Ray Summit 2026 上，我们介绍了 [PARK 堆栈](https://www.oreilly.com/radar/what-is-the-park-stack/)（PyTorch、AI 模型、Ray 和 Kubernetes）如何成为生产 AI 的行业标准。 Ray 长期以来一直是 GPU 上 PyTorch 工作负载普遍存在的分布式运行时。

今天，Anyscale 和 Google Cloud 宣布在 Google TPU 上对 PyTorch 提供原生 Ray 支持，这是为 Gemini 和 Google Cloud 上的大规模 AI 工作负载提供支持的基础超级计算基础设施。

这种集成以 Google 的 [TorchTPU 项目](https://cloud.google.com/blog/topics/ai-infrastructure/torchtpu-is-now-open-source-run-native-pytorch-on-tpus) 和 Google Kubernetes Engine (GKE) 上的 KubeRay 为基础，为 Cloud TPU 带来了本机、每个工作人员单设备的 PyTorch 体验。在 GKE 上运行的平台和 ML 团队现在可以在单个 Kubernetes 控制平面上跨 GPU 和 TPU 调度、扩展和操作分布式 PyTorch 训练、vLLM 推理和强化学习 (RL) 工作负载。

## Google TPU 上的 LinkNative PyTorch

从历史上看，在 Ray 上运行 TPU 工作负载需要适应主要为 JAX 设计的单程序、多数据 (SPMD) 执行模型，其中每个主机虚拟机有一个 Ray 工作进程管理所有机器连接的 TPU 芯片。 [TorchTPU](https://cloud.google.com/blog/topics/ai-infrastructure/torchtpu-is-now-open-source-run-native-pytorch-on-tpus) 去年推出，作为 Google 张量处理单元的原生 PyTorch 后端，带来了急切优先的原生 TPU 集成和“torch.distributed”扩展，用于在 TPU 上运行分布式工作负载。

继 TorchTPU 之后，我们将 Ray 发展为每个 TPU 芯片运行一个工作程序，这与 PyTorch 开发人员在 GPU 上习惯使用的单设备每个工作程序模型相匹配。

当使用 Ray 和 TorchTPU 调度任务或 actor 时，每个工作线程请求一个逻辑 TPU 设备 (`resources={"TPU": 1}`)，就像 GPU 工作线程请求 `num_gpus=1` 一样：

- **设备隔离：** 正如 Ray 自动为 GPU 工作线程设置“CUDA_VISIBLE_DEVICES”一样，Ray 使用“TPU_VISIBLE_CHIPS”隔离各个 TPU 设备并将其分配给工作线程
- **本机 PyTorch 设备和集合：** 在 Ray 任务或 Actor 内，将现有 PyTorch 代码从 GPU 迁移到 TPU 就像将“cuda”更改为“tpu”并将分布式通信后端从“nccl”切换到“tpu_dist”一样简单。
- **拓扑感知组调度：** GKE 将多主机 TPU 切片提供为通过高速芯片间互连 (ICI) 连接的节点池。为了利用这种物理布局，Ray 的 [SlicePlacementGroup](https://docs.ray.io/en/latest/ray-core/api/doc/ray.util.tpu.SlicePlacementGroup.html) API 提供了一个本机调度实现，保证 Actor 在同一个 TPU 切片上一起调度。

下面是在 TPU 上使用 Ray actor 的分布式 PyTorch“all_reduce”的示例。除了资源请求和设备/后端字符串之外，代码与在 GPU 上运行的 Ray actor 相同：
```
import os
import ray
import torch
import torch.distributed as dist

# On GPU: @ray.remote(num_gpus=1)
@ray.remote(resources={"TPU": 1})
class TorchWorker:
    def __init__(self, rank: int, world_size: int):
        self.rank = rank
        self.world_size = world_size
        # Ray automatically isolates the assigned device via TPU_VISIBLE_CHIPS
        self.local_rank = os.environ["TPU_VISIBLE_CHIPS"]

    def run_all_reduce(self, master_addr: str, master_port: int):
        os.environ["MASTER_ADDR"] = master_addr
        os.environ["MASTER_PORT"] = str(master_port)
        os.environ["WORLD_SIZE"] = str(self.world_size)
        os.environ["RANK"] = str(self.rank)
        os.environ["LOCAL_RANK"] = self.local_rank

        # On GPU: dist.init_process_group(backend="nccl")
        dist.init_process_group(backend="tpu_dist")

        # On GPU: device = torch.device("cuda")
        device = torch.device("tpu")
        tensor = torch.ones(2, 2, device=device) * self.rank

        dist.all_reduce(tensor, op=dist.ReduceOp.SUM)
        return tensor.cpu().numpy()
```
## TPU 上的 LinkTorchTrainer

对于分布式训练和微调，许多团队依靠 Ray Train 的“TorchTrainer”来编排分布式数据并行 (DDP)、完全分片数据并行 (FSDPv2) 和 DTensor 工作负载，而无需为分布式进程组编写手动样板。

借助 Ray Train 中的原生 TorchTPU 支持，您现在可以在单主机和多主机 Cloud TPU 切片上运行现有的“TorchTrainer”脚本，对 PyTorch 训练循环进行零更改。

当您通过“ScalingConfig”为 TPU 配置“TorchTrainer”时，Ray Train 会自动处理所有底层 TPU 编排：

- **原子 TPU 切片预留：** 通过指定 `use_tpu=True` 以及目标 `topology`（例如，`"4x4"`）和 `accelerator_type`（例如，`"TPU-V6E"` 或 `"TPU-V7X"`），`TorchTrainer` 会自动在后台提供一个 `SlicePlacementGroup`。这保证了所有训练工作线程都通过高速 ICI 被分组调度到连续的物理 TPU 切片上，从而防止资源碎片。
- **自动化 **`**tpu_dist**`** Bootstrap：** Ray Train 为每个 TPU 设备生成一个工作程序 (`resources_per_worker={"TPU": 1}`)，自动配置 PyTorch 分布式环境变量 (`RANK`、`WORLD_SIZE`、`LOCAL_RANK`、`MASTER_ADDR`、`MASTER_PORT`) 以及 TorchTPU 的切片构建器地址和网格拓扑，并初始化“tpu_dist”进程组。
- **插入式 Ray Train 实用程序：** 标准 Ray Train 辅助函数，如“ray.train.torch.get_device()”和“ray.train.torch.prepare_model()”会自动检测 TorchTPU 运行时，将模型移动到指定的“tpu”设备，并将其包装在 PyTorch 的 DistributedDataParallel 类中。

以下是使用“TorchTrainer”在 16 芯片多主机 Trillium（“TPU-V6E”、“4x4”拓扑）切片上扩展 PyTorch 训练循环的完整示例：
```
import ray
from ray import train
from ray.train import ScalingConfig
from ray.train.torch import TorchTrainer
import torch
from torch import nn, optim
import torch.distributed as dist

def train_fn_per_worker(config):
    # Automatically resolves to torch.device("tpu") on TPU workers
    device = ray.train.torch.get_device()

    model = nn.Sequential(
        nn.Linear(10, 32),
        nn.ReLU(),
        nn.Linear(32, 1),
    ).to(device)

    # Wraps the model in DDP over the "tpu_dist" backend
    model = ray.train.torch.prepare_model(model)

    criterion = nn.MSELoss()
    optimizer = optim.SGD(model.parameters(), lr=0.05)

    inputs = torch.randn(128, 10, device=device)
    targets = inputs.sum(dim=1, keepdim=True)

    for epoch in range(10):
        optimizer.zero_grad()
        outputs = model(inputs)
        loss = criterion(outputs, targets)
        loss.backward()
        optimizer.step()

        train.report({"loss": loss.item(), "epoch": epoch + 1})

scaling_config = ScalingConfig(
    num_workers=16,
    use_tpu=True,
    topology="4x4",
    accelerator_type="TPU-V6E",
    resources_per_worker={"TPU": 1},
)

trainer = TorchTrainer(
    train_loop_per_worker=train_fn_per_worker,
    scaling_config=scaling_config,
)

result = trainer.fit()
```
有关 Google Kubernetes Engine (GKE) 的完整端到端演练，请参阅[使用 Ray 和 TorchTPU 在多主机 TPU 上训练模型](https://docs.cloud.google.com/kubernetes-engine/docs/tutorials/train-models-tpu-ray-torchtpu)。

## LinkvLLM-TorchTPU 与 Ray Serve

对于在线推理，[vLLM-TorchTPU](https://github.com/vllm-project/vllm-torchtpu) 将 TorchTPU 注册为 vLLM 平台插件，以便 PyTorch 模型在 Cloud TPU 上编译和执行，而无需在 JAX 中重写模型定义。结合 [Ray Serve LLM](https://docs.ray.io/en/latest/serve/llm/index.html)，您可以使用 GPU 上使用的相同声明性“LLMConfig” API 跨单主机和多主机 TPU 切片部署 OpenAI 兼容的 vLLM 端点。

当“accelerator_type”和“accelerator_config”指定 TPU 切片时，Ray Serve 为每个副本保留一个拓扑感知的“SlicePlacementGroup”，并跨切片启动 vLLM 引擎工作线程：
```
from ray.serve.llm import (
    LLMConfig,
    LLMServingArgs,
    ModelLoadingConfig,
    build_openai_app,
)
llm_config = LLMConfig(
    model_loading_config=ModelLoadingConfig(
        model_id="google/gemma-4-26B-A4B-it",
    ),
    # On GPU: accelerator_type="H100"
    accelerator_type="TPU-V6E",
    accelerator_config={
        "kind": "tpu",
        "topology": "4x4",
    },
    placement_group_config={
        "bundle_per_worker": {"TPU": 1},
    },
    engine_kwargs={
        "tensor_parallel_size": 16,
        "enable_expert_parallel": True,
        "max_model_len": 8192,
    },
)
app = build_openai_app(LLMServingArgs(llm_configs=[llm_config]))
```
有关 Google Kubernetes Engine (GKE) 的完整端到端演练，请参阅[使用 Ray 和 TorchTPU 在多主机 TPU 上提供 LLM](https://cloud.google.com/kubernetes-engine/docs/tutorials/serve-llm-tpu-ray-torchtpu)。

## Link将 PARK 堆栈扩展到 TPU

随着 AI 工作负载从独立的训练作业发展为结合训练、高通量推理和强化学习的复合系统，组织正在开源 PARK 堆栈（PyTorch、AI 模型、Ray 和 Kubernetes）上进行标准化。将 TorchTPU 引入 Ray 和 GKE 在 Google Cloud 上完成了这一愿景：PyTorch 开发人员保留了他们已知的急切执行模型和 Ray API，而平台团队则获得了 GKE 的拓扑感知自动扩展、弹性和多加速器治理。

要立即开始，请探索使用 Ray 和 TorchTPU 的[服务 LLM](https://cloud.google.com/kubernetes-engine/docs/tutorials/serve-llm-tpu-ray-torchtpu) 或[训练模型](https://docs.cloud.google.com/kubernetes-engine/docs/tutorials/train-models-tpu-ray-torchtpu) 的端到端 GKE 教程，敬请关注我们将此基础扩展到 GKE 上的大规模 RL 后训练框架和下一代 Ironwood (TPU v7x) 切片。
