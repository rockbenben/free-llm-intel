# 向 CNCF 捐赠 KubeRay

作者：[Andrew Sy Kim (Google)](https://www.anyscale.com/blog?author=andrew-sy-kim-google)、[Edward Oakes](https://www.anyscale.com/blog?author=edward-oakes)、[Kai-Hsun Chen](https://www.anyscale.com/blog?author=kai-hsun-chen)、[Jui-An Huang](https://www.anyscale.com/blog?author=jui-an-huang)、[Richard Liaw](https://www.anyscale.com/blog?author=richard-liaw)、[Robert Nishihara](https://www.anyscale.com/blog?author=robert-nishihara) 和 [KubeRay 团队](https://www.anyscale.com/blog?author=the-kuberay-team) | 2026 年 11 月 9 日

PARK stack（PyTorch、AI 模型、Ray 和 Kubernetes）正在成为生产 AI 事实上的开源标准。在这套技术栈里，[KubeRay](https://github.com/kuberay-project/kuberay) 已成为一座桥梁，把基于 Ray 构建的可扩展 AI 应用与 Kubernetes 的计算编排连到一起。

PARK stack 里几乎每一个核心组件都已经归属 Linux Foundation：PyTorch 和 Ray 经由 PyTorch Foundation，Kubernetes 经由 Cloud Native Computing Foundation (CNCF)。缺的那一块就是 KubeRay。

今天，我们宣布 KubeRay 加入 CNCF，整个 PARK stack 由此纳入 Linux Foundation 的治理，也让各团队对它的中立与开放更有信心。

## Link在 Kubernetes 上扩展 Ray 集群

KubeRay 是一套功能强大的开源工具包和 Kubernetes operator，用来把 Ray 驱动的分布式 AI、机器学习和 Python 工作负载无缝跑在云原生基础设施上。随着分布式 AI 工作负载成为云原生的基础构件，KubeRay 弥合了 Python 优先的 AI 框架与 Kubernetes 原生基础设施之间的落差。

![Kubernetes 原生基础设施](https://images.ctfassets.net/xjan103pcp94/1btTPrJds1cvpaScrP0wLf/31e6436d2d5532237184923cb2be64a3/Kubernetes-native_infrastructure.png)

Kubernetes 原生基础设施

KubeRay 提供三个 Kubernetes Custom Resource Definitions (CRDs)，用于在生产环境中扩展和运行 Ray 工作负载：

- **RayCluster:** 在 Kubernetes 上运行 Ray 的基础构件。`RayCluster` 管理 Ray 集群的完整生命周期，自动完成 head 与 worker pod 的配置、健康检查、Global Control Service (GCS) 容错，以及与 Ray Autoscaler 协同的动态自动扩缩容。
- **RayJob:** 专为批处理、分布式训练和强化学习 (RL) 工作负载打造。`RayJob` 会自动拉起一个临时的 `RayCluster`，集群就绪后提交 Ray 作业，完成后再把集群拆掉，以尽量压满计算和加速器的利用率。
- **RayService:** 面向用 Ray Serve 做的长时、高可用在线推理。`RayService` 同时管理底层的 `RayCluster` 和 Ray Serve 部署图，让生产 AI 服务具备零停机滚动升级、自动故障转移和无缝流量路由。

这些自定义资源合在一起，为企业基于 Ray 和 Kubernetes 搭建现代机器学习平台打下基础。比如 Hark 这样的最终用户就用 KubeRay 来扩展自己的 AI agent 工作流。

> “大规模跑多模态 AI 工作负载，需要一个把 Python 优先的 AI 与 Kubernetes 紧密集成的平台。KubeRay 就是这座桥，帮我们可靠地扩展、管理复杂的 agentic 工作流。在 Hark，这正是我们用它、也为它做贡献的原因：我想帮更多构建者放心地把生产 AI 跑起来。”Kai-Hsun Chen，Hark AI 基础设施负责人

## Link壮大 KubeRay 生态

除了核心的集群生命周期管理，KubeRay 之所以被广泛采用，还在于它与其他 CNCF 项目以及更广阔的云原生生态集成得很深。它没有另起炉灶重造基础设施原语，而是直接接进平台团队已经在用的工具：

- **用 OpenTelemetry、Prometheus 和 Fluent Bit 做可观测性：** Ray 在指标管道里使用 OpenTelemetry，并以 Prometheus 格式暴露指标，让运行 KubeRay 的平台团队能把集群利用率、任务执行和 Ray Serve 延迟，连同现有的 Kubernetes 基础设施一起监控。再配合 Fluent Bit 做轻量级日志采集与转发，运维人员就能轻松汇总临时和长时 Ray 集群里分散的 worker 与作业日志。
- **用 Kueue、Volcano 和 KAI 做批量调度与配额管理：** 当企业在稀缺的 GPU 和 TPU 资源上扩大分布式训练时，KubeRay 与各种调度器原生集成，把 Kubernetes 原生的作业排队带给 `RayJob` 和 `RayCluster`。由此可以实现 gang scheduling（pod 要么全放、要么全不放）、多租户资源配额、优先级抢占和拓扑感知调度。
- **工作负载安全与隔离： **随着 AI 工作负载规模扩大，扎实的安全和多租户能力变得关键。KubeRay 通过自动化 mTLS 和 Kubernetes 网络策略，为保护 Ray 集群提供了基础。
