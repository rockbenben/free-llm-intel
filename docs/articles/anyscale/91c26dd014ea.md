# 引入标签选择器：提高 Ray 中的调度灵活性

作者：[Mengjin Yan](https://www.anyscale.com/blog?author=mengjin-yan) 和 [Ryan O'Leary (Google)](https://www.anyscale.com/blog?author=ryan-oleary-google) | 2025 年 10 月 30 日

*感谢所有为该项目做出贡献的人，包括：来自 Anyscale 的 Edward Oakes、Janet Li、Bruce Zhang、AlanGuo、Douglas Strodtman、Jui-An Huang、Han-Ju Chen，以及来自 Google、GKE 团队的 Andrew Sy Kim。*

今天，我们与 Google Kubernetes Engine 团队合作，向 Ray 引入标签选择器，这是一种将工作负载放置在正确节点上的更直接的方法。 API 和 UI 在 Ray 2.49 中提供，可在 Ray Dashboard、KubeRay 和 [Anyscale](https://www.anyscale.com/product/platform)（基于 Ray 构建的 AI 计算平台）上使用。

借助新的标签选择器 API，Ray 现在可以直接帮助开发人员完成以下任务：

- 为 Ray 集群中的节点分配标签（例如 `cpu-family=intel`、`market-type=spot`、`region=us-west-1`）
- 启动任务时，参与者或安置组声明诸如*“仅在英特尔芯片节点上运行”*之类的内容

借助这个新的 API，团队能够获得更好的开发体验，能够更轻松地使用标签描述调度意图，而不是黑客攻击（更多详细信息见下文），并且从第一天起就可以通过 UI 和 API 支持更轻松地调试布局。

## Link旧的解决方法

当 Ray 开发人员只想在 Ray 集群中的点节点上调度一些任务时，他们通常会在启动 Ray 节点时伪造一个“点”自定义资源，然后为每个任务请求一小部分 (0.01) – 希望不超过 100 个任务同时位于一个节点上，从而耗尽“点”资源。
```
1ray start --resources '{"CPU": 8, "spot": 1}'
```

```
1@ray.remote(resources={"spot": 0.01})
2def func():
3    pass
```
上述解决方法突出了一类调度限制：非资源约束（现货与按需）被伪造为“资源”。这将资源数量（CPU/GPU/RAM）与放置约束（区域/区域、现货与按需）混为一谈，并强制将非资源需求建模为资源。

第二个同样常见的限制是仅精确匹配：许多 Ray 开发人员需要任意或否定匹配 - 例如，“不在 GPU 节点上”或“在 us-west1-a 或 us-west1-b 中” - 以前的 API 无法表达。

借助标签选择器，Ray 开发人员能够解决这两个限制。它们使您可以使用在 RayCluster 创建时定义的或由 Ray 自动检测的节点标签（例如加速器类型）灵活地表达任务、参与者和置放组捆绑包的调度要求。

Ray 标签选择器从 Kubernetes [标签和选择器](https://kubernetes.io/docs/concepts/overview/working-with-objects/labels/) 中汲取灵感，通过使用熟悉的 API 和语义来增强两个系统之间的调度互操作性。这是 Ray 和 Kubernetes 共同努力解锁更高级用例的众多持续举措之一。

您可以使用标签做什么：

- 固定到特定节点（通过节点 ID）
- 在头节点或工作组上运行/避开
- 仅 CPU 放置
- 针对特定加速器或组
- 选择节点市场类型（现货或按需）
- 将工作保留在地区或区域内/外
- 按 CPU 系列（或其他主机特征）选择
- 目标 TPU 豆荚切片

请参阅 [Anyscale](https://docs.anyscale.com/configuration/compute/advanced#labels) 和 [Ray 指南](https://docs.ray.io/en/releases-2.50.0/ray-core/scheduling/labels.html) 了解使用说明和完整的 API 详细信息。

## LinkLabel 选择器 API

### 用户代码中的 LinkLabel 选择器

标签选择器使您可以通过与节点标签匹配来表达工作应该在哪里运行。

您可以将标签选择器添加到：

- 任务/参与者：“@ray.remote(...)”中的“label_selector”
- 归置组：`bundle_label_selector=[...]`在创建时

支持的语义：匹配、不匹配、任意、非任意

回到上面的示例，下面是表达这些要求的方式：
```
1import ray
2from ray.util.placement_group import placement_group
3
4# Schedule a task on spot instances only
5@ray.remote(label_selector={"ray.io/market-type": "spot"})
6def func():
7    pass
8
9# Placement group: avoid GPU worker group and run in us-west-1 or us-west-2
10pg = placement_group(
11    [{“CPU”: 1}] * 2, 
12    bundle_label_selector=[
13        {
14            "ray.io/node-group": "!gpu-node-group", 
15            "ray.io/region": "in(us-west-1,us-west-2)"
16        }
17    ] * 2,
18)
19
```
相同的代码可以在开源 Ray、Kubernetes 或 Anyscale 等托管提供商上可移植地运行。

### 链接节点标签

节点标签使用用于调度的属性来注释节点（例如，CPU 系列、加速器类型、现货/点播的市场类型、区域/区域）。您可以：

- 创建集群时定义标签（Anyscale UI/SDK、KubeRay RayCluster CR 或“ray start”）。
```
1# KubeRay RayCluster CR: Label nodes in a worker group with AMD CPU
2spec:
3 workerGroupSpecs:
4  - replicas: 1
5    labels:
6      cpu-family: amd
7
```

```
1# ray start: Label a node with AMD CPU
2ray start --labels="cpu-family=amd"
```
- 在 Anyscale UI 上：使用 AMD CPU 标记工作组中的节点

依赖 Ray 和 Anyscale 提供的自动检测标签（例如加速器类型）。在 Anyscale 上，会填充其他默认标签（市场类型、地区/区域）以实现更灵活的放置。 [请参阅文档以了解有关默认标签的更多信息](https://docs.anyscale.com/configuration/compute/advanced#head-node)。默认标签列表：

| **标签名称** | **描述** | **支持 Anyscale** | **OSS 支持** |
| --- | --- | --- | --- |
| `ray.io/node-id` |为节点生成的唯一 ID。 |是的 |是的 |
| `ray.io/加速器类型` |节点的加速器类型，例如L4。 |是的 |是的 |
| `ray.io/market-type` |指示节点是使用现货实例还是按需实例。 |是的 |否* |
| `ray.io/node-group` |节点工作组的名称或头节点的头。 |是的 |否* |
| `ray.io/region` |节点的云区域。 |是的 |否* |
| `ray.io/可用区` |节点的可用区域。 |是的 |否* |

注意：* 默认情况下不会填充默认标签。但是，如果在光线启动参数或 KubeRay CR 中的顶级“labels”字段中指定了标签，您仍然可以使用这些标签。

### LinkAutoscaling集群

标签选择器适用于静态和自动缩放集群。

在 Anyscale 上，自动缩放器会考虑资源形状和标签选择器，缩放适当的工作组，以便调出具有所需标签的节点。开源 Ray 中标签选择器的自动缩放支持将在 Ray 2.51 中发布。

## 链接它是如何工作的？

当您提交任务或创建参与者或放置组时，Ray 会将相应的标签选择器 (label_selector/bundle_label_selector) 附加到请求。每个节点的 Raylet 保存节点的标签（用户在 RayCluster 创建时定义或自动检测，例如加速器系列）以及来自所有节点的其他节点元数据。 Raylet 中的调度程序使用选择器和节点标签信息来做出放置决策：它检查标签匹配并执行正常的资源适配。仅当两项检查都通过时，该请求才被视为可调度到节点。

在自动缩放集群中，Ray 全局控制存储 (GCS) 聚合标签选择器未满足的需求以及资源需求，并将其发送到自动缩放器。自动缩放器使用这些信息来缩放适当的工作组，以便它显示具有所需标签的节点。

## LinkFuture 工作

当前的标签选择器是一个很好的起点，但我们有更多计划来使其变得更好。

- **后备标签选择器（有序首选项）**：如今，每个请求都带有一个标签选择器。我们计划支持每个任务/参与者/置放组捆绑包的有序回退，以便您可以表达有序意图，例如首选加速器=H100，否则加速器位于{A100，H100}。
- **库支持：** 将标签选择器支持扩展到 Ray 库（例如 Ray Data、Ray Serve、Ray Train），以便自动处理常见的调度模式。
- **改进与 Kubernetes 的互操作性：**我们希望尽可能轻松地从 Kubernetes Pod 继承标签并以 Kubernetes 原生方式影响 Pod 调度。
