# Ray 2.0 正式发布

作者：Anyscale Ray Team | 2022 年 8 月 23 日

今天，我们兴奋地宣布 Ray 2.0。在这个大版本中，我们朝"让分布式计算可扩展、统一、开放"的目标迈出了坚实步伐。

围绕这些目标，Ray 2.0 带来了统一机器学习（ML）生态的新能力、改善了 Ray 的生产支持，并让 ML 从业者比以往更容易使用 Ray 的库。

## 统一 ML 生态

**Ray AI Runtime——面向 ML 应用的可扩展统一工具包***

自诞生以来，Ray 一直用于加速和扩展计算密集的机器学习负载。以 beta 形式发布的 Ray AI Runtime（AIR）是对经验教训的一次沉淀：我们与社区用户交流，兼顾他们或大或小的使用场景。这一刻意努力最终为 Ray 社区带来了简洁、统一的工具包。

借助 Ray AIR，我们让 Ray 现有的原生 ML 库无缝协作，并轻松与社区流行 ML 框架集成。Ray AIR 的目标是：几行 Python 代码即可运行任意类型的 ML 负载，把大规模计算协调的重活交给 Ray。

你可以在[文档](https://docs.ray.io/en/releases-2.0.0/ray-air/getting-started.html)中了解更多关于 Ray AIR（beta）的内容。

### **面向 ML 负载的大规模 Shuffle**

许多 ML 用户告诉我们：如果 Ray 支持大数据 shuffle，他们就能简化基础设施、更统一地押注 Ray。在 Ray 2.0 中这已成现实：Ray 现在原生支持用 Ray Datasets 库 shuffle 100TB 甚至更多数据。入门方法见[文档](https://docs.ray.io/en/releases-2.0.0/data/performance-tips.html#improving-shuffle-performance)，分布式 shuffle 的实现细节参见我们的[技术论文](https://arxiv.org/abs/2203.05072)。

## 生产与规模

**经由 KubeRay 提供 Kubernetes 生产支持**

KubeRay 由 Ray 社区与 [ByteDance](https://www.bytedance.com/en/)、[Microsoft](https://www.microsoft.com/) 合作开发，让在 [Kubernetes](https://kubernetes.io/) 上部署基于 Ray 的作业与服务比以往更简单，并取代了旧版基于 Python 的 Ray operator。目前处于 beta 的 KubeRay 是在 K8s 上运行 Ray 的官方推荐方式。了解更多请见[这里](https://docs.ray.io/en/releases-2.0.0/cluster/kubernetes/index.html)。

**大规模 Ray Serve 部署的高可用**

**借助 KubeRay，你可以轻松以容错和 HA 模式部署 Ray Serve 集群，省去了以往为此所需的大量运维工作。你可以以故障转移（fail-over）模式部署服务，或把 Ray 集群以完全 HA 模式（alpha）部署，从而消除集群中的任何单点故障。在 KubeRay 上部署 Serve 的详情见[这里](https://docs.ray.io/en/releases-2.0.0/serve/production-guide/kubernetes.html)。

**全新 Ray 可观测性工具**

是否一直想查看你的 Ray 负载里发生了什么？Ray 2.0 新增 Ray State Observability API（alpha），让开发者看到 Ray 负载的健康与性能状况。了解更多请见[这里](https://docs.ray.io/en/releases-2.0.0/ray-observability/state/state-api.html)。

## 更简洁、更强大的库 API

### **Ray Serve Deployment Graph——多步、多模型推理化繁为简**

组合或串联多个模型完成一次预测，已成为现代 ML 应用中的常见模式。Ray Serve 灵活的执行模型使它一直是这类用例的热门选择。

在此基础上，我们很高兴推出 Ray Serve 的 **Deployment Graph API**——一种构建、测试和部署部署（deployment）推理图的全新简便方式。Deployment Graph 构建在 Ray 直观的任务与 actor API 之上，让混合模型与业务逻辑的推理流水线对每位 ML 从业者触手可及。

目前处于 beta 的 deployment graph 详情见[这里](https://docs.ray.io/en/releases-2.0.0/serve/model_composition.html)。

### **RLlib——开发者 API 更新与离线强化学习改进**

在 Ray 2.0 中，RLlib 团队重构了所有关键 RLlib 算法的实现，采用更简单的命令式模式，使实现新算法或调整现有算法更加容易。关于这些新模式的内容见[这里](https://docs.ray.io/en/releases-2.0.0/rllib/core-concepts.html#training-step-method-algorithm-training-step)。

RLlib 还引入了新的 Connectors API，让环境与策略模型之间的预处理"胶水"对用户更显式、更透明，从而简化 RLlib 模型的部署。

最后，Ray 2.0 新增了面向生产强化学习负载的算法与功能。RLlib 现已支持 Critic Regularized Regression（CRR）——一种离线 RL 的最先进算法，以及 Doubly Robust Off-Policy Estimator——一种策略评估算法。了解更多关于 RLlib 离线 RL 支持的内容见[这里](https://docs.ray.io/en/releases-2.0.0/rllib/rllib-offline.html)。

## 小结

总之，Ray 2.0 是我们"为 ML 从业者与基础设施团队简化计算"这一目标的重要一步。凭借这些新增强，Ray 2.0 为更广泛的社区打开了新思路、新机会与新应用。
