# Ray 1.13：改进 TB 级及更大数据集的 Shuffle 支持

作者：Stephanie Wang、Jiao Dong、Dmitri Gekhtman 和 Sang Cho | 2022 年 6 月 9 日

Ray 1.13 来了！本版本的亮点包括：

- **Ray Datasets 的可扩展 shuffle**（现为 alpha），改进对 TB 级及更大数据集 shuffle 的支持
- 对 Ray Serve Deployment Graph API 的**性能修复与其他增强**
- **KubeRay 增强**，包括自动扩缩支持（alpha）的稳定性改进
- **使用统计数据收集**，现默认开启（有 opt-out 提示守护），帮助开源 Ray 工程团队更好地理解该如何改进库与核心 API

运行 `pip install -U ray` 即可使用这些特性及更多内容。下面展开介绍。

## Ray Datasets 改进对 TB 级及更大数据集 shuffle 的支持

使用 Ray Datasets 做 ML 摄取或排序并调用 `random_shuffle` 的大规模用户（TB 级及以上数据集、和/或 1,000+ 分区）——这是为你们准备的。我们改进了对 TB 级及更大数据集 shuffle 的支持（现为 alpha）。受影响的 API 是 `Dataset.random_shuffle` 与 `Dataset.sort`。除了 Ray Core 的稳定性改进，我们还在 Datasets 库中引入了一种新的 shuffle 算法，以扩展到更大的集群与数据集。更多信息请[查看文档](https://docs.ray.io/en/master/data/performance-tips.html#improving-shuffle-performance)。

***冷知识****：这个特性的灵感来自 Anyscale 团队共同撰写的一篇*[*学术论文*](https://arxiv.org/abs/2203.05072)*——团队也会在*[*Ray Summit 上就此话题做演讲*](https://www.anyscale.com/ray-summit-2022/agenda/sessions/220)*。*

关于 1.13 中 Ray Datasets 改进的更多细节，请[阅读发布说明](https://github.com/ray-project/ray/releases/tag/ray-1.13.0)。

**注**：[Ray AI Runtime（AIR）](https://docs.ray.io/en/master/ray-air/getting-started.html)目前处于 alpha。在 Ray AIR beta 发布之前，我们计划改进 Ray Datasets 与 Ray AIR 集成的文档与范围。

## Deployment Graph API 增强

Ray 1.13 为 [Ray Serve Deployment Graph API](https://www.anyscale.com/blog/multi-model-composition-with-ray-serve-deployment-graphs) 带来性能修复与其他增强。该 API 以 Python 原生方式创建由多个模型组成的复杂推理图来完成一次推理或预测，例如链式、集成（ensemble）与动态控制流。

该 API 也已接近 beta——但我们需要你的反馈！如果你想让 Deployment Graph API 更好地服务自己的用例，请到我们的[用户论坛](https://discuss.ray.io/c/ray-serve/6)留言、在 [GitHub](https://github.com/ray-project/ray) 上提 issue 或功能请求，或[通过这个表单联系我们](https://docs.google.com/forms/d/1l8HT35jXMPtxVUtQPeGoe09VGp5jcvSv0TqPgyz6lGU)。我们迫不及待想与你在项目里一起用起来 Ray Serve！

关于用 Ray Serve 创建推理图的更多内容，可以[观看我们最近的 Ray Meetup](https://www.meetup.com/Bay-Area-Ray-Meetup/events/284051590/)，或[阅读文档中的完整端到端演练](https://docs.ray.io/en/latest/serve/deployment-graph.html#full-end-to-end-example-walkthrough)。

## KubeRay 改进的自动扩缩支持

[KubeRay](https://www.anyscale.com/blog/new-in-kuberay-0-2-0-autoscaling-alpha-simplified-installation-and-more) 是在 Kubernetes 上运行 Ray 应用的工具包。自 [Ray 1.12.0 发布](https://www.anyscale.com/blog/ray-1-12-ray-ai-runtime-alpha-usage-data-collection-and-more)以来，我们提升了自动扩缩支持（现为 alpha）的稳定性，并引入了 CI 测试，保证使用 KubeRay operator 部署时自动扩缩、Ray Client 与 Ray Job Submission 的功能正确。

## 使用统计数据收集

从 Ray 1.13 开始，Ray 默认收集使用统计数据（有 opt-out 提示守护）。开源 Ray 工程团队将用这些数据更好地理解如何改进我们的库和核心 API、如何排定 bug 修复与增强的优先级。

我们收集政策的指导原则：

- **不搞意外**：开始收集数据前会通知你；收集内容或使用方式有任何变化都会通知你。
- **轻松退出**：你可以随时方便地选择退出数据收集。
- **透明**：你可以审阅发送给我们的全部数据。
- **控制权**：你拥有自己数据的控制权，我们会遵照请求删除你的数据。
- 我们**不会**收集任何个人身份数据或专有代码/数据。
- 我们**不会**出售数据，也不会购买关于你的数据。

详情见[官方文档](https://docs.ray.io/en/master/cluster/usage-stats.html#usage-stats-collection)或 [RFC](https://github.com/ray-project/ray/issues/20857)。

## 其他亮点

- Python 3.10 支持现为 alpha。
- Ray Tune 现在可以通过对象存储在 worker 节点间同步 Trial 数据（不再需要 rsync！）。
- Ray Workflow 带来新 API 并与 Ray DAG 集成。
