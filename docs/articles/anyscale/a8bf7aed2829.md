构建[检索增强生成（RAG）](https://www.anyscale.com/blog/a-comprehensive-guide-for-building-rag-based-llm-applications-part-1)应用的第一步，是为数据创建嵌入（embedding）——向量数据库用于搜索与检索的意义和上下文的表示。创建嵌入面临若干挑战：

- **规模：** TB 级数据集很常见，且负载内存密集。规模伴随成本。
- **异构计算：** 嵌入计算涉及数据摄取、预处理、切块与推理，需要 CPU 与 GPU 计算混搭。更具挑战的是，可能还需要混合多种 GPU 型号。
- **多模态数据：** RAG 应用要处理文档、图像以及越来越多的数据模态。

我们很高兴宣布：借助 [Anyscale](https://www.anyscale.com/) 与 [Pinecone](https://www.pinecone.io/)，用户现在能以其他流行方案 10% 的成本，为分布式向量数据库生成嵌入！

## **突破性向量数据库，成本最多省 50 倍**

随着这次发布，Pinecone 通过彻底重构向量数据库，进一步巩固其技术与市场领导地位。这一开创性的 serverless 向量数据库让企业以前所未有的 2% 成本为 GenAI 应用添加无限知识。用 Pinecone serverless，你可以存储数十亿向量，只为搜索的部分付费。

带来成本节省与高性能的关键创新包括：

- 读、写与存储的分离，为各种类型和规模的负载显著降低成本。
- 首创架构：在 blob 存储之上做向量聚类，以低成本对几乎无限的数据规模提供低延迟、始终新鲜的向量搜索。
- 新型索引与检索算法，让向量搜索能在 blob 存储上快速、内存高效地进行，而不牺牲检索质量。
- 多租户计算层，为上千用户提供按需的强效检索。这成就了 serverless 体验：开发者无需配置、管理甚至考虑基础设施；按用量计费让公司只为自己使用的部分付费。

## **与其他嵌入计算方案对比**

计算嵌入时，常见的做法有这么几种：

- **OpenAI：** OpenAI 这类 API 服务商能处理嵌入计算，但数据摄取与预处理需要另外的可扩展方案，模型选择的灵活性也有限。
- **Spark：** Spark 这类分布式框架能扩展数据摄取与预处理，但高效的嵌入计算需要另外的方案。
- **Vertex AI：** Google Cloud 能处理数据摄取与预处理，Vertex AI 能处理嵌入计算。与 OpenAI 类似，模型选择灵活性有限。

上述方案都不是能同时规模化处理数据摄取与嵌入计算、又在预处理步骤与嵌入模型上保留灵活性的全家桶方案。

**RAG 整体技术栈**

*Pinecone Partners Launch*

往大了看，嵌入计算只是图景的一部分。构建 RAG 应用需要很多拼图：

- 一个高性能分布式向量数据库（如 [Pinecone](https://www.pinecone.io/)）必不可少，用以支持基于所算嵌入的高效插入与查询。
- [Hugging Face](https://huggingface.co/) 与 [LangChain](https://www.langchain.com/) 提供用于计算嵌入的开源模型与工具。
- 最后，一个分布式计算引擎（如 [Ray](https://github.com/ray-project/ray/)）把所有这些元素粘合起来，无缝管理端到端工作流。
