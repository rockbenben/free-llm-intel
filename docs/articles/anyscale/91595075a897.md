# Ray 中的数据处理支持

作者：Sang Cho、Alex Wu、Clark Zinzow、Eric Liang 和 Stephanie Wang | 2021 年 2 月 16 日

本文重点介绍最新 Ray 1.2 版本中的两项功能：原生支持溢出到外部存储，以及对 Python 数据处理生态库的支持，包括 PySpark 与 Dask 集成。

过去几年里，许多 Ray 用户向我们表达了愿望：希望把并行数据处理更直接地融入 Python 应用。这些用例从更快处理输入 CSV，到 shuffle 数百 TB 的 ML 输入数据（分布式 ETL）不等。共同诉求是：把数据处理与 ML 组件拼成一个应用，写在同一个 Python 程序里，而不用操心搭建、维护多个独立集群或服务，再把它们粘合起来。

我们没有为 Ray 再写一个 DataFrames 库，而是专注于支持其他框架的集成，从而让你可以：

- **打破计算孤岛：** 在应用代码中直接调用 Dask DataFrames 等数据处理 API，与 Tune、XGBoost、Horovod 等 ML 库并排使用。
- **利用分布式内存：** 自动对象溢出让数据库开发者与用户可以直接享用 Ray 的共享内存对象存储。

### 分布式数据处理与机器学习的统一基座

当今许多团队的常态是用 *workflow orchestrator*（如 [Airflow](https://airflow.apache.org) 或 [Kubeflow](http://kubeflow.org)）把分布式程序串起来。这可以支撑诸如：

- 在批 ETL 作业的结果上运行训练作业（如分布式训练、XGBoost on Ray）。
- 把分别编写的算子（任务）组合成流水线（如 Spark => PyTorch）。

但在很多情况下，workflow orchestrator 的使用会因计算孤岛效应带来代价，体现在**系统效率**与**运维**两方面。

系统效率：

- workflow 任务的启动开销增加延迟，降低作业的成本效率。
- 中间数据必须物化到外部存储（如 HDFS 或 S3），同样增加延迟。

运维层面：

- 为数据处理维护多套独立分布式系统，运维开销高。
- 流水线本身必须用独立的配置语言编写和配置（而非单个 Python 程序），这也限制了表达能力。

> 我们在 Ray 中支持数据处理的目标，是让分布式应用少写胶水代码：提升表达力、降低系统开销。

本文余下部分介绍 Ray 的新对象溢出功能与库集成。

### 对象溢出

我们高兴地宣布，Ray 现已支持[*自动对象溢出（object spilling）*](https://docs.ray.io/en/master/memory-management.html#object-spilling)到本地磁盘与云对象存储（如 S3）。该特性从 [Ray 1.2](https://github.com/ray-project/ray/releases/tag/ray-1.2.0) 起可用，并将在下个版本默认开启。

对象溢出让已在使用 Ray 对象存储的库能够处理放不进内存的数据集，也让 Ray 程序可以直接在大数据集上运行。例如，你现在可以用几十行 Python 写一个简单的[核外分布式 shuffle](https://github.com/ray-project/ray/blob/master/python/ray/experimental/shuffle.py)：

下面是用 Ray 对象溢出为 Dask-on-Ray 启用核外工作负载的例子。注意这段代码对数据集做完整排序，因此不与上面的简单 shuffle 直接对比。

*Dask-on-Ray 排序，Ray 对象溢出关闭 vs. 开启。运行于 32 核机器（AWS i3.8xlarge），Ray 对象存储内存限制 30GB。关闭对象溢出时，应用在 100GB 数据上遭遇 OOM 错误。*

注意，Spark 这类独立系统早已原生支持对象溢出。但对 Modin、Mars 这类库而言，自行实现是巨大的工作量。与 Ray 集成正是可以减轻库开发者负担、为最终用户解锁新负载的地方。工作原理见下一节。

注：要复现这些基准，你需要使用 [nightly wheels](https://docs.ray.io/en/latest/installation.html#daily-releases-nightlies)。也可以安装 [Ray v1.2](https://github.com/ray-project/ray/releases/tag/ray-1.2.0)（`pip install -U ray`）后在命令行运行 `ray install-nightly`。

### 库集成

除另有说明外，以下所有示例都可在 [Ray v1.2](https://github.com/ray-project/ray/releases/tag/ray-1.2.0) 上运行。

### PySpark on Ray

借助 [RayDP](https://github.com/oap-project/raydp) 的 PySpark 支持，几行代码即可发挥 Spark 的威力。RayDP 初始化后，你可以使用任何想要的 PySpark API：

**安装：**

```
1$ pip install ray raydp
```

**示例：**

```
1import ray
2import raydp
3
4ray.init()
5
6@ray.remote
7class PySparkDriver:
8  def __init__(self):
9  self.spark = raydp.init_spark(
10    app_name='RayDP example',
11    num_executors=2,
12    executor_cores=2,
13    executor_memory='4GB')
14
15  def foo(self):
16    return self.spark.range(1000).repartition(10).count()
17
18driver = PySparkDriver.remote()
19print(ray.get(driver.foo.remote()))
```

底层上，`raydp.init_spark` 会创建 num_executors 个 Ray Java *actor*，每个 actor 启动一个 Spark executor。这些 actor 之间通过 Spark 内部 IO 层通信。上面的示例用 PySparkDriver actor 类包装 Spark 会话，使其可被 Ray 应用的其他部分调用。注意该集成不使用 Ray 的对象存储，与下文其他集成不同。

想深入了解 RayDP，请查看[文档](https://github.com/oap-project/raydp)。

### Dask on Ray

我们近期发布了[Dask](https://dask.org/)的[轻量插件](https://docs.ray.io/en/master/dask-on-ray.html)，让你可以用 Ray 作为执行 Dask 任务的后端，其中包括针对大规模 shuffle 性能的 Ray 专属[优化](https://github.com/ray-project/ray/issues/13959)。试用方法：

**安装：**

```
1$ pip install ray 'dask[dataframe]' pandas numpy
```

注意：即使使用集群，也无需安装 dask.distributed，因为 Ray 会负责分布式调度。

**示例：**

```
1import ray
2
3import dask
4
5import dask.dataframe as dd 
6import pandas as pd
7import numpy as np
8from ray.util.dask import ray_dask_get
9
10dask.config.set(scheduler=ray_dask_get) # Sets Ray as the default backend.
11
12ray.init()
13
14df = pd.DataFrame(np.random.randint(0, 100, size=(2**10, 2**8)))
15df = dd.from_pandas(df, npartitions=10)
16print(df.head(10))
```

底层上，Dask 把任务分派给 Ray 进行调度与执行，任务输入输出都存进 Ray 的分布式共享内存对象存储。这意味着你可以无缝混用 Dask 与其他 Ray 库的负载。

想深入了解 Dask on Ray，请查看[文档](https://docs.ray.io/en/master/dask-on-ray.html)。

### Modin DataFrames

[Modin DataFrames](https://modin.readthedocs.io/en/latest/supported_apis/index.html) 可以让 Pandas 在 Ray 上透明扩展。试用：

**安装：**

```
1$ pip install 'modin[ray]' pandas numpy
```

**示例：**

```
1import ray
2ray.init() # Modin defaults to backing Ray's object store with disk. Start Ray before importing modin to use shared memory instead.
3
4import modin.pandas as pd
5import numpy as np
6
7frame_data = np.random.randint(0, 100, size=(2**10, 2**8))
8df = pd.DataFrame(frame_data)
9
10print(df.head(10))
```

想深入了解 Modin，请查看[文档](https://modin.readthedocs.io/en/latest/index.html)。

### Mars on Ray

[Mars](https://docs.pymars.org/en/latest/) 是一个基于张量的框架，可以扩展 numpy、Pandas 和 scikit-learn 应用。它近期新增了 [Ray 作为分布式执行后端](https://docs.ray.io/en/master/mars-on-ray.html)。

试用方法：

**安装：**

```
1$ pip install -U pymars ray==1.0
```

注意：即使使用集群，也无需安装 pymars[distributed]，因为 Ray 会负责分布式执行。

**示例**

```
1from mars.session import new_session
2ray_session = new_session(backend='ray').as_default() # Set Ray as the default backend.
3
4import mars.dataframe as md
5import mars.tensor as mt
6
7t = mt.random.randint(100, size=(2**10, 2**8))
8df = md.DataFrame(t)
9print(df.head(10).execute())
```

Mars-on-Ray 集成尚处于实验阶段并在积极开发中，可从[文档](https://docs.ray.io/en/master/mars-on-ray.html)了解更多信息。

### 结语

为第三方数据处理库与框架提供支持，Ray 才刚刚起步。我们正在积极开发对象溢出与内存管理等特性，以提升稳定性与性能。敬请期待我们下一篇关于大规模分布式 shuffle 的博客，它将更好地支撑这些数据处理框架。

在此之前，想进一步了解，请阅读[白皮书](https://docs.ray.io/en/master/whitepaper.html)或加入 [Ray Discourse](http://discuss.ray.io) 社区。
