# LangChain 提速：让 embedding 快 20 倍的实践指南

作者：[Amog Kamsetty](https://www.anyscale.com/blog?author=amog-kamsetty) 与 [Philipp Moritz](https://www.anyscale.com/blog?author=philipp-moritz) | 2023 年 5 月 3 日

这是博客系列的第 2 篇（[第 1 篇在这里](https://www.anyscale.com/blog/llm-open-source-search-engine-langchain-ray)）。在本博客中，我们会向你展示如何给 embedding 大幅提速。在后续的篇章里，我们会展示如何把向量数据库和 LLM 结合起来，做一个基于事实的问答服务。此外，我们还会优化代码并度量性能：成本、延迟和吞吐量。

从文档生成 embedding 是 LLM 工作流中关键的一步。如今许多 LLM 应用都是通过基于检索的相似度搜索来构建的：

- 文档被 embedding 并存入向量数据库。
- 用进来的 query 从向量数据库里拉取语义相关的段落，再把这些段落当作 context 交给 LLM 来回答这个 query。

在[上一篇博客](https://www.anyscale.com/blog/llm-open-source-search-engine-langchain-ray)里，我们演示了如何用 [LangChain](https://github.com/langchain-ai/langchain) 完成第 1 步，也演示了如何用 Ray tasks 把这一步并行化，从而更快地创建 embedding。

在这篇博客里，我们更进一步，把规模扩展到更多的文档。接着往下看，了解如何用 [Ray Data](https://docs.ray.io/en/latest/data/data.html)（Ray 框架的一个分布式数据处理组件）为来自云存储的 2,000 个 PDF 文档生成并存储 embedding，在 20 块 GPU 上并行，全部在不到 4 分钟内、不到 100 行代码里搞定。

虽然本教程里我们用 [Ray Data](https://docs.ray.io/en/latest/data/data.html) 从 S3 云存储读取 PDF 文件，但它也支持[大量其他数据格式](https://docs.ray.io/en/master/data/api/input_output.html#input-output)，比如文本数据、parquet、图像，还能从[各种数据源](https://docs.ray.io/en/master/data/api/input_output.html#input-output)读取数据，比如 MongoDB 和 SQL 数据库。

## 为什么我需要把它并行化？

![Embedding - 为什么我需要把它并行化？](https://images.ctfassets.net/xjan103pcp94/2CHfkngLbr34XsDZ7IKBAW/af3491b43c8afcdb307890881b2adf5c/embedding-why-do-I-need-to-parallelize-this.png)

Embedding - 为什么我需要把它并行化？

LangChain 提供了构建 LLM 应用所需的全套工具和集成，包括加载、embedding 和存储文档。用 LangChain 快速上手处理少量文档非常顺手，可当你想把语料扩展到成千上万篇文档时，很快就会变得难以驾驭。

天真地用一个 for 循环，对一个包含 2,000 篇文档的语料逐篇处理，要花 75 分钟：

```
1import os
2from tqdm import tqdm
3
4from langchain.document_loaders import PyPDFLoader
5from langchain.embeddings import HuggingFaceEmbeddings
6from langchain.text_splitter import RecursiveCharacterTextSplitter
7from langchain.vectorstores import FAISS
8
9text_splitter = RecursiveCharacterTextSplitter(
10    chunk_size=1000,
11    chunk_overlap=100,
12    length_function=len,
13)
14model_name = "sentence-transformers/all-mpnet-base-v2"
15model_kwargs = {"device": "cuda"}
16
17hf = HuggingFaceEmbeddings(model_name=model_name, model_kwargs=model_kwargs)
18
19# Put your directory containing PDFs here
20directory = '/tmp/data/'
21pdf_documents = [os.path.join(directory, filename) for filename in os.listdir(directory)]
22
23langchain_documents = []
24for document in tqdm(pdf_documents):
25    try:
26        loader = PyPDFLoader(document)
27        data = loader.load()
28        langchain_documents.extend(data)
29    except Exception:
30        continue
31
32print("Num pages: ", len(langchain_documents))
33print("Splitting all documents")
34split_docs = text_splitter.split_documents(langchain_documents)
35
36print("Embed and create vector index")
37db = FAISS.from_documents(split_docs, embedding=hf)
```

显然，如果你想快速迭代、去尝试不同的多文档语料、切分技巧、chunk 大小或 embedding 模型，光用一个 for 循环是搞不定的。

反过来，要想开发得更快，你需要做横向扩展，而这就需要一套框架把并行化变得非常轻松。

借助 Ray Data，我们可以定义自己的 embedding 生成流水线，用几行代码就能执行它，而且它会自动横向扩展，把集群里所有 CPU 和 GPU 的算力都用上。

## 我们数据流水线的各个阶段

在这个例子里，我们要为一组文档语料生成 embedding，这组语料由 arxiv 上关于「large language models」的前 2,000 篇论文组成。这些文档加起来超过 30,000 页。生成这份数据集的代码见[这里](https://github.com/ray-project/langchain-ray/blob/main/embedding_pdf_documents/arxiv_dataset_generation.py)。

![Embedding - 我们数据流水线的各个阶段](https://images.ctfassets.net/xjan103pcp94/2J2BxxlXHAsmjVdrjCqLdn/2ee02bfb6d2d96c7be6ab848c757d45e/embedded-stages-of-our-pipeline.png)

Embedding - 我们数据流水线的各个阶段

我们来看看数据流水线的各个阶段：

- 把 S3 桶里的 PDF 文档作为原始字节加载进来
- 用 PyPDF 把这些字节转换成字符串文本
- 用 LangChain 的文本切分器把文本切成 chunk
- 用预训练的 sentence-transformers 模型对每个 chunk 做 embedding
- 把 embedding 和原始文本存进 FAISS 向量库

整条数据流水线跑在 AWS EC2 上的 5 台 g4dn.12xlarge 实例上，一共 20 块 GPU。完整数据流水线的代码见[这里](https://github.com/ray-project/langchain-ray/blob/main/embedding_pdf_documents/embedding_ray.py)。

### 启动 Ray 集群

按照[这里](https://github.com/ray-project/langchain-ray/blob/main/embedding_pdf_documents/README.md)的步骤，在 AWS 上搭建一个多节点 Ray 集群。

Ray 集群也能在 GCP、Azure 或其他云厂商上启动。完整信息见 [Ray Cluster 文档](https://docs.ray.io/en/latest/cluster/getting-started.html)。

另外，你也可以用 [Anyscale 上的 Workspaces](https://docs.anyscale.com/develop/workspaces/get-started) 来管理你的 Ray 集群。

集群搭好之后，我们过一遍脚本里的各个步骤。

### 安装依赖

首先，我们要在 Ray 集群的所有节点上装好所需的依赖。这一步可以通过 Ray 的[运行时环境](https://docs.ray.io/en/latest/ray-core/handling-dependencies.html#id1)（runtime environment）功能来做。

```
1import ray
2
3ray.init(runtime_env={"pip": ["langchain", "pypdf", "sentence_transformers", "transformers"]})
```

### 阶段 1 - 加载文档

把 S3 桶里的 2,143 篇文档作为原始字节加载进来。这个 S3 桶装的是从 arxiv 下载下来的、未经修改的 PDF 文件。

这一步用 Ray Data 的读取 API 就能轻松完成，它会创建一个 Ray Dataset 对象。Ray Dataset 是惰性的：可以把后续操作链式接上，只有真正触发执行时各个阶段才会运行。

```
1from ray.data.datasource import FileExtensionFilter
2
3# Filter out non-PDF files.
4ds = ray.data.read_binary_files("s3://ray-llm-batch-inference/", partition_filter=FileExtensionFilter("pdf"))
```

### 阶段 2 - 转换

用 PyPDF 把原始字节读进来、解析成字符串文本。我们会跳过任何无法解析的文档或页面。即便跳过这些，数据集里仍有超过 33,642 页。

我们直接用 pypdf 库从字节读取 PDF，而不是从文件路径读取。等 [https://github.com/hwchase17/langchain/pull/3915](https://github.com/langchain-ai/langchain/pull/3915) 合并之后，就能直接使用 LangChain 的 PyPdfLoader。

```
1def convert_to_text(pdf_bytes: bytes):
2    pdf_bytes_io = io.BytesIO(pdf_bytes)
3
4    try:
5        pdf_doc = PdfReader(pdf_bytes_io)
6    except pypdf.errors.PdfStreamError:
7        # Skip pdfs that are not readable.
8        # We still have over 30,000 pages after skipping these.
9        return []
10
11    text = []
12    for page in pdf_doc.pages:
13        try:
14            text.append(page.extract_text())
15        except binascii.Error:
16            # Skip all pages that are not parseable due to malformed characters.
17            print("parsing failed")
18    return text
19
20# We use `flat_map` as `convert_to_text` has a 1->N relationship.
21# It produces N strings for each PDF (one string per page).
22# Use `map` for 1->1 relationship.
23ds = ds.flat_map(convert_to_text)
```

### 阶段 3 - 切分

用 LangChain 的 TextSplitter 抽象把文本切成 chunk。做完这一步转换后，33,642 页被切成 144,411 个 chunk。每个 chunk 接着在第 4 步被编码成一个 embedding。

```
1from langchain.text_splitter import RecursiveCharacterTextSplitter
2
3def split_text(page_text: str):
4    # Use chunk_size of 1000.
5    # We felt that the answer we would be looking for would be 
6    # around 200 words, or around 1000 characters.
7    # This parameter can be modified based on your documents and use case.
8    text_splitter = RecursiveCharacterTextSplitter(
9        chunk_size=1000, chunk_overlap=100, length_function=len
10    )
11    split_text: List[str] = text_splitter.split_text(page_text)
12
13    split_text = [text.replace("\n", " ") for text in split_text]
14    return split_text
15
16# We use `flat_map` as `split_text` has a 1->N relationship.
17# It produces N output chunks for each input string.
18# Use `map` for 1->1 relationship.
19ds = ds.flat_map(split_text)
```

### 阶段 4 - 生成 embedding

然后，我们在 GPU 上用预训练的 sentence transformer 模型对每个 chunk 做 embedding。这里我们借助 Ray Actors 来做有状态计算，让每块 GPU 只需初始化一次模型，而不是每个 batch 都初始化。

到这一阶段结束时，我们在 20 块 GPU 上跑 20 个模型副本，一共得到 144,411 个编码，每个副本一次处理 100 个 chunk 的 batch，以把 GPU 利用率拉满。

```
1class Embed:
2    def __init__(self):
3        # Specify "cuda" to move the model to GPU.
4        self.transformer = SentenceTransformer(model_name, device="cuda")
5
6    def __call__(self, text_batch: List[str]):
7        # We manually encode using sentence_transformer since LangChain
8        # HuggingfaceEmbeddings does not support specifying a batch size yet.
9        embeddings = self.transformer.encode(
10            text_batch,
11            batch_size=100,  # Large batch size to maximize GPU utilization.
12            device="cuda",
13        ).tolist()
14
15        return list(zip(text_batch, embeddings))
16
17# Use `map_batches` since we want to specify a batch size to maximize GPU utilization.
18ds = ds.map_batches(
19    Embed,
20    # Large batch size to maximize GPU utilization.
21    # Too large a batch size may result in GPU running out of memory.
22    # If the chunk size is increased, then decrease batch size.
23    # If the chunk size is decreased, then increase batch size.
24    batch_size=100,  # Large batch size to maximize GPU utilization.
25    compute=ray.data.ActorPoolStrategy(min_size=20, max_size=20),  # I have 20 GPUs in my cluster
26    num_gpus=1,  # 1 GPU for each actor.
27)
28
```

我们直接用 `sentence_transformers` 库，这样就能指定具体的 batch 大小。等 [https://github.com/hwchase17/langchain/pull/3914](https://github.com/langchain-ai/langchain/pull/3914) 合并之后，可以改用 LangChain 的 `HuggingfaceEmbeddings`。

### 阶段 5 - 存储

最后，我们通过迭代来执行这条数据流水线，并把结果存进一个持久化的 FAISS 向量数据库，供日后查询。

```
1from langchain import FAISS
2from langchain.embeddings import HuggingFaceEmbeddings
3
4text_and_embeddings = []
5for output in ds.iter_rows():
6    text_and_embeddings.append(output)
7
8vectore_store = FAISS.from_embeddings(
9    text_and_embeddings,
10    # Provide the embedding model to embed the query.
11    # The documents are already embedded.
12    embedding=HuggingFaceEmbeddings(model_name=model_name)
13)
14
15# Persist the vector store.
16vectore_store.save_local("faiss_index")
```
