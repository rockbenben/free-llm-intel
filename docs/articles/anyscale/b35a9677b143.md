# uv + Ray：集群中无痛的 Python 依赖关系

作者：[Christina Zhu](https://www.anyscale.com/blog?author=christina-zhu) 和 [Philipp Moritz](https://www.anyscale.com/blog?author=philipp-moritz) | 2025 年 2 月 27 日

![uv + 博客文章标题图像 2](https://images.ctfassets.net/xjan103pcp94/2KhO6m2ouQYf5yJ3qF8iN0/cfbb66f0fd3e12d10c8a6323a3a31a65/Illustration_Dark_mode_updated.png?w=1200)

当我们发现[uv包管理器](https://docs.astral.sh/uv)时，我们意识到Python包管理的新时代已经到来。它以一致性和速度解决了 Python 开发人员的依赖问题，同时也实现了快速的开发周期。

以下是 [astral.sh](http://astral.sh) 的人们正确收集的（非详尽的）我们真正喜欢的内容：

- **它们打包了整个环境**：您无需担心设置自己的 Python 发行版，这本身就非常麻烦。相反，让 uv [管理 Python 环境](https://docs.astral.sh/uv/concepts/python-versions/)。如果您愿意，uv 还支持使用系统安装的 Python。
- **他们让 uv 快如闪电：**对于初学者来说，它是用 Rust 编写的**，**就像他们非常成功的 Python linter [ruff](https://github.com/astral-sh/ruff)。 uv 的设计考虑到了速度，可以快速下载包，将它们缓存在本地磁盘上，消除环境之间的重复依赖关系，并使用硬链接将它们全部放在一起。
- **他们尊重并改进现有的 Python 约定：** 这包括对 [pyproject.toml](https://docs.astral.sh/uv/guides/projects/#pyprojecttoml) 的支持、出色的平台独立 [lockfile](https://docs.astral.sh/uv/concepts/projects/layout/#the-lockfile) 支持、[可编辑软件包](https://docs.astral.sh/uv/concepts/projects/dependency/#editable-dependency)、[环境变量](https://docs.astral.sh/uv/configuration/files/#env) 以及更多 - 添加更多功能并修复错误[一直](https://github.com/astral-sh/uv/blob/main/CHANGELOG.md)。

然而，在分布式环境中，管理 Python 依赖关系仍然具有挑战性。集群上有很多进程需要管理，我们需要确保它们所有的依赖关系都相互一致。如果更改单个依赖项，则必须将该更改传播到其他每个节点，因为每个工作进程都需要相同的环境，以便所有代码都以相同的方式执行。如果某个地方存在版本不匹配，您可能会花费大量时间来调试出了什么问题……这绝对不是一个有趣的消磨时间的方式。解决这个问题的传统方法是将所有内容容器化，但这会使开发迭代变慢 - 如果代码和依赖项发生变化，则需要构建新版本的容器并将其推送到所有节点。有时需要重新启动整个集群，这使得速度更慢。

如果您通过运行“uv run ... script.py”来启动分布式 Python 应用程序，并将动态创建的环境应用于集群中的每个进程，这不是很好吗？ *剧透*：这正是我们要做的。我们先来看一个使用 Ray 的简单示例。 [Ray](https://docs.ray.io/en/latest/) 是一个计算引擎，旨在轻松开发和运行分布式 Python 应用程序，尤其是 AI 应用程序。

由于这是[最新 Ray 2.43 版本](https://github.com/ray-project/ray/releases) 中的新功能，因此您当前需要设置一个功能标志：
```
1export RAY_RUNTIME_ENV_HOOK=ray._private.runtime_env.uv_runtime_env_hook.hook
```
我们计划在[收集更多反馈](https://github.com/ray-project/ray/issues/50961)后将其设为默认值，并在必要时调整行为。

设置此环境变量后，Ray 将自动检测您的脚本是否在 uv run 内运行，并将在同一环境中运行所有工作进程。我们首先看一个非常简单的例子。创建一个新文件“main.py”：
```
1import emoji
2import ray
3
4@ray.remote
5def f():
6    return emoji.emojize('Python is :thumbs_up:')
7# Execute 1000 copies of f across a cluster.
8
9print(ray.get([f.remote() for _ in range(1000)]))
```
并运行它
```
1uv run --with emoji main.py
```
这将在 Ray 集群中的多个 Python 工作进程中运行 1000 个“f”函数的副本。 “emoji”依赖项除了可用于主脚本之外，还将可用于所有工作进程。此外，当前工作目录中的源代码将可供所有工作人员使用。

就是这样！使用 Ray + uv，您可以管理分布式应用程序的 Python 依赖项，就像通常使用 uv 在单机上执行的操作一样。

### LinkEnd-to-end 使用 uv 的示例

现在，让我们通过一个更详细的示例来了解如何使用 uv 并深入了解它的一些方便的功能。我们将创建一个使用 Ray Data 和[新的 LLM 集成](https://docs.ray.io/en/latest/data/working-with-llms.html) 运行批量推理的应用程序。让我们首先创建一个具有必要依赖项的 pyproject.toml ：
```
1[project]
2name = "my_llm_batch_inference"
3version = "0.1"
4dependencies = [
5  "numpy",
6  "ray[llm]",
7]
```
您可能需要运行以下命令才能使 vLLM 正常工作：
```
1sudo apt-get update && sudo apt-get install -y build-essential
```
以及一个包含以下内容的脚本“batch_inference.py”：
```
1import ray
2from ray.data.llm import vLLMEngineProcessorConfig, build_llm_processor
3import numpy as np
4
5config = vLLMEngineProcessorConfig(
6    model_source="unsloth/Llama-3.1-8B-Instruct",
7    engine_kwargs={
8        "enable_chunked_prefill": True,
9        "max_num_batched_tokens": 4096,
10        "max_model_len": 16384,
11    },
12    concurrency=1,
13    batch_size=64,
14)
15processor = build_llm_processor(
16    config,
17    preprocess=lambda row: dict(
18        messages=[
19            {"role": "system", "content": "You are a bot that responds with haikus."},
20            {"role": "user", "content": row["item"]}
21        ],
22        sampling_params=dict(
23            temperature=0.3,
24            max_tokens=250,
25        )
26    ),
27    postprocess=lambda row: dict(
28        answer=row["generated_text"],
29        **row  # This will return all the original columns in the dataset.
30    ),
31)
32
33ds = ray.data.from_items(["Start of the haiku is: Complete this for me..."])
34
35ds = processor(ds)
36ds.show(limit=1)
```
要运行该应用程序，请将“pyproject.toml”和“batch_inference.py”文件放入同一目录中，并使用“uv run batch_inference.py”执行代码。

请注vLLM 支持该推理。

如果您想使用门后面的Hugging Face模型，您可以在工作目录中创建一个“.env”文件，如下所示：
```
1HF_TOKEN = your_huggingface_token
```
并使用“uv run --env-file .env batch_inference.py”运行代码。

如果要编辑任何依赖项，可以将它们克隆到相对于“working_dir”的路径“./path/foo”中，然后运行“uv add --editable ./path/foo”。这将在“pyproject.toml”中附加一个部分，指示 uv 使用签出（和编辑）的代码而不是原始包。

### Link 这在幕后是如何工作的？

![紫外线图1](https://images.ctfassets.net/xjan103pcp94/2rjcTtNwdOmuzfEHsVGTdv/70cdcb1e017635119e0e27f1007a0df3/Managing_Dependency_for_Ray_Applications_with_UV.png)

紫外线图1

**图：**如果没有 uv，script.py 在默认的 python 环境中运行，这可能与工作人员运行的运行时环境（左）不同，使用 uv 时，环境通过“uv run”同步，并且环境的创建通过 uv 的缓存加速

在底层，此集成使用 Ray 的[运行时环境](https://docs.ray.io/en/latest/ray-core/handling-dependency.html) 功能，该功能允许在代码中指定环境。我们定义了一个新的低级运行时环境插件，名为 [py_executable](https://docs.ray.io/en/latest/ray-core/handling-dependency.html#using-uv-for-package-management)。它允许您指定 Ray 工作程序将在其中启动的 Python 可执行文件（包括参数）。在“uv”的情况下，“py_executable”设置为“uv run”，其参数与运行驱动程序时使用的参数相同。此外，“working_dir”运行时环境用于将驱动程序的工作目录（包括“pyproject.toml”）传播给工作人员。这允许“uv”为工作人员运行设置正确的依赖关系和环境。

在一些高级用例中，您可能希望直接在程序中使用“py_executable”机制：

- **具有异构依赖关系的应用程序：** Ray 支持对不同的任务或参与者使用不同的运行时环境。这对于在不同的 Ray Serve 部署中部署不同的推理引擎、模型或微服务以及 Ray Data 中的异构数据管道非常有用。要实现这一点，您可以为每个不同的运行时环境指定不同的“py_executable”，并为每个环境使用带有不同“--project”参数的“uv run”。请参阅[此存储库此处](https://github.com/pcmoritz/ray-isolated-environments) 作为示例。
- **自定义工作程序运行的命令：** 在工作程序上，您可能希望使用一些不用于驱动程序的特殊参数来自定义 uv。或者，您可能希望使用诗歌运行、bazel 等构建系统、分析器或调试器来运行进程。在这些情况下，您可以通过“py_executable”显式指定工作线程应运行的可执行文件。如果您尝试以更复杂的方式包装多个进程，它甚至可能是存储在“working_dir”中的 shell 脚本。

### Link在射线作业中使用 uv

要将 uv 与 Ray 作业结合使用，请使用以下命令运行作业：
```
1ray job submit --runtime-env-json '{"working_dir": ".", "py_executable": "uv run"}' -- uv run main.py
```
这将确保作业的驱动程序和工作人员都在“pyproject.toml”指定的“uv”环境中运行。

### Link在 Ray 服务中使用 uv

要将 uv 与 Ray Serve 一起使用，请像上面一样设置“RAY_RUNTIME_ENV_HOOK”，并使用“uv runserve run app:main”运行服务。

### Link最佳实践和技巧

- 使用“uv lock”生成锁定文件并确保所有依赖项都被冻结，因此如果发布了新版本的软件包，事情不会以不受控制的方式发生变化。
- 如果您有一个“requirements.txt”文件并且不想使用“--with-requirements”标志，则可以使用“uv add -r request.txt”将依赖项添加到您的project.toml，然后将其与uv run一起使用。
- 如果需要，您可以通过“UV_SYSTEM_PYTHON=1”使用系统Python
- 如果您的“pyproject.toml”位于某个子目录中，您可以使用“uv run --project”从那里使用它。
- 如果您使用“uv run”并希望将工作目录重置为当前工作目录以外的目录，请使用“--directory”标志。 Ray uv 集成将确保您的“working_dir”被相应设置。

### 链接结论

将 uv 与 Ray 相结合，通过将 uv 的快速环境设置与 Ray 的可扩展编程模型相结合，显着改进了分布式系统的 Python 依赖管理，确保跨集群的工作执行一致。我们努力使 Ray + uv 成为以分布式方式运行代码的最佳解决方案，并且希望您能在 [GitHub](https://github.com/ray-project/ray/issues/50961) 或 [Discourse](https://discuss.ray.io/) 上提供反馈。

话虽如此，在某些情况下 uv 并不是一个可行的解决方案——您可能正在开发一个将不同的包管理器、存储库和二进制文件拼接在一起的既定项目。或者，您处于具有非常具体要求的企业环境中。在 Anyscale，我们正在开发基于 OCI 兼容的[快速容器运行时](https://www.anyscale.com/blog/cloud-infrastruct-for-llm-and-generative-ai-applications#faster-instance-startup-time:-a-step-change-in-performance-for-genai-and-llm-applications) 的依赖管理解决方案，该解决方案允许非常快速的开发迭代，并支持广泛的依赖需求。如果您对此感兴趣，请尝试一下 [Anyscale Platform](https://www.anyscale.com/)。
