# SkyRL 中视觉语言强化学习简介

作者：[Nithin Chalapathi](https://www.anyscale.com/blog?author=nithin-chalapathi)、[Sumanth Hegde](https://www.anyscale.com/blog?author=sumanth-hegde)、[Philipp Moritz](https://www.anyscale.com/blog?author=philipp-moritz) 和 [Kourosh Hakhamaneshi](https://www.anyscale.com/blog?author=kourosh-hakhamaneshi) | 2026 年 4 月 24 日

今天，我们宣布对 SkyRL 中的视觉语言模型后期训练提供全栈支持。团队现在可以在监督微调和强化学习工作流程中训练多模式模型，使用 SkyRL 中语言模型的相同可扩展后训练基础设施。

借助开箱即用的可扩展配方，任何人都可以开始构建自定义视觉语言训练后。携带现有的多模式 Tinker 配方？使用 SkyRL 运行它：
```
# Self-hosted Tinker service
uv run --extra tinker --extra fsdp -m skyrl.tinker.api \
--base-model $MODEL
--backend fsdp 

TINKER_API_KEY=tml-dummy uv run -m your_recipe \
	base_url=http://localhost:8000
```
或者，您还可以通过 SkyRL 基于 python 的入口点训练多模式模型。

**多模式工作负载 
**培训后工作负载变得越来越复杂和多模式。计算机使用、机器人技术和其他视觉代理任务等任务需要多步骤视觉推理。智能体处理视觉观察、采取行动并对环境反馈做出反应。在 SkyRL 中，支持这些工作负载意味着将视觉语言模型作为一等公民引入训练后堆栈，跨越监督微调和强化学习工作负载。

**支持的食谱
**SkyRL 现在涵盖了从监督微调到多轮、多图像代理强化学习的进展。尤其：

- [**VLM SFT 通过 Tinker**](https://docs.skyrl.ai/docs/tinker/cookbook#vision-language-vlm_classifier)，实现配方驱动的多模式监督微调。
- [**Agentic VLM RL**](https://docs.skyrl.ai/docs/examples/geometry3k)，用于通过工具调用进行基于图像的多步骤推理任务。
- [**多图像代理 VLM RL**](https://docs.skyrl.ai/docs/examples/visgym)，用于模型必须随着时间的推移观察、行动和适应的交互式视觉环境。
- [**异步执行和基于 LoRA 的训练选项**](https://docs.skyrl.ai/docs/examples/geometry3k#lora-support) 适用于实际的多轮 VLM RL 工作负载，继承了 SkyRL 的可扩展优化。

**调整 VLM RL 的推理和训练
**强化学习的核心挑战是确保推出生成和训练时间评分在序列构造和对数概率上一致。在早期的实现中，我们看到推理和训练之间存在严重的对数概率差异，这是由推理引擎和训练堆栈之间的多模式输入处理和数值精度的差异造成的。与整数值的文本标记相比，像素值的微小变化可能会导致输出出现较大偏差，从而破坏训练的稳定性。

为了最大限度地减少训练和推理之间的偏差，我们使用推理堆栈（此处为 vLLM）作为标记化和输入准备的事实来源。具体来说，我们帮助实现了分解的多模式[渲染和生成](https://github.com/vllm-project/vllm/pull/38405)。在此设计中，客户端首先使用“/v1/chat/completions/render”端点将 OpenAI 聊天输入转换为标记化文本和多模式输出。然后使用“/inference/v1/generate”进行令牌输入令牌输出生成。

![不同多模态处理管道对Geometry-3k训练动态的影响。](https://images.ctfassets.net/xjan103pcp94/Z7l8xv01r0a3A2nk8tegh/104745be6d1082693f460f3461a56adb/image4.png)图2：不同多模态处理管道的效果关于 Geometry-3k 训练动态。

不同多模态处理流程对 Geometry-3k 训练动态的影响。

分解方法确保了推出引擎和训练后端之间的一致性。在图 1 中，我们使用 HuggingFace 处理器或重新利用 vLLM 的内部输入处理器抽象来可视化替代方案。两者都会导致对数概率漂移以及奖励崩溃。将模型大小从 2B 缩放到 4B 会使问题变得更糟。 SkyRL 使用在 API 级别分离关注点的分解方法，即使在较大的模型尺寸下也能保持稳定性。

这种抽象有助于确保部署保持符合策略，同时消除培训人员的标记化和输入处理工作。随着多模式数据处理变得越来越复杂且计算成本越来越高，这允许独立扩展 CPU 工作线程以维持 GPU 吞吐量。

**从 SFT 到多轮代理 RL**

**VLM 通过 Tinker 监督微调**

通过 Tinker 界面，用户可以使用 SkyRL 训练后端运行 VLM 的监督微调工作流程。举一个简单的例子，开箱即用的 Tinker 分类 [SFT](https://github.com/thinking-machines-lab/tinker-cookbook/tree/main/tinker_cookbook/recipes/vlm_classifier) 配方在 SkyRL 上端到端运行。
```
# Start a local tinker server with the target base model
uv run --extra tinker --extra fsdp -m skyrl.tinker.api \
--base-model "Qwen/Qwen3-VL-2B-Instruct" 
--backend fsdp 
--backend-config '{"trainer.use_sample_packing": false}'

# Clone and run the target Tinker compatible cookbook against the local server.
git clone https://github.com/thinking-machines-lab/tinker-cookbook.git
cd tinker-cookbook

TINKER_API_KEY=tml-dummy uv run -m recipes.vlm_classifier.train \ 
dataset=caltech101 \
renderer_name=qwen3_vl \
model_name=Qwen/Qwen3-VL-2B-Instruct \
base_url=http://localhost:8000
```

**Agentic VLM RL - 几何 3k**

SkyRL 通过工具调用支持代理视觉语言任务的强化学习。为了证明这一点，我们使用 [Geometry3k](https://arxiv.org/abs/2105.04165) [1]，这是一个视觉几何推理数据集，其中模型必须解决几何问题。该模型提供有单个图像，并且必须通过它所看到的内容进行推理。
```
./examples/train/geometry3k/run_geometry3k.sh
```

**多图像代理 VLM RL**

在复杂的用例（例如，计算机使用任务）中，环境响应代理的操作。每一步都会渲染一个新的视觉状态，反映环境的状态。这些任务特别具有挑战性，因为模型将观察历史记录保留在上下文中，并且必须对帧进行空间推理和时间推理。
```
./examples/train/visgym/run_mazed2d_sft.sh
```
为了演示 SkyRL 中完整的端到端工作流程，我们使用 VisGym，这是一套包含 17 个多步骤视觉交互环境的套件。 VisGym [2] 涵盖的任务包括符号谜题、真实图像理解、导航和操作。该模型必须重复解释视觉状态、采取行动并根据环境反馈适应多个步骤，而不是产生单一响应。这使得 VisGym 环境成为代表更复杂任务的良好测试环境。 VisGym 是 SkyRL 多回合代理 VLM RL 支持的天然测试平台，包括异步执行和基于 LoRA 的训练。
