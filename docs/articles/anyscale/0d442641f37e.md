# SkyRL 引入视觉语言强化学习

作者：[Nithin Chalapathi](https://www.anyscale.com/blog?author=nithin-chalapathi)、[Sumanth Hegde](https://www.anyscale.com/blog?author=sumanth-hegde)、[Philipp Moritz](https://www.anyscale.com/blog?author=philipp-moritz) 和 [Kourosh Hakhamaneshi](https://www.anyscale.com/blog?author=kourosh-hakhamaneshi) | 2026 年 4 月 24 日

今天，我们宣布 SkyRL 已实现对视觉语言模型后训练的全栈支持。各团队现在可以跨 supervised fine-tuning（监督微调）和 reinforcement learning（强化学习）工作流来训练多模态模型，用的是 SkyRL 里为语言模型提供的同一套可扩展后训练基础设施。

借助开箱即用的可扩展 recipes，任何人都能上手搭建自己的视觉语言后训练。手头已有现成的多模态 Tinker recipe？直接在 SkyRL 上跑：

```
# Self-hosted Tinker service
uv run --extra tinker --extra fsdp -m skyrl.tinker.api \
--base-model $MODEL
--backend fsdp 

TINKER_API_KEY=tml-dummy uv run -m your_recipe \
	base_url=http://localhost:8000
```

另外，你也可以通过 SkyRL 基于 python 的入口来训练多模态模型。

这里是我们在 VisGym Maze2D 上跑 agentic 训练 recipes 的一个例子：

**多模态工作负载**
后训练工作负载正变得越来越复杂、越来越多模态。像 computer use（电脑操作）、机器人，以及其他视觉 agentic 任务，都需要多步视觉推理。Agents 处理视觉观察、采取行动，并对环境反馈作出响应。在 SkyRL 里，支持这些工作负载意味着把视觉语言模型作为一等公民引入后训练技术栈，覆盖 supervised fine-tuning 和 reinforcement learning 两类工作负载。

**支持的 Recipes**
SkyRL 现已覆盖从 supervised fine-tuning 到多轮、多图 agentic reinforcement learning 的整条演进。具体包括：

- [**通过 Tinker 做 VLM SFT**](https://docs.skyrl.ai/docs/tinker/cookbook#vision-language-vlm_classifier)，实现由 recipe 驱动的多模态监督微调。
- [**Agentic VLM RL**](https://docs.skyrl.ai/docs/examples/geometry3k)，用于带 tool calling 的多步、基于图像的推理任务。
- [**多图 Agentic VLM RL**](https://docs.skyrl.ai/docs/examples/visgym)，用于模型必须随时间观察、行动并适应的交互式视觉环境。
- [**异步执行与基于 LoRA 的训练选项**](https://docs.skyrl.ai/docs/examples/geometry3k#lora-support)，服务于实际的多轮 VLM RL 工作负载，继承 SkyRL 的可扩展优化。

**让 inference 与 training 对齐（面向 VLM RL）**
reinforcement learning 的一个核心挑战，是确保 rollout 生成和 training 时的打分在序列构造与 log probability 上达成一致。在早期实现里，我们观察到 inference 和 training 之间存在严重的 log probability 偏差，根源在于多模态输入处理的不同，以及 inference 引擎与训练技术栈之间数值精度的差异。和取值为整数的 text tokens 不同，像素值的微小变化就可能造成输出的大幅偏离，让训练失稳。

为了把 training 和 inference 之间的漂移降到最低，我们把 inference 技术栈（这里是 vLLM）当作 tokenization 和输入准备的唯一事实来源。具体来说，我们参与实现了多模态的分离式 [rendering 与 generation](https://github.com/vllm-project/vllm/pull/38405)。在这个设计里，客户端先调用 `/v1/chat/completions/render` endpoint，把 OpenAI chat 输入转换成 tokenize 后的文本和多模态输出；随后用 `/inference/v1/generate` 做一次 token-in-token-out 的生成。

![不同多模态处理流水线对 Geometry-3k 训练动态的影响](https://images.ctfassets.net/xjan103pcp94/Z7l8xv01r0a3A2nk8tegh/104745be6d1082693f460f3461a56adb/image4.png)图 2：不同多模态处理流水线对 Geometry-3k 训练动态的影响。

不同多模态处理流水线对 Geometry-3k 训练动态的影响。

分离式方案保证了 rollout 引擎和训练后端之间的一致性。在图 1 里，我们把两种替代做法做了可视化：一种用 HuggingFace processor，另一种复用 vLLM 内部的 input processor 抽象。两者都会带来 log probability 漂移，还会让 reward 崩掉。把模型规模从 2B 扩到 4B，问题只会更糟。而用这种在 API 层面分离关注点的分离式方案，即便在更大的模型规模上，SkyRL 也能保持稳定。

这层抽象有助于确保 rollouts 保持 on-policy，同时把 tokenization 和输入处理的活儿从训练 workers 上摘下来。随着多模态数据处理变得越来越复杂、越来越吃算力，这让我们可以独立地扩展 CPU workers，以维持 GPU 吞吐。

**从 SFT 到多轮 agentic RL**

**通过 Tinker 做 VLM 监督微调**

借助 Tinker 接口，用户可以用 SkyRL 训练后端来跑 VLM 的 supervised fine-tuning 工作流。举个简单的例子：一个开箱即用的 Tinker 分类 [SFT](https://github.com/thinking-machines-lab/tinker-cookbook/tree/main/tinker_cookbook/recipes/vlm_classifier) recipe 能在 SkyRL 上端到端跑起来。

```
# Start a local tinker server with the target base model
uv run --extra tinker --extra fsdp -m skyrl.tinker.api \
--base-model "Qwen/Qwen3-VL-2B-Instruct" 
--backend fsdp 
--backend-config '{"trainer.use_sample_packing": false}'

# Clone and run the target Tinker compatible cookbook against the local server.
git clone https://github.com/thinking-machines-lab/tinker-cookbook.git
cd tinker-cookbook

TINKER_API_KEY=tml-dummy uv run -m recipes.vlm_classifier.train \ 
dataset=caltech101 \
renderer_name=qwen3_vl \
model_name=Qwen/Qwen3-VL-2B-Instruct \
base_url=http://localhost:8000
```

**Agentic VLM RL - Geometry 3k**

SkyRL 支持带 tool calls 的 agentic 视觉语言任务的 reinforcement learning。为了演示这一点，我们用 [Geometry3k](https://arxiv.org/abs/2105.04165) [1]——一个视觉几何推理数据集，模型必须解其中的几何题。模型拿到一张图像，然后要就它所看到的进行推理。

```
./examples/train/geometry3k/run_geometry3k.sh
```

![Qwen3-VL 8B Instruct 在 Geometry-3k 上的示例 rollouts](https://images.ctfassets.net/xjan103pcp94/5vDHvT5JePRFwUKhZZihKC/947c2117f4cb7bfc5225330162781c2e/image2.gif)图 4. Qwen3-VL 8B Instruct 在 Geometry-3k 上的示例 rollouts。经过训练，这个 agent 学会了在作答时调用 tools 并纳入反馈。

Qwen3-VL 8B Instruct 在 Geometry-3k 上的示例 rollouts。

**多图 Agentic VLM RL**

在一些复杂的用例里（比如 computer use 任务），环境会对 agent 的动作作出响应。每一步都会渲染出一个新的视觉状态，反映环境的当前状态。这类任务尤其有挑战，因为模型要在 context 里保留观察的历史，并且既要在空间上推理、又要在时间上对这些帧推理。

```
./examples/train/visgym/run_mazed2d_sft.sh
```

为了演示 SkyRL 里一条完整的端到端工作流，我们用 VisGym——一套 17 个多步可视化交互环境。VisGym [2] 涵盖的任务包括符号谜题、真实图像理解、导航与操作。模型不是给出一个单次回答，而是要反复解读视觉状态、采取行动，并根据环境反馈在多步中不断适应。这让 VisGym 环境成为一个能代表更复杂任务的好测试环境。对 SkyRL 的多轮 agentic VLM RL 支持（含异步执行与基于 LoRA 的训练）来说，VisGym 是一处天然的 testbed。

你可以通过 Tinker 接口上手 VLM 训练，也可以直接从 SkyRL 上手。我们很希望用户社区把 SkyRL 应用于视觉语言任务的规模推向更大，并向我们反馈。你可以从我们的[教程与入门](https://docs.skyrl.ai/docs/tutorials/vision_language_rl)开始。

**未来路线图**：
多模态支持还处于早期，我们已经规划了好几个重要特性，包括 sequence packing、Megatron 后端支持、带 context parallelism 的长上下文训练，以及 step-wise 训练。现在正是参与多模态训练的好时机，我们欢迎社区贡献！
