# 学习闭环：拥有你自己的智能之路

作者：Christian Stano | 2026 年 8 月 25 日

AI 正在重写企业的价值等式。我们正走出"堆 token"（token-maxxing）的时代，迈向差异化智能的未来。

各公司正在调整战略，把智能构建为业务的持久护城河。于是，在全球科技中心的每一块广告牌、公交车和列车上，你都能看到同样三个词：Own Your Intelligence（拥有你自己的智能）。但这到底意味着什么？要做到需要什么？

本文给出我们对"拥有你的智能"这一问题的答案：学习闭环（learning loops）。我们将解释什么是学习闭环、我们认为多数公司构建它所经历的成熟度曲线、使其成为现实所需的工程投入，以及 Ray 与 Anyscale 在这张图景中的位置。

## 什么是学习闭环？

学习闭环是把数据清洗（data curation）、定制模型训练与推理连接起来的复利飞轮，全部由你的专有数据驱动。这个概念并不新鲜。然而在 LLM 与 agentic 系统的时代，构建一个学习闭环的规模、复杂度与基础设施投入呈指数级上升，而业务等待的代价逐月增长。

企业构建学习闭环面临三大挑战：

- 清洗大规模（TB-PB 级）专有数据集，其中很多还是多模态的
- 训练定制模型面临算力稀缺、蔓延与可靠性挑战——作业横跨多个 GPU 节点、一跑就是数周
- 推理要满足延迟要求的扩展，需要横跨技术栈多层的弹性与性能调优

*学习闭环*

闭环一旦部署，就产生复利效应：终端用户界面收集数据，数据被处理和清洗，用于训练改进后的定制模型或 agent，用评估（evals）测试，再部署出去做推理。这个环每转一圈，业务就多出一些性能更强、效率更高或成本更低的差异化。

## 成熟度曲线

由于部署差异化程度递增的学习闭环需要高昂的前期复杂度与成本，我们看到一条成熟度曲线正在浮现。

*学习闭环成熟路径*

**第 1 步：拥有你的提示词（Own the prompts）：**租用模型，把时间投入自己的提示词与评估。在追加底层基础设施投入之前先证明 ROI。

要预期成本随用量线性甚至更快增长，因为每个 token 都是"租来的智能、运行时与基础设施"这条长链上的一行账目。当你使用的模型与智能人人可得，你的差异化也只能建立在提示词与工作流这层更薄的壳上。

**第 2 步：拥有权重与运行时（Own the weights and runtime）：**当成本、性能与可靠性成为差异化的关键，就该投资基础设施：停止调用专有模型，开始用你的数据在模型权重层做差异化。

这一层开始需要数据清洗与训练流水线，而你不想让它们按 token 计价。清洗与训练是持续、重型的负载，按 token 付费等于为你本可自行调度的工作支付溢价。运行时投入由此开始。你掌握了负载如何执行，从而在你的基础设施投入上优化成本、性能与可靠性。

除了成本与性能，安全与数据主权也在这一步成为又一层的差异化。这些系统搬运、变换并激活专有数据，终极目标是把数据变成 token。当团队正把数千万乃至数亿美元的 capex 投入 GPU 基础设施，你必须控制这些数据及其产出的 token。

**第 3 步：拥有闭环（Own the Loop）：**一旦数据、训练与推理的地基部署完毕，你就能踏上拥有并优化闭环之路，筑起更深的智能护城河。

你要让每一次循环更快、每一次运行更省钱。组织的成本心智也开始从"每 token 成本"转向"每单位工作成本"（例如每处理一张图像的成本）。

你会追求用同样的资源做更多的工作，让闭环的每一圈产出更多差异化。

## 架构

在这些阶段之间每挪一步，你都在构建差异化，同时也在接管技术栈的更多层。这样一来，各层如何协同就成为"以高成本效率规模化交付智能"的关键。

每个学习闭环其实是若干负载：数据处理、训练、仿真、推理——各自的硬件与编排需求都不同。这些负载的挑战，与把它扩展到多用户、多负载、多云多加速器的平台挑战相互碰撞。

我们正在看到一种新架构浮现：它让团队能从单个负载扩展到众多负载，并具备管理庞大算力机群的能力。

*让人从单负载扩展到多负载、并能管理庞大算力机群的新架构。*

这一架构以 Ray 作为分布式计算底座，提供可扩展、容错的负载调度；以 Kueue、Kai、Volcano、Yunikorn 等负载编排器对相互竞争的作业做优先级管理。

栈的顶层是一个全局控制面，融合每一层的信息与访问——从基础设施到控制面及其中的一切——形成统一的技术栈。控制面的要义，是把正确的接口、正确的权限和正确的可观测性同时交给开发者和 agent。这包括全局层面的作业管理、放置、优先级与抢占——当然，这必须与单个集群和负载层面紧密协调。

当用户负载请求一百块 GPU 时，Ray 与 Kubernetes 协同放置（通常需要拓扑感知），Ray 与 Kueue 等工具评估容量、优先级以及对其他运行中作业的影响。这些模块之间的交接，正是作业成败、GPU 利用率提升或停滞、团队是半夜被叫起来值班还是安睡一整晚的分界线。

最终你得到的，是一个为你铺就"黄金路径"的技术栈——在你构建学习闭环时，默认就在每一朵云、每一种基底上把正确的事变容易。
