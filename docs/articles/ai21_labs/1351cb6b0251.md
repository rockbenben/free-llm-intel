我们激动地宣布一门开创性的新课程——**用 Jamba 构建长上下文 AI 应用（Build Long-Context AI Apps with Jamba）**——由 Andrew Ng 的 DeepLearning.AI 与 AI21 Labs 合作打造。这门课程为开发者配备使用 Jamba 革命性架构构建下一代 AI agent 的工具，展示开发者如何处理长上下文应用。

## LLM 的演进：为什么 Agent 需要更好的架构

通过开发语言模型并观察其真实世界应用，我们 AI21 Labs 对当前架构的局限有了深刻认识。随着企业开始试验并部署用于复杂任务的 AI agent，我们识别出影响这些 agent 效能的现有模型中的关键瓶颈。

为什么上下文长度对 agent 如此重要？AI agent 需要维持大量的运行时记忆才能有效执行复杂任务。它们在朝目标工作的同时，必须同时持有对话历史、参考资料、任务指令和中间结果。传统模型迫使 agent 不断"遗忘"关键上下文，导致性能不稳定和推理链断裂。

## 当前架构的局限

传统的基于 transformer 的架构虽然强大，却难以满足现代 AI agent 的需求。其计算量随长度呈二次方增长，使得处理长上下文昂贵得令人却步，迫使开发者人为地切分文档和会话。而这种碎片化恰恰破坏了让 agent 有效的上下文理解本身。

近期，Mamba 架构作为一种潜在解决方案出现，通过选择性状态空间模型承诺线性扩展。然而我们的大量测试表明，Mamba 的效率是以牺牲上下文理解和输出质量为重大代价的——而这恰恰是 agent 最需要的能力。

## 介绍 Jamba：为 Agentic 未来而生

对两种架构局限的深刻理解促使我们开发了 Jamba——一种将 transformer 的精准注意力机制与 Mamba 的高效处理相结合的混合架构。我们在突破上下文长度边界上的投入已经结出硕果：根据 [NVIDIA 独立 ruler benchmark，Jamba 拥有业界最高的有效上下文长度](https://www.ai21.com/blog/long-context-yoav-shoham)——对于需要维持庞大运行时记忆、同时交付稳定高质量输出的 AI agent 来说，这是关键优势。对 AI agent 而言，这意味着：

- **全面的上下文管理**——Agent 可以在不损失性能的情况下维持庞大的运行时记忆，实现更复杂、更细腻的任务执行。
- **增强的推理能力**——混合架构确保 agent 能够在海量信息之间建立关联，同时保持推理链的连贯。
- **可扩展的性能**——Agent 可以在单次处理中读完整个文档集合、对话历史和知识库，消除上下文碎片化。

## 企业级的 Agent 架构

Jamba 专为需要处理完整信息图景的企业应用而工程化。Jamba 让 agent 能够摆脱传统模型所必需的零敲碎打方式，转而去：

- 单次处理完整的法律合同、财务报告和监管备案文件
- 分析完整的客户历史和交易日志，无需武断的断点
- 搜索并理解整个内部 wiki、培训手册和项目文档，同时保持上下文关联
