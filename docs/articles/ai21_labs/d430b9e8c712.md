## 生产中平衡准确率、成本与延迟的挑战

部署过 LLM 驱动 agent 的人都知道：每个任务的准确率、成本和延迟无法独立优化；提升其一，几乎总要牺牲至少另一个。调用更强的模型，答案更好，但每查询成本翻三倍。加一个验证循环，准确率上去了，延迟却膨胀。并行跑多个候选，最好的胜出，但 token 开销被你成倍放大。而当 AI 功能要扩展到大用户群时，把这个权衡做对不是可选项；单位经济模型持续让 AI 试点卡在无法进入生产（[RSM AI Survey, March 2026](https://rsmcanada.com/insights/rsm-labs/welcome-to-your-ai-dream-home.html)）。

然而，要在准确率、成本、延迟之间达到正确的运行点，需要搜索的空间实际上由近乎无限的排列组合构成：模型选择、提示词配置、工具组合、agent harness 设计、扩展策略、执行策略。手动实验的深层问题不只是慢和贵——即使你找到一个能用的配置，你也只是从浩瀚空间中采样了屈指可数的几个点。你不知道自己错过了什么。而当环境变化——预算收紧或新模型发布——你没有任何有原则的方法来知道该调什么、变化会如何波及其他维度。

你退回试错，且没有收敛的保证。

我们构建 Maestro，就是为了系统性地解决任意 agent 任务的这一搜索空间优化问题。下面，我们先分享用当今常见 agent 优化技术在 BrowseComp-Plus 上做的实验，然后介绍 Maestro 的方案，展示在复合搜索空间上自动搜索、识别最优执行路径的价值。

## 优化技术一：模型与 agent 设置

任何 agent 优化工作最自然的起点是配置：选对 LLM、调提示词、挑工具、调 agent harness。不同模型带来不同的成本、延迟、成功率画像；不同提示词配置改变 agent 能解决好的问题空间部分。

为把这点讲具体，我们通过运行一组代表性的模型与工具变体，并在质量-成本与质量-延迟两个轴上度量性能，来刻画 BrowseComp-Plus 的基线版图。

图 1. BrowseComp-Plus 成本 vs. 准确率与延迟 vs. 准确率，展示单个模型/工具变体

- **稀疏检索（BM25）**——基于词元出现情况把文本编码为高维向量。该方法依赖精确的词面重合，在查询与相关文档共享词汇时特别有效。
- **稠密检索（Qwen2-7b）**——利用神经网络编码器把文本投影到捕捉语义的低维连续向量。这使得基于概念相似度的检索成为可能，即使没有词面重合。
- **后期交互（late-interaction）检索**——使用 Reason-ModernColbert 模型，把文本表示为一组上下文化的词元级稠密嵌入，而非单一向量。检索通过查询与文档词元之间的细粒度匹配完成，可实现更精准的对齐。
- **+/- 表示 Get_full_doc 工具**——遵循常用的基准脚手架（benchmark scaffold），部分 agent 配备了获取整篇文档内容的工具。

## 优化技术二：扩展（Scaling）

当 agent 配置触到天花板，下一根杠杆就是扩展：生成多个候选解决方案，并在运行时选出最好的。扩展有若干形式，可以组合并叠加在任何配置选择之上。

### 2a. 单变体扩展（best-of-N）

最简单的扩展策略是同一 agent 配置对同一查询运行 N 次，选取最佳输出，有时称为 *best-of-N*。

这一技术利用了 LLM agent 非确定性这一事实：同一个模型、同一个查询的提示，有时成功有时失败。这种逐次运行的方差在扩展文献中已有充分记录，其含义是：运行多个独立候选并选最好的，是提升覆盖率有原则的方式——每次 rollout 探索解空间的不同部分，至少一个成功的概率随 k 增长。下图可以看到这一点：

图 2. BrowseComp-Plus 成本 vs. 准确率与延迟 vs. 准确率，展示 variant@k 的「oracle」扩展曲线——k 次 rollout 中至少一次正确的概率。每个变体以不同的 k 值评估。这代表 best-of-N 扩展的潜力，与运行时候选选择解耦。

但要在实践中兑现这一点，你需要一种在运行时判断哪个候选最好的方法。在封闭式评估里，你可以对照 ground truth（oracle）。**在生产环境中，你需要一个运行时验证信号。**

在 BrowseComp-Plus 的工作中，我们利用了这样一个事实：**模型自生成的置信度分数，在经过恰当校准后，是任务准确率的可靠代理（[相关研究](https://arxiv.org/abs/2504.12516)）**。这意味着在生产中我们可以把模型自己的不确定性信号当作选择机制：选表达置信度最高的候选，你的选择成功率就显著优于随机。

我们展示：运行 variants@k 并用模型的最大自置信分数挑选最佳候选，可以兑现「oracle」曲线所代表的潜力，并在 BrowseComp-Plus 上确立一条新的帕累托前沿*（准确率与成本/延迟之间的最优权衡曲线）*：

图 3. BrowseComp-Plus 成本 vs. 准确率与延迟 vs. 准确率，展示 variant@k 扩展曲线，并对比基于置信度选择实现的准确率曲线与「oracle」曲线。

### 2b. 集成扩展（模型异质性）

单变体扩展利用的是单一模型、单一配置内部的方差。集成扩展更进一步：它取用一个*组合（portfolio）*中多样化的模型与配置，各自解决问题空间的不同子集。

不同的模型与检索器会犯不同类型的错。一道让 GPT-5@4 + 稠密检索卡住的查询，可能由 MiniMax@32 + 稀疏检索解决，反之亦然。不同变体互相补充的程度——它们的成功协方差——本身就是组合可度量的属性，并直接决定集成相对任何单个成员能带来多少增益。

图 4. BrowseComp-Plus 数据集上不同模型与工具变体之间成功重叠的分析，展示不同变体如何互补。

这也呼应更广泛的研究结论：[「More Agents is All You Need」（Tencent, 2024）](https://arxiv.org/abs/2402.05120)证明即使单个 agent 更小更便宜，集成规模与准确率仍会一起增长。这也是 [Andrej Karpathy 的 LLM Council](https://github.com/karpathy/llm-council) 等项目背后的理念。

在我们的 BrowseComp-Plus 实验中，对表现最好的配置做集成时，单个集成点在准确率轴上的位置明显高于最佳的单变体@k 帕累托曲线。集成的集体智慧达到了任何单模型扩展策略都无法匹敌的准确率水平。

例如，我们发现把 **Minimax, LateInteraction, + X 8、GPT-5, LateInteraction, + X 2 和 GPT-5, Dense X 2** 组合成集成，可以用显著更低的成本和延迟达到与最佳单配置扩展（GPT-5, LateInteraction, + X 4）相同甚至更高的准确率。

图 5. BrowseComp-Plus 成本 vs. 准确率与延迟 vs. 准确率，展示单个集成运行点——分批运行，一旦有候选通过自置信阈值即停止。集成点出现在最佳单变体帕累托曲线之上。

### 2c. 执行策略

既然我们现在运行多个候选——来自单一配置或某个集成——*如何*执行它们就成为叠加在扩展选择之上的又一个优化变量。执行策略决定候选如何排序、执行何时终止、预算如何在整轮运行中分配。

**并行 vs. 顺序执行。** 同时运行全部 N 个候选把延迟降到最低，但把 token 开销推到最高。顺序运行、一旦发现高置信候选就停止，能大幅削减成本——代价是最坏情况下更高的延迟。一个混合选项是小批量并行执行候选、批次之间顺序推进、任一批次中有候选达到置信阈值即停止。这能捕获并行的大部分延迟收益，同时让成本更接近顺序执行。

**选定候选即早停。** 一旦选定某个候选——无论来自并行批次还是顺序运行——仍在进行的其他 rollout 可以立即终止。这避免了为永远不会用到的补全付费，且对早早被确信解决的查询效果显著。

**级联（Cascading）。** 从便宜的模型开始；若失败或表达低置信，则升级到更贵的模型。用便宜方式处理简单查询省下的成本，远超过在困难长尾上使用昂贵模型的成本。

下图说明：在同一集成之上叠加不同执行策略，会在准确率-成本-延迟的权衡曲面上占据不同的位置。

图 6: BrowseComp-Plus 成本 vs. 准确率与延迟 vs. 准确率，展示同一集成（ensemble）上的不同执行策略（顺序与批量执行）。

- **Minimax + GPT-5 集成：** 由 <Minimax, LateInteraction, +> X32 + <GPT-5, Dense> X4 构成
- **顺序执行策略：** 按顺序产生候选，先跑 Minimax 的 rollout，再进入 GPT-5 的 rollout，一旦某候选通过自置信阈值即停止。
- **批量执行策略：** 并行产生 32 个 Minimax 候选。若至少一个通过自置信阈值，返回得分最高者；否则继续并行产生 4 个 GPT-5 候选，返回其中得分最高者。

每种执行策略在权衡曲面上占据不同位置。最优者取决于具体的查询分布、部署约束与客户偏好。

## 优化技术三：评审与修复循环

以上技术是从独立候选运行中做选择。第三类优化的工作方式不同：它通过评审与修复迭代地*改进*单一答案，把验证放到内部 agent 循环之外，做成显式、重复的步骤。

对质量难以用二元成功指标刻画的长文本生成任务，这一点尤其有力。这里的验证产出的是**连续分数与结构化反馈**——不只是停止信号，而是给修复步骤的可执行指导。我们把这一技术应用在 **Deep Research Bench 1** 上——一个深度研究报告生成基准。

对每个查询，流程如下：

**第 01 步. 生成查询专属的评分细则（rubrics）。** 在 agent 产出报告之前，我们针对当前查询生成评估标准。为 *"新兴市场中央银行数字货币（CBDC）的宏观经济影响是什么？"* 这样的查询，rubrics 可能包括：*报告是否覆盖了货币政策传导机制？是否引用了至少两项来自不同地区的实证研究？是否区分了零售型与批发型 CBDC？* 这些标准成为第一步生成上下文的一部分，让 agent 从一开始就有明确的质量目标——它们也驱动后续的验证步骤。

**第 02 步. 生成研究报告。** agent 使用标准的 agent 循环（递归派生研究 agent）产出一份初始报告。

**第 03 步. 对照 rubrics 验证。** 一个评审模型（judge）对报告逐条评估 rubric，对每条未达标项给出分数与具体反馈。

**第 04 步. 修复。** 一个修复步骤接收 rubric 反馈并改进报告，逐项解决识别出的缺口。

**第 05 步. 重复。** 第 3–4 步迭代运行，直到报告达到满意分数或触及预算上限。

我们基于 rubric 的打分框架采用了与 Deep Research Bench 1 基准自身评估指标类似的方法，并且我们已将其校准到与基准分数相关联。

使用我们的迭代评审-修复循环，我们展示了质量随着每次迭代都有实质提升。

## 在近乎无限的解空间中高效搜索

退后一步，审视我们刚描述的空间：模型选择、提示词配置、工具组合、扩展策略、执行策略、集成构成、评审循环深度。每个维度都有多个设置，设置之间互相作用，每个组合的具体效果又取决于特定用例的查询分布。

问题不只是空间大。而是采样少数几个点对「你错过了什么」几乎毫无交代，也在约束变化时给不了你任何杠杆。你退回试错，没有地图，也没有收敛的保证。

需要的是一种方法：自动地、高效地、并且能适应不断变化的 AI 技术栈地，绘出整个可达的权衡曲面。

## 自动、高效、自适应：为 agent 优化构建 AI21 Maestro

Maestro 是一个 agent 优化框架，把这一空间的探索自动化，并为任何生产 agent 暴露跨质量、成本、延迟的完整帕累托前沿。

系统有三个主要组件：

- **离线优化：Action Model 训练。** 给定一个 agent、一个题目集、一个成功指标和一个动作组合（可用模型、工具、配置集合），Maestro 训练一个 *Action Model*：一个概率模型，预测每种配置在不同查询上的成本、延迟和成功概率。
- **权衡可视化。** 离线模拟之后，Maestro 针对具体工作负载生成跨准确率、成本、延迟的完整帕累托前沿。团队可以直接检视每个可达的运行点——不只是碰巧测过的那几个——并基于部署约束选择配置，无需手动构建或搜索。
- **预算与效用感知的运行时。** 推理时，运行时基于 Action Model 的预测、所选集成与选定的成本/延迟设置，为每个请求动态组合并执行最优配置，无需重新训练。运行时实现了全部范围的执行策略：并行与顺序执行、混合分批、验证驱动的早停、跨模型层的级联。预算上限可按每次运行或每个动作的美元数设定；输出 token 预算以流式块消耗并支持早停以限制外溢；成本估算中会考虑前缀缓存（prefix caching）。

## 把 agent 优化当作一等的工程挑战

Agent 优化不是一次性的配置选择，而是在不断演化的约束下驾驭高维空间的持续实践。

构件是真实而有力的：模型与 agent 调优确立一条基线前沿；基于置信度选择的 best-of-N 扩展把它外推；集成的异质性把它推得更远；评审-修复循环解锁仅靠生成无法达到的质量层级；而执行策略决定你最终落在权衡曲面的确切位置。但这些技术彼此复合成一个没有任何团队能靠手动有信心穿越的搜索空间。

Maestro 把这种穿越自动化。通过训练一个 Action Model 在整个配置空间上预测成本、延迟和成功概率，并将其与一个按用户需求执行最优策略的预算感知运行时耦合，它把 agent 优化从一门手艺变成一种可重复的工程实践。
