*共同作者：Barak Lenz、Yonatan Belinkov、Subbarao Kambhampati、Kevin Leyton-Brown、Yoav Shoham*。

如今，人们对能够比传统 LLM 推理得更好的 AI 抱有极大兴趣（如果构建 LLM 短短七年的实践可以称为"传统"的话）。"推理"（Reasoning）当然是一个承载过重含义的词，但在当今 AI 的语境中，它已演变为意味着探索 token 链（包括内部的"思考" token，因此有了"思维链"或 CoT 这一术语），而不是目光短浅地只预测下一个 token。事实上，这些 CoT 模型有时被称为大推理模型（Large Reasoning Models，LRM）。在它们目前的形态中——例如 OpenAI、Google、DeepSeek、X.AI、Anthropic、阿里巴巴等公司近期的 LRM——其做法是：一个能够给出中间"思考" token 引导的解答猜测的基础 LLM，经过强化学习（RL）阶段的后续训练，以优化产生以正确答案收尾的思维链。然后在推理时，允许该模型在一定预算内展开这类链条。其结果在多项任务上带来了有实证支撑的性能提升。

这篇概念性文章的主旨，是解释为什么这是一种次优的方式去探索给定输入的可能答案空间，并描述一种基于规划的替代方案。本文的目的不是详细描述 AI21 构建的 AI 系统——那是另一篇论文的话题，这里只会略加提及——而是以更为通用的视角阐述我们如何看待这一领域。

从宏观层面看，主要信息如下：

- 思考行动（actions），而非 token。行动是指对某个工具的任意一次具体调用——对 LLM 的一次具体 prompt、一次具体的网页搜索、一次具体的数据库调用，等等。去寻找要采取的最佳行动序列，而不是要预测的最佳 token。
- 行动序列的空间极其庞大。通过显式的决策论规划来探索它，同时考虑答案质量分布和成本分布（以时间、算力和金钱计）。规划是外层循环；LLM（及其他工具）是内层。
- 在训练时，教会系统如何规划。在测试时，创建具体的计划并执行它，让规划与执行交替进行。
- 让用户全程参与这一过程，尤其是在测试时。用户既是系统的老板，也是为系统提供实时纠偏信息的资源。

## 当前的"推理"模型

让我们先看看当前 LRM 方法的一些固有局限，然后再讨论我们所看到的替代方案。需要先说明的是，大多数 LRM 开发者并未透露其模型的太多细节，因此本文的判断基于唯一一个被相当详细描述过的模型——DeepSeek 的 R1——以及对其他模型的合理推测。

我们看到 LRM 有两类主要的算法局限。第一类是低效。在训练时，为了让一个输入携带可供 RL 学习的信号，其输出必须足够频繁地以成功收尾。即便是非 CoT 的 LLM，由于 LLM 的运行是随机的，通常也会对每个输入采样 K 次输出，期望至少有一次成功。K 对所有输入是恒定的，这很低效：对简单案例是浪费，对困难案例又不够，对极难案例则无论采样多少次都不会够，连尝试都是浪费。加上 CoT 后问题更糟，因为 CoT 用"思考 token"炸开了搜索空间。这意味着在任何给定的采样预算（以 token 计）下，LRM 相比 LLM 探索的任务子集呈指数级缩小。如果 LRM 能在合理预算内呈指数级提高找到好答案的概率，那还能抵消搜索空间变大的缺点。但实证上似乎并非如此，LRM 往往运行很长时间、花费高昂。

另一个效率挑战是，奖励信号只在链条末尾给出，因而无法智能地分摊到链中的各个 token 上。（最后这一点并非 RL 固有的，而是反映了——同样据我们所知——当前 LRM 使用 RL 的方式。但完全可以应用过程奖励建模（Process Reward Modeling）为链中的中间步骤提供显式奖励。）此外还有空间复杂度方面的局限，因为整个训练都是把越来越多的链条喂进上下文窗口来完成的。随着工具集扩大、搜索空间随之增长，所有这些低效都会被成倍放大。类似地，测试时同样存在低效。LRM 说到底是一个语言模型，测试时你能做的就是把输入喂给它做一次前向传播。你无法很好地控制链条长度、无法并行化、无法根据算力资源的实时状态做自适应，*等等*。其中一些局限可以在一定程度上缓解：让模型倾向于产生更长或更短的链条相对容易；可以修改实现方式使多条链条并行展开，并通过多数投票之类的简单机制聚合结果；*等等*。但我们发现，与下文讨论的通过审慎规划实现的显式控制相比，这些启发式方法相当薄弱。

LRM 另一项独立的、也许更深层的算法局限，是它们无法以稳健的方式泛化。LRM 并不真正以通常意义上的方式"推理"。推理通常被理解为对可信程序的严格应用，其结果可预测且正确，并适用于一大类任务，例如乘法运算程序适用于所有合法输入。LRM 做不到这一点；它们只是概率性地追逐有用的 token 链。有时这些链条恰好对应于人们所说的推理，但一般而言并非如此，以致本文部分作者半开玩笑地将这些 CoT 模型称为"chain of thoughtlessness"（无思之链）、"large musing models"（大空想模型）和"large mumbling models"（大含糊模型）。无论你怎么称呼它们，最好的理解方式是：这些模型是精妙的自由联想器，而非推理者本身。有大量证据表明这些不是理论担忧，而是真实的短板。例如，一篇[近期论文](https://arxiv.org/abs/2502.01100)显示，o1 在各类组合问题上的表现随输入规模急剧退化。归根结底，样本复杂度总会回来找你算账。

在讨论绕过这些问题的方法之前，让我们简要提及几个在企业环境中至关重要、并为现有 LRM 架构部署带来进一步挑战的问题。

- *透明度、可理解性与可控性。*学习得到的 LRM 是不透明的。用户对链条的可见性有限——即便在提供链条轨迹的实现中，那些轨迹也往往不能可靠地反映 LRM 实际执行的搜索。用户当然更无法控制链条。
- *可预测性与保证*。就像它们源自的 LLM 一样，LRM 是概率性、"prompt-and-pray"式的机器。哪怕只是给 LLM 发一条 prompt 这样简单的流程，不同次尝试也会给出不同响应，且方差随流程复杂度增长。在企业中，提供非确定性的响应是绝对不可接受的——95% 的时间才华横溢、剩下 5% 胡说八道，是远远不够的。
- *可定制性。*从预训练、后训练到测试时计算的整个过程，处处都对领域敏感。具体来说，不同企业有不同的工具、不同的用例、不同的政策和不同的算力选项。AI 需要以某种方式与特定环境对齐，但 LRM 并不易于定制；充其量你只能通过 prompt 影响它，但能做到的十分有限，也不提供任何稳健性保证。尤其值得注意的是，它不允许你接入预训练期间不存在的工具。而为每个新环境重新训练一个 LRM 又不现实。

## 替代方案：在行动空间中规划

针对 LRM 的局限，业界已有各种补偿方案的建议，总体上归于一个被称为"AI 系统"（AI systems）的新兴领域。尽管细节各异，这一进路的共同点是认同这样一个理念：大模型——无论 LLM 还是 LRM——不是万能的终点，而是一个包含多个元素、并对其使用进行编排的更大系统的一部分。在 LRM（以及作为特例的 LLM）中，最终产物是一个模型，测试时对该模型执行标准的前向传播（尽管 R 类模型会引入"思考 token"）。相比之下，"AI 系统"在训练和测试时都有一个外部控制器来调用各种工具；控制器是外层循环，LLM 和其他工具位于内层。LLM 成为服务于编排器的一个工具——尽管是非常重要的一个。

说到最后一句，让我们先澄清一个可能产生的误解。本文可能被错误解读为我们认为 LLM 和 LRM 不重要。它们很重要。LLM 是"世界最大知识库"与 Kahneman 式系统 1 思维的奇妙组合。LRM 是出色的点子生成器。LLM 和 LRM 都有高方差的毛病，但正如我们下文将讨论的，它们都是构建可靠、可控、可预测的系统 2 AI 的关键要素。

构建 AI 系统最简单的方式，或许多是给现有模型加上*校验器（verifiers）*。这样就可以用一个简单的控制器来核验 L(L/R)M 的输出，如果检查失败，就想办法做得更好，或者告诉用户系统失败了。

我们确信校验器至关重要——在训练和测试时都是如此——但仅有校验器还不够。它们告诉你一个候选输出好不好，却不会帮你找到那些潜在的好输出。要在可能输出的干草堆中找到好输出，你需要执行一次智能的*搜索*，而首先要弄清你在搜索什么空间。能够支持系统性求解搜索的空间不是 token 序列的空间，而是*行动序列*的空间。行动集合是工具与工具可行输入之间的笛卡尔积。例如，如果把某个 LLM 作为一个工具，那么与该工具关联的行动集合就包括所有候选 prompt，再结合其他高层参数，如 temperature、随机种子或生成次数。因此行动集合是庞大的，行动序列的集合更是庞大。在行动序列空间中的搜索就是*规划*。我们将其视为近期 AI 方案中缺失的关键要素。

AI 领域有关于规划的丰富文献，从 1980 年代确定性启发式搜索方法开始，延续到今天更为常见的随机性方法。在随机域中规划的一种常用方法是蒙特卡洛树搜索（MCTS）。这正是 [Schultz 等人](https://arxiv.org/abs/2412.12119)近期一篇论文所使用的方法，论文表明外层的 MCTS 规划层能在游戏对弈中显著提升原始模型的性能。

在 AI21，我们相信同时学习如何规划以及如何执行规划，是实现稳健 AI 的关键，尽管 MCTS 本身并不足够。我们不展开具体细节（重申：那是另一篇论文的话题），但我们认为以下要素是实现稳健、基于规划的 AI 系统的关键：

- *一种用于描述规划的清晰语言*。在 AI21，我们已经开发了这样一种语言——它是 Python 的一个表达力强且行为良好的子集（详情我们很快会分享）。
- *清晰的目标*。借用柴郡猫的话：如果你不知道要去哪里，你就永远到不了那里。你应当尽可能以结构化的方式记录任务、可用的工具、对输出的硬性约束，以及其他相关要素，如可用预算（时间、金钱）和适用政策。然后你就准备好进行规划了。
- *建模成本与成功概率。*对计划中的每一步，都应当显式建模所涉成本的分布（以时间、算力和 $ 计），以及输出质量的分布。
- *决策论规划。*对成本和成功概率的建模使得决策论规划成为可能，既在训练时（为常见任务预计算计划），也在测试时（实例化并调整预训练的计划，并创建新计划）。测试时基于先验信息构建一个初始计划，并且只在恰当的粒度上进行。某些行动在看到具体输入之前无法规划，某些行动在看到其他行动的输出之前无法有效规划。因此规划与执行必须交替进行。
- *无校验，不生成。*计划中的每一步都关联一个校验器——可以是由确定性程序编码的硬性校验器，也可以是软性的启发式校验器（例如由评审语言模型 Judge Language Model 执行）。
- *"随时可用"（Anytime）的执行。*测试时快速提供一个不错的基线输出，并且在有理由相信还能改进、且预算允许的范围内持续改进它。
- *并行。*像没有明天一样地并行化。好吧，是在预算允许范围内。
- *人在回路。*测试时让用户全程参与。用户是老板，但从某种意义上说也是服务于系统的"工具"。向你提取的任务做确认；在合适的层级分享初始计划；在恰当的时机同步执行进展；在能力范围内为用户提供关于计划质量和成本的保证，并在做不到时明说。
- *谦逊*。需要时拒绝任务；并非所有任务都能完成，如果系统宣称自己有一个好计划而实际上没有，用户会对它失去信任。
