企业领导者早已被"自主 AI agent 将革命性改变商业"的炒作淹没了。各大厂商都在兜售所谓只需极少人工投入就能处理复杂任务的"agentic AI"系统。然而在实际层面，企业对 AI agent 的真正采用正在停滞。事实上，Gartner 预测[**到 2027 年超过 40% 的 AI agent 项目将被取消**](https://www.gartner.com/en/newsroom/press-releases/2025-06-25-gartner-predicts-over-40-percent-of-agentic-ai-projects-will-be-canceled-by-end-of-2027)，原因是成本飙升与价值不清[1](https://www.ai21.com/blog/maestro-putting-knowledge-to-work/#243774bf-30a2-4abd-bab8-2ebb8937309a)。尽管投入不断上升，多数部署仍停留在试点模式，几乎没有真正的 ROI。现实始终没能兑现承诺。

为什么这么多企业 AI agent 计划步履蹒跚？不是因为理念有错，而是当前的打法瞄错了靶心。大量精力被耗在建 agent 框架、工具集成或灵活管道上——却没有想清楚真正的价值在哪里。

## 真正的价值所在：知识工作——而不只是知识检索

"agent"（智能体）这个词本身已暗示其工作是认知性的。但太多时候，被造出来的不过是高级版检索壳——基本的 RAG 聊天机器人，从文档里翻出片段来回答问题。这类系统可能有用，但它们做的不是*知识工作*，它们做的是**知识查询**。

这正是我们必须分辨得更清楚的差别。

真正的机会，不在于帮客服代表从政策文档里调出一段引文，而在于**自动化那种今天只有受过训练、理解上下文的人类知识工作者才能完成的工作**——从多个来源检索信息、在含糊不清中推理、做出判断、综合证据，最终产出高价值的结构化成果：一份报告、一份摘要或一条建议。

Peter Drucker 在 1950 年代创造了"知识工作"（knowledge work）一词来描述这类工作：核心任务是用信息来思考、分析和产出。1950 年代，只有约 15% 的劳动者属于这一类；今天，在现代经济体中这一比例高达 70% 以上。然而我们看到的大多数自动化——无论是否基于 AI——仍围绕体力任务或例行行政流程。

AI agent 要成为企业运营的核心，就必须为企业规模的知识工作而构建。这意味着处理高风险的多步任务——比如产出并购尽调摘要、战略供应商评估报告或合规风险报告——而不只是回答 FAQ 或查询数据库。

这正是生成式 AI 该大放异彩之处——不仅因为它理解语言，更因为它能生成和评估想法、执行推理，并流畅地对接知识工作所依赖的工具与格式。尽管承诺满满，这场变革在实践中仍未发生。

## 为什么还没发生？

### 1. 错误随每一步成倍放大

第一道障碍是跨多个推理步骤的可靠性。知识工作不是一锤子买卖——它是一串动作，往往有依赖关系和不断演化的指令。但今天的 agent 仍然依赖在长链条上会失去连贯性的概率模型。早期一个误解或幻觉，就可能滚成残缺不全或彻底错误的答案。

研究中对此早有记载：LLM 的表现随任务长度衰减，而现有大多数框架在运行时自我纠错方面给不了什么。简言之，试图"边跑边想"的 agent 常常跑偏。

### 2. 它们缺少正确的上下文——也没有使用它的能力

更具限制性的，是企业特有上下文的缺失。在商业环境中执行高价值知识工作，需要知道去哪里找信息、如何在流程中穿行、什么与任务相关、如何在多种可行方案之间抉择。

这类上下文不是开箱即用的 LLM 天然"知道"的，也不是简单塞进 prompt 就行的。

拿一个筹备大客户提案的团队举例。人类分析师知道过往提案放在哪里、哪些与当前项目相似、这位客户看重哪些成功指标、如何根据内部定价政策或以往的赢单/输单分析来调整话术。他们还携带着组织记忆——了解类似交易过去如何演化、哪些说辞在以往谈判中引起共鸣、公司已放弃哪些做法及其原因。今天的 agent 对这些一无所知，除非有人把它显式地——通常还是手工地——编码进 prompt 或代码。它们缺乏这种机构知识，也缺乏从经验中学习的能力。它们不知道该看哪里，不知道为什么某些输入比其他更重要，也不知道如何把输出调整得符合组织规范。

这就是当前的天花板：agent 能检索事实，但还不能带着判断、综合与规划，用鲜活的专有企业知识执行工作流。

## 真正的机会：为复杂知识工作提供可信的 Agent

想象一下，如果我们能信任 AI agent 端到端地完成高风险知识工作，会有怎样的可能。

### 示例 1：端到端的并购尽调

一个企业发展团队需要评估一个收购标的。流程包括通读合同、NDA、董事会材料、财务模型、股权结构表和监管备案。它要求提取关键条款、识别不一致之处、生成资料请求清单、进行财务比率分析、总结风险。

如今，这需要一支分析师团队和数天的手工工作。有了合适的 agent，整条管道都可以自主完成——从文档摄取与信息提取，到综合与报告生成。过去要花一周的事，可以在一小时内完成，且每一步都可完全审计、可追溯。

### 示例 2：起草一份 AI 监管合规备忘录

法务团队被要求评估一个新的内部 AI 系统是否符合最新的 EU AI Act 条款。这需要审阅该系统能力的文档、与法律义务交叉比对、识别潜在不合规之处，并起草一份总结发现和缓解建议的备忘录。

一个为此任务而建的知识智能体会先定位并提取系统的相关细节、检索最新的监管指南、进行对比分析，并产出一份结构化的、法律上准确的建议备忘录——让法务团队腾出手来聚焦边缘情形，而非打地基的活。

在这两个例子里，价值都不在于检索到正确的片段，而在于把工作做完：驾驭流程、评估信息，并交付一份有结构、有理据、贴合需求的产品。这才是我们要抵达的前沿。

## 前行之路——AI21 Maestro

在 AI21，我们过去一年聚焦于一个问题：要构建真正能托付企业级知识工作的 agent，需要什么？

今天，我们自豪地推出 **AI21 Maestro**，正式面向企业客户开放。

Maestro 是一个构建和部署**知识智能体（knowledge agents）**的系统——专为在公司专有数据上执行多步推理与综合而打造的 AI 系统。它的设计不是像典型 agent 那样猜测下一步，而是有条不紊地规划和执行复杂工作流：选择正确的检索策略、校验中间结果、产出结构化且准确的输出。

与把规划交给运气、或需要数月硬编码逻辑的通用 agent 框架不同，**Maestro 为每个任务动态规划**，在成本与延迟等权衡之间取得平衡，并在工作过程中自我纠错——产出清晰、透明、可追溯、可信任的输出。

与简单的 RAG 管道不同，Maestro 不停留在检索。它走完知识工作的完整弧线：拆解目标、确定需要什么信息、检索、解读，并组装成连贯而有价值的结果——无论那是一份尽调备忘录、一份合规摘要，还是一份多页的研究文档。

我们相信，这才是 agent 一直以来的使命：不是模糊的聊天界面，而是能够在企业环境中**真正干活**的系统——干那些需要精度、结构和推理的工作。
