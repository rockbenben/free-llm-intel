# 后训练案例研究：与 Alice 一起达到前沿级攻击韧性

*本文由 Assaf Gerner、Guy Rephaeli、Asaf Karnieli、Guy Freund、Shaked Meirom 与 Joanna Kramer 撰写，与 Alice 的 Liran Cohen 和 Dadi Atar 合作完成。*

在仅仅三周里，我们的前沿部署研究员（Forward-Deployed Researchers，FDR）团队与 Alice 的研究团队并肩协作，对近期发布的 [NVIDIA Nemotron 3.5 Super VL](https://blogs.nvidia.com/blog/nemotron-3-5-super-vl/) 进行了后训练，以提升其对间接 prompt injection、恶意请求等攻击的韧性。结果表明，专业化开放模型能以极低的成本超越前沿级质量：

- **41 个提升点** **的攻击韧性** ——相比基础模型
- **提升 10 个点** ——相比 GPT-6.1 Sol
- **便宜 25x** ——相比 GPT-6.1 Sol（按每 1M tokens 成本计）

**图 1：我们的训练配方把 Nemotron 3.5 Super VL 从在质量与成本上与 GPT-6.1 Luna 相当，提升到以一小部分的成本在质量上超越 GPT-6.1 Sol。 **

本文详述 Alice 的用例，并介绍我们为在 Alice 的用例上达到前沿级结果而开发的定制训练配方。

## 与 Alice 一起提升 agent 抗攻击韧性

[Alice](https://alice.io/) 是一家 AI 安全与防护公司，为后训练构建 RL 环境（RL Environments），这些环境由关于威胁行为者行为的真实世界情报（「Rabbit Hole」）以及 150 多名内部安全研究人员与专家网络成员的意见提供信息支撑。他们为 AI21 提供了一套 RL gym，用于训练 agent 在其企业环境——包括平台、系统、工具、数据与工作流（如 Slack 与 GitHub）——中抵御安全威胁。目标是产出的 agent 在抵抗攻击与完成任务两方面都拿到高分——不让其中一个以牺牲另一个为代价。

*图 2：来自 Alice gym 的一个 Slack 任务示例。公司与域名均为虚构。*

这类攻击中的一种是间接 prompt injection——恶意指令被植入 agent 通过工具读取的信息中。例如，一个 agent 可能被告知在 Slack 上向员工发送密码重置提醒——但重置链接已被破坏，存在暴露员工登录凭证的风险。在 Alice 的 RL gym 中训练过的 agent 会学会发现这一漏洞并阻止它，同时仍然完成它的原始任务：通知员工重置密码（图 2）。

随着更多企业把 agent 整合进核心工作区——这意味着对敏感信息的大量访问以及对员工的广泛触达——确保这些 agent 有能力发现并阻止攻击变得至关重要。我们在 Alice 的 RL gym 上对 Nemotron 3.5 Super VL 做后训练的工作证明，agent 完全可以在保持高攻击韧性的同时完成任务。

## 挑战

要成功对 Nemotron 3.5 Super 做后训练、使其在这一用例上表现出色，我们的 FDR 必须应对两个核心挑战。

第一个挑战是如何在不损害常规良性任务完成率的前提下提升攻击韧性。以上面的例子来说，如果 Slack agent 在检测到恶意重置链接后就拒绝继续工作，它确实成功保护了公司——但最终并不是一个很有用的 agent。

第二个挑战围绕数据。鉴于训练数据集只包含数百个样本，团队需要找到一种方式，在不让模型过拟合训练数据的情况下完成训练。

他们设计了后训练流程来解决这些挑战。

## 方法论

### 在 Alice 的 RL gym 中训练 agent

要同时解决这两个挑战，就必须按 Nemotron 3.5 Super 的实际使用方式来训练它：作为一个在活跃环境中行动的 agent，而不是一个回答孤立 prompt 的模型。Alice 的 gym 被打包为 Harbor 任务 [1]，每个任务都自带一个容器镜像，内含一个模拟工作区，如 Slack 或 GitHub。

每一次 rollout，AI21 Training Platform 都会从该镜像启动一个全新的独立沙箱。随后模型在沙箱内完成任务：读取消息、调用工具、采取行动。回合结束后，由 gym 为结果打分。为每次 rollout 配备独立沙箱保证了训练的安全性，因为 agent 对攻击的任何响应都留在沙箱内。这也让我们能并行运行数百次 rollout。我们在整个流程中使用同一套配置：为 SFT 生成轨迹、为 GRPO 产生实时 rollout，以及评估每一个 checkpoint。

### 用近策略 SFT 热启动

在线强化学习已成为语言模型后训练的标准方法。由于它是 on-policy 的，模型从训练期间自己生成的 rollout 中学习，而不是从预先收集的数据集中学。在自己生成的输出上训练能提升质量，并降低灾难性遗忘的风险。使用最广泛的在线 RL 方法 GRPO 会为每个 prompt 采样一组 rollout 并将它们相互比较，从而让模型学会区分更好与更差的输出。这意味着只有当一组内的 rollout 拿到不同奖励时，GRPO 才能学习。如果一组中每条 rollout 都得到相同分数，所有优势都为零，该组不贡献任何梯度，什么也学不到。

然而在本案中，我们对 Nemotron 3.5 Super VL 做首轮评估时发现，模型生成的 rollout 多样性分数非常低。因此，在进入 RL 之前，他们先跑了一个监督微调（SFT）阶段，以提高组内奖励方差非零的任务占比 [2]。SFT 之后，训练集中奖励标准差非零的任务占比从 35% 升至 66%。

我们在这些 gym 上从若干开放模型生成了成功的 rollout，但原样用它们训练存在两个问题。其一，其中一些模型的推理链非常长，有时会陷入重复循环（图 4），这不是我们希望 Nemotron 3.5 学到的习惯。其二，SFT 数据应当教授安全行为，而不是另一个模型的写作风格。更宽泛地说，贴近策略自身分布的数据更容易学习、造成的遗忘也更少 [3]，所以即便在 SFT 阶段，我们也尽力让训练数据尽可能 on-policy（图 3）。为此，他们让 Nemotron 3.5 Super 用自己的话改写每条轨迹中的推理，从而在缩短长链的同时保持每个动作不变 [3,4]。

图 3 展示了效果。按原样，开放模型的 rollout 相对基础模型自身 rollout 的困惑度几乎高出两倍（×1.99）。在其上微调得到的策略漂移至 ×1.40，而在改写过后的 rollout 上微调得到的策略保持得更近，为 ×1.23。改写把额外增加的困惑度从 40% 压到了 23%。

**图 3：基础模型对每个模型的 rollout 有多「惊讶」。我们用 Nemotron 基础模型下的困惑度为每组 rollout 打分。困惑度越低，意味着 rollout 越贴近基础模型自身的分布。数值相对于基础模型对其自身 rollout 的困惑度（参照）显示。Average OS Model：以开放源模型的 rollout 作为 SFT 数据时，对这些 rollout 取均值。Original SFT：在那些原样 rollout 上微调后所得策略产生的 rollout。Rephrased SFT：在改写后的版本上微调后所得策略产生的 rollout。误差棒显示 95% CI。**

解决办法是让 Nemotron 3.5 Super 用自己的话改写每条轨迹中的推理。这样做在缩短长链的同时保持每个动作不变 [3,4]。

**图 4：改写 SFT 数据能把 checkpoint 的推理长度砍半，并几乎消除最常见的重复填充词（如「Hmm. OK」）。**

在改写数据上训练的 SFT checkpoint，质量与在原始 rollout 上训练的 checkpoint 相当，但生成的 token 少得多，且没有在其他任务上退步。

### 在线 RL 中的奖励塑形

在我们建立起一个好的 SFT 训练后的 Nemotron-3.5-Super-VL checkpoint——结果更好、rollout 更多样——之后，我们得以前进到第二阶段：使用 GRPO 的在线 RL 训练。

原版 GRPO 分两步计算每条 rollout 的优势：先减去组的平均奖励，再除以组的标准差。我们很快就发现，第二步并不适合 Alice 的 RL gym——它们使用稠密的连续奖励。除以组的离散度会把奖励差距的大小丢掉。例如，一组奖励为 [0.49, 0.51] 与另一组奖励为 [0, 1]，最后都得到优势 [−1, +1]。排序保住了，但幅度丢了。对于稠密奖励，这意味着微小、甚至可能带噪的差别——比如 LLM 裁判分数的一点轻微漂移——会被放大成满额梯度 [6,9]。因此我们舍弃了标准差归一化，只保留组均值基线（图 5）。

要让响应长度受控，还需要对奖励做另一处修改。响应长度在 RL 期间常常增长 [5,6]。而在本案中它增长得很猛，一些 rollout 陷入循环直到用尽上下文窗口。为应对这一点，我们消融了两个额外的奖励项：(1) 组内相对长度惩罚，惩罚每组中最长的 rollout [7,8]；(2) n-gram 重复惩罚，惩罚推理中反复出现同一 n-gram 很多次的 rollout [5]。事实上，这三处修改的组合取得了最好的结果——达到最高质量，同时生成最短的响应长度。（图 5）

*图 5：从同一个 SFT checkpoint 出发，每次只添加一处奖励改动：去掉 STD 归一化即可把奖励抬升到仅用重复惩罚之上的水平，而再加上长度惩罚则能阻止推理增长，并达到最高奖励*

## 结果

*图 6：验证集及其 GitHub 与 Slack 子集在各训练阶段——从基础模型经 SFT 到 GRPO——上的分布内得分。*

后训练后的模型在两组不同的集合上评估。用两组是为了检验其增益反映的是真实的安全行为，而不是对训练环境的过拟合。第一组是验证集，使用与训练相同的 GitHub 和 Slack 环境，度量分布内表现。第二组是 CHASM——Alice 的企业级间接 prompt injection（IPI）基准——它被设计为一个分布外 gym，包含 117 个攻击任务，横跨金融、HR、法务、客户支持等领域的企业工作流，行业覆盖从医疗到电信。

CHASM 与 RL gym 之间不共享任何任务或应用，因此它检验的是这种行为能否泛化。它的攻击多为间接 prompt injection 与中毒记录，试图把 agent 推向外泄数据、破坏机密性或转移付款。

在验证集上，每个阶段都在上一阶段的基础上继续提升（图 6）。SFT 使分数近乎翻倍，从 35.19 到 65.28；GRPO 再把它抬升到 76.2。GRPO 的大部分增益来自 GitHub（66.48 → 85.17），而 Slack 仅小幅提升（64.08 → 67.22）。

在 CHASM 上，基础模型仅得 7.54。SFT 将其抬到 34.58，主要靠教会模型避开有害动作。GRPO 守住了这一增益但没有再增加。SFT 学到的安全行为可以迁移到未见过的环境与攻击类型，而 GRPO 带来的增益仍停留在训练分布内。

## 用定制后训练配方达到前沿级攻击韧性

AI21 与 Alice 一起，把 Nemotron 3.5 Super VL 的攻击韧性相比基础模型提升了 41 个点、相比 GPT-6.1 Sol 提升了 10 个点，且没有损害整体任务表现——同时成本比前沿低 25x。为取得这些结果，AI21 的 FDR 团队顺序应用了 on-policy SFT，随后是修改版 GRPO（在线 RL）技术。

他们的工作表明，企业可以训练把自身核心安全与防护策略内化为核心行为原则的开放模型，确保 agent 在完成指定任务的同时发现并抵抗威胁，例如 prompt injection 攻击。
