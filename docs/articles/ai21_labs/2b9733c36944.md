到这里，token 支出问题已经被大量记录在案。而且它不会消失：[Goldman Sachs 预计 token 用量到 2030 年将增长约 24 倍](https://www.goldmansachs.com/insights/articles/ai-agents-forecast-to-boost-tech-cash-flow-as-usage-soars)。

这意味着 AI 领域的领导者们要应对的是不同的问题。在我们自己的对话里也注意到了这一点。我们已经听不到“*我的 agent 足够好吗？*”这样的话，现在的问题是：“*我们付得起把它规模化运行起来的成本吗？*”

这一转变带来了新的技术挑战。团队需要自动化系统，能在不损害 agent 质量的前提下削减浪费掉的 token —— 并且随着模型、价格和工作流的变化，持续改进这些削减。

## 不只是新闻标题

我们采访了某家企业级 AI 编程公司的一位 CTO，他用一句话精准概括了当下：*“我理解你在 token 上花了 $1M，但影响是什么？没人答得上来。”*

团队知道自己需要削减成本。但有两个挑战挡在前面。在与数十家已在生产环境跑 agent 的团队的私下交流中，我们听到的是这些：

- **手工调 agent 又慢又脆： **新的优化方法每周都在发布，而且不是每个招数都管用。某家 S&P 500 软件公司的 AI 副总裁告诉我们，他们那些把流量切给更便宜模型的 routing 规则最终反而让成本*上升*，因为更弱的模型产生的轨迹长得多。为每个用例找到正确的逻辑，可能要花上几周实验。
- **模型一变就归零： **agent 优化不附带终身保证。某家 AI 编程独角兽公司的 CEO 分享说，每当底层模型发布更新，他们的定价和性能假设就会被推翻。新增一个模型、工具，或者调整 harness，也是同样的事：地面在移动，精心调好的 agent 或 routing 规则就过时了。

我们从一线得到的图景是：agent 优化 —— 在不损害质量的前提下削减成本 —— 至今仍是手工编写、且对每个用例都不精确；要绕过这些障碍，需要的资源、时间和专业能力，是许多公司不具备的。

那么在这期间，团队们都在做什么？

## 团队正在收敛到 routing

你可以在技术栈的各个位置挤成本，但我们听得最多的是 **routing**：把每次调用发给能处理它的那个最便宜的模型。routing 无处不在：

- 来自行业领袖：就在过去一个月里，[Salesforce CEO Marc Benioff](https://youtu.be/jJRAvZNGUvI?si=SSY3LOp65ndhMYrh&t=3636)、[Harvey 联合创始人 Gabe Pereyra](https://www.youtube.com/watch?v=NpZbum0lmlI)、[Box CEO Aaron Levie](https://www.linkedin.com/posts/boxaaron_over-the-coming-weeks-and-months-youre-going-activity-7472664573737689088-9zmv) 都在为 routing 现身说法。
- 来自生产数据：[Vercel 的新报告发现](https://vercel.com/blog/ai-gateway-production-index)，规模化运行的团队**平均把 35 个模型**当作一张 routing 图来跑。这已经是生产环境的最佳实践。
- 在我们自己的实验室也一样：过去几周我们花时间研究多样化模型与 agent 集成的好处，最终拿下了 [BrowseComp-Plus 第一名](https://www.ai21.com/blog/maestro-deep-research-agents/) 和 [DeepResearch Bench II](https://www.ai21.com/blog/merging-weak-agents-into-a-state-of-the-art-deep-researcher/)。

难点在于把 routing 变成自动的，用一套逻辑去学习对每个 agent、每个领域各自最优的调用。它还得考虑 provider 的特殊性、KV caching、query 差异等等。

## 我们如何自动化 agent 优化

**我们从构建一个智能路由器开始，**这是一个即插即用的层，你把 agent 端点指向它，就能在运行时找出并削减浪费。在基础层，它识别 token 泄漏的常见来源（例如冗余上下文、重复指令、无关工具），并以 cache-aware 且一致的方式把它们裁掉。在这一层之上，它做出更高级的 routing 决策，并随着流量积累持续改进。
