太长不看

在可验证奖励上跑 GRPO 时，动态采样对稳定训练过程作用很大，但它也可能让训练慢得惊人。本文提出"动态数据小睡（dynamic data snoozing）"——一种在不破坏训练稳定性的前提下削减算力浪费的简单有效策略。应用这一方法，我们在不损失质量的情况下把算力效率提升至多 3 倍。

## GRPO 的高效批次构建

GRPO——因其有效和简洁而成为当今事实标准的 RL 算法——经常碰到某些训练输入产生不了学习信号的情况：当该输入的所有 rollout 奖励相同时，每条 rollout 计算出的 advantage 为 0。跑 GRPO 时忽视这一点会导致训练不稳定，因为我们的有效 batch size 并不固定，而是取决于带学习信号的样本数量。

这些 0-advantage 样本会引发训练不稳定，[DAPO](https://arxiv.org/abs/2503.14476) 论文用如今已成常规实践的动态采样机制处理了这一问题。动态采样会把没有学习信号的组——无论是太简单还是太难——过滤掉并替换为新输入。无论这些 0-advantage 样本实际上是被训练过程忽略、还是被显式替换，它们都显著拖慢了训练：我们为它们生成了对模型训练毫无影响的浪费样本。

图 1 展示了 DAPO 训练过程中用于生成的总样本数与实际用于梯度计算的样本数之比。训练低效一目了然：

- 初期：**训练效率尚可**，因为许多样本处于"不太简单也不太困难"的区间。
- 随训练推进：**训练最多慢至 16 倍**（相比最优采样器），因为样本变得越来越简单。

说到底，一次训练运行中实际用于训练的生成分布不到 15%。

图 1：使用动态采样的 DAPO 训练效率。可以看到，随着训练推进，生成的批次数量与最优生成量（每步一个）之间的差距不断拉大，导致训练越来越慢、越来越低效。

为了弥合这一巨大的性能落差，我们开发了几种简单方法，并在 [Jamba2](https://www.ai21.com/blog/introducing-jamba2/) 的训练中获得了性能收益。

### 离线难度分层

我们从离线难度分层开始——这是在线 RL 训练的关键预备步骤，在学习开始前提供对任务复杂度与模型行为的扎实理解。这份映射可以同时指导数据过滤与课程（curriculum）构建。

为创建这一分层，我们在训练数据上跑了多个基线模型的若干补全。基于这些模型在每个样本上的成功率，我们可以按实证难度切分训练数据，并为模型构建课程：过于困难（反正会被过滤）的样本被推迟到训练的较后阶段；反过来，过于简单的样本可以在时机成熟时彻底移出训练。借助这一分层，我们还可以调整数据集权重，对当前模型 checkpoint 而言信号最密集的数据区段做上采样。

虽然这对手动控制模型训练中样本的难度很有用，但这种 off-policy 方法会带来对样本难度的次优分类。为了更有效地处理数据中"过于简单"的那一侧，我们转向了在线、on-policy 的方法。

### 动态难度过滤

为了优化从训练集中移除过简样本的过程、简化数据再平衡，我们在训练流程中加入了一个简单却有效的启发式。

假设某数据集的奖励在 [0, 1] 区间。若一个样本组内所有 rollout 的奖励都为 1，则定义该样本"太简单"。这样的样本本来就会被过滤掉——因为所有 rollout 的 advantage 都是 0。假设训练正常推进，我们的模型理应在该样本上继续保持满分，那么没有任何理由在后续批次里继续把它展示给模型。于是，一旦某个样本因"太简单"被过滤，此后每个 epoch 再遇到它时我们持续过滤，省下昂贵的 rollout 生成阶段。训练预算便可重新分配给难度适中的样本。

图 2 描述了对 GSM8K 数据集应用动态难度过滤后的训练动态。动态过滤带来可观的 3 倍算力效率提升，最终测试分数保持相似——各变体都达到 84%。

图 2：GSM8K 的训练效率。我们把 DAPO 动态采样（红）与提出的方法——动态难度过滤（蓝）以及小睡系数为 5 的动态数据小睡（绿，本文后半部分介绍）——进行对比。可以看到两种方法都大幅减少了训练中生成的批次数，远低于朴素的动态采样。

## 在多任务批次构建中保持高效

动态难度过滤虽然带来可观的效率增益，却并非没有缺陷。在 GSM8K 这样的简单数据集上没有取舍，但当进入在多个数据集上训练的现实场景，事情就乱糟糟了[1](https://www.ai21.com/blog/dynamic-data-snoozing/#ce3be59b-6ec4-4f5f-a3b5-621731f9ed48)。由于不同任务的学习速度不同，来自各数据集的过滤速率也不同且随时间变化，这让 batch 内数据集的平衡更难控制——使用在线难度过滤时，这可能伤害稳定性。我们需要一种方法：保住效率增益，同时在多数据集之间维持稳定。

### 任务饥荒与模式坍缩：动态难度过滤的风险

图 3 中是一个按实证难度分层为简单与困难两个子集的数学数据集。构建 batch 前按等权重从两个子集采样，图中描述的是每一步中各子集在 batch 里的占比。首先，由于组过滤速率不同，我们观察到它们在 batch 中的代表性并不均等。随着训练推进，模型解数学题越来越强，batch 越来越被困难子集占据。

图 3：使用 DAPO 动态采样训练期间 batch 的构成比例。随着训练推进、模型能力增强，训练集中的简单子集因为变得太简单而被更频繁地过滤。

在大型多任务场景里，上述现象可能引发训练中的意外问题。一个潜在问题是"饥荒"——如果某任务相对其他任务更难，它可能被过滤得比其他数据集更多、在训练中代表性不足。除非我们为它在每个 batch 中保留一定下限的样本，这样的数据集会更慢地进步。

另一个问题出现在需要精心平衡的冲突任务数据集上。例如：

- **安全相关任务**：我们希望教模型在用户请求以某种方式不恰当时予以拒绝。
- **有据问答（grounded QA）**：希望模型只根据提供的上下文作答，答案不在上下文中时克制不作答。
- **开放式问答**：希望模型基于知识截止作答，或调用网页搜索工具。

对这些任务，如果 batch 中输入的平衡长期过于倾斜，模型可能坍缩到单边行为——比如不停地拒绝回答。

为了演示冲突任务的挑战，我们在一个部分输入无法回答的有据问答数据集上训练模型。两个数据集的权重设为：不可回答题 10%、可回答题 90%。图 4.C 展示了训练推进中 batch 里不可回答题的实际占比，对比常规训练与在线难度过滤。由于训练动态，许多可回答题被过滤，留下训练集和 batch 中过剩的不可回答题。图 4.A 与 4.B 展示模型在每个子集上的表现：不可回答题在 batch 中占比的抬升，导致可回答子集上的性能明显退化——模型开始拒绝回答许多本可回答的问题。

为了应对这些潜在风险，我们需要一种走中间道路的方法：移除过于简单的样本以免训练变慢，同时确保训练数据即便跨多个数据集也保持平衡。

## 引入动态数据小睡

回顾上面关于冲突任务的数据，"简单样本永远简单"这一假设显然不成立。我们需要一种方式定期回访这些样本，确认它们没有被遗忘。为了在不牺牲在线过滤性能增益的前提下支持这一能力，我们把动态难度过滤演进成了动态数据小睡。

简单说：不再永久过滤一个过简样本，而是让它"小睡"预设数量的 epoch。图 4 展示了同一数据集在小睡系数 2、3、5 个 epoch 下的表现。更高的小睡系数导致训练中暂时的性能退化更大，但模型能够恢复。这证明了动态数据小睡的可行性：保住动态过滤的性能增益，同时避开多任务场景的潜在陷阱。

图 4：在有据问答数据集上对比各样本采样方法。动态小睡在可回答与不可回答两个子集（分别为 A、B）上都保持强劲表现，同时维持算力高效。相反，激进过滤（红色）导致训练失衡与模式坍缩。小睡系数控制的是计算效率与训练不稳定风险之间的权衡。

图 2 展示了动态小睡在 GSM8K 上的表现：更激进的动态过滤有 3 倍效率增益，动态小睡仍有扎实的 2 倍。

### 动态数据小睡的实操

#### 选择小睡系数

小睡系数代表一种权衡：在给定数据集上想省多少算力，vs. 因数据集与其他任务交互而训练失衡的风险。如果我们对所训练的数据集有扎实理解、认为它相对独立，就选更大的小睡系数多省算力；反之，若认为数据集内部交互很多，就选 1 或 2。默认我们使用小睡系数 5，整体效果好且算力收益大。

#### 固定 batch 比例

本文假设数据集权重在过滤之前定义：某样本被过滤后，我们按同样的权重采样新样本。作为替代，也可以把权重定义在最终 batch 上——被过滤的样本从同一原数据集重采样。

这一改造有少许效率代价，但改善了许多前述问题。不过要注意：很多时候我们无法假定两个冲突数据集之间有清晰的分界。单个数据集可以隐式地由不同分布构成，而小睡让我们防止实际 batch 分布跑偏。

#### 用概率化小睡抹平不稳定

回看图 4：小睡让训练得以推进，但大系数下仍有波动和跌落。为了让行为更平滑、训练更一致稳定，我们试验了小睡的概率化版本：不再让样本小睡 N 个 epoch，而是在每个 epoch 以 1/N 的概率过滤它。这一方法大体有效，是确定性小睡的合理替代。

#### 动态样本加权

上面的概率化小睡，可以理解为单纯调低过简样本的权重。有了这个新视角，可以把动态权重推广到所有训练样本——不只限于没有学习信号的那些。模型在每个样本上表现给出的实证信号，可以纳入单个样本采样权重的分配，提高对我们模型最合适样本的权重。我们一直在试验这个方向，看到了很大潜力。

## 结论

我们探讨了审慎处理数据难度与课程构建如何大幅提升现有在线 RL 训练方法的效率。当我们转向在 agentic、长程任务上训练 LLM，在线 RL 正逐渐成为整个 LLM 训练栈中最昂贵的环节。我们把数据效率认定为一个大体被忽视的探索方向——它有潜力显著提升我们训练管道的效率。

动态数据小睡正是例证：一个对我们数据采样的简单直白的在线改造，带来了显著的效率提升。我们还讨论了现实多任务场景下在线 RL 训练不容小觑的动态——过度天真的方法在某些情况下会造成剧烈的训练不稳定。

希望这项工作能激发对这一研究方向更多的兴趣。
