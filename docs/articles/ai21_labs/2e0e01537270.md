## 简要说明

*在 agentic 搜索中，小模型通常已经产出了正确答案，却没有选中它。多数投票救不了这一点，因为它无法推翻一个流行的错误答案。加入一个独立校验器——对每个候选重新调研并否决错误者——就能在 FACTS-Search 上击败已发表的 SOTA；而一旦你训练了自己的 8B 校验器，它几乎不花钱、适配任何生成器池，并能泛化到新 benchmark 和新检索工具。*

图 1：候选池固定，只换校验器。仅靠多数投票得 83.3，低于已发表的 SOTA。未经训练的 Qwen3-8B 校验器达到 84.8，仍差一点。Claude Opus 校验器增加 10.1 分、花 2.94 美元；我们训练的 8B 校验器达到 92.9，成本只比完全不用校验器多一分钱。

让 agentic 系统更准确的默认做法，是买一个更好的生成器——一个前沿模型。这招有效，但它是最昂贵的选项。

本文要提出一个不同的论点：你怎么运行模型，比你运行哪个模型更重要。下面这套系统为任何 AI 架构加上了一个关键组件：校验器（verifier）。无论架构是前沿模型的集成还是高效的开源模型，这个组件都能提升每一个架构的性能。

## 为什么 agentic 搜索需要校验器

**你的高效 agent 多半已经找到了正确答案。问题在于它没有选中它。**

模型运行不是确定性的。同一个 agent、同一个问题，一次失败，下一次就成功。在我们测试过的所有生成器上，pass@k 都远高于单次准确率（pass@1）：正确答案常常就在池中，只是没被选出来。**所以 agentic 搜索的约束瓶颈在选择，不在生成。**

选择是可为的，因为检验比生成容易（至少对 agentic 搜索 QA 如此）。回答"*哪个乐队在收录了 'Little Sister' 的 Steve Earle 专辑里演奏了 'Johnny Come Lately'？*"需要一连串搜索、死胡同和综合。而验证一个候选答案要窄得多：调研一条主张，然后裁决。

**那么用集成的时候直接多数投票不就行了？**因为投票无法推翻一个流行的错误答案。当池子半数自信地重复同一个错误实体时，投票不是在过滤错误，而是在为错误盖章。高效池最常栽在这里——因为正确答案出现的频率更低。

图 2：FACTS-Search 一个问题上的三阶段循环。生成器产出 k 个候选，校验器对每一个独立调研并给出裁决，聚合器只在通过验证的答案之间投票。这里多数答案幸存了；这个循环的价值在于它不幸存的那些情形。

## 验证确实有效

首先，别管成本，用得上最好的校验器先跑一遍。

我们在 **FACTS-Search** 上工作——Google DeepMind 的 benchmark，由需要网页搜索才能回答的困难多跳事实问题组成。本文中所有模型，无论生成器还是校验器，都使用同一个 Brave Search API，因此测得的差异是模型能力之差，不是工具之差。

由闭源与开源模型组成的生成器集成（Claude Haiku、Sonnet、Opus、Qwen3-Coder-30B-A3B，k=4）在单纯多数投票下得 **83.3**，**叠加 Claude Opus 校验器后达 93.4**，超过已发表 SOTA 的 89.4（[GPT-5.6 Sol](https://www.kaggle.com/benchmarks/google/facts-search)），如图 1 所示。

## 头部空间在低端更大

前沿对前沿证明了机制。实践中真正要紧的形态是小生成器，而那里的头部空间不缩反涨：更嘈杂的池子依然会浮现出正确答案，只是数量处于劣势——而这恰恰是"识别出它们"回报最大的时候。

我们的全开源池（Qwen3-14B 与 Qwen3-Coder-30B-A3B，k=4）投票得 60.1。把 Claude Opus 校验器放到同样的候选上，得 **80.4，每问花费 1.76 美元**。二十分就这样躺在池子里，等一个足够好的校验器把它们领出来。

图 3：全开源池上的同一实验。多数投票得 60.1，未经训练的 Qwen3-8B 校验器加 2.4 分。Claude Opus 校验器把池子抬升 20.3 分，成本是我们训练的 8B 校验器的 105 倍；而后者以每问 $0.017 拿回其中 16.9 分。

## 校验器是昂贵的那部分，所以我们训练了自己的

一个前沿校验器要对每个候选跑完整的网络调研循环：k 个采样乘以生成器数量——在我们最佳配置下是每问十六个循环。这比它所校验的全部生成加起来还贵：**93.4 的结果每问花 $4.26，大头在校验器。**

显而易见的修法是找一个小型开源校验器，但它不灵。原装的 Qwen3-8B 校验器只把高效池从 60.1 抬到 62.5——同样的候选上，+2.4 分对 Opus 的 +20.3 分。这 18 分的差距就是训练问题：验证这项技能并不随参数白送。

## 训练

给定一个问题和一个候选答案，校验器运行自己的基于 Brave 搜索的 ReAct 循环，输出一个裁决。奖励是与标准答案标签的二元精确匹配，因此完全可验证，不需要奖励模型。训练数据约 6K 条（问题, 答案, VALID/NOT_VALID）三元组，来自生成器 rollout，去重、类别均衡，并按问题级别划分。

配方是先 SFT 后 RL，理由与 DeepSeek-R1 相同：冷启动的 RL 没有可探索的像样策略。这里的两个失效模式是验证特有的。只用 RL 会对类别不均衡进行奖励作弊——工具使用率九个步内从 94% 跌到 0%。平衡数据能堵上这条捷径，却堵不住底下真正的问题：策略陷入一种狭窄的搜索行为爬不出来，于是搜索质量就在冷启动所到之处原地平台化。只用 SFT 则教会了搜索技能却稀释了裁决——模仿把损失摊到长轨迹的每个 token 上，而验证信号只住在一个 token 里。两者组合后，工具使用率保持高位且变得自适应，裁决变尖锐而策略不崩溃。

衡量这一切需要两样东西。每个 checkpoint 都重跑完整循环太慢，所以校验器变体是对固定的预生成 rollout 候选池离线打分的：候选永远不变，只有裁判在变。而且指标必须先按问题计算再取平均，因为 rollout 级别的裁决指标（accuracy、precision、recall、F1）**经常一边改善、系统一边变差**。我们追踪四个量（图 4）：pass@1 和 pass@k——无校验器时随机取一个的得分与 oracle 上限；pass@1(v) 和 pass@k(v)——仅在通过验证的候选上的同样两个。三个差距把责任分派清楚——两个在校验器，一个在聚合器：

- *验证增益 := pass@1(v) − pass@1* 是校验器的精确率：最大化它。
- *聚合器余量 := pass@k(v) − pass@1(v)* 是更聪明的聚合器仍能从已验证候选中挽回的部分——一条我们在此未展开的独立线索。
- *召回天花板 := pass@k − pass@k(v)* 是那些可解问题中校验器否决了全部正确答案的比例：最小化它。

图 4：这些代理指标，先按问题计算再取平均。健康的校验器会让它们保持如上嵌套关系。

## 结果

100 问公开测试样本，官方评分。成本按常见服务平台的价格计。

**在 SOTA 配置里换一个组件。**把我们训练的 8B 校验器替换 Claude Opus 校验器，保持 **92.9 分，$1.34**：半分质量差，成本**低 3.2 倍**，仍远高于已发表 SOTA。系统中最昂贵的组件变成了最便宜的之一。

**完全去掉专有模型。**Qwen3-14B 和 Qwen3-Coder-30B-A3B（k=4）叠加我们训练的校验器得 **77.0，每问 $0.017**——同一池子多数投票只有 60.1，用 Opus 校验器是 80.4。生成器几乎免费，校验器就是系统本身。它以低 2.5 倍的成本击败单次 Claude Haiku 调用（76.3，$0.043），并以低 6 倍的成本落在距单次 Claude Sonnet 调用（81.2，$0.1）4.2 分之内。

## 它能泛化

我们刻意只在一个 benchmark、一个工具上训练，因为现实情形是客户带着自己的配置而来。**BrowseComp-Plus** benchmark 同时改变这两者：任务形态相同，但 agent 从一个固定语料库检索，而不是搜索开放网络。

校验器开箱即用地迁移，把下游投票从 39% 抬到 51%。丢掉的是召回：在 27% 的可解问题上它否决了所有候选、白白弃题。最后再用约 85 个保留域外问题做一次极小的 SFT——大约 15 个优化步——把这个缺口从 27% 压到 4%，把下游推到 **69%**。

图 5：在 FACTS 上训练的校验器迁移到 BrowseComp-Plus（保留的 benchmark 与检索工具），跨不同 rollout 预算。精确率原样迁移（中图，k=32 时 39 到 51）。召回没有：校验器在 27% 的可解问题上把池子清空（右图）。用 85 个域外问题做约 15 步 SFT，把这一比例砍到 4%，把部署系统抬到 69。

在任何 rollout 预算下，验证最多给系统成本加 5%。我们在这里并不声称 SOTA，因为生成器只是单个开源模型。我们声称的是这个配方：精确率免费泛化，召回缺口容易弥合。

## 总结

- 在 agentic 搜索中，正确答案通常已经在池中。多数投票无法把它们捞出来，因为它无法推翻流行的错误答案。瓶颈在选择。
- 一个独立的"调研-否决"校验器把前沿池在 FACTS-Search 上从 83.3 带到 93.4，越过已发表 SOTA。它同时也是该系统的主要成本。
- 原装 8B 几乎拿不回这份增益。训练后，同样的 8B 以 $1.34 保持 92.9，距 Claude Opus 校验器半分之内、成本低 3.2 倍；并在整个技术栈不含任何专有模型的情况下以 $0.017 交付 77.0。
- 它能跨 benchmark 与工具泛化：精确率免费迁移，一次小型适配即可弥合召回缺口并进一步提升精确率。

*注意事项：两个 benchmark 都只在 100 问样本上评估；训练标签继承了自动评分器的噪声；两个 SFT 阶段都是从闭源模型蒸馏；验证增加一轮延迟。最后一点是有界的：验证轨迹比生成 rollout 短得多——后者要把检索到的文档拖过整个上下文——且各循环之间不共享状态，所以十六次验证的墙钟时间等于一次。*
