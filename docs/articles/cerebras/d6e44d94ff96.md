# AI 推理（Reasoning）的经济学

Sherif Cherfa

2024 年，OpenAI 向公众发布了世界上第一个推理模型 o1，随后 DeepSeek-R1 和 o3 接踵而至。

到 2025 年，几乎所有模型——无论诞生于何处、无论开放与否——都支持了 reasoning。

在 LLM 还在摸索工具使用的早期，reasoning、"thinking"、"curfuffling"、"cooking" 是一种力量倍增器。O1 和 O3 能在问题上 crunch 数小时，然后返回大体准确的回应。

它的技术名词是"[**test-time compute**](https://openai.com/index/learning-to-reason-with-llms/)"——本质是消耗更多计算机处理时间来提高输出准确率：模型在给出答案之前，会生成与自己争辩、质疑自己的 token。

在同一时期，基准开始饱和，AI 在结构化输出（"tool calling"）上变强了，前沿也转向"必须替你行动的 agent"，而非聊天式体验。

Agentic 轨迹看重模型快速、精准地串联工具调用的能力，而 reasoning 有时会碍事。模型思考得越久，在被压缩（compacting）之前可用于工具调用的空间就越少。

鉴于短短一年我们取得了如此多的进展，要判定 reasoning 的成本及其对性能的影响，并不会那么直截了当。

从数据中我们可以看到：

- 技术性 prompt 上多花 6 倍 token
- 完成时间多 7-11 倍
- 开启 reasoning 带来 10-20% 的提升

### reasoning 有哪些类型

- [交错式思考（Interleaved thinking）：](https://platform.minimax.io/docs/guides/text-m3-function-call)这是当前标准。LLM 会在工具调用之间思考，决定下一步行动——把上下文历史与待做的下一个决策放在一起权衡。
- [自适应推理（Adaptive reasoning）：](https://arxiv.org/abs/2511.10788)模型被训练成自己决定该推理多少。
- [可配置推理（Configurable reasoning）：](https://www.promptingguide.ai/guides/reasoning-llms#reasoning-llm-usage-tips)用户可以在不同档位（low、medium、high）之间选择。

### reasoning 擅长什么？

LLM 可以在运行时通过消耗更多算力来提高自己的准确率。做法是生成"探索"某个主题的 token。例如，你会看到类似内心独白的东西：模型怀疑自己、考虑替代方案，甚至把计划的要点复述给自己。这是它在试图构建自己的上下文窗口，让成功更可能发生。

这也是我们教它交织部分相关概念的机会：苏格拉底式追问、复查自己的工作、提前规划。

对需要一连串精确步骤的任务，这一切极其宝贵：

- 复杂的单发挑战
- 谜题、数学、逻辑
- 冲击基准目标

毫无疑问，加大思考预算会提升模型表现。一个绝佳的例子：GPT-5.5（xHigh）与 GPT-5.5（low）之间约有 10% 的差距，而 GPT-5.5（low）与 GPT-5.5（无 reasoning）之间又有 10%。

这对更小的开放权重模型同样适用。例如，开启 reasoning 的 Qwen-3.6-27B 与 Gemma-4-31B，都击败了去年带 reasoning 的 SOTA Sonnet-4。

平均而言，不设上限的最大化 reasoning 会让编码与 agentic 基准的表现提升约 20%；但你需要比关闭 reasoning 时多花大约 5-10 倍的输出 token（很贵！）。

### 多数会话能从 reasoning 中获益多少？

对我自己用 Codex、Claude Code、Droid 和 Pi agent 的 1000+ 次 AI 会话的分析显示：大约一半的 prompt 简单得惊人，完全不需要 reasoning 或复杂智能就能完成。

你的多数 prompt 大概长这样：

- "在应用里找到并打开 x 文件"
- "查一下我的邮件和日历，看看今天要做什么"
- "找出我机器上运行的进程"
- "克隆并分析这个 GitHub 仓库"
- "下载并配置 x 资源"
- "把这个媒体转成另一种格式"

### 更少 reasoning，更多速度

是时候把 reasoning 当作一个速度控制或成本开关来看了。Anthropic 和 OpenAI 都为 1.5-2.5 倍的提速收费 2 倍。如果我们只需把原始智能降 20%，就能快 7 倍呢？

对 Qwen3.6-27B 这样的模型，生成 token 的 87.5% 以上都是 reasoning——意味着一半的情况下我要多付 7 倍的冤枉钱。此外，在内存受限的环境里，kv-cache 会变少，压缩就更频繁，而每次压缩都显著降低性能。

关闭 reasoning 后，我们可以期待 agent 在触发压缩之前跑得更久，账单便宜 85%。

对时间敏感的工作——取文件、定位问题、响应事故、做增量更新，以及把 AI 当作系统的一个组件——为一档 20% 的提升缴纳沉重费用往往毫无意义。
