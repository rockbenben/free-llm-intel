# 用强化学习扩展代码修复 Agent：为真实仓库扩展 OpenHands

Gokul Ramakrishnan

作者：[Harsh Gupta](https://www.linkedin.com/in/harshguptashnd/)、[Nishit Neema](https://www.linkedin.com/in/nishit-n-b198101b5/)、[Shivashish Naithani](https://www.linkedin.com/in/shivashish-naithani-36a9517a/)、[Srinjoy Mukherjee](https://www.linkedin.com/in/srinjoy-mukherjee/)、[Sapan Shah](https://www.linkedin.com/in/sapanhshah/)、[David Bick](https://www.linkedin.com/in/davidlbick/)、[Gokul Ramakrishnan](https://www.linkedin.com/in/gramakri/)、[Ganesh Venkatesh](https://www.linkedin.com/in/ganesh-venkatesh/)

### 引言

训练有效的代码修复 agent 需要的不只是大语言模型——它还需要一套稳健的基础设施，能够高效、大规模地与实际代码库交互。在构建了一个以 Docker 镜像打包的真实"issue-解决"实例全景数据集之后，我们面临一个关键挑战：像 OpenHands 这样的现有 agentic 框架与基准特有的假设深度耦合，无法用于大规模强化学习（RL）训练循环。

本文详细记录我们的技术旅程：把 OpenHands 从一个 SWE-Bench 评估工具，改造成一个能处理数千个多样化 Python 仓库的通用 RL 训练平台。

### 挑战：挣脱基准的束缚

OpenHands 通过其 CodeActAgent 提供了精致的 agentic 脚手架，但它的评估流水线是专门为 SWE-Bench Verified 架构的。这种紧耦合体现在多个方面：

- **硬编码的仓库假设**：固定的目录结构和预定义元数据 schema
- **静态的环境期望**：依赖 SWE-Bench 的 harness 工具
- **不灵活的评估流程**：不支持任意 Docker 镜像或自定义测试配置

我们的数据集涵盖从 PyPI 和 GitHub 抓取数千个 Python 仓库，提出了根本不同的需求。每个仓库都自带：

- 独特的项目结构与构建系统
- 自定义测试框架与配置
- 各异的依赖管理方式
- 仓库特定的元数据格式

### 架构重设计：通用化评估流水线

### 动态元数据加载

我们彻底重构了评估工作流，以消除对 SWE-Bench Verified 特定假设的依赖。新架构：

- **动态加载任意 Docker 镜像**作为问题实例
- **运行时解析元数据**，包括：

- 基线 commit SHA
- 失败测试的标识
- 通过测试套件的规格
- 测试运行器配置（pytest 等）
- 仓库特定的环境变量

3. **在完全隔离的容器化环境中执行测试**

4. **报告与 RL 奖励信号兼容的结构化通过/失败结果**

这一转变实际上把 OpenHands 变成了代码修复任务的**通用评估引擎**，只需极少配置即可在任何仓库上运行。

### 优化：统一的 Rollout 架构

### 容器重复加载问题

最初的 OpenHands 设计把补丁生成与评估分离成独立的工作流。每一步都会：

- 从磁盘加载 Docker 镜像（典型大小约 8GB）
- 初始化新的容器运行时
- 设置仓库环境
- 执行操作
- 拆除容器

对中等大小的 Docker 镜像，这种重复每个实例引入约 **3 分钟开销**——对每次训练迭代要生成数千条 rollout 的大规模 RL 训练来说完全不可行。

### 单上下文 Rollout 系统

我们的方案实现了一个**统一工作流**，在整个 agent 轨迹期间维持一个持久运行时上下文：

**关键架构改动：**

- **单次镜像加载**：Docker 镜像在 rollout 初始化时只加载一次
- **持久容器**：单个容器贯穿 agent 的全部动作
- **有状态环境**：仓库状态在编辑与评估之间保留
- **多轮交互支持**：agent 可以迭代地

- 生成代码编辑
- 增量应用补丁
- 运行测试验证改动
- 无需环境重新初始化即可获得反馈

### 性能影响

这一架构改动带来戏剧性的效率提升：

- **延迟下降**：容器运行时只有一次性成本
- **可扩展性与资源效率**：支持在计算集群上并行生成 rollout

### 使能多步强化学习

我们扩展后的 OpenHands fork 现在为通过 RL 训练代码修复 agent 提供了所有必需组件：

### 1. 多轮交互支持

Agent 可以参与长时间调试会话，进行多次编辑并在每一步获得反馈——这是学会复杂修复策略的关键。

### 2. 快速 Rollout 生成

更短的 rollout 时间支持训练中的快速迭代，兼容以下技术：

- GRPO
- CORPO

### 3. 稀疏奖励评估

来自测试套件的非过即败二值信号提供清晰的学习目标，同时避免奖励塑形带来的偏差。

### 4. 完整的轨迹日志

详细的执行轨迹记录：

- Agent 的推理步骤
- 代码编辑及其影响
- 测试结果
- 错误信息与堆栈跟踪

这些丰富数据支持离线分析、课程学习和奖励模型训练。

### 结果与未来方向

把我们精心构建的真实 issue 数据集与这套扩展后的 OpenHands 基础设施结合，我们已经建立了一条完整的大规模代码修复 agent 训练流水线。当前实验聚焦于：

- 在多样化 Python 仓库上用 RL 对 **Qwen3 coder-30B 做后训练**
- 逐步提升问题难度的**课程学习策略**
- 测试跨代码库迁移能力的**多仓库泛化**
- 在 SWE-Bench 等成熟基准上的**榜单评估**

早期结果表明，在多步修复任务上，RL 训练出的模型显著胜过监督微调基线——尤其在那些需要迭代调试和测试驱动打磨的问题上。

### 技术贡献总结

我们的工作交付了三项关键技术贡献：

- **通用评估引擎**：移除基准特有约束，支持任意仓库
- **统一 rollout 架构**：消除容器重复加载，开销降低约 95%
- **RL-ready 基础设施**：提供干净的 API，可与现代 RL 框架集成

这些进展把 OpenHands 从一个专用基准工具，转变为在真实软件工程任务上训练下一代代码修复 agent 的可扩展平台。
