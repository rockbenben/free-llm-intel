# 用好 GPT-5.6：Sol、Terra 与 Luna

Sherif Cherfa

Zhenwei Gao

你的 Codex 订阅现在自带 3 个主力模型——**Sol、Terra 和 Luna**——每个都是[独立训练、独立服务](https://community.openai.com/t/introducing-gpt-5-6-series-sol-terra-and-luna-coming-july-9-10am-pt/1384931)的，并配有推理旋钮（reasoning dials）。它们共同让你可以为每个任务在速度、成本和智能之间选择平衡点。

### **价格速览**（[OpenAI 开发者定价，2026 年 7 月 21 日](https://developers.openai.com/api/docs/pricing)）

价格上，无论短上下文还是长上下文，Terra 只要 Sol 的一半，Luna 只要 Sol 的五分之一。

这个定价与智能和速度基本同步。实践中，每个模型各有所长：

- ***Sol* 是[三者中最聪明的](https://openai.com/index/previewing-gpt-5-6-sol/)**。最适合**长时任务**、复杂技术挑战和个人助理场景。更强的能力伴随着更高的延迟和成本，但 Sol 擅长协调子 agent，并在超长工作流中驾驭大型项目。
- ***Terra* 稳居中间**，用 Sol 一半的价格提供大部分智能，速度也更快一些。与 Sol 搭配时，Terra 可以是一个强悍的子 agent：Sol 权衡选项、定好方向，然后把实现交给更快更便宜的 Terra。
- ***Luna* 是三者中最快、最实惠的**，价格只有 Sol 的五分之一，性能却仍胜过市场上大多数模型。对大多数日常 AI 任务，Luna 绰绰有余，以极低的价格交付可靠的表现。截至 2026 年 7 月 17 日，它在 [Artificial Analysis 模型智能指数上排名第 16/576](https://artificialanalysis.ai/models/gpt-5-6-luna)。

### **为任务挑对模型**

你如何决定哪个模型来处理一个请求、该投入多少推理？这个选择必须在任何 token 生成之前做出。

### 从 Luna 起步，再逐级升级。

面对任何任务的简单方法是：在你愿意支付的价格上，选择速度与智能平衡最优的模型。在 **GPT-5.6 家族**内：

**1. GPT-5.6-Sol**：智能的下限与上限都最高

**2. GPT-5.6-Luna：**速度的下限与上限都最高

一个好的默认策略是：大多数任务先用 Luna，当进展停滞时再升级到 Terra 或 Sol——比如 agent 卡住、修复不再奏效，或模型开始丢线头的时候。如果你愿意同时为速度和智能多花钱，可以[在 Cerebras 上以 750 tokens/秒 运行 Sol](https://openai.com/index/previewing-gpt-5-6-sol/)，这[比 Sol 常规模式最快快 10 倍](https://artificialanalysis.ai/models/gpt-5-6-sol)。

### **测试时计算 / 推理档位**

定制模型处理任务的另一种方式是调整其[推理档位](https://x.com/cerebras/status/2067357992929153268)。在 Codex 中，你可以从五档里选择："Light"、"Medium"、"High"、"Extra High" 和 "Ultra"。

通过投入更多计算时间来提升输出准确率，模型会在给出答案之前生成大量与自己辩论、自我质疑的 token。

- **Light：**非常适合快速搞定基础任务——找文件、克隆并配置仓库、整理下载文件夹等等。只要模型明确知道要做什么、失败可能性低，基本任何事都可以选这档。
- **Medium：**需要一点解读、规划或调试、但不需要深度探索的日常任务的好的默认选项。例如跨文件摘要、实现一个小功能，或排查一个熟悉的问题。
- **High** 和 **Extra-High：**最适合高难度的 STEM 和编码任务，如复杂调试、架构决策、大规模重构，或存在多种合理路径的问题。多数常规助理任务并不需要这么多——甚至完全不需要——推理。
- **Ultra：**如果你非常清楚自己要什么、约束很具体，尤其当工作横跨多个独立系统时使用最高推理档。例如，以非常特定的方式构建界面和 API 来打通 2 个 API。

我们通常把 Ultra 留给最大的研究问题和全新挑战。Ultra 档有把你用量额度迅速耗光的倾向，但你可以放心：模型已经用尽了全部推理预算来探索、验证并打磨它的答案。

根据 [Artificial Analysis 7 月 17 日的测试](https://artificialanalysis.ai/models/gpt-5-6-sol/)，GPT-5.6 Sol 的推理档位每升一档，平均单任务成本约上涨 50%。下图展示了额外推理对智能与成本的影响。

### **善用缓存读取（Cache Reads）。**

缓存输入比全新输入[便宜 90%](https://developers.openai.com/api/docs/guides/prompt-caching)。反复处理同一代码库或上下文的 Codex 任务因此受益匪浅。

GPT-5.6 的每个模型都[有约 30 分钟的缓存 TTL](https://developers.openai.com/api/docs/guides/prompt-caching)。这意味着维持一个长期使用的会话，比每个任务都新开一个会话更划算。

Codex 的压缩（compaction）也已经足够好，你可以让单个会话跑到数亿 token 而不遇到任何问题。

只要让会话保持"热"，prompt 处理就会便宜得多。你可以设置每 20 分钟运行一次的 Codex 自动化任务来给缓存续命，并用这些自动化来驱动长时进程。

### **高效使用多 Agent 工作流。**

不同模型用不同数据训练、为不同目标优化，这意味着**每个模型在特定事情上都会略好或略差。**

**Advisor（顾问）工作流**给一个 agent 安排一个狭窄的职责：通读完整会话、盯住目标和约束，一旦干活的 agent 开始漂移就介入。这能自动纠偏，并提升长任务中的可靠性。

本地 Codex 还支持把其他服务商接入应用。这意味着你可以在熟悉的 Codex 体验内，尝试更低成本的开放权重模型，如 **Kimi K2.7 Code**，或各有专长的模型，如**擅长长程推理与编码的 GLM-5.2**。

随后可把这些外部模型用于有边界的子 agent 工作，帮助降低成本，或发挥每个模型各自的强项。

一个重要的细节：这是通过 [Codex 配置文件](https://learn.chatgpt.com/docs/config-file/config-reference)和自定义 agent 文件完成的，而不是应用内一个简单的模型选择器。Codex 支持 Ollama、LM Studio 等本地服务商，以及兼容 Responses API 的自定义服务商。

### **结语**

订阅用量额度相当慷慨，但随着 AI agent 对越来越多人变得有用，很多人已经把需求推到一份订阅远不能覆盖的地步。

而且**就算你有钱任性**，也并非每个"前沿"模型在所有用例上都站在前沿。*在若干基准上，一个小模型常常能把一群世界最强模型按在地上摩擦。*

速度也是重要的开关：白天你与 agent 互动时，**高 tok/s 能极大改善体验**；而在非工作时间，给一个 /goal 配上慢但推理拉满的模型，也能产生天差地别的价值。

最后，多关注 Artificial Analysis——那里有高质量的模型速度基准和智能指数。
