# 在 Cerebras Inference 上引入 Multi-LoRA

Njdeh Satourian

今天，我们在 Cerebras Inference 上以私密预览形式推出 Multi-LoRA——Low-Rank Adaptation 的多适配器支持。Multi-LoRA 让团队可以在单一共享基座模型上使用多个 LoRA 适配器，从而针对不同领域、任务、客户和工作流特化模型行为。它推进了我们的使命：让 Cerebras Inference 成为运行特化 AI 应用最快、最简单的方式。

LoRA 是为特化基座模型而训练的轻量适配器。团队无需微调基座模型的全部参数，而是训练一组小得多的适配器权重，在推理时施加即可。这让特化既实际可行又经济，而不必为每个变体单独维护一个完整模型。

### **Multi-LoRA 在 Cerebras Inference 上的工作方式**

Cerebras Inference 负责端点背后的服务基础设施。我们管理基座模型与适配器的服务路径，团队则可以专注于构建把每个请求路由到正确特化方向的应用逻辑。

我们提供细粒度的 LoRA 支持，用户可以按请求应用不同的 LoRA。借助 Cerebras 上的 Multi-LoRA 推理，你可以：

- 与基座模型一起部署一组 HF PEFT 格式的 LoRA
- 在 Cerebras 上用你的 LoRA 适配器运行推理
- 按请求逐个切换适配器

#### 示例用例：Multi-LoRA 让编码助手按语言、任务和客户特化

编码 agent 天然适合 Multi-LoRA，因为它们往往需要同时支持多种特化。一家公司可能先按不同语言、框架和任务建立适配器：一个适配器专精 Python 后端服务，其他专注于 Rust、React、PyTorch、单元测试生成或 docstring 生成。

这帮助编码助手超越泛泛的代码生成，让输出更贴合眼前的语言、框架和任务。它还能帮团队把你偏好的测试、文档、重构规范或客户专属代码模式编码进去。

LoRA 也能支持更细颗粒度的个性化。对面向客户的编码助手，这可能意味着每个客户一个适配器，分别覆盖其私有代码库、内部 API、遗留系统或工程规范，帮助助手生成更契合每个客户环境的代码。

### 开始使用 Cerebras Inference 上的 Multi-LoRA

Multi-LoRA 支持现已作为私密预览向 Cerebras Inference 专属端点用户开放，且不额外收费。如果你有兴趣使用 Multi-LoRA，请联系你的 Cerebras 客户代表。
