# Cerebras 推出解耦式推理

[Atharva Talpade](https://www.cerebras.ai/author/atharva-talpade)

*我们已把 Cerebras 晶圆级引擎与 GPU 配合部署，规模化交付闪电般快速的 token*

世界渴望超快的 token。2026 年，无论是在自家的推理云还是通过合作伙伴，Cerebras 都看到了对快速推理的旺盛需求。为了满足需求，我们开始研发解耦式推理：由 GPU 承担 prompt 处理（prefill），由 Cerebras 系统承担输出生成（decode）。

该方案现已投入生产，在保持 Cerebras 同等超快速度的前提下，每兆瓦交付的 token 数量提升到五倍。

我们现在可以通过 Cerebras Inference Cloud 提供更多超快 token，以满足市场需求。基础设施合作伙伴也可以借助 Cerebras 的解耦方案，在自己的数据中心里获得更多超快 token。

连同近期发布的 CS-4、大幅扩张的制造能力，以及计划中的 700MW 数据中心容量，解耦式推理将让 Cerebras 与合作伙伴在 2027 年及以后提供更多超快 token。

### 对更多快速推理容量的需求

Muse、Copilot、Codex 等 agentic 应用正在快速扩张，需要高度交互的推理才能留住用户。要在电力受限的环境中满足这些应用日益增长的需求，整个行业必须以足以让这些应用真正好用的响应速度，提供远超以往的每兆瓦推理容量。

来源：Goldman Sachs Research，“AI Agents Forecast to Boost Tech Cash Flow as Usage Soars”，2026 年 5 月 20 日；Goldman Sachs 数据中心容量估算，据 Investing.com 2026 年 11 月 6 日报道。

正因如此，Cerebras 才投入[解耦](https://www.cerebras.ai/blog/disaggregated-inference-from-the-ground-up)。把负责 prompt 处理的 prefill 加速器与负责响应生成的 Cerebras 系统配对，能在保持 Cerebras 超快生成速度的同时提高每兆瓦的 token 吞吐量。对推理服务商而言，这意味着同样的电力预算下能服务更多客户，收入潜力也更大。

### Cerebras 为何在 decode 上占优

一次推理请求分为两个主要阶段。prompt 处理（即 prefill）处理输入并生成中间模型状态；响应生成（即 decode）利用该状态生成输出 token。拆分推理负载的方式有很多，draft–target、attention–FFN 等都在其中，但当目标是高度交互的推理时，把 prefill 与 decode 分开具有独特的优势。

decode 是自回归的：模型一次生成一个 token，又把每个已生成的 token 作为输入生成下一个。每一步都要重新从内存读取模型数据，因此内存带宽至关重要。在超快推理领域，以 SRAM 为中心的芯片更有优势，因为它们能把数据留在片上，读取快得多。Cerebras 把这一点做到晶圆级：单颗芯片上有数十 GB 的 SRAM 和每秒数十 PB 的内存带宽——分别是典型 GB300 GPU 的 350 倍 SRAM 容量和 5,400 倍内存带宽。这让 Cerebras 系统能在芯片上容纳更多并发请求和模型层，使 CS-3、CS-4 和 CS-5 以有吸引力的吞吐量达到超快速度。

### Cerebras 解耦式推理的生产结果

把为超快 decode 优化的 Cerebras 系统，与适合 prefill 计算需求的加速器（例如 AMD Instinct GPU）配对，就能规模化交付海量超快推理。在 Cerebras Inference Cloud 的生产部署中，AMD Instinct GPU 处理 prompt，Cerebras CS-3 系统生成响应。把 prompt 处理交给 GPU 之后，Cerebras 系统可以把服务容量全部用于响应生成。在我们实测的生产部署中，这一组合的每兆瓦吞吐量是纯 CS-3 配置的 5 倍，token 生成速度没有任何下降。

来源：2026 年 11 月 14 日通过 Cerebras Inference Cloud 共享的 GPT-OSS-120B 端点，在启用解耦式推理前后的每兆瓦吞吐量，已按聚合推理基线（1×）归一化。

我们计划到 2027 年底，在 Cerebras Inference Cloud 和合作伙伴部署中把解耦式推理推广到数百兆瓦的规模，目标是增加可供客户使用的超快推理容量。

### 面向基础设施合作伙伴的 Cerebras 解耦式推理

Cerebras 的解耦式推理方案同样是按合作伙伴可以采用的思路构建的。基础设施合作伙伴可以按照 Cerebras 提供的参考架构部署解耦式推理集群，在统一网络中把自选的 prefill 加速器与 Cerebras 系统同址部署。软件集成方面，合作伙伴既可以对接 Cerebras 的端到端解耦软件栈，也可以对接仅含 decode 的 SDK。

端到端解耦软件栈最适合优先考虑上市时间的合作伙伴，它包括：

- 一个解耦式推理框架，用于在 prefill 池和 decode 池之间路由请求，并管理副本容量与健康状态。
- 一个 prefill 引擎，使用 vLLM 或 SGLang 等开源推理引擎处理 prompt。
- 一个 Cerebras decode 引擎，在 Cerebras 系统上生成响应。
- KV Portal 软件，一个通过 RDMA 在 prefill 与 decode 引擎之间传输中间模型状态（包括键值缓存）的接口。

仅含 decode 的 SDK 最适合优先考虑控制力的合作伙伴。借助它，合作伙伴可以把自己的推理框架和 prefill 引擎接到 Cerebras decode 引擎和 KV Portal 软件上。此外，仅含 decode 的 SDK 还提供开发辅助，例如模拟的 Cerebras decode 副本，以及与开源解耦式推理框架和 prefill 引擎的参考集成。

包括 Amazon Web Services、Fireworks AI、Gimlet Labs 和 General Compute 在内的早期访问合作伙伴，已经可以在各自的部署中使用 Cerebras 的解耦方案。我们正在把访问权限扩展到更多希望为客户大规模提供超快推理的合作伙伴。
