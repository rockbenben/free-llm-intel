# GPU 正在被一分为二

Sarah Chieng

我们运行 AI 推理的整个方式正在被重新架构。AWS 与 Cerebras 刚刚宣布了围绕它的合作。NVIDIA 斥资 200 亿美元收购 Groq 以奋起直追。黄仁勋站上 GTC 2026 的舞台，实质上验证了 Cerebras 等公司多年来一直在说的话：通用 GPU 不足以支撑规模化的推理。

大家共同收敛的方向叫做**解耦推理（disaggregated inference）**。如果你是构建在 LLM 之上的开发者，这将改变你的产品有多快、运行成本有多高，甚至改变什么可以被构建。

### 你的 GPU 同时在干两份截然不同的工作

当你把 prompt 发给 LLM，模型并不是简单地"想一想"然后返回文本。它在同一块硬件上背靠背地执行两个完全独立的操作。

**阶段 1：Prefill（预填充）**

模型并行处理你的整个输入 prompt，构建 KV cache——也就是它的工作记忆。这是以矩阵乘法为主导的重计算工作，GPU 的核心在矩阵乘法上被拉满。

**阶段 2：Decode（解码）**

现在模型逐个 token 生成输出。由于每个新 token 都依赖前一个，这一步无法并行。与 prefill 不同，这个阶段不是算力受限，而是内存带宽受限。瓶颈变成你从内存读取数据的速度，而不是你有可用的 FLOPs 是多少。

现实是，这两个阶段对硬件的需求非常不同。Prefill 计算密集，受益于大规模并行计算；而 decode 受内存带宽制约，依赖极快、低延迟的内存访问。

GPU 在 prefill 这类计算密集场景表现不错。但由于它们是作为通用加速器设计的，当你需要在规模下达到峰值性能时，它们并未针对 decode 的内存受限特性做优化。通过把 prefill 和 decode 分离，解耦架构可以在保持一致交互性的同时，显著提升**每千瓦吞吐量**。

你不再需要在速度与规模之间做取舍，而是可以把更多 token 服务给更多用户，同时不牺牲响应性。

### 解耦推理到底意味着什么

一旦看清了问题，解法几乎不言自明：别再把两个阶段跑在同一块芯片上。

解耦推理把 prefill 和 decode 拆分到不同的机器上。一个资源池处理 prefill 繁重的并行计算，另一个处理 decode 快速的顺序内存读取。即使两个池子使用同一类硬件，仅仅是这种分离就能减少阶段间的相互干扰并改善延迟。

但真正的台阶式飞跃来自**异构解耦（heterogeneous disaggregation）**：为每个阶段配上与其负载特性匹配硬件。在这套系统中，prefill 用计算优化的系统，decode 用内存带宽优化的系统。这是我们看到收益最大的地方。

可以把它想象成餐厅后厨。解耦之前，同一位厨师既做备菜（prefill）又炒菜（decode），每当一份新的大订单需要备菜时，所有做了一半的盘子都得干等着。解耦之后，你有了备菜组和摆盘组。他们并行工作，把备好的食材（KV cache）从一个工位传递到下一个工位。

结果是：prefill 永远不再打断 decode。每个系统做自己最擅长的事。**你获得更高吞吐量、更低延迟，以及大幅改善的尾部延迟。**

### 新一代基础硬件

3 月 13 日，AWS 与 Cerebras 宣布了一项[解耦推理合作](https://www.cerebras.ai/blog/cerebras-is-coming-to-aws)，让这种新架构成为现实并以云的规模可用。

架构是这样的：AWS Trainium 芯片负责 prefill，Cerebras CS-3 系统负责 decode，通过 Amazon 的 Elastic Fabric Adapter（EFA）网络互联，经 Amazon Bedrock 对外提供。

CS-3 内部的 Wafer-Scale Engine 3（WSE-3）是全球最大的芯片：单一处理器上集成了 4 万亿个晶体管和 900,000 个 AI 优化核心。与 GPU 不同，WSE-3 把 SRAM 直接封装在芯片上，而不像 GPU 那样依赖片外 HBM。数字上，它有 44GB 片上 SRAM 和 21 PB/s 的内存带宽，有效内存带宽大约比仍依赖片外 HBM 的 NVIDIA B200 高 **1,000-2,000 倍**。整块芯片就是一枚巨型 die，消除了限制其他所有架构的封装与互联瓶颈。

> "把推理负载拆分到 Trainium 和 CS-3 上，每个系统做自己最擅长的事。其结果将是比当前可用方案快一个数量级的推理。" —— AWS 副总裁 David Brown

### 这对开发者为什么如此重要

**Agent 变得真正有响应性。**一条 10 步的 agent 链在 50 tok/s 下要跑 30 秒以上。在 1200 tok/s（由 Cerebras 驱动的 GPT-Codex-5.3-Spark）下，同样的链路 3 秒内完成。

**吞吐量大幅扩展。**专用硅片减少了无效计算，让每个系统能够以高速服务多得多的 token。我们预计解耦的 Trainium-Cerebras 方案相比聚合方案会将 token 吞吐量提升 5 倍。这些富余的容量将用来支持更多用户、更丰富的应用和日益复杂的 agent 工作流，而不是继续限制使用。

**延迟长尾被治好。**你的 P95 是 3 秒而中位数只有 500ms？那就是 prefill 卡顿造成的。解耦会消除它。研究显示，在 agentic 工作负载上 [P95 延迟最多改善 4.5 倍](https://arxiv.org/abs/2602.12029?utm_source=chatgpt.com)。

**所有云厂商都在向这里迁移。**AWS 与 Cerebras、NVIDIA 与 Groq、Oracle、Azure。每个主流 LLM 服务框架（Dynamo、SGLang、vLLM、llm-d）都已支持解耦。

这种向异构解耦系统的转变也在重塑竞争格局。不再是单一厂商控制整个技术栈，不同的芯片可以在推理的各个环节展开竞争。这将开始侵蚀 NVIDIA 的端到端主导地位，为更专用的硬件在最擅长的领域胜出打开大门。

对开发者而言，这种竞争是顺风。更多的玩家意味着更快的迭代，以及你所依托的技术栈全链路性能的不断攀升。

### 你应该为之构建的世界

两年前，一切围绕训练和"谁拥有最多的 H100"。那已经过去了。模型只训练一次，却被查询数十亿次。**经济账已经反转。**

过去两年，推理的算力需求增长了 1,000,000 倍，业内预计推理驱动的基础设施支出到 2027 年将超过[1 万亿美元](https://pwm.gs.com/nam/en-us/insights/markets-and-investing/innovation-technology/the-building-blocks-behind-ai-next-wave?utm_source=chatgpt.com)。

如果你是开发者，实际结论很简单：在未来 18 个月内，token 即将变得更快。让我们为那个世界而构建。
