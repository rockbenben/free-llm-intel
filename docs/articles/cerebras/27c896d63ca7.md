# 这个新模型比 Sonnet 4.5 更聪明……还快 20 倍？

Sarah Chieng

Sebastian Duerr

所以，你需要速度、智能，*还有*漂亮的经济学……介绍 GLM 4.7——首个三者兼得的开放模型。

### **开发者为何转投**

在 Cerebras，我们收到了开发者对 GLM 4.7 的汹涌需求。向 GLM 4.7 的迁移由三大关键因素驱动：成本、速度和智能。

- **成本：**GLM 4.7 比 Claude Sonnet 4.5 等模型更实惠，以极低的花费实现高水准的智能。
- **速度：**在 Cerebras 上，GLM 4.7 的输出速度最高达 [1500+ tokens/秒](https://artificialanalysis.ai/models/glm-4-6-reasoning/providers#output-speed)，比 Sonnet 4.5 等闭源竞争对手快 20 倍。这显著降低了 agentic 工作流的延迟，让开发环境中的快速迭代与执行成为可能。
- **智能**：GLM 4.7 是当今最强的开源编码模型。它的工具使用能力出众，在 𝜏²-Bench Telecom 上达到 96%，适合放进编码执行框架和通用 agent 里使用。此外，GLM 4.7 在推理与知识任务上同样出色，在高难度的 **GPQA Diamond（科学推理）**上得到 86 分，如[Artificial Analysis 所测](https://artificialanalysis.ai/models/glm-4-7-non-reasoning)。

### GLM 4.7 是什么（以及为何重要）

GLM 4.7 是 Z.ai 的最新模型，也是第一个能与 Sonnet 4.5 这类闭源巨头掰手腕的开源模型。几个要点：

- **规模：**约 **358B** 总参数，每个 token 约 **32B** 活跃参数（MoE 路由）
- **为以下场景而生：**编码 + 工具使用 + agentic 工作流
- **Cerebras 上的隐私：**输入/输出在内存中处理，不做持久化

但在看到结果之前，架构只是理论。

### [​](http://localhost:3000/resources/glm-47-marketing-blog#the-performance)性能

如果你关心编码和 agentic 评测，GLM 4.7 已跻身"最强开源模型"梯队。在 LiveCodeBench 上，GLM 4.7 超越 Anthropic 和 OpenAI 的模型，仅次于 Gemini 3。

GLM 4.7 在 GPQA 和 AIME 上的大幅进步延续了这一领先，两项都胜过 Claude Sonnet 4.5，AIME 2025 结果见下文。

而与上一代 GLM 4.6 直接对比时，编码与通用能力的提升相当可观——HLE 提高 12.4 分、Terminal Bench 2 提高 16.5 分等。

性能是一回事，可用性是另一回事。

### GLM 4.7：快 20 倍的机会

GLM 4.7 的美妙之处在于它是开源的。这意味着你不再被硬件瓶颈挡住。现在，你的产品可以实现比运行在 GPU 上的 Sonnet 4.5 或 GPT 5.2 这类闭源模型快几个数量级的 token 输出速度。例如，看看 GLM 4.7 在不同硬件服务商之间的速度差异。

每个模型都有不同的性格癖好。迁移到 GLM 4.7 时，一个常见错误是不加调整地沿用旧 prompt，无视它的独特行为，这会导致表现不佳。**要充分释放 GLM 4.7 的强项，必须相应地打磨你的 prompt、架构和采样参数。**

**下面是帮你把 GLM 4.7 用到极致的 10 条规则。**

### 规则 #1：指令前置

在 Cerebras 上，GLM 4.7 支持最高 131K 的上下文长度。但和大多数大型模型一样，GLM 4.7 在较短长度下输出质量最高，在极端长度下会退化。

尤其观察到的是，GLM 4.7 对 prompt 开头有很强的偏好，比其他模型更明显。在对话中使用 think 标签时这一点特别突出——它会强化靠前的指令。

因此，为确保正确遵循指令，**把所有必守指令和行为准则放在 system prompt 的最开头**，利用模型的开头偏好。这比把它们放在 prompt 后面更有效。

### 规则 #2：给出清晰直接的指令

不同模型遵循指令的方式不同。GLM 4.7 对消除歧义的强硬、直接语言响应最好。开局就用强而明确的指令（如 MUST、STRICTLY）立好规则，避免模型可能当成可选项的温和、商量式措辞。

*例如：*

- *要这样写：*"在写任何代码之前，你必须先阅读并完全理解 architecture.md 文件。你生成的所有代码必须严格遵循……"
- *不要这样写：*"请阅读并遵守我的 architecture.md……"

### 规则 #3：指定默认语言

因为 GLM 4.7 是多语言的，我们发现它有时会在回复中切换语言。

如果你从默认英语的语言模型迁移过来，在 system prompt 里加一条诸如"始终用英语回复"（或你偏好的语言）的指令会有帮助，可以避免意外输出。

我们偶尔观察到模型在第一轮用中文输出思考轨迹。显式的语言控制可以杜绝这种行为。

### 规则 #4：善用角色扮演

GLM 4.7 最大的强项之一，是能有效地维持并遵循角色与人格。它内部的"思考块"紧密贴合角色 prompt，让你能精确控制语气和领域知识。

要利用模型的扮演能力：给模型一个显式的人格，或构建各自带人格的多 agent 系统。

*例如：*

- *要这样写：*"你现在的角色是撰写高管摘要的分析师；务必详细审阅以下资料，然后给出结构化的、专业的回复……"

### 规则 #5：拆解任务

GLM 4.7 在行动前对每个 prompt 只做一轮推理，不会在任务中途持续重新评估。这种被称为"交错思考"（interleaved thinking）的机制由 Sonnet/OpenAI 等模型支持。

在交错思考中，模型会在以下步骤之间交替：

- 推理步骤（分析、生成假设）
- 行动步骤（检索、工具使用、代码执行或环境交互）

这让模型可以在任务执行全程暂停、反思中间结果并动态调整方法。

在没有交错思考的情况下，为了让 GLM 4.7 **更好地完成任务**，建议把任务拆成小而明确的子步骤。例如：

- 列出依赖项。
- 提出新结构。
- 生成并验证迁移。

这种渐进式方法产出更干净的结果，也契合 GLM 执行先行的倾向。

### 规则 #6：不需要时关闭或最小化推理

GLM 4.7 常常在输出中包含内部思考/推理块。对很多直接任务，这种推理开销没有必要，还会拖慢响应。

要最小化推理：

- **禁用推理**：在 Cerebras API 的请求参数中使用非标参数 disable_reasoning: True。注意这与 [Z.ai](http://z.ai/) 不同——Z.ai API 使用的参数是 thinking。
- **设置 max_completion_tokens：**通过设置合适的 token 上限可以有效控制 GLM 4.7 的冗长度。想要聚焦的回复时，考虑用更低的值。
- **Prompt 要求精简**：在 system prompt 中加入最小化推理的指令。例如加上："仅在必要时推理"或"简单任务跳过推理。"
- **设置输出约束**：使用结构化输出格式（JSON、列表、要点），天然抑制冗长的推理块。
- **设置 clear_thinking: true：**模型会在简单轮次对话之间清除内部状态，节省 token。

### 规则 #7：为复杂任务开启增强推理

虽然 GLM 4.7 的推理对简单任务可能过剩，但在需要逐步思考的复杂问题解决上，它变得很有价值。

要增强推理：

- **启用推理**：处理复杂问题时，确保 API 请求中 disable_reasoning 设为 False（或省略）。
- **Prompt 要求深度**：在 system prompt 中加入显式推理指令："对任何给定任务你必须逐步思考"或"把你的推理拆解成清晰的逻辑步骤。"
- **思维链 prompt**：包含展示你所期望推理过程的示例，向模型演示如何有条理地解题。

### 规则 #8：拿不准时，用评审员（critic）！

承接规则 #4，与 GLM 4.7（或任何 LLM）协作时最强大的模式之一，是启用专职的**评审 agent（critic agents）**在主 agentic 流程推进计划之前审查并验证输出。不要依赖单个 agent 既生成又验证代码，而是创建各有专长的专职子 agent：

- **代码评审 Agent：**配置为严格检查代码质量、对 SOLID/DRY/YAGNI 原则的遵循度以及可维护性问题。
- **QA 专家 Agent：**可绑定 agentic 浏览器能力，测试用户流程、边界情况和集成点。
- **安全评审 Agent：**专职识别漏洞、不安全模式和合规问题。
- **性能审计 Agent：**专注发现性能瓶颈、低效算法或资源泄漏。

通过把职责分散到多个各具聚焦人格的 agent（见规则 #4），你构建了一条生成与验证解耦的稳健流水线。

### 规则 #9：让 GLM 与前沿模型配对

与其他开源模型相比，GLM 4.7 擅长推理。但如果你的用例依赖前沿级推理能力，你可能会发现 GLM 4.7 在最难的 10% 用例上不敷使用。

这里有三种架构模式，能让你在应用中有效利用 GLM 4.7：

- 简单任务路由给 GLM 4.7，最复杂的查询回退到更慢的模型。
- 让 GLM 4.7 做快速的主干 agent，只在需要时把更慢、更智能的模型拉进循环。
- 先用 Sonnet 或 GPT 制定计划，然后用 GLM 4.7 快速执行——让你以极低成本处理海量任务，同时在复杂推理步骤上保住质量。

**通过把 GLM 4.7 快 17 倍的输出速度和更低成本用于大多数任务，你可以在不牺牲整体质量的前提下，收获显著的速度与成本节省。**

### **规则 #10：用 **clear_thinking 控制跨调用记忆

用 clear_thinking 决定 GLM 4.7 应在调用之间携带多少内部"思考状态"。对于 agent 循环、多步计划和依赖先前推理的编码会话，设置 clear_thinking: false，让模型在轮次之间保留内部状态。对于一次性调用、批处理任务，或当你看到来自先前步骤的不良漂移时，设置 clear_thinking: true，让每次回复只基于可见的 prompt。

用顶级智能，*加上*靠谱的经济学，跑世界上最快的推理。

在 Cerebras 上运行 GLM 4.7 时，你用的是我们的 Wafer-Scale Cluster，但与模型的协作方式保持熟悉。你可以使用约 131k tokens 的长上下文，并通过 max_completion_tokens 允许最高约 4 万输出 token 的回复，让模型有足够空间接收 prompt 并产出完整答案。

你还可以决定模型应该做多少内部"思考"。如果你更在意速度和简洁输出，可以用 disable_reasoning: true 关闭推理，让回复更短更干净。如果你在构建 agent 或编码循环，希望模型跨轮次保持内部状态，就保留 clear_thinking: false，让它不在调用之间重置。

采样方面，在 Cerebras 上的一个好起点是 *temperature=1* 配 *top_p=0.95*。这些默认值在我们系统上的多数负载中表现良好。看清 GLM 4.7 在你应用中的行为后，再一次只调一项设置，得到你想要的风格与多样性。
