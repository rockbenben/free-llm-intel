# 在框内思考：用于高效状态追踪的隐式链式 Transformer

Jayadeep More

Arun Kumar Patil

Ganesh Venkatesh

### 动机

大语言模型（LLM）解码器在开放式生成、推理与人机交互上展示了非凡能力。然而，标准自回归公式存在一个**表征瓶颈**：为生成下一个 token，模型必须通过对全部历史施加注意力，隐式地重新推导出底层语义语境。这种**无状态性**让标准 Transformer 在需要维护滚动状态的任务上出奇地脆弱——例如计算一列数对 X 取模的和，或执行图遍历。

在这项工作中，我们提出 **Implicit Chain Transformer（ICT）**——一个旨在弥合这一鸿沟的新架构。通过让一个可学习的"意图"（intent）潜变量沿时间步向前传播，我们的方法使模型能够显式地**更新并语境化**一个滚动状态，而不是只依赖对历史注意力模式的重新推导。早期评估显示，ICT 在状态密集的玩具任务上取得了强劲准确率——这些任务此前被研究认定为 Transformer 的难点——且**不引入 Chain-of-Thought（CoT）prompting 相伴的推理延迟成本**。这项工作是我们更大目标的基础性一步：让 Transformer 完全在潜空间内完成高效、稳健的推理。

### 挑战：无状态瓶颈

标准 Transformer 受制于一个根本的**表征瓶颈**：它们是无状态的。要生成 token t，模型必须通过关注所有先前 token 重新推导当前语境。它不能简单地"记住"当前状态（比如"和是 5"），而必须在每一步隐式地重算。这让它们在需要深层顺序依赖的任务上很脆弱，并随着上下文增长产生幻构。

### 任务设置：模运算与图遍历

我们选定了两项 prior work 指出的"'近似'注意力会遇到困难"的任务 [1]：

- **Sum Modulo X（对 X 取模的求和）：**需要维护一个精确的滚动累加值。一次进位错误就会污染整个后续序列。理论上这是一个并行归约任务——每个 token 都可以独立算出答案，而不必在前面的部分结果上叠加。但随着序列变长，这种每个 token 都重算的方式对模型来说变得过于昂贵。
- **Graph Traversal（图遍历）：**需要追踪穿过网络的一条路径。模型必须尊重连通性，在 token 间形成严格顺序依赖。鉴于时间步之间的紧耦合，这项任务对状态追踪与传播的质量要求高得多。

### 提议：Implicit Chain Transformer

我们提出 **Implicit Chain Transformer（ICT）**。不同于把信息流动限制在垂直方向（层层传递）的标准模型，ICT 让一个可学习的 **"Intent Vector"（zt）**沿时间步水平传播。这个向量扮演压缩版工作记忆：模型把当前逻辑状态"写入" zt 并传递给 t+1，无需重新处理整个历史就维持了连续性。我们研究两种不同的状态传播策略：

1. **自回归意图传播（Dense）** 在这种公式下，状态被持续更新。每一个 token 生成步，我们都取 token t *最后*一层的潜变量，注入 token t+1 的*早期*层。这与标准自回归解码相仿，但在 token 流旁增加了一条持续的"记忆流"，让模型能在词一级微管理状态。

2. **周期性意图传播（Sparse）** 这里我们把状态更新与 token 生成解耦。我们在输入流的固定间隔注入特殊 <THINK> token。

- **机制：**我们限定意图传播*只*在这些 <THINK> 边界发生。
- **直觉：**这迫使模型把这些 token 当作"语义检查点"——先把前面的语境聚合进一个连贯的摘要，再继续前进。由于状态更新只发生在模型明确构建高层概念之处，意图传播的架构就与数据的逻辑结构（而非随意的 token 序列）对齐了。这种方式还为推理优化带来显著优势，我们将在后续文章详述。

**用"迭代式潜反馈"训练** 递归的首要挑战是：它通常会破坏让 Transformer 可扩展的并行训练效率。为了在不退回 RNN 那种缓慢串行训练的前提下实现意图传播，我们引入**多趟近似**：

- **并行趟：**我们以标准 Transformer 模式并行处理整个序列，生成初始潜表征。
- **反馈注入：**取第一趟*最后*一层的潜向量，经一个 MLP 投影，融合为*早期*层的"意图"输入。
- **精炼趟：**用这份融合后的上下文做第二次前向传播，计算最终损失。

这虽然引入固定计算开销（需要额外前向趟），但成本与序列长度无关，是**恒定的**。这保住了 Transformer 训练 O(1) 的顺序复杂度，避免了 RNN 中 Backpropagation Through Time（BPTT）带来的 O(N) 训练时间之痛。

### **早期评估结论**

我们观察到 ICT 在所有任务上一致且显著超越基线。我们绘制准确率随 token 位置（或块索引）变化的曲线，实际衡量的是模型在计算深度增加时维持状态的能力。

- **基线的局限：**基线模型（粉线）显示标准 Transformer 如何依任务复杂度以不同方式失败。在 **Modulo 37** 和 **Permutation Prediction** 上，我们看到**灾难性崩塌**：模型在固定窗口内维持完美准确率（大概是落在其有效注意力跨度之内），随后几乎瞬间跌到接近零。在 **Modulo 97** 上，我们观察到**平滑渐进的退化**。随着更大模数的难度累积，模型对全部历史的注意力能力是稳步流失，而非骤然断裂。这值得进一步调查渐进下滑的原因。
- **Modulo Addition（取模加法）：** **ICT-Dense** 与 **ICT-Sparse** 两种变体都把高准确率维持得远比基线久。这验证了核心假设：传播一个潜向量，避免了困扰标准 Transformer 的状态重算。
- **图遍历（Permutation）：**在排列任务上，两种 ICT 变体的分野更清晰。两者都优于基线，但 **ICT-Dense**（绿色）比 **ICT-Sparse**（紫色）在更多的块数上保持稳定。*假设：*我们把这一差距归因于压缩的挑战。由于我们的原型是相对较浅的网络（三层），**Sparse** 模型可能难以把完整块表征有效地压进周期性的 "think" token。**Dense** 模型因为每一步都更新状态，避开了这个信息瓶颈，在更长序列上维持准确率。

### 未来工作

尽管这些早期结果令人鼓舞，它们只是迈向稳健潜推理的第一步。我们计划沿几条关键线拓展这项工作：

- **推理公式与优化：**当前评估聚焦准确率，但 ICT 的架构收益——尤其 sparse 公式——大幅延伸到速度。我们目前正在起草对推理机制与延迟权衡的详细分析，将在后续文章分享。
- **扩展 Sparse 公式：**我们相信 **ICT-Sparse** 路线在表征丰富度与计算成本之间提供了最佳平衡。但它目前在排列任务上的性能差距提示我们还需要更多消融实验来理解其扩展定律——特别是它在更深网络、以及更多样推理任务上的表现。
- **训练动力学与稳定性：**一个关键的开放问题是长程依赖训练的稳定性。我们计划严格研究鼓励更丰富潜表征的方法，包括对比完整 Backpropagation Through Time（BPTT）与梯度截断技术（如 MuZero 所用或标准 RNN 的 detach 手法），以在梯度稳定性与状态的多步迭代之间取得平衡。
