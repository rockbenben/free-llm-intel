# 更智能的模型并不能拯救你糟糕的安全带

[Sarah Chieng](https://www.cerebras.ai/author/sarah-chieng)[William Ryan](https://www.cerebras.ai/author/william-ryan)[Sherif Cherfa](https://www.cerebras.ai/author/sherif-cherfa)

代理大致是线束内的模型，在环境中运行。

**模型**提供情报。它进行推理、做出决策、编写代码并决定下一步要采取的操作。 **环境**是进行这项工作的实际计算机、存储库、浏览器或容器，而用户（有时是另一个代理）是提供目标并在需要时提供指导的人。

**线束**决定模型可以看到什么、可以采取什么操作、结果如何反馈到下一个推理中以及工作何时实际完成。

![](https://cdn.sanity.io/images/e4qjo92p/product/4c5dfeb50d444cc97f3af43d97e61be8895896ec-4040x1397.png?auto=format&dpr=2&fit=max&q=75&w=2000)

![](https://cdn.sanity.io/images/e4qjo92p/product/0fa06f54c42a11bcce559661ffabae5c21b7b568-4950x1656.png?auto=format&dpr=2&fit=max&q=75&w=2000)

您可以将线束工程视为围绕模型构建的系统，使其成为完成实际工作的引擎。模型有多智能并不重要。如果没有线束，它只是一个代币生成机器。借助安全带，智能才真正发挥作用。线束将模型转变为代理。

安全带有很多种类型。有些适合不同类型的工作

- 个人工作：Openclaw 和 Hermes 主要是个人代理，它们嵌入到外部应用程序（Telegram、Discord、iMessage）中。
- 编码：通常这些工具在终端或代码编辑器中运行。有专为强化学习和研究而设计的安全带，也有用于金融、营销和许多其他垂直领域的安全带。
- 知识工作：ChatGPT Work 和 Claude 桌面应用程序就是很好的例子。虽然许多应用程序也将它们用作编码代理，但这些应用程序拥有大量工具和插件，允许您将代理连接到 Slack、Notion、Gmail、Sheets、Teams、Clickup 等工具，所有这些都是为了支持一般知识工作。

![](https://cdn.sanity.io/images/e4qjo92p/product/47a43fe069beddf7e91c225027345e51d4c835e8-2168x1926.png?auto=format&dpr=2&fit=max&q=75&w=2000)

![](https://cdn.sanity.io/images/e4qjo92p/product/19dfa24cf2aaa63be95005b6f374b61848d53dc1-2140x2027.png?auto=format&dpr=2&fit=max&q=75&w=2000)

#### OpenAI 的 ChatGPT Work（如图）拥有强大的插件生态系统，可用于通用工作和软件工程。

但从根本上来说，它们都有相同的骨架。今天，我们将分解代理工具的各个层，以更好地了解我们的工艺工具。

### 什么是安全带？

大型语言模型接受输入，然后使用这些输入生成下一个标记，然后将最后生成的标记附加到输入，循环继续，直到它决定完成。靠他们自己，他们不能：

- 使用电脑
- 保持持久状态
- 搜索网络
- 运行外壳命令
- 读取、编辑或创建文件
- 执行代码
- 或者验证他们生产的产品是否有效

如果大型语言模型是大脑，那么线束就是它的身体。

当您提出以下查询时：

![](https://cdn.sanity.io/images/e4qjo92p/product/4d09e4cef9cc0ec3caff71bdadd0382f97789453-3840x998.png?auto=format&dpr=2&fit=max&q=75&w=2000)

您的提示不仅仅直接进入模型并作为神奇完成的补丁返回。该工具在反馈循环中复合了许多推理调用，如下所示：

![](https://cdn.sanity.io/images/e4qjo92p/product/12759c8b8d982b4d4515c07b1d3291776ce3546d-3840x3348.png?auto=format&dpr=2&fit=max&q=75&w=2000)

**这个循环就是我们所说的“代理”。**

这里概述的每个步骤都需要大量的工程设计

![](https://cdn.sanity.io/images/e4qjo92p/product/db667a809a23fae4584607fd3826c52ce8f9102b-2712x2540.png?auto=format&dpr=2&fit=max&q=75&w=2000)

线束一般拥有：

- **提示构建** - 系统/开发人员说明、回购说明、用户提示。
- **上下文选择** - 哪些文件、以前的消息、工具输出、内存、差异等可见。
- **工具** - shell、文件编辑、搜索、Web、MCP 工具、Git、测试。
- **工具架构** - 如何向模型描述这些功能。
- **工具执行** - 实际上将模型的意图转化为行动。
- **代理循环** - 决定如何返回工具结果并触发下一个推理。
- **状态** - 记住步骤/会话中发生的情况。
- **编排** - 产生专门的或并行的代理。
- **挂钩** - 在预定义触发器上确定性执行脚本（linting、阻止危险命令、代码审查）。
- **记忆** - 个人上下文被存储并注入到模型提示中，以帮助代理“记住”以前的会话。
- **上下文压缩** - 决定随着会话的增长而总结或丢弃哪些内容。
- **规划** - 计划、TODO 列表、子目标。
- **权限/沙箱** - 允许代理执行的内容。
- **错误处理** - 重试、失败的命令、超时。
- **验证** - 测试、检查、检查更改是否有效。
- **终止** - 决定代理回合何时实际完成。
- **约束** - 规定代理可以做什么和不能做什么的规则。

**安全带可以改变结果**

如果您在两种不同的编码工具中使用过相同的模型，您可能已经感觉到了这一点。模型可能相同，但输出的体验和质量可能截然不同。

一篇论文 [*停止在不披露框架的情况下比较 LLM 代理*](https://arxiv.org/html/2605.23950v1) 报告称，**Claude Opus 4.5 在标准化 SEAL 支架下得分为 45.9%，但在 SWE-bench Pro 上通过 Claude Code** 使用时得分为 55.4%。

![](https://cdn.sanity.io/images/e4qjo92p/product/bc46387046766b6ab7db94c827db585f108529fe-903x868.png?auto=format&dpr=2&fit=max&q=75&w=903)

这个故事的寓意是这样的：如果两次测试没有使用相同的线束，那么告诉您“模型 A 击败模型 B”的基准有时实际上可能会无意中产生误导。 **背景（和安全带）很重要。**

基准测试结果属于模型线束对。如果线束发生变化，结果也会发生变化。随着线束变得更加雄心勃勃，它们也会进行更多的模型调用。 **这就是快速推理开始变得重要的地方。**

### **线束是一个推理乘数**

看看**线束拥有**的事物列表：规划、循环、重试、验证、测试、压缩、编排、审查。其中每一个都需要另一次模型调用，这会花费代币，但更重要的是花费时间。

验证过程可能会发现错误，但也会使运行时间加倍。子代理可能会并行执行某些工作，但编排器仍然必须计划、调度和综合这些结果，并且所有这些步骤都是连续的。

每个模型调用都会增加延迟，并且在大多数串行代理循环中，粗略预算如下所示：

![](https://cdn.sanity.io/images/e4qjo92p/product/18e8b92d94612820d19d5561f63393b643a189da-3658x2648.png?auto=format&dpr=2&fit=max&q=75&w=2000)

一步慢了，十步就看不下去了。但相比之下，如果模型步骤很快，那么在代理停止感觉交互之前，线束就有空间做更多有用的工作。

区别很重要。在 Cerebras 上运行 [GPT-5.6 Sol 每秒可达到 750 个令牌，全轮响应时间低至 0.4 秒](https://www.cerebras.ai/blog/getting-the-most-out-of-gpt-5-6-sol-terra-and-luna)。这种速度水平解锁了新功能，并为线束提供了更大的推理、工具使用、恢复和验证预算。

### **“快速安全带”有何不同之处**

一旦模型延迟缩短，工程师就可以通过多种有用的方式来度过这些时间。

- **实时代理编排。** GPT 5.6 Sol Ultrafast 等智能模型可以编排大型项目和广泛的子代理扇出，从而快速提高延迟优势。
- **以人类的速度使用计算机**。特工已经可以使用计算机，但与人类相比，它们仍然笨重、容易出错且速度缓慢。快速推理消除了代理以人类速度移动的延迟。
- **实时指导。** 客服人员会立即对纠正做出反应，提供真正的协作体验。
- **推测执行。** 考虑某种方法的用户可以使用工作树实时实施和测试多种替代方案，向其呈现工作选项而不是假设的建议。
- **积极的重试和自我纠正。** 代理可以在编写代码时积极地测试和修复自己的代码，而最终用户的成本最低。一旦文件被编辑、验证或修复，钩子就会在几毫秒内触发。
- **自适应界面。** 代理可以根据当前状态实时生成预览、图表、可视化和模型。

这些只是几个例子，富有想象力的构建者当然可以以数千种有利的方式利用低延迟推理，但总体上最大的好处肯定是允许人类以交互方式实时参与构建过程。搜索、推理、工具使用和编辑折叠成一个更紧密的循环，更接近真正结对编程队友的感觉。

### **线束是瓶颈**

目前，智能体最大的瓶颈是推理步骤。有了 Cerebras Fast Inference，情况就不再是这样了。新的瓶颈变成了工具本身，或者更具体地说，是工具调用。

与代理合作时，工具调用既重要又常见。就像上面的示例一样，任务可以将数十个，或者在某些情况下，数百个工具调用串联在一起。下面是我们在实际生产代码库中运行的一些示例任务，让您了解针对给定任务可能使用多少个工具调用。

![](https://cdn.sanity.io/images/e4qjo92p/product/0328e057de3b24e9843b3f12b85513e2cc4bfdad-4040x2539.png?auto=format&dpr=2&fit=max&q=75&w=2000)

当推理不再是最慢的步骤时，线束工程师可以专注于优化代理堆栈的其余部分，优化线束本身的效率和性能。

### **速度改变线束的形状**

这些代理功能都不一定是新的。几乎任何工具都可以运行测试、编排代理、操作浏览器或生成可视化。区别在于这些操作是否实用，它们是否适合“交互内部”，或者它们是否迫使您将工作发送到后台。

缓慢的推理促使人们进行更少、更大的模型调用。多步骤工作变得异步，用户在代理已经做出大部分决策后查看结果（随着错误的复合）。我们不要忘记，这些模型很聪明，但它们并非绝对正确。 **具有良好设计品味的高级代理人员在提供判断、指导和指导方面仍然具有无价的价值。**
