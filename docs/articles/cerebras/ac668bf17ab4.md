# 案例研究——Cognition x Cerebras

## **实时编码 Agent 的黎明**

#### **TL;DR**

由 Cerebras Inference 驱动的 Cognition SWE-1.6 和 SWE-grep 系列，带来了前沿级别的编码性能，比在 GPU 上运行快约 5 倍，同时提供更顺滑的 agent 体验，让开发者在探索代码库、交付功能、调试复杂系统时保持心流。

> "与 Cerebras 的合作让我们可以把速度当作一等设计参数。当你的 agent 以约 1000 tokens/秒 运行时，你就有机会把 agent 的所有部分放在一起优化，包括上下文检索、UI 和模型行为。Cerebras 让我们得以探索一整套全新的方向，从更深的代码库理解到根本性的新交互模式。"

Scott Wu

CEO, Cognition

### **挑战**

AI 正在重新定义软件开发，把自然语言 prompt 变成可运行的代码。但一个 AI 编码助手要有用，就必须感觉瞬时响应，并无缝处理大型复杂项目。在此之前，GPU 上的 AI 编码意味着令人沮丧的延迟——20 到 30 秒的生成时间会打断开发者的专注。哪怕轻微的卡顿也会迫使人切换上下文。开发者只能二选一：要么用能力不足但更快的小模型，要么用太慢的大模型。行业需要一种在不牺牲智能的前提下，提供更多速度、稳定性和规模化的解决方案。

### **方案**

Cognition 端到端地协同设计了它的 agent、模型和推理栈，并选择了最快的推理服务商 Cerebras 来驱动 Windsurf 中快速版 SWE-1.6 体验。

SWE-1.6 是 Cognition 最新为软件工程 agent 打造的模型，同时针对智能和模型 UX 进行了优化。它从零开始做了后训练，在提升原始编码能力之外，让 agent 用起来更顺滑。

SWE-1.6 在 Windsurf 的 fast 档位上由 Cerebras 驱动，最高可达 950 tokens/秒——开发者从此不必再在"想得快"和"想得好"之间做选择。开发者可以用 SWE-1.6 探索大型仓库、构建全栈应用、编辑配置文件，并在五秒内完成快速而精确的修改，比如更新 Kubernetes manifest。

但 Cognition 并未止步于原始速度。SWE-1.6 还改善了模型 UX：它更频繁地使用并行工具调用，更少地陷入循环，更多地依赖自带工具而非终端命令。这让 agent 上下文收集更快、轨迹更高效、在复杂任务中需要的用户干预更少。

在 SWE-Bench Pro 上，Cognition 报告 SWE-1.6 得分为 50.4%，而 SWE-1.5 为 40.1%。正式发布的 SWE-1.6 模型延续了预览版的基准成绩表现，同时大幅改进了那些决定 agent 在日常工程工作流中"手感"的行为。

Cognition 的 SWE-grep 和 SWE-grep-mini 仍然是面向高并行代码搜索的专用子 agent。运行在 Cerebras Inference 上，它们驱动着 Windsurf 的 Fast Context 子 agent，把上下文收集从数十秒压缩到几秒。搜索、推理、工具使用和编辑融入一个更快的循环——更接近真实结对编程队友的体验。

通过对模型（SWE-1.6）、agent 框架（Cascade）和推理层（Cerebras）的共同优化，Cognition 交付了一个针对真实工程工作流和模型 UX 调优（而不仅仅是跑分）的凝聚一致的 agent 体验。有了 Cerebras 上的 SWE-1.6 和 Fast Context，加上并行工具调用和高度优化的流水线，搜索与推理时间被大幅压缩。在丰富、真实的编码环境上进行强化学习，结合超高速推理，造就了感觉像真实结对编程队友的 agent。

### **结论**

Cognition 的 SWE-1.6、SWE-grep 和 SWE-grep-mini 展示了当 agent 实验室与基础设施供应商围绕速度、智能和模型 UX 共同设计时可能达成什么。从前沿规模的编码模型到专用的检索子 agent，Cerebras Inference 提供了让工程师保持心流、解锁下一代软件工程 agent 所需的吞吐量和延迟表现。
