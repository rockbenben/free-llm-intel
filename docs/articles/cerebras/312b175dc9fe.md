# Rox × Cerebras：为 Agentic 销售工作流提供实时速度

Daniel Kim

Rox 在你的数据仓库之上提供企业级营收 agent（revenue agents）。平台用一个安全的知识图谱融合内外部数据源，包括客户交互的全部原始数据、你的 CRM、产品使用情况等，加上全网公开数据。

这些数据随后被 AI agent 用于自动化 go-to-market 工作流。这些工作流覆盖销售人员日常所做的一切：客户研究、自动填充 RFP、会议准备、外联触达，直到监控交易风险、推动交易在管道中前进。

用户通过 Web、Slack、macOS、iOS 以及一个名为 Command 的对话式界面与 Rox 交互。

### **挑战**

Rox 编排多个专精于高精度、多步研究的 AI agent。这种严谨很有价值，但当用户正在销售通话中、在 Slack 里复盘一单交易、或在手机上做准备时，它可能显得慢。随着采用面扩大到非技术用户之外，**期待开始向"响应敏捷"收敛**。语音把标准抬得更高：要让免手工作流可行，往返延迟必须具有对话感。

**方案：按意图路由，而非按意识形态路由**

Rox 使用**动态模型路由**，把工作匹配合适的推理路径：

- **快速路径（用户在等）。**Command 聊天/语音、Research 里的即时刷新、快速事实查询，以及其他用户正在实时参与的交互。这些流优先保证**低延迟**和高 tokens/秒。
- **深度路径（用户不在等）。**批量或复杂作业，如客户全景扫描、多跳网络研究、周末刷新——用户更看重深度而非即时。这些流优先保证推理深度与成本效率。

这种路由对用户透明，被编码进产品 UX（例如"速度"与"深度"模式），并用清晰的预期强化：当你实时交互时，响应立即流式返回；当你启动深度研究时，结果在它真正完整时送达。

### **Cerebras 驱动快速路径**

在 Rox 的整个平台中，响应敏捷驱动采用与习惯。当用户与 Command 聊天、免手说话、在研究表格里点"刷新"时，Cerebras 提供超低延迟推理，让 Rox 感觉瞬时完成。

Cerebras 在编排内部同样有用——当**短小、频繁的模型调用**决定下一步能否进行（规划、路由、快速验证、摘要）。保持这些跳板飞快，能维持流畅，减少整条链路上用户可见的等待。

对于**深度路径**负载，Rox 路由到擅长多步推理的更大模型。这些作业通常在后台运行（定时或批处理），写回 Rox 的知识图谱，就绪时通知用户。

**经济上的对齐**也自然而然：把高端速度精确部署在创造用户价值之处，只在任务真正受益于质量提升时才使用更重的模型。

### **速度的体验与影响**

对销售人员来说，**Command** 已成为工作的自然起点。他们可以要求会议准备、生成跟进邮件、摘要长对话串，Command 会即时编排 CRM、日历、数据富化、邮件等合适工具，返回一条连贯、可解释、实时流式呈现的线索。结果不像在查询一个系统，更像环内有一位得力的伙伴。

**语音**把这种交互再推一步。以快速推理为骨架，免手对话自然到足以在开车、会议间走路、翻阅演示稿时使用。销售代表保持心流，把任务说出来而不是打出来，不再有打断节奏的尴尬延迟。

对于像**研究**这类更重的负载，Rox 在深度与即时之间取得平衡。大规模客户发现与富化作业在后台持续运行；而"我现在就要"的查询则触发快速的交互式通道——先交付即时价值，更深度的综合就绪后再接上。

这些产品选择有可度量的业务影响。随着响应进入"即时"区间，团队报告 Command 的日参与度更高；当聊天与语音越过那道无形的延迟阈值，采用度还会再上一台阶。深度研究自动化在不知不觉中省掉数小时手工准备，而不打断用户的一天。这些收益叠加起来意味着：更多会议准时备好、跟进执行更快、营收组织更敏锐敏捷。
