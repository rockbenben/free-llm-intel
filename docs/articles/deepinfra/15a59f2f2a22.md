# GLM-5.3 现已在 DeepInfra 上线

GLM-5.3 与 GLM-5.2 共享同一个基础模型，因此每一项性能提升都来自后训练。Z.ai 把已有的强化学习栈规模化，于 2026 年 8 月 14 日发布了成果。GLM-5.3 是一个为复杂软件工程和长周期智能体任务而建的推理模型。在 Z.ai 内部 Code Bench 上，它相对 GLM-5.2 提升 50%，且 Z.ai 报告达成这些成绩所用的输出 token 更少。

网络安全是更大的意外。多阶段利用链推理在后训练中的成长速度超出了 Z.ai 的预期。GLM-5.3 在 CyberGym 基准上登顶，在 ExploitGym 上是 GLM-5.2 成绩的三倍多。自 GLM-5.2 起与中国安全团队协作以来，Z.ai 报告其模型在 269 个项目中发现了 2,436 个漏洞，其中 1,097 个为中高危。发现记录公开在 Z.ai 的 Security Disclosure Ledger 上。

该模型把 1M token 上下文窗口与三档可配置推理强度结合在一起。它的部分训练环境对标多天的专家级工程工作，因此 GLM-5.3 瞄准的是塞不进单个 prompt 的任务。

[GLM-5.3 现已登陆 DeepInfra](https://deepinfra.com/zai-org/GLM-5.3)。

## **这个模型有何不同**

基础模型与 GLM-5.2 完全相同。所有提升都来自把 Z.ai 为该版本已就位的强化学习栈规模化。三个组件承载了这一切：

- **IndexShare** 通过在多个稀疏 attention 层间复用同一个 indexer 来处理长上下文，削减长上下文的计算成本。
- **SAO** 是面向长周期任务的强化学习方法。它从 GLM-5.2 沿用并带 compaction，有助于提升在长程与短程任务上都能保持。
- **slime** 是 Z.ai 面向大规模强化学习的开源异步框架。

三者没有一个是 GLM-5.3 的新发明。Z.ai 加的是规模——更多环境、更多样的任务、更长的 episode、更多的算力，全部指向同一个基础模型。

Z.ai 还报告在长周期编码任务上端到端 RL 训练吞吐提升超过 2.3 倍。该数字是内部数据，外部无法验证。更大的意义在于一个有用的证据：仅靠后训练规模化，就能在未改动的基础权重上驱动一次显著的能力跃迁。

### **思考永远开启**

GLM-5.3 始终推理，Z.ai 不再支持关闭 thinking。你通过三档 reasoning_effort 控制算力预算：low、high、max。默认为 max，也是 Z.ai 推荐用于编程的档位。此前依赖 GLM-5.2 零思考路径的团队，迁移时应先改用 low。[GLM-5.3-Flash](https://deepinfra.com/zai-org/GLM-5.3-Flash) 为更轻量的工作负载提供更低的单 token 价格。

### **编程表现**

在 Z.ai 内部 Code Bench 上，GLM-5.3 在 max 档位完成任务的比例为 34.5%，GLM-5.2 为 23.4%——这就是发布通稿主打的约 50% 提升。token 成本看起来更好：在 high 档位，GLM-5.3 用约 50K 输出 token 拿到 31.4% 分，而 Claude Opus 4.8 用约 120K token 得 29.5%。GLM-5.3 仍落后于 Claude Fable 5——Z.ai 给出后者 max 档位为 39.5%。

Code Bench 是私有基准，这些数字无法独立复现。下面这些公开基准更容易核查：

| 基准 | GLM-5.2 | GLM-5.3 | Kimi K3 | Opus 4.8 | GPT-5.6 Sol | Fable 5（含 fallback） |
| --- | --- | --- | --- | --- | --- | --- |
| Terminal Bench 2.1 | 81.0 | 88.2 | 88.3 | 85.0 | 88.8 | 88.0 |
| Terminal Bench 3.0 | 4.6 | 28.3 | 17.4 | 21.1 | 34.6 | 33.7 |
| DeepSWE v1.1 | 46.2 | 66.9 | 67.5 | 58.0 | 72.7 | 69.7 |
| FrontierSWE | 67.5 | 78.1 | n/a | 66.5 | n/a | 88.2 |
| PostTrainBench | 31.7 | 39.8 | 32.0 | 32.9 | 36.2 | 41.8 |

GPT-5.6 Sol 在 Terminal Bench 2.1、Terminal Bench 3.0 和 DeepSWE 上领先。Kimi K3 在 Terminal Bench 2.1 上以 0.1 分、在 DeepSWE 上以 0.6 分险胜 GLM-5.3，但在 Terminal Bench 3.0 上落后它 10.9 分。Fable 5 领跑 FrontierSWE 和 PostTrainBench，GLM-5.3 在两项上均列第二。

相对 GLM-5.2 提升最大的是 Terminal Bench 3.0——基础模型未变，分数从 4.6 涨到 28.3。Z.ai 共发布 16 行基准，其中两行来自具名的外部评测方：Artificial Analysis 跑了 GDPval-AA v2，Proximal 跑了 FrontierSWE。其余 14 行大多由 Z.ai 自测，通常经由 Claude Code 2.1.207。

### **网络安全能力**

Z.ai 把网络安全提升称为"涌现"，即在后训练中比预期发育得更快。公司确实有意加入了漏洞发现的数据与环境，意外在于模型开始规划跨多个阶段的完整利用链，超出了识别孤立缺陷的范畴。

GLM-5.3 在 CyberGym 上得 84.5 分，是 Z.ai 列出的模型中最高。在 ExploitGym 上，两小时预算内完成 105 个任务、六小时预算内完成 130 个，此前分别是 29 和 39。ExploitBench 从 24.4 升到 54.4，刚好翻了一倍多。

与闭源前沿的差距依然很大。在同样的 ExploitGym 预算下，GPT-5.6 Sol 完成 216 和 293 个任务，Fable 5 完成 181 和 247 个。Z.ai 自己也这么说：能力增长最快的地方，恰恰是它落后最多的地方。

基准之外，自 GLM-5.2 起 Z.ai 就与中国的安全团队把模型跑在真实代码库上。经过专家评审、筛选与去重，这项工作产出 269 个项目中的 2,436 项发现，其中 1,097 项评为中高危。发现覆盖系统内核、操作系统、浏览器引擎和网络协议，包括 Linux、WebKit 和 FreeBSD。最老的缺陷可以追溯到大约 40 年前。发布时，53 项发现已公开并分配了 CVE，2,383 项仍在保密期内，所以在披露跟进之前，这些总量数字只是 Z.ai 的一面之词。台账公开在 [cvd.z.ai](https://cvd.z.ai/)。

### **智能体表现**

Z.ai 报告 GLM-5.3 在 Agents' Last Exam CLI 上以 28.5 分创下开放权重 SOTA，并以 48.2 分领跑 AutomationBench v1.0.6。它在 GDPval-AA v2 上得 1769 分，是 Z.ai 表中最高，领先 Kimi K3（1682）、Opus 4.8（1588）和 DeepSeek-V4 Pro（1590）。

该模型仅接受文本输入，支持 1,048,576 token 上下文窗口、function calling 和 JSON 输出。三者结合，适合以上下文累积为瓶颈的长周期 agent 循环。

## **在 DeepInfra 上开始使用**

GLM-5.3 现已在 DeepInfra 上架，模型标识为 zai-org/GLM-5.3。当前有 38% 促销折扣，定价为每 1M 输入 token $0.563、每 1M 输出 token $2.50、每 1M 缓存输入 token $0.125。无促销的挂牌价为 $0.90、$4.00 和 $0.20，因此超出促销期的预算请按挂牌价计算。

Flex 档在此基础上再打 8 折，当前费率为 $0.45、$2.00 和 $0.10。它对输入、输出和缓存施加同样的降幅，且可与促销叠加。GLM-5.3 支持 Flex，未列出 Priority 档。模型以 fp4 量化运行，支持完整的 1,048,576 token 上下文窗口，function calling 和 JSON 输出开箱可用。

有几个 API 细节最好在第一个请求之前了解。reasoning_effort 参数接受 low、high 或 max；省略或传入其他值时默认为 max，所以只有想拿质量换 token 效率时才需要设置它。聊天场景请传 clear_thinking=true，因为它默认为 false。要复现基准结果，请让 reasoning_effort 保持默认的 max。完整参数参考见 [GLM-5.3 API 页面](https://deepinfra.com/zai-org/GLM-5.3/api)。

DeepInfra 提供 OpenAI 兼容 API，替换 base URL 和 API key 即可配合现有工具使用。按用量计费、无最低消费。平台执行零数据保留政策，持有 SOC 2 与 ISO 27001 认证。

下面是一个最小可运行示例：

**cURL**

```
curl "https://api.deepinfra.com/v1/openai/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEEPINFRA_TOKEN" \
  -d '{
    "model": "zai-org/GLM-5.3",
    "messages": [
      {
        "role": "user",
        "content": "Find the bug in this function and return a corrected version: def add(a, b): return a - b"
      }
    ],
    "reasoning_effort": "max"
  }'
```

**Python**

```
from openai import OpenAI

client = OpenAI(
    api_key="$DEEPINFRA_TOKEN",
    base_url="https://api.deepinfra.com/v1/openai",
)

response = client.chat.completions.create(
    model="zai-org/GLM-5.3",
    messages=[{
        "role": "user",
        "content": "Find the bug in this function and return a corrected version: def add(a, b): return a - b",
    }],
    extra_body={"reasoning_effort": "max"},
)
print(response.choices[0].message.content)
```

**JavaScript**

```
import OpenAI from "openai";

const openai = new OpenAI({
  apiKey: "$DEEPINFRA_TOKEN",
  baseURL: "https://api.deepinfra.com/v1/openai",
});

const response = await openai.chat.completions.create({
  model: "zai-org/GLM-5.3",
  messages: [{
    role: "user",
    content: "Find the bug in this function and return a corrected version: def add(a, b): return a - b",
  }],
  // the cast lets DeepInfra's "max" reasoning_effort value pass the SDK type check
  reasoning_effort: "max",
} as any);
console.log(response.choices[0].message.content);
```

可以在模型页的 demo 标签里直接在浏览器跑一个请求，或领一个 API key 开始集成。需要独享容量的话，你可以把 GLM-5.3 部署为[私有端点](https://deepinfra.com/dash/deployments?new=custom-llm&base_model=zai-org%2FGLM-5.3)。

## **结语**

GLM-5.3 是关于后训练规模化的辩论中一个有用的数据点。Z.ai 把方法讲得很直白——同样的基础权重加上规模化的强化学习——并且把它输掉的行和赢下的行一起公布。

token 效率是生产中值得盯住的部分。如果 Z.ai 的 Code Bench 数字成立——用约 50K 输出 token 险胜用 120K 的 Claude Opus 4.8——那会体现为实打实的成本差异。

运行长周期智能体、自动化安全工具或复杂软件流水线的团队，应该拿自己的评测对着目前使用的模型跑一遍。DeepInfra 上的 Llama 和 Nemotron 家族为 agent 循环中的简单步骤提供了更便宜的选项。符合条件的初创公司可以申请 [DeepStart](https://deepinfra.com/deepstart)，最高获得 10 亿免费 token。
