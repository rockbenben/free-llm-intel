## **Granite 4.2 8B 简介**

[Granite 4.2 8B](https://deepinfra.com/ibm-granite/granite-4.2-8b) 是 IBM Granite 4.2 系列中的中型推理模型。 IBM 将其定位为通用企业应用程序的平衡模型。 *<think>…</think>* 标签内的内置思维链推理支持在 AIME 2025 (86.67) 和 LiveCodeBench v6 (73.24) 等推理密集型基准测试中取得出色结果。

三种思考模式可让您平衡每个查询的深度和延迟：充分思考（默认）、不思考和省力。

该模型是仅解码器的密集变压器。它使用分组查询注意力（32 个注意力头和 8 个 KV 头）、旋转位置嵌入 (RoPE) 和具有 SwiGLU 激活的 MLP。

它支持12种语言：英语、德语、西班牙语、法语、日语、葡萄牙语、阿拉伯语、捷克语、意大利语、韩语、荷兰语和中文。

### **关键功能**

- **内置推理：** 本机思维链提高了数学、编码和复杂的多步骤问题的性能。
- **灵活的思维模式：** 您可以在单个模型中在充分思考、不思考和低努力模式之间切换。
- **推理增强工具调用：** 模型在进行调用之前会推理要调用哪个工具以及原因。
- **代理工作流程：** 强化学习涵盖真实存储库上的软件工程、多步骤终端任务和多跳网络搜索。

## **模型的局限性**

Granite 4.2 8B 在部署之前有几个需要权衡的限制：

- **冗长：** 该模型在情报指数中生成了 1.3 亿个输出令牌，而中位数为 8200 万个。较长的输出会增加[输出成本](https://deepinfra.com/blog/inference-economics-ai-costs-at-scale)，所以要为它们做好预算。
- **推理延迟：** 到达第一个答案标记的时间包括思考时间。无思考和省力模式会减少对延迟敏感的请求的等待。
- **内存占用：** bfloat16 中的权重大约需要 16 GB，4 位量化构建将其缩小到大约 4 到 6 GB。 KV 缓存随着上下文长度和并发性而增长，因此为整个 131K 窗口提供服务需要的内存远多于单独的权重。
- **多语言差异：** 微调主要依赖于英语指令-响应对，因此多语言对话质量可能会有所不同。 IBM 指出，少量示例可以提供帮助。
- **安全和输出质量：** IBM 指出，该模型有时可能会产生不准确、有偏见或不安全的响应，并建议将其与 Granite Guardian 配对。推理标签内的内容为中间思考，并不代表最终结论。
- **编码净空：** SWE-Bench Verified 达到 47.67。 SWE-Bench Pro 上的得分为 19.11，Terminal-Bench 2.1 上的得分为 20.56，这表明在更困难的代理编码任务上还有增长的空间。
- **仅文本：** 该模型支持文本输入和输出，没有图像处理。

## **用于评估模型的方法**

本次审查结合了独立的人工分析测量、IBM 发布的结果和提供商数据。

### **智力评估**

- 模型根据人工智能分析智能指数进行评分。它是智能体 (30%)、编码 (20%)、科学推理 (20%) 和常识 (30%) 的加权平均值。
- Granite 4.2 8B 得分为 11，高于类似尺寸的开放重量模型的中位数 8。

### **性能指标**

- **第一个令牌的时间 (TTFT)：** 发送请求和接收响应的第一个令牌之间的时间。
- **输出速度：**第一个令牌到达后每秒接收的平均令牌数。
- [**混合定价：**](https://deepinfra.com/blog/pricing-101-token-math-cost-per-completion) 缓存命中、输入和输出令牌的比例为 7:2:1，接近实际的使用成本。

### **基准数据集**

IBM 发布的 8B 模型评估（使用基于 NeMo Evaluator SDK 的框架运行）包括：

- 用于软件工程的 SWE-Bench Verified (47.67)、SWE-Bench Multilingual (30.78) 和 SWE-Bench Pro (19.11)
- GPQA (64.14) 和 AIME 2025 (86.67) 用于科学和数学推理
- 用于工具调用的 Berkeley Function Calling Leaderboard v4 (52.39) 和 τ³-bench (58.06)
- IFBench (79.33) 和 Arena-Hard-V2 (65.19) 用于指令跟踪

IBM 自己报告这些结果，因此请将它们视为方向性的，直到独立评估赶上。

### **提供商比较**

- 人工分析在价格、输出速度和延迟方面对提供商进行基准测试。
- OpenRouter 数据提供路由行为和可用性。

## **分析的关键要点**

- **相对于其尺寸而言具有强大的智能：** Granite 4.2 8B 的智能指数得分为 11。这高于同类开放重量型号的中位数 8，并且在 141 款型号中排名第 35 位。
- **通过第三方提供商实现成本效率：** DeepInfra 列出每 100 万个输入代币 0.06 美元，每 100 万个输出代币 0.25 美元，每 100 万个缓存代币 0.015 美元。计算得出，混合费率为 0.05 美元，每项智力指数任务约为 0.02 美元。
- **Apache 2.0 许可：** 宽松许可证允许商业部署、微调和自托管。
- **灵活的推理模式：** 在全面思考、省力和非思考模式之间切换，让您可以针对每个查询的延迟调整深度。
- **原生** [**工具调用**](https://deepinfra.com/blog/deepinfra-function-calling-guide)**：** 推理增强工具调用让模型在执行之前权衡使用哪个工具。 IBM 报告 τ3-bench 上的得分为 58.06，BFCL v4 上的得分为 52.39。
- **具有冗长输出的竞争速度：** 以每秒 98.4 个输出令牌的速度，模型的运行速度比大约 75 的中位数要快。其冗长仍然影响着总响应时间和成本。
- **自托管是可行的：** IBM 发布 FP8、NVFP4、MXFP4 和 GGUF 变体。由于上下文长度有上限，4 位构建适合消费级 GPU。

＃＃ **结论**

Granite 4.2 8B 在一个紧凑的、许可许可的包中提供了强大的推理能力。它适合需要以下功能的组织：

- 企业级推理，模型权重完全透明
- 通过有竞争力的第三方 API 提供商进行经济高效的部署
- 具有本机工具调用和多步骤推理的代理工作流程支持
- 跨 12 种受支持语言的多语言功能

DeepInfra 是最强大的主要 API 选项，将最低的输入和缓存价格与最高的测量输出速度相结合。当自动故障转移和更高的可用性最重要时，请考虑使用 CoreWeave 来处理输出繁重的工作负载，并考虑使用 OpenRouter。

该模型适合范围广泛的任务，例如分类、元数据生成、[结构化 API 调用](https://deepinfra.com/blog/json-mode)、文档处理和内部助手。人工审核应该成为工作流程的一部分。要求较高的面向客户的分析或尖端软件工程可能需要更大的模型。
