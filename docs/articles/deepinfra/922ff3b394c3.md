# 最佳 JEV 替代方案：托管 API 和开放模型 (2026)

发布于 2026.10.30 由 Stefan Fidanov

![最佳 Jev 替代方案：托管 API 和开放模型 (2026)](https://deepinfrabldev.wpenginepowered.com/wp-content/uploads/2026/10/jev.png)

Jev 在诞生一个月之前就已经有了竞争对手。 TypeSafe 于 9 月 15 日推出，到 10 月第一周，OpenAI 宣布推出 Decisions API，Cloudflare 和 AWS 发布了开放权重决策模型，GitHub 上有一系列开源 Jev 替代品：Laya、OpenJev、Kev、AnyJev。我们运行了 Jev 以及您今天实际上可以根据相同决策实现的替代方案。

Jev 替代方案分为三种路线：托管决策 API、您自己运行的开放模型，或者您的产品已经调用的 LLM 端点，被告知仅从固定列表中回答。第三条路线是 DeepInfra 适合的地方，大多数团队今天下午都可以尝试。这不是最快的路线。 Jev 的回答时间中位数为 245 毫秒，而 DeepInfra 上的 DeepSeek-V4.1-Flash 的回答时间为 568 毫秒，准确率相同为 96.5%，笔记本电脑上的 2B 模型击败了两者。

## Jev 替代品必须取代什么

[Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev) 是一个决策模型。你向它发送一个状态（文本或 JSON）和一组命名问题，它会发回数字：哪个选项适合、文本位于刻度上的位置，或者是/否陈述的可能性有多大。它从不写散文，所以它不能返回你没有给它的选项。我们的 [TypeSafe Jev 评论](https://deepinfra.com/blog/typesafe-jev-review) 在五个小作业上对其进行了测试。

任何替代方案都必须满足四件事，而 Jev 对每件事都设定了标准：

| **您需要什么** | **Jev 1.13.0** |
| ---| ---|
|答案类型 |选择（最多 255 个选项）、分数（2 至 10 级）、noul（一项是/否陈述）|
|信心|每个选项的概率，加上选择的置信度域 |
|速度| TypeSafe 规定为 70 至 500 毫秒；我们的评论中 p50 约为 280 毫秒 |
|价格|每 100 万个输入代币 0.042 美元，免费输出 |

速度和价格是 Jev 最难击败的地方：审查的 5 项工作使用了大约 11,500 个输入代币，而 5 美元的试算表从未发生变化。但信心是替代方案最不同的地方。只有当 0.9 意味着大约十分之九正确时，概率才有用。这就是校准，按照预期校准误差 (ECE) 进行测量，即规定置信度与实际精度之间的平均差距。 [AI 模型校准，无人优化的基准](https://deepinfra.com/blog/ai-model-calibration-benchmark) 涵盖了一旦代码中的阈值依赖于该差距，该差距会产生什么影响。

## 路线 1：托管 Jev 替代方案

托管 API 保留了 Jev 的最佳特性：无需运行任何内容。改变的是你所依赖的人。

**OpenAI Decisions API。** OpenAI 在 [9 月 29 日的 DevDay](https://openai.com/index/devday-2026-recap/) 上宣布了它，并于 10 月 6 日将其作为 [公共测试版](https://developers.openai.com/api/docs/guides/decisions) 开放。它在 GPT-6 Luna 上运行，可以读取文本和图像；图像是杰夫无法读取的一种输入。选择答案以 Jev 的形状返回，即每个选项的概率加上置信域。每 100 万个代币的输入成本为 0.10 美元，输出免费，略高于 Jev 费率的两倍。这不是本轮测试的一部分。

**Cloudflare Clef 和 Clef-flash。** Cloudflare [于 10 月 1 日](https://blog.cloudflare.com/clef-decision-models/) 在 Apache 2.0 下作为开放权重发布，并在 [Workers AI](https://developers.cloudflare.com/workers-ai/models/clef/) 上托管它们，价格为每 100 万个输入代币 0.24 美元和 0.09 美元。这是 Jev 价格的两到六倍，但如果托管条款不再适合您，您可以将权重转移到其他地方，并且 Clef 会读取图像和视频。 Cloudflare 的发布帖子将 Clef 在 BANKING77 上的宏观 F1 评级为 94.2，而 Jev 为 79.7。这些是供应商的号码； Clef 的托管副本也没有在我们的车道上运行。

与任何一家公司的交易都与 Jev 相同：来自一家公司的特定于决策的 API，其定价与您已支付的 LLM 费用分开。

## 路线 2：您自己运行的开源 Jev 替代方案

开源 Jev 替代方案分为三个系列，每个系列的运行成本由该系列决定。

**小型编码器。** Laya 是一款 322M 至 421M ModernBERT 级模型，带有决策头，对于 CPU 来说足够轻。它的自述文件显示了编码器耗尽的地方：相对于 Jev 的第三方公布的数字，它赢得了 4 路 AG News（0.950 到 0.910），并在 BANKING77 的 70 多个标签上下降到 0.425，而 0.870。

**带有指针头的微调 Qwen。** Strands Decider 2B、OpenJev 和 Kev 将小型 Qwen 模型的文本头替换为分类器头，因此一次前向传递会返回每个选项的概率。 Kev 1.0 的版本为 0.8B 到 27B，其自述文件将 Kev-27B 的版本设置为 0.851，而在同一开发集上，Jev 的版本为 0.857。 AWS 发布了 Strands Decider 2B 的权重、训练数据和配方。

**免训练 logit 阅读器。** SemIf 和诺基亚的 AnyJev 通过选项标签读取股票开放模型的下一个令牌概率，无需任何训练。 AnyJev 还轮换期权顺序以取消仓位偏差，这在 Qwen3-8B 上将 20 路 BANKING77 准确度从 0.747 提高到 0.803，并将 ECE 从 0.240 降低到 0.184。

六个中的四个使用 Jev 的 /v1/systemone 有线格式，因此将评论的帮助程序移动到本地模型就是更改 URL：
```
import os, requests

def ask(state, questions, url="https://api.typesafe.ai/v1/systemone", key=None, model="jev-1.13.0"):
    headers = {"Authorization": f"Bearer {key}"} if key else {}
    r = requests.post(url, headers=headers, timeout=30,
                      json={"model": model, "state": state, "questions": questions})
    r.raise_for_status()
    return r.json()["answers"]

QUEUE = {"queue": {"type": "choice", "instructions": "Which support queue should handle this ticket?",
          "criteria": {"billing": "Charges, invoices, refunds",
                       "shipping": "Delivery status, lost or late packages",
                       "technical": "Errors, setup problems, broken features"}}}

ticket = "I was charged twice for my March invoice."
hosted = ask(ticket, QUEUE, key=os.environ["TYPESAFE_API_KEY"])
# Strands Decider 2B on the same laptop: strands-decider serve <checkpoint> --port 8000
local = ask(ticket, QUEUE, url="http://127.0.0.1:8000/v1/systemone")copy
```
AWS 的文档称 Strands 服务器与 Jev 的 API 的兼容性尚未得到验证。在我们的运行中，通过相同的ask() 帮助器，仅交换了URL，未更改相同的请求。

## 路线 3：具有结构化输出的 DeepInfra 上的 Jev 式决策

大多数了解 Jev 的团队已经为 LLM 端点付费。该端点也可以做出决定吗？如果它服务于开放模型，是的，一旦你剥夺了模型的编写自由。 DeepInfra 支持 OpenAI 兼容的[结构化输出](https://docs.deepinfra.com/chat/structured-outputs) json_schema 模式，并且唯一字段是选项 id 枚举的模式让解码器要做一件事：从列表中选择。没有可供解析的自由文本，并且您得到了与 Jev 所销售的相同的保证，即答案始终是您的选择之一。
```
import json, math, os
from openai import OpenAI

client = OpenAI(api_key=os.environ["DEEPINFRA_API_TOKEN"],
                base_url="https://api.deepinfra.com/v1/openai")

def decide(state, question, options, model="Qwen/Qwen3.5-9B", priority=False):
    listing = "\n".join(f"- {k}: {v}" for k, v in options.items())
    r = client.chat.completions.create(
        model=model,
        messages=[{"role": "system", "content": "You make one decision about the text. Pick exactly one of the listed options."},
                  {"role": "user", "content": f"Text:\n{state}\n\nQuestion: {question}\n\nOptions:\n{listing}"}],
        response_format={"type": "json_schema", "json_schema": {"name": "decision", "strict": True, "schema": {
            "type": "object", "properties": {"decision": {"type": "string", "enum": list(options)}},
            "required": ["decision"], "additionalProperties": False}}},
        temperature=0, max_tokens=20, logprobs=True,
        extra_body={"reasoning_effort": "none", "chat_template_kwargs": {"enable_thinking": False}},
        **({"service_tier": "priority"} if priority else {}),
    )
    choice = json.loads(r.choices[0].message.content)["decision"]
    conf = next((math.exp(t.logprob) for t in r.choices[0].logprobs.content
                 if t.token.strip(' "') and choice.startswith(t.token.strip(' "'))), None)
    return choice, confcopy
```
有一些设置很重要。温度=0使得拾取可重复。 [Qwen3.5-9B](https://deepinfra.com/Qwen/Qwen3.5-9B)是一种混合推理模型，所以思考必须关闭，否则你付出一段推理才能得到一个单词。 logprobs=True 返回每个生成令牌的对数概率，所选值的第一个令牌是该路线最接近置信度得分的事物。这只是选择的概率，而不是每个选项的概率。正如[可靠的纯 JSON 响应](https://deepinfra.com/blog/deepinfra-json-only-responses) 所解释的，像这样的小型模式也是失败最少的模式。

费用与 Jev 不同。 Jev 仅对输入进行计费。此处，选项列表随提示一起出现，输出约为 7 个 JSON 令牌，因此，一项决策大约需要一个简短的提示加上一些按模型标价计算的输出令牌。用于结构化输出的目录标签的任何模型都可以工作，包括每 1M 输入代币 0.03 美元的 [gpt-oss-20b](https://deepinfra.com/openai/gpt-oss-20b) 和 0.07 美元的 [Mistral Small 3.2](https://deepinfra.com/mistralai/Mistral-Small-3.2-24B-Instruct-2506)。

当一项工作需要每个选项的概率时，就像评论的票务路由余量那样，直接对选项进行评分。 echo=True 的完成端点返回每个提示标记的对数概率，因此您将每个选项附加到提示并读取模型找到它的可能性。这是 SemIf 的方法，通过 DeepInfra 的 API 重建：
```
TMPL = "<|im_start|>user\n{u}<|im_end|>\n<|im_start|>assistant\n<think>\n\n</think>\n\n"

def option_probs(prompt, options, model="Qwen/Qwen3.5-9B"):
    base = TMPL.format(u=prompt + "\n\nAnswer with the option name only.")
    scores = {}
    for o in options:  # one call per option; run them in parallel in production
        lp = client.completions.create(model=model, prompt=base + o, max_tokens=1,
                                       temperature=0, logprobs=1, echo=True).choices[0].logprobs
        scores[o] = sum(v for off, v in zip(lp.text_offset, lp.token_logprobs)
                        if len(base) <= off < len(base) + len(o))
    z = sum(math.exp(v) for v in scores.values())
    return {o: math.exp(v) / z for o, v in scores.items()}copy
```
Echo 每个选项需要调用一次，并且每次都会重新发送提示，因此包含许多选项的长状态会快速增加。在下面的烘烤中，每个决策的成本几乎是同一模型上枚举通道的三倍。两个读数传回不同的东西，这种差异决定了每个读数可以服务哪些工作：

## 在一组共享集上测试的 Jev 替代方案

每个通道都从 SemIf 的 MIT 许可的 [authored144 集](https://github.com/TheoLeeCJ/SemIf/blob/master/benchmarks/data/authored144.jsonl) 中获得相同的 144 个决策：三个系列中的三向选择，询问证据是否支持某个主张、规则是否允许采取行动以及哪个候选人满足要求。 SemIf 自己的 4B 模型报告其平衡精度为 0.813。 10 月 17 日，一次从笔记本电脑发出一个呼叫，因此延迟是完整的客户端往返。准确性与标签完全匹配，ECE 使用 10 个置信区间，每 1,000 个决策的成本来自每个响应的计费使用情况。

TypeSafe 的 API 上的通道是 Jev 1.13.0； DeepInfra 上的 Qwen3.5-9B 和 [DeepSeek-V4.1-Flash](https://deepinfra.com/deepseek-ai/DeepSeek-V4.1-Flash) 具有枚举结构化输出； Qwen3.5-9B再次进入DeepInfra的优先级； Qwen3.5-9B带回波评分；和 Strands Decider 2B 在 M1 Max MacBook Pro 上通过 MPS。 DeepSeek-V4.1-Flash 位于该集合中，因为它是审核用于起草回复的模型，即“您已调用的端点”情况。

Jev 和 DeepSeek-V4.1-Flash 在准确度上并列，均为 144 分中的 139 分，Jev 的置信度是所有通道中校准最好的，ECE 为 0.011，而 DeepSeek 为 0.040。枚举通道的第一个代币置信度比预期要好。在每个 DeepInfra 通道上，给出的答案在 0.85 或更高的情况下在 99% 的情况下都是正确的，因此只有当读数必须涵盖每个选项而不是指定获胜者时，回声评分才会获得额外的调用。但斯特兰德斯是个奇怪的人。它在准确度上与 echo 相当，但低估了自己，平均置信度为 0.80，而 94% 的时间都是正确的。

笔记本电脑上的 Strands 最快为 154 毫秒，无需支付网络跳跃费用。通过网络，Jev 的响应时间为 245 毫秒，DeepSeek-V4.1-Flash 的响应时间为 568 毫秒，而较小的型号 Qwen3.5-9B 在有或没有优先级的情况下花费了约 1.2 秒。

具有枚举模式的 Qwen3.5-9B 是最便宜的托管通道，每 1,000 个决策为 0.0126 美元，比 Jev 低约 20%。 DeepSeek-V4.1-Flash 的成本为 0.0173 美元，而 echo 的成本为 0.0364 美元，因为它每个三向决策进行 3 次调用。换句话说，在此处的任何托管通道上，一百万个决策的费用为 13 至 36 美元。

一个限制：每一行都是三个选项。该集不测试分数或 noul，或 70+ 标签路由。

## 当速度决定时：DeepInfra 前面的本地决策者

如果一个门位于请求路径上，就像代理前面的提示注入屏幕一样，那么几百毫秒就很重要。 DeepInfra 的[优先级](https://deepinfra.com/blog/priority-service-tier) 将请求移动到调度队列的前面，价格是标准价格的 1.5 倍，在我们的运行中，它几乎没有移动 Qwen3.5-9B 的 p50（1,222 到 1,236 毫秒），同时将其 p95 从 2,578 减少到 1,822 毫秒。优先级会修剪慢尾并保留典型的呼叫，即使是修剪后的尾部也比 Jev 的 341 毫秒高出五倍多。对于门，更快的 DeepInfra 杠杆是模型：DeepSeek-V4.1-Flash 的 p95 在标准层上为 903 毫秒。另一方面，可以等待的决定，例如每晚对每张开放门票重新评分，可以在 [flex tier](https://deepinfra.com/blog/flex-service-tier) 上以 20% 的折扣运行。

另一个答案是停止通过网络发送每个决定。应用服务器上的 2B 决策模型可以回答简短、简单的问题，任何不确定的问题或任何太长的问题都会交给 DeepInfra。 Strands Decider 2B 读取[默认情况下 4,096 个代币](https://www.eesel.ai/blog/strands-decider)，因此长状态会自动升级：
```
def route_ticket(ticket):
    a = ask(ticket, QUEUE, url="http://127.0.0.1:8000/v1/systemone")["queue"]
    if max(a["probabilities"].values()) >= 0.85 and len(ticket) < 8000:
        return a["choice"], "local"
    q = QUEUE["queue"]
    choice, conf = decide(ticket, q["instructions"], q["criteria"],
                          model="deepseek-ai/DeepSeek-V4.1-Flash", priority=True)
    return choice, "deepinfra"copy
```
这是评论模型路由器的私人通道，指向另一个方向。在那里，本地模型将敏感提示保留在云端。在这里，它使快速、自信的决策远离网络，并在 2B 模型更有可能出错的情况下进行 DeepInfra 调用。 0.85 的阈值在烘烤组中保持不变。 Strands 将其 144 个答案中的 71 个置于该值或之上，并且所有 71 个答案都是正确的。将另外 73 个决策发送到 DeepSeek-V4.1-Flash 得到了 144 个决策中的 139 个，这是 Jev 的数字，其中一半的决策从未离开过机器。这是三选项问题的一轮，因此请重新检查您自己标签上的截止值。代理的相同两模型形状在[为什么两层代理需要两个模型](https://deepinfra.com/blog/two-tier-agent-two-models)中。

## 选择哪个 Jev 替代方案

- **如果您需要 400 毫秒以下的托管 p95，请使用 Jev**，您的输入是英文文本，并且可以接受封闭的 API。它在烘焙比赛中也拥有最佳的信心，其价格仅比最便宜的通道低一美分。
- **如果您已经在那里调用开放模型，请使用 DeepInfra 结构化输出**。它是相同的密钥、相同的 SDK 和另一种模式，每 1,000 个决策的价格为 0.013 美元到 0.017 美元，并且[小型开放权重模型](https://deepinfra.com/blog/small-open-weight-models-cost)随着数量的增长而保持较低的价格。当工作需要每个选项的概率时，切换到回声评分。
- **使用 Strands Decider 2B 或 OpenJev** 用于请求路径上的门，或用于无法离开机器的数据。
- **如果您需要来自其多语言检查点或仅 CPU 托管的 100 多种语言，请选择 Laya**。
- **如果您针对 Jev 进行原型设计并希望在自己的 GPU 或 Mac 上使用相同的线路格式，请选择 Kev**。
- **如果您已经在 vLLM 或 llama.cpp 上自行托管开放模型，并且想要在不进行任何训练的情况下获得每个选项的概率，请使用 AnyJev 或 SemIf**。
- **如果您的决策依赖于图像，请使用 Workers AI 或 OpenAI Decisions API 上的 Clef**。只有 Clef 会看视频。

## 常见问题解答

### 有免费的 Jev 替代品吗？

是的。上述所有六个开放项目在 Apache 2.0 或 MIT 下都是免费的，Strands Decider 2B、Laya 和 OpenJev 的 1.7B 模型可以在笔记本电脑上运行。你需要为硬件而不是代币付费，尽管 Jev 无论如何在小批量情况下都接近免费。

### 我可以使用常规的 LLM 代替 Jev 吗？

是的，如果你限制它的输出。枚举模式可以从固定列表中选择任何受支持的开放模型，而 logprobs 则可以为选择提供信心。预计比专用决策模型有更多的延迟（在我们的测试中，DeepSeek-V4.1-Flash 为 568 毫秒，而 Jev 为 245 毫秒），并关闭混合推理模型的思考。

### OpenAI 的决策 API 是否返回概率？

是的。 OpenAI 的[决策指南](https://developers.openai.com/api/docs/guides/decisions) 表示，选择答案包含每个选项的概率以及单独的置信字段。我们还没有测量这些概率的校准程度，因此在代码中的阈值取决于它们之前，请对照您自己的标记示例检查它们。

### Jev 替代方案只能在 CPU 上运行吗？

是的，慢慢来。在 [已发布的测试](https://www.eesel.ai/blog/strands-decider) 中，Strands Decider 2B 在八线程 Xeon 上的 CPU 上运行每个短输入大约需要 1.6 秒，而大约 3,000 个令牌则需要 16 到 18 秒。这适合批处理作业，而不适合用户等待的门。
