# Gemini 3.7 Flash：新增功能、基准测试和 API 指南

DeepInfra 发布于 2026.11.17

![Gemini 3.7 Flash：新增功能、基准测试和 API 指南](https://deepinfrabldev.wpenginepowered.com/wp-content/uploads/2026/11/gemini-3-7-flash-model-overview-integration-guide-header.png)

[Gemini 3.7 Flash](https://deepinfra.com/google/gemini-3.7-flash)是Google的Flash层推理模型。它接受文本、图像、视频、音频和 PDF 文件作为输入，返回文本，并在 DeepInfra 上有一个包含 1,000,000 个令牌的上下文窗口。 Google DeepMind 于 [2026 年 8 月 13 日](https://artificialanalysis.ai/articles/gemini-3-7-time-frontier) 发布了它，大约在 Gemini 3.6 Flash 之后三周，并将其定位为编码和代理的主力模型。

它是一个封闭的模型。 DeepInfra 通过 Google 的 API 将其作为合作伙伴模型，因此您可以使用与开放模型（例如 [DeepSeek-V4.1-Flash](https://deepinfra.com/deepseek-ai/DeepSeek-V4.1-Flash)、[GLM-5.3](https://deepinfra.com/zai-org/GLM-5.3) 和 [MiMo-V2.6-Flash](https://deepinfra.com/XiaomiMiMo/MiMo-V2.6-Flash)）相同的 OpenAI 兼容端点、API 密钥和账单来调用它。 DeepInfra 每 100 万个输入代币收费 0.75 美元，每 100 万个输出代币收费 3.75 美元，与谷歌当前的折扣标准价格相同。

此后，Google 发布了更新的 Flash 版本。 [人工分析](https://artificialanalysis.ai/models/gemini-3-7-flash) 现在将 Gemini 3.7 Flash 标记为已弃用，并建议使用 Gemini 3.8 Flash。如果您已经运行 3.7 Flash，或者希望它在一个 API 下打开模型，本指南将介绍更改的内容、基准测试方式、成本以及如何调用它。

型号字符串：**`google/gemini-3.7-flash`**

## Gemini 3.6 Flash 有何变化

Gemini 3.7 Flash 保留了 3.6 Flash 的 1M-token 上下文和输入类型。变化体现在代理工作、每项任务的速度和价格方面。

**代理编码（Google 报告）。** 正如 [MindStudio 总结](https://www.mindstudio.ai/blog/gemini-3-7-flash-benchmarks/) 所示，Google 的发布数据显示了长期软件工程的最大收益：DeepSWE 从 49% 上升到 65.3%，FrontierCode 从 34.4% 上升到 43.6%。 Web Dev Arena 从大约 1538 Elo 移动到大约 1588 Elo。

**代理和知识工作（独立）。** [人工分析](https://artificialanalysis.ai/articles/gemini-3-7-time-frontier) 将大部分改进归因于代理评估：Terminal-Bench v2.1 上升 8 分，Tau3 Banking 上升 3 分，GDPval-AA v2 上升 103 Elo 至 1525，其 AA-Briefcase 知识工作评估上升 169 Elo 至 1132。

**每个任务的速度。** 人工分析在启动时测量了每秒约 340 个输出令牌，在高推理情况下每个智能指数任务平均需要 1.7 分钟。这使得 3.7 Flash 处于每个任务的智能与时间帕累托前沿。

**每项任务的成本。** 按照 Google 的折扣价，Artificial Analysis 将 Gemini 3.7 Flash（高）每项智能指数任务的价格定为 0.40 美元，比 Gemini 3.6 Flash 低 30%。按照中等推理，该数字降至 0.26 美元。

**推理级别。** Google 公开了三个推理级别（高、中、低），人工分析对所有三个级别进行了基准测试。 [参数](https://deepinfra.com/blog/gemini-3-7-flash-model-overview-integration-guide#parameters) 中介绍了该功能的 DeepInfra 参数。

AutomationBench 显示了最大的相对跳跃，尽管该模型在 Google 版本的测试中仍然未能完成大多数任务。 DeepSWE 是最强的绝对结果。

**它领先和落后的地方。** 发布时，Gemini 3.7 Flash 领先于 AA 的 AutomationBench-AA，领先于 Kimi K3 (53%) 和 GPT-5.6 Sol (51.2%)，以及 AA-AnalystAgent，领先于 Claude Opus 5 (54%) 和 Fable 5 (49%)。在整体指数上，它仅落后于 GPT-5.6 Terra 和 Muse Spark 1.2（均为 57）。在 GDPval-AA v2 上，其 1525 与 GLM-5.2 (1506) 持平，低于 DeepSeek V4 Flash 0731 (1558)。

AutomationBench-AA（62.7%）是Artificial Analysis自己的基准测试版本，因此它与上面谷歌的AutomationBench数据不一致。

### 现在的情况

Artificial Analysis 现在将 Gemini 3.7 Flash 列为已弃用：它仍然对模型进行基准测试，但每 18 小时而不是每 6 小时进行一次基准测试，并指向 [Gemini 3.8 Flash](https://artificialanalysis.ai/models/gemini-3-8-flash)。其目前的排行榜上由封闭前沿型号引领，例如 Claude Fable 5.2、Gemini 4 Carbon 和 Claude Opus 5.5。 Gemini 3.7 Flash 的优势在于代理和文档工作的吞吐量和每项任务的价格，而不是该表的顶部。

## 方式和背景

|规格| DeepInfra 上的 Gemini 3.7 Flash |
| --- | --- |
|输入|文本、图像、视频、音频、PDF |
|输出|文字|
|上下文窗口 | 1,000,000 个代币 |
|推理|是（推理模型） |
|特点|兼容OpenAI的API、JSON模式、结构化输出、函数调用、OCR |
|重量|专有（无开放重量）|

PDF 和 OCR 支持使其成为文档繁重的代理步骤的实用选择：阅读合同、发票或幻灯片并返回结构化 JSON。这与其在 AA-AnalystAgent 上的领先地位相匹配，AA-AnalystAgent 测试有关电子表格和文档的问题。

## 定价

定价截至 2026 年 11 月 17 日。 [模型页面](https://deepinfra.com/google/gemini-3.7-flash) 始终显示当前汇率。

|等级 |输入/1M |输出/1M |缓存输入/1M |
| --- | --- | --- | --- |
|标准| 0.75 美元 | 3.75 美元 |未列出 |

- **与 Google 的折扣价相同。** DeepInfra 的 0.75 美元/3.75 美元与 Google 在其自己的 API 上提供的折扣标准价格相符。 Google 的未折扣标准价格为 1.50 美元/7.50 美元（[人工分析](https://artificialanalysis.ai/articles/gemini-3-7-time-frontier)）。
- **比 Google 的 API 层级少。** Google 还为缓存输入提供 90% 的折扣，另外还以标准价格的一半提供 Flex 和 Batch 层级，而 DeepInfra 没有为此模型列出这些。对于大量重复提示的批量工作，Google 自己的 API 更便宜。
- **DeepInfra 上没有 Flex 或 Priority。** DeepInfra 的 Flex (0.8×) 和 Priority (1.5×) 层仅适用于带有这些标签的型号，而这一层则不然。

DeepInfra 为该模型提供的是整合，而不是更低的价格。一个 API 密钥、一张发票和一个适用于 Gemini 和开放模型的 OpenAI 兼容客户端。您不需要 Google Cloud 项目、第二个 SDK 或第二个结算关系。

### 计算代理步骤的成本

发送 20,000 个输入标记并返回 2,000 个输出标记的文档提取步骤的成本为：

- 输入：20,000 × $0.75 / 100 万 = $0.015
- 产出：2,000 × $3.75 / 100 万 = $0.0075
- **总计：每次调用 0.0225 美元**，或每 1,000 次调用 22.50 美元

推理令牌按输出计费，因此较高的推理工作量会提高该总和的输出部分。

## 开始使用

Gemini 3.7 Flash 使用 DeepInfra 的 [OpenAI 兼容 API](https://deepinfra.com/docs/openai_api)：

- **基本 URL：** `https://api.deepinfra.com/v1/openai`
- **端点：** `POST /chat/completions`
- **Auth 标头：** `Authorization: Bearer $DEEPINFRA_API_KEY`（在 [仪表板](https://deepinfra.com/dash/api_keys) 中创建密钥）

该模型需要使用 API 密钥登录帐户；不提供匿名免费电话。

### 参数

完整的架构位于模型的 [API 页面](https://deepinfra.com/google/gemini-3.7-flash/api) 上。

|参数|类型 |默认|笔记|
| --- | --- | --- | --- |
| `model` |字符串| — | `google/gemini-3.7-flash` |
| `messages` |数组| — |聊天记录；支持多模式内容 |
| `reasoning_effort` |字符串| — | DeepInfra 接受 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。较低的值可以减少推理标记和延迟 |
| `max_tokens` |整数 | — | DeepInfra 没有发布该模型的最大输出，因此为长输出明确设置 |
| `temperature` |浮动| 0.7 | 0.7取样温度|
| `top_p` |浮动| 0.9 | 0.9细胞核取样 |
| `stream` |布尔 |假 |服务器发送的事件 |
| `stop` |数组| — |最多 16 个停止字符串 |
| `n` |整数 | 1 |最多完成 4 项 |
| `presence_penalty` / `frequency_penalty` |浮动| 0 | −2 到 2 |
| `response_format` |对象| `{"type": "text"}` |用于结构化输出的 `json_object` 或 `json_schema` |
| `tools` / `tool_choice` |数组/字符串 | — |函数调用：`none`、`auto` 或 `required` |
| `seed` |整数 |随机|无法保证确定性 |

`reasoning_effort` 是 OpenAI SDK 标准参数的一部分，因此您可以直接传递它。在选择一种进行生产之前，请根据您自己的提示测试级别并比较质量、延迟和输出令牌计数。

＃＃＃ Python
```
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["DEEPINFRA_API_KEY"],
    base_url="https://api.deepinfra.com/v1/openai",
)

response = client.chat.completions.create(
    model="google/gemini-3.7-flash",
    messages=[
        {"role": "system", "content": "Extract fields as JSON."},
        {
            "role": "user",
            "content": "Invoice 4417 from Acme GmbH, dated 2026-10-02, total EUR 1,240.00. "
                       "Return invoice_number, vendor, date and total.",
        },
    ],
    reasoning_effort="low",
    response_format={"type": "json_object"},
    max_tokens=2048,
)

print(response.choices[0].message.content)
print(response.usage)copy
```
Gemini 3.7 Flash 和开放模型之间的切换是对 `model` 的一行更改。这对于成本和质量的 A/B 测试以及将机械步骤发送到更便宜的模型并为困难步骤保留更强的模型的[两层代理](https://deepinfra.com/blog/two-tier-agent-two-models) 非常有用。

### 输出限制

模型页面设置 1,000,000 个标记作为最大上下文，将输入和输出一起计数。 DeepInfra 没有为此模型指定单独的最大输出，因此只要您期望长答案，请传递 `max_tokens`，并检查 `finish_reason` 以获得 `"length"` 以捕获截断的响应。

## 结论

Gemini 3.7 Flash 在代理编码和文档工作方面比 3.6 Flash 带来了真正的进步，并且在启动时每个任务的速度都很快。人工分析现在将用户引导至较新的 Gemini 版本，因此，主要当您已经验证了它，或者需要在一个 API 下打开模型旁边的 PDF、音频和视频输入时，它是正确的选择。

在 DeepInfra 上，每个代币的成本与 Google 的折扣率相同，并且它与堆栈的其余部分共享密钥、发票和客户端。如果缓存输入折扣或批量定价导致您的账单增加，请在提交之前比较 Google 自己的 API。

**后续步骤**

- **计划模型退役。** 将模型 ID 保留在配置中并设置评估来比较替代品；请参阅[如何构建能够在模型退役后继续存在的 LLM 应用程序](https://deepinfra.com/blog/model-deprecation-llm-apps)。
- **将其与开放模型配对。** 将批量代理步骤路由到开放模型，并保留 Gemini 用于多模式或文档步骤。我们的[最佳开源编码模型指南](https://deepinfra.com/blog/best-open-source-models-for-coding) 对候选模型进行了比较。
- **尝试一下。** 打开 [Gemini 3.7 Flash 模型页面](https://deepinfra.com/google/gemini-3.7-flash)，创建 API 密钥，然后运行上面的示例。
