# Kimi K3.1 Pro：模型概览、基准测试与 API 指南

发布于 2026.11.17，作者 DeepInfra

![Kimi K3.1 Pro：模型概览、基准测试与 API 指南](https://deepinfrabldev.wpenginepowered.com/wp-content/uploads/2026/11/kimi-k3-1-pro-model-overview-header.png)

[Kimi K3.1 Pro](https://deepinfra.com/moonshotai/Kimi-K3.1-Pro) 是 Moonshot AI 的旗舰开放权重模型，于 [2026 年 10 月 23 日发布](https://artificialanalysis.ai/models/kimi-k3-1-pro)，面向长程 agent 工作构建：编码、3D 创作、金融研究以及文档密集型任务。它是一个 2.8 万亿参数的 Mixture-of-Experts 模型，每个 token 激活 104B 参数，输入为文本和图像，输出为文本，并拥有 [1,048,576 token 的上下文窗口](https://huggingface.co/moonshotai/Kimi-K3.1-Pro)。

K3.1 Pro 不是一次新的预训练。Moonshot [在 Kimi K3 的基础上对它做了后训练](https://www.kimi.ai/blog/kimi-k3-1-pro)，“后训练算力大幅增加”，并在数百个领域进行了大规模强化学习；同时把 K3 的全注意力层换成稀疏注意力，让长上下文的服务成本更低。它是 K3.1 系列的首个模型。

在 DeepInfra 上，该模型运行在 OpenAI 兼容的 API 之后，支持零数据保留、JSON 与结构化输出、function calling 和图像输入。如果你需要更便宜的模型来处理较简单的 agent 步骤，[DeepSeek V4.1 Flash-1017](https://deepinfra.com/deepseek-ai/DeepSeek-V4.1-Flash-1017) 也在同一个 API 上。模型字符串是：

**`moonshotai/Kimi-K3.1-Pro`**

## 相比 Kimi K3 有哪些变化

除特别标注外，下文 Moonshot 的说法均为厂商自报。

### 后训练与编码

- **长程编码：** 在 Moonshot 内部基准 Kimi Code Bench 3.0 Long-horizon 上，K3.1 Pro 得分 61.2，K3 为 55.95（[发布博文](https://www.kimi.ai/blog/kimi-k3-1-pro)）。
- **独立验证：** 在 [LiveBench 2.0](https://livebench.ai/)（2026 年 11 月 6 日的榜单）上，编码分数从 Kimi K3 的 53.1 升到 67.8，长程 agentic 工作从 36.0 升到 38.7。这是实打实的编码提升，不过在 LiveBench 编码项目上，K3.1 Pro 在开放权重模型中仍处于中游。

### 事实准确性

- 在 Moonshot 内部的 Kimi Hallu Bench Hard 上，声明级幻觉率从 K3 的 23.4% 降到 8.3%。Moonshot 称该基准是有意设计的压力测试，因此这个比率并不代表日常的错误率。

### 金融与业务工作

- Moonshot 内部的金融基准分别提升 7.2 分（金融建模）和 11.6 分（金融研究），其 Business Operation 模拟得分约为 K3 的 4.2 倍。在公开的 OfficeQA Pro v2 上，K3.1 Pro 得分 64.4，是 Moonshot 表格中的最高分。

### 注意力与长上下文

- K3.1 Pro 用 **Gated DeepSeek Sparse Attention（Gated DSA）**替换了 K3 的全注意力 Gated MLA 层：93 层中有 24 层改用稀疏注意力，top-k 为 2,048 个索引 token，其余 69 层使用 KDA 线性注意力。目的是在完整的 1M 窗口下降低长上下文建模的成本。

### 网络能力，刻意设限

- 为这次开放权重发布，Moonshot 从中间训练和 RL 中移除了网络攻防相关数据。在其内部的 xdev-bench-hard 上，未过滤的 checkpoint 在 pass@3 下解决 90.5% 的任务；发布的模型解决 81.0%。Moonshot 表示，K3.1 Pro 的攻击性网络能力仍落后于前沿专有模型。

### DeepInfra 上的价格

- [Kimi K3](https://deepinfra.com/moonshotai/Kimi-K3) 的标价仍是每 1M token 输入 $2.85、输出 $14.25。K3.1 Pro 的促销价 $1.90 / $9.50 在两项上都低了三分之一，并且 K3.1 Pro 新增了 Flex 档位。

## 定价

以下为 2026-11-17 的定价，按每 1M token 计（[模型页面](https://deepinfra.com/moonshotai/Kimi-K3.1-Pro)、[定价页面](https://deepinfra.com/pricing)）：

| 档位 | 输入 | 输出 | 缓存输入 |
| --- | --- | --- | --- |
| Standard，促销价（降 5%） | **$1.90** | **$9.50** | **$0.19** |
| Standard，标价 | $2.00 | $10.00 | $0.20 |
| Flex（0.8×） | $1.52 | $7.60 | $0.152 |
| Priority（1.5×） | $2.85 | $14.25 | $0.285 |

**折扣如何叠加。** 5% 的促销是在标价基础上减免，Flex 则在促销价基础上再打 8 折：$1.90 × 0.8 = $1.52 输入，$9.50 × 0.8 = $7.60 输出。Priority 在促销价基础上乘以 1.5。每个档位的缓存输入都是输入价格的 10%。促销没有公布结束日期。

**与其他提供商对比。** 在 [Artificial Analysis 的提供商基准](https://artificialanalysis.ai/models/kimi-k3-1-pro/providers)上，DeepInfra 的 $1.90 / $9.50 是其所测提供商中输入、输出和混合价格的第二低，也是零错误提供商中最低的：DeepInfra 实测错误率为 0.0%，而唯一更便宜的端点（PrimaLabs，$1.80 / $9.00）有 15.4% 的请求失败。大多数提供商收取 Moonshot 自己的 $2.00 / $10.00，高速档位则是输入 $4.00–$6.00、输出 $20–$30。如果你的产品卖点是响应速度，可以试试 DigitalOcean 或 Baseten，它们在标准 $2.00 / $10.00 费率下实测约 200 和 183 token/秒，而 DeepInfra 是 47；对于批处理、agent 和成本敏感的工作，每 token 的差距会在长输出上不断放大。

**Flex** 是工作可以等待时运行该模型最便宜的方式。发送 `"service_tier": "flex"`：容量不足时，请求最多等待 10 分钟，然后返回 HTTP 429，被拒绝的 Flex 请求不计费。过夜评测、批量抽取和后台 agent 都很适合。详见 [Flex 服务档位公告](https://deepinfra.com/blog/flex-service-tier)。

**Priority**（`"service_tier": "priority"`）面向不应排队的流量。价格为 $2.85 / $14.25，高于 Moonshot 的标价，因此只在排队代价高于溢价时使用。

对于一个啰嗦的模型和长时间的 agent 会话，**缓存**很重要：缓存输入成本为 $0.19，而全新输入是 $1.90。用 `prompt_cache_key` 把重复的前缀路由到同一份缓存，用 `prompt_cache_options` 让它保持更久的温热（参见 [prompt 缓存保留](https://deepinfra.com/blog/prompt-cache-retention)）。

想要完整的月度成本示例，请看 [Kimi K3.1 Pro 定价指南](https://deepinfra.com/blog/kimi-k3-1-pro-pricing-guide)。初创公司可以通过 [DeepStart](https://deepinfra.com/deepstart) 申请免费额度。

## 快速开始

该 API 与 OpenAI 兼容：

- **Base URL：** `https://api.deepinfra.com/v1/openai`
- **Endpoint：** `POST /chat/completions`
- **Auth header：** `Authorization: Bearer $DEEPINFRA_API_KEY`

完整的请求 schema 在模型的 [API 页面](https://deepinfra.com/moonshotai/Kimi-K3.1-Pro/api)上。

### 参数

先讲模型特有的参数。非标准字段请通过 OpenAI Python SDK 中的 `extra_body` 发送。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `reasoning_effort` | 模型默认 | `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。`"none"` 关闭思考。Moonshot 的基准测试使用 `max`。推理 token 按输出计费 |
| `reasoning` | — | 对象形式：`{"effort": "...", "enabled": true/false}` |
| `temperature` | 1 | Moonshot 的评测使用 1.0 |
| `top_p` | 1 | Moonshot 的评测使用 0.95 |
| `service_tier` | standard | `flex`（0.8×，最多排队 10 分钟，然后返回 429）或 `priority`（1.5×） |
| `fail_fast` | false | 立即返回 429，而不是排队 |
| `models` | — | 最多 4 个备用模型，当前模型无容量时按顺序尝试 |
| `prompt_cache_key`, `prompt_cache_options` | — | 在请求之间共享 prompt 缓存；例如 `{"ttl": "1h"}` |
| `model` | （必填） | `moonshotai/Kimi-K3.1-Pro` |
| `messages` | （必填） | 聊天消息；用户内容可以包含图像 |
| `max_tokens` | min（上下文 − 输入，65,536） | 最高 943,718 |
| `stream` | false | 服务端发送事件 |
| `stop` | — | 最多 16 个序列 |
| `n` | 1 | 最高 4 |
| `top_k`, `min_p` | 0 | 可选的采样控制 |
| `presence_penalty`, `frequency_penalty` | 0 | −2 到 2 |
| `response_format` | text | `json_object`、`json_schema` 或 `regex` |
| `tools`, `tool_choice` | — | OpenAI 风格的 function calling |

### Python

```
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["DEEPINFRA_API_KEY"],
    base_url="https://api.deepinfra.com/v1/openai",
)

response = client.chat.completions.create(
    model="moonshotai/Kimi-K3.1-Pro",
    messages=[
        {"role": "system", "content": "You are a senior equity research analyst."},
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "Summarize the revenue trend in this chart and list three risks."},
                {"type": "image_url", "image_url": {"url": "https://example.com/revenue-chart.png"}},
            ],
        },
    ],
    temperature=1.0,
    top_p=0.95,
    max_tokens=32768,
    extra_body={
        "reasoning_effort": "high",  # none | minimal | low | medium | high | xhigh | max
        "service_tier": "flex",      # remove this line for the standard tier
    },
)

print(response.choices[0].message.content)
print(response.usage)copy
```

对于分类、抽取或路由这类短小、定义明确的步骤，先用 `"reasoning_effort": "low"` 或 `"none"`。K3.1 Pro 在高 effort 下很啰嗦，而推理 token 在 Standard 档按输出计费，每 1M $9.50。

### 输出上限

该模型没有 16,384 token 的输出上限。你最多可以请求 **943,718 个输出 token**。如果不设置 `max_tokens`，DeepInfra 会在 65,536 token 与 1,048,576 token 窗口在输入之后剩余的部分之间取较小值。输入与输出合起来必须放进这个窗口。

Moonshot 公布的结果使用 `max` effort，在这种设置下，长时间的 agent 运行可能在最终答案开始之前就花掉数万个 token 用于推理。要更接近 Moonshot 的设置，请显式把 `max_tokens` 设为高于 65,536 的默认值、使用 `max` effort，并流式返回响应，以免长生成触发客户端超时。不保证完全复现，因为 Moonshot 的大部分基准是在自己的 harness 中运行的。

## 结论

Kimi K3.1 Pro 在 29 个同规模开放权重模型中拥有最高的 Artificial Analysis Intelligence Index 分数，而 Moonshot 自己的表格也把它放在 agentic、工具使用和文档工作的首位或接近首位。它的弱点同样清楚：闭源模型在无工具的知识、ProgramBench 和网络攻防任务上仍然领先，而且它很啰嗦，输出 token 占账单的大头。

因此，每个输出 token 的价格是最该盯住的数字。在 DeepInfra 上，按当前促销价，K3.1 Pro 每 1M 输出 token 花费 $9.50，Flex 档为 $7.60。这低于 Moonshot 的标价，也低于它所取代的模型，且实测错误率为 0%。
