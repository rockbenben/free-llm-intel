# 从截图到 tool call：DeepInfra 上的 NVIDIA Nemotron 3.5 Super VL

发布于 2026.10.15，作者 Aray Sultanbekova

![从截图到 tool call：DeepInfra 上的 NVIDIA Nemotron 3.5 Super VL](https://deepinfra.com/blog/nvidia-nemotron-3-5-super-vl-release.png)

[NVIDIA Nemotron 3.5 Super VL](https://developer.nvidia.com/blog/nvidia-nemotron-3-5-super-vl-powers-specialized-agents-with-multimodal-reasoning/)，[Nemotron 家族](https://deepinfra.com/nemotron)里新的开源多模态模型，从 day zero 起就在 DeepInfra 上可用。从今天开始，你可以通过我们 OpenAI 兼容的 API 调用它，不需要部署配置，按 token 付费。

Agents 正在越过文本。一个客服 agent 得读懂客户粘贴进来的截图。一个财务工作流得从扫描的发票里取出行项目。一个研究 agent 得看懂第 14 页上那张图表。

构建这类工作流的一种办法，是在一个独立的推理模型前面放一个 OCR 或视觉模型。那样可行，但它多了一次交接、多了一次集成，也多了一个有用内容可能丢失的地方。

Nemotron 3.5 Super VL 把视觉理解和推理放到同一个模型里，让构建按所见之物工作的 agent 变得更容易。

## 是什么让 Nemotron 3.5 Super VL 不同？

Super VL 加入 Nemotron 家族，与面向高效、大批量文本工作负载的 [Nemotron 3.5 Lightning](https://deepinfra.com/nvidia/NVIDIA-Nemotron-3.5-Lightning)，以及面向复杂推理与规划的 [Nemotron 3 Ultra](https://deepinfra.com/nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B) 并列。当你的工作流需要在推理和使用工具的同时做视觉理解，Super VL 就是那个选择。

**视觉理解与工具使用。** Super VL 处理文本、图像、文档和应用程序截图，用视觉上下文来推理下一步并生成 tool call。

**一个模型同时负责看与做。** 多数视觉管线把感知和推理分开。Super VL 读完文档或截图，然后决定该调用哪个工具，把任务留在同一个上下文中，而不是在各个模型之间传递摘要。

**大模型的容量，小模型的算力。** 它的 Mixture-of-Experts（MoE）架构约有 121B 参数，每个 token 激活 12.7B。每个 mixture-of-experts 层把一个 token 路由到 512 个被路由专家中的 22 个，外加一个共享专家。这提供了大模型的容量，同时激活算力足迹要小得多。

**为长 agent 循环而构建。** 主干结合了 Mamba-2、mixture-of-experts 和 attention 层。它的 88 层里只有 8 层使用 attention。Mamba 层携带固定大小的 state，而不是随每个 token 增长的 cache，这有助于长对话和多页文档保持高效。在 DeepInfra 上，该模型有 262K token 的上下文窗口，给应用留下处理长文档和多轮对话的空间。

**设计上就快。** 内建的多 token 预测（MTP）head 每一步草拟多个 token。在 NVIDIA Blackwell GPU 上配合 NVFP4 权重，DeepInfra 在其测试的单请求配置中报告的生成速度超过每秒 400 tokens。

![DeepInfra 上的 Nemotron 3.5 Super VL：按 prompt 类型划分的输出速度，由 Artificial Analysis 测量](https://deepinfra.com/blog/nvidia-nemotron-3-5-super-vl-release/output-speed.png)

*基准测试与 [Artificial Analysis](https://artificialanalysis.ai/) 团队合作完成。*

**开放且可定制。** 权重是开放的，NVIDIA 还发布了 [NeMo](https://www.nvidia.com/en-us/ai-data-science/products/nemo/) 配方，用于在你自己的数据、工具和策略上做精调与 LoRA。这为在专门的多模态任务上取得更高准确率提供了一条路径。

该模型理解 10 种语言：英语、法语、西班牙语、意大利语、德语、日语、印地语、韩语、巴西葡萄牙语和中文。

## 你能构建什么

- **文档智能：** 在多页的 PDF、扫描件和复杂版式中提取字段、表格和图表数值，然后生成摘要或报告。对于结构化工作流，Super VL 可以把抽取到的信息以受 schema 约束的 JSON 返回。
- **客服 agent：** 通过阅读客户发来的文档和截图、应用政策并调用服务工具，来解决多步骤请求。
- **电脑操作与 GUI agent：** 理解应用界面、仪表盘和表单，然后决定下一个动作。
- **多模态研究 agent：** 把在图表和文档中找到的信息与搜索、检索工具的结果结合起来。

## 在 DeepInfra 上开始使用

Nemotron 3.5 Super VL 可以配合任何 OpenAI 兼容的客户端。从 [DeepInfra dashboard](https://deepinfra.com/dash/api_keys) 获取一个 API key，把它设为 `DEEPINFRA_TOKEN`，并把客户端指向 DeepInfra 的 endpoint。

下面的示例给模型一张客户订单页的截图。模型识别出订单号，并调用一个能够获取最新发货信息的函数。

```
import base64
import os

from openai import OpenAI

client = OpenAI(
    api_key=os.environ["DEEPINFRA_TOKEN"],
    base_url="https://api.deepinfra.com/v1/openai",
)

MODEL = "nvidia/NVIDIA-Nemotron-3.5-Super-VL"

tools = [
    {
        "type": "function",
        "function": {
            "name": "lookup_order",
            "description": "Look up an order by ID and return its shipping status.",
            "parameters": {
                "type": "object",
                "properties": {"order_id": {"type": "string"}},
                "required": ["order_id"],
            },
        },
    }
]

with open("screenshot.png", "rb") as f:
    screenshot_b64 = base64.b64encode(f.read()).decode()

response = client.chat.completions.create(
    model=MODEL,
    messages=[
        {
            "role": "user",
            "content": [
                {"type": "image_url", "image_url": {"url": f"data:image/png;base64,{screenshot_b64}"}},
                {"type": "text", "text": "A customer sent this screenshot. Find their order and tell me if it has shipped."},
            ],
        }
    ],
    tools=tools,
)

message = response.choices[0].message
for call in message.tool_calls:
    print(call.function.name, call.function.arguments)

# The model's reasoning is returned alongside the tool call
print(message.reasoning_content)
copy
```

输入：客户的那张截图。

![用作输入的客户订单页截图](https://deepinfra.com/blog/nvidia-nemotron-3-5-super-vl-release/order-screenshot.png)

输出（0.5 秒，`finish_reason: tool_calls`）：

```
lookup_order {"order_id": "SL-48213-77"}

# the model's reasoning, abridged
The status shown in the image is "Preparing
to ship", but I should verify this using the
lookup_order function to get the most accurate
and current information.
copy
```

注意它并不只是从屏幕上读出那个状态徽章。它意识到一张截图可能已经过时，于是去找权威的数据来源。

```
response = client.chat.completions.create(
    model=MODEL,
    messages=[
        {
            "role": "user",
            "content": [

                {"type": "text", "text": "What is the order number in this screenshot? Reply with the order number only."},
            ],
        }
    ],
    extra_body={"reasoning_effort": "none"},
```
