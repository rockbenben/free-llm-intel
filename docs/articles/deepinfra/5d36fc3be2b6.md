# DeepSeek-V4.1-Flash：模型概览与集成

[DeepSeek-V4.1-Flash](https://deepinfra.com/deepseek-ai/DeepSeek-V4.1-Flash) 是一款多模态 Mixture-of-Experts 模型，骨干参数 552B，上下文窗口 1,048,576 token。它接受文本与图像输入，以自回归方式生成文本。

DeepInfra 以 fp8 精度服务该模型，并提供完整的 1,048,576 token 上下文，使服务端窗口与模型原生窗口一致。该架构瞄准输入密集型的智能体工作负载：Causal Encoder-Decoder 设计在 prefill 阶段每 token 激活 8B 参数、decode 阶段激活 16B，从而在长 prompt 上压住成本。

模型字符串：deepseek-ai/DeepSeek-V4.1-Flash

## 架构突破与最新动态

[DeepSeek-V4.1-Flash](https://www.deepseek.com/en/news/deepseek-v4-1-flash/) 的发布标志着内存与计算效率的一次重大飞跃。与传统的稠密模型不同，DeepSeek-V4.1-Flash 采用 **Causal Encoder-Decoder（CED）**架构，处理时只激活一小部分参数——prefill 阶段 80 亿，decode 阶段 160 亿。

### 关键创新

- **Compressed Sparse Attention 2（CSA2）：** 与 SWA Bounded Replay 一起，把全局 KV cache 占用降到每 token 仅 890 字节。相比前代 V4-Flash 是 4 倍缩减，相比最初的 V1 模型是 437 倍缩减，实际上消除了长上下文推理的内存瓶颈。
- **可控推理：** 本次发布的突出特性是**连续可控的 reasoning effort**。开发者现在可以调节一个滑块（1–100），在推理速度/成本与更强的准确率/推理深度之间动态权衡。
- **多模态融合：** 模型配备 **DeepSeek-ViT**——一个定制训练的视觉编码器，从预训练一开始就把视觉 embedding 与文本联合处理，确保无缝的多模态理解。

V4.1-Flash-Base 在 MMLU-Pro、HumanEval 和 GSM8K 上领先；在 AGIEval、BBH 和 MATH 上落后于两位前驱；SimpleQA-Verified 上 V4-Pro 保持明显领先。骨干参数量方面，V4-Flash 为 284B、V4-Pro 为 1.6T、V4.1-Flash 为 552B，因此这一对比在规模上并非同类比较。

## 定价

| 档位 | 输入 | 输出 | 缓存输入 |
| --- | --- | --- | --- |
| Standard | $0.20 | $0.60 | $0.006 |
| Priority（1.5x） | $0.30 | $0.90 | $0.009 |
| Flex（0.8x） | $0.16 | $0.48 | $0.0048 |

以上均为每 1M token 的价格。

将 service_tier 设为 "priority" 可在需求高峰时以 50% 附加费换取更快的首 token 时间与更高吞吐；设为 "flex" 可打 8 折，代价是更慢的尽力而为调度——flex 请求最多可等待容量 10 分钟再运行，否则返回 HTTP 429，因此请用于可重试的工作。不设置 service_tier 即为标准实时调度与定价。

响应中会带一个 service_tier 字段，确认是哪个档位服务了该请求。如果某模型不支持你请求的档位，[DeepInfra](https://deepinfra.com/deepseek-ai/DeepSeek-V4.1-Flash) 会以 standard 档位服务并按 standard 价格计费，不返回错误。

reasoning_effort 设置提供了第二个成本杠杆，在推理成本与准确率之间做权衡。

## 开始使用

API 与 OpenAI 兼容。把现有 OpenAI 客户端指向 DeepInfra 的 base URL、改一下模型名即可。

**Base URL：** https://api.deepinfra.com/v1/openai

**Endpoint：** /chat/completions

**Auth header：** Authorization: Bearer $DEEPINFRA_TOKEN

```
curl "https://api.deepinfra.com/v1/openai/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEEPINFRA_TOKEN" \
  -d '{
      "model": "deepseek-ai/DeepSeek-V4.1-Flash",
      "messages": [
        {
          "role": "user",
          "content": "Explain the benefits of a Mixture-of-Experts (MoE) architecture."
        }
      ],
      "max_tokens": 150
    }'
```

Python 和 JavaScript 同理：把 base_url 设为 DeepInfra 端点、api_key 设为你的 DeepInfra token 即可。

## 参数

| 参数 | 说明 |
| --- | --- |
| model | 必填。deepseek-ai/DeepSeek-V4.1-Flash |
| messages | 必填。角色：system、user、assistant。支持图文交错内容 |
| max_tokens | 最大生成 token 数，见下方输出限制 |
| temperature | 采样温度，0 到 2，默认 1.0。DeepSeek 对该模型推荐 1.0 |
| top_p | Nucleus sampling 阈值，默认 1.0。DeepSeek 对该模型推荐 0.95 |
| stream | 设为 true 则返回 server-sent events，以 [DONE] 结束 |
| stop | 最多 4 个用于终止生成的序列 |
| n | 生成补全序列的数量，默认 1 |
| presence_penalty | 范围 -2.0 到 2.0，默认 0 |
| frequency_penalty | 范围 -2.0 到 2.0，默认 0 |
| response_format | 设为 {"type": "json_object"} 获得结构化输出 |
| tools、tool_choice | Function calling |
| service_tier | "priority" 或 "flex"，不设置则为 standard |
| fail_fast | 模型满载时立即返回 HTTP 429 而非排队，默认 false |
| reasoning_effort | 1 到 100 的整数，控制推理深度与成本的权衡 |

## 输出限制

最大输出 token 数因模型而异，多数模型有 16,384 token 的硬上限。这与 1,048,576 token 的上下文窗口是两回事——后者覆盖 prompt 与 completion 之和。

需要更长输出时使用响应续写：在后续请求中把上一段响应作为 assistant 消息带上，模型会从停止处继续。续写不能突破总上下文窗口，超出的请求会返回 400 错误。

## 响应格式

```
{
    "id": "chatcmpl-guMTxWgpFf",
    "object": "chat.completion",
    "created": 1694623155,
    "model": "deepseek-ai/DeepSeek-V4.1-Flash",
    "choices": [
        {
            "index": 0,
            "message": {
                "role": "assistant",
                "content": "..."
            },
            "finish_reason": "stop"
        }
    ],
    "usage": {
        "prompt_tokens": 15,
        "completion_tokens": 16,
        "total_tokens": 31,
        "estimated_cost": 0.0000268
    }
}
```

usage 对象在 token 计数之外返回一个 estimated_cost 字段，这是开发期间核对花费的最快方式。

## 定价与服务档位

DeepSeek-V4.1-Flash 面向成本效率优化，提供分档定价以匹配不同的工作负载需求。

### Standard 定价

- **标准输入：** 每 100 万 token $0.20。
- **缓存输入：** 每 100 万 token $0.006。
- **标准输出：** 每 100 万 token $0.60。

### 服务档位

用户可以通过 service_tier 在成本与性能之间做选择：

- **Priority 档（1.5× 成本）：** 为低延迟生产需求优化。
- **Flex 档（0.8× 成本）：** 适合不紧急、成本敏感的批处理。

*注：reasoning_effort 设置允许你进一步在推理成本与准确率之间做权衡。最新定价请以 DeepInfra 官方定价页为准。*

## 结语

[DeepSeek-V4.1-Flash](https://deepinfra.com/deepseek-ai/DeepSeek-V4.1-Flash) 代表了高规模 AI 的一次范式转变：把 552B 参数的庞大骨干与业内领先的 KV cache 压缩结合在一起。无论你是在构建自主软件工程智能体、处理百万 token 级文档，还是部署多模态应用，DeepSeek-V4.1-Flash 都能以传统前沿模型一小部分的成本提供所需的灵活性与能力。

**下一步：**

- **启用 Prompt 缓存：** 用 prompt_cache_key 降低重复长上下文 prompt 的成本。
- **探索多模态：** 在 messages 数组中传入图像 URL 即可集成图像分析。
- **微调推理档位：** 试验 reasoning_effort 参数，为你的具体用例找到最佳平衡点。
