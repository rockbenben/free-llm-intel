# 智能体需要的是运行时边界，而不只是护栏

AI 智能体早已超越了单纯的模型调用，开始使用工具、API 和执行环境。随着这套技术栈不断壮大，运行时（runtime）成为架构中越来越重要的一环。

在 DeepInfra，我们的工作是贯穿整个技术栈的：推理、托管智能体（hosted agents）与沙箱（sandboxes）。

NVIDIA 对这一区分说得很清楚：**harness（执行框架）决定智能体尝试做什么，基础设施决定它能做什么。**

这与我们对智能体基础设施的思考方式直接对应：模型 API、agent harness 与沙箱。

## DeepInfra 目前运行的是什么

[**DeepInfra Sandboxes**](https://docs.deepinfra.com/sandboxes/overview) 使用 Kata Containers，在硬件隔离的 microVM 中运行不可信的智能体代码，每个沙箱都运行自己的内核。

网络策略在宿主机上、VM 之外强制执行。沙箱内的智能体可以访问公共互联网，但无法触及 DeepInfra 内部基础设施和云元数据服务。由于这些控制位于 VM 之外，一个被误导或被攻陷的智能体无法轻易改掉自己的边界。

我们的 [**Hosted Agents**](https://docs.deepinfra.com/agents/introduction) 服务把同样的原则应用于 OpenClaw、Hermes 这类常驻智能体。每个智能体运行在自己的环境中，拥有独立内核，SSH 由用户自己的密钥把关，dashboard 则藏在每个实例专属的私有 TLS URL 之后。

正因如此，我们把运行时隔离视为模型层面安全策略的必要补充。

## NVIDIA OpenShell 处于什么位置

DeepInfra 是 NVIDIA OpenShell 中的一方（first-party）推理提供方。我们贡献了 DeepInfra provider profile，并被列入 OpenShell 的 provider 文档。

OpenShell 把同样的安全原则应用到了更高一层。它的网关将凭证与策略保存在智能体环境之外。对于 DeepInfra 推理，API key 绑定到经批准的 DeepInfra 端点，网络与 L7 策略控制同样在智能体之外施加。

这正是 NVIDIA 在 Open Agent Safety Platform 中所描述的那种分离：独立的智能体沙箱、策略强制执行，以及一个统管网络、凭证、工具和模型端点访问的网关。

我们与 NVIDIA 在智能体基础设施上的合作还包括 NemoClaw——DeepInfra 是通过 build.nvidia.com 账号关联可用的推理提供方之一，自 2026 年 3 月 GTC 发布以来一直在线运行。

我们通过社区例会、RFC 讨论以及 PR 和 issue 讨论参与了 OpenShell 社区，并将随着平台的演进持续跟进。我们也在评估 OpenShell 能如何融入 DeepInfra 的智能体与沙箱基础设施。

## 面向智能体基础设施的 NVIDIA Vera CPU

运行时隔离是有成本的，而这会改变智能体基础设施的计算负载特征。

在[我们公开发布的测试](https://deepinfra.com/blog/nvidia-vera-cpu-benchmark)中，NVIDIA Vera CPU 在所有测试的工作负载类别中都是最快的架构。在我们 p99 ≤ 6 秒且零错误的 QoS 标准下，Vera 用 20 个物理核支撑了 256 个持续满载的智能体——每个都运行在自己的 microVM 中——而 Intel 现有旗舰平台只能支撑 160–192 个。

一个更重要的发现是：智能体托管中最大的开销来自隔离层本身，而非 CPU。

对于不可信智能体，这种隔离不是我们想去掉的东西。CPU 必须在这种隔离开销存在的情况下依然表现出色。

在我们的测试中，Vera 表现最好。这就是我们围绕 Vera 做规划的原因。

## 通过 OpenShell 运行 DeepInfra 推理

我们经过测试的 OpenShell × DeepInfra 集成指南现已发布：

[**DeepInfra + NVIDIA OpenShell 集成指南**](https://docs.deepinfra.com/integrations/openshell)

该指南演示如何在 OpenShell 沙箱中运行一个以 DeepInfra 为推理提供方的智能体。内容涵盖：锁定 OpenShell 版本、由我们维护的 DeepInfra provider profile、用现有 DeepInfra API key 配置推理、定义一个只允许访问 api.deepinfra.com 而阻断其他目的地的生产级沙箱策略变体，并完整演示了 Hermes Agent 在沙箱内的操作 walkthrough。

客户在自己的主机上运行 OpenShell，并自行配置模型与沙箱策略。DeepInfra 提供维护中的 provider profile、OpenAI 兼容的 chat 与 embeddings 接口、我们的模型目录以及 API key。

随着智能体工作负载的增长，我们将持续评估并贡献那些把安全边界置于智能体自身之外的方案。

对于智能体，护栏固然重要。**但边界终究要靠基础设施来强制执行。**
