# Kimi K3.1 Pro 定价：API 成本、提供商与 Flex（2026）

由 DeepInfra 发布于 2026.11.17

![Kimi K3.1 Pro 定价：API 成本、提供商与 Flex（2026）](https://deepinfrabldev.wpenginepowered.com/wp-content/uploads/2026/11/kimi-k3-1-pro-pricing-guide-header.png)

## Kimi K3.1 Pro 执行摘要

**价格截至 2026-11-17。** DeepInfra 的 Standard 价格是促销价（在 $2.00 / $10.00 的标价基础上打 5% 折扣，未公布结束日期）。如果你的规划超出本季度，请按标价做预算。

| 最适合 | 提供商推荐 | 原因 |
| --- | --- | --- |
| 错误率 0% 下的最低价格 | **DeepInfra Standard** | 每 100 万 token 输入 $1.90 / 输出 $9.50 / 缓存 $0.19：这是 Artificial Analysis 测得的错误率为 0% 的 endpoint 中最低的价格。有一个 endpoint 更便宜（PrimaLabs，$1.80 / $9.00），但错误率为 15.4%。 |
| 批处理任务、评测与回填 | **DeepInfra Flex** | $1.52 / $7.60 / $0.152，比 Standard 低 20%，适用于最多可以等待 10 分钟容量的请求。 |
| 带大量重复 prompt 的 agent 与 RAG | **DeepInfra Standard** | 缓存输入按输入价格的 10% 计费（$0.19），而 agent 流量大部分是缓存前缀。 |
| 官方直连与 Highspeed | **Moonshot (Kimi API)** | 标价为 $2.00 / $10.00 / $0.20，另有 $4.00 / $20.00 的 Highspeed 版本，只有 Moonshot 提供。 |
| 标价下最快的响应 | **DigitalOcean 或 Baseten** | 每秒分别输出 200.8 和 183.0 个 token，首个回答 token 约 25 秒，价格为 $2.00 / $10.00。 |
| 一个 API 打通多个托管方 | **OpenRouter** | 按各提供商自己的价格把 Kimi K3.1 Pro 路由到 15 家以上提供商，并支持 failover。 |

**结论：** 对大多数生产流量来说，DeepInfra Standard 是在 Artificial Analysis 测试中没有出现请求失败的 endpoint 里成本最低的，而 Flex 还能对任何可以等待的请求再降 20%。只有当响应速度本身就是产品时，才值得在别处以标价付费。

Kimi K3.1 Pro 是 Moonshot AI 的 open-weight 旗舰模型，于 [2026 年 10 月 23 日](https://www.kimi.ai/blog/kimi-k3-1-pro)发布，2026 年 11 月起在 DeepInfra 上线。它是一个 Mixture-of-Experts 模型，总参数 2.8T、激活参数 104B，上下文窗口 1,048,576 个 token，支持文本和图像输入。Moonshot 用多得多的算力在 Kimi K3 的基础上做了后训练，并把 K3 的 full-attention 层换成 sparse attention，让长上下文运行起来更便宜。权重在 [Kimi K3.1-Pro License](https://huggingface.co/moonshotai/Kimi-K3.1-Pro) 下发布，这是一种 MIT 风格的许可，对超大型商业运营方附加了两个条件（详见下文）。

在 [Artificial Analysis](https://artificialanalysis.ai/models/kimi-k3-1-pro) 上，Kimi K3.1 Pro 在 Intelligence Index v5.0.1 中得分 46，在同规模的 29 个 open-weight 模型中排名第一（同类中位数：23）。它同时也是一个长思考模型：跑完该指数时它写下了 1.13 亿个输出 token，而同类中位数是 1.04 亿。这就是一句话版本的定价故事：对一个开放模型来说，价目表偏高，输出是其中昂贵的一侧，而这个模型写得很多。有用的问题不是它便不便宜，而是选哪个 endpoint、用什么样的 token 组合，才能让你的账单保持合理。

## 理解 token 与计费方式

你为发送的内容付费，为模型写出的内容付费，还为你重复发送的内容付费——后者享受 90% 的折扣。

| Token 类型 | 它是什么 | 为什么对 Kimi K3.1 Pro 重要 |
| --- | --- | --- |
| 输入（未缓存） | 新的 prompt token：用户文本、检索到的文档、工具结果、图像 | 在 DeepInfra 上每 100 万 token 收费 $1.90。一个完整的 100 万 token prompt 在未命中缓存时约花费 $1.99。 |
| 缓存输入 | 提供商最近见过的 prompt 前缀：system prompt、tool schema、对话历史 | 每 100 万 token $0.19，为输入价格的 10%。agent 循环每一轮都会重发历史，因此这一项承载了大部分用量。 |
| 输出 | 生成的 token，包括推理 | 每 100 万 token $9.50，为输入价格的 5 倍。推理 token 也在这里计费。 |
| 最大输出 | 单次响应的上限 | 在 DeepInfra 上最高 943,718 个 token。如果不设置 `max_tokens`，默认为 65,536，输出费用最多约 $0.62。 |
| 上下文窗口 | 每次请求的 prompt 加输出 | 1,048,576 个 token。长上下文 RAG 无需激进切块即可装下，这是一种能力，而不是预算问题。 |

实际意味着：

- **钱主要花在输出上。** 输出价格是输入的 5 倍，加上 Artificial Analysis 给这个模型评的是「略偏啰嗦」，因此即使输出只占 token 的很小份额，通常也是它决定账单。
- **reasoning effort 是控制成本的旋钮。** DeepInfra 接受从 `none`（关闭思考）到 `max` 的 `reasoning_effort`。Moonshot 的 benchmark 数字使用的是 `max`。对于抽取、分类和路由类任务，更低的设置能省下任务并不需要的输出 token。
- **缓存命中率和缓存价格一样重要。** 在 Artificial Analysis 的 agentic Index 工作负载上，DeepInfra 的 endpoint 缓存命中率为 92.6%，而其它几个 endpoint 是 98–100%。即便 token 价格更低，这仍使 DeepInfra 每个 Index 任务的成本达到 $4.39，高于几个 $2.00 / $10.00 的 endpoint。把 prompt 中稳定的部分放在最前面，并设置 `prompt_cache_key`，让重复出现的前缀留在缓存里。
- **图像按输入计费。** Kimi K3.1 Pro 接受图像输入，图像会被 tokenize 并按输入价格收费。

**来源：** [Artificial Analysis 的提供商页面](https://artificialanalysis.ai/models/kimi-k3-1-pro/providers)、[OpenRouter](https://openrouter.ai/moonshotai/kimi-k3.1-pro) 以及 [DeepInfra 模型页面](https://deepinfra.com/moonshotai/Kimi-K3.1-Pro)，访问于 2026-11-17。

**按工作负载的要点：**

- **输出密集型工作：** DeepInfra 的 $9.50 输出价格是 Artificial Analysis 测得的零错误 endpoint 中最低的。每 1 亿个输出 token 比标价少花 $50。
- **批处理与异步工作：** Flex 的 $7.60 输出价格比标价低 24%，只需一个请求字段。
- **agent 循环：** $0.19 的缓存价格只有在请求真正命中缓存时才有帮助。把 prompt 结构化成有利于命中缓存的样子，然后在采信任何预测之前，去用量页面看看你的缓存 token 占比。
- **benchmark 之外的路由：** OpenRouter 上列出的少数托管方 token 价格更低，但 Artificial Analysis 没有对它们做 benchmark。这也是本指南中所有价格说法都限定在 Artificial Analysis 实测 endpoint 范围内的原因。

**要避开的成本陷阱：** 缓存失效。在下面的场景 1 中，缓存命中率从 90% 掉到 80%，月账单就从 $1,653.00 涨到 $2,166.00，而流量毫无变化。常见元凶是把时间戳或 request ID 放在 system prompt 开头，或者工具定义的顺序被打乱。

关于速度：DeepInfra 的 endpoint 实测为每秒 46.9 个 token，在 max reasoning 下首个回答 token 耗时 109.82 秒。如果响应速度就是你的产品，那就去测标价的 DigitalOcean 或 Baseten；对于批处理、agent 和对成本敏感的工作，每个 token 的价差会不断累积。

## DeepInfra：Kimi K3.1 Pro 最低成本的零错误路径

| 模型 / 上架项 | 最佳用途 | 上下文 | 输入（每 100 万 token） | 输出（每 100 万 token） |
| --- | --- | --- | --- | --- |
| [Kimi K3.1 Pro](https://deepinfra.com/moonshotai/Kimi-K3.1-Pro) Standard | agent、coding、长上下文 RAG、文档与图像理解 | 1,048,576 | $1.90（缓存 $0.19） | $9.50 |
| Kimi K3.1 Pro, Flex | 批处理任务、评测、回填 | 1,048,576 | $1.52（缓存 $0.152） | $7.60 |
| Kimi K3.1 Pro, Priority | 对延迟敏感的生产路径 | 1,048,576 | $2.85（缓存 $0.285） | $14.25 |

DeepInfra 上的 Kimi K3.1 Pro 通过一个兼容 OpenAI 的 endpoint 提供服务（`https://api.deepinfra.com/v1/openai/chat/completions`，模型 ID 为 `moonshotai/Kimi-K3.1-Pro`，`Authorization: Bearer $DEEPINFRA_API_KEY`）。它支持 JSON 模式、structured output、tool calling、图像输入和 reasoning 控制，并提供零数据保留、无最低消费。DeepInfra 拥有自己的 GPU 基础设施，当共享容量不够时，同一个账号可以把该模型部署到私有 endpoint 上。[`/api` 页面](https://deepinfra.com/moonshotai/Kimi-K3.1-Pro/api) 列出了所有参数。下面这个请求使用 Flex 和较低的 reasoning effort：

```
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["DEEPINFRA_API_KEY"],
    base_url="https://api.deepinfra.com/v1/openai",
)

response = client.chat.completions.create(
    model="moonshotai/Kimi-K3.1-Pro",
    messages=[{"role": "user", "content": "Extract the parties and dates from this contract as JSON: ..."}],
    max_tokens=2048,
    response_format={"type": "json_object"},
    extra_body={
        "service_tier": "flex",
        "reasoning_effort": "low",
    },
)
print(response.choices[0].message.content)copy
```

**为什么这一点重要：** 对这款模型，多数 endpoint 收取 Moonshot 的 $2.00 / $10.00 标价。DeepInfra 的促销价在每一种 token 类型上都比标价低 5%。在 Artificial Analysis 做 benchmark 的 endpoint 中，只有一个更便宜，而它的请求失败率是 15.4%。对一个失败的请求可能浪费数千 token 工作的推理模型来说，0.0% 的错误率本身就是价格的一部分。

## 开发者的真实成本场景

以下五个场景除特别说明外，都使用 DeepInfra 的促销 Standard 价格（$1.90 / $9.50 / $0.19）。每个场景都比对了同一工作负载在 Moonshot 标价（$2.00 / $10.00 / $0.20）下的成本，这既是 Artificial Analysis 上多数 endpoint 的收费，也是促销结束后 DeepInfra 的收费。token 量为月度量。「M」表示百万。

### 场景 1：25 人团队的仓库级 coding agent

| 用量 | 模型 | 提供商 | 输入 token | 输出 token | 月度成本 |
| --- | --- | --- | --- | --- | --- |
| 25 名开发者，每日 agent 会话 | Kimi K3.1 Pro | DeepInfra Standard | 3,000M（2,700M 缓存，300M 未缓存） | 60M | **$1,653.00** |

coding agent 每一轮都会重发仓库映射、tool schema 和对话历史，因此输入远多于输出，而且其中大部分应当命中缓存。这里假设缓存命中率为 90%，输出为输入的 2%。Moonshot 报告该模型在 SWE Marathon 上得分 51.7、在 Terminal-Bench 4.0 上得分 65.7（厂商自报），这正是这个循环所需的长时间跨度编码能力。

**为什么 DeepInfra 合适：** 缓存前缀按 $0.19 计费，而未缓存的输入与输出都处于 Artificial Analysis 测得的零错误 endpoint 中最低的价格水平。

**成本拆分** – 未缓存输入：300M × $1.90/M = $570.00 – 缓存输入：2,700M × $0.19/M = $513.00 – 输出：60M × $9.50/M = $570.00 – **合计：$1,653.00/月**

同一工作负载按标价（$2.00 / $10.00 / $0.20）计算：$600.00 + $540.00 + $600.00 = **$1,740.00**，多出 $87.00。若缓存命中率为 80%，DeepInfra 的账单会升到 $2,166.00。

### 场景 2：基于文档库的长上下文 RAG

| 用量 | 模型 | 提供商 | 输入 token | 输出 token | 月度成本 |
| --- | --- | --- | --- | --- | --- |
| 100,000 次查询 | Kimi K3.1 Pro | DeepInfra Standard | 6,000M（5,000M 缓存，1,000M 未缓存） | 80M | **$3,610.00** |

每次查询发送一个 60,000 token 的 prompt：其中 50,000 token 是由指令和核心文档构成的缓存前缀，另外 10,000 token 是新检索到的段落。它返回一个 800 token 的答案。100 万 token 的窗口留有余地，让你在不得不把切块做得更细之前还能把前缀做大。

**为什么 DeepInfra 合适：** 缓存前缀占输入的 83%，却只占账单里的 $950。未缓存的检索 token 才是那 5% 价差显现的地方。

**成本拆分** – 未缓存输入：1,000M × $1.90/M = $1,900.00 – 缓存输入：5,000M × $0.19/M = $950.00 – 输出：80M × $9.50/M = $760.00 – **合计：$3,610.00/月**（每次查询约 $0.036）

同一工作负载按标价：$2,000.00 + $1,000.00 + $800.00 = **$3,800.00**，多出 $190.00。

### 场景 3：在 Flex 上跑每夜的 agent 评测与回填

| 用量 | 模型 | 提供商 | 输入 token | 输出 token | 月度成本 |
| --- | --- | --- | --- | --- | --- |
| 每夜的评测扫描与数据回填 | Kimi K3.1 Pro | DeepInfra Flex | 2,000M（1,600M 缓存，400M 未缓存） | 100M | **$1,611.20** |

agent 产品的回归测试套件、合成数据生成以及旧工单重处理，都可以为等待容量多花几分钟。Flex 正是为此而生：同样的模型，价格为 0.8 倍，代价是可能要排队最多 10 分钟。

**为什么 DeepInfra 合适：** Flex 只是一个请求字段（`"service_tier": "flex"`），而它在 10 分钟内安排不下的请求会返回 429 且不收费。

**成本拆分（Flex）** – 未缓存输入：400M × $1.52/M = $608.00 – 缓存输入：1,600M × $0.152/M = $243.20 – 输出：100M × $7.60/M = $760.00 – **合计：$1,611.20/月**

在 DeepInfra Standard 上，同样的任务花费 $760.00 + $304.00 + $950.00 = **$2,014.00**，因此 Flex 省下 $402.80。按标价计算：$800.00 + $320.00 + $1,000.00 = **$2,120.00**，比 Flex 多 $508.80。

### 场景 4：JSON 与 tool calling 后端

| 用量 | 模型 | 提供商 | 输入 token | 输出 token | 月度成本 |
| --- | --- | --- | --- | --- | --- |
| 500,000 次请求 | Kimi K3.1 Pro（`reasoning_effort` 为 low） | DeepInfra Standard | 1,500M（1,000M 缓存，500M 未缓存） | 200M | **$3,040.00** |

一个后端把工单、发票和表单提交转换成经过校验的 JSON 与 tool call。每个请求携带 2,000 token 的缓存前缀（指令和 JSON schema）以及 1,000 个新 token，并返回 400 个 token。reasoning effort 设为低，因为抽取类任务从长时间思考中获益甚少。

**为什么 DeepInfra 合适：** 支持 structured output 与 tool calling，而占这份账单三分之二的输出，处于测得的零错误 endpoint 中最低的价格水平。

**成本拆分** – 未缓存输入：500M × $1.90/M = $950.00 – 缓存输入：1,000M × $0.19/M = $190.00 – 输出：200M × $9.50/M = $1,900.00 – **合计：$3,040.00/月**

同一工作负载按标价：$1,000.00 + $200.00 + $2,000.00 = **$3,200.00**，多出 $160.00。更大的杠杆是 reasoning 设置：每次请求每多 1,000 个推理 token，就增加 5 亿个输出 token，即每月多 $4,750.00。

### 场景 5：带 Priority 切片的生产级 agent 平台

| 用量 | 模型 | 提供商 | 输入 token | 输出 token | 月度成本 |
| --- | --- | --- | --- | --- | --- |
| 80% 流量 | Kimi K3.1 Pro | DeepInfra Standard | 6,400M（5,600M 缓存，800M 未缓存） | 240M | $4,864.00 |
| 20% 流量（交互式） | Kimi K3.1 Pro | DeepInfra Priority | 1,600M（1,400M 缓存，200M 未缓存） | 60M | $1,824.00 |
| **合计** |  |  | 8,000M | 300M | **$6,688.00** |

一个面向客户的 agent 平台把大部分工作跑在 Standard 上，而把用户盯着加载圈等待的那部分交互式流量路由到 Priority。

**为什么 DeepInfra 合适：** 两个档位使用相同的模型 ID、endpoint 和集成方式，因此在它们之间迁移流量只需改一个请求字段，而不是做一次迁移。如果之后需要专属容量，同一个账号还可以使用私有 endpoint。

**成本拆分** – Standard：800M × $1.90 + 5,600M × $0.19 + 240M × $9.50 = $1,520.00 + $1,064.00 + $2,280.00 = $4,864.00 – Priority：200M × $2.85 + 1,400M × $0.285 + 60M × $14.25 = $570.00 + $399.00 + $855.00 = $1,824.00 – **合计：$6,688.00/月**

如果全部跑在 Standard 上，成本为 $1,900.00 + $1,330.00 + $2,850.00 = **$6,080.00**，因此 Priority 这部分额外增加 $608.00。若全部按标价：**$6,400.00**。Priority 的价格高于标价，所以只在排队的代价高于 token 代价的地方使用它。

### 这些场景说明了 DeepInfra 的什么

- **价差在每个 token 上很小，但总量上很稳定。** 在每种 token 类型上都比标价低 5%，DeepInfra 在本文的 Standard 场景中每月节省 $87 到 $190。
- **Flex 带来的节省更大。** 把可排期的工作移到 Flex，让场景 3 相对 Standard 减少了 $402.80，比标价低 24%。
- **缓存纪律胜过挑提供商。** 场景 1 中缓存命中率从 90% 跌到 80%，每月多花 $513，接近价差所节省金额的六倍。
- **reasoning 设置比前两者都更关键。** 在场景 4 中，每次请求多 1,000 个推理 token 的代价会超过整份账单。
- **0% 的错误率是每一条「最低价格」说法成立的前提。** Artificial Analysis 测得的那个更便宜的 endpoint，请求失败率是 15.4%。

## 结论

Kimi K3.1 Pro 是 Artificial Analysis 上同规模类别中得分最高的 open-weight 模型，也是运行成本较高的一档。控制账单的是三个决定：在哪里运行它、每个 prompt 有多少内容命中缓存，以及你让它做多少推理。

关于在哪里：在 Artificial Analysis 测得的零错误 endpoint 中，DeepInfra 的 $1.90 / $9.50 是最低价格，而 Flex（$1.52 / $7.60）是运行任何可以等待的任务最便宜的方式。只有当你在卖的就是响应速度时，才值得在更快的 endpoint 上按 $2.00 / $10.00 的标价付费。关于缓存与推理：把稳定内容放在最前，关注你的缓存 token 占比，并按任务设置 `reasoning_effort`，而不是一律留在最大值。
