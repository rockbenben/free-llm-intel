# GLM-5.3 模型概览与集成指南

[GLM-5.3](https://deepinfra.com/zai-org/GLM-5.3-Flash) 是 Z.ai 的大规模推理模型，为复杂软件工程和长程 agent 任务而建。它以文本形式输入和输出，上下文窗口达 1,048,576 token，是 [DeepInfra 模型目录](https://deepinfra.com/models)中数百个模型之一。

这个模型用的是与 [GLM-5.2](https://deepinfra.com/zai-org/GLM-5.2) 相同的底座，所有的提升都来自后训练（post-training）——Z.ai 在编程能力上、以及在能力与 token 效率之间如何平衡的那部分工作，都集中在这里。如果你在更简单的任务上需要更低延迟、更低成本，轻量版的兄弟模型是 GLM-5.3-Flash。

DeepInfra 以 fp4 精度提供服务，开放完整的上下文窗口，并执行 [DeepInfra 信任中心](https://trust.deepinfra.com)里记录的零留存（zero-retention）政策。平台上其他值得拿来与它权衡的大型开放权重模型包括 [Qwen3.8-2.4T-A95B](https://deepinfra.com/Qwen/Qwen3.8-2.4T-A95B) 和 [DeepSeek-V4.1-Flash](https://deepinfra.com/deepseek-ai/DeepSeek-V4.1-Flash)，后者用一部分推理深度换来了低得多的单 token 价格。

模型字符串：zai-org/GLM-5.3

## 相比 GLM-5.2 变了什么

**编程。** Z.ai 报告 GLM-5.3 在其自研的 Z.ai Code Bench 上比 GLM-5.2 提升 50%，并称 GLM-5.3 是编程能力最强的开放权重模型。在公开基准上，Z.ai 宣称在 Terminal Bench 3.0 和 Agents’ Last Exam 上拿到开源 SOTA。这两个说法都限定在开放权重模型范围内：如下表所示，在其中若干基准上，闭源前沿模型仍然领先。

**网络安全。** Z.ai 描述说，在后训练规模化的过程中，网络攻防能力的增长快于预期。在 Z.ai 所对比的模型中，GLM-5.3 拿下最高的 CyberGym 分数 84.5。它相对提升最大的部分位于利用链更上游的环节：ExploitBench 从 24.4 提到 54.4，比 GLM-5.2 的两倍还略多一点。

**token 效率。** Z.ai 把 GLM-5.3 定位为相比 GLM-5.2 进一步改善了性能与 token 消耗之间的平衡，但没有公布具体的降低数字。

在这一组模型里，GLM-5.3 在 CyberGym、AutomationBench、FrontierSWE 和 GDPval-AA v2 上拿到最高分。GPT-5.6 Sol 在 Terminal Bench 2.1 和 3.0、DeepSWE、ExploitBench、Agents’ Last Exam 以及带工具的 HLE 上领先。Opus 4.8 在 NL2Repo 上领先，[Kimi K3](https://deepinfra.com/kimi) 则在 Toolathlon Verified 上领先，并在 DeepSWE 上以 0.6 分的优势胜出。

与 GPT-5.6 Sol 的差距在 ExploitBench 上最大，GLM-5.3 得 54.4，对方是 76.5；差距最小的是 Agents’ Last Exam，28.5 对 28.6。

相比 GLM-5.2，提升在上面列出的每一个基准上都既一致又明显，其中最夸张的是 Terminal Bench 3.0，从 4.6 涨到 28.3。如果要在价格和能力上把 GLM-5.3 与 [Qwen3-Max](https://deepinfra.com/Qwen/Qwen3-Max) 这类其他开放权重选项放在一起权衡，[模型对比工具](https://deepinfra.com/compare)可以把它们并排摆出来。

### 关于吞吐数字的一点说明

Z.ai 的 ExploitGym 方法会用取自 Artificial Analysis 的各模型每秒 token 数对结果重新缩放：GLM-5.3 为 115 TPS，Kimi K3 为 40 TPS，Qwen3.8-Max 为 47 TPS。这些数字是超时计算的输入，而不是对 DeepInfra 服务速度的测量。DeepInfra 上的吞吐取决于 DeepInfra 自己的 fp4 部署，所以请把 115 TPS 当作阅读该基准时的背景信息，而不是服务水平上的预期。

## 定价

GLM-5.3 目前享有 25% 的促销折扣。促销价那一栏就是你现在实际支付的价格。

| **档位** | **输入** | **输出** | **缓存输入** |
| --- | --- | --- | --- |
| 标准档，促销价 | $0.90 | $3.00 | $0.15 |
| 标准档，标价 | $1.20 | $4.00 | $0.20 |
| Flex 0.8x，促销价 | $0.72 | $2.40 | $0.12 |

以上数字均为每 1M token 的价格。

这里有两个各自独立的折扣，而且可以叠加。促销是在标价基础上减去 25%。Flex 服务档位则在当时的标准价基础上再减去 20%。只按标价算的 Flex 是每 1M 输入 token $0.96；$0.72 这个数字反映的是两个折扣叠加之后的结果。促销结束后，Flex 价格会随标准价一起上调。

把 service_tier 设为 “flex” 就能拿到这 20% 的折扣，代价是更慢的、尽力而为（best-effort）的调度。一个 flex 请求最多可能为等待容量排队十分钟，然后才执行或返回 HTTP 429，所以把它用在可以重试的工作上：评估、数据补全、异步任务。不设 service_tier 就是标准的实时调度。GLM-5.3 支持 Flex 档位，但不支持 Priority 档位。正在做新东西的团队也可以通过 [DeepStart](https://deepinfra.com/deepstart) 申请免费推理额度。

## 开始使用

API 与 OpenAI 兼容。把你现有的 OpenAI 客户端指向 DeepInfra 的 base URL 并改掉模型名即可；[DeepInfra 文档](https://docs.deepinfra.com/)覆盖了周边的接口面，包括 embeddings、语音和图像端点。

**Base URL：** https://api.deepinfra.com/v1/openai

**Endpoint：** /chat/completions

**认证头：** Authorization: Bearer $DEEPINFRA_TOKEN

### Python

```
import os
import requests
 
url = "https://api.deepinfra.com/v1/openai/chat/completions"
api_key = os.getenv("DEEPINFRA_TOKEN")
 
data = {
    "model": "zai-org/GLM-5.3",
    "messages": [
        {"role": "user",
         "content": "Explain the security implications of a buffer overflow."}
    ],
    "clear_thinking": True,
    "reasoning_effort": "max",
    "max_tokens": 2048
}
 
response = requests.post(
    url,
    headers={"Authorization": f"Bearer {api_key}"},
    json=data,
)
print(response.json())copy
```

如果你用的是 OpenAI SDK 而不是裸 HTTP，需要通过 extra_body 传入 clear_thinking 和 reasoning_effort，因为它们不属于标准的 OpenAI schema。[完整的 API 参考](https://docs.deepinfra.com/api-reference/chat-completions/openai-chat-completions)列出了所有可接受的字段。

### 参数

| **参数** | **说明** |
| --- | --- |
| model | 必填。zai-org/GLM-5.3 |
| messages | 必填。角色：system、user、assistant。 |
| reasoning_effort | 控制思考预算。接受 low、high 或 max。省略该字段或设为其他值时默认为 max。要复现已公布的基准结果就保留 max。 |
| clear_thinking | 默认为 false。聊天场景请传 true。 |
| max_tokens | 最多生成的 token 数，见下文的输出限制。 |
| temperature | 采样温度，0 到 2。默认 1.0。 |
| top_p | 核采样（nucleus sampling）阈值。默认 1.0。 |
| stream | 设为 true 走服务器发送事件（server-sent events），以 [DONE] 结束。 |
| stop | 最多 4 个会中止生成的序列。 |
| n | 生成补全的条数。默认 1。 |
| presence_penalty | 取值范围 -2.0 到 2.0。默认 0。 |
| frequency_penalty | 取值范围 -2.0 到 2.0。默认 0。 |
| response_format | 结构化输出设为 {“type”: “json_object”}。 |
| tools、tool_choice | 函数调用（function calling）。 |
| service_tier | 折扣档位设为 “flex”，标准调度则留空。该模型不支持 Priority。 |
| fail_fast | 模型达到容量上限时立即返回 HTTP 429，而不是排队。默认 false。 |

在 DeepInfra 上，各模型家族的思考预算行为并不一致，所以在把 prompt 从其他提供方移植过来之前，先查一下[推理模型指南](https://docs.deepinfra.com/chat/reasoning)。

### 输出限制

最大输出 token 数取决于具体模型，多数模型上有一个 16,384 token 的硬性上限。这与 1,048,576 token 的上下文窗口是两回事，后者覆盖的是 prompt 与补全加在一起的总量。

需要更长的输出时使用响应续写（response continuation）：把上一次响应作为一条 assistant 消息放进后续请求发出，模型会接着它停下的地方继续写。续写不能突破总上下文窗口，超出窗口的请求会返回 400 错误。

Z.ai 公布的部分评估所用的输出预算远高于 DeepInfra 的默认上限，有些达到 128K token。想通过共享的 serverless endpoint 复现这些结果，要么用响应续写，要么用私有部署。

## 结论

GLM-5.3 在推理模型版图中称得上是一台重型引擎，在编程和网络安全上给出了顶尖的性能。它把 1M token 的超大上下文窗口、精细的推理控制与业界领先的吞吐结合在一起，让开发者能够构建下一代自主 agent 和安全工具。

**下一步：**

- **优化成本**：使用 Flex 服务档位，推理开销最多省下 25%。
- **构建 Agent**：用原生 function calling 支撑复杂的多步工作流。
- **私有部署**：访问 [DeepInfra 控制台](https://deepinfra.com/zai-org/GLM-5.3)获得专属性能与自定义部署。
