# AI 支出审计：如何用开放模型削减成本

发布于 2026.10.15，作者 Niklas

![AI 支出审计：如何用开放模型削减成本](https://deepinfrabldev.wpenginepowered.com/wp-content/uploads/2026/10/AI-Spend-Audit_-Finding-Open-Model-Opportunities.png)

2026 年，与去年相比，美国的财报电话会议和投资者会议上提及开放权重或开源模型的情况[高出约六倍](https://www.ft.com/content/d9de4776-1fc9-4f2b-aaaf-9961c35d8acd?syn-25a6b1a6=1)。开口的公司也不再只有科技公司。PNC、CH Robinson 和 Siemens 近几周都讨论过开放权重模型。

最清晰的例子是 Tinder。其年化 AI 支出从 1 月的约 100 万美元攀升到 7 月的约 1000 万美元，其 CTO Vinay Kuruvila 告诉 FT，公司已开始把一部分来自非技术员工的查询路由到开放权重模型，以把成本控制下来。AT&T 表示开放模型已经承担其约 40% 的 AI 工作量，并希望达到 70%——这套系统每天处理约 450 亿 tokens。FT 还报道称，开放权重模型在 Vercel 的 AI Gateway 所流转 tokens 中的占比，从 12 月的 7% 升到了 8 月的 56%。

这些公司没有一家宣布自己离开了前沿模型供应商。它们做的是没那么戏剧化、但更有用的事：把流量拆开。简单、大容量的请求交给更便宜的开放模型，真正需要前沿模型的那部分工作留在原处。当“开放权重”开始出现在 CFO 的词汇表里，意味着 AI 已经不再是一笔创新预算条目，而变成了一条总得有人解释的成本线。

本文讲的是：如何从你自己的请求日志里找出可迁移的工作负载、如何用真实数字为迁移定价、如何在切换之前证明质量，以及如何平稳上线、不出现糟糕的一周。模型对比使用当前挂牌价和独立基准数据，演算示例以 [Claude Opus 5.5](https://deepinfra.com/anthropic/claude-opus-5-5) 和 Sonnet 5.5 作为基线，对比 [DeepSeek V4.1 Flash](https://deepinfra.com/deepseek-ai/DeepSeek-V4.1-Flash) 和 [Qwen3.8 Flash](https://deepinfra.com/Qwen/Qwen3.8-Flash)。

## 从账单入手，而不是从模型入手

多数团队做 AI 成本评审时，先问的是哪个模型最好。这是错误的第一个问题。正确的第一个问题是：你的哪些工作负载正在为不需要前沿能力的任务支付前沿价格——而没有请求级数据，你答不上来。

从你的网关、代理或服务商控制台拉取一个月的日志，确认每次调用都带有以下字段：

- 应用、团队和功能（业务用途，而不只是 API key）
- 模型与版本
- 输入 tokens、输出 tokens 与缓存 tokens
- 延迟与重试次数
- 某种结果信号，例如用户是否采纳、下游校验结果或点赞评分
- 每次调用的成本

如果你今天还没有功能级别的标签，先把它加上，别的都往后排。带标签的一周日志比一个季度的发票告诉你的更多。拿到之后，按月度支出给功能排序，看前十项。这份清单就是你的审计范围。在大的那几项处理完之前，前十名以外都属于四舍五入误差。

## 按任务边界的收敛程度给工作负载排序

判断一个工作负载能否迁移，最强的单一预测指标是任务边界有多紧。输出形态固定、“正确”的定义清晰、所需推理量有限的任务，是很强的候选；需要一长串相互依赖的决策、或者一个细微错误代价很高的任务，就不是。

| **工作负载类型** | **典型特征** | **可迁移性** |
| --- | --- | --- |
| 分类、路由、打标签 | 标签集固定、输出很短、体量巨大 | 高 |
| 结构化抽取 | schema 已知，可编程校验 | 高 |
| 工单、通话、文档摘要 | 输入有边界，质量容忍度较高 | 高 |
| [基于检索的内部文档问答](https://deepinfra.com/blog/building-a-rag-application) | 回答以提供的上下文为依据 | 中到高 |
| 有人工复核的支持与销售草稿 | 由人来兜住漏错 | 中到高 |
| 样板代码、测试、文档 | 跑一遍就能验证 | 中 |
| 多步 agentic 编码、长程工具使用 | 错误跨步骤累积放大 | 低，留在前沿模型 |
| 高风险判断（受监管、法律、医疗） | 答错的代价很大 | 迁移前需重点评估 |

你不必猜能力差距在哪里。截至 9 月下旬、取自 Vals AI 基准套件的 Claude Opus 5.5 对比 DeepSeek V4.1 Flash 公开基准数据显示，这个差距远非均匀。在综合的 Vals Index 上，Opus 5.5 得 69.7 分、V4.1 Flash 得 57.9 分，也就是说 Flash 整体大约相当于旗舰模型的 83%。但任务层面的图景比这一个数字更重要。

| **基准测试** | **Claude Opus 5.5** | **DeepSeek V4.1 Flash** | **差距** |
| --- | --- | --- | --- |
| MedScribe（临床病历生成） | 91.4% | 85.5% | 小 |
| Vibe Code Bench v1.1 | 90.3% | 84.7% | 小 |
| Public Benefits Bench | 70.6% | 64.3% | 小 |
| Tax Agent Bench | 70.5% | 62.5% | 中等 |
| Terminal-Bench 2.1 | 87.6% | 74.5% | 中等 |
| CyberBench v1.1 | 55.4% | 73.7% | Flash 领先 |
| ProofBench | 100% | 54% | 大 |
| IOI（竞赛编程） | 95.1% | 40.3% | 大 |
| Terminal-Bench 4.0 | 61.6% | 11.6% | 极大 |
| SRE Bench | 33.6% | 0.8% | 极大 |

这个规律与上面那张表是一致的。有边界的专业任务（文档、结构化分析、可测试的代码生成）与旗舰模型的差距在个位数以内。[长程 agent 工作](https://deepinfra.com/blog/open-source-ai)和竞赛级推理才是开放模型掉队的地方。这正是为什么审计是一项工作负载层面的功课，而不是供应商层面的决策。同一个模型，对你的工单摘要器可以痛快点头答应，对你的自主故障响应 agent 则可以明确说不。

## 用真实数字为迁移定价

以下是这次对比需要关注的挂牌价，按每百万 tokens 计。两个开放模型在 DeepInfra 上的价格，取自 2026 年 10 月初 OpenRouter 和公开价格追踪站的记录，而且经常变动，所以在搭建商业论证之前请核实当前价格。

| **模型** | **输入** | **输出** | **许可证** |
| --- | --- | --- | --- |
| Claude Opus 5.5 | $4.00 | $20.00 | 专有 |
| Claude Sonnet 5.5 | $2.00 | $10.00 | 专有 |
| DeepSeek V4.1 Flash（DeepInfra） | $0.14 | $0.42 | 开放权重 |
| Qwen3.8 Flash（DeepInfra） | $0.113 | $0.382 | 开放权重 |

单 token 价格本身构不成商业论证，所以拿一个具体的工作负载来看。设想某个功能每月处理 100 万次请求，每次平均 3,000 个输入 tokens（一段提示、一些检索到的上下文、一条指令）和 500 个输出 tokens。也就是每月 30 亿输入 tokens 和 5 亿输出 tokens。

| **模型** | **月度成本** | **年度成本** | **相对 Opus 5.5 的倍数** |
| --- | --- | --- | --- |
| Claude Opus 5.5 | $22,000 | $264,000 | 1x |
| Claude Sonnet 5.5 | $11,000 | $132,000 | 便宜 2x |
| DeepSeek V4.1 Flash | $630 | $7,560 | 便宜 35x |
| Qwen3.8 Flash | $530 | $6,360 | 便宜 42x |

以 Sonnet 作基线时差距变小，但依然很大：按挂牌价，Qwen3.8 Flash 大约便宜 21x，V4.1 Flash 大约便宜 17.5x

这些倍数是上限，不是预测。有三件事会把实际数字拉低，一份诚实的商业论证要把每一项都算进去。

- **冗长度：** 推理密集的开放模型每个任务产出的输出 tokens，可能远多于为简洁而调优的旗舰模型。Artificial Analysis 发现，最早的 DeepSeek V4 模型在其 Intelligence Index 上产生的 token 量是该指数中位数的数倍。要在你自己的工作负载上度量“每个完成任务消耗的 tokens”，而不只是每 token 价格。独立的每任务成本数字比挂牌价更有参考价值：V4 Flash 发布时，Artificial Analysis 估算每个基准任务的平均成本约为 3 美分，而 Claude Fable 5 是 $3.15。这仍然大致是 100x，但与对比费率表是完全不同的说法。
- **分词方式：** 不同模型家族会把同一段文本切成数量不同的 tokens，Anthropic 也提到，其近期的 tokenizer 对同样的文本会产出明显多于旧版的 tokens。请对比每任务成本，而不是每百万 tokens 成本。
- **兜底：** 没有哪个便宜模型能接住全部请求。现实的设计是分层的：便宜模型先答，疑难情形升级到前沿模型。这笔升级开销要计入成本模型。下面是同一个工作负载，以 DeepSeek V4.1 Flash 作为第一层、Opus 5.5 作为兜底。

| **升级到 Opus 5.5 的比例** | **月度成本** | **相对全量 Opus 的倍数** |
| --- | --- | --- |
| 0% | $630 | 35x |
| 2% | $1,070 | 21x |
| 4% | $1,510 | 15x |
| 10% | $2,830 | 8x |
| 20% | $5,030 | 4x |

在 4% 的升级比例下，分层设计比全量 Opus 便宜约 15x，仅这一个功能一年就能省下大约 $245,000。如果 Flash 同时把输出 tokens 翻倍，同样的 4% 场景会落到接近 13x。节省是真实且巨大的，同时对“便宜模型需要帮忙的频率”极其敏感。这种敏感，正是接下来两个步骤存在的理由。

再给财务读者一条公平性提示。基线本身也在变动。Opus 5.5 发布时的挂牌价是每百万 tokens $4 和 $20，低于 Opus 5 的 $5 和 $25，而 Anthropic 称其测试显示，在典型工作负载上每任务成本下降约 40%，因为模型使用的 tokens 更少。请按今天的费率、用你真实的缓存命中率给你当前的模型定价，因为 Opus 5.5 的缓存输入是每百万 $0.20。过期的基线会夸大你的节省，并让你在 CFO 面前失去可信度。

## 在你自己的流量上验证质量

公开基准告诉你该往哪里看，你自己的日志才告诉你迁移是否安全。在任何流量转移之前，为每个候选工作负载搭一个小规模评测。

- **采样真实请求**。每个工作负载抽取 500 到 1,000 条生产请求，按你见到的输入类型分层（短的与长的、简单与别扭的、你支持的每一种语言）。把这份集合冻结。它会成为你今后每次模型变更的回归套件。
- **捕获基线**。把这份集合跑一遍现有模型，保存输出以及任何已知结果，例如用户采纳了什么、下游系统如何处理该结果。
- **用最便宜但可靠的方法打分**。结构化任务用程序化校验：schema 合法性、关键字段精确匹配、生成代码的单元测试。开放式任务用 LLM 评审，但先校准它——让人工对 100 条左右的子集打分，检查评审模型是否与人工判断一致。高风险工作负载要把人工复核留在闭环里。
- **在看结果之前先写下验收标准**。例如：至少达到基线任务成功率的 97%、严重错误不增加、格式合法性高于 99%、每任务 tokens 在约定的基线倍数之内。先看到数字再定标准的团队，往往会把标准挪动。
- **看尾部，不看平均值**。97% 的平均质量分可能掩盖了某个客户群体或某类文档上的成片失败。按输入类别切片，并人工读完最差的五十条输出。

然后以影子模式运行候选模型：生产流量同时发给两个模型，用户只看到现有模型的答案，由你来对比。影子模式会多花几周的小成本，却省掉了大部分靠猜。

## 带着安全网上线

一旦某个工作负载过了验收线，上线过程就应该平淡无奇。多数企业团队最终收敛到的设计有五个部分。

### 便宜模型优先，升级时才用前沿模型

定义明确的触发条件：输出未通过 schema 校验、[置信度分数低于某个阈值](https://deepinfra.com/blog/two-tier-agent-two-models)、请求命中某个风险类别、或者用户重复提问。小型决策模型只返回一个选项和经过校准的置信度分数而不生成文本，非常适合承担路由这一步，因为它们带来的延迟和成本都极低。

### 对流量做灰度

从单个工作负载的 5% 开始，保持几天，然后到 25%，再到 100%。让旧路径一直保持随时可用，直到新路径完整熬过一个业务周期，包括月末或任何其他季节性高峰。

### 保留熔断开关

每个被路由的工作负载都需要一个改一行配置就能把 100% 流量切回现有模型的开关。在真正需要它之前先测试。

### 监控财务和工程各自关心的东西

在跟踪每笔被采纳任务成本的同时，跟踪升级率、任务成功率、严重错误率和每任务 tokens。升级率上升，是你的节省正在被侵蚀的早期预警。

### 锁定版本并重跑套件

开放权重模型的供应商更新发得很快，其中一些是 preview 版本，行为会在版本之间漂移。[在生产环境锁定模型版本](https://deepinfra.com/blog/model-deprecation-llm-apps)，并在采用任何新版本之前重跑你冻结的评测集合。

## 在 DeepInfra 上运行低价那一层

DeepInfra 通过 OpenAI 兼容的 API 提供开放模型，因此在既有流水线里加一层便宜模型，就是把第二个客户端指向另一个 base URL。下面是一个带 schema 校验和升级路径的最小分层模式。

```
import json
from openai import OpenAI

cheap = OpenAI(
    api_key="YOUR_DEEPINFRA_API_KEY",
    base_url="https://api.deepinfra.com/v1/openai",
)

CHEAP_MODEL = "deepseek-ai/DeepSeek-V4.1-Flash"  

def is_valid(text: str) -> bool:
    try:
        data = json.loads(text)
        return {"category", "priority"} <= data.keys()
    except (ValueError, AttributeError):
        return False

def classify_ticket(ticket: str) -> str:
    response = cheap.chat.completions.create(
        model=CHEAP_MODEL,
        messages=[
            {"role": "system", "content": "Return JSON with category and priority."},
            {"role": "user", "content": ticket},
        ],
        temperature=0,
    )
    answer = response.choices[0].message.content

    if is_valid(answer):
        return answer          # cheap tier handled it

    return call_frontier(ticket)  # your existing incumbent clientcopy
```

校验函数就是你的升级率被决定的地方。把每一次升级连同原因记入日志，并每周复盘，因为这份日志会准确告诉你，低价层接不了哪些请求、阈值是否需要调整。

## 结论

《Financial Times》描述的这场转变，讲的不是公司抛弃前沿模型，而是公司发现自己很大一部分 AI 流量从来就不需要前沿模型。按挂牌价，在典型工作负载上，DeepSeek V4.1 Flash 和 Qwen3.8 Flash 的成本比 Claude Sonnet 5.5 和 Opus 5.5 低大约 17x 到 42x。把冗长度和兜底成本算进去之后，一个选得合适的工作负载更现实的规划数字接近 10x 到 15x。对单个功能而言，这仍然意味着六位数预算条目与五位数之间的差别。

能力差距是真实且不均匀的：在有边界的专业任务上很小，在长程 agent 工作上极大，所以审计必须一个工作负载一个工作负载地做，用你自己的日志和你自己的验收标准。做完这套功课的团队会留下一个路由层、一套冻结的评测套件，以及一个财务信任的每笔被采纳任务成本指标。这三样资产比任何单一模型选择都更重要，因为它们让你能在一个下午、而不是一个季度里抓住下一次降价。
