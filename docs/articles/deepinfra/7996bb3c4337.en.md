# From Screenshots to Tool Calls: NVIDIA Nemotron 3.5 Super VL on DeepInfra

Published on 2026.10.15 by Aray Sultanbekova

![From Screenshots to Tool Calls: NVIDIA Nemotron 3.5 Super VL on DeepInfra](https://deepinfra.com/blog/nvidia-nemotron-3-5-super-vl-release.png)

[NVIDIA Nemotron 3.5 Super VL](https://developer.nvidia.com/blog/nvidia-nemotron-3-5-super-vl-powers-specialized-agents-with-multimodal-reasoning/), the new open multimodal model in the [Nemotron family](https://deepinfra.com/nemotron), is available on DeepInfra from day zero. Starting today, you can call it through our OpenAI-compatible API with no deployment setup and pay-per-token pricing.

Agents are moving past text. A support agent has to read the screenshot a customer pasted. A finance workflow has to pull line items from a scanned invoice. A research agent has to make sense of the chart on page 14.

One way to build these workflows is to put an OCR or vision model in front of a separate reasoning model. That works, but it adds another handoff, another integration, and another place where useful content can get lost.

Nemotron 3.5 Super VL brings visual understanding and reasoning together in one model, making it easier to build agents that work with what they see.

## What makes Nemotron 3.5 Super VL different?

Super VL joins the Nemotron family alongside [Nemotron 3.5 Lightning](https://deepinfra.com/nvidia/NVIDIA-Nemotron-3.5-Lightning) for efficient, high-volume text workloads and [Nemotron 3 Ultra](https://deepinfra.com/nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B) for complex reasoning and planning. Super VL is the choice when your workflow needs visual understanding alongside reasoning and tool use.

**Visual understanding and tool use.** Super VL works with text, images, documents, and application screenshots, using visual context to reason about the next step and generate tool calls.

**One model for seeing and acting.** Most visual pipelines split perception from reasoning. Super VL reads the document or screenshot and then decides which tool to call, keeping the task in one context instead of passing summaries between models.

**Large-model capacity, small-model compute.** Its Mixture-of-Experts (MoE) architecture has approximately 121B parameters, 12.7B active per token. Each mixture-of-experts layer routes a token to 22 of its 512 routed experts, plus a shared expert. This provides the capacity of a large model with a much smaller active compute footprint.

**Built for long agent loops.** The backbone combines Mamba-2, mixture-of-experts, and attention layers. Only 8 of its 88 layers use attention. Mamba layers carry a fixed-size state instead of a cache that grows with every token, helping long conversations and multi-page documents remain efficient. On DeepInfra, the model has a 262K-token context window, giving applications room to work with long documents and multi-turn conversations.

**Fast by design.** A built-in multi-token prediction (MTP) head drafts several tokens per step. With NVFP4 weights on NVIDIA Blackwell GPUs, DeepInfra reports generation speed above 400 tokens per second in its tested single-request configuration.

![Nemotron 3.5 Super VL on DeepInfra: output speed by prompt type, measured by Artificial Analysis](https://deepinfra.com/blog/nvidia-nemotron-3-5-super-vl-release/output-speed.png)

*Benchmarking done in collaboration with the [Artificial Analysis](https://artificialanalysis.ai/) team.*

**Open and customizable.** The weights are open, and NVIDIA publishes [NeMo](https://www.nvidia.com/en-us/ai-data-science/products/nemo/) recipes for fine-tuning and LoRA on your own data, tools, and policies. This provides a path to higher accuracy on specialized multimodal tasks.

The model understands 10 languages: English, French, Spanish, Italian, German, Japanese, Hindi, Korean, Brazilian Portuguese, and Chinese.

## What you can build

- **Document intelligence:** Extract fields, tables, and chart values from PDFs, scans, and complex layouts across many pages, then generate summaries or reports. For structured workflows, Super VL can return extracted information as schema-constrained JSON.
- **Customer service agents:** Resolve multi-step requests by reading the documents and screenshots customers send, applying policy, and calling service tools.
- **Computer-use and GUI agents:** Understand application screens, dashboards, and forms, then decide on the next action.
- **Multimodal research agents:** Combine information found in charts and documents with results from search and retrieval tools.

## Getting started on DeepInfra

Nemotron 3.5 Super VL works with any OpenAI-compatible client. Get an API key from the [DeepInfra dashboard](https://deepinfra.com/dash/api_keys), set it as `DEEPINFRA_TOKEN`, and point the client at the DeepInfra endpoint.

The example below gives the model a screenshot of a customer's order page. The model identifies the order number and calls a function that can retrieve the latest shipping information.

```
import base64
import os

from openai import OpenAI

client = OpenAI(
    api_key=os.environ["DEEPINFRA_TOKEN"],
    base_url="https://api.deepinfra.com/v1/openai",
)

MODEL = "nvidia/NVIDIA-Nemotron-3.5-Super-VL"

tools = [
    {
        "type": "function",
        "function": {
            "name": "lookup_order",
            "description": "Look up an order by ID and return its shipping status.",
            "parameters": {
                "type": "object",
                "properties": {"order_id": {"type": "string"}},
                "required": ["order_id"],
            },
        },
    }
]

with open("screenshot.png", "rb") as f:
    screenshot_b64 = base64.b64encode(f.read()).decode()

response = client.chat.completions.create(
    model=MODEL,
    messages=[
        {
            "role": "user",
            "content": [
                {"type": "image_url", "image_url": {"url": f"data:image/png;base64,{screenshot_b64}"}},
                {"type": "text", "text": "A customer sent this screenshot. Find their order and tell me if it has shipped."},
            ],
        }
    ],
    tools=tools,
)

message = response.choices[0].message
for call in message.tool_calls:
    print(call.function.name, call.function.arguments)

# The model's reasoning is returned alongside the tool call
print(message.reasoning_content)
copy
```

Input: the customer's screenshot.

![Customer order page screenshot used as input](https://deepinfra.com/blog/nvidia-nemotron-3-5-super-vl-release/order-screenshot.png)

Output (0.5 s, `finish_reason: tool_calls`):

```
lookup_order {"order_id": "SL-48213-77"}

# the model's reasoning, abridged
The status shown in the image is "Preparing
to ship", but I should verify this using the
lookup_order function to get the most accurate
and current information.
copy
```

Notice that it didn't just read the status badge off the screen. It recognized that a screenshot can be stale and went to the source of truth.

### Tip: skip the thinking for simple extraction

```
response = client.chat.completions.create(
    model=MODEL,
    messages=[
        {
            "role": "user",
            "content": [
                {"type": "image_url", "image_url": {"url": f"data:image/png;base64,{screenshot_b64}"}},
                {"type": "text", "text": "What is the order number in this screenshot? Reply with the order number only."},
            ],
        }
    ],
    extra_body={"reasoning_effort": "none"},
)

print(response.choices[0].message.content)
copy
```
