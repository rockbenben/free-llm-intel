# Prompt Hygiene：更便宜、更快的 LLM API 调用

DeepInfra 发布于 2026.11.17

![提示卫生：更便宜、更快的 LLM API 调用](https://deepinfrabldev.wpenginepowered.com/wp-content/uploads/2026/11/prompt-hygiene-cheaper-faster-llm-calls-header.png)

提示卫生是指编写干净、简洁且明确的提示的习惯。这听起来像是一个写作技巧，但在生产中它的表现就像基础设施优化：它减少了代币支出，改善了延迟，并通过使模型输出更可预测来降低重试率。

当团队抱怨 LLM 通话“太贵”或“太慢”时，根本原因通常不是模型。这是提示。臃肿的输入、不明确的指令和无限制的输出悄然增加了成本，并将可靠性变成了一场赌博。

本文解释了什么是即时卫生、为什么它很重要，以及如何应用它，使您的通话更便宜、更快捷，同时又不会降低质量。

## 为什么提示卫生在生产中很重要

在生产中，每个 LLM 调用都会在您的账单上显示两件事：您发送的令牌和模型发回的令牌。 （如果算法对您来说是新的，[Pricing 101](https://deepinfra.com/blog/pricing-101-token-math-cost-per-completion) 会逐步介绍它。）较长的提示需要花费更多的前期费用，并且通常需要更长的时间来处理。模糊的提示通常会在退出时花费更多，因为模型通过生成您实际上不需要的额外文本来填补空白，并且在大多数模型上输出令牌的价格高于输入令牌。两者都会增加延迟。

然而，真正的预算杀手并不是过于冗长的回应。这是一个以错误的形式返回的响应——缺少字段、错误的结构、无法解析——并迫使您再次运行调用。重试会使该调用的成本增加一倍，并且还会产生用户立即注意到的“随机缓慢”尾部延迟。这是更安静的原因之一 [API 账单可以在没有任何人更改模型的情况下翻倍](https://deepinfra.com/blog/why-your-api-bill-doubled-without-changing-models)。

及时保持卫生是控制这种变化的最简单方法。

## “脏提示”是什么样的

混乱的提示往往会以同样的几种方式失败。首先，它们包含了太多的上下文“以防万一”。人们粘贴整个文档，发送完整的聊天历史记录，或者以三种不同的方式重复相同的指令。这会增加令牌的使用，但很少改善答案。

其次，它们包含不明确或相互冲突的约束。要求“详细但简洁”的东西对人类来说听起来很合理，但它迫使模型选择优先考虑哪条指令。有时它会选择“详细”。有时它会选择“简洁”。这种不一致正是导致生产行为不可预测的原因。

最后，肮脏的提示通常不会定义输出契约。如果你想要项目符号但不说出来，有时你会得到段落。如果您想要 JSON 但不指定架构，您将得到一些看起来像 JSON 的东西 — 直到有一天它没有，并且您的解析器崩溃了。

### 目标：减少歧义并限制输出

及时卫生背后的核心思想很简单：减少模型必须做出的决策数量。

当您指定明确的任务、明确的约束和明确的输出格式时，您就减少了生成中的“熵”。熵越小意味着模型漂移、漫无目的或发明结构的可能性就越小。

当你限制输出长度时，你可以直接控制成本。一个好的提示可以遵循以下大纲：

- **任务：** 用一句话尽早明确地陈述任务。
- **约束：** 添加重要的规则：长度、需要时的语气、允许的来源以及缺少某些内容时应采取的措施。
- **输出格式：** 描述您希望模型返回的确切结构。
- **输入：** 仅提供此调用所需的数据。

这并不是为了僵化而僵化。它是为模型提供一个明确定义的车道，以便您以较低的成本获得一致的结果。

## 最省钱的卫生规则

### 规则 1：将任务放在前两行

当目标被预先设定时，模型反应最好。如果任务在很长的序言之后被隐藏，就会增加错位的可能性。

以“总结一下……”开头的提示比以“你是一个有用的助手……”开头，然后是几段场景设置的提示更容易误读模型。

### 规则 2：删除任何不会改变答案的内容

每个代币都有成本。如果句子不能提高正确性、格式或合规性，请将其删除。在实践中，这意味着削减激励性的废话、重复的指令以及不影响输出的“最好有”的背景。

### 规则 3：用可测量的限制限制输出长度

“简洁”是主观的，主观约束比团队预期更容易被忽视。硬限制之所以有效，是因为它们是可衡量的。您可以使用字数、项目符号计数、字符数或严格的 JSON 键来限制输出。即使是像“最多 120 个单词”这样的简单限制也可以大幅削减支出，因为[输出的冗长是大部分账单隐藏的地方](https://deepinfra.com/blog/token-verbosity)。

### 规则 4：始终指定输出格式

如果您的下游系统解析结果，那么格式化不是首选。这是一份合同。准确地告诉模型输出应该是什么样子。如果您需要 JSON，请提供架构（我们的 [仅 JSON 响应](https://deepinfra.com/blog/deepinfra-json-only-responses) 指南展示了如何在 API 级别强制执行它）。如果您需要项目符号，请指定数量和样式。如果需要标题，请指定标题。

添加一行以防止出现额外文本，例如“仅输出结果。请勿添加解释”。

### 规则 5：消除冲突的约束

包含矛盾指令的提示会导致结果不一致。不要“详细但简短”，而是定义“详细”的含义。例如，要求“恰好三个风险”或“包括两个边缘情况”。然后分别盖上长度。这将模糊的目标变成了确定性的目标。

### 规则 6：定义信息缺失时该怎么做

如果您不定义缺失数据行为，模型通常会进行猜测。一句话可以防止幻觉和重试：“如果答案不在输入中，请写下‘源代码中未说明’。”或者：“如果缺少某个字段，则返回 null。”这提高了可靠性并减少了返工。

## 生产卫生：大规模变化

一旦您重复调用模型（尤其是在 API 后面），最大的浪费不是单个冗长的提示。它一遍又一遍地为相同的代币支付全价。有两个习惯在这里产生了巨大的影响：将稳定的指令与每个请求的输入分开，并有意识地考虑如何提供上下文。

- **将稳定的指令与每个请求的输入分开** 如果您发现自己将相同的策略、语气指南或输出格式规则粘贴到每个请求中，那么您将为每次调用支付“税”。在生产中，将提示分为两层会更干净。第一层是一个稳定的、版本化的包装器，其中包含应始终适用的规则，例如输出格式、安全约束以及如何处理丢失的数据。第二层是每个请求的提示，它很短，仅包含实际的用户输入和特定于任务的详细信息。 API 是无状态的，因此包装器仍然随每个请求一起移动，但是可以从提示缓存中以输入价格的一小部分提供每次调用都相同的包装器（请参阅下一节）。它还使跨端点的行为保持一致，因为您不依赖于随着时间的推移而缓慢漂移的复制粘贴指令。
- **更喜欢检索和修剪而不是转储上下文** 另一个常见的成本陷阱是发送整个文档，因为答案是“在那里的某个地方”。您每次都需要为整个文本块付费，即使模型只需要一小段。更好的模式是检索或预先修剪相关部分，然后仅将这些部分传递到提示中。即使没有完整的 RAG 管道，您通常也可以通过选择特定部分、围绕关键字提取几个段落或提供实际包含答案的顶部片段来显着减少标记使用量。更小、更相关的上下文通常也会提高质量，因为它可以减少噪音并保持模型的重点。

## 提示缓存：为永不改变的部分支付更少的费用

稳定的前缀也是可缓存的。在 DeepInfra 上，[提示缓存](https://docs.deepinfra.com/chat/prompt-caching) 在支持的模型上是自动的：当提示的开头与同一模型上最近请求的前缀匹配时，缓存状态将被重用，模型会跳过重新处理该部分，并且这些令牌按模型的缓存输入速率而不是标准输入速率计费。

缓存匹配方式直接遵循两条卫生规则：

- **首先放置稳定的内容。** 缓存从提示符开始匹配，因此系统提示符、格式规则和少量示例位于用户输入之前。
- **保持前缀字节相同。** 单个更改的字符会使匹配无效。保留时间戳、用户 ID 以及前缀之外的任何其他内容。

这就是它的价值。 [DeepSeek-V4-Pro-0813](https://deepinfra.com/deepseek-ai/DeepSeek-V4-Pro-0813) 列出的标准输入价格为每 1M 代币 1.30 美元，缓存输入价格为每 1M 代币 0.10 美元。以每月发送 200,000 个请求的 3,000 个令牌稳定包装器为例，即 600M 前缀令牌：

|  |每 100 万代币的费率 |前缀的每月费用|
| --- | --- | --- |
|标准输入| 1.30 美元 | 780 美元 |
|缓存输入 | 0.10 美元 | 60 美元 |

这是一个基于慷慨假设的估计：每个请求都会命中缓存。缓存条目在一段时间不活动后就会过期，因此实际命中率取决于流量的稳定程度。您可以通过每个响应的使用对象中的“prompt_tokens_details.cached_tokens”字段来衡量您的令牌。如果您需要一个前缀在有保证的窗口内保持温暖，[提示缓存保留](https://deepinfra.com/blog/prompt-cache-retention) 将其保留 5 分钟或一个小时，以换取第一个请求的写入费用。

## 一个具体的前后示例

如果您通过 DeepInfra 运行提示，您会立即感受到混乱提示的成本：更多的输入令牌、更长的完成时间和更高的延迟，尤其是当您大规模调用模型或为面向用户的端点提供支持时。最快的胜利是收紧提示，以便模型仅在重要的工作上花费代币。

### 之前：浪费代币的“混乱”提示

这种提示在原型中很常见：

> “您是一名专家助理。请仔细阅读以下内容并提供专业的答案。确保其包含所有相关细节和上下文。全面且简洁。”

听起来很合理，但生产起来既昂贵又不可靠：

- 它**没有说明任务**（模型实际上应该做什么？）
- 它**鼓励冗长**（“相关细节和上下文”，“彻底”）
- 它包含**冲突的说明**（“彻底但简洁”）
- 它**没有输出契约**，因此格式会变化并且解析器会中断

在实践中，这通常意味着更长的响应、更多的方差和更多的重试——这正是增加支出和尾部延迟的组合。

### 之后：您可以在 API 后面发送“卫生”提示

这是一个生产就绪的重写，它更便宜、更快、更容易验证：

> 任务：仅使用提供的文本回答问题。
> 限制：
> 
> 
> 
> 
> 最多使用 6 个要点
> 
> 
> 
> 每个项目符号必须≤ 18 个单词
> 
> 
> 
> 如果文本不包含答案，请写：来源中未说明。
> 
> 
> 
> 
> 输出格式：仅返回项目符号列表（无介绍，无结束行）。
> 文字：……
> 问题：……

为什么这样效果更好：

- **较低的产出代币：** 硬上限可防止失控完成。
- **更低的延迟：**较短的代通常完成得更快并减少尾部延迟。
- **更少的重试：**严格的格式+清晰的缺失信息行为使响应更容易解析和验证。
- **更好的缓存机会：**指令块现在是提示缓存可以重用的固定前缀，并且当输出一致时，您还可以通过（模型、提示版本、输入哈希）缓存整个响应。

### 重写保存了什么

以下是 DeepSeek-V4-Pro-0813 标准费率的估计（每 100 万代币输入 1.30 美元，输出 2.60 美元）。假设：两个提示都带有相同的 1,500 个标记的源文本；混乱的指令大约有40个token，重写的指令大约有75个；无上限答案平均为 400 个标记；上限答案最多接近 145 个标记（6 个项目符号 × 18 个单词，每个标记大约 0.75 个单词）。

|每 100 万次通话 |输入令牌 |输出代币 |投入成本|产出成本|总计 |
| --- | --- | --- | --- | --- | --- |
|之前 | 1,540M | 400M | 2,002 美元 | 1,040 美元 | 3,042 美元 |
|之后| 1,575M | 145M | 2,048 美元 | 377 美元 | 2,425 美元 |

重写后的提示稍微长一些，但整体成本仍然便宜 20% 左右，因为输出成本下降了大约 64%。重试会扩大差距：如果“之前”的响应中有十分之一因为无法解析而必须重新运行，则每百万次调用会增加约 304 美元。由于缓存了 75 个令牌的指令块，“之后”行进一步下降了一些。

您的数字将根据您的模型、输入以及无上限答案的运行时间而有所不同。该方法继续下去：对进出、之前和之后的代币进行计数，并按照[模型页面](https://deepinfra.com/models)上的价格对其进行定价。

## 快速启动前检查清单

在发送提示之前，请先检查一个小清单：

- 任务是否在顶部明确说明？
- 你能在不改变结果的情况下删除至少 20% 的代币吗？
- 输出长度是否受到可测量规则的限制？
- 输出格式是否明确且可解析？
- 是否存在任何冲突的指示？
- 是否定义了缺失数据行为？
- 是否只包含必要的上下文？
- 提示的稳定部分是否首先出现，每次调用都没有变化，因此可以缓存？

通过此清单的提示往往更便宜、更快并且更容易维护。

## 结论

及时卫生并不是要缩短提示时间。这是为了让他们遵守纪律。

当您删除不必要的标记、限制输出、定义清晰的格式并保持提示的稳定部分可缓存时，您就可以减少模型的猜测并不再为重复的文本付出全部代价。这降低了成本，减少了延迟，而且最重要的是减少了重试。在生产中，这种可靠性通常比任何单一型号的升级更有价值。
