# DeepSeek-V4.1-Flash 现已上线 DeepInfra

[DeepSeek 的新作 V4.1-Flash](https://deepinfra.com/deepseek-ai/DeepSeek-V4.1-Flash) 在 5,520 亿参数的骨干中，处理输入时只激活 80 亿参数，却仍在 DeepSeek 公布的所有智能体基准上击败了规模大得多的 DeepSeek-V4-Pro。它于 2026 年 9 月发布，围绕 Causal Encoder-Decoder 设计构建，正是这一设计让总参数与激活参数之间的巨大差距成为可能。对运行输入密集型或长上下文工作负载的开发者来说，实际效果是每个 prefill token 成本更低，而智能体能力不降。

它[现已在 DeepInfra 上线](https://deepinfra.com/deepseek-ai/DeepSeek-V4.1-Flash)。

最亮眼的架构成果是 KV cache 压缩。V4.1-Flash 的全局 KV cache 占用为每 token 890 字节，约为其前代 V4-Flash 的四分之一，从而削减了让长智能体运行变得昂贵的那部分内存与存储成本。在真正关系到实际工作负载的基准上，它拿下 3471 的 Codeforces rating，为对比组中最高；在 DeepSWE v1.1 上得 74.2 分，险胜得 74.0 的 Claude Opus 5.0。该模型支持 1,048,576 token 的上下文窗口和原生多模态输入，在 DeepInfra 上以 fp8 运行，并以 MIT 许可开放权重。

## 这个模型有何不同

V4.1-Flash 在结构上最值得注意的一点是其 Causal Encoder-Decoder（CED）架构——对标准 decoder-only transformer 的一次真正背离。40 层骨干拆分为 20 层因果编码器加 20 层解码器，解码器的全局 KV cache 由编码器最后的隐状态投影而来，而非逐层构建。正是这种不对称造就了那样的激活参数量：相对 552B 的骨干，prefill 阶段只激活 8B、decode 阶段激活 16B，另有一个以稀疏方式访问的 196B Engram 条件记忆组件。对智能体流水线这类输入密集型工作负载，更低的 prefill 成本是实打实的。

KV cache 设计值得单独一说。V4.1-Flash 使用 Compressed Sparse Attention 2（CSA2），给每个 attention 层指定 Full、Reindex 或 Reuse 三种静态模式之一，以在各层之间共享主 KV 与 indexer K。CSA2 加上 FP4 主 KV 缓存，共同产出 890 字节的全局占用。另一套独立机制 SWA Bounded Replay 通过回放最近的 token 而非把它们持久化到 SSD 来重建滑动窗口 attention 状态，把持久化缓存压到 V4-Flash 的约八分之一。如果你想看这些数字与当世代同类产品（而非上一代）的对比，[GLM-5.3](https://deepinfra.com/zai-org/GLM-5.3) 和 [Qwen3.8-Flash](https://deepinfra.com/Qwen/Qwen3.8-Flash) 是今天在 DeepInfra 上最接近的参照点。

| **模型** | **每 token 全局 KV cache** | **相对 V4.1-Flash** |
| --- | --- | --- |
| DeepSeek-V1 | 约 389,000 字节 | 大 437 倍 |
| DeepSeek-V4-Flash | 约 3,560 字节 | 大 4 倍 |
| DeepSeek-V4.1-Flash | 890 字节 | 基准 |

890 字节的数字以及 4 倍、437 倍的比例都由 DeepSeek 官方公布；中间一列 V1 和 V4-Flash 的绝对字节数是依据这些比例推算的，并非直接发布。持久化 KV cache 是另一项独立度量：V4.1-Flash 在 SSD 上的占用约为 V4-Flash 所需量的八分之一。

对于跑长会话、大量命中缓存的智能体，这直接转化为更低的内存压力和更低的基础设施成本。

在基准上，V4.1-Flash 与激活参数量远高于它的模型竞争，并在多个智能体类目中领先。instruct 模型评测中的亮点：

- Codeforces rating：3471，对比表中最高，高于 V4-Pro 的 3348 和 V4-Flash 的 3289
- Terminal-Bench 2.1：90.6，表中最高，高于 Claude Opus 5.0 的 89.1
- DeepSWE v1.1（真实世界软件工程）：74.2，略微领先 Opus 5.0 的 74.0，V4-Pro 为 62.7
- CyberGym 得 88.1、AutomationBench 得 54.8，均为对比表中最高
- Agent's Last Exam：31.8，高于 Opus 5.0 的 28.6
- 不占优之处：GPQA Diamond 得 90.9，落后 V4-Pro 的 92.4；Terminal-Bench 3.0 和 4.0 明显落后 Opus 5.0——分别为 30.0 对 43.3、31.2 对 51.8

base 模型同样在 MMLU-Pro 上得 74.1（V4-Pro-Base 为 73.5）、HumanEval 上得 79.4、GSM8K 上得 93.0——尽管激活参数少得多，三项全部超过 V4-Pro-Base。

在能力方面，V4.1-Flash 支持完整的 1,048,576 token 上下文窗口，并从预训练起就原生多模态：通过从头训练的 DeepSeek-ViT（采用 2D-RoPE 和两层 MLP 投影器）处理文本与图像。base 模型的视觉基准包括 DocVQA 95.6 和 RefCOCO-avg 86.0。模型还支持连续可调的 reasoning effort——1 到 100 的整数——让你在推理时调节成本与准确率的权衡，而不是在思考模型与非思考模型之间二选一。

与它的前代相比：这些架构改动等于从零重建，而非微调或渐进更新。DeepSeek 用 45T token 从头预训练了该模型，围绕大规模自动化智能体任务合成重建了后训练流水线，并引入了 CED 设计。DeepInfra 会继续在平台上托管更早的 V4 系列模型，方便你直接对比跑分，或关注 [DeepInfra 博客](https://deepinfra.com/blog)上的发布公告。

## 在 DeepInfra 上开始使用

DeepSeek-V4.1-Flash 现已在 DeepInfra 上架，模型标识为 deepseek-ai/DeepSeek-V4.1-Flash。定价按用量分三档：Standard 为每 1M 输入 token $0.20、每 1M 输出 token $0.60；Priority 为 1.5 倍，即 $0.30 和 $0.90；Flex 为 0.8 倍，即 $0.16 和 $0.48。Flex 是尽力而为档位，运行前最多可等待容量 10 分钟，否则返回 HTTP 429。被拒绝的请求从不触及模型，因此不会产生任何计费。

缓存输入 token 在 Standard 档为每 1M $0.006，Priority 为 $0.009，Flex 为 $0.0048——考虑到该架构本就是围绕输入密集、缓存密集的工作负载设计的，这是很可观的节省。

模型开箱支持 JSON mode、function calling 以及文本加图像的多模态输入。关于限制有一点实际提醒：1,048,576 token 的上下文窗口覆盖 prompt 与 completion 之和，而 DeepInfra 对多数模型将输出上限设为 16,384 token。DeepSeek 自己建议的 256K 生成预算适用于你自己跑权重的场景，不适用于共享端点。如果需要超过上限的输出，请使用响应续写：把上一段响应作为 assistant 消息发回去即可。

DeepInfra 提供即时 API 访问、无需管理任何基础设施：OpenAI 兼容端点、按用量计费，以及匹配你延迟需求的 Priority 和 Flex 吞吐档位。公司执行零保留政策（详见其[隐私政策](https://deepinfra.com/privacy)），并持有 SOC 2 与 ISO 27001 认证。实时在线率发布在 [DeepInfra 状态页](https://status.deepinfra.com)，平台背后是为扩展推理云而完成的 [$1.07 亿 B 轮融资](https://deepinfra.com/series-b)。

如果你在 V4.1-Flash 之外评估备选，[NVIDIA Nemotron-3-Super-120B-A12B](https://deepinfra.com/nvidia/NVIDIA-Nemotron-3-Super-120B-A12B) 和 [Gemma 4 31B](https://deepinfra.com/google/gemma-4-31B-it) 位于价格-能力曲线的不同位置。embeddings、语音、reranking 和图像模型等[其他 API 接口](https://docs.deepinfra.com/apis/completions)遵循同一套计费模式。

要发出第一个调用，换上你的 DeepInfra token 和模型名即可：

```
curl "https://api.deepinfra.com/v1/openai/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEEPINFRA_TOKEN" \
  -d '{
      "model": "deepseek-ai/DeepSeek-V4.1-Flash",
      "messages": [
        {"role": "user", "content": "Hello!"}
      ]
    }'
from openai import OpenAI
 
client = OpenAI(
    api_key="$DEEPINFRA_TOKEN",
    base_url="https://api.deepinfra.com/v1/openai",
)
 
response = client.chat.completions.create(
    model="deepseek-ai/DeepSeek-V4.1-Flash",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(response.choices[0].message.content)
import OpenAI from "openai";
 
const openai = new OpenAI({
  apiKey: "$DEEPINFRA_TOKEN",
  baseURL: "https://api.deepinfra.com/v1/openai",
});
 
const response = await openai.chat.completions.create({
  model: "deepseek-ai/DeepSeek-V4.1-Flash",
  messages: [{ role: "user", content: "Hello!" }],
});
console.log(response.choices[0].message.content);
```

相比任何现有的 OpenAI 兼容集成，只需要改三样东西：base URL（https://api.deepinfra.com/v1/openai）、你的 DeepInfra API key，以及模型名。

## 结语

DeepSeek-V4.1-Flash 是一个真正有意思的工程成果：在大幅削减激活参数量与 KV cache 占用的同时，把基准分数推向正确的方向。这些架构选择不是表面文章——CED 设计与 CSA2 压缩对大规模运行长智能体会话的成本有直接影响。对于构建代码智能体、自主流水线，或任何依赖大上下文与高频缓存命中的开发者，这个模型应该进入你的评测队列。

领一个 API key，跑一遍上面的 curl 调用，在你自己的工作负载上与目前使用的模型对比，而不是只看基准表。基于 DeepInfra 构建的早期团队还可以申请 DeepStart 计划获取免费推理额度。
