# IBM Granite 4.2 8B 现已上线 DeepInfra

DeepInfra 发布于 2026.10.17

![IBM Granite 4.2 8B 现已上线 DeepInfra](https://deepinfrabldev.wpenginepowered.com/wp-content/uploads/2026/10/IBM-Granite-4.2-8B-Tech-Banner.png)

[Granite 4.2 8B](https://deepinfra.com/ibm-granite/granite-4.2-8b) 提供三种可选的推理模式：用 *<think>…</think>* 标签输出完整思维链、一条低投入的捷径，以及完全跳过推理的直接作答模式。

这让你可以按单次请求拿算力换延迟，而不用换模型权重。

它是 IBM 的 Granite 4.2 稠密推理家族里的中号成员，面向通用企业工作负载。

在 AIME 2025 上这个 8B 拿到 86.67，在 SWE-Bench Verified 上是 47.67。后一项对智能体编码能力往往比合成评测更是个诚实的信号。

推理能力来自一条三阶段训练管线：先在宽松许可的数据和合成数据上做监督微调，再用 GRPO 做多环境强化学习。

GRPO 那一段覆盖数学、代码、工具调用和[结构化输出](https://deepinfra.com/blog/json-mode)。

随后是一个面向有用性与安全的偏好对齐阶段。[工具调用](https://deepinfra.com/blog/deepinfra-function-calling-guide)是推理增强的，所以模型在真正调用之前会先想清楚该调哪个工具，用的是 OpenAI 的 function definition schema。

它以 Apache 2.0 许可发布，附带完整的透明度披露，原生支持 128K 上下文窗口。该模型于 2026 年 8 月 25 日在 IBM 的 GitHub 和 Hugging Face 上开放。

Granite 4.2 8B 已作为公开 API 端点上线 DeepInfra。

## **这款模型哪里不一样**

Granite 4.2 8B 是一个 decoder-only 的稠密 transformer，基于 GraniteForCausalLM 架构，由 Granite 4.1 8B Base 经一条三阶段管线后训练而来。

这条管线先做大规模预训练，然后在宽松许可的公开数据集、合成数据、智能体轨迹和人工精挑数据混合上做监督微调。

最后用 Group Relative Policy Optimization 做多阶段强化学习，覆盖数学、代码、科学、工具调用和指令跟随。

再往后是一个面向安全和对话质量的偏好对齐阶段。

架构上用了分组查询注意力，32 个注意力头配 8 个 KV 头，激活函数是 SwiGLU，归一化用 RMSNorm，RoPE 的基础频率是 10M。

这套配置在吞吐量与长上下文稳定性之间取平衡。

### **可选的推理模式**

按单次请求选推理档位，是这里比较实用的设计决定之一。模型没有把思维链做成常开，而是暴露三种模式：

- **Thinking（enable_thinking=True）：** 作答前输出完整的 *<think>…</think>* 思维链
- **Non-thinking（enable_thinking=False）：** 直接作答，不付推理开销
- **Low-effort（enable_thinking=True, low_effort=True）：** 面对较简单的请求只做简短推理

这样你可以按请求复杂度调节推理成本和延迟，而不必维护多份模型 checkpoint——在规模化的场景里这很要紧，也让部署更简单。

如果你想在本机跑这个模型，Ollama 上有量化版本 *ibm/granite4.2:8b-q3_K_M*。

也可以通过 HuggingChat 直接用这个模型，做快速试验不必搭任何基础设施。

### **长上下文与基准**

模型原生支持 128K 上下文窗口（序列长度 131,072 token），另有 512K 的长上下文扩展。在 RULER 长上下文基准上，这个 8B 在 64K 拿到 80.99、128K 拿到 71.41，对这个尺寸的模型来说是相当扎实的保持率。

基准方面，这个 8B 在推理和编码任务上都顶得住：

| **基准** | **分数** |
| --- | --- |
| AIME 2025 | 86.67 |
| GPQA | 64.14 |
| LiveCodeBench v6 | 73.24 |
| SWE-Bench Verified | 47.67 |
| MMLU-Pro | 74.04 |
| τ³-bench（AVG） | 58.06 |
| Arena-Hard-V2 | 65.19 |

IBM 的基准数据是自报的，所以在独立评测跟上之前，这些数字当作方向性参考，别当定论。

### **工具使用与部署**

工具调用是推理增强的：模型在调用之前先把工具选择推理想清楚，用的是 OpenAI 的 function definition schema。它已在 OpenCode、Pi、OpenHands 等智能体编码环境里验证过，并针对 vLLM（v0.20+）部署做了优化。多语言支持覆盖 12 种语言：英语、德语、西班牙语、法语、日语、葡萄牙语、阿拉伯语、捷克语、意大利语、韩语、荷兰语和中文。

## **在 DeepInfra 上上手**

Granite 4.2 8B 已作为公开 API 端点上线 DeepInfra。[计价](https://deepinfra.com/blog/pricing-101-token-math-cost-per-completion)按用量：每 100 万输入 token $0.06，每 100 万输出 token $0.25，每 100 万缓存 token $0.015。

DeepInfra 上的上下文窗口是 131,072 token，模型以 bfloat16 精度运行。JSON 输出和 function calling 都开箱支持。

DeepInfra 通过 OpenAI 兼容的 API 暴露 Granite 4.2 8B，所以没有新 SDK 要学，也没有基础设施要管。换掉 base URL 和模型名就能跑起来。

DeepInfra 执行零数据留存政策，并已通过 SOC 2 和 ISO 27001 认证。[API 参考](https://deepinfra.com/ibm-granite/granite-4.2-8b/api)里有支持的参数和请求格式的完整说明。

### **快速开始**

cURL:

```
curl https://api.deepinfra.com/v1/openai/chat/completions \

  -H "Authorization: Bearer $DEEPINFRA_TOKEN" \

  -H "Content-Type: application/json" \

  -d '{

    "model": "ibm-granite/granite-4.2-8b",

    "messages": [{"role": "user", "content": "Explain GRPO in two sentences."}]

  }'copy
```

Python:

```
from openai import OpenAI

client = OpenAI(

    api_key="$DEEPINFRA_TOKEN",

    base_url="https://api.deepinfra.com/v1/openai",

)

response = client.chat.completions.create(

    model="ibm-granite/granite-4.2-8b",

    messages=[{"role": "user", "content": "Explain GRPO in two sentences."}],

)

print(response.choices[0].message.content)

JavaScript:

import OpenAI from "openai";

const client = new OpenAI({

  apiKey: "$DEEPINFRA_TOKEN",

  baseURL: "https://api.deepinfra.com/v1/openai",

});

const response = await client.chat.completions.create({

  model: "ibm-granite/granite-4.2-8b",

  messages: [{ role: "user", content: "Explain GRPO in two sentences." }],

});

console.log(response.choices[0].message.content);copy
```

相对已有的 OpenAI 集成，你只需要改 base URL、API key 和模型名这三样。OpenAI 官方的 Python 和 Node.js 库不用改动就能用。

去 DeepInfra 上的 [Granite 4.2 8B 模型页](https://deepinfra.com/ibm-granite/granite-4.2-8b)可以试 API playground、看实时请求示例，然后开始构建。

## **结论**

Granite 4.2 8B 是一个工程做得扎实的 8B 模型，有几个设计决定在生产环境里是真有用的。按请求控制推理，对同时跑混合负载、延迟和成本随任务类型波动的团队来说是一个有分量的运维抓手。

Apache 2.0 许可、128K 原生上下文窗口和[推理增强的工具调用](https://deepinfra.com/blog/function-calling-feature)，让它成为智能体流水线一个靠得住的底座。

如果你在做编码助手、多步推理智能体或企业工作流自动化，它是一个体积小、可审计的选项。

不必为了拿到靠得住的工具调用而超配资源。

在 playground 里打第一次调用，或者把 Granite 4.2 8B 直接接进已有的 OpenAI 兼容集成。
