# IBM Granite 4.2 8B 现已在 DeepInfra 上提供

DeepInfra 发布于 2026.10.17

![IBM Granite 4.2 8B 现已在 DeepInfra 上推出](https://deepinfrabldev.wpenginepowered.com/wp-content/uploads/2026/10/IBM-Granite-4.2-8B-Tech-Banner.png)

[Granite 4.2 8B](https://deepinfra.com/ibm-granite/granite-4.2-8b) 附带三种可选推理模式：通过 *<think>...</think>* 标签的完整思维链、省力快捷方式以及完全跳过推理的直接回答模式。

这使您可以在每个查询的基础上用计算来换取延迟，而无需交换模型权重。

它是 IBM Granite 4.2 密集推理系列的中型成员，专为通用企业工作负载而构建。

在 AIME 2025 上，8B 得分为 86.67，在 SWE-Bench Verified 上得分为 47.67。与综合评估相比，后者往往是代理编码能力更诚实的信号。

推理能力来自三阶段训练流程：对许可数据和合成数据进行监督微调，然后通过 GRPO 进行多环境强化学习。

GRPO 阶段涵盖数学、代码、工具使用和[结构化输出](https://deepinfra.com/blog/json-mode)。

接下来是帮助性和安全性的偏好调整阶段。 [工具调用](https://deepinfra.com/blog/deepinfra-function-calling-guide) 是推理增强型的，因此模型会使用 OpenAI 的函数定义模式在调用之前思考要调用哪个工具。

它在 Apache 2.0 下发布，具有完全透明的披露，并支持本机 128K 上下文窗口。该模型于 2026 年 8 月 25 日在 IBM 的 GitHub 和 Hugging Face 上发布。

Granite 4.2 8B 可在 DeepInfra 上作为公共 API 端点使用。

## **这个模型有何不同**

Granite 4.2 8B 是一个基于 GraniteForCausalLM 架构的仅解码器密集变压器，通过三级管道从 Granite 4.1 8B Base 进行后训练。

该管道运行大规模预训练，然后对许可的公共数据集、合成数据、代理跟踪和精选的人类数据的组合进行监督微调。

它使用跨数学、代码、科学、工具使用和指令遵循的组相对策略优化进行多阶段强化学习。

接下来是安全和对话质量的偏好调整阶段。

该架构使用具有 32 个注意力头和 8 个 KV 头的分组查询注意力、SwiGLU 激活、RMSNorm 和基频为 10M 的 RoPE。

此设置平衡了吞吐量和长上下文稳定性。

### **可选择的推理模式**

每个查询的可选推理是这里更实用的设计决策之一。该模型没有致力于始终在线的思想链，而是公开了三种模式：

- **思考 (enable_thinking=True):** 完整的 *<think>...</think>* 回答之前的思考链
- **非思考（enable_thinking=False）：**直接回答，没有推理开销
- **低努力（enable_thinking=True，low_effort=True）：**简单查询的简要推理

这使您可以根据查询复杂性调整推理成本和延迟，而无需维护单独的模型检查点，这在规模上很重要并简化了部署。

如果您想在本地运行模型，*ibm/granite4.2:8b-q3_K_M* 可在 Ollama 上作为量化构建使用。

该模型还可以直接通过 HuggingChat 访问，以便快速进行实验，无需任何基础设施设置。

### **长上下文和基准**

该模型原生支持 128K 上下文窗口（序列长度为 131,072 个标记），并提供 512K 长上下文扩展。在 RULER 长上下文基准测试中，8B 在 64K 时得分为 80.99，在 128K 时得分为 71.41，对于这种尺寸的型号来说，保持力很不错。

在基准测试中，8B 在推理和编码任务中表现良好：

| **基准** | **分数** |
| ---| ---|
| AIME 2025 | 86.67 |
| GPQA | 64.14 |
| LiveCodeBench v6 | 73.24 | 73.24
| SWE-Bench 验证 | 47.67 | 47.67
| MMLU-专业版 | 74.04 |
| τ3-长凳 (AVG) | 58.06 | 58.06
| Arena-Hard-V2 | 65.19 | 65.19

IBM 的基准是自我报告的，因此在独立评估赶上之前，请将这些数字视为方向性而非确定性的。

### **工具使用和部署**

工具调用是推理增强的：模型在调用之前通过工具选择进行推理，使用 OpenAI 的函数定义模式。它已通过包括 OpenCode、Pi 和 OpenHands 在内的代理编码环境进行验证，并针对通过 vLLM (v0.20+) 进行部署进行了优化。多语言支持涵盖 12 种语言：英语、德语、西班牙语、法语、日语、葡萄牙语、阿拉伯语、捷克语、意大利语、韩语、荷兰语和中文。

## **DeepInfra 入门**

Granite 4.2 8B 可在 DeepInfra 上作为公共 API 端点使用。 [定价](https://deepinfra.com/blog/pricing-101-token-math-cost-per-completion) 基于使用情况：每 100 万个输入代币 0.06 美元，每 100 万个输出代币 0.25 美元，每 100 万个缓存代币 0.015 美元。

DeepInfra 上的上下文窗口有 131,072 个 token，模型以 bfloat16 精度运行。 JSON 输出和函数调用都是开箱即用的。

DeepInfra 通过 OpenAI 兼容的 API 公开 Granite 4.2 8B，因此无需学习 SDK，也无需管理基础设施。交换你的基本 URL 和模型名称，然后你就可以运行了。

DeepInfra 采用零数据保留政策，并通过了 SOC 2 和 ISO 27001 认证。 [API 参考](https://deepinfra.com/ibm-granite/granite-4.2-8b/api) 包含支持的参数和请求格式的完整细分。

### **快速入门**

卷曲：
```
curl https://api.deepinfra.com/v1/openai/chat/completions \

  -H "Authorization: Bearer $DEEPINFRA_TOKEN" \

  -H "Content-Type: application/json" \

  -d '{

    "model": "ibm-granite/granite-4.2-8b",

    "messages": [{"role": "user", "content": "Explain GRPO in two sentences."}]

  }'copy
```
Python：
```
from openai import OpenAI

client = OpenAI(

    api_key="$DEEPINFRA_TOKEN",

    base_url="https://api.deepinfra.com/v1/openai",

)

response = client.chat.completions.create(

    model="ibm-granite/granite-4.2-8b",

    messages=[{"role": "user", "content": "Explain GRPO in two sentences."}],

)

print(response.choices[0].message.content)

JavaScript:

import OpenAI from "openai";

const client = new OpenAI({

  apiKey: "$DEEPINFRA_TOKEN",

  baseURL: "https://api.deepinfra.com/v1/openai",

});

const response = await client.chat.completions.create({

  model: "ibm-granite/granite-4.2-8b",

  messages: [{ role: "user", content: "Explain GRPO in two sentences." }],

});

console.log(response.choices[0].message.content);copy
```
您需要从现有 OpenAI 集成中更改的唯一内容是基本 URL、API 密钥和模型名称。官方 OpenAI Python 和 Node.js 库无需修改即可运行。

前往 DeepInfra 上的 [Granite 4.2 8B 模型页面](https://deepinfra.com/ibm-granite/granite-4.2-8b) 探索 API 游乐场、查看实时请求示例并开始构建。

## **结论**

Granite 4.2 8B 是一款精心设计的 8B 型号，其中有一些在生产中实际重要的设计决策。对于运行混合工作负载的团队来说，每个查询推理控制是一种有意义的操作杠杆，其中延迟和成本因任务类型而异。

Apache 2.0 许可、128K 本机上下文窗口和[推理增强工具调用](https://deepinfra.com/blog/function-calling-feature) 使其成为代理管道的可靠基础。

如果您正在构建编码助手、多步骤推理代理或企业工作流程自动化，那么它是一个紧凑的、可审计的选项。

它不需要为了获得一致的工具使用而进行过度配置。

在 Playground 中运行您的第一个调用，或者将 Granite 4.2 8B 放入现有的 OpenAI 兼容集成中。
