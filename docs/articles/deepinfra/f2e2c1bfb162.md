# 小型开放权重模型：隐藏的成本优势

Qwen3.8-27B 以 1,595 分位列 [Arena.ai Code Arena WebDev 榜第 9 名](https://x.com/arena/status/2091920512796725272)，截至 2026 年 9 月，它是前十名中唯一参数量低于 300 亿的模型。同一年发布、又大三十亿参数的 Gemma 4-31B 排在第 80。比 27B 高三位的是 Qwen3.8-2.4T-A95B——参数量是它的 86 倍的同门模型（A95B 后缀指的是每个 token 实际运行的 950 亿参数；本文剩下的部分就在讲为什么这个区别决定了价格）。

关于开放模型的大部分报道只追踪一道差距：最大的开放权重离 GPT 和 Claude 有多近。而小型开放权重模型一直在收窄另一道少有人注意的差距：一个 GPU 装得下的模型，与需要一整柜的模型之间的距离。

更小、更高效的模型本应运行得更便宜。然后你打开价目表：在 DeepInfra 上，Qwen3.8-27B 每百万输出 token 收 $3.00，而 Gemma 4-31B 只要 $0.38——它反而是更大的那个模型。想找回那份效率红利，按 token 单价是最不该看的地方。

## 小型开放权重模型真正缩小的那道差距

Epoch AI 统计，自 2026 年 1 月以来，最佳开放权重模型与前沿闭源模型在[其 Capabilities Index 上的滞后是四个月](https://epoch.ai/data-insights/open-closed-eci-gap)。英国 AI Safety Institute 测得[网络安全能力上 4 到 7 个月](https://www.aisi.gov.uk/blog/how-far-behind-the-frontier-are-leading-open-weight-models-on-cyber)的差距，低于其在 2025 年发布的开放模型身上看到的 6 到 10 个月。这个故事已被充分报道，DeepInfra 也写过[自己对开放 vs. 闭源差距的解读](https://deepinfra.com/blog/open-vs-closed-source-ai-models)，覆盖智能、价格与速度。

另一条轴得到的关注少得多。Hugging Face 的[开放模型状况报告](https://huggingface.co/blog/state-of-open-models-summer-2026)给出中国模型的月度参数上限在 7,540 亿到 2.78 万亿之间，而美国模型在七个月里有五个月停留在 1,300 亿以下。阿里巴巴同时在这区间的两端出货：它发布前沿规模的权重，也发布一个在智能体编码上力压大部分参赛者的 27B。同一份报告统计 Hub 上有 151,448 个 Qwen 衍生仓库，每天增长 180 到 210 个——这就是一个有真实需求支撑的规模档位该有的样子。

如果你是做推理服务的而不是读排行榜的，第二道差距才是沾着钱的那道。四月的能力滞后决定你选哪个模型。而一个排名第 9 的 27B 决定你签哪张硬件账单。

按价格排序，规模次序就塌了。gpt-oss-120b 的参数量是 Qwen3.8-27B 的四倍，输出价却只有十七分之一。Qwen3.8-27B 与规模十四倍的 Qwen3.5-397B-A17B 定价完全相同。最刺眼的一对排在中间：Gemma 4-31B 是稠密模型、更大，每输出 token 却比在 Code Arena 上领先它 71 个名次的那个 27B 便宜 7.9 倍，其[完整定价与基准拆解](https://deepinfra.com/blog/gemma-4-pricing-benchmarks-cost-scenarios)走遍了该家族的其余成员。

按参数量购物，等于在读一列并不能预测账单的数字。

## 决定单 token 价格的是两个旋钮，都不是模型规模

输出一个 token，意味着把激活权重从 GPU 内存中读出来，而这次读取主导了解码成本。所以第一个旋钮是激活参数，不是总参数。gpt-oss-120b 每 token 触碰其 1,170 亿参数中的 51 亿——这个数字 [DeepInfra 就写在模型页上](https://deepinfra.com/openai/gpt-oss-120b)。Qwen3.8-27B 是稠密的，所以要触碰全部 278 亿，同一次前向传播的内存流量约为五倍半。

另一个旋钮是服务精度，DeepInfra 也逐模型公布。Gemma 4 基于同一份权重提供三种变体：[$0.09 输入、$0.34 输出的 fp4 turbo](https://deepinfra.com/google/gemma-4-31B-it-turbo)，[$0.13 和 $0.38 的 fp8](https://deepinfra.com/google/gemma-4-31B-it)，以及 [$0.27 和 $0.76 的 fp8 Ultra 档](https://deepinfra.com/google/gemma-4-31B-it-Ultra)。每个参数更少的字节就意味着更少的搬运，价目表如实反映这一点。

两个旋钮都可以直接从目录里读出来：

```
import json, urllib.request

CATALOG = "https://api.deepinfra.com/models/list"
WATCH = {
    "Qwen/Qwen3.8-27B",
    "google/gemma-4-31B-it",
    "google/gemma-4-31B-it-turbo",
    "openai/gpt-oss-120b",
}

with urllib.request.urlopen(CATALOG) as resp:
    catalog = json.load(resp)

for m in catalog:
    if m["model_name"] not in WATCH:
        continue
    p = m["pricing"]
    dollars_in = p["cents_per_input_token"] * 10_000
    dollars_out = p["cents_per_output_token"] * 10_000
    cached = dollars_in * (p["rate_per_input_token_cached"] or 1.0)
    print(
        f"{m['model_name']:30} {m['quantization'] or 'unquantized':12}"
        f" in ${dollars_in:.3f}  cached ${cached:.3f}  out ${dollars_out:.2f}"
    )
```

Qwen3.8-27B 那一行返回的 quantization 为空。DeepInfra 没有为它公布服务精度，所以诚实的假设是你拿到的接近阿里巴巴发布的那份权重——也就是在榜单上得分的那个文件。这是假设，不是规格。

两个旋钮合起来解释的是下限，而不是整个价差。在假定 bf16 下，Qwen3.8-27B 每 token 前向搬运约 56 GB 权重，而 Gemma 4-31B 在 fp8 下是 31 GB——1.8 倍的硬件差距，压在 7.9 倍的价格差距之下。剩余部分来自需求、工作负载形态和利润率。推理模型的账单记在输出通道上，而一个被指向长 agent 运行的模型每请求输出的 token 远多于通用 instruct 模型。价目表是一份价格清单，不是效率计。

## 27B 这个档位同时变好也变贵了

阿里巴巴已经连续三代填补同一个规模档位，同样的 262K 上下文，同一个端点。

| **模型** | **DeepInfra 上线时间** | **输入/1M** | **输出/1M** | **缓存输入** | **服务精度** |
| --- | --- | --- | --- | --- | --- |
| [Qwen3.5-27B](https://deepinfra.com/Qwen/Qwen3.5-27B) | 2026-03-24 | $0.26 | $2.60 | n/a | fp8 |
| [Qwen3.6-27B](https://deepinfra.com/Qwen/Qwen3.6-27B) | 2026-04-30 | $0.32 | $3.20 | n/a | fp8 |
| [Qwen3.8-27B](https://deepinfra.com/Qwen/Qwen3.8-27B) | 2026-08-17 | $0.40 | $3.00 | $0.04 | 未标注 |

输入价在五个月里爬升了 54%。如果效率红利以更低单 token 价的形式到来，本该在这一行显现——但它没有。DeepInfra 的 [Qwen3.5 27B 基准实测](https://deepinfra.com/blog/qwen3-5-27b-api-benchmarks)测得那一代输出 153.3 tokens/秒、按其输入输出配比混合下来 $0.84/百万——老模型仍然是搬运 token 的更便宜方式。

多花的那 14 美分买到的，是一个顶着相同参数数的不同模型：视觉输入、262K 的混合 attention，以及可以关掉的 thinking。混合 attention 意味着多数层用线性 attention、每隔若干层才有一次全量 attention，因此通常主导长上下文内存的 KV cache 保持很小。目录给 Qwen3.8-27B 打了 can-disable-reasoning 标签，而 [DeepInfra 的推理文档](https://docs.deepinfra.com/chat/reasoning)对这一点的重要性说得很直白：推理 token 计入输出 token 计费。在 $3.00/百万的价位上，这个模型的第一道成本控制，是逐请求决定你到底需不需要那段思考。

```
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["DEEPINFRA_API_TOKEN"],
    base_url="https://api.deepinfra.com/v1/openai",
)

# Ticket triage does not need a chain of thought. Switching reasoning off
# keeps the output lane, the expensive one, from carrying tokens you pay
# for and never read.
resp = client.chat.completions.create(
    model="Qwen/Qwen3.8-27B",
    messages=[
        {"role": "system", "content": "Label the ticket: bug, billing, or feature."},
        {"role": "user", "content": ticket_text},
    ],
    extra_body={"reasoning_effort": "none"},
    max_tokens=8,
)
print(resp.choices[0].message.content, resp.usage.completion_tokens)
```

## 真正动过的数字是"每个完成任务的成本"

Engram 和 Harvey 搭了一个合成律所：9,286 份文件、266 个客户案件、跨一亿 token，然后用参数化记忆（把领域知识烤进权重，而不是查询时再去取）和检索增强对 Qwen3.8-27B 做了适配。在严格的全对才算对的评分下，适配后的 27B [击败了 Claude Opus 4.8，30% 对 25%](https://engram.com/blog/legal-agents-with-memory)，约 $0.13/查询对 $1.32。完成任务轨迹中的 token 数下降了 58%。

小字要读清楚：那是领域语料上的微调模型，不是原装端点，差距有一部分属于适配本身。但机制仍然可迁移：用更少轮次完成的模型计费的 token 更少，而轮次正是智能体成本栖息的地方。

给一个真实的循环标个价，形态就显现了。假设每任务 12 轮、一个保持稳定的 6,000 token 系统与工具前缀、每轮 1,500 个新对话 token、每轮 700 个输出 token。前缀只在第一轮按全新计费，之后搭缓存跑完其余十一轮：即每任务 24,000 个全新输入、66,000 个可缓存 token、8,400 个输出 token。这个工作负载刻意只缓存静态前缀；真实 agent 还会累积对话历史，让缓存份额更高，所以下表按保守情形处理。

| **模型** | **缓存输入** | **全新输入** | **输出** | **每 1,000 个任务** |
| --- | --- | --- | --- | --- |
| [gemma-4-31B-it](https://deepinfra.com/google/gemma-4-31B-it) | $8.58 | $3.12 | $3.19 | **$14.89** |
| [Qwen3.8-27B](https://deepinfra.com/Qwen/Qwen3.8-27B) | $2.64 | $9.60 | $25.20 | **$37.44** |
| [Qwen3.8-2.4T-A95B](https://deepinfra.com/Qwen/Qwen3.8-2.4T-A95B) | $13.20 | $48.00 | $50.40 | **$111.60** |

估算基于 DeepInfra 实时费率与上述工作负载。你的轮次数才是关键变量。

两点结论浮现：在推理模型上，输出才是决定账单的通道，而缓存只碰得到另一条通道；以及这个 27B 走完同一条轨迹，只花其 2.4T 同门（在编码榜上高六名）三分之一的钱。更便宜的那一级能否一轮关掉你的任务，是一个测量问题，不是假设——这正是下面的插桩要做的。

别猜，装上仪表：

```
PRICES = {  # USD per million tokens, live DeepInfra rates
    "Qwen/Qwen3.8-27B": {"fresh": 0.40, "cached": 0.04, "out": 3.00},
    "google/gemma-4-31B-it": {"fresh": 0.13, "cached": 0.13, "out": 0.38},
}

def turn_cost(model: str, usage) -> float:
    p = PRICES[model]
    details = getattr(usage, "prompt_tokens_details", None)
    cached = getattr(details, "cached_tokens", 0) or 0
    fresh = usage.prompt_tokens - cached
    return (
        fresh * p["fresh"] + cached * p["cached"] + usage.completion_tokens * p["out"]
    ) / 1_000_000

spent, turns = 0.0, 0
for turn in run_agent(task):  # one chat.completions call per turn
    spent += turn_cost(turn.model, turn.usage)
    turns += 1

print(f"{task.id}: {turns} turns, ${spent:.4f}, ${spent / max(turns, 1):.4f} per turn")
```

## 每一个"能在家里跑"声明背后的量化星号

拿到第九名的那个 Qwen3.8-27B 是一个 55.58 GB 的 BF16 checkpoint。权重并不是账单的全部：它的 64 层里只有 16 层跑全量 attention，这让 KV cache 在完整 262K 上下文下只有 16 GiB，而[实际下限约在 67.8 GiB](https://kingy.ai/blog/qwen3-8-27b-specs-benchmarks-local-hardware)——意味着一张 80GB 卡或几张较小的卡拼起来。能塞进 24GB 消费级 GPU 的构建是 17.11 GB 的 Q4_K_M GGUF，而且很多人跑得更小。

这个区别在本地推理成本的论据里做着安静的工作。一份[被广泛转载的实测流程](https://www.youtube.com/watch?v=3WbXyUolFA0)测得 Q3 量化在消费级卡上 41 tokens/秒，按 250W、每千瓦时 21 美分计价，得出约 0.37 美分/百万输出 token，对比 $3.00 的端点费率。算术成立。范围却很窄：只算电费、一次一条流、跑在一个体积约为得分文件四分之一大小的模型上。

量化损失是可测量的，不是理论。同一份实测流程把 Kullback-Leibler 散度——量化模型的 next-token 分布与原版的差距——对照社区构建的文件大小画了曲线。Q3_K_M 落在 0.07 附近，约是上一档 Q4 构建散度的三倍。那个模型在负载下会做出不同的选择，把它称作"打折的同一份权重"低估了改变的程度。

这就是价格表中那个"未标注"格子值得多看一眼的原因。服务精度是一个你在把流量指过去之前可以逐模型核查的变量。

## 在小型开放权重模型的层级之间路由

一旦"每个任务的成本"成为指标，模型选择就从应用层决策变成逐步骤决策。两个杠杆干掉了大部分工作：上下文缓存与模型路由。

上下文缓存优先。DeepInfra 自动匹配 prompt 前缀并在 usage 对象里报告命中，你要做的是编排消息列表、让稳定的内容排前面。在 Qwen3.8-27B 上，这把 $0.40 的输入变成 $0.04，而每轮重发工具 schema 的 agent 是最受益的形态。

```
SYSTEM = TOOL_SCHEMAS + HOUSE_STYLE  # stable for the life of the run

resp = client.chat.completions.create(
    model="Qwen/Qwen3.8-27B",
    messages=[
        {"role": "system", "content": SYSTEM},  # stable prefix first
        *history,                               # then whatever changed
        {"role": "user", "content": step},
    ],
    extra_body={"prompt_cache_key": f"agent-{task.id}"},
)
d = resp.usage.prompt_tokens_details
print(f"{d.cached_tokens}/{resp.usage.prompt_tokens} prompt tokens came from cache")
```

模型路由次之。从便宜档起步、做校验、只在失败时升级。每一级共享同一个 base URL 和 key，所以一级就是一个字符串：

```
LADDER = [
    ("google/gemma-4-31B-it", {"reasoning_effort": "none"}),
    ("Qwen/Qwen3.8-27B", {"reasoning_effort": "medium"}),
    ("Qwen/Qwen3.8-2.4T-A95B", {"reasoning_effort": "high"}),
]

def solve(messages, passes):
    for model, opts in LADDER:
        resp = client.chat.completions.create(
            model=model, messages=messages, extra_body=opts
        )
        answer = resp.choices[0].message.content
        if passes(answer):
            return model, answer
    raise RuntimeError("no rung produced a valid answer")
```

只有便宜档能足够频繁地达标，这架梯子才划算。多频繁？这是个逐工作负载的测量问题。把每一级完成任务的记录与上一节的逐轮成本一起打点，升级率就变成你能据以行动的数。如果最高级关闭了大多数任务，这架梯子买到的只是延迟，别无其他——那就从最高级起步。反正换一级只值一个字符串的成本，因为三个模型都在同一个 OpenAI 兼容端点后面。DeepInfra 自己的[路由与缓存节省拆解](https://deepinfra.com/blog/openclaw-cost-optimization-cut-api-costs-90-percent)为编码智能体走过同一模式，[Qwen 价目表](https://deepinfra.com/blog/qwen-api-pricing-2026-guide)则为可能放上梯子的家族其余成员标价。

## 常见问题

### Qwen3.8-27B 真的比 Gemma 4-31B 强吗？

在编码与智能体工作上，是的。Qwen3.8-27B 报告 [LiveCodeBench v6 得 90.3，Gemma 4-31B 为 80.0](https://llm-stats.com/models/compare/gemma-4-31b-it-vs-qwen3.8-27b)，而第 9 与第 80 的对比出自 WebDev 编码榜，不是综合排名。Gemma 4-31B 在 AIME 2026 和 MMLU 上得分更高，每输出 token 还便宜一个数量级。按工作负载选择。

### 我能在 24GB GPU 上跑 Qwen3.8-27B 吗？

能，以更低的精度和更短的上下文。Q4_K_M GGUF 为 17.11 GB，在 24GB 卡上还能给 32K 到 64K token 的缓存留出空间。仅完整 BF16 权重就要 55.58 GB，原生 262K 上下文下的 KV cache 再加 16 GiB，把需求推高到约 67.8 GiB。

### 关闭推理会损害回答质量吗？

它改变的是模型成为什么。[DeepInfra 的文档](https://docs.deepinfra.com/chat/reasoning)指出，禁用推理会让推理模型表现得像标准聊天模型。对分类、抽取和路由，那通常正是你想要的行为，更便宜的账单是白捡的。对多步规划和仓库规模的编码，thinking 正是 Qwen3.8-27B 报告的提升的来源。

### 要做什么才能拿到缓存输入价吗？

不用。DeepInfra 上[前缀缓存是自动的](https://docs.deepinfra.com/chat/prompt-caching)，无需额外参数。把 prompt 组织成稳定内容在前，然后从 usage 对象读 prompt_tokens_details.cached_tokens 确认命中。可选的 prompt_cache_key 参数能提高相似 prompt 之间的命中率。

### Qwen3.8-27B 用什么许可证发布？

[Apache 2.0](https://huggingface.co/Qwen/Qwen3.8-27B)，允许商用与自托管。在这个规模档位，这如今已是常态而非例外：今年参数量超 200 亿的 178 个中国发布中，[59% 采用 Apache 2.0，22% 采用 MIT](https://huggingface.co/blog/state-of-open-models-summer-2026)。

## 这会如何改变你的模型选择器

小型开放权重模型今年缩小了一道真实的差距，而价目表是量它的错误仪器。单 token 价格用激活参数和服务精度设了个下限；需求与工作负载决定下限之上的一切。真正掉下来的是完成一份工作所需的 token 数，而只有当你按任务而非按 token 计量时它才显形。

把整个规模区间跑在同一个 OpenAI 兼容端点后面，正是让这件事可测量的原因，因为比较两级只值一个字符串的改动。从 [Qwen3.8-27B 模型页](https://deepinfra.com/Qwen/Qwen3.8-27B)起步看实时定价，或浏览[开放权重目录](https://deepinfra.com/models)看清整架梯子。欢迎到 [feedback@deepinfra.com](mailto:feedback@deepinfra.com)、[Discord](https://discord.gg/deepinfra) 或 @DeepInfra 告诉我们你的升级率长什么样。
