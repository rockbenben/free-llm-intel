# GLM-5.3-Flash 定价、提供方与成本

[GLM-5.3-Flash](https://deepinfra.com/zai-org/GLM-5.3-Flash) 是 Z.ai 在 GLM-5 家族下的模型，于 2026 年 8 月 26 日发布。它是一个原生多模态模型，接受文本和图像输入（包括 [OpenRouter](https://openrouter.ai/z-ai/glm-5.3-flash) 在内的部分列表还注明支持视频），输出为文本。Artificial Analysis 与 DeepInfra 都把它描述为 320B 参数的 mixture-of-experts 模型、每次推理激活 18B 参数；DeepInfra 的列表还注明 fp4 精度。模型以开放权重发布于 [Hugging Face](https://huggingface.co/zai-org/GLM-5.3-Flash)，采用 MIT 许可——这对日后可能想自托管的团队来说，改变了自建与外购的对话格局。

让 GLM-5.3-Flash 脱颖而出的是，它的经济性不是以牺牲能力换来的。Artificial Analysis 给它 Intelligence Index 42 分（远高于同类开放权重模型 18 的中位数）；OpenRouter 引用的 Artificial Analysis 数据为 41.8，同时给出 Coding Index 71.5、Agentic Index 50.9。它还支持大上下文窗口：Artificial Analysis 与 DeepInfra 标为 1M tokens，OpenRouter 上为 1,310,720 tokens。

对开发者和 ML 团队来说，实际问题不是模型有没有意思，而是它在哪儿运行才在运维上说得通。它的 API 可得性很广：Artificial Analysis 记录 20 个提供方，OpenRouter 上 31 个，加上 DeepInfra 的公有和私有部署路径。需要一开始就明白的权衡是：GLM-5.3-Flash 便宜，但也明显慢且啰嗦——Artificial Analysis 测得输出 55.9 tokens/秒（同类中位数 85.4），评测期间消耗 1.8 亿输出 token（中位数 1.4 亿）。如果你对成本敏感、在做编码智能体，或规划上下文长度和缓存定价很重要的 RAG 与文档密集系统，这个模型值得一份认真的定价审查，而不是匆匆一瞥。

## **GLM-5.3-Flash 执行摘要**

对一个大型开放权重推理模型来说，GLM-5.3-Flash 所处的价格带竞争激烈得不同寻常。标准定价为每 1M tokens 输入 $0.15 / 输出 $0.50；[DeepInfra](https://deepinfra.com/zai-org/GLM-5.3-Flash) 挂出 $0.075 / $0.25 / 缓存 $0.015 的折扣价；[OpenRouter](https://openrouter.ai/z-ai/glm-5.3-flash) 上各家提供方价格从约 $0.045 / $0.14 / $0.01 到最高 $0.30 / $1.00 / $0.03 不等。它最适合这样一类开发者：要构建编码智能体、长上下文助手和文档密集系统，希望拥有开放权重、多模态支持，并能在 DeepInfra、OpenRouter 路由提供方与直连 Z.ai 之间自由选择。

| **最适合** | **提供方推荐** | **原因** |

| RAG、文档密集或高吞吐用例 | DeepInfra | DeepInfra 把折扣定价与公共 API、私有部署选项、JSON 输出、function calling、多模态输入和约 1M token 上下文窗口结合在一起 |

## **Token 与计费方式**

GLM-5.3-Flash 的 token 定价纸面上简单，实践中很容易被低估。输入 token、输出 token 分开付费，有时缓存输入 token 又是一个价。对这个模型，这种拆分很要紧：输出侧比输入侧贵得多，而且模型据说相当啰嗦。

Token 是一段文本块，不是一个词。短词可能就是一个 token；长词、标点、代码、JSON 和空白模式的切法各不相同。图像等多模态输入在幕后也会被换算成计费单位，即使各提供方并不总以同样的方式呈现。做预算时唯一稳妥的假设是：长 prompt 要钱，长回答更贵，重复上下文则可能便宜也可能昂贵，取决于缓存行为。

| **Token 类型** | **是什么** | **为什么重要** |
| --- | --- | --- |
| 输入 token | 你的 prompt、system 消息、聊天记录、工具 schema、检索到的文档以及发给模型的一切文本 | 每个请求的基础成本。对 GLM-5.3-Flash，输入相对便宜，利好长上下文与 RAG 工作负载 |
| 输出 token | 模型生成回来的一切：答案、代码、推理、JSON、工具参数、摘要 | 成本容易在这里跳升。GLM-5.3-Flash 的输出价是输入的 3 倍多，而且据说啰嗦，放任的 prompt 能很快变贵 |
| 缓存输入 token | 提供方识别出并缓存供给、不按全额输入价计费的复用 prompt 内容 | 这是让重复大 prompt 可行的杠杆。如果你的应用复用 system prompt、长指令或稳定的文档前缀，缓存定价能实质性削减支出 |

Z.ai 标准定价中 GLM-5.3-Flash 常见挂出的费率：

- 输入：每 1M tokens $0.15
- 输出：每 1M tokens $0.50
- 缓存输入：每 1M tokens $0.03，有折扣时更低

实际解读：输入便宜到让大上下文 prompting 变得现实；输出是成本风险所在，因为它是输入费率的 3 倍多；对 agent 循环、长 system prompt 和重发大共享上下文的 RAG 流水线来说，缓存极其重要。

Artificial Analysis 报告 Z.ai API 有 83% 缓存折扣，并按缓存命中/输入/输出 7:2:1 的配比算得 $0.10/1M tokens 的混合费率。这个混合数有用，因为它反映生产系统的常见形态：重复的指令、重复的对话脚手架、稳定的检索上下文前缀，加上相对少量的新生成输出。

麻烦在于 GLM-5.3-Flash 被报告为非常啰嗦：Artificial Analysis 说它评测期间生成了 1.8 亿输出 token，同类模型中位数为 1.4 亿。如果你不限制补全长度、不收紧 prompt、不控制工具和结果的格式，输出支出能把便宜输入的收益抹干净。

对该模型的构建者来说，token 纪律比平常更重要：

- 设置保守的 max_tokens
- 尽可能优先使用结构化输出
- 避免索要 chain-of-thought 式的长篇大论
- 保持工具 schema 紧凑
- 采用对缓存友好的 prompt 布局
- 聊天记录不再有帮助时果断裁剪

## **改变 token 成本的提供方差异**

GLM-5.3-Flash 的 token 账本取决于你在哪里运行它。模型本身一样，但提供方的定价、缓存处理和路由行为对账单的影响，比任何微小的基准差距都大。

| **提供方路径** | **token 成本优势** | **token 成本劣势** |
| --- | --- | --- |
| DeepInfra | 研究资料中明确标注的最低公开折扣价之一：每 1M tokens $0.075 输入 / $0.25 输出 / $0.015 缓存输入。非常适合能从廉价缓存读取中受益的长上下文应用。公有与私有部署选项对日后想要更多支出控制权的也有帮助 | 折扣价未必永久。输出为主的费率结构照旧，输入便宜不会让啰嗦的生成自动变得便宜 |
| OpenRouter 折扣提供方 | 若干 OpenRouter 在列的提供方达到甚至优于 DeepInfra 的折扣价；撰稿时最低挂牌约 $0.045 输入 / $0.14 输出 / $0.01 缓存读取。想用一个 API 又享受降价时很有用 | 路由平台会让成本追踪更乱。实际提供方选择、路由模式和回退行为都会影响你付多少、以及这笔支出有多可预测 |
| OpenRouter 提供方市场 | 31 个在列提供方的充分竞争。想寻找性价比甜点位而不是接受某个默认端点时很好 | 提供方价格差异巨大：高端（Cloudflare）可达约 $0.30 输入 / $1.00 输出 / $0.03 缓存读取。不锁定提供方、不盯着路由行为，"同一个模型"会悄悄变成一张很不一样的账单 |
| Z.ai 直连/标准挂牌价 | $0.15 输入 / $0.50 输出的直接参考价。比较路由或折扣选项究竟省没省钱时，是良好基线 | 标准价明显高于 DeepInfra 与 OpenRouter 暴露的折扣价。如果成本是第一过滤器，除非你明确需要直连厂商，全额挂牌价很难自圆其说 |
| 自托管开放权重 | 模型是 MIT 许可、权重公开可得，你不会被永远锁在按 token 计费的 API 里。在持续高用量或利用率稳定的私有工作负载下，这会开始有吸引力 | token 价格消失了，但基础设施成本登场了。对一个 320B MoE、激活 18B 的模型，托管经济学不是闹着玩的：容量规划、GPU 利用率、延迟调优和运维开销取代了按 token 计费的简单 |

提供方相关的成本主线相当清楚：

- DeepInfra 和 OpenRouter 上最便宜的在列提供方，是研究资料里点名的最低公共 API 选项
- OpenRouter 的市场给了灵活性，而灵活性正是账单惊喜溜进来的门缝
- 直连标准价应被当作基线，而不是便宜
- 自托管只有当你的用量和运维成熟度足以跑赢 API 经济学时才成立

如果 token 成本优先，大致排序是：打折后的 DeepInfra 或 OpenRouter 折扣挂牌，然后较低价的 OpenRouter 提供方，然后标准挂牌价，最后是在真实利用率分析之后才谈自托管。

如果你的工作负载输出密集，Prompt 管控比选提供方更重要：模型在大规模地持续生成长答案时，输入省的那几厘钱帮不上忙；在每条提供方路径上，输出 token 仍然是预算漂移最可能的来源。

如果你的工作负载对缓存友好——重复的 system prompt、长静态指令、可复用的检索上下文、脚手架稳定的 agent 框架——提供方选择就更重要。$0.015 的缓存输入对全价输入的差别会开始起作用，尤其在使用长上下文、prompt 骨架比新用户的消息大得多的时候。

## **DeepInfra：GLM-5.3-Flash 的高阶用户之选**

DeepInfra 之所以突出，是因为它专为在乎价效比、而不仅仅是好拿到的团队而建。按 [DeepInfra 自己的说法](https://deepinfra.com/about)，公司创始团队有超大规模后端基础设施经验（曾构建并运营 imo 即时通讯应用背后的基础设施），其推理栈是从 GPU 硬件起自研，而不是在通用云上叠一层。对 GLM-5.3-Flash，这种基础设施专注配上激进的公开折扣价。如果你是开发者、高用量 API 用户，或一个想推大 token 量又不想多付钱的成本敏感团队，这是值得早早列入候选名单的提供方。

| **模型名** | **最佳用例** | **上下文窗口** | **输入价（每 1M tokens）** | **输出价（每 1M tokens）** |
| --- | --- | --- | --- | --- |
| GLM-5.3-Flash | 长上下文助手、编码智能体、多模态应用 | 1,048,576 tokens | $0.075 | $0.25 |

为何重要：在 DeepInfra 上，GLM-5.3-Flash 为每 1M 输入 token $0.075、每 1M 输出 token $0.25，而其标准挂牌是输入 $0.15、输出 $0.50——两侧直接砍半——缓存输入降到每 1M token $0.015。如果你的工作负载量大、重复或对缓存友好，这个价差会迅速累积。

对高用量或成本敏感的部署，DeepInfra 是你在别处按标准价付费之前应该先测的提供方。如果 GLM-5.3-Flash 在你的候选名单上，这是最快地验证真实经济性的地方之一，投入生产流量前可在[该模型的 DeepInfra 页面](https://deepinfra.com/zai-org/GLM-5.3-Flash)确认实时可用性与定价。

## **面向开发者的真实成本场景**

以下是 DeepInfra 让 GLM-5.3-Flash 格外有吸引力的工作负载：长上下文、缓存友好、智能体式、输出敏感的系统——在这些场景里，公开 API 价格打五折是有分量的。所有场景使用 DeepInfra 折扣价（输入 $0.075 / 输出 $0.25 / 缓存 $0.015），并与标准价对比（输入 $0.15 / 输出 $0.50 / 缓存 $0.03）。

### **场景 1：带大型可复用 prompt 的 RAG 支持副驾**

一个开发团队在构建内部支持助手，多数请求都带一段长 system prompt、检索指令和稳定的策略文本。这正是 DeepInfra 低缓存输入价发力的工作负载——可复用的 prompt 脚手架不必每次都按全价输入计费。

| **指标** | **数值** |
| --- | --- |
| 用量 | 每月 100M 缓存输入 + 20M 新输入 + 10M 输出 tokens |
| 模型 | GLM-5.3-Flash |
| 提供方 | DeepInfra |
| 月度成本 | $5.50 |

成本拆解：缓存输入 100M × $0.015 = $1.50，新输入 20M × $0.075 = $1.50，输出 10M × $0.25 = $2.50。合计：$5.50。

对比：同样的 token 构成按标准价（$0.15 输入、$0.50 输出、$0.03 缓存）要花 $11.00，DeepInfra 把它砍到 $5.50。

### **场景 2：面向 PR 与仓库任务的编码智能体**

这是 GLM-5.3-Flash 最明显的适配之一。编码与智能体框架占这类模型真实用量的一大块，而 DeepInfra 给了你不用付标准价的低成本路径。当智能体需要在一次推理里检查多个文件、工具 schema 和之前的步骤时，模型的长上下文也大显身手。

| **指标** | **数值** |

| 模型 | GLM-5.3-Flash |
| 提供方 | DeepInfra |

成本拆解：输入 50M × $0.075 = $3.75，输出 30M × $0.25 = $7.50。合计：$11.25。

DeepInfra 在这里显得强的原因：折扣费率、用于快速测试的公共端点、工作流日后需要更严格控制时的私有部署选项，以及服务于结构化 agent 循环的 function calling 和 JSON 输出。

对比：同样工作负载按标准价要花 $22.50，DeepInfra 每月省 $11.25。

一个团队处理大型合同、技术手册或审计文件，索要紧凑的结构化摘要。这正是 DeepInfra 约 1M token 上下文窗口、多模态支持、function calling 与折扣输入价组合起来格外有吸引力的地方。输入密集的应用受益比通常更大——GLM-5.3-Flash 的输入本来就不贵，DeepInfra 又给它再对半砍。

假设你在做一个面向开发者的应用，接受截图、图表或文图混合输入，给下游系统返回 JSON。DeepInfra 很合适，因为它在同一个折扣端点上暴露多模态输入、JSON 响应格式和 function calling。

这个场景适合用稳定的 system prompt、工具定义和编排脚手架运行大量重复智能体调用的团队。DeepInfra 在这里特别强，因为缓存输入降到每 1M token $0.015——低到让大型重复 prompt 帧在经济上成立。
