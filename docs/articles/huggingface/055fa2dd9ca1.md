# SafeCoder 与闭源代码助手的对比

几十年来，软件开发者一直在设计各种方法论、流程和工具来帮助提升代码质量与生产力。例如，敏捷开发、测试驱动开发、代码评审和 CI/CD 如今已是软件行业的标配。

在《How Google Tests Software》（Addison-Wesley，2012）一书中，Google 报告说：在系统测试——最后的测试阶段——修一个 bug 的成本是在单元测试阶段修它的 1000 倍。这把压力给到了链条的第一环——开发者，要求他们从一开始就把代码写好。

在生成式 AI 的一片喧嚣中，代码生成看起来是帮助开发者快速交付更好代码的一条有前景的路。确实，早期研究表明，像 [GitHub Copilot](https://github.blog/2023-06-27-the-economic-impact-of-the-ai-powered-developer-lifecycle-and-lessons-from-github-copilot) 或 [Amazon CodeWhisperer](https://aws.amazon.com/codewhisperer/) 这样的托管服务能帮助开发者提高效率。

然而，这些服务依赖闭源模型，无法按你的技术文化和流程做定制。Hugging Face 几周前发布了 [SafeCoder](https://huggingface.co/blog/starcoder) 正是为了补上这块。SafeCoder 是为企业构建的代码助手方案，给你最先进的模型、透明度、可定制性、IT 灵活性和隐私。

本文将对比 SafeCoder 与闭源服务，讲清楚你能从我们的方案中获得什么好处。

## 最先进的模型

SafeCoder 目前构建在 [StarCoder](https://huggingface.co/blog/starcoder) 模型之上——这是 [BigCode](https://huggingface.co/bigcode) 协作项目内设计并训练的开源模型家族。

StarCoder 是一个 155 亿参数的模型，面向 80 多种编程语言的代码生成而训练。它采用了创新的架构理念，如 [Multi-Query Attention](https://arxiv.org/abs/1911.02150)（MQA）来提升吞吐、降低延迟——这项技术也见于 [Falcon](https://huggingface.co/blog/falcon)，并被移植到 [LLaMa 2](https://huggingface.co/blog/llama2) 模型上。

StarCoder 有 8192 token 的上下文窗口，能更多地参考你的既有代码来生成新代码。它还能做中间填充（fill-in-the-middle），即在你的代码内部插入，而不是只在末尾追加。

最后，和 [HuggingChat](https://huggingface.co/chat/) 一样，SafeCoder 会随时间引入新的最先进模型，给你一条无缝升级的路径。

遗憾的是，闭源代码助手服务不共享底层模型的信息——能力如何、用什么数据训练，一概不知。

## 透明度

按照 [Chinchilla Scaling Law](https://arxiv.org/abs/2203.15556v1)，SafeCoder 是一个算力最优的模型，在 1 万亿（1000 billion）个代码 token 上训练。这些 token 来自 [The Stack](https://huggingface.co/datasets/bigcode/the-stack)——一个基于宽松开源许可仓库构建的 2.7TB 数据集。我们尽一切努力尊重退出（opt-out）请求，并做了一个[工具](https://huggingface.co/spaces/bigcode/in-the-stack)让仓库所有者检查自己的代码是否在数据集里。

本着透明的精神，我们的[研究论文](https://arxiv.org/abs/2305.06161)公开了模型架构、训练过程和详细指标。

遗憾的是，闭源服务只给些含糊的说法，比如"[该模型训练自]数十亿行代码"。据我们所知，没有任何指标可查。

## 可定制性

StarCoder 模型在设计之初就把可定制性考虑在内，我们已经做出了几个不同版本：

- [StarCoderBase](https://huggingface.co/bigcode/starcoderbase)：原始模型，在 The Stack 的 80+ 种语言上训练。
- [StarCoder](https://huggingface.co/bigcode/starcoder)：StarCoderBase 在 Python 上进一步训练。
- [StarCoder+](https://huggingface.co/bigcode/starcoderplus)：StarCoderBase 在英文 Web 数据上进一步训练，面向编程对话。

我们还在 GitHub 上公开了[微调代码](https://github.com/bigcode-project/starcoder/)。

每家公司都有自己的偏好语言和编码规范——怎么写内联文档、怎么写单元测试、安全和性能上的宜与忌。通过 SafeCoder，我们可以帮助你训练学习你自家软件工程流程特性的模型。我们的团队会帮你准备高质量数据集，并在你的基础设施上微调 StarCoder。你的数据永远不会暴露给任何人。

遗憾的是，闭源服务无法定制。

## IT 灵活性

SafeCoder 基于 Docker 容器做微调和部署。无论是本地还是云端，在任何容器管理服务上都很容易运行。

此外，SafeCoder 内置我们的 [Optimum](https://github.com/huggingface/optimum) 硬件加速库。无论你用 CPU、GPU 还是 AI 加速器，Optimum 都会自动生效，帮你在训练和推理上省时省钱。由于底层硬件由你掌控，你还可以按需调节基础设施的成本性能比。

遗憾的是，闭源服务只有托管形态。

## 安全与隐私

安全永远是头等大事，涉及源代码时更是如此。知识产权和隐私必须不惜代价保护。

无论在本地还是云上运行，SafeCoder 都处于你的完全行政管控之下。你可以实施并监控自己的安全检查，在整个 IT 平台上维持强一致合规。

SafeCoder 不窥探你的任何数据。你的提示和补全建议只属于你。SafeCoder 不会"call home"，不会向 Hugging Face 或任何其他人发送遥测数据。除了你，没人需要知道你在何时、如何使用 SafeCoder。SafeCoder 甚至不需要互联网连接。你可以（也应该）在完全离网的环境下运行它。

闭源服务依赖底层云的安全。这对你的合规态势是否适用，由你自己判断。对企业用户，提示和补全不会被存储（对个人用户则会）。不过我们遗憾地指出，GitHub 会收集["用户互动数据"](https://docs.github.com/en/copilot/overview-of-github-copilot/about-github-copilot-for-business)，且无法选择退出。AWS 默认也会同样收集，但允许你[选择退出](https://docs.aws.amazon.com/codewhisperer/latest/userguide/sharing-data.html)。
