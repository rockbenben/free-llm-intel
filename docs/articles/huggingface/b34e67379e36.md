# 希伯来语 LLM 开放排行榜上线！

这个项目回应了希伯来语 NLP 进步的迫切需求。希伯来语被视为低资源语言，现有的 LLM 排行榜往往缺少能准确反映其独特特征的基准。今天，我们很高兴推出一项改变这一局面的开创性工作——全新的开放 LLM 排行榜，专门用于评估和提升希伯来语语言模型。

希伯来语是一种形态丰富的语言，拥有复杂的词根与词型系统。单词由词根加前缀、后缀、中缀构成，这些词缀用于改变含义、时态或构成复数（以及其他功能）。这种复杂性导致同一个词根可以派生出多个合法的词形，使得为形态较简单语言设计的传统分词策略失效。结果是，现有语言模型可能难以准确处理和理解希伯来语的细微之处，这正凸显出为这些独特语言特性量身定制基准的必要性。

因此，希伯来语的 LLM 研究需要专门契合这门语言细微特征与语言属性的基准。我们的排行榜旨在填补这一空白：在语言特定任务上提供稳健的评估指标，并推动以开放、社区驱动的方式改进希伯来语生成式语言模型。我们相信这一倡议将成为研究者与开发者分享、对比和改进希伯来语 LLM 的平台。

## 排行榜指标与任务

我们构建了四个核心数据集，每个都用于检验语言模型对希伯来语的理解与生成能力，而不受其在其他语言上表现的影响。这些基准使用 few-shot prompt 格式评估模型，确保它们在有限上下文下也能正确适应并作答。

以下是排行榜纳入的各基准摘要。关于每个数据集、评分体系、prompt 构造的更详尽说明，请访问我们排行榜的 `About` 标签页。

- **希伯来语问答（Hebrew Question Answering）**：该任务评估模型理解和处理希伯来语信息的能力，侧重基于上下文的阅读理解与答案精确抽取。通过直接的问答格式检验模型对希伯来语句法和语义的掌握。*来源*：[HeQ](https://aclanthology.org/2023.findings-emnlp.915/) 数据集的测试子集。
- **情感准确率（Sentiment Accuracy）**：该基准测试模型在希伯来语文本中检测和解读情感的能力，评估其根据语言线索把陈述准确分类为正面、负面或中立的能力。*来源*：[Hebrew Sentiment](https://huggingface.co/datasets/HebArabNlpProject/HebrewSentiment)——一个希伯来语情感分析数据集。
- **Winograd Schema 挑战（Winograd Schema Challenge）**：该任务用于衡量模型对希伯来语代词消解和上下文歧义的理解。测试模型利用逻辑推理和通用世界知识，在复杂句中正确消解代词的能力。*来源*：Vered Schwartz 博士的[《Winograd Schema Challenge 希伯来语翻译版》](https://www.cs.ubc.ca/~vshwartz/resources/winograd_he.jsonl)。
- **翻译（Translation）**：该任务评估模型在英语与希伯来语之间互译的熟练度，考察语言的准确性、流畅度以及跨语言保持原意的能力，突出模型在双语翻译任务上的能力。*来源*：[NeuLabs-TedTalks](https://opus.nlpl.eu/NeuLab-TedTalks/en&he/v1/NeuLab-TedTalks) 对齐翻译语料库。

## 技术架构

该排行榜受 [Open LLM Leaderboard](https://huggingface.co/spaces/HuggingFaceH4/open_llm_leaderboard) 启发，使用了 [Demo Leaderboard 模板](https://huggingface.co/demo-leaderboard-backend)。提交的模型通过 HuggingFace 的 [Inference Endpoints](https://huggingface.co/docs/inference-endpoints/index) 自动部署，并经由 [lighteval](https://github.com/huggingface/lighteval) 库管理的 API 请求完成评估。实现过程很顺利，主要工作是搭建环境，其余代码都运行顺畅。
