# 基于 Intel Gaudi 2 和 Intel Xeon 构建高性价比企业 RAG 应用

![](https://huggingface.co/blog/assets/cost_efficient_rag_applications_with_intel/main.jpg)

检索增强生成（RAG）通过引入存放在外部数据存储中的新鲜领域知识，增强大语言模型的文本生成能力。把公司数据与语言模型在训练中习得的知识分离开来，对于在性能、准确性与安全隐私目标之间取得平衡至关重要。

在这篇博客中，你将了解 Intel 如何帮助你作为 [OPEA](https://opea.dev)（Open Platform for Enterprise AI，企业 AI 开放平台）的一部分开发和部署 RAG 应用。你还将通过一个真实的 RAG 用例，看到 Intel Gaudi 2 AI 加速器和 Xeon CPU 如何显著提升企业级性能。

# 开始上手

细聊之前，先拿到硬件。[Intel Gaudi 2](https://habana.ai/products/gaudi2/) 专为数据中心和云端的深度学习训练与推理加速而生。它在 [Intel Developer Cloud](https://www.intel.com/content/www/us/en/developer/tools/devcloud/overview.html)（IDC）上公开可用，也可本地部署。IDC 是上手 Gaudi 2 最快的方式：还没有账号的话，注册一个、订阅 "Premium"，然后申请访问权限。

软件方面，我们用 LangChain 构建应用——一个旨在简化基于 LLM 创建 AI 应用的开源框架。它提供模板化方案，让开发者用自定义嵌入模型、向量数据库和 LLM 搭建 RAG 应用。更多信息见 LangChain 文档。Intel 一直在积极向 LangChain 贡献多项优化，帮助开发者在 Intel 平台上高效部署生成式 AI 应用。

在 LangChain 中，我们使用 `rag-redis` 模板创建 RAG 应用，嵌入模型用 [BAAI/bge-base-en-v1.5](https://huggingface.co/BAAI/bge-base-en-v1.5)，默认向量数据库是 Redis。下图展示高层架构。

嵌入模型运行在 [Intel Granite Rapids](https://www.intel.com/content/www/us/en/newsroom/news/intel-unveils-future-generation-xeon.html#gs.6t3deu) CPU 上。Intel Granite Rapids 架构针对高核数性能敏感负载和通用计算负载， optimized 到最低的总拥有成本（TCO）。GNR 还支持 AMX-FP16 指令集，为混合 AI 负载带来 2-3 倍性能提升。

LLM 运行在 Intel Gaudi 2 加速器上。就 Hugging Face 模型而言，[Optimum Habana](https://huggingface.co/docs/optimum/en/habana/index) 库是 Hugging Face [Transformers](https://huggingface.co/docs/transformers/index) 和 [Diffusers](https://huggingface.co/docs/diffusers/index) 库与 Gaudi 之间的接口，为多种下游任务提供单卡/多卡下的模型加载、训练与推理工具。

我们提供一个 [Dockerfile](https://github.com/opea-project/GenAIExamples/tree/main/ChatQnA/langchain/docker)，简化 LangChain 开发环境的搭建。容器起来后，就可以在 Docker 环境里构建向量数据库、RAG 流水线和 LangChain 应用。详细分步指引参见 [ChatQnA](https://github.com/opea-project/GenAIExamples/tree/main/ChatQnA) 示例。

# 创建向量数据库

我们用 Nike 的公开财务文档填充向量数据库。示例代码如下。

```
# Ingest PDF files that contain Edgar 10k filings data for Nike.
company_name = "Nike"
data_path = "data"
doc_path = [os.path.join(data_path, file) for file in os.listdir(data_path)][0]
content = pdf_loader(doc_path)
chunks = text_splitter.split_text(content)

# Create vectorstore
embedder = HuggingFaceEmbeddings(model_name=EMBED_MODEL)

_ = Redis.from_texts(
    texts=[f"Company: {company_name}. " + chunk for chunk in chunks],
    embedding=embedder,
    index_name=INDEX_NAME,
    index_schema=INDEX_SCHEMA,
    redis_url=REDIS_URL,
)
```

# 定义 RAG 流水线

在 LangChain 中，我们用 Chain API 把提示词、向量数据库和嵌入模型连起来。

完整代码在[仓库](https://github.com/opea-project/GenAIExamples/blob/main/ChatQnA/langchain/redis/rag_redis/chain.py)中。

```
# Embedding model running on Xeon CPU
embedder = HuggingFaceEmbeddings(model_name=EMBED_MODEL)

# Redis vector database
vectorstore = Redis.from_existing_index(
    embedding=embedder, index_name=INDEX_NAME, schema=INDEX_SCHEMA, redis_url=REDIS_URL
)

# Retriever
retriever = vectorstore.as_retriever(search_type="mmr")

# Prompt template
template = """…"""
prompt = ChatPromptTemplate.from_template(template)

# Hugging Face LLM running on Gaudi 2
model = HuggingFaceEndpoint(endpoint_url=TGI_LLM_ENDPOINT, …)

# RAG chain
chain = (
    RunnableParallel({"context": retriever, "question": RunnablePassthrough()}) | prompt | model | StrOutputParser()
).with_types(input_type=Question)
```

# 把 LLM 加载到 Gaudi 2

我们的聊天模型将跑在 Gaudi2 上，使用 Hugging Face Text Generation Inference（TGI）服务器。这个组合让 MPT、Llama、Mistral 等热门开源 LLM 在 Gaudi2 硬件上实现高性能文本生成。

无需配置：可以直接用预构建的 Docker 镜像并传入模型名（例如 Intel NeuralChat）。

```
model=Intel/neural-chat-7b-v3-3
volume=$PWD/data
docker run -p 8080:80 -v $volume:/data --runtime=habana -e HABANA_VISIBLE_DEVICES=all -e OMPI_MCA_btl_vader_single_copy_mechanism=none --cap-add=sys_nice --ipc=host tgi_gaudi --model-id $model
```

该服务默认使用单个 Gaudi 加速器。更大的模型（例如 70B）可能需要多个加速器，这时请加上相应参数，比如 `--sharded true` 和 `--num_shard 8`。对于 [Llama](https://huggingface.co/meta-llama) 或 [StarCoder](https://huggingface.co/bigcode/starcoder) 这类受限模型，还需要用 `-e HUGGING_FACE_HUB_TOKEN=<token>` 指定你的 Hugging Face [token](https://huggingface.co/docs/hub/en/security-tokens)。

容器运行起来后，我们向 TGI 端点发一个请求验证服务正常。

```
curl localhost:8080/generate -X POST \
-d '{"inputs":"Which NFL team won the Super Bowl in the 2010 season?", \
"parameters":{"max_new_tokens":128, "do_sample": true}}' \
-H 'Content-Type: application/json'
```

如果看到生成的回答，说明 LLM 已正确运行，可以开始在 Gaudi 2 上享受高性能推理了！

TGI Gaudi 容器默认使用 bfloat16 数据类型。想要更高吞吐，可以启用 FP8 量化。根据我们的测试结果，FP8 量化相比 BF16 应带来 1.8 倍的吞吐提升。FP8 相关指令见 [README](https://github.com/opea-project/GenAIExamples/blob/main/ChatQnA/README.md) 文件。

最后，你还可以用 Meta 的 [Llama Guard](https://huggingface.co/meta-llama/LlamaGuard-7b) 模型启用内容审核。[README](https://github.com/opea-project/GenAIExamples/blob/main/ChatQnA/README.md) 提供了在 TGI Gaudi 上部署 Llama Guard 的说明。

# 运行 RAG 服务

我们用以下指令启动 RAG 应用的后端服务。`server.py` 脚本用 fastAPI 定义服务端点。

```
docker exec -it qna-rag-redis-server bash
nohup python app/server.py &
```

默认情况下，TGI Gaudi 端点应在本机的 8080 端口（即 `http://127.0.0.1:8080`）。如果运行在其他地址或端口，请相应设置 `TGI_ENDPOINT` 环境变量。

# 启动 RAG GUI

用以下指令安装前端 GUI 组件。

```
sudo apt-get install npm && \
    npm install -g n && \
    n stable && \
    hash -r && \
    npm install -g npm@latest
```

然后，在 `.env` 文件里更新 `DOC_BASE_URL` 环境变量，把本机 IP（`127.0.0.1`）换成 GUI 所在服务器的实际 IP。

运行以下命令安装所需依赖：

```
npm install
```

最后，用以下命令启动 GUI 服务器：

```
nohup npm run dev &
```

前端服务随即运行，应用也就启动了。

# 基准测试结果

我们在不同模型和配置上做了大量实验。下面两张图展示了 Llama2-70B 模型在 16 并发用户下，4 块 Intel Gaudi 2 平台与 4 块 Nvidia H100 平台的端到端吞吐相对比较和每美元性能比较。

两种情况下，向量数据库和嵌入模型都跑在同一 Intel Granite Rapids CPU 平台上。做每美元性能比较时，我们用公开可得的价格计算平均训练每美元性能，与 [MosaicML](https://www.databricks.com/blog/llm-training-and-inference-intel-gaudi2-ai-accelerators) 团队 2024 年 1 月公布的一致。

可以看到，基于 H100 的系统吞吐高出 1.13 倍，但每美元性能只有 Gaudi 2 的 0.44 倍。这些比较会因客户在不同云上的具体折扣而异。详细基准配置列在文末。

运行企业 AI 应用时，基于 Intel Granite Rapids CPU 和 Gaudi 2 加速器的系统在总拥有成本上更有优势。结合 FP8 优化还能更进一步。

**基准配置**

- Gaudi2 配置：HLS-Gaudi2，8 块 Habana Gaudi2 HL-225H 夹层卡、2 颗 Intel® Xeon® Platinum 8380 CPU @ 2.30GHz、1TB 系统内存；系统：Ubuntu 22.04.03，5.15.0 内核
- H100 SXM 配置：Lambda labs 实例 gpu_8x_h100_sxm5；8×H100 SXM、2 颗 Intel Xeon® Platinum 8480 CPU@2 GHz、1.8TB 系统内存；系统 Ubuntu 20.04.6 LTS，5.15.0 内核
- Intel Xeon：预生产 Granite Rapids 平台，2Sx120C @ 1.9GHz，8800 MCR DIMMs，1.5TB 系统内存。系统：Cent OS 9，6.2.0 内核
- Llama2 70B 部署到 4 卡（查询量归一化到 8 卡）。Gaudi2 用 BF16，H100 用 FP16。
- 嵌入模型为 BAAI/bge-base v1.5。测试组合：TGI-gaudi 1.2.1、TGI-GPU 1.4.5、Python 3.11.7、Langchain 0.1.11、sentence-transformers 2.5.1、langchain benchmarks 0.0.10、redis 5.0.2、cuda 12.2.r12.2/compiler.32965470 0、TEI 1.2.0，
- RAG 查询最大输入长度 1024，最大输出长度 128。测试数据集：langsmith Q&A。并发客户端数 16
- Gaudi2（70B）的 TGI 参数：`batch_bucket_size=22`、`prefill_batch_bucket_size=4`、`max_batch_prefill_tokens=5102`、`max_batch_total_tokens=32256`、`max_waiting_tokens=5`、`streaming=false`
- H100（70B）的 TGI 参数：`batch_bucket_size=8`、`prefill_batch_bucket_size=4`、`max_batch_prefill_tokens=4096`、`max_batch_total_tokens=131072`、`max_waiting_tokens=20`、`max_batch_size=128`、`streaming=false`
- TCO 参考：[https://www.databricks.com/blog/llm-training-and-inference-intel-gaudi2-ai-accelerators](https://www.databricks.com/blog/llm-training-and-inference-intel-gaudi2-ai-accelerators)
