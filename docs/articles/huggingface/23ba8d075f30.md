# 在单块 GPU 上用 ROCm 运行 ChatGPT 风格的聊天机器人

## 引言

ChatGPT——OpenAI 的开创性语言模型——已成为人工智能领域的强大影响力，为各行各业的大量 AI 应用铺平了道路。凭借惊人的理解与生成拟人文本的能力，ChatGPT 改变了从客户支持到创意写作等众多行业，甚至充当了极有价值的研究工具。

社区已经做出各种努力，提供能力出色但体积更小的开源大语言模型，例如 [OPT](https://huggingface.co/docs/transformers/model_doc/opt)、[LLAMA](https://github.com/facebookresearch/llama)、[Alpaca](https://github.com/tatsu-lab/stanford_alpaca) 和 [Vicuna](https://github.com/lm-sys/FastChat)。

在这篇博客中，我们将深入 Vicuna 的世界，讲解如何在单块 AMD GPU 上用 ROCm 运行 Vicuna 13B 模型。

**Vicuna 是什么？**

Vicuna 是一个拥有 130 亿参数的开源聊天机器人，由 UC Berkeley、CMU、Stanford 和 UC San Diego 的团队开发。打造 Vicuna 的方式是：用从 ShareGPT.com 经公共 API 收集的约 7 万条用户分享对话，对 LLAMA 基座模型做微调。以 GPT-4 作为参照的初步评估显示，Vicuna-13B 达到了 OpenAI ChatGPT 超过 90%* 的质量。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/chatbot-amd-gpu/01.png)

它几周前（4 月 11 日）刚在 [Github](https://github.com/lm-sys/FastChat) 上发布。值得一提的是，Vicuna 的数据集、训练代码、评估指标和训练成本都是公开的，总训练成本仅约 300 美元，对大众而言是一个高性价比方案。

关于 Vicuna 的更多细节，请查看 [https://vicuna.lmsys.org](https://vicuna.lmsys.org)。

**为什么需要量化的 GPT 模型？**

以 fp16 运行 Vicuna-13B 模型大约需要 28GB 显存。要进一步降低内存占用，就需要优化技术。最近的研究论文 GPTQ 提出了针对 GPT 模型的低比特精度、训练后精确量化方法。如下图所示，对于参数量超过 10B 的模型，4-bit 或 3-bit 的 GPTQ 可以达到与 fp16 相当的精度。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/chatbot-amd-gpu/02.png)

此外，这些模型的庞大参数也会严重拖累 GPT 的延迟，因为 GPT 的 token 生成更多受制于内存带宽（GB/s），而非计算量（TFLOPs 或 TOPs）本身。正因如此，当 GPU 处于内存受限（memory bound）状态时，量化模型并不会让 token 生成延迟变差。可参考 [GPTQ 量化论文](https://arxiv.org/abs/2210.17323)和 [github 仓库](https://github.com/IST-DASLab/gptq)。

借助这项技术，Hugging Face 上已有多个 4-bit 量化的 Vicuna 模型可用来，如下：

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/chatbot-amd-gpu/03.png)

## 在 AMD GPU 上用 ROCm 运行 Vicuna 13B 模型

要在 AMD GPU 上运行 Vicuna 13B 模型，我们需要借助 ROCm（Radeon Open Compute）的力量——这是一个开源软件平台，为深度学习和高性能计算应用提供 AMD GPU 加速。

下面是在 AMD GPU 上用 ROCm 部署并运行 Vicuna 13B 模型的分步指南：

**系统要求**

在安装之前，请确保你的系统满足以下条件：

- 一块支持 ROCm 的 AMD GPU（在 docs.amd.com 页面查看兼容列表）
- Linux 操作系统，最好是 Ubuntu 18.04 或 20.04
- Conda 或 Docker 环境
- Python 3.6 或更高

更多信息请查看 [https://docs.amd.com/bundle/ROCm-Installation-Guide-v5.4.3/page/Prerequisites.html](https://docs.amd.com/bundle/ROCm-Installation-Guide-v5.4.3/page/Prerequisites.html)。

本示例已在 [**Instinct MI210**](https://www.amd.com/en/products/server-accelerators/amd-instinct-mi210) 和 [**Radeon RX6900XT**](https://www.amd.com/en/products/graphics/amd-radeon-rx-6900-xt) 上测试，环境为 ROCm5.4.3 和 Pytorch2.0。

**快速开始**

**1 ROCm 安装与 Docker 容器设置（宿主机）**

**1.1 安装 ROCm**

以下命令适用于 ROCm5.4.3 和 Ubuntu 22.04。请按照你的目标 ROCm 与 Ubuntu 版本从这里开始调整：[https://docs.amd.com/bundle/ROCm-Installation-Guide-v5.4.3/page/How_to_Install_ROCm.html](https://docs.amd.com/bundle/ROCm-Installation-Guide-v5.4.3/page/How_to_Install_ROCm.html)

```
sudo apt update && sudo apt upgrade -y
wget https://repo.radeon.com/amdgpu-install/5.4.3/ubuntu/jammy/amdgpu-install_5.4.50403-1_all.deb
sudo apt-get install ./amdgpu-install_5.4.50403-1_all.deb
sudo amdgpu-install --usecase=hiplibsdk,rocm,dkms
sudo amdgpu-install --list-usecase
sudo reboot
```

**1.2 验证 ROCm 安装**

```
rocm-smi
sudo rocminfo
```

**1.3 拉取 Docker 镜像并运行容器**

以下使用 ROCm5.4.2 上的 Pytorch2.0。请根据你的目标 ROCm 和 Pytorch 版本选择合适镜像：[https://hub.docker.com/r/rocm/pytorch/tags](https://hub.docker.com/r/rocm/pytorch/tags)

```
docker pull rocm/pytorch:rocm5.4.2_ubuntu20.04_py3.8_pytorch_2.0.0_preview

sudo docker run --device=/dev/kfd --device=/dev/dri --group-add video \
--shm-size=8g --cap-add=SYS_PTRACE --security-opt seccomp=unconfined \
--ipc=host -it --name vicuna_test -v ${PWD}:/workspace -e USER=${USER} \
rocm/pytorch:rocm5.4.2_ubuntu20.04_py3.8_pytorch_2.0.0_preview
```

**2 模型量化与模型推理（在 Docker 内）**

你可以直接从 Huggingface 下载量化的 Vicuna-13b 模型，也可以自行量化浮点模型。如果你想量化浮点模型，请查看**附录 - GPTQ 模型量化**。

**2.1 下载量化的 Vicuna-13b 模型**

使用下面 git 仓库中的 download-model.py 脚本。

```
git clone https://github.com/oobabooga/text-generation-webui.git
cd text-generation-webui
python download-model.py anon8231489123/vicuna-13b-GPTQ-4bit-128g
```

- **在 AMD GPU 上运行 Vicuna 13B GPTQ 模型**

```
git clone https://github.com/oobabooga/GPTQ-for-LLaMa.git -b cuda
cd GPTQ-for-LLaMa
python setup_cuda.py install
```

这些命令会把经过 HIP 化处理、与 CUDA 等价的 kernel 二进制编译并链接为 Python 的 C extension。该实现的 kernel 由反量化（dequantization）+ FP32 Matmul 组成。如果想用反量化 + FP16 Matmul 获得进一步加速，请查看**附录 - 面向 AMD GPU 的 GPTQ 反量化 + FP16 Matmul kernel**。

```
git clone https://github.com/oobabooga/GPTQ-for-LLaMa.git -b cuda
cd GPTQ-for-LLaMa/
python setup_cuda.py install

# model inference
python llama_inference.py ../../models/vicuna-13b --wbits 4 --load \
../../models/vicuna-13b/vicuna-13b_4_actorder.safetensors --groupsize 128 --text “You input text here”
```

一切就绪，是时候在 AMD GPU 上运行 Vicuna 13B 了。用上面的命令运行模型，把 *"Your input text here"* 换成你作为输入的文本。如果设置都正确，你会看到模型根据你的输入生成输出文本。

**3. 把量化的 Vicuna 模型暴露为 Web API 服务**

修改 FastChat 中 GPTQ Python 模块（GPTQ-for-LLaMa）的路径，位置在这一行：

[https://github.com/thisserand/FastChat/blob/4a57c928a906705404eae06f7a44b4da45828487/fastchat/serve/load_gptq_model.py#L7](https://github.com/thisserand/FastChat/blob/4a57c928a906705404eae06f7a44b4da45828487/fastchat/serve/load_gptq_model.py#L7)

要从 gradio 库启动 Web UI，需要把 controller、worker（Vicuna 模型 worker）和 web_server 作为后台任务分别运行。

```
nohup python0 -W ignore::UserWarning -m fastchat.serve.controller &

nohup python0 -W ignore::UserWarning -m fastchat.serve.model_worker --model-path /path/to/quantized_vicuna_weights \
--model-name vicuna-13b-quantization --wbits 4 --groupsize 128 &

nohup python0 -W ignore::UserWarning -m fastchat.serve.gradio_web_server &
```

现在 4-bit 量化的 Vicuna-13B 模型可以装进拥有 16GB DDR 的 RX6900XT 显存里。运行 13B 模型只需 7.52GB DDR（占 16GB 的 46%），而 fp16 数据类型下模型需要超过 28GB 显存。延迟和精度的损失都非常小，相关指标在本文末尾给出。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/chatbot-amd-gpu/04.png)

**指标 - 模型大小（GB）**

- 模型参数大小。当模型预加载到 GPU 显存时，由于输入/输出 token 空间的缓存，实际显存占用会大于模型本身。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/chatbot-amd-gpu/08.png)

**指标 – 精度（PPL：Perplexity 困惑度）**

- 在 C4 数据集（[https://paperswithcode.com/dataset/c4](https://paperswithcode.com/dataset/c4)）的 2048 个样本上测量
- Vicuna 13b – baseline：fp16 参数，fp16 Matmul
- Vicuna 13b – quant (4bit/fp32)：4bits 参数，fp32 Matmul
- Vicuna 13b – quant (4bit/fp16)：4bits 参数，fp16 Matmul

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/chatbot-amd-gpu/09.png)

**指标 – 延迟（Token 生成延迟，ms）**

- 在 token 生成阶段测量。
- Vicuna 13b – baseline：fp16 参数，fp16 Matmul
- Vicuna 13b – quant (4bit/fp32)：4bits 参数，fp32 Matmul
- Vicuna 13b – quant (4bit/fp16)：4bits 参数，fp16 Matmul

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/chatbot-amd-gpu/10.png)

## 结语

大语言模型（LLM）已在聊天机器人系统上取得长足进步，OpenAI 的 ChatGPT 就是明证。Vicuna-13B 作为一个开源 LLM 模型，展现了出色的能力和质量。

按本指南操作，你现在应该更清楚如何在 AMD GPU 上用 ROCm 部署和运行 Vicuna 13B 模型，从而在你的研究和个人项目中释放这一前沿语言模型的全部潜力。

**从浮点 LLaMA 模型构建 Vicuna 量化模型**

**a. 从 Huggingface 下载 LLaMA 和 Vicuna delta 模型**

Vicuna 的开发者（lmsys）只提供可叠加到 LLaMA 模型上的 delta-model。需要分别从 Huggingface 下载 huggingface 格式的 LLaMA 和 Vicuna delta 参数。目前 Vicuna 提供 7b 和 13b 的 delta 模型。

[https://huggingface.co/models?sort=downloads&search=huggyllama](https://huggingface.co/models?sort=downloads&search=huggyllama)

[https://huggingface.co/models?sort=downloads&search=lmsys](https://huggingface.co/models?sort=downloads&search=lmsys)

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/chatbot-amd-gpu/13.png)

**b. 用 Vicuna-delta 模型把 LLaMA 转换为 Vicuna**

```
git clone https://github.com/lm-sys/FastChat
cd FastChat
```

用这条命令转换 LLaMA 参数：

（注意：不要使用 vicuna-{7b, 13b}-*delta-v0，它的 vocab_size 与 LLaMA 不同，模型无法转换）

```
python -m fastchat.model.apply_delta  --base /path/to/llama-13b --delta lmsys/vicuna-13b-delta-v1.1 \ 
--target ./vicuna-13b  
```

Vicuna-13b 模型现在就绪。

**c. 把 Vicuna 量化到 2/3/4 bits**

要将 GPTQ 应用于 LLaMA 和 Vicuna，先克隆：

```
git clone https://github.com/oobabooga/GPTQ-for-LLaMa -b cuda  
cd GPTQ-for-LLaMa
```

（注意：目前不要使用 [https://github.com/qwopqwop200/GPTQ-for-LLaMa](https://github.com/qwopqwop200/GPTQ-for-LLaMa)。因为该仓库实现的 2、3、4bit 量化 + MatMul kernel 没有把反量化+matmul 并行化，token 生成性能更差）

用这条命令量化 Vicuna-13b 模型。QAT 基于 c4 数据集完成，但你也可以使用其他数据集，例如 wikitext2

（注意：多尝试不同的 group size 组合，有些 wbit 与 groupsize 的组合下模型精度会显著变化。）

```
python llama.py ./Vicuna-13b c4 --wbits 4 --true-sequential --act-order \
--save_safetensors Vicuna-13b-4bit-act-order.safetensors
```

模型完成并保存为 **Vicuna-13b-4bit-act-order.safetensors**。
