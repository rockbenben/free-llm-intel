# 我们如何借助 distilabel 打造 Argilla 2.0 聊天机器人

## TL;DR

了解如何为你选定的工具（本文是 [Argilla 2.0](https://github.com/argilla-io/argilla)）构建一个聊天机器人：它能理解技术文档，并就文档与用户对话。

在这篇文章中，我们将展示如何借力 [distilabel](https://github.com/argilla-io/distilabel)，并微调一个领域专用的 embedding 模型，创建一个既准确又吸引人的对话模型。

本文概述为 Argilla 2.0 创建聊天机器人的流程。我们将：

- 从技术文档生成合成数据集，用于微调一个领域专用的 embedding 模型，
- 创建一个向量数据库来存储和检索文档，
- 把最终的聊天机器人部署到 Hugging Face Space，供用户交互，并把交互记录存入 Argilla，用于持续评估和改进。

点击[这里](https://huggingface.co/spaces/plaguss/argilla-sdk-chatbot-space)直达应用。

## 为微调自定义 Embedding 模型生成合成数据

需要快速复习 RAG？用这份[入门 notebook](https://huggingface.co/learn/cookbook/en/rag_zephyr_langchain#simple-rag-for-github-issues-using-hugging-face-zephyr-and-langchain)补补基础。我们等你跟上节奏！

### 下载并切分数据

切分数据（chunking）指把文本数据划分为大约每块 256 token 的可管理小块（后续 RAG 使用的 chunk 大小）。

进入第一步：处理目标仓库的文档。为简化这项工作，你可以借助 [llama-index](https://docs.llamaindex.ai/en/stable/examples/data_connectors/GithubRepositoryReaderDemo/) 之类的库读取仓库内容并解析 markdown 文件。具体来说，langchain 提供了实用的 [MarkdownTextSplitter](https://python.langchain.com/v0.1/docs/modules/data_connection/document_transformers/markdown_header_metadata/)，`llama-index` 提供了 [MarkdownNodeParser](https://docs.llamaindex.ai/en/stable/module_guides/loading/node_parsers/modules/?h=markdown#markdownnodeparser) 帮你抽取所需信息。如果你想要更省事的路线，可以考虑 [`davanstrien`](https://huggingface.co/davanstrien) 的 [corpus-creator](https://huggingface.co/spaces/davanstrien/corpus-creator) 应用。

为了让事情更简单高效，我们开发了一个定制 Python 脚本替你干重活。脚本在我们仓库的[这里](https://github.com/argilla-io/argilla-sdk-chatbot/blob/main/docs_dataset.py)。

这个脚本自动化完成从 GitHub 仓库抓取文档并将其作为数据集存到 Hugging Face Hub 的全过程。最棒的是？它易用得出奇！来看看怎么运行：

```
python docs_dataset.py \
    "argilla-io/argilla-python" \
    --dataset-name "plaguss/argilla_sdk_docs_raw_unstructured"
```

脚本虽然好用，你还可以通过额外参数进一步定制。不过有两个必需要提供的输入：

- 存放文档的 GitHub 仓库路径
- 数据集将要存放的 Hugging Face Hub 数据集 ID

提供这两个必需参数后，脚本会搞定其余一切。幕后发生的事如下：

- 脚本把指定 GitHub 仓库的文档下载到本地目录。默认在 `/docs` 目录寻找文档，你可以通过指定不同路径来更改。
- 从下载的文档中提取所有 markdown 文件。
- 把提取出的 markdown 文件切分成可管理的小块。
- 最后，把准备好的数据集推送到 Hugging Face Hub，随时可用。

为了让你更了解脚本的内部机制，这里给一段概括核心逻辑的代码：

```
# The function definitions are omitted for brevity, visit the script for more info!
from github import Github

gh = Github()
repo = gh.get_repo("repo_name")

# Download the folder
download_folder(repo, "/folder/with/docs", "dir/to/download/docs") 

# Extract the markdown files from the downloaded folder with the documentation from the GitHub repository
md_files = list(docs_path.glob("**/*.md"))

# Loop to iterate over the files and generate chunks from the text pieces
data = create_chunks(md_files)

# Create a dataset to push it to the hub
create_dataset(data, repo_name="name/of/the/dataset")
```

脚本包含若干短函数：下载文档、从 markdown 文件生成切块、创建数据集。要加入更多功能或实现更复杂的切分策略应该都不难。

### 使用 distilabel 为我们的 embedding 模型生成合成数据

我们将从文档中生成合成问题，让每个文档切块都能回答其中一个问题。我们还会通过生成毫不相关、容易区分的问题来构造困难负例（hard negative）。有了问题、困难负例和文档，就能组装用于微调数据集的三元组。

完整流水线脚本见参考仓库的 [`pipeline_docs_queries.py`](https://github.com/argilla-io/argilla-sdk-chatbot/blob/main/pipeline_docs_queries.py)，我们逐个过一遍各个步骤：

- `load_data`：

我们旅程的第一步，是获取存放宝贵文档切块的数据集。仔细查看后发现，装切块的列恰如其分地叫 `chunks`。但为了让后续模型无缝工作，我们需要给这一列换个身份：把它重命名为 `anchor`，因为这是我们后续步骤期望的输入名。我们用 `output_mappings` 来完成这个列名转换：

```
load_data = LoadDataFromHub(
    name="load_data",
    repo_id="plaguss/argilla_sdk_docs_raw_unstructured",
    output_mappings={"chunks": "anchor"},
    batch_size=10,
)
```

- `generate_sentence_pair`

现在我们来到流程中最精彩的部分：把文档片段转化为合成查询。主角是 [`GenerateSentencePair`](https://distilabel.argilla.io/latest/components-gallery/tasks/generatesentencepair/) 任务。这个强大的任务提供了生成高质量句对的广泛可能，建议阅读其文档以充分发挥它的潜力。

在我们的具体用例中，我们将利用 [`GenerateSentencePair`](https://distilabel.argilla.io/latest/components-gallery/tasks/generatesentencepair/) 的能力来打磨合成查询，最终提升模型表现。深入看看我们如何配置这个任务。

```
llm = InferenceEndpointsLLM(
    model_id="meta-llama/Meta-Llama-3-70B-Instruct",
    tokenizer_id="meta-llama/Meta-Llama-3-70B-Instruct",
)

generate_sentence_pair = GenerateSentencePair(
    name="generate_sentence_pair",
    triplet=True,  # Generate positive and negative
    action="query",
    context="The generated sentence has to be related with Argilla, a data annotation tool for AI engineers and domain experts.",
    llm=llm,
    input_batch_size=10,
    output_mappings={"model_name": "model_name_query"},
)
```

逐行拆解上面的代码。

设置 `triplet=True` 是指示该任务产出一系列三元组：锚句（anchor）、正例句和负例句。这种格式正适合微调，Sentence Transformers 库的[训练概览](https://www.sbert.net/docs/sentence_transformer/training_overview.html)有解释。

`action="query"` 参数是这个任务的关键，它指引 LLM 为正例句生成查询。魔法就发生在这里——我们的文档切块被转化为有意义的查询。

为了进一步帮助模型，我们加了 `context` 参数。当锚句上下文不足时（简短的文档切块常常如此），它为 LLM 提供补充信息。

最后，我们选择通过 [`InferenceEndpointsLLM`](https://distilabel.argilla.io/latest/components-gallery/llms/inferenceendpointsllm/) 组件使用 `meta-llama/Meta-Llama-3-70B-Instruct` 模型。这一选择让我们借力该模型的能力，生成高质量合成查询，最终提升我们的模型表现。

- `multiply_queries`

通过 `GenerateSentencePair` 步骤，我们得到的训练样本数等于切块数——本例是 251。但我们清楚，这未必足以微调一个能准确捕捉我们特定用例细微差别的定制模型。

为了突破这一限制，我们将动用另一个 LLM 生成更多查询，从而扩大训练数据集的规模，给模型更丰富的学习基础。

这把我们带到流水线的下一步：`MultipleQueries`——我们为进一步增广数据集手写的定制 `Task`。

```
multiply_queries = MultipleQueries(
    name="multiply_queries",
    num_queries=3,
    system_prompt=(
        "You are an AI assistant helping to generate diverse examples. Ensure the "
        "generated queries are all in separated lines and preceded by a dash. "
        "Do not generate anything else or introduce the task."
    ),
    llm=llm,
    input_batch_size=10,
    input_mappings={"query": "positive"},
    output_mappings={"model_name": "model_name_query_multiplied"},
)
```

来看看这个用于扩增训练集的定制 `Task` 的配置。关键旋钮是 `num_queries` 参数，这里设为 3，意味着每个样本再生成 3 条额外的"正例"查询；考虑到有些样本可能失败，实际上大致把数据集扩大四倍。

为了让大语言模型不跑偏，我们写了一个 system_prompt 清晰说明指令。鉴于所选模型足够强、样本足够简单，我们没有动用结构化生成技术；但在更复杂的场景中，那会是有价值的做法。

好奇这个定制 `Task` 的内部实现？点击下面的下拉框查看完整定义：

MultipleQueries 定义

```
multiply_queries_template = (
    "Given the following query:\n{original}\nGenerate {num_queries} similar queries by varying "
    "the tone and the phrases slightly. "
    "Ensure the generated queries are coherent with the original reference and relevant to the context of data annotation "
    "and AI dataset development."
)

class MultipleQueries(Task):
    system_prompt: Optional[str] = None
    num_queries: int = 1

    @property
    def inputs(self) -> List[str]:
        return ["query"]

    def format_input(self, input: Dict[str, Any]) -> ChatType:
        prompt = [
            {
                "role": "user",
                "content": multiply_queries_template.format(
                    original=input["query"],
                    num_queries=self.num_queries
                ),
            },
        ]
        if self.system_prompt:
            prompt.insert(0, {"role": "system", "content": self.system_prompt})
        return prompt

    @property
    def outputs(self) -> List[str]:
        return ["queries", "model_name"]

    def format_output(
        self, output: Union[str, None], input: Dict[str, Any]
    ) -> Dict[str, Any]:
        queries = output.split("- ")
        if len(queries) > self.num_queries:
            queries = queries[1:]
        queries = [q.strip() for q in queries]
        return {"queries": queries}
```

- `merge_columns`

临近流水线收尾，重点转向数据处理。我们的最终目标是产出一份由适合微调的三元组行组成的精修数据集。但生成多条查询后，数据集现在有两列：`positive` 和 `queries`。`positive` 列装着原始查询（单个字符串），`queries` 列装着字符串列表（同一实体生成的额外查询）。

为了把这两列合并成一个统一的列表，我们使用 [`MergeColumns`](https://distilabel.argilla.io/dev/components-gallery/steps/mergecolumns/) 步骤，把原始查询与生成的查询合到一起：

```
merge_columns = MergeColumns(
    name="merge_columns",
    columns=["positive", "queries"],
    output_column="positive"
)
```

- `expand_columns`

最后，用 [`ExpandColumns`](https://distilabel.argilla.io/dev/components-gallery/steps/expandcolumns/) 把刚才那列正例拆到不同的行上。效果是：每条 `positive` 查询各占一行，而 `anchor` 和 `negative` 列被复制以匹配展开后的正例查询。这一数据操作产出结构最适合微调的数据集：

```
expand_columns = ExpandColumns(columns=["positive"])
```

点击下拉框查看完整流水线定义：

Distilabel Pipeline

```
from pathlib import Path
from typing import Any, Dict, List, Union, Optional

from distilabel.pipeline import Pipeline
from distilabel.steps import LoadDataFromHub
from distilabel.llms import InferenceEndpointsLLM
from distilabel.steps.tasks import GenerateSentencePair
from distilabel.steps.tasks.base import Task
from distilabel.steps.tasks.typing import ChatType
from distilabel.steps import ExpandColumns, CombineKeys


multiply_queries_template = (
    "Given the following query:\n{original}\nGenerate {num_queries} similar queries by varying "
    "the tone and the phrases slightly. "
    "Ensure the generated queries are coherent with the original reference and relevant to the context of data annotation "
    "and AI dataset development."
)

class MultipleQueries(Task):
    system_prompt: Optional[str] = None
    num_queries: int = 1

    @property
    def inputs(self) -> List[str]:
        return ["query"]

    def format_input(self, input: Dict[str, Any]) -> ChatType:
        prompt = [
            {
                "role": "user",
                "content": multiply_queries_template.format(
                    original=input["query"],
                    num_queries=self.num_queries
                ),
            },
        ]
        if self.system_prompt:
            prompt.insert(0, {"role": "system", "content": self.system_prompt})
        return prompt

    @property
    def outputs(self) -> List[str]:
        return ["queries", "model_name"]

    def format_output(
        self, output: Union[str, None], input: Dict[str, Any]
    ) -> Dict[str, Any]:
        queries = output.split("- ")
        if len(queries) > self.num_queries:
            queries = queries[1:]
        queries = [q.strip() for q in queries]
        return {"queries": queries}


with Pipeline(
    name="embedding-queries",
    description="Generate queries to train a sentence embedding model."
) as pipeline:
    load_data = LoadDataFromHub(
        name="load_data",
        repo_id="plaguss/argilla_sdk_docs_raw_unstructured",
        output_mappings={"chunks": "anchor"},
        batch_size=10,
    )

    llm = InferenceEndpointsLLM(
        model_id="meta-llama/Meta-Llama-3-70B-Instruct",
        tokenizer_id="meta-llama/Meta-Llama-3-70B-Instruct",
    )

    generate_sentence_pair = GenerateSentencePair(
        name="generate_sentence_pair",
        triplet=True,  # Generate positive and negative
        action="query",
        context="The generated sentence has to be related with Argilla, a data annotation tool for AI engineers and domain experts.",
        llm=llm,
        input_batch_size=10,
        output_mappings={"model_name": "model_name_query"},
    )

    multiply_queries = MultipleQueries(
        name="multiply_queries",
        num_queries=3,
        system_prompt=(
            "You are an AI assistant helping to generate diverse examples. Ensure the "
            "generated queries are all in separated lines and preceded by a dash. "
            "Do not generate anything else or introduce the task."
        ),
        llm=llm,
        input_batch_size=10,
        input_mappings={"query": "positive"},
        output_mappings={"model_name": "model_name_query_multiplied"},
    )

    merge_columns = MergeColumns(
        name="merge_columns",
        columns=["positive", "queries"],
        output_column="positive"
    )

    expand_columns = ExpandColumns(
        columns=["positive"],
    )

    (
        load_data
        >> generate_sentence_pair
        >> multiply_queries
        >> merge_columns
        >> expand_columns
    )


if __name__ == "__main__":

    pipeline_parameters = {
        "generate_sentence_pair": {
            "llm": {
                "generation_kwargs": {
                    "temperature": 0.7,
                    "max_new_tokens": 512,
                }
            }
        },
        "multiply_queries": {
            "llm": {
                "generation_kwargs": {
                    "temperature": 0.7,
                    "max_new_tokens": 512,
                }
            }
        }
    }

    distiset = pipeline.run(
        parameters=pipeline_parameters
    )
    distiset.push_to_hub("plaguss/argilla_sdk_docs_queries")
```

### 在 Argilla 中探索数据集

如果你还没设置 Argilla 实例，别担心！按照 [docs](https://argilla-io.github.io/argilla/latest/getting_started/quickstart/#run-the-argilla-server) 里简单易懂的指南创建一个带 Argilla 的 Hugging Face Space。Space 跑起来后，只需更新 `api_url` 指向你的 Space 即可连接：

```
import argilla as rg

client = rg.Argilla(
    api_url="https://plaguss-argilla-sdk-chatbot.hf.space",

```

#### 存放技术文档切块的 Argilla 数据集

Argilla 实例就绪后，进入下一步：为数据集配置 `Settings`。好消息是，我们创建的默认 `Settings` 应该能直接适配你的具体用例，无需再做调整：

```
settings = rg.Settings(
    guidelines="Review the chunks of docs.",
    fields=[
        rg.TextField(
            name="filename",
            title="Filename where this chunk was extracted from",
            use_markdown=False,
        ),
        rg.TextField(
            name="chunk",
            title="Chunk from the documentation",
            use_markdown=False,
        ),
    ],
    questions=[
        rg.LabelQuestion(
            name="good_chunk",
            title="Does this chunk contain relevant information?",
            labels=["yes", "no"],
        )
    ],
)
```

仔细看看我们创建的数据集结构：`filename` 和 `chunk` 两个字段分别装着解析出的文件名和生成的切块。为进一步强化数据集，我们定义了一个简单的标签问题 `good_chunk`，可以手动把每个切块标为有用或无用。这种 human-in-the-loop 的方式让我们能够打磨自动生成的结果。必备要素齐备，现在可以创建数据集了：

```
dataset = rg.Dataset(
    name="argilla_sdk_docs_raw_unstructured",
    settings=settings,
    client=client,
)

### 创建存放文档切块的表

微调模型加载完毕，可以创建存 embedding 的表了。为这张表定义 schema 时，我们使用 `LanceModel`——类似 `pydantic.BaseModel`——为我们的 `Docs` 实体建立稳健的表示。

```
from lancedb.pydantic import LanceModel, Vector

class Docs(LanceModel):
    query: str = model.SourceField()
    text: str = model.SourceField()
    vector: Vector(model.ndims()) = model.VectorField()

table_name = "docs"
table = db.create_table(table_name, schema=Docs)
```

上面的代码为创建一张三列的表搭好舞台：

- `query`：专门存放合成查询
- `text`：存放切分后的文档文本
- `vector`：维度对应微调模型的输出，用于存 embedding

表结构就位后，就能与这张表交互了。

#### 填充数据表

表结构建好，可以灌数据了。加载最终的、包含查询的数据集，把它们连同对应的 embedding 写入数据库。这关键一步将让向量数据库活起来，使聊天机器人能够高效存储和检索信息：

```
ds = load_dataset("plaguss/argilla_sdk_docs_queries", split="train")

batch_size = 50
for batch in tqdm.tqdm(ds.iter(batch_size), total=len(ds) // batch_size):
    embeddings = model.generate_embeddings(batch["positive"])
    df = pd.DataFrame.from_dict({"query": batch["positive"], "text": batch["anchor"], "vector": embeddings})
    table.add(df)
```

上面的代码按 batch 迭代数据集，用微调后的模型为 `positive` 列的合成查询生成 embedding；然后创建 Pandas dataframe，包含 `query`、`text`、`vector` 三列——分别由 `positive`、`anchor` 列和新算出的 embedding 拼成。

先看 `Database` 类——聊天机器人知识与功能的脊梁。这个组件在存储和检索驱动对话的数据方面扮演关键角色：

点击查看 Database 类

```
class Database:

    def __init__(self, settings: Settings) -> None:

        self.settings = settings
        self._table: lancedb.table.LanceTable = self.get_table_from_db()

    def get_table_from_db(self) -> lancedb.table.LanceTable:

        lancedb_db_path = self.settings.LOCAL_DIR / self.settings.LANCEDB

        if not lancedb_db_path.exists():
            lancedb_db_path = download_database(
                self.settings.REPO_ID,
                lancedb_file=self.settings.LANCEDB_FILE_TAR,
                local_dir=self.settings.LOCAL_DIR,
                token=self.settings.TOKEN,
            )

        db = lancedb.connect(str(lancedb_db_path))
        table = db.open_table(self.settings.TABLE_NAME)
        return table

    def retrieve_doc_chunks(
        self, query: str, limit: int = 12, hard_limit: int = 4
    ) -> str:

        # Embed the query to use our custom model instead of the default one.
        embedded_query = model.generate_embeddings([query])
        field_to_retrieve = "text"
        retrieved = (
            self._table.search(embedded_query[0])
            .metric("cosine")
            .limit(limit)
            .select([field_to_retrieve])  # Just grab the chunk to use for context
            .to_list()
        )
        return self._prepare_context(retrieved, hard_limit)

    @staticmethod
    def _prepare_context(retrieved: list[dict[str, str]], hard_limit: int) -> str:

        # We have repeated questions (up to 4) for a given chunk, so we may get repeated chunks.
        # Request more than necessary and filter them afterwards
        responses = []
        unique_responses = set()

        for item in retrieved:
            chunk = item["text"]
            if chunk not in unique_responses:
                unique_responses.add(chunk)
                responses.append(chunk)

        context = ""
        for i, item in enumerate(responses[:hard_limit]):
            if i > 0:
                context += "\n\n"
            context += f"---\n{item}"
        return context
```

组件就位，来到准备喂给客户端的 prompt 阶段。这个 prompt 是激发机器学习模型魔法的输入，引导它生成既准确又有信息量、同时不回答无关问题的回复。本节我们深入探讨如何构造一个让模型成功的、结构良好的 prompt。`prepare_input` 函数负责准备对话，套用 prompt 和 chat template 后传给模型：

```
def prepare_input(message: str, history: list[tuple[str, str]]) -> str:

    # Retrieve the context from the database
    context = database.retrieve_doc_chunks(message)

    # Prepare the conversation for the model.
    conversation = []
    for human, bot in history:
        conversation.append({"role": "user", "content": human})
        conversation.append({"role": "assistant", "content": bot})

    conversation.insert(0, {"role": "system", "content": SYSTEM_PROMPT})
    conversation.append(
        {
            "role": "user",
            "content": ARGILLA_BOT_TEMPLATE.format(message=message, context=context),
        }
    )

    return tokenizer.apply_chat_template(
        [conversation],
        tokenize=False,
        add_generation_prompt=True,
    )[0]
```

这个函数接收两个参数：`message` 和 `history`——由 gradio 的 [`ChatInterface`](https://www.gradio.app/docs/gradio/chatinterface) 提供；从数据库获取文档片段帮助 LLM 生成回复；并准备好传给 `LLM` 模型的 prompt。

我们抵达了整个对话式 AI 系统的顶点：`chatty` 函数。它是总指挥，把此前构建的各个组件拢到一起。它的主要职责是调用 `prepare_input` 函数，打造传给客户端的 prompt。然后随文本流式生成逐个 yield；回复完成后，对话历史会被保存下来，成为供我们复盘和打磨模型的宝贵资源，确保它每一轮都在进步。

```
def chatty(message: str, history: list[tuple[str, str]]) -> Generator[str, None, None]:
    prompt = prepare_input(message, history)

    partial_response = ""

    for token_stream in client.text_generation(prompt=prompt, **client_kwargs):
        partial_response += token_stream
        yield partial_response

    global conv_id
    new_conversation = len(history) == 0
    if new_conversation:
        conv_id = str(uuid.uuid4())
    else:
        history.append((message, None))

    # Register to argilla dataset
    argilla_dataset.records.log(
        [
            {
                "instruction": create_chat_html(history) if history else message,
                "response": partial_response,
                "conv_id": conv_id,
                "turn": len(history)
            },
        ]
    )
```
