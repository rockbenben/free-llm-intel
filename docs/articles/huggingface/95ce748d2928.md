3 周前，我们展示了要在数学题上正确评估 LLM 表现有多难，并介绍了 [Math-Verify](https://github.com/huggingface/Math-Verify)——一个用于在数学上验证模型的更好方案（更多细节见[公告](https://x.com/HKydlicek/status/1881734376696041659)）！

今天，我们很高兴地宣布：我们已用 Math-Verify 对 Open LLM Leaderboard 历史上提交的全部 3,751 个模型进行了彻底重新评估，让模型对比更加公平、更加可靠！

## 为什么 Open LLM Leaderboard 的数学评估出了问题

[Open LLM Leaderboard](https://huggingface.co/spaces/open-llm-leaderboard/open_llm_leaderboard) 是 Hugging Face Hub 上使用最多的排行榜：它在多种任务上对比开源大语言模型（LLM）的表现。其中一项叫做 MATH-Hard 的任务专门考察数学题：评估 LLM 解决高中和大学水平数学题的能力。它使用 [Hendrycks MATH](https://github.com/hendrycks/math) 数据集中难度最高（Level 5）的 1,324 道题，横跨 7 个主题（预备微积分、预备代数、代数、中级代数、计数/概率和数论），采用 5-shot 方式（在提示词中给模型提供 5 个示例来演示应如何作答）。

一道典型的问题长这样：

```
For all real numbers $r$ and $s$, define the mathematical operation $\#$ such that the following conditions apply: $r\ \#\ 0 = r, r\ \#\ s = s\ \#\ r$, and $(r + 1)\ \#\ s = (r\ \#\ s) + s + 1$. What is the value of $11\ \#\ 5$?
```

答案是：

```
71
```

在排行榜中，模型必须以非常具体的字符串结束答案（遵循 [Minerva-Math 论文](https://arxiv.org/abs/2206.14858)）：

```
“Final answer is [ANSWER]. I hope it is correct.”
```

随后排行榜会用 [SymPy](https://docs.sympy.org/latest/index.html) 尝试解析 `[ANSWER]`，把它转换成符号表示（必要时还化简数值），最后与标准答案比对。

然而，用户报告了上述流程的一堆问题。

首先是反复出现的问题：一些模型无法遵循示例中期望的答案格式，而是输出其他句子来引出答案。由于格式没被遵循，即使答案实际正确也会被判定为错误！（当你真正关心的是"模型的数学有多好"时，这就是个问题了。）

| 📄 示例 | ❗️问题 | ✅ Math-Verify | 🛑 旧排行榜 |
| --- | --- | --- | --- |
| Therefore, the perimeter of one of these triangles is $14 + 7\sqrt{2}$ inches, expressed in simplest radical form. | 提取失败 | `7*sqrt(2) + 14` | None |
| Therefore, the sum of the infinite geometric series is (\frac{7}{9}). | 提取失败 | `7/9` | None |
| ( p(n) ) and ( p(n+1) ) share a common factor greater than 1 is (\boxed{41}). | 提取失败 | `4` | None |
| So it’s \frac{1}{9} | 提取失败 | `1/9` | None |
| Concluding he has \boxed{5} cars | 提取失败 | `5` | None |

下一步，把 `[ANSWER]` 转换为符号表示，也同样有问题，这次出在 SymPy 解析上：

| 📄 示例 | ❗️问题 | ✅ Math-Verify | 🛑 旧排行榜 |
| --- | --- | --- | --- |
| The final answer is $2x + 4y + z - 19 = 0$. I hope it is correct. | 参数方程只解析了一部分 | Eq(2*x + 4*y + z - 19, 0) | 0 |
| (23) | LaTeX 边界导致提取失败 | `23` | None |
| ((- \infty, -14) \cup (-3, \infty)). | 区间符号导致提取失败 | Union(Interval.open(-oo, -14), Interval.open(-3, oo)) | None |
| 100% | 非法符号导致提取失败 | `1` | None |
| \begin{pmatrix}\frac{1}{50}&\frac{7}{50}\frac{7}{50}&\frac{49}{50}\end{pmatrix} | 矩阵导致提取失败 | Matrix([[1/50, 7/50], [7/50, 49/50]]) | None |

最后一步，把提取出的答案与目标表达式比对时，也出现了一系列问题：

| 📄 示例 | ❗️问题 | ✅ Math-Verify | 🛑 旧排行榜 |
| --- | --- | --- | --- |
| 1/3 == 0.333333 | 不支持四舍五入 | True | False |
| sqrt(1/2)*7 == sqrt(0.5)*7 | 不支持数值求值 | True | False |
| k = 1 == 1 | 不支持变量赋值 | True | False |
| Matrix.ones == Matrix.ones | 不支持矩阵等价 | True | False |
| {1} \union {1,4} == {1,4} | 不支持集合比较 | True | False |

**所有这些问题，如今都已被全新的 Math-Verify 解析器彻底修复！**

## 谁的数学最强？更公平的评估让牌局彻底重洗

由于这些问题往往会累积叠加，一些模型深受其害，成绩被严重低估……于是我们移除了旧评估器、换上了 Math-Verify——改动简单到只需要 3 行代码！（你也可以在自己的数学评估里试试！）

这意味着要重新评估自 6 月以来提交的所有模型……结果让排行榜 MATH 子集的前 20 名彻底翻了天。

### 改动的冲击

平均而言，各模型全榜多解出了 **61 道题**，相当于整体分数普涨 **4.66 分**！

[![score_change](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/math_verify_leaderboard/score-change.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/math_verify_leaderboard/score-change.png)

提升最显著的两个子集都与代数相关（Algebra 和 Prealgebra），分别提高了 **8.27** 和 **6.93**。极端情况下，一些模型在这些子集上的提升接近 **90** 分。我们认为这两个子集进步最大，是因为它们的答案经常以集合（一题多解）和矩阵形式呈现。Math-Verify 对这两类答案的处理都做了增强，从而带来了这些显著的提升。

[![subset_change](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/math_verify_leaderboard/subset-change.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/math_verify_leaderboard/subset-change.png)

### 模型家族的变化

我们最初是在检查 Qwen 模型时发现数学评估问题的——它们的分数与自报表现相比异常地低。引入 Math-Verify 后，这些模型的分数翻了一倍多，说明此前的表现被严重低估了。

但 Qwen 不是孤例。另一个受影响的大家族是 **DeepSeek**。换用 Math-Verify 后，DeepSeek 模型的分数几乎翻了三倍！因为它们的答案通常包在 `(\boxed{})` 记号里，而旧评估器无法提取。[![model_family_change](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/math_verify_leaderboard/model-family-change.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/math_verify_leaderboard/model-family-change.png)

### MATH-Hard 排行榜的变化

如开头所说，前 20 名的排名发生了重大变动，**Nvidia 的 AceMath** 系列模型如今在 MATH-Hard 排行榜上占据统治地位。这次改动的其他大赢家是 **Qwen** 衍生模型，它们现在几乎垄断了紧随 AceMath 之后的位次。下面是新旧前 20 名完整对比表：

[![math_hard_leaderboard_change](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/math_verify_leaderboard/math-hard-change.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/math_verify_leaderboard/math-hard-change.png)

### 总榜的变化

最后，我们检视了整体排行榜结果的演化。虽然前四位岿然不动，其余位次却经历了剧烈变动。由于多个 Qwen 衍生模型在 MATH 子集上崛起，Qwen 系模型在前 20 中的存在感在总体结果中变得更强。[![leaderboard_change](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/math_verify_leaderboard/overal-change.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/math_verify_leaderboard/overal-change.png)

还有许多模型在排名中直接跃升了 200 名以上！你可以在 [Open LLM Leaderboard](https://huggingface.co/spaces/open-llm-leaderboard/open_llm_leaderboard#/) 查看更详细的结果。

## 小结

Math-Verify 的引入显著提升了我们在 Open LLM Leaderboard 上评估的准确性与公平性。这带来了排行榜的大洗牌，许多模型的分数出现了实质性提升。

我们鼓励所有开发者和研究人员在自己的数学评估中采用 Math-Verify。这样做，你可以确保模型得到更可靠的评估结果。同时也欢迎你查看更新后的排名，看看你心爱的模型表现有了怎样的变化。
