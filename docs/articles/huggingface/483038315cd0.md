现在，大语言模型可以在零样本分类任务上通过 [Evaluation on the Hub](https://huggingface.co/spaces/autoevaluate/model-evaluator) 进行评估了！

零样本评估是研究者衡量大语言模型性能的流行方式，因为已有[研究证明](https://arxiv.org/abs/2005.14165)，模型在训练中无需显式见过标注样本就能习得能力。[Inverse Scaling Prize](https://github.com/inverse-scaling/prize) 就是一次近期的社区大规模零样本评估努力：跨模型规模与家族进行评测，以发现大模型可能反而不如小模型的任务。

[![dataset](https://huggingface.co/blog/assets/106_zero_shot_eval_on_the_hub/zeroshot.jpg)](https://huggingface.co/blog/assets/106_zero_shot_eval_on_the_hub/zeroshot.jpg)

## 在 Hub 上实现语言模型的零样本评估

[Evaluation on the Hub](https://huggingface.co/blog/eval-on-the-hub) 帮你无需写代码即可评估 Hub 上的任何模型，由 [AutoTrain](https://huggingface.co/autotrain) 驱动。现在，Hub 上的任何因果语言模型都可以做零样本评估。零样本评估衡量训练模型生成给定 token 序列的可能性，不需要任何有标注的训练数据，让研究者得以省掉昂贵的标注工作。

我们为这个项目升级了 AutoTrain 基础设施，使大模型可以**免费**评估 🤯！对用户来说，想办法写自定义代码在 GPU 上评估大模型既昂贵又耗时。例如，一个 660 亿参数的语言模型光是加载和编译就可能要 35 分钟，使得大模型评估只有拥有昂贵基础设施和丰富技术经验的人才能做。有了这些改动，在一个含 2000 条句子长度样本的零样本分类任务上评估 660 亿参数的模型只需 3.5 小时，任何社区成员都能完成。Evaluation on the Hub 目前支持最高 660 亿参数的模型评估，更大模型的支持也在路上。

零样本文本分类任务接收一个数据集，其中包含一组提示（prompt）和候选补全（completion）。在底层，补全与提示拼接，对每个 token 的对数概率求和，再做归一化并与正确补全比较，从而报告任务准确率。

在这篇博文中，我们将用零样本文本分类任务在 [WinoBias](https://uclanlp.github.io/corefBias/overview) 上评估多个 [OPT](https://ai.facebook.com/blog/democratizing-access-to-large-scale-language-models-with-opt-175b/) 模型——WinoBias 是一个衡量与职业相关性别偏差的共指任务。WinoBias 衡量模型是否更倾向在提及某个职业的句子中选择刻板印象代词；我们观察到其结果呈现出随模型规模的[逆缩放](https://github.com/inverse-scaling/prize)趋势。

## 案例研究：在 WinoBias 任务上做零样本评估

[WinoBias](https://github.com/uclanlp/corefBias) 数据集已被格式化为零样本任务：分类选项即补全。每个补全只差在代词上，target 是该职业的反刻板印象补全（例如「developer」在刻板印象中是男性主导职业，所以 "she" 是反刻板印象代词）。示例见[这里](https://huggingface.co/datasets/mathemakitten/winobias_antistereotype_test)：

[![dataset](https://huggingface.co/blog/assets/106_zero_shot_eval_on_the_hub/dataset.png)](https://huggingface.co/blog/assets/106_zero_shot_eval_on_the_hub/dataset.png)

接下来，我们可以在 Evaluation on the Hub 界面中通过 `text_zero_shot_classification` 任务选中这个新上传的数据集，选择要评估的模型，提交评估任务！任务完成后，你会收到邮件通知：autoevaluator 机器人已在模型的 Hub 仓库中开了一个带结果的新 pull request。

[![Evaluation on the Hub](https://huggingface.co/blog/assets/106_zero_shot_eval_on_the_hub/eval_hub.png)](https://huggingface.co/blog/assets/106_zero_shot_eval_on_the_hub/eval_hub.png)

绘制 WinoBias 任务的结果可以发现：越小的模型越可能为句子选择反刻板印象代词，而越大的模型越容易学到文本中性别与职业之间的刻板关联。这与其他基准的结论一致（例如 [BIG-Bench](https://arxiv.org/abs/2206.04615) 显示更大、能力更强的模型在性别、种族、族裔和国籍上更可能有偏差），也与[既有研究](https://www.deepmind.com/publications/scaling-language-models-methods-analysis-insights-from-training-gopher)（表明大模型更可能生成有害文本）相符。

[![Winobias](https://huggingface.co/blog/assets/106_zero_shot_eval_on_the_hub/winobias.png)](https://huggingface.co/blog/assets/106_zero_shot_eval_on_the_hub/winobias.png)

## 为每个人提供更好的研究工具

开放科学在社区驱动的工具开发上取得了长足进步，例如 EleutherAI 的 [Language Model Evaluation Harness](https://github.com/EleutherAI/lm-evaluation-harness) 与 [BIG-bench](https://github.com/google/BIG-bench) 项目，让研究者能直接理解最先进模型的行为。

Evaluation on the Hub 是一个低代码工具，让沿 FLOPS 或模型规模等维度对比一组模型的零样本性能变得简单，也让对比在不同语料上训练的两组模型的性能变得简单。零样本文本分类任务极为灵活——任何能被整理成 Winograd schema（待比较样本仅相差几个词）的数据集都可以用于该任务并同时评估许多模型。我们的目标是让上传新评估数据集保持简单，让研究者能轻松用它给许多模型做基准。

这类工具能回答的一个典型研究问题就是逆缩放问题：虽然大模型在多数语言任务上普遍更强，但也有些任务上大模型表现更差。[Inverse Scaling Prize](https://github.com/inverse-scaling/prize) 是一项鼓励研究者构造「大模型输给小模型」任务的竞赛。我们鼓励你在各种规模的模型上用自己的任务尝试零样本评估！如果你发现沿模型规模的有趣趋势，考虑把你的发现提交到 [Inverse Scaling Prize](https://github.com/inverse-scaling/prize) 第二回合。
