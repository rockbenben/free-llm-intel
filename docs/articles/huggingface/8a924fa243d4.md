## 引言

欢迎回来 👋

在前两篇（[Part 1](https://huggingface.co/blog/Photoroom/prx-part1-architectures) 和 [Part 2](https://huggingface.co/blog/Photoroom/prx-part2)）里，我们探索了大量针对 diffusion 模型的架构与训练技巧。我们尝试逐一孤立地评估每个想法，测量吞吐量、收敛速度和最终图像质量，试图理解到底什么才真正起作用。

在这篇里，我们想回答一个实际得多的问题：

**当我们把所有有效的技巧组合起来会发生什么？**

我们不再一次只优化一个维度，而是把最有希望的原料叠加在一起，看在严格的算力预算下能把性能推到多远。

为了让事情具体，我们做了一场 **24 小时 speedrun**：

- **32 张 H200**
- 总算力预算约 **1500 美元（2 美元/小时/GPU）**

这与早期 diffusion 时代相去甚远——那时训练一个有竞争力的模型可能要花数百万美元。这里的目标是展示这个领域进化了多少，以及在一个训练日里，精细的工程能带你走多远。

这场 speedrun 不只是好玩的实验。它很可能成为我们今后大规模训练配方的基础。

除了结果，我们还开源了代码（[Github 链接](https://github.com/Photoroom/PRX)），其中包含：

- 本次 speedrun 使用的训练代码
- 前几篇博客中的实验框架

所以你可以自行复现、修改和扩展一切。

## 训练配方

现在我们逐步看看这场 24 小时 run 里都用上了什么。

### X-prediction 与像素空间训练

我们采用 *Back to Basics: Let Denoising Generative Models Denoise* [[Li and He, 2025](https://arxiv.org/abs/2511.13720)] 的 x-prediction 表述。正如 [Part 2](https://huggingface.co/blog/Photoroom/prx-part2) 所见，这使得**直接在像素空间训练成为可能，并且完全不需要 VAE**。我们使用 32 的 patch size，并在初始 token 投影层用一个 256 维的 bottleneck。这个设计把序列长度控制在合理范围，让像素空间训练即使在更高分辨率下计算量也可管理。

在 512px 下，序列长度为：

(512 / 32)^2 = 256

在 1024px 下，序列长度变为：

(1024 / 32)^2 = 1024

我们没有遵循常见的 256px → 512px → 1024px 调度，而是直接从 512px 开始，然后在 1024px 上微调。

在 token 数量可控、硬件现代化的条件下，像素空间训练不再高不可攀。它只是一个更干净、更直接的表述。

### 感知损失

在像素空间直接预测 x_0 有一个非常美妙的副作用：我们可以复用经典计算机视觉的一整箱工具。

当你的模型输出 latent 时，感知监督会变得别扭：要么解码回像素，要么在一个未必与人类感知对齐的学习到的 latent 空间里定义损失。一旦直接预测像素，一切又变得顺理成章。你可以按感知损失原本的设计原样接入。

我们从论文 *PixelGen: Pixel Diffusion Beats Latent Diffusion with Perceptual Loss* [[Ma et al.](https://arxiv.org/abs/2602.02493)] 获得启发，作者在 diffusion loss 之上引入了额外的感知目标。他们表明加入感知信号可以显著提升收敛速度和最终视觉质量。

在这场 24 小时 run 中，我们加了两个辅助损失：

- **LPIPS**（[[Zhang et al.](https://arxiv.org/abs/1801.03924)]）
- 一个**基于 DINO 的感知损失**（我们使用 DINOv2 [[Oquab et al.](https://arxiv.org/abs/2304.07193)]）

思路很简单：在标准 flow matching 目标之外，我们鼓励预测出的干净图像在感知特征空间上匹配目标图像。LPIPS 捕捉低层感知相似性，而 DINO 特征提供更强的语义信号。

我们沿用论文的整体思路，但微调了几个细节。实验中我们经验性地发现，以下做法效果更好：

- 在池化后的整幅图像上（而不是 patch 级特征上）应用感知损失
- 在所有噪声水平上应用它们

这些都是小的实现细节，但在我们的设置中它们持续带来更好的结果。

我们对 LPIPS 损失使用权重 **0.1**，对 DINO 感知损失使用 **0.01**，与原论文推荐的数值一致。

相比主 transformer 的前向传播，这些损失很轻量，在我们的设置里只增加一点开销，却带来一致的质量提升。

### 用 TREAD 做 Token 路由

为了让每一步更便宜，我们使用 *TREAD* [[Krause et al., 2025](https://openaccess.thecvf.com/content/ICCV2025/papers/Krause_TREAD_Token_Routing_for_Efficient_Architecture-agnostic_Diffusion_Training_ICCV_2025_paper.pdf)] 的 token 路由：随机选择一部分 token，让它们绕过一段连续的 transformer block，之后再重新注入，因此不会丢弃任何东西。

相比 SPRINT（[Park et al., 2025](https://arxiv.org/pdf/2510.21986)），我们选 TREAD 主要因为简单；而且在我们的设置里（512px 下 TREAD 的序列长度是 64 对 128），SPRINT 多出来的复杂度换来的那一点算力节省不值得。

按照 TREAD 配方，我们让**第二个 block** 把 **50% 的 token** 路由到 transformer 的**倒数第二个 block**。

路由模型在 vanilla CFG 下可能看起来更差，尤其在训练不足时，所以我们实现了一个受 Guiding Token-Sparse Diffusion Models（[Krause et al., 2025](https://arxiv.org/abs/2601.01608)）启发的简单 self-guidance 方案：用 dense 与 routed 的条件预测做引导，而不是依赖无条件分支。

### 用 REPA 与 DINOv3 做表征对齐

我们使用 **REPA** [[Yu et al., 2024](https://arxiv.org/abs/2410.06940)] 做表征对齐。

教师模型选了 **DINOv3** [[Siméoni et al. 2025](https://arxiv.org/abs/2508.10104)]，因为它在我们此前的实验中带来了最好的质量提升。

具体来说，我们在**第 8 个 transformer block** 施加一次对齐损失，损失权重 **0.5**。

由于把 **REPA** 与 **TREAD** 路由结合，我们只在**未被路由的 token**（即真正经过施加损失的那些 block 的 token）上计算对齐损失。这让 REPA 信号保持一致，避免对跳过了计算路径的 token 比较特征。

### 优化器：Muon

我们使用 **Muon** 优化器，采用 [muon_fsdp_2](https://github.com/samsja/muon_fsdp_2) 的 FSDP 实现，因为它在我们之前的 run 中相对 Adam 有明显提升。

Muon 只作用于 **2D 参数**（基本就是矩阵）。其他一切（偏置、norm、embedding 等）用 Adam 优化，这就是配置中有两个参数组的原因。

| 组 | 作用于 | 我们使用的关键参数 |
| --- | --- | --- |
| **Muon** | 2D 参数 | `lr=1e-4`, `momentum=0.95`, `nesterov=true`, `ns_steps=5` |
| **Adam** | 所有非 2D 参数 | `lr=1e-4`, `betas=(0.9, 0.95)`, `eps=1e-8` |

## 训练设置

我们在三个公开可用的合成数据集上训练：

- **Flux generated**（1.7M），[lehduong/flux_generated](https://huggingface.co/datasets/lehduong/flux_generated)
- **FLUX-Reason-6M**（6M），[LucasFang/FLUX-Reason-6M](https://huggingface.co/datasets/LucasFang/FLUX-Reason-6M)
- **midjourney-v6-llava**（1M），[brivangl/midjourney-v6-llava](https://huggingface.co/datasets/brivangl/midjourney-v6-llava)——我们用 **Gemini 1.5** 重新生成了 caption，让提示词更一致、削减标注噪声。

调度基本就是：512 先跑快，1024 再磨锐：

- **512px** 训练 **100k steps**，**batch size 1024**
- **1024px** 训练 **20k steps**，**batch size 512**，不使用 **REPA**

我们还为权重保留一份**EMA**用于采样和评估：

- `smoothing = 0.999`
- `update_interval = 10ba`
- `ema_start = 0ba`

## 结果与结语

下面是整场 run 中跟踪的评估曲线，以及最终 checkpoint 的一些样例网格：

[![image](https://cdn-uploads.huggingface.co/production/uploads/68e529af513e724edd8702f6/s2-rKg3fqtGefcBXmNFHJ.png)](https://cdn-uploads.huggingface.co/production/uploads/68e529af513e724edd8702f6/s2-rKg3fqtGefcBXmNFHJ.png)

对于一场只训练一天的 run，这已经是个相当扎实的位置。模型还不完美（你仍能看到一些纹理故障、偶尔奇怪的人体结构，在非常难的提示词上会有点不稳），但它明显可用。遵循提示词的能力很强，整体审美一致，而 1024 阶段基本达到了我们的意图：在不破坏构图的前提下锐化细节。

关键收获是：我们已经非常接近了。剩下的问题看起来更像训练不足的产物和数据多样性有限，而不是配方存在结构性缺陷的信号。这些失败模式与「一个还没见过足够多样数据的模型」的预期一致。只要更多算力、更广覆盖，这套完全相同的配置应该会相当可预期地继续提升。

往大了看，这场 speedrun 也凸显了 diffusion 训练已经走了多远。把像素空间训练、高效路由、表征对齐和轻量感知引导结合起来，如今在一天左右就能得到一个有意义的模型——预算放在不久前还会听起来不切实际。
