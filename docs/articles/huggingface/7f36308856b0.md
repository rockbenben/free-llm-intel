> Inkling 现在有了更小尺寸 🤗 Thinking Machines Lab 发布了 Inkling-Small。我们更新了本文的性能数据，以及 Inkling-Small 和 Inkling-Small-NVFP4 两个变体的部署配置。所有 Inkling 模型见[这个合集](https://huggingface.co/collections/thinkingmachines)。我们还让你在 Inference Endpoints 上一键部署 Inkling-Small（最高可达 160 TPS），并上线了一个实时语音+图像 demo，你可以直接与模型互动。

[Inkling](https://huggingface.co/thinkingmachines/Inkling) 是一个大型（1T 参数！）开放模型，原生接受图像、文本和音频输入。

TLDR; Thinking Machines 的 Inkling 已在 Hugging Face 发布。Inkling 是一个超大多模态 LLM，理解所有模态（图像、音频、文本），具备智能体能力，支持 1M 上下文。它提供完整 BF16 和精心校准的 NVFP4 两个变体，并内置推测式 MTP 层以加速推理。transformers、SGLang、vLLM 和 llama.cpp 均提供 day-0 支持。Thinking Machines Lab 还发布了 Inkling-Small：总参数 276B、激活参数 12B，同样支持 MXFP8 和 NVFP4 权重，架构与 Inkling 相同。

## Inkling 特别在哪？

Inkling 是第一个 **~1T 参数**、**1M 上下文窗口**、原生接收**图像、文本和音频输入**的大型开放模型，训练数据为 **45 万亿 token 的文本、图像、音频和视频**。它专注于跨音频、图像、文本等模态的推理，面向通过微调做领域适配。我们把玩了一下这个模型、做了一些 demo 并探索了它的架构——我们认为它很适合构建新一波多模态推理应用。

## 总体能力与架构

Inkling 是一个 decoder-only 的多模态 Mixture-of-Experts 模型，总参数 975B、激活参数 41B。里面门道很多，我们逐块拆解：

- Decoder-only：架构支持因果自回归生成，与大多数最先进 LLM 相同。
- 多模态：模型能吸收文本、音频和图像。
- Mixture of Experts (MoE)：每一层内部的前馈网络是稀疏的，推理更快，因为任意时刻只有 41B 参数被激活。模型有 256 个 expert，后面会看到。

先快速看一眼架构。

**相对注意力（Relative attention）**：Inkling 没有用常见的给 transformer 注入位置信息的方法 RoPE，而是用相对注意力来编码位置信息。每个注意力层直接在注意力 logits 中学习位置。除 key-query-value 外，还有第四个投影产生逐 token、逐头的相对特征 R。这个投影张量随后用距离信息（key 向量和 query 向量之间的距离）调整，再传入注意力模块。

[![Inkling relative attention architecture](https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/relative_attention.png)](https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/relative_attention.png)

**混合注意力（Hybrid attention）**：decoder 层在全注意力（一次关注整个上下文长度）和滑动窗口注意力（以滑动方式关注固定上下文窗口）之间交替。架构采用 5:1 的滑动窗口到全注意力层配比。这种混合注意力方案带来了计算效率。最后一层使用全注意力，帮助构建特征丰富的表示。

**短卷积（Short convolution）**：模型在隐藏状态上使用了独特的短 1D 卷积 `SConv`。SConv 读取当前 token 和前 `W-1` 个隐藏状态，`W` 为滑动窗口大小。这里的直觉是：SConv 辅助局部注意力，从而把注意力模块和 MoE 模块从局部表示中解放出来。

[![Inkling short convolution architecture](https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/sconv.png)](https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/sconv.png)

**带共享 expert 汇聚点的 MoE（MoE with shared experts sink）**：在 Inkling 中，路由器既给 routed experts 打分，也给 shared experts 打分。Top-k 选择基于 6 个 expert 外加 2 个始终激活的共享 expert。

**视觉理解**：模型包含一个简单的分层 MLP patchifier，由若干线性层构成。每层逐步合并像素，直到最后一层为每个 patch 产出一个嵌入。

**音频理解**：架构采用离散化的 mel 频谱图：每个音频块（100 ms）先转到 mel 尺度，再被分类到具体的 mel 频谱 bin。

与那些为每种模态配备独立 encoder 的模型不同，这些多模态塔是相对简单的模块。每个图像 patch 经过图像嵌入塔、每个音频块经过音频嵌入塔得到各自的媒体嵌入。图像输入还额外带一个时间维度用于视频处理。我们预计这个能力对下游微调有用，但尚未评估开箱即用的视频性能。塔把 patch 网格折叠：一小块相邻 token 堆叠到通道维度后过 hMLP。音频波形先转成 mel 尺度，再被分类到离散的 mel bin。这些 mel bin 值在音频嵌入塔里做嵌入，然后相加构造最终的音频输入。

## 推理支持

Inkling 带有 day-0 的 transformers 支持，也被 SGLang、vLLM 等主流推理引擎支持。

这个模型非常大。BF16 检查点需要 2 TB 显存，NVFP4 版本需要 600 GB 显存。你可以通过 Inference Providers 这类无服务器推理路由来体验模型，也可以用 ggml 量化配合 llama.cpp 做本地部署。

### Transformers

直接用 `transformers` 推理最简单的方式是使用 `any-to-any` pipeline。你可以在 Hopper 及更新架构的 GPU 上用 16 bit 的 `"thinkingmachines/Inkling"`，或在 Blackwell Nvidia GPU 上用量化检查点 `"thinkingmachines/Inkling-NVFP4"`。请确保 transformers 是最新版本（5.14.0 今天刚发布）（`pip install -U transformers`）。

```
from transformers import pipeline

model_id = "thinkingmachines/Inkling"
# model_id = "thinkingmachines/Inkling-NVFP4"

pipe = pipeline("any-to-any", model=model_id)
```

pipeline 初始化后，可以这样传入提示词。

```
image_url = (
    "https://huggingface.co/datasets/merve/vl-test-suite/"
    "resolve/main/pills.jpg"
)
messages = [
    {
        "role": "user",
        "content": [
            {
                "type": "image",
                "image": image_url,
            },
            {
                "type": "text",
                "text": "Do components in this supplement interact with each other?",
            },
        ],
    },
]
output = pipe(
    messages,
    max_new_tokens=2000,
    return_full_text=False,
    reasoning_effort="medium",
)
output[0]["generated_text"]
```

再往下走一层，可以使用 Auto 类。推理时，模型用 `AutoModelForMultimodalLM` 类，处理器用 `AutoProcessor` 类。针对不同推理任务，tokenizer 接受一个 `reasoning_effort` 参数，现有选项为 `"none"`、`"minimal"`、`"low"`、`"medium"`、`"high"`、`"xhigh"` 和 `"max"`。

```
from transformers import AutoModelForMultimodalLM, AutoProcessor

model_id = "thinkingmachines/Inkling"
processor = AutoProcessor.from_pretrained(model_id)
model = AutoModelForMultimodalLM.from_pretrained(
    model_id,
    dtype="auto",
    device_map="auto",
)

messages = [
    {"role": "system", "content": "You should only answer with a number."},
    {"role": "user", "content": "What is 17 * 23?"},
]

inputs = processor.apply_chat_template(
    messages,
    add_generation_prompt=True,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
    reasoning_effort="high",
).to(model.device)

output = model.generate(**inputs, max_new_tokens=2000)
generated_tokens = output[0][inputs["input_ids"].shape[1] :]
print(processor.decode(generated_tokens, skip_special_tokens=False))
```

### SGLang

SGLang 是发布时 Inkling 最快的部署框架之一，因为它包含了定制的模型实现。下面的启动命令把模型切分到 8 张 GPU 上，并在 30000 端口提供 OpenAI 兼容 API。

```
pip install sglang

python3 -m sglang.launch_server \
 --model-path thinkingmachine/Inkling \
 --tp-size 8 \
 --served-model-name inkling \
 --host 0.0.0.0 \
 --port 30000
```

把 `--tp-size` 设置为你的 GPU 数量。如果需要给 KV cache 留更多余量，加上 `--mem-fraction-static`（例如 `0.85`）。

### vLLM

vLLM 在生产服务上很强。一条 `vllm serve` 命令就会从 Hub 下载权重、用张量并行把模型切到你的 GPU 上，并在 8000 端口启动 OpenAI 兼容服务器。你可以在[这里](https://recipes.vllm.ai/thinkingmachines/Inkling)查看该模型的 vLLM Recipe，按你的硬件定制。

```
# Requires nightly or vllm>=0.26 (once released)
uv pip install -U vllm --pre \
  --extra-index-url https://wheels.vllm.ai/nightly/cu130 \
  --extra-index-url https://download.pytorch.org/whl/cu130 \
  --index-strategy unsafe-best-match

vllm serve thinkingmachines/Inkling-NVFP4 \
  --trust-remote-code \
  --tokenizer-mode inkling \
  --tensor-parallel-size 8 \
  --enable-auto-tool-choice \
  --tool-call-parser inkling \
  --reasoning-parser inkling \
  --served-model-name inkling
```

实际场景中，你可能需要多个节点和一个像 SLURM 这样的分发工具（见下文）。关键参数是 `--tensor-parallel-size`，设为你节点上的 GPU 数量；如果碰到 KV-cache 内存上限，用 `--max-model-len` 限制上下文窗口。

```
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "inkling",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

### 用 Hugging Face Inference Providers 做远程推理

你可以通过 Hugging Face 用多家推理服务商推理这个模型。各种消费方式的代码片段见[这里](https://huggingface.co/thinkingmachines/inkling?inference_provider=fastest&language=python&client=openai&inference_api=true)。下面是使用 OpenAI 客户端的方式。

```
import os

from openai import OpenAI

client = OpenAI(
    base_url="https://router.huggingface.co/v1",
    api_key=os.environ["HF_TOKEN"],
)

completion = client.chat.completions.create(
    model="thinkingmachines/Inkling:auto",
    messages=[
        {
            "role": "user",
            "content": "What is the capital of France?",
        },
    ],
)

print(completion.choices[0].message)
```

使用 `“:auto”` 后缀会路由到你设置中首选的服务商；也可以用 `“cheapest”` 或 `“:fastest”`。本次发布期间，我们为大家承担 2 小时内的推理费用。

注：Inference Providers 的音频支持还在开发中，很快就会上线。

### 用 llama.cpp 和 Unsloth 做本地推理

你可以在受限硬件上用 `llama.cpp` 运行模型的量化版本。Unsloth 已把模型量化到 1-bit 精度，相比原始模型显存消耗降低 95%。

```
llama serve -hf unsloth/inkling-GGUF:UD-IQ1_S
```

这会启动一个运行在 [`http://localhost:8080`](http://localhost:8080)`/v1` 的 OpenAI 兼容服务器，你可以用自己喜欢的工具或客户端连接。打开后就能和模型聊天、接入你最爱的 MCP、方便地传入图片或文件等等！

### 多 Token 预测起草器（Multi Token Prediction Drafters）

MTP 在模型上添加了额外的层，一次预测多个 token 而不只是下一个。推理时，这些额外的层充当推测解码的"起草器（drafters）"，在不损害性能的前提下加速生成。用 MTP，你得到完全相同的生成输出，生成速度成倍提升，只付出很小的显存代价（用于运行起草器）。Thinking Machines 在本次发布中也提供了 MTP drafter。

```
import torch
from transformers import AutoModelForMultimodalLM, AutoProcessor

processor = AutoProcessor.from_pretrained("thinkingmachines/Inkling")
model = AutoModelForMultimodalLM.from_pretrained(
    "thinkingmachines/Inkling",
    dtype=torch.bfloat16,
    device_map="auto",
)

# Preprocess the inputs.
...
generated = model.generate(
    **inputs,
    max_new_tokens=1000,
    do_sample=False,
    use_mtp=True,
)
print(processor.decode(generated[0], skip_special_tokens=True))
```

### 多模态视觉

我们从一个专家级来源和大学入学考试中整理了一小组推理题。截图时我们对着屏幕拍照并保留水印，以此给模型出难题。模型在高推理档全部解出，在最高档和 medium 档各失败一题。我们把模型答案链接放出来，供你查看模型的表现，并给出它解每道题消耗的 token 数。注意：这些 vibe eval 我们没有提供任何 system prompt，而这类推理问题通常应当配上好的 system prompt 来跑。Vibe eval 的图片和结果在[这里](https://huggingface.co/buckets/merve/inkling)。

| 类别 | 问题 | Token 数（推理档 Medium） | Token 数（推理档 High） | Token 数（推理档 Max） |
| --- | --- | --- | --- | --- |
| 开放式药物相互作用 | 这里的哪些成分会相互作用？ | 1,893 ✅ | 2,367 ✅ | 3,688 ✅ |
| 物理题（MMMU-Pro） | 回答图中的问题。 | 1,357 ✅ | 3,323 ✅ | 3,314 ✅ |
| 多语言物理题 | 回答图中给出的土耳其语问题。 | 1,435 ✅ | 2,129 ✅ | 3,162 ✅ |
| 律师资格考试题 | 回答图中的问题。 | 1,117 ✅ | 2,137 ✅ | 1,676 ✅ |
| 信息图问答（开放式） | 根据图中信息，预计北极夏季变暖周期大约是已观测到显著北极变暖时长的多少倍？ | 1,378 ❌ | 3,859 ✅ | 6000（超出 token 预算） |

**一些 vibe 观感：**

- 模型没有直接回答信息图的问题，而是先把图上文字转成文本来自我定位。
- 在推理中，提示词对省 token 影响很大。例如拿着药瓶背面的图问"哪些成分会相互作用？"这种含糊的问题，模型得先弄明白我们说的"相互作用"是什么意思。
- 选择题（MCQA）的作答形式很大程度上帮助模型组织自己的推理；开放式问题上模型则相对吃力——不过这是许多模型的通病。常见的思维链是：OCR → 刻画问题 → 逐个评估选项 → 作答。
- 0.7 的推理档（medium）看起来是个不错的折中。

**一些 vibe 观感：**

- 与视觉类似，模型先转写语音，再回答问题。
- 它能顶住干扰项：俄语测试中，尽管其他选项在音频里也出现过，模型仍选对了答案。
- 与视觉类似，常见思维链是：转写 → 刻画问题 → 逐个评估选项 → 作答。
- 推理档帮的是推理而不是"听力"。音频问答比图像题便宜得多。

### 后训练

如果你想对 Inkling 做后训练，Thinking Machines 做了 `tinker`——一个用于开源权重模型后训练的托管工具。他们的 cookbook 包含微调、蒸馏和强化学习的示例。

我们用 tinker 和 OpenEnv（一个智能体 RL 环境工具）对 Inkling 做了后训练。我们使用了 ECHO 算法：在没有 verifier 的情况下训练模型预测环境，对由环境产生的 token 施加下一 token 交叉熵损失，同时照常基于智能体动作做策略学习。这让策略学到隐式世界模型，无需单独的模型、教师或额外 rollout。示例见[这里](https://github.com/huggingface/OpenEnv/blob/main/examples/echo_world_model/backends/tinker_echo_demo.py)。

[![Inkling post-training metrics](https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/trackio.png)](https://huggingface.co/buckets/huggingface/inkling-blog-assets/resolve/trackio.png)

用 Tinker 和 OpenEnv 做 RL 的示例

```
git clone https://github.com/huggingface/OpenEnv.git
cd OpenEnv

# Add TINKER_API_KEY=... to .env, then run:
uv run --env-file .env \
  examples/echo_world_model/backends/tinker_echo_demo.py
```

如果你在用 Transformers Reinforcement Learning，我们建议把 Inkling 作为知识蒸馏设置里的 teacher 模型。例如，利用 Inkling 的文档理解能力提升一个更小的（端侧）模型的性能。在[这个示例](https://github.com/huggingface/trl/blob/main/examples/gold_chatbot_arena/gold_chatbot_arena.py)中，我们用 transformers reinforcement learning 库和 GOLD 算法做知识蒸馏。GOLD 在这里很好用，因为它能在不同 tokenizer 之间匹配 token logits，因此你可以蒸馏到 hub 上的任何模型。
