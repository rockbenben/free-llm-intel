## 什么是物体检测？

在计算机视觉领域，物体检测指的是在一幅图像中识别并定位各个物体的任务。不同于图像分类——其任务是判定图像里占主导的物体或场景——物体检测不仅对存在的物体类别进行分类，还提供空间信息，在每个检测到的物体周围画出边界框。物体检测器还能为每次检测输出一个"score"（或"confidence"）。它代表按模型之见，该检测到的物体属于每个边界框所预测类别的概率。

比如下面这张图展示了五次检测：一次"ball"，置信度 98%；四次"person"，置信度分别为 98%、95%、97% 和 97%。

图 1：物体检测器输出的示例。

物体检测模型用途广泛，在众多领域有广泛应用。一些用例包括自动驾驶车辆的视觉、人脸检测、监控与安全、医学影像、增强现实、运动分析、智慧城市、手势识别等等。

Hugging Face Hub 上有[数百个物体检测模型](https://huggingface.co/models?pipeline_tag=object-detection)，在不同数据集上预训练，能够识别并定位各种物体类别。

物体检测模型里有一类特别的，叫 *zero-shot*，它可以接收额外的文本查询来搜索文本中描述的目标物体。这些模型能检测训练时没见过的物体，而不受限于训练时所用的类别集合。

检测器的多样性不止于它们能识别的输出类别范围。它们在底层架构、模型大小、处理速度和预测精度上各不相同。

一个用于评估物体检测模型预测精度的流行指标是**平均精度（Average Precision，AP）**及其变体，本文后面会解释。

评估一个物体检测模型涉及多个组成部分，比如带真值标注的数据集、检测结果（输出预测）和指标。图 2 的示意图描述了这一过程：

图 2：传统物体检测模型评估流程的示意图。

首先，选定一个含带真值边界框标注图像的基准数据集，并将其输入物体检测模型。模型为每张图像预测边界框，并为每个框分配相应的类别标签和置信度分数。在评估阶段，这些预测边界框会与数据集中的真值框进行比较。评估得出一组指标，每个取值在 [0, 1] 之间，反映某个具体的评估准则。下一节我们会深入指标的计算细节。

### 什么是平均精度，如何计算？

平均精度（AP）是一个汇总 Precision x Recall 曲线的单一数字。在解释如何计算它之前，我们先要理解交并比（IoU）的概念，以及如何把一次检测归类为真阳性或假阳性。

IoU 是一个 0 到 1 之间的数，衡量预测边界框与实际（真值）边界框的重叠程度。其计算方式是两个框重叠区域的面积除以两个框合计覆盖的面积。图 3 用一个预测框和对应真值框的例子直观演示了 IoU。

图 3：一次检测（绿色）与真值（蓝色）之间的交并比（IoU）。

如果真值框和检测框坐标完全一致、代表图像中同一区域，它们的 IoU 值为 1。反之，如果两个框在任一像素上都不重叠，IoU 被视为 0。

在期望检测具有高精度的场景里（如自动驾驶车辆），预测边界框应当与真值框紧密对齐。为此，偏好一个接近 1 的 IoU 阈值（ TIOU \text{T}_{\text{IOU}} TIOU​ ）。而对于检测框相对目标物体的精确位置并不关键的应用，阈值可以放宽，把 TIOU \text{T}_{\text{IOU}} TIOU​ 设得接近 0。

模型预测的每个框都被视为一次"阳性"检测。交并比（IoU）准则根据我们定义的置信度阈值，把每次预测分类为真阳性（TP）或假阳性（FP）。

基于预定义的 TIOU \text{T}_{\text{IOU}} TIOU​，我们可以定义真阳性和假阳性：

- **真阳性（TP）**：一次正确的检测，IoU ≥ TIOU \text{T}_{\text{IOU}} TIOU​。
- **假阳性（FP）**：一次错误的检测（漏检物体），IoU < TIOU \text{T}_{\text{IOU}} TIOU​。

反之，阴性依据一个真值边界框来评估，可定义为假阴性（FN）或真阴性（TN）：

- **假阴性（FN）**：指模型未能检测到的真值物体。
- **真阴性（TN）**：指一次正确的"非检测"。在物体检测领域，图像里有无数的边界框**不**应当被识别，因为它们不代表目标物体。想想图像里所有不代表目标物体的可能框——数量相当庞大，不是吗？:) 正因如此，我们在计算物体检测指标时不考虑 TN。

现在我们能识别 TP、FP 和 FN 了，就可以定义 Precision 和 Recall：

- **Precision（精确率）** 是模型只识别相关物体的能力。它是正确阳性预测的百分比，由下式给出：

Precision=TP(TP+FP)=TPall detections \text{Precision} = \frac{TP}{(TP + FP)} = \frac{TP}{\text{all detections}} Precision=(TP+FP)TP​=all detectionsTP​

即真阳性与所有检测框之比。

- **Recall（召回率）** 衡量模型找出所有相关案例（所有真值边界框）的能力。它表示在所有真值中检测到的 TP 比例，由下式给出：

Recall=TP(TP+FN)=TPall ground truths \text{Recall} = \frac{TP}{(TP + FN)} = \frac{TP}{\text{all ground truths}} Recall=(TP+FN)TP​=all ground truthsTP​

注意 TP、FP 和 FN 取决于预定义的 IoU 阈值，Precision 和 Recall  likewise 如此。

平均精度捕捉了模型在不同 Precision 和 Recall 取值下正确分类和定位物体的能力。为此我们会用一个具体的目标类别（比如 "dog"）来绘制 Precision 与 Recall 之间的关系曲线。我们采用一个适中的 IoU 阈值 = 75% 来界定我们的 TP、FP 和 FN。随后即可计算 Precision 和 Recall 的值。为此我们需要让检测的置信度分数变化。

### 什么是平均召回，如何计算？

平均召回（AR）是常与 AP 一起用于评估物体检测模型的指标。AP 在不同置信度阈值上同时评估 Precision 和 Recall 以给出模型性能的单一数字汇总，而 AR 只聚焦 Recall 这一面，不考虑置信度、把所有检测都视为阳性。

COCO 的方法把 AR 计算为在 IOU > 0.5 和各类别上取得的最大 Recall 的平均。

通过在 [0.5, 1] 范围内使用 IOU 并对该区间上的 Recall 值取平均，AR 评估的是模型预测在物体定位上的表现。因此，如果你的目标是同时评估模型的高 Recall 和精确的物体定位，AR 是一个值得考虑的评估指标。

### 平均精度和平均召回有哪些变体？

基于预定义的 IoU 阈值以及与真值物体相关联的面积，可以得到 AP 和 AR 的不同版本：

- **AP@.5**：设 IoU 阈值 = 0.5，为图像数据集中的每个目标类别计算 Precision x Recall 的 AUC。然后把每个类别算得的结果相加并除以类别数。
- **AP@.75**：使用与 AP@.50 相同的方法，但 IoU 阈值 = 0.75。由于这个更高的 IoU 要求，AP@.75 被视为比 AP@.5 更严格，应用于评估那些需要在检测中达到高定位精度的模型。
- **AP@[.5:.05:.95]**：也被 cocoeval 工具称为 AP。这是 AP@.5 和 AP@.75 的扩展版本，因为它用不同的 IoU 阈值（0.5、0.55、0.6、…、0.95）计算 AP，并把算得的结果按下式取平均。与 AP@.5 和 AP@.75 相比，这个指标提供了整体性的评估，捕捉模型在更宽定位精度范围内的表现。

AP@[.5:.05:0.95=AP0.5+AP0.55+...+AP0.9510 \text{AP@[.5:.05:0.95} = \frac{\text{AP}_{0.5} + \text{AP}_{0.55} + ... + \text{AP}_{0.95}}{10} AP@[.5:.05:0.95=10AP0.5​+AP0.55​+...+AP0.95​​

- **AP-S**：它对面积 <322 \text{area} < 32^2 322<area<322 像素的（小）真值物体应用 AP@[.5:.05:.95]。
- **AP-M**：它对 322<area<962 32^2 < \text{area} < 96^2 322<area<962 像素的（中等大小）真值物体应用 AP@[.5:.05:.95]。

对于平均召回（AR），使用 10 个 IoU 阈值（0.5、0.55、0.6、…、0.95）来计算 Recall 值。AR 可通过限制每张图像的检测数，或基于物体面积限制检测来计算。

## 物体检测排行榜

我们最近发布了 [Object Detection Leaderboard](https://huggingface.co/spaces/hf-vision/object_detection_leaderboard)，用来比较我们 Hub 上开源模型的精度和效率。

图 8：物体检测排行榜。

为衡量精度，我们在 COCO val 2017 数据集上做基准，用涉及平均精度和平均召回的 12 项指标、以 [COCO 风格](https://cocodataset.org/#detection-eval) 进行评估。

如前所述，不同的工具在评估时可能采用不同的具体做法。为防止结果不一致，我们选择不实现我们自己的指标版本。相反，我们选择使用 COCO 官方的评估代码，也称为 PyCOCOtools，代码见[这里](https://github.com/cocodataset/cocoapi/tree/master/PythonAPI)。

在效率方面，我们用在整个数据集上的平均评估时间来为每个模型计算每秒帧数（FPS），考虑预处理和后处理步骤。鉴于每个模型对 GPU 显存的需求各不相同，我们选择以 batch size 为 1 来评估（这个选择也受我们的预处理步骤影响，稍后会展开）。不过要注意，这种做法未必完全契合真实性能，因为实践中常用更大的 batch size（往往包含多张图像）以获得更好的效率。

接下来我们会提供基于指标挑选最佳模型的建议，并指出哪些参数可能干扰结果。理解这些细微差别至关重要，因为它可能在社区里引发疑问和讨论。

### 如何基于指标挑选最佳模型？

选择恰当的指标来评估和比较检测器要考虑多个因素。主要考虑的是应用的目的，以及用于训练和评估模型的数据集的特性。

对于综合性能，**AP（AP@[.5:.05:.95]）** 是个好选择，如果你想让模型在不同 IoU 阈值上全面表现、且对检测物体的定位没有硬性要求。

如果你想要一个物体识别好、物体大致位置正确的模型，可以看 **AP@.5**。如果你更偏好边界框定位更精确的模型，**AP@.75** 更合适。

如果你对物体大小有限制，**AP-S**、**AP-M** 和 **AP-L** 就派上用场。例如，如果你的数据集或应用主要涉及小物体，AP-S 提供检测器识别这些小目标的效能洞察。这在诸如检测远处车辆或医学影像中的小伪影等场景里变得关键。

### 哪些参数会影响平均精度结果？

从 Hub 上挑了一个物体检测模型后，如果在模型的预处理和后处理步骤里使用不同参数，我们就能让输出框发生变化。这些可能影响评估指标。我们识别了一些最常导致结果差异的因素：

- 忽略得分低于某个阈值的检测。
- 推理时使用 `batch_sizes > 1`。
- 移植过来的模型输出的 logits 与原始模型不同。
- 某些真值物体可能被评估器忽略。
- 计算 IoU 可能颇为复杂。
- 文本条件模型需要精确的提示词。

我们以 DEtection TRansformer (DETR)（[facebook/detr-resnet-50](https://huggingface.co/facebook/detr-resnet-50)）模型作为示例。我们会展示这些因素如何影响输出结果。

#### 评估前对检测做阈值过滤

我们的示例模型使用 [`DetrImageProcessor` 类](https://huggingface.co/docs/transformers/main/en/model_doc/detr#transformers.DetrImageProcessor) 来处理边界框和 logits，如下代码片段所示：

```
from transformers import DetrImageProcessor, DetrForObjectDetection
import torch
from PIL import Image
import requests

url = "http://images.cocodataset.org/val2017/000000039769.jpg"
image = Image.open(requests.get(url, stream=True).raw)

processor = DetrImageProcessor.from_pretrained("facebook/detr-resnet-50")
model = DetrForObjectDetection.from_pretrained("facebook/detr-resnet-50")

inputs = processor(images=image, return_tensors="pt")
outputs = model(**inputs)

# PIL images have their size in (w, h) format
target_sizes = torch.tensor([image.size[::-1]])
results = processor.post_process_object_detection(outputs, target_sizes=target_sizes, threshold=0.5)
```

函数 `post_process_object_detection` 里的参数 `threshold` 用于根据置信度分数过滤检测到的边界框。

如前所述，Precision x Recall 曲线是通过在完整置信度范围 [0,1] 上测量 Precision 和 Recall 来构建的。因此，在评估前限制检测会产生有偏的结果，因为我们会漏掉一些检测。

#### 改变 batch size

batch size 不仅影响处理时间，还可能导致不同的检测框。图像预处理步骤可能根据图像大小改变其分辨率。

如 [DETR 文档](https://huggingface.co/docs/transformers/model_doc/detr)所述，默认情况下 `DetrImageProcessor` 会缩放输入图像使短边为 800 像素，然后再缩放使长边最多 1333 像素。因此一个 batch 里的图像可以有不同大小。DETR 通过把图像 padding 到 batch 中最大尺寸、并创建指示哪些像素是真实/哪些是 padding 的 pixel mask 来解决这一点。

为说明这个过程，我们考虑图 9 和图 10 的例子。在图 9 里我们考虑 batch size = 1，两张图像各自独立地用 `DetrImageProcessor` 处理。第一张图被缩放到 (800, 1201)，使检测器预测 28 个 `vase` 类、22 个 `chair` 类、十个 `bottle` 类等等。

图 9：用 `DetrImageProcessor` 以 batch size = 1 处理的两张图像。

图 10 展示了 batch size = 2 的过程，同样的两张图像在同一个 batch 里用 `DetrImageProcessor` 处理。两张图都被缩放到相同的形状 (873, 1201)，并应用 padding，使图像中有内容的部分保持其原始宽高比。然而，第一张图例如输出了不同数量的物体：31 个 `vase` 类、20 个 `chair` 类、八个 `bottle` 类等等。注意对于第二张图，在 batch size = 2 下，检测到一个新类别 `dog`。这是由于模型根据图像分辨率检测不同大小物体的能力。

图 10：用 `DetrImageProcessor` 以 batch size = 2 处理的两张图像。

#### 移植模型应当输出与原始模型相同的 logits

在 Hugging Face，我们移植模型到我们的代码库时非常小心。不仅关乎架构、清晰的文档和代码结构，我们还需要保证移植后的模型在给定相同输入时能产生与原始模型相同的 logits。

模型输出的 logits 会被后处理以产生置信度分数、标签 id 和边界框坐标。因此 logits 的细微变化也会影响指标结果。你可能记得[上面的例子](https://huggingface.co/blog/object-detection-leaderboard#whats-average-precision-and-how-to-compute-it)，我们讨论了计算平均精度的过程。我们展示了置信度水平会对检测排序，微小的变化可能导致不同的顺序，从而得到不同的结果。

重要的是要认识到模型可以以多种格式输出框，这也需要考虑在内，评估器需要进行恰当的转换。

- *(x, y, width, height)*：表示左上角坐标，后接绝对尺寸（宽和高）。
- *(x, y, x2, y2)*：该格式表示左上角和右下角的坐标。
- *(rel_x_center, rel_y_center, rel_width, rel_height)*：这些值表示中心的相对坐标和框的相对尺寸。

#### 某些真值在一些基准数据集中被忽略

有些数据集有时会使用在评估过程中被忽略的特殊标签。

例如 COCO 用 `iscrowd` 标签来标记成群的大物体（如一篮子里的许多苹果）。在评估时，标记为 `iscrowd=1` 的物体会被忽略。如果不考虑这一点，你可能得到不同的结果。

#### 计算 IoU 需要仔细考量

按 IoU 的定义来看它似乎很容易计算。但有一个关键细节要注意：如果真值和检测完全不重叠、哪怕一个像素都没有，IoU 应当为 0。为避免在计算并集时除以零，你可以在分母上加上一个小值（称为*epsilon*）。但务必谨慎选择 epsilon：大于 1e-4 的值可能不够中性，无法给出准确的结果。

#### 文本条件模型需要正确的提示词

有些情形下我们想评估文本条件模型，如 [OWL-ViT](https://huggingface.co/google/owlvit-base-patch32)，它可以接收文本提示并提供所需物体的位置。

对这类模型，不同的提示词（如 "Find the dog" 和 "Where's the bulldog?"）可能得到相同的结果。不过我们决定遵循各论文里描述的流程。例如对于 OWL-ViT，我们用提示词 "an image of a {}" 来预测物体，其中 {} 被替换为基准数据集的类别。

## 结论

在本文里，我们介绍了物体检测这一问题，并描绘了评估它们所用的主要指标。

如我们所见，评估物体检测模型可能比看上去费功夫。每个模型的特性都必须被仔细考虑，以防止有偏的结果。而且，每个指标代表同一模型的不同视角，挑选"最佳"指标取决于模型的应用以及所选基准数据集的特性。

下面这张表列出了针对特定用例推荐的指标，并给出真实场景作为示例。但要注意，这些只是建议，理想指标会因每个应用的独特特性而不同。

| Use Case | Real-world Scenarios | Recommended Metric |
| --- | --- | --- |
| General object detection performance | Surveillance, sports analysis | AP |
| Low accuracy requirements (broad detection) | Augmented reality, gesture recognition | AP@.5 |
| High accuracy requirements (tight detection) | Face detection | AP@.75 |
| Detecting small objects | Distant vehicles in autonomous cars, small artifacts in medical imaging | AP-S |
| Medium-sized objects detection | Luggage detection in airport security scans | AP-M |
| Large-sized objects detection | Detecting vehicles in parking lots | AP-L |
| Detecting 1 object per image | Single object tracking in videos | AR-1 |
| Detecting up to 10 objects per image | Pedestrian detection in street cameras | AR-10 |
| Detecting up to 100 objects per image | Crowd counting | AR-100 |
| Recall for small objects | Medical imaging for tiny anomalies | AR-S |
| Recall for medium-sized objects | Sports analysis for players | AR-M |
| Recall for large objects | Wildlife tracking in wide landscapes | AR-L |
