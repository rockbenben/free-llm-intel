# Perceiver IO：适用于任意模态的可扩展全注意力模型

### TLDR

我们已把 [Perceiver IO](https://huggingface.co/docs/transformers/model_doc/perceiver) 加入 Transformers——这是第一个能在各类模态（文本、图像、音频、视频、点云……）及其组合上工作的 Transformer 神经网络。看看下面这些 Space 示例：

- 预测图像之间的[光流](https://huggingface.co/spaces/nielsr/perceiver-optical-flow)
- [图像分类](https://huggingface.co/spaces/nielsr/perceiver-image-classification)。

我们还提供了[多个 notebook](https://github.com/NielsRogge/Transformers-Tutorials/tree/master/Perceiver)。

下面给出该模型的技术解释。

### 引言

[Transformer](https://arxiv.org/abs/1706.03762) 由 Vaswani 等人于 2017 年首次提出，在 AI 社区掀起革命，最初大幅刷新了机器翻译的最先进（SOTA）成绩。2018 年，[BERT](https://arxiv.org/abs/1810.04805) 发布——一个仅编码器的 Transformer，横扫自然语言处理（NLP）各项基准，最著名的就是 [GLUE benchmark](https://gluebenchmark.com/)。

不久之后，AI 研究者开始把 BERT 的思想推广到其他领域。举几个例子：

- Facebook AI 的 [Wav2Vec2](https://huggingface.co/docs/transformers/model_doc/wav2vec2) 证明这套架构可以扩展到音频
- Google AI 的 [Vision Transformer (ViT)](https://huggingface.co/docs/transformers/model_doc/vit) 展示它在视觉任务上非常好用
- 最新的 [Video Vision Transformer (ViViT)](https://arxiv.org/abs/2103.15691)，同样出自 Google AI，把这套架构用到了视频上。

在所有这些领域，强大架构加上大规模预训练的组合都让 SOTA 成绩大幅跃升。

然而，Transformer 的架构有一个重要限制：由于[自注意力机制](https://jalammar.github.io/illustrated-transformer/)，它在算力和内存上的[扩展性很差](https://arxiv.org/abs/2009.06732v2)。每一层中，所有输入都要用来产生 query 和 key，并计算成对点积。因此，没有某种预处理，自注意力无法直接作用于高维数据。Wav2Vec2 的做法是用一个特征编码器把原始波形转成时间特征序列。Vision Transformer（ViT）把图像切成不重叠的 patch 序列，作为「token」。Video Vision Transformer（ViViT）从视频中抽出不重叠的时空「管（tube）」作为「token」。要让 Transformer 处理某个模态，通常要把它离散化成 token 序列。

## Perceiver

[Perceiver](https://arxiv.org/abs/2103.03206) 旨在解决这一限制：把自注意力机制作用在一组 latent 变量上，而不是作用在输入上。`inputs`（可以是文本、图像、音频、视频）只用来与 latents 做交叉注意力。好处是大部分算力消耗在 latent 空间里，那里的算力很便宜（通常只用 256 或 512 个 latents）。由此得到的架构对输入尺寸没有二次方依赖：Transformer 编码器只与输入尺寸成线性关系，而 latent 注意力与它无关。在后续论文 [Perceiver IO](https://arxiv.org/abs/2107.14795) 中，作者把这个思想扩展到让 Perceiver 也能处理任意输出。思路相同：输出只用来与 latents 做交叉注意力。本文之下「Perceiver」与「Perceiver IO」可以互换，都指 Perceiver IO 模型。

下一节，我们将通过它在 [HuggingFace Transformers](https://github.com/huggingface/transformers) 中的实现，更深入看看 Perceiver IO 的实际运转——这个流行的库最初实现的是面向 NLP 的 Transformer 模型，如今也开始为其他领域实现模型。下面我们用张量形状的语言，详细解释 Perceiver 如何对任意模态做预处理与后处理。

HuggingFace Transformers 中所有 Perceiver 变体都基于 `PerceiverModel` 类。初始化一个 `PerceiverModel` 时，可以给模型提供 3 个额外组件：

- 一个 preprocessor（预处理器）
- 一个 decoder（解码器）
- 一个 postprocessor（后处理器）

注意它们每一个都是可选的。只有当 `inputs`（文本、图像、音频、视频等）尚未被嵌入时才需要 `preprocessor`。只有当你想把 Perceiver 编码器的输出（即 latents 的最后隐藏状态）解码成更有用的东西（比如分类 logits 或光流）时才需要 `decoder`。只有当你想把 decoder 的输出转成特定特征时才需要 `postprocessor`（这只有在自动编码时才需要，后面会看到）。架构总览如下图。

Perceiver 架构图。

换句话说，`inputs`（可以是任意模态或它们的组合）先可选地经 `preprocessor` 预处理。接着，预处理后的输入与 Perceiver 编码器的 latent 变量做交叉注意力：latent 变量产生 query（Q），预处理输入产生 key 和 value（KV）。之后，Perceiver 编码器用一个（可重复的）自注意力层块更新 latents 的嵌入。编码器最终输出形状为 (batch_size, num_latents, d_latents) 的张量，即 latents 的最后隐藏状态。然后是可选的 `decoder`，可把 latents 的最终隐藏状态解码成更有用的东西（如分类 logits）——做法是执行一次交叉注意力：可训练的嵌入产生 query（Q），latents 产生 key 和 value（KV）。最后是可选的 `postprocessor`，可对 decoder 输出做后处理，转成特定特征。

先从文本开始看 Perceiver 的实现。

## Perceiver 处理文本

假设想用 Perceiver 做文本分类。由于 Perceiver 自注意力机制的内存和时间需求不依赖输入规模，可以直接把原始 UTF-8 字节喂给模型。这是好事——熟悉的 Transformer 模型（[BERT](https://arxiv.org/abs/1810.04805)、[RoBERTa](https://arxiv.org/abs/1907.11692)）都采用某种显式分词，如 [WordPiece](https://research.google/pubs/pub37842/)、[BPE](https://arxiv.org/abs/1508.07909) 或 [SentencePiece](https://arxiv.org/abs/1808.06226)，而这[可能是有害的](https://arxiv.org/abs/2004.03720)。为了与 BERT（使用 512 子词 token 序列）公平对比，作者使用了 2048 字节的输入序列。再加上 batch 维度，模型的 `inputs` 形状为 (batch_size, 2048)，其中是某段文本的 byte ID（类似 BERT 的 `input_ids`）。可以用 `PerceiverTokenizer` 把文本转成 padding 到 2048 长度的 byte ID 序列：

```
from transformers import PerceiverTokenizer

tokenizer = PerceiverTokenizer.from_pretrained("deepmind/language-perceiver")

text = "hello world"

inputs = tokenizer(text, padding="max_length", return_tensors="pt").input_ids
```

在这种情况下，给模型提供 `PerceiverTextPreprocessor` 作为 preprocessor，它负责把 `inputs` 做嵌入（即把每个 byte ID 转成对应向量）并加入绝对位置嵌入。decoder 提供 `PerceiverClassificationDecoder`（把 latents 最后隐藏状态转成分类 logits）。不需要 postprocessor。换言之，HuggingFace Transformers 中做文本分类的 Perceiver 模型（叫 `PerceiverForSequenceClassification`）实现如下：

```
from torch import nn
from transformers import PerceiverModel
from transformers.models.perceiver.modeling_perceiver import PerceiverTextPreprocessor, PerceiverClassificationDecoder

class PerceiverForSequenceClassification(nn.Module):
    def __init__(self, config):
        super().__init__(config)

        self.perceiver = PerceiverModel(
            config,
            input_preprocessor=PerceiverTextPreprocessor(config),
            decoder=PerceiverClassificationDecoder(
                config,
                num_channels=config.d_latents,
                trainable_position_encoding_kwargs=dict(num_channels=config.d_latents, index_dims=1),
                use_query_residual=True,
            ),
        )
```

这里已经能看到 decoder 初始化时带了可训练的位置编码参数。为什么？我们仔细看看 Perceiver IO 的工作原理。初始化时，`PerceiverModel` 在内部定义一组 latent 变量：

```
from torch import nn

self.latents = nn.Parameter(torch.randn(config.num_latents, config.d_latents))
```

在 Perceiver IO 论文中，使用 256 个 latents，latents 维度设为 1280。加上 batch 维度，Perceiver 的 latents 形状为 (batch_size, 256, 1280)。首先，preprocessor（初始化时提供的那个）负责把 UTF-8 byte ID 嵌入成向量。因此 `PerceiverTextPreprocessor` 会把形状 (batch_size, 2048) 的 `inputs` 变成形状 (batch_size, 2048, 768) 的张量——假设每个 byte ID 转成 768 维向量（这由 `PerceiverConfig` 的 `d_model` 属性决定）。

随后 Perceiver IO 对 latents（产生 query，形状 (batch_size, 256, 1280)）和预处理输入（产生 keys 和 values，形状 (batch_size, 2048, 768)）做交叉注意力。这个初始交叉注意力操作的输出与 query 同形状——query 在这里就是 latents。也就是说输出形状为 (batch_size, 256, 1280)。

接着，一个（可重复的）自注意力层块用来更新 latents 的表示。注意这些层不依赖你提供输入的长度（字节数）——输入只在交叉注意力操作里被使用过。Perceiver IO 论文对文本模型用了单个 26 层自注意力块（每层 8 个注意力头）来更新 latents 表示。这 26 层自注意力之后的输出仍与最初喂给编码器的东西同形状：(batch_size, 256, 1280)。这也叫 latents 的「最后隐藏状态」，与 BERT 中输入 token 的「最后隐藏状态」非常类似。

好，现在有了形状 (batch_size, 256, 1280) 的最终隐藏状态。很好，但我们要把它变成形状 (batch_size, num_labels) 的分类 logits。怎么让 Perceiver 输出这个？

这由 `PerceiverClassificationDecoder` 处理。思路和把输入映射到 latent 空间时非常像：用交叉注意力。只不过这次由 latent 变量产生 keys 和 values，而我们提供任意想要的形状的张量——这里提供一个形状 (batch_size, 1, num_labels) 的张量充当 query（作者称之为「decoder queries」，因为它们在 decoder 中使用）。这个张量在训练开始时随机初始化、端到端训练。可以看到我们只是加了一个 dummy 序列长度维度 1。注意 QKV 注意力层的输出总是与 query 同形状——因此 decoder 输出形状 (batch_size, 1, num_labels) 的张量。decoder 随后把它 squeeze 成 (batch_size, num_labels)，boom，分类 logits 到手[1](https://huggingface.co/blog/perceiver#f1)。

很棒对吧？Perceiver 作者还表明，按 BERT 的方式对 Perceiver 做掩码语言建模预训练也很容易。该模型同样在 HuggingFace Transformers 中，名为 `PerceiverForMaskedLM`。它与 `PerceiverForSequenceClassification` 的唯一区别是 decoder 不用 `PerceiverClassificationDecoder`，而用 `PerceiverBasicDecoder`，把 latents 解码成形状 (batch_size, 2048, 1280) 的张量。然后加一个语言建模头，变成形状 (batch_size, 2048, vocab_size) 的张量。Perceiver 的词表只有 262：256 个 UTF-8 byte ID 加 6 个特殊 token。通过在英文维基和 [C4](https://arxiv.org/abs/1910.10683) 上预训练 Perceiver，作者证明微调后可以在 GLUE 上拿到总分 81.8。

## Perceiver 处理图像

看过如何用 Perceiver 做文本分类之后，用它做图像分类就顺理成章。唯一区别是给模型提供不同的 `preprocessor` 来嵌入图像 `inputs`。Perceiver 作者实际试验了 3 种不同预处理方式：

- 把像素值展平，接一个 kernel size 为 1 的卷积层，再加可学习的绝对 1D 位置嵌入。
- 把像素值展平，加固定的 2D Fourier 位置嵌入。
- 用 2D 卷积 + maxpool 层，加固定的 2D Fourier 位置嵌入。

每一种都在 Transformers 库中实现了，分别叫 `PerceiverForImageClassificationLearned`、`PerceiverForImageClassificationFourier` 和 `PerceiverForImageClassificationConvProcessing`。它们只在 `PerceiverImagePreprocessor` 的配置上有差别。我们细看 `PerceiverForImageClassificationLearned`。它这样初始化 `PerceiverModel`：

```
from torch import nn
from transformers import PerceiverModel
from transformers.models.perceiver.modeling_perceiver import PerceiverImagePreprocessor, PerceiverClassificationDecoder

class PerceiverForImageClassificationLearned(nn.Module):
    def __init__(self, config):
        super().__init__(config)

        self.perceiver = PerceiverModel(
            config,
            input_preprocessor=PerceiverImagePreprocessor(
                config,
                prep_type="conv1x1",
                spatial_downsample=1,
                out_channels=256,
                position_encoding_type="trainable",
                concat_or_add_pos="concat",
                project_pos_dim=256,
                trainable_position_encoding_kwargs=dict(num_channels=256, index_dims=config.image_size ** 2),
            ),
            decoder=PerceiverClassificationDecoder(
                config,
                num_channels=config.d_latents,
                trainable_position_encoding_kwargs=dict(num_channels=config.d_latents, index_dims=1),
                use_query_residual=True,
            ),
        )
```

可以看到 `PerceiverImagePreprocessor` 以 `prep_type = "conv1x1"` 初始化，并给可训练位置编码加了参数。这个预处理器具体是怎么工作的？假设给模型提供一个 batch 的图像。假设先做裁剪到 224 分辨率的中心 crop 和颜色通道归一化，于是 `inputs` 形状为 (batch_size, num_channels, height, width) = (batch_size, 3, 224, 224)。可以用 `PerceiverImageProcessor` 来做：

```
from transformers import PerceiverImageProcessor
import requests
from PIL import Image

processor = PerceiverImageProcessor.from_pretrained("deepmind/vision-perceiver")

url = 'http://images.cocodataset.org/val2017/000000039769.jpg'
image = Image.open(requests.get(url, stream=True).raw)

inputs = processor(image, return_tensors="pt").pixel_values
```

`PerceiverImagePreprocessor`（按上面设定的参数）先施加一个 kernel size (1, 1) 的卷积层，把 `inputs` 变成形状 (batch_size, 256, 224, 224) 的张量——即增大了通道维。然后把通道维挪到最后——现在张量形状是 (batch_size, 224, 224, 256)。接着展平空间维度（高+宽），得到形状 (batch_size, 50176, 256) 的张量。然后与可训练的 1D 位置嵌入拼接。由于位置嵌入的维度定义为 256（见上面的 `num_channels` 参数），得到形状 (batch_size, 50176, 512) 的张量。这个张量将用于与 latents 的交叉注意力操作。

作者对所有图像模型使用 512 个 latents，latents 维度设为 1024。因此 latents 是形状 (batch_size, 512, 1024) 的张量——假设加上 batch 维度。交叉注意力层接收形状 (batch_size, 512, 1024) 的 query 和形状 (batch_size, 50176, 512) 的 keys + values，输出与 query 同形状，即 (batch_size, 512, 1024)。随后重复施加一个 6 层自注意力块（8 次），得到 latents 的最终隐藏状态，形状 (batch_size, 512, 1024)。要把它们变成分类 logits，使用 `PerceiverClassificationDecoder`，其工作方式与文本分类类似：以 latents 作 keys + values，以形状 (batch_size, 1, num_labels) 的可训练位置嵌入作 query。交叉注意力输出是形状 (batch_size, 1, num_labels) 的张量，squeeze 后即得形状 (batch_size, num_labels) 的分类 logits。

Perceiver 作者展示，与主要为图像分类设计的模型（如 [ResNet](https://arxiv.org/abs/1512.03385) 或 [ViT](https://arxiv.org/abs/2010.11929)）相比，该模型能拿到很强的成绩。在 [JFT](https://paperswithcode.com/dataset/jft-300m) 上大规模预训练后，采用 conv+maxpool 预处理的模型（`PerceiverForImageClassificationConvProcessing`）在 ImageNet 上达到 84.5 的 top-1 准确率。值得注意的是，`PerceiverForImageClassificationLearned`——只用 1D 全可学习位置编码、对图像的 2D 结构毫无先验信息——也达到 72.7 的 top-1 准确率。

## Perceiver 处理光流

作者展示让 Perceiver 处理光流也很简单。光流是计算机视觉里有几十年历史的问题，有诸多广泛应用。想了解光流，参见[这篇博客](https://medium.com/swlh/what-is-optical-flow-and-why-does-it-matter-in-deep-learning-b3278bb205b5)。给定同一场景的两张图（例如视频相邻两帧），任务是估计第一张图中每个像素的二维位移。现有算法高度手工设计且复杂，但用 Perceiver 就相对简单了。该模型已在 Transformers 库中实现，名为 `PerceiverForOpticalFlow`，实现如下：

```
from torch import nn
from transformers import PerceiverModel
from transformers.models.perceiver.modeling_perceiver import PerceiverImagePreprocessor, PerceiverOpticalFlowDecoder

class PerceiverForOpticalFlow(nn.Module):
    def __init__(self, config):
        super().__init__(config)

        fourier_position_encoding_kwargs_preprocessor = dict(
            num_bands=64,
            max_resolution=config.train_size,
            sine_only=False,
            concat_pos=True,
        )
        fourier_position_encoding_kwargs_decoder = dict(
            concat_pos=True, max_resolution=config.train_size, num_bands=64, sine_only=False
        )
        
        image_preprocessor = PerceiverImagePreprocessor(
            config,
            prep_type="patches",
            spatial_downsample=1,
            conv_after_patching=True,
            conv_after_patching_in_channels=54,
            temporal_downsample=2,
            position_encoding_type="fourier",
            # position_encoding_kwargs
            fourier_position_encoding_kwargs=fourier_position_encoding_kwargs_preprocessor,
        )
        
        self.perceiver = PerceiverModel(
            config,
            input_preprocessor=image_preprocessor,
            decoder=PerceiverOpticalFlowDecoder(
                config,
                num_channels=image_preprocessor.num_channels,
                output_image_shape=config.train_size,
                rescale_factor=100.0,
                use_query_residual=False,
                output_num_channels=2,
                position_encoding_type="fourier",
                fourier_position_encoding_kwargs=fourier_position_encoding_kwargs_decoder,
            ),
        )
```

可以看到，preprocessor 用的是 `PerceiverImagePreprocessor`（即为与 latents 的交叉注意力准备两张图像），decoder 用的是 `PerceiverOpticalFlowDecoder`（把 latents 最终隐藏状态解码成实际预测的光流）。对两个帧中的每一帧，作者在每个像素周围提取 3 x 3 patch，于是每个像素有 3 x 3 x 3 = 27 个值（每个像素还有 3 个颜色通道）。作者使用 (368, 496) 的训练分辨率。如果把每个训练样本的两帧 (368, 496) 叠在一起，模型的 `inputs` 形状为 (batch_size, 2, 27, 368, 496)。

预处理器（按上面的设置）先把两个帧沿通道维拼接，得到形状 (batch_size, 368, 496, 54) 的张量——假设也把通道维挪到最后。作者在论文（第 8 页）解释了为什么沿通道维拼接是合理的。随后展平空间维度，得到形状 (batch_size, 368*496, 54) = (batch_size, 182528, 54)。再拼接位置嵌入（每个维度 258），得到最终预处理输入的形状 (batch_size, 182528, 322)。它们将用于与 latents 做交叉注意力。

作者对光流模型使用 2048 个 latents（没错，2048！），每个 latent 的维度为 512。因此 latents 形状为 (batch_size, 2048, 512)。交叉注意力之后，张量仍然同形状（因为 latents 充当 query）。随后，单个 24 层自注意力块（每层 16 个注意力头）用于更新 latents 的嵌入。

要把 latents 的最终隐藏状态解码成实际预测的光流，`PerceiverOpticalFlowDecoder` 直接把形状 (batch_size, 182528, 322) 的预处理输入用作交叉注意力的 query。随后把它们投影成形状 (batch_size, 182528, 2) 的张量。最后缩放并 reshape 回原始图像尺寸，得到形状 (batch_size, 368, 496, 2) 的预测光流。当在 [AutoFlow](https://arxiv.org/abs/2104.14544)——一个含 40 万对标注图像的大规模合成数据集——上训练时，作者声称在包括 [Sintel](https://link.springer.com/chapter/10.1007/978-3-642-33783-3_44) 和 [KITTI](http://www.cvlibs.net/publications/Menze2015CVPR.pdf) 在内的重要基准上取得了 SOTA 成绩。

## Perceiver 多模态自动编码

作者还用 Perceiver 做多模态自动编码。多模态自动编码的目标是：学习一个模型，能在架构引入的信息瓶颈下准确重建多模态输入。作者在 [Kinetics-700 数据集](https://deepmind.com/research/open-source/kinetics)上训练该模型，每个样本由图像序列（即帧）、音频和一个类别标签（700 个标签之一）组成。该模型同样在 HuggingFace Transformers 中实现，名为 `PerceiverForMultimodalAutoencoding`。为简洁起见，我省略该模型的定义代码，但要指出它使用 `PerceiverMultimodalPreprocessor` 来准备模型的 `inputs`。这个预处理器会先分别用各模态（图像、音频、标签）自己的预处理器。假设有一个 16 帧、224x224 分辨率、30,720 个音频采样的视频，各模态预处理如下：

- 图像——实际是帧序列——形状 (batch_size, 16, 3, 224, 224)，用 `PerceiverImagePreprocessor` 变成形状 (batch_size, 50176, 243) 的张量。这是一个「space to depth」变换，之后拼接固定的 2D Fourier 位置嵌入。
- 音频形状为 (batch_size, 30720, 1)，用 `PerceiverAudioPreprocessor`（把固定 Fourier 位置嵌入拼到原始音频上）变成形状 (batch_size, 1920, 401) 的张量。
- 类别标签形状 (batch_size, 700)，用 `PerceiverOneHotPreprocessor` 变成 (batch_size, 1, 700)。也就是说这个预处理器只是加了一个 dummy 时间（index）维。注意在评估时类别标签初始化为全零张量，让模型充当视频分类器。

随后，`PerceiverMultimodalPreprocessor` 会用模态专属的可训练嵌入对预处理后的各模态做 padding，使其可以沿时间维拼接。这里通道维最大的模态是类别标签（700 通道）。作者强制最小 padding 尺寸为 4，因此每个模态会被 pad 到 704 通道。然后它们就能拼接起来，最终预处理输入是形状 (batch_size, 50176 + 1920 + 1, 704) = (batch_size, 52097, 704) 的张量。

作者使用 784 个 latents，每个维度 512。因此 latents 形状 (batch_size, 784, 512)。交叉注意力后张量仍同形状（latents 充当 query）。随后一个 8 层自注意力块（每层 8 个注意力头）用于更新 latents 嵌入。

接下来是 `PerceiverMultimodalDecoder`，它会先为每个模态分别创建输出 query。但由于一次前向传播无法解码整个视频，作者改为按 chunk 自动编码。每个 chunk 会对各模态的某些 index 维度做子采样。假设我们把视频分 128 个 chunk 处理，decoder query 的生成方式如下：

- 对图像模态，decoder query 的总规模为 16x3x224x224 = 802,816。但自动编码第一个 chunk 时，只对前 802,816/128 = 6272 个值子采样。图像输出 query 的形状为 (batch_size, 6272, 195)——195 来自固定 Fourier 位置嵌入。
- 对音频模态，总输入有 30,720 个值。但只子采样前 30720/128/16 = 15 个值。因此音频 query 形状为 (batch_size, 15, 385)。385 同样来自固定 Fourier 位置嵌入。
- 对类别标签模态，无需子采样，因此子采样 index 设为 1。标签输出 query 形状为 (batch_size, 1, 1024)。query 使用可训练位置嵌入（1024 维）。

与预处理器类似，`PerceiverMultimodalDecoder` 把不同模态 pad 到相同通道数，使模态专属 query 可以沿时间维拼接。这里类别标签通道数又是最高的（1024），作者强制最小 padding 尺寸为 2，因此每个模态 pad 到 1026 通道。拼接后，最终 decoder query 形状为 (batch_size, 6272 + 15 + 1, 1026) = (batch_size, 6288, 1026)。这个张量在交叉注意力中产生 query，latents 充当 keys 和 values。因此交叉注意力输出是形状 (batch_size, 6288, 1026) 的张量。随后 `PerceiverMultimodalDecoder` 用一个线性层缩减输出通道，得到形状 (batch_size, 6288, 512) 的张量。

最后是 `PerceiverMultimodalPostprocessor`。这个类对 decoder 输出做后处理，生成每个模态的实际重建。它先按各模态把 decoder 输出的时间维拆开：图像 (batch_size, 6272, 512)、音频 (batch_size, 15, 512)、类别标签 (batch_size, 1, 512)。然后应用各模态自己的后处理器：

- 图像后处理器（在 Transformers 中叫 `PerceiverProjectionPostprocessor`）把 (batch_size, 6272, 512) 张量变成 (batch_size, 6272, 3)——即把最后一维投影成 RGB 值。
- `PerceiverAudioPostprocessor` 把 (batch_size, 15, 512) 张量变成 (batch_size, 240)。
- `PerceiverClassificationPostprocessor` 只取第一个（也是唯一一个）index，得到形状 (batch_size, 700) 的张量。

这样我们就分别得到含图像、音频和类别标签重建的张量。由于整个视频是分 chunk 自动编码的，需要把各 chunk 的重建拼接起来才能得到整个视频的最终重建。下图是一个例子：

![](https://huggingface.co/blog/assets/41_perceiver/original_video.gif) ![](https://huggingface.co/blog/assets/41_perceiver/reconstructed_video.gif) ![](https://huggingface.co/blog/assets/41_perceiver/perceiver_audio_autoencoding.png)

上图：原始视频（左），前 16 帧的重建（右）。视频取自 [UCF101 数据集](https://www.crcv.ucf.edu/data/UCF101.php)。下图：重建音频（取自论文）。

用这种方式，模型学习了 3 个模态上的联合分布。作者也指出，由于 latent 变量跨模态共享、并未显式分配给各模态，每个模态的重建质量对其损失项权重和其他训练超参数很敏感。通过更强调分类准确率，他们在保持视频 20.7 PSNR（峰值信噪比）的同时达到 45% 的 top-1 准确率。

## Perceiver 的其他应用

注意，Perceiver 的应用没有上限！在最初的 [Perceiver 论文](https://arxiv.org/abs/2103.03206)中，作者展示了这套架构可以处理 3D 点云——配备 Lidar 传感器的自动驾驶汽车的常见课题。他们在 [ModelNet40](https://modelnet.cs.princeton.edu/) 上训练模型——一个涵盖 40 个物体类别、源自 3D 三角网格的点云数据集。结果模型在测试集上达到 85.7% 的 top-1 准确率，能与 [PointNet++](https://arxiv.org/abs/1706.02413)——一个使用额外几何特征并做更复杂增强的强专用模型——相提并论。

作者还用 Perceiver 替换了 [AlphaStar](https://deepmind.com/blog/article/alphastar-mastering-real-time-strategy-game-starcraft-ii) 中原版的 Transformer——这套 SOTA 强化学习系统征战复杂的 [StarCraft II](https://starcraft2.com/en-us/)。在没有调整任何其他参数的情况下，作者观察到所得 agent 达到与原版 AlphaStar agent 相同的水平：在对人类数据做 [behavioral cloning](https://proceedings.neurips.cc/paper/1988/file/812b4ba287f5ee0bc9d43bbf5bbe87fb-Paper.pdf) 后，对 Elite bot 的胜率为 87%。

需要强调，目前实现的模型（如 `PerceiverForImageClassificationLearned`、`PerceiverForOpticalFlow`）只是 Perceiver 玩法的示例。它们每一个都只是 `PerceiverModel` 的不同实例——换了不同的 preprocessor 和/或 decoder（多模态自动编码还另有 postprocessor）。大家可以提出新的 preprocessor、decoder 和 postprocessor，让模型解决不同的问题。例如，可以扩展 Perceiver 去做类似 BERT 的命名实体识别（NER）或问答、类似 Wav2Vec2 的音频分类，或类似 DETR 的目标检测。

## 结论

在这篇博客中，我们走过了 Perceiver IO 的架构——Google Deepmind 对 Perceiver 的扩展——并展示了它处理各类模态的通用性。Perceiver 的最大优势在于：自注意力机制的算力和内存需求不依赖输入和输出的规模，因为大部分算力发生在 latent 空间（一小组不过大的向量）。尽管架构与任务无关，模型在语言、视觉、多模态数据和点云等模态上都取得了出色成绩。未来，在多个模态上同时训练一个共享的 Perceiver 编码器、配模态专属的 preprocessor 和 postprocessor，也许是有趣的方向。正如 [Karpathy 所说](https://twitter.com/karpathy/status/1424469507658031109)，这套架构很可能把所有模态统一进一个共享空间，配一整套编码器/解码器库。

说到库，该模型从今天起已在 [HuggingFace Transformers](https://github.com/huggingface/transformers) 中可用。很期待大家用它做出什么——它的应用看起来无穷无尽！
