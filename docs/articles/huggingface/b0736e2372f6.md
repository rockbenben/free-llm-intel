# Open Medical-LLM 排行榜：医疗健康领域的大型语言模型评测

多年来，大语言模型（LLM）已成长为可能彻底变革医疗健康方方面面的突破性技术。[GPT-3](https://arxiv.org/abs/2005.14165)、[GPT-4](https://arxiv.org/abs/2303.08774) 和 [Med-PaLM 2](https://arxiv.org/abs/2305.09617) 这类模型在理解和生成类人文本方面表现出非凡能力，是攻克复杂医学任务、改善患者护理的宝贵工具。它们在诸多医疗应用中已经显示出潜力，如医学问答（QA）、对话系统和文本生成。此外，随着电子健康档案（EHR）、医学文献和患者自生成数据的指数级增长，LLM 可以帮助医疗专业人士提取有价值的洞见、做出明智决策。

[![Image source : https://arxiv.org/pdf/2311.05112.pdf](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/medical_llms.png?raw=true)](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/medical_llms.png?raw=true)

然而，尽管 LLM 在医疗健康领域潜力巨大，仍有许多重大而特殊的挑战需要解决。

当模型用于娱乐性对话时，错误的后果无足轻重；但在医疗用途中并非如此——错误的解释和回答可能对患者护理和结局造成严重后果。语言模型提供信息的准确性和可靠性可能事关生死，因为它可能影响医疗决策、诊断和治疗方案。

例如，面对一个医学咨询（见下图），GPT-3 错误地建议一位孕妇使用四环素——尽管它同时正确地说明了该药因可能伤害胎儿而属于禁忌。若照这个错误建议执行，可能导致婴儿骨骼发育问题。

[![Image source : [https://arxiv.org/pdf/2311.05112.pdf](https://arxiv.org/abs/2307.15343)](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/gpt_medicaltest.png?raw=true)](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/gpt_medicaltest.png?raw=true)

要充分发挥 LLM 在医疗健康的能量，关键在于用一套专为医疗领域设计的体系来开发和基准测试模型。这套体系应考虑医疗健康数据与应用的独特特征和要求。医学 LLM 评估方法的发展不只是学术兴趣，更具有现实意义——因为它们在这个行业里存在真实的风险。

Open Medical-LLM 排行榜正是为应对这些挑战与局限而生：它提供一个标准化平台，在多样化的医疗任务和数据集上评估并比较各类大语言模型的表现。通过对每个模型医学知识与问答能力的全面评估，排行榜致力于推动更有效、更可靠的医疗 LLM 的发展。

这一平台帮助研究者和从业者识别不同方法的强项与弱点、推动该领域的进一步演进，最终为患者护理和结局的改善做出贡献。

## 数据集、任务与评估设置

Medical-LLM 排行榜包含多种任务，并使用准确率作为主要评估指标（准确率衡量语言模型在各医学 QA 数据集上给出正确答案的比例）。

### MedQA

[MedQA](https://arxiv.org/abs/2009.13081) 数据集由来自美国医师执照考试（USMLE）的多选题构成，考察通用医学知识，开发集含 11,450 道题、测试集含 1,273 道题。每题有 4 或 5 个选项，该数据集旨在评估美国行医资格所要求的医学知识与推理能力。

[![MedQA question](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/medqa.png?raw=true)](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/medqa.png?raw=true)

### MedMCQA

[MedMCQA](https://proceedings.mlr.press/v174/pal22a.html) 是源自印度医学入学考试（AIIMS/NEET）的大规模多选 QA 数据集，覆盖 2,400 个健康话题和 21 个医学学科，开发集超过 187,000 道题、测试集 6,100 道题。每题有 4 个选项并附有解析。MedMCQA 评估模型的一般医学知识和推理能力。

[![MedMCQA question](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/medmcqa.png?raw=true)](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/medmcqa.png?raw=true)

### PubMedQA

[PubMedQA](https://aclanthology.org/D19-1259/) 是一个闭域 QA 数据集，每道题都可以通过查看相关联的上下文（PubMed 摘要）来回答。它包含 1,000 组专家标注的问答对。每题附一段 PubMed 摘要作为上下文，任务是根据摘要信息给出 yes/no/maybe 回答。数据集分为开发 500 题、测试 500 题。PubMedQA 评估模型理解并推理科学生物医学文献的能力。

[![PubMedQA question](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/pubmedqa.png?raw=true)](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/pubmedqa.png?raw=true)

### MMLU 子集（医学与生物）

[MMLU benchmark](https://arxiv.org/abs/2009.03300)（Measuring Massive Multitask Language Understanding）收录多个领域的多选题。就 Open Medical-LLM 排行榜而言，我们聚焦与医学知识最相关的子集：

- Clinical Knowledge：265 题，考察临床知识与决策技能。
- Medical Genetics：100 题，覆盖医学遗传学相关主题。
- Anatomy：135 题，考察人体解剖知识。
- Professional Medicine：272 题，考察医学专业人士所需知识。
- College Biology：144 题，覆盖大学水平生物学概念。
- College Medicine：173 题，考察大学水平的医学知识。

每个 MMLU 子集都是 4 选项的多选题，旨在评估模型对特定医学与生物领域的理解。

[![MMLU questions](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/mmlu.png?raw=true)](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/mmlu.png?raw=true)

Open Medical-LLM 排行榜对模型在医学知识与推理各方面的表现提供稳健评估。

## 洞见与分析

Open Medical-LLM 排行榜在一套多样化的医学问答任务上评估各类 LLM 的表现。主要发现如下：

- 商业模型如 GPT-4-base 和 Med-PaLM-2 在各类医学数据集上稳定取得高准确率，在不同医学领域都表现出强劲水平。
- 开源模型如 [Starling-LM-7B](https://huggingface.co/Nexusflow/Starling-LM-7B-beta)、[gemma-7b](https://huggingface.co/google/gemma-7b)、Mistral-7B-v0.1 和 [Hermes-2-Pro-Mistral-7B](https://huggingface.co/NousResearch/Hermes-2-Pro-Mistral-7B)，尽管尺寸只有约 70 亿参数，在部分数据集和任务上同样表现有竞争力。
- 无论商业还是开源模型，在科学生物医学文献的理解与推理（PubMedQA）以及临床知识与决策技能应用（MMLU Clinical Knowledge 子集）这类任务上都表现不错。

[![Image source : [https://arxiv.org/abs/2402.07023](https://arxiv.org/abs/2402.07023)](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/model_evals.png?raw=true)](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/model_evals.png?raw=true)

Google 的 [Gemini Pro](https://arxiv.org/abs/2312.11805) 在多个医学领域表现强劲，尤其在 Biostatistics、Cell Biology、Obstetrics & Gynecology 这类数据密集、流程化的任务上非常出色。但在 Anatomy、Cardiology、Dermatology 等关键领域表现中等到偏低，暴露出要在综合医疗应用中落地仍需补足的短板。

[![Image source : [https://arxiv.org/abs/2402.07023](https://arxiv.org/abs/2402.07023)](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/subjectwise_eval.png?raw=true)](https://github.com/monk1337/research_assets/blob/main/huggingface_blog/subjectwise_eval.png?raw=true)

## 提交你的模型参与评估

要向 Open Medical-LLM 排行榜提交模型，请按以下步骤：

**1. 把模型权重转换为 Safetensors 格式**

先将模型权重转换为 safetensors 格式。Safetensors 是一种更安全、加载使用更快的新权重存储格式。转换后，排行榜还能在主表中展示你模型的参数量。

**2. 确保与 AutoClasses 兼容**

提交前，确认你的模型和 tokenizer 能用 Transformers 库的 AutoClasses 加载。用下面这段代码测试兼容性：

```
from transformers import AutoConfig, AutoModel, AutoTokenizer
config = AutoConfig.from_pretrained(MODEL_HUB_ID)
model = AutoModel.from_pretrained("your model name")
tokenizer = AutoTokenizer.from_pretrained("your model name")
```

如果这一步失败，请按错误信息排查后再提交——你的模型很可能是上传方式不对。

**3. 把模型设为公开**

确保你的模型可公开访问。排行榜无法评估私有或需要特殊访问权限的模型。

**4. 远程代码执行（即将支持）**

目前 Open Medical-LLM 排行榜不支持需要 `use_remote_code=True` 的模型。不过团队正在积极开发该特性，敬请期待更新。

**5. 通过排行榜网站提交模型**

当你的模型采用 safetensors 格式、兼容 AutoClasses 且公开可访问后，就可以在 Open Medical-LLM 排行榜网站用 "Submit here!" 面板提交评估。按要求填写模型名称、描述等信息，点击提交。

排行榜团队会处理你的提交，并在各医学 QA 数据集上评估模型表现。评估完成后，你的模型分数会被加入排行榜，你可以将它与其他已提交模型对比。

## 接下来？扩展 Open Medical-LLM 排行榜

Open Medical-LLM 排行榜致力于持续扩展，跟上研究社区与医疗行业 evolving 的需求。重点方向包括：

- 通过与研究者、医疗机构和行业伙伴协作，纳入更广泛的医学数据集，覆盖放射学、病理学、基因组学等医疗健康的更多方面。
- 增强评估指标与报告能力：在准确率之外探索更多性能度量，如 Pointwise score 和能够刻画医疗应用独特需求的领域专用指标。
- 这方面的若干工作已经启动。如果你有意在我们计划推出的下一个 benchmark 上合作，请加入我们的 [Discord 社区](https://discord.gg/A5Fjf5zC69)了解更多并参与进来。我们很乐意一起协作、碰撞想法。

如果你热衷于 AI 与医疗健康的交叉领域、热衷为医疗领域构建模型、关心医疗 LLM 的安全与幻觉问题，我们邀请你加入充满活力的 [Discord 社区](https://discord.gg/A5Fjf5zC69)。
