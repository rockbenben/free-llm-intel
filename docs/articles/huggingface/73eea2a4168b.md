![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/patchtstmixer/first_image.gif)

`PatchTSMixer` 是一种基于 MLP-Mixer 架构的轻量级时间序列建模方法，出自 IBM Research 作者 Vijay Ekambaram、Arindam Jati、Nam Nguyen、Phanwadee Sinthong 和 Jayant Kalagnanam 的论文 [TSMixer: Lightweight MLP-Mixer Model for Multivariate Time Series Forecasting](https://huggingface.co/papers/2306.09364)。

为了让模型获得更广泛的影响并推动开源，IBM Research 与 HuggingFace 团队合作，把这个模型发布进 Transformers 库。

在 [Hugging Face 实现](https://huggingface.co/docs/transformers/main/en/model_doc/patchtsmixer)中，我们提供 PatchTSMixer 的能力：跨 patch、跨通道、跨隐藏特征进行轻量混合，轻松实现有效的多变量时间序列建模。它还支持多种注意力机制，从简单的门控注意力到更复杂的自注意力模块，都可以按需定制。模型可以先预训练，随后用于预测、分类、回归等各种下游任务。

`PatchTSMixer` 在预测任务上以 8-60% 的显著优势超越最先进的 MLP 和 Transformer 模型；相比最新的强基准 Patch-Transformer 模型也高出 1-2%，同时内存和运行时间还减少 2-3 倍。更多细节见[论文](https://arxiv.org/pdf/2306.09364.pdf)。

本文演示 PatchTSMixer 的上手示例：先展示它在 Electricity 数据集上的预测能力，然后用在 Electricity 上训练的模型对 `ETTH2` 数据集做 zero-shot 预测，展示 PatchTSMixer 的迁移学习能力。

## PatchTSMixer 速览

#### 如果你已经熟悉 `PatchTSMixer`，可以跳过本节！

`PatchTSMixer` 把给定的多变量时间序列切分成一系列 patch（窗口）。随后把序列送入嵌入层，生成一个多维张量。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/patchtstmixer/1.gif)

这个多维张量接着送入 `PatchTSMixer` 主干，主干由一串 [MLP Mixer](https://arxiv.org/abs/2105.01601) 层组成。每个 MLP Mixer 层通过一系列置换和 MLP 操作，学习跨 patch、patch 内部和跨通道的关联。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/patchtstmixer/2.gif)

`PatchTSMixer` 还使用残差连接和门控注意力来突出重要特征。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/patchtstmixer/3.gif)

因此，一串 MLP Mixer 层构成了如下所示的 `PatchTSMixer` 主干。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/patchtstmixer/4.png)

`PatchTSMixer` 的模块化设计可以无缝支持掩码时间序列预训练，也支持直接的时间序列预测。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/patchtstmixer/5.gif)

### 加载并准备数据集

下一个单元格中，请根据你的应用调整以下参数：

- `dataset_path`：感兴趣数据的本地 .csv 文件路径，或 csv 文件的网络地址。数据用 pandas 加载，所以 `pd.read_csv` 支持的一切都可以：([https://pandas.pydata.org/pandas-docs/stable/reference/api/pandas.read_csv.html](https://pandas.pydata.org/pandas-docs/stable/reference/api/pandas.read_csv.html))。
- `timestamp_column`：包含时间戳信息的列名，没有这种列就用 `None`。
- `id_columns`：指定不同时间序列 ID 的列名列表。没有 ID 列就用 `[]`。
- `forecast_columns`：需要建模的列。
- `context_length`：作为模型输入的历史数据量。会从输入数据框中截取长度等于 `context_length` 的输入时间序列窗口。对于多时间序列数据集，context 窗口会被创建为始终落在同一条时间序列（同一个 ID）之内。
- `forecast_horizon`：要向未来预测的时间戳个数。
- `train_start_index`、`train_end_index`：加载数据中标识训练数据起止的索引。
- `valid_start_index`、`valid_end_index`：标识验证数据起止的索引。
- `test_start_index`、`test_end_index`：标识测试数据起止的索引。
- `num_workers`：PyTorch dataloader 的 CPU worker 数。
- `batch_size`：批大小。数据先加载进 Pandas dataframe 并切成训练、验证、测试三部分，然后再转换成训练所需的 PyTorch 数据集。

## 配置 PatchTSMixer 模型

接下来，我们用一个配置实例化一个随机初始化的 PatchTSMixer 模型。下面的参数控制与架构相关的各个超参数。

- `num_input_channels`：时间序列数据的输入通道数（或维度数），自动设为待预测列的数量。
- `context_length`：如上所述，作为模型输入的历史数据量。
- `prediction_length`：与上面说的预测窗口相同。
- `patch_length`：`PatchTSMixer` 模型的 patch 长度。建议选择能整除 `context_length` 的值。
- `patch_stride`：从 context 窗口提取 patch 时使用的步长。
- `d_model`：模型的隐藏特征维度。
- `num_layers`：模型层数。
- `dropout`：编码器中所有全连接层的 dropout 概率。
- `head_dropout`：模型头部使用的 dropout 概率。
- `mode`：PatchTSMixer 的工作模式。"common_channel"/"mix_channel"。common-channel 以通道独立模式工作；预训练请用 "common_channel"。
- `scaling`：按窗口标准缩放，推荐值 "std"。

参数完整说明见[文档](https://huggingface.co/docs/transformers/main/en/model_doc/patchtsmixer#transformers.PatchTSMixerConfig)。

建议只调整下一个单元格里的值。

```
patch_length = 8
config = PatchTSMixerConfig(
    context_length=context_length,
    prediction_length=forecast_horizon,
    patch_length=patch_length,
    num_input_channels=len(forecast_columns),
    patch_stride=patch_length,
    d_model=16,
    num_layers=8,
    expansion_factor=2,
    dropout=0.2,
    head_dropout=0.2,
    mode="common_channel",
    scaling="std",
)
model = PatchTSMixerForPrediction(config)
```

## 第 2 部分：从 Electricity 到 ETTh2 的迁移学习

本节演示 `PatchTSMixer` 模型的迁移学习能力：用在 Electricity 数据集上预训练的模型，对 `ETTh2` 数据集做 zero-shot 预测。

所谓迁移学习，就是先在一个`源`数据集上针对预测任务预训练模型（上面已经在 `Electricity` 数据集上做了），然后用这个预训练模型在`目标`数据集上做 zero-shot 预测。zero-shot 指不在目标域做任何额外训练、直接测试性能。我们期望模型从预训练中获得的知识足够多，可以迁移到不同的数据集。

随后，我们在目标数据的 `train` 切分上做线性探测（linear probing），然后（接着）再对预训练模型做微调，并在目标数据的 `test` 切分上验证预测性能。本例中源数据集是 Electricity 数据集，目标数据集是 `ETTh2`。

### 在 ETTh2 数据上迁移

所有评估都在 `ETTh2` 数据的 `test` 部分进行。步骤 1：直接评估 electricity 预训练模型，即 zero-shot 性能；步骤 2：线性探测之后评估；步骤 3：全量微调之后评估。

### 在 ETTh2 上做全量微调

我们可以在目标数据的 `train` 部分对整个模型做全量微调（而不是像上面只探测最后的线性层），看 `test` 性能能否提升。代码与上面的线性探测任务类似，只是不冻结任何参数。

```

    "patchtsmixer/electricity/model/pretrain/"
```
