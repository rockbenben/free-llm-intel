# 探索 SDXL 的简单优化

本文由 Sayak Paul（sayakpaul）与 Steven Liu（stevhliu）撰写。

[Stable Diffusion XL（SDXL）](https://huggingface.co/papers/2307.01952) 是 Stability AI 最新的潜空间扩散模型，用于生成高质量的超逼真图像。它克服了以往 Stable Diffusion 模型的难题，比如画对手和文字、以及空间上正确的构图。此外，SDXL 对上下文的感知能力更强，只需更少的提示词就能生成更好看的图像。

然而，所有这些改进都付出了模型显著变大的代价。大了多少？SDXL 基础模型有 3.5B 参数（尤其是 UNet），大约是上一代 Stable Diffusion 模型的 3 倍。

为了探索如何优化 SDXL 的推理速度与内存占用，我们在一块 A100 GPU（40 GB）上跑了一些测试。每次推理运行生成 4 张图，并重复 3 次。在计算推理延迟时，我们只取 3 次迭代中的最后一次。

所以，如果你原封不动地开箱运行 SDXL——全精度、默认注意力机制——它会占用 28GB 内存，耗时 72.2 秒！

```
from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained("stabilityai/stable-diffusion-xl-base-1.0").to("cuda")
pipe.unet.set_default_attn_processor()
```

这很不实用，而且会拖慢你，因为你通常会生成远超 4 张图。如果没有更强的 GPU，你就会撞上那个令人抓狂的 out-of-memory 报错。那么我们该如何优化 SDXL 以提高推理速度并降低内存占用呢？

在 🤗 Diffusers 中，我们有一堆优化技巧来帮你运行 SDXL 这种内存密集型模型，下面就来演示！我们聚焦两件事：*推理速度*和*内存*。

🧠 本文介绍的技术适用于所有的 pipeline。

## 推理速度

扩散是一个随机过程，所以不保证你能一次得到喜欢的图像。通常你需要多次运行推理并不断迭代，正因如此优化速度非常关键。本节重点是使用更低精度的权重，并引入 PyTorch 2.0 的 memory-efficient attention 与 `torch.compile` 来加速并缩短推理时间。

### 低精度

模型权重以某种*精度*存储，即用浮点数据类型表示。标准浮点数据类型是 float32（fp32），它能精确表示很大范围的浮点数。对于推理，往往不需要那么高的精度，你应该使用只覆盖较窄浮点数范围的 float16（fp16）。这意味着 fp16 的存储内存只有 fp32 的一半，且因为更容易计算而快一倍。此外，现代 GPU 卡有为 fp16 计算优化的硬件，使其更快。

在 🤗 Diffusers 中，你可以在加载模型时指定 `torch.dtype` 参数来转换权重，从而用 fp16 推理：

```
from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0",
    torch_dtype=torch.float16,
).to("cuda")
pipe.unet.set_default_attn_processor()
```

与完全未优化的 SDXL pipeline 相比，使用 fp16 占用 21.7GB 内存，只需 14.8 秒。推理几乎整整加速了一分钟！

### 内存高效注意力

transformer 模块中使用的注意力块可能是巨大的瓶颈，因为随着输入序列变长，内存呈*平方*增长。这很快会吃掉大量内存，让你收到 out-of-memory 报错。😬

内存高效注意力算法力求减轻计算注意力的内存负担，无论靠利用稀疏性还是分块（tiling）。这些优化算法过去大多作为需要单独安装的第三方库提供。但从 PyTorch 2.0 开始不再如此。PyTorch 2 引入了 [scaled dot product attention（SDPA）](https://pytorch.org/blog/accelerated-diffusers-pt-20/)，它提供了 [Flash Attention](https://huggingface.co/papers/2205.14135)、[memory-efficient attention](https://huggingface.co/papers/2112.05682)（xFormers）的融合实现，以及一个 C++ 的 PyTorch 实现。SDPA 可能是加速推理最简单的方式：如果你在 🤗 Diffusers 中使用 PyTorch ≥ 2.0，它默认就自动启用！

```
from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0",
    torch_dtype=torch.float16,
).to("cuda")
```

与完全未优化的 SDXL pipeline 相比，使用 fp16 和 SDPA 占用相同内存，推理时间缩短到 11.4 秒。我们就把它当作新基线，用来比较其他优化。

### torch.compile

PyTorch 2.0 还引入了 `torch.compile` API，可将你的 PyTorch 代码即时（JIT）编译为推理时更优化的 kernel。与其他编译器方案不同，`torch.compile` 对现有代码的改动极小，只需把模型包进这个函数即可。

通过 `mode` 参数，你可以在编译时针对内存开销或推理速度做优化，这带来了大得多的灵活性。

```
from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0",
    torch_dtype=torch.float16,
).to("cuda")
pipe.unet = torch.compile(pipe.unet, mode="reduce-overhead", fullgraph=True)
```

与上一个基线（fp16 + SDPA）相比，用 `torch.compile` 包装 UNet 把推理时间缩短到 10.2 秒。

⚠️ 第一次编译模型会较慢，但一旦编译完成，后续所有调用都会快得多！

## 模型内存占用

如今的模型越来越大，把它们塞进内存成了挑战。本节聚焦如何缩减这些巨型模型的内存占用，让你在消费级 GPU 上也能运行。这些技术包括 CPU offloading、把潜变量分多步解码为图像而非一次性完成，以及使用自编码器的蒸馏版本。

### 模型 CPU Offloading

模型 offloading 通过把 UNet 加载进 GPU 内存、而把扩散模型的其他组件（文本编码器、VAE）加载到 CPU 来节省内存。这样 UNet 可以在 GPU 上运行多轮迭代，直到不再需要它。

```
from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0",
    torch_dtype=torch.float16,
)
pipe.enable_model_cpu_offload()
```

与基线相比，现在占用 20.2GB 内存，为你省了 1.5GB。

### 顺序式 CPU Offloading

另一种能以更慢推理换取更多内存的 offloading 是顺序式 CPU offloading（sequential CPU offloading）。它不是卸载整个模型（如 UNet），而是把 UNet 不同子模块存储的权重卸载到 CPU，只在前向传播前才加载到 GPU。本质上，每次只加载模型的一部分，从而节省更多内存。唯一的缺点是明显更慢，因为你反复在加载和卸载子模块。

```
from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0",
    torch_dtype=torch.float16,
)
pipe.enable_sequential_cpu_offload()
```

与基线相比，这占用 19.9GB 内存，但推理时间增加到 67 秒。

## 切片（Slicing）

在 SDXL 中，变分编码器（VAE）把精炼后的潜变量（由 UNet 预测）解码为逼真图像。这一步的内存需求随预测图像数量（batch size）增长。根据图像分辨率和可用 GPU 显存，它可能相当吃内存。

这正是"切片"（slicing）有用的地方。待解码的输入张量被分成若干切片，解码计算分多步完成。这既省内存又允许更大的 batch size。

```
pipe = StableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0",
    torch_dtype=torch.float16,
).to("cuda")
pipe.enable_vae_slicing()
```

采用切片计算后，内存降到 15.4GB。若再加上顺序式 CPU offloading，进一步降到 11.45GB，让你每个提示词能生成 4 张（1024x1024）图像。不过，使用顺序 offloading 时推理延迟也会增加。

## 缓存计算

任何文本条件的图像生成模型通常都用文本编码器从输入提示计算 embeddings。SDXL 用了*两个*文本编码器！这对推理延迟贡献不小。然而，由于这些 embeddings 在整个反向扩散过程中保持不变，我们可以预计算并反复复用。这样，在计算完文本 embeddings 后，就可以把文本编码器移出内存。

首先，加载文本编码器及其对应的 tokenizer，从输入提示计算 embeddings：

```
tokenizers = [tokenizer, tokenizer_2]
text_encoders = [text_encoder, text_encoder_2]

(
    prompt_embeds,
    negative_prompt_embeds,
    pooled_prompt_embeds,
    negative_pooled_prompt_embeds
) = encode_prompt(tokenizers, text_encoders, prompt)
```

接着，清空 GPU 内存以移除文本编码器：

```
del text_encoder, text_encoder_2, tokenizer, tokenizer_2
flush()
```

现在 embeddings 可以直接送入 SDXL pipeline：

```
from diffusers import StableDiffusionXLPipeline

pipe = StableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0",
    text_encoder=None,
    text_encoder_2=None,
    tokenizer=None,
    tokenizer_2=None,
    torch_dtype=torch.float16,
).to("cuda")

call_args = dict(
        prompt_embeds=prompt_embeds,
        negative_prompt_embeds=negative_prompt_embeds,
        pooled_prompt_embeds=pooled_prompt_embeds,
        negative_pooled_prompt_embeds=negative_pooled_prompt_embeds,
        num_images_per_prompt=num_images_per_prompt,
        num_inference_steps=num_inference_steps,
)
image = pipe(**call_args).images[0]
```

与 SDPA 和 fp16 结合，我们可以把内存降到 21.9GB。上文讨论的其他优化内存的技术也可以与缓存计算搭配使用。

## Tiny Autoencoder

如前所述，VAE 把潜变量解码为图像。自然地，这一步直接受制于 VAE 的规模。那么，就用一个更小的自编码器吧！[`madebyollin` 的 Tiny Autoencoder](https://github.com/madebyollin/taesd)（在 [Hub 上可用](https://huggingface.co/madebyollin/taesdxl)）只有 10MB，是从 SDXL 使用的原始 VAE 蒸馏而来的。

```
from diffusers import AutoencoderTiny

pipe = StableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0",
    torch_dtype=torch.float16,
)
pipe.vae = AutoencoderTiny.from_pretrained("madebyollin/taesdxl", torch_dtype=torch.float16)
pipe.to("cuda")
```

用这套配置，我们把内存需求降到 15.6GB，同时缩短了推理延迟。

⚠️ Tiny Autoencoder 可能会省略图像中一些更精细的细节，这就是为什么 Tiny AutoEncoder 更适合用作图像预览。

## 结论

总结并梳理我们各项优化的收益：

⚠️ 在用 GPU 性能分析测量推理延迟与内存需求的权衡时，需要注意所用硬件。上述结论在不同硬件之间未必同等适用。例如，至少对 SDXL 而言，`torch.compile` 似乎只惠及较新的 GPU。

| **Technique** | **Memory (GB)** | **Inference latency (ms)** |
| --- | --- | --- |
| unoptimized pipeline | 28.09 | 72200.5 |
| fp16 | 21.72 | 14800.9 |
| **fp16 + SDPA (default)** | **21.72** | **11413.0** |
| default + `torch.compile` | 21.73 | 10296.7 |
| default + model CPU offload | 20.21 | 16082.2 |
| default + sequential CPU offload | 19.91 | 67034.0 |
| **default + VAE slicing** | **15.40** | **11232.2** |
| default + VAE slicing + sequential CPU offload | 11.47 | 66869.2 |
| default + precomputed text embeddings | 21.85 | 11909.0 |
| default + Tiny Autoencoder | 15.48 | 10449.7 |
