## 概览

在保持步行策略固定的情况下，为 [Microduck](https://pollen-robotics.com/microduck/) 添加局部避障能力。用可复用的 [SimReady](https://www.nvidia.com/en-us/glossary/simready/) 资产搭建不同的障碍场地，用 Newton 的光线投射器模拟 ToF 感知，再在 [Isaac Lab](https://developer.nvidia.com/isaac/lab) 中训练控制器，调整来自游戏手柄的速度指令，让机器人绕过障碍物。本教程涵盖仿真训练、评估、导出和实机部署。

## 简介

步行策略可以让 Microduck 保持平衡，但无法告诉它如何转向绕过路上的障碍。在这套流程中，我们复用[第一篇 Microduck 教程](https://huggingface.co/blog/nvidia/microduck-isaac-lab-sim-to-real)的步行策略，并固定其权重。本篇继续训练一个独立的避障控制器，利用飞行时间（ToF）感知。操作者用游戏手柄选择方向，控制器先调整速度指令，再将其传给步行策略。

[NVIDIA Isaac Lab](https://isaac-sim.github.io/IsaacLab/main/index.html) 是一个开源框架，可以在数千个由 GPU 并行运行的仿真环境中训练策略，并为机器人学习提供环境。[Newton](https://github.com/newton-physics/newton) 模拟物理过程和传感器的测深读数。我们将介绍控制架构，在不同的障碍布局上训练，评估得到的策略，并为硬件测试准备接口。

## 1. 在 Isaac Lab 中配置 Microduck 避障

进行仿真和训练前，请准备以下环境：

- 配备兼容 NVIDIA GPU 和驱动程序的 Linux 系统。平台要求参见 [Isaac Lab 安装指南](https://isaac-sim.github.io/IsaacLab/main/source/setup/installation/index.html)。
- 安装 Git LFS 的 Git，以及 uv 包管理器。

进行实机测试前，请准备：

- 一台配置好的 Microduck。加载导航任务使用的同一份带回程间隙建模的步行策略导出文件。
- 一个受支持的 ToF 传感器，并记录其配置。
- 一个已配对的游戏手柄，以及一块布置了障碍物的平坦测试场地。

### 快速安装

如果尚未安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)，请先安装。接着克隆 Isaac Lab 仓库的 exp/microduck 分支并安装依赖：

```
git lfs install
git clone --branch exp/microduck https://github.com/isaac-sim/IsaacLab.git
cd IsaacLab
uv sync --frozen
```

设置完成后，列出可用的 Microduck 环境和预设：

```
uv run isaaclab list_envs --keyword MicroDuck --show_presets
```

### 下载步行策略

训练前，先下载并导出一次[上游带回程间隙建模的步行策略检查点](https://omniverse-content-production.s3-us-west-2.amazonaws.com/Assets/Isaac/6.2/Isaac/IsaacLab/PretrainedCheckpoints/rsl_rl/IsaacContrib-Velocity-Rough-MicroDuck_backlash_newtonmjwarp_none_rsl_rl.pt)。避障任务会自动加载导出的步行策略。

```
uv run isaaclab play \
  --task IsaacContrib-Velocity-Rough-MicroDuck \
  --rl_library rsl_rl --checkpoint pretrained \
  --num_envs 1 --visualizer none \
  --video newton_gl --video_length 1 \
  presets=backlash
```

## 2. 搭建障碍场地

环境把简单的几何体和 Hugging Face 上 [SimReady Central](https://huggingface.co/spaces/nvidia/simready-central) 提供的 [OpenUSD](https://www.nvidia.com/en-us/glossary/openusd/) 资产组合起来。除了锥桶，我们还使用[纸箱](https://huggingface.co/datasets/nvidia/simready-assets/tree/main/box_cardboard_a01)、[办公垃圾桶](https://huggingface.co/datasets/nvidia/simready-assets/tree/main/trashCan_office_black_a03)和[床头柜](https://huggingface.co/datasets/nvidia/simready-assets/tree/main/table_bedside_b01)。从 IsaacLab 仓库根目录将固定版本的纸箱、垃圾桶和床头柜资产包下载到 assets/simready。

```
uvx --from huggingface-hub hf download nvidia/simready-assets \
  --repo-type dataset \
  --revision 9d4556bfe80868c1d27a7a7ba1c2774e63e8cedd \
  --include "box_cardboard_a01/*" \
  --include "trashCan_office_black_a03/*" \
  --include "table_bedside_b01/*" \
  --local-dir ./assets/simready
```

每次重置一个训练回合时，环境代码会自动抽取一种布局，打乱道具，并改变道具的位置和朝向。多数场地在 Microduck 前方散布障碍物，少部分则设置畅通的路径、隔栏或通道。代码还会对布局做镜像变换，并混用对齐和交错排列。

目标的初始位置在 Microduck 前方。运动指令引导它前往目标，策略则调整这些指令，让它绕过障碍物。

## 3. 了解 ToF 感知如何引导步行策略

`IsaacContrib-ObstacleAvoidance-Flat-MicroDuck` 任务把避障与平衡控制分开。导航策略利用 ToF 感知，以 50 Hz 的频率调整前进、横向和偏航指令。冻结的步行策略再将这些指令转化为关节动作，让机器人无须重新训练步态也能学会避障。

训练时，导航策略的 actor 接收 ToF 历史数据，以及真机可提供的机身和控制器状态。critic 可以访问额外的仿真状态来引导学习，部署时无需使用它。

奖励鼓励机器人向目标推进、安全抵达并绕开障碍物。只有在留出足够安全间距且向目标推进时，遵循运动指令才会获得奖励，过于贴近障碍物会降低奖励。惩罚项用于抑制快速接近障碍物、指令突变、碰撞和跌倒。

避障任务位于 [`isaaclab_tasks.contrib.microduck_obstacle`](https://github.com/isaac-sim/IsaacLab/tree/exp/microduck/source/isaaclab_tasks/isaaclab_tasks/contrib/microduck_obstacle)。任务配置位于 [`obstacle_avoidance_env_cfg.py`](https://github.com/isaac-sim/IsaacLab/blob/exp/microduck/source/isaaclab_tasks/isaaclab_tasks/contrib/microduck_obstacle/obstacle_avoidance_env_cfg.py)，ToF 感知位于 [`sensors.py`](https://github.com/isaac-sim/IsaacLab/blob/exp/microduck/source/isaaclab_tasks/isaaclab_tasks/contrib/microduck_obstacle/sensors.py)，动作、指令、观测和奖励则归在 [`mdp/`](https://github.com/isaac-sim/IsaacLab/tree/exp/microduck/source/isaaclab_tasks/isaaclab_tasks/contrib/microduck_obstacle/mdp) 下。

### 建模 ToF 传感器

MicroDuckToFCamera 扩展了 Newton 的 LegacyMultiMeshRayCasterCamera，用来模拟 Microduck 上的小型飞行时间（ToF）传感器 VL53L5CX。该传感器以 15 Hz 的频率测量 8×8 网格内的距离。仿真传感器的视场为 45°，量程为 0.12 至 4 米。它随 Microduck 的头部运动，安装位置接近实机传感器。

仿真中的传感器位置和地面读数参考了实机记录。训练会加入噪声、延迟和测量缺失，网格边缘附近也会出现这些情况，让策略适应不完整的数据。下文摘录了任务配置中已有的部分传感器设置，无需单独编辑或运行这段代码。

```
# Selected settings; mount and raycast targets omitted.
head_tof = MicroDuckToFCameraCfg(
    prim_path=MICRODUCK_HEAD_BODY_PATH,
    update_period=1.0 / 15.0,
    pattern_cfg=patterns.PinholeCameraPatternCfg(
        focal_length=1.0, width=8, height=8,
        horizontal_aperture=_TOF_APERTURE,
        vertical_aperture=_TOF_APERTURE,
    ),
    randomization=ToFRandomizationCfg(
        mount_pitch_degrees=(-10.0, 10.0),
        mount_height_m=(-0.02, 0.02),
        floor_validity_midpoint_offset_m=(0.0, 0.13),
        near_floor_edge_impairment_probability=0.5,
    ),
    data_types=["distance_to_image_plane", "distance_to_camera"],
    max_distance=TOF_MAX_RANGE,
    depth_clipping_behavior="zero",
)
```

## 4. 在并行环境中训练 Microduck 策略

使用 PPO，在 16,384 个并行环境中对导航策略进行 1,500 次训练迭代。actor、critic、归一化器和优化器都从头初始化。任务配置会加载固定的步行策略检查点、机器人模型和障碍物资产。

这里的 16,384 个环境可以调整，无需把它当成最低要求。可以降低 `--num_envs`，使训练适应 GPU 的可用显存。并行收集经验的环境减少后，要达到相近的策略表现，可能需要更多迭代和更长训练时间。我们还在 NVIDIA DGX Spark 上用 4,096 个并行环境完成了 3,000 次 PPO 更新，耗时约 6 小时，展示了同一流程的较小规模配置。

运行下列命令训练策略：

```
uv run isaaclab train \
  --task IsaacContrib-ObstacleAvoidance-Flat-MicroDuck \
  --rl_library rsl_rl \
  --num_envs 16384 \
  --max_iterations 1500 \
  --seed 42 \
  --device cuda:0 \
  --visualizer none \
  presets=backlash
```

## 5. 检查策略表现并导出 ONNX

回放使用与训练相同的道具、基础几何体、冻结的步行策略和传感器随机化配置，但采用不同的随机种子来生成新的障碍物排列。

导航检查点保存在仓库根目录下的 `logs/rsl_rl/microduck_obstacle_avoidance_tof_flat_backlash/<timestamp>/`。从自己的训练结果中选择一个 `model_<iteration>.pt` 文件，用它的路径替换下面的 `/absolute/path/to/model.pt`。此命令会回放策略、打开 Newton 查看器，并录制 20 秒仿真。若要无界面录制，将 --viz 设为 none。

```
uv run --extra video isaaclab play \
  --task IsaacContrib-ObstacleAvoidance-Flat-MicroDuck \
  --rl_library rsl_rl \
  --checkpoint /absolute/path/to/model.pt \
  --num_envs 1 \
  --seed 6173 \
  --device cuda:0 \
  --viz newton_gl \
  --video newton_gl \
  --video_length 1000 \
  presets=backlash
```

回放会把 TorchScript 和 ONNX 模型保存到检查点的导出目录。请把 ONNX 数据文件和模型放在一起。

## 6. 在 Microduck 实机上测试避障

这些[部署工具](https://github.com/isaac-sim/IsaacLab/tree/exp/microduck/scripts/deploy/microduck_tof_nav)在笔记本电脑上运行导航模型，并把调整后的手柄指令发送给机器人上的步行策略。请使用训练导航策略时使用的同一份步行策略。

第 1 节将步行策略导出的 ONNX 文件保存到 Isaac Lab 仓库根目录下的 `.pretrained_checkpoints/rsl_rl/https/omniverse-content-production.s3-us-west-2.amazonaws.com/Assets/Isaac/6.2/Isaac/IsaacLab/PretrainedCheckpoints/rsl_rl/exported/policy.onnx`。

按 [Pollen 的策略加载指南](https://github.com/pollen-robotics/microduck/blob/main/docs/robot/cheatsheet.md#trying-your-own-file)加载步行策略。部署 README 说明了文件传输步骤，也介绍了如何打包依赖外部数据文件的 ONNX 导出结果。

在本地 Isaac Lab 仓库中配置 SSH 访问，并让机器人直立静止，检查推理是否正常：

```
cd scripts/deploy/microduck_tof_nav
ssh-copy-id microduck@ROBOT_HOST
uv run nav_pad.py --robot ROBOT_HOST \
  --model /absolute/path/to/navigation/exported/policy.onnx \
  --dry-run --seconds 30
```

试运行会复制辅助程序并实时传输传感器数据，不会发送运动指令。观察障碍物进入传感器视野时，导航模型给出的指令。请将导航 ONNX 模型与配套的 .data 文件放在一起。

检查通过后，在有人监护的情况下启动手柄导航：

```
uv run nav_pad.py --robot ROBOT_HOST \
  --model /absolute/path/to/navigation/exported/policy.onnx
```

向前推住摇杆即可请求前进，策略会调整指令以避开障碍物。松开摇杆即可停止，按 X 切换导航状态，用 Ctrl-C 结束会话。默认前进速度上限为 0.15 m/s，另有近障制动和输入超时停车机制。先在空旷区域开始，确认能正常停车后再进入障碍场地测试。

操控方法、日志和故障排查说明参见[部署 README](https://github.com/isaac-sim/IsaacLab/blob/exp/microduck/scripts/deploy/microduck_tof_nav/README.md)。

## 7. 在 Isaac Lab 中探索 Microduck 的其他运动技能

## 构建下一个策略

从[第一篇 Microduck 教程](https://huggingface.co/blog/nvidia/microduck-isaac-lab-sim-to-real)开始，然后在 [Microduck 任务集](https://github.com/isaac-sim/IsaacLab/tree/exp/microduck/source/isaaclab_tasks/isaaclab_tasks/contrib/microduck)中选一个任务，用 Isaac Lab 和 Newton 构建自己的下一个策略。可以改变指令、奖励或环境来探索新的行为，从崎岖地形行走到基于感知的避障。在实机测试前，先用训练集之外的场景评估策略。
