## 长篇大论；博士

为[Microduck](https://pollen-robotics.com/microduck/)添加局部避障，同时保持其行走策略固定。使用可重复使用的 [SimReady](https://www.nvidia.com/en-us/glossary/simready/) 资源构建各种课程，使用牛顿光线投射器对 ToF 传感进行建模，并在 [Isaac Lab](https://developer.nvidia.com/isaac/lab) 中训练控制器以调整障碍物周围的游戏手柄速度命令。本教程涵盖模拟训练、评估、导出和真实机器人部署。

## 简介

步行策略可以使 Microduck 保持平衡，但它不会告诉机器人如何绕过路径上的障碍物。在此工作流程中，我们重用[第一个 Microduck 教程](https://huggingface.co/blog/nvidia/microduck-isaac-lab-sim-to-real) 中的行走策略并保持其权重固定。此后续工作使用飞行时间 (ToF) 传感来训练单独的回避控制器。你用游戏手柄选择一个方向；控制器在将速度命令传递给行走策略之前调整速度命令。

[NVIDIA Isaac Lab](https://isaac-sim.github.io/IsaacLab/main/index.html) 是一个开源框架，用于跨数千个 GPU 并行模拟训练策略，并提供机器人学习环境。 [Newton](https://github.com/newton-physics/newton) 模拟物理和传感器的深度测量。我们将介绍控制架构，训练不同的障碍物布局，评估最终的策略，并准备硬件测试的接口。

## 1. 在Isaac Lab中设置Microduck避障

对于模拟和培训，请准备：

- 具有兼容 NVIDIA GPU 和驱动程序的 Linux 系统。有关平台要求，请参阅 [Isaac Lab 安装指南](https://isaac-sim.github.io/IsaacLab/main/source/setup/installation/index.html)。
- Git 与 Git LFS 和 uv 包管理器。

对于物理机器人测试，请准备：

- 配置好的 Microduck。加载导航任务使用的相同反向间隙行走策略导出。
- 受支持的 ToF 传感器及其配置记录。
- 配对的游戏手柄和带有障碍物的水平测试区域。

### 快速安装

如果尚未安装，请安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)。然后克隆 Isaac Lab 存储库的 exp/microduck 分支并安装其依赖项：

```
git lfs install
git clone --branch exp/microduck https://github.com/isaac-sim/IsaacLab.git
cd IsaacLab
uv sync --frozen
```

设置完成后，列出可用的 Microduck 环境和预设：

```
uv run isaaclab list_envs --keyword MicroDuck --show_presets
```

### 下载步行政策

在训练前下载并导出一次[上游反向间隙行走检查点](https://omniverse-content-production.s3-us-west-2.amazonaws.com/Assets/Isaac/6.2/Isaac/IsaacLab/PretrainedCheckpoints/rsl_rl/IsaacContrib-Velocity-Rough-MicroDuck_backlash_newtonmjwarp_none_rsl_rl.pt)。避障任务自动加载导出的行走策略。

```
uv run isaaclab play \
  --task IsaacContrib-Velocity-Rough-MicroDuck \
  --rl_library rsl_rl --checkpoint pretrained \
  --num_envs 1 --visualizer none \
  --video newton_gl --video_length 1 \
  presets=backlash
```

## 2. 搭建障碍训练场

该环境将简单的原语与 Hugging Face 上的 [SimReady Central](https://huggingface.co/spaces/nvidia/simready-central) 提供的 [OpenUSD](https://www.nvidia.com/en-us/glossary/openusd/) 资产相结合。我们在锥体旁边使用了[纸板箱](https://huggingface.co/datasets/nvidia/simready-assets/tree/main/box_cardboard_a01)、[办公箱](https://huggingface.co/datasets/nvidia/simready-assets/tree/main/trashCan_office_black_a03)、[床头柜](https://huggingface.co/datasets/nvidia/simready-assets/tree/main/table_bedside_b01)。从 IsaacLab 存储库根目录，将固定的 box、bin 和 Cabinet 包下载到 asset/simready 中。

```
uvx --from huggingface-hub hf download nvidia/simready-assets \
  --repo-type dataset \
  --revision 9d4556bfe80868c1d27a7a7ba1c2774e63e8cedd \
  --include "box_cardboard_a01/*" \
  --include "trashCan_office_black_a03/*" \
  --include "table_bedside_b01/*" \
  --local-dir ./assets/simready
```

在每个情节重置时，环境代码会自动对布局进行采样，对道具进行洗牌，并改变它们的放置和旋转。大多数球场都会在鸭子前面散布障碍物，只有少量的畅通路径、障碍物和通道。该代码还反映了布局并混合了对齐和交错的行。

目标在鸭子之前开始。运动命令引导其朝着目标前进，而策略则围绕障碍进行调整。

## 3. 了解 ToF 传感如何指导步行策略

`IsaacContrib-ObstacleAvoidance-Flat-MicroDuck` 任务将避障与平衡分开。导航策略使用 ToF 传感来调整 50 Hz 的前向、侧向和偏航命令。然后，冻结的行走策略将这些命令转换为联合动作，使机器人能够学习避障，而无需重新训练其行走行为。

在训练期间，导航策略的参与者接收真实机器人上可用的 ToF 历史记录以及身体和控制器状态。它的批评者可以访问额外的模拟状态来指导学习，但部署不需要。

奖励鼓励朝着目标前进、安全到达以及绕过障碍。仅当机器人在足够的间隙内取得进展时，遵循移动命令才能获得积分；冒险的做法会降低这种信用。处罚会阻止快速接近、突然改变命令、碰撞和跌倒。

避障任务位于[`isaaclab_tasks.contrib.microduck_obstacle`](https://github.com/isaac-sim/IsaacLab/tree/exp/microduck/source/isaaclab_tasks/isaaclab_tasks/contrib/microduck_obstacle)。其配置在[`obstacle_avoidance_env_cfg.py`](https://github.com/isaac-sim/IsaacLab/blob/exp/microduck/source/isaaclab_tasks/isaaclab_tasks/contrib/microduck_obstacle/obstacle_avoidance_env_cfg.py)中，ToF传感在[`sensors.py`](https://github.com/isaac-sim/IsaacLab/blob/exp/microduck/source/isaaclab_tasks/isaaclab_tasks/contrib/microduck_obstacle/sensors.py)中，动作、命令、观察和奖励在[`mdp/`](https://github.com/isaac-sim/IsaacLab/tree/exp/microduck/source/isaaclab_tasks/isaaclab_tasks/contrib/microduck_obstacle/mdp)下组织。

### 对 ToF 传感器建模

MicroDuckToFCamera 扩展了 Newton 的 LegacyMultiMeshRayCasterCamera，以对 VL53L5CX 进行建模，这是 microduck 上的紧凑型飞行时间 (ToF) 传感器，可在 15Hz 的频率下测量 8×8 网格上的距离​​。模拟传感器具有 45° 视野和 0.12–4 m 范围。它遵循鸭子的头部，其位置与真实鸭子上的传感器类似。

真实记录告知模拟中的传感器放置和地板读数。训练会增加噪声、延迟和缺失测量（包括网格边缘附近的测量），从而使策略暴露于不完美的数据。下面的摘录显示了任务配置中已包含的选定传感器设置。您不需要单独编辑或运行此代码。

```
# Selected settings; mount and raycast targets omitted.
head_tof = MicroDuckToFCameraCfg(
    prim_path=MICRODUCK_HEAD_BODY_PATH,
    update_period=1.0 / 15.0,
    pattern_cfg=patterns.PinholeCameraPatternCfg(
        focal_length=1.0, width=8, height=8,
        horizontal_aperture=_TOF_APERTURE,
        vertical_aperture=_TOF_APERTURE,
    ),
    randomization=ToFRandomizationCfg(
        mount_pitch_degrees=(-10.0, 10.0),
        mount_height_m=(-0.02, 0.02),
        floor_validity_midpoint_offset_m=(0.0, 0.13),
        near_floor_edge_impairment_probability=0.5,
    ),
    data_types=["distance_to_image_plane", "distance_to_camera"],
    max_distance=TOF_MAX_RANGE,
    depth_clipping_behavior="zero",
)
```

## 4. 跨并行环境训练 Microduck 策略

使用 PPO 在 16,384 个并行环境中训练导航策略，进行 1,500 次训练迭代。它的参与者、批评者、标准化者和优化者都是全新的。任务配置加载固定步行检查点、机器人模型和障碍物资产。

此处显示的 16,384 个环境是可配置的，而不是最低要求。降低 `--num_envs` 以适应 GPU 的可用内存。由于并行收集经验的环境较少，达到可比较的策略性能可能需要更多的训练迭代和更长的训练时间。我们还在 NVIDIA DGX Spark 上使用 4,096 个并行环境进行了 3,000 个 PPO 更新，花费了大约 6 小时训练了该策略，展示了相同工作流程的较小规模配置。

运行以下命令来训练策略：

```
uv run isaaclab train \
  --task IsaacContrib-ObstacleAvoidance-Flat-MicroDuck \
  --rl_library rsl_rl \
  --num_envs 16384 \
  --max_iterations 1500 \
  --seed 42 \
  --device cuda:0 \
  --visualizer none \
  presets=backlash
```

## 5. 检查行为并将策略导出到 ONNX

回放使用与训练相同的道具、基元、冻结步行者和传感器随机化，并使用不同的种子来安排新的障碍物。

导航检查点保存在相对于存储库根目录的 `logs/rsl_rl/microduck_obstacle_avoidance_tof_flat_backlash/<timestamp>/` 下。从运行中选择一个 `model_<iteration>.pt` 文件，并将下面的 `/absolute/path/to/model.pt` 替换为其路径。这会播放策略，打开 Newton 查看器并记录 20 秒的模拟。将 --viz 设置为 none 以进行无头录制。

```
uv run --extra video isaaclab play \
  --task IsaacContrib-ObstacleAvoidance-Flat-MicroDuck \
  --rl_library rsl_rl \
  --checkpoint /absolute/path/to/model.pt \
  --num_envs 1 \
  --seed 6173 \
  --device cuda:0 \
  --viz newton_gl \
  --video newton_gl \
  --video_length 1000 \
  presets=backlash
```

回放将 TorchScript 和 ONNX 模型保存在检查点的导出文件夹中。将 ONNX 数据文件与模型放在一起。

## 6. 在真正的 Microduck 上测试避障

这些[部署工具](https://github.com/isaac-sim/IsaacLab/tree/exp/microduck/scripts/deploy/microduck_tof_nav) 在笔记本电脑上运行导航模型，并将调整后的游戏手柄命令发送到机器人上的行走策略。使用与导航训练期间相同的步行策略。

第 1 部分将 walker 的 ONNX 导出保存到 `.pretrained_checkpoints/rsl_rl/https/omniverse-content-production.s3-us-west-2.amazonaws.com/Assets/Isaac/6.2/Isaac/IsaacLab/PretrainedCheckpoints/rsl_rl/exported/policy.onnx`，相对于 Isaac Lab 存储库根。

使用 [Pollen 的策略加载指南](https://github.com/pollen-robotics/microduck/blob/main/docs/robot/cheatsheet.md#trying-your-own-file) 加载步行策略。部署自述文件包含传输步骤，包括如何打包使用外部数据文件的 ONNX 导出。

从 Isaac Lab 结账处，设置 SSH 访问并检查机器人直立静止的推理：

```
cd scripts/deploy/microduck_tof_nav
ssh-copy-id microduck@ROBOT_HOST
uv run nav_pad.py --robot ROBOT_HOST \
  --model /absolute/path/to/navigation/exported/policy.onnx \
  --dry-run --seconds 30
```

试运行会复制助手并流式传输传感器数据，但不发送移动命令。当障碍物进入传感器视野时，观察建议的命令。将导航 ONNX 和任何配套 .data 文件放在一起。

一旦这些检查通过，就开始受监督的游戏手柄导航：

```
uv run nav_pad.py --robot ROBOT_HOST \
  --model /absolute/path/to/navigation/exported/policy.onnx
```

向前握住操纵杆以请求移动；政策调整指挥，避障。松开摇杆即可停止，按 X 切换导航，然后使用 Ctrl-C 结束会话。默认情况下，前进速度上限为 0.15 m/s，并具有附加的近距离障碍物制动和过时输入停止功能。在测试路线之前，从空旷的区域开始并确认停止。

有关控制、日志和故障排除，请参阅[部署自述文件](https://github.com/isaac-sim/IsaacLab/blob/exp/microduck/scripts/deploy/microduck_tof_nav/README.md)。
