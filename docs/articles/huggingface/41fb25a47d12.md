去年 11 月，我们在这个博客上介绍了 [AnyLanguageModel](https://huggingface.co/blog/anylanguagemodel)：它是 Apple 的 Foundation Models 框架的直接替换品，让你可以自选 app 使用的模型和提供方。我们听到不少 app 开发者对本地模型感到好奇，却不一定清楚该从哪里上手。他们也想避免同时支持多个推理提供方带来的额外复杂度。AnyLanguageModel 就是从这些反馈里长出来的。

本地推理和托管推理各有长处，在建这一代智能 app 时，两者都有用武之地。一套共享的 API 让"为每个任务挑对模型"这件事更容易。

一年、几十个版本之后，[AnyLanguageModel 1.0](https://github.com/huggingface/AnyLanguageModel/releases/tag/1.0.0) 发布了，一同发布的还有 [swift-huggingface 1.0](https://github.com/huggingface/swift-huggingface/releases/tag/1.0.0) 和 [swift-xet 1.0](https://github.com/huggingface/swift-xet/releases/tag/1.0.0)。

下面说说有哪些变化，以及接下来还有什么：

## 可直接替换的兼容 API

AnyLanguageModel 的核心想法没有变：用 Foundation Models API，配上适合你 app 的模型。要开始用，只需改一下 `import` 语句：

```
- import FoundationModels
+ import AnyLanguageModel
```

同一段 session 代码随后就能用于系统模型，用于通过 llama.cpp、MLX 和 Core ML 运行的开放权重模型，也用于下面这些托管提供方。

过去一年里，我们加了几个重要功能：

- **工具调用**在每一个提供方上都可用。
- **受约束生成**在每一个提供方上也都可以，包括嵌套的 `@Generable` 类型以及它们的数组。
- **图像支持**让你用 Foundation Models 27 的语法把图像附到 prompt 上，包括在 iOS、macOS 和 visionOS 27 上使用系统模型的时候。

在 OS 27 上，AnyLanguageModel 还可以配合任何符合 Foundation Models 的 `LanguageModel` 协议的模型，包括 [Core AI](https://github.com/apple/coreai-models) 模型。

与 AnyLanguageModel 配套，我们还构建了 [swift-huggingface](https://github.com/huggingface/swift-huggingface) 和 [swift-xet](https://github.com/huggingface/swift-xet)，把 Hub 上加速的模型下载带到 Swift app 里。

## 托管模型也支持

今年对托管模型的支持也扩展了。AnyLanguageModel 现在支持：

- OpenAI 的 Chat Completions 和 Responses API
- [Open Responses](https://www.openresponses.org)，适用于任何提供兼容端点的提供方
- Anthropic 的 Messages API，并支持自适应思考与 effort 选项
- Google 的 Gemini API
- Ollama
- OS 27 上的 Private Cloud Compute
- [Hugging Face Inference Providers](https://huggingface.co/docs/inference-providers/index)，以及通过自定义 base URL 接入的 OpenRouter 等其他 OpenAI 兼容端点

借助 Inference Providers，你可以用同一段 session 代码，去使用那些大到无法在设备上运行的开放权重模型：

```
let model = OpenAILanguageModel(
    baseURL: URL(string: "https://router.huggingface.co/v1/")!,
    apiKey: ProcessInfo.processInfo.environment["HF_TOKEN"]!,
    model: "openai/gpt-oss-120b",
    apiVariant: .chatCompletions
)
```

托管提供方享有与本地模型相同的功能：受约束生成、带流式输出的工具调用，以及响应里的 token 用量。

推理（reasoning）现在也成了对话记录的一部分。当你切换提供方时，如果新提供方无法回放推理块，这些块会自动从请求中省略。

API 密钥来自一个闭包而不是字符串，因此你的 app 可以向自己的服务器获取短期 token。[README](https://github.com/huggingface/AnyLanguageModel#api-credentials-and-security) 解释了什么时候该让用户自带密钥，什么时候该把请求走代理。

AnyLanguageModel 也能在 Linux 上跑，所以同一份代码可以放在服务器上工作。

## 开放权重模型变强了

在我们让本地模型更易用的同时，模型本身也更有能力了，因此小模型成了不错的起点。下面是目前 Hub 上下载量最高的一些模型：

- 来自 Google 的 [Gemma 4 E2B](https://huggingface.co/google/gemma-4-E2B-it-qat-q4_0-gguf)，GGUF 格式，经过量化感知训练，在 `Q4_0` 下约 3.4 GB。
- 来自 Liquid AI 的 [LFM2.5 2.6B](https://huggingface.co/LiquidAI/LFM2.5-2.6B-GGUF)，GGUF 格式，在 `Q4_K_M` 下约 1.7 GB。
- 来自阿里巴巴的 [Qwen3.8 27B for MLX](https://huggingface.co/mlx-community/Qwen3.8-27B-4bit)，4 bit 下约 16 GB。

前两个能装进 iPhone，Qwen3.8 27B 则能在内存 32 GB 及以上的 Mac 上运行。选用 MLX 模型只需要一行：

```
let model = MLXLanguageModel(modelId: "mlx-community/Qwen3.8-27B-4bit")
```

而如果你手边有四台顶配 Mac Studio，来自 Z.ai 的 [GLM-5.3](https://huggingface.co/zai-org/GLM-5.3) 在 BF16 下大约要 1.5 TB。对我们其余人来说，可以通过 Inference Providers 使用它。

## 升级到 1.0

```
dependencies: [
    .package(
        url: "https://github.com/huggingface/AnyLanguageModel",
        from: "1.0.0",
        traits: ["MLX"]
    )
]
```

如果你要升级现有的 app，请参阅 [AnyLanguageModel](https://github.com/huggingface/AnyLanguageModel/releases/tag/1.0.0)、[swift-huggingface](https://github.com/huggingface/swift-huggingface/releases/tag/1.0.0) 和 [swift-xet](https://github.com/huggingface/swift-xet/releases/tag/1.0.0) 发布说明中的迁移指引，来更新你的代码。

社区反馈和贡献塑造了我们的好几个主要功能。感谢[每一位贡献者](https://github.com/huggingface/AnyLanguageModel/graphs/contributors)，是你们让 AnyLanguageModel 对 app 开发者更有用。

## 下一步

语言模型已被证明是把智能构建进产品的强大工具。它们也是开发者可以投入使用的众多模型类型之一。我们很期待把这套做法带到更多能力上：熟悉的 Swift API，配上可在设备上运行的、可自选的模型。即将到来：会做决策的模型，以及会倾听的模型。
