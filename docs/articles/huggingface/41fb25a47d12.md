马特

去年 11 月，我们在此博客上介绍了 [AnyLanguageModel](https://huggingface.co/blog/anylanguagemodel)：Apple 基础模型框架的直接替代品，可让您选择应用程序使用的模型和提供程序。我们听说应用程序开发人员对本地模型感到好奇，但并不总是确定如何开始。他们还希望避免支持多个推理提供程序带来的额外复杂性。 AnyLanguageModel 就是从这种反馈中产生的。

本地推理和托管推理各有优势，并且在构建新一代智能应用程序中都发挥着作用。共享 API 可以更轻松地为每个任务选择正确的模型。

一年后发布了数十个版本，[AnyLanguageModel 1.0](https://github.com/huggingface/AnyLanguageModel/releases/tag/1.0.0) 以及 [swift-huggingface 1.0](https://github.com/huggingface/swift-huggingface/releases/tag/1.0.0) 和 [swift-xet 1.0](https://github.com/huggingface/swift-xet/releases/tag/1.0.0)。

以下是更改的内容以及接下来的内容：

## 一个直接兼容的 API

AnyLanguageModel 的核心思想保持不变：将 Foundation Models API 与适合您的应用程序的模型结合使用。首先，更改您的“import”语句：
```
- import FoundationModels
+ import AnyLanguageModel
```
然后，相同的会话代码可与系统模型、通过 llama.cpp、MLX 和 Core ML 的开放权重模型以及下面的托管提供程序配合使用。

在过去的一年里，我们添加了几项主要功能：

- **工具调用**适用于每个提供商。
- **引导生成**也适用于每个提供者，包括嵌套的“@Generable”类型及其数组。
- **图像支持**允许您使用 Foundation Models 27 的语法将图像附加到提示，包括当您在 iOS、macOS 和 VisionOS 27 上使用系统模型时。

在 OS 27 上，AnyLanguageModel 还适用于符合 Foundation Models 的“LanguageModel”协议的任何模型，包括 [Core AI](https://github.com/apple/coreai-models) 模型。

除了 AnyLanguageModel 之外，我们还构建了 [swift-huggingface](https://github.com/huggingface/swift-huggingface) 和 [swift-xet](https://github.com/huggingface/swift-xet)，以将模型从 Hub 加速下载到 Swift 应用程序。

## 也有托管模型

今年对托管模型的支持也得到了扩展。 AnyLanguageModel 现在支持：

- OpenAI 的聊天完成和响应 API
- [开放响应](https://www.openresponses.org)，适用于任何具有兼容端点的提供商
- Anthropic 的消息 API，具有自适应思维和工作选项
- 谷歌的 Gemini API
- 奥拉马
- 私有云计算，操作系统 27
- [Hugging Face Inference Providers](https://huggingface.co/docs/inference-providers/index) 以及其他 OpenAI 兼容端点（例如 OpenRouter），通过自定义基本 URL

借助推理提供程序，您可以使用太大而无法在具有相同会话代码的设备上运行的开放权重模型：
```
let model = OpenAILanguageModel(
    baseURL: URL(string: "https://router.huggingface.co/v1/")!,
    apiKey: ProcessInfo.processInfo.environment["HF_TOKEN"]!,
    model: "openai/gpt-oss-120b",
    apiVariant: .chatCompletions
)
```
托管提供程序具有与本地模型相同的功能：引导生成、流式传输工具调用以及响应中的令牌使用。

推理现在也成为笔录的一部分。当您切换提供程序时，如果新提供程序无法重播推理块，则会自动从请求中省略推理块。

API 密钥来自闭包而不是字符串，因此您的应用程序可以从您自己的服务器获取短期令牌。 [README](https://github.com/huggingface/AnyLanguageModel#api-credentials-and-security) 解释了何时让人们携带自己的密钥以及何时通过代理路由请求。

AnyLanguageModel 也可以在 Linux 上运行，因此相同的代码可以在服务器上运行。

## 开放重量模型变得更好

虽然我们使本地模型更易于使用，但模型本身也变得更加强大，使小型模型成为一个良好的起点。以下是目前 Hub 上下载最多的一些模型：

- 来自 Google 的 [Gemma 4 E2B](https://huggingface.co/google/gemma-4-E2B-it-qat-q4_0-gguf)，在 GGUF 中，“Q4_0”处约 3.4 GB，具有量化感知训练。
- [LFM2.5 2.6B](https://huggingface.co/LiquidAI/LFM2.5-2.6B-GGUF) 来自 Liquid AI，以 GGUF 形式，在 `Q4_K_M` 处约 1.7 GB。
- [Qwen3.8 27B for MLX](https://huggingface.co/mlx-community/Qwen3.8-27B-4bit) 来自阿里巴巴，4 位时约 16 GB。

前两个适用于 iPhone，Qwen3.8 27B 可在具有 32 GB 或更多内存的 Mac 上运行。选择 MLX 型号只需一行：
```
let model = MLXLanguageModel(modelId: "mlx-community/Qwen3.8-27B-4bit")
```
如果您手边有四个已满的 Mac Studio，则 Z.ai 的 [GLM-5.3](https://huggingface.co/zai-org/GLM-5.3) 在 BF16 中大约需要 1.5 TB。对于我们其他人来说，可以通过推理提供程序获得它。

## 升级到1.0
```
dependencies: [
    .package(
        url: "https://github.com/huggingface/AnyLanguageModel",
        from: "1.0.0",
        traits: ["MLX"]
    )
]
```
如果您要升级现有应用程序，请参阅 [AnyLanguageModel](https://github.com/huggingface/AnyLanguageModel/releases/tag/1.0.0)、[swift-huggingface](https://github.com/huggingface/swift-huggingface/releases/tag/1.0.0) 中的迁移指南，以及[swift-xet](https://github.com/huggingface/swift-xet/releases/tag/1.0.0) 发行说明以帮助更新代码。

社区反馈和贡献塑造了我们的几个主要功能。感谢[所有贡献者](https://github.com/huggingface/AnyLanguageModel/graphs/contributors) 帮助 AnyLanguageModel 对应用程序开发人员更加有用。

## 接下来是什么

语言模型已被证明是将智能构建到产品中的强大工具。它们也是开发人员可以投入使用的多种模型之一。我们很高兴能够将相同的方法引入更多功能：熟悉的 Swift API 以及在设备上运行的模型选择。即将推出：决策模型和倾听模型。
