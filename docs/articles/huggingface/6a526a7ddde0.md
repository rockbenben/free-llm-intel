### 用法

首先，应安装 `diffusers==0.10.2` 以运行下面的代码片段：

```
pip install diffusers==0.10.2 transformers scipy ftfy accelerate
```

本文使用模型 [`v1-4`](https://huggingface.co/CompVis/stable-diffusion-v1-4) 版本，但你也可以几乎不改代码地使用 1.5、2、2.1 等其他版本。

Stable Diffusion 模型只需几行代码即可推理，用的是 [`StableDiffusionPipeline`](https://github.com/huggingface/diffusers/blob/main/src/diffusers/pipelines/stable_diffusion/pipeline_stable_diffusion.py) 流水线。这条流水线通过一个简单的 `from_pretrained` 调用，把文本生成图像所需的一切准备就绪。

```
from diffusers import StableDiffusionPipeline

pipe = StableDiffusionPipeline.from_pretrained("CompVis/stable-diffusion-v1-4")
```

如果有 GPU，把它挪上去！

```
pipe.to("cuda")
```

**注**：如果你受 GPU 显存限制、可用 GPU RAM 不到 10GB，加载 `StableDiffusionPipeline` 时请使用 float16 精度而非上面示范的默认 float32 精度。

做法是从 `fp16` 分支加载权重，并告诉 `diffusers` 权重是 float16 精度：

```
import torch
from diffusers import StableDiffusionPipeline

pipe = StableDiffusionPipeline.from_pretrained("CompVis/stable-diffusion-v1-4", revision="fp16", torch_dtype=torch.float16)
```

运行流水线只需定义提示词并调用 `pipe`。

```
prompt = "a photograph of an astronaut riding a horse"

image = pipe(prompt).images[0]

# you can save the image with
# image.save(f"astronaut_rides_horse.png")
```

import torch

你可以用 `num_inference_steps` 参数改变推理步数。

一般而言，步数越多结果越好，但步数越多，生成耗时也越长。Stable Diffusion 在相对较少的步数下就有不错的表现，所以我们推荐使用默认推理步数 `50`。想要更快，就用更小的数字；想要潜在更高质量，就用更大的数字。

来试试减少去噪步数运行流水线。

```
import torch

generator = torch.Generator("cuda").manual_seed(1024)
image = pipe(prompt, guidance_scale=7.5, num_inference_steps=15, generator=generator).images[0]

# you can save the image with
# image.save(f"astronaut_rides_horse.png")
```

[![png](https://huggingface.co/blog/assets/98_stable_diffusion/stable_diffusion_16_1.png)](https://huggingface.co/blog/assets/98_stable_diffusion/stable_diffusion_16_1.png)

可以看到结构相同，但宇航员的服装和整匹马的形态都出了问题。这说明只用 15 步去噪会显著降低生成质量。如前所述，`50` 步去噪通常足以生成高质量图像。

除了 `num_inference_steps`，前面所有示例还用到了另一个参数 `guidance_scale`。`guidance_scale` 是一种增强对条件信号（这里是文本）的遵循度、同时提升整体样本质量的手段。它也被称为 [classifier-free guidance](https://arxiv.org/abs/2207.12598)：简单说就是强迫生成结果更贴合提示词，代价可能是图像质量或多样性。对 Stable Diffusion 来说，`7` 到 `8.5` 之间的值通常不错。流水线默认使用 `7.5`。

如果把这个值设得非常大，图像可能很好看，但多样性会下降。关于这个参数的技术细节，请参阅[本文"编写你自己的推理流水线"一节](https://huggingface.co/blog/stable_diffusion#writing-your-own-inference-pipeline)。

接下来看看如何一次性为同一个提示词生成多张图像。首先创建一个 `image_grid` 函数帮助我们以网格形式美观地展示：

```
from PIL import Image

def image_grid(imgs, rows, cols):
    assert len(imgs) == rows*cols

    w, h = imgs[0].size
    grid = Image.new('RGB', size=(cols*w, rows*h))
    grid_w, grid_h = grid.size
    
    for i, img in enumerate(imgs):
        grid.paste(img, box=(i%cols*w, i//cols*h))
    return grid
```

为同一提示词生成多张图，只需把同一个提示词重复多次放进列表，然后把列表（而不是之前的字符串）传给流水线。

```
num_images = 3
prompt = ["a photograph of an astronaut riding a horse"] * num_images

images = pipe(prompt).images

grid = image_grid(images, rows=1, cols=3)

# you can save the grid with
# grid.save(f"astronaut_rides_horse.png")
```

[![png](https://huggingface.co/blog/assets/98_stable_diffusion/stable_diffusion_22_1.png)](https://huggingface.co/blog/assets/98_stable_diffusion/stable_diffusion_22_1.png)

默认情况下 Stable Diffusion 生成 `512 × 512` 像素的图像。用 `height` 和 `width` 参数很容易覆盖默认值，生成竖版或横版的矩形图像。

选择图像尺寸时，我们建议：

- 确保 `height` 和 `width` 都是 `8` 的倍数。
- 低于 512 可能导致图像质量下降。
- 两个方向都超过 512 会导致图像区域重复（全局一致性丢失）。
- 生成非方形图像的最佳方式是：一个维度用 `512`，另一个维度用更大的值。

看个例子：

```
prompt = "a photograph of an astronaut riding a horse"
image = pipe(prompt, height=512, width=768).images[0]

# you can save the image with
# image.save(f"astronaut_rides_horse.png")
```

[![png](https://huggingface.co/blog/assets/98_stable_diffusion/stable_diffusion_26_1.png)](https://huggingface.co/blog/assets/98_stable_diffusion/stable_diffusion_26_1.png)

## Stable Diffusion 是怎么工作的？

见识了 Stable Diffusion 能生成的高质量图像之后，我们来深入理解一下模型如何运转。

Stable Diffusion 基于一种特殊类型的扩散模型——**潜在扩散（Latent Diffusion）**，出自论文 [High-Resolution Image Synthesis with Latent Diffusion Models](https://arxiv.org/abs/2112.10752)。

总体而言，扩散模型是这样一类机器学习系统：训练目标是把随机高斯噪声*逐步去噪*，最终得到我们想要的样本，比如一张*图像*。想了解更详细的原理，请看[这个 colab](https://colab.research.google.com/github/huggingface/notebooks/blob/main/diffusers/diffusers_intro.ipynb)。

扩散模型在生成图像数据上达到了 SOTA。但它有一个缺点：反向去噪过程是重复、顺序执行的，所以很慢。而且这些模型在像素空间上操作，生成高分辨率图像时像素空间巨大，内存消耗惊人——因此训练和推理都不轻松。

潜在扩散把扩散过程移到更低维的*潜空间（latent space）*而不是真实像素空间，从而大幅降低内存和计算复杂度。这是标准扩散与潜在扩散模型的关键区别：**潜在扩散中，模型训练的是生成图像的潜在（压缩）表示。**

潜在扩散有三个主要组件。

- 自编码器（VAE）。
- [U-Net](https://colab.research.google.com/github/huggingface/notebooks/blob/main/diffusers/diffusers_intro.ipynb#scrollTo=wW8o1Wp0zRkq)。
- 文本编码器，例如 [CLIP 的文本编码器](https://huggingface.co/docs/transformers/model_doc/clip#transformers.CLIPTextModel)。

**1. 自编码器（VAE）**

VAE 模型分两部分：编码器和解码器。编码器用于把图像转换成低维潜在表示，作为 *U-Net* 模型的输入。解码器则反过来，把潜在表示变换回图像。

在潜在扩散的*训练*过程中，编码器用来获取图像的潜在表示（*latents*），供前向扩散流程使用——每一步叠加越来越多的噪声。在*推理*过程中，由反向扩散流程得到的去噪 latents 再用 VAE 解码器转换回图像。我们会看到，推理时**只需要 VAE 解码器**。

**2. U-Net**

U-Net 由编码器部分和解码器部分组成，都由 ResNet 块构成。编码器把图像表示压缩成更低分辨率的表示，解码器再把低分辨率图像表示解码回原来的高分辨率、且理论上噪声更少的表示。具体地，U-Net 的输出预测噪声残差（noise residual），可用于计算预测的去噪图像表示。

为防止 U-Net 在下采样过程中丢失重要信息，通常在编码器的下采样 ResNet 和解码器的上采样 ResNet 之间添加捷径连接（short-cut connections）。此外，Stable Diffusion 的 U-Net 通过交叉注意力层（cross-attention layers）让输出以文本嵌入为条件。交叉注意力层被加到 U-Net 的编码器和解码器两侧，通常位于 ResNet 块之间。

**3. 文本编码器**

文本编码器负责把输入提示词（如 "An astronaut riding a horse"）转换成 U-Net 能理解的嵌入空间。它通常就是一个简单的*基于 transformer* 的编码器，把输入 token 序列映射为潜在文本嵌入序列。

受 [Imagen](https://imagen.research.google/) 启发，Stable Diffusion 在训练期间**不**训练文本编码器，直接使用 CLIP 已训练好的文本编码器 [CLIPTextModel](https://huggingface.co/docs/transformers/model_doc/clip#transformers.CLIPTextModel)。

**潜在扩散为什么又快又高效？**

由于潜在扩散在低维空间上操作，相比像素空间扩散模型，内存和计算需求都大幅降低。例如，Stable Diffusion 使用的自编码器缩减因子为 8，也就是说形状为 `(3, 512, 512)` 的图像在潜空间变成 `(4, 64, 64)`——空间压缩比为 `8 × 8 = 64`。

这就是为什么能如此快速地生成 `512 × 512` 图像，甚至在 16GB 的 Colab GPU 上！

**推理时的 Stable Diffusion**

把一切串起来，近距离看看模型在推理时如何工作——下图是其逻辑流程。

![sd-pipeline](https://raw.githubusercontent.com/patrickvonplaten/scientific_images/master/stable_diffusion.png)

Stable Diffusion 模型的输入是潜噪声种子（latent seed）和文本提示词。潜种子用于生成 $64 \times 64$ 大小的随机潜在图像表示；文本提示词则经 CLIP 文本编码器转换为 $77 \times 768$ 的文本嵌入。

接下来 U-Net 在文本嵌入的条件下迭代地*去噪*随机潜在图像表示。U-Net 的输出（噪声残差）由调度算法（scheduler algorithm）用来计算去噪后的潜在图像表示。可供选择的调度算法很多，各有优缺点。对 Stable Diffusion，我们推荐以下之一：

- [PNDM scheduler](https://github.com/huggingface/diffusers/blob/main/src/diffusers/schedulers/scheduling_pndm.py)（默认）
- [DDIM scheduler](https://github.com/huggingface/diffusers/blob/main/src/diffusers/schedulers/scheduling_ddim.py)
- [K-LMS scheduler](https://github.com/huggingface/diffusers/blob/main/src/diffusers/schedulers/scheduling_lms_discrete.py)

调度算法如何工作的理论超出了本文范围，简单记住：它们根据上一时刻的噪声表示和预测的噪声残差，计算预测的去噪图像表示。更多细节推荐阅读 [Elucidating the Design Space of Diffusion-Based Generative Models](https://arxiv.org/abs/2206.00364)。

*去噪*过程重复约 50 次，一步步得到更好的潜在图像表示。完成后，潜在图像表示由变分自编码器的解码器部分解码为图像。

简要介绍了潜在扩散和 Stable Diffusion 之后，来看如何高级地使用 🤗 Hugging Face 的 `diffusers` 库！

## 编写你自己的推理流水线

最后，我们演示如何用 `diffusers` 创建自定义扩散流水线。编写自定义推理流水线是 `diffusers` 库的高级用法，在你需要替换某些组件（比如上文说的 VAE 或调度器）时会很有用。

举例来说，我们展示如何让 Stable Diffusion 使用另一种调度器——[Katherine Crowson](https://github.com/crowsonkb) 的 K-LMS 调度器（在[这个 PR](https://github.com/huggingface/diffusers/pull/185) 中加入）。

[预训练模型](https://huggingface.co/CompVis/stable-diffusion-v1-4/tree/main)包含搭建完整扩散流水线所需的全部组件，存放在以下目录：

- `text_encoder`：Stable Diffusion 使用 CLIP，但其他扩散模型可能使用 BERT 等其他编码器。
- `tokenizer`：必须与 `text_encoder` 模型所使用的匹配。
- `scheduler`：调度算法，训练期间用于逐步向图像添加噪声。
- `unet`：用于生成输入潜在表示的模型。
- `vae`：自编码器模块，用来把潜在表示解码成真实图像。

我们可以用 `from_pretrained` 的 `subfolder` 参数按目录加载各组件。

```
from transformers import CLIPTextModel, CLIPTokenizer
from diffusers import AutoencoderKL, UNet2DConditionModel, PNDMScheduler

# 1. Load the autoencoder model which will be used to decode the latents into image space. 
vae = AutoencoderKL.from_pretrained("CompVis/stable-diffusion-v1-4", subfolder="vae")

# 2. Load the tokenizer and text encoder to tokenize and encode the text. 
tokenizer = CLIPTokenizer.from_pretrained("openai/clip-vit-large-patch14")
text_encoder = CLIPTextModel.from_pretrained("openai/clip-vit-large-patch14")

# 3. The UNet model for generating the latents.
unet = UNet2DConditionModel.from_pretrained("CompVis/stable-diffusion-v1-4", subfolder="unet")
```

现在不加载预定义调度器，而是带一些合适参数加载 [K-LMS 调度器](https://github.com/huggingface/diffusers/blob/71ba8aec55b52a7ba5a1ff1db1265ffdd3c65ea2/src/diffusers/schedulers/scheduling_lms_discrete.py#L26)。

```
from diffusers import LMSDiscreteScheduler

scheduler = LMSDiscreteScheduler(beta_start=0.00085, beta_end=0.012, beta_schedule="scaled_linear", num_train_timesteps=1000)
```

接下来把模型搬到 GPU。

```
torch_device = "cuda"
vae.to(torch_device)
text_encoder.to(torch_device)
unet.to(torch_device) 
```

现在定义生成图像要用的参数。

注意 `guidance_scale` 的定义类似 [Imagen 论文](https://arxiv.org/pdf/2205.11487.pdf)公式 (2) 中的引导权重 `w`。`guidance_scale == 1` 相当于不做 classifier-free guidance。这里和前面一样设为 7.5。

与之前的示例不同，我们把 `num_inference_steps` 设为 100，以获得更精细的图像。

```
prompt = ["a photograph of an astronaut riding a horse"]

height = 512                        # default height of Stable Diffusion
width = 512                         # default width of Stable Diffusion

num_inference_steps = 100           # Number of denoising steps

guidance_scale = 7.5                # Scale for classifier-free guidance

generator = torch.manual_seed(0)    # Seed generator to create the initial latent noise

batch_size = len(prompt)
```

首先获取传入提示词的 `text_embeddings`。这些嵌入将用于给 UNet 模型做条件、引导图像生成向贴近输入提示词的方向靠拢。

```
text_input = tokenizer(prompt, padding="max_length", max_length=tokenizer.model_max_length, truncation=True, return_tensors="pt")

text_embeddings = text_encoder(text_input.input_ids.to(torch_device))[0]
```

我们还要获取用于 classifier-free guidance 的无条件文本嵌入，即 padding token（空文本）的嵌入。它们的形状需要与条件 `text_embeddings` 一致（`batch_size` 和 `seq_length`）。

```
max_length = text_input.input_ids.shape[-1]
uncond_input = tokenizer(
    [""] * batch_size, padding="max_length", max_length=max_length, return_tensors="pt"
)
uncond_embeddings = text_encoder(uncond_input.input_ids.to(torch_device))[0]   
```

classifier-free guidance 需要两次前向传播：一次用条件输入（`text_embeddings`），一次用无条件嵌入（`uncond_embeddings`）。实践中可以把两者拼成一个 batch，避免两次前向传播。

```
text_embeddings = torch.cat([uncond_embeddings, text_embeddings])
```

接下来生成初始随机噪声。

```
latents = torch.randn(
    (batch_size, unet.in_channels, height // 8, width // 8),
    generator=generator,
)
latents = latents.to(torch_device)
```

此时检查 `latents` 会发现形状是 `torch.Size([1, 4, 64, 64])`，比要生成的图像小得多。模型之后会把这份潜在表示（纯噪声）变换成 `512 × 512` 的图像。

然后初始化调度器，传入我们选择的 `num_inference_steps`。调度器会计算去噪过程中使用的 `sigmas` 和精确时间步数值。

```
scheduler.set_timesteps(num_inference_steps)
```

K-LMS 调度器需要把 `latents` 乘以其 `sigma` 值。在这里做：

```
latents = latents * scheduler.init_noise_sigma
```

可以写去噪循环了。

```
from tqdm.auto import tqdm

scheduler.set_timesteps(num_inference_steps)

for t in tqdm(scheduler.timesteps):
    # expand the latents if we are doing classifier-free guidance to avoid doing two forward passes.
    latent_model_input = torch.cat([latents] * 2)

    latent_model_input = scheduler.scale_model_input(latent_model_input, timestep=t)

    # predict the noise residual
    with torch.no_grad():
        noise_pred = unet(latent_model_input, t, encoder_hidden_states=text_embeddings).sample

    # perform guidance
    noise_pred_uncond, noise_pred_text = noise_pred.chunk(2)
    noise_pred = noise_pred_uncond + guidance_scale * (noise_pred_text - noise_pred_uncond)

    # compute the previous noisy sample x_t -> x_t-1
    latents = scheduler.step(noise_pred, t, latents).prev_sample
```

现在用 `vae` 把生成的 `latents` 解码回图像。

```
# scale and decode the image latents with vae
latents = 1 / 0.18215 * latents
with torch.no_grad():
    image = vae.decode(latents).sample
```
