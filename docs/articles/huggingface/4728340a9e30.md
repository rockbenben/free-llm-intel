## TL;DR

今天 Google 发布了更好的一族*多语言*视觉-语言编码器：[SigLIP 2](https://huggingface.co/collections/google/siglip2-67b5dcef38c175486e240107)。作者在 SigLIP 的训练目标（*sigmoid loss*）之上扩展了额外目标，以改善语义理解、定位（localization）和稠密特征。

在所有模型规模上，SigLIP 2 在核心能力上**超越**旧版 SigLIP——包括零样本分类、图文检索，以及作为视觉-语言模型（VLM）视觉表示提取时的迁移表现。

额外的惊喜是动态分辨率（`naflex`）变体，对纵横比和分辨率敏感的下游任务特别有用。

## 引言

视觉编码器很简单：输入图像，编码成表示，表示供下游任务使用——分类、目标检测、图像分割等等。研究者一直在追求**稠密**、**具位置感知**、**语义丰富**的视觉表示。

[CLIP](https://huggingface.co/docs/transformers/en/model_doc/clip) 和 [ALIGN](https://huggingface.co/docs/transformers/en/model_doc/align) 是第一批通过联合训练把图像编码器和文本编码器对齐的例子，这种思路打开了训练视觉模型的新方式。[SigLIP](https://huggingface.co/docs/transformers/en/model_doc/siglip) 更进一步，用 *sigmoid loss* 替换 CLIP 的*对比损失*，做出了更好的编码器。

启示是什么？借助更聪明的训练目标，我们持续构建结构更好、更细粒度、更强大的视觉编码器。SigLIP 2 正是如此：在 SigLIP 的训练目标之上叠加一系列聪明有趣的目标，产出更好的视觉语言编码器。

这篇博客我们想玩点新花样。与其罗列"新在哪、去哪找"，我们一起做一个小练习：从 SigLIP 出发，依次抛出一连串问题（前缀 🤔）和答案（新的小节标题），逐步覆盖 SigLIP 2 的全部更新。听起来不错？

我们的旅程从 patch size 为 **16**、图像分辨率为 **256** 的视觉编码器开始。训练起点有四个变体：

- [siglip2-base-patch16-256](https://hf.co/google/siglip2-base-patch16-256)
- [siglip2-large-patch16-256](https://hf.co/google/siglip2-large-patch16-256)
- [siglip2-so400m-patch16-256](https://hf.co/google/siglip2-so400m-patch16-256)
- [siglip2-giant-opt-patch16-256](https://hf.co/google/siglip2-giant-opt-patch16-256)

**🤔 问题 1：有什么（省力的）辅助训练目标，能帮我们学到更好的视觉表示（在位置感知和局部性意义上）？**

## 加一个解码器（就这么简单）

给训练加一个解码器。现在我们有了图像编码器、文本编码器和一个*文本解码器*。文本解码器有三个目标：

- 预测整图描述（caption）
- 给定描述*特定*图像区域的 caption，预测 bounding box 坐标
- 给定 bounding box 坐标，预测该区域的 caption

解码器为视觉编码器提供了额外信号，使其具备位置感知能力。这是 SigLIP 2 训练配方的第一项改进。

**🤔 问题 2：如何提升图像表示的细粒度局部语义？**

## 用 Global-Local Loss 与 Masked Prediction 做自蒸馏

为了提升图像表示的细粒度局部语义，我们引入两个关键训练目标：Global-Local Loss 和 Masked Prediction Loss。借鉴自监督学习的思路，我们采用*自蒸馏*：同一个模型既是老师也是学生。每次迭代后，老师是学生参数的滑动平均。

- **Global-Local Loss**：学生网络只看到训练图的部分（局部）视图，训练目标是匹配老师从完整图像得到的表示。
- **Masked Prediction Loss**：学生网络中 50% 的图像 patch 嵌入被 mask token 覆盖。学生需要在被覆盖的位置匹配老师的特征。

这些目标教会视觉编码器具备空间感知并改善局部语义。作者只在 sigmoid 和 decoder loss 完成 **80%** 训练之后才加入这个 loss——一是省算力（额外的 loss 相当贵），二是避免对编码器产生负面影响。

**🤔 问题 3：如何让模型适配不同分辨率？**

## 适配不同分辨率

众所周知，图像模型对分辨率和纵横比的变化非常敏感。这里可以用两种不同的方法来让模型适配不同分辨率和 patch size。

- **固定分辨率变体**：取 95% 训练进度时的检查点，调整位置嵌入和 patch 嵌入的尺寸，然后按请求的（可能更大的）分辨率继续训练。
- **动态分辨率变体**：借鉴 [FlexiViT](https://huggingface.co/papers/2212.08013)（使用不同序列长度的输入）和 [NaViT](https://huggingface.co/papers/2307.06304)（遵循原生纵横比），我们可以造出 **NaFlex** 变体。这很有意思：单个模型既能做 OCR（纵横比畸变小），又能做文档理解（合适的分辨率）。

> 带 -naflex 后缀的模型就是动态分辨率变体。固定分辨率模型可以直接用现有的 SiglipModel 类开箱即用，而 naflex 变体需要用 Siglip2Model。用 pipeline API 时我们会自动处理这件事！

SigLIP 到 SigLIP 2 的演进就讲到这里。接下来看 SigLIP 2 的应用。

## 用 transformers 跑推理

模型推理相当简单。下面的代码可以直接复制粘贴，在免费版 Colab notebook 上跑起来 🚀

> 要在 SigLIP 2 上推理，请从 main 或从这个稳定分支安装 transformers：
> pip install git+https://github.com/huggingface/transformers@v4.49.0-SigLIP-2

### 零样本分类

这里用顺手的 `pipeline` API 展示 SigLIP 2 的零样本分类能力。

```
from transformers import pipeline

ckpt = "google/siglip2-so400m-patch14-384"
pipe = pipeline(model=ckpt, task="zero-shot-image-classification")

inputs = {
    "images": [
        "https://huggingface.co/datasets/merve/coco/resolve/main/val2017/000000000285.jpg", # bear
        "https://huggingface.co/datasets/merve/coco/resolve/main/val2017/000000000776.jpg", # teddy bear
    ],
    "texts": [
        "bear looking into the camera",
        "bear looking away from the camera",
        "a bunch of teddy bears",
        "two teddy bears",
        "three teddy bears"
    ],
}

outputs = pipe(inputs["images"], candidate_labels=inputs["texts"])
```

### 编码图像供下游任务使用

还可以用下面的方式编码图像：

```
import torch
from transformers import AutoModel, AutoProcessor
from transformers.image_utils import load_image

ckpt = "google/siglip2-so400m-patch14-384"
model = AutoModel.from_pretrained(ckpt, device_map="auto").eval()
processor = AutoProcessor.from_pretrained(ckpt)

image = load_image("https://huggingface.co/datasets/merve/coco/resolve/main/val2017/000000000285.jpg")
inputs = processor(images=[image], return_tensors="pt").to(model.device)

with torch.no_grad():
    image_embeddings = model.get_image_features(**inputs)    

print(image_embeddings.shape) # torch.Size([1, 1152])
```

## 把编码器用于 VLM

对齐了文本信息的视觉编码器在**视觉语言模型**（VLM）的开发中越来越关键。构建 VLM 的常见做法是把预训练视觉编码器和预训练 LLM 组合起来，用多模态数据在多样的视觉-语言任务上联合训练。

善用 SigLIP 系列视觉编码器的一个典范是 **PaliGemma**。想深入了解 PaliGemma 的能力可以读这篇 [PaliGemma](https://huggingface.co/blog/paligemma) 博客。在此基础上新近推出的 [PaliGemma 2](https://huggingface.co/blog/paligemma2) 更进了一步，把 SigLIP 与更强的 Gemma 2 LLM 集成。在类 PaliGemma 的设置里把 SigLIP 换成 SigLIP 2 会怎样，真让人期待。
