## Core ML 的新优化

Core ML 是一个成熟的框架，可以让机器学习模型在设备端高效运行，充分利用 Apple 设备上的所有算力硬件：CPU、GPU 以及专门处理 ML 任务的 Neural Engine。受 Stable Diffusion 和带聊天界面的大语言模型流行的推动，端侧执行正经历一个格外受关注的时期。很多人出于便利、隐私、节省 API 成本等各种原因想在自己的硬件上跑这些模型。自然，许多开发者在探索端侧高效运行这些模型的方法，并打造新的 app 和用例。Core ML 为这一目标所做的改进对整个社区都是大新闻！

Core ML 的优化变化涉及两个（互补的）软件包：

- Core ML 框架本身。这是在 Apple 硬件上运行 ML 模型的引擎，是操作系统的一部分。模型必须导出为框架支持的特定格式，这种格式也被称为“Core ML”。
- `coremltools` 转换包。这是一个[开源 Python 模块](https://github.com/apple/coremltools)，使命是把 PyTorch 或 Tensorflow 模型转换成 Core ML 格式。

`coremltools` 现在包含一个名为 `coremltools.optimize` 的新子模块，汇集所有压缩和优化工具。关于这个包的完整细节，请看 [WWDC 这场分享](https://developer.apple.com/wwdc23/10047)。在 Stable Diffusion 的场景里，我们会用到*6-bit palettization*——一种量化方式，把模型权重从 16 位浮点表示压缩到每个参数仅 6 位。“palettization”这个名字指的是一种与计算机图形学中限制颜色数量所用的相似技术：颜色表（“调色板”）包含固定数量的颜色，图像中的颜色被替换为调色板中最接近颜色的索引。这立刻带来大幅缩减存储体积的好处，从而缩短下载时间、减少设备磁盘占用。

2-bit palettization 示意图。图片来源：Apple WWDC'23 Session

压缩后的 6 位*权重*不能直接参与计算，因为它们只是表索引，不再表示原始权重的大小。因此 Core ML 需要先把 palettized 权重解压再用。在旧版 Core ML 中，解压发生在模型首次从磁盘加载时，所以内存用量等于未压缩模型的大小。有了新改进，权重以 6 位数字保存，推理逐层推进时按需现场转换。这听起来可能慢——一次推理要做大量解压操作——但通常比把所有权重都准备成 16 位模式更高效！原因在于内存传输处于执行的关键路径上，传输更少的数据比传输未压缩的数据更快。

## 使用量化和优化后的 Stable Diffusion 模型

[去年 12 月](https://huggingface.co/blog/diffusers-coreml)，Apple 发布了 [`ml-stable-diffusion`](https://github.com/apple/ml-stable-diffusion)，一个基于 [diffusers](https://github.com/huggingface/diffusers) 的开源仓库，可以轻松把 Stable Diffusion 模型转换成 Core ML。它还应用了[对 Transformer 注意力层的优化](https://machinelearning.apple.com/research/neural-engine-transformers)，让配备 Neural Engine 的设备推理更快。WWDC 之后 `ml-stable-diffusion` 刚刚更新，内容包括：

- 转换时支持量化，使用 `--quantize-nbits`，可以量化到 8、6、4 甚至 2 bits！为获得最佳效果，我们推荐使用 6-bit 量化：精度损失小，同时推理快、内存节省显著。如果想更低，请看[这一节](https://huggingface.co/blog/fast-diffusers-coreml#using-less-than-6-bits)的高级技巧。
- 注意力层的额外优化，在 Neural Engine 上取得更好性能！诀窍是把 query 序列切成 512 的块，避免创建大型中间张量。这个方法在代码里叫 `SPLIT_EINSUM_V2`，能把性能提升 10% 到 30%。

为了让大家都能轻松用上这些改进，我们转换了四个官方 Stable Diffusion 模型并推送到 [Hub](https://huggingface.co/apple)。所有变体如下：

| 模型 | 未压缩 | Palettized |
| --- | --- | --- |
| Stable Diffusion 1.4 | [Core ML, `float16`](https://huggingface.co/apple/coreml-stable-diffusion-v1-4) | [Core ML, 6-bit palettized](https://huggingface.co/apple/coreml-stable-diffusion-1-4-palettized) |
| Stable Diffusion 1.5 | [Core ML, `float16`](https://huggingface.co/apple/coreml-stable-diffusion-v1-5) | [Core ML, 6-bit palettized](https://huggingface.co/apple/coreml-stable-diffusion-v1-5-palettized) |
| Stable Diffusion 2 base | [Core ML, `float16`](https://huggingface.co/apple/coreml-stable-diffusion-2-base) | [Core ML, 6-bit palettized](https://huggingface.co/apple/coreml-stable-diffusion-2-base-palettized) |
| Stable Diffusion 2.1 base | [Core ML, `float16`](https://huggingface.co/apple/coreml-stable-diffusion-2-1-base) | [Core ML, 6-bit palettized](https://huggingface.co/apple/coreml-stable-diffusion-2-1-base-palettized) |

要使用 6-bit 模型，你需要开发版的 iOS/iPadOS 17 或 macOS 14（Sonoma），因为只有它们包含最新版的 Core ML 框架。如果你是注册开发者，可以从 [Apple 开发者网站](https://developer.apple.com)下载，或者等几周后发布的公开测试版（public beta）。

注意，每个变体既有 Core ML 格式，也有 `zip` 压缩包。Zip 文件很适合原生 app，比如我们的[开源演示 app](https://github.com/huggingface/swift-coreml-diffusers)和其他[第三方工具](https://github.com/godly-devotion/MochiDiffusion)。如果你只想在自己的硬件上跑模型，最简单的方式是用我们的演示 app，选择想测试的量化模型。你需要用 Xcode 编译这个 app，但 App Store 很快就会提供更新版下载。更多细节见[之前的文章](https://huggingface.co/blog/fast-mac-diffusers)。

在演示 app 中运行 6-bit 的 stable-diffusion-2-1-base 模型

如果你想下载某个特定的 Core ML 包并集成到自己的 Xcode 项目，可以 clone 仓库，或者用类似下面的代码直接下载需要的版本。

```
from huggingface_hub import snapshot_download
from pathlib import Path

repo_id = "apple/coreml-stable-diffusion-2-1-base-palettized"
variant = "original/packages"

model_path = Path("./models") / (repo_id.split("/")[-1] + "_" + variant.replace("/", "_"))
snapshot_download(repo_id, allow_patterns=f"{variant}/*", local_dir=model_path, local_dir_use_symlinks=False)
print(f"Model downloaded at {model_path}")
```

## 转换和优化自定义模型

如果你想使用个性化的 Stable Diffusion 模型（比如你自己微调或做过 dreambooth 的模型），可以用 Apple 的 ml-stable-diffusion 仓库自己做转换。下面是简要步骤，但建议阅读[文档细节](https://github.com/apple/ml-stable-diffusion#-converting-models-to-core-ml)。

要应用量化，你需要最新版本的 `coremltools`、`apple/ml-stable-diffusion` 和 Xcode 才能完成转换。

- 从 [GitHub 的 releases 页面](https://github.com/apple/coremltools/releases)下载 coremltools 7.0 beta。
- 从 [Apple 开发者网站](https://developer.apple.com/)下载 Xcode 15.0 beta。
- 从[仓库](https://github.com/apple/ml-stable-diffusion)下载 `apple/ml-stable-diffusion` 并按安装说明操作。

- 选择要转换的模型。你可以自己训练，也可以从 [Hugging Face Diffusers Models Gallery](https://huggingface.co/spaces/huggingface-projects/diffusers-gallery) 挑选。例如，我们来转换 [`prompthero/openjourney-v4`](https://huggingface.co/prompthero/openjourney-v4)。
- 安装 `apple/ml-stable-diffusion`，先用 `ORIGINAL` 注意力实现做一次转换，像这样：

```
python -m python_coreml_stable_diffusion.torch2coreml \
    --model-version prompthero/openjourney-v4 \
    --convert-unet \
    --convert-text-encoder \
    --convert-vae-decoder \
    --convert-vae-encoder \
    --convert-safety-checker \
    --quantize-nbits 6 \
    --attention-implementation ORIGINAL \
    --compute-unit CPU_AND_GPU \
    --bundle-resources-for-swift-cli \
    --check-output-correctness \
    -o models/original/openjourney-6-bit
```

- 如果想做 image-to-image 任务，加上 `--convert-vae-encoder`。
- 当 `--quantized-nbits 6`（或更低）时*不要*使用 `--chunk-unet`，因为量化后的模型已经足够小，在 iOS 和 macOS 上都能正常运行。

- 用 `SPLIT_EINSUM_V2` 注意力实现再重复一次转换：

```
python -m python_coreml_stable_diffusion.torch2coreml \
    --model-version prompthero/openjourney-v4 \
    --convert-unet \
    --convert-text-encoder \
    --convert-vae-decoder \
    --convert-safety-checker \
    --quantize-nbits 6 \
    --attention-implementation SPLIT_EINSUM_V2 \
    --compute-unit ALL \
    --bundle-resources-for-swift-cli \
    --check-output-correctness \
    -o models/split_einsum_v2/openjourney-6-bit
```

- 在目标硬件上测试转换后的模型。经验法则：`ORIGINAL` 版本在 macOS 上通常更好，而 `SPLIT_EINSUM_V2` 在 iOS 上通常更快。更多细节和数据点，见社区在旧版 Core ML Stable Diffusion 上[贡献的测试](https://github.com/huggingface/swift-coreml-diffusers/issues/31)。
- 把选定的模型集成到你自己的 app：如果打算把模型内置在 app 里分发，使用 `.mlpackage` 文件（注意这会增大 app 二进制的体积）；否则可以使用编译好的 `Resources`，在 app 启动时动态下载。

如果不使用 `--quantize-nbits` 选项，权重会以 16 位浮点表示。这兼容当前正式版的 Core ML，因此你不必安装 iOS、macOS 或 Xcode 的 beta 版。

## 使用低于 6 bits

6-bit 量化是模型质量、模型体积和便利性之间的最佳平衡点——只需在转换时提供一个选项，就能量化任意预训练模型。这是一种*训练后压缩（post-training compression）*。

上周发布的 `coremltools` beta 版还包含*训练时（training-time）*压缩方法。其思想是：你可以在微调预训练 Stable Diffusion 模型的同时执行权重压缩。这样即使使用 4 位甚至 2 位压缩，也能把质量损失降到最低。之所以有效，是因为权重聚类用的是可微分算法，因此我们可以用常规的训练优化器，在保证模型 loss 最小的同时找到量化表。

我们计划很快评测这个方法，迫不及待想看看优化后的 4-bit 模型效果如何、能跑多快。如果你抢先试了，请给我们留言，我们很乐意看看 🙂

## 结论

量化方法可以用来缩小 Stable Diffusion 模型的体积，让它们在设备端运行更快、消耗更少资源。最新版本的 Core ML 和 `coremltools` 支持 6-bit palettization 这类技术——应用简单，对质量的影响也最小。我们已在 [Hub 上添加了 6-bit palettized 模型](https://huggingface.co/apple)，它们足够小，可以在 iOS 和 macOS 上运行。我们还演示了自己转换微调模型的方法。迫不及待想看到你用这些工具和技术做出什么！
