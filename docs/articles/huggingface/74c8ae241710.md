## 引言

Robert Heinlein 提出，一个全面发展的人应当能胜任从智力到体力的广泛任务，而不是在单一领域过度专精。把"全面发展的人"和机器智能做个类比：AI 系统千差万别，而人类智能的过人之处正在于 versatility——能适应不同任务、环境和意外。大语言模型和视觉-语言模型（LLM、VLM）前景可观，但它们无法与物理世界交互。要补上这块，我们需要在机器人数据上训练的模型。通用机器人模型能提升适应性，用多样化数据改善泛化和鲁棒性。与在孤立任务上训练不同，像 LLM 那样在多样的机器人数据上预训练，可以提升效率和性能。

开发通用人机器人策略（即机器人基础模型）面临三大关键挑战：

- **大规模研究的投入**：要充分利用预训练收益，需要相当规模的投入。
- **设计模型架构**：要能融合多样数据源，同时捕捉复杂的物理交互。这方面的一大挑战是**跨本体（cross-embodiment）训练**——模型必须从配置、控制空间和动作表示都各不相同的多种机器人中学习。现有方法的应对思路：**合并来自不同机器人平台的多模态数据集**以增强泛化；**使用共享表示**来弥合不同机器人形态（单臂、双臂、移动操作机器人）之间的差异。
- **打磨有效的训练配方**：NLP 和视觉领域的最新进展，很大程度上依赖细致的预训练和后训练策略。

在本文中，我们介绍 **π0 和 π0-FAST**——由 **Physical Intelligence** 开发、旨在克服上述挑战的原型模型与学习框架。

## 🔍 什么是 π0？

[Paper](https://www.physicalintelligence.company/download/pi0.pdf) | [Jax Code](https://github.com/Physical-Intelligence/openpi)

π0（**Pi-Zero**）是由 [Physical Intelligence 团队](https://www.physicalintelligence.company)开发的**视觉-语言-动作（VLA）模型**，面向**通用机器人控制**。它建立在**大规模预训练**和**基于 flow matching 的动作生成**之上，让机器人能够在不同本体上执行**灵巧操作任务**。

π0 在来自 **7 个机器人平台**、**68 个不同任务**的数据上训练，在叠衣服、清理餐桌、装购物袋、组装纸箱、拿取物品等复杂真实任务上，展示了很强的 **zero-shot** 和微调后的性能。

与标准机器人策略不同，**π0 采用 flow matching**，能以 **50Hz 生成平滑的实时动作轨迹**，因此在真实部署中非常**高效、精准、适应性强**。Flow matching 源自连续正则化流（continuous normalizing flows），并提升了扩散模型的生成质量。π0 使用的去噪过程原理相同：从随机噪声出发，逐步收敛到一段合理的电机动作序列。

## 在 LeRobot 中如何使用 π0？

首先，你需要升级 lerobot 安装——它现在把 `transformers` 作为依赖！git clone 之后只需执行

```
pip install -e ".[pi0]"
```

π0 模型和 PaliGemma 一样，是需要适配各种框架、环境和场景输入的基础模型。这里的底座模型可以直接使用，尤其是 π0。

### 用预训练 π0 模型做推理

```
python lerobot/scripts/eval.py \
--pretrained_policy.path=/path/to/pretrained/pi0
```

不过由于模型是从 jax 转换到 torch、且来自特定环境，性能有所折损。我们推荐像下面这样把你自己的 π0 微调到你的环境。

### 微调预训练的 π0 模型

要用 `openpi` 的 `pi0_base` checkpoint 微调 **π0** 模型，运行以下命令：

```
python lerobot/scripts/train.py \
--policy.path=lerobot/pi0 \
--dataset.repo_id=danaaubakirova/koch_test
```

要用 PaliGemma 和 Expert Gemma 组成的 π0 神经网络做微调（这两个组件在 π0 微调之前按 VLM 默认参数预训练），运行：

```
python lerobot/scripts/train.py \
--policy.type=pi0 \
--dataset.repo_id=danaaubakirova/koch_test
```

你也可以完全脱离 LeRobot 训练框架，单独使用预训练的 π0 模型：

```
policy = Pi0Policy.from_pretrained("lerobot/pi0")
```

## VLM 和 VLA 有什么区别？

视觉-语言模型（VLM）和视觉-语言-动作模型（VLA）有共同的基础：Transformer。但关键区别在于动作表示。VLM 处理和生成多模态表示（图像和文本），VLA 在此基础上进一步加入动作和观测状态 token。有了这些额外 token，下一个挑战就是搞清楚注意力是怎么计算的。

## 机器人策略中的注意力机制

先扩充一下词汇表，介绍几个关键术语：

#### **状态 Token（State Token）**

- 用单个 token 表示机器人当前的**环境状态**（如关节角度、传感器值或其他相关观测）。
- 掩码规则允许这个 token **关注前缀部分的图像和文本**，即状态 token 可以"看到"决策所需的任何视觉或文字线索。
- 它还以三角方式关注**之前的状态**。如果使用多个状态 token，每个新状态 token 能看到更早的，反之不行。

#### **动作 Token（Action Tokens）**

- 表示**电机指令序列**。
- 除 padding 区域外拥有**完全可见性**。也就是说每个动作 token 可以关注：**所有非 padding 图像 token**（整个场景）、**所有非 padding 文本 token**（指令或描述）、**状态 token**（当前的和之前的）、**其他动作 token**。

#### **前缀 Token（Prefix Tokens）**

- 表示**完整场景**，彼此完全可见地相互关注，与 **PaliGemma** 类似。

### **核心思想**

这些 token 概括了：

- 机器人对环境的**内部表示**（**state**），
- 机器人发出的**指令或控制**（**action**），
- **时间/步数索引**的编码（**time embedding**）。

它们被追加在前缀部分（图像 + 文本）之后，所以前缀充当上下文（例如场景图像、语言指令如 *"be a good robot"* 或 *"transfer the cube"*），而后缀捕捉具体策略相关的特征。

## ⚡ 走向 π0 中更快的注意力

不过，在 π0 中高效地处理注意力也有自己的难题。它注意力掩码的独特形状直接影响注意力的计算方式——我们细看一下！

### **处理 2D 注意力掩码**

得到的 **2D 因果掩码**有很强的**分块稀疏性**，但要划定每个块的边界——尤其是在一个 batch 的多个样本上——有点棘手。我们熟悉的是自回归建模里那种三角结构的因果掩码，但这里不是那种情况。

看下面的例子：图像（第一个元素）有一些 padding token，对应空摄像头位。然后加入文本 token 和状态 token。这个"前缀"部分构成完全非因果的注意力，和 PaliGemma 一样；"后缀"（状态 + 动作/时间 token）则是因果分块结构。朴素的 eager 实现会对整个输入做矩阵乘法再 softmax，效率非常低。

* 图 1：VLA 注意力掩码的可视化 *

### **能用 FlashAttention2 吗？**

- FlashAttention2 提供了 **varlen 接口**，但 `cu_seqlens`（前缀长度的累积和）必须**手工计算**。它设计用于 query 和 key 长度一致的**连续（或严格因果）注意力模式**。
- 它**不能天然处理不规则分块掩码**或逐 token 的任意"允许"位置——而这恰恰是我们的需求。
- 所以，虽然付出一些实现代价也能用，但我们最终选择了……

### **使用 PyTorch 的 FlexAttention**

这看起来就是给 [FlexAttention](https://pytorch.org/blog/flexattention/) 准备的活！它有纯 PyTorch 接口，我们尝试了两种方案：

- 在注意力被调低的位置，往因果掩码上加一个 **`score_mod`**。但即便是标量加法也会**显著拖慢 FlexAttention**，因为在我们的场景里 `score_mod` 是加在优化后的 CUDA kernel 之外的。
- 正确的做法是**对因果掩码做索引，把结果作为签名传入以创建 block mask**。这个 block mask 能高效标明哪里需要计算注意力、哪里可以整体跳过。

```
# Example of indexing the causal mask and using mask_mod
causal_mask = generate_causal_mask(your_samples) # should be[batch, head, q_len, kv_len]
# Now we need to wrap this mask 
def precomputed_mask_factory(precomputed_mask: torch.Tensor) -> _mask_mod_signature:
    def mask_mod(b, h, q_idx, kv_idx):
        return precomputed_mask[b][h][q_idx][kv_idx]
    return mask_mod
flex_attention_output = flex_attention(query, key, value, mask_mod=mask_mod)

mask_mod = precomputed_mask_factory(causal_mask)
# create a block mask with that signature
block_mask = create_block_mask(
    mask_mod=mask_mod,
    # ...
)

# Call flex attention now!
attn_output, attention_weights = flex_attention(
    query,
    key,
    value,
    block_mask=block_mask,
)
```

当前实现已经能跑，进行中的工作是让它支持 `torch.compile` 并把它的潜力发挥到极致！

## 如何高效地表示动作？

我们已经知道动作不过是可被 token 化的 **n 维向量**，接下来可以探讨 VLA 模型中动作表示的挑战。动作的表示方式直接影响效率、泛化和执行保真度。

一种思路是**语义动作表示**：把动作描述成子任务、关键点等高层概念。这支持 few-shot 和 zero-shot 学习，但通常依赖手工设计的低层控制器，在不同机器人之间的灵活性受限。相比之下，低层控制表示把动作直接映射为电机指令，动作精确，但训练更不稳定、也更难扩展规模。

现有大多数 VLA 使用**离散动作 token 化**：把连续动作转成离散 token，用自回归方式生成。最常见的方法是按维度、按时间步分桶（binning），它在高频控制任务上力不从心，导致表示有损、训练低效。向量量化（VQ）和时间序列压缩等替代方案有所改善，但 **VQ 对超参数敏感**，对形态多样的机器人不够可靠。

为了应对这些问题，**频域动作序列 Token 化（Frequency-space Action Sequence Tokenization, FAST）**提出了一种使用离散余弦变换（DCT）的新时间序列压缩方法。FAST 减少冗余、提升效率并增强动作保真度。

由此，我们带来 **π0-FAST**——**π0** 的更快、自回归版本，同样已登陆 LeRobot 仓库。它是 **π0** 的扩展，用这个新的 tokenizer 获得更好的动作表示。

## 🚀 什么是 π0-FAST？

[Paper](https://arxiv.org/pdf/2501.09747) | [Jax Code](https://github.com/Physical-Intelligence/openpi) | [Our implementation in Lerobot](https://github.com/huggingface/lerobot/pull/921)

π0-FAST 是 π0 的**自回归版本**，引入了 **FAST（Frequency-space Action Sequence Tokenization）**——一种提升效率与性能的新 token 化方案。

### π0-FAST 的关键优势：

- 相比基于扩散的 VLA，**训练快 5 倍**。
- **动作表示更好**，减少动作序列中的冗余。
- 在未见过的环境和机器人形态上**泛化更强**。

🔗 **π0-FAST tokenizer** 在这里：[FAST Tokenizer](https://huggingface.co/physical-intelligence/fast)

🔗 预训练权重在这里：[Pi0+FAST](https://huggingface.co/collections/lerobot/pi0fast-models-67eab97cc139d6f20513ff4a)

## FAST 是如何工作的？

**FAST** 用离散余弦变换（DCT）把连续动作序列压缩成离散 token。如图 2 所示，流程从归一化原始机器人动作开始：把每个动作维度的第 1 和第 99 百分位数映射到 [-1,1] 区间。这样做的目的是保证不同机器人系统之间的一致性，并提升对异常值的鲁棒性。

随后对每个动作维度独立做 DCT，把时域信号转换到频域。为了减少冗余，通过"缩放-取整"（scale-and-round）操作去掉不重要的系数，其中一个超参数在压缩率与重建精度之间做平衡。得到的 DCT 系数矩阵通常很稀疏，会被展平成一维整数序列：先把低频分量跨维度交错排列，以保留关键信息。

为进一步压缩序列，再施加字节对编码（BPE）。和常规做法一样，BPE 在保持固定词表大小的前提下，合并跨维度频繁出现的模式。

[![image/png](https://cdn-uploads.huggingface.co/production/uploads/640e21ef3c82bd463ee5a76d/w3p752hK9lyXH1HHYQfde.png)](https://cdn-uploads.huggingface.co/production/uploads/640e21ef3c82bd463ee5a76d/w3p752hK9lyXH1HHYQfde.png)

* 图 2：FAST 动作 token 化流水线 *

由于所有操作都可逆，动作可以从 token 高效、无损地重建。整条 token 化流水线只有两个超参数：取整前应用的缩放系数和 BPE 词表大小。这两个参数在不同数据集上都相当稳健。

此外，FAST 的通用版本 **FAST+** 在来自单臂、双臂和移动操作机器人的一百万条动作序列上训练，可以适用于各种机器人配置。FAST+ 以 **Hugging Face AutoProcessor** 的形式提供，用户只需几行代码就能对动作序列做 token 化。

要达到最佳压缩效果，输入动作在 token 化之前应先做分位数归一化到 [-1,1]。借助 `AutoProcessor` 模块，用户也可以在自己的数据集上训练定制的 FAST tokenizer。
