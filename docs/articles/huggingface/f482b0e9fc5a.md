# 用 RapidFire AI 让 TRL 微调快 20 倍

Hugging Face TRL 现已正式集成 RapidFire AI，加速你的微调与后训练实验。TRL 用户现在可以发现、安装并运行 RapidFire AI——它是比较多个微调/后训练配置、定制 LLM 的最快方式，无需大改代码，也无需膨胀 GPU 需求。

## 为什么这很重要

在微调或后训练 LLM 时，团队往往没有时间和/或预算去比较多个配置——尽管这能显著提升评估指标。RapidFire AI 让你并发启动多个 TRL 配置——哪怕在单块 GPU 上——并通过新的自适应、基于 chunk 的调度与执行机制近乎实时地进行比较。在 TRL 页面引用的内部基准中，相比逐个串行比较配置，这带来约 16-24 倍的实验吞吐，让你更快达到好得多的指标。

[![RapidFire AI Architecture](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/rapidfireai_intro/rf-usage.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/rapidfireai_intro/rf-usage.png) *RapidFire AI establishes live three-way communication between your IDE, a metrics dashboard, and a multi-GPU execution backend*

## 开箱即得的能力

- **即插即用的 TRL 包装器** — 用 `RFSFTConfig`、`RFDPOConfig` 和 `RFGRPOConfig` 作为 TRL SFT/DPO/GRPO 配置的近似零代码替代品。
- **自适应的基于 chunk 的并发训练** — RapidFire AI 把数据集切分成给定数量的 chunk，在 chunk 边界处轮换配置，既能更早做出同类（apples-to-apples）比较，也最大化 GPU 利用率。
- **交互式控制操作（IC Ops）** — 直接在仪表盘上即可 Stop、Resume、Delete、Clone-Modify（可选 Warm-Start）任何运行中的任务，避免在表现不佳的配置上浪费资源、加码更有希望的配置——无需重启任务、无需倒腾多台 GPU 或集群、没有资源浪费。

[![Interactive Control Operations](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/rapidfireai_intro/icop-clone.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/rapidfireai_intro/icop-clone.png) *Clone promising configurations with modified hyperparameters, optionally warm-starting from the parent's weights, all from the live dashboard*

- **多 GPU 编排** — RapidFire AI 调度器通过高效的共享内存机制，自动把各配置放置并编排到可用 GPU 上的数据 chunk 中。你只管模型和评估指标，不用管管道杂务。
- **基于 MLflow 的仪表盘** — 实验一启动，实时指标、日志和 IC Ops 尽在一处。Trackio、W&B、TensorBoard 等其他仪表盘的支持即将到来。

## 工作原理

RapidFire AI 把你的数据集随机切成"chunk"，并在 chunk 边界处让各 LLM 配置轮换使用 GPU。你能更快地拿到所有配置评估指标的增量信号。通过基于高效共享内存的 adapter/模型换入换出机制实现的自动 checkpoint，让训练保持顺滑、稳定、一致。用 IC Ops 在运行中调整：更早停掉低分选手、克隆有希望的配置并微调参数，还可以选择用父任务权重做 warm-start。

## 开始上手

安装 RapidFire AI，一分钟内跑起来：

```
pip install rapidfireai

# Authenticate with Hugging Face
huggingface-cli login --token YOUR_TOKEN

# Workaround for current issue
pip uninstall -y hf-xet

# Initialize and start RapidFire AI
rapidfireai init
rapidfireai start
```

仪表盘在 `http://localhost:3000` 启动，你可以监控并控制所有实验。

## 支持的 TRL trainer

- 用 `RFSFTConfig` 做 SFT
- 用 `RFDPOConfig` 做 DPO
- 用 `RFGRPOConfig` 做 GRPO

它们被设计为即插即用的替代品，让你保留 TRL 的心智模型，同时为微调/后训练应用获得更多并发与控制。

## 最小 TRL SFT 示例

即使在单块 GPU 上**并发训练多个配置**，代码长这样：

```
from rapidfireai import Experiment
from rapidfireai.automl import List, RFGridSearch, RFModelConfig, RFLoraConfig, RFSFTConfig
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer

# Setup: load your dataset and define formatting
dataset = load_dataset("bitext/Bitext-customer-support-llm-chatbot-training-dataset")
train_dataset = dataset["train"].select(range(128)).shuffle(seed=42)

def formatting_function(row):
    return {
        "prompt": [
            {"role": "system", "content": "You are a helpful customer support assistant."},
            {"role": "user", "content": row["instruction"]},
        ],
        "completion": [{"role": "assistant", "content": row["response"]}]
    }

dataset = dataset.map(formatting_function)

# Define multiple configs to compare
config_set = List([
    RFModelConfig(
        model_name="TinyLlama/TinyLlama-1.1B-Chat-v1.0",
        peft_config=RFLoraConfig(r=8, lora_alpha=16, target_modules=["q_proj", "v_proj"]),
        training_args=RFSFTConfig(learning_rate=1e-3, max_steps=128, fp16=True),
    ),
    RFModelConfig(
        model_name="TinyLlama/TinyLlama-1.1B-Chat-v1.0",
        peft_config=RFLoraConfig(r=32, lora_alpha=64, target_modules=["q_proj", "v_proj"]),
        training_args=RFSFTConfig(learning_rate=1e-4, max_steps=128, fp16=True),
        formatting_func=formatting_function,
    )
])

# Run all configs concurrently with chunk-based scheduling
experiment = Experiment(experiment_name="sft-comparison")
config_group = RFGridSearch(configs=config_set, trainer_type="SFT")

def create_model(model_config):
    model = AutoModelForCausalLM.from_pretrained(
        model_config["model_name"], 
        device_map="auto", torch_dtype="auto"
    )
    tokenizer = AutoTokenizer.from_pretrained(model_config["model_name"])
    return (model, tokenizer)

experiment.run_fit(config_group, create_model, train_dataset, num_chunks=4, seed=42)
experiment.end()
```

**运行后会发生什么？**

假设你在一台 2 GPU 的机器上运行上面的代码。与其串行训练（配置 1 → 等待 → 配置 2 → 等待），两个配置并发训练：

| 方式 | 到比较决策的时间 | GPU 利用率 |
| --- | --- | --- |
| 串行（传统） | 约 15 分钟 | 60% 利用率 |
| RapidFire AI（并发） | 约 5 分钟 | 95%+ 利用率 |

在两个配置都处理完第一个数据 chunk 之后，同样的资源下你就能把比较决策**提前 3 倍**做出，而不是等它们先后过完整个数据集。打开 `http://localhost:3000` 观看实时指标，用 IC Ops 根据所见实时停止、克隆或调整任务。

## 基准：真实世界的加速

以下是团队从串行比较切换到 RapidFire AI 支持的超并行实验后，到达"所有尝试配置中总体最佳训练损失"的可比时间点：

| 场景 | 串行时间 | RapidFire AI 时间 | 加速比 |
| --- | --- | --- | --- |

| 8 configs, 1 GPU | 240 min | 12 min | **20×** |
| 4 configs, 2 GPUs | 60 min | 4 min | **15×** |
