## 引言

Whisper 是 OpenAI 的 Alec Radford 等人于 [2022 年 9 月](https://openai.com/blog/whisper/)发布的自动语音识别（ASR）预训练模型。与许多前辈（例如在无标注音频上预训练的 [Wav2Vec 2.0](https://arxiv.org/abs/2006.11477)）不同，Whisper 是在海量**有标注**的音频-转写数据上预训练的，确切地说是 68 万小时。这比 Wav2Vec 2.0 使用的无标注音频数据（6 万小时）多了一个数量级。更重要的是，这些预训练数据中有 11.7 万小时是多语言 ASR 数据。由此得到的 checkpoint 可以应用于 96 种以上的语言，其中许多被视为*低资源*语言。

如此大量的标注数据让 Whisper 能够直接在语音识别这一*有监督*任务上预训练，从标注的音频-转写预训练数据中学到语音到文本的映射¹。因此 Whisper 只需很少的额外微调就能得到高性能的 ASR 模型。这与 Wav2Vec 2.0 形成对比——后者在*无监督*的掩码预测任务上预训练，即只凭无标注音频学习语音到隐藏状态的中间映射。无监督预训练虽能得到高质量的语音表征，但并**不**学到语音-文本映射；这个映射只能在微调阶段学习，因此需要更多微调才能达到有竞争力的性能。

当扩展到 68 万小时的标注预训练数据时，Whisper 模型展现出在许多数据集和领域上的强大泛化能力。其预训练 checkpoint 就能与最先进（SOTA）的 ASR 系统一较高下：在 LibriSpeech ASR 的 test-clean 子集上词错误率（WER）接近 3%，并在 TED-LIUM 上创下 4.7% WER 的新 SOTA（参见 [Whisper 论文](https://cdn.openai.com/papers/whisper.pdf)表 8）。Whisper 在预训练中习得的大量多语言 ASR 知识可以惠及其它低资源语言：通过微调，可以把预训练 checkpoint 适配到特定数据集和语言上，进一步提升结果。

Whisper 是基于 Transformer 的编码器-解码器模型，也叫*序列到序列*模型。它把音频谱图特征*序列*映射到文本 token *序列*。首先，原始音频输入经特征提取器转换为 log-Mel 谱图；然后 Transformer 编码器对谱图编码，得到编码器隐藏状态序列；最后，解码器以自回归方式预测文本 token，条件为之前的 token 和编码器隐藏状态。图 1 概括了 Whisper 模型。

图 1：

Whisper 模型。其架构遵循标准的基于 Transformer 的编码器-解码器模型。log-Mel 谱图作为编码器的输入，最后一批编码器隐藏状态通过交叉注意力机制输入解码器。解码器自回归地预测文本 token，联合条件为编码器隐藏状态和此前预测的 token。图片来源：OpenAI Whisper Blog。

在序列到序列模型中，编码器把音频输入转换为一组隐藏状态表征，从 spoken speech 中提取关键特征；解码器则扮演语言模型的角色，处理隐藏状态表征并生成对应的文本转写。把语言模型**内在地**融入系统架构的做法称为*深度融合（deep fusion）*。这与*浅度融合（shallow fusion）*形成对比——后者是把语言模型与编码器**外在**结合，比如 CTC + n-gram（参见 [Internal Language Model Estimation](https://arxiv.org/pdf/2011.01991.pdf)）。在深度融合下，整个系统可以用同一份训练数据和同一损失函数端到端训练，灵活性更高，性能通常也更优（参见 [ESB Benchmark](https://arxiv.org/abs/2210.13352)）。

Whisper 的预训练和微调都使用交叉熵目标函数——这是在分类任务上训练序列到序列系统的标准目标函数。系统的任务是正确地把目标文本 token 从预定义的文本 token 词表中分类出来。

### 准备特征提取器、分词器与数据

ASR 流水线可以分解为三个组件：

- 预处理原始音频输入的特征提取器
- 执行序列到序列映射的模型
- 把模型输出后处理成文本格式的分词器

在 🤗 Transformers 中，Whisper 模型配有相应的特征提取器和分词器，分别叫 [WhisperFeatureExtractor](https://huggingface.co/docs/transformers/main/model_doc/whisper#transformers.WhisperFeatureExtractor) 和 [WhisperTokenizer](https://huggingface.co/docs/transformers/main/model_doc/whisper#transformers.WhisperTokenizer)。

我们一个一个来看它们的细节！

### 加载 WhisperFeatureExtractor

语音是一个随时间变化的一维数组，数组在某个时刻的值就是信号在该点的*振幅*。仅凭振幅信息，我们就可以重建音频的频谱并恢复所有声学特征。

由于语音是连续的，它包含无穷多个振幅值，这对只接受有限数组的计算机器来说是个问题。因此我们通过对信号按固定时间间隔*采样*来离散化语音信号。采样的时间间隔称为*采样率*，通常以 samples/sec 或 *Hz（赫兹）*计量。采样率越高，对连续语音信号的逼近越好，但每秒需要存储的值也越多。

关键在于，音频输入的采样率必须与模型期望的采样率一致，因为不同采样率的音频信号分布差异很大。音频样本只应在正确的采样率下处理，做不到就会有意外后果！例如，一段 16kHz 采样的音频若以 8kHz 播放，听起来就像半速。同理，向只接受某一采样率的 ASR 模型喂入错误采样率的音频会让它犯错。Whisper 特征提取器期望 16kHz 的音频输入，所以我们需要把输入调整为这个值——可不想无意中让 ASR 系统学的是"慢动作"语音！

Whisper 特征提取器执行两个操作。第一个是对一批音频样本做填充/截断，使所有样本的输入长度都是 30 秒：短于 30s 的样本在序列末尾补零凑到 30s（音频信号中的零对应无信号或静音），长于 30s 的样本截断到 30s。由于批内所有元素都在输入空间中被填充/截断到统一的最大长度，把音频输入前传给 Whisper 模型时不需要注意力掩码。Whisper 在这方面很特别——多数音频模型都需要提供注意力掩码，指明序列在哪里被填充、从而在自注意力机制中应当忽略哪里。而 Whisper 在没有注意力掩码的情况下训练，直接从语音信号推断该忽略哪里。

Whisper 特征提取器的第二个操作是把填充后的音频数组转换为 log-Mel 谱图。谱图是信号频率的可视化表示，类似傅里叶变换。图 2 展示了一个示例谱图：y 轴是 Mel 通道，对应特定的频率分箱（frequency bin）；x 轴是时间；每个像素的颜色对应该频率分箱在该时刻的对数强度。log-Mel 谱图正是 Whisper 模型期望的输入形式。

Mel 通道（频率分箱）是语音处理中的标准配置，选取上近似人耳听觉范围。就 Whisper 微调而言，我们只需要知道谱图是语音信号中频率成分的可视化表示即可。想更深入了解 Mel 通道，可参考 [Mel-frequency cepstrum](https://en.wikipedia.org/wiki/Mel-frequency_cepstrum)。

图 2：

采样音频数组到 log-Mel 谱图的转换。左：采样得到的一维音频信号；右：对应的 log-Mel 谱图。图片来源：Google SpecAugment Blog。

幸运的是，🤗 Transformers 的 Whisper 特征提取器一行代码就能同时完成填充和谱图转换。让我们从预训练 checkpoint 加载特征提取器，为处理音频数据做好准备：

```
from transformers import WhisperFeatureExtractor

feature_extractor = WhisperFeatureExtractor.from_pretrained("openai/whisper-small")
```

### 加载 WhisperTokenizer

接下来看看如何加载 Whisper 分词器。Whisper 模型输出的文本 token 指示预测文本在词表条目字典中的*索引*。分词器负责把文本 token 序列映射回真正的文本字符串（例如 [1169, 3797, 3332] -> "the cat sat"）。

传统上，用仅编码器模型做 ASR 时，我们用 [*Connectionist Temporal Classification（CTC）*](https://distill.pub/2017/ctc/)解码。这要求每用一个数据集就训练一个 CTC 分词器。使用编码器-解码器架构的好处之一，是可以直接复用预训练模型的分词器。

Whisper 分词器在 96 种预训练语言的转写文本上训练，因此拥有覆盖极广的[字节对（byte-pair）](https://huggingface.co/course/chapter6/5?fw=pt#bytepair-encoding-tokenization)词表，几乎适用于所有多语言 ASR 场景。对于印地语，我们直接加载分词器就能用于微调，无需任何额外修改，只要指定目标语言和任务即可。这两个参数会告知分词器在编码后的标签序列开头加上语言与任务前缀 token：

```
from transformers import WhisperTokenizer

tokenizer = WhisperTokenizer.from_pretrained("openai/whisper-small", language="Hindi", task="transcribe")
```

> 提示：把上面这行的 task 设为 "translate"、language 设为目标文本语言，本文即可改造为语音翻译任务。这样在预处理数据集时会自动加上相应的翻译任务与语言 token。

我们可以编码 Common Voice 数据集的第一个样本来验证分词器能正确编码印地语字符。编码转写文本时，分词器会在序列首尾附加"特殊 token"，包括 transcript 开始/结束 token、语言 token 和任务 token（由上一步的参数指定）。解码 label id 时，可以选择"跳过"这些特殊 token，从而还原出原始输入形式的字符串：

```
input_str = common_voice["train"][0]["sentence"]
labels = tokenizer(input_str).input_ids
decoded_with_special = tokenizer.decode(labels, skip_special_tokens=False)
decoded_str = tokenizer.decode(labels, skip_special_tokens=True)

print(f"Input:                 {input_str}")
print(f"Decoded w/ special:    {decoded_with_special}")
print(f"Decoded w/out special: {decoded_str}")
print(f"Are equal:             {input_str == decoded_str}")
```

### 合并成 WhisperProcessor

为了简化特征提取器和分词器的使用，我们可以把两者*包装*进一个 `WhisperProcessor` 类。这个 processor 对象继承了 `WhisperFeatureExtractor` 和 `WhisperProcessor`，可以按需分别用于音频输入和模型预测。这样一来，训练期间我们只需要跟踪两个对象：`processor` 和 `model`：

```
from transformers import WhisperProcessor

processor = WhisperProcessor.from_pretrained("openai/whisper-small", language="Hindi", task="transcribe")
```

```
    # load and resample audio data from 48 to 16kHz
    audio = batch["audio"]

    # compute log-Mel input features from input audio array 
    batch["input_features"] = feature_extractor(audio["array"], sampling_rate=audio["sampling_rate"]).input_features[0]

    # encode target text to label ids 
    batch["labels"] = tokenizer(batch["sentence"]).input_ids
    return batch
```

用 dataset 的 `.map` 方法把这个数据准备函数应用到所有训练样本上：

```
common_voice = common_voice.map(prepare_dataset, remove_columns=common_voice.column_names["train"], num_proc=4)
```

## 训练与评估

数据准备好了，可以进入训练流水线。[🤗 Trainer](https://huggingface.co/transformers/master/main_classes/trainer.html?highlight=trainer) 会替我们完成大部分重活。我们只需要：

- 加载预训练 checkpoint：需要加载一个预训练 checkpoint 并正确配置成训练模式。
- 定义数据整理器（data collator）：data collator 接收预处理后的数据，整理成模型可直接使用的 PyTorch 张量。
- 评估指标：评估时我们希望用[词错误率（WER）](https://huggingface.co/metrics/wer)来评估模型，因此需要定义一个负责计算的 `compute_metrics` 函数。
- 定义训练参数：🤗 Trainer 会用这些参数构建训练计划。

微调完成后，我们会在测试数据上评估模型，验证它确实被正确地训练成了印地语语音转写系统。

### 加载预训练 Checkpoint

我们的微调从预训练 Whisper `small` checkpoint 开始。为此，从 Hugging Face Hub 加载预训练权重——同样，用 🤗 Transformers 做这事轻而易举！

```
from transformers import WhisperForConditionalGeneration

model = WhisperForConditionalGeneration.from_pretrained("openai/whisper-small")
```

在推理时，Whisper 模型会自动检测源音频的语言并按该语言预测 token id。当源音频的语言是*事先已知*的（例如多语言微调），显式设定语言会更好：这能避免预测错语言的场景——一旦预测错语言，生成文本就会偏离真实语言。做法是在生成配置中设置 [language](https://huggingface.co/docs/transformers/en/model_doc/whisper#transformers.WhisperForConditionalGeneration.generate.language) 和 [task](https://huggingface.co/docs/transformers/en/model_doc/whisper#transformers.WhisperForConditionalGeneration.generate.task) 参数；同时把任何 [`forced_decoder_ids`](https://huggingface.co/docs/transformers/main_classes/text_generation#transformers.generation_utils.GenerationMixin.generate.forced_decoder_ids) 设为 None，因为那是旧版设置语言与任务的方式：

```
model.generation_config.language = "hindi"
model.generation_config.task = "transcribe"

model.generation_config.forced_decoder_ids = None
```

### 定义数据整理器

序列到序列语音模型的 data collator 有点特别：它对 `input_features` 和 `labels` 的处理是相互独立的——`input_features` 由特征提取器负责，`labels` 由分词器负责。

`input_features` 已经被填充到 30s 并转换成固定维度的 log-Mel 谱图，所以我们只需把它们转成批量的 PyTorch 张量。用特征提取器的 `.pad` 方法并设 `return_tensors=pt` 即可。注意这里不会再应用额外的填充，因为输入维度本就是固定的，`input_features` 只是被转换为 PyTorch 张量。

另一方面，`labels` 尚未填充。我们先使用分词器的 `.pad` 方法把序列填充到批内最大长度，再把填充 token 替换为 `-100`，使这些 token 在计算损失时**不**被考虑。然后我们从标签序列开头裁掉 transcript 起始 token，因为训练时稍后会重新附加它。

我们可以利用先前定义的 `WhisperProcessor` 同时完成特征提取器和分词器的操作：

```
import torch

from dataclasses import dataclass
from typing import Any, Dict, List, Union

@dataclass
class DataCollatorSpeechSeq2SeqWithPadding:
    processor: Any
    decoder_start_token_id: int

    def __call__(self, features: List[Dict[str, Union[List[int], torch.Tensor]]]) -> Dict[str, torch.Tensor]:
        # split inputs and labels since they have to be of different lengths and need different padding methods
        # first treat the audio inputs by simply returning torch tensors
        input_features = [{"input_features": feature["input_features"]} for feature in features]
        batch = self.processor.feature_extractor.pad(input_features, return_tensors="pt")

        # get the tokenized label sequences
        label_features = [{"input_ids": feature["labels"]} for feature in features]
        # pad the labels to max length
        labels_batch = self.processor.tokenizer.pad(label_features, return_tensors="pt")

        # replace padding with -100 to ignore loss correctly
        labels = labels_batch["input_ids"].masked_fill(labels_batch.attention_mask.ne(1), -100)

        # if bos token is appended in previous tokenization step,
        # cut bos token here as it's append later anyways
        if (labels[:, 0] == self.decoder_start_token_id).all().cpu().item():
            labels = labels[:, 1:]

        batch["labels"] = labels

        return batch
```

初始化我们刚定义的 data collator：

```
data_collator = DataCollatorSpeechSeq2SeqWithPadding(
    processor=processor,
    decoder_start_token_id=model.config.decoder_start_token_id,
)
```

### 评估指标

接下来定义在评估集上使用的评估指标。我们用词错误率（WER），这是评估 ASR 系统的事实标准指标。更多信息见 WER [文档](https://huggingface.co/metrics/wer)。我们从 🤗 Evaluate 加载 WER 指标：

```
import evaluate

metric = evaluate.load("wer")
```

然后只需定义一个函数，接收模型预测并返回 WER。这个叫 `compute_metrics` 的函数先把 `label_ids` 中的 `-100` 替换回 `pad_token_id`（撤销 data collator 中为正确忽略填充 token 而做的替换），再把预测和标签 id 解码为字符串，最后计算预测与参考标签之间的 WER：

```
def compute_metrics(pred):
    pred_ids = pred.predictions
    label_ids = pred.label_ids

    # replace -100 with the pad_token_id
    label_ids[label_ids == -100] = tokenizer.pad_token_id

    # we do not want to group tokens when computing the metrics
    pred_str = tokenizer.batch_decode(pred_ids, skip_special_tokens=True)
    label_str = tokenizer.batch_decode(label_ids, skip_special_tokens=True)

    wer = 100 * metric.compute(predictions=pred_str, references=label_str)

    return {"wer": wer}
```

### 定义训练参数

最后一步，定义所有与训练相关的参数。下面解释其中一部分：

- `output_dir`：保存模型权重的本地目录，同时也会是 [Hugging Face Hub](https://huggingface.co/) 上的仓库名。
- `generation_max_length`：评估时自回归生成的最大 token 数。
- `save_steps`：训练期间，每隔 `save_steps` 个训练 step 会保存中间 checkpoint 并异步上传到 Hub。
- `eval_steps`：训练期间，每隔 `eval_steps` 个训练 step 对中间 checkpoint 做一次评估。
- `report_to`：训练日志的存放平台。支持 `"azure_ml"`、`"comet_ml"`、`"mlflow"`、`"neptune"`、`"tensorboard"` 和 `"wandb"`。选你喜欢的即可，或保持 `"tensorboard"` 直接记录到 Hub。

其他训练参数的详情见 Seq2SeqTrainingArguments [文档](https://huggingface.co/docs/transformers/main_classes/trainer#transformers.Seq2SeqTrainingArguments)。

```
from transformers import Seq2SeqTrainingArguments

training_args = Seq2SeqTrainingArguments(
    output_dir="./whisper-small-hi",  # change to a repo name of your choice
    per_device_train_batch_size=16,
    gradient_accumulation_steps=1,  # increase by 2x for every 2x decrease in batch size
    learning_rate=1e-5,
    warmup_steps=500,
    max_steps=5000,
    gradient_checkpointing=True,
    fp16=True,
    evaluation_strategy="steps",
    per_device_eval_batch_size=8,
    predict_with_generate=True,
    generation_max_length=225,
    save_steps=1000,
    eval_steps=1000,
    logging_steps=25,
    report_to=["tensorboard"],
    load_best_model_at_end=True,
    metric_for_best_model="wer",
    greater_is_better=False,
    push_to_hub=True,
)
```

**注意**：如果不想把模型 checkpoint 上传到 Hub，设 `push_to_hub=False`。

把训练参数连同模型、数据集、data collator 和 `compute_metrics` 函数一起交给 🤗 Trainer：

```
from transformers import Seq2SeqTrainer

trainer = Seq2SeqTrainer(
    args=training_args,
    model=model,
    train_dataset=common_voice["train"],
    eval_dataset=common_voice["test"],
    data_collator=data_collator,
    compute_metrics=compute_metrics,
    tokenizer=processor.feature_extractor,
)
```

这样，就可以开始训练了！

### 搭建 Demo

模型微调好了，现在可以搭个 demo 秀一把它的 ASR 能力！我们会用 🤗 Transformers 的 `pipeline`，它负责整条 ASR 流水线，从预处理音频输入到解码模型预测。交互式 demo 用 [Gradio](https://www.gradio.app) 搭建。Gradio 大概是最省事的机器学习 demo 构建工具——用它几分钟就能搭出一个 demo！

运行下面的示例会生成一个 Gradio demo：我们可以通过电脑麦克风录音，输入到微调好的 Whisper 模型，转写出对应文本：

```
from transformers import pipeline
import gradio as gr

pipe = pipeline(model="sanchit-gandhi/whisper-small-hi")  # change to "your-username/the-name-you-picked"

def transcribe(audio):
    text = pipe(audio)["text"]
    return text

iface = gr.Interface(
    fn=transcribe, 
    inputs=gr.Audio(source="microphone", type="filepath"), 
    outputs="text",
    title="Whisper Small Hindi",
    description="Realtime demo for Hindi speech recognition using a fine-tuned Whisper small model.",
)

iface.launch()
```
