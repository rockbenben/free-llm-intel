Hugging Face 与 OpenRouter 正在联手，让开放权重模型易于运行。每个重要的开放权重发布都已经在 Hugging Face Hub 上发布，而 [OpenRouter](https://openrouter.ai) 大规模地为这些模型提供服务，根据对每家提供商的实时测量，把每个请求路由到 80 多家提供商。合在一起，Hub 上任何由提供商服务的开放权重模型，都可以用你的 Hugging Face token 调用，走同一个 API，并为每个请求挑选最合适的提供商。

今天，我们把 [Inference Providers](https://huggingface.co/docs/inference-providers) 从自研的路由器切换为 OpenRouter 的。发往语言模型的请求现在经过 OpenRouter，它根据实时价格、速度和可靠性为每次调用挑选最佳提供商，并在第一家提供商失败时换一家重试。你的代码保持不变。

## 用你已经在用的工具运行它们

该路由器为所有 chat 模型支持 OpenAI 的 Chat Completions 和 Responses API 以及 Anthropic 的 Messages API，无论背后是哪家提供商。选好你的 coding agent 或 SDK 以及一个模型，然后复制步骤，或者把整套配置作为 prompt 复制给你的 agent：

配置指南见 [Claude Code](https://huggingface.co/docs/inference-providers/integrations/claude-code)、[Codex](https://huggingface.co/docs/inference-providers/integrations/codex)、[OpenCode](https://huggingface.co/docs/inference-providers/integrations/opencode)、[Pi](https://huggingface.co/docs/inference-providers/integrations/pi) 和 [Hermes Agent](https://huggingface.co/docs/inference-providers/integrations/hermes-agent)

同一个 Hugging Face token 还为你提供 [Storage Buckets](https://huggingface.co/storage) 的存储、[Jobs](https://huggingface.co/docs/hub/jobs-overview) 的计算以及 [Inference Endpoints](https://huggingface.co/docs/inference-endpoints) 的专用推理。PRO、Team 和 Enterprise 计划每月都包含计算和推理额度。

## 开放权重模型的使用情况

在 OpenRouter 上，开放权重模型在服务的 token 中占比从 2025 年 10 月的 26.8% 升至 2026 年 9 月底的 71.7%，此前在 7 月曾达到 77.5% 的峰值（[OpenRouter，2026 年 10 月](https://openrouter.ai/blog/insights/open-weight-vs-closed-weight-models/)）。同一时期，每周开放权重模型的用量增长了 60 多倍，而闭源模型增长了近十倍。本周，OpenRouter 上使用最多的模型就是开放权重模型 DeepSeek V4.1 Flash 1017，共 59.2 万亿 token（[排行榜](https://openrouter.ai/rankings)）。

![开放权重模型在 OpenRouter 上的 token 占比，从 2025 年 10 月的 26.8% 升至 2026 年 9 月的 71.7%](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/open-weight-share@2x.png) ![开放权重模型在 OpenRouter 上的 token 占比，从 2025 年 10 月的 26.8% 升至 2026 年 9 月的 71.7%](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/open-weight-share-dark@2x.png)

开放权重模型的平均成本约低四倍：每百万输入 token 0.28 美元、每百万输出 token 1.62 美元，而闭源模型是 1.27 美元和 6.36 美元。

在最难的基准测试上，最好的开放权重模型仍落后于最好的专有模型。在 [Artificial Analysis Intelligence Index](https://artificialanalysis.ai/leaderboards/models) 上，最好的开放权重模型 Kimi K3.1 Pro 得分为 46，Claude Fable 5.2 为 65，而每任务成本约为后者的七分之一（3.68 美元对 26.54 美元）。对许多工作负载来说，这个取舍是值得的。

![Artificial Analysis Intelligence Index 与每任务成本对比，覆盖顶级专有模型和开放权重模型](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/intelligence-vs-cost@2x.png) ![Artificial Analysis Intelligence Index 与每任务成本对比，覆盖顶级专有模型和开放权重模型](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/intelligence-vs-cost-dark@2x.png)

## 由 OpenRouter 驱动的路由

OpenRouter 每月为超过 1000 万用户提供超过 800 万亿 token，涵盖来自 80 多家提供商的 600 多个模型。其路由基于这些流量中对每家提供商的实时测量。

OpenRouter 最近[重建了其提供商路由](https://openrouter.ai/blog/announcements/how-we-rebuilt-provider-routing/)：不再只看最低标价，而是把每个请求发给价格、速度和可靠性综合最优的提供商。

当某家提供商变慢或开始失败时，流量会从它那里移开，直到它恢复；一次失败的尝试会在同一次调用内交给次优的提供商重试。在 OpenRouter 的测量中，新路由把容量错误减少了 46%，首 token 时间改善了 16.9%，吞吐量提升了 16.3%。

![当第一个提供商被限流时，默认路由会在另一家提供商上重试；:cheapest 选择最低价格，:fastest 选择最高吞吐量](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/routing@2x.gif) ![当第一个提供商被限流时，默认路由会在另一家提供商上重试；:cheapest 选择最低价格，:fastest 选择最高吞吐量](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/routing-dark@2x.gif)

以前，Inference Providers 为你的请求只挑一家提供商，失败就返回它的错误。现在，请求会在另一家提供商上重试。你仍然可以用模型 ID 上的后缀来选择策略或提供商：

```
zai-org/GLM-5.3            # default: best mix of price, speed and reliability
zai-org/GLM-5.3:fastest    # highest throughput
zai-org/GLM-5.3:cheapest   # lowest price
zai-org/GLM-5.3:novita     # only Novita
```

路由还会感知缓存：一段对话会留在持有其 prompt 缓存的那家提供商上。为了让它明确生效，请在 `X-HF-Session-Id` 请求头中为每段对话发送一个稳定的 UUID（参见 [prompt caching 指南](https://huggingface.co/docs/inference-providers/prompt-caching)）。

## 定价

定价没有变化：你在 Hugging Face 账单上支付提供商的价格，Hugging Face 不会在此基础上加价。PRO 用户每月获得 2 美元额度，Team 和 Enterprise 组织按席位每人 2 美元。详情见[定价与计费](https://huggingface.co/docs/inference-providers/pricing)。

## 图像、视频和音频生成

图像、视频和音频生成仍然和以前完全一样，直接通过 Hugging Face Inference Providers 进行，不经过 OpenRouter。你可以继续使用同一个 token 和 API，并访问数以万计的 [LoRA](https://huggingface.co/models?inference_provider=all&pipeline_tag=text-to-image&other=lora)。

## 查看你的请求去了哪里

在模型页面上，你可以直接在小部件里与模型对话。两个新标签页展示了背后的情况：Providers 列出 OpenRouter 可以把该模型路由到的每一家提供商，以及其输入输出价格、速度和过去 24 小时的正常运行时间；Metrics 则显示其中最佳的价格、吞吐量、首 token 时间、上下文长度和正常运行时间：

![在模型页小部件中与 Inkling-2-Small 对话，打开其代码片段，然后打开 Metrics 标签页](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/widget-playground-3@2x.gif) ![在模型页小部件中与 Inkling-2-Small 对话，打开其代码片段，然后打开 Metrics 标签页](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/widget-playground-3-dark@2x.gif)

你的[用量概览](https://huggingface.co/settings/inference-providers/overview)会按每个请求所到的提供商拆分你的支出：

![按提供商拆分的每日 Inference Providers 支出](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/usage-by-provider@2x.png) ![按提供商拆分的每日 Inference Providers 支出](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/usage-by-provider-dark@2x.png)

在你的[设置](https://huggingface.co/settings/inference-providers)中，你可以关闭任何不想要的提供商：路由器永远不会把请求发到那里。组织也有同样的设置，并且适用于向该组织计费的每一个请求。

![Inference Providers 设置，每家提供商都有一个开关](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/settings-providers@2x.png) ![Inference Providers 设置，每家提供商都有一个开关](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/settings-providers-dark@2x.png)

## 破坏性变更：自定义提供商密钥

发往语言模型的请求现在经过 OpenRouter，并向你的 Hugging Face 账户或组织计费，因此对这些模型你不能再使用自己在某家提供商处的 API key。你仍然可以用模型 ID 上的后缀（`model:provider`）挑选提供商，或在设置中关闭提供商，代码保持不变。图像和视频提供商的自定义密钥仍然有效。
