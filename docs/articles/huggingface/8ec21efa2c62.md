Hugging Face 和 OpenRouter 正在合作，使开放重量模型易于运行。每个主要的开放权重版本都已经在 Hugging Face Hub 上发布，并且 [OpenRouter](https://openrouter.ai) 大规模地为这些模型提供服务，根据每个提供者的实时测量在 80 多个提供者之间路由每个请求。总之，提供者所服务的 Hub 上的每个开放权重模型都可以通过相同的 API 使用您的 Hugging Face 令牌进行调用，并为每个请求选择最佳的提供者。

今天，我们将 [推理提供程序](https://huggingface.co/docs/inference-providers) 从我们自己的自定义路由器切换到 OpenRouter 的。对语言模型的请求现在通过 OpenRouter，它根据实时价格、速度和可靠性为每次调用选择最佳的提供商，并在第一个提供商失败时重试另一个提供商。您的代码保持不变。

## 使用您已经使用的工具运行它们

该路由器支持 OpenAI 的聊天完成和响应 API 以及 Anthropic 的消息 API，适用于每种聊天模型，无论其背后的提供商是谁。选择您的编码代理或 SDK 和模型，然后复制步骤，或复制整个设置作为代理的提示：

[Claude Code](https://huggingface.co/docs/inference-providers/integrations/claude-code)、[Codex](https://huggingface.co/docs/inference-providers/integrations/codex)、[OpenCode](https://huggingface.co/docs/inference-providers/integrations/opencode)、 [Pi](https://huggingface.co/docs/inference-providers/integrations/pi) 和 [Hermes Agent](https://huggingface.co/docs/inference-providers/integrations/hermes-agent)

相同的 Hugging Face 令牌还为您提供了[存储桶](https://huggingface.co/storage)的存储、[作业](https://huggingface.co/docs/hub/jobs-overview)的计算以及[推理端点](https://huggingface.co/docs/inference-endpoints)的专用推理。 PRO、团队和企业计划包括用于计算和推理的每月积分。

## 如何使用开放权重模型

在 OpenRouter 上，开放权重模型从 2025 年 10 月所服务代币的 26.8% 上升到 2026 年 9 月末的 71.7%，7 月份达到峰值 77.5%（[OpenRouter，2026 年 10 月](https://openrouter.ai/blog/insights/open-weight-vs-lined-weight-models/)）。同一时期，每周开放式重量的交易量增长了 60 多倍，而封闭式重量的交易量几乎增长了十倍。本周，OpenRouter 上最常用的模型是开放权重模型 DeepSeek V4.1 Flash 1017，拥有 59.2 万亿代币（[排名](https://openrouter.ai/rankings)）。

![开放权重模型在 OpenRouter 上的代币份额，从 2025 年 10 月的 26.8% 上升到 2026 年 9 月的 71.7%](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/open-weight-share@2x.png) ![开放权重模型在 OpenRouter 上的代币份额OpenRouter，从 2025 年 10 月的 26.8% 增长到 2026 年 9 月的 71.7%](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/open-weight-share-dark@2x.png)

开放权重模型的平均成本大约低四倍：每百万个输入代币 0.28 美元，每百万个输出代币 1.62 美元，而封闭模型为 1.27 美元和 6.36 美元。

在最严格的基准测试中，最好的开放重量模型仍然落后于最好的专有模型。在 [人工分析智能指数](https://artificialanalysis.ai/leaderboards/models) 上，最好的开放权重模型 Kimi K3.1 Pro 得分为 46，Claude Fable 5.2 得分为 65，每项任务成本约为 1/7（3.68 美元对 26.54 美元）。对于很多工作负载来说，这种权衡是值得的。

![针对每项任务成本的人工分析智能指数，针对顶级专有和开放权重模型](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/intelligence-vs-cost@2x.png) ![针对每项任务成本的人工分析智能指数，针对顶级专有和开放权重模型模型](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/intelligence-vs-cost-dark@2x.png)

## 由 OpenRouter 提供支持的路由

OpenRouter 每月为超过 1000 万用户提供超过 800 万亿个代币，涵盖来自 80 多个提供商的 600 多个模型。其路由基于该流量中每个提供商的实时测量。

OpenRouter 最近[重建了其提供商路由](https://openrouter.ai/blog/announcements/how-we-rebuilt-provider-routing/)：它不再只查看最低标价，而是将每个请求发送给具有最佳价格、速度和可靠性组合的提供商。

当某个提供程序速度变慢或开始失败时，流量会远离该提供程序直至其恢复，并且会在同一调用中的下一个最佳提供程序上重试失败的尝试。在 OpenRouter 的测量中，新路由将容量错误减少了 46%，并将首次令牌时间缩短了 16.9%，吞吐量提高了 16.3%。

![当第一个提供商受到速率限制时，默认在另一个提供商上重试路由，:cheapest 选择最低价格，:fastest 选择最高吞吐量](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/routing@2x.gif) ![当第一个提供商受到速率限制时，在另一个提供商上默认路由重试，:cheapest选择最低价格并：最快最高吞吐量](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/routing-dark@2x.gif)

以前，推理提供程序为您的请求选择一个提供程序，如果失败则返回其错误。现在，该请求将在另一个提供商上重试。您仍然可以选择模型 ID 上带有后缀的策略或提供商：
```
zai-org/GLM-5.3            # default: best mix of price, speed and reliability
zai-org/GLM-5.3:fastest    # highest throughput
zai-org/GLM-5.3:cheapest   # lowest price
zai-org/GLM-5.3:novita     # only Novita
```
路由也是缓存感知的：对话保留在保存其提示缓存的提供者上。为了使其明确，请在“X-HF-Session-Id”标头中为每个会话发送一个稳定的 UUID（请参阅[提示缓存指南](https://huggingface.co/docs/inference-providers/prompt-caching)）。

## 定价

定价不会改变：您在 Hugging Face 账单上支付提供商的价格，并且 Hugging Face 不会在其之上添加标记。 PRO 用户每月获得 2 美元的积分，团队和企业组织每个席位获得 2 美元。有关详细信息，请参阅[定价和计费](https://huggingface.co/docs/inference-providers/pricing)。

## 图像、视频和音频生成

图像、视频和音频生成继续像以前一样工作，直接通过 Hugging Face Inference Providers 进行，无需通过 OpenRouter。您可以继续使用相同的令牌和 API，并访问数以万计的 [LoRA](https://huggingface.co/models?inference_provider=all&pipeline_tag=text-to-image&other=lora)。

![每日推理提供商支出，按提供商细分](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/usage-by-provider@2x.png) ![每日推理提供商支出，按提供商细分提供商]（https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/inference-providers-openrouter/usage-by-provider-dark@2x.png）

## 重大更改：自定义提供程序密钥

对语言模型的请求现在通过 OpenRouter 进行，并向您的 Hugging Face 帐户或组织计费，因此您不能再将自己的 API 密钥用于具有这些模型的提供商。您仍然可以选择在模型 ID 上带有后缀的提供程序（“model:provider”），或者在您的设置中关闭提供程序，并且您的代码保持不变。图像和视频提供商的自定义密钥继续有效。

## 接下来是什么

这是我们与 OpenRouter 合作的第一步。下一篇：

- 将您的 OpenRouter 帐户连接到 Hugging Face。
- 更多任务通过 OpenRouter 路由。
