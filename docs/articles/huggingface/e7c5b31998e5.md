我们很高兴地宣布发布 **Kimina-Prover-72B**——这是基于 Qwen2.5-72B [[2]](https://huggingface.co/blog/AI-MO/kimina-prover#2)、采用 Kimi k1.5[[1]](https://huggingface.co/blog/AI-MO/kimina-prover#1) RL 流水线训练的当前最先进（state-of-the-art）定理证明模型。与此同时，我们还发布两个蒸馏变体：**Kimina-Prover-Distill-8B** 和 **1.7B**（分别基于 Qwen3-8B 和 Qwen3-1.7B[[3]](https://huggingface.co/blog/AI-MO/kimina-prover#3)）。

我们的核心创新包括：

- **测试时强化学习搜索（Test-Time Reinforcement Learning Search）**：一个可训练的智能体式证明框架，基于一种全新的“可用引理”（lemma-enabled）模式，让模型能够递归地发现、组合并应用多条引理来构造复杂证明。
- **纠错能力**：Kimina-Prover 能够阅读并解读 Lean 的错误信息，并给出针对性的修复方案。相比从零重新生成证明，其样本效率显著提升。

这些进展让 Kimina-Prover 能够解决高难度数学问题并超越已有方法。如图 1 所示，在广泛使用的 miniF2F 基准上，Kimina-Prover 达到了 **92.2%** 的最先进通过率。

# 引言

我们聚焦于 Lean 4 语言中的自动定理证明（ATP），目标是把形式化数学证明的构造过程自动化。近年来神经定理证明的进展大幅提升了 AI 系统辅助或自动化这一流程的能力。代表性成果包括 Google DeepMind 的 **AlphaProof**[[4]](https://huggingface.co/blog/AI-MO/kimina-prover#4)，它在国际数学奥林匹克级别的题目上展现了强劲表现；引入强化学习的开源系统 **DeepSeek-Prover-V2**[[5]](https://huggingface.co/blog/AI-MO/kimina-prover#5) 也取得了最先进结果。此外，**DSP+**[[6]](https://huggingface.co/blog/AI-MO/kimina-prover#6) 这类神经-符号智能体方法表明，凭借模块化框架组合使用现成模型，无需大规模训练也能达到有竞争力的性能。

我们此前的 Kimina-Prover Preview[[7]](https://huggingface.co/blog/AI-MO/kimina-prover#7) 提出了一种用于 Lean 形式化定理证明的大语言模型，在 miniF2F 基准上建立了新的性能基线。该模型通过大规模强化学习流水线训练，采用了推理驱动的探索范式，并证明了更大的模型可以成为更强的形式化推理器。其结构化的推理模式实现了高效的证明搜索，并模拟了类人的解题策略。

在取得初步成功后，我们通过更多轮强化学习迭代持续改进模型。但单步推理仍然不足以解决需要冗长、多阶段证明的复杂问题。为突破这一限制，我们引入了测试时强化学习（TTRL）搜索框架，让模型能够自主发现、组合并复用多个中间引理。该框架把难题拆解为可复用的子组件，从而支持更深、更长程的推理。

TTRL 搜索的一个关键要素是**可用引理模式（lemma-enabled pattern）**，它允许模型在构造证明的过程中识别并应用中间引理。这种对中间结果的结构化复用，使模型的问题求解能力大大超出了单步生成的范畴。

为了进一步提升稳健性，我们还整合了一个纠错机制：解读 Lean 的错误信息并给出针对性修正。这让模型能够通过迭代反馈打磨输出，提高证明的可靠性和整体样本效率。

# 方法

### 可用引理模式

可用引理模式旨在让模型具备识别并利用输入中提供的有用引理的能力。为支持这一能力，在强化学习（RL）训练期间，我们会从形式化引理集中随机抽取一到三条前置到问题上下文中，让证明器接触到可能有助于构造最终证明的中间结果。这些引理通过两步流水线准备：(1) 由通用 LLM 用自然语言生成候选引理；(2) 再用我们的 `Kimina-Autoformalizer-7b` 将其翻译为形式化陈述。

最初的观察显示，模型很少主动使用提供的引理。为解决这个问题，我们在 RL 框架中引入了基于偏好的奖励塑形策略：当一个定理存在多条可证明的轨迹时，成功利用了所提供引理的解会被赋予更高奖励，未利用的则受到惩罚。这一做法非常有效，训练后引理利用率稳定提升到 30–40%。重要的是，这种方法不仅鼓励使用引理，还培养了选择性：模型学会了在引理有用时策略性地应用，忽略无关引理，表现出更高效、更类人的推理行为。

## TTRL 搜索

[![kimina-prover-ttrl-search-fixed-fixed](https://hackmd.io/_uploads/H119Z46Sge.png)](https://hackmd.io/_uploads/H119Z46Sge.png)

图 2：

测试时强化学习（TTRL）搜索框架示意图。它由三个主要部分组成：RL 训练、子引理生成和否定过滤。子引理先生成并形式化，随后通过动态打分与剪枝整合进训练循环；否定过滤器通过丢弃无效引理来保证逻辑一致性。

**可用引理模式**让模型能够把预生成的引理作为中间步骤纳入证明构造。但我们发现，随机采样并插入引理，不足以解决需要高度结构化、深度嵌套推理的复杂问题。为突破这一限制，我们构建了**测试时强化学习搜索**框架——一种可训练的智能体式方法，能系统地组织、过滤和组合大量候选引理来构造完整证明。该框架把流程从随机探索转变为更具策略性、目标导向的搜索。

如图 2 所示，我们把每个问题的**搜索范围**定义为问题本身及其关联的候选引理。TTRL 搜索在每个搜索范围内跟踪**引理利用率得分**，用于衡量每条引理对最终证明的贡献频率和效果。每轮 RL 训练迭代开始时，对每个问题（即每个搜索范围），我们通过前置不同的引理组合构造 **K = 10** 个输入变体。为了在探索与利用之间取得平衡，**60%** 的输入使用排名靠前的引理——即利用率得分最高的那些——让模型聚焦最有希望的证明路径；其余 **40%** 则在这些头部引理之外再随机加入一到四条其他引理，鼓励探索新颖且可能有用的引理组合。

为保证质量，一个**过滤机制**会剪掉持续无法产生有效贡献的引理：任何在 50 次插入尝试后利用率得分仍达不到 τ=0.10 的引理，都会从搜索池中被移除。

TTRL 的一个关键特性是其**递归搜索机制**。搜索范围不仅限于原始定理，也为每条引理单独维护，使框架可以递归地把问题分解为更小的子问题。一个并行的**子引理生成过程**贯穿始终：每当某个定理或引理在 **N = 128** 次尝试后仍未找到证明，就生成新的候选子引理。这种递归策略实现了推理深度上的测试时扩展（test-time scaling），显著延伸了模型的有效问题求解能力。

为保持逻辑健全性，我们处理了一类失效模式：形式化错误的引理可能导致平凡或无效的证明。在这种情况下，模型可能利用逻辑不一致性构造出看似有效实则不成立的解。为防止这一点，我们引入了**否定证明过程**：对每条新生成的引理，尝试证明其逻辑否定。如果否定陈述可证，说明原引理在逻辑上不一致，立即丢弃。这一步确保了整体证明构造过程的可靠性与健全性。

## 为 Kimina-Prover 加入纠错能力

近期先进的定理证明模型有一个关键短板：无法根据证明助手的反馈修正证明——而这恰恰是人类用户每天都在使用的能力。为补齐这一缺口，我们开发了一套专门的框架，把**纠错能力**整合进 Kimina-Prover。

**纠错用的 SFT 数据生成。** 通用大语言模型在解读 Lean 错误信息并给出有效修正方面成功率很低。为克服这一点，我们构造了一份专门面向错误修正的**监督微调（SFT）**数据集，由 *(错误证明, Lean 反馈, 正确证明)* 三元组组成。为了让监督信号更丰富，我们提示 Claude 3.7 sonnet[[8]](https://huggingface.co/blog/AI-MO/kimina-prover#8) 合成逐步推理链，解释如何利用给定反馈把错误证明改造成正确证明。最终得到的高质量数据集不仅包含初始证明和修正后的证明，还包含中间推理过程，从而促进更有效的学习。

**批量失败重放策略。** 最初把错误修正直接集成进强化学习（RL）循环效果不佳：SFT 模型修错的成功率只有约 1%，导致奖励稀疏、训练不稳定。为此我们设计了**批量失败重放（Batched Failure Replay）**策略：不在 RL 迭代过程中立即尝试纠错，而是收集第 *N* 轮所有失败的证明尝试；在下一轮第 *N+1* 轮，训练批次由这些历史失败样本的固定大小并集（例如 500 条）与提示集中的标准问题（例如再 500 条）组成。这保证了每个训练步骤都能稳定、大量地接触错误修正任务，让模型以稳定且数据高效的方式逐步学会有效的错误处理行为。

|  | 16+16 尝试-修正 | 32×1 暴力重试 | 32+32 尝试-修正 |
| --- | --- | --- | --- |
| kimina-prover | 35.6 | 28.8 | 44.1 |

表 2：

在胜率最低的 59 道 MiniF2F-Test 题目子集上，纠错策略与暴力策略的性能对比。在相同样本预算下，纠错策略（16+16）优于暴力基线（32×1），体现出更高的样本效率。

这种训练方式让模型从失败中恢复的能力获得了可衡量的提升：模型从修正基础语法错误，进步到解决复杂逻辑错误，最终能在初次尝试失败时发现替代性的证明策略。至关重要的是，这一能力提升了样本效率。如表 2 所示，我们在固定计算预算下对比了不同策略：16+16 尝试-修正策略——16 次初始证明尝试、每次后跟一轮错误修正——取得 35.6% 的成功率，超过了 32 次独立尝试的 32×1 暴力基线（28.8%）。把样本预算提高到 32+32 并配合错误修正后，成功率达到 44.1%。这些结果表明，让模型修正自己的错误，比反复试错是更高效的算力利用方式。

## 其他改进

除了核心的 TTRL 搜索和纠错之外，我们还开发了若干其他新技术，以增强模型的学习过程和解题能力。

**提示集的整理与迭代。** 高效的数据整理对强化学习（RL）效率至关重要。我们最初超过 30 万道题的提示集被精简为约 9 万道竞赛导向的子集，重点选用 NuminaMath 1.5[[9]](https://huggingface.co/blog/AI-MO/kimina-prover#9) 中 *olympiads-ref* 子集等来源的题目。在 RL 过程中我们应用了**动态过滤**：成功率持续偏高的题目被移除以维持挑战性，而长期无法攻克的难题则借助通用 LLM 被分解为更简单的子问题或变体。最终的提示集结合了自动形式化陈述（保证覆盖面）、人工标注题目（保证质量）与增强变体（针对特定技能训练）。整理后的提示集将开源。

**在 Lean 数据上持续预训练。** 针对多数基座模型 Lean 能力不足的问题，我们应用了持续预训练（CPT）。我们构造了一个 60 亿 token 的 CPT 数据集，来源包括：来自 GitHub 等在线平台的 2.6 亿 token、我们 RL 流水线中经编译器验证的 rollout 数据 55 亿 token，以及 `state–tactic–state` 和 `state–tactic–error` 格式的结构化补充数据以提升多样性。这些结构化数据为基座模型补充了额外的领域知识。

**随机证明裁剪数据增强。** 为了更好地利用缺乏中间推理步骤的高质量人工标注证明，我们开发了**随机证明裁剪（Random Proof Cut）**技术。该方法通过两种变体增强这类数据：

- **证明截断**：移除证明的最后一部分，让模型补全。
- **证明填充**：随机选取一个内部代码块替换为占位符 token `sorry`，让模型重建缺失的步骤。

这一策略让模型学会扩展现有的推理线路并填补逻辑空缺，从而把人类生成内容有效地纳入训练过程。

**非证明型问题求解。** 许多问题的形式是要求给出最终答案，无法自然地表述为传统证明任务。受 CombiBench[[10]](https://huggingface.co/blog/AI-MO/kimina-prover#10) 评测方法的启发，我们引入了非证明型问题求解能力，把答案生成与证明构造统一起来。在这种设定下，模型拿到一道最终答案留空的题目，在单次推理中完成两阶段过程：先推导出正确答案，再生成一个完整的形式化证明来论证该答案。这种方式确保模型的推理被显式地以得出正确解为目标进行约束。

```
      have h8 : ∀ j : Fin N, Real.cos (a j + x) / (2 : ℝ) ^ (j : ℕ) = (Real.cos (a j) * Real.cos x - Real.sin (a j) * Real.sin x) / (2 : ℝ) ^ (j : ℕ) := by
        intro j
        have h9 : Real.cos (a j + x) = Real.cos (a j) * Real.cos x - Real.sin (a j) * Real.sin x := by
          rw [Real.cos_add]
        rw [h9]
      have h10 : ∑ j : Fin N, Real.cos (a j + x) / 2 ^ j.1 = ∑ j : Fin N, ((Real.cos (a j) * Real.cos x - Real.sin (a j) * Real.sin x) / (2 : ℝ) ^ (j : ℕ)) := by
        apply Finset.sum_congr
        .
          rfl
        .
          intro j hj
          have h9 : Real.cos (a j + x) / (2 : ℝ) ^ (j : ℕ) = (Real.cos (a j) * Real.cos x - Real.sin (a j) * Real.sin x) / (2 : ℝ) ^ (j : ℕ) := h8 j
          simpa using h9
      rw [h10]
      have h11 : ∑ j : Fin N, ((Real.cos (a j) * Real.cos x - Real.sin (a j) * Real.sin x) / (2 : ℝ) ^ (j : ℕ)) =
        (∑ j : Fin N, Real.cos (a j) / (2 : ℝ) ^ (j : ℕ)) * Real.cos x - (∑ j : Fin N, Real.sin (a j) / (2 : ℝ) ^ (j : ℕ)) * Real.sin x := by
        have h12 : ∀ j : Fin N, ((Real.cos (a j) * Real.cos x - Real.sin (a j) * Real.sin x) / (2 : ℝ) ^ (j : ℕ)) =
          (Real.cos (a j) / (2 : ℝ) ^ (j : ℕ)) * Real.cos x - (Real.sin (a j) / (2 : ℝ) ^ (j : ℕ)) * Real.sin x := by
          intro j
          ring_nf
        calc
          ∑ j : Fin N, ((Real.cos (a j) * Real.cos x - Real.sin (a j) * Real.sin x) / (2 : ℝ) ^ (j : ℕ))
            = ∑ j : Fin N, ((Real.cos (a j) / (2 : ℝ) ^ (j : ℕ)) * Real.cos x - (Real.sin (a j) / (2 : ℝ) ^ (j : ℕ)) * Real.sin x) := by
                apply Finset.sum_congr
                .
                  rfl
                .
                  intro j hj
                  specialize h12 j
                  linarith
          _ = (∑ j : Fin N, (Real.cos (a j) / (2 : ℝ) ^ (j : ℕ)) * Real.cos x) - (∑ j : Fin N, (Real.sin (a j) / (2 : ℝ) ^ (j : ℕ)) * Real.sin x) := by
              rw [Finset.sum_sub_distrib]
          _ = (∑ j : Fin N, Real.cos (a j) / (2 : ℝ) ^ (j : ℕ)) * Real.cos x - (∑ j : Fin N, Real.sin (a j) / (2 : ℝ) ^ (j : ℕ)) * Real.sin x := by
              rw [Finset.sum_mul, Finset.sum_mul]
      exact h11
    rw [h_eq2]
    specialize h_eq x
    linarith

theorem sub_eq_int_mul_pi_of_cos_eq_zero :
    ∀ (θ₁ θ₂ : ℝ), cos θ₁ = 0 → cos θ₂ = 0 → ∃ m : ℤ, θ₂ - θ₁ = m * π := by

    use l
    linarith
  rcases h2 with ⟨l, hl2⟩
  use l - k
  rw [hl2, hk1]
  field_simp at *
  <;> ring_nf <;> norm_num

theorem imo_1969_p2 (m n : ℝ) (k : ℕ) (a : ℕ → ℝ) (y : ℝ → ℝ) (h₀ : 0 < k)
    (h₁ : ∀ x, y x = ∑ i in Finset.range k, Real.cos (a i + x) / 2 ^ i) (h₂ : y m = 0)
    (h₃ : y n = 0) : ∃ t : ℤ, m - n = t * Real.pi := by
  have h4 : y m = ∑ i in Finset.range k, Real.cos (a i + m) / 2 ^ i := by
    specialize h₁ m
    simpa using h₁
  have h5 : y n = ∑ i in Finset.range k, Real.cos (a i + n) / 2 ^ i := by
    specialize h₁ n
    simpa using h₁
  rw [h4] at h₂
  rw [h5] at h₃
  have h9 : ∃ R0 α : ℝ, R0 > 0 ∧ ∀ x : ℝ, ∑ j : Fin k, Real.cos (a j + x) / 2 ^ j.1 = R0 * Real.cos (x + α) := by
    apply sum_cos_div_two_pow_eq_mul_cos k (fun (j : ℕ) => a j) (by omega)
  rcases h9 with ⟨R0, α, hR0, h_eq3⟩
  have h10 : ∑ i in Finset.range k, Real.cos (a i + m) / 2 ^ i = R0 * Real.cos (m + α) := by
    have h11 : ∑ i in Finset.range k, Real.cos (a i + m) / 2 ^ i = ∑ j : Fin k, Real.cos (a j + m) / 2 ^ j.1 := by
      simp [Finset.sum_range]
    rw [h11]
    specialize h_eq3 m
    simpa using h_eq3
  have h11 : ∑ i in Finset.range k, Real.cos (a i + n) / 2 ^ i = R0 * Real.cos (n + α) := by
    have h12 : ∑ i in Finset.range k, Real.cos (a i + n) / 2 ^ i = ∑ j : Fin k, Real.cos (a j + n) / 2 ^ j.1 := by
      simp [Finset.sum_range]
    rw [h12]
    specialize h_eq3 n
    simpa using h_eq3
  have h10' : R0 * Real.cos (m + α) = 0 := by
    have h_eq10 : ∑ i in Finset.range k, Real.cos (a i + m) / 2 ^ i = 0 := by
      linarith [h₂, h10]
    linarith [h10, h_eq10]
  have h11' : R0 * Real.cos (n + α) = 0 := by
    have h_eq11 : ∑ i in Finset.range k, Real.cos (a i + n) / 2 ^ i = 0 := by
      linarith [h₃, h11]
    linarith [h11, h_eq11]
  have h12 : Real.cos (m + α) = 0 := by
    apply (mul_left_inj' (ne_of_gt hR0)).mp
    linarith
  have h13 : Real.cos (n + α) = 0 := by
    apply (mul_left_inj' (ne_of_gt hR0)).mp
    linarith
  have h14 : ∃ m1 : ℤ, (n + α) - (m + α) = m1 * Real.pi := by
    apply sub_eq_int_mul_pi_of_cos_eq_zero (m + α) (n + α) h12 h13
  rcases h14 with ⟨m1, hm1⟩
  use -m1
  have hm4 : (m : ℝ) - (n : ℝ) = - (m1 * Real.pi) := by
    have hm3 : (n + α : ℝ) - (m + α : ℝ) = (m1 : ℝ) * Real.pi := by
      linarith [hm1]
    nlinarith
  have hm5 : (-m1 : ℤ) * Real.pi = - (m1 * Real.pi) := by
    simp
  rw [hm5]
  linarith [hm4]
```

### 纠错示例

在下面的例子中，初始证明超时了，因为直接对 `((Real.sqrt 3 / 2 : ℂ) + (1 / 2) * Complex.I) ^ 12` 应用 `simp` 会带来过高的搜索复杂度。把证明拆解为逐步计算中间幂次——先算 $z^3$，再算 $z^6$，最后算 $z^{12}$——显著降低了编译器的计算负担。

### 纠错前的证明

```
import Mathlib

theorem algebra_299086 {z : ℂ} (hz : z = (Real.sqrt 3 / 2) + (1 / 2) * .I) : z ^ 2016 = 1 := by
  have h1 : z = (Real.sqrt 3 / 2) + (1 / 2) * Complex.I := hz
  -- Prove z^12 = 1
  have h2 : z ^ 12 = 1 := by
    rw [h1]
    have h3 : ((Real.sqrt 3 / 2 : ℂ) + (1 / 2) * Complex.I) ^ 12 = 1 := by
      simp [pow_succ, pow_zero, Complex.ext_iff, Complex.I_mul_I, mul_add, add_mul, mul_comm, mul_assoc, pow_two, pow_three, pow_succ, Real.sqrt_sq]
      field_simp [Complex.ext_iff, mul_add, add_mul, pow_two, pow_three]
      <;> ring_nf <;> norm_num [Real.sqrt_sq] 
    exact h3
  calc
    z ^ 2016 = (z ^ 12) ^ 168 := by ring
    _ = 1 ^ 168 := by rw [h2]
    _ = 1 := by norm_num
```

### 纠错后的证明

```
import Mathlib

theorem algebra_299086 {z : ℂ} (hz : z = (Real.sqrt 3 / 2) + (1 / 2) * .I) : z ^ 2016 = 1 := by
  have h1 : z = (Real.sqrt 3 / 2) + (1 / 2) * Complex.I := by
    exact_mod_cast hz
  have h2 : z ^ 3 = Complex.I := by
    rw [h1]
    simp [pow_three, Complex.ext_iff, Complex.add_re, Complex.add_im, Complex.mul_re, Complex.mul_im, mul_add, add_mul, pow_two, mul_comm, mul_assoc]
    field_simp
    <;> ring_nf <;> norm_num
  have h3 : z ^ 6 = -1 := by
    calc
      z ^ 6 = (z ^ 3) ^ 2 := by ring
      _ = Complex.I ^ 2 := by rw [h2]
      _ = -1 := by simp [Complex.I_sq]
  have h4 : z ^ 12 = 1 := by
    calc
      z ^ 12 = (z ^ 6) ^ 2 := by ring
      _ = (-1) ^ 2 := by rw [h3]
      _ = 1 := by norm_num
  calc
    z ^ 2016 = (z ^ 12) ^ 168 := by
      ring_nf
    _ = (1) ^ 168 := by
      rw [h4]
    _ = 1 := by
      norm_num
```
