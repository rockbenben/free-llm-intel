[llama.cpp × AMD Benchmark](https://ggml-org-llamacpp-amd-bench.static.hf.space/index.html) 仪表板已经在 Hugging Face 上线了。借助它，你可以跨不同的 llama.cpp 构建、模型和量化方式，跟踪 prompt 处理与文本生成的性能，从而亲自探索本地推理在 AMD Ryzen 与 Radeon 硬件上究竟有怎样的表现。

本地推理的性能会随着模型、kernel 以及构建的演进而不断变化。我们希望任何一位 AMD 开发者都能轻松看到这些变化：选好一个硬件、一个模型和一个构建，比较不同的量化方式，并持续跟踪性能随时间的走势。基准测试的工作流和底层结果都是公开的，因此你也可以看清我们究竟是如何对推理性能做基准测试的。

## 快速开始

你可以从 Configuration 侧边栏里选择 **Hardware**、**Model** 和 **llama.cpp build** 这三项配置。当前可选的硬件是 Radeon 8060S (gfx1151) 和 Radeon AI Pro R9700S (gfx1201)。

- 在 **Overview** 标签页中，你可以针对同一组硬件、模型和构建来比较不同的量化方式。两张图表分别展示 PP512（处理 512 个输入 token、不做生成）和 TG128（生成 128 个 token）的成绩，两者的起点都是上下文深度 0。
- 在 **Build history** 标签页中，跟踪你所选硬件、模型和量化下所有已记录构建的 PP512 与 TG128 成绩。
- 在 **Context** **scaling** 标签页中，查看在所选构建、硬件、模型和量化下，token 生成吞吐会如何随着已有上下文的增长而发生变化。

## 这些数字意味着什么

仪表板展示的是两项彼此独立的测试结果，两者的计量单位都是每秒 token 数：

| 测试 | 负载 | 它帮你评估什么 |
| --- | --- | --- |
| **PP512** | 处理 512 个输入 token | 模型处理一个 prompt 有多快 |
| **TG128** | 生成 128 个 token | 模型产出输出有多快 |

两项测试都从上下文深度 0（`n_depth=0`）这个起点开始。PP512 衡量的是在不做任何生成的情况下处理 512 个输入 token；TG128 衡量的是在没有既有上下文的情况下生成 128 个 token。图表中绘制的数值是平均吞吐量（`avg_ts`）。这些都是很有参考价值的负载，而 Context scaling 标签页则可以让你进一步探索 token 生成吞吐随上下文增长而发生的变化。

## 我们如何运行基准测试

我们做基准测试用的对象，是通过 [llama-install.sh](https://github.com/ggml-org/llama-install.sh) 分发的预编译二进制文件——也就是 [llama.app](https://llama.app/) 背后的那个构建与安装项目。公开的 [gfx1151](https://github.com/ggml-org/llama-install.sh/blob/master/.github/workflows/bench-gfx1151.yml) 和 [gfx1201](https://github.com/ggml-org/llama-install.sh/blob/master/.github/workflows/bench-gfx1201.yml) 工作流每周定时运行，使用 [llama-bench 工具](https://github.com/ggml-org/llama.cpp/tree/master/tools/llama-bench) 在 Flash Attention 开启和关闭这两种情况下运行标准基准测试，每个配置重复 10 次。

模型集合会不断演进，目前已经包含了 Inkling 2 Mini、Qwen、Gemma、gpt-oss 和 LFM 这几个模型系列，覆盖 dense 与 mixture-of-experts（混合专家）两类架构。可用的 GGUF 格式包括 `Q4_K_M`、`Q8_0` 以及其他量化格式，还有 `BF16`、`F16` 这类更高精度的格式。

## 查看并复用结果

探索器的数据是直接从 Hugging Face 上公开的 [ggml-org/install.sh-benches-data Storage Bucket](https://huggingface.co/buckets/ggml-org/install.sh-benches-data) 读取的。图表标题旁边的 **data source** 链接，会为你打开所选构建、硬件和模型所对应的文件夹。

标准结果使用 `<build>/<hardware>/<model>/<quant>.jsonl` 这样的路径来存放；负载扫描则在同一个文件夹下使用 `<quant>-tg.jsonl` 作为文件名。

你可以用它们来调查某个具体结果、绘制自己的图表，或者与你自己在本地跑出来的结果作对比。
