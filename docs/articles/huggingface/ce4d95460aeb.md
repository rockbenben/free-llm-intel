# 为低资源 ASR 微调 MMS Adapter 模型

作者：Patrick von Platen（patrickvonplaten）

本文另有中文版本 [简体中文](https://huggingface.co/blog/zh/mms_adapters)。

***新（2023/06）***：*本博客深受 ["Fine-tuning XLS-R on Multi-Lingual ASR"](https://huggingface.co/blog/fine-tune-xlsr-wav2vec2) 的启发，可以视作它的改进版。*

**Wav2Vec2** 是一个用于自动语音识别（ASR）的预训练模型，由 *Alexei Baevski、Michael Auli 和 Alex Conneau* 于 [2020 年 9 月](https://ai.facebook.com/blog/wav2vec-20-learning-the-structure-of-speech-from-raw-audio/)发布。在 Wav2Vec2 于最流行的英文 ASR 数据集之一 [LibriSpeech](https://huggingface.co/datasets/librispeech_asr) 上展现出强劲性能后不久，*Facebook AI* 推出了 Wav2Vec2 的多语言版本 [XLSR](https://arxiv.org/abs/2006.13979) 和 [XLM-R](https://ai.facebook.com/blog/-xlm-r-state-of-the-art-cross-lingual-understanding-through-self-supervision/)，能识别多达 128 种语言的语音。XLSR 意为 *cross-lingual speech representations*（跨语言语音表征），指模型能够学到对多种语言都有用的语音表征。

Meta AI 的最新发布——由 *Vineel Pratap、Andros Tjandra、Bowen Shi 等*撰写的 [**Massive Multilingual Speech (MMS)**](https://ai.facebook.com/blog/multilingual-model-speech-recognition/)——把多语言语音表征带上了新台阶。**MMS** 能够识别、转录和生成超过 1,100 种口语语言——相关[语言识别、语音识别与语音合成 checkpoint](https://huggingface.co/models?other=mms)均已发布。

在这篇博客中，我们将展示 MMS 的 Adapter（适配器）训练如何只需微调 10-20 分钟就能达到低得惊人的词错误率。

对于低资源语言，我们**强烈**建议使用 MMS 的 Adapter 训练，而不是像 ["Fine-tuning XLS-R on Multi-Lingual ASR"](https://huggingface.co/blog/fine-tune-xlsr-wav2vec2) 那样微调整个模型。

在我们的实验中，MMS 的 Adapter 训练既更省显存、更稳健，在低资源语言上的性能也更好。不过对中等到高资源语言，微调整个 checkpoint 而非使用 Adapter 层仍可能更划算。

[![wav2vec2_structure](https://huggingface.co/blog/assets/151_mms/mms_map.png)](https://huggingface.co/blog/assets/151_mms/mms_map.png)

## **守护世界语言多样性**

据 [https://www.ethnologue.com/](https://www.ethnologue.com/) 统计，约 3,000 种——即全部"活着的"语言的 40%——因母语者日益减少而濒危。在日益全球化的世界里，这一趋势只会继续。

**MMS** 能够转录许多濒危语言，比如 *Ari* 和 *Kaivi*。未来，MMS 可以在让语言存续方面发挥关键作用：帮助仅存的使用者建立文字记录、用母语交流。

为适配 1000 多种不同的词表，**MMS** 使用了 Adapters——一种只训练模型权重中一小部分的方法。

Adapter 层就像语言的桥梁，让模型在解读一种语言时可以借助另一种语言的知识。

## **微调 MMS**

**MMS** 的无监督 checkpoint 在超过 **50 万**小时音频、**1,400** 多种语言上预训练，参数量从 3 亿到 10 亿不等。

你可以在 🤗 Hub 上找到 3 亿参数（300M）和 10 亿参数（1B）两种规格的纯预训练 checkpoint：

- [**`mms-300m`**](https://huggingface.co/facebook/mms-300m)
- [**`mms-1b`**](https://huggingface.co/facebook/mms-1b)

*注*：如果你想微调基座模型，方法与 ["Fine-tuning XLS-R on Multi-Lingual ASR"](https://huggingface.co/blog/fine-tune-xlsr-wav2vec2) 完全相同。

与 [BERT 的掩码语言建模目标](http://jalammar.github.io/illustrated-bert/)类似，MMS 在自监督预训练中通过随机掩码特征向量再送入 transformer 网络，学到上下文相关的语音表征。

用于 ASR 时，预训练的 [`MMS-1B` checkpoint](https://huggingface.co/facebook/mms-1b) 又在 1000 多种语言上以监督方式进一步微调，采用共享词表输出层。最后一步，共享词表输出层被丢弃，只保留各语言专属的 adapter 层。每个 adapter 层仅含约 **2.5M** 个权重，由每个注意力块的小型线性投影层加一个语言专属词表输出层组成。

已发布三个为语音识别（ASR）微调过的 **MMS** checkpoint，分别包含 102、1107 和 1162 份 adapter 权重（每种语言一份）：

- [**`mms-1b-fl102`**](https://huggingface.co/facebook/mms-1b-fl102)
- [**`mms-1b-l1107`**](https://huggingface.co/facebook/mms-1b-l1107)
- [**`mms-1b-all`**](https://huggingface.co/facebook/mms-1b-all)

可以看到基座模型照常保存为一个 [`model.safetensors` 文件](https://huggingface.co/facebook/mms-1b/blob/main/model.safetensors)，但这些仓库里还额外存了很多 adapter 权重，例如法语对应 [`adapter.fra.safetensors`](https://huggingface.co/facebook/mms-1b-all/blob/main/adapter.fra.safetensors)。

Hugging Face 文档[把这类 checkpoint 如何做推理讲得很清楚](https://huggingface.co/docs/transformers/main/en/model_doc/mms#loading)，所以本博客转而聚焦：如何基于任一已发布的 ASR checkpoint，高效训练出高性能的 adapter 模型。

## 训练自适应权重

在机器学习中，adapters 是一种保持原始模型参数不变、只微调预训练模型的方法：在模型既有层之间插入小型可训练模块（即 [adapter 层](https://arxiv.org/pdf/1902.00751.pdf)），让模型适配特定任务而无需大规模重训。

Adapters 在语音识别、尤其是**说话人识别**领域历史悠久。在说话人识别中，adapters 被有效用于改造既有模型以识别个体说话人的特征，[Gales 和 Woodland (1996)](https://www.isca-speech.org/archive_v0/archive_papers/icslp_1996/i96_1832.pdf) 和 [Miao 等 (2014)](https://www.cs.cmu.edu/~ymiao/pub/tasl_sat.pdf) 的工作即是例证。相比训练完整模型，这种做法不仅大幅降低计算需求，还能做出更好、更灵活的说话人定制。

**MMS** 的工作把 adapter 思路用于跨语言的语音识别：只微调少量 adapter 权重来掌握每种目标语言独特的语音和语法特征。由此，MMS 让单个大型基座模型（例如 [**`mms-1b-all`**](https://huggingface.co/facebook/mms-1b-all) checkpoint）配上 1000 多个小 adapter 层（对 **`mms-1b-all`** 而言每个仅 2.5M 权重）就能理解并转录多种语言，极大降低了为每种语言单独训练模型的算力需求。

好！理解了动机和理论，我们开始为 **`mms-1b-all`** 微调 adapter 权重 🔥

## 准备数据、Tokenizer 和 Feature Extractor

ASR 模型把语音转成文本，因此我们既需要一个把语音信号处理成模型输入格式（即特征向量）的 feature extractor，也需要一个把模型输出格式还原成文本的 tokenizer。

在 🤗 Transformers 中，MMS 模型配套有一个 feature extractor（[Wav2Vec2FeatureExtractor](https://huggingface.co/transformers/master/model_doc/wav2vec2.html#wav2vec2featureextractor)）和一个 tokenizer（[Wav2Vec2CTCTokenizer](https://huggingface.co/transformers/master/model_doc/wav2vec2.html#wav2vec2ctctokenizer)）。

先来创建 tokenizer，把预测的输出类别解码为转录文本。

### 创建 `Wav2Vec2CTCTokenizer`

微调过的 MMS 模型（如 [**`mms-1b-all`**](https://huggingface.co/facebook/mms-1b-all)）本身已带有配套的 [tokenizer](https://huggingface.co/facebook/mms-1b-all/blob/main/tokenizer_config.json)。但由于我们要在某语言特定的低资源数据上微调，推荐把 tokenizer 和词表输出层彻底移除，基于训练数据本身重新创建。

基于 CTC 微调的 Wav2Vec2 类模型用一次前向传播转录音频文件：先把音频输入处理成上下文书列表征，再用最终的词表输出层把每个上下文表征分类为一个代表转录结果的字符。

该层的输出大小对应词表中的 token 数，我们要从微调所用的标注数据集中抽取。所以第一步，来看所选的 Common Voice 数据集，并基于转录文本定义词表。

本笔记本使用 [Common Voice 6.1 数据集](https://huggingface.co/datasets/mozilla-foundation/common_voice_6_1)的土耳其语数据。土耳其语对应语言代码 `"tr"`。

可以看到转录文本中含一些特殊字符，如 `,.?!;:`。没有语言模型时，把语音块分类到这些特殊字符要难得多，因为它们并不对应某个有特征的声音单位。例如字母 `"s"` 有相对明确的声音，而特殊字符 `"."` 没有。而且，要理解语音信号的含义，通常也不需要把特殊字符包含在转录里。

我们把所有不贡献词义、无法用声音表示的字符移除，并对文本做规范化。

    return batch
```

在最终确定预处理之前，请教一下目标语言的母语者总是明智的——文本还能进一步简化吗。为了这篇博客，[Merve](https://twitter.com/mervenoyann) 热心地快速看了一眼，并指出像 `â` 这样的"带帽"字符在土耳其语中已不太使用，可以用"脱帽"的等价字母替换，如 `a`。

也就是说，我们应该把 `"yargı sistemi hâlâ sağlıksız"` 这样的句子替换成 `"yargı sistemi hala sağlıksız"`。

再写一个小映射函数进一步简化文本标签。记住——文本标签越简单，模型学会预测它们就越容易。

```
def replace_hatted_characters(batch):
    batch["sentence"] = re.sub('[â]', 'a', batch["sentence"])
    batch["sentence"] = re.sub('[î]', 'i', batch["sentence"])
    batch["sentence"] = re.sub('[ô]', 'o', batch["sentence"])
    batch["sentence"] = re.sub('[û]', 'u', batch["sentence"])
    return batch
```

```
common_voice_train = common_voice_train.map(replace_hatted_characters)
common_voice_test = common_voice_test.map(replace_hatted_characters)
```

在 CTC 中，把语音块分类到字母是常规做法，我们也照样来。从训练和测试数据中提取所有不同字母，用这个字母集合构建词表。

我们写一个映射函数，把所有转录文本拼成一条长文本，再把字符串转成字符集合。务必给 `map(...)` 函数传 `batched=True`，映射函数才能一次访问所有转录文本。

```
def extract_all_chars(batch):
  all_text = " ".join(batch["sentence"])
  vocab = list(set(all_text))
  return {"vocab": [vocab], "all_text": [all_text]}
```

```
vocab_train = common_voice_train.map(extract_all_chars, batched=True, batch_size=-1, keep_in_memory=True, remove_columns=common_voice_train.column_names)
vocab_test = common_voice_test.map(extract_all_chars, batched=True, batch_size=-1, keep_in_memory=True, remove_columns=common_voice_test.column_names)
```

vocab_list = list(set(vocab_train["vocab"][0]) | set(vocab_test["vocab"][0]))

很好，可以看到字母表中的所有字母都出现在数据集中（并不意外），还抽出了特殊字符 `""` 和 `'`。注意我们没有排除这些特殊字符，因为模型必须学会预测一个词何时结束——否则预测将永远是一串无法分词的连续字母。

请始终记住：预处理是训练模型前非常重要的一步。例如，我们不愿因为忘了做数据规范化，就让模型去区分 `a` 和 `A`。`a` 与 `A` 的区别根本不取决于字母的"声音"，而更多取决于语法——比如句首字母大写。所以去掉大小写差异是合理的，能让模型更容易学会转录语音。

为了让 `" "` 有自己的 token 类别更直观，我们把它换成更显眼的字符 `|`。此外再加一个 "unknown" token，让模型日后能处理 Common Voice 训练集中没出现过的字符。

```
vocab_dict["|"] = vocab_dict[" "]
del vocab_dict[" "]
```

最后，再加一个 padding token，对应 CTC 的"*blank token*"（空白符）。blank token 是 CTC 算法的核心组成部分，详情请看[这里的 "Alignment" 一节](https://distill.pub/2017/ctc/)。

```
vocab_dict["[UNK]"] = len(vocab_dict)
vocab_dict["[PAD]"] = len(vocab_dict)
len(vocab_dict)
```

```
    37
```

### 创建 `Wav2Vec2FeatureExtractor`

语音是连续信号，要让计算机处理，必须先离散化，通常称为**采样**。采样率很重要，它定义了每秒测量语音信号的多少个数据点。因此，更高的采样率能得到对*真实*语音信号更好的近似，但每秒需要的数值也更多。

预训练 checkpoint 期望其输入数据的采样分布与训练数据大致一致。同一段语音以两种不同采样率采样会有非常不同的分布，例如采样率翻倍意味着数据点翻倍。所以，在微调 ASR 模型的预训练 checkpoint 前，务必确认预训练数据的采样率与微调数据集的采样率一致。

实例化 `Wav2Vec2FeatureExtractor` 对象需要以下参数：

- `feature_size`：语音模型以特征向量序列为输入。序列长度显然会变，但特征维度不该变。就 Wav2Vec2 而言，feature size 为 1，因为模型在原始语音信号上训练 2 {}^2 2。
- `sampling_rate`：模型训练所用的采样率。
- `padding_value`：批量推理时，较短的输入需要用特定值填充
- `do_normalize`：输入是否要做*零均值单位方差*归一化。通常语音模型在输入归一化后表现更好
- `return_attention_mask`：模型批量推理时是否应使用 `attention_mask`。一般而言，XLS-R 模型的 checkpoint 应**始终**使用 `attention_mask`。

```
from transformers import Wav2Vec2FeatureExtractor

feature_extractor = Wav2Vec2FeatureExtractor(feature_size=1, sampling_rate=16000, padding_value=0.0, do_normalize=True, return_attention_mask=True)
```

很好，MMS 的特征提取流水线就此全部定义完毕！

为了对用户更友好，feature extractor 和 tokenizer 被*包装*进单一的 `Wav2Vec2Processor` 类，这样只需要 `model` 和 `processor` 两个对象。

```

第一步，直接调用 `batch["audio"]` 加载并重采样音频数据。第二步，从加载的音频文件中提取 `input_values`。在我们的例子里，`Wav2Vec2Processor` 只做归一化；但对其他语音模型，这一步可以包含更复杂的特征提取，如 [Log-Mel 特征提取](https://en.wikipedia.org/wiki/Mel-frequency_cepstrum)。第三步，把转录文本编码为标签 id。

**注意**：这个映射函数是 `Wav2Vec2Processor` 类应如何使用的很好示例。"正常"情况下，调用 `processor(...)` 会被转发到 `Wav2Vec2FeatureExtractor` 的 call 方法；而把 processor 包进 `as_target_processor` 上下文时，同一方法则被转发到 `Wav2Vec2CTCTokenizer` 的 call 方法。更多信息请查看[文档](https://huggingface.co/transformers/master/model_doc/wav2vec2.html#transformers.Wav2Vec2Processor.__call__)。

```
def prepare_dataset(batch):
    audio = batch["audio"]

    # batched output is "un-batched"
    batch["input_values"] = processor(audio["array"], sampling_rate=audio["sampling_rate"]).input_values[0]
    batch["input_length"] = len(batch["input_values"])

    batch["labels"] = processor(text=batch["sentence"]).input_ids
    return batch
```

## 训练

数据已处理好，可以着手搭建训练流水线。我们使用 🤗 的 [Trainer](https://huggingface.co/transformers/master/main_classes/trainer.html?highlight=trainer)，本质上需要做以下几件事：

- 定义 data collator。与多数 NLP 模型不同，MMS 的输入长度远大于输出长度。例如 50000 长的输入，输出不超过 100。给定这么大的输入规模，对训练批次做动态 padding 效率高得多——即每条训练样本只填充到其所在批次中最长样本的长度，而不是全局最长。因此微调 MMS 需要一个特殊的 padding data collator，我们在下面定义
- 评估指标。训练过程中要评估词错误率，需要相应定义 `compute_metrics` 函数
- 加载预训练 checkpoint，并为训练正确配置
- 定义训练配置。

微调完成后，我们会在测试数据上认真评估，验证模型确实学会了正确转录语音。

### 配置 Trainer

先从定义 data collator 开始。其代码复制自[这个示例](https://github.com/huggingface/transformers/blob/7e61d56a45c19284cfda0cee8995fb552f6b1f4e/examples/pytorch/speech-recognition/run_speech_recognition_ctc.py#L219)。

不展开太多细节：与常见 data collator 不同，这个 collator 对 `input_values` 和 `labels` 分别处理，用两个不同的 padding 函数（同样借助 MMS processor 的上下文管理器）。这是必要的，因为语音识别中输入和输出属于不同模态，不该用同一个 padding 函数处理。与常见 data collator 一样，标签中的 padding token 被替换为 `-100`，使这些 token 在计算损失时**不**被计入。

```
import torch

from dataclasses import dataclass, field
from typing import Any, Dict, List, Optional, Union

@dataclass
class DataCollatorCTCWithPadding:
    """
    Data collator that will dynamically pad the inputs received.
    Args:
        processor (:class:`~transformers.Wav2Vec2Processor`)
            The processor used for proccessing the data.
        padding (:obj:`bool`, :obj:`str` or :class:`~transformers.tokenization_utils_base.PaddingStrategy`, `optional`, defaults to :obj:`True`):
            Select a strategy to pad the returned sequences (according to the model's padding side and padding index)
            among:
            * :obj:`True` or :obj:`'longest'`: Pad to the longest sequence in the batch (or no padding if only a single
              sequence if provided).
            * :obj:`'max_length'`: Pad to a maximum length specified with the argument :obj:`max_length` or to the
              maximum acceptable input length for the model if that argument is not provided.
            * :obj:`False` or :obj:`'do_not_pad'` (default): No padding (i.e., can output a batch with sequences of
              different lengths).
    """

    processor: Wav2Vec2Processor
    padding: Union[bool, str] = True

    def __call__(self, features: List[Dict[str, Union[List[int], torch.Tensor]]]) -> Dict[str, torch.Tensor]:
        # split inputs and labels since they have to be of different lengths and need
        # different padding methods
        input_features = [{"input_values": feature["input_values"]} for feature in features]
        label_features = [{"input_ids": feature["labels"]} for feature in features]

        batch = self.processor.pad(
            input_features,
            padding=self.padding,
            return_tensors="pt",
        )

        labels_batch = self.processor.pad(
            labels=label_features,
            padding=self.padding,
            return_tensors="pt",
        )

        # replace padding with -100 to ignore loss correctly
        labels = labels_batch["input_ids"].masked_fill(labels_batch.attention_mask.ne(1), -100)

        batch["labels"] = labels

        return batch
```

```

```

接下来定义评估指标。如前所述，ASR 的主流指标是词错误率（WER），本笔记本也用它。

```
from evaluate import load

wer_metric = load("wer")
```

模型将返回一列 logit 向量 y1,…,ym \mathbf{y}_1, \ldots, \mathbf{y}_m y1​,…,ym​，其中 y1=fθ(x1,…,xn)[0] \mathbf{y}_1 = f_{\theta}(x_1, \ldots, x_n)[0] y1​=fθ​(x1​,…,xn​)[0]，且 n>>m n >> m n>>m。

一个 logit 向量 y1 \mathbf{y}_1 y1​ 包含对先前定义的词表中每个词的对数几率，因此 len(yi)= \text{len}(\mathbf{y}_i) = len(yi​)= `config.vocab_size`。我们关心模型最可能的预测，所以对 logits 取 `argmax(...)`。同时把编码后的标签还原成原始字符串：把 `-100` 替换为 `pad_token_id`，并解码 ids，同时确保连续 token **不**按 CTC 方式合并 1 {}^1 1。

```
def compute_metrics(pred):
    pred_logits = pred.predictions
    pred_ids = np.argmax(pred_logits, axis=-1)

    pred.label_ids[pred.label_ids == -100] = processor.tokenizer.pad_token_id

    pred_str = processor.batch_decode(pred_ids)
    # we do not want to group tokens when computing the metrics
    label_str = processor.batch_decode(pred.label_ids, group_tokens=False)

    wer = wer_metric.compute(predictions=pred_str, references=label_str)

    return {"wer": wer}
```

最后一步，定义训练相关的所有参数。就部分参数多说两句：

1 {}^1 1 为了让模型不受说话语速影响，CTC 会把连续相同的 token 简单合并为一个 token。但解码时编码标签不应被合并，因为它们并不对应模型的预测 token，这就是必须传 `group_tokens=False` 的原因。若不传这个参数，像 `"hello"` 这样的词会被错误地编码、解码为 `"helo"`。 2 {}^2 2 blank token 让模型能够预测 `"hello"` 这样的词——办法是强制在两个 l 之间插入 blank token。我们模型一个符合 CTC 规则的 `"hello"` 预测形如 `[PAD] [PAD] "h" "e" "e" "l" "l" [PAD] "l" "o" "o" [PAD]`。

把所有 adapter 层存进训练输出目录，以便正确上传到 Hub。

```
from safetensors.torch import save_file as safe_save_file
from transformers.models.wav2vec2.modeling_wav2vec2 import WAV2VEC2_ADAPTER_SAFE_FILE
import os

adapter_file = WAV2VEC2_ADAPTER_SAFE_FILE.format(target_lang)
adapter_file = os.path.join(training_args.output_dir, adapter_file)

safe_save_file(model._get_adapters(), adapter_file, metadata={"format": "pt"})
```

最后，把训练成果上传到 🤗 Hub。

```
trainer.push_to_hub()
```

adapter 权重训练的主要优势之一：占模型权重约 99% 的"基座"模型保持不变，只需共享一个小小的 [2.5M adapter checkpoint](https://huggingface.co/patrickvonplaten/wav2vec2-large-mms-1b-turkish-colab/blob/main/adapter.tur.safetensors) 就能使用训练好的 checkpoint。

这让追加训练更多 adapter 层、把它们加入你的仓库变得极其简单。

只要改一下想训练的语言（例如瑞典语用 `swe`）重跑这个脚本即可。同时注意：不要让词表被完全覆盖，而要按前面注释单元格里说的那样，把新语言词表**追加**到已有词表上。

为演示不同 adapter 层如何加载，我还训练并上传了一个瑞典语的 adapter 层，ISO 语言代码为 `swe`，见[这里](https://huggingface.co/patrickvonplaten/wav2vec2-large-mms-1b-turkish-colab/blob/main/adapter.swe.safetensors)。

照常使用 `from_pretrained(...)` 加载微调后的 checkpoint，但务必在方法中加上 `target_lang="<your-lang-code>"`，以加载正确的 adapter；同时也要为 tokenizer 正确设置目标语言。

先加载土耳其语 checkpoint。

```
model_id = "patrickvonplaten/wav2vec2-large-mms-1b-turkish-colab"

model = Wav2Vec2ForCTC.from_pretrained(model_id, target_lang="tur").to("cuda")
processor = Wav2Vec2Processor.from_pretrained(model_id)

processor.tokenizer.set_target_lang("tur")
```

检查模型能否正确转录土耳其语

```
from datasets import Audio

common_voice_test_tr = load_dataset("mozilla-foundation/common_voice_6_1", "tr", data_dir="./cv-corpus-6.1-2020-12-11", split="test", use_auth_token=True)
common_voice_test_tr = common_voice_test_tr.cast_column("audio", Audio(sampling_rate=16_000))
```

处理音频、跑一次前向传播并预测 ids

```
input_dict = processor(common_voice_test_tr[0]["audio"]["array"], sampling_rate=16_000, return_tensors="pt", padding=True)

logits = model(input_dict.input_values.to("cuda")).logits

pred_ids = torch.argmax(logits, dim=-1)[0]
```

最后解码这个示例。

```
print("Prediction:")
print(processor.decode(pred_ids))

print("\nReference:")
print(common_voice_test_tr[0]["sentence"].lower())
```

**输出**：

```
    Prediction:
    pekçoğuda roman toplumundan geliyor

    Reference:
    pek çoğu da roman toplumundan geliyor.
```

看起来几乎全对，只是第一个词里应该有两个空格。现在只需调用 [`model.load_adapter(...)`](https://huggingface.co/blog/mozilla-foundation/common_voice_6_1) 并把 tokenizer 也切到瑞典语，就能轻松换成瑞典语 adapter。

```
model.load_adapter("swe")
processor.tokenizer.set_target_lang("swe")
```

同样从 Common Voice 加载瑞典语测试集

common_voice_test_swe = load_dataset("mozilla-foundation/common_voice_6_1", "sv-SE", data_dir="./cv-corpus-6.1-2020-12-11", split="test", use_auth_token=True)
