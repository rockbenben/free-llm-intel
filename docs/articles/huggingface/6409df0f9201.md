# 介绍 RTEB：检索评估新标准

**太长不看版 –** 我们很高兴推出 [Retrieval Embedding Benchmark（RTEB）](https://huggingface.co/spaces/mteb/leaderboard?benchmark_name=RTEB%28beta%29)的 beta 版。这是一个全新基准，旨在可靠评估嵌入模型在真实应用中的检索精度。现有基准很难度量真正的泛化能力，RTEB 用"公开 + 私有"数据集的混合策略来解决这个问题。它的目标很简单：建立一个公平、透明、面向应用的评估标准，衡量模型在没见过的数据上的表现。

从 RAG、智能体到推荐系统，许多 AI 应用的性能根本上受限于搜索与检索的质量。因此，准确度量嵌入模型的检索质量是开发者普遍的痛点。你到底怎么知道一个模型在真实环境中表现如何？

事情在这里变得棘手。当前的评估标准通常依赖模型在公开基准上的"零样本"表现。但这最多只能粗略逼近模型真实的泛化能力。当模型反复在同样的公开数据集上评估时，其报告分数与在新数据、未见数据上的实际表现之间就会出现落差。

（公开数据集与封闭数据集之间的性能差异）

为应对这些挑战，我们开发了 RTEB——一个为检索模型提供可靠评估标准的基准。

## 现有基准为何不够格

底层评估方法和指标（如 NDCG@10）早已为人熟知且稳健，但现有基准的公信力常常受以下问题拖累：

**泛化鸿沟**。当前基准生态无意间鼓励了"应试教学"。当训练数据来源与评估数据集重叠时，模型分数会被虚高，破坏基准的公信力。这种做法无论有意无意，在一些模型的训练数据集里都看得分明。由此形成反馈循环：模型靠记住测试数据获得奖励，而不是发展稳健、可泛化的能力。

正因为如此，零样本分数低¹的模型可能在基准上表现得很好，却无法泛化到新问题上。所以，人们往往更推荐基准性能略低但零样本分数更高的模型。

（图来自 Chung et al. (2025)）

**与当今 AI 应用脱节**。许多基准与开发者今天在构建的企业用例契合度很差。它们往往依赖学术数据集，或从 QA 数据集派生检索任务——这些自有其价值，但当初并非为评估检索而设计，可能无法捕捉真实检索场景中的分布偏倚与复杂性。而没有这些问题的基准又常常过于狭窄，只关注单一领域（如代码检索），不适合评估通用模型。

## 介绍 RTEB

今天，我们隆重推出 **Retrieval Embedding Benchmark（RTEB）**。它的目标是建立一个全新、可靠、高质量的基准，度量嵌入模型真正的检索精度。

### 混合策略，验证真实泛化

为对抗基准过拟合，RTEB 采用公开与私有数据集结合的混合策略：

- **公开数据集：**语料、查询、相关性标签全部公开。这保证了透明度，任何用户都能复现结果。
- **私有数据集：**这些数据集保持私有，评估由 MTEB 维护者执行以保证公正。这为模型对未见数据的泛化能力提供了清晰、无偏的度量。出于透明考虑，我们为每个私有数据集提供描述性统计、数据集说明和示例 `(query, document, relevance)` 三元组。

这种混合方式鼓励开发具有广泛稳健泛化能力的模型。如果模型在公开集和私有集之间性能显著下滑，就说明存在过拟合，为社区提供了明确信号。一些模型已经显现出这一点——它们在 RTEB 私有数据集上的性能明显下降。

### 面向真实领域而建

RTEB 的设计特别注重企业用例。它不用复杂的层级结构，而是用简单的分组以求清晰。一个数据集可以属于多个分组（例如一个德国法律数据集同时存在于 "law" 和 "German" 组中）。

- **天然多语言：**基准数据集覆盖 20 种语言，从英语、日语这类常见语言到孟加拉语、芬兰语这类较少见的语言。
- **聚焦垂直领域：**基准收录法律、医疗、代码、金融等关键企业领域的数据集。
- **数据集规模适中：**数据集足够大以有意义（至少 1k 文档和 50 查询），又不至于大到让评估耗时昂贵。
- **检索优先的指标：**默认排行榜指标是 **NDCG@10**——排序搜索结果质量的金标准。

完整数据集列表见下文。我们计划持续更新公开与封闭两部分的各类数据集，并积极鼓励社区参与；如果你想建议其他数据集，请在 [MTEB 的 GitHub 仓库](https://github.com/embeddings-benchmark/mteb/issues)开 issue。

## 发布 RTEB：社区的努力

RTEB 今天以 beta 版发布。我们相信构建一个稳健的基准是社区的事业，并将根据开发者和研究者的反馈持续演进 RTEB。欢迎分享想法、建议新数据集、发现现有数据集的问题，和我们一起为所有人建立更可靠的标准。欢迎加入讨论或在 [MTEB 的 GitHub 仓库](https://github.com/embeddings-benchmark/mteb)开 issue。

## 局限与未来工作

为了指明改进方向，我们想对 RTEB 当前的局限和后续计划保持透明。

- **基准范围：**RTEB 聚焦现实的、检索优先的用例。高难度合成数据集不是当前目标，但未来可以加入。
- **模态：**基准目前只评估纯文本检索。我们计划在未来版本中加入图文及其他多模态检索任务。
- **语言覆盖：**我们正在积极扩展语言覆盖，特别是中文、阿拉伯语这样的大语种，以及更多低资源语言。如果你知道符合这些标准的高质量数据集，请告诉我们。
- **QA 数据集改造：**当前约 50% 的检索数据集由 QA 数据集改造而来，这可能带来问题：问题与上下文之间词汇重叠度高，会让依赖关键词匹配而非真正语义理解的模型占便宜。
- **私有数据集：**为测试泛化能力，我们使用仅 MTEB 维护者可见的私有数据集。为维护公平，所有维护者承诺不使用这些数据集训练并发布模型，只通过公开渠道在这些私有集上测试，确保任何公司或个人都不会获得不正当优势。

我们的目标是让 RTEB 成为社区信赖的检索评估标准。

RTEB 排行榜今天已在 [Hugging Face](https://huggingface.co/spaces/mteb/leaderboard?benchmark_name=RTEB%28beta%29) 上线，作为 MTEB 排行榜新设的检索板块的一部分。欢迎查看、评估你的模型，和我们一起为整个 AI 社区建设更好、更可靠的基准。
