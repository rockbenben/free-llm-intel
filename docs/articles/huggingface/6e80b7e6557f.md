# AprielGuard：现代 LLM 系统中面向安全与对抗鲁棒性的护栏

大语言模型（LLM）已从纯文本助手迅速演变为能够执行多步推理、调用外部工具、检索记忆并执行代码的复杂*智能体*系统。伴随这一演变的，是一个日益复杂的威胁格局：不仅有传统的内容安全风险，还有多轮越狱、提示注入、记忆劫持和工具操纵。

在这项工作中，我们推出 **AprielGuard**，一个 8B 参数、安全-安防的护栏模型，旨在检测：

- **16 类安全风险**，涵盖毒性、仇恨、成人内容、错误信息、自残、非法活动等。
- **广泛的对抗攻击**，包括提示注入、越狱、思维链损坏、上下文劫持、记忆投毒，以及多智能体利用序列。
- **智能体工作流中的安全违规与对抗攻击**，包括工具调用和模型推理轨迹。

AprielGuard 同时提供**推理**和**非推理**两种模式，在需要时实现可解释的分类，并为生产流水线实现低延迟分类。

## 动机

传统的安全分类器主要聚焦于一个有限的分类谱（例如毒性或自残），假设输入很短，并评估单条用户消息。而现代部署则具有以下特征：

- **多轮对话**
- **长上下文**
- **产生思维链的结构化推理步骤**
- **工具辅助的多步工作流（智能体）**
- **一类不断增长的、利用推理、工具或记忆的对抗攻击**

结果，生产团队越来越依赖变通方案：为不同阶段配备多个守卫模型、正则过滤器、静态规则或手工制作的启发式。这些方法脆弱且无法扩展。

AprielGuard 用一个**统一模型**和一个**统一的安全 + 对抗分类体系**来应对这些问题，专门为现代 LLM 智能体生态构建。

## AprielGuard 概览

AprielGuard 跨三种输入格式运作：

- **独立提示**（Standalone Prompt）
- **多轮对话**（Multi-turn Conversation）
- **智能体工作流**（Agentic Workflow）（工具调用、推理轨迹、记忆、系统上下文）

它输出：

- 安全分类，以及一份来自分类体系的被违反类别列表
- 对抗攻击分类
- 可选的、解释该决策的结构化**推理**

### **B. 对抗攻击分类体系**

模型检测并评估各种旨在操纵模型行为或规避安全机制的对抗性提示模式。模型输出一个二分类（例如 adversarial / non_adversarial），而非细粒度的攻击类别。

训练数据覆盖了多样化的对抗类型，例如角色扮演、世界观构建、说服和风格化，以及许多其他复杂的提示操纵策略。这些例子只是训练数据所纳入的更广泛对抗场景中的一个子集。

## 训练数据集

- **合成数据**：AprielGuard 在一个合成生成的训练数据集上训练。训练数据点在分类体系的子主题级别生成，以获得更好的覆盖。我们利用 Mixtral-8x7B 和内部开发的无审查模型来生成用于训练目的的不安全内容。模型以更高温度被提示以诱发输出变化。提示模板经过精心定制以确保准确的数据生成。对抗攻击通过结合合成数据点、多样化提示模板和基于规则的生成技术来构造。我们借助 [NVIDIA NeMo Curator](https://github.com/NVIDIA-NeMo/Curator) 生成大规模、多轮对话数据集，其中包含通过上下文切换进行迭代、演变攻击的复杂、真实场景。这种方式使我们能够系统地合成多样的交互模式，提升模型对长视界推理、对抗轮次和演变用户意图的鲁棒性。我们还使用 [SyGra](https://github.com/ServiceNow/SyGra) 框架来为有害提示和攻击生成的合成数据生成流程服务。训练数据集涵盖多种内容格式，例如对话、论坛帖子、推文、指令式提示、问题和操作指南。
- **数据增强**：为增强模型鲁棒性，我们对训练数据应用了一系列数据增强技术。这些增强旨在让模型接触现实场景中常见出现的自然变化和扰动。具体地，数据集包含诸如字符级噪声、插入拼写错误、leetspeak 替换、词级改写和句法重排等变换。这类增强通过降低对输入表层变化的敏感性来帮助模型更好地泛化，从而提升对对抗操纵和非标准文本表示的韧性。
- **智能体工作流**：智能体工作流代表真实世界场景，其中自主智能体执行涉及规划、推理，以及与工具、API 和其他智能体交互的多步任务。这些工作流常常包含用户提示、系统消息、中间推理步骤和工具调用的序列，使其容易受到多种攻击向量的影响。为构造这些训练数据点，我们合成了跨多个领域的广泛场景，捕捉用户与智能体系统之间真实的智能体交互。每个数据点都用细致的上下文元素加以丰富——包括工具定义、工具调用日志、智能体角色与策略、执行轨迹、对话历史、记忆状态和草稿本推理。对于恶意或对抗样本，我们损坏工作流的相关片段以反映某个特定攻击向量。根据场景不同，这可能涉及修改用户提示、篡改中间推理轨迹、修改工具输出、注入虚假记忆状态，或扰乱智能体之间的通信。通过系统地扰动智能体工作流的不同组件，我们产出高保真的例子，让模型接触到一整个现实且具挑战性的攻击模式谱。每个数据点都被模拟以反映真实的执行，同时纳入良性和对抗序列。
- **长上下文用例**：我们精选了一个专门的长上下文数据集，由多样的、高长度用例组成，例如检索增强生成（RAG）工作流、多轮对话线程、事件详情，以及包含详细通信的运维报告。这些例子模拟了大文本上下文司空见惯的真实环境。

## 模型架构

AprielGuard 构建在一个 **Apriel-1.5 Thinker Base 变体**之上，为高效部署缩减到 8B 配置。

- **因果的、仅解码器 transformer**
- **双模式运作**：**推理模式** → 产出结构化解释；**快速模式** → 仅分类

### 训练设置

| 参数 | 值 |
| --- | --- |
| 基座模型 | Apriel 1.5 Thinker Base（缩减版） |
| 模型大小 | 8B 参数 |
| 精度 | bfloat16 |
| 批大小 | 1，梯度累积 = 8 |
| LR | 2e-4 |
| 优化器 | Adam（β1=0.9, β2=0.999） |
| 轮数 | 3 |
| 序列长度 | 最多 32k |
| 推理模式 | 通过指令模板启用/禁用 |

## 智能体工作流评估

我们精选了一个内部基准数据集，用于评估在智能体工作流内检测安全风险和对抗攻击的能力。为构造这个基准，我们系统地设计了针对工作流不同组件的多种攻击场景——例如提示输入、推理轨迹、工具参数、记忆状态和智能体之间的通信。每个实例都按照漏洞分类体系做了标注。每个工作流都被模拟以反映真实的执行，同时纳入良性和对抗序列。数据集捕捉了横跨规划、推理、执行和响应生成等各阶段的细粒度攻击点，以提供对模型鲁棒性的细粒度评估。总体而言，数据集包含安全风险与对抗攻击的均衡混合。

## 长上下文鲁棒性（最多 32k token）

许多真实世界的安全或对抗风险并不在简短、孤立的文本片段中显现，而是出现在检索增强生成（RAG）工作流、多轮对话线程、组织事件详情，以及包含详细通信的运维报告等用例之中。因此，一个守卫模型必须检测那些微妙或"大海捞针"的案例，其中恶意或操纵性内容稀疏分布、嵌入多处引用之中，或刻意隐匿在良性文本里。

为评估 AprielGuard 的长上下文推理能力，我们精选了一个由多样、高长度用例组成的专门测试数据集。在这次评估中我们考虑了最多 32k token 的数据。基线数据最初由代表这些领域的良性内容构造。随后系统地注入恶意元素，以在保持文本整体连贯性的同时模拟对抗或不安全场景。例如，在一个事件案例摘要中，注入可以嵌在案例描述里、藏在元数据段中，或作为评论线程的一部分插入。类似地，在多轮对话数据中，对抗内容可能出现在对话中间、接近末尾或在开头，以测试长程依赖追踪。

## 多语言评估

当前内容审核研究领域的一个主要局限是高品质多语言基准的稀缺。为弥合这一差距并全面评估 AprielGuard 的多语言能力，我们把安全风险基准和对抗攻击基准扩展到多种非英语语言。翻译过程使用 [MADLAD400-3B-MT](https://huggingface.co/google/madlad400-3b-mt) 模型进行，一个基于 T5 架构的多语言机器翻译模型。

在这项研究中，我们挑选了八种使用最广的非英语语言，以确保广泛的语言学与地理覆盖：法语、加拿大法语、德语、日语、荷兰语、西班牙语、巴西葡萄牙语和意大利语。英文安全和对抗基准中的每个实例都被翻译成八种目标语言。翻译期间，我们保留原始的英文角色标识符（例如 *User:* 和 *Assistant:*），只翻译对话内容。这一设计选择确保与 AprielGuard 的审核框架对齐，其中角色上下文在评估安全与对抗意图时起着关键作用。

## 结论

- AprielGuard 把安全、安防和智能体鲁棒性统一进单一守卫模型，能够处理：全面的安全风险分类；对抗攻击检测（包括提示注入和越狱尝试）；各种输入形态（例如独立提示、多轮对话和完整的智能体工作流）；长上下文输入；多语言输入；可解释的推理。

随着 LLM 迈向深度集成的智能体系统，对统一流水线的需求愈发关键。AprielGuard 是朝那个未来迈出的一步——降低复杂度、提升覆盖度，并为可信 AI 部署提供一个可扩展的基础。

## 局限

- 语言覆盖：尽管 AprielGuard 主要在英文数据上训练，有限的测试表明它在若干语言上表现相当好，包括：英语、德语、西班牙语、法语、加拿大法语、意大利语、荷兰语和巴西葡萄牙语。然而，在非英语环境下将模型投入生产使用之前，强烈建议做彻底的测试和校准。
- 对抗鲁棒性：尽管针对对抗和操纵行为做了定向训练，模型仍可能对复杂或未见的攻击策略表现出脆弱。
- 领域敏感性：AprielGuard 在需要细腻上下文理解的高度专业或技术性领域（例如法律、医疗或科学语境）上可能表现不佳。
- 延迟-可解释性权衡：启用推理轨迹能增强可解释性，但会增加延迟和计算成本。对于低延迟或大规模用例，推荐使用非推理模式。
- 推理模式敏感性：模型在启用推理与不启用推理两种推理模式的分类结果之间偶有不一致。
- 预期用途：AprielGuard 严格用于护栏和风险评估模型。它按 AprielGuard 统一分类体系对潜在安全风险和对抗威胁进行分类。任何偏离规定推理的行为都可能导致意外的、不安全的或不可靠的行为。
