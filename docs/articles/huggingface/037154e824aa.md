# **哇！都从我的草坪上下去！**

[![BlogThumbnail](https://cdn-uploads.huggingface.co/production/uploads/6ab2a746c7d0655b3d8dfbb9/5bIvVxc791He8vRKSaBH4.png)](https://cdn-uploads.huggingface.co/production/uploads/6ab2a746c7d0655b3d8dfbb9/5bIvVxc791He8vRKSaBH4.png)

**TL;DR：** MonsterHouse 是我为万圣节做的一套互动投影。它会听万圣夜讨糖孩子说话，用一艘脾气暴躁的老海盗船的嗓音回答，而在客人记得起码说「请」的时候，它就会心软。它构建在 [NVIDIA Nemotron Voice Agent](https://github.com/NVIDIA-AI-Blueprints/nemotron-voice-agent) 之上，搭配 NVIDIA [Nemotron ASR](https://huggingface.co/nvidia/nemotron-speech-streaming-en-0.6b)、[Nemotron 3.5 Bolt E4B 4GB](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB)、[Magpie TTS Zeroshot](https://build.nvidia.com/nvidia/magpie-tts-zeroshot) 和 [Audio2Face-3D](https://github.com/NVIDIA/Audio2Face-3D)，整套跑在一台工作站上。

我想让万圣节来我家讨糖的孩子们有一种有趣又独特的互动方式。房子要说了算、由它来发糖，但与其吓人，不如暴躁。不知怎么的，我的解决方案是给车库门装上一张嘴，再教会它抱怨。

这就成了 MonsterHouse：一座脾气暴躁的老房子，满肚子海盗故事、一口火牙，还有个可疑的软肋——对「请」字毫无抵抗力。NVIDIA Nemotron Voice Agent 提供对话底座，Nemotron Speech 负责听，Bolt E4B 是大脑，NVIDIA Magpie TTS Zeroshot 是现场的声音，NVIDIA Audio2Face-3D 让那张木头嘴动起来。

### **Monster House 如何运转**

> 听：NVIDIA Nemotron 3 ASR 把来访者的话转成文本。[nemotron-speech-streaming-en-0.6b.gguf ]  
> 想：NVIDIA Nemotron 3.5 Bolt E4B 4GB，一个面向对话式 agent 的开放小语言模型，负责写出每一句回复。人格则由一个 LoRA adapter 提供。  
> 说：NVIDIA Magpie TTS Zeroshot 依据一段该角色的短参考样本，为每句回复配音。  
> 动：NVIDIA Audio2Face-3D 把干净的语音转成 Unreal Engine 5 里的嘴部动画。  
> 看：NVIDIA Nemotron 3 Nano Omni 描述服装造型，YOLO 和 ByteTrack 则负责清点并追踪来客。  
> 跑：NVIDIA Nemotron Voice Agent 在一台配备 NVIDIA RTX PRO 6000 Blackwell Max-Q 和 NVIDIA RTX PRO 4000 Blackwell 的工作站上把一切协调起来。

### **一嘴木刺的狞笑**

嘴是先做出来的。我想象那扇木车库门的木板裂成参差的嘴唇，每当它张开那张诅咒之口，地狱之火就从背后照亮车道。它看起来得沧桑、有表情，并且对「居然有访客」这件事微微感到被冒犯。

[![fireMouth](https://cdn-uploads.huggingface.co/production/uploads/6ab2a746c7d0655b3d8dfbb9/CzzK5VpTMFR9Azps_6Qbv.png)](https://cdn-uploads.huggingface.co/production/uploads/6ab2a746c7d0655b3d8dfbb9/CzzK5VpTMFR9Azps_6Qbv.png)*一座有很多话要说的房子的几个表情。*

自制一套动画绑定是这个搭建工程里最费工的环节之一。把它生生捶服帖之后，我导出了 Audio2Face-3D 后续可以驱动的面部表情形状。角色 SkelMesh 在 Autodesk Maya 里建模，再导出到 Unreal Engine，在门后面加上虚拟火焰和特效。没有眼睛、没有眉毛、不会眨眼——它是一个出奇地省资源的怪物。

在我这边忙着折腾角色这些鸡毛蒜皮的时候，NVIDIA 把 Nemotron Voice Agent 建好了。原本以为最难的部分，如今反倒变得相当有趣、可以迭代而且轻松。开箱即用地有了听、对话和说的底座。房子已经有了嘴，现在它总算能找点事抱怨了。

### **调教坏礼貌**

这栋房子需要一段和它脾气一样乖戾的过去，于是我想出一套背景设定：它是用一艘沉没海盗船的船木建成的，仍被那段风雨飘摇的往事缠绕。这些满嘴航海腔的抱怨从此有了出处。这艘船转世成了房产，而且对此不太满意。

表演需要一条剧本：从打招呼到道别要走的路线，一路上还得把糖发出去。起初，房子会用「我正忙着嘟囔呢，去烦隔壁吧！」这样的话把客人打发包走。但坚持能把他说动。一句「Please」可能当场破防，而「thank you」能换来一个热情的道别。一旦客人赢得了它，我希望它就一直被赢下去。没人想跟同一扇车库门谈判第二次。

这正是 Voice Agent 大放异彩的地方。你可以选任何喜欢的 LLM。因为我想要一套离网、完全自包含的系统，我的显存和算力都有预算。

这个角色需要的不止一句「脾气暴躁点」的 prompt。它得遵循主对话流程、回应来访者实际说的话、追踪每一次遭遇的状态，还要为流水线的其余部分留足算力。

测了十来个模型之后，我最终选了 [Bolt E4B](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB) 来负责现场对白。它是一个为本地对话式 agent 和互动角色专门构建的开放小语言模型——拿来形容一扇会说话的车库门倒是相当贴切。我默认用 4-bit 量化版本（名字里的「4GB」）作为回复模型，另有 [BF16 checkpoint](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB-BF16) 可用于对照。

如果到现在还不明显的话：我在 NVIDIA 工作，因此得以在 Bolt E4B 公开发布之前进行测试，发现它是一个扎实的选择，占用的体积比其他先行者——Qwen3 30B-A3B 和 Qwen 3.6 35B-A3B——更小。

它能在 Nemotron Voice Agent 的流水线里正常工作，把来访者说的话变成下一句足够不情不愿的回复。

对话底座由 Bolt 提供。我的 prompt、应用逻辑，以及用数千条人工审校过的示例对话训练出来的 LoRA adapter，把它塑成了这艘特定的犟船。

构建一个 5,000 多轮对话的数据集，意味着我能给每个我觉得有资格入围的模型训练 LoRA。有的大约一小时训完，有的要几个小时。一个本地 agent 跑完全部流程并对结果做基准测试。而最初创建并评判这个数据集的，是那个 agent 加一个非常大的 LLM。这些都是在夜里或者我干正职工作的同时完成的。

挂上 LoRA 之后，我会检查回复的连贯性、节奏和语气，就质量、重复率和速度对模型和 adapter 做基准，然后现场听表演。这房子应该最终让步，但不能变成一位笑呵呵的门房。一点抵抗正是它的魅力所在。没完没了地和车库门吵架就不是了。

### **值得一等的声音**

[![image](https://cdn-uploads.huggingface.co/production/uploads/6ab2a746c7d0655b3d8dfbb9/iVLQ71tHCdvLRIuaJ6oLk.png)](https://cdn-uploads.huggingface.co/production/uploads/6ab2a746c7d0655b3d8dfbb9/iVLQ71tHCdvLRIuaJ6oLk.png)*两条捷径，两种输出。预先写好的文本跳过了实时对白生成，缓存的音频跳过了合成。驱动动画的干净语音与放给观众的效果声是分开的。*

鬼屋要是抱怨得太慢，就没了威信。流水线会在整句回答写完之前就先放出可开口的文本，于是房子能先开口说话，后半句还在路上。预先准备好的问候语和糖果段子覆盖常见遭遇：文本库省下语言模型的算力，缓存录音省下语音合成。哪怕一位上了年纪的暴躁鬼，也从排练中受益。

```
median end-of-speech-to-audio with Bolt Q4 & TTS = 1.70 seconds
median end-of-speech-to-audio cached responses = 0.72 seconds
(note: speech-end detection currently waits for 300 ms of silence )
```

[NVIDIA Magpie TTS Zeroshot](https://build.nvidia.com/nvidia/magpie-tts-zeroshot) 把文本变成女王的英语。它的零样本声音克隆用的是一小段参考样本而不是训练好的音色；我供的那一段就是这位暴躁海盗。这个房子有七种情绪，从暴躁、阴森到觉得有趣、开心，由 prompt 模板指定、LLM 提供的 emotion tag 决定每句台词怎么念。由于每种情绪都需要一段不同的 3-10 秒声音样本，我在 UI 的工具页里加了一块「Sample your Voice」。我可以拿着我最好的快乐海盗腔或愤怒海盗腔，照着台词录一段样本。到了「开演」时刻，Bolt E4B 决定说什么，Magpie 再把那段文本变成带着恰如其分的欢欣或绝望的语音。

流水线上的下一站是 [Audio2Face-3D](https://github.com/NVIDIA/Audio2Face-3D)，以及我在 Epic 的 Unreal Engine 里创建的 3D 角色场景。默认模型权重最适合干净、中性的男声或女声，不要太低沉，也不要太高亢（按你的用例选对应的性别模型）。我想让这房子有极低沉、恶魔般、带回声和腔体感的声音。这种情况下，因为我的声音样本没有那种剧场级的厚重，反倒是个优点：Audio2Face-3D 从样本里拿到干净语音，另一路音频流再叠加可实时调节的人声效果，从音箱里放出去。

为了让一切流畅运行，我把活儿拆到两张 GPU 上：语言模型与语音模型的流水线跑在 NVIDIA RTX PRO 6000 Blackwell Max-Q 上，Unreal Engine 的图形加 Audio2Face-3D 跑在 NVIDIA RTX PRO 4000 Blackwell 上。瓶颈不在显存，在算力。不管 agent 流水线在后台算什么，我都要把动画维持在稳定帧率。

声音、动画和特效必须一起落地。一个可信的怪物光有快回答不够，它得听起来这抱怨就是这栋房子自己在抱怨——就我这个案子，还真是它自己在抱怨。音频播出的同步微调项是有的，我发现自己设好就可以忘了。（100ms 用来补偿 Audio2Face-3D 的缓冲）

### **怪物有一张控制台**

在某个节点上，「让房子开口」变成了一整套布满控件的界面。我能试听缓存台词、调整开场情绪、跟进对话进程、更换声音处理方案、微调嘴部动画。标签页覆盖对话、模型选择、录音、prompt、性能监控和摄像头画面，还有一个打击垫和自定义对白输入框，能让我替它说话。另外还有模型加载控件和一个 Unreal Engine 连接指示灯——因为有时候怪物不是在闹脾气，是掉线了。

[![image](https://cdn-uploads.huggingface.co/production/uploads/6ab2a746c7d0655b3d8dfbb9/8AZqpHSWLOS4hpRwACGOY.png)](https://cdn-uploads.huggingface.co/production/uploads/6ab2a746c7d0655b3d8dfbb9/8AZqpHSWLOS4hpRwACGOY.png)*MonsterHouse 的控制台，带打击垫、自定义台词、开场情绪和对话流程。*

火焰与光效也入了戏。可编辑的规则把视觉提示与台词播出绑定：现场出场的提示跟着语音启动，而预录的表演可以走一条保存好的时间轴。不用重建场景，我就能指挥一次情绪切换。

Live 模式跑讨糖角色；Demo 模式说服房子自我介绍；麦克风模式让我直接借房子的嘴说话，绕开识别、对白生成和语音合成。我干净的嗓门驱动那张嘴，观众听到的是加过处理的版本。房子管这叫附身。我管这叫好用的兜底。

### **下一阵敲门声**

[NVIDIA Nemotron 3 Nano Omni](https://huggingface.co/nvidia/Nemotron-3-Nano-Omni-30B-A3B-Reasoning-BF16) 是一个 VLM，给房子补上视觉上下文。作为可选的旁观者，它解读摄像头画面、描述看得见的服装，让角色有具体的东西可反应。我不打算重造每一个轮子，于是选了流行的目标检测与跟踪模型 YOLO 和 ByteTrack 来清点并追踪画面里的人。把这两摊活儿分开，房子就能在不要求 Omni 逐帧解说的情况下注意到一群人。

为了一个配得上这份荒唐的测试，我丢给 Omni 一段门口站着五只打扮过的羊的视频。它保存下来的分析认出了海盗、吸血鬼、女巫、南瓜和幽灵的装扮。这就是我希望房子能用的那种视觉上下文。看来连牲畜的万圣节计划都比我讲究。

[![image](https://cdn-uploads.huggingface.co/production/uploads/6ab2a746c7d0655b3d8dfbb9/v5ff_abLrivfqmxH5ZPqf.png)](https://cdn-uploads.huggingface.co/production/uploads/6ab2a746c7d0655b3d8dfbb9/v5ff_abLrivfqmxH5ZPqf.png)*一场合成测试回放里五只毛茸茸得很认真的讨糖羊。服装标签来自保存的 Omni 分析；检测框与跟踪 ID 仅用于示意。*

这几只羊是合成测试，不是万圣节之夜成功的证据。真实车道上的人群、服装和夜间光线仍待检验。检测确实会触发自动问候，但我担心时髦服装的识别和配得上它的俏皮回怼还得再训练一番。既然这房子没有眼睛，它就把自己的访客感知称为回声定位。这一条我依它。

还有更多事要做：动画总能更好，完整性能测试需要真访客，而总有一天糖果会自动发放。我还没实现最初的目标——让它自己主持万圣节，我带家人出门去看社区里其他的妖魔鬼怪。但那依然是这一切的意义。总有一天，一个孩子会遇见一座暴躁的老房子，试着给它一点善意，然后发现这堆老木头心里有一块软的地方。而且它真的发糖棒。

### **搭一个你自己的不讲理角色**

MonsterHouse 的代码本身没有打包发布，但它用到的每个 NVIDIA 模型今天都拿得到，而 NVIDIA Nemotron Voice Agent 能带你走完大半路程。我会走的就是这条路。

> 从语音流水线开始。克隆 NVIDIA Nemotron Voice Agent，跑通 Generic Assistant 示例。你会得到一条级联流水线：Nemotron Speech ASR、一个 LLM 加 Magpie TTS，还带语音活动检测与句尾处理，你的角色由此知道什么时候该开口。  
> 把 Bolt E4B 当大脑。Voice Agent 内置 Bolt E4B 的云端、服务器和单 GPU 部署配置文件。你可以先在 build.nvidia.com 上试模型。短而适合朗读的回复用 conversational 模式，更简单的交互可以关掉 reasoning。  
> 给它人格。从一份 system prompt 和几段连贯的示例对话开始。对话状态——比如谁已经说过 please——保持在你的应用里，而不是要求模型自己记住。当 prompt 不够用时，训练一个 LoRA adapter；NVIDIA NeMo AutoModel 有针对 Bolt E4B 的 LoRA recipe。  
> 给它声音。Magpie TTS Multilingual 是 Voice Agent 的默认选项。定制角色则用 Magpie TTS Zeroshot，它凭一段短参考样本工作。可以在 build.nvidia.com 上试用，并申请访问以自行运行。[CONFIRM: access path and link] 只使用你有权使用的声音。  
> 给它脸。NVIDIA Audio2Face-3D 把语音变成你角色的面部动画。喂给它干净的语音，效果之后再叠。  
> 可选：给它眼睛。Voice Agent 的 Nemotron Omni Assistant Subagents 示例用 Nemotron 3 Nano Omni 加入了实时的摄像头理解。若需要人数，再配一个轻量的人头跟踪器。

> 一个缓存回复库加上常用台词的录音，能让再慢的怪物也显得反应很快。事实上，如果你的算力当真是紧的，完全没理由不做这样一个 Live 版本：只用 Nemotron 3 ASR、一个 python 对话路由器，全部音频走缓存。你可以用 Bolt E4B 和 Magpie 的流水线离线生成成百上千条回复，演出时全用缓存。我打算给那些互动南瓜就这么干。
