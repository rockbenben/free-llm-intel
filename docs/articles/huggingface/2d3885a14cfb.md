## 太长不看版

开源 LLM 如今已达到的性能水平，使其足以作为驱动智能体工作流的推理引擎：在我们的基准上，[Mixtral](https://huggingface.co/blog/mixtral) 甚至[超过了 GPT-3.5](https://huggingface.co/blog/open-source-llms-as-agents#results)，而且它的性能还能通过微调轻松进一步提升。

> 可在[这里](https://huggingface.co/blog/smolagents)查看 smolagents 介绍博客。

## 引言

为[因果语言建模](https://huggingface.co/docs/transformers/tasks/language_modeling)训练的大语言模型（LLM）能处理广泛的任务，但它们在逻辑、计算和搜索这类基础任务上常常吃力。最糟的情形是，模型在某个领域（如数学）表现很差，却仍试图自己处理所有计算。

要克服这一弱点，除其他方法之外，一种做法是把 LLM 集成到一个能够调用工具的系统里：这样的系统就叫 LLM 智能体。

在本文里，我们会解释 ReAct 智能体的内部运作，然后演示如何用最近集成进 LangChain 的 `ChatHuggingFace` 类来构建它们。最后，我们在若干开源 LLM 与 GPT-3.5、GPT-4 之间做基准对比。

## 什么是智能体？

LLM 智能体的定义相当宽泛：凡是以 LLM 作为引擎、并能基于观测对其环境执行动作的系统，都是 LLM 智能体。它们可以用多轮 感知 ⇒ 反思 ⇒ 行动 的循环来完成任务，并常常辅以规划或知识管理系统来提升性能。你可以在 [Xi et al., 2023](https://huggingface.co/papers/2309.07864) 中找到对智能体领域很好的综述。

今天我们把重点放在 **ReAct 智能体**上。[ReAct](https://huggingface.co/papers/2210.03629) 是一种构建智能体的方法，名字来自两个词的组合："**Reasoning**（推理）" 和 "**Acting**（行动）"。在提示词里，我们描述模型、说明它能用哪些工具，并要求它"一步一步"地思考（也叫 [Chain-of-Thought](https://huggingface.co/papers/2201.11903) 行为），来规划并执行它的下一步动作，以得到最终答案。

![drawing](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/open-source-llms-as-agents/ReAct.png)

### ReAct 智能体内部运作的玩具示例

上面的图看起来很高屋建瓴，但底层其实很简单。

看看[这个 notebook](https://colab.research.google.com/drive/1j_vsc28FwZEDocDxVxWJ6Fvxd18FK8Gl?usp=sharing)：我们用 Transformers 库实现了一个简陋的工具调用示例。

LLM 在一个循环里被调用，提示词本质上包含：

```
Here is a question: "{question}" 
You have access to these tools: {tools_descriptions}. 
You should first reflect with ‘Thought: {your_thoughts}’, then you either:
- call a tool with the proper JSON formatting,
- or your print your final answer starting with the prefix ‘Final Answer:’
```

然后你解析 LLM 的输出：

- 如果它含有字符串 `‘Final Answer:’`，循环结束，你打印答案，
- 否则，LLM 应当输出了一个工具调用：你可以解析这个输出来得到工具名和参数，然后用那些参数调用该工具。随后把这个工具调用的输出追加到提示词里，你带着这些扩展信息再次调用 LLM，直到它拥有足够信息、最终给出对问题的回答。

例如，当回答这个问题时：`How many seconds are in 1:23:45?`，LLM 的输出可能长这样：

```
Thought: I need to convert the time string into seconds.

Action:
{
    "action": "convert_time",
    "action_input": {
    "time": "1:23:45"
    }
}
```

由于这个输出不含字符串 `‘Final Answer:’`，它是在调用一个工具：于是我们解析这个输出、得到工具调用参数：调用工具 `convert_time`，参数为 `{"time": "1:23:45"}`。运行这个工具调用返回 `{'seconds': '5025'}`。

于是我们把整块内容追加到提示词。

新提示词现在是（一个稍加完善的版本）：

```
Here is a question: "How many seconds are in 1:23:45?"
You have access to these tools:
    - convert_time: converts a time given in hours:minutes:seconds into seconds.

You should first reflect with ‘Thought: {your_thoughts}’, then you either:
- call a tool with the proper JSON formatting,
- or your print your final answer starting with the prefix ‘Final Answer:’

Thought: I need to convert the time string into seconds.

Action:
{
    "action": "convert_time",
    "action_input": {
    "time": "1:23:45"
    }
}
Observation: {'seconds': '5025'}
```

➡️ 我们带着这个新提示词再次调用 LLM。由于它能在 `Observation` 里访问到工具调用的结果，LLM 现在最可能输出：

```
Thought: I now have the information needed to answer the question.
Final Answer: There are 5025 seconds in 1:23:45.
```

任务就此解决！

### 智能体系统的挑战

通常，对 LLM 引擎而言运行一个智能体系统的难点在于：

- 从提供的工具里，挑选能助力达成目标的那一个：例如当被问 `"What is the smallest prime number greater than 30,000?"` 时，智能体可能用 `"What is the height of K2"` 去调用 `Search` 工具，但这毫无帮助。
- 以严格的参数格式调用工具：例如要计算一辆车 10 分钟行驶 3 公里的速度，你必须调用 `Calculator` 工具用 `distance` 除以 `time`：即便你的 Calculator 工具接受 JSON 格式调用 `{”tool”: “Calculator”, “args”: “3km/10min”}`，也有许多坑，比如：工具名拼写错误：`“calculator”` 或 `“Compute”` 都不行；给的是参数名而非值：`“args”: “distance/time”`；格式不标准：`“args": "3km in 10minutes”`
- 高效地吸收并使用过去观测中收集到的信息，无论是初始上下文还是工具使用后返回的观测。

那么，一个完整的智能体配置应该是什么样的？

## 用 LangChain 运行智能体

我们刚刚在 [🦜🔗LangChain](https://www.langchain.com/) 中集成了 `ChatHuggingFace` 包装器，让你能基于开源模型创建智能体。

创建 ChatModel 并给它工具的代码非常简单，你可以在 [Langchain 文档](https://python.langchain.com/docs/integrations/chat/huggingface) 里查看全部内容。

```
from langchain_community.llms import HuggingFaceEndpoint
from langchain_community.chat_models.huggingface import ChatHuggingFace

llm = HuggingFaceEndpoint(repo_id="HuggingFaceH4/zephyr-7b-beta")

chat_model = ChatHuggingFace(llm=llm)
```

你可以给 `chat_model` 一个 ReAct 风格的提示词和工具，把它变成智能体：

```
from langchain import hub
from langchain.agents import AgentExecutor, load_tools
from langchain.agents.format_scratchpad import format_log_to_str
from langchain.agents.output_parsers import (
    ReActJsonSingleInputOutputParser,
)
from langchain.tools.render import render_text_description
from langchain_community.utilities import SerpAPIWrapper

# setup tools
tools = load_tools(["serpapi", "llm-math"], llm=llm)

# setup ReAct style prompt
prompt = hub.pull("hwchase17/react-json")
prompt = prompt.partial(
    tools=render_text_description(tools),
    tool_names=", ".join([t.name for t in tools]),
)

# define the agent
chat_model_with_stop = chat_model.bind(stop=["\nObservation"])
agent = (
    {
        "input": lambda x: x["input"],
        "agent_scratchpad": lambda x: format_log_to_str(x["intermediate_steps"]),
    }
    | prompt
    | chat_model_with_stop
    | ReActJsonSingleInputOutputParser()
)

# instantiate AgentExecutor
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

agent_executor.invoke(
    {
        "input": "Who is the current holder of the speed skating world record on 500 meters? What is her current age raised to the 0.43 power?"
    }
)
```

智能体会处理输入：

```
Thought: To answer this question, I need to find age of the current speedskating world record holder.  I will use the search tool to find this information.
Action:
{
    "action": "search",
    "action_input": "speed skating world record holder 500m age"
}
Observation: ...
```

## 智能体对决：开源 LLM 作为通用推理智能体表现如何？

你可以在[这里](https://github.com/aymeric-roucher/benchmark_agents/)找到这个基准的代码。

### 评估

我们想衡量开源 LLM 作为通用推理智能体的表现。因此我们选取那些需要使用逻辑和基本工具的问题：一个计算器和一次互联网搜索。[最终数据集](https://huggingface.co/datasets/m-ric/agents_small_benchmark) 是另外 3 个数据集样本的组合：

- 为测试互联网搜索能力，我们从 [HotpotQA](https://huggingface.co/datasets/hotpot_qa) 中选取了问题：这原本是一个检索数据集，但也可用于带互联网访问的通用问答。一些问题原本需要结合来自多个来源的信息：在我们的设置里，这意味着要做多步互联网搜索以组合结果。
- 为测试计算器使用，我们加入了 [GSM8K](https://huggingface.co/datasets/gsm8k) 的问题：这个数据集测试小学数学能力，完全可以通过正确使用 4 个运算符（加、减、乘、除）来求解。
- 我们还从 [GAIA](https://huggingface.co/papers/2311.12983) 中挑选了问题，这是一个针对通用 AI 助手的非常难的基准。原始数据集里的问题可能需要许多其他工具，比如代码解释器或 pdf 阅读器：我们手工挑选了那些除搜索和计算器外不需要其他工具的问题。

评估用 GPT-4-as-a-judge 进行，提示词基于 [Prometheus 提示格式](https://huggingface.co/kaist-ai/prometheus-13b-v1.0)，在 5 级 Likert 量表上给出结果：准确提示词见[这里](https://github.com/aymeric-roucher/benchmark_agents/blob/master/scripts/prompts.py)。

### 模型

我们评估了几个强大的开源模型：

- [Llama2-70b-chat](https://huggingface.co/meta-llama/Llama-2-70b-chat-hf)
- [Mixtral-8x7B-Instruct-v0.1](https://huggingface.co/mistralai/Mixtral-8x7B-Instruct-v0.1)
- [OpenHermes-2.5-Mistral-7B](https://huggingface.co/teknium/OpenHermes-2.5-Mistral-7B)
- [Zephyr-7b-beta](https://huggingface.co/HuggingFaceH4/zephyr-7b-beta)
- [SOLAR-10.7B-Instruct-v1.0](https://huggingface.co/upstage/SOLAR-10.7B-Instruct-v1.0)

这些模型在 LangChain 的 [ReAct 实现](https://github.com/langchain-ai/langchain/tree/021b0484a8d9e8cf0c84bc164fb904202b9e4736/libs/langchain/langchain/agents/react) 中被评估。这意味着我们提示它们按这种格式输出函数调用：

```
{
  "action": $TOOL_NAME,
  "action_input": $INPUT
}
```

作为对比，我们也用 LangChain 的 [OpenAI 专属智能体](https://github.com/langchain-ai/langchain/tree/021b0484a8d9e8cf0c84bc164fb904202b9e4736/libs/langchain/langchain/agents/openai_functions_agent) 在相同样本上评估了 GPT-3.5 和 GPT-4。由于这使用了它们自己的、被微调过的函数调用模板，OpenAI 模型应处于其巅峰性能。

### 结果

由于开源模型没有专门为按给定输出格式调用函数而微调，相较 OpenAI 智能体它们略有劣势。

尽管如此，有些模型表现得非常好！💪

下面是 Mixtral-8x7B 回答这个问题 `“Which city has a larger population, Guiyang or Tacheng?”` 的一个例子：

```
Thought: To answer this question, I need to find the current populations of both Guiyang and Tacheng. I will use the search tool to find this information.
Action:
{
    "action": "search",
    "action_input": "current population of Guiyang"
}
4.697 million (2016)

Thought: I have obtained the population of Guiyang, which is 4.697 million (as of 2016). Now, I will use the search tool again to find the population of Tacheng.
Action:
{
    "action": "search",
    "action_input": "current population of Tacheng"
}
Population: Xinjiang: Tacheng data was reported at 1,110.000 Persons in 2021. This records a decrease from the previous number of 1,138.638 Persons for 2020.
Population: Xinjiang: Tacheng data is updated yearly, averaging 1,023.000 Persons from Dec 2005 to 2021, with 17 observations.

I have obtained the population of Tacheng, which is approximately 1.11 million (as of 2021). Comparing the two populations, Guiyang has a larger population than Tacheng.

Thought: I now know the final answer
Final Answer: Guiyang has a larger population, which is approximately 4.697 million (as of 2016), compared to Tacheng's population of approximately 1.11 million (as of 2021).
```

下面是模型在我们评估数据集上的基准（原本 1-5 级的平均分已转换为 0-100% 量表以便阅读）：

![benchmark of agents performance](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/open-source-llms-as-agents/benchmark_agents.png)

如你所见，一些开源模型在为智能体工作流提供动力上表现不佳：虽然小尺寸的 Zephyr-7b 本就预期如此，但 Llama2-70b 表现得出人意料地差。

👉 但 **Mixtral-8x7B 表现得非常好：它甚至胜过了 GPT-3.5！** 🏆

而且这是开箱即用的性能：***与 GPT-3.5 不同，Mixtral 并未针对智能体工作流做过微调***（据我们所知），这多少抑制了它的性能。例如在 GAIA 上，有 10% 的问题失败，是因为 Mixtral 试图用格式错误的参数调用工具。**若对函数调用和任务规划技能做恰当微调，Mixtral 的分数很可能更高。**

➡️ 我们强烈建议开源构建者开始为智能体微调 Mixtral，以超越下一个挑战者：GPT-4！🚀

**结语：**

- GAIA 基准，尽管这里只在一个小的问题子样本和几个工具上尝试，对于智能体工作流的整体模型性能似乎是一个非常稳健的指标，因为它通常涉及多个推理步骤和严谨的逻辑。
- 智能体工作流让 LLM 能够提升性能：例如在 GSM8K 上，[GPT-4 技术报告](https://arxiv.org/pdf/2303.08774.pdf) 报告 5-shot CoT 提示为 92%：给它一个计算器让我们零样本就能达到 95%。对 Mixtral-8x7B，[LLM Leaderboard](https://huggingface.co/spaces/HuggingFaceH4/open_llm_leaderboard) 报告 5-shot 为 57.6%，而我们零样本得到 73%。*（请记住我们只测试了 GSM8K 的 20 个问题）*
