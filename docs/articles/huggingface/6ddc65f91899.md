# BigCodeArena：用代码执行对代码生成进行端到端评判

评估 AI 生成代码的质量是出了名的难。人类可以很容易地看出代码"长得对不对"，但要判断它是否真的能正确运行、是否正确处理边界情况、是否产出预期结果，就必须实际运行和测试它。这就是为什么今天我们要兴奋地宣布 **BigCodeArena**——首个通过执行来评估代码生成模型的人在回路（human-in-the-loop）平台。

我们借鉴了面向 LLM 的 LMArena，搭建了一个让任何人都能并排比较代码生成模型的平台，但有一个关键区别：**你可以真的运行代码并看到它的产出**。只需提交一个编程任务，看两个不同的模型分别生成解法，执行这两个程序，然后投票选出哪个模型的结果更好。投票结果会被汇总到排行榜上，展示社区评分最高的模型。

## 动机

代码生成领域长期受困于可靠的评估方法。HumanEval 这类传统基准用预定义测试用例检验代码，但这些用例只占真实编程任务的一小部分。通用聊天机器人有人工评估平台，但用在代码上并不称职：阅读原始源代码并在脑海中模拟其执行，在认知上既吃力又易错，对较长的程序或复杂的 UI 应用尤其如此。

设想这个场景：

> 你让两个 AI 模型构建一个响应式照片画廊网站。两者生成的代码看起来语法都没问题。但哪个真的更好？不运行代码几乎无从判断。一个可能产出漂亮且功能完好的网格布局，另一个可能带着只有在浏览器里渲染出来才会暴露的隐蔽 bug 或糟糕的样式。

[![bigcodearena-demo](https://cdn-uploads.huggingface.co/production/uploads/62b7fb545233925f253531c8/SspOHYTm-BT-zIlIV3Rdg.png)](https://cdn-uploads.huggingface.co/production/uploads/62b7fb545233925f253531c8/SspOHYTm-BT-zIlIV3Rdg.png)

这个观察让我们得出一个关键洞见：**要让人可靠地评判代码质量，执行反馈必不可少。**这正是 BigCodeArena 所提供的。

## BigCodeArena 平台

BigCodeArena 在 Chatbot Arena 框架之上扩展出专为代码评估设计的强大功能：

### 实时执行

模型生成的每一段代码都会自动在隔离的沙箱环境中执行。无论是 Python 脚本、React 网页应用、PyGame 游戏还是 C++ 算法，你看到的是真实的输出，而不只是源代码。

### 多语言与多框架支持

我们目前支持 10 种语言（Python、JavaScript、TypeScript、HTML、C、C++、Java、Go、Rust 和 Markdown）以及 8 种执行环境：

- **Web 框架**：React、Vue、Core Web（原生 HTML/CSS/JS）
- **Python 框架**：Streamlit、Gradio、PyGame
- **图表**：Mermaid
- **通用解释器**：Python 和 JavaScript 代码解释器，以及编译语言运行器

### 交互式测试

不同于静态的代码对比，你可以真正与生成的应用交互：

- 在网页应用中点击按钮、测试 UI 元素
- 玩模型生成的游戏
- 编辑代码并重新运行，测试修改效果
- 查看图表、曲线图、示意图等可视化输出

[![bigcodearena](https://cdn-uploads.huggingface.co/production/uploads/62b7fb545233925f253531c8/2AvLXvIP1VE1moRw9BHS_.png)](https://cdn-uploads.huggingface.co/production/uploads/62b7fb545233925f253531c8/2AvLXvIP1VE1moRw9BHS_.png)

### 多轮对话

真实的编程不是一锤子买卖。BigCodeArena 支持多轮交互，你可以细化需求、要求添加功能或请求修复 bug——就像和真正的编程助手协作一样。

## 我们学到了什么：5 个月的社区评估

自 2025 年 2 月上线以来，BigCodeArena 已收集来自 500 多位用户的 **14,000 多场对话**，其中有 **4,700+ 条高质量偏好投票**，对比了 10 个前沿 LLM。

### 真实世界中的编程话题

我们的用户探索了极为多样的编码场景：

- **Web 设计（36%）**：构建响应式网站、交互式仪表盘和 Web 应用
- **问题求解（23%）**：算法、数据结构和计算挑战
- **游戏开发（16%）**：创建带物理、碰撞检测和图形的交互游戏
- **科学计算（14%）**：数据分析、可视化和数值模拟
- **创意编程（8%）**：艺术化可视化、生成艺术和实验性界面
- **图表绘制（3%）**：流程图、系统架构图和数据可视化

### 语言与框架热度

Python 以 4,000 多场对话遥遥领先，其次是 JavaScript/TypeScript（3,359）、HTML（1,601）和 C++（642）。框架方面，直接的 Python 解释器使用最多（6,000 个会话），React（2,729）、Core Web（1,574）、Streamlit（1,254）和 PyGame（1,087）也被大量使用。

### 用户交互模式

大多数交互集中而高效：76% 的对话只有 2 轮（一次请求、一次回复），对话平均长度为 4.12 条消息。不过，需要时平台也支持延长的多轮调试会话，部分对话在一些用户打磨复杂应用时超过了 10 轮。

### 来自社区投票的模型排名

我们从 1.4 万场对话中筛选出高质量的两两比较：至少两轮且实际执行了代码的对话。最终得到 **4,731 个投票样本**，每个被评估模型至少获得 700 票。我们使用 Bradley-Terry 模型把这些投票聚合成 **Elo 等级分**，该模型基于直接对战比较估计一个模型战胜另一个模型的概率。

为保证排名稳健，我们用 100 次 bootstrap 重采样构造 95% 置信区间，从而识别模型间具有统计显著性的性能差异。

[![elo_ratings_comparison_page-0001](https://cdn-uploads.huggingface.co/production/uploads/62b7fb545233925f253531c8/rEnROVN53CxyMHsLh223J.jpeg)](https://cdn-uploads.huggingface.co/production/uploads/62b7fb545233925f253531c8/rEnROVN53CxyMHsLh223J.jpeg)

我们在三种设定下评估模型，以控制不同因素：

- **All Data（全部数据）**：使用所有两两比较，不区分执行环境或编程语言
- **Environment Matched（环境匹配）**：仅比较两个模型在同一沙箱中执行时的数据（例如都在 React 或都在 PyGame 中）
- **Language Matched（语言匹配）**：在此基础上进一步限定为同一编程语言

三种设定下的排名出人意料地一致，揭示了清晰的性能梯队：

**第一梯队**：**o3-mini** 和 **o1-mini**  consistently 以最高 Elo 分和紧凑的置信区间领跑。无论环境和语言如何限制，这些模型都保持顶尖表现，在各类编码场景中展现出很强的鲁棒性。**Claude-3.5-Sonnet** 紧随其后，在固定语言变量时表现尤为突出。

**中间梯队**：**GPT-4o**、**o1** 和 **Gemini-2.0-Pro/Flash** 组成竞争激烈中间梯队。GPT-4o 对语言匹配表现出一定敏感性，说明其多语言一致性还有提升空间。

**开源模型**：**Qwen2.5** 各变体和 **Llama-3.3-70B** 落后于前沿闭源模型，凸显领先的闭源与开源模型之间仍存在的性能差距。

[![combined_performance_heatmaps_page-0001](https://cdn-uploads.huggingface.co/production/uploads/62b7fb545233925f253531c8/5iB4XRwOBzjEdQM5tqVoU.jpeg)](https://cdn-uploads.huggingface.co/production/uploads/62b7fb545233925f253531c8/5iB4XRwOBzjEdQM5tqVoU.jpeg)

*图：各模型在跨语言（*左*）和跨执行环境（*右*）会话中的总体胜率热力图（赢下的两两比较占比）。对每个类别，我们只保留至少出现在 3 场会话中的模型。*

#### 跨语言性能

按编程语言细分性能可以揭示一些有趣的模式：

- **o3-mini**、**o1-mini** 等顶级模型在 Python、Java、C++ 等主流语言中取得压倒性胜率
- **Gemini-2.0-Pro** 在 Rust 上表现尤为强势，拿下该类别最高胜率
- 不同模型展现出各自不同的专长领域，前沿模型各占一方山头
- Qwen2.5 变体等开源模型表现不稳定，在 Rust 和 Go 上尤其吃力

#### 跨执行环境性能

按执行环境分析胜率，可以看出模型如何处理不同的运行时上下文：

**稳健选手**：**o3-mini** 在 React、Streamlit、Gradio、Core Web 和 PyGame 上都保持一贯的强劲表现，展现出出色的环境适应力。

**稳定但挑环境**：**Claude-3.5-Sonnet** 和 **Gemini-2.0-Flash** 整体表现稳定，但在 Vue、Mermaid 这类复杂、重 UI 的环境中胜率下滑。

**框架特定短板**：**Qwen2.5** 模型虽然在某些 Web 框架（Core Web、React）中有竞争力，但在 PyGame、Vue、Mermaid 这类交互与可视化导向的环境中明显吃力。这些环境往往需要对控制流、图形渲染和包依赖进行精确处理。

这些结果突出了一个重要洞见：**聚合的 Elo 分数并不能说明全部**。有些模型在特定运行时约束下仍然脆弱，而对真实部署来说，执行环境非常关键。

## 两个新基准：BigCodeReward 与 AutoCodeArena

为了把研究推进到众包评估之外，我们发布两个互补的基准：

### BigCodeReward：评估面向代码的奖励模型

基于我们 4,700+ 条偏好投票，BigCodeReward 检验 LLM 作为奖励模型（reward model）评判代码质量的能力。关键发现？**执行结果能大幅提升判断准确率。**

当模型能看到执行输出（网页应用截图、游戏画面、程序日志）时，其与人类偏好的一致程度显著提高：

- Claude-Sonnet-4：准确率 **56.7% → 62.3%**
- GPT-4o：准确率 **54.6% → 63.8%**
- Qwen2.5-VL-72B：准确率 **58.7% → 66.2%**

这印证了我们的核心论点：不运行代码就无法可靠地评判它——对人和 AI 裁判都一样。

### AutoCodeArena：自动化的代码生成基准

受 Arena-Hard-Auto 启发，AutoCodeArena 提供了一种可扩展的方式来评估新模型，而无需等待数千张人工投票。我们从众包数据中精心挑选了 600 条具有代表性的提示词，覆盖全部编程话题和框架。

通过使用自动化 LLM 裁判（Claude-3.7-Sonnet）将代码执行结果与 GPT-4.1 基线对比评估，我们可以快速对新模型做基准测试。这种方式让排行榜能够随新模型发布做到每周更新。

我们的自动化基准评估了 20 多个前沿模型，包括最新发布的一些系统：

**表现最佳者：**

- **GPT-5** —— 以显著优势确立新的 SOTA（最先进水平）
- **Claude-Opus-4** 和 **Claude-Sonnet-4** —— 强劲的第二梯队，在重推理任务上表现出色
- **Qwen3-Coder**、**Kimi-K2**、**GLM-4.5** —— 领先的开源模型，正在缩小与中游闭源系统的差距

[![overall_performance](https://cdn-uploads.huggingface.co/production/uploads/62b7fb545233925f253531c8/NzyobCl-pYwgR-6ggufMe.jpeg)](https://cdn-uploads.huggingface.co/production/uploads/62b7fb545233925f253531c8/NzyobCl-pYwgR-6ggufMe.jpeg)

*图：在 AutoCodeArena 上，由 Claude-3.7-Sonnet 裁判评出的近期 LLM 相对 GPT-4.1 基线的胜率。50% 线代表与 GPT-4.1 打平；线上方的模型优于基线，下方则不及基线。误差线为 95% 置信区间。注：为避免自评偏差，Claude-3.7-Sonnet 未参与排名；GPT-4.1 仅作为参照基线出现。*

结果显示，虽然闭源模型仍占优势，但开源模型正在迅速追赶，部分已逼近 GPT-4.1 级别的性能。

## 亲自试一试

BigCodeArena 向所有人开放——无需注册账号！访问 [https://huggingface.co/spaces/bigcode/arena](https://huggingface.co/spaces/bigcode/arena) 即可：

- 对比更新的前沿 LLM 生成的代码（例如 Qwen3、DeepSeek-V3.X 及其他闭源模型）
- 测试网页应用、游戏、可视化和算法
- 查看真实的执行结果，而不只是源代码
- 为你喜欢的方案投票，帮助完善排行榜
- 探索多轮编码对话

无论你在构建 React 仪表盘、制作 PyGame 游戏、解算法题，还是生成创意可视化，BigCodeArena 都能让你看到哪些模型真正能交付。

## 接下来做什么？

我们把 BigCodeArena 视为一个与社区共同演进的长期项目：

- **扩展语言支持**：更多的编程语言和框架。
- **实时基准**：持续更新的评估提示词，防止过拟合
- **基于智能体的评估**：用 AI 智能体（agent）与网页应用交互，做更深入测试
- **更好的奖励模型**：推进自动化的代码质量评估
- **社区贡献**：我们欢迎新的执行环境、评估标准和模型加入，随时欢迎 [PR](https://huggingface.co/spaces/bigcode/arena/discussions?new_pr=true)！

## 结语

评估代码不像评估文本——你得运行它、测试它、与它交互。BigCodeArena 让这件事得以规模化，把人类判断与真实执行反馈结合起来，打造代码生成模型最可靠的评估平台。

加入我们一起建设代码生成评估的未来。写一个提示词，对比模型，投给你最喜欢的那个。你的反馈在帮助整个社区理解：哪些模型真正兑现了 AI 辅助编程的承诺。
