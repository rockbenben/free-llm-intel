# 推出 Modular Diffusers——扩散管线的可组合构建块

YiYi Xu（YiYiXu）、Alvaro Somoza（OzzyGT）、Dhruv Nair（dn6）、Sayak Paul（sayakpaul）

Modular Diffusers 引入了一种构建扩散 pipeline 的新方式——通过组合可复用的块（block）。你不必从零写出整条 pipeline，而是可以自由搭配各种块，拼出量身定制的工作流！它用一个更灵活、可组合的替代方案，补强了现有的 `DiffusionPipeline` 类。

在本文里，我们会走一遍 Modular Diffusers 如何工作——从运行一条模块化 pipeline 的熟悉 API，到构建完全自定义的块并把它们组合成你自己的流程。我们还会展示它如何与 Mellon 集成，那是一个基于节点（node-based）的可视化工作流界面，你可以用它把 Modular Diffusers 的块连到一起。

## 快速上手

下面是一个用预构建块对 `FLUX.2 Klein 4B` 跑推理的简单示例：

```
import torch
from diffusers import ModularPipeline

# Create a modular pipeline - this only defines the workflow, model weights have not been loaded yet
pipe = ModularPipeline.from_pretrained(
    "black-forest-labs/FLUX.2-klein-4B"
)
#  Now load the model weights — configure dtype, quantization, etc in this step
pipe.load_components(torch_dtype=torch.bfloat16)
pipe.to("cuda")

# Generate an image - API remains the same as DiffusionPipeline
image = pipe(
    prompt="a serene landscape at sunset",
    num_inference_steps=4,
).images[0]

image.save("output.png")
```

你会得到和标准 `DiffusionPipeline` 一样的结果，但它底层截然不同：它由灵活的*块*组成——文本编码、图像编码、去噪和解码——你可以直接检视它们：

```
print(pipe.blocks)
```

```
Flux2KleinAutoBlocks(
  ...
  Sub-Blocks:
    [0] text_encoder (Flux2KleinTextEncoderStep)
    [1] vae_encoder (Flux2KleinAutoVaeEncoderStep)
    [2] denoise (Flux2KleinCoreDenoiseStep)
    [3] decode (Flux2DecodeStep)
)
```

每个块都是自包含的，有自己的输入和输出。你可以把任意一个块作为独立 pipeline 来运行，也可以自由地增、删、换块——它们会动态地重新组合，与剩下的任何块配合工作。用 `.init_pipeline()` 把块转换为可运行的 pipeline，用 `.load_components()` 加载模型权重。

```
# get a copy of the blocks
blocks = pipe.blocks

# pop out the text_encoder block
text_blocks = blocks.sub_blocks.pop("text_encoder")

# run it as its own pipeline
text_pipe = text_blocks.init_pipeline("black-forest-labs/FLUX.2-klein-4B")

# load the text_encoder, or reuse already loaded components: text_pipe.update_components(text_encoder=pipe.text_encoder)
text_pipe.load_components(torch_dtype=torch.bfloat16)
text_pipe.to("cuda")
prompt_embeds = text_pipe(prompt="a serene landscape at sunset").prompt_embeds

# create a new pipeline from the remaining blocks
# it now accepts prompt_embeds directly instead of prompt
remaining_pipe = blocks.init_pipeline("black-forest-labs/FLUX.2-klein-4B")
remaining_pipe.load_components(torch_dtype=torch.bfloat16)
remaining_pipe.to("cuda")
image = remaining_pipe(prompt_embeds=prompt_embeds, num_inference_steps=4).images[0]
```

关于块类型、组合模式、懒加载，以及用 `ComponentsManager` 做内存管理的更多内容，请查看 [Modular Diffusers 文档](https://huggingface.co/docs/diffusers/en/modular_diffusers/overview)。

## 自定义块

在创建自己的块时，Modular Diffusers 才真正大放异彩。一个自定义块是一个 Python 类，定义它的组件、输入、输出和计算逻辑——一旦定义好，你就能把它插进任何工作流。

### 编写一个自定义块

下面是一个用 [Depth Anything V2](https://huggingface.co/depth-anything/Depth-Anything-V2-Large) 从图像中提取深度图的示例块。

```
class DepthProcessorBlock(ModularPipelineBlocks):
    @property
    def expected_components(self):
        return [
            ComponentSpec("depth_processor", DepthPreprocessor,
                          pretrained_model_name_or_path="depth-anything/Depth-Anything-V2-Large-hf")
        ]

    @property
    def inputs(self):
        return [
            InputParam("image", required=True,
                       description="Image(s) to extract depth maps from"),
        ]

    @property
    def intermediate_outputs(self):
        return [
            OutputParam("control_image", type_hint=torch.Tensor,
                        description="Depth map(s) of input image(s)"),
        ]

    @torch.no_grad()
    def __call__(self, components, state):
        block_state = self.get_block_state(state)
        depth_map = components.depth_processor(block_state.image)
        block_state.control_image = depth_map.to(block_state.device)
        self.set_block_state(state, block_state)
        return components, state
```

- `expected_components` 定义块需要哪些模型——这里是一个深度估计模型。`pretrained_model_name_or_path` 参数设置一个默认的 Hub 仓库来加载，所以 `load_components` 会自动拉取深度模型，除非你在 `modular_model_index.json` 里覆盖它。
- `inputs` 和 `intermediate_outputs` 定义进什么、出什么。
- `__call__` 是计算逻辑所在。

### 把块组合成工作流

我们把这个块用在 Qwen 的 ControlNet 工作流里。提取 ControlNet 工作流，并把深度块插在开头：

```
# Create Qwen Image pipeline
pipe = ModularPipeline.from_pretrained("Qwen/Qwen-Image")

print(pipe.blocks.available_workflows)
#       Supported workflows:
#        - `text2image`: requires `prompt`
#        - `image2image`: requires `prompt`, `image`
#        - `inpainting`: requires `prompt`, `mask_image`, `image`
#        - `controlnet_text2image`: requires `prompt`, `control_image`
#        - `controlnet_image2image`: requires `prompt`, `image`, `control_image`

# Extract the ControlNet workflow — it expects a control_image input
blocks = pipe.blocks.get_workflow("controlnet_text2image")
# Show the blocks this workflow uses
print(blocks)

# Insert depth block at the beginning — its output (control_image)
# automatically flows to the ControlNet block that needs it
blocks.sub_blocks.insert("depth", DepthProcessorBlock(), 0)

# You can inspect any block's inputs and outputs with print(blocks.doc)
blocks.sub_blocks['depth'].doc
```

序列里的块会自动共享数据：深度块的 `control_image` 输出会流向需要它的下游块，而它的 `image` 输入因为没有更早的块提供它，就变成了一个 pipeline 输入。

![blocks_composed](https://huggingface.co/datasets/diffusers/modular-diffusers-blog/resolve/main/blocks_composed.png)

```
from diffusers import ComponentsManager, AutoModel
from diffusers.utils import load_image

# ComponentsManager handles memory across multiple pipelines —
# it automatically offloads models to CPU when not in use
manager = ComponentsManager()

pipeline = blocks.init_pipeline("Qwen/Qwen-Image", components_manager=manager)
pipeline.load_components(torch_dtype=torch.bfloat16)

# The depth model loads automatically from the default path we set in expected_components —
# no need to load it manually even though it's not part of the Qwen repo.
# But controlnet is not included by default, so we do need to load it from a different repo
controlnet = AutoModel.from_pretrained("InstantX/Qwen-Image-ControlNet-Union", torch_dtype=torch.bfloat16)
pipeline.update_components(controlnet=controlnet)

# pipeline now takes image as input
image = load_image("https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/astronaut.jpg")
output = pipeline(
    prompt="an astronaut hatching from an egg, detailed, fantasy, Pixar, Disney",
    image=image,
).images[0]
```

### 在 Hub 上分享自定义块

你可以把自己的自定义块发布到 Hub，这样任何人都能用 `trust_remote_code=True` 加载它。我们做了一个[模板](https://huggingface.co/diffusers/custom-block-template)帮你起步——完整流程见[构建自定义块指南](https://huggingface.co/docs/diffusers/main/en/modular_diffusers/custom_blocks#quick-start-with-template)。

```
pipeline.save_pretrained(local_dir, repo_id="your-username/your-block-name", push_to_hub=True)
```

本文里的 `DepthProcessorBlock` 已发布在 [diffusers/depth-processor-custom-block](https://huggingface.co/diffusers/depth-processor-custom-block)——你可以直接加载并使用它：

```
from diffusers import ModularPipelineBlocks

depth_block = ModularPipelineBlocks.from_pretrained(
    "diffusers/depth-processor-custom-block", trust_remote_code=True
)
```

## 模块化仓库

`ModularPipeline.from_pretrained` 开箱即可用于任何现有的 Diffusers 仓库，但 Modular Diffusers 也引入了一种新的仓库：模块化仓库（Modular Repository）。

一个模块化仓库能够从原始的模型仓库引用组件。例如，[diffusers/flux2-bnb-4bit-modular](https://huggingface.co/diffusers/flux2-bnb-4bit-modular) 含有一个量化的 transformer，并从原始仓库加载其余组件。

```
// diffusers/flux2-bnb-4bit-modular/modular_model_index.json
{
    "transformer": [
        "diffusers", 
        "Flux2Transformer2DModel", 
        {
            "pretrained_model_name_or_path": "diffusers/flux2-bnb-4bit-modular",
            "subfolder": "transformer",
            "type_hint": ["diffusers", "Flux2Transformer2DModel"]
        }
    ],
    "vae": [
        "diffusers", 
        "AutoencoderKLFlux2", 
        {
            "pretrained_model_name_or_path": "black-forest-labs/FLUX.2-dev",
            "subfolder": "vae",
            "type_hint": ["diffusers", "AutoencoderKLFlux2"]
        }
    ],
    ...
}
```

模块化仓库还能把自定义 pipeline 块作为 Python 代码托管，并为 [Mellon](https://huggingface.co/docs/diffusers/main/en/modular_diffusers/mellon) 这类工具提供可视化 UI 配置——全在一处。

## 社区 Pipeline

社区已经开始用 Modular Diffusers 构建完整的 pipeline，并把它们连同模型权重和可运行代码发布到 Hub。

- [**Krea Realtime Video**](https://huggingface.co/krea/krea-realtime-video) —— 一个 14B 参数的实时视频生成模型，从 Wan 2.1 蒸馏而来，在单张 B200 GPU 上达到 11fps。它支持文本到视频、视频到视频，以及流式视频到视频——全都构建为模块化块。用户可以在生成过程中修改提示词、即时改换视频风格，并在 1 秒内看到首帧。

```
import torch
from diffusers import ModularPipeline

pipe = ModularPipeline.from_pretrained("krea/krea-realtime-video", trust_remote_code=True)
pipe.load_components(
    trust_remote_code=True, 
    device_map="cuda",
    torch_dtype={"default": torch.bfloat16, "vae": torch.float16}
)
```

- [**Waypoint-1**](https://huggingface.co/Overworld/Waypoint-1-Small) —— 来自 [Overworld](https://over.world) 的一个 2.3B 参数的实时扩散世界模型。它根据控制输入和文本提示自回归地生成交互式世界——你可以在消费级硬件上实时探索和与生成的环境交互。

团队可以构建新的架构、把它们打包为块，并把整条 pipeline 发布到 Hub，供任何人用 `ModularPipeline.from_pretrained` 使用。

查看完整的[社区 pipeline 合集](https://huggingface.co/collections/diffusers/modular-pipelines)以了解更多。

## 与 Mellon 的集成

> 💡 Mellon 处于早期开发阶段，尚不能用于生产。权当这是这一集成如何工作的一个预告！

[Mellon](https://github.com/cubiq/Mellon) 是一个与 Modular Diffusers 集成的节点图（node graph）界面。如果你熟悉 ComfyUI 这类基于节点的工具，你会觉得很亲切——但有一些关键区别：

- **动态节点** —— 不是几十种模型专属节点，我们有一小组节点，它们会根据你选择的模型自动调整自己的接口。学一次，就能在任何模型上用。
- **单节点工作流** —— 多亏 Modular Diffusers 的可组合块系统，你可以把整条 pipeline 折叠成一个节点。在同一画布上运行多条工作流，而不会杂乱。
- **开箱即用的 Hub 集成** —— 发布到 Hugging Face Hub 的自定义块在 Mellon 里立即可用。我们提供一个工具函数，能从你的块定义自动生成节点接口——无需 UI 代码。

这一集成之所以可能，是因为每个块都暴露相同的属性（`inputs`、`intermediate_outputs`、`expected_components`）。这套一致的 API 让 Mellon 能从任何块定义自动生成节点的 UI，并把块组合成更高层的节点。

例如，[diffusers/FLUX.2-klein-4B-modular](https://huggingface.co/diffusers/FLUX.2-klein-4B-modular) 在一个仓库里含有一份 pipeline 定义、组件引用，以及一个 `mellon_pipeline_config.json`。用 `ModularPipeline.from_pretrained("diffusers/FLUX.2-klein-4B-modular")` 在 Python 里加载，或在 Mellon 里创建单节点或多节点工作流。

下面是一个快速示例。我们往一条现有的文本到图像工作流里加一个 Gemini 提示词扩写节点——它托管为一个模块化仓库 [diffusers/gemini-prompt-expander-mellon](https://huggingface.co/diffusers/gemini-prompt-expander-mellon)：

- 拖入一个 **Dynamic Block** 节点并输入 `repo_id`（即 `diffusers/gemini-prompt-expander-mellon`）
- 点击 **LOAD CUSTOM BLOCK** —— 节点会自动长出一个用于你的提示词输入的文本框和一个名为 "prompt" 的输出接口（socket），全部由仓库配置
- 输入一段简短提示词，把输出连到 **Encode Prompt** 节点，然后运行

Gemini 会在生成图像前，把你的简短提示词扩写成一段详细描述。无需代码，无需配置——只是一个 Hub 仓库 id。

你的浏览器不支持 video 标签。

这只是一个示例。详细走查见 [Mellon x Modular Diffusers 指南](https://www.notion.so/Mellon-x-Modular-Diffusers-2fd1384ebcac819993d8f9ae94c7e866?pvs=21)。你也可以看看[这个视频](https://youtu.be/XogoQnkQUO8)！

## 结论

Modular Diffusers 带来了社区一直要求的可组合性和灵活性，同时不牺牲让 Diffusers 强大的那些特性。它还很早期——我们希望你的输入来塑造接下来的路。试一下，告诉我们什么有效、什么无效、还缺什么。
