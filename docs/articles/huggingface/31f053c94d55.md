# 用 Gradio 的 gr.HTML 一次性构建任意 Web 应用

**Gradio 6** 悄悄上线了一个非常强大的特性：**`gr.HTML`** 现在支持自定义模板、作用域 CSS 和 JavaScript 交互。这意味着你几乎可以构建任何 Web 组件——而且 Claude（或任何其它前沿 LLM）能一次性生成整个东西：前端、后端、状态管理，全在一个 Python 文件里。

我们构建了不同类型的应用来验证这一点。每个应用都是单个 Python 文件，没有构建步骤，几秒钟就能部署到 Hugging Face Spaces。

## 效率类应用

**[Pomodoro Timer](https://huggingface.co/spaces/ysharma/pomodoro-timer)**：一个专注计时器，随着你工作，一棵像素画小树在生长。从种子开始，发出枝条，长出叶子。完成一个时段，这棵树就加入你的森林。时段记录、主题切换、休息模式——全都可交互，全在一个文件里。

单是这个树的动画，通常就得单独写一个 React 组件。而这里只是 `css_template` 里的 CSS 关键帧加 `js_on_load` 里的状态更新。

## 商业类应用

**[GitHub Contribution Heatmap](https://huggingface.co/spaces/ysharma/github-contribution-heatmap)**：点击任意格子切换贡献状态。多种配色主题。图案生成器（连续、季节性、随机）。边编辑边更新的实时统计。

**[Kanban Board](https://huggingface.co/spaces/ysharma/drag-and-drop-kanban-board)**：列间完整拖放。内联编辑（双击任意卡片）。可实时过滤的搜索功能。可折叠的列。

拖放通常意味着引入一个库。而这里是原生 HTML5 拖放事件在 `js_on_load` 里接线，状态通过 `trigger('change')` 同步回 Python。

## 创意类应用

**[Spin-to-Win Wheel](https://huggingface.co/spaces/ysharma/spin-wheel)**：顺滑的 CSS 动画，旋转状态跨重渲染保持。内置是/否决策、选餐厅、选团队的预设配置。你还可以随时添加自定义的转盘扇区。

## ML 应用

这正是 `gr.HTML` 在机器学习工作上真正有趣的地方：你可以构建能处理你的确切输出格式的专用组件，然后像使用任何内置 Gradio 组件一样使用它们。

**[Detection Viewer](https://huggingface.co/spaces/hysts-gradio-custom-html/detection-viewer-demo)**：一个用于目标检测、实例分割和姿态估计结果的自定义查看器。渲染边界框、分割掩码、关键点和骨架连线——全部封装在一个可复用的 `gr.HTML` 子类里，可直接插入你的模型流水线。

社区也用 gr.HTML 造了一些很有创意的组件：

**[3D Camera Control for Image Editing](https://huggingface.co/spaces/multimodalart/qwen-image-multiple-angles-3d-camera)**：在 Gradio 应用里嵌了一个完整的 Three.js 视口！拖动手柄控制方位角、俯仰角和距离。你上传的图片会出现在 3D 场景中，相机参数直接输入 Qwen 最新的图像编辑模型。这类交互式 3D 控制通常需要单独的前端——而用 Gradio 只是一个 `gr.HTML` 子类🔥

**[Real-time Speech Transcription](https://huggingface.co/spaces/mistralai/Voxtral-Mini-Realtime)**：用 Mistral 的 Voxtral 模型做实时转写。转写显示是一个自定义 `gr.HTML` 组件，带动画状态徽章、实时 WPM 计数器，以及随你说话更新的样式化输出。不用 React 也能做实时 UI 反馈！

## 工作原理

每个 `gr.HTML` 组件接收三个模板：

```
gr.HTML(
    value={"count": 0},
    html_template="<button>Clicked ${value.count} times</button>",
    css_template="button { background: #667eea; color: white; }",
    js_on_load="""
        element.querySelector('button').onclick = () => {
            props.value = { count: props.value.count + 1 };
            trigger('change');
        };
    """
)
```

`${value}` 注入 Python 状态。`props.value` 从 JavaScript 更新它。`trigger('change')` 同步回 Python。这就是全部的 API。

要做可复用组件，就继承 `gr.HTML`：

```
class Heatmap(gr.HTML):
    def __init__(self, value=None, theme="green", **kwargs):
        super().__init__(
            value=value,
            theme=theme,
            html_template=TEMPLATE,
            css_template=STYLES,
            js_on_load=SCRIPT,
            **kwargs
        )
```

现在 `Heatmap()` 用起来就和 `gr.Image()` 或 `gr.Slider()` 一样——放进 Blocks、接上事件处理器，随你需要。

## 为什么这对 Vibe Coding 重要

当你让 LLM 构建一个自定义组件时，单文件输出就是一切。没有「现在创建样式文件」或「把这个接进你的构建配置」。就是一个能立即运行的 Python 文件。

反馈循环变成了：描述你要什么 → 拿到代码 → `gradio app.py` → 看到它跑起来 → 描述要改什么 → 重复。配合 [Gradio 的 reload 模式](https://www.gradio.app/guides/developing-faster-with-reload-mode)，每个循环只要几秒。

用 `gradio deploy` [部署到 Spaces](https://www.gradio.app/guides/sharing-your-app#hosting-on-hf-spaces)，或用 `demo.launch(share=True)` [分享临时链接](https://www.gradio.app/guides/sharing-your-app#sharing-demos)。从一个想法到一个上线应用，几秒钟。

Gradio 自带 32 个交互组件，但有时你完美的 AI Web 应用需要点特别的东西。这就是 `gr.HTML` 的用武之地。

如果你有想法，试试用 `gr.HTML` 把它做出来：向你的 LLM 描述需求，生成代码，运行。你可能会惊讶于 5 分钟能上线什么。
