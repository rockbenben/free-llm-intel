# 用 Gradio 工作流重建 AUTOMATIC1111

在[上一篇文章](https://huggingface.co/blog/gradio-workflow-guide)中，我们搭建了五个小型 `gr.Workflow` 图，并暗示了构建 AUTOMATIC1111 的 [stable-diffusion-webui](https://github.com/AUTOMATIC1111/stable-diffusion-webui) 那样复杂的东西需要什么。本文将带你走完 **Workflow1111**——我们把 AUTOMATIC1111 的绝大部分功能集重建到了一张工作流画布上。

Workflow1111 是一张由 **73 个节点**构成的、包含 **11 条媒体流水线**的图。它汇集了当前最先进（SOTA）模型，覆盖文生图、高分辨率修复、图生图、提示词矩阵网格、VLM 图像反推（interrogate）、检测生成局部重绘遮罩、类 ControlNet 标注器、背景移除、PNG Info 存储，以及图生视频。

用你的 Hugging Face 账号登录或提供 access token，就能运行其中任何一条流水线。登录后，模型调用使用你自己的额度。

👉 **[试一试 Workflow1111](https://huggingface.co/spaces/ysharma/Workflow1111)**，或者复制这个 Space，为你的用例重新接线。

我们沿着画布走一遍。

## 画布上有什么

所有媒体流水线都由上一篇文章和[官方指南](https://gradio.app/guides/workflows#operator-kinds)介绍的四类算子构成。画布上每个节点包装一个算子，算子的输入输出就是你要连边的端口。快速回顾四类算子：`fn` 是一个 Python 函数，`model` 是通过 `InferenceClient` 调用的模型，`space` 是另一个 Gradio Space，`dataset` 是 Hub 数据集里的一行。

逐条流水线看过来。

### 文生图

这是核心流水线。它带有 A1111 txt2img 标签页上你期待的所有控件：负面提示词、步数、CFG、seed、宽高，外加一个用于选择 checkpoint 的 `model_id` 字段。提示词先经过一个 prompt-builder `fn` 节点——追加所选风格预设并清理文本——然后进入一个通过 Inference Providers 调用 checkpoint 的 `model` 节点。一个后处理 `fn` 节点在输出时把生成参数写入 PNG 的 metadata，这正是后面 PNG Info 流水线要读回的内容。

### 高分辨率修复

在 Automatic1111 里，hi-res fix 先把 txt2img 输出上采样，再跑第二轮去噪。这里用一个两节点的绕行分支实现：文生图的结果进入一个 [FLUX.1-Kontext](https://huggingface.co/black-forest-labs/FLUX.1-Kontext-dev) `model` 节点，附带精修指令（"enhance fine detail and micro-texture, keep the composition identical"），返回更锐利、更大的图。

### 图生图

同一个 Kontext 节点兼作 image2img 标签页。上传一张图，描述你想要的改动，它返回编辑后的图。

### 让 LLM 写提示词

从一个粗略提示开始，比如 "A lighthouse in a storm."。这条流水线把它送进一个 [Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507) `model` 节点，再由一个小 `fn` 节点把回复整理成干净、上限四十个的标签列表："stormy sea, wet rocks, dramatic composition, low angle shot, volumetric lighting, ominous tone."。你可以把任意扩散模型节点接到这个输出来生成图像。

这里没有 ComfyUI 那种自定义节点。在 Gradio 工作流里，LLM 和扩散模型都只是同一张画布上的普通 `model` 算子。

### 把图像读回提示词

相当于 AUTOMATIC1111 的 Interrogate 按钮，只不过用 VLM 代替 CLIP 做反推。[Qwen2.5-VL](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct) 看一张夜市照片，写出一个能生成它的提示词。一个 [ViT](https://huggingface.co/google/vit-base-patch16-224) 分类器节点读同一张图，返回标签：restaurant 51.9%、tobacco shop 15.6%、toyshop 9.1%。

两个节点用同一个图像输入，所以 `gr.Workflow` 并行执行它们，两个答案的总耗时约等于只跑一个的时间。

### 检测转局部重绘遮罩

AUTOMATIC1111 要手工涂 inpaint 遮罩。这条流水线改由检测器生成。[DETR](https://huggingface.co/facebook/detr-resnet-50) 在一张街景照里找到六个目标（三个人、一只狗、一辆自行车和一辆汽车），随后工作流分成两条分支：一条把检测框画在原图上，另一条把它们转成遮罩，供下游 inpaint 流水线使用。

画框和生成遮罩都在本地用 Pillow 和 NumPy 完成。只有检测调用离开了本机。

### 提示词矩阵

相当于 AUTOMATIC1111 的 prompt matrix。一个基础提示 "a lone oak tree" 由 `fn` 节点与四个后缀（at sunrise、in a thunderstorm、under the Milky Way、in autumn fog）组合，每个变体各自接一个文生图节点。最后一个节点把四张结果拼成一张样张（contact sheet）。

`gr.Workflow` 没有循环算子，所以四个文生图节点并排摆在画布上。由于它们处于同一依赖深度，会并行运行，四张图同时开始生成。

### 超分与背景移除

相当于 Automatic1111 的 Extras 标签页。有两个上采样节点，走不同路线。第一个是 `fn` 节点里的本地 [Lanczos](https://en.wikipedia.org/wiki/Lanczos_resampling) 重采样，不需要网络调用，Pillow 缩放多快它就多快。第二个是 [AuraSR ×4](https://huggingface.co/spaces/gokaygokay/AuraSR-v2)，画布上第一个 `space` 节点：它调用 Hub 上的一个 [Space](https://huggingface.co/spaces/gokaygokay/AuraSR-v2)，结果和其他节点输出一样处理。

背景移除同理。[BRIA RMBG-2.0](https://huggingface.co/spaces/briaai/BRIA-RMBG-2.0) 又是一个 `space` 节点，整个模型住在它自己的 Space 里，这张画布只管调用。

### 标注器

Canny、line art、sketch、luma-depth、posterize，这些在 Automatic1111 里通常要靠 ControlNet 扩展提供的预处理器，在这里每个都是一个纯 NumPy 编写的 `fn` 节点，背后没有模型。在预装的建筑立面示例照片上，每个标注器在 CPU 上约需半秒。

整个应用有 36 个算子节点，其中 32 个是 `fn` 节点，而这 32 个里有 22 个完全在进程内运行、不发起网络调用。就算断网，大约三分之二的画布照样工作。这些就是普通 Python 函数，所以你也能脱离画布、服务器和 GPU 直接测试它们。

### PNG Info

AUTOMATIC1111 把生成细节存在 PNG 的 `parameters` 文本块里，PNG Info 标签页再读回来。Workflow1111 也一样：文生图流水线的后处理节点写入 metadata，这条流水线再读出来——包括提示词、负面提示词、步数、CFG、seed、图像尺寸和模型。

### 图生视频

PNG Info 读取的那个图像节点同时还喂给一个 [Wan 2.2 I2V A14B](https://huggingface.co/Wan-AI/Wan2.2-I2V-A14B) 节点来做动画；在演示示例里，一只睡着的狐狸醒来开始活动。没有第二个上传框，因为一个参考节点可以喂给你需要的任意多条下游流水线——一次上传，在同一张画布上既读 metadata 又做动画。

## 在你自己的 GPU 上跑模型

到这里，每次模型调用都发到了别人的硬件上——通过 Inference Providers 或某个 Space。正因如此，你不需要自己的 GPU 就能搭建并运行 Workflow1111 这样的东西。

但 `fn` 节点就是 Python，它同样可以在本地加载模型并跑在你自己的 GPU 上。[FastVideo/fastvideo-fasth3-preview](https://huggingface.co/spaces/FastVideo/fastvideo-fasth3-preview) 就是一个恰好这么做的 `gr.Workflow` 应用：它运行 [FastH3](https://huggingface.co/FastVideo/FastVideo-FastH3-4-step-Preview-v1-VSA-DataFree)——[MiniMax-H3](https://huggingface.co/MiniMaxAI/MiniMax-H3) 的四步蒸馏版——在 ZeroGPU 上生成带配乐的动画。

整个应用归结为一个绑定函数：

```
@spaces.GPU(duration=get_duration, size=GPU_SIZE)
def _generate(prompt_embeds, text_token_tags, height, width, num_frames, seed):
    ...

gr.Workflow(bind={"generate": generate, "status": status}).launch()
```

[ZeroGPU](https://huggingface.co/docs/hub/spaces-zerogpu) 在函数需要时给它一块 GPU，调用结束就释放。`gr.Workflow` 完全不用关心这些，它只管调用 `fn` 节点。

这也不限于 Spaces。把 `bind=` 指向一个加载本地 checkpoint 的函数，在你自己的机器上运行 `.launch()`，Workflow1111 画布就能驱动你自己的 GPU。

## 每个输出都是 API

画布上每个输出节点都自动成为一个 REST 端点，无需手写路由。Workflow1111 暴露九个：`/image`、`/edited_image`、`/generated_prompt`、`/recovered_prompt`、`/detected_objects`、`/x_y_grid`、`/upscaled_local`、`/annotator_map` 和 `/png_info`。

```
from gradio_client import Client

client = Client("ysharma/Workflow1111", oauth_token="hf_...")

image, params, hires = client.predict(
    "a red fox in a snowy pine forest",  # Prompt
    "",                                  # Negative prompt
    "Cinematic",                         # Style preset
    "enhance fine detail",               # Hires refine instruction
    api_name="/image",
)
```

这些端点同时也是 [MCP](https://modelcontextprotocol.io) 工具。用 `mcp_server=True` 启动（[指南](https://www.gradio.app/guides/building-mcp-server-with-gradio)），每个输出节点都会变成 AI 助手可调用的工具。把 Claude Code、Cursor 或任何 MCP 客户端指向服务器 URL：

```
{
  "mcpServers": {
    "workflow1111": {
      "url": "https://ysharma-workflow1111.hf.space/gradio_api/mcp/",
      "headers": { "X-HF-Token": "hf_..." }
    }
  }
}
```

现在，一个智能体就能生成图像、读回提示词或运行检测，作为更大任务中的步骤——零胶水代码。每个调用方在 `X-HF-Token` 头里带上自己的 token，Space 自己一个都不存。

## 与 ComfyUI 的对比

功能清单是 AUTOMATIC1111 给的，但 Gradio Workflow 真正被拿来比较的工具是 ComfyUI，因为两者都是节点图。对很多人想构建和交付的东西来说，`gr.Workflow` 覆盖了同样的领域。

- **一个节点可以是你不拥有的硬件。** 它可以通过 [Inference Providers](https://huggingface.co/docs/inference-providers/index) 运行、调用 Hub 上任意 Space 或任意 API，或者从数据集取数。Workflow1111 就是这样在没有自己 GPU 的情况下运行的。
- **每个输出都变成带类型的 REST 端点。** 端点由图自动生成。
- **访客可以以自己的身份运行工作流。** 开启 [OAuth](https://huggingface.co/docs/hub/spaces-oauth)，分享公开 URL，任何人都能登录即用、无需安装任何东西。
- **同一张画布混合模型与模态。** 扩散模型、LLM、VLM、检测器、视频模型都能进同一个工作流。
- **需要自定义？写个函数。** 自定义节点就是一个 Python 函数，Python 能做的事它都能做。

最终成果是一条多模型流水线，人们可以在浏览器里打开、登录、立即使用，还能从代码里调用。

## 构建你自己的

Workflow1111 有 73 个节点，但它的起点只是：

```
import gradio as gr

def your_function(text: str) -> str:
    pass

gr.Workflow(bind=[your_function]).launch()
```

`bind=` 把你的函数变成节点，`edges=` 把它们连起来，`.launch()` 在浏览器打开画布让你继续编辑。就绪之后，`gradio deploy` 把整个东西部署到 Space。[gr.Workflow 指南](https://gradio.app/guides/workflows)有完整细节，包括 JSON schema 和每种算子类型。

如果你更想从一个已经能跑的东西起步，打开 [Workflow1111](https://huggingface.co/spaces/ysharma/Workflow1111)，点 **Duplicate**，挑十一条流水线中的一条来改：删节点、换模型、重新接线。如果想先从小处开始，[上一篇文章](https://huggingface.co/blog/gradio-workflow-guide)里有五个大约一分钟就能跑起来的工作流。

无论你做出什么，发到 X 上并 tag [@gradio](https://x.com/Gradio)，我们乐意帮你传播。
