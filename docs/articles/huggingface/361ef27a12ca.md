## 引言

IF 是一个基于像素空间的文生图生成模型，由 [DeepFloyd 于 2023 年 4 月底发布](https://github.com/deep-floyd/IF)，模型架构深受 [Google 闭源的 Imagen](https://imagen.research.google/) 启发。

与 Stable Diffusion 这类现有文生图模型相比，IF 有两个明显优势：

- 模型直接在"像素空间"（*即*未压缩的图像）上工作，而不是像 [Stable Diffusion](http://hf.co/blog/stable_diffusion) 那样在潜空间（latent space）里跑去噪过程。
- 模型训练时使用的是 [T5-XXL](https://huggingface.co/google/t5-v1_1-xxl) 的输出作为文本条件，它比 Stable Diffusion 用作文本编码器的 [CLIP](https://openai.com/research/clip) 更强大。

因此，IF 更擅长生成高频细节丰富的图像（*例如*人脸和手），并且是第一个能可靠生成带文字图像的开源图像生成模型。

像素空间运行加上更强的文本编码器，代价是 IF 的参数量明显更大。T5、IF 的文生图 UNet 和 IF 的超分 UNet 分别有 45 亿、43 亿和 12 亿参数；相比之下，[Stable Diffusion 2.1](https://huggingface.co/stabilityai/stable-diffusion-2-1) 的文本编码器和 UNet 分别只有 4 亿和 9 亿参数。

不过，只要对模型做低内存优化，在消费级硬件上跑 IF 是完全可行的。本文就演示如何用 🧨 diffusers 做到这一点。

第 1 部分讲如何做文生图，第 2、3 部分演示 IF 的图像变体（image variation）和图像补全（inpainting）能力。

💡 **注意**：我们这里是用速度换内存，才能在免费版 Google Colab 上跑起 IF。如果你有 A100 这样的高端 GPU，建议把所有模型组件都留在 GPU 上以获得最快速度，就像 [IF 官方 demo](https://huggingface.co/spaces/DeepFloyd/IF) 那样。

💡 **注意**：部分较大的图片为了博客加载速度做了压缩。实际使用官方模型时，效果还会更好！

开始吧 🚀！

## 优化 IF 以运行在内存受限的硬件上

前沿 ML 不应该只掌握在少数精英手里。ML 民主化意味着让模型不依赖最新最强的硬件也能跑起来。

深度学习社区已经造出了一流的工具，让资源密集的模型能跑在消费级硬件上：

- [🤗 accelerate](https://github.com/huggingface/accelerate) 提供了处理[大模型](https://huggingface.co/docs/accelerate/usage_guides/big_modeling)的工具。
- [bitsandbytes](https://github.com/TimDettmers/bitsandbytes) 让所有 PyTorch 模型都能用上 [8-bit 量化](https://github.com/TimDettmers/bitsandbytes#features)。
- [🤗 safetensors](https://github.com/huggingface/safetensors) 不仅保证不会执行恶意代码，还显著加快了大模型的加载速度。

Diffusers 无缝集成了上述库，为优化大模型提供了一套简单的 API。

免费版 Google Colab 的 CPU 内存（13 GB RAM）和 GPU 显存（T4，15 GB VRAM）都很紧张，要跑下参数量超 100 亿的完整 IF 模型非常困难！

先看看 IF 各模型组件在完整 float32 精度下的大小：

- [T5-XXL 文本编码器](https://huggingface.co/DeepFloyd/IF-I-XL-v1.0/tree/main/text_encoder)：20GB
- [Stage 1 UNet](https://huggingface.co/DeepFloyd/IF-I-XL-v1.0/tree/main/unet)：17.2 GB
- [Stage 2 超分辨率 UNet](https://huggingface.co/DeepFloyd/IF-II-L-v1.0/blob/main/pytorch_model.bin)：2.5 GB
- [Stage 3 超分辨率模型](https://huggingface.co/stabilityai/stable-diffusion-x4-upscaler)：3.4 GB

float32 精度下完全跑不起来——T5 和 Stage 1 UNet 的权重各自都比可用的 CPU 内存还大。

换成 float16 后，T5、Stage 1 和 Stage 2 UNet 的组件大小分别是 11GB、8.6GB 和 1.25GB，GPU 勉强放得下，但加载 T5 时仍会遇到 CPU 内存溢出错误（部分 CPU 内存被其他进程占用）。

因此我们用 `bitsandbytes` 的 8bit 量化进一步降低 T5 的精度，这样 T5 检查点只需 [8 GB](https://huggingface.co/DeepFloyd/IF-I-XL-v1.0/blob/main/text_encoder/model.8bit.safetensors) 就能存下。

现在每个组件单独都能放进 CPU 和 GPU 内存，接下来要保证组件在各自需要用到的时刻，独占全部的 CPU 和 GPU 内存。

Diffusers 支持按需模块化加载单个组件，也就是说可以只加载文本编码器而不加载 UNet。这种模块化加载保证我们在 pipeline 的每一步只加载当前需要的组件，避免耗尽可用的 CPU 内存和 GPU 显存。

来试试吧 🚀

## 1. 文生图

我们将一步步走通用 Diffusers 的 IF 文生图流程。API 和优化只做简要说明，更详细的解释请看 [Diffusers](https://huggingface.co/docs/diffusers/index)、[Transformers](https://huggingface.co/docs/transformers/index)、[Accelerate](https://huggingface.co/docs/accelerate/index) 和 [bitsandbytes](https://github.com/TimDettmers/bitsandbytes) 的官方文档。

### 1.1 加载文本编码器

我们用 8bit 量化加载 T5。Transformers 通过 `load_in_8bit` 标志直接支持 [bitsandbytes](https://huggingface.co/docs/transformers/main/en/main_classes/quantization#load-a-large-model-in-8bit)。

`variant="8bit"` 标志会下载预先量化好的权重。

我们还使用 `device_map` 标志，允许 `transformers` 把模型层卸载（offload）到 CPU 或磁盘。Transformers 的 big modeling 支持任意 device map，可以把模型参数直接加载到各个可用设备上。传 `"auto"` 会自动生成 device map，详见 `transformers` [文档](https://huggingface.co/docs/accelerate/usage_guides/big_modeling#designing-a-device-map)。

```
from transformers import T5EncoderModel

text_encoder = T5EncoderModel.from_pretrained(
    "DeepFloyd/IF-I-XL-v1.0",
    subfolder="text_encoder", 
    device_map="auto", 
    load_in_8bit=True, 
    variant="8bit"
)
```

### 1.2 创建文本嵌入

Diffusers 访问扩散模型的 API 是 `DiffusionPipeline` 类及其子类。每个 `DiffusionPipeline` 实例都是自包含的方法与模型集合，用于运行扩散网络。我们可以在 `from_pretrained` 里以关键字参数传入替代的模型实例来覆盖默认模型。

这里我们把 `unet` 参数传 `None`，于是不加载 UNet。这样可以只运行扩散流程中的文本嵌入部分，而不把 UNet 加载进内存。

```
from diffusers import DiffusionPipeline

pipe = DiffusionPipeline.from_pretrained(
    "DeepFloyd/IF-I-XL-v1.0", 
    text_encoder=text_encoder, # pass the previously instantiated 8bit text encoder
    unet=None, 
    device_map="auto"
)
```

IF 还带有超分辨率 pipeline。我们会把 prompt 嵌入保存下来，之后直接传给超分 pipeline。这样超分 pipeline 加载时**不需要**文本编码器。

别再让宇航员[光是骑马](https://huggingface.co/blog/stable_diffusion)了，再给他手里塞块牌子！

先定义一个合适的 prompt：

```
prompt = "a photograph of an astronaut riding a horse holding a sign that says Pixel's in space"
```

然后把它送进 8bit 量化的 T5 模型：

```
prompt_embeds, negative_embeds = pipe.encode_prompt(prompt)
```

### 1.3 释放内存

prompt 嵌入算好之后，文本编码器就没用了。但它还占着 GPU 内存，我们必须把它清掉，才能加载 UNet。

释放 PyTorch 内存并不简单。要真正释放分配在 GPU 上的内存，必须先回收指向这些内存的 Python 对象。

首先用 Python 关键字 `del` 删除所有引用已分配 GPU 内存的 Python 对象

```
del text_encoder
del pipe
```

只删除 Python 对象还不够，真正的 GPU 内存释放发生在垃圾回收时。

另外我们还会调用 `torch.cuda.empty_cache()`。这个方法并非严格必需，因为缓存的 cuda 内存本来就能立即用于后续分配。清空缓存可以让我们在 Colab UI 里确认内存确实可用。

我们用一个辅助函数 `flush()` 来清内存。

```
import gc
import torch

def flush():
    gc.collect()
    torch.cuda.empty_cache()
```

然后运行它

```
flush()
```

### 1.4 Stage 1：主扩散过程

现在 GPU 内存可用了，我们重新加载只带 UNet 的 `DiffusionPipeline` 来跑主扩散过程。

`variant` 和 `torch_dtype` 标志让 Diffusers 以下载并加载 16 位浮点格式的权重。

```
pipe = DiffusionPipeline.from_pretrained(
    "DeepFloyd/IF-I-XL-v1.0", 
    text_encoder=None, 
    variant="fp16", 
    torch_dtype=torch.float16, 
    device_map="auto"
)
```

通常我们直接把文本 prompt 传给 `DiffusionPipeline.__call__`。但这里我们已经有预先算好的文本嵌入，可以直接传入。

IF 还带有一个超分辨率扩散过程。设置 `output_type="pt"` 会返回原始 PyTorch tensor 而不是 PIL 图像。这样可以把 tensor 留在 GPU 上，直接传给 Stage 2 超分 pipeline。

定义一个随机生成器，然后运行 Stage 1 扩散过程。

```
generator = torch.Generator().manual_seed(1)
image = pipe(
    prompt_embeds=prompt_embeds,
    negative_prompt_embeds=negative_embeds, 
    output_type="pt",
    generator=generator,
).images
```

手动把原始 tensor 转成 PIL，先睹为快。Stage 1 的输出是一张 64x64 的图像。

```
from diffusers.utils import pt_to_pil

pil_image = pt_to_pil(image)
pipe.watermarker.apply_watermark(pil_image, pipe.unet.config.sample_size)

pil_image[0]
```

[![t2i_64](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/if/t2i_64.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/if/t2i_64.png)

同样地，删掉 Python 指针并释放 CPU 和 GPU 内存：

```
del pipe
flush()
```

### 1.5 Stage 2：超分辨率 64x64 到 256x256

IF 有一个独立的扩散过程用于放大。

每个扩散过程都用单独的 pipeline 运行。

超分 pipeline 需要时可以带文本编码器加载。但我们通常已经有 IF 第一段 pipeline 预先算好的文本嵌入，这时就应该不带文本编码器加载 pipeline。

创建 pipeline

```
pipe = DiffusionPipeline.from_pretrained(
    "DeepFloyd/IF-II-L-v1.0", 
    text_encoder=None, # no use of text encoder => memory savings!
    variant="fp16", 
    torch_dtype=torch.float16, 
    device_map="auto"
)
```

运行它，复用预先算好的文本嵌入

```
image = pipe(
    image=image, 
    prompt_embeds=prompt_embeds, 
    negative_prompt_embeds=negative_embeds, 
    output_type="pt",
    generator=generator,
).images
```

又可以查看中间结果了。

```
pil_image = pt_to_pil(image)
pipe.watermarker.apply_watermark(pil_image, pipe.unet.config.sample_size)

pil_image[0]
```

[![t2i_upscaled](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/if/t2i_upscaled.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/if/t2i_upscaled.png)

还是老规矩，删除 Python 指针并释放内存

```
del pipe
flush()
```

### 1.6 Stage 3：超分辨率 256x256 到 1024x1024

IF 的第二个超分模型是之前发布的 [Stability AI x4 Upscaler](https://huggingface.co/stabilityai/stable-diffusion-x4-upscaler)。

创建 pipeline，用 `device_map="auto"` 直接加载到 GPU。

```
pipe = DiffusionPipeline.from_pretrained(
    "stabilityai/stable-diffusion-x4-upscaler", 
    torch_dtype=torch.float16, 
    device_map="auto"
)
```

🧨 diffusers 让独立开发的扩散模型很容易组合，因为 pipeline 可以串联起来。这里直接把上一个 PyTorch tensor 输出以 `image=image` 传给 Stage 3 pipeline 就行。

💡 **注意**：x4 Upscaler 不用 T5，它有[自己的文本编码器](https://huggingface.co/stabilityai/stable-diffusion-x4-upscaler/tree/main/text_encoder)。所以不能复用之前创建的 prompt 嵌入，必须传原始 prompt。

```
pil_image = pipe(prompt, generator=generator, image=image).images
```

与 IF pipeline 不同，Stable Diffusion x4 超分 pipeline 的输出默认不会加 IF 水印。

我们可以手动加上。

```
from diffusers.pipelines.deepfloyd_if import IFWatermarker

watermarker = IFWatermarker.from_pretrained("DeepFloyd/IF-I-XL-v1.0", subfolder="watermarker")
watermarker.apply_watermark(pil_image, pipe.unet.config.sample_size)
```

查看输出图像

```
pil_image[0]
```

[![t2i_upscaled_2](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/if/t2i_upscaled_2.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/if/t2i_upscaled_2.png)

大功告成！在免费版 Google Colab 里得到一张漂亮的 1024x1024 图像。

我们演示了 🧨 diffusers 如何让拆解和模块化加载资源密集的扩散模型变得简单。

💡 **注意**：不建议把上面的配置用于生产环境。8bit 量化、手动释放模型权重、磁盘卸载，全都是在用时间换内存（也就是牺牲推理速度）。如果反复复用 diffusion pipeline，这一点会更明显。生产环境建议使用 40GB 显存的 A100，把所有模型组件留在 GPU 上。参考[**IF 官方 demo**](https://huggingface.co/spaces/DeepFloyd/IF)。

## 2. 图像变体

同样的 IF 检查点也可以用于文本引导的图像变体和图像补全。核心扩散过程与文生图完全相同，只是初始的加噪图像由要被变体或补全的原图生成。

运行图像变体时，用 `IFImg2ImgPipeline.from_pretrained()` 和 `IFImg2ImgSuperResolution.from_pretrained()` 加载同样的检查点。

内存优化的 API 完全一样！

先释放上一节的内存。

```
del pipe
flush()
```

图像变体需要我们先有一张想要改造的原图。

本节我们拿著名的"Slaps Roof of Car"表情包开刀，先从网上下载它。

```
import requests

url = "https://i.kym-cdn.com/entries/icons/original/000/026/561/car.jpg"
response = requests.get(url)
```

并加载成 PIL 图像

```
from PIL import Image
from io import BytesIO

original_image = Image.open(BytesIO(response.content)).convert("RGB")
original_image = original_image.resize((768, 512))
original_image
```

[![iv_sample](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/if/iv_sample.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/if/iv_sample.png)

图像变体 pipeline 既接受 PIL 图像也接受原始 tensor。关于输入要求的更详细文档见 docstring，[这里](https://huggingface.co/docs/diffusers/v0.16.0/en/api/pipelines/if#diffusers.IFImg2ImgPipeline.__call__)。

### 2.1 文本编码器

图像变体由文本引导，所以我们可以定义一个 prompt 并用 T5 的文本编码器编码。

同样把文本编码器按 8bit 精度加载。

```
from transformers import T5EncoderModel

text_encoder = T5EncoderModel.from_pretrained(
    "DeepFloyd/IF-I-XL-v1.0",
    subfolder="text_encoder", 
    device_map="auto", 
    load_in_8bit=True, 
    variant="8bit"
)
```

图像变体我们用 [`IFImg2ImgPipeline`](https://huggingface.co/docs/diffusers/v0.16.0/en/api/pipelines/if#diffusers.IFImg2ImgPipeline) 加载检查点。用 `DiffusionPipeline.from_pretrained(...)` 时，检查点会被加载进各自的默认 pipeline。IF 的默认 pipeline 是文生图的 [`IFPipeline`](https://huggingface.co/docs/diffusers/v0.16.0/en/api/pipelines/if#diffusers.IFPipeline)。用非默认 pipeline 加载检查点时，必须显式指定该 pipeline。

```
from diffusers import IFImg2ImgPipeline

pipe = IFImg2ImgPipeline.from_pretrained(
    "DeepFloyd/IF-I-XL-v1.0", 
    text_encoder=text_encoder, 
    unet=None, 
    device_map="auto"
)
```

把我们的销售人员变成动漫角色吧。

```
prompt = "anime style"
```

和之前一样，用 T5 创建文本嵌入

```
prompt_embeds, negative_embeds = pipe.encode_prompt(prompt)
```

然后释放 GPU 和 CPU 内存。

先删除 Python 指针

```
del text_encoder
del pipe
```

再清内存

```
flush()
```

### 2.2 Stage 1：主扩散过程

## 3. 图像补全

IF 的图像补全 pipeline 与图像变体基本一致，区别只在只对图像的选定区域去噪。

我们用一张掩码（mask）图像指定要补全的区域。

来展示一下 IF 惊人的"文字生成"能力——把牌子上的文字换成别的口号。

先下载图像

```

url = "https://i.imgflip.com/5j6x75.jpg"
```

转成 PIL 图像

```
from PIL import Image

original_image = original_image.resize((512, 768))
original_image
```

ML 生态从工具与模型的开放共享中受益匪浅。仅这篇 notebook 就用到了 DeepFloyd、StabilityAI 和 [Google](https://huggingface.co/google) 的模型。所用到的库——Diffusers、Transformers、Accelerate 和 bitsandbytes——都离不开来自不同组织的无数贡献者。
