# 使用 DeepSpeed 加速大模型训练

在这篇文章中，我们将探讨如何利用 **[Accelerate](https://github.com/huggingface/accelerate)** 库来训练大型模型——它让用户能够使用 **[DeepSpeed](https://www.deepspeed.ai)** 的 ZeRO 特性。

## 动机 🤗

**为训练大模型时没完没了的 OOM（内存溢出）错误感到疲惫？我们来帮你。大型模型的性能非常出色 [1]，但用现有硬件训练它们很困难。要把现有硬件在大模型训练上的价值发挥到极致，可以采用基于 ZeRO（Zero Redundancy Optimizer，零冗余优化器）的数据并行 [2]**。

下面是基于 ZeRO 的数据并行的简要说明，图示来自这篇 [blog post](https://www.microsoft.com/en-us/research/blog/zero-deepspeed-new-system-optimizations-enable-training-models-with-over-100-billion-parameters/) [![ZeRO Data Parallelism](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/parallelism-zero.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/parallelism-zero.png)

（来源：[link](https://www.microsoft.com/en-us/research/blog/zero-deepspeed-new-system-optimizations-enable-training-models-with-over-100-billion-parameters/)）

a. **Stage 1**：在数据并行的各个 worker/GPU 之间切分优化器状态

b. **Stage 2**：在数据并行的各个 worker/GPU 之间切分优化器状态 + 梯度

c. **Stage 3**：在数据并行的各个 worker/GPU 之间切分优化器状态 + 梯度 + 模型参数

d. **Optimizer Offload**：在 ZeRO Stage 2 的基础上，把梯度和优化器状态卸载（offload）到 CPU/磁盘

e. **Param Offload**：在 ZeRO Stage 3 的基础上，把模型参数卸载到 CPU/磁盘

在本博客中，我们将探讨如何通过 Accelerate 使用基于 ZeRO 的数据并行。**[DeepSpeed](https://github.com/microsoft/deepspeed)**、**[FairScale](https://github.com/facebookresearch/fairscale/)** 和 **[PyTorch FullyShardedDataParallel (FSDP)](https://pytorch.org/blog/introducing-pytorch-fully-sharded-data-parallel-api/)** 都实现了 ZeRO 论文的核心思想。这些能力已经集成进 🤗 `transformers` Trainer 和 🤗 `accelerate`，并配有优秀博客 [Fit More and Train Faster With ZeRO via DeepSpeed and FairScale](https://huggingface.co/blog/zero-deepspeed-fairscale) [4] 和 [Accelerate Large Model Training using PyTorch Fully Sharded Data Parallel](https://huggingface.co/blog/pytorch-fsdp) [5]。底层原理的细节我们留给那两篇博客，本文主要聚焦如何用 Accelerate 使用 DeepSpeed ZeRO。

## Accelerate 🚀：零代码改动使用 DeepSpeed ZeRO

**硬件环境**：2 块 24GB NVIDIA Titan RTX GPU，60GB 内存。

我们来看一个针对文本分类任务微调仅编码器（encoder-only）模型的任务。我们使用预训练的 `microsoft/deberta-v2-xlarge-mnli`（9 亿参数）在 MRPC GLUE 数据集上微调。

代码见这里 [run_cls_no_trainer.py](https://github.com/pacman100/accelerate-deepspeed-test/blob/main/src/modeling/run_cls_no_trainer.py)。它与官方文本分类示例（[here](https://github.com/huggingface/transformers/blob/main/examples/pytorch/text-classification/run_glue_no_trainer.py)）基本相同，只是增加了测量训练和评估时间的逻辑。我们在多 GPU 环境下比较分布式数据并行（DDP）和 DeepSpeed ZeRO Stage-2 的性能。

要在零代码改动的情况下启用 DeepSpeed ZeRO Stage-2，请运行 `accelerate config`，并使用 [Accelerate DeepSpeed Plugin](https://huggingface.co/docs/accelerate/deepspeed#accelerate-deepspeed-plugin)。

**ZeRO Stage-2 DeepSpeed Plugin 示例**

```
compute_environment: LOCAL_MACHINE
deepspeed_config:
 gradient_accumulation_steps: 1
 gradient_clipping: 1.0
 offload_optimizer_device: none
 offload_param_device: none
 zero3_init_flag: false
 zero_stage: 2
distributed_type: DEEPSPEED
fsdp_config: {}
machine_rank: 0
main_process_ip: null
main_process_port: null
main_training_function: main
mixed_precision: fp16
num_machines: 1
num_processes: 2
use_cpu: false
```

然后运行以下命令进行训练：

```
accelerate launch run_cls_no_trainer.py \
  --model_name_or_path "microsoft/deberta-v2-xlarge-mnli" \
  --task_name "mrpc" \
  --ignore_mismatched_sizes \
  --max_length 128 \
  --per_device_train_batch_size 40 \
  --learning_rate 2e-5 \
  --num_train_epochs 3 \
  --output_dir "/tmp/mrpc/deepspeed_stage2/" \
  --with_tracking \
  --report_to "wandb" \
```

在我们的单节点多 GPU 环境中，DDP 在不发生 OOM 的情况下支持的最大 batch size 是 8。相比之下，DeepSpeed ZeRO Stage 2 可以在不触发 OOM 的情况下把 batch size 开到 40。因此，与 DDP 相比，DeepSpeed 每块 GPU 能容纳 **5 倍**的数据。下面是 wandb [run](https://wandb.ai/smangrul/DDP_vs_DeepSpeed_cls_task?workspace=user-smangrul) 的曲线图快照，以及 DDP 与 DeepSpeed 的基准对比表。

[![Wandb Run](https://huggingface.co/blog/assets/83_accelerate_deepspeed/cls_run.png)](https://huggingface.co/blog/assets/83_accelerate_deepspeed/cls_run.png)

| Method | Batch Size Max | Train time per epoch (seconds) | Eval time per epoch (seconds) | F1 score | Accuracy |
| --- | --- | --- | --- | --- | --- |
| DDP (Distributed Data Parallel) | 8 | 103.57 | 2.04 | 0.931 | 0.904 |
| DeepSpeed ZeRO Stage 2 | **40** | **28.98** | **1.79** | **0.936** | **0.912** |

表 1：DeBERTa-XL（900M）模型上的 DeepSpeed ZeRO Stage-2 基准测试

在这个更大的 batch size 下，我们在不影响性能指标的前提下，把总训练时间提速约 **3.5 倍**，而且所有这一切都不用改任何代码。太棒了！🤗。

如果想微调更多选项，就需要使用 DeepSpeed 配置文件并做少量代码改动。下面我们来看怎么做。

## Accelerate 🚀：用 DeepSpeed 配置文件调整更多选项

首先，我们来看一个微调 seq2seq 模型训练自家 Chatbot 的任务。具体地说，我们将在 [smangrul/MuDoConv](https://huggingface.co/datasets/smangrul/MuDoConv)（Multi-Domain Conversation，多领域对话）数据集上微调 `facebook/blenderbot-400M-distill`。该数据集收录了来自 10 个不同数据源的对话，覆盖人设扮演、特定情绪情境、目标导向对话（如餐厅预订）以及维基百科通用话题（如板球）。

代码见这里 [run_seq2seq_no_trainer.py](https://github.com/pacman100/accelerate-deepspeed-test/blob/main/src/modeling/run_seq2seq_no_trainer.py)。当前有效衡量 Chatbot 的 `Engagingness`（吸引力）和 `Humanness`（拟人度）的做法是昂贵的人工评估 [6]。因此本示例跟踪的指标是 BLEU 分数（虽然不理想，但它是这类任务的传统指标）。如果你拥有支持 `bfloat16` 精度的 GPU，也可以把这套代码改用于训练更大的 T5 模型，否则会碰到 `NaN` 损失值。我们将在 10,000 条训练样本和 1,000 条评估样本上做一次快速基准测试，因为我们关心的是 DeepSpeed 与 DDP 的对比。

训练将使用 DeepSpeed Zero Stage-2 配置 [zero2_config_accelerate.json](https://github.com/pacman100/accelerate-deepspeed-test/blob/main/src/modeling/configs/zero2_config_accelerate.json)（见下方）。各项配置特性的详细信息请参阅 [DeepSpeed](https://www.deepspeed.ai) 文档。

```
{
    "fp16": {
        "enabled": "true",
        "loss_scale": 0,
        "loss_scale_window": 1000,
        "initial_scale_power": 15,
        "hysteresis": 2,
        "min_loss_scale": 1
    },
    "optimizer": {
        "type": "AdamW",
        "params": {
            "lr": "auto",
            "weight_decay": "auto",
            "torch_adam": true,
            "adam_w_mode": true
        }
    },
    "scheduler": {
        "type": "WarmupDecayLR",
        "params": {
            "warmup_min_lr": "auto",
            "warmup_max_lr": "auto",
            "warmup_num_steps": "auto",
            "total_num_steps": "auto"
        }
    },
    "zero_optimization": {
        "stage": 2,
        "allgather_partitions": true,
        "allgather_bucket_size": 2e8,
        "overlap_comm": true,
        "reduce_scatter": true,
        "reduce_bucket_size": 2e8,
        "contiguous_gradients": true
    },
    "gradient_accumulation_steps": 1,
    "gradient_clipping": "auto",
    "steps_per_print": 2000,
    "train_batch_size": "auto",
    "train_micro_batch_size_per_gpu": "auto",
    "wall_clock_breakdown": false
}
```

要在上述配置下启用 DeepSpeed ZeRO Stage-2，请运行 `accelerate config`，并在被询问时提供配置文件路径。更多细节请参阅 🤗 `accelerate` 官方文档的 [DeepSpeed Config File](https://huggingface.co/docs/accelerate/deepspeed#deepspeed-config-file) 部分。

**ZeRO Stage-2 DeepSpeed 配置文件示例**

```
compute_environment: LOCAL_MACHINE
deepspeed_config:
 deepspeed_config_file: /path/to/zero2_config_accelerate.json
 zero3_init_flag: false
distributed_type: DEEPSPEED
fsdp_config: {}
machine_rank: 0
main_process_ip: null
main_process_port: null
main_training_function: main
mixed_precision: fp16
num_machines: 1
num_processes: 2
use_cpu: false
```

然后运行以下命令进行训练：

```
accelerate launch run_seq2seq_no_trainer.py \
    --dataset_name "smangrul/MuDoConv" \
    --max_source_length 128 \
    --source_prefix "chatbot: " \
    --max_target_length 64 \
    --val_max_target_length 64 \
    --val_min_target_length 20 \
    --n_val_batch_generations 5 \
    --n_train 10000 \
    --n_val 1000 \
    --pad_to_max_length \
    --num_beams 10 \
    --model_name_or_path "facebook/blenderbot-400M-distill" \
    --per_device_train_batch_size 200 \
    --per_device_eval_batch_size 100 \
    --learning_rate 1e-6 \
    --weight_decay 0.0 \
    --num_train_epochs 1 \
    --gradient_accumulation_steps 1 \
    --num_warmup_steps 100 \
    --output_dir "/tmp/deepspeed_zero_stage2_accelerate_test" \
    --seed 25 \
    --logging_steps 100 \
    --with_tracking \
    --report_to "wandb" \
    --report_name "blenderbot_400M_finetuning"
```

使用 DeepSpeed 配置时，如果用户在配置中指定了 `optimizer` 和 `scheduler`，就必须改用 `accelerate.utils.DummyOptim` 和 `accelerate.utils.DummyScheduler`。这是用户唯一需要做的几处小改动。下面展示了使用 DeepSpeed 配置所需的最小改动示例：

```
- optimizer = torch.optim.Adam(optimizer_grouped_parameters, lr=args.learning_rate)
+ optimizer = accelerate.utils.DummyOptim(optimizer_grouped_parameters, lr=args.learning_rate)

- lr_scheduler = get_scheduler(
-     name=args.lr_scheduler_type,
-     optimizer=optimizer,
-     num_warmup_steps=args.num_warmup_steps,
-     num_training_steps=args.max_train_steps,
- )

+ lr_scheduler = accelerate.utils.DummyScheduler(
+     optimizer, total_num_steps=args.max_train_steps, warmup_num_steps=args.num_warmup_steps
+ )
```

| Method | Batch Size Max | Eval Size Max | Train time per epoch (seconds) | Eval time per epoch (seconds) |
| --- | --- | --- | --- | --- |
| DDP (Distributed Data Parallel) | 100 | 50 | 27.36 | 48.41 |
| DeepSpeed ZeRO Stage 2 | **200** | **100** | **19.06** | **39.27** |

表 2：BlenderBot（400M）模型上的 DeepSpeed ZeRO Stage-2 基准测试

在我们的单节点多 GPU 环境中，DDP 在不发生 OOM 的情况下支持的最大 batch size 是 100。相比之下，DeepSpeed ZeRO Stage 2 可以开到 200 而不触发 OOM。因此，与 DDP 相比，DeepSpeed 每块 GPU 能容纳 **2 倍**的数据。由于我们能在同样的硬件上容纳更多数据，训练提速约 **1.44 倍**，评估提速约 **1.23 倍**。由于这个模型规模中等，提速不算惊艳，但模型越大效果会越明显。你可以在 🤗 Space [smangrul/Chat-E](https://huggingface.co/spaces/smangrul/Chat-E) 上与用全量数据训练的 Chatbot 聊天。你可以给它设定人设、把对话锚定在某种特定情绪上、用于目标导向任务，或者随意自由聊天。下面是一段与 chatbot 的有趣对话 💬。更多不同情境下对话的截图见[这里](https://github.com/pacman100/accelerate-deepspeed-test/tree/main/src/chatbot_snapshots)。

### CPU/磁盘卸载：让显存放不下的巨型模型也能训练

在单块 24GB 的 NVIDIA Titan RTX GPU 上，即使 batch size 开到 1 也无法训练 GPT-XL 模型（15 亿参数）。我们来看如何使用带 CPU 卸载（优化器状态、梯度和参数）的 DeepSpeed ZeRO Stage-3 来训练 GPT-XL。

训练将使用 DeepSpeed Zero Stage-3 CPU offload 配置 [zero3_offload_config_accelerate.json](https://github.com/pacman100/accelerate-deepspeed-test/blob/main/src/modeling/configs/zero3_offload_config_accelerate.json)（见下方）。该配置与 🤗 `accelerate` 的配合方式与上面的实验相同。

```
{
    "fp16": {
        "enabled": true,
        "loss_scale": 0,
        "loss_scale_window": 1000,
        "initial_scale_power": 16,
        "hysteresis": 2,
        "min_loss_scale": 1
    },
    "optimizer": {
        "type": "AdamW",
        "params": {
            "lr": "auto",
            "weight_decay": "auto"
        }
    },
    "scheduler": {
        "type": "WarmupDecayLR",
        "params": {
            "warmup_min_lr": "auto",
            "warmup_max_lr": "auto",
            "warmup_num_steps": "auto",
            "total_num_steps": "auto"
        }
    },
    "zero_optimization": {
        "stage": 3,
        "offload_optimizer": {
            "device": "cpu",
            "pin_memory": true
        },
        "offload_param": {
            "device": "cpu",
            "pin_memory": true
        },
        "overlap_comm": true,
        "contiguous_gradients": true,
        "reduce_bucket_size": "auto",
        "stage3_prefetch_bucket_size": "auto",
        "stage3_param_persistence_threshold": "auto",
        "sub_group_size": 1e9,
        "stage3_max_live_parameters": 1e9,
        "stage3_max_reuse_distance": 1e9,
        "stage3_gather_16bit_weights_on_model_save": true
    },
    "gradient_accumulation_steps": 1,
    "gradient_clipping": "auto",
    "steps_per_print": 2000,
    "train_batch_size": "auto",
    "train_micro_batch_size_per_gpu": "auto",
    "wall_clock_breakdown": false
}
```

**ZeRO Stage-3 CPU Offload DeepSpeed 配置文件示例**

```
compute_environment: LOCAL_MACHINE
deepspeed_config:
 deepspeed_config_file: /path/to/zero3_offload_config_accelerate.json
 zero3_init_flag: true
distributed_type: DEEPSPEED
fsdp_config: {}
machine_rank: 0
main_process_ip: null
main_process_port: null
main_training_function: main
mixed_precision: fp16
num_machines: 1
num_processes: 2
use_cpu: false
```

然后运行以下命令进行训练：

```
accelerate launch run_clm_no_trainer.py \
--config_name "gpt2-xl" \
--tokenizer_name "gpt2-xl" \
--dataset_name "wikitext" \
--dataset_config_name "wikitext-2-raw-v1" \
--block_size 128 \
--output_dir "/tmp/clm_deepspeed_stage3_offload__accelerate" \
--learning_rate 5e-4 \
--per_device_train_batch_size 16 \
--per_device_eval_batch_size 1 \
--num_train_epochs 1 \
--with_tracking \
--report_to "wandb"\
```

| Method | Batch Size Max | Train time per epoch (seconds) | Notes |
| --- | --- | --- | --- |
| DDP (Distributed Data Parallel) | - | - | OOM Error |
| DeepSpeed ZeRO Stage 3 | **16** | 6608.35 |  |

表 3：GPT-XL（1.5B）模型上的 DeepSpeed ZeRO Stage-3 CPU Offload 基准测试

DDP 即使 batch size 为 1 也会 OOM。而使用 DeepSpeed ZeRO Stage-3 CPU offload，我们可以以 16 的 batch size 进行训练。

最后请记住，🤗 `Accelerate` 只是集成了 DeepSpeed；因此如果你在使用 DeepSpeed 时遇到任何问题或有疑问，请到 [DeepSpeed GitHub](https://github.com/microsoft/DeepSpeed/issues) 提交 issue。
