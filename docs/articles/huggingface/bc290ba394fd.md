在 AI 世界里，时间仿佛被压缩了。我们半年度分析的 [春季报告](https://huggingface.co/blog/huggingface/state-of-os-hf-spring-2026) 梳理完整生态才过去几个月，到今年夏天就已经有不少新发现。本报告列出 2026 年 1 月到 8 月的这些观察，并呈现每条背后的数据。

[![Hugging Face 各任务类别数据集的累计增长，2026 年达到一百万](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/dataset-growth.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/dataset-growth.png)

HF hub 上的模型和数据集每天都在增长。公开模型仓库在此期间从 243 万增至 296 万，数据集从 71.1 万增至 100 万，Spaces 从 100 万增至 144 万。底层的分布依旧极端，约 85.6% 的模型历史下载量不到 200 次，而 1.5% 的仓库占据了全部下载量的 99.2%。下文所有事情都发生在这个形状之内。

**1. 前沿推进得很快**

过去有一条清晰的进阶路径：实验室先发布较小的模型，逐步爬到规模顶端。2026 年，几家中国实验室完全跳过了这条路径。

[![2026 年按月份、中国与硅谷实验室发布的最大开放模型](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/frontier-ceiling-by-country.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/frontier-ceiling-by-country.png)

**2026 年几乎每个月，来自中国实验室的最大、最强开放模型都比美国实验室发布的任何模型都大。** 中国的月度上限在 754B 到 2.78 万亿参数之间；美国模型在七个月里有五个月保持在 130B 以下，例外是 NVIDIA 5 月和 6 月的 [Nemotron 3 Ultra](https://huggingface.co/collections/nvidia/nvidia-nemotron-v3)（561B）以及 Thinking Machines Lab 的 [Inkling](https://huggingface.co/collections/thinkingmachines/inkling)。

[![每家实验室都有不同的尺寸策略](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/lab-size-strategy.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/lab-size-strategy.png)

这张图把实验室分成两派。[Moonshot](https://huggingface.co/moonshotai)、[MiniMax](https://huggingface.co/MiniMaxAI)、[Xiaomi](https://huggingface.co/XiaomiMiMo) 和 [Z.ai](http://Z.ai) 几乎不在 70B 以下发布，于是开发者与它们的第一次接触就是一个在自己设备上跑不动的模型。[Tencent](https://huggingface.co/tencent) 和 [Alibaba Qwen](https://huggingface.co/Qwen) 则覆盖整个区间，从 1B 以下一直到上。

有两件事让第一派成为可能。造大模型不再是差异化。Xiaomi、[蚂蚁集团](https://huggingface.co/inclusionAI) 和 [美团](https://huggingface.co/meituan-longcat) 今年都跨过了万亿参数，而十二个月前它们中没有一家是开放权重圈子里家喻户晓的名字。而且一个实验室不再非得发布小模型才能被够得着，因为社区的量化层会在几天之内把一个大的变得可运行——这一依赖我们下文还会回到。

于是尺寸分布就成了一种意图的表态，而非能力的表态。只做前沿的产品线把一切押在 benchmark 排名和 API 需求上。全谱系的产品线则是在争取成为开发者共同遵循的那个家族。两者都理性，只是争夺的目标不同。

美国并非缺席开源。

[![新发布的本土模型](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/new-homegrown-models.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/new-homegrown-models.png)

今年发布最多新开放模型的两家机构，也正是做硬件的公司：[AMD](https://huggingface.co/amd) 和 [NVIDIA](https://huggingface.co/nvidia)。各自发布了超过 200 个新模型仓库，远超其他玩家，[LiquidAI](https://huggingface.co/LiquidAI) 以约 100 个排名第三。硬件厂商已经意识到开放模型是卖芯片的一种方式：一个为你的硬件优化、又免费可得模型，就是硬件好用的最清楚证明。

把小模型和嵌入模型算进来——Google、Microsoft、IBM Granite 以及 OpenAI 较早的视觉和语音模型每年产生数亿下载——**美国的开源 AI 正在增长。**

更多硬件和基础设施机构（如 NVIDIA）在训练并开放有竞争力的模型权重。NVIDIA 的 Nemotron 模型家族性能很高。老牌领导者如 Meta 用 [Muse Glimmer](https://huggingface.co/meta-models/Muse-Glimmer-30B) 重新点燃开源根基。

在前沿规模上，今年美国一些超过 100B 参数的模型发布是建立在中国模型之上的，或借用了中国实验室的产物，例如 Thinking Machines 的 [Inkling](https://huggingface.co/collections/thinkingmachines/inkling)（952B）。主要的原创美国模型包括 NVIDIA 的 [Nemotron 3 Ultra](https://huggingface.co/collections/nvidia/nvidia-nemotron-v3)（561B）、[Nemotron 3 Super](https://huggingface.co/collections/nvidia/nvidia-nemotron-v3)（124B），以及 Arcee AI 的 [Trinity-Large](https://huggingface.co/collections/arcee-ai/trinity-large-thinking)（399B）。

AMD 贡献了很多转换版本。这项工作很重要：它让万亿参数模型能在美国硬件上高效运行。这代表一个 **分发与优化层**。

与此同时，中国的开放模型越来越多地为中国国产芯片做优化——同一场竞争的反向版本：模型围绕特定硬件生态来设计。

## **2. 关注 ≠ 采用**

我们取今年累计下载量最高的前 25 个模型仓库，以及点赞数最高的前 25 个。**两个列表里同时出现的只有一个仓库。**

**[![关注和使用是两套不同的经济](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/attention-vs-usage.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/attention-vs-usage.png)**

我们统计的是窗口期内的下载而非历史累计，于是不因为某模型存在得更久就给加分，控制年龄后分裂更明显。没有一个 2026 年发布的模型进入下载榜前 25，而前 25 里有 13 个来自 2022 年。[all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2) 七个月里被拉取 15.5 亿次，对应有 5,156 个赞；[Kimi-K3](https://huggingface.co/moonshotai/Kimi-K3) 大约每收到一个赞就被拉取约 60 次。

这两个数字记录的是不同的行为。一个赞说明一次发布很重要，它流向前沿模型刚发布后的那几周。一个下载说明某物被接进了一条按计划运行的流水线，它经年累月地累积到小的、稳定的模型上。赞是解读领域在为什么兴奋的合适工具，下载则是解读它当前依赖什么的合适工具。把任意一个当作另一个的代理，是我们在对 Hub 的报道——包括我们自己早前的工作——里看到的最常见错误。同样的分裂在发布者层面也会出现。

[![谁在下载什么](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/downloads-by-lab-and-model-size.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/downloads-by-lab-and-model-size.png)

中国的前沿实验室是 Hub 上唯一由重型档位扛起下载量的账号。MiniMax 2026 年的下载实际上全部是 70B 以上的模型，Moonshot 有 88%、DeepSeek 有 55%、Z.ai 有 39%。没有哪个大型美国账号是这个样子：Google、Microsoft 和 IBM Granite 的 2026 年下载在 70B 以上的基本为零，NVIDIA 和 Meta 也只有 14% 和 9%。

差距在总下载量上更清楚。Moonshot 只做前沿的产品线全年录得 3700 万下载，而 Qwen 跨越多种尺寸的更广发布策略达到了 20.45 亿（按声明了参数量的仓库算 20.61 亿，含全部仓库），约多 55 倍。家族的持续扩张——从 2.4T 参数的 Qwen 3.8 Max 到 27B 这样的小变体——体现出同样的、覆盖不同用例的重心。

时间也起着重要作用。多数模型在发布后使用量骤降，随后是一条平稳活动的长尾。一个模型的采用很大程度上在它最初几个月里就决定了。

这有助于解释为什么今天的下载量往往不是由最新的发布驱动，而是由一小群随时间成为基础设施的模型驱动。

## **3. 开放权重改变了价值积累的位置**

如果前沿模型是一门授权生意，你会预期最大的发布附带最严格的条款。然而下面的数据讲的是另一个故事。

[![许可证不是商业模式](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/model-licenses-by-region-and-size.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/model-licenses-by-region-and-size.png)

今年 178 个超过 20B 参数的中国发布里，59% 采用 Apache 2.0、22% 采用 MIT，且 **几乎没有附带非商业限制的**。不过在最近几周，我们开始看到对于超大模型这一趋势的变化，[Kimi K3](https://huggingface.co/moonshotai/Kimi-K3) 和 [Qwen 3.8 2.4T](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B) 开始在其许可证中加入一些非商业限制和收入分成要求。

DeepSeek 和 Z.ai 以纯 MIT 发布 7000 亿到 1.65 万亿参数的模型。中国实验室给它最大的模型授权的宽松程度几乎和给最小的一样，且比美国实验室给它自己的授权更宽松：在同一尺寸段的美国一侧，29% 是 Apache 或 MIT，41% 在定制条款之下，30% 什么都不声明。

无论这些发布是为了什么，都不是许可证收入。权重以最宽松的条款送出。回报必须来自别处：**API 与云业务、硬件与平台定位，或生态位本身。** 例如 Z.ai 和 Kimi 的估值指向一种行之有效的开源战略，在社区里获得牵引力和增长机会。但展望未来，行业很可能会转向从开源采用中获得更清晰的变现路径。

## **4. Qwen 已经成为社区的基座模型**

一个模型的生态地位不仅由它自己的发布定义，还由社区在它之上构建多少来定义。如上所述，Qwen 是一个既获得关注又获得采用的例外。

[![按组织统计的 Hugging Face 派生模型](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/derivatives-by-organization.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/derivatives-by-organization.png)

数据来自 Hugging Face

按这个衡量，Qwen 已成为开放模型生态里最大的底座之一。基于 Qwen 的模型现在在 Hub 上贡献了 **151,448 个派生模型**，是 Meta 总足迹的 2.6 倍、是 Llama 仓库的 4.7 倍。Google 以 82,506 个派生模型紧随其后。第三大来源是 Unsloth，一个社区账号，发布量化和便于微调的构建，其中许多进一步扩展了 Qwen 生态。

2026 年前七个月里，Qwen 派生模型大致以 **每天 180–210 个新仓库** 的速度增长，说明采用不仅仅由单次发布驱动。Qwen 已经成了开发者决定微调和部署哪些模型时默认工作流的一部分。

有几个因素促成了这一地位。**首先是稳定性。** Qwen 保持了规律的发布节奏，持续更新其模型家族，而非依赖偶尔的旗舰发布。**其次是覆盖度。** 它在很宽的尺寸范围和用例上发布模型，让开发者无论需要小的本地模型还是更大的部署模型，都能留在同一个生态里。**第三是开放性。** Apache 2.0 授权降低了修改、再分发和商业使用的摩擦。

这些因素相互强化。一个宽的模型家族吸引更多开发者；更多开发者造出更多派生模型；而这些派生模型又让生态对未来用户更有吸引力。

这一地位很大程度上是社区建起来的。**151,448 个派生模型** 代表的是其他开发者做的下游工作，而非 Qwen 自己发布的成果。即便在 Hub 上 **28,531 个 Qwen 模型的 GGUF 转换** 里，Qwen 官方也只发布了 54 个。

## **5. 小模型仍是实用层**

在声明了参数量的模型里，1B 以下占据全部历史下载量的 83%，100B 以上只占 1%。只看 2026 年累积的下载，结果不变：3% 的量流向 70B 以上的模型。这是三月份那个最干净地经住了时间检验的发现，原因也和之前一样：小模型是唯一能在多数开发者真正拥有的硬件上跑的模型。

[![下载量仍属于小模型](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/downloads-by-model-size.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/downloads-by-model-size.png)

那一个万亿参数模型到底靠什么触达到人？靠 llama.cpp。

2 月 ggml 团队 [加入了 Hugging Face](https://huggingface.co/blog/ggml-joins-hf)，项目保持完全开源、社区治理、技术方向不变。变的是本地推理里最重要的项目如今有了持久的资源支撑。

[![2026 年 Hub 上的 llama.cpp](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/llama-cpp-hub-growth.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/llama-cpp-hub-growth.png)

上限随 llama.cpp 移动。7 月的快照里有 DeepSeek-V4-Flash 约 284B 参数的 GGUF 构建，以及 Kimi-K3 约 2.8 万亿参数的构建。本地推理过去意味着笔记本上一个 8B 模型。现在意味着跨几台消费级机器铺开的一个万亿参数 MoE——这是一年前前沿还不具备的替代路径，也是一个只押前沿的发布策略得以成立的原因。

[![人们实际在本地跑什么](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/local-downloads-by-model-family.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/local-downloads-by-model-family.png)

而这条路跑在 Qwen 上：每月 3960 万 GGUF 下载，接近 Gemma 2080 万的两倍，是 Llama 750 万的五倍多。Llama 的差距不是供给问题，源自 Llama 的 GGUF 仓库数量甚至略多于 Qwen。同样的货架，五分之一的流量。

模型仓库在这七个月里增长 21.5%。它们周围的几样东西增长快了数倍。

[![运行时层增长最快](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/runtime-layer-growth.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/runtime-layer-growth.png)

声明 gguf 库的仓库增长 464%，lerobot 增长 194%，Apple 的 mlx 增长 148%，而 transformers 和 peft 增长 16%、diffusers 增长 21%。建模核心大约以平台平均水平增长。而决定一个模型能在哪里物理上跑本地推理的那一层——本地推理格式、Apple 芯片、机器人控制栈——增长比它快三到七倍。

在十大模型家族里，背后的实验室发布极少官方 GGUF 转换。然而对本地跑模型的开发者来说，GGUF 版本往往才是被使用的那一个。在发布时提供一个官方转换、记录量化选择并对产物签名，所需额外精力有限。与其在内部维护这条工作流，实验室不妨与现有的生态贡献者如 Unsloth 协作。这样做会缩小模型创造者所测权重与更广泛社区所采用版本之间的差距。

## **6. 智能体成了新的大用户**

三月份我们还写不了这一节，因为当时还没有测量工具。7 月发布的 [agent-usage](https://huggingface.co/datasets/huggingface/agent-usage) 数据集，记录了编码智能体通过 huggingface_hub 或 hf CLI 调用 Hub 时发送的 agent/<name> token——搜索模型、推送数据集、运行 Jobs、创建 Spaces。我们第一次能看到 Hub 接收多少智能体流量、来自哪些工具。

[![调用 Hugging Face Hub 的智能体](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/agent-hub-traffic.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/state-of-open-models-summer-2026/agent-hub-traffic.png) Claude Code 以 44.4% 领跑 7 月，但单个月份掩盖了真正的发现：它在 4 月占 67.8%、5 月占 64%，而 Codex 从 10.4% 稳步爬到 20.8%。这是一个没有垄断者的市场，一次发布或一个改动的默认值就能在一个月内挪走一半流量。

第二个发现是未注册那一行。7 月近四分之一的智能体标记流量来自数据集里尚未命名的工具，而 5 月这个数字是 59.8%。从 4 月到 7 月，出现了十几个新的客户端标识。新进入者来得比任何注册表能命名的速度都快——这本身就是发现。

这一年我们花了很多精力为这个读者而非仅为人类浏览器做建设。论文从 3 月开始提供机器可读的 Markdown。4 月带来了 [把 agent trace 作为一等数据集类型](https://huggingface.co/changelog/agent-trace-viewer)，以及每个 Gradio Space 上的 agents.md 端点，于是智能体能读取 Space 的 API 并直接调用。7 月带来了我们 MCP 服务器上的 [hf_fs 工具](https://huggingface.co/changelog/mcp-improvements-jul-26)，用一千多 token 通过单一接口暴露仓库、存储、文档和论文，并可挂载沙箱做安全执行。同样的整合发生在协议层，MCP 移入了 Linux 基金会的 Agentic AI Foundation。

然后，7 月，智能体不再只是一个读者，而成了一个入侵者。看起来是第一例自主智能体自行发起持续入侵的事件发生在我们身上。当我们团队试图用前沿闭源模型分析所捕获的攻击代码时，它们的安全护栏拒绝了这项工作。分析最终是在我们自己基础设施上跑的量化开放模型 GLM-5.2 上完成的。我们发布了一份 [披露](https://huggingface.co/blog/security-incident-july-2026) 和 [完整的技术时间线](https://huggingface.co/blog/agent-intrusion-technical-timeline)。

## **展望**

与春季报告相比，权力的地理再平衡在持续加速。虽然美国开源模型仍然有竞争力，但几家中国前沿模型实验室之间的竞赛吸引了大量关注。这些前沿模型上大量的赞指向了社区最兴奋的东西，也为利用这种关注度做估值的公司带来增长机会。

然而，AI 竞赛不只是冲刺，也是一场马拉松；像 llama.cpp 这样的工具有助于把大模型部署到本地，但一个宽的模型家族及其采用仍是关键，用以在开发者、发布者和未来用户之间建立正反馈循环。被嵌入基础设施、成为生态一部分的模型，或许会在隧道尽头带来一个商业上站得住的退出。

归根结底，当智能体首次成为 HF Hub 上排名第一的用户，下一份报告看起来可能会非常不同。

在 AI 里，几个月就能重塑生态。

### **方法说明**

本分析基于 2026 年前七个月在 Hugging Face Hub 上观察到的活动。

本报告使用的指标——包括下载、赞、派生和模型发布——代表生态活动的不同方面。它们不应被解读为模型质量、商业采用或整体市场份额的直接度量。

下载表明 Hub 生态内的使用，但它们不捕捉 API 使用、私有部署或通过其他渠道分发的模型。

赞反映社区的关注和兴趣，而派生模型则提供一个开发者在既有模型之上构建多少的信号。

由于开源 AI 的采用发生在许多渠道上，Hub 活动应被视作生态发展的一个视角，而非 AI 市场的完整度量。
