我们最新的发布 Apertus 1.5，在 8B 和 70B 的 Apertus 1.0 模型基础上扩展了图像/音频理解、可选的思考模式、四倍长的上下文窗口、更好的指令遵循能力，以及更好的工具使用。更新后的[8B 和 70B 模型权重](https://huggingface.co/collections/swiss-ai/apertus-v15)已于 2026 年 7 月 24 日以 Apache 2.0 许可发布到 Hugging Face。更多细节现可从项目[技术报告](https://huggingface.co/papers/2610.15542)获取，本文做一总结。

Apertus 1.5 是在第一代模型上的持续预训练：给 8B 模型增加 4 万亿 token 的文本与多模态训练数据，给 70B 模型增加 2 万亿 token，分别达到总计 19T 和 17T。与每一次 Apertus 发布一样，这些模型完全开放：开放的[权重](https://huggingface.co/collections/swiss-ai/apertus-v15)、开放的[数据](https://github.com/swiss-ai/apertus-data-transparency/)、开放的[价值观](https://apertus-ai.org/pages/charter/)，以及完整的训练[细节](https://apertus-ai.org/pages/research/)。

## 关键增强

- *原生多模态理解：* Apertus 1.5 在接受文本的同时接受图像和音频，把文档、示意图和照片带入对话。模型也能处理口语，不过这仍是实验性的。
- *思考模式：* 模型可以切换到思考模式，在作答之前先对输入进行推理，这会提升在推理问题上的表现。
- *长上下文：* 上下文窗口增长到 262,144 token，是 Apertus 1.0 的四倍。
- *更好的指令遵循：* 比 Apertus 1.0 更遵守指令，回答更可预测、更准确。
- *更好的工具使用：* 模型针对更好的工具集成做了训练，可以更有效地使用外部工具和 API。
- *开放价值观：* 更严格地遵循 Apertus 宪章，让模型的价值观与原则保持透明。

## 训练过程

[![Apertus 1.5 训练流水线，包含四个阶段的持续预训练，随后是 SFT、长上下文 SFT、RLVR、DPO 和 SDPO](https://cdn-uploads.huggingface.co/production/uploads/650ed7adf141bc34f91a12ae/Xi58nSrPTd5_ASGNIg60g.png)](https://cdn-uploads.huggingface.co/production/uploads/650ed7adf141bc34f91a12ae/Xi58nSrPTd5_ASGNIg60g.png) *完整的 Apertus 1.5 训练流水线*

### 通过 tokenizer 实现多模态

我们在 v1.5 模型中以早期融合的方式引入多模态：图像和音频作为离散 token，与文本 token 进入 Apertus 的同一个序列，而不是使用单独的视觉编码器。图像用 [Emu3.5](https://arxiv.org/abs/2510.26583) tokenizer 分词（一张 512×512 的图像变成 1,024 个 token），音频用 [WavTokenizer](https://arxiv.org/abs/2408.16532)（每秒 40 个 token）。我们只扩展了词表，因此架构保持不变，训练以纯文本的速度运行。模型能理解图像和音频，但只生成文本。

[![image](https://cdn-uploads.huggingface.co/production/uploads/650ed7adf141bc34f91a12ae/D-7BaNY68Nigi5bTw3RH9.png)](https://cdn-uploads.huggingface.co/production/uploads/650ed7adf141bc34f91a12ae/D-7BaNY68Nigi5bTw3RH9.png)

### 预训练

从 Apertus 1.0 出发，我们分四个阶段继续预训练：

- **非配对：** 文本加上独立的图像和音频，让模型学会新的模态。
- **配对：** 图像—说明、音频—转写配对，让它把这些模态与语言对齐。
- **冷却：** 更高质量的数据，数学和代码更多。
- **长上下文：** 窗口从 8k token 逐步增长到 262k token。

总体而言，超过一半的训练 token 是纯文本，这保住了 Apertus 1.0 的语言能力。文本数据用 [FineWeb2-HQ+](https://huggingface.co/datasets/epfml/FineWeb2-HQ-Plus)、FinePDFs 和 Nemotron-CC 等来源做了刷新。所有新数据（包括多模态数据）都达到与以往相同的标准：公开可得、许可宽松，并且追溯性地尊重 robots.txt 中的退出声明。每一个来源都列在 [apertus-data-transparency](https://github.com/swiss-ai/apertus-data-transparency) 中。

### 后训练

后训练分五个阶段：**SFT → 长上下文 SFT → RL → DPO → 宪章对齐（SDPO）**。

- **SFT**，使用 370 万条文本样本以及图像和语音数据。只有模型在不加推理轨迹时还无法解决的提示词，才会补上推理轨迹。工具使用数据仅限执行验证过的轨迹。我们在 Hugging Face 上发布了所用的[文本 SFT 混合数据](https://huggingface.co/datasets/swiss-ai/Apertus-v1.5-SFT-mix)。
- **长上下文 SFT**，在完整的 262k 窗口上进行，恢复被短上下文 SFT 侵蚀掉的长上下文能力。
- **带可验证奖励的 RL（RLVR）**，使用约 35 万条数学、代码、指令遵循、多语言和视觉提示词，思考模式开与关混合。
- **DPO**，使用裁判打分的偏好对，提升对话质量、工具使用和安全性。我们发布了[偏好池](https://huggingface.co/datasets/swiss-ai/Apertus-v1.5-Preference-Pool)和[训练对](https://huggingface.co/datasets/swiss-ai/Apertus-v1.5-Preference-Data)。
- **SDPO**，通过裁判反馈与自蒸馏，让模型与 [Apertus 宪章](https://apertus-ai.org/pages/charter/)对齐。

## 评估结果

除了扩展模型能力，我们也大幅扩展了评估范围。在 Apertus 1.0 所用的既有文本评估之外，我们增加了多模态评估（图像与音频）以及思考模式评估。

[![文本性能图](https://raw.githubusercontent.com/swiss-ai/model-cards-assets/main/apertus_1.5/text_performance_plot.png)](https://raw.githubusercontent.com/swiss-ai/model-cards-assets/main/apertus_1.5/text_performance_plot.png)

多模态评估通过 [MLLM-eval-suite](https://github.com/swiss-ai/MLLM-eval-suite) 流水线完成，它合并了两大多模态评估框架 [lmms-eval](https://github.com/swiss-ai/lmms-eval) 和 [VLMEvalKit](https://github.com/swiss-ai/VLMEvalKit)。我们还增加了一系列基于文本的基准，并扩展了翻译与多语言能力、安全性以及工具使用方面的基准测试。这些都可以在我们的后训练[评估仓库](https://github.com/swiss-ai/evals-post-train)中找到，它基于 [lm-evaluation-harness fork](https://github.com/swiss-ai/lm-evaluation-harness)。

[![视觉性能图](https://raw.githubusercontent.com/swiss-ai/model-cards-assets/main/apertus_1.5/visual_performance_plot.png)](https://raw.githubusercontent.com/swiss-ai/model-cards-assets/main/apertus_1.5/visual_performance_plot.png)

尽管仍落后于前沿的开源权重模型，新发布在编码和指令遵循能力上也有显著提升，其中 Apertus 1.5 8B 在 IF 和多语言任务上超过了同等规模的开源权重模型。思考模式进一步提升了在 AIME 这类推理密集的高难度基准上的表现。模型的多模态表现更接近 [Gemma 4 12B](https://deepmind.google/models/gemma/gemma-4/) 及其他当前的开源权重模型。Apertus 1.5 的多模态表现在开源权重模型中的空间理解、在开源模型中的文档/图表理解方面都具备竞争力。

我们还要感谢合作者和外部评估者在高效评测 Apertus 能力方面给予的帮助。特别是，Apertus 1.5 在瑞士法律任务上表现强劲，与领先的开源权重模型相当（[博客](https://github.com/JoelNiklaus/SwissLegalEvals/blob/main/blog/swiss-legal-evals-2026.md)、[代码](https://github.com/JoelNiklaus/SwissLegalEvals)）。此外，在 Last Translation Benchmark 上，Apertus 1.5 8B 的机器翻译能力与 [GPT-OSS-20B](https://arxiv.org/abs/2508.10925) 相当，并超过了 [Claude Haiku 4.5](https://www.anthropic.com/claude/haiku) 或 [Google Translate](https://translate.google.com) 等模型（[排行榜](https://last-translation-benchmark.vilda.net/leaderboard-results)、[论文](https://huggingface.co/papers/2609.04173)）。

### 评估卡：Apertus ❤️ EvalEval

Apertus 与 [EvalEval 联盟](https://evalevalai.com)合作，确保基准测试完全透明且可复现。我们以 [Every Eval Ever（EEE）](https://github.com/evaleval/every_eval_ever) schema 发布 Apertus 1.5 的结果，这是一个共享格式，不仅记录分数，还记录是谁运行的评估、模型是如何访问的、生成设置，以及每个指标应当如何解读：这些细节在排行榜上常常缺失，而它们往往能解释为什么看起来相似的分数会有差异。

结果展示在下面的评估卡中，它把运行数据与基准和模型的元数据合并成一条可解读的记录，同时也可以通过 [Hugging Face Community Evals](https://huggingface.co/blog/eee-community-evals) 获取。这与[英国 AI 安全研究所用来公开其评估结果](https://huggingface.co/blog/evaleval-aisi)的是同一套基础设施。由于我们的文本评估跑在 lm-evaluation-harness 的公开 fork 上，而 EEE 为该 fork 提供了专用转换器，任何人都可以重跑这些评估，并在完全相同的设置下把自己的数字与我们的对比。

结构化的评估报告在研究之外同样重要。EvalEval 已经[把评估卡映射到 AI 治理要求](https://evalevalai.com/infrastructure/2026/09/28/mapping-evaluation-cards-to-ai-governance-requirements/)，包括 EU AI Act 第 55 条和 GPAI 行为准则，并发现 EEE schema 能够表达这些框架所要求的 60 项评估报告要素中的 56 项。这与我们发布 Apertus 的方式相一致：除模型之外，我们还发布训练内容的[公开摘要](https://github.com/swiss-ai/apertus-legal/raw/main/apertus_1.5/Apertus_1_5_EU_Public_Summary.pdf)，并自愿发布一份[行为准则](https://raw.githubusercontent.com/swiss-ai/apertus-legal/main/apertus_1.5/Apertus_1_5_EU_Code_of_Practice.pdf)文档。机器可读的评估记录是自然而然的下一步：让监管者、部署者和研究者更容易找到、解读并比较一个模型背后的证据。

我们致力于通过 Eval Cards 和 EEE schema 推动可复现、透明的评估，并鼓励其他模型开发者以同样的方式报告结果，让分数可以跨模型、跨组织比较。

## Apertus 1.5 的可复现性

所有配方、消融和数据混合都记录在[技术报告](https://arxiv.org/abs/2610.15542)中。我们希望通过公开并开放 v1.5 的训练过程，来推动开放模型开发的普及。中间 checkpoint 托管在我们的 **[Apertus 1.5 Hugging Face collection](https://huggingface.co/collections/swiss-ai/apertus-v15)** 中，包括基础权重、SFT、RLVR 和 DPO，以及我们整理好的训练数据混合/自定义数据集（在 [Apertus 1.5 datasets collection](https://huggingface.co/collections/swiss-ai/apertus-v15-datasets) 中）。共享它们让研究者可以考察每个阶段如何改变模型行为。

报告涵盖了大量关于不同阶段后训练数据影响的消融实验，我们观察到：在 SFT 阶段把多模态数据与文本数据混合在一起，有助于提升所有模态的表现。我们还发现，多模态推理轨迹带来的收益能够经受随后的纯文本强化学习：从带多模态轨迹训练的 SFT checkpoint 出发，RL 对数学的提升比从纯文本 checkpoint 出发更多，而且在推理任务上的优势贯穿整个训练过程。

## 模型可用性

[Proton Lumo](https://proton.me/support/apertus-lumo) 和 [Infomaniak Euria](https://www.infomaniak.com/en/support/faq/2924/discover-euria-and-the-apertus-model) 是最近集成 Apertus 1.5 的两个被广泛使用的应用。这些部署连同其他案例都列在 **[Community Showcase](https://apertus-ai.org/pages/get-showcase/)** 中——可以在这个[讨论帖](https://github.com/swiss-ai/www-apertus/discussions/66)里看预览。

一批提供商已经宣布以 API 形式向开发者提供 Apertus 1.5，包括 [Swisscom](https://docs.cloud.swisscom.ch/guide/cloud-services/aip/models/apertus-1_5_70B)、[Infomaniak](https://www.infomaniak.com/en/hosting/ai-services/open-source-models)、[Phoeniqs](https://documentation.kvant.cloud/maas/active-models/)，以及列在我们 **[General Availability 指南](https://apertus-ai.org/articles/2026-09-apertus-1-5-ga/)** 中的其他公司。报告还详细说明了我们如何与外部评估者合作来测试和准备这些模型。

运行模型的技术说明见 Hugging Face 上 Apertus 各发布的模型卡，以及我们的 **[快速开始指南](https://apertus-ai.org/docs/quickstart/)**。
