## 理解嵌入

嵌入是自然语言处理中最通用的工具之一，能让从业者解决大量各种各样的任务。本质上，嵌入是把更复杂的对象（如文本、图像、音频等）表示为数值的产物。

[![embedding model](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/matryoshka/embedding_model.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/matryoshka/embedding_model.png)

嵌入模型永远产生尺寸相同的固定大小嵌入。你可以计算各自嵌入之间的相似度，从而度量复杂对象的相似度！

[![embedding similarity](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/matryoshka/embedding_similarity.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/matryoshka/embedding_similarity.png)

嵌入的用途极其广泛，是推荐系统、检索、单样本或少样本学习、异常检测、相似性搜索、复述检测、聚类、分类等众多应用背后的支柱。

## 🪆 Matryoshka 嵌入

随着研究的推进，新一代最先进（文本）嵌入模型产出的嵌入维度越来越高，也就是说，每段输入文本用更多的数值来表示。虽然这提升了性能，但代价是下游任务（如搜索或分类）的效率下降。

于是，[Kusupati et al.](https://huggingface.co/papers/2205.13147)（2022）受到启发，创造了一类嵌入模型：其嵌入可以合理地压缩，而性能不会损失太多。

[![matryoshka model](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/matryoshka/matryoshka_model.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/matryoshka/matryoshka_model.png)

这些 Matryoshka 嵌入模型在训练时就让被截断的小嵌入依然有用。简而言之，Matryoshka 嵌入模型能够产出各种维度下都有用的嵌入。

## 🪆 套娃

对不熟悉的人来说："Matryoshka dolls"（套娃），也叫"俄罗斯嵌套娃娃"，是一组由大到小、可以层层嵌套的木制娃娃。类似地，Matryoshka 嵌入模型力求把更重要的信息存放在靠前的维度、把次要的信息存放在靠后的维度。这一特性让我们可以截断模型产出的原始（大）嵌入，同时仍保留足够的信息以在下游任务上取得良好表现。

[![matryoshka models](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/matryoshka/matryoshka-small.gif)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/matryoshka/matryoshka-small.gif)

## 你为什么会用 🪆 Matryoshka 嵌入模型？

这种可变尺寸嵌入模型对从业者很有价值，例如：

- **初筛与重排序**：与其在完整嵌入上执行下游任务（如最近邻搜索），不如把嵌入压缩到更小尺寸，非常高效地"初筛"你的嵌入集合。之后，再用完整维度处理剩下的嵌入。
- **权衡取舍**：Matryoshka 模型允许你按照自己想要的存储成本、处理速度和性能来调节嵌入方案的规模。

## 🪆 Matryoshka 嵌入模型是如何训练的？

### 理论

Matryoshka 表示学习（MRL）方法几乎可以用于所有嵌入模型训练框架。通常，嵌入模型的一个训练步骤包括：为你的训练批次（例如文本）生成嵌入，然后用某个损失函数得到一个损失值，用来表征生成嵌入的质量。优化器在整个训练过程中调整模型权重以降低损失值。

对于 Matryoshka 嵌入模型，训练步骤同样要为训练批次生成嵌入，但损失函数不只判断完整尺寸嵌入的质量，还会在多个不同维度上判断嵌入的质量。例如输出维度取 768、512、256、128 和 64。各维度对应的损失值相加，得到最终损失值。优化器随后会尽力调整模型权重以降低这个损失值。

在实践中，这会激励模型把最重要的信息前置到嵌入的开头，这样即使嵌入被截断，关键信息也会被保留。

### 在 Sentence Transformers 中

[Sentence Transformers](https://sbert.net) 是训练嵌入模型的常用框架，最近已实现对 Matryoshka 模型的支持。用 Sentence Transformers 训练 Matryoshka 嵌入模型非常简单：不是在仅对完整尺寸嵌入施加某个损失函数，而是把同一个损失函数也施加到嵌入的截断部分上。

例如，一个模型原来的嵌入维度是 768，现在可以在 768、512、256、128 和 64 上同时训练。每一项损失都会叠加在一起，可选地各自带上权重：

```
from sentence_transformers import SentenceTransformer
from sentence_transformers.losses import CoSENTLoss, MatryoshkaLoss

model = SentenceTransformer("microsoft/mpnet-base")

base_loss = CoSENTLoss(model=model)
loss = MatryoshkaLoss(
    model=model,
    loss=base_loss,
    matryoshka_dims=[768, 512, 256, 128, 64],
    matryoshka_weight=[1, 1, 1, 1, 1],
)

model.fit(
    train_objectives=[(train_dataset, loss)],
    ...,
)
```

使用 `MatryoshkaLoss` 训练不会带来明显的训练时长开销。

## 我该如何使用 🪆 Matryoshka 嵌入模型？

### 理论

在实践中，从 Matryoshka 嵌入模型获取嵌入的方式与普通嵌入模型完全相同。唯一的区别是：拿到嵌入后，我们可以选择把它们截断到更小的维度。需要注意的是，如果嵌入原本做过归一化，截断后就不再是归一化的了，所以你可能需要重新归一化。

截断之后，你可以直接把这些嵌入用于你的场景，或者存储起来留待后用。毕竟，向量数据库里更小的嵌入应该会带来可观的加速！

请记住：虽然把更小的嵌入用于下游任务（检索、聚类等）处理起来更快，但从模型获取小嵌入和获取大嵌入的耗时是一样的。

### 在 Sentence Transformers 中

在 Sentence Transformers 中，你可以像加载其他模型一样加载 Matryoshka 嵌入模型，但可以通过 `truncate_dim` 参数指定期望的嵌入大小。之后你就可以用 [`SentenceTransformers.encode`](https://sbert.net/docs/package_reference/SentenceTransformer.html#sentence_transformers.SentenceTransformer.encode) 函数做推理，嵌入会自动截断到指定大小。

来试试我用 [`matryoshka_nli.py`](https://github.com/UKPLab/sentence-transformers/blob/master/examples/sentence_transformer/training/matryoshka/matryoshka_nli.py) 基于 [`microsoft/mpnet-base`](https://huggingface.co/microsoft/mpnet-base) 训练的模型：

```
from sentence_transformers import SentenceTransformer
from sentence_transformers.util import cos_sim

matryoshka_dim = 64
model = SentenceTransformer("tomaarsen/mpnet-base-nli-matryoshka", truncate_dim=matryoshka_dim)

embeddings = model.encode(
    [
        "The weather is so nice!",
        "It's so sunny outside!",
        "He drove to the stadium.",
    ]
)
print(embeddings.shape)
# => (3, 64)

# Similarity of the first sentence to the other two:
similarities = cos_sim(embeddings[0], embeddings[1:])
print(similarities)
# => tensor([[0.8910, 0.1337]])
```

- 模型链接：[tomaarsen/mpnet-base-nli-matryoshka](https://huggingface.co/tomaarsen/mpnet-base-nli-matryoshka)

欢迎自行试验 `matryoshka_dim` 取不同值时相似度如何变化。你可以在本地运行这段代码，也可以在云端运行（例如用 [Google Colab](https://colab.research.google.com/#fileId=https%3A//huggingface.co/tomaarsen/mpnet-base-nli-matryoshka/blob/main/inference.ipynb)），或者查看[演示](https://huggingface.co/blog/matryoshka#demo)。

参考：

点此查看如何使用 Nomic v1.5 Matryoshka 模型

注意：Nomic 特别要求在嵌入截断之前做 `F.layer_norm`。因此下面的代码片段使用手动截断到目标维度。对于所有其他模型，你可以像上一个例子那样在构造函数中使用 `truncate_dim` 选项。

```
from sentence_transformers import SentenceTransformer
from sentence_transformers.util import cos_sim
import torch.nn.functional as F

model = SentenceTransformer("nomic-ai/nomic-embed-text-v1.5", trust_remote_code=True)

matryoshka_dim = 64
embeddings = model.encode(
    [
        "search_query: What is TSNE?",
        "search_document: t-distributed stochastic neighbor embedding (t-SNE) is a statistical method for visualizing high-dimensional data by giving each datapoint a location in a two or three-dimensional map.",
        "search_document: Amelia Mary Earhart was an American aviation pioneer and writer.",
    ],
    convert_to_tensor=True,
)
# The Nomic team uses a custom architecture, making them recommend Layer Normalization before truncation
embeddings = F.layer_norm(embeddings, normalized_shape=(embeddings.shape[1],))
embeddings[..., :matryoshka_dim]  # Shrink the embedding dimensions

similarities = cos_sim(embeddings[0], embeddings[1:])
# => tensor([[0.7154, 0.4468]])
```

- 模型链接：[nomic-ai/nomic-embed-text-v1.5](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5)

## 结果

Matryoshka 模型已经介绍完了，接下来看看 Matryoshka 嵌入模型与普通嵌入模型相比实际可以期待什么样的性能。为此实验，我训练了两个模型：

- [tomaarsen/mpnet-base-nli-matryoshka](https://huggingface.co/tomaarsen/mpnet-base-nli-matryoshka)：基于 [`microsoft/mpnet-base`](https://huggingface.co/microsoft/mpnet-base) 运行 [`matryoshka_nli.py`](https://github.com/UKPLab/sentence-transformers/blob/master/examples/sentence_transformer/training/matryoshka/matryoshka_nli.py) 训练。
- [tomaarsen/mpnet-base-nli](https://huggingface.co/tomaarsen/mpnet-base-nli)：基于 [`microsoft/mpnet-base`](https://huggingface.co/microsoft/mpnet-base) 训练，运行 [`matryoshka_nli.py`](https://github.com/UKPLab/sentence-transformers/blob/master/examples/sentence_transformer/training/matryoshka/matryoshka_nli.py) 的修改版——训练损失只用 `MultipleNegativesRankingLoss`，而不是叠加在 `MultipleNegativesRankingLoss` 之上的 `MatryoshkaLoss`。

两个模型都在 AllNLI 数据集上训练，它是 [SNLI](https://huggingface.co/datasets/snli) 和 [MultiNLI](https://huggingface.co/datasets/multi_nli) 数据集的拼接。我在 [STSBenchmark](https://huggingface.co/datasets/mteb/stsbenchmark-sts) 测试集上，用多种不同的嵌入维度对这两个模型进行了评估。结果绘制在下图中：

[![results](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/matryoshka/results.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/matryoshka/results.png)

在上图中你可以看到，在所有维度上，Matryoshka 模型的斯皮尔曼相似度都高于标准模型，表明 Matryoshka 模型在这个任务上更胜一筹。

此外，Matryoshka 模型的性能随维度下降的速度远慢于标准模型，第二张图清楚展示了这一点——它显示的是嵌入维度相对于最大性能的保持程度。**即使在嵌入尺寸的 8.3% 处，Matryoshka 模型仍保留了 98.37% 的性能**，高于标准模型的 96.46%。

这些结果表明，使用 Matryoshka 模型的截断嵌入可以：1）显著加速检索等下游任务；2）显著节省存储空间——而且性能几乎不受影响。
