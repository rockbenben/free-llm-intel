# Hugging Face 登陆 AMD Instinct MI300 GPU

> 参加 6 月 6 日的下一期 Hugging Cast，向本文作者提问，观看在 Azure 上用 MI300X 部署 Llama 3 的现场 demo，外加一个在 Ryzen AI PC 上本地部署模型的加场 demo！
> 在 https://streamyard.com/watch/iMZUvJnmz8BV 报名

## 引言

在 Hugging Face，我们希望让「用开放模型和开源构建 AI」变得简单——无论你选择什么框架、云和技术栈。其中一个关键环节，是能把 AI 模型部署到多种多样的硬件上。通过与 AMD 近一年的协作，我们正在多种加速器上投入：AMD Instinct™ 和 Radeon™ GPU、EPYC™ 和 Ryzen™ CPU、Ryzen AI NPU，确保在这支 AMD 舰队里总有一块设备能运行最大的 AI 社区。今天我们很高兴宣布：Hugging Face 与 AMD 一起完成了大量工作，让最新一代 AMD GPU 服务器——AMD Instinct MI300——在整个 Hugging Face 平台中获得一等公民级的集成。从本地环境原型开发，到在 Azure ND Mi300x V5 VM 上生产运行模型，使用 transformers[1]、text-generation-inference 及其他库都不需要改任何代码，使用 Hugging Face 产品和解决方案时也一样——我们就是想让「在 Hugging Face 上用 AMD MI300 并获得最佳性能」简单到极致。开始吧！

## 开源与生产落地

### 在 Transformers 和 text-generation-inference 中持续支持 AMD Instinct GPU

眼下 AI 领域变化太快，确保 MI300 产品线得到长期、正确的测试和监控就 absolutely 必要。为此，我们和 Hugging Face 基础设施团队紧密协作，为任何需要启用持续集成/部署（CI/CD）的人准备好健壮的构建模块，做到无痛接入、不影响已有设施。

为实现这些目标，我们与 AMD 和 Microsoft Azure 团队合作，把新近推出的 [Azure ND MI300x V5](https://techcommunity.microsoft.com/t5/azure-high-performance-computing/introducing-the-new-azure-ai-infrastructure-vm-series-nd-mi300x/ba-p/4145152) 作为面向 MI300 的基础模块。几个小时内，我们的基础设施团队就完成了部署和配置，让我们得以在 MI300 上动手操作！

我们还把旧基础设施迁到了托管 Kubernetes 集群，由它调度 Hugging Face 协作者希望在特定硬件 pod 上运行的所有 GitHub workflows。这次迁移让我们能在多种硬件平台上跑完全相同的 CI/CD 流水线，而平台细节对开发者透明。在 Azure MI300X VM 上，我们没花多大力气就在几天内让 CI/CD 跑了起来。

结果就是，transformers 和 text-generation-inference 现在会定期在上一代 AMD Instinct GPU（MI250）和最新的 MI300 上测试。实践中，数以万计的单元测试持续验证这两个仓库的状态，长期保证集成的正确与健壮。

## 提升生产 AI 负载的性能

### 推理性能

如前所述，我们一直在做的工作是：让新的 AMD Instinct MI300 GPU 通过我们的开源推理方案 text-generation-inference（TGI）高效地跑推理负载。可以把 TGI 看成三个组件：

- 传输层：主要是 HTTP，对外暴露并接收客户端的 API 请求
- 调度层：确保这些请求可以被打包成批（即 continuous batching），在不影响用户体验的前提下提高硬件计算密度
- 建模层：负责在设备上执行实际计算，调用模型所需的高度优化例程

这里，我们在 AMD 工程师的帮助下聚焦最后一个组件——建模层——实际地为服务 [Meta Llama 系列](https://huggingface.co/meta-llama)这类模型搭建、运行并优化负载。具体聚焦在：

- Flash Attention v2
- Paged Attention
- GPTQ/AWQ 压缩技术
- PyTorch 对 [ROCm TunableOp](https://github.com/pytorch/pytorch/tree/main/aten/src/ATen/cuda/tunable) 的集成
- 优化融合 kernel 的集成

这些大多已经存在一段时间了：[FlashAttention v2](https://huggingface.co/papers/2307.08691)、[PagedAttention](https://huggingface.co/papers/2309.06180) 和 [GPTQ](https://huggingface.co/papers/2210.17323)/[AWQ](https://huggingface.co/papers/2306.00978) 压缩方法（尤其是它们的优化例程/kernel）。这三个我们不展开，请移步各自的原始实现页面了解更多。

不过，面对全新的硬件平台、新发布的 SDK，仔细验证、剖析和优化每一处仍然很重要——要确保用户把这台新平台的马力全部拿到手。

最后同样重要的是，随着这次 TGI 发布，我们集成了 PyTorch 2.3 刚发布的 AMD TunableOp。TunableOp 提供了一种灵活的机制，会针对形状和数据类型寻找执行通用矩阵乘法（GEMM）最高效的方式。TunableOp 已集成进 PyTorch 并仍在积极开发，但如下文所示，它能在几乎不影响用户体验的前提下提升 GEMM 操作性能。具体而言，在输入序列很短（对应自回归模型生成的解码阶段）时，用 TunableOp 我们获得了 8-10% 的延迟提速。

实际上，每当创建一个新的 TGI 实例，我们会启动一个预热步骤：拿一些 dummy 载荷，确保模型及其内存被分配好、随时可以发力。

借助 TunableOp，我们让 GEMM 例程调优器分配一些时间，根据用户给 TGI 的参数（序列长度、最大批次大小等）寻找最优配置。预热阶段结束后，我们关掉调优器，在服务器余下的生命周期里直接利用优化后的例程。

如前所述，我们所有的基准都在 Azure ND MI300x V5（最近在 Microsoft BUILD 上发布、内置八块 AMD Instinct GPU）上运行，对照上一代 MI250 在 Meta Llama 3 70B 部署上的表现：首 token 延迟（也称 prefill）提速 2x-3x，随后的自回归解码阶段延迟提速 2x。

### 模型微调性能

Hugging Face 的库同样可用于微调模型。我们用 Transformers 和 [PEFT](https://github.com/huggingface/peft) 库，以低秩适配器（LoRA）微调 Llama 3 70B。为了在多设备间做并行，我们通过 [Accelerate 库](https://huggingface.co/docs/accelerate/usage_guides/deepspeed)使用 [DeepSpeed Zero3](https://deepspeed.readthedocs.io/en/latest/zero3.html)。

在 Llama 3 70B 上，我们的负载是 448 token 的批次、批次大小为 2。使用低秩适配器，模型原始的 70,570,090,496 个参数保持冻结，我们改为训练一个 16,384,000 参数的附加子集——得益于 [low rank adapters](https://arxiv.org/abs/2106.09685)。

在 Llama 3 70B 上的对比结果显示：与使用上一代 AMD Instinct MI250 的 HPC 服务器相比，在 MI300X 驱动的 Azure VM 上，训练速度大约快 2 倍。

[![PEFT finetuning on mi300 vs mi250](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-amd-mi300/peft_finetuning_mi300_vs_mi250.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-amd-mi300/peft_finetuning_mi300_vs_mi250.png)

*此外，由于 MI300X 拥有 192GB HBM3 内存（MI250 为 128GB），我们得以在单块设备上完整加载并微调 Meta Llama 3 70B——而 MI250 无法在 float16 或 bfloat16 下单卡装下这个约 140GB 的模型。**由于基准结果能够复现和接受挑战始终很重要，我们发布了一个[配套 GitHub 仓库](https://github.com/huggingface/hf-rocm-benchmark)，收录了采集本文所展示性能数据所用的全部工件和源码。*

## 接下来？

这些新 AMD Instinct MI300 GPU 还有一堆令人兴奋的特性在路上。未来几周我们要大力投入的重点之一，是 minifloat（即 float8 及更低精度）。这类数据布局天然以非均匀方式压缩信息，能缓解整数量化面临的一些问题。

在 LLM 推理这类场景中，这意味着 LLM 常用的 key-value cache 体积减半。之后再把 float8 存储的 KV cache 与 float8/float8 矩阵乘法组合，还能带来额外性能收益并进一步压缩内存footprint。
