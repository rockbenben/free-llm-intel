## 引言

基于 Transformer 的模型在很多 NLP 任务上都非常好用。但它有一个主要限制：时间和内存复杂度是 O(n2)O(n^2)O(n2)（其中 nnn 是序列长度）。因此，把 Transformer 模型用在 n>512n > 512n>512 的长序列上计算代价非常高。最近的若干论文，*e.g.* `Longformer`、`Performer`、`Reformer`、`Clustered attention`，都试图通过近似完整注意力矩阵来解决这个问题。如果不熟悉这些模型，可以看看 🤗 之前的博客[文章](https://huggingface.co/blog/long-range-transformers)。

`BigBird`（发表于 [论文](https://arxiv.org/abs/2007.14062)）正是解决该问题的近期模型之一。`BigBird` 依赖**块稀疏注意力（block sparse attention）**而非普通注意力（即 BERT 的注意力），能以远低于 BERT 的计算代价处理最长 **4096** 的序列。它在很多涉及超长序列的任务上取得了 SOTA，例如长文档摘要、长上下文问答。

**BigBird RoBERTa 风格**模型现已登陆 🤗 Transformers。本文的目标是让读者**深入**理解 BigBird 的实现，并让你使用 BigBird 更轻松。但进入细节之前，请记住：`BigBird` 的注意力是对 `BERT` 完整注意力的**近似**，其追求不是比 `BERT` 的完整注意力**更好**，而是更高效。它只是让 Transformer 模型能用在长得多的序列上，因为 BERT 的平方级内存需求很快就会让人受不了。简单说，如果我们有 ∞\infty∞ 的算力和 ∞\infty∞ 的时间，BERT 的注意力仍然会优于块稀疏注意力（本文要讨论的就是它）。

如果你好奇为什么处理更长序列需要更多算力，这篇博客正适合你！

使用标准 `BERT` 式注意力时，人们常有的几个问题是：

- 真的需要每个 token 都关注所有其他 token 吗？
- 为什么不对重要 token 计算注意力就算了？
- 如何判定哪些 token 重要？
- 如何高效地只关注少数 token？

本文就尝试回答这些问题。

### 应该关注哪些 token？

我们通过句子 "BigBird is now available in HuggingFace for extractive question answering" 来具体看看注意力如何工作。在 `BERT` 式注意力里，每个词都会关注所有其他 token。用数学语言表达，即每个被查询的 token query-token∈{BigBird,is,now,available,in,HuggingFace,for,extractive,question,answering} \text{query-token} \in \{\text{BigBird},\text{is},\text{now},\text{available},\text{in},\text{HuggingFace},\text{for},\text{extractive},\text{question},\text{answering}\} query-token∈{BigBird,is,now,available,in,HuggingFace,for,extractive,question,answering}，都会关注完整列表 key-tokens=[BigBird,is,now,available,in,HuggingFace,for,extractive,question,answering] \text{key-tokens} = \left[\text{BigBird},\text{is},\text{now},\text{available},\text{in},\text{HuggingFace},\text{for},\text{extractive},\text{question},\text{answering} \right]key-tokens=[BigBird,is,now,available,in,HuggingFace,for,extractive,question,answering]。

用一点伪代码来思考：被查询的 token 实际上"只应该"关注哪些合理的 key token。我们假设被查询的是 `available`，为它构造一份合理的 key token 列表。

```
>>> # let's consider following sentence as an example
>>> example = ['BigBird', 'is', 'now', 'available', 'in', 'HuggingFace', 'for', 'extractive', 'question', 'answering']

>>> # further let's assume, we're trying to understand the representation of 'available' i.e. 
>>> query_token = 'available'

>>> # We will initialize an empty `set` and fill up the tokens of our interest as we proceed in this section.
>>> key_tokens = [] # => currently 'available' token doesn't have anything to attend
```

邻近的 token 应该重要，因为在句子（词序列）中，当前词高度依赖前后的邻近词。这个直觉就是 `sliding attention`（滑窗注意力）的思想。

```
>>> # considering `window_size = 3`, we will consider 1 token to left & 1 to right of 'available'
>>> # left token: 'now' ; right token: 'in'
>>> sliding_tokens = ["now", "available", "in"]

>>> # let's update our collection with the above tokens
>>> key_tokens.append(sliding_tokens)
```

**长程依赖：** 有些任务必须捕捉 token 之间的长距离关系。*E.g.*，在问答任务中，模型需要把上下文的每个 token 与整个问题做比较，才能判断上下文的哪些部分对正确答案有用。如果大部分上下文 token 只关注其他上下文 token 而不关注问题，模型就很难从不太重要的上下文 token 中筛出重要的。

`BigBird` 提出了两种在保持计算高效的同时允许长程注意力依赖的方式。

- **Global tokens（全局 token）：** 引入一些会关注所有 token、也被所有 token 关注的 token。例如："HuggingFace is building nice libraries for easy NLP"。假设 *'building'* 被定义为全局 token，而某个任务需要模型知道 *'NLP'* 和 *'HuggingFace'* 之间的关系（注意这两个 token 位于句子两端）；这时让 *'building'* 与所有其他 token 全局互注，大概率能帮模型把 *'NLP'* 与 *'HuggingFace'* 关联起来。

```
>>> # let's assume 1st & last token to be `global`, then
>>> global_tokens = ["BigBird", "answering"]

>>> # fill up global tokens in our key tokens collection
>>> key_tokens.append(global_tokens)
```

- **Random tokens（随机 token）：** 随机选一些 token，它们通过转交给其他 token、再由后者继续转传来传递信息。这可以降低信息从一个 token 传播到另一个 token 的成本。

```
>>> # now we can choose `r` token randomly from our example sentence
>>> # let's choose 'is' assuming `r=1`
>>> random_tokens = ["is"] # Note: it is chosen compleletly randomly; so it can be anything else also.

>>> # fill random tokens to our collection
>>> key_tokens.append(random_tokens)

>>> # it's time to see what tokens are in our `key_tokens` list
>>> key_tokens
{'now', 'is', 'in', 'answering', 'available', 'BigBird'}

# Now, 'available' (query we choose in our 1st step) will attend only these tokens instead of attending the complete sequence
```

这样一来，查询 token 只关注全部 token 的一个子集，同时仍能得到完整注意力的良好近似。其他查询 token 也照此处理。但要记住，这里的核心始终是尽可能高效地近似 `BERT` 的完整注意力。单纯让每个查询 token 关注所有 key token（BERT 的做法）在现代硬件（如 GPU）上可以用一串矩阵乘法非常高效地算出来；而滑窗、全局、随机注意力的组合看起来意味着稀疏矩阵乘法，在现代硬件上更难高效实现。`BigBird` 的主要贡献之一就是提出了 `block sparse`（块稀疏）注意力机制，让滑窗、全局和随机注意力可以被高效计算。下面就来细看！

### 用图来理解为什么需要 global、sliding、random key

首先，用图来更好地理解 `global`、`sliding` 和 `random` 注意力，并理解这三种注意力的组合为何能很好地近似标准的 `Bert 式`注意力。

*上面的图分别以图的形式展示了 `global`（左）、`sliding`（中）和 `random`（右）连接。每个节点对应一个 token，每条线代表一个注意力分数。如果两个 token 之间没有连线，则注意力分数视为 0。*

[![](https://huggingface.co/blog/assets/18_big_bird/graph.gif)](https://huggingface.co/blog/assets/18_big_bird/graph.gif) ![](https://huggingface.co/blog/assets/18_big_bird/full.png)

**BigBird 块稀疏注意力**是滑窗、全局与随机连接的组合（共 10 条连接），如左侧 `gif` 所示。而**普通注意力**的图（右）会有全部 15 条连接（注意：共 6 个节点）。你可以简单地把普通注意力理解为所有 token 都全局互注 1 {}^1 1。

**普通注意力：** 模型可以在单层内直接把信息从一个 token 传到另一个 token，因为每个 token 对所有其他 token 发起查询，也被所有其他 token 关注。考虑与上图类似的例子：如果模型需要把 *'going'* 和 *'now'* 关联起来，由于两个 token 之间有直接连线，它单层就能完成。

**块稀疏注意力：** 如果模型要在两个节点（token）之间共享信息，由于并非所有节点在单层内都直接相连，对某些 token 而言信息必须沿路径经过其他若干节点才能传播。*Eg.*，假设模型需要关联 *'going'* 和 *'now'*：若只有滑窗注意力，这两个 token 间的信息流动路径是 `going -> am -> i -> now`（要经过另外 2 个 token）。因此我们可能需要多层才能覆盖整个序列的信息。普通注意力一层就能做到。极端情况下，这可能意味着需要的层数多达输入 token 数。而如果引入一些全局 token，信息可以走 `going -> i -> now`（更短）；再引入随机连接后，还能走 `going -> am -> now`。有了随机连接和全局连接，信息就能在少数几层内非常快地从一个 token 到达另一个 token。

如果全局 token 很多，也许就不需要随机连接了，因为会存在多条短路径供信息传播。这正是 BigBird 的一个变体 ETC 中把 `num_random_tokens = 0` 的想法（后文详述）。

1 {}^1 1 在这些图中我们假设注意力矩阵是对称的，**即** Aij=Aji\mathbf{A}_{ij} = \mathbf{A}_{ji}Aij​=Aji​，因为图里若 token **A** 关注 **B**，那么 **B** 也关注 **A**。从下一节展示的注意力矩阵图可以看到，对 BigBird 的大部分 token 而言这个假设成立。

| 注意力类型 | `global_tokens` | `sliding_tokens` | `random_tokens` |
| --- | --- | --- | --- |
| `original_full` | `n` | 0 | 0 |
| `block_sparse` | 2 x `block_size` | 3 x `block_size` | `num_random_blocks` x `block_size` |

*`original_full` 代表 `BERT` 的注意力，`block_sparse` 代表 `BigBird` 的注意力。好奇 `block_size` 是什么？后面会讲，这里为简单起见当作 1。*

## BigBird 块稀疏注意力

BigBird 的块稀疏注意力就是上述思路的高效实现。每个 token 关注一些**全局 token**、**滑窗 token**和**随机 token**，而不是关注**所有**其他 token。作者为多个查询分量分别硬编码了注意力矩阵，并用了一个很妙的技巧来加速 GPU 和 TPU 上的训练/推理。

[![BigBird block sparse attention](https://huggingface.co/blog/assets/18_big_bird/attn.png)](https://huggingface.co/blog/assets/18_big_bird/attn.png) *注意：上方多了 2 个句子。可以看到，每个句子中所有 token 各自被平移了一位。滑窗注意力就是这样实现的：`q[i]` 乘以 `k[i,0:3]` 就得到 `q[i]` 的滑窗注意力分数（`i` 是元素在序列中的下标）。*

`block_sparse` 注意力的真实实现可以在[这里](https://github.com/vasudevgupta7/transformers/blob/5f2d6a0c93ca2017961199aa04a344b9b779d454/src/transformers/models/big_bird/modeling_big_bird.py#L513)找到。现在看起来可能很吓人 😨😨，但这篇文章一定能让你读代码时更轻松。

### 全局注意力

全局注意力中，每个查询简单地关注序列中所有其他 token，也被所有其他 token 关注。以上图为例，假设 `Vasudev`（第 1 个 token）和 `them`（最后一个 token）是全局的。可以看到这些 token 与其他所有 token 都直接相连（蓝色方框）。

```
# pseudo code

Q -> Query martix (seq_length, head_dim)
K -> Key matrix (seq_length, head_dim)

# 1st & last token attends all other tokens
Q[0] x [K[0], K[1], K[2], ......, K[n-1]]
Q[n-1] x [K[0], K[1], K[2], ......, K[n-1]]

# 1st & last token getting attended by all other tokens
K[0] x [Q[0], Q[1], Q[2], ......, Q[n-1]]
K[n-1] x [Q[0], Q[1], Q[2], ......, Q[n-1]]
```

### 滑窗注意力

把 key token 序列复制两份，一份每个元素右移一位，另一份左移一位。然后把查询序列向量与这三份序列向量相乘，就能覆盖所有滑窗 token。计算复杂度就是 `O(3xn) = O(n)`。对照上图，橙色方框代表滑窗注意力。可以看到图顶部的 3 个序列，其中 2 个各平移了一个 token（一个左移、一个右移）。

```
# what we want to do
Q[i] x [K[i-1], K[i], K[i+1]] for i = 1:-1

# efficient implementation in code (assume dot product multiplication 👇)
[Q[0], Q[1], Q[2], ......, Q[n-2], Q[n-1]] x [K[1], K[2], K[3], ......, K[n-1], K[0]]
[Q[0], Q[1], Q[2], ......, Q[n-1]] x [K[n-1], K[0], K[1], ......, K[n-2]]
[Q[0], Q[1], Q[2], ......, Q[n-1]] x [K[0], K[1], K[2], ......, K[n-1]]

# Each sequence is getting multiplied by only 3 sequences to keep `window_size = 3`.
# Some computations might be missing; this is just a rough idea.
```

### 随机注意力

随机注意力确保每个查询 token 也会关注若干随机 token。在真实实现中，这意味着模型随机收集一些 token 并计算它们的注意力分数。

```
# r1, r2, r are some random indices; Note: r1, r2, r3 are different for each row 👇
Q[1] x [K[r1], K[r2], ......, K[r]]
.
.
.
Q[n-2] x [K[r1], K[r2], ......, K[r]]

# leaving 0th & (n-1)th token since they are already global
```

**注意：** 当前实现进一步把序列分块，所有记号都是针对"块"而非 token 定义的。下一节详细展开。

| `block_sparse` | 1024 | 2 x `T` |
|  | 4096 | 8 x `T` |

*BERT 注意力与 BigBird 块稀疏注意力在时间和空间复杂度上的对比。*

需要看计算过程的话，展开这个片段

```
BigBird time complexity = O(w x n + r x n + g x n)
BERT time complexity = O(n^2)

Assumptions:
    w = 3 x 64
    r = 3 x 64
    g = 2 x 64

When seqlen = 512
=> **time complexity in BERT = 512^2**

When seqlen = 1024
=> time complexity in BERT = (2 x 512)^2
=> **time complexity in BERT = 4 x 512^2**

=> time complexity in BigBird = (8 x 64) x (2 x 512)
=> **time complexity in BigBird = 2 x 512^2**

When seqlen = 4096
=> time complexity in BERT = (8 x 512)^2
=> **time complexity in BERT = 64 x 512^2**

=> compute in BigBird = (8 x 64) x (8 x 512)
=> compute in BigBird = 8 x (512 x 512)
=> **time complexity in BigBird = 8 x 512^2**
```

## ITC 与 ETC

BigBird 模型可以用两种策略训练：**ITC** 和 **ETC**。ITC（internal transformer construction）就是上面讲的做法。ETC（extended transformer construction）则额外把一些 token 设为全局，使它们与所有 token 互相注意。

ITC 需要更少算力，因为全局 token 很少，同时借助随机注意力模型也能捕捉到足够的全局信息。另一方面，ETC 适合需要大量全局 token 的任务，比如问答：整个 question 都应被上下文全局关注，才能把上下文与问题正确对应起来。

***注意：** BigBird 论文展示了在许多 ETC 实验中，随机块数量被设为 0。结合前面图一节的讨论，这是合理的。*

## 在 🤗 Transformers 中使用 BigBird

你可以像使用任何其他 🤗 模型一样使用 `BigBirdModel`。看几段代码：

```
from transformers import BigBirdModel

# loading bigbird from its pretrained checkpoint
model = BigBirdModel.from_pretrained("google/bigbird-roberta-base")
# This will init the model with default configuration i.e. attention_type = "block_sparse" num_random_blocks = 3, block_size = 64.
# But You can freely change these arguments with any checkpoint. These 3 arguments will just change the number of tokens each query token is going to attend.
model = BigBirdModel.from_pretrained("google/bigbird-roberta-base", num_random_blocks=2, block_size=16)

# By setting attention_type to `original_full`, BigBird will be relying on the full attention of n^2 complexity. This way BigBird is 99.9 % similar to BERT.
model = BigBirdModel.from_pretrained("google/bigbird-roberta-base", attention_type="original_full")
```

（写本文时）🤗 Hub 上一共有 **3 个 checkpoint**：[`bigbird-roberta-base`](https://huggingface.co/google/bigbird-roberta-base)、[`bigbird-roberta-large`](https://huggingface.co/google/bigbird-roberta-large)、[`bigbird-base-trivia-itc`](https://huggingface.co/google/bigbird-base-trivia-itc)。前两个来自用 `masked_lm loss` 预训练 `BigBirdForPretraining`；最后一个是在 `trivia-qa` 数据集上微调 `BigBirdForQuestionAnswering` 后的 checkpoint。

如果你更喜欢用自己的 PyTorch 训练器，下面是在自己的任务上微调 🤗 BigBird 的最简代码：

```
# let's consider our task to be question-answering as an example

from transformers import BigBirdForQuestionAnswering, BigBirdTokenizer
import torch

device = torch.device("cpu")
if torch.cuda.is_available():
    device = torch.device("cuda")

# lets initialize bigbird model from pretrained weights with randomly initialized head on its top
model = BigBirdForQuestionAnswering.from_pretrained("google/bigbird-roberta-base", block_size=64, num_random_blocks=3)
tokenizer = BigBirdTokenizer.from_pretrained("google/bigbird-roberta-base")
model.to(device)

dataset = "torch.utils.data.DataLoader object"
optimizer = "torch.optim object"
epochs = ...

# very minimal training loop
for e in range(epochs):
    for batch in dataset:
        model.train()
        batch = {k: batch[k].to(device) for k in batch}

        # forward pass
        output = model(**batch)

        # back-propogation
        output["loss"].backward()
        optimizer.step()
        optimizer.zero_grad()

# let's save final weights in a local directory
model.save_pretrained("<YOUR-WEIGHTS-DIR>")

# let's push our weights to 🤗Hub
from huggingface_hub import ModelHubMixin
ModelHubMixin.push_to_hub("<YOUR-WEIGHTS-DIR>", model_id="<YOUR-FINETUNED-ID>")

# using finetuned model for inference
question = ["How are you doing?", "How is life going?"]
context = ["<some big context having ans-1>", "<some big context having ans-2>"]
batch = tokenizer(question, context, return_tensors="pt")
batch = {k: batch[k].to(device) for k in batch}

model = BigBirdForQuestionAnswering.from_pretrained("<YOUR-FINETUNED-ID>")
model.to(device)
with torch.no_grad():
    start_logits, end_logits = model(**batch).to_tuple()
    # now decode start_logits, end_logits with what ever strategy you want.

# Note:
# This was very minimal code (in case you want to use raw PyTorch) just for showing how BigBird can be used very easily
# I would suggest using 🤗Trainer to have access for a lot of features
```

使用 BigBird 时，请牢记以下几点：

- 序列长度必须是 block size 的整数倍，即 `seqlen % block_size = 0`。不过不用担心：当 batch 的序列长度不是 `block_size` 的整数倍时，🤗 Transformers 会自动 `<pad>` 到不小于序列长度的最小整数倍。
- 目前的 HuggingFace 版本**不支持 ETC**，因此只有第 1 块和最后 1 块是全局的。
- 当前实现不支持 `num_random_blocks = 0`。
- 作者建议当序列长度 < 1024 时设置 `attention_type = "original_full"`。
- 必须满足：`seq_length > global_token + random_tokens + sliding_tokens + buffer_tokens`，其中 `global_tokens = 2 x block_size`、`sliding_tokens = 3 x block_size`、`random_tokens = num_random_blocks x block_size`、`buffer_tokens = num_random_blocks x block_size`。如果不满足，🤗 Transformers 会带警告自动切换 `attention_type` 为 `original_full`。
- 把 big bird 当解码器用（或使用 `BigBirdForCasualLM`）时，`attention_type` 应为 `original_full`。不过不用担心，如果忘了设置，🤗 Transformers 会自动切换为 `original_full`。
