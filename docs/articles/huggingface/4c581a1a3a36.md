# Accelerate ND-Parallel：高效多 GPU 训练指南

跨多个 GPU 训练大模型可能颇具挑战，原因在于各种并行策略的复杂性。在 Accelerate 中，我们与 [Axolotl](https://github.com/axolotl-ai-cloud/axolotl/) 一起集成了一种快速简便的方式，让你能在训练脚本中使用任意并行策略组合！

以下是如何把它加进你的训练脚本：

```
from transformers import AutoModelForCausalLM
from accelerate import Accelerator
from accelerate.parallelism_config import ParallelismConfig
from accelerate.utils import FullyShardedDataParallelPlugin

# configure your desired parallelisms here - this particular configuration requires at least 2 nodes with 8 GPUs each. 
# setting any parallelism degree to 1 disables it i.e. dp_replicate_size=1 disables DP.
pc = ParallelismConfig(
    dp_shard_size=2, # Fully Sharded Data Parallel degree
    dp_replicate_size=2, # Data Parallel degree
    cp_size=2, # Context Parallel degree
    tp_size=2, # Tensor Parallel degree
)

fsdp_plugin = FullyShardedDataParallelPlugin(
    fsdp_version=2,
    auto_wrap_policy="transformer_based_wrap",
    transformer_cls_names_to_wrap=["LlamaDecoderLayer"],
    state_dict_type="SHARDED_STATE_DICT",
)

accelerator = Accelerator(
    parallelism_config=pc,
    fsdp_plugin=fsdp_plugin
)

model = AutoModelForCausalLM.from_pretrained(
    "NousResearch/Hermes-3-Llama-3.1-8B", 
    device_mesh=accelerator.torch_device_mesh
)

model = accelerator.prepare(model)
```

我们还在 Accelerate 仓库中包含了一个更完整的端到端[训练脚本](https://github.com/huggingface/accelerate/blob/main/examples/torch_native_parallelism/nd_parallel.py)，演示如何设置你的数据加载器、优化器和训练循环，以及如何在训练后保存模型。

为了进一步简化大规模的模型微调，并把并行策略与多种微调技术组合起来，我们也把这一技术集成进了 Axolotl。为帮助你立即上手，我们测试了一些[示例配置](https://github.com/axolotl-ai-cloud/axolotl/tree/main/examples/distributed-parallel)，你可以按需修改它们——试一个：

```
# note: this requires a minimum world size of 16 
axolotl train examples/distributed-parallel/llama-3_1-8b-hsdp-tp.yaml
```

你也可以查看 [Axolotl ND-Parallelism 文档](https://docs.axolotl.ai/docs/nd_parallelism.html)了解更多细节——把 ND 并行技术加进你现有的配置，就像往你的 Axolotl 配置文件里添加下面一个或多个字段那么简单：

```
# Fully Sharded Data Parallel degree (note: also requires the fsdp_config field) 
# see https://docs.axolotl.ai/docs/multi-gpu.html#sec-fsdp for more details
dp_shard_size: 2
# Data Parallel degree
dp_replicate_size: 2
# Context Parallel Degree
context_parallel_size: 2
# Tensor Parallel Degree
tensor_parallel_size: 2
```

我们通过 Accelerate 中的 [`ParallelismConfig`](https://github.com/huggingface/accelerate/blob/v1.10.0/src/accelerate/parallelism_config.py) 类，或 Axolotl 中的配置字段，让配置不同并行策略的度数以及它们如何组合变得简单。但我们怎么知道哪个配置最适合自己的用例呢？当我们扩展到训练数千亿甚至数千亿参数的模型时，主要挑战来自理解各种并行策略以及它们如何相互作用以最小化跨设备的通信开销。在本文中，我们会逐步讲解各种并行策略如何工作，以及你可能想何时、如何把它们组合起来。

## 数据并行

分布式数据并行（DDP）把整个模型复制到每块设备上，并把数据均匀分成每设备一个子批次。（来源：Martynas Šubonis）。

数据并行（DP）是跨多个 GPU 训练模型最常见的技术，它把模型、梯度和优化器状态复制到每块设备，同时在 GPU 之间均匀分配数据批次，并在更新参数之前跨设备同步梯度。相比单设备训练，这能显著提升吞吐，但要求你的模型能放进单块设备。

我们可以用 Accelerate 的 `ParallelismConfig` 中的 `dp_replicate_size` 参数或 Axolotl 中的配置字段来控制模型的副本数量。值得注意的是，DP 是一种*最顶层*的并行策略，这意味着如果我们使用 `dp_replicate_size=2` 并把它与其他并行策略组合，就会有模型的 2 个副本，每个副本同样受其他并行策略影响。例如，如果我们使用 `dp_replicate_size=2` 和 `tp_size=2`，就会有模型的 2 个副本，每个副本各有 2 个张量并行分片。

> 我们用"分片（shard）"一词来描述位于单块设备上的数据，它是更大一份数据的一个划分。

## 全分片数据并行

全分片数据并行（FSDP）把模型的每个参数均匀划分到每块设备，并且像 DDP 一样把数据均匀分成每设备一个子批次。为完成一次前向和反向传播，FSDP 必须在正向/反向传播之前**收集（gather）**每个参数的权重，使每块设备获得该参数的完整副本。（来源：Martynas Šubonis）。

如果我们的模型太大、放不进单块设备怎么办？全分片数据并行（FSDP）通过把模型的权重、梯度和优化器状态分片（均匀分布）到各 GPU 上来解决这个问题（这一思路受 DeepSpeed 的 ZeRO-3 启发），同时每块设备仍然接收到完整批次中属于它的那部分。正如你从上面那张图所注意到的，与其要求每块设备都持有整个模型的完整副本，我们只在正向传播之前收集单个层的权重，之后这些权重可以再次被分片。

通过这种方式，我们用每个前向/反向传播之前收集分片参数、以及对局部梯度做归约分散（reduce-scatter）的通信开销来换取内存占用。我们可以通过调优收集参数的粒度来控制 FSDP 中的这一权衡。在一个极端，我们可以收集并重新分片模型的每一层，这会导致最低的峰值内存占用，却带来最高的通信成本。在实践中，一种常见做法是一次收集整个 transformer 解码器块的权重。

虽然我们可以做进一步的内存-计算权衡、把模型参数和梯度卸载到 CPU 来训练更大的模型，但这可能慢得令人却步。相反，让我们考虑如何有效地利用更多设备来训练更大的模型，同时保持高数据吞吐。

我们用*节点（node）*一词指代承载多块 GPU（最多 8 块）的单一机器，GPU 之间通过例如 NVLink 的快速节点内通信通道相连。当使用多个节点训练时，我们依赖机器之间相对较慢的节点间通信通道，例如 Infiniband。我们也把进程池中设备总数称为世界大小（world size）——例如单节点带 8 块 GPU 表示世界大小为 8，而 4 个节点表示世界大小为 32。

在多个节点上使用 FSDP 时，我们把跨节点的所有设备集合视为我们在单个节点上训练。例如，对 4 个各含 8 块 GPU 的节点，我们跨 32 块设备进行分片，并使用节点内和节点间两套通信后端来执行集合的 all-reduce 和 reduce-scatter 操作。以这种方式，仅 FSDP 就能扩展到相当数量的 GPU，用较大的全局批大小来提升数据吞吐。然而，会遇到某些挑战，可能要求把 FSDP 与其他并行技术组合。我们通常尽量避免在超过一个完整节点上做 FSDP，因为通信开销可能变得过高，我们如何在[混合分片数据并行](https://huggingface.co/blog/accelerate-nd-parallel#hybrid-sharded-data-parallelism)一节中应对这一点。

> 你可以把 Accelerate 的 ParallelismConfig 中的 dp_shard_size 参数与一个准备好的 FullyShardedDataParallelPlugin 一起使用，或在 Axolotl 中设置 dp_shard_size 配置字段，来设置应用于模型的 FSDP 度数。

## 张量并行

张量并行把大的线性层拆分到各设备上，通常对第一层使用列向分片、对后续层使用行向分片。这种方式只需要单个 AllReduce 通信操作来合并分片输出，在节点内跨设备分配内存和计算的同时最小化通信开销。

张量并行（TP）是一种模型并行技术，其中模型的分片永久驻留在各自独立的设备上，而与数据并行技术相反，每块设备接收一份完全相同的数据批次。TP 通过把线性层的计算分布到各设备来工作，于是每块设备只计算矩阵乘法的一部分。当存在大的线性层（例如 transformer 模型中的前馈层，它们可以被拆分到各设备）时，这种技术效果最佳。我们也能几乎不增加额外通信成本地在注意力层的每个 query、key、value 和 output 投影上使用 TP。

为了达到最佳性能，连续层的参数能以特定方式分布，以最小化所需的通信。在处理成对的线性层时，我们可以列向拆分第一层、行向拆分后续层，使我们能只需一次 all-reduce 操作来合并分片输出，从而计算结果。

与 FSDP 动态的分片行为不同，TP 创建静态的内存分区，从而带来随 TP 组大小线性缩放的恒定内存占用下降。这对那些甚至单个解码器层都大到无法在 FSDP all-gather 期间放进内存的巨型模型至关重要（回想 FSDP 中常见做法是一次收集整个解码器层的权重）。然而，与相对跨节点线性扩展（在一点范围内——同质集群上约 512 块 GPU，在低带宽连接下显著更少）的 FSDP 不同，TP 只在单个节点的边界内有效。TP 需要在计算期间设备之间频繁地同步激活，因为每块设备只计算输出的一部分，需要其他设备的输出被传输过来才能继续前向传播。因此，如果我们想在多节点设置中使用 TP，我们必须考虑把 TP 与其他并行技术组合，同时把 TP 只保持在单个节点内。由于其巨大的通信开销，对 PCIe 连接的 GPU 不推荐使用 TP。

> 在 Accelerate 中，TP 大小通过 ParallelismConfig 中的 tp_size 配置，而在 Axolotl 中你可以使用 tensor_parallel_size 配置字段。

## 上下文并行

近来，LLM 的推理能力导致序列长度暴涨，因为模型使用越来越多的 token 来解决复杂任务。要通过微调达到这种行为，我们需要一种在非常大序列长度上训练模型的方法——有时甚至能多达一百万个 token！

由于 transformer 中的注意力操作随上下文长度二次方扩展，这在单块 GPU 上变得不可能。例如，当微调一个相对小的模型（例如 Mistral-7B，使用 32 个注意力头）时，如果我们用 128k 的序列长度，单个注意力矩阵将占用 128k * 128k * 2 字节 * `num_heads=32` = ~32GB * 32 = 约 1TB 的激活内存！虽然这个例子在使用 FlashAttention 等优化注意力实现时并不现实，但它有助于说明上下文长度增加带来的内存需求增长。

借助上下文并行（CP），我们可以沿序列维度分片输入，使得每块设备只处理完整上下文的一个区块，计算完整（大得令人却步的）注意力矩阵的一个更小部分。要看这如何工作，回想注意力计算由方程描述：Attention(Q, K, V) = softmax(QK^T)V

其中 Q、K、V 分别是查询、键、值矩阵。Q 的每个查询向量（行，或输入嵌入）都必须针对整个序列中 K 的*每个*键向量计算注意力分数，以正确应用 softmax 归一化。这些注意力分数随后会与 V 中的*所有*值向量加权。

这里的关键细节在于：Q 的每一行都能彼此独立地计算其注意力分数，但每个查询向量仍然需要完整的 K 和 V 矩阵。换句话说，给定一个长度为 n 的输入，我们可以把上面的注意力方程展开为：

Attention(Q,K,V)₁ = softmax(Q₁Kᵀ)V
Attention(Q,K,V)₂ = softmax(Q₂Kᵀ)V
⋮
Attention(Q,K,V)ₙ = softmax(QₙKᵀ)V

其中我们把查询矩阵的每一行记作 Q₁, Q₂, ..., Qₙ。这可以一般化为：Attention(Q,K,V)ᵢ = softmax(QᵢKᵀ)V，对所有 i ∈ {1, 2, ..., n}。

当我们跨设备分片输入时，（由这些输入分片计算得到的）结果 Q、K、V 矩阵也会沿序列维度自动分片——每块 GPU 只为其那部分序列计算查询、键和值。例如，对 W 块 GPU 的世界长度和序列长度 n：

- GPU 0 计算 Q₁:ₙ/ᴡ、K₁:ₙ/ᴡ、V₁:ₙ/ᴡ
- GPU 1 计算 Qₙ/ᴡ₊₁:₂ₙ/ᴡ、Kₙ/ᴡ₊₁:₂ₙ/ᴡ、Vₙ/ᴡ₊₁:₂ₙ/ᴡ
- ...
- GPU (W−1) 计算 Q₍w₋₁₎ₙ/ᴡ₊₁:ₙ、K₍w₋₁₎ₙ/ᴡ₊₁:ₙ、V₍w₋₁₎ₙ/ᴡ₊₁:ₙ

我们如何确保注意力被正确计算？如上所述，每块设备只需要它自己的 Q 分片，但需要完整的 K 和 V 矩阵来正确计算注意力。我们可以通过一种叫 [RingAttention](https://openreview.net/forum?id=WsRHpHH4s0) 的技术来做到这点，它这样工作：

- 起初，每块 GPU 持有它的 Q、K、V 分片（例如 GPU 0 持有 Q₁:ₙ/ᴡ、K₁:ₙ/ᴡ、V₁:ₙ/ᴡ）。
- 然后每块 GPU 为其 Qᵢ 分片和本地 Kⱼ、Vⱼ 分片计算一个部分注意力矩阵 Aᵢ,ⱼ。
- 每块 GPU 把它的 K、V 分片发送给环中的下一块 GPU。
- 每块 GPU 从环中的上一块 GPU 接收一个不同的 K、V 分片。
- 每块 GPU 使用收到的 K、V 分片计算额外的部分注意力矩阵 Aᵢ,ⱼ₊₁、Aᵢ,ⱼ₊₂ 等。
- 每块 GPU 重复此过程，直到所有 K、V 分片都被接收、所有部分注意力矩阵 Aᵢ,* 都已计算完毕。

上下文并行把输入序列分片到各 GPU，每块设备为其分派的区段持有查询和键-值对。环形注意力（ring-attention）在各 GPU 之间循环传输 K、V 分片（由箭头所示），让每个查询能针对来自整个序列的键和值计算注意力分数。最终的注意力输出在跨设备分配内存和计算的同时，融合了来自所有序列位置的信息。

Accelerate 通过 [`accelerator.maybe_context_parallel`](https://huggingface.co/docs/accelerate/v1.10.0/en/package_reference/accelerator#accelerate.Accelerator.maybe_context_parallel) 装饰器来启用这一点，它也在 Accelerate 的[示例脚本](https://github.com/huggingface/accelerate/blob/main/examples/torch_native_parallelism/nd_parallel.py)中有展示。你也可以在我们的 [CP 概念指南](https://huggingface.co/docs/accelerate/main/en/concept_guides/context_parallelism)中了解更多关于它如何工作及其局限。

> 与 TP 类似，在 Accelerate 中 CP 大小通过 ParallelismConfig 中的 cp_size 配置，而在 Axolotl 中你可以使用 context_parallel_size 配置字段。

## ND 并行

在多节点设置中，FSDP 这样的数据并行技术把整个网络拓扑视为它沿单一维度存在。你可能会出于各种理由觉得这种方式受限：

- 当扩展到更多节点时，FSDP 的集合操作会被节点间延迟所瓶颈，使训练慢得令人却步。
- 如我们上面提到的，巨型模型可能有无法放进 GPU 内存的解码器层，或即便处于分片状态也大到无法做前向传播的层。
- 你可能无法达到理想的批大小——要么批次大到纯数据并行无法高效处理，要么小到因模型大小带来的内存约束所限。

为了尝试解决其中一些问题，我们可以把多节点集群想象成具有二维拓扑：沿一个轴是设备之间快速的节点内通信，沿另一个轴是相对较慢的节点间通信。让我们考虑如何组合我们迄今介绍的并行技术来利用这一点。

### 混合分片数据并行

混合分片数据并行（HSDP）在每个副本组内执行 FSDP，并通过 AllReduce 跨副本组同步梯度，把 FSDP 的内存效率与 DP 跨节点的通信效率结合起来。

混合分片数据并行（HSDP）是一种二维并行，它在节点内执行 FSDP、在节点之间执行 DP——也就是说模型跨每个节点被复制，而在每个节点内用 FSDP 分片。这让 FSDP 较大的通信开销利用更快的节点内链路，而 DP 把较慢的节点间通信开销最小化为单个梯度同步步骤。如果你正面对问题 1 并希望以增加内存占用为代价来加速训练，你可能会考虑这种方式。

需要强调的是，我们可以自由配置二维网络拓扑的形状，因为我们并不受限于让维度与物理节点边界对齐——你可能跨 2 个节点应用 FSDP，同时按每组 2 个节点复制，这会导致更低的内存占用但更慢的吞吐，却仍把节点内 FSDP 通信开销降低一半。这是我们鼓励你根据自己具体的硬件设置和微调需求去调的一个旋钮。

> 你可以通过在 Accelerate 的 ParallelismConfig 中同时定义 dp_shard_size 和 dp_replicate_size，或通过 Axolotl 的配置字段来启用 HSDP。

### 全分片数据并行 + 张量并行

如我们早先提到的，TP 应当在节点内应用以利用高带宽的节点内通信，因此，组合 TP 和 FSDP 涉及用 FSDP 跨节点分片模型、并在节点内用 TP 分片。在一定程度上，这可能对上述三个问题都提供一个漂亮的解法：来自 FSDP 的延迟成本可降低 8 倍，大到放不进单块设备的层现在被均匀分布到各设备，而且由于每个 TP 组接收完全相同的数据批次，我们也能把全局批大小降低 8 倍。然而，如果这仍然不够，我们无法跨节点增大 TP 大小，必须考虑另一种方案。

> 在 Accelerate 中，你可以通过在 ParallelismConfig 中同时定义 dp_shard_size 和 tp_size 来组合 TP 和 FSDP，而在 Axolotl 中你可以同时添加 dp_shard_size 和 tensor_parallel_size 配置字段。

### 全分片数据并行 + 上下文并行

这是一种组合 FSDP 和 CP 的二维并行策略，虽然由于 CP 已经与 FSDP 结合（更多原因见 [accelerate 概念指南](https://huggingface.co/docs/accelerate/main/en/concept_guides/context_parallelism)），它并不常用，但在某些情况下可能有用，例如当需要很大的序列长度时，因而需要很大的 `cp_size`。如果这仍然放不进你的内存预算，你可以在其上应用 FSDP，进一步降低内存占用。

> 在 Accelerate 中，你可以通过在 ParallelismConfig 中同时定义 dp_shard_size 和 cp_size 来组合 CP 和 FSDP，而在 Axolotl 中你可以同时添加 dp_shard_size 和 context_parallel_size 配置字段。

### 混合分片数据并行 + 张量并行

在足够大的世界大小下（注意：3D 并行的最小世界大小是 8，但它在更大规模上最有效），我们可以考虑把 HSDP 与 TP 组合，这创建一个层级：DP 首先把模型跨节点组复制，FSDP 随后在每个组内分片模型，TP 在每块节点内拆分各个层。当你面对我们上面提到的所有扩展约束时，你可能会考虑这种方式，因为它通过做内存占用与吞吐之间的权衡，提供了适应你具体训练设置的最大灵活性。

> 在 Accelerate 中，你可以通过在 ParallelismConfig 中同时定义 dp_shard_size、dp_replicate_size 和 tp_size 来组合 HSDP 和 TP。类似地，在 Axolotl 中你可以同时添加 dp_shard_size、dp_replicate_size 和 tensor_parallel_size 配置字段。

## 使用提示

还有一些我们未涵盖的组合多种并行的方式，例如 HSDP + TP + CP 的 4D 并行，但它们的工作方式与我们已经介绍的技术非常相似。最重要的是，我们鼓励你去尝试不同的技术和配置——这是获得关于你能如何做内存/吞吐权衡之各种方式的直觉的最佳途径。

下面是一些你在分布式设置中工作时可能觉得有用的额外提示：

- 当使用 FSDP 并处理大到放不进单块设备的模型时，同时启用 CPU RAM 高效加载和分片 state dict 检查点技术至关重要。你可以通过 Accelerate 的 [`FullyShardedDataParallelPlugin`](https://huggingface.co/docs/accelerate/v1.10.0/en/package_reference/utilities#accelerate.FullyShardedDataParallelPlugin) 中的 `cpu_ram_efficient_loading` 和 `state_dict_type` 参数来启用它：`fsdp2_plugin = FullyShardedDataParallelPlugin( fsdp_version=2, auto_wrap_policy="transformer_based_wrap", transformer_cls_names_to_wrap=["LlamaDecoderLayer"], state_dict_type="SHARDED_STATE_DICT", cpu_ram_efficient_loading=True )`，或通过 Axolotl 中 `fsdp_config` 里的 `cpu_ram_efficient_loading` 和 `state_dict_type` 配置字段：`fsdp_version: 2 fsdp_config: auto_wrap_policy: TRANSFORMER_BASED_WRAP transformer_layer_cls_to_wrap: LlamaDecoderLayer state_dict_type: SHARDED_STATE_DICT cpu_ram_efficient_loading: True`。
- 训练期间使用的总批大小对训练稳定性、内存占用和数据吞吐起着重要作用。当使用 DP 和/或 FSDP 时，有效批大小按如下计算：`effective_batch_size = micro_batch_size * gradient_accumulation_steps * dp_world_size`，其中 `dp_world_size = (dp_shard_size * dp_replicate_size) / tp_size`。你可以通过在训练循环中增大你的总 micro batch 大小或梯度累积步数，或在 Axolotl 中设置 `micro_batch_size` 和 `gradient_accumulation_steps` 配置字段，或通过添加更多 GPU 来增大总 `dp_world_size`，来增大你的批大小。如我们上面提到的，这施加了一个 *最小* 总批大小，即 `dp_world_size`——当使用纯 DP/FSDP 时，这将是你总的 world size，而如果它太高，减小总批大小的唯一方式就是引入张量并行。最后，在固定数量 GPU 且内存受限的场景下，我们推荐增大 `gradient_accumulation_steps` 而非 `micro_batch_size` 来实现更大的有效批大小，反之亦然。
- 相应地，当你的有效批大小因引入数据并行而增大时，你应当缩放学习率以维持训练稳定性。常见做法包括线性缩放 `scaled_lr = base_lr * (effective_batch_size / base_batch_size)` 或平方根缩放 `scaled_lr = base_lr * sqrt(effective_batch_size / base_batch_size)`。
- 当即便采用并行策略内存约束仍持续存在时，梯度检查点能通过以计算换内存来提供额外的内存节省。在前向传播期间，只有一部分激活保留在内存中（通常在 transformer 块边界处），而中间激活在反向传播期间被重新计算。这项技术与我们上面涵盖的所有并行策略都能无缝协作。在 Accelerate 中，你可以通过在 `FullyShardedDataParallelPlugin` 中设置 `activation_checkpointing=true` 来启用它：`fsdp2_plugin = FullyShardedDataParallelPlugin( fsdp_version=2, auto_wrap_policy="transformer_based_wrap", transformer_cls_names_to_wrap=["LlamaDecoderLayer"], state_dict_type="SHARDED_STATE_DICT", cpu_ram_efficient_loading=True, activation_checkpointing=True )`，在 Axolotl 中也类似：`fsdp_version: 2 fsdp_config: auto_wrap_policy: TRANSFORMER_BASED_WRAP transformer_layer_cls_to_wrap: LlamaDecoderLayer state_dict_type: SHARDED_STATE_DICT cpu_ram_efficient_loading: True activation_checkpointing: True`。请注意梯度检查点通常因激活重计算而使训练时间增加约 20-30%，但能把激活内存降低 60-80%，这使它在训练非常大的模型或使用很长序列长度时尤为宝贵。
