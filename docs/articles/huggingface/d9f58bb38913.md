# Gradio 5 安全审查

**我们对 Gradio 5 进行了审计，让你的机器学习应用更安全！**

过去几年，[Gradio](https://github.com/gradio-app/gradio/)（PyPI 月安装量超 600 万）已成为用 Python 构建机器学习 Web 应用的默认方式。只需几行代码，你就能为图像生成应用、聊天机器人或任意 ML 应用创建用户界面，*并*通过 Gradio 内置的分享链接或 [Hugging Face Spaces](https://huggingface.co/spaces) 分享给他人。

```
import gradio as gr
def generate(seed, prompt):  
    ...  
    return image
    
# gr.Interface creates a web-based UI
gr.Interface(
    generate,  
    inputs=[gr.Slider(), gr.Textbox()],  
    outputs=[gr.Image()]
).launch(share=True)  
# share=True generates a public link instantly
```

我们对 Gradio 的目标是让开发者构建在机器学习场景下开箱即用的 Web 应用。这意味着让你作为开发者可以轻松构建这样的应用：

- 轻松扩展到大量并发用户
- 尽可能多地触达各类用户（可访问性）
- 提供一致的 UI、UX 和主题
- 在大量浏览器和设备上可靠工作

……即使你并非扩展性、可访问性或 UI/UX 方面的专家！

现在，我们要在这张清单上加入 **Web 安全**。我们邀请了知名网络安全公司 [Trail of Bits](https://www.trailofbits.com/) 对 Gradio 进行独立审计。他们发现的安全问题全部在 Gradio 5 发布前修复完毕。

这意味着你用 Gradio 5 **构建的**机器学习应用，**将在 Web 安全方面遵循最佳实践**，而你的代码无需重大改动。

## 为什么做安全审计？

过去两年，Gradio 团队与社区一起，在发现安全漏洞时及时修补。但随着 Gradio 的流行度增长（目前 Hugging Face Spaces 上有超过 47 万个 Gradio 应用），确保安全变得更加重要。

因此在 Gradio 5 中，我们决定换一种思路——对 Gradio 代码库做一次*先发制人的*安全审计，让你用 Gradio 5 构建的机器学习应用默认就是安全的。

我们请 Trail of Bits 对 Gradio 进行一次独立而全面的审计。他们 AI 与应用安全领域的专家团队在 4 类总体场景中识别出了 Gradio 代码库的安全风险：

- 在本地运行的 Gradio 应用
- 部署在 Hugging Face Spaces 或其他服务器上的 Gradio 应用
- 通过内置分享链接共享的 Gradio 应用
- 源自 Gradio CI 管道的供应链漏洞

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/gradio-5/security-scenarios.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/gradio-5/security-scenarios.png)

随后，我们与 Trail of Bits 紧密合作，为每一项风险制定缓解策略。Gradio 的简单好用对开发者是优点，但也带来了独特的安全挑战——因为我们不希望开发者必须配置 CORS、CSP 策略这类复杂的安全措施。

合作结束时，Trail of Bits 识别出的所有安全风险都已修复。所有修复均经 Trail of Bits 验证，并包含在 Gradio 5.0 发布版中。虽然不可能证明漏洞完全不存在，但这是给你的 Gradio 应用提供安全保障的重要一步。

## 主要发现

下面列出 Trail of Bits 在上述 4 类场景中发现的主要安全漏洞。本着透明和开源精神，我们公开了[完整安全报告](https://github.com/trailofbits/publications/blob/master/reviews/2024-10-huggingface-gradio-securityreview.pdf)，每个问题的更多细节都可以在报告中找到。

**在本地运行的 Gradio 应用**

- **TOB-GRADIO-1** 和 **TOB-GRADIO-2**：服务器 CORS 策略配置错误。在已认证的 Gradio 服务器上下文中，攻击者可以窃取访问 token，并在受害者访问其恶意网站时接管其账号。

**部署在 Hugging Face Spaces 或其他服务器上的 Gradio 应用**

- **TOB-GRADIO-3**：一个基于 GET 的完整读取型 SSRF，可让攻击者向任意端点发起请求并读取响应，包括用户内网中的端点。
- **TOB-GRADIO-10**：任意文件类型上传，攻击者可借此在用户的 Gradio 服务器上托管 XSS 载荷。在已认证的 Gradio 服务器上下文中，攻击者可利用它在受害者访问恶意网站时接管其账号。
- **TOB-GRADIO-13**：一个竞态条件，允许攻击者把用户流量重定向到其服务器，窃取上传的文件或聊天机器人对话。
- **TOB-GRADIO-16**：若干组件的后处理函数在非常简单的 Gradio 服务器配置下可能泄露任意文件。

**通过内置分享链接共享的 Gradio 应用**

- **TOB-GRADIO-19**：通过一处暴露未认证 docker API 的 nginx 配置错误，在 Gradio API Server 上以 root 用户实现远程代码执行（RCE）。攻击者可在图示第 2 步提供恶意的 host 和 port，把所有 frp 隧道重定向到一台记录全部用户流量（包括上传文件和聊天内容）的恶意服务器。
- **TOB-GRADIO-11**：frp-client 与 frp-server 之间通信缺乏强健加密，使处于能拦截请求（图中第 6、7 步）位置的攻击者可以读取和修改进出 frp-server 的数据。

**源自 Gradio CI 管道的供应链漏洞**

- **TOB-GRADIO-25**：Gradio 仓库中若干 GitHub Actions 工作流使用固定在 tag 或分支名（而非完整 commit SHA）上的第三方 action。恶意行为者可借此悄悄修改这些 action，可能导致应用发布被篡改或密钥泄露。
- 另外，一位 [GitHub 安全研究员报告](https://github.com/gradio-app/gradio/security/advisories/GHSA-48pj-2428-pp3w)称，如果攻击者触发某个 workflow 并巧妙地转储 GitHub runner 的内存，我们的 GitHub actions 可能被用于执行不可信代码并窃取密钥。

## 未来

我们非常感谢 Trail of Bits 对 Gradio 的全面安全审计，以及对他们为 Gradio 5 提出的缓解措施的验证。

未来，我们计划继续与安全社区协作，发现并缓解 Gradio 中的安全问题。我们还向测试套件加入了安全单元测试和专门用于发现潜在漏洞的模糊测试（fuzzer），并在 CI 中使用 Semgrep 等静态分析工具来检测常见安全问题、防止安全回退。

我们承诺，在继续开发 Gradio 5（[我们有很多计划！](https://huggingface.co/blog/gradio-5)）的过程中，始终把安全放在优先位置，尽我们所能让机器学习应用更好、更安全。
