# 推出 SyGra Studio

[SyGra 2.0.0](https://huggingface.co/blog/ServiceNow-AI/sygra-v2) 引入了 **Studio**，一个把合成数据生成变成透明、可视化技艺的交互式环境。你不再要手忙脚乱地应付 YAML 文件和终端，而是直接在画布上编排流程，在提交前预览数据集，用内联变量提示来调优提示词，并实时观看执行流——一切都在一个窗格里完成。其底层是同一个平台，所以你做的每一项可视化操作都会生成相应的、SyGra 兼容的图配置和任务执行器脚本。

### Studio 能让你做什么

- 用引导式表单配置并验证模型（OpenAI、Azure OpenAI、Ollama、Vertex、Bedrock、vLLM、自定义端点）。
- 连接 Hugging Face、文件系统或 ServiceNow 数据源，并在执行前预览行。
- 通过选择模型、编写提示（带自动建议的变量）以及定义输出或结构化 schema 来配置节点。
- 使用共享状态变量和基于 Pydantic 的映射来设计下游输出。
- 端到端执行流程，并即刻以节点级进度查看生成的结果。
- 用内联日志、断点、基于 Monaco 的代码编辑器和自动保存的草稿来调试。
- 用存储在 `.executions/` 中的执行历史监控每次运行的 token 成本、延迟和护栏结果。

我们一步步走过这个体验。

## 第 1 步：配置数据源

打开 Studio，点击 **Create Flow**，Start/End 节点会自动出现。在添加其他任何东西之前：

- 选择一个连接器（Hugging Face、磁盘或 ServiceNow）。
- 输入诸如 `repo_id`、split 或文件路径等参数，然后点击 **Preview** 获取样例行。
- 列名会立即变成状态变量（例如 `{prompt}`、`{genre}`），于是你确切地知道在提示和处理内部能引用什么。

一旦验证通过，Studio 会让配置保持同步，并把这些变量贯穿整个流程——无需手动接线或猜测。

## 第 2 步：可视化地构建流程

从调色板拖入你需要的区块。对于一个故事生成流水线：

- 拖入一个名为 "Story Generator" 的 **LLM 节点**，选择一个已配置的模型（例如 `gpt-4o-mini`），写出提示，并把结果存储到 `story_body`。
- 添加第二个名为 "Story Summarizer" 的 **LLM 节点**，在提示中引用 `{story_body}`，并输出到 `story_summary`。
- 切换结构化输出、附着工具，或添加 Lambda/Subgraph 节点，如果你需要可复用逻辑或分支行为。

Studio 的详情面板让一切都在上下文中——模型参数、提示编辑器、工具配置、前后处理代码，甚至当你想要并行生成时的多 LLM 设置。在提示内输入 `{` 会立即浮出所有可用的状态变量。

## 第 3 步：检查并运行

打开 **Code Panel** 来查看 Studio 正在生成的确切 YAML/JSON。这与写入 `tasks/examples/` 的是同一份产物，所以你看到的就是会被提交的东西。

当你准备好执行时：

- 点击 **Run Workflow**。
- 选择记录数、批大小、重试行为等。
- 按下 **Run**，观看 Execution 面板实时流式呈现节点状态、token 用量、延迟和成本。详细日志提供可观测性，让调试毫不费力。所有执行都被写入 `.executions/runs/*.json`。

运行之后，下载输出、与既往执行对比、获取延迟和用量详情的元数据。

## 运行现有工作流

### 运行 Glaive Code Assistant 工作流

SyGra Studio 也能执行 `tasks` 中已有的工作流。例如，在 `tasks/examples/glaive_code_assistant/` [工作流](https://github.com/ServiceNow/SyGra/tree/v2.0.0/tasks/examples/glaive_code_assistant) 中——它摄入 `glaiveai/glaive-code-assistant-v2` [数据集](https://huggingface.co/datasets/glaiveai/glaive-code-assistant-v2)，起草回答、对其进行批评，并循环直到批评返回 "NO MORE FEEDBACK"。

在 Studio 内你会注意到：

- **画布布局** – 两个 LLM 节点（`generate_answer` 和 `critique_answer`）由一条条件边连接，该边要么回流做更多修订，要么在批评满意时退出到 **END**。
- **可调输入** – Run 模态框让你切换数据集 split、调整批大小、限制记录数，或微调温度，而无需碰 YAML。
- **可观测的执行** – 观看两个节点依次亮起，检查中间的批评，并实时监控状态。
- **生成的输出** – 合成数据被生成，可直接用于模型训练、评估流水线或标注工具。

## 开始使用

```
git clone https://github.com/ServiceNow/SyGra.git
cd SyGra && make studio
```
