# Nemotron 3.5 内容安全：面向全球企业 AI 的可定制多模态安全

过去两年，NVIDIA 的内容安全技术栈从一个专注英语文本的分类器，成长为一个专精模型家族——每一个新成员都把覆盖面扩展到新的模态、语言和推理模式。2026 年 3 月发布的 [Nemotron 3 Content Safety](https://huggingface.co/nvidia/Nemotron-3-Content-Safety) 首次在单个 40 亿参数模型中融合了多模态与多语言能力。今天，我们发布 [Nemotron 3.5 Content Safety](https://huggingface.co/nvidia/Nemotron-3.5-Content-Safety)，为这条演进路线画上句点：一个模型统一多模态输入、多语言覆盖、企业自定义策略执行和可审计推理，全部在一次推理调用内完成。

本文介绍 3.5 的变化、每项新能力背后的设计决策，以及如何把模型集成进生产安全流水线。

## Nemotron 3.5 Content Safety 的新特性

### 1. 统一的多模态评估

Nemotron 3 引入了图像理解；Nemotron 3.5 把多模态融合做得更深。模型把**用户提示词、可选图像和可选 assistant 回复**当作同一个上下文窗口，对合并后的输入给出连贯的安全结论。把三者放在一起评估——而不是各自独立打分——补上了多模态安全场景中一个众所周知的漏洞：只有当文本与图像之间、或请求与回复之间*相互作用*时才显现的策略违规，现在一遍就能抓住。

### 2. 全球语言覆盖

Nemotron 3.5 维持了前代 12 种语言的显式训练覆盖——**英语、法语、西班牙语、德语、中文、日语、韩语、阿拉伯语、印地语、俄语、葡萄牙语和意大利语**——同时继承 Gemma 3 基础模型在约 140 种语言上的强 zero-shot 泛化能力。这意味着在训练数据稀缺的市场（如东南亚语言、北欧语言、低资源非洲语言）部署时，也能享受基础模型的多语言迁移，无需单独微调。

### 3. 自定义策略执行

这是 3.5 相对 Nemotron 3 最重要的架构新增。生产部署几乎不会只跑在一套通用安全分类体系下。医疗平台的风险画像与金融服务聊天机器人、开发者工具 IDE 或儿童教育应用截然不同。Nemotron 3.5 接受随输入一起提供的自定义策略说明。模型在给出结论时会针对该策略推理，而不是完全依赖内置分类体系。这把首次在 [Nemotron Content Safety Reasoning 4B](https://huggingface.co/nvidia/Nemotron-Content-Safety-Reasoning-4B) 中引入的工作扩展到了完整的多模态、多语言场景。

### 4. 推理轨迹（THINK 模式）

Nemotron 3.5 的每个安全结论都可以通过可选的 **think 模式**附上一段可审计的推理轨迹。启用时，模型在给出最终 `safe` / `unsafe` 标签（以及可选的违规类别）之前，先输出它的逐步推理。

```
<think>
The user prompt asks for guidance on acquiring a controlled substance without a prescription.
The assistant response provides specific sourcing steps and references an online marketplace.
This interaction violates the Criminal Planning/Confessions and Controlled Substances categories.
The image (a pharmacy exterior) provides locational context but does not alter the verdict.
</think>

User Safety: unsafe
Response Safety: unsafe
Safety Categories: Criminal Planning/Confessions, Controlled Substances
```

当延迟是首要约束时，可以关闭 THINK 模式，回到 Nemotron 3 同款的低延迟二元结论。

### 5. 安全数据集

伴随 Nemotron 3.5，我们一并发布安全数据集。这是一个重要里程碑，因为大多数开源安全模型通常不提供训练集或评估集。在多模态领域这个问题更严重——图像、视频这类素材往往来自许可条款严格的资源。Nemotron 3.5 Content Safety 数据集是多模态、多语言的，并包含用于训练模型的推理性安全轨迹。这些推理轨迹以两步方式生成，力求精炼，方式与 [Nemotron Content Safety Reasoning 4B](https://huggingface.co/nvidia/Nemotron-Content-Safety-Reasoning-4B) 类似。

## 模型架构

Nemotron 3.5 Content Safety 基于 **Google Gemma 3 4B IT**（40 亿参数）构建，拥有 128K 上下文窗口、强视觉-语言推理和广泛的多语言覆盖。NVIDIA 用一个 LoRA adapter 对该基础模型微调，植入针对性的安全分类行为，同时保持模型足够紧凑，可在 8GB+ 显存的 GPU 上实时部署。

推理接口支持三种输出模式：

**模式 1 —— 低延迟二元结论：**

```
User Safety: safe
Response Safety: unsafe
```

**模式 2 —— 带类别的二元结论：**

```
User Safety: safe
Response Safety: unsafe
Safety Categories: Violence, Criminal Planning/Confessions
```

**模式 3 —— THINK 模式（推理 + 结论）：**

```
<think>
[step-by-step reasoning trace]
</think>

User Safety: unsafe
Response Safety: unsafe
Safety Categories: [categories]
```

安全分类体系沿用 **Aegis 2.0** 框架：与 MLCommons 安全分类体系对齐的 13 个核心类别，外加 10 个细分子类别。这种对齐使得可以直接与在 Aegis 分类数据集上评测的其他开放/封闭护栏系统比较。

## 推理

推理是内容安全分类的强力加速器，因为它为生产 AI 系统——尤其是企业和受监管环境——提供了必要的上下文、定制化与可问责性。

**支持自定义与情境化的策略执行**

推理让内容安全模型能够在推理时动态解读并执行以自然语言定义的、领域特定的自定义策略。这之所以必要，是因为生产部署几乎不会只运行在单一通用安全分类体系下。金融服务聊天机器人的风险画像与儿童教育应用不同，后者的脏话容忍度可能更低。该能力支持：

- **类别抑制：** 禁用无关类别，例如避免 DevOps 工具在处理 "terminate a process"（终止进程）这样的短语时触发 "violence"（暴力）类别。
- **自定义类别注入：** 定义一个组织监管或产品政策特有的专有风险类别。

**提供可审计、有记录的判断依据**

推理轨迹展示模型在给出最终 safe/unsafe 结论前的逐步逻辑。这份有据可查的说明有诸多用途：

- **合规与审计日志：** 受监管行业通常要求内容审核决策有书面依据。
- **人工复核：** 审核员可以审计结论*为什么*这样下，从而发现系统性模型错误。
- **政策迭代：** 轨迹揭示模型如何解读边界案例，让团队得以逐步打磨自定义策略文本。

**延迟**

推理虽然会带来延迟，但 Nemotron 模型通过把推理链浓缩成简明摘要来限制输出 token 数、提升效率。这采用两步流程，与前作 [Nemotron-Content-Safety-Reasoning-4B](https://huggingface.co/nvidia/Nemotron-Content-Safety-Reasoning-4B) 一致。第一步，用更大更强的模型（如 Qwen 397B），基于给定的提示词、图像和回复生成思维链推理轨迹。我们同时提供样本的真值标签，避免任何错分混入推理轨迹。第二步，再用另一个大模型（如 Qwen 80B）把这些推理轨迹改写得更加精炼。我们明确要求该模型将原始轨迹（来自第一步）转述为不超过 3 句话。根据我们的实验，生成的推理轨迹大多数都在 3 句以内。

这种高效推理轨迹优化让低延迟的自定义策略执行成为可能。此外，推理轨迹本身就是有价值的训练信号，可用于训练专门的审核员模型。开发者可以选择双模式运行：通用任务关闭推理追求最低延迟，复杂策略则启用推理。

## 训练数据

驱动 Nemotron 3.5 的数据集是 Nemotron 3 所用多模态、多语言混合数据的演进版，并新增了面向推理与自定义策略能力的数据。我们使用了以下数据来源：

- 来自 [Nemotron Safety Guard Dataset v3](https://huggingface.co/datasets/nvidia/Nemotron-Safety-Guard-Dataset-v3) 的**多语言文本安全数据**，从具有文化细腻度的子集中采样，各安全类别和 safe/unsafe 比例均衡。
- 由 NVIDIA 以英语采集、翻译为 12 种语言的**人工标注多模态数据**。至关重要的是，**99% 的训练图像是真实照片**——不是合成生成。这直接回应了多模态安全基准领域的一个已知弱点：现有数据集如 VLGuard 和 MM-SafetyBench 大量依赖 SDXL 生成的图像，缺少生产内容所具有的文化质感与对抗复杂性。虽然这些真实图像并非全部可以发布（受许可限制），我们仍释出了来自 Wikimedia 的一个图像子集及合成生成部分。
- 来自 [Nemotron VLM Dataset v2](https://huggingface.co/datasets/nvidia/Nemotron-VLM-Dataset-v2) 的**安全多模态数据**，涵盖扫描文档、图表、论文和图示及配套查询——确保模型不会误伤良性的专业内容。
- **推理轨迹**来自更大教师模型（Qwen 397B）产出的思维链，再用 Qwen 80B 缩短——用于教会模型如何推理。
- 来自 [CantTalkAboutThis](https://huggingface.co/datasets/nvidia/CantTalkAboutThis-Topic-Control-Dataset) 数据集的**话题遵循数据**，由一系列企业部署场景（医疗、金融、银行、教育等）下的策略说明/结论对构成。
- **合成数据**约占总训练量 10%，主要用于多样化越狱（jailbreak）模式、生成罕见策略违规案例，以及制作多模态对抗样本。

## 基准测试

Nemotron 3.5 Content Safety 在覆盖多语言、多模态和自定义策略的安全基准上做了评估，包括 VLGuard、MM-SafetyBench、PolyGuard、RTP-LX、Aya Redteaming、XSafety、MultiJail、Aegis、Dynaguardrail 和 CoSA。这些评估反映的是企业安全的核心生产挑战：在全球语言、文本与图像输入、领域特定策略之上应用一致的护栏，同时不显著增加延迟。

Nemotron 3 曾打下强基线：多模态有害内容测试平均准确率 84%，延迟约为 LlamaGuard-4-12B 的一半。Nemotron 3.5 保持 4B 的紧凑高效，同时新增自定义策略支持与推理轨迹。

在跨多语言与多模态安全基准上，Nemotron 3.5 在保持紧凑规模的同时，交出了强劲的有害内容分类准确率。这一点很重要，因为许多安全模型要么英语优先、要么纯文本、要么在生产流水线里反复跑的成本过高。Nemotron 3.5 的设计目标就是把多语言覆盖、多模态分类、自定义策略支持和低延迟部署合入一个模型。

## 延迟

默认（无 THINK）模式的延迟表现与 Nemotron 3 一致。THINK 模式会按轨迹长度成比例增加推理时间，但这部分开销是可预测的，可以和同步审核循环分开预算——例如，把 THINK 模式评估作为审计流水线的一部分异步运行，默认模式负责实时决策。

[![figure4](https://cdn-uploads.huggingface.co/production/uploads/644c4b804ef896a09019a5b4/5drKmlTOcLxVobY03RJ7_.png)](https://cdn-uploads.huggingface.co/production/uploads/644c4b804ef896a09019a5b4/5drKmlTOcLxVobY03RJ7_.png) *图 4. 在多模态基准上，Nemotron 3.5 Content Safety 的端到端延迟比另一种多模态安全模型低 3 倍。*

与另一个推理型安全模型相比，我们的模型在启用推理时生成的 token 数最多少 50%，在成本和延迟上更高效。

## 正视基准测试的鸿沟

多模态安全研究里一个反复出现的主题，是现有评估基础设施的缺口。Nemotron 3.5 的开发过程中也遇到了文献中记录的同样缺口：

- **只有文本**：被引用最多的安全基准（WildGuard、XSTest、HarmBench）都是纯文本的。多模态表现无法从文本基准结果推断。
- **合成图像质量**：现有多数多模态基准使用 AI 生成图像（通常是 SDXL）而非真实照片，低估了真实生产内容的难度。
- **真实图像的授权**：图库照片的许可禁止在 AI 数据集中再分发，在研究与生产条件之间造成结构性缺口。

NVIDIA 的多模态训练数据——真实图像加文化细腻的多语言提示词——正是为补上模型训练侧的部分缺口而设计。评估侧的基准缺口，仍是整个安全研究社区待解的开放问题。

## 快速上手

Nemotron 3.5 Content Safety 已在 [Hugging Face](https://huggingface.co/nvidia/Nemotron-3.5-Content-Safety) 上架，以 NVIDIA 开放模型许可证授权，研究与商用皆可，同时发布训练[数据集](https://huggingface.co/datasets/nvidia/Nemotron-3.5-Content-Safety-Dataset)。它支持 transformers、vLLM 和 SGLang，并以生产级 [NVIDIA NIM](https://nvcr.io/nim/nvidia/nemotron-3.5-content-safety:2.0.5-variant) 的形式在 build.nvidia.com 提供，适合需要预打包、GPU 优化推理微服务的团队。

开发者还可以通过多个推理平台访问该模型，包括 [Baseten](https://www.baseten.co/library/nemotron-3-5-content-safety/)、[Eigen AI](https://www.eigenai.com/blog/2026-06-04-eigenai-delivers-day-0-inference-nvidia-nemotron-3-x-family-ultra-asr-content-safety)、[DeepInfra](https://deepinfra.com/nvidia/Nemotron-Content-Safety-3.5)、[OpenRouter](https://openrouter.ai/nvidia/nemotron-3.5-content-safety:free) 和 [Vultr](https://blogs.vultr.com/nemotron-3-5-content-safety)。

针对自定义策略工作流，NVIDIA 提供一个兼容 Claude 与 Codex 的[自定义策略生成 skill](https://github.com/NVIDIA-NeMo/Nemotron/tree/main/skills/nemotron-policy-generator)，以及展示模型用法的 [cookbook](https://github.com/NVIDIA-NeMo/Nemotron/tree/main/usage-cookbook/Nemotron-3.5-Content-Safety)。自定义策略与推理轨迹帮助团队把安全行为适配到领域特定规则，同时让决策保持可审计。
