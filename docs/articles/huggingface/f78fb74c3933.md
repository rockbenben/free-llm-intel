# 将 Artificial Analysis LLM 性能榜单带上 Hugging Face

用 LLM 构建应用需要考虑的不止质量：对许多用例来说，速度和价格同样重要，甚至更重要。

对消费级应用和聊天体验而言，速度和响应性对用户参与度至关重要。用户期望近乎即时的响应，延迟会直接导致参与度下降。在构建涉及工具调用或 agentic 系统的更复杂应用时，速度和成本变得更加重要，甚至可能成为整个系统能力的瓶颈。对 LLM 的串行请求耗时在每个用户请求中会迅速累积，推高成本。

这正是 [Artificial Analysis](https://artificialanalysis.ai/)（[@ArtificialAnlys](https://twitter.com/ArtificialAnlys)）开发一份榜单的原因——该榜单在 100 多个 serverless LLM API 端点上评估价格、速度和质量，如今登陆 Hugging Face。

榜单在[这里](https://huggingface.co/spaces/ArtificialAnalysis/LLM-Performance-Leaderboard)！

## LLM 性能榜单

LLM 性能榜单旨在提供全面的指标，帮助 AI 工程师决策：在 AI 应用中该使用哪些 LLM（开放与专有皆有）以及哪些 API 提供商。

工程师在选择要使用的 AI 技术时，需要考虑质量、价格和速度（延迟与吞吐）。LLM 性能榜单把三者聚在一处，让专有与开放模型的决策在同一平台完成。

### 指标覆盖

报告的指标包括：

- **质量（Quality）：**用于比较模型质量与准确度的简化指数，基于模型作者报告的 MMLU、MT-Bench、HumanEval 分数以及 Chatbot Arena 排名等指标计算。
- **上下文窗口（Context window）：**LLM 单次可处理的最大 token 数（包括输入与输出 token）。
- **价格（Pricing）：**提供商查询模型推理的收费。我们报告输入/输出每 token 价格，以及用于以单一指标比较托管提供商的"混合"价格。输入与输出价格按 3:1 混合（即假设输入长度是输出的 3 倍）。
- **吞吐（Throughput）：**端点在推理期间输出 token 的速度，以每秒 token 数衡量（常称 tokens/s 或 "TPS"）。我们报告过去 14 天测量的中位数、P5、P25、P75 和 P95。
- **延迟（Latency）：**请求发出后端点开始响应所需的时间，即首 token 时间（"TTFT"），以秒衡量。我们报告过去 14 天测量的中位数、P5、P25、P75 和 P95。

更多定义见我们的[完整方法页](https://artificialanalysis.ai/methodology)。

### 测试负载

榜单支持在多种负载（共 6 种组合）下探索性能：

- 变化 **prompt 长度**：约 100 token、约 1k token、约 10k token。
- 运行**并行查询**：1 个查询、10 个并行查询。

### 方法

我们每天对榜单上的每个 API 端点测试 8 次，榜单数字代表过去 14 天测量的中位数。折叠标签内还有百分位细分。

质量指标目前按模型收集，展示模型创作者报告的结果；随着我们开始分享对各端点独立的质量评估结果，请持续关注。

## 亮点（2024 年 5 月，最新数据请查看榜单）

- 过去一年语言模型市场的复杂度爆发式增长。仅最近两个月内震动市场的发布，既有 Anthropic Claude 3 系列这类专有模型，也有 Databricks DBRX、Cohere Command R Plus、Google Gemma、Microsoft Phi-3、Mistral Mixtral 8x22B、Meta Llama 3 等开放模型。
- 模型与提供商之间的价格和速度差异巨大。从 Claude 3 Opus 到 Llama 3 8B，价格相差 300 倍——超过两个数量级！
- API 提供商发布模型的速度在加快。Llama 3 发布 48 小时内就有 7 家提供商上架。这既体现了对新开放模型的旺盛需求，也反映了 API 提供商之间的竞争态势。

## 用例：速度与价格可以和质量同等重要

在某些情况下，用更快更便宜的模型发起多次请求的设计模式，不仅成本更低，整体系统质量也可能优于使用单个更大模型。

例如，考虑一个需要浏览网页、从近期新闻中查找相关信息的聊天机器人。一种做法是用 GPT-4 Turbo 这样的大而高质量的模型执行搜索，然后阅读并处理排名靠前的几篇文章。另一种做法是用 Llama 3 8B 这样更小更快的模型并行阅读几十张网页并提取要点，然后再用 GPT-4 Turbo 评估并总结最相关的结果。第二种方法即使算上多读 10 倍内容，成本效益也更高，且可能带来更高质量的结果。
