如果你曾经试着在 TPU 上运行 PyTorch，那你大概是把代码移植到了 `torch_xla`，或者最后不得不去学 JAX。有了 [TorchTPU](https://github.com/google-pytorch/torch_tpu) 这个原生 PyTorch 后端，TPU 现在只是又一个设备而已。它为 Hugging Face 生态打开了 TPU 的原生支持。Transformers、Diffusers 和 Kernels 都能在 TPU 上原生运行。从 Hub 里挑一个模型，把它送到 `"tpu"`，就完成了。

## 等等，TPU 是什么？🤔

TPU 是 [Tensor Processing Unit](https://cloud.google.com/tpu) 的缩写。TPU 是 Google 自家的 AI 加速器。它们是专为一项工作打造的芯片：神经网络绝大部分时间都在做的那种矩阵运算。Google 设计它们已经大约十年，并用它们来训练和提供自家模型，包括 Gemini。

TPU 可在 [Google Cloud](https://docs.cloud.google.com/tpu/docs/intro-to-tpu) 上使用，规模从单颗芯片一直到数千颗芯片组成的 pod。当你需要大量算力——无论是训练还是大规模推理服务——它们就特别出彩。

一直以来的拦路虎是软件。TPU 的软件栈是围绕 TensorFlow 和 JAX 长起来的，PyTorch 用户想进来就得更费劲。

## 旧的做法

到目前为止，要在 TPU 上跑 PyTorch，就意味着得走 PyTorch/XLA（`torch_xla`）。它能用，但有它的怪脾气。张量是惰性的（说的是张量，不是你），所以你的代码并不总是在你以为它执行的时候执行。微小的改动可能触发计算图重编译，而调试起来也很难推理。

为了让日子好过一点，我们做了 Optimum TPU。它让 Hugging Face 模型在 TPU 上获得了推理和训练支持。既然 TorchTPU 带来了原生支持，用 Transformers 和 Diffusers 跑 Hugging Face 模型就不再需要 Optimum TPU 了。

## 登场：TorchTPU 🚀

[TorchTPU](https://github.com/google-pytorch/torch_tpu) 把 TPU 加成了 PyTorch 的一个新后端。你照常写普通的 PyTorch 代码。它自带为 TPU 调优过的 Pallas kernel，支持分布式训练，还有一个 `torch.compile` 集成，供你需要更高速度时使用。在 TPU VM 上安装它只需要一条命令：

```
pip install torch-tpu --extra-index-url https://download.pytorch.org/whl/cpu
```

那个额外的索引给你的是 `torch` 的 CPU 构建。没有它的话，pip 会拉取大得多的 CUDA 构建，而你在 TPU 上并不需要那个。

## 你常用的那些库，现在跑在 TPU 上

### Transformers

Transformers v5 是围绕一个理念构建的：成为模型定义的唯一权威来源，好让它们能跑在任何地方。"任何地方"如今包括了 TPU。要把模型加载到 TPU 上，传 `device_map="tpu"` 即可。就这样。

```
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "Qwen/Qwen3.5-9B"
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    device_map="tpu", # will load model directly on the TPU
)
tokenizer = AutoTokenizer.from_pretrained(model_id)
inputs = tokenizer("The future of AI is", return_tensors="pt").to("tpu")
out = model.generate(**inputs, max_new_tokens=64)
print(tokenizer.decode(out[0], skip_special_tokens=True))
```

模型默认以 eager 模式运行。你也可以用 `torch.compile` 获得更好的性能，或者把它跑在分布式配置里。

### 图像？视频？Diffusers 在 TPU 上把它们画出来 🎨

TPU 现在在 Diffusers 里是一等设备。做原型或调试时，eager 模式只需要 `pipe.to("tpu")`。做部署时，编译模式只多一次 `compile` 调用。你的 pipeline 和代码都保持不变，也不需要维护一个 TPU 分支。

```
import torch
from diffusers import StableDiffusion3Pipeline

pipe = StableDiffusion3Pipeline.from_pretrained(
    "stabilityai/stable-diffusion-3.5-medium", dtype=torch.bfloat16
)
pipe.to("tpu")  # eager mode: that's the whole change
# optional: compiled mode
pipe.transformer.compile(backend="tpu", fullgraph=True, dynamic=False)

image = pipe("a corgi astronaut planting a flag on a pizza moon").images[0]
```

第一次调用会做编译，之后每次相同图像尺寸的调用都会复用那张计算图。

模型太大，放不进一颗芯片？把 `TensorParallelConfig` 传给 `from_pretrained`，transformer 就会在加载时被分片到多颗芯片上，因此完整的模型永远不必塞进一个地方。许多流行的 pipeline 开箱即支持这一点，不支持的也只是一个 `tp_plan` 的距离。[Diffusers TPU 指南](https://huggingface.co/docs/diffusers/main/optimization/tpu)里有完整做法。

### Kernels

[Kernels Hub](https://huggingface.co/kernels?sort=trending&search=tpu) 里有现成可用的 TPU kernel。用 Kernels 库加载一个，就能给你的模型提速。

TPU kernel 是用 [Pallas](https://docs.jax.dev/en/latest/pallas/tpu/) 写的，它让你能对硬件做底层控制。你也可以从 [Tokamax](https://github.com/openxla/tokamax) 库里引入 kernel。下面是一个来自 Tokamax 的 ragged-dot kernel 被接入 Mixture-of-Experts 模型的例子：

```
from kernels import get_kernel
from transformers import AutoModelForCausalLM
from transformers.integrations.moe import ALL_EXPERTS_FUNCTIONS

repo_id = "tengomucho/ragged-dot-tpu"
kernel = get_kernel(repo_id, version=1, trust_remote_code=[repo_id])
ALL_EXPERTS_FUNCTIONS.register("tokamax_ragged_dot", kernel.experts_forward)
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen3-30B-A3B-Instruct-2507",
    experts_implementation="tokamax_ragged_dot",
)
```

batch 越大，收益越大。在 batch size 为 64 时，Qwen3-30B-A3B 上的解码快了 21.5 倍，Gemma 4 26B-A4B 上快了 12.8 倍。

## 我们来测，你就不必费这个劲 🧪

我们通过运行该库的测试套件，持续改进 transformers 里的 TPU 支持。我们正在努力为 TPU 增加每日 CI，并把结果公开展示在（transformers 仪表盘）[[https://huggingface.co/spaces/transformers-community/transformers-ci-dashboard]](https://huggingface.co/spaces/transformers-community/transformers-ci-dashboard%5D)。

[![Transformers CI 仪表盘，TPU 测试结果与其他加速器并列](https://huggingface.co/buckets/huggingface/hf-torchtpu-blog-assets/resolve/images/tpu-ci-dashboard.png)](https://huggingface.co/buckets/huggingface/hf-torchtpu-blog-assets/resolve/images/tpu-ci-dashboard.png) *Transformers CI 仪表盘，TPU 结果与其他加速器并列展示。仍在进行中！*

现在还不是全绿，我们对此并不介意。在 TPU 上运行的测试里，96.5% 通过。我们发现的每一个失败案例，都会变成一个小的复现脚本，以及在 TorchTPU 仓库上的一条 issue。到目前为止我们报告了 34 条 issue，其中 19 条已经修好。在 TPU 上运行还抓到了 Transformers 本身的几个 bug，比如 `StaticCache` 和 Qwen3 张量并行方案里的问题。这些我们在上游修掉了。

如果有什么东西在 TPU 上出了问题，我们希望在你之前先发现它。

## 开始使用

对 PyTorch 用户来说，TPU 不再是一条支线任务了。安装 TorchTPU，从 Hub 取一个模型，把它送到 `"tpu"`。

- [GitHub 上的 TorchTPU](https://github.com/google-pytorch/torch_tpu)
- [Hub 上的 TPU kernel](https://huggingface.co/kernels?sort=trending&search=tpu)
- [Cloud TPU 文档](https://docs.cloud.google.com/tpu/docs)

我们迫不及待想看到你做出什么 🤗。如果碰到问题，开一条 issue 告诉我们。
