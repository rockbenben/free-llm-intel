## 引言

几个月前我们介绍了 [Time Series Transformer](https://huggingface.co/blog/time-series-transformers)——即把标准 Transformer（[Vaswani et al., 2017](https://arxiv.org/abs/1706.03762)）用于预测，并给出了**单变量**概率预测任务（逐个预测每条时间序列的一维分布）的示例。本文中我们介绍 *Informer* 模型（[Zhou, Haoyi, et al., 2021](https://arxiv.org/abs/2012.07436)），AAAI21 最佳论文，现已在 🤗 Transformers 中[可用](https://huggingface.co/docs/transformers/main/en/model_doc/informer)。我们将演示如何用 Informer 模型做**多变量**概率预测任务，即预测一个未来时间序列目标值**向量**的分布。注意，这对标准 Time Series Transformer 模型同样适用。

## 多变量概率时间序列预测

就概率预测的建模而言，处理多变量时间序列时 Transformer/Informer 不需要任何改动。无论单变量还是多变量设定，模型接收的都是向量序列，因此唯一的变化在输出（emission）一侧。

对高维数据的完整联合条件分布建模在计算上非常昂贵，所以方法上通常求助于分布的某种近似：最简单的是把数据建模为同族的独立分布，或对完整协方差做某种低秩近似，等等。这里我们直接使用独立（对角）emission，这在我们[已实现](https://huggingface.co/docs/transformers/main/en/internal/time_series_utils)的分布族中都有支持。

## Informer 的内部机制

Informer 建立在标准 Transformer（[Vaswani et al., 2017](https://arxiv.org/abs/1706.03762)）之上，做了两项重大改进。要理解这些改进，先回顾标准 Transformer 的短板：

- **标准自注意力的二次计算复杂度：**标准 Transformer 的计算复杂度为 O(T2D)O(T^2 D)O(T2D)，其中 TTT 是时间序列长度、DDD 是隐藏状态维度。对长时间序列预测（也称 *LSTF 问题*）来说，这可能极其昂贵。为解决这个问题，Informer 采用了一种叫 *ProbSparse* 注意力的新自注意力机制，时间和空间复杂度为 O(Tlog⁡T)O(T \log T)O(TlogT)。
- **堆叠层时的内存瓶颈：**堆叠 NNN 个 encoder/decoder 层时，标准 Transformer 的内存用量为 O(NT2)O(N T^2)O(NT2)，限制了模型处理长序列的能力。Informer 使用 *Distilling* 操作，把层间输入缩小一半。如此，整体内存用量降到 O(N⋅Tlog⁡T)O(N\cdot T \log T)O(N⋅TlogT)。

可以看到，Informer 模型的动机与 Longformer（[Beltagy et el., 2020](https://arxiv.org/abs/2004.05150)）、Sparse Transformer（[Child et al., 2019](https://arxiv.org/abs/1904.10509)）以及其他 NLP 论文相同——在**输入序列很长**时降低自注意力的二次复杂度。下面我们用代码示例深入了解 *ProbSparse* 注意力和 *Distilling* 操作。

### ProbSparse Attention

ProbSparse 的核心思想是：标准自注意力分数呈长尾分布，"活跃"（active）查询位于"头部"分数，"懒散"（lazy）查询位于"尾部"区域。所谓"活跃"查询，指其点积 ⟨qi,ki⟩\langle q_i,k_i \rangle⟨qi​,ki​⟩ **贡献**了主要注意力的查询 qiq_iqi​；而"懒散"查询的点积只产生**无关紧要**的注意力。这里 qiq_iqi​ 和 kik_iki​ 分别是 QQQ 和 KKK 注意力矩阵的第 iii 行。

有了"活跃"与"懒散"查询的概念，ProbSparse 注意力挑出"活跃"查询，构成一个缩减的查询矩阵 QreducedQ_{reduced}Qreduced​，用它计算注意力权重即可达到 O(Tlog⁡T)O(T \log T)O(TlogT)。下面结合代码示例细看。

回顾标准自注意力公式：

Attention(Q,K,V)=softmax(QKTdk)V \textrm{Attention}(Q, K, V) = \textrm{softmax}(\frac{QK^T}{\sqrt{d_k}} )V Attention(Q,K,V)=softmax(dk​​QKT​)V

其中 Q∈RLQ×dQ\in \mathbb{R}^{L_Q \times d}Q∈RLQ​×d，K∈RLK×dK\in \mathbb{R}^{L_K \times d}K∈RLK​×d，V∈RLV×dV\in \mathbb{R}^{L_V \times d}V∈RLV​×d。注意实践中自注意力计算里查询和键的输入长度通常相同，即 LQ=LK=TL_Q = L_K = TLQ​=LK​=T，TTT 为时间序列长度。因此 QKTQK^TQKT 相乘的计算复杂度是 O(T2⋅d)O(T^2 \cdot d)O(T2⋅d)。在 ProbSparse 注意力中，我们的目标是构造新的 QreduceQ_{reduce}Qreduce​ 矩阵并定义：

其中 QreduceQ_{reduce}Qreduce​ 矩阵只挑选 Top uuu 个"活跃"查询。这里 u=c⋅log⁡LQu = c \cdot \log L_Qu=c⋅logLQ​，ccc 称为 ProbSparse 注意力的*采样因子*超参数。由于 QreduceQ_{reduce}Qreduce​ 只选 Top uuu 个查询，其尺寸为 c⋅log⁡LQ×dc\cdot \log L_Q \times dc⋅logLQ​×d，所以 QreduceKTQ_{reduce}K^TQreduce​KT 的乘法只需 O(LKlog⁡LQ)=O(Tlog⁡T)O(L_K \log L_Q) = O(T \log T)O(LK​logLQ​)=O(TlogT)。

很好！但我们要如何挑出 uuu 个"活跃"查询来构造 QreduceQ_{reduce}Qreduce​？这就引出*查询稀疏度度量*。

#### 查询稀疏度度量

查询稀疏度度量 M(qi,K)M(q_i, K)M(qi​,K) 用于从 QQQ 中挑选 uuu 个"活跃"查询 qiq_iqi​ 来构造 QreduceQ_{reduce}Qreduce​。理论上，占主导的 ⟨qi,kj⟩\langle q_i,k_j \rangle⟨qi​,kj​⟩ 对会促使"活跃" qiq_iqi​ 的概率分布**偏离**均匀分布，如下图所示。因此，用实际查询分布与均匀分布之间的 [KL 散度](https://en.wikipedia.org/wiki/Kullback%E2%80%93Leibler_divergence)来定义稀疏度度量。

实践中，该度量定义为：

M(qi,K)=max⁡jqikjTd−1Lk∑j=1LkqikjTd M(q_i, K) = \max_j \frac{q_ik_j^T}{\sqrt{d}}-\frac{1}{L_k} \sum_{j=1}^{L_k}\frac{q_ik_j^T}{\sqrt{d}} M(qi​,K)=jmax​d​qi​kjT​​−Lk​1​j=1∑Lk​​d​qi​kjT​​

这里要理解的关键是：M(qi,K)M(q_i, K)M(qi​,K) 越大，查询 qiq_iqi​ 越应该进入 QreduceQ_{reduce}Qreduce​，反之亦然。

但如何以非二次时间计算 qikjTq_ik_j^Tqi​kjT​ 这一项？回顾一下，反正大多数点积 ⟨qi,ki⟩\langle q_i,k_i \rangle⟨qi​,ki​⟩ 产生的都是无关紧要的注意力（长尾分布特性），所以只需从 KKK 中随机采样一个子集即可，代码里称为 `K_sample`。

现在，我们来看 `probsparse_attention` 的代码：

```
from torch import nn
import math


def probsparse_attention(query_states, key_states, value_states, sampling_factor=5):
    """
    Compute the probsparse self-attention.
    Input shape: Batch x Time x Channel

    Note the additional `sampling_factor` input.
    """
    # get input sizes with logs
    L_K = key_states.size(1)
    L_Q = query_states.size(1)
    log_L_K = np.ceil(np.log1p(L_K)).astype("int").item()
    log_L_Q = np.ceil(np.log1p(L_Q)).astype("int").item()

    # calculate a subset of samples to slice from K and create Q_K_sample
    U_part = min(sampling_factor * L_Q * log_L_K, L_K)

    # create Q_K_sample (the q_i * k_j^T term in the sparsity measurement)
    index_sample = torch.randint(0, L_K, (U_part,))
    K_sample = key_states[:, index_sample, :]
    Q_K_sample = torch.bmm(query_states, K_sample.transpose(1, 2))

    # calculate the query sparsity measurement with Q_K_sample
    M = Q_K_sample.max(dim=-1)[0] - torch.div(Q_K_sample.sum(dim=-1), L_K)

    # calculate u to find the Top-u queries under the sparsity measurement
    u = min(sampling_factor * log_L_Q, L_Q)
    M_top = M.topk(u, sorted=False)[1]

    # calculate Q_reduce as query_states[:, M_top]
    dim_for_slice = torch.arange(query_states.size(0)).unsqueeze(-1)
    Q_reduce = query_states[dim_for_slice, M_top]  # size: c*log_L_Q x channel

    # and now, same as the canonical
    d_k = query_states.size(-1)
    attn_scores = torch.bmm(Q_reduce, key_states.transpose(-2, -1))  # Q_reduce x K^T
    attn_scores = attn_scores / math.sqrt(d_k)
    attn_probs = nn.functional.softmax(attn_scores, dim=-1)
    attn_output = torch.bmm(attn_probs, value_states)

    return attn_output, attn_scores
```

注意在实现中，UpartU_{part}Upart​ 的计算里包含了 LQL_QLQ​，这是出于稳定性考虑（详见[这个讨论](https://discuss.huggingface.co/t/probsparse-attention-in-informer/34428)）。

我们做到了！需要说明这只是 `probsparse_attention` 的部分实现，完整实现可以在 🤗 Transformers 中找到。

### Distilling

由于 ProbSparse 自注意力，encoder 的特征图存在可以去除的冗余。因此 distilling 操作用于把 encoder 层间输入缩小一半，从理论上消除这种冗余。实践中，Informer 的 "distilling" 操作只是在每个 encoder 层之间加了带 max pooling 的一维卷积层。设 XnX_nXn​ 是第 nnn 个 encoder 层的输出，distilling 操作定义为：

Xn+1=MaxPool(ELU(Conv1d(Xn)) X_{n+1} = \textrm{MaxPool} ( \textrm{ELU}(\textrm{Conv1d}(X_n)) Xn+1​=MaxPool(ELU(Conv1d(Xn​))

来看代码：

```
from torch import nn

# ConvLayer is a class with forward pass applying ELU and MaxPool1d
def informer_encoder_forward(x_input, num_encoder_layers=3, distil=True):
    # Initialize the convolution layers
    if distil:
        conv_layers = nn.ModuleList([ConvLayer() for _ in range(num_encoder_layers - 1)])
        conv_layers.append(None)
    else:
        conv_layers = [None] * num_encoder_layers
    
    # Apply conv_layer between each encoder_layer
    for encoder_layer, conv_layer in zip(encoder_layers, conv_layers):
        output = encoder_layer(x_input)
        if conv_layer is not None:
            output = conv_layer(loutput)
    
    return output
```

每层输入减半后，内存用量从 O(N⋅T2)O(N\cdot T^2)O(N⋅T2) 变成 O(N⋅Tlog⁡T)O(N\cdot T \log T)O(N⋅TlogT)，NNN 为 encoder/decoder 层数。这正是我们想要的！

## 把 `start` 更新为 `pd.Period`

第一件事：用数据的 `freq` 把每条时间序列的 `start` 特征转成 pandas `Period` 索引：

```
from functools import lru_cache

import pandas as pd
import numpy as np


@lru_cache(10_000)
def convert_to_pandas_period(date, freq):
    return pd.Period(date, freq)


def transform_start_field(batch, freq):
    batch["start"] = [convert_to_pandas_period(date, freq) for date in batch["start"]]
    return batch
```

现在我们用 `datasets` 的 [`set_transform`](https://huggingface.co/docs/datasets/v2.7.0/en/package_reference/main_classes#datasets.Dataset.set_transform) 功能就地动态完成转换：

```
from functools import partial

train_dataset.set_transform(partial(transform_start_field, freq=freq))
test_dataset.set_transform(partial(transform_start_field, freq=freq))
```

接着，用 GluonTS 的 `MultivariateGrouper` 把数据集转成多变量时间序列。这个 grouper 会把一条条一维时间序列合成单个二维矩阵。

## 定义模型

下一步实例化模型。模型将从零开始训练，所以这里不用 `from_pretrained` 方法，而是根据 [`config`](https://huggingface.co/docs/transformers/main/en/model_doc/informer#transformers.InformerConfig) 随机初始化。

我们给模型指定几个额外参数：

- `prediction_length`（本例为 `48` 小时）：decoder 要学习预测的跨度；
- `context_length`：如果不指定 `context_length`，模型会把 encoder 的 `context_length` 设成与 `prediction_length` 相同；
- 给定频率下的 `lags`：这是一种高效的"回看"机制——把过去的值与当前值拼接作为额外特征。例如 `Daily` 频率可以考虑回看 `[1, 7, 30, ...]`，`Minute` 数据可以考虑 `[1, 30, 60, 60*24, ...]` 等；
- 时间特征数量：本例是 `5`，因为我们会添加 `HourOfDay`、`DayOfWeek` 等以及 `Age` 特征（见下文）。

先看 GluonTS 对给定频率（"hourly"）提供的默认 lags：

```
from gluonts.time_feature import get_lags_for_frequency

lags_sequence = get_lags_for_frequency(freq)
print(lags_sequence)

>>> [1, 2, 3, 4, 5, 6, 7, 23, 24, 25, 47, 48, 49, 71, 72, 73, 95, 96, 97, 119, 120, 
     121, 143, 144, 145, 167, 168, 169, 335, 336, 337, 503, 504, 505, 671, 672, 673, 719, 720, 721]
```

这意味着每个时间步要回看最多 721 小时（约 30 天）作为额外特征。但由此得到的特征向量尺寸会是 `len(lags_sequence)*num_of_variates`，在我们这里是 34480！这行不通，所以我们自定义一组合理的 lags。

再看看 GluonTS 提供的默认时间特征：

```
from gluonts.time_feature import time_features_from_frequency_str
```

下面的变换都带注释解释其作用。总体上，我们会遍历数据集中的每条时间序列，增删字段或特征：

```
from transformers import PretrainedConfig


def create_transformation(freq: str, config: PretrainedConfig) -> Transformation:
    # create list of fields to remove later
    remove_field_names = []
    if config.num_static_real_features == 0:
        remove_field_names.append(FieldName.FEAT_STATIC_REAL)
    if config.num_dynamic_real_features == 0:
        remove_field_names.append(FieldName.FEAT_DYNAMIC_REAL)
    if config.num_static_categorical_features == 0:
        remove_field_names.append(FieldName.FEAT_STATIC_CAT)

    return Chain(
        # step 1: remove static/dynamic fields if not specified
        [RemoveFields(field_names=remove_field_names)]
        # step 2: convert the data to NumPy (potentially not needed)
        + (
            [
                AsNumpyArray(
                    field=FieldName.FEAT_STATIC_CAT,
                    expected_ndim=1,
                    dtype=int,
                )
            ]
            if config.num_static_categorical_features > 0
            else []
        )
        + (
            [
                AsNumpyArray(
                    field=FieldName.FEAT_STATIC_REAL,
                    expected_ndim=1,
                )
            ]
            if config.num_static_real_features > 0
            else []
        )
        + [
            AsNumpyArray(
                field=FieldName.TARGET,
                # we expect an extra dim for the multivariate case:
                expected_ndim=1 if config.input_size == 1 else 2,
            ),
            # step 3: handle the NaN's by filling in the target with zero
            # and return the mask (which is in the observed values)
            # true for observed values, false for nan's
            # the decoder uses this mask (no loss is incurred for unobserved values)
            # see loss_weights inside the xxxForPrediction model
            AddObservedValuesIndicator(
                target_field=FieldName.TARGET,
                output_field=FieldName.OBSERVED_VALUES,
            ),
            # step 4: add temporal features based on freq of the dataset
            # these serve as positional encodings
            AddTimeFeatures(
                start_field=FieldName.START,
                target_field=FieldName.TARGET,
                output_field=FieldName.FEAT_TIME,
                time_features=time_features_from_frequency_str(freq),
                pred_length=config.prediction_length,
            ),
            # step 5: add another temporal feature (just a single number)
            # tells the model where in the life the value of the time series is
            # sort of running counter
            AddAgeFeature(
                target_field=FieldName.TARGET,
                output_field=FieldName.FEAT_AGE,
                pred_length=config.prediction_length,
                log_scale=True,
            ),
            # step 6: vertically stack all the temporal features into the key FEAT_TIME
            VstackFeatures(
                output_field=FieldName.FEAT_TIME,
                input_fields=[FieldName.FEAT_TIME, FieldName.FEAT_AGE]
                + (
                    [FieldName.FEAT_DYNAMIC_REAL]
                    if config.num_dynamic_real_features > 0
                    else []
                ),
            ),
            # step 7: rename to match HuggingFace names
            RenameFields(
                mapping={
                    FieldName.FEAT_STATIC_CAT: "static_categorical_features",
                    FieldName.FEAT_STATIC_REAL: "static_real_features",
                    FieldName.FEAT_TIME: "time_features",
                    FieldName.TARGET: "values",
                    FieldName.OBSERVED_VALUES: "observed_mask",
                }
            ),
        ]
    )
```

## 定义 `InstanceSplitter`

为训练/验证/测试，我们接着创建 `InstanceSplitter`，用于从数据集中采样窗口（记住，由于时间和内存限制，我们不能把全部历史值喂给模型）。

instance splitter 从数据中随机采样 `context_length` 大小及其后 `prediction_length` 大小的窗口，并为 `time_series_fields` 中的时间键在对应窗口上添加 `past_` 或 `future_` 前缀键。它可以配置成三种模式：

- `mode="train"`：从传入的数据集（训练集）中随机采样 context 和 prediction 窗口
- `mode="validation"`：从传入的数据集中采样最后一个 context 长度窗口和 prediction 窗口（用于回测或验证似然计算）
- `mode="test"`：只采样最后一个 context 长度窗口（用于预测场景）

```
from gluonts.transform.sampler import InstanceSampler
from typing import Optional


def create_instance_splitter(
    config: PretrainedConfig,
    mode: str,
    train_sampler: Optional[InstanceSampler] = None,
    validation_sampler: Optional[InstanceSampler] = None,
) -> Transformation:
    assert mode in ["train", "validation", "test"]

    instance_sampler = {
        "train": train_sampler
        or ExpectedNumInstanceSampler(
            num_instances=1.0, min_future=config.prediction_length
        ),
        "validation": validation_sampler
        or ValidationSplitSampler(min_future=config.prediction_length),
        "test": TestSplitSampler(),
    }[mode]

    return InstanceSplitter(
        target_field="values",
        is_pad_field=FieldName.IS_PAD,
        start_field=FieldName.START,
        forecast_start_field=FieldName.FORECAST_START,
        instance_sampler=instance_sampler,
        past_length=config.context_length + max(config.lags_sequence),
        future_length=config.prediction_length,
        time_series_fields=["time_features", "observed_mask"],
    )
```

## 创建 DataLoaders

接下来创建 DataLoaders，得到（输入，输出）对的批次——也就是 (`past_values`, `future_values`)。

```
from typing import Iterable

import torch
from gluonts.itertools import Cached, Cyclic
from gluonts.dataset.loader import as_stacked_batches


def create_train_dataloader(
    config: PretrainedConfig,
    freq,
    data,
    batch_size: int,
    num_batches_per_epoch: int,
    shuffle_buffer_length: Optional[int] = None,
    cache_data: bool = True,
    **kwargs,
) -> Iterable:
    PREDICTION_INPUT_NAMES = [
        "past_time_features",
        "past_values",
        "past_observed_mask",
        "future_time_features",
    ]
    if config.num_static_categorical_features > 0:
        PREDICTION_INPUT_NAMES.append("static_categorical_features")

    if config.num_static_real_features > 0:
        PREDICTION_INPUT_NAMES.append("static_real_features")

    TRAINING_INPUT_NAMES = PREDICTION_INPUT_NAMES + [
        "future_values",
        "future_observed_mask",
    ]

    transformation = create_transformation(freq, config)
    transformed_data = transformation.apply(data, is_train=True)
    if cache_data:
        transformed_data = Cached(transformed_data)

    # we initialize a Training instance
    instance_splitter = create_instance_splitter(config, "train")

    # the instance splitter will sample a window of
    # context length + lags + prediction length (from all the possible transformed time series, 1 in our case)
    # randomly from within the target time series and return an iterator.
    stream = Cyclic(transformed_data).stream()
    training_instances = instance_splitter.apply(stream)
    
    return as_stacked_batches(
        training_instances,
        batch_size=batch_size,
        shuffle_buffer_length=shuffle_buffer_length,
        field_names=TRAINING_INPUT_NAMES,
        output_type=torch.tensor,
        num_batches_per_epoch=num_batches_per_epoch,
    )
```

## 推理

推理时，建议像 NLP 模型一样使用 `generate()` 方法做自回归生成。

预测所需的数据来自 test instance sampler，它会从数据集中每条时间序列采样最后一个 `context_length` 大小的值窗口，再传给模型。注意我们把预先可知的 `future_time_features` 也传给 decoder。

模型会从预测分布中自回归地采样一定数量的值并回传给 decoder，从而返回预测输出：

```
model.eval()

forecasts_ = []

for batch in test_dataloader:
    outputs = model.generate(
        static_categorical_features=batch["static_categorical_features"].to(device)
        if config.num_static_categorical_features > 0
        else None,
        static_real_features=batch["static_real_features"].to(device)
        if config.num_static_real_features > 0
        else None,
        past_time_features=batch["past_time_features"].to(device),
        past_values=batch["past_values"].to(device),
        future_time_features=batch["future_time_features"].to(device),
        past_observed_mask=batch["past_observed_mask"].to(device),
    )
    forecasts_.append(outputs.sequences.cpu().numpy())
```

模型输出一个形状为 (`batch_size`, `number of samples`, `prediction length`, `input_size`) 的张量。

在本例中，对 `862` 条时间序列（批次大小为 `1`，因为我们只有一条多变量时间序列）的未来 `48` 小时，我们得到 `100` 个可能的取值：

| Traffic Hourly | 1.922 | 1.922 | 2.482 | 2.294 | 2.535 | 1.281 | 1.571 | 0.892 | 0.825 | 1.100 | 1.066 | **0.821** | 1.191 |

可以看到，或许让一些人意外，多变量预测通常*比*单变量预测*更差*，原因在于跨序列相关性/关系的估计很困难。这些估计带来的额外方差往往会伤害预测结果，或者模型学到虚假相关。延伸阅读见[这篇论文](https://openreview.net/forum?id=GpW327gxLTF)。多变量模型通常在大量数据上训练时表现好。

所以标准 Transformer 在这里仍然是最好的！未来，我们希望在一个中央位置更好地评测这些模型，方便复现多篇论文的结果。敬请期待！
