[**LFM3**](https://huggingface.co/collections/LiquidAI/lfm3) 是我们新一代的 Liquid Foundation Models（LFMs），旨在成为专用智能的起点。它把文本、视觉、音频、omni 与决策模型放到同一条共享骨干上，全部处于 2B 参数区间。这意味着你可以按自己的模态挑选模型，在单张 GPU 上用自己的数据微调，再把它部署到应用运行的地方。

相比此前的 LFM2 系列，LFM3 带来四项主要变化：

- **每个参数具备更强能力：** 新的 tri-hybrid 架构与训练配方让 LFM3-1.7B 在参数少 35% 的情况下胜过 LFM2.5-2.6B。
- **所有模态共用一条骨干：** 六个 2B 级模型（文本、视觉、音频、omni 与决策）都从 LFM3-1.7B-Base 训练而来，其中包括我们的首个 omni 模型，以及视觉模型新增的视频输入。
- **为端侧而生：** 文本模型在 4-bit 精度下约占 1 GB 内存，全新的自研视觉与音频编码器加快了处理速度，文本模型 256K 的上下文窗口则让 agent 可以在设备本地运行。
- **天生适合专用化：** 每个模型都能在单张 GPU 上微调，因此你可以把它适配到自己的数据、术语与部署环境。

## 我们如何打造更具表达力的骨干

LFM2 证明了短卷积与 attention 的混合结构可以在设备本地快速运行，而不牺牲质量。到了 LFM3，我们用硬件在环（hardware-in-the-loop）架构搜索，针对 agentic 用例重新设计这套架构——这类用例需要更高的每参数能力，以及在长上下文上的快速推理。搜索范围现在覆盖 14 种设备与后端组合，从手机、Raspberry Pi 5 到笔记本、云上 CPU、GPU，以及 Qualcomm Hexagon NPU。

[![lfm3-1.7b-architecture](https://cdn-uploads.huggingface.co/production/uploads/644249b08443bce4c9890a0f/iZQBqXVZfrcUNCklF4eAs.png)](https://cdn-uploads.huggingface.co/production/uploads/644249b08443bce4c9890a0f/iZQBqXVZfrcUNCklF4eAs.png)

LFM3-1.7B-Base 有 24 层，包含四项主要变化：

- **Tri-hybrid 层组合：** 13 层带门控的短卷积、5 层窗口为 256 token 的滑动窗口注意力（SWA），以及 6 层全局注意力。卷积核大小为 7，比 LFM2 的 3 更大。
- **逐 head 门控注意力：** 一个 sigmoid 门控对每个 head 的输出做缩放，这样某个 head 在无话可说时可以自行关闭。这有助于压制会损害量化的激活离群值。
- **部分 RoPE：** 全局注意力层只旋转每个 head 中频率最高的那一半，于是另一半不受距离影响、按内容匹配。SWA 层保留完整 RoPE。
- **Sandwich norm：** 每个 block 对输入和输出都做归一化，让激活保持在合适的尺度上。

收益在长上下文上显现。按参数折算，LFM3-1.7B 在各类端侧设备的短 prompt 上与 LFM2-1.2B 持平，而在上下文含 8K token 时约快 25%。LFM3-1.7B-Base 在 22T token 上预训练，词表与 [LFM2.5-8B-A1B](https://huggingface.co/LiquidAI/LFM2.5-8B-A1B) 同为 128K。最后 3.5T token 是在精选数据上进行的 mid-training 阶段，其中 agentic trace 与工具调用的占比更高，这一阶段也把上下文窗口扩展到 256K token。

## 一条骨干，六个模型

每个 LFM3 模型都从 LFM3-1.7B-Base 分叉而来。你不必去跑一个大而全的通用模型，而是挑出契合你输入的那一个，定制它，然后在设备本地运行。

[![lfm3-post-training](https://cdn-uploads.huggingface.co/production/uploads/644249b08443bce4c9890a0f/6RfJINOKr6Ay2kHCPR-mz.png)](https://cdn-uploads.huggingface.co/production/uploads/644249b08443bce4c9890a0f/6RfJINOKr6Ay2kHCPR-mz.png)

| 模型 | 输入 | 输出 | 基于 |
| --- | --- | --- | --- |
| [LFM3-1.7B](https://huggingface.co/LiquidAI/LFM3-1.7B) | 文本 | 文本 | LFM3-1.7B-Base |
| [LFM3-VL-2B](https://huggingface.co/LiquidAI/LFM3-VL-2B) | 文本、图像、视频 | 文本 | LFM3 骨干 + 视觉编码器 |
| [LFM3-Audio-2B](https://huggingface.co/LiquidAI/LFM3-Audio-2B) | 文本、音频 | 文本、语音 | LFM3 骨干 + 音频编码器、音频解码器与 LiquidCodec |
| [LFM3-Omni-2B](https://huggingface.co/LiquidAI/LFM3-Omni-2B) | 文本、图像、视频、音频 | 文本、语音 | LFM3 骨干 + 视觉与音频编码器以及音频解码器 |
| [d1-2B](https://huggingface.co/LiquidAI/d1-2B) | 文本、图像、视频 | 校准后的答案 | LFM3-VL-2B |
| [d1-omni-2B](https://huggingface.co/LiquidAI/d1-omni-2B) | 文本、图像、视频、音频 | 校准后的答案 | LFM3-Omni-2B |

视觉与音频模型还配备了两个全新的自研编码器：

- **视觉编码器：** 它把卷积与 attention 结合起来，算力消耗比此前 LFM VL 模型中的 SigLIP2 编码器少 3 倍。我们这个 164M 参数的编码器在精度上与 Qwen3.5-2B 的视觉编码器相当，而所需 FLOPs 少 2.2 倍（两者均在同一 LFM2.5-230M 语言骨干上测量）。对视频而言，它把每一对采样帧嵌入为一个时间切片，使时序序列长度减半。
- **音频编码器与 LiquidCodec：** 音频编码器混合了滑动窗口注意力与短卷积，并且完全因果，因此模型可以在你说话的同时做 prefill，首 token 延迟低至 50 ms。我们的新音频 tokenizer LiquidCodec 在 Apple M4 Max 的单个 CPU 线程上以约 87 倍实时速度把生成的 token 转成语音，并支持流式解码。

## 如何使用 LFM3 模型

每个模型都能在 `transformers` 中运行。下面的代码片段来自各自的 model card，那里也列出了每个模型支持的其他推理引擎。

### LFM3-1.7B

当你需要本地 agent、工具调用、结构化输出，或需要一个领域专用微调的基座时，就选 LFM3-1.7B。它经过 post-training，可在 Hermes Agent、Pi、OpenClaw 这类 agentic harness 中运行。它在参数少 35% 的情况下胜过前代 LFM2.5-2.6B，提升最大的在 agentic 任务上：在 WebArena-Verified 上它得 38.42，而前代为 3.02；在浏览器与业务应用的长任务上，它甚至超过了 Qwen3.5-9B。更多细节见 [LFM3-1.7B model card](https://huggingface.co/LiquidAI/LFM3-1.7B)。

要运行 LFM3-1.7B，先安装最新版本的 `transformers`：

```
pip install -U transformers
```

然后加载并运行模型：

```
from transformers import pipeline

generator = pipeline(
    "text-generation",
    model="LiquidAI/LFM3-1.7B",
    trust_remote_code=True,
)

messages = [{"role": "user", "content": "What is C. elegans?"}]
output = generator(
    messages,
    do_sample=True,
    temperature=0.1,
    top_k=50,
    repetition_penalty=1.1,
    max_new_tokens=2048,
)
print(output[0]["generated_text"][-1]["content"])
```

本地 agent 的配置，参见 [Agent Harnesses 指南](https://docs.liquid.ai/examples/agent-harnesses)。

### LFM3-VL-2B

当你需要设备本地的视觉理解时，就选 LFM3-VL-2B。它是 LFM 首个接受视频输入的视觉模型；它会先逐步推理再作答，能定位物体并推理它们的空间摆放关系，这是机器人领域的坚实基础。与 LFM2.5-VL-3B 相比，它的参数更少（1.9B 对 3.1B），却把 62 个视觉 benchmark 的平均分从 57.6 提升到 71.4，与 Gemma 4 12B 持平——后者规模是它的六倍多。更多细节见 [LFM3-VL-2B model card](https://huggingface.co/LiquidAI/LFM3-VL-2B)。

要运行 LFM3-VL-2B，安装 transformers>=5.21.0 及其视觉依赖：

```
pip install "transformers>=5.21.0" torch torchvision pillow
```

然后加载并运行模型：

```
import torch
from transformers import AutoModelForImageTextToText, AutoProcessor

model_id = "LiquidAI/LFM3-VL-2B"

model = AutoModelForImageTextToText.from_pretrained(model_id, dtype=torch.bfloat16, device_map="auto", trust_remote_code=True)
processor = AutoProcessor.from_pretrained(model_id, trust_remote_code=True)

messages = [
    {
        "role": "user",
        "content": [
            {"type": "image", "url": "https://placecats.com/300/200"},
            {"type": "text", "text": "Describe this image."},
        ],
    }
]

inputs = processor.apply_chat_template(
    messages,
    add_generation_prompt=True,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
).to(model.device)

with torch.inference_mode():
    output_ids = model.generate(
        **inputs,
        do_sample=True,
        temperature=0.1,
        top_k=50,
        repetition_penalty=1.1,
        max_new_tokens=16384,  # generate() needs an explicit limit; reasoning can be long
    )

generated_ids = output_ids[:, inputs["input_ids"].shape[1] :]
print(processor.batch_decode(generated_ids, skip_special_tokens=True)[0])
```

工具调用、工具搜索以及用 llama.cpp 做设备本地推理，参见 [LFM3-VL-2B model card](https://huggingface.co/LiquidAI/LFM3-VL-2B)。

### LFM3-Audio-2B

当你需要在笔记本或端侧设备上做语音对话、语音识别、语音合成，或跨 18 种语言的翻译时，就选 LFM3-Audio-2B。它以文本或音频为输入，用文本、语音或两者同时作答，还能把口述请求转成工具调用。与 LFM2.5-Audio-1.5B 相比，它采用全新的自研音频编码器与语音 codec，说话质量更高（UTMOSv2 3.83 对 3.22），并新增了音频理解、通用音频推理与工具调用。更多细节见 [LFM3-Audio-2B model card](https://huggingface.co/LiquidAI/LFM3-Audio-2B)。

要运行 LFM3-Audio-2B，安装 `transformers>=5.20.2` 及其音频依赖：

```
pip install "transformers>=5.20.2" torch accelerate librosa soundfile
```

直接从 Hugging Face Hub 加载模型与 processor：

```
import torch
import soundfile as sf

from transformers import AutoModelForMultimodalLM, AutoProcessor

model_id = "LiquidAI/LFM3-Audio-2B"
device = "cuda" if torch.cuda.is_available() else "cpu"
dtype = torch.bfloat16 if device == "cuda" else torch.float32

model = AutoModelForMultimodalLM.from_pretrained(
    model_id, dtype=dtype, device_map=device, trust_remote_code=True
).eval()
processor = AutoProcessor.from_pretrained(model_id, trust_remote_code=True)
codec = processor.audio_tokenizer.to(device=device).eval()
```

然后开口提问，得到文本与语音两种回复：

```
conversation = [
    {"role": "system", "content": "Respond with interleaved text and audio."},
    {"role": "user", "content": [{"type": "audio", "audio": "question.wav"}]},
    {"role": "assistant", "content": "<|mixed_start|>"},
]
inputs = processor.apply_chat_template(
    conversation,
    continue_final_message=True,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
).to(device)
with torch.no_grad():
    outputs = model.generate(
        **inputs,
        max_new_tokens=1024,
        audio_temperature=1.0,
        audio_top_k=128,
        audio_repetition_penalty=1.1,
        audio_repetition_window=4096,
        return_dict_in_generate=True,
    )

    text = processor.decode(
        outputs.sequences[0, inputs["input_ids"].shape[1]:],
        skip_special_tokens=True,
    )
    waveform = codec.decode(
        outputs.audio_codes[:1, :, :outputs.audio_lengths[0]]
    ).audio_values[0]  # 24 kHz
print(text)
sf.write("reply.wav", waveform.float().cpu().numpy(), 24_000)
```

实时语音识别、语音合成、音频理解与工具调用，参见 [LFM3-Audio-2B model card](https://huggingface.co/LiquidAI/LFM3-Audio-2B)。

### LFM3-Omni-2B

当你需要一个能看、能听、还能回话的设备本地模型，用来替代各自独立的 ASR 模型、vision-language 模型、LLM 与 TTS 模型时，就选 LFM3-Omni-2B。它能回答关于图像的口头提问，能一边看一边听视频，还能把看到和听到的内容转成工具调用。这是我们的首个 omni 模型，支持文本、视觉与音频输入，同时输出文本与语音，并保留了独立 LFM3 模型的核心能力，包括视觉问答、语音识别、语音合成与指令遵循。与 LFM3-Audio-2B 一样，它通过 LiquidCodec 发声——把生成的 token 以超过实时的速度转成语音，因此语音回复会随模型生成而流式输出。在音视频理解上，它在 Daily-Omni、WorldSense 与 AV-SpeakerBench 上胜过了参数规模最高达 10.7B 的模型，例如 Qwen2.5-Omni-7B。更多细节见 [LFM3-Omni-2B model card](https://huggingface.co/LiquidAI/LFM3-Omni-2B)。

要运行 LFM3-Omni-2B，安装 `transformers>=5.20.2` 及其视觉与音频依赖：

### d1-2B 与 d1-omni-2B

当你需要的是快速、结构化的判断而非生成的文本时，就选 d1 系列模型。给它们一个情境（一张客服工单、一张发票、一个应用界面、一张照片、一条语音留言）和一串问题，它们会在一次前向传播里全部作答，每个答案都带校准后的概率。除了是/否、选项与评分，它们现在还能指向物体、从文档中读取数值、给出带区间的数值估计，并选出所有符合的选项。更多细节见 [d1-2B](https://huggingface.co/LiquidAI/d1-2B) 与 [d1-omni-2B](https://huggingface.co/LiquidAI/d1-omni-2B) 的 model card。

两个 d1 模型之间怎么选：

- **d1-2B**：输入是文本、图片与视频时选它。它替代 [d1-3B](https://huggingface.co/LiquidAI/d1-3B)，参数少三分之一，并在我们全部四个决策套件上都得分更高，例如在 ImajevBench 上 75.5 对 64.0。
- **d1-omni-2B**：输入包含音频时选它。如果你用语音而非文字提问，它几乎能保持全部准确率。

要运行 d1-2B，安装 `transformers>=5.19` 及其视觉依赖：

```
pip install "transformers>=5.19" torch torchvision pillow
```

然后加载 d1-2B，针对同一张客服工单在单次前向中提出多个问题：

```
import torch
from transformers import AutoModel

device = "cuda" if torch.cuda.is_available() else "mps" if torch.backends.mps.is_available() else "cpu"
dtype = torch.float32 if device == "cpu" else torch.bfloat16
model = AutoModel.from_pretrained("LiquidAI/d1-2B", trust_remote_code=True, dtype=dtype).to(device)

# Several named questions over one state, answered in one pass
questions = {
    "refund": {"type": "noul", "instructions": "Is the customer asking for a refund?"},  # yes/no: P(yes)
    "team": {"type": "choice", "instructions": "Which team should handle this?",
             "criteria": {"billing": "Charges, refunds, invoices", "shipping": "Delivery and parcels",
                          "technical": "App or site faults"}},
    "topics": {"type": "choice", "multiple": True, "instructions": "Which topics does the message raise?",
               "criteria": {"billing": "Payments and charges", "delivery": "Shipping and parcels",
                            "login": "Signing in to the account"}},
    "urgency": {"type": "score", "instructions": "How urgent is this ticket?", "criteria": ["low", "medium", "high"]},
}
out = model.system_one("I was charged twice and my parcel never arrived. Please refund one charge.", questions)
a = out["answers"]
urgency = a["urgency"]["legend"][str(int(a["urgency"]["score"]))]
print(round(a["refund"]["noul"], 2), a["team"]["choice"], a["topics"]["choices"], urgency)
# 1.0 billing ['billing', 'delivery'] medium
```

### 示例：教 LFM3 行动

我们把 LFM3-VL-2B 改造成三个互补的机器人模型，分别负责**编排、导航与操作**。编排器通过工具调用操作机械臂：它用指向来定位物体、用深度工具测量它们、调用运动规划器，并在后续的相机图像中检查结果。导航器依据最近的 RGB 观测跟随路线描述，只用五个 token 就预测出空间目标与路点轨迹。操作 VLA 在一次前向传播中把图像、语言与机器人状态映射为八步的连续动作块。该 VLA 在 15 种本体上联合训练，在四个 LIBERO 套件上取得 96.2% 的平均成功率，在 RoboCasa-GR1 桌面任务上达到 45.7%，并在 Jetson AGX Orin 上用 TensorRT FP16 于 50 ms 内生成动作块。这些结果表明，LFM3-VL-2B 是机器人领域一个紧凑的基座，从高层规划到低层控制，在嵌入式硬件上都能实时生成动作。
