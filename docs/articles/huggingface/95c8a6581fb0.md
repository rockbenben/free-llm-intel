今天我们很高兴宣布 SafeCoder——一个专为企业打造的代码助手解决方案。

SafeCoder 的目标是为企业释放软件开发生产力，提供一套完全合规、自托管的结对编程助手。用营销的话说："你自己的本地部署版 GitHub Copilot"。

在深入之前，你需要知道这几点：

- SafeCoder 不是一个模型，而是一套完整的端到端商业解决方案
- SafeCoder 以安全与隐私为核心原则构建——无论在训练还是推理阶段，代码都不会离开 VPC
- SafeCoder 设计为客户在自有基础设施上自托管
- SafeCoder 让客户拥有自己的代码大语言模型（Code LLM）

## 为什么需要 SafeCoder？

基于 LLM 构建的代码助手方案（如 GitHub Copilot）正带来显著的生产力提升（参见 [GitHub 的研究](https://github.blog/2022-09-07-research-quantifying-github-copilots-impact-on-developer-productivity-and-happiness/)）。对企业而言，在公司代码库上调优代码 LLM、打造专有 Code LLM，能提升补全的可靠性与相关性，再上一个生产力台阶。例如，Google 内部 LLM 代码助手凭借在内部代码库上训练，补全[接受率达到 25-34%](https://ai.googleblog.com/2022/07/ml-enhanced-code-completion-improves.html)。

然而，依赖闭源 Code LLM 来构建内部代码助手，会让公司面临合规与安全问题。训练阶段如此——用内部代码库微调闭源 Code LLM 就意味着把代码库暴露给第三方。推理阶段同样如此——微调后的 Code LLM 在推理时很可能"泄露"训练数据中的代码。为满足合规要求，企业需要把微调后的 Code LLM 部署在自己的基础设施内——而闭源 LLM 做不到这一点。

通过 SafeCoder，Hugging Face 将帮助客户构建自己的 Code LLM：使用最先进的开源模型和库，在客户自有代码库上微调，而无需把代码分享给 Hugging Face 或任何第三方。通过 SafeCoder，Hugging Face 交付的是一套容器化、硬件加速的 Code LLM 推理方案，由客户直接在自家安全基础设施内部署，代码输入与补全结果不会离开其安全的 IT 环境。

## 从 StarCoder 到 SafeCoder

SafeCoder 方案的核心是 [StarCoder](https://huggingface.co/bigcode/starcoder) 系列 Code LLM。它诞生于 [BigCode](https://huggingface.co/bigcode) 项目——Hugging Face、ServiceNow 与开源社区的协作成果。

StarCoder 模型具有的独特属性，与企业的自托管方案可谓天作之合：

- 最先进的代码补全效果——基准测试见[论文](https://huggingface.co/papers/2305.06161)和[多语言代码评估排行榜](https://huggingface.co/spaces/bigcode/multilingual-code-evals)
- 为推理性能而设计：15B 参数的模型配合代码优化，Multi-Query Attention 降低内存足迹，Flash Attention 支撑 8,192 词元的上下文。
- 在 [the Stack](https://huggingface.co/datasets/bigcode/the-stack) 上训练——这是一个伦理采购的开源代码数据集，只包含商业可许可的代码，从一开始就提供开发者退出（opt-out）机制，并经过密集的 PII 清除与去重打磨。

注意：StarCoder 是 SafeCoder 初版的灵感来源和驱动模型，但基于开源模型构建 LLM 方案的一大好处是，它可以跟进最新最好的开源模型。未来 SafeCoder 也可能提供其他商业上同样可许可、基于伦理来源与透明数据集构建的开源模型，作为供微调的基础 LLM。

## 隐私与安全作为核心原则

对任何公司来说，内部代码库都是最重要、最有价值的知识产权之一。SafeCoder 的一条核心原则是：客户的内部代码库在训练或推理过程中绝不向任何第三方（包括 Hugging Face）开放。

在 SafeCoder 的初始设置阶段，Hugging Face 团队提供容器、脚本和示例，与客户携手完成内部代码库数据的筛选、抽取、准备、去重和去标识，形成训练数据集，并放入一个按客户可用硬件基础设施配置好的 Hugging Face 训练容器中。

在 SafeCoder 的部署阶段，客户把 Hugging Face 提供的容器部署在自己的基础设施上，在 VPC 内暴露内部私有端点。这些容器按客户实际可用的硬件配置定制，包括 NVIDIA GPU、AMD Instinct GPU、Intel Xeon CPU、AWS Inferentia2 或 Habana Gaudi 加速器。

## 合规作为核心原则

围绕机器学习模型和数据集的监管框架在全球范围内仍在起草之中，跨国公司需要确保所用方案将法律风险降到最低。

数据来源、数据治理、受版权保护数据的管理，只是最重要的几个合规考量领域。BigCode 的前辈和灵感来源 BigScience，早在这些议题被欧盟 AI 法案草案广泛承认之前，就通过工作组解决了这些问题，因此在斯坦福 CRFM 的研究中被评为[基础模型提供者中合规度最高](https://crfm.stanford.edu/2023-06-15/eu-ai-act.html)。

BigCode 在此基础上更进一步，针对代码领域实现了新技术，并把合规作为核心原则来构建 The Stack：商业可许可的许可证过滤、同意机制（开发者可以[轻松查询自己的代码是否被收录并申请退出](https://huggingface.co/spaces/bigcode/in-the-stack)数据集），以及详尽的文档和工具来检视[源数据](https://huggingface.co/datasets/bigcode/the-stack-metadata)与数据集改进（如[去重](https://huggingface.co/blog/dedup)和 [PII 清除](https://huggingface.co/bigcode/starpii)）。

所有这些努力都转化为 StarCoder 模型使用者、SafeCoder 客户法律风险的降低。而对 SafeCoder 用户来说，这些努力进一步转化为合规功能：当开发者获得代码补全时，这些建议会与 The Stack 做比对，用户可以知道建议代码是否与源数据集中的现有代码匹配、以及对应的许可证。客户可以指定偏好的许可证，并把这些偏好呈现给他们的使用者。

## 它是如何工作的？

SafeCoder 是一套完整的商业解决方案，包含服务、软件与支持。

### 训练你自己的 SafeCoder 模型

StarCoder 在 80 多种编程语言上训练，并在[多个基准](https://huggingface.co/spaces/bigcode/multilingual-code-evals)上保持最先进水平。为了给 SafeCoder 客户提供更贴合的代码建议，我们在合作中以一个可选的训练阶段开场：Hugging Face 团队与客户团队直接协作，指导他们准备并构建训练代码数据集，通过微调创建自己的代码生成模型——全程不把代码库暴露给第三方或互联网。

最终成果是一个适配客户代码语言、标准和实践的模型。在这个过程中，SafeCoder 客户学会了这套流程，建立了创建和更新自己模型的管线，确保没有供应商锁定，并牢牢掌控自己的 AI 能力。

### 部署 SafeCoder

在设置阶段，SafeCoder 客户与 Hugging Face 共同设计并预备能支撑所需并发、带来出色开发者体验的最优基础设施。随后 Hugging Face 构建 SafeCoder 推理容器——硬件加速、针对吞吐优化——由客户部署在自己的基础设施上。

SafeCoder 推理支持多种硬件，给客户充分的选择空间：NVIDIA Ampere GPU、AMD Instinct GPU、Habana Gaudi2、AWS Inferentia 2、Intel Xeon Sapphire Rapids CPU 等等。

### 使用 SafeCoder

SafeCoder 部署完成、端点在客户 VPC 内上线后，开发者可以安装兼容的 SafeCoder IDE 插件，边写代码边获得建议。如今 SafeCoder 支持主流 IDE，包括 [VSCode](https://marketplace.visualstudio.com/items?itemName=HuggingFace.huggingface-vscode)、IntelliJ，更多插件正来自我们的合作伙伴。
