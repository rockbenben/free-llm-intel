# 推出 🤗 Optimum：面向大规模 Transformers 的优化工具包

本文是 Hugging Face 让最先进（state-of-the-art）**机器学习生产性能**走向大众之旅的第一步。为此，我们将与硬件合作伙伴携手并进——比如下文中的 Intel。加入我们的旅程，关注 [Optimum](https://github.com/huggingface/optimum)，我们的全新开源库！

## 为什么需要 🤗 Optimum？

### 🤯 Transformers 的规模化很难

Tesla、Google、Microsoft 和 Facebook 有什么共同点？共同点很多，但其中之一是：它们每天都在跑数十亿次 Transformer 模型预测。Transformer 在 Tesla 上驱动 AutoPilot 帮你开车（真幸运！），在 Gmail 里帮你补全句子，在 Facebook 里实时翻译你的帖子，在 Bing 里回答你的自然语言查询。

[Transformers](https://github.com/huggingface/transformers) 让机器学习模型的准确率实现了跨越式提升，已经征服了 NLP，并正从 [语音](https://huggingface.co/models?pipeline_tag=automatic-speech-recognition&sort=downloads)和[视觉](https://huggingface.co/models?pipeline_tag=image-classification&sort=downloads)开始扩展到其他模态。但对任何机器学习工程团队来说，把这些巨型模型投入生产、让它们大规模地快速运行，都是一个巨大挑战。

如果你不像上面那些公司一样雇得起几百名顶尖机器学习工程师怎么办？通过我们的新开源库 Optimum，我们要打造的是 Transformers 生产性能的终极工具包，让在特定硬件上训练和运行模型达到最高效率。

### 🏭 Optimum 让 Transformers 上岗干活

要在训练和模型服务中获得最优性能，模型加速技术必须与目标硬件具体兼容。每个硬件平台都有自己的软件工具链，[有些特性和可调参数对性能影响巨大](https://huggingface.co/blog/bert-cpu-scaling-part-1)。同样，要用上稀疏化、量化等高级模型加速技术，就需要优化过的 kernel 与芯片上的算子兼容，并针对模型架构派生出的神经网络图做定制。深入这个三维兼容性矩阵、学会使用模型加速库，是件令人头大的工作，有经验的机器学习工程师凤毛麟角。

[Optimum](https://github.com/huggingface/optimum) 的目标就是让这件事变简单：提供面向高效 AI 硬件的性能优化工具，与我们携手合作的硬件伙伴共同构建，把机器学习工程师变成模型优化大师。

借助 [Transformers](https://github.com/huggingface/transformers) 库，我们让研究人员和工程师可以轻松使用最先进模型，把框架、架构和流水线的复杂性抽象掉。

借助 [Optimum](https://github.com/huggingface/optimum) 库，我们让工程师可以轻松用上手头所有硬件特性，把硬件平台上模型加速的复杂性抽象掉。

## 🤗 Optimum 实战：如何为 Intel Xeon CPU 量化模型

### 🤔 量化为什么重要、又为什么难做对

BERT 这类预训练语言模型在众多自然语言处理任务上取得了最先进成果；ViT、Speech2Text 等其他 Transformer 系模型也分别在计算机视觉和语音任务上达到最先进——Transformer 已经遍布机器学习世界，而且会长期存在。

然而，把基于 transformer 的模型投入生产可能既棘手又昂贵，因为它们需要大量算力。为此有很多种技术，最流行的是量化。不幸的是，大多数情况下量化一个模型要做大量工作，原因有很多：

- 模型本身需要修改：一些算子要替换成量化版本，要插入新的算子（量化/反量化节点），还要让其他算子适配权重和激活已被量化的事实。

这部分可能非常耗时，因为 PyTorch 这类框架运行在 eager 模式下，意味着上述改动要直接加进模型实现本身。PyTorch 现在提供了一个叫 `torch.fx` 的工具，允许你在不改模型实现的情况下追踪并变换模型，但如果你的模型开箱不支持 tracing，它就很别扭。

在实际修改之外，你还得找出模型哪些部分需要改、哪些算子有现成的量化 kernel、哪些没有，等等。

- 模型改完之后，还要在大量参数之间摸索最佳量化配置：范围校准该用哪种 observer？该用哪种量化方案？目标设备支持哪些量化数据类型（int8、uint8、int16）？
- 在量化与可接受的精度损失之间权衡。
- 把量化模型导出到目标设备。

尽管 PyTorch 和 TensorFlow 在简化量化方面已取得长足进步，但基于 transformer 的模型的复杂性，使得你很难开箱即用这些工具、不下苦功就能跑通。

### 💡 Intel 如何用 Neural Compressor 解决量化及其他问题

Intel® [Neural Compressor](https://github.com/intel/neural-compressor)（原名 Low Precision Optimization Tool，LPOT）是一个开源 Python 库，帮助用户部署低精度推理方案。它为深度学习模型应用低精度配方，以在预期性能标准内达成最佳产品目标，如推理性能和内存占用。Neural Compressor 支持训练后量化、量化感知训练和动态量化。要指定量化方法、目标和性能标准，用户必须提供一份描述调优参数的配置 yaml 文件。配置文件既可以托管在 Hugging Face 的 Model Hub 上，也可以通过本地目录路径提供。
