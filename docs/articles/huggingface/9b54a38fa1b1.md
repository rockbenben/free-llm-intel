# 用 gr.Workflow 构建任何东西

大多数有趣的 AI 应用都是 pipeline。你生成一张图，然后可以选择抠掉背景，或者把它编辑成新内容。你写好一段脚本，然后为它生成配音，或者保留脚本换个声音。我们通常用 Python 把这些步骤串起来，一旦某个环节看起来不对，就得回去 print 调试，找出是哪一步产出了异常值。

内建于 Gradio 的 **`gr.Workflow`** 让 pipeline *成为界面本身*。你把步骤描述为一张带类型的节点图，Gradio 会提供一个拖放画布：每个节点都可运行，每个中间结果都可见。同一张图还是一个 REST API，并且一条命令即可部署到 Hugging Face Spaces。

理解它的最好方式是看几个 workflow 实际运行。下面每个 app 都是可以直接打开、运行和复制（duplicate）的 Huggingface Space。

## 编辑图像

上传一张图，输入编辑指令（"把它变成雪景冬天"、"加上墨镜"、"把车变成红色"），拿回编辑后的照片。整个 app 就是一个节点，调用 Hugging Face Inference Providers 上的 [Qwen-Image-Edit](https://huggingface.co/Qwen/Qwen-Image-Edit)。

👉 **[试试 Image Editor Pipeline](https://huggingface.co/spaces/ysharma/gr-workflow-image-editor)**

## 把真实模型串成媒体工作室

一张图、三条 pipeline。从一个 prompt 开始，用 [FLUX](https://huggingface.co/black-forest-labs/FLUX.1-schnell) 生成图像，再把它交给一个[背景移除 Gradio Space](https://huggingface.co/spaces/not-lain/background-removal)做成贴纸。一个主题通过[文本转语音 Gradio Space](https://huggingface.co/spaces/mrfakename/MeloTTS)变成旁白，同一主题又通过一次 [LLM](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct) 调用变成抓人的节目标题。

这是一块画布：经由 Hugging Face [Inference Providers](https://huggingface.co/docs/inference-providers/en/index) 调用两个模型，另外调用两个 Gradio Spaces。

由于这是一个 workflow，三个输出也各自拥有 REST endpoint：`/sticker`、`/voiceover` 和 `/episode_title`。你可以直接从代码调用任何一个，无需打开 UI。可运行示例见下文 [从代码调用](https://huggingface.co/blog/gradio-workflow-guide#call-it-from-code)。

👉 **[试试 AI Media Studio](https://huggingface.co/spaces/ysharma/gr-workflow-04-ai-media-studio)**

## 并行扇出生成图像

输入一个点子，它立刻变出一组生成艺术作品：一张来自 FLUX 的底图，两个对该图的 AI 再创作（柔和水彩版和霓虹赛博朋克版），以及一个由 LLM 撰写的画廊标题。

每张图都由使用 Inference Providers 的模型节点直接依据 prompt 生成，标题则来自调用 LLM 的 `fn` 节点。这就是扇出（fan-out）模式：一个点子可以同时喂给多个算子，并行生成。

👉 **[试试 Generative Art Lab](https://huggingface.co/spaces/ysharma/gr-workflow-01-generative-art-lab)**

## 给 Hugging Face 数据集做画像

输入一个 Hugging Face 数据集 ID，比如 `stanfordnlp/imdb` 或 `mteb/tweet_sentiment_extraction`，单个输入扇出到四个算子节点，使用 [Datasets Server](https://huggingface.co/docs/dataset-viewer) API 实时分析数据集。

你会得到一张概览卡片、前几行的预览、逐列统计和一张分布图，全部独立并行计算。这就是 workflow 的威力！

👉 **[试试 Data Detective](https://huggingface.co/spaces/ysharma/gr-workflow-03-data-detective)**

## 运行你自己的 GPU 模型

前面每个节点都在访问 Hugging Face 的服务。但 `fn` 节点只是 Python，这意味着它也可以在 Space 内的 GPU 上运行模型。

给绑定的函数加上 `@spaces.GPU` 装饰器，节点运行时，[ZeroGPU](https://huggingface.co/docs/hub/spaces-zerogpu) 会为这次调用抓取一块 GPU、运行模型、然后释放。我们并不总是需要依赖 Inference Providers 或现成的 Gradio Spaces。

看看这个 demo：通过 Diffusers 加载 [Lightricks/LTX-Video](https://huggingface.co/Lightricks/LTX-Video-0.9.7-distilled)，把一张静态图像做成动画，全程只在单个节点内完成。`gr.Workflow` 不需要知道你的 GPU 配置的任何细节，它只负责调用绑定函数。

👉 **[试试 ZeroGPU Animator](https://huggingface.co/spaces/ysharma/gr-workflow-zerogpu-animate)**

## 工作原理简述

每个 workflow 都是一张图，包含三类节点：**引用**（你的输入）、**算子**（干活的步骤）和**主题**（你的输出）。算子可以是你自己的 Python 函数、Hugging Face Inference Providers 上的模型、另一个 Gradio Space，或 Hub 数据集中的一行。你在带类型的端口之间拖拽连线，点 Run，然后看着每个结果就地出现。

## 从代码调用

你构建的每个 workflow 同时也是一个 API，无需额外工作。每个输出都会变成以其标签命名的 REST endpoint，你可以用 Gradio client 从 Python 调用。下面是对多 endpoint demo Space 的实时、无需 token 的示例，原样可用：

```
from gradio_client import Client

client = Client("ysharma/gr-workflow-multi-endpoint-API")

print(client.predict("hello there friend", api_name="/word_count"))  # -> 3
print(client.predict(20, api_name="/fahrenheit"))                    # -> 68.0
```

调用模型或 Space 的 endpoint 需要在 Hugging Face token 下运行，所以创建 client 时传入一个：

```
from gradio_client import Client, handle_file

client = Client("ysharma/gr-workflow-image-editor", token="hf_...")

edited = client.predict(
    handle_file("dog.jpg"),
    "turn it into a snowy winter scene",
    api_name="/edited_image",
)
```

更喜欢纯 HTTP？每个 endpoint 也可以用 `curl` 访问：

```
curl -s https://ysharma-gr-workflow-multi-endpoint-API.hf.space/gradio_api/call/word_count \
  -H "Content-Type: application/json" -d '{"data": ["hello there friend"]}'
```

## 构建你自己的

最快的入门方式是打开上面任意一个 demo，点击 **Duplicate**，开始重新连线。从 Python 出发，代码短到：

```
import gradio as gr

def your_function(text: str) -> str:
  pass

gr.Workflow(bind=[your_function]).launch()
```

完整讲解、算子类型、JSON schema 和可复用模式，请看 Gradio 文档中的官方 [gr.Workflow 指南](https://gradio.app/guides/workflows)。

你甚至能用 `gr.Workflow` 构建像 [AUTOMATIC1111](https://github.com/automatic1111/stable-diffusion-webui) 这样复杂的项目。留意我们的下一篇文章，届时我们将一步步讲解如何重建它。先来个剧透 😉👇
