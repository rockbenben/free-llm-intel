LLM 体积庞大是出了名的，在消费级硬件上运行或训练它们，对用户和可及性来说都是巨大挑战。我们的 [LLM.int8 博客](https://huggingface.co/blog/hf-bitsandbytes-integration)介绍过 [LLM.int8 论文](https://arxiv.org/abs/2208.07339)中的技术如何通过 `bitsandbytes` 库集成进 transformers。为了让模型对任何人都更加触手可及，我们决定再次与 bitsandbytes 合作，让用户能够以 4-bit 精度运行模型。这涵盖 HF 上绝大多数模型，无论什么模态（文本、视觉、多模态等）。用户还可以借助 Hugging Face 生态的工具在 4bit 模型之上训练适配器（adapters）。这正是 Dettmers 等人在 QLoRA 论文中今天 introduced 的新方法。论文摘要如下：

> We present QLoRA, an efficient finetuning approach that reduces memory usage enough to finetune a 65B parameter model on a single 48GB GPU while preserving full 16-bit finetuning task performance. QLoRA backpropagates gradients through a frozen, 4-bit quantized pretrained language model into Low Rank Adapters~(LoRA). Our best model family, which we name Guanaco, outperforms all previous openly released models on the Vicuna benchmark, reaching 99.3% of the performance level of ChatGPT while only requiring 24 hours of finetuning on a single GPU. QLoRA introduces a number of innovations to save memory without sacrificing performance: (a) 4-bit NormalFloat (NF4), a new data type that is information theoretically optimal for normally distributed weights (b) double quantization to reduce the average memory footprint by quantizing the quantization constants, and (c) paged optimizers to manage memory spikes. We use QLoRA to finetune more than 1,000 models, providing a detailed analysis of instruction following and chatbot performance across 8 instruction datasets, multiple model types (LLaMA, T5), and model scales that would be infeasible to run with regular finetuning (e.g. 33B and 65B parameter models). Our results show that QLoRA finetuning on a small high-quality dataset leads to state-of-the-art results, even when using smaller models than the previous SoTA. We provide a detailed analysis of chatbot performance based on both human and GPT-4 evaluations showing that GPT-4 evaluations are a cheap and reasonable alternative to human evaluation. Furthermore, we find that current chatbot benchmarks are not trustworthy to accurately evaluate the performance levels of chatbots. A lemon-picked analysis demonstrates where Guanaco fails compared to ChatGPT. We release all of our models and code, including CUDA kernels for 4-bit training.

## 引言

如果你还不熟悉模型精度和最常见的数据类型（float16、float32、bfloat16、int8），我们建议你仔细阅读[我们的第一篇博客](https://huggingface.co/blog/hf-bitsandbytes-integration)，它用通俗的语言和可视化图示讲解了这些概念的细节。

更多信息，我们建议通过[这份 wikibook 文档](https://en.wikibooks.org/wiki/A-level_Computing/AQA/Paper_2/Fundamentals_of_data_representation/Floating_point_numbers#:~:text=In%20decimal%2C%20very%20large%20numbers,be%20used%20for%20binary%20numbers.)阅读浮点数表示的基础知识。

近期的 QLoRA 论文探讨了不同的数据类型：4-bit Float 和 4-bit NormalFloat。这里我们讨论 4-bit Float 数据类型，因为它更容易理解。

FP8 和 FP4 分别代表 Floating Point 8 位和 4 位精度。它们属于浮点值中的 minifloats（迷你浮点）家族（除其他精度外，minifloats 家族还包括 bfloat16 和 float16）。

我们先看看 FP8 格式如何表示浮点值，再理解 FP4 格式的样子。

### FP8 格式

正如我们上一篇博客所讨论的，一个浮点数包含 n 位，每一位都属于某个特定类别，负责表示这个数的一个组成部分（符号、尾数和指数）。这些部分表示如下内容。

FP8（floating point 8）格式首次在[《FP8 for Deep Learning》](https://arxiv.org/pdf/2209.05433.pdf)一文中被提出，带有两种不同的 FP8 编码：E4M3（4 位指数 + 3 位尾数）和 E5M2（5 位指数 + 2 位尾数）。

| --- |
| **Floating Point 8 (FP8) 格式总览。来源：[`sgugger`](https://huggingface.co/sgugger) 的原创内容 ** |

虽然把位数从 32 缩减到 8 大幅降低了精度，但两个版本在各种场景中都可用。目前可以使用 [Transformer Engine 库](https://github.com/NVIDIA/TransformerEngine)，它也通过 accelerate 与 HF 生态集成。

在 E4M3 格式下可表示的浮点范围是 -448 到 448；而在 E5M2 格式中，随着指数位数增加，范围扩大到 -57344 到 57344——但由于可表示的数的总量保持不变，这以精度为代价。经验证明，E4M3 最适合前向传播，而第二个版本最适合反向计算。

### 简单说说 FP4 精度

符号位表示符号（+/-），指数位表示 2 的若干次幂（该整数由位序列表示，例如 `2^{010} = 2^{2} = 4`），而小数部分（fraction 或 mantissa）是负二次幂之和，每个为「1」的位会「激活」对应的一项。如果某位为「0」，则该 `2^-i` 项对小数部分没有贡献（i 为该位在位序列中的位置）。例如，尾数位 1010 表示 `(0 + 2^-1 + 0 + 2^-3) = (0.5 + 0.125) = 0.625`。要得到一个数值，我们把 *1* 加到小数部分上，再把所有结果相乘。例如，在 2 位指数、1 位尾数下，位序列 1101 表示：

`-1 * 2^(2) * (1 + 2^-1) = -1 * 4 * 1.5 = -6`

FP4 并没有固定格式，因此可以尝试不同的尾数/指数组合。通常大多数情况下 3 位指数效果略好，但有时 2 位指数加 1 位尾数能带来更好的性能。

## QLoRA 论文：让量化后的大型 transformer 模型走向大众的新路径

简单来说，QLoRA 降低了 LLM 微调的内存占用，且相比标准 16-bit 模型微调没有性能损失。该方法让单个 24GB GPU 就能微调 33B 模型，单个 46GB GPU 就能微调 65B 模型。

更具体地说，QLoRA 使用 4-bit 量化来压缩一个预训练语言模型。LM 参数随后被冻结，并以 Low-Rank Adapters（低秩适配器）的形式向模型添加相对少量的可训练参数。在微调过程中，QLoRA 将梯度穿过冻结的、4-bit 量化的预训练语言模型反向传播到低秩适配器中。LoRA 层是训练中唯一被更新的参数。关于 LoRA 的更多内容见[原始 LoRA 论文](https://arxiv.org/abs/2106.09685)。

QLoRA 有一个用于基础模型权重的存储数据类型（通常是 4-bit NormalFloat）和一个用于执行计算的计算数据类型（16-bit BrainFloat）。QLoRA 在执行前向和反向传播时把权重从存储数据类型反量化到计算数据类型，但只为使用 16-bit bfloat 的 LoRA 参数计算权重梯度。权重只在需要时才被解压，因此训练和推理期间的内存占用始终保持低位。

大量实验表明，QLoRA 调优可以匹配 16-bit 微调方法。此外，Guanaco 模型家族——使用 QLoRA 在 [OpenAssistant 数据集（OASST1）](https://huggingface.co/datasets/OpenAssistant/oasst1)上对 LLaMA 模型微调——是最先进的聊天机器人系统，在 Vicuna 基准上接近 ChatGPT。这是 QLoRA 调优实力的又一个例证。

想更深入了解，我们推荐阅读 [QLoRA 论文](https://arxiv.org/abs/2305.14314)。

## 在 transformers 中如何使用？

本节我们介绍该方法在 transformers 中的集成、如何使用，以及哪些模型可以被有效量化。

### 快速开始

作为快速上手，以 4bit 加载模型需要（撰写本文时）从源码安装 accelerate 和 transformers，并确保安装了最新版 bitsandbytes 库（0.39.0）。

```
pip install -q -U bitsandbytes
pip install -q -U git+https://github.com/huggingface/transformers.git
pip install -q -U git+https://github.com/huggingface/peft.git
pip install -q -U git+https://github.com/huggingface/accelerate.git
```

### Quickstart

以 4bit 加载模型的基本方式，是在调用 `from_pretrained` 方法时传入参数 `load_in_4bit=True`，同时提供一个 device map（传 `"auto"` 会自动推断出 device map）。

```
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained("facebook/opt-350m", load_in_4bit=True, device_map="auto")
...
```

就这么简单！

作为一般规则，我们建议用户在模型通过 `device_map` 加载后，不要再手动设置设备。因此在那一行之后，应当避免对模型或任何模型子模块做设备分配调用——除非你很清楚自己在做什么。

请注意，加载量化模型会自动把模型的其他子模块转换为 `float16` dtype。如果想改变这一行为（比如你希望 layer norm 使用 `float32`），可以通过向 `from_pretrained` 方法传入 `torch_dtype=dtype` 来实现。

### 进阶用法

你可以尝试 4bit 量化的不同变体，例如 NF4（normalized float 4，默认）或纯 FP4 量化。基于理论考量和论文中的实证结果，我们推荐使用 NF4 量化以获得更好的性能。

其他选项还包括 `bnb_4bit_use_double_quant`：它在第一次量化之后再做一次量化，从而每个参数额外节省 0.4 bit。最后是计算类型：虽然 4-bit bitsandbytes 以 4 bit 存储权重，但计算仍然以 16 或 32-bit 进行，这里可以选择任意组合（float16、bfloat16、float32 等）。

使用 16-bit 计算 dtype 时，矩阵乘法和训练会更快（默认是 torch.float32）。应当善用 transformers 新的 `BitsAndBytesConfig` 来修改这些参数。下面是一个使用 NF4 量化加载 4bit 模型的例子，同时启用双重量化，并以 bfloat16 作为计算 dtype 以加速训练：

```
from transformers import BitsAndBytesConfig


nf4_config = BitsAndBytesConfig(
   load_in_4bit=True,
   bnb_4bit_quant_type="nf4",
   bnb_4bit_use_double_quant=True,
   bnb_4bit_compute_dtype=torch.bfloat16
)

model_nf4 = AutoModelForCausalLM.from_pretrained(model_id, quantization_config=nf4_config)
```

#### 更改计算 dtype

如上所述，只需修改 `BitsAndBytesConfig` 中的 `bnb_4bit_compute_dtype` 参数即可更改量化模型的计算 dtype。

```
import torch
from transformers import BitsAndBytesConfig

quantization_config = BitsAndBytesConfig(
   load_in_4bit=True,
   bnb_4bit_compute_dtype=torch.bfloat16
)
```

#### 嵌套量化

要启用嵌套量化（nested quantization），可以在 `BitsAndBytesConfig` 中使用 `bnb_4bit_use_double_quant` 参数。这会在第一次量化之后再启用第二次量化，每个参数额外节省 0.4 bit。我们在训练版 Google Colab notebook 中也使用了这一特性。

```
from transformers import BitsAndBytesConfig

double_quant_config = BitsAndBytesConfig(
   load_in_4bit=True,
   bnb_4bit_use_double_quant=True,
)

model_double_quant = AutoModelForCausalLM.from_pretrained(model_id, quantization_config=double_quant_config)
```

当然，正如本节开头所说，这些组件都可以组合使用。你可以把所有这些参数拼在一起，找到最适合自己场景的用法。经验法则是：内存吃紧就用 double quant，追求更高精度就用 NF4，想要更快微调就用 16-bit dtype。比如在[推理 demo](https://colab.research.google.com/drive/1ge2F1QSK8Q7h0hn3YKuBCOAS0bK8E0wf?usp=sharing)中，我们用嵌套量化 + bfloat16 计算 dtype + NF4 量化，把 gpt-neo-x-20b（40GB）完全以 4bit 装进单张 16GB GPU。

### 常见问题

本节我们也回答一下关于这一集成的常见问题。

#### FP4 量化有硬件要求吗？

注意该方法仅兼容 GPU，因此无法在 CPU 上以 4bit 量化模型。在 GPU 中，该方法本身没有特别的硬件要求，只要装有 CUDA>=11.2，任何 GPU 都可以运行 4bit 量化。还要记住，计算并不是在 4bit 下进行的——只是权重和激活被压缩为该格式，计算仍以期望的或原生的 dtype 保持进行。

#### 支持哪些模型？

与[这篇博客](https://huggingface.co/blog/hf-bitsandbytes-integration)中介绍的 LLM.int8 集成一样，这个集成同样重度依赖 `accelerate` 库。因此，任何支持 accelerate 加载（即调用 `from_pretrained` 时支持 `device_map` 参数）的模型都可以做 4bit 量化。另外请注意，这与模态完全无关——只要模型能通过 `device_map` 参数加载，就可以对它做量化。

就文本模型而言，截至撰写本文时，这涵盖了最常用的架构，如 Llama、OPT、GPT-Neo、GPT-NeoX，多模态模型中的 Blip2 等等。

#### 可以训练 4bit/8bit 模型吗？

无法在这些模型上执行纯粹的 4bit 训练。不过，可以借助参数高效微调方法（PEFT）来训练这些模型，例如在其上训练适配器。这正是论文采用的做法，也是 Hugging Face 的 PEFT 库官方支持的功能。我们还提供了一个[训练 notebook](https://colab.research.google.com/drive/1VoYNfYDKcKRQRor98Zbf2-9VQTtGJ24k?usp=sharing)，并建议有兴趣复现论文结果的用户查看 [QLoRA 仓库](https://github.com/artidoro/qlora)。
