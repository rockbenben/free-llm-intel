大语言模型（LLM）的快速进步让既有学术与工业基准取得了长足进展。MMLU、GPQA 这类知识型基准如今已接近饱和，前沿模型也在 [HLE](https://huggingface.co/blog/lastexam.ai) 这类专家级评测上不断突破。然而，在静态知识型任务上的成功，并不总能在动态、交互式场景中转化为效能——而那正是我们希望高效助手与 AI agent 大显身手的环境。为 LLM 作为复杂探索环境中自主 agent 的表现建立稳健的评估方法论，仍是重大挑战。

评估自主 agent 有两条核心路径：要么使用真实环境加一小组特定技能（如工具使用或编码能力），要么使用模拟的开放世界环境。后者能更好地刻画 agent 在探索性环境中自主运行的能力——它要求在越来越长的上下文中持续进行自主推理，同时又便于评估。这一方向虽仍在发展中，但已因 [Balrog](https://balrogai.com)、ARC-AGI 等基准以及 Claude、Gemini 玩宝可梦的演示而受到越来越多的关注。沿着这条新兴路线，我们推出了 [TextQuests](https://huggingface.co/spaces/cais/textquests)。

## TextQuests

TextQuests 建立在 25 款经典 [Infocom](https://en.wikipedia.org/wiki/Infocom) 互动小说游戏之上。这些曾经风靡的文字冒险游戏，人类玩家需要 30 小时以上、需要数百个精确动作才能通关，为 agentic 推理的挑战提供了极具说服力的试验场。它们要求 agent 展现出：

- **长上下文推理：** agent 必须在不断增长的动作与观察历史上制定并执行多步计划，仅凭自身内在能力、不借助任何外部工具。
- **在探索中学习：** 游戏要求 agent 从经验中学习，审视自己的失败，在探索未知世界的过程中通过反复试错渐进改进。

在这些游戏中取得成功，要求 agent 在漫长的游戏会话中构建理解。这让我们能更直接、准确地评估 LLM 本身——作为 AI agent 系统的推理骨架。

## 评估

对每个模型，我们做两种不同的评估运行：一种可访问游戏官方提示（`With Clues`），一种不可（`No Clues`）。每次运行最多 500 步，若 agent 成功通关则提前停止。为处理不断增长的上下文，完整游戏历史在整次运行中不做截断地维护。得益于现代 LLM 推理框架内建的 prompt caching，这种长上下文评估在计算上是可行的。我们采用两个主要评估指标：

- **Game Progress（游戏进度）。** 该指标基于一组带标注的检查点计算，这些检查点代表通关路径上必需的目标。
- **Harm（伤害）。** 为评估 agent 的伦理行为，我们通过追踪游戏内某些在某种程度上被视为有害的具体动作来测量 Harm。该分数在全部游戏上取平均，以评估 agent 做出此类动作的整体倾向。

## 讨论

**长上下文推理。** 评估期间，上下文窗口可超过 100K token，要求 LLM 在海量观察与提示历史上持续进行精确的推理与规划才能有效推进。随着上下文变长，我们观察到当前模型常常对既往交互产生幻觉——比如以为自己已经捡起了某个物品（实际没有），或困在导航循环里。此外，与 [Gemini 2.5 Plays Pokémon](https://arxiv.org/abs/2507.06261) 中的观察类似，随着上下文变长，LLM agent 表现出更多重复历史动作的倾向，而不是合成新的计划。这些长上下文失效在需要空间推理的任务上尤其明显。例如在 *Wishbringer* 中，多数 LLM 在爬上悬崖后无法原路爬下。解法只需把登顶时使用的方向序列反转——这些信息就在上下文历史里——说明模型在构建和利用心智地图方面存在根本性困难。类似地，所有前沿 LLM 都在 *Zork I* 中声名狼藉的迷宫里举步维艰。

TextQuests 中长上下文推理失效的示例。

左：在 *Zork I* 中，受测 LLM 未能正确回忆自己历史中的信息，幻觉以为自己把火柴盒丢在了 Studio（工作室），而不是 Atlantis Room（大西洋厅）。

右：在 *Wishbringer* 中，LLM 常常无法从上下文历史中取回并反转自己的登顶路径，从而无法成功下崖。

**动态思考。** agent 的整体效能由其任务成功率与运行效率共同定义。对 LLM agent，效率与其输出的推理 token 数密切相关，直接影响推理成本与延迟。总体上，使用更多 test-time 计算（测试时计算）的模型性能更高。但超过一定预算后，这一趋势开始衰减。这一考量很重要，因为 TextQuests 中许多探索步骤（例如导航步骤）是中间性的，不需要很深的推理就能顺利完成。

最先进 LLM 在 TextQuests 上输出/推理 token 效率的对比。由于许多探索步骤是中间性的、不需要完整推理预算，理想的 LLM agent 应当在保持性能稳定的同时，让推理投入高效且有弹性。

总之，TextQuests 评估的是模型能在多大程度上稳定推进一系列曾经风靡人类的经典互动小说游戏。我们希望 TextQuests 的开源能帮助研究者更好地理解与评估 LLM agent 在富有挑战的探索环境中的当前能力。欢迎开源模型构建者发送邮件到 [agibenchmark@safe.ai](mailto:agibenchmark@safe.ai) 向 [TextQuests Leaderboard](https://huggingface.co/spaces/cais/textquests) 提交结果。
