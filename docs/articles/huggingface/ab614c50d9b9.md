# 通过 Flash Attention 2 打包提升 Hugging Face 训练效率

## TL;DR

得益于最近的 [PR](https://github.com/huggingface/transformers/pull/31629) 和新的 [DataCollatorWithFlattening](https://huggingface.co/docs/transformers/main/en/main_classes/data_collator#transformers.DataCollatorWithFlattening)，用打包（packing，无 padding）的指令微调样本训练，如今已与 Hugging Face 中的 Flash Attention 2 兼容。

训练吞吐最高可提升 2 倍，同时收敛质量不打折。详情见下文！

## 引言

训练时在 mini-batch 内对输入序列做 padding 是常见的收拢手段，但无用的 padding token 引入了低效。不做 padding、直接打包样本并利用 token 位置信息，是更高效的替代方案。然而以往的 packing 实现在使用 Flash Attention 2 时不考虑样本边界，导致不期望的跨样本注意力，拉低质量和收敛。

Hugging Face Transformers 现在解决了这个问题：新功能在打包时保持边界感知，同时引入新的 data collator `DataCollatorWithFlattening`。

选择 `DataCollatorWithFlattening` 后，Hugging Face `Trainer` 用户可以在 Flash Attention 2 计算中考虑序列边界，无缝地把多个序列拼接成单个张量。这通过 `flash_attn_varlen_func` 实现，它计算每个 mini-batch 内的累积序列长度（`cu_seqlens`）。

`TRL` 库中的 Hugging Face `SFTTrainer` 用户也能用同样的功能：调用 data collator `DataCollatorForCompletionOnlyLM` 时设置新标志 `padding_free=True` 即可。

## 最高 2 倍吞吐提升

使用这个新特性配合 `DataCollatorWithFlattening`，训练吞吐显著提升。下图展示了以 tokens/秒度量的训练吞吐。该示例中，吞吐是在 8 块 A100-80 GPU 上、对 FLAN 和 OrcaMath 两个指令微调数据集各随机抽 20K 样本训练一个 epoch 的每 GPU 平均值。

[![throughput](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/packing-with-FA2/thruput.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/packing-with-FA2/thruput.png)

FLAN 平均序列短但长度方差大，每个 batch 里的样本长度可能参差不齐，意味着带 padding 的 FLAN batch 会在无用的 padding token 上产生可观开销。在 FLAN 数据集上用新的 `DataCollatorWithFlattening` 训练，吞吐收益显著：在图中展示的三个模型 llama2-7B、mistral-7B、granite-8B-code 上观察到 2 倍吞吐提升。

OrcaMath 样本更长、长度方差更小，因此 packing 带来的提升也较小。实验显示，在 OrcaMath 数据集上用这种 packing 训练这三个模型，吞吐提升 1.4 倍。

[![memory](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/packing-with-FA2/memory.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/packing-with-FA2/memory.png)

内存方面同样因新的 `DataCollatorWithFlattening` 打包而改善。下图是同样三个模型在同样两个数据集上的峰值内存。在从打包中受益颇多的 FLAN 数据集上，峰值内存降低 20%。

在样本长度更均匀的 OrcaMath 数据集上，峰值内存降低 6%。

打包样本减少了优化步数时，可能损害训练收敛。但新特性保留了 mini-batch，因此优化步数与带 padding 训练时相同。训练收敛不受影响——下图可见，同一模型在相同数据集上无论用新的 `DataCollatorWithFlattening` 打包训练还是 padding 训练，验证损失完全一致。

[![ValLoss](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/packing-with-FA2/ValLoss.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/packing-with-FA2/ValLoss.png)

## 工作原理

考虑 batchsize = 4 的一个数据 batch，其中四个序列如下：

[![batch](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/packing-with-FA2/four_sequences.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/packing-with-FA2/four_sequences.png)

拼接样本后，无 padding 的 collator 返回每个样本的 `input_ids`、`labels` 和 `position_ids`。因此对这个 batch，collator 提供：

[![example](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/packing-with-FA2/input_ids_labels_position_ids.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/packing-with-FA2/input_ids_labels_position_ids.png)

所需的改动很轻量，仅限于把 `position_ids` 传给 Flash Attention 2。

不过这依赖模型暴露 `position_ids`。截至发稿，有 14 个模型暴露了 `position_ids` 并受该方案支持。具体包括：Llama 2 和 3、Mistral、Mixtral、Granite、DBRX、Falcon、Gemma、OLMo、Phi 1、2 和 3、phi3、Qwen 2 和 2 MoE、StableLM、StarCoder 2 都受支持。

## 快速上手

享受 `position_ids` 打包的好处很简单。

如果你用 `Transformers` 的 Hugging Face `Trainer`，只需两步：

- 用 Flash Attention 2 实例化模型
- 使用新的 `DataCollatorWithFlattening`

如果你用 `TRL` 的 Hugging Face `SFTTrainer` 配 `DataCollatorForCompletionOnlyLM`，所需两步是：

- 用 Flash Attention 2 实例化模型
- 调用 `DataCollatorForCompletionOnlyLM` 时设置 `padding_free=True`，形如：`collator = DataCollatorForCompletionOnlyLM(response_template_ids, tokenizer=tokenizer, padding_free=True)`

## 使用方法

对 `Trainer` 用户，下面示例演示如何使用新特性。

```
# Example using DataCollatorWithFlattening
 
import torch

# load model as usual
from transformers import AutoModelForCausalLM
model = AutoModelForCausalLM.from_pretrained(
    "instructlab/merlinite-7b-lab",
    torch_dtype=torch.bfloat16,
    attn_implementation="flash_attention_2"
)

# read dataset as usual
from datasets import load_dataset
train_dataset = load_dataset("json", data_files="path/to/my/dataset")["train"]

# use DataCollatorWithFlattening
from transformers import DataCollatorWithFlattening
data_collator = DataCollatorWithFlattening()

# train
from transformers import TrainingArguments, Trainer
train_args = TrainingArguments(output_dir="/save/path")
trainer = Trainer(
    args=train_args,
    model=model,
    train_dataset=train_dataset,
    data_collator=data_collator
)
trainer.train()
```

对 `TRL` 用户，下面示例演示在 `SFTTrainer` 中使用新特性。

```
# SFTTrainer example using DataCollatorForCompletionOnlyLM

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from datasets import load_dataset
from trl import SFTConfig, SFTTrainer, DataCollatorForCompletionOnlyLM

dataset = load_dataset("lucasmccabe-lmi/CodeAlpaca-20k", split="train")

model = AutoModelForCausalLM.from_pretrained(
    "instructlab/merlinite-7b-lab",
    torch_dtype=torch.bfloat16,
    attn_implementation="flash_attention_2")
tokenizer = AutoTokenizer.from_pretrained("instructlab/merlinite-7b-lab")
tokenizer.pad_token = tokenizer.eos_token 

def formatting_prompts_func(example):
    output_texts = []
    for i in range(len(example['instruction'])):
        text = f"### Question: {example['instruction'][i]}\n ### Answer: {example['output'][i]}"
        output_texts.append(text)
    return output_texts

response_template = " ### Answer:"
response_template_ids = tokenizer.encode(response_template, add_special_tokens=False)[2:]
collator = DataCollatorForCompletionOnlyLM(response_template_ids, tokenizer=tokenizer, padding_free=True)

trainer = SFTTrainer(
    model,
    train_dataset=dataset,
    args=SFTConfig(
        output_dir="./tmp",
        gradient_checkpointing=True,
        per_device_train_batch_size=8
    ),
    formatting_func=formatting_prompts_func,
    data_collator=collator,
)

trainer.train()
```

## 结论

得益于最近的 PR 和新的 `DataCollatorWithFlattening`，指令微调样本打包（而非 padding）如今与 Flash Attention 2 完全兼容。该方法兼容使用 `position_ids` 的模型。收益体现在训练吞吐和峰值内存上，而训练收敛毫无退化。实际的吞吐和内存改善取决于模型以及训练数据中样本长度的分布。样本长度差异越大的数据，用 `DataCollatorWithFlattening` 相对 padding 的获益越大。`TRL` 库中的 `SFTTrainer` 用户调用 `DataCollatorForCompletionOnlyLM` 时设置新标志 `padding_free=True` 即可获得同样能力。

更详尽的分析可看论文 [https://huggingface.co/papers/2407.09105](https://huggingface.co/papers/2407.09105)
