## 引言

时间序列预测是科学与商业上的核心问题，最近也见证了大量创新：除了[经典方法](https://otexts.com/fpp3/)之外，还出现了[基于深度学习](https://dl.acm.org/doi/abs/10.1145/3533382)的模型。ARIMA 这类经典方法与新型深度学习方法的一个重要区别如下。

## 概率性预测

通常，经典方法对数据集里的每条时间序列分别单独拟合，这类方法常被称为"单条"或"局部"方法。但当应用涉及海量时间序列时，在所有可用序列上训练一个"全局"模型更有利——它能让模型从许多不同来源学习潜在表示。

一些经典方法是点值的（即每个时间步只输出一个值），训练时对真值数据最小化 L2 或 L1 损失。但预测往往要用于真实世界的决策流程（哪怕有人参与），此时提供预测的不确定性要有用得多。这就是所谓的"概率性预测"（probabilistic forecasting），与"点预测"（point forecasting）相对。它意味着要建模一个概率分布，从中可以采样。

所以简单说：与其训练局部点预测模型，我们更想训练**全局概率性**模型。深度学习非常契合这一目标——神经网络既能从多条相关时间序列中学习表示，又能对数据的不确定性建模。

在概率性设置下，常见做法是学习某个选定参数化分布（如高斯分布或 Student-T 分布）未来时刻的参数；或学习条件分位数函数；或使用适配到时间序列场景的 Conformal Prediction 框架。方法的选择并不影响建模本身，通常可视作又一个超参数。概率性模型随时可以变成点预测模型——取经验均值或中位数即可。

## 时间序列 Transformer

时间序列本质上是序列数据，容易想象，研究者提出了基于循环神经网络（RNN，如 LSTM 或 GRU）、卷积网络（CNN）以及更近期 Transformer 系列的模型——后者天然契合时间序列预测场景。

在这篇博客里，我们将用原始 Transformer [(Vaswani et al., 2017)](https://arxiv.org/abs/1706.03762)来完成**单变量**概率性预测任务（即对每条时间序列分别预测其一维分布）。编码器-解码器 Transformer 用于预测是自然而然的选择，它把好几条归纳偏置（inductive biases）很好地封装了进去。

首先，在推理时使用编码器-解码器架构很方便：通常我们想基于某些已记录的数据，预测未来若干步。这和文本生成任务类似——给定上下文，采样下一个 token 再喂回解码器（也叫"自回归生成"）。同理，这里也可以在给定某种分布类型后，从分布中采样得到预测，一直持续到期望的预测视界（prediction horizon）。这称为祖先采样（Ancestral Sampling）。关于语言模型中的采样，[这篇博客](https://huggingface.co/blog/how-to-generate)写得很好。

其次，Transformer 帮助我们训练可能包含数千个时间点的序列数据。由于注意力机制的时间与内存约束，把一条序列*全部*历史一次性输入模型并不可行。因此可以选定一个合适的上下文窗口，在构造随机梯度下降（SGD）的 batch 时，从训练数据中采一个上下文窗口大小的窗口、紧接一个预测长度大小的窗口。上下文窗口喂给编码器，预测窗口喂给*带因果掩码（causal-masked）*的解码器，即解码器在学习下一个值时只能看到之前的时间步。这等同于给机器翻译训练原始 Transformer 的方式——即"teacher forcing"。

相比其他架构，Transformer 还有一个好处：我们可以把缺失值（时间序列里很常见）作为额外的掩码加到编码器或解码器上，照样训练，无需插值或填补。这与 Transformers 库中 BERT、GPT-2 等模型的 `attention_mask`（把 padding token 排除在注意力矩阵计算之外）同理。

Transformer 架构的一个缺点是上下文和预测窗口的大小受限——原始 Transformer 的计算和内存开销随序列长度平方增长，见 [Tay et al., 2020](https://arxiv.org/abs/2009.06732)。此外，由于 Transformer 很强，它比其他[方法](https://openreview.net/pdf?id=D7YBmfX_VQy)更容易过拟合或学到虚假相关。

🤗 Transformers 库自带一个原始的概率性时间序列 Transformer 模型，就叫 [Time Series Transformer](https://huggingface.co/docs/transformers/model_doc/time_series_transformer)。下文我们将展示如何在自定义数据集上训练这样的模型。

## 把 `start` 转成 `pd.Period`

我们要做的第一件事，是用数据的 `freq` 把每条时间序列的 `start` 特征转换为 pandas `Period` 索引：

```
from functools import lru_cache

import pandas as pd
import numpy as np

@lru_cache(10_000)
def convert_to_pandas_period(date, freq):
    return pd.Period(date, freq)

def transform_start_field(batch, freq):
    batch["start"] = [convert_to_pandas_period(date, freq) for date in batch["start"]]
    return batch
```

现在用 `datasets` 的 [`set_transform`](https://huggingface.co/docs/datasets/v2.7.0/en/package_reference/main_classes#datasets.Dataset.set_transform) 功能就地、即时地完成这一转换：

```
from functools import partial

train_dataset.set_transform(partial(transform_start_field, freq=freq))
test_dataset.set_transform(partial(transform_start_field, freq=freq))
```

## 定义模型

接下来实例化一个模型。模型将从零开始训练，所以这里不用 `from_pretrained` 方法，而是从 [`config`](https://huggingface.co/docs/transformers/model_doc/time_series_transformer#transformers.TimeSeriesTransformerConfig) 随机初始化。

我们要给模型指定若干附加参数：

- `prediction_length`（我们的例子里是 `24` 个月）：Transformer 解码器将学习预测的视界长度；
- `context_length`：若未指定 `context_length`，模型会把它设置为与 `prediction_length` 相等（编码器输入长度）；
- 给定频率下的 `lags`：表示我们"往回看"多远并作为额外特征加入。例如对 `Daily` 频率可能考虑 `[1, 2, 7, 30, ...]`，即回看 1、2……天；对 `Minute` 数据可能考虑 `[1, 30, 60, 60*24, ...]` 等；
- 时间特征数量：这里是 `2`，因为我们会添加 `MonthOfYear`（月份）和 `Age`（序列年龄）特征；
- 静态类别特征数量：这里只有 `1`，即一个"时间序列 ID"特征；
- cardinality（基数）：每个静态类别特征的取值个数，列表形式；这里是 `[366]`，因为有 366 条不同的时间序列；
- embedding 维度：每个静态类别特征的嵌入维度列表，例如 `[3]` 表示模型会为 366 条时间序列（地区）中的每条学一个长度为 `3` 的嵌入向量。

我们直接使用 GluonTS 针对"monthly"频率提供的默认 lags：

```
from gluonts.time_feature import get_lags_for_frequency

lags_sequence = get_lags_for_frequency(freq)
print(lags_sequence)

>>> [1, 2, 3, 4, 5, 6, 7, 11, 12, 13, 23, 24, 25, 35, 36, 37]
```

这意味着对每个时间步，我们最多回看 37 个月作为额外特征。

再看看 GluonTS 提供的默认时间特征：

```
from gluonts.time_feature import time_features_from_frequency_str

time_features = time_features_from_frequency_str(freq)
print(time_features)

>>> [<function month_of_year at 0x7fa496d0ca70>]
```

这里只有一个特征："一年中的第几个月"。也就是说，对每个时间步，我们会把月份作为一个标量值加入（时间戳是"一月"则为 `1`，"二月"则为 `2`，依此类推）。

现在具备了一切条件，可以定义模型：

```
from transformers import TimeSeriesTransformerConfig, TimeSeriesTransformerForPrediction

config = TimeSeriesTransformerConfig(
    prediction_length=prediction_length,
    # context length:
    context_length=prediction_length * 2,
    # lags coming from helper given the freq:
    lags_sequence=lags_sequence,
    # we'll add 2 time features ("month of year" and "age", see further):
    num_time_features=len(time_features) + 1,
    # we have a single static categorical feature, namely time series ID:
    num_static_categorical_features=1,
    # it has 366 possible values:
    cardinality=[len(train_dataset)],
    # the model will learn an embedding of size 2 for each of the 366 possible values:
    embedding_dimension=[2],
    
    # transformer params:
    encoder_layers=4,
    decoder_layers=4,
    d_model=32,
)

model = TimeSeriesTransformerForPrediction(config)
```

注意，与 🤗 Transformers 库中其他模型类似，[`TimeSeriesTransformerModel`](https://huggingface.co/docs/transformers/model_doc/time_series_transformer#transformers.TimeSeriesTransformerModel) 对应不带任何输出头的编码器-解码器 Transformer，而 [`TimeSeriesTransformerForPrediction`](https://huggingface.co/docs/transformers/model_doc/time_series_transformer#transformers.TimeSeriesTransformerForPrediction) 对应在其上加了一个**分布头（distribution head）**的 `TimeSeriesTransformerModel`。默认使用 Student-t 分布（可配置）：

```
model.config.distribution_output

>>> student_t
```

这是与 NLP 类 Transformers 的一个重要区别：NLP 模型的输出头通常是由 `nn.Linear` 实现的固定类别分布。

## 定义变换

接下来定义数据变换，尤其是时间特征的创建（基于数据集的或通用的）。

仍然使用 GluonTS 库。我们定义一条变换 `Chain`（类似于图像领域 `torchvision.transforms.Compose`），可以把多个变换组合成一条流水线。

```
from gluonts.time_feature import (
    time_features_from_frequency_str,
    TimeFeature,
    get_lags_for_frequency,
)
from gluonts.dataset.field_names import FieldName
from gluonts.transform import (
    AddAgeFeature,
    AddObservedValuesIndicator,
    AddTimeFeatures,
    AsNumpyArray,
    Chain,
    ExpectedNumInstanceSampler,
    InstanceSplitter,
    RemoveFields,
    SelectFields,
    SetField,
    TestSplitSampler,
    Transformation,
    ValidationSplitSampler,
    VstackFeatures,
    RenameFields,
)
```

下面的变换都加了注释说明其作用。总体上，我们会遍历数据集中的每条时间序列，逐条添加/删除字段或特征：

```
from transformers import PretrainedConfig

def create_transformation(freq: str, config: PretrainedConfig) -> Transformation:
    remove_field_names = []
    if config.num_static_real_features == 0:
        remove_field_names.append(FieldName.FEAT_STATIC_REAL)
    if config.num_dynamic_real_features == 0:
        remove_field_names.append(FieldName.FEAT_DYNAMIC_REAL)
    if config.num_static_categorical_features == 0:
        remove_field_names.append(FieldName.FEAT_STATIC_CAT)

    # a bit like torchvision.transforms.Compose
    return Chain(
        # step 1: remove static/dynamic fields if not specified
        [RemoveFields(field_names=remove_field_names)]
        # step 2: convert the data to NumPy (potentially not needed)
        + (
            [
                AsNumpyArray(
                    field=FieldName.FEAT_STATIC_CAT,
                    expected_ndim=1,
                    dtype=int,
                )
            ]
            if config.num_static_categorical_features > 0
            else []
        )
        + (
            [
                AsNumpyArray(
                    field=FieldName.FEAT_STATIC_REAL,
                    expected_ndim=1,
                )
            ]
            if config.num_static_real_features > 0
            else []
        )
        + [
            AsNumpyArray(
                field=FieldName.TARGET,
                # we expect an extra dim for the multivariate case:
                expected_ndim=1 if config.input_size == 1 else 2,
            ),
            # step 3: handle the NaN's by filling in the target with zero
            # and return the mask (which is in the observed values)
            # true for observed values, false for nan's
            # the decoder uses this mask (no loss is incurred for unobserved values)
            # see loss_weights inside the xxxForPrediction model
            AddObservedValuesIndicator(
                target_field=FieldName.TARGET,
                output_field=FieldName.OBSERVED_VALUES,
            ),
            # step 4: add temporal features based on freq of the dataset
            # month of year in the case when freq="M"
            # these serve as positional encodings
            AddTimeFeatures(
                start_field=FieldName.START,
                target_field=FieldName.TARGET,
                output_field=FieldName.FEAT_TIME,
                time_features=time_features_from_frequency_str(freq),
                pred_length=config.prediction_length,
            ),
            # step 5: add another temporal feature (just a single number)
            # tells the model where in its life the value of the time series is,
            # sort of a running counter
            AddAgeFeature(
                target_field=FieldName.TARGET,
                output_field=FieldName.FEAT_AGE,
                pred_length=config.prediction_length,
                log_scale=True,
            ),
            # step 6: vertically stack all the temporal features into the key FEAT_TIME
            VstackFeatures(
                output_field=FieldName.FEAT_TIME,
                input_fields=[FieldName.FEAT_TIME, FieldName.FEAT_AGE]
                + (
                    [FieldName.FEAT_DYNAMIC_REAL]
                    if config.num_dynamic_real_features > 0
                    else []
                ),
            ),
            # step 7: rename to match HuggingFace names
            RenameFields(
                mapping={
                    FieldName.FEAT_STATIC_CAT: "static_categorical_features",
                    FieldName.FEAT_STATIC_REAL: "static_real_features",
                    FieldName.FEAT_TIME: "time_features",
                    FieldName.TARGET: "values",
                    FieldName.OBSERVED_VALUES: "observed_mask",
                }
            ),
        ]
    )
```

## 定义 `InstanceSplitter`

针对训练/验证/测试，接下来创建 `InstanceSplitter`——它用于从数据集中采样窗口（记住，出于时间与内存约束，我们不能把整段历史都喂给 Transformer）。

实例分割器从数据中随机采样 `context_length` 大小的窗口及紧随其后 `prediction_length` 大小的窗口，并对 `time_series_fields` 中的时间键分别加上 `past_` 或 `future_` 前缀。实例分割器可配置为三种模式：

- `mode="train"`：从传入的数据集（训练集）中随机采样上下文窗口和预测窗口
- `mode="validation"`：从传入数据集中采样最后一个上下文窗口和预测窗口（用于回测或验证似然计算）
- `mode="test"`：只采样最后一个上下文窗口（用于预测场景）

```
from gluonts.transform.sampler import InstanceSampler
from typing import Optional

def create_instance_splitter(
    config: PretrainedConfig,
    mode: str,
    train_sampler: Optional[InstanceSampler] = None,
    validation_sampler: Optional[InstanceSampler] = None,
) -> Transformation:
    assert mode in ["train", "validation", "test"]

    instance_sampler = {
        "train": train_sampler
        or ExpectedNumInstanceSampler(
            num_instances=1.0, min_future=config.prediction_length
        ),
        "validation": validation_sampler
        or ValidationSplitSampler(min_future=config.prediction_length),
        "test": TestSplitSampler(),
    }[mode]

    return InstanceSplitter(
        target_field="values",
        is_pad_field=FieldName.IS_PAD,
        start_field=FieldName.START,
        forecast_start_field=FieldName.FORECAST_START,
        instance_sampler=instance_sampler,
        past_length=config.context_length + max(config.lags_sequence),
        future_length=config.prediction_length,
        time_series_fields=["time_features", "observed_mask"],
    )
```

## 创建 DataLoaders

接下来创建 DataLoaders，得到（输入，输出）对的 batch——也就是（`past_values`，`future_values`）。

```
from typing import Iterable

import torch
from gluonts.itertools import Cached, Cyclic
from gluonts.dataset.loader import as_stacked_batches


def create_train_dataloader(
    config: PretrainedConfig,
    freq,
    data,
    batch_size: int,
    num_batches_per_epoch: int,
    shuffle_buffer_length: Optional[int] = None,
    cache_data: bool = True,
    **kwargs,
) -> Iterable:
    PREDICTION_INPUT_NAMES = [
        "past_time_features",
        "past_values",
        "past_observed_mask",
        "future_time_features",
    ]
    if config.num_static_categorical_features > 0:
        PREDICTION_INPUT_NAMES.append("static_categorical_features")

    if config.num_static_real_features > 0:
        PREDICTION_INPUT_NAMES.append("static_real_features")

    TRAINING_INPUT_NAMES = PREDICTION_INPUT_NAMES + [
        "future_values",
        "future_observed_mask",
    ]

    transformation = create_transformation(freq, config)
    transformed_data = transformation.apply(data, is_train=True)
    if cache_data:
        transformed_data = Cached(transformed_data)

    # we initialize a Training instance
    instance_splitter = create_instance_splitter(config, "train")

    # the instance splitter will sample a window of
    # context length + lags + prediction length (from the 366 possible transformed time series)
    # randomly from within the target time series and return an iterator.
    stream = Cyclic(transformed_data).stream()
    training_instances = instance_splitter.apply(stream)
    
    return as_stacked_batches(
        training_instances,
        batch_size=batch_size,
        shuffle_buffer_length=shuffle_buffer_length,
        field_names=TRAINING_INPUT_NAMES,
        output_type=torch.tensor,
        num_batches_per_epoch=num_batches_per_epoch,
    )
```

```
    PREDICTION_INPUT_NAMES = [
        "past_time_features",
        "past_values",
        "past_observed_mask",
        "future_time_features",
    ]
    if config.num_static_categorical_features > 0:
        PREDICTION_INPUT_NAMES.append("static_categorical_features")

    if config.num_static_real_features > 0:
        PREDICTION_INPUT_NAMES.append("static_real_features")

    transformation = create_transformation(freq, config)
    transformed_data = transformation.apply(data)

    # we create a Validation Instance splitter which will sample the very last
    # context window seen during training only for the encoder.
    instance_sampler = create_instance_splitter(config, "validation")

    # we apply the transformations in train mode
    testing_instances = instance_sampler.apply(transformed_data, is_train=True)
    
    return as_stacked_batches(
        testing_instances,
        batch_size=batch_size,
        output_type=torch.tensor,
        field_names=PREDICTION_INPUT_NAMES,
    )
```

为了完整我们也放一个测试 dataloader 的辅助函数，尽管这里不会用到。它在生产场景中很有用——当我们要从一条时间序列的末尾开始预测时，测试 dataloader 会从所给数据集中采样最后一个上下文窗口并喂给模型。

```
def create_test_dataloader(
    config: PretrainedConfig,
    freq,
    data,
    batch_size: int,
    **kwargs,
):
    PREDICTION_INPUT_NAMES = [
        "past_time_features",
        "past_values",
        "past_observed_mask",
        "future_time_features",
    ]
    if config.num_static_categorical_features > 0:
        PREDICTION_INPUT_NAMES.append("static_categorical_features")

    if config.num_static_real_features > 0:
        PREDICTION_INPUT_NAMES.append("static_real_features")

    transformation = create_transformation(freq, config)
    transformed_data = transformation.apply(data, is_train=False)

    # We create a test Instance splitter to sample the very last
    # context window from the dataset provided.
    instance_sampler = create_instance_splitter(config, "test")

    # We apply the transformations in test mode
    testing_instances = instance_sampler.apply(transformed_data, is_train=False)
    
    return as_stacked_batches(
        testing_instances,
        batch_size=batch_size,
        output_type=torch.tensor,
        field_names=PREDICTION_INPUT_NAMES,
    )
```

注意模型返回了 loss。这是可能的，因为解码器会自动把 `future_values` 右移一位作为标签，从而可以在预测值与标签之间计算 loss。

另外，解码器使用因果掩码以避免"看到未来"——因为它要预测的值就在 `future_values` 张量里。

## 训练模型

开始训练！我们使用标准 PyTorch 训练循环。

这里使用 🤗 [Accelerate](https://huggingface.co/docs/accelerate/index) 库，它会自动把模型、优化器和 dataloader 放到合适的 `device` 上。

```
from accelerate import Accelerator
from torch.optim import AdamW

accelerator = Accelerator()
device = accelerator.device

model.to(device)
optimizer = AdamW(model.parameters(), lr=6e-4, betas=(0.9, 0.95), weight_decay=1e-1)

model, optimizer, train_dataloader = accelerator.prepare(
    model,
    optimizer,
    train_dataloader,
)

model.train()
for epoch in range(40):
    for idx, batch in enumerate(train_dataloader):
        optimizer.zero_grad()
        outputs = model(
            static_categorical_features=batch["static_categorical_features"].to(device)
            if config.num_static_categorical_features > 0
            else None,
            static_real_features=batch["static_real_features"].to(device)
            if config.num_static_real_features > 0
            else None,
            past_time_features=batch["past_time_features"].to(device),
            past_values=batch["past_values"].to(device),
            future_time_features=batch["future_time_features"].to(device),
            future_values=batch["future_values"].to(device),
            past_observed_mask=batch["past_observed_mask"].to(device),
            future_observed_mask=batch["future_observed_mask"].to(device),
        )
        loss = outputs.loss

        # Backpropagation
        accelerator.backward(loss)
        optimizer.step()

        if idx % 100 == 0:
            print(loss.item())
```

## 推理

推理时，建议使用 `generate()` 方法做自回归生成——与 NLP 模型相同。

预测的过程是：从测试实例采样器获取数据——它会从数据集中每条时间序列采样最后一个 `context_length` 大小的窗口，然后喂给模型。注意我们把提前已知的 `future_time_features` 传给解码器。

模型会从预测的分布中自回归地采样若干值并回填给解码器，从而返回预测输出：

```
model.eval()

forecasts = []

for batch in test_dataloader:
    outputs = model.generate(
        static_categorical_features=batch["static_categorical_features"].to(device)
        if config.num_static_categorical_features > 0
        else None,
        static_real_features=batch["static_real_features"].to(device)
        if config.num_static_real_features > 0
        else None,
        past_time_features=batch["past_time_features"].to(device),
        past_values=batch["past_values"].to(device),
        future_time_features=batch["future_time_features"].to(device),
        past_observed_mask=batch["past_observed_mask"].to(device),
    )
    forecasts.append(outputs.sequences.cpu().numpy())
```

模型输出形状为（`batch_size`、`采样数`、`prediction_length`）的张量。

我们可以针对测试集中样本外真值来评估预测结果。使用 [MASE](https://huggingface.co/spaces/evaluate-metric/mase) 和 [sMAPE](https://huggingface.co/spaces/evaluate-metric/smape) 指标，对数据集中每条时间序列分别计算：

```
    mase = mase_metric.compute(
        predictions=forecast_median[item_id], 
        references=np.array(ground_truth), 
        training=np.array(training_data), 
        periodicity=get_seasonality(freq))
```

```
def plot(ts_index):
    fig, ax = plt.subplots()

    index = pd.period_range(
        start=test_dataset[ts_index][FieldName.START],
        periods=len(test_dataset[ts_index][FieldName.TARGET]),
        freq=freq,
    ).to_timestamp()

    # Major ticks every half year, minor ticks every month,
    ax.xaxis.set_major_locator(mdates.MonthLocator(bymonth=(1, 7)))
    ax.xaxis.set_minor_locator(mdates.MonthLocator())

    ax.plot(
        index[-2*prediction_length:], 
        test_dataset[ts_index]["target"][-2*prediction_length:],
        label="actual",
    )

    plt.plot(
        index[-prediction_length:], 
        np.median(forecasts[ts_index], axis=0),
        label="median",
    )
    
    plt.fill_between(
        index[-prediction_length:],
        forecasts[ts_index].mean(0) - forecasts[ts_index].std(axis=0), 
        forecasts[ts_index].mean(0) + forecasts[ts_index].std(axis=0), 
        alpha=0.3, 
        interpolate=True,
        label="+/- 1-std",
    )
    plt.legend()
    plt.show()
```

## 后续步骤

鼓励读者拿 [notebook](https://colab.research.google.com/github/huggingface/notebooks/blob/main/examples/time-series-transformers.ipynb) 试试 [Hub](https://huggingface.co/datasets/monash_tsf) 上的其他时间序列数据集，只需替换对应的频率和预测长度参数。如果是自己的数据集，需要先转换成 GluonTS 约定的格式，其文档[这里](https://ts.gluon.ai/stable/tutorials/forecasting/extended_tutorial.html#What-is-in-a-dataset?)讲得很清楚。我们也准备了一个示例 notebook，演示如何把数据集转换为 🤗 datasets 格式，见[这里](https://github.com/huggingface/notebooks/blob/main/examples/time_series_datasets.ipynb)。

时间序列研究者都知道，把基于 Transformer 的模型应用于时间序列问题近来热度很高。原始 Transformer 只是众多基于注意力模型中的一种，因此库里还需要加入更多模型。

目前做多变量时间序列建模没有任何障碍，只是需要用多元分布头来实例化模型。当前支持的是对角独立分布，其他多元分布后续会加入。敬请期待带教程的下一篇博客。

路线图上的另一件事是时间序列分类：即在库中加入带分类头的时间序列模型，例如用于异常检测任务。

当前模型假设时间序列值旁边总有 datetime 信息，但现实世界的时间序列未必如此——比如 [WOODS](https://woods-benchmarks.github.io/) 这样的神经科学数据集。因此需要把当前模型泛化，让整个流水线中的部分输入变为可选。

最后，NLP/视觉领域从[大型预训练模型](https://arxiv.org/abs/1810.04805)中受益巨大，而就我们所知，时间序列领域还没有。基于 Transformer 的模型看起来是推进这条研究路线的当然选择——我们迫不及待想看到研究者和实践者能做出什么！
