> 在线评测 PP-OCRv6，然后用 PaddlePaddle、Transformers 或 ONNX Runtime 后端接入轻量的生产级 OCR。

PP-OCRv6 是 PaddleOCR 通用 OCR 模型家族的最新一代。它为真实世界的文本检测与识别而设计，覆盖文档、截图、多语言图像、数字显示屏、工业标签和场景文字。

[![ppocrv6_det_vis](https://cdn-uploads.huggingface.co/production/uploads/652b2e9166313ebb6197e706/BB9bToA0xHZ8Xu5cvBGx0.jpeg)](https://cdn-uploads.huggingface.co/production/uploads/652b2e9166313ebb6197e706/BB9bToA0xHZ8Xu5cvBGx0.jpeg)

模型家族的规模从 **1.5M 到 34.5M 参数**，分为三个档位：**tiny**、**small** 和 **medium**。medium 与 small 档位支持 **50 种语言**，包括简体中文、繁体中文、英文、日文以及 46 种拉丁字母语言。想快速在线体验 PP-OCRv6：[PP-OCRv6 Online Demo](https://huggingface.co/spaces/PaddlePaddle/PP-OCRv6_Online_Demo)。

[![ocrv6_models](https://cdn-uploads.huggingface.co/production/uploads/652b2e9166313ebb6197e706/Rwhy6dk3g8xb6eyVFL9R_.jpeg)](https://cdn-uploads.huggingface.co/production/uploads/652b2e9166313ebb6197e706/Rwhy6dk3g8xb6eyVFL9R_.jpeg)

在 PaddleOCR 官方内部的多场景 OCR 基准上，**PP-OCRv6_medium** 达到 **86.2% 的检测 Hmean** 和 **83.2% 的识别准确率**。相比 PP-OCRv5_server，文本检测提升 **4.6 个百分点**，文本识别提升 **5.1 个百分点**。

[![v6acc_opt](https://cdn-uploads.huggingface.co/production/uploads/652b2e9166313ebb6197e706/xYqS-wDYHDE7cUQQdkcqD.png)](https://cdn-uploads.huggingface.co/production/uploads/652b2e9166313ebb6197e706/xYqS-wDYHDE7cUQQdkcqD.png)

PP-OCRv6 聚焦一个务实的 OCR 需求：用小模型和灵活的部署选项产出准确、结构化的文本输出。想更深入地讨论「在 VLM 时代专门化 OCR 模型为何仍然有用」，参见我们此前的博客：[PP-OCRv5 on Hugging Face: A Specialized Approach to OCR](https://huggingface.co/blog/baidu/ppocrv5)。

## PP-OCRv6 的新内容

PP-OCRv6 在检测与识别两侧都引入了架构、训练和数据的改进。核心设计目标是在保持模型尺寸适配不同部署场景的同时提升 OCR 准确率。

### 三档模型

PP-OCRv6 提供三个档位，覆盖不同的模型大小与 OCR 准确率层级。

| 模型 | 模型大小 | 检测 Hmean | 识别准确率 | 典型应用场景 |
| --- | --- | --- | --- | --- |
| **PP-OCRv6_tiny** | **1.5M 参数** | 80.6% | 73.5% | 边缘设备、轻量本地 OCR、延迟敏感的 demo、资源受限环境 |
| **PP-OCRv6_small** | **7.7M 参数** | 84.1% | 81.3% | 移动、桌面、均衡型 OCR 服务、算力成本更低的多语 OCR |
| **PP-OCRv6_medium** | **34.5M 参数** | **86.2%** | **83.2%** | 准确率优先的 OCR、服务端流水线、工业 OCR、文档摄取、多语 OCR |

### PPLCNetV4 骨干

PP-OCRv6 使用 **PPLCNetV4** 作为文本检测与文本识别的统一骨干。

对开发者而言，主要收益是整个模型家族的一致性。tiny、small、medium 三档并非互不相干的模型；它们同属一个 OCR 家族，共享同一个架构方向。

### 用于文本检测的 RepLKFPN

文本检测是 OCR 流水线的第一阶段。检测质量会影响送进识别器的裁剪图，而差的裁剪往往带来更差的识别。

PP-OCRv6 用 **RepLKFPN** 升级检测模块——一个轻量的大核特征金字塔网络，为多尺度文本检测而设计，同时保持推理高效。

这对真实世界的 OCR 输入很有意义：文本可能细小、密集、旋转、低分辨率，或嵌在复杂背景里。

[![ppocrv6_det_pip_ori](https://cdn-uploads.huggingface.co/production/uploads/652b2e9166313ebb6197e706/Unp8cz-s3c4jSMl71qIFf.png)](https://cdn-uploads.huggingface.co/production/uploads/652b2e9166313ebb6197e706/Unp8cz-s3c4jSMl71qIFf.png)

### 用于识别的 EncoderWithLightSVTR

文本识别侧，PP-OCRv6 使用 **EncoderWithLightSVTR**。它把局部上下文建模与全局注意力结合，提升在困难文本裁剪图上的识别质量。

识别上的改进尤其利好多语言文本、屏幕文字、工业字符、特殊符号、密集文本和噪声图像区域。

[![rec](https://cdn-uploads.huggingface.co/production/uploads/652b2e9166313ebb6197e706/YLhR7a1-BdP62o0o_zZl1.png)](https://cdn-uploads.huggingface.co/production/uploads/652b2e9166313ebb6197e706/YLhR7a1-BdP62o0o_zZl1.png)

### 统一的多语言 OCR

medium 和 small 档位在一个模型家族内支持 **50 种语言**，覆盖简体中文、繁体中文、英文、日文和 46 种拉丁字母语言。

这有助于减少常见多语 OCR 场景下为每种语言各备一个 OCR 模型的需要。

## PaddleOCR 快速上手

安装 PaddleOCR：

```
pip install paddleocr
```

用 Paddle Inference（默认后端）运行 OCR：

```
from paddleocr import PaddleOCR

# Model: PP-OCRv6_medium(Default)
# Backend: Paddle Inference(Default)
ocr = PaddleOCR(
    use_doc_orientation_classify=False,
    use_doc_unwarping=False,
    use_textline_orientation=False,
)
result = ocr.predict("https://paddle-model-ecology.bj.bcebos.com/paddlex/imgs/demo_image/general_ocr_002.png")

for res in result:
    res.print()
    res.save_to_img("output")
    res.save_to_json("output")
```

OCR 结果可以保存为可视化图片和结构化的 JSON 输出。结构化输出随后可供下游系统使用，例如文档解析、搜索、抽取、RAG、分析或 agent 工作流。

## 可用的推理后端

PP-OCRv6 可以通过 PaddleOCR 使用多种推理后端。**PaddleOCR 3.7** 提供了统一的推理引擎接口：由 `engine` 选择底层运行时，相关配置可通过流水线或模块 API 传入。

| **后端** | **说明** |
| --- | --- |
| **Transformers** | 面向 Hugging Face / PyTorch 的推理路径，适用于受支持的 PaddleOCR 模型 |
| **ONNX Runtime** | 面向基于 ONNX 的部署环境的可移植推理路径 |
| **Paddle Inference** | Paddle 原生推理格式 |

对 Hugging Face 用户，PaddleOCR 支持用 Transformers 后端运行选定的 OCR 与文档解析模型。启用方式：

```
engine="transformers"
```

关于 Transformers 后端在 PaddleOCR 中如何工作的更多细节，见：

[PaddleOCR: Running OCR and Document Parsing Tasks with a Transformers Backend](https://huggingface.co/blog/PaddlePaddle/paddleocr-transformers)

用 Transformer 后端运行 PP-OCRv6 的例子：

```
from paddleocr import PaddleOCR

# Model: PP-OCRv6_medium(Default)
# Backend: transformers
ocr = PaddleOCR(
    use_doc_orientation_classify=False,
    use_doc_unwarping=False,
    use_textline_orientation=False,
    engine="transformers",
)
result = ocr.predict("https://paddle-model-ecology.bj.bcebos.com/paddlex/imgs/demo_image/general_ocr_002.png")
```

ONNX 版本也已放入 [PP-OCRv6 Collection](https://huggingface.co/collections/PaddlePaddle/pp-ocrv6)，供通过 `engine="onnxruntime"` 使用 ONNX Runtime 的环境：

```
from paddleocr import PaddleOCR

# Model: PP-OCRv6_medium(Default)
# Backend: ONNX Runtime
ocr = PaddleOCR(
    use_doc_orientation_classify=False,
    use_doc_unwarping=False,
    use_textline_orientation=False,
    engine="onnxruntime",
)
result = ocr.predict("https://paddle-model-ecology.bj.bcebos.com/paddlex/imgs/demo_image/general_ocr_002.png")
```

这些后端选项合在一起，让 PP-OCRv6 能跨不同运行时环境可用，同时在 Hugging Face Hub 上保持同一个 OCR 模型家族。

## 结论

PP-OCRv6 为 PaddleOCR 扩展出一个轻量、多语言的 OCR 模型家族，面向真实世界的文本检测与识别。

本次发布包含三个模型档位（**1.5M 到 34.5M 参数**）、最多 **50 种语言的 OCR 支持**、相对 PP-OCRv5_server 提升的检测与识别准确率，以及 Hugging Face Hub 上的多种模型格式，包括 **safetensors**、**Paddle inference 模型**和 **ONNX 模型**。
