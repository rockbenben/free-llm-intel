## 从 Q-Learning 到深度 Q-Learning

我们学过，**Q-Learning 是一个用来训练 Q 函数的算法**，Q 函数是一个**动作价值函数**，用于确定处于某个状态并采取特定动作的价值。

给定一个状态和一个动作，我们的 Q 函数输出一个 state-action 值（也叫 Q 值）。

**Q 来自「Quality」——该状态下那个动作的「质量」。**

在内部，我们的 Q 函数有一张 **Q 表，表格中每个单元格对应一个 state-action 对的值**。可以把 Q 表看作 Q 函数的**记忆或作弊小抄**。

问题在于 Q-Learning 是一种*表格式方法*（tabular method）。也就是说，问题的状态空间和动作空间**小到足以把价值函数用数组和表格来表示**。而这**不可扩展**。

在小状态空间环境中 Q-Learning 表现得很好，比如：

- FrozenLake，我们有 14 个状态。
- Taxi-v3，我们有 500 个状态。

但想想我们今天要做什么：我们要训练一个智能体，用画面帧作为输入，学会玩 Space Invaders。

正如 **[Nikita Melkozerov 提到的](https://twitter.com/meln1k)，Atari 环境**的观测空间形状为 (210, 160, 3)，取值范围 0 到 255，这就得到 256^(210x160x3) = 256^100800（作为对比，可观测宇宙中的原子数大约只有 10^80）。

因此，状态空间大得离谱，为这种环境创建和更新 Q 表并不可取。这种情况下，最好的办法是用一个带参数的 Q 函数 Qθ(s,a)Q_{\theta}(s,a)Qθ​(s,a) 来近似 Q 值，而不再用 Q 表。

这个神经网络会在给定状态时，近似该状态下每个可能动作的各个 Q 值。这正是深度 Q-Learning 做的事。

既然理解了深度 Q-Learning，我们进一步研究深度 Q 网络。

## 深度 Q 网络（DQN）

这就是我们深度 Q-Learning 网络的架构：

输入是**叠加的 4 帧画面**，作为状态通过网络，输出一个**该状态下每个可能动作的 Q 值向量**。然后，和 Q-Learning 一样，我们只需要用 epsilon-greedy 策略来选择要执行的动作。

神经网络刚初始化时，**Q 值估计非常糟糕**。但在训练过程中，我们的深度 Q 网络智能体会把情境与合适的动作关联起来，**逐渐学会玩好这个游戏**。

### 输入预处理与时间局限

我们提到会**对输入做预处理**。这是很重要的一步，因为我们希望降低状态的复杂度，从而减少训练所需的计算时间。

我们做的具体是**把状态空间缩小到 84x84 并转成灰度图**（因为 Atari 环境里的颜色并不增添重要信息）。这是一项关键的节省——我们**把三个颜色通道（RGB）缩减为 1**。

在某些游戏中，如果屏幕的一部分不含重要信息，我们还可以**裁剪掉那块区域**。然后把四帧叠在一起。

为什么要把四帧叠在一起？因为叠帧能帮我们**处理时间局限（temporal limitation）问题**。举个例子，看看 Pong 游戏。当你看到这一帧：

你能告诉我球往哪飞吗？不能，因为单帧画面不足以感知运动！但如果我再加三帧呢？**这样你就能看出球正朝右边去了**。

所以为了捕捉时间信息，我们要把四帧叠在一起。

随后，叠加的帧由三个卷积层处理。这些层**让我们能捕捉并利用图像中的空间关系**。而且由于帧是叠在一起的，**你还能利用跨帧的某些空间特性**。

最后，我们还有几层全连接层，为该状态下每个可能动作输出一个 Q 值。

所以可以看出，深度 Q-Learning 是用神经网络来近似给定状态时该状态下每个可能动作的各个 Q 值。接下来我们研究深度 Q-Learning 算法。

## 深度 Q-Learning 算法

我们学过，深度 Q-Learning **使用深度神经网络来近似某个状态下每个可能动作的各个 Q 值**（价值函数估计）。

区别在于，在训练阶段，我们不再像 Q-Learning 那样直接更新 state-action 对的 Q 值：

在深度 Q-Learning 中，我们构造一个**损失函数，衡量 Q 值预测与 Q 目标之间的差距，并用梯度下降更新深度 Q 网络的权重，让它更好地近似 Q 值**。

深度 Q-Learning 训练算法分*两个阶段*：

- **采样**：我们执行动作，并**把观察到的经验元组存入回放记忆（replay memory）**。
- **训练**：**随机选择一小批元组，通过一次梯度下降更新从中学习**。

但这并不是与 Q-Learning 的唯一区别。深度 Q-Learning 训练**可能受不稳定之扰**，主要因为非线性 Q 值函数（神经网络）与自举（bootstrapping，即用已有估计而非完整实际回报来更新目标）结合在了一起。

为帮助我们稳定训练，我们实现了三种方案：

- *经验回放（Experience Replay）*，让经验得到更**高效的利用**。
- *固定 Q 目标（Fixed Q-Target）*，用于**稳定训练**。
- *双重深度 Q-Learning（Double Deep Q-Learning）*，用于**处理 Q 值高估问题**。

### 用经验回放更高效地利用经验

为什么要创建回放记忆？

深度 Q-Learning 中的经验回放有两个作用：

- **在训练中更高效地利用经验**。

- 经验回放帮助我们在**训练中更高效地利用经验**。通常在在线强化学习中，我们在环境中交互、获得经验（状态、动作、奖励、下一状态）、从中学习（更新神经网络）然后把它们丢弃。
- 但有了经验回放，我们创建一个回放缓冲区，保存经验样本，**供训练时重复使用**。

⇒ 这让我们能对**单个经验进行多次学习**。

- **避免遗忘过往经验，并降低经验之间的相关性**。

- 如果把按顺序的经验样本喂给神经网络，问题是它往往会在用新经验覆盖旧经验时**遗忘之前的经验**。例如，我们在第一关，然后进入与之不同的第二关，智能体可能忘记在第一关该如何行动和打法。

解决办法是创建一个 Replay Buffer，在与环境交互时存储经验元组，然后采样一小批元组。这可以防止**网络只学习它刚刚做过的事**。

经验回放还有其他好处。通过随机采样经验，我们消除了观测序列中的相关性，避免**动作值剧烈震荡或灾难性发散**。

在深度 Q-Learning 的伪代码里，我们看到我们**初始化一个容量为 N 的回放记忆缓冲区 D**（N 是你可以定义的超参数）。然后我们在记忆中存储经验，并在训练阶段采样一小批经验喂给深度 Q 网络。

### 固定 Q 目标以稳定训练

当我们想计算 TD 误差（即 loss）时，我们计算的是 **TD 目标（Q-Target）与当前 Q 值（Q 的估计）之差**。

但我们**并不知道真正的 TD 目标**，需要估计它。借助贝尔曼方程，我们知道 TD 目标就是"在该状态采取该动作的奖励 + 下一状态最高 Q 值的折扣"。

但问题在于，我们用了**同一套参数（权重）来估计 TD 目标和 Q 值**。于是 TD 目标与我们正在调整的参数之间存在很强的相关性。

这意味着训练的每一步，**我们的 Q 值在变，目标值也在变**。我们在逼近目标，可目标也在移动——就像追一个会动的靶子！这会导致训练大幅震荡。

打个比方：你是一名牛仔（Q 估计），想套住一头牛（Q 目标），你必须靠近它（减小误差）。

每一步你都在试图靠近牛，而牛每一步也在移动（因为你用的是同一套参数）。

于是追赶的路线变得七扭八歪（训练剧烈震荡）。

而伪代码里我们看到的是：

- 用一个**参数独立的固定网络**来估计 TD 目标
- **每经过 C 步，把深度 Q 网络的参数复制过去**，更新目标网络。

### Double DQN

Double DQN（又称 Double Learning）由 [Hado van Hasselt 提出](https://papers.nips.cc/paper/3964-double-q-learning)。这个方法**处理 Q 值高估问题**。

要理解这个问题，回忆一下我们如何计算 TD 目标：

计算 TD 目标时我们面临一个简单的疑问：我们怎么确定**下一状态的最佳动作就是 Q 值最大的那个动作**？

我们知道 Q 值的准确度取决于我们尝试过哪些动作**以及**探索过哪些邻近状态。

因此在训练初期，我们对"该采取的最佳动作"掌握的信息并不充分。于是直接把最大 Q 值（它是带噪声的）当作最佳动作来选择，可能造成误报。如果次优动作**频繁比真正的最优动作拿到更高的 Q 值**，学习就会被带偏。

解决方案是：计算 Q 目标时，用两个网络把「动作选择」和「目标 Q 值生成」解耦。我们：

- 用 **DQN 网络**为下一状态选出最佳动作（Q 值最大的动作）。
- 用**目标网络**计算在该下一状态采取这个动作的目标 Q 值。

因此，Double DQN 帮我们减轻 Q 值高估，随之带来更快的训练和更稳定的学习。

在深度 Q-Learning 的这三项改进之后，人们又加入了很多其他改进，比如优先经验回放（Prioritized Experience Replay）、对抗式深度 Q-Learning（Dueling Deep Q-Learning）。它们超出本课程范围，如果你感兴趣，可以查看阅读列表里的链接。👉 **[https://github.com/huggingface/deep-rl-class/blob/main/unit3/README.md](https://github.com/huggingface/deep-rl-class/blob/main/unit3/README.md)**
