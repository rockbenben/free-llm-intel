# 在 Hugging Face Endpoints 上运行隐私保护推理

> 这是 Zama 团队的 guest 博客。Zama 是一家开源密码学公司，为区块链和 AI 构建最先进的 FHE 方案。

18 个月前，Zama 启动了 [Concrete ML](https://github.com/zama-ai/concrete-ml)——一个隐私保护机器学习框架，与 scikit-learn、ONNX、PyTorch、TensorFlow 等传统 ML 框架都有绑定。为了保护用户数据的隐私，Zama 使用全同态加密（Fully Homomorphic Encryption，FHE）：一种可以直接在加密数据上做计算的密码学工具，计算方永远不需要知道私钥。

从一开始，我们就想把一些 FHE 友好的网络预先编译好、放到互联网某个地方，让用户可以随手就用。今天准备好了！而且不是随便某个地方，而是直接上 Hugging Face。

更具体地说，我们用 Hugging Face [Endpoints](https://huggingface.co/docs/inference-endpoints/en/index) 和[自定义推理 handler](https://huggingface.co/docs/inference-endpoints/en/guides/custom_handler)来存储我们的 Concrete ML 模型，让用户一键部署到 HF 的机器上。读完本篇，你会明白如何使用预编译模型、以及如何准备你自己的模型。本文也可以当作又一篇自定义推理 handler 教程。

## 部署一个预编译模型

先来部署一个 FHE 友好的模型（由 Zama 或第三方准备——如何准备你自己的请看下文「准备你的预编译模型」一节）。

首先找到你要部署的模型：我们在 Zama 的 HF 主页预编译了[一批模型](https://huggingface.co/zama-fhe?#models)（也可以用标签[找到它们](https://huggingface.co/models?other=concrete-ml)）。假设你选了 [concrete-ml-encrypted-decisiontree](https://huggingface.co/zama-fhe/concrete-ml-encrypted-decisiontree)：如描述所说，这个预编译模型能让你在不看明文内容的情况下检测垃圾邮件。

和平台上任何模型一样，选择 *Deploy*，然后 *Inference Endpoint (dedicated)*：

![Inference Endpoint (dedicated)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/fhe-endpoints/inference_endpoint.png) *Inference Endpoint (dedicated)*

接着选 Endpoint 名称、区域，最重要的是选 CPU（Concrete ML 模型目前不用 GPU；我们正在[努力](https://www.zama.ai/post/tfhe-rs-v0-5)）以及合适的机器——下面的例子里我们选了 8 vCPU。现在点 *Create Endpoint*，等初始化完成。

![Create Endpoint](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/fhe-endpoints/create_endpoint.png) *Create Endpoint*

几十秒后 Endpoint 部署完毕，你的隐私保护模型就绪。

![Endpoint is created](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/fhe-endpoints/endpoint_is_created.png) *Endpoint 已创建*

> ：不用时记得删掉 Endpoint（或者至少暂停），否则费用会超出预期。

## 使用 Endpoint

### 安装客户端

目标不只是部署你的 Endpoint，还要让你的用户能玩起来。为此他们需要在自己电脑上克隆仓库：在下拉菜单中选择 *Clone Repository*：

![Clone Repository](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/fhe-endpoints/clone_repository.png) *Clone Repository*

会得到一条小命令行，在终端里执行：

```
git clone https://huggingface.co/zama-fhe/concrete-ml-encrypted-decisiontree
```

执行完进入 `concrete-ml-encrypted-decisiontree` 目录，用编辑器打开 `play_with_endpoint.py`。找到 `API_URL = …` 那一行，替换成上一节创建的 Endpoint 的新 URL。

```
API_URL = "https://vtx9w974oxrq54ff.us-east-1.aws.endpoints.huggingface.cloud"
```

当然，要换成*你自己*的 Entrypoint URL。另外定义一个[访问 token](https://huggingface.co/docs/hub/en/security-tokens)并存进环境变量：

```
export HF_TOKEN=[your token hf_XX..XX]
```

最后，用户机器需要本地安装 Concrete ML：建一个虚拟环境、激活、装好依赖：

```
python3.10 -m venv .venv
source .venv/bin/activate
pip install -U setuptools pip wheel
pip install -r requirements.txt
```

> 注意我们目前强制使用 Python 3.10（也是 Hugging Face Endpoints 的默认 Python 版本）。因为我们的开发文件目前依赖 Python 版本。我们正在做版本无关化，后续版本会支持。

### 适配你的应用或需求

编辑 `play_with_endpoint.py` 会看到我们在测试数据集的不同样本上迭代、直接在 Endpoint 上跑加密推理。

```
for i in range(nb_samples):

    # Quantize the input and encrypt it
    encrypted_inputs = fhemodel_client.quantize_encrypt_serialize(X_test[i].reshape(1, -1))

    # Prepare the payload
    payload = {
        "inputs": "fake",
        "encrypted_inputs": to_json(encrypted_inputs),
        "method": "inference",
        "uid": uid,
    }

    if is_first:
        print(f"Size of the payload: {sys.getsizeof(payload) / 1024:.2f} kilobytes")
        is_first = False

    # Run the inference on HF servers
    duration -= time.time()
    duration_inference = -time.time()
    encrypted_prediction = query(payload)
    duration += time.time()
    duration_inference += time.time()

    encrypted_prediction = from_json(encrypted_prediction)

    # Decrypt the result and dequantize
    prediction_proba = fhemodel_client.deserialize_decrypt_dequantize(encrypted_prediction)[0]
    prediction = np.argmax(prediction_proba)

    if verbose:
        print(
            f"for {i}-th input, {prediction=} with expected {Y_test[i]} in {duration_inference:.3f} seconds"
        )

    # Measure accuracy
    nb_good += Y_test[i] == prediction
```

当然，这只是 Entrypoint 用法的一个示例。鼓励开发者按自己的场景或应用改造这个例子。

### 底层机制

请注意，这一切都得益于[自定义 handler](https://huggingface.co/docs/inference-endpoints/en/guides/custom_handler)的灵活性，感谢 Hugging Face 开发者提供了这样的能力。机制定义在 `handler.py`。正如 HF 文档所说，`EndpointHandler` 的 `__call__` 方法基本可以随意定义：我们的做法是定义一个 `method` 参数，取值 `save_key`（保存 FHE 评估密钥）、`append_key`（密钥太大无法一次发送时分片保存）、以及 `inference`（运行 FHE 推理）。这些方法用于先设置一次评估密钥，然后逐条运行全部推理——正如 `play_with_endpoint.py` 中所示。

### 局限

不过可以注意到，密钥存储在 Endpoint 的 RAM 里，这对生产环境不太友好：每次重启密钥都会丢失、需要重发。而且当你用多台机器应对大流量时，这部分 RAM 在机器之间不共享。最后，可用的 CPU 机器给 Endpoint 最多只提供 8 vCPU，对高负载应用可能是瓶颈。

## 准备你的预编译模型

现在你知道部署预编译模型有多容易了，也许你想准备自己的。为此可以 fork 我们[准备好的仓库之一](https://huggingface.co/zama-fhe?#models)。Concrete ML 支持的每类模型（[线性](https://docs.zama.ai/concrete-ml/built-in-models/linear)、[树模型](https://docs.zama.ai/concrete-ml/built-in-models/tree)、内置 [MLP](https://docs.zama.ai/concrete-ml/built-in-models/neural-networks)、[PyTorch](https://docs.zama.ai/concrete-ml/deep-learning/torch_support)）都至少有一个例子，可以作为新预编译模型的模板。

然后编辑 `creating_models.py`，把 ML 任务改成你想在预编译模型里解决的那个：例如从 [concrete-ml-encrypted-decisiontree](https://huggingface.co/zama-fhe/concrete-ml-encrypted-decisiontree) 起步，改数据集和模型类型。

如前所述，你必须安装 Concrete ML 才能准备预编译模型。注意你可能需要使用与 Hugging Face 默认一致的 Python 版本（写本文时是 3.10），否则别人部署你的模型时可能得用包含你 Python 版本的容器。

现在运行 `python creating_models.py`。它会训练模型，并在 `compiled_model` 目录生成所需的开发文件（`client.zip`、`server.zip`、`versions.json`）。如[文档](https://docs.zama.ai/concrete-ml/deployment/client_server)所述，这些文件就是你的预编译模型。遇到问题可以到 [fhe.org discord](http://discord.fhe.org) 获得支持。

最后一步是修改 `play_with_endpoint.py`，让它处理与 `creating_models.py` 相同的 ML 任务：相应设置数据集。

然后，把这个目录连同 `compiled_model` 目录与文件、以及你对 `creating_models.py` 和 `play_with_endpoint.py` 的修改一起保存到 Hugging Face 的 models 上。当然你还需要跑些测试并做点微调才能工作。别忘了加上 `concrete-ml` 和 `FHE` 标签，这样你的预编译模型能方便地出现在[搜索](https://huggingface.co/models?other=concrete-ml)里。

## 现在可用的预编译模型

目前我们准备了少量预编译模型作为示例，希望社区很快扩展。预编译模型可以用 [concrete-ml](https://huggingface.co/models?other=concrete-ml) 或 [FHE](https://huggingface.co/models?other=FHE) 标签搜到。

| 模型类型 | 数据集 | 在 HF Endpoint 上的执行时间 |
| --- | --- | --- |
| [Logistic Regression](https://huggingface.co/zama-fhe/concrete-ml-encrypted-logreg) | 合成 | 0.4 秒 |
| [DecisionTree](https://huggingface.co/zama-fhe/concrete-ml-encrypted-decisiontree) | Spam | 2.0 秒 |
| [QNN](https://huggingface.co/zama-fhe/concrete-ml-encrypted-qnn) | Iris | 3.7 秒 |
| [CNN](https://huggingface.co/zama-fhe/concrete-ml-encrypted-deeplearning) | MNIST | 24 秒 |

记住，Hugging Face 对 CPU 型 Endpoint 的配置选项有限（目前最多 8 vCPU、16 GB RAM）。视你的生产需求和模型特性，在更强的云实例上执行时间可以更快。希望 Hugging Face Endpoints 很快提供更多强力的机器来改善这些时间。

## 结论与下一步

本文展示了自定义 Endpoint 既简单又强大。我们在 Concrete ML 里做的事情和 ML 从业者的常规工作流相当不同，但自定义 Endpoint 仍然能适配我们大部分需求。为 Hugging Face 工程师开发出如此通用的方案点赞。

我们讲了如何：

- 开发者创建自己的预编译模型，发布到 Hugging Face models。
- 公司部署开发者的预编译模型，通过 HF Endpoints 提供给自己的用户。
- 最终用户用这些 Endpoints 在加密数据上运行他们的 ML 任务。

更进一步，Hugging Face Endpoints 若提供更强大的机器，推理会更快。也可以设想 Concrete ML 与 Hugging Face 界面更深度集成，加一个 *Privacy-Preserving Inference Endpoint* 按钮，让开发者更省心。最后，为了在多服务器部署中集成，若能有办法在机器之间共享状态并保持该状态非易失（FHE 推理密钥存在那里）就更好了。
