# ConTextual 发布：你的多模态模型在文字丰富场景中能多好地联合推理文本与图像？

模型在纯文本理解上已经做得相当出色，但图像中的文本呢？它提供重要的上下文信息——例如导航一张地图，或理解一个表情包（meme）。推理图像中文本与视觉上下文之间交互的能力，可以驱动许多现实应用，如 AI 助手或助视工具。

我们把这类任务称为「上下文敏感的文字丰富视觉推理任务」（context-sensitive text-rich visual reasoning tasks）。

目前，对指令微调的大型多模态模型（LMM）的评测大多聚焦于模型能否回应以问题或祈使句形式提出的图像人类指令（「数一数这个」「列一下那个」等）……但并不考察它们对上下文敏感的文字丰富场景的理解！

因此，我们（来自加州大学洛杉矶分校 UCLA 的研究者）创建了 ConTextual——一个用于评估 LMM 的上下文敏感文字丰富视觉推理数据集。我们还发布了排行榜，让社区能亲眼看到哪些模型在这项任务上最强。

想深入了解，还可以查看这些额外资源：[论文](https://arxiv.org/abs/2401.13311)、[代码](https://github.com/rohan598/ConTextual)、[数据集](https://huggingface.co/datasets/ucla-contextual/contextual_all)、[验证数据集](https://huggingface.co/datasets/ucla-contextual/contextual_val)以及[排行榜](https://huggingface.co/spaces/ucla-contextual/contextual_leaderboard)。

## ConTextual 是什么

ConTextual 是一个上下文敏感的文字丰富视觉推理数据集，由 506 条面向 LMM 评估的高难度指令组成。我们在文字丰富的图像上创建了指令的多样集合，并约束它们必须对图像中的文本与视觉线索进行上下文敏感的联合推理。

它覆盖 8 类真实世界视觉场景——时间读取、购物、导航、抽象场景、移动应用、网页、信息图和各类自然场景。（每个子集的样例见配图）。

[![Real world visual scenarios examples](https://con-textual.github.io/static/images/teaser_figure.png)](https://con-textual.github.io/static/images/teaser_figure.png)

每个样本包含：

- 一张文字丰富的图像
- 一条人类撰写的指令（问题或祈使句任务）
- 一条人类撰写的参考回答

数据集以两种形式发布：

- (a) 验证集：从完整数据集中抽取的 100 个实例，含指令、图像和指令的参考答案。
- (b) 测试集：只含指令和图像。

排行榜同时收录模型在验证集和测试集上的结果（论文中也有这些信息）。开发集让从业者可以轻松测试并迭代自己的方法。评估沙箱在我们的 github 上。

## 实验

在初步实验中，我们的基准评估了 13 个模型的性能。我们把它们分为三类：

- **增强 LLM 方案**：GPT4 + 以图像 OCR 和/或稠密图像描述形式提供的视觉信息；
- **闭源 LMM**：GPT4V(ision) 和 Gemini-Vision-Pro；
- **开源 LMM**：LLaVA-v1.5-13B、ShareGPT4V-7B、Instruct-Blip-Vicuna-7B、mPlugOwl-v2-7B、Bliva-Vicuna-7B、Qwen-VL-7B 和 Idefics-9B。

我们的数据集为每条指令包含一条参考回答，让我们能测试各种自动评估方法。评估采用 LLM-as-a-judge 方案：把指令、参考回答和模型预测的回答喂给 GPT-4，由它判断预测回答是否可接受。（选择 GPT4 是因为在我们的实验中它与人类判断的相关性最高。）

来看几个例子！

[Example 1](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/leaderboards-on-the-hub/contextual-qualitative-ex-1.png) 在这个实例中，GPT-4V 尽管给出了看似合乎逻辑的推理，仍对该指令提供了错误回答。绿色表示与参考答案一致的部分，红色标出回答中的错误。此外还给出 Summarized Reasoning（推理摘要），概述 GPT-4V 得出答案所依据的理由。

[Example 2](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/leaderboards-on-the-hub/contextual-qualitative-ex-2.png) 在这个例子中，GPT-4V 正确回答了指令。然而 ShareGPT-4V-7B（表现最好的开源 LMM）和 GPT-4 w/ Layout-aware OCR + Caption（增强 LLM）给出了错误回答，原因是缺乏对文本与图像的联合推理。

更多此类例子见我们[论文](https://arxiv.org/abs/2401.13311)的附录部分！

## 关键结论！

在研究过程中我们发现：

- 现代 LMM（专有模型和开源模型）在 ConTextual 数据集上表现挣扎，而人类做得很好。这提示模型在文字丰富图像上的推理还有很大提升空间——这是一个具有重大现实应用的领域。
- 专有 LMM 在涉及时间读取的信息图推理上表现欠佳，说明与人类相比存在能力缺口。值得注意的是，表现最好的 GPT-4V 在抽象推理上超过人类（可能得益于接触过 meme 和引言数据），但在人类擅长的时间相关任务上却力不从心。
- 对于 LLaVA-1.5-13B 和 ShareGPT-4V-7B 等开源模型，它们能达到可接受人类评分的领域（抽象场景与自然场景）和其余领域（时间读取、信息图、导航、购物、网页和移动使用）之间存在明显落差。因此我们样本覆盖的许多领域很可能对这些模型是分布外数据。开源模型应当在训练数据中增加多样性。
- 给 LMM 配一个大语言模型做增强——把视觉信息经 OCR 或描述转成文本再输入——表现相当差，人类认可率仅 17.2%。我们的样本需要精确视觉感知与细粒度、微妙的视觉-语言对齐相结合才能解决。

我们的分析表明，下一步的可行方向包括：

- 开发更强的图像编码器，
- 创建高度精确的图像描述，
- 促进细粒度的视觉-语言对齐，以改善模型感知、减少幻觉的发生。

这些终将带来更有效的、上下文敏感的文字丰富视觉推理。

## 如何提交？

我们同时接受测试集和验证集的提交。请按相应流程操作。

### 验证集提交

要向排行榜提交验证结果，你可以按照[这些说明](https://github.com/rohan598/ConTextual?tab=readme-ov-file#-evaluation-pipeline-gpt-4)运行我们的自动评估代码（Evaluation Pipeline with GPT4）。

提交应为如下 json 格式：

```
{"model_name": {"img_url": "The boolean score of your model on the image, 1 for success and 0 for failure"}}
```

- 用你的模型名替换 model name（字符串）
- 用实例的 img_url 替换 img_url（字符串）
- 每个 img url 的值是 0 或 1（整数）

应有 100 条预测，对应验证集的 100 个 url。

提交时请前往托管在 HuggingFace 的[排行榜](https://huggingface.co/spaces/ucla-contextual/contextual_leaderboard)，填写 Submission 表单。

### 测试集提交

当你对验证结果满意后，可以把模型预测发送给 [Rohan](https://huggingface.co/blog/rwadhawan7@g.ucla.edu) 和 [Hritik](https://huggingface.co/blog/hbansal@g.ucla.edu)。

邮件请包含：

- 你的模型名称。
- 所属组织（affiliation）。
- （可选）GitHub 仓库或论文链接。

提交应为与验证集类似的 json 格式：

```
{"model_name": {"img_url": "predicted response"}}
```

- 用你的模型名替换 model name（字符串）
- 用实例的 img_url 替换 img_url（字符串）
- 每个 img url 的值是该实例的预测回答（字符串）

应有 506 条预测，对应测试集的 506 个 url。
