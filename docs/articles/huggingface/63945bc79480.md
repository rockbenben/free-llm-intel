[CWE-bench](https://cwe-bench.com/) 的设计目的是试探前沿网络能力（cyber capabilities）的边界。在 [Collinear AI](https://collinear.ai/) 持续推动这条边界的努力中，CWE-bench v2 公开了[一组 100 道任务](https://huggingface.co/datasets/collinear-ai/cwe-bench)，任何人都可以拿它们来跑、来评估自己的模型。设置和之前一样：一个 agent 拿到一份真实开源仓库的 checkout 和一段简短的指令，目标是找出并修复一处安全弱点，同时不破坏已有功能。打分完全程序化，所以结果是确定性的，任何人都可以零额外成本地复现。我们所有的程序化检查都在 LLM 评审团的帮助下做了筛选，把它们朝更难、更公道的方向打磨。我们还维护着一个[留出集](https://www.cwebench.com)，以便在没有任何模型见过的任务上持续跟踪进展。要在留出集上评估你的模型，请联系 [cyber@collinear.ai](mailto:cyber@collinear.ai)。

我们的目标是不留死角。防守方必须预判攻击方可能进来的每一条路径，而且每一次都得判断对。这 100 道任务覆盖 91 个不同的 CWE，横跨一大片漏洞类别。在这里表现好的模型，必须理解潜在攻击者可以利用的多重弱点面。认出一个熟悉的模式还不够。

作为我们持续改进质量的细致工作的一部分，对每一道任务我们都核查了下面这些问题是否成立：

- 这段指令读起来像一条真实的指令，而不是一处评测设置吗？
- 每一个被计分的行为都能从指令里推断出来吗？
- 验证器检查的是行为正确，而不是某一种修复的特定结构吗？
- 起始代码会失败、参考修复会通过吗？
- 加上新的修复之后，原有功能仍然工作吗？
- 验证器会拦住背下来的解法，比如已知的上游补丁吗？

每一道任务也都经过人工复核。把这组任务开源，是同一条改进质量的努力的一部分。欢迎对任何任务给出反馈，也欢迎为公开任务集做贡献。

## 结果

结果在 Hub 上的两个地方跟踪。[CWE-bench 数据集页面上的排行榜](https://huggingface.co/datasets/collinear-ai/cwe-bench)覆盖开放权重的模型，并自行更新：各家实验室和社区通过在模型仓库上提一个 PR、附一份结果文件来添加一条结果（[怎么做](https://huggingface.co/docs/hub/eval-results#adding-evaluation-results)）。要看完整对比，包括 Gemini、Claude 和 GPT 这些仅提供 API 的模型，请看 [CWE-bench 排行榜 Space](https://huggingface.co/spaces/collinear-ai/cwe-bench-leaderboard)，新模型通过在该 Space 上提 PR 加入。

## 直接从 Hub 上跑

每一道任务都是一个自包含的 [Harbor](https://harborframework.com/) 任务（一个 Docker 化的环境、一段指令，以及一个确定性的验证器），数据集里随附一份 `registry.json`。因此 Harbor 可以直接从 Hugging Face 仓库跑起整个基准，你不必自己克隆任何东西：

```
harbor run --repo "https://huggingface.co/datasets/collinear-ai/cwe-bench" -d cwe-bench@2.0 -k 4 \
  --agent <agent> --model <model> --env docker \
  --allow-agent-host <model API host>
```

`-k 4` 表示每道任务跑 4 次尝试，报告的分数是全部 400 次试验的平均奖励。这个数据集是受限的：先在[数据集页面](https://huggingface.co/datasets/collinear-ai/cwe-bench)接受它的访问条件。Harbor 用 git 拉取任务，所以还要一次性把你的 HF token 存进 git 的凭据助手：

```
hf auth login --token $HF_TOKEN --add-to-git-credential
```

这些任务同时打了 `rl-environment` 标签：同样的环境和验证器不只能为评估防御型 agent 提供判定，也能为训练它们提供奖励。
