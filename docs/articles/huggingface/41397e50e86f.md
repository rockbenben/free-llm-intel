我们在 Unsloth 的朋友昨天[分享了一个问题](https://unsloth.ai/blog/gradient)，涉及影响 transformers Trainer 的梯度累积。最初的报告来自 @bnjmn_marie（向他致谢！）。

梯度累积*本应*在数学上等价于全 batch 训练；然而，在该设置开启与关闭的训练运行之间，损失值并不匹配。

## 问题出在哪？

在每个模型的 modeling 代码内部，`transformers` 提供一个「默认」损失函数，即该任务最常用的损失。它由 modeling 类的用途决定：问答、token 分类、因果 LM、掩码 LM。

这是默认损失函数，本来并不打算可定制：只有当 `labels` 和 `input_ids` 作为输入传给模型时才会计算它，以便用户不必自己算损失。默认损失有用，但**设计上**就是受限的：任何不同的做法，我们都期望用户**不要直接传入 labels，而是从模型取回 logits，在模型之外用它们计算损失。**

然而，transformers Trainer 以及许多 Trainer 大量使用这些方法，正是因为它带来的简单——这是把双刃剑。提供一个会因用例不同而行为不同的「简单 API」，并不是一个经过深思熟虑的 API，连我们自己也被打了个措手不及。

准确地说，在因果 LM 训练这类 token 级任务的梯度累积中，正确的损失应该用梯度累积步骤内所有 batch 的损失总和，除以这些 batch 中所有非 padding token 的总数来计算。这不等于对各 batch 损失值取平均。修复相当简单，见下：

```
def ForCausalLMLoss(logits, labels, vocab_size, **kwargs):
    # Upcast to float if we need to compute the loss to avoid potential precision issues
    logits = logits.float()
    # Shift so that tokens < n predict n
    shift_logits = logits[..., :-1, :].contiguous()
    shift_labels = labels[..., 1:].contiguous()

    # Flatten the tokens
    shift_logits = shift_logits.view(-1, vocab_size)
    shift_labels = shift_labels.view(-1)
    # Enable model parallelism
    shift_labels = shift_labels.to(shift_logits.device)

    num_items = kwargs.pop("num_items", None)
+        loss = nn.functional.cross_entropy(shift_logits, shift_labels, ignore_index=-100, reduction="sum")
+        loss = loss / num_items
-        loss = nn.functional.cross_entropy(shift_logits, shift_labels, ignore_index=-100)
```

## 我们如何修复

为了解决这个问题，我们要以两种方式改变模型与训练的工作方式：

- 如果用户使用「默认」损失函数，我们在使用梯度累积时会自动考虑所需的修正，确保报告和使用正确的损失，从根源上修复问题。
- 为确保未来计算损失的任何问题不再阻塞用户，我们将开放一个 API，让用户把自己的损失函数直接传给 `Trainer`，这样在我们内部修复并发布新版 transformers 之前，他们可以便捷地自行修复。

所有继承自 `PreTrainedModel` 的模型现在都有一个 `loss_function` 属性，由以下之一决定：

- `config.loss_type`：这是为了确保任何人都能使用自己的自定义损失。你可以通过修改 `LOSS_MAPPING` 做到：

```
def my_super_loss(logits, labels):
    return loss = nn.functional.cross_entropy(logits, labels, ignore_index=-100)

LOSS_MAPPING["my_loss_type"] = my_super_loss
```

我们正在通过此 PR 把第一项改动率先上线到最流行的模型：[https://github.com/huggingface/transformers/pull/34191#pullrequestreview-2372725010](https://github.com/huggingface/transformers/pull/34191#pullrequestreview-2372725010)。此后，我们将发起贡献征集，帮助把该改动推广到其余模型，使大多数模型在下一个发布版本中得到支持。

我们也在积极通过此 PR 推进第二项改动：[https://github.com/huggingface/transformers/pull/34198](https://github.com/huggingface/transformers/pull/34198)。它将允许用户使用自己的损失函数，并利用每个 batch 的样本数来帮助计算损失（随着更多模型通过前述改动获得支持，它也会在梯度累积期间执行正确的损失计算）
