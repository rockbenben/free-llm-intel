# 欢迎 Falcon Mamba：首个强大的无注意力 7B 模型

本文由来自 TII（Technology Innovation Institute）的 Jingwei Zuo、Maksim Velikanov、Rhaiem DhiyaEddine、Ilyas Chahed、Younes B、Guillaume Kunsch 等撰写。

[Falcon Mamba](https://falconllm.tii.ae/tii-releases-first-sslm-with-falcon-mamba-7b.html) 是阿布扎比[技术创新研究所（TII）](https://www.tii.ae/ai-and-digital-science)发布的新型号，采用 [TII Falcon Mamba 7B License 1.0](https://falconllm.tii.ae/falcon-mamba-7b-terms-and-conditions.html) 许可。该模型开放可获取，并在 Hugging Face 生态中[此处](https://huggingface.co/tiiuae/falcon-mamba-7b)供任何人用于研究或应用目的。

在这篇博客中，我们将介绍该模型背后的设计决策、它相对其他现有 SoTA 模型的竞争力，以及如何在 Hugging Face 生态中使用它。

## 首个通用目的的大规模纯 Mamba 模型

基于注意力机制的 Transformer 是当今所有最强大型语言模型使用的主导架构。然而，注意力机制在处理长序列方面存在根本性局限——计算与内存成本随序列长度增长。各种替代架构，特别是状态空间语言模型（SSLM），试图解决序列扩展的局限，但相比 SoTA transformer 性能又落入下风。

借助 Falcon Mamba，我们证明了序列扩展的局限确实可以被克服而性能不受损失。Falcon Mamba 基于原始的 Mamba 架构（提出于 [*Mamba: Linear-Time Sequence Modeling with Selective State Spaces*](https://arxiv.org/abs/2312.00752)），并额外加入了 RMS 归一化层以保证大规模训练的稳定性。这一架构选择确保 Falcon Mamba：

- 能够处理任意长度的序列而内存占用不增加，尤其能放进单张 A10 24GB GPU。
- 生成新 token 的时间是恒定的，与上下文大小无关（见本[节](https://huggingface.co/blog/falconmamba#hardware-performance)）。

## 模型训练

Falcon Mamba 使用约 5500 亿（5500G）token 的数据训练，主要由 RefinedWeb 数据加上来自公开来源的高质量技术数据和代码数据构成。大部分训练过程使用恒定学习率，随后是一个相对较短的学习率衰减阶段。在最后这个阶段，我们还加入了一小部分高质量精选数据，以进一步提升模型性能。

## 处理长序列

沿着 SSM 模型处理长序列的理论高效路线，我们使用 [optimum-benchmark](https://github.com/huggingface/optimum-benchmark) 库，对 Falcon Mamba 与流行 transformer 模型的内存占用和生成吞吐量进行了比较。为了公平比较，我们把所有 transformer 模型的词表大小重新调整为与 Falcon Mamba 一致，因为它对模型的内存需求影响很大。

在看结果之前，先讨论序列的提示部分（prompt/prefill）与生成部分（decode）的区别。我们会看到，prefill 的细节对状态空间模型比对 transformer 模型更重要。当 transformer 生成下一个 token 时，它需要对上下文中所有先前 token 的 keys 和 values 做注意力。这意味着内存需求和生成时间都随上下文长度线性增长。而状态空间模型只关注并存储其递归状态（recurrent state），因此不需要额外内存或时间来生成长序列。这解释了 SSM 相对 transformer 在 decode 阶段声称的优势，但 prefill 阶段需要额外努力才能充分利用 SSM 架构。

prefill 的标准做法是并行处理整个 prompt 以充分利用 GPU。这种做法被 [optimum-benchmark](https://github.com/huggingface/optimum-benchmark) 库使用，我们称之为并行 prefill（parallel prefill）。并行 prefill 需要在内存中存储 prompt 中每个 token 的隐藏状态。对 transformer 而言，这部分额外内存主要由存储的 KV cache 内存主导。对 SSM 模型而言，不需要任何缓存，存储隐藏状态的内存成为唯一与 prompt 长度成正比的成分。结果是内存需求将随 prompt 长度增长，SSM 模型将失去处理任意长序列的能力，变得与 transformer 类似。

并行 prefill 的替代方案是逐 token 处理 prompt，我们称之为*顺序 prefill（sequential prefill）*。类似于序列并行，它也可以在更大的 prompt 分块而非单个 token 上进行，以提高 GPU 利用率。虽然顺序 prefill 对 transformer 意义不大，但它让 SSM 模型重新具备了处理任意长 prompt 的可能性。

带着以上认识，我们首先测试单张 24GB A10 GPU 能容纳的最大序列长度，结果见下方[图](https://huggingface.co/blog/falconmamba#max-length)。batch size 固定为 1，使用 float32 精度。即使是并行 prefill，Falcon Mamba 也能容纳比 transformer 更长的序列；而在顺序 prefill 下，它释放全部潜力，可以处理任意长的 prompt。

[![Model Performance](https://huggingface.co/datasets/tiiuae/documentation-images/resolve/main/falcon_mamba/max_len_llalma3-1.png)](https://huggingface.co/datasets/tiiuae/documentation-images/resolve/main/falcon_mamba/max_len_llalma3-1.png)

接下来，我们在长度为 1 的 prompt 加上最多 13 万个生成 token 的设定下测量生成吞吐量，使用 batch size 1 与 H100 GPU。结果见下方[图](https://huggingface.co/blog/falconmamba#throughput)。我们观察到 Falcon Mamba 以恒定吞吐生成所有 token，且 CUDA 峰值内存无任何增长。而 transformer 模型的峰值内存随生成 token 数增长，生成速度不断变慢。

## 如何在 Hugging Face transformers 中使用？

Falcon Mamba 架构将在 Hugging Face transformers 库的下个版本（>4.45.0）中提供。要使用该模型，请确保安装最新版 Hugging Face transformers，或从源码安装。

Falcon Mamba 兼容你熟悉的绝大多数 Hugging Face API，例如 `AutoModelForCausalLM` 与 `pipeline`：

```
from transformers import AutoModelForCausalLM, AutoTokenizer 

model_id = "tiiuae/falcon-mamba-7b" 
tokenizer = AutoTokenizer.from_pretrained(model_id) 

model = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype="auto", device_map="auto") 
inputs = tokenizer("Hello world, today", return_tensors="pt").to(0) 

output = model.generate(**inputs, max_new_tokens=100, do_sample=True) 
print(tokenizer.decode(Output[0], skip_special_tokens=True)) 
```

由于模型较大，它也支持 `bitsandbytes` 量化等特性，以便在更小 GPU 内存约束下运行模型，例如：

```
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig 

model_id = "tiiuae/falcon-mamba-7b" 
tokenizer = AutoTokenizer.from_pretrained(model_id) 

quantization_config = BitsAndBytesConfig(load_in_4bit=True) 
model = AutoModelForCausalLM.from_pretrained(model_id, quantization_config=quantization_config) 

inputs = tokenizer("Hello world, today", return_tensors="pt").to(0) 
output = model.generate(**inputs, max_new_tokens=100, do_sample=True) 

print(tokenizer.decode(output[0], skip_special_tokens=True)) 
```

我们也很高兴地推出 Falcon Mamba 的指令微调版本，它用额外的 50 亿 token 的监督微调（SFT）数据做了微调。这段延长训练增强了模型以更高精度和有效性执行指令任务的能力。你可以通过我们的演示体验 instruct 模型的能力，见[这里](https://huggingface.co/spaces/tiiuae/falcon-mamba-playground)。聊天模板我们使用如下格式：

```
<|im_start|>user
prompt<|im_end|>
<|im_start|>assistant
```

你也可以直接使用 [base 模型](https://huggingface.co/tiiuae/falcon-mamba-7b-4bit)和 [instruct 模型](https://huggingface.co/tiiuae/falcon-mamba-7b-instruct-4bit)转换好的 4-bit 版本。请确保你拥有兼容 `bitsandbytes` 库的 GPU 来运行量化模型。

你还可以借助 `torch.compile` 获得更快的推理：只需在加载完模型后调用一次 `model = torch.compile(model)`。
