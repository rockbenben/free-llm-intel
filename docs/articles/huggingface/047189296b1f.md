# 开放评估标准：用 NeMo Evaluator 为 NVIDIA Nemotron 3 Nano 做基准测试

要判断一个模型报告的改进是真实进步，还是评估条件、数据集构成或"照着基准题训练"带来的差异，正变得越来越难。NVIDIA Nemotron 的开放路线应对之道，是发布透明、可复现的评估配方（evaluation recipe），让结果可被独立验证。

NVIDIA 发布 [Nemotron 3 Nano 30B A3B](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16) 时采用明确公开的评估方式，把这一区分讲清楚。与模型卡一同发布的，还有生成这些结果所用的完整评估配方——基于 [NVIDIA NeMo Evaluator](https://github.com/NVIDIA-NeMo/Evaluator/) 库构建——任何人都可以重跑评估流水线、检查产物、独立分析结果。

我们相信开放创新是 AI 进步的基石。这种程度的透明之所以重要，是因为多数模型评估都遗漏了关键细节：配置、提示词、评估框架版本、运行时设置和日志常常缺失或语焉不详，而这些参数的细微差别就可能实质性地改变结果。没有完整配方，几乎无法分辨一个模型是真的更聪明，还是只是为某个基准做了优化。

本篇博客向开发者完整展示如何用全开放的工具、配置和产物复现 [Nemotron 3 Nano 30B A3B](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16) 背后的评估。你将了解评估是如何运行的、方法论为何重要，以及如何用 NeMo Evaluator 库执行同样的端到端工作流——从而验证结果、公平对比模型，并搭建你自己的透明评估流水线。

## 用 NeMo Evaluator 构建一致、透明的评估工作流

### 单一、一致的系统

开发者和研究人员需要可以依赖的评估工作流，而不是面对不同模型行为各异的一次性脚本。NeMo Evaluator 提供统一的方式来一次性定义基准、提示词、配置和运行时行为，再把这套方法论复用到不同模型和各次发布上。这避免了常见的局面：评估设置在各次运行之间悄悄变化，让跨时间的对比困难甚至误导。

### 方法论独立于推理设置

模型输出会因推理后端和配置而异，所以评估工具不应绑定某个单一推理方案——把评估工具锁死在一个推理方案上会限制它的用处。NeMo Evaluator 通过将评估流水线与推理后端分离来规避这一点：同一份配置可以对着托管端点、本地部署或第三方供应商运行。即使你更换基础设施或推理引擎，这种分离也能支撑有意义的对比。

### 为超越一次性实验而设计

许多评估流水线跑得通一次，随着范围扩大就崩溃了。NeMo Evaluator 的设计能从快速的单基准验证扩展到完整的模型卡套件、跨多个模型的重复评估。启动器、产物布局和配置模型都支持持续工作流而非孤立实验，让团队能长期保持一致的评估实践。

### 靠结构化产物与日志实现可审计

透明的评估不只是最终分数。每次评估运行默认产出结构化结果和日志，方便检查分数如何计算、理解打分过程、调试意外行为、做更深入的分析。评估的每个环节都被记录、可复现。

### 共享的评估标准

通过发布 [Nemotron 3 Nano 30B A3B](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16) 及其[完整评估配方](https://github.com/NVIDIA-NeMo/Evaluator/blob/main/packages/nemo-evaluator-launcher/examples/nemotron/nano-v3-reproducibility.md)，NVIDIA 提供了一套社区可以运行、检查并在其上继续建设的方法论参考。使用相同的配置和工具，让基准的选择、执行和解读保持一致，跨模型、跨供应商、跨发布的对比也因此更可靠。

## Nemotron 3 Nano 的开放评估

开放评估意味着不仅发布最终结果，还发布结果背后的完整方法论——这样基准以一致方式运行，结果才能随时间做有意义的比较。对 [Nemotron 3 Nano 30B A3B](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16)，这包括开源工具、透明配置，以及任何人都能端到端运行的可复现产物。

### 开源模型评估工具

[NeMo Evaluator](https://github.com/NVIDIA-NeMo/Evaluator/tree/main) 是一个开源库，面向生成式模型的健壮、可复现、可扩展评估。它不是再造一个独立的基准运行器，而是充当统一的编排层，把多个评估框架（harness）收拢到单一一致的接口之下。

在这一架构下，NeMo Evaluator 集成并协调来自众多常用评估框架的数百个基准，包括用于 Nemotron 指令遵循、工具使用与智能体评估的 [NeMo Skills](https://catalog.ngc.nvidia.com/orgs/nvidia/teams/eval-factory/containers/nemo_skills?version=25.11)，以及用于基座模型与预训练基准的 [LM Evaluation Harness](https://catalog.ngc.nvidia.com/orgs/nvidia/teams/eval-factory/containers/lm-evaluation-harness?version=latest) 等等（[完整基准目录](https://docs.nvidia.com/nemo/evaluator/latest/evaluation/benchmarks.html)）。每个框架保留自己原生的逻辑、数据集和打分语义，而 NeMo Evaluator 统一它们的配置、执行和日志方式。

这带来两个实际好处：团队用一份配置就能运行多样的基准类别，不必重写定制评估脚本；不同框架的结果以一致、可预测的方式存储和检视，即使底层任务不同。NVIDIA 的 Nemotron 研究与模型评估团队内部使用的这套编排框架，如今向社区开放，让开发者通过共享、可审计的工作流运行异构、多框架评估。

### 开放的配置

我们发布了用于 [Nemotron 3 Nano 30B A3B 模型卡](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16)评估的 NeMo Evaluator 精确 YAML 配置，包括：

- 模型推理与部署设置
- 基准与任务选择
- 基准特定参数，如采样、重复次数和提示词模板
- 运行控制，如并行度、超时与重试
- 输出路径与产物布局

用同一份配置，就是运行同一套评估方法论。

### 开放的日志与产物

每次评估运行都产出结构化、可检视的输出：逐任务的 `results.json` 文件、用于调试和审计的执行日志、按任务组织便于对比的产物。这种结构让你不仅能看懂最终分数，还能看懂分数如何产生，并对模型行为做更深入的分析。

## 复现工作流

复现 [Nemotron 3 Nano 30B A3B 模型卡](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16)的结果遵循一个简单的循环：

- 从已发布的模型 checkpoint 或托管端点出发

同样的工作流适用于你用 NeMo Evaluator 评估的任何模型。评估可以指向托管端点或本地部署，包括 [HuggingFace](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16)、[build.nvidia.com](https://build.nvidia.com/nvidia/nemotron-3-nano-30b-a3b)、[OpenRouter](https://openrouter.ai/chat?room=orc-1765809021-Ky770f22xVCIJI6lqlJJ) 等常见推理供应商。关键要求是访问模型——要么是能自行服务（serve）的权重，要么是可以调用的端点。本教程使用 [build.nvidia.com](https://build.nvidia.com/nvidia/nemotron-3-nano-30b-a3b) 上的托管端点。

### 1. 安装 NeMo Evaluator Launcher

`pip install nemo-evaluator-launcher`

### 2. 设置所需环境变量

```
# NVIDIA endpoint access
export NGC_API_KEY="your-ngc-api-key"

# Hugging Face access
export HF_TOKEN="your-huggingface-token"

# Required only for judge-based benchmarks such as HLE
export JUDGE_API_KEY="your-judge-api-key"
```

*可选但建议，便于更快重跑：* `export HF_HOME="/path/to/your/huggingface/cache"`

### 3. 模型端点

评估使用 [build.nvidia.com](https://build.nvidia.com/nvidia/nemotron-3-nano-30b-a3b) 上托管的 NVIDIA API 端点：

```
target:
  api_endpoint:
    model_id: nvidia/nemotron-nano-3-30b-a3b
    url: https://integrate.api.nvidia.com/v1/chat/completions
    api_key_name: NGC_API_KEY
```

评估可以对着 [HuggingFace](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16)、[build.nvidia.com](https://build.nvidia.com/nvidia/nemotron-3-nano-30b-a3b) 或 [OpenRouter](https://openrouter.ai/chat?room=orc-1765809021-Ky770f22xVCIJI6lqlJJ) 等常见推理供应商运行，或任何该模型有可用端点的地方。

如果你本地托管模型或使用不同端点：

```
nemo-evaluator-launcher run \
  --config local_nvidia_nemotron_3_nano_30b_a3b.yaml \
  -o target.api_endpoint.url=http://localhost:8000/v1/chat/completions
```

### 4. 运行完整评估套件

先用 `--dry-run` 预览而不实际执行：

```
nemo-evaluator-launcher run \
  --config local_nvidia_nemotron_3_nano_30b_a3b.yaml \
  --dry-run
```

在 examples 目录下，使用提供的 YAML 配置运行评估：

```
nemo-evaluator-launcher run \
  --config /path/to/examples/nemotron/local_nvidia_nemotron_3_nano_30b_a3b.yaml
```

注意，快速测试时可以用 `limit_samples` 限制样本数：

```
nemo-evaluator-launcher run \
  --config local_nvidia_nemotron_3_nano_30b_a3b.yaml \
  -o evaluation.nemo_evaluator_config.config.params.limit_samples=10
```

### 5. 运行单个基准

可以用 `-t` 标志运行特定基准（在 examples/nemotron 目录下）：

```
# Run only MMLU-Pro
nemo-evaluator-launcher run --config local_nvidia_nemotron_3_nano_30b_a3b.yaml -t ns_mmlu_pro

# Run only coding benchmarks
nemo-evaluator-launcher run --config local_nvidia_nemotron_3_nano_30b_a3b.yaml -t ns_livecodebench

# Run multiple specific benchmarks
nemo-evaluator-launcher run --config local_nvidia_nemotron_3_nano_30b_a3b.yaml -t ns_gpqa -t ns_aime2025
```

### 6. 监控执行并检查结果

```
# Check status of a specific job
nemo-evaluator-launcher status
```

```
# Stream logs for a specific job
nemo-evaluator-launcher logs <job-id>
```

结果写入定义的输出目录：

## 解读结果

复现评估时，你可能观察到最终分数在运行之间有细微差异。这种波动反映的是 LLM 的概率本性，而非评估流水线的问题。现代评估存在多个不确定性来源：解码设置、重复试验、评审模型打分、并行执行，以及服务基础设施的差异，都可能造成轻微波动。

开放评估的目的不是追求逐位一致的输出，而是交付**方法论一致性**以及评估结果的清晰出处。为确保你的评估与参考标准对齐，请核查：

- **配置**：不做修改地使用已发布的 NeMo Evaluator YAML，或显式记录任何改动
- **基准选择**：运行预期的任务、任务版本和提示词模板
- **推理目标**：确认评估的是预期的模型与端点，包括相关时的 chat template 行为和推理设置
- **执行设置**：保持运行参数一致，包括重复次数、并行度、超时和重试行为
- **输出**：确认产物和日志完整，并符合每个任务的预期结构

这些要素一致时，你的结果就是方法论的有效复现，即使单次运行略有出入。NeMo Evaluator 把这个过程简化了：它把基准定义、提示词、运行时设置和推理配置捆成一个可审计的工作流，尽量减少不一致。

## 总结：开放模型更透明的标准

随 Nemotron 3 Nano 发布的评估配方，是迈向更透明、更可靠的开放模型评估的有意义一步。我们正在告别把评估当作一堆定制的"黑盒"脚本的做法，转向一个定义清晰的系统——基准选择、提示词和执行语义都编码进透明的工作流。

对开发者和研究人员，这种透明改变了"分享结果"的含义。一个分数只和方法论一样可信——公开方法论，才能让社区验证声明、公平比较模型、在共同基础上继续建设。凭借开放的配置、开放的产物和开放的工具，Nemotron 3 Nano 展示了开放承诺在实践中长什么样。

NeMo Evaluator 通过提供跨模型、跨发布、跨推理环境的一致基准方法支持这一转变。目标不是每次运行数字完全相同，而是对一套明确、可检视、可重复的评估方法论的信心。对于需要自动化或大规模评估流水线的组织，另有独立的微服务产品——基于同样评估原则构建的企业级 [NeMo Evaluator microservice](https://developer.nvidia.com/nemo-evaluator)。

使用已发布的 [NeMo Evaluator 评估配置](https://github.com/NVIDIA-NeMo/Evaluator/blob/main/packages/nemo-evaluator-launcher/examples/nemotron/nano-v3-reproducibility.md)，端到端走一遍评估配方。
