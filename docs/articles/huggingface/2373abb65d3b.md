# PaliGemma – Google 的尖端开放视觉语言模型

merve（merve）、Andreas P. Steiner（andsteing，google）、Pedro Cuenca（pcuenq）

本文另有中文版本 [简体中文](https://huggingface.co/blog/zh/paligemma)。

更新于 2024-05-23：我们对 transformers 里 PaliGemma 实现在微调周围做了一些改动，见这个 [notebook](https://github.com/merveenoyan/smol-vision/blob/main/Fine_tune_PaliGemma.ipynb)。

PaliGemma 是 Google 新推出的视觉语言模型家族。PaliGemma 可以接收一张图像和一段文本，输出文本。

Google 团队发布了三类模型：预训练（pt）模型、mix 模型和微调（ft）模型，各自有不同的分辨率，并为方便起见提供多种精度。

所有模型都发布在 Hugging Face Hub 的模型仓库里，带有模型卡和许可证，并有 transformers 集成。

## PaliGemma 是什么？

PaliGemma（[Github](https://github.com/google-research/big_vision/blob/main/big_vision/configs/proj/paligemma/README.md)）是一个视觉语言模型家族，其架构由作为图像编码器的 [SigLIP-So400m](https://huggingface.co/google/siglip-so400m-patch14-384) 和作为文本解码器的 [Gemma-2B](https://huggingface.co/google/gemma-2b) 组成。SigLIP 是一个能同时理解图像和文本的最先进模型。像 CLIP 一样，它由一个图像编码器和一个文本编码器联合训练而成。类似 [PaLI-3](https://arxiv.org/abs/2310.09199)，组合起来的 PaliGemma 模型在图文数据上预训练，之后可以轻松地在下游任务上微调，例如描述生成或指代分割。[Gemma](https://huggingface.co/blog/gemma) 是一个用于文本生成的仅解码器模型。把 SigLIP 的图像编码器与 Gemma 用一个线性适配器结合，使 PaliGemma 成为一个强大的视觉语言模型。

[![Architecture](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/paligemma/paligemma_arch.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/paligemma/paligemma_arch.png)

PaliGemma 的发布包含三类模型：

- PT checkpoint：预训练模型，可微调到下游任务。
- Mix checkpoint：在多种任务混合上微调过的 PT 模型。它们适合用自由文本提示词做通用推理，仅供研究使用。
- FT checkpoint：一组微调模型，每个专精于不同的学术基准。它们有不同分辨率版本，仅供研究使用。

模型有三种不同的分辨率（`224x224`、`448x448`、`896x896`）和三种不同的精度（`bfloat16`、`float16`、`float32`）。每个仓库包含某个给定分辨率和任务的 checkpoint，每种可用精度对应三个 revision。每个仓库的 `main` 分支含 `float32` 的 checkpoint，而 `bfloat16` 和 `float16` revision 含相应精度。兼容 🤗 transformers 与原始 JAX 实现的模型各有单独的仓库。

如下文详述，高分辨率模型需要多得多的内存来运行，因为输入序列要长得多。它们或许对 OCR 这类细粒度任务有帮助，但对多数任务质量提升很小。224 版本对大多数用途完全够用。

你可以在这个[合集](https://huggingface.co/collections/google/paligemma-release-6643a9ffbf57de2ae0448dda)里找到所有模型和 Spaces。

## 模型能力

PaliGemma 是单轮视觉语言模型，并非为对话使用而设计，它在针对特定用例微调时表现最好。

你可以通过用任务前缀（如 "detect" 或 "segment"）来条件化模型，从而配置它要解决的任务。预训练模型以这种方式训练，以被赋予丰富的能力集（问答、描述生成、分割等）。但它们不是设计来直接使用的，而是通过微调以类似的提示词结构迁移到具体任务。要交互测试，你可以使用 "mix" 系列模型，它们在混合任务上做过微调。

下面的示例用 mix checkpoint 来演示部分能力。

### 图像描述生成

PaliGemma 在被提示时可以为图像生成描述。你可以用 mix checkpoint 试各种描述提示词，看它如何响应。

[![Captioning](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/paligemma/captioning.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/paligemma/captioning.png)

### 视觉问答

PaliGemma 可以回答关于图像的问题，只需把你的问题和图像一起传入即可。

[![VQA](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/paligemma/vqa.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/paligemma/vqa.png)

### 检测

PaliGemma 可以用 `detect [entity]` 提示词检测图像中的实体。它会以特殊的 `<loc[value]>` token 形式输出边界框坐标的位置，其中 `value` 是一个代表归一化坐标的数字。每个检测由四个位置坐标表示，顺序为 *y_min, x_min, y_max, x_max*，随后是在该框中检测到的标签。要把 value 转换为坐标，你需要先把数字除以 1024，然后把 `y` 乘以图像高度、`x` 乘以图像宽度。这会给出相对于原始图像尺寸的边界框坐标。

[![Detection](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/paligemma/detect.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/paligemma/detect.png)

### 指代表达分割

PaliGemma mix checkpoint 在给出 `segment [entity]` 提示词时，还能分割图像中的实体。这被称为指代表达分割，因为我们用自然语言描述来指代感兴趣的实体。输出是一串位置和分割 token。位置 token 如上所述表示一个边界框。分割 token 可以进一步处理以生成分割掩码。

[![Segmentation](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/paligemma/segment.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/paligemma/segment.png)

你也可以直接在[这个 notebook](https://colab.research.google.com/drive/1gOhRCFyt9yIoasJkd4VoaHcIqJPdJnlg?usp=sharing) 里尝试推理。

### 使用 Transformers

你可以用 `PaliGemmaForConditionalGeneration` 类对任一发布模型做推理。只需用内建的 processor 预处理提示词和图像，然后把预处理后的输入传给生成。

```
from transformers import AutoProcessor, PaliGemmaForConditionalGeneration

model_id = "google/paligemma-3b-mix-224"
model = PaliGemmaForConditionalGeneration.from_pretrained(model_id)
processor = AutoProcessor.from_pretrained(model_id)

prompt = "What is on the flower?"
image_file = "https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/bee.jpg?download=true"
raw_image = Image.open(requests.get(image_file, stream=True).raw)
inputs = processor(prompt, raw_image, return_tensors="pt")
output = model.generate(**inputs, max_new_tokens=20)

print(processor.decode(output[0], skip_special_tokens=True)[len(prompt):])
# bee
```

你也可以按如下方式以 4-bit 加载模型。

```
from transformers import BitsAndBytesConfig

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,

    bnb_4bit_compute_dtype=torch.bfloat16
)
model = PaliGemmaForConditionalGeneration.from_pretrained(
    model_id,
    quantization_config=bnb_config,
    device_map={"":0}
)
```

## 详细的推理过程

如果你想编写自己的预处理或训练代码，或想更深入理解 PaliGemma 如何工作，以下是输入图像和文本会经历的步骤。

输入文本照常分词。开头加上一个 `<bos>` token，末尾再追加一个换行 token（`\n`）。这个换行 token 是模型训练时所输入提示词的关键部分，显式加它能确保它始终在。分词后的文本还会以一个固定数量的 `<image>` token 作前缀。数量多少？这取决于输入图像分辨率和 SigLIP 模型所用的 patch 大小。PaliGemma 模型在三种方形尺寸之一（224x224、448x448 或 896x896）上预训练，且始终使用 14 的 patch 大小。因此，要前置的 `<image>` token 数量对 224 模型是 256（`224/14 * 224/14`），对 448 模型是 1024，对 896 模型是 4096。

注意更大的图像会带来长得多的输入序列，因此在经过模型的语言部分时需要多得多的内存。考虑用哪个模型时请记住这点。对 OCR 这类更细粒度的任务，更大的图像可能有助于取得更好结果，但对绝大多数任务增量质量很小。在决定转向更大分辨率之前一定要在你的任务上测试！

这个完整的"提示词"经过语言模型的文本嵌入层，为每个 token 生成 2048 维的 token 嵌入。

与之并行地，输入图像用双三次重采样缩放到所需的输入尺寸（最小分辨率模型为 224x224）。然后它经过 SigLIP 图像编码器，生成每个 patch 1152 维的图像嵌入。这里线性投影器发挥作用：图像嵌入被投影以获得每个 patch 2048 维的表示，与文本 token 得到的表示相同。最终的图像嵌入随后与 `<image>` 文本嵌入合并，这就是用于自回归文本生成的最终输入。生成照常以自回归模式进行。它对完整输入（`image + bos + prompt + \n`）使用全块注意力，对生成的文本使用因果注意力掩码。

所有这些细节都在 processor 和 model 类里自动处理，因此推理可以用前面示例中展示的那种熟悉的高层 transformers API 来完成。

## 微调

### 使用 big_vision

PaliGemma 在 [big_vision](https://github.com/github-research/big_vision) 代码库中训练。同样的代码库早先还被用来开发 BiT、原版 ViT、LiT、CapPa、SigLIP 等模型。

项目配置目录 [configs/proj/paligemma/](https://github.com/google-research/big_vision/blob/main/big_vision/configs/proj/paligemma/) 里有一个 `README.md`。预训练模型可以通过运行 [transfers/](https://github.com/google-research/big_vision/blob/main/big_vision/configs/proj/paligemma/transfers/) 子目录里的配置文件来迁移，我们所有的迁移结果都是通过运行其中提供的配置得到的。如果你想迁移自己的模型，fork 示例配置 [transfers/forkme.py](https://github.com/google-research/big_vision/blob/main/big_vision/configs/proj/paligemma/transfers/forkme.py)，并按注释里的说明把它改造成适配你的用例。

还有一个 Colab [`finetune_paligemma.ipynb`](https://colab.research.google.com/github/google-research/big_vision/blob/main/big_vision/configs/proj/paligemma/finetune_paligemma.ipynb)，它运行一种*简化微调*，能在免费的 T4 GPU 运行时上工作。为了适配有限的主机和 GPU 内存，Colab 里的代码只更新注意力层的权重（1.7 亿参数）并使用 SGD（而非 Adam）。

### 使用 transformers

得益于 transformers，微调 PaliGemma 非常容易。你也可以做 QLoRA 或 LoRA 微调。在这个示例里，我们会先简短地微调解码器，然后演示如何切换到 QLoRA 微调。我们会安装最新版的 transformers 库。

```
pip install transformers
```

和推理一节一样，我们会用 `notebook_login()` 认证以访问模型。

```
from huggingface_hub import notebook_login
notebook_login()
```

在这个示例里，我们会用 VQAv2 数据集，微调模型以回答关于图像的问题。我们来加载数据集。我们只用 question、multiple_choice_answer 和 image 这几列，所以也删掉其余列。我们还会划分数据集。

```
from datasets import load_dataset 
ds = load_dataset('HuggingFaceM4/VQAv2', split="train") 
cols_remove = ["question_type", "answers", "answer_type", "image_id", "question_id"] 
ds = ds.remove_columns(cols_remove)
ds = ds.train_test_split(test_size=0.1)
train_ds = ds["train"]
val_ds = ds["test"]
```

现在我们会加载 processor（包含图像处理和分词部分）并预处理我们的数据集。

```
from transformers import PaliGemmaProcessor 
model_id = "google/paligemma-3b-pt-224"
processor = PaliGemmaProcessor.from_pretrained(model_id)
```

我们会创建一个提示词模板来条件化 PaliGemma 回答视觉问题。由于分词器会 pad 输入，我们需要把标签里的 pad 设成不同于分词器 pad token 以及 image token 的值。

```
import torch
device = "cuda"

image_token = processor.tokenizer.convert_tokens_to_ids("<image>")
def collate_fn(examples):
  texts = ["answer " + example["question"] for example in examples]
  labels= [example['multiple_choice_answer'] for example in examples]
  images = [example["image"].convert("RGB") for example in examples]
  tokens = processor(text=texts, images=images, suffix=labels,
                    return_tensors="pt", padding="longest")

  tokens = tokens.to(torch.bfloat16).to(device)
  return tokens
```

你可以直接加载模型，也可以以 4-bit 加载模型做 QLoRA。下面你能看到如何直接加载模型。我们会加载模型，冻结图像编码器和投影器，只微调解码器。如果你的图像属于某个特定领域、可能不在模型预训练所用的数据集中，你可能想跳过冻结图像编码器。

```
model = PaliGemmaForConditionalGeneration.from_pretrained(model_id, torch_dtype=torch.bfloat16).to(device)

for param in model.vision_tower.parameters():
    param.requires_grad = False

for param in model.multi_modal_projector.parameters():
    param.requires_grad = True
```

如果你想以 4-bit 加载模型做 QLoRA，可以在下面加上这些改动。

```
from transformers import BitsAndBytesConfig
from peft import get_peft_model, LoraConfig

bnb_config = BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_quant_type="nf4",
        bnb_4bit_compute_type=torch.bfloat16
)

lora_config = LoraConfig(
    r=8, 
    target_modules=["q_proj", "o_proj", "k_proj", "v_proj", "gate_proj", "up_proj", "down_proj"],
    task_type="CAUSAL_LM",
)
model = PaliGemmaForConditionalGeneration.from_pretrained(model_id, quantization_config=bnb_config, device_map={"":0})
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
#trainable params: 11,298,816 || all params: 2,934,634,224 || trainable%: 0.38501616002417344
```

现在我们会初始化 Trainer 和 TrainingArguments。如果你做 QLoRA 微调，把优化器设为 `paged_adamw_8bit` 替代。

```
from transformers import TrainingArguments
args=TrainingArguments(
            num_train_epochs=2,
            remove_unused_columns=False,
            per_device_train_batch_size=16,
            gradient_accumulation_steps=4,
            warmup_steps=2,
            learning_rate=2e-5,
            weight_decay=1e-6,
            adam_beta2=0.999,
            logging_steps=100,
            optim="adamw_hf",
            save_strategy="steps",
            save_steps=1000,
            push_to_hub=True,
            save_total_limit=1,
            bf16=True,
            report_to=["tensorboard"],
            dataloader_pin_memory=False
        )
```

初始化 `Trainer`，传入数据集、数据整理函数和训练参数，然后调用 `train()` 开始训练。

```
trainer = Trainer(
        model=model,
        train_dataset=train_ds,
        eval_dataset=val_ds,
        data_collator=collate_fn,
        args=args
        )
trainer.train()
```
