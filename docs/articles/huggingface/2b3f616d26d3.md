在[上一篇文章](https://huggingface.co/blog/hf-torchneuron)里，我们介绍了 TorchNeuron——AWS Trainium 的原生 PyTorch 后端（也就是 `torch-neuronx` 包）。有了它，Transformers 会把自家的建模代码跑在 Trainium 上，就像在任何其他设备上一样，因此 Hub 上任何一个 Transformers 模型都有可能跑起来。那究竟哪些能跑？

[torch-neuronx 模型支持](https://huggingface.co/spaces/aws-neuron/torch-neuronx-model-support) Space 回答了 Hub 上最热门模型在这一点上的问题。它会告诉你某个模型能否不经修改地在 Trainium 上运行，并把让你自己跑起来的脚本一并给你。

[![torch-neuronx 模型支持](https://huggingface.co/spaces/aws-neuron/torch-neuronx-model-support/resolve/main/thumbnail.jpg)](https://huggingface.co/spaces/aws-neuron/torch-neuronx-model-support)

## 查一个模型

该 Space 打开时停在 **Selected** 视图：这是我们自己按下载量和趋势分数，从 Hub 上顶级模型里挑出的一份名单。每一行给出结果、模型分片所占的 Trainium 核心数、那次运行的实际耗时（含编译）以及峰值设备内存。

要查某个具体模型，切换到 **Trending** 或 **Downloads** 视图，然后输入它名字的一部分。这两个视图遵循 Hub 自己的排名，一次只覆盖一个任务，无论模型是否被测过。当某个模型是被有意略过时，Space 会告诉你原因（多数情况是没被优先安排，有时确实是不兼容）。你还可以选择查看哪个版本的 Neuron 编译器（`neuronx-cc`）和 Transformers。

> 撰写本文时，只测试 Transformers 模型，而且我们的选择仅限于文本生成和图文到文本（image-text-to-text）模型。我们计划扩展到 diffusers、sentence transformers 以及其他 transformers 任务。

## 自己跑一遍

选中一个模型就能看到怎么运行它。Space 会列出该模型所基于测试的 Neuron 栈、在其上需要安装的包，以及实际运行过的 `run.py` 脚本。这个脚本遵循 [TorchNeuron 发布公告](https://huggingface.co/blog/hf-torchneuron)里的配方：用 `from_pretrained` 加载模型，需要时做分片，然后用静态缓存和 `torch.compile(backend="neuron")` 生成。

在一个装有这套栈的 Trainium2（`trn2`）实例上——例如 [AWS Neuron Deep Learning Container](https://github.com/aws-neuron/deep-learning-containers#torch-neuronx) 里——先安装这些包，然后运行：

```
python3 run.py
```

不需要 `torchrun`：当模型需要分片时，脚本会自己拉起 `torch.distributed` 的各 rank。

第一次运行会从编译模型的计算图开始。要跳过这一步，可以从公开的 [NEFF 缓存](https://huggingface.co/buckets/aws-neuron/torch-neuronx-neff-cache) 桶里，把测试期间用同一版本编译器构建好的计算图拷过来。Space 会给出对应的命令和正确的编译器版本：

```
hf buckets sync hf://buckets/aws-neuron/torch-neuronx-neff-cache/neuronxcc-<version> /tmp/neff_cache
```

## “运行”意味着什么

每个测试都会把模型加载到一个 `trn2` 实例上，并分片到能够容纳其权重的最少数量的 Trainium 核心上。大多数模型用张量并行来分片。没有张量并行方案的 Mixture-of-Experts 模型只使用专家并行。随后测试生成 32 个 token 并检查它们。在单核上，这些 token 会与同一检查点 CPU 运行的结果做比较。当模型被分片时，则由一个小型评判模型检查文本是否为流利的英语。

撰写本文时，只测试能够放进 4 台 Trainium2 设备的模型，也就是最多 16 个核心。一个 `PASS` 并不说明吞吐，也不说明更长的生成。

## 结果本身就是一个数据集

Space 展示的一切都来自公开的 [`aws-neuron/torch-neuronx-model-support`](https://huggingface.co/datasets/aws-neuron/torch-neuronx-model-support) 数据集，每一对 `neuronx-cc` 与库版本对应一个 Parquet 文件。

每一行保存了某个模型的结果、失败时的错误、整个栈的版本，以及运行过的那个 `run.py`。你可以直接查询它：

```
import pandas as pd

df = pd.read_parquet("hf://datasets/aws-neuron/torch-neuronx-model-support/data")
df[df.model_id == "Qwen/Qwen3-0.6B"][["neuronx_cc", "library", "library_version", "neuron_cores", "result"]]
```

[数据集卡](https://huggingface.co/datasets/aws-neuron/torch-neuronx-model-support)给出了每种结果的准确含义。

下次你想知道某个模型能不能在 Trainium 上跑时，[查一查](https://huggingface.co/spaces/aws-neuron/torch-neuronx-model-support)。
