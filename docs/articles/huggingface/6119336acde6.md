# 用 🤗 Transformers 微调 XLSR-Wav2Vec2 实现低资源 ASR

***新增（2021/11）***：*本博文已更新，改为介绍 XLSR 的继任者 [XLS-R](https://huggingface.co/models?other=xls_r)*。

**Wav2Vec2** 是一个自动语音识别（ASR）预训练模型，由 *Alexei Baevski、Michael Auli 和 Alex Conneau* 于 [2020 年 9 月](https://ai.facebook.com/blog/wav2vec-20-learning-the-structure-of-speech-from-raw-audio/)发布。在 LibriSpeech——最受欢迎的英语 ASR 数据集之一——上展示出出色性能后不久，*Facebook AI* 推出了 Wav2Vec2 的多语言版本 [XLSR](https://arxiv.org/abs/2006.13979)。XLSR 意为 *cross-lingual speech representations*（跨语言语音表征），指该模型能学到对多种语言都有用的语音表征。

XLSR 的继任者就叫 **XLS-R**（对应[*《XLM-R*](https://ai.facebook.com/blog/-xlm-r-state-of-the-art-cross-lingual-understanding-through-self-supervision/)*：语音版*」的比喻），由 *Arun Babu、Changhan Wang、Andros Tjandra 等*于 [2021 年 11 月](https://ai.facebook.com/blog/xls-r-self-supervised-speech-processing-for-128-languages)发布。XLS-R 用 128 种语言、近 **50 万**小时的音频数据做自监督预训练，规模从 3 亿参数一直到 **20 亿**参数。预训练 checkpoint 可以在 🤗 Hub 上找到：

- [**Wav2Vec2-XLS-R-300M**](https://huggingface.co/facebook/wav2vec2-xls-r-300m)
- [**Wav2Vec2-XLS-R-1B**](https://huggingface.co/facebook/wav2vec2-xls-r-1b)
- [**Wav2Vec2-XLS-R-2B**](https://huggingface.co/facebook/wav2vec2-xls-r-2b)

与 [BERT 的掩码语言建模目标](http://jalammar.github.io/illustrated-bert/)类似，XLS-R 在自监督预训练中随机掩码特征向量再送入 Transformer 网络，从而学习上下文相关的语音表征（即下图左侧）。

微调时，在预训练网络顶部加一个线性层，用带标注的数据在语音识别、语音翻译、音频分类等下游语音任务上训练模型（即下图右侧）。

[![wav2vec2\_structure](https://raw.githubusercontent.com/patrickvonplaten/scientific_images/master/xls_r.png)](https://raw.githubusercontent.com/patrickvonplaten/scientific_images/master/xls_r.png)

XLS-R 在语音识别、语音翻译和说话人/语言识别上都相对此前 SOTA 有显著提升，分别参见官方[论文](https://ai.facebook.com/blog/xls-r-self-supervised-speech-processing-for-128-languages)的表 3-6、表 7-10 和表 11-12。

## 环境准备

在这篇博文中，我们将详细讲解如何为 ASR 微调 XLS-R——更具体地说是预训练 checkpoint [**Wav2Vec2-XLS-R-300M**](https://huggingface.co/facebook/wav2vec2-xls-r-300m)。

作为演示，我们在 [Common Voice](https://huggingface.co/datasets/common_voice) 的低资源 ASR 数据集上微调模型，其验证过的训练数据只有约 4 小时。

XLS-R 的微调使用 Connectionist Temporal Classification（CTC，连接时序分类）。CTC 是一种用于训练序列到序列问题神经网络的算法，典型应用包括 ASR 和手写识别。

## 准备数据、分词器、特征提取器

ASR 模型把语音转写成文本，因此我们既需要一个把语音信号处理成模型输入格式（如特征向量）的特征提取器，也需要一个把模型输出格式还原为文本的分词器。

在 🤗 Transformers 中，XLS-R 模型配有分词器 [Wav2Vec2CTCTokenizer](https://huggingface.co/transformers/master/model_doc/wav2vec2.html#wav2vec2ctctokenizer) 和特征提取器 [Wav2Vec2FeatureExtractor](https://huggingface.co/transformers/master/model_doc/wav2vec2.html#wav2vec2featureextractor)。

先创建分词器，用于把预测的输出类别解码成转写文本。

### 创建 `Wav2Vec2CTCTokenizer`

预训练的 XLS-R 模型把语音信号映射为上下文表征序列，如上图所示。但要做语音识别，模型必须把这个上下文表征序列映射为对应的转写文本，也就是要在 Transformer 块（上图黄色部分）顶部加一个线性层，用它对每个上下文表征做 token 类别分类——这类似于 BERT 预训练后在其 embedding 顶部加线性层做下游分类（参见[这篇博文](https://huggingface.co/blog/warm-starting-encoder-decoder)的 "BERT" 一节）。

该层的输出维度等于词表中的 token 数量，这**不**取决于 XLS-R 的预训练任务，只取决于微调所用的标注数据集。所以第一步，我们来看选定的 Common Voice 数据集，并基于转写文本定义词表。

首先去 Common Voice [官网](https://commonvoice.mozilla.org/en/datasets)选一门要微调 XLS-R 的语言。本 notebook 使用土耳其语。

每门语言的数据集都有一个对应的语言代码。在 [Common Voice](https://commonvoice.mozilla.org/en/datasets) 上找 "Version" 字段，下划线前的前缀就是语言代码。土耳其语的语言代码是 `"tr"`。

可以看到转写文本中包含一些特殊字符，如 `,.?!;:`。在没有语言模型的情况下，把语音片段分类到这些特殊字符要难得多，因为它们并没有对应的特征声音单元。比如字母 `"s"` 有相对明确的声音，而特殊字符 `"."` 没有。而且，要理解语音信号的含义，通常也不需要把特殊字符包含在转写里。

我们就直接移除所有不贡献词义、也无法用声音表示的字符，并对文本做归一化。

```
import re
chars_to_remove_regex = '[\,\?\.\!\-\;\:\"\“\%\‘\”\\']'

def remove_special_characters(batch):
    batch["sentence"] = re.sub(chars_to_remove_regex, '', batch["sentence"]).lower()
    return batch
```

```
common_voice_train = common_voice_train.map(remove_special_characters)
common_voice_test = common_voice_test.map(remove_special_characters)

def replace_hatted_characters(batch):
    batch["sentence"] = re.sub('[â]', 'a', batch["sentence"])
    batch["sentence"] = re.sub('[î]', 'i', batch["sentence"])

    batch["sentence"] = re.sub('[û]', 'u', batch["sentence"])
    return batch
```

在 CTC 中，通常把语音片段分类到字母，我们也照此办理。下面从训练和测试数据中提取所有不同的字母，用这组字母构建词表。

我们写一个映射函数，把所有转写文本拼接成一个长文本，再把字符串转换为字符集合。注意一定要给 `map(...)` 函数传 `batched=True` 参数，映射函数才能一次访问所有转写文本。

```
def extract_all_chars(batch):
  all_text = " ".join(batch["sentence"])
  vocab = list(set(all_text))
  return {"vocab": [vocab], "all_text": [all_text]}
```

```
vocab_train = common_voice_train.map(extract_all_chars, batched=True, batch_size=-1, keep_in_memory=True, remove_columns=common_voice_train.column_names)
vocab_test = common_voice_test.map(extract_all_chars, batched=True, batch_size=-1, keep_in_memory=True, remove_columns=common_voice_test.column_names)
```

模型必须学会判断一个词何时结束，否则模型的预测永远是一串连续的字符，词与词之间就没法分开了。

还要始终记住，预处理是训练前极其重要的一步。比如，我们不想因为忘了做数据归一化，就让模型去区分 `a` 和 `A`。`a` 与 `A` 的区别根本不取决于读音的"声音"，而更多取决于语法规则——比如句首字母大写。所以去掉大小写差异是明智的，能让模型更轻松地从语音中学会转写。

为了让 `" "` 作为独立 token 类别更直观，我们把它换成更显眼的字符 `|`。此外再添加一个"未知" token，让模型日后能处理 Common Voice 训练集中没出现过的字符。

```
vocab_dict["|"] = vocab_dict[" "]
del vocab_dict[" "]

最后，再添加一个填充 token，对应 CTC 的"*blank token*（空白 token）"。blank token 是 CTC 算法的核心组件。更多信息请看[这里](https://distill.pub/2017/ctc/)的 "Alignment" 一节。

```
vocab_dict["[UNK]"] = len(vocab_dict)
vocab_dict["[PAD]"] = len(vocab_dict)
len(vocab_dict)
```

### 创建 `Wav2Vec2FeatureExtractor`

语音是连续信号，计算机要处理它，必须先离散化，通常称为**采样**。采样率非常关键，因为它决定了每秒测量语音信号上多少个数据点。因此，更高的采样率能更好地逼近*真实*语音信号，但每秒也要存更多的值。

预训练 checkpoint 期望其输入数据的采样分布与训练数据大致相同。同一语音信号在两种采样率下的分布差异极大——例如采样率翻倍，数据点就变成两倍长。所以在微调 ASR 模型的预训练 checkpoint 之前，务必确认预训练数据的采样率与微调数据集的采样率一致。

XLS-R 在 [Babel](http://www.reading.ac.uk/AcaDepts/ll/speechlab/babel/r)、[Multilingual LibriSpeech (MLS)](https://huggingface.co/datasets/multilingual_librispeech)、[Common Voice](https://huggingface.co/datasets/common_voice)、[VoxPopuli](https://arxiv.org/abs/2101.00390) 和 [VoxLingua107](https://arxiv.org/abs/2011.12998) 的音频数据上预训练，采样率为 16kHz。Common Voice 原始形态的采样率是 48kHz，因此接下来我们必须把微调数据降采样到 16kHz。

实例化 `Wav2Vec2FeatureExtractor` 对象需要以下参数：

- `feature_size`：语音模型的输入是一串特征向量。序列长度自然各不相同，但特征维度应当固定。Wav2Vec2 的 feature_size 为 1，因为它是在原始语音信号上训练的²。
- `sampling_rate`：模型训练时的采样率。
- `padding_value`：批量推理时，较短的输入需要用指定值填充。
- `do_normalize`：输入是否要做*零均值单位方差*归一化。一般来说，语音模型在归一化输入后表现更好。
- `return_attention_mask`：模型批量推理时是否应使用 `attention_mask`。通常，XLS-R checkpoint **始终**应该使用 `attention_mask`。

```
from transformers import Wav2Vec2FeatureExtractor

feature_extractor = Wav2Vec2FeatureExtractor(feature_size=1, sampling_rate=16000, padding_value=0.0, do_normalize=True, return_attention_mask=True)
```

很好，XLS-R 的特征提取流水线至此完整定义！

为了更方便用户使用，特征提取器和分词器被*包装*进同一个 `Wav2Vec2Processor` 类，这样我们只需要 `model` 和 `processor` 两个对象。

```
from transformers import Wav2Vec2Processor

processor = Wav2Vec2Processor(feature_extractor=feature_extractor, tokenizer=tokenizer)
```

最后，借助 `Wav2Vec2Processor` 把数据处理成 `Wav2Vec2ForCTC` 训练所需的格式。这要用到 Dataset 的 [`map(...)`](https://huggingface.co/docs/datasets/package_reference/main_classes.html?highlight=map#datasets.DatasetDict.map) 函数。

首先，只需调用 `batch["audio"]` 即可加载并重采样音频数据。其次，从加载的音频中提取 `input_values`。在我们的场景里，`Wav2Vec2Processor` 只做了归一化；但对其他语音模型，这一步可能包含更复杂的特征提取，如 [Log-Mel 特征提取](https://en.wikipedia.org/wiki/Mel-frequency_cepstrum)。第三，把转写文本编码为 label id。

**注意**：这个映射函数是 `Wav2Vec2Processor` 类应如何使用的很好示例。"正常"情况下，调用 `processor(...)` 会被转发到 `Wav2Vec2FeatureExtractor` 的 call 方法；而把 processor 包进 `as_target_processor` 上下文后，同一方法会被转发到 `Wav2Vec2CTCTokenizer` 的 call 方法。更多信息请查看[文档](https://huggingface.co/transformers/master/model_doc/wav2vec2.html#transformers.Wav2Vec2Processor.__call__)。

```
def prepare_dataset(batch):
    audio = batch["audio"]

    # batched output is "un-batched"
    batch["input_values"] = processor(audio["array"], sampling_rate=audio["sampling_rate"]).input_values[0]
    batch["input_length"] = len(batch["input_values"])
    
    with processor.as_target_processor():
        batch["labels"] = processor(batch["sentence"]).input_ids
    return batch
```

把数据准备函数应用到所有样本。

```
common_voice_train = common_voice_train.map(prepare_dataset, remove_columns=common_voice_train.column_names)
common_voice_test = common_voice_test.map(prepare_dataset, remove_columns=common_voice_test.column_names)
```

**注意**：目前 `datasets` 使用 [`torchaudio`](https://pytorch.org/audio/stable/index.html) 和 [`librosa`](https://librosa.org/doc/latest/index.html) 做音频加载与重采样。如果你想自己实现定制的数据加载/采样，可以直接使用 `"path"` 列，忽略 `"audio"` 列即可。

## 训练

数据已处理完毕，可以着手搭建训练流水线。我们使用 🤗 的 [Trainer](https://huggingface.co/transformers/master/main_classes/trainer.html?highlight=trainer)，本质上需要完成以下几件事：

- 定义数据整理器（data collator）。与多数 NLP 模型不同，XLS-R 的输入长度远大于输出长度。例如一个输入长度为 50000 的样本，输出长度不超过 100。鉴于输入这么大，动态填充训练批次效率高得多——即每个批次只填充到批内最长的样本，而不是整个数据集最长的样本。因此微调 XLS-R 需要一个特殊的填充 data collator，下面来定义。
- 评估指标。训练期间要用词错误率评估模型，因此相应地定义 `compute_metrics` 函数。
- 加载预训练 checkpoint。需要加载预训练 checkpoint 并正确配置成训练模式。
- 定义训练配置。

微调完成后，我们会在测试数据上认真评估模型，验证它确实学会了正确转写语音。

### 配置 Trainer

先定义 data collator。其代码抄自[这个示例](https://github.com/huggingface/transformers/blob/7e61d56a45c19284cfda0cee8995fb552f6b1f4e/examples/pytorch/speech-recognition/run_speech_recognition_ctc.py#L219)。

不展开太多细节：与常见的 data collator 不同，这个 collator 对 `input_values` 和 `labels` 的处理方式不同，分别施加各自的填充函数（同样借助 XLS-R processor 的上下文管理器）。这是必要的，因为在语音任务中输入和输出属于不同模态，不应该用同一个填充函数。和常见 data collator 一样，labels 中的填充 token 被替换为 `-100`，使这些 token 在计算损失时**不**被考虑。

```
import torch

from dataclasses import dataclass, field
from typing import Any, Dict, List, Optional, Union

@dataclass
class DataCollatorCTCWithPadding:
    """
    Data collator that will dynamically pad the inputs received.
    Args:
        processor (:class:`~transformers.Wav2Vec2Processor`)
            The processor used for processing the data.
        padding (:obj:`bool`, :obj:`str` or :class:`~transformers.tokenization_utils_base.PaddingStrategy`, `optional`, defaults to :obj:`True`):
            Select a strategy to pad the returned sequences (according to the model's padding side and padding index)
            among:
            * :obj:`True` or :obj:`'longest'`: Pad to the longest sequence in the batch (or no padding if only a single
              sequence if provided).
            * :obj:`'max_length'`: Pad to a maximum length specified with the argument :obj:`max_length` or to the
              maximum acceptable input length for the model if that argument is not provided.
            * :obj:`False` or :obj:`'do_not_pad'` (default): No padding (i.e., can output a batch with sequences of
              different lengths).
    """

    processor: Wav2Vec2Processor
    padding: Union[bool, str] = True

    def __call__(self, features: List[Dict[str, Union[List[int], torch.Tensor]]]) -> Dict[str, torch.Tensor]:
        # split inputs and labels since they have to be of different lengths and need
        # different padding methods
        input_features = [{"input_values": feature["input_values"]} for feature in features]
        label_features = [{"input_ids": feature["labels"]} for feature in features]

        batch = self.processor.pad(
            input_features,
            padding=self.padding,
            return_tensors="pt",
        )
        with self.processor.as_target_processor():
            labels_batch = self.processor.pad(
                label_features,
                padding=self.padding,
                return_tensors="pt",
            )

        # replace padding with -100 to ignore loss correctly
        labels = labels_batch["input_ids"].masked_fill(labels_batch.attention_mask.ne(1), -100)

        batch["labels"] = labels

        return batch
```

```
data_collator = DataCollatorCTCWithPadding(processor=processor, padding=True)
```

接下来定义评估指标。如前所述，ASR 的主导指标是词错误率（WER），本 notebook 也用它。

```
wer_metric = load_metric("wer")
```

模型会返回一串 logits 向量：$\mathbf{y}_1, \ldots, \mathbf{y}_m$，其中 $\mathbf{y}_1 = f_{\theta}(x_1, \ldots, x_n)[0]$，且 $n \gg m$。

每个 logits 向量 $\mathbf{y}_1$ 包含先前定义的词表中每个词的 log-odds，因此 $\text{len}(\mathbf{y}_i)=$ `config.vocab_size`。我们关心模型最可能的预测，因此取 logits 的 `argmax(...)`。同时，把编码后的 labels 还原回原始字符串：将 `-100` 替换为 `pad_token_id`，再解码 id，并确保按 CTC 规则**不**把相邻相同 token 分组¹。

```
def compute_metrics(pred):
    pred_logits = pred.predictions
    pred_ids = np.argmax(pred_logits, axis=-1)

    pred.label_ids[pred.label_ids == -100] = processor.tokenizer.pad_token_id

    pred_str = processor.batch_decode(pred_ids)
    # we do not want to group tokens when computing the metrics
    label_str = processor.batch_decode(pred.label_ids, group_tokens=False)

    wer = wer_metric.compute(predictions=pred_str, references=label_str)

    return {"wer": wer}
```

现在可以加载 [Wav2Vec2-XLS-R-300M](https://huggingface.co/facebook/wav2vec2-xls-r-300m) 的预训练 checkpoint 了。分词器的 `pad_token_id` 必须用来定义模型的 `pad_token_id`，在 `Wav2Vec2ForCTC` 的场景下也就是 CTC 的 *blank token*²。为节省 GPU 内存，我们启用 PyTorch 的 [gradient checkpointing](https://pytorch.org/docs/stable/checkpoint.html)，并把损失归约方式设为"*mean*"。

由于数据集很小（约 6 小时训练数据）且 Common Voice 噪声不少，微调 Facebook 的 [wav2vec2-xls-r-300m checkpoint](https://huggingface.co/blog/FILL%20ME) 似乎需要一些超参调整。因此我反复试了 dropout、[SpecAugment](https://arxiv.org/abs/1904.08779) 的掩码 dropout 率、layer dropout 和学习率等不同取值，直到训练足够稳定。

**注意**：如果用本 notebook 在 Common Voice 的其它语言上训练 XLS-R，这套超参未必合适，请根据使用场景自行调整。

```

    "facebook/wav2vec2-xls-r-300m",

XLS-R 的第一部分是一叠 CNN 层，用来从原始语音信号中提取声学上有意义但上下文上独立的特征。这部分在预训练中已经训练充分，如[论文](https://arxiv.org/pdf/2006.13979.pdf)所述，无需再微调。因此可以把*特征提取*部分所有参数的 `requires_grad` 设为 `False`。

最后一步，定义所有与训练相关的参数。对其中几个参数多说两句：

- `group_by_length` 把输入长度相近的训练样本分组到同一批次，让训练更高效。这能大幅减少流经模型的无用 padding token 数量，显著加快训练。
- `learning_rate` 和 `weight_decay` 是凭经验调到微调稳定的。注意这些参数 strongly 依赖 Common Voice 数据集，对其他语音数据集可能并非最优。

其他参数的说明见[文档](https://huggingface.co/transformers/master/main_classes/trainer.html?highlight=trainer#trainingarguments)。

¹ 为了让模型不受说话人语速的影响，CTC 会把相邻的相同 token 合并为一个。但解码编码后的 labels 时不应做这种合并，因为它们并不是模型的预测 token，这就是必须传 `group_tokens=False` 的原因。不传的话，像 `"hello"` 这样的词就会被错误地编码、解码成 `"helo"`。 ² blank token 让模型可以预测像 `"hello"` 这样的词——通过强制在两个 l 之间插入 blank token。我们模型对 `"hello"` 的一个符合 CTC 规则的预测是 `[PAD] [PAD] "h" "e" "e" "l" "l" [PAD] "l" "o" "o" [PAD]`。
