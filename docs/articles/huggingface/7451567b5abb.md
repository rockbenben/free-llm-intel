# Gaia2 与 ARE：赋能社区研究智能体

在理想世界里，AI 智能体（agent）应当是可靠的助手：接到请求，它们能轻松处理指令中的歧义、构建分步计划、正确识别所需资源、执行计划时不被带偏、适应突发事件，同时还保持准确、避免幻觉。然而，开发智能体并测试这些行为绝非易事：如果你调试过自己的智能体，多半领教过这有多枯燥、多令人抓狂。现有的评估环境与被评估的任务强耦合，缺乏现实世界的灵活性，也反映不出开放世界智能体面对的混乱现实：模拟页面从不加载失败，事件不会 spontaneously 冒出来，异步的混乱更是无影无踪。

这就是为什么我们非常高兴地推出 Gaia2——智能体基准 GAIA 的续作，能够分析复杂得多的行为。Gaia2 与开放的 Meta Agents Research Environments（ARE）框架一同发布，用来运行、调试和评估智能体。ARE 模拟复杂的类真实世界条件，且可以自定义以更深入地研究智能体行为。Gaia2 数据集以 CC BY 4.0 许可证发布，ARE 以 MIT 许可证发布。

## Gaia2：面向现实生活助手任务的智能体评估

[GAIA](https://arxiv.org/abs/2311.12983) 是 2023 年发布的智能体基准，包含 3 个难度的信息检索问题，需要工具、网页浏览和推理才能解决。两年过去，最容易的级别对模型来说已经太简单，社区也在逼近最难问题的解答——是时候来一个全新且更难的智能体基准了！

Gaia2 应运而生，作为 GAIA 的续作，在研究的能力维度上远超前者！

GAIA 是只读的，Gaia2 则变成了读写兼备的基准，聚焦交互行为与复杂度的管理。现在评估智能体不仅看搜索与检索，还看在噪声环境（带受控故障）下对模糊或时间敏感查询的指令遵循——比任何其他模拟环境都更贴近现实条件。我们要测试智能体如何处理时不时罢工的工具或 API、在很具体的时间窗内规划一连串动作、以及对新事件做出适应——一整片全新的复杂度空间！

为此我们使用以下任务组（感谢 1000 个全新的人工创作场景）：

- **Execution（执行）**：多步指令遵循与工具使用（如更新联系人）
- **Search（搜索）**：跨来源信息收集（如从 WhatsApp 查朋友所在城市）
- **Ambiguity Handling（歧义处理）**：澄清相互冲突的请求（如日程冲突）
- **Adaptability（适应性）**：响应模拟中的变化（如用后续信息更新邮件）
- **Time/temporal Reasoning（时间/时序推理）**：时间敏感的动作（如延迟 3 分钟后叫车）
- **Agent-to-Agent Collaboration（智能体间协作）**：没有直接 API 权限时智能体之间的沟通
- **Noise Tolerance（噪声耐受）**：对 API 失败和环境不稳定的鲁棒性

秉承 GAIA 的精神，场景不需要专门知识：人类原则上应该能拿 100%，这让模型开发者容易调试。

想探索这个基准？看看我们的[数据集](https://huggingface.co/datasets/meta-agents-research-environments/Gaia2)，并可在[这个 demo](https://huggingface.co/spaces/meta-agents-research-environments/demo) 里更好地浏览。

### Gaia2 如何运行？

Gaia2 在 ARE（一个执行环境）中运行，你选定的智能体在其中可以访问一组应用及相应的预填充数据。

为 Gaia2，我们创建了一个**智能手机仿真**环境，模拟人类日常会用的东西。它包含现实世界应用：消息（Email）、工具类（Calendar、Contacts、Shopping、FileSystem……），以及与智能体对话的聊天界面。所有应用也都能通过工具调用被智能体访问。最后但同样重要的是，demo 还包含一个模拟人物的历史对话与应用交互记录。

所有智能体交互在执行期间都会被自动记录为**结构化轨迹**，便于深挖分析：包括工具调用、API 响应、模型思考、计时指标（如响应延迟）、用户交互等等——且都可以导出为 JSON。

### 结果

作为参照，我们对比了一批大型开源与闭源模型：Llama 3.3-70B Instruct、Llama-4-Maverick、GPT-4o、Qwen3-235B-MoE、Grok-4、Kimi K2、Gemini 2.5 Pro、Claude 4 Sonnet，以及所有推理模式下的 GPT-5。

所有模型用相同的设置评估（统一的 ReAct 循环以保一致性、温度 0.5、生成上限 16K token），并根据具体任务组合使用模型评审（model-as-a-judge，Llama 3.3 Instruct 70B）与精确匹配评估。全部 101 个工具（以及通用环境说明）都放在系统提示词里。

[![Results](https://huggingface.co/spaces/meta-agents-research-environments/demo/resolve/main/blog_assets/fig9_Gaia2_scores_per_capability.png)](https://huggingface.co/spaces/meta-agents-research-environments/demo/resolve/main/blog_assets/fig9_Gaia2_scores_per_capability.png)

在评估的模型中，截至 2025 年 9 月**总分最高的模型**是高推理模式的 GPT-5，最好的开源模型是 Kimi K2。

一些能力看起来已接近**被最强模型解决**：简单工具调用与指令遵循的执行（`execution`），以及整体的 `search`（从 GAIA 的当前成绩也能猜到）。而歧义、适应性和噪声这几个分项目前对所有模型仍然**很有挑战**。有意思的是，在曾被视为复杂智能体任务（指令遵循与搜索）上的表现，并不能很好地代理更贴近真实世界任务上的表现。最后，目前对所有模型最难的分项是 `time`：**模型当下很难正确处理时间敏感的动作**（虽然通过专用工具和更好的时序推理很可能能缓解）。这些结果的详细分析见论文。

不过，我们认为**把报告推离原始分数**很重要：如果模型答对了但花了几千 token、或跑了好几个小时，它就"不如"快几个数量级就成功的模型。因此我们还按成本对分数做归一化，成本量化为平均 LLM 调用次数和输出 token 数（两者共同定义了成本-性能 Pareto 前沿）。论文里有分数对比金钱成本和时间的分析。

### 用你喜爱的模型来对比！在 Gaia2 上评估

如果你想让你的模型上 Gaia2 评估，按以下步骤来：

首先，在你选的 Python 环境（uv、conda、virtualenv……）里安装 Meta 的 Agent Research Environment

```
pip install meta-agents-research-environments
```

然后，为全部配置运行基准：execution、search、adaptability、time 和 ambiguity。别忘了用 hf_upload 参数把所有结果上传到 hub！

```
are-benchmark run --hf meta-agents-research-environments/Gaia2     --split validation --config CONFIGURATION     --model YOUR_MODEL --model_provider YOUR_PROVIDER     --agent default     --max_concurrent_scenarios 2     --scenario_timeout 300     --output_dir ./monitored_test_results     --hf_upload YOUR_HUB_DATASET_TO_SAVE_RESULTS 
```

运行 oracle 得到你的汇总分数文件

```
are-benchmark judge --hf meta-agents-research-environments/Gaia2     --split validation --config CONFIGURATION     --agent default     --max_concurrent_scenarios 2     --scenario_timeout 300     --output_dir ./monitored_test_results --hf_upload YOUR_HUB_DATASET_TO_SAVE_RESULTS 
```

最后，在 README 里补充关于你模型的所有相关信息，并发布到排行榜，把 Gaia2 轨迹集中到[这里](https://huggingface.co/spaces/meta-agents-research-environments/leaderboard)！

## Gaia2 之外：用 ARE 研究你的智能体

除了基准场景，你还可以把 Gaia2 的应用和内容用于 ARE，看看模型能否正确解决更难以自动验证的任务——加载邮件、写跟进邮件、往日历加事件、预约会议——总之，这是**通过交互评估你的 AI 助手**的完美配置。

环境还能轻松自定义：1) **接入你自己的工具**（通过 MCP 或直接接入）来测试智能体；2) **实现你自己的场景**，包括定义**触发事件或定时事件**（例如：2 分钟后，Mail 应用会收到来自某联系人的一封新邮件），观察智能体如何适应不断演化的环境。

（由于智能体默认是 `json agents`，它们搞不坏你的机器——除非你当然把它们接到了带不安全权限的外部应用上。所以添加自有应用或使用不受信任的 MCP 时请谨慎操作。）

以下是我们用 ARE 做过的若干用例：

- 在真实或模拟数据上**随手检验（vibe-check）任何智能体**，研究带各自规则、工具、内容和校验的多种配置
- 测试智能体的**工具调用与编排能力**，用本地应用或 MCP 工具皆可
- 生成你自己的工具调用轨迹，用于**微调工具调用模型**
- 在统一框架中轻松收集并**复现已有的智能体基准**
- 在用户界面里即时调试并**研究智能体间的交互**
- 在噪声环境（API 超时与歧义并存）中**研究模型局限**

### 1) 在简单任务上测试智能体：组织活动

要检验默认模型组织活动有多在行，我们来策划一场生日派对！

我们先让智能体给 Renne 家的所有人发短信，通知用户 11 月 7 日的 30 岁生日派对。默认宇宙里有 21 个联系人，其中包括 5 位 Renne 家庭成员——Linda（模拟"户主"）、她的父母 George 和 Stephie、她的妹妹 Anna，以及她的外公 Morgan。智能体成功遍历了联系人列表，找出四位家庭成员并给他们发了短信。

接下来，我们让智能体创建一个日历邀请并把他们加为受邀者。智能体记得上面的上下文！它在正确的日期创建了日历邀请，并把家庭成员正确加了进去。
