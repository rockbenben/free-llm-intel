# 基于 Hugging Face Datasets 与 Transformers 的图像相似度

本文亦有[简体中文](https://huggingface.co/blog/zh/image-similarity)版本。

在这篇文章中，你将学习如何用 🤗 Transformers 构建一个图像相似度系统。查明一张查询图像（query image）与一组候选图像之间的相似度，是信息检索系统的一个重要用例，例如以图搜图（reverse image search）。系统要回答的始终是：给定一张*查询*图像和一组*候选*图像，哪些图像与查询图像最相似。

我们会借助 [🤗 `datasets` 库](https://huggingface.co/docs/datasets/)，因为它对并行处理的支持十分顺滑，在构建这个系统时正好能派上用场。

尽管本文使用了一个基于 ViT 的模型（[`nateraw/vit-base-beans`](https://huggingface.co/nateraw/vit-base-beans)）和一个特定的数据集（[Beans](https://huggingface.co/datasets/beans)），但它可以扩展为使用其他支持视觉模态的模型和其他图像数据集。一些你可以尝试的代表性模型：

- [Swin Transformer](https://huggingface.co/docs/transformers/model_doc/swin)
- [ConvNeXT](https://huggingface.co/docs/transformers/model_doc/convnext)
- [RegNet](https://huggingface.co/docs/transformers/model_doc/regnet)

此外，文中介绍的方法也有可能扩展到其他模态。

想研究完整可用的图像相似度系统，可以参考开头链接的 Colab Notebook。

## 我们如何定义相似度？

要构建这个系统，首先需要定义我们希望怎样计算两张图像之间的相似度。一种广泛流行的做法是：计算给定图像的稠密表示（嵌入，embedding），然后使用[余弦相似度（cosine similarity）](https://en.wikipedia.org/wiki/Cosine_similarity)来衡量两张图像的相似程度。

在本文中，我们用"嵌入"在向量空间中表示图像。这给了我们一种很好的方式，把图像高维的像素空间（例如 224 x 224 x 3）有意义地压缩到远更低维的空间（例如 768）。这样做的主要好处是后续步骤的计算时间大幅减少。

## 计算嵌入

为了从图像计算嵌入，我们会使用一个对"如何在向量空间中表示输入图像"有所理解的视觉模型。这类模型通常也被称为图像编码器（image encoder）。

加载模型时，我们使用 [`AutoModel` 类](https://huggingface.co/docs/transformers/model_doc/auto#transformers.AutoModel)。它为我们提供了一个接口，可以从 Hugging Face Hub 加载任何兼容的模型权重（checkpoint）。除了模型之外，我们还加载与该模型配套、用于数据预处理的处理器（processor）。

```
from transformers import AutoImageProcessor, AutoModel


model_ckpt = "nateraw/vit-base-beans"
processor = AutoImageProcessor.from_pretrained(model_ckpt)
model = AutoModel.from_pretrained(model_ckpt)
```

在本例中，这份权重是在 [`beans` 数据集](https://huggingface.co/datasets/beans)上微调一个 [基于 Vision Transformer 的模型](https://huggingface.co/google/vit-base-patch16-224-in21k)得到的。

这里可能会冒出一些问题：

**问题 1**：为什么我们不用 `AutoModelForImageClassification`？

因为我们想要的是图像的稠密表示，而不是离散的类别——后者正是 `AutoModelForImageClassification` 会给出的东西。

**问题 2**：为什么偏偏用这份权重？

如前所述，我们在一个特定数据集上构建这个系统。所以，与其使用一个通用型模型（例如在 [ImageNet-1k 数据集上训练的模型](https://huggingface.co/models?dataset=dataset:imagenet-1k&sort=downloads)），不如使用在当前所用数据集上微调过的模型。这样一来，底层模型能更好地理解输入图像。

**请注意**，你也可以使用自监督预训练得到的权重。权重不一定非得来自监督学习。事实上，如果预训练得当，自监督模型可以[取得](https://ai.facebook.com/blog/dino-paws-computer-vision-with-self-supervised-transformers-and-10x-more-efficient-training/)令人印象深刻的检索性能。

现在我们已经有了用于计算嵌入的模型，接下来需要一些可供查询比对的候选图像。

## 寻找相似图像的过程

下面展示了获取相似图像这一过程的图示概览。

把上图拆开来看，我们有以下步骤：

- 从候选图像（`candidate_subset`）中提取嵌入，存入一个矩阵。
- 取一张查询图像，提取它的嵌入。
- 遍历嵌入矩阵（第 1 步算出的），计算查询嵌入与当前候选嵌入之间的相似度分数。我们通常会维护一个类字典的映射结构，记录候选图像的某个标识符与相似度分数之间的对应关系。
- 按相似度分数对该映射结构排序并返回对应的标识符。我们用这些标识符取回候选样本。

我们可以写一个简单的工具函数，并用 `map()` 把它应用到候选图像数据集上，高效地计算嵌入。

```
import torch 

def extract_embeddings(model: torch.nn.Module):
    """Utility to compute embeddings."""
    device = model.device

    def pp(batch):
        images = batch["image"]
        # `transformation_chain` is a compostion of preprocessing
        # transformations we apply to the input images to prepare them
        # for the model. For more details, check out the accompanying Colab Notebook.
        image_batch_transformed = torch.stack(
            [transformation_chain(image) for image in images]
        )
        new_batch = {"pixel_values": image_batch_transformed.to(device)}
        with torch.no_grad():
            embeddings = model(**new_batch).last_hidden_state[:, 0].cpu()
        return {"embeddings": embeddings}

    return pp
```

我们可以这样映射 `extract_embeddings()`：

```
device = "cuda" if torch.cuda.is_available() else "cpu"
extract_fn = extract_embeddings(model.to(device))
candidate_subset_emb = candidate_subset.map(extract_fn, batched=True, batch_size=batch_size)
```

接下来，为了使用方便，我们创建一个列表，包含候选图像的标识符。

```
candidate_ids = []

for id in tqdm(range(len(candidate_subset_emb))):
    label = candidate_subset_emb[id]["labels"]

    # Create a unique indentifier.
    entry = str(id) + "_" + str(label)

    candidate_ids.append(entry)
```

我们会用所有候选图像嵌入构成的矩阵来计算与查询图像的相似度分数。候选图像的嵌入已经算好了，下面这个单元格只是把它们汇集成一个矩阵。

```
all_candidate_embeddings = np.array(candidate_subset_emb["embeddings"])
all_candidate_embeddings = torch.from_numpy(all_candidate_embeddings)
```

我们将使用[余弦相似度](https://en.wikipedia.org/wiki/Cosine_similarity)来计算两个嵌入向量之间的相似度分数，然后用它在给定查询样本时取回相似的候选样本。

```
def compute_scores(emb_one, emb_two):
    """Computes cosine similarity between two vectors."""
    scores = torch.nn.functional.cosine_similarity(emb_one, emb_two)
    return scores.numpy().tolist()


def fetch_similar(image, top_k=5):
    """Fetches the `top_k` similar images with `image` as the query."""
    # Prepare the input query image for embedding computation.
    image_transformed = transformation_chain(image).unsqueeze(0)
    new_batch = {"pixel_values": image_transformed.to(device)}

    # Comute the embedding.
    with torch.no_grad():
        query_embeddings = model(**new_batch).last_hidden_state[:, 0].cpu()

    # Compute similarity scores with all the candidate images at one go.
    # We also create a mapping between the candidate image identifiers
    # and their similarity scores with the query image.
    sim_scores = compute_scores(all_candidate_embeddings, query_embeddings)
    similarity_mapping = dict(zip(candidate_ids, sim_scores))
 
    # Sort the mapping dictionary and return `top_k` candidates.
    similarity_mapping_sorted = dict(
        sorted(similarity_mapping.items(), key=lambda x: x[1], reverse=True)
    )
    id_entries = list(similarity_mapping_sorted.keys())[:top_k]

    ids = list(map(lambda x: int(x.split("_")[0]), id_entries))
    labels = list(map(lambda x: int(x.split("_")[-1]), id_entries))
    return ids, labels
```

## 执行一次查询

有了所有这些工具函数，我们就具备做相似度检索的条件了。我们从 `beans` 数据集的 `test` 切分取一张查询图像：

```
test_idx = np.random.choice(len(dataset["test"]))
test_sample = dataset["test"][test_idx]["image"]
test_label = dataset["test"][test_idx]["labels"]

sim_ids, sim_labels = fetch_similar(test_sample)
print(f"Query label: {test_label}")
print(f"Top 5 candidate labels: {sim_labels}")
```

## 进一步扩展与结论

现在我们有了一个可用的图像相似度系统。但在现实中，你要处理的候选图像要多得多。考虑到这一点，当前的流程存在多个缺点：

- 如果原样存储嵌入，内存需求会迅速飙升，尤其是在处理数以百万计的候选图像时。在我们的例子中嵌入是 768 维的，在大规模场景下这仍然相对较高。
- 高维嵌入会直接影响检索部分后续计算的成本。

如果我们能在不破坏语义的前提下以某种方式降低嵌入的维度，就能在速度与检索质量之间保持良好的权衡。本文的配套 [Colab Notebook](https://colab.research.google.com/github/huggingface/notebooks/blob/main/examples/image_similarity.ipynb) 实现并演示了相关工具函数，展示了如何用随机投影（random projection）和局部敏感哈希（locality-sensitive hashing）达成这一点。

🤗 Datasets 与 [FAISS](https://github.com/facebookresearch/faiss) 有直接集成，这让构建相似度系统更加省心。假设你已经提取了候选图像（`beans` 数据集）的嵌入，并把它们存放在名为 `embeddings` 的特征列里。现在你可以轻松调用数据集的 [`add_faiss_index()`](https://huggingface.co/docs/datasets/v2.7.1/en/package_reference/main_classes#datasets.Dataset.add_faiss_index) 构建一个稠密索引：

```
dataset_with_embeddings.add_faiss_index(column="embeddings")
```

索引建好后，就可以用 `dataset_with_embeddings` 在给定查询嵌入时检索最近的样本，调用的是 [`get_nearest_examples()`](https://huggingface.co/docs/datasets/v2.7.1/en/package_reference/main_classes#datasets.Dataset.get_nearest_examples)：

```
scores, retrieved_examples = dataset_with_embeddings.get_nearest_examples(
    "embeddings", qi_embedding, k=top_k
)
```

该方法返回相似度分数和对应的候选样本。想了解更多，可以查看[官方文档](https://huggingface.co/docs/datasets/faiss_es)和[这份 notebook](https://colab.research.google.com/gist/sayakpaul/5b5b5a9deabd3c5d8cb5ef8c7b4bb536/image_similarity_faiss.ipynb)。
