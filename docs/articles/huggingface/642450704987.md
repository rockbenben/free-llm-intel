# 在 GCP 第五代 Xeon 上评测语言模型性能

本文由 Matrix Yao（MatrixYao，Intel）、Ke Ding（kding1，Intel）与 Ilyas Moutawwakil（IlyasMoutawwakil）撰写。

**TL;DR**：我们在两个基于 Xeon 的 Google Cloud Compute Engine CPU 实例——N2 和 C4——上，对 agentic AI 的两类代表性工作负载组件（文本 embedding 与文本生成）进行了基准测试。结果一致显示：在文本 embedding 上，C4 相对 N2 有 10 倍到 24 倍的吞吐提升；在文本生成上，C4 相对 N2 有 2.3 倍到 3.6 倍的吞吐提升。考虑价格因素，C4 的每小时价格约为 N2 的 1.3 倍；从这个意义上说，C4 在文本 embedding 上相对 N2 保持 7 倍到 19 倍的 TCO（总拥有成本）优势，在文本生成上有 1.7 倍到 2.9 倍的 TCO 优势。这些结果表明，完全基于 CPU 部署轻量级 Agentic AI 解决方案是可行的。

## 引言

人们相信人工智能的下一个前沿在于 agentic AI。新范式使用 `感知 - 推理 - 行动`（perceive - reason - action）流水线，将 LLM 精密的推理与迭代规划能力与强大的上下文理解增强相结合。上下文理解能力由向量数据库和传感器输入等工具提供，以构建更能感知上下文的 AI 系统，使其能够自主解决复杂的多步问题。此外，LLM 的函数调用（function calling）能力使 AI agent 能够直接采取行动，远远超越了聊天机器人所能提供的对话。Agentic AI 为各行业提升生产力与运营效率带来了令人振奋的前景。

人们正在把越来越多的工具引入 agentic AI 系统，而这些工具如今大多运行在 CPU 上，这带来一个隐忧：在该范式下会产生不可忽略的主机-加速器之间的流量开销。与此同时，模型构建者和厂商正在构建更小但强大的小语言模型（SLM），最新例子是 Meta 的 1B 和 3B llama3.2 模型，具备先进的多语言文本生成和工具调用能力。此外，CPU 也在演进，开始提供更强的 AI 支持：Intel 在其第四代 Xeon CPU 中引入了 Advanced Matrix Extensions（AMX）这一全新的 AI 张量加速器。把这三条线索放在一起，看看 CPU 承载整个 agentic AI 系统的潜力会很有意思，尤其是当它使用 SLM 时。

在本文中，我们将对 agentic AI 的两个代表性组件——文本 embedding 与文本生成——进行基准测试，并比较 CPU 在这两个组件上的代际性能提升。我们选取 Google Cloud Compute Engine 的 C4 实例与 N2 实例进行对比。背后的逻辑是：C4 由 [第五代 Intel Xeon 处理器](https://www.intel.com/content/www/us/en/products/docs/processors/xeon/5th-gen-xeon-scalable-processors.html)（代号 Emerald Rapids）驱动，是 Google Cloud 上最新一代 Xeon CPU，集成了 Intel AMX 以提升 AI 性能；而 N2 由 [第三代 Intel Xeon 处理器](https://www.intel.com/content/www/us/en/products/docs/processors/xeon-accelerated/3rd-gen-xeon-scalable-processors.html)（代号 Ice Lake）驱动，是 Google Cloud 上的上一代 Xeon CPU，只有 AVX-512 而没有 AMX。我们将展示 AMX 带来的收益。

我们使用 [`optimum-benchmark`](https://github.com/huggingface/optimum-benchmark)——Hugging Face 面向多后端、多设备的统一基准测试库——来测量性能。基准测试在 [`optimum-intel`](https://github.com/huggingface/optimum-intel) 后端上运行。`optimum-intel` 是 Hugging Face 的加速库，用于在 Intel 架构（CPU、GPU）上加速端到端流水线。我们的基准测试用例如下：

- 文本 embedding：使用 [`WhereIsAI/UAE-Large-V1`](https://huggingface.co/WhereIsAI/UAE-Large-V1) 模型，输入序列长度 128，batch size 从 1 扫到 128
- 文本生成：使用 [`meta-llama/Llama-3.2-3`](https://huggingface.co/meta-llama/Llama-3.2-3B) 模型，输入序列长度 256、输出序列长度 32，batch size 从 1 扫到 64

## 创建实例

### N2

访问 [Google Cloud 控制台](https://console.cloud.google.com/)，在你的项目下点击 `create a VM`。然后按以下步骤创建一个 96 vCPU 的单实例，对应一颗 Intel Ice Lake CPU 插槽。

- 在 `Machine configuration` 标签页选择 N2，并将 `Machine type` 指定为 `n2-standard-96`。然后需要按下图设置 `CPU platform`：[![alt text](https://huggingface.co/blog/assets/intel-gcp-c4/image-2.png)](https://huggingface.co/blog/assets/intel-gcp-c4/image-2.png)
- 按下图配置 `OS and storage` 标签页：[![alt text](https://huggingface.co/blog/assets/intel-gcp-c4/image-1.png)](https://huggingface.co/blog/assets/intel-gcp-c4/image-1.png)
- 其他配置保持默认
- 点击 `CREATE` 按钮

现在，你就有一个 N2 实例了。

## C4

按以下步骤创建一个 96 vCPU 实例，对应一颗 Intel Emerald Rapids 插槽。请注意，本文中 C4 与 N2 使用相同的 CPU 核心数，以确保等核数（iso-core-count）的公平基准测试。

- 在 `Machine configuration` 标签页选择 C4，并将 `Machine type` 指定为 `c4-standard-96`。你也可以设置 `CPU platform` 并开启全核 turbo（全核睿频），让性能更稳定：[![alt text](https://huggingface.co/blog/assets/intel-gcp-c4/image.png)](https://huggingface.co/blog/assets/intel-gcp-c4/image.png)
- `OS and storage` 的配置与 N2 相同
- 其他配置保持默认
- 点击 `CREATE` 按钮

现在，你就有一个 C4 实例了。

## 搭建环境

按以下步骤轻松搭建环境。为了可复现，我们在命令中列出所使用的版本与 commit。

- SSH 连接到实例
- `$ git clone https://github.com/huggingface/optimum-benchmark.git`
- `$ cd ./optimum-benchmark`
- `$ git checkout d58bb2582b872c25ab476fece19d4fa78e190673`
- `$ cd ./docker/cpu`
- `$ sudo docker build . -t <your_docker_image_tag>`
- `$ sudo docker run -it --rm --privileged -v /home/<your_home_folder>:/workspace <your_docker_image_tag> /bin/bash`

现在进入了容器，执行以下步骤：

- `$ pip install "optimum-intel[ipex]"@git+https://github.com/huggingface/optimum-intel.git@6a3b1ba5924b0b017b0b0f5de5b10adb77095b`
- `$ pip install torch==2.3.1 torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu`
- `$ python -m pip install intel-extension-for-pytorch==2.3.10`
- `$ cd /workspace/optimum-benchmark`
- `$ pip install .[ipex]`
- `$ export OMP_NUM_THREADS=48`
- `$ export KMP_AFFINITY=granularity=fine,compact,1,0`
- `$ export KMP_BLOCKTIME=1`
- `$ pip install huggingface-hub`
- `$ huggingface-cli login`，然后输入你的 Hugging Face token 以访问 llama 模型

## 基准测试

### 文本 embedding

你需要按以下方式更新 `optimum-benchmark` 目录中的 `examples/ipex_bert.yaml`，以 benchmark `WhereIsAI/UAE-Large-V1`。我们把 numa 绑定改为 `0,1`，因为 N2 和 C4 每个插槽都有 2 个 NUMA 域，你可以用 `lscpu` 复核。

```
--- a/examples/ipex_bert.yaml
+++ b/examples/ipex_bert.yaml
@@ -11,8 +11,8 @@ name: ipex_bert
 launcher:
   numactl: true
   numactl_kwargs:
-    cpunodebind: 0
-    membind: 0
+    cpunodebind: 0,1
+    membind: 0,1
 
 scenario:
   latency: true
@@ -26,4 +26,4 @@ backend:
   no_weights: false
   export: true
   torch_dtype: bfloat16
-  model: bert-base-uncased
+  model: WhereIsAI/UAE-Large-V1
```

然后运行基准测试：`$ optimum-benchmark --config-dir examples/ --config-name ipex_bert`

### 文本生成

你可以按以下方式更新 `examples/ipex_llama.yaml`，以 benchmark `meta-llama/Llama-3.2-3`。

```
--- a/examples/ipex_llama.yaml
+++ b/examples/ipex_llama.yaml
@@ -11,8 +11,8 @@ name: ipex_llama
 launcher:
   numactl: true
   numactl_kwargs:
-    cpunodebind: 0
-    membind: 0
+    cpunodebind: 0,1
+    membind: 0,1
 
 scenario:
   latency: true
@@ -34,4 +34,4 @@ backend:
   export: true
   no_weights: false
   torch_dtype: bfloat16
-  model: TinyLlama/TinyLlama-1.1B-Chat-v1.0
+  model: meta-llama/Llama-3.2-3B
```

然后运行基准测试：`$ optimum-benchmark --config-dir examples/ --config-name ipex_llama`

## 结果与结论

### 文本 embedding 结果

在文本 embedding 基准测试用例中，GCP C4 实例相对 N2 提供了大约 10 倍到 24 倍的吞吐提升。[![alt text](https://huggingface.co/blog/assets/intel-gcp-c4/embedding_throughput.png)](https://huggingface.co/blog/assets/intel-gcp-c4/embedding_throughput.png)

### 文本生成结果

同样，在文本生成基准测试中，C4 实例相对 N2 展示了大约 2.3 倍到 3.6 倍的吞吐提升。在 batch size 为 1 到 16 的范围内，吞吐提升可达 13 倍，同时不会显著牺牲延迟。这使得无需牺牲用户体验即可实现并发查询服务。[![alt text](https://huggingface.co/blog/assets/intel-gcp-c4/text_generation_perf.png)](https://huggingface.co/blog/assets/intel-gcp-c4/text_generation_perf.png)

### 结论

在本文中，我们对 Google Cloud Compute Engine CPU 实例 C4 与 N2 上的两类代表性 agentic AI 工作负载进行了基准测试。结果显示，得益于 Intel Xeon CPU 上的 AMX 和内存能力改进，性能提升显著。Intel 一个月前发布了 [Xeon 6 P-core 处理器](https://www.intel.com/content/www/us/en/products/details/processors/xeon/xeon6-product-brief.html)（代号 Granite Rapids），它在 Llama 3 上[提供了约 2 倍的性能提升](https://www.intel.com/content/www/us/en/developer/articles/technical/accelerate-meta-llama3-with-intel-ai-solutions.html)。我们相信，借助新一代 Granite Rapids CPU，可以探索完全在 CPU 上部署轻量级 Agentic AI 方案，以避免大量的主机-加速器流量开销。一旦 Google Cloud Compute Engine 上线 Granite Rapids 实例，我们将对其进行基准测试并报告结果。
