## 长篇大论；博士

NVIDIA Kumo Relational 是一种预先训练的关系基础模型，可直接对企业数据库进行预测。给定一个预测查询，它会收集多达 10,000 个历史示例作为上下文，并在一次前向传递中预测客户流失、需求或欺诈等结果。它不需要特定于任务的培训，不需要特征工程，也不需要表格扁平化。 Kumo Relational 是第一个在常见关系基准上优于监督机器学习的几次基础模型。在 15 个数据库上的 41 项任务中，它击败了有监督的关系深度学习模型和专家设计的梯度增强树管道，并且在 SAP SALT 企业基准上，它在平均倒数排名 (MRR) 方面超过了 AutoGluon 集成 8%。它可通过 NVIDIA 的开源 GPU 原生结构化数据模型库或作为 NVIDIA NIM 扩展到具有 500B+ 行的数据库，并适用于人类和代理。

## 向结构化数据基础模型的转变

基础模型已经重写了语言和视觉的剧本。不久前，生产型 NLP 意味着每个任务都有一个专用模型，每个模型都有自己的标记化、词形还原和 n 元语法管道。法学硕士使该堆栈在很大程度上变得过时，原因有三个：它们比最好的特定于任务的模型更准确，更容易投入生产，并且足够灵活，可以开启代理应用程序的新时代。

结构化数据现在也正在发生同样的转变。关系数据库为世界上最关键的业务决策提供支持，但对其进行预测建模仍然需要数周的特征工程、特定于任务的培训和调整管道。出于同样的三个原因，结构化数据基础模型改变了这一点：

**如今精度更高：** 作为直接替代品，这些模型已经击败了许多生产流程，尤其是 XGBoost。在 RelBench V1 分类任务中，Kumo Relational 在专家设计的特征上比梯度增强树平均高出近 4 个 AUROC 点。在 SAP SALT 上，它在工程功能方面比 XGBoost 领先 7 个 MRR 点（开箱即用），在微调后比 XGBoost 领先 13 个 MRR 点。这些结果为使用 Kumo Relational 替换生产 XGBoost 管道提供了令人信服的理由。

**简单性和敏捷性：** 一种预训练模型取代了各个任务的单独管道。新的预测变成了查询而不是项目，因此机器学习团队最终可以承担传统机器学习在组织的各个级别构建起来过于费力的用例。

**可以预测的代理：** LLM 允许代理进行读取、写入和推理。结构化数据基础模型让他们能够预测接下来会发生什么，例如哪个客户会流失，并采取行动。 Kumo Relational 已经构建为可供代理调用，其预测查询语言 (PQL) 为他们提供了一个简单的界面来询问预测问题。

今天，我们介绍 **Kumo Relational** （[论文](https://arxiv.org/abs/2604.12596)，[文档](https://docs.nvidia.com/sdgm/rfm/overview))，这是一种预先训练的基础模型，它将这种范式引入关系数据。连接数据库，描述要预测的内容，并在一次前向传递中获得预测。无需培训。

## Kumo 关系如何运作

大多数结构化数据的基础模型都在单个平面表上运行。相反，现实世界的数据存在于关系数据库中：用户连接到订单，连接到产品，所有这些都随着时间的推移而发展。通过手动聚合（*例如*，“过去 30 天的平均订单价值”）将这些关系扁平化为一行，会丢失细粒度的结构信号并需要大量的人力。

Kumo Relational 是一个“关系基础模型”，直接在数据库上运行，尊重其表、外键和时间戳。它在反映现实世界数据集的合成关系数据上进行了一次预训练，并通过*上下文学习*适应每个新任务，在推理时读取多达 10,000 个上下文示例。每个示例将某个时间点的实体周围的本地子图与其真实目标配对（*例如*，“该用户流失”或“该商品售出了 142 件”）。

![NVIDIA Kumo 关系系统概述：(a) 数据库集成，(b) 将自然语言转换为预测查询的提示界面，以及 (c) 自动生成上下文，为 NVIDIA Kumo 关系模型提供支持，该模型可横向扩展][![kumo-relational-architecture](https://cdn-uploads.huggingface.co/production/uploads/6ad8e88370f69967fafc8703/FY-lkW rNmBYRFrosRD2Le.png)](https://cdn-uploads.huggingface.co/production/uploads/6ad8e88370f69967fafc8703/FY-lkWrNmBYRFrosRD2Le.png)

为了进行预测，Kumo Relational 必须执行三件事：**(1)** 了解每个表中的值，**(2)** 跨表关联记录，以及 **(3)** 将具有已知目标的上下文示例与正在预测的实体关联起来。它的工作原理如下：

![Kumo 关系架构：(a) 包含任务、用户、订单和项目表的上下文输入； (b) 具有注入上下文目标的表中的列和行注意力； (c) 图注意力和跨样本注意力表。][![kumo-relational-system-overview](https://cdn-uploads.huggingface.co/production/uploads/6ad8e88370f69967fafc8703/OFX2a 7xwBTfUEcbedTsfe.png)](https://cdn-uploads.huggingface.co/production/uploads/6ad8e88370f69967fafc8703/OFX2a7xwBTfUEcbedTsfe.png)

*图 2.Kumo 关系架构：(a) 上下文输入，(b) 表内推理，(c) 跨表推理。*

**自动上下文生成：** 任务是用[预测查询语言 (PQL)](https://arxiv.org/abs/2602.09572) 编写的，这是一个声明性接口，您可以在其中说明要预测什么而不是如何预测。对于时态任务，Kumo Relational 会重播历史数据库状态：它对以实体为中心的子图进行采样，直到锚点时间戳，并根据该时间戳之后的事件计算每个目标，同时仅向模型提供之前的数据。这可以防止数据泄露。

**表内推理：** 轻量级网络独立处理每个表，交替列注意力（关联列内的值）和行注意力（关联行内的特征）。该模型了解哪些列和行对当前预测很重要，并在噪声传播之前过滤掉噪声。

**跨表推理：** 更大的网络通过主键/外键关系上的图注意力，与跨上下文示例的跨样本注意力交错，将行嵌入分布在关系结构中。这就是关系推理发生的地方，例如将用户的个人资料链接到他们的交易历史记录。由于此阶段适用于行嵌入而不是每个表中的每个单元格，因此该设计避免了二次成本并扩展到大型上下文和更深的子图。

## Kumo 关系是如何构建的

Kumo Relational 经过模拟的完全合成关系数据进行预训练，以反映具有各种预测查询的现实世界关系数据库。预训练分阶段进行，从单一表到日益复杂的关系结构。

预训练所需的各种关系数据库很少是公开的，因此合成数据填补了这一空白。 Kumo Relational 的生成器基于 [PluRel](https://arxiv.org/abs/2602.04029)（Kothapalli 等人，ICML 2026）的方法构建，该方法将单表数据生成器扩展到完整的关系数据库。 Kumo 团队的成员帮助开发了 PluRel 并共同撰写了原始论文。 PluRel 分三个阶段生成每个数据库：模式、像在实际数据中那样聚集的行之间的外键链接，以及来自具有时间趋势和跨表依赖性的结构因果模型的列值。生成是轻量级的，因此预训练数据实际上是无限的，PluRel 论文表明，随着合成数据库的添加，预训练损失遵循幂律，收益会延续到真实数据库。

通过这种预训练，模型学会跨表过滤、关联和聚合信息，而不是依赖固定的聚合。当最大精度很重要时，Kumo Relational 还可以针对特定数据集和任务进行微调。

＃＃ 表现

在本文中，我们根据来自 RelBench V1 和 V2、SAP SALT 和 4DBInfer 的 15 个关系数据库的 41 个基准测试对 Kumo Relational 进行了评估，涵盖电子商务、医疗、企业、社交和学术领域。在预训练中没有看到这些数据集。 Kumo Relational 在分类和回归方面都优于最强的监督模型，包括关系深度学习模型和专家设计的表格集成。在 [RelArena-α](https://arxiv.org/abs/2608.16319) 排行榜上，该排行榜比较了 RelBench V1 上的关系模型和系统，它也位于开箱即用的准确率-效率 Pareto 前面：

![RelArena-α 排行榜的散点图：跨任务的 Elo 相对准确度（y 轴）与每 1,000 个样本的中位推理时间（x 轴，对数刻度）。 Kumo Relational 位于 Pareto 前沿，大约为 17 秒，Elo 为 1,842。得分最高的条目 rt-plurel 在大约 7,300 秒时达到 Elo 1,878，大约慢了 430 倍。所有其他基础模型、特征工程系统和监督模型的得分均低于 Kumo，且运行速度较慢关系。][![relarena-alpha-leaderboard](https://cdn-uploads.huggingface.co/production/uploads/6ad8e88370f69967fafc8703/9ITlu bGvqGVnoy7j_NZDi.png)](https://cdn-uploads.huggingface.co/production/uploads/6ad8e88370f69967fafc8703/9ITlubGvqGVnoy7j_NZDi.png)

该论文还报告称，在 SAP SALT 企业基准测试中，Kumo Relational 在平均倒数排名 (MRR) 方面超过大型 AutoGluon 集成 8%，最近的表格基础模型超过约 25%，并且微调将其对 AutoGluon 的领先优势扩大到 16%。它在困难条件下也能正常工作：只需 0.2% 的训练数据作为上下文即可表现良好，在删除多达 75% 的外键链接时保持稳定，并且在添加许多噪声列时几乎不会降级。

## 限制

Kumo Relational 在具有有意义的关系和时间动态（例如随时间变化的用户行为）的数据上表现最佳。在训练集非常大的任务中，特定于任务的监督模型可能仍会优于上下文预测，后者在我们的基准测试中最多使用 10,000 个上下文示例。基础模型的微调正是针对这种情况而设计的。预测信号还必须在有限的跳数内可达，因此首先对一些相关表进行集中查询，并根据需要扩展图表。

## 演示

Kumo Relational 在数据库上本地运行上下文学习：在内存中，通过数据库和仓库连接器，或通过自定义图形引擎，通过内存映射 I/O 以高达 5 GB/s 的速度处理 500B+ 行。它可在 NVIDIA 新发布的 GPU 原生结构化数据模型库中找到，该库也是为我们的姊妹模型 [Kumo Tabular](https://huggingface.co/blog/nvidia/kumo-tabular) 提供支持的开源库。该库在首次使用时从 Hugging Face Hub 下载权重，因此您可以将模型加载到支持 GPU 的笔记本中并直接从中进行预测。下面的代码将上下文示例、预测实体及其相关表传递给模型：
```
# pip install structured-data-models
import sdm

model = sdm.models.KumoRelational(device="cuda")
pred = model(
    # In-context training table (fkeys/timestamps/targets):
    x_context=...,
    y_context=...,
    # Prediction examples (fkeys/timestamps):
    x_query=...,
    # Multi-table information for context/prediction entities:
    related_context_tables=...,
    related_query_tables=...,
)
```
有关完整的 RelBench 和 SAP SALT 管道，包括如何对每个实体的相关表进行采样，请参阅库的[关系示例](https://github.com/NVIDIA/structured-data-models/tree/main/examples/relational)。

要将模型作为单独的服务运行，请将其部署为 NVIDIA NIM，并从笔记本中将开源 [结构化数据模型客户端](https://github.com/NVIDIA/structured-data-models-client) 指向它。您用 PQL 编写预测，客户端收集上下文示例和相关表，然后发送请求：
```
# pip install 'structured-data-models-client[relational]'
import sdm_client

client = sdm_client.SDMClient(url="http://localhost:8001")  # NIM URL
query = sdm_client.PredictiveQuery(
    # Prediction task in Predictive Query Language (PQL):
    "PREDICT COUNT(orders.*, 0, 30, days) FOR EACH users.user_id",
    # Multi-table data as pandas DataFrames (keys/links inferred):
    {"users": ..., "orders": ...},
)
pred = client.predict(
    # Context examples and related tables for the entities to predict:
    query.materialize(indices=[1, 2, 3]),
    model=sdm_client.KumoRelational(),
)
```
请参阅客户端的[示例笔记本](https://github.com/NVIDIA/structured-data-models-client/tree/main/examples)，了解针对本地 NIM 和 Databricks 的端到端运行。
