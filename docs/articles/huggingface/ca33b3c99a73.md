# 如何生成文本：用 Transformers 的多种解码方法做语言生成

作者：Patrick von Platen（patrickvonplaten）

## 引言

近年来，得益于在数百万网页上训练的大规模 transformer 语言模型——包括 OpenAI 的 [ChatGPT](https://openai.com/blog/chatgpt) 和 Meta 的 [LLaMA](https://ai.meta.com/blog/large-language-model-llama-meta-ai/)——人们对开放式语言生成的兴趣与日俱增。条件式开放式语言生成的成果令人印象深刻：模型已被证明能[泛化到新任务](https://ai.googleblog.com/2021/10/introducing-flan-more-generalizable.html)、[处理代码](https://huggingface.co/blog/starcoder)，甚至[以非文本数据为输入](https://openai.com/research/whisper)。除了更好的 transformer 架构和海量的无监督训练数据，**更好的解码方法**也功不可没。

这篇博客简要概览不同的解码策略，更重要的是展示*你*如何用流行的 `transformers` 库毫不费力地实现它们！

以下所有功能都用于**自回归（auto-regressive）**语言生成（[复习链接](http://jalammar.github.io/illustrated-gpt2/)）。简单说，*自回归*语言生成的假设是：一个词序列的概率分布可以分解为一系列条件下一词分布的乘积：

P(w1:T∣W0)=∏t=1TP(wt∣w1:t−1,W0) ,with w1:0=∅, P(w_{1:T} | W_0 ) = \prod_{t=1}^T P(w_{t} | w_{1: t-1}, W_0) \text{ ,with } w_{1: 0} = \emptyset, P(w1:T​∣W0​)=t=1∏T​P(wt​∣w1:t−1​,W0​) ,with w1:0​=∅,

其中 W0W_0W0​ 是初始*上下文*词序列。词序列的长度 TTT 通常是*即时（on-the-fly）*确定的，对应于从 P(wt∣w1:t−1,W0)P(w_{t} | w_{1: t-1}, W_{0})P(wt​∣w1:t−1​,W0​) 生成 EOS token 的时间步 t=Tt=Tt=T。

我们将巡礼当前最主要的解码方法，主要是*贪心搜索（Greedy search）*、*束搜索（Beam search）*和*采样（Sampling）*。

我们快速安装 transformers 并加载模型。演示使用 PyTorch 版的 GPT2，但这套 API 在 TensorFlow 和 JAX 上完全一致。


```
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

torch_device = "cuda" if torch.cuda.is_available() else "cpu"

tokenizer = AutoTokenizer.from_pretrained("gpt2")

# add the EOS token as PAD token to avoid warnings
model = AutoModelForCausalLM.from_pretrained("gpt2", pad_token_id=tokenizer.eos_token_id).to(torch_device)
```

## 贪心搜索

贪心搜索是最简单的解码方法：每个时间步 ttt，都把概率最高的词选为下一个词：wt=argmaxwP(w∣w1:t−1)w_t = argmax_{w}P(w | w_{1:t-1})wt​=argmaxw​P(w∣w1:t−1​)。下面的示意图展示了贪心搜索的过程。

从单词 "The"\text{"The"}"The" 出发，算法贪心地选下下一个最高概率的词 "nice"\text{"nice"}"nice"，依此类推，最终生成的词序列是 ("The","nice","woman")(\text{"The"}, \text{"nice"}, \text{"woman"})("The","nice","woman")，总概率为 0.5×0.4=0.20.5 \times 0.4 = 0.20.5×0.4=0.2。

下面我们以 ("I","enjoy","walking","with","my","cute","dog")(\text{"I"}, \text{"enjoy"}, \text{"walking"}, \text{"with"}, \text{"my"}, \text{"cute"}, \text{"dog"})("I","enjoy","walking","with","my","cute","dog") 为上下文，用 GPT2 生成词序列。看看贪心搜索在 `transformers` 里怎么用：

```
# encode context the generation is conditioned on
model_inputs = tokenizer('I enjoy walking with my cute dog', return_tensors='pt').to(torch_device)

# generate 40 new tokens
greedy_output = model.generate(**model_inputs, max_new_tokens=40)

print("Output:\n" + 100 * '-')
print(tokenizer.decode(greedy_output[0], skip_special_tokens=True))
```

```
Output:
----------------------------------------------------------------------------------------------------
I enjoy walking with my cute dog, but I'm not sure if I'll ever be able to walk with my dog. I'm not sure if I'll ever be able to walk with my dog.

I'm not sure
```

好！我们用 GPT2 生成了第一段文本 😊。紧跟上下文的生成词还算合理，但模型很快就开始自我重复！这在语言生成中是一个非常常见的问题，在贪心和束搜索中似乎更明显——可参考 [Vijayakumar et al., 2016](https://arxiv.org/abs/1610.02424) 和 [Shao et al., 2017](https://arxiv.org/abs/1701.03185)。

不过贪心搜索最大的缺点是：高概率词如果藏在一个低概率词后面，就会被错过，上面示意图里就能看到这一点：

高条件概率 0.90.90.9 的词 "has"\text{"has"}"has" 藏在只有第二高条件概率的词 "dog"\text{"dog"}"dog" 后面，于是贪心搜索错失了序列 "The","dog","has"\text{"The"}, \text{"dog"}, \text{"has"}"The","dog","has"。

幸好，我们有束搜索来缓解这个问题！

## 束搜索

束搜索（Beam search）通过在每个时间步保留最可能的 `num_beams` 条假设、最终选择总体概率最高的那条，来降低错过隐藏高概率词序列的风险。以 `num_beams=2` 为例：

在时间步 1，除了最可能的假设 ("The","nice")(\text{"The"}, \text{"nice"})("The","nice")，束搜索还保留第二可能的 ("The","dog")(\text{"The"}, \text{"dog"})("The","dog")。在时间步 2，束搜索发现序列 ("The","dog","has")(\text{"The"}, \text{"dog"}, \text{"has"})("The","dog","has") 的概率 0.360.360.36 高于 ("The","nice","woman")(\text{"The"}, \text{"nice"}, \text{"woman"})("The","nice","woman") 的 0.20.20.2。很好，在我们的玩具例子里它找到了最可能的词序列！

束搜索总能找到比贪心搜索概率更高的输出序列，但也不保证找到最可能的输出。

看看束搜索在 `transformers` 中怎么用。我们设置 `num_beams > 1` 和 `early_stopping=True`，让所有束假设都到达 EOS token 时结束生成。

```
# activate beam search and early_stopping
beam_output = model.generate(
    **model_inputs,
    max_new_tokens=40,
    num_beams=5,
    early_stopping=True
)

print("Output:\n" + 100 * '-')
print(tokenizer.decode(beam_output[0], skip_special_tokens=True))
```

```
Output:
----------------------------------------------------------------------------------------------------
I enjoy walking with my cute dog, but I'm not sure if I'll ever be able to walk with him again.

I'm not sure if I'll ever be able to walk with him again. I'm not sure
```

虽然结果可以说更流畅了，但输出仍然包含相同词序列的重复。可选的解法之一是引入 *n-gram*（即 n 个词组成的词序列）惩罚，参考 [Paulus et al. (2017)](https://arxiv.org/abs/1705.04304) 和 [Klein et al. (2017)](https://arxiv.org/abs/1701.02810)。最常见的 *n-gram* 惩罚确保任何 *n-gram* 不出现两次：手工把可能构成已见过 *n-gram* 的下一个词的概率设为 0。

我们试试设置 `no_repeat_ngram_size=2`，让任何 *2-gram* 不出现两次：

```
# set no_repeat_ngram_size to 2
beam_output = model.generate(
    **model_inputs,
    max_new_tokens=40,
    num_beams=5,
    no_repeat_ngram_size=2,
    early_stopping=True
)

print("Output:\n" + 100 * '-')
print(tokenizer.decode(beam_output[0], skip_special_tokens=True))
```

```
Output:
----------------------------------------------------------------------------------------------------
I enjoy walking with my cute dog, but I'm not sure if I'll ever be able to walk with him again.

I've been thinking about this for a while now, and I think it's time for me to
```

不错，看起来好多了！可以看到重复消失了。不过 *n-gram* 惩罚要谨慎使用：如果生成一篇关于 *New York* 这座城市的故事却用了 *2-gram* 惩罚，城市名可能全文只会出现一次！

束搜索另一个重要特性是：生成后可以比较得分最高的几条束，挑选最符合需求的输出束。

在 `transformers` 中，只需把参数 `num_return_sequences` 设为要返回的最高分束的数量。注意要保证 `num_return_sequences <= num_beams`！

```
# set return_num_sequences > 1
beam_outputs = model.generate(
    **model_inputs,
    max_new_tokens=40,
    num_beams=5,
    no_repeat_ngram_size=2,
    num_return_sequences=5,
    early_stopping=True
)

# now we have 3 output sequences
print("Output:\n" + 100 * '-')
for i, beam_output in enumerate(beam_outputs):
  print("{}: {}".format(i, tokenizer.decode(beam_output, skip_special_tokens=True)))
```

可以看到，五条束假设彼此只有细微差异——只用 5 条束时这也不奇怪。

对于开放式生成，人们提出了若干理由说明束搜索可能不是最优选择：

- 在目标生成长度大致可预测的任务里——如机器翻译或摘要——束搜索非常有效，见 [Murray et al. (2018)](https://arxiv.org/abs/1808.10006) 和 [Yang et al. (2018)](https://arxiv.org/abs/1808.09582)。但开放式生成并非如此，其目标输出长度变化很大，例如对话和故事生成。
- 我们已经看到束搜索严重受制于重复生成。在故事生成中尤其难以用 *n-gram* 或其他惩罚来控制：在"抑制重复"和"陷入相同 *n-gram* 循环"之间找到好的平衡需要大量调参。
- 正如 [Ari Holtzman et al. (2019)](https://arxiv.org/abs/1904.09751) 所论证的，高质量的人类语言并不遵循"高概率下一词"的分布。换句话说，作为人类，我们希望生成的文本给我们惊喜，而不是无聊/可预测。作者们用一个漂亮的图展示了这一点：模型赋予人类文本的概率 vs 束搜索的输出。

## 采样

最基本的形式下，采样就是按照下一词的条件概率分布随机抽取 wtw_twt​：

wt∼P(w∣w1:t−1) w_t \sim P(w|w_{1:t-1}) wt​∼P(w∣w1:t−1​)

沿用上面的例子，下图展示了采样时的语言生成。

显然，用采样做语言生成不再*确定*了。词 ("car")(\text{"car"})("car") 从条件分布 P(w∣"The")P(w | \text{"The"})P(w∣"The") 中抽出，随后 ("drives")(\text{"drives"})("drives") 从 P(w∣"The","car")P(w | \text{"The"}, \text{"car"})P(w∣"The","car") 中抽出。

在 `transformers` 中，我们设置 `do_sample=True`，并通过 `top_k=0` 关闭 *Top-K* 采样（稍后详述）。下面为了演示方便固定了随机种子。你可以随意更改 `set_seed` 参数得到不同结果，或干脆删掉它以获得非确定性输出。

```
# set seed to reproduce results. Feel free to change the seed though to get different results
from transformers import set_seed
set_seed(42)

# activate sampling and deactivate top_k by setting top_k sampling to 0
sample_output = model.generate(
    **model_inputs,
    max_new_tokens=40,
    do_sample=True,
    top_k=0
)

print("Output:\n" + 100 * '-')
print(tokenizer.decode(sample_output[0], skip_special_tokens=True))
```

```
Output:
----------------------------------------------------------------------------------------------------
I enjoy walking with my cute dog for the rest of the day, but this had me staying in an unusual room and not going on nights out with friends (which will always be wondered for a mere minute or so at this point).
```

有意思！文本看起来还行——但仔细一看，并不太连贯，也不像人写的。这就是采样词序列的大问题：模型经常生成语无伦次的胡话，*cf.* [Ari Holtzman et al. (2019)](https://arxiv.org/abs/1904.09751)。

一个技巧是让分布 P(w∣w1:t−1)P(w|w_{1:t-1})P(w∣w1:t−1​) 更"陡峭"（提高高概率词的可能性、压低低概率词的可能性），方法是调低 [softmax](https://en.wikipedia.org/wiki/Softmax_function#Smooth_arg_max) 的所谓 `temperature`（温度）。

把温度应用到上面例子的效果如下图所示。

t=1t=1t=1 步的条件下一词分布变得更加陡峭，词 ("car")(\text{"car"})("car") 几乎不可能被选中。

我们看看在库里如何通过设置 `temperature=0.6` 给分布"降温"：

```
# set seed to reproduce results. Feel free to change the seed though to get different results
set_seed(42)

# use temperature to decrease the sensitivity to low probability candidates
sample_output = model.generate(
    **model_inputs,
    max_new_tokens=40,
    do_sample=True,
    top_k=0,
    temperature=0.6,
)

print("Output:\n" + 100 * '-')
print(tokenizer.decode(sample_output[0], skip_special_tokens=True))
```

```
Output:
----------------------------------------------------------------------------------------------------
I enjoy walking with my cute dog, but I don't like to chew on it. I like to eat it and not chew on it. I like to be able to walk with my dog."

So how did you decide
```

好一些了。奇怪的 n-gram 变少了，输出也更连贯了一点！虽然调温度可以让随机性变小，但在极限情况下——把 `temperature` 设为 →0\to 0→0——温度缩放采样就等价于贪心解码，会遭遇之前同样的问题。

### Top-K 采样

[Fan et. al (2018)](https://arxiv.org/pdf/1805.04833.pdf) 提出了一种简单但非常强大的采样方案，叫 ***Top-K*** 采样。*Top-K* 采样先过滤出最可能的 *K* 个下一词，然后把概率质量只重新分配到这 *K* 个词上。GPT2 采用了这种采样方案，这也是它在故事生成上成功的原因之一。

我们把上面例子两个采样步涉及的词范围从 3 个词扩展到 10 个词，以便更好地演示 *Top-K* 采样。

设定 K=6K = 6K=6 后，两个采样步都把采样池限制在 6 个词内。虽然在第一步，6 个最可能的词（记作 Vtop-KV_{\text{top-K}}Vtop-K​）只占整体概率质量的大约三分之二，但在第二步它几乎包含了全部概率质量。尽管如此，我们看到它成功消除了第二步中相当奇怪的候选词 (“not",“the",“small",“told")(\text{``not"}, \text{``the"}, \text{``small"}, \text{``told"})(“not",“the",“small",“told")。

看看在库里如何通过 `top_k=50` 使用 *Top-K*：

```
# set seed to reproduce results. Feel free to change the seed though to get different results
set_seed(42)

# set top_k to 50
sample_output = model.generate(
    **model_inputs,
    max_new_tokens=40,
    do_sample=True,
    top_k=50
)

print("Output:\n" + 100 * '-')
print(tokenizer.decode(sample_output[0], skip_special_tokens=True))
```

```
Output:
----------------------------------------------------------------------------------------------------
I enjoy walking with my cute dog for the rest of the day, but this time it was hard for me to figure out what to do with it. (One reason I asked this for a few months back is that I had a
```

相当不错！这段文本可以说是目前为止最"像人写的"。不过 *Top-K* 采样有个隐患：它不会根据下一词的概率分布 P(w∣w1:t−1)P(w|w_{1:t-1})P(w∣w1:t−1​) 动态调整被过滤的词数。这可能成问题：有些词可能来自一个非常陡峭的分布（上图中右侧的分布），另一些则来自更平坦的分布（上图左侧）。

在 t=1t=1t=1 步，*Top-K* 排除了采样 ("people","big","house","cat")(\text{"people"}, \text{"big"}, \text{"house"}, \text{"cat"})("people","big","house","cat") 的可能，而这些看起来是合理的候选；而在 t=2t=2t=2 步，方法却把明显不合适的词 ("down","a")(\text{"down"}, \text{"a"})("down","a") 留在了采样池里。因此，把采样池限制为固定大小 *K*，对陡峭分布可能让模型滑向胡话，对平坦分布则会限制模型的创造力。这个直觉让 [Ari Holtzman et al. (2019)](https://arxiv.org/abs/1904.09751) 提出了 ***Top-p*** 或 ***nucleus*（核）采样**。

### Top-p（核）采样

*Top-p* 采样不是只从最可能的 *K* 个词里采样，而是选择累计概率超过 *p* 的**最小**词集合进行采样，然后把概率质量在这个集合内重新分配。这样，词集合的大小（即集合中的词数）可以随下一词的概率分布动态增大或缩小。好，上面太绕了，看图。

设定 p=0.92p=0.92p=0.92 后，*Top-p* 采样挑选累计概率达到 p=92%p=92\%p=92% 所需的*最少*词数，记作 Vtop-pV_{\text{top-p}}Vtop-p​。第一个例子中它纳入了 9 个最可能的词，而第二个例子只需要前 3 个词就能超过 92%。其实挺简单！可以看到：当下一个词较难预测时（如 P(w∣"The”)P(w | \text{"The''})P(w∣"The”)）它保留较宽的词范围，而下一个词似乎更好预测时（如 P(w∣"The","car")P(w | \text{"The"}, \text{"car"})P(w∣"The","car")）只保留少数几个词。

好，到 `transformers` 里试试！通过设置 `0 < top_p < 1` 启用 *Top-p* 采样：

```
# set seed to reproduce results. Feel free to change the seed though to get different results
set_seed(42)

# set top_k to 50
sample_output = model.generate(
    **model_inputs,
    max_new_tokens=40,
    do_sample=True,
    top_p=0.92,
    top_k=0
)

print("Output:\n" + 100 * '-')
print(tokenizer.decode(sample_output[0], skip_special_tokens=True))
```

```
Output:
----------------------------------------------------------------------------------------------------

```

很好，这段听起来可以是人写的。嗯，也许还差一点。

虽然从理论上 *Top-p* 比 *Top-K* 更优雅，但两种方法在实践中都不错。*Top-p* 也可以与 *Top-K* 组合使用，从而既避开排名很低的词，又保留一定的动态选择。

最后，要获得多个独立采样的输出，我们可以*再次*设置参数 `num_return_sequences > 1`：

```

```

好，现在你已经有全部工具，可以让模型用 `transformers` 替你写故事了！

## 结论

作为一种临时（*ad-hoc*）解码方法，*top-p* 和 *top-K* 采样在开放式语言生成上似乎比传统的*贪心*搜索和*束*搜索产出更流畅的文本。有证据表明，*贪心*和*束*搜索的明显缺陷——主要生成重复词序列——根源在模型（尤其是模型的训练方式）而非解码方法本身，*cf.* [Welleck et al. (2019)](https://arxiv.org/pdf/1908.04319.pdf)。此外，[Welleck et al. (2020)](https://arxiv.org/abs/2002.02492) 表明 *top-K* 和 *top-p* 采样同样存在生成重复词序列的问题。

[Welleck et al. (2019)](https://arxiv.org/pdf/1908.04319.pdf) 显示，根据人工评估，在调整模型训练目标后，*束*搜索可以比 *Top-p* 采样生成更流畅的文本。

开放式语言生成是一个快速演进的研究领域，而且正如常常的那样，这里没有放之四海而皆准的方法——你得看在自己的具体用例中什么最有效。

好消息是*你*可以在 `transformers` 里尝试所有不同的解码方法 🤗——可用方法的总览在[这里](https://huggingface.co/docs/transformers/generation_strategies#decoding-strategies)。
