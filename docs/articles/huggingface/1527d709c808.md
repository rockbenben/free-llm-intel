## 引言

过去几年，Transformer 推动了 AI 的非凡进步——从具备类人推理能力的语言模型，到同时理解图像与文本的多模态系统。然而在真实机器人领域，进步要慢得多。机器人在多样的物体、环境和任务之间仍然难以泛化。这种有限的进展，源于**高质量多样数据的缺乏**，以及缺少能在物理世界中**像人一样推理和行动**的模型。

为应对这些挑战，学界近来转向**视觉-语言-动作（VLA）模型**——在单一架构内统一感知、语言理解和动作预测。VLA 通常以原始视觉观测和自然语言指令为输入，输出相应的机器人动作。前景虽然可观，但 VLA 的许多最新进展仍锁在专有模型和大规模私有数据集之后，往往需要昂贵的硬件配置和大量工程资源。整个机器人研究社区要在这些模型之上复现和再创新，门槛很高。

SmolVLA 正是为补上这一空白而生：一个开源、紧凑、高效的 VLA 模型，**只需公开数据集、在消费级硬件上即可训练**。我们不仅释出模型权重，还配合非常平价的开源硬件，SmolVLA 旨在让视觉-语言-动作模型人人可及，加速通向通才机器人智能体的研究。

## 认识 SmolVLA！

**SmolVLA-450M** 是我们的开源 VLA 模型，小而能干。它是：

- 小到能在 CPU 上跑、在单张消费级 GPU 上训练，甚至一台 MacBook 也行！
- 在公开、社区共享的机器人数据上训练
- 随附完整的训练与推理配方发布
- 可以在非常平价的硬件（SO-100、SO-101、LeKiwi 等）上测试和部署

受大语言模型（LLM）训练范式的启发，SmolVLA 先在通用操作数据上预训练，再进行任务特定的后训练。架构上，它把 Transformer 与**流匹配（flow-matching）解码器**结合，并为速度与低延迟推理做了如下设计：

- 跳过视觉模型一半的层，以获得更快推理和更小体积
- 自注意力与交叉注意力块交错排布
- 使用更少的视觉 token
- 利用更小的预训练 VLM

尽管训练集不到 3 万个 episode——比其它 VLA 少一个数量级——SmolVLA 在仿真和真实世界中**追平甚至超过**了大得多的模型。

为了让实时机器人更好用，我们引入了异步推理技术栈。这项技术把机器人"执行动作"与"理解所见所闻"解耦。正因为解耦，机器人在快速变化的环境中能更快响应。

## 🚀 如何使用 SmolVLA？

SmolVLA 的易用与易集成是设计目标——无论你是用自己的数据微调，还是把它接进现有机器人技术栈。

### 安装

首先安装依赖：

```
git clone https://github.com/huggingface/lerobot.git
cd lerobot
pip install -e ".[smolvla]"
```

### 微调预训练模型

使用 [`smolvla_base`](https://hf.co/lerobot/smolvla_base)——我们预训练的 450M 模型——配合 lerobot 训练框架：

```
python lerobot/scripts/train.py \
  --policy.path=lerobot/smolvla_base \
  --dataset.repo_id=lerobot/svla_so100_stacking \
  --batch_size=64 \
  --steps=20000  # 10% of training budget
```

### 从头训练

如果你想从架构（预训练 VLM + 动作专家）开始构建，而不是用预训练检查点：

```
python lerobot/scripts/train.py \
  --policy.type=smolvla \
  --dataset.repo_id=lerobot/svla_so100_stacking \
  --batch_size=64 \
  --steps=200000
```

也可以直接加载 `SmolVLAPolicy`：

```
from lerobot.common.policies.smolvla.modeling_smolvla import SmolVLAPolicy
policy = SmolVLAPolicy.from_pretrained("lerobot/smolvla_base")
```

## 方法

SmolVLA 不只是一个轻量能干的模型，也是一套训练与评估通才机器人策略的方法。本节介绍 SmolVLA 背后的*模型架构*，以及用于评估的*异步推理*设置——事实证明它更适应环境、恢复得更快。

SmolVLA 由两个核心组件构成：处理多模态输入的**视觉-语言模型（VLM）**，和输出机器人控制指令的**动作专家（action expert）**。下面分享 SmolVLA 架构主要组件与异步推理的细节。更多内容见我们的[技术报告](https://huggingface.co/papers/2506.01844)。

### 总体架构

#### 视觉-语言模型（VLM）

我们用 [SmolVLM2](https://huggingface.co/HuggingFaceTB/SmolVLM2-500M-Video-Instruct) 作为 VLM 主干。它针对多图输入优化，由 SigLIP 视觉编码器和 [SmolLM2](https://huggingface.co/HuggingFaceTB/SmolLM2-1.7B-Instruct) 语言解码器组成。

- **图像 token** 由视觉编码器提取
- **语言指令**经分词后直接送入解码器。
- **传感-运动状态**用一个线性层投影为单个 token，以对齐语言模型的 token 维度。

解码器层处理拼接后的图像、语言和状态 token。产出的特征再传给动作专家。

#### 动作专家：流匹配 Transformer

SmolVLA 的**动作专家**是一个紧凑的 transformer（约 1 亿参数），在 VLM 输出的条件下生成动作块（action chunks）——即未来的机器人动作序列。它用**流匹配（flow matching）目标**训练：教模型把带噪样本引导回真实值。相比之下，离散动作表示（例如通过 token 化）虽然强大，却常需要自回归解码——推理时又慢又低效。而流匹配允许**直接、非自回归地预测连续动作**，实现高精度的实时控制。

更直观地说：训练时，我们给机器人的真实动作序列加随机噪声，再让模型预测把它们带回正确轨迹的"校正向量"。这在动作空间上形成一个平滑的向量场，帮助模型学到准确稳定的控制策略。

我们用一个带**交错注意力块**（见图 2）的 transformer 架构实现它，并把它隐藏维度压到 **VLM 的 75%**，让模型保持轻巧、便于部署。

### 效率与鲁棒性的设计选择

把视觉-语言模型和动作预测模块结合，是 Pi0、GR00T、Diffusion Policy 等近期 VLA 系统的常见设计——而我们找到了若干能显著提升鲁棒性与性能的架构选择。在 SmolVLA 中，我们应用三项关键技术：**减少视觉 token 数量、跳过 VLM 上层**，以及在动作专家中**交错交叉注意力与自注意力层**。

#### 视觉 token 缩减

高分辨率图像有利于感知，但会显著拖慢推理。为取得平衡，**SmolVLA 在训练和推理时都把视觉 token 限制在每帧 64 个**。例如一张 512×512 的图像，通过高效的 PixelShuffle  technique 被压缩成区区 64 个 token，**而不是 1024 个**。底层视觉-语言模型（VLM）最初为更广的覆盖用图像分块（tiling）预训练，而 **SmolVLA 运行时只用全局图像**，让推理保持轻量快速。

#### 跳层加速推理

与其总是依赖 VLM 的最后一层——代价高、有时还不是最优——我们改用**中间层的特征**。已有工作表明，早期层往往对下游任务提供更好的表示。在 SmolVLA 中，动作专家在训练时只注意 VLM 到可配置层 N 为止的特征，取**总层数的一半**。这使 VLM 和动作专家的计算开销都**减半**，推理大幅加速而性能几乎不降。

#### 交叉注意力与自注意力交错

在动作专家内部，注意力层交替进行：

- **交叉注意力（CA）**：动作 token 注意 VLM 的特征
- **自注意力（SA）**：动作 token 彼此注意（因果式——只看过去）

我们发现这种**交错设计**比堆完整的注意力块更轻也更有效。只用 CA 或只用 SA 的模型，往往在流畅度和落地性（grounding）之间顾此失彼。

在 SmolVLA 中，CA 确保动作良好地基于感知与指令，SA 则提升**时间平滑性**——这对真实控制尤为关键，抖动的预测会导致不安全、不稳定的行为。

## 异步推理

图 3. 异步推理。异步推理技术栈示意。注意策略可以运行在远程服务器上，那里可以配 GPU。

现代的视觉-运动策略输出**动作块**——待执行的动作序列。管理它们有两种方式：

- **同步（sync）：** 机器人执行完一块，暂停，等下一块算完。简单，但会造成一段无法响应新输入的延迟。
- **异步（async）：** 在执行当前块的同时，机器人已把最新观测发给 **Policy Server**（可能挂在 GPU 上）去算下一块。这消除了空闲时间，提升了响应性。

我们的异步栈把动作执行与动作块预测解耦，带来更高的适应性，并在运行时完全消除执行卡顿。它依赖以下关键机制：

- **1. 提前触发：** 当队列长度低于阈值（例如 70%）时，向 **Policy Server** 发送观测，请求新的动作块。
- **2. 线程解耦：** 控制循环持续执行 → 推理并行进行（非阻塞）。
- **3. 块融合：** 相邻动作块重叠的动作按简单合并规则拼接，避免抖动。

我们非常激动能发布异步推理——它在不改动模型的前提下，保证更高的适应性和更好的性能。简言之，异步推理让执行与远程预测重叠，使机器人始终保持响应。

## 社区数据集

视觉与语言模型受益于 LAION、ImageNet、Common Crawl 这样的网络级数据集，机器人却没有对应的资源。不存在一张"机器人互联网"。数据散落在不同的机器人类型、传感器、控制方案和格式中，形成一座座孤立的"数据孤岛"。在[上一篇博客](https://huggingface.co/blog/lerobot-datasets)中，我们探讨了如何通过开放协作消解这种碎片化。正如 ImageNet 以大规模、多样的基准催化了计算机视觉的突破，我们相信**社区驱动的机器人数据集**也能为通才机器人策略扮演同样的奠基角色。

**SmolVLA 是我们朝这一愿景迈出的第一步**：它在精心整编的公开社区数据集混合上预训练，刻意反映真实世界的多样性。我们不只追求数据规模，更聚焦多样性：行为的范围、相机的视角、本体的种类，都要能促进迁移与泛化。

SmolVLA 使用的全部训练数据来自 **LeRobot 社区数据集**——即在 Hugging Face Hub 的 `lerobot` 标签下共享的机器人数据集。它们采集自多样的场景，从实验室到客厅，代表一场开放、去中心化的真实世界机器人数据扩展努力。

![A glimpse of the community dataset.](https://cdn-uploads.huggingface.co/production/uploads/640e21ef3c82bd463ee5a76d/V4QU-B-6YBONb-8K_lSpj.gif) 
 *图 4. 社区数据集一瞥。特别感谢 Ville Kuosmanen 制作了这段可视化。与学术基准不同，社区数据集天然捕捉杂乱、真实的交互：多变的光照、不够理想的演示、不按套路的物体、异构的控制方案。这种多样性对学习鲁棒的通用表示非常有用。*

我们用了一个自定义[过滤工具](https://huggingface.co/spaces/Beegbrain/FilterLeRobotData)（由 [Alexandre Chapin](https://huggingface.co/Beegbrain) 和 [Ville Kuosmanen](https://huggingface.co/villekuosmanen) 制作），按帧数、视觉质量和任务覆盖来筛选数据集。经过细致的人工复查（特别感谢 Marina Barannikov），我们整编出聚焦 **SO100 机械臂**、统一为 **30 FPS** 的 **487 个高质量数据集**。这带来约 **1000 万帧**——至少比其他流行基准数据集**小一个数量级**，但多样得多。

### 改进任务标注

社区数据集的普遍问题是任务描述有噪声或缺失。许多 episode 没有标注，或只有 "task desc"、"Move"、"Pick" 这类含糊标签。为了提升质量、统一各数据集的文本输入，我们用 [Qwen2.5-VL-3B-Instruct](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct) 生成简洁、动作导向的描述。

给定样例帧和原始标签，提示模型把指令改写成不超过 30 个字符、以动词开头（如 "Pick"、"Place"、"Open"）的句子。

所用的提示词是：

```
Here is a current task description: {current_task}. Generate a very short, clear, and complete one-sentence describing the action performed by the robot arm (max 30 characters). Do not include unnecessary words.
Be concise.
Here are some examples: Pick up the cube and place it in the box, open the drawer and so on.
Start directly with an action verb like “Pick”, “Place”, “Open”, etc.
Similar to the provided examples, what is the main action done by the robot arm?
```

### 统一相机视角

另一个挑战是相机命名不一致。有的数据集用 top 或 `wrist.right` 这样清晰的名字，有的则用 `images.laptop` 这种含义漂忽的标签。为此我们逐个数据集手工核对，把每个相机视角映射到统一规范：`OBS_IMAGE_1`：俯视视角 `OBS_IMAGE_2`：腕载视角 `OBS_IMAGE_3+`：其余视角

我们还单独考察了社区数据集预训练与多任务微调各自的贡献。没有 LeRobot 社区数据集预训练时，SmolVLA 在 SO100 上的初始成功率只有 **51.7%**。在社区数据上预训练后，性能跃升到 **78.3%**——绝对提升 **+26.6%**。多任务微调进一步提升表现，即便在低数据场景下也显示出很强的任务迁移能力。
