## Gemma 2 是什么？

Gemma 2 是 Google 最新一代开源 LLM，有 90 亿和 270 亿参数两种规模，均提供基座（预训练）和指令微调版本。Gemma 基于 Google DeepMind 的 Gemini，上下文长度 8K token：

- [gemma-2-9b](https://huggingface.co/google/gemma-2-9b)：9B 基座模型。
- [gemma-2-9b-it](https://huggingface.co/google/gemma-2-9b-it)：9B 基座模型的指令微调版。
- [gemma-2-27b](https://huggingface.co/google/gemma-2-27b)：27B 基座模型。
- [gemma-2-27b-it](https://huggingface.co/google/gemma-2-27b-it)：27B 基座模型的指令微调版。

Gemma 2 模型的训练数据约为前代的 2 倍：27B 版本用了 13 万亿 token，9B 版本用了 8 万亿 token，来源涵盖网页数据（以英文为主）、代码和数学。我们不知道训练配比的确切细节，只能猜测更大规模、更精细的数据筛选是性能提升的重要因素。

Gemma 2 沿用了[与第一代相同的许可证](https://ai.google.dev/gemma/terms)，这是一种宽松许可证，允许再分发、微调、商业使用和衍生作品。

## Gemma 2 的技术进步

Gemma 2 与第一代有很多相似之处：上下文长度 8192 token，使用旋转位置嵌入（RoPE）。相比初代 Gemma，Gemma 2 有四个主要进步：

- [滑动窗口注意力](https://huggingface.co/blog/gemma2#sliding-window-attention)：滑动窗口与全量二次注意力交替使用，保证生成质量。
- [Logit soft-capping](https://huggingface.co/blog/gemma2#soft-capping-and-attention-implementations)：通过把 logits 缩放到固定区间来防止其过度增长，改善训练。
- [知识蒸馏](https://huggingface.co/blog/gemma2#knowledge-distillation)：用更大的教师模型训练更小的模型（用于 9B 模型）。
- [模型融合](https://huggingface.co/blog/gemma2#model-merging)：把两个或更多 LLM 合并成一个新模型。

Gemma 2 在 [Google Cloud TPU 上训练（27B 用 v5p](https://cloud.google.com/blog/products/ai-machine-learning/introducing-cloud-tpu-v5p-and-ai-hypercomputer?hl=en)，[9B 用 TPU v4)](https://cloud.google.com/tpu/docs/v4)，使用 [JAX](https://jax.readthedocs.io/en/latest/quickstart.html) 和 [ML Pathways](https://blog.google/technology/ai/introducing-pathways-next-generation-ai-architecture/)。Gemma 2 Instruct 针对对话应用做了优化，用合成与人工生成的问答对混合数据训练，方法包括监督微调（SFT）、从更大模型蒸馏、基于人类反馈的强化学习（RLHF，使用更偏向对话能力的奖励模型），以及用 WARP 做模型融合以提升整体表现。

和预训练配比一样，微调数据集的细节以及 SFT 和 [RLHF](https://huggingface.co/blog/rlhf) 相关的超参数都没有公开。

### 滑动窗口注意力

[滑动窗口注意力](https://huggingface.co/papers/2004.05150)是一种降低 transformer 注意力计算内存与时间开销的方法，[Mistral](https://huggingface.co/papers/2310.06825) 等模型已在使用。Gemma 2 的新意在于：每隔一层使用滑动窗口（局部——4096 token），其间的层仍使用完整的二次全局注意力（8192 token）。我们猜测这是为了在长上下文场景下提高质量（仍有一半层关注全部 token），同时部分享受滑动注意力的好处。

### Soft-capping 与注意力实现

Soft capping 是一种在不截断的前提下防止 logits 过度增大的技术。做法是把 logits 除以一个最大值阈值（soft_cap），过一层 `tanh`（确保落在 `(-1, 1)` 区间），再乘回阈值。这样最终值必然落在 `(-soft_cap, +soft_cap)` 区间内，既几乎不损失信息，又稳定了训练。

合起来，logits 的计算式为：`logits ← soft_cap ∗ tanh(logits/soft_cap)`

Gemma 2 在最终层和每一层注意力上都使用 soft capping。注意力 logits 的阈值是 50.0，最终 logits 的阈值是 30.0。

发布之时，soft-capping 与 Flash Attention / SDPA 不兼容，但推理时仍可以使用它们以追求最高效率。Gemma 2 团队观察到，推理时去掉 soft-capping 带来的差异非常小。

*注意：要想微调训练稳定，你仍需开启 soft-capping，因此建议使用 `eager` 注意力而不是 SDPA 来微调。*

### 知识蒸馏

知识蒸馏是一种让较小的*学生*模型模仿更大、表现更好的*教师*模型的流行训练技术。其做法是在 LLM 的下一 token 预测任务上，叠加教师给出的 token 概率分布（例如 GPT-4、Claude 或 Gemini），为学生提供更丰富的学习信号。

根据 Gemma 2 技术报告，9B 模型预训练时使用了知识蒸馏，而 27B 模型是从零训练的。

后训练阶段，Gemma 2 团队让教师模型（报告中未指明，推测是 Gemini Ultra）生成了多样化的补全，然后用这份合成数据对学生模型做 SFT。很多开源模型正是这样来的，例如 [Zephyr](https://huggingface.co/HuggingFaceH4/zephyr-7b-beta) 和 [OpenHermes](https://huggingface.co/teknium/OpenHermes-2.5-Mistral-7B)，它们完全基于大 LLM 的合成数据训练。

这个方法虽然有效，也有缺点：学生和模型的容量差距会造成*训练-推理不匹配*（train-inference mismatch）——推理时学生自己生成的文本相对训练时见过的数据是分布外的。

为了解决这个问题，Gemma 2 团队采用了["on-policy distillation"（在线策略蒸馏）](https://arxiv.org/pdf/2306.13649)：由学生针对 SFT 提示词生成补全，再用这些补全计算教师与学生 logits 之间的 KL 散度。通过在训练过程中持续最小化 KL 散度，学生既学会了精确建模教师的行为，又缓解了训练-推理不匹配。

这个思路很有意思：社区已经观察到 online DPO 这类 on-policy 方法能训出更强的模型，而 on-policy 蒸馏的一个好处是只需要教师的 logits，不必依赖奖励模型或 LLM-as-a-judge 来改进模型。接下来几个月里这种方法会不会被更多微调玩家采用，值得期待！

### 模型融合

[模型融合](https://huggingface.co/blog/mlabonne/merge-models)是把两个或更多 LLM 合并成一个新模型的技术。它比较新、偏实验性质，无需加速卡也能做。[Mergekit](https://github.com/arcee-ai/mergekit) 是一个流行的开源 LLM 融合工具包，实现了线性融合、SLERP、TIES、DARE 等多种融合技术。

根据技术报告，Gemma 2 使用了 [Warp](https://arxiv.org/abs/2406.16768)——一种新的融合技术，分三个阶段融合模型：

- 指数移动平均（EMA）：在强化学习（RL）微调过程中应用。
- 球面线性插值（SLERP）：在对多个策略完成 RL 微调后应用。
- 朝初始化线性插值（LITI）：在 SLERP 阶段之后应用。

## 如何给 Gemma 2 写提示词

基座模型没有提示词格式。和其他基座模型一样，它们可以用来对输入序列续写出合理的后续，或做 zero-shot/few-shot 推理。Instruct 版本的对话结构非常简单：

```
<start_of_turn>user
knock knock<end_of_turn>
<start_of_turn>model
who is there<end_of_turn>
<start_of_turn>user
LaMDA<end_of_turn>
<start_of_turn>model
LaMDA who?<end_of_turn><eos>
```

要有效使用，必须原样复现这个格式。后面我们会演示用 `transformers` 自带的聊天模板复现指令提示词有多简单。

## 使用 Hugging Face Transformers

借助 Transformers [4.42 版本](https://github.com/huggingface/transformers/releases/tag/v4.42.0)，你可以使用 Gemma 并借力 Hugging Face 生态的全部工具。要用 transformers 使用 Gemma 模型，请确保安装最新的 `transformers` 版本：

```
pip install "transformers>=4.42.3" --upgrade
```

下面这段代码展示如何用 `transformers` 使用 `gemma-2-9b-it`。它需要约 18 GB 内存，很多消费级 GPU 都够用。同样的代码也适用于 `gemma-2-27b-it`——占用 56GB 内存，对生产用例来说是个很有吸引力的模型。以 8-bit 或 4-bit 模式加载还能进一步降低内存消耗。

```
from transformers import pipeline
import torch

pipe = pipeline(
    "text-generation",
    model="google/gemma-2-9b-it",
    model_kwargs={"torch_dtype": torch.bfloat16},
    device="cuda",
)

messages = [
    {"role": "user", "content": "Who are you? Please, answer in pirate-speak."},
]
outputs = pipe(
    messages,
    max_new_tokens=256,
    do_sample=False,
)
assistant_response = outputs[0]["generated_text"][-1]["content"]
print(assistant_response)
```

> Ahoy, matey! I be a humble ship o' words, sailin' the digital seas. They call me Gemma, a creation o' the fine folks at Google DeepMind. I be trained on a treasure trove o' texts, learnin' to speak and write like a true scallywag.
> Ask me yer questions, and I'll do me best to answer 'em, aye!  🦜📚

*我们使用 bfloat16 是因为它是该指令微调模型的参考精度。在你的硬件上跑 float16 可能更快，9B 模型的结果应当接近。但要注意，27B 指令微调模型在 float16 下会输出乱码：该模型权重必须使用 bfloat16。*

你还可以自动量化模型，以 8-bit 甚至 4-bit 模式加载。大号的 27B 版本以 4-bit 加载运行时只占约 18 GB 内存，很多消费级显卡和 Google Colab 的 GPU 都能跑。4-bit 加载生成管线的方式如下：

```
pipeline = pipeline(
    "text-generation",
    model=model,
    model_kwargs={
        "torch_dtype": torch.bfloat16,
        "quantization_config": {"load_in_4bit": True}
    },
)
```

关于用 `transformers` 使用这些模型的更多细节，请查看[模型卡](https://huggingface.co/google/gemma-2-9b)。

## 用 🤗 TRL 微调

训练 LLM 在技术和算力上都很有挑战。本节来看看 Hugging Face 生态中有哪些工具可以在消费级 GPU 上高效训练 Gemma。

下面是一个在 OpenAssistant 的[聊天数据集](https://huggingface.co/datasets/OpenAssistant/oasst_top1_2023-08-25)上微调 Gemma 的示例命令。我们用 4-bit 量化和 [QLoRA](https://arxiv.org/abs/2305.14314) 节省内存，目标是所有注意力块的线性层。注意，与稠密 transformer 不同，不应把目标设在 MLP 层上，因为它们是稀疏的，与 PEFT 配合不好。

首先，安装 🤗 TRL 的 nightly 版本并 clone 仓库以获得[训练脚本](https://github.com/huggingface/trl/blob/main/trl/scripts/sft.py)：

```
pip install "transformers>=4.42.3" --upgrade
pip install --upgrade bitsandbytes
pip install --ugprade peft
pip install git+https://github.com/huggingface/trl
git clone https://github.com/huggingface/trl
cd trl
```

然后运行脚本：

```
# peft tuning; single GPU; https://wandb.ai/costa-huang/huggingface/runs/l1l53cst
python \
    trl/scripts/sft.py \
    --model_name google/gemma-2-27b \
    --dataset_name OpenAssistant/oasst_top1_2023-08-25 \
    --dataset_text_field="text" \
    --per_device_train_batch_size 1 \
    --per_device_eval_batch_size 1 \
    --gradient_accumulation_steps 4 \
    --learning_rate 2e-4 \
    --report_to wandb \
    --bf16 \
    --max_seq_length 1024 \
    --lora_r 16 --lora_alpha 32 \
    --lora_target_modules q_proj k_proj v_proj o_proj \
    --load_in_4bit \
    --use_peft \
    --attn_implementation eager \
    --logging_steps=10 \
    --gradient_checkpointing \
    --output_dir models/gemma2
```

![alt_text](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/gemma2/lora.png?download=true)

## 与 Inference Endpoints 集成

你可以用 Text Generation Inference 作为后端，把 Gemma 2 部署到 Hugging Face 的 [Inference Endpoints](https://ui.endpoints.huggingface.co/philschmid/new?repository=google%2Fgemma-2-27b-it&accelerator=gpu&instance_id=aws-us-east-1-nvidia-a100-x1&task=text-generation&no_suggested_compute=true&tgi=true) 上。[Text Generation Inference](https://github.com/huggingface/text-generation-inference) 是 Hugging Face 开发的生产级推理容器，让大语言模型的部署变得简单。它支持连续批处理、token 流式输出、多 GPU 张量并行加速推理，以及生产级的日志和追踪。

要部署 Gemma 2 模型，前往[模型页面](https://huggingface.co/google/gemma-2-27b-it)，点击 [Deploy -> Inference Endpoints](https://ui.endpoints.huggingface.co/new?repository=google/gemma-2-27b-it) 组件。Inference Endpoints 支持兼容 OpenAI 的 [Messages API](https://huggingface.co/blog/tgi-messages-api)，只需更改 URL，就能从其他闭源模型无缝切换到开源模型。

```
from openai import OpenAI

# initialize the client but point it to TGI
client = OpenAI(
    base_url="<ENDPOINT_URL>" + "/v1/",  # replace with your endpoint url
    api_key="<HF_API_TOKEN>",  # replace with your token
)
chat_completion = client.chat.completions.create(
    model="tgi",
    messages=[
        {"role": "user", "content": "Why is open-source software important?"},
    ],
    stream=True,
    max_tokens=500
)

# iterate and print stream
for message in chat_completion:
    print(message.choices[0].delta.content, end="")
```
