# Consilium：当多个 LLM 协同工作

想象一下：四位 AI 专家围坐在一张扑克桌旁，实时辩论你最棘手的那些决策。这正是 Consilium 这个多 LLM 平台所做的事，它是我在 [Gradio Agents & MCP Hackathon](https://huggingface.co/spaces/Agents-MCP-Hackathon/consilium_mcp) 期间搭建的。它让多个 AI 模型讨论复杂问题，并通过结构化辩论达成共识。

这个平台既能作为一个可视化的 Gradio 界面，也能作为一个 MCP（Model Context Protocol，模型上下文协议）服务器，直接集成到 Cline 这类应用里（Claude Desktop 有些问题，因为它的超时时间没法调整）。核心想法一直是让 LLM 通过讨论达成共识——Consilium 这个名字正由此而来。后来为了把协作做得更精细，又加入了多数投票、排序选择等其他决策模式。

## 从概念到架构

这并不是一开始我就想好的黑客松选题。我最初只是想做一个简单的 MCP 服务器，用来跟我在 RevenueCat 上的项目对话。但当我意识到，一个让多个模型讨论问题、返回深思熟虑答案的多 LLM 平台会远更有吸引力时，我改变了主意。

时机恰好合适。黑客松结束后不久，微软发布了他们的 [AI Diagnostic Orchestrator (MAI-DxO)](https://microsoft.ai/new/the-path-to-medical-superintelligence/)，本质上是一个由不同角色组成的 AI 医生小组，比如"Dr. Challenger Agent"，通过反复迭代来诊断病人。在使用 OpenAI o3 的方案里，他们正确解决了 85.5% 的医学诊断基准用例，而执业医生的准确率只有 20%。这恰好印证了 Consilium 所展示的东西：多个 AI 视角协同，能显著胜过单一个体的分析。

确定概念之后，我需要一个既能当 MCP 服务器、又能作为吸引人的 Hugging Face space 演示的东西。一开始我考虑用标准的 Gradio Chat 组件，但希望自己的作品能脱颖而出。想法是让 LLM 们围坐在会议室的桌子旁，用对话气泡呈现，这样既能体现协作讨论，又足够有视觉吸引力。由于我没能把标准表格样式调得好到能被识别成表格，最后改用了扑克式的圆桌。这种方式也让我通过自建一个 Gradio 组件和一个 MCP 服务器，同时投稿到黑客松的两个赛道。

## 搭建视觉基础

这个自定义 Gradio 组件成了整个作品的核心：扑克式圆桌，参与者坐着，用对话气泡展示各自的回复、思考状态和研究活动——任何进入这个 space 的人一眼就会被吸引。得益于 Gradio 出色的开发体验，组件开发异常顺利，不过我在 PyPI 发布这一块确实遇到了文档缺失，也正是因此我第一次给 Gradio 项目贡献了代码。

```
# The visual component integration
roundtable = consilium_roundtable(
```

视觉设计在整个黑客松期间都足够稳健；初次实现之后，只是补充了用户自定义头像和桌子中央文字等功能，核心交互模型始终没变。

如果你也有兴趣创建自己的自定义 Gradio 组件，可以看看 [Custom Components in 5 minutes](https://www.gradio.app/guides/custom-components-in-five-minutes)——没错，标题没骗人，基础配置真的只要 5 分钟。

## 会话状态管理

可视化圆桌通过一套基于会话的字典系统来维护状态，每个用户都通过 `user_sessions[session_id]` 拿到隔离的状态存储。核心状态对象跟踪 `participants`、`messages`、`currentSpeaker`、`thinking` 和 `showBubbles` 这几个数组，通过 `update_visual_state()` 回调来更新。当模型正在思考、正在发言，或者正在执行研究时，引擎会把增量状态推送给前端——往 messages 数组追加内容、切换发言者/思考状态——从而在没有复杂状态机的情况下实现实时的视觉流转，只是把 JSON 状态直接在后端处理和前端渲染之间做同步变更。

## 让 LLM 真正"讨论"起来

实现过程中我发现，LLM 之间并没有真正的讨论，因为它们缺少清晰的角色。它们能拿到正在进行讨论的完整上下文，却不知道怎么有意义地参与。于是我引入了不同的角色来制造富有成效的辩论动态，几经调整后最终是这样：

```
self.roles = {
    'standard': "Provide expert analysis with clear reasoning and evidence.",
    'expert_advocate': "You are a PASSIONATE EXPERT advocating for your specialized position. Present compelling evidence with conviction.",
    'critical_analyst': "You are a RIGOROUS CRITIC. Identify flaws, risks, and weaknesses in arguments with analytical precision.",
    'strategic_advisor': "You are a STRATEGIC ADVISOR. Focus on practical implementation, real-world constraints, and actionable insights.",
    'research_specialist': "You are a RESEARCH EXPERT with deep domain knowledge. Provide authoritative analysis and evidence-based insights.",
    'innovation_catalyst': "You are an INNOVATION EXPERT. Challenge conventional thinking and propose breakthrough approaches."
}
```

这解决了讨论问题，但又带来一个新问题：如何判断达成共识，或者找出最强论点？我实现了一个"首席分析师"系统，由用户选定一个 LLM 来综合最终结果、评估是否达成了共识。

我还希望用户能控制通信结构。除了默认的全上下文共享，我额外加入了两种模式：

- **环形（Ring）**：每个 LLM 只接收上一位参与者的回复
- **星形（Star）**：所有消息都经过作为中央协调者的首席分析师流转

最后，讨论需要有终点。我实现了可配置的轮次（1-5 轮），测试表明更多轮次会提高达成共识的概率（当然计算成本也更高）。

## 模型选择与研究集成

当前的模型选择包括 Mistral Large、DeepSeek-R1、Meta-Llama-3.3-70B 和 QwQ-32B。虽然 Claude Sonnet、OpenAI 的 o3 等重量级模型不在其中，但这反映的是黑客松提供的额度限制和赞助商奖项的考量，而非技术限制。

```
self.models = {
    'mistral': {
        'name': 'Mistral Large',
        'api_key': mistral_key,
        'available': bool(mistral_key)
    },
    'sambanova_deepseek': {
        'name': 'DeepSeek-R1',
        'api_key': sambanova_key,
        'available': bool(sambanova_key)
    }
    ...
}
```

对于那些支持函数调用的模型，我集成了一个专门的研究 agent，它作为圆桌上的另一位参与者出现。我没有直接给模型开放网页访问，而是用这个 agent 的方式，让外部资源可用性在视觉上更清晰，同时保证所有支持函数调用的模型都能一致地访问。

```
def handle_function_calls(self, completion, original_prompt: str, calling_model: str) -> str:
    """UNIFIED function call handler with enhanced research capabilities"""
    
    message = completion.choices[0].message
    
    # If no function calls, return regular response
    if not hasattr(message, 'tool_calls') or not message.tool_calls:
        return message.content
    
    # Process each function call
    for tool_call in message.tool_calls:
        function_name = tool_call.function.name
        arguments = json.loads(tool_call.function.arguments)
        
        # Execute research and show progress
        result = self._execute_research_function(function_name, arguments, calling_model_name)
```

研究 agent 能访问五个来源：Web Search、Wikipedia、arXiv、GitHub 和 SEC EDGAR。我把这些工具构建在一套可扩展的基类架构之上，方便将来扩展，同时聚焦于可自由嵌入的资源。

```
class BaseTool(ABC):
    """Base class for all research tools"""
    
    def __init__(self, name: str, description: str):
        self.name = name
        self.description = description
        self.last_request_time = 0
        self.rate_limit_delay = 1.0
    
    @abstractmethod
    def search(self, query: str, **kwargs) -> str:
        """Main search method - implemented by subclasses"""
        pass
    
    def score_research_quality(self, research_result: str, source: str = "web") -> Dict[str, float]:
        """Score research based on recency, authority, specificity, relevance"""
        quality_score = {
            "recency": self._check_recency(research_result),
            "authority": self._check_authority(research_result, source),
            "specificity": self._check_specificity(research_result),
            "relevance": self._check_relevance(research_result)
        }
        return quality_score
```

由于研究操作可能比较耗时，对话气泡会显示进度指示和预估时长，以便在较长的研究任务中保持用户的参与感。

## 发现 Open Floor Protocol

黑客松之后，Deborah Dahl 向我介绍了 [Open Floor Protocol](https://github.com/open-voice-interoperability/openfloor-docs)，它与圆桌方式高度契合。这个协议为跨平台 agent 通信提供了标准化的 JSON 消息格式。它与其他 agent 间协议最大的区别在于：所有 agent 始终保持对会话的完整感知，就像真的坐在同一张桌子旁一样。还有一点我在其他协议里没见过——主持人（floor manager）可以动态地把 agent 邀请上席或请下席位。

这个协议的交互模式可以直接映射到 Consilium 的架构：

- **Delegation（委托）**：在 agent 之间转移控制权
- **Channeling（转达）**：原封不动地传递消息
- **Mediation（调解）**：在幕后进行协调
- **Orchestration（编排）**：多个 agent 协作

我正在集成 Open Floor Protocol 支持，让用户能把任意符合 OFP 的 agent 加入自己的圆桌讨论。你可以在这里跟进开发进展：[https://huggingface.co/spaces/azettl/consilium_ofp](https://huggingface.co/spaces/azettl/consilium_ofp)

## 经验教训与未来展望

黑客松让我接触到了此前不了解的多 agent 辩论研究，包括 [Encouraging Divergent Thinking in Large Language Models through Multi-Agent Debate](https://arxiv.org/abs/2305.19118) 这类奠基性研究。社区体验也非常棒——大家通过 Discord 互相支持、协作。看到我的圆桌组件被集成进[另一个黑客松项目](https://huggingface.co/spaces/Agents-MCP-Hackathon/multi-agent-chat)，是我做 Consilium 过程中最难忘的时刻之一。

我会继续完善 Consilium；随着模型选择扩展、Open Floor Protocol 集成以及可配置的 agent 角色，这个平台几乎能支撑任何你能想到的多 agent 辩论场景。

打造 Consilium 让我更坚定地相信：AI 的未来不在于单个更强的模型，而在于能让 AI 高效协作的系统。随着专用的小语言模型越来越高效、越来越省资源，我认为由任务专用 SLM 加上专职研究 agent 组成的圆桌，在很多用例上会成为通用大语言模型颇具竞争力的替代方案。
