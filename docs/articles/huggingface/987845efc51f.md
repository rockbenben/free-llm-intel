[**潜空间扩散模型**](https://arxiv.org/abs/2112.10752)（Latent Diffusion models）在解决文生图问题上具有革命性意义。[**Stable Diffusion**](https://stability.ai/blog/stable-diffusion-public-release) 是最著名的例子之一，在社区和工业界都得到了广泛应用。Stable Diffusion 模型背后的想法简单而有吸引力：从噪声向量出发，通过多个小步骤把噪声逐步精炼成潜空间的图像表示，从而生成图像。这种方法效果很好，但如果没有强大的 GPU，生成一张图可能要花很长时间。

过去五年里，[OpenVINO Toolkit](https://docs.openvino.ai/) 封装了许多高性能推理特性。它最初为计算机视觉模型设计，如今仍在该领域占据主导地位，为许多现代模型（包括 [Stable Diffusion](https://huggingface.co/blog/stable-diffusion-inference-intel)）提供同类最佳的推理性能。然而，要为资源受限的应用优化 Stable Diffusion 模型，仅靠运行时优化远远不够。这正是 OpenVINO [神经网络压缩框架](https://github.com/openvinotoolkit/nncf)（NNCF）的模型优化能力大显身手的地方。

在这篇博客中，我们将概述 Stable Diffusion 模型优化的痛点，并提出一套工作流，大幅降低此类模型在 CPU 等资源受限硬件上的延迟。具体而言，相比 PyTorch，我们实现了 **5.1 倍**推理加速和 **4 倍**模型体积缩减。

## Stable Diffusion 优化

在 [Stable Diffusion 管线](https://huggingface.co/docs/diffusers/api/pipelines/stable_diffusion/overview)中，UNet 模型是计算开销最大的部分。因此，只优化这一个模型就能在推理速度上获得可观收益。

但事实证明，传统的模型优化方法（比如训练后 8-bit 量化）对这个模型行不通。主要有两个原因。其一，像素级预测模型（如语义分割、超分辨率等）由于任务复杂，是模型优化难度最高的一类，改动模型参数和结构会以多种方式破坏结果。其二，这个模型在[数亿样本](https://laion.ai/blog/laion-5b/)上训练、容纳了大量信息，冗余度更低。这就是为什么研究者必须采用更精巧的量化方法来保住优化后的精度。例如，Qualcomm 使用了逐层知识蒸馏方法（[AdaRound](https://arxiv.org/abs/2004.10568)）来[量化](https://www.qualcomm.com/news/onq/2023/02/worlds-first-on-device-demonstration-of-stable-diffusion-on-android) Stable Diffusion 模型。这说明量化之后的模型调优无论如何都省不掉。既然如此，为什么不直接用[量化感知训练](https://arxiv.org/abs/1712.05877)（QAT）——它能像源模型训练那样同时调优模型和量化参数？于是我们在工作中尝试了这一方法，使用 [NNCF](https://github.com/openvinotoolkit/nncf)、[OpenVINO](https://www.intel.com/content/www/us/en/developer/tools/openvino-toolkit/overview.html) 和 [Diffusers](https://github.com/huggingface/diffusers)，并将其与 [Token Merging](https://arxiv.org/abs/2210.09461) 结合。

## 优化工作流

我们通常在模型训练完成后开始优化。这里我们从一个在 [Pokemons 数据集](https://huggingface.co/datasets/lambdalabs/pokemon-blip-captions)（包含宝可梦图像及其文本描述）上微调过的[模型](https://huggingface.co/svjack/Stable-Diffusion-Pokemon-en)出发。

我们使用了 Diffusers 提供的 Stable Diffusion [文生图微调示例](https://huggingface.co/docs/diffusers/training/text2image)，并把 NNCF 的 QAT 集成进这个训练[脚本](https://github.com/huggingface/optimum-intel/tree/main/examples/openvino/stable-diffusion)。我们还修改了损失函数，融入来自源模型的知识蒸馏——源模型在这个过程中充当教师，被训练的实际模型充当学生。这与经典知识蒸馏方法不同：经典方法是把训练好的教师模型蒸馏进一个更小的学生模型；而对我们来说，知识蒸馏只是辅助手段，用来提升被优化模型的最终精度。我们还对模型参数（量化器除外）使用指数移动平均（EMA），让训练过程更稳定。我们只微调 4096 次迭代。

借助一些技巧，例如梯度检查点以及把 [EMA 模型](https://github.com/huggingface/optimum-intel/blob/bbbe7ff0e81938802dbc1d234c3dcdf58ef56984/examples/openvino/stable-diffusion/train_text_to_image_qat.py#L941)留在内存（RAM）而非显存（VRAM），我们可以在一块 24 GB 显存的 GPU 上运行整个优化过程。使用一块 GPU，整个优化不到一天即可完成！

## 超越量化感知训练

仅量化本身就能带来显著增强：减小模型体积、缩短加载时间、降低内存占用和推理延迟。而量化的美妙之处在于，它可以与其他优化方法叠加，获得累积加速。

最近，Facebook Research 为 Vision Transformer 模型提出了 [Token Merging](https://arxiv.org/abs/2210.09461) 方法。方法的要点是用可选策略之一（求平均、取最大值等）把冗余 token 与重要 token 合并。合并发生在自注意力块之前——而自注意力正是 Transformer 模型计算量最大的部分。因此缩减 token 维度就减少了自注意力块的整体计算时间。该方法也被[适配](https://arxiv.org/pdf/2303.17604.pdf)到 Stable Diffusion 模型，在 GPU 上优化用于高分辨率图像合成的 Stable Diffusion 管线时展示了可观的前景。

我们把 Token Merging 方法做了修改以兼容 OpenVINO，并将其与 8-bit 量化叠加应用于 Attention UNet 模型。这同样涉及前述的所有技术，包括知识蒸馏等。和量化一样，它也需要微调来恢复精度。我们的优化与微调同样从在 [Pokemons 数据集](https://huggingface.co/datasets/lambdalabs/pokemon-blip-captions)上训练过的[模型](https://huggingface.co/svjack/Stable-Diffusion-Pokemon-en)出发。下图展示了整体优化工作流。

## 结果

我们用公开的优化工作流得到了两类优化模型——8-bit 量化模型和结合 Token Merging 的量化模型——并与 PyTorch 基线对比。我们还把基线转换成原生 OpenVINO 浮点（FP32）模型，以便全面比较。

上图展示了图像生成结果和部分模型特性。可以看到，仅转换到 OpenVINO 就大幅降低了推理延迟（**1.9 倍**）。应用 8-bit 量化后推理速度进一步提升，相比 PyTorch 达到 **3.9 倍**加速。量化的另一个好处是模型体积显著缩小，仅为 PyTorch 检查点的 **0.25**，同时也改善了模型加载时间。在量化之上叠加 Token Merging（ToME，**合并率 0.4**）带来 **5.1 倍**性能加速，而体积保持在同一水平。我们没有对优化模型的视觉质量做深入分析，但可以看到结果相当扎实。

本文展示的结果使用了默认的 50 步推理。推理步数更少时速度会更快，但这会影响最终图像质量，影响大小取决于模型和[调度器](https://huggingface.co/docs/diffusers/using-diffusers/schedulers)。我们建议多试不同的步数和调度器，找到最适合你用例的组合。

下面展示如何用针对 Intel CPU 优化的最终管线做推理：

```
from optimum.intel import OVStableDiffusionPipeline

# Load and compile the pipeline for performance.
name = "OpenVINO/stable-diffusion-pokemons-tome-quantized-aggressive"
pipe = OVStableDiffusionPipeline.from_pretrained(name, compile=False)
pipe.reshape(batch_size=1, height=512, width=512, num_images_per_prompt=1)
pipe.compile()

# Generate an image.
prompt = "a drawing of a green pokemon with red eyes"
output = pipe(prompt, num_inference_steps=50, output_type="pil").images[0]
output.save("image.png")
```

训练与量化[代码](https://github.com/huggingface/optimum-intel/tree/main/examples/openvino/stable-diffusion)可在 Hugging Face 的 [Optimum Intel](https://huggingface.co/docs/optimum/main/en/intel/index) 库中找到。演示优化模型与原始模型差异的 notebook 见[这里](https://github.com/huggingface/optimum-intel/blob/main/notebooks/openvino/stable_diffusion_optimization.ipynb)。你也可以在 Hugging Face Hub 的 [OpenVINO 组织](https://huggingface.co/OpenVINO)下找到[许多模型](https://huggingface.co/models?library=openvino&sort=downloads)。此外，我们还创建了一个 [demo](https://huggingface.co/spaces/helenai/stable_diffusion)，运行在第三代 Intel Xeon 可扩展处理器上。

## 通用版 Stable Diffusion 模型怎么办？

正如我们在宝可梦图像生成任务上展示的，用相对少量的训练资源就能让 Stable Diffusion 管线达到很高的优化程度。同时众所周知，训练一个通用 Stable Diffusion 模型是项[昂贵的工作](https://www.mosaicml.com/blog/training-stable-diffusion-from-scratch-part-2)。不过，只要预算和硬件资源足够，用本文描述的方法优化通用模型并把它调到能产出高质量图像是可行的。唯一的注意点在于 token merging 方法会大幅削减模型容量。经验法则：训练数据集越复杂，优化时使用的合并率就应该越低。

如果你喜欢这篇文章，可能也会对[这篇](https://huggingface.co/blog/stable-diffusion-inference-intel)感兴趣——它讨论了在第四代 Intel Xeon CPU 上优化 Stable Diffusion 性能的其他互补方法。
