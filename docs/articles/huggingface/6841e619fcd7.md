llama.cpp 使得在各种硬件上运行多模式 LLM 成为可能 - 从消费级本地计算机到高端企业服务器。通过量化、优化的后端和可移植的 C/C++ 实现，我们使 AI 推理可以在软件堆栈的各个级别进行访问。我们相信这是构建跨平台和私有人工智能产品的最轻量级、通用性和合理性的平台。

自[启动](https://github.com/ggml-org/llama.cpp/commit/26c0846)以来的 3.5 年里，该项目已经发展了很多，许多下游应用程序已经依赖于我们的工作。随着本地人工智能和隐私在我们的日常生活中变得越来越重要，我们预计这一趋势将持续下去。每一个新的集成都意味着更多的开发人员依赖我们的库接口，因此拥有灵活但稳定的 API 至关重要。

今天我们发布了库“v1.0.0”，强调了我们对这些开发人员的责任。展望未来，[llama.cpp](https://github.com/ggml-org/llama.cpp) 和 [ggml](https://github.com/ggml-org/ggml) 都将反映出 API 和 ABI 与主要版本的不兼容。随着采用率的增长，我们将更加严格地让下游消费者看到这些界限。

### 语义版本更新规则

以下规则适用于所有使用[语义版本控制](https://semver.org)的[ggml-org](https://huggingface.co/ggml-org)项目：

|更改类型 |凹凸|
| --- | --- |
| **专业** |对 `./include` 中公共 C API 的重大更改 |
| **次要** |向后兼容功能、后端更新、模型支持或 API 添加 |
| **补丁** |错误修复，无需更改 API |

### 发展

该项目培育了一个令人惊叹的开源社区，拥有高技能和才华横溢的贡献者。随着人工智能能力在软件工程领域的快速发展，我们继续以深思熟虑和合理的方式将LLM融入我们的开发周期中。维护高质量的代码库、保持对架构的控制和了解实现细节仍然是我们的首要任务。

为了加快发展步伐，我们继续投入越来越多的资源来改善项目背后的 CI 基础设施。借助 [HF Buckets](https://huggingface.co/docs/huggingface_hub/en/guides/buckets) 和 [HF Jobs](https://huggingface.co/docs/huggingface_hub/en/guides/jobs) 等 HF 技术，我们能够扩展必要的容量，以保证落在“master”分支上的每个更改的正确性。在 NVIDIA、AMD、Qualcomm、Arm、IBM 和 Intel 的硬件支持下，我们继续在所有主要硬件平台上招募更多自托管运行程序。

### 后端和模型覆盖范围

`llama.cpp` 的底层机器学习引擎 - `ggml` 被设计为几乎可以在任何现有的硬件上运行。这是通过实现专用的 ggml 后端来实现的。每个后端都可以编译为动态库，并可以选择在运行时加载。

当前实现的后端的完整列表可以在[此处](https://github.com/ggml-org/ggml/tree/master/src)找到。

我们致力于为所有模型架构提供持续支持。目前，llama.cpp 支持超过 [150 种架构变体](https://github.com/ggml-org/llama.cpp/tree/master/src/models) 以及所有主流推测解码方法。
