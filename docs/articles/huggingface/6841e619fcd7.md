llama.cpp 让多模态 LLM 能跑在各种各样的硬件上——从消费级本地机器到高端企业服务器。借助量化、优化过的后端和可移植的 C/C++ 实现，我们让 AI 推理在软件栈的每一层都触手可及。我们相信，这是构建跨平台、私有 AI 产品最轻量、最通用、也最合理的平台。

自[诞生](https://github.com/ggml-org/llama.cpp/commit/26c0846)以来的 3.5 年里，项目壮大了很多，已有不少下游应用依赖我们的工作。随着本地 AI 和隐私在日常生活中越来越重要，我们预计这一趋势还会延续。每多一个集成，就多一批开发者依赖我们的库接口，因此一套灵活又稳定的 API 至关重要。

今天我们发布 `v1.0.0` 库，以此表明对这些开发者的责任。往后，[llama.cpp](https://github.com/ggml-org/llama.cpp) 和 [ggml](https://github.com/ggml-org/ggml) 都会用主版本号升级来体现 API 与 ABI 的不兼容变更。随着采用者增多，我们会更严格地让下游使用者看清这些边界。

### 发布

| [ggml v1.0.0](https://github.com/ggml-org/ggml/releases/tag/v1.0.0) - 面向机器学习的张量库 | `libggml` | [`ggml/include/`](https://github.com/ggml-org/llama.cpp/blob/master/ggml/include/) |

### 语义化版本更新规则

以下规则适用于所有采用[语义化版本](https://semver.org)的 [ggml-org](https://huggingface.co/ggml-org) 项目：

| 变更类型 | 升级 |
| --- | --- |
| **MAJOR** | `./include` 中公共 C API 的破坏性变更 |
| **MINOR** | 向后兼容的新功能、后端更新、模型支持或 API 新增 |
| **PATCH** | 不改动 API 的 bug 修复 |

### 开发

这个项目孕育出了一个了不起的开源社区，汇聚了技术娴熟、才华出众的贡献者。随着 AI 能力在软件工程领域飞速进步，我们会继续以审慎、合理的方式把 LLM 调整并融入开发流程。维护高质量的代码库、牢牢掌控架构、吃透实现细节，仍是我们最优先的事。

为了跟上更快的开发节奏，我们持续投入更多资源改进项目背后的 CI 基础设施。借助 [HF Buckets](https://huggingface.co/docs/huggingface_hub/en/guides/buckets)、[HF Jobs](https://huggingface.co/docs/huggingface_hub/en/guides/jobs) 这类 HF 技术，我们得以扩容到足以保证落在 `master` 分支上的每一处改动都正确的程度。在 NVIDIA、AMD、Qualcomm、Arm、IBM 和 Intel 的硬件支持下，我们继续在各个主要硬件平台上接入更多 self-hosted runner。

### 后端与模型覆盖

`llama.cpp` 底层的机器学习引擎 `ggml`，被设计成几乎能在现存任何硬件上运行。这是通过实现专用的 ggml 后端做到的。每个后端都能编译成动态库，并可选择在运行时加载。

目前已实现的后端完整清单见[这里](https://github.com/ggml-org/ggml/tree/master/src)。

我们致力于为所有模型架构提供持续支持。目前 llama.cpp 支持超过 [150 种架构变体](https://github.com/ggml-org/llama.cpp/tree/master/src/models)，以及所有主流的投机解码方法。
