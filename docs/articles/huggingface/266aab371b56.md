*基于 transformer* 的编码器-解码器模型由 Vaswani 等人在著名的 [Attention is all you need 论文](https://arxiv.org/abs/1706.03762)中提出，如今已是自然语言处理（NLP）中 *de-facto* 标准的编码器-解码器架构。

最近，围绕基于 transformer 的编码器-解码器模型的不同*预训练目标*有大量研究，*e.g.* T5、Bart、Pegasus、ProphetNet、Marge *等等*，但模型架构大体保持不变。

本博客的目标，是给出一份**详尽的**解释，说明*基于 transformer* 的编码器-解码器架构是**如何**对*序列到序列*问题建模的。我们会聚焦架构所定义的数学模型，以及模型如何在推理中被使用。过程中，我们会介绍 NLP 中序列到序列模型的一些背景，并把*基于 transformer* 的编码器-解码器架构拆解为它的**编码器**和**解码器**两部分。我们提供许多插图，并在*基于 transformer* 的编码器-解码器模型的理论与它们在 🤗Transformers 中推理时的实际用法之间建立联系。注意，本文*不*解释这类模型如何被训练——那是未来一篇博客的主题。

基于 transformer 的编码器-解码器模型是多年关于*表示学习*和*模型架构*研究的成果。本文对神经编码器-解码器模型的历史做一个简短总结。要获得更多背景，建议读者阅读 Sebastion Ruder 这篇很棒的[博客](https://ruder.io/a-review-of-the-recent-history-of-nlp/)。此外，建议对*自注意力架构*有基本理解。Jay Alammar 的下面这篇博客是对原始 Transformer 模型很好的温习，见[这里](http://jalammar.github.io/illustrated-transformer/)。

在本文撰写之时，🤗Transformers 包含的编码器-解码器模型有 *T5*、*Bart*、*MarianMT* 和 *Pegasus*，它们在文档的[模型总结](https://huggingface.co/transformers/model_summary.html#sequence-to-sequence-models)下有概述。

本文分为四个部分：

- **背景** - *简要介绍神经编码器-解码模型的历史，重点在基于 RNN 的模型。*
- **编码器-解码器** - *介绍基于 transformer 的编码器-解码器模型，并解释模型如何用于推理。*
- **编码器** - *详细解释模型的编码器部分。*
- **解码器** - *详细解释模型的解码器部分。*

每个部分都建立在前一部分之上，但也可以独立阅读。

## **背景**

自然语言生成（NLG，NLP 的一个子领域）中的任务最适合表达为序列到序列问题。这类任务可以定义为：寻找一个模型，把一串输入词映射到一串目标词。一些经典例子是*摘要*和*翻译*。下面我们假设每个词都被编码成一个向量表示。nnn 个输入词可以表示为一串 nnn 个输入向量：

X1:n={x1,…,xn}.\mathbf{X}_{1:n} = \{\mathbf{x}_1, \ldots, \mathbf{x}_n\}.X1:n​={x1​,…,xn​}.

因此，序列到序列问题可以通过寻找一个从 nnn 个向量组成的输入序列 X1:n\mathbf{X}_{1:n}X1:n​ 到 mmm 个目标向量序列 Y1:m\mathbf{Y}_{1:m}Y1:m​ 的映射 fff 来解决，其中目标向量的数量 mmm 是先验未知的、取决于输入序列：

f:X1:n→Y1:m. f: \mathbf{X}_{1:n} \to \mathbf{Y}_{1:m}. f:X1:n​→Y1:m​.

[Sutskever et al. (2014)](https://arxiv.org/abs/1409.3215) 指出，深度神经网络（DNN）"*尽管有其灵活性和强大之处，却只能定义输入和目标都能以固定维度的向量合理编码的映射。*" 1{}^11

因此，用 DNN 模型 2{}^22 来解决序列到序列问题，就意味着目标向量的数量 mmm 必须先验已知、并且必须与输入 X1:n\mathbf{X}_{1:n}X1:n​ 无关。这是次优的，因为在 NLG 任务中，目标词的数量通常取决于输入 X1:n\mathbf{X}_{1:n}X1:n​，而不仅仅是输入长度 nnn。*E.g.*，一篇 1000 词的文章，根据其内容可以被摘要成 200 词，也可以被摘要成 100 词。

2014 年，[Cho et al.](https://arxiv.org/pdf/1406.1078.pdf) 和 [Sutskever et al.](https://arxiv.org/abs/1409.3215) 提出用纯基于循环神经网络（RNN）的编码器-解码器模型来做*序列到序列*任务。与 DNN 不同，RNN 能够建模到可变数量目标向量的映射。让我们更深入地看看基于 RNN 的编码器-解码器模型如何工作。

在推理时，编码器 RNN 通过不断*逐步更新其隐藏状态* 3{}^33 来编码输入序列 X1:n\mathbf{X}_{1:n}X1:n​。在处理完最后一个输入向量 xn\mathbf{x}_nxn​ 之后，编码器的隐藏状态就定义了输入编码 c\mathbf{c}c。因此编码器定义了映射：

fθenc:X1:n→c. f_{\theta_{enc}}: \mathbf{X}_{1:n} \to \mathbf{c}. fθenc​​:X1:n​→c.

随后，解码器的隐藏状态用输入编码初始化，在推理时，解码器 RNN 被用来自回归地生成目标序列。下面解释。

数学上，解码器定义了给定隐藏状态 c\mathbf{c}c 时目标序列 Y1:m\mathbf{Y}_{1:m}Y1:m​ 的概率分布：

pθdec(Y1:m∣c). p_{\theta_{dec}}(\mathbf{Y}_{1:m} |\mathbf{c}). pθdec​​(Y1:m​∣c).

根据贝叶斯法则，该分布可以分解为单个目标向量条件分布的乘积：

pθdec(Y1:m∣c)=∏i=1mpθdec(yi∣Y0:i−1,c). p_{\theta_{dec}}(\mathbf{Y}_{1:m} |\mathbf{c}) = \prod_{i=1}^{m} p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{c}). pθdec​​(Y1:m​∣c)=i=1∏m​pθdec​​(yi​∣Y0:i−1​,c).

因此，如果架构能建模下一个目标向量在给定所有先前目标向量条件下的分布：

pθdec(yi∣Y0:i−1,c),∀i∈{1,…,m}, p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{c}), \forall i \in \{1, \ldots, m\},pθdec​​(yi​∣Y0:i−1​,c),∀i∈{1,…,m},

那么它只需把所有条件概率相乘，就能建模给定隐藏状态 c\mathbf{c}c 时任意目标向量序列的分布。

那么基于 RNN 的解码器架构是如何建模 pθdec(yi∣Y0:i−1,c)p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{c})pθdec​​(yi​∣Y0:i−1​,c) 的呢？

在计算上，该模型把先前的内部隐藏状态 ci−1\mathbf{c}_{i-1}ci−1​ 和先前的目标向量 yi−1\mathbf{y}_{i-1}yi−1​ 逐步映射到当前的内部隐藏状态 ci\mathbf{c}_ici​ 和一个*logit 向量* li\mathbf{l}_ili​（下面用深红色标出）：

fθdec(yi−1,ci−1)→li,ci. f_{\theta_{\text{dec}}}(\mathbf{y}_{i-1}, \mathbf{c}_{i-1}) \to \mathbf{l}_i, \mathbf{c}_i.fθdec​​(yi−1​,ci−1​)→li​,ci​. 其中 c0\mathbf{c}_0c0​ 被定义为基于 RNN 的编码器输出隐藏状态 c\mathbf{c}c。随后用 *softmax* 操作把 logit 向量 li\mathbf{l}_ili​ 转换为下一个目标向量的条件概率分布：

p(yi∣li)=Softmax(li), with li=fθdec(yi−1,cprev). p(\mathbf{y}_i | \mathbf{l}_i) = \textbf{Softmax}(\mathbf{l}_i), \text{ with } \mathbf{l}_i = f_{\theta_{\text{dec}}}(\mathbf{y}_{i-1}, \mathbf{c}_{\text{prev}}). p(yi​∣li​)=Softmax(li​), with li​=fθdec​​(yi−1​,cprev​).

关于 logit 向量及得到的概率分布的细节，请见脚注 4{}^44。从上面的等式可以看出，当前目标向量 yi\mathbf{y}_iyi​ 的分布*直接*取决于先前的目标向量 yi−1\mathbf{y}_{i-1}yi−1​ 和先前的隐藏状态 ci−1\mathbf{c}_{i-1}ci−1​。因为先前的隐藏状态 ci−1\mathbf{c}_{i-1}ci−1​ 取决于所有先前的目标向量 y0,…,yi−2\mathbf{y}_0, \ldots, \mathbf{y}_{i-2}y0​,…,yi−2​，所以可以说基于 RNN 的解码器*隐式地*（*e.g.* *间接地*）建模了条件分布 pθdec(yi∣Y0:i−1,c)p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{c})pθdec​​(yi​∣Y0:i−1​,c)。

可能的目标向量序列 Y1:m\mathbf{Y}_{1:m}Y1:m​ 空间大得令人望而却步，因此在推理时必须依赖高效的解码方法 5{}^55 从 pθdec(Y1:m∣c)p_{\theta_{dec}}(\mathbf{Y}_{1:m} |\mathbf{c})pθdec​​(Y1:m​∣c) 中采样高概率的目标向量序列。

给定这样一套解码方法后，在推理时，下一个输入向量 yi\mathbf{y}_iyi​ 可以从 pθdec(yi∣Y0:i−1,c)p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{c})pθdec​​(yi​∣Y0:i−1​,c) 采样，从而被附加到输入序列上，于是解码器 RNN 接着建模 pθdec(yi+1∣Y0:i,c)p_{\theta_{dec}}(\mathbf{y}_{i+1} | \mathbf{Y}_{0: i}, \mathbf{c})pθdec​​(yi+1​∣Y0:i​,c) 以采样下一个输入向量 yi+1\mathbf{y}_{i+1}yi+1​，如此*自回归*地继续。

基于 RNN 的编码器-解码器模型一个重要特征是定义了*特殊*向量，比如 EOS\text{EOS}EOS 和 BOS\text{BOS}BOS 向量。EOS\text{EOS}EOS 向量常常表示最后一个输入向量 xn\mathbf{x}_nxn​，用来"提示"编码器输入序列已经结束，同时也定义目标序列的结束。一旦从某个 logit 向量采样出 EOS\text{EOS}EOS，生成就完成了。BOS\text{BOS}BOS 向量表示在第一个解码步送给解码器 RNN 的输入向量 y0\mathbf{y}_0y0​。要输出第一个 logit l1\mathbf{l}_1l1​ 需要一个输入，而在第一步还没有生成任何输入，所以把一个特殊的 BOS\text{BOS}BOS 输入向量送给解码器 RNN。好——挺复杂的！让我们来图解并走一遍例子。

## **编码器-解码器**

2017 年，Vaswani 等人引入了 **Transformer**，由此催生了*基于 transformer* 的编码器-解码器模型。

与基于 RNN 的编码器-解码器模型类似，基于 transformer 的编码器-解码器模型由编码器和解码器组成，两者都是*残差注意力块*的堆叠。基于 transformer 的编码器-解码器模型的关键创新在于，这样的残差注意力块可以处理可变长度 nnn 的输入序列 X1:n\mathbf{X}_{1:n}X1:n​，而不呈现循环结构。不依赖循环结构使得基于 transformer 的编码器-解码器高度可并行，这让它 Modern 硬件上比基于 RNN 的编码器-解码器模型高出数个数量级的计算效率。

回顾一下，要解决一个*序列到序列*问题，我们需要找到从输入序列 X1:n\mathbf{X}_{1:n}X1:n​ 到可变长度 mmm 的输出序列 Y1:m\mathbf{Y}_{1:m}Y1:m​ 的映射。来看看基于 transformer 的编码器-解码器模型是如何被用来找到这样的映射的。

与基于 RNN 的编码器-解码器模型类似，基于 transformer 的编码器-解码器模型定义了给定输入序列 X1:n\mathbf{X}_{1:n}X1:n​ 时目标向量 Y1:m\mathbf{Y}_{1:m}Y1:m​ 的条件分布：

pθenc,θdec(Y1:m∣X1:n). p_{\theta_{\text{enc}}, \theta_{\text{dec}}}(\mathbf{Y}_{1:m} | \mathbf{X}_{1:n}). pθenc​,θdec​​(Y1:m​∣X1:n​).

基于 transformer 的编码器部分把输入序列 X1:n\mathbf{X}_{1:n}X1:n​ 编码为一串*隐藏状态* X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​，从而定义映射：

fθenc:X1:n→X‾1:n. f_{\theta_{\text{enc}}}: \mathbf{X}_{1:n} \to \mathbf{\overline{X}}_{1:n}. fθenc​​:X1:n​→X1:n​.

基于 transformer 的解码器部分随后建模给定编码隐藏状态序列 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ 时目标向量序列 Y1:n\mathbf{Y}_{1:n}Y1:n​ 的条件概率分布：

pθdec(Y1:n∣X‾1:n). p_{\theta_{dec}}(\mathbf{Y}_{1:n} | \mathbf{\overline{X}}_{1:n}).pθdec​​(Y1:n​∣X1:n​).

由贝叶斯法则，这个分布可以因子分解为给定编码隐藏状态 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ 和所有先前目标向量 Y0:i−1\mathbf{Y}_{0:i-1}Y0:i−1​ 时目标向量 yi\mathbf{y}_iyi​ 的条件概率分布的乘积：

pθdec(Y1:n∣X‾1:n)=∏i=1npθdec(yi∣Y0:i−1,X‾1:n). p_{\theta_{dec}}(\mathbf{Y}_{1:n} | \mathbf{\overline{X}}_{1:n}) = \prod_{i=1}^{n} p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{\overline{X}}_{1:n}). pθdec​​(Y1:n​∣X1:n​)=i=1∏n​pθdec​​(yi​∣Y0:i−1​,X1:n​).

基于 transformer 的解码器在此把编码隐藏状态序列 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ 和所有先前目标向量 Y0:i−1\mathbf{Y}_{0:i-1}Y0:i−1​ 映射到*logit* 向量 li\mathbf{l}_ili​。logit 向量 li\mathbf{l}_ili​ 随后由 *softmax* 操作处理，以定义条件分布 pθdec(yi∣Y0:i−1,X‾1:n)p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{\overline{X}}_{1:n})pθdec​​(yi​∣Y0:i−1​,X1:n​)，正如基于 RNN 的解码器所做的那样。然而，与基于 RNN 的解码器不同，目标向量 yi\mathbf{y}_iyi​ 的分布是*显式地*（或直接地）条件化于所有先前目标向量 y0,…,yi−1\mathbf{y}_0, \ldots, \mathbf{y}_{i-1}y0​,…,yi−1​ 的，我们稍后会看到更多细节。其中第 0 个目标向量 y0\mathbf{y}_0y0​ 由一个特殊的"begin-of-sentence" BOS\text{BOS}BOS 向量表示。

定义了条件分布 pθdec(yi∣Y0:i−1,X‾1:n)p_{\theta_{\text{dec}}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{\overline{X}}_{1:n})pθdec​​(yi​∣Y0:i−1​,X1:n​) 之后，我们现在可以在推理时*自回归*地生成输出，从而定义从输入序列 X1:n\mathbf{X}_{1:n}X1:n​ 到输出序列 Y1:m\mathbf{Y}_{1:m}Y1:m​ 的映射。

一开始，编码器处理完整的输入序列 X1:7\mathbf{X}_{1:7}X1:7​ = "I want to buy a car"（用浅绿向量表示）得到上下文化编码序列 X‾1:7\mathbf{\overline{X}}_{1:7}X1:7​。*E.g.* x‾4\mathbf{\overline{x}}_4x4​ 定义的编码不仅取决于输入 x4\mathbf{x}_4x4​ = "buy"，还取决于所有其他词 "I"、"want"、"to"、"a"、"car" 和 "EOS"，*i.e.* 上下文。

pθenc,dec(y∣y0,X1:7)=pθenc,dec(y∣BOS,I want to buy a car EOS)=pθdec(y∣BOS,X‾1:7). p_{\theta_{enc, dec}}(\mathbf{y} | \mathbf{y}_0, \mathbf{X}_{1:7}) = p_{\theta_{enc, dec}}(\mathbf{y} | \text{BOS}, \text{I want to buy a car EOS}) = p_{\theta_{dec}}(\mathbf{y} | \text{BOS}, \mathbf{\overline{X}}_{1:7}). pθenc,dec​​(y∣y0​,X1:7​)=pθenc,dec​​(y∣BOS,I want to buy a car EOS)=pθdec​​(y∣BOS,X1:7​).

随后第一个目标向量 y1\mathbf{y}_1y1​ = Ich\text{Ich}Ich 从分布中采样得到（用灰色箭头表示，连接 l1\mathbf{l}_1l1​ 和 y1\mathbf{y}_1y1​），现在可以再次喂给解码器。解码器此时处理 y0\mathbf{y}_0y0​ = "BOS" 和 y1\mathbf{y}_1y1​ = "Ich" 两者，以定义第二个目标向量 y2\mathbf{y}_2y2​ 的条件分布：

```
# decode and print
print(tokenizer.decode(output_ids))
```

*输出：*

```

```

## **编码器**

如上一节所述，*基于 transformer* 的编码器把输入序列映射为上下文化编码序列：

fθenc:X1:n→X‾1:n. f_{\theta_{\text{enc}}}: \mathbf{X}_{1:n} \to \mathbf{\overline{X}}_{1:n}. fθenc​​:X1:n​→X1:n​.

更仔细地看架构，基于 transformer 的编码器是残差*编码器块*的堆叠。每个编码器块由一个**双向**自注意力层、后接两个前馈层组成。为简单起见，我们在本文中忽略归一化层。我们也不进一步讨论两个前馈层的作用，而只是把它看作每个编码器块中所需的最后一次向量到向量的映射 1{}^11。双向自注意力层把每个输入向量 x′j,∀j∈{1,…,n}\mathbf{x'}_j, \forall j \in \{1, \ldots, n\}x′j​,∀j∈{1,…,n} 与所有输入向量 x′1,…,x′n\mathbf{x'}_1, \ldots, \mathbf{x'}_nx′1​,…,x′n​ 联系起来，并借此把输入向量 x′j\mathbf{x'}_jx′j​ 转换为它自己更"精炼"的上下文表示，记作 x′′j\mathbf{x''}_jx′′j​。这样，第一个编码器块把输入序列 X1:n\mathbf{X}_{1:n}X1:n​ 的每个输入向量（下方用浅绿标出）从*上下文无关*的向量表示转换为*上下文相关*的向量表示，随后的编码器块进一步精炼这一上下文表示，直到最后一个编码器块输出最终的上下文化编码 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​（下方用较深的绿色标出）。

要进一步理解双向自注意力层的影响，假设处理下面这句话："*The house is beautiful and well located in the middle of the city where it is easily accessible by public transport*"。词 "it" 指代 "house"，二者相距 12 个"位置"。在基于 transformer 的编码器中，双向自注意力层只需执行一次数学操作，就能把 "house" 的输入向量与 "it" 的输入向量建立关系（对照本节第一张插图）。相比之下，在基于 RNN 的编码器中，相距 12 个"位置"的词至少需要 12 次数学操作，也就是说基于 RNN 的编码器需要线性数量的数学操作。这使得基于 RNN 的编码器更难建模长程上下文化表示。同时也很清楚，基于 transformer 的编码器比基于 RNN 的编码器-解码器模型更不容易丢失重要信息，因为编码的序列长度被保持不变，*i.e.* len(X1:n)=len(X‾1:n)=n\textbf{len}(\mathbf{X}_{1:n}) = \textbf{len}(\mathbf{\overline{X}}_{1:n}) = nlen(X1:n​)=len(X1:n​)=n，而 RNN 把长度从 ∗len((X1:n)=n*\textbf{len}((\mathbf{X}_{1:n}) = n∗len((X1:n​)=n 压缩到只有 len(c)=1\textbf{len}(\mathbf{c}) = 1len(c)=1，这使得 RNN 很难有效地编码输入词之间的长程依赖。

除了让长程依赖更易学习，我们还可以看到 Transformer 架构能够并行处理文本。数学上，把自注意力公式写成 query、key、value 矩阵的乘积就很容易看出：

X′′1:n=V1:nSoftmax(Q1:n⊺K1:n)+X′1:n.\mathbf{X''}_{1:n} = \mathbf{V}_{1:n} \text{Softmax}(\mathbf{Q}_{1:n}^\intercal \mathbf{K}_{1:n}) + \mathbf{X'}_{1:n}. X′′1:n​=V1:n​Softmax(Q1:n⊺​K1:n​)+X′1:n​.

输出 X′′1:n=x′′1,…,x′′n\mathbf{X''}_{1:n} = \mathbf{x''}_1, \ldots, \mathbf{x''}_nX′′1:n​=x′′1​,…,x′′n​ 是通过一系列矩阵乘法和 softmax 操作计算的，可以高效并行化。注意，在基于 RNN 的编码器模型中，隐藏状态 c\mathbf{c}c 的计算必须顺序进行：先算第一个输入向量 x1\mathbf{x}_1x1​ 的隐藏状态，再算依赖于第一个隐藏状态的第二个输入向量的隐藏状态，依此类推。RNN 的顺序性质阻碍了高效并行化，使其在现代 GPU 硬件上比基于 transformer 的编码器模型低效得多。

很好，现在我们应该更好地理解 a) 基于 transformer 的编码器模型如何有效地建模长程上下文化表示，以及 b) 它们如何高效地处理长输入向量序列。

现在，让我们用代码写一个关于 `MarianMT` 编码器-解码器模型编码器部分的简短示例，验证所讲理论在实践中成立。

1{}^11 关于前馈层在基于 transformer 的模型中扮演什么角色的详细解释超出了本文范围。[Yun et. al, (2017)](https://arxiv.org/pdf/1912.10077.pdf) 认为前馈层对于把每个上下文向量 x′i\mathbf{x'}_ix′i​ 单独映射到期望的输出空间至关重要，而*自注意力*层独自做不到这一点。这里应注意到，每个输出 token x′\mathbf{x'}x′ 都由同一个前馈层处理。更多细节建议阅读该论文。

2{}^22 然而，EOS 输入向量并非必须附加到输入序列，但已被证明在很多情况下能提升性能。与之对比，基于 transformer 的解码器的*第 0 个* BOS\text{BOS}BOS 目标向量是必需的，作为预测第一个目标向量的起始输入向量。

```
from transformers import MarianMTModel, MarianTokenizer
import torch

tokenizer = MarianTokenizer.from_pretrained("Helsinki-NLP/opus-mt-en-de")
model = MarianMTModel.from_pretrained("Helsinki-NLP/opus-mt-en-de")

embeddings = model.get_input_embeddings()

# create ids of encoded input vectors
input_ids = tokenizer("I want to buy a car", return_tensors="pt").input_ids

# pass input_ids to encoder
encoder_hidden_states = model.base_model.encoder(input_ids, return_dict=True).last_hidden_state

# change the input slightly and pass to encoder
input_ids_perturbed = tokenizer("I want to buy a house", return_tensors="pt").input_ids
encoder_hidden_states_perturbed = model.base_model.encoder(input_ids_perturbed, return_dict=True).last_hidden_state

# compare shape and encoding of first vector
print(f"Length of input embeddings {embeddings(input_ids).shape[1]}. Length of encoder_hidden_states {encoder_hidden_states.shape[1]}")

# compare values of word embedding of "I" for input_ids and perturbed input_ids
print("Is encoding for `I` equal to its perturbed version?: ", torch.allclose(encoder_hidden_states[0, 0], encoder_hidden_states_perturbed[0, 0], atol=1e-3))
```

*输出：*

```
    Length of input embeddings 7. Length of encoder_hidden_states 7
    Is encoding for `I` equal to its perturbed version?:  False
```

我们把输入词嵌入的长度，*i.e.* `embeddings(input_ids)`（对应 X1:n\mathbf{X}_{1:n}X1:n​），与 `encoder_hidden_states` 的长度（对应 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​）比较。我们还把词序列 "I want to buy a car" 及其轻微扰动的版本 "I want to buy a house" 送过编码器，以检查当输入序列中只改动最后一个词时，对应 "I" 的第一个输出编码是否不同。

如预期，输入词嵌入和编码器输出编码的长度，*i.e.* len(X1:n)\textbf{len}(\mathbf{X}_{1:n})len(X1:n​) 和 len(X‾1:n)\textbf{len}(\mathbf{\overline{X}}_{1:n})len(X1:n​)，是相等的。其次，可以注意到当最后一个词从 "car" 改为 "house" 时，x‾1="I"\mathbf{\overline{x}}_1 = \text{"I"}x1​="I" 的编码向量值是不同的。但如果理解了双向自注意力，这并不令人意外。

顺带一提，*自编码（autoencoding）*模型，比如 BERT，与*基于 transformer* 的编码器模型有完全相同的架构。*自编码*模型利用这一架构在开放域文本数据上做大规模自监督预训练，从而能把任意词序列映射到深度双向表示。在 [Devlin et al. (2018)](https://arxiv.org/abs/1810.04805) 中，作者展示了一个预训练的 BERT 模型加上一个任务专属的分类层就能在十一个 NLP 任务上取得 SOTA 结果。🤗Transformers 中所有*自编码*模型可见[这里](https://huggingface.co/transformers/model_summary.html#autoencoding-models)。

## **解码器**

如在*编码器-解码器*一节所述，*基于 transformer* 的解码器定义了给定上下文化编码序列时目标序列的条件概率分布：

pθdec(Y1:m∣X‾1:n), p_{\theta_{dec}}(\mathbf{Y}_{1: m} | \mathbf{\overline{X}}_{1:n}), pθdec​​(Y1:m​∣X1:n​),

它可由贝叶斯法则分解为给定上下文化编码序列和所有先前目标向量时下一个目标向量条件分布的乘积：

pθdec(Y1:m∣X‾1:n)=∏i=1mpθdec(yi∣Y0:i−1,X‾1:n). p_{\theta_{dec}}(\mathbf{Y}_{1:m} | \mathbf{\overline{X}}_{1:n}) = \prod_{i=1}^{m} p_{\theta_{dec}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{\overline{X}}_{1:n}). pθdec​​(Y1:m​∣X1:n​)=i=1∏m​pθdec​​(yi​∣Y0:i−1​,X1:n​).

让我们先理解基于 transformer 的解码器如何定义一个概率分布。基于 transformer 的解码器是*解码器块*的堆叠，后接一个稠密层"LM head"。解码器块堆叠把上下文化编码序列 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ 和一个由 BOS\text{BOS}BOS 向量前缀、并截到最后一个目标向量的目标向量序列（*i.e.* Y0:i−1\mathbf{Y}_{0:i-1}Y0:i−1​）映射为编码后的目标向量序列 Y‾0:i−1\mathbf{\overline{Y}}_{0: i-1}Y0:i−1​。然后"LM head"把编码后的目标向量序列 Y‾0:i−1\mathbf{\overline{Y}}_{0: i-1}Y0:i−1​ 映射为 logit 向量序列 L1:n=l1,…,ln\mathbf{L}_{1:n} = \mathbf{l}_1, \ldots, \mathbf{l}_nL1:n​=l1​,…,ln​，其中每个 logit 向量 li\mathbf{l}_ili​ 的维度对应词表的大小。这样，对于每个 i∈{1,…,n}i \in \{1, \ldots, n\}i∈{1,…,n}，通过对 li\mathbf{l}_ili​ 应用 softmax 操作就能得到整个词表上的概率分布。这些分布各自定义了条件分布：

pθdec(yi∣Y0:i−1,X‾1:n),∀i∈{1,…,n},p_{\theta_{dec}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{\overline{X}}_{1:n}), \forall i \in \{1, \ldots, n\},pθdec​​(yi​∣Y0:i−1​,X1:n​),∀i∈{1,…,n},

"LM head" 常常与词嵌入矩阵的转置绑定，*i.e.* Wemb⊺=[y1,…,yvocab]⊺\mathbf{W}_{\text{emb}}^{\intercal} = \left[\mathbf{y}^1, \ldots, \mathbf{y}^{\text{vocab}}\right]^{\intercal}Wemb⊺​=[y1,…,yvocab]⊺ 1{}^11。直观地说，这意味着对于所有 i∈{0,…,n−1}i \in \{0, \ldots, n - 1\}i∈{0,…,n−1}，"LM Head" 层把编码输出向量 y‾i\mathbf{\overline{y}}_iy​i​ 与词表中所有词嵌入 y1,…,yvocab\mathbf{y}^1, \ldots, \mathbf{y}^{\text{vocab}}y1,…,yvocab 比较，从而 logit 向量 li+1\mathbf{l}_{i+1}li+1​ 表示编码输出向量与每个词嵌入之间的相似度分数。softmax 操作只是把相似度分数转换为概率分布。对于每个 i∈{1,…,n}i \in \{1, \ldots, n\}i∈{1,…,n}，下列等式成立：

pθdec(y∣X‾1:n,Y0:i−1) p_{\theta_{dec}}(\mathbf{y} | \mathbf{\overline{X}}_{1:n}, \mathbf{Y}_{0:i-1})pθdec​​(y∣X1:n​,Y0:i−1​) =Softmax(fθdec(X‾1:n,Y0:i−1)) = \text{Softmax}(f_{\theta_{\text{dec}}}(\mathbf{\overline{X}}_{1:n}, \mathbf{Y}_{0:i-1}))=Softmax(fθdec​​(X1:n​,Y0:i−1​)) =Softmax(Wemb⊺y‾i−1) = \text{Softmax}(\mathbf{W}_{\text{emb}}^{\intercal} \mathbf{\overline{y}}_{i-1})=Softmax(Wemb⊺​y​i−1​) =Softmax(li). = \text{Softmax}(\mathbf{l}_i). =Softmax(li​).

把这一切合在一起，为了建模目标向量序列 Y1:m\mathbf{Y}_{1: m}Y1:m​ 的条件分布，由特殊 BOS\text{BOS}BOS 向量（*i.e.* y0\mathbf{y}_0y0​）前缀的目标向量 Y1:m−1\mathbf{Y}_{1:m-1}Y1:m−1​ 首先与上下文化编码序列 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ 一起被映射为 logit 向量序列 L1:m\mathbf{L}_{1:m}L1:m​。 consequently，每个 logit 目标向量 li\mathbf{l}_ili​ 用 softmax 操作转换为目标向量 yi\mathbf{y}_iyi​ 的条件概率分布。最后，所有目标向量 y1,…,ym\mathbf{y}_1, \ldots, \mathbf{y}_my1​,…,ym​ 的条件概率相乘，得到完整目标向量序列的条件概率：

pθdec(Y1:m∣X‾1:n)=∏i=1mpθdec(yi∣Y0:i−1,X‾1:n). p_{\theta_{dec}}(\mathbf{Y}_{1:m} | \mathbf{\overline{X}}_{1:n}) = \prod_{i=1}^{m} p_{\theta_{dec}}(\mathbf{y}_i | \mathbf{Y}_{0: i-1}, \mathbf{\overline{X}}_{1:n}).pθdec​​(Y1:m​∣X1:n​)=i=1∏m​pθdec​​(yi​∣Y0:i−1​,X1:n​).

与基于 transformer 的编码器不同，在基于 transformer 的解码器中，编码输出向量 y‾i\mathbf{\overline{y}}_iy​i​ 应当是*下一个*目标向量 yi+1\mathbf{y}_{i+1}yi+1​ 的良好表示，而不仅仅是输入向量本身的表示。另外，编码输出向量 y‾i\mathbf{\overline{y}}_iy​i​ 应当条件化于所有上下文化编码序列 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​。为了满足这些要求，每个解码器块由一个**单向**自注意力层、后接一个**交叉注意力**层和两个前馈层 2{}^22 组成。单向自注意力层只把它的每个输入向量 y′j\mathbf{y'}_jy′j​ 与所有先前的输入向量 y′i, with i≤j\mathbf{y'}_i, \text{ with } i \le jy′i​, with i≤j 建立关系（对所有 j∈{1,…,n}j \in \{1, \ldots, n\}j∈{1,…,n}）以建模下一个目标向量的概率分布。交叉注意力层把它的每个输入向量 y′′j\mathbf{y''}_jy′′j​ 与所有上下文化编码向量 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ 建立关系，从而也把下一个目标向量的概率分布条件化于编码器的输入。

可以看到 y′′1\mathbf{y''}_1y′′1​ 只依赖于 y′0\mathbf{y'}_0y′0​ 和 y′1\mathbf{y'}_1y′1​。因此我们把 "Ich" 的向量表示（*i.e.* y′1\mathbf{y'}_1y′1​）只与它自身和 "BOS" 目标向量（*i.e.* y′0\mathbf{y'}_0y′0​）建立关系，而**不**与 "will" 的向量表示（*i.e.* y′2\mathbf{y'}_2y′2​）建立关系。

那么为什么解码器里用单向自注意力而不是双向自注意力很重要？如上所述，基于 transformer 的解码器定义从输入向量序列 Y0:m−1\mathbf{Y}_{0: m-1}Y0:m−1​ 到对应于**下一个**解码器输入向量（即 L1:m\mathbf{L}_{1:m}L1:m​）的 logits 的映射。在我们的例子里，这意味着 *e.g.* 输入向量 y1\mathbf{y}_1y1​ = "Ich" 被映射为 logit 向量 l2\mathbf{l}_2l2​，后者用于预测输入向量 y2\mathbf{y}_2y2​。因此，如果 y′1\mathbf{y'}_1y′1​ 能访问后续输入向量 Y′2:5\mathbf{Y'}_{2:5}Y′2:5​，解码器就会简单地把 "will" 的向量表示（*i.e.* y′2\mathbf{y'}_2y′2​）复制为其输出 y′′1\mathbf{y''}_1y′′1​。这会被传到最后一层，使得编码输出向量 y‾1\mathbf{\overline{y}}_1y​1​ 本质上只对应向量表示 y2\mathbf{y}_2y2​。

这显然是不利的——基于 transformer 的解码器将永远学不到在给定所有先前词的情况下预测下一个词，而只会把目标向量 yi\mathbf{y}_iyi​ 通过网络复制为 y‾i−1\mathbf{\overline{y}}_{i-1}y​i−1​（对所有 i∈{1,…,m}i \in \{1, \ldots, m \}i∈{1,…,m}）。为了定义下一个目标向量的条件分布，该分布不能被条件化于下一个目标向量本身。从 p(y∣Y0:i,X‾)p(\mathbf{y} | \mathbf{Y}_{0:i}, \mathbf{\overline{X}})p(y∣Y0:i​,X) 预测 yi\mathbf{y}_iyi​ 没有意义，因为该分布被条件化在它本应建模的目标向量上。因此，单向自注意力架构使我们能够定义一个*因果（causal）*概率分布，而这对于有效建模下一个目标向量的条件分布是必需的。

很好！现在我们可以来看连接编码器和解码器的那一层——*交叉注意力*机制！

交叉注意力层接受两串向量序列作为输入：单向自注意力层的输出，即 Y′′0:m−1\mathbf{Y''}_{0: m-1}Y′′0:m−1​，以及上下文化编码向量 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​。和在自注意力层一样，query 向量 q0,…,qm−1\mathbf{q}_0, \ldots, \mathbf{q}_{m-1}q0​,…,qm−1​ 是上一层输出向量 Y′′0:m−1\mathbf{Y''}_{0: m-1}Y′′0:m−1​ 的投影。然而 key 和 value 向量 k0,…,km−1\mathbf{k}_0, \ldots, \mathbf{k}_{m-1}k0​,…,km−1​ 和 v0,…,vm−1\mathbf{v}_0, \ldots, \mathbf{v}_{m-1}v0​,…,vm−1​ 是上下文化编码向量 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ 的投影。定义了 key、value 和 query 向量之后，query 向量 qi\mathbf{q}_iqi​ 与*所有* key 向量比较，对应分数用于加权相应的 value 向量，正如*双向*自注意力中所做的那样，为所有 i∈0,…,m−1i \in {0, \ldots, m-1}i∈0,…,m−1 给出输出向量 y′′′i\mathbf{y'''}_iy′′′i​。交叉注意力可以总结如下：

y′′′i=V1:nSoftmax(K1:n⊺qi)+y′′i. \mathbf{y'''}_i = \mathbf{V}_{1:n} \textbf{Softmax}(\mathbf{K}_{1: n}^\intercal \mathbf{q}_i) + \mathbf{y''}_i. y′′′i​=V1:n​Softmax(K1:n⊺​qi​)+y′′i​.

注意 key 和 value 向量的索引范围是 1:n1:n1:n，对应上下文化编码向量的数量。

让我们为我们上面例子的输入向量 y′′1\mathbf{y''}_1y′′1​ 图示交叉注意力机制。

[![](https://raw.githubusercontent.com/patrickvonplaten/scientific_images/master/encoder_decoder/cross_attention.png)](https://raw.githubusercontent.com/patrickvonplaten/scientific_images/master/encoder_decoder/cross_attention.png)

我们可以看到 query 向量 q1\mathbf{q}_1q1​（紫色）由 y′′1\mathbf{y''}_1y′′1​（红色）导出，因而依赖于 "Ich" 一词的向量表示。query 向量 q1\mathbf{q}_1q1​ 随后与 key 向量 k1,…,k7\mathbf{k}_1, \ldots, \mathbf{k}_7k1​,…,k7​（黄色）比较，后者对应所有编码器输入向量 X1:n\mathbf{X}_{1:n}X1:n​ = "I want to buy a car EOS" 的上下文化编码表示。这就把 "Ich" 的向量表示直接放到与所有编码器输入向量的关系中。最后，注意力权重乘以 value 向量 v1,…,v7\mathbf{v}_1, \ldots, \mathbf{v}_7v1​,…,v7​（青绿色），在输入向量 y′′1\mathbf{y''}_1y′′1​ 之外给出输出向量 y′′′1\mathbf{y'''}_1y′′′1​（深红）。

那么直觉上，这里到底发生了什么？每个输出向量 y′′′i\mathbf{y'''}_iy′′′i​ 是所有编码器输入 value 投影 v1,…,v7\mathbf{v}_{1}, \ldots, \mathbf{v}_7v1​,…,v7​ 的加权和再加上输入向量本身 y′′i\mathbf{y''}_iy′′i​（*c.f.* 上面图示的公式）。要理解的关键机制是：*解码器输入向量*的 query 投影 qi\mathbf{q}_iqi​ 与*编码器输入向量* kj\mathbf{k}_jkj​ 的 key 投影越相似，编码器输入向量 vj\mathbf{v}_jvj​ 的 value 投影就越重要。粗略地说，这意味着一个解码器输入表示与某个编码器输入表示越"相关"，该输入表示对解码器输出表示的影响就越大。

好！现在我们可以看到这个架构如何巧妙地把每个输出向量 y′′′i\mathbf{y'''}_iy′′′i​ 条件化于编码器输入向量 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ 与输入向量 y′′i\mathbf{y''}_iy′′i​ 之间的相互作用上。在这一点上另一个重要观察是，该架构完全独立于输出向量 y′′′i\mathbf{y'''}_iy′′′i​ 所条件化于的上下文化编码向量 X‾1:n\mathbf{\overline{X}}_{1:n}X1:n​ 的数量 nnn。用于导出 key 向量 k1,…,kn\mathbf{k}_1, \ldots, \mathbf{k}_nk1​,…,kn​ 和 value 向量 v1,…,vn\mathbf{v}_1, \ldots, \mathbf{v}_nv1​,…,vn​ 的所有投影矩阵 Wkcross\mathbf{W}^{\text{cross}}_{k}Wkcross​ 和 Wvcross\mathbf{W}^{\text{cross}}_{v}Wvcross​ 在位置 1,…,n1, \ldots, n1,…,n 之间共享，所有 value 向量 v1,…,vn \mathbf{v}_1, \ldots, \mathbf{v}_n v1​,…,vn​ 求和为一个加权平均向量。现在也很清楚，为什么基于 transformer 的解码器不像基于 RNN 的解码器那样受长程依赖问题困扰。因为每个解码器 logit 向量都*直接*依赖于每一个编码输出向量，比较第一个编码输出向量和最后一个解码器 logit 向量所需的数学操作数本质上只有一个。

总之，单向自注意力层负责把每个输出向量条件化于所有先前的解码器输入向量和当前输入向量，而交叉注意力层负责进一步把每个输出向量条件化于所有编码输入向量。

为验证我们的理论理解，让我们继续上面编码器一节的代码示例。

1{}^11 词嵌入矩阵 Wemb\mathbf{W}_{\text{emb}}Wemb​ 给每个输入词一个唯一的*上下文无关*向量表示。这个矩阵常常被固定为"LM Head"层。然而，"LM Head" 层也完全可以由一个完全独立的"编码向量到 logit"的权重映射构成。

2{}^22 同样，关于前馈层在基于 transformer 的模型中扮演什么角色的详细解释超出了本文范围。[Yun et. al, (2017)](https://arxiv.org/pdf/1912.10077.pdf) 认为前馈层对于把每个上下文向量 x′i\mathbf{x'}_ix′i​ 单独映射到期望的输出空间至关重要，而*自注意力*层独自做不到这一点。这里应注意到，每个输出 token x′\mathbf{x'}x′ 都由同一个前馈层处理。更多细节建议阅读该论文。

```
from transformers import MarianMTModel, MarianTokenizer
import torch

tokenizer = MarianTokenizer.from_pretrained("Helsinki-NLP/opus-mt-en-de")
model = MarianMTModel.from_pretrained("Helsinki-NLP/opus-mt-en-de")
embeddings = model.get_input_embeddings()

# create token ids for encoder input
input_ids = tokenizer("I want to buy a car", return_tensors="pt").input_ids

# pass input token ids to encoder
encoder_output_vectors = model.base_model.encoder(input_ids, return_dict=True).last_hidden_state

# create token ids for decoder input
decoder_input_ids = tokenizer("<pad> Ich will ein", return_tensors="pt", add_special_tokens=False).input_ids

# pass decoder input ids and encoded input vectors to decoder
decoder_output_vectors = model.base_model.decoder(decoder_input_ids, encoder_hidden_states=encoder_output_vectors).last_hidden_state

# derive embeddings by multiplying decoder outputs with embedding weights
lm_logits = torch.nn.functional.linear(decoder_output_vectors, embeddings.weight, bias=model.final_logits_bias)

# change the decoder input slightly
decoder_input_ids_perturbed = tokenizer("<pad> Ich will das", return_tensors="pt", add_special_tokens=False).input_ids
decoder_output_vectors_perturbed = model.base_model.decoder(decoder_input_ids_perturbed, encoder_hidden_states=encoder_output_vectors).last_hidden_state
lm_logits_perturbed = torch.nn.functional.linear(decoder_output_vectors_perturbed, embeddings.weight, bias=model.final_logits_bias)

# compare shape and encoding of first vector
print(f"Shape of decoder input vectors {embeddings(decoder_input_ids).shape}. Shape of decoder logits {lm_logits.shape}")

# compare values of word embedding of "I" for input_ids and perturbed input_ids
print("Is encoding for `Ich` equal to its perturbed version?: ", torch.allclose(lm_logits[0, 0], lm_logits_perturbed[0, 0], atol=1e-3))
```

*输出：*

```
    Shape of decoder input vectors torch.Size([1, 5, 512]). Shape of decoder logits torch.Size([1, 5, 58101])
    Is encoding for `Ich` equal to its perturbed version?:  True
```

我们把解码器输入词嵌入的输出形状，*i.e.* `embeddings(decoder_input_ids)`（对应 Y0:4\mathbf{Y}_{0: 4}Y0:4​，这里 `<pad>` 对应 BOS，"Ich will das" 被分词为 4 个 token）与 `lm_logits` 的维度（对应 L1:5\mathbf{L}_{1:5}L1:5​）比较。我们还把词序列 "`<pad>` Ich will ein" 及轻微扰动的版本 "`<pad>` Ich will das" 连同 `encoder_output_vectors` 送过解码器，以检查当输入序列中只改动最后一个词（"ein" -> "das"）时，对应 "Ich" 的第二个 `lm_logit` 是否不同。

如预期，解码器输入词嵌入和 lm_logits 的输出形状，*i.e.* Y0:4\mathbf{Y}_{0: 4}Y0:4​ 和 L1:5\mathbf{L}_{1:5}L1:5​ 的维度，在最后一维上不同。虽然序列长度相同（=5），但解码器输入词嵌入的维度对应 `model.config.hidden_size`，而 `lm_logit` 的维度对应词表大小 `model.config.vocab_size`，如上所述。其次，可以注意到当最后一个词从 "ein" 改为 "das" 时，l1="Ich"\mathbf{l}_1 = \text{"Ich"}l1​="Ich" 的编码输出向量值是相同的。但如果理解了单向自注意力，这并不令人意外。

最后顺带一提，*自回归（auto-regressive）*模型，如 GPT2，与*基于 transformer* 的解码器模型有相同的架构，**前提是**移除交叉注意力层，因为独立的自回归模型不条件化于任何编码器输出。所以自回归模型与*自编码*模型本质上相同，只是用单向注意力替换了双向注意力。这些模型也可以在海量开放域文本数据上预训练，从而在自然语言生成（NLG）任务上展现出出色性能。在 [Radford et al. (2019)](https://cdn.openai.com/better-language-models/language_models_are_unsupervised_multitask_learners.pdf) 中，作者展示了一个预训练的 GPT2 模型无需太多微调就能在各种 NLG 任务上达到 SOTA 或接近 SOTA 的结果。🤗Transformers 中所有*自回归*模型可见[这里](https://huggingface.co/transformers/model_summary.html#autoregressive-models)。

好，就是这样！现在，你应该已经对*基于 transformer* 的编码器-解码器模型以及如何用 🤗Transformers 库使用它们有了很好的理解。

## **附录**

如上所述，下面这段代码展示如何为*基于 transformer* 的编码器-解码器模型编写一个简单的生成方法。这里我们用 `torch.argmax` 采样目标向量，实现一个简单的*贪心（greedy）*解码方法。

```
from transformers import MarianMTModel, MarianTokenizer
import torch

tokenizer = MarianTokenizer.from_pretrained("Helsinki-NLP/opus-mt-en-de")
model = MarianMTModel.from_pretrained("Helsinki-NLP/opus-mt-en-de")

# create ids of encoded input vectors
input_ids = tokenizer("I want to buy a car", return_tensors="pt").input_ids

# create BOS token
decoder_input_ids = tokenizer("<pad>", add_special_tokens=False, return_tensors="pt").input_ids

assert decoder_input_ids[0, 0].item() == model.config.decoder_start_token_id, "`decoder_input_ids` should correspond to `model.config.decoder_start_token_id`"

# STEP 1

# pass input_ids to encoder and to decoder and pass BOS token to decoder to retrieve first logit
outputs = model(input_ids, decoder_input_ids=decoder_input_ids, return_dict=True)

# get encoded sequence
encoded_sequence = (outputs.encoder_last_hidden_state,)
# get logits
lm_logits = outputs.logits

# sample last token with highest prob
next_decoder_input_ids = torch.argmax(lm_logits[:, -1:], axis=-1)

# concat
decoder_input_ids = torch.cat([decoder_input_ids, next_decoder_input_ids], axis=-1)

# STEP 2

# reuse encoded_inputs and pass BOS + "Ich" to decoder to second logit
lm_logits = model(None, encoder_outputs=encoded_sequence, decoder_input_ids=decoder_input_ids, return_dict=True).logits

# sample last token with highest prob again
next_decoder_input_ids = torch.argmax(lm_logits[:, -1:], axis=-1)

# concat again
decoder_input_ids = torch.cat([decoder_input_ids, next_decoder_input_ids], axis=-1)

# STEP 3
lm_logits = model(None, encoder_outputs=encoded_sequence, decoder_input_ids=decoder_input_ids, return_dict=True).logits
next_decoder_input_ids = torch.argmax(lm_logits[:, -1:], axis=-1)
decoder_input_ids = torch.cat([decoder_input_ids, next_decoder_input_ids], axis=-1)

# let's see what we have generated so far!
print(f"Generated so far: {tokenizer.decode(decoder_input_ids[0], skip_special_tokens=True)}")

# This can be written in a loop as well.
```

*输出：*

```
    Generated so far: Ich will ein
```

在这段代码示例里，我们精确地展示了前面所描述的内容。我们把输入 "I want to buy a car" 连同 BOS\text{BOS}BOS token 一起送过编码器-解码器模型，并从第一个 logit l1\mathbf{l}_1l1​（*i.e.* 第一行 `lm_logits`）采样。我们的采样策略很简单：贪心地选择概率最高的下一个解码器输入向量。以自回归方式，我们把采样到的解码器输入向量连同先前的输入一起再送过编码器-解码器模型并再次采样。我们重复三次。结果是，模型生成了词 "Ich will ein"。这个结果恰到好处——它是输入正确翻译的开头。

在实践中，会使用更复杂的解码方法来采样 `lm_logits`。其中大部分在[这篇](https://huggingface.co/blog/how-to-generate)博客里有讲。
