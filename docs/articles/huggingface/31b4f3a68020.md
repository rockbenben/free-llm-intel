我们超级激动地正式宣布：Hugging Face 收购了 XetHub 🔥

XetHub 是一家位于西雅图的公司，由 Yucheng Low、Ajit Banerjee、Rajat Arya 创立——他们此前在 Apple 工作，亲手打造并扩展了 Apple 内部的 ML 基础设施。XetHub 的使命是让 AI 开发也能用上软件工程的最佳实践。XetHub 研发的技术让 Git 能够扩展到 TB 级仓库，并让团队能够在大规模、持续演进的数据集和模型上探索、理解并协作。随后一支由 12 名优秀成员组成的团队也加入了他们。欢迎关注他们的新组织主页：[hf.co/xet-team](https://huggingface.co/xet-team)

## 我们在 HF 的共同目标

> XetHub 团队将帮助我们解锁 HF datasets 和 models 未来 5 年的增长——把 Hub 仓库的存储后端切换到我们自己的、更好的 LFS 替代版本。
> —— Julien Chaumond，HF CTO

2020 年我们构建 HF Hub 初版时，决定基于 Git LFS 来搭，因为它知名度还不错，也是为 Hub 冷启动的合理选择。

但当时我们就知道，终有一天要切换到自己的、更优化的存储与版本化后端。Git LFS——尽管名字里带着"大文件存储"——从来就不是为我们 AI 领域处理的大文件类型设计的。我们的文件不只是大，而是*非常非常大* 😃

## 未来用例示例 🔥 – 这会在 Hub 上带来什么

假设你有一个 10GB 的 Parquet 文件。加了一行数据。按今天的做法，你得重新上传 10GB。有了 XetHub 的分块文件和去重机制，你只需要重新上传包含这一新行的那几个块。

再举 GGUF 模型文件的例子：假设 [@bartowski](https://huggingface.co/bartowski) 想更新一个 Llama 3.1 405B 仓库里 GGUF 头部的一个元数据值。那么在未来，bartowski 只需重新上传一个几 KB 的块，整个流程效率大幅提升了 🔥

随着这个领域在未来几个月迈向万亿参数模型（感谢 Maxime Labonne 的新 [BigLlama-3.1-1T](https://huggingface.co/mlabonne/BigLlama-3.1-1T-Instruct) 🤯），我们希望这项新技术能为社区和企业内部同时打开新的规模级别。

最后，大数据集和大模型也带来了协作的挑战。团队如何在海量数据、模型和代码上协作？用户如何理解自己的数据和模型在如何演进？我们将努力找到更好的答案。

## 当前 Hub 仓库的有趣数据 🤯🤯

- 仓库数量：130 万个模型、45 万个数据集、68 万个 Spaces
- 累计总容量：LFS 存储 12PB（2.8 亿个文件）/ git（非 LFS）存储 7.3TB
- Hub 每日请求数：10 亿
- Cloudfront 日带宽：6PB 🤯

## 来自 [@ylow](https://huggingface.co/yuchenglow) 的个人感言

我身处 AI/ML 领域已经 15 年多，见证了深度学习如何一步步拿下视觉、语音、文本，以及越来越多的数据领域。

我过去严重低估的是数据的力量。几年前看似不可能的任务（比如图像生成），在数据量多出几个数量级、且模型容量足以消化它之后，就变得可行了。事后来看，这是 ML 历史上反复重演的教训。

博士毕业后我一直在数据领域工作。先是在初创公司（GraphLab/Dato/Turi）让结构化数据和 ML 算法在单机上扩展；被 Apple 收购后，又把 AI 数据管理扩展到 100PB 以上，支撑数十个内部团队每年交付数百个功能。2021 年，我和联合创始人们一起在 Madrona 和其他天使投资人的支持下创办了 XetHub，把我们"如何在大规模下实现协作"的经验带给世界。

XetHub 的目标是让 ML 团队能像软件团队一样运作：把 Git 文件存储扩展到 TB 级、无缝支持实验与可复现性、并提供可视化能力来理解数据集和模型的演进。

我和整个 XetHub 团队非常激动能加入 Hugging Face，继续这一使命——通过把 XetHub 技术集成进 Hub——让全球最大的 ML 社区用上这些协作能力！
