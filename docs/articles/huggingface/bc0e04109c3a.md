# 通过 TRL 使用 DDPO 微调 Stable Diffusion 模型

## 引言

扩散模型（例如 DALL-E 2、Stable Diffusion）是一类生成模型，在图像生成上非常成功，尤其是写实类图像。然而，这些模型生成的图像未必总是符合人类偏好或人类意图。对齐问题由此而来：我们如何确保模型的输出与「质量」这类人类偏好对齐，或者与那些难以用提示词表达的意图对齐？这就需要强化学习登场了。

在大语言模型（LLM）世界，强化学习（RL）已被证明是对齐模型与人类偏好的极有效工具，是 ChatGPT 这类系统卓越表现背后的主要配方之一。更准确地说，RL 是人类反馈强化学习（RLHF）的关键成分，而 RLHF 让 ChatGPT 像人一样交谈。

在 [Training Diffusion Models with Reinforcement Learning](https://arxiv.org/abs/2305.13301) 中，Black 等人展示了如何扩展扩散模型，借助 RL 按目标函数微调它们——方法名为 Denoising Diffusion Policy Optimization（DDPO）。

本博客讨论 DDPO 因何而来、简述它的工作原理，以及 DDPO 如何融入 RLHF 工作流以获得更符合人类审美的模型输出。随后我们话锋一转，谈谈如何用 `trl` 库新集成的 `DDPOTrainer` 把你的模型套用 DDPO，并讨论我们在 Stable Diffusion 上运行 DDPO 的发现。

## DDPO 的优势

对于「如何用 RL 微调扩散模型」这个问题，DDPO 并不是唯一可行的答案。

深入之前，比较两种 RL 方案的优劣时，有两个关键点要记住：

- 计算效率是关键。数据分布越复杂，计算成本越高。
- 近似很讨喜，但因为近似不是真东西，附带的误差会层层累积。

在 DDPO 之前，Reward-weighted regression（RWR）是用强化学习微调扩散模型的既有方法。RWR 复用扩散模型的去噪损失函数，配合从模型自身采样的训练数据和逐样本损失加权——权重取决于与最终样本关联的奖励。这个算法忽略中间的去噪步骤/样本。虽然有效，但要注意两件事：

- 通过加权相关损失来优化，是一个最大似然目标，属于近似优化
- 而且相关损失也不是精确的最大似然目标，而是从重新加权的变分界导出的近似

两层近似对性能和处理复杂目标的能力都有显著影响。

DDPO 把这个方法当作起点。DDPO 不把去噪步骤当成只看最终样本的单步操作，而是把整个去噪过程建模成一个多步马尔可夫决策过程（MDP），奖励在最末尾才获得。这个表述加上使用固定采样器，使得 agent 策略成为一个各向同性高斯分布，而不是任意复杂的分布。于是，与其使用最终样本的近似似然（RWR 的道路），这里使用每个去噪步的精确似然——而且它极好计算（ ℓ(μ,σ2;x)=−n2log⁡(2π)−n2log⁡(σ2)−12σ2∑i=1n(xi−μ)2 \ell(\mu, \sigma^2; x) = -\frac{n}{2} \log(2\pi) - \frac{n}{2} \log(\sigma^2) - \frac{1}{2\sigma^2} \sum_{i=1}^n (x_i - \mu)^2 ℓ(μ,σ2;x)=−2n​log(2π)−2n​log(σ2)−2σ21​∑i=1n​(xi​−μ)2 ）。

如果想了解更多 DDPO 细节，推荐阅读[原论文](https://arxiv.org/abs/2305.13301)和[配套博客](https://bair.berkeley.edu/blog/2023-07-14/ddpo/)。

## DDPO 算法简述

给定用来建模去噪过程序列性的 MDP 框架以及随之而来的其他考量，求解优化问题所选的工具是策略梯度方法，具体是 Proximal Policy Optimization（PPO）。整个 DDPO 算法与 PPO 几乎相同，唯独一处被高度定制：PPO 的轨迹收集部分。

## DDPO 与 RLHF：一对 enforcing 审美的组合

[RLHF](https://huggingface.co/blog/rlhf) 的一般训练环节粗略拆解为以下步骤：

- 监督微调一个「基座」模型，让它学习某些新数据的分布
- 收集偏好数据并用它训练一个奖励模型
- 以奖励模型为信号，用强化学习微调模型

要注意：在 RLHF 语境里，偏好数据是捕捉人类反馈的第一来源。

把 DDPO 加进来后，工作流变形为：

- 从一个预训练扩散模型出发
- 收集偏好数据并用它训练一个奖励模型
- 以奖励模型为信号，用 DDPO 微调模型

注意后者列表中缺少了通用 RLHF 工作流的第 3 步——这是因为实验证明（你马上会亲眼看到）它并不需要。

为了让我们让扩散模型输出更符合人类审美认知的图像这一尝试落地，我们遵循以下步骤：

- 从一个预训练 Stable Diffusion（SD）模型出发
- 在 [Aesthetic Visual Analysis](http://refbase.cvc.uab.es/files/MMP2012a.pdf)（AVA）数据集上训练一个带可学习回归头、冻结的 [CLIP](https://huggingface.co/openai/clip-vit-large-patch14) 模型，预测人们对输入图像的平均喜爱程度
- 以审美预测模型为奖励信号，用 DDPO 微调 SD 模型

带着这些步骤，我们进入下文描述的「实际跑起来」环节。

## 用 DDPO 训练 Stable Diffusion

### 环境

首先说硬件：对 DDPO 的这个实现，至少需要一块 NVIDIA A100 GPU 才能成功训练。低于这个档位的 GPU 很快会碰上显存溢出。

用 pip 安装 `trl` 库：

```
pip install trl[diffusers]
```

主库这样就装好了。接下来的依赖用于实验追踪和图像日志。装好 `wandb` 后，记得登录以便把结果保存到个人账号：

```
pip install wandb torchvision
```

注：你也可以用 `tensorboard` 代替 `wandb`，那就通过 `pip` 安装 `tensorboard` 包。

### 实操

`trl` 库中负责 DDPO 训练的核心类是 `DDPOTrainer` 和 `DDPOConfig`。关于这两个类的通用信息见[文档](https://huggingface.co/docs/trl/ddpo_trainer#getting-started-with-examplesscriptsstablediffusiontuningpy)。`trl` 仓库里有一个[示例训练脚本](https://github.com/huggingface/trl/blob/v0.9.6/examples/scripts/ddpo.py)，把这两个类与必需输入的默认实现和默认参数配合使用，微调 `RunwayML` 的默认预训练 Stable Diffusion 模型。

这个示例脚本用 `wandb` 记日志，使用一个审美奖励模型——其权重从一个公开的 HuggingFace 仓库读取（也就是说，收集数据和训练审美奖励模型已经替你做好了）。默认使用的 prompt 数据集是一份动物名称列表。

用户只需在命令行提供一个必需参数即可跑起来。此外，用户还需要一个 [huggingface 用户访问 token](https://huggingface.co/docs/hub/security-tokens)，用于微调后把模型上传到 HuggingFace hub。

下面这条 bash 命令就能开跑：

```
python ddpo.py --hf_user_access_token <token>
```

下表列出与正面结果直接相关的关键超参数：

| 参数 | 描述 | 单 GPU 训练的推荐值（截至目前） |
| --- | --- | --- |
| `num_epochs` | 训练的 epoch 数 | 200 |
| `train_batch_size` | 训练用的批次大小 | 3 |
| `sample_batch_size` | 采样用的批次大小 | 6 |
| `gradient_accumulation_steps` | accelerator 梯度累积步数 | 1 |
| `sample_num_steps` | 采样步数 | 50 |
| `sample_num_batches_per_epoch` | 每个 epoch 采样的批次数 | 4 |
| `per_prompt_stat_tracking` | 是否按 prompt 统计。若为 false，优势用整批的均值和标准差计算，而不是逐 prompt 追踪 | `True` |
| `per_prompt_stat_tracking_buffer_size` | 逐 prompt 统计的缓冲区大小 | 32 |
| `mixed_precision` | 混合精度训练 | `True` |
| `train_learning_rate` | 学习率 | 3e-4 |

所提供的脚本仅是起点。你可以放手调整超参数，甚至大改脚本来适配不同的目标函数。例如，可以接入一个衡量 JPEG 可压缩性的函数，或[一个用多模态模型评估图文对齐的函数](https://github.com/kvablack/ddpo-pytorch/blob/main/ddpo_pytorch/rewards.py#L45)，以及其他可能。

## 经验教训

- 尽管训练 prompt 规模很小，结果却能在很广的 prompt 范围内泛化。这一点在「奖励审美」这个目标函数上得到了充分验证。
- 尝试为审美目标显式泛化（增大训练 prompt 规模、变换 prompt）反而拖慢收敛速度，学不到的泛化行为几乎不可见——如果它存在的话。
- 虽然推荐 LoRA、且经过多次试验，非 LoRA 也值得考虑。除其他经验证据外，非 LoRA 似乎确实能产出相对更精致的图像。不过，要为稳定的非 LoRA 运行找对超参数要困难得多。
- 非 LoRA 的配置建议：学习率设低一些，`1e-5` 左右就够用，并把 `mixed_precision` 设为 `None`。

## 局限

- 目前 `trl` 的 DDPOTrainer 仅限于微调原版 SD 模型；
- 我们的实验主要聚焦 LoRA——它效果很好。我们也做了几次全量训练实验，质量可能更好，但找到合适的超参数更具挑战。

## 结论

像 Stable Diffusion 这样的扩散模型，在用 DDPO 微调后，能带来人类感知（或任何被恰当地概念化为目标函数的其他度量）所认定的生成图像质量的显著改善。

DDPO 的计算效率、以及不依赖近似的优化能力——尤其相对更早那些以同样目标（用 RL 微调扩散模型）的方法——使它成为微调 Stable Diffusion 这类扩散模型的合适候选。

`trl` 库的 `DDPOTrainer` 实现了用于微调 SD 模型的 DDPO。

我们的实验发现强调了 DDPO 在宽 prompt 范围内泛化的优势，尽管通过变换 prompt 显式泛化的尝试结果参差。非 LoRA 设定下寻找合适超参数的困难也是一条重要经验。

DDPO 是一项很有前景的技术，可让扩散模型对齐任何奖励函数。我们希望随着它进入 TRL，社区能更方便地用上它！
