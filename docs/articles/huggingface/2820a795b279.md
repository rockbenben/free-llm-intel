## FLUX.2：简要介绍

FLUX.2 既可以用于**图像引导**，也可以用于**文本引导**的图像生成。此外，它还能把多张图像作为参考输入，同时产出最终的输出图像。下面简要介绍 FLUX.2 引入的关键变化。

[![editing_teaser](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/flux2_blog/teaser_editing.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/flux2_blog/teaser_editing.png)

### 文本编码器

首先，它不再像 Flux.1 那样使用两个文本编码器，而是只用一个文本编码器——[Mistral Small 3.1](https://mistral.ai/news/mistral-small-3-1)。单一文本编码器大大简化了计算提示词嵌入（prompt embedding）的流程。管线（pipeline）支持 `max_sequence_length` 最高 512。FLUX.2 不再只用单层输出来做提示词嵌入，而是堆叠中间层的输出，[已有研究](https://www.arxiv.org/abs/2505.10046)表明这样做更有益。

### DiT

FLUX.2 沿用与 Flux.1 相同的大致架构：多模态扩散 transformer（[MM-DiT](https://arxiv.org/pdf/2403.03206)）+ 并行 [DiT](https://arxiv.org/pdf/2212.09748)。温习一下：MM-DiT 块先分别在两条独立的流中处理图像潜变量和条件文本，只在注意力计算时才把两者合到一起，因此被称为"双流"（double-stream）块；其后的并行块则作用于拼接后的图像与文本流，可以看作"单流"（single-stream）块。

从 Flux.1 到 FLUX.2，DiT 的关键变化如下：

- 时间和 guidance 信息（以 [AdaLayerNorm-Zero](https://arxiv.org/pdf/2212.09748) 调制参数的形式）分别在所有双流块和所有单流块之间共享，而不是像 Flux.1 那样每个块有各自的调制参数。
- 模型中没有任何层使用 `bias` 参数。特别地，两类 transformer 块中的注意力和前馈（FF）子块的任何层都不使用 `bias` 参数。
- 在 Flux.1 中，单流 transformer 块把注意力输出投影和 FF 输出投影融合了。FLUX.2 的单流块还把注意力 QKV 投影与 FF 输入投影也融合了，形成一个[完全并行的 transformer 块](https://arxiv.org/pdf/2302.05442)：  ![Figure taken from the ViT-22B paper.](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/flux2_blog/image.png) 图取自 ViT-22B 论文。  注意，与上图展示的 `ViT-22B` 块相比，FLUX.2 用的是 [SwiGLU](https://arxiv.org/abs/2002.05202) 风格的 MLP 激活而不是 GELU 激活（并且也不使用 `bias` 参数）。
- FLUX.2 中单流块占 transformer 块的比例更大（`8` 个双流块对 `48` 个单流块，而 Flux.1 是 `19`/`38`）。这也意味着单流块占 DiT 参数的比例更大：`Flux.1[dev]-12B` 约 54% 的总参数在双流块里，而 `FLUX.2[dev]-32B` 只有约 24% 的参数在双流块（约 73% 在单流块）。

### 其他

- 一个新的自编码器，即 `AutoencoderKLFlux2`
- 更好的方式来引入与分辨率相关的时间步调度（timestep schedule）

## 用 Diffusers 推理

FLUX.2 使用更大的 DiT，并以 Mistral3 Small 作为文本编码器。在不做任何卸载（offloading）的情况下一起使用时，推理需要超过 ***80GB VRAM***。接下来的小节里，我们演示在各种系统限制条件下以更易上手的方式对 FLUX.2 做推理。

### 安装与认证

在尝试下面的代码片段之前，请确保你已从 `main` 分支安装了 `diffusers`，并执行过 `hf auth login`。

```
pip uninstall diffusers -y && pip install git+https://github.com/huggingface/diffusers -U
```

### 常规推理

```
from diffusers import Flux2Pipeline
import torch

repo_id = "black-forest-labs/FLUX.2-dev"
pipe = Flux2Pipeline.from_pretrained(repo_id, torch_dtype=torch.bfloat16)
pipe.enable_model_cpu_offload()

image = pipe(
    prompt="dog dancing near the sun",
    num_inference_steps=50, # 28 is a good trade-off
    guidance_scale=4,
    height=1024,
    width=1024
).images[0]
```

上面的代码片段在 H100 上测试过，不开启 CPU 卸载是不够的。启用 CPU 卸载后，这套配置运行时需要约 62GB。

如果你用的是 Hopper 系列 GPU，可以启用 **Flash Attention 3** 来加速推理：

```
from diffusers import Flux2Pipeline
import torch

repo_id = "black-forest-labs/FLUX.2-dev"
pipe = Flux2Pipeline.from_pretrained(path, torch_dtype=torch.bfloat16)
+ pipe.transformer.set_attention_backend("_flash_3_hub")
pipe.enable_model_cpu_offload()

image = pipe(
    prompt="dog dancing near the sun",
    num_inference_steps=50,
    guidance_scale=2.5,
    height=1024,
    width=1024
).images[0]
```

### 资源受限场景

**使用 4-bit 量化**

借助 `bitsandbytes`，我们可以以 4-bit 加载 transformer 和文本编码器模型，让 24GB 显卡的用户也能在本地跑这个模型。这段代码可以在有约 20 GB **空闲** VRAM 的 GPU 上运行。

```
import torch
from transformers import Mistral3ForConditionalGeneration

from diffusers import Flux2Pipeline, Flux2Transformer2DModel

repo_id = "diffusers/FLUX.2-dev-bnb-4bit"
device = "cuda:0"
torch_dtype = torch.bfloat16

transformer = Flux2Transformer2DModel.from_pretrained(
  repo_id, subfolder="transformer", torch_dtype=torch_dtype, device_map="cpu"
)
text_encoder = Mistral3ForConditionalGeneration.from_pretrained(
  repo_id, subfolder="text_encoder", dtype=torch_dtype, device_map="cpu"
)

pipe = Flux2Pipeline.from_pretrained(
  repo_id, transformer=transformer, text_encoder=text_encoder, torch_dtype=torch_dtype
)
pipe.enable_model_cpu_offload()

prompt = "Realistic macro photograph of a hermit crab using a soda can as its shell, partially emerging from the can, captured with sharp detail and natural colors, on a sunlit beach with soft shadows and a shallow depth of field, with blurred ocean waves in the background. The can has the text `BFL Diffusers` on it and it has a color gradient that start with #FF5733 at the top and transitions to #33FF57 at the bottom."

image = pipe(
  prompt=prompt,
  generator=torch.Generator(device=device).manual_seed(42),
  num_inference_steps=50, # 28 is a good trade-off
  guidance_scale=4,
).images[0]

image.save("flux2_t2i_nf4.png")
```

注意，我们用的是一个包含 FLUX.2 DiT 和 Mistral 文本编码器 NF4 量化版本的仓库。

**本地 + 远程**

得益于 Diffusers 管线的*模块化设计*，我们可以把各个模块隔离出来按顺序使用。我们把文本编码器解耦出来，部署到一个[推理端点（Inference Endpoint）](https://endpoints.huggingface.co/)上。这样 VRAM 就只需要留给 DiT 和 VAE。

> ⚠️ 要使用远程文本编码器，你需要一个有效的 token。如果你已经通过认证，则无需再做任何操作。

下面的示例结合了本地与远程推理。此外，我们还通过 `bitsandbytes` 用 NF4 量化了 DiT。

这段代码可以在 18 GB VRAM 的 GPU 上运行：

```
from diffusers import Flux2Pipeline, Flux2Transformer2DModel
from diffusers import BitsAndBytesConfig as DiffBitsAndBytesConfig
from huggingface_hub import get_token
import requests
import torch
import io

def remote_text_encoder(prompts: str | list[str]):
  def _encode_single(prompt: str):
      response = requests.post(
          "https://remote-text-encoder-flux-2.huggingface.co/predict",
          json={"prompt": prompt},
          headers={
              "Authorization": f"Bearer {get_token()}",
              "Content-Type": "application/json"
          }
      )
      assert response.status_code == 200, f"{response.status_code=}"
      return torch.load(io.BytesIO(response.content))

  if isinstance(prompts, (list, tuple)):
      embeds = [_encode_single(p) for p in prompts]
      return torch.cat(embeds, dim=0)

  return _encode_single(prompts).to("cuda")

repo_id = "black-forest-labs/FLUX.2-dev"
quantized_dit_id = "diffusers/FLUX.2-dev-bnb-4bit"
dit = Flux2Transformer2DModel.from_pretrained(
  quantized_dit_id, subfolder="transformer", torch_dtype=torch_dtype, device_map="cpu"
)

pipe = Flux2Pipeline.from_pretrained(
  repo_id,
  text_encoder=None,
  transformer=dit,
  torch_dtype=torch.bfloat16,
)
pipe.enable_model_cpu_offload()

print("Running remote text encoder ☁️")
prompt1 = "a photo of a forest with mist swirling around the tree trunks. The word 'FLUX.2' is painted over it in big, red brush strokes with visible texture"
prompt2 = "a photo of a dense forest with rain. The word 'FLUX.2' is painted over it in big, red brush strokes with visible texture"
prompt_embeds = remote_text_encoder([prompt1, prompt2])
print("Done ✅")

out = pipe(
  prompt_embeds=prompt_embeds,
  generator=torch.Generator(device="cuda").manual_seed(42),
  num_inference_steps=50, # 28 is a good trade-off
  guidance_scale=4,
  height=1024,
  width=1024,
)

for idx, image in enumerate(out.images):
  image.save(f"flux_out_{idx}.png")
```

对于 VRAM 更低的 GPU，我们有 `group_offloading`，它能让只有 8GB **空闲** VRAM 的 GPU 用上这个模型，但你需要 32GB 的**空闲** RAM。或者，如果你愿意牺牲一些速度，可以设置 `low_cpu_mem_usage=True`，把 RAM 需求降到只有 10GB。

```
import io
import os

import requests
import torch

from diffusers import Flux2Pipeline, Flux2Transformer2DModel

repo_id = "diffusers/FLUX.2-dev-bnb-4bit"
torch_dtype = torch.bfloat16
device = "cuda"

def remote_text_encoder(prompts: str | list[str]):
  def _encode_single(prompt: str):
      response = requests.post(
          "https://remote-text-encoder-flux-2.huggingface.co/predict",
          json={"prompt": prompt},
          headers={"Authorization": f"Bearer {os.environ['HF_TOKEN']}", "Content-Type": "application/json"},
      )
      assert response.status_code == 200, f"{response.status_code=}"
      return torch.load(io.BytesIO(response.content))

  if isinstance(prompts, (list, tuple)):
      embeds = [_encode_single(p) for p in prompts]
      return torch.cat(embeds, dim=0)

  return _encode_single(prompts).to("cuda")

transformer = Flux2Transformer2DModel.from_pretrained(
  repo_id, subfolder="transformer", torch_dtype=torch_dtype, device_map="cpu"
)

pipe = Flux2Pipeline.from_pretrained(
  repo_id,
  text_encoder=None,
  transformer=transformer,
  torch_dtype=torch_dtype,
)
pipe.transformer.enable_group_offload(
  onload_device=device,
  offload_device="cpu",
  offload_type="leaf_level",
  use_stream=True,
  # low_cpu_mem_usage=True # uncomment for lower RAM usage
)
pipe.to(device)

prompt = "a photo of a forest with mist swirling around the tree trunks. The word 'FLUX.2' is painted over it in big, red brush strokes with visible texture"
prompt_embeds = remote_text_encoder(prompt)

image = pipe(
  prompt_embeds=prompt_embeds,
  generator=torch.Generator(device=device).manual_seed(42),
  num_inference_steps=50,
  guidance_scale=4,
  height=1024,
  width=1024,
).images[0]
```

### 多张参考图像

FLUX.2 支持把多张图像作为输入，最多可用 10 张。不过要注意，每多一张图像都需要更多 VRAM。你可以按序号引用图像（如 image 1、image 2），也可以用自然语言（如 the kangaroo、the turtle）。想要最佳效果，最好的做法是把两种方式结合起来。

```
import torch
from transformers import Mistral3ForConditionalGeneration

from diffusers import Flux2Pipeline, Flux2Transformer2DModel
from diffusers.utils import load_image

repo_id = "diffusers-internal-dev/new-model-image-final-weights"
device = "cuda:0"
torch_dtype = torch.bfloat16

pipe = Flux2Pipeline.from_pretrained(
  repo_id, torch_dtype=torch_dtype
)
pipe.enable_model_cpu_offload()

image_one = load_image("https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/flux2_blog/kangaroo.png")
image_two = load_image("https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/flux2_blog/turtle.png")

prompt = "the boxer kangaroo from image 1 and the martial artist turtle from image 2 are fighting in an epic battle scene at a beach of a tropical island, 35mm, depth of field, 50mm lens, f/3.5, cinematic lighting"

image = pipe(
  prompt=prompt,
  image=[image_one, image_two],
  generator=torch.Generator(device=device).manual_seed(42),
  num_inference_steps=50,
  guidance_scale=2.5,
  width=1024,
  height=768,
).images[0]

image.save(f"./flux2_t2i.png")
```

## LoRA 微调

FLUX.2 既是文生图模型也是图生图模型，对很多用例来说都是完美的微调候选！不过，单是推理就要占 80GB 以上的 VRAM，在消费级 GPU 上做 LoRA 微调就更难了。为了把能省的内存都省下来，我们把上面介绍的一些推理优化也用在训练里，再配合一些通用的省内存技巧，大幅降低内存消耗。训练时可以用下面的 diffusers 代码，也可以用 [Ostris' AI Toolkit](https://github.com/ostris/ai-toolkit)。

> 我们同时提供了文生图和图生图两套训练脚本，本文以文生图训练示例为主。

### 微调的内存优化

这些技术很多可以互相辅助、组合使用，进一步降低内存消耗。但也有一些技术是互斥的，所以开始训练前记得先确认。

以下为本节用到的省内存技术细节：

- **远程文本编码器：** 要在训练中使用远程文本编码，只需传 `--remote_text_encoder`。注意你要么登录了 Hugging Face 账号（`hf auth login`），要么用 `--hub_token` 传一个 token。
- **CPU 卸载：** 传 `--offload` 后，vae 和 text encoder 会被卸载到 CPU 内存，只在需要时才搬到 GPU。
- **潜变量缓存（Latent Caching）：** 先用 vae 把训练图像预编码，然后删掉 vae 腾出内存。要启用 `latent_caching`，传 `--cache_latents` 即可。
- **QLoRA**：基于量化的低精度训练——使用 8-bit 或 4-bit 量化。可以用以下标志：**用 `torchao` 做 FP8 训练**：传 `--do_fp8_training` 启用 FP8 训练。由于我们用到了 FP8 tensor core，需要计算能力至少 8.9 的 CUDA GPU。如果你想在较老的卡上做省内存训练，推荐使用其他训练器，如 `SimpleTuner`、`ai-toolkit` 等。**用 `bitsandbytes` 做 NF4 训练**：或者，你也可以通过传以下标志用 `bitsandbytes` 做 8-bit 或 4-bit 量化：- `--bnb_quantization_config_path`，指向包含配置的 json 文件路径。详见下文。
- **梯度检查点与梯度累积：** `--gradient accumulation` 指在执行一次反向/更新之前累积的更新步数，传大于 1 的值可以减少反向/更新次数，从而降低内存需求。* 用 `--gradient checkpointing` 可以节省内存：前向传播时不保存所有中间激活值，只保存一部分（检查点），其余在反向传播时按需重算。代价是反向传播会变慢。
- **8-bit-Adam 优化器：** 用 `AdamW` 训练时（不适用于 `prodigy`），可以传 `--use_8bit_adam` 降低训练的内存需求。要用这个功能请先安装 `bitsandbytes`。

> 开始训练前请务必查看 README 里的前置条件。
