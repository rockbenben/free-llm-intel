Hugging Face 平台上有大量数据集和预训练模型，让使用和训练最先进机器学习模型变得越来越触手可及。然而，扩展 AI 任务可能很困难：AI 数据集往往很大（数百 GB 到 TB 级），而使用 Hugging Face transformers 做模型推理有时计算开销很高。

[Dask](https://www.dask.org/?utm_source=hf-blog) 是一个用于分布式计算的 Python 库，能通过把数据集切分为大小适中的块来处理超内存计算（处理放不进内存的数据）。这让下面这些事情变得轻松：

- 用一套仿 pandas 的易用 API，对 TB 级数据集做高效的数据加载与预处理
- 并行模型推理（可选择多节点 GPU 推理）

在本文中，我们以 FineWeb 数据集为例演示数据处理，使用 FineWeb-Edu 分类器识别教育价值高的网页。我们将展示：

- 如何用 pandas 在本地处理 100 行
- 如何用 Dask 在云端多 GPU 上扩展到 2.11 亿行

## 用 Pandas 处理 100 行

[FineWeb 数据集](https://huggingface.co/datasets/HuggingFaceFW/fineweb)由来自 [Common Crawl](http://commoncrawl.org/)（一个托管每月更新公共网页爬取数据集的非营利组织）的 15 万亿 token 英文网页数据组成。该数据集常用于各类任务，如大语言模型训练、分类、内容过滤以及跨多个行业的信息检索。

在笔记本上，用 pandas 下载并读取单个文件可能需要 1 分钟以上。

```
import pandas as pd

df = pd.read_parquet(
    "hf://datasets/HuggingFaceFW/fineweb/data/CC-MAIN-2024-10/000_00000.parquet"
)
```

接下来，我们用 HF 的 [FineWeb-Edu 分类器](https://huggingface.co/HuggingFaceFW/fineweb-edu-classifier)来评判数据集中网页的教育价值。网页按 0 到 5 分排名，0 表示没有教育价值，5 表示教育价值很高。我们可以在数据的 100 行小子集上用 pandas 完成这件事——在带 GPU 的 M1 Mac 上大约需要 10 秒。

```
from transformers import pipeline

def compute_scores(texts):
    import torch

    # Select which hardware to use
    if torch.cuda.is_available():
        device = torch.device("cuda")
    elif torch.backends.mps.is_available():
        device = torch.device("mps")
    else:
        device = torch.device("cpu")

    pipe = pipeline(
        "text-classification",
        model="HuggingFaceFW/fineweb-edu-classifier",
        device=device
    )
    results = pipe(
        texts.to_list(),
        batch_size=25,                    # Choose batch size based on data size and hardware
        padding="longest",
        truncation=True,
        function_to_apply="none"
    )
    
    return pd.Series([r["score"] for r in results])

df = df[:100]
min_edu_score = 3
df["edu-classifier-score"] = compute_scores(df.text)
df = df[df["edu-classifier-score"] >= min_edu_score]
```

注意，我们还在 `compute_scores` 函数内部加了一步检查可用硬件的环节，因为在下一步用 Dask 扩展时，该函数会被分发到各 worker 上执行。这样就很容易从单机的本地测试（无论是 CPU，还是带有 Apple silicon GPU 的 MacBook），扩展到跨多台机器的分布式运行（比如 NVIDIA GPU）。

## 用 Dask 扩展到 2.11 亿行

2024 年 2/3 月的完整爬取数据在磁盘上为 432 GB、内存中约 715 GB，分散在 250 个 Parquet 文件中。即便在内存足以容纳整个数据集的机器上，串行处理也会慢得无法接受。

要扩展规模，我们可以用 [Dask DataFrame](https://docs.dask.org/en/stable/dataframe.html?utm_source=hf-blog)，它通过并行化 pandas 帮你处理大规模表格数据。它与 pandas API 高度相似，让你很容易从单个数据集的测试过渡到全量数据集的横向扩展。Dask 与 Parquet（Hugging Face 数据集的默认格式）配合良好，支持丰富数据类型、高效的列式过滤与压缩。

```
import dask.dataframe as dd

df = dd.read_parquet(
    # Load the full dataset lazily with Dask
    "hf://datasets/HuggingFaceFW/fineweb/data/CC-MAIN-2024-10/*.parquet" 
)
```

我们将用 `map_partitions` 在 Dask DataFrame 上并行应用文本分类的 `compute_scores` 函数——它会并行地应用到大型 Dask DataFrame 中的每个 pandas DataFrame。`meta` 参数是 Dask 特有的，用于指明输出的数据结构（列名与数据类型）。

```
from transformers import pipeline

def compute_scores(texts):
    import torch

    # Select which hardware to use
    if torch.cuda.is_available():
        device = torch.device("cuda")
    elif torch.backends.mps.is_available():
        device = torch.device("mps")
    else:
        device = torch.device("cpu")

    pipe = pipeline(
        "text-classification",
        model="HuggingFaceFW/fineweb-edu-classifier",
        device=device,
    )
    results = pipe(
        texts.to_list(),
        batch_size=768,
        padding="longest",
        truncation=True,
        function_to_apply="none",
    )

    return pd.Series([r["score"] for r in results])

min_edu_score = 3
df["edu-classifier-score"] = df.text.map_partitions(compute_scores, meta=pd.Series([0]))
df = df[df["edu-classifier-score"] >= min_edu_score]
```

注意，我们挑了一个在本例中合适的 `batch_size`，但在你自己的工作流中，大概率需要按硬件、数据和模型来定制它（参见 [HF 关于 pipeline 批处理的文档](https://huggingface.co/docs/transformers/en/main_classes/pipelines#pipeline-batching)）。

现在我们锁定了感兴趣的数据行，可以把结果保存下来供下游分析。Dask DataFrame 自动支持[分布式写入 Parquet](https://docs.dask.org/en/stable/dataframe-parquet.html?utm_source=hf-blog)。Hugging Face 用 commit 跟踪数据集变更，并允许并行写入 Dask DataFrame。

```
repo_id = "<your-hf-user>/<your-dataset-name>"  # Update with your dataset location
df.to_parquet(f"hf://datasets/{repo_id}")
```

由于这样会每个文件产生一个 commit，建议上传后压缩（squash）历史：

```
from huggingface_hub import HfApi

HfApi().super_squash_history(repo_id=repo_id, repo_type="dataset")
```

或者，你也可以使用[这个自定义函数](https://gist.github.com/lhoestq/8f73187a4e4b97b9bb40b561e35f6ccb)，它每次 commit 上传多个文件。

### 多 GPU 并行模型推理

把 Dask [部署](https://docs.dask.org/en/stable/deploying.html?utm_source=hf-blog)到各种硬件上有许多方式。这里我们用 [Coiled](https://docs.coiled.io/user_guide/ml.html?utm_source=hf-blog) 在云端部署 Dask，按需拉起 VM，用完再清理。

```
cluster = coiled.Cluster(
    region="us-east-1",                 # Same region as data
    n_workers=100,                      
    spot_policy="spot_with_fallback",   # Use spot instances, if available
    worker_vm_types="g5.xlarge",        # NVIDIA A10 Tensor Core GPU
    worker_options={"nthreads": 1},
)
client = cluster.get_client()
```

在底层，Coiled 负责：

- 供应带 GPU 硬件的云 VM。本例是 [AWS 上的 `g5.xlarge` 实例](https://aws.amazon.com/ec2/instance-types/g5/)。
- 安装合适的 NVIDIA 驱动、CUDA runtime 等。
- 通过[包同步](https://docs.coiled.io/user_guide/software/sync.html?utm_source=hf-blog)在云 VM 上自动安装与你本地相同的包，包括工作目录中的 Python 文件。

整个工作流大约 5 小时完成，GPU 利用率很理想。

GPU 利用率和显存占用都接近上限，说明我们把可用硬件用到了实处。

把所有内容拼在一起，下面是完整工作流：

```
import dask.dataframe as dd
from transformers import pipeline
from huggingface_hub import HfApi
import os
import coiled

cluster = coiled.Cluster(
    region="us-east-1",
    n_workers=100,
    spot_policy="spot_with_fallback",
    worker_vm_types="g5.xlarge",
    worker_options={"nthreads": 1},
)
client = cluster.get_client()
cluster.send_private_envs(
    {"HF_TOKEN": "<your-hf-token>"}             #  Send credentials over encrypted connection
)

df = dd.read_parquet(
    "hf://datasets/HuggingFaceFW/fineweb/data/CC-MAIN-2024-10/*.parquet"
)

def compute_scores(texts):
    import torch

    # Select which hardware to use
    if torch.cuda.is_available():
        device = torch.device("cuda")
    elif torch.backends.mps.is_available():
        device = torch.device("mps")
    else:
        device = torch.device("cpu")

    pipe = pipeline(
        "text-classification",
        model="HuggingFaceFW/fineweb-edu-classifier",
        device=device
    )
    results = pipe(
        texts.to_list(),
        batch_size=768,
        padding="longest",
        truncation=True,
        function_to_apply="none"
    )

    return pd.Series([r["score"] for r in results])

min_edu_score = 3
df["edu-classifier-score"] = df.text.map_partitions(compute_scores, meta=pd.Series([0]))
df = df[df["edu-classifier-score"] >= min_edu_score]

repo_id = "<your-hf-user>/<your-dataset-name>"  # Replace with your dataset location
df.to_parquet(f"hf://datasets/{repo_id}")

HfApi().super_squash_history(repo_id=repo_id, repo_type="dataset")  # optional: squash commit history
```

## 结论

Hugging Face + Dask 是一对强大的组合。在本例中，我们通过 Dask + Coiled 在云端多 GPU 上并行运行工作流，把分类任务从 100 行扩展到 2.11 亿行。

同类工作流也可用于其他场景，例如：

- 过滤基因组数据以挑选目标基因
- 从无结构文本中提取信息，转为结构化数据集
- 清洗从互联网或 Common Crawl 抓取到的文本数据
- 运行多模态模型推理，分析大规模音频、图像或视频数据集
