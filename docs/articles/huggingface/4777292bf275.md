> 这是一篇由 Digital Green 撰写的客座博文。Digital Green 参与了一项由 CGIAR 主导的协作，为小农户带来农业支持。

全球估计有 5 亿小农户：他们在全球粮食安全中扮演着关键角色。能否及时获取准确信息，对这些农户做出明智决策、提高产量至关重要。

「农业推广服务」为农户提供农业技术建议，并供应支持其农业生产所需的投入与服务。仅在印度，农业推广员就有 30 万名，他们为小农户提供关于改进农业实践的必要信息、帮助其决策。

但尽管人数可观，推广人员的规模仍不足以应对全部需求：他们与农户的接触比例通常高达 1:1000。通过协作与技术触达推广人员和农户，仍是关键所在。

于是 GAIA 项目登场了——这是由 [CGIAR](https://www.cgiar.org/) 发起的协作倡议，引入了 [Hugging Face](https://huggingface.co/) 作为 [Expert Support 项目](https://huggingface.co/support)下的导师，以及 [Digital Green](http://digitalgreen.org) 作为项目伙伴。

GAIA 有一个高远的目标：把多年积累的农业知识——以精心维护在 [GARDIAN 门户](https://gardian.bigdata.cgiar.org/#/)中的研究论文形式——交到农户手中。那里有近 46,000 篇研究论文和报告，承载了跨越数十年、覆盖不同作物的全球农业知识。

[Digital Green](http://www.digitalgreen.org) 立刻看到了在经审核的精选信息之上、用检索增强生成（RAG）构建智能聊天机器人的潜力，于是决定开发 [Farmer.chat](https://farmerchat.digitalgreen.org/)——一个借助大语言模型（LLM）能力、向农户和一线推广人员提供个性化、可靠农业建议的聊天机器人。

要为如此多样的语言、地区、作物和使用场景打造这样一个聊天机器人，是一项巨大挑战：所传播的信息必须与农场本地细节相契合（contextual），用农户听得懂的语言和语气表达，并且足够准确（基于可信来源）才能供农户据此行动。为评估系统性能，CGIAR 团队与 HF 专家协作搭建了一套强力的评估体系，其形式就是一个 LLM-as-a-judge（以 LLM 充当评委）系统。

来看看他们如何应对这一挑战！

## 系统架构

![System architecture](https://miro.medium.com/v2/resize:fit:4800/format:webp/1*L8epmSjWRweoVhQoLlAbuQ.png)

完整系统由许多组件构成，以给出锚定于多种工具与外部知识的聊天回答。关键要素包括：

- **知识库：** 预处理：第一步是借助 [Scio](https://scio.systems/) 维护的 API，把 PDF 文档引入 Farmer.chat 流水线。在知识库中，主题会被自动归入相关地理区域并按语义分组。语义分块：带元数据的整理文件被进一步处理，语义相近的句子被归入同一文本块。该函数目前使用小文本嵌入配合余弦相似度。转换为 VectorDB 格式：每个文本块经嵌入模型转为向量表示，向量存储于 QdrantDB。
- **RAG 流水线：** 它确保交付的信息锚定于内容本身而非外部。分两部分：信息检索：在知识库中搜索与用户查询相匹配的相关内容——调用知识库构建阶段创建的向量数据库 API 获取所需文本块。生成：基于文本块中检索到的信息与用户查询，生成器调用 LLM，产出满足用户需求的类人回答。
- **面向用户的 Agent：** 规划 agent 底层使用 GPT-4o。它的任务是：理解用户意图；基于意图与工具描述判断还需要什么信息；在向用户询问直到需求清晰；需求清晰后调用执行 agent；从执行 agent 获取回答并生成最终响应。该 agent 运行一个基于 ReAct 的 prompt，逐步思考、调用相应工具并分析响应。然后借助工具回答：目前 agent 使用以下工具集：进一步对话、RAG QA 端点、视频检索端点、天气端点、作物表。

这样一个系统有很多运动部件，每个部件都会对性能的某些方面产生重大影响，因此我们必须谨慎地做性能评估。

过去一年里，Farmer.chat 的使用量已增长到服务 2 万多名农户、处理超过 34 万次查询。在这样的规模下，我们如何评估系统性能？

在每周的头脑风暴中，Hugging Face 提示了「LLM 充当评委」的思路，并给出了他们的 notebook 链接 [LLM as a Judge](https://huggingface.co/learn/cookbook/en/llm_judge)。团队详细讨论了这份材料，此后它成为一种实践，一路指引着 [Farmer.chat](https://farmerchat.digitalgreen.org/) 的开发。

## LLM 评委的力量

Farmer.Chat 采用精巧的检索增强生成（RAG）流水线，向农户交付锚定在知识库中的准确、相关信息。RAG 流水线用 LLM 从庞大知识库中检索信息，然后生成简洁而信息充分的回答。

但我们如何衡量这条流水线的有效性？

难点在于：并不存在某个确定性指标可以用来给回答的质量、简洁性、精确度……打分。

这正是 *LLM-as-a-judge* 技术派上用场的地方。想法很简单：让一个 LLM 对任意指标给输出打分。巨大的优势在于指标可以是任何东西——LLM-as-a-Judge 极其多面。

例如，你可以像这样评估提示（prompt）的清晰度：

```
You will be given a user input about agriculture, and your task is to score it on various aspects.
Think step by step and rate the user input on all three following criteria and give a score for each:
1) The intent and ask is clear.
2) The topic is well-specified.
3) The target entity is well-specified, as well as its attributes, for instance "disease resistant" or "high yield".
You should give your scores on an integer scale of 1 to 3, 1 being the worst and 3 the best score.

After creating a score for each three, take the average and round it off to the nearest integer which becomes the final score.  

Example:
User input: "tell the benefits of batian coffee variety"
Criterion 1: scores 3, as the intent is clear (about knowing about batian variety of coffee) and the ask is clear (want to summarize the benefits).  
Criterion 2: scores 3, the topic is well specified (coffee varieties)   
Criterion 3: scores 2, as the entity is clear (batian variety) but not the attributes.
```

如[前文提到的那篇文章](https://huggingface.co/learn/cookbook/en/llm_judge)所述，使用 LLM-as-a-judge 的关键，在于清晰地定义任务、评判标准与整数评分量表。

Farmer.Chat 背后的研究团队借助 LLM 的能力评估多个关键指标：

- **Prompt 清晰度（Prompt Clarity）**：评估用户表达问题的能力。LLM 被训练来评估用户意图的清晰度、主题的明确性以及实体-属性的辨识，从而洞察用户表达需求的沟通效率。
- **问题类型（Question Type）**：按认知复杂度把用户问题分类。LLM 分析用户查询并归入六个类别之一，如「记忆」「理解」「应用」「分析」「评价」「创造」，帮助我们理解用户交互的认知需求。
- **已回答查询率（Answered Queries）**：追踪聊天机器人回答问题的比例，反映知识库的广度以及平台处理各类查询的能力。
- **RAG 准确率（RAG Accuracy）**：评估 RAG 流水线检索信息的忠实度（faithfulness）与相关性。LLM 充当评委，将检索到的信息与用户查询对比，评估回答是否准确、相关。

它让我们超越「机器人能答多少问题、回答多快」这类粗指标，转而深入探究回答质量，以更细致的方式理解用户体验。

对于 RAG 准确率，我们用 LLM-as-a-judge 在二元量表上评估：0 或 1。但任务的分解方式形成了一套成熟流程，其得分我们已与人类评估者在约 360 个问题上做过比对：LLM 的评判实际做得很好，与人类评估高度相关！

下面是 prompt，灵感来自 RAGAS 库。

```
You are a natural language inference engine. You will be presented with a set of factual statements and context. You are supposed to analyze if each statement is factually correct given the context. You can come up with the scores of 'Yes' (1) and 'No' (0) as verdict.

Use the following rules:  
If the statement can be derived from the context, give a score of 1.
If there is no statement and there is no context, give a score of 1.
If the statement can’t be derived from the context, give a score of 0.
If there is no context but there is a statement, give a score of 0.

#### Input :

Context : {context}

Statements : {statements}
```

上面的 context 变量是用于生成回答的输入文本块，而 statements 是由另一次 LLM 调用生成的原子事实语句。

这是非常重要的一步，因为它让规模化评估成为可能——在处理海量文档与查询时这很关键。作为核心的 LLM-as-a-judge 得出的指标，就像指南针，为我们 AI 流水线可选的各个方案导航。

## 结果：为 RAG 基准测试 LLM

我们创建了一个包含 700 多条用户查询的样本数据集，随机覆盖不同价值链（作物）与日期（月份）。仅这次升级本身就有 11 个不同版本，用 RAG 准确率和回答率进行评估；同一方法也被用来测量主流 LLM 的性能——每种 LLM 调用都不做任何 prompt 改动。本实验我们选择了 OpenAI 的 GPT-4-Turbo、Gemini-1.5 的 Pro 与 Flash 版本，以及 Llama-3-70B-Instruct。

| LLM | Faithful | Relevant | Answered * Relevant | Answered * Faithful | Unanswered |
| --- | --- | --- | --- | --- | --- |
| GPT-4-turbo | 88% | 75% | 59% | 69% | 21.9% |
| Llama-3-70B | 78% | 76% | 76% | 78% | 0.3% |
| Gemini-1.5-Pro | 91% | 88% | 71% | 73% | 19.4% |
| Gemini-1.5-Flash | 89% | 78% | 74 % | 85% | 4.5% |

我们看到，在四个模型中，事实正确回答的最高水平（"Faithful" 列）由 Gemini-1.5-pro 取得，Gemini-1.5-Flash 与 GPT-4-turbo 紧随其后。

我们发现，仅看忠实度，Gemini-1.5-Pro 领先其他模型。但如果同时考虑模型愿意回答问题的比例，Llama-3-70B 和 Gemini-1.5-Flash 表现更好。

最终我们选择了 Gemini-1.5-Flash，因为它的折衷最出色：未回答率低、忠实度非常高。

## 结论

通过让 LLM 充当评委，我们对用户行为以及 AI 工具在农业场景中的有效性有了更深的理解。这种数据驱动的方法对以下方面至关重要：

- **改善用户体验：** 通过发现用户难以表达需求的环节、或 RAG 流水线表现不如预期的环节，我们可以改进平台的设计与功能。
- **优化知识库：** 对未回答查询的分析帮助我们识别知识库的缺口、排定内容开发的优先级。
- **选择正确的 LLM：** 通过在关键指标上对不同的 LLM 做基准测试，我们能就哪些模型最适合特定任务与场景做出有依据的决策。

LLM 能够作为评委评估 AI 系统性能，是游戏规则的改变者。它让我们能以更客观、数据驱动的方式衡量这些系统的影响，最终推动开发更稳健、更有效、更易用的农业 AI 工具。

一年多的时间里，我们的产品持续演进。在这段不长的时间内，我们做到了：

- 触达 2 万多名农户
- 回答超过 34 万个问题
- 服务 6 种以上语言、覆盖 50 种价值链作物
- 保持接近于零的偏见或有害回答
