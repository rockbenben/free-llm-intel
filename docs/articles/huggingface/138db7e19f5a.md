# 推出 Private Hub：用机器学习进行构建的新方式

> 2023 年 6 月更新：Private Hub 现已更名为 Enterprise Hub。
> Enterprise Hub 是一款托管方案，兼具云托管服务（SaaS）与企业级安全之长。它让客户可以在从云上到本地的大范围算力选项上部署 Inference Endpoints 等特定服务，并通过 SSO 提供高级用户管理与访问控制。
> 我们不再提供 Private Hub 的本地部署，这一实验已经停止。
> 请联系我们的 Enterprise 团队，为你的公司找到最佳方案。

机器学习正在改变公司构建技术的方式。从驱动新一代颠覆性产品，到为我们人人常用、喜爱的知名应用加入更聪明的功能，ML 已经成为开发流程的核心。

但每一次技术变革都伴随着新挑战。

[大约 90% 的机器学习模型永远进不了生产环境](https://venturebeat.com/2019-07-19/why-do-87-of-data-science-projects-never-make-it-into-production/)。不熟悉的工具和非标准的工作流拖慢了 ML 开发。模型和数据集不在公司内部共享，团队之间不断重复造轮子。数据科学家难以向业务方展示自己的工作，业务方也难以给出精确、及时的反馈。机器学习团队还不得不在 Docker/Kubernetes 和生产模型优化上浪费时间。

基于这些思考，我们推出了 [Private Hub](https://huggingface.co/platform)（PH）——一种用机器学习构建的新方式。从研究到生产，它提供一整套统一的工具，以安全合规的方式加速机器学习生命周期的每一步。PH 把各类 ML 工具集中到一处，让机器学习协作更简单、更有趣、更高效。

在这篇博客中，我们将深入了解 Private Hub 是什么、为什么有用，以及客户如何用它加速自己的 ML 路线图。

## 1. Hugging Face Hub 是什么？

在深入了解 Private Hub 之前，先看看它的核心——Hugging Face Hub。

[Hugging Face Hub](https://huggingface.co/docs/hub/index) 提供超过 6 万个模型、6 千个数据集和 6 千个 ML 演示应用，全部开源且公开可用，是一个人们可以轻松协作、共同构建 ML 的在线平台。Hub 作为一个中心场所，任何人都可以在这里探索、试验、协作，用机器学习构建技术。

在 Hugging Face Hub 上，你可以创建或发现以下 ML 资产：

- [模型](https://huggingface.co/models)：托管 NLP、计算机视觉、语音、时序、生物、强化学习、化学等领域最新的 SOTA 模型。
- [数据集](https://huggingface.co/datasets)：涵盖不同领域、模态和语言的多样数据。
- [Spaces](https://huggingface.co/spaces)：交互式应用，直接在浏览器中展示 ML 模型。

上传到 Hub 的每个模型、数据集或 space 都是一个 [基于 Git 的仓库](https://huggingface.co/docs/hub/repositories)，即支持版本控制、可存放你所有文件的地方。你可以用传统的 git 命令拉取、推送、克隆和处理文件。你可以查看模型、数据集和 space 的提交历史，看到谁在什么时候做了什么。

（模型上的提交历史）

Hugging Face Hub 同时也是机器学习反馈与开发的中心。团队用 [pull request 和讨论](https://huggingface.co/blog/community-update)来支持模型、数据集和 space 的同行评审，改善协作并加速 ML 工作。

（模型上的 pull request 与讨论）

Hub 允许用户创建[组织（Organizations）](https://huggingface.co/docs/hub/organizations)，也就是团队账户，用于协作管理模型、数据集和 space。组织的仓库会展示在组织主页上，管理员可以设置角色来控制这些仓库的访问权限。只要权限合适，组织的每个成员都可以为模型、数据集和 space 做贡献。在 Hugging Face，我们相信：有了协作的工具，机器学习开发就会大大提速！🔥

（Hub 上 BigScience 的组织页）

基础讲完了，接下来看看托管在 Hugging Face Hub 上的模型、数据集和 space 各自的特点。

### 模型

[迁移学习](https://www.youtube.com/watch?v=BqqfQnyjmgg&ab_channel=HuggingFace)改变了公司处理机器学习问题的方式。传统上，公司需要从零训练模型，这要耗费大量时间、数据和资源。而现在，机器学习团队可以拿一个预训练模型，[针对自己的用例做微调](https://huggingface.co/course/chapter3/1?fw=pt)，又快又省。这极大加速了获得高精度、高性能模型的过程。

在 Hub 上，你可以找到 6 万多个覆盖 NLP、计算机视觉、语音、时序、生物、强化学习、化学等领域的最先进开源预训练模型。你可以用搜索栏，或按任务、库、许可证和其他标签筛选，找到适合你特定用例的模型：

（Hub 上可用的 60,000+ 模型）

这些模型覆盖 180 种语言、支持最多 25 个 ML 库（包括 Transformers、Keras、spaCy、Timm 等），在模型类型、语言和库方面都有很大选择空间。

每个模型都有一份[模型卡（model card）](https://huggingface.co/docs/hub/models-cards)——一个描述模型本身的简单 markdown 文件，内容包括模型的用途、训练数据、代码示例、潜在偏见与风险说明、指标、相关研究论文等等。模型卡是理解模型的好办法，也有帮你找到合适的预训练模型作为 ML 项目起点：

（模型卡）

除了提升模型的可发现性与可复用性，模型卡还让模型风险管理（MRM）流程更轻松。ML 团队通常需要按要求提供其构建模型的信息，让合规团队识别、度量和缓释模型风险。借助模型卡，组织可以预先设定包含所有必填信息的模板，让 ML 团队与合规团队之间的 MRM 沟通直接在模型页面内顺畅进行。

Hub 还提供[推理组件（Inference Widget）](https://huggingface.co/docs/hub/models-widgets)，让你直接在浏览器里试用模型！这是感受某个模型是否合适、是否值得深入的好方法：

（推理组件）

数据是构建机器学习模型的关键；没有合适的数据，就得不到准确的模型。🤗 Hub 托管了 [6000 多个开源、即取即用的 ML 数据集](https://huggingface.co/datasets)，并配有快速易用、高效的数据处理工具。和模型一样，你可以通过搜索栏或标签筛选找到适合用例的数据集。例如，按任务 "sentiment-classification" 筛选，就能轻松找到情感分析相关的数据集：

（情感分类可用数据集）

与模型类似，上传到 🤗 Hub 的数据集都有[数据集卡（Dataset Cards）](https://huggingface.co/docs/hub/datasets-cards#dataset-cards)，帮助用户理解数据集内容、该如何使用、如何创建以及使用时的相关注意事项。你可以用 [Dataset Viewer](https://huggingface.co/docs/hub/datasets-viewer) 快速查看数据，判断某个数据集是否对你的 ML 项目有用：

（Super Glue 数据集预览）

## 2. Private Hub 是什么？

[Private Hub](https://huggingface.co/platform) 让公司可以在自己的私有、合规环境中使用 Hugging Face 的完整生态，从而加速机器学习开发。它把覆盖 ML 生命周期每一步的工具集中在一个地方，让 ML 协作更简单高效，同时提供企业构建安全 ML 所必需的合规环境：

（Private Hub）

有了 Private Hub，数据科学家可以在自己的服务器上私密、安全地托管模型、数据集和 space，无缝使用 [Transformers](https://github.com/huggingface/transformers)、[Datasets](https://github.com/huggingface/datasets) 及其他[开源库](https://github.com/huggingface)，并借助 Hub 的以下功能更快完成机器学习工作：

- [AutoTrain](https://huggingface.co/autotrain)：用我们的 AutoML 无代码方案训练最先进模型，自动在你的服务器上完成微调、评估与部署。
- [Evaluate](https://huggingface.co/spaces/autoevaluate/model-evaluator)：在 Private Hub 上用任意指标评估任意数据集上的任意模型，不用写一行代码。
- [Spaces](https://huggingface.co/spaces/launch)：轻松托管 ML 演示应用，向业务方展示工作、尽早获得反馈、加快构建。
- [Inference API](https://huggingface.co/inference-api)：在 Private Hub 上创建的每个私有模型，都可以通过简单的 API 调用在你自己的基础设施上部署推理。
- [PR 与讨论](https://huggingface.co/blog/community-update)：对模型、数据集和 space 进行同行评审，提升团队间协作。

从研究到生产，你的数据永远不会离开你的服务器。Private Hub 运行在你自己的合规服务器上，提供安全扫描、审计跟踪、SSO 和访问控制等企业安全能力，保障模型与数据安全。

我们为 Private Hub 的部署提供了灵活选项，可落在你的私有合规环境中，包括：

- **托管 Private Hub（SaaS）**：运行在 Hugging Face 拥有的隔离虚拟私有服务器（VPC）中。无需管理任何基础设施，就能享受完整的 Hugging Face 私有 Hub 体验。
- **云上 Private Hub**：运行在客户自有的 AWS、Azure 或 GCP 云账户中。这种部署方式让你对底层云基础设施拥有完全的管理控制权，可实现更强的安全与合规。
- **本地 Private Hub**：在你自己的基础设施上部署 Hugging Face Hub。适合有严格合规规则、和/或不允许或不愿在公有云上运行的工作负载的客户。

了解 Private Hub 的基本面后，再来看看公司如何用它加速机器学习开发。

## 3. 公司如何用 Private Hub 加速 ML 路线图？

[🤗 Transformers](https://github.com/huggingface/transformers) 是[有史以来增长最快的开源项目之一](https://star-history.com/#tensorflow/tensorflow&nodejs/node&kubernetes/kubernetes&pytorch/pytorch&huggingface/transformers&Timeline)。我们现在提供 [25 个以上开源库](https://github.com/huggingface)，已有超过 10,000 家公司用 Hugging Face 通过机器学习构建技术。

身处开源 AI 社区的中心，我们与机器学习与数据科学团队进行了数千次对话，这让我们对公司在构建机器学习时面临的最常见问题与挑战有独特视角。

通过这些对话，我们发现当前的机器学习构建工作流是破碎的：重复劳动、反馈循环低效、团队协作摩擦大、流程与工具非标准、生产模型优化困难——这些都拖慢了 ML 开发。

我们打造 Private Hub 就是为了改变这一点。就像 Git 和 GitHub 永远改变了公司构建软件的方式，Private Hub 正在改变公司构建机器学习的方式：

（使用 Private Hub 前后对比）

本节通过一个演示示例，展示客户如何利用 PH 加速 ML 生命周期。我们将一步步构建一个 ML 应用，自动分析金融分析师的 🏦 报告。

首先，搜索一个与用例相关的预训练模型，并在自建的情感分析数据集上微调；接着，构建一个 ML Web 应用，向业务方展示模型的工作方式；最后，用 Inference API 在可承载生产级负载的架构上运行推理。这个 ML 演示应用的所有产物都可以在 [Hub 上的这个组织](https://huggingface.co/FinanceInc)找到。

### 更快地训练出高精度模型

#### 借力 Hub 上的预训练模型

迁移学习让你不再需要从零训练模型——通过微调 Hub 上现成的预训练模型适配你的具体用例，构建更准确的模型可以快 10 倍 ⚡️。

对于我们的演示示例，这个面向金融分析师的 ML 应用的需求之一就是情感分析。业务方希望财务文档和分析师报告一发布，就能立刻感知公司业绩的基调。

因此，创建这个 ML 应用的第一步，是深入 [🤗 Hub](https://huggingface.co/models)，看看有哪些预训练模型可以拿来做情感分析微调。借助搜索栏和标签，我们能非常快速地筛选和发现相关模型。很快我们找到了 [FinBERT](https://huggingface.co/yiyanghkust/finbert-pretrain)——一个在企业报告、财报电话会议记录和金融分析师报告上预训练的 BERT 模型：

（Finbert 模型）

我们把该模型[克隆](https://huggingface.co/FinanceInc/finbert-pretrain)到自己的 Private Hub 中，让团队其他同事也能使用。我们还在模型卡中补充了所需信息，以便与合规团队更顺畅地推进模型风险管理流程。

#### 用自定义数据集微调预训练模型

有了适合金融数据的优秀预训练模型，下一步是用我们自己的数据为情感分析做微调！

于是，我们先上传[团队内部构建的情感分析自定义数据集](https://huggingface.co/datasets/FinanceInc/auditor_sentiment)到 Private Hub。该数据集包含数千条英文金融新闻句子和公司自有金融数据，由团队按情感人工标注。数据含有敏感信息，合规团队只允许把它上传到我们自己的服务器。幸运的是这不成问题——我们的 Private Hub 就跑在自己的 AWS 实例上。

然后，我们用 [AutoTrain](https://huggingface.co/autotrain) 以自定义情感分析数据集快速微调 FinBert 模型。直接从 Private Hub 的数据集页面即可操作：

（用 AutoTrain 微调预训练模型）

接着，模型选择"manual"，并挑选我们[克隆的 Finbert 模型](https://huggingface.co/FinanceInc/finbert-pretrain)作为用该数据集微调的对象：

（用 AutoTrain 创建新项目）

最后，选择要用我们的数据训练多少个候选模型。我们选了 25 个——搞定！几分钟后，AutoTrain 已自动用我们的情感分析数据微调出 25 个 finbert 模型，并展示每个模型的性能指标 🔥🔥🔥

（AutoTrain 微调出的 25 个模型）

除了性能指标，我们还可以直接在浏览器里通过推理组件测试[微调后的模型](https://huggingface.co/FinanceInc/auditor_sentiment_finetuned)，直观感受其效果：

（用推理组件测试微调模型）

### 扩展推理规模，同时远离 MLOps 琐事

到这里，业务方已经给出了很有价值的反馈，帮助我们改进了模型。合规团队通过模型卡提供的信息评估了潜在风险，为项目的生产化亮了绿灯。现在，我们准备好让这些模型真正干活、开始大规模分析金融报告了！🎉

不用再浪费时间折腾 Docker/Kubernetes、为模型搭服务器或做生产优化——我们只需要用 [Inference API](https://huggingface.co/inference-api)。不必操心部署和扩展性问题，通过简单的 API 调用就能集成我们的自定义模型。

上传到 Hub 和/或用 AutoTrain 创建的模型会被即时部署到生产环境，随时可做大规模、实时的推理。而运行推理只需要 12 行代码！

要获取用我们的[情感分析模型](https://huggingface.co/FinanceInc/auditor_sentiment_finetuned)做推理的代码片段，只需点击 "Deploy" 和 "Accelerated Inference"：

（用 Inference API 对自定义模型做推理）

随后就能看到向 Inference API 发 HTTP 请求、用我们的自定义模型分析数据的代码：

```
import requests

API_URL = "https://api-inference.huggingface.co/models/FinanceInc/auditor_sentiment_finetuned"
headers = {"Authorization": "Bearer xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"}

def query(payload):
    response = requests.post(API_URL, headers=headers, json=payload)
    return response.json()

output = query({
    "inputs": "Operating profit jumped to EUR 47 million from EUR 6.6 million",
})
```

仅凭 12 行代码，我们就跑通了推理，底层基础设施可扩展、实时、能承载生产级负载 🚀。是不是很爽？

## 最后的话

机器学习正在成为构建技术的默认方式，这主要归功于开源与开放科学。

但构建机器学习依然很难。很多 ML 项目仓促上马，最终没能进入生产。ML 开发被非标准工作流拖累。ML 团队被重复劳动、团队间协作不足、碎片化的 ML 工具生态搞得灰心丧气。

在 Hugging Face，我们相信构建机器学习有更好的方式。这就是我们创建 [Private Hub](https://huggingface.co/platform) 的原因。我们认为，为机器学习开发的每一步提供统一的工具集和协作工具，会带来更好的 ML 工作、让更多 ML 方案进入生产，并帮助 ML 团队点燃创新。
