# 我们让 Claude 来微调开源 LLM

[![banner](https://raw.githubusercontent.com/huggingface/blog/refs/heads/main/assets/hf-skills-training/thumbnail.png)](https://raw.githubusercontent.com/huggingface/blog/refs/heads/main/assets/hf-skills-training/thumbnail.png)

我们通过一个新工具 [Hugging Face Skills](https://hf-learn.short.gy/gh-hf-skills) 让 Claude 获得了微调语言模型的能力。不只是写训练脚本，而是真正把任务提交到云端 GPU、监控进度，并把训练好的模型推送到 Hugging Face Hub。本教程展示它如何工作，以及你自己如何使用。

> Claude Code 可以使用「skills」——打包好的指令、脚本和领域知识——来完成专门任务。hf-llm-trainer 这个 skill 教会 Claude 关于训练的一切：什么规模的模型该选什么 GPU、如何配置 Hub 认证、什么时候用 LoRA、什么时候全量微调，以及一次成功训练背后几十个其他决策该怎么处理。

有了这个 skill，你可以对 Claude 说：

```
Fine-tune Qwen3-0.6B on the dataset open-r1/codeforces-cots
```

然后 Claude 会：

- 校验你的数据集格式
- 选择合适的硬件（0.6B 模型用 t4-small）
- 使用并更新带 Trackio 监控的训练脚本
- 把任务提交到 Hugging Face Jobs
- 报告任务 ID 和预估费用
- 在你询问时查看进度
- 出了问题帮你调试

模型在 Hugging Face 的 GPU 上训练，你去做别的事。训练完成后，微调好的模型就出现在 Hub 上，随时可用。

这不是玩具演示。这个 skill 支持与生产环境相同的训练方法：监督微调、直接偏好优化，以及带可验证奖励的强化学习。你可以训练 0.5B 到 70B 参数的模型，把它们转成 GGUF 做本地部署，还能跑组合多种技术的多阶段流水线。

## 安装与配置

开始前你需要：

- 一个开通了 [Pro](https://hf.co/pro) 或 [Team / Enterprise](https://hf.co/enterprise) 计划的 Hugging Face 账户（Jobs 需要付费计划）
- 一个来自 [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens) 的写权限 token
- 一个编码智能体，如 Claude Code、OpenAI Codex 或 Google 的 Gemini CLI

Hugging Face skills 兼容 Claude Code、Codex 和 Gemini CLI。对 Cursor、Windsurf、Continue 的集成也在路上。

### Claude Code

- 把仓库注册为 marketplace 插件：

```
/plugin marketplace add huggingface/skills
```

- 安装某个 skill，运行：

```
/plugin install <skill-folder>@huggingface-skills
```

例如：

```
/plugin install hf-llm-trainer@huggingface-skills
```

### Codex

- Codex 会通过 `AGENTS.md` 文件识别 skills。你可以用下面的命令验证指令已加载：

```
codex --ask-for-approval never "Summarize the current instructions."
```

- 更多细节见 [Codex AGENTS 指南](https://developers.openai.com/codex/guides/agents-md)。

### Gemini CLI

- 本仓库包含 `gemini-extension.json`，用于集成 Gemini CLI。
- 本地安装：

```
gemini extensions install . --consent
```

或使用 GitHub URL：

```
gemini extensions install https://github.com/huggingface/skills.git --consent
```

- 更多帮助见 [Gemini CLI 扩展文档](https://geminicli.com/docs/extensions/#installing-an-extension)。

### 连接 Hugging Face

你必须用[写权限 token](https://huggingface.co/settings/tokens)认证到 Hugging Face 账户，任务才能创建模型仓库。

设置 token：

```
hf auth login
# or 
export HF_TOKEN=hf_your_write_access_token_here
```

> 配置 Hugging Face MCP Server 使用你的写 token：通过 HF_TOKEN 或 Authorization: Bearer HTTP 头发送。
> Claude Code：claude mcp add --transport http hf-skills https://huggingface.co/mcp?bouquet=skills --header "Authorization: Bearer $HF_TOKEN"

## 第一次训练

我们走一遍完整示例。先微调一个小模型，看完整工作流，然后再探索更高级的能力。

### 让编码智能体去微调

从一个简单明确的指令开始，微调指定模型：

```
Fine-tune Qwen3-0.6B on the open-r1/codeforces-cots dataset for instruction following. 
```

编码智能体会分析你的请求并准备训练配置。对于在这个演示数据集上训练 0.6B 模型，它选择了 `t4-small`——对这个模型规模够用，也是最便宜的选择。

> open-r1/codeforces-cots 是一个包含 Codeforces 题目和解答的数据集，很适合用来指令微调一个能解高难度编程问题的模型。

> 这对视觉语言模型同样有效！你可以直接运行「Fine-tune Qwen/Qwen3-VL-2B-Instruct on llava-instruct-mix」。

### 提交前先检查

在你的编码智能体提交任何东西之前，你会看到配置：

```
I'll fine-tune Qwen/Qwen3-0.6B on open-r1/codeforces-cots using SFT.

Configuration:
- Hardware: t4-small (~$0.75/hour)
- Estimated time: ~20 minutes
- Estimated cost: ~$0.30
- Output: username/qwen-codeforces-cots-sft

The model will be pushed to Hub automatically. Should I submit?
```

这是你调整一切的机会。改输出仓库名、换硬件，或者让 Claude 修改训练参数。你批准后，智能体就提交任务。

比如，你可以让智能体先试跑一次：

```
Do a quick test run on 100 examples.
```

### 跟踪进度

提交后你会拿到任务详情：

```
✅ Job submitted successfully!

Job ID: abc123xyz
Monitor: https://huggingface.co/jobs/username/abc123xyz

Expected time: ~20 minutes
Estimated cost: ~$0.30

View real-time metrics at: https://huggingface.co/spaces/username/trackio
```

[![Example Trackio dashboard of a Sweep test](https://raw.githubusercontent.com/huggingface/skills/c1452671ff251c138b1f6adc974ed8f54beb21e7/apps/tutorials/sweep_example.png)](https://raw.githubusercontent.com/huggingface/skills/c1452671ff251c138b1f6adc974ed8f54beb21e7/apps/tutorials/sweep_example.png)

这个 skill 内置 Trackio 集成，你可以实时看着训练损失下降。任务异步运行，你可以关掉终端回头再来。想要更新时：

```
How's my training job doing?
```

智能体就会拉取日志并总结进度。

### 使用你的模型

训练完成后，你的模型就在 Hub 上了：

```
from transformers import AutoModelForCausalLM, AutoTokenizer

model = AutoModelForCausalLM.from_pretrained("username/qwen-codeforces-cots-sft")
tokenizer = AutoTokenizer.from_pretrained("username/qwen-codeforces-cots-sft")
```

这就是完整闭环。你用普通英语描述了想要什么，智能体搞定了 GPU 选择、脚本生成、任务提交、认证和持久化。整个过程花了大约三毛钱。

## 训练方法

这个 skill 支持三种训练方式。了解各自的适用时机能帮你拿到更好的结果。

### 监督微调（SFT）

大多数项目从 SFT 开始。你提供示范数据——输入和期望输出的例子——训练让模型去匹配这些模式。

当你有高质量的目标行为示例时就该用 SFT：客服对话、代码生成对、领域专属问答——任何你能向模型展示「好的样子」的数据。

```
Fine-tune Qwen3-0.6B on my-org/support-conversations for 3 epochs.
```

智能体会验证数据集、选择硬件（7B 模型用 a10g-large + LoRA），并配置带 checkpoint 和监控的训练。

> 对超过 3B 参数的模型，智能体会自动使用 LoRA（Low-Rank Adaptation，低秩适配）来降低内存需求。这让 7B 或 13B 模型在单张 GPU 上的训练变得可行，同时保留大部分全量微调的质量。

### 直接偏好优化（DPO）

DPO 在偏好数据对上训练——一个回答被「选中」、另一个被「拒绝」。这让模型输出对齐人类偏好，通常放在初步 SFT 之后。

当你有人工标注的偏好或自动比较结果时使用 DPO。DPO 直接优化偏好回答，不需要单独训练奖励模型。

```
Run DPO on my-org/preference-data to align the SFT model I just trained.
The dataset has 'chosen' and 'rejected' columns.
```

> DPO 对数据集格式敏感。它要求列名精确为 chosen 和 rejected，或带输入数据的 prompt 列。智能体会先验证这一点；如果你的数据集用了别的列名，它会向你展示如何做列映射。

> 用 Skills 也能对视觉语言模型跑 DPO！试试 openbmb/RLAIF-V-Dataset。Claude 会做一些小修改，最终能训练成功。

### 组相对策略优化（GRPO）

GRPO 是一种强化学习方法，已被证明在可验证任务上有效：解数学题、写代码，或任何有程序化成功标准的任务。

```
Train a math reasoning model using GRPO on the openai/gsm8k dataset based on Qwen3-0.6B.
```

模型生成回答、根据正确性获得奖励、从结果中学习。这比 SFT 或 DPO 更复杂，但配置方式类似。

## 硬件与费用

智能体根据你的模型规模选硬件，但了解取舍能帮你做更好的决策。

### 模型规模与 GPU 对应关系

**1B 参数以下的微型模型**，`t4-small` 就很合适。这些模型训练很快——完整跑一遍约 1-2 美元。非常适合教学或实验。

**小模型（1-3B）**，升级到 `t4-medium` 或 `a10g-small`。训练要几个小时，花费 5-15 美元。

**中等模型（3-7B）**，需要 `a10g-large` 或 `a100-large` 配合 LoRA。全量微调放不下，但 LoRA 让这类模型非常好训。生产预算 15-40 美元。

**大模型（7B+）**，这个 HF skills 任务就不合适了。

### 演示 vs 生产

测试工作流时，从小开始：

```
Do a quick test run to SFT Qwen-0.6B with 100 examples of my-org/support-conversations.
```

编码智能体会配置最小化训练——足以验证你的流水线能跑，几乎不花钱。

生产环境则要明确：

```
SFT Qwen-0.6B for production on the full my-org/support-conversations.
Checkpoints every 500 steps, 3 epochs, cosine learning rate.
```

> 在投入一个数小时的生产任务之前，先跑一次演示。一个 0.5 美元的演示抓出格式错误，能省下 30 美元的失败运行。

## 数据集验证

数据集格式是训练失败最常见的原因。智能体可以在你消耗 GPU 时间之前验证数据集。

```
Check if my-org/conversation-data works for SFT training.
```

智能体在 CPU 上跑一次快速检查（花不到一分钱的零头）并报告：

```
Dataset validation for my-org/conversation-data:

SFT: ✓ READY
  Found 'messages' column with conversation format

DPO: ✗ INCOMPATIBLE
  Missing 'chosen' and 'rejected' columns
```

如果你的数据集需要转换，智能体可以教你怎么做：

```
My DPO dataset uses 'good_response' and 'bad_response' instead
of 'chosen' and 'rejected'. How do I fix this?
```

智能体给出映射代码，并能直接把它整合进你的训练脚本。

## 监控训练

实时监控能帮你尽早发现问题。这个 skill 默认配置 Trackio——提交任务后，你可以在这里看指标：

```
https://huggingface.co/spaces/username/trackio
```

上面有训练损失、学习率和验证指标。健康的运行会显示损失稳步下降。

随时询问智能体状态：

```
What's the status of my training job?
```

```
Job abc123xyz is running (45 minutes elapsed)

Current step: 850/1200
Training loss: 1.23 (↓ from 2.41 at start)
Learning rate: 1.2e-5

Estimated completion: ~20 minutes
```

出问题的时候，智能体帮忙诊断。显存溢出（OOM）？智能体建议减小 batch size 或升级硬件。数据集错误？智能体会定位不匹配之处。超时？智能体建议更长的时限或更快的训练设置。

## 转换为 GGUF

训练之后，你可能想在本地运行模型。GGUF 格式兼容 llama.cpp 以及 LM Studio、Ollama 等依赖工具。

```
Convert my fine-tuned model to GGUF with Q4_K_M quantization.
Push to username/my-model-gguf.
```

智能体提交一个转换任务：合并 LoRA 适配器、转换为 GGUF、应用量化，然后推送到 Hub。

之后在本地使用：

```
llama-server -hf <username>/<model-name>:<quantization>

# For example, to run the Qwen3-1.7B-GGUF model on your local machine:
llama-server -hf unsloth/Qwen3-1.7B-GGUF:Q4_K_M
```

## 接下来

我们已经证明，像 Claude Code、Codex 或 Gemini CLI 这样的编码智能体能处理模型微调的完整生命周期：验证数据、选择硬件、生成脚本、提交任务、监控进度、转换产物。这曾经是一项专门技能，现在变成了你通过对话就能完成的事。

一些可以尝试的事情：

- 在你自己的数据集上微调一个模型
- 用 SFT → DPO 构建偏好对齐的模型
- 用 GRPO 在数学或代码上训练推理模型
- 把模型转成 GGUF 并用 Ollama 运行

[这个 skill 是开源的](https://hf-learn.short.gy/gh-hf-skills)。你可以扩展它、按你的工作流定制它，或把它作为其他训练场景的起点。
