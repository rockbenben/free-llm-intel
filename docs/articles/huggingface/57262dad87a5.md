如今的现代语言模型在预训练时往往需要大量算力，在没有几十上百块 GPU 或 TPU 的情况下几乎无法获得。尽管理论上可以整合多个个人的资源，但实践中，此类分布式训练方法此前取得的成功有限，因为互联网上的连接速度远慢于高性能 GPU 超算内部的连接。

在这篇博文中，我们介绍 [DeDLOC](https://arxiv.org/abs/2106.10207)——一种新的协作式分布式训练方法，它能自我适配参与者的网络与硬件约束。我们通过 40 位志愿者协作预训练孟加拉语模型 [sahajBERT](https://huggingface.co/neuropark/sahajBERT)，证明它可以成功应用于现实场景。在孟加拉语下游任务上，该模型达到了接近最先进的质量，结果可与动用数百台顶级加速器训练的大得多的模型相提并论。

## 开放协作中的分布式深度学习（Distributed Deep Learning in Open Collaborations）

### 我们为什么要做这件事？

如今，许多最高质量的 NLP 系统基于大型预训练 Transformer。总体而言，规模越大质量越好：通过扩大参数量、利用海量无标注文本数据，你可以在自然语言理解与生成上取得无与伦比的结果。

遗憾的是，我们使用这些预训练模型不只是因为方便。在大数据集上训练 Transformer 所需的硬件资源，往往超出个人甚至大多数商业或研究机构所能负担的范围。以 BERT 为例：据估算其训练成本约为 7,000 美元；而对 GPT-3 这样最大的模型，这一数字可高达 1,200 万美元！这种资源限制看似理所当然、无可避免，但对更广泛的 ML 社区而言，使用预训练模型真的没有别的选择吗？

不过，摆脱这一困境的办法也许是存在的：只需环顾四周。我们要找的计算资源可能已经在那里了——比如，我们当中许多人家里有配着游戏卡或工作站 GPU 的强力电脑。你可能已经猜到，我们要像 [Folding@home](https://foldingathome.org/)、[Rosetta@home](https://boinc.bakerlab.org/)、[Leela Chess Zero](https://lczero.org/) 以及各种利用志愿者计算的 [BOINC](https://boinc.berkeley.edu/) 项目那样把它们的力量联合起来，而且做法更为通用。例如，若干实验室可以合并各自较小的集群以用尽所有可用资源，也有人可能想用廉价的云实例加入实验。

在怀疑者看来，我们似乎遗漏了一个关键因素：分布式 DL 中的数据传输常常是瓶颈，因为我们需要聚合来自多个 worker 的梯度。确实，任何天真的互联网分布式训练方法都注定失败——大多数参与者没有千兆连接，而且可能随时断网。那么，用家庭上网套餐到底怎么可能训练出什么东西呢？:)

作为对这个问题的解法，我们提出了一种新的训练算法，称为开放协作中的分布式深度学习（**DeDLOC**），详见我们最近发布的 [preprint](https://arxiv.org/abs/2106.10207)。接下来，让我们看看这一算法背后的核心思想！

### 与志愿者一起训练

在最常用的版本中，多 GPU 分布式训练相当直接。回想一下：做深度学习时，你通常在训练数据的一个 batch 的多个样本上计算损失函数的平均梯度。在*数据并行（data-parallel）*分布式 DL 中，你只需把数据切分到多个 worker 上、各自计算梯度，然后在本地 batch 处理完毕后对它们求平均。当所有 worker 都算出平均梯度后，我们用优化器调整模型权重并继续训练。下面可以看到所执行各类任务的示意图。

[![assets/24_sahajBERT/roles_tasks.png](https://huggingface.co/blog/assets/24_sahajBERT/roles_tasks.png)](https://huggingface.co/blog/assets/24_sahajBERT/roles_tasks.png)

分布式训练中由对等节点执行的典型机器学习任务，可能带有角色分工

通常，为了减少同步量并稳定学习过程，我们可以在求平均前累积 N 个 batch 的梯度，这相当于把实际 batch size 扩大 N 倍。这一做法，加上「大多数最先进语言模型使用大 batch」这一观察，让我们得到一个简单的想法：在每次优化器步骤之前，跨所有志愿者设备累积一个*非常*大的 batch！除了与常规分布式训练完全等价、易于扩展之外，这种方法还天然具备容错能力，我们在下面说明。

让我们考虑协作实验中可能遇到的几种失效场景。最常见的情况是某位或多位参与者从训练过程中掉线：他们可能连接不稳定，或者只是想把 GPU 拿去干别的。这种情况下，训练只遭受轻微挫折：这些参与者的贡献会从当前累积的 batch size 中扣除，但其他参与者会用他们的梯度补上。而且，如果更多参与者加入，目标 batch size 只会更快达到，训练过程自然提速。你在视频中可以看到演示：

### 自适应平均

讨论完整体训练流程后，还剩一个问题：我们如何实际聚合参与者的梯度？大多数家用电脑难以接受传入连接，下载速度也可能成为约束。

由于实验依赖志愿者硬件，中心服务器并非可行选项——当扩展到数十个客户端、上亿参数时，它会很快被压垮。反正当今大多数数据并行训练也不使用该策略，而是依赖 All-Reduce——一种高效的 all-to-all 通信原语。得益于巧妙的算法优化，每个节点无需把整个本地梯度发给每个对等方，即可计算出全局平均。

因为 All-Reduce 是去中心化的，它看起来是个好选择；不过，我们仍需考虑硬件与网络环境的多样性。例如，有些志愿者可能从网络慢但 GPU 强的电脑加入，有些可能只与部分对等方有更好的连接，还有些可能被防火墙挡住了传入连接。

结果发现，利用这些性能信息，我们其实可以动态地设计出最优的数据传输策略。宏观上，我们根据每个对等方的网速将整个梯度向量切分成不同的部分：连接最快的负责聚合最大的部分。另外，若某些节点不接受传入连接，它们就只发送自己的数据用于聚合，而不亲自计算平均。视条件而定，这一自适应算法既能还原经典的分布式 DL 算法，又能以混合策略对其改进，如下所示。

## sahajBERT

一如既往，设计得再好的算法框架也不保证在实践中按预期工作，因为某些假设可能在真实训练运行中不成立。为了验证这一技术的竞争力、展示其潜力，我们组织了一场特别的协作活动，为孟加拉语预训练一个掩码语言模型。尽管孟加拉语是世界第五大母语人口的语言，其开放可用的掩码语言模型却[寥寥无几](https://huggingface.co/models?filter=bn&pipeline_tag=fill-mask)，这恰恰凸显了这类赋能社区的工具的重要性——它们能解锁该领域的大量机会。

我们与 Neuropark 社区的真实志愿者完成了这次实验，并使用开放可用的数据集（OSCAR 与 Wikipedia），因为我们想要一个完全可复现的例子，能激励其他团队。下面，我们详述训练运行的设置并展示其结果。

### 架构

实验中我们选择了 ALBERT（*A Lite BERT*）——一个以掩码语言建模（MLM）与句子顺序预测（SOP）为目标预训练的语言表征模型。选择这一架构是因为权重共享使其参数极其高效：例如，ALBERT-large 只有约 18M 可训练参数，在 GLUE 基准上与约 108M 权重的 BERT-base 表现相当。这意味着对等方之间需要交换的数据更少，这对我们的设置至关重要，可显著加快每次训练迭代。

### 分词器（Tokenizer）

我们模型的第一块砖称为*tokenizer*，负责把原始文本转换为词汇表索引。由于我们训练的模型面向孟加拉语——它与英语差异不小——我们需要在 tokenizer 中实现语言特定的预处理。可以把它看作一连串操作：

- **归一化（Normalization）：** 包括对原始文本数据的所有预处理操作。这是我们改动最多的一步，因为删去某些细节可能改变文本含义、也可能保持不变，取决于语言。例如，标准 ALBERT 归一化器会去掉重音符号，而对孟加拉语我们必须保留它们，因为其中包含元音信息。最终我们采用以下操作：NMT 归一化、NFKC 归一化、多余空格清理、孟加拉语中反复出现的 Unicode 字符统一化，以及小写化。
- **预分词（Pretokenization）：** 描述切分输入的规程（例如按空白切分），以强制特定的 token 边界。与原始工作一致，我们选择让空白不属于 token。因此，为了区分单词、避免出现多个单空格 token，每个位于词开头的 token 都以特殊字符 "_"（U+2581）起始。此外，我们把所有标点和数字与其他字符隔离，以精简词汇表。
- **Tokenizer 建模：** 在这一层，文本被映射为词汇表元素的序列。对此有若干算法，如 Byte-Pair Encoding（BPE）或 Unigram，其中大多数需要从文本语料构建词汇表。遵循 ALBERT 的设置，我们使用 **Unigram Language Model** 方法，在去重后的 OSCAR 数据集孟加拉语部分上训练了一个 32k token 的词汇表。
- **后处理（Post-processing）：** 分词之后，我们可能想添加架构要求的若干特殊 token，例如以 `[CLS]` 起始序列、用 `[SEP]` 分隔两个片段。由于我们的主架构与原版 ALBERT 相同，我们保持相同的后处理：具体地说，在每个样例开头加 `[CLS]`，并在两个片段之间及序列末尾都加 `[SEP]`。

💡 各组件的更多信息请阅读 [Tokenizers doc](https://huggingface.co/docs/tokenizers/python/latest/components.html#components)

你可以运行以下代码复用我们的 tokenizer：

```
from transformers import AutoTokenizer
tokenizer = AutoTokenizer.from_pretrained("neuropark/sahajBERT")
```

### 数据集

最后要谈的是训练数据集。如你所知，BERT 或 ALBERT 这类预训练模型的一大优势是不需要标注数据集，只需要大量文本。训练 sahajBERT 时，我们使用了 [2021-03-20 的孟加拉语 Wikipedia dump](https://huggingface.co/datasets/lhoestq/wikipedia_bn) 和 [OSCAR](https://huggingface.co/datasets/oscar) 的孟加拉语子集（600MB + 6GB 文本）。这两个数据集都可以轻松从 HF Hub 下载。

然而，加载整个数据集需要时间和存储——而这两样我们的对等方未必都有。为了充分利用参与者提供的资源，我们实现了**数据集流式加载（dataset streaming）**，让他们加入网络后几乎可以立刻开始训练。具体而言，数据集中的样本是在训练的同时被并行下载和转换的。我们还可以打乱数据集，使各对等方同时处理到相同样本的概率很小。由于数据集不是预先下载和预处理的，从纯文本到训练样本所需的转换（见下图）都是在线完成的。

[![Create dataset](https://huggingface.co/blog/assets/24_sahajBERT/create_dataset.png)](https://huggingface.co/blog/assets/24_sahajBERT/create_dataset.png)

从原始样本到训练样本

数据集流式模式自 🤗 datasets 库 v1.9 起可用，你现在就可以这样使用：

```
from datasets import load_dataset

oscar_dataset = load_dataset("oscar", name="unshuffled_deduplicated_bn", streaming=True)
```

### 协作活动

sahajBERT 协作训练活动于 5 月 12 日至 21 日举行。活动汇聚了 40 位参与者，其中 30 位是孟加拉语志愿者，10 位来自作者之一所在组织的志愿者。这 40 位志愿者加入了 [Neuropark](https://neuropark.co/) 的 Discord 频道，接收活动的所有信息并参与讨论。要加入实验，志愿者需要：

- 把自己的用户名发给管理员以加入白名单；
- 在本地、Google Colaboratory 或 Kaggle 上打开提供的 notebook；
- 运行一个代码单元，并在被要求时填入 Hugging Face 凭证；
- 在共享看板上观看训练损失下降！

出于安全考虑，我们搭建了一套授权系统，只有 Neuropark 社区成员才能训练模型。略去技术细节：我们的授权协议能保证每位参与者都在白名单内，并确认每位对等方的个人贡献。

在下图中，你可以看到每位志愿者的活动情况。整个实验中，志愿者们共登录了 600 个不同的会话。参与者经常并行启动多个运行，许多人还把自己启动的运行在时间上分散开。单个参与者的运行平均时长为 4 小时，最长为 21 小时。参与统计的更多细节可参阅论文。

展示 [sahajBERT](https://huggingface.co/neuropark/sahajBERT) 实验参与者的图表。圆半径相对累计处理的 batch 数，参与者不活动时圆变灰。每个紫色方块代表一台活动中的设备，颜色越暗表示性能越高

除了参与者提供的资源，我们还使用了 16 个可抢占（便宜但频繁被打断）的单 GPU T4 云实例来保证运行的稳定性。实验累计运行时长为 234 天，下图中你就能看到每位 peer 贡献的损失曲线片段！

### 评测

为评估 sahajBERT 的性能，我们在两个孟加拉语下游任务上对它做了微调：

- 在 [WikiANN](https://aclanthology.org/P17-1178/) 的孟加拉语划分上做命名实体识别（NER）。该任务的目标是把输入文本中的每个 token 分为以下类别之一：人名、组织、地点，或都不是。
- 在来自 [IndicGLUE](https://aclanthology.org/2020.findings-emnlp.445/) 的 Soham articles 数据集上做新闻类别分类（NCC）。该任务的目标是预测输入文本所属的类别。

我们在训练过程中于 NER 任务上评测它，以确认一切顺利；从下面的图可以看到，确实如此！

不同预训练模型 checkpoint 上微调模型在 NER 任务上的评测指标。

训练结束后，我们将 sahajBERT 与另外三个预训练语言模型比较：[XLM-R Large](https://arxiv.org/abs/1911.02116)、[IndicBert](https://aclanthology.org/2020.findings-emnlp.445/) 和 [bnRoBERTa](https://huggingface.co/neuralspace-reverie/indic-transformers-bn-roberta)。下表显示，我们的模型结果可与 HF Hub 上最好的孟加拉语语言模型相当——尽管我们的模型只有约 18M 训练参数，而例如 XLM-R（一个强多语言基线）有约 559M 参数、在数百块 V100 GPU 上训练。

#### sahajBERT-NER

Model card: [https://hf.co/neuropark/sahajBERT-NER](https://hf.co/neuropark/sahajBERT-NER)

```
from transformers import (
    AlbertForTokenClassification,
    TokenClassificationPipeline,
    PreTrainedTokenizerFast,
)

# Initialize tokenizer
tokenizer = PreTrainedTokenizerFast.from_pretrained("neuropark/sahajBERT-NER")

# Initialize model
model = AlbertForTokenClassification.from_pretrained("neuropark/sahajBERT-NER")

# Initialize pipeline
pipeline = TokenClassificationPipeline(tokenizer=tokenizer, model=model)

raw_text = "এই ইউনিয়নে ৩ টি মৌজা ও ১০ টি গ্রাম আছে ।" # Change me
output = pipeline(raw_text)
```

## 结论

在这篇博文中，我们讨论了一种能够协作预训练神经网络的方法，并以 sahajBERT 作为其应用于现实问题的首个真正成功案例。

这对更广泛的 ML 社区意味着什么？首先，现在你可以和朋友一起跑大规模分布式预训练了，我们期待看到很多以前难以企及的酷炫新模型。此外，我们的结果对多语言 NLP 也可能意义重大：任何语言的社区现在都可以训练自己的模型，而无需把大量计算资源集中在一处。
