# 英特尔与 Hugging Face 合作，让机器学习硬件加速走向大众

Julien Simon（juliensimon）

[![image](https://huggingface.co/blog/assets/80_intel/01.png)](https://huggingface.co/blog/assets/80_intel/01.png)

Hugging Face 的使命是让优质机器学习走向大众，并让它在各行各业和社会中发挥最大的正面影响。我们不仅致力于推进 Transformer 模型，也在努力简化它们的使用。

今天，我们很高兴宣布 Intel 正式加入我们的 [Hardware Partner Program](https://huggingface.co/hardware)。借助 [Optimum](https://github.com/huggingface/optimum-intel) 开源库，Intel 和 Hugging Face 将合作构建最先进的硬件加速，用于用 Transformers 进行训练、微调和预测。

Transformer 模型正变得越来越大、越来越复杂，这可能给搜索、聊天机器人这类对延迟敏感的应用带来生产上的挑战。遗憾的是，延迟优化长期以来一直是机器学习（ML）从业者的一大难题。即便对底层框架和硬件平台有深入了解，也需要大量试错才能搞清楚该用哪些手段和特性。

Intel 用 Intel Xeon Scalable CPU 平台，以及一系列硬件优化的 AI 软件工具、框架和库，提供了加速 AI 的完整基础。因此，Hugging Face 与 Intel 联手、合作构建强大的模型优化工具，让用户在 Intel 平台上获得最佳的性能、规模和生产力，是再合理不过的事。

Intel 副总裁、AI 与分析事业部总经理 Wei Li 表示："*我们很高兴与 Hugging Face 合作，通过开源集成和一体化的开发者体验，把 Intel Xeon 硬件和 Intel AI 软件的最新创新带给 Transformers 社区。*"

近几个月，Intel 与 Hugging Face 在扩展 Transformer 工作负载上做了合作。我们发布了详细的调优指南和推理基准（[第 1 部分](https://huggingface.co/blog/bert-cpu-scaling-part-1)、[第 2 部分](https://huggingface.co/blog/bert-cpu-scaling-part-2)），并在最新的 Intel Xeon Ice Lake CPU 上把 DistilBERT 做到了[个位数毫秒级延迟](https://huggingface.co/blog/infinity-cpu-performance)。在训练侧，我们加入了对 [Habana Gaudi](https://huggingface.co/blog/getting-started-habana) 加速器的支持，它相比 GPU 可提供高达 40% 更优的性价比。

接下来顺理成章的一步，是在此基础上扩展并与 ML 社区共享。于是有了 [Optimum Intel](https://github.com/huggingface/optimum-intel) 开源库！我们深入看看。

## 用 Optimum Intel 获得峰值 Transformers 性能

[Optimum](https://github.com/huggingface/optimum) 是 Hugging Face 创建的开源库，旨在简化在不断增长的训练与推理设备上的 Transformer 加速。得益于内建的优化技术，你可以用现成的脚本、或对现有代码做极少改动，在几分钟内就开始加速你的工作负载。新手可以开箱即用 Optimum 并获得出色结果，专家可以继续微调以达到最大性能。

[Optimum Intel](https://github.com/huggingface/optimum-intel) 是 Optimum 的一部分，构建于 [Intel Neural Compressor](https://www.intel.com/content/www/us/en/developer/tools/oneapi/neural-compressor.html)（INC）之上。INC 是一个[开源库](https://github.com/intel/neural-compressor)，为多种深度学习框架提供统一接口，支持流行的网络压缩技术，如量化、剪枝和知识蒸馏。这个工具支持自动的、以精度为导向的调优策略，帮助用户快速构建最佳的量化模型。

有了 Optimum Intel，你可以用最小的精力把最先进的优化技术应用于你的 Transformers。我们来看一个完整示例。

## 案例研究：用 Optimum Intel 量化 DistilBERT

在这个示例里，我们会对一个为分类微调过的 DistilBERT 模型做训练后量化。量化是一个通过降低模型参数的位宽来缩减内存和算力需求的过程。例如，你常常可以用 8-bit 整数替换 32-bit 浮点参数，只付出预测精度的一点下降。

我们已经把原始模型微调好，用于按星级评分（1 到 5 星）对鞋子商品评论做分类。你可以在 Hugging Face hub 上查看这个[模型](https://huggingface.co/juliensimon/distilbert-amazon-shoe-reviews)及其[量化](https://huggingface.co/juliensimon/distilbert-amazon-shoe-reviews-quantized?)版本。你也可以在这个 [Space](https://huggingface.co/spaces/juliensimon/amazon-shoe-reviews-spaces) 里测试原始模型。

开始吧！所有代码都在这个 [notebook](https://gitlab.com/juliensimon/huggingface-demos/-/blob/main/amazon-shoes/03_optimize_inc_quantize.ipynb) 里。

和往常一样，第一步是安装所有所需的库。值得一提的是，我们必须使用 PyTorch 的纯 CPU 版本，量化过程才能正确工作。

```
pip -q uninstall torch -y 
pip -q install torch==1.11.0+cpu --extra-index-url https://download.pytorch.org/whl/cpu
pip -q install transformers datasets optimum[neural-compressor] evaluate --upgrade
```

然后，我们准备一个评估数据集，用于在量化期间评估模型性能。从我们用来微调原始模型的数据集出发，我们只保留几千条评论及其标签，并存到本地存储。

接着，我们从 Hugging Face hub 加载原始模型、它的分词器和评估数据集。

```
from datasets import load_dataset
from transformers import AutoModelForSequenceClassification, AutoTokenizer

model_name = "juliensimon/distilbert-amazon-shoe-reviews"
model = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=5)
tokenizer = AutoTokenizer.from_pretrained(model_name)
eval_dataset = load_dataset("prashantgrao/amazon-shoe-reviews", split="test").select(range(300))
```

然后，我们定义一个评估函数，在评估数据集上计算模型指标。这让 Optimum Intel 库能够比较量化前后的这些指标。就这个目的而言，Hugging Face 的 [evaluate](https://github.com/huggingface/evaluate/) 库非常方便！

```
import evaluate

def eval_func(model):
    task_evaluator = evaluate.evaluator("text-classification")
    results = task_evaluator.compute(
        model_or_pipeline=model,
        tokenizer=tokenizer,
        data=eval_dataset,
        metric=evaluate.load("accuracy"),
        label_column="labels",
        label_mapping=model.config.label2id,
    )
    return results["accuracy"]
```

随后，我们用[配置]来设置量化作业。关于这个配置的细节可在 Neural Compressor [文档](https://github.com/intel/neural-compressor/blob/master/docs/source/quantization.md)找到。这里我们采用训练后动态量化，可接受的精度下降为 5%。如果精度下降超过允许的 5%，就会对模型的不同部分做量化，直到达到可接受的精度下降，或达到最大试验次数（这里设为 10）。

```
from neural_compressor.config import AccuracyCriterion, PostTrainingQuantConfig, TuningCriterion

tuning_criterion = TuningCriterion(max_trials=10)
accuracy_criterion = AccuracyCriterion(tolerable_loss=0.05)
# Load the quantization configuration detailing the quantization we wish to apply
quantization_config = PostTrainingQuantConfig(
    approach="dynamic",
    accuracy_criterion=accuracy_criterion,
    tuning_criterion=tuning_criterion,
)
```

现在我们可以启动量化作业，并把得到的模型及其配置文件存到本地存储。

```
from neural_compressor.config import PostTrainingQuantConfig
from optimum.intel.neural_compressor import INCQuantizer

# The directory where the quantized model will be saved
save_dir = "./model_inc"
quantizer = INCQuantizer.from_pretrained(model=model, eval_fn=eval_func)
quantizer.quantize(quantization_config=quantization_config, save_directory=save_dir)
```

很好，但这对精度和预测时间有什么影响？

在每个量化步骤前后，Optimum Intel 都会在当前模型上运行评估函数。量化模型的精度现在比原始模型（`0.574`）略低（`0.546`）。我们还看到，量化模型的评估步骤比原始模型快 1.34 倍。几行代码换来这个，不错！

## 我们才刚开始

在这个示例里，我们演示了如何用 Optimum Intel 轻松对模型做训练后量化，而这只是开始。该库还支持其他类型的量化，以及剪枝——一种把对预测结果影响很小或没有影响的模型参数置零或移除的技术。
