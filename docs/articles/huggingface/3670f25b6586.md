# Hugging Face 与 JFrog 合作，让 AI 安全更透明

我们很高兴地宣布与 [JFrog](https://jfrog.com)——JFrog 软件供应链平台的创造者——建立合作伙伴关系，这是我们为 ML 社区提供安全可靠平台的[长期承诺](https://huggingface.co/blog/2024-security-features)的一部分。

我们决定将 JFrog 的扫描器加入我们的平台，以持续提升 Hugging Face Hub 的安全性。JFrog 的扫描器为扫描带来了新的能力，旨在减少 Hub 上的误报。事实上，我们目前观察到：模型权重中可能包含在反序列化时、并视格式不同有时在推理时会被执行的代码。这些代码对开发者而言往往是无害的常规用法。由于我们现有的 picklescan 扫描器只对模块名做模式匹配，我们无法总是确认某个函数或模块的使用是否为恶意。JFrog 则更进一步，会解析并分析它在模型权重中找到的代码，以检查潜在的恶意用法。

> 有兴趣加入我们的安全合作 / 在 Hub 上提供扫描信息吗？请通过 security@huggingface.co 与我们联系。

## 模型安全回顾

为了共享模型，我们会对权重、配置以及我们用于与模型交互的其他数据结构进行序列化，以便存储与传输。某些序列化格式容易受到恶意攻击，例如任意代码执行（说的就是你，pickle），这使得使用这些格式的共享模型可能变得危险。

随着 Hugging Face 成为热门的模型共享平台，我们希望能帮助社区防范此类风险——正因如此，我们开发了像 [picklescan](https://github.com/mmaitre314/picklescan) 这样的工具，也正因如此，我们把 JFrog 集成进了我们的扫描器套件。

pickle 并不是唯一可被利用的格式，[可参考此文档](https://github.com/Azure/counterfit/wiki/Abusing-ML-model-file-formats-to-create-malware-on-AI-systems:-A-proof-of-concept)了解如何利用 Keras Lambda 层实现任意代码执行。好消息是，JFrog 既能捕获这两种攻击，还能在更多文件格式中捕获更多威胁——最新扫描器信息请查阅他们的 [Model Threats](https://research.jfrog.com/model-threats/) 页面。

> 在此阅读我们关于安全的全部文档：https://huggingface.co/docs/hub/security 🔥

## 集成

你无需做任何操作就能从中受益！所有公开模型仓库在你把文件推送到 Hub 后，都会被 JFrog 自动扫描。你可以查看这个示例仓库来了解该功能的实际效果：[mcpotato/42-eicar-street](https://huggingface.co/mcpotato/42-eicar-street)。

`mcpotato/42-eicar-street` 中 `danger.dat` 的扫描结果

请注意，你的模型今天可能还没有扫描结果，因为我们有数百万个模型仓库，我们可能需要一些时间才能全部跑完 😅。

总的来说，我们已经扫描了数以亿计的文件，因为我们坚信：让社区能够以安全且无摩擦的方式共享模型，将推动整个领域共同成长。
