- **NVIDIA Nemotron 3 Nano Omni** 是一款全新的全模态（omni-modal）理解模型，为**真实文档分析、多图推理、自动语音识别、长音视频理解、agentic 计算机操作和通用推理**而生。
- 它把 Nemotron 多模态产品线从强大的视觉-语言系统扩展到更广的**文本 + 图像 + 视频 + 音频**模型。
- Nemotron 3 Nano Omni 在复杂文档智能榜单上提供**同类最佳准确率**，如 [MMlongbench-Doc](https://huggingface.co/spaces/OpenIXCLab/mmlongbench-doc)、[OCRBenchV2](https://99franklin.github.io/ocrbench_v2/)，同时在 [WorldSense](https://jaaackhongggg.github.io/WorldSense/#leaderboard)、[DailyOmni](https://lliar-liar.github.io/Daily-Omni/#leaderboard) 等视频与音频榜单上领先。它在 [VoiceBench](https://matthewcym.github.io/VoiceBench/) 音频理解上拿下最高准确率，并在 [MediaPerf](https://mediaperf.org/leaderboard) 上位列性价比最高的开放视频理解模型。
- 底层上，它把 **Nemotron 3 混合 Mamba-Transformer Mixture-of-Experts 骨干**与 **C-RADIOv4-H** 视觉编码器、**Parakeet-TDT-0.6B-v2** 音频编码器结合在一起。
- 架构设计兼顾：保留精细视觉细节、加入原生音频理解、并能扩展到**超长多模态上下文**，以应对密集图像、文档、视频和混合模态推理。
- 训练配方采用**分阶段多模态对齐与上下文扩展**，随后是**偏好优化与多模态强化学习**。
- 相比同类方案，Nemotron 3 Nano Omni 在多模态用例上吞吐量最高提升 9 倍，单流推理速度快 2.9 倍。

## Nemotron 3 Nano Omni 的设计目标

总体上，Nemotron 3 Nano Omni 面向五类工作负载：

### 1. 真实文档分析

这不只是 OCR。模型的定位是长、乱、高价值的文档——其理解依赖版面、表格、图形、公式、章节结构和跨页引用。想想合同、技术论文、报告、手册、多页表格、合规材料包。模型可以处理 100 页以上的文档。

### 2. 自动语音识别（ASR）

Nemotron 3 Nano Omni 包含强大的语音理解能力，能在各种音频条件下完成高质量转录。它能处理带有不同说话人、口音和背景噪声的长音频。这些能力可以融入更广泛的工作流：把口述内容转录、分析，并与其他模态结合，用于摘要、问答、跨模态推理等任务。

### 3. 长音视频理解

许多企业和开发者工作流依赖音频与视觉的混合证据：带解说的录屏、培训视频、有幻灯片的会议、教程、产品演示、客服录像、长视频档案。Nemotron 3 Nano Omni 就是为联合推理这些输入而构建的。

### 4. Agentic 计算机操作

Nemotron 3 Nano Omni 专门针对 agentic 计算机操作做了训练，能够在图形用户界面（GUI）环境中协助完成任务。其能力包括解读截图、监控界面状态、把推理锚定在屏幕视觉上，并协助动作选择或工作流自动化。

### 5. 通用多模态推理

模型设计不止于感知。它擅长需要跨长上下文窗口、多模态、结构化/半结构化证据综合信息的重推理任务。它能进行多步推理、执行计算、联结来自文本、图像、表格及其他输入的信号，给出连贯且有据的答案。

## 模型架构与关键创新

Nemotron 3 Nano Omni 采用统一的**编码器-投影器-解码器**（encoder-projector-decoder）设计。语言骨干是 Nemotron 3 Nano 30B-A3B，搭配 C-RADIOv4-H 视觉编码器和 Parakeet-TDT-0.6B-v2 音频编码器。各模态专属编码器通过轻量投影器（projector）接入 LLM 骨干。

[![Nemotron_arch_v3_reduced](https://cdn-uploads.huggingface.co/production/uploads/67ac5d85a19e34140ea1013b/r408GJ1edj5Q7ao-lIOZp.png)](https://cdn-uploads.huggingface.co/production/uploads/67ac5d85a19e34140ea1013b/r408GJ1edj5Q7ao-lIOZp.png) 图 2. NVIDIA Nemotron 3 Nano Omni 30B-A3B 的模型架构

### 面向长多模态上下文的混合 Mamba-Transformer-MoE 骨干

模型骨干交织了三种关键组件：**23 层 Mamba 选择性状态空间层**用于高效长上下文处理；**23 层 MoE 层**，配 **128 个专家、top-6 路由**和一个用于条件容量的**共享专家**；以及 **6 层分组查询注意力（grouped-query attention）层**，以保持强全局交互与表达力。

Nemotron 3 Nano Omni 把状态空间模型、注意力和 MoE 统一在一个设计里，既保持强推理性能，又对长多模态上下文保持实用。

### 面向密集文档、图表和屏幕的动态分辨率

视觉方面，Nemotron 3 Nano Omni 用**按原始纵横比的动态分辨率处理**取代了 v2 模型的分块（tiling）策略。每张图像可以用可变数量的 16 x 16 patch 表示，**每张图最少 1,024、最多 13,312 个视觉 patch**。对正方形图像而言，分别等效于 512 x 512 和 1840 x 1840。

这种灵活性对处理高分辨率、复杂的视觉输入至关重要——OCR 密集文档、财务表格、幻灯片、研究图、截图、GUI 布局——尤其是当细节和整体结构需要同时被理解时。

### 面向视频的 Conv3D 时间压缩

视频方面，Nemotron 3 Nano Omni 使用专门的 **Conv3D tubelet 嵌入**路径。不再为每一帧独立做嵌入，而是把每相邻两帧在进入 ViT 之前融合成一个 "tubelet"，让语言模型需要关注的视觉 token 数减半。这样要么在同样的 token 预算下让帧数翻倍，要么在同样的帧数下把 token 数减半。

### EVS——高效视频采样（Efficient Video Sampling）

EVS 是一个重要特性，在推理时启用，会在视觉编码器之后丢弃冗余的视频 token。它在保持准确率的同时降低延迟、提升吞吐。视频的第一帧完整保留，之后对每一帧，EVS 保留画面变化处的"动态" token，丢弃与上一帧相比毫无变化的"静态" token。我们把它与 Conv3D 结合以实现更优的压缩：Conv3D 把相邻两帧的 token 融合为一，EVS 再剪掉冗余的静态信息。

### 原生音频输入，而不只是文本转录

音频侧由 **Parakeet-TDT-0.6B-v2** 驱动，通过它自己的 2 层 MLP 投影器接入骨干。音频采样率为 **16 kHz**，模型训练时输入最长 **1,200 秒（20 分钟）**，而 LLM 的最大上下文长度可支撑 5 小时以上。

这代表了从传统 VLM 管道的一次转变：在共享的多模态序列内实现原生音频处理，让音频、视觉和文本 token 被联合建模。这对以下场景至关重要：带解说的录屏、语音改变视觉含义的视频问答、长篇教学或会议内容，以及需要时间锚定多模态推理的任务。

### 轻量模态投影器与统一 token 交错

每个编码器都通过一个轻量 **2 层 MLP 投影器**接到 LLM，把编码器特征映射进共享嵌入空间。投影之后，**视觉、音频和文本 token 交错排列、联合处理**。

这种设计让整体系统保持模块化，同时骨干内部仍可实现真正的跨模态推理。

## 训练数据、基础设施与系统工程

各 SFT 阶段在 **NVIDIA H100** 上训练，根据阶段不同从 **32 节点扩展到 128 节点**。技术栈使用 **Megatron-LM**、**Transformer Engine** 和 **Megatron Energon**，配张量并行、专家并行、序列并行、长上下文阶段的上下文并行、在线序列打包（online sequence packing）和选择性激活重计算。

SFT 之后的强化学习使用 [**NeMo-RL**](https://github.com/NVIDIA-NeMo/RL/blob/nano-v3-omni/docs/guides/nemotron-3-nano-omni.md) **和 [NeMo Gym](https://github.com/NVIDIA-NeMo/Gym)**，后端为 Megatron。RL 基础设施采用**基于 Ray 的分布式部署**，横跨 **B200 与 H100 集群**，并配有模态去重，避免重复 rollout 使图像、视频、音频内存成倍增长。

我们开源了训练代码的相当大部分。

### 用 RL 塑造可靠的多模态行为

我们在 Nemotron 3 Nano Omni 中引入了多环境文本与全模态训练。文本 RL 训练阶段在 Nemo-Gym 的多样环境中进行，评估模型执行一系列动作的能力——如工具调用、写代码、满足可验证标准的多步规划。

Omni RL 训练模型在统一框架内**跨图像、视频、音频和文本**推理，覆盖从**单模态到完全多模态**的任务。一套多样的验证器（verifier）会评估多种格式的输出——选择题、数学、GUI grounding、ASR——同时有意纳入"无法回答"的案例，教会模型在证据不足时选择弃答而不是幻觉。

### 数据与数据管道

Nemotron 3 Nano Omni 在增强数据集上训练，强调跨模态的高质量推理。我们大幅扩展了任务覆盖面，并为公开数据集不足的复杂推理场景引入合成数据。为支撑这一点，我们构建了面向具体任务的多阶段管道，用于可扩展的合成数据生成。

举一个例子：我们用 [NeMo Data Designer](https://github.com/NVIDIA-NeMo/DataDesigner) 从大规模真实 PDF 语料生成了约 1140 万条合成 QA 对（约 450 亿 token）。该数据集用于在 post-training 阶段强化长上下文文档推理，使 MMLongBench-Doc 总体准确率提升 2.19 倍。

我们在 [Data Designer 开发者笔记](https://nvidia-nemo.github.io/DataDesigner/latest/devnotes/training-a-vlm-to-understand-long-documents-an-iterative-sdg-story/)中详述了完整的管道演进，包括失败分析和关键经验。笔记还包含[九个可运行的管道配方](https://github.com/NVIDIA-NeMo/DataDesigner/tree/main/docs/assets/recipes/vlm_long_doc)，可作为构建你自己的文档理解数据集的起点。
