# nanoVLM：用纯 PyTorch 训练你的 VLM 的最简仓库

[**nanoVLM**](https://github.com/huggingface/nanoVLM) 是用纯 PyTorch **训练**你自己的视觉语言模型（VLM）的*最简单*入门方式。它是一个轻量*工具箱*，让你在[免费层 Colab notebook](https://colab.research.google.com/github/huggingface/nanoVLM/blob/main/nanoVLM.ipynb) 上就能启动 VLM 训练。

> 我们的灵感来自 Andrej Karpathy 的 nanoGPT，为视觉领域提供了一个类似的项目。

nanoVLM 的内核是一个**工具箱**，帮你构建并训练一个既能理解图像和文本、又能据此生成文本的模型。nanoVLM 之美在于它的*简洁*。整个代码库刻意保持*极简*和*可读*，非常适合初学者，或任何想窥探 VLM 内部构造却又不想被淹没的人。

在这篇博客中，我们介绍项目背后的核心思想，并给出与仓库交互的最简路径。我们不仅细说项目细节，还把一切封装好，让你快速上手。

## 什么是视觉语言模型？

顾名思义，视觉语言模型（VLM）是一个处理两种模态——视觉与文本——的多模态模型。这类模型通常以图像和/或文本作为输入，以文本作为输出。

基于对图像和文本（输入）的理解来生成文本（输出），是一种强大的范式。它支撑了大量应用：从图像描述、目标检测，到回答关于视觉内容的问题（见下表）。需要说明的是，nanoVLM 只把视觉问答（Visual Question Answering）作为训练目标。

| ![an image of a cat](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/nanovlm/cat.jpg) | Caption the image | Two cats lying down on a bed with remotes near them | Captioning |
| --- | --- | --- | --- |
| Detect the objects in the image | `<locxx><locxx><locxx><locxx>` | Object Detection |  |
| Segment the objects in the image | `<segxx><segxx><segxx>` | Semantic Segmentation |  |
| How many cats are in the image? | 2 | Visual Question Answering |  |

nanoVLM 以两个广为人知、广泛使用的架构为蓝本。我们的视觉主干（`models/vision_transformer.py`）是标准 Vision Transformer，更具体地说是 Google 的 [SigLIP](https://huggingface.co/docs/transformers/en/model_doc/siglip) 视觉编码器。我们的语言主干遵循 [Llama 3](https://huggingface.co/docs/transformers/en/model_doc/llama3) 架构。

视觉和文本两种模态通过一个模态投影（Modality Projection）模块*对齐*。该模块以视觉主干产出的图像嵌入为输入，将其变换为与语言模型 embedding 层产出的文本嵌入兼容的表示，然后拼接在一起送入语言解码器。模态投影模块由一个 pixel shuffle 操作加一个线性层构成。

| [![diagram of the model architecture](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/nanovlm/architecture.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/nanovlm/architecture.png) |
| --- |
| 模型架构图（来源：作者） |

[Pixel shuffle](https://huggingface.co/papers/1609.05158) 减少图像 token 的数量，从而降低计算开销、加快训练——对输入长度敏感的基于 transformer 的语言解码器尤其受益。下图演示了这一概念。

所有文件都非常轻量且文档完善。强烈建议你逐个查看，以更好理解实现细节（`models/xxx.py`）。

训练时我们使用以下预训练主干权重：

- 视觉主干：[`google/siglip-base-patch16-224`](https://huggingface.co/google/siglip-base-patch16-224)
- 语言主干：[`HuggingFaceTB/SmolLM2-135M`](https://huggingface.co/HuggingFaceTB/SmolLM2-135M)

> 你也可以把主干换成 SigLIP/SigLIP 2（视觉）和 SmolLM2（语言）的其他变体。

## 训练你自己的 VLM

既然熟悉了架构，我们换个挡位，来聊聊如何用 `train.py` 训练你自己的视觉语言模型。

```
.
├── data
│   └── ...
├── models
│   └── ...
└── train.py     # 👈 You are here
```

启动训练：

```
python train.py
```

这个脚本是整个训练流水线的一站式入口，包括：

- 数据集加载与预处理
- 模型初始化
- 优化与日志

**配置**

脚本首先从 `models/config.py` 加载两个配置类：

- `TrainConfig`：训练相关参数，如学习率、检查点路径等。
- `VLMConfig`：初始化 VLM 所用的配置参数，如隐藏维度、注意力头数等。

**数据加载**

数据流水线的核心是 `get_dataloaders` 函数。它会：

- 通过 Hugging Face 的 `load_dataset` API 加载数据集。
- 合并并打乱多个数据集（如果有）。
- 用索引方式做训练/验证划分。
- 用自定义数据集（`VQADataset`、`MMStarDataset`）和 collator（`VQACollator`、`MMStarCollator`）包装。

> 有个有用的开关是 data_cutoff_idx，方便在小规模子集上调试。

**模型初始化**

模型通过 `VisionLanguageModel` 类构建。如果要从检查点恢复，一行搞定：

```
from models.vision_language_model import VisionLanguageModel

model = VisionLanguageModel.from_pretrained(model_path)
```

否则得到的是全新初始化的模型，视觉和语言主干都可以选择性地预加载权重。

**优化器设置：两个学习率**

由于模态投影（MP）是全新初始化的，而主干是预训练的，优化器被拆成两个参数组，各自用不同的学习率：

- MP 用较高的学习率
- 编码器/解码器堆栈用较小的学习率

这样既让 MP 快速学习，又保住了视觉与语言主干里的知识。

**训练循环**

这部分相当标准但结构讲究：

- 使用 `torch.autocast` 混合精度以提升性能。
- 通过 `get_lr` 实现带线性预热的余弦学习率调度。
- 每个 batch 记录 token 吞吐（tokens/sec）用于性能监控。

每 250 步（可配置），模型会在验证集和 `MMStar` 测试数据集上评估。若准确率提升，就保存检查点。

**日志与监控**

如果启用 `log_wandb`，`batch_loss`、`val_loss`、`accuracy`、`tokens_per_second` 等训练统计会记录到 Weights & Biases 做实时追踪。

运行名称由 `get_run_name` 辅助函数用样本量、批量大小、epoch 数、学习率和日期等元数据自动生成。

**推送到 Hub**

训练完成后，用下面的方式保存模型，供他人发现与测试：

```
model.save_pretrained(save_path)
```

再轻松推送到 Hub：

```
model.push_to_hub("hub/id")
```

## 在预训练模型上运行推理

我们用 nanoVLM 工具箱训练了一个[模型并发布到 Hub](https://huggingface.co/lusxvr/nanoVLM-222M)。主干为 `google/siglip-base-patch16-224` 和 `HuggingFaceTB/SmolLM2-135M`。模型在单块 H100 GPU 上训练了约 6 小时，数据来自 [cauldron](https://huggingface.co/datasets/HuggingFaceM4/the_cauldron) 约 170 万个样本。

这个模型不是用来和 SOTA 竞争的，而是为了揭开 VLM 组件与训练过程的神秘面纱。

```
.
├── data
│   └── ...
├── generate.py     # 👈 You are here
├── models
│   └── ...
└── ...
```

用 `generate.py` 脚本对训练好的模型做推理。运行：

```
python generate.py
```

这会用默认参数，在图像 `assets/image.png` 上跑查询 "What is this?"。你也可以用自己的图片和提示词运行这个脚本：

```
python generate.py --image path/to/image.png --prompt "You prompt here"
```

如果想看脚本的心脏，其实就这几行：

```
model = VisionLanguageModel.from_pretrained(source).to(device)
model.eval()

tokenizer = get_tokenizer(model.cfg.lm_tokenizer)
image_processor = get_image_processor(model.cfg.vit_img_size)

template = f"Question: {args.prompt} Answer:"
encoded = tokenizer.batch_encode_plus([template], return_tensors="pt")
tokens = encoded["input_ids"].to(device)

img = Image.open(args.image).convert("RGB")
img_t = image_processor(img).unsqueeze(0).to(device)

print("\nInput:\n ", args.prompt, "\n\nOutputs:")
for i in range(args.generations):
    gen = model.generate(tokens, img_t, max_new_tokens=args.max_new_tokens)
    out = tokenizer.batch_decode(gen, skip_special_tokens=True)[0]
    print(f"  >> Generation {i+1}: {out}")
```

我们创建模型并设为 `eval`，初始化分词器（用于文本提示词）和图像处理器（用于图像处理），接着处理输入并调用 `model.generate` 生成输出文本，最后用 `batch_decode` 解码。
