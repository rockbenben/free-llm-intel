# 起飞！如何开始你的第一个 ML 项目 🚀

刚进入机器学习世界的人，常常会在两个反复出现的坎上绊倒。第一是选对要学的库——可选项多到让人头大。第二是即便选定了一个库、也跟完了教程，接下来还得张罗自己的第一个大项目，并把范围定好，让学习收益最大化。如果你正被这些问题困扰，并且在找一个能加入工具箱的新 ML 库，来对地方了！

这篇文章里，我会以 [Sentence Transformers](https://www.sbert.net)（ST）为例，带你走过用一个新库从 0 到 100 的一些心得。我们先弄清 ST 能做什么的基本盘，点出它值得学的理由；然后分享我屡试不爽的第一个自主项目攻略；还会聊聊我是怎么做出第一个 ST 项目的、一路上学到了什么 🥳

## 什么是 Sentence Transformers？

句子嵌入？语义搜索？余弦相似度？！几周前的我，被这些词搅得头昏脑涨。我听说 [Sentence Transformers](https://www.sbert.net) 是一个处理语言和图像数据的强大而多面的库，很想上手玩玩，又怕自己水平不够。结果证明，我完全想错了！

Sentence Transformers 是 [Hugging Face 集成的库之一](https://huggingface.co/docs/hub/models-libraries)，Hub 上的描述是：

> 为句子、段落和图像计算稠密向量表示

一句话概括：Sentence Transformers 回答的是这样一个问题——如果能把句子当作多维向量空间中的点会怎样？也就是说，你可以丢给它任意一串文本（比如 "I'm so glad I learned to code with Python!"），它会把它变换成一个向量，如 `[0.2, 0.5, 1.3, 0.9]`。另一句 "Python is a great programming language." 会变成另一个向量。这些向量叫"嵌入"（embedding），[在机器学习中扮演着关键角色](https://medium.com/@b.terryjack/nlp-everything-about-word-embeddings-9ea21f51ccfe)。如果这两个句子用同一个模型做嵌入，它们就共存于同一个向量空间——许多有趣的玩法由此而来。

ST 特别实用的地方在于：生成嵌入之后，你可以用内置工具函数比较两个句子的相似程度，***连同义词也算数！*** 🤯 方法之一是[余弦相似度（Cosine Similarity）](https://www.machinelearningplus.com/nlp/cosine-similarity/)。在 ST 里，烦人的数学可以全跳过，直接调用极其好用的 `util.cos_sim`，得到一个 -1 到 1 之间的分数，表示两个句子在共享向量空间里有多"相似"——分越高，句子越像！

句子嵌入之后，我们可以用余弦相似度来比较它们。

按相似度比较句子意味着：如果我们有一堆句子或段落，可以用一种叫*[语义搜索](https://www.sbert.net/examples/applications/semantic-search/README.html)*的过程，快速找出匹配某个搜索查询的那些。具体应用可参考[做一个 GitHub 代码搜索器的教程](https://huggingface.co/spaces/sentence-transformers/Sentence_Transformers_for_semantic_search)，或另一篇[用 Sentence Transformers 构建 FAQ 引擎](https://huggingface.co/blog/getting-started-with-embeddings)的教程。

## 为什么要学 Sentence Transformers？

第一，它给了你一个低门槛的途径，亲手用最先进的模型生成[嵌入](https://daleonai.com/embeddings-explained)。我发现，自己动手做句子嵌入是极好的学习工具——它加深了我对现代模型如何处理文本的理解，也激发了创意。在 Jupyter notebook 里加载 [msmarco-MiniLM-L-6-v3 模型](https://huggingface.co/sentence-transformers/msmarco-MiniLM-L-6-v3)几分钟后，仅仅嵌入一些句子、跑几个 ST 的工具函数，我就冒出了一堆有趣的项目点子！

第二，Sentence Transformers 是通往许多重要 ML 概念的入口，你可以沿着分支深入。比如借它学习[聚类](https://www.sbert.net/examples/applications/clustering/README.html)、[模型蒸馏](https://www.sbert.net/examples/training/distillation/README.html)，甚至用 [CLIP](https://www.sbert.net/examples/applications/image-search/README.html) 进军文生图领域。事实上，ST 的多面性让它一路冲到 GitHub 近 8000 star，[超过 3000 个项目和包依赖它](https://github.com/UKPLab/sentence-transformers/network/dependents?dependent_type=REPOSITORY&package_id=UGFja2FnZS00ODgyNDAwNzQ%3D)。除了官方文档，还有海量的社区创作内容（文末有一些链接 👀）；库的普及也让它[在科研中很受欢迎](https://twitter.com/NimaBoscarino/status/1535331680805801984?s=20&t=gd0BycVE-H4_10G9w30DcQ)。

第三，嵌入是不少工业应用的关键。谷歌搜索用嵌入来[匹配文本与文本、文本与图像](https://cloud.google.com/blog/topics/developers-practitioners/meet-ais-multitool-vector-embeddings)；Snapchat 用它"[把对的广告投给对的用户、在对的时机](https://eng.snap.com/machine-learning-snap-ad-ranking)"；Meta（Facebook）用它做[社交搜索](https://research.facebook.com/publications/embedding-based-retrieval-in-facebook-search/)。换句话说，嵌入能让你搭建聊天机器人、推荐系统、zero-shot 分类器、图像搜索、FAQ 系统等。

最重要的是，它还得到一大堆 [Hugging Face 集成](https://huggingface.co/docs/hub/sentence-transformers)的支持 🤗。

## 攻克你的第一个项目

所以你决定试试 Sentence Transformers、也刷完了文档里的例子……然后呢？你的第一个自主项目（我称之为"火箭发射"项目 🚀）是学习之旅的一大步，要把它价值榨干！这是我尝试新工具时爱用的一套配方：

- **把工具能干的事全部倒出来**：对 Sentence Transformers 而言，包括生成句子嵌入、比较句子、[为复杂搜索任务做检索加重排](https://www.sbert.net/examples/applications/retrieve_rerank/README.html)、聚类，以及用[语义搜索](https://www.sbert.net/examples/applications/semantic-search/README.html)找相似文档。
- **琢磨一些有意思的数据源**：[Hugging Face Hub](https://huggingface.co/datasets) 上有海量数据集，也可以翻 [awesome-public-datasets](https://github.com/awesomedata/awesome-public-datasets) 这类清单找灵感。有趣的数据常在意想不到的地方——比如你所在市政府可能有[开放数据门户](https://opendata.vancouver.ca/pages/home/)。你会花相当多的时间和数据相处，不如挑让你兴奋的数据集！
- **挑一个你还算顺手的*次要*工具**：何必一次只学一个工具？["分布式练习"](https://senecalearning.com/en-GB/blog/top-10-most-effective-learning-strategies/)（即"间隔重复"）把学习分散到多个场次，是被证明有效的学习策略。主动实践的一种方式是：在不是主打学习目标的场合也练新技能。如果你最近刚上手一个工具，这正是通过实战检验来成倍放大学习收益的好机会。我建议火箭发射项目里最多带一个次要工具。
- **头脑风暴**：花点时间设想前 3 步里各元素的不同组合能玩出什么！没有烂点子，我一般先追求数量而不是纠结质量。很快你就会发现几个让你眼里冒光的想法 ✨

我的第一个 ST 项目，是想起手头正好有一份流行歌曲歌词的小数据集——可以和 ST 的语义搜索结合，做一个好玩的歌单生成器。我设想：如果让用户输入一句文本提示（比如 "I'm feeling wild and free!"），也许就能找到歌词与之匹配的歌！我当时也在用 [Gradio](https://gradio.app/) 做 demo，最近正练习新发布的 [Gradio Blocks](https://gradio.app/introduction_to_blocks/?utm_campaign=Gradio&utm_medium=web&utm_source=Gradio_4)，于是次要工具就定了：做一个漂亮的基于 Blocks 的 Gradio 应用来展示项目。一石二鸟的机会永远不要错过 🦆🐓

[这是我最后做出来的东西！](https://huggingface.co/spaces/NimaBoscarino/playlist-generator)后续会有一篇博客拆解它是怎么构建的，敬请期待 👀

## 第一个项目能让你学到什么？

每个项目都不一样，你的学习之旅自然也是独一份。[建构主义](https://www.wgu.edu/blog/what-constructivism2005.html)学习理论认为，知识是高度个人化的，靠主动与已有知识建立连接而构建。比如在我的歌单生成器项目里，我不得不去了解 Sentence Transformers 支持的各种预训练模型，才能找到匹配用例的那一个。因为我在 [Hugging Face Spaces](https://huggingface.co/spaces) 上写 Gradio，我学会了把嵌入托管在 Hugging Face Hub 并加载进应用。最后，由于歌词量大，我寻找加速嵌入的方法，还学到了 [Sentence Transformers 的多进程支持](https://www.sbert.net/examples/applications/computing-embeddings/README.html#multi-process-multi-gpu-encoding)。

做完第一个项目，你会发现点子反而更多了。玩得开心，记得把你的项目和所学分享到 [hf.co/join/discord](http://hf.co/join/discord) 🤗
