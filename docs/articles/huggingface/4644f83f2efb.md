# Hugging Face 的开源文本生成与 LLM 生态

merve (merve)

[2023 年 7 月 24 日更新：加入 Llama 2。]

文本生成与对话技术早已存在。早期的难点在于通过推理参数和判别性偏置同时控制文本的连贯性与多样性：连贯的输出往往缺乏创意、更接近原始训练数据、听起来更不像人话。近期的进展克服了这些挑战，友好的 UI 让人人都能上手这些模型。ChatGPT 这类服务最近把聚光灯打在了 GPT-4 这样的强模型上，也推动了 Llama 这样的开源替代走向主流。我们相信这些技术会长期存在，并越来越深入地融入日常产品。

## 文本生成简史

文本生成模型的训练目标本质上就是补全不完整的文本，或根据给定的指令/问题从零生成文本。补全未写完文本的模型叫因果语言模型（Causal Language Model），著名例子有 OpenAI 的 GPT-3 和 Meta AI 的 [Llama](https://ai.meta.com/blog/large-language-model-Llama-meta-ai/)。

[![Causal LM Output](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/text_generation.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/text_generation.png)

在继续之前你需要了解一个概念：微调（fine-tuning）。这是把一个非常大的模型里蕴含的知识迁移到另一个用例的过程，那个用例我们称为*下游任务*。任务可以是指令形式。随着模型规模增大，它对预训练数据中不存在、但在微调中学到的指令泛化得更好。

因果语言模型通过一种叫"基于人类反馈的强化学习"（RLHF）的过程做适配。这种优化主要关注文本听起来是否自然、连贯，而不是答案是否有效。RLHF 如何工作不在本文范围内，更多信息见[这里](https://huggingface.co/blog/rlhf)。

例如，GPT-3 是因果语言*基座*模型，而 ChatGPT（GPT 系列模型的 UI）背后的模型是通过 RLHF 在由对话或指令组成的 prompt 上微调而来的。这两类模型的区别很重要。

在 Hugging Face Hub 上，你既能找到因果语言模型，也能找到指令微调过的因果语言模型（后文会给出链接）。Llama 是最早追平/超过闭源模型的开源 LLM 之一。Together 领导的研究团队复刻了 Llama 的数据集——Red Pajama——并在其上训练了 LLM 和指令微调模型。详情见[这里](https://www.together.xyz/blog/redpajama)，[模型检查点在 Hugging Face Hub 上](https://huggingface.co/models?sort=trending&search=togethercomputer%2Fredpajama)。写作本文时，采用开源许可证的最大因果语言模型包括 [MosaicML 的 MPT-30B](https://huggingface.co/mosaicml/mpt-30b)、[Salesforce 的 XGen](https://huggingface.co/Salesforce/xgen-7b-8k-base) 和 [TII UAE 的 Falcon](https://huggingface.co/tiiuae/falcon-40b)，全部在 Hugging Face Hub 开放。最近 Meta 发布了 [Llama 2](https://ai.meta.com/Llama/)，一个允许商用的开放访问模型。目前 Llama 2 在多个基准上超过所有其他开源大语言模型。[Hub 上的 Llama 2 检查点](https://huggingface.co/meta-Llama)与 transformers 兼容，最大的检查点人人可在 [HuggingChat](https://huggingface.co/chat/) 试用。关于如何微调、部署 Llama 2 及写提示词，见[这篇博客](https://huggingface.co/blog/llama2)。

第二种文本生成模型通常叫文本到文本生成模型（text-to-text）。这类模型在文本晚上训练，可以是问答对或指令-回复对。最流行的是 T5 和 BART（目前已不是 SOTA）。Google 近期发布了 FLAN-T5 系列。FLAN 是近年为指令微调开发的技术，FLAN-T5 本质上就是用 FLAN 微调过的 T5。目前 FLAN-T5 系列是 SOTA 且开源，发布在 [Hugging Face Hub](https://huggingface.co/models?search=google/flan)。注意它们与指令微调的因果语言模型不同，尽管输入输出格式看起来很像。下面插图展示了这些模型的工作方式。

[![FLAN-T5 Illustration](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/flan_t5.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/flan_t5.png)

拥有更多样的开源文本生成模型，能让企业把数据留在自己手里、更快地把模型适配到自己的领域、并在推理上省钱，而不必依赖闭源付费 API。Hub 上全部开源因果语言模型见[这里](https://huggingface.co/models?pipeline_tag=text-generation)，文本到文本生成模型见[这里](https://huggingface.co/models?pipeline_tag=text2text-generation&sort=trending)。

### Hugging Face 与 BigScience 和 BigCode 用爱打造的模型 💗

Hugging Face 共同领导了两个科学计划：BigScience 和 BigCode。产出了两个大语言模型：[BLOOM](https://huggingface.co/bigscience/bloom) 🌸 和 [StarCoder](https://huggingface.co/bigcode/starcoder) 🌟。BLOOM 是在 46 种语言和 13 种编程语言上训练的因果语言模型，是第一个参数量超过 GPT-3 的开源模型。全部可用检查点见 [BLOOM 文档](https://huggingface.co/docs/transformers/model_doc/bloom)。

StarCoder 是以 Fill-in-the-Middle 目标在 GitHub 上宽松许可代码（80+ 种编程语言 🤯）上训练的语言模型。它没有做指令微调，所以更多是充当编码助手：补全代码（如把 Python 翻译成 C++）、解释概念（什么是递归）、或扮演终端。所有 StarCoder 检查点可在[这个应用](https://huggingface.co/spaces/bigcode/bigcode-playground)里试用，还配有 [VSCode 扩展](https://marketplace.visualstudio.com/items?itemName=HuggingFace.huggingface-vscode)。

本文提到的所有模型的使用代码片段，都在对应模型仓库或 Hugging Face 上该模型类型的文档页里给出。

## 许可证

许多文本生成模型要么闭源，要么许可证限制商用。所幸开源替代品开始涌现，并被社区接受为进一步开发、微调或其他项目集成的积木。下面是完全开源许可证的大规模因果语言模型清单：

- [Falcon 40B](https://huggingface.co/tiiuae/falcon-40b)
- [XGen](https://huggingface.co/tiiuae/falcon-40b)
- [MPT-30B](https://huggingface.co/mosaicml/mpt-30b)
- [Pythia-12B](https://huggingface.co/EleutherAI/pythia-12b)
- [RedPajama-INCITE-7B](https://huggingface.co/togethercomputer/RedPajama-INCITE-7B-Base)
- [OpenAssistant（Falcon 变体）](https://huggingface.co/OpenAssistant/falcon-40b-sft-mix-1226)

代码生成模型有两个：[BigCode 的 StarCoder](https://huggingface.co/models?sort=trending&search=bigcode%2Fstarcoder) 和 [Salesforce 的 Codegen](https://huggingface.co/models?sort=trending&search=salesforce%2Fcodegen)。两者都有不同规模的检查点以及开源或 [open RAIL](https://huggingface.co/blog/open_rail) 许可证，只有 [Codegen 的指令微调版](https://huggingface.co/Salesforce/codegen25-7b-instruct)除外。

Hugging Face Hub 还托管了各种为指令或聊天用途微调的模型，风格和规模随需选择。

- Mosaic ML 的 [MPT-30B-Chat](https://huggingface.co/mosaicml/mpt-30b-chat) 使用 CC-BY-NC-SA 许可证，不允许商用。但 [MPT-30B-Instruct](https://huggingface.co/mosaicml/mpt-30b-instruct) 使用 CC-BY-SA 3.0，可以商用。
- [Falcon-40B-Instruct](https://huggingface.co/tiiuae/falcon-40b-instruct) 和 [Falcon-7B-Instruct](https://huggingface.co/tiiuae/falcon-7b-instruct) 都使用 Apache 2.0 许可证，允许商用。
- 另一个热门家族是 OpenAssistant，其中一些基于 Meta 的 Llama 模型加自定义指令微调数据集构建。由于原版 Llama 仅限研究用途，构建在其上的 OpenAssistant 检查点不算完全开源。但存在构建在开源模型上的 OpenAssistant 模型，如 [Falcon](https://huggingface.co/models?search=openassistant/falcon) 或 [pythia](https://huggingface.co/models?search=openassistant/pythia) 版本，用的是宽松许可证。
- [StarChat Beta](https://huggingface.co/HuggingFaceH4/starchat-beta) 是 StarCoder 的指令微调版，采用允许商用的 BigCode Open RAIL-M v1 许可证。Salesforce 的指令微调编码模型 [XGen](https://huggingface.co/Salesforce/xgen-7b-8k-inst) 则仅限研究用途。

如果你想基于现有指令数据集微调模型，需要了解数据集是怎么汇编的。一些现有指令数据集要么来自众包，要么使用了现有模型的输出（比如 ChatGPT 背后的模型）。Stanford 创建的 [ALPACA](https://crfm.stanford.edu/2023-03-13/alpaca.html) 数据集就来自 ChatGPT 背后模型的输出。此外还有多种采用开源许可证的众包指令数据集，比如 [oasst1](https://huggingface.co/datasets/OpenAssistant/oasst1)（由数千名志愿者创建）或 [databricks/databricks-dolly-15k](https://huggingface.co/datasets/databricks/databricks-dolly-15k)。想自建数据集，可参考 [Dolly 的数据集卡](https://huggingface.co/datasets/databricks/databricks-dolly-15k#sources)了解如何构建指令数据集。在这些数据集上微调的模型是可以分发的。

## Hugging Face 生态中用于 LLM 服务的工具

### Text Generation Inference

响应时间和并发用户的延迟是服务这些大模型的大难题。为应对这个问题，Hugging Face 发布了 [text-generation-inference](https://github.com/huggingface/text-generation-inference)（TGI）——一个基于 Rust、Python 和 gRPc 的大语言模型开源服务方案。TGI 已集成进 Hugging Face 的推理方案 [Inference Endpoints](https://huggingface.co/inference-endpoints) 和 [Inference API](https://huggingface.co/inference-api)：你可以直接创建带优化推理的 endpoint（几次点击），或干脆只向 Hugging Face 的 Inference API 发请求来受益，无需把 TGI 集成到你自己的平台。

[![Screenshot from HuggingChat](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/huggingchat_ui.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/huggingchat_ui.png)

TGI 目前驱动着 [HuggingChat](https://huggingface.co/chat/)——Hugging Face 的 LLM 开源聊天 UI。该服务目前用 OpenAssistant 的一个模型做后端。你可以无限地和 HuggingChat 聊天，还能开启网页搜索功能，让回答引用当前网页的内容。你也可以给每条回复反馈，供模型作者训练更好的模型。HuggingChat 的 UI 同样[开源](https://github.com/huggingface/chat-ui)，我们正在为它开发更多功能，比如在聊天中生成图像。

[![HuggingChat Search](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/huggingchat_web.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/huggingchat_web.png)

最近，HuggingChat 的 Docker 模板在 Hugging Face Spaces 上发布了。这允许任何人几次点击就部署基于大语言模型的自有实例，并可自由定制。你可以在[这里](https://huggingface.co/new-space?template=huggingchat/chat-ui-template)基于各种 LLM（包括 Llama 2）创建自己的大语言模型实例。

[![HuggingChat Space](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/docker_chat.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/docker_chat.png)

### 如何找到最佳模型？

Hugging Face 维护着 [LLM 排行榜](https://huggingface.co/spaces/HuggingFaceH4/open_llm_leaderboard)。榜单由社区提交的模型在 Hugging Face 集群上跑文本生成基准评测而来。如果找不到你要的语言或领域，可以在[这里](https://huggingface.co/models?pipeline_tag=text-generation&sort=downloads)筛选。

[![Open LLM Leaderboard](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/LLM_leaderboard.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/os_llms/LLM_leaderboard.png)

还可以看看 [LLM 性能排行榜](https://huggingface.co/spaces/optimum/llm-perf-leaderboard)，它评测 Hugging Face Hub 上大语言模型的延迟与吞吐。

## 参数高效微调（PEFT）

如果你想基于自己的指令数据集微调现有大模型之一，在消费级硬件上几乎不可能做到，之后也没法部署（指令模型和用于微调的原始检查点一样大）。[PEFT](https://huggingface.co/docs/peft/index) 是一个支持参数高效微调技术的库。也就是说不用训练整个模型，只需训练极少量的附加参数，大幅加快训练，性能损失极小。用 PEFT 可以做低秩适配（LoRA）、prefix tuning、prompt tuning 和 p-tuning。
