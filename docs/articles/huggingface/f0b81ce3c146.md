[![DaisyRose-27B](https://www.radixark.com/images/daisyrose-27b/hero.png)](https://www.radixark.com/images/daisyrose-27b/hero.png)

今天我们发布 **DaisyRose-27B**，这是 RadixArk 的第一个模型，基于 Qwen3.8-27B 构建，并使用 [Miles](https://miles.radixark.com/) 做强化学习训练。我们针对长程 agent 任务训练它，单次会话最长可达 100 万 token；只用了 1,200 个精挑细选的任务，18 天内在 144 张 H200 GPU 上完成训练。DaisyRose-27B 把 Terminal-Bench 4.1 pass@1 从 **5.6% 提升到 12.0%**。除 Terminal-Bench 4.1 之外，它在多项推理、指令遵循和编程 benchmark 上也都有提升。

checkpoint 以 **Apache 2.0** 协议提供：

- [BF16](https://huggingface.co/RadixArk/DaisyRose-27B)
- [FP8](https://huggingface.co/RadixArk/DaisyRose-27B-FP8)
- [NVFP4](https://huggingface.co/RadixArk/DaisyRose-27B-NVFP4)

模型保留了 Qwen3.8-27B 的架构、tokenizer、chat template、图像理解能力以及 **256K token 的上下文窗口**。更长的训练会话通过 harness 摘要来跨越多个 trajectory。模型属性和推理参数见[模型卡](https://huggingface.co/RadixArk/DaisyRose-27B)。

## 运行 DaisyRose-27B

我们建议用 SGLang 配合 DSpark 投机解码来部署 DaisyRose-27B。[SGLang cookbook](https://docs.sglang.io/cookbook/autoregressive/RadixArk/DaisyRose-27B) 里给出了针对不同 GPU 和 checkpoint 格式的启动配置。

用 `DaisyRose-27B` 作为 served model name、在 `30000` 端口启动服务后，即可用 OpenAI Python 客户端发送请求：

```
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:30000/v1",
    api_key="none",
)

response = client.chat.completions.create(
    model="DaisyRose-27B",
    messages=[
        {
            "role": "user",
            "content": "How many positive divisors does 360 have?",
        }
    ],
    temperature=1.0,
    top_p=0.95,
    extra_body={"top_k": 20, "min_p": 0.0},
)

print(response.choices[0].message.reasoning_content)
print(response.choices[0].message.content)
```

模型默认先思考再作答：推理过程通过 `reasoning_content` 返回，最终答案在 `content` 中。以上参数与[模型卡的 quickstart](https://huggingface.co/RadixArk/DaisyRose-27B#3-getting-started) 一致。

## Benchmark 结果

[![DaisyRose-27B 在七个 benchmark 上与八个模型的对比](https://www.radixark.com/images/daisyrose-27b/benchmarks.png)](https://www.radixark.com/images/daisyrose-27b/benchmarks.png)

| Benchmark | Qwen3.8-27B | DaisyRose-27B |
| --- | --- | --- |
| Terminal Bench 4.1 | 5.6 | **12.0** |
| Terminal Bench 2.1 | 73.0 | **75.5** |
| DeepSWE v1.1 | 42.2 | **46.2** |
| SWE Bench Pro v2 | 91.3 | **94.7** |
| HLE（纯文本） | 33.9 | **34.3** |
| IFBench | 79.5 | **82.4** |
| GPQA Diamond | 89.2 | **90.7** |

在上述每一个 benchmark 上，DaisyRose-27B 的得分都高于原始 Qwen3.8-27B。提升最大的是 Terminal Bench 4.1，pass@1 从 5.6% 升到 12.0%。

每个 benchmark 取 BF16 与 FP8 两次运行中较高的成绩；在两者都评测过的项目上，差距不到 1 分。对比数据来源与评测设置见[模型卡](https://huggingface.co/RadixArk/DaisyRose-27B#2-evaluations)。

这次发布能做成，靠训练方案里的三件事：精心设计的任务、高效的训练后端，以及可靠的 sandbox。

## 高质量训练数据

这些任务是我们与 [Eigent AI](https://www.eigent.ai/) 合作构建的，起点是它在机器学习、软件工程、科学等领域积累的大量任务。双方一共做出数千个候选任务，最终约 1,200 个进入训练集。

我们用三条标准筛选任务：

- **每个任务都针对原模型确实会犯的错误。** 我们在每个任务上跑一遍 Qwen3.8-27B，围绕希望模型改掉的错误重新设计任务，再调整难度，直到解决率落在一个有学习价值的区间。
- **每个任务都需要多个相互依赖的步骤。** agent 必须在一项长作业中完成推理、规划和执行。每次尝试在 sandbox 里最长 1.5 小时，涉及 100 次以上工具调用和超过 256K 输出 token。
- **任务必须奖励真正解决问题。** 我们逐个复核任务与模型的尝试记录；凡是没解决目标问题也能通过的任务，或者存在设计缺陷的任务，都已修正或删除。

## 高效的训练后端

RadixArk 用 Miles（我们面向大规模模型后训练的开源强化学习框架）以全异步模式训练 DaisyRose-27B：agent 持续干活，模型同时学习，两边互不等待。128 张 H200 负责 agent 任务的推理，另外 16 张跑 trainer，从 trajectory 中学习。每一步结束后，更新后的模型下发到跑 agent 的 128 张 GPU。学习过程跑在我们内部的训练后端上，这套后端专为 agent 训练打造：每一步都从少数几个超长会话中学习，有的会话长达 100 万 token，经 harness 摘要折叠成多个 trajectory。

**训练成本降低 57%。** 这次发布中，我们的后端让每张 GPU 峰值算力的 37% 用于有效训练工作（model FLOPs utilization，即 MFU）；基于 Megatron 的开源 trainer 在可比运行中只有 16%。因此同样的训练所需 GPU 时间减少 57%。在 mixture-of-experts 模型上收益更大：Qwen3.6-35B-A3B 上为 6.2 倍，约 300B 参数的 GLM-5.3-Flash 上超过 10 倍。

[![GPU 效率：RadixArk 内部后端与开源 trainer 的对比](https://www.radixark.com/images/daisyrose-27b/gpu-efficiency.png)](https://www.radixark.com/images/daisyrose-27b/gpu-efficiency.png)

**端到端快 2 倍。** 把 agent 花在任务上的时间也算进去，这次发布运行在 144 张 GPU 上的训练吞吐约为每秒 16,800 token；开源 trainer 在同样硬件上约为每秒 8,300 token。

[![端到端训练速度：144 张 H200 上每秒 16.8k 与 8.3k token](https://www.radixark.com/images/daisyrose-27b/training-speed.png)](https://www.radixark.com/images/daisyrose-27b/training-speed.png)

**数周保持稳定。** 这次发布运行在 144 张 H200 上训练了数周，共 63,000 GPU 小时。从第一步到最后一步，速度和效率始终平稳。

[![DaisyRose-27B 发布运行期间的训练速度与 GPU 效率](https://www.radixark.com/images/daisyrose-27b/training-stability.png)](https://www.radixark.com/images/daisyrose-27b/training-stability.png)

*DaisyRose-27B 发布运行在 144 张 H200 上的每一个训练 step，横轴为累计训练时间。虚线：可比运行中的开源 trainer。*

## 稳得住的 sandbox 服务

每次训练尝试都在 sandbox 中运行：任务环境的一份全新副本，agent 在其中执行命令、编辑文件，然后接受评分。

这套服务建立在开源项目 [AgentENV](https://github.com/kvcache-ai/AgentENV) 之上，我们也向它提交修复。9 月中旬到 11 月中旬，它为本项目运行了约 **94.4 万个 sandbox**，并发峰值达 **1,566 个**。

这套服务从一台机器扩展到最多 12 台。我们上线了十次升级，几乎都在训练进行中完成。九周里 sandbox 创建成功率 99%；10 月下旬以来，这一数字已超过 99.95%。

[![总计 944K 个 sandbox、1,566 个并发峰值，最终运行成功率 99.95%](https://www.radixark.com/images/daisyrose-27b/sandboxes.png)](https://www.radixark.com/images/daisyrose-27b/sandboxes.png)

本项目 sandbox 的云基础设施成本，比用主流云 sandbox 服务商跑同样的 sandbox 低约 **80%**。降本的一个做法是让每个 sandbox 的内存分配随实际用量伸缩，从而让更多 sandbox 共享同一台机器。
