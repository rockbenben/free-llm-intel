今天我们发布 **DaisyRose-27B**，RadixArk 的第一个模型，基于 Qwen3.8-27B 构建，并使用 [Miles](https://miles.radixark.com/) 进行强化学习训练。我们对它进行了长期代理任务的训练，会话量高达 100 万代币，18 天内在 144 个 H200 GPU 上仅执行了 1,200 个策划任务。 DaisyRose-27B 将 Terminal-Bench 4.1 pass@1 从 **5.6% 提高到 12.0%**。除了 Terminal-Bench 4.1 之外，它还提供了各种其他推理、指令跟踪和编码基准测试的提升。

检查点在 **Apache 2.0** 下可用：

- [BF16](https://huggingface.co/RadixArk/DaisyRose-27B)
- [FP8](https://huggingface.co/RadixArk/DaisyRose-27B-FP8)
- [NVFP4](https://huggingface.co/RadixArk/DaisyRose-27B-NVFP4)

该模型保留了 Qwen3.8-27B 的架构、分词器、聊天模板、图像理解和 **256K 令牌上下文窗口**。较长的训练课程使用​​线束汇总来跨越多个轨迹。有关模型属性和推理设置，请参阅[模型卡](https://huggingface.co/RadixArk/DaisyRose-27B)。

## 运行 DaisyRose-27B

我们建议使用 SGLang 和 DSpark 推测解码来为 DaisyRose-27B 提供服务。 [SGLang 食谱](https://docs.sglang.io/cookbook/autoregressive/RadixArk/DaisyRose-27B) 提供了不同 GPU 和检查点格式的启动配置。

在端口 `30000` 上启动具有服务模型名称 `DaisyRose-27B` 的服务器后，您可以使用 OpenAI Python 客户端发送请求：
```
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:30000/v1",
    api_key="none",
)

response = client.chat.completions.create(
    model="DaisyRose-27B",
    messages=[
        {
            "role": "user",
            "content": "How many positive divisors does 360 have?",
        }
    ],
    temperature=1.0,
    top_p=0.95,
    extra_body={"top_k": 20, "min_p": 0.0},
)

print(response.choices[0].message.reasoning_content)
print(response.choices[0].message.content)
```
默认情况下，模型会在回答之前进行思考。它的推理在 `reasoning_content` 中返回，其最终答案在 `content` 中。这些设置遵循[型号卡的快速入门](https://huggingface.co/RadixArk/DaisyRose-27B#3-getting-started)。

## 基准测试结果

[![DaisyRose-27B 在七个基准测试中与八个模型进行比较](https://www.radixark.com/images/daisyrose-27b/benchmarks.png)](https://www.radixark.com/images/daisyrose-27b/benchmarks.png)

|基准| Qwen3.8-27B |雏菊玫瑰-27B |
| --- | --- | --- |
|终端工作台 4.1 | 5.6 | 5.6 **12.0** |
|终端工作台2.1 | 73.0 | 73.0 **75.5** |
| DeepSWE v1.1 | 42.2 | 42.2 **46.2** |
| SWE Bench Pro v2 | SWE Bench Pro v2 | SWE Bench Pro v2 | SWE Bench Pro v2 91.3 | 91.3 **94.7** |
| HLE（纯文本）| 33.9 | 33.9 **34.3** |
| IFBench | 79.5 | 79.5 **82.4** |
| GPQA 钻石 | 89.2 | 89.2 **90.7** |

DaisyRose-27B 在上述每个基准测试中的得分均高于原始 Qwen3.8-27B 型号。涨幅最大的是 Terminal Bench 4.1，其中 pass@1 从 5.6% 上升至 12.0%。

每个基准测试的分数使用 BF16 和 FP8 运行中的较高者；无论在哪里进行评估，两者的差异都小于一分。 [模型卡](https://huggingface.co/RadixArk/DaisyRose-27B#2-evaluations)包括比较源和评估设置。

训练设置的三个部分使此版本成为可能：精心设计的任务、高效的训练后端和可靠的沙箱。

## 高质量的训练数据

我们与 [Eigent AI](https://www.eigent.ai/) 合作构建了这些任务，从其在机器学习、软件工程、科学和其他领域的大量任务开始。我们共同培养了数千名候选人。大约 1,200 人进入了最终训练集。

我们使用三个标准选择任务：

- **每项任务都针对原始模型所犯的错误。** 我们在每项任务上运行 Qwen3.8-27B，并围绕我们希望模型停止犯的错误重新设计每一项任务。然后我们调整难度，直到解决率落入有用的学习范围内。
- **每项任务都需要几个相互依赖的步骤。** 代理必须在一项长期工作中进行推理、计划和执行。每次尝试都会在沙盒中长达 1.5 小时，其中包含超过 100 次工具调用和超过 256K 的输出令牌。
- **任务必须奖励实际解决问题。**我们审查了每项任务以及模型的尝试。可以在未解决预期问题的情况下通过的任务或包含设计缺陷的任务已被修复或删除。

## 高效的训练后端

RadixArk 使用 Miles（我们用于大规模模型后训练的开源强化学习框架）以完全异步模式训练 DaisyRose-27B：代理在模型学习时继续工作，互不等待。 128 个 H200 对代理任务运行推理，另外 16 个 H200 运行训练器并从轨迹中学习。每一步完成后，更新的模型都会发送到运行代理的 128 个 GPU。学习在我们的内部训练后端上运行，该后端是为代理训练而构建的：每个步骤都从几个非常长的会话中学习，有些会话长达 1M 个令牌，通过线束摘要折叠成多个轨迹。

**训练成本降低了 57%。** 在此版本中，每个 GPU 峰值计算的 37% 投入到了后端的有用训练工作（模型 FLOP 利用率，或 MFU）。这款基于威震天 (Megatron) 构建的开源训练器在可比运行中达到了 16%。因此相同的训练需要的 GPU 时间减少 57%。混合专家模型的增益甚至更大：Qwen3.6-35B-A3B 上的增益为 6.2 倍，大约 300B 参数的 GLM-5.3-Flash 上的增益超过 10 倍。

[![GPU效率：RadixArk的内部后端与开源训练器相比](https://www.radixark.com/images/daisyrose-27b/gpu-efficiency.png)](https://www.radixark.com/images/daisyrose-27b/gpu-efficiency.png)

**端到端速度提高了 2 倍。** 计算代理在其任务上花费的时间，该版本在 144 个 GPU 上每秒训练约 16,800 个令牌。开源训练器在相同的 GPU 上达到了约 8,300。

[![端到端训练速度：144 个 H200 上每秒 16.8k 与 8.3k 令牌](https://www.radixark.com/images/daisyrose-27b/training-speed.png)](https://www.radixark.com/images/daisyrose-27b/training-speed.png)

**稳定数周。** 该版本在 144 个 H200 上运行了数周，总共 63,000 个 GPU 小时。从第一步到最后一步，速度和效率都保持稳定。

[![DaisyRose-27B 版本运行期间的训练速度和 GPU 效率](https://www.radixark.com/images/daisyrose-27b/training-stability.png)](https://www.radixark.com/images/daisyrose-27b/training-stability.png)

*DaisyRose-27B 版本的每个训练步骤都在 144 个 H200 上运行，根据总训练时间绘制。虚线：可比运行的开源训练器。*

## 强大的沙箱服务

每次训练尝试都在沙箱中运行：任务环境的全新副本，代理在其中运行命令、编辑文件，然后进行评分。

我们的服务基于开源 [AgentENV](https://github.com/kvcache-ai/AgentENV) 项目构建，我们还为其提供了修复程序。从 9 月中旬到 11 月中旬，该项目运行了大约 **944,000 个沙箱**，其中并发运行的沙箱数量高达 **1,566 个**。

该服务从一台机器增加到多达 12 台。我们对其进行了十次升级，几乎都是在训练运行期间进行的。在这九周内，99% 的沙盒创作都成功了；自10月下旬以来，这一数字已超过99.95%。

[![沙箱总数944K，峰值并发沙箱1,566个，最终运行成功率99.95%](https://www.radixark.com/images/daisyrose-27b/sandboxes.png)](https://www.radixark.com/images/daisyrose-27b/sandboxes.png)

该项目沙箱的云基础设施成本比与流行的云沙箱提供商运行相同的沙箱低约 **80%**。我们降低成本的一种方法是让每个沙箱的内存分配随着其实际使用情况而增长和收缩，从而允许更多的沙箱共享每台机器。
