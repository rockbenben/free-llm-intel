上周，我想要一个随 Qwen-Image 2.1 一起发布的那个 [prompt rewriter](https://huggingface.co/Qwen/Qwen-Image-2.1-PE-T2I) 的小尺寸版本。官方那个是一个 9B 模型，需要大约 20 GB 内存，而且在写下第一个段落之前要思考几千个 token。在 Hub 上，我只找到同一个 9B 模型的压缩副本。于是我向 [ML Intern](https://huggingface.co/chat/?mode=ml-intern) 描述了我想要的东西，第二天我就有了一个能在 CPU 上跑的 [0.8B 版本](https://huggingface.co/ML-Intern-lab/Qwen-Image-2.1-PE-T2I-Pocket-0.8B)。它 99.7% 的情况下返回有效输出，用的 token 大约只有 teacher 的四分之一。整个项目的算力开销——包括让那个 9B 模型给 8,797 条示例请求打标签——一共是 USD 16。

在接下来的几天里，我用同样的方法又做了五个模型。每一个都是从 HuggingChat 里的一条消息开始——把 ML-intern 打开——最后都成为 Hub 上的公开模型，评估结果就写在 model card 里。ML-intern 负责规划工作，在花任何钱之前先向我要预算，在正式作业之前先跑一个小测试，然后在 Hugging Face 的硬件上训练、评估并发布。

## 我是怎么给 ML Intern 写 prompt 的

第一条消息就是我把功夫花下去的地方。我的第一个 prompt——为下面分享的那个 *citrus* 模型写的——大约 450 个词。到第 6 个项目时它已经接近 2,000 词，因为每个项目都教会我一些东西，而这些东西我希望在下一个项目里用上。七个 prompt 全都在 GitHub 的 [yvrjsharma/ml-intern-prompts](https://github.com/yvrjsharma/ml-intern-prompts) 上，与我当时写下的一模一样。

一个 prompt 先用一行话说清想法，以及我为什么想要它。然后点名具体的部件：dataset、base model、训练脚本。任何我已经核实过的东西，都放在一个标题字面上写着 "Verified facts, do not re-derive" 的小节下，这样 agent 就把预算花在工作本身，而不是重新发现我已经知道的事。对那个 camera-angle LoRA，那一节列出了哪个 trainer 刚刚加上了透明图像支持，以及哪几个未关闭的 GitHub issue 让备用 trainer 有风险。

**prompt 里有两行是关键的**。**第一行**要求在任何训练之前先给出一个 baseline。例如，那个 *citrus prompt* 里写着："请在训练之前，用同一指标报告 base model 的 zero-shot 分数，好让我们看到增益。"没有这一句，你只会得到一个训练好的模型，却完全不知道它是否比你的起点更好。**第二行**是一个附带检查项的 smoke test。对那几个图像 LoRA，我要求先跑 50 个训练 step，然后检查保存下来的权重确实发生了变化，在此之后才付费跑完整的训练。

在 prompt 的末尾，我列出期望的交付物并限定成本。我定义 model card 里应该放什么，并写上一条类似"总花费上限设为 USD 12，超出之前先问我"的指令。因为 ML-intern 每个任务都从零美元预算开始，而且在执行付费作业之前需要得到许可，这条花费上限会被严格执行。当你没有给出预算时，agent 会根据项目规模建议几条路线，并问你偏好哪一条。

你第一次尝试时未必需要上面所有这些。例如，我在给 *citrus* 的需求里并没有 *verified-facts* 那一节，而 ML Intern 仍然产出了一个模型，把 [Qwen3.5-2B](https://huggingface.co/Qwen/Qwen3.5-2B) 模型的 accuracy [提升了三倍有余](https://huggingface.co/ML-Intern-lab/citrus-disease-vlm#results)。下面带你看我在短短几天里用 Ml-Intern 做的 6 样东西。

## 1. 一个懂你所在领域的模型

通用的视觉模型能描述一片正在发黄的柑橘叶。然而要告诉你那是螨虫问题还是镁元素缺乏，以及处理这株植物的生物法与非生物法手段，就非常难了。借助 Claude，我把托管在 Hub 上 [Project-AgML](https://huggingface.co/Project-AgML) 组织下的三个来源合并成了一个训练数据集。得到的 [citrus-disease-vlm-instruct](https://huggingface.co/datasets/ML-Intern-lab/citrus-disease-vlm-instruct) 是一个包含 3,017 张标注图像的数据集，覆盖 21 种不同的病虫害、疾病、营养缺口与治疗方案。ML-intern 用这些样本完成了 Qwen3.5-2B 的 fine-tuning，并且事先确保对 foundation model 做了 benchmark。

在 335 张测试照片上，base model 只有 14.9% 的情况下说对了问题。在一块 A10G 上跑完两个 epoch 之后，微调后的模型拿到了 52.8%。算力成本约 USD 1.90。

去看看：[模型](https://huggingface.co/ML-Intern-lab/citrus-disease-vlm) · [数据集](https://huggingface.co/datasets/ML-Intern-lab/citrus-disease-vlm-instruct) · [Citrus Doctor 应用](https://huggingface.co/spaces/ML-Intern-lab/citrus-doctor)

## 2. 一个会画你家角色的模型

图像模型认识很多角色。但用 Hugging Face 品牌资产的扁平风格画出来的 Huggy 不在其中。我让 ML-Intern 在 [FLUX.2 klein base 4B](https://huggingface.co/black-forest-labs/FLUX.2-klein-base-4B) 上做一个 LoRA，用 [Chunte/huggy_for_training](https://huggingface.co/datasets/Chunte/huggy_for_training) 数据集里 84 张带 caption 的图画来训练。

agent 每 100 个 step 存一个 checkpoint，并用每个 checkpoint 画同一组 prompt，这让挑选变得容易。第 200 步是 Huggy 第一次完全*贴合形象*。从第 500 步开始，Huggy 的风格开始渗进那些与 Huggy 毫无关系的 prompt 里！训练好的 LoRA 在蒸馏后的 klein 模型上跑 4 步也能用。算力成本约 USD 7.60。

去看看：[模型](https://huggingface.co/ML-Intern-lab/huggy-flux2-klein-lora) · [数据集](https://huggingface.co/datasets/Chunte/huggy_for_training) · [Huggy Generator 应用](https://huggingface.co/spaces/ML-Intern-lab/huggy-generator)

## 3. 一个会耍新花样的模型

- **Camera-angle LoRA** 是早先的 Qwen-Image 模型最受欢迎的社区附加件之一。你可以给模型一张物体的图片，然后要求从左侧 45 度的角度看它。我在 Qwen-Image 2.1 模型发布几天后去看时，还没有人做过，于是我把这件事交给 ML-intern 去做。

![Qwen 相机视角 LoRA](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/building-with-ml-intern/viewpoint-orbit-lora.gif)

ML-intern 从 [Google Scanned Objects](https://huggingface.co/datasets/suvadityamuk/google-scanned-objects) 渲染了 1,030 个扫描得到的家居物品，每个 24 个角度，共 24,722 张透明图像，而这只是一个花了几美分的 CPU 作业。它后来确定了 461 个物体用于训练、40 个留出用于测试，以及 1,844 对训练前后的配对图像，均匀分布在 23 条相机视角指令上。

训练在一块 A100 上跑了 2,000 个 step，约 90 分钟（约 USD 3.75）。整个项目花了大约半天和 48 个作业，其中也算上那些因为缺包或路径写错而失败、要由 ML-Intern 重新提交的作业。总算力成本约 USD 16。

去看看：[模型](https://huggingface.co/ML-Intern-lab/Qwen-Image-2.1-viewpoint-orbit-LoRA) · [数据集](https://huggingface.co/datasets/ML-Intern-lab/gso-orbit-rgba) · [Viewpoint Orbit 应用](https://huggingface.co/spaces/ML-Intern-lab/Qwen-Image-2.1-viewpoint-orbit-LoRA)

- **Doodle-in LoRA** 是另一个很妙的点子。上传一张上面有品红色涂鸦的照片，再配上一句点名某个物体的短 prompt。这个 LoRA 会把那团涂鸦替换成那个物体，同时让原有的光照和构图保持一致。

这件事没有现成的数据集，所以我的 prompt 描述了该怎么做一个。从 Open Images 里的一张真实照片出发，用 LaMa inpainting 模型去掉其中一个物体，并在物体原本所在的位置画一团涂鸦。未经改动的原照片就是目标。ML-intern 在一个 CPU 沙箱里写好并测了配对构建脚本，然后把它们作为 GPU 作业运行，一路记录下每张源图的作者与许可证。它构建了 6,042 对训练配对和一个 160 对的测试集，其中 40 对测试配对来自 23 个完全没有进入训练数据的物体类别。

训练之前，它先测量了 base model 单独使用、以及配上 Viggle turbo LoRA 时的表现，并检查了批量跑编辑是否能产出完全相同的图像，这让评估更省钱。训练在一块 A100 上跑了 2,000 个 step，用时 1 小时 38 分钟（约 USD 4），再在 48 对测试配对上比较保存下来的各个 checkpoint，选出了第 500 步。

与 [Viggle turbo LoRA](https://huggingface.co/Viggle/Qwen-Image-2.1-viggle-turbo) 配对、跑 6 步时，这个 LoRA 表现出色。[67.5%](https://huggingface.co/ML-Intern-lab/Qwen-Image-2.1-doodle-in-LoRA#main-comparison--160-test-pairs) 的物体在它们被画出的位置上就被检测到了，每次编辑 4.7 秒。那 23 个未见类别里的物体落点和其他类别一样可靠（65.0% 对 64.2%）。项目花了一天多一点和 59 个作业。总算力成本约 USD 24。

去看看：[模型](https://huggingface.co/ML-Intern-lab/Qwen-Image-2.1-doodle-in-LoRA) · [数据集](https://huggingface.co/datasets/ML-Intern-lab/doodle-in-pairs) · [Doodle-in 应用](https://huggingface.co/spaces/ML-Intern-lab/Qwen-Image-2.1-doodle-in-LoRA)

## 4. 一个适配你设备的模型

- 本文开头提到的那个 **Pocket Rewriter** 就是第一个。ML-intern 先通过 Inference Providers 用一个小号 instruct 模型生成了 8,797 条简短的图像请求，遵循我在 prompt 里设定的配比：照片、海报、logo、信息图等等，其中约三分之一要求出现引号里的确切文字，许多用的是英语以外的语言。随后那个 9B 的 teacher 在一块 A100 上花了 2 小时 37 分钟（约 USD 6.50）把它们全部改写了一遍。经过质量过滤后，选出 1,840 条样本作为训练数据集。

在 A10G 上训练 0.8B 和 2B 两个 student 分别花了 12 分钟和 18 分钟（两个一共 USD 0.75）。0.8B 还额外以一个 812 MB 的 GGUF 文件形式发布，用于在 CPU 上运行。项目大约花了 11 小时和 24 个作业。总算力成本约 USD 16。

去看看：[Pocket rewriter 0.8B Student](https://huggingface.co/ML-Intern-lab/Qwen-Image-2.1-PE-T2I-Pocket-0.8B) · [2B Student](https://huggingface.co/ML-Intern-lab/Qwen-Image-2.1-PE-T2I-Pocket-2B) · [数据集](https://huggingface.co/datasets/ML-Intern-lab/Qwen-Image-2.1-rewriter-distill) · [Pocket Studio 应用](https://huggingface.co/spaces/ML-Intern-lab/Qwen-Image-2.1-pocket-studio) · [在 Rewriter Arena 里对比 teacher 与 student](https://huggingface.co/spaces/ML-Intern-lab/Qwen-Image-2.1-rewriter-arena)

- **Agate-Preview-002-4step** 是第二个。[Logolabs 的 Agate Preview 002](https://huggingface.co/Logolabs/agate-preview-002) 是一个 260M 参数的 text-to-image 模型，小到足以跑在浏览器里，但它需要 50 个带 guidance 的 step，也就是每张图 100 次网络前向。我让 ML-intern 把它蒸馏到只要 4 次前向！

这需要两轮。第一轮把 155,000 张训练图像缓存为 latent，把 guidance 烘焙进模型，然后把 step 数逐级从 16 砍到 8 再到 4，全部在 A100 上完成。在 GenEval 和 FID 上，4 步的 student 胜过了同样跑 4 步的 teacher；之后 ML-intern 把它导出为 ONNX 供浏览器使用。这一轮大约花了 13 小时和 USD 22。

我又做了第二轮训练，让 ML-Intern 把那个 4 步的 student 再改进一点。它随后用 16 步的 teacher 多生成了 24,000 对图像，并用这些配对对 4 步 student 做了约一小时的 fine-tuning。GenEval 从 0.509 升到 0.536，而 teacher 在 50 步时是 0.563——我们只用了 4 步（算力是四分之一）。ML-intern 重新导出了浏览器版本。第二轮大约花了 8 小时。两轮总算力成本约 USD 37。

去看看：[Agate 4-step 模型](https://huggingface.co/ML-Intern-lab/agate-preview-002-4step) · [数据集](https://huggingface.co/datasets/ML-Intern-lab/agate-preview-002-4step-latents) · [在浏览器里跑 Agate](https://huggingface.co/spaces/ML-Intern-lab/agate-preview-002-4step-webgpu) · [Agate 4-step 直播版](https://huggingface.co/spaces/ML-Intern-lab/agate-preview-002-4step-live)

## 也来做你自己的

ML-intern 就在 [HuggingChat](https://huggingface.co/chat/) 里。打开 ML-intern 模式，粘贴一个 prompt。如果你需要一个起点，[我的示例 prompts](https://github.com/yvrjsharma/ml-intern-prompts) 可以随便抄。从一个你希望存在的模型出发，配上一个你手上已有的、或者你能描述清楚的数据集。给它一个小预算，要求一个 baseline 和一个 smoke test，并且在调高上限之前先读一读它返回的东西。

如果你用它做出了什么，请分享到 X 上并 @ [@Gradio](https://x.com/Gradio) 和 [@HuggingFace](https://x.com/huggingface)。我们很想看到你做出来的那些——别人根本想不到要为你做的模型。
