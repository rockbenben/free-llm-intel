# 给你的编码智能体一份真正属于你的记忆

作者：David Corvoysier（dacorvo）

我在好几台机器之间工作，并根据任务在不同编码智能体之间切换。它们每一个认识我的项目时都是陌生人。"上周二"的推理过程随着会话结束就消失了。每个新智能体、每台新机器，都从零开始。

今年早些时候，[*Software Forgets: Agent Traces Are the Memory*](https://huggingface.co/blog/huggingface/agent-traces-as-memory) 论证了一个观点：编码智能体其实已经在产出我们一直丢失的那份记录。当它们在代码库里搜索、尝试方案、撞上错误、阅读文档、转换方向时，会留下一份密集的账本——不仅记录*改了什么*，还记录*为什么改*。

诊断是对的，但 traces（执行轨迹）只是潜在的记忆。智能体的会话日志仍然只是一个归档。你不可能靠 `grep` 在上万个回合里找到*"我们当时为什么弃用流式解析器？"*。要让智能体在工作时能用上这些 traces，还需要索引、检索、排序和精确的出处溯源。

这正是 [funes](https://github.com/huggingface/funes) 提供的东西。它是给你的智能体（Claude Code、Codex、pi 和 Hermes）用的持久记忆层。它由你机器上已有的会话构建，完全本地运行，一条命令就能融入你的智能体的日常工作流。需要的时候，它还能把记忆带到一个默认私有的、属于你自己的 Hugging Face 数据集上。

## 给你已经在用的智能体加上记忆

funes 是单个二进制文件。它的默认推理后端不依赖任何 ML 运行时，嵌入和重排都发生*在你自己的机器上*。安装：

```
curl -fsSL https://huggingface.co/buckets/huggingface/funes/resolve/install.sh | sh
```

然后把它加到一个智能体上：

```
funes add claude    # or: codex, pi, hermes
```

就这一条 `add` 命令，会构建第一份索引、给智能体配上 `recall` 和 `get` 工具，并安装自动化钩子——每完成一个回合就把它索引。索引是增量的：新的运行只添加新回合，不会把整段历史重新嵌入。更早、更深的旧内容可以分有限几步回填。

之后你只管正常干活。当任务牵涉到过去的决策、理由或发现时，智能体会自己伸手调用 `recall`。你不需要记得旧会话，也不用把它的上下文粘贴到新会话里。

[![A coding agent reaches for funes on its own, recalls an earlier decision, and grounds its answer in the retrieved session](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/funes/recall.gif)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/funes/recall.gif)

> 加上 funes 之后，回忆就发生在对话内部。智能体自己调用它的
> 记忆，并说出答案背后是哪个会话。

`recall` 返回的是原始文本而不是摘要，并精确显示出处（哪个智能体、时间戳、会话、回合）。每条结果都附带一条 `get` 命令，可以打开完整回合及其上下文。

底层是一条确定性的流水线：把每种支持的 trace 解析成统一的"回合-块"结构，切块，用固定版本的本地模型做嵌入，写入本地的 **Lance** 数据集。一次查询会组合向量检索和 BM25 检索、融合两者排序、用 cross-encoder 对候选重排、按新旧程度重新加权，并挂上相邻的分块。

这个设计赋予 funes 三个重要特性：

- **跨智能体的一份记忆：** Claude Code、Codex、pi 和 Hermes 都写入同一种结构。`recall` 横跨它们的历史，每条命中都标明出自哪个智能体。
- **原始证据保持完整：** 写入时不会把内容蒸馏成"事实"。任何结果都能回溯到产生它的那个回合。
- **`recall` 默认本地：** 不需要账号，也不需要 Hub 仓库。托管模型不会为了索引处理你的会话；嵌入和重排在你的机器上运行，推理交给你的编码智能体自己做。

"智能体形同陌路"的问题在单机上已经解决。但当下一个智能体跑在别的机器上时，记忆才真正发挥价值。

## 记忆是一份数据集，不是一个服务

要让记忆跟着你的工作走，在给智能体添加 funes 时绑定一份记忆：

```
funes add codex acme/funes-memory
```

这条 bind 会把你当前的记忆发布到那里。之后 funes 会让它保持最新：每个回合在本地索引，在会话边界处发布。智能体全程从这份记忆中回忆。在另一台机器上运行同样的命令，记忆就跟过去了。

底层上，本地记忆是一个 Lance 数据集，共享记忆则是一份你拥有的 Hugging Face 数据集（默认私有）。

在任何内容到达 Hub 之前，凭据在索引阶段就已被脱敏。发布时还会再次扫描每个分块，扣下任何仍像密钥的内容。这套扫描器的能力边界——覆盖什么、不覆盖什么——都记录在 [`SECURITY.md`](https://github.com/huggingface/funes/blob/main/SECURITY.md) 中。

当智能体读取远端记忆时，funes 会把数据集文件缓存在本地，因此热查询恢复成本地速度。所有权、访问控制、版本管理和分发，都由 Hub 对它承载的其他数据集提供的既有机制来完成。你的记忆不会变成某个独立记忆服务里的一个账号，你也不用再通过 API 把它"租"回来。

## 先问，再接

`recall` 是为智能体设计的。当你想亲自向一份记忆提问时，用 `ask`。它默认读取你的本地记忆：

```
funes ask claude "what did we decide about the streaming parser"
```

也可以指向一份共享记忆。我们发布了一份记录 funes 开发过程的[记忆](https://huggingface.co/datasets/huggingface/funes-memory)，所以你不用建立自己的记忆，就能直接问"funes 为什么是这样设计的"：

```
funes ask claude "why is funes append-only" --memory huggingface/funes-memory
```

[![Asking the published funes memory why it is append-only; funes retrieves the relevant sessions and a coding agent answers from them](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/funes/ask.gif)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/funes/ask.gif)

> funes ask 是 funes add 的只读、单问题版兄弟。它召回相关段落，
> 把它们交给一个编码智能体，返回一个注明来源、有据可依的回答。
> 它不会安装集成，也不会改变智能体的持久配置。

检索不中不会被搪塞过去。如果这些段落无法支撑一个答案，智能体会直说。你可以换个问法，或者把 funes 加到智能体里，让它在正常工作中对记忆做迭代式搜索。

## 换智能体而不丢失思路

共享记忆不绑定产生它的智能体或模型。今天在 Claude Code 里开始一个任务，下周在 Codex 里继续，第二个智能体能召回第一个智能体的推理。用 pi 配本地模型或经 Hugging Face router 服务的模型干一阵，再回到 Claude。

[![Claude Code chooses an embedding model, then Codex recalls that decision in a separate session](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/funes/cross-agents.gif)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/funes/cross-agents.gif)

*Claude 做出一个决策；一个钩子把它索引；Codex 在另一个会话里召回它。演示中较旧的命中之所以多，是因为它们是同一实验的早期录像：一份只追加（append-only）的记忆连排练也一并记住了。*

这在几个不同范围上都有意义：

- **跨你的机器：** 把每个智能体绑定到同一份记忆，在任何一台主机上都能召回历史。
- **跨团队：** 新队友的智能体在第一天就能检索几个月来的决策，包括死胡同和从未进入 PR 的理由。
- **围绕开源项目：** 维护者可以把一次发布背后的会话发布出来，在 push 时点名它们。可以把它想象成一份可搜索的 `CLAUDE.md`，记载"项目为什么是现在这个样子"的历史，而不是一个需要有人不断重写的页面。任何人都可以用 `--memory` 读取一份公开记忆。

发布的记忆自带 dataset card 和 funes 标签，因此可识别、[可在 Hub 上被发现](https://huggingface.co/datasets?other=funes)。Hub 已经在承载开放权重和数据集，funes 在此之上加入的是开放的工作记忆。它保存一个项目的决策、失败的方案和背后的理由，可被另一个智能体查询，并可追溯到产生它们的会话。

## 摆脱长会话的最省钱办法

一次漫长的调查会让会话膨胀，直到每个回合"背着上下文"的成本比干活本身还高。常规解法是让智能体做 compact（压缩摘要）继续跑，或者写一份交接文档然后重开。Recall 是第三种，于是我们在 [handoff-vs-recall 基准](https://huggingface.co/datasets/dacorvo/funes-handoff-recall-benchmark/blob/main/results/README.md)上把三者放在一起测：两个任务，其答案没有会话先验知识就无法重建。

Compaction 是多数智能体的默认行为，也是三者中唯一一个结果分裂的：在一个任务上它成功了，在另一个上始终没成功。在它失败的地方，它的摘要把关键的发现压平了。Recall 返回的是段落原文，所以某个发现不必先挺过"被摘要"这一关。

在两个任务上，recall 都是三者中最便宜的：在一个任务上比手写交接便宜 8 倍，在另一个上便宜 4 倍。

[![Weighted tokens per successful task for five channels across two tasks, with recall the shortest bar on both](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/funes/handoff-recall-cost.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/funes/handoff-recall-cost.jpg)

*每根条中较浅的部分是准备该通道的一次性开销——交接文档或压缩摘要——在提出第一个问题之前支付、只计一次。叉号表示该通道从未成功到达，因此没有"每次成功的成本"。*

## 别再从零开始

> "思考就是遗忘差异、概括、做抽象。"
> —— 豪尔赫·路易斯·博尔赫斯，《富内斯，一个记性极好的人》（Funes the Memorious）

你的智能体早已写下那份记录。funes 就在 [`github.com/huggingface/funes`](https://github.com/huggingface/funes)，距你只差一条命令：把那份记录变成下一位智能体可读的记忆，无论你在哪台机器上。

## 建立在开源之上

funes 在这套东西里几乎没发明什么。它依托的是足以本地运行的开源嵌入模型、[Lance](https://github.com/lancedb/lance) 支持低成本增量写入的 append-only 数据集，以及 Hub 已有的数据集缓存与内容去重。真正的工作，是把它们装配成一份智能体实际用得上的记忆。

funes 本身也是开源的。从安装卡壳、一次召回失误，到你想支持的新智能体，任何事都可以[提 issue](https://github.com/huggingface/funes/issues)。
