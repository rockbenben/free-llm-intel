# Granite 4.0 3B Vision：面向企业文档的紧凑多模态智能

今天我们很高兴发布 [Granite 4.0 3B Vision](https://huggingface.co/ibm-granite/granite-4.0-3b-vision)——一个为企业文档理解设计的紧凑型视觉语言模型（VLM）。它为从复杂文档、表单和结构化图形中可靠地抽取信息而生。Granite 4.0 3B Vision 在以下能力上表现出色：

- **表格抽取**：从文档图像中精确解析复杂表格结构（多行、多列等）
- **图表理解**：把图表和图形转换为结构化的机器可读格式、摘要或可执行代码
- **语义键值对（KVP）抽取**：在多样的文档版式中识别并定位有语义意义的键值字段对

该模型以一个 LoRA adapter 的形式发布，叠加在我们的稠密语言模型 [Granite 4.0 Micro](https://huggingface.co/ibm-granite/granite-4.0-micro) 之上，让视觉与语言保持模块化——既支持纯文本回退，也能无缝嵌入混合流水线。它继续支持视觉-语言任务，例如从图像生成细致的自然语言描述（如"详细描述这张图"）。模型可单独使用，也可与 [Docling](https://github.com/docling-project/docling) 配合，用深度视觉理解能力增强文档处理流水线。

## Granite 4.0 3B Vision 是怎么造出来的

Granite 4.0 3B Vision 的性能来自三项关键投入：一个用新颖的代码引导数据增强方法构建的专用图表理解数据集、一种新颖的 [DeepStack 架构](https://arxiv.org/abs/2406.04334)变体（支持高细节的视觉特征注入）、以及让模型对企业部署保持务实的模块化设计。

### ChartNet：教会模型真正理解图表

图表对 VLM 是个挑战：理解它需要同时推理视觉模式、数值数据和自然语言——多数 VLM 处理不好这种组合，尤其当空间精度要紧时——比如从折线图上读出精确数值。为补上这个缺口，我们开发了 [ChartNet](https://huggingface.co/datasets/ibm-granite/ChartNet)：一个百万量级、专为图表解读与推理构建的多模态数据集，详见我们即将发表的 [CVPR 2026 论文](https://arxiv.org/abs/2603.27064)。

ChartNet 使用代码引导的合成流水线，生成 170 万个多样图表样本，横跨 24 种图表类型和 6 个绘图库[见图 1]。它的独特之处在于每个样本包含五个对齐的组成部分——绘图代码、渲染图像、数据表、自然语言摘要、问答对——为模型提供对图表"含义"的深度跨模态视角，而不只是"长相"。数据集还包含人工标注子集与真实世界子集，并按视觉保真度、语义准确性和多样性做了筛选。

成果是一份让 VLM 从仅仅"描述图表"走向真正"理解图表编码的结构化信息"的训练资源——在各种模型规模、架构和任务上带来一致的增益。

[![chartnet (1)](https://cdn-uploads.huggingface.co/production/uploads/653fb52cbfd890805461d691/yX68Qg2FjRNRk9AAh4mTi.jpeg)](https://cdn-uploads.huggingface.co/production/uploads/653fb52cbfd890805461d691/yX68Qg2FjRNRk9AAh4mTi.jpeg) *图 1：ChartNet 的合成数据生成流水线。*

### DeepStack：更聪明的视觉特征注入

多数 VLM 只在单一位置把视觉信息注入语言模型，这迫使模型同时处理高层语义与细粒度空间细节。Granite 4.0 3B Vision 用 DeepStack 注入走另一条路：抽象视觉特征被路由进较浅的层做语义理解，高分辨率空间特征则喂进较深的层以保住细节。结果是模型既懂文档里"有什么"也懂"在哪里"——这对表格抽取、图表理解、KVP 解析这类版式与内容同等重要的任务至关重要。完整技术拆解见 model card 的 [Model Architecture](https://huggingface.co/ibm-granite/granite-4.0-3b-vision#model-architecture) 一节。

### 模块化：一个模型，两种模式

Granite 4.0 3B Vision 以 LoRA adapter 打包在 [Granite 4.0 Micro](https://huggingface.co/ibm-granite/granite-4.0-micro) 之上，而不是独立模型。实际意义是：同一份部署可以同时服务多模态和纯文本负载，不需要视觉时自动回退到基座模型。这让企业集成保持简单，又不牺牲性能。

## 性能表现

**图表**：在人工校验的 ChartNet 基准上用 LLM-as-a-judge 评估，Granite 4.0 3B Vision 拿下所有被评模型中最高的 Chart2Summary 分数（86.4%），包括大它许多的模型[见图 2]。Chart2CSV 上排名第二（62.1%），仅次于体积超过它两倍的 Qwen3.5-9B（63.4%）。

[![image](https://cdn-uploads.huggingface.co/production/uploads/653fb52cbfd890805461d691/CBMcvEZIzDllDWi7I4rrJ.png)](https://cdn-uploads.huggingface.co/production/uploads/653fb52cbfd890805461d691/CBMcvEZIzDllDWi7I4rrJ.png) *图 2：以 LLM-as-a-judge 与同级 VLM 对比，Granite 4.0 3B Vision 在 chart2csv 与 chart2summary 上的表现。*

**表格**：我们在两种设定下评估表格抽取：裁剪表格（独立区域）与整页文档（嵌在复杂版式里的表格）[见图 3]。基准套件包括 [TableVQA-extract](https://arxiv.org/abs/2404.19205)（裁剪的表格图像）、[OmniDocBench-tables](https://arxiv.org/abs/2412.07626)（整页文档）和 [PubTables-v2](https://arxiv.org/abs/2512.10888)（两种设定皆有）。模型需以 HTML 格式抽取表格，用 TEDS 评分——一个同时刻画结构与内容准确性的指标。Granite 4.0 3B Vision 跨基准取得最强表现：在 PubTablesV2 裁剪（92.1）与整页（79.3）、OmniDocBench（64.0）、TableVQA（88.1）上均领先所有被评模型。

[![Tables](https://cdn-uploads.huggingface.co/production/uploads/653fb52cbfd890805461d691/k4-ExbC0Lnbf-HctVHq4q.png)](https://cdn-uploads.huggingface.co/production/uploads/653fb52cbfd890805461d691/k4-ExbC0Lnbf-HctVHq4q.png) *图 3：以 TEDS 度量，Granite 4.0 3B Vision 在裁剪与整页基准（TableVQA-extract、PubTables-v2、OmniDocBench-tables）上的表格抽取性能。*

**语义 KVP**：[VAREX](https://arxiv.org/abs/2603.15118) 是一个专为区分小型抽取模型设计的基准，包含 1,777 份美国政府表单，从简单扁平版式到复杂嵌套与表格结构皆有。模型用精确匹配（EM）评估——一个严格要求抽取的键值对与标准答案一致的指标。Granite 4.0 3B Vision 零样本达到 85.5% 的 EM 准确率。

## 如何使用

Granite 4.0 3B Vision 既可以作为独立的视觉信息抽取引擎，也可以作为 Docling 全自动文档处理流水线的一部分。模型设计目标是跨多样文档类型与视觉格式的可扩展、高精度抽取。

**1. 独立的图像理解** Granite 4.0 3B Vision 可直接对单张图像运行。这对已有工作流、需要定向视觉抽取而不改动上游系统的应用很实用。集成进现有自动化工作流容易，适合轻量的任务型工具（表单解析器、图表分析器等）。

**2. 与 Docling 集成的文档理解流水线** Granite 4.0 3B Vision 也能与 Docling 无缝集成，支持端到端文档理解。这个模式可提供：

- 多页 PDF 的大规模处理
- 用 Docling 自动检测、分割并裁剪图形、表格等视觉元素，把干净的裁剪图转给 Granite Vision 做细粒度抽取
- 总体计算成本更低、吞吐更高的工作流
- 在大型文档集合上更准确的抽取、更可靠的结果和显著改善的效率

**示例用例**

- **表单处理**：用 KVP 能力从发票、表单、收据抽取结构化字段，或用 image2text 功能为图形生成自然语言描述（如"详细描述这张图"）。
- **财务报告分析**：用 Docling 解析报告、检测图形、裁剪视觉元素。图表用 Granite Vision 的 chart2csv、chart2code 处理，表格用 tables_json 能力处理，把它们转成结构化、机器可读的数据，支撑可行动的洞察。
- **研究文档智能**：用 Docling 处理密集学术 PDF 的 OCR 与版式解析，把抽出的图形交给 chart2summary、表格裁剪交给 tables_html，让视觉内容与自由文本在同一条流水线中一起可检索。
