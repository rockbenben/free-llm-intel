## 什么是 agent？

大语言模型（LLM）能处理广泛的任务，但在逻辑、计算、搜索这类特定任务上常常力不从心。在这些它表现不佳的领域里给出提示词时，它经常无法生成正确答案。

克服这一弱点的一种思路是构建一个 **agent**——说白了就是一个由 LLM 驱动的程序。agent 通过 **工具（tools）** 来获得执行动作的能力。当解决某个问题需要特定技能时，它可以从自己的工具箱里调用合适的工具。

因此，在解决问题的过程中，一旦 agent 需要某种特定技能，它可以直接依赖工具箱中合适的工具。

从实践来看，agent 框架通常效果很好，在多个基准测试上达到了最先进水平。比如看看 [HumanEval 的头部提交](https://paperswithcode.com/sota/code-generation-on-humaneval)：清一色都是 agent 系统。

## Transformers Agents 的方法

构建 agent 工作流很复杂，我们认为这类系统需要极高的清晰度和模块化程度。一年前我们发布了 Transformers Agents，如今我们更加坚定地打磨这些核心设计目标。

我们的框架致力于：

- **以简单求清晰：** 我们把抽象降到最低。简单的错误日志和易于访问的属性，让你轻松查看内部发生了什么，获得更多清晰度。
- **模块化：** 我们更愿意提供积木式的组件，而不是完整而复杂的功能套装。你可以自由挑选最适合自己项目的积木。例如，任何 agent 系统本质上都只是由 LLM 引擎驱动的一辆载具，因此我们在概念上把两者分开，这样你就能用任意底层 LLM 构建任意类型的 agent。

除此之外，我们还有**分享功能**，让你可以站在巨人的肩膀上继续构建！

### 核心要素

- `Tool`：这是用于使用某个工具或实现新工具的类。它主要由一个可调用的 forward `method`（执行工具动作）和几个 essential 属性组成：`name`、`descriptions`、`inputs` 和 `output_type`。这些属性用于动态生成工具的使用说明书，并插入到 LLM 的提示词中。
- `Toolbox`：一组提供给 agent 用于解决特定任务的工具。出于性能考虑，工具箱中的工具都是已实例化、随时可用的。这是因为有些工具初始化耗时，所以通常最好复用现有工具箱、只替换其中一个工具，而不是在每次 agent 初始化时从零重建整套工具。
- `CodeAgent`：一个非常简单的 agent，把动作生成为一整段 Python 代码。它无法基于先前的观察结果进行迭代。
- `ReactAgent`：ReAct agent 遵循 思考 ⇒ 行动 ⇒ 观察 的循环，直到解决任务。我们提供两类 ReactAgent：`ReactCodeAgent` 把动作生成为 Python 代码块；`ReactJsonAgent` 把动作生成为 JSON 代码块。

查看[文档](https://huggingface.co/docs/transformers/en/main_classes/agent)了解如何使用每个组件！

agent 在底层是怎么工作的？

本质上，agent 做的事情是「让 LLM 能够使用工具」。agent 有一个关键的 `agent.run()` 方法，它会：

- 通过**专门的提示词**向你的 LLM 提供工具使用说明。这样，LLM 就能选择工具来执行，从而解决任务。
- **解析** LLM 输出中的工具调用（可以是代码形式、JSON 形式或任何其他形式）。
- **执行**这些调用。
- 如果该 agent 被设计为在先前输出上迭代，它会**维护一份记忆**，记录之前的工具调用和观察结果。根据你希望记忆保存多久，这份记忆可以有不同的细粒度。

![agent 工作流示意图](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/agents/agent_single_multistep.png)

### 自我纠错的检索增强生成

快速定义：检索增强生成（RAG）是「用 LLM 回答用户查询，但回答基于从知识库中检索到的信息」。与使用原生或微调过的 LLM 相比，它有很多优势：简单列举几个——它能让回答扎根于真实事实、减少编造，能为 LLM 提供领域特定知识，还能对知识库信息的访问做细粒度控制。

假设我们要做 RAG，而某些参数需要动态生成。例如，根据用户查询，我们可能想把搜索限制在知识库的特定子集上，或者想调整检索文档的数量。难点在于：如何根据用户查询动态调整这些参数？

没问题，只要让 agent 能访问这些参数即可！

来搭建这套系统。

运行下面这行安装所需依赖：

```
pip install langchain sentence-transformers faiss-cpu
```

首先加载我们要在其上执行 RAG 的知识库：这个数据集汇集了许多 `huggingface` 包的文档页面，以 markdown 存储。

```
import datasets
knowledge_base = datasets.load_dataset("m-ric/huggingface_doc", split="train")
```

接下来处理数据集并存入向量数据库，供检索器使用，以此准备好知识库。我们要用 LangChain，因为它在向量数据库方面有很优秀的工具：

```
from langchain.docstore.document import Document
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain.vectorstores import FAISS
from langchain_community.embeddings import HuggingFaceEmbeddings

source_docs = [
    Document(
        page_content=doc["text"], metadata={"source": doc["source"].split("/")[1]}
    ) for doc in knowledge_base
]

docs_processed = RecursiveCharacterTextSplitter(chunk_size=500).split_documents(source_docs)[:1000]

embedding_model = HuggingFaceEmbeddings("thenlper/gte-small")
vectordb = FAISS.from_documents(
    documents=docs_processed,
    embedding=embedding_model
)
```

数据库准备就绪，现在来构建一个基于它回答用户查询的 RAG 系统！

我们希望系统能根据查询，只挑选最相关的信息来源。

我们的文档页面来自以下来源：

```
>>> all_sources = list(set([doc.metadata["source"] for doc in docs_processed]))
>>> print(all_sources)

['blog', 'optimum', 'datasets-server', 'datasets', 'transformers', 'course',
'gradio', 'diffusers', 'evaluate', 'deep-rl-class', 'peft',
'hf-endpoints-documentation', 'pytorch-image-models', 'hub-docs']
```

如何根据用户查询挑选相关来源？

👉 让我们把 RAG 系统构建为一个 agent，让它自由选择来源！

我们创建一个检索器工具，agent 可以用自己选择的参数来调用它：

```
import json
from transformers.agents import Tool
from langchain_core.vectorstores import VectorStore

class RetrieverTool(Tool):
    name = "retriever"
    description = "Retrieves some documents from the knowledge base that have the closest embeddings to the input query."
    inputs = {
        "query": {
            "type": "text",
            "description": "The query to perform. This should be semantically close to your target documents. Use the affirmative form rather than a question.",
        },
        "source": {
            "type": "text", 
            "description": ""
        },
    }
    output_type = "text"
    
    def __init__(self, vectordb: VectorStore, all_sources: str, **kwargs):
        super().__init__(**kwargs)
        self.vectordb = vectordb
        self.inputs["source"]["description"] = (
            f"The source of the documents to search, as a str representation of a list. Possible values in the list are: {all_sources}. If this argument is not provided, all sources will be searched."
          )

    def forward(self, query: str, source: str = None) -> str:
        assert isinstance(query, str), "Your search query must be a string"

        if source:
            if isinstance(source, str) and "[" not in str(source): # if the source is not representing a list
                source = [source]
            source = json.loads(str(source).replace("'", '"'))

        docs = self.vectordb.similarity_search(query, filter=({"source": source} if source else None), k=3)

        if len(docs) == 0:
            return "No documents found with this filtering. Try removing the source filter."
        return "Retrieved documents:\n\n" + "\n===Document===\n".join(
            [doc.page_content for doc in docs]
        )
```

现在，创建一个使用这个工具的 agent 就轻而易举了！

agent 初始化时需要这些参数：

- *`tools`*：agent 可以调用的工具列表。
- *`llm_engine`*：驱动 agent 的 LLM。

我们的 `llm_engine` 必须是一个可调用对象，输入为 [messages](https://huggingface.co/docs/transformers/main/chat_templating) 列表，返回文本。它还需要接受一个 `stop_sequences` 参数，用于指示何时停止生成。为了方便，我们直接使用包中提供的 `HfEngine` 类，获得一个调用我们 [Inference API](https://huggingface.co/docs/api-inference/en/index) 的 LLM 引擎。

```
from transformers.agents import HfEngine, ReactJsonAgent

llm_engine = HfEngine("meta-llama/Meta-Llama-3-70B-Instruct")

agent = ReactJsonAgent(
    tools=[RetrieverTool(vectordb, all_sources)],
    llm_engine=llm_engine
)

agent_output = agent.run("Please show me a LORA finetuning script")

print("Final output:")
print(agent_output)
```

由于我们把 agent 初始化为 `ReactJsonAgent`，它自动获得了一个默认系统提示词，告诉 LLM 引擎逐步处理并把工具调用生成为 JSON 代码块（必要时你可以用自己的提示词模板替换它）。

随后当它的 `.run()` 方法启动时，agent 会负责调用 LLM 引擎、解析工具调用的 JSON 代码块并执行这些工具调用，全部在一个循环里进行，只有给出最终答案时才停止。

我们得到如下输出：

```
Calling tool: retriever with arguments: {'query': 'LORA finetuning script', 'source': "['transformers', 'datasets-server', 'datasets']"}
Calling tool: retriever with arguments: {'query': 'LORA finetuning script'}
Calling tool: retriever with arguments: {'query': 'LORA finetuning script example', 'source': "['transformers', 'datasets-server', 'datasets']"}

```

可以看到自我纠错在发挥作用：agent 一开始尝试限制来源，但由于找不到对应文档，最终放弃了来源限制。

### 用简单的多 agent 架构 🤝 实现高效网页浏览

在这个示例中，我们想构建一个 agent 并在 GAIA 基准（[Mialon et al. 2023](https://huggingface.co/papers/2311.12983)）上测试。GAIA 是一个难度极高的基准，大多数问题需要多个推理步骤并使用不同的工具。其中一个特别棘手的要求是得有一个强大的网页浏览器，能够按特定约束访问页面：通过网站的内部导航发现页面、按时间筛选特定文章……

网页浏览需要深入子页面并滚动大量文本 token，而这些对上层任务求解并非必需。我们把网页浏览子任务交给一个专门的网页浏览员（web surfer）agent。我们为它配备了一些浏览网页的工具和一个专门的提示词（具体实现见仓库）。

定义这些工具不在本文范围内：你可以查看[仓库](https://github.com/aymeric-roucher/agent_reasoning_benchmark)找到具体实现。

```
from transformers.agents import ReactJsonAgent, HfEngine

WEB_TOOLS = [
    SearchInformationTool(),
    NavigationalSearchTool(),
    VisitTool(),
    DownloadTool(),
    PageUpTool(),
    PageDownTool(),
    FinderTool(),
    FindNextTool(),
]

websurfer_llm_engine = HfEngine(
    model="CohereForAI/c4ai-command-r-plus"
)  # We choose Command-R+ for its high context length

websurfer_agent = ReactJsonAgent(
    tools=WEB_TOOLS,
    llm_engine=websurfer_llm_engine,
)
```

要让更高层的任务求解 agent 调用这个 agent，只需把它封装进另一个工具：

```
class SearchTool(Tool):
    name = "ask_search_agent"
    description = "A search agent that will browse the internet to answer a question. Use it to gather informations, not for problem-solving."

    inputs = {
        "question": {
            "description": "Your question, as a natural language sentence. You are talking to an agent, so provide them with as much context as possible.",
            "type": "text",
        }
    }
    output_type = "text"

    def forward(self, question: str) -> str:
        return websurfer_agent.run(question)
```

然后用这个搜索工具初始化任务求解 agent：

```
from transformers.agents import ReactCodeAgent

llm_engine = HfEngine(model="meta-llama/Meta-Llama-3-70B-Instruct")
react_agent_hf = ReactCodeAgent(
    tools=[SearchTool()],
    llm_engine=llm_engine,
)
```

让我们用以下任务运行这个 agent：

> Use density measures from the chemistry materials licensed by Marisa Alviar-Agnew & Henry Agnew under the CK-12 license in LibreText's Introductory Chemistry materials as compiled 08/21/2023.
> I have a gallon of honey and a gallon of mayonnaise at 25C. I remove one cup of honey at a time from the gallon of honey. How many times will I need to remove a cup to have the honey weigh less than the mayonaise? Assume the containers themselves weigh the same.

```

==== Agent is executing the code below:
density_honey = ask_search_agent(question="What is the density of honey at 25C?")
print("Density of honey:", density_honey)
density_mayo = ask_search_agent(question="What is the density of mayonnaise at 25C?")
print("Density of mayo:", density_mayo)
===

===== New step =====
Thought: I will convert the density of mayonnaise from g/cm³ to kg/L and then calculate the initial weights of the honey and mayonnaise in a gallon. After that, I will calculate the weight of honey after removing one cup at a time until it weighs less than the mayonnaise.
==== Agent is executing the code below:

density_mayo = density_mayo * 1000 / 1000 # conversion

initial_mayo_weight = density_mayo * gallon_to_liters

removed_honey_weight = cup_to_liters * density_honey
===
Observation:

===== New step =====
Thought: Now that I have the initial weights of honey and mayonnaise, I'll try to calculate the number of cups to remove from the honey to make it weigh less than the mayonnaise using a simple arithmetic operation.
==== Agent is executing the code below:
cups_removed = int((initial_honey_weight - initial_mayo_weight) / removed_honey_weight) + 1
print("Cups removed:", cups_removed)
final_answer(cups_removed)
===
>>> Final answer: 6
```

✅ 答案是**正确的**！

## 测试我们的 agents

让我们的 agent 框架上场练练，用它对不同模型做基准测试！

以下所有实验的代码都可以在[这里](https://github.com/aymeric-roucher/agent_reasoning_benchmark)找到。

### 对 LLM 引擎做基准测试

`agents_reasoning_benchmark` 是一个小而强的推理测试，用于评估 agent 性能。这个基准在我们[更早的博客](https://huggingface.co/blog/open-source-llms-as-agents)中已经使用并做过更详细的说明。

其理念是：与 agent 搭配使用的工具选择，可能彻底改变某些任务上的性能。所以这个基准把工具集限制为一个计算器和一个基础搜索工具。我们从若干数据集中挑选了仅用这两个工具就能解决的问题：

- 来自 [HotpotQA](https://huggingface.co/datasets/hotpot_qa) 的 **30 个问题**（[Yang et al., 2018](https://huggingface.co/papers/1809.09600)），用于测试搜索工具的使用。
- 来自 [GSM8K](https://huggingface.co/datasets/gsm8k) 的 **40 个问题**（[Cobbe et al., 2021](https://huggingface.co/papers/2110.14168)），用于测试计算器的使用。
- 来自 [GAIA](https://huggingface.co/datasets/gaia-benchmark/GAIA) 的 **20 个问题**（[Mialon et al., 2023](https://huggingface.co/papers/2311.12983)），用于测试用这两种工具解决难题的能力。

这里我们试用了 3 个不同的引擎：[Mixtral-8x7B](https://huggingface.co/mistralai/Mixtral-8x7B-Instruct-v0.1)、[Llama-3-70B-Instruct](https://huggingface.co/meta-llama/Meta-Llama-3-70B-Instruct) 和 [GPT-4 Turbo](https://platform.openai.com/docs/models)。

![agent 性能基准测试图](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/agents/aggregate_score.png)

结果如上图所示——取了两次完整运行的平均值以提高精度。我们还测试过 [Command-R+](https://huggingface.co/CohereForAI/c4ai-command-r-plus) 和 [Mixtral-8x22B](https://huggingface.co/mistralai/Mixtral-8x22B-Instruct-v0.1)，为了图表清晰没有展示。

⇒ **Llama-3-70B-Instruct 领跑开源模型：它与 GPT-4 不相上下**，并且借助 Llama 3 出色的编码能力，在 `ReactCodeAgent` 中表现尤为强劲！

💡 把基于 JSON 和基于代码的 React agent 拿来对比很有意思：在较弱的 LLM 引擎（如 Mixtral-8x7B）上，基于代码的 agent 表现不如 JSON 版，因为 LLM 引擎经常生成不出好代码。但当引擎换成更强的模型时，代码版就大放异彩：根据我们的经验，用 Llama-3-70B-Instruct 时，代码版甚至比 JSON 版更强。因此下一步挑战——在完整 GAIA 基准上测试——我们采用了代码版。

### 用多模态 agent 攀登 GAIA 排行榜

[GAIA](https://huggingface.co/datasets/gaia-benchmark/GAIA)（[Mialon et al., 2023](https://huggingface.co/papers/2311.12983)）是一个难度极高的基准：从上文的 `agent_reasoning_benchmark` 可以看到，即便我们已经精心挑选了能用两个基础工具解决的问题，模型的得分也没有超过 50%。

现在我们想在完整数据集上拿分，不再挑题。因此必须覆盖所有模态，这促使我们使用这些特定工具：

- `SearchTool`：上文定义的网页浏览器。
- `TextInspectorTool`：把文档作为文本文件打开并返回其内容。
- `SpeechToTextTool`：把音频文件转写为文本。我们使用默认工具，基于 [distil-whisper](https://huggingface.co/distil-whisper/distil-large-v3)。
- `VisualQATool`：对图像进行视觉分析。这方面我们使用了全新出场的 [Idefics2-8b-chatty](https://huggingface.co/HuggingFaceM4/idefics2-8b-chatty)！

我们先初始化这些工具（更多细节，请查看[仓库](https://github.com/aymeric-roucher/agent_reasoning_benchmark)中的代码）。

然后初始化我们的 agent：

```
from transformers.agents import ReactCodeAgent, HfEngine

TASK_SOLVING_TOOLBOX = [
    SearchTool(),
    VisualQATool(),
    SpeechToTextTool(),
    TextInspectorTool(),
]

react_agent_hf = ReactCodeAgent(
    tools=TASK_SOLVING_TOOLBOX,
    llm_engine=HfEngine(model="meta-llama/Meta-Llama-3-70B-Instruct"),
    memory_verbose=True,
)
```

在完成 165 个问题花了一些时间之后，我们把结果提交到 [GAIA 排行榜](https://huggingface.co/spaces/gaia-benchmark/leaderboard)，然后……🥁🥁🥁

![GAIA 排行榜](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/agents/leaderboard.png)

⇒ 我们的 agent 排名第 4：击败了许多基于 GPT-4 的 agents，现在是开源类别的头名竞争者！
