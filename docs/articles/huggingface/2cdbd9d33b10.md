# 用 Hugging Face 轻松构建和共享 ROCm Kernel

[![Easily Build and Share ROCm Kernels with Hugging Face](https://huggingface.co/blog/assets/build-rocm-kernels/thumbnail.png)](https://huggingface.co/blog/assets/build-rocm-kernels/thumbnail.png)

## 引言

自定义 kernel 是高性能深度学习的脊梁——它让 GPU 操作可以精确贴合你的工作负载，无论是图像处理、张量变换还是其它计算密集型任务。但为正确的架构编译这些 kernel、配置各种构建参数、再把它们干净地集成进 PyTorch extension，很快就会变成一团 CMake/Nix、编译器报错和 ABI 问题的乱麻，非常痛苦。Hugging Face 的 [**kernels**](https://github.com/huggingface/kernels) 库让构建（借助 [**kernel-builder**](https://github.com/huggingface/kernels/tree/main/kernel-builder)）和共享这些 kernel（通过 [**kernels-community**](https://huggingface.co/kernels-community)）变得轻松，支持包括 CUDA、ROCm、Metal 和 XPU 在内的多种 GPU 与加速器后端，确保你的 kernel 快速、可移植，并与 PyTorch 无缝集成。

本指南只聚焦 ROCm 兼容的 kernel，演示如何用 [kernels](https://github.com/huggingface/kernels/tree/main) 构建、测试和共享它们。你将学习如何创建能在 AMD GPU 上高效运行的 kernel，以及可复现性、打包和部署的最佳实践。

这份 ROCm 专项指南是原 kernel-builder 指南的精简版。如果你想要更宽的 CUDA 主视角版本，见这里：[A Guide to Building and Scaling Production-Ready CUDA Kernels](https://huggingface.co/blog/kernel-builder)。

## 构建步骤

我们以 [RadeonFlow_Kernels](https://github.com/RadeonFlow/RadeonFlow_Kernels) 的 GEMM kernel 为例。想直接跳到指南请[点击这里](https://huggingface.co/blog/build-rocm-kernels#step-1-project-structure)。

### 关于这个 kernel

> 本节由 RadeonFlow GEMM kernel 的作者撰写，用于介绍该 kernel。作者：ColorsWind、Zesen Liu 和 Andy

**RadeonFlow GEMM** kernel 是一个高性能、FP8 分块（block-wise）矩阵乘法实现，针对 AMD Instinct MI300X GPU 优化。GEMM（General Matrix Multiplication，通用矩阵乘法）是多数深度学习工作负载背后的核心构件：给定矩阵 A 和 B，计算乘积 C = A × B。这里的实现采用 FP8——一种用少量精度换取更高吞吐和更低内存带宽的低精度浮点格式。该 kernel 为 [AMD Developer Challenge 2025](https://www.datamonsters.com/amd-developer-challenge-2025) 开发，并于 **2025 年 6 月**荣膺 🏆 **Grand Prize**，表彰其在 AMD 硬件上的性能与创新表现。

该 kernel 对量化输入进行操作，使用 `e4m3fnuz` 浮点格式，并施加按块缩放（per-block scaling）以在低精度计算中保持精度。`e4m3fnuz` 是 FP8 的一个变体：4 位指数、3 位尾数，专为神经网络工作负载的高效计算设计。由于 FP8 的动态范围远小于 FP16/FP32，我们采用按块缩放因子（a_scale 和 b_scale），让每个数值块在计算前后都被重新缩放到一个数值上"舒适"的范围，从而在低精度下仍保住精度。它接受如下参数：

```
(a, b, a_scale, b_scale, c)
```

其中 `a` 和 `b` 是输入矩阵，`a_scale` 和 `b_scale` 分别是 `a` 和 `b` 的缩放因子，`c` 是输出矩阵：

- `a` 是 K × M 的 e4m3fnuz
- `b` 是 K × N 的 e4m3fnuz
- `a_scale` 是 (K // 128) × M 的 fp32
- `b_scale` 是 (K // 128) × (N // 128) 的 fp32
- `c` 是 M × N 的 bf16

该 kernel 针对特定矩阵形状预编译，并假定转置的内存布局（比赛要求）。要支持更多形状或其他内存布局，你需要修改 kernel launcher。

现在我们有了一个高性能的 ROCm kernel，自然的问题是：如何把它集成进真实的 PyTorch 工作流并与他人共享？这正是接下来要讲的——用 `kernels` 来组织、构建和发布这个 ROCm kernel。

> 这是一份相当技术向的指南，但你不必理解每个细节也能逐 step 跟着做，一切都能正常运行。好奇的话，随时可以回头深挖概念。

### 第 1 步：项目结构

Hugging Face Kernel Builder 期望你的文件按如下方式组织：

```
gemm/
├── build.toml
├── gemm
│   └── gemm_kernel.h
├── flake.nix
└── torch-ext
    ├── torch_binding.cpp
    ├── torch_binding.h
    └── gemm
        └── __init__.py
```

- **build.toml**：项目清单，整个构建过程的"大脑"。
- **gemm/**：你的原始 CUDA/HIP 源码，GPU 魔法发生的地方。
- **flake.nix**：完美可复现构建环境的钥匙。
- **torch-ext/gemm/**：原始 PyTorch 算子的 Python 包装。

有时你的项目可能依赖其他文件，比如测试或辅助脚本，加进来完全没问题。在我们的例子里，项目结构如下：

```
gemm/
├── build.toml
├── gemm
│   ├── gemm_kernel.h
│   ├── gemm_kernel_legacy.h
│   ├── transpose_kernel.h
│   └── gemm_launcher.hip
├── include
│   ├── clangd_workaround.h
│   ├── gpu_libs.h
│   ├── gpu_types.h
│   └── timer.h
├── src/utils
│   ├── arithmetic.h
│   └── timer.hip
├── tests/checker
│   ├── checker.cpp
│   ├── metrics.h
│   └── checker.h
├── flake.nix
└── torch-ext
    ├── torch_binding.cpp
    ├── torch_binding.h
    └── gemm
        └── __init__.py
```

如果你查看 RadeonFlow Kernels 中 gemm kernel 的原始文件，会发现它们是扩展名为 `.cpp` 的 HIP 源文件。第一步要根据内容和用途把这些扩展名改为 `.h` 或 `.hip`：

- 对包含 kernel 声明、内联函数或模板代码、会被其他文件 include 的头文件使用 `.h`
- 对包含需要单独编译的 HIP/GPU 代码的实现文件使用 `.hip`（例如 kernel launcher、复杂实现的设备函数）

在我们的例子中，`gemm_kernel.h`、`gemm_kernel_legacy.h` 和 `transpose_kernel.h` 是头文件，而 `gemm_launcher.hip` 是 HIP 实现文件。这一命名约定帮助 kernel-builder（[`kernels/builder`](https://github.com/huggingface/kernels/tree/main/kernel-builder)）正确识别并编译每种文件类型。

### 第 2 步：配置文件的设置

#### `build.toml` 清单

这个文件统筹整个构建，告诉 kernel-builder 编译什么、各部分如何连接。

```
[general]
name = "gemm"
universal = false

[torch]
src = [
  "torch-ext/torch_binding.cpp",
  "torch-ext/torch_binding.h",
]

[kernel.gemm]
backend = "rocm"
rocm-archs = [
    "gfx942",
]

depends = ["torch"]

src = [
  "include/clangd_workaround.h",
  "include/gpu_libs.h",
  "include/gpu_types.h",
  "include/timer.h",
  "gemm/gemm_kernel.h",
  "gemm/gemm_kernel_legacy.h",
  "gemm/gemm_launcher.hip",
  "gemm/transpose_kernel.h",
  "src/utils/arithmetic.h",
  "src/utils/timer.hip",
  "tests/checker/metrics.h",
]

include = ["include"]
```

**general**

本节包含项目的通用配置。

- **name**（必填）：项目名。应与 kernel 名一致，并将用于 Python 包。
- **universal**（可选）：设为 `true` 时该 kernel 是 universal kernel。universal kernel 是纯 Python 包（无编译文件），不使用下面描述的其他节。Triton kernel 就是一个很好的 universal kernel 例子。默认：`false`

**torch**

本节描述 Torch extension 配置，定义把 kernel 暴露给 PyTorch 的 Python 绑定。

- **src**（必填）：PyTorch extension 的源文件和头文件列表。在我们的例子里，这是创建 Python 接口的 C++ 绑定文件。

**kernel.gemm**

名为 "gemm" 的 kernel 的规格说明。如果有多个 kernel，可以在同一个 build.toml 中定义多个 kernel 节。

- **backend**（必填）：kernel 的计算后端。AMD GPU 支持使用 "rocm"。
- **rocm-archs**（ROCm 必填）：kernel 应为其编译的 ROCm 架构列表。"gfx942" 对应 MI300 系列 GPU。
- **depends**（必填）：依赖列表。我们依赖 "torch" 以使用 PyTorch 的张量操作。
- **include**（可选）：相对项目根目录的 include 目录，帮助编译器找到头文件。

#### `flake.nix` 可复现性文件

为了确保任何人能在任何机器上构建你的 kernel，我们使用 flake.nix 文件。它锁定 kernel-builder 及其依赖的确切版本。（这个示例可以直接复制粘贴，只改 description 即可）

```
{
  description = "Flake for GEMM kernel";

  inputs = {
    kernel-builder.url = "github:huggingface/kernels";
  };

  outputs =
    {
      self,
      kernel-builder,
    }:

    kernel-builder.lib.genFlakeOutputs {
      inherit self;
      path = ./.;
    };
}
```

#### 编写 Kernel

轮到 GPU 代码了。在 `gemm/gemm_launcher.hip` 里，我们定义如何启动 GEMM kernel。根据配置，我们要么调用新的优化版 `gemm/gemm_kernel`，要么回退到 legacy 实现（`gemm/gemm_kernel_legacy`）。

```
// ... previous includes and definitions
extern "C" void run(
    void *a, void *b, void *as, void *bs, void *c,
    int m, int n, int k,
    PerfMetrics *metrics, hipStream_t job_stream0
) {
    const __FP8_TYPE *a_ptr = static_cast<const __FP8_TYPE *>(a);
    const __FP8_TYPE *b_ptr = static_cast<const __FP8_TYPE *>(b);
    __BF16_TYPE *c_ptr = static_cast<__BF16_TYPE *>(c);
    const float *as_ptr = static_cast<const float *>(as);
    const float *bs_ptr = static_cast<const float *>(bs);

    KernelTimerScoped timer(timers, 2LL * m * n * k,
        metrics ? &metrics->entries[0].time : nullptr,
        metrics ? &metrics->entries[0].gflops : nullptr, job_stream0);

    // Dispatch GEMM to the fastest available implementation
    switch (pack_shape(m, n, k)) {
        DISPATCH_GEMM(1024, 1536, 7168, 256, 128, 128, 4, 2, 512, 4, 16);
        DISPATCH_GEMM(6144, 7168, 2304, 256, 128, 128, 4, 2, 512, 1, 16);
        default: {
            printf("Error: Unsupported shape M=%d, K=%d, N=%d\n", m, k, n);
            abort();
        }
    }
}
// ...
```

#### 注册原生 PyTorch 算子

这一步是关键。我们不只是把函数暴露给 Python，而是把它变成一个原生 PyTorch 算子——它由此成为 PyTorch 的一等公民，可通过 `torch.ops` 访问。

`torch-ext/torch_binding.cpp` 负责这个注册。

```
#include <torch/all.h>
#include <torch/library.h>
#include <hip/hip_runtime.h>

#include "registration.h"
#include "torch_binding.h"

// Forward declaration of the C function from gemm_launcher.hip
extern "C" {
    struct PerfMetrics;
    void run(void *a, void *b, void *as, void *bs, void *c, int m, int n, int k, PerfMetrics *metrics, hipStream_t job_stream0);
}

void gemm(torch::Tensor &out, torch::Tensor const &a, torch::Tensor const &b, 
          torch::Tensor const &as, torch::Tensor const &bs) {
    
    // Validate tensor properties
    TORCH_CHECK(a.device().is_cuda(), "Input tensor a must be on GPU device");
    TORCH_CHECK(b.device().is_cuda(), "Input tensor b must be on GPU device");
    TORCH_CHECK(as.device().is_cuda(), "Scale tensor as must be on GPU device");
    TORCH_CHECK(bs.device().is_cuda(), "Scale tensor bs must be on GPU device");
    TORCH_CHECK(out.device().is_cuda(), "Output tensor out must be on GPU device");
    
    TORCH_CHECK(a.is_contiguous(), "Input tensor a must be contiguous");
    TORCH_CHECK(b.is_contiguous(), "Input tensor b must be contiguous");
    TORCH_CHECK(as.is_contiguous(), "Scale tensor as must be contiguous");
    TORCH_CHECK(bs.is_contiguous(), "Scale tensor bs must be contiguous");
    TORCH_CHECK(out.is_contiguous(), "Output tensor out must be contiguous");
    
    // Get matrix dimensions from tensor shapes
    // Assuming a is [M, K], b is [K, N], out is [M, N]
    int M = a.size(0);
    int K = a.size(1);
    int N = b.size(1);
    
    TORCH_CHECK(b.size(0) == K, "Matrix dimensions mismatch: a.size(1) != b.size(0)");
    TORCH_CHECK(out.size(0) == M, "Output tensor dimension mismatch: out.size(0) != M");
    TORCH_CHECK(out.size(1) == N, "Output tensor dimension mismatch: out.size(1) != N");
    
    // Use default HIP stream (stream 0)
    const hipStream_t stream = 0;
    
    // Call the C function
    run(a.data_ptr(), b.data_ptr(), as.data_ptr(), bs.data_ptr(), out.data_ptr(),
        M, N, K, nullptr, stream);
}

TORCH_LIBRARY_EXPAND(TORCH_EXTENSION_NAME, ops) {
  ops.def("gemm(Tensor! out, Tensor a, Tensor b, Tensor a_scale, Tensor b_scale) -> ()");
  ops.impl("gemm", torch::kCUDA, &gemm);
}

REGISTER_EXTENSION(TORCH_EXTENSION_NAME)
```

`torch_binding.h` 文件包含函数声明。例如 `gemm` kernel 在 `torch_binding.h` 中有如下声明：

```
#pragma once

#include <torch/torch.h>

void gemm(torch::Tensor &out, torch::Tensor const &a, torch::Tensor const &b, 
          torch::Tensor const &as, torch::Tensor const &bs);
```

#### 设置 `__init__.py` 包装

在 `torch-ext/gemm/` 中，我们需要一个 `__init__.py` 文件，把这个目录变成 Python 包，并以友好的方式暴露自定义算子。

```
from typing import Optional
import torch
from ._ops import ops

def gemm(a: torch.Tensor, b: torch.Tensor, as_: torch.Tensor, bs: torch.Tensor, 
         out: Optional[torch.Tensor] = None) -> torch.Tensor:
         
    if out is None:
        # Create output tensor with appropriate shape and dtype
        M, K = a.shape
        K_b, N = b.shape
        assert K == K_b, f"Matrix dimension mismatch: A has {K} cols, B has {K_b} rows"
        
        # Output should be BF16 type on the same device as inputs
        out = torch.empty((M, N), dtype=torch.bfloat16, device=a.device)
    
    ops.gemm(out, a, b, as_, bs)
    return out
```

### 第 3 步：构建 Kernel

kernel builder 使用 Nix 构建 kernel。如果系统装了 Nix，可以直接构建或运行 kernel。我们推荐以下方式安装 Nix：

- **Linux**：使用 [官方 Nix 安装器](https://nixos.org/download/)。
- **macOS**：使用 [Determinate Nix 安装器](https://docs.determinate.systems/determinate-nix/)。另外，目前构建 kernel 需要 Xcode 16.x。

#### Nix 起步

首先运行：

```
nix flake update
```

这会生成一个 `flake.lock` 文件，锁定 kernel builder 及其所有传递依赖。把 `flake.nix` 和 `flake.lock` 都提交到仓库，以确保 kernel 构建可复现。

由于 kernel builder 依赖大量包（例如每个受支持的 PyTorch 版本），建议启用 Hugging Face 缓存以避免昂贵的重新构建：

```
# Install cachix and configure the cache
cachix use huggingface
```

或者不永久安装 cachix，只运行一次：

```
# Use cachix without installing it
nix run nixpkgs#cachix -- use huggingface
```

#### 用 Nix 构建 Kernel

带 `flake.nix` 文件的 kernel 可以用 build-and-copy 命令构建：

```
cd Build_RadeonFlow_Kernels/gemm
nix build . -L
```

编译好的 kernel 会出现在本地 `build/` 目录中。

#### 本地开发的 Development Shell

kernel-builder 提供用于开发 kernel 的 shell。在这样的 shell 中，所有必需依赖以及用于生成项目文件的 `build2cmake` 都可用：

```
$ nix develop
$ build2cmake generate-torch build.toml
$ cmake -B build-ext
$ cmake --build build-ext
```

如果你想把 kernel 作为 Python 包测试，也可以做到。`nix develop` 会自动在 `.venv` 中创建虚拟环境并激活：

```
$ nix develop
$ build2cmake generate-torch build.toml
$ pip install --no-build-isolation -e .
```

每种构建配置都有对应的 development shell。例如，可以用下面方式获得带 ROCm 6.3 的 Torch 2.7 开发 shell：

```
$ rm -rf .venv  # Remove existing venv if any
$ nix develop .#devShells.torch27-cxx11-rocm63-x86_64-linux
```

### 第 4 步：把 Kernel 上传到 Hub

kernel 构建好了，我们可以测试它并上传到 Hub。

#### 为所有 PyTorch 和 ROCm 版本构建 Kernel

在共享之前，我们要做的一件小事是清理构建过程中产生的所有开发杂物，避免上传不必要的文件。

```
build2cmake clean build.toml 
```

要为所有受支持的 PyTorch 和 ROCm 版本构建 kernel，kernel-builder 工具会自动完成：

```
# Outside of the dev shell, run the following command
# if you are inside of the sandbox you can leave with `exit`
nix build . -L
```

> 注意：这个过程可能耗时较长，因为它会为所有受支持的 PyTorch 和 ROCm 版本构建 kernel。输出在 result 目录。

最后一步是把结果移动到预期的 build 目录（kernels 库会在这里寻找它们）。

```
mkdir -p build
rsync -av --delete --chmod=Du+w,Fu+w result/ build/
```

#### 推送到 Hugging Face Hub

把构建产物推送到 Hub，其他开发者使用你的 kernel 就会非常直接。我们可以用 `kernels upload` 命令：

```
kernels upload <path_to_kernel> --repo_id hub-username/img2gray
```

也可以走标准的基于 git 的上传流程。

首先创建一个新仓库：

```
hf repo create gemm
```

> 确保你已用 huggingface-cli login 登录 Hugging Face Hub。

然后在项目目录中把项目连接到新仓库并推送代码：

```
# Initialize git and connect to the Hugging Face Hub
git init
git remote add origin https://huggingface.co/<your-username>/gemm

# Pull the changes (just the default .gitattributes file)
git pull origin main
git xet install
git checkout -b main

# Update to use Xet for the binary files
git xet track "*.so"

# Add and commit your changes (being careful to only include the necessary files
# since our build2cmake command generated a lot of dev-specific files)
git add \
  build/ gemm/ include/ src/utils tests/checker \
  torch-ext/torch_binding.cpp torch-ext/torch_binding.h torch-ext/gemm \
  flake.nix flake.lock build.toml

git commit -m "feat: Created a compliant gemm kernel"
git push -u origin main
```

太棒了！你的 kernel 现在已在 Hugging Face Hub 上，供他人使用，并完全符合 kernels 库的规范。

### 第 5 步：开始使用它 :)

用 **kernels** 库，你不需要按传统意义"安装" kernel，而是直接从它的 Hub 仓库加载，加载过程会自动注册新算子。

```
import torch
from kernels import get_kernel

# Load the kernel from the Hub
gemm = get_kernel("kernels-community/gemm")

# Matrix dimensions (must be supported - see gemm_launcher.cpp)
M, N, K = 1024, 1536, 7168
QUANT_SIZE = 128

# Setup device
device = torch.device("cuda")

# Create inputs - kernel expects A:(K,M), B:(K,N)
A_fp32 = torch.randn(M, K, device=device)
B_fp32 = torch.randn(K, N, device=device)

# Convert to FP8
A_fp8 = A_fp32.to(torch.float8_e4m3fnuz)
B_fp8 = B_fp32.to(torch.float8_e4m3fnuz)

# Create scale factors (uniform scaling)
A_scale = torch.ones(K // QUANT_SIZE, M, device=device, dtype=torch.float32)
B_scale = torch.ones(K // QUANT_SIZE, N // QUANT_SIZE, device=device, dtype=torch.float32)

C = torch.zeros(M, N, device=device, dtype=torch.bfloat16)

# Use the kernel
result = gemm.gemm(A_fp8, B_fp8, A_scale, B_scale, C)
```

就这样！你的 ROCm kernel 现在可以从 Hugging Face Hub 直接使用了。

## 结语

借助 Hugging Face，构建和共享 ROCm kernel 已空前简单。由 Nix 驱动的干净、可复现的工作流，加上与 PyTorch 的无缝集成，让开发者可以专注于优化性能而不是折腾环境。构建完成后，你的自定义 kernel 可以共享在 Hugging Face Hub 上，社区即刻可用，几行代码就能跨项目调用。🚀
