# 为 Kaggle 用户改善 Hugging Face 模型的接入体验

Kaggle 和 Hugging Face 的用户同属一个 AI 社区。正因如此，我们非常高兴地宣布：我们将让两个平台与两个社区走得更近，以更好地服务世界各地的 AI 开发者。

从今天起，Kaggle 推出一项集成，在 Kaggle 上直接提升 Hugging Face 模型的可见性与可发现性。

## 如何开始

你可以在 Hugging Face 模型与 Kaggle 之间相互跳转。先访问一个 Hugging Face 模型页，例如 [Qwen/Qwen3-1.7B](https://huggingface.co/Qwen/Qwen3-1.7B)。要在 Kaggle Notebook 中使用它，可以点击 "Use this model" 并选择 "Kaggle"，即可打开一个预填了加载模型代码片段的 Kaggle notebook。在 Kaggle 上的 Hugging Face 模型页也可以做同样的事，点击 "Code" 按钮即可。

当你在 Kaggle 上运行一个引用了托管在 Hugging Face Hub 上模型的 notebook 时，如果对应的 Hugging Face 模型页尚不存在，我们会自动生成一个。你的代码无需做任何特殊改动。此外，当你把 notebook 设为公开时，它会自动出现在 Kaggle 模型页的 "Code" 标签下。

请在 Kaggle 的 [https://www.kaggle.com/models](https://www.kaggle.com/models) 一处集中发现 Hugging Face 模型，并浏览公开 notebook 中的所有社区示例。随着越来越多 Hugging Face 模型在 Kaggle 上被使用，你可以从中获取灵感的模型及相关代码示例数量也会不断增长。

在 Kaggle 上浏览 Hugging Face 模型时，我们希望你能轻松返回 Hugging Face，去探索更多细节、元数据、Hugging Face Spaces 中的社区用例、讨论等等。只需在 Kaggle 模型页点击 "Open in Hugging Face"。

## 对于私有和需授权（consent-gated）的 Hugging Face 模型，这套机制如何工作？

如果你在 Kaggle notebook 中使用私有的 Hugging Face 模型，照常通过你的 Hugging Face 账号认证即可（在 notebook 编辑器的 "Add-ons > Secrets" 菜单中添加你的 HF_TOKEN）。Kaggle 上不会为该 Hugging Face 模型生成模型页。

如果你想在 Kaggle notebook 中访问一个需授权的模型（consent-gated model），你需要使用 Hugging Face 账号申请访问权限，并照常按浏览器中 Hugging Face 模型页上的提示操作。[Hugging Face 有相关文档](https://huggingface.co/docs/hub/en/models-gated#access-gated-models-as-a-user)引导你完成这一流程。除此之外，该集成的表现与对非受限模型完全相同。

## 后续计划

我们正在积极推进一套方案，让需要在离线环境下提交 notebook 的 Kaggle 竞赛也能无缝使用 Hugging Face 模型。虽然这还需要几个月才能完成，但我们相信这份等待是值得的。

你可以阅读 Kaggle 关于["AI 竞赛作为 GenAI 评估中实证严谨性的金标准"](https://huggingface.co/papers/2505.00612)的立场文件，了解为什么把集成的这一部分做对对我们如此重要！简而言之——Kaggle 对数据泄漏及其对模型污染的影响高度敏感。我们的目标是把这项设计做得既能保住竞赛的完整性及其在行业中至关重要的角色，又能让 Kaggle 参赛者无缝地用 Hugging Face 上最优秀的模型进行构建！

在此期间，我们非常希望听到你的反馈——请[在这里分享你的想法与建议](https://huggingface.co/spaces/kaggle/hf-integration-feedback/discussions/1)！

祝你在 Kaggle 玩得开心！
