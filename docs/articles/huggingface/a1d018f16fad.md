你的智能体在彩排时运行正常，可到了现场演示，它走了另一条路，把同一个任务搞砸了。

这在台上非常尴尬。在生产环境里，这就是可靠性问题：一次成功的工作流，下一次用户提出同样请求时可能就失败了。对于关键任务——比如核对一笔金融交易、检查合同中的某项义务——这可能是致命的。

大多数基准把这种波动性藏在平均值后面。在 AppWorld 上，一个用 GPT-4.1 的 ReAct 智能体在五次重复运行中的平均成功率是 **77.4%**。但对五个运行全部成功的任务只占 **53.0%**——存在 **24.4 个百分点的一致性差距**。

大多数基准报告的是第一个数字。我们构建了测量第二个数字——并改进它——的方法。

在之前的文章中，我们介绍了 [ALTK-Evolve](https://huggingface.co/blog/ibm-research/altk-evolve)——一个把智能体自身历史轨迹自动蒸馏成可复用指南、并在推理时注入回系统的机制。它能可度量地提升任务成功率，但那些结果同样只回答了平均值问题。本文介绍 **一致性指南（consistency guidelines）**——[`altk-evolve`](https://github.com/AgentToolkit/altk-evolve) 中的一种新指南类型，构建在我们称为 **一致性分析器（Consistency Analyzer）**的诊断工具之上，直接针对这个差距。

**太长不看**

- **准确率掩盖了一个不可靠问题。** 一个 ReAct 智能体（GPT-4.1，AppWorld `test_normal`）平均成功率 77.4%，但 5 次重复运行全部成功的任务只有 53.0%——**一致性差距 24.4 个百分点**；在困难任务上达到 30 个百分点。
- **我们为这个问题量身打造了诊断工具。** 一致性分析器重采样智能体自己记录的轨迹，找出*易翻转*的决策点——那些只差一次 token 采样就会做出不同选择的步骤。它只需要一条轨迹、不需要标准答案——它对轨迹中每个决策点重采样，一次调用请求 k 个补全（默认 k=5），而不是端到端重跑任务。
- **把诊断变成指南，差距减半**——从 **24.4pp 降到 12.0pp**（同任务 Pass⁵ +16.0pp，相似任务 +13.0pp），并且不损失任何平均准确率。
- **完整方法和评估**见 [arXiv 技术报告](https://arxiv.org/abs/2609.08832)。

## 几乎没人报告的指标

标准智能体评估报告的是 **Mean@k**：把基准跑 *k* 次，对通过率取平均。通常 *k*=3，有时干脆是 1。这是每个排行榜上的数字，也就是“准确率 77%”的实际含义。

Mean@k 回答的是“这个智能体平均有多好？”它没有回答真实用户关心的问题：**我再问一遍同样的问题，它还能做好吗？** 要回答这个问题需要 **Pass^k**：智能体在 *全部* k 次运行中都成功的任务比例。

> ⚠️ Pass^k 不是 Pass@k。大家熟悉的 Pass@k 是乐观的——它问的是 k 次尝试中是否至少有一次成功，这在你可以验证并重试时是正确的问题。Pass^k 是它的悲观镜像：每一次尝试都必须成功。同样的字母，相反的问题。恒有 Pass^k ≤ Mean@k ≤ Pass@k。

一个由 GPT-4.1 驱动的 ReAct 智能体 Mean@5 达到 **77.4%**——确实很强。但 Pass^5 只有 **53.0%**。近四分之一的基准任务，智能体*有时*能解决、有时不能，而任务本身在两次运行之间没有任何变化。我们把这个差距——Mean@k 减去 Pass^k——称为**一致性差距（consistency gap）**。

这不是换个更大模型就能解决的能力问题。它是一条正交的维度：**智能体可以既强大又不稳定。**

## 智能体为什么会翻转：锋利的决策 vs 平坦的决策

LLM 智能体每做一个决定——调用哪个 API、传什么参数、要不要重试——这个决定都来自下一 token 的概率分布。关键在于分布的**形状**。**陡峭（sharp）**的分布把大部分质量放在单个 token 上：第二名差得很远，一次次的运行都会给出同样的选择。**平坦（flat）**的分布把相当的质量分散在几个几乎并列的 token 上，谁胜出基本就是抛硬币。

形状决定了需要多大的噪声才能改变结果。陡峭分布很有韧性——GPU 浮加法不满足结合律、请求批处理等平台侧效应会让数字轻微抖动，但远不足以让明确的赢家变位。平坦分布恰恰怕这种抖动：势均力敌的选项在微小扰动下就可能重排。而一条轨迹串联了几十个决策，单步的小翻转概率会复合成“*某次*运行走岔”的大概率。24 个百分点的差距就是这么来的。

这也是为什么这个问题躲得过你的解码设置。贪心解码和固定随机种子管的都是*分布如何变成 token*——它们管不了分布本身。在托管端点上，概率逐次运行会有轻微变化，所以同一个提示发给同一个模型、即使温度为 0，今天的毫厘之差可能这样判、明天就那样判。

> 我们的设置：ReAct 智能体以温度 0.0 运行，所以上述波动都不是普通的采样造成的。

## 先诊断，再修复

于是问题变成一场搜索：给定轨迹里哪些步骤是平坦的——知道之后又该怎么办？

一致性指南出自一条两阶段流水线，它接入 ALTK-Evolve 现有的机制——只是用新的信号来驱动写入的内容。

**1. 检测——一致性分析器。** 给定一条记录的轨迹，分析器通过受控重采样逐步骤回放每个决策，测量模型输出在该点的实际变化幅度。具体来说，就是每个决策步骤额外一次模型调用，离线做一次——用采样参数设置一次抽取 k 个补全（默认 k=5）——在已记录的上下文上回放，不发新的工具调用、不与环境新交互，也不第二次端到端运行任务。这会为每个决策步骤产出一个一致性分数，写入记分卡，精确指出哪些决策在下次运行中有翻转风险。检测完全是黑盒的——不用 logits、不用模型内部信息，除了你已有的轨迹外不需要任何埋点。

**2. 生成——针对性指南。** 每个被标记的步骤都会变成一条标准 ALTK-Evolve 格式的候选一致性指南，直接纳入现有的存储和检索流水线。这是一个真实示例，由 GPT-4.1 从 AppWorld 任务 "How many activities are done in my bucket list as per my SimpleNote note?" 的轨迹生成：

> [指南 1] 统计笔记内容中的复选框标记时，使用行锚定的正则匹配，而不是简单的子串计数——笔记标题经常在图例行里重复标记符号。
> [指南 2] 始终核验笔记查询的搜索结果：检查是否有多个匹配，确认找到正确的笔记后再继续。

这里没有任何任务专属的琐碎信息。字符串计数错误和未核验的搜索结果，是在许多 AppWorld 任务中都以高不确定性出现的决策点。这正是重点：分析器针对的是不稳定性，而不是失败——所以它能抓住那些智能体这次碰巧做对、但下次很容易做错的步骤。

[观看 2 分钟 demo](https://www.youtube.com/watch?v=qlp7EzXe8Pg)——五个并行的智能体运行在这个任务上因为对计数策略的不确定而分裂成 3-2；把这些指南放进上下文后再跑：五次全部一致。

## 结果：缩小差距而不损失准确率

我们在 AppWorld `test_normal`（168 个任务）上用 GPT-4.1 的 ReAct 智能体评估：每个任务从一条基线轨迹生成一致性指南，然后在 5 次全新运行上测试。

Mean@5 (%)，汇总——与上文 Pass^5 同一尺度。

**一致性差距约减半。** 汇总 Pass^5 从 53.0% 升到 69.0%，Mean@5 从 77.4% 升到 81.0%，“看起来能干”与“靠得住”之间的差距从 **24.4pp 缩到 12.0pp**。近三分之一的原本不稳定任务，变成了智能体*每一次运行*都能通过的任务。

**中等和困难档获益最大。** Medium +22.9pp（相对 +44%）、Hard +14.3pp（相对 +45%）——相对幅度基本打平，Medium 在绝对值上领先。Easy 提升 +12.2pp，因为它空间最小。这正是一致性指南设计要做的事：找到并稳住那些智能体自身不确定性泄漏到结果中的具体决策点。

**Mean@5 从未下降。** 保住平均准确率是硬性要求，不是锦上添花：一个靠牺牲 Mean@5 来抬升 Pass^5 的系统只是在挪移不可靠性，而不是修复它。在每个难度级别上，平均准确率都保持或提升。

### 指南是可泛化的——它们不是在修补一条轨迹

应用到**同一 AppWorld 场景中不同但相关的任务**——指南挖掘来源场景的另一个变体——一致性指南仍把 Pass^5 提升 **+13.0pp**，只比同任务数字低 3 个百分点。从一次运行导出的指南不只是在修补那次运行；它们捕捉到了某种可迁移的东西。

更有力的证据来自较弱的模型 **gpt-oss-120b**。同任务 Pass^5 从低得多的基线上升 +6.0pp（10.1% → 16.1%）——而且有趣的是，相似任务的泛化数字（+8.7pp）实际上*超过*了同任务增益，说明指南捕捉到的是真正可复用的失败模式，而不是记住了某条轨迹的细节。

## 如果你在上线智能体

- **在 Mean@k 旁边报告 Pass^k。** 平均值分不清一个智能体是可靠还是侥幸；即使 k=3 也会暴露你可能不自知的差距。
- **预期差距随难度扩大。** 最难的那一档，单个平均值最具误导性。
- **别先想到换更大的模型。** 一致性与能力正交。更强的模型抬高 Mean@k；未必缩小一致性差距。
- **诊断不需要判分器也不需要实时回放。** 每个决策步一次额外 LLM 调用（默认采样 k=5 个补全）就够了——不需要 ground truth，不需要对着环境重跑任务。这正是它能用于生产流量的原因——在很多生产场景里，你连一次端到端重放都做不到。

## 试一试

> 试试 ALTK-Evolve——开源仓库现已包含这些实验用到的一致性分析器和一致性指南生成——或阅读 arXiv 技术报告了解完整方法。

如果你也熟悉那种“在自己任务上复现不出来的准确率数字”，我们很想听听你的经历——你自己的智能体中易翻转行为的具体例子，恰恰是塑造我们下一步方向的最佳反馈。[提 issue 或开 discussion](https://github.com/AgentToolkit/altk-evolve)。

## 附录：理解这些指标

- **Mean@k。** 把一个任务跑 *k* 次，报告平均通过率——即大多数基准口中的“准确率”。
- **Pass^k。** 智能体在**全部** *k* 次独立运行中都成功的任务比例。恒 ≤ Mean@k。用户把同一个查询问两遍时体验到的就是它。
- **Pass@k。** *k* 次运行中至少**一次**成功——乐观版的对应物，常见于代码生成论文。
- **一致性差距。** Mean@k − Pass^k，以百分点计。

谢谢，你恰恰落在了我们期望的操作要点上：易翻转的决策步骤本身就应是评估目标。进一步说，知道它们在哪里，还能把评估变成诊断：一致性差距告诉你智能体不可靠，而易翻转步骤告诉你发生在哪、为什么发生。

关于你的发布门禁问题：我们强烈鼓励，k=3 是合理的默认值。给任何想把 Pass^k 作为门禁的人几条建议：

- **固定 k，也不必把 k 推得远高于 3**。Pass^k 随 k 增大而更严格，所以“Pass^3 ≥ X”和“Pass^5 ≥ X”是不同的门槛；选一个并在各版本间保持一致。我们研究用了 k=5，但作为发布门禁，超过 k=3 之后收益递减很快。按我们的经验，多数不稳定任务在前三个运行内至少失败一次，再往后成本线性增长，而对“哪些任务不可靠”的新洞察相对很少。
- **注意样本量**。Pass^k 给每个任务一个全有或全无的结果，所以其精度主要取决于任务数量而非 k；在小任务集上，Pass^k 和 Mean@k 都会很嘈杂。比较版本时逐任务对比，而不是只看汇总分数；在给智能体贴上稳定/不稳定标签前先报告任务数量或区间。

我想更好地理解你结尾那句话。在我们的实验中，我们没有在单条指南之间做选择：对每个新任务，我们注入来自最相似任务导出的指南。很好奇你说的“该注入哪些指南的分歧”会从哪儿产生。
