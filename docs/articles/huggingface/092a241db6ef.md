# CodeGemma——Google 官方发布的代码 LLM

CodeGemma 是 Gemma 开放访问（open-access）版本的模型家族，专门针对代码进行了特化。我们很高兴与 Google 合作发布这一系列模型，让它尽可能触手可及。🤗

CodeGemma 有三种形态：

- 2B 基座模型，专攻填充（infilling）与开放式生成。
- 7B 基座模型，同时用代码填充和自然语言训练。
- 7B 指令模型，可以和用户就代码问题进行对话。

我们与 Google 合作，确保它能与 Hugging Face 生态最佳集成。三个开放访问模型已就绪，可直接在 Hub 上使用。本次随发布一同推出的功能与集成包括：

- [Hub 上的模型](https://huggingface.co/collections/google/codegemma-release-66152ac7b683e2667abdee11)，附带模型卡和许可证。有 transformers 库版本、用于 Google 原始代码库的 checkpoint，以及供社区自行量化的全精度 GGUF 文件。
- Transformers 集成
- Google Cloud 集成
- Inference Endpoints 集成
- 代码基准测试

## 什么是 CodeGemma？

CodeGemma 是 Google 推出的代码专精 LLM 模型家族，基于预训练的 [2B 和 7B Gemma checkpoint](https://huggingface.co/blog/gemma)。CodeGemma 在其之上额外训练了 5000 亿 token，主要为英文语言数据、数学和代码，用以提升逻辑与数学推理能力，适合代码补全和代码生成。

[CodeGemma 2B](https://huggingface.co/google/codegemma-2b) 完全使用代码填充训练，面向快速的代码补全与生成，特别适合对延迟和/或隐私敏感的场景。[CodeGemma 7B](https://huggingface.co/google/codegemma-7b) 的训练数据混合了代码填充数据（80%）和自然语言，既可用于代码补全，也可用于代码与语言的理解和生成。[CodeGemma 7B Instruct](https://huggingface.co/google/codegemma-7b-it) 在 CodeGemma 7B 之上做了指令跟随微调，面向对话式使用，尤其是代码、编程或数学推理相关的话题。所有模型的上下文长度都与前代一致，为 8K token。

### 提示词格式

CodeGemma 2B 和 CodeGemma 7B 通过填充（代码、注释、docstring、import 语句）完成代码补全。CodeGemma 使用中间填充（fill-in-the-middle，FIM）目标训练该任务：提供前缀（prefix）和后缀（suffix）作为补全的上下文。用于分隔输入各部分的是以下特殊 token：

- `<|fim_prefix|>` 位于需要补全内容之前的上下文前面。
- `<|fim_suffix|>` 位于后缀之前。你必须把这个 token 精确放在编辑器中光标所在的位置，因为模型就是在这里进行代码补全。
- `<|fim_middle|>` 是邀请模型执行生成的提示符。

除此之外还有 `<|file_separator|>`，用于提供多文件上下文。使用示例会在后面的“使用 transformers”一节给出。

CodeGemma 7B Instruct 使用与 Gemma 指令微调基座版本相同的提示词格式，遵循如下对话结构：

```
<bos><start_of_turn>user
knock knock<end_of_turn>
<start_of_turn>model
who is there<end_of_turn>
<start_of_turn>user
LaMDA<end_of_turn>
<start_of_turn>model
LaMDA who?<end_of_turn>
```

和 Gemma 一样，复现这一格式最简单的方法是使用 `transformers` 中的 chat template。

下面的代码片段演示如何用 `codegemma-2b` 通过 transformers 做代码补全。它在 `float16` 精度下约需 6 GB 内存，非常适合消费级 GPU 和端侧应用。

```
from transformers import GemmaTokenizer, AutoModelForCausalLM
import torch

model_id = "google/codegemma-2b"
tokenizer = GemmaTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.float16
).to("cuda:0")

prompt = '''\
<|fim_prefix|>import datetime
def calculate_age(birth_year):
    """Calculates a person's age based on their birth year."""
    current_year = datetime.date.today().year
    <|fim_suffix|>
    return age<|fim_middle|>\
'''

inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
prompt_len = inputs["input_ids"].shape[-1]
outputs = model.generate(**inputs, max_new_tokens=100)
print(tokenizer.decode(outputs[0][prompt_len:]))
```

注意 `<|fim_suffix|>` token 出现在编辑器中光标会放置的位置，标记生成的位置。`<|fim_prefix|>` 提供光标之前的上下文，其后直到 `<|fim_middle|>` 的内容是光标之后的补充上下文。如果光标位于文件开头或结尾，两者之一可以为空。

上面的代码可能返回类似下面的内容：

```
age = current_year - birth_year<|file_separator|>test_calculate_age.py
<|fim_suffix|>

    assert calculate_age(1990) == 33
    assert calculate_age(1980) == 43
    assert calculate_age(1970) == 53
    assert calculate_age(1960) == 63
    assert calculate_age(1950) == 73
```

注意正确补全之后还有额外内容。CodeGemma 7B 尤其如此，它更啰嗦，往往在补全后还会给出额外代码或注释。做代码填充时，我们必须忽略 FIM token 或 EOS token 之后出现的一切内容。在 transformers 中可以通过给 `generate` 函数传入终止符列表来提前停止生成，如下所示：

```
FIM_PREFIX = '<|fim_prefix|>'
FIM_SUFFIX = '<|fim_suffix|>'
FIM_MIDDLE = '<|fim_middle|>'
FIM_FILE_SEPARATOR = '<|file_separator|>'

terminators = tokenizer.convert_tokens_to_ids(
    [FIM_PREFIX, FIM_MIDDLE, FIM_SUFFIX, FIM_FILE_SEPARATOR]
)
terminators += [tokenizer.eos_token_id]

outputs = model.generate(
  **inputs,
  max_new_tokens=100,
  eos_token_id=terminators,
)
```

这种情况下，一旦遇到第一个分隔符，生成就立即停止：

```
age = current_year - birth_year<|file_separator|>
```

### 关于精度的说明

原版 CodeGemma checkpoint 以 `bfloat16` 精度发布。如果加载模型时不指定 `torch_dtype`，PyTorch 会将其提升为 `float32`。转换为 `float16` 使用完全没有问题，而且在某些硬件上比 `bfloat16` 快得多。若追求最高精度，建议使用 `bfloat16` 而不是 `float32`。

你也可以自动量化模型，以 8-bit 或 4-bit 模式加载。CodeGemma 7B 的 4-bit 加载只需约 9 GB 显存，因此大多数消费级显卡以及 Google Colab 的所有 GPU 都能运行。以 4-bit 加载生成 pipeline 的方法如下：

```
pipeline = pipeline(
    "text-generation",
    model=model,
    model_kwargs={
        "torch_dtype": torch.float16,
        "quantization_config": {"load_in_4bit": True}
    },
)
```

## Inference Endpoints 集成

你可以将 CodeGemma 部署到 Hugging Face 的 [Inference Endpoints](https://ui.endpoints.huggingface.co/new?repository=google/codegemma-2b&vendor=aws&region=us-east-1&accelerator=gpu&instance_size=2xlarge&task=text-generation&no_suggested_compute=true&tgi=true&tgi_max_batch_total_tokens=1024000&tgi_max_total_tokens=32000)，其后端是 Text Generation Inference。[Text Generation Inference](https://github.com/huggingface/text-generation-inference) 是 Hugging Face 开发的生产级推理容器，用于轻松部署大语言模型。它支持连续批处理（continuous batching）、token 流式输出、多 GPU 张量并行加速推理、生产级日志与追踪，并以 Apache 2 许可证分发。

要部署 CodeGemma 模型，前往[模型页面](https://huggingface.co/google/codegemma-2b)并点击 [Deploy -> Inference Endpoints](https://ui.endpoints.huggingface.co/new?repository=google/codegemma-2b) 组件。你可以在这篇先前的博客中了解更多关于 [用 Hugging Face Inference Endpoints 部署 LLM](https://huggingface.co/blog/inference-endpoints-llm) 的内容。注意 T4 不支持 `bfloat16` 格式，因此需要选择其他 GPU。

```
from huggingface_hub import InferenceClient

client = InferenceClient(model=IE_ENDPOINT)

prompt = """\
<|fim_prefix|>import <|fim_middle|>

if __name__ == '__main__':
  sys.exit(0)<|fim_middle|>\
"""

client.text_generation(prompt=prompt)
```
