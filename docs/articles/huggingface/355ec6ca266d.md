# 用 NVIDIA NIM 加速 Hugging Face 上的 LLM 世界

企业 + 文章

发布于 2025 年 7 月 21 日








AI 构建者希望能自由选用最新的[大语言模型](https://www.nvidia.com/en-us/glossary/large-language-models/) (LLM) 架构及专用变体，用于 [AI agents](https://www.nvidia.com/en-us/glossary/ai-agents/) 和其他应用，但应对这种多样性会拖慢测试与部署流程。尤其是，要跨各类 LLM 和不同服务需求达到最佳性能，需要管理和优化不同的推理软件框架，这成为一项耗时的瓶颈，使高性能 AI 应用难以尽快交付到最终用户手中。

NVIDIA AI 的客户与生态合作伙伴借助 [NVIDIA NIM](https://developer.nvidia.com/nim) 推理微服务，简化在 NVIDIA 加速基础设施上部署最新 AI 模型的流程，其中包括来自 NVIDIA、Meta、Mistral AI、Google 以及数百家其他创新模型构建者的 LLM、多模态模型和领域专用模型。我们已经看到，客户与合作伙伴凭借这种简化、可靠的模型部署方式，能够更快地交付更多创新成果；而今天，我们很高兴能借助 NIM 开放 Hugging Face 上超过 100,000 个 LLM，实现快速、可靠的部署。

## 用单一 NIM 微服务部署广泛的 LLM

NIM 现在提供单一的 docker 容器，用于部署由 NVIDIA 及社区的领先推理框架所支持的各类 LLM，包括 NVIDIA TensorRT-LLM、vLLM 和 SGLang。当把一个 LLM 提供给 NIM 容器时，它会自动执行若干部署与性能优化步骤，无需手动配置：

| LLM 适配阶段 | NIM 的作用 |
| --- | --- |
| *模型分析* | NIM 自动识别模型的格式，包括 Hugging Face 模型、TensorRT-LLM 检查点或预构建的 TensorRT-LLM 引擎，确保兼容性。 |
| *架构与量化检测* | 识别模型的架构（例如 Llama、Mistral）和量化格式（例如 FP16、FP8、INT4）。 |
| *后端选择* | 基于上述分析，NIM 选择一个推理后端（NVIDIA TensorRT-LLM、vLLM 或 SGLang）。 |
| *性能设置* | NIM 为所选模型和后端应用预配置的设置，然后启动推理服务器，减少手动调优工作。 |

表 1. NVIDIA NIM 的 LLM 适配阶段与功能

这个单一的 NIM 容器支持常见的 LLM 权重格式，包括：

- **Hugging Face Transformers 检查点**：带有 `.safetensors` 文件的 LLM 可以直接从 Hugging Face 仓库部署，无需复杂的格式转换。
- **GGUF 检查点：**受支持模型架构的量化 GGUF 检查点可以直接从 HuggingFace 或本地下载的文件部署
- **TensorRT-LLM 检查点**：打包在 `trtllm_ckpt` 目录中、针对 TensorRT-LLM 优化过的模型可以部署。
- **TensorRT-LLM 引擎**：`trtllm_engine` 目录中预构建的 TensorRT-LLM 引擎可用于在 NVIDIA GPU 上获得峰值性能。

## 开始使用

要使用 NIM，请确保你的环境具备：装有适当驱动（CUDA 12.1+）的 NVIDIA GPU、已安装 Docker、用于获取 NIM Docker 镜像的 [NVIDIA NGC](https://catalog.ngc.nvidia.com/) 账户和 API Key，以及用于需要身份验证的模型的 Hugging Face 账户和 API token。有关环境前提条件的更多信息，请参阅 [NIM 文档](https://docs.nvidia.com/nim/large-language-models/latest/getting-started.html)。

环境搭建包括设置环境变量和创建持久化缓存目录。请确保 `nim_cache` 目录具有正确的 Unix 权限，最好由启动 Docker 容器的同一个 Unix 用户拥有，以避免权限问题。命令使用 `-u $(id -u)` 来管理这一点。

为方便使用，我们把一些常用信息存入环境变量。

```
# A variable for storing the NIM docker image specification
NIM_IMAGE=llm-nim
# Populate with your Hugging Face API token.
HF_TOKEN=<your_huggingface_token>
```

### 示例 1：部署模型

以 Codestral-22B 为例演示如何从 Hugging Face 部署 LLM：

```
docker run --rm --gpus all \
  --shm-size=16GB \
  --network=host \
  -u $(id -u) \
  -v $(pwd)/nim_cache:/opt/nim/.cache \
  -v $(pwd):$(pwd) \
  -e HF_TOKEN=$HF_TOKEN \
  -e NIM_TENSOR_PARALLEL_SIZE=1 \
  -e NIM_MODEL_NAME="hf://mistralai/Codestral-22B-v0.1" \
  $NIM_IMAGE
```

对于本地下载的模型，将 `NIM_MODEL_NAME` 指向该路径并挂载目录：

```
docker run --rm --gpus all \
  --shm-size=16GB \
  --network=host \
  -u $(id -u) \
  -v $(pwd)/nim_cache:/opt/nim/.cache \
  -v $(pwd):$(pwd) \
  -v /path/to/model/dir:/path/to/model/dir \
  -e HF_TOKEN=$HF_TOKEN \
  -e NIM_TENSOR_PARALLEL_SIZE=1 \
  -e NIM_MODEL_NAME="/path/to/model/dir/mistralai-Codestral-22B-v0.1" \
  $NIM_IMAGE
```

部署模型时，可以随时查看输出日志，了解 NIM 在模型部署过程中所做的选择。已部署的模型可在 `http://localhost:8000`, 其 API endpoint 位于 [`http://localhost:8000/docs`](http://localhost:8000/docs)。

底层引擎还提供了其他参数。你可以在容器内运行 nim-run --help 查看这类参数的完整列表，如下所示。

```
docker run --rm --gpus all \
  --network=host \
  -u $(id -u) \
  $NIM_IMAGE nim-run --help
```

### 示例 2：指定后端

要查看兼容的后端或选择特定后端，请使用 `list-model-profiles`：

```
docker run --rm --gpus all \
  --shm-size=16GB \
  --network=host \
  -u $(id -u) \
  -v $(pwd)/nim_cache:/opt/nim/.cache \
  -v $(pwd):$(pwd) \
  -e HF_TOKEN=$HF_TOKEN \
  $NIM_IMAGE list-model-profiles --model "hf://meta-llama/Llama-3.1-8B-Instruct"
```

该命令会列出兼容的 profile，包括适用于 LoRA adapter 的 profile。要使用 vLLM 等特定后端部署，请设置 `NIM_MODEL_PROFILE` 环境变量，其值取自 `list-model-profiles` 的输出：

```
docker run --rm --gpus all \
  --shm-size=16GB \
  --network=host \
  -u $(id -u) \
  -v $(pwd)/nim_cache:/opt/nim/.cache \
  -v $(pwd):$(pwd) \
  -e HF_TOKEN=$HF_TOKEN \
  -e NIM_TENSOR_PARALLEL_SIZE=1 \
  -e NIM_MODEL_NAME="hf://meta-llama/Llama-3.1-8B-Instruct" \
  -e NIM_MODEL_PROFILE="e2f00b2cbfb168f907c8d6d4d40406f7261111fbab8b3417a485dcd19d10cc98" \
  $NIM_IMAGE
```

### 示例 3：量化模型部署

NIM 让量化模型的部署变得简单。它会自动检测量化格式（例如 GGUF、AWQ），并使用标准部署命令选择合适的后端：

```
# Choose a quantized model and populate the MODEL variable, for example:
# MODEL="hf://modularai/Llama-3.1-8B-Instruct-GGUF"
# or
# MODEL="hf://Qwen/Qwen2.5-14B-Instruct-AWQ"
docker run --rm --gpus all \
  --shm-size=16GB \
  --network=host \
  -u $(id -u) \
  -v $(pwd)/nim_cache:/opt/nim/.cache \
  -v $(pwd):$(pwd) \
  -e HF_TOKEN=$HF_TOKEN \
  -e NIM_TENSOR_PARALLEL_SIZE=1 \
  -e NIM_MODEL_NAME=$MODEL \
  $NIM_IMAGE
```

对于高级用户，NIM 支持通过环境变量进行自定义，例如用 `NIM_MAX_MODEL_LEN` 设置上下文长度。对于大型 LLM，`NIM_TENSOR_PARALLEL_SIZE` 可启用多 GPU 部署。请确保向 Docker 传入 `--shm-size=<shared memory size>`，以支持多 GPU 通信。

NIM 容器支持由 NVIDIA TensorRT-LLM、vLLM 和 SGLang 支撑的广泛 LLM，包括 Hugging Face 上的热门 LLM 及专用变体。有关支持的 LLM 的更多详情，请参阅[文档](https://docs.nvidia.com/nim/large-language-models/latest/supported-llm-agnostic-architectures.html)。

## 用 Hugging Face 和 NVIDIA 构建

NIM 旨在简化 AI 模型在 NVIDIA 加速基础设施上的部署，为高性能 AI 构建者和企业 AI 团队加快创新速度、缩短价值实现时间。我们期待 Hugging Face 社区的参与和反馈。

在 [build.nvidia.com](https://build.nvidia.com/nvidia/bring-llm-to-nim) 的 NVIDIA 托管计算环境中，通过开发者示例即可开始上手。
