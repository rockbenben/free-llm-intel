# 在 Vertex AI 上部署 🤗 ViT

在之前的文章里，我们演示了如何把 🤗 Transformers 的 [Vision Transformers（ViT）模型](https://huggingface.co/docs/transformers/main/en/model_doc/vit)[在本地](https://huggingface.co/blog/tf-serving-vision)以及[在 Kubernetes 集群上](https://huggingface.co/blog/deploy-tfserving-kubernetes)部署。这篇文章将带你把同一个模型部署到 [Vertex AI 平台](https://cloud.google.com/vertex-ai)上。你能达到与基于 Kubernetes 的部署相同的可扩展性，但代码量大大减少。

本文建立在上面链接的两篇前作之上，如果你还没看过，建议先读一下。

完整的实操示例可以在文章开头链接的 Colab Notebook 中找到。

## 什么是 Vertex AI？

按 [Google Cloud](https://www.youtube.com/watch?v=766OilR6xWc) 的说法：

> Vertex AI 提供覆盖整个 ML 工作流的工具，支持不同的模型类型和各种 ML 专业水平的用户。

在模型部署方面，Vertex AI 以统一的 API 设计提供了几项重要能力：

- 身份认证
- 基于流量的自动扩缩容
- 模型版本管理
- 同一模型不同版本之间的流量分配
- 限流
- 模型监控与日志
- 支持在线与批量预测

对于 TensorFlow 模型，它提供了大量开箱即用的工具，本文就会用到。但对 PyTorch、[scikit-learn](https://codelabs.developers.google.com/vertex-cpr-sklearn) 等其他框架也有类似的支持（[PyTorch 示例](https://cloud.google.com/blog/topics/developers-practitioners/pytorch-google-cloud-how-deploy-pytorch-models-vertex-ai)）。

要使用 Vertex AI，你需要一个[启用了计费的 Google Cloud Platform (GCP) 项目](https://cloud.google.com/billing/docs/how-to/modify-project)，并开通以下服务：

- Vertex AI
- Cloud Storage

## 回顾待服务的模型

你将沿用前两篇文章中使用的[ TensorFlow 版 ViT B/16 模型](https://huggingface.co/docs/transformers/main/en/model_doc/vit#transformers.TFViTForImageClassification)。序列化模型时嵌入了对应的预处理和后处理操作，以减少[训练-服务偏差（training-serving skew）](https://developers.google.com/machine-learning/guides/rules-of-ml#:~:text=Training%2Dserving%20skew%20is%20a,train%20and%20when%20you%20serve.)。详细讨论请看[第一篇文章](https://huggingface.co/blog/tf-serving-vision)。最终序列化的 `SavedModel` 的签名如下：

```
The given SavedModel SignatureDef contains the following input(s):
  inputs['string_input'] tensor_info:
      dtype: DT_STRING
      shape: (-1)
      name: serving_default_string_input:0
The given SavedModel SignatureDef contains the following output(s):
  outputs['confidence'] tensor_info:
      dtype: DT_FLOAT
      shape: (-1)
      name: StatefulPartitionedCall:0
  outputs['label'] tensor_info:
      dtype: DT_STRING
      shape: (-1)
      name: StatefulPartitionedCall:1
Method name is: tensorflow/serving/predict
```

模型接受图像的 [base64 编码](https://www.base64encode.org/)字符串作为输入，执行预处理、运行推理，最后完成后处理步骤。对字符串做 base64 编码是为了防止网络传输过程中发生修改。预处理包括把输入图像缩放到 224x224、归一化到 `[-1, 1]` 范围，并转置为 `channels_first` 内存布局。后处理则把预测的 logits 映射为字符串标签。

要在 Vertex AI 上部署，你需要把模型产物放在一个 [Google Cloud Storage (GCS) 存储桶](https://cloud.google.com/storage/docs/json_api/v1/buckets)里。配套的 Colab Notebook 演示了如何创建 GCS 存储桶并把模型产物存入其中。

## Vertex AI 的部署工作流

下图给出了在 Vertex AI 上部署已训练好的 TensorFlow 模型的流程概览。

[![](https://huggingface.co/blog/assets/97_vertex_ai/image7.png)](https://huggingface.co/blog/assets/97_vertex_ai/image7.png)

接下来谈谈 Vertex AI Model Registry 和 Endpoint 是什么。

### Vertex AI Model Registry

Vertex AI Model Registry 是一个全托管的机器学习模型注册中心。"全托管"有两层含义：第一，你不用操心模型存储在哪里、怎么存；第二，它负责管理同一模型的不同版本。

这些能力对生产环境的机器学习非常重要。构建一个保证高可用和安全性的模型注册中心并不容易。而且我们往往无法掌控黑盒机器学习模型的内部，所以经常需要把当前模型回滚到某个历史版本。借助 Vertex AI Model Registry，这些都能轻松实现。

目前支持的模型类型包括 TensorFlow 的 `SavedModel`、scikit-learn 和 XGBoost。

### Vertex AI Endpoint

从用户视角看，Vertex AI Endpoint 只是提供一个接收请求、返回响应的端点。但它在底层为机器学习运维人员提供了大量可配置项。你可以选择以下配置：

- 模型版本
- VM 规格（CPU、内存、加速器）
- 计算节点的最小/最大数量
- 流量分配比例
- 模型监控窗口长度及其目标
- 预测请求采样率

## 执行部署

[`google-cloud-aiplatform`](https://pypi.org/project/google-cloud-aiplatform/) Python SDK 提供了简单的 API 来管理 Vertex AI 上部署的生命周期。它分为四步：

- 上传模型
- 创建端点
- 把模型部署到端点
- 发起预测请求

在这些步骤中，你会需要 `google-cloud-aiplatform` Python SDK 里的 `ModelServiceClient`、`EndpointServiceClient` 和 `PredictionServiceClient` 模块来与 Vertex AI 交互。

[![](https://huggingface.co/blog/assets/97_vertex_ai/image3.png)](https://huggingface.co/blog/assets/97_vertex_ai/image3.png)

**1.** 工作流的第一步是把 `SavedModel` 上传到 Vertex AI 的模型注册中心：

```
tf28_gpu_model_dict = {
    "display_name": "ViT Base TF2.8 GPU model",
    "artifact_uri": f"{GCS_BUCKET}/{LOCAL_MODEL_DIR}",
    "container_spec": {
        "image_uri": "us-docker.pkg.dev/vertex-ai/prediction/tf2-gpu.2-8:latest",
    },
}
tf28_gpu_model = (
    model_service_client.upload_model(parent=PARENT, model=tf28_gpu_model_dict)
    .result(timeout=180)
    .model
)
```

逐段解读这段代码：

- `GCS_BUCKET` 是存放模型产物的 GCS 存储桶路径（例如 `gs://hf-tf-vision`）。
- 在 `container_spec` 中，你提供用于对外提供预测服务的 Docker 镜像 URI。Vertex AI 提供了服务 TensorFlow 模型的[预构建镜像](https://huggingface.co/blog/(https://cloud.google.com/vertex-ai/docs/predictions/pre-built-containers))，但使用其他框架时也可以用自定义 Docker 镜像（[示例](https://cloud.google.com/blog/topics/developers-practitioners/pytorch-google-cloud-how-deploy-pytorch-models-vertex-ai)）。
- `model_service_client` 是一个 [`ModelServiceClient`](https://cloud.google.com/python/docs/reference/aiplatform/latest/google.cloud.aiplatform_v1.services.model_service.ModelServiceClient) 对象，暴露了向 Vertex AI Model Registry 上传模型的方法。
- `PARENT` 设置为 `f"projects/{PROJECT_ID}/locations/{REGION}"`，让 Vertex AI 确定模型在 GCP 内的作用范围。

**2.** 然后创建一个 Vertex AI Endpoint：

```
tf28_gpu_endpoint_dict = {
    "display_name": "ViT Base TF2.8 GPU endpoint",
}
tf28_gpu_endpoint = (
    endpoint_service_client.create_endpoint(
        parent=PARENT, endpoint=tf28_gpu_endpoint_dict
    )
    .result(timeout=300)
    .name
)
```

这里用到的 `endpoint_service_client` 是一个 [`EndpointServiceClient`](https://cloud.google.com/vertex-ai/docs/samples/aiplatform-create-endpoint-sample) 对象，用它来创建和配置 Vertex AI Endpoint。

**3.** 接下来就是真正的部署了！

```
tf28_gpu_deployed_model_dict = {
    "model": tf28_gpu_model,
    "display_name": "ViT Base TF2.8 GPU deployed model",
    "dedicated_resources": {
        "min_replica_count": 1,
        "max_replica_count": 1,
        "machine_spec": {
            "machine_type": DEPLOY_COMPUTE, # "n1-standard-8"
            "accelerator_type": DEPLOY_GPU, # aip.AcceleratorType.NVIDIA_TESLA_T4
            "accelerator_count": 1,
        },
    },
}

tf28_gpu_deployed_model = endpoint_service_client.deploy_model(
    endpoint=tf28_gpu_endpoint,
    deployed_model=tf28_gpu_deployed_model_dict,
    traffic_split={"0": 100},
).result()
```

这里把你上传到 Vertex AI Model Registry 的模型和上面创建的 Endpoint 串了起来。先在 `tf28_gpu_deployed_model_dict` 下定义部署配置。

在 `dedicated_resources` 下配置了：

- `min_replica_count` 和 `max_replica_count`，负责部署的自动扩缩容。
- `machine_spec` 定义部署硬件的配置：`machine_type` 是运行 Docker 镜像所用的基础机型，底层自动扩缩容器会根据流量负载对它进行伸缩。可从[支持的机型](https://cloud.google.com/vertex-ai/docs/predictions/configure-compute#machine-types)中选择一种。`accelerator_type` 是执行推理所用的硬件加速器。`accelerator_count` 表示每个副本挂载的加速器数量。

**注意**，在 Vertex AI 上部署模型并不强制要求提供加速器。

接下来按上述配置部署端点：

```
tf28_gpu_deployed_model = endpoint_service_client.deploy_model(
    endpoint=tf28_gpu_endpoint,
    deployed_model=tf28_gpu_deployed_model_dict,
    traffic_split={"0": 100},
).result()
```

注意流量分配（traffic split）的定义方式。如果模型有多个版本，你可以定义一个字典：键表示模型版本，值表示该版本应承接的流量百分比。

有了 Model Registry 和管理 Endpoint 的专用[界面](https://console.cloud.google.com/vertex-ai/endpoints)，Vertex AI 让你能轻松掌控部署的各个关键方面。

Vertex AI 完成部署大约需要 15 到 30 分钟。完成后，你就能在[控制台](https://console.cloud.google.com/vertex-ai/endpoints)上看到它。

## 进行预测

如果部署成功，你可以向已部署的 Endpoint 发起预测请求来测试。

首先，准备一个 base64 编码的图像字符串：

```
import base64
import tensorflow as tf

image_path = tf.keras.utils.get_file(
    "image.jpg", "http://images.cocodataset.org/val2017/000000039769.jpg"
)
bytes = tf.io.read_file(image_path)
b64str = base64.b64encode(bytes.numpy()).decode("utf-8")
```

**4.** 下面这个工具函数先准备一个实例列表（这里只有一个实例），然后使用类型为 [`PredictionServiceClient`](https://cloud.google.com/python/docs/reference/automl/latest/google.cloud.automl_v1beta1.services.prediction_service.PredictionServiceClient) 的预测服务客户端。`serving_input` 是被服务模型的输入签名键名。本例中 `serving_input` 是 `string_input`，可以从上面展示的 `SavedModel` 签名输出中核实。

```
from google.protobuf import json_format
from google.protobuf.struct_pb2 import Value

def predict_image(image, endpoint, serving_input):
    # The format of each instance should conform to
    # the deployed model's prediction input schema.
    instances_list = [{serving_input: {"b64": image}}]
    instances = [json_format.ParseDict(s, Value()) for s in instances_list]

    print(
        prediction_service_client.predict(
            endpoint=endpoint,
            instances=instances,
        )
    )

predict_image(b64str, tf28_gpu_endpoint, serving_input)
```

对于在 Vertex AI 上部署的 TensorFlow 模型，请求载荷需要按特定格式组织。对 ViT 这类处理图像等二进制数据的模型，需要对其进行 base64 编码。按[官方指南](https://cloud.google.com/vertex-ai/docs/predictions/online-predictions-custom-models#encoding-binary-data)，每个实例的请求载荷应形如：

```
{serving_input: {"b64": base64.b64encode(jpeg_data).decode()}}
```

`predict_image()` 工具函数就是按这一规范来构造请求载荷的。

如果一切顺利，调用 `predict_image()` 时你会得到类似这样的输出：

```
predictions {
  struct_value {
    fields {
      key: "confidence"
      value {
        number_value: 0.896659553
      }
    }
    fields {
      key: "label"
      value {
        string_value: "Egyptian cat"
      }
    }
  }
}
deployed_model_id: "5163311002082607104"
model: "projects/29880397572/locations/us-central1/models/7235960789184544768"
model_display_name: "ViT Base TF2.8 GPU model"
```

不过请注意，这并不是使用 Vertex AI Endpoint 获取预测的唯一方式。打开 Endpoint 控制台并选中你的端点，它会展示两种获取预测的方式：

[![](https://huggingface.co/blog/assets/97_vertex_ai/image4.png)](https://huggingface.co/blog/assets/97_vertex_ai/image4.png)

也可以不用 Vertex AI SDK，绕过 cURL 请求以编程方式获取预测。想了解更多信息请参考[这个 notebook](https://github.com/sayakpaul/deploy-hf-tf-vision-models/blob/main/hf_vision_model_vertex_ai/test-vertex-ai-endpoint.ipynb)。

学完如何用 Vertex AI 部署 TensorFlow 模型之后，再来看看 Vertex AI 提供的一些实用功能，它们能帮你更深入地了解你的部署。

## 用 Vertex AI 做监控

Vertex AI 还能让你零配置地监控模型。在 Endpoint 控制台上，你可以看到端点的性能指标和所分配资源的利用率。

[![](https://huggingface.co/blog/assets/97_vertex_ai/image8.png)](https://huggingface.co/blog/assets/97_vertex_ai/image8.png)

[![](https://huggingface.co/blog/assets/97_vertex_ai/image6.png)](https://huggingface.co/blog/assets/97_vertex_ai/image6.png)

从上图可以看到，加速器占空比（利用率）在很短一段时间内达到了约 100%，看起来非常舒服；其余时间没有请求要处理，因此处于空闲状态。

这类监控能帮你快速了解当前部署的 Endpoint 状况并按需调整。还可以申请对模型解释（explanation）进行监控，详情见[这里](https://cloud.google.com/vertex-ai/docs/explainable-ai/overview)。

## 本地负载测试

我们用 [Locust](https://locust.io/) 做了一次本地负载测试，以更好地了解 Endpoint 的极限。下表汇总了请求统计：

[![](https://huggingface.co/blog/assets/97_vertex_ai/image5.png)](https://huggingface.co/blog/assets/97_vertex_ai/image5.png)

## 价格

你可以用 [GCP 成本估算器](https://cloud.google.com/products/calculator)估算使用成本，精确的每小时价格表在[这里](https://cloud.google.com/vertex-ai/pricing#custom-trained_models)。值得一提的是，只有节点在处理实际预测请求时才会计费，并且要分别按有无 GPU 计算价格。

对于自训练模型的 Vertex Prediction，可以选择 [`n1-standard-2` 到 `n1-highcpu-32`](https://cloud.google.com/vertex-ai/pricing#custom-trained_models) 的 N1 机型。本文使用了 `n1-standard-8`，配备 8 个 vCPU 和 32GB 内存。

| **机型** | **每小时价格（美元）** |
| --- | --- |
| n1-standard-8 (8vCPU, 30GB) | $ 0.4372 |

此外，当你在计算节点上挂载加速器时，会根据所选加速器类型额外计费。本文使用了 `NVIDIA_TESLA_T4`，但几乎所有现代加速器（包括 TPU）都受支持。更多信息见[这里](https://cloud.google.com/vertex-ai/pricing#custom-trained_models)。

| **加速器类型** | **每小时价格（美元）** |
