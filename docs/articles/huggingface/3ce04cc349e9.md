# AI Secure LLM 安全排行榜简介

Chenhui Zhang (danielz01, guest)

Chulin Xie (alphapav, guest)

Mintong Kang (Cometkmt, guest)

Chejian Xu (chejian, guest)

Bo Li (BoLi-aisecure, guest)

本文也有英文版本：[English](https://huggingface.co/blog/leaderboard-decodingtrust)。

LLM 已被广泛采用，在真正大规模部署之前，弄清它们在各种场景下的安全性与风险至关重要。特别是，美国白宫发布了关于安全、可靠、可信 AI 的行政令；欧盟《AI 法案》也对高风险 AI 系统强调了强制性要求。与监管配套，提供技术手段来评估 AI 系统风险、提升其安全性，并可能给出带安全保障的对齐 AI 系统，同样重要。

因此，2023 年我们在 [Secure Learning Lab](https://boli.cs.illinois.edu/) 推出了 [DecodingTrust](https://decodingtrust.github.io/)——首个专门评估 LLM 可信性的全面统一评测平台。（该工作获得了 [NeurIPS 2023 杰出论文奖](https://blog.neurips.cc/2023-12-11/announcing-the-neurips-2023-paper-awards/)。）

DecodingTrust 提供了覆盖八个可信维度的多角度评测框架：毒性（toxicity）、刻板印象偏见、对抗鲁棒性、OOD 鲁棒性、对抗性示例下的鲁棒性、隐私、机器伦理和公平性。具体而言，DecodingTrust 1) 提供全面的可信维度以实现整体可信性评估；2) 为每个维度定制新型红队（red-teaming）算法，支持对 LLM 的深度测试；3) 支持在各种云环境便捷安装；4) 基于可信性为开源和闭源模型提供完整排行榜；5) 提供失败案例研究，增强透明度和理解；6) 提供端到端演示和详细的模型评测报告，方便实际使用。

今天，我们很高兴宣布发布全新的 [LLM Safety Leaderboard](https://huggingface.co/spaces/AI-Secure/llm-trustworthy-leaderboard)，它聚焦 LLM 的安全评估，基于 [HF leaderboard template](https://huggingface.co/demo-leaderboard-backend) 构建。

## 红队（Red-teaming）评估

DecodingTrust 为每个评估维度提供了多种新型红队方法来做压力测试。详细的测试场景和指标见我们论文的 [Figure 3](https://arxiv.org/html/2306.11698v4/extracted/5331426/figures/taxonomy.main.png)。

毒性方面，我们设计优化算法并驱动提示生成模型，生成有挑战性的用户提示。我们还设计了 33 个有挑战性的系统提示，如角色扮演、任务重述、以程序身份回复等，以便在不同场景下评估。然后用 Perspective API 在给定挑战提示的情况下评估生成内容的毒性分数。

刻板印象偏见方面，我们收集了 24 个人口群体、16 个刻板印象主题，每个主题配三种提示变体来评估模型偏见。我们对模型提示 5 次并取平均值作为模型偏见分数。

对抗鲁棒性方面，我们针对三个开源模型（Alpaca、Vicuna、StableVicuna）构造了五种对抗攻击算法。使用攻击开源模型生成的对抗数据，我们在五种不同任务上评估各模型的鲁棒性。

OOD 鲁棒性方面，我们设计了不同的风格变换、知识变换等，用于评估以下两种情况的模型表现：1) 输入风格转换为较少见的风格（如莎士比亚风格或诗歌体）；2) 回答问题所需的知识不在 LLM 的训练数据中。

对抗性示例鲁棒性方面，我们设计了包含误导信息的示例，如反事实样本、伪相关和后门攻击，以评估模型在不同任务上的表现。

隐私方面，我们提供不同层级的评估，包括 1) 预训练数据中的隐私泄露，2) 对话过程中的隐私泄露，3) LLM 对隐私相关词汇和事件的理解。特别是针对 1) 和 2)，我们设计了多种隐私攻击方式。例如，用不同格式的提示引导 LLM 输出邮箱、信用卡号等敏感信息。

伦理方面，我们利用 ETHICS 和 Jiminy Cricket 数据集设计了越狱（jailbreak）系统提示和用户提示，用于评估模型对不道德行为的识别能力。

公平性方面，我们在不同任务中控制不同的受保护属性来生成有挑战性的问题，评估模型在 zero-shot 和 few-shot 设定下的公平性。

## 论文的一些关键发现

总体而言，我们发现：

- GPT-4 比 GPT-3.5 更脆弱，
- 没有任何单个 LLM 能在所有可信维度上持续优于其他模型，
- 不同可信维度之间存在权衡，
- LLM 理解不同隐私相关词汇的能力不同。例如，用 "in confidence" 提示 GPT-4 时它可能不泄露隐私信息，而用 "confidentially" 提示时它就可能泄露。
- 在各种可信维度下，LLM 都容易受到对抗性或误导性提示与指令的影响。

## 如何提交你的模型参与评估

首先，把模型权重转成 safetensors。这是存储权重的新格式，更安全，加载和使用也更快。这还能让我们在总表里展示你模型的参数量！

然后，确保你能用 AutoClasses 加载模型和分词器：

```
from transformers import AutoConfig, AutoModel, AutoTokenizer
config = AutoConfig.from_pretrained("your model name")
model = AutoModel.from_pretrained("your model name")
tokenizer = AutoTokenizer.from_pretrained("your model name")
```

如果这一步失败，请按错误信息调试你的模型再提交。很可能是模型的上传方式有问题。

注意：

- 确保你的模型是公开的！
- 我们暂不支持需要 `use_remote_code=True` 的模型。我们正在开发，敬请关注！

最后，使用[排行榜里的 "Submit here!" 面板](https://huggingface.co/spaces/AI-Secure/llm-trustworthy-leaderboard)提交你的模型参与评估！
