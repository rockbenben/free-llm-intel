# GaLore：推进消费级硬件上的大模型训练

GaLore 融入大语言模型（LLM）训练，是深度学习领域的一大进步——无论在内存效率还是 AI 研究平民化方面。它让十亿参数级模型可以在消费级硬件上训练、缩减优化器状态的内存占用，并运用先进的投影矩阵技术，为算力资源有限的研究者和实践者打开了新天地。

## 用消费级硬件扩展 LLM

GaLore 能够支持在 NVIDIA RTX 4090 这类消费级 GPU 上训练最多 70 亿参数的模型（例如基于 Llama 架构的模型），这是开创性的。实现方式，是大幅削减训练过程中优化器状态和梯度通常伴随的内存需求。其做法是利用深度神经网络梯度的天然低秩结构，施加投影来降低需要存储和操控的数据维度。

## 优化器状态的内存效率

优化器状态——尤其在 Adam 这类自适应优化算法中——占据了模型训练内存footprint的很大一部分。GaLore 的做法是在优化器处理梯度之前，先把梯度投影到更低维的子空间。这不仅降低了存储这些状态所需的内存，还保持了优化过程的有效性。

内存节省非常可观——[据作者报告](https://x.com/AnimaAnandkumar/status/1765613815146893348?s=20)「训练期间存储优化器状态的内存**减少超过 82.5%**」，这让在相同内存约束下训练更大的模型或使用更大的批次成为可能。如果再配上 8-bit 精度优化器，节省还能更夸张。

## 子空间切换与高级投影技术

GaLore  effective 的关键组件之一是其动态子空间切换机制：模型在训练全程可以在不同低秩子空间之间穿行。这保证模型不会被禁锢在参数空间的有限角落，保留了全参数学习的能力。何时、如何切换子空间是重中之重——切换频率要在保持稳定的优化轨迹与适应梯度低秩结构的演化之间取得平衡。

能够根据梯度结构变化动态调整这些投影，是 GaLore 武器库里的一件利器，让我们对训练大模型时内存-优化之间不可避免的权衡有更精细的掌控。

## GaLore 与 8-bit 优化器结合

GaLore 与 8-bit 精度优化器的组合，是一种在最大化内存效率的同时保持训练过程完整性与性能协同。8-bit 优化器通过量化优化器状态来压缩内存footprint。与 GaLore 的投影机制配合使用时，就得到一个内存极其高效的训练方案，且不牺牲模型准确率或收敛速度。

这种组合在内存成为关键瓶颈的场景中尤其有效，比如在消费级硬件上训练大模型，或在内存受限的环境中部署模型。它让同样的硬件约束内可以使用更复杂的模型和更大的数据集，把有限资源的可能性边界再往外推。

## 实现细节

把 8-bit 优化器与 GaLore 结合用于训练大语言模型，涉及把梯度、权重和优化器状态量化为 8-bit 表示。这个量化过程大幅降低内存footprint，使同样的内存约束下能训练更大的模型或使用更大的批次。这套集成的算法细节包含几个关键步骤，其中一些若能原生 CUDA 实现可以获得可观的效率增益。GaLore 打开了新的可能：把这些技术与量化、矩阵的专用参数化更紧密地整合，还能进一步降低内存用量。我们目前正在 bitsandbytes 库中探索这个方向。

### 8-bit 优化与 GaLore 的算法概览

**梯度投影**：GaLore 用投影矩阵把全精度梯度投影到低秩子空间。这一步降低梯度维度，随后梯度被量化为 8-bit 格式。

**量化**：投影后的梯度连同模型权重和优化器状态（如 Adam 的滑动平均）一起，从 32 位浮点量化为 8 位整数表示。这涉及把浮点值缩放到 8-bit 范围并四舍五入到最近的整数。

**优化器更新**：用 8-bit 量化后的梯度更新模型权重。这一步包括把梯度反量化回浮点格式、应用优化器的更新规则（如 Adam 的矩更新和参数调整），然后把更新后的优化器状态重新量化为 8-bit 存储。

**反量化与权重更新**：8-bit 量化权重会被反量化为浮点表示以便处理，但由于取值范围受限，它仍保有量化形式固有的 8-bit 精度。之所以需要这一步，是因为 PyTorch 等框架的标准操作不支持 8 位整数，而且这样的整数权重无法承载梯度。这种做法虽然不会天然提升准确率，但让量化权重在当前深度学习库的约束下得以实际应用和计算梯度。注意，在反量化之后、应用权重更新之前，GaLore 还会再做一次投影，把反量化的低秩更新投影回原始空间。

## 在 Hugging Face Transformers 中使用

要在 Hugging Face transformers 库中使用 GaLore 优化器，首先要升级到支持 GaLore 优化器的版本：可以安装最新版（`pip install transformers>=4.39.0`），也可以从源码安装 transformers。

然后用 `pip install galore-torch` 安装 galore-torch 库。下面是一份完整可运行的示例——用 GaLore 配 transformers，在 imdb 数据集上对 Mistral-7B 做预训练：

```
import torch
import datasets
from transformers import TrainingArguments, AutoConfig, AutoTokenizer, AutoModelForCausalLM
import trl

train_dataset = datasets.load_dataset('imdb', split='train')

args = TrainingArguments(
    output_dir="./test-galore",
    max_steps=100,
    per_device_train_batch_size=2,
    optim="galore_adamw",
    optim_target_modules=["attn", "mlp"]
)

model_id = "mistralai/Mistral-7B-v0.1"

config = AutoConfig.from_pretrained(model_id)

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_config(config).to(0)

trainer = trl.SFTTrainer(
    model=model, 
    args=args,
    train_dataset=train_dataset,
    dataset_text_field='text',
    max_seq_length=512,
)

trainer.train()
```

`TrainingArguments`：只要传入有效的 `optim_target_modules`（支持单个字符串、正则，或字符串/正则列表），再把 `optim` 设成有效的 GaLore 优化器——`galore_adamw`、`galore_adamw_8bit`、`galore_adafactor`——就可以开跑了！

### 逐层更新

另一个要强调的点是*逐层（layer-wise）*优化器（即一次只更新一层权重）。通常，优化器在反向传播后对所有层执行一次统一的权重更新，为此需要把全部权重梯度存在内存里。改用逐层权重更新后，训练期间的内存footprint还能进一步降低。底层实现是用 PyTorch 的 post-accumulation 钩子挂在用户想要更新的层上。

要使用这个特性，只需在优化器名后加 `_layerwise`，例如 `galore_adamw_layerwise`。

## 结论

GaLore 利用梯度低秩结构的创新思路，是 LLM 内存高效训练的重要一步。它让十亿参数模型可以在消费级硬件上训练、通过投影技术降低优化器状态的内存footprint、支持动态子空间切换，把大规模模型训练的门槛拉了下来，实现了平民化。GaLore 与 8-bit 精度优化器的兼容性更进一步提升了它的实用性——不需要专用计算资源，也有路径训练更大、更复杂的模型。这为 AI 研究和应用打开了新的可能，无论实践者还是研究者，现在都是令人兴奋的时刻。
