*通过微调通用开源模型（例如 Qwen 和 Gemma）专门针对某个领域或某项任务的模型，继承了为许多领域和通用应用程序构建的词汇表。*

*在我们生产中运行的论文评分器中，词汇表将模型写入最多的文本分成许多标记。本文预览了我们即将发布的 VocabX 论文的一些结果：我们如何围绕每个标记的成本而不是其频率来专门化词汇表，并在不更改基本模型的情况下将测量的推理成本降低 77%。*

[！[同一句话，更少的标记：14 个带有基本标记器的标记，4 个带有VocabX](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/TYOhAFobnI4ss3UnNqMHc.p ng）]（https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/TYOhAFobnI4ss3UnNqMHc.png）

分词器通常被视为基本模型的固定属性，继承并保留。对于专门针对单一领域的模型，它可能是最大的成本杠杆之一，并且它是在任何训练步骤之前设置的。

我们在生产中运行的系统之一是基于 Qwen3-4B 构建的葡萄牙语论文自动评分器。它接收论文、提示和支持文本，并返回一个 JSON 评估，其中包含每个能力的评分和评论。

该模型已经很小，有 40 亿个参数，并且已经针对该任务进行了训练。然而，它的分词器仍然是最初的 Qwen3-4B 分词器，专为多种语言和多种文本而构建。在评分器中，它用于单一语言、葡萄牙语和单一响应格式。这有两个成本：评分者在每个请求上写入的文本占用的标记超出了所需的标记，并且在每个生成的标记中，模型对 151,669 个条目的词汇表进行了评分，其中包括许多该任务几乎从未使用过的词汇。

我们使用称为 VocabX 的方法重建词汇表，保持相同的基础模型、相同的数据和相同的训练配方。本文中的数字来自论文的当前版本，仍在审查中，并且在发布前可能会发生变化。

## 适合每个人的词汇

领先的语言模型读取和写入标记，标记器决定文本如何成为标记。领先的通用模型的分词器接受了来自许多领域和语言的大量文本集合的训练，从源代码到合同再到中文。对于通用模型来说，这种选择是有意义的。

对于单个领域中使用的模型，它会同时产生两种浪费。

首先是碎片化。分词器将域重复最多的部分分成许多部分。在评分器中，每个响应都以相同的 JSON 信封、相同的能力名称和相同的评估短语开头。在合同中，它是样板条款。在代码中，标识符。这些序列中的每一个都会花费几个代币，并且模型会根据每个请求为每个序列支付费用。

[![评分者在每个响应中写入的范围使用基本标记器需要 12 个标记，而使用基础标记器则需要 1 个标记VocabX](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/K5De-hfTaOl9vUJItSijj.p ng)](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/K5De-hfTaOl9vUJItSijj.png)

二是过剩。该词汇表包含该领域从未使用的数万个条目，并且该模型会在其生成的每个标记上计算所有条目的分数。一个针对美国学校生物考试等级的模型几乎永远不会用中文书写，但它会计算每一步中每个中文标记的概率。词汇表将领域重复最多的部分分成许多部分，并包含领域从未使用的条目。

[![基础分词器中有 151,669 个词汇条目，其中 64,767 个VocabX](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/Inl5L1IDqWUBbD0Xlq-JB.p ng)](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/Inl5L1IDqWUBbD0Xlq-JB.png)

## 阅读很便宜，写作很昂贵

自然的反应是计算令牌并尝试减少计数。但计数并不是账单。

要了解为什么生成的令牌成本更高，了解推理的工作原理会有所帮助。它有两个阶段。在 *prefill* 中，模型通过网络一次性处理整个输入：从 GPU 内存读取的每个权重都会被每个输入标记重复使用，并且限制是计算。在“解码”中，模型一次生成一个令牌的响应，并且每个令牌都需要完整的传递。每个权重读取仅使用几次，GPU 大部分时间都在等待数据从内存到达：内存带宽成为限制。

这种效应在我们运营的地方最为强烈：小型号、中等批量的服务。批处理请求会拆分各个请求的权重读数并缓解问题，但并不能解决问题。在每个解码步骤中，模型还会读取 KV 缓存，即保存已处理上下文并随之增长的注意力内存。在我们测量的情况下，分级机，生成的令牌的成本是读取令牌的 7.4 倍，但该比率随硬件、问题、批量大小、上下文长度和其他因素的不同而变化，并且可能会更大。总的来说，这个方向是成立的：生成成本比阅读成本更高。

[！[在我们测量的情况下，写入令牌的成本是读取的 7.4 倍一](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/q-GjdgYd6GgXnv3-wJQsY.pn g)](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/q-GjdgYd6GgXnv3-wJQsY.png)

想象一下一家按箱子收费的运输公司，但寄出箱子的收费是传入箱子的七倍。减少盒子总数会有所帮助。减少发件箱的效果可提高七倍。对输入和输出进行同等压缩的方法会错过大部分可能的节省。

该法案的第三个组成部分是词汇本身。模型的最后一层，即 LM 头，将内部状态转换为每个可能标记的分数。为此，它为每个词汇条目保存一行参数。在 Qwen3-4B 大小的模型中，该矩阵几乎占参数的 10%。这是大型模型在不知不觉中吸收的份额，但它对小型模型来说却是沉重的负担。

而且成本并不是只支付一次。输入层仅查找正在读取的令牌的行，但 LM 头会读取每个生成令牌的整个矩阵并将其相乘。由于解码已经受内存限制，因此每增加一行就需要在每一步移动更多数据。域从不使用的条目的成本与经常使用的条目的成本完全相同。这就是为什么添加代币可以减少计数并同时提高账单的原因。 VocabX 不将该术语包含在其选择标准中，但它通过两个步骤控制词汇表大小：子词合并用较小的、特定于领域的词汇表替换基本词汇表，并且宏在固定预算下输入。在分级器中，输出层从约 152,000 行增加到约 65,000 行。

## 为什么现有解决方案存在不足

调整模型的词汇并不是一个新想法。文献中的参考方法，例如快速词汇转移（FVT）、多词分词（MWT）和Liquid AI的[就地分词器扩展]（https://www.liquid.ai/blog/tokenizer-expansion）（就地BPE）从原始词汇继续进行BPE训练，已经减少了碎片。当我们针对我们的问题测试它们时，我们发现了两个局限性。

**他们根据频率而不是成本来选择令牌。** 在输入中经常出现的表达式对他们来说比在响应中出现频率较低的表达式更有价值，即使第二个表达式的服务成本更高。

**它们在单层上工作。**它们要么调整单词的分割方式，要么将整个短语合并为一个标记。这三个人都没有在同一标准下做到这两者。而分级机最大的浪费正是在长的、重复的跨度中，例如 JSON 信封，子词方法只有在逐个合并每个部分后才能到达。

## 我们如何解决这个问题

VocabX 解决了这两个限制，以及在解决第一个问题的明显路径上出现的第三个问题。

**首先，我们改变了问题。** 我们不再问候选人节省了多少代币，而是问节省了多少成本和时间。每个被淘汰的代币都会乘以它出现的字段的价格：系统提示、用户消息或模型响应。在我们测量的情况下，评分者，响应中保存的令牌的价值是输入中保存的令牌的 7.4 倍，并且相应地构建了词汇表。

**其次，我们同时处理两层。** 回到运输公司：您可以通过更好地包装每件物品来切割盒子，或者通过认识到每周运送相同的十二件物品套件并将该套件放在一个盒子中发送。 VocabX 两者兼而有之。在子词层，它重建了领域词的切分方式。在多单词层，它会查找重复的整个跨度，从短表达式到整行和 JSON 信封，并将每个单词转换为单个标记，我们称之为宏标记。这两层都是根据相同的成本标准选择的，每层都有自己的预算。

[![12个盒子变成1个，7个令牌变成1个宏令牌](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/B5Wig-4nTEutpFZlGQ6sk.g如果）]（https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/B5Wig-4nTEutpFZlGQ6sk.gif）

为了找到这些跨度，我们使用五个挖掘器，自动搜索在整个语料库中重复的跨度，每个挖掘器专门针对一种重复：长单词、整行、表达式、完整句子以及带有标点符号的结构，例如 JSON 和标签。平均超过八个语料库，最后一个贡献最大，仅在代码上就占了 17.5 分。如果没有这五项，评分器上的标记减少将下降 55.6 分。

[！[两层，一层成本标准]（https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/_EdPyU7R3xdomvFxuadPY .png)](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/_EdPyU7R3xdomvFxuadPY.png)

**第三，我们估计样本看不到的东西。** 按成本选择代币需要知道每个候选人在已经选择的代币之后还可以节省多少。准确地衡量这一点需要在每次选择后重新处理整个语料库数万次。大规模执行此操作的常见方法是对文档样本进行测量，然后样本中缺席的候选人获得零增益。

在 50,000 个文档中出现 37 次的表达式在包含 400 个文档的样本中仅出现约 26% 的概率。在合同语料库中，只有 16.6% 的候选人出现在 400 个文档样本中；其余的从未被评估。

[![37 次出现均未出现在 400 文档中示例](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/zxfdAxNxsvfBCBNeUThx5.p ng)](https://cdn-uploads.huggingface.co/production/uploads/6a725daa5ca641a21ab61956/zxfdAxNxsvfBCBNeUThx5.png)

候选人的收获有两部分。一是它在整个语料库中节省了多少，并且无需样本即可准确计算。 The other is how much of that saving is not yet covered by the tokens already chosen, and only that part needs to be estimated. For candidates the sample cannot see, we use a statistical estimate based on the behavior of the ones it can see, instead of zero. A candidate that is rare in the sample but frequent in the corpus is back in the running.

That change alone, with the same sample and the same budget, raised token reduction on a contracts corpus from 44.7% to 52.8%.

[！[用估计而不是零：44.7% 到 52.8% 令牌减少](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/PxGLMRrjTPVYDW8rlDuBd .png)](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/PxGLMRrjTPVYDW8rlDuBd.png)

## 分级机中发生了什么变化

为了衡量真实效果，我们使用相同的基础模型、相同的数据、相同的配方和相同的种子训练了七个版本的分级机。它们之间的唯一区别是标记器。所有这些都在同一台测试机器上运行相同的 500 个请求，配备 RTX 5090 GPU 和 vLLM 推理服务器，并根据测量的运行时间计算成本。

[![分级机结果：成本降低 77.0%，基准分数从 0.703 提高到0.810](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/7CKshmOEsUkemfgL9Mopn.p ng)](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/7CKshmOEsUkemfgL9Mopn.png)

该模型的平均响应从 350 个令牌下降到 101 个令牌。成本下降77.0%。质量（以基准分数衡量，结合了评分准确性和筛选离题或违规文章的准确性）从 0.703 上升到 0.810。

到达那里需要修正航向。词汇表的第一个版本将每个能力的等级与周围的 JSON 融合成一个宏标记。它是最紧凑的选择，但质量下降：其基准分数为 0.689，低于生产分级机的 0.703。通过宏内的等级，等级和结构的每种组合都成为同一令牌的不同变体，并且模型在一步中选择两者。为评分提供自己的标记，每个响应需要额外花费 2 个标记，将基准分数提高到 0.810，并且在测量中甚至更便宜：降低了 77.0%，而融合版本则降低了 73.3%。

该课程不仅适用于评分者。当压缩跨度承载模型要做出的决策时，压缩就会产生成本。我们的目标不是最便宜的词汇表，而是保留重要标记的最便宜的词汇表。

## 超越分级机

为了查明增益是否特定于我们的案例，我们将 VocabX 与五个公共领域（合同、医学论文、科学论文、新闻和 Python 代码）和三个模型系列（Qwen3、Llama-3.1 和 Gemma-3）的三种参考方法进行了比较。所有方法都使用相同的挖掘和测试文档以及相同的词汇上限。

VocabX 比所有 15 种组合中最强的参考方法压缩了 1.2 到 9.3 个点。在估计推理成本方面，VocabX 的修剪版本也在所有 15 项中领先，Qwen3 上的平均差距为 10.2 分，Llama-3.1 上的平均差距为 7.5 分，Gemma-3 上的平均差距为 13.6 分。在合约方面，修剪后的版本使用了 113,426 个词汇条目，代币减少了 62.6%，而最佳就地 BPE 配置使用了 207,803 个词汇条目，减少了 61.8%。

[![VocabX 平均领先优势：+10.2 (Qwen3)、+7.5 (Llama-3.1)、+13.6 (Gemma-3)点](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/bCCQQjpY6tU5ZAD3hXOeN.p ng)](https://cdn-uploads.huggingface.co/product/uploads/6a725daa5ca641a21ab61956/bCCQQjpY6tU5ZAD3hXOeN.png)

## 只为重要的代币付费

VocabX 并没有让模型变得更智能。它使模型停止为不需要逐段编写的文本付费，并停止对永远不会使用的词汇进行评分。在我们的评分器中，使用相同的基础模型和相同的训练配方，测量推理成本降低了 77%。

专业化通常从数据和权重开始。它也可以在词汇表中更早地开始一层。

完整的方法、每个实验的表格以及废弃的干预措施将在 VocabX 论文中，我们将很快发布。
