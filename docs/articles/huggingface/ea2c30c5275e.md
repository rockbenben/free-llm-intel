# NVIDIA 发布 600 万多语言推理数据集

作者：Dhruv Nathawani, Shuoyang Ding US, Vitaly Lavrukhin US, Jane Polak Scowcroft US, Oleksii Kuchaiev US

NVIDIA 持续发布宽松许可的数据集以支持开放生态，这次是 [6 Million Multilingual Reasoning Dataset](https://huggingface.co/datasets/nvidia/Nemotron-Post-Training-Dataset-v2)。

继近期成功的 [Nemotron Post-Training Dataset v1](https://huggingface.co/datasets/nvidia/Nemotron-Post-Training-Dataset-v1)（被用于 [Llama Nemotron Super model](https://developer.nvidia.com/blog/build-more-accurate-and-efficient-ai-agents-with-the-new-nvidia-llama-nemotron-super-v1-5/)）和我们今年早些时候发布的 [Llama Nemotron Post-Training Dataset](https://huggingface.co/datasets/nvidia/Llama-Nemotron-Post-Training-Dataset) 之后，我们很高兴发布翻译成五种目标语言的推理数据集：法语、西班牙语、德语、意大利语和日语。

新发布的 [NVIDIA Nemotron Nano 2 9B](https://huggingface.co/nvidia/NVIDIA-Nemotron-Nano-9B-v2) 把这些能力带到边缘侧，以混合 Transformer–Mamba 架构和可配置的 thinking budget 实现领先的精度与效率——你可以按需调节精度、吞吐和成本，匹配真实世界的需求。

## 模型亮点（TL;DR）

- **模型规模**：9B 参数
- **架构**：混合 Transformer–Mamba（Mamba-2 + 少量注意力层），在相近精度下比纯 Transformer 同级模型吞吐更高
- **吞吐**：在同等规模的主流模型中，token 生成速度最高快 6 倍
- **成本**：thinking budget 让你控制使用的"思考"token 数——推理成本最多可节省 60%
- **目标场景**：客服 agent、支持类聊天机器人、分析 copilot，以及边缘/RTX 部署
- **可用性**：模型权重已在 Hugging Face 提供，可在 build.nvidia.com 试用端点，模型还将以 NVIDIA NIM 形式提供，实现高吞吐低延迟
- **许可证**：nvidia-open-model-license

此次发布是我们持续致力于模型开发与改进中开放透明的重要一步。除训练工具和最终模型权重外，通过发布训练数据，NVIDIA 支持开放权重模型的持续改进。

## 数据集里有什么、如何构建

总体而言，Nemotron Post-Training Dataset V2 把我们此前发布的英文推理数据翻译成五种目标语言（法、德、意、日、西）。为了最大化利用预训练中植入的英文知识，我们在保留原始英文推理链的同时翻译用户 prompt 和模型回复。

[![image/png](https://cdn-uploads.huggingface.co/production/uploads/67ee17721b341f4d5608e585/Tov1aIsRIX16n12P22NTE.png)](https://cdn-uploads.huggingface.co/production/uploads/67ee17721b341f4d5608e585/Tov1aIsRIX16n12P22NTE.png)

根据 WMT 2024 通用翻译共享任务的结果，LLM 在机器翻译任务上已达到最先进水平的表现。然而，对于后训练数据的合成生成，我们的初步研究表明：

- 相比翻译常见机器翻译测试集（如 FLORES），LLM 翻译 SFT 数据集时更容易产生幻觉。
- 开源 LLM 的翻译质量和幻觉率随输入长度增加而显著恶化。

因此，我们引入了多种机制来维持高翻译质量并便于幻觉检测。概括来说：

- 我们按换行符拆分句子并逐行翻译。若某行不可翻译（如只有制表符）或属于代码块，则不翻译。
- 我们强制特定格式（"Wrap the translated text in brackets 〘〙"），用这组特殊匹配括号提取翻译。其他示例被丢弃（见 Table 1）。
- 我们对 prompt 输入的翻译运行 fastText 语言识别，过滤掉偏离目标语言的数据点。我们又丢弃了 55,567 个示例（占全部多语言示例的另外 1.1%）。

*Table 1: Ratio of discarded data (measured by bytes) by enforcing output format*

| Language | code | qa | math |
| --- | --- | --- | --- |
| de | 2.28% | 1.11% | 2.47% |
| es | 26.14% | 5.15% | 6.38% |
| fr | 11.01% | 1.37% | 1.96% |
| it | 4.94% | 1.36% | 0.75% |
| ja | 7.68% | 2.51% | 3.86% |

经过基准比较，我们选择了 `Qwen2.5-32B-Instruct-AWQ`（用于德语）和 `Qwen2.5-14B-Instruct`（用于其他语言）执行翻译。选择这些模型的考量包括：

- 稳健的翻译质量
- 可以放进单张 A100 GPU 推理
- 训练数据具有广泛的领域覆盖
- 开放许可（Apache 2.0）
