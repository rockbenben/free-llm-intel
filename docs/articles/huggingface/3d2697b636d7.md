我们最近发布了 **[NVIDIA Nemotron 3.5 Parse](https://huggingface.co/nvidia/Nemotron-3.5-Parse)**，这是一个紧凑的文档模型，能把页面图像转换成结构化数据，供检索增强生成（RAG）和 agent 使用。

现在，我们在这项发布的基础上继续推进，推出**合成训练数据集、一份微调配方，以及一个用于加速推理的 DFlash2 推测器**。我们还公开了 Parse 3.5 的训练方式：先通过监督微调教会它理解文档，再用强化学习提升准确率、一致性以及稳定完成输出的能力。

## Parse 3.5 能产出什么

Parse 会把文档页面中的内容按阅读顺序抽取出来，为其分配标题、段落、表格、图表等内容类别，并返回用于定位这些内容的边界框。表格和图表会变成结构化记录，可支撑下游的文档处理应用。

[![左侧是一份带有预测区域的运营简报，右侧是它的结构化抽取结果。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-01-page-structure.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-01-page-structure.png)

*图 1. 一份合成运营简报的实际模型输出，展示了页面与其结构化表示之间的对应关系。*

Parse 的这一最新版本大幅扩展了读取图表和表格的能力，尤其是在更困难、更含糊的情形下。例如，那些完全没有标注数值的柱状图或其他绘图。模型能够观察坐标轴和柱子的高度来推断出这些数值。表格可能格外棘手，因为其结构本身承载着很重的意义——只要错位一行或一列，就可能彻底改变解读和含义。这些进步在很大程度上得益于合成数据生成：渲染出各种变体的图表和表格（并带有已知的 ground truth），再训练模型去逆向复现这一过程。

我们开源了 **Parse 3.5 训练中用到的三个数据集**：

- **[Synthetic Charts V1 —— 9.98M 条示例](https://huggingface.co/datasets/nvidia/Synthetic-Charts-V1)：** 渲染出的图表与结构化标注，用于学习类别、系列和数值。
- **[Synthetic Tables V1 —— 1M 条示例](https://huggingface.co/datasets/nvidia/Synthetic-Tables-V1)：** 渲染出的 HTML 表格，其目标保留了行、列、表头和单元格之间的关系。
- **[OCR Synthetic Multilingual v2 —— 7.9M 条示例](https://huggingface.co/datasets/nvidia/OCR-Synthetic-Multilingual-v2)：** 带有 Parse 格式目标的合成文档页面，覆盖多种字体与版面，用于多语言 OCR 与结构化页面阅读。

每个发布版本都包含图像、标注、生成文档以及训练格式。你可以用这些配对数据微调文档模型，或针对目标文档类型或语言构造新的变体。

[![一张没有印出数值的柱状图，以及已发布模型从中抽取出的数值 18、27、39 和 54。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-02-chart-geometry.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-02-chart-geometry.png)

## SFT 教会能力，RLVR 提升一致性

我们分两个阶段训练 Parse 3.5。**监督微调（SFT）**覆盖文本、版面、表格、图表和多语言文档。通过学习预测结构化目标，模型建立起了阅读页面并表达其内容的通用能力。

之后我们继续做**带可验证奖励的强化学习（RLVR）**，采用**组相对策略优化（GRPO）**。奖励会检查采样抽取结果的质量。例如，一次图表抽取如果能还原正确的系列和数值、产出可用的结构，并且完成输出时没有反复生成同样的内容，就能拿到更高的奖励。

一张困难的页面可能存在多种有效的表示形式。这些检查让模型不必被限定为某一个确切的 token 序列，也能灵活地找到正确答案，同时抑制循环生成和未完成的输出。

[![一组匹配条件下的训练对比，显示 GRPO 之后抽取效果的提升，以及重复标记和触及 token 上限的减少。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-03-sft-grpo-gains.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-03-sft-grpo-gains.png)

*图 3. 在匹配的评测设置下对 SFT 与 GRPO 做的受控对比。这些都是开发阶段的 checkpoint，与最终发布的模型不同。循环计数使用重复性检查。[方法](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/blob/main/measurement-notes.md#training-and-adaptation-figures)。*

匹配对比的结果显示了收益：被标记为循环的输出从 **126 页降到 29 页——减少约 77%**，触及 9,000 token 上限的输出从 **185 个降到 35 个**。总体得分从 **66.24 提升到 71.38**，其中表格 **+5.18 分**，图表 **+4.15 分**。

## 通过架构和 DFlash2 实现更快的推理

解析器必须为每一页生成大量文本和结构。在训练工作之外，我们还优化了 Parse 3.5 处理图像以及解码这些输出的方式。

| **组件** | **Parse 2.0** | **Parse 3.5** |
| --- | --- | --- |
| 页面预处理 | 固定的 2048 × 1664 画布 | NaViT 动态矩形输入 |
| 图文连接 | 编码器–解码器交叉注意力 | 压缩后的视觉 token 作为因果前缀 |
| 解码器自注意力 | 多头注意力 | GQA-8：16 个 query 头，8 个 key/value 头 |
| 投机解码 |  | 单 token 前瞻（MTP）；可选 DFlash2 |

**NaViT 预处理**会让输入的形状随页面自适应。一个视觉适配器把图像序列压缩，文本解码器则把它作为前缀来使用，从而取代编码器–解码器交叉注意力。**带八个 key/value 头的分组查询注意力（GQA-8）**降低了解码器注意力缓存的内存占用。

内置的**多 token 预测（MTP）**头提供单 token 的前瞻。我们的 **[DFlash2 推测器](https://huggingface.co/nvidia/Nemotron-3.5-Parse/tree/main/dflash2)** 更进一步：一个小型草稿模型一次提出**最多 32 个 token** 的候选，Parse 再对这些候选一并验证。在实测的 32 token 配置下，它平均接受约 **14 个草稿 token**，也就是说，把目标 token 算在内，**每次验证步骤大约推进 15 个输出 token**。

[![对比 Parse 2.0 与 Parse 3.5 基础版、MTP 版和 DFlash2 版的吞吐曲线。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-04-parse-concurrency.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-04-parse-concurrency.png)

*图 4. 单张 H200、BF16 下的原生单遍吞吐，使用同一批 2,078 页。Parse 2.0 每个数据点跑一次试验；Parse 3.5 显示三次试验的中位数。箭头表示从 Parse 3.5 基础版到 DFlash2 的提升。[测量细节](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/blob/main/measurement-notes.md)。*

在单张 H200、BF16 下的原生单遍基准测试中，与关闭投机解码的 Parse 3.5 相比，DFlash2 在并发度为 1 时把吞吐提升了 **7.62 倍**，在并发度为 512 时提升了 **1.52 倍**。并发度为 512 时，Parse 3.5 在不做投机的情况下达到 **13.48 页/秒**，启用 DFlash2 后达到 **20.44 页/秒**，而 Parse 2.0 是 **2.98 页/秒**。这分别是 Parse 2.0 吞吐的 **4.53 倍**和 **6.86 倍**。

解析变快之后，我们就有余力回头处理那些困难的区域。先做一次整页预测，再在文档需要的地方加入有针对性的重处理：

- **单遍 -** 对整页做一次解析，抽取文本、版面、表格和图表。
- **双遍 - 用于密集的表格和细小的图表细节。**裁出解析器找到的表格和图表区域，以更高的细节重新解析，再把精修结果合并进整页输出。
- **三遍 -** 不再只依赖模型整页解析得到的边界框，而是让模型以检测模式再跑一遍，以验证所有框都被准确找到、文本没有遗漏，然后在第三遍中重新抽取找到的所有图表或表格

[![单遍页面解析、双遍裁剪区域精修，以及借助独立区域检测器进行的三遍精修。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-05-multipass.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-05-multipass.png)

*图 5. 额外的阶段把计算集中在困难的区域。多次裁剪可能会带来多次请求。*

在公开的参考评测中，双遍和三遍分别比单遍多出 **2.18 和 2.46 个 ParseBench 分**。额外的工作让应用可以用一部分吞吐换取困难区域更好的抽取效果。[参考结果与服务测量](https://huggingface.co/nvidia/Nemotron-3.5-Parse#single-double-or-triple-pass)。

## 把同样的 SFT/RLVR 方法用到你自己的文档上

我们分享了一份 **[Parse 微调配方](https://github.com/NVIDIA-NeMo/Nemotron/blob/main/docs/nemotron/parse/index.md)**，带开发者依次走完配对数据生成、**NeMo Automodel SFT** 和 **NeMo RL GRPO**，并用 vLLM 生成候选答案。

这个完整示例用的是一张合成的牙科表单，上面有一个**牙位图（odontogram）**：展示牙齿、计划实施的操作以及受影响牙面的图表。在适配之前，Parse 能读出印刷的牙位编号，却漏掉了本应输出的操作表。SFT 教会它把每一颗被标记的牙齿与某个操作、以及该操作在牙齿上的位置关联起来。

[![一页合成的牙科表单、基础模型转录出的牙位编号，以及预期的牙位/操作/牙面表格。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-06-dental-adaptation.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-06-dental-adaptation.png)

*图 6. 一个配方录制示例：SFT 之后，图表中的全部六行都与目标一致。[完整图像与原生训练标签](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/blob/main/examples/dental-adaptation.md)。*

随后 RLVR 会强化准确率和一致的完成度。在牙科的参考运行中，估计的首次尝试成功率（采样的 pass@1）从基础模型的 0.00% 上升到 SFT 之后的 95.85%，再到 RLVR 之后的 96.58%。

[![牙科采样 pass@1：SFT 之后为 95.85%，RLVR 之后为 96.58%，图中 y 轴范围为 90% 到 100%](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-07-dental-sft-rlvr.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-07-dental-sft-rlvr.png)

*图 7. 在来自同一合成生成器的 256 份留出表单上做匹配评测，每页采样八次。成功要求自然完成、图表内容完全正确，且归一化后的页面文本没有错误。[评测协议](https://github.com/NVIDIA-NeMo/Nemotron/blob/main/docs/nemotron/parse/workflow.md#evaluation-and-dental-example-results)。*

要适配这套配方，请提供你自己的图像/标签对，以及一个验证器（verifier）：用来判断抽取结果是否正确的一组检查。随附的 **[文档奖励组件](https://github.com/NVIDIA-NeMo/Nemotron/tree/main/src/nemotron/recipes/parse/document_rewards)** 覆盖文本保真度、边界框、表格、图表事实和完成度。把与你任务相关的组件组合起来，再加上 schema 校验，并用完成度检查和重复性检查来抑制循环或未完成的输出。

我们很高兴看到社区已经把 Parse 扩展并改进到了 **[泰语](https://huggingface.co/iapp/OpenThai2.1-OCR-Markdown-20261118)**、**[波斯语/Farsi](https://huggingface.co/Reza2kn/Bina-0.4-Koochik)** 和 **[阿拉伯语](https://huggingface.co/g3ida/absir-arabic-ocr-mini)**，我们也希望这些新增的数据集和微调配方能有助于鼓励这些工作，以及未来的模型。
