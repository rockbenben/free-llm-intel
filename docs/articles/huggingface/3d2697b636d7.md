我们最近发布了 **[NVIDIA Nemotron 3.5 Parse](https://huggingface.co/nvidia/Nemotron-3.5-Parse)**，这是一个紧凑型文档模型，可将页面图像转换为结构化数据，用于检索增强生成（RAG）和智能体。

现在，我们在该版本基础上继续构建，推出**合成训练数据集、微调配方，以及用于加速推理的 DFlash2 推测器**。我们还将分享 Parse 3.5 的训练方式：首先通过监督微调教会模型理解文档，然后使用强化学习提升准确性、一致性和可靠完成度。

## Parse 3.5 的输出内容

Parse 将文档页面中的内容按阅读顺序提取出来，为内容分配类别（如标题、段落、表格和图表），并返回定位内容的边界框。表格和图表会转换为结构化记录，可支撑下游文档处理应用。

[![左侧为带有预测区域的操作简报，右侧为其结构化提取结果。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-01-page-structure.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-01-page-structure.png)

*图 1. 来自合成操作简报的实际模型输出，展示页面与其结构化表示之间的对应关系。*

Parse 的最新版本显著扩展了读取图表和表格的能力，尤其是在更困难、更模糊的情况下。例如，没有任何标注数值的柱状图或其他图形。模型能够通过观察坐标轴和柱的高度来推断这些数值。表格可能尤其棘手，因为结构本身承载重要含义，一行或一列错位就可能完全改变解读和含义。这些进步主要得益于合成数据生成——渲染出带有已知真值的图表和表格变体，然后训练模型逆向还原这一过程。

我们开源了 **Parse 3.5 训练中使用的三个数据集**：

- **[Synthetic Charts V1 — 998 万个样本](https://huggingface.co/datasets/nvidia/Synthetic-Charts-V1)：** 渲染的图表和结构化标注，用于学习类别、系列和数值。
- **[Synthetic Tables V1 — 100 万个样本](https://huggingface.co/datasets/nvidia/Synthetic-Tables-V1)：** 渲染的 HTML 表格及目标，保留行、列、表头和单元格关系。
- **[OCR Synthetic Multilingual v2 — 790 万个样本](https://huggingface.co/datasets/nvidia/OCR-Synthetic-Multilingual-v2)：** 具有 Parse 格式目标的合成文档页面，涵盖多种字体和布局，用于多语言 OCR 和结构化页面阅读。

每个发布版本都包含图像、标注、生成文档和训练格式。可使用这些配对数据来微调文档模型，或针对目标文档类型或语言创建新的变体。

[![一张未印出柱值的柱状图，以及发布模型提取出的 18、27、39 和 54。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-02-chart-geometry.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-02-chart-geometry.png)

*图 2. Parse 从图表几何形状中恢复出 18、27、39 和 54*

## SFT 建立能力；RLVR 提升一致性

我们分两个阶段训练 Parse 3.5。**监督微调（SFT）**涵盖文本、布局、表格、图表和多语言文档。学习预测结构化目标建立了阅读页面并表示其内容的通用能力。

随后我们继续进行**可验证奖励的强化学习（RLVR）**，使用**组相对策略优化（GRPO）**。奖励会检查采样提取结果的质量。例如，图表提取若能恢复正确的系列和数值、生成可用的结构，并且完成时没有反复生成相同内容，就能获得更高的奖励。

一个困难的页面可能有多种有效表示。这些检查让模型能够灵活地找到正确答案，而不必规定某个确切的 token 序列，同时抑制循环和未完成的输出。

[![匹配训练对比，展示 GRPO 后的提取增益，以及更少的重复标记和 token 上限命中。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-03-sft-grpo-gains.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-03-sft-grpo-gains.png)

*图 3. 在匹配评估设置下对 SFT 和 GRPO 的受控对比。这些是开发检查点，与最终发布模型不同。循环计数使用重复检查。[方法](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/blob/main/measurement-notes.md#training-and-adaptation-figures)。*

匹配对比显示了收益：被标记为循环的输出从 **126 页降至 29 页——减少约 77%**——达到 9,000 token 上限的输出从 **185 降至 35**。总体得分从 **66.24 提升至 71.38**，其中**表格 +5.18 分**，**图表 +4.15 分**。

## 通过架构和 DFlash2 实现更快推理

解析器必须为每个页面生成大量文本和结构。在训练工作的同时，我们优化了 Parse 3.5 处理图像和解码这些输出的方式。

| **组件** | **Parse 2.0** | **Parse 3.5** |
| --- | --- | --- |
| 页面预处理 | 固定 2048 × 1664 画布 | NaViT 动态矩形输入 |
| 图像到文本连接 | 编码器–解码器交叉注意力 | 压缩视觉 token 作为因果前缀 |
| 解码器自注意力 | 多头注意力 | GQA-8：16 个查询头，8 个键/值头 |
| 推测解码 |  | 单 token 前瞻（MTP）；可选 DFlash2 |

**NaViT 预处理**使输入形状适应页面。视觉适配器压缩图像序列，文本解码器将其作为前缀消费，取代编码器–解码器交叉注意力。**八键/值头的分组查询注意力（GQA-8）**减少了解码器的注意力缓存内存。

内置的**多 token 预测（MTP）**头提供单 token 前瞻。我们的 **[DFlash2 推测器](https://huggingface.co/nvidia/Nemotron-3.5-Parse/tree/main/dflash2)**更进一步：一个小型草稿模型**最多提议未来 32 个 token**，Parse 一起验证这些提议。在实测的 32 token 配置中，平均约**接受 14 个草稿 token**，即每个验证步骤（含目标 token）约**推进 15 个输出 token**。

[![吞吐量曲线对比 Parse 2.0 与 Parse 3.5 基础版、MTP 和 DFlash2。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-04-parse-concurrency.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-04-parse-concurrency.png)

*图 4. 在单张 H200、BF16 上使用相同 2,078 页的原生单遍吞吐量。Parse 2.0 每个点一次试验；Parse 3.5 显示三次试验的中位数。箭头显示从 Parse 3.5 基础版到 DFlash2 的增益。[测量详情](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/blob/main/measurement-notes.md)。*

在单张 H200、BF16 的原生单遍基准测试中，与禁用推测解码的 Parse 3.5 相比，DFlash2 在并发 1 时吞吐量提升 **7.62×**，在并发 512 时提升 **1.52×**。在 512 并发下，Parse 3.5 无推测达到 **13.48 页/秒**，使用 DFlash2 达到 **20.44 页/秒**，而 Parse 2.0 为 **2.98 页/秒**。分别是 Parse 2.0 吞吐量的 **4.53×** 和 **6.86×**。

快速解析让我们有余力重新审视困难区域。先进行整页预测，然后在文档需要的地方添加针对性重新处理：

- **单遍 -** 对整页解析一次，提取文本、布局、表格和图表。
- **双遍 - 用于密集表格和小图表细节。** 裁剪解析器找到的表格和图表区域，以更高细节重新解析，并将细化结果合并到页面输出中。
- **三遍 -** 不仅使用模型的整页解析边界框，还以检测模式进行第二遍模型处理，以验证所有框均已准确找到且文本未被遗漏，并在第三遍中重新提取任何找到的图表或表格

[![单遍页面解析、双遍裁剪细化和使用独立区域检测器的三遍细化。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-05-multipass.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-05-multipass.png)

*图 5. 额外阶段将计算集中在困难区域。多个裁剪可能需要多个请求。*

在已发布的参考评估中，双遍和三遍相比单遍分别增加 **2.18 和 2.46 个 ParseBench 分**。额外工作让应用可以牺牲部分吞吐量，换取困难区域的更好提取效果。[参考结果和服务测量](https://huggingface.co/nvidia/Nemotron-3.5-Parse#single-double-or-triple-pass)。

## 将相同的 SFT/RLVR 方法应用于你的文档

我们分享了一个 **[Parse 微调配方](https://github.com/NVIDIA-NeMo/Nemotron/blob/main/docs/nemotron/parse/index.md)**，引导开发者完成配对数据生成、**NeMo Automodel SFT** 和 **NeMo RL GRPO**，并使用 vLLM 生成候选答案。

示例使用一个带有**牙位图**的合成牙科表单：图表显示牙齿、计划程序和受影响的牙面。在适配之前，Parse 能读取印刷的牙位编号，但遗漏了预期的程序表。SFT 教会它将每颗标记的牙齿与程序及其在牙齿上的位置关联起来。

[![合成牙科页面、基础模型的牙位编号转录，以及预期的牙齿/程序/牙面表。](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-06-dental-adaptation.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-06-dental-adaptation.png)

*图 6. 一个记录的配方示例：经过 SFT 后，全部六行图表均与目标匹配。[完整图像和原生训练标签](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/blob/main/examples/dental-adaptation.md)。*

RLVR 随后强化准确性和一致完成度。在牙科参考运行中，估计的首次尝试成功率（采样 pass@1）从基础模型的 0.00% 升至 SFT 后的 95.85%，RLVR 后达到 96.58%。

[![牙科采样 pass@1：SFT 后 95.85%，RLVR 后 96.58%，y 轴显示 90% 至 100%](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-07-dental-sft-rlvr.png)](https://huggingface.co/datasets/nvidia/Nemotron-Parse-Blog-Assets/resolve/main/images/figure-07-dental-sft-rlvr.png)

*图 7. 在来自同一合成生成器的 256 份留出表单上进行匹配评估，每页八个样本。成功要求自然完成、图表内容完全正确且归一化页面文本无错误。[评估协议](https://github.com/NVIDIA-NeMo/Nemotron/blob/main/docs/nemotron/parse/workflow.md#evaluation-and-dental-example-results)。*

要适配该配方，请提供你自己的图像/标签对和验证器：即判断提取是否正确的检查。包含的**[文档奖励组件](https://github.com/NVIDIA-NeMo/Nemotron/tree/main/src/nemotron/recipes/parse/document_rewards)**涵盖文本保真度、边界框、表格、图表事实和完成度。组合与你的任务相关的组件，添加模式检查，并使用完成度和重复检查来抑制循环或未完成的输出。

我们很高兴社区已经为**[泰语](https://huggingface.co/iapp/OpenThai2.1-OCR-Markdown-20261118)**、**[波斯语/法尔西语](https://huggingface.co/Reza2kn/Bina-0.4-Koochik)**和**[阿拉伯语](https://huggingface.co/g3ida/absir-arabic-ocr-mini)**扩展并改进了 Parse，我们希望这些额外的数据集和微调配方能帮助鼓励这些努力和未来的模型。
