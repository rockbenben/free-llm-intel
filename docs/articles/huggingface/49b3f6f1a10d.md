但如果你能在自己的书桌上让自己的 agent 活起来呢？一个能帮你干活、又能私密处理你数据的 AI 伙伴？

在今天的 CES 主题演讲中，Jensen Huang 向我们展示了如何做到这一点：用 NVIDIA [DGX Spark](https://www.nvidia.com/en-us/products/workstations/dgx-spark/) 的算力搭配 [Reachy Mini](https://huggingface.co/spaces/pollen-robotics/Reachy_Mini)，创造属于你的桌面小 R2D2——可以和它说话、与它协作。

这篇博文提供逐步指南，让你在家用 DGX Spark 和 [Reachy Mini](https://huggingface.co/spaces/pollen-robotics/Reachy_Mini) 复刻这趟美妙体验。

## 食材

想直接开火，这里是 [demo 的源代码](https://github.com/brevdev/reachy-personal-assistant)。

我们会用到：

- 推理模型：demo 使用 [NVIDIA Nemotron 3 Nano](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16)
- 视觉模型：demo 使用 [NVIDIA Nemotron Nano 2 VL](https://huggingface.co/nvidia/NVIDIA-Nemotron-Nano-12B-v2-VL-BF16)
- 文本转语音模型：demo 使用 [ElevenLabs](https://elevenlabs.io)
- [Reachy Mini](https://www.pollen-robotics.com/reachy-mini/)（或 [Reachy Mini 仿真](https://github.com/pollen-robotics/reachy_mini/blob/main/docs/source/platforms/simulation/get_started.md)）
- Python v3.10+ 环境，配 [uv](https://docs.astral.sh/uv/)

尽管改编配方、做出你自己的版本——把模型接入应用的方式有很多种：

- 本地部署——跑在你自己的硬件上（[DGX Spark](https://www.nvidia.com/en-us/products/workstations/dgx-spark/) 或显存足够的 GPU）。我们的实现中推理模型约需 65GB 磁盘空间，视觉模型约 28GB。
- 云端部署——把模型部署到云 GPU，例如通过 [NVIDIA Brev](http://build.nvidia.com/gpu) 或 [Hugging Face Inference Endpoints](https://endpoints.huggingface.co/)。
- 无服务器模型端点——向 [NVIDIA](https://build.nvidia.com/nvidia/nemotron-3-nano-30b-a3b/deploy) 或 [Hugging Face Inference Providers](https://huggingface.co/docs/inference-providers/en/index) 发请求。

## 给 Reachy 赋予 agent 能力

把 AI agent 从简单聊天界面变成可以自然交互的存在，会让对话更真实。当 AI agent 能通过摄像头看、大声说话、执行动作，体验就更有吸引力。这正是 Reachy Mini 带来的可能。

Reachy Mini 天生为可定制而设计。借助对传感器、执行器与 API 的访问，你可以轻松把它接入现有 agent 技术栈——无论是仿真还是真实硬件，都可以直接用 Python 控制。

本文侧重组合既有的积木，而非重造轮子。我们把用于推理与视觉的开放模型、用于编排的 agent 框架、用于动作的工具处理器组合起来。各组件松耦合，方便换模型、改路由逻辑或添加新行为。

与封闭的个人助手不同，这套方案保持完全开放。模型、prompt、工具和机器人动作都由你掌控。Reachy Mini 只是成为你 agent 的物理终端——感知、推理与动作在此汇合。

## 构建 agent

在这个例子中，我们用 NVIDIA 的 [NeMo Agent Toolkit](https://github.com/NVIDIA/NeMo-Agent-Toolkit)——一个灵活、轻量、框架无关的开源库——把 agent 的所有组件连接起来。它与其他 agentic 框架（如 LangChain、LangGraph、CrewAI）无缝协作，处理模型间如何交互、在它们之间路由输入输出，让你易于尝试不同配置或添加新能力而无需重写核心逻辑。该 toolkit 还提供内置的性能剖析与优化功能，让你跟踪各工具与 agent 的 token 使用效率与延迟、识别瓶颈，并自动调优超参以在降低成本与延迟的同时最大化准确率。

## 第 0 步：配置好模型与服务的访问

首先，克隆包含全部所需代码的仓库：

```
git clone git@github.com/brevdev/reachy-personal-assistant
cd reachy-personal-assistant
```

要访问由 NVIDIA Nemotron 模型驱动的智能层，你可以用 [NVIDIA NIM](https://docs.nvidia.com/nim/large-language-models/latest/getting-started.html) 或 [vLLM](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16#use-it-with-vllm) 部署它们，或通过 [build.nvidia.com](http://build.nvidia.com) 的远程端点连接。

下面的说明假设你通过端点访问 Nemotron 模型。在主目录创建一个 .env 文件写入你的 API key。本地部署则无需指定 API key，可跳过此步。

```
NVIDIA_API_KEY=your_nvidia_api_key_here
ELEVENLABS_API_KEY=your_elevenlabs_api_key_here
```

## 第 1 步：搭建聊天界面

先通过 NeMo Agent Toolkit 的 API server 跑起一个基础 LLM 聊天工作流。NeMo Agent Toolkit 支持用 `nat serve` 加配置文件运行工作流。这里传入的[配置文件](https://github.com/brevdev/reachy-personal-assistant/blob/main/nat/src/ces_tutorial/config.yml)包含 agent 所需的全部设置信息，包括聊天与图像理解所用模型，以及 agent 使用的路由模型。[NeMo Agent Toolkit UI](https://github.com/NVIDIA/NeMo-Agent-Toolkit-UI) 可通过 HTTP/WebSocket 连接，让你像使用标准聊天产品一样与你的工作流对话。在本实现中，NeMo Agent Toolkit 服务器启动在 8001 端口（这样你的 bot 能调用它，UI 也能）：

```
cd nat
uv venv
uv sync
uv run --env-file ../.env nat serve --config_file src/ces_tutorial/config.yml --port 8001
```

然后，在另一个终端发送一个纯文本 prompt，确认一切配置正确：

```
curl -s http://localhost:8001/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "test", "messages": [{"role": "user", "content": "What is the capital of France?"}]}'
```

查看 agent 配置你会发现，它定义的能力远超一次简单的聊天补全。后面的步骤会逐一展开。

## 第 2 步：加入 NeMo Agent Toolkit 内置的 ReAct agent 做工具调用

工具调用是 AI agent 的本质组成。NeMo Agent Toolkit 内置一个 ReAct agent，能在工具调用之间推理、在回答前使用多个工具。我们把「动作请求」路由给允许调用工具的 ReAct agent（例如触发机器人行为或获取机器人当前状态的工具）。

几条实践提示：

- 工具 schema 保持精简（清晰的 name/description/args），因为 agent 就是靠它决定调用什么。
- 给步数设硬上限（max_tool_calls），防止 agent 无限打转。
- 如果用实体机器人，考虑对物理动作采用「执行前确认」模式，确保运动安全。

看看配置的这一部分：它定义了工具（如 Wikipedia 搜索），并指定管理这些工具所用的 ReAct agent 模式。

```
functions:
   wikipedia_search:
      _type: wiki_search
      max_results: 2
      
   ..
   react_agent:
      _type: react_agent
      llm_name: agent_llm
      verbose: true
      parse_agent_response_max_retries: 3
      tool_names: [wikipedia_search]

​​workflow:
   _type: ces_tutorial_router_agent
   agent: react_agent
```

## 第 3 步：加一个路由，把查询导向不同模型

核心思想：不要用一个模型包打天下，而是按意图路由：

- 文本查询用快速的文本模型
- 视觉查询必须走 VLM
- 动作/工具请求路由到 ReAct agent + 工具

路由可以有多种实现方式（启发式、轻量分类器、或专用路由服务）。想要这个理念的「生产级」版本，可参考 NVIDIA [LLM Router 开发者示例](https://build.nvidia.com/nvidia/llm-router)——完整参考实现，含评估与监控模式。

一个基础路由策略可能长这样：

- 如果用户问的是关于所处环境的问题，则把请求连同相机（或 Reachy）抓取的图像发给 VLM。
- 如果用户的问题需要实时信息，把输入交给 ReACT agent 通过工具调用做网页搜索。
- 如果只是简单问题，把请求发给为闲聊优化的小而快的模型。

配置的这些部分定义了路由拓扑并指定路由模型。

```
functions:
   ..
   
   router:
      _type: router
      route_config:
        - name: other
          description: Any question that requires careful thought, outside information, image understanding, or tool calling to take actions.
        - name: chit_chat
          description: Any simple chit chat, small talk, or casual conversation.
        - name: image_understanding
          description: A question that requires the assistant to see the user eg a question about their appearance, environment, scene or surroundings. Examples what am I holding, what am I wearing, what do I look like, what is in my surroundings, what does it say on the whiteboard. Questions about attire eg what color is my shirt/hat/jacket/etc
      llm_name: routing_llm


llms:
   ..
   routing_llm: 
      _type: nim
      model_name: microsoft/phi-3-mini-128k-instruct
      temperature: 0.0
```

**注意**：想降低延迟/成本或离线运行，你可以自托管其中一路模型（通常是「快速文本」模型），而把 VLM 留在远端。常见做法是用 NVIDIA NIM 或 vLLM 服务，并把 NeMo Agent Toolkit 指向一个 OpenAI 兼容端点。

## 第 4 步：加入 Pipecat bot 实现实时语音 + 视觉

现在进入实时环节。[Pipecat](https://www.pipecat.ai/) 是为低延迟语音/多模态 agent 设计的框架：它编排音视频流、AI 服务与传输，让你构建自然的对话。在这个仓库里，bot 服务负责：

- 采集视觉（机器人相机）
- 语音识别 + 文本转语音
- 协调机器人运动与表现行为

全部 pipecat bot 代码在 `reachy-personal-assistant/bot` [文件夹](https://github.com/brevdev/reachy-personal-assistant/tree/main/bot)。

## 第 5 步：把一切接到 Reachy（硬件或仿真）

Reachy Mini 暴露一个守护进程（daemon），系统其余部分都连接到它。本仓库默认以仿真运行守护进程（--sim）。如果你有真的 Reachy，去掉这个 flag，同一套代码就会控制你的机器人。

### 运行整个系统

跑起整个系统需要三个终端：

#### 终端 1：Reachy 守护进程

```
cd bot
# macOS:
uv run mjpython -m reachy_mini.daemon.app.main --sim --no-localhost-only

# Linux:
uv run -m reachy_mini.daemon.app.main --sim --no-localhost-only
```

如果你用实体硬件，记得从命令中省略 --sim flag。

#### 终端 2：Bot 服务

```
cd bot
uv venv
uv sync
uv run --env-file ../.env python main.py
```

#### 终端 3：NeMo Agent Toolkit 服务

如果第 1 步的 NeMo Agent Toolkit 服务没在运行，现在在终端 3 启动它。

```
cd nat
uv venv
uv sync
uv run --env-file ../.env nat serve --config_file src/ces_tutorial/config.yml --port 8001
```

三个终端就绪后，主要盯两个窗口：

- **Reachy Sim** —— 在终端 1 启动仿真守护进程时会自动出现这个窗口。适用于以 Reachy Mini 仿真代替实体设备的场景。
- **Pipecat Playground** —— 这是客户端 UI，你可以在这里连接 agent、启用麦克风与相机输入、查看实时转写。在终端 2 里打开 bot 服务暴露的 URL：[http://localhost:7860/](http://localhost:7860/client/)。在浏览器点 "CONNECT"。初始化可能需要几秒，期间会提示你授予麦克风（以及可选的相机）权限。两个窗口就绪后：

- Client 和 Agent 的 STATUS 指示应显示 READY
- bot 会用欢迎语问候你："Hello, how may I assist you today?"

到这里，你就可以开始和你的 agent 互动了！
