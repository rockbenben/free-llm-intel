# 数据集 SQL Console 上线

本文另有中文版本 [简体中文](https://huggingface.co/blog/zh/sql-console)。

数据集的使用正在爆炸式增长，Hugging Face 已成为许多数据集的默认之家。随着上传到 Hub 的数据集数量逐月增长，对它们进行查询、过滤和发现的需求也在与日俱增。

[![Dataset Monthly Creations](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/sql_console/dataset_monthly_creations.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/sql_console/dataset_monthly_creations.png) *Hugging Face Hub 上每月新建的数据集*

我们非常兴奋地宣布：你现在就能在 Hugging Face Hub 上直接对数据集运行 SQL 查询！

## 面向数据集的 SQL Console

在每个数据集上，你都会看到一个新 **SQL Console** 徽章。轻轻一点，即可打开 SQL Console 查询该数据集。

对 Magpie-Ultra 数据集做查询，获取高质量优秀推理指令。

所有工作都在浏览器中完成，且 console 附带一些巧妙特性：

- **100% 本地**：SQL Console 由 [DuckDB](https://duckdb.org/) WASM 驱动，无需任何依赖即可查询数据集。
- **完整的 DuckDB 语法**：DuckDB 支持[完整 SQL](https://duckdb.org/docs/sql/introduction.html)语法，并内建正则、列表、JSON、embedding 等大量函数。你会发现 DuckDB 语法与 PostgreSQL 非常相似。
- **导出结果**：可把查询结果导出为 parquet。
- **可分享**：公共数据集的查询结果可以通过链接分享。

## 工作原理

### Parquet 转换

Hugging Face 上的多数数据集以 Parquet 存储——一种为性能与存储效率优化的列式格式。Hugging Face 的 Dataset Viewer 和 SQL Console 直接从数据集的 Parquet 文件加载数据。如果数据集是其他格式，前 5GB 会自动转换为 Parquet。关于 Parquet 转换流程的更多信息见 [Dataset Viewer Parquet API 文档](https://huggingface.co/docs/dataset-viewer/en/parquet)。

基于这些 Parquet 文件，SQL Console 会按你的数据集 split 和 config 创建可供查询的视图。

### DuckDB WASM 🦆

[DuckDB WASM](https://duckdb.org/docs/api/wasm/overview.html) 是 SQL Console 的引擎。它是运行在浏览器 WebAssembly 中的进程内数据库引擎，无需服务器或后端。

完全在浏览器中运行，让用户拥有最大的灵活性——随喜好查询数据，无任何依赖；也让通过一条简单链接分享可复现结果变得极其容易。

你可能在想：「大数据集也能行吗？」答案是：能！

这是对 [OpenCo7/UpVoteWeb](https://huggingface.co/datasets/OpenCo7/UpVoteWeb) 数据集的一次查询，其 Parquet 转换后有 `12.6M` 行。

[![Reddit Movie Suggestions](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/sql_console/reddit-movie-suggestions.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/sql_console/reddit-movie-suggestions.png)

可以看到，一个简单过滤查询在 3 秒内就返回了结果。

虽然查询时间会随数据集规模和查询复杂度增长，但 SQL Console 能做到的事仍会让你惊讶。

与任何技术一样，它也有局限。

- SQL Console 能胜任很多查询。但内存上限约 3GB，因此可能内存不足、无法处理查询（*提示：尽量用过滤减少查询的数据量，并配合 `LIMIT`*）。
- 虽然 DuckDB WASM 很强大，但它与 DuckDB 并非完全功能对等。例如，DuckDB WASM 尚不支持[用 `hf://` 协议查询数据集](https://github.com/duckdb/duckdb-wasm/discussions/1858)。

### 示例：把数据集从 Alpaca 格式转换为对话格式

介绍完 SQL Console，我们来看一个实际例子。微调大语言模型（LLM）时，你常常需要处理不同的数据格式。一种特别流行的格式是对话（conversational）格式：每行表示用户与模型之间的多轮对话。SQL Console 能帮我们高效地把数据转换成这种格式。看看如何用 SQL 把 Alpaca 数据集转为对话格式。

通常开发者会用 Python 预处理来完成这个任务，但我们可以展示如何用 SQL Console 在 30 秒内达成同样效果。

在上述数据集中，点击 **SQL Console** 徽章打开 console。你会看到下面的查询已自动填充。

准备就绪后，点击 **Run Query** 按钮执行查询。

### SQL

```
-- Convert Alpaca format to Conversation format
WITH 
source_view AS (
  SELECT * FROM train  -- Change 'train' to your desired view name here
)
SELECT 
  [
    struct_pack(
      "from" := 'user',
      "value" := CASE 
                   WHEN input IS NOT NULL AND input != '' 
                   THEN instruction || '\n\n' || input
                   ELSE instruction
                 END
    ),
    struct_pack(
      "from" := 'assistant',
      "value" := output
    )
  ] AS conversation
FROM source_view
WHERE instruction IS NOT NULL 
AND output IS NOT NULL;
```

在这个查询中，我们用 `struct_pack` 函数为每个对话构造一个新的 STRUCT 行。

DuckDB 关于 `STRUCT` [数据类型](https://duckdb.org/docs/sql/data_types/struct.html)和[函数](https://duckdb.org/docs/sql/functions/struct.html)的文档非常完善。你会发现许多数据集含有 JSON 数据的列，DuckDB 提供了方便的函数来解析和查询这些列。
