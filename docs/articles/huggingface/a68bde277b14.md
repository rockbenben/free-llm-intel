## 总览

用 LoRA dreambooth 微调的 Stable Diffusion XL（SDXL）模型，只需少量图像就能极好地捕捉新概念，同时保持 SDXL 的美学与画质，而且所需算力和资源很少。可以在[这里](https://huggingface.co/spaces/multimodalart/LoraTheExplorer)欣赏一些很棒的 SDXL LoRA。在这篇博客里，我们将回顾一些流行的实践与技巧，让你的 LoRA 微调跑得更猛（go brrr），并演示如何用 diffusers 立刻训练你自己的 LoRA！

回顾：LoRA（Low-Rank Adaptation，低秩适应）是一种用于 Stable Diffusion 模型微调的技术，它对图像与提示词交汇的关键交叉注意力层做轻微调整。其质量可与完整微调的模型看齐，但速度快得多、所需算力也少得多。想了解更多 LoRA 的原理，请参考我们之前的文章——[Using LoRA for Efficient Stable Diffusion Fine-Tuning](https://huggingface.co/blog/lora)。

## Pivotal Tuning

[Pivotal Tuning](https://arxiv.org/abs/2106.05744) 是一种把 [Textual Inversion](https://arxiv.org/abs/2208.01618) 与常规扩散模型微调结合的方法。做 Dreambooth 时，通常要提供一个罕见 token 作为触发词，比如 "an sks dog"。但这些 token 往往自带其他语义，会影响结果。社区里流行的 sks 这个例子，实际关联的是一个武器品牌。

为解决这个问题，我们把新 token 插入模型的文本编码器，而不是复用已有 token。然后优化这些新插入的 token 嵌入来表示新概念：这就是 Textual Inversion——我们学习用嵌入空间中的新"词"来表示概念。一旦得到表示它的新 token 及其嵌入，就可以带着这些 token 嵌入去训练 Dreambooth LoRA，两全其美。

**训练**

在我们的新训练脚本中，提供以下参数即可进行文本反演训练：

```
--train_text_encoder_ti
--train_text_encoder_ti_frac=0.5
--token_abstraction="TOK"
--num_new_tokens_per_abstraction=2
--adam_weight_decay_text_encoder
```

- `train_text_encoder_ti`：开启新概念嵌入的训练
- `train_text_encoder_ti_frac`：指定何时停止文本反演（即停止优化文本嵌入、只继续优化 UNet）。中途切换（即前一半训练 epoch 做文本反演）是 cog sdxl 示例的默认值，我们的实验也验证了这一设置。鼓励大家多做尝试。
- `token_abstraction`：概念标识符，即在图像描述（caption）里用来指代要训练概念的单词。你选的 token_abstraction 必须与 instance prompt、validation prompt 或自定义 caption 中使用的保持一致。这里我们选了 TOK，比如 "a photo of a TOK" 可以是 instance prompt。由于 `--token_abstraction` 是占位符，训练前我们会把新 token 插入替换 `TOK` 的位置并对它们做优化（也就是说 "a photo of `TOK`" 在训练中会变成 "a photo of `<s0><s1>`"，其中 `<s0><s1>` 是新 token）。因此 `token_abstraction` 必须与 instance prompt、validation prompt 及自定义 prompt（若使用）中的标识符对应。`num_new_tokens_per_abstraction`：为每个 `token_abstraction` 初始化的新 token 数量——即对模型的每个文本编码器插入并训练多少个新 token。默认值为 2，鼓励大家实验并分享结果！
- `adam_weight_decay_text_encoder`：用于为文本编码器参数设置不同于 UNet 参数的 weight decay 值。

## 自适应优化器

训练/微调扩散模型（或其实任何机器学习模型）时，我们用优化器引路，朝训练目标的收敛点前进——即所选损失函数的最小值点，代表模型学到了我们要教的东西。深度学习任务的标准（也是 SOTA）选择是 Adam 和 AdamW 优化器。

但它们要求用户大量调校通往收敛路的超参数（如学习率、weight decay 等）。这可能带来耗时而结果欠佳（suboptimal）的实验；即便找到了理想的学习率，如果训练过程中学习率恒定，仍可能出现收敛问题。有些参数受益于更频繁的更新以加速收敛，另一些则需要更小的调整以避免冲过最优值。为应对这一挑战，出现了带自适应学习率的算法，如 **Adafactor** 和 [**Prodigy**](https://github.com/konstmish/prodigy)。这些方法根据各参数历史梯度动态调整其学习率，优化算法在损失曲面中的行进。

我们把重点放在 Prodigy 上，因为觉得它对 Dreambooth LoRA 训练特别有帮助！

**训练**

```
--optimizer="prodigy"
```

使用 prodigy 时，通常建议同时设置

```
--learning_rate=1.0
```

对扩散模型——尤其 LoRA 训练——被证明有益的其他设置：

```
--prodigy_safeguard_warmup=True
--prodigy_use_bias_correction=True
--adam_beta1=0.9
# Note these are set to values different than the default:
--adam_beta2=0.99 
--adam_weight_decay=0.01
```

用 prodigy 训练还可以调其他超参数（如 `--prodigy_beta3`、`prodigy_decouple`、`prodigy_safeguard_warmup`），本文不展开，详情见[这里](https://github.com/konstmish/prodigy)。

## 其他良好实践

除了 pivotal tuning 和自适应优化器，还有一些会影响训练 LoRA 质量的技术，它们全部已被整合进新的 diffusers 训练脚本。

### 文本编码器与 UNet 独立学习率

社区普遍认为，优化文本编码器时给它设置不同于 UNet 的学习率能带来更好的质量——具体来说是**更低**的文本编码器学习率，因为它*过拟合得更快*。在做 pivotal tuning 时，UNet 和文本编码器使用不同学习率的重要性也很明显——这种情况下，给文本编码器设**更高**的学习率反而更好。* 不过注意，使用 Prodigy（或一般的自适应优化器）时，我们从所有被训练参数完全相同的初始学习率出发，让优化器自己施展魔法 ✨

**训练**

```
--train_text_encoder
--learning_rate=1e-4 #unet
--text_encoder_lr=5e-5 
```

`--train_text_encoder` 开启完整的文本编码器训练（即文本编码器的权重被完全优化，区别于只优化插入嵌入的文本反演方式 `--train_text_encoder_ti`）。如果希望文本编码器学习率始终等于 `--learning_rate`，设置 `--text_encoder_lr=None` 即可。

### 自定义 Caption

用一组相同 instance prompt（如 "photo of a person" 或 "in the style of " 等）的图像训练也能取得不错效果，但如果概念复杂、模型对该概念不熟、或训练集没能很好覆盖概念，使用同一个 caption 可能导致欠佳结果。

**训练** 要使用自定义 caption，先确保已安装 datasets 库，否则可以这样安装——

```
!pip install datasets
```

要加载自定义 caption，你的训练集目录需要遵循 datasets `ImageFolder` 的结构，同时包含图像和每张图像对应的 caption。

- *选项 1*：从 Hub 上选一个已经包含图像和提示词的数据集——例如 [LinoyTsaban/3d_icon](https://huggingface.co/datasets/LinoyTsaban/3d_icon)。接下来只需在训练参数里指定数据集名和 caption 列名（这里是 "prompt"）：

```
--dataset_name=LinoyTsaban/3d_icon
--caption_column=prompt
```

- *选项 2*：你想用自己的图像并给它们加 caption。这时可以用[这个 colab notebook](https://colab.research.google.com/github/huggingface/notebooks/blob/main/diffusers/SDXL_Dreambooth_LoRA_advanced_example.ipynb)通过 BLIP 自动给图像打 caption，或手动在 metadata 文件里写 caption。之后同样地，把 `--dataset_name` 指定为你的文件夹路径，`--caption_column` 指定为 caption 的列名。

### Min-SNR Gamma 加权

扩散模型的训练常常收敛缓慢，部分原因是不同时间步（timesteps）的优化方向互相冲突。[Hang et al.](https://arxiv.org/abs/2303.09556) 通过引入简单的 Min-SNR-gamma 方法缓解了这个问题。该方法根据截断后的信噪比（signal-to-noise ratio）调整各时间步的损失权重，从而有效平衡时间步之间的冲突。* 对于小数据集，Min-SNR 加权策略的效果可能不明显，但对较大数据集效果大概率会更显著。* `snr vis` *可以看 [Weights and Biases 上的这个项目](https://wandb.ai/sayakpaul/text2image-finetune-minsnr)，它对比了 snr_gamma 设为 5.0、1.0 和 None 三种设置的损失曲面。*

**训练**

要使用 Min-SNR gamma，设置一个值：

```
--snr_gamma=5.0
```

默认 `--snr_gamma=None`，即不使用。开启 `--snr_gamma` 时推荐值为 5.0。

### Repeats（重复）

这个参数指数据集中的图像在训练集中被重复的次数。它与 epoch 的区别在于：先把图像重复，然后再洗牌（shuffle）。

**训练**

要启用重复，只需设一个大于 1 的整数作为重复次数——

```
--repeats
```

默认 `--repeats=1`，即训练集不重复。

### 训练集构建

- 常言道——"垃圾进，垃圾出"。用少量图像训练一个好的 Dreambooth LoRA 并不难，但这些图像的质量对微调后的模型影响极大。
- 一般而言，微调某个对象/主体时，要确保训练集包含尽可能多样地展示该对象/主体的图像——越接近你以后想要提示的形态越好。
- 例如，我的概念是这个红色背包（可在 [google/dreambooth](https://huggingface.co/datasets/google/dreambooth) 数据集中找到）：![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/dreambooth_backpack_01.jpg)
- 我大概率也想生成它被人背着的图，那么训练集中包含符合这一场景的这类示例：![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/dreambooth_backpack_02.jpg) 很可能让模型在推理时更容易泛化到该场景/构图。

*特别*是训练*人脸*时，关于你的数据集需要注意以下几点：

- 如果可能，总是选择**高分辨率、高质量**的图像。模糊或低分辨率的图像会伤害调优过程。
- 训练人脸时，建议训练集中不要出现其他人脸——我们不想造成"训练的是哪张脸"的歧义。
- **特写照片**对实现真实感很重要，但也应包含好的全身照，以提升对不同姿势/构图的泛化能力。
- 建议**避免主体距离太远的照片**，因为这类图像中大多数像素与我们要优化的概念无关，模型学不到多少东西。
- 避免重复的背景/服装/姿势——要追求**多样性**：打光、姿势、背景、表情都要有变化。多样性越高，LoRA 就越灵活、越具泛化性。
- **Prior preservation loss**——Prior preservation loss 是一种利用模型自身生成的样本帮助它学会生成更多样图像的方法。由于这些样本图像与你提供的图像属于同一类别，它们能帮助模型保留对该类别已有知识，并用这些知识组合出新的画面。***真实图像做正则 VS 模型生成的图像***：选择 class 图像时，你可以选合成的（即由扩散模型生成的）或真实的。支持真实图像的理由是：它们能提升微调模型的真实感。而另一派观点认为，使用模型生成的图像更好地服务于保留模型对该类别*以及整体美学的已有知识*这一目的。
- **Celebrity lookalike（名人替身）**——这更多是关于 captioning/instance prompt 的技巧。有微调者发现，在 token 标识符之外加一个基础模型认识的、与训练对象长相相似的公众人物，能改善结果。

**带 prior preservation loss 的训练**

```
--with_prior_preservation
--class_data_dir
--num_class_images
--class_prompt
```

`--with_prior_preservation` - 开启 prior preservation 训练
`--class_data_dir` - 存放 class 图像的文件夹路径
`--num_class_images` - prior preservation loss 所需的最少 class 图像数。如果 `--class_data_dir` 中已有的图像不够，会用 `--class_prompt` 采样补齐。

### 实验设置与结果

为了探索上述方法，我们在不同目标（风格调优、人脸、物体）上试验了这些技术的不同组合。

为了把近乎无限的超参数组合收窄，我们先用一些更流行、更常见的配置作为起点，再逐步调整。

**Huggy Dreambooth LoRA** 首先，我们想微调一个 huggy LoRA——意味着同时学习一种艺术风格和一个特定角色。这个例子里，我们策划了一个高质量 Huggy 吉祥物数据集（使用 Chunte-Lee 的精彩作品），包含 31 张配有自定义 caption 的图像。

配置：

```
--train_batch_size = 1, 2,3, 4
-repeats = 1,2
-learning_rate = 1.0 (Prodigy), 1e-4 (AdamW)
-text_encoder_lr = 1.0 (Prodigy), 3e-4, 5e-5 (AdamW)
-snr_gamma = None, 5.0 
-max_train_steps = 1000, 1500, 1800
-text_encoder_training = regular finetuning, pivotal tuning (textual inversion)
```

- 完整文本编码器微调 VS Pivotal Tuning——我们注意到 pivotal tuning 取得的效果与完整文本编码器训练相当甚至更好，而且无需优化 text_encoder 的权重。
- Min SNR Gamma——我们对比了[版本 1](https://wandb.ai/linoy/dreambooth-lora-sd-xl/runs/mvox7cqg?workspace=user-linoy)（不带 `snr_gamma` 训练）和[版本 2](https://wandb.ai/linoy/dreambooth-lora-sd-xl/runs/cws7nfzg?workspace=user-linoy)（带 `snr_gamma = 5.0` 训练）。具体来说两个版本都使用了以下参数（版本 2 额外加了 `snr_gamma`）：


**Y2K 网页 LoRA** 再看一个例子。这次的训练集由 27 张来自 90 年代和 2000 年代初的网页截图组成——这是我们带着 nostalgia（🥲）从互联网上抓取的：

配置：

```
–rank = 4,16,32
-optimizer = prodigy, adamW
-repeats = 1,2,3
-learning_rate = 1.0 (Prodigy), 1e-4 (AdamW)
-text_encoder_lr = 1.0 (Prodigy), 3e-4, 5e-5 (AdamW)
-snr_gamma = None, 5.0 
-train_batch_size = 1, 2, 3, 4
-max_train_steps = 500, 1000, 1500
-text_encoder_training = regular finetuning, pivotal tuning
```

这个例子表现出与上一个稍有不同行为。虽然两种情况使用的图像数量大致相同（都约 30 张），但我们发现对网页风格 LoRA，之前在 Huggy LoRA 上取得好效果的同样设置会造成过拟合。

对 v1，我们选取了训练 Huggy LoRA 时最有效的设置作为起点——结果明显过拟合，于是接下来通过调整 `--max_train_steps`、`--repeats`、`--train_batch_size` 和 `--snr_gamma` 在后续版本中纠正。具体来说，下面是各版本之间改动的设置（其余全部保持一致）：

| 参数 | v1 | v2 | v3 | v4 | v5 | v6 | v7 | v8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `max_train_steps` | 1500 | 1500 | 1500 | 1000 | 1000 | 1000 | 1000 | 1000 |
| `repeats` | 1 | 1 | 2 | 2 | 1 | 1 | 2 | 1 |
| `train_batch_size` | 4 | 4 | 4 | 4 | 2 | 1 | 1 | 1 |
| `instance_data_dir` | `web_y2k` | 从 `web_y2k` 随机抽取 14 张 | `web_y2k` | `web_y2k` | `web_y2k` | `web_y2k` | `web_y2k` | `web_y2k` |
| `snr_gamma` | 5.0 | 5.0 | 5.0 | 5.0 | - | - | 5.0 | 5.0 |

我们发现 v4、v5、v6 达到了最佳平衡。

**人脸 LoRA** 训练人脸图像时，我们的目标是让 LoRA 生成的图像尽可能真实、尽可能接近原型人物，同时也能很好地泛化到训练集中没见过的背景和构图。这个用例中，我们用了几个由 6-10 张 Linoy 人脸照片组成的数据集，包括同一时间拍摄的特写照片集，以及不同场合拍摄的照片集（背景、打光、服装都在变化）和全身照。我们发现：精挑细选的少量图像胜过质量平庸（打光/分辨率/对焦欠佳）的大量图像——少即是多：挑你最好的照片来训练模型！配置：

```
rank = 4,16,32, 64
optimizer = prodigy, adamW
repeats = 1,2,3,4
learning_rate = 1.0 , 1e-4
text_encoder_lr = 1.0, 3e-4
snr_gamma = None, 5.0
num_class_images = 100, 150
max_train_steps = 75 * num_images, 100 * num_images, 120 * num_images
text_encoder_training = regular finetuning, pivotal tuning
```

- Prior preservation loss——与常见做法相反，我们发现使用生成的 class 图像会降低对主体的相似度和真实感。我们用从 [unsplash](https://unsplash.com) 下载的免费授权图像制作了一个真实人像[数据集](https://huggingface.co/datasets/multimodalart/faces-prior-preservation)。现在你也可以在新的[训练 space](https://huggingface.co/spaces/multimodalart/lora-ease) 中自动使用它！使用真实图像数据集时，我们确实观察到更少的语言漂移（即模型不会把 woman/man 这些词只和训练过的那张脸绑定，也能生成其他人），同时保持了训练人脸的真实感和整体质量。
- Rank——我们对比了 rank 为 4、16、32、64 的 LoRA。在我们探索测试的设置中，64 rank LoRA 生成的图像更"磨皮"，皮肤纹理的真实感更差。因此在下面的实验以及 [LoRA ease space](https://huggingface.co/spaces/multimodalart/lora-ease) 中，我们默认使用 rank 32。
- 训练步数
- 即便少量高质量图像（在我们的例子里是 6 张）效果就很好，仍需确定理想训练步数。
- 我们试验了图像数量的几种乘数：6 x75 = 450 步 / 6 x100 = 600 步 / 6 x120 = 720 步。
- 如下图所示，我们的初步结果显示 120x 乘数效果最好（前提是数据集足够多样、不会过fit——尽量不要用同一次拍摄的照片）![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/diffusers/image_multiplier_comparison_linoy_loras.png) 上图展示了用 3 个 LoRA 生成的图像（除 `--max_train_steps` 外所有参数保持一致），具体配置为：

```
rank = 32
optimizer = prodigy
repeats = 1
learning_rate = 1.0
text_encoder_lr = 1.0
max_train_steps = 75 * num_images, 100 * num_images, 120 * num_images
train_text_encoder_ti
with_prior_preservation_loss
num_class_images = 150
```

## 推理

用上述技术训练的模型推理方式与任何 trainer 相同，区别在于做 pivotal tuning 时，除了 LoRA 的 `*.safetensors` 权重，还有模型一起训练的新 token 文本嵌入 `*.safetensors`。要用它们推理，我们在常规加载 LoRA 的步骤前加 2 步：

1. 从 hub 下载训练好的嵌入（嵌入文件名默认是 `{model_name}_emb.safetensors`）

```
import torch
from huggingface_hub import hf_hub_download
from diffusers import DiffusionPipeline
from safetensors.torch import load_file

pipe = DiffusionPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0",
    torch_dtype=torch.float16,
    variant="fp16",
).to("cuda")

# download embeddings
embedding_path = hf_hub_download(repo_id="LinoyTsaban/web_y2k_lora", filename="web_y2k_emb.safetensors", repo_type="model")
```

2. 把嵌入加载进文本编码器

```
# load embeddings to the text encoders
state_dict = load_file(embedding_path)
# notice we load the tokens <s0><s1>, as "TOK" as only a place-holder and training was performed using the new initialized tokens - <s0><s1>
# load embeddings of text_encoder 1 (CLIP ViT-L/14)
pipe.load_textual_inversion(state_dict["clip_l"],
    token=["<s0>", "<s1>"],
    text_encoder=pipe.text_encoder, tokenizer=pipe.tokenizer)
# load embeddings of text_encoder 2 (CLIP ViT-G/14)
pipe.load_textual_inversion(state_dict["clip_g"],
    token=["<s0>", "<s1>"],
    text_encoder=pipe.text_encoder_2, tokenizer=pipe.tokenizer_2)
```

3. 加载你的 LoRA 并提示它！

```
# normal LoRA loading
pipe.load_lora_weights("LinoyTsaban/web_y2k_lora", weight_name="pytorch_lora_weights.safetensors")

prompt="a <s0><s1> webpage about an astronaut riding a horse"
images = pipe(
    prompt,
    cross_attention_kwargs={"scale": 0.8},
).images

# your output image
images[0]
```

### Comfy UI / AUTOMATIC1111 推理

新脚本完整支持以 Comfy UI 和 AUTOMATIC1111 格式加载文本反演！

**AUTOMATIC1111 / SD.Next**

在 AUTOMATIC1111/SD.Next 中，我们会同时加载一个 LoRA 和一个文本嵌入。

*LoRA*：除了 diffusers 格式，脚本还会训练一个 WebUI 兼容的 LoRA，生成为 `{your_lora_name}.safetensors`。你可以把它放进 `models/Lora` 目录。

*Embedding*：嵌入文件在 diffusers 和 WebUI 之间通用。你可以从训练好的模型下载 `{lora_name}_emb.safetensors` 文件，放进 `embeddings` 目录。

然后可以通过提示 `a y2k_emb webpage about the movie Mean Girls <lora:y2k:0.9>` 来推理。`y2k_emb` token 可以正常使用，包括用 `(y2k_emb:1.2)` 提高它的权重。

**ComfyUI**

在 ComfyUI 中，我们同样同时加载一个 LoRA 和一个文本嵌入。

*LoRA*：除了 diffusers 格式，脚本还会训练一个 ComfyUI 兼容的 LoRA，生成为 `{your_lora_name}.safetensors`。把它放进 `models/Lora` 目录，然后加载 LoRALoader 节点，与 model 和 CLIP 连起来。[加载 LoRA 的官方指南](https://comfyanonymous.github.io/ComfyUI_examples/lora/)

*Embedding*：嵌入文件在 diffusers 和 WebUI 之间通用。你可以从训练好的模型下载 `{lora_name}_emb.safetensors` 文件，放进 `models/embeddings` 目录，在提示词中以 `embedding:y2k_emb` 的形式使用。[加载嵌入的官方指南](https://comfyanonymous.github.io/ComfyUI_examples/textual_inversion_embeddings/)
