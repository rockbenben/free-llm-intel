## 引言

图形用户界面（GUI）自动化是计算机视觉最具挑战性的前沿之一。让模型能"看懂"并与用户界面交互，将使 AI 智能体能够导航移动端、桌面端和 Web 平台。这会重塑数字交互的未来。

本文给出一套训练视觉-语言模型做 GUI 自动化的完整方法，采用多阶段训练策略。我们演示如何把一个完全没有 grounding 能力的模型，变成能理解并与图形界面交互的 agentic 编码智能体。

我们不追求 SOTA 模型，目标是把整个过程——从数据处理到模型训练——完整走一遍，借此展示如何解锁 VLM 的 GUI grounding 能力。

[![GUI capabilities combine understanding of the interface and precise element localization. These abilities enable the model to translate high-level tasks into low-level GUI actions such as clicking, typing, …](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/smol2operator/google.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/smol2operator/google.png)

*GUI 能力 = 对界面的理解 + 精确的元素定位。这两种能力让模型能把高层任务翻译成点击、输入等低层 GUI 动作。*

我们的方案以 [**SmolVLM2-2.2B-Instruct**](https://huggingface.co/HuggingFaceTB/SmolVLM2-2.2B-Instruct) 为基线模型——一个小巧强力的视觉-语言模型，最初对 GUI 任务没有任何 grounding 能力，正是展示我们训练方法论效果的理想候选。通过两阶段训练，我们先给模型注入 grounding 能力，再用监督微调（SFT）增强其 agentic 推理能力。

我们在成熟的感知基准 [**ScreenSpot-v2**](https://huggingface.co/datasets/HongxinLi/ScreenSpot_v2) 上评估——它考验模型理解截图并在其中定位元素的能力。我们的流程受 [AGUVIS](https://huggingface.co/papers/2412.04454) 论文启发，并借助其精编数据集在其基础工作之上继续构建。

[![Evolution of ScreenSpot-v2 performance during the training phase of the base model SmolVLM2-2.2B-Instruct.](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/smol2operator/screenspot-v2.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/smol2operator/screenspot-v2.png)

## 1. 数据转换与统一动作空间

*本节说明我们如何**把多个数据集里异构的 GUI 动作格式转换成统一格式**。通过标准化函数名、签名和参数，我们造出一致、高质量的数据，为有效模型训练打下基础。*

### 不一致动作空间的挑战

处理多个 GUI 自动化数据集时的首要挑战，是动作表示缺乏标准化：不同数据集用不同的函数签名、参数命名约定和动作分类法，让跨数据源训练统一模型非常困难。

### 我们的统一方案

我们取 AGUVIS（[论文](https://huggingface.co/papers/2412.04454)）最初使用的开源数据集（[xlangai/aguvis-stage1](https://huggingface.co/datasets/xlangai/aguvis-stage1)、[xlangai/aguvis-stage2](https://huggingface.co/datasets/xlangai/aguvis-stage2)），实现了完整的数据转换管道来构建统一动作空间。做法包括：

- **函数解析与归一化**：开发了函数解析器（见 `utils/function_parser.py`），能从各数据集的各种格式中提取并解析函数调用。解析器支持任意函数签名格式、处理复杂参数结构，并能按正确参数顺序重建函数调用。
- **动作空间统一**：实现了完整的动作转换系统（见 `preprocessing/action_conversion.py`），把所有原始动作表示转换为标准化的函数命名和参数结构。这一过程凸显了不同数据集函数签名的巨大不一致，并让我们得以：去掉不需要或冗余的动作；统一参数命名约定；构建内聚的动作词汇表。
- **（加分项）灵活适配框架**：转换管道还包含一些工具，允许用户用 `utils/action_space_converter.py` 把整个数据集适配到自己的动作空间命名约定，或提取并分析当前动作空间结构。

### 数据转换示例

下面是动作转换系统（`preprocessing/action_conversion.py`）的真实例子，展示如何把异构动作表示转成统一格式（grounding 坐标归一化到 [0,1]）：

**转换前（原始动作数据集格式）：**

```
# Mobile Actions
mobile.home()
mobile.open_app(app_name='drupe')
mobile.swipe(from_coord=[0.581, 0.898], to_coord=[0.601, 0.518])
mobile.long_press(x=0.799, y=0.911)
mobile.terminate(status='success')
# Desktop Actions
pyautogui.click(x=0.8102, y=0.9463)
pyautogui.doubleClick(x=0.8102, y=0.9463)
pyautogui.hotkey(keys=['ctrl', 'c'])
pyautogui.scroll(page=-0.1)
pyautogui.write(message='bread buns')
pyautogui.dragTo(from_coord=[0.87, 0.423], to_coord=[0.8102, 0.9463])
```

**转换后（统一动作数据集格式）：**

```
# Unified Mobile Actions
navigate_home()
open_app(app_name='drupe')
swipe(from_coord=[0.581, 0.898], to_coord=[0.601, 0.518])
long_press(x=0.799, y=0.911)
final_answer('success')
# Unified Desktop Actions
click(x=0.8102, y=0.9463)
double_click(x=0.8102, y=0.9463)
press(keys=['ctrl', 'c'])
scroll(direction='up', amount=10)  # Smart direction detection
type(text='bread buns')
drag(from_coord=[0.87, 0.423], to_coord=[0.8102, 0.9463])
```

这一统一过程至关重要——只有它才能造出连贯的训练数据，让模型在多样 GUI 环境中学到一致的动作模式。

💡 为什么用归一化坐标？

在文本-动作数据点里使用原始像素坐标（如

click(x=302, y=63)

）会把它们绑定到单一图像尺寸。视觉-语言模型（VLM）经常缩放图像，导致像素坐标失效、需要调整。归一化坐标（相对图像尺寸）在任何分辨率下都有效，能让数据集保持一致。

### （加分项）用 Action Space Converter 适配自定义动作空间

为了在不同用例下最大化灵活性，我们开发了 **Action Space Converter**（`utils/action_space_converter.py`），让用户轻松地把动作空间适配到自己的动作词汇表和命名约定。

你可以用它把一种动作签名（函数名、参数名、参数取值变化……）转换成另一种：

**转换前**

```
assistant_message: "Action: click(x=0.5, y=0.3)"
```

**转换后**

```
assistant_message: "Action: touch(x_coord=200, y_coord=300)"
```

### 关键特性

Action Space Converter 提供：

- **可配置映射**：定义统一动作与你偏好的动作名之间的自定义映射
- **参数变换**：重命名参数、做值变换、设默认值
- **灵活架构**：既支持简单参数映射，也支持复杂的自定义变换函数
- **校验**：内置验证，确保映射配置合法

### 使用示例

```
from utils.action_space_converter import ActionSpaceConverter, ActionMapping, ParameterMapping
from utils.function_parser import parse_function_call

# Create custom mappings
mappings = [
    ActionMapping(
        source_function="click",
        target_function="touch",
        parameter_mappings=[
            ParameterMapping(source_name="x", target_name="x_coord"),
            ParameterMapping(source_name="y", target_name="y_coord")
        ],
        description="Touch screen at coordinates"    ),
    ActionMapping(
        source_function="type", # source_function is the name of the function in the original function call
        target_function="write", # target_function is the name of the function in the target function call        
        parameter_mappings=[
            ParameterMapping(source_name="text", target_name="content")
            # source_name is the name of the parameter in the original function call            
            # target_name is the name of the parameter in the target function call        
        ],
        description="Input text"    
    )
]

assistant_message = "I'll interact at those coordinates for you. click(x=0.5, y=0.3) Now I'll input the text. type(text='hello world')"

# Parse function calls
parsed_function_calls = parse_function_call(text)

# Initialize converter
converter = ActionSpaceConverter(mappings)

# Convert actions
converted_actions = converter.convert_actions(parsed_function_calls)
for new_function_call, old_function_call in zip(converted_actions, parsed_function_calls):
    text = text.replace(old_function_call.to_string(), new_function_call.to_string())

print(text)
# Output: I'll interact at those coordinates for you. touch(x_coord=0.5, y_coord=0.3) Now I'll input the text. write(content='hello world')
```

这个工具让研究者和从业者能够：

- **定制训练数据**：把数据集适配到自己的动作词汇表要求
- **领域适配**：为不同平台（移动 vs 桌面 vs Web）变换动作
- **框架集成**：轻松把训练数据对齐到既有自动化框架
- **快速实验**：迅速测试不同动作空间配置
- **发布准备**：用一致的命名约定为标准化的生产部署准备动作空间

Action Space Converter 在准备训练数据集时尤其有价值：它保证不同部署环境下动作词汇表一致，同时兼容既有自动化框架。

## 2. 阶段 1：从零到感知

### 训练数据

阶段 1 使用 [smolagents/aguvis-stage-1](https://huggingface.co/datasets/smolagents/aguvis-stage-1) 数据集。它通过把低层指令与多样的可执行动作（以代码形式表达）配对，引入 **GUI grounding**。例如，[smolagents/aguvis-stage-1](https://huggingface.co/datasets/smolagents/aguvis-stage-1) 中一个 user/assistant 轮次的结构：

```
{
  "user": "click on more button",
  "assistant": "click(x=0.8875, y=0.2281)",
}
```

每个样本把一张截图与多轮 user/assistant 交互关联起来，让模型跨对话轮次学习细粒度的动作 grounding。微调时，data collator 在计算损失时把除 assistant 回答外的一切都掩码掉。

### 优化实验

在进行完整的阶段 1 训练前，我们做了大量消融实验以确定最优训练配置。

### 图像分辨率与坐标系分析

我们实验了不同图像尺寸和坐标表示系统，找出 SmolVLM2 的最优配置：

- **测试的图像尺寸**：384px、768px、1152px
- **坐标系**：像素坐标 vs 归一化坐标（0-1 范围）
- **训练数据**：来自 Aguvis 数据集的 40 万样本

> 一些 SOTA 的 GUI VLM（如 Qwen-VL）似乎还使用另一种归一化范围（0–1000），本实验未测试。

| 配置（坐标 / 图像尺寸） | Screenspot-v2 (%) |
| --- | --- |
| *归一化坐标* |  |
| Base / – | 0.47 |
| 384 | 31.28 |
| 764 | 32.32 |
| 1152 | **33.72** |
| *像素坐标* |  |
| Base / – | 0.55 |
| 384 | 1.17 |
| 764 | 2.67 |
| 1152 | 4.32 |

**表 1：** *基线 HuggingFaceTB/SmolVLM2-2.2B-Instruct（40 万样本，aguvis-stage-1）。越高越好。*

*正如基准结果所示，SmolVLM2-2.2B-Instruct 基座最初在 ScreenSpot-v2 这类感知基准上为 0% 表现。这种 grounding 能力的完全缺失，给了我们一块干净的画布来评估训练方法论的效果。*

### 关键发现

从实验我们确定：

- **图像尺寸**：1152px
- **坐标系**：归一化坐标（0-1 范围）对 SmolVLM2 最有效
- 注意：像素坐标与归一化坐标的取舍，可能随基座模型的预训练方式而变

### 阶段 1 结果

用最优配置（1152px 分辨率 + 归一化坐标），我们在 smolagents/aguvis-stage-1 上训练 2 个 epoch。结果显著：**ScreenSpot-v2 相对基线提升 +41%**。

这一巨大提升说明阶段 1 训练成功为模型注入了基本的 grounding 能力，使其能理解并在截图中定位视觉元素。

| 配置（坐标 / 图像尺寸） | Screenspot-v2 (%) |
| --- | --- |
| 归一化坐标 / 1152 | 41.27 |

**表 2：** *基线 HuggingFaceTB/SmolVLM2-2.2B-Instruct（2 epoch，aguvis-stage-1）。*

## 3. 阶段 2：从感知到认知

阶段 1 给了模型 grounding 能力，阶段 2 瞄准 **agentic 推理**——行动前深思和规划的能力。这一阶段把模型从识别 GUI 元素的被动系统，变成能执行复杂多步交互的主动智能体。

### 训练数据

阶段 2 使用 [smolagents/aguvis-stage-2](https://huggingface.co/datasets/smolagents/aguvis-stage-2) 数据集，引入 agentic 场景：

- 对即将执行的动作进行**显式推理**
- 跨多个交互步保持**上下文一致性**
- **高层指令**需要多步低层动作来完成。

例如，[smolagents/aguvis-stage-2](https://huggingface.co/datasets/smolagents/aguvis-stage-2) 的聊天消息长这样：

```
{
  "system": "You are a helpful GUI agent. ...",
  "user": "Please generate the next move according to the UI screenshot, instruction and previous actions.\n\nInstruction: What information does the site provide about Judith Lauand's career, works and exhibitions?\n\nPrevious actions:\nNone",
  "assistant": "<think>\nClick on the link labeled 'Judith Lauand: Brazilian 1922-2022' to explore more about her career and exhibitions.\n</think>\n<code>\nclick(x=0.41, y=0.178)\n</code>",
}
```

每个样本把截图与 system/user/assistant 轮次关联。微调时，data collator 在计算损失时把除 assistant 回答外的一切掩码掉。

### 阶段 2 结果

从阶段 1 检查点（1152px 分辨率、归一化坐标）出发，我们在 [smolagents/aguvis-stage-2](https://huggingface.co/datasets/smolagents/aguvis-stage-2) 上微调 2 个 epoch。**ScreenSpot-v2 准确率从 41% 提升到 61%**，说明显式推理改善了 GUI grounding 表现。

| 配置（坐标 / 图像尺寸） | Screenspot-v2 (%) |
| --- | --- |
| 归一化坐标 / 1152 | 61.71 |

**表 2：** *HuggingFaceTB/SmolVLM2-2.2B-Instruct 在阶段 1 微调后的基线（2 epoch，aguvis-stage-1）。*

## 4. 你需要的只是开源

所有训练代码、数据管道、数据集和模型全部开源！

- **训练配方**（[`recipe.ipynb`](https://github.com/huggingface/smol2operator/blob/main/recipe.ipynb)）：阶段 1 和阶段 2 的完整训练管道，含数据集混合配置与训练编排。我们用 [TRL](https://huggingface.co/docs/trl/en/index) 库训练模型。
- **数据集**（[`smolagents/aguvis-stage-1`](https://huggingface.co/datasets/smolagents/aguvis-stage-1)、[`smolagents/aguvis-stage-2`](https://huggingface.co/datasets/smolagents/aguvis-stage-2)）：所用数据集全部开源。
- **模型**（[`smolagents/SmolVLM2-2.2B-Instruct-Agentic-GUI`](https://huggingface.co/smolagents/SmolVLM2-2.2B-Instruct-Agentic-GUI)）：按上述训练配方产出的模型。
- **预处理工具**：**Function Parser**（[`utils/function_parser.py`](https://github.com/huggingface/smol2operator/blob/main/utils/function_parser.py)）：从各种数据集格式中解析、归一化并重建函数调用的工具，支持复杂参数结构、位置参数和多函数调用提取。**动作转换系统**（[`preprocessing/action_conversion.py`](https://github.com/huggingface/smol2operator/blob/main/preprocessing/action_conversion.py)）：核心统一引擎，把移动端和 PyAutoGUI 桌面动作转换为标准化 API 格式，具备智能坐标处理、滚动动作的方向检测和全面的参数归一化。**Action Space Converter**（[`utils/action_space_converter.py`](https://github.com/huggingface/smol2operator/blob/main/utils/action_space_converter.py)）：把统一动作空间适配到自定义词汇表与命名约定的灵活工具，通过可配置参数映射实现领域定制。

## 5. 结论

我们的实验表明：仅用监督微调（SFT），高质量、面向推理的数据就能显著提升 GUI grounding——即使对小 VLM 也是如此。除性能收益之外，这些结果说明 GUI grounding 能力在很大程度上由数据质量决定：精编的数据集教会模型用户界面的结构与语义，为准确的动作预测提供锚定。

为支持 GUI 智能体的发展，我们把一切都开源了：完整管道、数据集和训练好的模型。你可以复现我们的结果，尝试不同的模型与架构，或把我们的方法适配到新领域。agentic AI 的未来，取决于像你一样不断拓展边界的研究者！
