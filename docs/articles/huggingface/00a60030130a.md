# 用 Optimum-Intel 和 OpenVINO GenAI 优化与部署模型

在边缘或客户端部署 Transformers 模型时，性能和兼容性都需要仔细权衡。Python 虽然强大，但并非这类部署的理想选择，尤其是在以 C++ 为主的环境中。本文将指导你如何使用 Optimum-Intel 和 OpenVINO™ GenAI 优化并部署 Hugging Face Transformers 模型，以最少依赖实现高效 AI 推理。

## 为什么用 OpenVINO™ 做边缘部署

OpenVINO™ 最初就是作为 C++ AI 推理方案开发的，非常适合边缘和客户端部署——在这些场景里尽量减少依赖至关重要。随着 GenAI API 的推出，把大语言模型（LLM）集成进 C++ 或 Python 应用变得更加简单，其特性专为简化部署和提升性能而设计。

## 步骤 1：环境准备

## 前置条件

首先确保环境已正确配置好 Python 和 C++。安装所需的 Python 包：

```
pip install --upgrade --upgrade-strategy eager "optimum[openvino]"
```

本文用到的具体包版本：

```
transformers==4.44
openvino==24.3
openvino-tokenizers==24.3
optimum-intel==1.20
lm-eval==0.4.3
```

GenAI C++ 库的安装请按[这里](https://docs.openvino.ai/2024/get-started/install-openvino/install-openvino-genai.html)的说明操作。

## 步骤 2：导出模型到 OpenVINO IR

Hugging Face 与 Intel 的合作催生了 [Optimum-Intel](https://huggingface.co/docs/optimum/en/intel/index) 项目，专为在 Intel 硬件上优化 Transformers 推理而设计。Optimum-Intel 支持 OpenVINO 作为推理后端，其 API 为多种模型架构提供了基于 OpenVINO 推理 API 的封装。这些封装都以 `OV` 前缀开头，例如 `OVModelForCausalLM`。除此之外，它与 🤗 Transformers 库的 API 基本一致。

把 Transformers 模型导出为 OpenVINO 中间表示（IR）有两种途径：可以用 Python 的 `.from_pretrained()` 方法，也可以用 Optimum 命令行工具（CLI）。下面分别给出两种方法的示例：

### 使用 Python API

```
from optimum.intel import OVModelForCausalLM

model_id = "meta-llama/Meta-Llama-3.1-8B"
model = OVModelForCausalLM.from_pretrained(model_id, export=True)
model.save_pretrained("./llama-3.1-8b-ov")
```

### 使用命令行（CLI）

```
optimum-cli export openvino -m meta-llama/Meta-Llama-3.1-8B ./llama-3.1-8b-ov
```

`./llama-3.1-8b-ov` 文件夹会包含 `.xml` 和 `bin` 的 IR 模型文件，以及来自源模型的必需配置文件。🤗 tokenizer 也会被转换为 `openvino-tokenizers` 库的格式，相应配置文件生成在同一文件夹中。

## 步骤 3：模型优化

在资源受限的边缘和客户端设备上运行 LLM 时，强烈建议进行模型优化。仅量化权重（weight-only quantization）是主流方法，能显著降低延迟和模型体积。Optimum-Intel 通过 Neural Network Compression Framework（NNCF）提供仅权重量化能力，其中包含多种专为 LLM 设计的优化技术：从免数据的 INT8 和 INT4 权重量化，到 [AWQ](https://huggingface.co/docs/transformers/main/en/quantization/awq)、[GPTQ](https://huggingface.co/docs/transformers/main/en/quantization/gptq)、量化缩放估计（quantization scale estimation）、混合精度量化等数据感知方法。默认情况下，参数量超过十亿的模型权重会被量化为对精度安全的 INT8。也就是说，前面描述的导出步骤产出的是 8-bit 权重模型。不过，4-bit 仅权重量化能带来更好的精度-性能权衡。

对于 `meta-llama/Meta-Llama-3.1-8B` 模型，我们推荐组合使用 AWQ、量化缩放估计，并配合一个反映实际部署场景的校准数据集做混合精度 INT4/INT8 权重量化。与导出一样，给 LLM 应用 4-bit 仅权重量化也有两种途径：

### 使用 Python API

- 在 `.from_pretrained()` 方法中指定 `quantization_config` 参数。此时需要创建 `OVWeightQuantizationConfig` 对象并赋给该参数，如下所示：

```
from optimum.intel import OVModelForCausalLM, OVWeightQuantizationConfig

MODEL_ID = "meta-llama/Meta-Llama-3.1-8B"
quantization_config = OVWeightQuantizationConfig(bits=4, awq=True, scale_estimation=True, group_size=64, dataset="c4")
model = OVModelForCausalLM.from_pretrained(MODEL_ID, export=True, quantization_config=quantization_config)
model.save_pretrained("./llama-3.1-8b-ov")
```

### 使用命令行（CLI）

```
optimum-cli export openvino -m meta-llama/Meta-Llama-3.1-8B --weight-format int4 --awq --scale-estimation --group-size 64 --dataset wikitext2 ./llama-3.1-8b-ov
```

> 注意：模型优化过程可能耗时较长，因为它会依次应用多种方法，并需要在指定数据集上执行模型推理。

用 API 做模型优化更灵活，可以使用自定义数据集——例如把它们作为可迭代对象传入，既可以是 🤗 库的 `Dataset` 对象实例，也可以就是一个字符串列表。

权重量化通常会造成精度指标的某些下降。为了比较优化后模型与源模型，我们在 [Wikitext](https://huggingface.co/datasets/EleutherAI/wikitext_document_level) 数据集上测量 Word Perplexity（词困惑度）指标，使用 [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness.git) 项目——它开箱即用地支持 🤗 Transformers 和 Optimum-Intel 模型。

| 模型 | PPL PyTorch FP32 | OpenVINO INT8 | OpenVINO INT4 |
| --- | --- | --- | --- |
| meta-llama/Meta-Llama-3.1-8B | 7.3366 | 7.3463 | 7.8288 |

## 步骤 4：用 OpenVINO GenAI API 部署

完成转换和优化后，用 OpenVINO GenAI 部署模型非常直接。OpenVINO GenAI 的 LLMPipeline 类同时提供 Python 和 C++ API，以最少的依赖支持多种文本生成方式。

### Python API 示例

```
import argparse
import openvino_genai

device = "CPU"  # GPU can be used as well
pipe = openvino_genai.LLMPipeline(args.model_dir, device)
config = openvino_genai.GenerationConfig()
config.max_new_tokens = 100
print(pipe.generate(args.prompt, config))
```

运行这个示例只需在 Python 环境中安装最少的依赖，因为 OpenVINO GenAI 的设计目标就是轻量部署。你可以把 OpenVINO GenAI 包装进同一个 Python 环境，也可以单独建一个环境以对比应用的依赖体积：

```
pip install openvino-genai==24.3
```

### C++ API 示例

来看看如何用 OpenVINO GenAI C++ API 运行同一个 pipeline。GenAI API 的设计直观，可以从 🤗 Transformers API 无缝迁移。

> 注意：下面示例中的 "device" 变量可以指定你环境中任何可用设备。例如，如果你使用的是带集成显卡的 Intel CPU，"GPU" 也值得一试。要查看可用设备，可以使用 ov::Core::get_available_devices 方法（参见 query-device-properties）。

```
#include "openvino/genai/llm_pipeline.hpp"
#include <iostream>

int main(int argc, char* argv[]) {
   std::string model_path = "./llama-3.1-8b-ov";
   std::string device = "CPU"  // GPU can be used as well
   ov::genai::LLMPipeline pipe(model_path, device);
   std::cout << pipe.generate("What is LLM model?", ov::genai::max_new_tokens(256));
}
```

### 自定义生成配置

`LLMPipeline` 还支持通过 `ov::genai::GenerationConfig` 指定自定义生成选项：

```
ov::genai::GenerationConfig config;
config.max_new_tokens = 256;
std::string result = pipe.generate(prompt, config);
```

借助 LLMPipeline，用户不仅能轻松使用 Beam Search 等各种解码算法，还可以配合 Streamer 构建交互式对话场景，如下例所示。此外，LLMPipeline 的内部优化也值得利用：通过聊天方法 start_chat() 和 finish_chat() 复用此前聊天历史的 KV cache，可以缩短提示词处理时间（参见 [using-genai-in-chat-scenario](https://docs.openvino.ai/2024/learn-openvino/llm_inference_guide/genai-guide.html#using-genai-in-chat-scenario)）。

```
ov::genai::GenerationConfig config;
config.max_new_tokens = 100;
config.do_sample = true;
config.top_p = 0.9;
config.top_k = 30;

auto streamer = [](std::string subword) {
    std::cout << subword << std::flush;
    return false;
};

// Since the streamer is set, the results will
// be printed each time a new token is generated.
pipe.generate(prompt, config, streamer);
```

最后看看如何在聊天场景中使用 LLMPipeline：

```
pipe.start_chat()
for (size_t i = 0; i < questions.size(); i++) {
   std::cout << "question:\n";
   std::getline(std::cin, prompt);

   std::cout << pipe.generate(prompt) << std::endl;
}
pipe.finish_chat();
```
