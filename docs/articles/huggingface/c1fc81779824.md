（为简单起见，我们省略批次维度，并假设下面 `flash_attn_func` 的输入和输出都是三维张量 `(tokens, heads, head dimension)`。属于同一 GQA 组的 head 在输出中连续排列）

**注意：DIFF V2 相减的两个 head 位于同一 GQA 组，即它们共享同样的 key 和 value。这对性能至关重要。** 见设计消融一节和 Github 代码。

```
def DiffAttnV1(
        layer_index, q1, q2, k1, k2, v,
        lam_q1, lam_k1, lam_q2, lam_k2,
):
        """
      q1, q2: (N, h/2, d)
      k1, k2: (N, h_kv/2, d)
      v:      (N, h_kv/2, 2d)
      lam_*: (d,)
      """
      attn1 = flash_attn_func(q1, k1, v)
        attn2 = flash_attn_func(q2, k2, v)
        
        lam_init = 0.8 - 0.6 * \
            exp(-0.3 * layer_index)
        lam1 = exp(sum(lam_q1 * lam_k1)
    lam2 = exp(sum(lam_q2 * lam_k2)
    lam = lam1 - lam2 + lam_init
    attn = attn1 - lam * attn2
    
    attn = rmsnorm(attn)
    attn = attn * (1 - lam_init)
    return attn
```

```
def DiffAttnV2(
        q, k, v, lam
):
        """
      q:   (N, 2h, d)
      k:   (N, h_kv, d)
      v:   (N, h_kv, d)
      lam: (N, h, 1)
      """
        
        attn = flash_attn_func(q, k, v)
        attn1, attn2 = (attn[:, 0::2], 
                        attn[:, 1::2])
        
        lam_val = sigmoid(lam)
        attn = attn1 - lam_val * attn2
    return attn
```

完整代码见：[unilm/Diff-Transformer/Diff-Transformer-V2 at master · microsoft/unilm](https://github.com/microsoft/unilm/tree/master/Diff-Transformer/Diff-Transformer-V2)。脚本中 `h` 表示 query head 数量，`h_kv` 表示 key-value head 数量，`d` 是 head 维度。DIFF V2 中的 λ\lambdaλ 对每个 token、每个 head 从 XXX 投影得到。

DIFF V2 在保持 key-value head 数量不变的前提下把 query head 数量翻倍，差分操作后多出的维度被压缩回 `h*d`，因此 W_O 投影与基线 Transformer 保持一致。

## 动机

### **更快解码 & 无需定制 kernel**

与基线 Transformer 相比，DIFF V2 引入了额外的 query head，**但没有增加 key-value（KV）head 的数量**。由于 LLM 解码通常是内存受限的，这一设计让 DIFF V2 的解码速度能与标准 Transformer 持平。**此外，由于 query、key、value 的 head 维度是对齐的，DIFF V2 不需要定制的注意力 kernel。** 相比之下，DIFF V1 解码时可能更慢：value cache 必须加载两次，而且需要定制注意力 kernel。DIFF V2 还能提升解码时注意力模块的算术强度。

**预训练期间**，在 H 系列和 B 系列 GPU 上使用最新的 FlashAttention kernel 时，DIFF V2 引入的吞吐损失可以忽略。**长序列 prefill 场景**，我们建议把 DIFF V2 与 [YOCO](https://arxiv.org/abs/2405.05254) 这类技术结合（[Gemma 3n](https://github.com/huggingface/transformers/blob/main/src/transformers/models/gemma3n/modeling_gemma3n.py) 也用了它），YOCO 已能把 prefill 复杂度降到关于序列长度的线性。

**另一种视角是把 DIFF V2 与一个具有相同 query 维度 `2h*d` 的 Transformer 对比。** 在这种对比下，两个模型的注意力 kernel 速度相同，而 DIFF V2 在输出投影上拥有更少的参数和 FLOPs。

### **Softmax 幅值约束**

在标准缩放点积注意力（SDPA）中，设 Q,K,V∈Rn×dQ, K, V \in \mathbb{R}^{n \times d}Q,K,V∈Rn×d 为 queries、keys 和 values。上下文向量 CCC 定义为：

C=Softmax(QKTd)V=AV C = \text{Softmax}\left(\frac{QK^T}{\sqrt{d}}\right)V = AV C=Softmax(d​QKT​)V=AV

其中 A∈Rn×nA \in \mathbb{R}^{n \times n}A∈Rn×n 是注意力权重矩阵。我们聚焦 CCC 的某一行 ci\mathbf{c}_ici​，它是 value 向量 vj\mathbf{v}_jvj​ 的加权和：

ci=∑j=1naijvj \mathbf{c}_i = \sum_{j=1}^{n} a_{ij} \mathbf{v}_j ci​=j=1∑n​aij​vj​

我们定义**上下文 RMS**（均方根）来表示这个输出的幅值：

RMS(ci)=1d∥ci∥2 \text{RMS}(\mathbf{c}_i) = \sqrt{\frac{1}{d} \|\mathbf{c}_i\|^2} RMS(ci​)=d1​∥ci​∥2​​

权重 aija_{ij}aij​ 非负且和为 1（ ∑j=1naij=1\sum_{j=1}^{n} a_{ij} = 1∑j=1n​aij​=1 ）。假设 value 向量 vj\mathbf{v}_jvj​ 互不相关且 RMS 为 1，那么**无论注意力分布如何变化，上下文 RMS 都被严格限制在 [1n,1)[\frac{1}{\sqrt{n}},1)[n​1​,1) 区间内**：

- 如果注意力完全集中在一个 token 上，上下文 RMS 为 111。
- 如果注意力均匀散布到所有 token（ aij=1na_{ij} = \frac{1}{n}aij​=n1​ ），上下文 RMS 降到 1n\frac{1}{\sqrt{n}}n​1​。
- 其他情况下，上下文 RMS 介于 1n\frac{1}{\sqrt{n}}n​1​ 和 111 之间。

在 DIFF V1 中，我们对上下文向量加了逐 head 的 RMSNorm：

c^i=ciRMS(ci) \mathbf{\hat{c}}_i = \frac{\mathbf{c}_i}{\text{RMS}(\mathbf{c}_i)} c^i​=RMS(ci​)ci​​

如果模型在某个 head 上学到均匀注意力分布，上下文 RMS 约为 1/n1/\sqrt{n}1/n​。要把它归一化回 111，RMSNorm 必须把向量乘以 n\sqrt{n}n​ 的缩放。对 n=8192n = 8192n=8192，n≈90.5\sqrt{n} \approx 90.5n​≈90.5。也就是说 RMSNorm 层对输出施加了**约 100 倍**的放大。在大规模预训练中，我们发现这会造成巨大的梯度和数值不稳定。

一个典型现象是：DIFF V1 以大学习率预训练时，训练后期的梯度范数相比 Transformer 出现更大的上升和更高的方差。**在 DIFF V2 中，移除逐 head RMSNorm 后，梯度范数的规模与 Transformer 相当，梯度尖峰也减少了**（下文继续讨论）。

我们在 DIFF V1 中采用逐 head RMSNorm，主要是因为 value head 维度翻倍、且 λ\lambdaλ 在所有 token 间全局共享。鉴于 DIFF V2 对这两点都做了修改，我们发现移除 RMSNorm 现在是安全的。

### **突破 Softmax 约束 & 消除 Attention Sink**

我们证明 DIFF V2 能够克服上述 Softmax 的约束，还能帮助消除 [attention sink（注意力汇聚）](https://arxiv.org/abs/2309.17453)。

- 在原始 Softmax 注意力中：

aij=Softmax(zij)=exp⁡(zij)∑k=1nexp⁡(zik)ci=∑j=1naijvj=∑j=1nSoftmax(zij)vjRMS(ci)∈[1n,1) a_{ij} = \text{Softmax}(z_{ij}) = \frac{\exp(z_{ij})}{\sum_{k=1}^{n} \exp(z_{ik})} \\ \mathbf{c}_i = \sum_{j=1}^{n} a_{ij} \mathbf{v}_j = \sum_{j=1}^{n} \text{Softmax}(z_{ij}) \mathbf{v}_j \\ \text{RMS}(\mathbf{c}_i) \in \left[\frac{1}{\sqrt{n}},1\right) aij​=Softmax(zij​)=∑k=1n​exp(zik​)exp(zij​)​ci​=j=1∑n​aij​vj​=j=1∑n​Softmax(zij​)vj​RMS(ci​)∈[n​1​,1)

- 在 DIFF V2 中，我们为每个 token、每个 head 引入一个投影出来的 λ\lambdaλ：

ci=∑j=1n(Softmax(zij1)−sigmoid(λi)⋅Softmax(zij2))vjRMS(ci)∈(0,2) \mathbf{c}_i = \sum_{j=1}^{n} \left( \text{Softmax}(z_{ij}^\text{1}) - \text{sigmoid}(\lambda_i) \cdot \text{Softmax}(z_{ij}^\text{2}) \right) \mathbf{v}_j \\ \text{RMS}(\mathbf{c}_i) \in \left(0, \sqrt{2}\right) ci​=j=1∑n​(Softmax(zij1​)−sigmoid(λi​)⋅Softmax(zij2​))vj​RMS(ci​)∈(0,2​)

投影出的 λi\lambda_iλi​ 有助于控制上下文 RMS。我们观察到，**把上下文 RMS 的下界降到零尤其重要**。**它有助于消除 attention sink 并提升训练稳定性。** 上界只需要保持有界即可。

注意，这里的分析针对的是输出投影 W_O 之前的 RMS。尽管经过输出投影后 RMS 可以被恢复和调整，但 Softmax 自由度的缺失仍会影响学习效果。

## 实验观察

我们在生产规模的 LLM 上开展预训练实验，包括稠密模型和一个 30A3 MoE，使用 6e-4 到 1e-3 的大学习率、在数万亿 token 上训练。

实验仍在进行中。目前已观察到：

- 相比 Transformer，**语言建模损失显著更低**（训练 1T token 时差距为 0.02 到 0.03）。
- **训练中的损失尖峰和梯度尖峰都减少**，尤其在大学习率设置下——那里 Transformer 基线会变得不稳定。
- **激活离群值（outliers）的幅度降低。**

我们计划在训练的后续阶段探索：

- 中期训练与后训练阶段的学习效率。
- 下游长上下文基准的表现（缓解 context rot 上下文腐烂）。

## 讨论

### 差分操作的构造

理论上，一个具有 2h2h2h 个注意力头的标准 Transformer 可以通过学习 WO2i=−WO2i+1,i=0,1,…,h−1W_O^{2i}=-W_O^{2i+1}, i=0,1,\ldots,h-1WO2i​=−WO2i+1​,i=0,1,…,h−1 来学会差分操作，其中 WOiW_O^{i}WOi​ 表示第 iii 个 head 的输出投影，head 2i2i2i 和 2i+12i+12i+1 属于同一 GQA 组。

**假设 1。** 实践中，这样的解很难通过优化学到，因为它要求两组参数收敛到互为严格相反数。

**假设 2。** 差分操作是可以被模型学到、并且模型在训练中选择了去学它。**那么在输出投影之前像 DIFF V2 那样显式地构造它，就能省下一半的 W_O 参数。** 省下的参数量也不可小觑：在当前的 GQA 设置下，注意力模块的参数主要由 W_Q 和 W_O 主导，因此大约可以**节省注意力模块 25% 的参数**。省下的参数预算可以重新分配给模型的其他部分。

即便 DIFF V2 在重新分配参数后没有比基线取得更低损失、只是持平，只要它能带来额外收益——如训练更稳定、离群值更可控、训练效率更高——**这个方法依然值得**。这与 [GQA](https://arxiv.org/abs/2305.13245) 类似：GQA 损失与 MHA 持平，但额外减少了 KV-cache。所以关键还是实证性能。

### 设计消融

- 相减的两个 head **不**在同一 GQA 组，即它们**不**共享同样的 key 和 value。

（为简单起见，我们省略批次维度，并假设下面 `flash_attn_func` 的输入和输出都是三维张量 `(tokens, heads, head dimension)`。属于同一 GQA 组的 head 在输出中连续排列）

```
# Ablation 1
# ❌ Wrong Implementation of DIFF V2!
...
attn = flash_attn_func(q, k, v)
nh = attn.size(1)
attn1, attn2 = (attn[:, :nh//2], 
                    attn[:, nh//2:])
...
```

```
# DIFF V2
# ✅ Correct Implementation of DIFF V2
...
attn = flash_attn_func(q, k, v)

attn1, attn2 = (attn[:, 0::2], 
                    attn[:, 1::2])
...
```

在我们的大学习率设置下，消融 1 的配置出现明显的训练不稳定（损失和梯度尖峰多得多），损失也高于 DIFF V2。参与相减的两个 head 应当共享 value 来构造差分操作，这在 DIFF V1 论文中有讨论。

- 相减两个注意力图但不带 λ\lambdaλ 缩放因子，即 `attn1 - attn2` 而不是 `attn1 - lam_val * attn2`。这会导致初始化时上下文 RMS 过小。
- 直接使用投影出的 λ\lambdaλ 而不做 `sigmoid`。上下文 RMS 上方无界。

消融 2 和消融 3 的语言建模损失都比 DIFF V2 高。消融 2 保持了与 DIFF V2 类似的训练稳定性，消融 3 稳定性稍差（但仍比消融 1 稳定）。

- 一个具有 `1.5*h` 个 head、参数量与 DIFF V2 对齐的 Transformer。

消融 4 的训练损失同样高于 DIFF V2。

### 其他

- 在 DIFF 中，qk logits 的离群值可以比基线更小。这一点在 DIFF V1 中已有分析：DIFF 能在用更小 qk logits 的情况下达到与基线相当的注意力稀疏度。我们进一步提出，DIFF 的差分机制会抵消较小的注意力值，**可能有助于缓解这个[博客](https://spaces.ac.cn/archives/11371)和[论文](https://arxiv.org/abs/2510.04212)中讨论的注意力舍入误差问题**。
- **DIFF V2 与稀疏注意力兼容。** 在许多现有稀疏注意力框架中，同一 GQA 组内的 query head 需要关注相同的 key-value 块才能最大化加速。常见策略是按各 head 的平均注意力 logits 选块。对 DIFF V2，问题变成：如何为包含成对差分 head 的更大 GQA 组设计有效的块选择策略。选择时可能需要对两类差分 head 分开处理，也可能实践中简单平均注意力 logits 就够了。概念上，这与标准 Transformer 的块稀疏注意力没有本质区别。
