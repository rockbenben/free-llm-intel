TorchNeuron 为 AWS Trainium 上的 PyTorch 提供了新的本机后端。 Transformers、Diffusers 和 Kernels 本身就支持它，使得在 Trainium 上运行模型并在 HF 集线器上共享它们比以往任何时候都更容易。

## 火炬神经元

[TorchNeuron](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/frameworks/torch/index.html) 是一个 PyTorch 插件，为 Trainium 带来了新的后端，支持 eager 模式、“torch.compile”以及本机分布式 API（如 FSDP 和 TP）。阅读 Pytorch [博客](https://pytorch.org/blog/introducing-torchneuron-native-pytorch-backend-for-aws-trainium/) 以了解有关 TorchNeuron 的更多信息。

从 2026 年 10 月 20 日开始，TorchNeuron 将作为公开测试版提供。研究人员和开发人员将能够使用“pip install torch-neuronx”来安装它。

## 新后端，HF 库中的本机接口

迄今为止，AWS Trainium 和 Inferentia（分别为经济高效的大规模训练和推理而设计的人工智能芯片）上的 Hugging Face 体验已通过 [optimum-neuron](https://github.com/huggingface/optimum-neuron) 提供。该库依赖于 torch-neuronx 包，该包基于 PyTorch XLA。这是当时的自然选择，但这意味着像编译器一样思考：惰性张量而不是急于执行，仅静态形状，每个图形中断都重新编译。 Optimum Neuron 的存在就是为了隐藏这种复杂性，并维护自定义代码（建模类、训练器等）来做到这一点。

TorchNeuron 改变了这一点。它直接集成到 PyTorch 中，并将“神经元”公开为本机设备，具有急切执行、PyTorch 自己的分布式原语（DTensor、FSDP2）和“torch.compile”。

对于 Hugging Face 库，Trainium 成为像任何其他设备一样的设备：Transformers、Diffusers、Accelerate、PEFT 和 TRL 直接在其上运行，具有与在任何其他加速器上使用的相同的类和脚本。从现在开始，我们建议 Neuron 用户直接使用这些库，而不是通过 Optimum Neuron。

### 变形金刚

#### 推论

Transformers 现在原生支持多种模型的文本生成。 TorchNeuron 可以开箱即用地支持前 100 个最常用文本生成模型架构中的 89%，而 Optimum Neuron v0.4.5 的支持率为 46%。您只需在代码中传递“device_map=neuron”参数，您的模型就会被移动到 Neuron 设备。

以下是具有张量并行性的文本生成示例，这将使您能够充分受益于您的 Neuron 实例。请注意，它使用静态缓存进行生成，因为强烈建议 Neuron 使用静态缓存，以防止频繁重新编译。
```
import os

import torch
import torch.distributed as dist
import torch_neuronx  # noqa: F401
from torch.distributed import DeviceMesh
from transformers import AutoModelForCausalLM, AutoTokenizer, GenerationConfig
from transformers.distributed import DistributedConfig
from transformers.generation.configuration_utils import CompileConfig

MODEL_ID = "Qwen/Qwen3.8-27B"
MAX_SEQ_LEN = 1024
PREFILL_CHUNK_SIZE = 512

dist.init_process_group(backend="neuron")
world_size = dist.get_world_size()

model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    dtype=torch.bfloat16,
    distributed_config=DistributedConfig(tp_size=world_size),
    device_mesh=DeviceMesh("neuron", list(range(world_size))),
).eval()

tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token
tokenizer.padding_side = "left"

inputs = tokenizer.apply_chat_template(
    [{"role": "user", "content": "The future of AI is"}],
    add_generation_prompt=True,
    padding=True,
    tokenizer_kwargs={"pad_to_multiple_of": PREFILL_CHUNK_SIZE},
    return_tensors="pt",
)

generation_config = GenerationConfig(
    max_new_tokens=128,
    do_sample=False,
    use_cache=True,
    pad_token_id=tokenizer.pad_token_id,
    eos_token_id=tokenizer.eos_token_id,
    cache_implementation="static",
    max_cache_len=MAX_SEQ_LEN,
    prefill_chunk_size=PREFILL_CHUNK_SIZE,
    compile_config=CompileConfig(backend="neuron", fullgraph=False, dynamic=False),
)

with torch.no_grad():
    output_ids = model.generate(
        inputs["input_ids"],
        attention_mask=inputs["attention_mask"],
        generation_config=generation_config,
    )

if dist.get_rank() == 0:
    prompt_len = inputs["input_ids"].shape[1]
    print(tokenizer.decode(output_ids[0, prompt_len:], skip_special_tokens=True))
```
#### 培训

现在 Neuron 是原生 PyTorch 设备，Trainium 上的训练使用与任何其他加速器相同的 Hugging Face 库：Transformers、Accelerate、PEFT 和 TRL。您不再需要专门的培训师或特定于 Neuron 的模型代码分支。标准 TRL 微调脚本在 Trainium 实例上运行，仅具有一些特定于 Neuron 的设置。

这是一个基于 TRL 的“SFTTrainer”构建的监督微调脚本。如果您之前在 GPU 上使用 TRL 微调过模型，它应该看起来很熟悉。
```
import os

import torch
from datasets import load_dataset
from transformers.distributed import DistributedConfig

from trl import ModelConfig, ScriptArguments, SFTConfig, SFTTrainer, TrlParser


def main(script_args, training_args, model_args):
    # The Neuron backend can't compile Dynamo's automatic dynamic shapes yet (https://github.com/huggingface/trl/issues/7660)
    torch._dynamo.config.automatic_dynamic_shapes = False

    training_args.model_init_kwargs = {
        "revision": model_args.model_revision,
        "trust_remote_code": training_args.trust_remote_code,
        "attn_implementation": model_args.attn_implementation,
        "dtype": model_args.dtype,
        "device_map": None,
    }
    if int(os.environ.get("WORLD_SIZE", "1")) > 1:
        # The model is sharded on the TP x FSDP grid as its weights are loaded
        training_args.model_init_kwargs["distributed_config"] = DistributedConfig(
            tp_size=int(os.environ.get("TP_SIZE", "1")),
            fsdp_size=int(os.environ.get("FSDP_SIZE", "1")),
        )

    # Prepare dataset
    train_dataset = load_dataset(
        script_args.dataset_name,
        name=script_args.dataset_config,
        split=script_args.dataset_train_split,
    )
    # UltraChat also has a string `prompt` column, which makes TRL treat it as a prompt-completion dataset.
    train_dataset = train_dataset.select_columns(["messages"])

    # Training
    trainer = SFTTrainer(
        model=model_args.model_name_or_path,
        args=training_args,
        train_dataset=train_dataset,
    )

    trainer.train()
    trainer.save_model(training_args.output_dir)
    trainer.end()


if __name__ == "__main__":
    parser = TrlParser((ScriptArguments, SFTConfig, ModelConfig))
    script_args, training_args, model_args = parser.parse_args_and_config()
    main(script_args, training_args, model_args)
```
并行性由 Transformers 本地处理。您将具有张量并行 (TP) 和 FSDP 大小的“DistributedConfig”放入“model_init_kwargs”中，“SFTTrainer”将其传递给“from_pretrained”，模型在加载权重时被分片。 Trainer 看到模型已经分发，不会再次包装它。您不需要 `--fsdp` 标志或 Accelerate FSDP 配置。

脚本中的任何内容都与 Trainium 无关：相同的代码可以在任何硬件上运行。当您在 Trainium 上运行它时，有一些事情值得了解：

- **静态形状。** 该脚本禁用“torch.compile”中的自动动态形状，并使用包装打包来生成最多 2048 个令牌的序列。当 TRL ≥ 1.16 时，Neuron 上的批次将填充为 128 个标记的倍数，从而限制输入形状的数量。编译后的图形可重复用于具有相同形状的后续步骤。
- **`torch.compile` 打开。** 只需要传递 `--torch_compile true` 即可：在 Trainium 实例上，`torch.compile` 会检测设备并自动选择 Neuron 后端，无需配置任何其他内容。
- **异步权重加载关闭。** Neuron 不支持 Transformers 中内置的异步权重加载，因此现在我们使用“HF_DEACTIVATE_ASYNC_LOAD=1”禁用它。

下面的命令启动使用“torchrun”的训练，它为每个 NeuronCore 启动一个进程。 `TP_SIZE` 和 `FSDP_SIZE` 设置并行布局，它们的乘积是进程数：这里 4 x 8 = 32，匹配 `--nproc_per_node`。 32 个进程形成 4 x 8 网格。张量并行性将每一层划分为 TP 组的 4 个核心，FSDP 将参数、梯度和优化器状态划分为 8 个 TP 组。
```
TP_SIZE=4 FSDP_SIZE=8 HF_DEACTIVATE_ASYNC_LOAD=1 uv run torchrun --nproc_per_node=32 sft_neuron_example.py \
    --model_name_or_path Qwen/Qwen3-8B \
    --dataset_name HuggingFaceH4/ultrachat_200k \
    --dataset_train_split train_sft \
    --output_dir Qwen3-8B-sft-tp4-fsdp8 \
    --dtype bfloat16 \
    --max_length 2048 \
    --packing true \
    --packing_strategy wrapped \
    --learning_rate 2e-5 \
    --warmup_steps 0.03 \
    --num_train_epochs 1 \
    --logging_steps 2 \
    --per_device_train_batch_size 4 \
    --gradient_accumulation_steps 4 \
    --save_only_model true \
    --torch_compile true
```
我们在 8 个 Trainium2 芯片（32 个 NeuronCore）上运行它，它是“trn2.48xlarge”实例的一半。

训练运行至完成，“trainer.save_model”写入标准 Transformers 检查点。其中没有任何内容与 Neuron 相关：您可以将其按原样推送到 Hugging Face Hub 并将其加载到任何其他硬件上。

### 扩散器

#### 推论

Diffusers 库中的许多管道在 Eager 和 Compiled 模式下与 TorchNeuron 兼容。 FLUX.1-dev、FLUX.2、Qwen-Image、Qwen-Image-2.1 和 H3 还与张量并行兼容，以充分利用您的 Neuron 设备。以下是展示如何使用 TP 的示例：
```
import torch, torch.distributed as dist, torch_neuronx # TP
from torch.distributed.device_mesh import DeviceMesh # TP
from diffusers import QwenImage21Pipeline, QwenImage21Transformer2DModel, TensorParallelConfig

# Distributed devices initialization
dist.init_process_group(backend="neuron") # TP
dev = torch.neuron.current_device()
mesh = DeviceMesh("neuron", list(range(8))) # TP=8

# Pipeline initialization
model = "Qwen/Qwen-Image-2.1"
transformer = QwenImage21Transformer2DModel.from_pretrained(
    model,
    subfolder="transformer",
    torch_dtype=torch.bfloat16,
    parallel_config=TensorParallelConfig(mesh=mesh), # TP
)
pipe = QwenImage21Pipeline.from_pretrained(
    model,
    transformer=transformer,
    torch_dtype=torch.bfloat16,
)
pipe.vae.to(dev)
pipe.transformer.compile_repeated_blocks(backend="neuron", fullgraph=True, dynamic=False)

# Image generation
emb, mask, _ = pipe.encode_prompt(prompt="A capybara wearing a wizard hat, oil painting", device="cpu")  # text encoder stays on CPU
image = pipe(
    prompt_embeds=emb.to(dev),
    prompt_embeds_mask=mask.to(dev) if mask is not None else None,
    height=1024,
    width=1024,
    num_inference_steps=40,
    generator=torch.Generator("cpu").manual_seed(0), # same noise on every rank
).images[0]
if dist.get_rank() == 0:
    image.save("out.png")
```
您可以使用以下命令运行这段代码：“NEURON_LOGICAL_NC_CONFIG=2 torchrun --nproc_per_node=8 run.py”。

越来越多的管道将兼容TP。如果您不喜欢的管道，您还可以按照[本指南](https://huggingface.co/docs/diffusers/main/en/training/distributed_inference#writing-a-tensor-parallelism-plan)添加对其的支持。

### 内核

请务必查看 [Neuron 团队的内核](https://huggingface.co/aws-neuron/kernels)，因为 Hub 上将提供越来越多的 Neuron 内核来加速您的模型。神经元内核可以使用 [神经元内核接口](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/nki/index.html) (NKI) 编写，它为优化操作提供了较低的控制。这样，用户可以运行自己的自定义操作并在集线器上共享它们。

例如，您可以使用[此内核](https://huggingface.co/kernels/aws-neuron/vit-encoder-neuron-kernels) 来加速您的视觉转换器，在 Trainium 上加速高达 x2.4！
