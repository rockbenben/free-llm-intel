TorchNeuron 为 AWS Trainium 上的 PyTorch 提供了一个新的原生后端。Transformers、Diffusers 与 Kernels 都原生支持它，让在 Trainium 上运行模型、并把模型分享到 HF hub 比以往更容易。

## TorchNeuron

[TorchNeuron](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/frameworks/torch/index.html) 是一个 PyTorch 插件，为 Trainium 带来新的后端，支持 eager 模式、`torch.compile` 以及 FSDP、TP 这类原生分布式 API。更多内容请阅读 PyTorch 的[博客](https://pytorch.org/blog/introducing-torchneuron-native-pytorch-backend-for-aws-trainium/)。

自 2026 年 10 月 20 日起，TorchNeuron 将以公开测试版提供。研究者和开发者可以用 `pip install torch-neuronx` 安装它。

## 新后端，HF 库中的原生接口

迄今为止，Hugging Face 在 AWS Trainium 与 Inferentia（这两款 AI 芯片分别面向高性价比的大规模训练与推理）上的体验，都是通过 [optimum-neuron](https://github.com/huggingface/optimum-neuron) 提供的。这个库依赖基于 PyTorch XLA 的 torch-neuronx 包。在当时这是自然而然的选择，但代价是你得像编译器一样思考：用惰性张量而非 eager 执行、只支持静态形状、每次 graph break 都要重新编译。Optimum Neuron 的存在就是为了隐藏这些复杂性，并为此维护了大量自定义代码（建模类、trainer 等）。

TorchNeuron 改变了这一点。它直接集成进 PyTorch，把 `neuron` 暴露为一个原生设备，支持 eager 执行、PyTorch 自身的分布式原语（DTensor、FSDP2）以及 `torch.compile`。

对 Hugging Face 的各个库来说，Trainium 变成了和其他设备一样的设备：Transformers、Diffusers、Accelerate、PEFT 和 TRL 可以直接在其上运行，使用的类与脚本和你在其他任何加速器上所用的一致。从今往后，我们建议 Neuron 用户直接使用这些库，而不再经由 Optimum Neuron。

### Transformers

#### 推理

Transformers 现在为大量模型原生支持文本生成。借助 TorchNeuron，最常用的 100 个文本生成模型架构中有 89% 可直接开箱支持，而在 Optimum Neuron v0.4.5 上只有 46%。你只需在代码中传入 `device_map=neuron` 参数，模型就会被移动到 Neuron 设备上。

下面是一个使用张量并行的文本生成示例，它能让你充分利用 Neuron 实例。注意它在生成时使用了静态 cache，因为在 Neuron 上强烈建议这样做，以避免频繁重编译。

```
import os

import torch
import torch.distributed as dist
import torch_neuronx  # noqa: F401
from torch.distributed import DeviceMesh
from transformers import AutoModelForCausalLM, AutoTokenizer, GenerationConfig
from transformers.distributed import DistributedConfig
from transformers.generation.configuration_utils import CompileConfig

MODEL_ID = "Qwen/Qwen3.8-27B"
MAX_SEQ_LEN = 1024
PREFILL_CHUNK_SIZE = 512

dist.init_process_group(backend="neuron")
world_size = dist.get_world_size()

model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    dtype=torch.bfloat16,
    distributed_config=DistributedConfig(tp_size=world_size),
    device_mesh=DeviceMesh("neuron", list(range(world_size))),
).eval()

tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token
tokenizer.padding_side = "left"

inputs = tokenizer.apply_chat_template(
    [{"role": "user", "content": "The future of AI is"}],
    add_generation_prompt=True,
    padding=True,
    tokenizer_kwargs={"pad_to_multiple_of": PREFILL_CHUNK_SIZE},
    return_tensors="pt",
)

generation_config = GenerationConfig(
    max_new_tokens=128,
    do_sample=False,
    use_cache=True,
    pad_token_id=tokenizer.pad_token_id,
    eos_token_id=tokenizer.eos_token_id,
    cache_implementation="static",
    max_cache_len=MAX_SEQ_LEN,
    prefill_chunk_size=PREFILL_CHUNK_SIZE,
    compile_config=CompileConfig(backend="neuron", fullgraph=False, dynamic=False),
)

with torch.no_grad():
    output_ids = model.generate(
        inputs["input_ids"],
        attention_mask=inputs["attention_mask"],
        generation_config=generation_config,
    )

if dist.get_rank() == 0:
    prompt_len = inputs["input_ids"].shape[1]
    print(tokenizer.decode(output_ids[0, prompt_len:], skip_special_tokens=True))
```

#### 训练

既然 Neuron 已成为原生 PyTorch 设备，在 Trainium 上训练所用的 Hugging Face 库与其他加速器完全一样：Transformers、Accelerate、PEFT 和 TRL。你不再需要专用的 trainer，也不需要 Neuron 专属的模型代码分支。一个标准的 TRL 微调脚本只需少量 Neuron 专属设置，就能在 Trainium 实例上运行。

下面是一个基于 TRL `SFTTrainer` 的监督微调脚本。如果你之前在 GPU 上用 TRL 微调过模型，它看上去应该很眼熟。

```
import os

import torch
from datasets import load_dataset
from transformers.distributed import DistributedConfig

from trl import ModelConfig, ScriptArguments, SFTConfig, SFTTrainer, TrlParser


def main(script_args, training_args, model_args):
    # The Neuron backend can't compile Dynamo's automatic dynamic shapes yet (https://github.com/huggingface/trl/issues/7660)
    torch._dynamo.config.automatic_dynamic_shapes = False

    training_args.model_init_kwargs = {
        "revision": model_args.model_revision,
        "trust_remote_code": training_args.trust_remote_code,
        "attn_implementation": model_args.attn_implementation,
        "dtype": model_args.dtype,
        "device_map": None,
    }
    if int(os.environ.get("WORLD_SIZE", "1")) > 1:
        # The model is sharded on the TP x FSDP grid as its weights are loaded
        training_args.model_init_kwargs["distributed_config"] = DistributedConfig(
            tp_size=int(os.environ.get("TP_SIZE", "1")),
            fsdp_size=int(os.environ.get("FSDP_SIZE", "1")),
        )

    # Prepare dataset
    train_dataset = load_dataset(
        script_args.dataset_name,
        name=script_args.dataset_config,
        split=script_args.dataset_train_split,
    )
    # UltraChat also has a string `prompt` column, which makes TRL treat it as a prompt-completion dataset.
    train_dataset = train_dataset.select_columns(["messages"])

    # Training
    trainer = SFTTrainer(
        model=model_args.model_name_or_path,
        args=training_args,
        train_dataset=train_dataset,
    )

    trainer.train()
    trainer.save_model(training_args.output_dir)
    trainer.end()


if __name__ == "__main__":
    parser = TrlParser((ScriptArguments, SFTConfig, ModelConfig))
    script_args, training_args, model_args = parser.parse_args_and_config()
    main(script_args, training_args, model_args)
```

并行由 Transformers 原生处理。你把带有张量并行（TP）和 FSDP 大小的 `DistributedConfig` 放进 `model_init_kwargs`，`SFTTrainer` 会把它传给 `from_pretrained`，模型在加载权重时即完成分片。Trainer 发现模型已经是分布式的，便不会再包装一次。你不需要 `--fsdp` 标志，也不需要 Accelerate 的 FSDP 配置。

脚本里没有任何东西与 Trainium 绑定：同样的代码在任何硬件上都能运行。在 Trainium 上运行时，有几点值得了解：

- **静态形状。** 脚本禁用了 `torch.compile` 的自动动态形状，并使用 wrapped packing 生成最长 2048 token 的序列。在 TRL ≥ 1.16 中，Neuron 上的 batch 会 padding 到 128 token 的倍数，从而限制输入形状的数量。编译后的图会在后续形状相同的步骤中被复用。
- **开启 `torch.compile`。** 只需传入 `--torch_compile true`：在 Trainium 实例上，`torch.compile` 会自动识别设备并选用 Neuron 后端，无须再做其他配置。
- **关闭异步权重加载。** Transformers 内置的异步权重加载在 Neuron 上不受支持，因此目前我们用 `HF_DEACTIVATE_ASYNC_LOAD=1` 把它关闭。

下面的命令用 `torchrun` 启动训练，它会为每个 NeuronCore 启动一个进程。`TP_SIZE` 和 `FSDP_SIZE` 设定并行布局，二者相乘就是进程数：这里是 4 x 8 = 32，与 `--nproc_per_node` 一致。32 个进程构成一个 4 x 8 的网格。张量并行把每一层切分到 TP 组的 4 个 core 上，FSDP 则把参数、梯度和优化器状态分片到 8 个 TP 组之间。

```
TP_SIZE=4 FSDP_SIZE=8 HF_DEACTIVATE_ASYNC_LOAD=1 uv run torchrun --nproc_per_node=32 sft_neuron_example.py \
    --model_name_or_path Qwen/Qwen3-8B \
    --dataset_name HuggingFaceH4/ultrachat_200k \
    --dataset_train_split train_sft \
    --output_dir Qwen3-8B-sft-tp4-fsdp8 \
    --dtype bfloat16 \
    --max_length 2048 \
    --packing true \
    --packing_strategy wrapped \
    --learning_rate 2e-5 \
    --warmup_steps 0.03 \
    --num_train_epochs 1 \
    --logging_steps 2 \
    --per_device_train_batch_size 4 \
    --gradient_accumulation_steps 4 \
    --save_only_model true \
    --torch_compile true
```

我们在 8 颗 Trainium2 芯片（32 个 NeuronCore）上运行了它，相当于半台 `trn2.48xlarge` 实例。

训练完整跑完，`trainer.save_model` 写出的是标准 Transformers checkpoint。其中没有任何东西与 Neuron 绑定：你可以原样推送到 Hugging Face Hub，并在其他任何硬件上加载。

### Diffusers

#### 推理

Diffusers 库中的许多 pipeline 在 eager 与编译模式下都与 TorchNeuron 兼容。FLUX.1-dev、FLUX.2、Qwen-Image、Qwen-Image-2.1 和 H3 还兼容张量并行，以充分利用你的 Neuron 设备。下面是一个演示如何使用 TP 的示例：

```
import torch, torch.distributed as dist, torch_neuronx # TP
from torch.distributed.device_mesh import DeviceMesh # TP
from diffusers import QwenImage21Pipeline, QwenImage21Transformer2DModel, TensorParallelConfig

# Distributed devices initialization
dist.init_process_group(backend="neuron") # TP
dev = torch.neuron.current_device()
mesh = DeviceMesh("neuron", list(range(8))) # TP=8

# Pipeline initialization
model = "Qwen/Qwen-Image-2.1"
transformer = QwenImage21Transformer2DModel.from_pretrained(
    model,
    subfolder="transformer",
    torch_dtype=torch.bfloat16,
    parallel_config=TensorParallelConfig(mesh=mesh), # TP
)
pipe = QwenImage21Pipeline.from_pretrained(
    model,
    transformer=transformer,
    torch_dtype=torch.bfloat16,
)
pipe.vae.to(dev)
pipe.transformer.compile_repeated_blocks(backend="neuron", fullgraph=True, dynamic=False)

# Image generation
emb, mask, _ = pipe.encode_prompt(prompt="A capybara wearing a wizard hat, oil painting", device="cpu")  # text encoder stays on CPU
image = pipe(
    prompt_embeds=emb.to(dev),
    prompt_embeds_mask=mask.to(dev) if mask is not None else None,
    height=1024,
    width=1024,
    num_inference_steps=40,
    generator=torch.Generator("cpu").manual_seed(0), # same noise on every rank
).images[0]
if dist.get_rank() == 0:
    image.save("out.png")
```

你可以用下面这条命令运行这段代码：`NEURON_LOGICAL_NC_CONFIG=2 torchrun --nproc_per_node=8 run.py`。

越来越多的 pipeline 将兼容 TP。如果你喜欢的某个 pipeline 还不支持，也可以按照[这份指南](https://huggingface.co/docs/diffusers/main/en/training/distributed_inference#writing-a-tensor-parallelism-plan)为其添加支持。

### Kernels

请务必看看 [Neuron 团队提供的 kernels](https://huggingface.co/aws-neuron/kernels)，因为会有越来越多 Neuron kernel 出现在 Hub 上，用来加速你的模型。Neuron kernel 可以用 [Neuron Kernel Interface](https://awsdocs-neuron.readthedocs-hosted.com/en/latest/nki/index.html)（NKI）编写，它提供更底层的控制来优化操作。这样用户就能运行自己的自定义操作，并把它们分享到 hub 上。

例如，你可以用[这个 kernel](https://huggingface.co/kernels/aws-neuron/vit-encoder-neuron-kernels) 来加速你的视觉 transformer，在 Trainium 上最高可获得 2.4 倍加速！
