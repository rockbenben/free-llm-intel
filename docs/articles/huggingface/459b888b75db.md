*一个 agent 用两个 Hugging Face Space 搭出了 3D 巴黎画廊。*

我让一个 coding agent 建一个漂亮的网站，把巴黎的地标以 3D 高斯泼溅（Gaussian splats）呈现。我从没打开过图像生成器，也从没碰过 3D 重建工具。agent 通过直接调用两个 Hugging Face Space 产出了所有素材（图像**和** 3D 泼溅），再把它们接入一个电影感的查看器。

这是成果，以静态 Space 的形式在线运行：

👉 **[mishig/monuments-de-paris](https://huggingface.co/spaces/mishig/monuments-de-paris)**

本文讲的是这在今天*如何*成为可能，以及为什么我认为它是此后大量多媒体软件构建方式的一个预演。

## 积木经济正在进军多媒体

Mitchell Hashimoto 最近描述了一个他称之为[积木经济（building block economy）](https://mitchellh.com/writing/building-block-economy)的转变：通往软件的最有效路径不再是一个打磨完好的整体巨作，而是小巧、文档完善、他人（越来越多是 *agent*）可以组装的组件。他的关键观察：AI 从零造东西还算可以，但**真的擅长把成熟零件粘起来**。

这个论断大多是用*代码*库来讲的。但同一股力量正冲击**多媒体 AI**。使用最先进的图像模型、视频模型、TTS 模型或 3D 重建模型，难的部分从来不是模型，而是集成：SDK、权重、GPU、输入格式、轮询。如果每个模型反而是一个有文档、可调用的积木，agent 就能像拼接 npm 包那样把它们粘起来。

这正是 Hugging Face Spaces 悄然变成的东西。

## 通过 `agents.md`，每个 Space 都是一块积木

Hub 托管着数千个最先进模型（其中很大比例是**开放权重**），且大多以可交互的 **Space** 部署。截至目前，每个 Gradio Space 还暴露一份纯文本的 [`agents.md`](https://huggingface.co/docs/hub/en/spaces-agents)，告诉 agent *确切*如何调用它：

```
curl https://huggingface.co/spaces/VAST-AI/TripoSplat/agents.md
```

一次性返回所需的一切：schema URL、调用与轮询模板、如何上传文件，以及认证提示：

```
API schema:   GET  .../gradio_api/info
Call endpoint: POST .../gradio_api/call/v2/{endpoint} {"param_name": value, ...}
Poll result:  GET  .../gradio_api/call/{endpoint}/{event_id}
File inputs:  POST .../gradio_api/upload -F "files=@file.ext"
Auth:         Bearer $HF_TOKEN
```

没有客户端库，没有硬编码的集成。agent 读完这些，就能端到端地驱动这个 Space。设置一个 [`HF_TOKEN`](https://huggingface.co/settings/tokens) 即可出发。你可以在任何 Gradio Space 上通过 **Agents** 按钮找到这些说明：

真正的解锁点是**链式组合**：一个 Space 的输出成为下一个 Space 的输入。提示 → 图像 → 3D。这就是这个画廊背后的整条流水线。

## 完整实例：巴黎地标 → 泼溅

agent 串联了两个 Space：

- **图像：** 一个图像生成 Space 把每个地标变成干净的暗背景「标本」照（还把埃菲尔铁塔变成基座上的小透视景模型）。提示词进，图像出。
- **泼溅：** [`VAST-AI/TripoSplat`](https://huggingface.co/spaces/VAST-AI/TripoSplat) 从每张单图重建出一个 3D 高斯泼溅（`.ply`）。图像进，3D 出。

此后，「粘合」工作也由 agent 完成。它发现 TripoSplat 的输出是 Y 轴向下的，就把它们翻正；为每个地标自动取景；把 `.ply` 文件压缩为 `.ksplat`（体积小约 3 倍，加载快）；用 Three.js 搭了一个带滚动切换、拖拽旋转 UI 的查看器；最后把整个东西部署成静态 Space。人类输入只剩品味层面："拉远一点"、"把方尖碑换成更适合泼溅的东西"、"转场停留太久了"。

其中几步是**agent 在应对现实**。宽大的玻璃金字塔泼溅效果差。细长的方尖碑很无聊。单视角重建要靠推断补出背面。这正是积木经济所预言的「外包研发、快速迭代」循环——只不过研发是一场对话。

## 两句提示词，一座全新画廊

积木真正的考验，是复用它有多便宜。这条流水线一旦存在，开一座全新的画廊大约只需一句话的成本。"为日本做一座类似的带泼溅的 Space"，然后为埃及再来一遍，agent 就把剩下的做了：每个国家六张地标图像、六个泼溅、压缩、查看器、部署好的 Space。

- 🏛️ [Monuments of Egypt](https://huggingface.co/spaces/mishig/monuments-of-egypt)：大金字塔、狮身人面像、阿布辛贝、图坦卡蒙金面具、卡纳克、曼农巨像。

- ⛩️ [Monuments of Japan](https://huggingface.co/spaces/mishig/monuments-of-japan)：东京塔、姬路城、金阁寺、大阪城、镰仓大佛、严岛神社海上鸟居。

同样的两个 Space、同样的 `agents.md`，只是提示词变了。这就是用一句话说清的积木经济：一个多媒体新应用的边际成本，趋近于描述它的成本。

## 为什么这很重要

- **模型变得可组合。** 一个 SOTA 泼溅模型与一个 SOTA 图像模型，来自不同机构，零集成代码串联。Hub 的开放权重目录变成了可调用多媒体原语的图书馆。
- **Agent 偏爱有文档、可达的东西。** `agents.md` 让 Space 唾手可得，agent 会选它而不是选一个需要手动搭建的模型。这与 Hashimoto 为开源库指出的动力学相同。
- **门槛是集成，而它已基本消失。** "把一个提示词变成一座可旋转的 3D 地标"曾是一个项目，这里只是流水线里的一步。

```
# image generation
curl https://huggingface.co/spaces/ideogram-ai/ideogram4/agents.md
# single-image to 3D gaussian splat
curl https://huggingface.co/spaces/VAST-AI/TripoSplat/agents.md
```
