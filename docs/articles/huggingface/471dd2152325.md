当所有人（以及他们的奶奶 👵）都在不断推出新的 ASR 模型时，为你的用例挑对模型，可能比选下一部 Netflix 剧还让人头大。截至 2025 年 11 月 21 日，Hub 上有 **150 个 [Audio-Text-to-Text](https://huggingface.co/models?pipeline_tag=audio-text-to-text&sort=trending)** 模型和 **2.7 万个 [ASR 模型](https://huggingface.co/models?pipeline_tag=automatic-speech-recognition&sort=trending)** 🤯

大多数基准聚焦**短音频英语转录（<30 秒）**，忽略了其他重要任务，比如 (1) 多语言性能与 (2) 模型吞吐量——而对会议、播客这类长音频，吞吐量可能就是决定性因素。

过去两年，[**Open ASR Leaderboard**](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard) 已成为在**准确率**与**效率**两方面比较开源与闭源模型的标准。近期，排行榜新增了**多语言**与**长音频转录**赛道 🎉

### TL;DR - [Open ASR Leaderboard](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard)

- 📝 基于排行榜的 ASR 趋势**新 preprint**：[https://hf.co/papers/2510.06961](https://hf.co/papers/2510.06961)
- 🧠 **准确率最佳**：Conformer 编码器 + LLM 解码器（开源万岁 🥳）
- ⚡ **速度最快**：CTC / TDT 解码器
- 🌍 **多语言**：以牺牲单语言性能为代价
- ⌛ **长音频**：闭源系统仍领先（暂时 😉）
- 🧑‍💻 **微调指南**（[Parakeet](https://github.com/Deep-unlearning/Finetune-Parakeet)、[Voxtral](https://github.com/Deep-unlearning/Finetune-Voxtral-ASR)、[Whisper](https://huggingface.co/learn/audio-course/chapter5/fine-tuning)）：继续推动性能

# 来自 60+ 模型的要点

截至 2025 年 11 月 21 日，*Open ASR Leaderboard* 在 **11 个数据集**上比较来自 **18 家机构**的 **60 多个开源与闭源模型**。

在最近的 [preprint](https://hf.co/papers/2510.06961) 中，我们深入技术设置并突出现代 ASR 的几个关键趋势。以下是主要收获 👇

## 1. Conformer 编码器 🤝 LLM 解码器登顶 📈

把 [**Conformer 编码器**](https://huggingface.co/papers/2005.08100)与**大语言模型（LLM）解码器**结合的模型，目前在英语转录准确率上领先。例如，**NVIDIA 的 [Canary-Qwen-2.5B](https://huggingface.co/nvidia/canary-qwen-2.5b)**、**IBM 的 [Granite-Speech-3.3-8B](https://huggingface.co/ibm-granite/granite-speech-3.3-8b)** 与 **Microsoft 的 [Phi-4-Multimodal-Instruct](https://huggingface.co/microsoft/Phi-4-multimodal-instruct)** 取得了最低的词错误率（[WER](https://huggingface.co/learn/audio-course/en/chapter5/evaluation#word-error-rate)），表明整合 LLM 推理能显著提升 ASR 准确率。

💡 *小贴士：NVIDIA 提出了 [Fast Conformer](https://huggingface.co/papers/2305.05084)——Conformer 的 2 倍加速版本，用于其 Canary 与 Parakeet 模型系列。*

## 2. 速度与准确率的权衡 ⚖️

这些 LLM 解码器虽然准确率高，但往往比更简单的方案**更慢**。在 *Open ASR Leaderboard* 上，效率用*逆实时因子*（RTFx）衡量，越高越好。

要更快的推理，[**CTC**](https://huggingface.co/learn/audio-course/en/chapter3/ctc#ctc-architectures) 与 [**TDT**](https://huggingface.co/papers/2304.06795) 解码器提供 **10-100 倍**的吞吐，尽管错误率略高。这使它们非常适合**实时**、**离线**或**批量转录**任务（如会议、讲座、播客）。

## 3. 多语言 🌍

OpenAI 的 [**Whisper Large v3**](https://huggingface.co/openai/whisper-large-v3) 仍是强有力的多语言基线，支持 **99 种语言**。然而，像 [**Distil-Whisper**](https://huggingface.co/distil-whisper/distil-large-v3.5) 与 [**CrisperWhisper**](https://huggingface.co/nyrahealth/CrisperWhisper) 这样的**微调或蒸馏变体**，在**纯英语**任务上往往胜过原版，说明有针对性的微调可以提升专业化（*如何微调？看看 [Whisper](https://huggingface.co/learn/audio-course/chapter5/fine-tuning)、[Parakeet](https://github.com/Deep-unlearning/Finetune-Parakeet) 与 [Voxtral](https://github.com/Deep-unlearning/Finetune-Voxtral-ASR) 的指南*）。

不过，专注英语往往会**降低多语言覆盖** 👉 专业化和泛化的经典权衡。类似地，Meta 的 [**Massively Multilingual Speech（MMS）**](https://huggingface.co/facebook/mms-1b-all) 与 [**Omnilingual ASR**](https://github.com/facebookresearch/omnilingual-asr) 这样的**自监督**系统能支持 1000+ 种语言，但准确率落后于面向特定语言的编码器。

⭐ *目前排行榜只基准测试了 5 种语言，我们计划扩展到更多语言，也期待社区通过 GitHub [pull request](https://github.com/huggingface/open_asr_leaderboard) 为多语言 ASR 贡献新数据集与模型。*

🎯 与多语言基准并行，多个**社区驱动的排行榜**聚焦单一语言。例如 [**Open Universal Arabic ASR Leaderboard**](https://huggingface.co/spaces/elmresearchcenter/open_universal_arabic_asr_leaderboard) 在**现代标准阿拉伯语及各地区方言**上比较模型，凸显语音变异与双言现象（diglossia）对当前系统的挑战。同样，[**Russian ASR Leaderboard**](https://huggingface.co/spaces/Vikhrmodels/Russian_ASR_Leaderboard) 提供了一个不断成长的中心，在**俄语特有的音系与形态**上评估 encoder-decoder 与 CTC 模型。这些本地化努力呼应了多语言排行榜的使命——鼓励**数据集共享、微调 checkpoint 与透明的模型对比**，尤其是对 ASR 资源较少的语言。

## 4. 长音频转录是另一盘棋 ⏳

对**长音频**（如播客、讲座、会议），**闭源系统**仍略胜开源。原因可能是领域调优、定制的切块（chunking）或生产级优化。

开源模型中，**OpenAI 的 Whisper Large v3** 表现最好。但论吞吐，**基于 CTC 的 Conformer** 大放异彩 👉 例如 **NVIDIA 的 [Parakeet CTC 1.1B](https://huggingface.co/nvidia/parakeet-ctc-1.1b)** 达到 **RTFx 2793.75**，而 Whisper Large v3 只有 **68.56**，WER 仅温和恶化（分别为 **6.68** 与 **6.43**）。

代价呢？Parakeet 是**纯英语的**，又一次提醒我们多语言与专业化的权衡 🫠。

⭐ *虽然闭源系统仍领先，但这里蕴藏着巨大的开源创新空间。长音频 ASR 仍是社区接下来最值得攻克的前沿之一！*

# 🎤 演出必须继续

ASR 演进如此之快，我们期待看到哪些新架构能推动性能与效率，也期待 *Open ASR Leaderboard* 继续作为该领域**透明、社区驱动的基准**，并为其他排行榜（[俄语](https://huggingface.co/spaces/Vikhrmodels/Russian_ASR_Leaderboard)、[阿拉伯语](https://huggingface.co/spaces/elmresearchcenter/open_universal_arabic_asr_leaderboard)与 [Speech DeepFake Detection](https://huggingface.co/spaces/Speech-Arena-2025/Speech-DF-Arena)）提供参考。

我们将持续扩展 *Open ASR Leaderboard*——**更多模型、更多语言、更多数据集**——敬请期待 👀
