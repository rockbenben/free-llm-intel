# 大型语言模型的快速推理：Habana Gaudi2 加速器上的 BLOOMZ

本文将演示如何用 🤗 [Optimum Habana](https://huggingface.co/docs/optimum/habana/index)——Gaudi2 与 🤗 Transformers 库之间的桥梁——在 [Habana® Gaudi®2](https://habana.ai/training/gaudi2/) 上轻松部署像 BLOOM 这样拥有数千亿参数的大语言模型。正如本文展示的基准测试所证明的，这能让你**以比目前市面上任何 GPU 都快的速度运行推理**。

随着模型越来越大，把它们部署到生产环境做推理也变得愈发有挑战。硬件和软件都为应对这些挑战做出了很多创新，那我们就来看看如何高效地翻过这些山！

## BLOOMZ

[BLOOM](https://arxiv.org/abs/2211.05100) 是一个 1760 亿参数的自回归模型，训练目标是补全文本序列。它能处理 46 种自然语言和 13 种编程语言。作为 [BigScience](https://bigscience.huggingface.co/) 计划的一部分设计与训练，BLOOM 是一个开放科学项目，汇聚了全球大量研究人员和工程师。最近，另一个架构完全相同的模型也发布了：[BLOOMZ](https://arxiv.org/abs/2211.01786)，它是 BLOOM 在多个任务上微调后的版本，泛化能力更强，并具备 zero-shot[^1] 能力。

如此大的模型，无论[训练](https://huggingface.co/blog/bloom-megatron-deepspeed)还是[推理](https://huggingface.co/blog/bloom-inference-optimization)，都在内存和速度上带来新挑战。即使以 16-bit 精度，单实例也需要 352 GB 才能装下！眼下你恐怕很难找到这么大内存的单卡设备，但像 Habana Gaudi2 这样的先进硬件，确实能够以低延迟对 BLOOM 和 BLOOMZ 模型执行推理。

## Habana Gaudi2

[Gaudi2](https://habana.ai/training/gaudi2/) 是 Habana Labs 设计的第二代 AI 硬件加速器。一台服务器包含 8 个加速器设备（称为 Habana Processing Unit，即 HPU），每个拥有 96GB 内存，足以装下超大模型。不过，如果计算很慢，能装下模型也没什么意义。好在 Gaudi2 正是在这一点上表现出色：它与 GPU 的不同之处在于，其架构可以让加速器并行执行通用矩阵乘法（GeMM）及其他运算，从而加速深度学习工作流。这些特性使 Gaudi2 成为 LLM 训练与推理的有力候选。

Habana 的 SDK——SynapseAI™——支持 PyTorch 和 DeepSpeed 来加速 LLM 训练与推理。[SynapseAI 图编译器](https://docs.habana.ai/en/latest/Gaudi_Overview/SynapseAI_Software_Suite.html#graph-compiler-and-runtime)会优化图中累积运算的执行（例如算子融合、数据布局管理、并行化、流水线与内存管理，以及图级优化）。

此外，SynapseAI 最近引入了对 [HPU graphs](https://docs.habana.ai/en/latest/PyTorch/Inference_on_PyTorch/Inference_Using_HPU_Graphs.html) 和 [DeepSpeed-inference](https://docs.habana.ai/en/latest/PyTorch/DeepSpeed/Inference_Using_DeepSpeed.html) 的支持，正如我们下面的基准测试所示，它们非常适合对延迟敏感的应用。

所有这些能力都已集成进 🤗 [Optimum Habana](https://github.com/huggingface/optimum-habana) 库，因此把模型部署到 Gaudi 上非常简单。快速上手页面在[这里](https://huggingface.co/docs/optimum/habana/quickstart)。

如果你想获得 Gaudi2 的使用权限，前往 [Intel Developer Cloud](https://www.intel.com/content/www/us/en/secure/developer/devcloud/cloud-launchpad.html)，并按[这份指南](https://huggingface.co/blog/habana-gaudi-2-benchmark#how-to-get-access-to-gaudi2)操作。

## 基准测试

本节给出 BLOOMZ 在 Gaudi2、第一代 Gaudi 和 Nvidia A100 80GB 上的初步基准测试。虽然这些设备内存都很大，但模型实在太大，单卡装不下一个 BLOOMZ 实例。为解决这个问题，我们使用 [DeepSpeed](https://www.deepspeed.ai/)——一个深度学习优化库，带来大量内存和速度改进，能加速模型并让它塞进设备。具体地说，这里依赖的是 [DeepSpeed-inference](https://arxiv.org/abs/2207.00032)：它引入了多项特性，例如[模型（流水线）并行](https://huggingface.co/blog/bloom-megatron-deepspeed#pipeline-parallelism)，以充分利用可用的设备。在 Gaudi2 上，我们使用 [Habana 的 DeepSpeed 分支](https://github.com/HabanaAI/deepspeed)，它增加了对 HPU 的支持。

### 延迟

我们测量了 BLOOMZ 两个数十亿参数规格的延迟（批量为一个样本）：

- [1760 亿](https://huggingface.co/bigscience/bloomz)参数
- [70 亿](https://huggingface.co/bigscience/bloomz-7b1)参数

测试在 16-bit 精度下使用 DeepSpeed-inference 进行，配备 8 个设备，并启用了 [key-value 缓存](https://huggingface.co/docs/transformers/v4.27.1/en/model_doc/bloom#transformers.BloomForCausalLM.forward.use_cache)。注意，CUDA graphs 目前与 DeepSpeed 的模型并行不兼容（DeepSpeed v0.8.2，见[这里](https://github.com/microsoft/DeepSpeed/blob/v0.8.2/deepspeed/inference/engine.py#L158)），而 HPU graphs 在 Habana 的 DeepSpeed 分支中受支持。所有基准测试都以[贪心生成](https://huggingface.co/blog/how-to-generate#greedy-search)方式输出 100 个 token。输入提示词是：

> "DeepSpeed is a machine learning framework"

用 BLOOM 的分词器计为 7 个 token。

推理延迟结果见下表（单位为*秒*）。

| 模型 | 设备数量 | Gaudi2 延迟（秒） | A100-80GB 延迟（秒） | 第一代 Gaudi 延迟（秒） |
| --- | --- | --- | --- | --- |
| BLOOMZ | 8 | 3.103 | 4.402 | / |
| BLOOMZ-7B | 8 | 0.734 | 2.417 | 3.321 |
| BLOOMZ-7B | 1 | 0.772 | 2.119 | 2.387 |

*更新：上述数字已随 Optimum Habana 1.6 和 SynapseAI 1.10 的发布而更新，带来 Gaudi2 相对 A100 在 BLOOMZ 上 x1.42 的加速。*

Habana 团队最近在 SynapseAI 1.8 中引入了对 DeepSpeed-inference 的支持，从而迅速实现了千亿级参数模型的推理。**在 1760 亿参数检查点上，Gaudi2 比 A100 80GB 快 1.42 倍**。较小的检查点也有很有意思的结果。**在 BLOOMZ-7B 上，Gaudi2 比 A100 快 2.89 倍！** 同样值得关注的是，Gaudi2 能从模型并行中获益，而 A100 在单卡上反而更快。

我们也在第一代 Gaudi 上运行了这些模型。它虽然比 Gaudi2 慢，但从价格角度看很有意思：AWS 上的 DL1 实例大约每小时 13 美元。第一代 Gaudi 上 BLOOMZ-7B 的延迟为 2.387 秒。因此，**对于 70 亿参数检查点，第一代 Gaudi 提供了比 A100 更好的性价比**——A100 每小时成本超过 30 美元！

我们期待 Habana 团队在后续的 SynapseAI 版本中进一步优化这些模型的性能。比如在上一次基准测试中，我们看到 [Gaudi2 的 Stable Diffusion 推理比 A100 快 2.2 倍](https://huggingface.co/blog/habana-gaudi-2-benchmark#generating-images-from-text-with-stable-diffusion)，之后又借助 Habana 提供的最新优化进一步提升到了 2.37 倍。随着新 SynapseAI 版本发布并被集成进 Optimum Habana，我们也会持续更新这些数字。

### 如何复现这些结果？

用于在 Gaudi2 和第一代 Gaudi 上测试 BLOOMZ 的脚本在[这里](https://github.com/huggingface/optimum-habana/tree/main/examples/text-generation)。运行前，请按照 [Habana 的安装说明](https://docs.habana.ai/en/latest/Installation_Guide/index.html)安装最新版 SynapseAI 和 Gaudi 驱动。

然后执行：

```
git clone https://github.com/huggingface/optimum-habana.git
cd optimum-habana && pip install . && cd examples/text-generation
pip install git+https://github.com/HabanaAI/DeepSpeed.git@1.9.0
```

最后，按如下方式启动脚本：

```
python ../gaudi_spawn.py --use_deepspeed --world_size 8 run_generation.py --model_name_or_path bigscience/bloomz --use_hpu_graphs --use_kv_cache --max_new_tokens 100
```

关于多节点推理，可参考 Optimum Habana 文档中的[这份指南](https://huggingface.co/docs/optimum/habana/usage_guides/multi_node_training)。

你也可以使用参数 `--dataset_name my_dataset_name` 从 Hugging Face Hub 加载任意数据集作为生成用的提示词来源。

本基准测试使用 Transformers v4.28.1、SynapseAI v1.9.0 和 Optimum Habana v1.5.0 完成。

对于 GPU，[这里](https://github.com/huggingface/transformers-bloom-inference/blob/main/bloom-inference-scripts/bloom-ds-inference.py)是产出先前结果的脚本，结果曾在[这篇博客](https://huggingface.co/blog/bloom-inference-pytorch-scripts)中发布（使用方法是[这里](https://github.com/huggingface/transformers-bloom-inference/tree/main/bloom-inference-scripts#deepspeed-inference)的说明）。要使用 CUDA graphs，需要静态 shape，而这在 🤗 Transformers 中不受支持。你可以使用 Habana 团队编写的[这个仓库](https://github.com/HabanaAI/Model-References/tree/1.8.0/PyTorch/nlp/bloom)来启用它。

## 结论

本文展示了 **Habana Gaudi2 的 BLOOMZ 推理快于 Nvidia A100 80GB**。而且不必编写复杂的脚本——🤗 [Optimum Habana](https://huggingface.co/docs/optimum/habana/index) 提供了易用的工具，就能在 HPU 上运行数千亿参数模型的推理。Habana 的 SynapseAI SDK 未来版本预计会带来进一步加速，随着 SynapseAI 上的 LLM 推理优化持续演进，我们也会定期更新这份基准测试。我们同样期待 Gaudi2 上 FP8 推理带来的性能红利。

我们还展示了第一代 Gaudi 的成绩。对较小的模型，它能达到与 A100 相当甚至更好的表现，价格却约为其三分之一。对于 BLOOMZ 这种超大模型的推理，它是 GPU 之外的一个优秀替代选择。
