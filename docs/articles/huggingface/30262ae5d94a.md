# 使用 Hugging Face Transformers 和 Amazon SageMaker 部署 GPT-J 6B 推理

差不多正好 6 个月前，[EleutherAI](https://www.eleuther.ai/) 发布了 [GPT-J 6B](https://huggingface.co/EleutherAI/gpt-j-6B)，作为 [OpenAI GPT-3](https://openai.com/blog/gpt-3-apps/) 的开源替代。[GPT-J 6B](https://huggingface.co/EleutherAI/gpt-j-6B) 是 [EleutherAI](https://www.eleuther.ai/) GPT-NEO 家族的 60 亿参数后继者——这是一个基于 GPT 架构、用 transformer 做文本生成的语言模型家族。

[EleutherAI](https://www.eleuther.ai/) 的首要目标是训练一个与 GPT-3 体量相当的模型，并以开放许可证公之于众。

过去 6 个月里，`GPT-J` 引起了研究员、数据科学家乃至软件开发者的大量关注，但要把 `GPT-J` 部署进生产环境服务真实用例和产品，仍然非常困难。

确实有一些托管方案可以在生产负载中使用 `GPT-J`，比如 [Hugging Face Inference API](https://huggingface.co/inference-api)，或者用 [EleutherAI 的 6b playground](https://6b.eleuther.ai/) 做实验，但如何把它轻松部署到你自己的环境，例子少之又少。

在这篇博客里，你将学会如何用几行代码，借助 [Amazon SageMaker](https://aws.amazon.com/de/sagemaker/) 和 [Hugging Face Inference Toolkit](https://github.com/aws/sagemaker-huggingface-inference-toolkit)，在一张配备 NVIDIA T4 的常规 GPU 实例（约 500 美元/月）上，把 `GPT-J` 部署为可扩展、可靠、安全的实时推理服务。

不过在开始之前，我想先解释一下为什么部署 `GPT-J` 上生产这么难。

## 背景

这个 60 亿参数模型的权重代表着约 24GB 的内存占用。用 float32 加载它，至少需要 2 倍模型大小的 CPU 内存：1 倍放初始权重，另外 1 倍用于读取 checkpoint。也就是说，光是加载 `GPT-J` 就需要至少 48GB CPU 内存。

为了让模型更易用，[EleutherAI](https://www.eleuther.ai/) 同时提供了 float16 权重，而 `transformers` 也新增了若干减少大语言模型内存占用的选项。把这些组合起来，加载模型大约只需要 12.1GB CPU 内存。

```
from transformers import GPTJForCausalLM
import torch

model = GPTJForCausalLM.from_pretrained(
    "EleutherAI/gpt-j-6B",
        revision="float16",
        torch_dtype=torch.float16,
        low_cpu_mem_usage=True
)
```

这个例子的代价是：模型要花很长时间才能加载进内存、准备就绪。在我的实验中，在 `P3.2xlarge` AWS EC2 实例上用上面这段代码加载模型耗时 `3 分 32 秒`（模型当时不在磁盘上）。如果提前把模型存在磁盘上，可以缩短这个时间——加载时间降到 `1 分 23 秒`，但对于需要考虑扩缩和可靠性的生产负载来说仍然太长。

举个例子，Amazon SageMaker 对请求响应有一个 [60 秒的限制](https://docs.aws.amazon.com/general/latest/gr/sagemaker.html#sagemaker_region)，意味着模型加载加预测必须在 60 秒内完成——在我看来，这对保持模型/端点的可扩展性和可靠性非常合理。如果你有更长的预测任务，可以使用 [batch-transform](https://docs.aws.amazon.com/sagemaker/latest/dg/batch-transform.html)。

在 [Transformers](https://github.com/huggingface/transformers) 中，用 `from_pretrained` 方法加载的模型遵循 PyTorch 的[推荐实践](https://pytorch.org/tutorials/beginner/saving_loading_models.html#save-load-state-dict-recommended)，对 BERT 来说约需 `1.97 秒`[[REF]](https://colab.research.google.com/drive/1-Y5f8PWS8ksoaf1A2qI94jq0GxF2pqQ6?usp=sharing)。PyTorch 还提供了[另一种保存和加载模型的方式](https://pytorch.org/tutorials/beginner/saving_loading_models.html#save-load-entire-model)：`torch.save(model, PATH)` 和 `torch.load(PATH)`。

*「以这种方式保存模型会用 Python 的 [pickle](https://docs.python.org/3/library/pickle.html) 模块序列化整个模块。这种做法的缺点是，序列化数据会绑定到保存模型时所用的特定类和确切的目录结构。」*

这意味着，用 `transformers==4.13.2` 保存的模型，在试图用 `transformers==4.15.0` 加载时可能不兼容。不过，用这种方式加载模型可以把加载时间缩短 **约 12 倍**——BERT 降到 `0.166 秒`。

套用到 `GPT-J` 上，就意味着我们可以把加载时间从 `1 分 23 秒` 压到 `7.7 秒`，快了约 10.5 倍。

## 教程

用这种保存和加载模型的方法，我们让 `GPT-J` 的模型加载性能达到了生产场景可用的水平。但要记住，我们必须对齐：

> 在用 torch.save(model, PATH) 保存模型和用 torch.load(PATH) 加载模型时，对齐 PyTorch 和 Transformers 的版本，以避免不兼容。

### 用 `torch.save` 保存 `GPT-J`

要创建我们支持 `torch.load()` 的模型文件，先用 Transformers 的 `from_pretrained` 方法加载 `GPT-J`，然后用 `torch.save()` 保存。

```
from transformers import AutoTokenizer,GPTJForCausalLM
import torch

# load fp 16 model
model = GPTJForCausalLM.from_pretrained("EleutherAI/gpt-j-6B", revision="float16", torch_dtype=torch.float16)
# save model with torch.save
torch.save(model, "gptj.pt")
```

现在我们就能用 `torch.load()` 加载我们的 `GPT-J` 模型来跑预测了。

```
from transformers import pipeline
import torch

# load model
model = torch.load("gptj.pt")
# load tokenizer
tokenizer = AutoTokenizer.from_pretrained("EleutherAI/gpt-j-6B")

# create pipeline
gen = pipeline("text-generation",model=model,tokenizer=tokenizer,device=0)

# run prediction
gen("My Name is philipp")
#[{'generated_text': 'My Name is philipp k. and I live just outside of Detroit....
```

### 为 Amazon SageMaker 实时端点创建 `model.tar.gz`

既然我们能快速加载模型并运行推理，那就把它部署到 Amazon SageMaker。

把 transformers 部署到 Amazon SageMaker 有两种方式：[「从 Hugging Face Hub 直接部署模型」](https://huggingface.co/docs/sagemaker/inference#deploy-a-model-from-the-%F0%9F%A4%97-hub)，或者[「部署 `model_data` 存在 S3 上的模型」](https://huggingface.co/docs/sagemaker/inference#deploy-with-model_data)。由于我们不再使用默认的 Transformers 加载方式，只能选第二种：用存在 S3 上的模型部署端点。

为此，我们需要创建一个 `model.tar.gz` 制品，包含模型权重以及推理所需要的其他文件，例如 `tokenizer.json`。

**我们已上传了公开可访问的 `model.tar.gz` 制品，可直接配合 `HuggingFaceModel` 把 `GPT-J` 部署到 Amazon SageMaker。**

使用方法见[「把 `GPT-J` 部署为 Amazon SageMaker Endpoint」](https://www.notion.so/Deploy-GPT-J-6B-for-inference-using-Hugging-Face-Transformers-and-Amazon-SageMaker-ce65921edf2246e6a71bb3073e5b3bc7)。

如果你仍想（或因合规要求必须）自己创建 `model.tar.gz`，可以用辅助脚本 [convert_gpt.py](https://github.com/philschmid/amazon-sagemaker-gpt-j-sample/blob/main/convert_gptj.py)：它会创建 `model.tar.gz` 并上传到 S3。

```
# clone directory
git clone https://github.com/philschmid/amazon-sagemaker-gpt-j-sample.git

# change directory to amazon-sagemaker-gpt-j-sample
cd amazon-sagemaker-gpt-j-sample

# create and upload model.tar.gz
pip3 install -r requirements.txt
python3 convert_gptj.py --bucket_name {model_storage}
```

`convert_gpt.py` 应该会打印出类似这样的 S3 URI：`s3://hf-sagemaker-inference/gpt-j/model.tar.gz`。

### 把 `GPT-J` 部署为 Amazon SageMaker Endpoint

部署 Amazon SageMaker Endpoint 时，我们使用 [Amazon SageMaker Python SDK](https://sagemaker.readthedocs.io/en/stable/) 和 `HuggingFaceModel` 类。

下面的代码片段使用了 `get_execution_role`，它只在 Amazon SageMaker Notebook Instance 或 Studio 内可用。如果你想在其外部部署模型，请查阅[文档](https://huggingface.co/docs/sagemaker/train#installation-and-setup#)。

`model_uri` 指定我们 `GPT-J` 模型制品的位置。这里用我们提供的公开可用的那一个。

```
from sagemaker.huggingface import HuggingFaceModel
import sagemaker

# IAM role with permissions to create endpoint
role = sagemaker.get_execution_role()

# public S3 URI to gpt-j artifact
model_uri="s3://huggingface-sagemaker-models/transformers/4.12.3/pytorch/1.9.1/gpt-j/model.tar.gz"

# create Hugging Face Model Class
huggingface_model = HuggingFaceModel(
    model_data=model_uri,
    transformers_version='4.12.3',
    pytorch_version='1.9.1',
    py_version='py38',
    role=role, 
)

# deploy model to SageMaker Inference
predictor = huggingface_model.deploy(
    initial_instance_count=1, # number of instances
    instance_type='ml.g4dn.xlarge' #'ml.p3.2xlarge' # ec2 instance type
)
```

如果你想用自己的 `model.tar.gz`，只需把 `model_uri` 换成你的 S3 URI。

部署大约需要 3-5 分钟。

### 运行预测

我们可以用 `.deploy` 方法创建的 `predictor` 实例来跑预测。向端点发送请求，用 `predictor.predict` 传入我们的 `inputs`。

```
predictor.predict({
    "inputs": "Can you please let us know more details about your "
})
```

如果你想用 `min_length` 等额外 `kwargs` 自定义预测，参见下面的「使用最佳实践」。

## 使用最佳实践

使用生成模型时，大多数时候你都想按自己的需求配置或定制预测，例如使用 beam search、设置生成序列的最大/最小长度，或调节温度以减少重复。Transformers 库为此提供了各种策略和 `kwargs`，Hugging Face Inference toolkit 也提供了同样的功能，用请求载荷里的 `parameters` 字段即可。下面你会看到不带参数的默认生成、beam search 以及自定义配置的例子。想了解不同的解码策略，可以读这篇[博客](https://huggingface.co/blog/how-to-generate)。

### 默认请求

这是使用 `greedy`（贪心）搜索的默认请求示例。

首次请求之后的推理时间：`3 秒`

```
predictor.predict({
    "inputs": "Can you please let us know more details about your "
})
```

### Beam search 请求

这是使用 5 条 beam 的 `beam` 搜索请求示例。

首次请求之后的推理时间：`3.3 秒`

```
predictor.predict({
    "inputs": "Can you please let us know more details about your ",
  "parameters" : {
    "num_beams": 5,
  }
})
```

### 带参数的请求

这是使用自定义参数的请求示例，例如用 `min_length` 至少生成 512 个 token。

首次请求之后的推理时间：`38 秒`

```
predictor.predict({
    "inputs": "Can you please let us know more details about your ",
  "parameters" : {
    "max_length": 512,
    "temperature": 0.9,
  }
})
```

### Few-Shot 示例（进阶）

这是一个展示如何用 `eos_token_id` 在遇到特定 token 时停止生成的例子，例如对 few-shot 预测可用 `\n`、`.` 或 `###`。下面是根据关键词生成推文（tweet）的 few-shot 示例。

首次请求之后的推理时间：`15-45 秒`

```
from transformers import AutoTokenizer
tokenizer = AutoTokenizer.from_pretrained("EleutherAI/gpt-j-6B")

end_sequence="###"
temperature=4
max_generated_token_length=25
prompt= """key: markets
tweet: Take feedback from nature and markets, not from people.
###
key: children
tweet: Maybe we die so we can come back as children.
###
key: startups
tweet: Startups shouldn’t worry about how to put out fires, they should worry about how to start them.
###
key: hugging face
tweet:"""

predictor.predict({
    'inputs': prompt,
  "parameters" : {
    "max_length": int(len(prompt) + max_generated_token_length),
    "temperature": float(temperature),
    "eos_token_id": int(tokenizer.convert_tokens_to_ids(end_sequence)),
    "return_full_text":False
  }
})
```

要删除你的端点，可以运行：

```
predictor.delete_endpoint()
```

## 结论

我们成功用 Amazon SageMaker 部署了 `GPT-J`——[EleutherAI](https://www.eleuther.ai/) 打造的 60 亿参数语言模型。模型加载时间从 3.5 分钟降到 8 秒，从而可以运行可扩展、可靠的推理。
