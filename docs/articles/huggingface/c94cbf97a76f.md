2023 年，公众对大语言模型（LLM）的兴趣激增。如今大多数人都已经了解 LLM 是什么、能做什么，围绕开源与闭源的公共讨论也触及了更广泛的受众。在 Hugging Face，我们非常关注开放模型，因为它们让研究可复现、让社区能够参与 AI 模型的开发、更容易审视模型的偏见与局限，并通过鼓励 checkpoint 复用降低整个行业的碳排放（此外还有[许多其他好处](https://huggingface.co/papers/2302.04844)）。

那么，让我们来回顾一下开放 LLM 的一年！

*为了让本文篇幅可控，我们不会讨论代码模型。*

## 🍜 预训练大语言模型的配方

首先，一个大语言模型是怎么来的？（如果你已经了解，可以自由略过本节！）

模型的**架构**（architecture，即其代码）描述了具体的实现方式和数学形状：它是模型全部参数的清单，以及这些参数如何与输入相互作用。目前性能最高的 LLM 大多是「decoder-only」Transformer 架构的变体（更多细节见[原始 transformers 论文](https://huggingface.co/papers/1706.03762)）。

**训练数据集**包含模型训练所用（即参数被学习出来）的全部样本和文档，也因此决定了模型学到的具体模式。这些文档在大多数情况下是文本：自然语言（如法语、英语、中文）、编程语言（如 Python、C），或任何可以表示为文本的结构化数据（如 markdown 或 latex 表格、公式等）。

**Tokenizer（分词器）**定义了如何把训练数据集中的文本转换为数字（因为模型是一个数学函数，需要数字作为输入）。分词通过把文本转换为称为 token 的子单元来完成（根据分词方法不同，token 可以是词、子词或字符）。tokenizer 的词表大小表示它认识多少种不同的 token，通常在 32k 到 200k 之间。数据集的规模通常以拆分成这些独立「原子」单元序列后所含的 **token 数量**来衡量，如今范围从几千亿 token 到几万亿 token！

**训练超参数**则定义了模型如何被训练：为拟合每个新样本，参数应该调整多少？模型更新的节奏应该多快？

选定这些参数之后，你只需要：1）大量算力来训练模型，2）有能力（且友善）的人员来运行和监控训练。训练本身包括实例化架构（在训练所用的硬件上创建矩阵），并用上述超参数在训练数据集上运行训练算法。得到的结果是一组模型**权重（weights）**——即学习之后的模型参数，也是大多数人说「开放预训练模型」时所指的东西。这些权重随后可用于**推理（inference）**，即对新输入做预测，例如生成文本。

预训练 LLM 在预训练之后还可以被专门化或适配到特定任务，尤其是当权重公开发布时。它们通过称为 **fine-tuning（微调）**的过程，被用作各种用例和应用的起点。微调是在另一个通常更专门、更小的数据集上对模型施加额外的训练步骤，使其针对特定应用进行优化。虽然这一步也有算力成本，但无论在经济上还是环境上，通常都比从零训练一个模型便宜得多。这正是高质量开源预训练模型非常有价值的原因之一：即便从业者只有有限的计算预算，也可以自由使用并在其之上继续构建。

## 🗝️ 2022：从拼规模到拼数据

2023 年之前，社区能用到哪些开放模型？

直到 2022 年初，机器学习界的趋势还是：模型越大（参数越多），性能越好。特别是，模型一旦越过某些规模门槛，能力似乎就会出现跃升——这两个概念被称为 `emergent abilities`（涌现能力）和 `scaling laws`（缩放定律）。2022 年发布的开源预训练模型家族大多遵循这一范式。

- [BLOOM](https://huggingface.co/papers/2211.05100)（BigScience Large Open-science Open-access Multilingual Language Model）：BLOOM 是由 BigScience 发布的一系列[模型](https://huggingface.co/bigscience/bloom)。BigScience 是一项协作工程，汇聚了来自 60 个国家、250 家机构的 1000 名研究者，由 Hugging Face 协调，并与法国机构 GENCI 和 IDRIS 合作。这些模型使用 decoder-only transformer，并做了少量修改（embedding 后置归一化[^1]，以及使用 ALiBi 位置嵌入[^2]）。该家族中最大的模型有 176B 参数，在覆盖 46 种人类语言和 13 种编程语言的 350B token 多语数据上训练。大部分训练数据已发布，其来源、整理与处理细节也已公开。它是迄今为止最大的开源大规模多语模型。
- [OPT](https://huggingface.co/papers/2205.01068)（Open Pre-trained Transformer）：OPT [模型](https://huggingface.co/facebook/opt-66b)家族由 Meta 发布。这些模型采用 decoder-only transformers 架构，沿用了 GPT-3 论文的诸种技巧（特定的权重初始化、预归一化），并对注意力机制做了一些改动（稠密与局部带状注意力层交替）。该家族最大的模型有 175B 参数，在主要来自公开来源（书籍、通过 Reddit 获取的社交数据、新闻、维基百科及其他各种互联网来源）的 180B token 数据上训练。该家族模型性能与 GPT-3 相当，并通过编码优化降低了计算强度。
- [GLM-130B](https://huggingface.co/papers/2210.02414)（General Language Model）：[GLM-130B](https://huggingface.co/THUDM/glm-roberta-large) 由清华大学和智谱 AI（Zhipu.AI）发布。它使用带有一些改动的完整 transformer 架构（结合 DeepNorm 的层后归一化、旋转位置编码）。这个 130B 参数的模型在中英文互联网数据（The Pile、Wudao Corpora 及其他中文语料）的 400B token 上训练，性能同样与 GPT-3 模型相当。
- 更小或更专门的开放 LLM：一些更小的开源模型也被发布，主要用于研究目的。Meta 发布了 [Galactica](https://huggingface.co/papers/2211.09085) 系列，最大有 [120B](https://huggingface.co/facebook/galactica-120b) 参数，在 106B token 的科学文献上预训练；EleutherAI 发布了 [GPT-NeoX-20B](https://huggingface.co/EleutherAI/gpt-neox-20b) 模型——一个完全开源（包括架构、权重、数据）的 decoder transformer 模型，在 500B token 上训练（使用 RoPE 并对注意力和初始化做了改动），旨在为科学研究提供完整的可复现工件。

这些巨型模型令人兴奋，但运行起来也非常昂贵！执行推理（从模型计算预测）时，模型需要加载到内存中，而一个 100B 参数的模型通常需要 220GB 内存才能加载（下文会解释这个过程），这非常庞大，大多数组织和从业者都无法负担！

然而在 2022 年 3 月，DeepMind 发表了一篇[新论文](https://huggingface.co/papers/2203.15556)，研究在给定计算预算下 token 与模型参数的最优比例是什么。换句话说，如果你只有 X 金额可以花在模型训练上，模型和数据的大小分别应该是什么？作者们发现，总体而言，就当前 LLM 平均计算预算来说，模型应该更小、但在多得多的数据上训练。他们自己的模型 Chinchilla（非开源）有 70B 参数（只有上述模型的三分之一大小），但在 1.4T token 的数据上训练（数据量是其 3 到 4 倍）。无论与开源还是闭源的更大模型相比，它的性能都相当或更好。

这一范式转变（在闭源实验室里可能早已知晓）席卷了开放科学社区。

## 🌊 2023：开放发布之年

### 小型大语言模型的崛起

2023 年涌现出一波 decoder 风格 transformer 的浪潮，新的预训练模型一开始是每月发布，很快变成每周、甚至每天发布：2 月是 LLaMA（Meta），4 月是 StableLM（StabilityAI）和 Pythia（Eleuther AI），5 月是 MPT（MosaicML），6 月是 X-GEN（Salesforce）和 Falcon（TIIUAE），7 月是 Llama 2（Meta），8 月是 StableLM v2（StabilityAI），9 月是 Qwen（阿里巴巴）和 Mistral（Mistral.AI），11 月是 Yi（01-ai），12 月是 DeciLM（Deci）、Phi-2 和 SOLAR（Upstage）。

所有这些发布 a）都包含模型权重（许可证的开放程度不一），b）在较小规模（3B 到 70B 参数）的模型上具备不错的性能，因此被社区迅速采用。几乎所有这些模型都使用 decoder transformer 架构，并做了各种调优（ALiBi 或 RoPE、RMS 预归一化、SwiGLU），还对注意力函数做了改动（Flash-Attention、GQA、滑动窗口），以及采用不同的代码库实现来优化训练或推理速度。这些调优多少会影响性能和训练速度；不过，由于所有架构都已随权重公开发布，留下来的核心差异其实是训练数据和模型的许可证。

这一系列中的第一个模型家族是 Meta AI 发布的 [LLaMA](https://huggingface.co/papers/2302.13971) 家族。研究人员的明确目标是训练一组不同规模的模型，在给定计算预算下取得尽可能好的性能。研究团队第一次明确决定不仅考虑训练预算，还要考虑推理成本（对某一性能目标而言，运行推理要花多少钱）。基于这一考虑，他们决定用比通常更多的数据、更多的步数去训练更小的模型，从而在更小的模型规模上达到更高的性能（代价是训练计算效率）。Llama 1 家族中最大的模型是 65B 参数、在 1.4T token 上训练，而较小的模型（分别为 6B 和 13B 参数）在 1T token 上训练。小巧的 13B LLaMA 模型在多数基准上超越了 GPT-3，而最大的 LLaMA 模型发布时即是当时的 SOTA。不过权重附带非商业许可证，限制了社区采用。

[Pythia](https://huggingface.co/papers/2304.01373) 模型由开源非营利实验室 Eleuther AI 发布，是一[系列不同尺寸的 LLM](https://huggingface.co/collections/EleutherAI/pythia-scaling-suite-64fb5dfa8c21ebb3db7ad2e1)，完全在公开数据上训练，旨在帮助研究者理解 LLM 训练的不同阶段。

几个月后 MosaicML 发布的 [MPT 模型](https://www.mosaicml.com/blog/mpt-7b)性能接近，但许可证允许商业使用，并公开了训练数据配方的细节。第一个 MPT 模型是一个 [7B 模型](https://huggingface.co/mosaicml/mpt-7b)，随后 6 月又发布了 30B 版本，两者都在 1T token 的英文与代码数据（来自 C4、CommonCrawl、The Stack、S2ORC）上训练。

MPT 之后很快出现 TIIUAE 发布的 Falcon 系列 7B 和 30B [模型](https://huggingface.co/tiiuae/falcon-7b)（[Falcon 系列](https://huggingface.co/collections/tiiuae/falcon-64fb432660017eeec9837b5a)），在 1 到 1.5T token 的英文与代码数据（RefinedWeb、Project Gutenberg、Reddit、StackOverflow、Github、arXiv、维基百科等来源）上训练——这年晚些时候还发布了庞大的 180B 模型。Falcon 的模型、数据和训练过程在一篇技术报告和一篇[后续研究论文](https://huggingface.co/papers/2311.16867)中有详细说明。

继承自 GPT-Neo-X 模型，StabilityAI 发布了 [StableLM-Base-Alpha](https://huggingface.co/stabilityai/stablelm-base-alpha-7b) 模型——一个小型（3B 和 7B）预训练系列，使用基于 ThePile 构建的实验性数据集的 1.5T token；随后是数据配方包含 RefinedWeb、RedPajama、ThePile 及未公开内部数据集的 [v2 系列](https://huggingface.co/stabilityai/stablelm-base-alpha-7b-v2)；最后是一个非常小的 3B 模型 [StableLM-3B-4e1T](https://huggingface.co/stabilityai/stablelm-3b-4e1t)，并附有[详细技术报告](https://stability.wandb.io/stability-llm/stable-lm/reports/StableLM-3B-4E1T--VmlldzoyMjU4?accessToken=u3zujipenkx5g7rtcj9qojjgxpconyjktjkli2po09nffrffdhhchq045vp0wyfo)。

此前的模型大多公开其数据，而从此之后的发布几乎不再说明模型用什么数据训练，其工作无法复现——不过它们通过发布的权重为社区提供了起点。

初夏时节，Salesforce 发布了 [X-Gen](https://huggingface.co/papers/2309.03450) [模型](https://huggingface.co/Salesforce/xgen-7b-4k-base)——7B 参数模型，在 1.5T token 的「自然语言和代码」上按多个阶段、遵循数据调度系统（并非所有数据都同时引入模型）训练。

X-Gen 多少被 Meta 万众瞩目的新 [LLaMA-2](https://huggingface.co/papers/2307.09288) 家族盖过了风头：LLaMA-2 是一系列 [7B 到 70B 模型](https://huggingface.co/meta-llama/Llama-2-7b)，在「来自公开可得来源」的 2T token 上训练，附带宽松的社区许可证，以及一整套基于人类偏好的微调（RLHF）流程，即所谓的对齐（alignment）程序。

几个月后，新创公司 Mistral 的首个[模型](https://huggingface.co/mistralai/Mistral-7B-v0.1)——即 [Mistral-7B](https://huggingface.co/papers/2310.06825)——发布了，在用「从开放 Web 提取」的数据训练的 token 数量未公开。2023 年末的模型发布非常密集：Mistral 的第二个更大模型（Mixtral 8x7B）、Deci.AI 首个令人印象深刻的模型 [DeciLM](https://deci.ai/blog/introducing-DeciLM-7B-the-fastest-and-most-accurate-7b-large-language-model-to-date)（[链接](https://huggingface.co/Deci/DeciLM-7B)），以及 Upstage 将多个模型合并而成的更大模型 [SOLAR](https://huggingface.co/upstage/SOLAR-10.7B-v1.0)，其数据量和来源同样未公开。所有这些模型都在排行榜和开放基准上稳步提升。

与此同时，2023 年末一个值得关注的事件是在中国训练并公开发布的模型在数量和性能上的崛起。两个中英双语模型系列发布：来自阿里巴巴的 [Qwen](https://huggingface.co/papers/2309.16609)（[模型](https://huggingface.co/Qwen/Qwen-72B)规模 7B 到 72B 参数，在 2.4T token 上训练），以及来自 01-AI 的 [Yi](https://huggingface.co/01-ai/Yi-34B)（模型规模 6B 到 34B 参数，在 3T token 上训练）。这些模型的性能领先于此前的模型，无论实在 [Open LLM leaderboard](https://huggingface.co/spaces/HuggingFaceH4/open_llm_leaderboard) 这样的开放排行榜上，还是在 [Skill-Mix](https://huggingface.co/papers/2310.17567) 这类最困难的基准上。2023 年末另一位强劲选手是 [DeepSeek AI](https://huggingface.co/deepseek-ai) 的 DeepSeek 代码模型，在 2T token 上从头训练，数据构成 87% 代码、13% 中英文自然语言（本质上主要是代码模型）。

### 对话模型无处不在

与 2022 年相比，2023 年发布的几乎所有预训练模型都同时提供预训练版本和对话微调版本，采用的是几种现有方法之一。虽然把模型适配到对话场景的方法在 2022 年及更早便已开发，但这些技术的广泛采用真正起飞是在 2023 年，凸显出公众对聊天模型的使用日益增长，以及通过直接与模型对话进行的人工评测（「vibe-check」式评估）日益增多。这里我们详述最广为人知的把预训练模型适配为聊天模型的方法，但实际上存在许多变体！

**基于对话的微调（Chat-based fine-tuning）**是监督微调的一种变体：标注数据是聊天数据（多轮对话式数据，很像你在社交媒体上会见到的那种），你用这些数据来微调模型。使用的技术与训练模型时相同：对于 decoder transformer，就是教会模型逐词预测下一个词（称为自回归方法）。

**指令微调（Instruction fine-tuning，IFT）**遵循同样的思路，但使用指令数据集——其中包含成对的类查询提示（prompt）加答案（必要时还有可选的附加输入）。这些数据集教会模型如何遵循指令，可以由人类或 LLM 生成。使用大规模的模型输出合成数据集（由模型生成内容构成的数据集，例如来自 GPT-4 的生成，可以是基于指令生成，也可以基于用户与该模型的交互）是实现指令微调和聊天微调的方式之一。这通常被称为 `distillation`（蒸馏），因为它涉及把高性能模型的知识用来训练或微调一个更小的模型。

这两种方法都相对容易实现：你只需要找到或生成相关数据集，然后用与训练时相同的技术微调模型。去年发布了大量指令数据集，提升了模型在对话式场景中的表现。想更深入了解这一主题，可以阅读这篇入门博客（[这里](https://huggingface.co/blog/dialog-agents)）。不过，模型虽然更好了，仍然未必能满足人类的期望。

**基于人类反馈的强化学习（RLHF）**是一种专门的方法，旨在让模型的预测对齐人类最喜欢（依据特定标准）的输出。在（年初时）它还是一种新的微调技术：给定一个提示，模型生成多个可能的回答；人类对这些回答排序；排序被用来训练一个所谓偏好模型（preference model，它学会给出反映人类偏好的分数）；然后用强化学习借助偏好模型来微调语言模型。更详细的信息见这篇[博客](https://huggingface.co/blog/rlhf)、[RLHF 原始论文](https://huggingface.co/papers/1909.08593)，或 Anthropic 关于 [RLHF](https://huggingface.co/papers/2204.05862) 的论文。这是一种昂贵的方法（标注/排序 + 训练一个新模型 + 微调都相当贵），主要用于面向安全目标地对齐模型。一种更便宜的变体被开发出来：用一个高质量 LLM 代替人类为模型输出排序，即**基于 AI 反馈的强化学习（RLAIF）**。

**直接偏好优化（DPO）**是 RLHF 的另一种变体，但不需要训练和使用单独的偏好模型——该方法同样需要人类或 AI 的排序数据集，但通过观察模型原始策略（预测方式）与最优策略（会预测排名最好的答案）之间的差异，直接用这些数据更新模型。换句话说，被对齐后的模型本身就是偏好模型，这让优化流程简单得多，而最终表现看起来相当。

好，回到我们前面讲的（主要来自私营公司的）小型开放权重模型浪潮：其中很多都随发布附带了微调版本。MPT-7B 同时带来了 instruct 版和 chat 版，Falcon 和 XGen 的指令微调版在年末发布，Llama-2、Qwen 和 Yi 发布了聊天版本，DeciLM 则带有一个 instruct 版本。Llama-2 的发布格外引人瞩目，因为它在预训练和微调模型中都对安全给予了高度重视。

### 社区呢？

虽然聊天模型和指令微调模型通常会随新模型发布直接提供，但社区和研究者并没有把这视为理所当然：在这些基座模型提供的肥沃土壤上，一个庞大而健康的模型微调社区蓬勃发展，讨论自发地发生在 Reddit、Discord、Hugging Face Hub 和 Twitter 上。社区模型发布非常频繁，与各种有趣新数据集的创建同步进行（这些数据集也被用于微调模型并验证其良好性能和品质）。

2023 年初，已有一些用于指令/聊天微调的数据集发布。例如在人类偏好方面，OpenAI 的 [WebGPT](https://huggingface.co/datasets/openai/webgpt_comparisons) 数据集、Anthropic 的 [HH-RLHF 数据集](https://github.com/anthropics/hh-rlhf)和 OpenAI 的 [Summarize](https://huggingface.co/datasets/openai/summarize_from_feedback) 在这一方向上具有开创意义。指令数据集的例子包括 BigScience 的 [Public Pool of Prompts](https://huggingface.co/datasets/bigscience/P3)、Google 的 [FLAN](https://github.com/google-research/FLAN) 1 和 2、AllenAI 的 [Natural Instructions](https://github.com/allenai/natural-instructions)、由多位不同机构研究者开发的自动生成指令框架 [Self Instruct](https://github.com/yizhongw/self-instruct)、有时被用作微调数据的专家创建指令基准 [SuperNatural instructions](https://aclanthology.org/2022.emnlp-main.340/)、由特拉维夫大学和 Meta 自动生成的指令数据集 [Unnatural instructions](https://aclanthology.org/2023.acl-long.806.pdf) 等等。

❄️ 2022/2023 冬季：今年 1 月，来自多家机构的中国研究者发布了 [Human ChatGPT Instruction 语料库](https://huggingface.co/datasets/Hello-SimpleAI/HC3)（HC3），包含人类与模型对各类问题的回答对比。3 月则被各种发布填满：斯坦福开放了 [Alpaca](https://github.com/tatsu-lab/stanford_alpaca) 模型——第一个遵循指令的 LLaMA 模型（7B）——以及配套数据集（用 LLM 生成的 5.2 万条指令）。LAION（一家开源非营利实验室）发布了 [Open Instruction Generalist](https://laion.ai/blog/oig-dataset/)（OIG）数据集，包含 4300 万条指令，既有数据增广创建的，也有从其他已有数据源汇编的。同月，LMSYS org（加州大学伯克利分校）发布了 [Vicuna](https://lmsys.org/blog/2023-03-30-vicuna/)，同样是一个 LLaMA 微调（13B），但这次用在聊天数据上：用户与 ChatGPT 的对话，由用户自己在 [ShareGPT](https://share-gpt.com/) 上公开分享。[Guanaco](https://huggingface.co/datasets/JosephusCheung/GuanacoDataset) 数据集（Alpaca 数据集的扩展，增加了 50 万条更多语种的条目）以及对应的 LLaMA-7B 微调也一并发布。

🌱 春季：4 月，BAIR（伯克利 AI 实验室）发布了 [Koala](https://bair.berkeley.edu/blog/2023-04-03/koala/)，一个聊天调优的 LLaMA 模型，使用了前面几个数据集（Alpaca、HH-RLHF、WebGPT、ShareGPT）；DataBricks 发布了 [Dolly](https://huggingface.co/datasets/databricks/databricks-dolly-15k) 数据集——1.5 万条人工手动生成指令的巨大人力成果——以及配套的 Pythia 微调模型。5 月，清华大学发布了 [UltraChat](https://arxiv.org/abs/2305.14233)——一个包含指令的 150 万条对话数据集——以及在该数据集上微调的 UltraLLaMA。随后 Microsoft 发布了 [GPT4-LLM](https://github.com/Instruction-Tuning-with-GPT-4/GPT-4-LLM) 数据集/框架，用 GPT4 生成指令；6 月，Microsoft research 分享了一种新方法 [Orca](https://arxiv.org/pdf/2306.02707.pdf)，利用更大模型的推理轨迹（展示其逐步推理过程）来构建指令数据集——该做法很快被社区复现（特别是 Alignmentlab.ai），创建了数百万条条目的 [Open Orca](https://huggingface.co/Open-Orca) 数据集，用于微调一批模型（Llama、Mistral 等）。5 月和 6 月，[Camel-AI](https://huggingface.co/camel-ai) 用 GPT4 在不同主题（物理、生物、化学等，每个领域超过 2 万条样本）发布了一批指令或聊天数据集。同样在 6 月，[Airoboros](https://github.com/jondurbin/airoboros) 框架（按照 self-instruct 思路用模型生成数据微调模型）以及一系列 [instruct 数据集](https://huggingface.co/jondurbin)发布。

🌻 夏季：8 月，中国非营利组织 OpenBMB 发布了 [UltraLM](https://github.com/thunlp/UltraChat)（LLaMA 的高性能聊天微调）；9 月，他们发布了配套的偏好数据集 [UltraFeedback](https://huggingface.co/datasets/openbmb/UltraFeedback)——一个由 GPT4 对比输入（并附带标注）的反馈数据集。整个夏季，团体 [NousResearch](https://huggingface.co/NousResearch) 基于若干私人和公开指令数据集发布了多个微调模型（特别是 Hermes 和 Capybara 系列）。9 月，清华大学的学生团队发布了 [OpenChat](https://huggingface.co/openchat/openchat_3.5)——一个采用新 RL 微调策略的 LLaMA 微调；Intel 发布了一个 [Orca 风格的 DPO 数据集](https://huggingface.co/datasets/Intel/orca_dpo_pairs)。

🍂 秋季：10 月，Hugging Face 发布了 [Zephyr](https://huggingface.co/HuggingFaceH4/zephyr-7b-beta)——在 UltraChat 和 UltraFeedback 上使用 DPO 和 AI 反馈的 Mistral 微调；社区成员发布了 [OpenHermes 2](https://huggingface.co/teknium/OpenHermes-2-Mistral-7B)——一个在 90 万条来自网页或用 Axolotl 生成的条目上微调的 Mistral-7B。Lmsys 发布了 LMSYS-Chat-1M——与 25 个 LLM 的真实用户对话。11 月，OpenBuddy 发布 OpenBuddy-Zephyr——在多轮对话数据上对 Zephyr 的微调；Argilla 发布了 [Notus](https://huggingface.co/argilla/notus-7b-v1)——对 Zephyr 的 DPO 微调。NVIDIA 发布了 [HelpSteer](https://huggingface.co/datasets/nvidia/HelpSteer)——一个对齐微调数据集，提供提示、相应模型回答，以及按多项标准对这些回答评出的分数；Microsoft Research 发布了 [Orca-2](https://huggingface.co/microsoft/Orca-2-13b) 模型——在一个新的合成推理数据集上微调的 Llama 2；Intel 则发布了 [Neural Chat](https://huggingface.co/Intel/neural-chat-7b-v3-1)——在 Orca 上微调并使用 DPO 的 Mistral。12 月，Berkeley 发布了 [Starling](https://huggingface.co/berkeley-nest/Starling-LM-7B-alpha)——对 OpenChat 的 RLAIF 微调——以及配套数据集 [Nectar](https://huggingface.co/datasets/berkeley-nest/Nectar)，包含 20 万条对比数据。

如我们所见，这一年的发展既依赖于利用高质量预训练 LLM 创建新数据集，也依赖于社区发布的所有开放模型，两者共同推动该领域实现跨越式前进！如果你现在在模型名字里看到这些名称中的某一个，你就能大致知道它出自哪里 🤗

注：*一些更专门的数据集（如数学题微调数据集 [MetaMath](https://meta-math.github.io/) 和 [MathInstruct](https://huggingface.co/datasets/TIGER-Lab/MathInstruct)、数学与代码指令数据集 [Evol-Instruct](https://huggingface.co/datasets/WizardLM/WizardLM_evol_instruct_70k)、代码指令数据集 [CodeAlpaca](https://huggingface.co/datasets/sahil2801/CodeAlpaca-20k) 和 [CodeCapybara](https://github.com/FSoft-AI4Code/CodeCapybara)）也已发布，这里不逐一详述，但它们同样被用于提升模型在特定任务上的表现。你还可以参见 [awesome instructions dataset](https://github.com/jianzhnie/awesome-instruction-datasets) 了解其他相关数据集的汇编。*

## 让访问普惠化

注：还有许多工具也涌现出来，为更初级的用户支持推理与部署，如 llama.cpp、ollama、text-generation-inference、vllm 等。它们不在本文的讨论范围内。

### 模型合并：极致的定制

以典型的开源风格，社区的一项标志性活动是模型/数据合并。随着每一次合并/提交，既很难追踪所用数据（因为不少发布的数据集本身就是对其他数据集的汇编），也很难追溯模型的历史——高性能模型往往是相似模型的微调版本的微调版本（在本总结中我们还没来得及讲这种神奇的技术，那就用最后几段话聊聊它。参见 Mistral 的「子模型树」[这里](https://huggingface.co/spaces/davanstrien/mistral-graph)。）

那么，合并一个模型是什么意思？

**模型合并（Model merging）**是把不同模型的权重融合进单个模型的方法，以（理想情况下）在统一的单模型中结合各模型的各自优势。已有若干技术可以做到这一点，它们大多在社区论坛上被扩展和发布，是全球范围内实践者、研究者与爱好者之间完全去中心化研究的一个生动案例。最简单的方法之一是对共享同一架构的一组模型的参数取平均（[示例 1](https://huggingface.co/papers/2204.03044)、[示例 2](https://huggingface.co/papers/2109.01903)），但也有更复杂的参数组合方式，例如确定在给定任务下每个模型中哪些参数最具影响力（[加权平均](https://huggingface.co/papers/2111.09832)），或在合并时先考虑参数在模型间的相互干扰再选择保留哪些参数（[ties merging](https://huggingface.co/papers/2306.01708)）。想概览相关文献，可以看看这个[很棒的论文集合](https://huggingface.co/collections/osanseviero/model-merging-65097893623330a3a51ead66)！

这些技术让任何人都能轻松生成模型的组合，而今天大多数模型都是同一架构的变体这一事实，使得合并尤其容易。这也是为什么提交到 [open LLM leaderboard](https://huggingface.co/spaces/HuggingFaceH4/open_llm_leaderboard) 的某些模型名字会像 `llama2-zephyr-orca-ultra` 这样。这个具体的例子很可能是 `llama2` 与 `zephyr` 模型的合并，并在 orca 和 ultra 数据集上做过微调。通常更多细节可以在 Hugging Face hub 上对应的模型卡中找到。

### PEFT：触手可及的个性化

有时候，你想要更可控的个性化，却没有足够的内存把整个模型加载进来做微调。你知道微调其实不需要动用整个模型吗？

你可能想用所谓的**参数高效微调（parameter efficient fine-tuning，PEFT）**。这种技术先冻结你感兴趣的预训练模型的参数，然后在其之上添加一批新参数，称为适配器（adapters）。你在自己任务上实际微调的只有（轻量的）适配器权重，比原始模型小得多。之后你只需要分享你的小适配器权重（加上新模型）即可！你可以在[这里](https://github.com/huggingface/peft)找到一系列值得关注的 PEFT 方法。

### 量化：模型到处能跑

我们已经看到，高性能模型如今有各种形状和尺寸……但即便如此，也不代表人人可用！一个 30B 参数的模型光是加载到内存（且不说使用）就可能需要的超过 66G 内存，而社区里并不是每个人都有相应的硬件。

这就是量化登场的地方！量化是一种通过改变参数精度来缩小模型体积的特殊技术。

这是什么意思？

在计算机里，数值以给定精度存储（如 `float32`、`float16`、`int8` 等）。精度既指明数值类型（是浮点数还是整数），也指明该数值占用多少内存：`float32` 用 32 位存储浮点数。想更深入理解，见[这个链接](https://huggingface.co/docs/optimum/concept_guides/quantization#going-further-how-do-machines-represent-numbers)。所以，精度越高，数值占用的物理内存越多，因为它存储在更多位上。

因此，如果降低精度，就降低了每个模型参数在存储中占用的内存，从而缩小模型体积！但这同时也意味着降低了……计算的实际精度，可能损害模型性能。不过我们发现，在更大的模型上，这种性能退化实际上非常[有限](https://huggingface.co/blog/overview-quantization-transformers)。

回到上面的例子：我们的 30B 参数模型在 `float16` 下需要略低于 66G 内存，在 `8bit` 下只需要一半，即 33G 内存；而 `4bit` 再减半，约 16G 内存，使其可用性大大提高。

从一种精度转换到另一种精度有很多方式，存在许多不同的「转换」方案，各有优劣。流行的方法包括 [bitsandbytes](https://huggingface.co/papers/2208.07339)、[GPTQ](https://huggingface.co/papers/2210.17323) 和 [AWQ](https://huggingface.co/papers/2306.00978)。一些用户，比如 [TheBloke](https://huggingface.co/TheBloke)，甚至在把热门模型转换格式以便社区使用。这些方法都非常新、仍在发展，希望随着时间推移能看到更多进展。

## 接下来呢？

这一年还没过完！最后的这几天/几小时已经带来不少惊喜：是否会有新架构最终在性能上超越简单高效的 Transformer？

新的发布包括：

- 混合专家（Mixture of experts）：[Mixtral](https://huggingface.co/mistralai/Mixtral-8x7B-v0.1)。该模型由 8 个子模型（transformer decoder）组成，对每个输入，一个路由（router）挑选最好的 2 个子模型并对其输出求和。
- 若干状态空间模型（state space models：通过潜空间把输入映射到输出的模型，依任务不同既可以表示为 RNN 也可以表示为 CNN；想更多了解状态模型，[这个资源](https://srush.github.io/annotated-s4/)讲解得很好）：[Mamba](https://huggingface.co/papers/2312.00752)，一种加入选择机制的状态空间模型；[Striped Hyena](https://huggingface.co/togethercomputer/StripedHyena-Nous-7B)，一种带快速卷积核的状态空间模型。

现在断言这些新方法是否会取代 Transformer 还言之过早，但状态空间模型相当有前景！

## 要点回顾

- 这一年见证了来自各类主体（大公司、初创公司、研究实验室）的开放发布浪潮，推动社区以前所未有的速度开始实验和探索。
- 模型公告的开放程度有起有伏：从年初发布时非常开放（数据配方、权重、架构），到年末发布对训练数据只字不提，从而无法复现。
- 开放模型从许多新地方涌现，包括中国，一些新玩家正把自己定位为 LLM 竞赛中的有力竞争者。
- 个性化能力达到历史新高，出现了新的微调策略（RLHF、适配器、合并），而它们才刚刚起步。
- 更小的模型规模和量化的进步，让 LLM 真正为更多的人所可用！
- 新架构也出现了——它们最终会取代 Transformer 吗？
