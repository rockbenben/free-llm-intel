# 开发 Diffusers 库的伦理准则

我们正走在让库更具责任感的路上，一次提交一个进步！

作为 [Diffusers 库文档](https://huggingface.co/docs/diffusers/main/en/index)的一部分，我们自豪地宣布发布了一份[伦理框架](https://huggingface.co/docs/diffusers/main/en/conceptual/ethical_guidelines)。

鉴于扩散模型在现实世界中的应用及其对社会的潜在负面影响，这一倡议旨在指导 Diffusers 库维护者在社区贡献方面的技术决策。我们希望以透明的方式做出决策，更重要的是，我们希望阐明指导这些决策的价值观。

我们将伦理视为一个融合引导价值、具体行动和持续调适的过程。因此，我们承诺随时间不断调整我们的准则，跟随 Diffusers 项目的演进，以及让这个社区保持活力的宝贵社区反馈。

## 伦理准则

- **透明（Transparency）**：我们承诺在管理 PR、向用户解释我们的选择以及做技术决策时保持透明。
- **一致性（Consistency）**：我们承诺在项目管理中为用户提供同等水平的关注，保持项目在技术上的稳定与一致。
- **简洁（Simplicity）**：怀着让 Diffusers 库易于使用和发挥价值的愿望，我们承诺保持项目目标的精简与连贯。
- **可及性（Accessibility）**：Diffusers 项目降低了贡献者的参与门槛，即使不具备专业技术背景也能参与维护。这让研究产物对整个社区更加触手可及。
- **可复现性（Reproducibility）**：当通过 Diffusers 库提供上游代码、模型和数据集时，我们力求对其可复现性保持透明。
- **责任感（Responsibility）**：作为一个社区，我们通过协作，对承担集体责任——预判并缓解这项技术的潜在风险和危害。

## 安全特性与机制

此外，我们提供一份非详尽的——但愿会不断扩充的——由 Hugging Face 团队及更广泛社区实现的安全特性与机制清单。

- **[社区标签页（Community tab）](https://huggingface.co/docs/hub/repositories-pull-requests-discussions)**：让社区能够围绕项目进行讨论并更好地协作。
- **标记功能（Tag feature）**：仓库作者可以将其内容标记为"Not For All Eyes"（非适宜所有人群观看）。
- **偏见的探索与评估**：Hugging Face 团队提供了一个 [Space](https://huggingface.co/spaces/society-ethics/DiffusionBiasExplorer)，可交互式地展示 Stable Diffusion 和 DALL-E 中的偏见。就此而言，我们支持并鼓励偏见探索与评估。
- **鼓励部署中的安全性**：**[Safe Stable Diffusion](https://huggingface.co/docs/diffusers/main/en/api/pipelines/stable_diffusion_safe)**：它缓解了一个众所周知的问题——像 Stable Diffusion 这样在未过滤的网络抓取数据集上训练的模型，容易出现不适宜的退化（inappropriate degeneration）。相关论文：[Safe Latent Diffusion: Mitigating Inappropriate Degeneration in Diffusion Models](https://arxiv.org/abs/2211.05105)。**在 Hub 上分阶段发布**：在特别敏感的情形下，某些仓库的访问应受到限制。这种分阶段发布是中间步骤，让仓库作者对其用途有更强的控制。
- **许可证（Licensing）**：[OpenRAILs](https://huggingface.co/blog/open_rail) 是一种新型许可证，让我们在确保自由访问的同时，通过一系列限制来保障更负责任的使用。
