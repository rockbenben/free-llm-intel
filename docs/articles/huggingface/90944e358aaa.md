## 🤗 欢迎收看机器学习专家 - Lewis Tunstall

朋友们好！欢迎收看机器学习专家（Machine Learning Experts）节目。我是主持人 Britney Muller，今天的嘉宾是 [Lewis Tunstall](https://twitter.com/_lewtun)。Lewis 是 Hugging Face 的机器学习工程师，致力于用 Transformers 自动化业务流程、解决 MLOps 挑战。

Lewis 曾为初创企业和大型企业在 NLP、拓扑数据分析和时间序列领域构建机器学习应用。

你会听到 Lewis 谈论他的[新书](https://transformersbook.com/)、transformers、大规模模型评估、他如何帮助 ML 工程师优化以换取更低延迟和更高吞吐等内容。

在此之前，Lewis 曾是一名理论物理学家；工作之余，他喜欢弹吉他、越野跑，并参与开源项目贡献。

### 我想请你做个简短的自我介绍，并聊聊是什么把你带入了 Hugging Face？

**Lewis：** 把我带进 Hugging Face 的是 transformers。2018 年，我在瑞士一家初创公司做 transformers 相关工作。我的第一个项目是问答任务：输入一段文本，训练一个模型去找出文本中问题的答案。

那时候这个库还叫 pytorch-pretrained-bert，是一个非常精简的代码库，只有几个脚本，那是我第一次接触 transformers。我当时完全摸不着头脑，就去读了原始的 [‘Attention Is All You Need’](https://arxiv.org/abs/1706.03762) 论文，结果没看懂。于是我开始四处寻找其他可以学习的资料。

在这个过程中，Hugging Face 的库迎来了爆发式增长，扩展到了许多架构，我也对参与开源软件贡献变得非常兴奋。于是在 2019 年前后，我冒出了一个有点疯狂的想法——写一本关于 transformers 的书，因为我觉得存在一个缺失的信息鸿沟。我拉上了朋友 [Leandro](https://twitter.com/lvwerra)（von Werra），凭空给 [Thom](https://twitter.com/Thom_Wolf)（Wolf）发了一封冷邮件："嘿，我们打算写一本关于 transformers 的书，你有兴趣吗？"我们本来以为不会有任何回复。但出乎意料的是，他回了："好啊，我们聊聊。"大约一年半后，这本书诞生了：[NLP with Transformers](https://transformersbook.com/)。

这次合作种下了种子，让 Leandro 和我最终加入了 Hugging Face。我来这儿已经九个月左右了。

这是非常令人兴奋的感受，真正拿在手里（相比读 PDF）完全不同。它确认了这是真实存在的，不是我做的梦。

### 能谈谈你在 transformers 库上做的工作吗？

**Lewis：** 我在加入 Hugging Face 之前的工作中体验到的一个事情是：把这些模型部署到生产环境时，行业内普遍面临一个挑战——这些模型在参数规模上非常庞大，这会给你的需求附加很多复杂度。

比如说，如果你在做一个聊天机器人，你需要模型非常快速、响应灵敏。而大多数时候，如果你只是拿一个现成模型、训练完、然后试图集成到应用里，这些模型都有点太慢了。

过去几个月我在 transformers 库上做的工作，就是提供把这些模型导出为某种格式的功能，让你可以用 Hugging Face 内部以及整个开源生态中的工具更高效地运行它们。

从某种意义上说，transformers 库的哲学就是：我们写很多代码，让用户不用写这些代码。

在这个具体例子里，我们说的是 ONNX 格式。这是工业界使用的一种特殊格式，一个用 PyTorch 写的模型基本可以转换成 TensorFlow，或者跑在某些专用硬件上。

如果你真的去看 transformers 库里实现这个转换需要什么，会发现相当棘手。但我们让它变得只需运行一行代码，剩下的交给库来处理。

所以这个功能的意义在于：机器学习工程师甚至数据科学家可以拿自己的模型，转换成这个格式，然后做优化，获得更低的延迟和更高的吞吐。

### 太棒了。有没有什么令人印象深刻的 transformers 应用？

**Lewis：** 我觉得有几个。其中一个可能比较情绪化或个人化。例如 OpenAI 发布 GPT-2 时——那个非常著名的可以生成文本的语言模型——我们很多人都经历过。

OpenAI 其实在博客文章里给出了这个模型写的一些文章示例。其中一篇特别好笑，是一篇关于"我们为什么不该回收垃圾"或"回收垃圾为什么是坏事"的文章。

模型写了一篇令人信服的论述，说回收垃圾为什么不好。当时 Leandro 和我在一家初创公司工作，我把文章打印出来，当作玩笑贴在了办公室回收站的正上方。大家看了都说"哇，这是谁写的？"我说："一个算法。"

我觉得这里面有一种奇异的"人性"——当我们看到生成的文本时，如果它看起来像是我（或另一个人）写的，我们会更加惊讶；而文本分类之类更常规的任务就不会让人有这种反应。

**Lewis：** 对！

### 你和 Hugging Face 的其他专家一直在为 Hugging Face 课程努力。它是怎么来的？接下来往什么方向走？

**Lewis：** 我加入 Hugging Face 时，transformers 库的两位核心维护者 [Sylvian](https://twitter.com/GuggerSylvain) 和 [Lysandre](https://twitter.com/LysandreJik) 正在开发一门课程，本质上是为了在软件工程师和对自然语言处理（尤其是正在发生的 transformers 革命）好奇的人之间搭桥。于是我和他们以及开源团队的其他人一起制作了一门免费课程——[Hugging Face 课程](https://huggingface.co/course/chapter1/1)。这门课的目标就是真正帮助人们从对 ML 了解不多，一路成长为能够在多种任务上训练模型。

我们已经发布了课程的两个部分，计划今年发布第三部分。我对正在开发的下一部分非常期待——我们会探索 transformers 真正强大的不同模态。我们通常把 transformers 和 NLP 联系在一起，但近两年明显出现了爆炸式扩展，transformers 被用在音频、计算机视觉等领域，我们会详细讲解这些内容。

### 你希望在哪些领域看到更多 ML 应用？

**Lewis：** 就我个人而言，我最兴奋的领域是机器学习在自然科学中的应用。一部分原因是我的背景——我上辈子是个物理学家。但我认为同样令人兴奋的是，在很多领域，比如物理或化学，你已经知道底层规律是什么（可以写出的方程），但结果发现你感兴趣研究的许多问题往往需要模拟，或者需要非常强悍的超级计算机来理解和求解这些方程。对我来说最令人兴奋的事情之一，就是把深度学习和科学家积累的先验知识结合起来，做出以前无法实现的突破。

我觉得一个很好的例子是 [DeepMind 的 AlphaFold](https://www.deepmind.com/research/highlighted-research/alphafold) 蛋白质结构预测模型。他们基本上是把 transformers 与一些额外信息结合，生成蛋白质的结构预测——我认为以前这类预测要以月计，而现在几天就能完成。

这以非常强大的方式加速了整个领域。我可以想象，这些应用最终会给人类带来一个更美好的未来。

### 你如何看待模型评估这个领域的发展？

**Lewis：** 好问题。在 Hugging Face，我一直在做的一件事，是构建能支撑所谓"大规模评估"的基础设施和工具。你可能知道 [Hugging Face Hub](https://huggingface.co/models) 上有成千上万的模型和数据集。但如果你想在这片领域里摸索，你可能会问自己："我对问答感兴趣，想知道这个任务上前 10 名的模型是什么。"

而目前，找到这个答案很难——不仅在 Hub 上难，在整个机器学习领域都很难。你常常要读论文，然后自己手动测试这些模型，非常低效。

所以我们一直在做的一件事，是探索直接通过 Hub 评估模型和数据集的方法。我们还在这个方向上做实验，但我希望今年晚些时候能拿出一些厉害的东西。

这还有另一面：衡量机器学习进步的一个很大部分依赖基准测试。这些基准传统上是一组数据集加一些任务，但可能缺失的是：很多研究人员来跟我们说"嘿，我有一个很棒的基准想法，但我不想实现提交、维护等等那些琐碎的基础设施。"

所以我们一直在和一些很厉害的合作方一起把基准直接托管在 Hub 上。这样研究社区就能使用我们的工具，简化这些模型的评估。

### 这真的非常有趣、也非常强大。

**Lewis：** 也许有一点值得提：评估这个问题其实非常微妙。从之前的基准——比如著名的衡量模型问答能力的 SQuAD——我们知道，很多 transformers 模型很擅长走捷径。

走捷径本是目标，但结果发现这些模型确实特别会走捷径。所以它们实际做的是在基准上拿高分，而高分未必转化为你真正关心的那件事——回答问题。

于是你会看到各种微妙的失败模式：模型可能给出完全错误的答案，或者根本就不该作答。当前研究社区正围绕"基准在我们衡量进步的方式中扮演什么角色"进行非常活跃而热烈的讨论。

同时还有：这些基准如何体现我们这个社区的价值观？我认为 Hugging Face 真正能为社区提供的，是让价值观谱系多样化的手段——传统上大多数研究论文来自美国，美国是个很棒的国度，但它只是人类体验的一小片，对吧？

### 机器学习工程师或团队常犯的错误有哪些？

**Lewis：** 我可以说说我犯过的那些。

它们大概能代表其他大多数人犯的错。我觉得入门阶段学到的最大一课，是从基线模型起步。我早期常犯这个错，后来也看到其他初级工程师这样做：一上来就挑最花哨的最先进模型。

虽然那样也许能用，但很多情况下，你给问题引入了大量复杂度，而你那个最先进模型可能藏着一个 bug，你又不知道怎么修，因为它太复杂了。在工业界，尤其在 NLP 里，一个非常常见的经验是：靠正则表达式和逻辑回归这类线性模型其实能走很远，它们能给你一个不错的起点。之后如果你能构建更好的模型，那当然好，去做就是了，但有一个参照点总是好的。

我觉得从做大量项目中学到的第二课是：你会不自觉地对问题中"建模"那部分产生执念，因为那是机器学习里最令人兴奋的部分——但整个外围还有一个生态系统。尤其在大公司里，你的应用周围会有一整套服务生态。

所以教训是：你真的应该尝试先端到端地搭出一个东西，哪怕里面一点机器学习都没有。因为那是你构建整个系统其余部分的脚手架——不然你可能花所有时间训练了一个很棒的模型，然后一声惊呼：糟糕。

它和应用的要求无法集成。于是你白白浪费了所有时间。

### 这条太赞了！不要过度设计。这也是我一直提醒自己的一件事。

**Lewis：** 没错。我觉得这是人之常情，尤其如果你是极客，你真的想找最有意思的做事方式，但大多数时候，简单即好。

### 如果能回到机器学习职业生涯的起点改变一件事，你会改什么？

**Lewis：** 哦，哇。这题太难了。嗯……这个问题之所以难答，是因为现在我做的 Hugging Face 的工作，是我这辈子最有成就感的事业。而如果我在起步时改变了什么，也许就轮不到我在这儿了，对吧？

这是非常宝贵的技能。但我后来发现，我真正的热情所在是开源软件开发。所以如果重来，我大概会更早开始做开源。因为说到底，开源主要由社区成员驱动。

不过，我对《终结者》那种事没那么担心。我更担心的是，比如一个失控的智能体在股票市场上把整个世界搞破产。

### 不，这很好。下一个问题接着你那台叠衣服机器人聊：AI 辅助机器人什么时候能进入千家万户？

### 你最喜欢的机器学习论文有哪些？

**Lewis：** 取决于怎么衡量，但有一篇论文特别突出，虽然它相当老了（[https://www.stat.berkeley.edu/~breiman/randomforest2001.pdf](https://www.stat.berkeley.edu/~breiman/randomforest2001.pdf)）。它是随机森林的发明者 Leo Breiman 写的。随机森林是经典的著名机器学习方法，对工业界常见的表格数据特别有用。一年前我在大学教随机森林。

我想，好吧，我读读这篇 2000 年代初的论文，看看还能不能看懂。它是清晰的典范。文章很短，却非常清晰地讲明白算法是怎么实现的。基本上拿这篇论文就能非常非常容易地把代码实现出来。对我来说，这是"中世纪"论文如何写作的绝佳范例。

而如今的大多数论文都是套路化写法：这里有段引言，这里有一张数字越来越好的表，再配一段随意的相关工作小节。所以这一篇特别让我印象深刻。

另一篇稍微新一些，又是 [DeepMind 的一篇论文](https://www.nature.com/articles/d41586-021-03593-1)，讲的是用机器学习技术证明代数拓扑等领域的基本定理——代数拓扑是抽象数学的一个特殊分支。我人生中一度做的就是这些相关课题。

所以对我来说，这是一种令人兴奋的前景：增强数学家拥有的知识，帮他们缩小需要搜索的定理空间。这一点对我来说是意外，因为我长期以来相当怀疑机器学习能带来超越"显而易见"层面（比如做预测）的根本性科学洞见。

但这个例子表明，机器学习真的可以颇具创造性，帮助数学家发现新思想。

### 人生的意义是什么？

**Lewis：** 我觉得诚实的答案是：我不知道。而任何直接告诉你答案的人大概都在撒谎。这话有点讽刺。我不知道……我猜作为理论科学家出身——尤其是物理学家——你会形成一种世界观：事情其实并没有某种更深层的意义。

宇宙在很大程度上是随机的，我想除了陷入非常悲伤，你能从中得到的只有自己赋予意义，对吧？大多数时候，这意义来自你的工作，来自家人，来自朋友。

但我觉得，当你找到赋予意义的方式，发现自己在做的事确实有趣且有分量，那就是最美好的部分。人生有起有落，对吧？至少就我个人而言，一直很有意义的事通常是创造。我以前是音乐人，那是一种为他人创造音乐的方式，做起来非常快乐。而现在，我想我是在创造代码，那也是一种创作。

### 它真的很好看！

**Lewis：** [举起封面画着鹦鹉的书] 你知道鹦鹉背后的故事吗？

### 我猜不知道。

**Lewis：** 当 O'Reilly 告诉你"我们要让插画师来设计封面"时，这一切是个秘密，对吧？

他们不告诉你背后的逻辑，你也没有发言权。基本上就是插画师自己想点子。书的后几章有一个部分，我们 basically 在 Python 代码上训练了一个类似 GPT-2 的模型——那是 Thom 的主意——他决定把它叫做"代码鹦鹉"（code parrot）。

我想他的点子或玩笑是：社区里有很多关于 Meg Mitchell 等人参与的论文《Stochastic Parrots》（随机鹦鹉）的讨论。那个观点是：你拥有的这些强大的语言模型，在写作中似乎表现出人类特质——正如我们之前讨论的——但骨子里也许它们只是在学鹦鹉舌。

你看，你跟一只凤头鹦鹉说话，它可能会骂你或讲笑话。但那也许并不是智能的真正衡量标准，对吧？所以我觉得插画师不知怎么看到了这一点，决定放上一只鹦鹉——我认为这是这本书的完美隐喻。

再加上书里讲的是 transformers。

### 我完全不知道 O'Reilly 的封面是这样来的。他们不告诉你，只是从书里提取语境然后创作？

**Lewis：** 看起来是这样。我是说，我们也不真了解流程。我只能猜插画师大概是在找灵感，然后看到书里有几个动物。有一章我们讨论了长颈鹿和斑马之类。总之，我对鹦鹉封面很满意。

### 我也喜欢。它看起来真的太棒了。这类书往往枯燥而技术化，而这本书读起来几乎像一部小说，又夹杂着大量实用的技术信息，这很美。

**Lewis：** 谢谢。是的，那是我们事后才意识到的——第一次写书，我们觉得应该正经一点，对吧？但如果你了解我，就知道我对任何事都正经不起来。现在回头看，我们真该在书里更放飞一点。
