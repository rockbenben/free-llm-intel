### TLDR 👉 一个新的 [TTS 排行榜](https://huggingface.co/spaces/hf-audio/open_tts_leaderboard)，聚焦 open-source 与 multilingual

开源 text-to-speech（TTS）模型的发布速度一直在惊人地推进。在 Hugging Face Hub 上（截至 Sep 30, 2026）已经有多于 [8K TTS 模型](https://huggingface.co/models?pipeline_tag=text-to-speech)可以取用 🚀

**但评测并没有跟上：它仍然是碎片化、没有标准化的。** 金标准是人类偏好分数，例如 MOS 或 MUSHRA（关于[指标](https://picovoice.ai/blog/measuring-tts-quality/)的更多内容）。为此，几个 arena 式的排行榜已经成为对社区有用的参照点：

- [TTS Arena v2](https://huggingface.co/spaces/TTS-AGI/TTS-Arena-V2)
- [Artificial Analysis](https://artificialanalysis.ai/text-to-speech/leaderboard/provider-voice)
- [Voice Arena](https://voicearena.com/tts-leaderboard)

这些 arena 比较模型的方式，是向用户呈现两个模型的 TTS 输出，请用户二选一。收集到足够多的投票之后，会算出一个 [Elo 分数](https://en.wikipedia.org/wiki/Elo_rating_system)来给模型排名，通常用 Bradley–Terry 模型（参见 [Voice Arena methodology](https://voicearena.com/tts-methodology)）。

人类偏好当然是最终的裁断者，但 **arena 无法扩展以跟上 TTS 发布的节奏**。这或许部分解释了为什么 open-source 模型在 arena 式排行榜上代表性不足：截至 Sep 30, 2026，[Artificial Analysis](https://artificialanalysis.ai/text-to-speech/leaderboard/provider-voice) 上的 92 个模型里只有 16 个是 open-weights，[Voice Arena](https://voicearena.com/tts-leaderboard) 上也有类似的偏向。这大概反映的是现实因素：接入一个 API 模型几乎只需要一个 API key，而一个 open 模型必须由 arena 运营方自己托管并提供服务，并且商业提供方比 open-source 作者更有理由去争取一个上榜位置。arena 式评测的另一个局限是投票者的一致性：没有任何 arena 能够保证同一批投票者带着同一套"更好"的标准，在时间推移中始终一致地评估模型。甚至同一个人的偏好也会随时间变化（正如 Heraclitus 那句名言所说："人不能两次踏进同一条河流"）。

为此，我们做出了 [Open TTS Leaderboard](https://huggingface.co/spaces/hf-audio/open_tts_leaderboard)，它用客观指标来评估模型在若干互补的性能维度上的表现：

- **Intelligibility（可理解度）**：prompt 与生成音频转写之间的词错误率/字符错误率（WER 与 CER），使用 [Qwen3 ASR](https://huggingface.co/Qwen/Qwen3-ASR-1.7B-hf)（[Open ASR Leaderboard](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard) 上排名最高的 open-source 模型）。
- **Speed**：在 H200 GPU 上做批量离线推理时的 inverse real-time factor（RTFx），以及用来量化 H200 GPU 和 CPU 上 streaming batch size 1 延迟的 time-to-first-audio（TTFA）。
- **Speaker similarity**：计算生成音频与参考片段各自的 [WavLM speaker embeddings](https://huggingface.co/bezzam/wavlm_large_finetune_seed_tts_eval) 之间的余弦相似度（SIM）。

依靠客观指标，**评估一个模型从几周（收集投票所需）降到了几个小时** ⚡

重要的是，Open TTS Leaderboard 并不取代人类偏好排名。基于 ASR 的 WER 提供的是 intelligibility 的一个代理指标，而 speaker similarity 估计的是音色身份的保留程度。两者都不直接度量 naturalness、表现力或听众偏好。尽管如此，它们甚至能够为投票式排行榜提供依据，告诉它们该把哪些模型纳入评测。

我们做这个排行榜的意图，是让它由**社区来塑造**；我们希望听到你的反馈，让评测保持有用且有洞察。接下来几个小节概览 Open TTS Leaderboard 的主要功能。

## 多语言 + voice cloning 评测

在排行榜的默认视图里，模型按 macro-average WER 排名，这个指标来自 [Seed TTS Eval](https://github.com/BytedanceSpeech/seed-tts-eval)（[paper](https://huggingface.co/papers/2406.02430)）和 [CV3 Eval](https://github.com/QwenAudio/CV3-Eval)（zero shot）（[paper](https://huggingface.co/papers/2505.17589)）的英文 split。

[hexgrad/Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M)、[Supertone/supertonic-3](https://huggingface.co/Supertone/supertonic-3) 和 [fishaudio/s2-pro](https://huggingface.co/fishaudio/s2-pro) 在这两个 split 上取平均后的英文 WER 领先，而 Pareto 图把在 WER、批量推理（RTFx）与体积之间取得良好平衡的模型可视化出来。

英文上的表现未必能迁移到其他语言。可以切换多种语言，按多语言表现给模型排名。Seed TTS Eval 只有英文和中文的音频，所以其他语言就直接是 CV3 Eval（zero shot）上的分数。注意中文、日文和韩文是字符型语言，因此报告的是字符错误率（CER），而跨语言的"Average WER"是跨各语言的 macro-average。

[k2-fsa/OmniVoice](https://huggingface.co/k2-fsa/OmniVoice)、[fishaudio/s2-pro](https://huggingface.co/fishaudio/s2-pro) 和 [FunAudioLLM/Fun-CosyVoice3-0.5B-2512](https://huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512) 都是很强的多语言模型。

打开"Voice cloning"开关后，就可以比较那些（在所选定语言上）支持这一功能的模型。

此外，表格里会多出一列 SIM 表示 speaker similarity，还会多出两张 Pareto 图，用来可视化 SIM、批量推理与体积之间的取舍。

一些模型的平均 WER 在 voice cloning 条件下——也就是提供了参考音频时——会变好，例如 [bosonai/higgs-tts-3-4b](https://huggingface.co/bosonai/higgs-tts-3-4b) 和 [openbmb/VoxCPM2](https://huggingface.co/openbmb/VoxCPM2)。

## 比较 TTS 输出并投票

数字只讲了故事的一部分，而如前所述，**人类偏好才是最终的裁断者**。在"Listen"标签页里，你可以比较那些指标背后的生成输出，看看自己更偏好哪些模型！

挑你感兴趣的**语言/数据集**，选择是否要比较 **voice cloning**，并可以（也可不）指定模型，或直接听一组随机挑选的输出。

**"Listen"标签页填补了现有 TTS 排行榜上一块重要的空白：一个可以试听各种模型输出的地方。**

你甚至可以对这些生成输出给出反馈。随着我们从社区收集到更多投票，我们可能会把这份数据纳入排行榜。**所以来投票吧！但请用你的 HF 账号登录，好帮我们滤掉 spam/bot。**

## Streaming 性能

"Streaming"标签页比较各模型的 streaming 能力。模型按 TTFA（time-to-first-audio）排名，它量化的是：用户请求一个模型之后，要多久才能拿到可以播放的音频。这对 voice agent 和其他交互式应用很重要。

对支持 streaming 的模型（在"Streaming API"下打了 ✅ 的那些），它是直到第一个音频 chunk 到达的时间。对不支持 streaming 的模型，它是直到整句话生成完的时间，因为播放不可能更早开始。每个模型一次只跑一条音频（batch size 1），都用来自 CV3-Eval 的同一组 50 条英文 prompt，在同一台硬件上、用它默认的音色。我们把前 3 次运行作为预热丢掉，报告其余运行的 TTFA 中位数。

默认视图比较的是在 H200 GPU 上的性能。对于一小部分（但正在增长的）模型，也提供 CPU 的结果！

[kyutai/pocket-tts](https://huggingface.co/kyutai/pocket-tts) 是一款在 GPU 和 CPU 上都非常适合 streaming 的好模型！

## 结论

Open TTS Leaderboard 的目标不仅是跟上 TTS 模型发布那惊人的节奏，更是要由社区来塑造；我们希望听到你的反馈，让评测保持有用且有洞察。请告诉我们你想看到哪些数据集、模型和指标！

目前我们聚焦于：

- **open-source 模型**，把许多被 arena 式评测忽略的优秀模型推到台前。
- **多语言**，因为英文表现并不是其他语言的合适代理指标。

我们很快就会把评测脚本 open-source，就像 Open ASR Leaderboard 的 [repo](https://github.com/huggingface/open_asr_leaderboard) 那样，这样你就能直接通过 GitHub Issues 和 PR 提供反馈与建议！一起来塑造 TTS 评测吧 🤗

> 英文上的表现未必能迁移到其他语言。可以切换多种语言，按多语言表现给模型排名。Seed TTS Eval 只有英文和中文的 movie box 音频，所以其他语言就直接是 CV3 Eval（zero shot）上的分数。注意中文、日文和韩文是字符型语言，因此报告的是字符错误率（CER），而跨语言的"Average WER"是跨各语言的 macro-average。

Open TTS Leaderboard 是一个开放的评测平台，旨在让多语言 text-to-speech 与 voice-cloning 模型更容易在规模化的条件下相互比较。传统的 TTS arena 通常让用户听两个模型的输出并选出自己更偏好的那一个。这些投票随后可以用来计算一个 Elo 式的分数，通常借助 Bradley–Terry 模型一类的方法，从而给用户一个简单的途径，基于人类偏好来理解不同系统的表现。

人类反馈仍然是评估语音质量的重要一环，但在新 TTS 模型以极快节奏发布的当下，只依赖 arena 式投票会很困难。open-source 模型也可能遇到实际障碍，因为它们一般需要由评测平台自己托管和提供服务，而基于 API 的商业模型接入起来更容易。这会导致 open-weight 系统在公开排行榜上不那么显眼。另一个挑战是一致性：人们的偏好和评判标准会随时间变化，这意味着相隔数月收集的投票未必代表同一套标准。

Open TTS Leaderboard 希望通过提供一个可扩展且透明的空间，来评估多语言 TTS 与 voice-cloning 系统，从而应对这些挑战。目标是让比较更容易复现、扩大对 open 模型的覆盖，并在人类偏好之外提供有用的评测信号。把可扩展的测试与社区反馈结合起来，这个项目能帮助研究者、开发者和用户更好地理解语音模型在不同语言、不同音色与不同用例下的表现。
