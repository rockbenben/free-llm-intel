# 使用 Arize Phoenix 追踪并评估你的智能体

好了，你的智能体搭起来了。它接收输入和工具，处理后生成响应。也许它在做决策、检索信息、自主执行任务，或者三样都有。但现在大问题来了——它干得怎么样？更重要的是，你怎么知道？

构建智能体是一回事，理解它的行为是另一回事。这就是追踪（tracing）和评估（evaluation）登场的原因。追踪能让你逐步步看清智能体在做什么——它收到什么输入、如何处理信息、如何得出最终输出，相当于给你的智能体的决策过程拍 X 光片。评估则帮你衡量性能，确保你的智能体不只是"能跑"，而是真的有效。它给出的答案对吗？每一步找到的内容有多相关？智能体的回答组织得好吗？符合你的目标吗？

[Arize Phoenix](https://phoenix.arize.com/) 提供一个集中平台，在同一处实时追踪、评估和调试智能体的决策。我们将深入讲解如何落地它们来打磨和优化你的智能体。因为构建只是开始——真正的智能来自清楚知道底层发生了什么。

在此之前，先把智能体搭起来！你可以跟着下面的步骤走，也可以用你自己的智能体。

## 搭一个智能体

### 第 1 步：安装所需库

```
pip install -q smolagents
```

### 第 2 步：导入全部基本构件

现在把我们用到的类和工具引进来：

```
from smolagents import (
   CodeAgent,
   DuckDuckGoSearchTool,
   VisitWebpageTool,
   HfApiModel,
)
```

### 第 3 步：配置基座模型

我们创建一个由 Hugging Face Hub Serverless API 驱动的模型实例：

```
hf_model = HfApiModel()
```

### 第 4 步：创建工具调用智能体

```
agent = CodeAgent(
    tools=[DuckDuckGoSearchTool(), VisitWebpageTool()],
    model=hf_model,
    add_base_tools=True
)
```

### 第 5 步：运行智能体

见证奇迹的时刻——看看我们的智能体开工。我们问它的问题是：
*"取一下 Google 从 2020 到 2024 年的股价，并据此画一条折线图？"*

```
agent.run("fetch the share price of google from 2020 to 2024, and create a line graph from it?")
```

你的智能体接下来会：

- 用 DuckDuckGoSearchTool 搜索 Google 的历史股价。
- 可能用 VisitWebpageTool 访问页面寻找这些数据。
- 尝试汇总信息，并生成或描述如何绘制折线图。

## 追踪你的智能体

智能体跑起来后，下一个挑战是看懂它的内部工作流。追踪帮你记录智能体走的每一步——从调用工具、处理输入到生成响应——让你能调试问题、优化性能，确认它按预期行事。

要启用追踪，我们用 Arize Phoenix 做可视化，用 OpenTelemetry + OpenInference 做插桩。

安装 smolagents 的遥测模块：

```
pip install -q 'smolagents[telemetry]'
```

Phoenix 有多种运行方式。这条命令会在你机器上跑一个本地 Phoenix 实例：

```
python -m phoenix.server.main serve
```

关于 Phoenix 的其他托管选项，你可以[创建一个免费的在线 Phoenix 实例](https://app.phoenix.arize.com/login/sign-up)、[在本地自托管应用](https://docs.arize.com/phoenix/deployment)，或[把应用托管在 Hugging Face Spaces 上](https://huggingface.co/learn/cookbook/en/phoenix_observability_on_hf_spaces)。

启动后，我们注册一个 tracer provider，指向我们的 Phoenix 实例。

```
from phoenix.otel import register
from openinference.instrumentation.smolagents import SmolagentsInstrumentor

tracer_provider = register(project_name="my-smolagents-app") # creates a tracer provider to capture OTEL traces
SmolagentsInstrumentor().instrument(tracer_provider=tracer_provider) # automatically captures any smolagents calls as traces
```

现在任何对 smolagents 的调用都会送到我们的 Phoenix 实例。

追踪已启用，用一个简单查询测一下：

```
agent.run("What time is it in Tokyo right now?")
```

一旦 OpenInference 和 SmolAgents 设置完成，每次智能体调用都会自动在 Phoenix 中被追踪。

## 评估你的智能体

智能体上线、运行被监控之后，下一步是评估其表现。评估（evals）帮你判断智能体检索、处理和呈现信息的水平。

可做的评估有很多种，例如响应相关性、事实准确性、延迟等。更深入的评估技术请看 [Phoenix 文档](https://docs.arize.com/phoenix/evaluation/llm-evals)。

这个例子里，我们重点评估智能体用到的 DuckDuckGo 搜索工具。我们用大语言模型（LLM）当裁判来衡量搜索结果的相关性——具体来说是 OpenAI 的 GPT-4o。

### 第 1 步：安装 OpenAI

首先安装必要的包：

```
pip install -q openai
```

我们将用 GPT-4o 来评估搜索工具的响应是否相关。
这种方法叫 LLM-as-a-judge（以 LLM 为裁判），利用语言模型给响应分类和打分。

### 第 2 步：取回工具执行 span

要评估 DuckDuckGo 的信息检索质量，先要提取调用该工具的执行轨迹。

```
from phoenix.trace.dsl import SpanQuery
import phoenix as px
import json

query = SpanQuery().where(
    "name == 'DuckDuckGoSearchTool'",
).select(
    input="input.value", # this parameter must be named input to work with the RAG_RELEVANCY_PROMPT_TEMPLATE
    reference="output.value", # this parameter must be named reference to work with the RAG_RELEVANCY_PROMPT_TEMPLATE
)

# The Phoenix Client can take this query and return the dataframe.
tool_spans = px.Client().query_spans(query, project_name="my-smolagents-app")

tool_spans["input"] = tool_spans["input"].apply(lambda x: json.loads(x).get("kwargs", {}).get("query", ""))
tool_spans.head()
```

### 第 3 步：导入提示词模板

接下来加载 RAG Relevancy Prompt Template，它会帮助 LLM 判断搜索结果是否相关。

```
from phoenix.evals import (
    RAG_RELEVANCY_PROMPT_RAILS_MAP,
    RAG_RELEVANCY_PROMPT_TEMPLATE,
    OpenAIModel,
    llm_classify
)
import nest_asyncio
nest_asyncio.apply()

print(RAG_RELEVANCY_PROMPT_TEMPLATE)
```

### 第 4 步：运行评估

现在用 **GPT-4o** 当裁判跑评估：

```
from phoenix.evals import (
    llm_classify,
    OpenAIModel,
    RAG_RELEVANCY_PROMPT_TEMPLATE,
)

eval_model = OpenAIModel(model="gpt-4o")

eval_results = llm_classify(
    dataframe=tool_spans,
    model=eval_model,
    template=RAG_RELEVANCY_PROMPT_TEMPLATE,
    rails=["relevant", "unrelated"],
    concurrency=10,
    provide_explanation=True,
)
eval_results["score"] = eval_results["explanation"].apply(lambda x: 1 if "relevant" in x else 0)
```

这里发生了什么？

- 我们用 GPT-4o 分析搜索查询（input）和搜索结果（output）。
- LLM 根据提示词把结果分类为相关或不相关。
- 我们给出二元分数（1 = 相关，0 = 不相关）供后续分析。

查看结果：

```
eval_results.head()
```

### 第 5 步：把评估结果送回 Phoenix

```
from phoenix.trace import SpanEvaluations

px.Client().log_evaluations(SpanEvaluations(eval_name="DuckDuckGoSearchTool Relevancy", dataframe=eval_results))
```

有了这套配置，我们就能系统评估智能体中 DuckDuckGo 搜索工具的有效性。借助 LLM-as-a-judge，我们可以确保智能体检索到的是准确且相关的信息，从而带来更好的表现。

照着本教程，任何评估都很容易搭起来——只要把 RAG_RELEVANCY_PROMPT_TEMPLATE 换成符合你需求的另一个提示词模板。Phoenix 提供了多种预先写好、预先测试过的评估模板，覆盖忠实度、响应连贯性、事实准确性等领域。查看 Phoenix 文档探索完整列表，为你的智能体找到最合适的那一个！
