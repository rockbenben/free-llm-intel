# 2024 年安全功能亮点

安全是 Hugging Face 的最高优先级，我们致力于持续增强防御能力，保护用户。在持续不断的安全工作中，我们开发了一系列安全功能，帮助用户保护自身及其资产。在这篇博客中，我们将回顾截至 2024 年 8 月 6 日的整体安全状况，并逐一介绍 Hugging Face Hub 上可用的关键安全功能。

本文将分为两部分：在前几节中，我们介绍所有 Hub 用户都可使用的基础安全功能；然后在第二部分中，我们描述面向 Enterprise Hub 用户的高级安全控制。

## Hub 的“默认”安全功能

以下安全功能对所有 Hugging Face Hub 用户开放。我们强烈建议尽可能启用所有这些控制措施，这将有助于提升你针对各类常见攻击的抵御能力，例如钓鱼、token 泄露、凭证填充（credential stuffing）、会话劫持等。

### 细粒度 Token（Fine Grained Token）

通过 API 访问 Hugging Face 需要用户访问令牌（User Access Token）。除了标准的 "read" 和 "write" token 之外，Hugging Face 还支持 "fine-grained"（细粒度）token，让你能够按资源维度逐项定义权限，从而贯彻最小权限原则，确保即使 token 泄露也不会波及其他资源。细粒度 token 提供了丰富的配置方式，可选项见下方图片。关于 token 的更多信息请见：[https://huggingface.co/docs/hub/en/security-tokens](https://huggingface.co/docs/hub/en/security-tokens)

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/fine-grained-tokens-1.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/fine-grained-tokens-1.png) [![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/fine-grained-tokens-2.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/fine-grained-tokens-2.png)

### 双因素认证（2FA）

双因素认证通过在授予访问权限前要求两种验证方式，为你的在线账户增加一层额外保护。2FA 将你知道的东西（如密码）与你拥有的东西（如智能手机）结合起来，确保只有经过授权的用户才能访问敏感信息。启用 2FA 后，你可以大幅降低因密码泄露、凭证填充和钓鱼导致的未授权访问风险。关于 2FA 的更多信息请见：[https://huggingface.co/docs/hub/en/security-2fa](https://huggingface.co/docs/hub/en/security-2fa)

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/2fa.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/2fa.png)

### 提交签名（Commit Signing）

虽然 Git 有一层认证机制来控制谁可以向仓库推送提交，但它并不验证提交作者的真实身份。这意味着恶意攻击者可以通过 `git config --global user.email you@company.com` 和 `git config --global user.name Your Name` 来冒充他人。这些配置本身并不会让他们获得推送你的仓库的额外权限——但确实使他们可以在任何能推送的地方冒充你，无论那是一个公共仓库，还是一个使用了泄露凭证或被盗 SSH key 的私有仓库。

提交签名利用 GPG 增加了一层额外的安全防护来缓解这一问题；更多信息参见 [Git Tools: Signing Your Work](https://git-scm.com/book/en/v2/Git-Tools-Signing-Your-Work)。Hugging Face 允许作者将自己的 GPG key 添加到个人资料中。当一个带签名的提交被推送时，系统会使用作者资料中的 GPG key 对签名进行验证。如果签名有效，该提交将被标记上 "Verified"（已验证）徽章。关于提交签名的更多信息请见：[https://huggingface.co/docs/hub/en/security-gpg](https://huggingface.co/docs/hub/en/security-gpg)

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/commit-signing.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/commit-signing.png)

### 组织访问控制

Hugging Face 上的组织可以使用组织访问控制（Organizational Access Controls）。这让团队和企业能够为其组织定义最小权限访问，为每位用户分配 "read"、"write"、"contributor" 或 "admin" 角色。这有助于确保单个用户账户被攻破（例如通过钓鱼）时不会波及整个组织。关于组织访问控制的更多信息请见：[https://huggingface.co/docs/hub/en/organizations-security](https://huggingface.co/docs/hub/en/organizations-security)

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/organizational-access-controls.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/organizational-access-controls.png)

### 自动化安全扫描

Hugging Face 实现了一条自动化安全扫描流水线，对所有仓库和提交进行扫描。目前该流水线包含三个主要组件：

- 恶意软件扫描（malware scanning）：使用 [ClamAV](https://clamav.net) 扫描已知恶意软件签名
- pickle 扫描（pickle scanning）：使用 [picklescan](https://github.com/mmaitre314/picklescan) 扫描 pickle 文件中的恶意可执行代码
- 机密信息扫描（secret scanning）：使用 [`trufflehog filesystem`](https://github.com/trufflesecurity/trufflehoghttps://github.com/trufflesecurity/trufflehog) 命令扫描密码、token 和 API key

一旦检测到恶意文件，扫描流程会在仓库上放置警告标识，让用户知悉自己可能正在与一个恶意仓库交互。你可以在这里查看一个（伪造的）恶意仓库示例：[https://huggingface.co/mcpotato/42-eicar-street/tree/main](https://huggingface.co/mcpotato/42-eicar-street/tree/main)。

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/security-scanning.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/security-scanning.png)

对于任何检测到的已验证（verified）机密信息，流水线会向所有者发送邮件通知，以便其作废并刷新该机密。

已验证的机密是指那些已被确认可用于向相应服务商进行身份认证的机密。但请注意，未验证的机密并不一定无害或无效：验证可能因技术原因失败，例如服务商宕机。

关于自动化扫描的更多信息请见：

- [https://huggingface.co/docs/hub/en/security-malware](https://huggingface.co/docs/hub/en/security-malware)
- [https://huggingface.co/docs/hub/en/security-pickle](https://huggingface.co/docs/hub/en/security-pickle)
- [https://huggingface.co/docs/hub/en/security-secrets](https://huggingface.co/docs/hub/en/security-secrets)

## Enterprise Hub 安全功能

除了面向所有用户的安全功能之外，Hugging Face 还为企业用户提供高级安全控制。这些额外的控制措施让企业能够构建最适合自己的安全配置。

### 单点登录（SSO）

单点登录（SSO）允许用户使用一套凭证访问多个应用。企业已广泛采用 SSO，因为它使员工能够使用由 IT 团队集中管理的身份访问各种企业软件。Hugging Face Enterprise 同时支持 SAML 2.0 和 OpenID Connect（OIDC）两种协议的 SSO，并兼容任何符合标准的身份提供商，如 Okta、OneLogin、Azure AD 等。此外，还可以配置 SSO 用户根据身份提供商提供的数据动态分配访问控制角色。关于 SSO 的更多信息请见：[https://huggingface.co/docs/hub/en/security-sso](https://huggingface.co/docs/hub/en/security-sso)

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/sso.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/sso.png)

### 资源组（Resource Groups）

在基础的组织访问控制之外，企业还可以将仓库分组定义和管理为资源组（Resource Groups）。这让你能够按团队或用途对资源进行隔离，例如 "Research"、"Engineering"、"Production"，从而确保某个分组被攻破时不会波及其他分组。关于资源组的更多信息请见：[https://huggingface.co/docs/hub/en/security-resource-groups](https://huggingface.co/docs/hub/en/security-resource-groups)

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/resource-groups.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/resource-groups.png)

### 组织 Token 管理

✨新功能✨ Enterprise 用户现在可以管理哪些 token 能够访问其组织和资源。组织所有者可以强制使用细粒度 token，并要求每个 token 都经过管理员批准。管理员可以随时审查并撤销任何有权访问其仓库的 token。

关于组织 token 管理的更多信息请见：[https://huggingface.co/docs/hub/enterprise-hub-tokens-management](https://huggingface.co/docs/hub/enterprise-hub-tokens-management)

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/organizational-token-management-1.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/organizational-token-management-1.png) [![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/organizational-token-management-2.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/organizational-token-management-2.png)

### 数据驻留（Data Residency）

Enterprise 用户可以使用数据驻留控制，自行定义仓库（模型、数据集、Spaces）的存储位置。这既满足监管和法律合规要求，又能通过让数据更靠近用户来提升下载和上传性能。我们目前支持美国和欧盟区域，亚太地区即将推出。我们称此功能为 "Storage Regions"（存储区域）。关于数据驻留的更多信息请见：[https://huggingface.co/docs/hub/en/storage-regions](https://huggingface.co/docs/hub/en/storage-regions)

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/data-residency.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/data-residency.png)

### 审计日志（Audit Logs）

Enterprise 用户可以访问审计日志，组织管理员可通过它审查对仓库、设置和账单的变更。审计日志包含用户名、位置、IP 及所执行的操作，可以下载为 JSON 文件并接入你自己的安全工具。关于审计日志的更多信息请见：[https://huggingface.co/docs/hub/en/audit-logs](https://huggingface.co/docs/hub/en/audit-logs)

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/audit-log.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/2024-security-features/audit-log.png)

### 合规性（Compliance）

Hugging Face 已获得 SOC2 Type 2 认证并符合 GDPR。我们为 Enterprise Plan 用户提供 GDPR 数据处理协议的商业伙伴附加条款（Business Associate Addendums）。关于我们合规工作的更多信息请见：[https://huggingface.co/docs/hub/en/security](https://huggingface.co/docs/hub/en/security)

### 定制安全功能

Hugging Face 为企业账户提供定制协议与功能/工具的开发，通过工作说明书（Statement of Work，SoW）和服务级别协议（Service Level Agreements，SLA）确立。你可以直接联系销售团队讨论可选方案：[https://huggingface.co/contact/sales](https://huggingface.co/contact/sales)。
