## 引言

来自人类反馈的强化学习（RLHF）已成为 GPT-4、Claude 这类 LLM 事实上的最后训练步骤，以确保语言模型的输出符合人类期望，例如对话风格或安全特性。但它也把 RL 的复杂性带进了 NLP：我们需要构建一个好的奖励函数、训练模型去估计状态价值，同时小心不要离原始模型太远、输出胡言乱语而非合理文本。这个过程相当复杂，涉及众多环节，而且并不总是容易做对。

Rafailov、Sharma、Mitchell 等人的近期论文 [Direct Preference Optimization](https://arxiv.org/abs/2305.18290)（DPO，直接偏好优化）提出把现有方法使用的 RL 目标，改写为一个可以通过简单的二元交叉熵损失直接优化的目标，从而大幅简化 LLM 的打磨过程。

本篇博文介绍 DPO 方法——它现已在 [TRL 库](https://github.com/lvwerra/trl)中可用——并演示如何在包含 stack-exchange 各门户问题排序回答的 [stack-exchange preference](https://huggingface.co/datasets/lvwerra/stack-exchange-paired) 数据集上微调最新的 Llama v2 7B 参数模型。

## DPO 对阵 PPO

在用 RL 优化人类偏好的传统模式里，首选方法一直是用一个辅助奖励模型，通过 RL 机制微调目标模型以最大化给定奖励。直观上，我们用奖励模型向被优化的模型提供反馈，让它更频繁地生成高奖励样本、更少生成低奖励样本。同时我们用冻结的参考模型保证生成的内容不会偏离太远、继续保持生成多样性。这通常通过参考模型在完整的奖励最大化目标中加入 KL 惩罚来实现，其作用是防止模型学会欺骗或利用奖励模型。

DPO 公式绕开了奖励建模这一步，借助一个关键洞察在偏好数据上直接优化语言模型：即奖励函数到最优 RL 策略的解析映射。这个映射使作者们能把关于奖励与参考模型的 RL 损失，直接转化为关于参考模型的损失！直观上，该映射衡量的是给定奖励函数与给定偏好数据的契合程度。因此，DPO 从 RLHF 损失的最优解出发，通过变量替换，推导出一个*仅*关于参考模型的损失！

于是这个直接的似然目标即可优化，既不需要奖励模型，也不需要可能繁琐的 RL 优化。

## 如何用 TRL 训练

如前所述，典型的 RLHF 流水线由这些相互独立的部件组成：

- 监督微调（SFT）步骤
- 给数据标注偏好标签的过程
- 在偏好数据上训练奖励模型
- 以及 RL 优化步骤

TRL 库为这些部件都提供了帮手，但 DPO 训练去掉了奖励建模与 RL（第 3、4 步），直接在带偏好标注的数据上优化 DPO 目标。

就这点而言，我们仍需要做第 1 步，但取代第 3、4 步的是：需要给 TRL 的 `DPOTrainer` 提供第 2 步产出的偏好数据，其格式非常具体，即一个带以下三个键的字典：

- `prompt`：推理时提供给模型用于文本生成的上下文提示
- `chosen`：针对对应提示被偏好的生成回答
- `rejected`：相对于给定提示不被偏好、或不应被采样的回答

例如，对 stack-exchange 偏好对数据集，我们可以用下面这个辅助函数把数据集条目映射为所需字典，并丢弃所有原始列：

```
def return_prompt_and_responses(samples) -> Dict[str, str, str]:
    return {
        "prompt": [
            "Question: " + question + "\n\nAnswer: "
            for question in samples["question"]
        ],
        "chosen": samples["response_j"],   # rated better than k
        "rejected": samples["response_k"], # rated worse than j
    }

dataset = load_dataset(
    "lvwerra/stack-exchange-paired",
    split="train",
    data_dir="data/rl"
)
original_columns = dataset.column_names

dataset.map(
    return_prompt_and_responses,
    batched=True,
    remove_columns=original_columns
)
```

数据集就绪后，DPO 损失本质上是一个有监督损失——它借助参考模型获得隐式奖励。因此从高层看，`DPOTrainer` 需要我们要优化的基座模型以及一个参考模型：

```
dpo_trainer = DPOTrainer(
    model,                 # base model from SFT pipeline
    model_ref,             # typically a copy of the SFT trained base model
    beta=0.1,              # temperature hyperparameter of DPO
    train_dataset=dataset, # dataset prepared above
    tokenizer=tokenizer,   # tokenizer
    args=training_args,    # training arguments e.g. batch size, lr, etc.
)
```

其中 `beta` 超参数是 DPO 损失的温度参数，通常取 `0.1` 到 `0.5`。它控制我们在多大程度上关注参考模型——`beta` 越小，我们越忽略参考模型。初始化 trainer 后，只需调用下面一行，即可用给定的 `training_args` 在数据集上训练：

```
dpo_trainer.train()
```

## Llama v2 实验

把 DPO trainer 实现在 TRL 里的好处是，可以借助 TRL 及其依赖库（Peft、Accelerate）训练大型 LLM 的所有附加功能。有了这些库，我们甚至能用 [bitsandbytes](https://github.com/TimDettmers/bitsandbytes) 库提供的 [QLoRA 技术](https://huggingface.co/blog/4bit-transformers-bitsandbytes)训练 Llama v2 模型。

### 监督微调

如上所述，流程的第一步是用 [QLoRA](https://arxiv.org/abs/2305.14314) 在数据的 SFT 划分上对 7B Llama v2 做监督微调，通过 TRL 的 `SFTTrainer` 完成：

```
# load the base model in 4-bit quantization
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
)

base_model = AutoModelForCausalLM.from_pretrained(
    script_args.model_name,        # "meta-llama/Llama-2-7b-hf"
    quantization_config=bnb_config,
    device_map={"": 0},
    trust_remote_code=True,
    use_auth_token=True,
)
base_model.config.use_cache = False

# add LoRA layers on top of the quantized base model
peft_config = LoraConfig(
    r=script_args.lora_r,
    lora_alpha=script_args.lora_alpha,
    lora_dropout=script_args.lora_dropout,
    target_modules=["q_proj", "v_proj"],
    bias="none",
    task_type="CAUSAL_LM",
)
...
trainer = SFTTrainer(
    model=base_model,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
    peft_config=peft_config,
    packing=True,
    max_seq_length=None,
    tokenizer=tokenizer,
    args=training_args,         # HF Trainer arguments
)
trainer.train()
```

### DPO 训练

SFT 结束后，我们可以保存所得模型，进入 DPO 训练。按照惯例，前一步 SFT 保存的模型同时用作 DPO 的基座模型与参考模型。然后我们用它们在上述 stack-exchange 偏好数据上按 DPO 目标训练。由于模型是经 LoRA 适配器训练的，我们通过 Peft 的 `AutoPeftModelForCausalLM` 辅助类加载模型：

```
model = AutoPeftModelForCausalLM.from_pretrained(
    script_args.model_name_or_path, # location of saved SFT model
    low_cpu_mem_usage=True,
    torch_dtype=torch.float16,
    load_in_4bit=True,
    is_trainable=True,
)
model_ref = AutoPeftModelForCausalLM.from_pretrained(
    script_args.model_name_or_path,  # same model as the main one
    low_cpu_mem_usage=True,
    torch_dtype=torch.float16,
    load_in_4bit=True,
)
...
dpo_trainer = DPOTrainer(
    model,
    model_ref,
    args=training_args,
    beta=script_args.beta,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
    tokenizer=tokenizer,
    peft_config=peft_config,
)
dpo_trainer.train()
dpo_trainer.save_model()
```

可见我们以 4-bit 配置加载模型，再通过 `peft_config` 参数以 QLora 方法训练。trainer 还会在训练期间针对评估数据集评估进展，并回报一系列关键指标——例如隐式奖励（implicit reward）——可记录并展示在 WandB 等工具中。最终训练好的模型可以推送到 HuggingFace Hub。

## 结论

SFT 与 DPO 训练脚本的完整源码在 [examples/stack_llama_2](https://github.com/lvwerra/trl/tree/main/examples/research_projects/stack_llama_2) 目录，带合并适配器的训练后模型在 HF Hub 上：[这里](https://huggingface.co/kashif/stack-llama-2)。

DPO 训练运行的 WandB 日志在[这里](https://wandb.ai/krasul/huggingface/runs/c54lmder)，训练与评估期间 `DPOTrainer` 记录以下奖励指标：

- `rewards/chosen`：对 chosen 回答，策略模型与参考模型对数概率之差的平均值（乘以 `beta` 缩放）
- `rewards/rejected`：对 rejected 回答，策略模型与参考模型对数概率之差的平均值（乘以 `beta` 缩放）
- `rewards/accuracies`：chosen 奖励高于对应 rejected 奖励的频率均值
- `rewards/margins`：chosen 奖励与对应 rejected 奖励之差的均值

直观上，训练期间我们希望 margins 不断上升、accuracies 趋近 1.0——换句话说，希望 chosen 奖励高于 rejected 奖励（即 margin 大于 0）。这些指标可以在某个评估数据集上计算。

我们希望随着代码发布，能降低各位读者在自己数据集上尝试这种大语言模型对齐方法的门槛——我们迫不及待想看到你们构建的成果！如果你想亲自试试模型，可以在这里体验：[trl-lib/stack-llama](https://huggingface.co/spaces/trl-lib/stack-llama)。
