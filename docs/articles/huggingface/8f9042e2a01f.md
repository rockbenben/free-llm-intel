# 欢迎 Llama 4 Maverick & Scout 加入 Hugging Face

我们无比激动地欢迎 Meta 的下一代大语言模型来到 Hugging Face Hub：[Llama 4 Maverick（约 400B）](https://huggingface.co/meta-llama/Llama-4-Maverick-17B-128E-Instruct)和 [Llama 4 Scout（约 109B）！](https://huggingface.co/meta-llama/Llama-4-Scout-17B-16E-Instruct) 🤗 两者都是 17B 激活参数的混合专家（Mixture of Experts，MoE）模型。

这些强大的原生多模态模型今天发布，代表了一次显著的跃升。我们与 Meta 紧密合作，确保其无缝融入 Hugging Face 生态——从第一天起就支持 transformers 和 TGI。

这只是我们与 Llama 4 旅程的开始。未来几天，我们会继续与社区协作，用 Maverick 和 Scout 构建精彩的模型、数据集和应用！🔥

## Llama 4 是什么？

Llama 4 由 Meta 开发，引入了新的自回归混合专家（MoE）架构。这一代包含两个模型：

- 能力强劲的 **Llama 4 Maverick**：总参数约 400B、激活参数 17B，128 个专家。
- 高效的 **Llama 4 Scout**：同样激活 17B 参数、总量约 109B，只用 16 个专家。

两个模型都利用 early fusion 实现原生多模态，可处理文本和图像输入。Maverick 和 Scout 都用最高 40 万亿 token 训练，数据覆盖 200 种语言（并对 12 种语言做了专门的微调支持，包括阿拉伯语、西班牙语、德语和印地语）。

部署方面，Llama 4 Scout 为易得性而设计，借助即时的 4-bit 或 8-bit 量化可以装进单张服务器级 GPU；Maverick 提供 BF16 和 FP8 格式。这些模型以定制的 Llama 4 Community License Agreement 发布，许可证见模型仓库。

## Hugging Face 上的特性与集成

为帮助社区立即用上这些最先进模型，我们高兴地宣布以下集成：

- **Hub 上的模型权重：** Llama 4 Maverick 和 Scout 的权重都直接发布于 Hugging Face Hub 的 `meta-llama` 组织下，包含基座版和指令微调版，方便访问、探索和下载。需要先在模型卡上接受许可条款才能获得权重访问。
- **Hugging Face `transformers` 集成**：现在就开建！Llama 4 已完整集成进 `transformers`（`v4.51.0`）。用熟悉的 API 即可轻松加载、推理和微调，包括其原生多模态能力，以及 TRL 等下游库。
- **transformers 中的张量并行（tensor-parallel）自动支持与自动设备映射。**
- **Text Generation Inference（TGI）支持：** 为优化、可扩展的部署，两个模型都受 TGI 支持，可实现高吞吐文本生成，让 Llama 4 更容易进入生产应用。
- **量化支持：** Scout 提供即时的 int4 量化代码，在降低硬件占用部署面积的同时把性能损失降到最低；Maverick 附带 FP8 量化权重，可在兼容硬件上高效部署。
- **Xet 存储：** 为改善上传下载、让社区微调模型的迭代更快，所有 Llama 4 模型都使用 [Xet 存储后端](https://huggingface.co/blog/xet-on-the-hub)发布。这套存储系统为更快的上传与下载而设计，在 Llama 4 上实现约 25% 的去重。衍生模型（微调、量化等）的去重率更高（约 40%），为社区省下更多时间和带宽。

## 上下文长度与架构选择

Llama 4 系列以 256K 上下文长度做预训练。Instruct 模型则微调支持大得多的上下文长度：128 专家的 Maverick 支持 1M，16 专家的 Scout 支持 10M（！）。

| 模型 | Instruct | 上下文长度 |
| --- | --- | --- |
| Scout (16E) | ✅ | 10M |
| Maverick (128E) | ✅ | 1M |
| Scout (16E) |  | 256K |
| Maverick (128E) |  | 256K |

这些超长上下文伴随着几个很有意思的架构选择。在官方技术报告发布之前，这是我们目前已知的内容。

- **无 RoPE 层（NoPE）**

NoPE（名字可爱，魅力值 +1）早在 2022 年就被探索过：干脆不用 transformer 模型常用的传统位置编码方案（如 RoPE）。Llama 4 里每 4 层用一次 NoPE 层。这些层对长上下文至关重要，因为它们对整个上下文使用完整因果掩码。

其余的 RoPE 层（4 层里的 3 层）使用*分块注意力（chunked attention）*。

Meta 把 NoPE 层的*交错*使用（结合下文说的温度缩放）称为 `iRoPE` 架构。

*想更多了解位置编码，推荐 [Chris 的这篇文章](https://huggingface.co/blog/designing-positional-encoding)。*

- **分块注意力**（用于 RoPE 层）

为降低内存需求，Llama 4 在使用传统 RoPE 位置编码的层（4 个 decoder 层中的 3 个）用分块注意力。理解它的最好方式是这段从 [transformers 源码](https://github.com/huggingface/transformers/blob/main/src/transformers/models/llama4/modeling_llama4.py#L848-L857)抓出来的 ASCII 示意：

```
'What'      :  0 ■ ⬚ ⬚ ⬚ ⬚ ⬚ 
'▁is'       :  1 ■ ■ ⬚ ⬚ ⬚ ⬚ 
'▁ch'       :  2 ■ ■ ■ ⬚ ⬚ ⬚ 
'unked'     :  3 ⬚ ⬚ ⬚ ■ ⬚ ⬚ 
'▁attention':  4 ⬚ ⬚ ⬚ ■ ■ ⬚ 
'?'         :  5 ⬚ ⬚ ⬚ ■ ■ ■ 
```

这张图展示的是分块注意力长度为 3 时的注意力掩码。Llama 4 的分块注意力长度是 `8192`。也就是说 RoPE 层只能在 8K 的块内跟踪上下文，而 NoPE 层能访问完整上下文。你可以把它看成更省内存、省计算的滑动窗口注意力（Sliding Window Attention）版本。

- **注意力温度调优（Attention Temperature Tuning）**

长上下文上的注意力有个已知问题：随着序列变长，注意力概率分数会*衰减*趋向零——这是 softmax 作用于超长序列的已知后果。为解决它，Llama 4 使用带缩放的 softmax，模型称之为温度调优。这个只施加在 NoPE 层，RoPE 层不加，因为它们注意的只是较短的子序列。

这套方法是为任意上下文长度提升泛化的手段，很可能也是 Llama 4 Scout 达成 10M 上下文的关键因素之一。

- **QK 归一化**

Llama Scout（16 专家版）在 RoPE 层的 Query 与 Key 状态上，于 RoPE 嵌入应用之后额外做一次不带可学习参数的 RMS 归一化。

- **MoE 交错**

Llama Scout 是由 16 个专家构成的全 MoE。Llama Maverick 用 128 个专家，但 MoE 层与稠密层交替——因此专家只在一半层里生效。

- **共同蒸馏（Co-distillation）**

Llama Maverick 由更大的模型 Llama Behemoth 共同蒸馏而来，使用一种对 student 与 teacher logit 动态加权的新奇损失函数。

- **MetaP**

模型采用 MetaP——一种很可能受 [MuP](https://huggingface.co/papers/2203.03466) 启发方法论——在训练预算、模型规模等不同维度上最优地调超参数。

## 如何用 Transformers 使用

用 `transformers` 上手 Llama 4 很直接。确保安装 `transformers v4.51.0` 或更新版本（`pip install -U transformers huggingface_hub[hf_xet]`）。下面是一个快速示例：用指令微调的 Maverick 描述两张图，并用张量并行拉满速度。该脚本需要在 8 GPU 实例上运行，命令形如：
`torchrun –nproc-per-instance=8 script.py`

```
from transformers import AutoProcessor, Llama4ForConditionalGeneration
import torch

model_id = "meta-llama/Llama-4-Maverick-17B-128E-Instruct"

processor = AutoProcessor.from_pretrained(model_id)
model = Llama4ForConditionalGeneration.from_pretrained(
    model_id,
    attn_implementation="flex_attention",
    device_map="auto",
    torch_dtype=torch.bfloat16,
)

url1 = "https://huggingface.co/datasets/huggingface/documentation-images/resolve/0052a70beed5bf71b92610a43a52df6d286cd5f3/diffusers/rabbit.jpg"
url2 = "https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/datasets/cat_style_layout.png"
messages = [
    {
        "role": "user",
        "content": [
            {"type": "image", "url": url1},
            {"type": "image", "url": url2},
            {"type": "text", "text": "Can you describe how these two images are similar, and how they differ?"},
        ]
    },
]

inputs = processor.apply_chat_template(
    messages,
    add_generation_prompt=True,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
).to(model.device)

outputs = model.generate(
    **inputs,
    max_new_tokens=256,
)

response = processor.batch_decode(outputs[:, inputs["input_ids"].shape[-1]:])[0]
print(response)
print(outputs[0])
```

详细用法——包括多模态示例、特定提示格式（如系统提示词）、量化细节和高级配置选项——请务必查看仓库里的模型卡（[Llama 4 Maverick (~400B)](https://huggingface.co/meta-llama/Llama-4-Maverick-17B-128E-Instruct) 与 [Llama 4 Scout (~109B)](https://huggingface.co/meta-llama/Llama-4-Scout-17B-16E-Instruct)）！

## 评估分数

评估结果证实了这些模型的实力：最先进（SOTA）的性能显著超越 Llama 3.1 405B 等前代。例如在推理与知识任务上，指令微调的 Maverick 在 MMLU Pro 拿到 80.5%、GPQA Diamond 拿到 69.8%，而 Scout 分别为 74.3% 和 57.2%。
