# Pollen-Vision：机器人领域 Zero-Shot 视觉模型的统一接口

> 这是 Pollen Robotics 团队的客座博客。我们是 Reachy 的创造者——一款为真实世界操作而设计的开源人形机器人。

在自主行为的语境下，机器人的可用性本质上取决于它理解和交互环境的能力。这种理解主要来自**视觉感知**——它让机器人能够识别物体、识别人、在空间中导航等等。

我们很高兴分享开源 `pollen-vision` 库的首发，这是我们赋予机器人自主抓取未知物体能力的第一步。**这个库精心收藏了一批为机器人直接应用而挑选的视觉模型。** `Pollen-vision` 以安装和使用便捷为设计目标，由独立模块组成，可以组合成 3D 物体检测 pipeline，得到物体在 3D 空间中的位置（x, y, z）。

我们专注于挑选 [zero-shot 模型](https://huggingface.co/tasks/zero-shot-object-detection)，无需任何训练，让这些工具开箱即用。

我们的首次发布聚焦于 3D 物体检测——通过提供物体空间坐标的可靠估计，为机器人抓取等任务打下基础。目前功能限于 3D 空间定位（尚未扩展到完整 6D 姿态估计），但已为基本机器人操作任务建立了扎实的地基。

## Pollen-Vision 的核心模型

这个库封装了若干关键模型。我们希望所用模型是 zero-shot 且多才多艺的，无需重新训练就能检测广泛的物体；同时模型必须「能实时运行」，即至少在消费级 GPU 上达到几 fps。我们首批选择的模型是：

- [OWL-VIT](https://huggingface.co/docs/transformers/model_doc/owlvit)（Open World Localization - Vision Transformer，Google Research 出品）：该模型在 RGB 图像上执行文本条件化的 zero-shot 2D 物体定位，输出 bounding boxes（类似 YOLO）
- [Mobile Sam](https://github.com/ChaoningZhang/MobileSAM)：Meta AI 的 Segment Anything Model（SAM）的轻量版本。SAM 是 zero-shot 图像分割模型，可以用 bounding box 或点作为 prompt。
- [RAM](https://github.com/xinyu1205/recognize-anything)（Recognize Anything Model，OPPO 研究院出品）：RAM 为 zero-shot 图像打标而设计，能基于文本描述判断物体是否存在于图像中，为后续分析奠定基础。

## 几行代码快速上手！

下面是一个简单例子，用 pollen-vision 构建物体检测与分割 pipeline，输入只需要图像和文本。

```
from pollen_vision.vision_models.object_detection import OwlVitWrapper
from pollen_vision.vision_models.object_segmentation import MobileSamWrapper
from pollen_vision.vision_models.utils import Annotator, get_bboxes

owl = OwlVitWrapper()
sam = MobileSamWrapper()
annotator = Annotator()

im = ...
predictions = owl.infer(im, ["paper cups"])  # zero-shot object detection
bboxes = get_bboxes(predictions)

masks = sam.infer(im, bboxes=bboxes)  # zero-shot object segmentation
annotated_im = annotator.annotate(im, predictions, masks=masks)
```

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/pollen-vision/paper_cups.png)

OWL-VIT 的推理时间取决于提供的 prompt 数量（即待检测物体数量）。在一台配备 RTX 3070 GPU 的笔记本上：

```
1 prompt   : ~75ms  per frame
2 prompts  : ~130ms per frame
3 prompts  : ~180ms per frame
4 prompts  : ~240ms per frame
5 prompts  : ~330ms per frame
10 prompts : ~650ms per frame
```

因此，从性能角度看，只拿我们确知在图像中的物体去 prompt OWL-VIT 是明智的。这正是 RAM 的用武之地——它速度快，且恰好提供这类信息。

## 一个机器人用例：在不受约束的环境中抓取未知物体

有了物体的分割掩码，我们可以通过计算二值掩码的质心来估计它在像素空间中的 (u, v) 位置。这里分割掩码非常有用，因为它让我们可以对掩码内部的深度值求平均，而不是对整个 bounding box——后者的背景会把平均值带偏。

一种做法是对掩码中非零像素的 u、v 坐标求平均

```
def get_centroid(mask):
    x_center, y_center = np.argwhere(mask == 1).sum(0) / np.count_nonzero(mask)
    return int(y_center), int(x_center)
```

现在引入深度信息来估计物体的 z 坐标。深度值已经是米为单位，但 (u, v) 坐标以像素表示。利用相机的内参矩阵（K），我们可以得到物体质心以米为单位的 (x, y, z) 位置

```
def uv_to_xyz(z, u, v, K):
    cx = K[0, 2]
    cy = K[1, 2]
    fx = K[0, 0]
    fy = K[1, 1]

    x = (u - cx) * z / fx
    y = (v - cy) * z / fy

    return np.array([x, y, z])
```

这样我们就得到了物体在相机参考系下 3D 位置的估计。

如果我们知道相机相对于机器人原点坐标系的位置，就可以通过简单变换得到物体在机器人坐标系中的 3D 位置。这意味着我们能把机器人的末端执行器移动到物体所在处，**并抓取它**！🥳

## 接下来？

我们在本文中展示的，是迈向目标的第一步——在野外自主抓取未知物体。仍有一些问题需要解决：

- OWL-Vit 并非每次都能检测到所有目标，且可能不稳定。我们正在寻找更好的方案。
- 目前没有任何时间或空间一致性，每帧都从头重新计算。我们正在集成点跟踪（point tracking）方案，以提升检测的一致性。
- 抓取技术（目前仅前向抓取）不是本次工作的重点。我们将在感知（6D 检测）和抓取姿态生成方面探索不同方法以提升抓取能力。
- 整体速度还有提升空间
