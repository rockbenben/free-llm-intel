Hugging Face 提供了一个 Hub 平台，让你可以轻松上传、共享和部署模型。它节省了开发者从零开始训练模型所需的时间和计算资源。然而，在真实的生产环境中或以云原生的方式部署模型仍然会带来挑战。

这正是 BentoML 发挥作用的地方。BentoML 是一个用于机器学习模型服务和部署的开源平台。它是一个统一的框架，用于构建、交付和扩展包含传统模型、预训练模型、生成式模型以及大语言模型的生产就绪 AI 应用。以下是从高层视角使用 BentoML 框架的方式：

- **定义模型**：在使用 BentoML 之前，你需要一个机器学习模型（或多个模型）。这些模型可以使用 TensorFlow、PyTorch 等机器学习库进行训练。
- **保存模型**：得到训练好的模型后，将其保存到 BentoML 的本地模型仓库（Model Store），它既用于在本地管理所有训练好的模型，也用于为服务提供模型访问。
- **创建 BentoML Service**：你创建一个 `service.py` 文件来封装模型并定义服务逻辑。它为模型指定 [Runner](https://docs.bentoml.org/en/latest/concepts/runner.html)，以便大规模运行模型推理，并暴露 API 来定义如何处理输入和输出。
- **构建 Bento**：通过创建一个配置 YAML 文件，你将所有模型和 [Service](https://docs.bentoml.org/en/latest/concepts/service.html) 打包成一个 [Bento](https://docs.bentoml.org/en/latest/concepts/bento.html)，即包含全部代码和依赖项的可部署构件。
- **部署 Bento**：Bento 就绪后，你可以将其容器化以创建一个 Docker 镜像并在 Kubernetes 上运行。或者，将 Bento 直接部署到 Yatai，这是一个开源的端到端解决方案，用于在 Kubernetes 上大规模自动化并运行机器学习部署。

在这篇博文中，我们将按照上述工作流演示如何将 [DeepFloyd IF](https://huggingface.co/docs/diffusers/api/pipelines/if) 与 BentoML 集成。

## DeepFloyd IF 简介

DeepFloyd IF 是一个最先进的开源文本生成图像模型。它之所以有别于 Stable Diffusion 等潜在扩散模型，在于其独特的运行策略和架构。

DeepFloyd IF 实现了高度的真实感和精密的语言理解能力。与 Stable Diffusion 不同，DeepFloyd IF 直接在像素空间中工作，采用一种模块化结构，包含一个冻结的文本编码器和三个级联的像素扩散模块。每个模块在流程中都扮演着独特的角色：Stage 1 负责生成一张 64x64 像素的基础图像，随后在 Stage 2 和 Stage 3 中逐步上采样至 1024x1024 像素。DeepFloyd IF 独特性的另一个关键方面，是它集成了一个大语言模型（T5-XXL-1.1）来编码 prompt，从而对复杂 prompt 提供更出色的理解。更多信息请参阅 Stability AI 关于 DeepFloyd IF 的[这篇博客文章](https://stability.ai/blog/deepfloyd-if-text-to-image-model)。

为了让你的 DeepFloyd IF 应用在生产环境中保持高性能运行，你可能希望合理地分配和管理资源。在这方面，BentoML 允许你为每个 Stage 独立扩展 Runner。例如，你可以为 Stage 1 的 Runner 使用更多 Pod，或为其分配更强大的 GPU 服务器。

## 准备环境

[这个 GitHub 仓库](https://github.com/bentoml/IF-multi-GPUs-demo)存储了本项目所需的全部文件。要在本地运行此项目，请确保你已具备：

- Python 3.8+
- 已安装 `pip`
- 至少 2 块 16GB 显存（VRAM）的 GPU 或 1 块 40GB 显存的 GPU。对于本项目，我们使用了一台 Google Cloud 的 `n1-standard-16` 类型机器，外加 64 GB 内存和 2 块 NVIDIA T4 GPU。请注意，虽然可以在单块 T4 上运行 IF，但对于生产级服务而言并不推荐。

满足前提条件后，将项目仓库克隆到本地机器并进入目标目录。

```
git clone https://github.com/bentoml/IF-multi-GPUs-demo.git
cd IF-multi-GPUs-demo
```

在构建应用之前，让我们简要浏览一下此目录中的关键文件：

- `import_models.py`：为 [`IFPipeline`](https://huggingface.co/docs/diffusers/api/pipelines/if) 的每个阶段定义模型。你使用此文件将所有模型下载到本地机器，以便将它们打包进同一个 Bento。
- `requirements.txt`：定义本项目所需的全部包和依赖项。
- `service.py`：定义一个 BentoML Service，其中包含使用 `to_runner` 方法创建的三个 Runner，并暴露一个用于生成图像的 API。该 API 接受一个 JSON 对象作为输入（即 prompt 和 negative prompt），并使用一系列模型返回一张图像作为输出。
- `start-server.py`：通过 `service.py` 中定义的 Service 启动一个 BentoML HTTP 服务器，并创建一个 Gradio Web 界面，供用户输入 prompt 来生成图像。
- `bentofile.yaml`：定义待构建 Bento 的元数据，包括 Service、Python 包和模型。

我们建议你创建一个虚拟环境以实现依赖隔离。例如，运行以下命令以激活 `venv`：

```
python -m venv venv
source venv/bin/activate
```

安装所需的依赖项：

```
pip install -r requirements.txt
```

如果你之前没有通过命令行从 Hugging Face 下载过模型，则必须先登录：

```
pip install -U huggingface_hub
huggingface-cli login
```

## 将模型下载到 BentoML 模型仓库

如上所述，你需要下载 DeepFloyd IF 各阶段所用的所有模型。环境搭建完成后，运行以下命令将模型下载到本地模型仓库。此过程可能需要一些时间。

```
python import_models.py
```

下载完成后，在模型仓库中查看这些模型。

## 启动 BentoML Service

你可以直接使用 `start-server.py` 文件运行由 Gradio 提供 Web UI 的 BentoML HTTP 服务器，它是本应用的入口点。它提供了多种来自定义执行和管理各 Stage 之间 GPU 分配的选项。根据你的 GPU 配置，你可能使用不同的命令：

- 对于显存超过 40GB 的 GPU，在同一块 GPU 上运行所有模型。`python start-server.py `
- 对于两块各具 15GB 显存的 Tesla T4，将 Stage 1 模型分配给第一块 GPU，将 Stage 2 和 Stage 3 模型分配给第二块 GPU。`python start-server.py --stage1-gpu=0 --stage2-gpu=1 --stage3-gpu=1 `
- 对于一块 15GB 显存的 Tesla T4 和两块显存较小的额外 GPU，将 Stage 1 模型分配给 T4，将 Stage 2 和 Stage 3 模型分别分配给第二块和第三块 GPU。`python start-server.py --stage1-gpu=0 --stage2-gpu=1 --stage3-gpu=2 `

要查看所有可自定义的选项（如服务器的端口），运行：

```
python start-server.py --help
```

## 测试服务器

服务器启动后，你可以访问 [http://localhost:7860](http://localhost:7860) 处的 Web UI。BentoML API 端点也可以在 [http://localhost:3000](http://localhost:3000) 访问。下面是一个 prompt 和 negative prompt 的示例。

Prompt：

> orange and black, head shot of a woman standing under street lights, dark theme, Frank Miller, cinema, ultra realistic, ambiance, insanely detailed and intricate, hyper realistic, 8k resolution, photorealistic, highly textured, intricate details

Negative prompt：

> tiling, poorly drawn hands, poorly drawn feet, poorly drawn face, out of frame, mutation, mutated, extra limbs, extra legs, extra arms, disfigured, deformed, cross-eye, body out of frame, blurry, bad art, bad anatomy, blurred, text, watermark, grainy
