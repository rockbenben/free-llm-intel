## 概览

在开始之前，让我们先谈谈我们要创造什么。这款游戏灵感来自 Google 的 [Quick, Draw!](https://quickdraw.withgoogle.com/) 游戏，在其中你会得到一个词，一个神经网络有 20 秒时间来猜你在画什么（重复 6 次）。实际上，我们将使用他们的[训练数据](https://huggingface.co/blog/ml-web-games#training-data)来训练我们自己的草图检测模型！你不也热爱开源吗？😍

在我们的版本里，你有一分钟时间一次一个提示地尽可能多地画物品。如果模型预测出正确的标签，画布会被清空，并给你一个新词。就这样一直画到计时器耗尽！由于游戏在浏览器本地运行，我们完全不用担心服务器延迟。模型能在你绘画时做出实时预测，达到每秒 60 次以上的预测……🤯 哇！

## 1. 训练神经网络

### 训练数据

我们将使用 Google [Quick, Draw!](https://quickdraw.withgoogle.com/data) 数据集的一个[子集](https://huggingface.co/datasets/Xenova/quickdraw-small)来训练模型，该数据集包含跨越 345 个类别的超过 500 万张绘画。以下是数据集中的一些样本：

[![Quick, Draw! dataset](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml-web-games/quickdraw-dataset.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml-web-games/quickdraw-dataset.png)

### 模型架构

我们将微调 [`apple/mobilevit-small`](https://huggingface.co/apple/mobilevit-small)，一个轻量、对移动端友好的 Vision Transformer，已在 [ImageNet-1k](https://huggingface.co/datasets/imagenet-1k) 上预训练。它只有 5.6M 参数（约 20 MB 文件大小），是在浏览器中运行的完美候选。更多信息请查看 [MobileViT 论文](https://huggingface.co/papers/2110.02178)和下面的模型架构。

[![MobileViT archtecture](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml-web-games/mobilevit.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml-web-games/mobilevit.png)

### 微调

为了让博文（相对）简短，我们准备了一个 Colab notebook，它会展示我们在数据集上微调 [`apple/mobilevit-small`](https://huggingface.co/apple/mobilevit-small) 所采取的确切步骤。从宏观层面看，这涉及：

- 加载 ["Quick, Draw!" 数据集](https://huggingface.co/datasets/Xenova/quickdraw-small)。
- 用 [`MobileViTImageProcessor`](https://huggingface.co/docs/transformers/model_doc/mobilevit#transformers.MobileViTImageProcessor) 转换数据集。
- 定义我们的 [collate 函数](https://huggingface.co/docs/transformers/main_classes/data_collator)和[评估指标](https://huggingface.co/docs/evaluate/types_of_evaluations#metrics)。
- 用 [`MobileViTForImageClassification.from_pretrained`](https://huggingface.co/docs/transformers/model_doc/mobilevit#transformers.MobileViTForImageClassification) 加载[预训练的 MobileVIT 模型](https://huggingface.co/apple/mobilevit-small)。
- 用 [`Trainer`](https://huggingface.co/docs/transformers/main_classes/trainer) 和 [`TrainingArguments`](https://huggingface.co/docs/transformers/main_classes/trainer#transformers.TrainingArguments) 辅助类训练模型。
- 用 [🤗 Evaluate](https://huggingface.co/docs/evaluate) 评估模型。

*注：* 我们微调后的模型可以在 Hugging Face Hub 上[此处](https://huggingface.co/Xenova/quickdraw-mobilevit-small)找到。

## 2. 用 Transformers.js 在浏览器中运行

### 什么是 Transformers.js？

[Transformers.js](https://huggingface.co/docs/transformers.js) 是一个 JavaScript 库，让你可以直接在浏览器中运行 [🤗 Transformers](https://huggingface.co/docs/transformers)（无需服务器）！它被设计为与 Python 库在功能上等价，意味着你可以用非常相似的 API 运行同样的预训练模型。

在幕后，Transformers.js 使用 [ONNX Runtime](https://onnxruntime.ai/)，所以我们需要把微调后的 PyTorch 模型转换为 ONNX。

### 把我们的模型转换为 ONNX

幸运的是，[🤗 Optimum](https://huggingface.co/docs/optimum) 库把把微调模型转换为 ONNX 变得超级简单！最简单（也是推荐）的方式是：

- 克隆 [Transformers.js 仓库](https://github.com/xenova/transformers.js)并安装所需的依赖：`git clone https://github.com/xenova/transformers.js.git cd transformers.js pip install -r scripts/requirements.txt `
- 运行转换脚本（其底层使用 `Optimum`）：`python -m scripts.convert --model_id <model_id> ` 其中 `<model_id>` 是你想转换的模型名称（例如 `Xenova/quickdraw-mobilevit-small`）。

### 搭建我们的项目

让我们先用 Vite 搭一个简单的 React 应用脚手架：

```
npm create vite@latest doodle-dash -- --template react
```

接下来，进入项目目录并安装所需的依赖：

```
cd doodle-dash
npm install
npm install @xenova/transformers
```

然后你可以通过运行以下命令启动开发服务器：

```
npm run dev
```

### 在浏览器中运行模型

运行机器学习模型是计算密集型的，所以在一个单独的线程中执行推理很重要。这样我们就不会阻塞用于渲染 UI 和响应你绘画手势的主线程 😉。[Web Workers API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API) 让这件事超级简单！

在 `src` 目录中创建一个新文件（例如 `worker.js`）并加入以下代码：

```
import { pipeline, RawImage } from "@xenova/transformers";

const classifier = await pipeline("image-classification", 'Xenova/quickdraw-mobilevit-small', { quantized: false });

const image = await RawImage.read('https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml-web-games/skateboard.png');

const output = await classifier(image.grayscale());
console.log(output);
```

现在我们可以在 `App.jsx` 文件中使用这个 worker，在 `App` 组件中加入以下代码：

```
import { useState, useEffect, useRef } from 'react'
// ... rest of the imports

function App() {
    // Create a reference to the worker object.
    const worker = useRef(null);

    // We use the `useEffect` hook to set up the worker as soon as the `App` component is mounted.
    useEffect(() => {
        if (!worker.current) {
            // Create the worker if it does not yet exist.
            worker.current = new Worker(new URL('./worker.js', import.meta.url), {
                type: 'module'
            });
        }

        // Create a callback function for messages from the worker thread.
        const onMessageReceived = (e) => { /* See code */ };

        // Attach the callback function as an event listener.
        worker.current.addEventListener('message', onMessageReceived);

        // Define a cleanup function for when the component is unmounted.
        return () => worker.current.removeEventListener('message', onMessageReceived);
    });

    // ... rest of the component
}
```

你可以通过运行开发服务器（用 `npm run dev`）、访问本地网站（通常是 [http://localhost:5173/](http://localhost:5173/)）并打开浏览器控制台来测试一切是否正常。你应该会看到模型的输出被记录到控制台。

```
[{ label: "skateboard", score: 0.9980043172836304 }]
```

*嘻！* 🥳 尽管上面的代码只是[最终产品](https://github.com/xenova/doodle-dash)的一小部分，但它展示了其中的机器学习一侧有多么简单！剩下的只是把它做得好看，并加上一些游戏逻辑。

## 3. 游戏设计

在这一节，我会简要讨论游戏设计的过程。提醒一下，你可以在 [GitHub](https://github.com/xenova/doodle-dash) 上找到项目的完整源代码，所以我不会深入讲述代码本身。

### 利用实时性能

在浏览器中执行推理的主要优势之一是我们能实时做出预测（每秒超过 60 次）。在原始的 [Quick, Draw!](https://quickdraw.withgoogle.com/) 游戏中，模型每隔几秒才做一次新预测。我们也能在我们的游戏里那样做，但那样我们就没有利用它的实时性能了！所以，我决定重新设计主游戏循环：

- 我们的版本不再是六个 20 秒的回合（每个回合对应一个新词），而是要求玩家在 60 秒内一次一个提示地尽可能正确地画出越多越好的涂鸦。
- 如果你遇到一个画不出来的词，你可以跳过它（但这会耗费你剩余时间中的 3 秒）。
- 在原游戏中，由于模型每隔几秒猜一次，它可以慢慢把标签从清单上划掉，直到最终猜对。在我们的版本里，我们转而降低模型对前 `n` 个错误标签的得分，其中 `n` 随着用户继续绘画而随时间增大。

### 体验质量改进

原始数据集包含 345 个不同的类别，而由于我们的模型相对较小（约 20MB），它有时无法正确猜出某些类别。为解决这个问题，我们移除了一些属于以下情况的词：

- 与其他标签太相似（例如 "barn" 对比 "house"）
- 太难理解（例如 "animal migration"）
- 太难在足够细节下画出（例如 "brain"）
- 有歧义（例如 "bat"）

过滤之后，我们仍然剩下 300 多个不同的类别！
