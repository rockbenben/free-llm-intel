# 如何使用 Megatron-LM 训练语言模型

用 PyTorch 训练大语言模型，远不止一个简单的训练循环。它通常分布在多个设备上，并需要许多优化技术来保证训练稳定高效。Hugging Face 🤗 [Accelerate](https://huggingface.co/docs/accelerate/index) 库就是为了支持 GPU 和 TPU 上的分布式训练而创建的，与训练循环集成非常轻松。🤗 [Transformers](https://huggingface.co/docs/transformers/index) 也通过 [Trainer](https://huggingface.co/docs/transformers/main_classes/trainer#transformers.Trainer) API 支持分布式训练，在 PyTorch 里提供功能完备的训练，甚至不需要你自己实现训练循环。

研究者预训练大型 Transformer 模型的另一个常用工具是 [Megatron-LM](https://github.com/NVIDIA/Megatron-LM)——NVIDIA 应用深度学习研究团队打造的强大框架。与 `accelerate` 和 `Trainer` 不同，Megatron-LM 用起来不算直白，对新手可能有点劝退。但它针对 GPU 训练做了深度优化，能带来一些加速。在这篇博客里，你将学会如何在 NVIDIA GPU 上用 Megatron-LM 训练语言模型，并让它和 `transformers` 一起工作。

我们会拆解在这个框架下训练 GPT2 模型的各个步骤，包括：

- 环境配置
- 数据预处理
- 训练
- 模型转换成 🤗 Transformers 格式

## 为什么选 Megatron-LM？

在进入训练细节前，先弄清这个框架凭什么比其他框架更高效。本节受到一篇讲 BLOOM 用 [Megatron-DeepSpeed](https://github.com/bigscience-workshop/Megatron-DeepSpeed) 训练的优秀[博客](https://huggingface.co/blog/bloom-megatron-deepspeed)启发，更多细节请看那篇——本文的初衷是带一个 Megatron-LM 的温和入门。

### DataLoader

Megatron-LM 自带一个高效 DataLoader：数据在训练前就完成了 tokenize 和打乱。它还会把数据切成带索引的编号序列，索引只需计算一次并存储下来。构建索引时，会根据训练参数算出 epoch 数，先创建一个顺序再打乱。这不同于常见做法——把整个数据集迭代到耗尽、第二个 epoch 再重来一遍。这样能平滑学习曲线，并节省训练时间。

### Fused CUDA Kernels

GPU 上执行一次计算时，需要先从内存取数据，算完再把结果写回内存。简单说，fused kernel 的思想就是把 PyTorch 通常分开做的相似操作合并成一个硬件操作，从而把多次离散计算中的内存搬运合并成一次。下图说明了 Kernel Fusion 的思想，灵感来自这篇[论文](https://www.arxiv-vanity.com/papers/1305.1183/)，其中对该概念有详细讨论。

![](https://huggingface.co/blog/assets/100_megatron_training/kernel_fusion.png)

当 f、g、h 融合进一个 kernel 时，f 和 g 的中间结果 x'、y' 存在 GPU 寄存器里，h 可以立即使用。而不融合时，x'、y' 需要拷回内存、再由 h 加载。因此 Kernel Fusion 能为计算显著提速。Megatron-LM 还使用了 [Apex](https://github.com/NVIDIA/apex) 的 Fused AdamW 实现，比 PyTorch 的实现更快。

虽说在 `transformers` 里也可以自定义像 Megatron-LM 那样的 DataLoader、使用 Apex 的 Fused 优化器，但亲手构建自定义 Fused CUDA Kernels 对新手绝不友好。

了解了这个框架以及它的优势之后，我们进入训练细节！

## 如何用 Megatron-LM 训练？

### 配置环境

最简单的环境配置方式是拉取 NVIDIA PyTorch Container，它自带全部所需组件，来自 [NGC](https://catalog.ngc.nvidia.com/orgs/nvidia/containers/pytorch)。更多细节见[文档](https://docs.nvidia.com/deeplearning/frameworks/pytorch-release-notes/index.html)。如果不想用这个容器，你需要自行安装最新版 pytorch、cuda、nccl、NVIDIA [APEX](https://github.com/NVIDIA/apex#quick-start) 以及 `nltk` 库。

装好 Docker 后，可以用下面命令运行容器（`xx.xx` 表示你的 Docker 版本），然后在里面 clone [Megatron-LM 仓库](https://github.com/NVIDIA/Megatron-LM)：

```
docker run --gpus all -it --rm nvcr.io/nvidia/pytorch:xx.xx-py3
git clone https://github.com/NVIDIA/Megatron-LM
```

你还需要把 tokenizer 的词表文件 `vocab.json` 和合并表 `merges.txt` 放进容器的 Megatron-LM 文件夹。这些文件可以在模型仓库中和权重一起找到，GPT2 见这个[仓库](https://huggingface.co/gpt2/tree/main)。你也可以用 `transformers` 训练自己的 tokenizer，可以参考 [CodeParrot 项目](https://github.com/huggingface/transformers/tree/main/examples/research_projects/codeparrot)的实际例子。如果想从容器外拷贝这些数据，可以用以下命令：

```
sudo docker cp vocab.json CONTAINER_ID:/workspace/Megatron-LM
sudo docker cp merges.txt CONTAINER_ID:/workspace/Megatron-LM
```

### 数据预处理

下文以 [CodeParrot](https://huggingface.co/codeparrot/codeparrot-small) 模型和数据为例。

训练数据需要一些预处理。首先，把它转换成一个宽松的 json 格式：每行一个 json，包含一条文本样本。如果你用 🤗 [Datasets](https://huggingface.co/docs/datasets/index)，下面演示怎么做（同样在 Megatron-LM 文件夹内）：

```
from datasets import load_dataset

train_data = load_dataset('codeparrot/codeparrot-clean-train', split='train')
train_data.to_json("codeparrot_data.json", lines=True)  
```

随后用以下命令对数据做 tokenize、打乱，并处理成训练用的二进制格式：

```
#if nltk isn't installed
pip install nltk
python tools/preprocess_data.py \
       --input codeparrot_data.json \
       --output-prefix codeparrot \
       --vocab vocab.json \
       --dataset-impl mmap \
       --tokenizer-type GPT2BPETokenizer \
       --merge-file merges.txt \
       --json-keys content \
       --workers 32 \
       --chunk-size 25 \
       --append-eod
```

`workers` 和 `chunk_size` 指预处理使用的 worker 数量，以及分配给每个 worker 的数据块大小。`dataset-impl` 指定索引数据集的实现模式，可选 ['lazy', 'cached', 'mmap']。输出两个文件 `codeparrot_content_document.idx` 和 `codeparrot_content_document.bin`，训练时要用。

### 训练

你可以像下面这样配置模型结构和训练参数，也可以写进 bash 脚本运行。这条命令在 8 块 GPU 上对一个 110M 参数的 CodeParrot 模型做预训练。注意数据默认按 969:30:1 划分训练/验证/测试集。

```
GPUS_PER_NODE=8
MASTER_ADDR=localhost
MASTER_PORT=6001
NNODES=1
NODE_RANK=0
WORLD_SIZE=$(($GPUS_PER_NODE*$NNODES))
DISTRIBUTED_ARGS="--nproc_per_node $GPUS_PER_NODE --nnodes $NNODES --node_rank $NODE_RANK --master_addr $MASTER_ADDR --master_port $MASTER_PORT"
CHECKPOINT_PATH=/workspace/Megatron-LM/experiments/codeparrot-small
VOCAB_FILE=vocab.json
MERGE_FILE=merges.txt
DATA_PATH=codeparrot_content_document
GPT_ARGS="--num-layers 12
--hidden-size 768
--num-attention-heads 12
--seq-length 1024
--max-position-embeddings 1024
--micro-batch-size 12
--global-batch-size 192
--lr 0.0005
--train-iters 150000
--lr-decay-iters 150000
--lr-decay-style cosine
--lr-warmup-iters 2000
--weight-decay .1
--adam-beta2 .999
--fp16
--log-interval 10
--save-interval 2000
--eval-interval 200
--eval-iters 10
"
TENSORBOARD_ARGS="--tensorboard-dir experiments/tensorboard"
python3 -m torch.distributed.launch $DISTRIBUTED_ARGS \
        pretrain_gpt.py \
        --tensor-model-parallel-size 1 \
        --pipeline-model-parallel-size 1 \
        $GPT_ARGS \
        --vocab-file $VOCAB_FILE \
        --merge-file $MERGE_FILE \
        --save $CHECKPOINT_PATH \
        --load $CHECKPOINT_PATH \
        --data-path $DATA_PATH \
        $TENSORBOARD_ARGS
```

在这个配置下，训练大约需要 12 小时。

这份配置用的是数据并行（Data Parallelism）。对于单块 GPU 装不下的超大模型，也可以使用模型并行（Model Parallelism）。第一种选择是张量并行（Tensor Parallelism），把单个 Transformer 模块的执行拆分到多块 GPU 上，你需要把 `tensor-model-parallel-size` 参数改成想要的 GPU 数。第二种是流水线并行（Pipeline Parallelism），把 Transformer 模块切成等大的阶段，`pipeline-model-parallel-size` 参数决定模型被拆成多少个阶段。更多细节参考这篇[博客](https://huggingface.co/blog/bloom-megatron-deepspeed)。

### 把模型转换成 🤗 Transformers

训练完成后，我们想在 `transformers` 里用这个模型——做评估或者部署到生产。你可以按照这个[教程](https://huggingface.co/nvidia/megatron-gpt2-345m)转换模型。例如，训练结束后，你可以拷贝第 150k 次迭代的权重，用以下命令把 `model_optim_rng.pt` 文件转换成 `transformers` 支持的 `pytorch_model.bin`：

```
# to execute outside the container:
mkdir -p nvidia/megatron-codeparrot-small
# copy the weights from the container
sudo docker cp CONTAINER_ID:/workspace/Megatron-LM/experiments/codeparrot-small/iter_0150000/mp_rank_00/model_optim_rng.pt nvidia/megatron-codeparrot-small
git clone https://github.com/huggingface/transformers.git
git clone https://github.com/NVIDIA/Megatron-LM.git
export PYTHONPATH=Megatron-LM
python transformers/src/transformers/models/megatron_gpt2/convert_megatron_gpt2_checkpoint.py nvidia/megatron-codeparrot-small/model_optim_rng.pt
```

小心：转换之后，如果你打算从那里加载 tokenizer，需要把生成的词表文件和合并表替换回我们前面提到的原始文件。

别忘了把你的模型推到 hub 上、分享给社区——只要三行代码 🤗：

```
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained("nvidia/megatron-codeparrot-small")
# this creates a repository under your username with the model name codeparrot-small
model.push_to_hub("codeparrot-small")
```

也可以轻松用它生成文本：

```
from transformers import pipeline

pipe = pipeline("text-generation", model="your_username/codeparrot-small")
outputs = pipe("def hello_world():")
print(outputs[0]["generated_text"])
```

```
 def hello_world():   
    print("Hello World!")
```

Transformers 同样能高效处理大模型推理。如果你训练了一个非常大的模型（例如用了模型并行），可以用以下命令轻松跑推理：

```
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained("your_username/codeparrot-large", device_map="auto")
```

背后会调用 [accelerate](https://huggingface.co/docs/accelerate/index) 库，自动把模型权重分布到你可用的设备（GPU、CPU 内存）上。

声明：我们展示了任何人都可以用 Megatron-LM 训练语言模型。问题在于什么时候该用它。这个框架显然会因额外的预处理和转换步骤带来时间开销，所以你需要判断对你自己的场景和模型规模，哪个框架更合适。我们推荐在预训练或长时间微调时尝试它，但中型模型的短期微调大概并不合适。`Trainer` API 和 `accelerate` 库在模型训练上同样好用，它们与设备无关，给用户提供了极大的灵活性。

恭喜 🎉 现在你知道了如何在 Megatron-LM 中训练一个 GPT2 模型并让它被 `transformers` 支持！
