Capital Fund Management（CFM）是一家另类投资管理公司，总部位于巴黎，在纽约和伦敦也设有团队，目前管理着 155 亿美元资产。

CFM 用科学方法做金融，借助量化与系统化手段设计卓越的投资策略。

CFM 一直在与 [Hugging Face 的 Expert Support](https://huggingface.co/support) 合作，跟进机器学习的最新进展，并为广泛的金融应用用好开源技术。双方合作的主要目标之一，是探索 CFM 如何高效使用开源大语言模型（LLM）来增强现有机器学习用例。量化对冲基金依赖海量数据来决定买入或卖出特定金融产品。除了金融市场的标准数据源（如价格），对冲基金还日益从另类数据中提炼洞见，比如新闻文章里的文本信息。把新闻纳入全自动交易策略的一大挑战，是准确识别文章中提到的产品或实体（如公司、股票、货币）。虽然 CFM 的数据供应商会提供这些标签，但它们可能不完整，需要进一步校验。

CFM 探索了多种提升金融实体识别的方案，包括用 LLM 和更小模型做零样本 NER、用 Hugging Face Inference Endpoints 和 Argilla 做 LLM 辅助数据标注，以及在精编数据集上微调更小的模型。这些思路既利用了大模型的多面手优势，也回应了真实金融应用中成本与可扩展性的挑战。

在开源模型中，Meta 的 Llama 3.1 系列凭借在各项基准上的强劲表现脱颖而出，成为生成合成标注的首选。这些 LLM 在构建高质量标注数据集上起了关键作用，把自动化与人类专家结合起来，让标注流程更顺畅，并提升模型在金融 NER 任务上的表现。

## 金融新闻与股价整合数据集上的 NER

## 用 Llama 做 LLM 辅助数据标注

要有效地对比不同方法，首先需要整理出一份可靠的数据集，作为评估候选方法的基础。这份数据集既用于测试模型零样本表现，也作为微调的底子。

我们用 Llama 辅助数据标注来加速并提升标注过程：让 Llama 3.1 为数据集样本生成标签，然后用开源数据标注平台 [Argilla](https://argilla.io/) 对自动生成的标签做人工复核。这样既加快了标注速度，又保证了标注质量。

### ***为 NER 给 Llama 写提示词***

发送请求之前，需要设计一个能有效引导模型产出期望输出的提示词。经过多轮测试，我们把提示词分成多个部分来精确完成任务：

- **角色定义**：把模型定位为精通英语的金融专家。
- **任务指令**：让模型抽取与标题所指文章讨论的股票相关联的公司名，同时排除标题中常见的股票指数。
- **期望输出**：模型须返回一个字典：`"result"`：确切的公司的名字或股票代码；`"normalized_result"`：与 `"result"` 对应的标准化公司名。
- **少样本示例**：一系列输入-输出示例，展示期望行为，保证在各种输入上表现一致。这些示例帮助模型理解如何区分相关实体、如何正确格式化输出。每个示例展示不同的标题结构，让模型为各种真实场景做好准备。

```
SYSTEM_PROMPT = “””
###Instructions:### 
You are a financial expert with excellent English skills.  
Extract only the company names from the following headlines that are related to a stock discussed in the article linked to the headline.  
Do not include stock indices such as "CAC40" or "Dow Jones". 

##Expected Output:## 
Return a dictionary with: 
A key "result" containing a list of company names or stock symbols. Make sure to return them exactly as they are written in the text even if the original text has grammatical errors. If no companies or stocks are mentioned, return an empty list. 
A key "normalized_result" containing the normalized company names corresponding to the entries in the "result" list, in the same order. This list should have the same size as the "result" list. 

##Formatting:## 
Do not return companies not mentioned in the text. 

##Example Outputs##

Input: "There's A New Trading Tool That Allows Traders To Trade Cannabis With Leverage" 
Output: {"result": [], "normalized_result": []} 
Input: "We explain AAPL, TSLA, and MSFT report earnings" 
Output: {"result": ["AAPL", "TSLA", "MSFT"], "normalized_result": ["Apple", "Tesla", "Microsoft"]} 
Input: "10 Biggest Price Target Changes For Friday" 
Output: {"result": [], "normalized_result": []} 
Input: "'M' is For Microsoft, and Meh" 
Output: {"result": ["Microsoft"], "normalized_result": ["Microsoft"]} 
Input: "Black Diamond: The New North Face? (BDE, VFC, JAH, AGPDY.PK)" 
Output: {"result": ['Black Diamond', 'North Face', 'BDE', 'VFC','JAH','AGPDY.PK'], "normalized_result": ['Black Diamond','The North Face', 'BPER Banca', 'VF Corporation','Jarden Corporation','AGP Diagnostics']} 
“””

### **从端点获取预测**

提示词和端点都就绪后，下一步是用数据集中的标题发送请求。为了高效完成，我们使用 `huggingface_hub` 库的 [`AsyncInferenceClient`](https://huggingface.co/docs/huggingface_hub/package_reference/inference_client#huggingface_hub.AsyncInferenceClient)。它是 `InferenceClient` 的异步版本，基于 `asyncio` 和 `aiohttp` 构建，允许我们向端点并发发送多个请求，让数据集的处理更快更高效。

```
from huggingface_hub import AsyncInferenceClient

# Initialize the Hugging Face AsyncInferenceClient 
client = AsyncInferenceClient(base_url="https://your-endpoint-url.huggingface.cloud")
```

为确保模型返回结构化输出，我们使用 guidance 配合一个专门的 Pydantic schema `Companies`。

```
from pydantic import BaseModel 
from typing import List, Dict, Any

# This class defines the expected structure for the output using Pydantic.
class Companies(BaseModel):
    """
    Pydantic model representing the expected LLM output.
    
    Attributes:
        result (List[str]): A list of company names or results from the LLM.
        normalized_result (List[str]): A list of 'normalized' company names, i.e., processed/cleaned names.
    """
    result: List[str]
    normalized_result: List[str]

grammar: Dict[str, Any] = {
    "type": "json_object",
    "value": Companies.schema()  
    # This instructs the LLM to return a JSON with "result" and "normalized_result" as keys
}
```

同时设置生成参数：

```
max_tokens: int = 512  # Maximum number of tokens to generate in the response
temperature: float = 0.1  # Controls randomness in the output (lower values are more deterministic)
```

然后定义向端点发送请求并解析输出的函数：

```
async def llm_engine(messages: List[Dict[str, str]]) -> str:
    """
    Function to send a request to the LLM endpoint and get a response.

    Args:
        messages (List[Dict[str, str]]): A list of messages to pass to the LLM.

    Returns:
        str: The content of the response message or 'failed' in case of an error.
    """
    try:
        # Send the request to the LLM endpoint asynchronously
        response = await client.chat_completion(
            messages=messages,
            model="ENDPOINT",  # Replace with your model endpoint
            temperature=temperature,
            response_format=grammar,
            max_tokens=max_tokens
        )
        # Extract the content of the response message
        answer: str = response.choices[0].message.content
        return answer
    except Exception as e:
        # Handle any exceptions that occur during the request
        print(f"Error in LLM engine: {e}")
        return "failed"

def parse_llm_output(output_str: str) -> Dict[str, Any]:
    """
    Parse the JSON-like output string from an LLM into a dictionary.

    Args:
        output_str (str): The string output from an LLM, expected to be in JSON format.

    Returns:
        Dict[str, Any]: A dictionary parsed from the input JSON string with a 'valid' flag.
    """
    try:
        # Parse the JSON string into a dictionary
        result_dict: Dict[str, Any] = json.loads(output_str)
        result_dict["valid"] = True
        return result_dict
    except json.JSONDecodeError as e:
        # Handle JSON parsing errors and return a default structure
        print(f"Error decoding JSON: {e}")
        return {
            "result": [output_str],
            "normalized_result": [output_str],
            "valid": False
        }
```

接着创建一个 `process_batch` 函数，按可控的批次发送请求，避免 API 端点过载或触达限流。这种批处理让我们高效并发处理多个请求而不打满服务器，降低超时、请求被拒或被限流的风险。通过控制请求流量，我们获得稳定的性能、更快的响应、更容易的错误处理，同时最大化吞吐。

```
import asyncio

async def process_batch(batch):
    """ 
    Get the model output for a batch of samples.
    
    This function processes a batch of samples by sending them to the LLM and
    gathering the results concurrently.
    
    Args:
        batch (List[Dict[str, str]]): A list of dictionaries where each dictionary
                                      contains the data for a single sample, including
                                      an "Article_title".
    
    Returns:
        List[str]: A list of responses from the LLM for each sample in the batch.
    """
    
    list_messages = []
    
    # Loop through each sample in the batch
    for sample in batch:
        messages = [
           {"role": "system", "content": SYSTEM_PROMPT}, 
           {"role": "user", "content": sample["Article_title"]} 
        ]
        list_messages.append(messages) 

    # Use asyncio.gather to send requests to the LLM concurrently for all message sequences
    return await asyncio.gather(*[llm_engine(messages) for messages in list_messages])
```

```
from datasets import load_dataset, Dataset

def get_sample_batch(iterable_dataset, batch_size):
    batch = []
    try:
        for _ in range(batch_size):
            batch.append(next(iterable_dataset))
    except StopIteration:
        pass
    return batch

### 用 Argilla 复核预测

拿到 LLM 生成的标注数据后，下一步是精选一个高质量子集，确保对零样本、微调等各种方法的评估可靠。这份经过认真复核的数据集也将作为微调小模型的基础。LLM 标注的完整数据集也可以在 [弱监督](https://en.wikipedia.org/wiki/Weak_supervision)框架下用于微调。

***数据集抽样与划分***

为了得到适合复核的样本量，我们用 LLM 标签，并用 [rapidfuzz](https://rapidfuzz.github.io/RapidFuzz/) 库的 [模糊匹配](https://en.wikipedia.org/wiki/Approximate_string_matching)对公司名做聚类。我们应用 cdist 函数计算公司名之间的 Levenshtein 距离，以 85 为阈值聚类。每个聚类选出一个代表公司，Llama 的预测相应映射。最后，从每个公司相关聚类的新闻标题中抽样 5%，再从不含公司的标题中抽 5%，得到一个 2714 条样本的数据集。

然后利用元数据，把抽样后的数据集分成三部分：

- **Train**：2010 到 2016 年的新闻，用于训练小型 ML 模型——**2405 条样本**
- **Validation**：2017 到 2018 年的新闻，用于调超参——**204 条样本**
- **Test**：2019 到 2020 年的新闻，用于在未见过数据上评估模型——**105 条样本**

创建之后，我们搭好标注工具 [Argilla](https://argilla.io/) 来简化标注流程。

Argilla 是一个融入 Hugging Face 生态的开源工具，擅长为广泛的 AI 项目收集人类反馈。无论你做的是文本分类、NER 等传统 NLP 任务，是为检索增强生成（RAG）或偏好调优微调大语言模型（LLM），还是开发文生图这类多模态模型，Argilla 都提供了高效收集和精炼反馈所需的工具，确保你的模型基于高质量、人工校验的数据持续改进。

## 零样本方法在金融 NER 上的表现

有了高质量、经过复核的数据集，我们现在可以尝试不同的零样本 NER 方法。我们测试了四个模型：

**小语言模型：**

- GLINER
- SpanMarker **大语言模型（LLM）：**
- Llama-3.1-8b
- Llama-3.1-70b

- **GLiNER**

[GLiNER](https://arxiv.org/abs/2311.08526) 是一个紧凑、多面手的 NER 模型，利用 BERT 这类双向 transformer 识别广泛的实体类型，突破传统模型只能预定义实体的限制。与大型自回归模型不同，GLiNER 把 NER 当作"把实体类型与文本中的跨度匹配"的任务，并用并行处理保证效率。它是 LLM 务实且省资源的替代方案，在零样本场景下表现强劲，却没有大模型的高昂计算成本。

[![GliNER](https://huggingface.co/blog/assets/cfm-case-study/gliner.png)](https://huggingface.co/blog/assets/cfm-case-study/gliner.png)

*[原论文](https://arxiv.org/abs/2311.08526)中的 GLiNER 架构<*

GLiNER 提供三种模型变体：

- **GLiNER-Small-v2.1**（50M 参数）
- **GLiNER-Medium-v2.1**（90M 参数）
- **GLiNER-Large-v2.1**（0.3B 参数）

与 Llama-3.1-70b 这类 LLM 相比，GLiNER 模型更紧凑、更具性价比、NER 任务上更高效；LLM 通常灵活性更广，但体积大得多、也更耗资源。GLiNER medium 可在 Hugging Face Space 上试用：[https://huggingface.co/spaces/tomaarsen/gliner_medium-v2.1](https://huggingface.co/spaces/tomaarsen/gliner_medium-v2.1)。实验中我们聚焦一个特定的 GLiNER 变体 [EmergentMethods/gliner_medium_news-v2.1](https://huggingface.co/EmergentMethods/gliner_medium_news-v2.1)，它已在 [EmergentMethods/AskNews-NER-v0](https://huggingface.co/datasets/EmergentMethods/AskNews-NER-v0) 上微调过，旨在提升广泛主题的准确率，尤其是长上下文新闻实体识别抽取。使用 GLiNER 可安装基于 Hugging Face [transformers](https://huggingface.co/docs/transformers/en/index) 库的 `gliner` 包。

```
!pip install gliner
```

之后用 GLiNER 做 NER 很简单：

```
from gliner import GLiNER

model = GLiNER.from_pretrained("EmergentMethods/gliner_large_news-v2.1")

text = """
EMCOR Group Company Awarded Contract for Installation of Process Control Systems for Orange County Water District's Water Purification Facilities
"""

labels = ["company"] # Add other entities that you want to detect here

entities = model.predict_entities(text, labels, threshold=.5)
#threshold indicates the minimum probability the model should have for the returned entities.

for entity in entities:
    print(entity["text"], "=>", entity["label"])
```

**输出**

```
“EMCOR Group => company"
```

"Integra Eyes Orthopedics Company => company" #incorrect predictions, ground truth Integra
```

在前面整理的 2714 条标注数据集上，零样本 F1 分数为 **87%**。

GLiNER 模型很擅长从文本中提取公司名，但在某些情形下会犯难，例如公司以股票代码形式出现时；它还会把泛指股票行业的表述（如 "Healthcare stocks"、"Industrial stocks"）误判成公司名。虽然多数情况下有效，这些错误也指明了需要进一步打磨的地方，以便更好地区分公司与更宽泛的行业表述。

- **SpanMarker** [SpanMarker](https://github.com/tomaarsen/SpanMarkerNER) 是一个用 BERT、RoBERTa、DeBERTa 这类熟悉的编码器训练强 NER 模型的框架。它紧密构建在 🤗 Transformers 之上，能充分利用后者的能力；对熟悉 Transformers 的人来说，SpanMarker 用起来很顺手。我们选择这个变体 [tomaarsen/span-marker-bert-base-orgs](https://huggingface.co/tomaarsen/span-marker-bert-base-orgs)，它在 [FewNERD、CoNLL2003 和 OntoNotes v5](https://huggingface.co/datasets/tomaarsen/ner-orgs) 数据集上训练，可用于 NER。该 SpanMarker 模型以 [bert-base-cased](https://huggingface.co/bert-base-cased) 作为底层编码器，专训识别组织（organization），可以按如下方式推理预测 `ORG`（组织）标签：

```
from span_marker import SpanMarkerModel

# Download from the 🤗 Hub
model = SpanMarkerModel.from_pretrained("tomaarsen/span-marker-bert-base-orgs")
# Run inference
entities = model.predict("Enernoc Acquires Energy Response; Anticipates Deal Will Add to 2013 EPS")

for entity in entities:
    print(entity["span"], "=>", entity["label"])
```

输出：

```
“EMCOR Group => ORG" #correct predictions
"Energy Response => ORG" #incorrect 
```

在前面整理的 2714 条标注数据集上，零样本 F1 分数为 **47%**。SpanMarker 提取准确公司名表现不错，但倾向于识别出过多错误实体。这是因为它在更宽泛的 "organization" 类别上训练，该类别涵盖非营利组织、政府机构、教育机构和运动队等实体，因此有时会把它们与公司名混淆，导致过度抽取、某些语境下精度下降。

- **Llama3.1-8b 和 Llama3.1-70b**

我们测试了 Llama3.1 的两个变体，包括之前用于整理真值样例的 70b，并使用上文的提示词。在标注子集上的结果如下：

| *模型* | *[Llama 3.1 8b](https://huggingface.co/meta-llama/Llama-3.1-8B-Instruct)* | *[Llama 3.1 70b](https://huggingface.co/meta-llama/Llama-3.1-70B-Instruct)* |
| --- | --- | --- |
| *F1 分数* | 88% | 95% |

**性能小结**

| *模型* | *GLiNER* | *SpanMarker* | *[Llama 3.1 8b](https://huggingface.co/meta-llama/Llama-3.1-8B-Instruct)* | *[Llama 3.1 70b](https://huggingface.co/meta-llama/Llama-3.1-70B-Instruct)* |
| --- | --- | --- | --- | --- |
| *F1 分数* | 87% | 47% | 88% | **95%** |

这个实验对比了 **GLiNER**、**SpanMarker** 这类小模型与 **Llama 3.1-8b**、**Llama 3.1-70b** 这类 LLM 的表现。像 GLiNER（87% F1）这样的小模型在准确率与计算效率之间取得了良好平衡，适合资源受限的场景；而 LLM 虽然更耗资源，但准确率更高，Llama 3.1-70b 达到 95% F1。这凸显了 NER 任务中小模型与 LLM 之间性能与效率的取舍。接下来看看微调紧凑模型后表现有何不同。

## 用 LLM 辅助标注的数据集微调紧凑模型以提升性能

**微调**

使用先前创建的 train/validation/test 子集，我们在一台带单张 Nvidia A10 GPU 的 AWS 实例上微调 GLiNER 和 SpanMarker。GLiNER 的微调示例见[这里](https://github.com/urchade/GLiNER/blob/main/examples/finetune.ipynb)，SpanMarker 见[这里](https://github.com/tomaarsen/SpanMarkerNER/blob/main/notebooks/model_training.ipynb)。微调这些模型很简单，用按 [Hugging Face dataset](https://huggingface.co/docs/datasets/en/load_hub) 格式创建的 `train_dataset` 和 `valid_dataset` 跑下面代码即可。

```
import numpy as np

# calculate number of epochs 
batch_size = 4 
learning_rate=5e-6
num_epochs = 20 
model=GLiNER.from_pretrained("EmergentMethods/gliner_medium_news-v2.1")

        others_lr=1e-5, 					     # learning rate

        per_device_eval_batch_size=batch_size,    # Evaluation batch

        focal_loss_gamma=2,             # Focal loss gamma parameter

trainer = Trainer(

在这份更新后的对比中，我们按微调后的 F1 分数评估模型。**GLiNER-medium-news** 微调后从 87.0% 提升到 93.4%，准确率显著上涨；**SpanMarker** 同样从 47.0% 跃升到 90.1%，竞争力大增。与此同时，**Llama 3.1-8b** 和 **Llama 3.1-70b** 开箱即用就有不错的表现，未做微调分别为 80.0% 和 92.7%。这个对比说明：微调 GLiNER、SpanMarker 这样的小模型可以大幅提升性能，以更低的计算成本追平更大的 LLM。

## 弱监督 vs. LLM 辅助标注

这个实验中，我们探索了 NER 数据标注的两种主要方式：**弱监督**和**LLM 辅助标注**。弱监督能在合成数据上可扩展地训练，但我们的结论是：它达不到人工标注数据训练模型那样的准确率。以 1,000 条样本为例：人工标注花 3 小时，F1 分数 **0.915**；而 Llama 3.1-70b 推理只需 2 分钟，F1 略低，为 **0.895**。速度与准确率之间的取舍，取决于任务的要求。

[![Comparison](https://huggingface.co/blog/assets/cfm-case-study/comparison-graph.png)](https://huggingface.co/blog/assets/cfm-case-study/comparison-graph.png)

*弱监督 vs. LLM 辅助标注*

图表对比了 **GLiNER** 在人工标注数据与 **Llama-3.1 70b** 推理出的合成数据上微调的表现，横轴为不同数据集规模。蓝点代表人工标注数据训练模型的 F1 分数，红点代表 Llama-3.1 70b 推断数据的。随着数据规模增大，人工标注微调的模型持续领先，拿到更高的 F1 分数。这说明：虽然人工标注微调的准确率更高，**LLM 辅助标注**（使用 Llama-3.1 70b）仍有相当大的价值，尤其当人工标注资源有限时。LLM 推断数据的 F1 分数虽略低，在各种数据规模下仍保持竞争力。LLM 能快速生成海量标注，为高效扩展数据集提供了务实方案，在时间和成本约束关键的场景中特别有用。

## 结论

**我们的实验表明：像 Llama 3.1 这样的大模型虽然开箱即用表现更好，但用 LLM 辅助标注来微调 GLiNER、SpanMarker 这样的小模型能显著提升准确率，以几分之一的成本与 LLM 匹敌。这条路径说明，用 LLM 洞见投资微调小模型，为金融 NER 任务提供了一种成本友好、可扩展的方案，也是准确率与资源效率都至关重要的真实应用的首选。**
