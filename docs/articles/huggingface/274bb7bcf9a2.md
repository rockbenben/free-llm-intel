# DABStep：面向多步推理的数据智能体基准

Alex Egg（eggie5）、Martin Iglesias Goyanes（martinigoyanes）、Friso Kingma（frisokingma）、Andreu Mora（andreumora）、Leandro von Werra（lvwerra）、Thomas Wolf（thomwolf）、Aymeric Roucher（m-ric）

语言模型的能力越来越强，能够作为智能体（agent）自主完成任务。有令人兴奋的诸多用例，尤其是在推理、代码与数据的交叉地带。然而，针对真实问题的合适评测基准仍然缺位，拖慢了该领域的进展。

为应对这一挑战，Adyen 与 Hugging Face 联合构建了面向多步推理的数据智能体基准（Data Agent Benchmark for Multi-step Reasoning，DABstep）。DABstep 包含 450 多个数据分析任务，用于评估最先进 LLM 和 AI 智能体的能力。

> 我们的发现表明，DABstep 对当前 AI 模型构成了重大挑战，最先进的基于推理的智能体也只达到 16% 的准确率，凸显出该领域仍有可观的进步空间。

DABstep 要求 AI 模型：

- 深入数据细节并保持严谨（不得幻觉）
- 在自由文本和数据库之上进行推理
- 对接现实生活用例（不只是数学或代码）

在这篇博客中，我们会介绍该基准的设计与构建、分析评测结果，并讨论当前模型与有效解决复杂数据分析任务能力之间的显著差距。

## 动机

数据分析既是一门艺术也是一门科学，需要技术能力、领域知识和创造力，因此它很少是直截了当的。即便是经验丰富的数据分析师也会面临这样的挑战：

- **简单但耗时的任务**：哪怕只是小任务，数量一多，就把 straightforward 的分析变成几小时的重复劳动。
- **复杂上下文与高认知负荷**：有些任务要求分析师在错综复杂的领域专属知识之间来回权衡，既耗时又耗神。例如，(1) 阅读分散、嵌套且复杂的文档；(2) 分析数据；(3) 对结果进行推理；最后给出能够指引业务方向的建议。
- **技术功底**：只要数据可用性高、质量高、开箱即用，分析数据本可以很简单。可惜现实很少如此，分析师需要有足够的技术深度去搭建消费、转换和提供数据的管道。数据分析师常常承担本属于数据工程的活儿。

在 Adyen 这样的公司里，分析师要处理的问题跨度很大，从日常查询到需要创造力、精确度和迭代推理的复杂工作流。要是有个能干的数据分析智能体，能自动化简单重复的任务、并在复杂任务上提供协助，分析师就能工作得更快、减轻心智负担、专注于解决更有影响力的问题。那对许多需要数据分析和洞察的行业（比如金融）都将是一个关键转折点。

近期 *agentic workflows*（智能体工作流）的进展——装备了工具的 LLM 独立执行多步任务——在编码、[开放问答](https://openai.com/index/introducing-deep-research/)、[软件工程](https://www.swebench.com)乃至 [Kaggle 竞赛](https://openai.com/index/mle-bench/) 等诸多领域都展现出巨大潜力。这些系统不只是理论上的，它们已经在驱动真实世界的生产力提升。

于是问题就变成了：**智能体工作流能否重塑我们做数据分析的方式？**

## 介绍 DABstep

机器学习的进步由高质量基准推动，因为它们能给出可靠的进展信号。因此，我们很高兴推出面向多步推理的数据智能体基准（DABstep），一个用于评估和推进数据分析中智能体工作流的新基准。

DABstep 的独特之处在于：

- **真实世界用例**：基于从 Adyen 实际工作负载中抽取的 450 多个真实任务。这些任务不是合成的玩具题；它们反映的是分析师每天面对的挑战，使 DABstep 区别于 DS-1000 或 DS Bench 等其他基准 [^1]。
- **兼顾结构化与非结构化数据**：这些任务需要高阶的数据分析技巧，既能驾驭结构化数据，又能理解非结构化数据中的多个数据集与文档。
- **搭建简单**：与 SWE-bench 或 MLE-bench 这类需要复杂配置的基准不同，DABstep 用起来很简单。用模型生成答案只需要一个代码执行环境，参赛者可以直接向排行榜提交答案、自动完成评测。
- **事实型评测**：任务被设计成可客观评估，因此任务输出的评估总能对应到一个二元结果——对或错——无需解读。
- **多步复杂度**：DABstep 在从日常查询到多步迭代工作流的整个分析任务谱系上测试系统。与只关注孤立问题的基准不同，DABstep 要求模型在多样、实际的任务上进行端到端的智能体推理。

DABstep 是如何做到这一切、同时保持易于运行的？来看看它的设计。

## DABstep 里有什么

DABstep 的设计兼顾低门槛使用、优质评测和递增的难度等级。为此，我们把以下内容作为 DABstep 的一部分开源：数据集（Datasets）、任务（Tasks）、评测（Evals）、实时排行榜（Real-time Leaderboard）和基线（Baselines）。

### 数据

分析师在处理真实问题时最大的挑战之一，是在领域知识和技术技能之间取得平衡。为此，DABstep 同时包含非结构化数据和结构化数据，分别用来衡量领域知识和技术技能。

表 1 展示了我们随基准发布的部分数据集的快照。

| 名称 | 说明 |
| --- | --- |
| payments.csv | 包含 13.8 万笔（已脱敏）交易的支付数据集，带各种与欺诈和风险用例相关的信号。 |
| payments-readme.md | Payments 数据集的文档 |
| acquirer_countries.csv | 收单银行及其所属国家对照表 |
| fees.json | 由 1000 套卡组织费率结构组成的详尽数据集。 |
| merchant_category_codes.csv | 商户类别码（MCC）对照表 |
| merchant_data.json | 描述商户的表 |
| manual.md | 在金融领域，业务背景通常由卡组织、监管机构和处理机构发布的大部头手册来界定。在本基准的第一版中，我们创建了一个 markdown 文件（manual.md），把核心业务知识提炼成既精确又简化的格式，以便准确地完成任务。 |

*表 1：基准由跨多种任务的多个数据集构成，涵盖金融支付领域*

其中一些结构化数据集是表示真实世界数据的 CSV 和 JSON 文件，例如交易遥测数据和业务元数据（如商户类别码）。此外还有非结构化数据，如文档、冗长的手册以及由卡组织、监管机构和处理机构发布的详尽手册。

所有这些数据集都来自 Adyen 的真实任务。

### 任务

基于 DABstep 中包含的新数据集，我们发布了若干难度递增的任务，用以测试 AI 智能体的准确率。

每个任务包含以下条目：

- 一个向分析师提出挑战的 **问题（question）**。
- 一个体现任务难度的 **等级（level）**。
- 一份 **指南（guidelines）**，说明如何组织答案以满足事实型评测的规范。

没有任何一个任务能用一段代码搞定；换句话说，它们无法仅凭推理解决，而需要一步步的迭代式问题求解。例如，至少智能体必须知道对应数据集里有哪些列才能回答问题。这与 GAIA、MATH、SimpleQA 等流行基准形成对比——在那些基准里，不少问题可以靠一段代码一次性正确作答。

图 1 展示了两个示例任务，图 2 展示了一个人工编写的参考解。

| 名称 | 说明 |
| --- | --- |
| **问题：** 2023 年哪家卡组织的平均欺诈率最高？  **指南：** 答案必须是卡组织名称。  *[LLM/Agent Loop…]*  **答案：** SwiftCharge | **问题：** 针对 2023 年，聚焦商户 Crossfit Hanna，如果我们想通过激励手段鼓励用户切换到另一种授权特征指示符（Authorization Characteristics Indicator）以减少欺诈交易，那么基于最低费用，哪个选项最具性价比？  **指南：** 答案必须是所选的 ACI 及对应费用，保留两位小数，格式为：{card_scheme}:{fee}。  *[LLM/Agent Loop…]*  **答案：** E:346.49 |

#### 等级

基准由两个难度等级组成：

- **Easy 级**：这些任务当作热身用，帮助验证配置、集成和研究方向。它们通常只需要单个结构化数据集和最少量的背景知识。人类在 3 小时以上的工作后平均能达到 62% 的基线，而 Llama 70B 的零样本提示可以超过 90% 的准确率。
- **Hard 级**：这些任务要求更复杂的方法，涉及多个结构化数据集和领域专属知识。不同于 Easy 级，它们通常无法用一次代码生成解决，需要多步推理。

作为一个多步推理问题的例子，下面这段代码展示了某个 Hard 级任务人工参考解的片段。整体被分解为四（4）个顺序步骤，包括开发各种辅助宏。要写出这个解，智能体必须具备特定的领域知识，以及按顺序进行迭代推理的能力。

*图 2：Hard 集中某问题的 220 行参考解："如果商户 {merchant} 在 2023 年初之前把其 MCC 码切换为 {target_mcc}，那么 2023 年他们需要支付的费用会有多大差异？" 该解需要多步归纳推理，对一次性代码生成来说很难。*

#### 泛化

一些关于我们如何希望通过该基准鼓励泛化的简短说明。

**符号推理（Symbolic Reasoning）：** 沿着 [GSM-Symbolic](https://arxiv.org/abs/2410.05229) 的思路，任务通过时间范围、商户名等的排列组合在数量上做了扩展。其道理在于排除"碰巧猜对"的可能，验证核心推理（推理的可重复性）和泛化。

**隐藏测试集：** 我们选择不把数据集划分为验证集和测试集，只发布一个留出的测试集。这是因为一个数据分析师智能体应当能在各种分析任务上泛化，而不仅仅局限于本版本基准所覆盖的任务。

**Dev 集：** 鉴于这种严格的泛化设定、基准的规模（450 题），以及出于对开发者友好的考虑，我们也发布了一个 dev 集，它是完整测试集的一个有代表性的子集，并包含答案。这个 dev 集的精神在于让研究者在本地配置好端到端的提交流水线，包括评测和快速反馈回路，然后再正式提交到排行榜。

要测试广泛的泛化，不应只拿 DABstep 单独作基准，而应把它和测试整体泛化与问题求解能力的其他基准（如 MMLU、SuperGlue、GPQA）结合来看。

### 评测

为简单起见，我们选择了基于事实型答案的评估系统。这意味着对基准问题的答案应当是简单的词、数字或多选题组合。这使得评测可以无偏、可扩展且不依赖模型。（这与由评判 LLM 评估自然语言答案提交的做法相反。）

据此，我们并不想让答案格式成为基准的焦点。为此，我们实现了一套灵活的评估方法，确保焦点始终在答案的准确性而非其格式上。举例来说，我们用自适应容差来比较数值，允许精度和格式上的差异；字符串经过归一化后用带相似度阈值的模糊匹配比较；列表则在归一化后逐元素评估。

## 快速上手与基础设施

我们清楚，通过与基准交互来做智能体研究需要一个执行环境，并涉及成本。我们通过提供 HuggingFace 的 **Inference API** 和 [**smolagents**](https://huggingface.co/docs/smolagents/en/index) 的访问来降低门槛。有了这些工具，研究者每天可获得 **1000 次免费 LLM 请求**，并接入一个**安全的本地代码执行环境**。

为了方便，我们提供了一个**示例 notebook**：一个零成本提交参赛方案的现成解（[quickstart.ipynb](https://colab.research.google.com/drive/1pXi5ffBFNJQ5nn1111SnIfjfKCOlunxu)）。

通过消除摩擦，DABstep 确保任何人——从资深研究者到好奇的新人——都能为推进数据分析中的智能体工作流做出贡献。

## 未来方向

我们对 DABstep 的发布非常兴奋，认为它将有助于检验当下数据分析智能体的水平。不过，这次发布只是第一步，我们计划随时间演进这个基准。

以 AI 的进步速度看，我们预计基准在现有形态下终将被视为"已解决"。然而，基准通过在多个维度上增加难度，被设计成能在更长时间里保持有效。我们会在保持完全向后兼容的前提下为基准添砖加瓦。下面是我们改进基线的一些大致方向。

**任务：** 当前任务范围很窄，主要涵盖欺诈和支付费用。这只是真实世界的一个子集，现实中还有许多其他维度和变量在起作用。未来，我们会在同一基准上扩展任务，涵盖批准率（发卡行拒绝）、认证流失，以及跨越更长时间窗口（如季节性分量）的实时情形。这会考验智能体同时权衡多个变量、并在多个维度上执行取舍的能力。

**领域：** 基准目前围绕金融领域的任务。但我们邀请来自健康、生物、保险、电信等其他领域的研究者和从业者为本基准贡献新的子集，以便我们在众多领域上评估性能。

**数据规模：** 结构化数据最终将无法装入内存。它们将用标准工具来分析，要求分析师使用分布式计算引擎或调度工作流以便后续评估。

**文档：** 映射领域知识的非结构化数据将爆炸式增长，包含更多带时间演化的文件（如公告）、不同格式（如 PDF），以及针对不同卡组织、收单行或合作伙伴的相似但不同的逻辑的各种版本。上下文将增长到在逻辑上无法塞进当前和未来上下文窗口所允许的 token 规模。

**多模态：** 智能体也应变得多模态。为此，我们会用需要解读并创建图表、图形来提取逻辑的任务来增强基准。

## 相关工作

评估 AI 数据分析的现有基准已经推动了该领域发展，DABstep 正是建立在这些基础之上。

DS Bench 评估了来自 Modeloff 竞赛的 466 个问题，主要为基于 Excel 的工作流设计。虽然对小规模任务有效，但 Excel 并不支持真实数据分析中常见的迭代式、代码驱动的工作流（例如 Jupyter notebook）。此外，依赖 GPT-4 作为评估者会引入偏置、降低泛化性。

DS 1000 测试来自 StackOverflow 的 Python 数据分析任务，经过精心挑选以避免死记硬背。但其任务简短且是一次性的，缺乏真实数据集和迭代推理。这限制了它评估端到端工作流或多模态能力的本领。
