# Hugging Face Inference Endpoints 入门

训练机器学习模型已变得相当简单，尤其是随着预训练模型和迁移学习的兴起。好吧，有时确实没那么*简单*，但至少训练模型不会搞垮关键应用、让客户对你的服务质量不满。部署模型嘛……是的，我们都经历过。

把模型部署到生产环境通常要跳过一连串"火圈"：把模型打包进容器、准备基础设施、创建预测 API、保护它、扩展它、监控它等等。说实话：搭建所有这些管线会占用做实际机器学习工作的宝贵时间。而且不幸的是，还很容易出大问题。

我们正努力用新推出的 Hugging Face [Inference Endpoints](https://huggingface.co/inference-endpoints) 解决这个问题。本着让机器学习更简单同时不牺牲最先进质量的精神，我们构建了这样一个服务：直接从 [Hugging Face hub](https://huggingface.co) 把模型在几次点击内部署到你心仪云上的托管基础设施。简单、安全、可扩展：你全都能拥有。

让我演示一下它如何工作！

### 在 Inference Endpoints 上部署模型

查看了 Inference Endpoints 支持的[任务](https://huggingface.co/docs/inference-endpoints/supported_tasks)列表后，我决定部署一个我最近用 [AutoTrain](https://huggingface.co/autotrain) 在 [food101](https://huggingface.co/datasets/food101) 数据集上微调的 Swin 图像分类模型。如果你好奇这个模型是怎么构建的，这个[视频](https://youtu.be/uFxtl7QuUvo)会展示整个过程。

从我的[模型页](https://huggingface.co/juliensimon/autotrain-food101-1471154053)出发，我点击 `Deploy` 并选择 `Inference Endpoints`。

这会直接把我带到 [endpoint 创建](https://ui.endpoints.huggingface.co/new)页面。

我决定把模型的最新版本部署在单 GPU 实例上，托管于 AWS 的 `eu-west-1` 区域。作为可选项，我可以配置自动扩缩，甚至可以在[自定义容器](https://huggingface.co/docs/inference-endpoints/guides/custom_container)中部署模型。

接下来，我需要决定谁能访问我的 endpoint。按安全性从低到高，有三种选项：

- **Public（公开）**：endpoint 运行在公开的 Hugging Face 子网中，互联网上任何人都可以在无认证的情况下访问它。选择前请三思！
- **Protected（受保护）**：endpoint 运行在公开的 Hugging Face 子网中，互联网上持有相应组织 token 的人可以访问它。
- **Private（私有）**：endpoint 运行在私有的 Hugging Face 子网中，互联网上不可访问。它只能通过用 [AWS PrivateLink](https://aws.amazon.com/privatelink/) 创建的 VPC Endpoint 在你的 AWS 账号内访问。你可以控制 AWS 账号中哪些 VPC 和子网有权访问该 endpoint。

我们先部署一个受保护的 endpoint，然后再部署一个私有 endpoint。

### 部署受保护的 Inference Endpoint

我只需选择 `Protected` 并点击 `Create Endpoint`。

几分钟后，endpoint 就已运行，并且能看到它的 URL。

我可以通过在推理小部件中上传一张[图片](https://huggingface.co/blog/assets/109_inference_endpoints/food.jpg)立即测试。

当然，我也可以直接用几行 Python 代码调用该 endpoint，认证使用我的 Hugging Face API token（你可以在 hub 的账号设置中找到自己的 token）。

```
import requests, json

API_URL = "https://oncm9ojdmjwesag2.eu-west-1.aws.endpoints.huggingface.cloud"

headers = {
  "Authorization": "Bearer MY_API_TOKEN",
  "Content-Type": "image/jpg"
}

def query(filename):
    with open(filename, "rb") as f:
        data = f.read()
    response = requests.request("POST", API_URL, headers=headers, data=data)
    return json.loads(response.content.decode("utf-8"))

output = query("food.jpg")
```

### 部署私有 Inference Endpoint

重复上述步骤，这次我选择 `Private`。

这会打开一个新的输入框，要求填写该 endpoint 将可见于其中的 AWS 账号标识符。我输入相应的 ID 并点击 `Create Endpoint`。

不确定自己的 AWS 账号 id？给你一个 AWS CLI 一行命令：`aws sts get-caller-identity --query Account --output text`

几分钟后，Inference Endpoints 界面显示出 VPC 服务名称。我的是 `com.amazonaws.vpce.eu-west-1.vpce-svc-07a49a19a427abad7`。

接下来，我打开 AWS 控制台，进入 [VPC Endpoints](https://console.aws.amazon.com/vpc/home?#Endpoints:) 页面，点击 `Create endpoint` 创建一个 VPC endpoint，使我的 AWS 账号能通过 AWS PrivateLink 访问我的 Inference Endpoint。

简而言之，我需要填入上面显示的 VPC 服务名称，选择允许访问该 endpoint 的 VPC 与子网，并附加一个合适的安全组。没什么可怕的：只需照着 [Inference Endpoints 文档](https://huggingface.co/docs/inference-endpoints/guides/private_link)列出的步骤做。
