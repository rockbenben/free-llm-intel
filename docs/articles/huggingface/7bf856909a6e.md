# Falcon 降临 Hugging Face 生态系统

Falcon 是由阿布扎比的 [Technology Innovation Institute](https://www.tii.ae/) 创建的一族最先进语言模型，以 Apache 2.0 许可证发布。**值得一提的是，[Falcon-40B](https://huggingface.co/tiiuae/falcon-40b) 是第一个在能力上可与当前众多闭源模型匹敌的"真正开放"模型**。这对从业者、爱好者和行业都是绝佳消息，它为许多令人兴奋的用例打开了大门。

*注：本次发布几个月后，Falcon 团队推出了 1800 亿参数的更大模型（[180 billion parameters](https://huggingface.co/blog/falcon-180b)）。*

2023 年 9 月更新：

Falcon 180B 刚刚发布！它是目前规模最大的开放模型，可与 PaLM-2 等专有模型抗衡。

在这篇博客中，我们将深入了解 Falcon 模型：先讨论它独特在哪里，然后**展示如何基于 Hugging Face 生态的工具在它之上构建（推理、量化、微调等）**。

## Falcon 模型

Falcon 家族由两个基础模型组成：[Falcon-40B](https://huggingface.co/tiiuae/falcon-40b) 和它的弟弟 [Falcon-7B](https://huggingface.co/tiiuae/falcon-7b)。**40B 参数模型发布时登顶 [Open LLM Leaderboard](https://huggingface.co/spaces/HuggingFaceH4/open_llm_leaderboard)，7B 模型则是同体重级里最强的**。

*注：下表中的性能分数已按 2023 年 11 月启用的新评估方法（新增基准）更新，详情见[这篇文章](https://huggingface.co/blog/open-llm-leaderboard-drop)。*

Falcon-40B 需要约 90GB 显存——很多，但仍比它超越的 LLaMA-65B 少。另一边，Falcon-7B 只需约 15GB，推理和微调在消费级硬件上都可及。*（博客后面我们会讨论如何用量化让 Falcon-40B 在更便宜的 GPU 上也能跑！）*

TII 还发布了模型的 instruct 版本：[Falcon-7B-Instruct](https://huggingface.co/tiiuae/falcon-7b-instruct) 和 [Falcon-40B-Instruct](https://huggingface.co/tiiuae/falcon-40b-instruct)。这些实验性质的变体在指令与会话数据上做了微调，因此更适合流行的助手型任务。**如果你只想快速上手玩模型，它们是首选。**你也可以基于社区制作的众多数据集构建自己的 instruct 版本——接着看分步教程！

Falcon-7B 和 Falcon-40B 分别在 1.5 万亿和 1 万亿 token 上训练，符合当下优化推理的模型风格。**Falcon 高质量的关键配方是它的训练数据——其中超过 80% 基于 [RefinedWeb](https://arxiv.org/abs/2306.01116)，一个基于 CommonCrawl 构建的新型海量网络数据集**。TII 没有东拼西凑零散的精选来源，而是专注于扩大网络数据的规模并提升其质量，借助大规模去重和严格过滤来达到其他语料的水准。Falcon 的训练中仍包含一些精选来源（比如来自 Reddit 的会话数据），但比 GPT-3、PaLM 这类最先进 LLM 常见的比例低得多。最好的部分？TII 已公开发布了 [RefinedWeb](https://huggingface.co/datasets/tiiuae/falcon-refinedweb) 的 6000 亿 token 抽取版本，供社区在自己的 LLM 中使用！

Falcon 模型另一个有趣的特性是使用了 [**multiquery attention**](https://arxiv.org/abs/1911.02150)（多查询注意力）。普通的多头注意力每个头各有一组 query、key、value；multiquery 则让所有头共享同一组 key 和 value。

| [![mqa](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/147_falcon/multi-query-attention.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/147_falcon/multi-query-attention.png) |
| --- |
| **Multi-Query Attention 让所有注意力头共享 key 和 value 嵌入。图源 Harm de Vries。** |

## 推理

你可以使用熟悉的 transformers API 在自己的硬件上运行模型，但要注意几个细节：

- 模型用 `bfloat16` 数据类型训练，所以我们建议你也用它。这需要较新版本的 CUDA，在现代显卡上效果最好。你也可以尝试用 `float16` 推理，但要记住模型是用 `bfloat16` 评估的。
- 你需要允许远程代码执行。因为模型用了一个还未并入 `transformers` 的新架构——所需代码由模型作者在仓库中提供。具体来说，如果允许远程执行，会用到这些文件（以 `falcon-7b-instruct` 为例）：[configuration_RW.py](https://huggingface.co/tiiuae/falcon-7b-instruct/blob/main/configuration_RW.py)、[modelling_RW.py](https://huggingface.co/tiiuae/falcon-7b-instruct/blob/main/modelling_RW.py)。

带着这些注意事项，你可以用 transformers 的 `pipeline` API 加载 7B 指令模型：

```
from transformers import AutoTokenizer
import transformers
import torch

model = "tiiuae/falcon-7b-instruct"

tokenizer = AutoTokenizer.from_pretrained(model)
pipeline = transformers.pipeline(
    "text-generation",
    model=model,
    tokenizer=tokenizer,
    torch_dtype=torch.bfloat16,
    trust_remote_code=True,
    device_map="auto",
)
```

然后，用类似下面的代码跑文本生成：

```
sequences = pipeline(
   "Write a poem about Valencia.",
    max_length=200,
    do_sample=True,
    top_k=10,
    num_return_sequences=1,
    eos_token_id=tokenizer.eos_token_id,
)
for seq in sequences:
    print(f"Result: {seq['generated_text']}")
```

你可能会得到类似这样的结果：

```
Valencia, city of the sun
The city that glitters like a star
A city of a thousand colors
Where the night is illuminated by stars
Valencia, the city of my heart
Where the past is kept in a golden chest
```

### Falcon 40B 的推理

跑 40B 模型的难点在体积：它装不进单块 80GB 的 A100。以 8-bit 模式加载，可以在约 45GB 内存内运行——A6000（48GB）放得下，但 40GB 版的 A100 放不下。方法如下：

```
from transformers import AutoTokenizer, AutoModelForCausalLM
import transformers
import torch

model_id = "tiiuae/falcon-40b-instruct"

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.bfloat16,
    trust_remote_code=True,
    load_in_8bit=True,
    device_map="auto",
)

pipeline = transformers.pipeline(
    "text-generation",
    model=model,
    tokenizer=tokenizer,
)
```

注意，混合 8-bit 推理会用 `torch.float16` 而不是 `torch.bfloat16`，所以务必充分测试效果。

如果你有多张卡且装了 `accelerate`，可以利用 `device_map="auto"` 把模型层自动分布到各卡上。必要时它甚至能把一些层卸载到 CPU，但会拖慢推理速度。

还可以用最新版的 `bitsandbytes`、`transformers` 和 `accelerate` 进行 [4-bit 加载](https://huggingface.co/blog/4bit-transformers-bitsandbytes)。这种情况下 40B 模型运行约需 27GB 内存。可惜这比 3090、4090 这类卡的显存略多一点，但在 30 或 40GB 的卡上够用。

### Text Generation Inference

[Text Generation Inference](https://github.com/huggingface/text-generation-inference) 是 Hugging Face 开发的生产级推理容器，让大语言模型的部署更轻松。

主要特性：

- 连续批处理
- 用 Server-Sent Events (SSE) 做 token 流式输出
- 多 GPU 上更快的张量并行推理
- 用自定义 CUDA kernel 优化 transformers 代码
- 通过 Prometheus 与 Open Telemetry 提供生产级的日志、监控与追踪

自 v0.8.2 起，Text Generation Inference 原生支持 Falcon 7B 和 40B 模型，不再依赖 Transformers 的 "trust remote code" 特性，让部署更严密、便于安全审计。此外，Falcon 的实现包含自定义 CUDA kernel，显著降低端到端延迟。

| [![tgi-hfe-screenshot.png](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/147_falcon/tgi-hfe.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/147_falcon/tgi-hfe.png) |
| --- |
| **Inference Endpoints 现已支持 Text Generation Inference。在 1xA100 上用 Int-8 量化轻松部署 Falcon 40B Instruct 模型** |

Text Generation Inference 已集成进 Hugging Face 的 [Inference Endpoints](https://huggingface.co/inference-endpoints)。要部署 Falcon 模型，进入[模型页](https://huggingface.co/tiiuae/falcon-7b-instruct)，点击 [Deploy -> Inference Endpoints](https://ui.endpoints.huggingface.co/new?repository=tiiuae/falcon-7b-instruct) 组件即可。

7B 模型，我们建议选 "GPU [medium] - 1x Nvidia A10G"。

40B 模型，你需要部署在 "GPU [xlarge] - 1x Nvidia A100" 并启用量化：Advanced configuration -> Serving Container -> Int-8 Quantization。*注：可能需要向 [api-enterprise@huggingface.co](mailto:api-enterprise@huggingface.co) 申请提升配额。*

## 评估

那 Falcon 到底有多强？Falcon 作者的深度评估即将发布，我们先把基础和 instruct 模型跑了一遍我们的 [open LLM benchmark](https://huggingface.co/spaces/HuggingFaceH4/open_llm_leaderboard)。该基准在以下领域度量 LLM 的推理能力与给出真实回答的能力：

- [AI2 Reasoning Challenge](https://allenai.org/data/arc)（ARC）：小学科学多选题。
- [HellaSwag](https://arxiv.org/abs/1905.07830)：围绕日常事件的常识推理。
- [MMLU](https://github.com/hendrycks/test)：57 个学科（专业与学术）的多选题。
- [TruthfulQA](https://arxiv.org/abs/2109.07958)：考察模型把事实从对抗性挑选的错误陈述集合中分辨出来的能力。

结果显示，40B 基础与 instruct 模型非常强劲，目前在 [LLM leaderboard](https://huggingface.co/spaces/HuggingFaceH4/open_llm_leaderboard) 上分列第一和第二 🏆！

## 用 PEFT 微调

训练 10B+ 规模的模型在技术和算力上都不轻松。本节我们看看 Hugging Face 生态里有哪些工具能在简单硬件上高效训练超大模型，并演示如何用单张 NVIDIA T4（16GB——Google Colab）在自定义数据上微调 Falcon-7B。

我们来看看如何用 [Guanaco 数据集](https://huggingface.co/datasets/timdettmers/openassistant-guanaco)——[Open Assistant 数据集](https://huggingface.co/datasets/OpenAssistant/oasst1)的一个高质量子集，约 1 万段对话——训练 Falcon。借助 [PEFT 库](https://github.com/huggingface/peft)，我们可以用最新的 [QLoRA](https://arxiv.org/abs/2305.14314) 方法在冻结的 4-bit 模型上微调适配器。关于 4-bit 量化模型的集成，可阅读[这篇博文](https://huggingface.co/blog/4bit-transformers-bitsandbytes)。

由于使用低秩适配器（LoRA）时只有模型极小一部分可训练，需要学习的参数量和训练产物的大小都大幅缩减。如下图所示，保存的模型只有 65MB——对比 7B 参数模型本身（半精度约 15GB）。

| [![repo-screenshot.png](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/147_falcon/adapter-screenshot.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/147_falcon/adapter-screenshot.png) |
| --- |
| **最终仓库只有 65MB 权重——对比原始模型约 15GB 的半精度体积** |

更具体地说，选好要适配的目标模块（通常是注意力模块的 query/key 层）后，小的可训练线性层会被挂到这些模块旁边，如下图示意。适配器产生的隐藏状态随后与原状态相加，得到最终隐藏状态。

| [![lora-gif](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/lora-animated.gif)](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/lora-animated.gif) |
| --- |
| **原始（冻结）预训练权重的输出激活（左）由一个低秩适配器增强，该适配器由权重矩阵 A 和 B 组成（右）。** |

训练完成后，无需保存整个模型——底座模型保持冻结。另外，只要这些模块输出的隐藏状态被转换成与适配器相同的 dtype，就可以让模型保持任意 dtype（int8、fp4、fp16 等）——bitsandbytes 模块（`Linear8bitLt` 和 `Linear4bit`）正是如此，它们返回的隐藏状态与未量化原始模块的 dtype 一致。

我们在 Guanaco 数据集上微调了 Falcon 的两种变体（7B 和 40B）。7B 模型在单张 NVIDIA-T4 16GB 上微调，40B 模型在单张 NVIDIA A100 80GB 上微调。我们使用 4bit 量化的底座模型与 QLoRA 方法，以及 [TRL 库最新的 `SFTTrainer`](https://huggingface.co/docs/trl/main/en/sft_trainer)。

复现实验的完整脚本文 [这里](https://gist.github.com/pacman100/1731b41f7a90a87b457e8c5415ff1c14)，但只想快速跑起来 `SFTTrainer`（为简洁起见不用 PEFT）只需要几行代码：

```
from datasets import load_dataset
from trl import SFTTrainer
from transformers import AutoTokenizer, AutoModelForCausalLM

dataset = load_dataset("imdb", split="train")

model_id = "tiiuae/falcon-7b"

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id, trust_remote_code=True)

trainer = SFTTrainer(
    model,
    tokenizer=tokenizer,
    train_dataset=dataset,
    dataset_text_field="text",
    max_seq_length=512,
)
trainer.train()
```

关于评估训练好的模型，参见 [qlora 原始仓库](https://github.com/artidoro/qlora/) 的更多细节。
