Llama 3.2 来了！今天，[Llama 系列](https://huggingface.co/collections/meta-llama/llama-32-66f448ffc8c32f949b04c8cf)的下一代产品正式登陆 Hugging Face。这一次，我们很高兴与 Meta 在多模态和小模型上联合发布。十个开放权重模型（5 个多模态模型和 5 个纯文本模型）已在 Hub 上提供。

Llama 3.2 Vision 有两种尺寸：11B 适合在消费级 GPU 上高效部署和开发，90B 适合大规模应用。两个版本都有 base 和指令微调变体。除了四个多模态模型，Meta 还发布了支持视觉的新版 Llama Guard。Llama Guard 3 是一个安全防护模型，可以对模型输入和生成内容分类，包括检测有害的多模态提示词或助手回复。

Llama 3.2 还包括能在设备上运行的小型纯文本语言模型。它们有两个新尺寸（1B 和 3B），各有 base 和 instruct 变体，并且在同尺寸中能力很强。此外还有一个小型 1B 版 Llama Guard，可以在生产场景中与小模型或更大的文本模型搭配部署。

本次发布的特性和集成包括：

- [Hub 上的模型 checkpoints](https://huggingface.co/collections/meta-llama/llama-32-66f448ffc8c32f949b04c8cf)
- 面向 Vision 模型的 [Hugging Face Transformers](https://huggingface.co/docs/transformers/v4.45.1/en/model_doc/mllama) 和 TGI 集成
- 与 Inference Endpoints、Google Cloud、Amazon SageMaker 和 DELL Enterprise Hub 的推理与部署集成
- 用 [transformers🤗](https://github.com/huggingface/huggingface-llama-recipes/blob/main/fine_tune/Llama-Vision%20FT.ipynb) 和 [TRL](https://github.com/huggingface/huggingface-llama-recipes/blob/main/fine_tune/sft_vlm.py) 在单卡 GPU 上微调 Llama 3.2 11B Vision

## 什么是 Llama 3.2 Vision？

Llama 3.2 Vision 是 Meta 发布的最强开放多模态模型。它有很强的视觉理解与推理能力，可以完成多种任务，包括视觉推理与定位（grounding）、文档问答和图文检索。它的思维链（Chain of Thought，CoT）答案通常非常好，让视觉推理尤其强大。

Llama 3.2 Vision 既能处理文本加图像，也能只处理文本。图文提示时模型接受英文输入；纯文本提示时模型支持多种语言。

纯文本模式支持的完整语言列表：

- 英语
- 德语
- 法语
- 意大利语
- 葡萄牙语
- 印地语
- 西班牙语
- 泰语

这些模型的架构是 Llama 3.1 LLM 组合一个视觉塔（vision tower）和一个图像适配器（image adapter）。其中 Llama 3.2 11B Vision 模型使用的文本模型是 Llama 3.1 8B，90B Vision 模型用的是 Llama 3.1 70B。据我们理解，训练视觉模型时文本模型是冻结的，以保留纯文本性能。

视觉模型的上下文长度为 128k token，允许多轮包含图像的对话。不过模型在只关注单张图像时效果最好，因此 `transformers` 实现只关注输入中提供的最后一张图像。这既保证质量又节省内存。

11B base 模型支持 448 的 tile 尺寸，而 instruct 版本和 90B 模型都使用 560 的 tile 尺寸。这些模型在 60 亿图文对构成的巨大数据集上训练，数据配比多样。这使它们成为下游任务微调的绝佳候选。作为参考，下面是 Meta 报告的 11B、90B 及其指令微调版本在部分基准上的对比。更多基准和细节请查看模型卡。

|  | 11B | 11B（指令微调） | 90B | 90B（指令微调） | 指标 |
| --- | --- | --- | --- | --- | --- |
| MMMU (val) | 41.7 | 50.7 (CoT) | 49.3 (zero-shot) | 60.3 (CoT) | Micro Average Accuracy |
| VQAv2 | 66.8 (val) | 75.2 (test) | 73.6 (val) | 78.1 (test) | Accuracy |
| DocVQA | 62.3 (val) | 88.4 (test) | 70.7 (val) | 90.1 (test) | ANLS |
| AI2D | 62.4 | 91.1 | 75.3 | 92.3 | Accuracy |

我们预计这些模型的文本能力分别与 8B 和 70B 的 Llama 3.1 模型相当，因为我们理解训练 Vision 模型时文本模型是冻结的。因此文本基准应与 8B、70B 保持一致。

## Llama 3.2 1B 和 3B 有什么特别之处？

Llama 3.2 系列包含 1B 和 3B 文本模型。这些模型面向设备端用例设计，比如提示词改写、多语言知识检索、摘要任务、工具使用，以及在本地运行的助手。它们的表现超过许多同尺寸的开放访问模型，甚至能与体积大得多一倍的模型竞争。在后文一小节，我们会演示如何离线运行这些模型。

这些模型沿用与 Llama 3.1 相同的架构，训练时最多用到 9 万亿 token，仍然支持 128k token 的长上下文。模型支持多语言，包括英语、德语、法语、意大利语、葡萄牙语、印地语、西班牙语和泰语。

还有全新的小型 Llama Guard——Llama Guard 3 1B，可以搭配这些模型部署，用于评估多轮对话中最后一条用户或助手回复。它使用一组预定义类别（这版的新特性）可以定制或排除，以适配开发者的用例。关于 Llama Guard 使用的更多细节请查看模型卡。

彩蛋：Llama 3.2 在训练中还接触过比上述 8 种支持语言更广的语言。鼓励开发者针对特定语言用例微调 Llama 3.2 模型。

我们用 Open LLM Leaderboard 评测套件跑了 base 模型；instruct 模型则在三个流行基准上评估——它们度量指令遵循能力，且与 LMSYS Chatbot Arena 高度相关：[IFEval](https://arxiv.org/abs/2311.07911)、[AlpacaEval](https://arxiv.org/abs/2404.04475) 和 [MixEval-Hard](https://arxiv.org/abs/2406.06565)。base 模型结果如下，附上 Llama-3.1-8B 作参照：

| 模型 | BBH | MATH Lvl 5 | GPQA | MUSR | MMLU-PRO | 平均 |
| --- | --- | --- | --- | --- | --- | --- |
| Meta-Llama-3.2-1B | 4.37 | 0.23 | 0.00 | 2.56 | 2.26 | 1.88 |
| Meta-Llama-3.2-3B | 14.73 | 1.28 | 4.03 | 3.39 | 16.57 | 8.00 |
| Meta-Llama-3.1-8B | 25.29 | 4.61 | 6.15 | 8.98 | 24.95 | 14.00 |

以下是 instruct 模型的结果，附上 Llama-3.1-8B-Instruct 作参照：

| 模型 | AlpacaEval (LC) | IFEval | MixEval-Hard | 平均 |
| --- | --- | --- | --- | --- |
| Meta-Llama-3.2-1B-Instruct | 7.17 | 58.92 | 26.10 | 30.73 |
| Meta-Llama-3.2-3B-Instruct | 20.88 | 77.01 | 31.80 | 43.23 |
| Meta-Llama-3.1-8B-Instruct | 25.74 | 76.49 | 44.10 | 48.78 |

值得注意的是，3B 模型在 IFEval 上和 8B 一样强！这让模型非常适合 agentic 应用——在这类应用里，遵循指令对提升可靠性至关重要。对这个尺寸来说，这么高的 IFEval 分数非常亮眼。

1B 和 3B 指令微调模型都支持工具使用。工具由用户在 zero-shot 设定下指定（模型对开发者将使用的工具没有任何预先信息）。因此，Llama 3.1 模型中内置的工具（`brave_search` 和 `wolfram_alpha`）不再可用。

由于体积小巧，这些小模型可以用作更大模型的助手，执行[辅助生成](https://huggingface.co/blog/assisted-generation)（也称投机解码，speculative decoding）。[这里](https://github.com/huggingface/huggingface-llama-recipes/blob/main/assisted_decoding/assisted_decoding_8B_1B.ipynb)有一个把 Llama 3.2 1B 作为 Llama 3.1 8B 助手的示例。离线用例请看下文[设备端](https://huggingface.co/blog/llama32#on-device)一节。

## 使用 Hugging Face Transformers

纯文本 checkpoint 与之前版本架构相同，所以不需要更新环境。但由于是新架构，Llama 3.2 Vision 需要升级 Transformers。请务必升级到 4.45.0 或更高版本。

```
pip install "transformers>=4.45.0" --upgrade
```

升级后，你就可以使用新的 Llama 3.2 模型，并用上 Hugging Face 生态的全部工具。

## Llama 3.2 1B 与 3B 语言模型

用 Transformers 两行代码就能跑 1B 和 3B 文本模型 checkpoint。模型 checkpoint 以 `bfloat16` 精度上传，但你也可以用 float16 或量化权重。内存需求取决于模型大小和权重精度。下表是不同配置下推理的大致内存需求：

| 模型大小 | BF16/FP16 | FP8 | INT4 |
| --- | --- | --- | --- |
| 3B | 6.5 GB | 3.2 GB | 1.75 GB |
| 1B | 2.5 GB | 1.25 GB | 0.75 GB |

```
from transformers import pipeline
import torch

model_id = "meta-llama/Llama-3.2-3B-Instruct"
pipe = pipeline(
    "text-generation",
    model=model_id,
    torch_dtype=torch.bfloat16,
    device_map="auto",
)

messages = [
    {"role": "user", "content": "Who are you? Please, answer in pirate-speak."},
]
outputs = pipe(
    messages,
    max_new_tokens=256,
)
response = outputs[0]["generated_text"][-1]["content"]
print(response)
# Arrrr, me hearty! Yer lookin' fer a bit o' information about meself, eh? Alright then, matey! I be a language-generatin' swashbuckler, a digital buccaneer with a penchant fer spinnin' words into gold doubloons o' knowledge! Me name be... (dramatic pause)...Assistant! Aye, that be me name, and I be here to help ye navigate the seven seas o' questions and find the hidden treasure o' answers! So hoist the sails and set course fer adventure, me hearty! What be yer first question?
```

几个细节：

- 我们以 `bfloat16` 加载模型。如前所述，这是 Meta 发布的原始 checkpoint 所用的类型，也是确保最佳精度或做评测时推荐的运行方式。根据你的硬件，float16 可能更快。
- 默认情况下，transformers 使用与 Meta 原始代码库相同的采样参数（temperature=0.6、top_p=0.9）。我们还没做 extensive 测试，欢迎自行探索！

## Llama 3.2 Vision

Vision 模型更大，所以运行所需内存比小文本模型多。作为参考，11B Vision 模型在 4-bit 模式下推理时约占 10 GB GPU RAM。

使用指令微调的 Llama Vision 模型，最简单的方式是用内置的 chat template。输入用 `user` 和 `assistant` 角色表示对话轮次。与文本模型的一个区别是不支持 system 角色。用户轮可以包含图文或纯文本输入。要表明输入包含图像，在内容的 content 部分加上 `{"type": "image"}`，然后把图像数据传给 `processor`：

```
import requests
import torch
from PIL import Image
from transformers import MllamaForConditionalGeneration, AutoProcessor

model_id = "meta-llama/Llama-3.2-11B-Vision-Instruct"
model = MllamaForConditionalGeneration.from_pretrained(
    model_id,
    torch_dtype=torch.bfloat16,
    device="cuda",
)
processor = AutoProcessor.from_pretrained(model_id)

url = "https://huggingface.co/datasets/huggingface/documentation-images/resolve/0052a70beed5bf71b92610a43a52df6d286cd5f3/diffusers/rabbit.jpg"
image = Image.open(requests.get(url, stream=True).raw)

messages = [
    {"role": "user", "content": [
        {"type": "image"},
        {"type": "text", "text": "Can you please describe this image in just one sentence?"}
    ]}
]

input_text = processor.apply_chat_template(
    messages, add_generation_prompt=True,
)
inputs = processor(
    image,
    input_text,
    add_special_tokens=False,
    return_tensors="pt",
).to(model.device)
output = model.generate(**inputs, max_new_tokens=70)

print(processor.decode(output[0][inputs["input_ids"].shape[-1]:]))


## The image depicts a rabbit dressed in a blue coat and brown vest, standing on a dirt road in front of a stone house.
```

你可以继续围绕这张图像对话。但要记住，如果在新用户轮里提供了新图像，模型从那一刻起会引用新图像。你不能同时查询两张不同的图像。下面是在之前对话基础上续接的例子：我们把助手轮加入对话，并追问更多细节：

```
messages = [
    {"role": "user", "content": [
        {"type": "image"},
        {"type": "text", "text": "Can you please describe this image in just one sentence?"}
    ]},
    {"role": "assistant", "content": "The image depicts a rabbit dressed in a blue coat and brown vest, standing on a dirt road in front of a stone house."},
    {"role": "user", "content": "What is in the background?"}
]

input_text = processor.apply_chat_template(
    messages,
    add_generation_prompt=True,
)
inputs = processor(image, input_text, return_tensors="pt").to(model.device)
output = model.generate(**inputs, max_new_tokens=70)
print(processor.decode(output[0][inputs["input_ids"].shape[-1]:]))
```

我们得到的回答是：

```
In the background, there is a stone house with a thatched roof, a dirt road, a field of flowers, and rolling hills.
```

你也可以自动量化模型，用 `bitsandbytes` 库以 8-bit 甚至 4-bit 模式加载。下面是以 4-bit 加载生成流水线的方式：

```
import torch
from transformers import MllamaForConditionalGeneration, AutoProcessor
+from transformers import BitsAndBytesConfig

+bnb_config = BitsAndBytesConfig(
+    load_in_4bit=True,
+    bnb_4bit_quant_type="nf4",
+    bnb_4bit_compute_dtype=torch.bfloat16
)
 
model = MllamaForConditionalGeneration.from_pretrained(
    model_id,
-   torch_dtype=torch.bfloat16,
-   device="cuda",
+   quantization_config=bnb_config,
)
```

之后你就可以像之前一样应用 chat template、使用 processor 并调用模型。

你可以用下面这些开源库，直接在设备的 CPU/GPU/浏览器上运行 Llama 3.2 1B 和 3B。

### Llama.cpp 与 Llama-cpp-python

[Llama.cpp](https://github.com/ggerganov/llama.cpp) 是跨平台设备端 ML 推理的不二之选。我们在这个 collection 中为 1B 和 3B 模型都提供了 4-bit 和 8-bit 量化权重。我们期待社区拥抱这些模型，产出更多量化和微调版本。所有量化后的 Llama 3.2 模型见[这里](https://huggingface.co/models?search=hugging-quants/Llama-3.2-)。

以下是如何把这些 checkpoint 直接用于 llama.cpp。

通过 brew 安装 llama.cpp（Mac 和 Linux 均可用）。

```
brew install llama.cpp
```

你可以用 CLI 跑单次生成，或启动与 Open AI messages 规范兼容的 llama.cpp 服务器。

CLI 这样用：

```
llama-cli --hf-repo hugging-quants/Llama-3.2-3B-Instruct-Q8_0-GGUF --hf-file llama-3.2-3b-instruct-q8_0.gguf -p "The meaning to life and the universe is"
```

服务器这样起：

```
llama-server --hf-repo hugging-quants/Llama-3.2-3B-Instruct-Q8_0-GGUF --hf-file llama-3.2-3b-instruct-q8_0.gguf -c 2048
```

你也可以用 [llama-cpp-python](https://github.com/abetlen/llama-cpp-python) 在 Python 里以编程方式访问这些模型。从 [PyPI](https://pypi.org/project/llama-cpp-python/) 安装：

```
pip install llama-cpp-python
```

然后可以这样运行模型：

```
from llama_cpp import Llama

llm = Llama.from_pretrained(
    repo_id="hugging-quants/Llama-3.2-3B-Instruct-Q8_0-GGUF",
    filename="*q8_0.gguf",
)
output = llm.create_chat_completion(
      messages = [
          {
              "role": "user",
              "content": "What is the capital of France?"
          }
      ]
)

print(output)
```

### Transformers.js

你甚至可以用 [Transformers.js](https://huggingface.co/docs/transformers.js) 在浏览器（或 Node.js、Deno、Bun 等任何 JavaScript 运行时）里运行 Llama 3.2。ONNX 模型见 Hub 上的 [ONNX model](https://huggingface.co/onnx-community/Llama-3.2-1B-Instruct)。如果还没安装，可以从 [NPM](https://www.npmjs.com/package/@huggingface/transformers) 安装：

```
npm i @huggingface/transformers
```

然后可以这样运行模型：

```
import { pipeline } from "@huggingface/transformers";

// Create a text generation pipeline
const generator = await pipeline("text-generation", "onnx-community/Llama-3.2-1B-Instruct");

// Define the list of messages
const messages = [
  { role: "system", content: "You are a helpful assistant." },
  { role: "user", content: "Tell me a joke." },
];

// Generate a response
const output = await generator(messages, { max_new_tokens: 128 });
console.log(output[0].generated_text.at(-1).content);
```

示例输出

```
Here's a joke for you:

What do you call a fake noodle?

An impasta!

I hope that made you laugh! Do you want to hear another one?
```

### MLC.ai Web-LLM

MLC.ai Web-LLM 是一个高性能的浏览器内 LLM 推理引擎，借助硬件加速把语言模型推理直接带进浏览器。一切都运行在浏览器里，无需服务器支持，并用 WebGPU 加速。

WebLLM 与 OpenAI API 完全兼容。也就是说，你可以在本地对任何开源模型使用同样的 OpenAI API，功能包括流式输出、JSON 模式、function calling 等。

可以从 npm 安装 Web-LLM

```
npm install @mlc/web-llm
```

然后可以这样运行模型：

```
// Import everything
import * as webllm from "@mlc-ai/web-llm";
// Or only import what you need
import { CreateMLCEngine } from "@mlc-ai/web-llm";

// Callback function to update model loading progress
const initProgressCallback = (initProgress) => {
  console.log(initProgress);
}
const selectedModel = "Llama-3.2-3B-Instruct-q4f32_1-MLC";

const engine = await CreateMLCEngine(
  selectedModel,
  { initProgressCallback: initProgressCallback }, // engineConfig
);
```

引擎初始化成功后，就可以通过 `engine.chat.completions` 接口用 OpenAI 风格的 chat API 调用聊天补全。

```
const messages = [
  { role: "system", content: "You are a helpful AI assistant." },
  { role: "user", content: "Explain the meaning of life as a pirate!" },
]

const reply = await engine.chat.completions.create({
  messages,
});
console.log(reply.choices[0].message);
console.log(reply.usage);
```

## 微调 Llama 3.2

TRL 开箱即用地支持 Llama 3.2 文本模型的聊天和微调：

```
# Chat
trl chat --model_name_or_path meta-llama/Llama-3.2-3B

# Fine-tune
trl sft  --model_name_or_path meta-llama/Llama-3.2-3B \
         --dataset_name HuggingFaceH4/no_robots \
         --output_dir Llama-3.2-3B-Instruct-sft \
         --gradient_checkpointing
```

TRL 也支持微调 Llama 3.2 Vision，用[这个脚本](https://github.com/huggingface/trl/tree/main/examples/sft_visual_chat/sft_visual_chat.py)。

```
# Tested on 8x H100 GPUs
accelerate launch --config_file=examples/accelerate_configs/deepspeed_zero3.yaml \
    examples/sft_visual_chat/sft_visual_chat.py \
    --dataset_name HuggingFaceH4/llava-instruct-mix-vsft \
    --model_name_or_path meta-llama/Llama-3.2-11B-Vision-Instruct \
    --per_device_train_batch_size 8 \
    --gradient_accumulation_steps 8 \
    --output_dir Llama-3.2-11B-Vision-Instruct-sft \
    --bf16 \
    --torch_dtype bfloat16 \
    --gradient_checkpointing
```

也可以看看[这个 notebook](https://github.com/huggingface/huggingface-llama-recipes/blob/main/fine_tune/Llama-Vision%20FT.ipynb)，用 transformers 和 PEFT 做 LoRA 微调。
