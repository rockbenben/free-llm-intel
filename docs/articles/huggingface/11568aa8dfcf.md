多向量 embedding 模型让每个 query token 都有机会在文档里找到自己的匹配项。这让它们在检索上极富表达力，但那些文档向量很快就会堆起来。一个含数百万文档的语料库，可能装着数亿个向量！

token pooling 通过合并相似的 token 向量来压缩这些表示。然而我压得越狠，就越容易丢掉有用的东西。pooling 感知训练教 encoder 在向量被合并时保住要紧的信息，帮你在同样的存储预算下检索得更好。

本文里，我会讲清 pooling 如何工作，用 Sentence Transformers 训练一个用于压缩检索的模型，并探究由此得到的质量与存储取舍。用 `pool_factor=4` 时，按常规训练的模型在文档向量减少 **4 倍**的情况下，仍保留未 pooling 时 NanoBEIR nDCG@10 的 94.6%；在同样的存储预算下，token pooling 感知训练把这一保留率提到了 97.8%！来看看是怎么做到的。

> 本文建立在 Stefan Josef 的 Learn to Pool 与 LightOn 的 pooling 正则化研究之上，那两篇也探讨了定向训练与自适应预算。这里我聚焦于理解方法本身，并用一个简短、可复现的 Sentence Transformers 示例把它用起来。

## 为什么多向量检索需要这么多向量

单向量 embedding 模型把整篇文档压成一个向量。[多向量模型](https://huggingface.co/blog/multi-vector-encoder)（如 ColBERT）则保留一组带上下文的 token 向量，让 query 的不同部分去匹配文档的不同部分。

例如，一个关于「电池续航长的笔记本」的 query，可以在文档的一处找到关于笔记本的证据，在另一处找到关于电池续航的证据。用 MaxSim 打分时，每个 query 向量挑出与自己最匹配的文档向量，再把这些分数加起来：

MaxSim⁡(Q,D)=∑q∈Qmax⁡d∈Dq⊤d \operatorname{MaxSim}(Q, D) = \sum_{q \in Q} \max_{d \in D} q^\top d

即便用上 [Fast-PLAID](https://github.com/lightonai/fast-plaid) 支持的 2-bit 或 4-bit 残差量化，每篇文档存上几百个向量也很可观。按每个残差坐标 4 bit 算，200 个 128 维向量每篇文档需要 12.8 KB 的量化残差，一百万篇文档就是 12.8 GB。把每篇文档 pooling 到 50 个向量，在同样的维度和精度下能降到 3.2 GB。

一个有用的观察是：许多文档向量彼此相似。好几个 token 可能描述的是紧密相关的概念，这就给了我们把它们一起表示的机会。

## Token Pooling

[HierarchicalTokenPooling](https://sbert.net/docs/package_reference/multi_vector_encoder/modules.html#hierarchicaltokenpooling) 用 [Ward 层次聚类](https://scikit-learn.org/stable/modules/clustering.html#hierarchical-clustering)把相似的 token embedding 分组。它从「每个 token 向量一组」开始，反复合并那两个让组内向量离散度增加最小的组。这个离散度用每个向量到本组均值的平方距离之和来度量，因此 Ward 方法偏好由相似向量组成的紧致分组。

这些合并构建出一个组越来越大的层次结构，让我们能选一个贴合预算的压缩档位。随后我们用每组的均值来代表它，并把得到的向量再归一化一次，即可用于 MaxSim 打分。

你可以让压缩与文档长度成正比：

```
from sentence_transformers.multi_vector_encoder.modules import HierarchicalTokenPooling

pooling = HierarchicalTokenPooling(pool_factor=4)
```

用 `pool_factor=4` 时，文档大约保留原来四分之一的向量，于是较长的文档能按比例保留更多容量。默认情况下，第一个 token 受保护、不参与合并，且 pooling 只作用于文档 embedding，query embedding 保持不变。

### 选择 pooling 预算

`HierarchicalTokenPooling` 提供三种可选的控制方式：

| 设置 | 表达的含义 |
| --- | --- |
| `max_tokens=16` | 每篇文档最多 16 个向量，含受保护的 token。 |
| `pool_factor=4` | 约为每篇文档原始向量的四分之一。 |
| `distance_threshold=...` | 一个共享的 Ward 合并距离阈值，让向量数随 embedding 几何形态变化。 |

当文档长度参差时，这个区别很要紧。用 `pool_factor=4`，较长的文档能保留大约四分之一的向量，让它的表示随内容一起增长。用 `distance_threshold`，当需要保住更多彼此不同的 embedding 时，向量数就会增长。

### 校准自适应 pooling

自适应 pooling 用一个共享的距离阈值，更激进地合并相似 embedding，同时为内容独特的文档保留更多向量。它可用于任意多向量模型，*包括那些没有用 pooling 感知目标训练过的模型*。

与其手动挑一个阈值，不如按目标平均向量数来校准它。给定语料库里有代表性的一批样本放在 `calibration_documents` 里：

```
from sentence_transformers import MultiVectorEncoder
from sentence_transformers.multi_vector_encoder.modules import HierarchicalTokenPooling

model = MultiVectorEncoder("lightonai/LateOn")
calibration_embeddings = model.encode_document(calibration_documents)
threshold = HierarchicalTokenPooling.calibrate_distance_threshold(calibration_embeddings, target_tokens=16)
pooling = HierarchicalTokenPooling(distance_threshold=threshold)

# Apply pooling, targeting an average of 16 vectors per document
document_embeddings = model.encode_document(documents_to_index, token_pooling=pooling)
```

校准只需要文档 embedding，返回一个可在建索引时复用的阈值。目标是平均值，所以单篇文档可能拿到多于或少于 16 个向量。换到另一个语料库，实际达成的平均值也会变。

## Token Pooling 感知训练

在普通的多向量模型上，pooling 就已经有用了。难点出现在：某篇文档里含有一个对检索很要紧的区分，但合并它的向量会让这个区分更难还原。原本的训练目标从没要求模型去对付这些压缩后的表示。不过，你完全可以教会它这么做。

如果你用过 [Matryoshka embeddings](https://huggingface.co/blog/matryoshka)，这个训练思路会很眼熟。Matryoshka 在若干种 embedding 宽度上施加检索目标，教较短的前缀保持有用。pooling 感知训练则把目标施加到 token 向量更少的表示上。

在我的示例里，每个训练 batch 贡献两个 loss：

- 用原始文档 embedding 做检索。
- 把文档压缩到约为原始向量四分之一之后做检索。

我把它们取平均：

L=12Lunpooled+12Lpooled \mathcal{L} = \tfrac{1}{2}\mathcal{L}_{\mathrm{unpooled}} + \tfrac{1}{2}\mathcal{L}_{\mathrm{pooled}}

第一项教模型用完整表示去检索。第二项教它把自己的 token embedding 排布好，让有用的匹配在 pooling 之后依然留得下来。两个目标更新的是同一个 encoder，给它关于压缩前与压缩后检索的反馈。

Ward 聚类对「哪些 token 归为一组」做的是离散决策。训练时，`HierarchicalTokenPooling` 用 straight-through estimator，把梯度从 pooling 后的向量传回它的成员 token，而不对聚类分配求导。这样 encoder 就能从用 pooling 表示犯下的检索错误里学习。

### Sentence Transformers 里的一个 loss 包装器

[`MultiVectorTokenPoolingLoss`](https://sbert.net/docs/package_reference/multi_vector_encoder/losses.html#multivectortokenpoolingloss) 包装一个已有的多向量检索 loss，并用你选定的 poolers 来施加它：

```
from sentence_transformers import MultiVectorEncoder
from sentence_transformers.multi_vector_encoder.losses import (
    CachedMultiVectorMultipleNegativesRankingLoss,
    MultiVectorTokenPoolingLoss,
)
from sentence_transformers.multi_vector_encoder.modules import HierarchicalTokenPooling

model = MultiVectorEncoder("answerdotai/ModernBERT-base", similarity_fn_name="maxsim")
pooling = HierarchicalTokenPooling(pool_factor=4)

base_loss = CachedMultiVectorMultipleNegativesRankingLoss(model, mini_batch_size=64)
loss = MultiVectorTokenPoolingLoss(
    model,
    base_loss,
    token_poolings=[None, pooling],
    weights=[0.5, 0.5],
)
```

`CachedMultiVectorMultipleNegativesRankingLoss` 提供检索目标。它教每个 query 把自己相关的文档打得高于 batch 里的负样本文档。默认它用 `model.similarity`，即采用模型的相似度设置（本例是 MaxSim）和 kernel 设置。配了 `similarity_fn_name="meanmaxsim"` 的模型，训练时也会用 MeanMaxSim。

梯度缓存让 encoder 能处理较小的 mini-batch，同时保住更大的一批 in-batch negatives。我的训练脚本用 64 的 mini-batch、256 的训练 batch size。

`MultiVectorTokenPoolingLoss` 加上压缩目标。这里 `None` 表示其中一个变体用原始 embedding，`pooling` 则提供 factor-4 的变体。两个权重把它们的 loss 取平均。pooling 变体复用已算好的 token embedding，所以每多一个 pooler 只是多一份聚类与打分的工作，不必为该变体再跑一次 encoder。

poolers 也可以是自定义的、能在输入 embedding 上保住梯度的 `BaseTokenPooling` 实现。你可以让训练目标贴合你打算部署的那种表示。

把 factor-4 的 pooler 换成你选定的部署配置，或者放几个 pooler 进来、为它们的 loss 分别配权重。

完整的 [training script](https://github.com/huggingface/sentence-transformers/blob/main/examples/multi_vector_encoder/training/token_pooling/training_cached_contrastive.py) 含数据集、trainer、验证 loss，以及训练过程中的小规模检索评测。从 repository 的 checkout 里，用 [uv](https://docs.astral.sh/uv/getting-started/installation/) 在本地跑两个变体：

```
uv run examples/multi_vector_encoder/training/token_pooling/training_cached_contrastive.py --baseline
uv run examples/multi_vector_encoder/training/token_pooling/training_cached_contrastive.py
```

脚本声明了训练与 kernel 依赖，uv 会替你装好。兼容的 kernel 会自动启用。

你也可以在云 GPU 上用 [Hugging Face Jobs](https://huggingface.co/docs/hub/jobs-quickstart) 训练。装好 CLI，并用一个能跑 Jobs、能上传模型的 token 登录：

### 可选的 kernel 加速

你可以用 [kernels](https://sbert.net/docs/multi_vector_encoder/usage/kernels.html) 加速 MaxSim 打分、Ward 聚类，以及受支持的 backbone 运算。装训练与 kernel 依赖：

```
pip install -U "sentence-transformers[train,kernels]"
```

在上面那个训练示例里，构造 loss 之前把模型和 pooler 的初始化替换为：

```
model = MultiVectorEncoder(
    "answerdotai/ModernBERT-base",
    device="cuda",
    similarity_fn_name="maxsim",
    use_kernels=True,
)
pooling = HierarchicalTokenPooling(pool_factor=4)
```

层次 pooler 默认继承模型的 kernel 设置，所以你只需在模型上启用 kernel。

Sentence Transformers 会为你的环境挑兼容的 kernel，在没有替代品的地方沿用现有实现。例如[默认的 MaxSim kernel](https://huggingface.co/kernels/sentence-transformers/late-interaction-kernels) 给 query 与文档打分时，不在内存里构建完整的 token 相似度矩阵，但它需要 CUDA 和 Triton。

默认的 [Ward clustering kernel](https://huggingface.co/kernels/sentence-transformers/ward-clustering) 跑在 CUDA 而非 CPU 上，大幅加速层次聚类——按设置不同，比 SciPy 快 30 到 150 倍。

## 使用训练好的模型

我们来加载 pooling 感知模型，用压缩后的文档 embedding 做检索。kernel 设置不随模型一起保存，所以若推理时也想用，加载时加上 `use_kernels=True`：

```
from sentence_transformers import MultiVectorEncoder
from sentence_transformers.multi_vector_encoder.modules import HierarchicalTokenPooling

model = MultiVectorEncoder("tomaarsen/mve-ModernBERT-base-token-pooling")
pooling = HierarchicalTokenPooling(pool_factor=4)

queries = ["Which planet is known as the Red Planet?"]
documents = [
    "Venus is often called Earth's twin because of its similar size and proximity.",
    "Mars, known for its reddish appearance, is often referred to as the Red Planet.",
    "Jupiter, the largest planet in our solar system, has a prominent red spot.",
]

query_embeddings = model.encode_query(queries)
document_embeddings = model.encode_document(documents, token_pooling=pooling)

print([len(embedding) for embedding in document_embeddings])
# [5, 6, 5]
print(model.similarity(query_embeddings, document_embeddings))
# tensor([[16.0037, 25.9879, 22.8159]], device='cuda:0')

# For comparison, the same model without token pooling:
# [18, 21, 19]
# tensor([[16.6115, 27.6060, 24.1766]], device='cuda:0')
```

pooler 在 encoder 的前向流水线之后压缩文档 embedding，把总数从 58 个向量降到 16 个，query embedding 保持不变。Mars 仍拿到最高的相似度分，其次是 Jupiter 和 Venus——尽管所存文档向量少得多，排序依然保住了。

推理时你可以改 `pool_factor`，用同一个训练好的模型去试不同的存储预算。若会反复使用，也可以在初始化 `MultiVectorEncoder` 时传 `token_pooling=pooling`，把它设成运行时默认值。pooler 的 `tasks` 仍控制哪些输入被压缩（例如只压文档）。

## 评测结果

为了探究，我从 `answerdotai/ModernBERT-base` 训练了两个模型，各自带一个全新的 128 维 token projection：

- [tomaarsen/mve-ModernBERT-base-token-pooling-baseline](https://huggingface.co/tomaarsen/mve-ModernBERT-base-token-pooling-baseline)，只用 cached contrastive loss。
- [tomaarsen/mve-ModernBERT-base-token-pooling](https://huggingface.co/tomaarsen/mve-ModernBERT-base-token-pooling)，用 cached contrastive loss 包上前面那套未 pooling 与 factor-4 目标。

两次运行都在同一批 120,000 条 MS MARCO triplets 上跑一个 epoch，seed 42，初始化与优化设置一致。训练 token 上限为 300，短 query 会扩展到至少 32 个 token 位置，以提供更多带上下文的 query 向量。两个实验只有 loss 不同，我没有做超参搜索。

我在 NanoBEIR@13 上评测两个模型，报告平均 nDCG@10（%）。图里对比了常规训练与 pooling 感知训练在 pool factor 为 2、3、4、6 以及未 pooling 检索下的表现。表里还含固定上限与自适应阈值，展示训练收益如何迁移到别的 pooling 设置。

对自适应 pooling，我为每个 encoder 和每个 NanoBEIR 语料单独校准了一个阈值，用它们未 pooling 的文档 embedding 去对齐 64、32、16 三档上限下的平均向量数。短文档会把这些平均值拉到各自上限之下。

在训练所用的 `pool_factor=4` 下，nDCG@10 从 49.03 提升到 51.23，而所存文档向量比未 pooling 检索少 74.8%。这把分数保留率从 94.6% 提高到 97.8%——保留率定义为 pooling 后的平均 nDCG@10 除以该模型自己未 pooling 时的平均值。未 pooling 检索也有所改善，从 51.84 到 52.39。

收益还延伸到固定上限与自适应 pooling，尽管训练只用了完整表示与按比例 pooling。在平均每篇文档 29.58 个向量时，自适应 pooling 保留了 pooling 感知模型未 pooling 分数的 97.3%，而所存文档向量少了 84.7%；同样预算下，常规训练的模型只保留 93.3%。

## 组合多种压缩技术

如果索引体积是你最在意的，我会按这个顺序去挑这些选项：

- 把 embedding 量化到 4、2 或 1 bit，例如借 [Fast-PLAID](https://github.com/lightonai/fast-plaid)，降低每个坐标的存储。
- 用 token pooling 减少文档向量数量，可选地配上本文展示的 pooling 感知微调。
- 用 [Matryoshka token embeddings](https://sbert.net/examples/multi_vector_encoder/training/matryoshka/README.html) 降低每个 token 向量的维度，可选地配微调，以在较小宽度下保住检索质量。

如果模型默认维度大于 128，我也会更早考虑 Matryoshka 截断与微调。这些做法可以组合，所以用你自己的搜索引擎和语料库去评测最终的索引体积与检索质量。

`MultiVectorMatryoshkaLoss` 训练 token embedding 在截断之后仍保持有用。你可以用 `MultiVectorTokenPoolingLoss` 把它包起来，同时为更小维度和更少文档向量做训练，在各压缩设置间复用 encoder 的 embedding。

试试[完整训练示例](https://sbert.net/examples/multi_vector_encoder/training/token_pooling/README.html)，挑一个对你的应用真正要紧的预算，再和一次配置对齐的普通 loss 运行做对比。随附的 [evaluation script](https://github.com/huggingface/sentence-transformers/blob/main/examples/multi_vector_encoder/training/token_pooling/evaluate_token_pooling.py) 会测未 pooling 检索、64/32/16/8/4 个向量的上限，以及 2 到 6 的 pool factor，好让你为自己模型画出质量与存储的取舍曲线。

只要在训练目标里多写几行，更小的文档表示就成了模型主动学会去用的东西。这为让多向量检索更实用，打开了相当可观的空间！
