# 投机解码让 Whisper 推理提速 2x

Sanchit Gandhi（sanchit-gandhi）

本文亦有[简体中文](https://huggingface.co/blog/zh/whisper-speculative-decoding)版本。

OpenAI 的 [Whisper](https://openai.com/research/whisper) 是一个通用语音转写模型，在各类基准和音频条件下都拿到了最先进的成绩。最新的 [large-v3](https://huggingface.co/openai/whisper-large-v3) 模型登顶 [OpenASR 排行榜](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard)，是英语语音转写最强的开源模型。它在多语言上同样表现出色：在 Common Voice 15 数据集测试的 58 种语言中，42 种语言的词错误率（WER）低于 30%。

不过，转写精度惊人的同时，推理速度也非常慢。一段 1 小时的音频，即便用上了 [flash attention](https://huggingface.co/docs/transformers/perf_infer_gpu_one#flashattention-2)、半精度、[分块（chunking）](https://huggingface.co/docs/transformers/main_classes/pipelines#transformers.AutomaticSpeechRecognitionPipeline.chunk_length_s)这些推理优化，在 16GB T4 GPU 上也要 6 分钟起。

在这篇博客里，我们将演示如何用投机解码（Speculative Decoding）把 Whisper 的推理时间缩短到一半——**2 倍提速**，同时在数学上确保模型输出**完全一致**。这意味着它非常适合直接替换现有 Whisper 管线：白赚 2 倍速度，精度分毫不损。想要更精简、少解释但代码齐全的版本，可以看配套的 [Google Colab](https://colab.research.google.com/github/sanchit-gandhi/notebooks/blob/main/speculative_decoding.ipynb)。

## 投机解码

投机解码出自 Google 的 Yaniv Leviathan 等人的论文 [Fast Inference from Transformers via Speculative Decoding](https://arxiv.org/abs/2211.17192)。它的前提是：一个更快的**辅助模型（assistant model）**生成的 token 往往和更大的**主模型（main model）**相同。

第一步，辅助模型自回归地生成 N N N 个*候选 token*，y^1:N \hat{\boldsymbol{y}}_{1:N} y^​1:N​。下图里，辅助模型生成了 5 个候选 token：`The quick brown sock jumps`。

这些候选 token 生成得很快，但可能与主模型的预测不一致。于是第二步，把候选 token 交给主模型"验证"。主模型以候选 token 为输入，做**一次前向传播**，输出序列中每一步的"正确" token：y1:N \boldsymbol{y}_{1:N} y1:N​。

在上图中，主模型预测的前三个 token 与辅助模型一致：The quick brown。但辅助模型的第四个候选 token sock 与主模型给出的正确 token fox 不符。

我们知道，第一个不匹配位置之前的所有候选 token 都是正确的（The quick brown），因为它们与主模型预测一致；但第一个不匹配之后，候选 token 就偏离了主模型实际预测的 token。因此，可以把第一个错误候选 token（sock）替换为主模型的正确 token（fox），并丢弃之后的所有 token，因为它们已经发散。修正后的序列 `The quick brown fox` 成为辅助模型的新输入：

推理过程接着重复：辅助模型再生成一组 N N N 个候选 token，主模型再一次前向传播完成验证。

由于自回归生成用的是快的辅助模型，慢的主模型只做验证性质的前向传播，解码过程被大幅加速。而且主模型的验证前向传播保证了最终输出与单用主模型**完全相同**。这让投机解码成为现有 Whisper 管线的理想直接替代——可以确定质量不会变。

要把延迟收益最大化，辅助模型应当显著快于主模型，同时尽可能预测出相同的 token 分布。实践中这两者构成一个权衡：模型越快往往越不准。但由于大约 70-80% 的预测 token 都是"简单" token，这个权衡明显偏向选更快的模型而非更准的模型。因此辅助模型至少要比主模型快 3 倍（越快越好），并把示例中所有"简单" token 都预测对；剩下 20-30% 的"难" token 交给更大的主模型验证即可。

选辅助模型唯一的硬性约束是词表必须与主模型一致——即辅助模型要用与主模型一一对应的同一个分词器。所以，如果想对多语言版 Whisper（如 [large-v2](https://huggingface.co/openai/whisper-large-v2)）用投机解码，辅助模型也得选多语言版，例如 [tiny](https://huggingface.co/openai/tiny)；如果想对纯英语版（如 [medium.en](https://huggingface.co/openai/whisper-medium.en)）用投机解码，辅助模型也得是纯英语版，例如 [tiny.en](https://huggingface.co/openai/tiny.en)。目前 Whisper [large-v3](https://huggingface.co/openai/whisper-large-v3) 是个例外：它是唯一一个词表尺寸扩大过的 Whisper checkpoint，因此与之前的 Whisper checkpoint 不兼容。

了解了投机解码的背景，就可以动手实践了。在 [🤗 Transformers](https://huggingface.co/docs/transformers/index) 库里，投机解码以"辅助生成（assisted generation）"推理策略实现。想了解实现细节，推荐阅读 Joao Gante 的优秀博客 [Assisted Generation](https://huggingface.co/blog/assisted-generation)。

## 英语语音转写

### 基线实现

我们先给 Whisper [large-v2](https://huggingface.co/openai/whisper-large-v2) 做基准，得到推理速度的基线。通过方便的 [`AutoModelForSpeechSeq2Seq`](https://huggingface.co/docs/transformers/model_doc/auto#transformers.AutoModelForSpeechSeq2Seq) 和 [`AutoProcessor`](https://huggingface.co/docs/transformers/model_doc/auto#transformers.AutoProcessor) 类加载主模型及对应处理器。模型用 `float16` 精度加载，并传入 [`low_cpu_mem_usage=True`](https://huggingface.co/docs/transformers/main_classes/model#large-model-loading) 让加载尽量快；同时传入 [`use_safetensors=True`](https://huggingface.co/docs/transformers/main_classes/model#transformers.PreTrainedModel.from_pretrained.use_safetensors) 确保以 [safetensors](https://huggingface.co/docs/diffusers/main/en/using-diffusers/using_safetensors) 格式加载；最后传 `attn_implementation="sdpa"`，通过 PyTorch 的 [SDPA attention 内核](https://pytorch.org/docs/master/generated/torch.nn.functional.scaled_dot_product_attention.html)吃到 Flash Attention 加速：

```
import torch
from transformers import AutoModelForSpeechSeq2Seq, AutoProcessor

device = "cuda:0" if torch.cuda.is_available() else "cpu"
torch_dtype = torch.float16 if torch.cuda.is_available() else torch.float32

model_id = "openai/whisper-large-v2"

model = AutoModelForSpeechSeq2Seq.from_pretrained(
    model_id,
    torch_dtype=torch_dtype,
    low_cpu_mem_usage=True,
    use_safetensors=True,
    attn_implementation="sdpa",
)
model.to(device)

processor = AutoProcessor.from_pretrained(model_id)
```

来加载用于基准测试的英语转写数据集。我们用一个小数据集：从 [LibriSpeech ASR](https://huggingface.co/datasets/librispeech_asr) validation-clean 数据集取 73 条样本，总共约 9MB，非常轻量、下载很快：

```
from datasets import load_dataset

dataset = load_dataset("hf-internal-testing/librispeech_asr_dummy", "clean", split="validation")
```

基准只关心生成时间，所以写一个简短的辅助函数。下面这个函数同时返回解码后的 token 和模型运行耗时：

```
import time

def generate_with_time(model, inputs, **kwargs):
    start_time = time.time()
    outputs = model.generate(**inputs, **kwargs)
    generation_time = time.time() - start_time
    return outputs, generation_time
```

现在遍历数据集中的音频样本，累计总生成时间：

```
from tqdm import tqdm

all_time = 0
predictions = []
references = []

for sample in tqdm(dataset):
    audio = sample["audio"]
    inputs = processor(audio["array"], sampling_rate=audio["sampling_rate"], return_tensors="pt")
    inputs = inputs.to(device=device, dtype=torch.float16)
    
    output, gen_time = generate_with_time(model, inputs)
    all_time += gen_time
    predictions.append(processor.batch_decode(output, skip_special_tokens=True, normalize=True)[0])
    references.append(processor.tokenizer._normalize(sample["text"]))

print(all_time)
```

**输出：**

```
100%|██████████| 73/73 [01:37<00:00,  1.33s/it]
72.99542546272278
```

好！转写这 73 条样本用了 73 秒。看看预测的 WER：

```
from evaluate import load

wer = load("wer")
print(wer.compute(predictions=predictions, references=references))
```

**输出：**

```
0.03507271171941831
```

我们的最终基线是：73 秒，WER 3.5%。

### 投机解码

现在加载用于投机解码的辅助模型。这里用 Whisper 的蒸馏变体 [distil-large-v2](https://huggingface.co/distil-whisper/distil-large-v2)。蒸馏模型完整保留了 Whisper 的编码器，但解码器只保留了 32 层中的 2 层。因此它比 Whisper 快 6 倍，同时在同分布外测试集上 WER 差距在 1% 以内。高转写精度加快速生成，它正是辅助模型的理想选择 1{}^11。

由于 Distil-Whisper 与 Whisper 主模型的编码器完全相同，主模型和辅助模型可以共用一个编码器，只需把 Distil-Whisper 的 2 层解码器作为"decoder-only"模型加载即可，用方便的 [`AutoModelForCausalLM`](https://huggingface.co/docs/transformers/model_doc/auto#transformers.AutoModelForCausalLM) 自动类就能做到。实测下来，相比只加载主模型，显存（VRAM）只增加 8%。

```
from transformers import AutoModelForCausalLM

assistant_model_id = "distil-whisper/distil-large-v2"

assistant_model = AutoModelForCausalLM.from_pretrained(
    assistant_model_id,
    torch_dtype=torch_dtype,
    low_cpu_mem_usage=True,
    use_safetensors=True,
    attn_implementation="sdpa",
)

assistant_model.to(device)
```

1{}^11 我们计划发布一个改进版 Distil-Whisper，其 token 分布对齐更好，能让投机解码性能再上一层楼。请关注 [Distil-Whisper 仓库](https://github.com/huggingface/distil-whisper)获取更新。

可以为投机解码基准定义一个改造过的函数。它与前面的函数唯一的区别是调用 `.generate` 时传入辅助模型：

```
def assisted_generate_with_time(model, inputs, **kwargs):
    start_time = time.time()
    outputs = model.generate(**inputs, assistant_model=assistant_model, **kwargs)
    generation_time = time.time() - start_time
    return outputs, generation_time
```

用投机解码跑基准，Distil-Whisper 给 Whisper 当辅助：

```
all_time = 0
predictions = []
references = []

for sample in tqdm(dataset):
    audio = sample["audio"]
    inputs = processor(audio["array"], sampling_rate=audio["sampling_rate"], return_tensors="pt")
    inputs = inputs.to(device=device, dtype=torch.float16)
    
    output, gen_time = assisted_generate_with_time(model, inputs)
    all_time += gen_time
    predictions.append(processor.batch_decode(output, skip_special_tokens=True, normalize=True)[0])
    references.append(processor.tokenizer._normalize(sample["text"]))

print(all_time)
```

**输出：**

```
100%|██████████| 73/73 [00:38<00:00,  1.88it/s]
32.69683289527893
```

用投机解码后推理只要 33 秒，比之前快 2.2 倍！确认 WER 相同：

```
print(wer.compute(predictions=predictions, references=references))
```

**输出：**

```
0.03507271171941831
```

完美！还是 3.5% WER，输出与单用主模型完全一致。

投机解码也能直接用在 🤗 Transformers 易用的 [pipeline](https://huggingface.co/docs/transformers/pipeline_tutorial) API 上。下面用模型和处理器实例化 pipeline，然后转写玩具数据集的第一条样本。同样的方式可以扩展到任意长度的音频转写，还支持批量：

```
from transformers import pipeline

pipe = pipeline(
    "automatic-speech-recognition",
    model=model,
    tokenizer=processor.tokenizer,
    feature_extractor=processor.feature_extractor,
    max_new_tokens=128,
    chunk_length_s=15,
    batch_size=4,
    generate_kwargs={"assistant_model": assistant_model},
    torch_dtype=torch_dtype,
    device=device,
)

sample = dataset[0]["audio"]
result = pipe(sample)
print(result["text"])
```

**输出：**

```
 Mr. Quilter is the apostle of the middle classes and we are glad to welcome his gospel.
```

运行 Whisper + Distil-Whisper 投机解码的端到端代码片段可以在 [Distil-Whisper 模型卡](https://huggingface.co/distil-whisper/distil-large-v2#speculative-decoding)上找到，它把这个 notebook 里讲的推理步骤整合成了一个代码示例。

## 多语言语音转写

Distil-Whisper 是英语转写理想的辅助模型：与原 Whisper 的 WER 差距在 1% 以内，长短音频上都快 6 倍。但官方的 Distil-Whisper checkpoint 只支持英语，不能用于多语言转写。

要多语言投机解码，辅助模型既可以用[官方多语言 Whisper checkpoint](https://huggingface.co/openai/whisper-large-v2#model-details)之一，也可以用 Whisper 的微调变体。写这篇博客时，Hugging Face Hub 上已经有覆盖 100 多种语言的 5000 多个[微调 Whisper checkpoint](https://huggingface.co/models?other=whisper)。它们是挑选单语言表现优异的辅助模型的好起点。这里我们用最小编号的官方多语言 checkpoint：Whisper [tiny](https://huggingface.co/openai/whisper-tiny)。欢迎拿你自己语言的微调 checkpoint 做实验！

加载新的辅助模型 Whisper tiny 的权重。这次它的编码器与 large-v2 不同，所以用 `AutoModelForSpeechSeq2Seq` 把编码器和解码器一起加载：

```
assistant_model_id = "openai/whisper-tiny"

assistant_model = AutoModelForSpeechSeq2Seq.from_pretrained(
    assistant_model_id,
    torch_dtype=torch_dtype,
    low_cpu_mem_usage=True,
    use_safetensors=True,
    attn_implementation="sdpa",
)

assistant_model.to(device);
```

基准数据集用 [VoxPopuli](https://huggingface.co/datasets/facebook/voxpopuli) 荷兰语（"nl"）划分的 73 条样本：

```
dataset = load_dataset("sanchit-gandhi/voxpopuli_dummy", "nl", split="validation")
```

好！按之前的方式重新跑基线模型 Whisper large-v2 的基准。唯一的改动是给 generate 传 language 和 task 参数，确保做语音转写（而非语音翻译）。投机解码与转写、翻译两种任务都完全兼容，按需设置 task 参数即可：

```
all_time = 0
predictions = []
references = []

for sample in tqdm(dataset):
    audio = sample["audio"]
    inputs = processor(audio["array"], sampling_rate=audio["sampling_rate"], return_tensors="pt")
    inputs = inputs.to(device=device, dtype=torch.float16)
    
    output, gen_time = generate_with_time(model, inputs, language="nl", task="transcribe")
    all_time += gen_time
    predictions.append(processor.batch_decode(output, skip_special_tokens=True, normalize=True)[0])
    references.append(processor.tokenizer._normalize(sample["normalized_text"]))

wer_result = wer.compute(predictions=predictions, references=references)

print("Time:", all_time)
print("WER:", wer_result)
```

**输出：**

```
100%|██████████| 73/73 [02:05<00:00,  1.72s/it]
Time: 116.50992178916931
WER: 0.127190136275146
```

基线出来了：117 秒，WER 12.8%。用投机解码再跑一次生成：

```
all_time = 0
predictions = []
references = []

for sample in tqdm(dataset):
    audio = sample["audio"]
    inputs = processor(audio["array"], sampling_rate=audio["sampling_rate"], return_tensors="pt")
    inputs = inputs.to(device=device, dtype=torch.float16)

    output, gen_time = assisted_generate_with_time(model, inputs, language="nl", task="transcribe")
    all_time += gen_time
    predictions.append(processor.batch_decode(output, skip_special_tokens=True, normalize=True)[0])
    references.append(processor.tokenizer._normalize(sample["normalized_text"]))

wer_result = wer.compute(predictions=predictions, references=references)

print("Time:", all_time)
print("WER:", wer_result)
```

**输出：**

```
100%|██████████| 73/73 [01:08<00:00,  1.06it/s]
Time: 62.10229682922363
WER: 0.127190136275146
```

同样是 12.8% WER，但这次推理只要 62 秒，提速 1.9 倍。考虑到加载辅助模型的开销极低，又有"输出完全一致"的数学保证，投机解码就是现有 Whisper 管线的完美直接替代。

## 高效投机解码的策略

最后一节，讲两个确保投机解码推理速度最快的策略。

#### 辅助模型

目标是选一个至少比主模型快 3 倍、**并且**能正确转写出至少 70-80% 预测 token（通常是示例中的"简单" token）的辅助模型。如果你有特定目标语言，一个有效的做法是训练两个不同尺寸的 Whisper 模型，一个给另一个当辅助：

- 先把 Whisper [large-v3](https://huggingface.co/openai/whisper-large-v3) 微调成你的主模型
- 再用同一份数据蒸馏这个 large-v3，得到一个快速辅助模型

微调与蒸馏能同时提升主模型和辅助模型在目标语言上的 WER，并最大化两者 token 分布的对齐程度。Whisper 微调完整指南见[这里](https://huggingface.co/blog/fine-tune-whisper)，蒸馏见[这里](https://github.com/huggingface/distil-whisper/tree/main/training)。

#### Batch Size

值得注意的是，投机解码最大的提速出现在 batch size 为 1 时。批量投机解码要求**整个批次**的候选 token 全部通过验证才会被接受：某一位上只要有一个样本的 token 不匹配，该位置之后的所有候选 token 都会被丢弃。因此投机解码更偏向小批量。实践中，我们发现直到 batch size 4，投机解码都还有正收益；超过 4 之后，反而比单用主模型更慢。完整结果见 [Distil-Whisper 论文](https://arxiv.org/pdf/2311.00430.pdf)的 D.3 节。

## 结论

这篇博客介绍了投机解码这一推理策略在 Whisper 语音转写上的应用。我们展示了如何在数学上保证输出不变的前提下获得 2 倍提速。鉴于额外辅助模型的开销极低、且转写结果有一致性保证，推荐把投机解码作为现有 Whisper 管线的直接替代来尝试。
