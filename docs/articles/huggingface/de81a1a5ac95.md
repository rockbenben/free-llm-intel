# 模型卡

## 引言

模型卡是理解、分享和改进机器学习模型的重要文档框架。做得好的模型卡可以充当*边界对象（boundary object）*——一件让背景和目标各异的、想要理解模型的人都能使用的单一制品，包括开发者、学生、政策制定者、伦理学家，以及受机器学习模型影响的人。

今天，我们上线了一个[模型卡创作工具](https://huggingface.co/spaces/huggingface/Model_Cards_Writing_Tool)和一本[模型卡指南](https://huggingface.co/docs/hub/model-card-guidebook)，详细说明如何填写模型卡、相关用户研究，以及 ML 文档的最先进进展。这项工作建立在许多人和其他组织的成果之上，着重*包容*背景与角色各异的人群。我们希望它成为通往改进 ML 文档道路上的垫脚石。

总而言之，今天我们发布：

- 一个[模型卡创作工具](https://huggingface.co/spaces/huggingface/Model_Cards_Writing_Tool)，让创建模型卡无需编程，也帮助团队分工完成不同章节。
- 一个更新的模型卡模板，发布于 [`huggingface_hub` 库](https://github.com/huggingface/huggingface_hub/blob/main/src/huggingface_hub/templates/modelcard_template.md)，汇集了学术界与业界在模型卡上的成果。
- 一份[带注释的模型卡模板](https://huggingface.co/docs/hub/model-card-annotated)，详细说明如何填写卡片。
- 一份关于 Hugging Face 内部模型卡使用情况的[用户研究](https://huggingface.co/docs/hub/model-cards-user-studies)。
- 一份关于模型文档最新进展的[全景分析与文献综述](https://huggingface.co/docs/hub/model-card-landscape-analysis)。

## 迄今为止的模型卡

自 [Mitchell 等人（2018）](https://arxiv.org/abs/1810.03993)提出模型卡——灵感来自自然语言处理的数据声明（Data Statements）[(Bender & Friedman, 2018)](https://aclanthology.org/Q18-1041/)和数据集说明书（Datasheets for Datasets）[(Gebru et al., 2018)](https://www.fatml.org/media/documents/datasheets_for_datasets.pdf)这两大文档框架工作——以来，机器学习文档的全景已不断扩展演化。针对数据、模型和 ML 系统的大量文档工具和模板被提出和开发——这背后是数百名研究者、受影响社区成员、倡导者和其他利益相关者的卓越工作。关于 ML 文档与负责任的 AI 变革理论之间关系的重要讨论，也塑造了 ML 文档生态的这些发展。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/121_model-cards/MC_landscape.png) 
  ML 文档迄今的工作面向不同受众。我们今天分享的工作把其中许多想法汇聚到了一起。

## 我们的工作

我们的工作呈现了模型卡当下所处位置以及未来可能去向的观点。我们对不断增长的 ML 文档工具全景做了广泛分析，并在 Hugging Face 内部开展用户访谈，以补充我们对模型卡多元观点的理解。我们还为 Hugging Face Hub 上的 ML 模型创建或更新了几十张模型卡，基于所有这些经验，我们提出了一个新的模型卡模板。

### 标准化模型卡结构

通过背景研究和用户研究（在[指南](https://huggingface.co/docs/hub/model-card-guidebook)中有进一步讨论），我们旨在确立大众所理解的"模型卡"的新标准。

基于这些发现，我们创建了一个新的模型卡模板，不仅标准化了 HF 模型卡的结构和内容，还提供了默认提示文本。这些文本旨在帮助撰写模型卡各章节，特别关注偏差、风险与局限（Bias, Risks and Limitations）部分。

### 可及性与包容

为了降低创建模型卡的门槛，我们设计了[模型卡撰写工具](https://huggingface.co/spaces/huggingface/Model_Cards_Writing_Tool)——一个具有图形用户界面（GUI）的工具，让拥有不同技能与角色的个人和团队可以轻松协作创建模型卡，无需写代码或 markdown。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/121_model-cards/upload_a_mc.gif)

撰写工具鼓励还没写过模型卡的人更轻松地创建它们。对以前写过模型卡的人，这种方式邀请他们在提示信息之上继续补充——同时把模型文档的伦理性内容放在中心位置。

随着 ML 与不同领域的交织日益加深，以可及性、伦理与包容为核心的协作式开源 ML 流程，是机器学习生命周期中至关重要的一环，也是 ML 文档的垫脚石。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/121_model-cards/vines_idea.jpg) 
  今天的发布位于更大的 ML 文档生态之中：数据和模型文档已被众多科技公司采纳，包括 Hugging Face 🤗。我们优先推进了数据集卡和模型卡的"仓库卡（Repository Cards）"，强调多学科交叉。沿着这条路线继续，这个模型卡创建 UI 工具专注包容性，为不同背景的人提供格式与提示指引，帮助创建卡片。

## 行动号召

让我们向前看

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/121_model-cards/looking_ahead.png)

这项工作是基于对 ML 文档制品诸多实现方式的全景分析所得的模型卡当前状态的"*快照*"。模型卡指南与这些发现代表了对模型卡现状与更高愿景的多种视角之一。

- Hugging Face 生态将持续改进通过[代码](https://huggingface.co/docs/huggingface_hub/how-to-model-cards)和[用户界面](https://huggingface.co/spaces/huggingface/Model_Cards_Writing_Tool)简化模型卡创建的方法，包括把更多功能直接构建进仓库和产品。
- 随着我们进一步发展诸如 [Evaluate on the Hub](https://huggingface.co/blog/eval-on-the-hub) 之类的模型工具，我们会把其用法整合进模型卡开发工作流。例如，当跨分组因素自动评估模型性能变得更容易时，这些结果将可以导入模型卡。
- 研究模型与模型卡的配对仍有更多工作要做，例如构建研究论文 → 模型文档的管道，让从论文到模型卡创建变得轻而易举。这将实现更大范围的跨领域触达和模型文档的进一步标准化。

我们持续学习模型卡如何被创建和使用、以及卡片对模型使用的影响。基于这些学习，我们将进一步更新模型卡模板、说明和 Hub 集成。

当我们努力纳入更多声音和利益相关者的模型卡使用场景时，[收藏我们的模型卡撰写工具并试一试](https://huggingface.co/spaces/huggingface/Model_Cards_Writing_Tool)吧！

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/121_model-cards/like_the_space.gif)

我们期待了解你对模型卡、我们的模型卡撰写 GUI 的想法，以及 AI 文档如何赋能你的领域。🤗
