# 介绍 *smolagents*：一个构建智能体的简单库

作者：Aymeric Roucher（m-ric）、merve、Thomas Wolf（thomwolf）

今天我们发布 [`smolagents`](https://github.com/huggingface/smolagents)——一个非常简单的库，为语言模型解锁智能体（agentic）能力。先来一眼：

```
from smolagents import CodeAgent, DuckDuckGoSearchTool, HfApiModel

agent = CodeAgent(tools=[DuckDuckGoSearchTool()], model=HfApiModel())

agent.run("How many seconds would it take for a leopard at full speed to run through Pont des Arts?")
```

## 🤔 什么是智能体？

任何高效的 AI 系统都需要给 LLM 某种访问真实世界的途径：比如调用搜索工具获取外部信息，或操作某些程序来完成任务。换句话说，LLM 应该拥有***能动性（agency）***。智能体程序就是 LLM 通向外部世界的门户。

AI 智能体是**由 LLM 输出来控制工作流的程序**。

任何使用 LLM 的系统都会把 LLM 的输出融入代码。LLM 输入对代码工作流的影响程度，就是 LLM 在该系统中的能动性级别。

注意按这个定义，"智能体"不是非黑即白的 0/1 概念：相反，"能动性"在一个连续谱上演化——取决于你在工作流中给 LLM 多大权力。

下表展示了不同系统的能动性差异：

| 能动性级别 | 描述 | 通常的叫法 | 示例模式 |
| --- | --- | --- | --- |
| ☆☆☆ | LLM 输出对程序流程无影响 | 简单处理器 | `process_llm_output(llm_response)` |
| ★☆☆ | LLM 输出决定基本控制流 | 路由器 | `if llm_decision(): path_a() else: path_b()` |
| ★★☆ | LLM 输出决定函数执行 | 工具调用 | `run_function(llm_chosen_tool, llm_chosen_args)` |
| ★★★ | LLM 输出控制迭代与程序继续运行 | 多步智能体 | `while llm_should_continue(): execute_next_step()` |
| ★★★ | 一个智能体工作流可以启动另一个智能体工作流 | 多智能体 | `if llm_trigger(): execute_agent()` |

多步智能体的代码结构是这样的：

```
memory = [user_defined_task]
while llm_should_continue(memory): # this loop is the multi-step part
    action = llm_get_next_action(memory) # this is the tool-calling part
    observations = execute_action(action)
    memory += [action, observations]
```

这个系统在一个循环里运行，每一步执行一个新动作（动作可以涉及调用一些预定义的*工具*——其实就是函数），直到观察结果让它判断当前状态已满足、任务已解决。下面是一个多步智能体解决简单数学题的例子：

## ✅ 什么时候该用智能体 / ⛔ 什么时候别用

当你需要 LLM 来决定应用的工作流时，智能体很有用。但它们常常是大炮打蚊子。关键问题是：我真的需要工作流的灵活性才能高效解决手头的任务吗？如果预定好的工作流经常不够用，就说明你需要更多灵活性。举个例子：你在做一个处理冲浪旅行网站客户请求的应用。

你可以提前知道请求只会落在两个桶里（按用户选择），并且每种情况都有预定义的工作流。

- 想了解行程信息？⇒ 给他们一个搜索栏去搜你的知识库
- 想和销售聊？⇒ 让他们填联系表单

如果这套确定性工作流能满足所有查询，那就尽管全部写死！这会给你一个 100% 可靠的系统，没有让不可预测的 LLM 掺和进来引入错误的风险。为了简单和稳健，建议尽量向"不使用任何智能体行为"收敛。

但如果工作流没法提前确定得这么好怎么办？

比如用户想问：`"我周一能来，但忘带护照，可能拖到周三。周二早上带我去海边、带上我的装备可以吗？要有取消保险。"` 这个问题牵涉很多因素，上面预设的标准大概没有一个能覆盖这个请求。

如果预定工作流经常不够用，就说明你需要更多灵活性。

这正是智能体架构帮上忙的地方。

上面的例子里，你可以做一个多步智能体，让它接入天气预报 API、用 Google Maps API 算路程、查员工排班面板，再加一个基于你知识库的 RAG 系统。

直到最近，计算机程序还局限于预定义工作流，靠堆砌 if/else 开关来应对复杂性。它们聚焦极窄的任务，比如"算这些数的和"或"找这张图的最短路径"。但事实上，大多数现实任务（比如我们的旅行例子）并不适合预定义工作流。智能体系统把真实世界的广阔任务空间向程序打开了！

## 代码智能体

在多步智能体中，每一步 LLM 都要以调用外部工具的形式写一个动作。常见的写法（Anthropic、OpenAI 及其他家都在用）大同小异："把动作写成工具名加参数的 JSON，然后解析它，知道该执行哪个工具、传什么参数"。

[多](https://huggingface.co/papers/2402.01030)[篇](https://huggingface.co/papers/2411.01747)[研究论文](https://huggingface.co/papers/2401.00812)已经表明：让 LLM 用代码来调用工具要好得多。

原因很简单——*我们人类发明编程语言，恰恰就是为了把"计算机执行的动作"表达得最好*。如果 JSON 片段是更好的表达方式，那 JSON 就该是第一编程语言，写程序就得生不如死。

下图出自 [Executable Code Actions Elicit Better LLM Agents](https://huggingface.co/papers/2402.01030)，展示了用代码写动作的一些优势：

用代码而不是类 JSON 片段来写动作，在以下方面更好：

- **可组合性**：你能把一个 JSON 动作嵌套进另一个，或定义一组 JSON 动作留着以后复用吗？就像定义一个 python 函数那样。
- **对象管理**：像 `generate_image` 这种动作的输出，你怎么用 JSON 存？
- **通用性**：代码生来就能简洁地表达计算机能做的任何事。
- **在 LLM 训练数据中的代表性**：LLM 的训练数据里已经包含大量高质量代码，意味着它们早就为这种表达受过训！

## 介绍 *smolagents*：让智能体变简单 🥳

我们构建 [`smolagents`](https://github.com/huggingface/smolagents) 的目标是：

✨ **简单**：智能体的逻辑只有约几千行代码（见[这个文件](https://github.com/huggingface/smolagents/blob/main/src/smolagents/agents.py)）。我们把抽象保持在原始代码之上的最小形态！

🧑‍💻 **对代码智能体的一等支持**——也就是用代码写动作的智能体（区别于"用智能体来写代码"）。为了安全，我们支持在 [E2B](https://e2b.dev/) 提供的沙箱环境中执行代码。

- 在此之上，[`CodeAgent`](https://huggingface.co/docs/smolagents/reference/agents#smolagents.CodeAgent) 类之外，我们仍然支持标准的 [`ToolCallingAgent`](https://huggingface.co/docs/smolagents/reference/agents#smolagents.ToolCallingAgent)，它以 JSON/文本块形式写动作。

🤗 **Hub 集成**：你可以把工具分享到 Hub、从 Hub 加载工具，后续还会有更多！

🌐 **支持任意 LLM**：既支持从 Hub 以 `transformers` 版本加载的模型或通过我们的推理 API 使用的模型，也通过 [LiteLLM](https://www.litellm.ai/) 集成支持 OpenAI、Anthropic 等的模型。

[`smolagents`](https://github.com/huggingface/smolagents) 是 [`transformers.agents`](https://huggingface.co/blog/agents) 的继任者；随着后者未来弃用，将由 smolagents 接替它。

### 构建一个智能体

构建智能体至少需要两个要素：

- `tools`：智能体可用的工具列表
- `model`：作为智能体引擎的 LLM。

`model` 可以用任意 LLM：通过我们的 `HfApiModel` 类使用开放模型（借助 Hugging Face 免费推理 API，就像上面豹子的例子），或用 `LiteLLMModel` 借助 [litellm](https://github.com/BerriAI/litellm) 从 100 多种云端 LLM 中挑选。

工具方面，你只要写一个函数：输入输出带类型注解，docstring 里描述输入参数，再用 `@tool` 装饰器把它变成工具。

下面是如何做一个从 Google Maps 获取旅行时间的自定义工具，并把它用在旅行规划智能体里：

```
from typing import Optional
from smolagents import CodeAgent, HfApiModel, tool

@tool
def get_travel_duration(start_location: str, destination_location: str, transportation_mode: Optional[str] = None) -> str:
    """Gets the travel time between two places.

    Args:
        start_location: the place from which you start your ride
        destination_location: the place of arrival
        transportation_mode: The transportation mode, in 'driving', 'walking', 'bicycling', or 'transit'. Defaults to 'driving'.
    """
    import os   # All imports are placed within the function, to allow for sharing to Hub.
    import googlemaps
    from datetime import datetime

    gmaps = googlemaps.Client(os.getenv("GMAPS_API_KEY"))

    if transportation_mode is None:
        transportation_mode = "driving"
    try:
        directions_result = gmaps.directions(
            start_location,
            destination_location,
            mode=transportation_mode,
            departure_time=datetime(2025, 6, 6, 11, 0), # At 11, date far in the future
        )
        if len(directions_result) == 0:
            return "No way found between these places with the required transportation mode."
        return directions_result[0]["legs"][0]["duration"]["text"]
    except Exception as e:
        print(e)
        return e

agent = CodeAgent(tools=[get_travel_duration], model=HfApiModel(), additional_authorized_imports=["datetime"])

agent.run("Can you give me a nice one-day trip around Paris with a few locations and the times? Could be in the city or outside, but should fit in one day. I'm travelling only with a rented bicycle.")
```

经过几步收集旅行时间、做计算之后，智能体给出这个最终方案：

```
One-day Paris bike trip itinerary:
1. Start at Eiffel Tower at 9:00 AM.
2. Sightseeing at Eiffel Tower until 10:30 AM.
3. Travel to Notre-Dame Cathedral at 10:46 AM.
4. Sightseeing at Notre-Dame Cathedral until 12:16 PM.
5. Travel to Montmartre at 12:41 PM.
6. Sightseeing at Montmartre until 2:11 PM.
7. Travel to Jardin du Luxembourg at 2:33 PM.
8. Sightseeing at Jardin du Luxembourg until 4:03 PM.
9. Travel to Louvre Museum at 4:12 PM.
10. Sightseeing at Louvre Museum until 5:42 PM.
11. Lunch break until 6:12 PM.
12. Planned end time: 6:12 PM.
```

工具建好之后，分享到 Hub 也极其简单：

```
get_travel_duration.push_to_hub("{your_username}/get-travel-duration-tool")
```

结果见[这个 Space](https://huggingface.co/spaces/m-ric/get-travel-duration-tool)。工具的逻辑可以看 [Space 里的 tool.py 文件](https://huggingface.co/spaces/m-ric/get-travel-duration-tool/blob/main/tool.py)。可以看到，工具实际上被导出成了一个继承 [`Tool`](https://huggingface.co/docs/smolagents/reference/tools#smolagents.Tool) 类的类——这是我们所有工具的底层结构。

### 开放模型在智能体工作流上有多强？

我们用一些前沿模型构建了 [`CodeAgent`](https://huggingface.co/docs/smolagents/reference/agents#smolagents.CodeAgent) 实例，并在[这个基准](https://huggingface.co/datasets/m-ric/agents_medium_benchmark_2)上对比——它从若干不同基准收集问题，构成多样化的挑战组合。

[基准在这里](https://github.com/huggingface/smolagents/blob/main/examples/benchmark.ipynb)，有更详细的智能体设置说明，还能看到代码智能体与工具调用智能体的对比（剧透：代码方式更好）。

![benchmark of different models on agentic workflows](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/smolagents/benchmark_code_agents.png)

这个对比说明：开源模型现在可以和最好的闭源模型掰手腕了！
