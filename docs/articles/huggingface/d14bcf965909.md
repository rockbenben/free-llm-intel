# 使用 Sentence Transformers 训练与微调稀疏 Embedding 模型

Tom Aarsen（tomaarsen）

Arthur BRESNU（arthurbresnu）

[Sentence Transformers](https://sbert.net/) 是一个 Python 库，用于使用和训练稠密嵌入模型、重排序（cross encoder）模型和稀疏嵌入模型，服务于检索增强生成、语义搜索、语义文本相似度、释义挖掘等众多应用。本博客演示如何用它微调一个稀疏编码器/嵌入模型，并解释为什么要这么做。最终产出 [sparse-encoder/example-inference-free-splade-distilbert-base-uncased-nq](https://huggingface.co/sparse-encoder/example-inference-free-splade-distilbert-base-uncased-nq)——一个成本很低、在混合检索或"检索+重排"场景里表现特别好的模型。

微调稀疏嵌入模型涉及若干组件：模型、数据集、损失函数、训练参数、评估器，以及 Trainer 类。我会逐一讲解这些组件，并配上如何微调出强力稀疏嵌入模型的实用示例。

除了训练自己的模型，你还可以从 [Hugging Face Hub](https://huggingface.co/models?library=sentence-transformers&other=sparse) 上大量预训练稀疏编码器中挑选。为了帮你在这个快速扩张的领域里导航，我们整理了一个 [SPLADE Models 合集](https://huggingface.co/collections/sparse-encoder/splade-models-6862be100374b320d826eeaa)，收录了一些最值得关注的模型。
文档中的 [Pretrained Models](https://sbert.net/docs/sparse_encoder/pretrained_models.html) 列出了最有代表性的模型及其基准成绩。

## 什么是稀疏 Embedding 模型？

"嵌入模型"（embedding model）这个更大的范畴，指的是把输入（通常是文本）转换成捕捉其语义的向量表示（嵌入）的模型。与直接处理原始输入不同，你可以对这些嵌入做数学运算，得到可用于搜索、聚类、分类等各类任务的相似度分数。

稠密嵌入模型——也就是最常见的种类——产出的通常是低维向量（如 384、768、1024 维），其中大部分值非零。而稀疏嵌入模型产出高维向量（如 30000+ 维），其中大部分值为零。通常，稀疏嵌入中每个活跃维度（即取值非零的维度）对应模型词表中的一个具体 token，因而是可解释的。

来看一个例子：[naver/splade-v3](https://huggingface.co/naver/splade-v3)，一个最先进的稀疏嵌入模型：

```
from sentence_transformers import SparseEncoder

# Download from the 🤗 Hub
model = SparseEncoder("naver/splade-v3")

# Run inference
sentences = [
    "The weather is lovely today.",
    "It's so sunny outside!",
    "He drove to the stadium.",
]
embeddings = model.encode(sentences)
print(embeddings.shape)
# (3, 30522)

# Get the similarity scores for the embeddings
similarities = model.similarity(embeddings, embeddings)
print(similarities)
# tensor([[   32.4323,     5.8528,     0.0258],
#         [    5.8528,    26.6649,     0.0302],
#         [    0.0258,     0.0302,    24.0839]])

# Let's decode our embeddings to be able to interpret them
decoded = model.decode(embeddings, top_k=10)
for decoded, sentence in zip(decoded, sentences):
    print(f"Sentence: {sentence}")
    print(f"Decoded: {decoded}")
    print()
```

在这个例子里，嵌入是 30522 维的向量，每一维对应模型词表中的一个 token。`decode` 方法返回了嵌入中取值最高的前 10 个 token，让我们能看懂哪些 token 对嵌入的贡献最大。

我们甚至可以算出嵌入之间的交集/重叠，这在判断两段文本为何被认为相似或不相似时非常有用：

```
# Let's also compute the intersection/overlap of the first two embeddings
intersection_embedding = model.intersection(embeddings[0], embeddings[1])
decoded_intersection = model.decode(intersection_embedding)
print(decoded_intersection)
```

### 查询与文档扩展

神经稀疏嵌入模型的一个核心组件是**查询/文档扩展（query/document expansion）**。与 BM25 这类只匹配精确 token 的传统词汇方法不同，神经稀疏模型一般会自动用术语义相关的词扩展原始文本：

- **传统词汇方法（如 BM25）：** 只匹配文本中的精确 token
- **神经稀疏模型：** 自动用相关词做扩展

例如在上面代码的输出中，句子 "The weather is lovely today" 被扩展出了 "beautiful"、"cool"、"pretty"、"nice" 这些原文里没有的词；同样，"It's so sunny outside!" 被扩展出了 "weather"、"summer"、"sun"。

这种扩展让神经稀疏模型即使没有精确 token 匹配，也能命中语义相关的内容或同义词，能应对拼写错误，能克服词汇不匹配问题。这就是为什么 SPLADE 这类神经稀疏模型常能胜过传统词汇搜索方法，同时保留稀疏表示的效率优势。

但扩展也有风险。比如对 "What is the weather on Tuesday?" 做查询扩展，很可能也会扩展出 "monday"、"wednesday" 等，而这未必是我们想要的。

### 为什么要用稀疏 Embedding 模型？

简单说，神经稀疏嵌入模型恰好卡在一个很有价值的生态位：介于 BM25 等传统词汇方法与 Sentence Transformers 这类稠密嵌入模型之间。它们有以下优势：

- **混合潜力：** 与稠密模型搭配非常有效，稠密模型在词法匹配重要的搜索中常常吃力
- **可解释：** 你能确切看到哪些 token 促成了匹配
- **性能：** 在许多检索任务上与稠密模型持平甚至更强

本博客中，"稀疏嵌入模型"和"稀疏编码器模型"两个叫法会互换使用。

## 为什么要微调？

大多数（神经）稀疏嵌入模型都采用前述的查询/文档扩展，因此即使两段文本没有一个相同的词，只要含义几乎一致也能匹配上。简单说，模型必须识别同义词，这些词才能被放进最终的嵌入里。

多数开箱即用的稀疏嵌入模型能轻松认出 "supermarket"、"food"、"market" 是包含 "grocery" 的文本的有用扩展，但比如：

- "The patient complained of severe cephalalgia."

扩展出来的是：

```
'##lal', 'severe', '##pha', 'ce', '##gia', 'patient', 'complaint', 'patients', 'complained', 'warning', 'suffered', 'had', 'disease', 'complain', 'diagnosis', 'syndrome', 'mild', 'pain', 'hospital', 'injury'
```

而我们期望它扩展出 "headache"——"cephalalgia"（头痛）的日常说法。这类例子还包括：认不出 "Java" 是一门编程语言、"Audi" 是造汽车的、"NVIDIA" 是做显卡的公司。

通过微调，模型可以学会只聚焦于对你重要的领域和/或语言。

## 训练组件

训练 Sentence Transformer 模型涉及以下组件：

- [**模型（Model）**](https://huggingface.co/blog/train-sparse-encoder#model)：要训练或微调的模型，可以是预训练的 Sparse Encoder 模型，也可以是一个基座模型。
- [**数据集（Dataset）**](https://huggingface.co/blog/train-sparse-encoder#dataset)：用于训练与评估的数据。
- [**损失函数（Loss Function）**](https://huggingface.co/blog/train-sparse-encoder#loss-function)：量化模型表现并引导优化过程的函数。
- [**训练参数（Training Arguments）**](https://huggingface.co/blog/train-sparse-encoder#training-arguments)（可选）：影响训练表现以及跟踪/调试的参数。
- [**评估器（Evaluator）**](https://huggingface.co/blog/train-sparse-encoder#evaluator)（可选）：在训练前、中、后评估模型的工具。
- [**Trainer**](https://huggingface.co/blog/train-sparse-encoder#trainer)：把模型、数据集、损失函数及其他组件组织到一起完成训练。

## 模型

Sparse Encoder 模型由一串[模块（Modules）](https://sbert.net/docs/package_reference/sentence_transformer/models.html)、[Sparse Encoder 专属模块](https://sbert.net/docs/package_reference/sparse_encoder/models.html)或[自定义模块](https://sbert.net/docs/sentence_transformer/usage/custom_models.html#advanced-custom-modules)组成，非常灵活。如果你想继续微调一个已有的 Sparse Encoder 模型（比如它有 [modules.json 文件](https://huggingface.co/naver/splade-cocondenser-ensembledistil/blob/main/modules.json)），完全不用关心它用了哪些模块：

```
from sentence_transformers import SparseEncoder

model = SparseEncoder("naver/splade-cocondenser-ensembledistil")
```

但如果你想从别的 checkpoint 或从零开始训练，以下是最常用的几种架构：

### Splade

Splade 模型使用 [`MLMTransformer`](https://sbert.net/docs/package_reference/sparse_encoder/models.html#sentence_transformers.sparse_encoder.models.MLMTransformer)，后接 [`SpladePooling`](https://sbert.net/docs/package_reference/sparse_encoder/models.html#sentence_transformers.sparse_encoder.models.SpladePooling) 模块。前者加载一个预训练的[掩码语言建模（MLM）Transformer 模型](https://huggingface.co/models?pipeline_tag=fill-mask)（如 [BERT](https://huggingface.co/google-bert/bert-base-uncased)、[RoBERTa](https://huggingface.co/FacebookAI/roberta-base)、[DistilBERT](https://huggingface.co/distilbert/distilbert-base-uncased)、[ModernBERT](https://huggingface.co/answerdotai/ModernBERT-base) 等），后者对 MLMHead 的输出做池化，得到一个词表大小的稀疏嵌入。

```
from sentence_transformers import models, SparseEncoder
from sentence_transformers.sparse_encoder.models import MLMTransformer, SpladePooling

# Initialize MLM Transformer (use a fill-mask model)
mlm_transformer = MLMTransformer("google-bert/bert-base-uncased")

# Initialize SpladePooling module
splade_pooling = SpladePooling(pooling_strategy="max")

# Create the Splade model
model = SparseEncoder(modules=[mlm_transformer, splade_pooling])
```

如果你给 SparseEncoder 传入的是一个 fill-mask 架构，这就是默认架构，所以用快捷方式更简单：

```
from sentence_transformers import SparseEncoder

model = SparseEncoder("google-bert/bert-base-uncased")
# SparseEncoder(
#   (0): MLMTransformer({'max_seq_length': 512, 'do_lower_case': False, 'architecture': 'BertForMaskedLM'})
#   (1): SpladePooling({'pooling_strategy': 'max', 'activation_function': 'relu', 'word_embedding_dimension': None})
# )
```

### Inference-free Splade

Inference-free Splade 使用一个 [`Router`](https://sbert.net/docs/package_reference/sentence_transformer/models.html#sentence_transformers.models.Router) 模块，为查询和文档配置不同的子模块。这类架构通常文档侧是传统 Splade 架构（[`MLMTransformer`](https://sbert.net/docs/package_reference/sparse_encoder/models.html#sentence_transformers.sparse_encoder.models.MLMTransformer) 后接 [`SpladePooling`](https://sbert.net/docs/package_reference/sparse_encoder/models.html#sentence_transformers.sparse_encoder.models.SpladePooling)），查询侧是 [`SparseStaticEmbedding`](https://sbert.net/docs/package_reference/sparse_encoder/models.html#sentence_transformers.sparse_encoder.models.SparseStaticEmbedding) 模块——对查询中的每个 token 直接返回一个预先算好的分数。

```
from sentence_transformers import SparseEncoder
from sentence_transformers.models import Router
from sentence_transformers.sparse_encoder.models import SparseStaticEmbedding, MLMTransformer, SpladePooling

# Initialize MLM Transformer for document encoding
doc_encoder = MLMTransformer("google-bert/bert-base-uncased")

# Create a router model with different paths for queries and documents
router = Router.for_query_document(
    query_modules=[SparseStaticEmbedding(tokenizer=doc_encoder.tokenizer, frozen=False)],
    # Document path: full MLM transformer + pooling
    document_modules=[doc_encoder, SpladePooling("max")],
)

# Create the inference-free model
model = SparseEncoder(modules=[router], similarity_fn_name="dot")
# SparseEncoder(
#   (0): Router(
#     (query_0_SparseStaticEmbedding): SparseStaticEmbedding ({'frozen': False}, dim:30522, tokenizer: BertTokenizerFast)
#     (document_0_MLMTransformer): MLMTransformer({'max_seq_length': 512, 'do_lower_case': False, 'architecture': 'BertForMaskedLM'})
#     (document_1_SpladePooling): SpladePooling({'pooling_strategy': 'max', 'activation_function': 'relu', 'word_embedding_dimension': None})
#   )
# )
```

这种架构用轻量的 SparseStaticEmbedding 实现了快速的查询侧处理——它可以被训练，本质上就是一组线性权重——而文档仍用完整的 MLM transformer 加 SpladePooling 处理。

> Inference-free Splade 特别适合对查询延迟要求苛刻的搜索应用，因为它把计算复杂度挪到了可以离线完成的文档索引阶段。

> 训练带 Router 模块的模型时，必须在 SparseEncoderTrainingArguments 里用 router_mapping 参数把训练数据集的列映射到正确的路由（"query" 或 "document"）。例如，如果你的数据集有 ["question", "answer"] 两列，可以这样映射：
> args = SparseEncoderTrainingArguments(
>     ...,
>     router_mapping={
>         "question": "query",
>         "answer": "document",
>     }
> )
> 
> 另外，建议给 SparseStaticEmbedding 模块设远高于模型其余部分的学习率。这可以通过 SparseEncoderTrainingArguments 的 learning_rate_mapping 参数，把参数名模式映射到各自的学习率。例如，想让 SparseStaticEmbedding 用 1e-3、其余部分用 2e-5：
> args = SparseEncoderTrainingArguments(
>     ...,
>     learning_rate=2e-5,
>     learning_rate_mapping={
>         r"SparseStaticEmbedding\.*": 1e-3,
>     }
> )

### 对比稀疏表示（Contrastive Sparse Representation，CSR）

CSR 模型出自论文 [Beyond Matryoshka: Revisiting Sparse Coding for Adaptive Representation](https://arxiv.org/pdf/2503.01776)，做法是在一个稠密 Sentence Transformer 模型（通常由 [`Transformer`](https://sbert.net/docs/package_reference/sentence_transformer/models.html#sentence_transformers.models.Transformer) 后接 [`Pooling`](https://sbert.net/docs/package_reference/sentence_transformer/models.html#sentence_transformers.models.Pooling) 模块组成）之上加一个 [`SparseAutoEncoder`](https://sbert.net/docs/package_reference/sparse_encoder/models.html#sentence_transformers.sparse_encoder.models.SparseAutoEncoder) 模块。从零初始化如下：

```
from sentence_transformers import models, SparseEncoder
from sentence_transformers.sparse_encoder.models import SparseAutoEncoder

# Initialize transformer (can be any dense encoder model)
transformer = models.Transformer("google-bert/bert-base-uncased")

# Initialize pooling
pooling = models.Pooling(transformer.get_word_embedding_dimension(), pooling_mode="mean")

# Initialize SparseAutoEncoder module
sparse_auto_encoder = SparseAutoEncoder(
    input_dim=transformer.get_word_embedding_dimension(),
    hidden_dim=4 * transformer.get_word_embedding_dimension(),
    k=256,  # Number of top values to keep
    k_aux=512,  # Number of top values for auxiliary loss
)
# Create the CSR model
model = SparseEncoder(modules=[transformer, pooling, sparse_auto_encoder])
```

如果你的基座模型是 1）稠密 Sentence Transformer 模型，或 2）非 MLM 的 Transformer 模型（MLM 模型默认按 Splade 加载），那么下面这个快捷方式会自动帮你初始化 CSR 模型：

```
from sentence_transformers import SparseEncoder

model = SparseEncoder("mixedbread-ai/mxbai-embed-large-v1")
# SparseEncoder(
#   (0): Transformer({'max_seq_length': 512, 'do_lower_case': False, 'architecture': 'BertModel'})
#   (1): Pooling({'word_embedding_dimension': 1024, 'pooling_mode_cls_token': True, 'pooling_mode_mean_tokens': False, 'pooling_mode_max_tokens': False, 'pooling_mode_mean_sqrt_len_tokens': False, 'pooling_mode_weightedmean_tokens': False, 'pooling_mode_lasttoken': False, 'include_prompt': True})
#   (2): SparseAutoEncoder({'input_dim': 1024, 'hidden_dim': 4096, 'k': 256, 'k_aux': 512, 'normalize': False, 'dead_threshold': 30})
# )
```
> 与（Inference-free）Splade 模型不同，CSR 模型产出的稀疏嵌入和基座模型的词表没有同尺寸关系。这意味着你不能像 Splade 模型那样直接解读"哪些词被激活了"——Splade 模型里每一维都对应词表中的一个具体 token。
> 除此之外，CSR 模型在表征维度较高的稠密编码器模型上（如 1024-4096 维）最能发挥作用。

### 架构选择指南

如果你拿不准该用哪种架构，这里有个速查指南：

- 想把一个已有的稠密嵌入模型稀疏化？是的话用 [**CSR**](https://huggingface.co/blog/train-sparse-encoder#contrastive-sparse-representation-csr)。
- 愿意牺牲一点性能换取瞬时查询推理？是的话用 [**Inference-free SPLADE**](https://huggingface.co/blog/train-sparse-encoder#inference-free-splade)。
- 其他情况用 [**SPLADE**](https://huggingface.co/blog/train-sparse-encoder#splade)。

### 数据格式

务必保证数据集格式与所选[损失函数](https://huggingface.co/blog/train-sparse-encoder#loss-function)匹配。检查两点：

- 如果你的损失函数需要*标签（Label）*（见 [Loss Overview](https://sbert.net/docs/sparse_encoder/loss_overview.html) 表格），数据集必须有名为 **"label"** 或 **"score"** 的列。
- 除 **"label"** 或 **"score"** 之外的所有列都被视为*输入（Inputs）*（见 [Loss Overview](https://sbert.net/docs/sparse_encoder/loss_overview.html) 表格）。这些列的数量必须等于所选损失的有效输入个数。列名不重要，**只有列的顺序重要**。

例如，若损失函数接受 `(anchor, positive, negative)` 三元组，那么数据集的第一、二、三列分别对应 `anchor`、`positive`、`negative`。这意味着第一、二列的文本应嵌入得尽量近，第一、三列的文本应嵌入得尽量远。这就是为什么数据集列顺序要视损失函数而定。

一个列为 `["text1", "text2", "label"]` 的数据集，其中 `"label"` 列是浮点相似度分数，它可以配合 `SparseCoSENTLoss`、`SparseAnglELoss` 和 `SparseCosineSimilarityLoss` 使用，因为：

- 数据集有这些损失要求的 "label" 列。
- 数据集有 2 个非标签列，正好等于这些损失需要的输入数。

如果列顺序不对，用 [`Dataset.select_columns`](https://huggingface.co/docs/datasets/main/en/package_reference/main_classes#datasets.Dataset.select_columns) 重排。另外用 [`Dataset.remove_columns`](https://huggingface.co/docs/datasets/main/en/package_reference/main_classes#datasets.Dataset.remove_columns) 删掉多余列（如 `sample_id`、`metadata`、`source`、`type`），否则它们会被当成输入。

## 损失函数

损失函数衡量模型在给定 batch 上的表现并引导优化过程。选哪个损失取决于你手头的数据和目标任务。完整清单见 [Loss Overview](https://sbert.net/docs/sparse_encoder/loss_overview.html)。

> 训练 SparseEncoder 时，按架构需要 SpladeLoss 或 CSRLoss 之一。它们是包装损失：在主损失函数之上加稀疏正则项，主损失必须作为参数传入。唯一能独立使用的损失是 SparseMSELoss，因为它做的是嵌入级蒸馏——直接复制教师的稀疏嵌入，天然保证稀疏。

多数损失函数只需传入正在训练的 `SparseEncoder` 加一些可选参数即可初始化，例如：

```
from datasets import load_dataset
from sentence_transformers import SparseEncoder
from sentence_transformers.sparse_encoder.losses import SpladeLoss, SparseMultipleNegativesRankingLoss

# Load a model to train/finetune
model = SparseEncoder("distilbert/distilbert-base-uncased")

# Initialize the SpladeLoss with a SparseMultipleNegativesRankingLoss
# This loss requires pairs of related texts or triplets
loss = SpladeLoss(
    model=model,
    loss=SparseMultipleNegativesRankingLoss(model=model),
    query_regularizer_weight=5e-5,  # Weight for query loss
    document_regularizer_weight=3e-5,
) 

# Load an example training dataset that works with our loss function:
train_dataset = load_dataset("sentence-transformers/natural-questions", split="train")
print(train_dataset)
"""
Dataset({
    features: ['query', 'answer'],
    num_rows: 100231
})
"""
```

**文档**

- [`SpladeLoss`](https://sbert.net/docs/package_reference/sparse_encoder/losses.html#sentence_transformers.sparse_encoder.losses.SpladeLoss)
- [`CSRLoss`](https://sbert.net/docs/package_reference/sparse_encoder/losses.html#sentence_transformers.sparse_encoder.losses.CSRLoss)
- [Losses API 参考](https://sbert.net/docs/package_reference/sparse_encoder/losses.html)

## 训练参数

[`SparseEncoderTrainingArguments`](https://sbert.net/docs/package_reference/sparse_encoder/training_args.html#sentence_transformers.sparse_encoder.training_args.SparseEncoderTrainingArguments) 类让你指定影响训练表现和跟踪/调试的参数。虽然是可选的，但多试这些参数能提升训练效率，也能帮你理解训练过程。

Sentence Transformers 文档里我整理了一些最有用的训练参数，推荐阅读 [Training Overview > Training Arguments](https://sbert.net/docs/sparse_encoder/training_overview.html#training-arguments)。

[`SparseEncoderTrainingArguments`](https://sbert.net/docs/package_reference/sparse_encoder/training_args.html#sentence_transformers.sparse_encoder.training_args.SparseEncoderTrainingArguments) 的初始化示例：

```
from sentence_transformers import SparseEncoderTrainingArguments

args = SparseEncoderTrainingArguments(
    # Required parameter:
    output_dir="models/splade-distilbert-base-uncased-nq",
    # Optional training parameters:
    num_train_epochs=1,
    per_device_train_batch_size=16,
    per_device_eval_batch_size=16,
    learning_rate=2e-5,
    warmup_ratio=0.1,
    fp16=True,  # Set to False if your GPU can't handle FP16
    bf16=False,  # Set to True if your GPU supports BF16
    batch_sampler=BatchSamplers.NO_DUPLICATES,  # Losses using "in-batch negatives" benefit from no duplicates
    # Optional tracking/debugging parameters:
    eval_strategy="steps",
    eval_steps=100,
    save_strategy="steps",
    save_steps=100,
    save_total_limit=2,
    logging_steps=100,
    run_name="splade-distilbert-base-uncased-nq",  # Used in W&B if `wandb` is installed
)
```

注意 `eval_strategy` 是 `transformers` `4.41.0` 版本引入的，之前的版本要用 `evaluation_strategy`。

## 评估器

可以给 [`SparseEncoderTrainer`](https://sbert.net/docs/package_reference/sparse_encoder/trainer.html#sentence_transformers.sparse_encoder.SparseEncoderTrainer) 传一个 `eval_dataset` 来获得训练期间的评估损失，但训练时如果能拿到更具体的指标就更好了。评估器（evaluator）就是用有意义的指标在训练前、中、后评估模型的。`eval_dataset` 和评估器可以都上、只上一个、或都不上，它们按 [`Training Arguments`](https://sbert.net/docs/sparse_encoder/training_overview.html#training-arguments) 中的 `eval_strategy` 和 `eval_steps` 触发评估。

以下是 Sentence Transformers 为 Sparse Encoder 模型实现的评估器：

| 评估器 | 所需数据 |
| --- | --- |
| [`SparseBinaryClassificationEvaluator`](https://sbert.net/docs/package_reference/sparse_encoder/evaluation.html#sentence_transformers.sparse_encoder.evaluation.SparseBinaryClassificationEvaluator) | 带类别标签的句对。 |
| [`SparseEmbeddingSimilarityEvaluator`](https://sbert.net/docs/package_reference/sparse_encoder/evaluation.html#sentence_transformers.sparse_encoder.evaluation.SparseEmbeddingSimilarityEvaluator) | 带相似度分数的句对。 |
| [`SparseInformationRetrievalEvaluator`](https://sbert.net/docs/package_reference/sparse_encoder/evaluation.html#sentence_transformers.sparse_encoder.evaluation.SparseInformationRetrievalEvaluator) | Queries（qid => 问题）、Corpus（cid => 文档）、相关文档（qid => set[cid]）。 |
| [`SparseNanoBEIREvaluator`](https://sbert.net/docs/package_reference/sparse_encoder/evaluation.html#sentence_transformers.sparse_encoder.evaluation.SparseNanoBEIREvaluator) | 无需数据。 |
| [`SparseMSEEvaluator`](https://sbert.net/docs/package_reference/sparse_encoder/evaluation.html#sentence_transformers.sparse_encoder.evaluation.SparseMSEEvaluator) | 教师模型要嵌入的来源句子和学生模型要嵌入的目标句子。可以是同一批文本。 |
| [`SparseRerankingEvaluator`](https://sbert.net/docs/package_reference/sparse_encoder/evaluation.html#sentence_transformers.sparse_encoder.evaluation.SparseRerankingEvaluator) | `{'query': '...', 'positive': [...], 'negative': [...]}` 字典列表。 |
| [`SparseTranslationEvaluator`](https://sbert.net/docs/package_reference/sparse_encoder/evaluation.html#sentence_transformers.sparse_encoder.evaluation.SparseTranslationEvaluator) | 两种语言之间的句对。 |
| [`SparseTripletEvaluator`](https://sbert.net/docs/package_reference/sparse_encoder/evaluation.html#sentence_transformers.sparse_encoder.evaluation.SparseTripletEvaluator) | (anchor, positive, negative) 三元组。 |

此外，[`SequentialEvaluator`](https://sbert.net/docs/package_reference/sentence_transformer/evaluation.html#sequentialevaluator) 可把多个评估器合成一个传给 [`SparseEncoderTrainer`](https://sbert.net/docs/package_reference/sparse_encoder/trainer.html#sentence_transformers.sparse_encoder.SparseEncoderTrainer)。

## Trainer

[`SparseEncoderTrainer`](https://sbert.net/docs/package_reference/sparse_encoder/trainer.html#sentence_transformers.sparse_encoder.SparseEncoderTrainer) 是把前面所有组件汇合的地方。只需给 trainer 指定模型、训练参数（可选）、训练数据集、评估数据集（可选）、损失函数、评估器（可选），就能开始训练。来看一个把所有组件组合在一起的脚本：

```
import logging

from datasets import load_dataset

from sentence_transformers import (
    SparseEncoder,
    SparseEncoderModelCardData,
    SparseEncoderTrainer,
    SparseEncoderTrainingArguments,
)
from sentence_transformers.models import Router
from sentence_transformers.sparse_encoder.evaluation import SparseNanoBEIREvaluator
from sentence_transformers.sparse_encoder.losses import SparseMultipleNegativesRankingLoss, SpladeLoss
from sentence_transformers.sparse_encoder.models import SparseStaticEmbedding, MLMTransformer, SpladePooling
from sentence_transformers.training_args import BatchSamplers

logging.basicConfig(format="%(asctime)s - %(message)s", datefmt="%Y-%m-%d %H:%M:%S", level=logging.INFO)

# 1. Load a model to finetune with 2. (Optional) model card data
mlm_transformer = MLMTransformer("distilbert/distilbert-base-uncased", tokenizer_args={"model_max_length": 512})
splade_pooling = SpladePooling(
    pooling_strategy="max", word_embedding_dimension=mlm_transformer.get_sentence_embedding_dimension()
)
router = Router.for_query_document(
    query_modules=[SparseStaticEmbedding(tokenizer=mlm_transformer.tokenizer, frozen=False)],
    document_modules=[mlm_transformer, splade_pooling],
)

model = SparseEncoder(
    modules=[router],
    model_card_data=SparseEncoderModelCardData(
        language="en",
        license="apache-2.0",
        model_name="Inference-free SPLADE distilbert-base-uncased trained on Natural-Questions tuples",
    ),
)

# 3. Load a dataset to finetune on
full_dataset = load_dataset("sentence-transformers/natural-questions", split="train").select(range(100_000))
dataset_dict = full_dataset.train_test_split(test_size=1_000, seed=12)
train_dataset = dataset_dict["train"]
eval_dataset = dataset_dict["test"]
print(train_dataset)
print(train_dataset[0])

# 4. Define a loss function
loss = SpladeLoss(
    model=model,
    loss=SparseMultipleNegativesRankingLoss(model=model),
    query_regularizer_weight=0,
    document_regularizer_weight=3e-3,
)

# 5. (Optional) Specify training arguments
run_name = "inference-free-splade-distilbert-base-uncased-nq"
args = SparseEncoderTrainingArguments(
    # Required parameter:
    output_dir=f"models/{run_name}",
    # Optional training parameters:
    num_train_epochs=1,
    per_device_train_batch_size=16,
    per_device_eval_batch_size=16,
    learning_rate=2e-5,
    learning_rate_mapping={r"SparseStaticEmbedding\.weight": 1e-3},  # Set a higher learning rate for the SparseStaticEmbedding module
    warmup_ratio=0.1,
    fp16=True,  # Set to False if you get an error that your GPU can't run on FP16
    bf16=False,  # Set to True if you have a GPU that supports BF16
    batch_sampler=BatchSamplers.NO_DUPLICATES,  # MultipleNegativesRankingLoss benefits from no duplicate samples in a batch
    router_mapping={"query": "query", "answer": "document"},  # Map the column names to the routes
    # Optional tracking/debugging parameters:
    eval_strategy="steps",
    eval_steps=1000,
    save_strategy="steps",
    save_steps=1000,
    save_total_limit=2,
    logging_steps=200,
    run_name=run_name,  # Will be used in W&B if `wandb` is installed
)

# 6. (Optional) Create an evaluator & evaluate the base model
dev_evaluator = SparseNanoBEIREvaluator(dataset_names=["msmarco", "nfcorpus", "nq"], batch_size=16)

# 7. Create a trainer & train
trainer = SparseEncoderTrainer(
    model=model,
    args=args,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
    loss=loss,
    evaluator=dev_evaluator,
)
trainer.train()

# 8. Evaluate the model performance again after training
dev_evaluator(model)

# 9. Save the trained model
model.save_pretrained(f"models/{run_name}/final")

# 10. (Optional) Push it to the Hugging Face Hub
model.push_to_hub(run_name)
```

这个示例里我从 [`distilbert/distilbert-base-uncased`](https://huggingface.co/distilbert/distilbert-base-uncased) 开始微调——它是一个还不是 Sparse Encoder 的基座模型。从这种基座开始训练，比微调已有的 Sparse Encoder 模型（如 [`naver/splade-cocondenser-ensembledistil`](https://huggingface.co/naver/splade-cocondenser-ensembledistil)）需要更多数据。

运行这个脚本后，[sparse-encoder/example-inference-free-splade-distilbert-base-uncased-nq](https://huggingface.co/sparse-encoder/example-inference-free-splade-distilbert-base-uncased-nq) 模型自动上传了。它在 NanoMSMARCO 上 NDCG@10 为 0.5241，在 NanoNFCorpus 上为 0.3299，在 NanoNQ 上为 0.5357——对一个只用 Natural Questions 数据集 10 万句对训练出来的 inference-free distilbert 模型来说，这是很好的成绩。

这个模型文档侧的稀疏嵌入平均只有 184 个活跃维度，查询侧平均 7.7 个活跃维度（即查询中的平均 token 数），对应稀疏度分别为 99.39% 和 99.97%。

所有这些信息都存放在自动生成的模型卡里，包括基座模型、语言、许可证、评估结果、训练与评估数据集信息、超参数、训练日志等等。不用你费任何额外功夫，你上传的模型就会包含潜在用户判断模型是否适合自己所需的全部信息。

### 多数据集训练

高性能模型通常同时在多个数据集上训练。[`SparseEncoderTrainer`](https://sbert.net/docs/package_reference/sparse_encoder/trainer.html#sentence_transformers.sparse_encoder.SparseEncoderTrainer) 简化了这件事：不需要把多个数据集转成同一种格式就能一起训练，甚至可以给每个数据集用不同的损失函数。多数据集训练的步骤：

- 用一组 [`datasets.Dataset`](https://huggingface.co/docs/datasets/main/en/package_reference/main_classes#datasets.Dataset) 实例组成的字典（或 [`datasets.DatasetDict`](https://huggingface.co/docs/datasets/main/en/package_reference/main_classes#datasets.DatasetDict)）作为 `train_dataset` 和 `eval_dataset`。
- （可选）若想给不同数据集用不同损失，用"数据集名 → 损失"的字典。

每个训练/评估 batch 只会包含来自其中一个数据集的样本。多个数据集取 batch 的顺序由 [`MultiDatasetBatchSamplers`](https://sbert.net/docs/package_reference/sentence_transformer/training_args.html#sentence_transformers.training_args.MultiDatasetBatchSamplers) 枚举决定，可通过 `multi_dataset_batch_sampler` 传给 [`SparseEncoderTrainingArguments`](https://sbert.net/docs/package_reference/sparse_encoder/training_args.html#sentence_transformers.sparse_encoder.training_args.SparseEncoderTrainingArguments)。可选值：

- `MultiDatasetBatchSamplers.ROUND_ROBIN`：各数据集轮流取 batch，直到某一个耗尽。这种策略可能用不完每个数据集的所有样本，但每个数据集被等量采样。
- `MultiDatasetBatchSamplers.PROPORTIONAL`（默认）：按各数据集大小成比例采样。所有样本都会用上，更大的数据集被采样得更频繁。

## 评估

我们用 NanoMSMARCO 数据集评估刚训练好的 inference-free SPLADE 模型，并与稠密检索方案对比。我们还会试验把稀疏与稠密向量结合的混合检索，以及用重排序进一步提升搜索质量。

运行我们对 [hybrid_search.py](https://github.com/UKPLab/sentence-transformers/blob/master/examples/sparse_encoder/applications/retrieve_rerank/hybrid_search.py) 脚本稍作修改后的版本，针对 NanoMSMARCO 数据集、使用这些模型得到如下结果：

- **稀疏**：[`sparse-encoder/example-inference-free-splade-distilbert-base-uncased-nq`](https://huggingface.co/sparse-encoder/example-inference-free-splade-distilbert-base-uncased-nq)（我们刚训练的模型）
- **稠密**：[`sentence-transformers/all-MiniLM-L6-v2`](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)
- **重排序**：[`cross-encoder/ms-marco-MiniLM-L6-v2`](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2)

| 稀疏 | 稠密 | 重排序 | NDCG@10 | MRR@10 | MAP |
| --- | --- | --- | --- | --- | --- |
| x |  |  | 52.41 | 43.06 | 44.20 |
|  | x |  | 55.40 | 47.96 | 49.08 |
| x | x |  | 62.22 | 53.02 | 53.44 |
| x |  | x | 66.31 | 59.45 | 60.36 |
|  | x | x | 66.28 | 59.43 | 60.34 |
| x | x | x | 66.28 | 59.43 | 60.34 |

稀疏与稠密的排名可以用 Reciprocal Rank Fusion（RRF）合并——这是一种把多个排名简单融合的方法。如果启用重排序，它会对上一步检索的结果重排。

结果表明在这个数据集上，稠密+稀疏排名融合非常能打：相比稠密和稀疏基线分别提升 12.3% 和 18.7%。简单说，稀疏与稠密检索混合是提高搜索性能的非常有效的手段。

此外，在任何排名上应用重排序器都能把性能提升到约 66.3 NDCG@10——这说明无论是稀疏、稠密还是混合（稠密+稀疏），相关文档都在其 top 100 内被找到了，重排序器再把它们排进 top 10。因此，把"稠密 → 重排序"管线换成"稀疏 → 重排序"管线，可能同时改善延迟与成本：

- 稀疏嵌入的存储可能更便宜。例如我们的模型对 MS MARCO 文档只用约 180 个活跃维度，而稠密模型通常要 1024 维。
- 一些稀疏编码器支持 inference-free 的查询处理，第一阶段检索近乎瞬时，效果类似 BM25 这样的词汇方案。

## 训练技巧

Sparse Encoder 模型有些小脾气，训练时要留意：

- 评估 Sparse Encoder 模型不能只看评估分数，还要看嵌入的稀疏度。毕竟稀疏度低意味着模型的嵌入存储昂贵、检索缓慢。
- 更强的 Sparse Encoder 模型几乎都是从更强的教师模型（例如 [CrossEncoder 模型](https://sbert.net/docs/cross_encoder/usage/usage.html)）蒸馏训练而来，而不是直接从文本句对或三元组训练。可参考 [SPLADE-v3 论文](https://arxiv.org/abs/2403.06789)，它用 [`SparseDistillKLDivLoss`](https://sbert.net/docs/package_reference/sparse_encoder/losses.html#sentence_transformers.sparse_encoder.losses.SparseDistillKLDivLoss) 和 [`SparseMarginMSELoss`](https://sbert.net/docs/package_reference/sparse_encoder/losses.html#sentence_transformers.sparse_encoder.losses.SparseMarginMSELoss) 做蒸馏。本文没有详细展开蒸馏，因为它需要更多数据准备，但蒸馏方案值得认真考虑。

## 向量数据库集成

训练好稀疏嵌入模型后，下一个关键步骤是把它高效部署到生产环境。向量数据库提供了大规模存储、索引和检索稀疏嵌入所需的基础设施。常见选择包括 Qdrant、OpenSearch、Elasticsearch、Seismic 等。

关于上述向量数据库的完整示例，参见[基于向量数据库的语义搜索文档](https://sbert.net/examples/sparse_encoder/applications/semantic_search/README.html#vector-database-search)，或直接看下面的 Qdrant 示例。

### Qdrant 集成示例

Qdrant 对稀疏向量支持出色，存储高效、检索迅速。下面是一个完整的实现示例：

### 前置条件：

- 本地运行（或可访问）的 Qdrant，详见 [Qdrant Quickstart](https://qdrant.tech/documentation/quickstart/)。
- 安装 Python Qdrant 客户端：`pip install qdrant-client `

这个示例演示如何为稀疏向量搜索配置 Qdrant：用稀疏编码器高效编码并索引文档、用稀疏向量构造搜索查询，并提供交互式查询界面。见下：

```
import time

from datasets import load_dataset
from sentence_transformers import SparseEncoder
from sentence_transformers.sparse_encoder.search_engines import semantic_search_qdrant

# 1. Load the natural-questions dataset with 100K answers
dataset = load_dataset("sentence-transformers/natural-questions", split="train")
num_docs = 10_000
corpus = dataset["answer"][:num_docs]

# 2. Come up with some queries
queries = dataset["query"][:2]

# 3. Load the model
sparse_model = SparseEncoder("naver/splade-cocondenser-ensembledistil")

# 4. Encode the corpus
corpus_embeddings = sparse_model.encode_document(
    corpus, convert_to_sparse_tensor=True, batch_size=16, show_progress_bar=True
)

# Initially, we don't have a qdrant index yet
corpus_index = None
while True:
    # 5. Encode the queries using the full precision
    start_time = time.time()
    query_embeddings = sparse_model.encode_query(queries, convert_to_sparse_tensor=True)
    print(f"Encoding time: {time.time() - start_time:.6f} seconds")

    # 6. Perform semantic search using qdrant
    results, search_time, corpus_index = semantic_search_qdrant(
        query_embeddings,
        corpus_index=corpus_index,
        corpus_embeddings=corpus_embeddings if corpus_index is None else None,
        top_k=5,
        output_index=True,
    )

    # 7. Output the results
    print(f"Search time: {search_time:.6f} seconds")
    for query, result in zip(queries, results):
        print(f"Query: {query}")
        for entry in result:
            print(f"(Score: {entry['score']:.4f}) {corpus[entry['corpus_id']]}, corpus_id: {entry['corpus_id']}")
        print("")

    # 8. Prompt for more queries
    queries = [input("Please enter a question: ")]
```
