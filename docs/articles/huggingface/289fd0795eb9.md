# 使用 Huggingface Transformers 和 Ray 实现检索增强生成

##### 本文由 Anyscale 团队的 [Amog Kamsetty](https://huggingface.co/amogkam) 投稿

[Huggingface Transformers](https://huggingface.co/) 最近加入了 [Retrieval Augmented Generation (RAG)](https://twitter.com/huggingface/status/1310597560906780680) 模型，一种新的 NLP 架构，它利用外部文档（如 Wikipedia）来扩充自身知识，并在知识密集型任务上取得最先进结果。在这篇博客里，我们把 [Ray](https://docs.ray.io/en/master/)——一个用于构建可扩展应用的库——集成进 RAG 的上下文文档检索机制。这使检索调用提速 2 倍，并改善了 RAG 分布式[微调](https://github.com/huggingface/transformers/tree/master/examples/research_projects/rag)的可扩展性。

### 什么是检索增强生成（RAG）？

[![alt_text](https://huggingface.co/blog/assets/12_ray_rag/rag_gif.gif)](https://huggingface.co/blog/assets/12_ray_rag/rag_gif.gif)

*RAG 概览。模型在执行过程中从外部数据集检索上下文文档。这些上下文文档与原始输入一起用于产生输出。GIF 取自 [Facebook 的原始博客](https://ai.facebook.com/blog/retrieval-augmented-generation-streamlining-the-creation-of-intelligent-natural-language-processing-models)。*

最近，[Huggingface](https://huggingface.co/) 与 [Facebook AI](https://ai.facebook.com/) 合作，把 [RAG](https://twitter.com/huggingface/status/1310597560906780680) 模型作为其 Transformers 库的一部分推出。

[RAG](https://ai.facebook.com/blog/retrieval-augmented-generation-streamlining-the-creation-of-intelligent-natural-language-processing-models/) 运作起来和任何其它 [seq2seq 模型](https://blog.keras.io/a-ten-minute-introduction-to-sequence-to-sequence-learning-in-keras.html)一样。不过 [RAG](https://ai.facebook.com/blog/retrieval-augmented-generation-streamlining-the-creation-of-intelligent-natural-language-processing-models/) 有一个中间组件，从外部知识库（如 Wikipedia 文本语料）检索上下文文档。这些文档随后与输入序列一起使用，并传入底层的 seq2seq [生成器](https://huggingface.co/blog/how-to-generate)。

这一步信息检索让 [RAG](https://ai.facebook.com/blog/retrieval-augmented-generation-streamlining-the-creation-of-intelligent-natural-language-processing-models/) 能利用多种知识来源——既包含模型参数里内化的知识，也包含上下文段落里的信息，从而在问答等任务上胜过其它最先进模型。你可以用 [Huggingface 提供的这个 demo](https://huggingface.co/rag/) 亲自试试！

### 扩大微调规模

这种上下文文档的检索对 RAG 的最先进结果至关重要，但也引入了额外的复杂性。当通过数据并行训练流程来扩大训练规模时，朴素的文档查找实现可能成为训练瓶颈。而且检索组件所用的**文档索引**往往很大，使得每个训练 worker 无法各自加载一份复制的索引。

RAG 微调的先前实现借助 [torch.distributed](https://pytorch.org/docs/stable/distributed.html) 通信包来做文档检索部分。然而，这种实现有时不够灵活、扩展性也有限。

取而代之，需要一个框架无关、对即席并发编程更灵活的实现。[Ray](https://ray.io/) 正合适。Ray 是一个简单却强大的 Python 库，用于通用的分布式与并行编程。用 Ray 做分布式文档检索，我们在每次检索调用上相比 `torch.distributed` 实现了 **2 倍加速**，并带来了整体更好的微调可扩展性。

### 用 Ray 做文档检索

[![alt_text](https://huggingface.co/blog/assets/12_ray_rag/torch_distributed_document_retrieval.png)](https://huggingface.co/blog/assets/12_ray_rag/torch_distributed_document_retrieval.png) *用 torch.distributed 实现做文档检索*

[torch.distributed](https://pytorch.org/docs/stable/distributed.html) 实现在文档检索上的主要缺点，是它依附于训练所用的同一个进程组，且只有 rank 0 训练 worker 把索引加载进内存。

结果，这个实现有一些局限：

- **同步瓶颈**：rank 0 worker 必须从所有 worker 接收输入、执行索引查询，再把结果发回其它 worker。这限制了多训练 worker 下的性能。
- **PyTorch 专属**：文档检索进程组必须依附于训练所用的现有进程组，意味着训练也必须用 PyTorch。

[![alt_text](https://huggingface.co/blog/assets/12_ray_rag/ray_arch_updated.png)](https://huggingface.co/blog/assets/12_ray_rag/ray_arch_updated.png) *用 Ray 实现做文档检索*

为克服这些局限，我们引入了一种基于 Ray 的新型分布式检索实现。借助 [Ray 的有状态 actor 抽象](https://docs.ray.io/en/master/actors.html)，多个独立于训练进程的进程被用来加载索引并处理检索查询。有了多个 Ray actor，检索不再是瓶颈，PyTorch 也不再是 RAG 的硬性要求。

如下所见，在 Ray 实现下，多 GPU 微调的检索性能更好。下面结果展示的是每次检索调用的秒数，我们看到随着训练所用 GPU 数增加，用 Ray 相比 `torch.distributed` 性能更优。而且，如果增加执行检索的 Ray 进程数，由于单一检索进程不再是瓶颈，我们在更多训练 worker 下也能获得更好的性能。

|  | 2 GPU | 3 GPU | 4 GPU |
| --- | --- | --- | --- |
| torch.distributed | 2.12 sec/retrieval | 2.62 sec/retrieve | 3.438 sec/retrieve |
| Ray 2 retrieval processes | 1.49 sec/retrieve | 1.539 sec/retrieve | 2.029 sec/retrieve |
| Ray 4 retrieval processes | 1.145 sec/retrieve | 1.484 sec/retrieve | 1.66 sec/retrieve |

*不同检索实现的性能对比。对每种文档检索实现，我们都以每 GPU 批大小 8 跑 500 个训练步，并测量在 rank 0 训练 worker 上为每个批次检索上下文文档所需的时间。如结果所示，使用多个检索进程能提升性能，尤其在向多 GPU 扩展训练时。*

### 我该如何使用它？

[Huggingface](https://huggingface.co/) 提供了一个基于 [PyTorch Lightning](https://github.com/PyTorchLightning/pytorch-lightning) 的[微调脚本](https://github.com/huggingface/transformers/tree/master/examples/research_projects/rag)，我们把它扩展为可选地加入 Ray 检索实现。

要试用它，先安装所需的依赖

```
pip install ray
pip install transformers
pip install -r transformers/examples/research_projects/rag/requirements.txt
```

然后，你可以指定你的数据路径和其它配置，运行 [finetune-rag-ray.sh](https://github.com/huggingface/transformers/blob/master/examples/research_projects/rag/finetune_rag_ray.sh)！

```
# Sample script to finetune RAG using Ray for distributed retrieval.

# Add parent directory to python path to access lightning_base.py
export PYTHONPATH="../":"${PYTHONPATH}"

# Start a single-node Ray cluster.
ray start --head

# A sample finetuning run, you need to specify data_dir, output_dir and model_name_or_path
# run ./examples/rag/finetune_rag_ray.sh --help to see all the possible options

python examples/rag/finetune_rag.py \
    --data_dir $DATA_DIR \
    --output_dir $OUTPUT_DIR \
    --model_name_or_path $MODEL_NAME_OR_PATH \
    --model_type rag_sequence \
    --fp16 \
    --gpus 8 \
    --profile \
    --do_train \
    --do_predict \
    --n_val -1 \
    --train_batch_size 8 \
    --eval_batch_size 1 \
    --max_source_length 128 \
    --max_target_length 25 \
    --val_max_target_length 25 \
    --test_max_target_length 25 \
    --label_smoothing 0.1 \
    --dropout 0.1 \
    --attention_dropout 0.1 \
    --weight_decay 0.001 \
    --adam_epsilon 1e-08 \
    --max_grad_norm 0.1 \
    --lr_scheduler polynomial \
    --learning_rate 3e-05 \
    --num_train_epochs 100 \
    --warmup_steps 500 \
    --gradient_accumulation_steps 1 \
    --distributed_retriever ray \
    --num_retrieval_workers 4

# Stop the Ray cluster.
ray stop
```

## 接下来是什么？

把 RAG 配合 [Huggingface transformers](https://github.com/huggingface/transformers/tree/master/examples/research_projects/rag) 和 [Ray 检索实现](https://github.com/huggingface/transformers/blob/master/examples/research_projects/rag/finetune_rag_ray.sh) 用于更快的分布式微调，你就能在你自己的知识密集型任务上用 RAG 做基于检索的生成。

另外，超参调优也是 transformer 微调的一个重要方面，能对[准确率产生巨大影响](https://medium.com/distributed-computing-with-ray/hyperparameter-optimization-for-transformers-a-guide-c4e32c6c989b)。要可扩展又轻松地做超参调优，看看 [Ray Tune](https://docs.ray.io/en/latest/tune/) 库。通过 [Ray Tune 与 PyTorch Lightning 的集成](https://medium.com/distributed-computing-with-ray/scaling-up-pytorch-lightning-hyperparameter-tuning-with-ray-tune-4bd9e1ff9929)，或[与 Huggingface transformers 的内建集成](https://huggingface.co/blog/ray-tune)，你可以跑实验为你的 RAG 模型找到完美的超参数。

最后，也请期待 [RAG](https://ai.facebook.com/blog/retrieval-augmented-generation-streamlining-the-creation-of-intelligent-natural-language-processing-models) 在 [Huggingface](https://huggingface.co/) 上可能的 Tensorflow 实现！

如果你打算试用 RAG+Ray 集成，欢迎在 [Ray Discourse](https://discuss.ray.io/) 分享你的经验，或加入 [Ray 社区 Slack](https://docs.google.com/forms/d/e/1FAIpQLSfAcoiLCHOguOm8e7Jnn-JJdZaCxPGjgVCvFijHB5PLaQLeig/viewform) 进一步讨论——我们很想听听你的声音！
