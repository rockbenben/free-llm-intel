## 什么是离线强化学习？

深度强化学习（RL）是构建决策智能体（agent）的一套框架。这些智能体的目标，是通过与环境进行试错交互、并以奖励作为唯一反馈信号，来学习最优行为（策略，policy）。

智能体的目标是最大化**其累积奖励，即回报（return）**。因为 RL 建立在奖励假说（reward hypothesis）之上：**所有目标都可以被描述为期望累积奖励的最大化。**

深度强化学习智能体**通过成批的经验数据来学习**。问题在于，它们如何收集这些数据？：

[![离线 vs 在线 RL](https://huggingface.co/blog/assets/58_decision-transformers/offlinevsonlinerl.gif)](https://huggingface.co/blog/assets/58_decision-transformers/offlinevsonlinerl.gif)

*在线与离线设置下强化学习的对比，图片取自[这篇文章](https://offline-rl.github.io/)*

在线强化学习中，**智能体直接收集数据**：它通过与环境交互来收集一批经验数据，然后立即（或经由 replay buffer）利用这些经验进行学习（更新策略）。

但这就意味着，你要么直接在真实世界中训练智能体，要么拥有一个模拟器。如果没有，你就得自己构建一个——这可能非常复杂（如何在一个环境中反映真实世界的复杂性？）、昂贵，并且不安全：如果模拟器存在缺陷，而利用这些缺陷能带来竞争优势，智能体就会去钻空子。

而在离线强化学习中，智能体只使用从其他智能体或人类演示中收集到的数据，**不与环境交互**。

流程如下：

- 使用一个或多个策略和/或人类交互来创建数据集。
- 在该数据集上运行离线 RL，学习一个策略。

这种方法有一个缺点：反事实查询（counterfactual queries）问题。如果我们的智能体决定做一件数据里没有覆盖的事，该怎么办？例如，在路口右转，而我们的数据集中没有这条轨迹。

关于这个问题已经存在一些解决方案；如果你想更深入地了解离线强化学习，可以观看[这个视频](https://www.youtube.com/watch?v=k08N5a0gG0A)。

## 初识 Decision Transformers

Decision Transformer 模型由 [Chen L. 等人的「Decision Transformer: Reinforcement Learning via Sequence Modeling」](https://arxiv.org/abs/2106.01345)提出。它把强化学习抽象为一个**条件序列建模问题**。

核心思想是：不再用 RL 方法（例如拟合一个价值函数，告诉我们要最大化回报（累积奖励）该采取什么动作）来训练策略，而是使用一个序列建模算法（Transformer）——给定期望回报、历史状态和动作，它会生成能够实现该期望回报的未来动作。换言之，这是一个以期望回报、历史状态和动作为条件的自回归模型，用来生成达成期望回报的未来动作。

这是强化学习范式的一次彻底转变：我们用生成式轨迹建模（对状态、动作、奖励序列的联合分布建模）来取代传统的 RL 算法。也就是说，在 Decision Transformers 中，我们并不最大化回报，而是生成一连串能够实现期望回报的未来动作。

流程如下：

- 我们将最近 K 个时间步输入 Decision Transformer，每个时间步有 3 个输入：Return-to-go（待获取回报）、State（状态）、Action（动作）。
- token 的嵌入方式取决于模态：状态是向量时用线性层，是图像帧时用 CNN 编码器。
- 输入由一个 GPT-2 模型处理，通过自回归建模预测未来动作。

[![Decision Transformers 架构](https://huggingface.co/blog/assets/58_decision-transformers/dt-architecture.gif)](https://huggingface.co/blog/assets/58_decision-transformers/dt-architecture.gif) *Decision Transformer 架构。状态、动作与回报经过按模态定制的线性嵌入后输入，并叠加位置化的情景时间步编码（positional episodic timestep encoding）。token 被送入 GPT 架构，在因果自注意力掩码（causal self-attention mask）下以自回归方式预测动作。图片来自 [1]。*

## 在 🤗 Transformers 中使用 Decision Transformer

Decision Transformer 模型现已作为 🤗 transformers 库的一部分提供。此外，我们还公开了[九个在 Gym 环境连续控制任务上预训练的模型 checkpoint](https://huggingface.co/models?other=gym-continous-control)。

*一个「专家级」Decision Transformers 模型，在 Gym Walker2d 环境中通过离线 RL 训练得到。*

### 安装该包

```
pip install git+https://github.com/huggingface/transformers
```

### 加载模型

使用 Decision Transformer 相对容易，但由于它是自回归模型，在每个时间步组装模型输入时需要多加留意。我们准备了[一个 Python 脚本](https://github.com/huggingface/transformers/blob/main/examples/research_projects/decision_transformer/run_decision_transformer.py)和[一个 Colab notebook](https://colab.research.google.com/drive/1K3UuajwoPY1MzRKNkONNRS3gS5DxZ-qF?usp=sharing)，演示如何使用这个模型。

在 🤗 transformers 库中加载一个预训练的 Decision Transformer 很简单：

```
from transformers import DecisionTransformerModel

model_name = "edbeeching/decision-transformer-gym-hopper-expert"
model = DecisionTransformerModel.from_pretrained(model_name)
```

### 创建环境

我们为 Gym 的 Hopper、Walker2D 和 Halfcheetah 提供了预训练 checkpoint。Atari 环境的 checkpoint 也即将上线。

```
import gym
env = gym.make("Hopper-v3")
state_dim = env.observation_space.shape[0] # state size
act_dim = env.action_space.shape[0] # action size
```

### 自回归预测函数

该模型执行的是[自回归预测（autoregressive prediction）](https://en.wikipedia.org/wiki/Autoregressive_model)：也就是说，当前时间步 **t** 做出的预测，会依次以前面各时间步的输出为条件。这个函数的内容相当丰富，我们会在注释里加以说明。

```
# Function that gets an action from the model using autoregressive prediction 
# with a window of the previous 20 timesteps.
def get_action(model, states, actions, rewards, returns_to_go, timesteps):
    # This implementation does not condition on past rewards
    
    states = states.reshape(1, -1, model.config.state_dim)
    actions = actions.reshape(1, -1, model.config.act_dim)
    returns_to_go = returns_to_go.reshape(1, -1, 1)
    timesteps = timesteps.reshape(1, -1)
    
    # The prediction is conditioned on up to 20 previous time-steps
    states = states[:, -model.config.max_length :]
    actions = actions[:, -model.config.max_length :]
    returns_to_go = returns_to_go[:, -model.config.max_length :]
    timesteps = timesteps[:, -model.config.max_length :]
    
    # pad all tokens to sequence length, this is required if we process batches
    padding = model.config.max_length - states.shape[1]
    attention_mask = torch.cat([torch.zeros(padding), torch.ones(states.shape[1])])
    attention_mask = attention_mask.to(dtype=torch.long).reshape(1, -1)
    states = torch.cat([torch.zeros((1, padding, state_dim)), states], dim=1).float()
    actions = torch.cat([torch.zeros((1, padding, act_dim)), actions], dim=1).float()
    returns_to_go = torch.cat([torch.zeros((1, padding, 1)), returns_to_go], dim=1).float()
    timesteps = torch.cat([torch.zeros((1, padding), dtype=torch.long), timesteps], dim=1)
    
    # perform the prediction
    state_preds, action_preds, return_preds = model(
            states=states,
            actions=actions,
            rewards=rewards,
            returns_to_go=returns_to_go,
            timesteps=timesteps,
            attention_mask=attention_mask,
            return_dict=False,)
    return action_preds[0, -1]
```

### 评估模型

要评估模型，我们还需要一些额外信息：训练期间使用的状态均值和标准差。幸运的是，每个 checkpoint 在 Hugging Face Hub 上的[模型卡（model card）](https://huggingface.co/edbeeching/decision-transformer-gym-hopper-expert)都提供了这些数据！

我们还需要为模型指定一个目标回报（target return）。这正是以回报为条件的离线强化学习的威力所在：我们可以通过目标回报来控制策略的表现。这在多人游戏场景中可能非常有用——比如把对手机器人的表现调整到适合玩家的难度。论文作者在这点上展示了一张很棒的图！

[![Results Decision Transformers](https://huggingface.co/blog/assets/58_decision-transformers/results-dt.png)](https://huggingface.co/blog/assets/58_decision-transformers/results-dt.png) *Decision Transformer 在以指定目标（期望）回报为条件时，采样（评估）所得的累积回报。上：Atari。下：D4RL medium-replay 数据集。图片来自 [1]。*

state_std = np.array(
    [0.15980862, 0.0446214,  0.14307782, 0.17629202, 0.5912333,  0.5899924,
         1.5405099,  0.8152689,  2.0173461,  2.4107876,  5.8440027,])

state_mean = torch.from_numpy(state_mean)
state_std = torch.from_numpy(state_std)

state = env.reset()
target_return = torch.tensor(TARGET_RETURN).float().reshape(1, 1)
states = torch.from_numpy(state).reshape(1, state_dim).float()
actions = torch.zeros((0, act_dim)).float()
rewards = torch.zeros(0).float()
timesteps = torch.tensor(0).reshape(1, 1).long()

# take steps in the environment
for t in range(max_ep_len):
    # add zeros for actions as input for the current time-step
    actions = torch.cat([actions, torch.zeros((1, act_dim))], dim=0)
    rewards = torch.cat([rewards, torch.zeros(1)])

    # predicting the action to take
    action = get_action(model,
                        (states - state_mean) / state_std,
                        actions,
                        rewards,
                        target_return,
                        timesteps)
    actions[-1] = action
    action = action.detach().numpy()

    # interact with the environment based on this action
    state, reward, done, _ = env.step(action)
    
    cur_state = torch.from_numpy(state).reshape(1, state_dim)
    states = torch.cat([states, cur_state], dim=0)
    rewards[-1] = reward

    target_return = torch.cat([target_return, pred_return.reshape(1, 1)], dim=1)
