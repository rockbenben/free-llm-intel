TLDR：随着我们压缩记忆次数的增加，Infini-attention 的性能会越来越差。据我们所知，[ring attention](https://x.com/Haojun_Zhao14/status/1815419356408336738)、[YaRN](https://arxiv.org/abs/2309.00071) 和 [rope scaling](https://arxiv.org/abs/2309.16039) 仍然是把预训练模型扩展到更长上下文的最佳方式。

## 第 0 节：引言

上下文长度是语言模型除性能之外最核心的属性之一。自 in-context learning（上下文学习）出现以来，往模型输入里添加相关信息变得越来越重要。于是上下文长度迅速从"段落"（BERT/GPT-1 的 512 token）涨到"页面"（GPT-2 和 GPT-3 分别为 1024/2048），再到"书"（Claude 的 128k），一路到"书库"（Gemini 的 1-10M token）。然而，把标准注意力扩展到这种长度依然极具挑战。

> Ring Attention 小简介：Ring Attention 由 UC Berkeley 的研究者在 2024 年首次提出 [link]（据我们所知）。这一工程技巧通过分块（blockwise）方式执行自注意力和前馈网络计算，并把序列维度分布到多张卡上，实现计算与通信并行，从而突破显存限制。

即便有 Ring Attention，要在 100 万 token 上下文、batch size 为 1 的设置下训练一个 [Llama 3 8B](https://arxiv.org/abs/2407.21783)，也需要 512 张 GPU。正如 scaling laws 所[展示](https://arxiv.org/abs/2001.08361)的，模型规模与下游性能强相关——模型越大效果越好（当然前提是都训练得当）。所以我们不仅要 100 万 token 的上下文，还要最大的模型（比如 Llama 3 8B、405B）也能有 100 万 token 上下文。而这样的资源，全世界只有少数几家公司具备。

> 回顾一下自注意力的内存复杂度
> 在标准注意力（非 flash-attention）中，序列里每个 token 都要关注其他所有 token，产生一个尺寸为 [seq_len, seq_len] 的注意力矩阵。对每一对 token 都要计算注意力分数，因此随着序列长度（seq_len）增加，内存和计算需求呈二次增长：注意力矩阵的内存是 O(seq_len^2)。例如序列长度增加 10 倍，内存需求就增加 100 倍。即使是 Flash Attention 这类内存高效注意力方法，内存仍随上下文长度线性增长，并且受单卡显存瓶颈限制——在今天的 GPU 上，最大上下文通常远低于 100 万 token。

受此驱动，我们尝试了一种替代标准注意力的方案：infini-attention。这篇论文由 Google 的研究者在 2024 年 4 月发布 [[link]](https://arxiv.org/abs/2404.07143)。Infini-attention 不再计算所有词之间的注意力分数，而是把序列切分成若干段（segment），把较早的段落压缩进一个固定大小的缓冲区（buffer），让下一段既能从更早的段落检索记忆，又只在当前段内部计算注意力分数。它的一个关键优势是：固定大小的缓冲区给总内存用量设了上限。另外，同一段内使用同一个 query 同时访问本段信息和压缩记忆，让我们能以很低的代价扩展预训练模型的上下文长度。理论上，由于所有早前段落的记忆只保存在一个缓冲区里，我们可以做到无限上下文。但现实中，压缩限制了能有效存储的信息量，问题因此变成：这样压缩出来的记忆到底有多少可用？

在纸面上理解一个新方法相对容易，但真正把它跑通往往是另一回事——而这段经历很少被人公开分享。出于这个考虑，我们决定分享复现 Infini-attention 论文的实验与心路历程：在调试过程中是什么支撑着我们（我们把 90% 的时间花在了调试一个收敛问题上），以及把事情做成可以有多难。

随着 Llama 3 8B（上下文上限 8k token）发布，我们想把这一长度扩展到 100 万 token，同时不让内存随之二次增长。本文将先解释 Infini-attention 的原理，然后说明我们的复现原则，描述最初的小规模实验，讨论遇到的挑战及应对方式，最后总结结论和尝试过的其他思路。想试用我们训练出的 checkpoint [[link]](https://huggingface.co/nanotron/llama3-8b-infini-attention)，可以在这个仓库里找到 [[link]](https://github.com/huggingface/nanotron/tree/xrsrke/infini_attention_this_actually_works)（注意：代码按现状提供，不作支持承诺）。

## 第 1 节：复现原则

在实现新方法时，我们发现以下几条规则很有帮助，并把它们作为大量工作的指导原则：

- **原则 1：** 从能给出有效信号的最小模型开始做实验，拿到好信号后再放大规模。
- **原则 2：** 永远训练一个扎实的基线（baseline）来衡量进展。
- **原则 3：** 要判断某个改动是否提升性能，就训练两个模型，除了被测改动外其余完全一致。

带着这些原则，我们来看看 Infini-attention 到底是怎么工作的。理解其机制对后续实验至关重要。

## 第 2 节：Infini-attention 如何工作

- 步骤 1：把输入序列切分成固定大小的小块，称为"段"（segment）。
- 步骤 2：在每个段内部计算标准的因果（causal）点积注意力。
- 步骤 3：用当前段的 query 向量从压缩记忆中检索相关信息。检索过程的数学定义如下：Amem = σ(Q)Ms−1 / σ(Q)zs−1，其中 Amem ∈ R^{N×d_value}：从记忆中检索到的内容，代表长期上下文；Q ∈ R^{N×d_key}：query 矩阵，N 是 query 数量，d_key 是每个 query 的维度；Ms−1 ∈ R^{d_key×d_value}：上一段传来的记忆矩阵，存储键值对；σ：非线性激活函数，具体是逐元素的 ELU+1；zs−1 ∈ R^{d_key}：归一化项。

```
import torch.nn.functional as F
from torch import einsum
from einops import rearrange

def _retrieve_from_memory(query_states, prev_memory, prev_normalization):
    ...
    sigma_query_states = F.elu(query_states) + 1
    retrieved_memory = einsum(
        sigma_query_states,
        prev_memory,
        "batch_size n_heads seq_len d_k, batch_size n_heads d_k d_v -> batch_size n_heads seq_len d_v",
    )

    denominator = einsum(
        sigma_query_states,
        prev_normalization,
        "batch_size n_heads seq_len d_head, batch_size n_heads d_head -> batch_size n_heads seq_len",
    )
    denominator = rearrange(
        denominator,
        "batch_size n_heads seq_len -> batch_size n_heads seq_len 1",
    )

    # NOTE: because normalization is the sum of all the keys, so each word should have the same normalization
    retrieved_memory = retrieved_memory / denominator
    return retrieved_memory
```

- 步骤 4：把局部上下文（来自当前段）和长期上下文（从压缩记忆中检索）结合起来生成最终输出，这样注意力输出就同时兼顾了短期与长期上下文。A = sigmoid(β) ⊙ Amem + (1 − sigmoid(β)) ⊙ Adot，其中 A ∈ R^{N×d_value}：组合后的注意力输出；sigmoid(β)：可学习的标量参数，控制长期记忆内容 Amem 与局部上下文之间的取舍；Adot ∈ R^{N×d_value}：当前段用点积注意力得到的输出。

- 步骤 5：把当前段的键值状态加进压缩记忆来完成更新，这样就能随时间积累上下文。Ms ← Ms−1 + σ(K)^T V；zs ← zs−1 + Σ_{t=1}^{N} σ(K_t)。其中 Ms ∈ R^{d_key×d_value}：当前段更新后的记忆矩阵，融入了新信息；K ∈ R^{N×d_key}：当前段的 key 矩阵，表示要存入的新键；V ∈ R^{N×d_value}：当前段的 value 矩阵，表示与新键关联的新值；K_t：key 矩阵中的第 t 个键向量；zs：当前段更新后的归一化项。

```
import torch

def _update_memory(prev_memory, prev_normalization, key_states, value_states):
    ...

    sigma_key_states = F.elu(key_states) + 1

    if prev_memory is None or prev_normalization is None:
        new_value_states = value_states
    else:
        numerator = einsum(
            sigma_key_states,
            prev_memory,
            "batch_size n_heads seq_len d_k, batch_size n_heads d_k d_v -> batch_size n_heads seq_len d_v",
        )
        denominator = einsum(
            sigma_key_states,
            prev_normalization,
            "batch_size n_heads seq_len d_k, batch_size n_heads d_k -> batch_size n_heads seq_len",
        )
        denominator = rearrange(
            denominator,
            "batch_size n_heads seq_len -> batch_size n_heads seq_len 1",
        )

        prev_v = numerator / denominator
        new_value_states = value_states - prev_v

    memory = torch.matmul(sigma_key_states.transpose(-2, -1), new_value_states)

    normalization = reduce(
        sigma_key_states,
        "batch_size n_heads seq_len d_head -> batch_size n_heads d_head",
        reduction="sum",
        ...
    )

    memory += prev_memory if prev_memory is not None else 0
    normalization += prev_normalization if prev_normalization is not None else 0

    return memory, normalization
```

理论理清了，接下来撸起袖子做真正的实验。先从小的开始，快速拿到反馈、快速迭代。

## 第 3 节：小规模的首批实验

Llama 3 8B 相当大，所以我们决定先从一个 200M 的 Llama 开始，用 Nanotron [[link]](https://github.com/huggingface/nanotron) 和 Fineweb 数据集 [[link]](https://huggingface.co/datasets/HuggingFaceFW/fineweb) 从零预训练 Infini-attention。在 200M 模型上拿到好结果后，再对 Llama 3 8B 做继续预训练。我们使用 200 万 token 的 batch size、256 的上下文长度、梯度裁剪 1、权重衰减 0.1；前 5,000 次迭代做线性预热（warmup），其余步数用余弦衰减，学习率为 3e-5。

**用 passkey 检索任务做评估**

passkey 检索任务由 EPFL 的研究者首次提出 [[link]](https://arxiv.org/abs/2305.16300)。该任务用于评估模型从长上下文中检索信息的能力，且信息的位置可控。给模型的提示格式如下：

`There is important info hidden inside a lot of irrelevant text. Find it and memorize them. I will quiz you about the important information there. The grass is green. The sky is blue. The sun is yellow. Here we go. There and back again. (repeat x times) The pass key is 9054. Remember it. 9054 is the pass key. The grass is green. The sky is blue. The sun is yellow. Here we go. There and back again. (repeat y times) What is the pass key? The pass key is`

如果模型输出中包含"针"（needle，上例中的 "9054"）就算成功，否则算失败。实验中，我们把针放在上下文的多个位置，即总上下文长度的 0%、5%、10%……95%、100%（0% 表示离生成位置最远）。例如上下文长度为 1024 token 时，把针放在 10% 处意味着它大约位于第 102 个 token。在每个深度位置，我们用 10 个不同样本测试模型并计算平均成功率。

**首批结果**

200M 小模型上的首批结果如下：

可以看到它大致能工作。观察生成样例，Infini-attention 会生成与前面段落相关的内容。

由于 Infini-attention 在预测第二段第一个 token 时以第一段的完整内容为条件，而它把第一个 token 生成为 "_grad"，这是个不错的信号。为了验证这个信号是不是假阳性，我们提出一个假设：也许只是因为给定第二段首 token 为 "_grad" 时，Infini-attention 总会生成 PyTorch 相关教程，碰巧与前面段落相关。于是我们做了一个健全性测试：唯一输入 token 就是 "_grad"，它生成了【此处原文有文本】。这说明它确实用到了记忆，只是用得不够好（无法检索出精确的针，也无法精确续写前段内容）。生成内容：


基于这些结果，模型看起来确实在使用压缩记忆。我们决定放大实验规模，对 Llama 3 8B 做继续预训练。不幸的是，当针被放在更早的段落时，模型无法通过 needle 评估。

我们决定检查所有层的 balance factor（平衡压缩记忆与非压缩记忆比例的因子）。根据 Figure 3a 和 Figure 3b，我们发现约 95% 的权重集中在 0.5 附近。回想一下，权重能否收敛到理想区间取决于两个因素：步长和梯度幅度。但 Adam 会把梯度归一化到幅度 1，于是问题变成：训练超参是否允许这次微调收敛？

## 第 4 节：研究收敛性？

我们模拟了在梯度处于良好区间（L2 范数为 0.01）时，训练过程中 balance 权重会变化多少。结果发现，按上一个 8B LLaMA3 微调实验的配置，权重绝对变化总量只有 0.03。由于 balance factor 初始化为 0（在本例中无所谓），最终的权重区间是 [0 - 0.03, 0 + 0.03] = [-0.03, 0.03]。

有依据的猜测是：infinity attention 要正常工作，global weights 应像论文里那样散布在 0 到 1 的区间。就上面的权重而言，sigmoid([-0.03, 0.03]) = tensor([0.4992, 0.5008])（与我们此前实验中 balance factor 约为 0.5 的结果吻合）。于是下一步我们决定给 balance factor 用更高的学习率（其他参数仍用 Llama 3 8B 的学习率），并显著增加训练步数，让 balance factor 至少能变化 4，这样如果梯度下降愿意，global weights 就能到达理想权重（sigmoid(-4) ≈ 0，sigmoid(4) ≈ 1）。

[![Figure 4a: generation](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/185_infini_attention/total_abs_change_in_adam.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/185_infini_attention/total_abs_change_in_adam.png)

我们还要注意到，由于梯度方向并不总是一致，会相互抵消，所以学习率和训练步数要显著大于绝对变化总量才够。回想 Llama 3 8B 的学习率是 3.0x10^-4，这意味着如果把该值用作全局学习率，门控（gating）根本不可能收敛。

> 结论：我们决定采用 3.0x10^-4 的全局学习率，以及 0.01 的门控学习率——这应该能让门控函数收敛。

用这些超参数，Infini-attention 的 balance factor 是可训练的了，但我们观察到 200M llama 的 loss 在 20B token 后变成 NaN（我们试过从 0.001 到 1.0e-6 的学习率）。我们检查了 20B token checkpoint（10k 训练步）处的若干生成样例，见 Figure 4a。模型现在能精确续写内容、记住身份（一旦记忆被屏蔽，它就输出垃圾）。

[![Figure 4b: generation](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/185_infini_attention/exp_51_generation.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/185_infini_attention/exp_51_generation.png)

[![Figure 4c: global weights across training steps](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/185_infini_attention/exp_51_global_weights_across_training_steps.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/185_infini_attention/exp_51_global_weights_across_training_steps.png)

但它仍然无法把一个段里的针检索到另一个段（在同一个段内检索则很稳定）。当针放在第 1 段（共 2 段）时，needle 评估完全失败（放在第 2 段时成功率 100%）。如 Figure 4b 所示，我们还观察到 balance factor 在 5,000 步之后就停止变化。虽然取得了一些进展，但还没脱离险境。balance factor 的表现仍不如我们所愿，我们决定继续深挖、做更多调整。

## 第 5 节：balance factor 不做权重衰减

再次仔细检查 balance factor，我们看到了一些进展：现在约 95% 的 head 的 global weight 落在 0.4 到 0.5 之间，没有任何 head 的 global weight 大于 0.6。但权重仍未进入理想区间。

我们想到另一个潜在原因：权重衰减（weight decay）会鼓励 balance factor 保持较小的 L2 范数，导致 sigmoid 值收敛在零附近，因子聚集在 0.5 周围。

还有一个可能的原因是 rollout 太小。200M 实验只用了 4 次 rollout，8B 实验只用了 2 次（8192**2）。更大的 rollout 应该能激励模型好好压缩并使用记忆。于是我们决定把 rollout 增加到 16 次并取消权重衰减。我们把上下文长度缩减到 1024，配 16 次 rollout，得到 64 的段长。

## 第 6 节：结论

遗憾的是，尽管有这些进展，我们在实验中仍觉得 Infini-attention 不够令人信服，尤其是不够可靠。在复现的这个阶段，我们依然认为 Ring Attention [[link]](https://x.com/Haojun_Zhao14/status/1815419356408336738)、YaRN [[link]](https://arxiv.org/abs/2309.00071) 和 rope scaling [[link]](https://arxiv.org/abs/2309.16039) 是把预训练模型扩展到更长上下文的更好选择。

这些技术对于超大规模模型（如 400B 及以上）仍然有巨大的资源需求。因此我们依然认为，探索压缩技术、或者把本文描述的这系列实验继续做下去，对整个社区都很有价值。我们也很期待跟进并尝试可能出现新技术，去克服当前工作的这些局限。

**要点回顾**

- 训练神经网络意味着什么：给它好的数据，搭好架构和训练配置以收到良好的梯度信号，然后让它收敛。
- Infini-attention 的长上下文性能随记忆压缩次数的增加而下降。
- 门控（gating）很关键；调整训练让门控收敛能改善 Infini-attention 的长上下文性能（但仍不够好）。
- 永远训练一个好的参考模型作为基线来衡量进展。
- 还有一个 bug 搞乱了注意力输出的维度，导致尽管训练全程 loss 在下降，模型仍然无法在段长范围内生成连贯文本。教训：即使你把模型的条件设置错了，梯度下降照样能找到降 loss 的路子。但模型不会按预期工作，所以一定要跑评估。
