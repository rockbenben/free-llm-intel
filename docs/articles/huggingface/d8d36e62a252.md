## 什么是 Mixtral 8x7b？

Mixtral 的架构与 Mistral 7B 相似，但有个巧妙之处：它实际上是把 8 个"专家"模型合而为一，靠的是混合专家（Mixture of Experts, MoE）技术。对 Transformer 模型来说，实现方式是把部分前馈层（Feed-Forward）替换为稀疏 MoE 层。MoE 层内含一个路由网络（router），决定哪些 token 交给哪些专家处理最有效率。Mixtral 每个时间步选两个专家，这让模型的解码速度相当于 12B 参数的稠密模型，但有效参数量是其 4 倍！

关于 MoE 的更多细节，见配套博客文章：[hf.co/blog/moe](https://huggingface.co/blog/moe)

**Mixtral 发布要点 TL;DR；**

- 同时发布 base 版和 Instruct 版
- 支持 32k token 上下文长度。
- 多数基准上超越 Llama 2 70B，与 GPT3.5 打平或更好
- 会说英语、法语、德语、西班牙语和意大利语。
- 编码能力强，HumanEval 得分 40.2%
- 商业友好的 Apache 2.0 许可证

### 关于名字

这款 Mixtral MoE 模型叫 **Mixtral-8x7B**，但它并没有 56B 参数。发布后不久我们发现，有些人误以为这个模型行为类似 8 个 7B 参数模型的集成，但 MoE 模型不是这样工作的。模型中只有某些层（前馈块）是被复制的，其余参数与一个 7B 模型相同。总参数量不是 56B，而是约 45B。叫 [`Mixtral-45-8e`](https://twitter.com/osanseviero/status/1734248798749159874) 也许更好，能更准确反映架构。想了解 MoE 如何工作，请参考[《Mixture of Experts Explained》一文](https://huggingface.co/blog/moe)。

### 提示格式

[基础模型](https://huggingface.co/mistralai/Mixtral-8x7B-v0.1)没有提示格式。和其他基础模型一样，它可以对输入序列做合理的续写，或用于 zero-shot/few-shot 推理，也是微调到你自己场景的绝佳底座。[Instruct 模型](https://huggingface.co/mistralai/Mixtral-8x7B-Instruct-v0.1)的对话结构非常简单：

```
<s> [INST] User Instruction 1 [/INST] Model answer 1</s> [INST] User instruction 2[/INST]
```

要有效使用这套格式，必须一字不差地复现它。后面我们会展示如何用 `transformers` 提供的聊天模板轻松复现 instruct 提示。

### 我们还不知道的事

和之前 Mistral 7B 发布时一样，这个新系列模型仍有不少未解问题。特别是，我们不知道预训练数据集的规模、组成以及预处理方式。

同样，Mixtral instruct 模型也没有公开微调数据集的细节，以及 SFT 和 DPO 相关的超参数。

## 推理

运行 Mixtral 模型推理主要有两种方式：

- 通过 🤗 Transformers 的 `pipeline()` 函数。
- 使用 Text Generation Inference，它支持连续批处理、张量并行等高级特性，速度飞快。

每种方法都可以用半精度（float16）或量化权重运行模型。由于 Mixtral 的规模大致相当于一个 45B 参数的稠密模型，可以估算所需的最小显存如下：

| 精度 | 所需 VRAM |
| --- | --- |
| float16 | >90 GB |
| 8-bit | >45 GB |
| 4-bit | >23 GB |

### 使用 🤗 Transformers

使用 Transformers [4.36 版本](https://github.com/huggingface/transformers/releases/tag/v4.36.0)，你就可以使用 Mixtral 并调用 Hugging Face 生态的全部工具，例如：

- 训练和推理脚本及示例
- 安全的文件格式（`safetensors`）
- 与 bitsandbytes（4-bit 量化）、PEFT（参数高效微调）和 Flash Attention 2 等工具的集成
- 运行模型生成的辅助函数
- 部署用的模型导出机制

请确保使用较新的 `transformers` 版本：

```
pip install --upgrade transformers
```

下面的代码片段展示如何用 🤗 Transformers 配合 4-bit 量化做推理。由于模型很大，你至少需要一张带 30 GB 显存的卡才能跑起来，例如 A100（80 或 40GB 版本）或 A6000（48 GB）。

```
from transformers import pipeline
import torch

model = "mistralai/Mixtral-8x7B-Instruct-v0.1"

pipe = pipeline(
    "text-generation",
    model=model,
    model_kwargs={"torch_dtype": torch.float16, "load_in_4bit": True},
)

messages = [{"role": "user", "content": "Explain what a Mixture of Experts is in less than 100 words."}]
outputs = pipe(messages, max_new_tokens=256, do_sample=True, temperature=0.7, top_k=50, top_p=0.95)
print(outputs[0]["generated_text"][-1]["content"])
```

> <s>[INST] Explain what a Mixture of Experts is in less than 100 words. [/INST] A
> Mixture of Experts is an ensemble learning method that combines multiple models,
> or "experts," to make more accurate predictions. Each expert specializes in a
> different subset of the data, and a gating network determines the appropriate
> expert to use for a given input. This approach allows the model to adapt to
> complex, non-linear relationships in the data and improve overall performance.

### 使用 Text Generation Inference

**[Text Generation Inference](https://github.com/huggingface/text-generation-inference)** 是 Hugging Face 开发的生产级推理容器，方便部署大语言模型。特性包括连续批处理、token 流式输出、多 GPU 张量并行加速推理，以及生产级的日志和链路追踪。

你可以把 Mixtral 部署到 Hugging Face 的 [Inference Endpoints](https://ui.endpoints.huggingface.co/new?repository=mistralai%2FMixtral-8x7B-Instruct-v0.1&vendor=aws&region=us-east-1&accelerator=gpu&instance_size=2xlarge&task=text-generation&no_suggested_compute=true&tgi=true&tgi_max_batch_total_tokens=1024000&tgi_max_total_tokens=32000)，其后端就是 Text Generation Inference。要部署 Mixtral 模型，前往[模型页面](https://huggingface.co/mistralai/Mixtral-8x7B-Instruct-v0.1)，点击 [Deploy -> Inference Endpoints](https://ui.endpoints.huggingface.co/new?repository=meta-llama/Llama-2-7b-hf) 组件。

*注：访问 A100 可能需要发邮件到 **[api-enterprise@huggingface.co](mailto:api-enterprise@huggingface.co)** 申请提升配额*

想了解更多，请阅读我们的博客 **[用 Hugging Face Inference Endpoints 部署 LLM](https://huggingface.co/blog/inference-endpoints-llm)**。这篇[博客](https://huggingface.co/blog/inference-endpoints-llm)介绍了支持哪些超参数，以及如何用 Python 和 Javascript 流式获取响应。

你也可以用 Docker 在本地 2x A100（80GB）上运行 Text Generation Inference：

```
docker run --gpus all --shm-size 1g -p 3000:80 -v /data:/data ghcr.io/huggingface/text-generation-inference:1.3.0 \
    --model-id mistralai/Mixtral-8x7B-Instruct-v0.1 \
    --num-shard 2 \
    --max-batch-total-tokens 1024000 \
    --max-total-tokens 32000
```

## 用 🤗 TRL 微调

训练 LLM 在技术和算力上都很有挑战。本节看看 Hugging Face 生态中有哪些工具可以在单张 A100 GPU 上高效训练 Mixtral。

下面是在 OpenAssistant [聊天数据集](https://huggingface.co/datasets/OpenAssistant/oasst_top1_2023-08-25)上微调 Mixtral 的示例命令。为节省内存，我们使用 4-bit 量化和 [QLoRA](https://arxiv.org/abs/2305.14314)，目标是注意力块中的所有线性层。注意：与稠密 Transformer 不同，这里不应把 MLP 层作为目标，因为它们是稀疏的，与 PEFT 配合得不好。

首先，安装 🤗 TRL 的 nightly 版本并克隆仓库以获得[训练脚本](https://github.com/huggingface/trl/blob/main/trl/scripts/sft.py)：

```
pip install -U transformers
pip install git+https://github.com/huggingface/trl
git clone https://github.com/huggingface/trl
cd trl
```

然后运行脚本：

```
accelerate launch --config_file examples/accelerate_configs/multi_gpu.yaml --num_processes=1 \
    trl/scripts/sft.py \
    --model_name mistralai/Mixtral-8x7B-v0.1 \
    --dataset_name trl-lib/ultrachat_200k_chatml \
    --batch_size 2 \
    --gradient_accumulation_steps 1 \
    --learning_rate 2e-4 \
    --save_steps 200_000 \
    --use_peft \
    --peft_lora_r 16 --peft_lora_alpha 32 \
    --target_modules q_proj k_proj v_proj o_proj \
    --load_in_4bit
```

单张 A100 上训练大约需要 48 小时，但只要调整 `--num_processes` 为你可用的 GPU 数，就能轻松并行。

## 量化 Mixtral

如前所见，这个模型要想人人可用，难点是让它跑在消费级硬件上——仅以半精度（`torch.float16`）加载就需要约 90GB。

借助 🤗 transformers 库，我们支持开箱即用地使用 QLoRA、GPTQ 等先进量化方法做推理。关于支持的量化方法，可在[相应文档章节](https://huggingface.co/docs/transformers/quantization)了解更多。

### 以 4-bit 量化加载 Mixtral

如推理一节所示，安装 `bitsandbytes` 库（`pip install -U bitsandbytes`）后，给 `from_pretrained` 方法传入 `load_in_4bit=True` 就能以 4-bit 量化加载 Mixtral。为了更好性能，建议用户加上 `bnb_4bit_compute_dtype=torch.float16` 加载。注意，要正常运行下面这段代码，需要至少 30GB VRAM 的 GPU。

```
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig

model_id = "mistralai/Mixtral-8x7B-Instruct-v0.1"
tokenizer = AutoTokenizer.from_pretrained(model_id)

quantization_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_compute_dtype=torch.float16
)
model = AutoModelForCausalLM.from_pretrained(model_id, quantization_config=quantization_config)

prompt = "[INST] Explain what a Mixture of Experts is in less than 100 words. [/INST]"
inputs = tokenizer(prompt, return_tensors="pt").to(0)

output = model.generate(**inputs, max_new_tokens=50)
print(tokenizer.decode(output[0], skip_special_tokens=True))
```

这种 4-bit 量化技术出自 [QLoRA 论文](https://huggingface.co/papers/2305.14314)，可在[文档相应章节](https://huggingface.co/docs/transformers/quantization#4-bit)或[这篇文章](https://huggingface.co/blog/4bit-transformers-bitsandbytes)了解更多。

### 以 GPTQ 加载 Mixtral

GPTQ 算法是一种训练后量化技术：对权重矩阵逐行独立量化，寻找一组使误差最小的量化权重。这些权重以 int4 存储，推理时会即时恢复为 fp16。与 4-bit QLoRA 不同，GPTQ 需要用数据集对模型做校准才能量化。现成的 GPTQ 模型由 [TheBloke](https://huggingface.co/TheBloke) 发布在 🤗 Hub 上，人人可取用，无需自己校准。

对 Mixtral，我们调整了校准方法：**不**量化专家的门控层，以获得更好的效果。量化后模型的困惑度（perplexity，越低越好）为 `4.40`，半精度模型是 `4.25`。量化模型在[这里](https://huggingface.co/TheBloke/Mixtral-8x7B-v0.1-GPTQ)；要用 🤗 transformers 运行它，先更新 `auto-gptq` 和 `optimum` 库：

```
pip install -U optimum auto-gptq
```

还需要从源码安装 transformers：

```
pip install -U git+https://github.com/huggingface/transformers.git
```

装好后，用 `from_pretrained` 加载 GPTQ 模型即可：

```
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig

model_id = "TheBloke/Mixtral-8x7B-v0.1-GPTQ"
tokenizer = AutoTokenizer.from_pretrained(model_id)

model = AutoModelForCausalLM.from_pretrained(model_id, device_map="auto")

prompt = "[INST] Explain what a Mixture of Experts is in less than 100 words. [/INST]"
inputs = tokenizer(prompt, return_tensors="pt").to(0)

output = model.generate(**inputs, max_new_tokens=50)
print(tokenizer.decode(output[0], skip_special_tokens=True))
```

注意，无论 QLoRA 还是 GPTQ，至少都需要 30 GB GPU VRAM 才能装下模型。如果只有 24 GB，可以像上面示例一样用 `device_map="auto"`，把部分层卸载到 CPU。

## 免责声明与后续工作

- **量化**：MoE 的量化仍是活跃的研究方向。我们与 TheBloke 做的一些初步实验如上所示，随着对这种架构的了解不断深入，预计还会有更多进展。接下来几天、几周这个领域的发展一定很精彩。另外，最新工作如 [QMoE](https://arxiv.org/abs/2310.16795)（对 MoE 实现低于 1-bit 的量化）也可以应用到这里。
- **显存占用高**：MoE 推理很快，但仍需要大量 VRAM（也就意味着昂贵的 GPU）。这在本地环境下使用是个挑战。MoE 适合多设备、大显存的场景。Mixtral 在半精度下需要 90GB VRAM 🤯
