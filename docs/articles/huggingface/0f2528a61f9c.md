# 5 分钟了解 Hugging Face Kernel Hub

**用预优化 kernel 提升模型性能，从 Hub 轻松加载。**

今天我们来探索 Hugging Face 的一个激动人心的新进展：**Kernel Hub**！作为 ML 从业者，我们都知道要榨干性能往往得深入优化代码、手写 CUDA kernel 或折腾复杂的构建系统。Kernel Hub 把这个过程彻底简化了！

下面是一段简短示例，演示如何在代码中使用 kernel。

```
import torch

from kernels import get_kernel

# Download optimized kernels from the Hugging Face hub

# Random tensor
x = torch.randn((10, 10), dtype=torch.float16, device="cuda")

# Run the kernel
y = torch.empty_like(x)
activation.gelu_fast(y, x)

print(y)
```

## 1. Kernel Hub 是什么？

[Kernel Hub](https://huggingface.co/kernels-community)（👈 去逛逛！）让 Python 库和应用能够**直接从 Hugging Face Hub 加载优化的计算 kernel**。可以把它理解成"面向底层高性能代码片段（kernel）的 Model Hub"——这些 kernel 用来加速特定操作，通常是在 GPU 上。

例子包括高级注意力机制（比如 [FlashAttention](https://huggingface.co/kernels-community/flash-attn)，可大幅提速并节省内存）、自定义[量化 kernel](https://huggingface.co/kernels-community/quantization)（让 INT8、INT4 等低精度数据类型的高效计算成为可能）、复杂架构（如 [Mixture of Experts（MoE）层](https://huggingface.co/kernels-community/moe)）所需的专用 kernel——涉及精细的路由与计算模式——以及[激活函数](https://huggingface.co/kernels-community/activation)和[归一化层（如 LayerNorm 或 RMSNorm）](https://huggingface.co/kernels-community/triton-layer-norm)。

不必手动管理复杂的依赖、与编译flags较劲，或从源码构建 Triton、CUTLASS 这类库——用 `kernels` 库，你可以即刻拉取并运行预编译的优化 kernel。

例如，启用 **FlashAttention** 只需一行——不用构建、不用 flags：

```
from kernels import get_kernel

flash_attention = get_kernel("kernels-community/flash-attn")
```

`kernels` 会检测你精确的 Python、PyTorch 和 CUDA 版本，然后下载匹配预编译二进制——通常只要几秒（慢网络也就一两分钟）。

相比之下，自己编译 FlashAttention 需要：

- 克隆仓库并安装每一个依赖。
- 配置构建 flags 和环境变量。
- 预留 **约 96 GB 内存**和大量 CPU 核心。
- 等待 **10 分钟到数小时**，视你的硬件而定。（详见项目自己的[安装指南](https://github.com/Dao-AILab/flash-attention#installation)。）

Kernel Hub 抹掉了所有这些摩擦：一次函数调用，即刻加速。

### Kernel Hub 的好处：

- **即刻获取优化 kernel**：加载并运行针对各种硬件（首批支持 NVIDIA 和 AMD GPU）优化的 kernel，免去本地编译之苦。
- **分享与复用**：在不同项目和社区之间发现、分享、复用 kernel。
- **轻松更新**：只需从 Hub 拉取最新版本，就能跟上 kernel 的改进。
- **加速开发**：专注于你的模型架构和逻辑，不用操心 kernel 编译与部署的细节。
- **提升性能**：借助专家优化的 kernel，潜在加快训练和推理。
- **简化部署**：按需拉取 kernel，降低部署环境的复杂度。
- **开发并分享你自己的 kernel**：如果你写出了优化 kernel，可以轻松发布到 Hub 供他人使用，促进社区协作与知识共享。

> 很多机器学习开发者都有体会：管理依赖、从源码构建底层代码，是一件既耗时又容易出错的事。Kernel Hub 的目标就是简化这一切——提供一个集中式的优化计算 kernel 仓库，随时加载即用。

多花时间在打造好模型上，少花时间和构建系统搏斗！

## 2. 如何使用 Kernel Hub（基础示例）

Kernel Hub 的使用方式力求直截了当，`kernels` 库提供主入口。这里有个快速示例，加载一个优化的 GELU 激活函数 kernel。（后面我们还会看如何在模型里集成 kernel。）

文件：[`activation_validation_example.py`](https://gist.github.com/drbh/aa4b8cfb79597e98be6cf0108644ce16)

```
# /// script
# dependencies = [
#  "numpy",
#  "torch",
#  "kernels",
# ]
# ///

import torch
import torch.nn.functional as F
from kernels import get_kernel

DEVICE = "cuda"

# Make reproducible
torch.manual_seed(42)

# Download optimized activation kernels from the Hub
activation_kernels = get_kernel("kernels-community/activation")

# Create a random tensor on the GPU
x = torch.randn((4, 4), dtype=torch.float16, device=DEVICE)

# Prepare an output tensor
y = torch.empty_like(x)

# Run the fast GELU kernel
activation_kernels.gelu_fast(y, x)

# Get expected output using PyTorch's built-in GELU
expected = F.gelu(x)

# Compare the kernel output with PyTorch's result
torch.testing.assert_close(y, expected, rtol=1e-2, atol=1e-2)

print("✅ Kernel output matches PyTorch GELU!")

# Optional: print both tensors for inspection
print("\nInput tensor:")
print(x)
print("\nFast GELU kernel output:")
print(y)
print("\nPyTorch GELU output:")
print(expected)

# List available functions in the loaded kernel module
print("\nAvailable functions in 'kernels-community/activation':")
print(dir(activation_kernels))
```

**（注意：** 如果你安装了 [`uv`](https://github.com/astral-sh/uv)，可以把这个脚本保存为 `script.py`，运行 `uv run script.py` 就能自动处理依赖。）

### 这里发生了什么？

- **导入 `get_kernel`**：这个函数是通过 `kernels` 库进入 Kernel Hub 的入口。
- **`get_kernel("kernels-community/activation")`**：这一行会找 `kernels-community` 组织下的 `activation` kernel 仓库，下载、缓存并加载合适的预编译 kernel 二进制。
- **准备张量**：我们在 GPU 上创建输入（`x`）和输出（`y`）张量。
- **`activation_kernels.gelu_fast(y, x)`**：调用加载的 kernel 模块提供的具体优化函数（`gelu_fast`）。
- **验证**：检查输出。

这个简单示例展示了获取并执行高度优化代码有多轻松。下面我们看一个更实际的集成：RMS Normalization。

## 3. 给简单模型加上 Kernel

我们把一个优化的 **RMS Normalization** kernel 集成进一个基础模型。使用 `kernels-community/triton-layer-norm` 仓库提供的 `LlamaRMSNorm` 实现（注意：该仓库包含多种归一化 kernel），并与 PyTorch 的 RMSNorm 基线实现做对比。

首先，在 PyTorch 中定义一个简单的 RMSNorm 模块，并用它搭一个基线模型：

文件：[`rmsnorm_baseline.py`](https://gist.github.com/drbh/96621d9eafec5dfa0ca9ca59f6fc1991)

```
# /// script
# dependencies = [
#  "numpy",
#  "torch",
#  "kernels",
# ]
# ///
import torch
import torch.nn as nn

DEVICE = "cuda"

DTYPE = torch.float16  # Use float16 for better kernel performance potential


# Simple PyTorch implementation of RMSNorm for baseline comparison
class RMSNorm(nn.Module):
    def __init__(self, hidden_size, variance_epsilon=1e-5):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(hidden_size))
        self.eps = variance_epsilon
        self.hidden_size = hidden_size

    def forward(self, x):
        # Assumes x is (batch_size, ..., hidden_size)
        input_dtype = x.dtype
        # Calculate variance in float32 for stability
        variance = x.to(torch.float32).pow(2).mean(-1, keepdim=True)
        x = x * torch.rsqrt(variance + self.eps)

        # Apply weight and convert back to original dtype
        return (self.weight * x).to(input_dtype)


class BaselineModel(nn.Module):
    def __init__(self, input_size, hidden_size, output_size, eps=1e-5):
        super().__init__()
        self.linear1 = nn.Linear(input_size, hidden_size)
        self.norm = RMSNorm(hidden_size, variance_epsilon=eps)
        self.activation = nn.GELU()
        self.linear2 = nn.Linear(hidden_size, output_size)

        # ensure all linear layers weights are 1 for testing
        with torch.no_grad():
            self.linear1.weight.fill_(1)
            self.linear1.bias.fill_(0)
            self.linear2.weight.fill_(1)
            self.linear2.bias.fill_(0)
            self.norm.weight.fill_(1)

    def forward(self, x):
        x = self.linear1(x)
        x = self.norm(x)  # Apply RMSNorm
        x = self.activation(x)
        x = self.linear2(x)
        return x


# Example usage
input_size = 128
hidden_size = 256
output_size = 10
eps_val = 1e-5

baseline_model = (
    BaselineModel(input_size, hidden_size, output_size, eps=eps_val)
    .to(DEVICE)
    .to(DTYPE)
)
dummy_input = torch.randn(32, input_size, device=DEVICE, dtype=DTYPE)  # Batch of 32
output = baseline_model(dummy_input)
print("Baseline RMSNorm model output shape:", output.shape)
```

现在，我们做一个用 `kernels` 加载 `LlamaRMSNorm` kernel 的版本。

文件：[`rmsnorm_kernel.py`](https://gist.github.com/drbh/141373363e83ea0345807d6525e1fb64)

```
# /// script
# dependencies = [
#  "numpy",
#  "torch",
#  "kernels",
# ]
# ///
import torch
import torch.nn as nn
from kernels import get_kernel, use_kernel_forward_from_hub

# reuse the model from the previous snippet or copy the class
# definition here to run this script independently
from rmsnorm_baseline import BaselineModel

DEVICE = "cuda"
DTYPE = torch.float16  # Use float16 for better kernel performance potential


layer_norm_kernel_module = get_kernel("kernels-community/triton-layer-norm")

# Simply add the decorator to the LlamaRMSNorm class to automatically replace the forward function
# with the optimized kernel version
# 
# Note: not all kernels ship with layers already mapped, and would require calling the function directly
# However in this case, the LlamaRMSNorm class is already mapped to the kernel function. Otherwise we'd need to
# call the function directly like this:
# ```python
# layer_norm_kernel_module.rms_norm_fn(
#     hidden_states,
#     self.weight,
#     bias=None,
#     residual=None,
#     eps=self.variance_epsilon,
#     dropout_p=0.0,
#     prenorm=False,
#     residual_in_fp32=False,
# )
# ```
@use_kernel_forward_from_hub("LlamaRMSNorm")
class OriginalRMSNorm(nn.Module):
    def __init__(self, hidden_size, variance_epsilon=1e-5):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(hidden_size))
        self.eps = variance_epsilon
        self.hidden_size = hidden_size

    def forward(self, x):
        # Assumes x is (batch_size, ..., hidden_size)
        input_dtype = x.dtype
        # Calculate variance in float32 for stability
        variance = x.to(torch.float32).pow(2).mean(-1, keepdim=True)
        x = x * torch.rsqrt(variance + self.eps)

        # Apply weight and convert back to original dtype
        return (self.weight * x).to(input_dtype)


class KernelModel(nn.Module):
    def __init__(
        self,
        input_size,
        hidden_size,
        output_size,
        device="cuda",
        dtype=torch.float16,
        eps=1e-5,
    ):
        super().__init__()
        self.linear1 = nn.Linear(input_size, hidden_size)
        # OriginalRMSNorm will be replaced with the optimized kernel layer
        # when the model is loaded
        self.norm = OriginalRMSNorm(hidden_size, variance_epsilon=eps)
        self.activation = nn.GELU()
        self.linear2 = nn.Linear(hidden_size, output_size)

        # ensure all linear layers weights are 1 for testing
        with torch.no_grad():
            self.linear1.weight.fill_(1)
            self.linear1.bias.fill_(0)
            self.linear2.weight.fill_(1)
            self.linear2.bias.fill_(0)
            self.norm.weight.fill_(1)

    def forward(self, x):
        x = self.linear1(x)
        x = self.norm(x)
        x = self.activation(x)
        x = self.linear2(x)
        return x


# Example usage
input_size = 128
hidden_size = 256
output_size = 10
eps_val = 1e-5

kernel_model = (
    KernelModel(
        input_size, hidden_size, output_size, device=DEVICE, dtype=DTYPE, eps=eps_val
    )
    .to(DEVICE)
    .to(DTYPE)
)

baseline_model = (
    BaselineModel(input_size, hidden_size, output_size, eps=eps_val)
    .to(DEVICE)
    .to(DTYPE)
)

dummy_input = torch.randn(32, input_size, device=DEVICE, dtype=DTYPE)  # Batch of 32

output = baseline_model(dummy_input)
output_kernel = kernel_model(dummy_input)
print("Kernel RMSNorm model output shape:", output_kernel.shape)

# Verify outputs are close (RMSNorm implementations should be numerically close)
try:
    torch.testing.assert_close(output, output_kernel, rtol=1e-2, atol=1e-2)
    print("\nBaseline and Kernel RMSNorm model outputs match!")
except AssertionError as e:
    print("\nBaseline and Kernel RMSNorm model outputs differ slightly:")
    print(e)
except NameError:
    print("\nSkipping output comparison as kernel model output was not generated.")
```

**关于 `KernelModel` 的重要说明：**

- **Kernel 继承：** `KernelRMSNorm` 类继承自 `layer_norm_kernel_module.layers.LlamaRMSNorm`，即 kernel 中的 RMSNorm 实现，让我们可以直接使用优化 kernel。
- **访问函数：** 访问 RMSNorm 函数的确切方式（`layer_norm_kernel_module.layers.LlamaRMSNorm.forward`、`layer_norm_kernel_module.rms_norm_forward` 或其他）**完全取决于 kernel 作者在 Hub 上如何组织仓库**。你可能需要检查加载的 `layer_norm_kernel_module` 对象（例如用 `dir()`），或查看该 kernel 在 Hub 上的文档，才能找到正确的函数/方法及其签名。我这里用了 `rms_norm_forward` 作为合理占位并加了错误处理。
- **参数：** 我们现在只定义 `rms_norm_weight`（没有 bias），与 RMSNorm 一致。

## 4. 基准测试性能影响

优化的 Triton RMSNorm kernel 比标准 PyTorch 版本快多少？我们来对前向传播做个基准测试。

文件：[`rmsnorm_benchmark.py`](https://gist.github.com/drbh/c754a4ba52bcc46190ae4a45516fb190)

```
# /// script
# dependencies = [
#  "numpy",
#  "torch",
#  "kernels",
# ]
# ///
import torch

# reuse the models from the previous snippets or copy the class
# definitions here to run this script independently
from rmsnorm_baseline import BaselineModel
from rmsnorm_kernel import KernelModel

DEVICE = "cuda"
DTYPE = torch.float16  # Use float16 for better kernel performance potential


# Use torch.cuda.Event for accurate GPU timing (ensure function is defined)
def benchmark_model(model, input_tensor, num_runs=100, warmup_runs=10):
    model.eval()  # Set model to evaluation mode
    dtype = input_tensor.dtype
    model = model.to(input_tensor.device).to(dtype)

    # Warmup runs
    for _ in range(warmup_runs):
        _ = model(input_tensor)
    torch.cuda.synchronize()

    # Timed runs
    start_event = torch.cuda.Event(enable_timing=True)
    end_event = torch.cuda.Event(enable_timing=True)
    start_event.record()
    for _ in range(num_runs):
        _ = model(input_tensor)
    end_event.record()
    torch.cuda.synchronize()
    elapsed_time_ms = start_event.elapsed_time(end_event)
    avg_time_ms = elapsed_time_ms / num_runs
    return avg_time_ms


input_size_bench = 4096
hidden_size_bench = 4096  # RMSNorm performance is sensitive to this dimension
output_size_bench = 10
eps_val_bench = 1e-5

# Create larger models and input for benchmark
# Ensure both models are fully converted to the target DEVICE and DTYPE
baseline_model_bench = (
    BaselineModel(
        input_size_bench, hidden_size_bench, output_size_bench, eps=eps_val_bench
    )
    .to(DEVICE)
    .to(DTYPE)
)
kernel_model_bench = (
    KernelModel(
        input_size_bench,
        hidden_size_bench,
        output_size_bench,
        device=DEVICE,
        dtype=DTYPE,
        eps=eps_val_bench,
    )
    .to(DEVICE)
    .to(DTYPE)
)

# call both with larger batch sizes to warm up the GPU
# and ensure the models are loaded
warmup_input = torch.randn(4096, input_size_bench, device=DEVICE, dtype=DTYPE)
_ = kernel_model_bench(warmup_input)
_ = baseline_model_bench(warmup_input)

batch_sizes = [
    256,
    512,
    1024,
    2048,
    4096,
    8192,
    16384,
    32768,
]

print(
    f"{'Batch Size':<12} | {'Baseline Time (ms)':<18} | {'Kernel Time (ms)':<18} | {'Speedup'}"
)
print("-" * 74)

for batch_size in batch_sizes:
    # Call cuda synchronize to ensure all previous GPU operations are complete
    torch.cuda.synchronize()

    # Create random input tensor
    # Ensure the input tensor is on the correct device and dtype
    bench_input = torch.randn(batch_size, input_size_bench, device=DEVICE, dtype=DTYPE)

    # Run benchmarks only if kernel was loaded successfully
    baseline_time = benchmark_model(baseline_model_bench, bench_input)

    kernel_time = -1  # Sentinel value

    kernel_time = benchmark_model(kernel_model_bench, bench_input)

    baseline_time = round(baseline_time, 4)
    kernel_time = round(kernel_time, 4)
    speedup = round(baseline_time / kernel_time, 2) if kernel_time > 0 else "N/A"
    if kernel_time < baseline_time:
        speedup = f"{speedup:.2f}x"
    elif kernel_time == baseline_time:
        speedup = "1.00x (identical)"
    else:
        speedup = f"{kernel_time / baseline_time:.2f}x slower"
    print(f"{batch_size:<12} | {baseline_time:<18} | {kernel_time:<18} | {speedup}")
```

**预期结果：** 和 LayerNorm 一样，用 Triton 精心调优的 RMSNorm 实现相比 PyTorch 默认版本可以带来可观加速——在兼容硬件（如 NVIDIA Ampere 或 Hopper GPU）上、`float16` 或 `bfloat16` 等低精度类型下的内存受限负载尤其明显。

**请记住：**

- 结果会因 GPU、输入大小和数据类型而异。
- 微基准测试可能无法反映真实性能。
- 性能取决于 kernel 实现的质量。
- 由于开销，优化 kernel 对小批大小未必有收益。

## 上手与下一步！

你已经看到用 Hugging Face Kernel Hub 获取并使用优化 kernel 有多简单。准备好自己试了吗？

- **安装库：** `pip install kernels torch numpy ` 确保已安装兼容的 PyTorch 版本和 GPU 驱动。
- **浏览 Hub：** 在 Hugging Face Hub 的 [`kernels` 标签](https://huggingface.co/models?other=kernels)下或 [`kernels-community`](https://huggingface.co/kernels-community) 这样的组织中探索可用 kernel。寻找与你操作相关的 kernel（激活、注意力、LayerNorm/RMSNorm 等归一化等）。
- **动手实验：** 试着替换你自己模型中的组件，用 `get_kernel("user-or-org/kernel-name")`。**关键是检查加载的 kernel 对象**（例如 `print(dir(loaded_kernel))`），或查看其 Hub 仓库文档，弄清如何正确调用它的函数/方法以及它需要哪些参数（权重、bias、输入、epsilon）。
- **做基准：** 在你的具体硬件和工作负载上测量性能影响。别忘了检查数值正确性（`torch.testing.assert_close`）。
- **（进阶）贡献：** 如果你开发了优化 kernel，考虑发布到 Hub 分享给大家！

## 总结
