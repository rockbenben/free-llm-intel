tl;dr：我们做了一个 agent skill，教会编程智能体编写生产级 CUDA 内核。然后我们让 Claude 和 Codex 对准两个真实目标：一条 **diffusers** 流水线和一个 **transformers** 模型。智能体为两者都产出了可用的内核——正确的 PyTorch 绑定、基准测试，端到端全部搞定。

写 CUDA 内核很难。写出能与 `transformers` 和 `diffusers` 正确集成的 CUDA 内核更难。体系结构相关的内存访问模式、向量化策略、warp shuffle 归约，还有十几个连老手都会踩的集成坑。而这恰恰是 agent skill 最能发挥作用的场景：高度专门化、高风险的问题。

我们给编程智能体提供了它们需要的领域知识：瞄准哪个 GPU 架构、如何组织一个 kernel-builder 项目、何时用共享内存何时用寄存器、如何写 PyTorch 绑定。剩下的交给智能体。如果你用过 [LLM 训练 skill](https://huggingface.co/blog/hf-skills-training)，或读过 [We Got Claude to Teach Open Models](https://huggingface.co/blog/upskill)，这个模式会很熟悉：把领域专家知识打包成 skill，把智能体对准问题，然后让它干活。

## 为什么要给内核做 skill？

[Kernel Hub](https://huggingface.co/blog/hello-hf-kernels) 解决了自定义硬件内核的分发问题：一行 `get_kernel` 就能从 Hub 加载预编译内核，不用构建、不用调参数。但仍然需要有人**把内核写出来**。这个 skill 补的就是这个缺口。

CUDA 内核开发的知识面广得吓人：

- 每一代 GPU 都有一套硬件专属的优化指南。H100、A100、T4 的计算能力、共享内存大小、带宽特征各不相同。
- 在库这一侧，`diffusers` 和 `transformers` 的模块层级、归一化约定、集成模式各不相同。自定义内核必须注册进 PyTorch，`torch.compile` 才认得了它。
- 在分发这一侧，内核依赖 CUDA、PyTorch、Python 版本，构成庞大的环境矩阵。

这些领域知识散落在文档标签页和 Stack Overflow 回答里。agent skill 把它们打包成按需加载的上下文。

先展示怎么用起来，再细讲内核的基准测试。

## 安装 skill

这个 skill 随 `kernels` 库一起发布。一条命令装进你的编程智能体：

```
# we need to install kernels from main for this
pip install git+https://github.com/huggingface/kernels.git#subdirectory=kernels
kernels skills add cuda-kernels --claude
```

这会把 skill 放进 `.claude/skills/cuda-kernels/`，Claude Code 和 Cursor 会自动识别。其他智能体：

```
# Codex
kernels skills add cuda-kernels --codex

# OpenCode
kernels skills add cuda-kernels --opencode

# Custom destination
kernels skills add cuda-kernels --dest ./my-agent/skills/

# Install globally (available across all projects)
kernels skills add cuda-kernels --global

# Overwrite an existing installation
kernels skills add cuda-kernels --claude --force
```

装好后，给你的智能体下提示：

```
Build a vectorized RMSNorm kernel for H100 targeting the Qwen3-8B model in transformers.
```

也可以更开放一些：

```
Build an optimized attention kernel for H100 targeting the Qwen3-8B model in transformers. Benchmark it against the PyTorch baseline and validate improvements in end-to-end performance.
```

智能体能读 skill、选出正确的架构参数、生成 CUDA 源码、写 PyTorch 绑定、配置 `build.toml`、做出基准脚本。

如果你在写更复杂的内核，或 skill 未覆盖的架构专属优化，skill 也会提供基本构件和模式帮你起步。我们也欢迎对 [skill 本身](https://github.com/huggingface/kernels/tree/main/kernel-builder/skills)的贡献。

## skill 里有什么

这个 skill 大约是 **550 token** 的结构化指南，外加参考脚本、GPU 优化指南、排障文档和完整可运行示例。Codex、Claude 这类智能体编程工具读了就能产出一个能跑的内核项目。

它覆盖：

- H100、A100、T4 的 NVIDIA GPU 架构感知优化（计算能力、内存带宽、共享内存大小、块尺寸）
- `diffusers` 与 `transformers` 两者的集成模式，包括各自专属的坑
- 内核模板：BF16、FP16、FP32 的向量化内存访问模式
- 基准测试工作流：单内核微基准和端到端流水线对比都有
- 通过 `get_kernel` 接入 HuggingFace Kernel Hub 加载社区内核

```
.claude/skills/cuda-kernels/
├── SKILL.md                              # Main instructions (~550 tokens)
├── scripts/
│   ├── benchmark_example.py              # End-to-end benchmark template
│   ├── benchmark_rmsnorm.py              # Isolated kernel micro-benchmark
│   ├── ltx_kernel_injection_example.py   # Diffusers integration pattern
│   ├── transformers_injection_example.py # Transformers integration pattern
│   └── huggingface_kernels_example.py    # Kernel Hub integration
└── references/
    ├── diffusers-integration.md          # Diffusers guide with pitfalls
    ├── transformers-integration.md       # Transformers guide
    ├── huggingface-kernels-integration.md
    ├── h100-optimization-guide.md
    ├── a100-optimization-guide.md
    ├── t4-optimization-guide.md
    ├── kernel-templates.md
    └── troubleshooting.md
```

智能体加载后，就从"给我写个 RMSNorm 内核"一路拿到一个可构建、可基准的完整项目。它会用 grep 和 glob 在 skill 里找相关文件目录，所以 skill 的结构必须易于查找。

指令要求智能体生成的内核符合 `references/kernel-templates.md` 里的模板，并产出一个完整的内核项目：

```
examples/your_model/
├── kernel_src/
│   └── rmsnorm.cu              # Vectorized CUDA kernel
├── torch-ext/
│   ├── your_kernels/__init__.py
│   └── torch_binding.cpp       # PyTorch C++ bindings
├── benchmark_rmsnorm.py        # Micro-benchmark script
├── build.toml                  # kernel-builder config
├── setup.py                    # pip install -e .
└── pyproject.toml
```

我们在两个真实目标上做了验证。

## 内核基准测试：Diffusers（LTX-Video，H100）

智能体为 [LTX-Video](https://huggingface.co/Lightricks/LTX-Video)（`diffusers` 里的视频生成流水线）构建了 RMSNorm、RoPE 3D、GEGLU 和 AdaLN 内核。完整示例在 `examples/ltx_video/`。我们把 RMSNorm 内核针对 H100 做了优化。两项基准都在 H100 80GB HBM3、BFloat16 精度下运行。

想看生成的内核，去[这个示例](https://github.com/burtenshaw/kernel-skill/tree/main/examples/ltx_video)。

| [2x1024x2048] | 0.040 | 0.073 | **1.82x** |

## 内核基准测试：Transformers（Qwen3-8B，H100）

智能体为 [Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B)（`transformers` 里 32 层共 65 个 RMSNorm 模块的大语言模型）构建了 RMSNorm 内核。完整示例在 `examples/qwen3_8b/`。我们把 RMSNorm 内核针对 H100 做了优化。两项基准都在 H100 80GB HBM3、BFloat16 精度下运行。

想研究这个内核，看[这里](https://github.com/burtenshaw/kernel-skill/tree/main/examples/qwen3_8b)。

## 把你的内核发布到 Hub

智能体给你一个能用的内核。[Kernel Hub](https://huggingface.co/kernels-community) 让你把它分享出去，任何人无需编译即可加载。以下是从智能体产出到发布内核的完整路径。

### 1. 检查项目结构

智能体产出的项目已经遵循 [kernel-builder](https://huggingface.co/docs/kernels/en/builder/writing-kernels) 布局：

```
your_kernel/
├── build.toml               # Build configuration
├── kernel_src/
│   └── rmsnorm.cu           # CUDA kernel source
└── torch-ext/
    ├── torch_binding.cpp    # Registers Torch ops
    └── your_kernels/
        └── __init__.py      # Python API wrapping _ops
```

`build.toml` 告诉 `kernel-builder` 要构建什么。智能体会帮你生成，包括目标 GPU 正确的 `cuda-capabilities`：

```
[general]
name = "your_kernels"
backends = ["cuda"]

[torch]
src = ["torch-ext/torch_binding.cpp"]

[kernel.rmsnorm]
backend = "cuda"
src = ["kernel_src/rmsnorm.cu"]
depends = ["torch"]
cuda-capabilities = ["9.0"]  # H100
```

### 2. 用 Nix 构建全部变体

Kernel Hub 上的内核必须支持所有较新的 PyTorch 和 CUDA 组合。kernel-builder 的 Nix flake 会自动处理。把[示例 `flake.nix`](https://github.com/huggingface/kernels/blob/main/examples/kernels/relu/flake.nix) 复制进你的项目，然后运行：

```
nix flake update
nix run .#build-and-copy -L
```

这会为每个必需的 PyTorch/CUDA 变体构建内核，并把结果放进 `build/`。想构建更快，可以启用 HuggingFace 的 Nix 缓存：

```
nix run nixpkgs#cachix -- use huggingface
```

### 3. 创建 Hub 仓库并推送

在 Hub 上创建一个模型仓库并上传构建好的内核：

```
huggingface-cli repo create your-org/your-kernel --type model
huggingface-cli upload your-org/your-kernel ./build
```

### 4. 其他人一行加载

发布后，任何人零编译即可使用你的内核：

```
from kernels import get_kernel

rmsnorm = get_kernel("your-org/your-kernel")
```

`get_kernel` 会检测用户的 Python、PyTorch 和 CUDA 版本，下载匹配的预编译二进制。不用构建、不用参数，通常几秒就绪。

skill 和 Hub 是互补的：skill 负责开发，Hub 负责分发。用 skill 造内核、用基准脚本验证、发布到 Hub——它对所有人就变成了一行代码的事。

## 结论

我们做了一个 agent skill，教编程智能体编写生产级 CUDA 内核，然后让 Claude 和 Codex 对准两个真实目标：一条 **diffusers** 流水线和一个 **transformers** 模型。智能体为两者都产出了可用的内核，PyTorch 绑定和基准测试全部正确、端到端完成。内核实测表明：优化后的内核无论在独立还是端到端性能上都能带来加速。
