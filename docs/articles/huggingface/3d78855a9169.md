# AMD + Hugging Face：AMD GPU 上开箱即用的大型语言模型加速

今年早些时候，在 AMD 的 AI Day 活动上，[AMD 与 Hugging Face 宣布建立合作伙伴关系](https://huggingface.co/blog/huggingface-and-amd)以加速 AI 模型。我们一直在努力工作，把这一愿景变成现实：让 Hugging Face 社区能轻松地在 AMD 硬件上运行最新 AI 模型，并获得尽可能好的性能。

AMD 驱动着世界上一些最强大的超级计算机，包括欧洲最快的那台 [LUMI](https://www.lumi-supercomputer.eu/lumi-retains-its-position-as-europes-fastest-supercomputer/)——它运行着超过 10,000 张 AMD MI250X GPU。在这次活动上，AMD 发布了最新一代服务器 GPU——AMD [Instinct™ MI300](https://www.amd.com/fr/graphics/instinct-server-accelerators) 系列加速器，它们很快将正式发售。

在这篇博客里，我们汇报在为 AMD GPU 提供优秀开箱即用支持、以及提升最新服务器级 AMD Instinct GPU 互操作性方面的进展。

## 开箱即用的加速

你能在下面找出 AMD 专属的代码改动吗？别伤眼睛了——和在 NVIDIA GPU 上跑相比，一处都没有 🤗。

```
from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

model_id = "01-ai/Yi-6B"
tokenizer = AutoTokenizer.from_pretrained(model_id)
with torch.device("cuda"):
    model = AutoModelForCausalLM.from_pretrained(model_id, torch_dtype=torch.float16)

inp = tokenizer(["Today I am in Paris and"], padding=True, return_tensors="pt").to("cuda")
res = model.generate(**inp, max_new_tokens=30)

print(tokenizer.batch_decode(res))
```

我们一直在攻克的要点之一，是无需任何代码改动就能运行 Hugging Face Transformers 模型。现在我们已在 AMD Instinct GPU 上支持所有 Transformers 模型和所有任务。我们的合作不止于此——还在探索对 diffusers 模型、其他库以及其他 AMD GPU 的开箱即用支持。

达成这个里程碑是我们两个团队和公司之间大量努力和协作的成果。为了维护对 Hugging Face 社区的支持和性能，我们已在自己的数据中心建立了 Hugging Face 开源库在 AMD Instinct GPU 上的集成测试——并且与 Verne Global 合作，把 AMD Instinct 服务器部署到[冰岛](https://verneglobal.com/about-us/locations/iceland/)，尽可能降低这些新工作负载的碳排放。

在原生支持之上，我们合作的另一个重点是落地 AMD GPU 上最新创新和功能的集成。经过 Hugging Face 团队、AMD 工程师和开源社区成员的协作，我们很高兴宣布[支持](https://huggingface.co/docs/optimum/amd/index)：

- 来自 AMD 开源工作的 Flash Attention v2（[ROCmSoftwarePlatform/flash-attention](https://github.com/ROCmSoftwarePlatform/flash-attention)），已原生集成进 [Transformers](https://huggingface.co/docs/transformers/perf_infer_gpu_one#flashattention-2) 和 [Text Generation Inference](https://huggingface.co/docs/text-generation-inference/quicktour)。
- 来自 [vLLM](https://github.com/vllm-project/vllm/pull/1313) 的 Paged Attention，以及 [Text Generation Inference](https://huggingface.co/docs/text-generation-inference/quicktour) 中为 ROCm 提供的各种融合 kernel。
- 配合 Transformers 在 ROCm GPU 上使用 [DeepSpeed](https://github.com/microsoft/DeepSpeed) 现在也得到官方验证和支持。
- GPTQ——一种常用的降低模型内存需求的权重量化技术——已通过 [AutoGPTQ](https://github.com/PanQiWei/AutoGPTQ) 与 [Transformers](https://huggingface.co/blog/gptq-integration) 的直接集成支持 ROCm GPU。
- [Optimum-Benchmark](https://github.com/huggingface/optimum-benchmark)：一个便捷的实用工具，用于在 AMD GPU 上对 Transformers 做性能基准测试，覆盖普通和分布式场景，并支持各种优化和量化方案。
- 通过 [Optimum 库](https://huggingface.co/docs/optimum/onnxruntime/usage_guides/amdgpu)，用 [ROCMExecutionProvider](https://onnxruntime.ai/docs/execution-providers/ROCm-ExecutionProvider.html) 在 ROCm GPU 上运行 ONNX 模型的支持。

我们非常兴奋把这些最先进的加速工具变得触手可及、简单易用，并通过为 AMD Instinct GPU 新建的持续集成与开发流水线提供有维护的支持和性能。

一张拥有 128 GB 高带宽显存的 AMD Instinct MI250 GPU 包含两个独立的 ROCm 设备（GPU 0 和 1），每个各有 64 GB 高带宽显存。

`rocm-smi` 显示的 MI250 两个设备

这意味着仅用一张 MI250 GPU 卡，我们就有两个 PyTorch 设备，可以非常轻松地通过张量并行和数据并行获得更高吞吐、更低延迟。

在本文其余部分，我们报告大语言模型文本生成两个步骤的性能结果：

- **Prefill 延迟**：模型计算用户输入或提示词表示所花的时间（也称「Time To First Token」，首 token 时间）。
- **解码每 token 延迟**：prefill 之后以自回归方式生成每个新 token 所需的时间。
- **解码吞吐量**：解码阶段每秒生成的 token 数。

## 生产解决方案

我们合作的另一个重要重点是构建对 Hugging Face 生产解决方案的支持，首先从 Text Generation Inference（TGI）开始。TGI 提供了大规模部署大语言模型推理的端到端方案。

起初，TGI 主要面向 Nvidia GPU，利用了针对 Ampere 及之后架构的近期多项优化，例如 Flash Attention v1 和 v2、GPTQ 权重量化和 Paged Attention。

今天我们很高兴宣布 TGI 初步支持 AMD Instinct MI210 和 MI250 GPU——把上文详述的各种优秀开源工作集成进一个完整的端到端方案，随时可部署。

性能方面，我们花大量时间在 AMD Instinct GPU 上为 Text Generation Inference 跑基准，以验证并找出优化的着力点。在 AMD GPU 工程师的支持下，我们已经能够追平 TGI 原本提供的性能。

在这一背景下，依托 AMD 与 Hugging Face 正在建立的长期关系，我们持续集成并测试 AMD GeMM Tuner 工具——它允许我们调优 TGI 中使用的 GeMM（矩阵乘法）kernel，找到通往更高性能的最佳配置。GeMM Tuner 工具预计将[作为 PyTorch 的一部分](https://github.com/pytorch/pytorch/pull/114894)在后续版本发布，让人人受益。

说完以上这些，我们很激动地展示首批性能数据——它们证明了最新 AMD 技术的实力，让 AMD GPU 上的 Text Generation Inference 凭借 Llama 模型家族跻身高效推理解决方案的第一梯队。

Llama 34B 的 TGI 延迟结果：单张 AMD Instinct MI250 对比 A100-SXM4-80GB。如前所述，一张 MI250 对应两个 PyTorch 设备。

Llama 70B 的 TGI 延迟结果：两张 AMD Instinct MI250 对比两张 A100-SXM4-80GB（使用张量并行）

A100 缺失的柱子对应 OOM 错误——Llama 70B 在 float16 下重 138 GB，而中间激活、KV cache 缓冲（2048 序列长度、batch size 8 需要 5GB 以上）、CUDA context 等都需要足够的空闲内存。Instinct MI250 有 128 GB 全局显存，而 A100 只有 80GB——这解释了 MI250 能运行更大负载（更长序列、更大 batch）的原因。

Text Generation Inference 已[可部署](https://huggingface.co/docs/text-generation-inference/quicktour)到 AMD Instinct GPU 的生产环境，使用 docker 镜像 `ghcr.io/huggingface/text-generation-inference:1.2-rocm`。关于支持及其限制，请务必查阅[文档](https://huggingface.co/docs/text-generation-inference/supported_models#supported-hardware)。

## 接下来？

希望这篇博客让你和 Hugging Face 一样对与 AMD 的这项合作感到兴奋。当然这只是旅程的开端，我们期待在更多 AMD 硬件上解锁更多用例。

未来几个月，我们将推进对 AMD Radeon GPU（就是你可以在自己台式机里插上本地使用的同款 GPU）的更多支持和验证，降低可及性门槛，为用户铺就更灵活的路。

我们当然也会很快着手 MI300 产品线的性能优化，确保开源侧和解决方案侧都以 Hugging Face 一贯追求的最高稳定性提供最新创新。

我们关注的另一个方向是 AMD Ryzen AI 技术——它驱动着最新一代 AMD 笔记本 CPU，让 AI 能在边缘、在设备本机上运行。在编程助手、图像生成工具和个人助理越来越普及的当下，提供能满足隐私需求、又能用好这些强大工具的方案十分重要。为此，兼容 Ryzen AI 的模型已经上架 [Hugging Face Hub](https://huggingface.co/models?other=RyzenAI)，我们正在与 AMD 紧密合作，在未来几个月带来更多此类模型。
