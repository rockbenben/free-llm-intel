### 业务背景

随着 IT 持续演进并重塑我们的世界，在行业内营造一个更多元、更包容的环境至关重要。[Witty Works](https://www.witty.works/) 于 2018 年创立，正是为了应对这一挑战。它起初是一家为组织提供多元化建议的咨询公司，最先帮助用户用包容性语言撰写招聘广告。为了把这一努力规模化，他们在 2019 年构建了一个 Web 应用，帮助用户用英语、法语和德语撰写包容性的招聘广告。他们迅速扩大了范围，推出了一款作为浏览器扩展的写作助手，能够自动修正并解释邮件、Linkedin 帖子、招聘广告等中潜在的偏见。其目标是提供一种用于内部与外部沟通的解决方案，通过提供微型学习内容来解释被高亮词语和短语背后的偏见，从而推动文化变革。

### 早期实验

Witty Works 最初选择了一种基础的机器学习方法从零开始构建其助手。借助基于预训练 spaCy 模型的迁移学习，该助手能够：

- 分析文本并把单词转换为词元（lemma），
- 执行语言学分析，
- 从文本中提取语言特征（单复数形式、性别）、词性标签（代词、动词、名词、形容词等）、词语依存标签、命名实体识别等。

通过根据特定知识库来检测并按语言特征过滤词语，该助手能够实时高亮非包容性词语并给出替代建议。

### 挑战

该词库在德语和英语中各自约有 2300 个非包容性词语和习语。上述那种基础方法对 85% 的词库效果良好，但对依赖上下文的词语则会失败。因此任务就是构建一个依赖上下文的非包容性词语分类器。这样的挑战（理解上下文而非识别语言特征）促使他们使用 Hugging Face transformers。

```
Example of context dependent non-inclusive words: 
Fossil fuels are not renewable resources. Vs He is an old fossil
You will have a flexible schedule. Vs You should keep your schedule flexible.
```

### [Hugging Face 专家](https://huggingface.co/support?utm_source=blog-post&utm_medium=blog-post&utm_campaign=blog-post-classification-use-case)提供的解决方案

- **为选择合适的 ML 方法提供指导。**

最初选择的方法是原生 transformers（用于提取特定非包容性词语的 token embeddings）。Hugging Face 专家建议从上下文相关的词 embeddings 切换到上下文相关的句 embeddings。在这种方法中，句子中每个词的表示都依赖于其周围的上下文。

Hugging Face 专家建议使用 [Sentence Transformers](https://www.sbert.net/) 架构。该架构为整个句子生成 embeddings。语义相似的句子之间距离被最小化，相距较远的句子则被最大化。

在这种方法中，Sentence Transformers 使用孪生网络（Siamese networks）和三元网络（triplet network）结构，改造预训练的 transformer 模型以生成"语义上有意义"的句子 embeddings。

所得到的句子 embedding 作为输入，供基于 KNN 或逻辑回归的经典分类器使用，从而构建一个依赖上下文的非包容性词语分类器。

```
Elena Nazarenko, Lead Data Scientist at Witty Works: 
“We generate contextualized embedding vectors for every word depending on its 
sentence (BERT embedding). Then, we keep only the embedding for the “problem” 
word’s token, and calculate the smallest angle (cosine similarity)”  
```

要对一个基于原生 transformers 的分类器（例如一个简单的 BERT 模型）进行微调，Witty Works 本需要大量标注数据。每个被标记词的类别都需要数百个样本。然而，这样的标注流程既昂贵又耗时，是 Witty Works 负担不起的。

- **为选择合适的 ML 库提供指导。**

Hugging Face 专家建议使用 Sentence Transformers 微调库（即 [SetFit](https://github.com/huggingface/setfit)），这是一个用于对 Sentence Transformers 模型进行少样本（few-shot）微调的高效框架。结合对比学习与语义句子相似度，SetFit 在极少标注数据的情况下也能在文本分类任务上取得高准确率。

```
Julien Simon, Chief Evangelist at Hugging Face: 
“SetFit for text classification tasks is a great tool to add to the ML toolbox” 
```

Witty Works 团队发现，每个特定词只需 15–20 条标注句子，性能就已足够。

```
Elena Nazarenko, Lead Data Scientist at Witty Works: 
“At the end of the day, we saved time and money by not creating this large data set”
```

减少句子数量对于确保模型训练足够快、模型运行高效至关重要。但这样做还有另一个必要原因：Witty 明确采用了高度监督/基于规则的方法来[主动管理偏见](https://www.witty.works/en/blog/is-chatgpt-able-to-generate-inclusive-language)。减少句子数量对于降低人工审阅训练句子的成本非常重要。

- **为选择合适的 ML 模型提供指导。**

对 Witty Works 来说，一大挑战是以低延迟部署模型。没有人愿意为了获得改善文本的建议而等待 3 分钟！Hugging Face 和 Witty Works 都尝试了几种 sentence transformers 模型，最终选定了 [mpnet-base-v2](https://huggingface.co/sentence-transformers/all-mpnet-base-v2)，并结合逻辑回归与 KNN。

在 Google Colab 上完成首次测试后，Hugging Face 专家指导 Witty Works 在 Azure 上部署模型。由于模型已经足够快，无需再做优化。

```
Elena Nazarenko, Lead Data Scientist at Witty Works: 
“Working with Hugging Face saved us a lot of time and money. 
One can feel lost when implementing complex text classification use cases. 
As it is one of the most popular tasks, there are a lot of models on the Hub. 
The Hugging Face experts guided me through the massive amount of transformer-based 
models to choose the best possible approach. 
Plus, I felt very well supported during the model deployment”
```
