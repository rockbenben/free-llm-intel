最有用的知识都是用英语书写和数字化的。而最需要这些知识的人，却用印地语、泰米尔语、泰卢固语、古吉拉特语、马拉地语等自己的地区语言说话和思考。许多人宁愿开口说，也不愿动手打字。

我们构建了一个小型语音 Agent 来弥合这一差距，使用 [CUGA](https://cuga.dev) 作为 Agent 的 harness（运行框架）。本文介绍该用例以及我们从中得到的经验。你可以在 [CUGA Apps](https://huggingface.co/spaces/ibm-research/cuga-apps) 中亲自试用。

## 用例：农场助手

一位农民用自己的语言大声提问：*我怎么分辨好种子和坏种子？* 这个 Agent 会：

- **聆听**，并把语音转成文本。
- **搜索**一本 154 页、用英语写成的农业手册。
- **回答**时用提问者所用的语言，说两到四句口语化的句子，且只使用手册中写明的内容。
- **朗读**答案并展示来源页码，以便核对。

如果有人问板球或编程，它会礼貌地把话题引回农业，而不是凭空编造。

## CUGA 在其中扮演什么角色

[CUGA](https://cuga.dev)（ConfigUrable Generalist Agent）是 IBM Research 的开源 Agent harness。它负责模型连接、工具管理、状态与护栏，因此你只需编写工具和 prompt，而不必编写 Agent 循环。在这里，我们把它作为嵌入式 SDK 用在一个小型 Web 应用中，用于三件事：

- **同一个 Agent，任意模型。** 通过一个设置即可在 watsonx 和 OpenAI 之间切换。
- **知识引擎。** 解析 PDF、切块、嵌入，并用 `agent.knowledge.search()` 在本地检索。
- **对话线程。** 每个问题都获得一个新线程，因此一个人的语言或上下文绝不会泄漏到另一个人那里。

核心设计理念很简单：**CUGA 是一个文本输入、文本输出的大脑。** 语音只是它外层的两个薄层。

```
audio ──▶ speech-to-text ──▶ knowledge.search ──▶ CUGA (grounded answer) ──▶ text-to-speech ──▶ audio
```

因为 Agent 始终只看到文本，所以你可以先用纯文本构建并测试它，然后再添加“耳朵”和“嘴巴”。你也可以在不改动 Agent 的情况下更换语音提供商。我们支持两种：Sarvam AI 的云端语音 API（直接从用户浏览器调用），以及在你自己的服务器上运行的开源模型（语音转文本用 SraVaani，文本转语音用 Svara）。

### 难点不在语音

添加语音是容易的部分。难的是**跨语言检索**：一个印地语问题必须找到一段英语段落。

搜索的原理是把文本转成向量，再找出最接近的向量。CUGA 默认的嵌入模型仅支持英语，因此它把印地语转成的向量几乎不携带任何含义。用它时，一个印地语或泰米尔语问题仍然会检索出五段文字，但都是错误的段落。模型被正确地要求只能依据所给内容作答，于是它会平静地说“手册没有涵盖这一点”。每一层的行为都正确，所以既没有报错也没有警告。

解决方案是使用多语言嵌入模型（我们用的是 `intfloat/multilingual-e5-large`），这样无论何种语言，相同的含义都会落在相同的位置。概念上很简单，但把它接入 CUGA 需要一点小的变通（教程中已展示）。之后，一份英语文档就能服务所有语言，你不需要任何译制副本。

我们的建议是：在调整任何一条 prompt 之前，先用非英语语言向你的 Agent 问一个问题，检查它能否找到正确的页面。

### 让它听起来自然，并保持安全

有几个小决定比我们预想的更重要：

- **为耳朵而写。** Markdown、项目符号、引用标记以及像“millet (बाजरा)”这样括号内的翻译，在朗读出来时听起来都不对。prompt 会要求模型不要生成这些内容，一个轻量格式化器会在语音合成前清除任何漏网的内容。
- **让护栏保持低成本。** 简单的输入检查能拦住明显的跑题问题。如果有漏网的，模型会在回复开头加上 `OFF_TOPIC`，应用则换成礼貌的引导语。无需第二次 LLM 调用，因此语音链路保持快速。
- **为每个答案提供依据。** 模型只能看到检索到的段落，被要求不得使用外部知识，并且页码来源会展示给用户。
- **把密钥留在服务器之外。** 使用 Sarvam 选项时，浏览器直接与 Sarvam 通信。服务器只接收文本，永远看不到用户的密钥。

## 超越农业：为 Bharat 扩展

这里没有任何内容是农业特有的。把手册换成计划文档、健康提示或法律指南，你就有了另一个助手。更换语音提供商，你就改变了部署模式，例如为速度选择云端，或为数据主权选择本地部署，而无需重写 Agent。

语音优先的多语言助手，是数字服务触达那些从未被纯英语文本界面服务好的人群的方式。将它们构建在开放、可审计的 harness 之上，并让答案与人们可以核对的来源绑定，是它们赢得信任的方式。

这种方法恰好落在我们正在用 IBM Bharat Core 构建的东西的交汇点上。Bharat Core 是构建在 IBM Sovereign Core 之上的优化 AI 栈，专为印度生态系统设计，可在本地基础设施上安全运行 Indic AI 工作负载。当把一个语音 Agent 从原型扩展到安全的企业应用（例如方言 KYC 系统或多语言政府机器人）时，你需要对数据主权有更强的控制。将 CUGA 灵活的 Agent harness 与 Bharat Core 的即用型 Indic 连接器和微调模型相结合，开发者就能构建完全合规、主权可控且契合印度独特语言多样性的 AI 解决方案。

如果你正在为印度的规模化场景构建，请看看 **[IBM Bharat Core](https://www.ibmbharatcore.info/)** 正在进行的工作。

可以在浏览器中试用的 Spaces：
