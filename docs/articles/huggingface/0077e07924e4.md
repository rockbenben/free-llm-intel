大多数有用的知识都是用英语写成并数字化的。而需要这些知识的人，大多用自己的地区语言说话和思考，比如 Hindi、Tamil、Telugu、Gujarati、Marathi 等等。许多人更愿意开口说，而不是打字。

为了弥合这一差距，我们搭建了一个小型语音 agent，用 [CUGA](https://cuga.dev) 作为 agent harness。本文介绍这一用例，以及我们从中得到的经验。你可以在 [CUGA Apps](https://huggingface.co/spaces/ibm-research/cuga-apps) 中亲自试用。

## 用例：一位农场助手

一位农民用自己的语言大声提问：*我该怎么分辨好种子和坏种子？* agent 会：

- **聆听**，把语音转成文字。
- **检索**一本 154 页、用英语写成的农业手册。
- **回答**，用提问所用的语言说出两到四句话，且只依据手册中的内容。
- **朗读**答案并展示来源页码，以便核对。

如果有人问板球或编程，它会礼貌地把话题引回农业，而不是凭空编造。

## CUGA 处在什么位置

[CUGA](https://cuga.dev)（ConfigUrable Generalist Agent）是 IBM Research 的开源 agent harness。它负责模型接入、工具管理、状态与 guardrails，因此你只需要写工具和 prompt，而不用去写 agent 循环。在这里，我们把它当作嵌入式 SDK 用在一个小型 Web 应用里，主要做三件事：

- **一个 agent，任意模型。** 改一个设置就能在 watsonx 和 OpenAI 之间切换。
- **知识引擎。** 解析 PDF、切块、embed，并用 `agent.knowledge.search()` 在本地检索。
- **会话线程。** 每个问题都开一个新线程，这样一个人的语言或上下文永远不会串到另一个人那里。

核心的设计思路很简单：**CUGA 是一个文本进、文本出的大脑。** 语音只是它外面薄薄的两层。

```
audio ──▶ speech-to-text ──▶ knowledge.search ──▶ CUGA (grounded answer) ──▶ text-to-speech ──▶ audio
```

由于 agent 只能看到文本，你可以先用纯文本把它构建并测试好，然后再给它加上耳朵和嘴巴。你也可以在不改动 agent 的情况下替换语音提供方。我们支持两种：Sarvam AI 的云端语音 API，由用户的浏览器直接调用；以及在你自己服务器上运行的开源模型（语音识别用 SraVaani，语音合成用 Svara）。

### 难的不是语音

加上语音是容易的那部分。难的是**跨语言检索**：一个 Hindi 问题必须能找到一段英文段落。

检索的原理是把文本转成向量，再找出最近的向量。CUGA 默认的 embedding 模型只支持英语，所以它会把 Hindi 转成几乎不携带任何含义的向量。用它的时候，一个 Hindi 或 Tamil 问题照样能检索出五个段落，但都是错的段落。模型被告知只能依据所给内容作答——这条指令执行得很正确——于是它悄悄地回答“手册里没有涵盖这一点”。每一层的行为都是对的，所以既没有报错，也没有告警。

解决办法是改用多语言 embedding 模型（我们用的是 `intfloat/multilingual-e5-large`），这样无论什么语言，相同的含义都会落在相同的位置。概念上很简单，不过要把它接进 CUGA 还是需要一个小小的变通办法（教程中有演示）。做完这一步，一份英文文档就能服务所有语言，你也不需要任何东西的译文副本。

我们的建议是：在你调整哪怕一个 prompt 之前，先用一种非英语语言向你的 agent 提一个问题，看它能不能找到正确的页面。

### 让它听起来得体，并保持安全

有几个小决定，重要性超出了我们的预期：

- **为耳朵而写。** Markdown、项目符号、引用标签，以及像“millet (बाजरा)”这样带括号的译名，朗读出来都很别扭。prompt 要求模型不要产出这些东西，而一个轻量的格式化器会在朗读之前清掉漏网的残留。
- **让 guardrails 保持廉价。** 简单的输入检查就能拦下明显的跑题问题。如果有漏网的，模型会在回复开头写上 `OFF_TOPIC`，应用再替换成一句礼貌的引导。不需要第二次 LLM 调用，所以语音链路依然很快。
- **让每个答案都有依据。** 模型只能看到检索到的段落，被要求不得使用外部知识，来源页码也会展示给用户。
- **把密钥挡在服务器之外。** 选择 Sarvam 方案时，浏览器直接与 Sarvam 通信。服务器只收到文本，永远看不到用户的密钥。

## 不止农业：为 Bharat 规模化

这里的任何东西都不专属于农业。把农业手册换成方案文件、健康提示或法律指南，你就得到另一个助手。换掉语音提供方，你就改变了部署模式——比如为追求速度用云端，或为数据主权用本地部署——而无需重写 agent。

语音优先、多语言的助手，是数字服务触达那些从未被纯英文文本界面服务好的人群的方式。把它们建立在开放、可审计的 harness 之上，并让答案与人们能够核查的来源绑定，这是它们赢得信任的方式。

这种方法恰好落在我们与 IBM Bharat Core 共同构建的方向的交汇处。Bharat Core 是构建在 IBM Sovereign Core 之上的优化 AI 栈，专为印度生态设计，用于在本地基础设施上安全地运行 Indic AI 负载。当把一个语音 agent 从原型扩展到安全的企业级应用（比如本地语言的 KYC 系统或多语言政务机器人）时，你需要对数据主权有更强的控制。把 CUGA 灵活的 agent harness 与 Bharat Core 开箱即用的 Indic connectors 和微调模型结合起来，开发者就能构建完全合规、主权可控、契合印度独特语言多样性的 AI 方案。

如果你在面向印度做规模化构建，可以看看 **[IBM Bharat Core](https://www.ibmbharatcore.info/)** 上的工作。
