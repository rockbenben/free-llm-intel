# WWDC 24：用 Core ML 运行 Mistral 7B

WWDC'24 是 Apple 正式发布 Apple Intelligence、重申其对高效、隐私、端侧 AI 承诺的时刻。在主题演讲和随后的分场中，他们演示了 Apple Intelligence——它驱动了一大片 AI 增强功能，在日常任务中展现了实用价值。这些不是 *为 AI 而 AI* 的花哨 demo，而是省时、恰当（还挺有趣！）的助手，与应用和操作系统深度整合，同时给开发者提供了多种方式把这些能力纳入自己的应用。

Apple Intelligence 的功能能这么好用，靠的是垂直整合的软件栈充分发挥了 Apple Silicon 的能力。Apple 还面向开发者提供了在端侧运行模型的框架 Core ML。这套软件栈可以让 ML 模型用到 Apple Silicon 硬件上全部 3 种计算单元（CPU、GPU 和神经引擎）。

在这篇博文中，我们将探索几项最棒的新 Core ML 特性，用来复刻 Apple 在 WWDC'24 的 [Deploy machine learning and AI models on-device with Core ML](https://developer.apple.com/videos/play/wwdc2024/10161/) 分场中展示的 Mistral 7B 示例——他们用 [swift-transformers](https://github.com/huggingface/swift-transformers) 的一个 fork 在 Mac 上运行了一个最先进的大语言模型。这是一个 70 多亿参数的高质量模型，把当今消费级硬件的能力推到了极限。你还可以看看 WWDC'24 的另一场 [Bring your machine learning and AI models to Apple silicon](https://developer.apple.com/videos/play/wwdc2024/10159/)，里面展示了 Mistral 7B 转换过程的一部分。

我们来看看如何把它跑得尽可能高效，并学习 iOS 18 与 macOS Sequoia 中的新工具。

## WWDC'24 最值得关注的新 Core ML 特性

下面是 WWDC'24 的 Core ML 特性中，我们用来在 Mac 上跑 Mistral 7B 时影响最大的几项。

### Swift Tensor

首先想强调的特性是一种全新的 Swift 类型，用于处理 ML 张量。这些是 ML 框架都在用的多维数据结构。做 ML 的 Python 开发者都熟悉 `numpy` 数组或 `torch` 张量——它们提供了便捷的高层接口来轻松操作大型多维矩阵。新的 [`MLTensor`](https://developer.apple.com/documentation/coreml/MLTensor) 类型提供了与 Python 框架类似的高层抽象，大大简化了 Swift 中的张量数据处理。

Core ML 早已有 [MLMultiArray](https://developer.apple.com/documentation/coreml/mlmultiarray) 和 [MLShapedArray](https://developer.apple.com/documentation/coreml/mlshapedarray) 这类多维数据类型，但它们只适合数据存储和简单操作——比如把数据打包送进 Core ML 模型，或者从模型结果里解包。要用这些 API *操作* 张量数据则很难：只提供了少数几个原始操作，往往得把底层存储当不透明指针取出来自己写实现，既费时又易错。

新的 `Tensor` 类型提供了与 Python 框架类似的高层抽象，大幅简化 Swift 的张量操作。考虑我们要移植到 Core ML 的这种语言模型：语言模型接收 token 输入序列，输出词表中所有 token 的概率估计——概率高的 token 更可能是输入的合理续写。应用的工作就是根据这些概率挑选下一个最佳 token 追加到序列。`Tensor` 类型让这类操作不需要自定义代码就能轻松处理。

[我们发布 swift-transformers](https://huggingface.co/blog/swift-coreml-llm) 时写了很多代码（后来社区还做了扩展，谢谢！❤️）来处理输入准备（把词转成 token）和输出后处理。例如我们[用 Accelerate 实现的 softmax 操作](https://github.com/huggingface/swift-transformers/blob/main/Sources/TensorUtils/Math.swift#L103)。改用 `MLTensor` 后这些都可以删掉，因为 `softmax` 是开箱即用的！

### Stateful Buffers（有状态缓冲）

在 WWDC'24 之前，Core ML 模型本质上是一个纯无状态函数：你提供输入，它返回输出。但有时你需要保存依赖先前计算的状态。函数式编程维持状态的做法是多加一对输入/输出：模型根据你的输入和状态计算输出和新状态。这条路没有错，事实上 JAX 这样的高性能框架就是这么工作的。

但这里有实际限制：每调用一次模型，状态数据都要作为输入传入、作为输出取出。如果状态数据很大，这种反复搬运会增加开销、拖慢速度。对 LLM 来说尤其重要，因为生成一个序列要跑很多轮迭代，性能瓶颈通常是计算机的内存带宽（即数据搬到 GPU 再搬回来的速度）。有状态模型解决了这个问题：为状态数据预留一块内存并留在 GPU 上，使用模型时不必每次都收发它。

Stateful Buffers 在[这个 WWDC'24 分场](https://developer.apple.com/videos/play/wwdc2024/10161/?time=510)中用一个玩具示例引入，好懂但不代表 LLM 这类大模型的实际用法。transformer 类 LLM 的一个性能技巧是键值缓存（kv-caching）。如下图所示，它通过缓存先前步骤的计算结果，避开了关键注意力模块中昂贵的矩阵乘法。细节我们不多展开，要点是：kv-cache 能大幅提升性能，而且需要一大块内存——正是使用 stateful buffers 的完美场景。关于 stateful 模型，这里有 [coremltools 用户指南](https://apple.github.io/coremltools/docs-guides/source/stateful-models.html)的更新说明。

[![stateful-buffer](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/mistral-coreml/stateful-buffer.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/mistral-coreml/stateful-buffer.png)

### 新量化技术

在 WWDC 23，我们探索过一项很酷的技术——调色板量化（palettization），并展示了它如何帮助把[Stable Diffusion](https://huggingface.co/blog/fast-diffusers-coreml) 这样的文生图模型带上 Mac 和 iPhone。

这些技术能显著减小体积，但压得太狠，质量损失会很严重。越大的模型受影响越明显，因为其权重数据动态范围很广，想用一个小的查找表（LUT）覆盖所有可能值越来越难。WWDC 24 给出的解法是：一次聚焦数据更小的一块，为同一个张量的不同区域创建多个查找表。

[![quantization-algorithm](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/mistral-coreml/quantization-algorithm.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/mistral-coreml/quantization-algorithm.png)

这些方法（分块量化）让我们可以把模型压到最低 4-bit 精度。每个模型参数不再用 4 字节（`float32` 的大小）表示，半字节（nibble，4 bit）就够了。模型体积直接缩小 8 倍（还要扣除分块量化表的少量开销），与 `float16` 精度相比也有 4 倍缩小。

### Multifunction 支持

这个例子里我们不用这个特性，但它在 WWDC 24 发布，而且我们会在后续工作中展示，所以在这里提一句。Multifunction 支持 essentially 允许把 LoRA 适配器打包进生成式模型，用同一个模型（加上一小套额外参数，即 adapter）做不同的任务。LoRA 是社区对大模型微调的首选方法。在扩散模型中，你可以用 LoRA 生成不同风格的图像，比如照片写实或卡通风。我们相信 LoRA 是 Apple Genmoji 实现方案的一部分。对语言模型，LoRA 适配器可以把通用 LLM 适配到特定任务或领域。

想多了解 LoRA，可以看看[这篇博文](https://huggingface.co/blog/lora)。

想多了解 Multifunction，可以看 Apple coremltools 用户指南的[这里](https://apple.github.io/coremltools/docs-guides/source/multifunction-models.html)。

## 把 Mistral 7B 转换为 Core ML

高效运行大语言模型最重要的单一组件是 kv-cache。如上所述，它是 WWDC'24 发布的[新 stateful 模型特性](https://apple.github.io/coremltools/docs-guides/source/stateful-models.html)的理想用武之地。transformers 库中的模型本就使用大量依赖 kv-caching 的高效注意力实现，但默认实现是为 Nvidia GPU 优化的，而那类硬件的约束集与 Apple Silicon 不同。就 Core ML 而言，我们必须预先分配好完整的缓存缓冲区，并确保每次调用模型时就地更新缓冲区。这样能避免低效的内存分配和张量拼接，而且这也是 Core ML stateful buffers 的要求。

为达成这个目标，我们必须使用考虑了这些因素的另一套注意力实现。这需要修改 Mistral 架构的 transformers 建模代码，具体在[这段代码](https://github.com/huggingface/swift-transformers/blob/21b015691624ad103470370f0f255eb660579511/Examples/Mistral7B/export.py#L121)中完成。

注意：如果你想跟着复刻转换过程（或转换另一个基于 Mistral 的模型，比如不同的微调版本），可以用[这个脚本](https://github.com/huggingface/swift-transformers/blob/preview/Examples/Mistral7B/export.py)跑完全部转换步骤。

### 追踪与转换

第一步加载模型。我们使用带就地缓存方法的打过补丁的实现。

```
MODEL_ID = "mistralai/Mistral-7B-Instruct-v0.3"
torch_model = StatefulMistralForCausalLM(MODEL_ID)
torch_model.eval()
```

运行 Core ML 转换之前，需要用示例输入追踪（trace）模型。这个过程记录这些输入上执行的张量运算，追踪得到的图会在转换时被翻译成 Core ML 操作。我们用示例输入追踪模型，不需要真实数据。

```
input_ids = torch.zeros((1, 2), dtype=torch.int32)
causal_mask = torch.zeros((1, 1, 2, 5), dtype=torch.float32)

traced_model = torch.jit.trace(torch_model, [input_ids, causal_mask])
```

语言模型的输入是长度可变的 token 序列。我们允许输入从单个 token 一直增长到最大 2048 的上下文长度。可以用 [coremltools](https://github.com/apple/coremltools) 的 range dimensions 指定这些边界。

```
query_length = ct.RangeDim(lower_bound=1, upper_bound=2048, default=1)
end_step_dim = ct.RangeDim(lower_bound=1, upper_bound=2048, default=1)

inputs = [
    ct.TensorType(shape=(1, query_length), dtype=np.int32, name="inputIds"),
    ct.TensorType(shape=(1, 1, query_length, end_step_dim), dtype=np.float16, name="causalMask"),
]

outputs = [ct.TensorType(dtype=np.float16, name="logits")]
```

除了序列 token（上例中叫 `inputIds`），还有另一个输入 `causalMask`，指明模型需要注意哪些 token。它主要用于用批处理同时生成多个序列的场景：批内所有输入序列必须等长，于是用 padding token 填充，再靠因果掩码告诉模型这些 padding token 不作为输入考虑。这些输入如何使用，可以看[示例运行器里的这段代码](https://github.com/huggingface/swift-transformers/blob/21b015691624ad103470370f0f255eb660579511/Examples/Mistral7B/generate.py#L29-L42)。

### 状态准备

PyTorch 建模代码用 `keyCache` 和 `valueCache` 作为存放 kv-cache 的缓存缓冲区名。这些块按最大上下文长度（2048）分配。我们用 `coremltools` 的新的 [StateType](https://apple.github.io/coremltools/source/coremltools.converters.mil.input_types.html#statetype) 指定这些块在转换时必须转为有状态的 Core ML 缓冲区。

```
# Specify kv-cache states by using `StateType`.

states = [
    ct.StateType(
        wrapped_type=ct.TensorType(shape=torch_model.kv_cache_shape, dtype=np.float16),
        name="keyCache",
    ),
    ct.StateType(
        wrapped_type=ct.TensorType(shape=torch_model.kv_cache_shape, dtype=np.float16),
        name="valueCache",
    ),
]
```

### Core ML 转换

要把模型转成 Core ML，需要指定输入、输出类型以及状态。转换后的模型会使用 `float16` 精度，因为我们给输入数据指定的就是它。还要指明最低部署目标为 iOS18，因为这些特性从该版本起可用。（也可以用 `macOS15`，指的是同一个转换目标。）

```
mlmodel_fp16 = ct.convert(
    traced_model,
    inputs=inputs,
    states=states,
    outputs=outputs,
    minimum_deployment_target=ct.target.iOS18,
    skip_model_load=True,
)
```

### 模型压缩

使用上文描述的新分块量化策略，我们采用块大小 32 的 4-bit 线性量化。这会大幅减小模型体积并让模型跑得更快。虽然计算仍在 `float16` 下进行，但权重以 4-bit 模式传输、即时解压，比搬移大量 16-bit 权重更高效。

量化参数配置如下：

```
op_config = ct.optimize.coreml.OpLinearQuantizerConfig(
    mode="linear_symmetric",
    dtype="int4",
    granularity="per_block",
    block_size=32,
)
config = ct.optimize.coreml.OptimizationConfig(global_config=op_config)
```

用这个配置量化模型。下面这行要跑几分钟：

```
mlmodel_int4 = ct.optimize.coreml.linear_quantize_weights(mlmodel_fp16, config=config)

mlmodel_int4.save("StatefulMistral7BInstructInt4.mlpackage")
```

转换和量化完成后还有最后一步。我们需要附加一段元数据，标注我们使用的模型标识（`mistralai/Mistral-7B-Instruct-v0.3`）。Swift 代码会用它在下载 tokenizer 文件时定位。分词（tokenization）是把文本数据转换成模型使用的数值表示，每个模型都不一样。

```
mlmodel_int4._spec.description.metadata.userDefined.update({
    "co.huggingface.exporters.name": MODEL_ID
})
```

生成的模型是一个约 3.8G 的 `mlpackage`，而 `float16` 转换会产出 14G。[你可以在 Hub 上找到它](https://huggingface.co/apple/mistral-coreml/tree/main)。

## 用 Swift 运行 Mistral 7B

如果你跟着跑完了上述步骤，或从 Hub 下载了模型，就可以用 `swift-transformers` 的 `preview` 分支在本地运行它。Apple 工程师为该项目贡献了这个分支，包含以下重要特性：

- 完整的 `Tensor` 支持，大幅简化前后处理任务，让我们得以删掉大量低层、费解且脆弱的代码。
- 支持 Stateful API 的 Swift 对应实现。

由于采用这些特性是破坏性变更且需要 iOS 18 或 macOS 15，我们暂时把它们留在 `preview` 分支里。

要从命令行运行模型，请先克隆 GitHub 仓库的 `preview` 分支：

```
    git clone -b preview https://github.com/huggingface/swift-transformers
```

然后运行 CLI 测试模型：

```
#to run in release mode, pass -c release
swift run transformers "Best recommendations for a place to visit in Paris in August 2024:" --max-length 128 Examples/Mistral7B/StatefulMistral7BInstructInt4.mlpackage
```

为了方便测试，你还可以用 `swift-chat`——我们写的一个简单应用，演示如何把 `swift-transformers` 包集成进去。同样需要使用 `preview` 分支。本文开头播放的示例就是 `swift-chat` 运行转换后 Mistral 模型的画面。

## 用 Python 运行 Mistral 7B

对更熟悉 Python 的同学，同样简单！

```
python3 generate.py Examples/Mistral7B/StatefulMistral7BInstructInt4.mlpackage --prompt "Best recommendations for a place to visit in Paris in August 2024:"
```

用 coremltools 在 Python 中运行 Core ML 模型就是这么省事。

## 接下来做什么？

我们对今年 [Core ML](https://developer.apple.com/documentation/coreml/) 和 [coremltools](https://github.com/apple/coremltools) 的进展感到非常兴奋，也期待看到大量第三方应用用 ML 模型解决人们需要的真实任务。在我们这边，我们承诺让这件事尽可能简单，好让开发者专注于做出酷炫的应用。我们的图纸上还有几件事：

- 本文介绍的模型更新对 Mac 电脑的 GPU 非常理想。Core ML 还能使用神经引擎（Neural Engine），在 iPhone 上尤其高效。要榨取神经引擎的最大性能还需要一些额外适配，我们计划在若干示例模型上做这项工作，基础是 Apple 这篇 [2022 年（且至今非常有参考价值的）文章](https://machinelearning.apple.com/research/neural-engine-transformers)。我们不会在 iPhone 上跑 Mistral 7B，但有多个更小的模型——比如 Apple 的 OpenELM 或 DCLM——是绝佳的探索候选！
- 这里的代码高度实验性。随着夏天的推进，我们计划采用这些方法并集成进 `exporters`——那个把 transformers 模型转换为 Core ML 的 Python 工具。希望很快你就能非常轻松地转换许多有趣的模型架构。
- 我们会继续维护 `swift-transformers` 的 `preview` 分支，随新特性和 API 变化更新。如果你感兴趣，记得盯着它！
