# Code Llama：Llama 2 学会编程

## 简介

Code Llama 是一系列最先进的、开放访问的 [Llama 2](https://huggingface.co/blog/llama2) 代码特化版本，我们非常高兴能发布它在 Hugging Face 生态中的集成！Code Llama 采用与 Llama 2 相同的宽松社区许可证发布，可用于商业用途。

- 与 Inference Endpoints 的集成

代码 LLM 对软件工程师来说是一项令人兴奋的进展，因为它可以通过 IDE 中的代码补全提升生产力、代劳重复或烦人的任务（比如写 docstring），还能生成单元测试。

## Code Llama 是什么？

本次 Code Llama 发布了一个包含 70 亿、130 亿和 340 亿参数参数的模型家族。基础模型从 Llama 2 初始化，然后在 5000 亿 token 的代码数据上训练。Meta 对这些基础模型进行了两种不同方向的微调：Python 专精版本（额外 1000 亿 token）和能理解自然语言指令的指令微调版本。

这些模型在 Python、C++、Java、PHP、C#、TypeScript 和 Bash 上均表现出最先进水平。7B 和 13B 的基础版与指令版都支持基于上下文的填充（infilling），非常适合作为代码助手使用。

Code Llama 以 16k 上下文窗口训练。此外，三种模型变体都经过了额外的长上下文微调，可以管理最长 100,000 token 的上下文窗口。

把 Llama 2 的 4k 上下文窗口提升到 Code Llama 的 16k（可外推至 100k）得益于 RoPE 缩放的最新进展。社区发现 Llama 的位置编码可以在线性域或频率域中进行插值，这通过微调让向更大上下文窗口的过渡变得平滑。在 Code Llama 的情况下，频率域缩放是带余量（slack）进行的：微调长度仅为缩放后预训练长度的一小部分，这赋予了模型强大的外推能力。

[![训练流程](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/160_codellama/training-process.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/160_codellama/training-process.jpg)

所有模型最初都在一个近乎去重（near-deduplicated）的公开代码数据集上用 5000 亿 token 训练。该数据集中也包含一些自然语言数据，例如关于代码的讨论和代码片段。遗憾的是，关于数据集没有更多信息。

对于指令模型，他们使用了两个数据集：为 Llama 2 Chat 收集的指令微调数据集，以及一个自指令（self-instruct）数据集。自指令数据集的做法是：用 Llama 2 生成面试编程题，然后用 Code Llama 生成单元测试和解法，最后通过执行测试来评估。

#### 关于数据类型的说明

在使用 Code Llama 这类模型时，关注模型的数据类型很重要。

- 32 位浮点（`float32`）：PyTorch 的惯例是在初始化模型时以 `float32` 加载，无论模型权重以何种精度存储。`transformers` 出于与 PyTorch 保持一致的考虑也遵循这一惯例。
- 16 位 Brain 浮点（`bfloat16`）：Code Llama 就是以这种精度训练的，因此如果继续训练或微调，推荐使用它。
- 16 位浮点（`float16`）：推荐用这种精度做推理，因为它通常比 `bfloat16` 更快，且评估指标相比 `bfloat16` 没有可察觉的下降。你也可以用 `bfloat16` 做推理，并建议微调后分别用 `float16` 和 `bfloat16` 检查推理结果。

如上所述，`transformers` 以 `float32` 加载权重（无论模型以何种精度存储），因此在加载模型时明确指定所需的 `dtype` 很重要。如果要微调 Code Llama，建议使用 `bfloat16`，因为 `float16` 可能导致溢出和 NaN。如果做推理，建议使用 `float16`，因为 `bfloat16` 可能更慢。

#### 代码补全

7B 和 13B 模型可以用于文本/代码补全或填充。下面的代码片段使用 `pipeline` 接口演示文本补全。只要选择 GPU 运行时，它就能在 Colab 免费层上运行。

```
from transformers import AutoTokenizer
import transformers
import torch

tokenizer = AutoTokenizer.from_pretrained("codellama/CodeLlama-7b-hf")
pipeline = transformers.pipeline(
    "text-generation",
    model="codellama/CodeLlama-7b-hf",
    torch_dtype=torch.float16,
    device_map="auto",
)

sequences = pipeline(
    'def fibonacci(',
    do_sample=True,
    temperature=0.2,
    top_p=0.9,
    num_return_sequences=1,
    eos_token_id=tokenizer.eos_token_id,
    max_length=100,
)
for seq in sequences:
    print(f"Result: {seq['generated_text']}")
```

输出可能类似下面这样：

Code Llama 专精于代码理解，但它本身也是一个语言模型。你可以用同样的生成策略来补全注释或普通文本。

#### 代码填充

这是代码模型特有的一项任务。模型被训练成根据已有的前缀和后缀生成最匹配的 code（包括注释）。这正是代码助手通常采用的策略：它们被要求填充当前光标位置，同时参考其前后出现的内容。

该任务在 7B 和 13B 模型的**基础版**和**指令版**中可用。34B 系列模型和 Python 版本均*不*支持。

要正确使用这个功能，你需要密切关注模型在此任务训练时使用的格式，因为它使用特殊分隔符来识别提示词的不同部分。好在 transformers 的 `CodeLlamaTokenizer` 把这件事变得非常简单，如下所示：

```
from transformers import AutoTokenizer, AutoModelForCausalLM
import transformers
import torch

model_id = "codellama/CodeLlama-7b-hf"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    torch_dtype=torch.float16
).to("cuda")

prompt = '''def remove_non_ascii(s: str) -> str:
    """ <FILL_ME>
    return result
'''

input_ids = tokenizer(prompt, return_tensors="pt")["input_ids"].to("cuda")
output = model.generate(
    input_ids,
    max_new_tokens=200,
)
output = output[0].to("cpu")

filling = tokenizer.decode(output[input_ids.shape[1]:], skip_special_tokens=True)
print(prompt.replace("<FILL_ME>", filling))
```

```
def remove_non_ascii(s: str) -> str:
    """ Remove non-ASCII characters from a string.

    Args:
        s: The string to remove non-ASCII characters from.

    Returns:
        The string with non-ASCII characters removed.
    """
    result = ""
    for c in s:
        if ord(c) < 128:
            result += c
    return result
```

底层实现上，tokenizer 会[自动按 `<FILL_ME>` 切分](https://huggingface.co/docs/transformers/main/model_doc/code_llama#transformers.CodeLlamaTokenizer.fill_token)，生成符合[原始训练格式](https://github.com/facebookresearch/codellama/blob/cb51c14ec761370ba2e2bc351374a79265d0465e/llama/generation.py#L402)的输入字符串。这比自己手动拼格式更稳妥：它避开了诸如 token 粘连（token glueing）这类极难调试的坑。

#### 对话式指令

基础模型可用于补全和填充，如上所述。Code Llama 发布还包含一个指令微调模型，可用于对话式界面。

为该任务准备输入时，需要使用我们在 [Llama 2 博客文章](https://huggingface.co/blog/llama2#how-to-prompt-llama-2)中介绍过的提示词模板，这里再贴一次：

```
<s>[INST] <<SYS>>
{{ system_prompt }}
<</SYS>>

{{ user_msg_1 }} [/INST] {{ model_answer_1 }} </s><s>[INST] {{ user_msg_2 }} [/INST]
```

注意系统提示词（system prompt）是可选的——没有它模型也能工作，但你可以用它进一步配置模型的行为或风格。例如，如果你希望始终得到 JavaScript 的回答，就可以在这里写明。系统提示词之后，需要提供对话中此前的所有交互：用户问了什么、模型答了什么。和填充一样，要注意使用的分隔符。输入的最后部分必须是一个新的用户指令，这将作为模型给出回答的信号。

以下代码片段演示了这个模板的实际用法。

- **首个用户提问，无系统提示词**

```
user = 'In Bash, how do I list all text files in the current directory (excluding subdirectories) that have been modified in the last month?'

prompt = f"<s>[INST] {user.strip()} [/INST]"
inputs = tokenizer(prompt, return_tensors="pt", add_special_tokens=False).to("cuda")
```

- **首个用户提问，带系统提示词**

```
system = "Provide answers in JavaScript"
user = "Write a function that computes the set of sums of all contiguous sublists of a given list."

prompt = f"<s>[INST] <<SYS>>\\n{system}\\n<</SYS>>\\n\\n{user}[/INST]"
inputs = tokenizer(prompt, return_tensors="pt", add_special_tokens=False).to("cuda")
```

- **进行中的对话，包含已有回答**

流程与 [Llama 2](https://huggingface.co/blog/llama2#how-to-prompt-llama-2) 相同。为了表述最清晰，这个例子没有使用循环或做通用化：

```
system = "System prompt"
user_1 = "user_prompt_1"
answer_1 = "answer_1"
user_2 = "user_prompt_2"
answer_2 = "answer_2"
user_3 = "user_prompt_3"

prompt  = f"<<SYS>>\n{system}\n<</SYS>>\n\n{user_1}"
prompt  = f"<s>[INST] {prompt.strip()} [/INST] {answer_1.strip()} </s>"
prompt += f"<s>[INST] {user_2.strip()} [/INST] {answer_2.strip()} </s>"
prompt += f"<s>[INST] {user_3.strip()} [/INST]"

inputs = tokenizer(prompt, return_tensors="pt", add_special_tokens=False).to("cuda")
```

#### 4-bit 加载

Code Llama 在 Transformers 中的集成意味着你可以立即使用 4-bit 加载等高级特性。这让你能在 nvidia 3090 这类消费级 GPU 上运行 32B 参数的大模型！

以 4-bit 模式运行推理的方法如下：

```
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig
import torch

model_id = "codellama/CodeLlama-34b-hf"
quantization_config = BitsAndBytesConfig(
   load_in_4bit=True,
   bnb_4bit_compute_dtype=torch.float16
)

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    quantization_config=quantization_config,
    device_map="auto",
)

prompt = 'def remove_non_ascii(s: str) -> str:\n    """ '
inputs = tokenizer(prompt, return_tensors="pt").to("cuda")

output = model.generate(
    inputs["input_ids"],
    max_new_tokens=200,
    do_sample=True,
    top_p=0.9,
    temperature=0.1,
)
output = output[0].to("cpu")
print(tokenizer.decode(output))
```

### 使用 text-generation-inference 和 Inference Endpoints

[Text Generation Inference](https://github.com/huggingface/text-generation-inference) 是 Hugging Face 开发的生产级推理容器，让大语言模型的部署变得简单。它具备持续批处理（continuous batching）、token 流式输出、用于多 GPU 快速推理的张量并行，以及生产级的日志与链路追踪等功能。

你可以在自己的基础设施上试用 Text Generation Inference，也可以使用 Hugging Face 的 [Inference Endpoints](https://huggingface.co/inference-endpoints)。要部署 Codellama 2 模型，前往[模型页面](https://huggingface.co/codellama)并点击 [Deploy -> Inference Endpoints](https://huggingface.co/codellama/CodeLlama-7b-hf) 组件即可。

- 对于 7B 模型，我们建议选择 "GPU [medium] - 1x Nvidia A10G"。
- 对于 13B 模型，我们建议选择 "GPU [xlarge] - 1x Nvidia A100"。
- 对于 34B 模型，我们建议选择 "GPU [1xlarge] - 1x Nvidia A100" 并启用 `bitsandbytes` 量化，或选择 "GPU [2xlarge] - 2x Nvidia A100"。

*注意：访问 A100 可能需要通过邮件向 **[api-enterprise@huggingface.co](mailto:api-enterprise@huggingface.co)** 申请配额提升*

想了解更多内容，请阅读我们博客中的[如何用 Hugging Face Inference Endpoints 部署 LLM](https://huggingface.co/blog/inference-endpoints-llm)。该[博客](https://huggingface.co/blog/inference-endpoints-llm)还介绍了支持的超参数，以及如何用 Python 和 Javascript 流式获取响应。

## 评测

代码语言模型通常在 HumanEval 等数据集上进行基准测试。它由一系列编程挑战组成：模型会看到一个函数签名和一段 docstring，需要补全函数体。然后通过对预定义单元测试集来验证模型给出的解法。最终报告的是通过率，即多少解法通过了全部测试。pass@1 衡量模型只有一次机会时生成正确解法的频率，而 pass@10 衡量在 10 个候选解法中至少有一个通过的概率。

虽然 HumanEval 是一个 Python 基准，但业界已投入大量工作将其翻译到更多编程语言，从而实现更全面的评估。[MultiPL-E](https://github.com/nuprl/MultiPL-E) 就是这样一种方法，它把 HumanEval 翻译成了十几种语言。我们基于它托管了一个[多语言代码排行榜](https://huggingface.co/spaces/bigcode/multilingual-code-evals)，让社区可以在不同语言之间比较模型，评估哪个模型最适合自己的使用场景。
