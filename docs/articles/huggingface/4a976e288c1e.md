大语言模型（LLM）能力惊人，但也需要巨大的算力——个人电脑上很少具备。于是我们别无选择，只能把它们部署在本地机房或云端的专用 AI 服务器上。

## 为什么本地 LLM 推理令人向往

如果能在普通个人电脑上运行最先进的开源 LLM，我们难道不能享受这些好处吗：

- **更强的隐私**：数据不必为推理发送到外部 API。
- **更低的延迟**：省掉网络往返。
- **离线工作**：无需联网也能工作（常旅客的梦想！）。
- **更低的成本**：不必为 API 调用或模型托管花钱。
- **可定制性**：每个用户都能找到最适合日常任务的模型，甚至可以微调，或用本地检索增强生成（RAG）提升相关性。

这一切听起来确实令人心动。那为什么我们还没这么做？回到开头的话：你日常那台价格适中的笔记本算力不足以用可接受的性能运行 LLM。既没有几千核的 GPU，也没有飞快的高带宽内存。

难道没戏了？当然不是。

## 为什么本地 LLM 推理现在成为可能

人类的头脑总能把东西做得更小、更快、更优雅、更省钱。近几个月，AI 社区努力在不牺牲预测质量的前提下压缩模型。三个方向令人兴奋：

- **硬件加速**：现代 CPU 架构内置专门加速最常见深度学习算子（如矩阵乘法、卷积）的硬件，让 AI PC 上涌现新的生成式 AI 应用，并显著提升其速度与效率。
- **小语言模型（SLM）**：得益于创新的架构与训练技术，这些模型与更大的模型并驾齐驱甚至更好。因为参数更少，推理所需的计算与内存更低，是资源受限环境的绝佳候选。
- **量化**：量化通过降低模型权重与激活的位宽（例如从 16 位浮点 `fp16` 降到 8 位整数 `int8`）来降低内存与计算需求。减少位数意味着所得模型推理时占用更少内存，从而加快内存受限步骤（如文本生成的解码阶段）的延迟。此外，当权重与激活同时量化时，得益于整数运算，矩阵乘法等操作还能跑得更快。

本文中我们三者并用。从 Microsoft 的 [Phi-2](https://huggingface.co/microsoft/phi-2) 模型出发，借助我们 [Optimum Intel](https://github.com/huggingface/optimum-intel) 库中的 Intel OpenVINO 集成，对模型权重施加 4-bit 量化。然后在一台搭载 Intel Meteor Lake CPU 的中端笔记本上运行推理。

> 注：如果你对权重与激活同时量化感兴趣，可以在文档中找到更多信息。

开工吧。

## Intel Meteor Lake

Intel Meteor Lake 于 2023 年 12 月发布（现已更名为 [Core Ultra](https://www.intel.com/content/www/us/en/products/details/processors/core-ultra.html)），是一个为高性能笔记本优化的新[架构](https://www.intel.com/content/www/us/en/content-details/788851/meteor-lake-architecture-overview.html)。

作为 Intel 首款采用 chiplet 架构的客户端处理器，Meteor Lake 包含：

- 一颗最多 16 核的**高能效 CPU**；
- 一个最多 8 个 Xe 核的**集成 GPU（iGPU）**，每个 Xe 核含 16 个 Xe 向量引擎（XVE）。顾名思义，XVE 可对 256 位向量做向量运算，还实现 DP4a 指令：在两个 4 字节值向量之间计算点积，把结果存进 32 位整数并加到第三个 32 位整数上。
- 一个**神经网络处理单元（NPU）**——Intel 架构首次。NPU 是为高效端侧 AI 打造的专用 AI 引擎，专门高效地处理繁重的 AI 计算，释放主 CPU 与显卡去做别的事。相比用 CPU 或 iGPU 做 AI 任务，NPU 的设计更省电。

为了运行下面的 demo，我们选了一台搭载 [Core Ultra 7 155H CPU](https://www.intel.com/content/www/us/en/products/sku/236847/intel-core-ultra-7-processor-155h-24m-cache-up-to-4-80-ghz/specifications.html) 的[中端笔记本](https://www.amazon.com/MSI-Prestige-Evo-Laptop-A1MG-029US/dp/B0CP9Y8Q6T/)。现在，挑一个可爱的小语言模型在这台笔记本上跑。

> 注：要在 Linux 上运行这段代码，请按照说明安装 GPU 驱动。

## Microsoft Phi-2 模型

[Phi-2](https://huggingface.co/microsoft/phi-2) 于 2023 年 12 月[发布](https://www.microsoft.com/en-us/research/blog/phi-2-the-surprising-power-of-small-language-models/)，是一个 27 亿参数、面向文本生成训练的模型。

在已公布的基准上，Phi-2 不以为小的体积为意，超越了部分最好的 70 亿、130 亿参数 LLM，甚至逼近大得多的 Llama-2 70B。

这让它成为笔记本推理的热门候选。好奇的读者也可以试试 11 亿参数的 [TinyLlama](https://huggingface.co/TinyLlama/TinyLlama-1.1B-Chat-v1.0) 模型。

接下来看看如何把模型压缩得更小更快。

## 用 Intel OpenVINO 与 Optimum Intel 做量化

Intel OpenVINO 是一个用于在多种 Intel 硬件平台上优化 AI 推理的开源工具包（[Github](https://github.com/openvinotoolkit/openvino)、[文档](https://docs.openvino.ai/2024/home.html)），核心手段之一就是模型量化。

我们与 Intel 合作，把 OpenVINO 集成进了 Optimum Intel——我们专注在 Intel 平台加速 Hugging Face 模型的开源库（[Github](https://github.com/huggingface/optimum-intel)、[文档](https://huggingface.co/docs/optimum/intel/index)）。

首先确保安装了最新版本的 `optimum-intel` 及所有必要依赖：

```
pip install --upgrade-strategy eager optimum[openvino,nncf]
```

这个集成让 Phi-2 的 4-bit 量化简单直白。我们定义一个量化配置，设置优化参数，从 hub 加载模型；量化并优化完成后存到本地。

```
from transformers import AutoTokenizer, pipeline
from optimum.intel import OVModelForCausalLM, OVWeightQuantizationConfig

model_id = "microsoft/phi-2"
device = "gpu"
# Create the quantization configuration with desired quantization parameters
q_config = OVWeightQuantizationConfig(bits=4, group_size=128, ratio=0.8)

# Create OpenVINO configuration with optimal settings for this model
ov_config = {"PERFORMANCE_HINT": "LATENCY", "CACHE_DIR": "model_cache", "INFERENCE_PRECISION_HINT": "f32"}

tokenizer = AutoTokenizer.from_pretrained(model_id)
model = OVModelForCausalLM.from_pretrained(
    model_id,
    export=True, # export model to OpenVINO format: should be False if model already exported
    quantization_config=q_config,
    device=device,
    ov_config=ov_config,
  )

# Compilation step : if not explicitly called, compilation will happen before the first inference
model.compile()
pipe = pipeline("text-generation", model=model, tokenizer=tokenizer)
results = pipe("He's a dreadful magician and")

save_directory = "phi-2-openvino"
model.save_pretrained(save_directory)
tokenizer.save_pretrained(save_directory)
```

`ratio` 参数控制我们量化到 4-bit 的权重比例（这里是 80%），其余量化到 8-bit。`group_size` 定义权重量化分组的大小（这里 128），每组有自己的缩放因子。调小这两个值通常能提升精度，代价是模型体积与推理延迟。

关于权重量化的更多信息见我们的[文档](https://huggingface.co/docs/optimum/main/en/intel/optimization_ov#weight-only-quantization)。

> 注：带文本生成示例的完整 notebook 在 Github 上。

那么，量化模型在我们笔记本上有多快？看下面的视频亲自感受。记得选 1080p 分辨率以获得最清晰的画面。

第一个视频问模型一道高中物理题："*Lily has a rubber ball that she drops from the top of a wall. The wall is 2 meters tall. How long will it take for the ball to reach the ground?*"

第二个视频问模型一道编程题："*Write a class which implements a fully connected layer with forward and backward functions using numpy. Use markdown markers for code.*"

如两个示例所见，生成的回答质量非常高。量化过程没有损害 Phi-2 的高质量，生成速度也够用。我很乐意每天在本地和这个模型一起工作。
