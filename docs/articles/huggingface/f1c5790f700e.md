# Würstchen 介绍：用于图像生成的快速扩散模型

[![Collage of images created with Würstchen](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/wuertschen/collage_compressed.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/wuertschen/collage_compressed.jpg)

## 什么是 Würstchen？

Würstchen 是一个扩散模型，其文本条件组件在高度压缩的图像潜在空间中工作。为什么这很重要？压缩数据可以把训练和推理的计算成本降低几个数量级。在 1024×1024 图像上训练比在 32×32 上训练昂贵得多。通常，其他工作只使用相对较小的压缩，空间压缩倍数在 4x-8x 之间。Würstchen 把这一点推向极致：通过其新颖设计实现了 42x 的空间压缩！此前从未有人做到，因为常见方法在 16x 空间压缩后就无法忠实重建细节丰富的图像。Würstchen 采用两级压缩，我们称之为 Stage A 和 Stage B。Stage A 是 VQGAN，Stage B 是扩散自编码器（细节见**[论文](https://arxiv.org/abs/2306.00637)**）。Stage A 和 B 合起来称为*Decoder（解码器）*，因为它们把压缩图像解码回像素空间。第三个模型 Stage C 学习于这个高度压缩的潜在空间。这部分训练所需的算力只是当前最先进模型的几分之一，同时还能带来更便宜、更快速的推理。我们把 Stage C 称为 *Prior（先验）*。

[![Würstchen images with Prompts](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/wuertschen/generated_images.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/wuertschen/generated_images.jpg)

## 为什么再来一个文生图模型？

因为这个特别快、特别高效。Würstchen 最大的优势在于它生成图像比 Stable Diffusion XL 这类模型快得多，而且内存占用小得多！对于我们这些没有 A100 可用的人来说，这来得正及时。下面是与 SDXL 在不同批大小下的对比：

[![Inference Speed Plots](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/wuertschen/inference_speed_v2.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/wuertschen/inference_speed_v2.jpg)

此外，Würstchen 的另一个重大意义在于训练成本的大幅降低。在 512x512 分辨率上工作的 Würstchen v1 只需要 9,000 GPU 小时的训练。与之相比，Stable Diffusion 1.4 花了 150,000 GPU 小时——这一 16 倍的成本下降不仅让研究者做新实验时受益，也让更多机构有机会训练此类模型。Würstchen v2 用了 24,602 GPU 小时，分辨率提升到 1536，仍然比只在 512x512 训练的 SD1.4 便宜 6 倍。

## 如何使用 Würstchen？

你可以在这里体验 Demo：

另外，模型可通过 Diffusers 库使用，所以你可以直接用熟悉的方式。例如，用 `AutoPipeline` 推理：

```
import torch
from diffusers import AutoPipelineForText2Image
from diffusers.pipelines.wuerstchen import DEFAULT_STAGE_C_TIMESTEPS

pipeline = AutoPipelineForText2Image.from_pretrained("warp-ai/wuerstchen", torch_dtype=torch.float16).to("cuda")

caption = "Anthropomorphic cat dressed as a firefighter"
images = pipeline(
    caption,
    height=1024,
    width=1536,
    prior_timesteps=DEFAULT_STAGE_C_TIMESTEPS,
    prior_guidance_scale=4.0,
    num_images_per_prompt=4,
).images
```

[![Anthropomorphic cat dressed as a fire-fighter](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/wuertschen/Anthropomorphic_cat_dressed_as_a_fire_fighter.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/wuertschen/Anthropomorphic_cat_dressed_as_a_fire_fighter.jpg)

### Würstchen 支持什么图像尺寸？

Würstchen 在 1024x1024 到 1536x1536 的分辨率之间训练。我们也观察到在 1024x2048 这类尺寸上有时效果不错，欢迎尝试。我们还发现 Prior（Stage C）对新分辨率的适应非常快，所以在 2048x2048 上微调它的计算成本应该很低。![](https://cdn-uploads.huggingface.co/production/uploads/634cb5eefb80cc6bcaf63c3e/5pA5KUfGmvsObqiIjdGY1.jpeg)

### Hub 上的模型

所有 checkpoint 都可以在 [Huggingface Hub](https://huggingface.co/warp-ai) 上看到。多个 checkpoint、未来的 demo 和模型权重都在那里。目前有 3 个 Prior 的 checkpoint 和 1 个 Decoder 的 checkpoint。请查看[文档](https://huggingface.co/docs/diffusers/main/en/api/pipelines/wuerstchen)，其中有对 checkpoint 的说明，以及不同 Prior 模型是什么、可用于什么。

### Diffusers 集成

由于 Würstchen 完全集成在 `diffusers` 中，它开箱即用地带来各种好东西和优化。其中包括：

- 自动使用 [PyTorch 2 `SDPA`](https://huggingface.co/docs/diffusers/optimization/torch2.0) 加速注意力（下文详述）。
- 支持 [xFormers flash attention](https://huggingface.co/docs/diffusers/optimization/xformers) 实现，供仍需使用 PyTorch 1.x 而非 2.0 的用户。
- [模型卸载（Model offload）](https://huggingface.co/docs/diffusers/optimization/fp16#model-offloading-for-fast-inference-and-memory-savings)，在未使用时把不活跃的组件移到 CPU，以几乎不损失性能节省内存。
- [顺序 CPU 卸载（Sequential CPU offload）](https://huggingface.co/docs/diffusers/optimization/fp16#offloading-to-cpu-with-accelerate-for-memory-savings)，用于内存真正紧张的场景，内存占用降到最低，代价是推理变慢。
- 借助 [Compel](https://github.com/damian0815/compel) 库实现[prompt 加权](https://huggingface.co/docs/diffusers/using-diffusers/weighted_prompts)。
- 支持 Apple Silicon mac 上的 [`mps` 设备](https://huggingface.co/docs/diffusers/optimization/mps)。
- 使用 generator 实现[可复现性](https://huggingface.co/docs/diffusers/using-diffusers/reproducibility)。
- 为推理设置合理的默认值，在多数情况下产出高质量结果。当然，所有参数都可以按你的意愿调整！

## 优化技术一：Flash Attention

从 2.0 版本起，PyTorch 集成了一个高度优化、资源友好的注意力机制版本 [`torch.nn.functional.scaled_dot_product_attention`](https://pytorch.org/docs/master/generated/torch.nn.functional.scaled_dot_product_attention)（SDPA）。根据输入的特性，该函数会调用多种底层优化，其性能和内存效率都超越传统注意力模型。值得注意的是，SDPA 函数体现了*flash attention*技术的特性，正如 Dao 团队的研究论文 [Fast and Memory-Efficient Exact Attention with IO-Awareness](https://arxiv.org/abs/2205.14135) 所述。

如果你在 PyTorch 2.0+ 上使用 Diffusers 且 SDPA 可用，这些增强会自动生效。按照[官方指南](https://pytorch.org/get-started/locally/)安装 torch 2.0 或更新版本即可开始！

```
images = pipeline(caption, height=1024, width=1536, prior_timesteps=DEFAULT_STAGE_C_TIMESTEPS, prior_guidance_scale=4.0, num_images_per_prompt=4).images
```

要深入了解 `diffusers` 如何利用 SDPA，请查看[文档](https://huggingface.co/docs/diffusers/optimization/torch2.0)。

如果你用的是 2.0 之前的 PyTorch，仍可以通过 [xFormers](https://facebookresearch.github.io/xformers/) 库实现内存高效注意力：

```
pipeline.enable_xformers_memory_efficient_attention()
```

## 优化技术二：Torch Compile

如果你想再榨一点性能，可以使用 `torch.compile`。最佳做法是同时对 prior 和 decoder 的主模型应用它，以获得最大的性能提升。

```
pipeline.prior_prior = torch.compile(pipeline.prior_prior , mode="reduce-overhead", fullgraph=True)
pipeline.decoder = torch.compile(pipeline.decoder, mode="reduce-overhead", fullgraph=True)
```

请注意，模型编译期间首次推理会耗时较长（最多 2 分钟）。之后正常推理即可：

```
images = pipeline(caption, height=1024, width=1536, prior_timesteps=DEFAULT_STAGE_C_TIMESTEPS, prior_guidance_scale=4.0, num_images_per_prompt=4).images
```

好消息是编译只需执行一次。此后，在相同的图像分辨率上你会持续获得更快的推理。初始的编译时间投入很快就能被后续的速度收益抵消。想深入了解 `torch.compile` 及其细节，请看[官方文档](https://pytorch.org/tutorials/intermediate/torch_compile_tutorial.html)。
