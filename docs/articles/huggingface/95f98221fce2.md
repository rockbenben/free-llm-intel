### 训练管线

随着 Open R1 的发布，GRPO（Grouped Relative Policy Optimization，分组相对策略优化）已被整合进最新的 TRL 版本（[0.14 版](https://x.com/QGallouedec/status/1884978284686905468)）。这一集成使得用单个或多个奖励函数/奖励模型训练任何模型成为可能。GRPO 实现与 DeepSpeed ZeRO 1/2/3 集成，支持可扩展到大量 GPU 的并行训练，并使用 vLLM 做快速生成——生成正是在线训练方法的主要瓶颈。

```
from datasets import load_dataset
from trl import GRPOConfig, GRPOTrainer

dataset = load_dataset("trl-lib/tldr", split="train")

# Dummy reward: rewards completions that are close to 20 characters
def reward_len(completions, **kwargs):
    return [-abs(20 - len(completion)) for completion in completions]

training_args = GRPOConfig(output_dir="Qwen2-0.5B-GRPO", logging_steps=10)
trainer = GRPOTrainer(
    model="Qwen/Qwen2-0.5B-Instruct",
    reward_funcs=reward_len,
    args=training_args,
    train_dataset=dataset,
)
trainer.train()
```

目前仍存在与高内存占用相关的一些限制，我们正在分析并设法降低它们。

### 合成数据生成

R1 报告最激动人心的发现之一，是主模型可以用来生成合成推理轨迹，在这个数据集上微调的小模型也能获得与主模型类似的性能增益。我们自然也想重建这个合成推理数据集，好让社区能在其上微调其他模型。

对于 R1 这么大的模型，主要挑战是如何高效、快速地扩展生成规模。我们花了一周时间折腾各种配置与设置。

模型可以放进两个 8xH100 节点，所以我们自然先在这个配置上实验，用 vLLM 作为推理服务器。但很快发现这个配置并不理想：吞吐不理想，只能支持 8 个并行请求，因为 GPU KV cache 填得太快。缓存填满时会发生的是：占用大量缓存的请求被抢占，如果配置使用了 `PreemptionMode.RECOMPUTE`，这些请求会在 VRAM 更充裕时重新调度。

随后我们切换到 4x 8xH100 节点的配置，总共 32 块 GPU。这样剩余的 VRAM 足够让 32 个请求并行运行，几乎不会因缓存占用率达到 100% 而被重新调度。

起初我们用成批的请求去查询 vLLM 服务器，但很快注意到批次中的掉队者会让 GPU 利用率忽高忽低——因为新一批要等上一批最后一个样本完成才开始处理。把批量推理改为流式请求后，GPU 利用率显著稳定下来：

[![image/png](https://cdn-uploads.huggingface.co/production/uploads/5e48005437cb5b49818287a5/37qSDNV_r9lefG9KA54hD.png)](https://cdn-uploads.huggingface.co/production/uploads/5e48005437cb5b49818287a5/37qSDNV_r9lefG9KA54hD.png)

这只改了向 vLLM 服务器发送请求的代码。批量推理的旧代码：

```
# send requests in batches of 500
for batch in batch_generator(dataset, bs=500):
    active_tasks = []
    for row in batch:
        task = asyncio.create_task(send_requests(row))
        active_tasks.add(task)
    if active_tasks:
        await asyncio.gather(*active_tasks)
```

新的流式请求代码：

```
active_tasks = []
for row in dataset:
    # keep the total active requests under 500
    while len(active_tasks) >= 500:
        done, active_tasks = await asyncio.wait(
            active_tasks,
            return_when=asyncio.FIRST_COMPLETED
        )

    task = asyncio.create_task(send_requests(row))
    active_tasks.add(task)

# wait for all remaining tasks to complete
if active_tasks:
    await asyncio.gather(*active_tasks)
```

我们现在的生成速率已相当稳定，但也许还会继续探索——例如当长查询被抢占时，切换到 CPU 缓存是否是更好的策略。

当前的推理代码在[这里](https://gist.github.com/anton-l/7e3bcfd0cd3847af44c61b9963107de0)。

### 数据集

社区在一系列与 R1 相关的数据集工作上非常活跃，一些亮点包括：

- [bespokelabs/Bespoke-Stratos-17k](https://huggingface.co/datasets/bespokelabs/Bespoke-Stratos-17k)：对 [Berkeley Sky-T1](https://novasky-ai.github.io/posts/sky-t1/) 数据管线的复现，使用 DeepSeek-R1 创建问题、推理轨迹与答案的数据集。这些数据随后用于以类似 R1 论文的蒸馏方法微调 7B 和 32B 的 Qwen 模型。
- [open-thoughts/OpenThoughts-114k](https://huggingface.co/datasets/open-thoughts/OpenThoughts-114k)：一个"包含 114k 条高质量样本的开放合成推理数据集，覆盖数学、科学、代码和谜题"。Open Thoughts 项目的一部分。
- [cognitivecomputations/dolphin-r1](https://huggingface.co/datasets/cognitivecomputations/dolphin-r1)：80 万条带 DeepSeek-R1 补全的样本数据集，加上 20 万条 Dolphin chat 样本，目标是帮助训练 R1 风格的模型。
- [ServiceNow-AI/R1-Distill-SFT](https://huggingface.co/datasets/ServiceNow-AI/R1-Distill-SFT)：目前有 17,000 条样本，是 ServiceNow 语言模型实验室为支持 Open-R1 工作而创建数据的努力。
- [NovaSky-AI/Sky-T1_data_17k](https://huggingface.co/datasets/NovaSky-AI/Sky-T1_data_17k)：用于训练 Sky-T1-32B-Preview 的数据集。这是较早复现 o1 风格推理的尝试之一。在该数据集上训练模型的开销不到 $450。详情见这篇[博客](https://novasky-ai.github.io/posts/sky-t1/)。
- [Magpie-Align/Magpie-Reasoning-V2-250K-CoT-Deepseek-R1-Llama-70B](https://huggingface.co/datasets/Magpie-Align/Magpie-Reasoning-V2-250K-CoT-Deepseek-R1-Llama-70B)：该数据集把 [Magpie](https://huggingface.co/papers/2406.08464) 无需起始提示词生成指令数据的方法扩展到让回复包含推理。指令由 Llama 3.1 70B Instruct 和 Llama 3.3 70B Instruct 生成，回复由 DeepSeek-R1-Distill-Llama-70B 生成。

这份清单只涵盖了 Hub 上一小部分与推理和解题相关的数据集。我们很期待看到社区未来几周还会构建哪些数据集。

## 接下来做什么？

我们才刚刚起步，想把训练管线完成，在小模型上试运行，并利用扩大的推理管线生成高质量数据集。想参与贡献的话，请查看 [GitHub 上的 open-r1 仓库](https://github.com/huggingface/open-r1)，或关注 [Hugging Face open-r1 组织](https://huggingface.co/open-r1)。
