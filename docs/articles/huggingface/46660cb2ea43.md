*高性能零样本预测，搭配商用友好的开放许可*

时间序列基础模型正在改变预测系统的构建方式。用户不再需要为每个数据集训练并维护各自的模型，而是可以直接使用预训练模型，零样本地生成预测。

IBM 发布了 [**Granite Time Series PatchTST-FM-r2**](https://huggingface.co/ibm-granite/granite-timeseries-patchtst-fm-r2)——Granite TSFM 家族的最新模型（[github](https://github.com/ibm-granite/granite-tsfm)、[blog](https://research.ibm.com/blog/time-series-ai-enterprise)）。PatchTST-FM-r2 是前代 [PatchTST-FM-r1](https://huggingface.co/ibm-granite/granite-timeseries-patchtst-fm-r1) 的新版本，在一个约 **385M 参数**的模型中融合了更新的架构、更大的预训练语料、概率预测、缺失值填补支持，以及强劲的零样本性能。

截至 2026 年 9 月 8 日，该模型是 **GIFT-Eval 排行榜上可复现零样本模型中、以宽松、商用友好的开源许可（Apache 2.0 与 OpenMDW 1.0）发布的表现最好的零样本模型**。GIFT-Eval 是一个综合性的时间序列预测基准，旨在多样预测场景下评估模型；该模型在可复现零样本模型中总体排名第 2。

**模型权重、架构、推理流水线以及复现基准结果所需的代码全部开放可用。**

本文中我们将介绍该模型、深入基准测试结果与模型架构、讨论训练数据与许可证，并提供演示如何用起来的代码示例。最后，我们还会介绍如何借助 [Confluent 产品](https://events.confluent.io/early-access-flink-features)，把 Granite Time Series 家族模型用于生产环境的流式应用。

## TL;DR

- 面向需求、价格、能源负载、交通、遥测等各类时间序列的通用零样本预测。
- 约 385M 参数，上下文长度最高 8,192，灵活的预测长度，通过 99 分位预测头输出概率预测。
- 模型主干由 conformer 块构成，把多头自注意力与时序卷积结合，捕捉长程与短程的时序结构。
- 宽松许可的模型，在 GIFT-Eval 基准的可复现零样本类别中表现第一（Apache-2.0 与 OpenMDW-1.0 双许可，用户可任选其一）。
- 开放权重、架构、推理流水线及复现基准的代码。

## 在 GIFT-Eval 上强劲的零样本预测

基础模型最有价值的时刻，是它能泛化到没有专门训练过的时间序列。因此我们先看零样本性能。

GIFT-Eval 在异构数据集与预测场景上对预测模型做广泛评估。把排行榜限制为零样本、可复现、且评估无测试泄漏的模型时，截至 2026 年 9 月 8 日，PatchTST-FM-r2 在 CRPS 与 MASE 上均排名第二，如图 1 与图 2 所示（两个指标都是越低越好）。重要的是，**在采用宽松、商用友好许可的模型中，PatchTST-FM-r2 是同类中表现最好的。**

*图 1. 领先可复现零样本模型的 GIFT-Eval CRPS。PatchTST-FM-r2 的几何平均 CRPS 为 0.467，紧随 TimesFM-3 之后位列第一梯队，而在宽松许可模型中排名第一。*

*图 2. 领先可复现零样本模型的 GIFT-Eval MASE。PatchTST-FM-r2 的几何平均 MASE 为 0.6846。蓝色柱代表 IBM 时间序列基础模型团队发布的模型。*

## 架构：相对 PatchTST-FM-r1 改了什么？

PatchTST-FM-r2 保留了让 PatchTST 家族行之有效的 patch（分片）表征，但内部架构经过重新设计，以高效捕捉长短期关系并平滑 patch 之间的预测——这两点都显著改善了误差指标。

一项改动是从标准 transformer 层转向在多头自注意力之外结合卷积的层。这些层称为 conformer 层，其[起源](https://arxiv.org/pdf/2005.08100)在语音处理应用。

[![Architectural evolution from PatchTST-FM-r1 to Conformer-based PatchTST-FM-r2](https://cdn-uploads.huggingface.co/production/uploads/64b01b5252349201f972ba17/gYPoFfbdOqaT9nZmABON1.png)](https://cdn-uploads.huggingface.co/production/uploads/64b01b5252349201f972ba17/gYPoFfbdOqaT9nZmABON1.png)

*图 5. 从 PatchTST-FM-r1 到基于 Conformer 的 PatchTST-FM-r2 的架构演进。*

PatchTST-FM-r1 的块把多头自注意力与一个前馈网络组合。在 r2 中，我们把它替换成 conformer 风格的块：两个半步前馈层夹着多头自注意力与一个时序卷积层。

这给了模型两种互补的时间序列推理机制。自注意力可以建模 patch 之间的长程关系，卷积则提供对局部时序结构的归纳偏置。卷积成分因此可以捕捉较短程的交互，让注意力专注于更远距离的关系。这一现象在 transformer 版本与 conformer 版本捕捉到的注意力模式中都可观察到（见下图，使用 ETTh1 数据集的真实样本）。transformer 自注意力的很大一部分（图左）集中在对角线附近、即捕捉局部关系，而 conformer 块中的注意力（图右）由于卷积层覆盖了短距离，呈现出远距离（偏离对角线）的关注。主干中的 conformer 块交替使用 3 与 5 的卷积核尺寸，按 {5, 5, 3, 3} 的模式循环。

*图 6. 使用 ETTh1 数据集真实样本，对比 transformer（左）与 conformer（右）版本捕捉到的注意力模式。*

此外，PatchTST-FM-r2 使用 **50% 重叠的 patch 配合 Hamming 窗加权与 overlap-and-add 预测**，来平滑 patch 边界、提高预测精度。最后，架构加入了归一化以提升稳定性，并把块数从 20 扩展到 **30 块**。

有了这些改动，所得模型约 **385M 参数**，支持最长 **8,192 步**的超长上下文，并在灵活的预测长度上输出 **99 个分位数**。模型同时提供点预测与用于预测分布和不确定性区间的分位数输出。

## 训练数据

对于面向真实应用的基础模型，模型质量只是考量之一。开发者越来越需要理解模型用了哪些数据训练、基准数据是否泄漏进了训练、以及部署该模型意味着什么。

PatchTST-FM-r2 使用一份有文档记载的预训练语料，由四个来源构成：来自 GiftEvalPretrain 的选定数据集；基于 KernelSynth 并采用修改周期核与有限增强的自定义合成数据；用 Chronos 描述的方法生成、但限定使用 GIFT-Eval 评估集之外数据集的 TSMixup 语料；以及约 50 万条形成长度 4,096 的合成 CauKer 序列。

对企业采用者来说，这种透明度可能与排行榜上再多几分同样重要。这不能取代组织自身的模型治理与许可审查，但它比一份不透明的预训练语料给用户提供了多得多的审查信息。

## 几行 Python 试用 PatchTST-FM-r2

评估基础模型最简单的方式，就是在你自己的时间序列数据上试。

安装 Granite TSFM 包：

```
pip install "granite-tsfm>=0.3.9"
```

然后直接从 Hugging Face Hub 加载 PatchTST-FM-r2：

```
import pandas as pd
from tsfm_public import PatchTSTFMForPrediction, TimeSeriesForecastingPipeline

# Load model weights
model = PatchTSTFMForPrediction.from_pretrained(
    "ibm-granite/granite-timeseries-patchtst-fm-r2"
)

# Read some sample data from ETTh
df = pd.read_csv(
    "https://raw.githubusercontent.com/zhouhaoyi/ETDataset/main/ETT-small/ETTh1.csv",
    parse_dates=["date"],
)

# Set up the forecasting pipeline
pipe = TimeSeriesForecastingPipeline(
    model=model,
    id_columns=[],
    timestamp_column="date",
    target_columns=["HUFL"],
    max_context_length=model.config.context_length,
    context_length=512,
    prediction_length=64,
    impute_method=None,
    quantile_levels=[0.1, 0.5, 0.9],
    explode_forecasts=True,
    freq="1h",
)

# Create a forecast from the last 512 samples of the input dataframe
forecast = pipe(df.iloc[-512:])
```

可以看到，不需要微调，也不需要针对任务拟合模型。流水线只需要序列的近期历史，就能生成未来预测，包括所请求的分位数。

上面是公开数据上的简单示例——你可以把示例输入数据换成你自己的：需求、传感器遥测、CPU 利用率、能源消耗、交易量、交通、价格，或任何其他等间隔采样的时间序列。
