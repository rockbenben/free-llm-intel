# ggml 简介

Xuan-Son Nguyen (ngxson)

Georgi Gerganov (ggerganov, ggml-org)

slaren (slaren, ggml-org)

[ggml](https://github.com/ggerganov/ggml) 是一个用 C 和 C++ 编写、以 Transformer 推理为重心的机器学习（ML）库。项目开源，正由不断壮大的社区积极开发。ggml 与 PyTorch、TensorFlow 这类 ML 库相似，但它仍处于早期阶段，一些底层机制还在快速变化。

随着时间推移，ggml 与 [llama.cpp](https://github.com/ggerganov/llama.cpp)、[whisper.cpp](https://github.com/ggerganov/whisper.cpp) 等项目一起流行起来。还有许多项目底层使用 ggml 来实现端侧 LLM，包括 [ollama](https://github.com/ollama/ollama)、[jan](https://github.com/janhq/jan)、[LM Studio](https://github.com/lmstudio-ai)、[GPT4All](https://github.com/nomic-ai/gpt4all)。

人们选择 ggml 而非其他库的主要原因是：

- **极简**：核心库自包含在不到 5 个文件里。GPU 支持需要额外文件，但那是可选的。
- **编译容易**：不需要花哨的构建工具。不带 GPU 支持时，只要 GCC 或 Clang 就行！
- **轻量**：编译出的二进制不到 1MB，相比 PyTorch（动辄几百 MB）小得多。
- **兼容性好**：支持多种硬件，包括 x86_64、ARM、Apple Silicon、CUDA 等。
- **支持量化 tensor**：tensor 可以量化以节省内存（类似 JPEG 压缩），某些情况下还能提升性能。
- **极其省内存**：存储 tensor 和执行计算的开销都很小。

不过 ggml 也有缺点，使用时需要记住（这份清单在 ggml 未来的版本中可能变化）：

- 并非所有 tensor 操作在所有后端都支持。例如某些操作在 CPU 上能跑，在 CUDA 上却不行。
- 用 ggml 开发未必顺手，可能需要底层编程的深厚功底。
- 项目在积极开发中，破坏性变更在所难免。

本文将聚焦 ggml 的基础，面向打算上手这个库的开发者。我们不涉及更高层的任务，比如构建在 ggml 之上的 llama.cpp 的 LLM 推理。我们会探索 ggml 的核心概念和基本用法，为后续学习和发展打下扎实基础。

## 起步

好，从哪开始？

为简单起见，本指南演示在 **Ubuntu** 上编译 ggml。实际上你几乎可以在任何平台编译 ggml（包括 Windows、macOS 和 BSD）。

```
# Start by installing build dependencies
# "gdb" is optional, but is recommended
sudo apt install build-essential cmake git gdb

# Then, clone the repository
git clone https://github.com/ggerganov/ggml.git
cd ggml

# Try compiling one of the examples
cmake -B build
cmake --build build --config Release --target simple-ctx

# Run the example
./build/bin/simple-ctx
```

预期输出：

```
mul mat (4 x 3) (transposed result):
[ 60.00 55.00 50.00 110.00
 90.00 54.00 54.00 126.00
 42.00 29.00 28.00 64.00 ]
```

看到预期结果，就说明一切就绪！

## 术语与概念

深入 ggml 之前，先理解几个关键概念。如果你来自 PyTorch、TensorFlow 这类高层库，这些概念可能有点难啃。但请记住 ggml 是一个**低层**库。理解这些术语能让你对性能有更强的掌控：

- [ggml_context](https://github.com/ggerganov/ggml/blob/18703ad600cc68dbdb04d57434c876989a841d12/include/ggml.h#L355)：一个"容器"，存放 tensor、图，以及可选的数据。
- [ggml_cgraph](https://github.com/ggerganov/ggml/blob/18703ad600cc68dbdb04d57434c876989a841d12/include/ggml.h#L652)：表示计算图。可以理解为要传给后端的"计算顺序"。
- [ggml_backend](https://github.com/ggerganov/ggml/blob/18703ad600cc68dbdb04d57434c876989a841d12/src/ggml-backend-impl.h#L80)：执行计算图的接口。后端有很多种：CPU（默认）、CUDA、Metal（Apple Silicon）、Vulkan、RPC 等。
- [ggml_backend_buffer_type](https://github.com/ggerganov/ggml/blob/18703ad600cc68dbdb04d57434c876989a841d12/src/ggml-backend-impl.h#L18)：表示一种缓冲区类型。可以理解为每个 `ggml_backend` 连接的"内存分配器"。例如要在 GPU 上计算，需要通过 `buffer_type`（常缩写为 `buft`）在 GPU 上分配内存。
- [ggml_backend_buffer](https://github.com/ggerganov/ggml/blob/18703ad600cc68dbdb04d57434c876989a841d12/src/ggml-backend-impl.h#L52)：由 `buffer_type` 分配出的缓冲区。记住：一个缓冲区可以同时存放多个 tensor 的数据。
- [ggml_gallocr](https://github.com/ggerganov/ggml/blob/18703ad600cc68dbdb04d57434c876989a841d12/include/ggml-alloc.h#L46)：图内存分配器，用于高效分配计算图中使用的 tensor。
- [ggml_backend_sched](https://github.com/ggerganov/ggml/blob/18703ad600cc68dbdb04d57434c876989a841d12/include/ggml-backend.h#L169)：调度器，支持同时使用多个后端。处理大模型或多 GPU 时，它能把计算分发到不同硬件（如 GPU 和 CPU）；还能自动把 GPU 不支持的操作分给 CPU，兼顾最优资源利用率与兼容性。

## 简单示例

这个例子复现 [起步](https://huggingface.co/blog/introduction-to-ggml#getting-started) 里跑过的代码。我们需要创建 2 个矩阵，相乘得到结果。用 PyTorch 的话代码长这样：

```
import torch

# Create two matrices
matrix1 = torch.tensor([
  [2, 8],
  [5, 1],
  [4, 2],
  [8, 6],
])
matrix2 = torch.tensor([
  [10, 5],
  [9, 9],
  [5, 4],
])

# Perform matrix multiplication
result = torch.matmul(matrix1, matrix2.T)
print(result.T)
```

用 ggml 要达到同样结果，需要做这些步骤：

- 分配 `ggml_context` 存放 tensor 数据
- 创建 tensor 并设置数据
- 为 mul_mat 操作创建 `ggml_cgraph`
- 运行计算
- 取回结果（输出 tensor）
- 释放内存并退出

**注意**：为简单起见，本例把 tensor 数据分配在 `ggml_context` **内部**。实践中内存应当分配为设备缓冲区，下一节会看到。

开始吧，先创建新目录 `examples/demo`

```
cd ggml # make sure you're in the project root

# create C source and CMakeLists file
touch examples/demo/demo.c
touch examples/demo/CMakeLists.txt
```

本示例代码基于 [simple-ctx.cpp](https://github.com/ggerganov/ggml/blob/6c71d5a071d842118fb04c03c4b15116dff09621/examples/simple/simple-ctx.cpp)

编辑 `examples/demo/demo.c`，填入以下内容：

```
#include "ggml.h"
#include "ggml-cpu.h"
#include <string.h>
#include <stdio.h>

int main(void) {
    // initialize data of matrices to perform matrix multiplication
    const int rows_A = 4, cols_A = 2;
    float matrix_A[rows_A * cols_A] = {
        2, 8,
        5, 1,
        4, 2,
        8, 6
    };
    const int rows_B = 3, cols_B = 2;
    float matrix_B[rows_B * cols_B] = {
        10, 5,
        9, 9,
        5, 4
    };

    // 1. Allocate `ggml_context` to store tensor data
    // Calculate the size needed to allocate
    size_t ctx_size = 0;
    ctx_size += rows_A * cols_A * ggml_type_size(GGML_TYPE_F32); // tensor a
    ctx_size += rows_B * cols_B * ggml_type_size(GGML_TYPE_F32); // tensor b
    ctx_size += rows_A * rows_B * ggml_type_size(GGML_TYPE_F32); // result
    ctx_size += 3 * ggml_tensor_overhead(); // metadata for 3 tensors
    ctx_size += ggml_graph_overhead(); // compute graph
    ctx_size += 1024; // some overhead (exact calculation omitted for simplicity)

    // Allocate `ggml_context` to store tensor data
    struct ggml_init_params params = {
        /*.mem_size   =*/ ctx_size,
        /*.mem_buffer =*/ NULL,
        /*.no_alloc   =*/ false,
    };
    struct ggml_context * ctx = ggml_init(params);

    // 2. Create tensors and set data
    struct ggml_tensor * tensor_a = ggml_new_tensor_2d(ctx, GGML_TYPE_F32, cols_A, rows_A);
    struct ggml_tensor * tensor_b = ggml_new_tensor_2d(ctx, GGML_TYPE_F32, cols_B, rows_B);
    memcpy(tensor_a->data, matrix_A, ggml_nbytes(tensor_a));
    memcpy(tensor_b->data, matrix_B, ggml_nbytes(tensor_b));


    // 3. Create a `ggml_cgraph` for mul_mat operation
    struct ggml_cgraph * gf = ggml_new_graph(ctx);

    // result = a*b^T
    // Pay attention: ggml_mul_mat(A, B) ==> B will be transposed internally
    // the result is transposed
    struct ggml_tensor * result = ggml_mul_mat(ctx, tensor_a, tensor_b);

    // Mark the "result" tensor to be computed
    ggml_build_forward_expand(gf, result);

    // 4. Run the computation
    int n_threads = 1; // Optional: number of threads to perform some operations with multi-threading
    ggml_graph_compute_with_ctx(ctx, gf, n_threads);

    // 5. Retrieve results (output tensors)
    float * result_data = (float *) result->data;
    printf("mul mat (%d x %d) (transposed result):\n[", (int) result->ne[0], (int) result->ne[1]);
    for (int j = 0; j < result->ne[1] /* rows */; j++) {
        if (j > 0) {
            printf("\n");
        }

        for (int i = 0; i < result->ne[0] /* cols */; i++) {
            printf(" %.2f", result_data[j * result->ne[0] + i]);
        }
    }
    printf(" ]\n");

    // 6. Free memory and exit
    ggml_free(ctx);
    return 0;
}
```

在你创建的 `examples/demo/CMakeLists.txt` 里写入：

```
set(TEST_TARGET demo)
add_executable(${TEST_TARGET} demo)
target_link_libraries(${TEST_TARGET} PRIVATE ggml)
```

编辑 `examples/CMakeLists.txt`，在末尾加一行：

```

```

编译并运行：

```

# Run it

```

```

```

## 使用后端的示例

ggml 里的"后端"（Backend）指处理 tensor 操作的接口。后端可以是 CPU、CUDA、Vulkan 等。

后端把计算图的执行抽象掉了。图一旦定义好，就可以用对应后端的实现在可用硬件上计算。注意 ggml 会自动为计算所需的中间 tensor 预留内存，并根据这些中间结果的存活期优化内存使用。

用后端做计算或推理时，通常步骤是：

- 初始化 `ggml_backend`
- 分配 `ggml_context` 存放 tensor 元数据（此时**不需要**马上分配 tensor 数据）
- 创建 tensor 元数据（只有形状和数据类型）
- 分配一个 `ggml_backend_buffer` 存储所有 tensor
- 把 tensor 数据从主内存（RAM）拷贝到后端缓冲区
- 为 mul_mat 操作创建 `ggml_cgraph`
- 为 cgraph 分配创建 `ggml_gallocr`
- 可选：用 `ggml_backend_sched` 调度 cgraph
- 运行计算
- 取回结果（输出 tensor）
- 释放内存并退出

本示例代码基于 [simple-backend.cpp](https://github.com/ggerganov/ggml/blob/6c71d5a071d842118fb04c03c4b15116dff09621/examples/simple/simple-backend.cpp)

```
#include "ggml.h"
#include "ggml-alloc.h"
#include "ggml-backend.h"
#ifdef GGML_USE_CUDA
#include "ggml-cuda.h"
#endif

#include <stdlib.h>
#include <string.h>
#include <stdio.h>

int main(void) {
    // initialize data of matrices to perform matrix multiplication
    const int rows_A = 4, cols_A = 2;
    float matrix_A[rows_A * cols_A] = {
        2, 8,
        5, 1,
        4, 2,
        8, 6
    };
    const int rows_B = 3, cols_B = 2;
    float matrix_B[rows_B * cols_B] = {
        10, 5,
        9, 9,
        5, 4
    };

    // 1. Initialize backend
    ggml_backend_t backend = NULL;
#ifdef GGML_USE_CUDA
    fprintf(stderr, "%s: using CUDA backend\n", __func__);
    backend = ggml_backend_cuda_init(0); // init device 0
    if (!backend) {
        fprintf(stderr, "%s: ggml_backend_cuda_init() failed\n", __func__);
    }
#endif
    // if there aren't GPU Backends fallback to CPU backend
    if (!backend) {
        backend = ggml_backend_cpu_init();
    }

    // Calculate the size needed to allocate
    size_t ctx_size = 0;
    ctx_size += 2 * ggml_tensor_overhead(); // tensors
    // no need to allocate anything else!

    // 2. Allocate `ggml_context` to store tensor data
    struct ggml_init_params params = {
        /*.mem_size   =*/ ctx_size,
        /*.mem_buffer =*/ NULL,
        /*.no_alloc   =*/ true, // the tensors will be allocated later by ggml_backend_alloc_ctx_tensors()
    };
    struct ggml_context * ctx = ggml_init(params);

    // Create tensors metadata (only there shapes and data type)
    struct ggml_tensor * tensor_a = ggml_new_tensor_2d(ctx, GGML_TYPE_F32, cols_A, rows_A);
    struct ggml_tensor * tensor_b = ggml_new_tensor_2d(ctx, GGML_TYPE_F32, cols_B, rows_B);

    // 4. Allocate a `ggml_backend_buffer` to store all tensors
    ggml_backend_buffer_t buffer = ggml_backend_alloc_ctx_tensors(ctx, backend);

    // 5. Copy tensor data from main memory (RAM) to backend buffer
    ggml_backend_tensor_set(tensor_a, matrix_A, 0, ggml_nbytes(tensor_a));
    ggml_backend_tensor_set(tensor_b, matrix_B, 0, ggml_nbytes(tensor_b));

    // 6. Create a `ggml_cgraph` for mul_mat operation
    struct ggml_cgraph * gf = NULL;
    struct ggml_context * ctx_cgraph = NULL;
    {
        // create a temporally context to build the graph
        struct ggml_init_params params0 = {
            /*.mem_size   =*/ ggml_tensor_overhead()*GGML_DEFAULT_GRAPH_SIZE + ggml_graph_overhead(),
            /*.mem_buffer =*/ NULL,
            /*.no_alloc   =*/ true, // the tensors will be allocated later by ggml_gallocr_alloc_graph()
        };
        ctx_cgraph = ggml_init(params0);
        gf = ggml_new_graph(ctx_cgraph);

        // result = a*b^T
        // Pay attention: ggml_mul_mat(A, B) ==> B will be transposed internally
        // the result is transposed
        struct ggml_tensor * result0 = ggml_mul_mat(ctx_cgraph, tensor_a, tensor_b);

        // Add "result" tensor and all of its dependencies to the cgraph
        ggml_build_forward_expand(gf, result0);
    }

    // 7. Create a `ggml_gallocr` for cgraph computation
    ggml_gallocr_t allocr = ggml_gallocr_new(ggml_backend_get_default_buffer_type(backend));
    ggml_gallocr_alloc_graph(allocr, gf);

    // (we skip step 8. Optionally: schedule the cgraph using `ggml_backend_sched`)

    // 9. Run the computation
    int n_threads = 1; // Optional: number of threads to perform some operations with multi-threading
    if (ggml_backend_is_cpu(backend)) {
        ggml_backend_cpu_set_n_threads(backend, n_threads);
    }
    ggml_backend_graph_compute(backend, gf);

    // 10. Retrieve results (output tensors)
    // in this example, output tensor is always the last tensor in the graph
    struct ggml_tensor * result = ggml_graph_node(gf, -1);
    float * result_data = malloc(ggml_nbytes(result));
    // because the tensor data is stored in device buffer, we need to copy it back to RAM
    ggml_backend_tensor_get(result, result_data, 0, ggml_nbytes(result));
    printf("mul mat (%d x %d) (transposed result):\n[", (int) result->ne[0], (int) result->ne[1]);
    for (int j = 0; j < result->ne[1] /* rows */; j++) {
        if (j > 0) {
            printf("\n");
        }

        for (int i = 0; i < result->ne[0] /* cols */; i++) {
            printf(" %.2f", result_data[j * result->ne[0] + i]);
        }
    }
    printf(" ]\n");
    free(result_data);

    // 11. Free memory and exit
    ggml_free(ctx_cgraph);
    ggml_gallocr_free(allocr);
    ggml_free(ctx);
    ggml_backend_buffer_free(buffer);
    ggml_backend_free(backend);
    return 0;
}
```

## 打印计算图

`ggml_cgraph` 表示计算图，定义了后端将执行的操作顺序。打印计算图是一个很有用的调试工具，尤其是处理更复杂模型和计算时。

可以加 `ggml_graph_print` 打印 cgraph：

```
...

// Mark the "result" tensor to be computed
ggml_build_forward_expand(gf, result0);

// Print the cgraph
ggml_graph_print(gf);
```

运行后：

```
=== GRAPH ===
n_nodes = 1
 -   0: [     4,     3,     1]          MUL_MAT  
n_leafs = 2
 -   0: [     2,     4]     NONE           leaf_0
 -   1: [     2,     3]     NONE           leaf_1
========================================
```

此外还可以把 cgraph 导出为 graphviz dot 格式：

```
ggml_graph_dump_dot(gf, NULL, "debug.dot");
```

用 `dot` 命令或这个[在线网站](https://dreampuf.github.io/GraphvizOnline)就能把 `debug.dot` 渲染成最终图像：

[![ggml-debug](https://huggingface.co/blog/assets/introduction-to-ggml/ggml-debug.svg)](https://huggingface.co/blog/assets/introduction-to-ggml/ggml-debug.svg)
