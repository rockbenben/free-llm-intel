但挑战在这里：找到一个惊艳的模型只是开始。如果你发现的模型有 90% 契合你的用例，但你还需要那最后 10% 的定制，怎么办？传统微调基础设施复杂、昂贵，往往还需要相当程度的 DevOps 能力才能搭建和维护。

Together AI 与 Hugging Face 今天正在填补的正是这个空缺。我们宣布一项强大的新能力：整个 Hugging Face Hub 都可以借助 Together AI 的基础设施进行微调。现在，Hub 上任意兼容的 LLM——无论来自 Meta 还是个人贡献者——都能以 Together 平台一贯的易用性和可靠性完成微调。🚀

## **5 分钟上手**

在 Together AI 平台上开始微调一个 HF 模型，只需要这些：

```
#pip install together

from together import Together

client = Together(api_key="your-api-key")

file_upload = client.files.upload("sft_examples.jsonl", check=True)

# Fine-tune any compatible HF model
job = client.fine_tuning.create(
    model="togethercomputer/llama-2-7b-chat",  # Base model for configuration
    from_hf_model="HuggingFaceTB/SmolLM2-1.7B-Instruct",  # Your chosen HF model
    training_file=file_upload.id,
    n_epochs=3,
    learning_rate=1e-5,
    hf_api_token="hf_***",  # for private repos
    hf_output_repo_name="my-username-org/SmolLM2-1.7B-FT"  # to upload model back to hub
)

print(f"Training job started: {job.id}")
```

就这么简单！模型会在 Together 的基础设施上训练完成，随后可用于推理部署、下载，甚至回传到 Hub！私有仓库只需加上你的 HF token：`hf_api_token="hf_xxxxxxxxxxxx"`。

## 工作原理：

如上面的示例所示，在 Together AI 上微调 Hugging Face 模型时，你实际上要指定两个模型：

- **基座模型**（`model` 参数）：来自 Together [官方目录](https://docs.together.ai/docs/fine-tuning-models)的模型，提供基础设施配置、训练优化和推理设置
- **自定义模型**（`from_hf_model` 参数）：你真正要微调的 Hugging Face 模型

可以把基座模型理解为"训练模板"。它告诉我们的系统如何最优地分配 GPU 资源、配置内存、搭建训练流水线、并让模型做好推理准备。为了获得最佳效果，你的自定义模型应与基座模型有相似的架构、近似的规模和序列长度。

例如上例中，如果要微调 `HuggingFaceTB/SmolLM2-1.7B-Instruct`（采用 Llama 架构），就用 `togethercomputer/llama-2-7b-chat` 作为基座模型模板——因为它们共享同一套底层架构。

这一集成是**双向的**。Together AI 可以从 Hugging Face Hub 拉取任意兼容的公开模型用于训练；配上正确的 API token，也能下载私有仓库中的模型。训练完成后，如果你指定了 `hf_output_repo_name`，微调后的模型会自动推回 Hub，方便与团队或更广泛的社区共享。

总体而言，所有 100B 参数以下的 `CausalLM` 模型都应该可用。关于如何选择基座模型与自定义模型等更多细节，请阅读完整[指南](https://docs.together.ai/docs/fine-tuning-byom)！

## 对开发者意味着什么

这个集成解决的是我们都遇到过的真实问题：在 Hugging Face 上找到了很棒的模型，却没有基础设施按自己的需求真正去微调它。现在，从发现一个有潜力的模型，到让定制版本跑在生产环境，只需几次 API 调用。

最大的收益是消除了摩擦。不必再花几天搭建训练基础设施，也不再受限于各平台官方支持的那几个模型——Hub 上任意兼容模型都能拿来实验。找到一个接近需求的专用编码模型？用你的数据训练它！📈

对团队来说，这意味着更快的迭代循环。你可以快速测试多种模型路线、站在社区创新的肩膀上，甚至把你自己微调出的模型当作进一步定制的起点。

## **团队们正在怎么用这个功能？**

这一功能的 Beta 用户和早期采用者已经在各种用例中看到了成果。

[**Slingshot AI**](https://www.together.ai/customers/slingshot-ai) 已把该能力直接整合进他们的模型开发流水线。他们不再局限于 Together 的模型目录：可以在自己的基础设施上跑训练流水线的部分环节，把模型上传到 Hub，然后用 Together AI 微调平台对这些模型做继续微调。这大幅加速了他们的开发周期，让他们可以轻松实验各种各样的模型变体。

[**Parsed**](https://www.together.ai/blog/fine-tune-small-open-source-llms-outperform-closed-models) 在他们的工作中展示了这条路线的威力：精心调校的小体积开源模型可以胜过大得多的闭源模型。通过在精细整理的数据集上微调，他们取得了更优的性能，同时保持成本效率和对模型的完全掌控。

**我们从其他客户那里看到的常见用法包括：**

- *领域适配*：拿通用模型，针对医疗、金融、法律等行业做专业化。团队先找到已具备一定领域知识的模型，再用 Together 的基础设施把它们适配到自己的数据和需求上。
- *模型迭代改进*：以社区模型为起点微调，再把结果当作下一轮精调的起点。这种复利式的改进效果，从零开始很难达到。
- *社区模型专门化*：利用已经为特定任务（如编码、推理、多语言）优化过的模型，进一步定制到自己的专有场景。
- *架构探索*：新架构、新模型变体一发布就能快速试，不必等它们被加入各官方平台。

团队反馈中最显著的优势是*价值兑现速度*。不必花几周搭建训练基础设施、也不必花几个月从零训练模型——他们能从社区中找到有希望的起点，几天内就让专门化模型跑上生产环境。

成本效率是另一大收益。从已具备相关能力的模型出发，团队需要的训练轮次更少、达成目标性能所需的数据集也更小，算力成本因此大幅下降。

也许最重要的是，这种方式让团队能够借助开源社区的集体智慧。每一次突破、每一种专门化改造、每一个新架构，都可能成为你自己工作的起点。
