# StarCoder：面向代码的最先进 LLM

本文由 Leandro von Werra（lvwerra）与 Loubna Ben Allal（loubnabnl）撰写。

## 介绍 StarCoder

StarCoder 和 StarCoderBase 是面向代码的大语言模型（Code LLMs），训练数据来自 GitHub 上采用宽松许可证的数据，涵盖 80 多种编程语言、Git 提交、GitHub issues 和 Jupyter notebooks。与 LLaMA 类似，我们训练了一个约 15B 参数的模型，训练量达 1 万亿 token。我们将 StarCoderBase 模型在 350 亿 Python token 上进一步微调，得到了我们称之为 StarCoder 的新模型。

我们发现，StarCoderBase 在主流编程基准上优于现有的开源 Code LLM，并与闭源模型持平或更强，例如 OpenAI 的 `code-cushman-001`（即最初支撑 GitHub Copilot 早期版本的 Codex 模型）。凭借超过 8,000 token 的上下文长度，StarCoder 模型能够比任何其他开源 LLM 处理更多的输入，从而支撑一系列有趣的广泛应用。例如，通过以一系列对话的形式提示 StarCoder 模型，我们让它扮演技术助手。此外，模型还可以用于代码自动补全、按指令修改代码，以及用自然语言解释代码片段。在安全地开放模型方面我们采取了几个重要步骤，包括改进的 PII 脱敏流水线、一种新颖的归因追踪工具，并以改进版的 OpenRAIL 许可证公开提供 StarCoder。更新后的许可证简化了企业将模型集成到其产品的流程。我们相信，凭借出色的性能，StarCoder 模型将成为一个坚实的基座，供社区使用并改造以适应他们自己的用例与产品。

## 评估

我们对 StarCoder 和若干同类模型在各种基准上进行了全面评估。一个流行的 Python 基准是 HumanEval，它测试模型能否基于函数签名和 docstring 补全函数。我们发现，StarCoder 和 StarCoderBase 都优于最大的模型，包括 PaLM、LaMDA 和 LLaMA，尽管它们的规模要小得多。它们也胜过 CodeGen-16B-Mono 和 OpenAI 的 code-cushman-001（12B）模型。我们还注意到该模型的一个失败案例是会生成 `# Solution here` 这样的代码，可能是因为这类代码通常出现在练习题中。为了迫使模型生成真正的解法，我们加了提示 `<filename>solutions/solution_1.py\n# Here is the correct implementation of the code exercise`。这把 StarCoder 的 HumanEval 得分从 34% 显著提升到 40% 以上，为开源模型创造了新的最先进成绩。我们也对 CodeGen 和 StarCoderBase 尝试了这个提示，但没有观察到太大差异。

| **Model** | **HumanEval** | **MBPP** |
| --- | --- | --- |
| LLaMA-7B | 10.5 | 17.7 |
| LaMDA-137B | 14.0 | 14.8 |
| LLaMA-13B | 15.8 | 22.0 |
| CodeGen-16B-Multi | 18.3 | 20.9 |
| LLaMA-33B | 21.7 | 30.2 |
| CodeGeeX | 22.9 | 24.4 |
| LLaMA-65B | 23.7 | 37.7 |
| PaLM-540B | 26.2 | 36.8 |
| CodeGen-16B-Mono | 29.3 | 35.3 |
| StarCoderBase | 30.4 | 49.0 |
| code-cushman-001 | 33.5 | 45.9 |
| StarCoder | 33.6 | **52.7** |
| StarCoder-Prompted | **40.8** | 49.5 |

StarCoder 的一个有趣特性是它的多语言能力，因此我们在 MultiPL-E 上做了评估，该基准把 HumanEval 扩展到了许多其他语言。我们观察到 StarCoder 在许多语言上与 `code-cushman-001` 持平或超过它。在一个名为 DS-1000 的数据科学基准上，它也明显击败了后者以及所有其他开放访问模型。不过让我们也看看这个模型除了代码补全之外还能做什么！

## 技术助手

在详尽的评估中，我们发现 StarCoder 非常擅长写代码。但我们也想测试它能否用作技术助手——毕竟它在大量文档和 GitHub issues 上训练过。受 Anthropic 的 [HHH prompt](https://gist.github.com/jareddk/2509330f8ef3d787fc5aaac67aab5f11#file-hhh_prompt-txt) 启发，我们构建了一个 [Tech Assistant Prompt](https://huggingface.co/datasets/bigcode/ta-prompt)。令人惊讶的是，仅凭这个提示，模型就能够扮演技术助手并回答编程相关请求！

[![ChatExamples](https://huggingface.co/datasets/bigcode/admin/resolve/main/StarCoderChatExamples.png)](https://huggingface.co/datasets/bigcode/admin/resolve/main/StarCoderChatExamples.png)

## 训练数据

该模型在 The Stack 1.2 的一个子集上训练。该数据集只包含宽松许可的代码，并包含一个退出（opt-out）流程，代码贡献者可以从中移除自己的数据（参见 Am I in The Stack）。我们与 [Toloka](https://toloka.ai/blog/bigcode-project/) 合作，从训练数据中移除了个人身份信息（PII），如姓名、密码和电子邮件地址。

## 关于 BigCode

BigCode 是由 Hugging Face 和 ServiceNow 共同牵头的一个开放科学合作项目，致力于负责任地开发面向代码的大语言模型。
