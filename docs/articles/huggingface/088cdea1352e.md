# 超越 LLM：为何企业 AI 的规模化落地取决于智能体逻辑

指南（向导）贯穿历史一直在帮助人类。史前文明就懂得用日月在陆地的远行和大洋的航行中定位方向。随着各类旅途的积累，人们绘制出地图，以便更好地规划行程、更快抵达熟悉的目的地。几个世纪后，指南针让航海者在寻找未知目的地时达到更高的精度。而今天，GPS 导航应用指引着我们的每一次出行。在当今的 agentic AI 世界里，AI 智能体无疑有潜力推动 AI 的规模化采用，重塑我们所熟知的各行各业。但要兑现这一潜力，需要一个智能向导——智能体逻辑（agent logic）——用高智能体质量、高性价比，进而赢得终端用户的信任。

**企业工作流与用例**

大量研究指出 AI 试点的压倒性失败，也有研究强调 AI 必须在企业工作流的核心处运转，才能实现规模化落地。[1] [2] 要理解这一现象和相应论断，需要对企业工作流做些分析。这些工作流是：

A. 动态且长时间运行的
B. 拥有大量 API、数据库和服务
C. 常常受业务策略和/或法规约束

在上述特征下，要让智能体有效工作，自然就要求扩展的模型上下文——最先进的前沿 LLM 确实具备，但代价是什么？更多的幻觉？更多的 token 消耗？进一步说，能否给 LLM 配一个智能向导、一套"GPS"，让 agentic AI 在工作流核心处执行，驱动更理想的结果？我们设计并构建了配备相应智能体逻辑的智能体来检验这些假设——面向 IBM 的产品，充分考虑了上述特征。这些产品涉及企业关键负载的软件交付生命周期中各阶段负责人（领域专家）所面对的一些最具挑战性的任务，包括：

- 理解用遗留代码（Cobol / PL/1）编写的应用
- 帮开发者加快测试生成
- 主动响应故障事件，实现"移左"的应用韧性
- 为关键环境自动化合规现代化

在逐一审视这些领域之前，先定义什么是智能体逻辑。智能体逻辑是运行在智能体层（agent harness 之内）的软件原语——例如知识图谱、算法、程序分析库——它们能够有意识地把 LLM 引向企业工作流的核心方向，缩小上下文空间。如此往往能以更具性价比的方式产出更高性能的结局。现在我们来看智能体逻辑如何在上述四个领域中实现这样的结果。

- 理解用遗留代码（Cobol / PL/1）编写的应用——程序分析。[3]

IBM watsonx Code Assistant for Z（WCA4Z）用 AI 和自动化加速大型机应用开发与现代化，其中配备了用于应用理解的 App Insights 智能体——这是在 IBM 大型机上运行关键负载的企业客户的首要关注领域之一。该智能体利用贯穿应用的深度静态分析，并把预先索引好的表示存进一个数据库 schema——跨数百张具有复杂语义的关联表——使智能体能检索精确、结构化且已经存在的信息；从而提升答案准确率、降低 token 用量、减少与语言模型（本例中是 Mistral Medium 250B）的来回交互。把这种方法应用于多个关键遗留系统（最多 100 万行代码、1000 个程序）时，应用理解性能保持略微领先，而 token 消耗比纯前沿 LLM 基线低约 30 倍。

- 用 Aster 帮开发者加快测试生成——程序分析。[4], [5]

Aster 是 IBM 专有的、基于程序分析与数据前后处理的库，用于以智能体方式生成单元测试、集成测试、API 测试和基于变更的测试；对多个开发者社区的分析显示，其获得的开发者评分高于各种开源工具或开发者手写的测试。基于后者、以及与类似开源工具（集成测试）和零样本 LLM、编码智能体（单元测试）相比更优的行/分支/方法覆盖率基准——全部在开源应用上测试——我们已在 75+ 个 IBM CIO 的 Java 应用（最多 560+ 个类、67K+ 行代码）上以预生产模式运行 Aster，模型用 Devstral 24B。迄今稳定状态的结果显示，行/分支/方法覆盖率提升 20%–45%，并在其中部分应用上相比最先进编码智能体性能更优，而 token 消耗低数量级（最多 15 倍）。这些结果的逻辑在于：程序分析的输出（用于提示和"聚焦"LLM）加上负责补覆盖率、修复运行时与编译错误的子智能体，能以显著更低的成本获得更高性能的结果。

- 主动响应故障事件、实现"移左"的应用韧性——知识图谱、程序分析库与可观测性调查驱动的编排。[6],[7]

第 1、2 条中的应用相关用例的 LLM 上下文被"限定"在应用源代码内；而对于在已部署基础设施上的应用运行时管理，整个 IT 栈都进入视野。这里我们定义一个知识图谱（KG），涵盖各类实体（微服务、数据库/中间件服务、MELT 等）并嵌入领域专家的"部落"知识。借助这样的图、并把 LLM 约束在局部有界推理上来处理非确定性结果，我们用可观测性驱动的方式，缩减横跨 IT 栈及相关应用源代码（如有必要）的上下文空间，完成故障根因分析（及其他用例）。采用这种方法、复用等价的 Instana 数据模型，我们看到专有的 Instana "I3"（intelligent incident investigation [8]）智能体在 ITBench [9] 的测评中，相比以 GPT-5.1 为基座的 ReAct 智能体取得最多 4.0 倍的提升。换用 Gemini 3 Flash 时，ReAct 智能体的表现只比 I3 低 17% 以内，但多消耗 1.6 倍 token。我们已把该方法扩展到源代码层面：用于代码分析（借助程序依赖图）和缺陷修复（借助推理扩展）的智能体，同样在 ITBench 上测试，结果显示源代码分析智能体和缺陷修复智能体（Gemini 2.5 Flash）相比最先进编码智能体性能更优——定位肇事微服务（3.0 倍）和修复缺陷（1.6 倍），而 token 分别少用 3.7 倍和 5.9 倍。这一多智能体系统在 IBM Think 大会上作为新发布的 IBM Concert 平台的一部分公布，用于"移左"的 IT 运维，并正与 IBM CIO 内部试点。[10]

- 为关键环境自动化 IT 合规现代化——算法、自适应规划与编排。[11]

企业面临的合规要求日益复杂且割裂，团队不得不花大量时间手工创建控制项、评估和整改计划。不存在集中的知识，修复方案全靠手写，带来出错和安全缺口的风险。因为合规工作复杂且多步，它需要跨专业智能体协调的、策略驱动的自动化，而非人力或简单 AI 提示。我们的多智能体系统通过算法把复杂任务分解为协调的步骤来实现合规自动化，使用自适应规划、动态分解和工作流排序，配合持续反馈迭代地识别修复方案、扩展评估。同样以 ITBench 测量，它比使用固定规划策略的既往智能体（Claude 4 Sonnet）性能高 1.3–2.0 倍。这种方法把合规变成持续受指导、自我纠错的过程，大幅提升结果——尤其在复杂场景中，把成功率从个位数提升到最高 +80%（Claude 4 Sonnet）。这一多智能体系统和 16K+ 条数字化控制项映射，是作为 IBM Think 上发布的 IBM Sovereign Core 的一部分亮相的，集成了监控与漂移检测，提供自动证据生成，确保审计证据始终安全地留在客户掌控之中。[12]

以上例子展示了智能体逻辑在缩减 LLM 上下文、引导 LLM 以高性能、高性价比的方式穿行于工作流核心的影响。此外，我们在两个案例研究中也采用了类似方法：一个是医疗领域可配置的通用智能体及其运行时（CUGA），另一个是与 IBM Global Real Estate 合作的物理资产状态检修（condition-based maintenance）。

**领域案例研究**

案例 1：可配置通用智能体（CUGA）医疗基准——算法化策略执行。[13]

下面这个健康保险客户服务的例子，简洁地说明了为什么在有监管的环境中 agentic 系统胜过纯 LLM 对话模型。CUGA（可配置通用智能体）的策略系统实现了面向智能体治理的"策略即代码（policy-as-code）"，在运行时强制执行，独立于模型提示词、无需微调。实验显示，该智能体的策略系统在任务正确率上弥合了很大的差距——在所有模型家族（Claude Opus – 4.5、GPT OSS 120B 和 GPT – 4.1）中强制执行结构化工作流、安全的意图处理、可靠的工具使用和受控的输出格式，准确率提升介于 15% 到 26%。权限通过最小特权披露、显式合规规则和人工升级路径来强制执行。智能动作可以被提出，但权威由策略和监督机制来行使；推理是自主的，决策权是受约束的。CUGA 也是 IBM Think 上 Sovereign Core 发布的关键组成部分。

案例 2：IBM Global Real Estate 的物理资产状态检修——有向无环图。[14],[15]

企业的维护系统收集海量资产数据，却无法有效整合它们——需要专家手工拼凑碎片化的信号，在没有统一、循证洞察的情况下做决定。我们新近发布的 Maximo Condition Insights [16] 智能体分析跨数千资产和地点的大规模资产数据（传感器、工单、失效模式与事件分析），用结构化证据和验证循环来可靠地识别问题、排定行动优先级、以一致可追溯的洞察支持决策。我们已与 IBM Global Real Estate（GRE）内部试点该智能体（基于 GPT OSS 120B），把资产分析时间从 15–20 分钟缩短到 15–30 秒（提升 97%），资产审查覆盖率从约 1% 提升到约 30%，覆盖 120+ 个场所、6K 个物理资产。借助 AssetOpsBench，Condition Insights 智能体把无依据的论断减少 57%，冗余表述削减 35%，规则合规度提升 30%，几乎维持零矛盾，平均 token 用量降低 77%，同时诊断的针对性略有增强。这个配备了有向无环图的智能体，提供了结构工程与运维上下文，减少朴素提示下无依据的推理；而约束感知的提示显著提升规则遵从、减少冗余并降低总体 token 消耗，且不会引入不稳定性。

**总结与参考文献：** 几个世纪以来我们受益于各种向导，它们简化和改善了我们的生活。随着技术演进，我们使用的向导也在演进，让我们能做更多的事、进一步缩小这个地球村。随着 agentic AI 时代的到来，当我们寻求通过规模经济等方式进一步增益社会时，应当延续这一趋势，充分利用智能体逻辑来简化模型上下文、智能地穿行于企业工作流的核心——唯有如此，以最优运营成本实现规模化采用才真正可行。
