# 日语 LLM 开放榜单介绍

LLM 在英语上的能力日益增强，但要知道它们在广泛使用的其他民族语言中表现如何却很难——这些语言自有其一整套语言学挑战。今天，我们很高兴为日语填补这一空白！

我们要宣布 **[Open Japanese LLM Leaderboard](https://huggingface.co/spaces/llm-jp/open-japanese-llm-leaderboard)** 上线，它由 20 多个数据集组成，从经典到现代 NLP 任务，用以理解日语 LLM 的底层机制。该榜单由 **[LLM-jp](https://llm-jp.nii.ac.jp/en/)**——一个与 **Hugging Face** 合作、跨机构的日语大语言模型研发项目——构建。

日语有其独特的挑战。它形态丰富，并因与世界其他地区的历史文化交融而不断演化；其书写系统混用三套不同的字符：源自中文的简化表意符号汉字（漢字）、表音文字平假名（平仮名 / ひらがな），以及常用于外来词的片假名（片仮名 / カタカナ）。现代日语可以说是最难处理的语言之一，它混合了日源汉字词、和语、拉丁字母（romaji /ローマ字）、来自荷兰语、葡萄牙语、法语、英语、德语的借词，外加阿拉伯数字与传统汉字数字。此外，日本的数字世界还带来了 Unicode 颜文字 :) 的发展、使用西里尔字母的 kaomoji（っ °Д °;)っ 和希腊字母 ＿φ(°-°=)。当然还有源自日本、随 1990 年代手机流行而兴起的那些经典 emoji。

[![Japanese writing system](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/fxTPcxQqAo49s_jE_5wCw.png)](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/fxTPcxQqAo49s_jE_5wCw.png)

日语复杂的书写系统之下还藏着另一层复杂性：词与词之间没有空格。与中文或泰语类似，日语在语言单位之间没有空白，这使得 tokenization 时的词边界检测极为困难。多年来，生机勃勃的日本生态（从顶尖大学实验室、AI 创业公司到行业巨头的研发中心）在开发现代、健壮的日语 LLM 时已将日语 NLP 的这些特殊性纳入考量，但该领域一直缺少一个集中而开放的模型比较体系。

因此我们推出 Open Japanese LLM Leaderboard——Hugging Face 与 LLM-jp 的合作——以促进研究透明，鼓励开源模型开发理念。我们坚信这一倡议将成为日本与国际研究者协作、评估并改进日语 LLM 的平台。

## 榜单任务介绍

Open Japanese LLM Leaderboard 使用专门的评估套件 **[llm-jp-eval](https://github.com/llm-jp/llm-jp-eval)** 评估日语 LLM，覆盖 16 类任务——从经典任务（如*自然语言推理、机器翻译、摘要、问答*）到更现代的任务（如*代码生成*、*数学推理*或*人类考试*）。任务以 4-shot 方式运行。

数据集由 LLM-jp 评估团队汇编：有的与语言学家、专家和人工标注者从零构建，有的自动翻译成日语并针对日语特性调整，其中一些还需要长上下文推理。为便于理解榜单，我们将详细介绍 8 个数据集的样例（日语原文，浅灰色为英文译文）。关于所有可用任务的细节，请查看榜单的 "About" 标签页以及各数据集的官方链接。

### Jamp

**Jamp**（*用于评估语言模型泛化能力的受控日语时间推理数据集*，Controlled Japanese Temporal Inference Dataset for Evaluating Generalization Capacity of Language Models）是面向 NLI 的日语时间推理基准。数据集探索英日句对之间的各类时间推理模式，并标注了蕴含、中立、矛盾等金标签。

[![Jamp](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/EF2BuJC_oWvw2Jc5kvGCo.png)](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/EF2BuJC_oWvw2Jc5kvGCo.png)

### JEMHopQA

**JEMHopQA**（*Japanese Explainable Multi-hop Question Answering*）是一个可评估内部推理的日语多跳问答数据集。任务输入一个问题，生成答案和推理过程。

[![JEMHopQA](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/ZicrCMz4LtXDxSxeBBTl-.png)](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/ZicrCMz4LtXDxSxeBBTl-.png)

### jcommonsenseqa

**jcommonsenseqa** 是 CommonsenseQA 的日语版本，一个多选问答数据集，用于评估常识推理能力。

[![jcommonsensqa](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/s21OdhQIRRW7dqTF9mYoq.png)](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/s21OdhQIRRW7dqTF9mYoq.png)

### chABSA

**chABSA** 是一个*基于方面的情感分析*（Aspect-Based Sentiment Analysis）数据集。ChABSA 基于 2016 财年日本上市公司的财务报告，对实体、属性、情感三元组进行标注。更具体地说，依据日本金融监管机构*金融厅（FSA）*的分类体系，对日本 2,260 家上市公司中的 230 家（约 10%）进行了标注。

[![chABSA](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/O2kTDa1w0YAJOW1quXuDQ.png)](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/O2kTDa1w0YAJOW1quXuDQ.png)

### mbpp-ja

**mbpp-ja** 数据集是一个编程数据集：它是由 **[LLM-jp](https://llm-jp.nii.ac.jp/en/)** 借助翻译工具 **[DeepL](https://www.deepl.com)** 将英语 *Mostly Basic Python Problems dataset*（MBPP）翻译成日语的版本。

[![mbpp-ja](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/g21y5x0BuCWlX6foubsv5.png)](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/g21y5x0BuCWlX6foubsv5.png)

### mawps

日语 **mawps** 数据集基于 `MAWPS`（*A Math Word Problem Repository*），是一个数学评估数据集。该版本评估通过逐步推理（即 Chain-of-Thought / CoT 推理）解决新任务的能力，并对人名、单位、地名做了转换以适配日语语境。数学推理的难度较为简单：加法、减法、多步算术，以及单方程或方程组。

[![mawps](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/1FXowoymJJ72r6I2Q9si_.png)](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/1FXowoymJJ72r6I2Q9si_.png)

### JMMLU

**JMMLU** 是一个采用四选一问答的知识数据集。它由 MMLU 数据集中考察高中水平知识的一部分题目日译构成。基于天文学、化学、社会学、国际法等 57 个学科，题目与答案被翻译成日语，并针对日本公民、日本地理、日语惯用语等独特日本文化语境做了调整。

[![JMMLU](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/gVojua_19QLpFJqGSA8xz.png)](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/gVojua_19QLpFJqGSA8xz.png)

### XL-Sum

**XL-Sum** 是一个摘要数据集，基于研究 *"XL-Sum: Large-Scale Multilingual Abstractive Summarization for 44 Languages"*，使用 BBC 新闻文章的日语翻译。数据集分为三部分：标题、正文（全文文章）和摘要。主题包括全球议题、政治、科技、体育与文化。

[![XL-Sum](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/dlMq7ii_VfVzYHLDQx7Y_.png)](https://cdn-uploads.huggingface.co/production/uploads/63171caf1cc81c5e95ed7b92/dlMq7ii_VfVzYHLDQx7Y_.png)

## 技术配置

榜单灵感来自 **[Open LLM Leaderboard](https://huggingface.co/spaces/HuggingFaceH4/open_llm_leaderboard)**。提交的模型使用 HuggingFace 的 **[Inference endpoints](https://huggingface.co/docs/inference-endpoints/index)** 自动部署，通过 1.14.1 版本的 **[llm-jp-eval](https://github.com/llm-jp/llm-jp-eval)** 库、内存高效的推理与服务引擎 **[vLLM](https://github.com/vllm-project/vllm)**（v0.6.3）进行评估，并在日本面向研究的高性能计算平台 **[mdx](https://mdx.jp/)** 的后端完成计算。

## 观察

根据日语 LLM 指南 **[Awesome Japanese LLM](https://llm-jp.github.io/awesome-japanese-llm/)**（有日、英、法三种语言版本），Meta 的 `LLama` 开源架构似乎是众多日本 AI 实验室的最爱。不过其他架构也被日本开源社区成功运用，如法国 Mistral 的 `Mistral`、中国阿里巴巴的 `Qwen`。这些架构在日语 LLM 榜单上取得了最高分。

在一般语言处理任务上，我们观察到基于开源架构的日语 LLM 正在缩小与闭源 LLM 的差距，例如由 LLM-jp 开发、大学经费支持的日语 LLM `llm-jp-3-13b-instruct`，已达到与闭源模型相当的性能。而 `chABSA`（金融）、`Wikipedia Annotated Corpus`（语言学标注）、代码生成（`mbpp-ja`）和摘要（`XL-Sum`）等领域专用数据集对多数 LLM 仍是挑战。有趣的是，来自日本公司或实验室的模型在特定的 `JCommonsenseMorality` 数据集上得分更高——它评估模型在面对伦理困境时按日本价值观做选择的能力。

## 未来方向

Open Japanese LLM Leaderboard 将跟随评估工具 **[llm-jp-eval](https://github.com/llm-jp/llm-jp-eval)** 的发展，以反映日语 LLM 的持续演进。以下是 llm-jp-eval 未来方向的几个例子，欢迎联系我们提供帮助或建议方向！

- **新数据集：更多日语评估** llm-jp-eval 评估团队正在推进该部分，目前新增 **[JHumanEval](https://huggingface.co/datasets/kogi-jwu/jhumaneval)**（*HumanEval 日语版*）和 **[MMLU](https://github.com/hendrycks/test)**（*Measuring Massive Multitask Language Understanding*）。
- **新评估体系：思维链评估** 我们想在 Chain-of-Thought prompt 与基础 prompt 下比较 LLM 表现，以更深入理解模型行为。
- **新指标支持：Out-of-Choice 率** 对于已有明确标签列表的评估任务（如自然语言推理），我们希望添加一个补充指标，测试模型预测选项外 token 的频率。由于选项已在 prompt 中给出，这将让我们评估每个 LLM 遵循特定指令的能力。
