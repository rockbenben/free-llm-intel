# Granite Embedding Multilingual R2：Apache 2.0 开放、32K 上下文的多语言嵌入——100M 参数以下最佳检索质量

> TL;DR：两个基于 ModernBERT 构建的全新 Apache 2.0 多语言嵌入模型——一个 97M 参数的紧凑模型，在 MTEB 多语言检索（60.3）上击败所有开放的 100M 参数以下多语言嵌入模型；一个 311M 的全尺寸模型，在 MTEB 多语言检索上得 65.2 分（500M 参数以下开放模型中排名第 2），并支持 Matryoshka。两个模型都覆盖 200+ 语言、针对 52 种语言做了调优、支持 32K token 上下文（R1 的 64 倍），并新增 9 种编程语言的代码检索。

多语言嵌入模型长期面临一个矛盾：语言覆盖广通常要拿模型体积换，小模型通常又牺牲语言数。如果你跨语言工作——在多语言语料上做检索增强生成、跨语言搜索、国际团队里的代码检索——你大概率不得不在"够快"和"够好"之间二选一。

Granite Embedding Multilingual R2 这次发布大大缩小了这个差距。我们发布两个新的多语言嵌入模型：

- [**granite-embedding-311m-multilingual-r2**](https://huggingface.co/ibm-granite/granite-embedding-311m-multilingual-r2) —— 311M 参数的全尺寸模型，768 维嵌入，支持 Matryoshka 维度，多语言检索质量一流。
- [**granite-embedding-97m-multilingual-r2**](https://huggingface.co/ibm-granite/granite-embedding-97m-multilingual-r2) —— 97M 参数的紧凑模型，384 维嵌入，以该体积提供了强劲的检索质量。

两个模型都支持 **200+ 语言**，针对 **52 种语言和编程代码**的检索质量做了增强，支持最长 **32,768 token** 的上下文（比 R1 前代增加 64 倍），并以 **Apache 2.0** 许可证发布。它们开箱即用地兼容 `sentence-transformers` 和 `transformers`，不需要任务特定指令，在 **LangChain**、**LlamaIndex**、**Haystack** 和 **Milvus** 中只需改一行模型名即可作为即插即用替换。对于目前默认只用英文的框架，这一行就能让你社区里的每个用户获得 200+ 语言支持——不改 API、不加依赖、用户端零代码改动。两个模型都附带 ONNX 和 OpenVINO 权重，支持 CPU 优化推理。

## 为企业就绪的设计

两个嵌入模型的训练数据混合了 IBM 精选数据集、公开可得数据以及内部生成或合成数据。训练中使用的源自公开网络的数据，经过 IBM 开发的质量、去重与治理流程筛选，以降低下游商业使用的风险。我们有意不使用 MS-MARCO 训练数据集以及带明确非商业许可限制的数据集。模型预训练使用 [GneissWeb](https://huggingface.co/datasets/ibm-granite/GneissWeb)——一个由 IBM 基于公开网络内容精选、并用 IBM 数据准备与治理工具链处理的数据集——以及额外的 IBM 精选数据和其他公开来源。数据集都经过 IBM 治理评审，评估许可考量、所有权信号和个人数据风险。这些流程旨在为负责任的使用和企业级部署提供保障。

## 一个强悍的 100M 以下多语言模型

本次发布最亮眼的是 **granite-embedding-97m-multilingual-r2**。以 9700 万参数，它在覆盖 18 种语言的 Multilingual MTEB Retrieval 上得 **60.3 分**——是我们所知 100M 参数以下开放多语言嵌入模型中的最高检索分。同一体积档次的第二名 multilingual-e5-small 在同一基准上只有 50.9 分——在一个成熟的基准上拉开了 **+9.4 分**的差距。

体积约为 311M 全尺寸模型的三分之一，它在多语言、代码和长文档基准上保留了绝大部分检索质量——相比直接前代在 MTEB 多语言检索上 **+12.2 分**的进步，来自新架构、更好的训练数据和一套新颖的剪枝方法（详见下文）。全尺寸 **granite-embedding-311m-multilingual-r2** 在同一基准上得 **65.2 分**，比其 R1 前代 **+13.0 分**。

## 相比 R1 改了什么

Granite Embedding Multilingual R1 模型基于 XLM-RoBERTa 编码器，上下文窗口只有 512 token。R2 一代是彻底的重建：

[![Granite Embedding R2 架构](https://cdn-uploads.huggingface.co/production/uploads/642ae74b25442667e9bd72ed/jhz201_Ud5zUWfA3k4ITA.png)](https://cdn-uploads.huggingface.co/production/uploads/642ae74b25442667e9bd72ed/jhz201_Ud5zUWfA3k4ITA.png)

[ModernBERT](https://huggingface.co/blog/modernbert) 是近期的编码器架构，用过去五年 Transformer 研究的成果重新审视了 BERT 的原始设计。这一转变带来多项实际收益：交替注意力长度减少了长序列的计算（长序列吞吐显著提升），旋转位置编码让 32K 上下文窗口无需老式架构里那些麻烦的位置插值技巧，Flash Attention 2.0 支持则让现代 GPU 上的编码更快。

新的多语言 tokenizer 也值得单独一说。我们没有复用 XLM-RoBERTa 的 250K token 词表，而是采用了在多语言和代码覆盖上都很强的现成 tokenizer。311M 模型使用 Gemma 3 tokenizer（262K token）；97M 模型从 GPT-OSS tokenizer 出发，剪枝到紧凑的 180K token 词表，在保留广泛多语言覆盖的同时缩减了嵌入表的参数规模。Tokenizer 的效率比人们意识到的更重要——32K token 窗口听起来很唬人，但如果你的 tokenizer 编码一段泰文就烧掉一半窗口，那就另当别论了。

## 全尺寸 311M 模型的训练

311M 模型是一个 22 层的 ModernBERT 编码器，带 262K token 多语言词表，通过多阶段流水线训练：

- **知识蒸馏**：模型同时向多个教师模型学习。教师是 Granite 3.3 Instruct 和 Mistral v0.2 Instruct 解码器模型（为文本嵌入进一步微调过），把检索专项知识迁移进 311M 编码器架构。
- **对比微调**：标准对比训练，使用多语言检索配对——在 52 种语言和代码中，把查询与相关段落及困难负例配对——锤炼模型区分相关与无关结果的能力。
- **模型合并**：训练后，我们合并来自不同训练阶段和配置的 checkpoint，把为不同目标优化的模型（例如多语言广度 vs. 英文深度）的优势合进同一套权重，不需要额外训练算力。
- **Matryoshka Representation Learning**：模型用 Matryoshka 目标训练，其 768 维嵌入可以几乎不损质量地截断到 512、384、256 或 128 维（见下文 [Matryoshka 嵌入](https://huggingface.co/blog/ibm-granite/granite-embedding-multilingual-r2#matryoshka-embeddings-311m)）。

成果是一个在 MTEB 多语言检索上得 65.2、总体平均分 56.3 的模型——比其 R1 前代平均 **+14.5 分**。

## 紧凑 97M 多语言模型的打造

97M 模型通过**词表选择**与**知识蒸馏**结合训练：

- **词表选择**：将 262K token 词表缩减为专门训练的 180K token 词表，在大幅缩小嵌入表的同时保留广泛的多语言覆盖。
- **知识蒸馏**：剪枝后的模型再经知识蒸馏微调，使用多个教师模型（包括 [Granite 4.1 8B](https://huggingface.co/ibm-granite/granite-4.1-8b) 和基于 Mistral Instruct 解码器的教师），并配合对比训练提升检索质量。

这种方法在缩减模型参数的同时不牺牲语言覆盖，把检索专项知识从多个强教师那里迁移过来。成果是一个高效的紧凑模型——在 MTEB 多语言检索上得 60.3 分（全尺寸模型 65.2 分），而体积约小 3 倍。

## Matryoshka 嵌入（311M）

311M 模型支持 [Matryoshka Representation Learning](https://arxiv.org/abs/2205.13147)，允许把嵌入从完整的 768 维优雅地截断到 512、384、256 或 128 维，质量平缓下降。当存储、内存或相似度计算成本是要素时这很有用——256 维嵌入只需 768 维三分之一的存储，余弦相似度的计算开销也按比例降低。

下面是检索质量随嵌入维度的保持情况：

[![Matryoshka 嵌入：截断维度上质量的平缓下降](https://cdn-uploads.huggingface.co/production/uploads/642ae74b25442667e9bd72ed/myYhY1YHLY9Vs3l0gyMJB.png)](https://cdn-uploads.huggingface.co/production/uploads/642ae74b25442667e9bd72ed/myYhY1YHLY9Vs3l0gyMJB.png)

降维带来的质量损失小得惊人。从 768 降到 256 维——存储与相似度计算成本 **3 倍缩减**——MTEB 多语言检索只掉 0.5 分（65.2 → 64.7），代码检索掉 0.5 分（63.9 → 63.4）。即使降到 128 维（**6 倍缩减**），模型在 MTEB 多语言检索上仍有 63.7、代码 62.3，保留了全维度性能 **97% 以上**。实际含义是：你可以大幅缩小索引规模和搜索延迟，而结果质量几乎不受影响。（注：上图结果在英文与多语言检索上用 1024 上下文长度评估，代码用 8192。）

作为对比，311M 模型截断到 384 维（与 97M 模型的原生输出同维）后，在全部三项基准上仍胜过 97M 模型。如果你需要 384 维嵌入且负担得起 311M 的编码成本，Matryoshka 截断是更强的选项。

```
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("ibm-granite/granite-embedding-311m-multilingual-r2")

# Full 768-dimensional embeddings
full = model.encode(["example text"])
print(full.shape)  # (1, 768)

# Truncated to 384 dimensions
small = model.encode(["example text"], truncate_dim=384)
print(small.shape)  # (1, 384)
```

97M 模型不支持 Matryoshka——384 维已经足够紧凑。

### 跨语言检索

MTEB 检索中跨语言任务的平均表现。[Belebele](https://huggingface.co/datasets/facebook/belebele) 衡量 122 种语言的跨语言段落匹配；MLQA 衡量 7 种语言的抽取式跨语言问答检索。

| 模型 | Belebele 检索 | MLQA 检索 |
| --- | --- | --- |
| granite-embedding-107m-multilingual (R1) | 55.1 | 60.5 |
| granite-embedding-278m-multilingual (R1) | 62.2 | 63.0 |
| granite-embedding-97m-multilingual-r2 | 52.9 | 60.5 |
| **granite-embedding-311m-multilingual-r2** | **66.5** | **67.1** |

311M R2 模型相比其 R1 前代在 Belebele 上 +4.3、MLQA 上 +4.1，在两个基准上都展现了更大规模下更好的跨语言迁移。

97M R2 模型在 Belebele 上较低（52.9 vs 55.1，−2.2），MLQA 与其 R1 前代持平（60.5）。Belebele 的差距是剪枝与词表缩减过程固有的权衡——R2 模型的训练优先了更广泛的 18 语言 MTEB 多语言检索集（相比 R1 提升 +12.2）和长文档检索（+31.3），而更小的词表（180K vs 250K）和更少的层数（12 vs 22）影响了窄范围的跨语言迁移任务。如果你的主要用例是众多语言对之间的跨语言迁移，全尺寸 311M 模型是更好的选择。

## 部署选项

两个模型都提供了面向生产的多条部署路径。核心库安装：

```
pip install sentence-transformers
```

**Sentence Transformers**（推荐大多数用户）：

```
from sentence_transformers import SentenceTransformer, util

model = SentenceTransformer("ibm-granite/granite-embedding-97m-multilingual-r2")

queries = [
    "What is the tallest mountain in Japan?",          # English
    "Wer hat das Lied Achy Breaky Heart geschrieben?", # German
    "ドイツの首都はどこですか？",                            # Japanese
]

    "富士山は、静岡県と山梨県にまたがる活火山で、標高3776.12 mで日本最高峰の独立峰である。",  # Japanese
    "Achy Breaky Heart is a country song written by Don Von Tress.",                        # English
    "Berlin ist die Hauptstadt und ein Land der Bundesrepublik Deutschland.",                # German

q_emb = model.encode(queries)

# Each query scores highest against its matching passage — across languages
```

```
from haystack.components.embedders import (
    SentenceTransformersDocumentEmbedder,
    SentenceTransformersTextEmbedder,
)
from haystack.components.retrievers.in_memory import InMemoryEmbeddingRetriever
from haystack.dataclasses import Document
from haystack.document_stores.in_memory import InMemoryDocumentStore

doc_embedder = SentenceTransformersDocumentEmbedder(
    model="ibm-granite/granite-embedding-97m-multilingual-r2"
)
query_embedder = SentenceTransformersTextEmbedder(
    model="ibm-granite/granite-embedding-97m-multilingual-r2"
)
doc_embedder.warm_up()
query_embedder.warm_up()

# Embed and index documents
document_store = InMemoryDocumentStore()
result_docs = doc_embedder.run(documents=[
    Document(content="富士山は日本最高峰の独立峰です。"),
    Document(content="Mount Fuji is Japan's highest peak."),
    Document(content="Achy Breaky Heart is a country song written by Don Von Tress."),
    Document(content="Berlin ist die Hauptstadt und ein Land der Bundesrepublik Deutschland."),
])
document_store.write_documents(result_docs["documents"])

# Embed query and retrieve
result_query = query_embedder.run(text="What is Japan's tallest mountain?")
retriever = InMemoryEmbeddingRetriever(document_store=document_store)
results = retriever.run(query_embedding=result_query["embedding"], top_k=2)
for doc in results["documents"]:
    print(f"{doc.score:.3f}  {doc.content}")
# 0.961  Mount Fuji is Japan's highest peak.
# 0.913  富士山は日本最高峰の独立峰です。
```

```
from pymilvus import MilvusClient
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("ibm-granite/granite-embedding-97m-multilingual-r2")

# Use "./milvus.db" for local persistence or a server URI for production
client = MilvusClient(":memory:")
client.create_collection(collection_name="multilingual_docs", dimension=384)

docs = [
    "富士山は日本最高峰の独立峰です。",
    "Mount Fuji is Japan's highest peak.",
    "Achy Breaky Heart is a country song written by Don Von Tress.",
    "Berlin ist die Hauptstadt und ein Land der Bundesrepublik Deutschland.",
]
embeddings = model.encode(docs).tolist()
client.insert(
    collection_name="multilingual_docs",
    data=[{"id": i, "vector": emb, "text": doc} for i, (emb, doc) in enumerate(zip(embeddings, docs))],
)

query_emb = model.encode(["What is Japan's tallest mountain?"]).tolist()
results = client.search(
    collection_name="multilingual_docs",
    data=query_emb,
    limit=2,
    output_fields=["text"],
)
for hit in results[0]:
    print(f"{hit['distance']:.3f}  {hit['entity']['text']}")
# 0.961  Mount Fuji is Japan's highest peak.
# 0.913  富士山は日本最高峰の独立峰です。
```

## 给框架集成者

如果你维护某个嵌入框架、向量存储或 RAG 流水线库，正在评估这些模型作为默认选项，你需要知道：

- **许可证**：Apache 2.0，训练未使用 MS-MARCO
- **即插即用行为**：不需要任务特定指令前缀——API 层面表现得像 `all-MiniLM-L6-v2`，现有调用 `.encode()` 的代码无需改动。
- **维度**：384 维输出（97M）和 768 维输出（311M），与最常见的现有默认值相同，不需要索引迁移。
- **模型体积**：97M 模型权重 195 MB（safetensors）——不到 `paraphrase-multilingual-MiniLM-L12-v2`（471 MB，最常见的多语言默认）的一半。量化 ONNX 权重只有 98 MB，与 `all-MiniLM-L6-v2`（91 MB）相当，却覆盖 200+ 语言。
- **CPU 友好**：附带 ONNX 和 OpenVINO 权重做 CPU 优化推理，入门教程不需要 GPU。
- **默认多语言**：如果你当前的默认是纯英文，这是一次一行的替换，社区每个用户即可获得 200+ 语言支持——他们的代码一行都不用动。
- **稳定标识**：`ibm-granite/granite-embedding-97m-multilingual-r2` 在 Hugging Face 上，由 IBM 在 Granite 模型家族下维护。

想讨论在你的项目中采用这些模型作为默认，请到 [ibm-granite/granite-embedding-models](https://github.com/ibm-granite/granite-embedding-models) 开 issue。

## 该选哪个模型？

这两个多语言模型是更庞大的 **Granite Embedding R2** 家族的一部分，该家族还包含两个高性能英文专用模型：[granite-embedding-english-r2](https://huggingface.co/ibm-granite/granite-embedding-english-r2)（149M 参数）和 [granite-embedding-small-english-r2](https://huggingface.co/ibm-granite/granite-embedding-small-english-r2)（47M 参数）。如果你的数据以英文为主，英文模型能以更小体积在英文基准上提供更高检索质量——它们无需把容量分摊到 200+ 语言上。

| 如果你需要…… | 用 |
| --- | --- |
| 最佳多语言检索质量 | [granite-embedding-311m-multilingual-r2](https://huggingface.co/ibm-granite/granite-embedding-311m-multilingual-r2) |
| 灵活嵌入维度（存储/速度权衡） | granite-embedding-311m-multilingual-r2（Matryoshka） |
| 最大吞吐 / 边缘部署 / 低延迟 | [granite-embedding-97m-multilingual-r2](https://huggingface.co/ibm-granite/granite-embedding-97m-multilingual-r2) |
| 众多语言对上最佳的跨语言迁移 | granite-embedding-311m-multilingual-r2 |
| 以英文为主的数据 | [granite-embedding-english-r2](https://huggingface.co/ibm-granite/granite-embedding-english-r2) 或 [granite-embedding-small-english-r2](https://huggingface.co/ibm-granite/granite-embedding-small-english-r2) |
