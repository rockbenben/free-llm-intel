# 工具使用，走向统一

本文另有[简体中文](https://huggingface.co/blog/zh/unified-tool-use)版本。

现在，一批主流模型家族拥有了**统一的工具使用（tool use）API**。这意味着同一份代码可以跨模型移植——要在对话中使用 [Mistral](https://huggingface.co/mistralai)、[Cohere](https://huggingface.co/CohereForAI)、[NousResearch](https://huggingface.co/NousResearch) 或 [Llama](https://huggingface.co/collections/meta-llama/llama-31-669fc079a0c406a149a5738f) 模型的工具，几乎不需要任何模型专属的改动。此外，Transformers 还新增了让工具调用更省事的辅助功能，并提供了覆盖整个工具使用流程的[完整文档](https://huggingface.co/docs/transformers/main/chat_templating#advanced-tool-use--function-calling)和[示例](https://github.com/huggingface/blog/blob/main/notebooks/unified-tool-calling.ipynb)。对更多模型的支持也将在不久后加入。

## 引言

工具使用是个挺奇特的功能——人人都觉得它很棒，但大多数人自己还没试过。概念上它非常直白：你把一些工具（可调用的函数）交给 LLM，它可以自行决定调用它们来帮助回答用户的问题。也许你给它一个计算器，让它不必依赖自己不可靠的内部算术能力；也许你让它搜索网页、查看你的日历，或者给它一个公司数据库的（只读！）访问权限，让它能查信息或检索技术文档。

工具使用弥补了 LLM 的很多核心短板。许多 LLM 谈吐流畅、夸夸其谈，但在计算和事实方面常常不精确，对小众话题的具体细节也含糊其辞。它们对训练截止日期之后发生的事情一无所知。它们是通才——进入对话时，除了系统消息里给的信息，它们对你、对你的工作场所毫无了解。工具为它们提供了结构化、具体、相关且最新的信息，这大有帮助，能让它们成为真正有用的伙伴，而不只是好看的新奇玩具。

问题出在你真正动手实现工具使用的时候。文档往往稀缺、不一致，甚至自相矛盾——闭源 API 和开放模型都一样！工具使用理论上很简单，实践中却经常变成噩梦：怎么把工具传给模型？怎么保证工具提示词的格式和模型训练时的格式一致？模型调用工具后，怎么把这次调用融进对话？如果你以前实现过工具使用，大概会发现这些问题出奇地棘手，而文档并不总是完整和有帮助。

更糟的是，不同模型的工具使用实现可能天差地别。就连最基础的"定义可用工具"这一步，有的服务商期待 JSON schema，有的却期待 Python 函数头。同样期待 JSON schema 的各家，细节也常有小出入，造成大大的 API 不兼容。这带来了大量摩擦，也总体上加深了用户的困惑。那么，我们对这一切能做点什么？

## 对话模板化

Hugging Face 电影宇宙的铁杆粉丝会记得，开源社区过去在**对话模型**上面对过类似的挑战。对话模型使用像 `<|start_of_user_turn|>` 或 `<|end_of_message|>` 这样的控制 token 来让模型明白对话正在进行什么，但不同模型训练时用的控制 token 完全不同，这意味着用户必须为想用的每个模型编写专门的格式化代码。在当时，这是个大麻烦。

我们的解决方案是**对话模板（chat templates）**——本质上，模型自带一个小小的 [Jinja](https://jinja.palletsprojects.com/en/3.1.x/) 模板，它会用适合该模型的格式和控制 token 渲染对话。有了对话模板，用户就能以通用的、与模型无关的格式编写对话，把各模型的专属格式交给 Jinja 模板去处理。

于是支持工具使用的显然思路，就是扩展对话模板也支持工具。我们正是这么做的——但工具给模板系统带来了许多新挑战。我们来过一遍这些挑战以及我们的解法。希望在这个过程中，你也能对系统如何工作、如何让它为你所用有更深的理解。

## 把工具传给对话模板

设计工具使用 API 时，我们的第一准则是：定义工具并把它传给模板的过程应当直观。我们发现多数用户是先写工具函数，再想法子从函数生成工具定义、把它传给模型。这引出一个显而易见的方案：如果用户能直接把函数传给对话模板，让模板自动生成工具定义呢？

但这里的问题在于，"传函数"是一件非常依赖编程语言的事，而很多人是用 [JavaScript](https://huggingface.co/docs/transformers.js/en/index) 或 [Rust](https://huggingface.co/docs/text-generation-inference/en/index) 访问对话模型的，而不是 Python。于是我们找到了一个我们认为两全其美的折中方案：**对话模板期待工具以 JSON schema 定义，但如果你传的是 Python 函数，模板会自动帮你转换成 JSON schema。** 最终 API 干净漂亮：

```
def get_current_temperature(location: str):
    """
    Gets the temperature at a given location.

    Args:
        location: The location to get the temperature for
    """
    return 22.0  # bug: Sometimes the temperature is not 22. low priority

tools = [get_current_temperature]    

chat = [
    {"role": "user", "content": "Hey, what's the weather like in Paris right now?"}
]

tool_prompt = tokenizer.apply_chat_template(
    chat, 
    tools=tools,
    add_generation_prompt=True,
    return_tensors="pt"
)
```

在内部，`get_current_temperature` 函数会被展开成完整的 JSON schema。想看生成的 schema，可以用 `get_json_schema` 函数：

```
>>> from transformers.utils import get_json_schema

>>> get_json_schema(get_current_weather)
{
    "type": "function",
    "function": {
        "name": "get_current_temperature",
        "description": "Gets the temperature at a given location.",
        "parameters": {
            "type": "object",
            "properties": {
                "location": {
                    "type": "string",
                    "description": "The location to get the temperature for"
                }
            },
            "required": [
                "location"
            ]
        }
    }
}
```

如果你喜欢手动控制，或者你用的语言不是 Python，也可以把这类 JSON schema 直接传给模板。不过当你在 Python 里工作时，可以避免直接摆弄 JSON schema。你只需要用清晰的**函数名**、准确的**类型标注**和完整的 **docstring**（包括**参数说明**）来定义工具函数——这些都会被用来生成模板所读取的 JSON schema。其中大部分本来就是好的 Python 实践，遵循它你会发现根本不需要额外工作——你的函数天然就能当工具用！

记住：准确的 JSON schema——无论是由 docstring 和类型标注生成还是手工指定——对模型理解如何使用你的工具至关重要。模型永远不会看到你函数里的代码，但它会看到 JSON schema。它们越干净、越准确越好！

## 把工具调用加进对话

一个经常被用户（以及模型文档 😬）忽略的细节是：当模型调用一个工具时，实际上需要往对话历史里加**两条**消息。第一条是助手**调用**工具的消息，第二条是**工具响应**，即被调用函数的输出。

工具调用和工具响应两者都必不可少——记住，模型只知道对话历史里的内容，如果它既看不到自己发出的调用、也看不到传过去的参数，它就没法理解一条工具响应。"22" 这个数本身没什么信息量，但如果它知道前面那条消息是 `get_current_temperature("Paris, France")`，这就非常有用。

这恰是各家服务商实现差异最大的地方之一，而我们最终定下的标准是：**工具调用是助手消息的一个字段**，如下所示：

```
message = {
    "role": "assistant",
    "tool_calls": [
        {
            "type": "function",
             "function": {
                 "name": "get_current_temperature", 
                 "arguments": {
                     "location": "Paris, France"
                }
            }
        }
    ]
}
chat.append(message)
```

## 把工具响应加进对话

工具响应就简单多了，特别是当工具只返回单个字符串或数字时。

```
message = {
    "role": "tool", 
    "name": "get_current_temperature", 
    "content": "22.0"
}
chat.append(message)
```

## 工具使用的实战

我们把目前的代码串起来，做一个完整的工具调用示例。如果你想在自家项目里用工具，建议多玩一玩这里的代码——自己跑一遍、增删工具、换模型、调细节，找到手感。等你真要在软件里落地工具使用时，这份熟稔会让事情轻松得多。为方便起见，这个示例也有 [notebook 版本](https://github.com/huggingface/blog/blob/main/notebooks/unified-tool-calling.ipynb)。

首先设置模型。我们用 `Hermes-2-Pro-Llama-3-8B`，因为它小巧、能干、无需申请权限，而且支持工具调用。在复杂任务上，用更大的模型也许效果更好！

```
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

checkpoint = "NousResearch/Hermes-2-Pro-Llama-3-8B"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
model = AutoModelForCausalLM.from_pretrained(checkpoint, torch_dtype=torch.bfloat16, device_map="auto")
```

接下来设置工具和我们要用的对话。就用上面的 `get_current_temperature` 例子：

```
def get_current_temperature(location: str):
    """
    Gets the temperature at a given location.

    Args:
        location: The location to get the temperature for, in the format "city, country"
    """
    return 22.0  # bug: Sometimes the temperature is not 22. low priority to fix tho

tools = [get_current_temperature]    

chat = [
    {"role": "user", "content": "Hey, what's the weather like in Paris right now?"}
]

tool_prompt = tokenizer.apply_chat_template(
    chat, 
    tools=tools, 
    return_tensors="pt",
    return_dict=True,
    add_generation_prompt=True,
)
tool_prompt = tool_prompt.to(model.device)
```

现在可以给模型生成对用户问题的回应了，它有权使用那些工具：

```
out = model.generate(**tool_prompt, max_new_tokens=128)
generated_text = out[0, tool_prompt['input_ids'].shape[1]:]

print(tokenizer.decode(generated_text))
```

我们得到：

```
<tool_call>
{"arguments": {"location": "Paris, France"}, "name": "get_current_temperature"}
</tool_call><|im_end|>
```

模型请求调用了一个工具！注意它如何正确推断出应该传参数 "Paris, France" 而不只是 "Paris"——因为函数 docstring 里推荐的就是这个格式。

不过模型其实并没有对工具的编程访问权限——和所有语言模型一样，它只是在生成文本。如何接收模型的请求并真正调用函数，是你作为程序员的工作。不过首先，把模型的工具请求加进对话。

注意这一步可能需要一点手工处理——虽然你总应该按下面的格式把请求加进对话，但工具调用请求的文本形式，比如 `<tool_call>`/`</tool_call>` 这类标签，可能因模型而异。通常它相当直观，但当你自己在代码里做这件事时，可能还是需要一点模型专属的 `json.loads()` 或 `re.search()`！

```
message = {
    "role": "assistant", 
    "tool_calls": [
        {
            "type": "function", 
            "function": {
                "name": "get_current_temperature", 
                "arguments": {"location": "Paris, France"}
            }
        }
    ]
}
chat.append(message)
```

现在，我们在 Python 代码里真正调用这个工具，并把它的响应加进对话：

```
message = {
    "role": "tool", 
    "name": "get_current_temperature", 
    "content": "22.0"
}
chat.append(message)
```

最后，和之前一样，把更新后的对话格式化后传给模型，让它能在对话中利用工具响应：

```
tool_prompt = tokenizer.apply_chat_template(
    chat, 
    tools=tools, 
    return_tensors="pt",
    return_dict=True,
    add_generation_prompt=True,
)
tool_prompt = tool_prompt.to(model.device)

out = model.generate(**tool_prompt, max_new_tokens=128)
generated_text = out[0, tool_prompt['input_ids'].shape[1]:]

print(tokenizer.decode(generated_text))
```

于是我们得到给用户的最终回答——它是借助中间那步工具调用获取的信息构建出来的：

```
The current temperature in Paris is 22.0 degrees Celsius. Enjoy your day!<|im_end|>
```

## 令人遗憾的响应格式不统一

读这个示例时你可能已经注意到：虽然对话模板能在"从对话和工具定义到格式化文本"的方向上屏蔽模型间的差异，反过来却不行。当模型发出工具调用时，它会用自己的格式，所以目前你得先手工解析出来，再按统一格式加进对话。好在大多数格式都相当直观，所以通常只要几行 `json.loads()`，最坏也不过一个简单的 `re.search()`，就能构造出你需要的工具调用字典。

话说回来，这仍是整个流程中"未统一"的最大一块。我们对如何修复它有一些想法，但还没到能公开的时候。用年轻人的话说："让我们再炖一会儿。"

## 结论

尽管有上面这个小缺憾，我们认为相比之前的局面——工具使用零散、混乱、文档匮乏——这已经是大步前进。我们希望这能让开源开发者更容易在自己的项目里加入工具使用，用一系列工具为强大的 LLM 增添出色的新能力。从 [Hermes-2-Pro-8B](https://huggingface.co/NousResearch/Hermes-2-Pro-Llama-3-8B) 这样的小模型，到 [Mistral-Large](https://huggingface.co/mistralai/Mistral-Large-Instruct-2407)、[Command-R-Plus](https://huggingface.co/CohereForAI/c4ai-command-r-plus) 或 [Llama-3.1-405B](https://huggingface.co/meta-llama/Meta-Llama-3.1-405B-Instruct) 这样体型庞大的最先进巨兽，众多前沿 LLM 如今都支持工具使用了。我们相信工具将是下一波 LLM 产品不可或缺的一部分，也希望这些改动能让你更轻松地在自己的项目里用上它们。祝好运！
