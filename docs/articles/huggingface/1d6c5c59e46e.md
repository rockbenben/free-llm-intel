今天我们发布 [**Old Ideas, Novel Problems**](https://arxiv.org/abs/2610.02022)，这是一项关于大语言模型能否可靠评估科学研究想法新颖性的新研究。随论文一同发布的，还有用于测试 novelty judge 的 benchmark、数据和代码，以及一条可供研究者构建新评测集的自动化 pipeline。

在 Ai2，我们一直在开发支持科学发现不同环节的 AI 系统。[DataVoyager](https://allenai.org/blog/asta-datavoyager) 帮助研究者探索和分析结构化数据，[AutoDiscovery](https://allenai.org/blog/autodiscovery) 生成并检验假设，[Theorizer](https://allenai.org/blog/theorizer) 将海量文献中的证据综合为候选科学理论。连同 [Asta](https://allenai.org/asta)，这些项目指向这样一类系统：它们能帮助研究者从理解既有工作，走到提出、检验和打磨新想法。

但生成研究想法只是自动化科学发现这项挑战的一部分。这些想法还必须贡献真正新的东西，这意味着这类系统需要有能力区分真正新颖的方向与基本上只是重新包装既有工作的方向。

这项判断往往交给另一个 LLM——我们称之为 *novelty judge*。Novelty judge 评估一个研究想法相对于既有工作是否新颖，可以单独评估，也可以与另一个想法比较。构建它并没有标准做法；研究团队自行选择模型、prompt、评测格式、推理预算，有时还包括文献检索系统。这些选择会实质性影响判定结果。然而，这类 judge 往往只在人类撰写的论文上做过验证，而不是在它们实际要评估的 AI 生成想法上验证。

我们新的 benchmark 结果提示，新颖性评测本身远谈不上可靠。在六个 LLM judge——GPT-5.1、GPT-5.2、GPT-5.4、Claude Sonnet 4.5、Claude Opus 4.5 和 Claude Opus 4.6——上，评测设置中看似微小的改动，会让同一批想法得到截然不同的判断。在一项实验中，只改动 prompt 里的几个词，模型判断两个想法中哪一个更新颖的准确率就偏移了 50 个百分点以上。检索和额外推理并不能稳定改善判断，而两个专门打造的 novelty 评测系统，表现还不如一个简单的 prompt 版 Claude Opus 4.6 baseline。

如果 AI 要在科学发现中扮演更大的角色，我们就需要更可靠的方法来判断它是否真的提出了新东西。我们的工作为研究这一问题提供了工具，同时也显示出还有多少问题悬而未决。

## 为 novelty judge 构建 benchmark

为了测试 novelty judge 区分更新颖与较不新颖研究想法的可靠程度，我们首先需要一批例子，其中关于底层科学贡献原创性的证据足够充分。

于是我们围绕 ICLR 2026 的同行评审构建了一条自动化 pipeline。我们没有把论文被接收当作新颖性的代理指标，而是从评审意见本身挖掘评审者明确讨论某项贡献原创性的段落。这一区别是关键：一篇论文只要在其他方面足够强，即使并不特别新颖也可能被接收。同样，一篇有原创贡献的被拒论文也可能存在其他弱点。

我们构建了一个包含 154 个人类撰写研究想法的 *high-novelty pool*：挑选其所在 ICLR 研究领域评分前 10% 的被接收论文，且其评审者明确认定具有新颖性、没有任何评审者提出异议。我们应用相反的标准构建 *lower-novelty pool*：145 个来自评分后 10% 的被拒论文的想法，其评审者提出了原创性疑虑，且没有任何评审者明确认定新颖。在对评审挖掘流程的一次单独核查中，一位标注者在 50 例里有 47 例与提取出的新颖性信号极性一致；这些分歧没有一例会改变某位评审者是否被计为在称赞或质疑论文的新颖性。

这两个池共同构成我们的第一个评测设置 *Human-Only*，用于测试 novelty judge 能否区分有较强证据表明新颖性较高或较低的人类撰写想法。但在实践中，novelty judge 越来越多地被用于评估 AI 生成的想法。因此我们创建了第二个设置 *Human+Generated*。

在这个池中，我们把同样的 154 个经过验证的人类想法与 154 个由简单 LLM 生成器产出的想法配对。我们假设生成的想法不如对应的人类撰写想法新颖；这些是弱标签，并非对每个想法逐一验证过的判断。生成器只收到一个研究领域和一条提出新颖想法的指令，没有文献检索、工具、迭代或反馈。这让我们得到一个保守的对比：来自基础生成器的想法，对上来自 ICLR 前 10% 论文、其评审者明确认可其原创性的贡献。

作为额外的核查，一位专家独立审阅了 30 组 *Human+Generated* 配对，其中大量偏向我们最强 judge 判断错误的案例；我们还把人类撰写与 AI 生成的想法改写为统一结构，以测试 judge 是否只是在反应写作风格上的差异。这位专家在全部 30 组中都更偏好人类想法，并认为没有一个生成的想法具备新颖性。

重要的是，我们的许多核心发现根本不依赖于这些标签。如果两个合理的评测设置对同一对想法给出相反答案，这种分歧本身就揭示了不稳定性。

## 微小的改动就能带来截然不同的判定

借助我们的人类撰写与 AI 生成研究想法集合，我们测试了六个 LLM judge——GPT-5.1、GPT-5.2、GPT-5.4、Claude Sonnet 4.5、Claude Opus 4.5 和 Claude Opus 4.6——通过 pointwise（即绝对新颖性评分）与 pairwise（即比较两个想法、找出更新颖的那个）两种比较方式评估新颖性的表现。我们每次只改变一个因素：prompt、推理预算、judge 能否看到相关论文、想法的格式化方式、多少个判断被合并为最终判定，以及——对 AI 生成的想法而言——由哪个模型生成。

性能上最大的变化来自我们如何用 prompt 引导模型判断新颖性。

例如，我们用两个 prompt 向 GPT-5.4 展示同样的 *Human+Generated* 配对——每组包含一个经过验证的人类撰写想法和一个 AI 生成想法。一个 prompt 告诉模型，评审者发现每组中恰好有一个想法是新颖的，并要求它指出是哪一个；另一个只是问哪个想法新颖。当我们换用更简单的 prompt 时，准确率从 93.5% 掉到 40.9%——低于随机水平——模型对超过一半的相同配对改变了判定。

[![柱状图比较六种 AI 模型在两个 prompt 下选中评审者称赞的人类想法的频率。Claude Opus 4.6：100.0% 对 72.7%；GPT-5.2：81.8% 对 76.0%；Claude Opus 4.5：92.2% 对 58.4%；GPT-5.1：79.2% 对 56.5%；GPT-5.4：93.5% 对 40.9%；Claude Sonnet 4.5：60.4% 对 36.4%。](https://www.datocms-assets.com/64837/1793023853-novelty-bench-prompt-wording-chart.png)](https://www.datocms-assets.com/64837/1793023853-novelty-bench-prompt-wording-chart.png)

相比之下，同样的 prompt 改动在 *Human-Only* 数据集上只让准确率偏移了约 7 个百分点，该数据集把新颖性证据较强与较弱的人类撰写想法配对。这表明，novelty judge 在人类撰写的研究上可能显得相对稳定，但在 AI 生成的想法上表现会大不相同。

话虽如此，人类撰写想法也并非不受影响。我们在 *Human-Only* 数据集上也看到了显著变化；同一改动让 Claude Opus 4.6 的准确率移动了 21 个点。只是这些变化没有 AI 生成想法上那么剧烈。

也不存在普适更好的 prompt。例如，在逐个判断想法时，删掉那条警告 judge 不要把琐碎或渐进式贡献视为新颖的指令，会提高某些 judge 的准确率，同时降低另一些 judge 的准确率。换句话说，对一个模型效果好的 prompt，未必能迁移到另一个模型。

我们还测试了 novelty judge 的一种常见用法：比较来自两个 AI 生成器的想法。我们把 Claude Opus 4.5 与 Claude Sonnet 4.5 的想法配对，把 GPT-5.4 与 GPT-5.1 的想法配对。在所测试的 prompt 改动中，六个 judge 平均约有四分之一到三分之一的判定发生了变化。这种分歧无需假设哪个生成器产出的想法更新颖就能测量出来，说明 judge prompt 的选择会如何影响不同 ideation 系统之间的比较。

更多的搜索与推理并不必然带来更好的新颖性判断。我们给 GPT-5.6 Sol 额外高的推理预算，并允许它进行限定在 arXiv 上的实时迭代搜索，然后把它与采用标准检索的 judge 对比，后者每个都看到五条预先检索好的摘要。（这一对比中的所有 judge 都在 *Human+Generated* 上对每个想法运行一次。）这个 agentic judge 得分 0.78 macro-F1——比 Claude Opus 4.6 的 0.89 低 11 个点，与更简单的 Claude Opus 4.5、GPT-5.4 设置大致处于同一区间——而按当前 API 价格，每次判定的成本约为其 10 倍。（在此语境下，macro-F1 衡量 judge 识别新颖与非新颖想法的能力；越高越好。）

专门打造的评测器也没有更准确，尽管成本高得多。在 *Human+Generated* 集上，一个简单的 Claude Opus 4.6 prompt，采用低推理并在三次调用间做多数投票，取得了 0.854 macro-F1，总评测成本 $2.59。作为对比，Idea Novelty Checker——一条基于文献的检索与重排序 pipeline——得分 0.642，成本 $30.66；而 Sakana AI 的 AI Scientist（其 novelty 评测器会迭代搜索 Semantic Scholar）得分 0.772，成本 $82.05。（两个专用评测器都使用 Claude Opus 4.6，每次判定一次调用。）

换句话说，这个简单的 prompt baseline 比两个专用系统都更准确，也便宜得多。

综合来看，这些结果表明，在这些系统越来越多被要求判断的 AI 生成想法上，新颖性评测尤其脆弱。

## 走向更可靠的新颖研究评测

我们的结果表明，基于 LLM 的新颖性评测仍是一个重大的开放问题。在人类撰写研究上显得可靠的 judge，在 AI 生成想法上可能表现不同；对一个模型有帮助的 prompt 可能损害另一个模型；更多的搜索或算力并不必然带来更一致的判断。

未来的工作应当在与 judge 实际要评估的想法同类的想法上测试它们，测量其对 prompt 与模型的敏感性，改进既有文献的引入方式，并构建能够随着科学文献增长与 AI 系统进步而演进的 benchmark。我们的 benchmark 与可复用的数据 pipeline 是一个起点——研究者可以把它们应用到新的同行评审、其他科学共同体，以及未来几代的 novelty judge。

自动化 ideation 不只取决于生成看似合理的研究方向；我们还需要能够判断这些想法何时真正新颖的方法。通过让当前 novelty judge 的弱点更容易被测量，我们希望这次发布能帮助研究者构建更稳健的方法来评估 AI 生成的研究想法。
