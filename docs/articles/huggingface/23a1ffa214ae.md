## 0. 选择合适的模型

在我们开始构建应用之前，先聊聊哪些模型在移动设备上表现良好，以及选择时要考虑什么。

### 模型大小考量

在移动设备上运行 LLM 时，大小非常关键：

- **小模型（1-3B 参数）**：最适合大多数移动设备，性能良好、延迟最低
- **中模型（4-7B 参数）**：在较新的高端设备上表现不错，但在旧手机上可能会变慢
- **大模型（8B+ 参数）**：对大多数移动设备通常太耗资源，但如果量化为 Q2_K 或 Q4_K_M 这类低精度格式也能用

### GGUF 量化格式

下载 GGUF 模型时，你会遇到各种量化格式。理解它们有助于你在模型大小和性能之间找到正确的平衡：

#### 传统量化（Legacy Quants，Q4_0、Q4_1、Q8_0）

- 基础、直白的量化方法
- 每个 block 存储：
 • 量化值（压缩后的权重）。
 • 一个（_0）或两个（_1）缩放常数。
- 快，但不如新方法高效 => 已不再广泛使用

#### K-Quant（Q3_K_S、Q5_K_M 等）

- 在这个 [PR](https://github.com/ggml-org/llama.cpp/pull/1684) 中引入
- 比传统量化更聪明的位分配
- "K-quants" 里的 K 指的是一种混合量化格式，意味着有些层会获得更多位以提升精度。
- _XS、_S、_M 这类后缀指特定的量化组合（越小 = 压缩越多），例如：
• Q3_K_S 对所有张量使用 Q3_K
• Q3_K_M 对 attention.wv、attention.wo 和 feed_forward.w2 张量使用 Q4_K，其余用 Q3_K。
• Q3_K_L 对 attention.wv、attention.wo 和 feed_forward.w2 张量使用 Q5_K，其余用 Q5_K。

#### I-Quant（IQ2_XXS、IQ3_S 等）

- 它仍使用基于 block 的量化，但带一些受 QuIP 启发新特性
- 文件更小，但在某些硬件上可能更慢
- 最适合算力较强但内存有限的设备

## 1. 搭建你的环境

React Native 是一个用 JavaScript 和 React 构建移动应用的流行框架。它让开发者创建能在 Android 和 iOS 平台上运行的应用，同时共享大量代码，从而加快开发、减少维护。

在你能用 React Native 开始写代码之前，需要正确地搭建环境。

### 你需要的工具

- **Node.js：** Node.js 是一个 JavaScript 运行时，让你能运行 JavaScript 代码。它对管理 React Native 项目里的包和依赖至关重要。你可以从 [Node.js downloads](https://nodejs.org/en/download) 安装。
- **react-native-community/cli：** 这个命令安装 React Native 命令行界面（CLI），它提供创建、构建和管理 React Native 项目的工具。运行以下命令安装它：

```
npm i @react-native-community/cli
```

### 虚拟设备设置

要在开发期间运行你的应用，你需要一个模拟器（emulator）或仿真器（simulator）：

- **如果你在 macOS 上：**  iOS：安装 Xcode -> 打开 Developer Tools -> Simulator [![alt text](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/llm-inferencen-on-edge/xcode_simulator.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/llm-inferencen-on-edge/xcode_simulator.png) Android：安装 Java Runtime 和 Android Studio -> 进入 Device Manager 并创建一个 emulator [![alt text](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/llm-inferencen-on-edge/android.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/llm-inferencen-on-edge/android.png)

### 项目结构

应用文件夹组织如下：

#### 默认文件/文件夹

- `android/`  含原生 Android 项目文件 **用途**：在 Android 设备上构建和运行应用
- `ios/`  含原生 iOS 项目文件 **用途**：在 iOS 设备上构建和运行应用
- `node_modules/`  **用途**：存放项目用到的所有 npm 依赖
- `App.tsx`  应用的主根组件，用 TypeScript 编写 **用途**：应用 UI 和逻辑的入口
- `index.js`  注册根组件（`App`） **用途**：React Native 运行时的入口。你不需要修改这个文件。

附加配置文件

- `tsconfig.json`：配置 TypeScript 设置
- `babel.config.js`：配置 Babel 用于转译现代 JavaScript/TypeScript，意味着它会把现代 JS/TS 代码转换成兼容旧浏览器或旧设备的旧 JS/TS 代码。
- `jest.config.js`：配置 Jest 用于测试 React Native 组件和逻辑。
- `metro.config.js`：为项目自定义 Metro 打包器。它是一个专为 React Native 设计的 JavaScript 打包器。它把项目的 JavaScript 和资源打包成单个文件（或多个文件以便高效加载），并在开发期间提供给应用。Metro 针对快速增量构建做了优化，支持热重载，并处理 React Native 的平台专属文件（.ios.js 或 .android.js）。
- `.watchmanconfig`：配置 Watchman，React Native 用于热重载的文件监听服务。

### 从 Hub 获取可用的 GGUF 模型

我们先定义应用将要支持的模型格式及其仓库。当然，`llama.rn` 是 `llama.cpp` 的绑定，所以我们需要加载 `GGUF` 文件。要为我们想支持的模型找到 GGUF 仓库，可以用 [Hugging Face](https://huggingface.co/) 上的搜索栏搜索某个特定模型的 `GGUF` 文件，或者用[这里](https://github.com/MekkCyber/EdgeLLM/blob/main/quantize_gguf.py)提供的脚本 `quantize_gguf.py` 自己量化模型，并把文件上传到我们的 hub 仓库。

```
const modelFormats = [
  {label: 'Llama-3.2-1B-Instruct'},
  {label: 'Qwen2-0.5B-Instruct'},
  {label: 'DeepSeek-R1-Distill-Qwen-1.5B'},
  {label: 'SmolLM2-1.7B-Instruct'},

const HF_TO_GGUF = {
    "Llama-3.2-1B-Instruct": "medmekk/Llama-3.2-1B-Instruct.GGUF",
    "DeepSeek-R1-Distill-Qwen-1.5B":
      "medmekk/DeepSeek-R1-Distill-Qwen-1.5B.GGUF",
    "Qwen2-0.5B-Instruct": "medmekk/Qwen2.5-0.5B-Instruct.GGUF",
    "SmolLM2-1.7B-Instruct": "medmekk/SmolLM2-1.7B-Instruct.GGUF",
```

`HF_TO_GGUF` 对象把用户友好的模型名映射到对应的 Hugging Face 仓库路径。例如：

- 当用户选择 'Llama-3.2-1B-Instruct'，它映射到 [`medmekk/Llama-3.2-1B-Instruct.GGUF`](https://huggingface.co/medmekk/Llama-3.2-1B-Instruct-GGUF)，那是含 Llama 3.2 1B Instruct 模型 GGUF 文件的仓库之一。

`modelFormats` 数组包含在选择界面展示给用户的模型选项列表，我们选了 [Llama 3.2 1B Instruct](https://huggingface.co/meta-llama/Llama-3.2-1B)、[DeepSeek R1 Distill Qwen 1.5B](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B)、[Qwen 2 0.5B Instruct](https://huggingface.co/Qwen/Qwen2-0.5B-Instruct) 和 [SmolLM2 1.7B Instruct](https://huggingface.co/HuggingFaceTB/SmolLM2-1.7B-Instruct)，因为它们是最流行的小模型。

接下来，我们创建一种方式，为我们选定的模型格式从 hub 获取并展示可用的 GGUF 模型文件。

当用户选择一个模型格式时，我们用我们在 `HF_TO_GGUF` 对象里映射的仓库路径向 Hugging Face 发起 API 调用。我们专门查找以 '.gguf' 扩展名结尾的文件，那是我们的量化模型文件。

一旦收到响应，我们只提取这些 GGUF 文件的文件名，用 `setAvailableGGUFs` 存进 `availableGGUFs` 状态。这让我们能向用户展示一个他们可下载的 GGUF 模型变体列表。

获取可用的 GGUF 文件

```
const fetchAvailableGGUFs = async (modelFormat: string) => {
  if (!modelFormat) {
    Alert.alert('Error', 'Please select a model format first.');
    return;
  }

  try {
    const repoPath = HF_TO_GGUF[modelFormat as keyof typeof HF_TO_GGUF];
    if (!repoPath) {
      throw new Error(
        `No repository mapping found for model format: ${modelFormat}`,
      );
    }

    const response = await axios.get(
      `https://huggingface.co/api/models/${repoPath}`,
    );

    if (!response.data?.siblings) {
      throw new Error('Invalid API response format');
    }

    const files = response.data.siblings.filter((file: {rfilename: string}) =>
      file.rfilename.endsWith('.gguf'),
    );

    setAvailableGGUFs(files.map((file: {rfilename: string}) => file.rfilename));
  } catch (error) {
    const errorMessage =
      error instanceof Error ? error.message : 'Failed to fetch .gguf files';
    Alert.alert('Error', errorMessage);
    setAvailableGGUFs([]);
  }
};
```

> 注意：如果还没导入，确保在文件顶部导入 axios 和 Alert。

我们需要测试这个函数是否工作正常，往 UI 加一个按钮来触发这个函数，用 `SafeAreaView`（后面详述）组件替代 `View`，并会在一个 `ScrollView` 组件里展示可用的 GGUF 文件。`onPress` 函数在按钮被按下时触发：

### 模型下载实现

现在我们在 `handleDownloadModel` 函数里实现模型下载功能，它应在用户点击下载按钮时被调用。这会从 Hugging Face 下载选定的 GGUF 文件并存到应用的 Documents 目录：

模型下载函数

```
const handleDownloadModel = async (file: string) => {
  const downloadUrl = `https://huggingface.co/${
    HF_TO_GGUF[selectedModelFormat as keyof typeof HF_TO_GGUF]
  }/resolve/main/${file}`;
  // we set the isDownloading state to true to show the progress bar and set the progress to 0
  setIsDownloading(true);
  setProgress(0);

  try {
    // we download the model using the downloadModel function, it takes the selected GGUF file, the download URL, and a progress callback function to update the progress bar
    const destPath = await downloadModel(file, downloadUrl, progress =>
      setProgress(progress),
    );
  } catch (error) {
    const errorMessage =
      error instanceof Error
        ? error.message
        : 'Download failed due to an unknown error.';
    Alert.alert('Error', errorMessage);
  } finally {
    setIsDownloading(false);
  }
};
```

我们本可以把 `api` 请求实现在 `handleDownloadModel` 函数内部，但我们把它放在单独的文件里以保持代码整洁可读。`handleDownloadModel` 调用位于 `src/api` 的 `downloadModel` 函数，它接受三个参数：`modelName`、`downloadUrl` 和一个 `progress` 回调函数。这个回调在下载过程中被触发以更新进度。在下载之前，我们需要把 `selectedModelFormat` 状态设为我们想下载的模型格式。

在 `downloadModel` 函数内部，我们使用 `RNFS` 模块（`react-native-fs` 库的一部分）来访问设备的文件系统。它让开发者能读取、写入和管理设备存储上的文件。这里，模型用 `RNFS.DocumentDirectoryPath` 存到应用的 Documents 文件夹，确保下载的文件对应用可访问。进度条会相应更新以反映当前下载状态，进度条组件定义在 `components` 文件夹里。

```
import RNFS from 'react-native-fs'; // File system module

const loadModel = async (modelName: string) => {
  try {
    const destPath = `${RNFS.DocumentDirectoryPath}/${modelName}`;

    // Ensure the model file exists before attempting to load it
    const fileExists = await RNFS.exists(destPath);
    if (!fileExists) {
      Alert.alert('Error Loading Model', 'The model file does not exist.');
      return false;
    }

    if (context) {
      await releaseAllLlama();
      setContext(null);
      setConversation(INITIAL_CONVERSATION);
    }

    const llamaContext = await initLlama({
      model: destPath,
      use_mlock: true,
      n_ctx: 2048,
      n_gpu_layers: 1
    });
    console.log("llamaContext", llamaContext);
    setContext(llamaContext);
    return true;
  } catch (error) {
    Alert.alert('Error Loading Model', error instanceof Error ? error.message : 'An unknown error occurred.');
    return false;
  }
};
```

### 聊天实现

模型现已加载进我们的上下文，接下来可以实现对话逻辑。我们定义一个名为 `handleSendMessage` 的函数，当用户提交输入时被触发。这个函数会更新对话状态，并通过 `context.completion` 把更新后的对话发给模型。模型的响应随后被用来进一步更新对话，也就是说这个函数里对话会被更新两次。

聊天函数

```
const handleSendMessage = async () => {
  // Check if context is loaded and user input is valid
  if (!context) {
    Alert.alert('Model Not Loaded', 'Please load the model first.');
    return;
  }

  if (!userInput.trim()) {
    Alert.alert('Input Error', 'Please enter a message.');
    return;
  }

  const newConversation: Message[] = [
    // ... is a spread operator that spreads the previous conversation array to which we add the new user message
    ...conversation,
    {role: 'user', content: userInput},
  ];
  setIsGenerating(true);
  // Update conversation state and clear user input
  setConversation(newConversation);
  setUserInput('');

  try {
    // we define list the stop words for all the model formats
    const stopWords = [
      '</s>',
      '<|end|>',
      'user:',
      'assistant:',
      '<|im_end|>',
      '<|eot_id|>',
      '<|end▁of▁sentence|>',
      '<｜end▁of▁sentence｜>',
    ];
    // now that we have the new conversation with the user message, we can send it to the model
    const result = await context.completion({
      messages: newConversation,
      n_predict: 10000,
      stop: stopWords,
    });

    // Ensure the result has text before updating the conversation
    if (result && result.text) {
      setConversation(prev => [
        ...prev,
        {role: 'assistant', content: result.text.trim()},
      ]);
    } else {
      throw new Error('No response from the model.');
    }
  } catch (error) {
    // Handle errors during inference
    Alert.alert(
      'Error During Inference',
      error instanceof Error ? error.message : 'An unknown error occurred.',
    );
  } finally {
    setIsGenerating(false);
  }
};
```

### 其他功能

应用现在功能完整，你可以下载一个模型、选择一个 GGUF 文件、并和模型聊天，但用户体验不是最好。在 [`EdgeLLMPlus`](https://github.com/MekkCyber/EdgeLLM/tree/main/EdgeLLMPlus) 仓库里，我加了一些其他功能，比如即时生成、自动滚动、推理速度追踪、以及像 deepseek-qwen-1.5B 那样的模型思考过程……我们这里不展开细节，否则博客会太长，我们会过一遍其中一些想法和如何实现，完整代码在仓库里

#### 即时生成（Generation on the fly）

应用逐个 token 增量地生成响应，而非一次性给出整个响应。这提升了用户体验，让用户可以在响应成形时就开始阅读。我们通过 `context.completion` 里的一个 `callback` 函数实现，它在每个 token 生成后被触发，使我们能相应地更新 `conversation` 状态。

#### 自动滚动

自动滚动确保最新的消息或 token 始终对用户可见——在新内容加入时自动把聊天视图滚到底部。要实现它，我们用一个对 `ScrollView` 的引用以便编程控制滚动位置，并在有新消息加入 `conversation` 状态时用 `scrollToEnd` 方法把 `ScrollView` 滚到底部。我们还定义一个 `autoScrollEnabled` 状态变量，当用户从 `ScrollView` 底部往上滚动超过 100px 时设为 false。

#### 推理速度追踪

推理速度追踪会记录生成每个 token 所花的时间，并显示在模型生成的每条消息下面。这个功能容易实现，因为 `context.completion` 函数返回的 `CompletionResult` 对象含有一个 `timings` 属性，它是一个字典，包含关于推理过程的许多指标。我们可以用 `predicted_per_second` 指标来追踪模型的速度。

#### 思考过程

思考过程是一个像 deepseek-qwen-1.5B 那样展示模型思考过程的功能。应用识别特殊 token 并据此处理模型的内部推理或"思考"。当遇到某个 token 时，应用进入一个"思考块"，在其中累积代表模型推理的 token。一旦检测到结束 token，累积的思考就被提取并关联到该消息，让用户可以切换模型推理的可见性。要实现它，我们需要给 `Message` 类型加一个 `thought` 和一个 `showThought` 属性。`message.thought` 存储模型的推理，`message.showThought` 是一个布尔，当用户点击消息以切换思考的可见性时被设为 true。

#### Markdown 渲染

应用使用 `react-native-markdown-display` 包来渲染对话里的 markdown。这个包让我们能以更好的格式渲染代码。

#### 模型管理

我们在 `App.tsx` 文件里加了一个 `checkDownloadedModels` 函数，检查模型是否已下载到设备上，如果没下载我们就下载它，如果已下载就直接加载进上下文，并在 UI 里加一些元素来显示一个模型是否已下载。

#### 停止/返回按钮

我们在 UI 里加了两个重要按钮：停止按钮和返回按钮。停止按钮会停止响应生成，返回按钮会导航到模型选择界面。为此，我们在 `App.tsx` 文件里加了一个 `handleStopGeneration` 函数，它通过调用 `context.stop` 停止响应生成并把 `isGenerating` 状态设为 false。我们还在 `App.tsx` 文件里加了一个 `handleBack` 函数，通过把 `currentPage` 状态设为 `modelSelection` 导航到模型选择界面。

- 在 Metro 打包器终端里按 `j` 启动 Chrome DevTools
- 导航到 "Sources" 标签

[![alt text](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/llm-inferencen-on-edge/dev_tools.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/llm-inferencen-on-edge/dev_tools.png) 3. 找到你的源文件
4. 点击行号设置断点
5. 使用调试控件（右上角）：

- Step Over - 执行当前行
- Step Into - 进入函数调用
- Step Out - 退出当前函数
- Continue - 运行到下一个断点
