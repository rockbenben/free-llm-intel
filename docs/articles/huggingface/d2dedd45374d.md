Llama 3.1 发布了！今天我们欢迎 Llama 家族的新一轮迭代入驻 Hugging Face。我们与 Meta 密切合作，确保它在 Hugging Face 生态中有最好的集成。Hub 上共提供八个开放权重模型（3 个基础模型和 5 个微调模型）。

Llama 3.1 有三个尺寸：8B 适合消费级 GPU 上的高效部署与开发；70B 适合大规模 AI 原生应用；405B 适合合成数据、LLM as a Judge（大模型当评委）或蒸馏。三种尺寸都有 base 和 instruction-tuned 两个版本。

除了六个生成式模型，Meta 还发布了两个新模型：Llama Guard 3 和 Prompt Guard。Prompt Guard 是一个小型分类器，用于检测提示注入（prompt injection）和越狱（jailbreak）。Llama Guard 3 是一个安全防护模型，可以对 LLM 的输入和生成内容进行分类。

## Llama 3.1 有什么新东西？

Llama 3.1 为什么这么令人兴奋？在前代模型能力之上，Llama 3.1 带来几个关键新特性：

- 上下文长度达到 128K token（原来只有 8K）
- 多语言能力
- 工具使用能力
- 参数量高达 4050 亿的超大稠密模型
- 更宽松的许可证

我们逐条来看！

Llama 3.1 发布了六个基于 Llama 3 架构的新开源 LLM，分三个尺寸：8B、70B、405B，每个尺寸都有 base（预训练）和 instruct 微调版本。所有变体都支持 **128K token** 上下文和 8 种语言，包括英语、德语、法语、意大利语、葡萄牙语、印地语、西班牙语和泰语。Llama 3.1 继续使用分组查询注意力（Grouped-Query Attention, GQA），这是一种高效表示方式，对更长上下文有帮助。

- [Meta-Llama-3.1-8B](https://huggingface.co/meta-llama/Meta-Llama-3.1-8B)：8B 基础模型
- [Meta-Llama-3.1-8B-Instruct](https://huggingface.co/meta-llama/Meta-Llama-3.1-8B-Instruct)：8B 基础模型的 Instruct 微调版
- [Meta-Llama-3.1-70B](https://huggingface.co/meta-llama/Meta-Llama-3.1-70B)：70B 基础模型
- [Meta-Llama-3.1-70B-Instruct](https://huggingface.co/meta-llama/Meta-Llama-3.1-70B-Instruct)：70B 基础模型的 Instruct 微调版
- [Meta-Llama-3.1-405B](https://huggingface.co/meta-llama/Meta-Llama-3.1-405B)：405B 基础模型
- [Meta-Llama-3.1-405B-Instruct](https://huggingface.co/meta-llama/Meta-Llama-3.1-405B-Instruct)：405B 基础模型的 Instruct 微调版

除这 6 个语言模型外，还发布了 Llama Guard 3 和 Prompt Guard。

- [Llama Guard 3](https://huggingface.co/meta-llama/Llama-Guard-3-8B) 是 Llama Guard 家族的最新一代，基于 Llama 3.1 8B 微调而来。它为生产场景打造，支持 128k 上下文和多语言。Llama Guard 3 可以对 LLM 的输入（提示）和回复分类，按照风险分类体系检测不安全内容。
- [Prompt Guard](https://huggingface.co/meta-llama/Prompt-Guard-86M) 则是一个 279M 参数、基于 BERT 的小型分类器，可以检测提示注入和越狱。它在大规模攻击语料上训练，官方建议再结合应用特定数据做微调。

与 Llama 3 相比，Llama 3.1 的新变化是 instruct 模型针对智能体（agentic）场景在工具调用上做了微调。内置两个工具（搜索、基于 Wolfram Alpha 的数学推理），并可通过自定义 JSON 函数扩展。

Llama 3.1 模型在自建 GPU 集群上用超过 15 万亿 token 训练，共消耗 3930 万 GPU 小时（8B 用 146 万，70B 用 700 万，405B 用 3084 万）。训练数据集的具体混合比例不得而知，我们只能猜测为了多语言能力做了更多样化的筛选。Llama 3.1 Instruct 针对指令跟随做了优化，训练数据来自公开指令数据集，以及 2500 万条合成生成样本，使用监督微调（SFT）和人类反馈强化学习（RLHF）。在构建数据混合时，Meta 开发了基于 LLM 的分类器来筛选高质量提示和回复。

许可证方面，Llama 3.1 的条款与之前非常相似，但有一个关键区别：**允许使用模型输出去改进其他 LLM**。也就是说，可以用 Llama 3.1 生成合成数据、做蒸馏，哪怕目标是不同的模型！这对 405B 模型尤为重要，后面会详谈。许可证允许再分发、微调和创建衍生作品，仍要求衍生模型名称以 "Llama" 开头，且任何衍生作品或服务须注明 "Built with Llama"。完整细节请阅读[官方许可证](https://huggingface.co/meta-llama/Meta-Llama-3.1-8B-Instruct/blob/main/LICENSE)。

## Llama 3.1 需要多少内存？

Llama 3.1 带来了令人振奋的进步，但运行它需要认真考虑硬件资源。下面按三个尺寸分别拆解训练和推理的内存需求。

### 推理内存需求

推理的内存需求取决于模型尺寸和权重精度。下表列出各配置的大致所需内存：

| **模型尺寸** | **FP16** | **FP8** | **INT4** |
| --- | --- | --- | --- |
| 8B | 16 GB | 8 GB | 4 GB |
| 70B | 140 GB | 70 GB | 35 GB |
| 405B | 810 GB | 405 GB | 203 GB |

*注：以上数字仅指加载模型 checkpoint 所需的 GPU VRAM，不包含 torch 为 kernel 或 CUDA graph 预留的空间。*

举例来说，一个 H100 节点（8 卡 H100）约有 640GB VRAM，所以 405B 模型需要多节点部署，或者用更低精度（如 FP8）运行——后者是推荐做法。

同时记住，更低精度（如 INT4）可能损失一些精度，但能显著降低内存需求、提升推理速度。除模型权重外，KV 缓存也要占内存：它保存上下文中所有 token 的键和值，这样生成新 token 时不必重新计算。尤其当用满 128K 这样长的上下文时，KV 缓存会成为一大开销。FP16 下 KV 缓存的内存需求如下：

| **模型尺寸** | **1k token** | **16k token** | **128k token** |
| --- | --- | --- | --- |
| 8B | 0.125 GB | 1.95 GB | 15.62 GB |
| 70B | 0.313 GB | 4.88 GB | 39.06 GB |
| 405B | 0.984 GB | 15.38 | 123.05 GB |

对小模型来说，接近上下文长度上限时，KV 缓存占的内存几乎和权重一样多。

### 训练内存需求

下表列出用不同技术训练 Llama 3.1 模型的大致内存需求：

| **模型尺寸** | **全量微调** | **LoRA** | **Q-LoRA** |
| --- | --- | --- | --- |
| 8B | 60 GB | 16 GB | 6 GB |
| 70B | 500 GB | 160 GB | 48 GB |
| 405B | 3.25 TB | 950 GB | 250 GB |

*注：这些是估算值，实际会因具体实现细节和优化而不同。*

## 使用 Hugging Face Transformers

Llama 3.1 需要模型代码做一处小更新，以便有效处理 RoPE scaling。使用 Transformers [4.43.2 版本](https://github.com/huggingface/transformers/releases/tag/v4.43.2)，你就可以使用新的 Llama 3.1 模型并调用 Hugging Face 生态的全部工具。请确保使用最新的 `transformers`：

```
pip install "transformers>=4.43.2" --upgrade
```

几个要点：

- Transformers 默认以 bfloat16 加载模型。Meta 发布的原始 checkpoint 用的就是这种类型，所以这是确保最佳精度或做评测时的推荐方式。
- Assistant 的回复可能以特殊 token `<|eot_id|>` 结尾，但遇到普通 EOS token 时也必须停止生成。可以通过在 `eos_token_id` 参数里传入一组终止符来提前停止。
- 我们采用了 Meta 原始代码库里的默认采样参数（`temperature` 和 `top_p`）。我们还没来得及做大量测试，欢迎自行探索！

下面这段代码演示如何使用 `meta-llama/Meta-Llama-3.1-8B-Instruct`，大约需要 16 GB VRAM，很多消费级 GPU 都能装下。同样的代码也适用于 `meta-llama/Meta-Llama-3.1-70B-Instruct`（140GB VRAM）和 `meta-llama/Meta-Llama-3.1-405B-Instruct`（需要 810GB VRAM），对生产场景很有吸引力。以 8-bit 或 4-bit 模式加载还可以进一步降低内存占用。

```
from transformers import pipeline
import torch

model_id = "meta-llama/Meta-Llama-3.1-8B-Instruct"
pipe = pipeline(
    "text-generation",
    model=model_id,
    model_kwargs={"torch_dtype": torch.bfloat16},
    device="cuda",
)

messages = [
    {"role": "user", "content": "Who are you? Please, answer in pirate-speak."},
]
outputs = pipe(
    messages,
    max_new_tokens=256,
    do_sample=False,
)
assistant_response = outputs[0]["generated_text"][-1]["content"]
print(assistant_response)
# Arrrr, me hearty! Yer lookin' fer a bit o' information about meself, eh? Alright then, matey! I be a language-generatin' swashbuckler, a digital buccaneer with a penchant fer spinnin' words into gold doubloons o' knowledge! Me name be... (dramatic pause)...Assistant! Aye, that be me name, and I be here to help ye navigate the seven seas o' questions and find the hidden treasure o' answers! So hoist the sails and set course fer adventure, me hearty! What be yer first question?
```

也可以自动量化模型，以 8-bit 甚至 bitsandbytes 的 4-bit 模式加载。70B 版本的 4-bit 加载大约只需 34 GB 内存。4-bit 加载生成 pipeline 的方式如下：

```
pipeline = pipeline(
    "text-generation",
    model=model_id,
    model_kwargs={
        "torch_dtype": torch.bfloat16,
        "quantization_config": {"load_in_4bit": True}
    },
)
```

使用 `transformers` 的更多细节请查看[模型卡](https://huggingface.co/meta-llama/Meta-Llama-3.1-8B-Instruct)。

*注：Transformers 会处理好所有烦人的提示模板问题。想更深入了解提示格式，请看下一节。*

## 如何给 Llama 3.1 写提示

基础模型没有提示格式。和其他基础模型一样，它们可以用来对输入序列做合理的续写，或用于 zero-shot/few-shot 推理，也是微调到你自己场景的绝佳底座。

Instruct 版本支持包含 4 种角色的对话格式：

- **system：** 设定对话背景，可以放入规则、指南或有效回复所需的必要信息，也在适合时用于启用工具使用。
- **user：** 用户的输入、命令和问题。
- **assistant：** 助手基于 'system' 和 'user' 提示提供的上下文做出的回复。
- **ipython：** Llama 3.1 引入的新角色，用于表示工具调用的输出，回传给 LLM。

Instruct 版本在简单对话中使用如下结构：

```
<|begin_of_text|><|start_header_id|>system<|end_header_id|>

{{ system_prompt }}<|eot_id|><|start_header_id|>user<|end_header_id|>

{{ user_msg_1 }}<|eot_id|><|start_header_id|>assistant<|end_header_id|>

{{ model_answer_1 }}<|eot_id|>
```

Llama 3.1 Instruct 模型现在支持工具调用，包括三个内置工具（brave_search、wolfram_alpha、code_interpreter），也支持通过 JSON 函数调用实现自定义工具。内置工具使用 Python 语法。模型能输出 Python 代码来调用函数，这本身就是代码解释器工具的一部分，需通过系统提示里的 `Environment` 关键字启用，如下所示。

### 内置 Tool calling

加入 "Environment: ipython" 会开启代码解释器模式，模型可以生成它预期会被执行的 Python 代码。此时 assistant 回复的消息正文以特殊标签 `<|python_tag|>` 开头，并以 `<|eom_id|>`（而非标准的 `<|eot_id|>`）结尾。后者表示本轮结束，前者表示多步推理还在继续。

内置工具调用示例

```
<|begin_of_text|><|start_header_id|>system<|end_header_id|>


Environment: ipython
Tools: brave_search, wolfram_alpha

Cutting Knowledge Date: 01 March 2023
Today's Date: 13 July 2024


You are a helpful Assistant.<|eot_id|><|start_header_id|>user<|end_header_id|>

Weather in Menlo Park, California<|eot_id|><|start_header_id|>assistant<|end_header_id|>
```

此时模型的回复会是调用某个受支持工具（这里是 `brave_search`）的 Python 代码：

```
<|python_tag|>brave_search.call(query="current weather in Menlo Park, California")<|eom_id|>
```

然后把执行调用的结果发回模型，得到最终回复。为简洁起见，在上一条消息后追加的内容如下：

```
<|python_tag|>brave_search.call(query="Menlo Park California weather")<|eom_id|><|start_header_id|>ipython<|end_header_id|>

{"query": "Menlo Park California weather", "top_k": [{"title": "10-Day Weather Forecast for West Menlo Park, CA - The Weather Channel | weather.com", "url": "https://weather.com/weather/tenday/l/West+Menlo+Park+CA?canonicalCityId=b2375713aa1943aad7d1a13a85e1c0adad13c1b10563b2bbaad70734dc61cf11", "description": "Be prepared with the most accurate 10-day forecast for West <strong>Menlo</strong> <strong>Park</strong>, CA with highs, lows, chance of precipitation from The <strong>Weather</strong> Channel and <strong>Weather</strong>.com", "type": "search_result"},....}<|eot_id|><|start_header_id|>assistant<|end_header_id|>
```

LLM 的最终回复就是：

```
The current weather in Menlo Park, California is mostly sunny with a high of 77°F and a low of 56°F.<|eot_id|>
```

## 自定义 Tool calling

Llama 3.1 Instruct 支持从单条用户消息触发自定义函数调用。下面的提示展示了一个例子：如何从模型输出去调用自定义函数。在自定义函数调用中，模型输出 `<|eot_id|>` 而不是 `<|eom_id|>`。需要调整系统提示，告诉模型如何处理函数调用的输出。

自定义 Tool calling JSON 函数

```
<|begin_of_text|><|start_header_id|>system<|end_header_id|>

You are a helpful assistant with tool calling capabilities. When you receive a tool call response, use the output to format an answer to the orginal user question.<|eot_id|><|start_header_id|>user<|end_header_id|>

Given the following functions, please respond with a JSON for a function call with its proper arguments that best answers the given prompt.

Respond in the format {"name": function name, "parameters": dictionary of argument name and its value}. Do not use variables.

{
    "type": "function",
    "function": {
    "name": "get_current_conditions",
    "description": "Get the current weather conditions for a specific location",
    "parameters": {
        "type": "object",
        "properties": {
        "location": {
            "type": "string",
            "description": "The city and state, e.g., San Francisco, CA"
        },
        "unit": {
            "type": "string",
            "enum": ["Celsius", "Fahrenheit"],
            "description": "The temperature unit to use. Infer this from the user's location."
        }
        },
        "required": ["location", "unit"]
    }
    }
}

Question: what is the weather like in Menlo Park?<|eot_id|><|start_header_id|>assitant<|end_header_id|>

{"name": "get_current_conditions", "parameters": {"location": "Menlo Park, CA", "unit": "Fahrenheit"}}<|eot_id|><|start_header_id|>ipython<|end_header_id|>
```

拿到所选工具的输出后，我们用同样的 `<|python_tag|>` 分隔符把它传回模型。`<|python_tag|>` 并不意味着一定使用 Python，它只是用来标记任意工具输出的开始。

```
<|python_tag|>{
    "tool_call_id": "get_current_conditions"
    "output": "Clouds giving way to sun Hi: 76° Tonight: Mainly clear early, then areas of low clouds forming Lo: 56°"
}<|eot_id|><|start_header_id|>assistant<|end_header_id|>

The weather in Menlo Park is currently cloudy with a high of 76° and a low of 56°, with clear skies expected tonight.<|eot_id|>
```

要有效使用这套格式，必须一字不差地复现它。transformers 里提供的聊天模板（chat template）可以自动完成正确的提示格式化。

## Llama 3.1 405B 的 FP8、AWQ 与 GPTQ 量化

Meta 发布了[官方 FP8 量化版 Llama 3.1 405B](https://huggingface.co/meta-llama/Meta-Llama-3.1-405B-Instruct-FP8)，精度损失极小。做法是只对模型的主要线性算子做 FP8 量化，即 gate、up 和 down 投影以及 FFN（覆盖 75% 的推理 FLOPs）。我们共同确保了这份 FP8 checkpoint 在社区生态（transformers、TGI、VLLM）中可互通使用。

此外，我们还分别用 AutoAWQ 和 AutoGPTQ 制作了 INT4 的 AWQ 与 GPTQ 量化版本。AWQ 对所有线性层使用 GEMM kernel 量化，做零点量化、压到 4 bit、group size 为 128；GPTQ 用同样的设置，只是换成 GPTQ kernel。我们确保了这些 INT4 checkpoint 与 transformers 和 TGI 兼容，包括 TGI 中用 Marlin kernel 加速 GPTQ 量化模型推理的支持。

Llama 3.1 405B 可用的量化权重：

- [meta-llama/Meta-Llama-3.1-405B-Base-FP8](https://huggingface.co/meta-llama/Meta-Llama-3.1-405B-FP8)：官方 FP8 量化权重，可在 8xH100 上运行
- [meta-llama/Meta-Llama-3.1-405B-Instruct-FP8](https://huggingface.co/sllhf/Meta-Llama-3.1-405B-Instruct-FP8)：官方 FP8 量化权重，可在 8xH100 上运行
- [hugging-quants/Meta-Llama-3.1-405B-Instruct-AWQ-INT4](https://huggingface.co/hugging-quants/Meta-Llama-3.1-405B-Instruct-AWQ-INT4)：Hugging Face 量化权重，可在 8xA100 80GB、8xH100 80GB 及 8xA100 40GB（需缩减 KV-cache 且不能用 CUDA graph）上运行
- [hugging-quants/Meta-Llama-3.1-405B-Instruct-GPTQ-INT4:](https://huggingface.co/hugging-quants/Meta-Llama-3.1-405B-Instruct-GPTQ-INT4) Hugging Face 量化权重，可在 8xA100 80GB、8xH100 80GB 及 8xA100 40GB（需缩减 KV-cache 且不能用 CUDA graph）上运行
- [hugging-quants/Meta-Llama-3.1-405B-BNB-NF4](https://huggingface.co/hugging-quants/Meta-Llama-3.1-405B-BNB-NF4)：Hugging Face 量化权重，适合 QLoRA 微调
- [hugging-quants/Meta-Llama-3.1-405B-Instruct-BNB-NF4](https://huggingface.co/hugging-quants/Meta-Llama-3.1-405B-Instruct-BNB-NF4)：Hugging Face 量化权重，适合在 8xA100 或 4xH100 上做推理

[Hugging Quants 组织](https://huggingface.co/hugging-quants)下还有 70B 和 8B 版本的量化 checkpoint。

## 推理集成

### Hugging Face Inference API

[现在 Hugging Face PRO 用户可以访问专属 API 端点](https://huggingface.co/blog/inference-pro)，托管由 [text-generation-inference](https://github.com/huggingface/text-generation-inference) 驱动的 Llama 3.1 8B Instruct、Llama 3.1 70B Instruct 和 Llama 3.1 405B Instruct AWQ。所有版本都支持 Messages API，因此兼容 OpenAI 客户端库，包括 LangChain 和 LlamaIndex。

*注：请用 `pip install "huggingface_hub>=0.24.1` 升级到最新的 `huggingface_hub` 版本。*

```
from huggingface_hub import InferenceClient

# Initialize the client, pointing it to one of the available models
client = InferenceClient()

chat_completion = client.chat.completions.create(
    model="meta-llama/Meta-Llama-3.1-405B-Instruct-FP8",
    messages=[
        {"role": "system", "content": "You are a helpful an honest programming assistant."},
        {"role": "user", "content": "Is Rust better than Python?"},
    ],
    stream=True,
    max_tokens=500
)

# iterate and print stream
for message in chat_completion:
    print(message.choices[0].delta.content, end="")
```

Messages API 的更多细节请[查看这篇文章](https://huggingface.co/blog/tgi-messages-api)。

### Hugging Face Inference Endpoints

你可以把 Llama 3.1 部署到 Hugging Face 的 [Inference Endpoints](https://ui.endpoints.huggingface.co/)，后端使用 Text Generation Inference。[Text Generation Inference](https://github.com/huggingface/text-generation-inference) 是 Hugging Face 开发的生产级推理容器，支持 FP8、连续批处理、token 流式输出、多 GPU 张量并行加速推理。要部署 Llama 3.1，前往[模型页面](https://huggingface.co/meta-llama/Meta-Llama-3-70B-instruct)，点击 Deploy -> Inference Endpoints 组件即可：

- [Meta-Llama-3.1-8B-Instruct](https://huggingface.co/meta-llama/Meta-Llama-3.1-8B-Instruct)：推荐 1x NVIDIA A10G 或 L4 GPU
- [Meta-Llama-3.1-70B-Instruct](https://huggingface.co/meta-llama/Meta-Llama-3.1-70B-Instruct)：推荐 4x NVIDIA A100，或用 AWQ/GPTQ 量化后 2x A100
- [Meta-Llama-3.1-405B-Instruct-FP8](https://huggingface.co/sllhf/Meta-Llama-3.1-405B-Instruct-FP8)：推荐 8x NVIDIA H100（FP 精度），或用 [AWQ](https://huggingface.co/hugging-quants/Meta-Llama-3.1-405B-Instruct-AWQ-INT4)/[GPTQ](https://huggingface.co/hugging-quants/Meta-Llama-3.1-405B-Instruct-GPTQ-INT4) 量化后 8x A100


## 用 distilabel 生成合成数据

Llama 3.1 许可证的一大变化是允许使用模型输出去改进其他 LLM——也就是说，你可以用 Llama 3.1 生成合成数据集，再拿去微调更小、更专门的模型。

来看一个例子：如何用开源合成数据生成框架 [distilabel](https://github.com/argilla-io/distilabel) 生成偏好数据集。这个数据集可以用于 TRL 提供的偏好优化方法（如 DPO 或 KTO）来微调模型。

首先用 `pip` 安装最新的 `distilabel` 及 `hf-inference-endpoints` 附加组件：

```
pip install “distilabel[hf-inference-endpoints]” --upgrade
```

然后定义一个 pipeline：

- 从 Hugging Face Hub 加载带指令的数据集。
- 通过 Hugging Face Inference Endpoints 分别用 Llama 3.1 70B Instruct 和 Llama 3.1 405B Instruct 生成回复。
- 最后用 Llama 3.1 405B Instruct 当评委，按 UltraFeedback 提示给回复打分。根据评分挑选 chosen 和 rejected 回复，用于以偏好优化方法微调模型。

定义 pipeline 的代码见下方，也可以用这个 [Colab notebook](https://colab.research.google.com/drive/1o0ALge7DHBmcKgdyrk59yOL70tcGS3v4?usp=sharing) 直接运行，并在 Hub 上查看生成的数据集。

```
from distilabel.llms import InferenceEndpointsLLM
from distilabel.pipeline import Pipeline
from distilabel.steps import LoadDataFromHub, CombineColumns
from distilabel.steps.tasks import TextGeneration, UltraFeedback

llama70B = InferenceEndpointsLLM(
    model_id="meta-llama/Meta-Llama-3.1-70B-Instruct"
)
llama405B = InferenceEndpointsLLM(
    model_id="meta-llama/Meta-Llama-3.1-405B-Instruct-FP8"
)

with Pipeline(name="synthetic-data-with-llama3") as pipeline:
    # load dataset with prompts
    load_dataset = LoadDataFromHub(
        repo_id="argilla/10Kprompts-mini"
    )
    # generate two responses for each prompt
    generate = [
        TextGeneration(llm=llama70B),
        TextGeneration(llm=llama405B)
    ]
    # combine responses into one column
    combine = CombineColumns(
        columns=["generation", "model_name"],
        output_columns=["generations", "model_names"]
    )
    # rate responses with 405B LLM-as-a-judge
    rate = UltraFeedback(aspect="overall-rating", llm=llama405B)
    # define the pipeline
    load_dataset >> generate >> combine >> rate

if __name__ == "__main__":
    distiset = pipeline.run()
```

接下来还能做什么？除了上面的示例，`distilabel` 还为各种场景和主题提供了丰富的 LLM 合成数据生成方案，实现了当前 SOTA 文献中的多种做法：用 LLM-as-a-judge 方法评估输出、指令演化、数据过滤，以及自定义组件。
