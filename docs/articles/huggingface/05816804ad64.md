# 用 Intel Sapphire Rapids 加速 PyTorch Transformers——第 1 部分

大约一年前，我们[演示过](https://huggingface.co/blog/accelerating-pytorch)如何在集群或第三代 [Intel Xeon Scalable](https://www.intel.com/content/www/us/en/products/details/processors/xeon/scalable.html) CPU（即 Ice Lake）上分布式训练 Hugging Face transformers。最近，Intel 发布了第四代 Xeon CPU，代号 Sapphire Rapids，带来了加速深度学习模型常见操作的新指令。

本文将教你如何在 AWS 上运行的 Sapphire Rapids 服务器集群上加速 PyTorch 训练任务。我们用 [Intel oneAPI Collective Communications Library](https://www.intel.com/content/www/us/en/developer/tools/oneapi/oneccl.html)（CCL）做分布式，用 [Intel Extension for PyTorch](https://github.com/intel/intel-extension-for-pytorch)（IPEX）库自动用上新的 CPU 指令。由于这两个库都已与 Hugging Face transformers 库集成，我们的示例脚本可以开箱即用，一行代码都不用改。

在后续文章中，我们会看看 Sapphire Rapids CPU 上的推理及其带来的性能提升。

## 为什么值得考虑在 CPU 上训练

在 Intel Xeon CPU 上训练深度学习（DL）模型可以是一种兼具性价比与可扩展性的方案，尤其当你在中小数据集上使用分布式训练和微调这类技术时。

Xeon CPU 支持诸如高级向量扩展（[AVX-512](https://en.wikipedia.org/wiki/AVX-512)）和超线程等高级特性，有助于提升 DL 模型的并行度和效率，从而加快训练速度，并更好地利用硬件资源。

此外，与训练大型深度学习模型通常所需的专用硬件（如 GPU）相比，Xeon CPU 一般更便宜、更易获取。Xeon CPU 还很容易转作其他生产任务——从 Web 服务器到数据库——让它成为 IT 基础设施中多才多艺、灵活机动的一选。

最后，云用户还可以用竞价实例（spot instances）进一步压低 Xeon CPU 训练的成本。竞价实例由闲置计算能力构成，以折扣价出售，相比按需实例可节省大量成本，有时高达 90%。还有一点：CPU 竞价实例通常也比 GPU 实例更容易买到。

接下来看看 Sapphire Rapids 架构的新指令。

## 高级矩阵扩展：为深度学习而生的新指令

Sapphire Rapids 架构引入了 Intel 高级矩阵扩展（[AMX](https://en.wikipedia.org/wiki/Advanced_Matrix_Extensions)）来加速 DL 负载。使用它们就像安装最新版 IPEX 一样简单，你的 Hugging Face 代码不需要任何改动。

AMX 指令加速矩阵乘法——这是按数据批次训练 DL 模型的核心操作。它同时支持 Brain Floating Point（[BF16](https://en.wikipedia.org/wiki/Bfloat16_floating-point_format)）和 8 位整数（INT8），可为不同训练场景提供加速。

AMX 引入了新的二维 CPU 寄存器，称为 tile 寄存器。由于上下文切换时需要保存和恢复这些寄存器，它们需要内核支持：在 Linux 上，你需要 [v5.16](https://discourse.ubuntu.com/t/kinetic-kudu-release-notes/27976) 或更新版本。

接下来看看如何搭建一个 Sapphire Rapids CPU 集群做分布式训练。

## 搭建 Sapphire Rapids CPU 集群

写作本文时，上手 Sapphire Rapids 服务器最简单的方式是使用新的 Amazon EC2 [R7iz](https://aws.amazon.com/ec2/instance-types/r7iz/) 实例族。由于它还在预览阶段，你需要[注册](https://pages.awscloud.com/R7iz-Preview.html)获取访问权限。另外，虚拟机还不支持 AMX，所以我们要用裸金属实例（`r7iz.metal-16xl`，64 vCPU，512GB 内存）。

为了避免逐台手工配置集群节点，我们先配置好主节点，并从它创建一个新的 Amazon Machine Image（[AMI](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AMIs.html)），然后用这个 AMI 启动其余节点。

网络方面，我们需要以下设置：

- 对所有实例开放 22 端口用于 ssh 访问，以便配置和调试。
- 配置从主实例（启动训练的那台）到所有其他实例（包括主节点自身）的[免密 ssh](https://www.redhat.com/sysadmin/passwordless-ssh)。也就是说，主节点的 ssh 公钥必须在所有节点上被授权。
- 允许集群内部所有网络流量，让分布式训练畅通无阻。AWS 通过[安全组](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_SecurityGroups.html)提供了安全便捷的方式：只需创建一个允许来自同安全组实例全部流量的安全组，并确保把它绑定到集群中的所有实例。这是我的配置的样子。

开工，搭建集群的主节点。

## 配置主节点

首先，我们用一个 Ubunutu 20.04 AMI（`ami-07cd3e6c4915b2d18`）和刚才创建的安全组启动一台 `r7iz.metal-16xl` 实例作为主节点。这个 AMI 自带 Linux v5.15.0，但幸运的是 Intel 和 AWS 已经给内核打了补丁加上 AMX 支持，所以我们不需要升级到 v5.16。

实例启动后，我们 ssh 上去，用 `lscpu` 确认 AMX 确实受支持。你应该能在 flags 一节看到：

```
amx_bf16 amx_tile amx_int8
```

然后，安装系统和 Python 依赖。

```
sudo apt-get update 

# Install tcmalloc for extra performance (https://github.com/google/tcmalloc)
sudo apt install libgoogle-perftools-dev -y

# Create a virtual environment
sudo apt-get install python3-pip -y
pip install pip --upgrade
export PATH=/home/ubuntu/.local/bin:$PATH
pip install virtualenv

# Activate the virtual environment
virtualenv cluster_env
source cluster_env/bin/activate

# Install PyTorch, IPEX, CCL and Transformers
pip3 install torch==1.13.0 -f https://download.pytorch.org/whl/cpu
pip3 install intel_extension_for_pytorch==1.13.0 -f https://developer.intel.com/ipex-whl-stable-cpu
pip3 install oneccl_bind_pt==1.13 -f https://developer.intel.com/ipex-whl-stable-cpu
pip3 install transformers==4.24.0

# Clone the transformers repository for its example scripts
git clone https://github.com/huggingface/transformers.git
cd transformers
git checkout v4.24.0
```

接着，用 `ssh-keygen` 创建一对名为 'cluster' 的新 ssh 密钥，存到默认位置（`~/.ssh`）。

最后，从这台实例[创建一个新的 AMI](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/creating-an-ami-ebs.html)。

## 搭建集群

AMI 就绪后，我们用它在启动 3 台额外的 `r7iz.16xlarge-metal` 实例，别忘了绑定之前创建的安全组。

在这些实例启动期间，我们先 ssh 到主节点完成网络配置。首先编辑 `~/.ssh/config` 中的 ssh 配置文件，使用各节点的私有 IP 地址和刚创建的密钥对，启用从主节点到其他所有节点的免密连接。我的文件如下。

```
Host 172.31.*.*
   StrictHostKeyChecking no

Host node1
    HostName 172.31.10.251
    User ubuntu
    IdentityFile ~/.ssh/cluster

Host node2
    HostName 172.31.10.189
    User ubuntu
    IdentityFile ~/.ssh/cluster

Host node3
    HostName 172.31.6.15
    User ubuntu
    IdentityFile ~/.ssh/cluster
```

此时，用 `ssh node[1-3]` 就可以无任何提示地连接任意节点。

仍在主节点上，我们创建一个 `~/hosts` 文件，写入集群中所有节点的名称（即上面 ssh 配置里定义的名字）。主节点用 `localhost`，因为训练脚本要在它上面启动。我的文件如下。

```
localhost
node1
node2
node3
```

集群就绪。开始训练！

## 启动分布式训练任务

这个例子里，我们在 [SQUAD](https://huggingface.co/datasets/squad) 数据集上对一个 [DistilBERT](https://huggingface.co/distilbert-base-uncased) 模型做问答微调。想试其他示例也随意。

```
source ~/cluster_env/bin/activate
cd ~/transformers/examples/pytorch/question-answering
pip3 install -r requirements.txt
```

作为 sanity check，我们先启动一个本地训练任务。请注意几个重要 flags：

- `no_cuda` 确保任务忽略本机上的任何 GPU，
- `use_ipex` 启用 IPEX 库，从而用上 AVX 和 AMX 指令，
- `bf16` 启用 BF16 训练。

```
export LD_PRELOAD="/usr/lib/x86_64-linux-gnu/libtcmalloc.so"
python run_qa.py --model_name_or_path distilbert-base-uncased \
--dataset_name squad --do_train --do_eval --per_device_train_batch_size 32 \
--num_train_epochs 1  --output_dir /tmp/debug_squad/ \
--use_ipex --bf16 --no_cuda
```

不必让任务跑完，我们只跑一分钟确认所有依赖安装正确。这也给我们单实例训练的基线：1 个 epoch 约需 **26 分钟**。作为参照，同样的任务在软件配置相同的可比 Ice Lake 实例（`c6i.16xlarge`）上，每个 epoch 要 **3 小时 30 分钟**。这是 **8 倍加速**。新指令的好处已经可见一斑！

现在把训练分布到 4 台实例上。一台 `r7iz.16xlarge` 有 32 个物理 CPU 核心，我们选择直接以物理核工作而不使用 vCPU（`KMP_HW_SUBSET=1T`）。我们决定分配 24 核给训练（`OMP_NUM_THREADS`）、2 核给 CCL 通信（`CCL_WORKER_COUNT`），剩下的 6 个线程留给内核和其他进程。24 个训练线程支撑 2 个 Python 进程（`NUM_PROCESSES_PER_NODE`）。因此 4 节点集群上运行的 Python 任务总数是 8（`NUM_PROCESSES`）。

```
# Set up environment variables for CCL
oneccl_bindings_for_pytorch_path=$(python -c "from oneccl_bindings_for_pytorch import cwd; print(cwd)")
source $oneccl_bindings_for_pytorch_path/env/setvars.sh

export MASTER_ADDR=172.31.3.190
export NUM_PROCESSES=8
export NUM_PROCESSES_PER_NODE=2
export CCL_WORKER_COUNT=2
export CCL_WORKER_AFFINITY=auto
export KMP_HW_SUBSET=1T
```

现在启动分布式训练任务。

```
# Launch distributed training
mpirun -f ~/hosts \
 -n $NUM_PROCESSES -ppn $NUM_PROCESSES_PER_NODE  \
 -genv OMP_NUM_THREADS=24 \
 -genv LD_PRELOAD="/usr/lib/x86_64-linux-gnu/libtcmalloc.so" \
 python3 run_qa.py \
 --model_name_or_path distilbert-base-uncased \
 --dataset_name squad \
 --do_train \
 --do_eval \
 --per_device_train_batch_size 32  \
 --num_train_epochs 1  \
 --output_dir /tmp/debug_squad/ \
 --overwrite_output_dir \
 --no_cuda \
 --xpu_backend ccl \
 --bf16
```

现在 1 个 epoch 只需 **7 分 30 秒**。

任务运行起来是这个样子。最上面是主节点，你可以看到其他 3 台节点上各跑着两个训练进程。

4 节点完美线性加速应该是 6 分 30 秒（26 分钟除以 4）。我们非常接近这个理想值，说明这套方案的可扩展性很好。
