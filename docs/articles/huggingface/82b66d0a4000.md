# `LeRobotDataset:v3.0`：将大规模数据集引入 `lerobot`

**TL;DR** 今天我们发布 `LeRobotDataset:v3`！在之前的 `LeRobotDataset:v2` 里，我们把一个 episode 存一个文件，当数据集扩展到百万级 episode 时会撞上文件系统限制。`LeRobotDataset:v3` 把多个 episode 打包进单个文件，用关系型元数据从多 episode 文件中按单个 episode 粒度取回信息。新格式还原生支持以流式（streaming）方式访问数据集，可即时处理大数据集。我们提供一行命令的工具，把所有 LeRobotDataset 格式的数据集转成新格式，并非常期待在下一个稳定版发布之前先把这个里程碑分享给社区！

## LeRobotDataset, v3.0

`LeRobotDataset` 是一个标准化数据集格式，为机器人学习的特殊需求而设计，对跨模态的机器人数据——包括传感器读数、多路相机画面和遥操作状态——提供统一、便捷的访问。我们的数据格式还存储数据如何被采集的一般信息（*元数据*），包括所执行任务的文字描述、机器人种类，以及图像与机器人状态流采样帧率（fps）等度量细节。元数据在 Hugging Face Hub 上对机器人数据集做索引和检索时非常有用！

在 `lerobot`——我们在 Hugging Face 开发的机器人库——里，`LeRobotDataset` 为处理多模态时序数据提供统一接口，并与 Hugging Face 和 PyTorch 生态无缝集成。该格式设计成易于扩展和定制，已经支持来自各种形态（embodiment）的公开数据集——包括 SO-100 机械臂和 ALOHA-2 平台这类操作平台、真实世界人形机器人数据、仿真数据集，甚至有自动驾驶数据！你可以用[数据集可视化器](https://huggingface.co/spaces/lerobot/visualize_dataset)浏览社区贡献的现有数据集！🔗

除了规模，这次 `LeRobotDataset` 新版本还带来*流式*能力：无需把大得吓人的数据下载进磁盘，就能对大数据集按批即时处理。任何 `v3.0` 数据集都可以通过专门的 `StreamingLeRobotDataset` 接口以流式模式访问！流式数据集是让机器人学习更易得的关键里程碑，我们很兴奋能把它分享给社区 🤗

从「以 episode 为单位」到「以文件为单位」的数据集。

## 安装 `lerobot`，录制一个数据集

[`lerobot`](https://github.com/huggingface/lerobot) 是 Hugging Face 开发的端到端机器人库，支持真实世界机器人，也支持最先进的机器人学习算法。这个库可以在真实机器人上本地录制数据集，并把数据集存储到 Hugging Face Hub。关于我们目前支持的机器人，可阅读[文档](https://huggingface.co/docs/lerobot/)！

`LeRobotDataset:v3` 将从 `lerobot-v0.4.0` 起成为 `lerobot` 库的一部分。我们非常乐意提前分享给社区。你可以直接从 PyPI 安装支持这一新数据格式的最新 `lerobot-v0.3.x`：

```
pip install "https://github.com/huggingface/lerobot/archive/33cad37054c2b594ceba57463e8f11ee374fa93c.zip"  # this will affect your local lerobot installation!
```

库的稳定版发布进展，关注[这里](https://github.com/huggingface/lerobot/issues/1654) 🤗

装好支持新格式的 lerobot 版本后，你可以用我们的招牌机械臂 SO-101 配合遥操作录制数据集：

```
lerobot-record \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.usbmodem585A0076841 \
    --robot.id=my_awesome_follower_arm \
    --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 1920, height: 1080, fps: 30}}" \
    --teleop.type=so101_leader \
    --teleop.port=/dev/tty.usbmodem58760431551 \
    --teleop.id=my_awesome_leader_arm \
    --display_data=true \
    --dataset.repo_id=${HF_USER}/record-test \
    --dataset.num_episodes=5 \
    --dataset.single_task="Grab the black cube"
```

如何为你的场景录制数据集，见[官方文档](https://huggingface.co/docs/lerobot/en/il_robots?record=Command#record-a-dataset)。

# （新）格式设计

`LeRobotDataset` 背后的一个核心设计选择，是把底层数据存储与面向用户的 API 分开。这样既能高效序列化与存储，又能把数据以直观、开箱即用的形态呈现。数据集由三大组件组织：

- **表格数据（Tabular Data）**：关节状态、动作等低维高频数据存进高效的 [Apache Parquet](https://parquet.apache.org/) 文件，并通常交给更成熟的 `datasets` 库处理，提供快速的内存映射访问或流式访问。
- **视觉数据（Visual Data）**：为处理海量相机数据，帧被串联编码进 MP4 文件。同一 episode 的帧总是进同一个视频，多个视频再按相机归类。为减轻文件系统压力，同一相机视角的视频组还会拆分到多个子目录。
- **元数据（Metadata）**：一组 JSON 文件，从元数据角度描述数据集结构，作为表格维度与视觉维度的关系层。元数据包括各特征的 schema、帧率、归一化统计量、episode 边界。

[![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/lerobotdataset-v3/dataset-v3-pillars.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/lerobotdataset-v3/dataset-v3-pillars.png)

为支持可能有百万级 episode（对应数亿/数十亿个单独帧）的数据集，我们把不同 episode 的数据合并进同样的顶层结构。具体讲，任何一份表格集合或视频不再只含一个 episode 的信息，而是多个 episode 信息的串联。这样无论本地还是 Hugging Face 这样的远端存储，文件系统压力都在可控范围。需要 episode 级信息时——例如某 episode 在某个视频中的起止时间戳——再去查元数据。

数据集以 repository 形式组织，包含：

- **`meta/info.json`**：中央元数据文件。包含完整的数据集 schema，定义所有特征（如 `observation.state`、`action`）的形状与数据类型。还保存数据集帧率（`fps`）、codebase 版本、用于定位数据与视频文件的路径模板等关键信息。
- **`meta/stats.json`**：存储每个特征在全数据集范围的汇总统计量（mean、std、min、max）。这些用于数据归一化，可通过 `dataset.meta.stats` 访问。
- **`meta/tasks.jsonl`**：自然语言任务描述到整数任务索引的映射，供任务条件化（task-conditioned）的策略训练使用。
- **`meta/episodes/`**：该目录存放每个单独 episode 的元数据，如其长度、对应任务、数据存放位置的指针。为了可扩展性，这些信息存成分块的 Parquet 文件，而不是单个巨型 JSON。
- **`data/`**：存放逐帧的核心表格数据，Parquet 格式。为提升性能并支撑大数据集，**多个 episode 的数据被串联进更大的文件**。这些文件组织成分块子目录，让单文件大小 manageable。因此单个文件通常含多个 episode 的数据。
- **`videos/`**：存放所有视觉观测流的 MP4 视频文件。与 `data/` 目录类似，**多个 episode 的视频画面被串联进单个 MP4 文件**。这个策略显著减少数据集的文件数量，对现代文件系统效率更高。路径结构（`/videos/<camera_key>/<chunk>/file_...mp4`）让数据加载器先定位到正确的视频文件，再 seek 到给定帧的精确时间戳。

## 把你的 `v2.1` 数据集迁移到 `v3.0`

`LeRobotDataset:v3.0` 将随 `lerobot-v0.4.0` 发布，同时提供便捷的转换能力，把 Hugging Face Hub 上的任何数据集转成新的 `v3.0`：

```
python -m lerobot.datasets.v30.convert_dataset_v21_to_v30--repo-id=<HFUSER/DATASET_ID>
```

我们非常兴奋提前把这个新格式分享给社区！在 `lerobot-v0.4.0` 开发完成之前，你也可以用支持该新格式的最新版 `lerobot-v0.3.x`（直接从 PyPI 安装）把数据集转到新版本：

```
pip install "https://github.com/huggingface/lerobot/archive/33cad37054c2b594ceba57463e8f11ee374fa93c.zip"  # this will affect your lerobot installation!
python -m lerobot.datasets.v30.convert_dataset_v21_to_v30 --repo-id=<HFUSER/DATASET_ID>
```

注意这是预发布版本，通常不稳定。下一个稳定版的开发状态见[这里](https://github.com/huggingface/lerobot/issues/1654)！

转换脚本 `convert_dataset_v21_to_v30.py` 把多个 episode 文件 `episode-0000.mp4, episode-0001.mp4, episode-0002.mp4, ...` / `episode-0000.parquet, episode-0001.parquet, episode-0002.parquet, episode-0003.parquet, ...` 聚合为单个文件 `file-0000.mp4` / `file-0000.parquet`，并相应更新元数据，以便能从更高层文件中取回 episode 级信息。

### 代码示例：在 `torch.utils.data.DataLoader` 中使用 `LeRobotDataset`

Hugging Face Hub 上任何包含上述三大支柱（表格数据、视觉数据和关系元数据）的数据集，都能一行代码访问。

多数机器人学习算法——基于强化学习（RL）或行为克隆（BC）——都在观测与动作的堆栈上工作。例如 RL 算法通常使用过去观测的历史 `o_{t-H_o:t}`，而 BC 算法通常被训练去回归一段多个动作的 chunk。为贴合机器人学习训练的特殊需求，`LeRobotDataset` 提供原生的窗口（windowing）操作：通过 `delta_timestamps` 参数，取任意观测前后若干*秒*的数据。

方便的还有：把 `LeRobotDataset` 配 PyTorch `DataLoader` 使用，数据集里单个样本字典会自动 collate 成一批张量组成的大字典。

```
from lerobot.datasets.lerobot_dataset import LeRobotDataset

repo_id = "yaak-ai/L2D-v3"

# Load from the Hugging Face Hub (will be cached locally)
dataset = LeRobotDataset(repo_id)

# Get the 100th frame in the dataset by index
sample = dataset[100]
print(sample)
# The sample is a dictionary of tensors
# {
#     'observation.state': tensor([...]),
#     'action': tensor([...]),
#     'observation.images. front_left': tensor([C, H, W]),
#     'timestamp': tensor(1.234),
#     ...
# }
delta_timestamps = {
    "observation.images.front_left": [-0.2, -0.1, 0.0]  # 0.2 and 0.1 seconds *before* any observation
}
dataset = LeRobotDataset(
    repo_id
    delta_timestamps=delta_timestamps
)

# Accessing an index now returns a stack of frames for the specified key
sample = dataset[100]

# The image tensor will now have a time dimension
# 'observation.images.wrist_camera' has shape [T, C, H, W], where T=3
print(sample['observation.images.front_left'].shape)

batch_size=16
# Wrap the dataset in a DataLoader to process it in batches for training purposes
data_loader = torch.utils.data.DataLoader(
    dataset,
    batch_size=batch_size
)

# 3. Iterate over the DataLoader in a training loop
num_epochs = 1
device = "cuda" if torch.cuda.is_available() else "cpu"

for epoch in range(num_epochs):
    for batch in data_loader:
        # 'batch' is a dictionary where each value is a batch of tensors.
        # For example, batch['action'] will have a shape of [32, action_dim].

        # If using delta_timestamps, a batched image tensor might have a
        # shape of [32, T, C, H, W].

        # Move data to the appropriate device (e.g., GPU)
        observations = batch['observation.state.vehicle'].to(device)
        actions = batch['action.continuous'].to(device)
        images = batch['observation.images.front_left'].to(device)
```

## 流式（Streaming）

你也可以用 `StreamingLeRobotDataset` 类，把任何 `v3.0` 格式的数据集以流式模式使用，无需本地下载。

```
from lerobot.datasets.streaming_dataset import StreamingLeRobotDataset
# Streams directly from the Hugging Face Hub, without downloading the dataset into disk or loading into memory
repo_id = "yaak-ai/L2D-v3"
dataset = StreamingLeRobotDataset(repo_id)
```
