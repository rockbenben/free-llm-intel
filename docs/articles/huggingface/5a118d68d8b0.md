过去几个月，Hugging Face 团队与外部贡献者为 Transformers 加入了多种 TensorFlow 视觉模型。这份清单在系统性地增长，已经包含最先进预训练模型，如 [Vision Transformer](https://huggingface.co/docs/transformers/main/en/model_doc/vit)、[Masked Autoencoders](https://huggingface.co/docs/transformers/model_doc/vit_mae)、[RegNet](https://huggingface.co/docs/transformers/main/en/model_doc/regnet)、[ConvNeXt](https://huggingface.co/docs/transformers/model_doc/convnext) 等等！

部署 TensorFlow 模型时，你有多种选择。根据用例，你可能想把模型暴露为端点，或把它打包进应用本身。TensorFlow 提供了满足不同场景的工具。

在本文中，你将看到如何用 [TensorFlow Serving](https://www.tensorflow.org/tfx/tutorials/serving/rest_simple)（TF Serving）在本地部署一个用于图像分类的 Vision Transformer（ViT）模型。这将让开发者把模型暴露为 REST 或 gRPC 端点。而且 TF Serving 还开箱支持许多部署特性，如模型预热、服务端批处理等。

要获得本文展示的完整可运行代码，请参考开头给出的 Colab Notebook。

## 保存模型

🤗 Transformers 中所有 TensorFlow 模型都有一个名为 `save_pretrained()` 的方法。用它可以把模型权重序列化为 h5 格式，也可以导出为独立的 [SavedModel 格式](https://www.tensorflow.org/guide/saved_model)。TF Serving 需要模型以 SavedModel 格式存在。所以，我们先加载一个 Vision Transformer 模型并保存：

```
from transformers import TFViTForImageClassification

temp_model_dir = "vit"
ckpt = "google/vit-base-patch16-224"

model = TFViTForImageClassification.from_pretrained(ckpt)
model.save_pretrained(temp_model_dir, saved_model=True)
```

默认情况下，`save_pretrained()` 会先在我们提供的路径内创建一个版本目录。最终路径成为：`{temp_model_dir}/saved_model/{version}`。

我们可以用 SavedModel CLI 检查 SavedModel 的 serving signature：

```
saved_model_cli show --dir {temp_model_dir}/saved_model/1 --tag_set serve --signature_def serving_default
```

输出应为：

```
The given SavedModel SignatureDef contains the following input(s):
  inputs['pixel_values'] tensor_info:
      dtype: DT_FLOAT
      shape: (-1, -1, -1, -1)
      name: serving_default_pixel_values:0
The given SavedModel SignatureDef contains the following output(s):
  outputs['logits'] tensor_info:
      dtype: DT_FLOAT
      shape: (-1, 1000)
      name: StatefulPartitionedCall:0
Method name is: tensorflow/serving/predict
```

可以看到，模型接受单个 4 维输入（即 `pixel_values`），其轴为 `(batch_size, num_channels, height, width)`。对这条模型，可接受的高和宽被设为 224，通道数为 3。你可以通过检查模型的 config 参数（`model.config`）来验证。模型输出一个 1000 维的 `logits` 向量。

## 模型外科手术

通常，每个 ML 模型都有一些预处理和后处理步骤。ViT 模型也不例外。主要的预处理步骤包括：

- 把图像像素值缩放到 [0, 1] 区间。
- 把缩放后的像素值归一化到 [-1, 1]。
- 调整图像大小，使空间分辨率为 (224, 224)。

你可以通过检查与该模型关联的图像处理器来确认：

```
from transformers import AutoImageProcessor

processor = AutoImageProcessor.from_pretrained(ckpt)
print(processor)
```

打印结果：

```
ViTImageProcessor {
  "do_normalize": true,
  "do_resize": true,
  "image_mean": [
    0.5,
    0.5,
    0.5
  ],
  "image_std": [
    0.5,
    0.5,
    0.5
  ],
  "resample": 2,
  "size": 224
}
```

由于这是一个在 [ImageNet-1k 数据集](https://huggingface.co/datasets/imagenet-1k)上预训练的图像分类模型，模型输出需要作为后处理步骤映射到 ImageNet-1k 的类别。

为减轻开发者的认知负担、缩小训练-服务偏差（training-serving skew），把大部分预处理与后处理步骤内置进交付的模型往往是好主意。因此，你应当在序列化 SavedModel 时把上述处理操作嵌入它的计算图。

### 预处理

就预处理而言，图像归一化是最核心的部分之一：

```
def normalize_img(
    img, mean=processor.image_mean, std=processor.image_std
):
    # Scale to the value range of [0, 1] first and then normalize.
    img = img / 255
    mean = tf.constant(mean)
    std = tf.constant(std)
    return (img - mean) / std
```

按照 🤗 Transformers 的标准格式，你还需要把图像 resize 并转置为通道在前。下面的代码片段展示了所有预处理步骤：

```
CONCRETE_INPUT = "pixel_values" # Which is what we investigated via the SavedModel CLI.
SIZE = processor.size["height"]


def normalize_img(
    img, mean=processor.image_mean, std=processor.image_std
):
    # Scale to the value range of [0, 1] first and then normalize.
    img = img / 255
    mean = tf.constant(mean)
    std = tf.constant(std)
    return (img - mean) / std


def preprocess(string_input):
    decoded_input = tf.io.decode_base64(string_input)
    decoded = tf.io.decode_jpeg(decoded_input, channels=3)
    resized = tf.image.resize(decoded, size=(SIZE, SIZE))
    normalized = normalize_img(resized)
    normalized = tf.transpose(
        normalized, (2, 0, 1)
    )  # Since HF models are channel-first.
    return normalized


@tf.function(input_signature=[tf.TensorSpec([None], tf.string)])
def preprocess_fn(string_input):
    decoded_images = tf.map_fn(
        preprocess, string_input, dtype=tf.float32, back_prop=False
    )
    return {CONCRETE_INPUT: decoded_images}
```

**关于让模型接受字符串输入的说明：**

通过 REST 或 gRPC 请求处理图像时，请求负载的大小会随着传入图像的分辨率迅速失控。因此，可靠的实践是先把图像压缩、再准备请求负载。

### 后处理与模型导出

现在你已经有了预处理操作，可以注入模型的计算图。本节还会把后处理操作注入图中，并导出模型！

```
def model_exporter(model: tf.keras.Model):
    m_call = tf.function(model.call).get_concrete_function(
        tf.TensorSpec(
            shape=[None, 3, SIZE, SIZE], dtype=tf.float32, name=CONCRETE_INPUT
        )
    )

    @tf.function(input_signature=[tf.TensorSpec([None], tf.string)])
    def serving_fn(string_input):
        labels = tf.constant(list(model.config.id2label.values()), dtype=tf.string)
        
        images = preprocess_fn(string_input)
        predictions = m_call(**images)
        
        indices = tf.argmax(predictions.logits, axis=1)
        pred_source = tf.gather(params=labels, indices=indices)
        probs = tf.nn.softmax(predictions.logits, axis=1)
        pred_confidence = tf.reduce_max(probs, axis=1)
        return {"label": pred_source, "confidence": pred_confidence}

    return serving_fn
```

你可以先从模型的前向方法（`call()`）派生出[具体函数（concrete function）](https://www.tensorflow.org/guide/function)，让模型被良好地编译成图。然后按顺序应用以下步骤：

- 把输入通过预处理操作。
- 把预处理后的输入送入派生的具体函数。
- 对输出做后处理，并以格式良好的字典返回。

现在导出模型！

```
MODEL_DIR = tempfile.gettempdir()
VERSION = 1

tf.saved_model.save(
    model,
    os.path.join(MODEL_DIR, str(VERSION)),
    signatures={"serving_default": model_exporter(model)},
)
os.environ["MODEL_DIR"] = MODEL_DIR
```

导出后，再检查一次模型签名：

```
saved_model_cli show --dir {MODEL_DIR}/1 --tag_set serve --signature_def serving_default
```

```

  inputs['string_input'] tensor_info:
      dtype: DT_STRING
      shape: (-1)
      name: serving_default_string_input:0

  outputs['confidence'] tensor_info:
```

可以看到模型的签名已经改变：输入类型现在是字符串，模型返回两样东西：置信度分数与字符串标签。

只要你已安装 TF Serving（Colab Notebook 里有讲），现在就可以部署这个模型了！

## 用 TensorFlow Serving 部署

只需一条命令：

```
nohup tensorflow_model_server \
  --rest_api_port=8501 \
  --model_name=vit \
  --model_base_path=$MODEL_DIR >server.log 2>&1
```

上面命令中的重要参数：

- `rest_api_port`：TF Serving 部署模型 REST 端点所用的端口。默认情况下，TF Serving 用 8500 端口提供 gRPC 端点。
- `model_name`：指定模型名（可以是任意值），调用 API 时会用到。
- `model_base_path`：TF Serving 用来加载模型最新版本的基准路径。

（完整支持的参数列表在[这里](https://github.com/tensorflow/serving/blob/master/tensorflow_serving/model_servers/main.cc)。）

大功告成！几分钟内，你就拥有了一个部署好、具备两个端点——REST 与 gRPC——的模型。

## 查询 REST 端点

回想一下，我们导出模型时让它接受 [base64](https://en.wikipedia.org/wiki/Base64) 编码的字符串输入。所以构造请求负载可以这样做：

```
# Get image of a cute cat.
image_path = tf.keras.utils.get_file(
    "image.jpg", "http://images.cocodataset.org/val2017/000000039769.jpg"
)

# Read the image from disk as raw bytes and then encode it. 
bytes_inputs = tf.io.read_file(image_path)
b64str = base64.urlsafe_b64encode(bytes_inputs.numpy()).decode("utf-8")


# Create the request payload.
data = json.dumps({"signature_name": "serving_default", "instances": [b64str]})
```

TF Serving REST 端点的请求负载格式规范见[这里](https://www.tensorflow.org/tfx/serving/api_rest#request_format_2)。你可以在 `instances` 里传入多张编码图像。这类端点面向在线预测场景。对于多于一个数据点的输入，你会想[启用批处理](https://github.com/tensorflow/serving/blob/master/tensorflow_serving/batching/README.md)以获得性能优化收益。

现在可以调用 API：

```
headers = {"content-type": "application/json"}
json_response = requests.post(
    "http://localhost:8501/v1/models/vit:predict", data=data, headers=headers
)
print(json.loads(json_response.text))
# {'predictions': [{'label': 'Egyptian cat', 'confidence': 0.896659195}]}
```

REST API 为 `http://localhost:8501/v1/models/vit:predict`，遵循[这里的规范](https://www.tensorflow.org/tfx/serving/api_rest#predict_api)。默认它总是取模型的最新版本。如果你想指定版本，可以用：`http://localhost:8501/v1/models/vit/versions/1:predict`。

## 查询 gRPC 端点

REST 在 API 世界很流行，但许多应用同样受益于 gRPC。[这篇文章](https://blog.dreamfactory.com/grpc-vs-rest-how-does-grpc-compare-with-traditional-rest-apis/)很好地对比了两种部署方式。gRPC 通常更适合低延迟、高扩展性和分布式系统。

有几个步骤。首先，打开一个通信通道：

```
import grpc
from tensorflow_serving.apis import predict_pb2
from tensorflow_serving.apis import prediction_service_pb2_grpc


channel = grpc.insecure_channel("localhost:8500")
stub = prediction_service_pb2_grpc.PredictionServiceStub(channel)
```

然后，创建请求负载：

```
request = predict_pb2.PredictRequest()
request.model_spec.name = "vit"
request.model_spec.signature_name = "serving_default"
request.inputs[serving_input].CopyFrom(tf.make_tensor_proto([b64str]))
```

你可以用程序化的方式确定 `serving_input` 键：

```
loaded = tf.saved_model.load(f"{MODEL_DIR}/{VERSION}")
serving_input = list(
    loaded.signatures["serving_default"].structured_input_signature[1].keys()
)[0]
print("Serving function input:", serving_input)
# Serving function input: string_input
```

现在可以获取预测了：

```
grpc_predictions = stub.Predict(request, 10.0)  # 10 secs timeout
print(grpc_predictions)
```

```
outputs {
  key: "confidence"
  value {
    dtype: DT_FLOAT
    tensor_shape {
      dim {
        size: 1
      }
    }
    float_val: 0.8966591954231262
  }
}
outputs {
  key: "label"
  value {
    dtype: DT_STRING
    tensor_shape {
      dim {
        size: 1
      }
    }
    string_val: "Egyptian cat"
  }
}
model_spec {
  name: "resnet"
  version {
    value: 1
  }
  signature_name: "serving_default"
}
```

你也可以从上面的结果中取回我们关心的键值：

```
grpc_predictions.outputs["label"].string_val, grpc_predictions.outputs[
    "confidence"
].float_val
# ([b'Egyptian cat'], [0.8966591954231262])
```
