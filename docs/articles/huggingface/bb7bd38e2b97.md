# 推出开放阿拉伯语 LLM 排行榜

Open Arabic LLM Leaderboard（OALL）旨在回应阿拉伯语处理领域对专业基准日益增长的需求。随着自然语言处理（NLP）学科的进步，关注点往往严重偏向英语，其他语言在资源上存在巨大缺口。OALL 的目标正是通过提供一个专门评估和比较阿拉伯语大语言模型（LLM）性能的平台来平衡这一点，从而推动阿拉伯语 NLP 的研究与开发。

这一倡议的意义格外重大，因为它直接服务于全球超过 3.8 亿阿拉伯语使用者。通过提升准确评估和改进阿拉伯语 LLM 的能力，我们希望 OALL 在开发精细适配阿拉伯语言、文化与遗产微妙之处的模型和应用方面发挥关键作用。

## 基准、指标与技术架构

### 基准数据集

OALL 使用一大套丰富而多样的稳健数据集，确保模型评估全面覆盖。

- [AlGhafa benchmark](https://aclanthology.org/2023.arabicnlp-1.21)：由 TII LLM 团队创建，目标是在阅读理解、情感分析、问答等一系列能力上评估模型。它最初包含 11 个原生阿拉伯语数据集，后来扩展增加了另外 11 个——它们是英语 NLP 社区广泛采用的基准的译本。
- ACVA 和 AceGPT benchmarks：包含来自论文 ["AceGPT, Localizing Large Language Models in Arabic"](https://arxiv.org/abs/2309.12053) 的 58 个数据集，以及 MMLU 和 EXAMS 基准的译本，以拓宽评估谱系、覆盖尽可能广的语言任务。这些基准经过精心整理，设有多个子集，能准确捕捉阿拉伯语的复杂性与微妙之处。

### 评估指标

鉴于任务性质（包括选择题和是/否题），排行榜主要使用所有任务的归一化 log likelihood accuracy（归一化对数似然准确率）。选这个指标，是因为它能对模型在不同题型上的表现给出清晰、公平的衡量。

### 技术架构

OALL 的技术架构使用：

- 受 [`demo-leaderboard`](https://huggingface.co/demo-leaderboard-backend) 启发的前后端，后端运行在 TII 集群本地
- 执行评估的 `lighteval` 库。我们为把上文讨论的阿拉伯语基准整合进 `lighteval` 做出了重要贡献，让社区可以开箱即用地评估阿拉伯语模型（详见 GitHub 上的 [PR #44](https://github.com/huggingface/lighteval/pull/44) 和 [PR #95](https://github.com/huggingface/lighteval/pull/95)）。

## 未来方向

关于扩展 OALL 的范围，我们有很多想法。计划在多个类别下引入新的排行榜，例如在检索增强生成（RAG）场景下评估阿拉伯语 LLM 的排行榜，以及根据用户偏好计算阿拉伯语聊天机器人 ELO 分数的对话竞技场。

此外，我们计划扩展基准以覆盖更全面的任务，开发 OpenDolphin benchmark——它将包含约 50 个数据集，是对 Nagoudi 等人论文 [“Dolphin: A Challenging and Diverse Benchmark for Arabic NLG”](https://arxiv.org/abs/2305.14989) 工作的开放复现。有兴趣添加自己的基准或参与 OpenDolphin 项目的，请通过 discussion 标签页或这个[邮箱](mailto:elfilali.ali01@gmail.com)联系我们。

我们欢迎你在这些方面做出贡献！鼓励社区通过提交模型、提议新基准或参与讨论来贡献力量。也鼓励社区利用当前排行榜上的头部模型，通过微调或其他任何可能帮助你攀上榜首的技术创造新模型！下一个阿拉伯语开放模型英雄也许就是你。

我们希望 OALL 不仅能推动技术进步，还能彰显阿拉伯语独有的语言与文化特质；也希望我们的技术架构和搭建大规模单语排行榜的经验，能为其他代表性不足语言的类似倡议提供参考。这种关注有助于弥合长期以来由英语中心模型主导的资源与研究差距，让全球 NLP 版图拥有更多元、更包容的工具——在 AI 技术日益融入世界各地日常生活的今天，这一点至关重要。

## 提交你的模型！

### 模型提交流程

为保证评估流程顺畅，参与者向 OALL 提交模型时必须遵循以下具体指南：

- **确保模型精度对齐：** 提交模型的精度必须与原模型一致。精度不一致可能导致模型虽被评估、却无法在排行榜上正常显示。
- **提交前检查：**  **加载模型和 tokenizer：** 确认你的模型和 tokenizer 能用 AutoClasses 成功加载。使用以下命令：`from transformers import AutoConfig, AutoModel, AutoTokenizer config = AutoConfig.from_pretrained("your model name", revision=revision) model = AutoModel.from_pretrained("your model name", revision=revision) tokenizer = AutoTokenizer.from_pretrained("your model name", revision=revision) ` 如果遇到错误，按错误提示处理，确保模型已正确上传。  **模型可见性：** 确保你的模型设为公开。另外注意，如果你的模型需要 `use_remote_code=True`，该特性目前不支持，但已在开发中。
- **把模型权重转为 Safetensors：** 将模型权重转换为 safetensors——一种更安全、加载更快的权重格式。转换后，模型的参数量也能展示在 `Extended Viewer` 里。
- **许可证与模型卡：**  **开放许可：** 确认你的模型采用开放许可。本排行榜推广开放 LLM 的可及性，以确保广泛可用。 **完善模型卡：** 填写详实的模型卡信息。这些数据会被自动抽取并随你的模型一起显示在排行榜上。

### 模型评估失败时

如果你的模型出现在「FAILED」类别，说明执行被中止。请对照上面列出的步骤排查并解决。也可以在本地跑这个[脚本](https://gist.github.com/alielfilali01/d486cfc962dca3ed4091b7c562a4377f)测试你的模型，确认能正常工作后再重新提交。
