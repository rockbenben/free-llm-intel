# 只需 3 个简单步骤即可在 Intel CPU 上运行您的 VLM

随着大语言模型（LLM）能力不断增强，一类新的模型也随之出现：[视觉语言模型（VLM）](https://huggingface.co/blog/vlms-2025)。这些模型可以分析图像和视频，描述场景、生成字幕、回答关于视觉内容的问题。

在自己的设备上运行 AI 模型可能不容易，因为这些模型通常对算力要求很高；但好处也很明显：数据留在本地机器上，隐私更好；不依赖网络连接和外部服务器，速度和可靠性也更优。这正是 [Optimum Intel](https://huggingface.co/docs/optimum-intel/en/index) 和 [OpenVINO](https://docs.openvino.ai/2025/index.html) 这类工具大显身手的地方，再配合像 [SmolVLM](https://huggingface.co/blog/smolvlm) 这样小巧高效的模型即可。在这篇博客里，我们将带你用三个简单步骤在本地跑起一个 VLM——不需要昂贵的硬件或 GPU（当然，本文所有代码示例也可以在 Intel GPU 上运行）。

## 用 Optimum 部署你的模型

像 SmolVLM 这样的小模型本就是为低资源消耗设计的，但它们还能进一步压榨优化。在这篇博客里，我们将看看如何优化模型：降低内存占用、加速推理，让它能更高效地部署在资源有限的设备上。

要继续本教程，你需要安装 `optimum` 和 `openvino`：

```
pip install optimum-intel[openvino] transformers==4.52.*
```

## 步骤 1：转换模型

首先，你需要把模型转换成 [OpenVINO IR](https://docs.openvino.ai/2025/documentation/openvino-ir-format.html) 格式。有多种方式可以做到：

- 使用 [Optimum CLI](https://huggingface.co/docs/optimum-intel/en/openvino/export#using-the-cli)

```
optimum-cli export openvino -m HuggingFaceTB/SmolVLM2-256M-Video-Instruct smolvlm_ov/
```

- 或者在加载模型时[在线](https://huggingface.co/docs/optimum-intel/en/openvino/export#when-loading-your-model)转换：

```
from optimum.intel import OVModelForVisualCausalLM

model_id = "HuggingFaceTB/SmolVLM2-256M-Video-Instruct"
model = OVModelForVisualCausalLM.from_pretrained(model_id)
model.save_pretrained("smolvlm_ov")
```

## 步骤 2：量化

接下来该优化模型了。量化会降低模型权重和/或激活值的精度，从而得到更小、更快的模型。本质上，它是把高精度数据类型（比如 32 位浮点数 FP32）的值映射到低精度格式（通常是 8 位整数 INT8）。这一过程好处很多，但也可能带来一定的精度损失。

![Quantization](https://huggingface.co/datasets/OpenVINO/documentation/resolve/main/blog/openvino_vlm/quantization.png)

Optimum 支持两种主要的训练后量化方法：

- [仅权重量化（Weight Only Quantization，WOQ）](https://huggingface.co/docs/optimum-intel/en/openvino/optimization#weight-only-quantization)
- [静态量化（Static Quantization）](https://huggingface.co/docs/optimum-intel/en/openvino/optimization#full-quantization)

我们逐一看一下。

### 选择 1：仅权重量化

仅权重量化指只量化权重，激活值保持原始精度。这样模型更小、更省内存，加载时间也更短；但由于激活值没有量化，推理速度的提升有限。仅权重量化是简单稳妥的第一步，因为通常不会造成明显的精度下降。

> 从 OpenVINO 2024.3 起，如果模型权重已被量化，对应的激活值也会在运行时一并量化，根据设备的不同还能带来额外的加速。

要使用它，需要创建一个量化配置 `OVWeightQuantizationConfig`，如下：

```
from optimum.intel import OVModelForVisualCausalLM, OVWeightQuantizationConfig

q_config = OVWeightQuantizationConfig(bits=8)
q_model = OVModelForVisualCausalLM.from_pretrained(model_id, quantization_config=q_config)
q_model.save_pretrained("smolvlm_int8")
```

等价地，也可以用 CLI：

```
optimum-cli export openvino -m HuggingFaceTB/SmolVLM2-256M-Video-Instruct --weight-format int8 smolvlm_int8/
```

## 选择 2：静态量化

静态量化在推理之前同时量化权重和激活值。为了尽可能准确地估计激活值的量化参数，我们要先做一次校准（calibration）：把一小份有代表性的数据集喂进模型。在本例中，我们使用 [contextual dataset](https://huggingface.co/datasets/ucla-contextual/contextual_test) 的 50 个样本，并对视觉编码器应用静态量化，模型其余部分则用仅权重量化。实验表明，对视觉编码器做静态量化能带来明显的性能提升，且精度几乎没有损失。由于视觉编码器每次生成只调用一次，对它做静态量化带来的整体性能收益，低于优化语言模型这类更频繁调用的组件。不过在某些场景下这个方法依然有用，比如需要简短回答、尤其是多图输入的时候。

```
from optimum.intel import OVModelForVisualCausalLM, OVPipelineQuantizationConfig, OVQuantizationConfig, OVWeightQuantizationConfig

q_config = OVPipelineQuantizationConfig(
    quantization_configs={
        "lm_model": OVWeightQuantizationConfig(bits=8),
        "text_embeddings_model": OVWeightQuantizationConfig(bits=8),
        "vision_embeddings_model": OVQuantizationConfig(bits=8),
    },
    dataset=dataset,
    num_samples=num_samples,
)
q_model = OVModelForVisualCausalLM.from_pretrained(model_id, quantization_config=q_config)
q_model.save_pretrained("smolvlm_static_int8")
```

量化激活值会引入一些可能累积并影响精度的小误差，因此事后认真测试很重要。更多信息和示例见[我们的文档](https://huggingface.co/docs/optimum-intel/en/openvino/optimization#pipeline-quantization)。

### 步骤 3：运行推理

现在可以用你的量化模型跑推理了：

```
generated_ids = q_model.generate(**inputs, max_new_tokens=100)
generated_texts = processor.batch_decode(generated_ids, skip_special_tokens=True)
print(generated_texts[0])
```

如果你用的是较新的 Intel 笔记本、Intel AI PC 或 Intel 独立 GPU，可以在加载模型时加上 `device="gpu"`，把模型加载到 GPU 上：

```
model = OVModelForVisualCausalLM.from_pretrained(model_id, device="gpu")
```

## 评估与结论

我们跑了一个基准测试，对比原始模型的 [PyTorch](https://huggingface.co/HuggingFaceTB/SmolVLM2-256M-Video-Instruct)、[OpenVINO](https://huggingface.co/echarlaix/SmolVLM2-256M-Video-Instruct-openvino) 和 [OpenVINO 8-bit WOQ](https://huggingface.co/echarlaix/SmolVLM2-256M-Video-Instruct-openvino-8bit-woq-data-free) 三个版本，目标是评估仅权重量化在 Intel CPU 硬件上对延迟和吞吐的影响。测试使用的输入是[一张图像](https://huggingface.co/datasets/OpenVINO/documentation/resolve/main/blog/openvino_vlm/flower.png)。

我们用以下指标来评估模型性能：

- Time To First Token (TTFT)：生成第一个输出 token 所需的时间。
- Time Per Output Token (TPOT)：生成后续每个输出 token 所需的时间。
- 端到端延迟（End-to-End Latency）：生成全部输出 token 所需的总时间。
- 解码吞吐（Decoding Throughput）：模型在解码阶段每秒生成的 token 数。

以下是 Intel CPU 上的结果：

| 配置 | Time To First Token (TTFT) | Time Per Output Token (TPOT) | 端到端延迟 | 解码吞吐 |
| --- | --- | --- | --- | --- |
| pytorch | 5.150 | 1.385 | 25.927 | 0.722 |
| openvino | 0.420 | 0.021 | 0.738 | 47.237 |
| openvino-8bit-woq | 0.247 | 0.016 | 0.482 | 63.928 |

这个基准展示了像 [SmolVLM2-256M](https://huggingface.co/HuggingFaceTB/SmolVLM2-256M-Video-Instruct) 这样经过优化的小型多模态模型在 Intel CPU 上不同配置下的表现。测试显示，PyTorch 版本延迟很高：首 token 时间（TTFT）超过 5 秒，解码吞吐只有 0.7 token/s。仅用 Optimum 把模型转换到 OpenVINO 再运行，TTFT 就大幅降到 0.42 秒（**加速 12 倍**），吞吐提升到 47 token/s（**提升 65 倍**）。再加上 8-bit 仅权重量化后，TTFT 进一步降低（**1.7 倍**）、吞吐进一步提升（**1.4 倍**），同时还缩小了模型体积、提高了效率。
