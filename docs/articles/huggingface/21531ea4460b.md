**Wav2Vec2** 是一个广受欢迎的语音识别预训练模型。它由 Meta AI Research 于 [2020 年 9 月](https://ai.facebook.com/blog/wav2vec-20-learning-the-structure-of-speech-from-raw-audio/)发布，这一新颖架构推动了语音识别自监督预训练领域的进展，*例如* [*G. Ng et al.*, 2021](https://arxiv.org/pdf/2104.03416.pdf)、[*Chen et al*, 2021](https://arxiv.org/abs/2110.13900)、[*Hsu et al.*, 2021](https://arxiv.org/abs/2106.07447) 以及 [*Babu et al.*, 2021](https://arxiv.org/abs/2111.09296)。在 Hugging Face Hub 上，Wav2Vec2 最受欢迎的预训练 checkpoint 目前每月下载量已超过 [**250,000** 次](https://huggingface.co/facebook/wav2vec2-base-960h)。

**Wav2Vec2** 的核心是一个 **transformers** 模型，而 **transformers** 的一个问题在于它通常只能处理有限的序列长度。这要么是因为它使用了 **position encodings**（此处并非如此），要么仅仅是因为 transformers 中 attention 的开销实际上是随 sequence_length 呈 O(n²) 的，这意味着使用非常长的 sequence_length 会导致复杂度/内存占用爆炸。因此，在有限的硬件上（即使是一块像 A100 这样非常大的 GPU），你无法直接在长达一小时的文件上运行 Wav2Vec2。你的程序会崩溃。我们来试试看！

pip install transformers

```
from transformers import pipeline

# This will work on any of the thousands of models at
# https://huggingface.co/models?pipeline_tag=automatic-speech-recognition
pipe = pipeline(model="facebook/wav2vec2-base-960h")


# The Public Domain LibriVox file used for the test
#!wget https://ia902600.us.archive.org/8/items/thecantervilleghostversion_2_1501_librivox/thecantervilleghostversion2_01_wilde_128kb.mp3 -o very_long_file.mp3

pipe("very_long_file.mp3")
# Crash out of memory !

pipe("very_long_file.mp3", chunk_length_s=10)
# This works and prints a very long string ! 
# This whole blogpost will explain how to make things work
```

## 简单的分块

要在非常长的文件上完成推理，最简单的做法就是把原始音频直接切分成更短的样本（比如每段 10 秒），在这些样本上分别运行推理，最后再拼出最终结果。这种做法在计算上是高效的，但通常会导致欠佳的结果，原因在于要想获得好的推理效果，模型需要一定的上下文，因此在分块边界附近，推理质量往往很差。

请看下面的示意图：

[![Simple chunking](https://huggingface.co/blog/assets/49_asr_chunking/chunk.png)](https://huggingface.co/blog/assets/49_asr_chunking/chunk.png)

有一些方法可以尝试以通用的方式绕开这个问题，但它们从来都不是完全稳健的。你可以尝试只在遇到静音时才分块，但音频可能长时间都不静音（比如一首歌，或者嘈杂的咖啡馆录音）。你也可以尝试只在没有语音时才切割，但这需要另一个模型，而且这并不是一个已被完全解决的问题。你还可能遇到持续时间很长的连续人声。

事实证明，Wav2Vec2 所使用的 CTC 结构可以被利用起来，从而在非常长的文件上也能实现极为稳健的语音识别，而不会陷入这些陷阱。

## 带步长的分块

Wav2Vec2 使用了 [CTC 算法](https://distill.pub/2017/ctc/)，这意味着音频的每一帧都会被映射为单个字母预测（logit）。

[![CTC](https://huggingface.co/blog/assets/49_asr_chunking/CTC.png)](https://huggingface.co/blog/assets/49_asr_chunking/CTC.png)

这正是我们要用来加入 `stride` 的主要特性。这个[链接](https://www.quora.com/What-does-stride-mean-in-the-context-of-convolutional-neural-networks)是在图像的语境下解释它，但对音频而言概念是相同的。由于这一性质，我们可以：

- 开始在**相互重叠**的分块上进行推理，使模型在中心区域真正拥有恰当的上下文。
- **丢弃**位于两侧的推理 logits。
- 把去掉两侧之后剩余的 **logits** 串联起来，从而还原出与模型在完整长度音频上所作预测极为接近的结果。

[![Striding](https://huggingface.co/blog/assets/49_asr_chunking/Striding.png)](https://huggingface.co/blog/assets/49_asr_chunking/Striding.png)

在**技术**上，这与在整个文件上运行模型并非 100% 相同，因此它默认并未启用，但正如你在前面的示例中所见，你只需为 `pipeline` 加上 `chunk_length_s` 就能让它工作。

在实践中我们观察到，大部分糟糕的推理结果都被限制在步长区域之内，而这些区域会在推理之前就被丢弃，从而得到对全文的正确推理。

值得一提的是，这项技术的每一个参数你都可以自行选择：

```
from transformers import pipeline

pipe = pipeline(model="facebook/wav2vec2-base-960h")
# stride_length_s is a tuple of the left and right stride length.
# With only 1 number, both sides get the same stride, by default
# the stride_length on one side is 1/6th of the chunk_length_s
output = pipe("very_long_file.mp3", chunk_length_s=10, stride_length_s=(4, 2))
```

## 在经 LM 增强的模型上使用带步长的分块

在 [transformers](https://github.com/huggingface/transformers) 中，我们还加入了对 Wav2Vec2 引入 LM 的支持，以便在甚至无需微调的情况下提升模型的 WER 表现。[请参阅这篇讲解其工作原理的优秀博文](https://huggingface.co/blog/wav2vec2-with-ngram)。

事实证明，LM 直接作用于 logits 本身，因此我们实际上可以不加任何修改就应用与之前完全相同的方法！所以，在这些经 LM 增强的模型上对大文件进行分块依然开箱即用。

## 实时推理

使用像 Wav2vec2 这样的 CTC 模型有一个很大的好处：它是单次前向（single pass）模型，因此速度**非常**快。尤其是在 GPU 上。我们可以利用这一点来做实时推理。

其原理与常规的步长分块完全相同，但这一次我们可以在数据**刚刚传入时**就把它喂给 pipeline，并只需在例如长度为 10 秒的完整分块上以 1 秒的步长进行切分，以获得恰当的上下文。

这比简单的文件分块需要多得多的推理步骤，但它能让实时体验好得多，因为模型可以在你说话的同时就输出内容，而不必等待 X 秒才能看到有东西显示出来。
