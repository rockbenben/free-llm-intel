**Wav2Vec2** 是一种广受欢迎的语音识别预训练模型。它由 Meta AI Research 于 [2020年9月](https://ai.facebook.com/blog/wav2vec-20-learning-the-structure-of-speech-from-raw-audio/) 发布，该新颖架构推动了语音识别自监督预训练领域的进展，*例如* [*G. Ng et al.*, 2021](https://arxiv.org/pdf/2104.03416.pdf)、[*Chen et al*, 2021](https://arxiv.org/abs/2110.13900)、[*Hsu et al.*, 2021](https://arxiv.org/abs/2106.07447) 以及 [*Babu et al.*, 2021](https://arxiv.org/abs/2111.09296)。在 Hugging Face Hub 上，Wav2Vec2 最热门的预训练 checkpoint（检查点）目前拥有超过 [**250,000** 次月下载量](https://huggingface.co/facebook/wav2vec2-base-960h)。

**Wav2Vec2** 的核心是一个 **transformers** 模型，而 **transformers** 的一个限制在于它通常只能处理有限的序列长度。这要么是因为它使用了 **position encodings**（位置编码，此处并非如此），要么仅仅是因为 transformers 中的 attention（注意力机制）开销相对于 sequence_length 是 O(n²)，这意味着使用超长 sequence_length 会导致计算复杂度和显存占用爆炸式增长。因此，在有限的硬件条件下（即使像 A100 这样非常强大的 GPU），你无法直接在长达一小时的文件上运行 Wav2Vec2。你的程序会崩溃。我们来试一下！

```
pip install transformers
```

```
from transformers import pipeline

# This will work on any of the thousands of models at
# https://huggingface.co/models?pipeline_tag=automatic-speech-recognition
pipe = pipeline(model="facebook/wav2vec2-base-960h")


# The Public Domain LibriVox file used for the test
#!wget https://ia902600.us.archive.org/8/items/thecantervilleghostversion_2_1501_librivox/thecantervilleghostversion2_01_wilde_128kb.mp3 -o very_long_file.mp3

pipe("very_long_file.mp3")
# Crash out of memory !

pipe("very_long_file.mp3", chunk_length_s=10)
# This works and prints a very long string ! 
# This whole blogpost will explain how to make things work
```

## 简单分块

在超长文件上实现推理的最简单方法，就是直接将原始音频切分成较短的样本（比如每个 10 秒），分别在这些片段上运行推理，最后进行结果重构。这种方法在计算上很高效，但通常会导致较差的效果，原因在于为了实现良好的推理，模型需要一定的上下文，因此在切分边界附近，推理质量往往较差。

请看下图：

[![Simple chunking](https://huggingface.co/blog/assets/49_asr_chunking/chunk.png)](https://huggingface.co/blog/assets/49_asr_chunking/chunk.png)

有一些通用方法可以尝试解决这个问题，但它们都不是完全稳健的。你可以尝试仅在遇到静音时进行分块，但音频可能会长时间没有静音（比如一首歌，或者嘈杂的咖啡馆音频）。你也可以尝试仅在没有语音时进行切割，但这需要另一个模型，并且这并非一个已完全解决的问题。你还可能会遇到持续时间极长的连续人声。

事实证明，Wav2Vec2 所采用的 CTC 结构可以被用来实现极为稳健的语音识别，即使在超长文件上也不会陷入这些困境。

## 带步长的分块

Wav2Vec2 使用了 [CTC 算法](https://distill.pub/2017/ctc/)，这意味着音频的每一帧都会被映射到单个字母预测（logit）。

[![CTC](https://huggingface.co/blog/assets/49_asr_chunking/CTC.png)](https://huggingface.co/blog/assets/49_asr_chunking/CTC.png)

这是我们将用来添加 `stride`（步长）的核心特性。该[链接](https://www.quora.com/What-does-stride-mean-in-the-context-of-convolutional-neural-networks)在图像背景下对其进行了解释，但在音频中概念是相同的。借助该特性，我们可以：

- 在**重叠**的块上开始进行推理，使模型在中心区域拥有充足的上下文。
- **丢弃**边缘处推理得到的 logits。
- 将去除了边缘的 **logits** 拼接起来，还原出与模型在完整长度音频上所做预测极其接近的结果。

[![Striding](https://huggingface.co/blog/assets/49_asr_chunking/Striding.png)](https://huggingface.co/blog/assets/49_asr_chunking/Striding.png)

在**技术层面**上，这与在整个文件上运行模型并不 100% 相同，因此它默认没有启用，但正如你在之前的示例中所见，你只需要在你的 `pipeline` 中添加 `chunk_length_s` 即可使其工作。

在实践中，我们观察到大部分不良推理都局限在步长区域内，而这些区域在推理后会被丢弃，从而能够正确推理出全文。

值得注意的是，你可以自定义该技术的各项参数：

```
from transformers import pipeline

pipe = pipeline(model="facebook/wav2vec2-base-960h")
# stride_length_s is a tuple of the left and right stride length.
# With only 1 number, both sides get the same stride, by default
# the stride_length on one side is 1/6th of the chunk_length_s
output = pipe("very_long_file.mp3", chunk_length_s=10, stride_length_s=(4, 2))
```

## 在语言模型（LM）增强模型上使用带步长的分块

在 [transformers](https://github.com/huggingface/transformers) 中，我们还添加了为 Wav2Vec2 引入 LM（Language Model，语言模型）的支持，以便在无需微调的情况下提升模型的 WER（字错率）性能。[请参阅这篇出色的博文，了解其工作原理](https://huggingface.co/blog/wav2vec2-with-ngram)。

事实证明，LM 直接作用于 logits 本身，因此我们完全可以在不做任何修改的情况下应用与之前完全相同的技术！所以在此类经 LM 增强的模型上对大文件进行分块依然开箱即用。

## 实时推理

使用像 Wav2vec2 这样的 CTC 模型的绝佳优势在于它是一个单次前向（single pass）模型，因此其速度**非常**快。尤其是在 GPU 上。我们可以利用这一点来实现实时推理。

其原理与常规步长完全相同，但这次我们可以在**数据传入时**直接将其送入 pipeline，并仅在例如长度为 10 秒的完整分块上使用 1 秒的步长，以获取适当的上下文。

这需要比简单的文件分块运行更多的推理步骤，但它可以带来好得多的实时体验，因为模型可以在你说话的同时输出内容，而不必等待 X 秒后才能看到显示的文字。
