# 开源 DeepResearch——解放我们的搜索智能体

## 太长不看版

昨天，OpenAI 发布了 [Deep Research](https://openai.com/index/introducing-deep-research/)——一个能浏览网页、总结内容并基于总结回答问题的系统。这套系统令人印象深刻，我们第一次试用时就被震撼到了。

其博客中的一个重要成果，是在 [General AI Assistants 基准（GAIA）](https://huggingface.co/gaia-benchmark)上的性能大幅提升——我们最近也在玩这个基准。他们单次尝试平均达到约 67% 的正确答案，在尤其困难、需要多步推理和工具使用的 "level 3" 题目上也拿到 47.6%（GAIA 的介绍见下文）。

DeepResearch 由一个 LLM（可从 OpenAI 当前提供的模型列表中挑选：4o、o1、o3 等）和一个内部的"智能体框架"（agentic framework）组成，后者引导 LLM 使用网页搜索等工具，并把行动组织成步骤。

如今强大的 LLM 在开源世界唾手可得（比如最近的 [DeepSeek R1 模型](https://huggingface.co/deepseek-ai/DeepSeek-R1)），但 OpenAI 没有公开 Deep Research 背后的智能体框架多少细节……

于是我们决定来一场 24 小时任务：复现他们的成绩，并顺手把所需的框架开源！

时钟开始滴答，冲！⏱️

## 什么是智能体框架，它为什么重要？

> 智能体框架是架在 LLM 之上的一层，让 LLM 能够执行动作（比如浏览网页、读取 PDF 文档），并把操作组织成一系列步骤。
>    想快速了解智能体，可以看 Andrew Ng 的精彩访谈和我们关于 smolagents 库的介绍博客。想更深入学习智能体，可以订阅我们的智能体课程，几天后开课：链接在这里。

几乎每个人都已经在和聊天机器人玩耍中体会过 LLM 有多强大。但还没人人皆知的是：把这些 LLM 集成进智能体系统，可以给它们真正的超能力！

下面是一个最近的例子，对比几个前沿 LLM 有无智能体框架（这里是简洁的 [smolagents](https://github.com/huggingface/smolagents) 库）的表现——用上智能体框架，性能最多能提升 60 分！

[![Benchmarks](https://huggingface.co/datasets/huggingface/documentation-images/resolve/6c7ed2035810565043c92b472d5564c3f1fa4d7e/blog/open-deep-research/benchmarks.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/6c7ed2035810565043c92b472d5564c3f1fa4d7e/blog/open-deep-research/benchmarks.png)

实际上，OpenAI 也在[发布博客](https://openai.com/index/introducing-deep-research/)中强调，Deep Research 在知识密集型基准 "[Humanity's Last Exam](https://huggingface.co/datasets/cais/hle)" 上的表现远胜于单独的 LLM。

那么，当我们把当前最强的开源 LLM 接入智能体框架，向 `open-DeepResearch` 迈进，会发生什么？

**小提示：** 我们会在同一个 GAIA 挑战上评测结果，但请记住这是一个进行中的工作。DeepResearch 是一项巨大成就，开放复现需要时间。特别是，要做到完全对标，还需要改进浏览器使用与交互能力——就像 OpenAI Operator 提供的那样——超越我们在这第一步中探索的纯文本网页交互。

先来了解挑战的范围：GAIA。

## GAIA 基准

[GAIA](https://huggingface.co/datasets/gaia-benchmark/GAIA) 可以说是最全面的智能体基准。题目非常难，直击基于 LLM 系统的诸多痛点。看一道难题的例子：

> Which of the fruits shown in the 2008 painting "Embroidery from Uzbekistan" were served as part of the October 1949 breakfast menu for the ocean liner that was later used as a floating prop for the film "The Last Voyage"? Give the items as a comma-separated list, ordering them in clockwise order based on their arrangement in the painting starting from the 12 o'clock position. Use the plural form of each fruit.

可以看出这道题包含多个挑战：

- 按受约束的格式作答，
- 使用多模态能力（从图像中提取水果），
- 收集多条相互依赖的信息：识别图中的水果；找出哪艘远洋邮轮被用作电影《The Last Voyage》的水上浮景道具；找到上述邮轮 1949 年 10 月的早餐菜单
- 按正确顺序串联起一条问题求解轨迹。

解这道题既需要高层规划能力，又需要严谨的执行——而这两样恰是 LLM 单独使用时的软肋。

所以它是智能体系统的绝佳测试集！

在 GAIA 的[公开排行榜](https://huggingface.co/spaces/gaia-benchmark/leaderboard)上，GPT-4 在没有任何智能体配置的情况下，验证集得分连 7% 都不到。而在另一端，OpenAI 的 Deep Research 在验证集拿到 67.36%，好了一个数量级！（尽管我们不知道它在私有测试集上的真实表现。）

来看看用开源工具我们能不能做得更好！

## 构建开放版 Deep Research

### 使用 CodeAgent

我们要动的第一个传统 AI 智能体系统的改进，是使用所谓的"代码智能体"（code agent）。正如 [Wang et al. (2024)](https://huggingface.co/papers/2402.01030) 所示，让智能体用代码表达行动有诸多优势，最突出的是：**代码天生就是为表达复杂动作序列而设计的**。

看一个 Wang et al. 给出的例子：

[![Code Agent](https://huggingface.co/datasets/huggingface/documentation-images/resolve/6c7ed2035810565043c92b472d5564c3f1fa4d7e/blog/open-deep-research/code_agent.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/6c7ed2035810565043c92b472d5564c3f1fa4d7e/blog/open-deep-research/code_agent.png)

这凸显了用代码的几个优势：

- 代码动作比 JSON **简洁得多**。要跑 4 条并行的、各有 5 个连续动作的流水线？用 JSON 你得生成 20 个 JSON 块，每个占一个独立步骤；用代码只要 1 步。论文显示，平均而言 Code 动作比 JSON 少 30% 的步骤，相当于等比例的生成 token 削减。由于 LLM 调用往往是智能体系统的成本大头，这意味着你的智能体运行便宜约 30%。
- 代码可以复用常见库里的工具
- 基准表现更好，原因有二：表达动作的方式更直观；LLM 在训练中大量接触过代码

这些优势在我们的 [agent_reasoning_benchmark](https://github.com/aymeric-roucher/agent_reasoning_benchmark) 实验中得到了印证。

从构建 `smolagents` 的经验中，还可以举出一个显著附加优势：更好的状态（state）管理——这对多模态任务尤其有用。需要暂存这张图/这段音频/别的什么供以后使用？没问题，把它赋值成状态里的一个变量，4 步之后需要时直接取用。换成 JSON，你得让 LLM 给它起个字典键名，还得指望 LLM 之后能明白这个键仍然可用。

### 打造合适的工具 🛠️

现在需要给智能体配上恰当的工具集。

**1.** 一个网页浏览器。虽然要达到完整性能需要 [Operator](https://openai.com/index/introducing-operator/) 那样功能完备的网页浏览器交互，但我们第一个概念验证先从一个极简的文本网页浏览器开始。代码在[这里](https://github.com/huggingface/smolagents/tree/main/examples/open_deep_research/scripts/text_web_browser.py)

**2.** 一个简单的文本检查器，用于**读取一批文本文件格式**，见[这里](https://github.com/huggingface/smolagents/tree/main/examples/open_deep_research/scripts/text_inspector_tool.py)。

这些工具取自微软研究院出色的 [Magentic-One](https://www.microsoft.com/en-us/research/articles/magentic-one-a-generalist-multi-agent-system-for-solving-complex-tasks/) 智能体，向他们致敬！我们没做太多改动，目标就是以最低复杂度拿到尽可能高的性能。

以下是我们觉得能切实提升这些工具表现的改进路线图（欢迎开 PR 贡献！）：

- 扩展可读文件格式的数量。
- 对文件的处理做得更细粒度。
- 用基于视觉的浏览器替换文本浏览器——我们已经开始，见[这里](https://github.com/huggingface/smolagents/tree/main/src/smolagents/vision_web_browser.py)。

## 结果 🏅

在这 24 小时多的复现冲刺中，我们的智能体在 GAIA 上的表现已在稳步提升！

我们很快超过了此前开放框架的 SOTA——Magentic-One 的约 46%——达到[当前验证集 55.15% 的成绩](https://huggingface.co/spaces/gaia-benchmark/leaderboard)。

这一性能提升主要归功于让智能体用代码写动作！确实，当换回用 JSON 而非代码写动作的标准智能体、其余设置完全相同时，验证集平均分立刻掉到 33%。

[最终的智能体系统在这里。](https://github.com/huggingface/smolagents/tree/main/examples/open_deep_research)

我们还搭了一个[在线演示](https://m-ric-open-deep-research.hf.space)供你体验！

不过这只是开始，还有很多可以改进！我们的开放工具可以做得更好，smolagents 框架也可以继续调优，我们还很想探索更强的开源模型作为智能体底座的表现。

欢迎社区加入我们这项工作，一起发挥开放研究的力量，构建伟大的开源智能体框架！它将让任何人都能在家跑一个 DeepResearch 式的智能体——用自己喜欢的模型，完全本地化、完全可定制！
