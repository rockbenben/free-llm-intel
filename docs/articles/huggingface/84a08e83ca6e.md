# Databricks ❤️ Hugging Face：大语言模型的训练与调优提速高达 40%

生成式 AI 正在席卷世界。作为数据与 AI 公司，我们一路同行：发布了开源大语言模型 [Dolly](https://huggingface.co/databricks/dolly-v2-12b)，以及用于微调它的、允许研究和商业使用的内部众包数据集 [databricks-dolly-15k](https://huggingface.co/datasets/databricks/databricks-dolly-15k)。模型和数据集都发布在 Hugging Face 上。在这个过程中我们学到了很多，今天我们很高兴宣布即将推出的众多对 Hugging Face 代码库的官方提交中的第一个：它让用户可以轻松地从一个 Apache Spark™ dataframe 创建 Hugging Face Dataset。

#### 「很高兴看到 Databricks 向社区发布模型和数据集，而现在我们看到他们以对 Hugging Face 的直接开源承诺延续了这项工作。Spark 是大规模数据处理最高效的引擎之一，很高兴看到用户现在能够借助这项技术更高效地微调 Hugging Face 的模型。」

— Clem Delangue，Hugging Face CEO

## Hugging Face 获得一等的 Spark 支持

过去几周，我们收到许多用户的请求：希望能有更简单的方式把他们的 Spark dataframe 加载为可用于模型训练或调优的 Hugging Face dataset。在本次发布之前，要把数据从 Spark dataframe 灌入 Hugging Face dataset，用户必须先把数据写入 Parquet 文件，再让 Hugging Face dataset 指向这些文件重新加载。例如：

```
from datasets import load_dataset

train_df = train.write.parquet(train_dbfs_path, mode="overwrite")

train_test = load_dataset("parquet", data_files={"train":f"/dbfs{train_dbfs_path}/*.parquet", "test":f"/dbfs{test_dbfs_path}/*.parquet"})

#16GB == 22min
```

这不仅麻烦，还意味着数据必须先写入磁盘再读回来。除此之外，数据重新加载进 dataset 后还会被再次物化，消耗更多资源，因此也消耗更多时间和成本。用这种方式，我们观察到相对较小（16GB）的数据集从 Spark dataframe 到 Parquet、再回到 Hugging Face dataset 大约需要 22 分钟。

通过最新的 Hugging Face 发布，我们让用户用 Datasets 中新增的 "from_spark" 函数简单调用就能完成同样的任务：

```
from datasets import Dataset

df = [some Spark dataframe or Delta table loaded into df]

dataset = Dataset.from_spark(df)

#16GB == 12min
```

这让用户可以用 Spark 高效地加载和转换数据来训练或微调模型，然后轻松地把 Spark dataframe 映射为 Hugging Face dataset，极简地融入训练 pipeline。这结合了 Spark 的成本优势和速度，以及 Hugging Face datasets 的内存映射、智能缓存等优化。这些改进把我们示例中 16GB 数据集的处理时间削减了 40% 以上，从 22 分钟降到仅 12 分钟。

## 为什么这很重要？

随着我们过渡到新的 AI 范式，组织需要用自己极具价值的数据来增强 AI 模型，才能在特定领域取得最佳表现。这几乎必然需要大量的数据转换工作，而高效地在大数据集上完成这类工作正是 Spark 的设计初衷。Spark 与 Hugging Face 的集成让你既获得 Spark 的性价比与性能，又保留 Hugging Face 提供的 pipeline 集成能力。

## 持续的开源支持

我们把这次发布视为进一步贡献开源社区的新途径——我们认为 Hugging Face 在这方面做得非常出色，它已成为开源模型和数据集的事实仓库。这只是众多贡献的开始。我们已经有计划通过 Spark 添加流式（streaming）支持，让 dataset 加载更快。

要成为用户踏入 AI 世界的最佳平台，我们正在努力提供成功训练、调优和部署模型的最佳工具。我们不仅会继续向 Hugging Face 贡献代码，也开始发布其他开源项目的改进。最近一次 [MLflow](https://www.databricks.com/blog/2023-04-18/introducing-mlflow-23-enhanced-native-llm-support-and-new-features.html) 发布增加了对 transformers 库的支持、OpenAI 集成以及 Langchain 支持。我们还宣布了 Databricks SQL 中的 [AI Functions](https://www.databricks.com/blog/2023-04-18/introducing-ai-functions-integrating-large-language-models-databricks-sql.html)，让用户可以轻松地把 OpenAI（未来也可以是自行部署的模型）集成进查询。最后，我们还发布了 Spark 版的 [PyTorch distributor](https://www.databricks.com/blog/2023-04-20/pytorch-databricks-introducing-spark-pytorch-distributor.html)，简化在 Databricks 上的分布式 PyTorch 训练。
