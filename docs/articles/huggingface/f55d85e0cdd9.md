🤗 Hugging Face [Diffusers](https://github.com/huggingface/diffusers) 从 `0.5.1` 版起支持 Flax！这让在 Google TPU——例如 Colab、Kaggle 或 Google Cloud Platform 上可用的那些——上做超快推理成为可能。

本文展示如何用 JAX / Flax 运行推理。如果你想了解更多 Stable Diffusion 如何工作的细节，或想在 GPU 上运行它，请参考 [这个 Colab notebook](https://colab.research.google.com/github/huggingface/notebooks/blob/main/diffusers/stable_diffusion.ipynb)。

如果你想跟着做，点击上方按钮把本文作为 Colab notebook 打开。

首先，确保你使用的是 TPU 后端。如果你在 Colab 里运行本 notebook，在上方菜单选择 `Runtime`，然后选择 "Change runtime type"，接着在 `Hardware accelerator` 设置下选 `TPU`。

注意 JAX 并非只能用于 TPU，但它在这类硬件上表现出色，因为每台 TPU 服务器有 8 个 TPU 加速器并行工作。

## 配置

```
import jax
num_devices = jax.device_count()
device_type = jax.devices()[0].device_kind

print(f"Found {num_devices} JAX devices of type {device_type}.")
assert "TPU" in device_type, "Available device is not a TPU, please select TPU from Edit > Notebook settings > Hardware accelerator"
```

*输出*：

```
    Found 8 JAX devices of type TPU v2.
```

确保 `diffusers` 已安装。

```
!pip install diffusers==0.5.1
```

然后导入所有依赖。

```
import numpy as np
import jax
import jax.numpy as jnp

from pathlib import Path

from flax.jax_utils import replicate
from flax.training.common_utils import shard
from PIL import Image

from huggingface_hub import notebook_login
from diffusers import FlaxStableDiffusionPipeline
```

TPU 设备支持 `bfloat16`，一种高效的半浮点类型。我们测试时用它，但你也可以用 `float32` 来使用全精度。

```
dtype = jnp.bfloat16
```

Flax 是一个函数式框架，所以模型是无状态的，参数存放在模型之外。加载预训练的 Flax pipeline 会同时返回 pipeline 本身和模型权重（或参数）。我们使用权重的 `bf16` 版本，这会导致一些类型警告，你可以安全地忽略。

```
pipeline, params = FlaxStableDiffusionPipeline.from_pretrained(
    "CompVis/stable-diffusion-v1-4",
    revision="bf16",
    dtype=dtype,
)
```

## 推理

由于 TPU 通常有 8 个设备并行工作，我们会把提示词复制成与设备数相同的份数。然后我们同时在 8 个设备上做推理，每个设备负责生成一张图像。因此，在一块芯片生成单张图所用的同样时间里，我们能拿到 8 张图。

复制提示词之后，我们通过调用 pipeline 的 `prepare_inputs` 函数得到分词后的文本 id。分词后文本的长度被设为 77 个 token，这是底层 CLIP Text 模型配置所要求的。

```
prompt = "A cinematic film still of Morgan Freeman starring as Jimi Hendrix, portrait, 40mm lens, shallow depth of field, close up, split lighting, cinematic"
prompt = [prompt] * jax.device_count()
prompt_ids = pipeline.prepare_inputs(prompt)
prompt_ids.shape
```

*输出*：

```
    (8, 77)
```

### 复制与并行化

模型参数和输入必须在我们的 8 个并行设备间复制。参数字典通过 `flax.jax_utils.replicate` 复制，它遍历字典并改变权重的形状，使其重复 8 次。数组通过 `shard` 复制。

```
p_params = replicate(params)
```

```
prompt_ids = shard(prompt_ids)
prompt_ids.shape
```

*输出*：

```
    (8, 1, 77)
```

这个形状意味着 `8` 个设备中的每一个都会收到一个形状为 `(1, 77)` 的 `jnp` 数组作为输入。`1` 就是每设备的批大小。在内存充足的 TPU 上，如果我们想一次生成多张图（每芯片），它可以大于 `1`。

我们几乎可以生成图像了！只需创建一个随机数生成器传给生成功能。这是 Flax 的标准做法，Flax 对随机数非常严谨且有自己的主张——所有处理随机数的函数都应接收一个生成器。这确保了可复现性，即使我们跨多个分布式设备训练。

下面的辅助函数用一个种子来初始化随机数生成器。只要我们用同一个种子，就会得到完全相同的结果。稍后在 notebook 里探索结果时尽可以用不同的种子。

```
def create_key(seed=0):
    return jax.random.PRNGKey(seed)
```

我们得到一个 rng，然后把它"拆分"8 次，使每个设备收到一个不同的生成器。因此每个设备会创建不同的图像，而整个过程仍可复现。

```
rng = create_key(0)
rng = jax.random.split(rng, jax.device_count())
```

JAX 代码可以被编译成运行非常高效且快速的表示。然而我们需要确保后续调用中所有输入都有相同的形状；否则 JAX 必须重新编译代码，我们就无法利用优化后的速度。

如果传入 `jit = True` 作为参数，Flax pipeline 可以替我们编译代码。它还会确保模型在 8 个可用设备上并行运行。

第一次运行下面的单元格时会花很长时间编译，但后续调用（即使输入不同）会快得多。例如，我在 TPU v2-8 上测试时编译花了一分多钟，但之后的推理运行大约只需 **`7s`**。

```
images = pipeline(prompt_ids, p_params, rng, jit=True)[0]
```

*输出*：

```
    CPU times: user 464 ms, sys: 105 ms, total: 569 ms
    Wall time: 7.07 s
```

返回的数组形状为 `(8, 1, 512, 512, 3)`。我们重排它以去掉第二维，得到 8 张 `512 × 512 × 3` 的图像，然后转换为 PIL。

```
images = images.reshape((images.shape[0],) + images.shape[-3:])
images = pipeline.numpy_to_pil(images)
```

### 可视化

让我们创建一个用网格显示图像的辅助函数。

```
def image_grid(imgs, rows, cols):
    w,h = imgs[0].size
    grid = Image.new('RGB', size=(cols*w, rows*h))
    for i, img in enumerate(imgs): grid.paste(img, box=(i%cols*w, i//cols*h))
    return grid
```

```
image_grid(images, 2, 4)
```

## 使用不同的提示词

我们不必在所有设备上复制 *同一个* 提示词。我们可以做任意想做的事：把 2 个提示词各生成 4 次，甚至一次生成 8 个不同的提示词。就这么做！

首先，我们把输入准备代码重构进一个顺手的函数：

```
prompts = [
    "Labrador in the style of Hokusai",
    "Painting of a squirrel skating in New York",
    "HAL-9000 in the style of Van Gogh",
    "Times Square under water, with fish and a dolphin swimming around",
    "Ancient Roman fresco showing a man working on his laptop",
    "Close-up photograph of young black woman against urban background, high quality, bokeh",
    "Armchair in the shape of an avocado",
    "Clown astronaut in space, with Earth in the background",
]
```

```
prompt_ids = pipeline.prepare_inputs(prompts)
prompt_ids = shard(prompt_ids)
images = pipeline(prompt_ids, p_params, rng, jit=True).images
images = images.reshape((images.shape[0], ) + images.shape[-3:])
images = pipeline.numpy_to_pil(images)
image_grid(images, 2, 4)
```

## 并行化是怎么工作的？

我们之前说过 `diffusers` 的 Flax pipeline 会自动编译模型并在所有可用设备上并行运行。现在我们稍微窥探其内部，展示它如何工作。

JAX 的并行化可以用多种方式完成。最简单的一种围绕使用 `jax.pmap` 函数来实现单程序多数据（SPMD）并行化。这意味着我们会运行同一代码的多份副本，每份在不同的数据输入上。更复杂的方法也是可能的，如果你感兴趣，欢迎阅读 [JAX 文档](https://jax.readthedocs.io/en/latest/index.html) 和 [`pjit` 页面](https://jax.readthedocs.io/en/latest/jax-101/08-pjit.html?highlight=pjit) 来探索这个主题！

`jax.pmap` 替我们做两件事：

- 编译（或 `jit`）代码，就像我们调用了 `jax.jit()` 一样。这并不发生在调用 `pmap` 时，而是第一次调用被 pmap 包装的函数时。
- 确保编译后的代码在所有可用设备上并行运行。

为展示它如何工作，我们把 pipeline 的 `_generate` 方法 `pmap` 起来，这是负责生成图像的私有方法。请注意该方法在 `diffusers` 的未来版本里可能被重命名或移除。

```
p_generate = pmap(pipeline._generate)
```

使用 `pmap` 之后，准备好的函数 `p_generate` 在概念上会做以下事情：

- 在每个设备上调用底层函数 `pipeline._generate` 的一份副本。
- 给每个设备发送输入参数的不同部分，这正是 sharding 的用途。在我们的例子里 `prompt_ids` 形状为 `(8, 1, 77, 768)`。这个数组会被拆成 `8` 份，每份 `_generate` 副本会收到一个形状为 `(1, 77, 768)` 的输入。

我们可以完全无视"它会被并行调用"这件事来编写 `_generate`。我们只关心我们的批大小（本例为 `1`）以及对我们代码有意义的维度，不需要为了并行而改任何东西。

与我们使用 pipeline 调用时一样，第一次运行下面的单元格会花一段时间，但之后会快得多。

```
images = p_generate(prompt_ids, p_params, rng)
images = images.block_until_ready()
images.shape
```

*输出*：

```
    CPU times: user 118 ms, sys: 83.9 ms, total: 202 ms
    Wall time: 6.82 s

    (8, 1, 512, 512, 3)
```

我们用 `block_until_ready()` 来正确测量推理时间，因为 JAX 使用异步调度，会尽快把控制权交还给 Python 循环。你的代码里不需要用它；当你想使用一个尚未实体化的计算结果时，阻塞会自动发生。
