# Tiny Agents：50 行代码实现 MCP 驱动的智能体

作者：Julien Chaumond（julien-c）

> 新！（2025 年 5 月 23 日）如果你更喜欢 Python，请看配套文章 Tiny Agents in Python。

过去几周，我一直在研究 MCP（[Model Context Protocol](https://modelcontextprotocol.io/)），想弄清围绕它的热度到底是怎么回事。

我的 TL;DR 是：它相当简单，但确实很强：**MCP 是一套标准 API，用来暴露可以挂接到 LLM 上的一组工具（Tools）。**

扩展一个推理客户端并不难——在 HF，我们有两个官方客户端 SDK：JS 的 [`@huggingface/inference`](https://github.com/huggingface/huggingface.js) 和 Python 的 [`huggingface_hub`](https://github.com/huggingface/huggingface_hub/)——把它们也变成 MCP 客户端，将 MCP 服务器提供的工具挂进 LLM 推理即可。

而在做这件事的过程中，我有了第二个领悟：

> 一旦你有了 MCP 客户端，智能体（Agent）就字面只是它上面的一个 while 循环。

在这篇短文里，我会带你走一遍我在 Typescript（JS）里的实现，看看你如何采纳 MCP，以及它如何让智能体 AI 在未来变得简单得多。

如果你有 NodeJS（配 `pnpm` 或 `npm`），在终端里直接运行：

```

```

或用 `pnpm`：

```

```

你会看到简单的 Agent 连上两个（在本地运行的）MCP 服务器、加载它们的工具，然后提示你开始对话。

## 代码在哪里

Tiny Agent 的代码位于 `huggingface.js` 单仓的 `mcp-client` 子包——这是我们所有 JS 库所在的 GitHub 单仓。

[https://github.com/huggingface/huggingface.js/tree/main/packages/mcp-client](https://github.com/huggingface/huggingface.js/tree/main/packages/mcp-client)

> 代码库使用了现代 JS 特性（尤其是异步生成器），这让实现容易得多，特别是 LLM 响应这类异步事件。如果你还不熟悉这些 JS 特性，可以去问问大模型。

## 这一切的基础：LLM 原生支持工具调用

让整篇博客变得如此简单的前提是：新一代 LLM（无论闭源开源）都经过函数调用（function calling，也就是工具使用）的训练。

一个工具由名称、描述和参数的 JSONSchema 表示定义。某种意义上，它就是任意函数接口的外部（即 LLM 视角——它不关心函数实际怎么实现）的不透明表示。

```
const weatherTool = {
    type: "function",
    function: {
        name: "get_weather",
        description: "Get current temperature for a given location.",
        parameters: {
            type: "object",
            properties: {
                location: {
                    type: "string",
                    description: "City and country e.g. Bogotá, Colombia",
                },
            },
        },
    },
};
```

我在这里要引用的权威文档是 [OpenAI 的函数调用指南](https://platform.openai.com/docs/guides/function-calling?api-mode=chat)。（是的……整个社区的 LLM 标准差不多是 OpenAI 定的 😅）

推理引擎允许你在调用 LLM 时传入一个工具列表，LLM 可以自行调用零个、一个或多个工具。作为开发者，你负责执行这些工具，并把结果喂回 LLM 继续生成。

> 注意：在底层（推理引擎层面），工具其实只是像其他消息一样，以特定格式化的 chat_template 传给模型，然后再从响应里解析出来（使用模型特有的特殊 token），以工具调用的形式暴露。可在我们的 chat-template playground 里看示例。

## 在 InferenceClient 之上实现 MCP 客户端

既然知道了近期 LLM 里工具是什么，我们来实现真正的 MCP 客户端。

[https://modelcontextprotocol.io/quickstart/client](https://modelcontextprotocol.io/quickstart/client) 的官方文档写得相当不错。你只需要把文中所有 Anthropic 客户端 SDK 换成任意 OpenAI 兼容的客户端 SDK。（还有一份 [llms.txt](https://modelcontextprotocol.io/llms-full.txt)，可以喂给你喜欢的 LLM 帮你照着写代码。）

提醒一下，我们的推理客户端用的是 HF 的 `InferenceClient`。

> 完整的 McpClient.ts 代码文件在这里，想跟着真实代码阅读的话请自取 🤓

我们的 `McpClient` 类包含：

- 一个推理客户端（任意 Inference Provider 都行；`huggingface/inference` 对远程和本地端点都支持）
- 一组 MCP 客户端会话，每个已连接的 MCP 服务器一个（是的，我们要支持多服务器）
- 一份可用工具列表，从已连接的服务器填入，只需轻微重新格式化。

```
export class McpClient {
    protected client: InferenceClient;
    protected provider: string;
    protected model: string;
    private clients: Map<ToolName, Client> = new Map();
    public readonly availableTools: ChatCompletionInputTool[] = [];

    constructor({ provider, model, apiKey }: { provider: InferenceProvider; model: string; apiKey: string }) {
        this.client = new InferenceClient(apiKey);
        this.provider = provider;
        this.model = model;
    }
    
    // [...]
}
```

要连接 MCP 服务器，官方 `@modelcontextprotocol/sdk/client` TypeScript SDK 提供了一个 `Client` 类，带 `listTools()` 方法：

```
async addMcpServer(server: StdioServerParameters): Promise<void> {
    const transport = new StdioClientTransport({
        ...server,
        env: { ...server.env, PATH: process.env.PATH ?? "" },
    });
    const mcp = new Client({ name: "@huggingface/mcp-client", version: packageVersion });
    await mcp.connect(transport);

    const toolsResult = await mcp.listTools();
    debug(
        "Connected to server with tools:",
        toolsResult.tools.map(({ name }) => name)
    );

    for (const tool of toolsResult.tools) {
        this.clients.set(tool.name, mcp);
    }

    this.availableTools.push(
        ...toolsResult.tools.map((tool) => {
            return {
                type: "function",
                function: {
                    name: tool.name,
                    description: tool.description,
                    parameters: tool.inputSchema,
                },
            } satisfies ChatCompletionInputTool;
        })
    );
}
```

`StdioServerParameters` 是 MCP SDK 的一个接口，能让你轻松启动一个本地进程：如前所述，目前所有 MCP 服务器都是本地进程。

对每个连接上的 MCP 服务器，我们把它那份工具列表轻微重新格式化后加进 `this.availableTools`。

### 怎么使用工具

简单，把 `this.availableTools` 连同常规的 messages 数组一起传给 LLM 的 chat-completion：

```
const stream = this.client.chatCompletionStream({
    provider: this.provider,
    model: this.model,
    messages,
    tools: this.availableTools,
    tool_choice: "auto",
});
```

`tool_choice: "auto"` 就是让 LLM 自行决定生成零个、一个或多个工具调用的参数。

在解析或流式读取输出时，LLM 会生成若干工具调用（即函数名 + JSON 编码的参数），需要由你（开发者）来执行。MCP 客户端 SDK 再次让这变得很简单：它有 `client.callTool()` 方法：

```
const toolName = toolCall.function.name;
const toolArgs = JSON.parse(toolCall.function.arguments);

const toolMessage: ChatCompletionInputMessageTool = {
    role: "tool",
    tool_call_id: toolCall.id,
    content: "",
    name: toolName,
};

/// Get the appropriate session for this tool
const client = this.clients.get(toolName);
if (client) {
    const result = await client.callTool({ name: toolName, arguments: toolArgs });
    toolMessage.content = result.content[0].text;
} else {
    toolMessage.content = `Error: No session found for tool: ${toolName}`;
}
```

最后把生成的 tool 消息加入 `messages` 数组，再喂回 LLM。

## 我们的 50 行代码智能体 🤯

现在我们有了一个 MCP 客户端：能连接任意 MCP 服务器拿到工具列表，也能把工具注入 LLM 推理并解析出工具调用。那么……智能体又是什么？

> 一旦你有了一个带工具集的推理客户端，智能体就只是它上面的一个 while 循环。

详细一点，智能体就是这么几样东西的组合：

- 一条系统提示词
- 一个 LLM 推理客户端
- 一个 MCP 客户端，把一堆 MCP 服务器的工具挂到推理上
- 一些基本控制流（while 循环见下文）

> 完整的 Agent.ts 代码文件在这里。

我们的 Agent 类只是继承 McpClient：

```
export class Agent extends McpClient {
    private readonly servers: StdioServerParameters[];
    protected messages: ChatCompletionInputMessage[];

    constructor({
        provider,
        model,
        apiKey,
        servers,
        prompt,
    }: {
        provider: InferenceProvider;
        model: string;
        apiKey: string;
        servers: StdioServerParameters[];
        prompt?: string;
    }) {
        super({ provider, model, apiKey });
        this.servers = servers;
        this.messages = [
            {
                role: "system",
                content: prompt ?? DEFAULT_SYSTEM_PROMPT,
            },
        ];
    }
}
```

默认我们使用一条非常简单的系统提示词，灵感来自 [GPT-4.1 提示指南](https://cookbook.openai.com/examples/gpt4-1_prompting_guide)里分享的那条。

虽然它出自 OpenAI 😈，但其中这句话越来越适用于闭源和开源的众多模型：

> 我们鼓励开发者只用 tools 字段传工具，而不是手动把工具说明塞进提示词、再为工具调用单独写解析器——过去有人这么做。

也就是说，我们不需要在提示词里精心构造一大堆工具使用示例。`tools: this.availableTools` 这个参数就够了。

给 Agent 加载工具，字面上就是连接我们想要的那些 MCP 服务器（在 JS 里并行做太容易了）：

```
async loadTools(): Promise<void> {
    await Promise.all(this.servers.map((s) => this.addMcpServer(s)));
}
```

我们额外加了两个（MCP 之外的）工具，供 LLM 在 Agent 控制流中使用：

```
const taskCompletionTool: ChatCompletionInputTool = {
    type: "function",
    function: {
        name: "task_complete",
        description: "Call this tool when the task given by the user is complete",
        parameters: {
            type: "object",
            properties: {},
        },
    },
};
const askQuestionTool: ChatCompletionInputTool = {
    type: "function",
    function: {
        name: "ask_question",
        description: "Ask a question to the user to get more info required to solve or clarify their problem.",
        parameters: {
            type: "object",
            properties: {},
        },
    },
};
const exitLoopTools = [taskCompletionTool, askQuestionTool];
```

一旦调用这两个工具之一，Agent 就跳出循环，把控制权交还给用户等待新输入。

### 完整的 while 循环

瞧瞧我们的完整 while 循环。🎉

Agent 主 while 循环的要旨：我们与 LLM 轮流交替——它调用工具、我们喂回工具结果——**直到 LLM 连续两次返回不带工具调用的回复**。

这就是完整的 while 循环：

```
let numOfTurns = 0;
let nextTurnShouldCallTools = true;
while (true) {
    try {
        yield* this.processSingleTurnWithTools(this.messages, {
            exitLoopTools,
            exitIfFirstChunkNoTool: numOfTurns > 0 && nextTurnShouldCallTools,
            abortSignal: opts.abortSignal,
        });
    } catch (err) {
        if (err instanceof Error && err.message === "AbortError") {
            return;
        }
        throw err;
    }
    numOfTurns++;
    const currentLast = this.messages.at(-1)!;
    if (
        currentLast.role === "tool" &&
        currentLast.name &&
        exitLoopTools.map((t) => t.function.name).includes(currentLast.name)
    ) {
        return;
    }
    if (currentLast.role !== "tool" && numOfTurns > MAX_NUM_TURNS) {
        return;
    }
    if (currentLast.role !== "tool" && nextTurnShouldCallTools) {
        return;
    }
    if (currentLast.role === "tool") {
        nextTurnShouldCallTools = false;
    } else {
        nextTurnShouldCallTools = true;
    }
}
```
