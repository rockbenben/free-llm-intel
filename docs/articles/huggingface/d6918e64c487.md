# AudioLDM 2，但更快 ⚡️

作者：Sanchit Gandhi（sanchit-gandhi）

本文另有中文版本 [简体中文](https://huggingface.co/blog/zh/audioldm2)。

AudioLDM 2 出自 Haohe Liu 等人的论文 [AudioLDM 2: Learning Holistic Audio Generation with Self-supervised Pretraining](https://arxiv.org/abs/2308.05734)。AudioLDM 2 以文本提示为输入，预测对应的音频，可以生成逼真的音效、人声和音乐。

虽然生成的音频质量很高，但用原始实现做推理非常慢：生成一段 10 秒的音频样例要花 30 秒以上。原因是多重因素叠加：深层多阶段的建模方式、巨大的 checkpoint 尺寸，以及未优化的代码。

在这篇博客里，我们演示如何在 Hugging Face 🧨 Diffusers 库中使用 AudioLDM 2，探索一系列代码优化（半精度、flash attention、编译）和模型优化（调度器选择、负向提示），把推理时间降低 **10 倍以上**，而输出音频质量几乎无损。博客还配了一个更精简的 [Colab notebook](https://colab.research.google.com/github/sanchit-gandhi/notebooks/blob/main/AudioLDM-2.ipynb)，包含全部代码但解释更少。

看到最后，你会发现如何只用 1 秒生成一段 10 秒的音频！

## 模型概览

AudioLDM 2 受 [Stable Diffusion](https://huggingface.co/docs/diffusers/api/pipelines/stable_diffusion/overview) 启发，是一个文本到音频的*潜空间扩散模型（LDM）*，从文本嵌入学习连续的音频表示。

整体生成过程概括如下：

- 给定文本输入 x\boldsymbol{x}x，用两个文本编码器计算文本嵌入：[CLAP](https://huggingface.co/docs/transformers/main/en/model_doc/clap) 的文本分支和 [Flan-T5](https://huggingface.co/docs/transformers/main/en/model_doc/flan-t5) 的文本编码器

E1=CLAP(x);E2=T5(x) \boldsymbol{E}_{1} = \text{CLAP}\left(\boldsymbol{x} \right); \quad \boldsymbol{E}_{2} = \text{T5}\left(\boldsymbol{x}\right) E1​=CLAP(x);E2​=T5(x)

CLAP 文本嵌入经过训练，与对应音频样本的嵌入对齐；Flan-T5 嵌入则更好地表示文本的语义。

- 这些文本嵌入通过各自的线性投影映射到共享嵌入空间：

P1=WCLAPE1;P2=WT5E2 \boldsymbol{P}_{1} = \boldsymbol{W}_{\text{CLAP}} \boldsymbol{E}_{1}; \quad \boldsymbol{P}_{2} = \boldsymbol{W}_{\text{T5}}\boldsymbol{E}_{2} P1​=WCLAP​E1​;P2​=WT5​E2​

在 `diffusers` 实现中，这些投影由 [AudioLDM2ProjectionModel](https://huggingface.co/docs/diffusers/api/pipelines/audioldm2/AudioLDM2ProjectionModel) 定义。

- 用一个 [GPT2](https://huggingface.co/docs/transformers/main/en/model_doc/gpt2) 语言模型（LM），以投影后的 CLAP 和 Flan-T5 嵌入为条件，自回归生成 NNN 个新嵌入向量：

E~i=GPT2(P1,P2,E~1:i−1)for i=1,…,N \tilde{\boldsymbol{E}}_{i} = \text{GPT2}\left(\boldsymbol{P}_{1}, \boldsymbol{P}_{2}, \tilde{\boldsymbol{E}}_{1:i-1}\right) \qquad \text{for } i=1,\dots,N E~i​=GPT2(P1​,P2​,E~1:i−1​)for i=1,…,N

- 生成的嵌入向量 E~1:N\tilde{\boldsymbol{E}}_{1:N}E~1:N​ 和 Flan-T5 文本嵌入 E2\boldsymbol{E}_{2}E2​ 作为 LDM 的交叉注意力条件；LDM 通过逆向扩散过程对随机潜变量*去噪*。LDM 的逆向扩散共跑 TTT 个推理步：

zt=LDM(zt−1∣E~1:N,E2)for t=1,…,T \boldsymbol{z}_{t} = \text{LDM}\left(\boldsymbol{z}_{t-1} | \tilde{\boldsymbol{E}}_{1:N}, \boldsymbol{E}_{2}\right) \qquad \text{for } t = 1, \dots, T zt​=LDM(zt−1​∣E~1:N​,E2​)for t=1,…,T

其中初始潜变量 z0\boldsymbol{z}_{0}z0​ 取自正态分布 N(0,I)\mathcal{N} \left(\boldsymbol{0}, \boldsymbol{I} \right)N(0,I)。LDM 的 [UNet](https://huggingface.co/docs/diffusers/api/pipelines/audioldm2/AudioLDM2UNet2DConditionModel) 很特别：它接收**两组**交叉注意力嵌入——来自 GPT2 语言模型的 E~1:N\tilde{\boldsymbol{E}}_{1:N}E~1:N​ 和来自 Flan-T5 的 E2\boldsymbol{E}_{2}E2​——而多数 LDM 只有一组交叉注意力条件。

- 最终去噪得到的潜变量 zT\boldsymbol{z}_{T}zT​ 送入 VAE 解码器，恢复梅尔频谱 s\boldsymbol{s}s：

s=VAEdec(zT) \boldsymbol{s} = \text{VAE}_{\text{dec}} \left(\boldsymbol{z}_{T}\right) s=VAEdec​(zT​)

- 梅尔频谱再送入声码器，得到输出音频波形 y\mathbf{y}y：

y=Vocoder(s) \boldsymbol{y} = \text{Vocoder}\left(\boldsymbol{s}\right) y=Vocoder(s)

下图展示了文本输入如何经过文本条件模型，两组提示嵌入在 LDM 中作为交叉条件：

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/161_audioldm2/audioldm2.png?raw=true)

关于 AudioLDM 2 的完整训练细节，请参阅 [AudioLDM 2 论文](https://arxiv.org/abs/2308.05734)。

Hugging Face 🧨 Diffusers 提供了端到端推理流水线类 [`AudioLDM2Pipeline`](https://huggingface.co/docs/diffusers/main/en/api/pipelines/audioldm2)，把这个多阶段生成过程包装成单个可调用对象，几行代码即可从文本生成音频。

AudioLDM 2 有三个变体。其中两个 checkpoint 适用于通用的文本到音频生成，第三个只在文本到音乐生成上训练。三个官方 checkpoint 的详情见下表，都能在 [Hugging Face Hub](https://huggingface.co/models?search=cvssp/audioldm2) 找到：

| --- | --- | --- | --- |
| [cvssp/audioldm2](https://huggingface.co/cvssp/audioldm2) | 文本到音频 | 1.1B | 1150k |
| [cvssp/audioldm2-music](https://huggingface.co/cvssp/audioldm2-music) | 文本到音乐 | 1.1B | 665k |
| [cvssp/audioldm2-large](https://huggingface.co/cvssp/audioldm2-large) | 文本到音频 | 1.5B | 1150k |

概述了 AudioLDM 2 生成过程的高层原理后，我们来把理论落地！

## 加载流水线

本教程使用基座 checkpoint [cvssp/audioldm2](https://huggingface.co/cvssp/audioldm2) 的预训练权重初始化流水线。用 [`.from_pretrained`](https://huggingface.co/docs/diffusers/main/en/api/pipelines/overview#diffusers.DiffusionPipeline.from_pretrained) 方法即可加载整条流水线，它会实例化流水线并加载预训练权重：

```
from diffusers import AudioLDM2Pipeline

model_id = "cvssp/audioldm2"
pipe = AudioLDM2Pipeline.from_pretrained(model_id)
```

**输出：**

```
Loading pipeline components...: 100%|███████████████████████████████████████████| 11/11 [00:01<00:00,  7.62it/s]
```

把流水线移到 GPU 的方式与标准 PyTorch nn 模块一样：

```
pipe.to("cuda");
```

好！我们定义一个 Generator 并设置种子保证可复现。这样就能固定 LDM 的初始潜变量，改提示词时能看清提示对生成结果的影响：

```
import torch

generator = torch.Generator("cuda").manual_seed(0)
```

现在可以完成第一次生成了！整篇教程我们会一直用同一个运行示例：固定文本提示加固定种子。[`audio_length_in_s`](https://huggingface.co/docs/diffusers/main/en/api/pipelines/audioldm2#diffusers.AudioLDM2Pipeline.__call__.audio_length_in_s) 参数控制生成音频的时长，默认是 LDM 训练时的音频长度（10.24 秒）：

```
prompt = "The sound of Brazilian samba drums with waves gently crashing in the background"

audio = pipe(prompt, audio_length_in_s=10.24, generator=generator).audios[0]
```

**输出：**

```
100%|███████████████████████████████████████████| 200/200 [00:13<00:00, 15.27it/s]
```

好！这次运行大约花了 13 秒。听听输出的音频：

```
from IPython.display import Audio

Audio(audio, rate=16000)
```

听起来跟我们的文本提示很像！质量不错，但仍有背景噪声的痕迹。我们可以给流水线一个[*负向提示*](https://huggingface.co/docs/diffusers/main/en/api/pipelines/audioldm2#diffusers.AudioLDM2Pipeline.__call__.negative_prompt)，抑制某些生成特征。这里我们传入一个抑制低质量音频的负向提示，并省略 `audio_length_in_s` 参数让它取默认值：

```
negative_prompt = "Low quality, average quality."

audio = pipe(prompt, negative_prompt=negative_prompt, generator=generator.manual_seed(0)).audios[0]
```

**输出：**

```

```

使用负向提示不会改变推理时间 1{}^11——我们只是把 LDM 的无条件输入替换成负向输入。也就是说音频质量上的收益是白送的。

听听结果音频：

```

```

整体音质确实有提升——噪声痕迹更少，音频整体更清脆。 1{}^11 注意，实践中从第一次生成到第二次，推理时间通常会有所下降，因为第一次计算时 CUDA 会"热身"。第二次生成才是对我们实际推理时间的更好度量。

## 优化 1：Flash Attention

PyTorch 2.0 及以上版本包含一个对注意力操作优化、省内存的实现 [`torch.nn.functional.scaled_dot_product_attention`](https://pytorch.org/docs/master/generated/torch.nn.functional.scaled_dot_product_attention)（SDPA）。该函数会根据输入自动应用多种内置优化，比原版注意力实现更快、更省内存。整体上，SDPA 给出的行为类似论文 [Fast and Memory-Efficient Exact Attention with IO-Awareness](https://arxiv.org/abs/2205.14135)（Dao 等）提出的 *flash attention*。

只要安装了 PyTorch 2.0 且 `torch.nn.functional.scaled_dot_product_attention` 可用，Diffusers 就会默认启用这些优化。你只需按[官方说明](https://pytorch.org/get-started/locally/)安装 torch 2.0 或更高版本，然后照常使用流水线即可 🚀

```
audio = pipe(prompt, negative_prompt=negative_prompt, generator=generator.manual_seed(0)).audios[0]
```

**输出：**

```
100%|███████████████████████████████████████████| 200/200 [00:12<00:00, 16.60it/s]
```

关于 SDPA 在 `diffusers` 中的使用细节，参考对应[文档](https://huggingface.co/docs/diffusers/optimization/torch2.0)。

## 优化 2：半精度

默认情况下，`AudioLDM2Pipeline` 以 float32（全）精度加载模型权重，所有模型计算也在 float32 精度进行。推理时，我们可以安全地把权重和计算转为 float16（半）精度，这会改善推理时间和 GPU 显存占用，而生成质量的变化几乎不可感知。

只需给 `.from_pretrained` 传入 [`torch_dtype`](https://huggingface.co/docs/diffusers/main/en/api/pipelines/overview#diffusers.DiffusionPipeline.from_pretrained.torch_dtype) 参数，以 float16 精度加载权重：

```
pipe = AudioLDM2Pipeline.from_pretrained(model_id, torch_dtype=torch.float16)

pipe.to("cuda");
```

用 float16 精度做一次生成并听听输出：

```
audio = pipe(prompt, negative_prompt=negative_prompt, generator=generator.manual_seed(0)).audios[0]

Audio(audio, rate=16000)
```

**输出：**

```
100%|███████████████████████████████████████████| 200/200 [00:09<00:00, 20.94it/s]
```

Your browser does not support the audio element.

音频质量与全精度生成基本无异，推理快了约 2 秒。以我们的经验，使用 `diffusers` 流水线的 float16 精度从未造成明显的音频劣化，却总能稳定换来大幅加速。因此建议默认使用 float16。

## 优化 3：Torch Compile

还想再快一点？可以使用新的 `torch.compile` 特性。由于流水线中 UNet 通常是计算最重的部分，我们只把 unet 用 `torch.compile` 包起来，其余子模型（文本编码器和 VAE）保持原样：

```
pipe.unet = torch.compile(pipe.unet, mode="reduce-overhead", fullgraph=True)
```

UNet 被 `torch.compile` 包装后，第一次推理通常很慢——因为要为 UNet 的前向传播编译付出开销。我们先跑一次流水线把这次长耗时消化掉。注意编译第一步可能耗时接近 2 分钟，请耐心等待！

```
audio = pipe(prompt, negative_prompt=negative_prompt, generator=generator.manual_seed(0)).audios[0]
```

**输出：**

```
100%|███████████████████████████████████████████| 200/200 [01:23<00:00,  2.39it/s]
```

好！UNet 编译完成后，跑完整扩散过程就能享受加速了：

```
audio = pipe(prompt, negative_prompt=negative_prompt, generator=generator.manual_seed(0)).audios[0]
```

**输出：**

```
100%|███████████████████████████████████████████| 200/200 [00:04<00:00, 48.98it/s]
```

只要 4 秒！实践中，UNet 只需编译一次，之后的每次生成都更快。也就是说编译耗时会被后续推理的收益摊平。更多 `torch.compile` 的信息和选项见 [torch compile 文档](https://pytorch.org/tutorials/intermediate/torch_compile_tutorial.html)。

## 优化 4：调度器

另一个选项是减少推理步数。选择更高效的调度器，可以在不牺牲音频质量的前提下减少步数。调用 [`schedulers.compatibles`](https://huggingface.co/docs/diffusers/v0.20.0/en/api/schedulers/overview#diffusers.SchedulerMixin) 属性即可查看哪些调度器与 `AudioLDM2Pipeline` 兼容：

```
pipe.scheduler.compatibles
```

**输出：**

```

好！一大串可选调度器 📝。默认情况下 AudioLDM 2 使用 [`DDIMScheduler`](https://huggingface.co/docs/diffusers/api/schedulers/ddim)，需要 200 个推理步才能得到不错的音频质量。而像 [`DPMSolverMultistepScheduler`](https://huggingface.co/docs/diffusers/main/en/api/schedulers/multistep_dpm_solver#diffusers.DPMSolverMultistepScheduler) 这样更高效的调度器，只需要 **20-25 个推理步**就能达到相近效果。

看看如何把 AudioLDM 2 的调度器从 DDIM 换成 DPM Multistep。我们用 [`ConfigMixin.from_config()`](https://huggingface.co/docs/diffusers/main/en/api/configuration#diffusers.ConfigMixin.from_config) 方法，基于原 [`DDIMScheduler`](https://huggingface.co/docs/diffusers/api/schedulers/ddim) 的配置加载 [`DPMSolverMultistepScheduler`](https://huggingface.co/docs/diffusers/main/en/api/schedulers/multistep_dpm_solver#diffusers.DPMSolverMultistepScheduler)：

```
from diffusers import DPMSolverMultistepScheduler

pipe.scheduler = DPMSolverMultistepScheduler.from_config(pipe.scheduler.config)
```

把推理步数设为 20，用新调度器重跑生成。由于 LDM 潜变量的形状没变，不需要重新编译：

```
audio = pipe(prompt, negative_prompt=negative_prompt, num_inference_steps=20, generator=generator.manual_seed(0)).audios[0]
```

**输出：**

```
100%|███████████████████████████████████████████| 20/20 [00:00<00:00, 49.14it/s]
```

生成音频只用了不到 **1 秒**！听听结果：

```
Audio(audio, rate=16000)
```

和最初的音频样例基本一样，生成时间却只是零头！🧨 Diffusers 流水线的设计讲究*可组合*，你可以轻松替换调度器等组件，换上性能更好的对应项。

## 显存怎么办？

我们想生成的音频时长决定了 LDM 中去噪潜变量的*宽度*。由于 UNet 交叉注意力层的显存随序列长度（宽度）平方增长，生成很长的音频可能触发 OOM。批大小同样影响显存，它控制生成的样本数量。

前面提过，以 float16 半精度加载模型能大幅省内存。使用 PyTorch 2.0 的 SDPA 也能省内存，但对超长序列可能仍不够。

试生成一段 2.5 分钟（150 秒）的音频。同时通过 [`num_waveforms_per_prompt`](https://huggingface.co/docs/diffusers/main/en/api/pipelines/audioldm2#diffusers.AudioLDM2Pipeline.__call__.num_waveforms_per_prompt)`=4` 生成 4 个候选音频。当 [`num_waveforms_per_prompt`](https://huggingface.co/docs/diffusers/main/en/api/pipelines/audioldm2#diffusers.AudioLDM2Pipeline.__call__.num_waveforms_per_prompt)`>1` 时，会自动对生成音频与文本提示打分：音频和文本嵌入到 CLAP 音频-文本嵌入空间，再按余弦相似度排序。位置 `0` 的就是"最佳"波形。

由于我们改了 UNet 潜变量的宽度，必须针对新潜变量形状再做一次 torch 编译。为了省时间，我们直接重新加载不带 torch compile 的流水线，避免一上来就吃一次漫长的编译：

```
pipe = AudioLDM2Pipeline.from_pretrained(model_id, torch_dtype=torch.float16)

pipe.to("cuda")

audio = pipe(prompt, negative_prompt=negative_prompt, num_waveforms_per_prompt=4, audio_length_in_s=150, num_inference_steps=20, generator=generator.manual_seed(0)).audios[0]
```

除非你的 GPU 显存足够大，上面的代码大概率会报 OOM。虽然 AudioLDM 2 流水线包含多个组件，但任一时刻只有正在使用的模型需要待在 GPU 上，其余模块可以卸载到 CPU。这个技术叫 *CPU offload*（CPU 卸载），能降低显存占用，代价是推理时间只有很轻微的损失。

用 [enable_model_cpu_offload()](https://huggingface.co/docs/diffusers/main/en/api/pipelines/audioldm2#diffusers.AudioLDM2Pipeline.enable_model_cpu_offload) 函数即可为流水线开启 CPU 卸载：

```python
pipe.enable_model_cpu_offload()
```

Running generation with CPU offload is then the same as before:

```
audio = pipe(prompt, negative_prompt=negative_prompt, num_waveforms_per_prompt=4, audio_length_in_s=150, num_inference_steps=20, generator=generator.manual_seed(0)).audios[0]
```

**Output:**

```
100%|███████████████████████████████████████████| 20/20 [00:36<00:00,  1.82s/it]
```

这样，一次调用就能生成 4 段、每段 150 秒的音频！使用 large 版 AudioLDM 2 checkpoint 时总显存占用会更高（UNet 参数量 750M，是基座 350M 的两倍多），所以这个省显存技巧在这种情况下尤其有用。

## 结论

在这篇博客里，我们演示了 🧨 Diffusers 开箱即用的四种优化方法，把 AudioLDM 2 的生成时间从 14 秒压到不足 1 秒。我们还介绍了如何用半精度、CPU 卸载等省显存技巧，降低长音频或大 checkpoint 场景的峰值显存。
