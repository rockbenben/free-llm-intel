最近，我们介绍了最新一代的 [Intel Xeon](https://www.intel.com/content/www/us/en/products/details/processors/xeon/scalable.html) CPU（代号 Sapphire Rapids）、它用于深度学习加速的新硬件特性，以及如何利用它们来加速自然语言处理 Transformers 的[分布式微调](https://huggingface.co/blog/intel-sapphire-rapids)和[推理](https://huggingface.co/blog/intel-sapphire-rapids-inference)。

在本文中，我们将向你展示在 Sapphire Rapids CPU 上加速 Stable Diffusion 模型的不同技术。后续文章会针对分布式微调做同样的事情。

在撰写本文时，入手一台 Sapphire Rapids 服务器最简单的方式是使用 Amazon EC2 的 [R7iz](https://aws.amazon.com/ec2/instance-types/r7iz/) 实例系列。由于它仍处于预览阶段，你必须[注册](https://pages.awscloud.com/R7iz-Preview.html)才能获得访问权限。和之前的文章一样，我使用的是一台 `r7iz.metal-16xl` 实例（64 vCPU，512GB 内存），配 Ubuntu 20.04 AMI（`ami-07cd3e6c4915b2d18`）。

我们开始吧！代码示例可在 [Gitlab](https://gitlab.com/juliensimon/huggingface-demos/-/tree/main/optimum/stable_diffusion_intel) 上获取。

## Diffusers 库

[Diffusers](https://huggingface.co/docs/diffusers/index) 库让用 Stable Diffusion 模型生成图像变得极其简单。如果你还不熟悉这些模型，这里有一篇很棒的[图文入门](https://jalammar.github.io/illustrated-stable-diffusion/)。

首先，让我们用所需的库创建一个虚拟环境：Transformers、Diffusers、Accelerate 和 PyTorch。

```
virtualenv sd_inference
source sd_inference/bin/activate
pip install pip --upgrade
pip install transformers diffusers accelerate torch==1.13.1
```

然后，我们编写一个简单的基准测试函数，反复运行推理，并返回单次图像生成的平均延迟。

```
import time

def elapsed_time(pipeline, prompt, nb_pass=10, num_inference_steps=20):
    # warmup
    images = pipeline(prompt, num_inference_steps=10).images
    start = time.time()
    for _ in range(nb_pass):
        _ = pipeline(prompt, num_inference_steps=num_inference_steps, output_type="np")
    end = time.time()
    return (end - start) / nb_pass
```

现在，让我们用默认的 `float32` 数据类型构建一个 `StableDiffusionPipeline`，并测量它的推理延迟。

```
from diffusers import StableDiffusionPipeline

model_id = "runwayml/stable-diffusion-v1-5"
pipe = StableDiffusionPipeline.from_pretrained(model_id)
prompt = "sailing ship in storm by Rembrandt"
latency = elapsed_time(pipe, prompt)
print(latency)
```

平均延迟为 **32.3 秒**。正如这个 [Intel Space](https://huggingface.co/spaces/Intel/Stable-Diffusion-Side-by-Side) 所演示的，同样的代码在上一代 Intel Xeon（代号 Ice Lake）上大约需要 45 秒。

开箱即用，我们可以看到 Sapphire Rapids CPU 无需任何代码改动就已经快了不少！

现在，让我们进一步加速！

## Optimum Intel 与 OpenVINO

[Optimum Intel](https://huggingface.co/docs/optimum/intel/index) 可在 Intel 架构上加速端到端管线。它的 API 与原始的 [Diffusers](https://huggingface.co/docs/diffusers/index) API 极为相似，使改造现有代码变得轻而易举。

Optimum Intel 支持 [OpenVINO](https://docs.openvino.ai/latest/index.html)，这是 Intel 面向高性能推理的开源工具包。

Optimum Intel 和 OpenVINO 可以如下安装：

```
pip install optimum[openvino]
```

从上面的代码出发，我们只需要把 `StableDiffusionPipeline` 替换成 `OVStableDiffusionPipeline`。要加载一个 PyTorch 模型并即时转换为 OpenVINO 格式，你可以在加载模型时设置 `export=True`。

```
from optimum.intel.openvino import OVStableDiffusionPipeline
...
ov_pipe = OVStableDiffusionPipeline.from_pretrained(model_id, export=True)
latency = elapsed_time(ov_pipe, prompt)
print(latency)

# Don't forget to save the exported model
ov_pipe.save_pretrained("./openvino")
```

OpenVINO 会自动为 `bfloat16` 格式优化模型。得益于这一点，平均延迟现在降到 **16.7 秒**，是一个惬意的 2 倍加速。

上面的管线支持动态输入形状，对图像数量或分辨率没有限制。对于 Stable Diffusion，你的应用通常被限制到一个（或少数几个）不同的输出分辨率，比如 512x512 或 256x256。因此，把管线重塑（reshape）为固定分辨率来解锁显著的加速是非常合理的。如果你需要多个输出分辨率，只需为每个分辨率各保留几个管线实例即可。

```
ov_pipe.reshape(batch_size=1, height=512, width=512, num_images_per_prompt=1)
latency = elapsed_time(ov_pipe, prompt)
```

使用静态形状后，平均延迟被大幅削减到 **4.7 秒**，额外带来 3.5 倍加速。

正如你所见，OpenVINO 是一种简单而高效的加速 Stable Diffusion 推理的方式。当与 Sapphire Rapids CPU 结合时，相比在 Ice Lake Xeon 上的原始推理，它带来接近 10 倍的加速。

如果你无法或不想使用 OpenVINO，本文的其余部分将向你展示一系列其他优化技术。系好安全带！

## 系统级优化

Diffuser 模型是数 GB 的大型模型，而图像生成是一个内存密集型操作。通过安装一个高性能内存分配库，我们应该能够加速内存操作，并将它们跨 Xeon 核心并行化。请注意，这会改变你系统上默认的内存分配库。当然，你可以通过卸载新库回到默认库。

[jemalloc](https://jemalloc.net/) 和 [tcmalloc](https://github.com/gperftools/gperftools) 同样值得考虑。在这里，我安装 `jemalloc`，因为我的测试显示它有略微的性能优势。它也可以针对特定工作负载进行调优，例如最大化 CPU 利用率。你可以参考[调优指南](https://github.com/jemalloc/jemalloc/blob/dev/TUNING.md)了解详情。

```
sudo apt-get install -y libjemalloc-dev
export LD_PRELOAD=$LD_PRELOAD:/usr/lib/x86_64-linux-gnu/libjemalloc.so
export MALLOC_CONF="oversize_threshold:1,background_thread:true,metadata_thp:auto,dirty_decay_ms: 60000,muzzy_decay_ms:60000"
```

接下来，我们安装 `libiomp` 库以优化并行处理。它是 [Intel OpenMP* Runtime](https://www.intel.com/content/www/us/en/docs/cpp-compiler/developer-guide-reference/2021-8/openmp-run-time-library-routines.html) 的一部分。

```
sudo apt-get install intel-mkl
export LD_PRELOAD=$LD_PRELOAD:/usr/lib/x86_64-linux-gnu/libiomp5.so
export OMP_NUM_THREADS=32
```

最后，我们安装 [numactl](https://github.com/numactl/numactl) 命令行工具。这让我们可以把 Python 进程绑定到特定的核心，避免一些与上下文切换相关的开销。

```
numactl -C 0-31 python sd_blog_1.py
```

多亏这些优化，我们最初的 Diffusers 代码现在只需 **11.8 秒** 即可预测。这几乎快 3 倍，而且没有任何代码改动。这些工具在我们这台 32 核 Xeon 上确实表现出色。

我们远未结束。让我们把 Intel Extension for PyTorch 也加进来。

## IPEX 与 BF16

[Intel Extension for Pytorch](https://intel.github.io/intel-extension-for-pytorch/)（IPEX）扩展了 PyTorch，并利用 Intel CPU 上的硬件加速特性，例如 [AVX-512](https://en.wikipedia.org/wiki/AVX-512) 向量神经网络指令（AVX512 VNNI）和[高级矩阵扩展](https://en.wikipedia.org/wiki/Advanced_Matrix_Extensions)（AMX）。

我们来安装它。

```
pip install intel_extension_for_pytorch==1.13.100
```

然后我们更新代码，用 IPEX 优化管线的每个元素（你可以打印 `pipe` 对象来列出它们）。这需要将它们转换为 channels-last 格式。

```
import torch
import intel_extension_for_pytorch as ipex
...
pipe = StableDiffusionPipeline.from_pretrained(model_id)

# to channels last
pipe.unet = pipe.unet.to(memory_format=torch.channels_last)
pipe.vae = pipe.vae.to(memory_format=torch.channels_last)
pipe.text_encoder = pipe.text_encoder.to(memory_format=torch.channels_last)
pipe.safety_checker = pipe.safety_checker.to(memory_format=torch.channels_last)

# Create random input to enable JIT compilation
sample = torch.randn(2,4,64,64)
timestep = torch.rand(1)*999
encoder_hidden_status = torch.randn(2,77,768)
input_example = (sample, timestep, encoder_hidden_status)

# optimize with IPEX
pipe.unet = ipex.optimize(pipe.unet.eval(), dtype=torch.bfloat16, inplace=True, sample_input=input_example)
pipe.vae = ipex.optimize(pipe.vae.eval(), dtype=torch.bfloat16, inplace=True)
pipe.text_encoder = ipex.optimize(pipe.text_encoder.eval(), dtype=torch.bfloat16, inplace=True)
pipe.safety_checker = ipex.optimize(pipe.safety_checker.eval(), dtype=torch.bfloat16, inplace=True)
```

我们还启用 `bfloat16` 数据格式，以利用 Sapphire Rapids CPU 上的 AMX 瓦片矩阵乘法单元（TMMU）加速器。

```
with torch.cpu.amp.autocast(enabled=True, dtype=torch.bfloat16):
    latency = elapsed_time(pipe, prompt)
    print(latency)
```

使用这个更新版本后，推理延迟从 11.9 秒进一步降低到 **5.4 秒**。多亏 IPEX 和 AMX，这是超过 2 倍的加速。

我们还能榨取更多性能吗？能，靠调度器（scheduler）！

## 调度器

Diffusers 库允许我们把一个[调度器](https://huggingface.co/docs/diffusers/using-diffusers/schedulers)附加到 Stable Diffusion 管线上。调度器试图在去噪速度和去噪质量之间找到最佳权衡。

根据文档：“*在撰写本文时，DPMSolverMultistepScheduler 可以说提供了最佳的速率/质量权衡，并且最少只需 20 步即可运行。*”

我们来试试。

```
from diffusers import StableDiffusionPipeline, DPMSolverMultistepScheduler
...
dpm = DPMSolverMultistepScheduler.from_pretrained(model_id, subfolder="scheduler")
pipe = StableDiffusionPipeline.from_pretrained(model_id, scheduler=dpm)
```

使用这个最终版本，推理延迟现在降到 **5.05 秒**。相比我们最初的 Sapphire Rapids 基线（32.3 秒），这几乎快了 6.5 倍！

*环境：Amazon EC2 r7iz.metal-16xl, Ubuntu 20.04, Linux 5.15.0-1031-aws, libjemalloc-dev 5.2.1-1, intel-mkl 2020.0.166-1, PyTorch 1.13.1, Intel Extension for PyTorch 1.13.1, transformers 4.27.2, diffusers 0.14, accelerate 0.17.1, openvino 2023.0.0.dev20230217, optimum 1.7.1, optimum-intel 1.7*
