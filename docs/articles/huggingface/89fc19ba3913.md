# Transformers.js v4：现已登陆 NPM！

我们很高兴地宣布，Transformers.js v4 已经在 NPM 上发布！经过一年开发（我们从 2025 年 3 月开工 🤯），它终于准备好交到你手上。

```
npm i @huggingface/transformers
```

## 性能与运行时改进

最大的变化无疑是引入了全新的 WebGPU Runtime——用 C++ 完全重写。我们与 ONNX Runtime 团队紧密合作，在我们支持的大约 200 种模型架构以及许多 v4 独有的新架构上对这个 runtime 做了充分测试。

除了更好的算子支持（性能、精度、覆盖度），这个新的 WebGPU runtime 让同一份 transformers.js 代码可以跑在各种 JavaScript 环境中，包括浏览器、服务端 runtime 和桌面应用。没错，你现在可以直接在 Node、Bun 和 Deno 里运行 WebGPU 加速的模型！

我们已经证明了"在浏览器里 100% 本地运行最先进 AI 模型"是可行的，现在我们把重心放在性能上：让这些模型跑得快一点、再快一点，哪怕在资源受限的环境里。这要求我们彻底重构导出策略，对大语言模型尤其如此。我们的做法是逐个算子地重新实现新模型，并利用 ONNX Runtime 的专用 [Contrib Operators](https://github.com/microsoft/onnxruntime/blob/main/docs/ContribOperators.md)，比如 [com.microsoft.GroupQueryAttention](https://github.com/microsoft/onnxruntime/blob/main/docs/ContribOperators.md#com.microsoft.GroupQueryAttention)、[com.microsoft.MatMulNBits](https://github.com/microsoft/onnxruntime/blob/main/docs/ContribOperators.md#com.microsoft.MatMulNBits)、[com.microsoft.QMoE](https://github.com/microsoft/onnxruntime/blob/main/docs/ContribOperators.md#com.microsoft.QMoE)，把性能拉满。

例如，采用 [com.microsoft.MultiHeadAttention](https://github.com/microsoft/onnxruntime/blob/main/docs/ContribOperators.md#com.microsoft.MultiHeadAttention) 算子后，基于 BERT 的嵌入模型实现了约 4 倍加速。

## 仓库重构

开发新的主版本让我们有机会投资代码库，补上早就该做的重构。

### PNPM Workspaces

此前，GitHub 仓库本身就是我们的 npm 包。只要仓库只发布一个库，这招没问题。但面向未来，我们需要各种子包：它们重度依赖 Transformers.js 核心，同时服务不同用例——比如特定库的实现，或者多数用户用不到、但对某些人不可或缺的小工具。

因此我们把仓库转成了基于 pnpm workspaces 的 monorepo。这让我们可以发布依赖 `@huggingface/transformers` 的小包，而不必承担维护多个独立仓库的开销。

### 模块化类结构

另一项大规模重构针对的是不断膨胀的 models.js 文件。在 v3 中，所有可用模型都定义在一个超过 8,000 行的单一文件里，越来越难维护。v4 把它拆成更小的聚焦模块，工具函数、核心逻辑和模型专属实现泾渭分明。新结构提升了可读性，也让加入新模型轻松得多——开发者可以专注于模型自身的逻辑，不必在成千上万行无关代码里翻找。

### 示例仓库

v3 时，许多 Transformers.js 示例项目就直接放在主仓库里。v4 把它们搬到了[独立仓库](https://github.com/huggingface/transformers.js-examples)，让主代码库更干净、更专注于核心库。用户查找和贡献示例也更容易，不用在主仓库里大海捞针。

### Prettier

我们更新了 Prettier 配置并重新格式化了全仓库文件。这保证了整个代码库风格一致，未来所有 PR 自动遵循同一套风格。不用再为格式争论…… Prettier 全搞定，让代码对所有人都清爽易读。

## 新模型与新架构

得益于新的导出策略和 ONNX Runtime 对自定义算子支持的不断扩展，我们在 Transformers.js v4 中加入了大量新模型和架构，包括 GPT-OSS、Chatterbox、GraniteMoeHybrid、LFM2-MoE、HunYuanDenseV1、Apertus、Olmo3、FalconH1、Youtu-LLM 等人气模型。其中不少要求我们实现对高级架构模式的支持，包括 Mamba（状态空间模型）、Multi-head Latent Attention（MLA，多头潜在注意力）和 Mixture of Experts（MoE，混合专家）。也许最重要的是，这些模型全部兼容 WebGPU——用户可以在浏览器或服务端 JavaScript 环境里借助硬件加速直接运行。我们已经发布了多个 [Transformers.js v4 demos](https://huggingface.co/collections/webml-community/transformersjs-v4-demos)，后续还会继续放出更多！

## 新构建系统

我们把构建系统从 Webpack 迁移到 esbuild，效果惊艳。构建时间从 2 秒降到 200 毫秒——10 倍提升，开发迭代快得多。好处不止速度：所有构建的 bundle 体积平均缩小约 10%。最显眼的是默认导出 transformers.web.js，瘦身 53%，意味着用户下载更快、启动更快。

## 库的新特性

第 4 版还加入了新的库特性，让构建稳健、可上生产的应用更容易。

### ModelRegistry

新的 `ModelRegistry` API 为生产流程而设计。在加载任何东西之前，它提供对 pipeline 资产的显式可见性：用 `get_pipeline_files` 列出所需文件，用 `get_file_metadata` 查看逐文件元数据（算总下载体积特别好用），用 `is_pipeline_cached` 检查缓存状态，用 `clear_pipeline_cache` 清理缓存产物。你还可以用 `get_available_dtypes` 查询某个模型可用的精度类型。基于这个新 API，`progress_callback` 现在包含 `progress_total` 事件，无需手动聚合各文件进度就能渲染端到端的加载进度。

See `ModelRegistry` examples

```
import { ModelRegistry, pipeline } from "@huggingface/transformers";

const modelId = "onnx-community/all-MiniLM-L6-v2-ONNX";
const modelOptions = { dtype: "fp32" };

const files = await ModelRegistry.get_pipeline_files(
  "feature-extraction",
  modelId,
  modelOptions
);
// ['config.json', 'onnx/model.onnx', ..., 'tokenizer_config.json']

const metadata = await Promise.all(
  files.map(file => ModelRegistry.get_file_metadata(modelId, file))
);

const downloadSize = metadata.reduce((total, item) => total + item.size, 0);

const cached = await ModelRegistry.is_pipeline_cached(
  "feature-extraction",
  modelId,
  modelOptions
);

const dtypes = await ModelRegistry.get_available_dtypes(modelId);
// ['fp32', 'fp16', 'q4', 'q4f16']

if (cached) {
  await ModelRegistry.clear_pipeline_cache(
    "feature-extraction",
    modelId,
    modelOptions
  );
}

const pipe = await pipeline(
  "feature-extraction",
  modelId,
  {
    progress_callback: e => {
      if (e.status === "progress_total") {
        console.log(`${Math.round(e.progress)}%`);
      }
    },
  }
);
```

### 新的环境设置

我们还为模型加载加入了新的环境控制项。`env.useWasmCache` 启用 WASM runtime 文件的缓存（在缓存存储可用时），让应用在首次加载之后可以完全离线工作。

`env.fetch` 允许你提供自定义 fetch 实现，适用于带鉴权的模型访问、自定义 header、可中止请求等场景。

See env examples

```
import { env } from "@huggingface/transformers";

env.useWasmCache = true;

env.fetch = (url, options) =>
  fetch(url, {
    ...options,
    headers: {
      ...options?.headers,
      Authorization: `Bearer ${MY_TOKEN}`,
    },
  });
```

### 更好的日志控制

最后，真实部署中的日志更好管了。ONNX Runtime WebGPU 警告默认不再显示，而且你可以分别为 Transformers.js 和 ONNX Runtime 设置显式的日志等级。这项更新同样来自社区反馈，让控制台输出聚焦于有用的信号，而不是低价值噪音。

See `logLevel` example

```
import { env, LogLevel } from "@huggingface/transformers";

// LogLevel.DEBUG
// LogLevel.INFO
// LogLevel.WARNING
// LogLevel.ERROR
// LogLevel.NONE

env.logLevel = LogLevel.WARNING;
```

## 独立的 Tokenizers.js 库

用户频繁提的一个需求，是把分词逻辑抽成独立库，v4 我们做到了。[@huggingface/tokenizers](https://www.npmjs.com/package/@huggingface/tokenizers) 是对分词逻辑的完全重构，设计目标是在浏览器和服务端 runtime 间无缝工作。gzip 后仅 8.8kB、零依赖，极其轻巧，同时保持完整的类型安全。

See example code

```
import { Tokenizer } from "@huggingface/tokenizers";

// Load from Hugging Face Hub
const modelId = "HuggingFaceTB/SmolLM3-3B";
const tokenizerJson = await fetch(
  `https://huggingface.co/${modelId}/resolve/main/tokenizer.json`
).then(res => res.json());

const tokenizerConfig = await fetch(
  `https://huggingface.co/${modelId}/resolve/main/tokenizer_config.json`
).then(res => res.json());

// Create tokenizer
const tokenizer = new Tokenizer(tokenizerJson, tokenizerConfig);

// Tokenize text
const tokens = tokenizer.tokenize("Hello World");
// ['Hello', 'ĠWorld']

const encoded = tokenizer.encode("Hello World");
// { ids: [9906, 4435], tokens: ['Hello', 'ĠWorld'], ... }
```

这一拆分让 Transformers.js 核心保持专注精干，同时交出一个通用的独立工具，任何 WebML 项目都可以单独使用。

## 杂项改进

我们在库各处做了一批改善体验的升级。类型系统增强了"动态 pipeline 类型"，能根据输入自适应，开发体验和类型安全都更好。

另外，我们加入了对超过 8B 参数的大模型支持。测试中，我们在 M4 Pro Max 上以约 60 token/s 的速度跑起了 GPT-OSS 20B（q4f16）。
