# 借助 Latent Consistency LoRAs，用 4 步生成 SDXL

本文另有中文版本可用：[简体中文](https://huggingface.co/blog/zh/lcm_lora)。

[Latent Consistency Models（LCM）](https://huggingface.co/papers/2310.04378)是一种减少 Stable Diffusion（或 SDXL）生成图像所需步数的方法——把原始模型*蒸馏（distill）*成另一个版本，只需更少步数（4 到 8 步，而非原来的 25 到 50 步）。蒸馏是一类训练过程，试图用一个新模型复现源模型的输出。被蒸馏出的模型可能更小（[DistilBERT](https://huggingface.co/docs/transformers/model_doc/distilbert) 或新近发布的 [Distil-Whisper](https://github.com/huggingface/distil-whisper) 就是这种情况），或者像这里这样，需要更少步数运行。它通常是个漫长又昂贵的过程，需要海量数据、耐心，和几块 GPU。

好了，那是今天之前的状态！

我们很高兴宣布一种新方法，基本可以让 Stable Diffusion 和 SDXL 提速，就好像它们被 LCM 流程蒸馏过一样！听起来如何——在 3090 上用约 1 秒而不是 7 秒跑*任何* SDXL 模型，或在 Mac 上快 10 倍？往下看细节！

## 方法概述

那么窍门是什么？Latent consistency 蒸馏需要对每个模型单独蒸馏。LCM LoRA 的核心思想是只训练一小撮 adapter——也就是所谓的 [LoRA 层](https://huggingface.co/docs/peft/conceptual_guides/lora)——而不是整个模型。这样产出的 LoRA 可以应用到该模型的任何微调版本上，不必逐个蒸馏。如果你等不及想看实际效果，直接跳到[下一节](https://huggingface.co/blog/lcm_lora#fast-inference-with-sdxl-lcm-loras)玩推理代码。如果你想训练自己的 LoRA，流程是：

- 从 Hub 选一个可用的 teacher 模型。例如 [SDXL (base)](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0)，或任何你喜欢的微调/dreambooth 版本。
- 在该模型上[训练一个 LCM LoRA](https://huggingface.co/blog/lcm_lora#how-to-train-lcm-models-and-loras)。LoRA 是一种参数高效微调（PEFT），比全模型微调便宜得多。PEFT 的更多细节见[这篇博客](https://huggingface.co/blog/peft)或 [diffusers 的 LoRA 文档](https://huggingface.co/docs/diffusers/training/lora)。
- 把这个 LoRA 配合任何 SDXL 扩散模型和 LCM 调度器使用；搞定！只需几步就能得到高质量推理。

流程细节请[下载我们的技术报告](https://huggingface.co/latent-consistency/lcm-lora-sdxl/resolve/main/LCM-LoRA-Technical-Report.pdf)。

## 为什么这很重要？

Stable Diffusion 和 SDXL 的快速推理催生了新用例与工作流。举几个例子：

- **可及性**：更多人能有效使用生成工具，哪怕没有最新硬件。
- **更快的迭代**：用一小部分时间得到更多图像、更多变体！对艺术家和研究人员——无论个人还是商用——都很棒。
- 生产负载或许可以在各种加速器上跑，包括 CPU。
- 更便宜的图像生成服务。

为了感受我们在说的速度差：在 M1 Mac 上用 SDXL（基座）生成一张 1024x1024 图像约需一分钟。用 LCM LoRA，只要约 6 秒（4 步）就能拿到很棒的结果。这快了一个数量级，而"不用等结果"是颠覆性的。用 4090，响应几乎即时（不到 1 秒）。这让 SDXL 可以进入需要实时事件的应用。

## 用 SDXL LCM LoRA 快速推理

今天发布的 `diffusers` 版本让使用 LCM LoRA 变得非常简单：

```
from diffusers import DiffusionPipeline, LCMScheduler
import torch

model_id = "stabilityai/stable-diffusion-xl-base-1.0"
lcm_lora_id = "latent-consistency/lcm-lora-sdxl"

pipe = DiffusionPipeline.from_pretrained(model_id, variant="fp16")

pipe.load_lora_weights(lcm_lora_id)
pipe.scheduler = LCMScheduler.from_config(pipe.scheduler.config)
pipe.to(device="cuda", dtype=torch.float16)

prompt = "close-up photography of old man standing in the rain at night, in a street lit by lamps, leica 35mm summilux"
images = pipe(
    prompt=prompt,
    num_inference_steps=4,
    guidance_scale=1,
).images[0]
```

注意这段代码：

- 用 SDXL 1.0 基座实例化标准扩散流水线。
- 应用 LCM LoRA。
- 把调度器换成 LCMScheduler——latent consistency 模型用的就是它。
- 就这么多了！

这会得到下面的全分辨率图像：

![SDXL in 4 steps with LCM LoRA](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/lcm-lora/lcm-1.jpg?download=true)
 *用 LCM LoRA 让 SDXL 在 4 步内生成的图像。*

### 质量对比

看看步数如何影响生成质量。下面的代码用 1 到 8 步生成图像：

```
images = []
for steps in range(8):
    generator = torch.Generator(device=pipe.device).manual_seed(1337)
    image = pipe(
        prompt=prompt,
        num_inference_steps=steps+1,
        guidance_scale=1,
        generator=generator,
    ).images[0]
    images.append(image)
```

这 8 张图排成网格：

![LCM LoRA generations with 1 to 8 steps](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/lcm-lora/lcm-grid.jpg?download=true)
 *LCM LoRA 用 1 到 8 步生成的图像。*

不出所料，只走 **1** 步得到的是一个没有可辨特征、缺乏纹理的近似形状。但结果迅速改善，通常 4 到 6 步就非常令人满意。就我个人而言，觉得上一个测试里第 8 步的图饱和度有点高、略显"卡通"，所以这个例子里我大概会在 5 步和 6 步的图之间挑。生成快到你先用 4 步批量造出许多变体，挑出喜欢的，再用更多步数和精炼的提示词迭代。

### Guidance Scale 与负向提示词

注意前面的例子用了 `guidance_scale` = `1`，等于把它关掉了。这对多数提示词都有效、也最快，但会忽略负向提示词。你也可以用 1 到 2 之间的 guidance scale 来使用负向提示词——我们发现更大的值不起作用。

### 与基座 SDXL 的质量比较

和标准 SDXL 流水线比质量如何？来看例子！

我们可以快速把流水线还原为标准 SDXL：卸载 LoRA 权重、换回默认调度器：

```
from diffusers import EulerDiscreteScheduler

pipe.unload_lora_weights()
pipe.scheduler = EulerDiscreteScheduler.from_config(pipe.scheduler.config)
```

然后照常规对 SDXL 推理，收集不同步数的结果：

```
images = []
for steps in (1, 4, 8, 15, 20, 25, 30, 50):
    generator = torch.Generator(device=pipe.device).manual_seed(1337)
    image = pipe(
        prompt=prompt,
        num_inference_steps=steps,
        generator=generator,
    ).images[0]
    images.append(image)
```

![SDXL results for various inference steps](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/lcm-lora/lcm-sdxl-grid.jpg?download=true)
 *SDXL 流水线结果（同样的提示词和随机种子），分别用 1、4、8、15、20、25、30、50 步。*

可以看到，这个例子里图像要到约 20 步（第二行）才勉强可用，而且继续加步数质量仍明显上升。最后一张图的细节令人惊叹——但花了 50 步。

### 其他模型上的 LCM LoRA

这个技术对任何微调过的 SDXL 或 Stable Diffusion 模型同样有效。示范一下：在 [`collage-diffusion`](https://huggingface.co/wavymulder/collage-diffusion)（用 Dreambooth 从 [Stable Diffusion v1.5](https://huggingface.co/runwayml/stable-diffusion-v1-5) 微调而来）上运行推理。

代码与前面的例子类似。加载微调模型，再加载适配 Stable Diffusion v1.5 的 LCM LoRA。

```
from diffusers import DiffusionPipeline, LCMScheduler
import torch

model_id = "wavymulder/collage-diffusion"
lcm_lora_id = "latent-consistency/lcm-lora-sdv1-5"

pipe = DiffusionPipeline.from_pretrained(model_id, variant="fp16")
pipe.scheduler = LCMScheduler.from_config(pipe.scheduler.config)
pipe.load_lora_weights(lcm_lora_id)
pipe.to(device="cuda", dtype=torch.float16)

prompt = "collage style kid sits looking at the night sky, full of stars"

generator = torch.Generator(device=pipe.device).manual_seed(1337)
images = pipe(
    prompt=prompt,
    generator=generator,
    negative_prompt=negative_prompt,
    num_inference_steps=4,
    guidance_scale=1,
).images[0]
images
```

![LCM LoRA technique with a Dreambooth Stable Diffusion v1.5 model, allowing 4-step inference.](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/lcm-lora/collage.png?download=true)
 *LCM LoRA 技术用在 Dreambooth 微调的 Stable Diffusion v1.5 模型上，实现 4 步推理。*

LCM 在 `diffusers` 中的集成，让你能利用 diffusers 工具箱里的众多特性与工作流。例如：

这一节不求穷尽，只求展示我们在各种电脑上达到的生成速度。再强调一次：能如此自由地探索图像生成，何等解放。

| 硬件 | SDXL + LCM LoRA（4 步） | SDXL 标准（25 步） |
| --- | --- | --- |
| Mac, M1 Max | 6.5s | 64s |
| 2080 Ti | 4.7s | 10.2s |
| 3090 | 1.4s | 7s |
| 4090 | 0.7s | 3.4s |
| T4（Google Colab 免费档） | 8.4s | 26.5s |
| A100（80 GB） | 1.2s | 3.8s |

所有测试的 batch size 为 1，使用 [Sayak Paul](https://huggingface.co/sayakpaul) 的[这个脚本](https://huggingface.co/datasets/pcuenq/gists/blob/main/sayak_lcm_benchmark.py)。

对 A100 这样容量富余的卡，一次生成多张图时性能会显著提升——生产负载通常如此。

## 附赠：LCM LoRA 与普通 SDXL LoRA 组合使用

借助 [diffusers + PEFT 集成](https://huggingface.co/docs/diffusers/main/en/tutorials/using_peft_for_inference)，你可以把 LCM LoRA 与普通 SDXL LoRA 组合，让它们获得只需 4 步就能跑 LCM 推理的超能力。

这里我们把 `CiroN2022/toy_face` LoRA 与 LCM LoRA 组合：

```
from diffusers import DiffusionPipeline, LCMScheduler
import torch

model_id = "stabilityai/stable-diffusion-xl-base-1.0"
lcm_lora_id = "latent-consistency/lcm-lora-sdxl"
pipe = DiffusionPipeline.from_pretrained(model_id, variant="fp16")
pipe.scheduler = LCMScheduler.from_config(pipe.scheduler.config)

pipe.load_lora_weights(lcm_lora_id)
pipe.load_lora_weights("CiroN2022/toy-face", weight_name="toy_face_sdxl.safetensors", adapter_name="toy")

pipe.set_adapters(["lora", "toy"], adapter_weights=[1.0, 0.8])
pipe.to(device="cuda", dtype=torch.float16)

prompt = "a toy_face man"
negative_prompt = "blurry, low quality, render, 3D, oversaturated"
images = pipe(
    prompt=prompt,
    negative_prompt=negative_prompt,
    num_inference_steps=4,
    guidance_scale=0.5,
).images[0]
images
```

![Combining LoRAs for fast inference](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/lcm-lora/lcm-toy.png?download=true)
 *标准 LoRA 与 LCM LoRA 组合，实现快速（4 步）推理。*

## 如何训练 LCM 模型与 LoRA

作为今天 `diffusers` 发布的一部分，我们提供与 LCM 团队作者共同开发的训练与微调脚本，让用户可以：

- 在 Laion 这样的大数据集上对 Stable Diffusion 或 SDXL 模型做全模型蒸馏。
- 训练 LCM LoRA——这是容易得多的过程。如本文所示，它让你不必经历蒸馏训练，就能让 Stable Diffusion 跑快速推理。
