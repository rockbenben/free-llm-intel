# 什么样的对话 Agent 才有用？

## ChatGPT 背后的技术：RLHF、IFT、CoT、Red teaming 等

*本文另有中文译文，见[简体中文](https://mp.weixin.qq.com/s/Xd5VtRP-ziH-PYFOci65Hg)*。

几周前，ChatGPT 横空出世，把公众讨论卷进了一串生僻的缩写：RLHF、SFT、IFT、CoT 等等，人们把这些都归为 ChatGPT 成功的原因。这些晦涩的缩写到底是什么？它们为什么如此重要？我们调研了这些主题上的重要论文，对这些工作加以归类，总结已有成果的要诀，并分享哪些结论尚待验证。

先来看看基于语言模型的对话 agent 的整体版图。ChatGPT 并不是第一个——事实上，许多机构在 OpenAI 之前就发布过自己的语言模型对话 agent，包括 [Meta 的 BlenderBot](https://arxiv.org/abs/2208.03188)、[Google 的 LaMDA](https://arxiv.org/abs/2201.08239)、[DeepMind 的 Sparrow](https://arxiv.org/abs/2209.14375) 和 [Anthropic 的 Assistant](https://arxiv.org/abs/2204.05862)（*该 agent 的后续演进在出处标注不全的情况下也被称为 Claude*）。还有一些团体宣布了他们打造开源 chatbot 的计划并公开了路线图（[LAION 的 Open Assistant](https://github.com/LAION-AI/Open-Assistant)）；另有一些人显然也在做，只是尚未公布。

下表根据公开访问情况、训练数据、模型架构和评测方向，对这些 AI chatbot 进行了对比。ChatGPT 没有公开文档，所以我们改为分享 InstructGPT 的细节——这是 OpenAI 的指令微调模型，被认为是 ChatGPT 的基础。

|  | LaMDA | BlenderBot 3 | Sparrow | ChatGPT/ InstructGPT | Assistant |
| --- | --- | --- | --- | --- | --- |
| **机构** | Google | Meta | DeepMind | OpenAI | Anthropic |
| **访问方式** | 封闭 | 开放 | 封闭 | 受限 | 封闭 |
| **规模** | 137B | 175B | 70B | 175B | 52B |
| **预训练基座模型** | 未知 | OPT | Chinchilla | GPT-3.5 | 未知 |
| **预训练语料规模**（token 数） | 2.81T | 180B | 1.4T | 未知 | 400B |
| **模型可访问网络** | ✔ | ✔ | ✔ | ✖️ | ✖️ |
| **监督微调** | ✔ | ✔ | ✔ | ✔ | ✔ |
| **微调数据规模** | 质量：6.4K 安全：8K 有依据性（Groundedness）：4K IR：49K | 20 个 NLP 数据集，规模从 18K 到 1.2M 不等 | 未知 | 12.7K（InstructGPT 的规模，ChatGPT 大概率远多于此） | 150K + LM 生成数据 |

我们看到，尽管各系统在训练数据、模型和微调方式上差异很大，也存在一些共同点。上述所有 chatbot 的一个共同目标是**遵循指令（instruction following）**，即按照用户指定的指令行事。例如，指示 ChatGPT 写一首关于微调的诗。

[![ChatGPT 指令示例](https://huggingface.co/blog/assets/dialog-agents/chatgpt-example.png)](https://huggingface.co/blog/assets/dialog-agents/chatgpt-example.png)

### **从预测文本到遵循指令：**

通常，基座模型的语言建模目标并不足以让模型学会以有益的方式跟随用户的指引。模型开发者会使用**指令微调（Instruction Fine-Tuning, IFT）**：在基座模型上，用涵盖非常多样的任务的人工书写指令示范数据做微调，此外还包括情感、文本分类、摘要等传统 NLP 任务。这些指令示范由三个主要部分组成——指令（instruction）、输入（inputs）和输出（outputs）。输入是可选的，有些任务只需要指令，比如上面 ChatGPT 例子中的开放式生成。一个输入和一个输出（如果存在）构成一个*实例（instance）*。同一条指令可以有多个输入-输出实例。示例见下（取自 [Wang et al., '22]）。

[![指令与实例示例](https://huggingface.co/blog/assets/dialog-agents/ift.png)](https://huggingface.co/blog/assets/dialog-agents/ift.png)

IFT 的数据通常是一批人类书写的指令，加上用语言模型自举（bootstrap）生成的指令实例。所谓自举，就是如上图所示以 few-shot 方式用示例提示语言模型，并指示它生成新的指令、输入和输出。每一轮中，提示模型时从人类书写和模型生成的样本中共同选取。人类与模型对数据集的贡献比例构成一个谱系，见下图。

[![IFT 谱系](https://huggingface.co/blog/assets/dialog-agents/ift-spectrum.png)](https://huggingface.co/blog/assets/dialog-agents/ift-spectrum.png)

一端是纯模型生成的 IFT 数据集，如 Unnatural Instructions（[Honovich et al., '22](https://arxiv.org/abs/2212.09689)）；另一端是大规模社区手工撰写指令的成果，如 Super-natural instructions（[Wang et al., '22](https://arxiv.org/abs/2204.07705)）。介于两者之间的，是先用一小批高质量种子数据集、再做自举的工作，如 Self-instruct（[Wang et al., 22](https://arxiv.org/pdf/2212.10560.pdf)）。为 IFT 收集数据的另一种方式，是把已有的、涵盖各类任务（包括 prompt 任务）的高质量众包 NLP 数据集，用统一的 schema 或多样的模板转写成指令。这一路线的工作包括 T0（[Sanh et al., '22](https://arxiv.org/pdf/2110.08207.pdf)）、Natural instructions 数据集（[Mishra et al., '22](https://arxiv.org/pdf/2104.08773.pdf)）、FLAN LM（[Wei et al., '22](https://arxiv.org/pdf/2109.01652.pdf)）以及 OPT-IML（[Iyer et al., '22](https://arxiv.org/pdf/2212.12017.pdf)）。

### 安全地遵循指令

然而，指令微调后的 LM 并不总能生成**有用**且**安全**的回复。这类行为的例子包括：总是给出无用的回应来回避问题，比如 "I'm sorry, I don't understand."（抱歉，我不明白）；或者针对用户在敏感话题上的输入生成不安全的回复。为了缓解这类行为，模型开发者使用**监督微调（Supervised Fine-tuning, SFT）**，在高质量人工标注数据上对基座语言模型做微调，以达成有用（helpfulness）与无害（harmlessness）。例如下表，取自 Sparrow 论文（附录 F）。

SFT 与 IFT 紧密关联。指令微调可以看作监督微调的一个子集。在近年的文献中，SFT 阶段常被用于安全主题，而不是指令主题本身——后者在 IFT 之后完成。未来，这套分类与边界应当沉淀出更清晰的用例与方法论。

[![人工编写的安全规则](https://huggingface.co/blog/assets/dialog-agents/rules.png)](https://huggingface.co/blog/assets/dialog-agents/rules.png)

Google 的 LaMDA 同样在一个对话数据集上做了微调，其中包含基于一系列规则的安全标注（附录 A）。这些规则通常由模型开发者预先定义，涵盖伤害、歧视、错误信息等广泛主题。

### 模型的微调

另一方面，OpenAI 的 InstructGPT、DeepMind 的 Sparrow 和 Anthropic 的 Constitutional AI 使用人类偏好标注，这种设置称为**基于人类反馈的强化学习（reinforcement learning from human feedback, RLHF）**。在 RLHF 中，一组模型回复根据人类反馈进行排序（例如在两段文字中选出更受偏好的那段）。接着，在这些被标注的回复上训练一个偏好模型，为 RL 优化器返回一个标量奖励。最后，通过强化学习训练对话 agent 去模拟这个偏好模型。更多细节见我们此前关于 RLHF 的[博客文章](https://huggingface.co/blog/rlhf)。

**思维链（Chain-of-thought, CoT）**提示（[Wei et al., '22](https://arxiv.org/abs/2201.11903)）是指令示范的一种特殊形式，通过引导对话 agent 进行逐步推理来生成输出。经过 CoT 微调的模型使用带有逐步推理人工标注的指令数据集。这就是那句著名提示 ***[let's think step by step](https://arxiv.org/abs/2205.11916)*（让我们一步步思考）** 的由来。下面的例子取自 [Chung et al., '22](https://arxiv.org/pdf/2210.11416.pdf)。橙色高亮的是指令，粉色标出的是输入和输出，蓝色是 CoT 推理。

[![CoT 示意图](https://huggingface.co/blog/assets/dialog-agents/cot.png)](https://huggingface.co/blog/assets/dialog-agents/cot.png)

如 [Chung et al., '22](https://arxiv.org/pdf/2210.11416.pdf) 所示，经过 CoT 微调的模型在涉及常识、算术和符号推理的任务上表现要好得多。

[Bai et al., '22](https://www.anthropic.com/constitutional.pdf) 还表明，CoT 微调在无害性（harmlessness）方面同样非常有效（有时甚至比 RLHF 更好），而且模型不会变得闪避、对敏感提示生成"抱歉，我无法回答这个问题"。更多示例见其论文附录 D。

[![CoT 与 RLHF 对比](https://huggingface.co/blog/assets/dialog-agents/rlhf.png)](https://huggingface.co/blog/assets/dialog-agents/rlhf.png)

## 要点小结：

- 与预训练数据相比，指令微调只需要极小比例的数据（几百条的量级）。
- 监督微调利用人工标注，让模型输出更安全、更有用。
- CoT 微调提升模型在需要逐步思考的任务上的表现，并让它们在敏感话题上更少回避。

## 对话 agent 的下一步

这篇博客总结了大量关于"是什么让对话 agent 有用"的现有工作。但仍有许多开放问题有待探索，这里列出其中一些。

- RL 在从人类反馈中学习这件事上到底有多重要？能否靠更高质量的 IFT 或 SFT 数据训练达到 RLHF 的性能？
- 在安全方面，Sparrow 的 SFT + RLHF 与 LaMDA 只用 SFT 相比如何？
- 在已有 IFT、SFT、CoT 和 RLHF 的情况下，多少预训练是必要的？权衡是什么？人们应该使用哪些最好的基座模型（无论公开可用还是不可公开获取的）？
- 本文提及的许多模型都经过精心的 [red-teaming](https://arxiv.org/abs/2209.07858)（红队测试），工程师专门搜寻失效模式，并根据暴露出的问题影响后续训练（提示与方法）。我们如何系统地记录这些方法的效果并复现它们？
