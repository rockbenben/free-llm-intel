## SegMoE 是什么？

SegMoE 模型与 Stable Diffusion 采用相同架构。就像 [Mixtral 8x7b](https://huggingface.co/blog/mixtral) 一样，一个 SegMoE 模型内含多个模型。实现方式是：把一些前馈层替换成稀疏 MoE 层。MoE 层包含一个路由网络，决定哪个专家处理哪些 token 最有效。你可以用 `segmoe` 包创建自己的 MoE 模型！整个过程只需几分钟。更多信息请访问 [GitHub 仓库](https://github.com/segmind/segmoe)。我们参考了广受欢迎的 [`mergekit`](https://github.com/arcee-ai/mergekit) 库来设计 `segmoe`，感谢 `mergekit` 的贡献者们做出如此实用的库。

关于 MoE 的更多细节，见 Hugging Face 🤗 的文章：[hf.co/blog/moe](https://huggingface.co/blog/moe)。

**SegMoE 发布 TL;DR；**

- 发布 SegMoE-4x2、SegMoE-2x1 和 SegMoE-SD4x2 版本
- 发布自定义 MoE 制作代码

### 关于命名

SegMoE 系列命名为 **SegMoE-AxB**：`A` 指被混合（MoE）在一起的专家模型数量，`B` 指生成每张图像时参与计算的专家数量。根据配置不同，只有模型的部分层（前馈块、注意力层，或全部）会被复制；其余参数与 Stable Diffusion 模型相同。想了解 MoE 的工作原理，请参考 ["Mixture of Experts Explained"](https://huggingface.co/blog/moe) 一文。

## 推理

我们在 Hub 上发布了 3 个合并模型：

- [SegMoE 2x1](https://huggingface.co/segmind/SegMoE-2x1-v0)：包含 2 个专家模型。
- [SegMoE 4x2](https://huggingface.co/segmind/SegMoE-4x2-v0)：包含 4 个专家模型。
- [SegMoE SD 4x2](https://huggingface.co/segmind/SegMoE-SD-4x2-v0)：包含 4 个 Stable Diffusion 1.5 专家模型。

### 使用 🤗 Diffusers

请运行以下命令安装 `segmoe` 包。确保已安装最新版本的 `diffusers` 和 `transformers`。

```
pip install -U segmoe diffusers transformers
```

下面加载上面列表中的第二个模型（"SegMoE 4x2"）并运行生成。

```
from segmoe import SegMoEPipeline

pipeline = SegMoEPipeline("segmind/SegMoE-4x2-v0", device="cuda")

prompt = "cosmic canvas, orange city background, painting of a chubby cat"
negative_prompt = "nsfw, bad quality, worse quality"
img = pipeline(
    prompt=prompt,
    negative_prompt=negative_prompt,
    height=1024,
    width=1024,
    num_inference_steps=25,
    guidance_scale=7.5,
).images[0]
img.save("image.png")
```

### 使用本地模型

也可以加载本地模型，这里 `segmoe_v0` 是存放本地 SegMoE 模型的目录路径。想学习如何构建自己的模型，请看[创建你自己的 SegMoE](https://huggingface.co/blog/segmoe#creating-your-own-segmoe)！

```
from segmoe import SegMoEPipeline

pipeline = SegMoEPipeline("segmoe_v0", device="cuda")

prompt = "cosmic canvas, orange city background, painting of a chubby cat"
negative_prompt = "nsfw, bad quality, worse quality"
img = pipeline(
    prompt=prompt,
    negative_prompt=negative_prompt,
    height=1024,
    width=1024,
    num_inference_steps=25,
    guidance_scale=7.5,
).images[0]
img.save("image.png")
```

## 创建你自己的 SegMoE

只需准备一个具有如下结构的 `config.yaml` 文件：

```
base_model: Base Model Path, Model Card or CivitAI Download Link
num_experts: Number of experts to use
moe_layers: Type of Layers to Mix (can be "ff", "attn" or "all"). Defaults to "attn"
num_experts_per_tok: Number of Experts to use 
experts:
  - source_model: Expert 1 Path, Model Card or CivitAI Download Link
    positive_prompt: Positive Prompt for computing gate weights
    negative_prompt: Negative Prompt for computing gate weights
  - source_model: Expert 2 Path, Model Card or CivitAI Download Link
    positive_prompt: Positive Prompt for computing gate weights
    negative_prompt: Negative Prompt for computing gate weights
  - source_model: Expert 3 Path, Model Card or CivitAI Download Link
    positive_prompt: Positive Prompt for computing gate weights
    negative_prompt: Negative Prompt for computing gate weights
  - source_model: Expert 4 Path, Model Card or CivitAI Download Link
    positive_prompt: Positive Prompt for computing gate weights
    negative_prompt: Negative Prompt for computing gate weights
```

可以组合任意数量的模型。关于如何创建配置文件的详细说明，请参考 [GitHub 仓库](https://github.com/segmind/segmoe)

**注意**：Hugging Face 和 CivitAI 的模型都支持。对 CivitAI 模型，粘贴其下载链接即可，例如："[https://civitai.com/api/download/models/239306](https://civitai.com/api/download/models/239306)"

然后运行以下命令：

```
segmoe config.yaml segmoe_v0
```

这会创建一个名为 `segmoe_v0` 的文件夹，结构如下：

```
├── model_index.json
├── scheduler
│   └── scheduler_config.json
├── text_encoder
│   ├── config.json
│   └── model.safetensors
├── text_encoder_2
│   ├── config.json
│   └── model.safetensors
├── tokenizer
│   ├── merges.txt
│   ├── special_tokens_map.json
│   ├── tokenizer_config.json
│   └── vocab.json
├── tokenizer_2
│   ├── merges.txt
│   ├── special_tokens_map.json
│   ├── tokenizer_config.json
│   └── vocab.json
├── unet
│   ├── config.json
│   └── diffusion_pytorch_model.safetensors
└──vae
    ├── config.json
    └── diffusion_pytorch_model.safetensors
```

也可以通过 Python API 创建专家混合模型：

```
from segmoe import SegMoEPipeline

pipeline = SegMoEPipeline("config.yaml", device="cuda")

pipeline.save_pretrained("segmoe_v0")
```

### 推送到 Hub

模型可以通过 huggingface-cli 推送到 hub

```
huggingface-cli upload segmind/segmoe_v0 ./segmoe_v0
```

也可以直接从 Python 推送到 Hub：

```
from huggingface_hub import create_repo, upload_folder
 
model_id = "segmind/SegMoE-v0"

repo_id = create_repo(repo_id=model_id, exist_ok=True).repo_id

upload_folder(
    repo_id=repo_id,
    folder_path="segmoe_v0",
    commit_message="Initial Commit",
    ignore_patterns=["step_*", "epoch_*"],
)
```

详细用法见[这里](https://huggingface.co/docs/huggingface_hub/guides/upload)

## 声明与进行中的工作

- **速度更慢**：如果每个 token 的专家数大于 1，MoE 就需要在多个专家模型上做计算。这使它比单个 SD 1.5 或 SDXL 模型慢。
- **显存占用高**：MoE 推理很快，但仍需要大量显存（也就需要昂贵的 GPU）。这使它在本地部署场景比较吃力，但非常适合多 GPU 部署。作为参考，SegMoE-4x2 在半精度下需要 24GB 显存。

## 结论

我们构建 SegMoE，是想给社区一件新工具：只需组合预训练模型，就能轻松做出潜在的 SOTA 扩散模型，同时保持较低的推理时间。我们很期待用它做出什么！
