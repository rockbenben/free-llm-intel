# Hugging Face 上的 Optimum-NVIDIA：一行代码实现极速 LLM 推理

大语言模型（LLM）已经革新了自然语言处理，并越来越多地被用于在规模化场景下解决复杂问题。由于这些模型独特而强烈的计算需求，想让它们达到最优性能向来极其困难。LLM 的优化性能对追求敏捷响应体验的终端用户极具价值，对需要改进吞吐以节省成本的规模化部署同样如此。

这正是 [Optimum-NVIDIA](https://github.com/huggingface/optimum-nvidia) 推理库登场的地方。Optimum-NVIDIA 在 Hugging Face 上可用，通过极其简单的 API 在 NVIDIA 平台上显著加速 LLM 推理。只需**修改一行代码**，你就可以在 NVIDIA 平台上获得最高 **28 倍推理加速和 1200 tokens/秒**。

Optimum-NVIDIA 是首个受益于 NVIDIA Ada Lovelace 和 Hopper 架构新支持的 `float8` 格式的 Hugging Face 推理库。FP8 加上 [NVIDIA TensorRT-LLM 软件](https://developer.nvidia.com/blog/nvidia-tensorrt-llm-supercharges-large-language-model-inference-on-nvidia-h100-gpus/)的高级编译能力，大幅加速了 LLM 推理。

### 如何运行

用 Optimum-NVIDIA 的 pipeline，只需 3 行代码你就能以极速推理跑起 LLaMA。如果你已经用 Hugging Face transformers 库的 pipeline 跑 LLaMA，只需修改一行代码即可解锁峰值性能！

```
- from transformers.pipelines import pipeline
+ from optimum.nvidia.pipelines import pipeline

# everything else is the same as in transformers!
pipe = pipeline('text-generation', 'meta-llama/Llama-2-7b-chat-hf', use_fp8=True)
pipe("Describe a real-world application of AI in sustainable energy.")
```

你还可以用一个开关启用 FP8 量化，从而在单张 GPU 上以更快的速度运行更大的模型且不牺牲精度。示例中展示的该开关默认使用预定义的校准策略，你也可以提供自己的校准数据集和自定义 tokenization，让量化贴合你的用例。

pipeline 接口非常适合快速上手，但希望精细控制采样参数的进阶用户可以使用 Model API。

```
- from transformers import AutoModelForCausalLM
+ from optimum.nvidia import AutoModelForCausalLM
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-2-13b-chat-hf", padding_side="left")

model = AutoModelForCausalLM.from_pretrained(
  "meta-llama/Llama-2-13b-chat-hf",
+ use_fp8=True,  
)

model_inputs = tokenizer(
    ["How is autonomous vehicle technology transforming the future of transportation and urban planning?"], 
    return_tensors="pt"
).to("cuda")

generated_ids, generated_length = model.generate(
    **model_inputs, 
    top_k=40, 
    top_p=0.7, 
    repetition_penalty=10,
)

tokenizer.batch_decode(generated_ids[0], skip_special_tokens=True)
```

更多细节请查看我们的[文档](https://github.com/huggingface/optimum-nvidia)。

### 性能评估

评估 LLM 性能时，我们考虑两个指标：首 token 延迟（First Token Latency）和吞吐（Throughput）。首 token 延迟（也称 Time to First Token 或 prefill 延迟）衡量从输入 prompt 到开始收到输出的等待时间，这个指标能告诉你模型会有多"跟手"。相比原版 transformers，Optimum-NVIDIA 的首 token 延迟最高快 3.3 倍：

Figure 1. Time it takes to generate the first token (ms)

而吞吐衡量模型生成 token 的速度，在你希望把生成批量打包时尤其相关。吞吐有几种计算方式，我们采用标准方法：用端到端延迟除以总序列长度（包括所有批次上输入与输出 token 之和）。相比原版 transformers，Optimum-NVIDIA 的吞吐最高提升 28 倍：

Figure 2. Throughput (token / second)

对[最近发布的 NVIDIA H200 Tensor Core GPU](https://www.nvidia.com/en-us/data-center/h200/)的初步评估显示，相比 NVIDIA H100 Tensor Core GPU，LLaMA 模型的吞吐还能再提升最多 2 倍。随着 H200 GPU 逐渐普及，我们将分享 Optimum-NVIDIA 在其上的性能数据。

### 下一步

Optimum-NVIDIA 目前为 LLaMAForCausalLM 架构 + 任务提供峰值性能，因此任何基于 [LLaMA 的模型](https://huggingface.co/models?other=llama,llama2)（包括微调版本）今天都应能直接配合 Optimum-NVIDIA 使用。我们正在积极扩展支持到其他文本生成模型架构和任务，全部在 Hugging Face 生态内完成。

我们将持续突破性能边界，计划引入前沿优化技术，如提升 prompt 流式吞吐的 In-Flight Batching，以及让单卡跑更大模型的 INT4 量化。
