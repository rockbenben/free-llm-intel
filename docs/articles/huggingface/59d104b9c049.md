## 1. 什么是 Optimum？极简解释

[Hugging Face Optimum](https://github.com/huggingface/optimum) 是一个开源库，是 [Hugging Face Transformers](https://github.com/huggingface/transformers) 的扩展：提供统一的性能优化工具 API，在加速硬件上实现模型训练与运行的最高效率，包括针对 [Graphcore IPU](https://github.com/huggingface/optimum-graphcore) 和 [Habana Gaudi](https://github.com/huggingface/optimum-habana) 的性能优化工具包。Optimum 可用于加速训练、量化、图优化，现在也支持推理，并兼容 [transformers pipelines](https://huggingface.co/docs/transformers/main/en/main_classes/pipelines#pipelines)。

## 2. Optimum 新的推理与 pipeline 特性

随着 Optimum 1.2 [发布](https://github.com/huggingface/optimum/releases/tag/v1.2.0)，我们加入了[推理](https://huggingface.co/docs/optimum/main/en/onnxruntime/modeling_ort)与 [transformers pipelines](https://huggingface.co/docs/transformers/main/en/main_classes/pipelines#pipelines) 支持。这让 Optimum 用户能用与 transformers 相同惯用的 API，享受 [ONNX Runtime](https://onnxruntime.ai/) 这类加速运行时的威力。

**从 Transformers 切换到 Optimum Inference** [Optimum Inference 模型](https://huggingface.co/docs/optimum/main/en/onnxruntime/modeling_ort)与 Hugging Face Transformers 模型 API 兼容。也就是说，只需把 `AutoModelForXxx` 类换成 Optimum 对应的 `ORTModelForXxx` 类。例如，这样在 Optimum 中使用问答模型：

```
from transformers import AutoTokenizer, pipeline
-from transformers import AutoModelForQuestionAnswering
+from optimum.onnxruntime import ORTModelForQuestionAnswering

-model = AutoModelForQuestionAnswering.from_pretrained("deepset/roberta-base-squad2") # pytorch checkpoint
+model = ORTModelForQuestionAnswering.from_pretrained("optimum/roberta-base-squad2") # onnx checkpoint
tokenizer = AutoTokenizer.from_pretrained("deepset/roberta-base-squad2")

optimum_qa = pipeline("question-answering", model=model, tokenizer=tokenizer)

question = "What's my name?"
context = "My name is Philipp and I live in Nuremberg."
pred = optimum_qa(question, context)
```

在首个发布版本中我们加入了 [ONNX Runtime 支持](https://huggingface.co/docs/optimum/main/en/onnxruntime/modeling_ort)，未来还会有更多！这些新的 `ORTModelForXX` 现在可以配合 [transformers pipelines](https://huggingface.co/docs/transformers/main/en/main_classes/pipelines#pipelines) 使用，也完整集成进 [Hugging Face Hub](https://huggingface.co/models)，可与社区互推优化过的检查点。除此之外，你还可以先用 [ORTQuantizer](https://huggingface.co/docs/optimum/main/en/onnxruntime/quantization) 和 [ORTOptimizer](https://huggingface.co/docs/optimum/main/en/onnxruntime/optimization) 对模型做量化和优化，再跑推理。细节见[端到端教程：加速 RoBERTa 问答模型，含量化与优化](https://huggingface.co/blog/optimum-inference#3-end-to-end-tutorial-on-accelerating-roberta-for-question-answering-including-quantization-and-optimization)。

## 3. 端到端教程：加速 RoBERTa 问答模型，含量化与优化

开始吧 🚀

*本教程在 AWS EC2 `m5.xlarge` 实例上制作并运行。*

### 3.1 为 Onnxruntime 安装 `Optimum`

第一步是用 `onnxruntime` 工具集安装 `Optimum`。

```
pip install "optimum[onnxruntime]==1.2.0"
```

这会装好所有需要的包，包括 `transformers`、`torch` 和 `onnxruntime`。如果用 GPU，可以用 `pip install optimum[onnxruntime-gpu]`。

### 3.2 把 Hugging Face `Transformers` 模型转换为 ONNX 用于推理**

开始优化之前，先把原生的 `transformers` 模型转成 `onnx` 格式。我们用新的 [ORTModelForQuestionAnswering](https://huggingface.co/docs/optimum/main/en/onnxruntime/modeling_ort#optimum.onnxruntime.ORTModelForQuestionAnswering) 类，调用 `from_pretrained()` 时带上 `from_transformers` 属性。使用的模型是 [deepset/roberta-base-squad2](https://huggingface.co/deepset/roberta-base-squad2)——一个在 SQUAD2 数据集上微调的 RoBERTa，F1 分数 `82.91`——任务（feature）为 `question-answering`。

```
from pathlib import Path
from transformers import AutoTokenizer, pipeline
from optimum.onnxruntime import ORTModelForQuestionAnswering

model_id = "deepset/roberta-base-squad2"
onnx_path = Path("onnx")
task = "question-answering"

# load vanilla transformers and convert to onnx
model = ORTModelForQuestionAnswering.from_pretrained(model_id, from_transformers=True)
tokenizer = AutoTokenizer.from_pretrained(model_id)

# save onnx checkpoint and tokenizer
model.save_pretrained(onnx_path)
tokenizer.save_pretrained(onnx_path)

# test the model with using transformers pipeline, with handle_impossible_answer for squad_v2
optimum_qa = pipeline(task, model=model, tokenizer=tokenizer, handle_impossible_answer=True)
prediction = optimum_qa(question="What's my name?", context="My name is Philipp and I live in Nuremberg.")

print(prediction)
# {'score': 0.9041663408279419, 'start': 11, 'end': 18, 'answer': 'Philipp'}
```

我们成功把原生 transformers 模型转成了 `onnx`，并用 `transformers.pipelines` 完成了第一次预测。接下来优化它。🏎

想更多了解 transformers 模型导出，请阅读文档：[Export 🤗 Transformers Models](https://huggingface.co/docs/transformers/main/en/serialization)

### 3.3 用 `ORTOptimizer` 优化模型

把 onnx 检查点存到 `onnx/` 后，就可以用 `ORTOptimizer` 施加图优化——如算子融合、常量折叠——来加速延迟与推理。

```
from optimum.onnxruntime import ORTOptimizer
from optimum.onnxruntime.configuration import OptimizationConfig

# create ORTOptimizer and define optimization configuration
optimizer = ORTOptimizer.from_pretrained(model_id, feature=task)
optimization_config = OptimizationConfig(optimization_level=99) # enable all optimizations

# apply the optimization configuration to the model
optimizer.export(
    onnx_model_path=onnx_path / "model.onnx",
    onnx_optimized_model_output_path=onnx_path / "model-optimized.onnx",
    optimization_config=optimization_config,
)
```

要测试性能，再次使用 `ORTModelForQuestionAnswering` 类，多传一个 `file_name` 参数来加载优化后的模型。**（对 Hub 上的模型同样适用。）**

```
from optimum.onnxruntime import ORTModelForQuestionAnswering

# load quantized model
opt_model = ORTModelForQuestionAnswering.from_pretrained(onnx_path, file_name="model-optimized.onnx")

# test the quantized model with using transformers pipeline
opt_optimum_qa = pipeline(task, model=opt_model, tokenizer=tokenizer, handle_impossible_answer=True)
prediction = opt_optimum_qa(question="What's my name?", context="My name is Philipp and I live in Nuremberg.")
print(prediction)
# {'score': 0.9041663408279419, 'start': 11, 'end': 18, 'answer': 'Philipp'}
```

第 [3.6 步"评估性能与速度"](https://huggingface.co/blog/optimum-inference#36-evaluate-the-performance-and-speed)会详细评估性能变化。

### 3.4 用 `ORTQuantizer` 做动态量化

模型优化完成后，还可以用 `ORTQuantizer` 做量化进一步加速。`ORTQuantizer` 可以施加动态量化以缩小模型体积、加速延迟与推理。

*实例由支持 avx512 的 Intel cascade-lake CPU 驱动，所以我们用 `avx512_vnni`。*

```
from optimum.onnxruntime import ORTQuantizer
from optimum.onnxruntime.configuration import AutoQuantizationConfig

# create ORTQuantizer and define quantization configuration
quantizer = ORTQuantizer.from_pretrained(model_id, feature=task)
qconfig = AutoQuantizationConfig.avx512_vnni(is_static=False, per_channel=True)

# apply the quantization configuration to the model
quantizer.export(
    onnx_model_path=onnx_path / "model-optimized.onnx",
    onnx_quantized_model_output_path=onnx_path / "model-quantized.onnx",
    quantization_config=qconfig,
)
```

可以来比较一下模型大小和延迟性能

```
import os
# get model file size
size = os.path.getsize(onnx_path / "model.onnx")/(1024*1024)
print(f"Vanilla Onnx Model file size: {size:.2f} MB")
size = os.path.getsize(onnx_path / "model-quantized.onnx")/(1024*1024)
print(f"Quantized Onnx Model file size: {size:.2f} MB")

# Vanilla Onnx Model file size: 473.31 MB
# Quantized Onnx Model file size: 291.77 MB
```

模型体积从 473MB 压到 291MB，几乎缩小一半。要跑推理，再次使用 `ORTModelForQuestionAnswering` 类，多传 `file_name` 参数加载量化模型。**（对 Hub 上的模型同样适用。）**

```
# load quantized model
quantized_model = ORTModelForQuestionAnswering.from_pretrained(onnx_path, file_name="model-quantized.onnx")

# test the quantized model with using transformers pipeline
quantized_optimum_qa = pipeline(task, model=quantized_model, tokenizer=tokenizer, handle_impossible_answer=True)
prediction = quantized_optimum_qa(question="What's my name?", context="My name is Philipp and I live in Nuremberg.")
print(prediction)
# {'score': 0.9246969819068909, 'start': 11, 'end': 18, 'answer': 'Philipp'}
```

漂亮！模型给出了同样的答案。

### 3.5 用 Transformers pipelines 跑加速推理

[Optimum](https://huggingface.co/docs/optimum/main/en/pipelines#optimizing-with-ortoptimizer) 内置支持 [transformers pipelines](https://huggingface.co/docs/transformers/main/en/main_classes/pipelines#pipelines)，让我们沿用使用 PyTorch 和 TensorFlow 模型时熟悉的那套 API。前面 3.2、3.3、3.4 步我们已经用过了。目前支持 [ONNX Runtime](https://onnxruntime.ai/)，未来还会加入更多。使用 [transformers pipelines](https://huggingface.co/docs/transformers/main/en/main_classes/pipelines#pipelines) 的示例如下。

```
from transformers import AutoTokenizer, pipeline
from optimum.onnxruntime import ORTModelForQuestionAnswering

tokenizer = AutoTokenizer.from_pretrained(onnx_path)
model = ORTModelForQuestionAnswering.from_pretrained(onnx_path)

optimum_qa = pipeline("question-answering", model=model, tokenizer=tokenizer)
prediction = optimum_qa(question="What's my name?", context="My name is Philipp and I live in Nuremberg.")

print(prediction)
# {'score': 0.9041663408279419, 'start': 11, 'end': 18, 'answer': 'Philipp'}
```

除此之外，我们在 Optimum 中加入了 `pipelines` API，为你的加速模型提供更强的安全保障：如果用 `optimum.pipelines` 传入不支持的模型或任务，会直接报错。你可以把 `optimum.pipelines` 当作 `transformers.pipelines` 的替代品。

```
from transformers import AutoTokenizer
from optimum.onnxruntime import ORTModelForQuestionAnswering
from optimum.pipelines import pipeline

tokenizer = AutoTokenizer.from_pretrained(onnx_path)
model = ORTModelForQuestionAnswering.from_pretrained(onnx_path)

optimum_qa = pipeline("question-answering", model=model, tokenizer=tokenizer, handle_impossible_answer=True)
prediction = optimum_qa(question="What's my name?", context="My name is Philipp and I live in Nuremberg.")

print(prediction)
# {'score': 0.9041663408279419, 'start': 11, 'end': 18, 'answer': 'Philipp'}
```

### 3.6 评估性能与速度

在这篇[端到端教程](https://huggingface.co/blog/optimum-inference#3-end-to-end-tutorial-on-accelerating-roberta-for-question-answering-including-quantization-and-optimization)中我们造出了 3 个模型：原生转换版、优化版、量化版。

最后一步，仔细看看模型的性能与准确率。应用图优化、量化等优化技术不仅影响性能（延迟），也可能影响准确率——加速模型是有取舍的。

来评估。我们的 transformers 模型 [deepset/roberta-base-squad2](https://huggingface.co/deepset/roberta-base-squad2) 在 SQUAD2 数据集上微调过，就用它来评估。

```
from datasets import load_metric,load_dataset

metric = load_metric("squad_v2")
dataset = load_dataset("squad_v2")["validation"]

print(f"length of dataset {len(dataset)}")
#length of dataset 11873
```

接下来用 [datasets](https://huggingface.co/docs/datasets/index) 的 [map](https://huggingface.co/docs/datasets/v2.1.0/en/process#map) 函数遍历 squad 2 验证集、对每个数据点跑预测。为此写一个 `evaluate` 辅助方法，调用我们的 pipelines 并做变换以适配 [squad v2 指标](https://huggingface.co/metrics/squad_v2)。

*这会比较久（1.5 小时）*

```
def evaluate(example):
  default = optimum_qa(question=example["question"], context=example["context"])
  optimized = opt_optimum_qa(question=example["question"], context=example["context"])
  quantized = quantized_optimum_qa(question=example["question"], context=example["context"])
  return {
      'reference': {'id': example['id'], 'answers': example['answers']},
      'default': {'id': example['id'],'prediction_text': default['answer'], 'no_answer_probability': 0.},
      'optimized': {'id': example['id'],'prediction_text': optimized['answer'], 'no_answer_probability': 0.},
      'quantized': {'id': example['id'],'prediction_text': quantized['answer'], 'no_answer_probability': 0.},
      }

result = dataset.map(evaluate)
# COMMENT IN to run evaluation on 2000 subset of the dataset
# result = dataset.shuffle().select(range(2000)).map(evaluate)
```

来比较结果

```
default_acc = metric.compute(predictions=result["default"], references=result["reference"])
optimized = metric.compute(predictions=result["optimized"], references=result["reference"])
quantized = metric.compute(predictions=result["quantized"], references=result["reference"])

print(f"vanilla model: exact={default_acc['exact']}% f1={default_acc['f1']}%")
print(f"optimized model: exact={optimized['exact']}% f1={optimized['f1']}%")
print(f"quantized model: exact={quantized['exact']}% f1={quantized['f1']}%")

# vanilla model: exact=79.07858165585783% f1=82.14970024570314%
# optimized model: exact=79.07858165585783% f1=82.14970024570314%
# quantized model: exact=78.75010528088941% f1=81.82526107204629%
```

优化并量化的模型拿到 `78.75%` 的 exact match 和 `81.83%` 的 F1——相当于原始准确率的 `99.61%`。考虑到我们只用了动态量化，达到 `99%` 原始精度已经非常好。

好，来测优化和量化模型的性能（延迟）。

先把上下文和问题扩展到更有意义的 128 长度序列。

```
context="Hello, my name is Philipp and I live in Nuremberg, Germany. Currently I am working as a Technical Lead at Hugging Face to democratize artificial intelligence through open source and open science. In the past I designed and implemented cloud-native machine learning architectures for fin-tech and insurance companies. I found my passion for cloud concepts and machine learning 5 years ago. Since then I never stopped learning. Currently, I am focusing myself in the area NLP and how to leverage models like BERT, Roberta, T5, ViT, and GPT2 to generate business value."
question="As what is Philipp working?"
```

简单起见，用 python 循环分别计算原生模型与优化+量化模型的平均延迟。

```
from time import perf_counter
import numpy as np

def measure_latency(pipe):
    latencies = []
    # warm up
    for _ in range(10):
        _ = pipe(question=question, context=context)
    # Timed run
    for _ in range(100):
        start_time = perf_counter()
        _ =  pipe(question=question, context=context)
        latency = perf_counter() - start_time
        latencies.append(latency)
    # Compute run statistics
    time_avg_ms = 1000 * np.mean(latencies)
    time_std_ms = 1000 * np.std(latencies)
    return f"Average latency (ms) - {time_avg_ms:.2f} +\- {time_std_ms:.2f}"

print(f"Vanilla model {measure_latency(optimum_qa)}")
print(f"Optimized & Quantized model {measure_latency(quantized_optimum_qa)}")

# Vanilla model Average latency (ms) - 117.61 +\- 8.48
# Optimized & Quantized model Average latency (ms) - 64.94 +\- 3.65
```

延迟从 `117.61ms` 压到 `64.94ms`（约 2 倍），同时保留了 `99.61%` 的准确率。要记住我们用的只是中等性能、2 个物理核的 CPU 实例。[换 GPU 或更强的 CPU 实例（如 ice-lake，延迟能降到几毫秒）。](https://huggingface.co/blog/bert-cpu-scaling-part-2#more-efficient-ai-processing-on-latest-intel-ice-lake-cpus)

## 4. 当前局限

我们刚刚开始支持推理，所以也想分享当前的局限。这些都已在路线图上，不久会解决。

- **Hub 上的模型 > 2GB：**当前从 [Hugging Face Hub](https://hf.co/) 加载只支持小于 2GB 的模型。我们正在支持 > 2GB / 多文件模型。
- **Seq2seq 任务/模型：**暂不支持像摘要这样的 seq2seq 任务和 T5 这类模型，主要受单模型支持的限制。我们正在全力推进，以提供与 transformers 一致的使用体验。
- **Past key values：**GPT-2 这类生成模型使用 past key values——预计算的注意力块键值对，可加速解码。目前 ORTModelForCausalLM 不使用 past key values。
- **没有缓存：**加载优化后的模型（*.onnx）时，当前不会在本地缓存。

## 5. Optimum 推理 FAQ

**支持哪些任务？**

支持任务的完整列表见[文档](https://huggingface.co/docs/optimum/main/en/pipelines)。当前支持的 pipeline 任务有 `feature-extraction`、`text-classification`、`token-classification`、`question-answering`、`zero-shot-classification`、`text-generation`

**支持哪些模型？**

任何能用 [transformers.onnx](https://huggingface.co/docs/transformers/serialization) 导出、且任务受支持的模型都能用，包括 BERT、ALBERT、GPT2、RoBERTa、XLM-RoBERTa、DistilBERT……

**支持哪些运行时？**

目前支持 ONNX Runtime，未来会加入更多。感兴趣的具体运行时可以[告诉我们](https://discuss.huggingface.co/c/optimum/59)。

**如何配合 Transformers 使用 Optimum？**

示例和说明见[文档](https://huggingface.co/docs/optimum/main/en/pipelines#transformers-pipeline-usage)。

**如何用 GPU？**

安装 `optimum[onnxruntine-gpu]` 即可装上所需的 GPU provider，并默认使用。

**如何用 pipelines 跑量化+优化的模型？**

用新的 [ORTModelForXXX](https://huggingface.co/docs/optimum/main/en/onnxruntime/modeling_ort) 类加载优化或量化模型，通过 [from_pretrained](https://huggingface.co/docs/optimum/main/en/onnxruntime/modeling_ort#optimum.onnxruntime.ORTModelForQuestionAnswering.forward.example) 方法。详见[文档](https://huggingface.co/docs/optimum/main/en/onnxruntime/modeling_ort#optimum-inference-with-onnx-runtime)。

## 6. 接下来？

Optimum 的下一步是什么？很多事情。我们的目标是让 Optimum 成为使用 transformer 做加速与优化的参考级开源工具包。为此我们会解决当前局限、完善文档、产出更多内容与示例，不断突破 transformer 加速与优化的边界。

除了[当前局限](https://huggingface.co/blog/optimum-inference#4-current-limitations)，路线图上还有这些重要特性：

- 支持语音模型（Wav2vec2）与语音任务（自动语音识别）
- 支持视觉模型（ViT）与视觉任务（图像分类）
- 通过支持 [OrtValue](https://onnxruntime.ai/docs/api/python/api_summary.html#ortvalue) 和 [IOBinding](https://onnxruntime.ai/docs/api/python/api_summary.html#iobinding) 提升性能
- 提供更简单的方式来评估加速后的模型
