原生 Speech to Speech 模型的出现，为提升语音智能体能力、简化语音工作流带来了令人兴奋的机会。但关键是评估：这种简化是否以模型性能为代价，或带来了其他取舍。

为支持这方面的分析，Artificial Analysis 发布了 **[Big Bench Audio](https://huggingface.co/datasets/ArtificialAnalysis/big_bench_audio)**——一个评估音频语言模型推理能力的新评测数据集。该数据集把 **[Big Bench Hard](https://arxiv.org/pdf/2210.09261)** 的问题（因其对高阶推理的严格检验而被选中）改造进了音频域。

本文介绍 Big Bench Audio 数据集，并给出 GPT-4o 与 Gemini 1.5 系列模型的最初基准结果。我们的分析在多种模态组合上测试这些模型：原生 Speech to Speech、Speech to Text、Text to Speech 和 Text to Text。结果概要见下文以及 [**Artificial Analysis** 网站](https://artificialanalysis.ai/models/speech-to-speech)新的 Speech to Speech 页面。初步结果显示存在一个显著的「语音推理差距」：GPT-4o 在数据集的纯文本版本上准确率 92%，而它的 Speech to Speech 表现跌到 66%。

## Big Bench Audio 数据集

[Big Bench Audio](https://huggingface.co/datasets/ArtificialAnalysis/big_bench_audio) 包含 **1,000 个音频问题**，选自 Big Bench Hard 的四个类别，每个类别都因适合音频评估而被选中：

- **Formal Fallacies**：根据给定陈述做逻辑演绎
- **Navigate**：判断一系列导航步骤是否回到原点
- **Object Counting**：对集合中的特定物品计数
- **Web of Lies**：评估用自然语言表达的布尔逻辑

每个类别贡献 250 个问题，构成一个均衡的数据集，避开了重度依赖视觉元素、或口头表达后可能产生歧义的任务。

数据集中每个问题的结构如下：

```
{
  "category": "formal_fallacies",
  "official_answer": "invalid",
  "file_name": "data/question_0.mp3",
  "id": 0
}
```

音频文件由 **[Artificial Analysis Speech Arena](https://artificialanalysis.ai/text-to-speech/arena?tab=Leaderboard)** 中排名靠前的 Text to Speech 模型的 **23 个合成声音**生成。每个音频生成都用 Levenshtein 距离对照转录做了严格校验，边界案例经过人工复核。想了解数据集如何创建，请查看 **[dataset card](https://huggingface.co/datasets/ArtificialAnalysis/big_bench_audio)**。

## 评估音频推理

为评估音频对每个模型推理性能的影响，我们在 Big Bench Audio 上测试了 **四种不同配置**：

- **Speech to Speech**：输入一个音频文件，模型生成包含答案的输出音频文件。
- **Speech to Text**：输入一个音频文件，模型生成文本回答。
- **Text to Speech**：提供问题的文本版本，模型生成包含答案的输出音频文件。
- **Text to Text**：提供问题的文本版本，模型生成文本回答。

### 评估方法

为确保所有配置下评估的一致性与可扩展性，我们开发了一个基于 LLM Evaluator 的自动评估系统。其工作方式是：

- 对音频回答，先用 OpenAI 的 Whisper API 转录成文本
- 对文本回答，直接作为「候选答案」使用
- LLM Evaluator 接收：候选答案、官方答案、原始问题（作为上下文）

LLM Evaluator 拿到候选答案、官方答案与原始问题作为上下文，被要求把候选答案标为 **正确或错误**。对于 Artificial Analysis 上列出的 Big Bench Audio 分数，我们使用 Anthropic 的 Claude 3.5 Sonnet (Oct '24) 作为 LLM 评估器。

**LLM Evaluator 提示词：**

```
Assess whether the following CANDIDATE ANSWER is CORRECT or INCORRECT.
For the CANDIDATE ANSWER to be correct, it must be consistent with the OFFICIAL ANSWER.
If the CANDIDATE ANSWER contradicts itself, assess the first proposed answer.
If the CANDIDATE ANSWER provides a final answer and working, assess the final answer only.
If the CANDIDATE ANSWER includes irrelevant information, assess only the relevant information.
If the CANDIDATE ANSWER includes a numeric value it is ok if it is spelled e.g. 7 or seven
It is ok if the CANDIDATE ANSWER involves a misspelling of a person's name e.g. Leda or Lida, Autry or Audrie.
  
The question, for reference only: START QUESTION {question} \n\nEND QUESTION

The OFFICIAL ANSWER:{official_answer}

BEGIN CANDIDATE ANSWER TO ASSESS

{candidate_answer}

END CANDIDATE ANSWER TO ASSESS

Reply only with CORRECT or INCORRECT.
```

### 音频推理差距

我们的分析揭示出文本推理与音频推理之间的大幅性能差距。GPT-4o (Aug '24) 在数据集的 Text to Text 版本上准确率 92%，而其 Speech to Speech 对应版本（GPT-4o Realtime Preview Oct '24）只得 66%。Text to Speech 配置取得介于两者之间的 74%，说明语音输入和语音输出都在造成性能差距。

### 就推理而言，Speech to Speech 流水线目前胜过原生音频

传统流水线方案（用 Whisper 转录、GPT-4o (Aug '24) 推理、TTS-1 配音）相比纯文本处理只有极小的性能退化。这表明：在推理准确性至关重要的应用中，流水线方案目前在性能与音频能力之间提供了最佳平衡。

我们预计这一差距会随时间缩小，并将持续用 Big Bench Audio 测试新的 Speech to Speech 模型。Google 的 Gemini 2.0 Flash 的 Speech to Speech 模式更新，敬请留意！
