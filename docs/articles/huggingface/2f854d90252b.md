# 🚧 给搭建花哨神经网络的简单人的简单思考

随着机器学习不断渗透到行业的方方面面，神经网络从未如此被热炒。比如 GPT-3 这样的模型过去几周在社交媒体上随处可见，还在科技新闻之外持续制造头条，配上危言耸听的标题。

[![Builders](https://huggingface.co/blog/assets/13_simple-considerations/1_sENCNdlC7zK4bg22r43KiA.png)](https://huggingface.co/blog/assets/13_simple-considerations/1_sENCNdlC7zK4bg22r43KiA.png)

The Guardian 上的一篇文章

与此同时，深度学习框架、工具和专用库正通过让最先进研究比以往更易用来推动机器学习的平民化。我们常会见到这些近乎魔法、即插即用的 5 行代码，承诺（接近）最先进的结果。在 [Hugging Face](https://huggingface.co/) 🤗 工作，我承认我在这方面多少有些"罪责"。😅 它会让没有经验的用户产生一种误导性印象，以为神经网络如今已是成熟技术，而事实上这个领域一直在发展。

现实中，**构建和训练神经网络常常是一件极其令人沮丧的事**：

- 有时很难弄清你的表现究竟是来自模型/代码里的一个 bug，还是仅仅受限于模型的表达能力。
- 你会在过程的每一步犯一堆小错而一时没察觉，而你的模型照样能训练、并给出还不错的表现。

**在这篇帖子里，我会尝试强调我在构建和调试神经网络时心路历程的几个步骤。** 这里说的"调试"，是指确保你所构建的东西与你心里想的对得上。我也会列出一些当你不确定下一步该怎么做时可以参考的点，并罗列我通常会问自己的典型问题。

*很多这些想法源于我做自然语言处理研究的经验，但其中大部分原则可以套用到机器学习的其他领域。*

## 1. 🙈 先把机器学习放到一边

这听起来可能反直觉，但构建神经网络的第一步，是把机器学习放到一边、只关注你的数据。看看那些样本、它们的标签、如果你处理文本则看词汇的多样性、长度分布等等。你应该深入数据去感受你在处理的原始产品，专注于提炼出模型可能捕捉得到的一般模式。希望在看了几百个样本后，你能识别出高层模式。几个你可以问自己的标准问题：

- 标签均衡吗？
- 有没有你不同意的"金标签"（gold-label）？
- 数据是怎么获取的？这个过程中可能的噪声来源是什么？
- 有没有什么看起来自然的预处理步骤（分词、去除 URL 或话题标签等）？
- 样本的多样性如何？
- 什么样的规则算法在这个问题上能表现得尚可？

重要的是对你的数据集有一个**高层的（定性）感觉，同时辅以细粒度（定量）分析**。如果你在处理一个公开数据集，别人可能已经深入数据并报告过他们的分析（比如在 Kaggle 竞赛里很常见），所以你绝对该去看看这些！

## 2. 📚 就当自己刚学机器学习那样继续

一旦你对数据有了又深又广的理解，我始终建议**把自己放回当年刚接触机器学习、还在 Coursera 上看 Andrew Ng 入门课的那个自己的位置上**。**从尽可能简单的起点开始**，以感受任务的难度、以及标准基线会表现得多好。比如，如果你处理文本，二分类文本的标准基线可以包括在 word2vec 或 fastText 嵌入之上训练一个逻辑回归。以目前的工具而言，跑这些基线和跑 BERT 一样简单（甚至更简单），而 BERT 可以说得上是许多 NLP 问题的标准工具之一。如果有其他基线可用，跑（或实现）其中一些。这会帮你更熟悉数据。

作为开发者，构建花哨东西时很容易自我感觉良好，但如果它只比简单基线好上几个点，有时很难给它一个理性的辩解，所以确保你有合理的对照点非常核心：

- 一个随机预测器会表现如何（尤其分类问题）？数据集可能不均衡……
- 对随机预测器而言损失会长什么样？
- 衡量我在任务上进步的最佳指标是什么？
- 这个指标的局限是什么？如果它完美，我能得出什么结论？得不出什么？
- "简单方法"里缺了什么才能达到满分？
- 我的神经网络工具箱里有没有哪些架构能很好地建模数据的归纳偏置？

## 3. 🦸‍♀️ 别怕去看这些 5 行模板的底层

接下来，你可以基于先前获得的洞察和理解开始构建你的模型。如前所述，实现神经网络会很快变得相当棘手：有很多协同工作的活动部件（优化器、模型、输入处理流水线等），在实现这些部件并把它们互相连接时很多小地方会出错。**挑战在于，你犯了这些错，模型照样能训练、从不出错，结果看起来还不错……**

然而，当你以为实现完成时，有一个好习惯是**在一个小批样本上过拟合**（比如 16 个）。如果你的实现（近乎）正确，你的模型应当能过拟合、通过显示 0 损失记住这些样本（确保你移除任何形式的正则化，比如权重衰减）。如果不能，极有可能是你在实现里做错了什么。在少数情况下，这意味着你的模型表达能力不够或缺乏容量。同样，**从小规模模型开始**（比如更少的层数）：你在调试模型，所以要的是快速反馈回路，而非高性能。

> 小贴士：以我处理预训练语言模型的经验，把嵌入模块冻结在其预训练值上，对微调任务性能影响不大，却能显著加快训练。

一些常见错误包括：

- 索引错了……（这些是最糟的 😅）。比如确保你沿正确的维度收集张量……
- 你忘了在评估模式下调 `model.eval()`（在 PyTorch 里）或调 `model.zero_grad()` 来清理梯度
- 输入的预处理出了问题
- 损失拿到的参数不对（比如在它期望 logits 时传入了概率）
- 初始化没有打破对称（通常发生在你用一个常数初始化整个矩阵时）
- 有些参数在前向传播中从未被调用（因而收不到梯度）
- 学习率一直在取一些奇怪的值，比如始终是 0
- 你的输入被以一种欠佳的方式截断

> 小贴士：当你处理语言时，认真看看分词器的输出。我数不清自己花了多少"Lost hours"去复现结果（有时甚至复现我自己以前的结果），就因为分词出了问题。🤦‍♂️

另一个有用的工具是**深入训练动态**，并（比如在 Tensorboard 里）绘制训练中多个标量随时间的演化。至少，你应当看看你的损失、参数及其梯度的动态。

随着损失下降，你也想看看模型的预测：要么在开发集上评估，要么——我个人最爱的——**打印几个模型输出**。例如，如果你在训练一个机器翻译模型，看着生成为越来越令人信服的过程是很满足的。你要特别小心过拟合：你的训练损失还在下降，而评估损失却直奔云霄。💫

## 4. 👀 调参，但别瞎调

一旦一切都跑起来了，你可能想调超参数，为你的配置找到最佳组合。我一般坚持随机网格搜索，因为它在实践中相当有效。

> 有人报告说用贝叶斯优化这类花哨的超参调优方法取得成功，但以我的经验，在一个合理手工定义的网格上随机搜索仍是一个难以被击败的基线。

最重要的是，用不同的超参（或像激活函数这样的架构微调）启动 1000 次运行毫无意义：**对比几次用不同超参的运行，以了解哪些超参影响最大**；但总体而言，指望只调几个值就拿到最大的性能跃升是一种幻觉。比如，如果你表现最好的模型是用 4e2 的学习率训练的，那你的神经网络内部大概有什么更根本的东西在起作用，你想识别并理解这个行为，这样你就能在当前特定语境之外复用这份知识。

平均而言，专家用更少的资源找到更好的方案。

总之，一条一直帮助我把构建神经网络做得更好的普遍建议是：**尽可能（尽量）去深入理解神经网络的每个组件，而不是盲目地（甚至带有魔法意味地）去微调架构**。保持简单，避免那些你即使拼命尝试也无法理性辩解的小改动。当然，在"试错法"和"分析法"之间要找到一个恰当的平衡，但随着你积累实践经验，很多这些直觉会越来越自然。**你自己也在训练你的内部模型。** 🤯
