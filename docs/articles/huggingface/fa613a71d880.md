# 用 TensorFlow 和 TPU 在 🤗 Transformers 中训练语言模型

## 引言

TPU 训练是一门有用的技能：TPU pod 性能高、扩展性极强，从数千万参数到真正巨大的规模都能轻松训练：Google 的 PaLM 模型（超过 5000 亿参数！）就完全在 TPU pod 上训练。

我们此前写过一篇[教程](https://huggingface.co/docs/transformers/main/perf_train_tpu_tf)和一个 [Colab 示例](https://colab.research.google.com/github/huggingface/notebooks/blob/main/examples/tpu_training-tf.ipynb)，演示用 TensorFlow 做小规模 TPU 训练，并介绍让模型跑在 TPU 上需要理解的核心概念。这次我们要再上一个台阶：用 TensorFlow 和 TPU 从零训练一个掩码语言模型，涵盖从训练 tokenizer、准备数据集到最终模型训练与上传的每一步。这类任务你大概会想要一个专用 TPU 节点（或 VM），而不是只用 Colab，所以我们的重点也放在这里。

和我们的 Colab 示例一样，我们借助 TensorFlow 通过 XLA 和 `TPUStrategy` 提供的非常干净的 TPU 支持。我们还会受益于这样一个事实：🤗 Transformers 中大部分 TensorFlow 模型都完全 [XLA 兼容](https://huggingface.co/blog/tf-xla-generate)。所以令人惊讶的是，让它们跑在 TPU 上几乎不需要什么工作。

与 Colab 示例不同，这个示例被设计为**可扩展**的，更接近一次真实的训练运行——尽管我们默认只用一个 BERT 规模的模型，只需更改几个配置项，这段代码就能扩展到更大的模型和更强的 TPU pod slice。

## 动机

我们为什么现在写这份指南？毕竟 🤗 Transformers 支持 TensorFlow 已有数年。但让这些模型在 TPU 上训练一直是社区的痛点，因为：

- 许多模型不兼容 XLA
- Data collator 没有使用原生 TF 操作

我们认为 XLA 是未来：它是 JAX 的核心编译器，在 TensorFlow 中有一等支持，你甚至可以在 [PyTorch](https://github.com/pytorch/xla) 里使用它。因此我们做了[一次大力推进](https://blog.tensorflow.org/2022/11/how-hugging-face-improved-text-generation-performance-with-xla.html)，让代码库兼容 XLA，并移除其他阻碍 XLA 与 TPU 兼容的障碍。这意味着用户应该能够轻松地在 TPU 上训练我们的大部分 TensorFlow 模型。

现在关注 TPU 训练还有一个重要原因：LLM 和生成式 AI 的最新重大进展激发了公众对模型训练的巨大兴趣，以至于对大多数人来说，获得最先进 GPU 已变得极其困难。懂得在 TPU 上训练，等于为你打开了另一条获取超高算力硬件的道路——这比在 eBay 上竞标最后一块 H100 失败后趴在桌上痛哭体面多了。你值得更好的。而且以亲身经历说：一旦你习惯了在 TPU 上训练，你可能就不想回去了。

## 你将看到什么

我们要在 [WikiText 数据集 (v1)](https://huggingface.co/datasets/wikitext) 上从零训练一个 [RoBERTa](https://huggingface.co/docs/transformers/model_doc/roberta)（base 模型）。除了训练模型，我们还要训练 tokenizer、对数据做 tokenize 并以 TFRecord 格式上传到 Google Cloud Storage，供 TPU 训练访问。全部代码在[这个目录](https://github.com/huggingface/transformers/tree/main/examples/tensorflow/language-modeling-tpu)。如果你是某种性格的人，可以直接跳过博客剩下的部分去看代码；但如果你留下来，我们会更深入地看看代码库中的一些关键思想。

这里的许多观点在我们的 [Colab 示例](https://colab.research.google.com/github/huggingface/notebooks/blob/main/examples/tpu_training-tf.ipynb)中也提到过，但我们想给用户展示一个完整的端到端示例，把它们组装起来并实际运行，而不是只在高层讲概念。下图概览了用 TensorFlow 和 TPU 通过 🤗 Transformers 训练语言模型所涉及的步骤：

![tf-tpu-training-steps](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/tf_tpu/tf_tpu_steps.png)

## 获取数据并训练 tokenizer

如前所述，我们使用 [WikiText 数据集 (v1)](https://huggingface.co/datasets/wikitext)。你可以去 [Hugging Face Hub 上的数据集页面](https://huggingface.co/datasets/wikitext)浏览它。

![dataset-explore](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/tf_tpu/wikitext_explore.png)

由于数据集已以兼容格式存在于 Hub 上，我们可以用 🤗 datasets 轻松加载和交互。不过在这个示例中，由于我们同时也要从零训练 tokenizer，我们做了：

- 用 🤗 datasets 加载 WikiText 的 `train` split。
- 用 🤗 tokenizers 训练一个 [Unigram 模型](https://huggingface.co/course/chapter6/7?fw=pt)。
- 把训练好的 tokenizer 上传到 Hub。

tokenizer 训练代码见[这里](https://github.com/huggingface/transformers/tree/main/examples/tensorflow/language-modeling-tpu#training-a-tokenizer)，tokenizer 本体在[这里](https://huggingface.co/tf-tpu/unigram-tokenizer-wikitext)。该脚本也允许你对 Hub 上[任何兼容的数据集](https://huggingface.co/datasets?task_ids=task_ids:language-modeling)运行。

> 💡 用 🤗 datasets 托管你的文本数据集很容易，参阅指南了解更多。

## 对数据做 tokenize 并创建 TFRecord

tokenizer 训练好后，我们可以将它用于所有 split（本例中是 `train`、`validation` 和 `test`），并把它们做成 TFRecord shard。把数据分摊到多个 TFRecord shard 有利于大规模并行处理，比每个 split 只放一个 TFRecord 文件更好。

我们逐个样本 tokenize，然后取一批样本拼接起来，切成固定大小（本例为 128）的若干 chunk。我们采用这一策略，而不是用固定长度 tokenize 整个 batch，以避免因截断而大量丢弃文本内容。

随后我们把这些 tokenized 样本按批取出，序列化为多个 TFRecord shard——shard 数量由数据集总长度和单个 shard 大小决定。最后这些 shard 被推送到 [Google Cloud Storage (GCS) bucket](https://cloud.google.com/storage/docs/json_api/v1/buckets)。

如果你用 TPU 节点训练，数据需要从 GCS bucket 流式读取，因为节点宿主机内存很小。但对 TPU VM，可以本地使用数据集，甚至给 VM 挂持久存储。由于 TPU 节点至今仍被广泛使用，我们的示例基于 GCS bucket 存储数据。

你可以在[这个脚本](https://github.com/huggingface/transformers/blob/main/examples/tensorflow/language-modeling-tpu/prepare_tfrecord_shards.py)中看到这一切的代码。为便于使用，我们还把生成的 TFRecord shard 托管在 Hub 上的[这个仓库](https://huggingface.co/datasets/tf-tpu/wikitext-v1-tfrecords)。

## 在 GCS 数据上训练模型

如果你熟悉 🤗 Transformers，你已经知道建模代码：

```
from transformers import AutoConfig, AutoTokenizer, TFAutoModelForMaskedLM

tokenizer = AutoTokenizer.from_pretrained("tf-tpu/unigram-tokenizer-wikitext")

config = AutoConfig.from_pretrained("roberta-base")
config.vocab_size = tokenizer.vocab_size
model = TFAutoModelForMaskedLM.from_config(config) 
```

但既然我们身在 TPU 领地，需要在 strategy scope 下完成这个初始化，才能让模型随数据并行训练分布到各个 TPU worker：

```
import tensorflow as tf

tpu = tf.distribute.cluster_resolver.TPUClusterResolver(...)
strategy = tf.distribute.TPUStrategy(tpu)

with strategy.scope():
    tokenizer = AutoTokenizer.from_pretrained("tf-tpu/unigram-tokenizer-wikitext")
    config = AutoConfig.from_pretrained("roberta-base")
    config.vocab_size = tokenizer.vocab_size
    model = TFAutoModelForMaskedLM.from_config(config) 
```

类似地，优化器也需要在与模型编译相同的 strategy scope 下初始化。完整训练代码我们不在本文逐行讲解，欢迎你到[这里](https://github.com/huggingface/transformers/blob/main/examples/tensorflow/language-modeling-tpu/run_mlm.py)阅读。相反，我们讨论另一个关键点——一个 TensorFlow 原生的 data collator [`DataCollatorForLanguageModeling`](https://huggingface.co/docs/transformers/main_classes/data_collator#transformers.DataCollatorForLanguageModeling)。

`DataCollatorForLanguageModeling` 负责从输入序列中随机选 token 做掩码并准备标签。默认这些 collator 返回 NumPy 数组；但许多 collator 也支持在指定 `return_tensor="tf"` 时返回 TensorFlow tensor。这对我们的数据管道兼容 TPU 训练至关重要。

值得感谢的是，TensorFlow 对从 GCS bucket 读取文件提供了无缝支持：

```
training_records = tf.io.gfile.glob(os.path.join(args.train_dataset, "*.tfrecord"))
```

如果 `args.dataset` 含有 `gs://` 标识符，TensorFlow 就知道要去看 GCS bucket。想本地加载只需去掉 `gs://` 标识符。数据管道相关的其余代码可参见训练脚本的[这一节](https://github.com/huggingface/transformers/blob/474bf508dfe0d46fc38585a1bb793e5ba74fddfd/examples/tensorflow/language-modeling-tpu/run_mlm.py#L186-#L201)。

数据集准备完毕、模型与优化器初始化、模型编译好之后，我们就可以做社区最爱的事——`model.fit()`。训练时我们没有做大量超参数调优，只是以 1e-4 的学习率训练了更久。我们还用了 [`PushToHubCallback`](https://huggingface.co/docs/transformers/main_classes/keras_callbacks#transformers.PushToHubCallback) 做模型 checkpoint 并与 Hub 同步。超参数细节和训练好的模型在这里：[https://huggingface.co/tf-tpu/roberta-base-epochs-500-no-wd](https://huggingface.co/tf-tpu/roberta-base-epochs-500-no-wd)。

模型训练完成后，用它做推理同样简单：

from transformers import pipeline

model_id = "tf-tpu/roberta-base-epochs-500-no-wd"
unmasker = pipeline("fill-mask", model=model_id, framework="tf")
unmasker("Goal of my life is to [MASK].")

## 结语

如果这个示例有一件事是我们想强调的，那就是 TPU 训练**强大、可扩展且简单**。事实上，如果你已经用 TF/Keras 搭配 🤗 Transformers 模型并从 `tf.data` 流式读取数据，你可能会惊讶于把整个训练管道搬到 TPU 需要的工作量如此之少。TPU 的名声有点晦涩高端、复杂难懂，但其实相当平易近人；而且启动一个大的 pod slice，绝对比维护多台 GPU 服务器同步要容易！

让最先进模型训练所用的硬件多样化，在 2020 年代将变得关键——尤其如果 GPU 短缺持续下去。希望这份指南能给你所需工具，无论面对什么境遇都能支撑前沿的训练运行。
