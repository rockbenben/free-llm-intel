# Hugging Face Reads，2021 年 2 月——长程 Transformers

Efficient Transformers taxonomy from Efficient Transformers: a Survey by Tay et al.

由 Teven Le Scao、Patrick Von Platen、Suraj Patil、Yacine Jernite 和 Victor Sanh 共同撰写。

> 每月我们会选一个主题精读，读一组该主题近期发表的四篇论文。然后我们写一篇简短博客，总结它们的发现与共性趋势，以及读完后为后续工作留下的问题。2021 年 1 月的第一个主题是稀疏与剪枝，2021 年 2 月我们处理的是 Transformers 中的长程注意力。

## 引言

2018、2019 年大型 Transformer 模型兴起之后，两个迅速显现的趋势都在降低其计算需求。其一，条件计算、量化、蒸馏和剪枝让大模型在算力受限环境下的推理成为可能——我们在[上期读书会文章](https://discuss.huggingface.co/t/hugging-face-reads-01-2021-sparsity-and-pruning/3144)里已部分讨论过。随后研究社区转向降低预训练成本。

其中一个问题处于努力的正中心：Transformer 相对序列长度的内存与时间二次方开销。为了让超大模型可以有效训练，2020 年涌现了大量论文攻克这一瓶颈，把 Transformer 扩展到年初 NLP 默认的 512 或 1024 序列长度之外。

这一主题从一开始就是我们研究讨论的核心，我们团队的 Patrick Von Platen 还专门为 [Reformer](https://huggingface.co/blog/reformer) 写过[四部曲](https://huggingface.co/blog/reformer)。这次读书会，我们不求面面俱到（方法实在太多了！），而是聚焦四个主要思路：

- 自定义注意力模式（[Longformer](https://arxiv.org/abs/2004.05150)）
- 递归（[Compressive Transformer](https://arxiv.org/abs/1911.05507)）
- 低秩近似（[Linformer](https://arxiv.org/abs/2006.04768)）
- 核近似（[Performer](https://arxiv.org/abs/2009.14794)）

想要该领域的全面综述，请看 [Efficient Transformers: A Survey](https://arxiv.org/abs/2009.06732) 和 [Long Range Arena](https://arxiv.org/abs/2011.04006)。

## 摘要

### Longformer - The Long-Document Transformer

Iz Beltagy, Matthew E. Peters, Arman Cohan

Longformer 把常规自注意力替换为"窗口/局部/稀疏注意力（参见 [Sparse Transformers (2019)](https://arxiv.org/abs/1904.10509)）+ 全局注意力"的组合，其开销随序列长度线性增长，以此解决 Transformer 的内存瓶颈。与此前的长程 Transformer 模型（如 [Transformer-XL (2019)](https://arxiv.org/abs/1901.02860)、[Reformer (2020)](https://arxiv.org/abs/2001.04451)、[Adaptive Attention Span (2019)](https://arxiv.org/abs/1905.07799)）不同，Longformer 的自注意力层被设计为标准自注意力的即插即用替代，因此可以拿预训练 checkpoint 继续做长序列任务的预训练和/或微调。

标准自注意力矩阵（图 a）随输入长度呈二次方增长：

Figure taken from Longformer

Longformer 对自回归语言建模、编码器预训练与微调、seq2seq 任务使用不同的注意力模式。

- 自回归语言建模中，把因果自注意力（GPT2 风格）替换为膨胀窗口自注意力（图 c）效果最好。设 n 为序列长度、w 为窗口长度，该模式把内存消耗从 n² 降到 w·n——在 w≪n 的假设下随序列长度线性增长。
- 编码器预训练中，Longformer 把双向自注意力（BERT 风格）替换为局部窗口与全局双向自注意力的组合（图 d）。内存消耗从 n² 降到 w·n + g·n，其中 g 是被全局关注的 token 数，同样随序列长度线性增长。
- 对 seq2seq 模型，只有编码器层（BART 风格）被替换为局部+全局双向自注意力的组合（图 d），因为多数 seq2seq 任务中只有编码器要处理超长输入（如摘要）。内存消耗因此从 n_s² + n_s·n_t + n_t² 降到 w·n_s + g·n_s + n_s·n_t + n_t²，其中 n_s、n_t 分别为源（编码器输入）与目标（解码器输入）长度。Longformer Encoder-Decoder 要高效，前提是 n_s 远大于 n_t。

#### 主要发现

- 作者提出了膨胀窗口自注意力（图 c），并证明它在语言建模上优于单纯的窗口/稀疏自注意力（图 b）。窗口尺寸随层数递增。该模式在下游基准上进一步超越了先前的架构（如 Transformer-XL、自适应注意力跨度）。
- 全局注意力让信息可以流经整个序列；把全局注意力施加在有任务依据的 token 上（如 QA 中问题的 token、句子分类的 CLS token）能提升下游任务表现。借助这一全局模式，Longformer 可以成功应用于迁移学习设定下的文档级 NLP 任务。
- 标准预训练模型只需把常规自注意力替换为本文提出的长程自注意力，再在下游任务上微调，即可适配长输入——这避免了为长程输入做昂贵的专属预训练。

#### 后续问题

- 膨胀窗口自注意力随层数递增的窗口大小，让人联想到计算机视觉中堆叠 CNN 增大感受野的发现。这两个发现有什么关联？有哪些可以互相迁移的经验？
- Longformer 的 Encoder-Decoder 架构很适合目标长度不长的任务（如摘要）。但对需要长目标输出的长程 seq2seq 任务（如文档翻译、语音识别），尤其是考虑到 encoder-decoder 模型的 cross-attention 层，它会表现如何？
- 实践中，滑动窗口自注意力依赖大量索引操作来保证 query-key 权重矩阵的对称性。这些操作在 TPU 上非常慢，凸显了此类模式在其他硬件上的适用性问题。

### Compressive Transformers for Long-Range Sequence Modelling

Jack W. Rae, Anna Potapenko, Siddhant M. Jayakumar, Timothy P. Lillicrap

[Transformer-XL (2019)](https://arxiv.org/abs/1901.02860) 证明，把此前计算的层激活缓存在 memory 里可以提升语言建模任务（如 *enwik8*）的表现。模型不只关注当前的 n 个输入 token，还能关注过去 n_m 个 token，n_m 即模型的 memory 大小。Transformer-XL 的内存复杂度是 O(n² + n·n_m)，n_m 很大时内存开销会显著上升。因此 Transformer-XL 不得不在缓存激活数超过 n_m 时丢弃过去的激活。Compressive Transformer 解决了这个问题：额外增加一个压缩 memory，高效缓存那些原本会被丢弃的过去激活，使模型能利用多得多的历史激活，学到更好的长程序列依赖。

Figure taken from Compressive Transformer

压缩因子 c（示意图中为 3）决定过去激活的压缩速率。作者实验了不同的压缩函数 f_c，如 max/mean pooling（无参数）和 1D 卷积（可训练层）。压缩函数通过沿时间反向传播或局部辅助压缩损失来训练。除当前长度 n 的输入外，模型还能关注常规 memory 里的 n_m 个缓存激活和压缩 memory 里的 n_{cm} 个激活，支持的长时依赖达到 l × (n_m + c·n_{cm})，其中 l 是注意力层数。这比 Transformer-XL 多覆盖 l × c × n_{cm} 个 token，内存开销为 O(n² + n·n_m + n·n_{cm})。实验覆盖强化学习、音频生成和自然语言处理。作者还提出了新的长程语言建模基准 [PG19](https://huggingface.co/datasets/pg19)。

#### 主要发现

- Compressive Transformer 在语言建模的状态最优困惑度上大幅领先，尤其是在 enwik8 和 WikiText-103 数据集上。压缩 memory 对建模长序列中的罕见词起着关键作用。
- 作者展示，模型学会了保留显著信息——越来越多地关注压缩 memory 而非 regular memory，这与"旧记忆被访问频率更低"的常规趋势相反。
- 各种压缩函数（average pooling、max pooling、1D 卷积）结果相似，证实 memory 压缩是存储历史信息的行之有效的方法。

#### 后续问题

- Compressive Transformer 需要特殊的优化调度：有效 batch size 要逐步增大，否则在较低学习率下性能会显著退化。这一效应尚未被很好理解，值得更多分析。
- 相比 BERT 或 GPT2 这样的简单模型，Compressive Transformer 多出许多超参数：压缩率、压缩函数与损失、常规与压缩 memory 大小等等。这些参数能否很好地泛化到不同任务（语言建模之外），还是像学习率一样让训练很脆弱，并不清楚。
- 对 regular memory 和 compressed memory 做 probing 会很有趣，可以分析长序列中到底记住了什么信息。厘清哪些信息最显著，能为 [Funnel Transformer](https://arxiv.org/abs/2006.03236) 这类方法提供依据——后者削减了维持全长 token 级序列的冗余。

### Linformer: Self-Attention with Linear Complexity

Sinong Wang, Belinda Z. Li, Madian Khabsa, Han Fang, Hao Ma

目标是把自注意力相对序列长度 n 的复杂度从二次降到线性。论文观察到注意力矩阵是低秩的（即并不包含 n×n 那么多信息），并探索用高维数据压缩技术构建更省内存的 Transformer。

所提方法的理论基础是 Johnson-Lindenstrauss 引理。考虑高维空间中的 m 个点，我们想把它投影到低维空间，同时在误差 ε 范围内保持数据集的结构（即点与点之间的距离）。Johnson-Lindenstrauss 引理告诉我们：可以选取小维度 k ∼ 8 log(m) / ε²，并且只需尝试随机正交投影，就能在多项式时间内找到合适的投影到 R^k 的方法。

Linformer 通过学习注意力上下文矩阵的低秩分解，把序列长度投影到更小的维度。自注意力的矩阵乘法被巧妙地重写，从此不需要计算和存储任何 n×n 的矩阵。

Standard transformer:

Attention(Q, K, V) = softmax(Q * K) * V

```
              (n * h)	            (n * n)   (n * h)
```

Linformer:

LinAttention(Q, K, V) = softmax(Q * K * W^K) * W^V * V

```
              (n * h)	            (n * d)   (d * n)   (n * h)
```

#### 主要发现

- 自注意力矩阵是低秩的，意味着其大部分信息可以由前几个最大特征值恢复，可用低秩矩阵近似。
- 大量工作聚焦于降低隐藏状态维度。本文证明：通过学习投影来缩短序列长度同样可以是强有力的替代方案，并把自注意力的内存复杂度从二次降到线性。
- 增加序列长度不影响 Linformer 的推理速度（wall-clock）——普通 Transformer 此时是线性增长。此外，收敛速度（更新次数）也不受 Linformer 自注意力的影响。

Figure taken from Linformer

#### 后续问题

- 尽管投影矩阵在各层间共享，本文方法与 Johnson-Lindenstrauss 引理（随机正交投影在多项式时间内已足够）形成了对照。这里用随机投影行不行？这让人想起 Reformer——它在局部敏感哈希中使用随机投影来降低自注意力的内存复杂度。

### Rethinking Attention with Performers

Krzysztof Choromanski, Valerii Likhosherstov, David Dohan, Xingyou Song, Andreea Gane, Tamas Sarlos, Peter Hawkins, Jared Davis, Afroz Mohiuddin, Lukasz Kaiser, David Belanger, Lucy Colwell, Adrian Weller

目标（还是它！）是把自注意力相对序列长度 n 的复杂度从二次降到线性。与其他论文不同，作者指出自注意力的稀疏性和低秩先验在其他模态（语音、蛋白质序列建模）中未必成立。因此论文探索的是不依赖注意力矩阵任何先验、也能降低自注意力内存负担的方法。

作者观察到，如果我们能隔着 softmax 完成 K×V 的矩阵乘法（softmax(Q × K) × V），就不必计算 n×n 的 Q×K 矩阵——它正是内存瓶颈。他们用随机特征映射（即随机投影）把 softmax 近似为：

softmax(Q * K) ∼ Q' * K' = φ(Q) * φ(K)

其中 φ 是一个合适的非线性函数。于是：

Attention(Q, K, V) ∼ φ(Q) * (φ(K) * V)

借鉴 2000 年代初的机器学习论文，作者提出了 **FAVOR+**（**F**ast **A**ttention **V**ia **O**rthogonal **R**andom positive (**+**) **F**eatures，正交随机正特征快速注意力），一个能给出无偏或近似无偏自注意力矩阵估计的流程，具有一致收敛性和低估计方差。

#### 主要发现

- FAVOR+ 能高精度近似自注意力矩阵，且不需要对注意力矩阵形态做任何先验假设，因此可以作为标准自注意力的即插即用替代，并在多种应用和模态中取得出色表现。
- 关于 softmax 该怎么近似、不该怎么近似的大量数学论证，彰显了 2000 年代初发展出的有原则的方法在深度学习时代依然有价值。
- FAVOR+ 还可用于高效建模 softmax 之外的其他可核化（kernelizable）注意力机制。

#### 后续问题

- 即使注意力机制的近似很紧，小误差也会在 Transformer 各层间传播。这引出问题：用 FAVOR+ 近似自注意力后，对预训练网络做微调的收敛性和稳定性如何？
- FAVOR+ 算法是多个组件的组合。哪个组件对性能的经验影响最大并不清楚，考虑到本文涉及模态的多样性，更是如此。

## 读书会讨论

用于自然语言理解与生成的预训练 Transformer 语言模型发展令人瞩目，把这些系统做成高效的生产级应用已成为非常活跃的研究领域。这提醒我们：在方法论和实践两侧都还有大量东西要学、要建，才能实现高效、通用的深度学习系统，尤其是需要建模长程输入的应用。

上面四篇论文给出应对自注意力二次内存复杂度的不同办法，通常把复杂度降到线性。Linformer 和 Longformer 都基于同一观察：自注意力矩阵不含 n×n 那么多信息（注意力矩阵低秩且稀疏）。Performer 给出有原则的方法来近似 softmax 注意力核（以及 softmax 之外任何可核化的注意力机制）。Compressive Transformer 则提供了基于递归的正交思路来建模长程依赖。

这些不同的归纳偏置在计算速度、以及超出训练设定的泛化能力上各有影响。具体来说，Linformer 和 Longformer 的取舍不同：Longformer 显式设计自注意力的稀疏注意力模式（固定模式），Linformer 则学习自注意力矩阵的低秩矩阵分解。在我们的实验中，Longformer 效率不如 Linformer，且当前高度依赖实现细节。另一方面，Linformer 的分解只对（训练时固定的）固定上下文长度有效，不做特定适配就无法泛化到更长序列，而且它无法缓存之前的激活——这在生成设定中本可以非常有用。有趣的是，Performer 在概念上不同：它学习近似 softmax 注意力核，不依赖任何稀疏或低秩假设。对于不同训练数据量，这些归纳偏置如何互相对比，仍是开放问题。

这些工作共同凸显了自然语言中长程输入建模的重要性。工业界常见文档翻译、文档分类、文档摘要这类用例，都需要高效且稳健地建模超长序列。最近，零样本示例提示（GPT3 风格）也已成为标准微调的有前景的替代方案，而增加提示示例数量（也就是扩大上下文长度）能持续提升表现和稳健性。此外，在语音、蛋白质建模等其他模态中，超过标准 512 时间步的长序列很常见。

长输入建模与短输入建模并不对立，而应当从"序列从短到长"的连续谱视角来思考。[Shortformer](https://arxiv.org/abs/2012.15832)、Longformer 和 BERT 都提供证据：先在短序列上训练、再逐步增加序列长度，可以加速训练并带来更强的下游表现。这一观察与直觉一致：数据少时学到的长程依赖可能靠的是伪相关而非稳健的语言理解。这与 Teven Le Scao 在语言建模上做的一些实验呼应：在低数据区间，LSTM 比 Transformer 学得更好，在 Penn Treebank 这类小规模语言建模基准上困惑度更低。

从实践角度，位置嵌入问题同样是一个关键的方法论议题，还牵涉计算效率的取舍。相对位置嵌入（Transformer-XL 提出、Compressive Transformer 使用）很吸引人，因为可以轻易扩展到未见过的序列长度，但相对位置嵌入计算昂贵。绝对位置嵌入（Longformer、Linformer 使用）对超过训练时见过的长度则没那么灵活，但计算更高效。有趣的是，[Shortformer](https://arxiv.org/abs/2012.15832) 提出一个简单替代：不往 token 嵌入上加位置信息，而是加到自注意力的 query 和 key 上。这个方法叫 position-infused attention，实验证明既高效又出成绩。
