# 大语言模型：新的摩尔定律？

几天前，Microsoft 和 NVIDIA [发布了](https://www.microsoft.com/en-us/research/blog/using-deepspeed-and-megatron-to-train-megatron-turing-nlg-530b-the-worlds-largest-and-most-powerful-generative-language-model/) Megatron-Turing NLG 530B——一个基于 Transformer、被誉为「*全球最大、最强生成式语言模型*」的模型。

这无疑是令人印象深刻的机器学习工程展示，不容置疑。但我们该为这种巨模型风潮兴奋吗？至少我不。原因如下。

### 深度学习下的大脑长这样

研究者估计人脑平均包含 [860 亿个神经元](https://pubmed.ncbi.nlm.nih.gov/19226510/)和 100 万亿个突触。可以合理假设，其中并非全部负责语言。有趣的是，据[预计](https://www.wired.com/story/cerebras-chip-cluster-neural-networks-ai/)，GPT-4 大约有 100 万亿个参数……尽管这个类比很粗糙，我们难道不该想想：建一个和人脑一样大的语言模型，是否是长期最佳路线？

当然，我们的大脑是几百万年进化的杰作，而深度学习模型只有几十年的历史。即便如此，直觉也应该提醒我们：有什么地方不对劲（一语双关：compute）。

### 深度学习，深不见底的钱包？

可以想象，在海量文本数据集上训练一个 5300 亿参数的模型需要相当规模的基建。事实上，Microsoft 和 NVIDIA 用了几百台 DGX A100 多 GPU 服务器。每台 19.9 万美元，再加上网络设备、托管成本等，任何想复现这个实验的人都得花将近 1 亿美元。薯条要加吗？

说正经的，哪些组织的业务用例撑得起在深度学习基建上花 1 亿美元？哪怕 1000 万？极少。那这些模型到底是给谁的？

### 那股暖流来自你的 GPU 集群

尽管工程上无可挑剔，用 GPU 训练深度学习模型仍是暴力法。按参数表，每台 DGX 服务器功耗可达 6.5 千瓦。当然，你的数据中心（或机柜）还得配上至少同等规模的制冷。除非你是史塔克家、需要让临冬城在冬天暖和起来，否则这就是你必须处理的又一个问题。

此外，随着公众对气候和社会责任议题意识增强，组织需要核算碳足迹。根据马萨诸塞大学 2019 年这项[研究](https://arxiv.org/pdf/1906.02243.pdf)，「*在 GPU 上训练 BERT 大约相当于一趟横贯美国的航班*」。

BERT-Large 才 3.4 亿参数。Megatron-Turing 的足迹只能靠外推了……了解我的人不会说我是一个热心环保人士。但有些数字就是让人没法忽视。

### 所以呢？

我为 Megatron-Turing NLG 530B 和接下来要出的任何巨兽兴奋吗？不。我认为（相对微小的）基准提升值得那点额外成本、复杂度和碳足迹吗？不。我认为建造并鼓吹这些巨型模型，有助于组织理解和采用机器学习吗？不。

我剩下的只有疑问：这一切意义何在。为科学而科学？老一套营销？技术霸权？可能每样都有一点。那就随他们去吧。

不如让我聚焦于务实、可落地的技术，让你们都能用它构建高质量的机器学习方案。

### 使用预训练模型

绝大多数情况下，你不需要自定义模型架构。也许你*想要*一个自定义的（那是另一回事），但那里有龙。仅限专家！

一个好的起点是去找为你要解决的任务预训练过的[模型](https://huggingface.co/models)（比如[英语文本摘要](https://huggingface.co/models?language=en&pipeline_tag=summarization&sort=downloads)）。

然后，快速拿几个模型预测你自己的数据。如果指标显示某个够用了，你就完事了！如果还需要多一点准确率，可以考虑微调模型（马上讲）。

### 使用更小的模型

评估模型时，应选能满足你精度需求的最小模型。它预测更快，训练和推理所需要的硬件资源也更少。节俭的意义深远。

这也不是新鲜事。计算机视觉从业者应该记得 2017 年 [SqueezeNet](https://arxiv.org/abs/1602.07360) 出世——模型体积比 [AlexNet](https://papers.nips.cc/paper/2012/hash/c399862d3b9d6b76c8436e924a68c45b-Abstract.html) 缩小 50 倍，准确率持平甚至更高。多么巧妙！

自然语言处理社区的缩容工作也在推进，借助[知识蒸馏](https://en.wikipedia.org/wiki/Knowledge_distillation)等迁移学习技术。[DistilBERT](https://arxiv.org/abs/1910.01108) 大概是最知名的成果：相比原版 BERT，它保留了 97% 的语言理解能力，却小 40%、快 60%。可以在[这里](https://huggingface.co/distilbert-base-uncased)试试。同样的思路也用于 Facebook 的 [BART](https://arxiv.org/abs/1910.13461) 等其他模型，DistilBART 可以在[这里](https://huggingface.co/models?search=distilbart)试用。

[Big Science](https://bigscience.huggingface.co/) 项目的近期模型同样非常出色。如[研究论文](https://arxiv.org/abs/2110.08207)中这张图所示，他们的 T0 模型比 GPT-3 小 16 倍，却在许多任务上胜出。

你可以在[这里](https://huggingface.co/bigscience/T0pp)试用 T0。这才是我们需要的研究类型！

### 微调模型

如果你需要专门化一个模型，几乎没有理由从零训练。你该做的是微调——只在你自己的数据上训练几个 epoch。如果数据不够，也许这些[数据集](https://huggingface.co/datasets)中的一个可以让你起步。

你猜对了，这也是迁移学习的一种玩法，而且在所有方面都帮你省钱：

- 更少数据要收集、存储、清洗和标注，
- 实验和迭代更快，
- 生产所需资源更少。

换句话说：省时间、省钱、省硬件、拯救世界！

如果你需要教程，Hugging Face [课程](https://huggingface.co/course)会让你迅速入门。

### 使用云端基础设施

不管你喜欢与否，云厂商知道怎么构建高效基础设施。可持续性研究表明，云基础设施比自建方案更节能、更低碳：见 [AWS](https://sustainability.aboutamazon.com/environment/the-cloud)、[Azure](https://azure.microsoft.com/en-us/global-infrastructure/sustainability) 和 [Google](https://cloud.google.com/sustainability)。Earth.org [说](https://earth.org/environmental-impact-of-cloud-computing/)，虽然云基础设施并不完美，「[*它*]比自建方案更能效，并且促进对环境有益的服务与经济增长。」

云在易用性、灵活性和按量付费方面确实优势明显。它也比你以为的更绿一点。如果你的 GPU 不够用，为什么不在 AWS 的机器学习托管服务 [Amazon SageMaker](https://aws.amazon.com/sagemaker/) 上微调你的 Hugging Face 模型？我们为你准备了[大量示例](https://huggingface.co/docs/sagemaker/train)。

### 优化你的模型

从编译器到虚拟机，软件工程师早就在用工具自动优化代码以适配任何运行硬件。

但机器学习社区在这个话题上仍在挣扎，这有其道理：为体积和速度优化模型是出了名的复杂，涉及的技术有：

- 加速训练（[Graphcore](https://www.graphcore.ai/)、[Habana](https://habana.ai/)）和推理（[Google TPU](https://cloud.google.com/tpu)、[AWS Inferentia](https://aws.amazon.com/machine-learning/inferentia/)）的专用硬件。
- 剪枝：移除对预测结果影响很小或没有影响的模型参数。
- 融合：合并模型层（比如卷积与激活）。
- 量化：以更小的值存储模型参数（比如 8 位代替 32 位）

所幸，自动化工具开始出现，比如开源库 [Optimum](https://huggingface.co/hardware)，以及能以 1 毫秒延迟交付 Transformers 精度的容器化方案 [Infinity](https://huggingface.co/infinity)。

### 结论

过去几年，大语言模型的规模每年增长 10 倍。这开始像另一条[摩尔定律](https://en.wikipedia.org/wiki/Moore%27s_law)了。

我们以前经历过，我们本该知道这条路通向收益递减、成本更高、复杂度上升和新风险。指数级的事往往不得善终。还记得 [Meltdown 和 Spectre](https://meltdownattack.com/) 吗？我们想去看看那在 AI 里长什么样吗？

与其追逐万亿参数模型（下注从速），不如一起构建务实用的、高效的、所有开发者都能拿来解决真实世界问题的方案，是不是对大家都更好？
