# LAVE：使用 LLM 对 Docmatix 进行零样本 VQA 评估——我们还需要微调吗？

本文由 Dana Aubakirova（danaaubakirova）与 Andres Marafioti（andito）撰写。

在开发 Docmatix 时，我们发现经其微调的 Florence-2 在 DocVQA 任务上表现出色，但在基准测试中得分仍然较低。为了提高性能，我们必须在 DocVQA 数据集上进一步微调模型，以学习该基准测试所要求的语法风格。有意思的是，人类评估者认为额外微调后的表现似乎反而更差，因此我们主要把额外微调的模型用于消融实验，而公开发布的只是在 Docmatix 上训练的模型，供更广泛的使用。

尽管模型生成的答案在语义上与参考答案一致（如图 1 所示），但得分却较低。这就引出了一个问题：我们应该微调模型以改进这些指标，还是应该开发与人类感知更相符的新指标？

*图 1：Docmatix 数据集零样本生成答案与参考答案的 t-SNE 可视化*

## 背景

社区最近很关注分布外（out-of-distribution，OOD）评估，即利用零样本迁移到未见过的 VQA 任务，或在一个 VQA 数据集上微调、在另一个数据集上评估等方法。随着用于微调视觉语言模型（VLM）的合成数据集（如 Docmatix、SciGraphQA、SimVQA）日渐兴起，这一转变愈发重要。

一直以来，VQA Accuracy（VQA 准确度）都是评估模型性能的主要指标。它依赖模型预测答案与人工标注的一组参考答案之间的精确字符串匹配。这一指标之所以有效，是因为 VQA 评估遵循独立同分布（IID）范式，训练数据与测试数据分布相似，模型能够有效地适配 [详见此处](https://arxiv.org/pdf/2205.12191)。

但在 OOD 场景下，由于格式、具体程度或解读方式的差异，生成的答案即使正确也可能与参考答案不匹配。图 1 完美地展示了这种情况——我们将零样本生成的描述与合成数据集的参考描述进行了比较。指令生成的数据集与人工策展数据集之间尤其如此。一些[方法](https://proceedings.mlr.press/v202/li23q.html)曾尝试让答案格式与参考答案对齐，但这只是治标不治本，没有解决评估指标有缺陷的根本原因。人工评估虽然可靠，但成本高且不可扩展，这凸显了对与人类判断更相符的指标的需求。

## 方法

[Docmatix](https://huggingface.co/blog/docmatix) 是最大的合成 DocVQA 数据集，基于精选文档数据集 [PDFA](https://huggingface.co/datasets/pixparse/pdfa-eng-wds) 生成，比之前可用的数据集大 100 倍。其人工策展的对应数据集是 DocVQA，被用作文档理解 VQA 模型的评估基准。本文中，我们将使用 **Docmatix 的一个子集**，包含约 200 个测试样本，可在此下载 [Docmatix-zero-shot-exp](https://huggingface.co/datasets/HuggingFaceM4/Docmatix/viewer/zero-shot-exp)。

*图 2：来自 Docmatix 和 DocVQA 测试集的问答对示例。注：此处未显示相应的图像。*

尽管 Docmatix 和 DocVQA 中问答对的内容相似，但两者的风格差异显著。在此情境下，CIDER、ANLS、BLEU 等传统指标对零样本评估可能过于严格。鉴于在 t-SNE 中观察到的嵌入相似性（图 1），我们决定使用不同的评估指标。本文采用 LAVE（LLM-Assisted VQA Evaluation，LLM 辅助 VQA 评估）指标，以更好地评估在这个未见但语义相似的数据集上的泛化能力。

*图 3：Docmatix 和 DocVQA 数据集中问题、答案与图像特征的 t-SNE 可视化*

*图 5：Docmatix 和 DocVQA 数据集中问题、答案与图像特征的 t-SNE 可视化*

在我们的评估中，选择 [MPLUGDocOwl1.5](https://arxiv.org/pdf/2403.12895) 作为基线模型。该模型在原始 DocVQA 数据集测试子集上取得了 84% 的 ANLS 得分。然后我们在 Docmatix 的一个子集（含 200 张图像）上运行零样本生成，并使用 [Llama-2-Chat-7b](https://huggingface.co/meta-llama/Llama-2-7b-chat-hf) 对答案进行评分。

## 关于 LAVE

我们遵循[该论文](https://arxiv.org/html/2310.02567v2)中的流程。VQA 评估被构造成一个适合用 LLM 做上下文学习的答案评分任务。我们使用 1 到 3 的评分区间，以涵盖问题含糊或答案不完整的情况。提示词包含任务描述、若干输入/输出演示样例，以及待测样本的输入。

我们组织了任务描述，并加入了指令 **"Give the rationale before rating"（评分前先给出理由）**，以便展示所给评分的依据。每个演示包含一个问题、一组参考答案、候选答案、答案评分以及评分的解释。我们还加入了 **"Provide only one rating"（只给出一个评分）**，以避免逐句分析——那有时会得出多个评分。

```
task_description = """You are given a question, a set of gold-standard reference answers written by
experts, and a candidate answer. Please rate the accuracy of the candidate answer for the question
considering the reference answers. Use a scale of 1-3, with 1 indicating an incorrect or irrelevant
answer, 2 indicating an ambiguous or incomplete answer, and 3 indicating a correct answer.
Give the rationale before rating. Provide only one rating.
THIS IS VERY IMPORTANT:
A binary question should only be answered with 'yes' or 'no',
otherwise the candidate answer is incorrect."""

demonstrations = [
    {
        "question": "What's the weather like?",
        "reference_answer": ["sunny", "clear", "bright", "sunny", "sunny"],
        "generated_answer": "cloudy"
    }
]
```

#### 评分函数

给定 LLM 为测试样本生成的文本，我们从最后一个字符（1、2 或 3）中提取评分，并将其映射到 [0, 1] 范围内的分数：[ s = \frac{r - 1}{2} ]

## 我们对 VQA 系统的评估是否过于严格？我们还需要微调吗？

使用 LLM 评估回答后，我们的准确率提高了约 50%，这表明答案即使不遵循严格格式也可能是正确的。这说明我们当前的评估指标可能过于死板。需要指出的是，这不是一篇全面的研究论文，还需要更多消融研究来充分理解不同指标在合成数据集零样本性能评估上的有效性。我们希望这项工作能成为一个起点，拓宽当前在合成数据集背景下改进零样本视觉语言模型评估的研究方向，并探索超越提示学习的更高效方法。
