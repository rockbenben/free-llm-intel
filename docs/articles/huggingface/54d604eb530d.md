agent skills 最妙的一点，是让你的 agent 在难题上 *提升技能*。这件事有两种看法：

- 你可以用 Opus 4.5 或其他 SOTA 模型，去啃最难的那批问题。
- 你也可以用能在笔记本上跑的模型，给它们提升技能去对付更难的问题。这篇博文里，我们会展示怎么做后一种。

这篇博文会完整走一遍流程：用一个新工具 `upskill`，借助大模型生成并评估 agent skills，再把它们用到更小的模型上。我们会在为 [`diffusers`](https://huggingface.co/docs/diffusers/en/index) 模型编写 CUDA 内核这个任务上对 `upskill` 做基准测试，但这一流程通常也适用于降低成本，或让更小的模型去解决高难度、特定领域的问题。

## 什么是 agent skills？

如果你还没留意到，agent skills 正在横扫 coding agent 这个圈子。其实它的概念很直白：把模型上下文定义成文件，比如指令写成 markdown、代码写成 scripts。这种文件格式让它们易于生成、分享和审阅。简言之，它们是在模型与工具之间共享能力的实用媒介，在特定领域或难题上最有用。反正不是模型本来就能做好的那类事。

本文用 Claude 生成一个 Skill 文件来展示这一流程：这个 Skill 可供开源模型完成一项复杂而专门的任务 —— 编写 CUDA 内核。我们先试了一个基于现有文档的简单 skill，发现它提升了部分模型的表现，但不是全部。事实上，对某些模型它甚至会降低表现、或增加 token 用量。看看下面这张图，对比一下模型在用了和没用这个基础 skill 时的表现。

[![plot of model performance](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/upskill-blog/plot.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/upskill-blog/plot.png)

现在，我们来走一遍：如何用 `upskill` 让你的 agent 在难题上提升技能，并衡量表现。

## 1. 让老师（Claude Opus 4.5）构建一个内核

首先，我们用 Claude Code 以交互方式构建一个内核，并导出 trace。整个过程我们靠下达指令、做验证、补文档链接一步步推进。这个略显朴素的过程很重要，它能暴露模型最初遇到的挑战。事实上，你可以反复迭代：用 skill 的草稿版本试着解决任务，再拿更小的模型做实验。每一轮，你都可以让 agent 改进 skill，并在那个更小的模型上测试。

这里是我们创建、并一直用来构建内核的一个 [skill 示例](https://huggingface.co/hf-skills/h100-diffusers-kernel-builder)。我们从这条 [agent trace](https://huggingface.co/hf-skills/h100-diffusers-kernel-builder/blob/main/agent-trace.txt) 起步 —— 在那条 trace 里，agent 能构建出内核，但少不了一些人工帮忙。

## 2. 从 trace 生成一个 agent skill

老师模型完成任务之后，我们需要让它产出一个 skill。有若干种有效的做法。

- 在同一个会话里，让 agent 为它刚完成的任务创建一个 skill 文件。
- 用 [Anthropic ‘skill creator’ skill](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)，既可以在当前 agent 会话里用，也可以配合一份导出的 trace、在一个新的 agent 会话里用。
- 用 `upskill` 工具，基于 trace 创建一个 skill。

多数情况下，前两种做法都能产出可用的 skill。但带上 skill 的 agent 表现如何，仍是未知数。这正是 `upskill` 的用武之地：它还会基于 trace 为你的 skill 生成测试用例，然后对比两种情形下的结果 —— 用 trace，或者应用 skill。下面可以看到，原始模型（Claude Opus）在用了和没用 skill 时表现相同。这意味着 *对这个模型而言*，skill 已经把这项任务固化下来了。很棒！

[![terminal evaluation](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/upskill-blog/terminal.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/upskill-blog/terminal.png)

## 3. 把你的 skill 用到开源、更小或更便宜的模型上

最后，我们需要把刚创建的 skill 迁移到打算使用的工具或模型上。像 `codex`、`cursor`、`opencode` 这类工具，大多已经对 skill 采用了一致的格式，即 `{agent}/skills/{skill_name}/SKILL.md` ，所以我们只需把 skill 目录复制到这个位置。

用 `upskill`，我们可以把一个 skill 和一组模型传给 `eval` 命令，`upskill` 就会在这些模型上分别跑带 skill 和不带 skill 的测试用例来对比表现。这里可以看到，这个 skill 提升了部分开放模型的准确率，但不是全部。

[![performance evaluation](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/upskill-blog/accuracy.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/upskill-blog/accuracy.png)

这种情况下，我们可能想通过重新生成 skill，在 `gpt-oss` 的 skills 上继续迭代。做法就是 `upskill generate --from {skill}`。

agent skills 的意义不止于模型表现。很多时候，agent 带不带 skill 都能达到某个准确率，只是要达到那个水平得消耗更多 token。对于反复出现的任务，我们希望优化 agent，让它们用更少的 token 拿到同样的准确率。下面的结果揭示了 skill 的另一个维度：有些模型显著降低了达成该表现所需的 token 用量，而另一些模型 **带上** skill 反而用掉更多 token。举例来说，对 [`moonshotai/Kimi-K2-Thinking`](https://huggingface.co/moonshotai/Kimi-K2-Thinking) 而言，这个 skill 在准确率和 token 用量上效果都很明显。但对 Claude Opus 4.5 来说，表现没有明显提升，token 用量反而增加了，所以你不会想把这个 skill 用在 Claude Opus 4.5 上。

[![token usage](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/upskill-blog/tokens.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/upskill-blog/tokens.png)

**tldr;** 拿你创建的 skills 去试用、评估模型。用 `upskill eval` 或类似工具，评估模型在带 skills 和不带 skills 时的表现。

以上就是在难题上给编码 agent 提升技能的高层端到端流程。现在就像这样试试 upskill：

```
# install upskill
pip install upskill

# or use uvx 
uvx upskill --help

# generate a skill based on an agent trace
upskill generate "write nvidia kernels" --from ./trace.md
# evaluate models on a skill
upskill eval ./skills/my-skill/ --model haiku --model sonnet

# generate skills for local models
upskill generate "parse YAML" 
    --model opus 
    --eval-model "unsloth/GLM-4.7-Flash-GGUF:Q4_0" 
    --eval-base-url http://localhost:8080/v1
```

## 用 agent skills 构建内核的深度教程

我们已经对如何给 agent 提升技能有了高层认识。现在来看看我们解决的这个用例：编写 CUDA 内核。

我们不想只写内核代码，还想弄懂完整的 kernel-builder 工作流：项目结构、`build.toml` 配置、针对特定架构的优化，以及 PyTorch 绑定。本教程展示 upskill 如何创建真正能用、经过验证的 skill。

[`kernel-builder-cuda-kernels`](https://github.com/burtenshaw/kernel-skill) 这个 skill 把 Claude 做 CUDA 开发需要知道的一切都教给它：该针对哪种 GPU 架构、如何组织一个 kernel-builder 项目、何时用 shared memory 而非 registers、以及如何编写 PyTorch 绑定。

有了这个 skill，你就能对 Claude 下这样的指令：

```
Build a fused LayerNorm + GELU kernel optimized for H100.
```

Claude 随后会生成完整的项目结构、CUDA 实现和构建配置——严格遵循 kernel-builder 期望的约定。

这不是为了生成样板代码。这个 skill 把领域专长编码了进去：H100 使用 compute capability 9.0、shared memory 要按 128 字节对齐、异步内存拷贝要求 `__CUDA_ARCH__ >= 900`。那些本来要从文档里花上几小时才能搜集齐的知识，被打包成约 500 个按需加载的 token。

## 安装与设置

安装 upskill：

```
pip install upskill
# or use uvx for one-off runs
uvx upskill --help
```

设置你的 API key：

```
export ANTHROPIC_API_KEY=sk-ant-...
export HF_TOKEN=hf_...
```

就这样。Upskill 默认用 Anthropic Claude Opus-4.5 模型，但也支持把 OpenAI 模型和通过 OpenAI 兼容 endpoint 接入的本地模型用作生成器。我们希望用更贵、质量更高的模型来生成 skills，再用更小的模型去使用它们。想想 Robin Hood 吧。

## 生成 skill

我们来走一遍：用 HuggingFace 的 [`kernels`](https://github.com/huggingface/kernels) 库，生成一个教 agent 如何构建 CUDA 内核的 skill。

### 生成 skill

先写一段清晰的任务描述：

```
upskill generate "build optimized CUDA kernels for PyTorch using HuggingFace kernel-builder"
```

上面我们用的是 upskill，但其实任何 agent 或聊天工具，加上一份导出的 trace 都可以。

```
upskill generate "write kernels" --from <agent-trace>.md
```

另外，也可以从一个已有的 skill 出发，往里补充：

```
upskill generate "add more error handling and edge cases" 
    --from ./skills/kernel-builder-cuda-kernels/
```

upskill 会加载已有的 skill、应用你的改进，并重新评估，确认这些改动确实有帮助。

upskill 创建 skill、生成测试用例、评估表现，再依据失败案例打磨：

```
Generating skill with sonnet...
Generating test cases...
Evaluating on sonnet... (attempt 1)
  60% -> 95% (+35%) OK

  kernel-builder-cuda-kernels
  Build optimized CUDA kernels for PyTorch using HuggingFace kernel-builder.

  SKILL.md              ~520 tokens

  baseline   ████████████                60%
  with skill ███████████████████    95%  (+35%)

Saved to ./skills/kernel-builder-cuda-kernels
```

基线显示模型在完全不带 skill 时的表现。"with skill" 的结果则是把 skill 注入上下文之后的表现。35% 的提升说明这个 skill 起作用了。

这个 skill 按 [Agent Skills 规范](https://agentskills.io) 保存为一个目录：

```
./skills/kernel-builder-cuda-kernels/
├── SKILL.md           # Main instructions (~520 tokens)
└── skill_meta.json    # Metadata and test cases
```

打开 `SKILL.md`，看看 upskill 生成了什么：

```
---
name: kernel-builder-cuda-kernels
description: Build optimized CUDA kernels for PyTorch using HuggingFace kernel-builder.
---

# Building CUDA Kernels with kernel-builder

## Overview

This guide explains how to create optimized CUDA kernels for PyTorch models 
using HuggingFace's kernel-builder. It covers project setup, kernel implementation, 
and building for specific GPU architectures like NVIDIA H100.

## Project Structure

project/
├── build.toml              # Build configuration
├── kernel_src/             # CUDA kernel implementations
│   ├── attention.cu
│   ├── layernorm.cu
│   └── geglu.cu
└── torch-ext/              # PyTorch C++ bindings
    └── torch_binding.cpp

## Build Configuration

Create `build.toml` to define your kernel package:

[general]
name = "diffuser_kernels"
backends = ["cuda"]

[general.cuda]
# H100 is compute capability 9.0
capabilities = ["9.0"]

...
```

## upskill 里的评估是怎么运作的

upskill 用老师-学生的方式来评估模型：由老师模型生成测试用例，让学生模型在这些用例上接受评估。

- **老师模型**（Opus）生成 skill
- **测试用例**（Opus）根据任务描述自动生成
- **学生模型**（本地）在带 skill 和不带 skill 两种情况下接受评估
- **Skill lift** 衡量提升幅度

如果把已有的 skill 传给 `upskill eval`，它会为这个 skill 生成测试用例，并在这些用例上评估模型。测试用例就是简单的输入/输出对，用来验证 agent 是否理解了任务：

```
{
  "cases": [
    {
      "input": "Create a build.toml for a CUDA kernel targeting H100",
      "expected": {"contains": "9.0"}
    },
    {
      "input": "Write a basic CUDA kernel template with proper includes",
      "expected": {"contains": "cuda_runtime.h"}
    }
  ]
}
```

我们还可以测试一个 skill 在不同模型上的表现：

```
upskill eval ./skills/kernel-builder-cuda-kernels/ 
    --model haiku --m kimi --runs 5
```

## 下一步

我们已经证明，upskill 能创建经过验证的 skill，把领域专长从强大的模型迁移到更便宜的模型上。kernel-builder skill 只是可能做到的事情中的一个例子。

可以试试这些：

- **为你内部的工具生成 skills**
- **为你的代码库建一个 skill 库**
- **沉淀团队里的隐性知识**
- **跨模型做基准测试**

这套方法适用于任何专门任务 —— 那些你本来得反复写详细 prompt 的任务。skills 可以在 [Claude Code](https://docs.anthropic.com/en/docs/claude-code)、[Codex](https://github.com/openai/codex)、[Cursor](https://cursor.com/docs/context/skills) 以及其他支持 [Agent Skills 规范](https://agentskills.io) 的工具之间移植。

2 月 4 日

`Upskill generate` 大体上按预期工作，但当我试着做真正有意思的那一步、跑 `upskill eval` 时，一切就开始崩了。

我踩到的几个具体问题（Windows + Ubuntu/WSL）：

**Skill 路径混乱：**

- Ubuntu：Access denied … 即使文件确实存在，也说 SKILL.md 不在允许的 skill 目录内。
- Windows：Path must be absolute… 然后 fast-agent 又试图从 /tmp/.../SKILL.md 里 read_skill (!)，这在 Linux 上算「absolute」，在 Windows 上却不算。
- 我最后把 /skills、/tmp/skills、.fast-agent/skills、.claude/skills、绝对路径挨个试了个遍……没有哪个能在多次运行里始终被接受。

**模型选择混乱 / fast-agent 标志冲突**

- -m 在 fast-agent 里是别的意思，所以除非用对标志，否则工具评估的是错的东西。很容易以为自己跑的是 Haiku/Sonnet，其实并不是。
- `-m haiku` 居然让程序真的写了一首俳句 😭😭

**提供方 / 模型参数不匹配**

- OpenAI GPT-5 模型会报错，因为请求用的是 max_tokens 而非 max_completion_tokens（直接 400）。

[![Screenshot 2026-02-04 125447](https://cdn-uploads.huggingface.co/production/uploads/69833b37a33f96b73185a290/tinDi6C4KBeM3pg3naTko.png)](https://cdn-uploads.huggingface.co/production/uploads/69833b37a33f96b73185a290/tinDi6C4KBeM3pg3naTko.png)

**诡异的 UI / 日志行为**

- 终端输出刷屏似地重复「Chatting … turn 1」这样的行，然后即便运行日志都在，也始终不打印结果表格。

[![Screenshot 2026-02-04 131229](https://cdn-uploads.huggingface.co/production/uploads/69833b37a33f96b73185a290/Aoa-GDqQLxTrJfwUoRCrg.png)](https://cdn-uploads.huggingface.co/production/uploads/69833b37a33f96b73185a290/Aoa-GDqQLxTrJfwUoRCrg.png)

- 可能迅速爆掉（我见过输出量猛增）
