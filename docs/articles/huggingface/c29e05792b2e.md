# 介绍 swift-huggingface：Hugging Face 的完整 Swift 客户端

作者：Mattt（mattt）

今天我们发布 [swift-huggingface](https://github.com/huggingface/swift-huggingface)——一个新的 Swift 包，为 Hugging Face Hub 提供完整的客户端。

你现在就可以把它作为独立包使用；它很快会集成进 swift-transformers，取代后者现有的 `HubApi` 实现。

## 问题

今年早些时候 [swift-transformers 1.0](https://huggingface.co/blog/swift-transformers) 发布后，社区的呼声非常响亮：

- **下载又慢又不稳。** 大模型文件（动辄几 GB）下到一半就失败，还没法续传。开发者只好手动下载模型再打包进 App——这完全违背了动态加载模型的初衷。
- **与 Python 生态没有共享缓存。** Python 的 `transformers` 库把模型存放在 `~/.cache/huggingface/hub`。Swift 应用却下载到另一个位置、用另一种结构。如果你已经用 Python CLI 下载过某个模型，Swift 应用还会再下载一遍。
- **认证让人困惑。** token 应该从哪来？环境变量？文件？钥匙串？答案是"看情况"，而现有实现没有把各种选项讲清楚。

## 介绍 swift-huggingface

swift-huggingface 是从零重写的，聚焦可靠性和开发者体验。它提供：

- **完整的 Hub API 覆盖** —— 模型、数据集、Spaces、合集、讨论等等
- **健壮的文件操作** —— 进度跟踪、断点续传、完善的错误处理
- **与 Python 兼容的缓存** —— Swift 和 Python 客户端共享下载的模型
- **灵活的认证** —— `TokenProvider` 模式，让凭据来源一目了然
- **OAuth 支持** —— 面向用户、需要登录用户账号的应用获得一等支持
- **Xet 存储后端支持** *（即将推出！）* —— 基于分块的去重，下载显著提速

来看几个例子。

## 用 TokenProvider 做灵活认证

最大的改进之一是认证方式。`TokenProvider` 模式把凭据来源摆在明面上：

```
import HuggingFace

// For development: auto-detect from environment and standard locations
// Checks HF_TOKEN, HUGGING_FACE_HUB_TOKEN, ~/.cache/huggingface/token, etc.
let client = HubClient.default

// For CI/CD: explicit token
let client = HubClient(tokenProvider: .static("hf_xxx"))

// For production apps: read from Keychain
let client = HubClient(tokenProvider: .keychain(service: "com.myapp", account: "hf_token"))
```

自动探测遵循与 Python `huggingface_hub` 库相同的约定：

- `HF_TOKEN` 环境变量
- `HUGGING_FACE_HUB_TOKEN` 环境变量
- `HF_TOKEN_PATH` 环境变量（token 文件路径）
- `$HF_HOME/token` 文件
- `~/.cache/huggingface/token`（HF CLI 的标准位置）
- `~/.huggingface/token`（兜底位置）

也就是说，如果你已经用 `hf auth login` 登录过，swift-huggingface 会自动找到并使用那个 token。

## 面向用户应用的 OAuth

要做让用户用 Hugging Face 账号登录的应用？swift-huggingface 内置了完整的 OAuth 2.0 实现：

```
import HuggingFace

// Create authentication manager
let authManager = try HuggingFaceAuthenticationManager(
    clientID: "your_client_id",
    redirectURL: URL(string: "yourapp://oauth/callback")!,
    scope: [.openid, .profile, .email],
    keychainService: "com.yourapp.huggingface",
    keychainAccount: "user_token"
)

// Sign in user (presents system browser)
try await authManager.signIn()

// Use with Hub client
let client = HubClient(tokenProvider: .oauth(manager: authManager))

// Tokens are automatically refreshed when needed
let userInfo = try await client.whoami()
print("Signed in as: \(userInfo.name)")
```

OAuth 管理器负责 token 的钥匙串存储、自动刷新和安全登出。再也不用手动管 token 了。

## 可靠的下载

下载大模型如今简单直白：进度跟踪和断点续传都是标配。

```
// Download with progress tracking
let progress = Progress(totalUnitCount: 0)

Task {
    for await _ in progress.publisher(for: \.fractionCompleted).values {
        print("Download: \(Int(progress.fractionCompleted * 100))%")
    }
}

let fileURL = try await client.downloadFile(
    at: "model.safetensors",
    from: "microsoft/phi-2",
    to: destinationURL,
    progress: progress
)
```

下载中断了，可以续传：

```
// Resume from where you left off
let fileURL = try await client.resumeDownloadFile(
    resumeData: savedResumeData,
    to: destinationURL,
    progress: progress
)
```

要下载整个模型仓库，`downloadSnapshot` 全都包办：

```
let modelDir = try await client.downloadSnapshot(
    of: "mlx-community/Llama-3.2-1B-Instruct-4bit",
    to: cacheDirectory,
    matching: ["*.safetensors", "*.json"],  // Only download what you need
    progressHandler: { progress in
        print("Downloaded \(progress.completedUnitCount) of \(progress.totalUnitCount) files")
    }
)
```

snapshot 函数会为每个文件记录元数据，后续调用只下载发生变化的文件。

## 与 Python 共享缓存

还记得前面说的第二个问题吗？"与 Python 生态没有共享缓存。"现在解决了。

swift-huggingface 实现了与 Python 兼容的缓存结构，Swift 和 Python 客户端可以无缝共享：

```
~/.cache/huggingface/hub/
├── models--deepseek-ai--DeepSeek-V3.2/
│   ├── blobs/
│   │   └── <etag>           # actual file content
│   ├── refs/
│   │   └── main             # contains commit hash
│   └── snapshots/
│       └── <commit_hash>/
│           └── config.json  # symlink → ../../blobs/<etag>
```

这意味着：

- **一次下载，处处使用。** 如果模型已经用 `hf` CLI 或 Python 库下载过，swift-huggingface 会自动找到它。
- **内容寻址存储。** 文件按 ETag 存放在 `blobs/` 目录。两个修订版共用同一文件时，只存一份。
- **用符号链接提效。** snapshot 目录里是到 blobs 的符号链接，磁盘占用最小、文件结构清爽。

缓存位置同样遵循 Python 的环境变量约定：

- `HF_HUB_CACHE` 环境变量
- `HF_HOME` 环境变量 + `/hub`
- `~/.cache/huggingface/hub`（默认）

你也可以直接使用缓存：

```
let cache = HubCache.default

// Check if a file is already cached
if let cachedPath = cache.cachedFilePath(
    repo: "deepseek-ai/DeepSeek-V3.2",
    kind: .model,
    revision: "main",
    filename: "config.json"
) {
    let data = try Data(contentsOf: cachedPath)
    // Use cached file without any network request
}
```

为避免多个进程访问同一缓存时的竞态，swift-huggingface 使用文件锁（[`flock(2)`](https://man7.org/linux/man-pages/man2/flock.2.html)）。

## 前后对比

这是用旧的 `HubApi` 下载模型快照的样子：

```
// Before: HubApi in swift-transformers
let hub = HubApi()
let repo = Hub.Repo(id: "mlx-community/Llama-3.2-1B-Instruct-4bit")

// No progress tracking, no resume, errors swallowed
let modelDir = try await hub.snapshot(
    from: repo,
    matching: ["*.safetensors", "*.json"]
) { progress in
    // Progress object exists but wasn't always accurate
    print(progress.fractionCompleted)
}
```

这是用 swift-huggingface 做同样操作：

```
// After: swift-huggingface
let client = HubClient.default

let modelDir = try await client.downloadSnapshot(
    of: "mlx-community/Llama-3.2-1B-Instruct-4bit",
    to: cacheDirectory,
    matching: ["*.safetensors", "*.json"],
    progressHandler: { progress in
        // Accurate progress per file
        print("\(progress.completedUnitCount)/\(progress.totalUnitCount) files")
    }
)
```

API 相似，但实现完全不同——基于 `URLSession` 下载任务，配合规范的 delegate 处理、续传数据支持和元数据跟踪。

## 不止下载

等等，还有更多！swift-huggingface 是一个完整的 Hub 客户端：

```
// List trending models
let models = try await client.listModels(
    filter: "library:mlx",
    sort: "trending",
    limit: 10
)

// Get model details
let model = try await client.getModel("mlx-community/Llama-3.2-1B-Instruct-4bit")
print("Downloads: \(model.downloads ?? 0)")
print("Likes: \(model.likes ?? 0)")

// Work with collections
let collections = try await client.listCollections(owner: "huggingface", sort: "trending")

// Manage discussions
let discussions = try await client.listDiscussions(kind: .model, "username/my-model")
```

还不止这些！swift-huggingface 包含了与 [Hugging Face Inference Providers](https://huggingface.co/docs/inference-providers/index) 交互所需的一切，让你的 App 即刻获得数百个机器学习模型的访问能力，背后由一流的推理提供商支撑：

```
import HuggingFace

// Create a client (uses auto-detected credentials from environment)
let client = InferenceClient.default

// Generate images from a text prompt
let response = try await client.textToImage(
    model: "black-forest-labs/FLUX.1-schnell",
    prompt: "A serene Japanese garden with cherry blossoms",
    provider: .hfInference,
    width: 1024,
    height: 1024,
    numImages: 1,
    guidanceScale: 7.5,
    numInferenceSteps: 50,
    seed: 42
)

// Save the generated image
try response.image.write(to: URL(fileURLWithPath: "generated.png"))
```

支持的完整功能清单请看 [README](https://github.com/huggingface/swift-huggingface)。

## 接下来

我们在两条线上并行推进：

**与 swift-transformers 集成。** 我们有一个[进行中的 PR](https://github.com/huggingface/swift-transformers/pull/297)，用 swift-huggingface 替换 `HubApi`。这会给所有使用 swift-transformers、[mlx-swift-lm](https://github.com/ml-explore/mlx-swift-lm) 及更广生态的用户带来可靠下载。如果你维护某个 Swift 库或应用、想获得接入 swift-huggingface 的帮助，请联系我们——我们乐意效劳。

**用 Xet 加速下载。** 我们正在加入对 [Xet 存储后端](https://huggingface.co/docs/hub/storage-backends)的支持，它基于分块去重，能显著提升大模型的下载速度。更多内容近期奉上。
