# 如何用 OpenAI 隐私过滤器构建可扩展的 Web 应用

OpenAI 本周在 Hub 上发布了 Privacy Filter：一个开源的个人身份信息（PII）检测器，在 128k 上下文上单次前向即可按八个类别标注文本。[模型卡](https://huggingface.co/openai/privacy-filter)。我们花了几小时用它做开发，最终落地成三个应用，每个各展示它能做什么的一个切面。

- [**Document Privacy Explorer**](https://huggingface.co/spaces/ysharma/OPF-Document-PII-Explorer)：拖入 PDF 或 DOCX，回读文档时每个 PII 片段就地高亮。
- [**Image Anonymizer**](https://huggingface.co/spaces/ysharma/OPF-Image-Anonymizer)：上传一张图片，拿回时被黑条遮盖了姓名、邮箱、账号号码的版本。图片还可以在画布上编辑，下载前自行补充标注。
- [**SmartRedact Paste**](https://huggingface.co/spaces/ysharma/OPF-SmartRedact-Paste)：粘贴敏感文本，得到一个分发脱敏版本的公开 URL，同时自己保留一个可查看原文的私有链接。

三个应用都构建在 [gradio.Server](https://huggingface.co/blog/introducing-gradio-server) 之上——它允许你把自定义 HTML/JS 前端与 Gradio 的排队、ZeroGPU 分配和 `gradio_client` SDK 配对。在这些应用中，**`gradio.Server`** 承担的角色完全相同，而这种一致性正是它强大的地方。

## 模型

Privacy Filter 是一个 1.5B 参数、50M 活跃参数的模型，以宽松的 Apache 2.0 许可发布。PII 类别为 `private_person`、`private_address`、`private_email`、`private_phone`、`private_url`、`private_date`、`account_number`、`secret`。上下文 128,000 token。在 [PII-Masking-300k 基准](https://huggingface.co/datasets/ai4privacy/pii-masking-300k)上达到最先进表现。完整数字和方法见[官方发布博客](https://openai.com/index/introducing-openai-privacy-filter/)。

## 1. Document Privacy Explorer

体验地址：[ysharma/OPF-Document-PII-Explorer](https://huggingface.co/spaces/ysharma/OPF-Document-PII-Explorer)。

**用户问题。** 你想阅读一份 PII 密集的文档（合同、简历、导出的聊天记录），每个检出的片段按类别高亮，侧边栏有筛选器，顶部有汇总面板。阅读体验应当像普通文档，而不是表单。

**Privacy Filter 在这里的作用。** 整个文件在一次 128k 上下文的前向中处理完，所以没有分块、没有拼接，片段的偏移量与渲染文本直接对齐。BIOES 解码让长歧义串中的片段边界也很干净。

**`gr.Server` 在这里的作用。** 用 Blocks + `gr.HighlightedText` 加侧边栏也能把它搭出来，而且能跑。但我们想要的阅读体验（衬线正文、类别筛选在前端切换 CSS class 而不是重跑模型、不触发整页重渲染的汇总面板）手写比拼组件更容易。`gr.Server` 让我们把阅读视图作为单个 HTML 文件发布，同时只暴露一个带排队的模型端点：

```
import gradio as gr
from fastapi.responses import HTMLResponse
from gradio.data_classes import FileData

server = gr.Server()

@server.get("/", response_class=HTMLResponse)
async def homepage():
    return FRONTEND_HTML                           # reader view; see app.py

@server.api(name="analyze_document")
def analyze_document(file: FileData) -> dict:
    text = extract_text(file["path"])              # PyMuPDF / python-docx
    source_text, spans = run_privacy_filter(text)  # single 128k pass
    return {
        "text":  source_text,
        "spans": spans,                            # [{start, end, label}, ...]
        "stats": compute_stats(source_text, spans),
    }
```

注意装饰器：`@server.api(name="analyze_document")`，而不是普通的 `@server.post`。这一步把 handler 接进 Gradio 的队列，于是并发上传会被序列化，`@spaces.GPU` 在 ZeroGPU 上能正确组合，同一个端点浏览器和 `gradio_client` 都能访问，无需重复代码。浏览器用 Gradio JS 客户端调用它：

```
<script type="module">
import { Client, handle_file } from "https://cdn.jsdelivr.net/npm/@gradio/client/dist/index.min.js";
const client = await Client.connect(window.location.origin);

async function uploadFile(file) {
  const result = await client.predict("/analyze_document", { file: handle_file(file) });
  renderResults(result.data[0]);                   // { text, spans, stats }
}
</script>
```

## 2. Image Anonymizer

体验地址：[ysharma/OPF-Image-Anonymizer](https://huggingface.co/spaces/ysharma/OPF-Image-Anonymizer)。

**用户问题。** 你想分享一张图片或任意截图（Slack 消息串、收据、Stripe 后台），并给 PII 打上黑条。你想能开关黑条、拖动重新定位，或为模型漏掉的内容手画一个，然后导出结果。

**Privacy Filter 在这里的作用。** Tesseract 先做 OCR，返回逐词的边界框。后端据此重建完整文本并维护字符偏移—框的映射，然后对整个文本跑一次 Privacy Filter。检出的字符片段回查词映射，按行合并成像素矩形。

**`gr.Server` 在这里的作用。** `gr.ImageEditor` 支持分层标注，是图像脱敏的合理起点。但我们想要的工作流（每个黑条带类别元数据、同类别黑条一键全部开关、以原始分辨率在前端导出 PNG 而不绕服务器一圈）在自定义 `<canvas>` 前端上构建更干净。`gr.Server` 从一个带排队的端点返回像素矩形，其余一切交给 canvas：

```
@server.api(name="anonymize_screenshot")
def anonymize_screenshot(image: FileData) -> dict:
    img = Image.open(image["path"]).convert("RGB")
    full_text, char_to_box = ocr_image(img)        # per-word boxes + char map
    spans = run_privacy_filter(full_text)
    boxes = spans_to_pixel_boxes(spans, char_to_box)
    return {
        "image_data_url": pil_to_base64(img),
        "width":  img.width,
        "height": img.height,
        "boxes":  boxes,                           # [{x, y, w, h, label, text}, ...]
    }
```

前端用 `client.predict("/anonymize_screenshot", { image: handle_file(file) })` 调用它，模式与上面相同。开关、拖动、画新黑条、导出 PNG 全在浏览器完成；编辑从不绕回服务器。

## 3. SmartRedact Paste

体验地址：[ysharma/OPF-SmartRedact-Paste](https://huggingface.co/spaces/ysharma/OPF-SmartRedact-Paste)。

**用户问题。** 你想要一个"分享前先脱敏"的 pastebin。粘贴一行日志、一封邮件、一张工单，拿回两个 URL：公开的那个分发带 `<PRIVATE_PERSON>`、`<PRIVATE_EMAIL>`、`<ACCOUNT_NUMBER>` 占位符的脱敏版本，遵循[官方博客示例](https://openai.com/index/introducing-openai-privacy-filter/#:~:text=coherent%20masking%20boundaries.-,Example%20input%20text,-Subject%3A%20Q2%20Planning)的遮蔽约定；私有的那个由你自己保留的 token 把关，显示高亮了片段的原文。

**Privacy Filter 在这里的作用。** 在存储的粘贴内容中，把每个检出片段替换成 `<CATEGORY>` 占位符——这就是全部脱敏步骤。多语言文本（西班牙语、法语、中文、印地语以及模型卡示例中的其他语言）走同一个调用，无需改动。

**`gr.Server` 在这里的作用。** 这个应用需要对同一个粘贴 ID 提供两条不同的 GET 路由，一条公开、一条 token 门控；URL 形态很关键，因为 reveal 链接是你要留存的凭证。`gr.Server` 底层就是 FastAPI 应用，所以适合这里——这也是 `@server.api` 和普通 `@server.get` 能在同一进程里并排共存的原因。注：这个应用也可以用 `gr.Blocks()` 配合[挂载自定义 FastAPI 路由](https://www.gradio.app/docs/gradio/mount_gradio_app)来构建：

```
# Model call → queued endpoint. Hit from the browser via
# client.predict("/create_paste", { text, ttl }).
@server.api(name="create_paste")
def create_paste(text: str, ttl: str = "never") -> dict:
    source_text, spans = run_privacy_filter(text)
    redacted = redact(source_text, spans)          # <CATEGORY> placeholders
    pid, reveal_token = secrets.token_urlsafe(6), secrets.token_urlsafe(22)
    PASTES[pid] = Paste(pid, reveal_token, source_text, redacted, spans,
                        expires_at=_ttl(ttl))      # see app.py
    return {
        "view_path":   f"/view/{pid}",
        "reveal_path": f"/view/{pid}?token={reveal_token}",
    }

# View page → plain FastAPI GET. No model, no queue needed, and we
# actually want the bespoke URL shape `/view/{pid}?token=...` that a
# queued endpoint couldn't give us.
@server.get("/view/{pid}", response_class=HTMLResponse)
async def view_paste(pid: str, token: str | None = None):
    p = _store_get(pid)                            # see app.py for store
    if p is None:
        return HTMLResponse(_not_found(), status_code=404)
    revealed = bool(token) and secrets.compare_digest(token, p.reveal_token)
    return HTMLResponse(_render_view(p, revealed))
```

一个守护线程每 30 秒清退一次过期的粘贴。由于一切都在同一个进程里，整个服务包括存储只有大约 200 行应用代码。

## `gradio.Server` 提供什么

三个应用的分工一致——凡是碰模型的都走 `@server.api`，其余留在普通 FastAPI 路由上：

| 应用 | 排队计算（`@server.api`） | 普通 FastAPI 路由 |
| --- | --- | --- |
| Document Privacy Explorer | `analyze_document` — 抽取、检测、统计 | `GET /` 提供自定义阅读视图 |
| Image Anonymizer | `anonymize_screenshot` — OCR、检测、片段 → 像素框 | `GET /` + `GET /examples/*` 提供 canvas UI 和预置示例 |
| SmartRedact Paste | `create_paste` — 检测、脱敏、签发 ID | `GET /` 编写页、`GET /view/{pid}?token=...` 公开与 token 门控视图、`GET /api/paste/{pid}` JSON 查询 |

`@server.api` 给你 Gradio 的队列（请求序列化、ZeroGPU 上正确的 `@spaces.GPU` 组合、进度事件），浏览器通过 [`@gradio/client`](https://www.gradio.app/guides/getting-started-with-the-js-client) 访问它；同一个端点也是 Python 里 `gradio_client` 用户访问的——一个函数、两个 SDK、零重复代码。普通的 `@server.get`/`@server.post` 留给静态面：HTML 页面、文件查询、廉价的字典读取。这条经验法则来自 [gradio.Server 介绍帖](https://huggingface.co/blog/introducing-gradio-server)，也是这三个 UI 迥异的应用手感一致的原因。
