TLDR；Inkling 2 Mini 是一款新的 looped transformer 模型。这是一个多模态 Mixture-of-Experts，*物理*总参数约 26B，每 token 激活 3B 参数。它用一个巧妙的办法提升容量：某些层会被循环访问三次，使它表现得像拥有更多参数。它支持 1M token 的上下文长度，可接受图像和文本输入。Thinking Machines Lab 以混合精度格式发布该模型，专家权重采用 NVFP4 和 MXFP8。此外还附带一个 DSpark drafter，用少量内存开销换取额外加速。

Inkling 2 Mini 比 Inkling 2 Small 小得多得多，是为本地部署而设计的。我们觉得这是一款让人耳目一新的优秀本地模型。在我们的 vibe 测试中，它至少与 Qwen 3.8 27B 相当。还需要更多验证，不过我们对这次发布非常兴奋！

我们提供 transformers、Llama App（llama.cpp）和 MLX 支持。SGLang 也为数据中心硬件上的生产部署提供 Day 0 推理支持。

本文介绍 Inkling Mini 的不同之处、我们的一些 vibe 测试，以及如何在你的环境里使用它。

## Inkling 2 Mini 有哪些新特性？

Inkling 2 Mini 是一个拥有 24 个解码器层的 mixture-of-experts 模型，但中间的 12 层会在一个循环里跑三遍。因此，模型只用了 24 个*物理*层，表现却像拥有 48 个（6 + 3*12 + 6）*逻辑*层。

与 Inkling 2 Small 类似，Inkling 2 Mini 每 token 执行 48 次层访问。隐藏维度是 2,304，而不是 4,608。每次层访问时，两个变体都会把 token 路由到 8 个专家，但 Mini 是从每层的 128 个专家里选，Small 则从 384 个里选。
解码器把第 0–5 层跑一遍，第 6–17 层跑三遍，第 18–23 层跑一遍。第 6–17 层的三次遍历复用同一套权重。

Nanbeige 等架构此前已经探索过循环的做法，而 Inkling 2 Mini 走的是一条有意思的路子。每一次遍历循环核心（第 6–17 层）都从同一份输入出发，也就是前六层的输出。各次遍历之间通过跨 pass 的 `messages` 传递信息。每个循环层用自己的、学习到的 query，从上一次遍历的输出中读取一条 message（query、key、value 和 MLP 输入各有一条 message）。随后一个小的门控控制器同时查看该层的当前输入和这条 message，决定要忘掉当前输入的多少、再加上这条 message 的多少。于是每一次遍历都在上一次遍历算出的结果上继续细化。

[![Inkling 2 Mini 架构](https://huggingface.co/buckets/huggingface-projects/inkling-2-mini-release-assets/resolve/architecture.png)](https://huggingface.co/buckets/huggingface-projects/inkling-2-mini-release-assets/resolve/architecture.png)

> 每个六层块包含五个滑动窗口层和一个全注意力层。本地窗口最多容纳 1,024 个 token。  
> 注意力使用 24 个 query 头和 8 个 KV 头。它使用学习到的相对位置 logits、一个学习到的 sink 和一个输出门。全注意力层使用动态 key 和 value 卷积。  
> 路由器为每个 token 从 128 个 SwiGLU 专家中选择 8 个。它对选中的分数做归一化，并将权重缩放 8 倍。  
> 在第 2 和第 3 次遍历中，每个核心层会对上一次遍历的两个残差块做注意力。四个 rank-64 门将各自的 message 混合进 query、key、value 和 MoE 输入。

> 文本解码器宽度为 2,304，每个专家的中间宽度为 1,152。复用核心权重减少了 checkpoint 存储的不同层数量。模型仍然执行全部 48 次访问，每次访问都保留自己的 KV 和短卷积状态。

除了旗舰型号 Inkling 2 Mini，还发布了一个研究用版本。它采用相同的架构，但这个变体在训练时就接受可变次数的循环 🤯。把遍历次数设为 1 或 2 而不是 3，推理会快很多，但生成质量可能略差。我们测试过这个变体，它确实能跑，只是还没有做深入评估。

## 基准测试结果

在 Artificial Analysis Intelligence Index v5（AAv5）以及各类别的众多基准测试中，Inkling 2 Mini 都处于同类模型的最前列。与 Gemma 4 31B、Muse Glimmer、Qwen3.8-27B 和 Nemotron 3.5 Super VL 相比，Inkling 2 Mini 在 48 个基准里有 32 个领先。这些基准覆盖编程与自动研究、面向知识工作的 agentic 搜索与工具使用、视觉理解与创作、推理与知识，以及安全与对齐。完整的基准列表和分数见 [Inkling 2 Mini 模型卡](https://huggingface.co/thinkingmachines/Inkling-2-Mini)。

Inkling 2 Mini 是一个很棒的本地编程搭档。它在 FrontierCode v2.0 上领先，在 Terminal-Bench 4.0 上与 Qwen3.8-27B 打平，在 AutomationBench-AA v1.0.6 上落后于 Qwen。下面是我们挑选的几个编程和知识工作亮点。注意 AA Briefcase 采用 ELO 评分，越高越好。

## 推理支持

本节介绍如何在 transformers、llama.cpp、MLX 和 SGLang 中使用 Inkling 2 Mini。

### Transformers

我们同时支持 Inkling 2 Mini（固定循环）和 `TML-d24-varloop-research`（可变循环）研究变体。

#### 使用 Inkling 2 Mini 的固定循环

你可以使用 `AutoModelForMultimodalLM` 类。

```
import torch
from transformers import AutoModelForMultimodalLM, AutoProcessor

model_id = "thinkingmachines/Inkling-2-Mini"

processor = AutoProcessor.from_pretrained(model_id)
model = AutoModelForMultimodalLM.from_pretrained(
    model_id,
)

messages = [{"role": "user", "content": [{"type": "text", "text": "Why is the sky blue?"}]}]

inputs = processor.apply_chat_template(
    messages, tokenize=True, add_generation_prompt=True, return_dict=True, return_tensors="pt",
).to(model.device)
input_len = inputs["input_ids"].shape[-1]

outputs = model.generate(**inputs, max_new_tokens=1024)
print(processor.decode(outputs[0][input_len:], skip_special_tokens=False))
```

#### 可变循环

要设置研究 checkpoint 中的循环次数，可以按如下方式修改 `text_config` 中的 `loop_num_passes`。下面的示例使用两次循环。

```
import torch
from transformers import AutoModelForMultimodalLM, AutoProcessor

model_id = "thinkingmachines/TML-d24-varloop-research"

processor = AutoProcessor.from_pretrained(model_id)
model = AutoModelForMultimodalLM.from_pretrained(
    model_id,
    text_config={"loop_num_passes": 2},
)

messages = [{"role": "user", "content": [{"type": "text", "text": "Why is the sky blue?"}]}]

inputs = processor.apply_chat_template(
    messages, reasoning_effort="medium", tokenize=True, add_generation_prompt=True, return_dict=True, return_tensors="pt", 
).to(model.device)
input_len = inputs["input_ids"].shape[-1]

outputs = model.generate(**inputs, max_new_tokens=1024)
print(processor.decode(outputs[0][input_len:], skip_special_tokens=False))
```

#### 图像与文本

对于图像 prompt，将任一示例中的 messages 替换为下面的列表，然后照常推理。

messages = [

        "role": "user",

#### 推理强度

向 `processor.apply_chat_template(...)` 传入 `reasoning_effort="medium"` 可为请求设置强度。chat template 会把对应的数值作为 system message 加入 prompt。默认值为 `high`（0.9）。

```
inputs = processor.apply_chat_template(
    messages, reasoning_effort="medium", tokenize=True, add_generation_prompt=True, return_dict=True, return_tensors="pt", 
).to(model.device)
```

可用级别有 `none`（0.0）、`minimal`（0.1）、`low`（0.2）、`medium`（0.7）、`high`（0.9；默认）、`xhigh`（0.99）和 `max`（0.99）。你也可以传入 0.0 到 0.99 之间的数字，例如 `reasoning_effort=0.35`。

#### 工具调用

下面让模型调用几个工具。

这个示例里，我们问模型某个地点当前的温度。除了 prompt，我们还把完成这件事的工具（`get_current_temperature`）一并交给它。模型会请求发起工具调用，我们代它调用，然后把输出加入下一轮指令。模型再利用工具的输出，给我们最终结果。

如果你想进一步了解工具调用，建议查阅我们的[官方文档](https://huggingface.co/docs/transformers/en/chat_extras)。

```
import torch
from transformers import AutoModelForMultimodalLM, AutoProcessor

model_id = "thinkingmachines/Inkling-2-Mini"
processor = AutoProcessor.from_pretrained(model_id)
model = AutoModelForMultimodalLM.from_pretrained(model_id, dtype=torch.bfloat16, device_map="auto")


def get_current_temperature(location: str, unit: str):
    """
    Get the current temperature at a location.

    Args:
        location: The location to get the temperature for, in the format "City, Country"
        unit: The unit to return the temperature in. (choices: ["celsius", "fahrenheit"])
    """
    return 22.0  # A real function would call a weather API here


def ask(messages):
    inputs = processor.apply_chat_template(
        messages, tools=[get_current_temperature], reasoning_effort="low", tokenize=True, return_dict=True, return_tensors="pt"
    ).to(model.device)
    output = model.generate(**inputs, max_new_tokens=1024)[0][inputs["input_ids"].shape[-1] :]
    parsed = processor.parse_response(output, prefix=inputs["input_ids"][0])
    return parsed


messages = [{"role": "user", "content": "Hey, what's the temperature in Paris right now?"}]

reply = ask(messages)
call = reply["tool_calls"][0]["function"]
print("Model calls:", call["name"], call["arguments"])  # the model fills in the arguments itself

temperature = get_current_temperature(**call["arguments"])
messages += [reply, {"role": "tool", "name": call["name"], "content": str(temperature)}]
print(ask(messages)["content"])

# Model calls: get_current_temperature {'location': 'Paris, France', 'unit': 'celsius'}
# Right now in Paris it’s about **22°C** (roughly **71.6°F**).
```

### Llama App 与 Llama.cpp

[Llama App](https://llama.app/) 让你可以在 macOS（从菜单栏）或 Windows（系统托盘）上轻松运行和管理本地语言模型。它基于 llama.cpp 构建，由同一团队开发。该应用还提供本地 OpenAI 兼容 API，便于与编程 agent、编辑器和脚本集成。

为 Inkling 2 Mini 的发布，我们为两个模型提供了 GGUF 4-bit（`IQ4_NL)`）和 8-bit（`Q8_0`）量化版本。

如果你使用 Linux，或想从 CLI 提供模型服务，可以对固定循环模型运行以下命令：

```
llama serve -hf ggml-org/Inkling-2-Mini-GGUF:IQ4_NL
```

要运行可变循环模型，可以运行

```
llama serve -hf ggml-org/TML-d24-varloop-research-GGUF:IQ4_NL
```

要加载 8-bit 权重，请将后缀改为 `:Q8_0`。

这里我们让 4-bit 模型给一个叫 plant therapy 的 SaaS 做网站，这家服务把植物匹配给持证治疗师。模型相当自主：它自己做了网站上要用的 SVG 视觉素材，连匹配逻辑也一并写了。

### SGLang

Inkling 2 Mini 在 SGLang 里提供 Day 0 支持。安装最新版本的 SGLang，执行下面的命令即可把服务器跑起来。有一个前提要先处理：它需要运行在 `SM103` 上。

```
export MODEL="thinkingmachines/Inkling-2-Mini"

python -m sglang.launch_server \
  --model-path $MODEL \
  --served-model-name inkling \
  --attention-backend fa4 --bf16-gemm-backend torch --dtype bfloat16 \
  --tp 1 --page-size 128 --grammar-backend xgrammar \
  --host 0.0.0.0 --port 30000
```

服务器启动后，你应该可以这样请求 API

```
curl -s localhost:30000/health_generate && echo OK
curl -s localhost:30000/v1/models | python -m json.tool

curl -s localhost:30000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
        "model": "inkling",
        "messages": [{"role": "user", "content": "What is 17 times 24?"}],
        "max_tokens": 512,
        "reasoning_effort": "low"
      }' | python -m json.tool
```

也可以通过设置 `--enable-multimodal` 启用多模态。

### 投机解码

SGLang 可以使用三层 DSpark draft 来提出候选 token，交由目标模型验证。该 draft 会读取解码器第 5、23 和 41 次访问的输入，以及索引 48 处的最终归一化状态。在已有 draft 权重的情况下，在服务器命令中加入 `--speculative-algorithm DSPARK --context-length 131072`。

我们对启用和不启用投机解码的模型进行了基准测试，在单张 NVIDIA B300 GPU 上测量生成速度，其中每个请求都有 1,024-token 的 prompt，并恰好生成 1,024 个 token，并发数为 1、4、16 和 64。

展开 SGLang 基准测试脚本

```
MODEL=thinkingmachines/Inkling-2-Mini

for TAG in base mtp; do
  EXTRA=""; [ $TAG = mtp ] && EXTRA="--speculative-algorithm DSPARK"

  # Start the server (with or without MTP)
  python -m sglang.launch_server --model-path $MODEL \
    --attention-backend fa4 --bf16-gemm-backend torch --dtype bfloat16 \
    --tp 1 --page-size 128 --context-length 131072 --max-running-requests 64 \
    --port 30000 $EXTRA > $TAG.log 2>&1 &
  until curl -sf localhost:30000/health_generate > /dev/null; do sleep 10; done

  # Benchmark at increasing concurrency
  for C in 1 4 16 64; do
    python -m sglang.bench_serving --backend sglang --port 30000 --model $MODEL \
      --dataset-name random --apply-chat-template \
      --random-input-len 1024 --random-output-len 1024 --random-range-ratio 1.0 \
      --num-prompts $(( C*4 < 32 ? 32 : C*4 )) --max-concurrency $C \
      --output-file results_$TAG.jsonl
  done

  kill %1; wait
done
```
