[Meta Llama 3.1](https://huggingface.co/blog/llama31) 是 Meta 于 2024 年 7 月发布的最新开放 LLM。Meta Llama 3.1 有三种尺寸：8B 适合在消费级 GPU 上高效部署和开发，70B 适合大规模 AI 原生应用，405B 适合合成数据、LLM as a Judge 或蒸馏等用例。它的关键特性包括：128K token 的超长上下文（原来是 8K）、多语言能力、工具调用能力，以及更宽松的许可证。

## Vertex AI 简介

Vertex AI 是一个机器学习（ML）平台，让你能训练和部署 ML 模型与 AI 应用，并能为你的 AI 应用定制大语言模型（LLM）。Vertex AI 融合了数据工程、数据科学和 ML 工程工作流，让团队用统一的工具集协作，并借助 Google Cloud 的优势扩展应用。

本博客聚焦于用预构建容器从 Hugging Face Hub 部署一个已微调好的模型，得到实时的在线预测。因此我们会展示 Vertex AI 在推理上的用法。

更多信息见 [Vertex AI - Documentation - Introduction to Vertex AI](https://cloud.google.com/vertex-ai/docs/start/introduction-unified-platform)。

## 1. 在 Google Cloud 上运行 Meta Llama 3.1 模型的要求

Meta Llama 3.1 带来了令人兴奋的进步。但要跑这些模型，得仔细考虑硬件资源。推理的内存需求取决于模型大小和权重精度。下表给出不同配置的大致内存需求：

| **模型大小** | **FP16** | **FP8** | **INT4** |
| --- | --- | --- | --- |
| 8B | 16 GB | 8 GB | 4 GB |
| 70B | 140 GB | 70 GB | 35 GB |
| 405B | 810 GB | 405 GB | 203 GB |

*注：以上数字指的是仅加载模型 checkpoint 所需的 GPU VRAM，不含 torch 为 kernel 或 CUDA graph 预留的空间。*

举个例子，一个 H100 节点（8 块各 80GB 的 H100）共有约 640GB VRAM，所以 405B 模型要么以多节点方式运行，要么用更低精度（如 FP8）运行——后者是推荐做法。更多详见 [Hugging Face 的 Meta Llama 3.1 博客](https://huggingface.co/blog/llama31#inference-memory-requirements)。

Google Cloud 的 A3 加速器优化机型配备 8 块 H100 80GB NVIDIA GPU、208 vCPU 和 1872 GB 内存。该机型针对计算和内存密集、网络受限的 ML 训练与 HPC 负载做了优化。关于 A3 机型上线的公告详见 [Announcing A3 supercomputers with NVIDIA H100 GPUs, purpose-built for AI](https://cloud.google.com/blog/products/compute/introducing-a3-supercomputers-with-nvidia-h100-gpus)，A3 机型系列详见 [Compute Engine - Accelerator-optimized machine family](https://cloud.google.com/compute/docs/accelerator-optimized-machines#a3-vms)。

尽管 A3 机型在 Google Cloud 中可用，你仍然需要向 Google Cloud 申请自定义配额提升，因为需要专门审批。注意 A3 机型只在部分 zone 提供，所以请先到 [Compute Engine - GPU regions and zones](https://cloud.google.com/compute/docs/gpus/gpu-regions-zones) 检查对应 zone 的 A3 High 乃至 A3 Mega 可用性。

本例中，要使用 A3 High GPU 机型需要提升以下配额：

- `Service: Vertex AI API`、`Name: Custom model serving Nvidia H100 80GB GPUs per region` 设为 **8**
- `Service: Vertex AI API`、`Name: Custom model serving A3 CPUs per region` 设为 **208**

[![A3 Quota Request in Google Cloud](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/llama31-on-vertex-ai/a3-quota-request.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/llama31-on-vertex-ai/a3-quota-request.png)

如何申请配额提升详见 [Google Cloud Documentation - View and manage quotas](https://cloud.google.com/docs/quotas/view-manage)。

## 2. 为 Vertex AI 配置 Google Cloud

继续之前，我们先为了方便地设置两个环境变量：

```
%env PROJECT_ID=your-project-id
%env LOCATION=your-region
```

首先要在你的机器上按 [Cloud SDK - Install the gcloud CLI](https://cloud.google.com/sdk/docs/install) 的说明安装 `gcloud`，然后登录你的 Google Cloud 账号，设置项目和首选的 Google Compute Engine region。

```
gcloud auth login
gcloud config set project $PROJECT_ID
gcloud config set compute/region $LOCATION
```

Google Cloud SDK 装好后，还需要启用必要的 Google Cloud API，以便在 Artifact Registry for Docker 里通过 Deep Learning Container（DLC）使用 Vertex AI。

```
gcloud services enable aiplatform.googleapis.com
gcloud services enable compute.googleapis.com
gcloud services enable container.googleapis.com
gcloud services enable containerregistry.googleapis.com
gcloud services enable containerfilesystem.googleapis.com
```

接着还要安装 [`google-cloud-aiplatform`](https://github.com/googleapis/python-aiplatform)，用于从 Python 以编程方式操作 Google Cloud Vertex AI。

```
pip install --upgrade --quiet google-cloud-aiplatform
```

然后按如下方式用 Python 初始化：

```
import os
from google.cloud import aiplatform

aiplatform.init(project=os.getenv("PROJECT_ID"), location=os.getenv("LOCATION"))
```

最后，由于 Meta Llama 3.1 模型在 [Hugging Face Hub 的 `meta-llama` 组织](https://hf.co/meta-llama)下是 gated 的，你需要申请访问并等待审批（一般不超过 24 小时）。之后安装 `huggingface_hub` Python SDK，用 `huggingface-cli` 登录 Hugging Face Hub 才能下载这些模型。

```
pip install --upgrade --quiet huggingface_hub
```

另外，也可以跳过安装 `huggingface_hub`，直接生成一个 [Hugging Face Fine-grained Token](https://hf.co/settings/tokens)，只赋予对 [`meta-llama/Meta-Llama-3.1-405B-Instruct-FP8`](https://hf.co/meta-llama/Meta-Llama-3.1-405B-Instruct-FP8) 或 [`meta-llama` 组织](https://hf.co/meta-llama)下其他模型的只读权限，例如选择 `Repository permissions -> meta-llama/Meta-Llama-3.1-405B-Instruct-FP8 -> Read access to contents of selected repos`。然后把该 token 设置到 `HF_TOKEN` 环境变量里，或手动传给 `notebook_login` 方法：

```
from huggingface_hub import notebook_login

notebook_login()
```

## 3. 在 Vertex AI 上注册 Meta Llama 3.1 405B 模型

要在 Vertex AI 上注册 Meta Llama 3.1 405B 模型，需要使用 `google-cloud-aiplatform` Python SDK。但在继续之前，先确定用哪个 DLC——本例选择最新的 Hugging Face TGI GPU DLC。

截至当前（2024 年 8 月），最新可用的 Hugging Face TGI DLC 是 [us-docker.pkg.dev/deeplearning-platform-release/gcr.io/huggingface-text-generation-inference-cu121.2-2.ubuntu2204.py310](https://huggingface.co/blog/us-docker.pkg.dev/deeplearning-platform-release/gcr.io/huggingface-text-generation-inference-cu121.2-2.ubuntu2204.py310)，使用 TGI v2.2。该版本支持 Meta Llama 3.1 架构——它需要与前代 Meta Llama 3 不同的 RoPE 缩放方法。

要查看 Google Cloud 里有哪些 Hugging Face DLC，可以打开 [Google Cloud Artifact Registry](https://console.cloud.google.com/artifacts/docker/deeplearning-platform-release/us/gcr.io) 并按 "huggingface-text-generation-inference" 过滤，或使用以下 `gcloud` 命令：

```
gcloud container images list --repository="us-docker.pkg.dev/deeplearning-platform-release/gcr.io" | grep "huggingface-text-generation-inference"
```

然后定义容器的配置——即 `text-generation-launcher` 期望作为参数传入的环境变量（参见[官方文档](https://huggingface.co/docs/text-generation-inference/en/basic_tutorials/launcher)），本例包括：

- `MODEL_ID`：Hugging Face Hub 上的模型 ID，即 `meta-llama/Meta-Llama-3.1-405B-Instruct-FP8`。
- `HUGGING_FACE_HUB_TOKEN`：对 gated 仓库 `meta-llama/Meta-Llama-3.1-405B-Instruct-FP8` 的读取令牌，是从 Hugging Face Hub 下载权重所必需的。
- `NUM_SHARD`：分片数，即使用的 GPU 数。本例设为 8，因为使用的是带 8 块 H100 NVIDIA GPU 的 A3 实例。

另外，建议同时定义 `HF_XET_HIGH_PERFORMANCE=1`，通过 `hf_xet` 工具获得更快的下载速度——Meta Llama 3.1 405B 约 400 GiB，否则下载权重会很久。

然后就可以通过 `google-cloud-aiplatform` Python SDK 在 Vertex AI 的 Model Registry 中注册模型：

```
from huggingface_hub import get_token

model = aiplatform.Model.upload(
    display_name="meta-llama--Meta-Llama-3.1-405B-Instruct-FP8",
    serving_container_image_uri="us-docker.pkg.dev/deeplearning-platform-release/gcr.io/huggingface-text-generation-inference-cu121.2-2.ubuntu2204.py310",
    serving_container_environment_variables={
        "MODEL_ID": "meta-llama/Meta-Llama-3.1-405B-Instruct-FP8",
        "HUGGING_FACE_HUB_TOKEN": get_token(),
        "HF_XET_HIGH_PERFORMANCE": "1",
        "NUM_SHARD": "8",
    },
)
model.wait()
```

## 4. 在 Vertex AI 上部署 Meta Llama 3.1 405B

Meta Llama 3.1 405B 在 Vertex AI Model Registry 注册完成后，就可以创建 Vertex AI Endpoint 并把模型以 Hugging Face TGI DLC 作为服务容器部署到该端点。

如前所述，FP8 的 Meta Llama 3.1 405B 约占 400 GiB 磁盘空间，意味着我们需要至少 400 GiB 的 GPU VRAM 来加载模型，且节点内的 GPU 必须支持 FP8 数据类型。本例使用带 8 块 NVIDIA H100 80GB（共约 640 GiB VRAM）的 A3 实例加载模型，同时为 KV Cache 和 CUDA Graphs 留出一些空闲 VRAM。

```
endpoint = aiplatform.Endpoint.create(display_name="Meta-Llama-3.1-405B-FP8-Endpoint")

deployed_model = model.deploy(
    endpoint=endpoint,
    machine_type="a3-highgpu-8g",
    accelerator_type="NVIDIA_H100_80GB",
    accelerator_count=8,
)
```

> 注意：在 Vertex AI 上部署 Meta Llama 3.1 405B 可能需要 25-30 分钟——需要在 Google Cloud 上分配资源、从 Hugging Face Hub 下载权重（约 10 分钟），再在 TGI 中加载用于推理（约 2 分钟）。

[![Meta Llama 3.1 405B Instruct FP8 deployed on Vertex AI](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/llama31-on-vertex-ai/vertex-ai-endpoint.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/llama31-on-vertex-ai/vertex-ai-endpoint.png)

恭喜，你已经把 Meta Llama 3.1 405B 部署到自己的 Google Cloud 账号里了！🔥 现在是时候检验模型了。

## 5. 用 Meta Llama 3.1 405B 做在线预测

Vertex AI 会在 `/predict` 路由上暴露一个在线预测端点，背后由 Text Generation Inference（TGI）DLC 提供文本生成，并确保输入输出数据符合 Vertex AI 的负载格式（关于 Vertex AI I/O payloads 的更多内容见 [Vertex AI Documentation - Get online predictions from a custom trained model](https://cloud.google.com/vertex-ai/docs/predictions/get-online-predictions#formatting-prediction-input)）。

由于暴露的是 `/generate` 端点，你需要在发请求前用 chat template 格式化消息，因此建议安装 🤗`transformers`，用 `PreTrainedTokenizerFast` 分词器的 `apply_chat_template` 方法。

```
pip install --upgrade --quiet transformers
```

然后用分词器对对话应用 chat template：

```
import os
from huggingface_hub import get_token
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained(
    "meta-llama/Meta-Llama-3.1-405B-Instruct-FP8",
    token=get_token(),
)

messages = [
    {"role": "system", "content": "You are an assistant that responds as a pirate."},
    {"role": "user", "content": "What's the Theory of Relativity?"},
]
inputs = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,
)
```

现在你得到用 Meta Llama 3.1 默认 chat template 把对话消息格式化后的字符串：

> <|begin_of_text|><|start_header_id|>system<|end_header_id|>\n\nYou are an assistant that responds as a pirate.<|eot_id|><|start_header_id|>user<|end_header_id|>\n\nWhat's the Theory of Relativity?<|eot_id|><|start_header_id|>assistant<|end_header_id|>\n\n

这就是你发往已部署 Vertex AI Endpoint 的 payload 内容，此外还有生成参数，参见 [Consuming Text Generation Inference (TGI) -> Generate](https://huggingface.co/docs/huggingface_hub/main/en/package_reference/inference_client#huggingface_hub.InferenceClient.text_generation)。

### 5.1 通过 Python

#### 5.1.1 同一会话内

如果你想在当前会话（也就是部署模型所用的那个会话）里直接做在线预测，可以通过 `aiplatform.Model.deploy` 方法返回的 `aiplatform.Endpoint` 以编程方式发送请求，如下面的片段。

```
output = deployed_model.predict(
    instances=[
        {
            "inputs": inputs,
            "parameters": {
                "max_new_tokens": 128,
                "do_sample": True,
                "top_p": 0.95,
                "temperature": 0.7,
            },
        },
    ]
)
```

产生如下 `output`：

> Prediction(predictions=["Yer want ta know about them fancy science things, eh? Alright then, matey, settle yerself down with a pint o' grog and listen close. I be tellin' ye about the Theory o' Relativity, as proposed by that swashbucklin' genius, Albert Einstein.\n\nNow, ye see, Einstein said that time and space be connected like the sea and the wind. Ye can't have one without the other, savvy? And he proposed that how ye see time and space depends on how fast ye be movin' and where ye be standin'. That be called relativity, me"], deployed_model_id='', metadata=None, model_version_id='1', model_resource_name='projects//locations//models/', explanations=None)

#### 5.1.2 从不同会话

如果 Vertex AI Endpoint 是在另一个会话里部署的，你现在只想用它、又拿不到 `aiplatform.Model.deploy` 返回的 `deployed_model` 变量，那么也可以用下面的片段，通过资源名实例化已部署的 `aiplatform.Endpoint`。资源名可以在 Vertex AI 在线预测 UI 里找到，从上面实例化的 `aiplatform.Endpoint` 获取，或者直接替换 `projects/{PROJECT_ID}/locations/{LOCATION}/endpoints/{ENDPOINT_ID}` 中的值。

```
import os
from google.cloud import aiplatform

aiplatform.init(project=os.getenv("PROJECT_ID"), location=os.getenv("LOCATION"))

endpoint = aiplatform.Endpoint(f"projects/{os.getenv('PROJECT_ID')}/locations/{os.getenv('LOCATION')}/endpoints/{ENDPOINT_ID}")
output = endpoint.predict(
    instances=[
        {
            "inputs": inputs,
            "parameters": {
                "max_new_tokens": 128,
                "do_sample": True,
                "top_p": 0.95,
                "temperature": 0.7,
            },
        },
    ],
)
```

产生如下 `output`：

> Prediction(predictions=["Yer lookin' fer a treasure trove o' knowledge about them fancy physics, eh? Alright then, matey, settle yerself down with a pint o' grog and listen close, as I spin ye the yarn o' Einstein's Theory o' Relativity.\n\nIt be a tale o' two parts, me hearty: Special Relativity and General Relativity. Now, I know what ye be thinkin': what in blazes be the difference? Well, matey, let me break it down fer ye.\n\nSpecial Relativity be the idea that time and space be connected like the sea and the sky."], deployed_model_id='', metadata=None, model_version_id='1', model_resource_name='projects//locations//models/', explanations=None)

## 6. 清理资源

用完后可以按下面方式释放创建的资源，避免不必要的开销：

- `deployed_model.undeploy_all`：从所有端点卸载模型。
- `deployed_model.delete`：在 `undeploy_all` 之后，优雅删除模型部署所在的端点。
- `model.delete`：从 registry 中删除模型。

```
deployed_model.undeploy_all()
deployed_model.delete()
model.delete()
```

也可以在 Google Cloud Console 里按以下步骤移除：

- 进入 Google Cloud 的 Vertex AI
- 进入 Deploy and use -> Online prediction
- 点击端点，再点击已部署模型，选择 "Undeploy model from endpoint"
- 然后回到端点列表删除端点
- 最后进入 Deploy and use -> Model Registry，删除模型
