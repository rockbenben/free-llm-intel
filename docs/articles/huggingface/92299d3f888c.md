你可能会想，Hugging Face 上的教程已经汗牛充栋，为何还要再写一篇？答案在于可及性：现有大多数资源都默认你具备某种技术背景，包括会写 Python，这会把非技术背景的人挡在 ML 基础门外。我自己就是从 AI 的业务侧过来的，深知学习曲线本身就是一道障碍，所以想为同好们提供一条更友好的路径。

因此，本指南面向的是对开源机器学习充满兴趣、又不想从零学 Python 的非技术读者。我们不假设任何先验知识，所有概念都会从头讲起，确保清楚易懂。如果你是工程师，这份指南可能显得有点基础，但对初学者来说，它是理想的起点。

让我们开干……不过先来点背景。

## Hugging Face Transformers 是什么？

Hugging Face Transformers 是一个开源 Python 库，提供对数千个预训练 Transformer 模型的访问，覆盖自然语言处理（NLP）、计算机视觉、音频任务等领域。它把在 PyTorch、TensorFlow、JAX 这类底层 ML 框架中训练或部署模型的复杂度抽象掉，让实现 Transformer 模型变得简单。

## 什么是库？

库就是一堆可复用代码的集合，可以整合进项目里，更高效地实现功能，而不必从零写自己的代码。

具体而言，Transformers 库提供了在 PyTorch、TensorFlow、JAX 等常见框架中实现模型的可复用代码。这些可复用代码通过调用库中的函数（也叫方法）来使用。

## 什么是 Hugging Face Hub？

Hugging Face Hub 是一个协作平台，托管了海量开源机器学习模型和数据集，可以把它想象成 ML 界的 GitHub。Hub 让分享与协作变得容易——你可以轻松地发现、学习和使用开源社区里有价值的 ML 资产。Hub 与 Transformers 库深度集成、配套使用：通过 Transformers 库部署的模型就是从 Hub 下载的。

## 什么是 Hugging Face Spaces？

Hugging Face Spaces 是 Hub 上的一项服务，提供易用的图形界面，用于构建和部署托管在 Web 上的 ML 演示和应用。通过这个服务，你可以快速搭建 ML demo、上传托管你自己的应用，甚至直接从若干预配置的 ML 应用中挑一个即刻部署。

在教程中，我们将部署其中一个预配置应用——JupyterLab notebook，只需选对应的 docker 容器即可。

## 什么是 notebook？

Notebook 是一种交互式应用，允许你把实时可执行代码与叙述性文字交织在一起编写和分享。它对数据科学家和机器学习工程师特别有用，因为你可以实时试验代码，并轻松查看和分享结果。

Docker 模板是软件环境的预定义蓝图，包含所需的软件和配置，让开发者能够以一致且隔离的方式轻松、快速地部署应用。

## 什么是 !pip install？

`!pip` 是从 Python 包索引（[PyPI](https://pypi.org/)）安装 Python 包的命令。PyPI 是一个 Web 仓库，收录了可供 Python 环境使用的各种库。它通过引入大量第三方插件来扩展 Python 应用的功能。

## 我们既然用 Transformers，为什么还要 Pytorch？

Hugging Face（Transformers）是构建在 Pytorch、Tensorflow、JAX 等框架之上的库。本例中我们把 Transformers 与 Pytorch 搭配使用，所以需要安装它以调用其功能。

![](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/llama2-non-engineers/guide7.png)

- 从 Transformers 导入 AutoTokenizer 和 AutoModelForCausalLM 类

- 在新的一行输入以下代码并运行

```
from transformers import AutoTokenizer, AutoModelForCausalLM
```

## 什么是类（Class）？

把类想象成创建所谓"对象（Objects）"的代码食谱。它有用的地方在于，能让我们保存兼具属性和函数的对象。这进而简化了编程——某个主题所需的全部信息和操作都能在同一个地方获取。我们将用这些类创建两个对象：一个 `model` 对象和一个 `tokenizer` 对象。

## 装好 Transformers 之后，为什么还要再导入类？

虽然 Transformers 已经安装，但 Transformers 里具体的类并不会自动在你的环境中可用。Python 要求我们显式导入单个类，这有助于避免命名冲突，并确保只有库里必要的部分被加载进当前的工作上下文。

- 定义你想运行的模型

- 要指定从 Hugging Face Hub 下载并运行的模型，你需要在代码里写明模型仓库的名字
- 我们把这个设为一个等于模型名的变量，这里我们决定把变量叫做 `model_id`
- 我们用 Microsoft 的 Phi-2——一个虽小却能力惊人的模型，地址是 [https://huggingface.co/microsoft/phi-2](https://huggingface.co/microsoft/phi-2)。注意：Phi-2 是基座模型而非指令微调模型，如果你拿它做聊天，它的回答会很怪异

```
model_id = "microsoft/phi-2"
```

## 什么是指令微调模型？

指令微调语言模型是这样一类模型：它在基座版本之上经过进一步训练，能够理解并对用户给出的命令或提示词做出回应，从而提升遵循指令的能力。基座模型擅长续写文本，但对指令的回应往往不实用。后面对 Phi 做提示词时你就会看到这一点。

- 创建模型对象并加载模型

- 要把模型从 Hugging Face Hub 加载到本地环境，我们需要实例化模型对象。做法是：把上一步定义的 "model_id" 传给 AutoModelForCausalLM 类的 `.from_pretrained` 方法作为参数。
- 运行代码，去倒杯咖啡，模型可能要下载几分钟

```
model = AutoModelForCausalLM.from_pretrained(model_id)
```

## 什么是参数？

参数是传给函数、用来计算出输出的输入信息。我们把参数放在函数括号里传给函数。本例中模型 ID 是唯一的参数，尽管函数可以有多个参数，也可以一个都没有。

## 什么是方法？

方法是函数的另一个名字，特指使用某个特定对象或类的信息的函数。本例中 `.from_pretrained` 方法使用类和 `model_id` 的信息来创建一个新的 `model` 对象。

- 创建分词器对象并加载分词器

- 加载分词器现在需要创建一个 tokenizer 对象。做法同样是把 `model_id` 作为参数传给 AutoTokenizer 类的 `.from_pretrained` 方法。
- 注意还有几个额外参数，就本例而言理解它们并不重要，我们就不解释了。

```
tokenizer = AutoTokenizer.from_pretrained(model_id, add_eos_token=True, padding_side='left')
```

## 什么是分词器？

分词器是一种把句子切分为更小文本片段（词元/token）的工具，并为每个词元分配一个称为输入 id 的数值。之所以需要它，是因为我们的模型只懂数字，必须先把文本转换（即编码）成模型能理解的格式。每个模型都有自己的分词器词表，务必使用模型训练时所用的那个分词器，否则模型会误解文本。

- 构造给模型处理的输入

- 定义一个新变量 `input_text`，用来放你想给模型的提示词。这里我问了 "Who are you?"，但你可以随意选自己喜欢的。
- 把新变量作为参数传给 tokenizer 对象，生成 `input_ids`
- 再给 tokenizer 对象传第二个参数 `return_tensors="pt"`，它确保 token_id 以适合我们所使用模型版本（即 Pytorch 而非 Tensorflow）的向量形式表示

```
input_text = "Who are you?"
input_ids = tokenizer(input_text, return_tensors="pt")
```

- 运行生成并解码输出

- 现在输入格式对了，需要把它送进模型。做法是在 `model` 对象上调用 `.generate` 方法，把 `input_ids` 作为参数传入，并赋值给新变量 `outputs`。我们还把第二个参数 `max_new_tokens` 设为 100，限制模型生成的词元数量。
- 输出此时还不是人类可读的，要还原成文本必须解码输出。可以用 `.decode` 方法，并把结果存到变量 `decoded_outputs`
- 最后，把 `decoded_output` 变量传给 print 函数，我们就能在 notebook 里看到模型的输出。
- 可选：把 `outputs` 变量传给 print 函数，对比一下它和 `decoded outputs` 的区别

```
outputs = model.generate(input_ids["input_ids"], max_new_tokens=100)
decoded_outputs = tokenizer.decode(outputs[0])
print(decoded_outputs)
```

## 为什么需要解码？

模型只懂数字，所以我们以向量形式提供 `input_ids` 时，它返回的输出也是同样格式。要把这些输出还原为文本，需要把最初用分词器做的编码逆转回来。

## 为什么输出读起来像个故事？

记住，Phi-2 是一个未经对话类指令微调的基座模型，所以它本质上就是一个超大号的自动补全模型。基于你的输入，它会根据自己见过的所有网页、书籍和其他内容，预测它认为最可能出现在后面的内容。
