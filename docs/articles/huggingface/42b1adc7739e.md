# Holo3.1：快速且本地的计算机操作智能体

去年三月，我们发布了 Holo3，我们最先进的计算机操作（computer-use）模型。它被迅速采用。开发者、企业和合作伙伴开始在各类工作流中部署 Holo3，从浏览器自动化、业务软件到内部工具和桌面应用。随着采用度增长，我们意识到仅有性能已经不够了。

用户希望在桌面和移动环境中运行同样的计算机操作能力，并与不同的智能体框架无缝集成。他们希望部署灵活，从云端推理到在终端用户设备上的完全本地执行。

这正是我们发布 Holo3.1 系列的原因。Holo3.1 在生产中最关键的三个维度上提升了鲁棒性：环境（web、桌面、移动）、智能体框架，以及部署目标。我们首次发布了为本地推理优化的量化检查点，包括 FP8、Q4 GGUF 和 NVFP4。

Holo3.1 是我们迈向通用计算机操作智能体愿景的重要一步：这类系统能够跨环境操作、集成进任何智能体技术栈，并在工作流所在之处运行。

# 跨 GUI 环境与智能体框架的计算机操作

Holo3.1 基于 Qwen 系列，旨在提升计算机操作智能体实际部署环境中的鲁棒性，同时保持最先进的性能。

随着各团队把 Holo3 从评估推向生产，我们反复观察到同一个挑战：在一种设置下的强劲性能未必能迁移到另一种设置。移动设备、替代的智能体框架以及不同的执行框架都会引入各自不同的分布偏移来源。

## 移动自动化

Holo3.1 将 Holo3 的能力扩展到浏览器和桌面控制之外，在移动环境上带来大幅提升。在 AndroidWorld 上，我们的 35B-A3B 模型从 67% 提升到 79.3%，而更小的 4B 和 9B 变体从 58% 提升到 72%。

## 跨框架性能

为了更好地支持在第三方智能体技术栈中部署 Holo 的团队，Holo3.1 在 Holo3 已有的结构化 JSON 输出之外，引入了对 function-calling（函数调用）协议的原生支持。

在 OSWorld 以及我们覆盖电商、业务软件和协作工作流的内部基准套件上，function-calling 和原生执行如今达到了几乎持平的性能。在我们的 Holotab 产品框架内评估时，Holo3.1 相比 Holo3 也带来了超过 25% 的提升。

## 面向性能-成本权衡的更小尺寸

为了进一步支持本地和设备端推理，除了用于最先进的较大 35B-A3B 模型外，我们还发布了新的模型尺寸，包括用于经济高效且私有部署的小模型（0.8B、4B 和 9B）。

# 快速且本地的推理

这是我们首个发布量化权重的版本。我们从 35B-A3B 检查点开始，提供 FP8、Q4 GGUF 和 NVFP4。

对于 NVFP4，我们在 W4A16 配置下使用了 NVIDIA 的 Model Optimizer。这些检查点使计算机操作智能体能够进行快速本地推理，而模型性能几乎不降级。FP8 和 NVFP4 达到相同的 OSWorld 分数，仅比全精度 BF16 检查点低约两个点。

加速相当显著：在 DGX Spark 上，NVFP4 W4A16 提供了 FP8 总 token 吞吐量的 1.41 倍、BF16 的 1.74 倍。[![quality_throughput_pareto_light (1)](https://cdn-uploads.huggingface.co/production/uploads/69ce2739f4b9146a31e99a2f/LRDMlYHe5n_FLLu41CRXd.png)](https://cdn-uploads.huggingface.co/production/uploads/69ce2739f4b9146a31e99a2f/LRDMlYHe5n_FLLu41CRXd.png)

## 迈向消费级硬件上的本地智能体

我们还发布了面向在消费级硬件上本地部署计算机操作智能体的 Q4 GGUF 检查点。

智能体本身在 Windows 或 Mac 机器上本地运行，而模型可以运行在同一台机器上（我们提供了 Apple Silicon 的参考数据），或运行在同一网络中的 DGX Spark 上。两种情况下，执行都完全私密且本地化，没有任何东西离开用户的网络。

在 Spark 上，我们与 NVIDIA 共同开发的智能体框架优化，叠加上述 NVFP4 量化，相比 FP8 基线带来了复合约 2× 的端到端加速，将平均步时从 6.8 秒降至 3.3 秒。
