我们很高兴推出 [NPHardEval 排行榜](https://huggingface.co/spaces/NPHardEval/NPHardEval-leaderboard)，其基础是 [NPHardEval](https://arxiv.org/abs/2312.14890)——由密歇根大学与罗格斯大学研究者开发的尖端基准。

NPHardEval 引入了一个基于复杂度、动态的框架，用于评估大语言模型（LLM）的推理能力。它提出覆盖 NP-Hard 复杂度类及以下难度的 900 道算法题，旨在严格测试 LLM，并且每月更新以防止过拟合！

## LLM 评估的独特方法

[NPHardEval](https://arxiv.org/abs/2312.14890) 的独特之处在于采用计算复杂度类，为 LLM 推理能力提供可量化、稳健的度量。基准的任务映射现实世界的决策挑战，增强了其相关性与适用性。基准数据点每月的定期更新降低了模型过拟合的风险，确保评估可靠。

NPHardEval 的主要贡献在于采用新的基准策略（提出自动、动态的基准），以及引入评估 LLM 推理的新方式。

在基准策略上，NPHardEval 使用**自动化机制**同时生成和检验问题。由于它们基于算法可计算的问题，判断 LLM 回答是否正确不需要人工介入。这也让 NPHardEval 成为**动态基准**：既然问题可以自动生成，基准就能按月更新。这个每月刷新的基准有助于防止模型过拟合，因为我们总能生成不同难度的新题用于评估。

问题本身体系采用新系统来评估 LLM 推理。基准中的问题扎根于计算复杂度层级——这是理论计算机科学中久经研究的确立概念。这一基础让我们能借助已有研究，**通过复杂度类来定义推理**，从而严格、定量地衡量 LLM 逻辑推理的程度。基准还刻意把数值计算排除在问题之外，因为那是 LLM 出了名的难题。**聚焦逻辑问题**能更准确地评估 LLM 纯粹的逻辑推理能力，因为数值问题会干扰这一评估。

## 数据合成

NPHardEval 对 9 种算法各使用 100 道题、9 个难度层级，跨复杂度与难度共 900 道题。这 9 种算法包含 3 类 P、3 类 NP-complete 和 3 类 NP-hard 问题，按计算理论界定。900 道题每月全部合成并更新。

## 评估指标

我们用两个指标评估 LLM 的推理能力：加权准确率与失败率。

### 加权准确率（Weighted Accuracy, WA）

**加权准确率（WA）**用于评估问题求解的准确率。对每道题，该方法或者与正确答案比对，或者对没有唯一答案的问题逐步骤检查结果。为了更有效地反映比较性准确率，我们给不同难度层级赋权。每个层级的权重对应其相对重要性或难度，难度越高权重越大，呈线性递增（例如层级 1 权重 1、层级 2 权重 2，依此类推）。

加权准确率公式如下：

WA = \frac{\sum\limits_{i=1}^{10} (w_i \times A_i)}{\sum\limits_{i=1}^{10} w_i}

其中 w_i 表示分配给难度层级 i（1 到 10）的权重，A_i 是该层级的准确率。

### 失败率（Failure Rate, FR）

我们考虑的另一个关键指标是**失败率（FR）**。它用于衡量不同问题与难度层级上未成功结果出现的频率，尤其适合识别 LLM 输出不符合预期格式的情形。

失败率的计算方式是看每个难度层级上失败尝试占总尝试的比例。若模型生成的结果在所有端点调用中都无法成功解析，该尝试记为失败。我们把最大尝试次数设为 10。对每道题，失败率在全部难度层级上汇总，考虑每级共 10 次尝试。

失败率的形式化定义：

FR = \frac{\sum\limits_{i=1}^{10} F_i}{100}

其中 F_i 是难度层级 i 上的失败尝试次数。

## 实验与洞见

基准包含系统性实验，跨各种复杂度类与难度层级分析 LLM。它深入剖析 LLM 性能的细节，为其推理优势与局限提供宝贵洞见。总体而言：

- 闭源模型普遍好于开源模型，其中 GPT 4 Turbo 综合表现最佳。
- 模型在复杂度较低的问题（更易的复杂度类）上普遍表现更好，但并非总随复杂度层级线性下降。Claude 2 这类模型在 NP-complete（中等复杂度）问题上表现最佳。
- 一些开源模型在特定问题上能超过闭源模型。领先的开源模型包括 Yi-34b、Qwen-14b、Phi-2 和 Mistral-7b。

## 在你自己的机器上复现 NPHardEval 基准结果

搭建 NPHardEval 基准需要几个步骤：

- 环境配置：把仓库克隆到本地后，用 `conda` 安装所需的 Python 库。`conda create --name llm_reason python==3.10 conda activate llm_reason git clone https://github.com/casmlab/NPHardEval.git pip install -r requirements.txt `
- 配置 API key：获取 API key 并修改 `secrets.txt` 中对应条目。
- 示例命令：用 NPHardEval 基准评估你的模型！

例如，使用 GPT 4 Turbo 模型（GPT-4-1106-preview）与编辑距离问题（EDP）做评估：

- 零样本（zeroshot）实验，可以用：

```
  cd Close/run
  python run_p_EDP.py gpt-4-1106-preview
```

- 少样本（fewshot）实验，

```
  cd Close/run
  python run_p_EDP_few.py gpt-4-1106-preview self
```

我们目前支持来自同一问题的少样本示例（self），未来可能支持来自其他问题的示例（other）。
