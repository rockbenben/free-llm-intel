# 🤗 PEFT 迎来新的合并方法

Sourab Mangrulkar（smangrul）、Sayak Paul（sayakpaul）

模型合并很快成了推高大语言模型性能上限的 *de-facto* 标准。在 [Open LLM Leaderboard](https://huggingface.co/spaces/HuggingFaceH4/open_llm_leaderboard) 上，我们不断看到合并后的模型登顶。我们自己的 Omar Sanseviero 对模型合并做了一次小冲刺，并[发现](https://twitter.com/osanseviero/status/1745198646876885267)了一些有趣的结论。

到目前为止，典型的模型合并方式是取一组模型把它们合并。[这篇帖子](https://huggingface.co/blog/mlabonne/merge-models)对这个话题做了很好的入门。一般而言，合并多个模型时，我们先下载它们的 checkpoint 再做合并。取决于合并算法和底层模型的大小，这个过程可能相当费内存。`mergekit` 库为处理这一点提供了优化的方式，让这个过程在有限内存下也能应付。

但如果我们想合并的是从***同一个***模型得到的不同"适配器"呢？你可能有四个从同一基座模型得到的不同 LoRA checkpoint，想尝试不同的合并技术。最终你想确定一个最佳合并，为你的任务给出最好的结果。在接近这样的开发者体验时，有几点会变得很明显：

- 处理 LoRA 这样的适配器时，用户常会换入换出不同适配器，甚至把它们组合起来。适配器可以被激活、停用，或完全从内存中换出。因此，我们需要*"就地"做合并*（不同于上面描述的方法），以给用户无缝的体验。
- 不同的适配器对合并可能有不同要求。例如 LoRA 的合并算法未必能同等地套用到 IA3 上。

带着这些考量，我们在 🤗 PEFT 中[上线](https://github.com/huggingface/peft/pull/1364)了面向热门 LoRA 适配器的新合并方法。在这篇帖子里，我们想带你了解可用的方法、帮你上手的代码示例、令人印象深刻的结果，以及我们的未来计划。开始吧 🚀

## 组合/合并 LoRA 适配器的方法

### 拼接（`cat`）

在这个方法里，LoRA 矩阵被拼接。例如，如果我们有 2 个 LoRA 适配器 (A1,B1) (A_1, B_1) (A1​,B1​) 和 (A2,B2) (A_2, B_2) (A2​,B2​)，以及用于这两个适配器加权合并的权重 weight1 weight_1 weight1​ 和 weight2 weight_2 weight2​，那么合并如下发生：

Amerged=concat(weight1∗scaling1∗A1,weight2∗scaling2∗A2,dim=0)A_{merged} = concat(weight_1*scaling_1*A_1, weight_2*scaling_2*A_2, dim=0)Amerged​=concat(weight1​∗scaling1​∗A1​,weight2​∗scaling2​∗A2​,dim=0)

Bmerged=concat(B1,B2,dim=1)B_{merged} = concat(B_1, B_2, dim=1)Bmerged​=concat(B1​,B2​,dim=1)

其中 shape(Amerged)=(rank1+rank2, d))and(shape(Bmerged)=(d, rank1+rank2) shape(A_{merged}) = (rank_1+rank_2,\ d) )\\ and \\( shape(B_{merged}) = (d,\ rank_1+rank_2) shape(Amerged​)=(rank1​+rank2​, d))and(shape(Bmerged​)=(d, rank1​+rank2​)。

现在，这个新合并 LoRA 层的输出，会等同于原来的 2 个 LoRA 处于激活状态、第一个和第二个适配器分别应用 weight1weight_1weight1​ 和 weight2weight_2weight2​。

h=W0x+BmergedAmergedxh = W_0x + B_{merged}A_{merged}xh=W0​x+Bmerged​Amerged​x

这里我们可观察到：

BmergedAmerged=weight1∗scaling1∗B1A1+weight2∗scaling2∗B2A2B_{merged}A_{merged} = weight_1 * scaling_1 * B_1A_1 + weight_2 * scaling_2 * B_2A_2Bmerged​Amerged​=weight1​∗scaling1​∗B1​A1​+weight2​∗scaling2​∗B2​A2​

🧠 这正是 LoRA 适配器的精确加权合并。当你调用 `set_adapters()` 时，通过 Diffusers 的 PEFT 集成也能用，只不过那里不是创建一个新的合并适配器，而是把激活的适配器顺序组合起来，如上面公式右侧所示。用这种方法时，允许参与的 LoRA 适配器有不同的 rank。

### 线性/任务算术（`linear`）

在这个方法里，LoRA 矩阵参与加权求和。这正是 Task arithmetic 论文对任务权重所做的。在任务算术中，先计算任务权重（即微调权重与基座模型权重之差），再对这些任务权重做加权求和。这里考虑的是 delta 权重，是单独的矩阵 AAA 和 BBB，而非它们的乘积 BABABA。此方法只能在所有参与的 LoRA 适配器 rank 相同时应用。

我们看一个例子。考虑 2 个 LoRA 适配器 (A1,B1) (A_1, B_1) (A1​,B1​) 与 (A2,B2) (A_2, B_2) (A2​,B2​)，以及用于加权合并这两个适配器的 weight1 weight_1 weight1​ 和 weight2 weight_2 weight2​，则合并如下发生：

Amerged=sqrt(weight1∗scaling1)∗A1+sqrt(weight2∗scaling2)∗A2A_{merged} = sqrt(weight_1 * scaling_1) * A_1+ sqrt (weight_2 * scaling_2) * A_2Amerged​=sqrt(weight1​∗scaling1​)∗A1​+sqrt(weight2​∗scaling2​)∗A2​

Bmerged=sqrt(weight1∗scaling1)∗B1+sqrt(weight2∗scaling2)∗B2B_{merged} = sqrt(weight_1 * scaling_1) * B_1+ sqrt (weight_2 * scaling_2) * B_2Bmerged​=sqrt(weight1​∗scaling1​)∗B1​+sqrt(weight2​∗scaling2​)∗B2​

更多细节请参考论文：[Editing Models with Task Arithmetic](https://arxiv.org/abs/2212.04089)。

### SVD（`svd`）

此方法不把单独的矩阵 A A A 和 B B B 视为任务权重，而是把它们的乘积 BA BA BA（即 delta 权重）视为任务权重。

让我们接着前面小节例子继续。这里首先按下式计算合并组合的 delta 权重：

deltamerged=weight1∗scaling1∗B1A1+weight2∗scaling2∗B2A2delta_{merged} = weight_1 * scaling_1 * B_1A_1 + weight_2 * scaling_2 * B_2A_2deltamerged​=weight1​∗scaling1​∗B1​A1​+weight2​∗scaling2​∗B2​A2​

得到上面合并的 delta 权重后，应用 SVD（奇异值分解）得到近似的 Amerged_approx A_{merged\_approx} Amerged_approx​ 和 Bmerged_approx B_{merged\_approx} Bmerged_approx​：

🧠 与 `cat` 方法类似，此方法也允许不同 rank 的 LoRA 适配器。此外，你可以为最终合并的 LoRA 适配器选择 rank，默认为参与适配器中的最大 rank。这一方法的局限是执行 SVD 运算需要大量 GPU 显存。

### TIES（`ties`、`ties_svd`）

此方法在 `linear` 和 `svd` 方法基础上，改变从任务权重计算合并适配器的方式，分别得到 `ties` 和 `ties_svd` 方法。在 TIES（TRIM、ELECT SIGN & MERGE）中，先计算任务权重——在我们的例子里非 svd 变体是 LoRA 适配器 A A A、B B B，svd 变体是它们的乘积 BA BA BA。然后，根据指定比例 `density` 剪掉任务权重里最小的值、保留 top-k 值。接着，从参与的、剪枝后的任务权重计算多数符号掩码（majority sign mask），把任务张量乘上用户提供的权重，再基于多数符号掩码做不相交合并（disjoint merge）。对于多数符号掩码的计算，你有两个选项：

- `total` 同时考虑大小和符号来得到多数符号，即把所有对应权重相加；
- `frequency` 只考虑权重符号来获得多数符号，即把所有对应权重的符号相加。

更多细节，参考论文：[TIES-Merging: Resolving Interference When Merging Models](https://arxiv.org/abs/2306.01708)。

### DARE（`dare_linear`、`dare_ties`、`dare_linear_svd`、`dare_ties_svd`）

此方法也在 `linear` 和 `svd` 方法基础上，任务权重为非 svd 变体的 LoRA 适配器 A A A、B B B，以及 svd 变体的乘积 BA BA BA。`DARE` 方法在 [Language Models are Super Mario: Absorbing Abilities from Homologous Models as a Free Lunch](https://arxiv.org/abs/2311.03099) 中提出，先根据指定比例 `1-density` 随机剪掉任务权重的值，再把剪枝后的任务权重按 `1/density` 重新缩放。`DARE` 是一个通用插件，可应用于任何已有的模型合并方法。我们实现了 `DARE` 配合 Linear/Task Arithmetic（`*_linear*`）和 TIES（`*_ties*`）。

对 `DARE` 的 `*_linear*` 变体，我们先使用 `DARE` 随机剪枝任务权重，然后根据用户对参与 LoRA 适配器指定的权重做任务张量的加权求和。

对 `DARE` 的 `*_ties*` 变体，我们先使用 `DARE` 得到剪枝后的任务权重，再采用 `ties` 的最后 2 步，即计算多数符号掩码、并用该掩码做任务权重的不相交合并。

### 幅度剪枝（`magnitude_prune`、`magnitude_prune_svd`）

此方法也在 `linear` 和 `svd` 方法基础上，任务权重为非 svd 变体的 LoRA 适配器 A A A、B B B，以及 svd 变体的乘积 BA BA BA。在这个方法里，先根据指定比例 `density` 剪掉任务权重里最小的值、保留 top-k 值。然后，根据用户对参与 LoRA 适配器指定的权重做任务张量的加权求和。

## 扩展到文本到图像生成

本节展示如何利用这些合并方法做文本到图像生成，使用 🤗 Diffusers。注意 Diffusers [已经依赖 PEFT](https://huggingface.co/docs/diffusers/main/en/tutorials/using_peft_for_inference) 处理所有 LoRA 相关事情，包括训练和推理。然而目前，在 Diffusers pipeline 上调用 [`set_adapters()`](https://huggingface.co/docs/diffusers/main/en/api/loaders/unet#diffusers.loaders.UNet2DConditionLoadersMixin.set_adapters) 时还无法用上新合并方法。因此我们正在与社区[公开讨论](https://github.com/huggingface/diffusers/issues/6892)如何在 Diffusers 内部最地道地原生支持它。

但多亏 PEFT，总有办法绕开这点。我们会用到 [`add_weighted_adapter()`](https://huggingface.co/docs/peft/main/en/package_reference/lora#peft.LoraModel.add_weighted_adapter) 功能。确切说，为组合 ["toy-face" LoRA](https://huggingface.co/CiroN2022/toy-face) 和 ["Pixel-Art" loRA](https://huggingface.co/nerijs/pixel-art-xl) 并尝试不同的合并技术，我们会采取以下步骤：

- 从这些 LoRA checkpoint 得到 `PeftModel`。
- 用 `add_weighted_adapter()` 方法配合我们选定的合并方法，把 `PeftModel` 合并起来。
- 把合并后的模型赋给底层 `DiffusionPipeline` 的对应组件。

我们来看效果。下面各部分展示的所有代码都来自[这个 Colab Notebook](https://colab.research.google.com/github/huggingface/peft/blob/main/examples/multi_adapter_examples/multi_adapter_weighted_inference_diffusers.ipynb)。

由于两个 LoRA checkpoint 都以 [SDXL](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0) UNet 作为基座模型，我们先加载 UNet：

```
from diffusers import UNet2DConditionModel

然后加载实际的 SDXL pipeline 和 LoRA checkpoint。我们从 "CiroN2022/toy-face" LoRA 开始：

```

## 观察

- 在多数场景下，`cat` 方法会给出很好的结果。所以从它开始。但注意，如果你组合很多适配器，合并后的适配器由于拼接可能体积很大，导致 OOM。所以在探索少量适配器时，`cat` 会是个不错的起点。
- 如果你想探索或 `cat` 不奏效，按顺序试 `linear`、`magnitude_prune` 和 `dare_linear`。对 `magnitude_prune` 和 `dare_linear`，我们发现约 0.7-0.8 的较高 `density` 值效果更好。
- 用 `ties` 时，我们发现很多情况下 `majority_sign_method="frequency"` 比 `majority_sign_method="total"`（`total` 目前是默认）表现更好。对 ties，`density` 一个好的默认值是 0.5。你可以在合并适配器后根据自己的观察来向低或向高调。
- `dare_ties` 没能给出好的结果。
- 当处理有不同 rank 的 Stable Diffusion LoRA 适配器时，你可以试 `*svd` 系列方法。注意这些需要更多 GPU 显存，且由于昂贵的 SVD 运算，创建合并适配器需要约 1.5 分钟。如上面的例子所示，在组合 `subject` + `style` LoRA 时 `ties_svd` 给出了好结果。当组合 2 个 `style` 适配器时，带高 `density` 的 `dare_linear` 或配合 `majority_sign_method="frequency"` 的 `ties` 似乎效果更好，如上面的例子。
