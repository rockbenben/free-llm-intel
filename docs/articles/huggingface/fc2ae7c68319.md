[Sentence Transformers](https://sbert.net/) 是一个用于使用与训练 embedding 和 reranker 模型的 Python 库，面向检索增强生成、语义搜索等应用。在我 [上一篇博客](https://huggingface.co/blog/multimodal-sentence-transformers) 里，我介绍了新的多模态能力，演示了如何处理文本、图像、音频和视频的 embedding 与 reranker 模型。在这篇博客里，我会向你展示如何在你自己的数据上 **训练或微调** 这些多模态模型。

作为实际示例，我会走一遍为视觉文档检索（Visual Document Retrieval，VDR）微调 [`Qwen/Qwen3-VL-Embedding-2B`](https://huggingface.co/Qwen/Qwen3-VL-Embedding-2B) 的过程——VDR 就是为一个文本查询检索相关文档页（以图像形式，保留图表、表格和版面）的任务。所得 [`tomaarsen/Qwen3-VL-Embedding-2B-vdr`](https://huggingface.co/tomaarsen/Qwen3-VL-Embedding-2B-vdr) 展示了在你自己的领域上微调能带来多大提升。在我的评估数据上，微调后模型达到 NDCG@10 0.947，而基座模型是 0.888，并且超过了我测过的所有现有 VDR 模型，包括那些体积达它 4 倍的。

[![VDR 模型尺寸 vs NDCG](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/multimodal-sentence-transformers/vdr_plot.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/multimodal-sentence-transformers/vdr_plot.png)

> 如果你是初次接触 Sentence Transformers 里的多模态模型，我建议先读《用 Sentence Transformers 做多模态 Embedding 和 Reranker 模型》。要训练纯文本的 embedding、reranker 或稀疏 embedding 模型，见文末的"相关博客"一节。

## 为什么要微调？

像 [`Qwen/Qwen3-VL-Embedding-2B`](https://huggingface.co/Qwen/Qwen3-VL-Embedding-2B) 这样的通用多模态 embedding 模型，是在多样数据上训练，以便在广泛的语言和任务上都有好表现：图文匹配、视觉问答、文档理解等等。但这种通用性意味着模型很少是任何特定任务的最佳选择。

以视觉文档检索为例：给定一个像"这家公司第三季度的营收是多少？"这样的文本查询，模型必须从上千文档截图里找到最相关的那一张。这要求理解文档版面、图表、表格和文本，这与比如把鞋子照片和产品描述做匹配是很不一样的技能。

通过在领域特定数据上微调，模型可以学到这些专门的模式。在我的实验里，微调把 NDCG@10 从 0.888 提升到 0.947，超过我测过的每一个近期多模态模型，包括那些体积大它 4 倍的。

## 训练组件

训练多模态 Sentence Transformer 模型涉及的组件与训练纯文本模型相同：

- [**模型**](https://huggingface.co/blog/train-multimodal-sentence-transformers#model)：要训练或微调的多模态模型。
- [**数据集**](https://huggingface.co/blog/train-multimodal-sentence-transformers#dataset)：用于训练和评估的数据。
- [**损失函数**](https://huggingface.co/blog/train-multimodal-sentence-transformers#loss-function)：一个量化模型表现并引导优化过程的函数。
- [**训练参数**](https://huggingface.co/blog/train-multimodal-sentence-transformers#training-arguments)（可选）：影响训练表现以及追踪/调试的参数。
- [**评估器**](https://huggingface.co/blog/train-multimodal-sentence-transformers#evaluator)（可选）：在训练前、中、后评估模型的工具。
- [**Trainer**](https://huggingface.co/blog/train-multimodal-sentence-transformers#trainer)：把模型、数据集、损失函数及其他组件汇集到一起用于训练。

多模态训练流水线用的就是与纯文本训练相同的 [`SentenceTransformerTrainer`](https://sbert.net/docs/package_reference/sentence_transformer/trainer.html#sentence_transformers.sentence_transformer.trainer.SentenceTransformerTrainer)。关键差别是你的数据集里除文本外还含有图像（或其他模态），而模型的 processor 会自动处理图像预处理。

让我们逐个组件走一遍，用视觉文档检索（把文本查询匹配到文档截图）作为贯穿始终的例子。

## 模型

最常见的做法是微调一个已有的多模态 embedding 模型，或从一个视觉-语言模型（VLM）检查点起步。[`Transformer`](https://sbert.net/docs/package_reference/base/modules.html#sentence_transformers.base.modules.Transformer) 模块会从模型的 processor 自动检测支持的模态。

要微调一个已有的多模态 embedding 模型（例如已经有 `modules.json` 文件的那个），你可以传入 `processor_kwargs` 和 `model_kwargs` 分别控制预处理和模型加载。`processor_kwargs` 直接传给 [`AutoProcessor.from_pretrained(...)`](https://huggingface.co/docs/transformers/model_doc/auto#transformers.AutoProcessor.from_pretrained)（例如图像分辨率边界：更高的 `max_pixels` 意味着更高质量但更多内存），而 `model_kwargs` 传给相应的 [`AutoModel.from_pretrained(...)`](https://huggingface.co/docs/transformers/model_doc/auto#transformers.AutoModel.from_pretrained) 调用（例如精度、注意力实现）：

```
from sentence_transformers import SentenceTransformer

model = SentenceTransformer(
    "Qwen/Qwen3-VL-Embedding-2B",
    model_kwargs={"attn_implementation": "flash_attention_2", "torch_dtype": "bfloat16"},
    processor_kwargs={"min_pixels": 28 * 28, "max_pixels": 600 * 600},
)
```

你也可以从一个尚未为 embedding 训练过的新 VLM 检查点起步。Sentence Transformers 会尝试识别架构、从 processor 推断支持的模态，并设置好合适的前向方法和池化。如果某个模型的自动检测不完美，可以编辑保存于 `sentence_bert_config.json` 里的配置来调整模态设置、前向方法和输出处理：

```
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("Qwen/Qwen3-VL-2B")
```

两种情况下，[`Transformer`](https://sbert.net/docs/package_reference/base/modules.html#sentence_transformers.base.modules.Transformer) 模块都会检查 processor 以确定有哪些模态可用，并在需要时自动加上 [`Pooling`](https://sbert.net/docs/package_reference/sentence_transformer/modules.html#sentence_transformers.sentence_transformer.modules.Pooling)。你可以验证支持的模态：

```
print(model.modalities)
# ['text', 'image', 'video', 'message']

print(model.supports("image"))
# True
```

替代方案：用 Router 搭建多模态模型

除了用单一 VLM 骨干，你还可以用 [`Router`](https://sbert.net/docs/package_reference/base/modules.html#sentence_transformers.base.modules.Router) 模块为不同模态组合独立的编码器。这让你能把任意已有编码器组合起来，并根据检测到的模态把输入路由到合适的那个：

```
from sentence_transformers import SentenceTransformer
from sentence_transformers.sentence_transformer.modules import Dense, Pooling, Router, Transformer

# Create separate encoders for different modalities
text_encoder = Transformer("sentence-transformers/all-MiniLM-L6-v2")
text_pooling = Pooling(text_encoder.get_embedding_dimension(), pooling_mode="mean")
text_projection = Dense(text_encoder.get_embedding_dimension(), 768)

# SigLIP outputs pooled embeddings directly, so no separate Pooling module is needed
image_encoder = Transformer("google/siglip2-base-patch16-224")

# Route inputs based on modality
router = Router(
    sub_modules={
        "text": [text_encoder, text_pooling, text_projection],
        "image": [image_encoder],
    },
)

model = SentenceTransformer(modules=[router])
```

> 由于基于 Router 的多模态模型每个模态用独立编码器，它们的 embedding 空间最初是不对齐的。需要训练来对齐空间，以获得有意义的跨模态相似度。上面展示的 Dense 投影层有助于把不同编码器的 embedding 映射到一个共享空间。

当你想用轻量、专门的编码器而非一个大型 VLM 时，这种做法很有用。你也可以用 `route_mappings` 把基于 Router 的多模态与基于任务的路由（例如查询与文档用不同编码器）结合。高级路由场景见 [`Router`](https://sbert.net/docs/package_reference/base/modules.html#sentence_transformers.base.modules.Router) 文档。

## 数据集

### 视觉文档检索数据集

在本例中，我使用 [`tomaarsen/llamaindex-vdr-en-train-preprocessed`](https://huggingface.co/datasets/tomaarsen/llamaindex-vdr-en-train-preprocessed) 数据集，它是 [`llamaindex/vdr-multilingual-train`](https://huggingface.co/datasets/llamaindex/vdr-multilingual-train) 预处理过的英文子集。源数据集随 LlamaIndex 的 [《视觉文档检索走向多语言》](https://huggingface.co/blog/vdr-2b-multilingual) 博客一同发布，由约 50 万个多语言图文样本组成，采自公开互联网 PDF，查询是用 VLM（gemini-1.5-pro 和 Qwen2-VL-72B）合成的。我的预处理版本筛选出 53,512 条英文样本，并把每个样本里 16 个基于 ID 的困难负例中的 4 个解析为实际的文档截图图像，因此可以直接用于训练而无需进一步预处理：

```
from datasets import load_dataset

train_dataset = load_dataset("tomaarsen/llamaindex-vdr-en-train-preprocessed", "train", split="train")
train_dataset = train_dataset.select_columns(["query", "image", "negative_0"])
eval_dataset = load_dataset("tomaarsen/llamaindex-vdr-en-train-preprocessed", "eval", split="train")
```

`train` 配置包含前 10,000 条样本，`eval` 配置包含接下来的 300 条样本（也有包含全部 53,512 条样本的 `full` 配置）。训练时我选 `query`、`image` 和 `negative_0`，组成（锚、正、困难负）三元组。加入更多困难负例很可能改善训练信号，但每个额外负例也会增加内存使用和训练时间，所以我用一个。评估时我保留每个查询的全部四个困难负例，以构建一个更有挑战的检索语料（更多见 [评估器](https://huggingface.co/blog/train-multimodal-sentence-transformers#evaluator) 一节）。

### 数据集格式

和纯文本训练一样，数据集格式必须匹配你选的 [损失函数](https://huggingface.co/blog/train-multimodal-sentence-transformers#loss-function)。规则相同：

- 如果你的损失函数需要一个 *标签（Label）*，你的数据集必须有一个名为 **"label"** 或 **"score"** 的列。
- 除 **"label"** 或 **"score"** 以外的所有列都被视为 *输入（Inputs）*。这些列的数量必须与你所选损失函数的有效输入数匹配。除了标签列，列名并不重要，只有顺序重要。

对于多模态数据集，输入可以包含：

- **文本**：字符串。
- **图像**：PIL 图像、文件路径、URL 或 numpy/torch 数组。
- **音频**：文件路径、numpy/torch 数组、含 `"array"` 和 `"sampling_rate"` 键的字典，或（若安装了 `torchcodec`）`torchcodec.AudioDecoder` 实例。
- **视频**：文件路径、numpy/torch 数组、含 `"array"` 和 `"video_metadata"` 键的字典，或（若安装了 `torchcodec`）`torchcodec.VideoDecoder` 实例。
- **多模态字典**：把模态名映射到值的字典，例如 `{"text": ..., "image": ...}`。键必须是 `"text"`、`"image"`、`"audio"` 或 `"video"`。

数据整理器会自动调用 `model.preprocess()`，它检测每个输入的模态并施加合适的预处理。不需要手动分词或图像处理。

> 许多开箱即可配合 Sentence Transformers 使用的 Hugging Face 数据集被打上了 sentence-transformers 标签，便于你在 https://huggingface.co/datasets?other=sentence-transformers 轻松找到它们。

## 损失函数

### CachedMultipleNegativesRankingLoss

本次训练我用 [`CachedMultipleNegativesRankingLoss`](https://sbert.net/docs/package_reference/sentence_transformer/losses.html#cachedmultiplenegativesrankingloss)，这是检索任务的常见选择。它接受（查询，正例）对，外加任意数量的困难负例列，从 0 到 n，只要每个样本有相同数量的负例。训练期间，损失把每个查询与其正例的相似度 *往上* 推、把它与每个负例的相似度 *往下* 压。负例来自两个来源：

- **困难负例**：数据集里显式提供的负例列（在我们的三元组设置里只是 `negative_0`）。
- **批内负例**：同一批次里每个 *其他* 样本的正例和困难负例，被免费复用为这个查询的额外负例。

每个查询的负例越多，训练信号越强，所以更大的批大小直接提升训练质量。除此之外，损失的 "cached" 变体用梯度缓存，让大的有效批大小在 GPU 显存受限时也可行。

`mini_batch_size` 参数控制在缓存前向期间一次处理多少样本。对大型多模态模型，把它设成小值（例如 1）对避免内存溢出、同时不牺牲大有效批大小的好处很重要：

```
from sentence_transformers.sentence_transformer.losses import CachedMultipleNegativesRankingLoss

loss = CachedMultipleNegativesRankingLoss(model, mini_batch_size=1)
```

### MatryoshkaLoss

为了产出在多个维度上都表现良好的 embedding，我用 [`MatryoshkaLoss`](https://sbert.net/docs/package_reference/sentence_transformer/losses.html#matryoshkaloss) 包装基础损失。它训练模型，使把 embedding 截断到更少维度时仍能取得好表现：

```
from sentence_transformers.sentence_transformer.losses import CachedMultipleNegativesRankingLoss, MatryoshkaLoss

loss = CachedMultipleNegativesRankingLoss(model, mini_batch_size=1)
loss = MatryoshkaLoss(model, loss, matryoshka_dims=[2048, 1536, 1024, 512, 256, 128, 64])
```

这对多模态模型尤其有用，因为它们的 embedding 可能很大（Qwen3-VL 是 2048 维）。通过 Matryoshka 训练，你可以在部署时使用截断的 embedding（例如 256 或 128 维），以更快的检索、最小的质量损失。正如我会在 [结果](https://huggingface.co/blog/train-multimodal-sentence-transformers#results) 一节展示的，微调后的模型即使在 512 维也能接近峰值表现。

## 训练参数

[`SentenceTransformerTrainingArguments`](https://sbert.net/docs/package_reference/sentence_transformer/training_args.html#sentencetransformertrainingarguments) 类让你控制训练超参数。以下是 VDR 微调所用的配置：

```
from sentence_transformers.sentence_transformer.training_args import SentenceTransformerTrainingArguments, BatchSamplers

run_name = "Qwen3-VL-Embedding-2B-vdr"
args = SentenceTransformerTrainingArguments(
    # Required parameter:
    output_dir=f"models/{run_name}",
    # Optional training parameters:
    num_train_epochs=1,
    per_device_train_batch_size=64,
    per_device_eval_batch_size=64,
    learning_rate=2e-5,
    warmup_ratio=0.1,
    fp16=False,
    bf16=True,
    batch_sampler=BatchSamplers.NO_DUPLICATES,
    # Optional tracking/debugging parameters:
    eval_strategy="steps",
    eval_steps=0.1,
    save_strategy="steps",
    save_steps=0.1,
    save_total_limit=2,
    logging_steps=0.05,
    run_name=run_name,
)
```

对（多模态）训练有几点要注意：

- `bf16=True`：bfloat16 通常比 float16 更受青睐，因为数值稳定性更好。
- `batch_sampler=BatchSamplers.NO_DUPLICATES`：使用 `MultipleNegativesRankingLoss` 或其缓存变体时，批次里没有重复样本能确保每个批内负例都是真正不同的样本。
- `per_device_train_batch_size=64`：对一个 2B 参数的 VLM 这看起来很大，但 `CachedMultipleNegativesRankingLoss` 配合 `mini_batch_size=1` 通过梯度缓存处理了内存约束。
- `eval_steps`、`save_steps` 和 `logging_steps`：把它们设成一个分数（例如 0.1）意味着评估、保存和日志每 10% 个 epoch 触发一次，便于监控训练进度。

## 评估器

为在训练前、中、后跟踪检索表现，我使用 [`InformationRetrievalEvaluator`](https://sbert.net/docs/package_reference/sentence_transformer/evaluation.html#informationretrievalevaluator)。它计算标准检索指标，如 NDCG@10、MAP 和 Recall@k：

```
from sentence_transformers.sentence_transformer.evaluation import InformationRetrievalEvaluator

# Build the evaluation data from the eval dataset.
# Queries and corpus use integer IDs: query 0's relevant document is corpus 0.
eval_queries = {qid: sample["query"] for qid, sample in enumerate(eval_dataset)}
eval_corpus = {did: sample["image"] for did, sample in enumerate(eval_dataset)}
num_eval = len(eval_dataset)

# Add hard negatives to the corpus with offset IDs (num_eval, 2*num_eval, ...)
# so they don't collide with the positive document IDs (0..num_eval-1).
negative_columns = ["negative_0", "negative_1", "negative_2", "negative_3"]
for neg_idx, neg_col in enumerate(negative_columns):
    for did, sample in enumerate(eval_dataset):
        eval_corpus[num_eval * (neg_idx + 1) + did] = sample[neg_col]

# Each query's relevant document is the positive at the same index
eval_relevant_docs = {idx: [idx] for idx in range(len(eval_dataset))}

eval_evaluator = InformationRetrievalEvaluator(
    queries=eval_queries,
    corpus=eval_corpus,
    relevant_docs=eval_relevant_docs,
    batch_size=1,
    show_progress_bar=True,
    name="vdr-eval-hard",
)
```

评估器接受文本查询、一个图像语料（含困难负例），以及哪些文档与哪些查询相关的映射。注意语料里正例和困难负例的文档截图混在一起，让这次评估很有挑战。用 `batch_size=1` 可防止大型 VLM 评估期间出现内存溢出。

## Trainer

[`SentenceTransformerTrainer`](https://sbert.net/docs/package_reference/sentence_transformer/trainer.html#sentence_transformers.sentence_transformer.trainer.SentenceTransformerTrainer) 把一切汇聚起来。下面是完整训练脚本：

```
from datasets import load_dataset

from sentence_transformers import SentenceTransformer
from sentence_transformers.sentence_transformer.evaluation import InformationRetrievalEvaluator
from sentence_transformers.sentence_transformer.losses import CachedMultipleNegativesRankingLoss, MatryoshkaLoss
from sentence_transformers.sentence_transformer.model_card import SentenceTransformerModelCardData
from sentence_transformers.sentence_transformer.trainer import SentenceTransformerTrainer
from sentence_transformers.sentence_transformer.training_args import (
    BatchSamplers,
    SentenceTransformerTrainingArguments,
)

# 1. Load a model to finetune with (optional) model card data
model = SentenceTransformer(
    "Qwen/Qwen3-VL-Embedding-2B",
    model_card_data=SentenceTransformerModelCardData(
        language="en",
        license="apache-2.0",
        model_name="Qwen3-VL-Embedding-2B model trained on Visual Document Retrieval query-document screenshot pairs",
    ),
    model_kwargs={"attn_implementation": "flash_attention_2", "torch_dtype": "bfloat16"},
    # Control image resolution: lower values save memory, higher values preserve detail
    processor_kwargs={"min_pixels": 28 * 28, "max_pixels": 600 * 600},
)

# 2. Load a dataset to finetune on: (query, positive, negative_0) triplets for training,
# all 4 hard negatives retained for evaluation
train_dataset = load_dataset("tomaarsen/llamaindex-vdr-en-train-preprocessed", "train", split="train")
train_dataset = train_dataset.select_columns(["query", "image", "negative_0"])
eval_dataset = load_dataset("tomaarsen/llamaindex-vdr-en-train-preprocessed", "eval", split="train")

# 3. Define a loss function
loss = CachedMultipleNegativesRankingLoss(model, mini_batch_size=1)
loss = MatryoshkaLoss(model, loss, matryoshka_dims=[2048, 1536, 1024, 512, 256, 128, 64])

# 4. (Optional) Specify training arguments
run_name = "Qwen3-VL-Embedding-2B-vdr"
args = SentenceTransformerTrainingArguments(
    # Required parameter:
    output_dir=f"models/{run_name}",
    # Optional training parameters:
    num_train_epochs=1,
    per_device_train_batch_size=64,
    per_device_eval_batch_size=64,
    learning_rate=2e-5,
    warmup_ratio=0.1,
    fp16=False,  # BF16 is preferred over FP16 for VLMs due to better numerical stability
    bf16=True,  # Set to True if your GPU supports BF16 (most modern GPUs do)
    batch_sampler=BatchSamplers.NO_DUPLICATES,  # MultipleNegativesRankingLoss benefits from no duplicates
    # Optional tracking/debugging parameters:
    eval_strategy="steps",
    eval_steps=0.1,
    save_strategy="steps",
    save_steps=0.1,
    save_total_limit=2,
    logging_steps=0.05,
    run_name=run_name,  # Used in e.g. Trackio if installed
    # report_to=["codecarbon", "trackio"],  # Uncomment to enable logging (pip install codecarbon trackio)
)

# 5. (Optional) Create an evaluator & evaluate the base model
eval_queries = {qid: sample["query"] for qid, sample in enumerate(eval_dataset)}
eval_corpus = {did: sample["image"] for did, sample in enumerate(eval_dataset)}
num_eval = len(eval_dataset)
negative_columns = ["negative_0", "negative_1", "negative_2", "negative_3"]
for neg_idx, neg_col in enumerate(negative_columns):
    for did, sample in enumerate(eval_dataset):
        eval_corpus[num_eval * (neg_idx + 1) + did] = sample[neg_col]
eval_relevant_docs = {idx: [idx] for idx in range(len(eval_dataset))}

eval_evaluator = InformationRetrievalEvaluator(
    queries=eval_queries,
    corpus=eval_corpus,
    relevant_docs=eval_relevant_docs,
    batch_size=1,
    show_progress_bar=True,
    name="vdr-eval-hard",
)
eval_evaluator(model)

# 6. Create a trainer & train
trainer = SentenceTransformerTrainer(
    model=model,
    args=args,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
    loss=loss,
    evaluator=eval_evaluator,
)
trainer.train()

# 7. (Optional) Evaluate at each Matryoshka dimension
eval_evaluator(model)
for dim in [2048, 1536, 1024, 512, 256, 128, 64]:
    dim_evaluator = InformationRetrievalEvaluator(
        queries=eval_queries,
        corpus=eval_corpus,
        relevant_docs=eval_relevant_docs,
        truncate_dim=dim,
        batch_size=1,
        show_progress_bar=True,
        name=f"vdr-eval-hard-{dim}d",
    )
    dim_evaluator(model)

# 8. Save the trained model
model.save_pretrained(f"models/{run_name}/final")

# 9. (Optional) Push it to the Hugging Face Hub
# This pushes to your personal namespace, e.g. {your_username}/Qwen3-VL-Embedding-2B-vdr
model.push_to_hub("Qwen3-VL-Embedding-2B-vdr")
```

训练脚本与纯文本训练脚本几乎一模一样。唯一的区别是：

- 模型加载：我们传入 `model_kwargs` 控制精度和注意力实现，传入 `processor_kwargs` 控制图像分辨率边界。
- 损失函数：我们用 `CachedMultipleNegativesRankingLoss` 配合 `mini_batch_size=1` 来在不爆内存的情况下处理大型 VLM。
- 评估器：评估器在语料里用图像、查询用文本，从而支持跨模态检索评估。

其余一切（Trainer、训练参数、数据集加载）与纯文本训练完全一样。

### Matryoshka 维度 vs NDCG@10

上面的比较用的是完整 2048 维 embedding。得益于 Matryoshka 训练，微调后的模型在截断到更少维度时也表现稳健，让你在部署时权衡 embedding 大小与检索质量：

[![MRL 维度 vs NDCG@10](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/multimodal-sentence-transformers/vdr_plot_mrl.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/multimodal-sentence-transformers/vdr_plot_mrl.png)

> 微调后模型的峰值在完整的 2048 维（0.948），但一直到 512 维（小 4 倍）都保持在峰值的 0.3% 之内，而在 64 维（小 32 倍）仍保留超过峰值的 92%。Matryoshka 训练把最重要的信息集中在靠前的维度里，所以适度截断花费的性能很少。

| --- | --- | --- |
| 2048（完整） | 0.8961 (100%) | 0.9480 (100%) |
| 1536 | 0.8940 (99.8%) | 0.9439 (99.6%) |
| 1024 | 0.8941 (99.8%) | 0.9464 (99.8%) |
| 512 | 0.8760 (97.8%) | 0.9451 (99.7%) |
| 256 | 0.8347 (93.2%) | 0.9372 (98.9%) |

## 训练多模态 Reranker 模型

你也可以用同样的训练基础设施微调多模态 Cross Encoder（reranker）模型。关键差别是使用 [`CrossEncoderTrainer`](https://sbert.net/docs/package_reference/cross_encoder/trainer.html#sentence_transformers.cross_encoder.trainer.CrossEncoderTrainer) 和 Cross Encoder 专属的损失函数。本节给一个简要概览；包含数据准备和评估的完整可运行脚本见 [完整训练示例](https://github.com/huggingface/sentence-transformers/tree/main/examples/cross_encoder/training/multimodal)。

下面是一个基于 [doodles 训练脚本](https://github.com/huggingface/sentence-transformers/blob/main/examples/cross_encoder/training/multimodal/training_doodles_any_to_any.py) 的简化示例，它训练一个把图像与文本描述匹配的 reranker：

```
from sentence_transformers.cross_encoder import CrossEncoder
from sentence_transformers.cross_encoder.losses import BinaryCrossEntropyLoss
from sentence_transformers.cross_encoder.modules import LogitScore, Transformer
from sentence_transformers.cross_encoder.trainer import CrossEncoderTrainer
from sentence_transformers.cross_encoder.training_args import CrossEncoderTrainingArguments

# 1. Build the model from modules
transformer = Transformer(
    "Qwen/Qwen3.5-0.8B",
    transformer_task="any-to-any",
    model_kwargs={"torch_dtype": "bfloat16", "device_map": "auto", "attn_implementation": "flash_attention_2"},
    processing_kwargs={"chat_template": {"add_generation_prompt": True}},
)

# Extend chat template to support "query" and "document" roles
transformer.processor.chat_template = transformer.processor.chat_template.replace(
    'message.role == "user"', 'message.role in ["user", "query", "document"]'
)

# LogitScore: score = log(P("1")) - log(P("0"))
score_head = LogitScore(
    true_token_id=transformer.tokenizer.convert_tokens_to_ids("1"),
    false_token_id=transformer.tokenizer.convert_tokens_to_ids("0"),
)

model = CrossEncoder(
    modules=[transformer, score_head],
    num_labels=1,
    prompts={
        "image_to_text": "Given the image, judge whether the text matches it. Respond with 1 if they match, 0 if they don't.",
        "text_to_image": "Given the text, judge whether the image matches it. Respond with 1 if they match, 0 if they don't.",
    },
)

# 2. Define the loss
loss = BinaryCrossEntropyLoss(model)

# 3. Multi-dataset training with separate directions
trainer = CrossEncoderTrainer(
    model=model,
    args=args,
    train_dataset={"image_to_text": train_image_to_text, "text_to_image": train_text_to_image},
    eval_dataset={"image_to_text": eval_image_to_text, "text_to_image": eval_text_to_image},
    loss=loss,
    evaluator=[image_to_text_evaluator, text_to_image_evaluator],
)
trainer.train()
```

多模态 reranker 有多种有效的架构选择，包括：

- Any-to-Any + LogitScore：用多模态语言模型生成一个 token，然后计算"1"对"0"的对数几率。
- Feature Extraction + Pooling + Dense：只用多模态基座模型，提取最后一个 token 的隐状态，通过 Dense 层投影成分数，避免语言建模头的计算。

两种做法都在 [多模态 cross encoder 训练示例](https://github.com/huggingface/sentence-transformers/tree/main/examples/cross_encoder/training/multimodal) 里有演示。

上面链接的两个脚本把训练数据拆成两个数据集，每个方向一个（图到文和文到图），各自配一个任务专属的提示词，告诉模型在该方向上如何打分。然后每个正对都用随机采样的负例扩展，让损失看到一个匹配与非匹配均衡的混合。
