# 用 🤗 datasets 做图片搜索

🤗 [`datasets`](https://huggingface.co/docs/datasets/) 是一个让访问和共享数据集变得轻松的库。它同样能让高效处理数据变得轻松——包括处理那些放不进内存的数据。

`datasets` 刚发布时，主要跟文本数据联系在一起。不过最近，`datasets` 增强了对音频和图像的支持。具体来说，现在有了一个针对图像的 `datasets` [feature type（特征类型）](https://huggingface.co/docs/datasets/package_reference/main_classes.html?highlight=image#datasets.Image)。此前的一篇[博客文章](https://huggingface.co/blog/fine-tune-vit)展示了如何把 `datasets` 与 🤗 `transformers` 结合来训练一个图像分类模型。在这篇博客里，我们来看看如何把 `datasets` 和另外几个库结合起来，做一个图片搜索应用。

首先，我们安装 `datasets`。由于要处理图像，我们也一并安装 [`pillow`](https://pillow.readthedocs.io/en/stable/)。我们还需要 `sentence_transformers` 和 `faiss`，后面会更详细地介绍它们。我们还安装了 [`rich`](https://github.com/Textualize/rich)——这里只是简短用到它，但它是一个非常实用、值得常备的包——我真的很推荐你进一步探索它！

我们可以看到，传入图像有好几种不同的方式。稍后会再回到这一点。

`datasets` 库有一个非常贴心的特性（除了处理数据、内存映射等功能之外）：你能「免费」得到一些好东西。其中之一就是可以给数据集加上一个 [`faiss`](https://github.com/facebookresearch/faiss) 索引。[`faiss`](https://github.com/facebookresearch/faiss) 是一个「用于高效相似度搜索和稠密向量聚类的库」。

`datasets` 的[文档](https://huggingface.co/docs/datasets)给出了一个用 `faiss` 索引做文本检索的[示例](https://huggingface.co/docs/datasets/faiss_es.html#id1)。在这篇文章里，我们来看看能否对图像做同样的事情。

## 数据集：「数字化图书——被识别为装饰图案的图像。约 1510 年 – 约 1900 年」

这是一个图像数据集，图像取自大英图书馆的一批数字化图书。这些图像来自跨越很长时段、覆盖广泛领域的书籍。图像是借助每本书 OCR 输出中包含的信息提取出来的。因此，我们知道图像出自哪本书，但关于该图像的其他信息却不一定知道，也就是说图像里画的是什么并不确定。

为了帮助克服这一问题，曾有过一些尝试，比如把图像上传到 [flickr](https://www.flickr.com/photos/britishlibrary/albums)。这样人们就能给图像打标签，或把它们归入不同的类别。

也有过[用机器学习](https://blogs.bl.uk/digital-scholarship/2016/11/sherlocknet-update-millions-of-tags-and-thousands-of-captions-added-to-the-bl-flickr-images.html)给这个数据集打标签的项目。这项工作使得按标签搜索成为可能，但我们或许想要一种「更丰富」的搜索能力。在这次特定的实验中，我们在馆藏中一个包含「装饰图案（embellishments）」的子集上开展工作。这个数据集要小一些，因此更适合用来做实验。我们可以从大英图书馆的数据仓库获取完整数据：[https://doi.org/10.21250/db17](https://doi.org/10.21250/db17)。由于完整数据集仍然相当大，你多半会想从一个更小的样本开始。

## 创建我们的数据集

我们的数据集由一个文件夹构成，其中包含若干子目录，子目录里放着图像。这是共享图像数据集的一种相当标准的格式。多亏了一个最近合并的 [pull request](https://github.com/huggingface/datasets/pull/2830)，我们可以直接用 `datasets` 的 `ImageFolder` 加载器来加载这个数据集 🤯

```
from datasets import load_dataset
dataset = load_dataset("imagefolder", data_files="https://zenodo.org/record/6224034/files/embellishments_sample.zip?download=1")
```

来看看我们得到了什么。

在这个特定的数据集中，图像的文件名也包含了关于该图像出自哪本书的一些元数据。我们有几种方式可以获取这些信息。

当我们查看数据集中的某个示例时，会看到 `image` feature 是一个 `PIL.JpegImagePlugin.JpegImageFile`。由于 `PIL.Image` 有一个 filename 属性，我们可以借助访问它来抓取文件名。

## 把所有东西都推到 hub 上！

🤗 生态系统中一件非常棒的事情就是 Hugging Face Hub。我们可以用 Hub 来访问模型和数据集。它通常用于与他人分享成果，但也可以是一个用于处理半成品工作的有用工具。`datasets` 最近加入了一个 `push_to_hub` 方法，让你几乎不费吹灰之力就能把数据集推到 Hub 上。由于它允许你把一个已经完成所有变换等操作的数据集来回传递，这一点真的很有帮助。

目前，我们先把数据集推到 Hub 上，并先保持私有。

根据你运行代码的地方，你可能需要进行身份验证。你可以用 `huggingface-cli login` 命令来做，或者，如果你在 notebook 里运行，可以用 `notebook_login`。

```
from huggingface_hub import notebook_login

notebook_login()
```

```
dataset.push_to_hub('davanstrien/embellishments-sample', private=True)
```

## 创建 embeddings 🕸

我们现在有了一个装着一堆图像的数据集。要开始搭建我们的图片搜索应用，需要对这些图像做嵌入（embed）。尝试这件事的方法有很多种，但其中一种可行的方式是借助 `sentence_transformers` 库使用 CLIP 模型。OpenAI 的 [CLIP 模型](https://openai.com/blog/clip/)为图像和文本学习了一个联合表示，这对我们想做的事情非常有用，因为我们希望输入文本、取回图像。

我们可以用 `SentenceTransformer` 类下载模型。

```
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('clip-ViT-B-32')
```

这个模型接收的输入要么是一张图像要么是一段文本，并返回一个 embedding。我们可以用 `datasets` 的 `map` 方法，用这个模型对所有的图像进行编码。调用 map 时，我们返回一个以 `embeddings` 为键的字典，其中包含模型返回的 embeddings。我们在调用模型时还传入 `device='cuda'`；这确保编码是在 GPU 上进行的。

```
ds_with_embeddings = dataset.map(
    lambda example: {'embeddings':model.encode(example['image'], device='cuda')}, batched=True, batch_size=32)
```

我们可以用 `push_to_hub` 推回 Hub 来「保存」我们的工作。

```
ds_with_embeddings.push_to_hub('davanstrien/embellishments-sample', private=True)
```

如果我们换到另一台机器，可以再次从 Hub 加载我们的工作把它取回来 😃

```
from datasets import load_dataset

ds_with_embeddings = load_dataset("davanstrien/embellishments-sample", use_auth_token=True)
```

我们现在有了一个包含图像 embeddings 的新列。我们可以手动在这些 embeddings 中搜索并与某个输入的 embedding 做比较，但 datasets 提供了一个 `add_faiss_index` 方法。它使用 [faiss](https://github.com/facebookresearch/faiss) 库创建一个用于搜索 embeddings 的高效索引。想了解这个库的更多背景，你可以观看这个 [YouTube 视频](https://www.youtube.com/embed/sKyvsdEv6rk)。

```
ds_with_embeddings['train'].add_faiss_index(column='embeddings')
```

```
Dataset({
        features: ['fname', 'year', 'path', 'image', 'embeddings'],
        num_rows: 10000
    })
```

## 图片搜索

> 注意，这些示例是在完整版本的数据集上生成的，因此你可能得到略有不同的结果。

我们现在已经具备了创建一个简单图片搜索所需的一切。我们可以用之前给图像编码的那个同样的模型，来给一段输入文本编码。它将充当我们要寻找相近示例的提示（prompt）。我们从「a steam engine（一台蒸汽机）」开始。

```
prompt = model.encode("A steam engine")
```

我们可以用 datasets 库里的另一个方法 `get_nearest_examples`，来取得那些 embedding 与我们的输入 prompt embedding 相近的图像。我们可以传入想要取回的结果数量。

```
scores, retrieved_examples = ds_with_embeddings['train'].get_nearest_examples('embeddings', prompt, k=9)
```

我们可以索引到它检索回来的第一个示例：

```
retrieved_examples['image'][0]
```

这并不完全是一台蒸汽机，但也不算一个完全离谱的结果。我们可以把其他结果画出来，看看返回了什么。

```
import matplotlib.pyplot as plt
```

```
plt.figure(figsize=(20, 20))
columns = 3
for i in range(9):
    image = retrieved_examples['image'][i]
    plt.subplot(9 / columns + 1, columns, i + 1)
    plt.imshow(image)
```

其中一些结果看起来跟我们的输入 prompt 相当接近。我们可以把它包装进一个函数，以便更方便地尝试不同的 prompt。

```
def get_image_from_text(text_prompt, number_to_retrieve=9):
    prompt = model.encode(text_prompt)
    scores, retrieved_examples = ds_with_embeddings['train'].get_nearest_examples('embeddings', prompt, k=number_to_retrieve)
    plt.figure(figsize=(20, 20))
    columns = 3
    for i in range(9):
        image = retrieved_examples['image'][i]
        plt.title(text_prompt)
        plt.subplot(9 / columns + 1, columns, i + 1)
        plt.imshow(image)
```

```
get_image_from_text("An illustration of the sun behind a mountain")
```

### 尝试一堆 prompt ✨

现在我们有了一个能取回若干结果的函数，就可以试各种各样的 prompt：

- 其中一些我会选那些属于宽泛「类别」的 prompt，也就是「a musical instrument（一件乐器）」或「an animal（一只动物）」，另一些则是具体的，也就是「a guitar（一把吉他）」。
- 出于兴趣，我还试了一个布尔运算符："An illustration of a cat or a dog（一幅猫或狗的插图）"。
- 最后我试了一点更抽象的东西："an empty abyss（一片空寂的深渊）"

```
prompts = ["A musical instrument", "A guitar", "An animal", "An illustration of a cat or a dog", "an empty abyss"]
```

```
for prompt in prompts:
    get_image_from_text(prompt)
```

我们可以看到，这些结果并不总是对的，但通常是合理的。看起来这种方式对于在本数据集中搜索图像的语义内容就已经很有用了。不过，我们或许得先按捺住就这样把它分享出去的冲动……

## 做一个 Hugging Face Space？🤷🏼

对于这类项目，一个显而易见的下一步就是做一个 Hugging Face [Space](https://huggingface.co/spaces/launch) 演示。我在其他[模型](https://huggingface.co/spaces/BritishLibraryLabs/British-Library-books-genre-classifier-v2)上就是这么做的。

从我们目前到达的这个点出发，把一个 [Gradio 应用搭建起来](https://gradio.app/)的过程相当简单。下面是这个应用的一张截图：

不过，我对立刻把它公开还有点犹豫。看看 CLIP 模型的模型卡（model card），我们可以看到其主要预期用途（primary intended uses）：

> Primary intended uses
> 	
> 
> We primarily imagine the model will be used by researchers to better understand robustness, generalization, and other capabilities, biases, and constraints of computer vision models.
> source

这跟我们在这里感兴趣的东西相当接近。具体来说，我们可能想知道这个模型在应对我们数据集中这类图像（主要来自 19 世纪图书的插图）时表现如何。我们数据集中的图像与训练数据（大概）相当不同。有些图像里还含有文字这一事实，也许会对 CLIP 有帮助，因为它展现出一定的 [OCR 能力](https://openai.com/blog/clip/)。

然而，看看模型卡里所列的超范围使用场景（out-of-scope use cases）：

> Out-of-Scope Use Cases
> 	
> 
> Any deployed use case of the model - whether commercial or not - is currently out of scope. Non-deployed use cases such as image search in  a constrained environment, are also not recommended unless there is thorough in-domain testing of the model with a specific, fixed class  taxonomy. This is because our safety assessment demonstrated a high need for task specific testing especially given the variability of  CLIP's performance with different class taxonomies. This makes untested and unconstrained deployment of the model in any use case > currently potentially harmful.  > source

这表明「部署（deployment）」并不是一个好主意。虽然我拿到的结果很有意思，但我还没有对这个模型进行足够的摸索（也没有做任何更系统的东西来评估它的性能和偏差），还没有信心去「部署」它。另一个需要考虑的因素是目标数据集本身。这些图像取自涵盖各种主题和时期的书籍。其中有大量书籍体现了殖民主义的态度，因此其中一些图像可能以负面的方式呈现某些人群。对于一个允许把任意文本输入编码为 prompt 的工具来说，这可能是一个潜在的危险组合。

或许有绕过这一问题的办法，但这需要更多的思考。

## 结论

虽然我们没有拿得出手的精彩演示，但我们已经看到了如何用 `datasets` 来：

- 把图像加载进新的 `Image` feature type
- 用 `push_to_hub`「保存」我们的工作，并借此在机器/会话之间传递数据
- 为图像创建一个 `faiss` 索引，我们可以用它从文本（或图像）输入中检索图像。
