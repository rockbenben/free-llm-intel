在这篇文章中，我将演示如何用 Gradio 的 reload 模式快速构建一个可用的 AI 应用。不过在开始之前，我想先解释 reload 模式做什么，以及 Gradio 为什么要实现自己的自动重载逻辑。如果你已经熟悉 Gradio、想直接动手，请跳到第三[节](https://huggingface.co/blog/gradio-reload#building-a-document-analyzer-application)。

## Reload 模式做什么？

简单说，它在不重启 Gradio 服务器的情况下加载源文件的最新改动。如果这样说还不直观，请继续读下去。

Gradio 是一个用于创建交互式机器学习应用的流行 Python 库。Gradio 开发者完全用 Python 声明 UI 布局，并添加一些在 UI 事件发生时触发的 Python 逻辑。只要你懂基础 Python，它就很容易上手。还不熟悉 Gradio 的话可以看看这个 [quickstart](https://www.gradio.app/guides/quickstart)。

Gradio 应用的启动方式和其他 Python 脚本一样，运行 `python app.py` 即可（包含 Gradio 代码的文件可以叫任何名字）。这会启动一个 HTTP 服务器，渲染你应用的 UI 并响应用户操作。如果你想改动应用，通常需要停掉服务器（一般按 `Ctrl + C`）、编辑源文件，再重新运行脚本。

开发应用时，反复停止并重启服务器会引入大量延迟。如果有办法自动加载最新代码改动、让你即刻测试新点子，那就更好了。

这正是 Gradio reload 模式做的事。只需把 `python app.py` 换成 `gradio app.py`，就能以 reload 模式启动应用！

## Gradio 为什么要自研重载器？

Gradio 应用由 [uvicorn](https://www.uvicorn.org/) 运行——一个面向 Python Web 框架的异步服务器。Uvicorn 本身已提供[自动重载](https://www.uvicorn.org/)，但 Gradio 出于以下原因实现了自己的逻辑：

- **更快的重载**：Uvicorn 的自动重载会关闭服务器再重启。这比手动操作快，但对开发 Gradio 应用来说还是太慢。Gradio 开发者用 Python 构建 UI，理应一改就看到 UI 变成什么样。这在 JavaScript 生态是标配，但在 Python 里还是新鲜事。
- **选择性重载**：Gradio 应用是 AI 应用，意味着它们通常会把 AI 模型加载进内存，或连接向量数据库这类数据存储。开发期间重启服务器就意味着重载模型或重连数据库，在开发循环之间引入太大延迟。为解决这个问题，Gradio 引入了 `if gr.NO_RELOAD:` 代码块，用来标记不应被重载的代码。只有 Gradio 自己实现重载逻辑才能做到这一点。

下面我就演示如何用 Gradio reload 模式快速构建一个 AI 应用。

## 构建一个文档分析应用

我们的应用将允许用户上传文档图片并就其提问，得到自然语言回答。我们将使用免费的 [Hugging Face Inference API](https://huggingface.co/docs/huggingface_hub/guides/inference)，你应该可以在自己的电脑上跟做，无需 GPU！

第一步，创建一个最简的 `gr.Interface`。把下面的代码写进 `app.py`，并用 `gradio app.py` 以 reload 模式启动：

```
import gradio as gr

demo = gr.Interface(lambda x: x, "text", "text")

if __name__ == "__main__":
    demo.launch()
```

这会创建如下简单 UI。

由于我想让用户在提问的同时上传图像文件，我把输入组件换成 `gr.MultimodalTextbox()`。注意 UI 是如何即时更新的！

[![Simple Interface with MultimodalTextbox](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/gradio-reload/change_to_multimodal_tb.gif)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/gradio-reload/change_to_multimodal_tb.gif)

这个 UI 能用，但我觉得输入框放在输出框下面更好。用 `Blocks` API 就能做到。我还通过加占位文本来自定义输入框，引导用户。

[![Switch to Blocks](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/gradio-reload/switch_to_blocks.gif)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/gradio-reload/switch_to_blocks.gif)

UI 满意后，我开始实现 `chat_fn` 的逻辑。

由于要用 Hugging Face 的 Inference API，我从 `huggingface_hub` 包导入 `InferenceClient`（它随 Gradio 预装）。我用 [`impira/layouylm-document-qa`](https://huggingface.co/impira/layoutlm-document-qa) 模型回答用户问题，然后用 [HuggingFaceH4/zephyr-7b-beta](https://huggingface.co/HuggingFaceH4/zephyr-7b-beta) LLM 给出自然语言响应。

```
from huggingface_hub import InferenceClient

client = InferenceClient()

def chat_fn(multimodal_message):
    question = multimodal_message["text"]
    image = multimodal_message["files"][0]
    
    answer = client.document_question_answering(image=image, question=question, model="impira/layoutlm-document-qa")
    
    answer = [{"answer": a.answer, "confidence": a.score} for a in answer]
   
    user_message = {"role": "user", "content": f"Question: {question}, answer: {answer}"}
   
    message = ""
    for token in client.chat_completion(messages=[user_message],
                           max_tokens=200, 
                           stream=True,
                           model="HuggingFaceH4/zephyr-7b-beta"):
        if token.choices[0].finish_reason is not None:
           continue
        message += token.choices[0].delta.content
        yield message
```

这就是我们运行中的 demo！

[![Demoing our App](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/gradio-reload/demo_1.gif?download=true)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/gradio-reload/demo_1.gif?download=true)

我还将提供一条 system message，让 LLM 保持回答简短、不输出原始置信度分数。为避免每次改动都重建 `InferenceClient`，我把它放进 no-reload 代码块。

```
if gr.NO_RELOAD:
    client = InferenceClient()

system_message = {
    "role": "system",
    "content": """
You are a helpful assistant.
You will be given a question and a set of answers along with a confidence score between 0 and 1 for each answer.
You job is to turn this information into a short, coherent response.

For example:
Question: "Who is being invoiced?", answer: {"answer": "John Doe", "confidence": 0.98}

You should respond with something like:
With a high degree of confidence, I can say John Doe is being invoiced.

Question: "What is the invoice total?", answer: [{"answer": "154.08", "confidence": 0.75}, {"answer": "155", "confidence": 0.25}

You should respond with something like:
I believe the invoice total is $154.08 but it can also be $155.
"""}
```

这是现在的运行效果！system message 确实帮助 bot 的回答保持简短、没有冗长小数。
