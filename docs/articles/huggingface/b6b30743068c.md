Mistral Large 4（又名 Le Chonk）是 Mistral 推出的多模态、多语言 Mixture-of-Experts (MoE) 模型。它以文本和图像为输入，生成文本。它约有 **1T 总参数、49B 激活参数**，上下文窗口为 **1M tokens**。

该模型以两种官方变体发布：

- [FP8](https://huggingface.co/mistralai/Mistral-Large-4-1T-A52B)
- [NVFP4](https://huggingface.co/mistralai/Mistral-Large-4-1T-A52B-NVFP4)

此外还有 [Unsloth](https://huggingface.co/unsloth/Mistral-Large-4-1T-A52B-GGUF) 和 llama.cpp 团队制作的 [GGUF](https://huggingface.co/ggml-org)。它采用 Mistral Ecosystem Open-Weight License 分发（这是 MIT 的衍生许可证，对 model-as-a-service 类产品设定了限制）。

Mistral Large 4 在网络安全、编程 agent 和多模态方面尤其强悍。在这篇文章里，我们来看看这个模型是如何工作的、它的能力、架构以及更多内容！

## Mistral Large 4 有何新变化

[Mistral Large 4](https://huggingface.co/collections/mistralai/mistral-large-4) 把庞大的专家池、稀疏注意力和一个 [Pixtral](https://huggingface.co/docs/transformers/en/model_doc/pixtral) 视觉编码器结合在一起。语言模型为每个 token 选择一小群专家，而它的注意力索引器则选择要关注哪些更早的 token 位置。这是两种不同形式的稀疏：一种选择前馈网络，另一种选择上下文位置。

你可以在 [Mistral Large 4 collection](https://huggingface.co/collections/mistralai/mistral-large-4) 中找到全部 checkpoint。

### 网络安全能力

在 Artificial Analysis Cyber Index 测试——要求模型复现开源软件中的一个真实漏洞、然后给该软件打上补丁——上，Mistral Large 4 得到 82% 分。Mistral 报告说，好几款闭源前沿模型在同一测试上近乎零分，因为它们拒绝尝试这项工作。这对防守方极其重要，因为修复一个漏洞通常要先复现这个漏洞。在 Mistral 的内部测试中，Mistral Large 4 在恶意软件分析、漏洞优先级排序和编写检测规则方面同样有用，而这些并不是模型被显式训练过的任务。

Mistral 主要把该模型定位在防御性安全工作上。漏洞研究和事件响应在模型输入里常常看起来像攻击，因此闭源的过滤器会把它们拦下。依赖某个 API 的团队也可能在处置事件的中途失去访问权限。关键在于，开放权重模型把使用政策和部署都交到用户自己手里。即便如此，模型仍然会拒绝有害请求：在来自 JailbreakBench、StrongREJECT 和 AgentHarm 的网络类 prompt 上，它的平均拒绝率高于任何其他开放权重模型。

对社区建设者来说，Mistral Large 4 这样的开放权重模型解锁了大量下游用例。你可以围绕自己的代码库、崩溃日志和恶意软件样本构建自己的网络安全的系统。例如，你可以用 [TRL 精调](https://huggingface.co/blog/mistral-large4#fine-tuning-with-trl)出更小的模型，训练数据来自 Mistral Large 4 修补你代码库的轨迹。实际上，先复现再修补这类任务使用的是可验证奖励，因此它契合 RL 环境，可以用来进一步用 RL 训练更小的安全模型。开放权重还能让研究者直接测量模型的拒绝行为，而不必依赖服务商的描述。

简而言之，像 ML4 这样的网络能力走向开放，对整个社区是巨大的助力。

## 架构

[![ML4](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/ml4.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/ml4.png)

Mistral Large 4 的文本解码器有 72 层，hidden dimension 为 6,144，64 个注意力头。它的注意力块把 Multi-head Latent Attention (MLA) 与 DeepSeek Sparse Attention (DSA) 索引器结合在一起（GLM 5.3 等其他模型也走这个方向）。MLA 保留压缩的 KV 表示，DSA 则为每个 query 最多挑选 2,048 个 key 位置。

[![Attention](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/attention.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/attention.png)
对每个解码器块，存在 3:1 的 RoPE 与 NoPE 排布，即 3 个解码器层采用 RoPE，每第 4 层使用 NoPE。该模型还在层间共享 KV 状态。
第一个解码器层使用稠密前馈网络。其余 71 层使用 MoE 块，其中 softmax 路由器为每个 token 从 128 个专家里选出 4 个。有一个共享专家始终与被选中的专家一同运行，因此每个 token 总共有 5 个激活专家。

关于 RoPE，Mistral 使用 *LeRope*，那是一种每个频率带一个可学习乘数的 YaRN 缩放 RoPE。

[![Experts](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/experts.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/experts.png)

### 视觉编码器

Mistral Large 4 采用了一个 1.6B 的 Pixtral 编码器。Pixtral 有 30 层，hidden dimension 为 2,048，16 个注意力头。它使用 14 × 14 的 patch，以及空间合并尺寸为 2 的 patch-merge 投影器。编码器流水线见下。

[![Image Encoder](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/img_encoder.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/img_encoder.png)

## 基准测试结果

Mistral Large 4 在编程、网络安全、多模态理解和 agent 工作流上都交出了强劲的基准成绩，这使它成为开放权重生态中极具竞争力的一员。截至 2026 年 10 月 29 日，该模型是 Artificial Analysis Intelligence index 上排名第五的开放权重模型。

在编程方面，ML4 取得 **DeepSWE v1.1 上 61.7%**、**SWE-Atlas-QnA 上 59.4%**、**Terminal-Bench 4 上 28.3%** 的成绩。其综合 **Coding Agent Index 得分 49.8%**，位列 DeepSeek V4 Pro 0813 和 Qwen3.8 Max 之前。

ML4 的编程能力延伸到了知识工作：**AutomationBench 上 59.9%**、**AA-Briefcase 上 1,393 Elo**，这两项基准评估的是业务工作流和长程专业任务。

网络安全是 Mistral Large 4 最突出的能力之一，在真实漏洞评估和安全竞赛任务上都有出色表现。三项基准凸显了该模型的网络能力：

- **Artificial Analysis Cyber Index：** 在这项衡量模型发现并修复软件漏洞能力的独立评测中，ML4 位列**全球模型前五**。
- **漏洞复现与修补：** 它达到 **82%**，是该 index 内这项测试上有报告的最高分。任务要求在开源软件中复现一个真实漏洞并加以修补，同时考察调查与修复两方面的能力。
- **Cybench：** ML4 解出了**取自安全竞赛的 40 道题**中 **93%** 的题目，在动手型安全问题上表现出强劲水准。

Mistral Large 4 还在 Lakera 的 B3 基准上表现出 **93.3% 的攻击抵抗力**，为其抵御 prompt-injection 攻击的稳健性又添一份证据。在基准之外，内部测试在恶意软件分析、漏洞优先级排序和检测规则生成上也给出了可观的结果。

## 推理支持

Mistral Large 4 发布即可获得 transformers、vLLM 和 llama.cpp 的 day-0 支持。GGUF 量化版可从 GGUF 和 [llama.cpp 团队](https://huggingface.co/ggml-org/Mistral-Large-4-1T-A52B-GGUF)处获得。我们提供了通过 Inference Endpoints 远程部署、以及通过 Inference Providers 使用 serverless 推理的选项。

### Transformers

Transformers 实现提供 `AutoModelForMultimodalLM`，由 `AutoProcessor` 准备对话和图像输入。Mistral Large 4 的 reasoning effort 可以取 `low`、`medium`、`high`。默认是 `high`，并且注意推理无法关闭，所以使用 `reasoning_effort`: `none` 仍会按 `high` 执行。

要运行该模型，请先升级 transformers 包

```
pip install --upgrade transformers
```

```
import os
from transformers import AutoProcessor, AutoModelForMultimodalLM, DistributedConfig

distributed_config = DistributedConfig(
    tp_size=int(os.environ["WORLD_SIZE"]),
    ep_size=int(os.environ["WORLD_SIZE"]),
)

model_id = "mistralai/Mistral-Large-4-1T-A52B"
processor = AutoProcessor.from_pretrained(model_id)
model = AutoModelForMultimodalLM.from_pretrained(
    model_id,
    distributed_config=distributed_config,
)

# only text
text_messages = [
    {
        "role": "user",
        "content": "Who are you?"
    }
]

# text + image
multimodal_messages = [
    {
        "role": "user",
        "content": [
            {
                "type": "image",
                "image": "https://huggingface.co/datasets/huggingface/cats-image/resolve/main/cats_image.jpeg",
            },
            {
                "type": "text",
                "text": "How many cats are in the image?",
            },
        ],
    },
]

for messages in [text_messages, multimodal_messages]:
    inputs = processor.apply_chat_template(
        messages,
        add_generation_prompt=True,
        tokenize=True,
        return_dict=True,
        return_tensors="pt",
        reasoning_effort="medium",
    ).to(model.device).to(model.dtype)
    input_len = inputs["input_ids"].shape[-1]

    outputs = model.generate(**inputs, max_new_tokens=100)
    if int(os.environ["RANK"]) == 0:
        print(processor.decode(outputs[0][input_len:], skip_special_tokens=False))
```

你可以把上面的脚本保存为 python 文件 `script.py`，然后运行

```
torchrun --nproc-per-node 8 script.py
```

### vLLM

vLLM 支持高质量的 NVFP4 Mistral Large 4 checkpoint，它的内存占用更小，需要 NVIDIA Blackwell GPU。该模型还自带一个 DSpark drafter，可在 vLLM 中获得进一步加速。按如下方式启动服务器：

```
vllm serve mistralai/Mistral-Large-4-1T-A52B-NVFP4 \
  --config-format mistral \
  --load-format mistral \
  --tensor-parallel-size 8 \
  --decode-context-parallel-size 8 \
  --enable-expert-parallel \
  --dtype bfloat16 \
  --max-model-len 131072 \
  --max-num-seqs 16 \
  --max-num-batched-tokens 2048 \
  --gpu-memory-utilization 0.85 \
  --enable-prefix-caching \
  --enforce-eager \
  --mm_processor_cache_gb 0.0
```

服务器运行起来后，你可以执行下面这条命令。

```
curl -s http://127.0.0.1:8000/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"What is 17*23?"}],"max_tokens":512}'
```

### Llama.cpp

Llama.cpp 和 [Llama App](https://llama.app/) 已经支持 Mistral Large 4。

可以用以下命令安装 Llama App：

```
curl -LsSf https://llama.app/install.sh | sh
```

然后按如下方式启动服务器，在模型 ID 后面指明量化后缀：

```
llama serve -hf ggml-org/Mistral-Large-4-1T-A52B-GGUF:Q2_K
```

[这个仓库](https://huggingface.co/ggml-org/Mistral-Large-4-1T-A52B-GGUF)提供由 FP8 checkpoint 派生的量化版，[这个是 NVFP4 版](https://huggingface.co/ggml-org/Mistral-Large-4-1T-A52B-NVFP4-GGUF)，由官方 NVFP4 仓库转换而来。

服务器启动后，前往 localhost:9931 就能用内置的 WebUI 聊天。在 web UI 里，你可以添加图像进行推理，并调节推理力度。
你也可以按如下方式查询服务器。关于多模态、tool calls 等更多内容，欢迎查阅 [API 参考](https://llama.app/docs/serve)。

```
curl http://localhost:8080/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
        "messages": [
            {"role": "system", "content": "You are a helpful assistant."},
            {"role": "user", "content": "Write a limerick about python exceptions"}

    }'
```

图像与文本的推理可以这样跑。

```
curl -s http://127.0.0.1:8080/v1/chat/completions \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer <your-key>" \
    -d '{
        "model": "muse-spark-open",
        "messages": [
            {
                "role": "user",
                "content": [
                    {
                        "type": "text",
                        "text": "What is in this image?"
                    },
                    {
                        "type": "image_url",
                        "image_url": {
                            "url": "data:image/png;base64,..."
                        }
                    }
                ]
            }
        ],
        "temperature": 0

```

llama.cpp 团队发布了以下量化版本：`IQ2_XXS`、`Q2_K`、`Q4_K_M`、`NVFP4`、`Q8_0`，以及供进一步转换的 `BF16`。2-bit 量化版可以运行在一台配备 512 GB 统一内存的单台 Apple Silicon Ultra 电脑上。其余版本需要分布式推理。你也可以在多台 NVIDIA 或 AMD 显卡上运行。

在单台 M3 Ultra 上运行 `Q2_K`，我们得到约 90 tokens 每秒的 prefill 吞吐和 15 tok/s 的生成速度。在 4 x RTX6000 Pro 上，我们观察到如下结果：

- NVFP4：32K 上下文长度，prefill 130-590 t/s，生成速度约 10 t/s
- IQ2_XXS：800K 上下文长度。短上下文时 prefill 为 500 tok/s、生成为 30 tok/s；但使用长上下文时，性能降到 129 tok/s（prefill）和 3 tok/s（生成）。

## 用 TRL 精调

我们同样提供 day 0 支持：用 TRL 精调 Mistral Large 4。你只需把 `transformers`、`trl` 和 `peft` 升级到最新版本。

```
pip install --upgrade transformers trl peft
```

在下面的例子中，我们训练模型进行多语言思考。精调后的模型将能够按照 system prompt 要求的语言进行推理！

该脚本在由 8 张 B300 组成的节点上运行 FP8 变体。带 Slurm 启动器的完整示例见 [TRL 的 examples](https://github.com/huggingface/trl/tree/main/examples/sft_mistral_large_4)。

```
# torchrun --nproc-per-node 8 sft.py
import os

from datasets import load_dataset
from peft import LoraConfig
from transformers import AutoModelForImageTextToText, DistributedConfig
from trl import SFTConfig, SFTTrainer

world_size = int(os.environ["WORLD_SIZE"])
model_id = "mistralai/Mistral-Large-4-1T-A52B"
model = AutoModelForImageTextToText.from_pretrained(
    model_id,
    distributed_config=DistributedConfig(fsdp_size=world_size, ep_size=world_size),
    dtype="auto",
)

dataset = load_dataset("HuggingFaceH4/Multilingual-Thinking", split="train")
# the assistant turns carry reasoning, so render them in reasoning mode
dataset = dataset.map(lambda x: {"chat_template_kwargs": {"reasoning_effort": "high"}})

trainer = SFTTrainer(
    model=model,
    args=SFTConfig(
        packing=True,
        max_length=4096,
        assistant_only_loss=True,
        learning_rate=1e-4,
        lr_scheduler_type="cosine",
        warmup_steps=10,
    ),
    train_dataset=dataset,
    peft_config=LoraConfig(
        r=16,
        lora_alpha=32,
        target_modules=r".*language_model.*\.(q_proj|kv_a_proj_with_mqa|kv_b_proj|o_proj|gate_proj|up_proj|down_proj)",
    ),
)
trainer.train()
```

## Inference Endpoints

Mistral Large 4 也上线了 Inference Endpoints，提供在 8 x NVIDIA H200 GPU 上开箱即用的部署配方。该配方运行 vLLM，用 tensor 并行和 expert 并行把 FP8 权重切分到全部八张 GPU 上，并利用模型内置的 DSpark draft head 通过投机解码加快生成。它最多可服务 131K tokens 的上下文、一次最多处理 16 个请求，我们观察到的结果如下：

- 单请求：对 1K token 的 prompt，首 token 时间约 0.6 秒，生成速度约 65 tok/s；在 DSpark 草稿被采纳的聊天 prompt 上可达 120–138 tok/s。
- 长 prompt：四个一组、每个 16K token 的 prompt，总 prefill 速度约 4,300 tok/s，首 token 时间 8–9 秒。
- 负载下：在 1,000 段 ShareGPT 对话上，总生成速度约 480 tok/s。

你可以用 `hf` CLI 这样部署：

```
hf endpoints catalog deploy --repo mistralai/Mistral-Large-4-1T-A52B --name mistral-large-4
```

endpoint 运行起来后，用 endpoint URL 和你的 Hugging Face token 即可查询它的 OpenAI 兼容 API。`reasoning_effort` 字段控制模型在作答前推理多少，可设为 `low`、`medium` 或 `high`（默认）。

```
curl "$(hf endpoints describe mistral-large-4 --json | jq -r .status.url)/v1/chat/completions" \
    -H "Authorization: Bearer $(hf auth token 2>/dev/null)" \
    -H "Content-Type: application/json" \
    -d '{
        "model": "mistralai/Mistral-Large-4-1T-A52B",
        "messages": [
            {"role": "user", "content": "Write a limerick about python exceptions"}
        ],
        "reasoning_effort": "medium"
    }'
```

答案在 `choices[0].message.content` 中返回，推理过程在 `choices[0].message.reasoning` 中。该 endpoint 还支持 tool calls、结构化输出、图像输入，并通过标准的 Chat Completions 字段支持流式传输。
