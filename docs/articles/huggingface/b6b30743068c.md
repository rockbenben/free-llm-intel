Mistral Large 4（又名 Le Chonk）是 Mistral 的多模式、多语言、专家混合 (MoE) 模型。它以文本和图像作为输入并生成文本。它大约有 **总共 1T，49B 个活动参数**，以及一个 **1M 代币**的上下文窗口。

该模型以两种官方版本发布：

- [FP8](https://huggingface.co/mistralai/Mistral-Large-4-1T-A52B)
- [NVFP4](https://huggingface.co/mistralai/Mistral-Large-4-1T-A52B-NVFP4)

还有 [Unsloth](https://huggingface.co/unsloth/Mistral-Large-4-1T-A52B-GGUF) 和 llama.cpp 团队创建的 [GGUF](https://huggingface.co/ggml-org)。它根据 Mistral Ecosystem Open-Weight License（麻省理工学院的衍生产品，为模型即服务产品建立了限制）进行分发。

Mistral Large 4 在网络安全、编码代理和多模态方面尤其强大。在这篇文章中，我们将了解该模型的工作原理、功能、架构等等！

## Mistral Large 4 的新增功能

[Mistral Large 4](https://huggingface.co/collections/mistralai/mistral-large-4) 结合了大量具有稀疏注意力的专家和 [Pixtral](https://huggingface.co/docs/transformers/en/model_doc/pixtral) 视觉编码器。语言模型为每个标记选择一小组专家，而其注意力索引器选择要关注的早期标记位置。这是两种不同形式的稀疏性，其中一种选择前馈网络，另一种选择上下文位置。

您可以在[Mistral Large 4合集](https://huggingface.co/collections/mistralai/mistral-large-4)中找到所有检查点。

### 网络安全能力

Mistral Large 4 在人工分析网络指数测试中得分为 82%，该测试要求模型重现开源软件中的真实漏洞，然后修补该软件。Mistral报告说，几个封闭边界模型在同一测试中得分接近零，因为它们拒绝尝试这项工作。这对于防御者来说非常重要，因为修复漏洞通常需要重现漏洞。在 Mistral 的内部测试中，Mistral Large 4 对于恶意软件分析、漏洞优先级划分和编写检测规则也很有用，而该模型并未针对这些进行明确的训练。

Mistral主要定位防御性安全工作的模式。漏洞研究和事件响应通常看起来像模型输入中的攻击，因此闭源过滤器可以阻止它们。依赖 API 的团队也可能在事件发生期间失去访问权限。至关重要的是，开放权重模型将使用策略和部署置于用户的控制之下。也就是说，该模型仍然拒绝有害请求：根据 JailbreakBench、StrongREJECT 和 AgentHarm 的网络提示，其平均拒绝率高于任何其他开放权重模型。

对于社区建设者来说，像 Mistral Large 4 这样的开放权重模型可以释放大量下游用例。您可以围绕代码库、崩溃日志和恶意软件样本构建自己的网络系统。例如，使用 [TRL]，您可以微调 Mistral Large 4 中的较小模型来修补您的代码库。事实上，“重现然后修补”任务使用可验证的奖励，因此它适合 RL 环境，可用于进一步强化 RL 更小的安全模型。开放权重还让研究人员可以直接衡量模型的拒绝行为，而不是依赖提供者的描述。

简而言之，像 ML4 这样的开放网络能力对社区来说是一个巨大的推动。

＃＃ 建筑学

[![ML4](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/ml4.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/ml4.png)

Mistral Large 4 的文本解码器有 72 层，隐藏维度为 6,144，以及 64 个注意力头。它的注意力模块将多头潜在注意力 (MLA) 与 DeepSeek 稀疏注意力 (DSA) 索引器结合起来（GLM 5.3 等其他模型的方向）。 MLA 保留压缩的 KV 表示，DSA 为每个查询选择最多 2,048 个关键位置。

[![注意](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/attention.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/attention.png)
对于每个解码器块，有 3:1 RoPE 到 NoPE 模式，即 3 个解码器层采用 RoPE，每第四层使用 NoPE。该模型还跨层共享 KV 状态。
第一解码器层使用密集前馈网络。其他 71 层使用 MoE 块，其中 softmax 路由器为每个令牌选择 128 个专家中的 4 个。一名共享专家始终与选定的专家一起运行，每个代币总共有 5 名活跃专家。

关于 RoPE，Mistral 使用 *LeRope*，这是一种 YaRN 规模的 RoPE，每个频率都有一个学习乘数。

[![专家](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/experts.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/experts.png)

### 视觉编码器

Mistral Large 4 采用 1.6B Pixtral 编码器。 Pixtral 有 30 层，隐藏维度为 2,048，以及 16 个注意力头。它使用 14 × 14 块和空间合并大小为 2 的块合并投影仪。您可以在下面看到编码器管道。

[![图像编码器](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/img_encoder.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ml4/img_encoder.png)

## 基准测试结果

Mistral Large 4 在编码、网络安全、多模式理解和代理工作流程方面提供强大的基准性能，将其定位为开放权重生态系统的竞争补充。截至 2026 年 10 月 29 日，该模型是人工智能指数第五最佳开放权重模型。

在编码方面，ML4 在 DeepSWE v1.1 上达到 **61.7%**，在 SWE-Atlas-QnA** 上达到 **59.4%，在 Terminal-Bench 4** 上达到 **28.3%。其**编码代理指数综合得分为 49.8%**，领先于 DeepSeek V4 Pro 0813 和 Qwen3.8 Max。

ML4 的编码能力扩展到知识工作，**AutomationBench** 上的得分为 59.9%，**AA-Briefcase 上的 Elo 为 1,393%**，可评估业务工作流程和长期专业任务。

网络安全是 Mistral Large 4 的突出功能之一，在现实世界的漏洞评估和安全竞赛任务中取得了优异的成绩。三个基准凸显了该模型的网络性能：

- **人工分析网络指数：** 在对模型查找和修复软件漏洞能力的独立评估中，ML4 名列**全球前五名模型**。
- **漏洞复制和修补：**达到**82%**，这是该测试中该测试报告的最高分数。该任务需要重现开源软件中的真实漏洞，然后对其进行修补，测试调查和修复。
- **Cybench：** ML4 解决了来自安全竞赛**的一系列 **40 项挑战中的 **93%**，在实际安全问题上展示了强大的性能。

Mistral Large 4 还展示了**在 Lakera 的 B3 基准上具有 93.3% 的攻击抵抗力**，增加了针对即时注入攻击的稳健性证据。除了基准测试之外，内部测试在恶意软件分析、漏洞优先级划分和检测规则生成方面也显示出了可喜的结果。

## 推理支持

Mistral Large 4 附带了对 Transformer、vLLM 和 llama.cpp 的 Day-0 支持。 GGUF 定量可从 GGUF 和 [llama.cpp 团队](https://huggingface.co/ggml-org/Mistral-Large-4-1T-A52B-GGUF) 获得。我们提供使用推理端点进行远程部署的选项，并通过推理提供程序使用无服务器推理。

### 变形金刚

Transformers 实现提供了“AutoModelForMultimodalLM”，以及准备对话和图像输入的“AutoProcessor”。 Mistral Large 4 可以将“低”、“中”、“高”作为推理强度。默认值为“high”，请注意，不能禁用推理，因此使用“reasoning_effort”：“none”仍将使用“high”。

要运行模型，请升级 Transformers 包
```
pip install --upgrade transformers
```

```
import os
from transformers import AutoProcessor, AutoModelForMultimodalLM, DistributedConfig

distributed_config = DistributedConfig(
    tp_size=int(os.environ["WORLD_SIZE"]),
    ep_size=int(os.environ["WORLD_SIZE"]),
)

model_id = "mistralai/Mistral-Large-4-1T-A52B"
processor = AutoProcessor.from_pretrained(model_id)
model = AutoModelForMultimodalLM.from_pretrained(
    model_id,
    distributed_config=distributed_config,
)

# only text
text_messages = [
    {
        "role": "user",
        "content": "Who are you?"
    }
]

# text + image
multimodal_messages = [
    {
        "role": "user",
        "content": [
            {
                "type": "image",
                "image": "https://huggingface.co/datasets/huggingface/cats-image/resolve/main/cats_image.jpeg",
            },
            {
                "type": "text",
                "text": "How many cats are in the image?",
            },
        ],
    },
]

for messages in [text_messages, multimodal_messages]:
    inputs = processor.apply_chat_template(
        messages,
        add_generation_prompt=True,
        tokenize=True,
        return_dict=True,
        return_tensors="pt",
        reasoning_effort="medium",
    ).to(model.device).to(model.dtype)
    input_len = inputs["input_ids"].shape[-1]

    outputs = model.generate(**inputs, max_new_tokens=100)
    if int(os.environ["RANK"]) == 0:
        print(processor.decode(outputs[0][input_len:], skip_special_tokens=False))
```
您可以通过将上面的脚本保存在 python 文件“script.py”中来运行它，然后运行
```
torchrun --nproc-per-node 8 script.py
```
### LLM

vLLM 支持高质量 NVFP4 Mistral Large 4 检查点，该检查点内存占用较小，需要 NVIDIA Blackwell GPU。该模型还配备了 DSpark 绘图仪，可进一步提高 vLLM 的速度。像这样启动服务器：
```
vllm serve mistralai/Mistral-Large-4-1T-A52B-NVFP4 \
  --config-format mistral \
  --load-format mistral \
  --tensor-parallel-size 8 \
  --decode-context-parallel-size 8 \
  --enable-expert-parallel \
  --dtype bfloat16 \
  --max-model-len 131072 \
  --max-num-seqs 16 \
  --max-num-batched-tokens 2048 \
  --gpu-memory-utilization 0.85 \
  --enable-prefix-caching \
  --enforce-eager \
  --mm_processor_cache_gb 0.0
```
服务器启动并运行后，您可以运行以下命令。
```
curl -s http://127.0.0.1:8000/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"What is 17*23?"}],"max_tokens":512}'
```
### 骆驼.cpp

Llama.cpp 和 [Llama App](https://llama.app/) 已支持 Mistral Large 4。

您可以使用以下命令安装 Llama App：
```
curl -LsSf https://llama.app/install.sh | sh
```
然后就可以按如下方式启动服务器，在型号ID后面加上Quant后缀：
```
llama serve -hf ggml-org/Mistral-Large-4-1T-A52B-GGUF:Q2_K
```
[这里是存储库](https://huggingface.co/ggml-org/Mistral-Large-4-1T-A52B-GGUF)，其中包含从 FP8 检查点派生的量化，以及[这是 NVFP4 ](https://huggingface.co/ggml-org/Mistral-Large-4-1T-A52B-NVFP4-GGUF)，从官方 NVFP4 转换而来回购。

服务器启动后，您可以前往 localhost:9931 使用内置 WebUI 聊天。从 Web UI 中，您可以添加用于推理的图像并调整推理杆。
您还可以按如下方式查询服务器。请随意查看 [API 参考](https://llama.app/docs/serve) 了解多模态、工具调用等。
```
curl http://localhost:8080/v1/chat/completions \
    -H "Content-Type: application/json" \
    -d '{
        "messages": [
            {"role": "system", "content": "You are a helpful assistant."},
            {"role": "user", "content": "Write a limerick about python exceptions"}
        ]
    }'
```
您可以按如下方式运行图像文本推理。
```
curl -s http://127.0.0.1:8080/v1/chat/completions \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer <your-key>" \
    -d '{
        "model": "muse-spark-open",
        "messages": [
            {
                "role": "user",
                "content": [
                    {
                        "type": "text",
                        "text": "What is in this image?"
                    },
                    {
                        "type": "image_url",
                        "image_url": {
                            "url": "data:image/png;base64,..."
                        }
                    }
                ]
            }
        ],
        "temperature": 0
    }'
```
llama.cpp 团队提供了以下量化：“IQ2_XXS”、“Q2_K”、“Q4_K_M”、“NVFP4”、“Q8_0”和“BF16”以进行进一步转换。 2 位量化在一台具有 512 GB 统一 RAM 的 Apple Silicon Ultra 计算机上运行。其他的需要分布式推理。您还可以在多个 NVIDIA 或 AMD 卡上运行。

在单个 M3 Ultra 上运行“Q2_K”，我们获得了每秒约 90 个令牌的预填充吞吐量，以及 15 tok/s 的生成速度。在 4 x RTX6000 Pro 上，我们观察到以下结果：

- NVFP4：32K 上下文大小，预填充 130-590 t/s，生成速度 ~10 t/s
- IQ2_XXS：800K 上下文大小。在较短的上下文大小下，预填充速度为 500 tok/s，生成运行速度为 30 tok/s。然而，使用长上下文性能会下降至 129 tok/s（预填充）和 3 tok/s（生成）。

## 使用 TRL 进行微调

我们还提供使用 TRL 微调 Mistral Large 4 的第 0 天支持。您所要做的就是升级到最新版本的“transformers”、“trl”和“peft”。
```
pip install --upgrade transformers trl peft
```
在下面的示例中，我们训练模型来执行多语言思维。微调后的模型将能够用系统提示要求的语言进行推理！

该脚本在 8xB300 节点上的 FP8 变体上运行。带有 Slurm 启动器的完整示例位于 [TRL 示例](https://github.com/huggingface/trl/tree/main/examples/sft_mistral_large_4)。
```
# torchrun --nproc-per-node 8 sft.py
import os

from datasets import load_dataset
from peft import LoraConfig
from transformers import AutoModelForImageTextToText, DistributedConfig
from trl import SFTConfig, SFTTrainer

world_size = int(os.environ["WORLD_SIZE"])
model_id = "mistralai/Mistral-Large-4-1T-A52B"
model = AutoModelForImageTextToText.from_pretrained(
    model_id,
    distributed_config=DistributedConfig(fsdp_size=world_size, ep_size=world_size),
    dtype="auto",
)

dataset = load_dataset("HuggingFaceH4/Multilingual-Thinking", split="train")
# the assistant turns carry reasoning, so render them in reasoning mode
dataset = dataset.map(lambda x: {"chat_template_kwargs": {"reasoning_effort": "high"}})

trainer = SFTTrainer(
    model=model,
    args=SFTConfig(
        packing=True,
        max_length=4096,
        assistant_only_loss=True,
        learning_rate=1e-4,
        lr_scheduler_type="cosine",
        warmup_steps=10,
    ),
    train_dataset=dataset,
    peft_config=LoraConfig(
        r=16,
        lora_alpha=32,
        target_modules=r".*language_model.*\.(q_proj|kv_a_proj_with_mqa|kv_b_proj|o_proj|gate_proj|up_proj|down_proj)",
    ),
)
trainer.train()
```
## 推理端点

Mistral Large 4 还可用于推理端点，并在 8 个 NVIDIA H200 GPU 上提供可立即部署的方案。该配方使用张量和专家并行性在所有八个 GPU 上分配 FP8 权重来运行 vLLM，并使用模型的内置 DSpark 草稿头通过推测解码来更快地生成。它提供多达 131K 个上下文令牌，一次最多处理 16 个请求，我们观察到以下结果：

- 单个请求：对于 1K 令牌提示，第一个令牌的时间约为 0.6 秒，生成速度约为 65 tok/s，在接受 DSpark 草稿的聊天提示上达到 120–138 tok/s。
- 长提示：16K 令牌提示，一次四个，总共以大约 4,300 tok/s 的速度预填充，第一个令牌的时间为 8-9 秒。
- 负载下：1,000 个 ShareGPT 对话的总生成量约为 480 tok/s。

您可以使用 `hf` CLI 进行部署，如下所示：
```
hf endpoints catalog deploy --repo mistralai/Mistral-Large-4-1T-A52B --name mistral-large-4
```
端点运行后，您可以使用端点 URL 和 Hugging Face 令牌查询其 OpenAI 兼容 API。 “reasoning_effort”字段控制模型在回答之前推理的程度，可以设置为“low”、“medium”或“high”（默认）。
```
curl "$(hf endpoints describe mistral-large-4 --json | jq -r .status.url)/v1/chat/completions" \
    -H "Authorization: Bearer $(hf auth token 2>/dev/null)" \
    -H "Content-Type: application/json" \
    -d '{
        "model": "mistralai/Mistral-Large-4-1T-A52B",
        "messages": [
            {"role": "user", "content": "Write a limerick about python exceptions"}
        ],
        "reasoning_effort": "medium"
    }'
```
答案在 `choices[0].message.content` 中返回，推理在 `choices[0].message.reasoning` 中。该端点还支持工具调用、结构化输出、图像输入以及通过标准聊天完成字段进行流式传输。
