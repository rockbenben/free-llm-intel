# 在 Hugging Face 上用 🤗 Transformers 微调 Wav2Vec2，实现英文 ASR

Patrick von Platen（patrickvonplaten）

Wav2Vec2 是一个用于自动语音识别（ASR）的预训练模型，由 Alexei Baevski、Michael Auli 和 Alex Conneau 于 [2020 年 9 月](https://ai.facebook.com/blog/wav2vec-20-learning-the-structure-of-speech-from-raw-audio/)发布。

使用一种新颖的对比预训练目标，Wav2Vec2 从超过 50,000 小时的无标注语音中学到强大的语音表示。类似于 [BERT 的掩码语言建模](http://jalammar.github.io/illustrated-bert/)，模型通过在送入 transformer 网络之前随机掩码特征向量来学习上下文化的语音表示。

[![wav2vec2\_structure](https://raw.githubusercontent.com/patrickvonplaten/scientific_images/master/wav2vec2.png)](https://raw.githubusercontent.com/patrickvonplaten/scientific_images/master/wav2vec2.png)

首次有证据表明，先预训练、再在极少标注语音数据上微调，可以达到媲美最先进 ASR 系统的结果。仅用少至 10 分钟的标注数据，Wav2Vec2 在 [LibriSpeech](https://huggingface.co/datasets/librispeech_asr) 干净测试集上的词错误率（WER）就能低于 5%——*cf.* [论文](https://arxiv.org/pdf/2006.11477.pdf)表 9。

在本文里，我们会详尽解释如何把 Wav2Vec2 的预训练 checkpoint 微调应用到任何英文 ASR 数据集。注意，本文微调 Wav2Vec2 时不使用语言模型。把 Wav2Vec2 作为端到端 ASR 系统、不带语言模型来用要简单得多，而且已有证据表明一个独立的 Wav2Vec2 声学模型就能取得亮眼结果。为演示目的，我们在相对小的 [Timit](https://huggingface.co/datasets/timit_asr) 数据集上微调"base"尺寸的[预训练 checkpoint](https://huggingface.co/facebook/wav2vec2-base)，该数据集只有 5 小时训练数据。

Wav2Vec2 用连接时序分类（CTC）来微调。CTC 是一种用于训练神经网络处理序列到序列问题的算法，主要用于自动语音识别和手写识别。

我强烈推荐阅读 Awni Hannun 写得非常好的那篇 [Sequence Modeling with CTC (2017)](https://distill.pub/2017/ctc/) 博客。

1{}^11 Timit 通常用音素错误率（PER）评估，但 ASR 里最常用得多的指标是词错误率（WER）。为了让本文尽可能通用，我们决定用 WER 来评估模型。

## 准备数据、分词器、特征提取器

ASR 模型把语音转写为文本，这意味着我们既需要一个把语音信号处理成模型输入格式（*e.g.* 特征向量）的特征提取器，也需要一个把模型输出格式处理成文本的分词器。

在 🤗 Transformers 里，Wav2Vec2 模型因此同时配有叫 [Wav2Vec2CTCTokenizer](https://huggingface.co/transformers/master/model_doc/wav2vec2.html#wav2vec2ctctokenizer) 的分词器和叫 [Wav2Vec2FeatureExtractor](https://huggingface.co/transformers/master/model_doc/wav2vec2.html#wav2vec2featureextractor) 的特征提取器。

我们先创建负责解码模型预测的分词器。

### 创建 Wav2Vec2CTCTokenizer

[预训练的 Wav2Vec2 checkpoint](https://huggingface.co/facebook/wav2vec2-base)把语音信号映射为一串上下文表示，如上图所示。一个微调后的 Wav2Vec2 checkpoint 需要把这串上下文表示映射为对应的转写文本，因此要在 transformer 块（图中黄色部分）之上加一个线性层。这一线性层用来把每个上下文表示分类到一个 token 类别，就像*BERT* 预训练之后在其嵌入之上加一个线性层做进一步分类一样——*cf.* 本[博客](https://huggingface.co/blog/warm-starting-encoder-decoder)的"BERT"一节。

该层的输出维度对应词表中的 token 数量，这**不**取决于 Wav2Vec2 的预训练任务，而只取决于用于微调的标注数据集。所以第一步，我们来看 Timit，并基于数据集的转写定义一个词表。

```
timit = timit.map(remove_special_characters)
```

我们写一个映射函数，把所有转写拼接成一长串转写，然后把字符串转换成一个字符集合。重要的是给 `map(...)` 函数传入 `batched=True` 参数，这样映射函数才能一次性访问所有转写。

```
def extract_all_chars(batch):
  all_text = " ".join(batch["text"])
  vocab = list(set(all_text))
  return {"vocab": [vocab], "all_text": [all_text]}

vocabs = timit.map(extract_all_chars, batched=True, batch_size=-1, keep_in_memory=True, remove_columns=timit.column_names["train"])
```

```
vocab_dict["|"] = vocab_dict[" "]
```

### 创建 Wav2Vec2 特征提取器

语音是连续信号，要交给计算机处理，先得离散化，这通常叫**采样**。采样率在此起着重要作用，它定义了每秒测量语音信号的多少个数据点。因此，用更高采样率采样会得到对*真实*语音信号更好的近似，但每秒也需要更多的值。

一个预训练 checkpoint 期望它的输入数据大致从与它训练时所用的数据相同的分布中采样。同一个语音信号在两种不同采样率下分布会很不同，*e.g.* 把采样率翻倍会让数据点变成长度两倍。因此，在微调一个 ASR 模型的预训练 checkpoint 之前，务必要确认用于预训练模型的数据采样率与用于微调的数据集采样率一致。

Wav2Vec2 在 [LibriSpeech](https://huggingface.co/datasets/librispeech_asr) 和 LibriVox 的音频数据上预训练，二者都以 16kHz 采样。我们用于微调的数据集 [Timit]() 幸运地也是以 16kHz 采样。如果微调数据集的采样率低于或高于 16kHz，我们就得先对语音信号做升采样或降采样，以匹配预训练所用数据的采样率。

一个 Wav2Vec2 特征提取器对象实例化需要以下参数：

- `feature_size`：语音模型以特征向量序列作为输入。序列的长度显然会变，但特征尺寸不该变。在 Wav2Vec2 的情形，特征尺寸为 1，因为模型是在原始语音信号上训练的 2{}^22。
- `sampling_rate`：模型训练所用的采样率。
- `padding_value`：对于批量推理，较短的输入需要用某个特定值做 padding。
- `do_normalize`：输入是否应做*零均值单位方差*归一化。通常语音模型在归一化输入时表现更好。
- `return_attention_mask`：模型是否应在批量推理中使用 `attention_mask`。一般来说，模型应当**始终**使用 `attention_mask` 来掩码 padding token。然而，由于 `Wav2Vec2` 的"base" checkpoint 一个非常具体的设计选择，不使用 `attention_mask` 反而能得到更好的结果。这**不**推荐用于其他语音模型。更多信息可参考[这个](https://github.com/pytorch/fairseq/issues/3227) issue。**重要**：如果你想用本文微调 [large-lv60](https://huggingface.co/facebook/wav2vec2-large-lv60)，该参数应设为 `True`。

```
from transformers import Wav2Vec2FeatureExtractor

feature_extractor = Wav2Vec2FeatureExtractor(feature_size=1, sampling_rate=16000, padding_value=0.0, do_normalize=True, return_attention_mask=False)
```

好，Wav2Vec2 的特征提取流程至此完整定义了！

为了让 Wav2Vec2 的用法尽可能对使用者友好，特征提取器和分词器被*封装*进单个 `Wav2Vec2Processor` 类，这样只需要一个 `model` 和一个 `processor` 对象。

```
from transformers import Wav2Vec2Processor

processor = Wav2Vec2Processor(feature_extractor=feature_extractor, tokenizer=tokenizer)
```

最后，我们可以把数据集处理成模型训练所期望的格式。我们会用到 `map(...)` 函数。

首先，通过简单调用 `batch["audio"]` 来加载并重采样音频数据。其次，从加载的音频文件中提取 `input_values`。在我们的情形里，`Wav2Vec2Processor` 只做归一化。但对其他语音模型，这一步可以包含更复杂的特征提取，例如 [Log-Mel 特征提取](https://en.wikipedia.org/wiki/Mel-frequency_cepstrum)。第三，我们把转写编码为 label id。

**注意**：这个映射函数是 `Wav2Vec2Processor` 类应如何使用的一个好例子。在"正常"语境下，调用 `processor(...)` 会被重定向到 `Wav2Vec2FeatureExtractor` 的调用方法。而当把 processor 包进 `as_target_processor` 上下文时，同一个方法会被重定向到 `Wav2Vec2CTCTokenizer` 的调用方法。更多信息请查看[文档](https://huggingface.co/transformers/master/model_doc/wav2vec2.html#transformers.Wav2Vec2Processor.__call__)。

```
def prepare_dataset(batch):
    audio = batch["audio"]

    # batched output is "un-batched" to ensure mapping is correct
    batch["input_values"] = processor(audio["array"], sampling_rate=audio["sampling_rate"]).input_values[0]
    
    with processor.as_target_processor():
        batch["labels"] = processor(batch["text"]).input_ids
    return batch
```

我们把数据准备函数应用到所有样本。

```
timit = timit.map(prepare_dataset, remove_columns=timit.column_names["train"], num_proc=4)
```

## 训练与评估

数据已经处理好，我们可以开始搭建训练流程。我们会用到 🤗 的 [Trainer](https://huggingface.co/transformers/master/main_classes/trainer.html?highlight=trainer)，为此我们本质上需要做以下几件事：

- 定义一个数据整理器（data collator）。与大多数 NLP 模型不同，Wav2Vec2 的输入长度远大于输出长度。*E.g.*，一个输入长度为 50000 的样本，其输出长度不超过 100。鉴于输入规模很大，动态地 padding 训练批次要高效得多，意思是每个训练样本只 padding 到其所在批次里最长的那个样本，而不是整体最长的那个样本。因此，微调 Wav2Vec2 需要一个特殊的 padding 数据整理器，我们在下面定义。
- 评估指标。在训练期间，模型应在词错误率上被评估。我们应相应地定义一个 `compute_metrics` 函数。
- 加载一个预训练 checkpoint。我们需要加载一个预训练 checkpoint 并正确地为训练做配置。
- 定义训练配置。

微调模型之后，我们会在测试数据上正确评估它，验证它确实学会了正确转写语音。

### 配置 Trainer

我们先从定义数据整理器开始。数据整理器的代码抄自[这个示例](https://github.com/huggingface/transformers/blob/7e61d56a45c19284cfda0cee8995fb552f6b1f4e/examples/pytorch/speech-recognition/run_speech_recognition_ctc.py#L219)。

不过多展开细节，与常见数据整理器不同，这个数据整理器对 `input_values` 和 `labels` 的处理方式不同，因此对它们应用各自的 padding 函数（再次利用 Wav2Vec2 的上下文管理器）。这是必需的，因为在语音里输入和输出属于不同的模态，意味着它们不应被同一个 padding 函数处理。与常见数据整理器类似，labels 里的 padding token 被替换为 `-100`，这样计算损失时这些 token **不**被计入。

```
import torch

from dataclasses import dataclass, field
from typing import Any, Dict, List, Optional, Union

@dataclass
class DataCollatorCTCWithPadding:
    """
    Data collator that will dynamically pad the inputs received.
    Args:
        processor (:class:`~transformers.Wav2Vec2Processor`)
            The processor used for processing the data.
        padding (:obj:`bool`, :obj:`str` or :class:`~transformers.tokenization_utils_base.PaddingStrategy`, `optional`, defaults to :obj:`True`):
            Select a strategy to pad the returned sequences (according to the model's padding side and padding index)
            among:
            * :obj:`True` or :obj:`'longest'`: Pad to the longest sequence in the batch (or no padding if only a single
              sequence if provided).
            * :obj:`'max_length'`: Pad to a maximum length specified with the argument :obj:`max_length` or to the
              maximum acceptable input length for the model if that argument is not provided.
            * :obj:`False` or :obj:`'do_not_pad'` (default): No padding (i.e., can output a batch with sequences of
              different lengths).
        max_length (:obj:`int`, `optional`):
            Maximum length of the ``input_values`` of the returned list and optionally padding length (see above).
        max_length_labels (:obj:`int`, `optional`):
            Maximum length of the ``labels`` returned list and optionally padding length (see above).
        pad_to_multiple_of (:obj:`int`, `optional`):
            If set will pad the sequence to a multiple of the provided value.
            This is especially useful to enable the use of Tensor Cores on NVIDIA hardware with compute capability >=
            7.5 (Volta).
    """

    processor: Wav2Vec2Processor
    padding: Union[bool, str] = True
    max_length: Optional[int] = None
    max_length_labels: Optional[int] = None
    pad_to_multiple_of: Optional[int] = None
    pad_to_multiple_of_labels: Optional[int] = None

    def __call__(self, features: List[Dict[str, Union[List[int], torch.Tensor]]]) -> Dict[str, torch.Tensor]:
        # split inputs and labels since they have to be of different lengths and need
        # different padding methods
        input_features = [{"input_values": feature["input_values"]} for feature in features]
        label_features = [{"input_ids": feature["labels"]} for feature in features]

        batch = self.processor.pad(
            input_features,
            padding=self.padding,
            max_length=self.max_length,
            pad_to_multiple_of=self.pad_to_multiple_of,
            return_tensors="pt",
        )
        with self.processor.as_target_processor():
            labels_batch = self.processor.pad(
                label_features,
                padding=self.padding,
                max_length=self.max_length_labels,
                pad_to_multiple_of=self.pad_to_multiple_of_labels,
                return_tensors="pt",
            )

        # replace padding with -100 to ignore loss correctly
        labels = labels_batch["input_ids"].masked_fill(labels_batch.attention_mask.ne(1), -100)

        batch["labels"] = labels

        return batch
```


接下来定义评估指标。如前所述，ASR 里的主要指标是词错误率（WER），因此本文也用它。

```
wer_metric = load_metric("wer")
```

模型会返回一串 logit 向量：

y1,…,ym \mathbf{y}_1, \ldots, \mathbf{y}_m y1​,…,ym​，

其中 y1=fθ(x1,…,xn)[0]\mathbf{y}_1 = f_{\theta}(x_1, \ldots, x_n)[0]y1​=fθ​(x1​,…,xn​)[0]，且 n>>mn >> mn>>m。

一个 logit 向量 y1 \mathbf{y}_1 y1​ 包含我们先前定义的词表中每个词的 log-odds，因此 len(yi)=\text{len}(\mathbf{y}_i) =len(yi​)= `config.vocab_size`。我们感兴趣的是模型最可能的预测，于是对 logits 取 `argmax(...)`。同时，我们通过对编码后的 label 把 `-100` 替换为 `pad_token_id` 并解码 id，同时在解码时确保按 CTC 风格不把连续的 token **不**分组为同一个 token，从而把它们转回原始字符串 1{}^11。

```
def compute_metrics(pred):
    pred_logits = pred.predictions
    pred_ids = np.argmax(pred_logits, axis=-1)

    pred.label_ids[pred.label_ids == -100] = processor.tokenizer.pad_token_id

    pred_str = processor.batch_decode(pred_ids)
    # we do not want to group tokens when computing the metrics
    label_str = processor.batch_decode(pred.label_ids, group_tokens=False)

    wer = wer_metric.compute(predictions=pred_str, references=label_str)

    return {"wer": wer}
```

1{}^11 为了让模型不受说话人语速影响，在 CTC 里，连续的相同 token 会被简单地分组为单个 token。然而，在解码时编码后的 label 不应被分组，因为它们并不对应模型的预测 token，这就是为什么必须传入 `group_tokens=False` 参数。如果我们不传这个参数，像 `"hello"` 这样的词会被错误地编码并解码为 `"helo"`。2{}^22 blank token 让模型能够预测像 `"hello"` 这样的词——办法是迫使它在两个 l 之间插入 blank token。我们模型一个符合 CTC 的 `"hello"` 预测会是 `[PAD] [PAD] "h" "e" "e" "l" "l" [PAD] "l" "o" "o" [PAD]`。

```
def map_to_result(batch):
  with torch.no_grad():
    input_values = torch.tensor(batch["input_values"], device="cuda").unsqueeze(0)
    logits = model(input_values).logits

  pred_ids = torch.argmax(logits, dim=-1)
  batch["pred_str"] = processor.batch_decode(pred_ids)[0]
  batch["text"] = processor.decode(batch["labels"], group_tokens=False)
  
  return batch

results = timit["test"].map(map_to_result, remove_columns=timit["test"].column_names)
```
