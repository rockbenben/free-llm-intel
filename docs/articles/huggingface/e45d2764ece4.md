*指令微调（instruction tuning）* 是一种微调方法，让大语言模型（LLM）具备遵循自然人类指令的能力。但在编程任务上，多数模型的调校数据要么来自人工撰写的指令（成本极高），要么由超大专有 LLM 生成（未必被许可使用）。**我们推出 [StarCoder2-15B-Instruct-v0.1](https://huggingface.co/bigcode/starcoder2-15b-instruct-v0.1)——第一个完全自对齐的代码 LLM，训练管线完全透明且许可宽松**。我们的开源管线用 StarCoder2-15B 自己生成数千条指令-回答对，然后用这些数据微调 StarCoder-15B 本身，全程不依赖任何人工标注，也不从巨型专有 LLM 蒸馏数据。

**StarCoder2-15B-Instruct 在 HumanEval 上拿到 72.6 分，甚至超过了 CodeLlama-70B-Instruct 的 72.0！** 在 LiveCodeBench 上的进一步评测显示，这个自对齐模型甚至比用 GPT-4 蒸馏数据训练的同尺寸模型更好——这暗示 LLM 从自身分布内的数据学习，可能比从教师 LLM 转移过来的偏移分布学习更有效。

## 方法

我们的数据生成管线主要由三步组成：

- 从 [The Stack v1](https://huggingface.co/datasets/bigcode/the-stack)（一个体量巨大、许可宽松的源码语料库）中提取高质量、多样化的种子函数。
- 围绕种子函数中体现的不同代码概念（如数据反序列化、列表拼接、递归）构造多样化且贴近真实的代码指令。
- 对每条指令，通过执行引导的自我验证生成高质量回答。

下面各节逐一展开。

### 收集种子代码片段

要充分发挥代码模型的指令遵循能力，模型应当接触过覆盖广泛编程原则与实践的多样化指令。受 [OSS-Instruct](https://github.com/ise-uiuc/magicoder) 启发，我们进一步从开源代码片段中挖掘代码概念来促进多样性，具体来说是从 The Stack V1 中提取结构良好的种子 Python 函数。

种子数据集方面，我们仔细提取 The Stack V1 中所有带 docstring 的 Python 函数，用 [autoimport](https://lyz-code.github.io/autoimport/) 推断所需依赖，并对所有函数应用以下过滤规则：

- **类型检查**：使用 [Pyright](https://github.com/microsoft/pyright) 启发式类型检查器，移除所有产生静态错误的函数（这些函数可能有误）。
- **去污染（Decontamination）**：检测并移除我们评测所用基准的题目，对解答和提示词都使用精确字符串匹配。
- **Docstring 质量过滤**：用 StarCoder2-15B 作为评委去掉文档质量差的函数。我们给基座模型 7 个少样本示例，要求它回答 "Yes" 或 "No" 来决定是否保留该条目。
- **近重复去重**：使用 MinHash 和局部敏感哈希，Jaccard 相似度阈值 0.5，过滤数据集中的重复种子函数。这套流程与应用于 StarCoder 训练数据的[同一套流程](https://huggingface.co/blog/dedup)相同。

这套过滤管线最终得到一个 25 万个 Python 函数的数据集，从 500 万个带 docstring 的函数中筛出。整个过程深受 [MultiPL-T](https://huggingface.co/datasets/nuprl/MultiPL-T) 数据采集管线的启发。

### Self-OSS-Instruct

收集完种子函数后，我们用 Self-OSS-Instruct 生成多样化指令。具体地说，借助上下文学习（in-context learning）让基座 StarCoder2-15B 从给定种子代码片段自行生成指令。该过程使用 16 个精心设计的少样本示例，每个都按 *(snippet, concepts, instruction)* 格式组织。指令生成分两步：

- **概念提取：** 对每个种子函数，提示 StarCoder2-15B 产出函数中包含的代码概念列表。代码概念指编程中基础的原则与技巧，例如*模式匹配*和*数据类型转换*，是开发者必须掌握的东西。
- **指令生成：** 随后提示 StarCoder2-15B 基于识别出的代码概念自行生成一道编程任务。

最终这一过程生成了 23.8 万条指令。

### 回答自我验证

有了 Self-OSS-Instruct 生成的指令，下一步是为每条指令匹配高质量回答。以往的做法通常依赖从更强教师模型（如 GPT-4）蒸馏回答——期望其质量更高。但蒸馏专有模型会导致许可不宽松的问题，而且更强的教师模型未必总能拿到。更重要的是，教师模型也会出错，教师与学生之间的分布差异甚至可能有害。

我们提出的方案是显式对齐 StarCoder2-15B：让模型在产出与自然语言交织的回答之后，明确生成用于自我验证的测试。这个过程很像开发者给自己的代码实现写测试。具体来说，对每条指令，StarCoder2-15B 生成 10 个 *(NL Response, Test)* 格式的样本，我们过滤掉在沙箱环境中被测试执行判定不通过的样本，然后对每条指令随机挑选一个通过的回答进入最终 SFT 数据集。总共对 23.8 万条指令以温度 0.7 生成了 240 万（10 x 238k）条回答，其中 50 万通过执行测试。去重后剩下 5 万条指令，每条配一个随机通过的回答，这就是最终的 SFT 数据集。

## 评测

在流行且严格的 [EvalPlus](https://github.com/evalplus/evalplus) 基准上，StarCoder2-15B-Instruct 是同尺寸宽松许可 LLM 中的最强者：超过大得多的 Grok-1、Command-R+、DBRX，与 Snowflake Arctic 480B、Mixtral-8x22B-Instruct 也基本持平。据我们所知，StarCoder2-15B-Instruct 是第一个以完全透明、宽松许可的管线达到 70+ HumanEval 分的代码 LLM。它大幅超越 OctoCoder——此前透明管线宽松许可代码 LLM 的最先进水平。

即便与许可受限的强大小模型相比，StarCoder2-15B-Instruct 依然有竞争力：超过 Gemini Pro 和 Mistral Large，与 CodeLlama-70B-Instruct 相当。另外，完全用自生成数据训练的 StarCoder2-15B-Instruct 与 OpenCodeInterpreter-SC2-15B 十分接近——后者是在 GPT-3.5/4 蒸馏数据上微调 StarCoder2-15B 得到的。

除了 EvalPlus，我们还在 [LiveCodeBench](https://livecodebench.github.io)（收录 2023-09-01 之后创建的新编程题）以及面向数据科学程序的 [DS-1000](https://ds1000-code-gen.github.io) 上，评测了尺寸相近或更小的最先进开源模型。在 LiveCodeBench 上，StarCoder2-15B-Instruct 取得被测模型中的最佳成绩，并持续超越蒸馏 GPT-4 数据的 OpenCodeInterpreter-SC2-15B。在 DS-1000 上，尽管数据科学相关训练数据很少，StarCoder2-15B-Instruct 仍保持竞争力。

## 结论

StarCoder2-15B-Instruct-v0.1 首次表明：不依赖 GPT-4 这样更强的教师模型，同样能造出强大的指令微调代码模型。这个模型证明了自对齐——模型用自身生成的内容来学习——在代码领域同样有效。它完全透明、允许蒸馏，这使它区别于 Snowflake-Arctic、Grok-1、Mixtral-8x22B、DBRX、CommandR+ 等其他更大但虽宽松却不透明的模型。我们已经把数据集和整个管线（包括数据整理与训练）完全开源。希望这项开创性工作能为该领域带来更多未来研究与开发。
