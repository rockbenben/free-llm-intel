# 不用真实数据的高效表格预训练：TAPEX 介绍

近年来，语言模型预训练通过利用大规模文本数据取得了巨大成功。借助[掩码语言建模](https://arxiv.org/abs/1810.04805)等预训练任务，这些模型在多个下游任务上展现出惊艳的性能。然而，预训练任务（如语言建模）与下游任务（如表格问答）之间的巨大落差使现有预训练效率不足。实践中，我们往往需要*海量*的预训练数据才能获得有前景的提升，即便是[领域自适应预训练](https://arxiv.org/abs/2004.02349)也是如此。我们能否设计一种预训练任务来缩小这一差距、从而加速预训练？

### 概览

在 "[TAPEX: Table Pre-training via Learning a Neural SQL Executor](https://openreview.net/forum?id=O50443AsCP)" 中，我们探索**在预训练中用合成数据代替真实数据**，并以 *TAPEX（Table Pre-training via Execution）* 展示其强大之处。在 TAPEX 中，我们表明可以通过学习一个神经 SQL 执行器，在合成语料上实现表格预训练。

[![snippet](https://huggingface.co/blog/assets/74_tapex/tapex-overview.png)](https://huggingface.co/blog/assets/74_tapex/tapex-overview.png)

> 注：[Table] 是输入中用户所提供表格的占位符。

如上图所示，通过对表格系统性采样*可执行的 SQL 查询及其执行结果*，TAPEX 首先合成一个非自然的合成预训练语料；然后继续预训练一个语言模型（如 [BART](https://arxiv.org/abs/1910.13461)）输出 SQL 查询的执行结果，模拟一个神经 SQL 执行器的过程。

### 预训练

下图展示了预训练过程。每一步，我们先从网页取一张表。示例表格关于奥运会。然后我们可以采样一个可执行 SQL 查询 `SELECT City WHERE Country = France ORDER BY Year ASC LIMIT 1`。通过现成的 SQL 执行器（如 MySQL），得到查询的执行结果 `Paris`。同理，把 SQL 查询与展平后的表格拼接后送入模型（如 BART encoder）作为输入，执行结果就作为模型（如 BART decoder）输出的监督信号。

[![corpus](https://huggingface.co/blog/assets/74_tapex/procedure.gif)](https://huggingface.co/blog/assets/74_tapex/procedure.gif)

为什么用 SQL 查询这样的程序而非自然语言句子作为预训练来源？最大的优势在于：与自然语言句子不可控相比，程序的多样性和规模可以被系统性地保证。因此，我们可以通过采样 SQL 查询轻松合成多样、大规模、高质量的预训练语料。

你可以在 🤗 Transformers 中像下面这样试用训练好的神经 SQL 执行器：

```
from transformers import TapexTokenizer, BartForConditionalGeneration
import pandas as pd

tokenizer = TapexTokenizer.from_pretrained("microsoft/tapex-large-sql-execution")
model = BartForConditionalGeneration.from_pretrained("microsoft/tapex-large-sql-execution")

data = {
    "year": [1896, 1900, 1904, 2004, 2008, 2012],
    "city": ["athens", "paris", "st. louis", "athens", "beijing", "london"]
}
table = pd.DataFrame.from_dict(data)

# tapex accepts uncased input since it is pre-trained on the uncased corpus
query = "select year where city = beijing"
encoding = tokenizer(table=table, query=query, return_tensors="pt")

outputs = model.generate(**encoding)

print(tokenizer.batch_decode(outputs, skip_special_tokens=True))
# ['2008']
```

### 实验

我们在四个基准数据集上评估 TAPEX，包括 [WikiSQL (Weak)](https://huggingface.co/datasets/wikisql)、[WikiTableQuestions](https://huggingface.co/datasets/wikitablequestions)、[SQA](https://huggingface.co/datasets/msr_sqa) 和 [TabFact](https://huggingface.co/datasets/tab_fact)。前三个数据集是表格问答，最后一个是表格事实核验，两者都需要对表格与自然语言联合推理。下面是最具挑战的数据集 WikiTableQuestions 中的例子：

| Question | Answer |
| --- | --- |
| according to the table, what is the last title that spicy horse produced? | Akaneiro: Demon Hunters |
| what is the difference in runners-up from coleraine academical institution and royal school dungannon? | 20 |
| what were the first and last movies greenstreet acted in? | The Maltese Falcon, Malaya |
| in which olympic games did arasay thondike not finish in the top 20? | 2012 |
| which broadcaster hosted 3 titles but they had only 1 episode? | Channel 4 |

实验结果表明，TAPEX 大幅超越以往的表格预训练方法，并在⭐所有基准上创下新的最先进结果⭐。包括：弱监督 WikiSQL 指称准确率提升至 **89.6%**（比 SOTA +2.3%，比 BART +3.8%）、TabFact 准确率 **84.2%**（比 SOTA +3.2%，比 BART +3.0%）、SQA 指称准确率 **74.5%**（比 SOTA +3.5%，比 BART +15.9%）、WikiTableQuestion 指称准确率 **57.5%**（比 SOTA +4.8%，比 BART +19.5%）。据我们所知，这是首个利用合成可执行程序进行预训练、并在多个下游任务上取得最先进结果的工作。

### 与以往表格预训练的比较

最早的表格预训练工作——Google Research 的 [TAPAS](https://aclanthology.org/2020.acl-main.398/)（同样[已收录于 🤗 Transformers](https://huggingface.co/docs/transformers/model_doc/tapas)）和 Meta AI 的 [TaBERT](https://aclanthology.org/2020.acl-main.745/)——揭示了收集更多*领域自适应*数据能提升下游性能。但这些以往工作主要采用*通用型*预训练任务，如语言建模及其变体。TAPEX 探索了另一条路径：牺牲预训练来源的自然性，换取一个*领域自适应*的预训练任务——SQL 执行。BERT、TAPAS/TaBERT 与我们 TAPEX 的图示对比见下。

[![comparsion](https://huggingface.co/blog/assets/74_tapex/comparsion-tapex.png)](https://huggingface.co/blog/assets/74_tapex/comparsion-tapex.png)

我们认为 SQL 执行任务更接近下游的表格问答任务，尤其从结构推理能力的角度看。想象你面对一个 SQL 查询 `SELECT City ORDER BY Year` 和一个自然语言问题 `Sort all cities by year`。两者所需的推理路径是相似的，只是 SQL 比自然语言更刻板。如果一个语言模型可以被预训练到忠实"执行"SQL 查询并产出正确结果，那么它对具有类似意图的自然语言也应该有深刻理解。

[![efficiency](https://huggingface.co/blog/assets/74_tapex/tapex-efficiency.png)](https://huggingface.co/blog/assets/74_tapex/tapex-efficiency.png)

效率如何？这种预训练方法与以往相比有多高效？答案见上图：与以往的表格预训练方法 TaBERT 相比，TAPEX 仅用 2% 的预训练语料就能带来 2% 的提升，速度几乎快了 **50** 倍！如果用更大的预训练语料（如 500 万 <SQL, Table, Execution Result> 对），下游数据集的表现还会更好。

### 结论

在这篇博客中，我们介绍了 TAPEX——一种通过采样 SQL 查询及其执行结果自动合成语料的表格预训练方法。TAPEX 通过在多样、大规模、高质量的合成语料上学习神经 SQL 执行器，解决了表格预训练中的数据稀缺挑战。在四个下游数据集上的实验结果表明，TAPEX 以更高预训练效率大幅超越以往表格预训练方法。

### 要点

从 TAPEX 的成功中我们能学到什么？我建议，尤其是当你想做高效的继续预训练时，不妨尝试这些选项：

- 合成一个精确而小的语料，而不是从互联网挖掘庞大但嘈杂的语料。
- 用程序模拟领域自适应技能，而不是用自然语言句子做通用语言建模。
