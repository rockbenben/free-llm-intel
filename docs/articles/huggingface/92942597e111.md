## 太长不看

我们很高兴宣布 SmolVLM 家族迎来两位新成员：SmolVLM-256M 和 SmolVLM-500M。没错——256M 参数，这是全世界最小的视觉语言模型！

我们在 SmolVLM 2B 积累的一切经验之上，聚焦效率、数据配比和新的设计权衡。我们兴奋地带来这一对模型：用极小的体量保住了强劲的多模态性能。

本次发布包含四个检查点：两个基座模型和两个指令微调模型，参数量分别为 256M 和 500M。这些模型可直接加载到 transformers、MLX 和 ONNX，我们为 transformers 和 WebGPU（基于 ONNX）准备了演示。本次发布的全部模型与演示可在[这里](https://huggingface.co/collections/HuggingFaceTB/smolvlm-256m-and-500m-6791fafc5bb0ab8acc960fb0)找到。

## 概览

- **SmolVLM-256M** – 全世界最小的 VLM！
- **SmolVLM-500M** – 五亿参数的兄弟模型，性能显著提升，同时依然超级轻量。
- **全新的视觉编码器选择** – 我们把 SigLIP 400M SO（SmolVLM 2B 和许多大型 VLM 所用）与更小的 SigLIP base patch-16/512 做了对比。出乎意料，更大的编码器只带来微不足道的提升，所以本次发布我们选用了 93M 参数的 SigLIP base patch-16/512。
- **更大的图像分辨率** – 更小的视觉编码器能以更高分辨率处理图像（灵感来自 Apple 的 VLM 研究和 Google 的 PaliGemma）。这带来更敏锐的图像理解，而开销几乎不变。
- **训练优化** – 一个全新的分词技巧显著提升了真实基准表现，尽管纸面上的训练损失反而更难看。

我们现在补齐了与 SmolLM2 家族（135M、360M、1.7B）对位的产品线，你得到一套完整的小号 LLM + VLM 组合可以玩。

## 为什么要做更小？

发布 SmolVLM 2B 时，社区反响非常好：模型非常轻、开源且许可宽松、容易集成进现有工作流。但我们想把这条路走得更远——为使用受限设备、消费级笔记本甚至浏览器内推理的人们。这正是新的 256M 和 500M 模型大显身手之处。而在另一端，对于要处理海量数据的人来说，这些模型只需 2B 模型的一小部分成本就能跑起来。

过去一年，我们训练了两个 80B VLM 并把它们缩减到 8B。然后在 SmolVLM 上，我们接受了把 2B 继续缩小的挑战。我们学到的是：前沿还能被推得更远！我们兴奋于证明在 256M 和 500M 上仍能获得出色性能。新的 256M 模型是迄今发布的最小 VLM，却超越了仅仅 17 个月前我们的 Idefics 80B 模型的表现。

### 认识 256M 参数"巨人"

仅凭 2.56 亿参数，这个模型成为有史以来最迷你的 VLM。别看它小，爆发力惊人。在很多多模态任务上它都相当能打，包括：

- **图像描述：** 描述图片或短视频。
- **文档问答：** 回答关于 PDF 或扫描件文本的问题。
- **基础视觉推理：** 回答有关图表或示意图的问题。

### 更进一步：500M

如果你需要更大的性能余量同时保持低内存占用，SmolVLM-500M 就是我们五亿参数档位的折中方案。它比之前的 2B 版本小得多，却能把 DocVQA、MMMU 这类任务上的分数推向大模型的水平。我们还发现这个模型对提示词更鲁棒，开箱即用就更适合生产环境。当然，两个模型微调后都很出色。

## 相比 SmolVLM 2B 改了什么？

**1. 视觉编码器选择** 此前我们使用标准 SigLIP 400M SO 视觉骨干，也就是许多 VLM 架构里都有的那一款。对这些小模型，我们实验了两种配置：

- **SigLIP 400M SO：** 容量更大，性能出色。
- **SigLIP base patch-16/512（93M）：** 小得多，性能接近得出人意料。

我们发现性能差距不足以让 256M 和 500M 模型背上更重的编码器。于是决定视觉编码器也走小巧路线。附带的好处是，更小的编码器能以更高分辨率处理图像——根据 [Apple](https://arxiv.org/pdf/2403.09611) 和 [Google](https://arxiv.org/pdf/2412.03555) 的研究，这往往能在不膨胀参数量的情况下带来更好的视觉理解。

**2. 数据配比更新**

与之前的发布类似，我们以 [The Cauldron](https://huggingface.co/datasets/HuggingFaceM4/the_cauldron) 和 [Docmatix](https://huggingface.co/datasets/HuggingFaceM4/Docmatix) 为主，新增了 [MathWriting](https://huggingface.co/datasets/andito/mathwriting-google)。

数据集的比例做了调整，更强调文档理解（41%）和图像描述（14%），同时保持对视觉推理、图表理解和通用指令遵循等其他关键领域的均衡关注。这次更新让模型建立在扎实的文档理解基础上，也为微调打开大门——你可以据此调整它对特定任务的理解。

**3. 分词优化**

我们把像素打乱（pixel shuffle）推得更远了！新模型以每个词元 4096 像素的比率编码图像，而 2B 模型是 1820 像素每词元。

为了进一步优化分词，我们添加了特殊词元来更高效地表示子图像分隔符。这意味着以前 `<row_1_col_1>` 这样的字符串要映射到 7 个词元，现在只映射到 1 个词元。对直到 `<row_6_col_6>` 的所有字符串我们都做了同样处理。这让模型训练稳定性与结果质量都有可观提升。更多细节记录在这篇 [LinkedIn 帖子](https://www.linkedin.com/posts/andimarafioti_when-worse-training-losses-lead-to-better-activity-7284521064934592513-yBZe?utm_source=share&utm_medium=member_desktop)。

**4. 补齐 SmolLM2-SmolVLM 家族**

SmolLM2 有三个尺寸：135M、360M 和 1.7B。随着今天发布的两个模型，我们终于凑齐了一套完整的小号 LLM + VLM 组合。

## 更小的多模态检索：ColSmolVLM 256M 与 500M

我们还发现，微调和实验出奇地简单。打造 ColBERT 风格检索模型的团队训练出了 ColSmolVLM，以与他们 10 倍体积模型相当的性能，交付了最先进水平的多模态检索速度。SmolVLM 让构建可检索数据库更快、更便宜。我们认为 256M 模型能成为许多任务上出色的专用模型。如何使用新的 ColSmolVLM 搭配新 SmolVLM 模型的链接见[下一步](https://huggingface.co/blog/smolervlm#next-steps)。

## 使用更小的 SmolVLM

新版 SmolVLM 与旧版 SmolVLM 代码开箱即用，因此你可以用 transformers 和 MLX 做推理与微调，用 TRL 做对齐 🚀 此外，本次发布还带来 ONNX 检查点。

用 transformers 上手 SmolVLM，如下所示：

```
import torch
from transformers import AutoProcessor, AutoModelForVision2Seq

# Initialize processor and model
processor = AutoProcessor.from_pretrained("HuggingFaceTB/SmolVLM-500M-Instruct")
model = AutoModelForVision2Seq.from_pretrained(
    "HuggingFaceTB/SmolVLM-500M-Instruct",
    torch_dtype=torch.bfloat16,
    _attn_implementation="flash_attention_2" if DEVICE == "cuda" else "eager",
)

# Create input messages
messages = [
    {
        "role": "user",
        "content": [
            {"type": "image"},
            {"type": "text", "text": "Can you describe this image?"}
        ]
    },
]

# Preprocess
prompt = processor.apply_chat_template(messages, add_generation_prompt=True)
inputs = processor(text=prompt, images=[image], return_tensors="pt")

# Generate
generated_ids = model.generate(**inputs, max_new_tokens=500)
generated_texts = processor.batch_decode(
    generated_ids,
    skip_special_tokens=True,
)
```

用以下 CLI 命令通过 MLX 运行 SmolVLM：

```
python3 -m mlx_vlm.generate --model HuggingfaceTB/SmolVLM-500M-Instruct --max-tokens 400 --temp 0.0 --image https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm_example.jpg --prompt "What is in this image?"
```
