# 在 Xeon 上用 🤗 Optimum Intel 实现极速 SetFit 推理

作者：Daniel Korat（Intel）、Tom Aarsen、Oren Pereg（Intel）、Moshe Wasserblat（Intel）、Ella Charlaix、Abirami Prabhakaran（Intel）

本文另有中文版本 [简体中文](https://huggingface.co/blog/zh/setfit-optimum-intel)。

SetFit 针对的是一个常见的建模难题：训练缺少标注数据怎么办。它由 Hugging Face 与 [Intel Labs](https://www.intel.com/content/www/us/en/research/overview.html) 和 [UKP Lab](https://www.informatik.tu-darmstadt.de/ukp/ukp_home/index.en.jsp) 的研究伙伴共同开发，是一个用 [Sentence Transformers](https://sbert.net/) 模型做少样本微调的高效框架。

SetFit 在标注数据很少时也能取得高准确率——例如在 Banking 77 金融意图数据集上，SetFit 在 3-shot 下[胜过](https://arxiv.org/pdf/2311.06102.pdf) GPT-3.5，在 5-shot 下还胜过了 3-shot 的 GPT-4。

与基于 LLM 的方法相比，SetFit 有两大独特优势：

🗣 **不需要提示词或模板句**：LLM 的少样本上下文学习依赖手工调制的提示词，这让结果脆弱、对措辞敏感、还依赖使用者的调词功力。SetFit 彻底不用提示词，直接从少量标注文本样本生成高质量嵌入。

🏎 **训练快**：SetFit 不依赖 GPT-3.5 或 Llama2 这类 LLM 就能实现高准确率。因此它的训练和推理速度通常要快一个数量级甚至更多。

关于 SetFit 的更多细节，请看我们的[论文](https://arxiv.org/abs/2209.11055)、[博客](https://huggingface.co/blog/setfit)、[代码](https://github.com/huggingface/setfit)和[数据](https://huggingface.co/SetFit)。

SetFit 已被 AI 开发者社区广泛采用：每月约 10 万次下载，Hub 上有 [~1500 个](https://huggingface.co/models?library=setfit) SetFit 模型，并且平均每天新增约 4 个！

## 再快一点！

在这篇博客里，我们将说明如何通过 🤗 [Optimum Intel](https://github.com/huggingface/optimum-intel) 优化你的 SetFit 模型，在 Intel CPU 上把推理加速 **7.8 倍**。我们会展示：只需对模型做一步简单的训练后量化，就能获得巨大的吞吐提升。这让基于 Intel Xeon CPU 的生产级 SetFit 部署成为可能。

[Optimum Intel](https://github.com/huggingface/optimum-intel) 是一个开源库，在 Intel 硬件上加速用 Hugging Face 库搭建的端到端流水线。Optimum Intel 内置多种模型加速技术：低位量化、权重剪枝、蒸馏，以及一个加速运行时。

[Optimum Intel](https://github.com/huggingface/optimum-intel) 的运行时和优化利用了 Intel CPU 上的 Intel® 高级矢量扩展 512（Intel® AVX-512）、向量神经网络指令（VNNI）和 Intel® 高级矩阵扩展（Intel® AMX）。具体来说，每个核心都内置了 [BFloat16](https://en.wikipedia.org/wiki/Bfloat16_floating-point_format)（bf16）和 int8 的 GEMM 加速器，加速深度学习训练与推理。AMX 加速推理在 PyTorch 2.0 和 [Intel Extension for PyTorch](https://github.com/intel/intel-extension-for-pytorch)（IPEX）中引入，后者还针对常见算子提供了额外优化。

用 Optimum Intel 对预训练模型做优化非常省事；大量简单示例见[这里](https://huggingface.co/docs/optimum/main/en/intel/optimization_inc)。本博客配有 [notebook](https://github.com/huggingface/setfit/blob/main/notebooks/setfit-optimum-intel.ipynb)，可一步步照着做。

## 第 1 步：用 🤗 Optimum Intel 量化 SetFit 模型

为了优化 SetFit 模型，我们将对模型主体施加量化，使用 [Intel Neural Compressor](https://www.intel.com/content/www/us/en/developer/tools/oneapi/neural-compressor.html)（INC）——它是 Optimum Intel 的一部分。

**量化**是非常流行的深度学习模型推理加速手段。它减少表示神经网络权重和/或激活所需的比特数：把一组高精度数字转成更低位宽的表示（如 INT8）。此外，量化还能让低精度下的计算更快。

具体地，我们采用训练后静态量化（PTQ）。PTQ 能降低推理的内存占用和延迟，同时保持模型精度——只需一小份无标注校准集，无需任何训练。开始前，请确保已安装所有必需的库，并且 Optimum Intel 版本不低于 `1.14.0`（该功能从该版本引入）：

```
pip install --upgrade-strategy eager optimum[ipex]
```

### 准备校准数据集

校准数据集应能代表未见数据的分布。一般来说，准备 100 条样本就够校准用了。本例我们使用 `rotten_tomatoes` 数据集——它是影评文本，与我们的目标数据集 `sst2` 类似。

首先从这个数据集随机加载 100 条样本。然后为量化做准备，需要逐条 tokenize。"text" 和 "label" 列不再需要，删掉：

```
calibration_set = load_dataset("rotten_tomatoes", split="train").shuffle(seed=42).select(range(100)) 

def tokenize(examples):
    return tokenizer(examples["text"], padding="max_length", max_length=512, truncation=True)
 
tokenizer = setfit_model.model_body.tokenizer
calibration_set = calibration_set.map(tokenize, remove_columns=["text", "label"])
```

### 运行量化

运行量化前，定义想要的量化方式——这里是**静态训练后量化**，然后用 `optimum.intel` 在校准数据集上执行量化：

```
from optimum.intel import INCQuantizer
from neural_compressor.config import PostTrainingQuantConfig

setfit_body = setfit_model.model_body[0].auto_model
quantizer = INCQuantizer.from_pretrained(setfit_body)
optimum_model_path = "/tmp/bge-small-en-v1.5_setfit-sst2-english_opt"
quantization_config = PostTrainingQuantConfig(approach="static", backend="ipex", domain="nlp")

quantizer.quantize(
    quantization_config=quantization_config,
    calibration_dataset=calibration_set,
    save_directory=optimum_model_path,
    batch_size=1,
)
tokenizer.save_pretrained(optimum_model_path)
```

就这样！我们本地就有了一份量化后的 SetFit 模型。来测一测。

## 第 2 步：推理基准测试

在我们的 [notebook](https://github.com/huggingface/setfit/blob/main/notebooks/setfit-optimum-intel.ipynb) 里，我们实现了 `PerformanceBenchmark` 类来计算模型延迟、吞吐和准确率。用它来给 Optimum Intel 模型做基准，并与另外两种常用方法对比：

- 使用 PyTorch 和 🤗 Transformers 库，fp32 精度。
- 使用 [Intel Extension for PyTorch](https://github.com/intel/intel-extension-for-pytorch)（IPEX）运行时，bf16 精度，并用 TorchScript 对模型做 tracing。

加载测试数据集 `sst2`，先用 PyTorch 和 🤗 Transformers 库跑基准：

```
from datasets import load_dataset
from setfit import SetFitModel
test_dataset = load_dataset("SetFit/sst2")["validation"]

model_path = "dkorat/bge-small-en-v1.5_setfit-sst2-english"
setfit_model = SetFitModel.from_pretrained(model_path)
pb = PerformanceBenchmark(
    model=setfit_model,
    dataset=test_dataset,
    optim_type="bge-small (transformers)",
)
perf_metrics = pb.run_benchmark()
```

第二轮基准用 [Intel Extension for PyTorch](https://github.com/intel/intel-extension-for-pytorch)（IPEX），bf16 精度加 TorchScript tracing。使用 IPEX 只需导入库并对目标模型（在我们的场景里是 SetFit 的 transformer 模型主体）调用 `ipex.optimize()`：

```
dtype = torch.bfloat16
body = ipex.optimize(setfit_model.model_body, dtype=dtype)
```

TorchScript tracing 方面，我们根据模型最大输入长度生成随机序列，token 从 tokenizer 词表中采样：

```
tokenizer = setfit_model.model_body.tokenizer
d = generate_random_sequences(batch_size=1, length=tokenizer.model_max_length, vocab_size=tokenizer.vocab_size)

body = torch.jit.trace(body, (d,), check_trace=False, strict=False)
setfit_model.model_body = torch.jit.freeze(body)
```

现在用量化后的 Optimum 模型跑基准。我们先要定义一个包装器，把量化后的模型主体在推理时插进 SetFit 模型（替换原始主体）。然后就可以用这个包装器跑基准了。

```
from optimum.intel import IPEXModel

class OptimumSetFitModel:
    def __init__(self, setfit_model, model_body):
        model_body.tokenizer = setfit_model.model_body.tokenizer
        self.model_body = model_body
        self.model_head = setfit_model.model_head


optimum_model = IPEXModel.from_pretrained(optimum_model_path)
optimum_setfit_model = OptimumSetFitModel(setfit_model, model_body=optimum_model)

pb = PerformanceBenchmark(
    model=optimum_setfit_model,
    dataset=test_dataset,
    optim_type=f"bge-small (optimum-int8)",
    model_path=optimum_model_path,
    autocast_dtype=torch.bfloat16,
)
perf_metrics.update(pb.run_benchmark())
```

## 结果

![](https://huggingface.co/blog/assets/178_setfit_optimum_intel/latency.png)

*batch size=1 时的准确率 vs 延迟*

|  | bge-small (transformers) | bge-small (ipex-bfloat16) | bge-small (optimum-int8) |
| --- | --- | --- | --- |
| 模型大小 | 127.32 MB | 63.74 MB | 44.65 MB |
| 测试集准确率 | 88.4% | 88.4% | 88.1% |
| 延迟（bs=1） | 15.69 +/- 0.57 ms | 5.67 +/- 0.66 ms | 4.55 +/- 0.25 ms |

看 batch size 为 1 的性能，我们的优化模型带来了 **3.45 倍的延迟降低**。注意这几乎没有损失准确率！同时模型体积也缩小了 **2.85 倍**。

![](https://huggingface.co/blog/assets/178_setfit_optimum_intel/throughput.png)

接着进入我们最关注的部分：不同 batch size 下的吞吐。这里的优化加速幅度更大：比较各 batch size 下可达到的最高吞吐，优化后的模型比原始 transformers fp32 模型**快 7.8 倍！**

## 小结

在这篇博客里，我们展示了如何用 🤗 Optimum Intel 的量化能力优化 SetFit 模型。执行了一个快速简单的训练后量化流程后，模型精度得以保留，而推理吞吐提升了 **7.8 倍**。这种优化方法可以直接套用到任何运行在 Intel Xeon 上的现有 SetFit 部署。
