# 用 Intel 技术加速 PyTorch 分布式微调

尽管性能出色，最先进的深度学习模型往往需要很长时间训练。为了加速训练任务，工程团队依赖分布式训练——一种分而治之的技术：集群中的每台服务器各自保存一份模型副本，在训练集的子集上训练，并交换结果以收敛到最终模型。

GPU 长期以来一直是训练深度学习模型的事实（*de facto*）首选。然而迁移学习的兴起正在改变游戏规则。模型如今很少再在海量数据集上从头训练，而是经常在特定的（更小的）数据集上微调，以构建在特定任务上比基座模型更精确的专用模型。由于这类训练任务短得多，使用基于 CPU 的集群可以成为一个兼顾训练时间与成本的有趣选择。

### 本文内容

在这篇文章中，你将学习如何把 [PyTorch](https://pytorch.org) 训练任务分布式地跑在由 Ice Lake 架构驱动、运行性能优化软件库的 Intel Xeon Scalable CPU 服务器集群上，从而实现加速。我们将从零开始搭建这个集群，你也应该能够在自己的基础设施上——无论在云上还是本地——轻松复现这个演示。

我们运行一个文本分类任务：在 [MRPC](https://www.microsoft.com/en-us/download/details.aspx?id=52398) 数据集（[GLUE](https://gluebenchmark.com/) 基准包含的任务之一）上微调一个 [BERT](https://huggingface.co/bert-base-cased) 模型。MRPC 数据集包含从新闻来源抽取的 5,800 个句子对，标签告诉我们每一对句子在语义上是否等价。我们选择这个数据集是因为它的训练时间适中，想尝试其他 GLUE 任务也不过是改一个参数的事。

集群就绪后，我们先在单台服务器上跑一个基线任务，然后扩展到 2 台和 4 台服务器，测量加速比。

过程中我们会覆盖以下主题：

- 列出所需的基础设施和软件构件，
- 搭建集群，
- 安装依赖，
- 运行单节点任务，
- 运行分布式任务。

开工吧！

### 使用 Intel 服务器

为了获得最佳性能，我们使用基于 Ice Lake 架构的 Intel 服务器，它支持 Intel AVX-512 和 Intel 向量神经网络指令（VNNI）等硬件特性。这些特性能加速深度学习训练和推理中的典型操作。你可以在这份[演示文稿](https://www.intel.com/content/dam/www/public/us/en/documents/product-overviews/dl-boost-product-overview.pdf)（PDF）中了解更多。

三大云厂商都提供由 Intel Ice Lake CPU 驱动的虚拟机：

- Amazon Web Services：Amazon EC2 [M6i](https://aws.amazon.com/blogs/aws/new-amazon-ec2-m6i-instances-powered-by-the-latest-generation-intel-xeon-scalable-processors/) 和 [C6i](https://aws.amazon.com/blogs/aws/new-amazon-ec2-c6i-instances-powered-by-the-latest-generation-intel-xeon-scalable-processors/) 实例。
- Azure：[Dv5/Dsv5 系列](https://docs.microsoft.com/en-us/azure/virtual-machines/dv5-dsv5-series)、[Ddv5/Ddsv5 系列](https://docs.microsoft.com/en-us/azure/virtual-machines/ddv5-ddsv5-series) 和 [Edv5/Edsv5 系列](https://docs.microsoft.com/en-us/azure/virtual-machines/edv5-edsv5-series) 虚拟机。
- Google Cloud Platform：[N2](https://cloud.google.com/blog/products/compute/compute-engine-n2-vms-now-available-with-intel-ice-lake) Compute Engine 虚拟机。

当然，你也可以使用自己的服务器。如果它们基于 Cascade Lake 架构（Ice Lake 的前代）也没问题，因为 Cascade Lake 同样包含 AVX-512 和 VNNI。

### 使用 Intel 性能库

为了在 PyTorch 中利用 AVX-512 和 VNNI，Intel 设计了 [Intel extension for PyTorch](https://github.com/intel/intel-extension-for-pytorch)。这个软件库开箱即用地加速训练和推理，所以我们一定要安装它。

说到分布式训练，性能瓶颈通常在网络。集群中的不同节点需要周期性地交换模型状态信息以保持同步。而 transformer 是拥有数十亿（有时远不止）参数的大模型，信息量相当可观，节点越多情况越糟。因此，使用为深度学习优化的通信库非常重要。

事实上，PyTorch 内置了 [`torch.distributed`](https://pytorch.org/tutorials/intermediate/dist_tuto.html) 包，支持不同的通信后端。这里我们使用 Intel oneAPI 集合通信库 [(oneCCL)](https://github.com/oneapi-src/oneCCL)，它是深度学习中常用通信模式（[all-reduce](https://en.wikipedia.org/wiki/Collective_operation) 等）的高效实现。关于 oneCCL 与其他后端的性能对比，可以阅读这篇 PyTorch [博客](https://pytorch.medium.com/optimizing-dlrm-by-using-pytorch-with-oneccl-backend-9f85b8ef6929)。

构件讲清楚了，下面谈谈训练集群的整体设置。

### 搭建集群

在这个演示中，我使用运行 Amazon Linux 2 的 Amazon EC2 实例（c6i.16xlarge，64 vCPU，128GB 内存，25Gbit/s 网络）。在其他环境中搭建方式会不同，但步骤应该大同小异。

请记住你需要 4 台完全相同的实例，所以最好规划某种自动化，避免把同样的设置跑 4 遍。这里我会手动配置一台实例，从它创建一个新的 Amazon Machine Image（[AMI](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AMIs.html)），再用这个 AMI 启动 3 台相同实例。

从网络角度看，我们需要以下设置：

- 在所有实例上开放 22 端口用于 `ssh` 访问，以便安装和调试。
- 配置主实例（启动训练的那台）与所有其他实例（**包括主实例自己**）之间的[免密](https://www.redhat.com/sysadmin/passwordless-ssh) `ssh`。
- 在所有实例上开放全部 TCP 端口，供 oneCCL 在集群内部通信。**请务必不要把这些端口暴露给外部世界**。AWS 提供了一种便捷做法：只允许运行特定[安全组](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_SecurityGroups.html)的实例之间的连接。我的设置就是这样配置的。

现在手动配置第一台实例。我先创建实例本身、绑定上述安全组，并添加 128GB 存储。为了优化成本，我把它作为[spot 实例](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/using-spot-instances.html)启动。

实例启动后，我通过 `ssh` 连上去安装依赖。

### 安装依赖

我们要走的步骤如下：

### 启动单节点任务

为了得到基线，我们在 `transformers/examples/pytorch/text-classification` 中启动一个运行 `run_glue.py` 脚本的单节点任务。这在任何实例上都应该能工作，也是进入分布式训练前的一次不错的健全性检查。

```
python run_glue.py \
--model_name_or_path bert-base-cased --task_name mrpc \
--do_train --do_eval --max_seq_length 128 \
--per_device_train_batch_size 32 --learning_rate 2e-5 --num_train_epochs 3 \
--output_dir /tmp/mrpc/ --overwrite_output_dir True
```

这个任务耗时 **7 分 46 秒**。现在让我们用 oneCCL 设置分布式任务，把速度提起来！

### 用 oneCCL 设置分布式任务

运行分布式训练任务需要三步：

- 列出训练集群的节点，
- 定义环境变量，
- 修改训练脚本。

**列出训练集群的节点**

在主实例上，在 `transformers/examples/pytorch/text-classification` 中创建一个名为 `hostfile` 的文本文件。这个文件保存集群中各节点的名称（写 IP 地址也可以）。第一行应指向主实例。

我的文件如下：

```
ip-172-31-28-17.ec2.internal
ip-172-31-30-87.ec2.internal
ip-172-31-29-11.ec2.internal
ip-172-31-20-77.ec2.internal
```

**定义环境变量**

接下来，我们需要在主节点上设置一些环境变量，最主要是它的 IP 地址。关于 oneCCL 变量的更多信息见[文档](https://oneapi-src.github.io/oneCCL/env-variables.html)。

```
for nic in eth0 eib0 hib0 enp94s0f0; do
  master_addr=$(ifconfig $nic 2>/dev/null | grep netmask | awk '{print $2}'| cut -f2 -d:)
  if [ "$master_addr" ]; then
    break
  fi
done
export MASTER_ADDR=$master_addr

source /home/ec2-user/anaconda3/envs/transformer/lib/python3.7/site-packages/torch_ccl-1.3.0+43f48a1-py3.7-linux-x86_64.egg/torch_ccl/env/setvars.sh

export LD_LIBRARY_PATH=/home/ec2-user/anaconda3/envs/transformer/lib/python3.7/site-packages/torch_ccl-1.3.0+43f48a1-py3.7-linux-x86_64.egg/:$LD_LIBRARY_PATH
export LD_PRELOAD="${CONDA_PREFIX}/lib/libtcmalloc.so:${CONDA_PREFIX}/lib/libiomp5.so"

export CCL_WORKER_COUNT=4
export CCL_WORKER_AFFINITY="0,1,2,3,32,33,34,35"
export CCL_ATL_TRANSPORT=ofi
export ATL_PROGRESS_MODE=0
```

### 用 oneCCL 运行分布式任务

在**主节点**上，我用 `mpirun` 启动一个 2 节点任务：`-np`（进程数）设为 2，`-ppn`（每节点进程数）设为 1。因此 `hostfile` 中的前两个节点会被选中。

```
mpirun -f hostfile -np 2 -ppn 1 -genv I_MPI_PIN_DOMAIN=[0xfffffff0] \
-genv OMP_NUM_THREADS=28 python run_glue.py \
--model_name_or_path distilbert-base-uncased --task_name mrpc \
--do_train --do_eval --max_seq_length 128 --per_device_train_batch_size 32 \
--learning_rate 2e-5 --num_train_epochs 3 --output_dir /tmp/mrpc/ \
--overwrite_output_dir True --xpu_backend ccl --no_cuda True
```

几秒钟后，任务在前两个节点上启动。任务在 **4 分 39 秒**内完成，加速 **1.7 倍**。

把 `-np` 设为 4 再启动新任务，现在集群的每个节点上各有一个进程在运行。

训练在 **2 分 36 秒**内完成，加速 **3 倍**。

最后一件事。把 `--task_name` 改成 `qqp`，我还跑了 Quora Question Pairs 这个 GLUE 任务，它基于一个大得多的[数据集](https://quoradata.quora.com/First-Quora-Dataset-Release-Question-Pairs)（超过 400,000 条训练样本）。微调时间为：

- 单节点：11 小时 22 分钟，
- 2 节点：6 小时 38 分钟（1.71x），
- 4 节点：3 小时 51 分钟（2.95x）。

看起来加速比相当稳定。欢迎继续用不同的学习率、batch size 和 oneCCL 设置做实验。我相信你还能更快！
