## 引言

视觉语言模型（Vision Language Model，VLM）越来越强，但把它们*对齐*到人类偏好仍然是关键问题。在 TRL 中，我们已经演示过如何用 [**监督微调（SFT）**](https://huggingface.co/docs/trl/main/en/training_vlm_sft) 和 [**直接偏好优化（DPO）**](https://huggingface.co/learn/cookbook/fine_tuning_vlm_dpo_smolvlm_instruct) 对 VLM 做后训练。这一次，我们走得更远。

**tl;dr** TRL 的新增内容：

- **混合偏好优化（Mixed Preference Optimization，MPO）**
- **组相对策略优化（Group Relative Policy Optimization，GRPO）**
- **组序列策略优化（Group Sequence Policy Optimization，GSPO）**（GRPO 的一个变体）

它们超越了成对的 DPO，能从偏好数据中提取更丰富的信号，也能更好地扩展到现代 VLM 上。

我们还把一些现有方法扩展到了 VLM：

- **Reinforce Leave One Out（RLOO）**
- **在线直接偏好优化（Online DPO）**

这让多模态对齐更高效、更可扩展。

最后是：

- **视觉语言模型的原生监督微调支持**
- **训练脚本和演示 notebook**，帮你快速上手

## 视觉语言模型的对齐

传统做法是：拿一个基础模型，先用 SFT 让它学会遵循指令，再用 DPO 把它对齐到偏好数据。此前我们[已经把这套流程适配到视觉语言模型（VLM）上](https://huggingface.co/blog/dpo_vlm)，并在 IDEFICS2 上验证了效果，模型回答确实有提升。

DPO 的工作原理是用一个对比式损失来优化模型回答对之间的偏好：你有一个被选中的回答和一个被拒绝的回答，基于"想要什么、不想要什么"来优化偏好。

但过去一年里，新的多模态对齐方法火了起来——GRPO 和 MPO，它们能把 VLM 的性能再往上推。文末有一张表格，展示了各模型回答的差别。

### 混合偏好优化（MPO）

只用 SFT 对齐多模态模型来做推理任务，会因为分布偏移（distribution shift）而力不从心；而用 DPO 对齐的模型又难以生成连贯的推理过程（rationale），还可能生成重复的回答。为解决这个问题，有一项专门为多模态模型设计的新方法叫 [Mixed Preference Optimization](https://huggingface.co/papers/2411.10442)（MPO）。这个方法本质上是 DPO 的多损失扩展：DPO 的偏好损失（sigmoid）、Binary Classifier Optimization（BCO）的质量损失，以及 SFT 的生成损失。按[论文](https://huggingface.co/papers/2411.10442)的说法，仅仅换成这个组合损失，MathVista 上就提升了 6.2 分！

[![MPO](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/trl-vlm/image_1.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/trl-vlm/image_1.png)

由于这只改动损失函数，我们直接给 TRL 的 `DPOTrainer` 类加了组合损失支持。用法是先这样初始化 `DPOConfig`：

```
mpo_config = DPOConfig(
    loss_type=["sigmoid", "bco_pair", "sft"], # Loss types to combine, as used in the MPO paper
    loss_weights=[0.8, 0.2, 1.0], # Corresponding weights, as used in the MPO paper
)
```

然后初始化 `DPOTrainer`：

```
mpo_trainer = DPOTrainer(
    model=model_id,
    args=mpo_config,
    processing_class=tokenizer,
    train_dataset=dataset,
)
mpo_trainer.train()
```

就这么简单！想进一步探索的话，完整 notebook 示例在[这里](https://huggingface.co/learn/cookbook/fine_tuning_vlm_mpo)。

### 多模态组相对策略优化（GRPO）

组相对策略优化（GRPO）是最前沿的对齐方法，最早提出于 [DeepSeek Math](https://huggingface.co/papers/2402.03300) 论文，后来集成到划时代的 LLM DeepSeek R1 中。它是 PPO 的扩展，策略更新在"组"上进行（组是一批代表对话如何展开的轨迹）。这个特性让它对奖励噪声更鲁棒，因为噪声在组内会被平均掉。由于模型学的是"好的回答"的更广义概念、而不是单个高奖励样本，这个方法也让模型表现非常出色。

[![GRPO](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/trl-vlm/image_2.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/trl-vlm/image_2.png)

在 TRL 中，我们现在为视觉语言模型引入了 GRPO 支持。这里不给出完整训练脚本示例（notebook 里有），我们只重点讲关键组件和概念。

要让训练脚本有效工作，我们需要验证回答格式是否正确、答案本身是否接近标准解，因此要写两个奖励函数。想真正看到后一个奖励的改进，你需要一个相当" maximalist"的配置：模型相对大一些、生成数量多、数据集质量高且多样。

```
import re
from math_verify import LatexExtractionConfig, parse, verify

def format_reward(completions, **kwargs):
    """Reward function that checks if the completion has a specific format."""
    pattern = r"^<think>.*?</think>\s*<answer>.*?</answer>$"
    matches = [re.match(pattern, content) for content in completions]
    rewards_list = [1.0 if match else 0.0 for match in matches]
    rewards = [1.0 if match else 0.0 for match in matches]
    print(completions)
    print(rewards)
    return rewards

def accuracy_reward(completions, **kwargs):
    """Reward function that checks if the completion is the same as the ground truth."""
    solutions = kwargs['solution']
    completion_contents = [completion[0]["content"] for completion in completions]
    rewards = []
    for content, solution in zip(completion_contents, solutions):
        gold_parsed = parse(solution, extraction_mode="first_match", extraction_config=[LatexExtractionConfig()])
        answer_parsed = parse(content, extraction_mode="first_match", extraction_config=[LatexExtractionConfig()])
        if len(gold_parsed) != 0:
            try:
                rewards.append(float(verify(answer_parsed, gold_parsed)))
            except Exception:
                rewards.append(0.0)
        else:
            rewards.append(1.0)
    return rewards
```

然后初始化 GRPOConfig 和 GRPOTrainer，把上面定义好的奖励函数传进去，调用 train() 就能开始训练。

```
from trl import GRPOConfig, GRPOTrainer

training_args = GRPOConfig(
    learning_rate=1e-5,
    max_prompt_length=None,
    ... # setup other params of choice here
)
trainer = GRPOTrainer(
    model=model_id,
    reward_funcs=[format_reward, accuracy_reward],
    args=training_args,
    train_dataset=train_dataset,
)
trainer.train()
```

完整 notebook 示例在[这里](https://huggingface.co/learn/cookbook/fine_tuning_vlm_grpo_trl)。

### 组序列策略优化（GSPO）

[Group Sequence Policy Optimization](https://huggingface.co/papers/2507.18071)（GSPO）是 Qwen 最近发布的 RL 对齐算法，解决了 GRPO 的一些局限。它通过在序列级别（而不是逐 token）计算重要性采样权重，实现了更稳定的训练。它的优势在 MoE 类模型上更[明显](https://github.com/volcengine/verl/pull/2775#issuecomment-3134375131)。

最新 TRL 也引入了 GSPO 支持；由于它是 GRPO 损失的一个变体，天然带有多模态支持。创建 trainer 的流程与 GRPO 相同，只需加上下面这些额外参数（数值取自论文）。

```
from trl import GRPOConfig

training_args = GRPOConfig(
        ...
    importance_sampling_level="sequence",
    epsilon=3e-4,
    epsilon_high=4e-4,
    beta=0.0,
    loss_type="grpo",
    steps_per_generation=1,
    steps_per_generation=4
)
```

**问题：** 在给定图形中，若角 APO 为 25.0 度，角 AOB 的度数是多少？选项：A: 140° B: 130° C: 120° D: 110°

**数据集中的答案：** 要求角 AOB 的度数，可以利用四边形内角和等于 360 度这一性质。应用该性质，角 AOB 可算作 360 − 角 OAP − 角 OBP − 角 P。由于角 OAP 和角 OBP 都是 90 度、角 P 已知为 50 度，代入等式得角 AOB = 360 − 90 − 90 − 50 = 130 度。因此角 AOB 的度数是 130 度，答案是选项 B。Answer:B

**基础模型输出：** 要求角 AOB 的度数，需要用到了同一段弧所对圆周角与圆心角的性质。具体地说，弧在圆心处所对的角（角 AOB）是该弧在圆周上任一点所对角（角 APO）的两倍。已知角 APO = 25°，可以这样计算角 AOB：由于角 AOB 是角 APO 的两倍，所以：[ 角 AOB = 2 * 角 APO ][ 角 AOB = 2 * 25° ][ 角 AOB = 50° ]然而，对照给定选项，这个计算看起来不对。让我们用正确的性质重新核算。正确的性质是：弧在圆心处所对的角是该弧在圆周上任一点所对角的两倍。因此正确的计算应为：角 AOB = 2 * 角 APO = 2 * 25° = 50°但既然这与给定选项不符，我们换一种思路。如果角 APO 是 25°，考虑圆内接四边形的性质，或者圆内接四边形对角和为 180°这一事实，我们可能需要看弧与弦所构成的补角。假设正确解法是求给定角 APO 的补角，从而得到角 AOB 的度数：角 AOB = 180° − 角 APO = 180° − 25° = 155°这仍然与选项不符。就给定选项来看，题目可能存在理解偏差或需要另一种解释。不过按标准几何原理，正确答案应该是：角 AOB = 2 * 角 APO = 2 * 25° = 50° 如果不是这样，请提供更多上下文或澄清题意。

**MPO 输出：** 要求角 AOB 的度数，需要用到了同一段弧所对圆周角与圆心角的性质。具体地说，弧在圆心处所对的角（角 AOB）是该弧在圆周上任一点所对角（角 APO）的两倍。已知角 APO = 25°，可以这样计算角 AOB：由于角 AOB 是角 APO 的两倍，所以：[ 角 AOB = 2 * 角 APO ][ 角 AOB = 2 * 25° ][ 角 AOB = 50° ]然而，对照给定选项，这个计算看起来不对。让我们用正确的性质重新核算。正确的性质是：弧在圆心处所对的角是该弧在圆周上任一点所对角的两倍。因此正确的计算应为：角 AOB = 2 * 角 APO = 2 * 25° = 50°但既然这与给定选项不符，我们换一种思路。如果看三角形 OAP，角 AOP 是 90°，因为它是一条直径所对的圆周角（直角）。现在角 APO 已知为 25°，那么角 AOA 会是 65°（因为它是角 APO 的余角）。所以角 AOB 应该是它的一半，即 32.5°。可这同样与选项不符。让我们考虑题目可能涉及另一种解释或另一种几何构型。就选项来看，题目表述或选项本身可能存在错误。如果必须在给定选项中选一个，按这类问题的标准几何原理，没有一个选项能正确对应。

**GRPO 输出**：要求角 AOB 的度数，需要理解角 AOB 是与圆心角 AOP 所对同一段弧的圆周角。根据圆周角定理，圆周角的度数是它所对弧的圆心角度数的一半。已知：- 角 APO = 25.0 度由于角 AOB 是与圆心角 AOP 所对同一段弧的圆周角，可以使用圆周角定理：角 AOB 的度数是角 AOP 度数的一半。因此角 AOB 的度数是 130 度。

**GSPO 输出：** 要求角 AOB 的度数，需要理解角 AOB 是与圆心角 AOP 所对同一段弧的圆周角。根据圆周角定理，圆周角的度数是它所对弧的圆心角度数的一半。已知：- 角 APO = 25.0 度由于角 AOB 是与圆心角 AOP 所对同一段弧的圆周角，可以用圆周角定理求角 AOB：角 AOB 的度数是角 AOP 度数的一半。因此答案是 B：130°。

### VLM 的更多扩展

除 MPO、GRPO 和 GSPO 之外，TRL 现在也为视觉语言模型（VLM）支持 [Reinforce Leave One Out](https://huggingface.co/papers/2402.14740)（RLOO）和 [Online Direct Preference Optimization](https://huggingface.co/papers/2402.04792)（Online DPO），可以在多模态数据集上做对齐。

#### Reinforce Leave One Out（RLOO）

RLOO 现已支持常见的 VLM。完整训练示例见 [`rloo_visual_math.py`](https://github.com/huggingface/trl/blob/main/examples/rloo_visual_math/rloo_visual_math.py) 脚本。

`RLOOTrainer` 的配置方式：

```
trainer = RLOOTrainer(
    model=model_name,
    args=training_args,
    reward_funcs=[think_format_reward, accuracy_reward],
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
)

trainer.train()
```

直接用示例脚本启动训练：

```
CUDA_VISIBLE_DEVICES=1,2 python3 examples/rloo_visual_math/rloo_visual_math.py --model_name_or_path Qwen/Qwen2.5-VL-3B-Instruct
```

#### 在线直接偏好优化（Online DPO）

Online DPO 同样支持 VLM。简单示例见 [`online_dpo_visual_math.py`](https://github.com/huggingface/trl/blob/main/examples/online_dpo_visual_math/online_dpo_visual_math.py) 脚本。

运行示例脚本（vLLM 集成后面会讲）：

```
CUDA_VISIBLE_DEVICES=1,2 python3 examples/online_dpo_visual_math/online_dpo_visual_math.py --model_name_or_path Qwen/Qwen2.5-VL-3B-Instruct --use_vllm --vllm_mode server
```

> 这些脚本都可以直接跑 VLM 训练；完整参数调优文档见 TRL：Online DPO trainer RLOO Trainer。

## 原生监督微调支持

此前，[`SFTTrainer`](https://huggingface.co/docs/trl/en/sft_trainer) 对视觉语言模型只是部分支持，主要因为 transformers API 里各家 VLM 实现差异太多。随着 transformers API 的标准化，我们现在提供了对视觉语言模型的完整支持。直接用 VLM 初始化 `SFTTrainer` 即可。

```
from trl import SFTConfig, SFTTrainer
from datasets import load_dataset

trainer = SFTTrainer(
    model="Qwen/Qwen2.5-VL-3B-Instruct",
    args=SFTConfig(max_length=None), # To avoid truncation that may remove image tokens during training
    train_dataset=load_dataset("trl-lib/llava-instruct-mix", split="train"),
)
trainer.train()
```

训练 VLM 时，数据集需要多一个 `images` 列，存放要处理的图像。具体格式参见 [Dataset Formats — Vision Datasets](https://huggingface.co/docs/trl/en/dataset_formats#vision-datasets)。一个很好的例子是 [LLaVA Instruct Mix](https://huggingface.co/datasets/trl-lib/llava-instruct-mix)。

我们还提供了一个 [`sft_visual_chat.py`](https://github.com/huggingface/trl/blob/main/examples/sft_visual_chat/sft_visual_chat.py) 脚本，对 transformers 的视觉语言模型开箱即用。

## TRL 中的 vLLM 集成

TRL 集成了 vLLM，以支持训练过程中需要生成样本的在线对齐方法。像下面这样运行示例脚本即可启用 vLLM：

```
CUDA_VISIBLE_DEVICES=1,2 python3 examples/grpo_visual_math/grpo_visual_math.py --model_name_or_path Qwen/Qwen2.5-VL-3B-Instruct --use_vllm --vllm_mode colocate
```

主要有两种模式：`colocate` 和 `server`。[`colocate`](https://huggingface.co/blog/vllm-colocate) 在同一进程里运行 vLLM 和训练循环，训练与生成共用同一张 GPU，在 `GRPOTrainer` 内部创建一个 vLLM LLM 实例。而 `server` 模式需要你单独在另一个进程里起一个 vLLM 服务，训练进程去访问它。起服务可以用这个命令：

```
trl vllm-serve --model Qwen/Qwen2.5-VL-3B-Instruct --tensor-parallel-size 1 
```

然后这样运行脚本：

```
CUDA_VISIBLE_DEVICES=1,2 python3 examples/grpo_visual_math/grpo_visual_math.py --model_name_or_path Qwen/Qwen2.5-VL-3B-Instruct --use_vllm --vllm_mode server
```

再给一个小提示：我们已经支持在 TRL 中让 vLLM 使用 transformers 后端。无论是 colocate 方式跑脚本还是起服务，传 `--vllm_model_impl transformers` 标志即可启用。

关于 TRL 的 vLLM 集成，更多细节见[这里](https://huggingface.co/docs/trl/en/vllm_integration)。
