# 宣布 Hub 上线评估功能

2023 年 11 月更新：

该项目已被归档。如果你想在 Hub 上评估 LLM，可以看看[这个排行榜合集](https://huggingface.co/collections/clefourrier/llm-leaderboards-and-benchmarks-%E2%9C%A8-64f99d2e11e92ca5568a7cce)。

*太长不看*：今天我们推出 [Evaluation on the Hub](https://huggingface.co/spaces/autoevaluate/model-evaluator)——一个由 [AutoTrain](https://huggingface.co/autotrain) 驱动的新工具，让你不写一行代码就能在 Hub 上的任何数据集评估任何模型！

评估所有模型 🔥🔥🔥！

AI 的进步堪称惊人，甚至有人开始认真讨论 AI 模型是否在某些任务上已经胜过人类。但这份进步其实非常不均衡：对一个几十年前的机器学习研究者来说，现代硬件和算法也许看起来不可思议，我们手头的海量数据和算力也是，但我们评估模型的方式却基本没变。

然而毫不夸张地说，现代 AI 正处在一场评估危机之中。如今像样的评估意味着要测很多模型、往往在很多数据集上、用多个指标。但做起来格外繁琐。如果我们还在意可复现性，那就更是如此——因为自报的结果可能受无意中的 bug、实现细节的微妙差异，甚至更糟的问题影响。

我们相信，只要我们——社区——建立一套更好的最佳实践并扫清障碍，更好的评估是可以实现的。过去几个月，我们一直在埋头打造 [Evaluation on the Hub](https://huggingface.co/spaces/autoevaluate/model-evaluator)：点一下按钮，就能用任何指标在任何数据集上评估任何模型。作为起步，我们在若干关键数据集上评估了数百个模型，并利用 Hub 上全新的 [Pull Request 功能](https://huggingface.co/blog/community-update)，在大量模型卡片上开了 PR 来展示经过验证的性能。评估结果按照 Hub 上[所有模型通用的格式](https://huggingface.co/docs/hub/models-cards)直接编码进模型卡片元数据。看看 [DistilBERT](https://huggingface.co/distilbert-base-uncased-finetuned-sst-2-english/blob/main/README.md#L7-L42) 的模型卡片就知道长什么样！

## Hub 之上

Evaluation on the Hub 打开了一大门缝，后面是这么多有趣的用例：从需要决定部署哪个模型的数据科学家或高管，到想在新的数据集上复现论文结果的高校研究者，到想更好理解部署风险伦理学家。如果非要挑出三个最初的主要使用场景，就是它们：

**为你的任务找到最佳模型**
 假设你清楚知道自己的任务是什么，想找到合适的模型。你可以查看一个能代表你任务的某数据集的排行榜，它汇总了所有结果。这很棒！那如果你看上的那个新潮模型还没出现在该数据集的[排行榜](https://huggingface.co/spaces/autoevaluate/leaderboards)上怎么办？直接为它跑一次评估就好，连 Hub 都不用离开。

**在你全新的数据集上评估模型**
 再假设你有一个崭新出炉的数据集，想跑一批基线？你可以把它上传到 Hub，然后在上面评估任意多个模型，完全不需要代码。更重要的是，你可以确信：你在自己数据集上评估模型的方式，与它们在其他数据集上被评估的方式完全一致。

**在许多相关数据集上评估你的模型**
 又或者你有一个全新的问答模型，在 SQuAD 上训练的？可用来评估的问答数据集有几百个 :scream: 你可以挑选你关心的那些，直接在 Hub 上评估你的模型。

### 配置评估任务

首先，前往 [`model-evaluator` Space](https://huggingface.co/spaces/autoevaluate/model-evaluator)，选择你想在其上评估模型的数据集。对于我们这个狗和食物图片数据集，你会看到类似下图的界面：

[![Model Evaluator](https://huggingface.co/blog/assets/82_eval_on_the_hub/model-evaluator.png)](https://huggingface.co/blog/assets/82_eval_on_the_hub/model-evaluator.png)

Hub 上的许多数据集包含元数据，指定了评估应如何配置（例如看看 [acronym_identification](https://huggingface.co/datasets/acronym_identification/blob/main/README.md#L22-L30)）。有了它你就能一键评估模型，不过在这里我们要演示如何手动配置评估。

点击 *Advanced configuration*（高级配置）按钮，你会看到可选的各项设置：

- 任务、数据集和 split 的配置
- 数据集列到标准格式的映射
- 指标的选择

如下图所示，配置要评估的任务、数据集和 split 非常直接：

[![Advanced Configuration](https://huggingface.co/blog/assets/82_eval_on_the_hub/config.png)](https://huggingface.co/blog/assets/82_eval_on_the_hub/config.png)

下一步是定义哪些数据集列包含图片、哪些列包含标签：

[![Dataset Mapping](https://huggingface.co/blog/assets/82_eval_on_the_hub/mapping.png)](https://huggingface.co/blog/assets/82_eval_on_the_hub/mapping.png)

任务和数据集都配置好之后，最后（可选）一步是选择评估用的指标。每类任务都关联一组默认指标。例如下面这张图显示 F1 分数、准确率等会自动计算。为了加点料，我们再把 [Matthew's correlation coefficient](https://huggingface.co/spaces/evaluate-metric/matthews_correlation)（马修斯相关系数）也算上，它对分类器性能的衡量更均衡：

[![Selecting Metrics](https://huggingface.co/blog/assets/82_eval_on_the_hub/select-metrics.png)](https://huggingface.co/blog/assets/82_eval_on_the_hub/select-metrics.png)

配置一个评估任务就这些！接下来只需要挑几个模型来评估——我们来看看。

### 选择要评估的模型

Evaluation on the Hub 通过模型卡片元数据中的标签把数据集和模型关联起来。在我们的例子里有三个模型可选，所以全选！

[![Selecting Models](https://huggingface.co/blog/assets/82_eval_on_the_hub/select-model.png)](https://huggingface.co/blog/assets/82_eval_on_the_hub/select-model.png)

选好模型后，输入你的 Hugging Face Hub 用户名（用于接收评估完成通知），然后按下大大的 *Evaluate models* 按钮：

[![Launching the Evaluation](https://huggingface.co/blog/assets/82_eval_on_the_hub/evaluate.png)](https://huggingface.co/blog/assets/82_eval_on_the_hub/evaluate.png)

任务提交后，模型会被自动评估，并且 Hub 上会开出包含评估结果的 pull request：

[![Pull Request](https://huggingface.co/blog/assets/82_eval_on_the_hub/pr.png)](https://huggingface.co/blog/assets/82_eval_on_the_hub/pr.png)

你还可以把评估元数据复制粘贴到数据集卡片里，这样下次你和其他社区成员就能跳过手动配置！

[![Metadata Pull Request](https://huggingface.co/blog/assets/82_eval_on_the_hub/metadata.png)](https://huggingface.co/blog/assets/82_eval_on_the_hub/metadata.png)

## 更大的图景

自机器学习诞生之日起，我们评估模型的方式就是在被假定为独立同分布的保留测试集上计算某种形式的准确率。在现代 AI 的压力之下，这个范式已经开始出现明显的裂缝。

基准正在饱和，也就是说机器在某些测试集上超越人类的速度，几乎比我们想出新高基准的速度还快。然而 AI 系统出了名的脆弱，不仅深受严重恶意偏见的影响，甚至会放大它们。可复现性严重不足。开放性常常是事后才想起。人们盯着排行榜，而部署模型的实际考量——比如效率和公平——却经常被略过。数据在模型开发中的极端重要性仍未得到足够重视。而且，预训练和基于提示词的上下文内学习（in-context learning）实践已经让「分布在分布内」这个概念本身变得模糊。机器学习正在慢慢补上这些课，我们也希望用自己的工作推动这个领域向前走。

## 下一步

几周前，我们发布了 Hugging Face 的 [Evaluate 库](https://github.com/huggingface/evaluate)，旨在降低机器学习评估最佳实践的门槛。我们此前也在托管基准，比如 [RAFT](https://huggingface.co/spaces/ought/raft-leaderboard) 和 [GEM](https://huggingface.co/spaces/GEM/submission-form)。Evaluation on the Hub 是我们努力的下一个合乎逻辑的步骤：让模型的评估走向更整体的方式——在多个评估轴上、以可信且保证可复现的方式进行。很快还会有更多发布，敬请期待，包括更多任务，以及一个全新升级的[数据测量工具](https://huggingface.co/spaces/huggingface/data-measurements-tool)！

我们很期待看到社区把它带向何方！想帮忙的话，尽管在任何数据集上评估任意多的模型。和以往一样，欢迎给我们大量反馈，可以发到 [Community 讨论区](https://huggingface.co/spaces/autoevaluate/model-evaluator/discussions)，也可以发到[论坛](https://discuss.huggingface.co/)。
