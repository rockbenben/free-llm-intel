[Hugging Face](https://huggingface.co/) 与 [EleutherAI](https://www.eleuther.ai/) 和 [Stability AI](https://stability.ai/) 密切合作，委托对 `safetensors` 库进行了外部安全审计。审计结果使这三家组织得以推进把该库作为模型保存的默认格式。

由 [Trail of Bits](https://www.trailofbits.com/) 执行的安全审计完整结果见这里：[报告](https://huggingface.co/datasets/safetensors/trail_of_bits_audit_repot/resolve/main/SOW-TrailofBits-EleutherAI_HuggingFace-v1.2.pdf)。

以下博文介绍这个库的由来、这些审计结果为何重要，以及下一步计划。

## safetensors 是什么？

🐶[Safetensors](https://github.com/huggingface/safetensors) 是一个在最常见框架（包括 PyTorch、TensorFlow、JAX、PaddlePaddle 和 NumPy）中保存和加载张量的库。

为了更具体，我们用 PyTorch 举例。

```
import torch
from safetensors.torch import load_file, save_file

weights = {"embeddings": torch.zeros((10, 100))}
save_file(weights, "model.safetensors")
weights2 = load_file("model.safetensors")
```

与其他格式相比，它还有若干[亮眼特性](https://github.com/huggingface/safetensors#yet-another-format-)，其中最关键的是文件加载是*安全*的，后文会详述。

当你使用 `transformers` 时，如果安装了 `safetensors`，就会优先使用这类文件以防问题，也就是说

```
pip install safetensors
```

很可能就是安全运行 `safetensors` 文件所需做的唯一一件事。

展望未来，得益于该库通过验证，`safetensors` 现在将默认随 `transformers` 安装。下一步是让 `safetensors` 成为默认的模型保存格式。

我们很高兴看到 `safetensors` 已在 ML 生态中被使用，包括：

- [Civitai](https://civitai.com/)
- [Stable Diffusion Web UI](https://github.com/AUTOMATIC1111/stable-diffusion-webui)
- [dfdx](https://github.com/coreylowman/dfdx)
- [LLaMA.cpp](https://github.com/ggerganov/llama.cpp/blob/e6a46b0ed1884c77267dc70693183e3b7164e0e0/convert.py#L537)

## 为什么要创造新东西？

创建这个库的动因是 PyTorch 底层使用 `pickle`，而 pickle 本质上不安全。（来源：[1](https://huggingface.co/docs/hub/security-pickle)、[2，视频](https://www.youtube.com/watch?v=2ethDz9KnLk)、[3](https://github.com/pytorch/pytorch/issues/52596)）

用 pickle，攻击者可以写出一个伪装成模型的恶意文件，在用户不知情的情况下把用户电脑的完全控制权交给攻击者，让他偷走用户所有的比特币 😓。

pickle 的这个漏洞在计算机安全界人尽皆知（PyTorch [文档](https://pytorch.org/docs/stable/generated/torch.load.html)也承认），但在更广的 ML 社区中并不是常识。

Hugging Face Hub 是一个任何人都能上传和分享模型的平台，因此努力防止用户感染恶意软件非常重要。

我们也在采取措施确保既有 PyTorch 文件不是恶意的，但能做的最多只是标记可疑文件。

当然，市面上还有其他文件格式，但都不符合我们团队总结的一整套[理想要求](https://github.com/huggingface/safetensors#yet-another-format-)。

除了安全，`safetensors` 还支持惰性加载，且加载通常更快（CPU 上约快 100 倍）。

惰性加载指高效地只加载张量的一部分。这一特性让高效推理库（如 [text-generation-inference](https://github.com/huggingface/text-generation-inference)）能做任意分片，在各种硬件上以最高效率加载 LLM（如 LLaMA、StarCoder 等）。

因为加载如此之快且框架无关，我们甚至可以用同一文件在 PyTorch 或 TensorFlow 中加载模型。

## 安全审计

既然 `safetensors` 的主要资产是提供安全保障，我们想确认它确实兑现了承诺。这就是 Hugging Face、EleutherAI 和 Stability AI 联手请外部安全审计来确认的原因。

重要发现：

- 未发现导致任意代码执行的严重安全缺陷。
- 发现并修复了规范格式中的一些不精确之处。
- 某些缺失的校验原本允许[多语言混合文件（polyglot files）](https://en.wikipedia.org/wiki/Polyglot_(computing))，已修复。
- 提出并实现了大量对测试套件的改进。

本着开放透明的精神，三家公司一致同意将报告完全公开。

[完整报告](https://huggingface.co/datasets/safetensors/trail_of_bits_audit_repot/resolve/main/SOW-TrailofBits-EleutherAI_HuggingFace-v1.2.pdf)

有一点值得注意：该库用 Rust 编写。这额外增加了一层[安全](https://doc.rust-lang.org/rustc/exploit-mitigations.html)，直接来自语言本身。

虽然不可能证明缺陷绝对不存在，但这是给用户吃下定心丸的重大一步：`safetensors` 确实可以放心使用。

## 展望未来

对 Hugging Face、EleutherAI 和 Stability AI 来说，总体计划是默认切换到这一格式。

EleutherAI 已在其 LM Evaluation Harness 中添加了对以 `safetensors` 存储的模型的评估支持，并在其 GPT-NeoX 分布式训练库中支持该格式。

在 `transformers` 库内，我们正在做：

- 创造 `safetensors`。
- 验证它可行、能兑现所有承诺（LLM 惰性加载、跨框架单文件、更快加载）。
- 验证它安全。（今天的公告就是这件事。）
- 把 `safetensors` 变为核心依赖。（已完成或即将完成。）
- 把 `safetensors` 作为默认保存格式。这将在几个月后发生——届时我们有足够反馈确保尽可能少造成扰动，并且已有足够多的用户装有该库，能在较旧的 `transformers` 版本上加载新模型。

至于 `safetensors` 本身，我们在研究为 LLM 训练添加更高级的特性——当前格式在训练上有其自身的问题。

最后，我们计划在不久的将来发布 `1.0`，由 `transformers` 庞大的用户群完成最终测试。格式和库自诞生以来改动很少，这是稳定性的好兆头。

我们很高兴能推动 ML 离安全、高效更近一步！
