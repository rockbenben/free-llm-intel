# 深入解析：Hugging Face Optimum Graphcore 上的 Vision Transformers

本博客将展示：在 Graphcore Intelligence Processing Units（IPU）上用 Hugging Face Optimum 库，为你的数据集微调预训练 Transformer 模型有多简单。作为例子，我们将提供一份手把手指南和一个 notebook：拿一个大规模、广泛使用的胸部 X 光数据集，训练一个 vision transformer（ViT）模型。

## 认识 vision transformer（ViT）模型

2017 年，一组 Google AI 研究者发表论文 introducing transformer 架构。凭借新颖的自注意力机制，transformer 被提出为新一代高效的语言模型。过去五年，transformers 人气爆炸，如今被公认是自然语言处理（NLP）的事实标准。

语言方向的 transformer 最具代表性的也许是快速演进的 GPT 和 BERT 家族。作为不断成长的 [Hugging Face Optimum Graphcore 库](https://huggingface.co/posts/getting-started-with-hugging-face-transformers-for-ipus-with-optimum)的一部分，两者都能在 Graphcore IPU 上轻松高效地运行。

![transformers_chrono](https://www.graphcore.ai/hs-fs/hubfs/transformers_chrono.png?width=1024&name=transformers_chrono.png)

重要 transformer 语言模型的发布时间线（图源：Hugging Face）

关于 transformer 架构（聚焦 NLP）的深度讲解见 [Hugging Face 网站](https://huggingface.co/course/chapter1/4?fw=pt)。

transformers 在语言上初战告捷，但它极其多才多艺，可以用在一系列其他用途上，包括计算机视觉（CV）——本博客就会讲到。

CV 领域里，卷积神经网络（CNN）无疑是最流行的架构。然而 vision transformer（ViT）架构——最早见于 Google Research 的 [2021 年论文](https://arxiv.org/abs/2010.11929)——代表了图像识别的一项突破，其核心组件与 BERT、GPT 使用同样的自注意力机制。

BERT 等基于 transformer 的语言模型以句子（词的列表）为输入；ViT 模型则把输入图像切成若干小 patch，相当于语言处理中的单个词。每个 patch 被 transformer 模型线性编码成可以独立处理的向量表示。这种把图像拆成 patch（视觉 token）的做法，与 CNN 使用的像素阵列形成对照。

多亏了预训练，ViT 模型学到了图像的内在表示，可以用来提取对下游任务有用的视觉特征。例如，在预训练视觉编码器顶部放一个线性层，就能在一批新标注图像上训练分类器。通常在 [CLS] token 之上放线性层，因为该 token 的最后隐藏状态可以视作整幅图像的表示。

![vit diag](https://www.graphcore.ai/hs-fs/hubfs/vit%20diag.png?width=1024&name=vit%20diag.png)

ViT 模型结构总览，出自 [Google Research 2021 年原始论文](https://arxiv.org/abs/2010.11929)

与 CNN 相比，ViT 模型以更低的计算成本展示了更高的识别准确率，应用范围涵盖图像分类、目标检测和分割。仅医疗健康领域的用例就包括 [COVID-19](https://www.mdpi.com/1660-4601/18/21/11086/pdf)、[股骨骨折](https://towardsdatascience.com/vision-transformers-for-femur-fracture-classification-480d62f87252)、[肺气肿](https://iopscience.iop.org/article/10.1088/1361-6560/ac3dc8/meta)、[乳腺癌](https://arxiv.org/abs/2110.14731)和[阿尔茨海默病](https://www.biorxiv.org/content/10.1101/2021.11.27.470184v2.full)等的检测与分类——不胜枚举。

## ViT 模型与 IPU：天作之合

Graphcore IPU 特别适合 ViT 模型，因为它能通过数据流水线与模型并行的组合来并行化训练。这一大规模并行过程的加速，依托于 IPU 的 MIMD 架构和以 IPU-Fabric 为核心的 scale-out 方案。

引入流水线并行后，数据并行每个实例可处理的批次变大，单块 IPU 管理的内存区域访问效率更高，数据并行学习中参数聚合的通信时间也减少了。

多亏了 Hugging Face Optimum Graphcore 开源库中加入的一批预优化 transformer 模型，在 IPU 上运行和微调 ViT 这类模型时，获得高性能和高效率变得轻而易举。

通过 Hugging Face Optimum，Graphcore 发布了开箱即用的 IPU 训练模型 checkpoint 和配置文件，让高效训练模型变得简单。这对 ViT 尤其有用——它们通常需要海量数据预训练。这个集成让你直接使用原作者发布在 Hugging Face 模型 hub 上的 checkpoint，不必自己训练。通过让用户即插即用任何公开数据集，Optimum 缩短了 AI 模型的整体开发生命周期，并与 Graphcore 最先进硬件无缝衔接，更快兑现价值。

本博客中，我们使用在 ImageNet-21k 上预训练的 ViT 模型，基于 Dosovitskiy 等人的论文 [An Image is Worth 16x16 Words: Transformers for Image Recognition at Scale](https://arxiv.org/abs/2010.11929)。作为示例，我们将演示用 Optimum 在 [ChestX-ray14 数据集](https://paperswithcode.com/dataset/chestx-ray14)上微调 ViT 的过程。

## ViT 模型在 X 光分类上的价值

与所有医学影像任务一样，放射科医生要花费多年学习如何可靠、高效地从 X 光片中发现问题并给出初步诊断。这种困难很大程度上来自图像极其微小的差异和空间局限——这正是计算机辅助检测与诊断（CAD）技术在改善临床工作流和患者结局上展现巨大潜力的原因。

同时，开发任何 X 光分类模型（无论是否 ViT）都有其相当的挑战：

- 从零训练模型需要海量标注数据；
- 高分辨率和数据量要求意味着必须用强大算力训练；
- 像肺部疾病诊断这类多类别、多标签问题，其复杂性随疾病类别数量呈指数增长。

如前所述，我们用 Hugging Face Optimum 做演示，不需要从零训练 ViT。相反，我们直接使用托管在 [Hugging Face 模型 hub](https://huggingface.co/google/vit-base-patch16-224-in21k) 上的模型权重。

一张 X 光片可能对应多种疾病，所以我们要做多标签分类。所用模型基于 [google/vit-base-patch16-224-in21k](https://huggingface.co/google/vit-base-patch16-224-in21k) checkpoint，由 [TIMM 仓库](https://github.com/rwightman/pytorch-image-models)转换而来，在 ImageNet-21k 的 1400 万张图像上预训练。为了在 IPU 上并行和优化任务，配置已通过 [Graphcore-ViT 模型卡](https://huggingface.co/Graphcore/vit-base-ipu)提供。

如果你第一次用 IPU，请先读 [IPU Programmer's Guide](https://docs.graphcore.ai/projects/ipu-programmers-guide/en/latest/) 学习基本概念。要在 IPU 上运行你自己的 PyTorch 模型，见 [PyTorch 基础教程](https://github.com/graphcore/tutorials/blob/master/tutorials/pytorch/basics)；Optimum 用法见我们的 [Hugging Face Optimum Notebooks](https://github.com/huggingface/optimum-graphcore/tree/main/notebooks)。

## 创建数据集

现在可以创建 PyTorch 数据集并划分训练/验证集。这一步会把数据集转为 [Arrow 文件格式](https://arrow.apache.org/)，让训练与验证期间的数据加载更快（[关于 Arrow 与 Hugging Face](https://huggingface.co/docs/datasets/v2.3.2/en/about_arrow)）。由于整个数据集会被加载和预处理，这一步可能要几分钟。

我们从 checkpoint `google/vit-base-patch16-224-in21k` 导入 ViT 模型。该 checkpoint 是 Hugging Face 托管的标准模型，不由 Graphcore 维护。

要微调预训练模型，新数据集必须与预训练用的原始数据集具有相同属性。在 Hugging Face 中，原始数据集信息由 `AutoImageProcessor` 加载的配置文件给出。对这个模型，X 光图像会被 resize 到正确分辨率（224x224）、从灰度转成 RGB，并以均值 (0.5, 0.5, 0.5)、标准差 (0.5, 0.5, 0.5) 在 RGB 通道上归一化。

要让模型高效运行，图像需要成批处理。为此我们定义 `vit_data_collator` 函数，按 [Transformers Data Collator](https://huggingface.co/docs/transformers/main_classes/data_collator) 中 `default_data_collator` 的模式，返回图像与标签组成的字典批次。

## 准备模型

要在 IPU 上训练模型，需要从 Hugging Face Hub 导入模型，并用 IPUTrainer 类定义 trainer。IPUTrainer 接受与原版 [Transformer Trainer](https://huggingface.co/docs/transformers/main_classes/trainer) 相同的参数，并与指定 IPU 编译和执行行为的 IPUConfig 对象配合工作。

现在从 Hugging Face 导入 ViT 模型。

要在 IPU 上使用这个模型，需要加载 IPU 配置 `IPUConfig`——它控制 Graphcore IPU 特有的所有参数（现有的 IPU 配置可在[这里](https://huggingface.co/Graphcore)找到）。我们将使用 `Graphcore/vit-base-ipu`。

接着用 `IPUTrainingArguments` 设置训练超参数。它继承自 Hugging Face 的 `TrainingArguments` 类，增加了 IPU 及其执行特性专属的参数。

## 实现自定义性能指标用于评估

多标签分类模型的性能可以用 ROC（接收者操作特征）曲线下面积（AUC_ROC）评估。AUC_ROC 以不同类别、不同阈值下的真阳性率（TPR）对假阳性率（FPR）作图。它对类别不平衡不敏感、易于解读，因此是多标签分类任务的常用指标。

对这个数据集，AUC_ROC 衡量模型区分不同疾病的能力。0.5 表示有 50% 可能蒙对疾病，1 表示能完美区分疾病。Datasets 里没有这个指标，所以要自己实现。HuggingFace Datasets 包允许通过 `load_metric()` 函数自定义指标计算。我们定义一个 `compute_metrics` 函数，像数据集包支持的其他指标一样暴露给 Transformer 的评估函数。`compute_metrics` 接收 ViT 模型预测的标签并计算 ROC 曲线下面积。它接收一个 `EvalPrediction` 对象（带 `predictions` 和 `label_ids` 字段的具名元组），并必须返回一个字符串到浮点的字典。

训练模型时，我们用 `IPUTrainer` 类定义 trainer——它负责把模型编译到 IPU 上运行，并执行训练和评估。`IPUTrainer` 的工作方式与 Hugging Face Trainer 类相同，只是多了 `ipu_config` 参数。
