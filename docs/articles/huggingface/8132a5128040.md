在过去五年里，Transformer 模型 [[1](https://arxiv.org/abs/1706.03762)] 已成为众多机器学习（ML）任务*事实上的*标准，例如自然语言处理（NLP）、计算机视觉（CV）、语音等。如今，许多数据科学家和 ML 工程师依赖流行的 transformer 架构——如 BERT [[2](https://arxiv.org/abs/1810.04805)]、RoBERTa [[3](https://arxiv.org/abs/1907.11692)]、Vision Transformer [[4](https://arxiv.org/abs/2010.11929)]，或 [Hugging Face](https://huggingface.co) hub 上 13 万多个预训练模型——以最先进的准确率解决复杂的业务问题。

然而，Transformer 虽好，部署到生产环境却很有挑战。除了模型部署通常伴随的基础设施管线（这部分我们用 [Inference Endpoints](https://huggingface.co/inference-endpoints) 服务已基本解决），Transformers 本身是动辄超过数 GB 的大模型。像 [GPT-J-6B](https://huggingface.co/EleutherAI/gpt-j-6B)、[Flan-T5](https://huggingface.co/google/flan-t5-xxl)、[Opt-30B](https://huggingface.co/facebook/opt-30b) 这样的大语言模型（LLM）是几十 GB 的量级，更不用说 [BLOOM](https://huggingface.co/bigscience/bloom) 这样的巨无霸——我们自己的 LLM，足足 350 GB。

把这些模型塞进单个加速器就非常困难了，更别提拿到应用所需的高吞吐和低推理延迟——对话应用和搜索都是如此。此前，ML 专家们设计了复杂的手工技术来切分大模型、把它们分布到一组加速器上并优化延迟。可惜这种工作极其困难、耗时，对多数 ML 从业者完全力不能及。

在 Hugging Face，我们在推动 ML 普惠，并一直在寻找同样相信每一位开发者和组织都应受益于最先进模型的伙伴。为此，我们很高兴地与 Amazon Web Services 合作，为 AWS [Inferentia 2](https://aws.amazon.com/machine-learning/inferentia/) 优化 Hugging Face Transformers！这是一款全新的、专为推理打造的加速器，在吞吐量、延迟、每瓦性能和可扩展性上达到前所未有的水平。

## AWS Inferentia2 简介

AWS Inferentia2 是 2019 年推出的 Inferentia1 的下一代。基于 Inferentia1 的 Amazon EC2 Inf1 实例相比搭载 NVIDIA A10G GPU 的同类 G5 实例提供了高 25% 的吞吐和低 70% 的成本；而有了 Inferentia2，AWS 再次突破极限。

新款 Inferentia2 芯片相比 Inferentia 提供 4 倍吞吐提升和 10 倍延迟降低。同样，新的 [Amazon EC2 Inf2](https://aws.amazon.com/de/ec2/instance-types/inf2/) 实例相比同类 G5 实例有高达 2.6 倍更好的吞吐、8.1 倍更低的延迟和 50% 更优的每瓦性能。Inferentia 2 让你两全其美：高吞吐带来的单次推理成本优化，以及低推理延迟带来的应用响应速度。

Inf2 实例有多种规格，配备 1 到 12 块 Inferentia 2 芯片。多芯片时，它们通过极快的 Inferentia2 直连互联，用于大模型的分布式推理。例如最大规格 inf2.48xlarge 有 12 块芯片，内存足以加载 GPT-3 或 BLOOM 这样的 1750 亿参数模型。

值得庆幸的是，这一切都不以增加开发复杂度为代价。借助 [optimum neuron](https://github.com/huggingface/optimum-neuron)，你不需要切分或修改模型。由于与 [AWS Neuron SDK](https://github.com/aws-neuron/aws-neuron-sdk) 的原生集成，把模型编译到 Inferentia 2 只需一行代码。几分钟内就能开始实验！测一测你的模型在 Inferentia 2 上能达到的性能，眼见为实。

说到这，我们来展示几个 Hugging Face 模型在 Inferentia 2 上的运行情况。基准测试时间到！

## 在 AWS Inferentia 2 上为 Hugging Face 模型做基准

我们评测了 [Hugging Face Hub](https://huggingface.co/models) 上最受欢迎的若干 NLP 模型，包括 BERT、RoBERTa、DistilBERT，以及 Vision Transformers 这样的视觉模型。

第一项基准对比 Inferentia、Inferentia 2 与 GPU 的性能。所有实验都在 AWS 上运行，实例类型如下：

- Inferentia1 —— [inf1.2xlarge](https://aws.amazon.com/ec2/instance-types/inf1/?nc1=h_ls)，单块 Inferentia 芯片。
- Inferentia2 —— [inf2.xlarge](https://aws.amazon.com/ec2/instance-types/inf2/?nc1=h_ls)，单块 Inferentia2 芯片。
- GPU —— [g5.2xlarge](https://aws.amazon.com/ec2/instance-types/g5/)，单块 NVIDIA A10G GPU。

*注意：我们没有针对 GPU 环境优化模型，模型以 fp32 评估。*

对 Transformer 模型做基准时，最被广泛采用的指标有两个：

- **延迟（Latency）**：模型完成一次预测（预处理、预测、后处理）所需的时间。
- **吞吐（Throughput）**：在固定时间内，单一基准配置完成的执行次数。

我们考察了不同设置、不同模型下的延迟，理解新 Inferentia2 实例的收益与取舍。如果你想自己跑基准，我们准备了一个 [Github 仓库](https://github.com/philschmid/aws-neuron-samples/tree/main/benchmark)，包含全部信息和脚本。

### 结果

基准确认了 AWS 宣称的性能提升可以在真实用例和示例中复现并验证。平均而言，AWS Inferentia2 的延迟比 NVIDIA A10G GPU 好 4.5 倍，比 Inferentia1 实例好 4 倍。

我们在 6 种不同模型架构上跑了 144 次实验：

- 加速器：Inf1、Inf2、NVIDIA A10G
- 模型：[BERT-base](https://huggingface.co/bert-base-uncased)、[BERT-Large](https://huggingface.co/bert-large-uncased)、[RoBERTa-base](https://huggingface.co/roberta-base)、[DistilBERT](https://huggingface.co/distilbert-base-uncased)、[ALBERT-base](https://huggingface.co/albert-base-v2)、[ViT-base](https://huggingface.co/google/vit-base-patch16-224)
- 序列长度：8、16、32、64、128、256、512
- Batch size：1

每次实验收集 p95 延迟数据。基准的完整细节见这张表格：[HuggingFace: Benchmark Inferentia2](https://docs.google.com/spreadsheets/d/1AULEHBu5Gw6ABN8Ls6aSB2CeZyTIP_y5K7gC7M3MXqs/edit?usp=sharing)。

## 结论

Transformer 模型已成为许多机器学习任务的首选方案。然而，由于其体积庞大且有延迟要求，把它们部署到生产环境一直很有挑战。多亏 AWS Inferentia2 以及 Hugging Face 与 AWS 的合作，开发者和组织如今无需先积累深厚的机器学习专业知识，就能享受最先进模型带来的好处。你可以从低至 0.76 美元/小时开始测试。

初步基准结果令人振奋，显示 Inferentia2 相比 Inferentia 和 NVIDIA A10G GPU 都提供了更优的延迟表现。这一最新突破预示着高质量机器学习模型可以触达更广泛的人群，把 AI 的普惠带给每一个人。
