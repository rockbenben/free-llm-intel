# 面向画廊、图书馆、档案馆与博物馆的 Hugging Face Hub

Daniel van Strien（davanstrien）

## 面向画廊、图书馆、档案馆与博物馆的 Hugging Face Hub

### Hugging Face Hub 是什么？

Hugging Face 的目标是让每个人都能用上高质量的机器学习。这个目标通过多种途径推进，包括开发像广受欢迎的 Transformers 库这样的开源代码库、提供[免费课程](https://huggingface.co/learn)，以及提供 Hugging Face Hub。

[Hugging Face Hub](https://huggingface.co/) 是一个中央仓库，人们可以在这里分享和访问机器学习模型、数据集和 demo。Hub 托管了超过 19 万个机器学习模型、3.3 万个数据集和超过 10 万个机器学习应用与 demo。这些模型涵盖广泛的任务，从预训练语言模型、文本/图像/音频分类模型、目标检测模型，到各种各样的生成模型。

托管在 Hub 上的模型、数据集和 demo 跨越众多领域和语言，社区也不断努力扩展 Hub 可提供内容的范围。这篇博客旨在帮助在画廊、图书馆、档案馆与博物馆（GLAM）领域工作、或与该领域合作的人理解他们如何使用——以及如何贡献——Hugging Face Hub。

## 你在 Hugging Face Hub 上能找到什么？

### 模型

Hugging Face Hub 提供访问覆盖各种任务和领域的机器学习模型。许多机器学习库都和 Hugging Face Hub 有集成，让你可以通过这些库直接使用或分享模型到 Hub。

### 数据集

Hugging Face hub 托管了超过 3 万个数据集。这些数据集覆盖一系列领域和模态，包括文本、图像、音频和多模态数据集。这些数据集对训练和评估机器学习模型很有价值。

### Spaces

Hugging Face [Spaces](https://huggingface.co/docs/hub/spaces) 是一个让你托管机器学习 demo 和应用的平台。这些 Spaces 从简单的 demo（让你探索某个机器学习模型做出的预测）到更复杂的 ứng 用不等。

Spaces 让托管应用、并让他人可访问地用起来要简单得多。你可以用 Spaces 托管 [Gradio](https://huggingface.co/blog/gradio.app/) 和 [Streamlit](https://streamlit.io/) 应用，也可以用 Spaces 运行[自定义 docker 镜像](https://huggingface.co/docs/hub/spaces-sdks-docker)。把 Gradio 和 Spaces 结合使用，往往意味着你能在几分钟内创建并托管一个可供他人使用的应用。如果你想完全掌控你的应用，可以用 Spaces 托管一个 Docker 镜像。还有一些 Docker 模板能让你快速访问许多流行工具的托管版本，包括 [Argailla](https://argilla.io/) 和 [Label Studio](https://labelstud.io/) 标注工具。

## 你如何使用 Hugging Face Hub：在 Hub 上找到相关模型

GLAM 领域有许多潜在用例，机器学习模型能在其中派上用场。虽然有些机构可能具备从零训练机器学习模型所需的资源，但你可以用 Hub 找到已公开分享的模型——它们要么已经做到你想要的，要么非常接近你的目标。

举个例子，假设你在处理一批元数据极少的数字化挪威文档。要更好地理解这批馆藏里有什么，一个方法是使用命名实体识别（NER）模型。这种模型从文本中抽取实体，例如识别文本里提到的地点。知道文本里包含哪些实体，是更好地理解一个文档在讲什么的有价值的方式。

我们可以通过按任务过滤模型，在 Hub 上找到 NER 模型。这里我们选 `token-classification`，这个任务包含了命名实体识别模型。[这个过滤器](https://huggingface.co/datasets?task_categories=task_categories:token-classification)会返回被标记为做 `token-classification` 的模型。由于我们在处理挪威文档，我们可能还想[按语言过滤](https://huggingface.co/models?pipeline_tag=token-classification&language=no&sort=downloads)；这把我们带到一个想探索的更小的模型集。这些模型里很多还含有一个 [model widget](https://huggingface.co/saattrupdan/nbailab-base-ner-scandi)，让我们可以测试模型。

[![](https://i.imgur.com/9V9xni5.png)](https://i.imgur.com/9V9xni5.png)

model widget 能快速展示一个模型在我们的数据上可能的表现有多好。一旦找到你感兴趣的模型，Hub 提供了使用该工具的不同方式。如果你已经熟悉 Transformers 库，可以点击 "use in Transformers" 按钮，弹出一个窗口展示如何在 Transformers 里加载该模型。

[![](https://i.imgur.com/E9MiMi9.png)](https://i.imgur.com/E9MiMi9.png)

[![](https://huggingface.co/blog/image/media/image4.png)](https://huggingface.co/blog/image/media/image4.png)

如果你更喜欢通过 API 使用模型，点击模型仓库里的 `deploy` 按钮会给你各种把模型托管在 API 之后的选项。如果你想在一批更大的数据上试用某个模型、但缺少本地运行模型的基建，这会特别有用。

类似的方法也能用于在 Hugging Face Hub 上查找相关模型和数据集。

## 实操：如何把 GLAM 数据集加到 Hub 上？

我们可以通过多种方式让数据集在 Hugging Face hub 上可用。我会演示一个把 CSV 数据集加到 Hugging Face hub 的例子。

*通过浏览器界面把数据集上传到 Hub 的流程概览*

在我们的例子里，我们要把 [On the Books Training Set](https://cdr.lib.unc.edu/concern/data_sets/6q182v788?locale=en) 做到 Hub 上可用。这个数据集由一个 CSV 文件组成，包含可用于训练文本分类模型的数据。由于 CSV 格式是把数据上传到 Hugging Face Hub 的[支持格式](https://huggingface.co/docs/datasets/upload_dataset#upload-dataset)之一，我们可以直接在 Hub 上分享这个数据集而无需写任何代码。

### 创建一个新的数据集仓库

把数据集上传到 Hub 的第一步是创建一个新的数据集仓库。这可以通过点击 Hugging Face hub 右上角下拉菜单里的 `New Dataset` 按钮来完成。

[![Creating a new dataset repository](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/create_dataset.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/create_dataset.png)

完成之后，你可以为新数据集仓库选一个名字。你也可以在不同的所有者（即某个组织）下创建数据集，并可选地指定一个许可证。

[![Choosing a name](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/new_repository.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/new_repository.png)

### 上传文件

创建好数据集仓库后，你需要上传数据文件。这可以通过点击数据集仓库 `Files` 标签下的 `Add file` 来完成。

[![Add files button](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/add-files.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/add-files.png)

现在你可以选择你想上传到 Hub 的数据。

[![Adding files to the Hub](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/file-upload.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/file-upload.png)

你可以用上传界面上传单个文件或多个文件。上传完文件后，提交你的更改以完成上传。

[![Commit your new files](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/commit.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/commit.png)

### 添加元数据

给你的数据集仓库添加元数据很重要，这样你的数据集更容易被发现、对他人更有用。这能让他人找到你的数据集并了解它包含什么。

你可以用 `Metadata UI` 编辑器编辑元数据。它允许你为数据集指定许可证、语言、标签等。

[![Example metadata](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/add-metadata.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/add-metadata.png)

更详细地说明你的数据集是什么、如何以及为何构建、它的优缺点，也非常有用。这可以在数据集仓库里通过填写 `README.md` 文件来完成。这个文件会充当你数据集的[数据集卡（dataset card）](https://huggingface.co/docs/datasets/dataset_card)。数据集卡是一种面向机器学习数据集的半结构化文档形式，旨在确保数据集得到充分记录。当你编辑 `README.md` 文件时，你会得到一个导入模板数据集卡的选项。这个模板会为你提供关于数据集卡里该包含哪些有用内容的提示。

*提示：写好一张数据集卡可能是大量工作。不过你不必非要一次做完所有这些工作，因为人们可以在 Hub 上就托管的数据集提问或提出建议，所以记录数据集的过程可以是一种集体活动。*

### 数据集预览

一旦我们把数据集上传到 Hub，就会得到一个数据集预览。数据集预览是更好理解该数据集的一个有益方式。

[![Dataset server preview](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/server-view.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/hf-hub-glam-guide/server-view.png)

## 画廊、图书馆、档案馆与博物馆为什么会想用 Hugging Face hub？

机构想要贡献 Hugging Face Hub 的原因有很多：

- **接触新受众**：Hub 已成为从事机器学习、AI 及相关领域工作者的一个核心去处。在 Hub 上分享会帮助你的馆藏和工作被这一受众看到。这也为与该受众进一步合作打开了机会。
- **社区**：Hub 有许多面向社区的特性，让你材料的使用者和潜在使用者能够提问、并就你通过 Hub 分享的材料互动交流。分享训练好的模型和机器学习数据集也让人能够彼此在对方成果之上构建，并降低了在该领域使用机器学习的门槛。
- **训练数据的多样性**：GLAM 使用机器学习的一个障碍是缺少用于训练和评估机器学习模型的相关数据。在基准数据集上表现良好的机器学习模型，在 GLAM 组织的数据上未必同样好。建立一个分享领域专属数据的社区，能确保机器学习在 GLAM 领域被更有效地推进。
- **气候变化**：训练机器学习模型会产生碳足迹。足迹的大小取决于各种因素。我们 collectively 减少这一足迹的一个方法是把训练好的模型与社区分享，这样人们就不会重复训练相同的模型（并在此过程中产生更多碳排放）。

## Hugging Face Hub 的使用示例

个人和组织已经在使用 Hugging Face hub 分享与 GLAM 领域相关的机器学习模型、数据集和 demo。

### BigLAM

一个在 [BigScience 项目](https://bigscience.huggingface.co/)基础上发展起来的倡议，聚焦于让来自 GLAM、与机器学习相关的数据集更易获取。BigLAM 迄今已经把 30 多个与 GLAM 相关的数据集做到了 Hugging Face hub 上可用。

### Nasjonalbiblioteket AI Lab

挪威国家图书馆的 AI 实验室是 Hugging Face hub 的一个非常活跃的用户，公开分享了约 120 个模型、23 个数据集和六个机器学习 demo。这些模型包括在挪威国家图书馆的挪威语文本上训练的语言模型，以及在萨米语上训练的 Whisper（语音转文本）模型。

### Smithsonian Institution

史密森尼学会分享了一个托管在 Hugging Face Spaces 上的应用，演示了两个被训练来识别亚马逊鱼类物种的机器学习模型。这个项目旨在用工具赋能社区，从而更准确地测量亚马逊的鱼类物种数量。把这样的工具通过一个 Spaces demo 提供出来，进一步降低了人们使用这些工具的门槛。

[来源](https://huggingface.co/Smithsonian)

## 面向画廊、图书馆、档案馆与博物馆的 Hub 特性

Hub 支持许多有助于让机器学习更易于接触的特性。对 GLAM 机构可能特别有帮助的一些特性包括：

- **组织（Organizations）**：你可以在 Hub 上创建一个组织。这让你能创建一个地方来分享你机构的成果。
- **铸造 DOI**：[DOI](https://www.doi.org/)（Digital Object Identifier，数字对象标识符）是一个对象的持久数字标识符。DOI 已成为为出版物、数据集和软件创建持久标识符的重要手段。期刊、会议或科研资助方在引用学术成果时往往需要一个持久标识符。Hugging Face Hub 支持为在 Hub 上分享的模型、数据集和 demo 签发 DOI。
- **使用追踪**：你可以查看 Hub 上托管数据集和模型的月度下载统计，或查看所有时间的总下载次数。这些统计可以是机构展示其影响力的一种有价值的方式。
- **基于脚本的数据集分享**：如果你已经在某处托管了数据集，你仍然可以通过 Hugging Face hub 用一个[数据集加载脚本](https://huggingface.co/docs/datasets/dataset_script)提供对它们的访问。
- **模型与数据集访问门控**：有些情况下你会想对谁访问模型和数据集有更多控制。Hugging Face hub 支持模型和数据集门控，让你添加访问控制。
