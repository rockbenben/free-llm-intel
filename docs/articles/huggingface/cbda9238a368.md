＃＃ 介绍

3D 生成在机器人、模拟、媒体和娱乐领域有多种用途。在这些领域中，很难使生成的对象遵守严格的规则并标准化模型和数据表示。文件格式有很多种，例如 [GLB](https://en.wikipedia.org/wiki/GlTF) 和 [PLY](https://en.wikipedia.org/wiki/PLY_(file_format))。还有[许多表示](https://huggingface.co/spaces/suvadityamuk/3d-representations-guide)，例如[神经辐射场(NeRFs)](https://www.matthewtancik.com/nerf)和[3D高斯泼溅(3DGS)](https://en.wikipedia.org/wiki/Gaussian_splatting)。每一种都有不同的优点和缺点。

[TRELLIS](https://huggingface.co/papers/2412.01506)引入了一种通用的内部表示，称为统一潜在表示。其解码器将此表示形式转换为所需输出格式的 3D 模型。因此，您不必为每种表示格式使用不同的模型。

该团队随后发布了 [TRELLIS.2](https://huggingface.co/papers/2512.14692)，它改进了模型对 3D 结构的表示。但这两种模型都没有提供一种简单的方法来使其适应特定任务。

### 我们想要改进的地方

通用模型（例如 TRELLIS.2）可能会在对特定应用程序很重要的细节上出错。例如，用户可能需要家具模型的精确几何形状。如果不对该任务进行微调，预训练模型可能会生成不够准确的几何形状。我们使用包含 188 个鞋类对象的 GSO 子集进行实验。在我们最初的测试中，预训练模型通常会生产出看起来正确的鞋子，但鞋底却不正确。我们测试LoRA是否可以使鞋底更加准确。

[![唯一轨道基地](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/sole_orbit_base.gif)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/sole_orbit_base.gif)

我们的目标是使用 [Google 扫描对象 (GSO)](https://huggingface.co/datasets/hugging-3d/google-scanned-objects) 数据集来提高 TRELLIS.2 在特定对象类别上的性能。我们将解释哪些管道组件需要微调，哪些组件在训练期间保持不变。管道将结构、详细几何形状和材料分开。因此，我们将仅微调对我们的任务重要的组件。

[![Meme](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/meme.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/meme.jpg)

> 选择冻结内容与选择微调内容一样重要。

### 我们将使用什么？

#### 洛拉

LoRA 是低秩适应的缩写，它通过训练小型适配器矩阵来微调模型，同时保持原始权重冻结。这减少了可训练参数的数量以及其梯度和优化器状态所需的内存。我们使用 Hugging Face 的 PEFT 库来添加和训练这些适配器。有关更多信息，请阅读我们的 [LoRA 指南](https://huggingface.co/docs/peft/package_reference/lora)。

#### Hugging Face工作

Hugging Face Jobs 在云硬件上运行容器化工作负载。我们用它进行预处理和训练。要使用您自己的 GPU，请参阅下面的本地 Docker 命令。在开始之前，请确保您拥有：

- 您可以[从此处]获取 HF_TOKEN(https://huggingface.co/settings/tokens/new)
- 您的 Hugging Face 帐户必须具有 [访问 DINOv3](https://huggingface.co/collections/facebook/dinov3)，因为 DINOv3 是一个门控模型
- 如果您使用自己的数据集，请在开始之前将其网格上传到中心。

## TRELLIS.2 的工作原理

在训练之前，让我们看看 TRELLIS.2 如何生成 3D 对象以及我们将在哪里添加 LoRA 适配器。

TRELLIS.2有五个主要阶段：去除图像背景、编码图像、预测粗略结构、生成详细几何形状和生成材料。然后，管道将结果导出为纹理网格。

[![TRELLIS.2 管道](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/pipeline_lr.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/pipeline_lr.png)

### 对输入图像进行编码

首先，BiRefNet 从输入图像中删除背景。然后 DINOv3-L 将图像编码为特征标记。生成模型使用这些标记来引导 3D 对象。

[![像素到特征标记](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/image_to_tokens.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/image_to_tokens.png)

###稀疏结构生成（稀疏结构流）

稀疏结构流 DiT 预测对象的粗略形状。它是一个扩散变压器 (DiT)，可生成大小为 16×8 的小型潜在变量。然后，变分自动编码器 (VAE) 解码器将此潜在变量更改为 64 × 64 × 64 占用网格。网格中的每个体素都会显示该位置是否是对象的一部分。体素是三维的像素。我们向该模型添加 LoRA 适配器，因为它的输出引导几何阶段。
[![阶段 1](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage1_sparse_struct.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage1_sparse_struct.png)

### O-体素和结构化潜伏

O-Voxel 是 TRELLIS.2 的 3D 格式。它是一个稀疏体素网格。它仅保留对象表面上的体素。每个体素都保留局部几何形状，例如网格顶点和材质属性。由于格式很小，CPU 可以在几秒钟内将网格转变为 O-Voxel。 GPU 在几秒钟内将 O-Voxel 变回网格。

结构化稀疏潜在变量来自 TRELLIS。他们将 3D 数据保存在稀疏张量中，这使得计算速度更快。该模型仅使用网格中大约 10% 的体素，因此它不会在空体素上花费计算。因此，形状流DiT和纹理流DiT是稀疏变换器。稀疏结构流 DiT 是一个密集变压器。
[![O-Voxel](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/ovoxel_sparse.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/ovoxel_sparse.png)

### 几何生成（形状流）

形状流 DiT 使用占用网格和 DINOv3 特征标记来生成潜在的。然后，另一个 VAE 解码器将其转换为分辨率为 512 × 512 × 512 的 O-体素几何。

我们在此阶段将 LoRA 适配器添加到 DiT，因为它控制对象的形状。

[![阶段 2](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage2_shape.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage2_shape.png)

### 材质生成+网格创建

在最后阶段，纹理流 DiT 使用潜在形状和 DINOv3 特征作为输入。它定义了几何体表面的材质和纹理。然后，VAE 解码器将每个体素的潜在值更改为基色、金属、粗糙度和 alpha 值。我们不会在此阶段添加 LoRA 适配器。我们的数据集具有漫反射颜色图，但缺少此阶段训练所需的单独材质图。另外，我们的问题是鞋子的形状。基础模型已经产生了良好的颜色和纹理。

最后，管道将几何体和材质属性组合成纹理网格并将其导出为 GLB 文件。

[![阶段 3](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage3_texture.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage3_texture.png)

## 规划

### 哪些组件需要微调

我们仅将 LoRA 适配器添加到稀疏结构流 DiT 和形状流 DiT 中。这些 DiT 控制对象的形状和几何形状。我们冻结纹理流 DiT 以保持其当前功能。

我们的数据集包含漫反射颜色贴图，其中包括烘焙光照效果。为了训练纹理流 DiT，我们需要单独的材质贴图。我们数据集中的颜色图将表面颜色与光照混合。因此，他们不是本次培训的正确目标。

如果我们在这些贴图上训练纹理流 DiT，它可以学习将光照显示为表面属性。它还可能忘记以前学到的东西，这种问题称为灾难性遗忘。

### 为什么使用 LoRA

我们的子集包含 GSO 中 1,030 个对象中的 188 个鞋子。对于这么小的数据集，LoRA 是比完全微调更好的选择。完全微调的成本要高得多。它还可以覆盖模型已经做得很好的部分（它学到的先验知识）。我们的配置为两个目标 DiT 总共训练了大约 930 万个适配器参数。我们在稀疏结构流 DiT 的注意力和前馈 (MLP) 层中使用 8 级适配器。我们在形状流 DiT 的注意力层中使用 16 级适配器。等级设置适配器矩阵的大小。更高的等级可以让适配器了解更多。

### 你将运行什么

3D 模型设置可能需要许多依赖项和安装步骤。我们提供两个 Docker 镜像（您可以在 [Jobs](https://hf.co/jobs) 或您自己的机器上运行）以及必要的软件。一张图像用于预处理，一张图像用于微调。

要训练您的 LoRA 适配器并将其上传到集线器：

- 允许容器访问您的数据。
- 为您的任务设置参数。
- 运行预处理容器。
- 运行微调容器。

然后我们解释微调脚本、其设置以及每个设置如何影响训练。

### 实验概述

我们将逐步完成实验的三个部分：

- **准备数据。** 将 GLB 或 OBJ 网格转换为 TRELLIS.2 用于训练的潜在表示，并渲染输入图像。
- **训练适配器。** 使用准备好的数据集和 LoRA 配置为每个 DiT 运行一项作业。
- **解释代码。**检查容器如何加载数据、添加适配器和训练模型。

我们保存预处理的数据集，以便所有训练运行都可以重复使用它。

## 演练

### Hugging Face工作

#### 预处理

预处理容器使用 Blender 渲染每个对象的 16 个视图。 LoRA 训练将使用这些视图作为条件图像。 Blender 通过 xvfb-run 实用程序在没有显示器的情况下运行。容器还通过[预处理管道](https://github.com/microsoft/TRELLIS.2/blob/main/data_toolkit/README.md)处理每个对象。请参阅此处的 [鞋类数据集](https://huggingface.co/datasets/suvadityamuk/gso-footwear-trellis2-lateents) 以获取示例中间输出。对于 188 个对象，100 个大型作业的完整运行大约需要 1 小时。 [此配套存储库](https://github.com/suvadityamuk/trellis2-finetuning/blob/master/preprocess.py) 中还提供了预处理管道的紧凑版本。
```
export HF_TOKEN=hf_xxx  

# Replace your-username with your Hugging Face username

hf jobs run -d --flavor a100-large --timeout 6h --secrets HF_TOKEN \
  cr.hf.co/suvadityamuk/trellis2-finetuning-prep:latest \
  trellis2-prep \
    --meshes your-username/my-meshes \
    --push-to your-username/my-meshes-trellis2 \
    --private --holdout 0.05 \
    --views 16 --workers 8
```
对于Hugging Face工作，我们传递以下参数：

|旗帜|意义|
| --- | --- |
| `-d` |分离：打印作业 ID 和 URL，然后返回。要跟踪作业，请运行 `hf jobs messages -f <id>` |
| `--flavor a100-large` |硬件。我们使用 a100-large (80 GB)。要查看所有选项，请运行 hf jobs hardware |
| `--超时 6h` |作业在此时间后停止。两个命令都恢复。预处理会跳过完成的对象。训练从 --push-to | 中的最新检查点继续进行
| `--秘密 HF_TOKEN` |将您的令牌（从 HF_TOKEN 或 hf auth 登录）作为加密的环境变量发送到作业。令牌未写入图像 |
| `cr.hf.co/...:最新` |要运行的图像。它后面的所有文本都是在容器中运行的命令 |

该容器接受更多参数（无论是在 Hugging Face Jobs 上运行还是使用 Docker 运行），您可以[在此处找到文档](https://github.com/suvadityamuk/trellis2-finetuning#1-preprocess-trellis2-prep)。预处理管道中采取的步骤稍后记录在[本节](https://huggingface.co/blog/3d-lora-finetuning#preprocessing-into-latents)中。

#### LoRA 微调

训练容器加载准备好的数据集和配置预设或文件。它使用 Trackio 记录训练指标。使用 Trackio 仪表板监控跑步情况。

我们使用“ss”和“shape”来表示训练 LoRA 的两种模式。 “ss”模式将仅微调稀疏结构流 DiT，而“shape”模式将微调形状流 DiT。在幕后，他们只是引用不同的 config.json 文件以用于每个阶段。有关该过程的更多详细信息，请参阅稍后的[本节](https://huggingface.co/blog/3d-lora-finetuning#training)。
```
export HF_TOKEN=hf_xxx  # Replace your-username with your Hugging Face username

hf jobs run -d --flavor a100-large --timeout 12h --secrets HF_TOKEN \
  cr.hf.co/suvadityamuk/trellis2-finetuning-train:latest \
  trellis2-train --config ss \
    --latents your-username/my-meshes-trellis2 \
    --push-to your-username/my-trellis2-lora \
    --run-name ss_lora \
    --push-path ss_lora \
    --trackio-space your-username/trellis2-trackio

hf jobs run -d --flavor a100-large --timeout 12h --secrets HF_TOKEN \
  cr.hf.co/suvadityamuk/trellis2-finetuning-train:latest \
  trellis2-train --config shape \
    --latents your-username/my-meshes-trellis2 \
    --push-to your-username/my-trellis2-lora \
    --run-name shape_lora \
    --push-path shape_lora \
    --trackio-space your-username/trellis2-trackio \
    --set max_steps=3000 i_save=500
```
如果设置“--push-to”，容器会将适配器检查点上传到集线器。该容器接受的参数也[为简洁起见在此处记录](https://github.com/suvadityamuk/trellis2-finetuning#3-train-trellis2-train)。 [同一存储库](https://github.com/suvadityamuk/trellis2-finetuning/blob/master/finetune.py) 中还提供了紧凑的脚本。

如果您想使用我们已经处理的数据集并进行微调，请随意使用以下命令集。
```

# Replace your-username with your Hugging Face username

# For the Sparse-Structure Flow DiT
hf jobs run -d --flavor a100-large --timeout 12h --secrets HF_TOKEN \

  trellis2-train \
    --config ss \
    --latents suvadityamuk/gso-footwear-trellis2-latents \
    --push-to your-username/trellis2-footwear-lora \
    --run-name ss_lora \
    --push-path ss_lora \
    --trackio-space your-username/trellis2-trackio \
    --set max_steps=3000 i_save=500

# For the Shape Flow DiT
hf jobs run -d --flavor a100-large --timeout 12h --secrets HF_TOKEN \
  cr.hf.co/suvadityamuk/trellis2-finetuning-train:latest \
  trellis2-train \
    --config shape \
    --latents suvadityamuk/gso-footwear-trellis2-latents \
    --push-to your-username/trellis2-footwear-lora \
    --run-name shape_lora \
    --push-path shape_lora \
```

#### 预处理为潜在变量

#### 准备 LoRA 适配器

[![准备 LoRA 适配器](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/lora_adapters.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/lora_adapters.png) 我们使用`peft` 库将 LoRA 适配器插入到选定的层中。 TRELLIS.2 有一个自定义前向传递，因此标准的“PeftModel()”包装器不起作用。相反，我们调用“inject_adapter_in_model()”。此函数将适配器直接添加到模型中并保留其自定义接口。

我们将可训练适配器权重保留为 32 位浮点（“fp32”）以实现数值稳定性，并使用 bfloat16（“bf16”）自动转换进行前向传递。自动转换让 PyTorch 对某些操作使用较低的精度，从而减少内存使用。自动铸造不会改变冻结主干权重的存储方式。
```
model = models.from_pretrained(cfg["ckpt"])
for block in model.blocks:
    block.use_checkpoint = True

inject_adapter_in_model(
    LoraConfig(
        r=cfg["rank"], lora_alpha=cfg["alpha"], target_modules=cfg["lora_targets"]
    ),
    model,
)

params = []
for name, p in model.named_parameters():
    p.requires_grad_("lora_" in name)
    if p.requires_grad:
        p.data = p.data.float()  # fp32 master weights for LoRA
        params.append(p)

model.cuda().train()
```
#### 培训

[![训练循环](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/training_loop.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/training_loop.png) 需要注意的是，我们的目标函数是古老的整流流匹配（如流行的图像生成模型，如 [Stable Diffusion 3](https://huggingface.co/collections/stabilityai/stable-diffusion-3)、[Flux 2](https://huggingface.co/collections/black-forest-labs/flux2) 等）。 TRELLIS.2在预训练中使用了相同的目标，因此它是微调的不错选择。有关理论，请阅读有关流匹配的[此博客](https://huggingface.co/spaces/ariG23498/flow-matching)。

我们仅更新稀疏结构和形状 DiT 中的 LoRA 参数。所有原始模型重量保持冻结。

> 下面的片段显示了一个阶段的核心训练循环。它们比容器代码更简单，并且不包含一些设置步骤。对于完整的工作流程，请使用容器命令。

我们初始化优化器并加载 DINOv3 以从输入图像中提取特征。
```
opt = torch.optim.AdamW(
    params, lr=cfg["lr"], weight_decay=cfg["weight_decay"], betas=(0.9, 0.95)
)

dino = DinoV3FeatureExtractor(
    cfg["image_cond_model"], image_size=cfg["image_size"]
).cuda()
```
然后，我们在训练循环中遵循以下步骤：

- 为每个样本采样一个时间步 *t*（对于稀疏结构流 DiT 使用 logitNormal，对于基于 TRELLIS.2 配置的形状流 DiT 使用uniform）。
- 生成与数据形状匹配的随机噪声并重塑 *t* 以进行广播。
- 基于 *t* 将干净数据与噪声混合（其中 *t = 0* 是噪声最小的数据，*t = 1* 是纯噪声）。
- 预测 *t × 1000* 的速度以匹配预训练条件。
- 将损失计算为预测速度和目标速度之间的均方误差（*x_t* 的一阶导数）。
```
def flow_loss(x0, cond):
    s = cfg["t_schedule"]

    t = (
        torch.rand(x0.shape[0])
        if s["name"] == "uniform"
        else torch.sigmoid(
            torch.randn(x0.shape[0]) * s["args"]["std"] + s["args"]["mean"]
        )
    )
    t = t.cuda()

    noise = (
        x0.replace(torch.randn_like(x0.feats))
        if cfg["sparse"]
        else torch.randn_like(x0)
    )

    tv = t.view(-1, *[1] * (len(x0.shape) - 1))

    x_t = (1 - tv) * x0 + (cfg["sigma_min"] + (1 - cfg["sigma_min"]) * tv) * noise

    pred, target = model(x_t, t * 1000, cond), (1 - cfg["sigma_min"]) * noise - x0

    return (
        F.mse_loss(pred.feats, target.feats)
        if cfg["sparse"]
        else F.mse_loss(pred, target)
    )
```
训练循环计算损失并更新适配器权重。梯度累积在每个优化器步骤之前添加 4 个小批次的梯度。梯度检查点通过在反向传播期间重新计算一些中间值来节省 GPU 内存。外部循环运行给定数量的优化器步骤，而内部循环则在一组批次上累积梯度。

对于每个批次，DINOv3 对调节图像进行编码。对于[无分类器指导](https://huggingface.co/papers/2207.12598) (CFG) dropout，循环将样本的随机部分 (p_uncond) 的条件设置为零。然后，它使用 bf16 自动广播计算流匹配损失。内部循环之后，它会剪辑梯度以防止非常大的更新，并执行优化器步骤。它每 10 步记录一次丢失情况，每 500 步保存一个适配器检查点。
```
for step in range(1, STEPS + 1):
    for _ in range(ACCUM):
        batch = next(batches)
        x0 = recursive_to_device(batch["x_0"], "cuda")

        with torch.no_grad():
            cond = dino(batch["cond"])
            cond[torch.rand(len(cond), device="cuda") < cfg["p_uncond"]] = 0

        with torch.autocast("cuda", dtype=torch.bfloat16):
            loss = flow_loss(x0, cond) / ACCUM

            loss.backward()

    torch.nn.utils.clip_grad_norm_(params, cfg["grad_clip"])

    opt.step()
    opt.zero_grad()
```
### 结果

我们训练了两种适配器：一种用于稀疏结构 DiT，一种用于形状 DiT。容器镜像中的 LoRA 配置文件包含完整的训练设置：稀疏结构流 DiT 的 [`ss_flow_lora_gso.json`](https://github.com/suvadityamuk/trellis2-finetuning/blob/master/container/trellis2/configs/lora/slat_flow_img2shape_lora_gso.json) 和[`slat_flow_img2shape_lora_gso.json`](https://github.com/suvadityamuk/trellis2-finetuning/blob/master/container/trellis2/configs/lora/slat_flow_img2shape_lora_gso.json)用于形状流DiT。每次运行都在 Hugging Face Jobs 上使用一台 A100 80 GB。稀疏结构运行耗时 7.2 小时，形状运行耗时 3.6 小时。

稀疏结构流 DiT 的训练损失一开始下降得很快，然后下降得更慢。形状流 DiT 的损失保持在大致相同的水平。这些曲线显示了训练目标如何变化，但它们并不直接测量生成的几何图形的质量。
[![损失](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/training_loss.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/training_loss.png)

流匹配损失随采样对象、噪声和时间步长的变化而变化。为了查明微调是否改善了几何形状，我们还必须比较保留对象的输出。
