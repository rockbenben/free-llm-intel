## 引言

3D 生成在机器人、仿真、媒体和娱乐领域有很多用途。在这些领域里，要让生成的对象遵守严格的规则、把模型和数据的表示标准化都很困难。文件格式有很多种，比如 [GLB](https://en.wikipedia.org/wiki/GlTF) 和 [PLY](https://en.wikipedia.org/wiki/PLY_(file_format))。[表示方式](https://huggingface.co/spaces/suvadityamuk/3d-representations-guide)也有很多种，例如[神经辐射场 (NeRFs)](https://www.matthewtancik.com/nerf)和[3D Gaussian splatting (3DGS)](https://en.wikipedia.org/wiki/Gaussian_splatting)。每一种各有优劣。

[TRELLIS](https://huggingface.co/papers/2412.01506) 引入了一种通用的内部表示，称为统一 latent 表示。它的解码器把这种表示转换成所需输出格式的 3D 模型。这样一来，你不必为每种表示格式准备不同的模型。

同一个团队后来发布了 [TRELLIS.2](https://huggingface.co/papers/2512.14692)，改进了模型对 3D 结构的表示。但两个模型都没有提供简便的办法，让它适配某个具体任务。

### 我们想改进什么

像 TRELLIS.2 这样的通用模型，可能会在对某个具体应用很关键的细节上出错。比如，用户可能需要家具模型有精确的几何形状。不针对这个任务做微调，预训练模型生成的几何形状就可能不够精确。我们的实验用了 GSO 的一个子集，包含 188 个鞋类对象。在最初的测试里，预训练模型生成的鞋看起来通常没问题，但鞋底不对。我们测试 LoRA 能否让鞋底更准确。

[![Sole Orbit Base](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/sole_orbit_base.gif)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/sole_orbit_base.gif)

我们的目标是用 [Google Scanned Objects (GSO)](https://huggingface.co/datasets/hugging-3d/google-scanned-objects) 数据集提升 TRELLIS.2 在某个特定对象类别上的表现。我们会说明哪些流水线组件该微调、哪些在训练时保持不动。这条流水线把结构、精细几何和材质分开，所以我们只微调对任务重要的组件。

[![Meme](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/meme.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/meme.jpg)

> 选什么来冻结，和选什么来微调一样重要。

### 我们会用到什么？

#### LoRA

LoRA 是 low-rank adaptation 的缩写，它在保持原始权重冻结的前提下，通过训练小型适配器矩阵来微调模型。这样既减少了可训练参数的数量，也减少了它们的梯度和优化器状态所需的内存。我们用 Hugging Face 的 PEFT 库来添加并训练这些适配器。更多内容见我们的 [LoRA 指南](https://huggingface.co/docs/peft/package_reference/lora)。

#### Hugging Face Jobs

Hugging Face Jobs 在云硬件上运行容器化的工作负载。我们用它做预处理和训练。想用自己的 GPU，可以看下面的本地 Docker 命令。开始之前，请确认你已经具备：

- 一个 HF_TOKEN，可以[从这里](https://huggingface.co/settings/tokens/new)获取
- 你的 Hugging Face 账号必须能[访问 DINOv3](https://huggingface.co/collections/facebook/dinov3)，因为 DINOv3 是门控模型
- 如果你用自己的数据集，请在开始之前把其中的网格上传到 Hub。

## TRELLIS.2 是怎么工作的

训练之前，先看看 TRELLIS.2 如何生成一个 3D 对象，以及我们要在哪里加 LoRA 适配器。

TRELLIS.2 有五个主要阶段：去掉图像背景、编码图像、预测粗略结构、生成精细几何、生成材质。随后流水线把结果导出为带纹理的网格。

[![TRELLIS.2 流水线](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/pipeline_lr.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/pipeline_lr.png)

### 编码输入图像

首先，BiRefNet 去掉输入图像的背景。接着 DINOv3-L 把图像编码成特征 token。生成模型用这些 token 来引导 3D 对象。

[![从像素到特征 token](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/image_to_tokens.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/image_to_tokens.png)

### 稀疏结构生成（Sparse Structure Flow）

稀疏结构流 DiT 预测对象的粗略形状。它是一个扩散 transformer (DiT)，生成一个大小为 16³ × 8 的小型 latent。随后，变分自编码器 (VAE) 解码器把这个 latent 转成 64 × 64 × 64 的占用网格。网格里每个体素表示该位置是否属于对象。体素就是三维中的像素。我们给这个模型加 LoRA 适配器，因为它的输出会引导几何阶段。
[![阶段 1](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage1_sparse_structure.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage1_sparse_structure.png)

### O-Voxel 与结构化 latent

O-Voxel 是 TRELLIS.2 的 3D 格式。它是一个稀疏体素网格，只保留对象表面上的体素。每个体素保存局部几何（比如网格顶点）和材质属性。由于这个格式很小，CPU 几秒钟就能把网格转成 O-Voxel，GPU 几秒钟就能把 O-Voxel 转回网格。

结构化稀疏 latent 来自 TRELLIS。它们把 3D 数据放在稀疏张量里，因此计算更快。模型只用到网格中大约 10% 的体素，不会在空体素上浪费算力。所以，形状流 DiT 和纹理流 DiT 都是稀疏 transformer，而稀疏结构流 DiT 是稠密 transformer。
[![O-Voxel](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/ovoxel_sparse.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/ovoxel_sparse.png)

### 几何生成（Shape Flow）

形状流 DiT 用占用网格和 DINOv3 特征 token 生成一个 latent。另一个 VAE 解码器再把这个 latent 转成分辨率为 512 × 512 × 512 的 O-Voxel 几何。

我们在这个阶段给 DiT 加 LoRA 适配器，因为它控制对象的形状。

[![阶段 2](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage2_shape.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage2_shape.png)

### 材质生成与网格创建

最后一个阶段，纹理流 DiT 以形状 latent 和 DINOv3 特征为输入，定义几何表面的材质和纹理。随后 VAE 解码器把 latent 转成每个体素的基础色、金属度、粗糙度和 alpha 值。我们不给这个阶段加 LoRA 适配器。我们的数据集有漫反射颜色贴图，但缺少这个阶段训练所需的独立材质贴图。而且，我们要解决的是鞋子的形状；基础模型已经能生成不错的颜色和纹理。

最后，流水线把几何和材质属性合成带纹理的网格，导出为 GLB 文件。

[![阶段 3](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage3_texture.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/stage3_texture.png)

## 规划

### 微调哪些组件

我们只给稀疏结构流 DiT 和形状流 DiT 加 LoRA 适配器。这两个 DiT 控制对象的形状和几何。我们冻结纹理流 DiT，保留它现有的能力。

我们的数据集里是带烘焙光照效果的漫反射颜色贴图。要训练纹理流 DiT，需要独立的材质贴图。我们数据集中的颜色贴图把表面颜色和光照混在了一起，因此不是这次训练的正确目标。

如果拿这些贴图去训练纹理流 DiT，它可能学会把光照当成表面属性，还可能忘掉之前学到的东西，也就是所谓的灾难性遗忘。

### 为什么用 LoRA

我们的子集是 GSO 中 1,030 个对象里的 188 只鞋。数据集这么小，LoRA 比全量微调更合适。全量微调成本高得多，还可能覆盖模型本来就做得好的部分（它学到的先验）。我们的配置给两个目标 DiT 总共训练约 930 万个适配器参数。稀疏结构流 DiT 的注意力和前馈 (MLP) 层用 rank 8 的适配器，形状流 DiT 的注意力层用 rank 16 的适配器。rank 决定适配器矩阵的大小，rank 越高，适配器能学到的越多。

### 你要运行什么

搭一套 3D 模型环境可能要装很多依赖、走很多安装步骤。我们提供两个 Docker 镜像（可以在 [Jobs](https://hf.co/jobs) 上跑，也可以在自己的机器上跑），里面装好了所需软件。一个用于预处理，一个用于微调。

要训练 LoRA 适配器并上传到 Hub：

- 让容器能访问你的数据。
- 为你的任务设置参数。
- 运行预处理容器。
- 运行微调容器。

接着我们会讲解微调脚本、它的各项设置，以及每项设置如何影响训练。

### 实验概览

实验分三部分来讲：

- **准备数据。** 把 GLB 或 OBJ 网格转成 TRELLIS.2 训练用的 latent 表示，并渲染输入图像。
- **训练适配器。** 用准备好的数据集和一份 LoRA 配置，为每个 DiT 各跑一个作业。
- **讲解代码。** 看容器如何加载数据、添加适配器并训练模型。

我们会把预处理后的数据集保存下来，供所有训练运行复用。

## 演练

### 在 Hugging Face Jobs 上运行

#### 预处理

预处理容器用 Blender 为每个对象渲染 16 个视图。LoRA 训练会用这些视图作为条件图像。Blender 通过 xvfb-run 工具在没有显示器的环境下运行。容器还会让每个对象走一遍[预处理流水线](https://github.com/microsoft/TRELLIS.2/blob/main/data_toolkit/README.md)。示例中间结果可以看[这个鞋类数据集](https://huggingface.co/datasets/suvadityamuk/gso-footwear-trellis2-latents)。我们这 188 个对象，在一个 a100-large 作业上完整跑一遍约需 1 小时。[这个配套仓库](https://github.com/suvadityamuk/trellis2-finetuning/blob/master/preprocess.py)里还有预处理流水线的精简版。

```
export HF_TOKEN=hf_xxx  

# Replace your-username with your Hugging Face username

hf jobs run -d --flavor a100-large --timeout 6h --secrets HF_TOKEN \
  cr.hf.co/suvadityamuk/trellis2-finetuning-prep:latest \
  trellis2-prep \
    --meshes your-username/my-meshes \
    --push-to your-username/my-meshes-trellis2 \
    --private --holdout 0.05 \
    --views 16 --workers 8
```

对于 Hugging Face Jobs，我们传了这些参数：

| flag | 含义 |
| --- | --- |
| `-d` | 后台运行：打印作业 ID 和 URL 后返回。要跟踪作业，运行 `hf jobs logs -f <id>` |
| `--flavor a100-large` | 硬件。我们用 a100-large (80 GB)。查看全部选项，运行 hf jobs hardware |
| `--timeout 6h` | 作业到这个时间就停止。两个命令都能续跑。预处理会跳过已完成的对象，训练从 --push-to 中最新的 checkpoint 继续 |
| `--secrets HF_TOKEN` | 把你的 token（来自 HF_TOKEN 或 hf auth login）作为加密环境变量发给作业。token 不会写进镜像 |
| `cr.hf.co/...:latest` | 要运行的镜像。它后面的所有内容都是在容器里执行的命令 |

这个容器还接受另外几个参数（无论跑在 Hugging Face Jobs 上还是用 Docker），可以[在这里查到文档](https://github.com/suvadityamuk/trellis2-finetuning#1-preprocess-trellis2-prep)。预处理流水线各步骤的说明在后面[这一节](https://huggingface.co/blog/3d-lora-finetuning#preprocessing-into-latents)。

#### LoRA 微调

训练容器加载准备好的数据集，以及一份配置预设或配置文件。它用 Trackio 记录训练指标，可以用 Trackio 面板监控运行。

我们用 ‘ss’ 和 ‘shape’ 表示训练 LoRA 的两种模式。‘ss’ 模式只微调 Sparse-Structure Flow DiT，‘shape’ 模式则微调 Shape Flow DiT。底层其实就是给每个阶段引用不同的 config.json 文件。更多细节见后面[这一节](https://huggingface.co/blog/3d-lora-finetuning#training)。

```
export HF_TOKEN=hf_xxx  # Replace your-username with your Hugging Face username

hf jobs run -d --flavor a100-large --timeout 12h --secrets HF_TOKEN \
  cr.hf.co/suvadityamuk/trellis2-finetuning-train:latest \
  trellis2-train --config ss \
    --latents your-username/my-meshes-trellis2 \
    --push-to your-username/my-trellis2-lora \
    --run-name ss_lora \
    --push-path ss_lora \
    --trackio-space your-username/trellis2-trackio

hf jobs run -d --flavor a100-large --timeout 12h --secrets HF_TOKEN \
  cr.hf.co/suvadityamuk/trellis2-finetuning-train:latest \
  trellis2-train --config shape \
    --latents your-username/my-meshes-trellis2 \
    --push-to your-username/my-trellis2-lora \
    --run-name shape_lora \
    --push-path shape_lora \
    --trackio-space your-username/trellis2-trackio \
    --set max_steps=3000 i_save=500
```

如果设置了 `--push-to`，容器会把适配器 checkpoint 上传到 Hub。为简洁起见，容器接受的参数也[记录在这里](https://github.com/suvadityamuk/trellis2-finetuning#3-train-trellis2-train)。[同一个仓库](https://github.com/suvadityamuk/trellis2-finetuning/blob/master/finetune.py)里还有精简版脚本。

如果你想拿[我们已经处理好的数据集](https://huggingface.co/datasets/suvadityamuk/gso-footwear-trellis2-latents)试着微调，直接用下面这组命令就行。

```
export HF_TOKEN=hf_xxx  

# Replace your-username with your Hugging Face username

# For the Sparse-Structure Flow DiT
hf jobs run -d --flavor a100-large --timeout 12h --secrets HF_TOKEN \
  cr.hf.co/suvadityamuk/trellis2-finetuning-train:latest \
  trellis2-train \
    --config ss \
    --latents suvadityamuk/gso-footwear-trellis2-latents \
    --push-to your-username/trellis2-footwear-lora \
    --run-name ss_lora \
    --push-path ss_lora \
    --trackio-space your-username/trellis2-trackio \
    --set max_steps=3000 i_save=500

# For the Shape Flow DiT
hf jobs run -d --flavor a100-large --timeout 12h --secrets HF_TOKEN \
  cr.hf.co/suvadityamuk/trellis2-finetuning-train:latest \
  trellis2-train \
    --config shape \
    --latents suvadityamuk/gso-footwear-trellis2-latents \
    --push-to your-username/trellis2-footwear-lora \
    --run-name shape_lora \
    --push-path shape_lora \
    --trackio-space your-username/trellis2-trackio \
    --set max_steps=3000 i_save=500
```

### 用 Docker 在本地运行

##### 预处理

命令和旗标与 Hugging Face Jobs 一样，只是 Docker 的选项不同。

```
# For preprocessing into latents
docker run --gpus all --rm --shm-size 16g -e HF_TOKEN=hf_xxx \
  -v hf-cache:/root/.cache/huggingface -v "$PWD/work":/workspace/work \
  cr.hf.co/suvadityamuk/trellis2-finetuning-prep:latest \
  trellis2-prep --meshes your-username/my-meshes --push-to your-username/my-meshes-trellis2
```

##### LoRA 微调

```
# For Sparse-structure Flow DiT
docker run --gpus all --rm --shm-size 16g \
  -v hf-cache:/root/.cache/huggingface -v "$PWD/work":/workspace/work \
  cr.hf.co/suvadityamuk/trellis2-finetuning-train:latest \
  trellis2-train --config ss --latents your-username/my-meshes-trellis2 \
    --push-to your-username/my-trellis2-lora --trackio-space your-username/trellis2-trackio

# For Shape Flow DiT
docker run --gpus all --rm --shm-size 16g \
  -v hf-cache:/root/.cache/huggingface -v "$PWD/work":/workspace/work \
  cr.hf.co/suvadityamuk/trellis2-finetuning-train:latest \
  trellis2-train --config shape --latents your-username/my-meshes-trellis2 \
    --push-to your-username/my-trellis2-lora --trackio-space your-username/trellis2-trackio
```

如果你想在自己选的机器上本地使用[已预处理好的数据集](https://huggingface.co/datasets/suvadityamuk/gso-footwear-trellis2-latents)，用下面的命令：

  -v "$PWD/work":/workspace/work \
  cr.hf.co/suvadityamuk/trellis2-finetuning-train:latest \

## 训练流水线内部

#### 预处理为 latent

[![预处理](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/preprocessing.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/preprocessing.png) 我们用 TRELLIS.2 冻结的编码器把输入网格转成训练用的 latent。这些 latent 会保存下来，之后的运行就不必再编码一次网格。

我们还在 Blender 里为每个对象渲染 16 个视图。训练时，给每个样本随机选一个视图作为条件图像。188 个对象里留 9 个用于评估，在其余 179 个上训练。这些留出的对象能检验适配器在训练中没见过的对象上是否奏效。

[![条件图像](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/conditioning_views.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/conditioning_views.png)

> Blender 为其中一个对象渲染的部分视图

第一段代码把数据准备好。`FLOW` 选择要训练的流 DiT（`ss` 或 `shape`），`STEPS` 设置优化器步数。batch size 取 4、梯度累积 4 步，等效 batch size 就是 16。接着，这段代码加载所选流 DiT 的 LoRA 配置文件，按 TRELLIS.2 的格式构造数据集，去掉留出的对象，再建好用于微调的 data loader。

```
cfg = json.load(
    open(
        {
            "ss": "/workspace/TRELLIS.2/configs/lora/ss_flow_lora_gso.json",
            "shape": "/workspace/TRELLIS.2/configs/lora/slat_flow_img2shape_lora_gso.json",
        }[FLOW]
    )
)

key, latents = {
    "ss": ("ss_latent", "ss_latents/ss_enc_conv3d_16l8_fp16_64"),
    "shape": ("shape_latent", "shape_latents/shape_enc_next_dc_f16c32_fp16_512"),
}[FLOW]


roots = json.dumps(

        "gso": {
            key: f"{DATA}/{latents}",
            "render_cond": f"{DATA}/renders_cond",
            "meta": DATA,
        }
    }
)

ds = getattr(datasets, cfg["dataset"])(roots, **cfg["dataset_args"])

holdout = set(open(f"{DATA}/holdout.txt").read().split())
ds.instances = [(root, sha) for root, sha in ds.instances if sha not in holdout]

    DataLoader(
        ds,
        batch_size=BATCH,

```

#### 准备 LoRA 适配器

[![准备 LoRA 适配器](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/lora_adapters.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/lora_adapters.png) 我们用 `peft` 库把 LoRA 适配器插进选定的层。TRELLIS.2 有自定义的前向传播，标准的 `PeftModel()` 包装器用不了，所以我们改调用 `inject_adapter_in_model()`。这个函数把适配器直接加到模型上，并保留它原有的自定义接口。

可训练的适配器权重保留 32 位浮点（`fp32`）以保证数值稳定，前向传播则用 bfloat16（`bf16`）自动精度转换。借助 autocasting，PyTorch 可以对部分运算使用较低精度，从而减少显存占用。autocasting 不改变冻结主干权重的存储方式。

```
model = models.from_pretrained(cfg["ckpt"])
for block in model.blocks:
    block.use_checkpoint = True

inject_adapter_in_model(
    LoraConfig(
        r=cfg["rank"], lora_alpha=cfg["alpha"], target_modules=cfg["lora_targets"]
    ),
    model,
)

params = []
for name, p in model.named_parameters():
    p.requires_grad_("lora_" in name)
    if p.requires_grad:
        p.data = p.data.float()  # fp32 master weights for LoRA
        params.append(p)

model.cuda().train()
```

#### 训练

[![训练循环](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/training_loop.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/training_loop.png) 要注意的是，这里的目标函数就是经典的 rectified flow matching（在 [Stable Diffusion 3](https://huggingface.co/collections/stabilityai/stable-diffusion-3)、[Flux 2](https://huggingface.co/collections/black-forest-labs/flux2) 这类主流图像生成模型里都能见到）。TRELLIS.2 预训练用的也是同一个目标，所以拿来做微调很合适。想了解理论，可以看[这篇](https://huggingface.co/spaces/ariG23498/flow-matching)关于 flow matching 的博客。

我们只更新稀疏结构和形状 DiT 里的 LoRA 参数，所有原始模型权重保持冻结。

> 下面的代码片段展示单个阶段的核心训练循环。它们比容器里的代码更简单，省略了一些设置步骤。完整流程请用容器命令。

初始化优化器，并加载 DINOv3 从输入图像里提取特征。

```
opt = torch.optim.AdamW(
    params, lr=cfg["lr"], weight_decay=cfg["weight_decay"], betas=(0.9, 0.95)
)

dino = DinoV3FeatureExtractor(
    cfg["image_cond_model"], image_size=cfg["image_size"]
).cuda()
```

然后在训练循环里按下面的步骤走：

- 给每个样本采样一个时间步 *t*（按 TRELLIS.2 的配置，稀疏结构流 DiT 用 logitNormal，形状流 DiT 用 uniform）。
- 生成与数据形状一致的随机噪声，并重塑 *t* 以便广播。
- 按 *t* 把干净数据和噪声混合（*t = 0* 是噪声最少的数据，*t = 1* 是纯噪声）。
- 在 *t × 1000* 处预测速度，以匹配预训练条件。
- 损失取预测速度与目标速度（*x_t* 的一阶导数）之间的均方误差。

```
def flow_loss(x0, cond):
    s = cfg["t_schedule"]

    t = (
        torch.rand(x0.shape[0])
        if s["name"] == "uniform"
        else torch.sigmoid(
            torch.randn(x0.shape[0]) * s["args"]["std"] + s["args"]["mean"]
        )
    )
    t = t.cuda()

    noise = (
        x0.replace(torch.randn_like(x0.feats))
        if cfg["sparse"]
        else torch.randn_like(x0)
    )

    tv = t.view(-1, *[1] * (len(x0.shape) - 1))

    x_t = (1 - tv) * x0 + (cfg["sigma_min"] + (1 - cfg["sigma_min"]) * tv) * noise

    pred, target = model(x_t, t * 1000, cond), (1 - cfg["sigma_min"]) * noise - x0

    return (
        F.mse_loss(pred.feats, target.feats)
        if cfg["sparse"]
        else F.mse_loss(pred, target)
    )
```

训练循环计算损失并更新适配器权重。梯度累积在每次优化器更新前，把 4 个小 batch 的梯度加起来。梯度检查点通过在反向传播时重算部分中间值来节省 GPU 显存。外层循环跑指定数量的优化器步，内层循环则在一组 batch 上累积梯度。

每个 batch 里，DINOv3 对条件图像做编码。为了做 [classifier-free guidance](https://huggingface.co/papers/2207.12598) (CFG) dropout，循环会把随机一部分样本 (p_uncond) 的条件置零。随后在 bf16 autocast 下计算 flow matching 损失。内层循环结束后，裁剪梯度以防更新幅度过大，再走一次优化器步。它每 10 步记录一次损失，每 500 步保存一个适配器 checkpoint。

```
for step in range(1, STEPS + 1):
    for _ in range(ACCUM):
        batch = next(batches)
        x0 = recursive_to_device(batch["x_0"], "cuda")

        with torch.no_grad():
            cond = dino(batch["cond"])
            cond[torch.rand(len(cond), device="cuda") < cfg["p_uncond"]] = 0

        with torch.autocast("cuda", dtype=torch.bfloat16):
            loss = flow_loss(x0, cond) / ACCUM

            loss.backward()

    torch.nn.utils.clip_grad_norm_(params, cfg["grad_clip"])

    opt.step()
    opt.zero_grad()
```

### 结果

我们训练了两个适配器：一个给稀疏结构 DiT，一个给形状 DiT。容器镜像里的 LoRA 配置文件包含完整的训练设置：稀疏结构流 DiT 用 [`ss_flow_lora_gso.json`](https://github.com/suvadityamuk/trellis2-finetuning/blob/master/container/trellis2/configs/lora/slat_flow_img2shape_lora_gso.json)，形状流 DiT 用 [`slat_flow_img2shape_lora_gso.json`](https://github.com/suvadityamuk/trellis2-finetuning/blob/master/container/trellis2/configs/lora/slat_flow_img2shape_lora_gso.json)。每次运行都在 Hugging Face Jobs 上用一张 A100 80 GB。稀疏结构那次跑了 7.2 小时，形状那次 3.6 小时。

稀疏结构流 DiT 的训练损失一开始掉得很快，之后变慢。形状流 DiT 的损失基本维持在同一水平。这些曲线反映训练目标怎么变化，但并不能直接衡量生成几何的质量。
[![损失](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/training_loss.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/training_loss.png)

flow matching 损失会随采样到的对象、噪声和时间步变化。要判断微调有没有改善几何，还得比较留出对象上的输出。

下图比较了 9 个留出对象里 5 个的输出，依次给出输入图像、基础模型的生成结果、做过旋转调整后的基础输出、加了鞋类适配器后的输出，以及参考扫描。在这些例子里，微调后模型的鞋底更接近扫描结果。

[![留出对象的网格](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/heldout_meshes.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/heldout_meshes.png)

我们还用三个指标评估测试集上的几何：

| 指标 | 含义 |
| --- | --- |
| Chamfer 距离 | 一个表面上的点到另一个表面最近点的距离，两个方向都测。越低越好。 |
| F-score @ 0.02 | 精确率（生成的表面有多少靠近参考）和召回率（参考表面有多少被生成的表面覆盖）的综合。这里匹配阈值取扫描包围盒对角线的 2%。越高越好。 |
| 法线一致性 | 表面方向的一致程度。表面法线是垂直于表面的向量。越高越好。 |

### [![留出对象指标](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/heldout_metrics.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/3d-lora-finetuning/heldout_metrics.png)

图表里 9 个对象的比较中，基础模型的平均 F-score 是 0.276，带鞋类适配器的模型是 0.803。Chamfer 距离从 0.174 降到 0.033，法线一致性从 0.530 升到 0.804。两个适配器都加上后，9 个留出对象的 F-score 全部变好。

## 后续方向

呼，就到这儿！我们给控制几何的两个模型组件加上 LoRA 适配器，把 TRELLIS.2 微调成了专门生成鞋类的模型。数据只准备了一次，适配器分在不同作业里训练，再在留出对象上评估输出。

最主要的经验是：选训练目标时，要让它和你面对的问题、手里的数据对得上。这次实验里，我们微调了结构和形状阶段，冻结了纹理阶段。

接下来可以看看同样的选择能不能帮到其他 3D 生成模型，比如 [Pixal3D](https://github.com/TencentARC/Pixal3D) 和 [UniLat3D](https://github.com/UniLat3D)。

Gaussian-splat 和世界生成模型，比如 [HunyuanWorld 2.0](https://github.com/Tencent-Hunyuan/HY-World-2.0) 和 [NVIDIA Lyra 2.0](https://nv-tlabs.github.io/Project-Lyra/)，也是可能的下一步。它们的表示和训练流水线可能需要不同的方法。
