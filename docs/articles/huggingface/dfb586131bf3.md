## 架构

Muse Glimmer 是一个 30B 参数的稠密模型，由以下部分组成：

- 用于视觉的 2B ViT 风格编码器（Perception Encoder）
- 28B 参数的文本解码器

除主 VLM 外，还有一个基于 DFlash 实现的推测解码草稿模型（drafter）。这个模块是可选的，用一些内存开销换取明显更快的生成。我们发现这个 drafter 特别适合结构化内容生成，比如写代码。

### 文本解码器

语言模型使用了以下架构组件：

- **混合注意力：** 三层使用旋转位置编码的滑动窗口注意力层（窗口 2,048 token），之后跟一层使用全注意力和 NoPE（无位置编码）的层。模式即 (SWA, SWA, SWA, Full)，重复 13 次共 52 层。这让模型既能用 RoPE 保留相对顺序与距离信息，又能用 NoPE 全局保留信息。
- **门控分组查询注意力（Gated GQA）：** 每个 KV 头被 16 个 query 头共享，KV 缓存内存因此降低 16 倍，生成更快也更便宜。
- **带额外 query 缩放的 Q-K 归一化：** 计算注意力之前，Muse Glimmer 对每个 query 和 key 头施加 RMS 归一化，以保持注意力 logits 稳定。之后 query 会乘上一个缩放因子，用于设定归一化后的目标 logit 尺度。这个额外的 query 缩放相当于在 softmax 层面做了一个逆温度。

### Perception Encoder

Muse Glimmer 用单个图像编码器同时处理图像和视频。与其他 VLM 相对较小的视觉编码器不同，这是一个体量可观的 2B ViT 风格模型，按 Perception Encoder 架构设计。Perception Encoder 此前由 Meta [作为多种下游空间与多模态任务的骨干](https://huggingface.co/papers/2504.13181)推出。编码器把图像切成 2 帧 x 3 通道 x 14 x 14 的 patch，通过一个线性层投影，再加上传自学习位置表的插值绝对位置编码。这些嵌入随后送入由 50 层和 GELU MLP 组成的视觉塔。与语言模型类似，注意力模式是三层窗口注意力加一层全注意力；注意力层内部对 query 和 key 应用 2D RoPE。

Transformer 之后，pixel shuffle 把相邻空间 token 以 2x2 组拼接，在不丢弃通道的情况下把图像 token 数减少 4 倍。合并后的特征再被投影到文本解码器的共享 embedding 空间。

视频按帧经过同一个编码器，每帧转成 patch（形状为 [batch, temporal groups, grid height, grid width, 2 frames, 3 channels, 14, 14]）。处理器以每秒 2 帧为目标，并把片段上限设为在整个视频上均匀采样的 96 帧。处理器创建带时间戳的视频占位符，把文本与帧交错，例如 "Time: 0.0s <|video|> x N"，其中最终的视频 embedding 会在最后的投影层之前被替换进去。

## Transformers

升级 transformers 到最新版本即可使用 Muse Glimmer。

```
pip install --upgrade transformers accelerate
```

Muse Glimmer 在 transformers 中获得 day-0 支持，主模型和推测解码 drafter 都有。用 `AutoModelForMultimodalLM` 和 `AutoProcessor` 类即可加载模型和处理器。

```
from transformers import AutoProcessor, AutoModelForMultimodalLM

MODEL_ID = "meta-models/Muse-Glimmer-30B"

# Load model
processor = AutoProcessor.from_pretrained(MODEL_ID)
model = AutoModelForMultimodalLM.from_pretrained(
    MODEL_ID,
    dtype="auto",
    device_map="auto"
)
```

同一段代码在 NVIDIA (CUDA)、AMD (ROCm) 和 Intel (XPU) GPU 上可原样运行，`device_map="auto"` 会把模型放到可用的加速器上。

### 纯文本推理

加载模型后，可以按下面方式做纯文本推理。

```
from transformers import AutoProcessor, AutoModelForMultimodalLM

MODEL_ID = "meta-models/Muse-Glimmer-30B"

# Load model
processor = AutoProcessor.from_pretrained(MODEL_ID)
model = AutoModelForMultimodalLM.from_pretrained(
    MODEL_ID,
    dtype="auto",
    device_map="auto"
)

# Prompt
messages = [
    {"role": "user", "content": "Write a short joke about saving RAM."},
]

# Process input
inputs = processor.apply_chat_template(
    messages,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
    add_generation_prompt=True,
    reasoning_strength="low"
).to(model.device)
input_len = inputs["input_ids"].shape[-1]

# Generate output
outputs = model.generate(**inputs)
response = processor.decode(outputs[0][input_len:], skip_special_tokens=False)
print(response)
```

## Llama.cpp

Muse Glimmer 有 llama.cpp 的 day-0 支持。Meta 在[这个仓库](https://huggingface.co/meta-models/Muse-Glimmer-30B-GGUF)发布了校准过的量化版本，Unsloth 也在发布优化量化版本。DFlash 推测解码同样支持。你可以用预编译的 llama 二进制启动 llama 服务器或 CLI。安装 llama.cpp：

curl -LsSf https://llama.app/install.sh | sh
```

然后按如下方式启动服务器。

```

## 推测解码

DFlash 使用一个轻量的 block-diffusion 草稿模型，在解码阶段给出相同输出的同时提供额外加速。Transformers 和 llama.cpp 都提供了 Muse Glimmer 的 DFlash drafter 的 day-0 支持。

下面可以看到推测解码在真实场景中如何加速生成。视频左侧是带 DFlash 的 llama.cpp WebUI，右侧是普通生成。

### 用 transformers 做推测解码

按如下方式加载 drafter 和模型，推理时与基础模型一样，只需多一个参数（见下面的代码片段）。

```
import torch
from transformers import AutoProcessor, MuseGlimmerAssistantModel, MuseGlimmerForConditionalGeneration

model_id = "meta-models/Muse-Glimmer-30B"
assistant_model_id = "meta-models/Muse-Glimmer-30B-assistant"
target = MuseGlimmerForConditionalGeneration.from_pretrained(model_id, dtype=torch.bfloat16, device_map="auto")
assistant = MuseGlimmerAssistantModel.from_pretrained(assistant_model_id, dtype=torch.bfloat16, device_map="auto")
processor = AutoProcessor.from_pretrained(model_id)

messages = [
    {
        "role": "user", "content": [
            {"type": "image", "url": "https://huggingface.co/datasets/merve/vl-test-suite/resolve/main/SF.png"},
            {"type": "text", "text": "What is shown in this image?"}
        ]
    }
]

inputs = processor.apply_chat_template(
    messages,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
    add_generation_prompt=True,
    reasoning_strength="low"
).to(target.device)
input_len = inputs["input_ids"].shape[-1]

outputs = target.generate(
    **inputs,
    assistant_model=assistant,
    speculation_type="dflash",
    do_sample=True
)
response = processor.decode(outputs[0][input_len:], skip_special_tokens=False)
print(response)
```

### 用 llama.cpp 做推测解码

用以下命令启动 llama server。`--spec-draft-n-max` 参数控制 DFlash 在每个推测解码步骤中提议多少个未来 token。Muse Glimmer 的 DFlash 模型按块大小 16 训练——1 个锚 token 加 15 个提议 token，所以大于 15 的值都会被截到 15。

```
llama serve -hf meta-models/Muse-Glimmer-30B-GGUF --spec-type draft-dflash --spec-draft-n-max 15
```

也可以在 llama cli 中使用推测解码 drafter：

```
llama cli -hf meta-models/Muse-Glimmer-30B-GGUF --spec-type draft-dflash
```

## 用 TRL 微调

你可以用 TRL 以从 SFT 到 Async GRPO 的多种方法微调 Muse Glimmer。我们在每张 80GB 显存的 Hopper 级 GPU 上用 bf16 跑了两个实验。

| 负载 | 实际最低配置 |
| --- | --- |
| 推理 / 评测，BF16 | 1×80 GB H100 |
| LoRA SFT，BF16 | 1×80 GB H100，microbatch 1 + checkpointing |
| 全量 SFT，BF16 | 8×80 GB H100，配 FSDP/ZeRO-3 |
| LoRA GRPO，Transformers rollouts | 1×80 GB H100 可行，但慢且紧张 |
| LoRA GRPO，独立 vLLM rollout 服务器 | 8×H100：4 张 rollout + 4 张训练 |
| 全量微调 GRPO | 8 张 GPU 通常不够 |

作为本次发布的一部分，我们附带了一个[在 MolmoWeb 数据集小切分上微调 Muse Glimmer 的例子](https://huggingface.co/merve/smol-vision/blob/main/qlora_click_grounding.ipynb)。它展示了如何让模型生成结构化输出，以及如何在图像上微调。

我们还试验了在 [OpenCode 上配合 AsyncGRPO 示例运行该模型](https://github.com/huggingface/trl/blob/v1.14.1/examples/async_grpo_opencode/async_grpo_opencode.py)。模型表现出很强的编程能力，所以我们鼓励你试试用 OpenEnv 和 TRL 中的编程环境来训练。

这里有一些好玩的 Muse Glimmer 体验方式。在我们看来，这个模型最酷之处在于它是一个会写代码的本地规模个人助理。这意味着你可以让它做这些事：量化自己、在 Hub 上找到自己的量化权重、把自己部署到 inference endpoints，甚至针对特定硬件优化自己！Team local 冲呀 🚀

## 把 OpenClaw 连到 Muse Glimmer

假设该 Inference Endpoint 暴露了 OpenAI 兼容的 `/v1` API。

在 OpenClaw 网关环境中设置 `HF_TOKEN`，然后把下面内容加到 `~/.openclaw/openclaw.json`：

OpenClaw 配置

```
{
  models: {
    mode: "merge",
    providers: {
      muse: {
        baseUrl: "https://YOUR-ENDPOINT.endpoints.huggingface.cloud/v1",
        apiKey: {
          source: "env",
          provider: "default",
          id: "HF_TOKEN"
        },
        api: "openai-completions",
        authHeader: true,
        models: [{
          id: "meta-models/Muse-Glimmer-30B",
          name: "Muse Glimmer",
          reasoning: false,
          input: ["text", "image"],
          contextWindow: 32768,
          maxTokens: 8192
        }]
      }
    }
  },
  agents: {
    defaults: {
      model: { primary: "muse/meta-models/Muse-Glimmer-30B" }
    }
  }
}
```

重启 OpenClaw：

```
openclaw gateway restart
```

在新会话中验证：

```
openclaw agent --message "Reply with: muse-ready"
```

如果 endpoint 的 `/v1/models` 返回的模型 ID 与上文不同，请使用它返回的准确 ID。

### 嘿 Muse Glimmer，量化你自己

如果把 Muse Glimmer 接入 [Hugging Face MCP](https://huggingface.co/mcp) 并更新它的 [`AGENTS.md`](http://AGENTS.md)，它就获得了在 Hub 上找到自己量化版本并在本地运行的能力。想做私密的事、或者只想省钱时，这很好用。

如果你做第二次，Muse Glimmer 会发现缓存的权重并直接切换过去，所以不妨加一条顺手的命令，比如 `/spawn`。

Muse Glimmer 会检查本机与 Hub，选择或创建 Q4_K_M GGUF，启动 llama-server，并验证模型发现和 chat completion。最终你会得到一个更小的本地构建，藏在 OpenAI 兼容 API 后面。这是我们加到 `AGENTS.md` 里的提示。

### 嘿 Muse Glimmer，部署你自己

Muse Glimmer 也能处理反向操作。让 Glimmer 把自己部署到 Hugging Face Inference Endpoints——当你想在某些前沿硬件上提速时，这很有用。

注：你也可以[直接把 Muse Glimmer 部署到 Inference Endpoints](https://endpoints.huggingface.co/huggingface/new/meta-models/Muse-Glimmer-30B)，然后接上你的智能体。

Muse Glimmer 会钉住模型 revision，把它部署到受保护的 Hugging Face Inference Endpoint，并验证健康检查、模型发现和 chat completion，然后把 Claw 智能体连接起来，同时保留密钥与回滚能力。这是我们加到 [`AGENTS.md`](http://AGENTS.md) 的提示。Muse Glimmer 还需要 [Hugging Face MCP](https://huggingface.co/mcp) 和/或 [Hugging Face CLI 与 Skills](https://huggingface.co/docs/hub/en/agents-skills)。

Inference Endpoint 部署提示

```
## Hugging Face Inference Endpoint deployment

When asked to deploy on Hugging Face Inference Endpoints, perform the work; do
not give instructions.

1. Inspect Hugging Face authentication, the current model repository, and any
   existing endpoints.
2. Confirm the exact model repository and immutable revision through the Hub
   API; inspect its architecture, configuration, and chat template.
3. Confirm that the model is supported by vLLM, then deploy or update a
   protected Inference Endpoint using the managed native vLLM engine.
4. Choose an available region and the smallest suitable accelerator. Use one
   replica and enable scale-to-zero when supported.
5. Preserve the previous endpoint configuration for rollback. Do not expose
   tokens, publish private weights, or replace an unrelated endpoint.
6. Wait for the endpoint to become ready. If startup fails, inspect the logs

7. Validate `/health`, `/v1/models`, and `/v1/chat/completions`, requiring the
   expected model and non-empty, correct content. When agent use is required,

8. Configure the Claw agent to use the endpoint's OpenAI-compatible `/v1` URL,
   storing credentials as secrets and retaining the previous provider as
   rollback. Test the connection in a fresh session.
9. Report concise progress and finish with the repository, revision, engine,
   hardware, endpoint URL, scaling state, and validation results. Claim
   completion only after every required check passes.
```

### 嘿 Muse Glimmer，优化你自己

最后，让 Muse Glimmer 做点轻量 RSI（自我改进）。我们可以指示我们的智能体针对特定硬件（这里是 Nvidia H100）优化自己的推理引擎。要做到这一点，智能体需要使用另一个推理引擎，比如上面提到的 Inference Endpoints。

Muse Glimmer 给自己在单张 H100 上的 serving 栈做基准测试，固定负载、一次只试一个可逆的改动。它只保留通过正确性检查的收益，最终给出最快且可复现的配置。这是我们加到 [`AGENTS.md`](http://AGENTS.md) 的提示。Muse Glimmer 需要 [Hugging Face MCP](https://huggingface.co/mcp) 和 [Hugging Face CLI 与 Skills](https://huggingface.co/docs/hub/en/agents-skills)。

自我优化提示

```
You are Muse Glimmer acting as an autonomous inference-optimization engineer for your own serving stack.

Goal: maximize valid single-H100 aggregate completion throughput in tokens/second.

Protocol:
1. Establish a correctness-passing baseline.
2. Test one reversible optimization at a time.
3. Keep the prompt, concurrency, sampling, request count, warm-up, and decode length fixed.
4. Reject results that fail correctness or prefix checks.
5. Record every experiment chronologically with its configuration, raw throughput, correctness, and delta.
6. Keep improvements and revert regressions.
7. Stop after six consecutive regressions or when the experiment budget is exhausted.
8. Report the best valid configuration and exact reproduction command.

Create a minimal scientific animation of the results:
- white background;
- raw tokens/second—never normalize;
- one point revealed per experiment;
- connect every point chronologically;
- begin with the lowest valid result;
- stop at the best result;
- export as a GIF.

Never fabricate, interpolate, or count correctness-failing measurements.
```
