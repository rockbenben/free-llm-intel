# 在任意云上运行 AI 负载，存储留在 Hugging Face：SkyPilot 实现零出口费用存储

对多数团队来说，模型和数据集住在某朵云某个区域的桶里。而你买到的 GPU——无论用于开发、训练还是服务——越来越多地和你的数据不在同一朵云。两者一旦分离，光是把自己的数据读进自己的 GPU，你就要交一笔跨云传输税。

我们与 Hugging Face 一起把这两半接上了：模型和数据集留在 Hub 上，SkyPilot 则在任何有 GPU 的集群上跑计算（开发、训练或服务）。用一个 `hf://` URL 加上你已有的 `HF_TOKEN`，就能把 Hugging Face Bucket 或任何 Hub 仓库挂载进 SkyPilot 任务，然后到有容量的地方去运行。Hugging Face 不收出口费，所以在任何云上把数据读进 GPU 都不花钱。

新东西如下：

- **Hub 数据进任何任务。** `store: hf` 用一个 `hf://` URL 和你的现有 `HF_TOKEN`，把 Hugging Face **Bucket**（可读写）或任何**模型/数据集/Space 仓库**（只读）挂载进 SkyPilot 任务，支持 `MOUNT` 或 `COPY` 两种方式。
- **在任何云的任何 GPU 上运行。** [SkyPilot](https://docs.skypilot.co/) 能在 20+ 云、Kubernetes、Slurm 和本地机房里为任务找到算力，同一次运行可以用你预留或按需 GPU 里当前可用的一块，无论哪家供应商。
- **读数据零出口费。** Hugging Face Storage [不收出口或 CDN 费用](https://huggingface.co/pricing)，所以无论 SkyPilot 把任务调度到哪里，它都从同一个桶直接读取模型和数据集——不需要按云准备副本，也没有把数据拉过来的出口账单。
- **Xet 支撑的去重。** Bucket 构建在 [Xet](https://huggingface.co/docs/hub/xet/overview) 之上，增量 checkpoint 和模型变体只存储和传输发生变化的数据块。
- **共同构建。** [Hugging Face](https://huggingface.co/) 与 [SkyPilot](https://docs.skypilot.co/) 联合发布了这一能力，Hugging Face 团队还把让它在非特权容器中可用的 `hf-mount` FUSE 修复提交进了上游。

## Hugging Face Storage 成为 SkyPilot 的一等后端

[![SkyPilot mounts Hugging Face models, datasets, and checkpoints into jobs running on reserved GPU clusters across CoreWeave, Nebius, GCP, and 20+ more, with zero-egress reads.](https://huggingface.co/blog/assets/skypilot-hf-storage/architecture.png)](https://huggingface.co/blog/assets/skypilot-hf-storage/architecture.png)

SkyPilot 任务本就支持读写各云对象存储（S3、GCS、Azure、R2 等），以本地路径挂载。Hugging Face Storage 现在以 `store: hf` 加入这个列表，通过 `hf://` 方案访问：

```
file_mounts:
  # A Hugging Face Bucket, read-write, for checkpoints, logs, processed data.
  /checkpoints:
    source: hf://buckets/my-org/qwen-sft
    store: hf
    mode: MOUNT # or COPY
  # A model repo, mounted read-only.
  /base-model:
    source: hf://Qwen/Qwen3.5-4B
    store: hf
    mode: MOUNT
  # A dataset repo, pinned to a revision, read-only.
  /data:
    source: hf://datasets/my-org/my-dataset@main
    store: hf
    mode: MOUNT
```

这一个 `hf://` 方案覆盖了整个生命周期：从仓库读**模型**和**数据集**，训练时把 **checkpoint** 写进 Bucket，完成后把模型发布回仓库，服务时再拉上推理服务器。多数团队本来就把模型和数据集放在 Hub 上，所以没有迁移步骤，也不用新开存储账户。

`MOUNT` 使用 Hugging Face 的 [`hf-mount`](https://github.com/huggingface/hf-mount) FUSE 后端，桶或仓库会以本地路径出现，与 SkyPilot 的其他 FUSE 挂载（`gcsfuse`、`blobfuse2`、`rclone`、`goofys`）并列。取数发生在文件系统层：你的代码发出 `read()` 时，驱动只从 Xet 后端拉取对应字节——只有真正触碰到的数据才过网，`hf-mount` 还维护一个磁盘缓存让重复读取留在本地。这个磁盘缓存正是 SkyPilot 其他后端在 [`MOUNT_CACHED`](https://docs.skypilot.co/en/latest/reference/storage.html) 下的行为，而普通 `MOUNT` 则是每次读取都从桶里流式传输、本地不留。对 `hf` 存储，`MOUNT` 与 `MOUNT_CACHED` 行为一致，两种模式都会保留缓存。

因为读取是惰性的，一个进程可以在大文件下载完之前就开工，不必阻塞等待整个副本。这让 GPU 几乎立刻忙起来——数据流入即训练，而不是边拷贝边空烧（还计费）。收益最大的是第一个 epoch，此时尚无缓存。`COPY` 走另一条路，预先通过 `huggingface_hub` 下载，无特殊要求。

认证就用你已有的 token。在环境里设置 `HF_TOKEN`，再用 [`--secret HF_TOKEN`](https://docs.skypilot.co/en/latest/running-jobs/environment-variables.html) 交给任务；无论任务落到哪朵云，SkyPilot 都用它完成挂载。一个 token 通吃 AWS、GCP、Azure、Nebius、Lambda 或你自己的 Kubernetes 集群，不用再管各云的桶密钥。

## 零出口费：存储不再决定你在哪里跑

GPU 容量如今很少来自一个地方。为了凑够 H100/H200，团队同时在多家供应商持有预留和承诺容量（一块超大规模云的、一个 neocloud 集群，也许还有本地机柜），哪里有配额就在哪里跑。SkyPilot 正是为此而生：一份任务描述，调度到 20+ 云、Kubernetes 和本地机房，落在任何一个空闲的预留集群上。

对象存储一直是那个坑。对象存储按云按区域划分，要给别家数据中心里的 GPU 或推理服务器喂数据，要么在每个供应商的桶里各放一份副本，要么付费跨云搬运。多数云对离开其网络的数据收取出口费（AWS 约 $0.09/GB），同一朵云跨区域也经常收费。把基座模型拉到每台推理节点，或在另一朵云的集群上迭代多个 epoch 数据集，会在已预留的 GPU 费用之外再加一笔可观账单。结果团队被迫把每次运行钉死在持有数据的那家供应商，让其余容量空转。

Hugging Face Storage 把这笔开销从最疼的地方——读取侧——拿掉了：[没有出口和 CDN 费用](https://huggingface.co/pricing)，存储 $12-18/TB/月（对比 AWS S3 约 $23/TB 外加出口费），同一个桶所有集群都能访问，无论 GPU 在哪读取都免费。写回仍然要付你计算云平时的出口费，与写到任何云外存储一样；但对多数 AI 工作负载来说读取占大头：数据集要流式过多个 epoch，模型权重要拉上每台新的训练或推理节点。于是你不必再把每次运行钉在持有数据副本的那家供应商。

## 一个快速基准

为拿到一些基准数字，我们跑了一个小微调：用 TRL 的 [`SFTTrainer`](https://huggingface.co/docs/trl/sft_trainer) 在 [`HuggingFaceH4/Multilingual-Thinking`](https://huggingface.co/datasets/HuggingFaceH4/Multilingual-Thinking) 数据集上微调 [`Qwen/Qwen3.5-4B`](https://huggingface.co/Qwen/Qwen3.5-4B)，模型从 Hub 仓库只读挂载，每个 checkpoint 写入一个 Hugging Face Bucket。同一份 SkyPilot YAML 分别在 AWS、GCP、Lambda 上运行，只改 `--infra`。SkyPilot 把每个任务放到 GPU 空闲处，三个云读写的是同一个桶。

```
# qwen-sft.yaml. Launch anywhere: sky launch qwen-sft.yaml --infra aws|gcp|...
resources:
  accelerators: H100:1 # or whatever the cloud has

file_mounts:
  /base-model:
    source: hf://Qwen/Qwen3.5-4B # read-only, lazy-mounted from the Hub
    store: hf
    mode: MOUNT
  /checkpoints:
    source: hf://buckets/my-org/qwen-sft # read-write Bucket
    store: hf
    mode: MOUNT

run: |
  python train.py --model /base-model --output_dir /checkpoints
```

测量结果：

- **模型在每个云上都是免费加载的。** 惰性读取只拉 `from_pretrained` 触碰的部分，因此大约 30 秒内即可开始训练（最高约 500 MB/s）。因为 Hugging Face 不收出口费，这次拉取零成本；如果模型放在 S3，向其他云上的 GPU 每次读取都会被计出口费（AWS 约 $0.09/GB）。
- **Checkpoint 直接流入桶**，最高约 170 MB/s（每个权重 8.43 GB），且在 GPU 实例销毁后仍然保留。

各云上 checkpoint 写入桶的速度：

| 云 | GPU | Checkpoint 写入 |
| --- | --- | --- |
| AWS (us-east-2) | L40S | ~168 MB/s |
| GCP (us-central1) | L4 | ~123 MB/s |
| Lambda (us-west-3) | H100 | ~112 MB/s |

## Xet 支撑的存储：为 checkpoint 与模型变体自动去重

Hugging Face Bucket 构建在 [Xet](https://huggingface.co/docs/hub/xet/overview) 之上，使用[内容定义分块](https://huggingface.co/docs/hub/xet/deduplication)把文件切成约 64 KB 的块、每个唯一块只存一份。由于块边界跟随内容，一次编辑只改变它触及的块，其余都被识别为已存储。这在几个场景收益明显：

- **增量与 adapter checkpoint。** 冻结层、训练 adapter 或两次保存之间大部分权重不变时，只上传变化的块，而不是整个 checkpoint。
- **共享基座的模型变体。** 同一基座的微调和量化变体重叠度很高，共享块全局只存一份。
- **持续追加的数据集。** 对话轨迹、推理输出这类日志靠向大 Parquet 文件追加行增长。既有 row group 保持逐字节不变，所以只有新行需要传输：在 Hugging Face 的[测试](https://huggingface.co/blog/parquet-cdc)中，向 10 万行的表追加 1 万行只动了约 10 MB，而非整个约 106 MB。（如果你原地修改或删除行，写入时用 `use_content_defined_chunking=True` 以保持变化局部化。）
- **重复上传跳过已存储内容。** 我们的测试里，重新上传桶中已有的 8.43 GB 块只花约 8 秒，而首次上传用了 24 秒——因为只有块哈希在动。同一机制也让服务端 `hf buckets cp` 在仓库与桶之间按引用复制，无需重传字节。

能省多少取决于工件的重叠程度，但去重是全自动的：你照常写 checkpoint，只有新块离开机器。

## 快速上手

```
pip install "skypilot[huggingface]"
hf auth login  # or: export HF_TOKEN=<your-token>
```

在任何 SkyPilot 任务里加一个 `hf://` 挂载然后启动即可。`MOUNT` 需要基础镜像具备 glibc 2.34+ 和 `/dev/fuse`。

## 共同构建：Hugging Face 与 SkyPilot

最初的 `store: hf` 支持[始于 Nikhil Jha 的一笔贡献](https://github.com/skypilot-org/skypilot/pull/9418)。Hugging Face 团队[把它向前推进](https://github.com/skypilot-org/skypilot/pull/9698)，并将 `hf-mount` 的 FUSE 修复上流化，使其能在非特权容器中挂载——这是许多 Kubernetes 集群的默认环境。SkyPilot 团队把它接进了存储后端。整条链路全开源：SkyPilot、Hugging Face 的 `hf-mount` 和 `huggingface_hub` 客户端。
