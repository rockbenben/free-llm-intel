# 视觉语言模型（更好、更快、更强）

## 动机

视觉语言模型（VLM）是当下的热门话题。在[上一篇博客](https://huggingface.co/blog/vlms)（*2024 年 4 月*）里，我们聊了很多 VLM 的事，一大块内容是 [LLaVA](https://huggingface.co/papers/2304.08485)——第一个**成功**且**易于复现**的开源视觉语言模型——以及关于如何发现、评估和微调开放模型的技巧。

自那以来，变化天翻地覆。模型变得更[小巧却更强](https://huggingface.co/blog/smolvlm)，新架构和新能力不断涌现（推理、智能体、长视频理解等等）。与此同时，全新的范式也成型了，比如多模态检索增强生成（RAG）和多模态智能体。

在这篇博客里，我们回顾过去一年视觉语言模型发生的一切，你会看到关键变化、新兴趋势和值得关注的进展。

> 想给视觉语言模型打个好基础，我们强烈建议先读第一篇博客。

## 新模型趋势

这一节我们来看看新型 VLM。有些是彻头彻尾的新物种，另一些则是既有研究的升级版。

## Any-to-any 模型

顾名思义，any-to-any（任意模态到任意模态）模型可以接收任意模态、输出任意模态（图像、文本、音频）。它们靠对齐各模态来实现：一种模态的输入可以转换成另一种模态（例如单词 "dog" 会关联到一张狗的图片，或这个词的语音）。

这类模型有多个编码器（每种模态一个），然后把嵌入融合起来构建共享的表示空间。解码器（单个或多个）以这个共享潜在空间为输入，解码成所选模态。最早尝试构建 any-to-any 模型的是 [Meta 的 Chameleon](https://huggingface.co/collections/facebook/chameleon-668da9663f80d483b4c61f58)，它能接收图像和文本、输出图像和文本。Meta 没有发布该模型的图像生成能力，于是 Alpha-VLLM 发布了 [Lumina-mGPT](https://huggingface.co/collections/Alpha-VLLM/lumina-mgpt-family-66ae48a59a973eeae4513848)，在 Chameleon 之上内置了图像生成。

目前最强大、最新的 any-to-any 模型是 [Qwen 2.5 Omni](https://huggingface.co/collections/Qwen/qwen25-omni-67de1e5f0f9464dc6314b36e)（下图），它是理解 any-to-any 模型架构的绝佳例子。

[![Qwen-Omni](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/qwen-omni.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/qwen-omni.png)

Qwen2.5-Omni 采用新颖的 "Thinker-Talker"（思考者-说话者）架构："Thinker" 负责文本生成，"Talker" 以流式方式产出自然语音响应。[MiniCPM-o 2.6](https://huggingface.co/openbmb/MiniCPM-o-2_6) 是一个 8B 参数的多模态模型，能跨视觉、语音和语言模态理解并生成内容。[Janus-Pro-7B](https://huggingface.co/deepseek-ai/Janus-Pro-7B) 由 DeepSeek AI 推出，是一个统一多模态模型，跨模态的理解与生成都很出色，采用解耦的视觉编码架构，把理解和生成两个过程分开。

我们预计未来几年这类模型会越来越多。业界有个公认的直觉：多模态学习是把深层表示学得更透彻的唯一道路。我们精选了一些 any-to-any 模型和 demo，放在[这个 collection](https://huggingface.co/collections/merve/any-to-any-models-6822042ee8eb7fb5e38f9b62)里。

### 推理模型

推理模型是能解决复杂问题的模型。我们先在大语言模型上见识了它们，现在轮到视觉语言模型。直到 2025 年，开源多模态推理模型只有一家：Qwen 的 [QVQ-72B-preview](https://huggingface.co/Qwen/QVQ-72B-Preview)。那是阿里 Qwen 团队做的实验性模型，带着不少免责声明。

今年迎来了新玩家：Moonshot AI 团队的 [Kimi-VL-A3B-Thinking](https://huggingface.co/moonshotai/Kimi-VL-A3B-Thinking)。它以 MoonViT（SigLIP-so-400M）作图像编码器，解码器是总参数 16B、活跃参数仅 2.8B 的 Mixture-of-Experts（MoE，混合专家）。该模型是在 Kimi-VL 基础视觉语言模型上做长思维链微调、再对齐（强化学习）得到的。你可以[在这里](https://huggingface.co/spaces/moonshotai/Kimi-VL-A3B-Thinking)试用。

> 作者们还发布了一个指令微调版本，叫 Kimi-VL-A3B-Instruct。

[![kimi-vl](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/kimi-vl.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/kimi-vl.png) 该模型能接收长视频、PDF、截图等更多内容，还具备智能体（agentic）能力。

### 小而能的模型

社区过去靠参数数量堆智能，后来靠高质量合成数据。到某个点之后，基准饱和了，继续放大模型收益递减。于是社区转向用蒸馏等各种方法把大模型缩小。这很合理：降低算力成本、简化部署、解锁本地运行这类用例，还能加强数据隐私。

说到小型视觉语言模型，我们通常指参数少于 2B、能在消费级 GPU 上跑的模型。SmolVLM 是小型 VLM 的一个好例子。作者们没有简单地把大模型缩小，而是彻底尝试把模型塞进 256M、500M、2.2B 这样极小的参数预算里。例如 SmolVLM2 试图在这个规模上解决视频理解，发现 500M 是很好的平衡点。在 Hugging Face，我们做了一个 iPhone 应用 HuggingSnap，证明这些尺寸的模型可以在消费设备上实现视频理解。

另一个亮眼的模型是 Google DeepMind 的 [gemma3-4b-it](https://huggingface.co/google/gemma-3-4b-it)。它尤其让人兴奋，因为是最小的拥有 128k token 上下文窗口、支持 140 多种语言的多模态模型之一。它属于 Gemma 3 家族，该家族最大的模型当时在 Chatbot Arena 排名第一，随后最大的模型被蒸馏出了 1B 变体。

最后，虽然不是最小的，[Qwen2.5-VL-3B-Instruct](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct) 也值得一提。这个模型能完成从定位（目标检测和指点）到文档理解、再到智能体任务等各种任务，上下文长度可达 32k token。

你可以通过 MLX 和 Llama.cpp 集成使用这些小模型。用 MLX 的话（假设已安装），一行命令即可跑起 SmolVLM-500M-Instruct：

```
python3 -m mlx_vlm.generate --model HuggingfaceTB/SmolVLM-500M-Instruct --max-tokens 400 --temp 0.0 --image https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm_example.jpg --prompt "What is in this image?" 
```

用 llama.cpp 以 GGUF 格式跑 [gemma-3-4b-it](https://huggingface.co/collections/google/gemma-3-release-67c6c6f89c4f76621268bb6d)，CLI 一行搞定：

```
llama-mtmd-cli -hf ggml-org/gemma-3-4b-it-GGUF  
```

也可以按下面的方式把它作为服务启动。

```
llama-server -hf ggml-org/gemma-3-4b-it-GGUF  
```

我们要向 [moondream2](https://huggingface.co/vikhyatk/moondream2) 和 [Florence-2](https://huggingface.co/collections/microsoft/florence-6669f44df0d87d9c3bfb76de) 致敬，它们是最早尝试超小视觉语言模型的一批。本博客主要覆盖更新的模型（多为 2024 年 4 月之后发布的）。

### 用混合专家（MoE）做解码器

Mixture of Experts（MoE，混合专家）模型为**稠密（dense）**架构提供了一种*替代方案*：它动态选择并只激活与给定输入片段最相关的子模型（称为"专家"）来处理输入。这种由 router（路由器）完成的选择性激活机制，已被证明能在用更少计算资源的同时，大幅提升模型表现和运行效率。

MoE 推理比同等参数规模的稠密模型更快，因为每次只激活网络的一小片；训练时收敛也更快。但好东西都有代价：MoE 需要更多显存，因为整个模型都得放在 GPU 上，哪怕只用到一小部分。

在被广泛采用的 Transformer 架构中，MoE 层最常见的集成方式是替换每个 Transformer block 里的标准前馈网络（FFN）层。稠密网络跑一次推理要动用整个模型，而规模相当的 MoE 网络只选择性激活部分专家，这有助于更好的算力利用和更快的推理。

采用 MoE 解码器的视觉语言模型表现似乎更强。例如，Kimi-VL 目前就是最先进的、带 MoE 解码器的开源推理模型。MoE 在 [MoE-LLaVA](https://huggingface.co/papers/2401.15947)（主打效率和减少幻觉）和 [DeepSeek-VL2](https://huggingface.co/deepseek-ai/deepseek-vl2)（广泛的通用多模态能力）上也显示出不错的成果。Llama 的最新版（[Llama 4](https://huggingface.co/collections/meta-llama/llama-4-67f0c30d9fe03840bc9d0164)）就是带视觉能力的 MoE。MoE 作为解码器是一个很有前景的研究方向，我们预计这类模型会越来越多。

> 想很好地理解 MoE，我们推荐读这篇精彩的文章。

### 视觉-语言-动作模型（VLA）

VLM 甚至正在机器人领域留下印记！在那里它们被称为视觉-语言-动作模型（Vision-language-action models，VLA）。别被名字唬住，它们本质上就是戴了帽子、贴了胡子的 VLM。VLA 接收图像和文本指令，直接返回说明机器人该做什么动作的文本。VLA 在视觉语言模型基础上扩展出动作和状态 token，用来与物理环境交互并控制它。这些额外的 token 代表系统的内部状态（它如何感知环境）、动作（基于指令做什么）以及时间相关信息（如任务中步骤的顺序）。这些 token 被拼接到视觉语言输入上，生成动作或策略。

VLA 通常在基座 VLM 之上微调得到。有人把这个定义进一步扩展，把任何以视觉方式与真实或数字世界交互的模型都算作 VLA。按这个定义，VLA 可以做 UI 导航或用于智能体工作流。但很多人认为那些应用其实属于 VLM 的范畴。

VLA 的出色例子是 [π0](https://huggingface.co/lerobot/pi0) 和 π0-FAST——Physical Intelligence 的首批机器人基础模型，被移植到了 Hugging Face 的 LeRobot 库。这些模型在 7 个机器人平台、68 个不同任务上训练，在叠衣服、收拾餐桌、装杂货袋、装箱、取物等复杂真实活动中，展现出很强的零样本和微调能力。

[GR00T N1](https://huggingface.co/nvidia/GR00T-N1-2B) 是 NVIDIA 面向通用人形机器人的开源 VLA 基础模型。它理解图像和语言，并把它们转化为动作——比如挥动手臂、听从指令——靠的是一套把智能推理和实时运动控制结合起来的系统。GR00T N1 还基于 LeRobot 数据集格式构建，这一开放标准就是为了简化机器人演示数据的共享与训练。

[![pi0](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/pi0.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/pi0.png)

摘自[论文](https://www.physicalintelligence.company/download/pi0.pdf)

看完了最新的 VLM 模型创新，我们再来看看更成熟的能力是如何演进的。

## 专项能力

### 用视觉语言模型做目标检测、分割与计数

如前几节所见，VLM 让传统计算机视觉任务获得了*泛化*能力。模型现在可以接收图像和各种提示——比如开放式文本——输出带定位 token 的结构化文本（用于检测、分割等）。

去年，[PaliGemma](https://huggingface.co/blog/paligemma) 是第一个尝试解决这些任务的模型。它接收图像和文本，文本是感兴趣目标的描述，再加一个任务前缀，提示词形如 "segment striped cat" 或 "detect bird on the roof"。

做检测时，模型以 *token* 形式输出边界框坐标；做分割时，模型输出检测 token 加分割 token。这些分割 token 并不是全部被分割的像素坐标，而是码本（codebook）索引，由一个变分自编码器解码成有效的分割掩码（如下图所示）。

[![PaliGemma3](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/pg2-seg.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/pg2-seg.png)

PaliGemma 之后，许多模型加入定位任务行列。去年年末，PaliGemma 的升级版 PaliGemma 2 出现，能力相同、性能更好。再之后还有 Allen AI 的 Molmo，它能用点来指点目标实例，还能计数。

[![molmo](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/molmo-pointing.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/molmo-pointing.png)

Qwen2.5-VL 同样能检测、指点和计数对象，而且把 UI 元素也算作对象！

[![Qwen2.5VL](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/qwen3-gui.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/qwen3-gui.png)

### 多模态安全模型

生产环境中的视觉语言模型需要对输入输出做**过滤**，以防越狱和有害输出、满足合规要求。有害内容从含暴力的输入到色情内容都有。多模态安全模型正是为此而来：它们部署在 VLM 的前后，过滤输入和输出。它们和 LLM 安全模型类似，只是多了图像输入。

2025 年初，Google 发布了第一个开源多模态安全模型 [ShieldGemma 2](https://huggingface.co/google/shieldgemma-2-4b-it)，基于纯文本安全模型 ShieldGemma 构建。它接收图像和内容策略，返回图像在给定策略下是否安全。这里的*策略*指图像不适当的标准。ShieldGemma 2 也可用于过滤图像生成模型的输出。

Meta 的 [Llama Guard 4](https://huggingface.co/spaces/merve/llama-guard-4) 是一个稠密的多模态、多语言安全模型。它是从 Llama 4 Scout（一个多模态 MoE 模型）稠密剪枝并做安全微调而来。

[![Llama Guard 4](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/llama-guard.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/llama-guard.png)

该模型可用于纯文本和多模态推理，还能接收视觉语言模型的输出、完整对话，在发给用户之前先过滤。

### 多模态 RAG：检索器、重排器

接下来看看检索增强生成（RAG）在多模态领域的演进。针对复杂文档（通常是 PDF）的 RAG 一般分三步处理：

- 把文档彻底解析成文本
- 把纯文本和查询交给检索器和重排器，找出最相关的文档
- 把相关上下文和查询交给 LLM

传统 PDF 解析器由多个组件构成，以保留文档的结构和视觉元素——*版面*、*表格*、*图像*、*图表*——全部渲染成 markdown。但这套东西很难维护。
[![Traditional Parsing](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/rag-1.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/rag-1.png)

随着视觉语言模型的兴起，这个问题有了新解法：现在有了多模态检索器和重排器。

[![Multimodal RAG](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/rag-2.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/rag-2.png)

多模态检索器接收一摞 PDF 和一个查询作为输入，返回最相关的页码及其置信度分数。分数表示该页包含答案的可能性，或查询与该页的相关程度。这就跳过了脆弱的解析步骤。

然后，最相关的页面连同查询一起喂给视觉语言模型，由 VLM 生成答案。

**多模态检索器**主要有两种架构：

- Document Screenshot Embedding（DSE、MCDSE）
- ColBERT 风格模型（ColPali、ColQwen2、ColSmolVLM）

DSE 模型由文本编码器和图像编码器组成，每个查询返回一个向量。返回的分数是对嵌入点积做 softmax 得到的，每个段落返回单个向量。

[![DSE](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/dse.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/dse.png)

摘自[论文](https://arxiv.org/pdf/2406.11251)

ColBERT 风格模型（如 ColPali）也是双编码器，但有个转折：ColPali 用视觉语言模型做图像编码器、大语言模型做文本编码器。它们本质上不是编码器，但会输出嵌入，再交给 "MaxSim" 处理。与 DSE 不同，输出是多个向量——每个 token 一个。MaxSim 会计算每个文本 token 嵌入与每个图像 patch 嵌入之间的相似度，因此能捕捉更细的语义。也正因如此，ColBERT 风格模型成本效率较低，但性能更好。

下面可以看到 ColPali 的索引延迟。由于它只是一个模型，维护也更容易。

[![ColPali](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/colpali.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/colpali.png) 摘自[论文](https://arxiv.org/pdf/2407.01449)

在 Hugging Face Hub 上，你可以在 "[Visual Document Retrieval](https://huggingface.co/models?pipeline_tag=visual-document-retrieval&sort=trending)" 任务下找到这些模型。

这个任务最流行的基准是 ViDoRe，由**英语**和**法语**文档组成，内容从财务报告、科学图表到行政文书不等。ViDoRe 的每个样本包含作为图像的文档、一个查询和若干可能答案。与查询匹配的文档有助于对比预训练，因此 ViDoRe 训练集被用来训练新模型。

## 多模态智能体

视觉语言模型解锁了大量智能体工作流，从与文档聊天到操作计算机都有。这里我们讲后者，因为它需要更高级的智能体能力。近期发布了很多能理解并操作 UI 的视觉语言模型，最新的是字节跳动的 UI-TARS-1.5，在浏览器、计算机和手机操作上都展现出了出色成果，还能带推理地玩游戏、在开放世界游戏中行动。今年另一个有影响力的发布是 MAGMA-8B，它是同时面向 UI 导航和真实世界物理交互的基础模型。此外，Qwen2.5-VL（尤其是[32B 变体](https://huggingface.co/Qwen/Qwen2.5-VL-32B-Instruct)，它在智能体任务上进一步训练过）和 [Kimi-VL 推理模型](https://huggingface.co/collections/moonshotai/kimi-vl-a3b-67f67b6ac91d3b03d382dd85)在 GUI 智能体任务上也表现出色。

2025 年初，我们推出了 smolagents——一个实现 ReAct 框架的轻量级新智能体库。不久后我们就为库加入了视觉语言支持。这个集成面向两个用例：

- 在运行开始时一次性提供图像，适合带工具使用的文档 AI。
- 动态获取图像，适合 VLM 智能体控制 GUI 这类需要反复截图的场景。

库为用户提供了积木，让你构建带图像理解的智能体工作流，并提供了多种脚本和一行式 CLI 命令，帮你轻松上手。

第一个用例，假设我们想让智能体描述文档（这智能体味道不浓，但适合最小化场景）。你可以像这样初始化 CodeAgent（会自己写代码的智能体！）：

```
agent = CodeAgent(tools=[], model=model) #  no need for tools
agent.run("Describe these documents:", images=[document_1, document_2, document_3])
```

后一个用例中，智能体需要截取屏幕，我们可以定义一个回调，在每个 `ActionStep` 结束时执行。对于你自己需要动态取图的场景，随意修改回调。为求简单，这里不详细定义它（可选：阅读本博客末尾的博文和脚本本身）。现在先看如何用回调和浏览器控制步骤来初始化智能体。

```
def save_screenshot(memory_step: ActionStep, agent: CodeAgent) -> None:
    """ 
    Takes screenshots and writes to observations.
"""
  png_bytes = driver.get_screenshot_as_png()
        memory_step.observations_images = [image.copy()]  # persist images to memory_step
    url_info = f"Current url: {driver.current_url}"
    memory_step.observations = (
        url_info if memory_step.observations is None else memory_step.observations + "\n" + url_info
    )
    return

agent = CodeAgent(
    tools=[go_back, close_popups, search_item_ctrl_f], # pass navigation tools
    model=model,
    additional_authorized_imports=["helium"],
    step_callbacks=[save_screenshot], # pass callback
)
```

只要运行下面这条 CLI 命令就能体验完整示例。它会启动一个能控制网页浏览器的智能体，由视觉语言模型驱动来完成网页自动化任务（请把网址换成你想浏览的网站）。

```
webagent "go to xyz.com/men, get to sale section, click the first clothing item you see. Get the product details, and the price, return them. note that I'm shopping from France"   
```

smolagents 提供多种模型类型：本地 transformers 模型、通过 Inference Providers 服务的开源模型，或闭源模型提供商的 endpoint。我们鼓励使用开源模型——如今许多智能体工作流都需要推理能力，而这对大参数模型更有利。截至 2025 年 4 月，Qwen 2.5 VL 是智能体工作流的好候选，因为它在智能体任务上做过进一步训练。

## 视频语言模型

如今大多数视觉语言模型都能处理视频，因为视频可以表示成帧序列。不过视频理解很难，原因在帧之间的时序关系以及帧数量巨大，所以人们用了各种技术来选出有代表性的视频帧。
[![Video LMs](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/video.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/video.png)

从去年起，社区对解决这个问题的各种方法和技巧反复权衡。

一个很好的例子是 Meta 的 [LongVU 模型](https://huggingface.co/collections/Vision-CAIR/longvu-67181d2debabfc1eb050c21d)。它先对视频帧做下采样：把帧交给 DINOv2 找出最相似的帧并剔除；然后模型再按文本查询挑出最相关的帧做精炼——文本和帧被投影到同一空间计算相似度。[Qwen2.5VL](https://huggingface.co/collections/Qwen/qwen25-vl-6795ffac22b334a837c0f9a5) 能处理长上下文，并适配动态 FPS——模型用不同帧率的视频训练过。通过扩展的多模态 RoPE，它理解帧的绝对时间位置，能在不同帧率下依然理解现实中事件发生的速度。另一个模型是 [Gemma 3](https://huggingface.co/collections/google/gemma-3-release-67c6c6f89c4f76621268bb6d)，它可以接收在文本提示中与时间戳交错的视频帧，例如 "Frame 00.00: <image>.."，在视频理解任务上性能很强。

[![MRoPE](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/mrope.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/mrope.png)
摘自[论文](https://arxiv.org/pdf/2502.13923)

## 视觉语言模型的新对齐技术

**偏好优化（Preference optimization）**是语言模型的一种替代微调方法，也可以扩展到视觉语言模型。它不依赖固定标签，而是基于偏好在候选回答之间比较和排序。[trl](https://huggingface.co/docs/trl/en/index) 库支持直接偏好优化（DPO），也包括 VLM。

下面是一个用于 VLM DPO 微调的偏好数据集结构示例。每个条目由一个"图像 + 问题"对和两个对应回答组成：一个被选中（chosen）、一个被拒绝（rejected）。VLM 被微调得更倾向于生成与被选中回答对齐的响应。

[![DPO](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/dpo.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/dpo.png)

这一流程的示例数据集是 [RLAIF-V](https://huggingface.co/datasets/openbmb/RLAIF-V-Dataset)，包含 83,000 多条按上述结构标注的样本。每个条目包含一个图像列表（通常一张）、一个提示词、一个 chosen 回答和一个 rejected 回答——正是 DPOTrainer 所期望的格式。

还有一个 [RLAIF-V formatted](https://huggingface.co/datasets/HuggingFaceH4/rlaif-v_formatted) 数据集，已经按格式处理好。下面是一个样本示例：

```
{'images': [<PIL.JpegImagePlugin.JpegImageFile image mode=L size=980x812 at 0x154505570>],
 'prompt': [ { "content": [ { "text": null, "type": "image" }, { "text": "What should this catcher be using?", "type": "text" } ], "role": "user" } ],
 'rejected': [ { "content": [ { "text": "The catcher, identified by the number...", "type": "text" } ], "role": "assistant" } ],
 'chosen': [ { "content": [ { "text": "The catcher in the image should be using a baseball glove...", "type": "text" } ], "role": "assistant" } ]}
```

数据集准备好后，你可以用 trl 库的 *DPOConfig* 和 *DPOTrainer* 类来配置并启动微调流程。
下面是一个用 *DPOConfig* 的配置示例：

```
from trl import DPOConfig

training_args = DPOConfig(
    output_dir="smolvlm-instruct-trl-dpo-rlaif-v",
    bf16=True,
    gradient_checkpointing=True,
    per_device_train_batch_size=1,
    per_device_eval_batch_size=1,
    gradient_accumulation_steps=32,
    num_train_epochs=5,
    dataset_num_proc=8,  # tokenization will use 8 processes
    dataloader_num_workers=8,  # data loading will use 8 workers
    logging_steps=10,
    report_to="tensorboard",
    push_to_hub=True,
    save_strategy="steps",
    save_steps=10,
    save_total_limit=1,
    eval_steps=10,  # Steps interval for evaluation
    eval_strategy="steps",
)
```

用 *DPOTrainer* 训练模型时，你可以选择提供一个参考模型来计算奖励差。如果使用参数高效微调（PEFT），可以通过设置 *ref_model=None* 省略参考模型。

```
from trl import DPOTrainer

trainer = DPOTrainer(
    model=model,
    ref_model=None,
    args=training_args,
    train_dataset=train_dataset,
    eval_dataset=test_dataset,
    peft_config=peft_config,
    tokenizer=processor
)

trainer.train()
```

## 新基准

过去一年基准也大幅演进。在之前的博客里，我们把 MMMU 和 MMBench 描述为评估视觉语言模型的两个新兴基准。随着领域快速进步，模型在这些基准上已经饱和，我们需要更好的评测工具。为此，在通用基准之外，我们还需要能评估特定能力的工具。

[![MMT-Bench](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/mmt-bench.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/vlm2/mmt-bench.png)

这里重点介绍两个表现突出的通用基准：MMT-Bench 和 MMMU-Pro。

### MMT-Bench

[MMT-Bench](https://huggingface.co/papers/2404.16006) 旨在跨大量需要专家知识、精确视觉识别、定位、推理和规划的多模态任务上评估 VLM。基准包含来自多种多模态场景的 31,325 道多选视觉问题，覆盖图像、文本、视频和点云模态。它包含 32 个元任务、162 个子任务，覆盖 OCR、视觉识别、视觉-语言检索等各种任务。

### MMMU-Pro

[MMMU-Pro](https://huggingface.co/papers/2409.02813) 是原版 MMMU 基准的加强版，同样考察 AI 模型跨模态的真实理解能力。

它比 MMMU 更复杂，例如增加了"纯视觉输入"设定，候选选项数量也从 4 个增到 10 个。基准还融入了真实世界模拟：纯视觉问题取自模拟显示器内截图或实拍照片，背景、字体样式和大小各异，以还原真实条件。
