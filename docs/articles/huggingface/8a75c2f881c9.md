## 数据集

我们要微调 `black-forest-labs/FLUX.1-dev`，让它习得 Alphonse Mucha 的艺术风格，使用一个小型 [数据集](https://huggingface.co/datasets/derekl35/alphonse-mucha-style)。

## FLUX 架构

模型由三个主要部分组成：

- 文本编码器（CLIP 和 T5）
- Transformer（主模型——Flux Transformer）
- 变分自编码器（VAE）

我们的 QLoRA 方案只微调 **Transformer 部分**。文本编码器和 VAE 在整个训练过程中保持冻结。

### 关键优化技术

**LoRA（Low-Rank Adaptation，低秩适配）详解：** [LoRA](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora) 用低秩矩阵记录权重更新，让模型训练更高效。LoRA 不更新完整的权重矩阵 W，而是学习两个更小的矩阵 A 和 B，对权重的更新为 ΔW = BA，其中 A ∈ R^{r×k}、B ∈ R^{d×r}。r（称为*rank*，秩）远小于原始维度，意味着要更新的参数少得多。最后是 α（缩放因子），用于缩放 LoRA 激活，它决定 LoRA 对更新的影响大小，通常设为与 r 相等或它的倍数，帮助平衡预训练模型与 LoRA adapter 的影响力。想先了解概念，可看我们之前的博文：[Using LoRA for Efficient Stable Diffusion Fine-Tuning](https://huggingface.co/blog/lora)。

![LoRA 在冻结权重矩阵两侧注入两个低秩矩阵的示意图](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/peft/lora_diagram.png)

**QLoRA：效率重器：** [QLoRA](https://huggingface.co/docs/peft/main/en/developer_guides/quantization) 在 LoRA 之上更进一步：先把预训练基座模型以量化格式加载（通常经 `bitsandbytes` 做 4-bit），大幅压缩基座模型的内存占用，然后在这个量化基座之上训练 LoRA adapter（一般用 FP16/BF16）。这显著降低了装下基座模型所需的显存。

例如在 [HiDream 的 DreamBooth 训练脚本](https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/README_hidream.md#using-quantization)中，用 bitsandbytes 做 4-bit 量化可以把一次 LoRA 微调的峰值显存从约 60GB 降到约 37GB，质量几乎无损。我们这里就是把同样的原理用在消费级硬件上微调 FLUX.1。

**8-bit 优化器（AdamW）：** 标准 AdamW 为每个参数以 32-bit（FP32）保存一阶和二阶动量估计，非常占内存。8-bit AdamW 用分块量化把优化器状态存成 8-bit 精度，同时保持训练稳定。相比标准 FP32 AdamW，这项技术可减少约 75% 的优化器内存。脚本里启用很简单：

```
# Check for the --use_8bit_adam flag
if args.use_8bit_adam:
    optimizer_class = bnb.optim.AdamW8bit
else:
    optimizer_class = torch.optim.AdamW

optimizer = optimizer_class(
    params_to_optimize,
    betas=(args.adam_beta1, args.adam_beta2),
    weight_decay=args.adam_weight_decay,
    eps=args.adam_epsilon,
)
```

**梯度检查点（Gradient Checkpointing）：** 前向传播时通常会保存中间激活供反向传播计算梯度。梯度检查点以计算换内存：只保存部分*检查点激活*，其余在反向传播时重算。

```
if args.gradient_checkpointing:
    transformer.enable_gradient_checkpointing()
```

**缓存 Latents（Cache Latents）：** 这项优化在训练开始前先用 VAE 编码器预处理所有训练图像，把得到的 latent 表示存在内存里。训练中不再实时编码图像，直接用缓存的 latents。好处有二：

- 消除训练中重复的 VAE 编码计算，每个训练步更快
- 缓存完成后 VAE 可彻底移出 GPU 显存。代价是为存所有缓存 latents 需要更多 RAM，但对小数据集通常完全可控。

```
# Cache latents before training if the flag is set
    if args.cache_latents:
        latents_cache = []
        for batch in tqdm(train_dataloader, desc="Caching latents"):
            with torch.no_grad():
                batch["pixel_values"] = batch["pixel_values"].to(
                    accelerator.device, non_blocking=True, dtype=weight_dtype
                )
                latents_cache.append(vae.encode(batch["pixel_values"]).latent_dist)
        # VAE is no longer needed, free up its memory
        del vae
        free_memory()
```

**配置 4-bit 量化（`BitsAndBytesConfig`）：**

这一段展示基座模型的 QLoRA 配置：

```
# Determine compute dtype based on mixed precision
bnb_4bit_compute_dtype = torch.float32
if args.mixed_precision == "fp16":
    bnb_4bit_compute_dtype = torch.float16
elif args.mixed_precision == "bf16":
    bnb_4bit_compute_dtype = torch.bfloat16

nf4_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=bnb_4bit_compute_dtype,
)

transformer = FluxTransformer2DModel.from_pretrained(
    args.pretrained_model_name_or_path,
    subfolder="transformer",
    quantization_config=nf4_config,
    torch_dtype=bnb_4bit_compute_dtype,
)
# Prepare model for k-bit training
transformer = prepare_model_for_kbit_training(transformer, use_gradient_checkpointing=False)
# Gradient checkpointing is enabled later via transformer.enable_gradient_checkpointing() if arg is set
```

**定义 LoRA 配置（`LoraConfig`）：** 把 adapter 加到量化后的 transformer 上：

```
transformer_lora_config = LoraConfig(
    r=args.rank,
    lora_alpha=args.rank, 
    init_lora_weights="gaussian",
    target_modules=["to_k", "to_q", "to_v", "to_out.0"], # FLUX attention blocks
)
transformer.add_adapter(transformer_lora_config)
print(f"trainable params: {transformer.num_parameters(only_trainable=True)} || all params: {transformer.num_parameters()}")
# trainable params: 4,669,440 || all params: 11,906,077,760
```

可训练的只有这些 LoRA 参数。

### 预计算文本嵌入（CLIP/T5）

在启动 QLoRA 微调之前，把文本编码器的输出一次性缓存下来，能省下大块显存和墙钟时间。

训练时 dataloader 直接读缓存的嵌入，不再重新编码 caption，CLIP/T5 编码器因此完全不需要驻留 GPU 显存。

代码

```
# https://github.com/huggingface/diffusers/blob/main/examples/research_projects/flux_lora_quantization/compute_embeddings.py
import argparse

import pandas as pd
import torch
from datasets import load_dataset
from huggingface_hub.utils import insecure_hashlib
from tqdm.auto import tqdm
from transformers import T5EncoderModel

from diffusers import FluxPipeline


MAX_SEQ_LENGTH = 77
OUTPUT_PATH = "embeddings.parquet"


def generate_image_hash(image):
    return insecure_hashlib.sha256(image.tobytes()).hexdigest()


def load_flux_dev_pipeline():
    id = "black-forest-labs/FLUX.1-dev"
    text_encoder = T5EncoderModel.from_pretrained(id, subfolder="text_encoder_2", load_in_8bit=True, device_map="auto")
    pipeline = FluxPipeline.from_pretrained(
        id, text_encoder_2=text_encoder, transformer=None, vae=None, device_map="balanced"
    )
    return pipeline


@torch.no_grad()
def compute_embeddings(pipeline, prompts, max_sequence_length):
    all_prompt_embeds = []
    all_pooled_prompt_embeds = []
    all_text_ids = []
    for prompt in tqdm(prompts, desc="Encoding prompts."):
        (
            prompt_embeds,
            pooled_prompt_embeds,
            text_ids,
        ) = pipeline.encode_prompt(prompt=prompt, prompt_2=None, max_sequence_length=max_sequence_length)
        all_prompt_embeds.append(prompt_embeds)
        all_pooled_prompt_embeds.append(pooled_prompt_embeds)
        all_text_ids.append(text_ids)

    max_memory = torch.cuda.max_memory_allocated() / 1024 / 1024 / 1024
    print(f"Max memory allocated: {max_memory:.3f} GB")
    return all_prompt_embeds, all_pooled_prompt_embeds, all_text_ids


def run(args):
    dataset = load_dataset("Norod78/Yarn-art-style", split="train")
    image_prompts = {generate_image_hash(sample["image"]): sample["text"] for sample in dataset}
    all_prompts = list(image_prompts.values())
    print(f"{len(all_prompts)=}")

    pipeline = load_flux_dev_pipeline()
    all_prompt_embeds, all_pooled_prompt_embeds, all_text_ids = compute_embeddings(
        pipeline, all_prompts, args.max_sequence_length
    )

    data = []
    for i, (image_hash, _) in enumerate(image_prompts.items()):
        data.append((image_hash, all_prompt_embeds[i], all_pooled_prompt_embeds[i], all_text_ids[i]))
    print(f"{len(data)=}")

    # Create a DataFrame
    embedding_cols = ["prompt_embeds", "pooled_prompt_embeds", "text_ids"]
    df = pd.DataFrame(data, columns=["image_hash"] + embedding_cols)
    print(f"{len(df)=}")

    # Convert embedding lists to arrays (for proper storage in parquet)
    for col in embedding_cols:
        df[col] = df[col].apply(lambda x: x.cpu().numpy().flatten().tolist())

    # Save the dataframe to a parquet file
    df.to_parquet(args.output_path)
    print(f"Data successfully serialized to {args.output_path}")


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument(
        "--max_sequence_length",
        type=int,
        default=MAX_SEQ_LENGTH,
        help="Maximum sequence length to use for computing the embeddings. The more the higher computational costs.",
    )
    parser.add_argument("--output_path", type=str, default=OUTPUT_PATH, help="Path to serialize the parquet file.")
    args = parser.parse_args()

    run(args)
```

### 怎么使用

```
python compute_embeddings.py \
  --max_sequence_length 77 \
  --output_path embeddings_alphonse_mucha.parquet
```

把它和缓存 VAE latents（`--cache_latents`）结合，活跃模型就只剩量化的 transformer + LoRA adapter，整次微调稳稳压在 10 GB 显存以内。

**RTX 4090 的配置：** 在 RTX 4090 上，我们用 `train_batch_size` 1、`gradient_accumulation_steps` 4、`mixed_precision="bf16"`、`gradient_checkpointing=True`、`use_8bit_adam=True`、LoRA `rank` 4、分辨率 512x768，并用 `cache_latents=True` 缓存 latents。

**显存占用（RTX 4090）：**

- **QLoRA：** QLoRA 微调的峰值显存约 9GB。
- **BF16 LoRA：** 同样设置下跑标准 LoRA（基座 FLUX.1-dev 用 FP16）要 26 GB 显存。
- **BF16 全参微调：** 不做任何内存优化的话估计约 120 GB 显存。

**训练时间（RTX 4090）：** 在 Alphonse Mucha 数据集上微调 700 步，RTX 4090 用 `train_batch_size` 1、512x768 分辨率约需 41 分钟。

## 用 TorchAO 做 FP8 微调

对于算力等级（compute capability）8.9 及以上的 NVIDIA GPU（如 H100、RTX 4090），通过 `torchao` 库使用 FP8 训练还能获得更高的速度收益。

我们在 H100 SXM 上用略微修改的 [`diffusers-torchao`](https://github.com/sayakpaul/diffusers-torchao/)[训练脚本](https://gist.github.com/sayakpaul/f0358dd4f4bcedf14211eba5704df25a#file-train_dreambooth_lora_flux-py)对 FLUX.1-dev 做了 LoRA 微调。使用的命令如下：

```
accelerate launch train_dreambooth_lora_flux.py \
  --pretrained_model_name_or_path=black-forest-labs/FLUX.1-dev \
  --dataset_name=derekl35/alphonse-mucha-style --instance_prompt="a woman, alphonse mucha style" --caption_column="text" \
  --output_dir=alphonse_mucha_fp8_lora_flux \
  --mixed_precision=bf16 --use_8bit_adam \
  --weighting_scheme=none \
  --height=768 --width=512 --train_batch_size=1 --repeats=1 \
  --learning_rate=1e-4 --guidance_scale=1 --report_to=wandb \
  --gradient_accumulation_steps=1 --gradient_checkpointing \
  --lr_scheduler=constant --lr_warmup_steps=0 --rank=4 \
  --max_train_steps=700 --checkpointing_steps=600 --seed=0 \
  --do_fp8_training --push_to_hub
```

这次训练**峰值内存 36.57 GB**，约 **20 分钟**完成。

FP8 微调模型的定性结果也在此：[![FP8 模型输出](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/quantization-backends-diffusers2/alphonse_mucha_fp8_combined.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/quantization-backends-diffusers2/alphonse_mucha_fp8_combined.png)

用 `torchao` 启用 FP8 训练的关键步骤：

- 用 `torchao.float8` 的 `convert_to_float8_training` 向模型**注入 FP8 层**。
- **定义 `module_filter_fn`**，指定哪些模块要转 FP8、哪些不转。

更详细的指南和代码片段见 [这份 gist](https://gist.github.com/sayakpaul/f0358dd4f4bcedf14211eba5704df25a) 和 [`diffusers-torchao` 仓库](https://github.com/sayakpaul/diffusers-torchao/tree/main/training)。

## 用训好的 LoRA Adapter 做推理

训练好你的 [LoRA adapter](https://huggingface.co/collections/derekl35/flux-qlora-68527afe2c0ca7bc82a6d8d9)后，推理有两条主要路线。

### 方案一：加载 LoRA Adapter

一条路是在基座模型上[加载训练好的 LoRA adapter](https://huggingface.co/docs/diffusers/v0.33.1/en/using-diffusers/loading_adapters#lora)。

**加载 LoRA 的好处：**

- **灵活：** 不用重载基座模型就能在不同 LoRA adapter 之间切换
- **便于实验：** 换 adapter 就能测试多种艺术风格或概念
- **模块化：** 用 `set_adapters()` 组合多个 LoRA adapter 做创意融合
- **存储高效：** 一份基座模型加多份很小的 adapter 文件即可

代码

```
from diffusers import FluxPipeline, FluxTransformer2DModel, BitsAndBytesConfig
import torch 

ckpt_id = "black-forest-labs/FLUX.1-dev"
pipeline = FluxPipeline.from_pretrained(
    ckpt_id, torch_dtype=torch.float16
)
pipeline.load_lora_weights("derekl35/alphonse_mucha_qlora_flux", weight_name="pytorch_lora_weights.safetensors")

pipeline.enable_model_cpu_offload()

image = pipeline(
    "a puppy in a pond, alphonse mucha style", num_inference_steps=28, guidance_scale=3.5, height=768, width=512, generator=torch.manual_seed(0)
).images[0]
image.save("alphonse_mucha.png")
```

### 方案二：把 LoRA 合并进基座模型

当你只需要一种风格、追求最大效率时，可以[把 LoRA 权重合并](https://huggingface.co/docs/diffusers/using-diffusers/merge_loras)进基座模型。

**合并 LoRA 的好处：**

- **显存高效：** 推理时没有 adapter 权重带来的额外内存开销
- **速度：** 推理略快，因为不用再做 adapter 计算
- **量化兼容：** 可以对合并后的模型重新量化，把内存压到最低

代码

```
from diffusers import FluxPipeline, AutoPipelineForText2Image, FluxTransformer2DModel, BitsAndBytesConfig
import torch 

ckpt_id = "black-forest-labs/FLUX.1-dev"
pipeline = FluxPipeline.from_pretrained(
    ckpt_id, text_encoder=None, text_encoder_2=None, torch_dtype=torch.float16
)
pipeline.load_lora_weights("derekl35/alphonse_mucha_qlora_flux", weight_name="pytorch_lora_weights.safetensors")
pipeline.fuse_lora()
pipeline.unload_lora_weights()

pipeline.transformer.save_pretrained("fused_transformer")

bnb_4bit_compute_dtype = torch.bfloat16

nf4_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=bnb_4bit_compute_dtype,
)
transformer = FluxTransformer2DModel.from_pretrained(
    "fused_transformer",
    quantization_config=nf4_config,
    torch_dtype=bnb_4bit_compute_dtype,
)

pipeline = AutoPipelineForText2Image.from_pretrained(
    ckpt_id, transformer=transformer, torch_dtype=bnb_4bit_compute_dtype
)
pipeline.enable_model_cpu_offload()

image = pipeline(
    "a puppy in a pond, alphonse mucha style", num_inference_steps=28, guidance_scale=3.5, height=768, width=512, generator=torch.manual_seed(0)
).images[0]
image.save("alphonse_mucha_merged.png")
```

## 在 Google Colab 上运行

虽然我们展示的是 RTX 4090 上的结果，同样的代码也能跑在更容易获得的硬件上，比如 [Google Colab](https://colab.research.google.com/github/DerekLiu35/notebooks/blob/main/flux_lora_quant_blogpost.ipynb) 免费提供的 T4 GPU。

## 结论

QLoRA 配合 `diffusers` 库，大幅降低了定制 FLUX.1-dev 这类最先进模型的门槛。在 RTX 4090 上的演示证明，高效微调完全够得着，而且能产出高质量的风格化效果。此外，对拥有最新 NVIDIA 硬件的用户，`torchao` 还能通过 FP8 精度实现更快的训练。
