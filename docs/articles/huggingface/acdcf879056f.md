# 小而更美：Q8-Chat——Xeon 上的高效生成式 AI 体验

本文另有中文版本 [简体中文](https://huggingface.co/blog/zh/generative-ai-models-on-intel-cpu)。

大语言模型（LLM）正席卷机器学习世界。得益于 [Transformer](https://arxiv.org/abs/1706.03762) 架构，LLM 拥有从海量非结构化数据（如文本、图像、视频、音频）中学习的惊人能力。它们在许多[任务类型](https://huggingface.co/tasks)上表现出色，无论是抽取式的文本分类，还是生成式的文本摘要和文生图。

顾名思义，LLM 是*巨大*的模型，参数规模常常超过百亿。有些模型参数超过千亿，例如 [BLOOM](https://huggingface.co/bigscience/bloom)。LLM 需要大量算力——通常是高端 GPU——才能在搜索或对话应用这类低延迟场景中达到够快的预测速度。遗憾的是，对许多组织而言，相关成本令人望而却步，难以在自己的应用中使用最先进的 LLM。

在本文中，我们将讨论有助于降低 LLM 体积和推理延迟的优化技术，帮助它们在 Intel CPU 上高效运行。

## 量化入门

LLM 通常以 16 位浮点参数（即 FP16/BF16）训练。因此，存储单个权重或激活值需要 2 字节内存。此外，浮点运算比整数运算更复杂、更慢，需要更多算力。

量化是一种模型压缩技术，旨在通过缩小模型参数可取的唯一值范围来同时解决这两个问题。例如，可以把模型量化到 8 位整数（INT8）这样的更低精度，从而缩小模型体积，并用更简单、更快的整数运算替代复杂的浮点运算。

简而言之，量化把模型参数重新缩放到更小的值域。成功时，模型至少缩小 2 倍，而不影响模型精度。

你可以在训练过程中施加量化，即量化感知训练（[QAT](https://arxiv.org/abs/1910.06188)），它通常取得最好的效果。如果你想量化一个已有模型，可以应用训练后量化（[PTQ](https://www.tensorflow.org/lite/performance/post_training_quantization#:~:text=Post%2Dtraining%20quantization%20is%20a,little%20degradation%20in%20model%20accuracy.))，这是一种快得多、几乎不需要算力的技术。

有多种量化工具可选。例如 PyTorch 内置了[量化](https://pytorch.org/docs/stable/quantization.html)支持。你也可以使用 Hugging Face 的 [Optimum Intel](https://huggingface.co/docs/optimum/intel/index) 库，它提供易用友好的 QAT 和 PTQ API。

## 量化 LLM

近期研究 [[1]](https://arxiv.org/abs/2206.01861)[[2]](https://arxiv.org/abs/2211.10438) 表明，现有量化技术对 LLM 效果不佳。特别是，LLM 在所有层、所有 token 的某些激活通道中表现出大幅值的离群点（outlier）。以 OPT-13B 模型为例，可以看到某个激活通道的值在所有 token 上都远大于其他通道。这一现象在模型的所有 Transformer 层中都存在。

*来源：SmoothQuant*

目前最好的量化技术按 token 逐个量化激活，导致要么截断离群值、要么小值激活下溢。两种方案都会显著损害模型质量。而且量化感知训练需要额外训练，在多数情况下因算力和数据不足并不现实。

SmoothQuant [[3]](https://arxiv.org/abs/2211.10438)[[4]](https://github.com/mit-han-lab/smoothquant) 是一种解决此问题的新量化技术。它对权重和激活施加一个联合数学变换，在激活之间降低离群值与非离群值的比例，代价是权重侧比例增大。这一变换让 Transformer 各层变得「量化友好」，从而在不损害模型质量的前提下实现 8 位量化。结果是：更小、更快的模型，在 Intel CPU 平台上运行良好。

*来源：SmoothQuant*

接下来，看看 SmoothQuant 应用于主流 LLM 的实际效果。

## 用 SmoothQuant 量化 LLM

我们在 Intel 的朋友们用 SmoothQuant-O3 量化了多个 LLM：OPT [2.7B](https://huggingface.co/facebook/opt-2.7b) 和 [6.7B](https://huggingface.co/facebook/opt-6.7b) [[5]](https://arxiv.org/pdf/2205.01068.pdf)、LLaMA [7B](https://huggingface.co/decapoda-research/llama-7b-hf) [[6]](https://ai.facebook.com/blog/large-language-model-llama-meta-ai/)、Alpaca [7B](https://huggingface.co/tatsu-lab/alpaca-7b-wdiff) [[7]](https://crfm.stanford.edu/2023-03-13/alpaca.html)、Vicuna [7B](https://huggingface.co/lmsys/vicuna-7b-delta-v1.1) [[8]](https://vicuna.lmsys.org/)、BloomZ [7.1B](https://huggingface.co/bigscience/bloomz-7b1) [[9]](https://huggingface.co/bigscience/bloomz)、MPT-7B-chat [[10]](https://www.mosaicml.com/blog/mpt-7b)。他们还使用 [Language Model Evaluation Harness](https://github.com/EleutherAI/lm-evaluation-harness) 评估了量化模型的精度。

下表总结了他们的发现。第二列显示量化后有所提升的基准比例；第三列是平均退化值（**负值表示该基准有所提升*）。详细结果见本文末尾附录。

可以看到，OPT 模型非常适合 SmoothQuant 量化。与预训练的 16 位模型相比，模型体积缩小约 2 倍；大多数指标提升，未提升的也只有微小损失。

LLaMA 7B 和 BloomZ 7.1B 的情况更具反差。模型同样压缩约 2 倍，约一半任务指标改善；另一半也只有轻微影响，仅单个任务相对退化超过 3%。

使用更小模型的明显好处是推理延迟显著下降。这里有一个[视频](https://drive.google.com/file/d/1Iv5_aV8mKrropr9HeOLIBT_7_oYPmgNl/view?usp=sharing)，演示在单路 Intel Sapphire Rapids CPU（32 核、batch size 为 1）上用 MPT-7B-chat 实时生成文本。

在这个例子里，我们问模型：「*Hugging Face 在推动 NLP 民主化中扮演什么角色？*」。这会向模型发送如下 prompt：*"A chat between a curious user and an artificial intelligence assistant. The assistant gives helpful, detailed, and polite answers to the user's questions. USER: What is the role of Hugging Face in democratizing NLP? ASSISTANT:*"

这个例子展示了 8bit 量化与第四代 Xeon 结合带来的额外好处：每个 token 的生成时间极低。这样的性能水平无疑让在 CPU 平台上运行 LLM 成为可能，为客户带来前所未有的 IT 灵活性和性价比。

## Xeon 上的聊天体验

最近，HuggingFace CEO Clem 说：「*更多公司最好聚焦于更小、更专用的模型——它们训练和运行都更便宜。*」Alpaca、BloomZ、Vicuna 这类较小模型的出现，为企业降低生产环境中微调与推理成本开辟了新机会。如前所述，高质量量化让 Intel CPU 平台也能拥有高质量的聊天体验，无需运行庞然大物般的 LLM 和复杂的 AI 加速器。

我们与 Intel 联合在 Spaces 上推出一个令人兴奋的新 demo：[Q8-Chat](https://huggingface.co/spaces/Intel/Q8-Chat)（读作 "Cute chat"）。Q8-Chat 提供类似 ChatGPT 的聊天体验，而它只跑在一台单路 Intel Sapphire Rapids CPU 上，32 核、batch size 为 1。
