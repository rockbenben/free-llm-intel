## 学习记忆采用带有 GPT-4.1 的基本 ReAct 代理

使用 GPT-4.1（一种较旧的非推理模型），基本客户服务代理在 τ² 基准零售上达到 **67.5% 通过^4** — 这意味着它通过“所有四次”独立尝试解决了 67.5% 的任务。在我们 2026 年 10 月 12 日的排行榜快照中，它的得分高于所有零售条目。它在基准测试的库存 ReAct 支架上运行，并在其系统提示中附加了学习的指南。

**[ALTK-Evolve](https://github.com/AgentToolkit/altk-evolve) 使用 GPT-4.1 构建该剧本。** 它分析代理的训练任务尝试，并使用模型将成功和失败提炼为简短的行为规则：如何验证客户、确认交易或处理退货。然后，这些指南将添加到客服人员的后续对话提示中。相同的模型为指南提取和代理提供支持；不需要权重更新或人工注释。

我们的[之前的工作](https://huggingface.co/blog/ibm-research/altk-evolve-sldd) 在编码代理上演示了这种方法。在这里，我们在客户服务上对其进行测试，成功需要遵循域策略、了解客户的请求并执行正确的工具操作。

## τ²-bench 测试受政策约束的客户服务

[τ²-bench](https://github.com/sierra-research/tau2-bench)（来自 Sierra）衡量客服人员在实际约束下处理**客户服务对话**的情况。每项任务都将代理与一个模拟 LLM 的**客户配对，该客户有一个目标、一组**领域工具**（查找订单、发放退款、重新预订航班）以及代理必须遵循的书面**政策文档**。代理人必须制定正确的细节，遵守政策，并采取正确的（通常是不可逆转的）行动；仅当最终数据库状态与预期结果（严格的二元奖励）匹配时，任务才算已解决。我们使用其两个客户服务领域：**零售**和**航空公司**。

我们运行 τ²-bench 自己实现的基本 ReAct 代理，具有两阶段 **THINK → ACT** 循环，使用“gpt-4.1”作为代理模型，使用“gpt-5.5”作为客户模拟器模型； **每项任务 4 次试验**。 **我们所做的唯一改变**是附加到系统提示中的一块学习指南 - 其他所有内容（策略、工具、脚手架）都是库存 τ²-bench。具体来说，学习到的指南作为简单的降价列表附加在域策略之后：
```
You are a customer service agent that helps users according to the policy below.
Always follow the policy strictly. Use the provided tools when needed.

<policy>
# Retail agent policy

As a retail agent, you can help users:
- cancel or modify pending orders
- return or exchange delivered orders
- modify their default user address
…
</policy>

## Guidelines learned from past task attempts (follow these carefully):
- Authenticate the user before taking any order-related action. If email is unavailable, verify identity via full name and zip code using the find_user_id_by_name_zip API.
- Always confirm all intended changes (modify, cancel, return, exchange) with a clear, structured summary, and require explicit user approval before executing any database-updating action.
- When processing a return or exchange, communicate the refund with an itemized breakdown and clarify refund timing — don't wait for the user to ask.
- Take one action per step: never combine a tool call with a user-facing message in the same turn, and wait for the tool's result before replying.
- Before looking a user up, parse and clean their name — e.g. split a combined handle like `daiki_johnson_9523` into first/last name — and after a couple of failed lookups, state the exact format you need.
…
```
我们使用 **`gpt-4.1`**（与为代理提供动力的模型相同的模型）从 τ²-bench **train** 任务上的代理轨迹中提取指导方针，然后将它们不变地应用到保留的 **测试** 集上。

## 指南提高能力和可靠性

在[之前的文章](https://huggingface.co/blog/ibm-research/altk-evolve-hmm)中，我们讨论了不同的模型/任务如何需要不同剂量的指导。根据这个想法，我们还评估了为模型提供的不同数量的指南。

每条指南都带有一个**支持**计数——它是从中提取的不同训练任务的数量，因此更高的支持意味着一条规则可以推广到更多任务，而不是一次性的。我们比较三种配置：**基线**（无指南）、**sup3**（仅保留支持度≥3的指南——一个小的、高置信度的核心）和**无损**（在合并后保留每条指南，即支持度≥1）。

**表 1. 指南配置和按域保留的指南计数。**

|变体 |上下文中包含的指南 |零售 |航空公司 |
| --- | --- | --- | --- |
| **基线** |没有指南 | 0 | 0 |
| **sup3** |支持`n≥3`（高支持核心）| 31 | 14 | 14
| **无损** |所有指南 | 292 | 292 101 | 101

**我们跟踪的指标。** 每项任务都会尝试 **4 次**，我们通过两种方式解读这些试验：

- **平均准确度** — 4 次试验的平均成功率。这是**能力**轴：*代理多久能做到这一点？*
- **通过^4** — 通过所有 4 次试验的任务百分比。这沿着 **可靠性** 轴和 τ² 基准排行榜报告的指标进行测量。这在这里很重要，因为支持代理在 4 次中解决了 3 次退款问题，但仍然让四分之一的真实客户失败 - Pass^4 会询问您是否可以“每次”信任该代理，而不仅仅是平均而言。

### 最佳指导量取决于领域

这两个领域对于指导的效果“有多大”存在分歧。在**零售**中，每个指标越多越好——小型的sup3核心在准确度上勉强超过基线，并且您需要**完整的无损设置**才能实现真正的跳跃。在 **航空公司** 中，情况在可靠性方面发生了翻转：无损在准确性方面领先（65% 与 60%），但紧凑的 **sup3 核心（14 条准则）是更*可靠的***，将 Pass^4 提升到 **45%**，而无损则为 40%。与之前的发现相呼应，即[交付是一个刻度盘，而不是一个常量](https://huggingface.co/blog/ibm-research/altk-evolve-hmm)，**支持计数是一个值得每个域调整的旋钮**，而不是硬编码的值。

## 更好的性能需要花费更多的代币，而不是更多的回合

指南不是免费的，但成本却在你所期望的地方——在**提示输入标记**中，而不是在更长、更曲折的对话中：

代理人是否可以通过“更长的交谈”来达到目的？为了清楚地回答这个问题，我们比较**同类**：任务在**基线和指南变体下运行解决 - 相同的场景和种子，真正的“相同的任务，正确完成”集 - 并计算每一侧的助手轮数。

**表 4. 在测试分组的两种设置下解决的匹配运行的每个对话的助理轮数，汇集四个试验。**

代理不会说更长的时间 - 在共享集上，指导方针使对话**稍微缩短**：两个域（零售 10.59 → 10.16，航空公司 9.15 → 8.82）中的无损修剪 ~0.3–0.4 回合，并且没有变体延长它们。这比成本更重要：每一轮都是一个连续的 LLM 往返，因此更少的轮次意味着**更低的端到端延迟 - 对客户来说更快的完成时间**，而不仅仅是更便宜的。唯一真正的价格是在输入方面——每次 LLM 通话都会产生更大的系统提示：零售业的 292 条指南提示将每次对话的成本从约 0.084 美元推至约 0.139 美元，而航空公司的较小剧本则更便宜。在生产中，即使这在很大程度上也可以通过**提示缓存**进行回收，因为每次调用的指导块都是相同的。

因此，这种交易是有利的：对于**稍高的输入成本**（其中大部分在实践中被缓存），代理立即获得**更高的准确性、更高的可靠性，*和*更短的完成时间**——不是通常的质量与延迟的权衡，而是所有三者都以正确的方式一起移动。

## 学习指南还可以使用前沿模型改进智能体

到目前为止，我们使用了一个较旧的非推理模型——“gpt-4.1”。一个公平的反对意见是，学习的指导方针可能对使用“前沿”模型的代理没有什么帮助：也许它们只能弥补较弱模型的差距。因此，我们直接对其进行了测试 - 我们在同一个 τ²-bench ReAct 支架上使用 **`gpt-5.5` 重新运行 **airline** 来提取代理和指南**，并从代理的 *自己的* 运行中重新挖掘指南。模型的一个细节发生了变化：在此设置中提取的指导方针均未达到支持度 ≥ 3（它们在支持度 2 处达到顶峰），因此此处的高支持核心是 **sup2** 而不是 su3。

**表 5. 在每个任务的四次试验中，“gpt-5.5”代理的航空公司表现。**

|航空公司·“gpt-5.5”（20 个保留的测试任务）|准确度|通过^4 |
| --- | --- | --- |
|基线（0 条指南）| 72.5% | 55.0% |
| SU2（103 条指南）| 80.0% (+7.5) | 70.0% (+15.0) |
| **无损（146 条准则）** | **82.5% (+10.0)** | **70.0% (+15.0)** |

学到的指南也改进了这个设置。在相同的保留测试任务中，将它们附加到提示提升**准确度+10分**（72.5→82.5）和严格的**通过^4+15分**（55.0→70.0）——比我们在这些任务上使用“gpt-4.1”观察到的“更大”可靠性增益（+10分），并且来自更高的楼层。围绕模型学习指导方针可以改进智能体，即使它是从更强大的基础开始的。当基线的可靠性在重新运行之间波动时，无损配置会准确地再现 - 它购买的增益是可靠的，而不是幸运抽奖。

## ALTK-Evolve 在排行榜比较中名列前茅

根据 τ²-bench 的要求，提交的内容在**完整的基础分割**（训练∪测试）上进行评分，并在**通过^4**处报告。由于这涵盖了完整的任务集而不是保留的测试拆分，因此这些数字与上面报告的测试任务数字不同。这就是实际结果出现的地方——提示级记忆携带使用每个基本模型*进入*或*过去*当前前沿公司的代理：

- **[零售：#1](https://github.com/sierra-research/tau2-bench/pull/542)。** 在基础分割上，具有学习指导的代理达到**通过^4 = 67.5%**，领先于每个前沿模型*和*领先于**RAFT-30B-A3B** (61.4%)，这是一个**在合成τ²基准零售数据上进行微调的模型**。使用库存“gpt-4.1”和提示附加的剧本，它的性能比微调系统高**+6.1点**。
- **[航空公司：#1](https://github.com/sierra-research/tau2-bench/pull/551) 使用 `gpt-5.5`，#8 使用 `gpt-4.1`** 相对于已发布的主板，紧凑的 **sup3 核心** 使用 `gpt-4.1` 为代理提供 **Pass^4 = 44%** — **第八**，击败 GPT-5.2（无推理）并且几乎匹配 Claude十四行诗 4.5。交换更强的基础，同样的方法完全领先：**使用“gpt-5.5”的代理达到 82.0%**，清除了每个边界条目 (66-72%)。

## 代理无需权重更新即可改进

在基准上微调模型成本高昂、脆弱，并且不会转移到下一个领域。在这里，ALTK-Evolve 在两个领域中改进了库存模型上的库存代理，并且匹配或击败了零售方面的微调系统，仅使用从代理自己的运行中提取的提示级别指南，自动进行，无需人工注释，也没有任何测试集泄漏。
