*ALTK-Evolve 用 GPT-4.1 学习并应用一套行为手册，在客户服务智能体基准 τ²-bench 上超过了零售领域的所有条目——而且没有更新模型权重。*

## 学习到的记忆把一个使用 GPT-4.1 的基础 ReAct 智能体送上榜首

使用 GPT-4.1 这个较老的非推理模型，一个基础的客户服务智能体在 **τ²-bench 零售领域的 Pass^4 达到 67.5%** —— 也就是说，对 67.5% 的任务，它在*全部四次*独立尝试中都解决了问题。它在我们 2026 年 10 月 12 日的排行榜快照中，得分高于零售领域的每一个条目。它运行在基准自带的 ReAct 脚手架上，只是把学到的准则追加进了系统提示词。

**[ALTK-Evolve](https://github.com/AgentToolkit/altk-evolve) 用 GPT-4.1 构建这套行为手册。** 它分析智能体在训练任务上的尝试，并用该模型把成功与失败蒸馏成简短的行为规则：如何验证客户、确认交易、处理退货。随后这些准则被加入智能体的提示词，用于之后的对话。同一个模型既驱动准则抽取，也驱动智能体本身；不需要更新权重，也不需要人工标注。

我们[此前的工作](https://huggingface.co/blog/ibm-research/altk-evolve-sldd)已在编码智能体上展示了这一方法。在这里，我们把它放到客户服务上测试——这里的成功需要遵循领域策略、理解客户的请求，并执行正确的工具操作。

## τ²-bench 考察受策略约束的客户服务

[τ²-bench](https://github.com/sierra-research/tau2-bench)（来自 Sierra）衡量智能体在真实约束下处理**客户服务对话**的能力。每个任务都会让智能体与一位 LLM 模拟的**客户**配对，这位客户心里有目标，还配有一组**领域工具**（查询订单、发放退款、改订航班），以及一份智能体必须遵循的书面**策略文档**。智能体必须问出正确的细节、不越出策略、并采取正确——往往不可逆——的操作；只有最终数据库状态与预期结果一致时，任务才算解决，这是一个严格的二元奖励。我们使用它的两个客户服务领域：**零售**和**航空**。

我们运行 τ²-bench 自带的基础 ReAct 智能体实现，采用两阶段的 **THINK → ACT** 循环，用 `gpt-4.1` 作为智能体模型、`gpt-5.5` 作为客户模拟器模型；每个任务 **4 次试验**。**我们唯一的改动**是在系统提示词末尾追加一段学到的准则——其他一切（策略、工具、脚手架）都是 τ²-bench 原样。具体来说，学到的准则以普通 markdown 列表的形式接在领域策略之后：

```
You are a customer service agent that helps users according to the policy below.
Always follow the policy strictly. Use the provided tools when needed.

<policy>
# Retail agent policy

As a retail agent, you can help users:
- cancel or modify pending orders
- return or exchange delivered orders
- modify their default user address
…
</policy>

## Guidelines learned from past task attempts (follow these carefully):
- Authenticate the user before taking any order-related action. If email is unavailable, verify identity via full name and zip code using the find_user_id_by_name_zip API.
- Always confirm all intended changes (modify, cancel, return, exchange) with a clear, structured summary, and require explicit user approval before executing any database-updating action.
- When processing a return or exchange, communicate the refund with an itemized breakdown and clarify refund timing — don't wait for the user to ask.
- Take one action per step: never combine a tool call with a user-facing message in the same turn, and wait for the tool's result before replying.
- Before looking a user up, parse and clean their name — e.g. split a combined handle like `daiki_johnson_9523` into first/last name — and after a couple of failed lookups, state the exact format you need.
…
```

我们用 **`gpt-4.1`**（也就是驱动智能体的同一个模型）从智能体在 τ²-bench **训练**任务上的轨迹中抽取准则，然后原样应用到留出的**测试**集上。

## 准则同时提升能力与可靠性

在[此前的一篇文章](https://huggingface.co/blog/ibm-research/altk-evolve-hmm)中，我们讨论过不同的模型/任务需要不同剂量的指导。与这一思路一致，我们也评估了提供给模型的不同准则数量。

每条准则都带有一个**支持度**计数——它是从多少个不同的训练任务中抽取出来的，因此支持度越高，说明这条规则在更多任务上泛化过，而不是一次性的。我们比较三种配置：**baseline**（不带准则）、**sup3**（只保留支持度 ≥ 3 的准则——一个小而高置信度的核心），以及 **lossless**（保留合并后留存下来的每一条准则，即支持度 ≥ 1）。

**表 1。准则配置及各领域保留的准则数量。**

| 变体 | 上下文中包含的准则 | 零售 | 航空 |
| --- | --- | --- | --- |
| **baseline** | 无准则 | 0 | 0 |
| **sup3** | 支持度 `n ≥ 3`（高支持度核心） | 31 | 14 |
| **lossless** | 全部准则 | 292 | 101 |

**我们追踪的指标。** 每个任务尝试 **4 次**，我们从两个角度解读这些试验：

- **Mean Accuracy（平均准确率）** —— 4 次试验的平均成功率。这是**能力**轴：*智能体把这个做对的频率有多高？*
- **Pass^4** —— 在全部 4 次试验中都通过的任务百分比。它衡量的是**可靠性**轴，也是 τ²-bench 排行榜所报告的指标。它在这里很重要，因为一个客服在 4 次里成功处理退款 3 次，仍然会让四分之一的真实客户失望——Pass^4 问的是你是否能在*每一次*都信任这个智能体，而不只是平均而言。

[![留出测试任务上按变体划分的 Mean Accuracy 与 Pass^4，覆盖零售与航空。lossless 让零售准确率提升 +4.4 个百分点、Pass^4 提升 +10.0 个百分点；航空方面 lossless 让准确率提升 +7.5 个百分点，而 sup3 给出最佳的 Pass^4，+10.0 个百分点。](https://cdn-uploads.huggingface.co/production/uploads/6435a1131860001f144239ea/HtL2uTn98-xHkcTxKqkFY.png)](https://cdn-uploads.huggingface.co/production/uploads/6435a1131860001f144239ea/HtL2uTn98-xHkcTxKqkFY.png)

*图 1。使用 `gpt-4.1` 的智能体在留出的零售与航空任务上、每个任务四次试验的 Mean Accuracy 与 Pass^4。*

*智能体模型：`gpt-4.1`（用户模拟器：`gpt-5.5`）。*

**表 2。使用 `gpt-4.1`、每个任务四次试验时留出任务的智能体表现。括号内为相对 baseline 的百分点变化。**

| 领域（测试任务） | 配置 | Mean Accuracy | Pass^4 |
| --- | --- | --- | --- |
| **零售**（40） | baseline | 78.1% | 57.5% |
|  | sup3 | 78.8% (+0.7) | 60.0% (+2.5) |
|  | **lossless** | **82.5% (+4.4)** | **67.5% (+10.0)** |
| **航空**（20） | baseline | 57.5% | 35.0% |
|  | sup3 | 60.0% (+2.5) | **45.0% (+10.0)** |
|  | **lossless** | **65.0% (+7.5)** | 40.0% (+5.0) |

Mean Accuracy 在两个领域都上升——零售 **+4.4 个百分点**（78.1 → 82.5），航空 **+7.5 个百分点**（57.5 → 65.0）。可靠性的移动更大：严格的 **Pass^4** 在零售上升 **+10 个百分点**（57.5 → 67.5），在航空上升 **+10 个百分点**（35.0 → 45.0）。而且这些增益来自更明智的决策，而不是更长的对话——我们在下文的[更好的表现花的是更多 token，而不是更多轮次](https://huggingface.co/blog/ibm-research/altk-evolve-bc#better-performance-costs-more-tokens-not-more-turns)中直接考察了对话长度。

### 最合适的指导量取决于领域

两个领域在*多少*指导才划算这件事上给出的答案不同。在**零售**，每个指标都是越多越好——小的 sup3 核心在准确率上几乎不比 baseline 强，想要真正的跃升就得用**完整的 lossless 集合**。在**航空**，可靠性这一端的图景反转了：lossless 在准确率上领先（65% 对 60%），但紧凑的 **sup3 核心（14 条准则）才是更*可靠*的那个**，把 Pass^4 提到 **45%**，而 lossless 是 40%。这也呼应了早先的发现——[投放量是一个旋钮，不是一个常数](https://huggingface.co/blog/ibm-research/altk-evolve-hmm)，**支持度阈值是一个值得按领域调校的旋钮**，而不是一个可以硬编码的值。

## 更好的表现花的是更多 token，而不是更多轮次

准则不是免费的，但代价落在你预期的地方——**提示词的输入 token**，而不是更长、更绕的对话：

[![按零售与航空分组的每次对话成本。lossless 相对无准则的 baseline 分别把成本提高了 65% 和 32%。](https://cdn-uploads.huggingface.co/production/uploads/6435a1131860001f144239ea/MsqhICXsHtpJozVFZYEm7.png)](https://cdn-uploads.huggingface.co/production/uploads/6435a1131860001f144239ea/MsqhICXsHtpJozVFZYEm7.png)

*图 2。在完整 base split 上，按领域和准则配置划分的每次对话 LLM 总成本。*

**表 3。在完整 base split 上、四次试验的每次对话 LLM 总成本（智能体与用户模拟器）。越低越好。**

| 领域 | 配置 | 每次对话成本 | 相对 baseline |
| --- | --- | --- | --- |
| **零售** | baseline | $0.084 | — |
|  | sup3 | $0.095 | +12% |
|  | **lossless** | $0.139 | +65% |
| **航空** | baseline | $0.081 | — |
|  | sup3 | $0.097 | +19% |
|  | **lossless** | $0.107 | +32% |

智能体是靠*说得更久*达到这个结果吗？为了干净地回答这一点，我们做**同类比较**：那些在 baseline 和带准则变体下**都**被解决的任务运行——场景和随机种子完全相同，一个真正的"同一任务、都做对了"集合——然后统计两侧的助手轮次。

**表 4。测试集上在两种设置下都被解决、相互匹配的运行中，每次对话的助手轮次（合并四次试验）。**

| 领域 | 共享集合 | 两者都解决的数量 (n) | baseline 轮次 | +准则 | Δ |
| --- | --- | --- | --- | --- | --- |
| **零售** | baseline ∩ sup3 | 108 | 10.40 | 10.35 | −0.05 |
|  | baseline ∩ **lossless** | 111 | 10.59 | 10.16 | **−0.43** |
| **航空** | baseline ∩ sup3 | 38 | 8.97 | 8.53 | **−0.45** |
|  | baseline ∩ **lossless** | 40 | 9.15 | 8.82 | −0.33 |

智能体并没有说得更久——在共享集合上，准则让对话**略微变短**：lossless 在两个领域都削减了约 0.3–0.4 轮（零售 10.59 → 10.16，航空 9.15 → 8.82），也没有任何变体把它们变长。这一点在成本之外同样重要：每一轮都是一次串行的 LLM 往返，所以轮次更少意味着**端到端延迟更低——对客户来说更快完成**，而不只是更便宜。真正的代价只在输入侧——更大的系统提示词会搭在每一次 LLM 调用上：零售那 292 条准则的提示词把每次对话的成本从约 $0.084 推高到约 $0.139，而航空那套更小的行为手册则便宜一些。在生产环境中，即便这部分也大体可以用**提示词缓存**收回，因为准则块在每一次调用中都是一样的。

所以这笔交易是划算的：付出**略高的输入成本**（实际上大部分会被缓存掉），智能体同时得到**更高的准确率、更高的可靠性，*以及*更短的完成时间**——不是常见的"用延迟换质量"，而是三者一起朝好的方向移动。

## 学到的准则同样能提升使用前沿模型的智能体

到目前为止，我们用的是较老的非推理模型 `gpt-4.1`。一个合理的反对意见是：对于使用*前沿*模型的智能体，学到的准则能补的东西也许更少——也许它们只是在补弱模型的短板。所以我们直接做了测试——我们用 **`gpt-5.5` 同时作为智能体和准则抽取模型**重跑了**航空**领域，仍是同一个 τ²-bench ReAct 脚手架，准则从智能体*自己*的运行中重新挖掘。有一个细节随模型而变：这套设置下抽取出的准则没有一条达到支持度 ≥ 3（最高只到支持度 2），所以这里的高支持度核心是 **sup2** 而不是 sup3。

**表 5。`gpt-5.5` 智能体在留出航空任务上、每个任务四次试验的表现。**

| 航空 · `gpt-5.5`（20 个留出测试任务） | 准确率 | Pass^4 |
| --- | --- | --- |
| baseline（0 条准则） | 72.5% | 55.0% |
| sup2（103 条准则） | 80.0% (+7.5) | 70.0% (+15.0) |
| **lossless（146 条准则）** | **82.5% (+10.0)** | **70.0% (+15.0)** |

学到的准则在这套设置下同样带来提升。在同一批留出测试任务上，把它们追加到提示词后，**准确率提升 +10 个百分点**（72.5 → 82.5），严格的 **Pass^4 提升 +15 个百分点**（55.0 → 70.0）——这比我们在这些同样任务上用 `gpt-4.1` 观察到的可靠性增益（+10 个百分点）*更大*，而且起点高得多。在模型*周围*学习准则，即使智能体起点更强，也能带来改进。而且在 baseline 的可靠性会在重跑之间摆动的地方，lossless 配置精确复现——它买到的增益是可靠的，而不是一次幸运的抽样。

## ALTK-Evolve 在排行榜对比中登顶

按 τ²-bench 的要求，提交在**完整 base split**（训练 ∪ 测试）上评分，并以 **Pass^4** 报告。由于这覆盖的是完整任务集而不是留出的测试划分，这些数字与上面报告的测试任务数字不同。实用层面的结论就在这里显现——提示词层面的记忆，把使用各个基础模型的智能体*带入*甚至*越过*当前前沿阵营：

- **[零售：第 1 名](https://github.com/sierra-research/tau2-bench/pull/542)。** 在 base split 上，带学到准则的智能体达到 **Pass^4 = 67.5%**，领先于每一个前沿模型，也领先于 **RAFT-30B-A3B**（61.4%）——后者是一个**在合成的 τ²-bench 零售数据上微调过的**模型。用原版 `gpt-4.1` 加上追加到提示词的行为手册，它以 **+6.1 个百分点**超过了那个微调系统。
- **[航空：使用 `gpt-5.5` 第 1 名](https://github.com/sierra-research/tau2-bench/pull/551)，使用 `gpt-4.1` 第 8 名。** 对照已发布的榜单，紧凑的 **sup3 核心**让使用 `gpt-4.1` 的智能体达到 **Pass^4 = 44%**——**第 8 名**，胜过 GPT-5.2（无推理），并且几乎追平 Claude Sonnet 4.5。换上更强的基础模型，同样的方法直接登顶：**使用 `gpt-5.5` 的智能体达到 82.0%**，压过每一个前沿条目（66–72%）。

*图 3。ALTK-Evolve 各次运行与 2026 年 10 月 12 日 τ²-bench 排行榜快照的 Pass^4 对比。*

两个领域传达的是同一个信息：**在模型*周围*学习准则，在不同的基础模型上都行得通**——把使用较老非推理模型的智能体在零售上带入前沿阵营，也把使用前沿模型的智能体在航空上送到榜首。

## 智能体可以在不更新权重的情况下改进

在基准上微调模型既昂贵又脆弱，而且不会迁移到下一个领域。在这里，ALTK-Evolve 在两个领域都改进了**原版模型上的原版智能体**——并在零售上追平甚至超过一个微调过的系统——所用的只是**从智能体自己的运行中抽取的提示词层面准则**，全自动、无需人工标注，也没有任何测试集泄漏。
