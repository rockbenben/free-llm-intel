## 太长不看

这篇博客介绍 SmolVLM——一个 2B 的 VLM，在其内存占用档位上是最先进的。SmolVLM 小而强、快、省内存，且完全开源。所有模型检查点、VLM 数据集、训练配方和工具都以 Apache 2.0 许可发布。

## 什么是 SmolVLM？

今年是模态 AI 爆发的一年，发布了大量大型视觉语言模型。趋势先是堆算力，之后是用大模型生成合成数据来扩充数据多样性，而最近则是做小、提升效率。小型开放模型可以本地部署到浏览器或边缘设备、削减推理成本，并支持用户自定义。值得注意的例子包括 PaliGemma 3B、moondream2 和 Qwen2VL。

在这篇博客中，我们介绍 [SmolVLM](https://huggingface.co/HuggingFaceTB/SmolVLM-Instruct)——一个新的小型视觉语言模型家族，参数 2B，可商用，可以部署到更小的本地环境，训练管线完全开放。

我们发布三个模型：[SmolVLM-Base](https://huggingface.co/HuggingFaceTB/SmolVLM-Base)，可用于下游微调；[SmolVLM-Synthetic](https://huggingface.co/HuggingFaceTB/SmolVLM-Synthetic)，在合成数据上微调的变体；以及 [SmolVLM Instruct](https://huggingface.co/HuggingFaceTB/SmolVLM-Instruct)，指令微调变体，开箱即用，适合面向终端用户的交互式应用。

本次发布包含集成进 transformers 的开源模型、[基于 SmolVLM Instruct 的演示](https://huggingface.co/spaces/HuggingFaceTB/SmolVLM)，以及一个监督微调脚本。我们沿用了此前 Idefics3 使用的数据集：[the Cauldron](https://huggingface.co/datasets/HuggingFaceM4/the_cauldron) 和 [Docmatix](https://huggingface.co/datasets/HuggingFaceM4/Docmatix)，它们同样完全开源。

## 架构

对于 SmolVLM，我们紧密沿用了 Idefics3 的架构，甚至直接使用 transformers 中的同一实现。不过有几处关键差异：

- 我们用 SmolLM2 1.7B 替换了 Llama 3.1 8B 作为语言骨干。
- 我们更激进地压缩分块后的视觉信息：用像素打乱（pixel shuffle）策略把信息压缩 9 倍，而 Idefics3 是 4 倍。
- 我们使用 384*384 的图块，而非 364x364，因为 384 能被 3 整除，这是我们的像素打乱策略所必需的。
- 为此，我们把视觉骨干改为形状优化的 SigLIP，图块为 384x384 像素、内部小块为 14x14。

### 内存

在 transformers 现有的视觉语言模型中，SmolVLM 的内存使用最优。这让它可以高效运行在笔记本等设备上。上表展示了各模型的 GPU 内存占用（GB），推理时输入一张或两张图像，所有测试使用相同的图像和文本提示词。SmolVLM 的图像编码效率内建在模型中：每个 384x384 的图像块被编码为 81 个词元。因此 SmolVLM 把我们的测试提示词加单张图编码为约 1.2k 词元，而 Qwen2-VL 要用 16k 词元。这也解释了为什么两张图时 Qwen 和 InternVL 的内存消耗涨那么多；相比之下，采用类似方案的 SmolVLM 和 PaliGemma 增长就平缓得多。

### 吞吐

SmolVLM 极小的内存占用还意味着预填充和生成所需的计算量少得多。与 Qwen2-VL 相比，预填充吞吐快 3.3 到 4.5 倍，生成吞吐快 7.5 到 16 倍。

### 视频

鉴于 SmolVLM 的长上下文以及可以调整模型内部帧缩放的能力，我们探索了它作为基础视频分析任务的可及选项的适用性，尤其是算力有限的场景。

在评估 SmolVLM 的视频理解能力时，我们实现了一个简单的[视频处理管线代码](https://github.com/huggingface/smollm/blob/7dfcd81c046a946031291c11451e9398609a0aeb/tools/smolvlm_local_inference/SmolVLM_video_inference.py)，从每个视频均匀采样最多 50 帧，同时不做内部帧缩放。这个朴素方法在 CinePile 基准上取得了出人意料竞争力的结果——得分 27.14%，介于 InternVL2 (2B) 和 Video LlaVa (7B) 之间。

定量结果与我们的定性测试一致。看一个 FineVideo 数据集的例子：

```
Question: what is shown in the close-up? 
Assistant: In the close-up, there are bottles of Heinz tomato ketchup,
  honey, soy sauce, and garlic on a kitchen counter.

Question: describe what is happening in the video. 
Assistant: The video shows a man cooking in a kitchen.
  He is wearing a black shirt and a black apron.
  He is standing in front of a counter and is holding a bottle of Heinz tomato ketchup,
  a bottle of honey, soy sauce, and a bowl of minced garlic
```

虽然第二个问题中能看到一些时序理解的局限（厨师是一个接一个地指着食材，而不是同时指着/拿着所有食材），但 SmolVLM 展示了出色的场景理解和物体识别能力。

### VLMEvalKit 集成

我们把 SmolVLM 集成进了 [VLMEvalKit](https://github.com/open-compass/VLMEvalKit)，方便在更多基准上评估。

运行以下命令，你可以评估 SmolVLM 或你微调过的 SmolVLM 模型。

```
python run.py --data <benchmarks> --model SmolVLM --work-dir <output_directory>
```

例如，在 MMMU dev 验证集和 MathVista mini 上评估，并把结果存进名为 smol 的文件夹：

```
python run.py --data MMMU_DEV_VAL MathVista_MINI --model SmolVLM --work-dir smol
```

## 用 Transformers 使用 SmolVLM

你可以用 transformers 的 `Auto` 类轻松加载 SmolVLM。底层把模型和处理器都映射到与 Idefics3 相同的实现。

```
from transformers import AutoProcessor, AutoModelForVision2Seq
import torch
DEVICE = "cuda" if torch.cuda.is_available() else "cpu"

processor = AutoProcessor.from_pretrained("HuggingFaceTB/SmolVLM-Instruct")
model = AutoModelForVision2Seq.from_pretrained("HuggingFaceTB/SmolVLM-Instruct",
                                                torch_dtype=torch.bfloat16,
                                                _attn_implementation="flash_attention_2" if DEVICE == "cuda" else "eager").to(DEVICE)
```

图像与文本可以任意交错，也可以传入多张图像。下面是如何使用聊天模板并把格式化输入传给处理器的方法。

```
from PIL import Image
from transformers.image_utils import load_image


# Load images
image1 = load_image("https://huggingface.co/spaces/HuggingFaceTB/SmolVLM/resolve/main/example_images/rococo.jpg")
image2 = load_image("https://huggingface.co/spaces/HuggingFaceTB/SmolVLM/resolve/main/example_images/rococo_1.jpg")

# Create input messages
messages = [
    {
        "role": "user",
        "content": [
            {"type": "image"},
            {"type": "image"},
            {"type": "text", "text": "Can you describe the two images?"}
        ]
    },
]

# Prepare inputs
prompt = processor.apply_chat_template(messages, add_generation_prompt=True)
inputs = processor(text=prompt, images=[image1, image2], return_tensors="pt")
inputs = inputs.to(DEVICE)
```

用预处理好的输入开始生成，并解码生成的输出。

```
# Generate outputs
generated_ids = model.generate(**inputs, max_new_tokens=500)
generated_texts = processor.batch_decode(
    generated_ids,
    skip_special_tokens=True,
)

print(generated_texts[0])
```

## 训练细节

### 数据集

首先，我们必须训练 SmolLM2 来扩展其上下文，下一章细说。在拿到长上下文的 SmolLM2 之后，我们用与 Idefics3 相同的数据训练 SmolVLM，主要使用 The Cauldron 和 Docmatix。我们使用的完整数据集列表[可以在这里查阅](https://huggingface.co/HuggingFaceTB/SmolVLM-Instruct/blob/main/smolvlm-data.pdf)。

### 上下文扩展

SmolLM2 的预训练上下文窗口对 VLM 来说不够用。图像会被编码为大量词元，而我们又想支持多张图像。为解决这个问题，我们按照 ["Scaling Laws of RoPE-based Extrapolation"](https://arxiv.org/abs/2310.05209) 的指引，把 RoPE base 值从 10k 增加到 273k，将其扩展到 16k 词元。我们在长上下文与短上下文数据的混合上微调模型。长上下文数据用 Dolma 的 "books" 子集（主要是 Project Gutenberg）和 The Stack 中 8k+ 词元的代码文档，各占最终配比的 20%。短上下文数据方面，我们精简了原先 SmolLM2 的预训练配比，包括 20% FineWeb-Edu、20% DCLM 和 20% 我们的数学数据集（即将发布）。数学数据集做了上采样，以缓解上下文扩展过程中在 GSM8k 上观察到的性能下降。所有实验基于 [EasyContext 仓库](https://github.com/jzhang38/EasyContext)实现。

### 检查点选择

在训练过程中，我们每 25 个优化步保存一次检查点，便于在不同训练阶段评估并可能恢复模型状态。这一做法对找到最优模型版本至关重要，因为训练更久并不总能保证更好。我们在多个视觉-语言基准上评估性能，每个基准按其重要性加权。核心基准包括：

- 通用多模态理解（MMMU 和 MMStar），它们是最全面的基准。
- 文档与基于文本的视觉问答（DocVQA 和 TextVQA）
- 数学推理（MathVista）
- 示意图理解（AI2D）

为了选择最优检查点，我们用一个单一指标组合这些基准，并手动赋予不同权重以反映它们在评估模型能力时的相对重要性。我们用这个单一指标选出最佳检查点。总的来说，训练越久模型在大多数基准上越好，但它们在 DocVQA 上的相对表现会明显下降。

## 微调

你可以用 transformers 微调 SmolVLM，并用 TRL 应用对齐技术 🚀

我们提供一个 [notebook](https://github.com/huggingface/smollm/blob/main/vision/finetuning/Smol_VLM_FT.ipynb)，可在 VQAv2 数据集上微调，可选 LoRA、QLoRA 或全量微调。notebook 里还有一些进一步省内存的技巧，可以用更大的批大小，把 SmolVLM 塞进 L4 这类消费级 GPU 来训练。批大小为 4、8-bit QLoRA 加载并开启梯度检查点时，就能在 L4 上微调，占用约 16 GB VRAM。这意味着你可以用 Colab 微调你的 SmolVLM！你可以自行调参，找到训练时长与内存的漂亮平衡点。

SmolVLM 还集成了 TRL，可以通过 CLI 轻松应用直接偏好优化（DPO）。先运行 `pip install trl accelerate peft` 安装并起步，然后运行以下命令在 [RLAIF-V](https://huggingface.co/datasets/HuggingFaceH4/rlaif-v_formatted) 数据集上微调：

```
accelerate launch \
  --config_file examples/accelerate_configs/multi_gpu.yaml examples/dpo_reduce_hallucinations/dpo_reduce_hallucinations.py  \
  --dataset_name HuggingFaceH4/rlaif-v_formatted \
  --model_name_or_path HuggingFaceTB/SmolVLM-Instruct \
  --per_device_train_batch_size 8 \
  --gradient_accumulation_steps 32 \
  --dataset_num_proc 32 \
  --output_dir dpo_smolvlm_rlaif-v \
  --bf16 --torch_dtype bfloat16 \
  --use_peft --lora_target_modules=all-linear 
```

得到的 LoRA 适配器权重见 [SmolVLM-Instruct-DPO](https://huggingface.co/HuggingFaceTB/SmolVLM-Instruct-DPO)。关于视觉 LLM 偏好微调的详细教程请看：[dpo_vlm](https://huggingface.co/blog/dpo_vlm)。
