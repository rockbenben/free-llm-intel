# 借助 JAX 在 Cloud TPU v5e 上加速 Stable Diffusion XL 推理

Stable Diffusion XL（SDXL）这类生成式 AI 模型，能以广泛的应用产出高质量、逼真的内容。但要发挥这些模型的威力，挑战与计算成本都不小。SDXL 是个大型图像生成模型，其 UNet 组件比上一代大约 3 倍。部署这样的模型很棘手：内存需求更高，推理时间也更长。今天，我们高兴地宣布 Hugging Face Diffusers 现已支持用 JAX 在 Cloud TPU 上服务 SDXL，实现高性能、高性价比的推理。

[Google Cloud TPU](https://cloud.google.com/tpu) 是定制设计的 AI 加速器，针对大型 AI 模型的训练与推理优化——包括最先进的 LLM 和 SDXL 这样的生成式 AI 模型。全新的 [Cloud TPU v5e](https://cloud.google.com/blog/products/compute/announcing-cloud-tpu-v5e-and-a3-gpus-in-ga) 专为大规模 AI [训练](https://cloud.google.com/blog/products/compute/using-cloud-tpu-multislice-to-scale-ai-workloads)与[推理](https://cloud.google.com/blog/products/compute/how-cloud-tpu-v5e-accelerates-large-scale-ai-inference)所需的成本效率和性能而生。价格不到 TPU v4 的一半，TPU v5e 让更多组织能够训练和部署 AI 模型。

🧨 Diffusers 的 JAX 集成提供了一种便捷方式，通过 [XLA](https://github.com/openxla/xla) 在 TPU 上运行 SDXL，我们还做了一个演示来展示它。你可以在 [这个 Space](https://huggingface.co/spaces/google/sdxl) 或下方嵌入的 playground 中试用：

这个演示的底层运行在若干 TPU v5e-4 实例上（每个实例有 4 个 TPU 芯片），并利用并行化在约 4 秒内提供四张 1024×1024 的大图。这个时间包含格式转换、通信和前端处理；正如后文所示，实际生成时间约 2.3 秒！

## 为什么 SDXL 要选 JAX + TPU v5e？

在 Cloud TPU v5e 上用 JAX 高性能、高性价比地服务 SDXL，靠的是为 AI 定制的 TPU 硬件与性能优化的软件栈相结合。下面强调两个关键因素：JAX 的即时（jit）编译，以及 XLA 编译器驱动的并行与 JAX pmap。

#### JIT 编译

JAX 的一个显著特性是[即时（just-in-time，jit）编译](https://jax.readthedocs.io/en/latest/jax-101/02-jitting.html)。JIT 编译器在首次运行时追踪代码，生成高度优化的 TPU 二进制文件，供后续调用复用。这个过程的前提是所有输入、中间值和输出的形状必须**静态**——必须事先已知。每次形状变化都会触发一次昂贵的新编译。JIT 编译非常适合能围绕静态形状设计的服务：编译只跑一次，之后就能享受超快的推理。

图像生成天生适配 JIT 编译。只要每次生成的图片数量固定、尺寸相同，输出形状就是恒定的、可预知的。文本输入同样固定：Stable Diffusion 和 SDXL 设计上就是用固定形状的嵌入向量（带 padding）表示用户输入的提示词。因此我们可以写依赖固定形状的 JAX 代码，并大幅优化它！

#### 大批次下的高吞吐

工作负载可以用 JAX 的 [pmap](https://jax.readthedocs.io/en/latest/_autosummary/jax.pmap.html) 跨多设备扩展，它表达的是单程序多数据（SPMD）程序。对函数施加 pmap 后，XLA 会编译该函数，然后在多个 XLA 设备上并行执行。对文生图负载来说，这意味着增加同时渲染的图像数量实现起来很简单，也不牺牲性能。例如，在 8 芯片的 TPU 上运行 SDXL，生成 8 张图所需时间与单芯片生成 1 张相同。

TPU v5e 实例有多种规格：1、4、8 芯片，一直到 256 芯片（一个完整的 TPU v5e pod），芯片间有超快的 ICI 互联。你可以挑选最适合自己用例的 TPU 规格，轻松享受 JAX 与 TPU 带来的并行能力。

## 如何用 JAX 写图像生成流水线

我们将一步步写出用 JAX 超快推理所需的代码！先导入依赖。

```
# Show best practices for SDXL JAX
import jax
import jax.numpy as jnp
import numpy as np
from flax.jax_utils import replicate
from diffusers import FlaxStableDiffusionXLPipeline
import time
```

现在加载 SDXL 基础模型及推理所需的其他组件。diffusers 流水线会帮我们处理下载与缓存。按照 JAX 的函数式风格，模型参数会单独返回，推理时要传给流水线：

```
pipeline, params = FlaxStableDiffusionXLPipeline.from_pretrained(
    "stabilityai/stable-diffusion-xl-base-1.0", split_head_dim=True
)
```

模型参数默认以 32 位精度下载。为节省内存、加快计算，我们把它们转换成 `bfloat16`——一种高效的 16 位表示。但有个注意点：为了最佳效果，*调度器状态（scheduler state）*必须保持 `float32`，否则精度误差会累积，导致低质量甚至全黑的图像。

```
scheduler_state = params.pop("scheduler")
params = jax.tree_util.tree_map(lambda x: x.astype(jnp.bfloat16), params)
params["scheduler"] = scheduler_state
```

现在可以设置提示词和流水线的其余输入了。

```
default_prompt = "high-quality photo of a baby dolphin ​​playing in a pool and wearing a party hat"
default_neg_prompt = "illustration, low-quality"
default_seed = 33
default_guidance_scale = 5.0
default_num_steps = 25
```

提示词必须以张量形式传给流水线，且各次调用维度必须保持一致，这样推理调用才能被编译。流水线的 `prepare_inputs` 方法会做好所有必要步骤，我们写个辅助函数把提示词和负向提示词都准备成张量，稍后在 `generate` 函数中使用：

```
def tokenize_prompt(prompt, neg_prompt):
    prompt_ids = pipeline.prepare_inputs(prompt)
    neg_prompt_ids = pipeline.prepare_inputs(neg_prompt)
    return prompt_ids, neg_prompt_ids
```

为了利用并行，我们把输入复制到各设备。一台 Cloud TPU v5e-4 有 4 个芯片，复制输入后每个芯片并行生成一张不同的图。注意要给每个芯片提供不同的随机种子，这样 4 张图才互不相同：

```
NUM_DEVICES = jax.device_count()

# Model parameters don't change during inference,
# so we only need to replicate them once.
p_params = replicate(params)

def replicate_all(prompt_ids, neg_prompt_ids, seed):
    p_prompt_ids = replicate(prompt_ids)
    p_neg_prompt_ids = replicate(neg_prompt_ids)
    rng = jax.random.PRNGKey(seed)
    rng = jax.random.split(rng, NUM_DEVICES)
    return p_prompt_ids, p_neg_prompt_ids, rng
```

现在可以把所有内容组装进 generate 函数了：

```
def generate(
    prompt,
    negative_prompt,
    seed=default_seed,
    guidance_scale=default_guidance_scale,
    num_inference_steps=default_num_steps,
):
    prompt_ids, neg_prompt_ids = tokenize_prompt(prompt, negative_prompt)
    prompt_ids, neg_prompt_ids, rng = replicate_all(prompt_ids, neg_prompt_ids, seed)
    images = pipeline(
        prompt_ids,
        p_params,
        rng,
        num_inference_steps=num_inference_steps,
        neg_prompt_ids=neg_prompt_ids,
        guidance_scale=guidance_scale,
        jit=True,
    ).images

    # convert the images to PIL
    images = images.reshape((images.shape[0] * images.shape[1], ) + images.shape[-3:])
    return pipeline.numpy_to_pil(np.array(images))
```

`jit=True` 表示我们希望编译这次流水线调用。编译发生在第一次调用 `generate` 时，会非常慢——JAX 需要追踪操作、优化并转成低层原语。我们先跑一次生成，完成这个过程、把一切"热身"到位：

```
start = time.time()
print(f"Compiling ...")
generate(default_prompt, default_neg_prompt)
print(f"Compiled in {time.time() - start}")
```

第一次大约花了三分钟。但代码一旦编译完成，推理就会飞快。再来一次！

```
start = time.time()
prompt = "llama in ancient Greece, oil on canvas"
neg_prompt = "cartoon, illustration, animation"
images = generate(prompt, neg_prompt)
print(f"Inference in {time.time() - start}")
```

现在生成 4 张图只用了大约 2 秒！

## 基准测试

以下指标在运行 SDXL 1.0 base、20 步、默认 Euler Discrete 调度器的条件下测得。我们在相同批量下对比 Cloud TPU v5e 与 TPUv4。注意，由于并行化，像我们演示所用的 TPU v5e-4 在批量为 1 时会一次生成 **4 张图**（批量为 2 时 8 张）。同理，TPU v5e-8 在批量为 1 时会生成 8 张图。

Cloud TPU 测试使用 Python 3.10 和 jax 0.4.16。与我们的 [demo Space](https://huggingface.co/spaces/google/sdxl) 规格一致。

|  | 批量大小 | 延迟 | Perf/$ |
| --- | --- | --- | --- |
| TPU v5e-4 (JAX) | 4 | 2.33s | 21.46 |
|  | 8 | 4.99s | 20.04 |
| TPU v4-8 (JAX) | 4 | 2.16s | 9.05 |
|  | 8 | 4.17 | 8.98 |

在 SDXL 上，TPU v5e 的每美元性能最高可达 TPU v4 的 2.4 倍，展示了最新一代 TPU 的成本效率。

测量推理性能，我们用行业标准指标——吞吐量。先测模型编译加载完成后每张图的延迟，再用批量大小除以每芯片延迟得到吞吐量。这样，吞吐量衡量的是模型在生产环境中的表现，与芯片数量无关。再把吞吐量除以列表价，就得到每美元性能。

## 演示是怎么跑的？

[前面展示的 demo](https://huggingface.co/spaces/google/sdxl) 用的脚本基本就是本文代码。它跑在几台各含 4 芯片的 Cloud TPU v5e 设备上，外加一个简单的负载均衡服务器，把用户请求随机路由到后端服务器。你在 demo 中输入提示词后，请求会被分配给某台后端服务器，你会收到它生成的 4 张图。

这是基于若干预分配 TPU 实例的简单方案。未来的文章里，我们会介绍如何用 GKE 构建随负载自适应的动态方案。

演示的全部代码都是开源的，今天在 Hugging Face Diffusers 中就能用上。我们很期待看到你基于 Diffusers + JAX + Cloud TPUs 构建的东西！
