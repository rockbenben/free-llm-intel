自推测解码（self-speculative decoding）在 [LayerSkip: Enabling Early Exit Inference and Self-Speculative Decoding](https://arxiv.org/abs/2404.16710) 中被提出，是一种新的文本生成方法。它把推测解码的优势与大语言模型（LLM）的提前退出（early exit）结合起来：用*同一个模型*的前几层起草 token，后面的层负责验证，从而实现高效生成。

这项技术不仅加快文本生成，还显著节省内存、降低计算延迟。要获得端到端的加速，前面层的输出需要足够接近最后一层。这通过一套训练配方实现——论文指出，该配方既可以用于预训练，也可以用于特定领域的微调。自推测解码对真实应用尤其高效：可以部署在更小的 GPU 上，降低**大规模推理**所需的整体硬件规模。

在这篇博客中，我们将探讨自推测解码的概念、实现方式，以及在 🤗 transformers 库中的实际使用。你会了解其技术要点，包括**提前退出层（early exit layers）**、**unembedding（反嵌入）**和**训练改动**。为了把这些概念落到实处，我们提供代码示例、与传统推测解码的基准对比，以及性能取舍方面的见解。

想直接了解这种方法并亲手试试，可以查看以下 Hugging Face 资源：

- [Hugging Face 论文讨论区](https://huggingface.co/papers/2404.16710)

## 推测解码与自推测解码

[![LayerSkip Demo GIF](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/layerskip-assets/LayerSkip-Demo.gif)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/layerskip-assets/LayerSkip-Demo.gif) *在 [`facebook/layerskip-llama2-7B`](https://huggingface.co/facebook/layerskip-llama2-7B)（用 LayerSkip 配方继续预训练的 Llama2 7B）上执行 LayerSkip 推理的示意。*

[传统推测解码](https://huggingface.co/blog/assisted-generation)用**两个**模型：小模型（草稿模型）生成一串草稿 token，大模型（验证模型）检验草稿是否准确。生成工作的大部分由小模型完成，大模型负责精修结果。这加快了文本生成速度，因为大模型可以一次验证整个序列，而不必逐条草稿生成。

自推测解码在此基础上更进一步：用大模型的前几层生成草稿 token，再由模型更深的层验证。这种"自"（self）推测解码需要特定训练，让同一个模型兼顾起草和验证。与传统推测解码相比，这既提升了速度又降低了计算成本。

## 在 `transformers` 中使用

要在 [🤗 transformers 库](https://github.com/huggingface/transformers)中启用提前退出的自推测解码，只需在 `generate()` 函数里加上 `assistant_early_exit` 参数。

下面的代码片段展示了这个功能。

```
pip install transformers
```

```
from transformers import AutoTokenizer, AutoModelForCausalLM

early_exit_layer = 4
prompt = "Alice and Bob"
checkpoint = "facebook/layerskip-llama2-7B"

tokenizer = AutoTokenizer.from_pretrained(checkpoint)
inputs = tokenizer(prompt, return_tensors="pt").to("cuda")

model = AutoModelForCausalLM.from_pretrained(checkpoint).to("cuda")
outputs = model.generate(**inputs, assistant_early_exit=early_exit_layer)
```

> 注意：虽然 `assistant_early_exit` 参数理论上可以为任意仅解码器（decoder-only）
> Transformer 启用提前退出自推测解码，但除非模型经过专门训练，
> 否则中间层的 logits 无法被 unembed（通过 LM Head 解码的过程，本文后面会介绍）。
> 也只有按提升前几层精度的方式训练出的 checkpoint 才会带来加速。
> LayerSkip 论文提出了实现这一点的训练配方
> （即施加提前退出损失，并逐层递增 dropout 率）。
> 一批用 LayerSkip 训练配方继续预训练的 Llama2、Llama3 和 Code Llama
> checkpoint 已提供。

## 提前退出与 Unembedding

自推测解码的一项关键技术是提前退出（early exit）：生成过程可以在预先指定的某一层停止。为此，我们把这些层的 logits **unembed**——将它们投影到语言模型（LM）head 上以预测下一个 token。这样模型可以跳过后续各层，改善推理时间。

unembedding 可以在任意 Transformer 层执行，使提前退出成为一种高效的 token 预测机制。一个自然的问题是：LM head 当初只针对最后一层训练，怎么让它适配更早层的 logits？这就是训练改动的用武之地。

## 训练改动：*层 Dropout* 与*提前退出损失*

在训练阶段，我们引入**层 dropout（layer dropout）**，让模型在训练中可以跳过某些层。dropout 率随层数加深而递增，使模型不那么依赖后面的层，同时增强泛化能力、加快训练。

除层 dropout 外，还施加**提前退出损失（early exit loss）**，确保 LM head 学会 unembed 各个层。带提前退出的模型总损失函数是各退出点（中间层）归一化损失之和。这项技术把学习任务分散到所有层，从而实现高效训练。

## 自起草与自验证

训练完成后，推理时就可以用自推测解码。[流程](https://huggingface.co/docs/transformers/v4.46.3/en/llm_optims#speculative-decoding)从**自起草（self-drafting）**开始：token 由某个中间层提前输出生成。推测 token 的数量决定这一阶段产出多少草稿 token，而选择的退出层决定起草阶段规模多大、精度多高。这两个参数都可以在推理时指定，在[起草阶段的速度与精度之间做取舍](https://huggingface.co/blog/assisted-generation)。

下一阶段是**自验证（self-verification）**：用完整模型验证草稿 token。验证模型复用草稿模型已产生的那部分缓存。如果草稿 token 与验证结果一致，就直接并入最终输出——这更好地利用了系统的内存带宽，因为只要若干 token 能匹配上，用完整模型生成一串 token 远比验证一份草稿昂贵。

在自验证阶段，只需要计算剩余的层，因为前面各层的结果已经在起草阶段缓存好了。

## 优化点：共享权重、共享 KV 缓存、共享计算

自推测解码从缓存复用中获益良多，尤其是 **KV 缓存**，它存储起草阶段计算出的键值对。由于草稿和验证阶段使用相同的前几层，缓存让模型跳过重复计算。此外，**退出 query 缓存（exit query cache）**存储退出层的 query 向量，让验证能够无缝衔接起草阶段继续执行。

与传统的双模型推测解码相比，提前退出式自推测解码还能获得以下节省：

- **共享权重**：前 E 层的权重在起草和验证中都被复用。
- **共享 KV 缓存**：前 E 层的键值对在起草和验证中都被复用。
- **共享计算**：通过 **Exit Query Cache** 只保存退出层 E−1 的 query 向量，前 E 层的计算被复用，验证过程无需再计算第 0 到 E−1 层。

KV 缓存与退出 query 缓存的组合（称为 **KVQ 缓存**）降低了内存开销、改善了推理延迟。

目前 🤗 transformers 库已在这份 [pull request](https://github.com/huggingface/transformers/pull/34240) 中实现了第一项优化（共享权重）。随着使用该方法模型数量的增加，我们会考虑其余优化。感兴趣的话欢迎提 PR！

## 我们最早能在哪一层退出？

起草阶段的提前退出层是一个超参数，可以在推理时调优或修改：

- 退出得越早，草稿 token 生成越快，但精度越低。
- 退出得越晚，草稿 token 精度越高，但生成越慢。

我们可以观察到：

- 对于没有用 LayerSkip 训练配方预训练或继续预训练的基线 checkpoint，提前退出式自推测解码反而比自回归解码更慢。这是因为多数 LLM 在训练时，前面的层并没有被激励去学习预测输出，所以用前面的层生成 token 的接受率会非常低。
- 反过来，对用 LayerSkip 训练配方继续预训练的 Llama checkpoint，至少有一部分层的提前退出式自推测解码比自回归解码有更高加速。除 Llama3.2 1B 外，大多数模型在逐层扫描时呈现一个规律模式：前几层的加速较低，随后逐渐增大到一个最佳点，然后再下降。提前退出层的最佳点，就是预测精度与生成开销之间取舍最优的位置。这个最佳点因模型而异，也可能取决于提示词或提示词所属领域。

这些观察为进一步实验和探索提供了有趣的机会。鼓励读者在这些想法之上继续测试各种变体、开展自己的研究——这些努力会带来有价值的见解，也能切实推动这个领域。

## 总结

LayerSkip 把提前退出、层 dropout 和缓存复用三者的合力用在文本生成流水线上，做到又快又省。通过训练模型 unembed 各层输出，并用缓存优化验证过程，这种方法在速度与精度之间取得了平衡。因此它在保持高质量输出的同时显著改善了大语言模型的推理时间。由于同一个模型兼任草稿模型和验证模型，它也比传统推测解码技术更省内存。

自推测（self-speculation）是个令人兴奋的领域——同一个 LLM 既能生成草稿 token 又能自我纠错。其他自推测方法还包括：

- [Draft & Verify](https://aclanthology.org/2024.acl-long.607/)：起草阶段跳过预先设定的注意力和前馈层。
- [MagicDec](https://arxiv.org/abs/2408.11049)：起草阶段只使用 KV 缓存的子集，对长上下文输入很有用。
- [Jacobi Decoding](https://arxiv.org/abs/2305.10427) 和 [Lookahead Decoding](https://arxiv.org/abs/2402.02057)：起草阶段是一串"猜测 token"，可以来自随机或 n-gram 查询表。
