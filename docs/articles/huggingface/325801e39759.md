# 用 TRL 为视觉语言模型做偏好优化

这篇文章也有中文版 [简体中文](https://huggingface.co/blog/zh/dpo_vlm)。

训练模型去理解和预测人类偏好可以极其复杂。传统方法（比如监督微调）常常要求给数据打具体标签，对于细腻的任务来说成本并不划算。偏好优化是另一种思路，可以简化这个过程并得到更准确的结果。通过把重点放在比较和排序候选答案而非固定标签上，偏好优化能让模型更有效地捕捉人类判断中的微妙之处。

偏好优化被广泛用于语言模型微调，但它同样可以应用于视觉语言模型（VLM）。我们很高兴地宣布 **[TRL](https://huggingface.co/docs/trl/index) 库现已支持面向 VLM 的直接偏好优化（DPO）**。本文将带你走完用 TRL 和 DPO 训练 VLM 的全过程。

## 偏好数据集

偏好优化需要能体现用户偏好的数据。在二选一设定下，每个样本包含一个提示词和两个候选答案：一个被选中（chosen），一个被拒绝（rejected）。模型的目标是学会预测出被选中的答案而不是被拒绝的那个。比如，你需要下面这样的样本：

Image from

openbmb/RLAIF-V-Dataset

**❔ 问题**：*有多少个家庭？*

- **❌ 被拒绝：** *图片没有提供任何关于家庭的信息。*
- **✅ 被选中：** *图片展示了一个 Union Organization 表格配置，包含 18,000 个家庭。*

注意，被选中的消息不一定是正确的。比如被选中的回答说是 18,000 个家庭，仍然是错的，只是相对于被拒绝的回答错得更少。

本文中我们使用 [openbmb/RLAIF-V-Dataset](https://huggingface.co/datasets/openbmb/RLAIF-V-Dataset)，它包含超过 83,000 条标注记录。我们来仔细看看这个数据集：

```
>>> from datasets import load_dataset
>>> dataset = load_dataset("openbmb/RLAIF-V-Dataset", split="train[:1%]")
>>> sample = dataset[1]
>>> sample["image"].show()
>>> sample["question"]
'how many families?'
>>> sample["rejected"]
'The image does not provide any information about families.'
>>> sample["chosen"]
'The image shows a Union Organization table setup with 18,000 families.'
```

我们的模型需要文本和图片共同作为输入，所以第一步是把数据集格式化成符合要求的样子。数据应被组织成模拟用户与助手之间对话的形式：用户提供包含图片和问题的提示词，助手给出回答。格式化是这样做的：

```
from datasets import features
from transformers import AutoProcessor

processor = AutoProcessor.from_pretrained("HuggingFaceM4/idefics2-8b", do_image_splitting=False)

def format(example):
    # Prepare the input for the chat template
    prompt = [
        {
            "role": "user",
            "content": [{"type": "image"}, {"type": "text", "text": example["question"]}],
        },
    ]
    chosen = [
        {
            "role": "assistant",
            "content": [{"type": "text", "text": example["chosen"]}],
        },
    ]
    rejected = [
        {
            "role": "assistant",
            "content": [{"type": "text", "text": example["rejected"]}],
        },
    ]
    # Apply the chat template
    prompt = processor.apply_chat_template(prompt, tokenize=False)
    chosen = processor.apply_chat_template(chosen, tokenize=False)
    rejected = processor.apply_chat_template(rejected, tokenize=False)
    # Resize the image to ensure it fits within the maximum allowable
    # size of the processor to prevent OOM errors.
    max_size = processor.image_processor.size["longest_edge"]
    example["image"].thumbnail((max_size, max_size))
    return {"images": [example["image"]], "prompt": prompt, "chosen": chosen, "rejected": rejected}

# Apply the formatting function to the dataset,
# remove columns to end up with only "images", "prompt", "chosen", "rejected" columns
dataset = dataset.map(format, remove_columns=dataset.column_names)

# Make sure that the images are decoded, it prevents from storing bytes.
# More info here https://github.com/huggingface/blog/pull/2148#discussion_r1667400478
f = dataset.features
f["images"] = features.Sequence(features.Image(decode=True))  # to avoid bytes
dataset = dataset.cast(f)
```

```
 'rejected': 'Assistant: The image does not provide any information about families.<end_of_utterance>\n',
 'chosen': 'Assistant: The image shows a Union Organization table setup with 18,000 families.<end_of_utterance>\n'}
```

## 训练

作为示例，我们训练 [Idefics2-8b](https://huggingface.co/HuggingFaceM4/idefics2-8b) 模型，但注意 TRL 的 DPO 实现也支持其他模型，如 [Llava 1.5](https://huggingface.co/llava-hf/llava-1.5-7b-hf) 和 [PaliGemma](https://huggingface.co/google/paligemma-3b-pt-224)。更多信息见 [Finetuning Llava 1.5, PaliGemma and others](https://huggingface.co/blog/dpo_vlm#finetuning-llava-15-paligemma-and-others) 一节。在进入训练流程之前，我们先确保一切能顺畅地放进显存。

### 我需要多少显存？

我有一张 80GB 显存的 GPU，够训练我的 Idefics2-8b 模型吗？下面是估算所需显存的计算步骤。

设 N 为参数量，P 为精度。以下组件必须一起塞进显存：

- **待训练模型**：N×P N \times P N×P
- **参考模型**：参考模型和待训练模型一样大，所以同样需要 N×P N \times P N×P
- **梯度**：我们训练整个模型，每个参数都需要一份梯度，因此需要 N×P N \times P N×P
- **优化器状态**：我们使用 [AdamW](https://pytorch.org/docs/stable/generated/torch.optim.AdamW.html)，每个参数需要两个状态，因此需要 2×N×P 2 \times N \times P 2×N×P

Idefics2-8b 有 80 亿参数，我们用 `float32` 精度，每个浮点数占 4 字节。于是总显存需求为：

| 组件 | 计算 | 显存 |
| --- | --- | --- |
| 待训练模型 | 8×109×4 8 \times 10^9 \times 4 8×109×4 | 32 GB |
| 参考模型 | 8×109×4 8 \times 10^9 \times 4 8×109×4 | 32 GB |
| 梯度 | 8×109×4 8 \times 10^9 \times 4 8×109×4 | 32 GB |
| 优化器状态 | 2×8×109×4 2 \times 8 \times 10^9 \times 4 2×8×109×4 | 64 GB |
| **总计** |  | **160 GB** |

这远超我 GPU 的显存容量。幸运的是，通过量化和 LoRA 等技术，我们可以大幅降低显存需求，让训练变得可行。我们来看看怎么做。

### 量化

量化是降低模型权重和激活精度的技术。从 `float32` 切到 `bfloat16`，每个参数的存储需求从 4 字节减半到 2 字节。这个优化既节省显存又加速计算，性能几乎不打折。要在模型中启用 `bfloat16` 精度：

```
import torch
from transformers import AutoModelForVision2Seq

model = AutoModelForVision2Seq.from_pretrained("HuggingFaceM4/idefics2-8b", torch_dtype=torch.bfloat16)
```

`bfloat16` 精度也可以通过在训练参数中设置 `bf16=True` 应用到优化器：

```
from transformers import TrainingArguments

training_args = TrainingArguments(..., bf16=True)
```

### LoRA

[LoRA](https://arxiv.org/abs/2106.09685) 通过在学习原始权重保持冻结的同时训练成对的秩分解矩阵，减少可训练参数数量。这显著降低了适配特定任务的 LLM 的存储需求。LoRA 已集成进 [PEFT](https://github.com/huggingface/peft)，配置起来非常快：

```
  from transformers import AutoModelForVision2Seq
+ from peft import get_peft_model, LoraConfig

  model = AutoModelForVision2Seq.from_pretrained("HuggingFaceM4/idefics2-8b")
+ peft_config = LoraConfig(target_modules="all-linear")
+ model = get_peft_model(model, peft_config)
```

PEFT 像一层包装（称为 *adapter*，适配器）套在模型外面。训练时训练的是这层适配器，内层模型保持冻结。LoRA 把可训练参数减少到多少？

```
>>> model.print_trainable_parameters()
trainable params: 55,348,736 || all params: 8,458,116,848 || trainable%: 0.6543860411799315
```

可训练参数从 80 亿降到 5500 万，差距巨大，这会显著降低显存需求。

### 量化 + LoRA 之后的新显存需求

既然显存需求已经降下来了，我们重新算一遍：

| 组件 | 计算 | 显存 |
| --- | --- | --- |
| 待训练模型 | 8G×2 8 \mathrm{G} \times 2 8G×2 | 16 GB |
| 参考模型 | 8G×2 8 \mathrm{G} \times 2 8G×2 | 16 GB |
| 梯度 | 55M×2 55 \mathrm{M} \times 2 55M×2 | 0.1 GB |
| 优化器状态 | 2×55M×2 2 \times 55 \mathrm{M} \times 2 2×55M×2 | 0.2 GB |
| **总计** |  | **32.3 GB** |

这次我们只需要约 32GB 显存就能微调 Idefics2-8b，合理多了，我的 GPU 装得下！

想了解更多用 LoRA 和 QLoRA 优化显存的信息，可参考 [PEFT 文档](https://huggingface.co/docs/peft/en/index)，或 Google 的 [面向 LLM 的 LoRA 与 QLoRA 建议](https://cloud.google.com/vertex-ai/generative-ai/docs/model-garden/lora-qlora)。

### 那 batch size 呢？

我们的显存计算并不精确，因为它没有计入激活值。激活值是网络各层的中间输出，其显存需求取决于模型结构和 batch size。精确计算激活值所需显存很有挑战，所以我们依靠经验判断。

选择训练 batch size（`per_device_train_batch_size`）的方法是：从你希望的 batch size 开始（比如 64）。这大概率会触发显存溢出（OOM）错误。如果是，把 batch size 减半、把梯度累积步数（`gradient_accumulation_steps`）翻倍，以保持等效 batch size 不变。重复这个过程直到显存放得下。在我们的例子里，最终用到 batch size 为 2、梯度累积步数为 32。

另一个优化是用梯度检查点（`gradient_checkpointing`）降低激活值的显存需求。这个技术通过在反向传播时重算网络的部分组件，用计算换显存。在训练参数里设 `gradient_checkpointing=True` 即可启用。

### 总结：完整训练脚本

模型、数据集、训练参数都已就绪，可以开训了。下面是把所有东西拼进一个脚本的方式，还包括一些加速处理的额外项，比如 `dataset_num_proc` 和 `dataloader_num_workers`：

```
# dpo_idefics2-8b.py
from datasets import features, load_dataset
from transformers import AutoModelForVision2Seq, AutoProcessor
import torch
from trl import DPOConfig, DPOTrainer
from peft import LoraConfig


def main():
    # Load the model and processor
    model = AutoModelForVision2Seq.from_pretrained("HuggingFaceM4/idefics2-8b", torch_dtype=torch.bfloat16)
    processor = AutoProcessor.from_pretrained("HuggingFaceM4/idefics2-8b", do_image_splitting=False)

    # Load the dataset
    dataset = load_dataset("openbmb/RLAIF-V-Dataset", split="train")

    def format(example):
        # Prepare the input for the chat template
        prompt = [{"role": "user", "content": [{"type": "image"}, {"type": "text", "text": example["question"]}]}]
        chosen = [{"role": "assistant", "content": [{"type": "text", "text": example["chosen"]}]}]
        rejected = [{"role": "assistant", "content": [{"type": "text", "text": example["rejected"]}]}]
        # Apply the chat template
        prompt = processor.apply_chat_template(prompt, tokenize=False)
        chosen = processor.apply_chat_template(chosen, tokenize=False)
        rejected = processor.apply_chat_template(rejected, tokenize=False)
        # Resize the image to ensure it fits within the maximum allowable
        # size of the processor to prevent OOM errors.
        max_size = processor.image_processor.size["longest_edge"] // 2
        example["image"].thumbnail((max_size, max_size))
        return {"images": [example["image"]], "prompt": prompt, "chosen": chosen, "rejected": rejected}

    # Apply the formatting function to the dataset
    dataset = dataset.map(format, remove_columns=dataset.column_names, num_proc=32)

    # Make sure that the images are decoded, it prevents from storing bytes.
    # More info here https://github.com/huggingface/blog/pull/2148#discussion_r1667400478
    f = dataset.features
    f["images"] = features.Sequence(features.Image(decode=True))
    dataset = dataset.cast(f)

    # Train the model
    training_args = DPOConfig(
        output_dir="idefics2-8b-dpo",
        bf16=True,
        gradient_checkpointing=True,
        per_device_train_batch_size=2,
        gradient_accumulation_steps=32,
        num_train_epochs=1,
        dataset_num_proc=32,  # tokenization will use 32 processes
        dataloader_num_workers=32,  # data loading will use 32 workers
        logging_steps=10,
    )
    trainer = DPOTrainer(
        model,
        ref_model=None,  # not needed when using peft
        args=training_args,
        train_dataset=dataset,
        tokenizer=processor,
        peft_config=LoraConfig(target_modules="all-linear"),
    )

    trainer.train()


if __name__ == "__main__":
    main()
```

## 结果

几个小时后，训练完成。我们来看看训练曲线：

[![Learning curves](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dpo_vlm/learning_curves.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dpo_vlm/learning_curves.png)

在 DPO 中，我们关注几个指标来评估训练质量：

- **准确率（Accuracy）**：该指标表示在训练样本中，模型输出 chosen 答案而非 rejected 答案概率更高的比例。可以看到准确率在提升，这是积极信号。
- **奖励（Rewards）**：奖励与答案被选中的概率相关。更多细节参见 [DPO 论文第 5 节](https://arxiv.org/abs/2305.18290)。我们期望 chosen 答案的奖励高于 rejected 答案。为验证这一点，我们看*奖励边际（reward margin）*——chosen 与 rejected 答案奖励之差。如此处所见的奖励边际增大，也是好兆头。

### 推理

模型训练完成后，下一步是在一些样例上评估它的表现，让我们对模型学得好不好、预测是否有效有个直观感受。下面这个脚本可以帮你评估模型并在测试样例上分析其表现：

```
from transformers import AutoModelForVision2Seq, AutoProcessor
from PIL import Image

model = AutoModelForVision2Seq.from_pretrained("HuggingFaceM4/idefics2-8b").to("cuda")
processor = AutoProcessor.from_pretrained("HuggingFaceM4/idefics2-8b", do_image_splitting=False)
model.load_adapter("HuggingFaceH4/idefics2-8b-dpo-rlaif-v-v0.3")  # <-- Load the adapter we've just trained

# Process
user_message = ...
image_path = ...
data = [{"role": "user", "content": [{"type": "image"}, {"type": "text", "text": user_message}]}]
prompts = processor.apply_chat_template(data, add_generation_prompt=True)  # add_generation_prompt=True to end the prompt with "ASSISTANT:"
images = [Image.open(image_path)]
inputs = processor(prompts, images, return_tensors="pt")
inputs = {k: v.to("cuda") for k, v in inputs.items()}

# Generate
generated_ids = model.generate(**inputs, max_new_tokens=500)
response_text = processor.batch_decode(generated_ids, skip_special_tokens=True)[0]
print(response_text)
```

## 微调 Llava 1.5、PaliGemma 及其他

写作本文时，TRL 的 DPO 实现支持 Idefics2、Llava 1.5 和 PaliGemma，并且正在持续增加对更多模型的支持。微调这些模型最简单的方式是使用 TRL 仓库提供的[示例脚本](https://github.com/huggingface/trl/blob/main/examples/dpo_reduce_hallucinations/dpo_reduce_hallucinations.py)。例如，微调 PaliGemma 可以用下面这条命令：

```
accelerate launch examples/dpo_reduce_hallucinations/dpo_reduce_hallucinations.py \
    --dataset_name HuggingFaceH4/rlaif-v_formatted \
    --model_name_or_path google/paligemma-3b-pt-224 \
    --per_device_train_batch_size 2 \
    --gradient_accumulation_steps 32 \
    --dataset_num_proc 32 \
    --output_dir dpo_paligemma_rlaif-v \
    --bf16 \
    --torch_dtype bfloat16 \
    --gradient_checkpointing \
    --use_peft \
    --lora_target_modules=all-linear
```

关于 PaliGemma 微调的详细专讲，可以查看 [smol-vision](https://github.com/merveenoyan/smol-vision) 项目。
