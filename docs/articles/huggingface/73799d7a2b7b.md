# 聊聊机器学习中的偏见！

*ML 中的偏见无处不在，ML 中的偏见也很复杂——复杂到没有任何单一的技术干预可能真正解决它引发的问题。ML 模型作为社会-技术系统，会放大某些社会趋势，以依赖部署语境、且不断演化的方式加剧不公与有害偏见。*

*这意味着，用心开发 ML 系统需要保持警惕、回应部署语境发回的反馈；而我们可以通过跨语境分享经验、并在 ML 开发的每个层级开发偏见分析工具来促成这一点。*

## *机器偏见*：从 ML 系统到个人与社会风险

ML 系统让我们能在前所未有的规模上自动化复杂任务，因为它们正被部署到越来越多的行业和使用场景。技术发挥最好的一面时，能润滑人与技术系统之间的互动、免除高度重复的工作、或打开处理信息支持研究的新方式。

但这些系统同样很可能复现其训练数据中记录的歧视性与侵害性行为——当数据编码了人类行为时尤其如此。于是技术有潜力让这些问题严重得多。自动化与规模化部署确实能够：

- **锁死（lock in）**行为于时间之中，阻碍社会进步[被技术反映出来](https://dl.acm.org/doi/10.1145/3442188.3445922)，
- 把有害行为[传播到](https://arxiv.org/abs/2203.07785)原始训练数据[语境之外]，
- 通过在做预测时[过度聚焦刻板联想](https://arxiv.org/abs/2010.03058)而**放大**不公，
- 把偏见[藏进"黑箱"系统](https://pubmed.ncbi.nlm.nih.gov/33737318/)，从而**剥夺申诉的可能性**。

为了更好地理解和应对这些风险，ML 研究者和开发者开始研究*机器偏见*（machine bias）或*算法偏见*（algorithmic bias）——即可能导致系统编码**负面刻板印象或联想**、或对其部署语境中不同人群群体表现出**表现差异**（disparate performance）等问题的机制。

**这些问题对包括 Hugging Face 及更广泛 ML 社区在内的许多研究开发者来说极为切身**。Hugging Face 是一家[国际化公司](https://twitter.com/osanseviero/status/1587444072901492737)，我们中的许多人生活在国家与文化之间。当我们看到自己从事的技术在开发时[缺乏足够的顾虑](https://dl.acm.org/doi/10.1145/3461702.3462624)去保护像我们一样的人，那种紧迫感很难尽述——尤其当这些系统造成歧视性的[错误逮捕](https://incidentdatabase.ai/cite/72/)或不必要的[经济困境](https://racismandtechnology.center/2021-10-29/amnestys-grim-warning-against-another-toeslagenaffaire/)，并且正被[越来越多地卖给](https://www.oecd.org/migration/mig/EMN-OECD-INFORM-FEB-2022-The-use-of-Digitalisation-and-AI-in-Migration-Management.pdf)世界各地的移民执法和治安部门时。同样，看到我们的身份在日常中被[从训练数据集中抹除](https://aclanthology.org/2021.emnlp-main.98/)或在"生成式 AI"[系统的输出](https://huggingface.co/spaces/sasha/StableDiffusionBiasExplorer)中[代表性不足](https://twitter.com/willie_agnew/status/1592829238889283585)，把这些关切与我们日常的生活体验联结起来——[既启发人，也消耗人](https://www.technologyreview.com/2022-10-28/1062332/responsible-ai-has-a-burnout-problem/)。

虽然我们的亲身经历远不足以覆盖 ML 介导的歧视以何种方式不成比例地伤害与我们经历不同的人，但它们为思考这项技术内含的取舍提供了一个入口。我们从事这些系统，是因为我们**坚信 ML 的潜力——我们认为，只要以用心来开发、听取其部署语境中人们的意见**，而不是把它当作放之四海皆准的万灵药，ML 就能作为有价值的工具大放异彩。具体来说，要实现这种用心，需要更好地理解机器偏见在 ML 开发流程中的各种机制，并开发工具，帮助[拥有不同技术知识水平的人都能参与到必要的讨论](https://www.vice.com/en/article/bvm35w/this-tool-lets-anyone-see-the-bias-in-ai-image-generators)——讨论其利弊如何分配。

这篇来自 Hugging Face [Ethics and Society regulars](https://huggingface.co/blog/ethics-soc-1) 的博文，概述了我们如何着手、正在如何着手、以及建议 HF 库生态的用户如何在 ML 开发流程的各个阶段应对偏见，以及我们为支撑这个过程开发的工具。希望它能成为一份有用的资源，引导你具体思考自己工作的社会影响，并利用文中提到的工具在这些问题出现时加以缓解。

## 把偏见放进语境

处理机器偏见时第一个、也许最重要的概念是**语境**。Su Lin Blodgett 等人在关于 [NLP 中的偏见](https://aclanthology.org/2020.acl-main.485.pdf)的奠基性工作里指出：*"[T]he majority of [academic works on machine bias] fail to engage critically with what constitutes 'bias' in the first place"*（大多数关于机器偏见的学术工作从一开始就没批判性地厘清"偏见"指什么），其中包括把她们的工作建立在*"关于哪些系统行为有害、以何种方式、对谁有害、为何有害的未言明假设"*之上。

考虑到 ML 研究社区[对"泛化"价值的推崇](https://dl.acm.org/doi/10.1145/3531146.3533083)——它是仅次于"性能"该领域工作被引用最多的动机——这或许不奇怪。然而，适用于广泛场景的偏见评估工具，对**促成跨模型行为共性趋势的更宏观分析**很有价值，但它们在**具体使用场景**中直指歧视成因的能力天然有限。要用它们指导 ML 开发周期内的具体决策，通常还需要多走一两步，把系统的具体使用语境和受影响的人纳入考量。

![Excerpt on considerations of ML uses context and people from the Model Card Guidebook](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ethics_soc_2/img_foresight.png) *[Model Card Guidebook](https://huggingface.co/docs/hub/model-cards) 中关于 ML 使用语境与人群考量的一节*

接下来深入看看"孤立的/无语境的 ML 产物中的偏见"与"具体伤害"之间的联系。一个有用的思路是把**机器偏见看作基于歧视的伤害的风险因素**。举个例子：一个文生图模型在被要求生成职业场景中的人物图像时会过度表现浅肤色，但在[提示词提到犯罪](https://arxiv.org/abs/2211.03759)时却生成更深的肤色。这些倾向就是我们说的*模型层面的机器偏见*。现在设想几个使用该文生图模型的系统：

- 模型被集成进一个网站创建服务（比如 SquareSpace、Wix），帮用户生成页面背景。该模型明确禁用在生成背景中的人物图像。这种情况下，机器偏见的"风险因素"没有导致歧视性伤害，因为偏见聚焦的对象（人物图像）在使用场景中根本不存在。对机器偏见不需要进一步的风险缓解，尽管开发者应当留意关于在商业系统中集成用抓取数据训练的模型合法性的持续讨论。
- 模型被集成进一个图库网站，为用户提供（比如职业场景中）人物的合成图像，隐私顾虑更少，例如用来给 Wikipedia 条目配图。这种情况下，机器偏见起到**锁死**并**放大**既有社会偏见的作用。它强化了关于人群的刻板印象（"CEO 都是白人男性"），这些印象又回流进复杂的社会系统，在更多层面引发更多歧视（例如强化职场中的[隐性偏见](https://philpapers.org/rec/BEEAIT-2)）。缓解策略可以包括教育图库用户认识这些偏见，或者图库网站可以对生成图像做策展，有意提供更多样的形象。
- 模型被集成进一个卖给警察部门的"虚拟模拟画像"软件，基于口头证词生成嫌疑人画像。这种情况下，机器偏见直接造成歧视：系统性地把警方引向深色肤色人群，令他们面临更高伤害风险，包括身体伤害与非法拘禁。这类情形下，可能任何程度的偏见缓解都无法把风险降到可接受。特别地，这种用例与执法语境下面部识别高度相关——类似的[偏见问题](https://www.law.georgetown.edu/privacy-technology-center/publications/a-forensic-without-the-science-face-recognition-in-u-s-criminal-investigations/)已促使多家商业机构和立法机关采纳暂停或全面禁止其使用的禁令。

那么，谁要为 ML 中的机器偏见担责？这三种情形说明了为什么关于 ML 开发者应对偏见之责任的讨论会如此复杂：取决于在 ML 系统开发流程的其他节点由其他人做出的决策，一个 ML 数据集或模型中的偏见，其后果可能落在"与应用场景无关"到"直接导致严重伤害"之间的任何位置。然而，在所有这些情形中，**模型/数据集中更强的偏见都会增加负面结果的概率**。欧盟已在[近期的监管努力](https://ec.europa.eu/info/business-economy-euro/doing-business-eu/contract-rules/digital-contracts/liability-rules-artificial-intelligence_en)中着手建立应对这一现象的框架：简单说，部署基于可测量有偏模型的 AI 系统的公司，要为系统造成的伤害担责。

把偏见概念化为风险因素，能让我们更好理解各个阶段开发者之间对机器偏见的**共同责任**。偏见永远无法被彻底根除——部分原因是社会偏见的定义、以及把它们与歧视绑定的权力关系，在不同社会语境中天差地别。但是：

- 开发流程的每个阶段——任务规格、数据集策划、模型训练，到模型集成与系统部署——都能采取行动，**最小化那些最直接依赖其选择**与技术决策**的机器偏见方面**，以及
- 各 ML 开发阶段之间清晰的沟通与**信息流动**，能决定做出的是层层叠加、削弱偏见负面潜力的选择（正如上文部署情形 1 的多管齐下偏见缓解策略），*还是*相互叠加、放大伤害风险的选择（正如部署情形 3）。

下一节，我们将检视这些阶段以及每个阶段上可以帮助应对机器偏见的一些工具。

## 在 ML 开发全流程中应对偏见

准备好接受实操建议了吗？开始 🤗

开发 ML 系统没有唯一的路径；哪些步骤以什么顺序发生，取决于诸多因素：开发环境（大学、大公司、初创、草根组织……）、模态（文本、表格数据、图像……）、以及公开 ML 资源的丰富或稀缺。不过，我们可以识别出应对偏见时特别值得关注的三个常见阶段：任务定义、数据策划和模型训练。我们来看看偏见处理在这些阶段中可能有何不同。

### 我正在为我的 ML 系统定义任务，如何应对偏见？

系统中的偏见在多大程度上具体影响人，最终取决于系统被用来做什么。因此，开发者能着手缓解偏见的第一个位置，就是决定 ML 在其系统中如何安放的时候——比如决定它要用的优化目标。

举个例子，回到最早被高度关注的生产环境算法内容推荐 ML 系统案例之一。2006 到 2009 年，Netflix 举办了 [Netflix Prize](https://www.cs.uic.edu/~liub/KDD-cup-2007/proceedings/The-Netflix-Prize-Bennett.pdf)——一场百万美元奖金的竞赛，挑战全球团队开发能基于用户历史评分准确预测其对新电影打分的 ML 系统。[获奖方案](https://www.asc.ohio-state.edu/statistics/dmsl/GrandPrize2009_BPC_BigChaos.pdf)把未见用户-电影对的预测 RMSE（均方根误差）相比 Netflix 自家的 CineMatch 算法改进了 10% 以上——也就是说，它非常擅长根据用户历史预测他们会给新电影打多少分。这一做法开启了现代算法内容推荐的大门，也让公众认识到 ML 在推荐系统中建模用户偏好的角色。

这和偏见有什么关系？给人们展示他们可能喜欢的内容，难道不是内容平台的好服务吗？结果证明，给人们更多展示**他们过去喜欢过的东西**，最终会[降低他们消费的媒体多样性](https://dl.acm.org/doi/10.1145/3391403.3399532)。不仅长期看用户[满意度更低](https://dl.acm.org/doi/abs/10.1145/3366423.3380281)，还意味着初始模型捕捉到的任何偏见或刻板印象——无论是建模[美国黑人用户偏好](https://www.marieclaire.com/culture/a18817/netflix-algorithms-black-movies/)的时候，还是[系统性不利于](https://dl.acm.org/doi/10.1145/3269206.3272027)某些创作者的动态——如果模型继续在[ML 介导的用户交互](https://arxiv.org/abs/2209.03942)上训练，都很可能被强化。这体现了我们上文提到的两类偏见关切：训练目标充当了偏见相关伤害的**风险因素**，因为它让既有偏见更可能出现在预测中；任务设定则起到**锁死**并加剧过往偏见的作用。

在这一阶段，一个有前景的偏见缓解策略是重构任务，在把 ML 用于算法内容推荐时显式地[同时建模参与度与多样性](https://dl.acm.org/doi/10.1145/3437963.3441775)。用户长期满意度可能更高，上文所述加剧偏见的风险也降低了！

这个例子说明：ML 支撑的产品中机器偏见的影响，不仅取决于我们决定在哪里使用 ML，还取决于 ML 技术如何被整合进更大的技术系统、以什么目标整合。当我们初步考察 ML 如何融入一个你感兴趣的产品或使用场景时，我们建议先别急着看可用的模型或数据集，而是先透过偏见的镜头寻找系统的失败模式——这个领域现有系统的哪些行为在 ML 预测加剧偏见时会特别有害或更常发生？

我们为另一个算法内容管理案例——[自动内容审核中的仇恨言论检测](https://aclanthology.org/2022.hcinlp-1.2/)——构建了一个[工具](https://huggingface.co/spaces/hf-task-exploration/ExploreACMnaacl)，带用户回答这些问题。我们发现，只阅读并不特别聚焦技术 ML 部分的新闻和学术文章，就已经是感知偏见在何处起作用的好办法。强烈建议去看看这个例子，了解模型和数据集如何与部署语境契合、如何关联到已知的偏见相关伤害！

#### 任务定义：建议

ML 任务定义与部署影响偏见相关伤害风险的方式，和 ML 系统的应用一样多。如上文的例子，一些常见步骤有助于决定要不要、以及如何应用 ML 并把偏见风险降到最低：

- 调研：ML 之前该领域已有的偏见报道；你的具体用例中处于风险的人群类别
- 审视：你的优化目标对偏见的强化作用； favor 多样性与长期正面影响的可替代目标

### 我正在为我的 ML 系统策划/挑选数据集，如何应对偏见？

虽然训练数据集并[非偏见的唯一来源](https://www.cell.com/patterns/fulltext/S2666-3899(21)00061-1)，但它扮演重要角色。你的[数据集是否不成比例地把](https://aclanthology.org/2020.emnlp-main.23/)女性传记与生活事件关联、而把男性传记与成就关联？这些**刻板印象**八成会出现在你的完整 ML 系统里！你的语音识别数据集是否只收录特定口音？这对用它构建的[技术包容性](https://www.scientificamerican.com/article/speech-recognition-tech-is-yet-another-example-of-bias/)而言不是好兆头——**表现差异**！**无论你是在为 ML 应用策划数据集，还是挑选数据集训练 ML 模型**，发现、缓解并[向外界传达](https://dl.acm.org/doi/10.1145/3479582)数据在多大程度上呈现这些现象，都是降低偏见相关风险的必要步骤。

通常，通过思考数据集从哪来、数据中表现的是哪些人、策划过程是什么，就能对可能的偏见有很好的感知。针对这种反思与记录，学界提出了若干框架，例如 [Data Statements for NLP](https://direct.mit.edu/tacl/article/doi/10.1162/tacl_a_00041/43452/Data-Statements-for-Natural-Language-Processing) 和 [Datasheets for Datasets](https://dl.acm.org/doi/10.1145/3458723)。Hugging Face Hub 提供了受这些工作启发的 Dataset Card [模板](https://github.com/huggingface/datasets/blob/main/templates/README.md)和[指南](https://github.com/huggingface/datasets/blob/main/templates/README_guide.md#dataset-card-creation-guide)；[使用数据的考量](https://github.com/huggingface/datasets/blob/main/templates/README_guide.md#considerations-for-using-the-data)一节，通常是你浏览数据集时该找偏见相关信息的位置，或当你发布新数据集时该写一段分享见解的地方。如果你在找写什么内容的灵感，可以看看 [BigLAM 组织](https://huggingface.co/biglam)在 Hub 上为历史数据集写的这几节：[法律审判记录](https://huggingface.co/datasets/biglam/old_bailey_proceedings#social-impact-of-dataset)、[图像分类](https://huggingface.co/datasets/biglam/brill_iconclass#social-impact-of-dataset)和[报纸](https://huggingface.co/datasets/biglam/bnl_newspapers1841-1879#social-impact-of-dataset)。

![HF Dataset Card guide for the Social Impact and Bias Sections](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ethics_soc_2/img3.png) *关于社会影响与偏见章节的 [HF Dataset Card 指南](https://github.com/huggingface/datasets/blob/main/templates/README_guide.md#social-impact-of-dataset)*

描述数据集的来源与语境始终是理解其中偏见的良好起点，而对编码这些bias的现象做[量化度量](https://arxiv.org/abs/2212.05129)同样有帮助。如果你在两个数据集之间做选择，或在两个基于不同数据集训练的模型之间做选择，知道哪个更能代表你 ML 系统用户群体的人口构成，就能做出更明智的决定以降低偏见风险。如果你是通过从源头过滤数据点或选择新数据源来迭代策划数据集，度量这些选择如何影响整体数据集的多样性与偏见，会让它总体上更安全可用。

我们最近发布了两个可以从偏见视角度量数据的工具。[disaggregators🤗 库](https://github.com/huggingface/disaggregators)提供量化数据集构成的实用功能，既可使用元数据，也可借助模型推断数据点属性。这对最小化偏见相关的**[代表性伤害](https://aclanthology.org/P16-2096/)**或训练模型的**表现差异**风险尤其有用。看看[演示](https://huggingface.co/spaces/society-ethics/disaggregators)，了解它在 LAION、MedMCQA 和 The Stack 数据集上的应用！

![Disaggregators tool by Nima](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ethics_soc_2/img4.png) *[Disaggregator 工具](https://huggingface.co/spaces/society-ethics/disaggregators)，作者 [Nima](https://huggingface.co/NimaBoscarino)*

拿到关于数据集构成的有用统计后，你还会想查看数据条目特征之间的联想关系，尤其可能编码贬损或其他负面刻板印象的联想。我们去年[最初介绍](https://huggingface.co/blog/data-measurements-tool#comparison-statistics)的 Data Measurements Tool 就能做到这一点：它会查看文本数据集中词项之间的[归一化点互信息（nPMI）](https://dl.acm.org/doi/10.1145/3461702.3462557)；特别是性别代词之间可能指示性别刻板印象的联想。[自己跑起来](https://github.com/huggingface/data-measurements-tool)，或在[这里](https://huggingface.co/spaces/huggingface/data-measurements-tool)体验几个预计算好的数据集！

![Data Measurements tool by Meg, Sasha, Bibi, and the Gradio team](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ethics_soc_2/img5.png) *[Data Measurements 工具](https://huggingface.co/spaces/huggingface/data-measurements-tool)，作者 [Meg](https://huggingface.co/meg)、[Sasha](https://huggingface.co/sasha)、[Bibi](https://huggingface.co/Bibss) 与 [Gradio 团队](https://gradio.app/)*

#### 数据集选择/策划：建议

这些工具本身不是完整方案，而是为批判性审视和改进数据集提供多镜头支撑，偏见与偏见相关风险是其中一镜头。总体上，我们建议在使用这些及其他工具缓解数据集策划/选择阶段的偏见风险时，记住以下步骤：

- 识别：数据集创作中可能加剧特定偏见的方面；与该数据集任务和领域特别相关的人群类别与社会变量
- 度量：数据集中的人口分布；已识别出的负面刻板印象的呈现程度
- 记录：把你的"识别"与"度量"结果写进 Dataset Card 分享出去，让它惠及更多用户、开发者以及其他受影响的人
- 调整：选择最不容易造成偏见伤害的数据集；以迭代方式降低偏见风险地改进数据集

### 我正在为我的 ML 系统训练/选择模型，如何应对偏见？

与数据集策划/选择阶段类似，对模型中偏见相关现象的记录和度量，既帮助直接使用或微调现成模型的 ML 开发者，也帮助训练自己模型的开发者。对后者而言，模型偏见相关指标的测量能帮他们借鉴别的模型的成功与失败，并成为指导自身开发选择的信号。

Model Card 最初由 [(Mitchell et al., 2019)](https://dl.acm.org/doi/10.1145/3287560.3287596) 提出，为模型报告提供了框架，突出与偏见风险相关的信息，包括广泛的伦理考量、分群评估和使用场景建议。Hugging Face Hub 在模型文档方面提供了更多工具：Hub 文档里有 [model card guidebook](https://huggingface.co/docs/hub/model-cards)，还有一个[可以为新模型轻松创建详尽 model card 的应用](https://huggingface.co/spaces/huggingface/Model_Cards_Writing_Tool)。

![Model Card writing tool by Ezi, Marissa, and Meg](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ethics_soc_2/img6.png) *[Model Card 写作工具](https://huggingface.co/spaces/huggingface/Model_Cards_Writing_Tool)，作者 [Ezi](https://huggingface.co/Ezi)、[Marissa](https://huggingface.co/Marissa) 和 [Meg](https://huggingface.co/meg)*

文档是分享模型行为通用见解的好第一步，但它通常是静态的，对所有人呈现相同信息。在很多情况下，尤其对能生成近似训练数据分布输出的生成模型，我们可以通过可视化和对比模型输出，获得对偏见相关现象与**负面刻板印象**更语境化的理解。访问模型的生成内容，能帮助用户带来与其生活经历对应的[模型行为中的交叉性问题](https://www.technologyreview.com/2022-12-12/1064751/the-viral-ai-avatar-app-lensa-undressed-me-without-my-consent/)，并评估模型在多大程度上复现了[不同形容词对应的性别刻板印象](https://www.vice.com/en/article/bvm35w/this-tool-lets-anyone-see-the-bias-in-ai-image-generators)。为促成这个过程，我们构建了一个工具，让你不仅跨一组形容词和职业比较生成结果，还能跨不同模型比较！[去玩一玩](https://huggingface.co/spaces/society-ethics/DiffusionBiasExplorer)，感受一下哪个模型在你的用例中偏见风险最低。

![Visualize Adjective and Occupation Biases in Image Generation by Sasha](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ethics_soc_2/img7.png) 
 *[Visualize Adjective and Occupation Biases in Image Generation](https://huggingface.co/spaces/society-ethics/DiffusionBiasExplorer)，作者 [Sasha](https://huggingface.co/sasha)*

可视化模型输出也不只适用于生成模型！对分类模型，我们还要警惕模型在不同人群上**表现差异**造成的偏见伤害。如果你知道哪些受保护类别最可能有歧视风险、并且评估集中有这些标注，那就可以在[你的 model card](https://dl.acm.org/doi/10.1145/3287560.3287596) 里报告按类别分群的绩效，如前文所述，让用户做明智决定。但如果你担心还没识别出全部有偏见伤害风险的人群，或者没有带标注的测试样本去度量你怀疑的偏见——这时，可视化"模型在何处、以何种方式出错"的交互工具就派上用场了！为此，[SEAL 应用](https://huggingface.co/spaces/nazneen/seal)可以把模型的相似错误分组，展示每个簇中的共性特征。想更进一步的话，你甚至可以把它和数据一节介绍的 [disaggregators 库](https://github.com/huggingface/disaggregators)结合，找出指示偏见相关失败模式的簇！

![Systematic Error Analysis and Labeling (SEAL) by Nazneen](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ethics_soc_2/img8.png) *[Systematic Error Analysis and Labeling (SEAL)](https://huggingface.co/spaces/nazneen/seal)，作者 [Nazneen](https://huggingface.co/nazneen)*

最后，还存在一些可度量模型偏见相关现象的基准。对语言模型，[BOLD](https://github.com/amazon-science/bold)、[HONEST](https://aclanthology.org/2021.naacl-main.191.pdf) 或 [WinoBias](https://aclanthology.org/N18-2003/) 等基准提供了针对特定行为的量化评估，可指示模型中的偏见。虽然这些基准有其[局限](https://aclanthology.org/2021.acl-long.81/)，它们确实提供了对某些已识别偏见风险的有限视角，可用于描述模型如何运作、或在模型间做选择。你可以在[这个探索 Space](https://huggingface.co/spaces/sasha/BiasDetection)找到一批常见语言模型上预计算好的评估结果，先感受一下它们之间的比较！

![Language Model Bias Detection by Sasha](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ethics_soc_2/img9.png) *[Language Model Bias Detection](https://huggingface.co/spaces/sasha/BiasDetection)，作者 [Sasha](https://huggingface.co/sasha)*

即便能访问针对目标模型的基准，你也可能发现，跑你正在考虑的大语言模型的评估代价高不可攀，或凭你自己的算力技术上做不到。我们今年发布的 [Evaluation on the Hub](https://huggingface.co/spaces/autoevaluate/model-evaluator) 工具可以帮上忙：它不仅替你跑评估，还会把结果接入模型文档，一次记录、长期可查——这样每个人都能看到，例如规模对 OPT 这类模型的偏见风险有[可测量的增加](https://huggingface.co/blog/zero-shot-eval-on-the-hub)！

![Large model WinoBias scores computed with Evaluation on the Hub by Helen, Tristan, Abhishek, Lewis, and Douwe](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/ethics_soc_2/img_winobias.png) *[用 Evaluation on the Hub 计算的大模型 WinoBias 分数](https://huggingface.co/blog/zero-shot-eval-on-the-hub)，作者 [Helen](https://huggingface.co/mathemakitten)、[Tristan](https://huggingface.co/Tristan)、[Abhishek](https://huggingface.co/abhishek)、[Lewis](https://huggingface.co/lewtun) 和 [Douwe](https://huggingface.co/douwekiela)*

#### 模型选择/开发：建议

对模型，正如对数据集，不同的记录与评估工具会给出模型偏见风险的不同切面，各自都能在帮助开发者选择、开发或理解 ML 系统方面发挥作用。

- 可视化 生成模型：可视化模型输出如何反映刻板印象；分类模型：可视化模型错误，找出可能导致表现差异的失败模式
- 评估 尽可能在相关基准上评估模型
- 记录 分享你从可视化和定性评估中的所学；报告模型的分群绩效以及适用的公平性基准结果

## 结语与 🤗 偏见分析与文档工具总览

随着我们在越来越多的应用中借助 ML 系统，能否公平地收获其益处，取决于我们能否积极缓解与之相关的偏见伤害风险。尽管"在任何场景下该怎么做最好"没有唯一答案，我们仍能通过分享经验、工具与方法论来彼此支撑。这篇博文概述了 Hugging Face 团队成员应对偏见问题的若干方式及配套工具，希望它们对你有用，也鼓励你开发并分享你自己的工具！

链接工具小结：

- 任务：浏览我们的 [ML 任务目录](https://huggingface.co/tasks)，了解有哪些技术框架和资源可选；用工具探索具体任务的[完整开发生命周期](https://huggingface.co/spaces/hf-task-exploration/ExploreACMnaacl)
- 数据集：使用并贡献 [Dataset Cards](https://github.com/huggingface/datasets/blob/main/templates/README_guide.md#social-impact-of-dataset)，分享数据集偏见的相关见解；用 [Disaggregator](https://github.com/huggingface/disaggregators) 排查[可能的表现差异](https://huggingface.co/spaces/society-ethics/disaggregators)；查看[数据集的聚合度量](https://huggingface.co/spaces/huggingface/data-measurements-tool)（含 nPMI），揪出可能的刻板联想
- 模型：使用并贡献 [Model Cards](https://huggingface.co/docs/hub/model-cards)，分享模型偏见的相关见解；用 [Interactive Model Cards](https://huggingface.co/spaces/nazneen/interactive-model-cards) 可视化绩效差异；查看[系统性模型错误](https://huggingface.co/spaces/nazneen/seal)，留意已知社会偏见；用 [Evaluate](https://github.com/huggingface/evaluate) 和 [Evaluation on the Hub](https://huggingface.co/spaces/autoevaluate/model-evaluator) 探索[语言模型偏见](https://huggingface.co/blog/evaluating-llm-bias)，包括在[大模型](https://huggingface.co/blog/zero-shot-eval-on-the-hub)中的偏见；用[文生图偏见浏览器](https://huggingface.co/spaces/sasha/StableDiffusionBiasExplorer)比较图像生成模型的偏见；用 Bias [Score Card](https://huggingface.co/spaces/sasha/BiasDetection) 比较语言模型偏见
