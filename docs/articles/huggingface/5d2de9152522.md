只需一条命令，你就能在 Hugging Face 基础设施上拉起一个私有、OpenAI 兼容的 LLM 端点——不用置备服务器、不用 Kubernetes，按秒计费。起来之后，你可以从笔记本、notebook 或任何地方调用它。

这是为测试、评估或批量生成快速搭起模型的最快方式。（如果你想要的是托管的、生产就绪的服务，那是 [Inference Endpoints](https://huggingface.co/docs/inference-endpoints) 的定位——文末[详述如何选择](https://huggingface.co/blog/vllm-jobs#hf-jobs-or-inference-endpoints)。）

下面是一个完整的端到端流程。

## 前置条件

- 一种支付方式或正的预充值余额（Jobs 按硬件使用量每分钟计费）。
- `huggingface_hub >= 1.20.0`：`pip install -U "huggingface_hub>=1.20.0"`。
- 本地已登录：`hf auth login`。

## 启动服务器

`hf jobs run` 就是 HF 基础设施版的 `docker run`。我们使用官方 `vllm/vllm-openai` 镜像，用 `--flavor` 申请 GPU，用 `--expose` 暴露 vLLM 的端口：

```
hf jobs run --flavor a10g-large --expose 8000 --timeout 2h \
  vllm/vllm-openai:latest \
  vllm serve Qwen/Qwen3-4B --host 0.0.0.0 --port 8000
```

`--expose 8000` 会把容器端口经 HF 的公共 jobs 代理路由出去（完整参考见 [Serve Models 指南](https://huggingface.co/docs/hub/jobs-serving)）。命令会打印你的服务器可访问的 URL：

```
✓ Job started
  id: 6a381ca1953ed90bfb947332
  url: https://huggingface.co/jobs/qgallouedec/6a381ca1953ed90bfb947332
Hint: Exposed ports are reachable at (requires an HF token with read access to the job):
  https://6a381ca1953ed90bfb947332--8000.hf.jobs
```

`6a381ca1953ed90bfb947332` 是你的任务 ID，记好，后面要用。下文用 `<job_id>` 作为它的占位符。

给它几分钟下载权重并启动。当日志出现 `Application startup complete`，你就上线了。

## 从任何地方调用它

vLLM 讲 OpenAI API，每个请求只需把你的 HF token 作为 bearer token。最快的调用方式是 curl：

```
curl https://<job_id>--8000.hf.jobs/v1/chat/completions \
  -H "Authorization: Bearer $(hf auth token)" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen3-4B",
    "messages": [{"role": "user", "content": "Hello!"}],
    "chat_template_kwargs": {"enable_thinking": false}
  }'
```

返回的是常见的 OpenAI 风格 JSON，`choices[0].message.content` 里是 `"Hello! How can I assist you today? 😊"`。

或者在 Python 里，把 OpenAI 客户端指向暴露的 URL，把 token 作为 API key 传入：

```
from huggingface_hub import get_token
from openai import OpenAI

client = OpenAI(
    base_url="https://<job_id>--8000.hf.jobs/v1",
    api_key=get_token(),
)
resp = client.chat.completions.create(
    model="Qwen/Qwen3-4B",
    messages=[{"role": "user", "content": "Hello!"}],
    extra_body={"chat_template_kwargs": {"enable_thinking": False}},
)
print(resp.choices[0].message.content)
```

```
Hello! How can I assist you today? 😊
```

开工前的快速健康检查：`curl https://<job_id>--8000.hf.jobs/v1/models -H "Authorization: Bearer $(hf auth token)"` 应列出模型。

> 🔐 端点是受门禁的，不公开。每个请求必须携带对该任务命名空间有读取权限的 HF token。浏览器直接访问会被拒绝。实际上 jobs 代理就是你的 API 网关：访问范围限定在你（和你的组织）。私有使用完全没问题，但要据此对待 URL：别指望它是开放的而随意分享，也别把 token 粘到不可信的地方。如果你需要更细粒度的或公开的访问，请在前面加一个正式的网关。或者参见下文「HF Jobs 还是 Inference Endpoints？」。

## 清理

Jobs 按秒计费，用完记得关掉服务器：

```
hf jobs cancel <job_id>
```

你设置的 `--timeout` 是安全网（会自动停止），但显式取消更省钱。`a10g-large` 的价格是 $1.50/小时——用 `hf jobs hardware` 查看完整价目表，选能装下你模型的最小规格。

## 更进一步：更大的模型

同一条命令可以扩展到大得多的模型——选个更强的 `--flavor`，用 `--tensor-parallel-size` 让 vLLM 把模型分片到多张 GPU。例如在 2× H200 上跑 122B 的 Qwen3.5 混合专家模型：

```
hf jobs run --flavor h200x2 --expose 8000 --timeout 2h \
  vllm/vllm-openai:latest \
  vllm serve Qwen/Qwen3.5-122B-A10B \
  --host 0.0.0.0 --port 8000 --tensor-parallel-size 2 \
  --max-model-len 32768 --max-num-seqs 256
```

`--tensor-parallel-size` 应与规格中的 GPU 数一致（`h200x2` → 2，`h200x8` → 8）。运行 `hf jobs hardware` 查看可用选项；给更大的模型更长的 `--timeout`，因为它们下载和加载更久。对大模型而言，H200 规格通常性价比最高。

`--max-model-len 32768 --max-num-seqs 256` 这两个旗标是该模型特有的：Qwen3.5-122B 是 Mamba/attention 混合架构，默认 256K token 上下文，留下的内存不够 vLLM 的默认批设置。限制上下文长度与并发序列数能把它压回 GPU 显存之内。如果某个模型启动失败并报 out-of-memory 或 cache-block 错误，首先就该调低这两个值。其余一切（暴露的 URL、OpenAI 客户端、token 认证）都完全不变。

## 更进一步：用 UI 和它聊天

比起 curl 更喜欢聊天窗口？几行 [Gradio](https://www.gradio.app/) 指向同一个端点即可。在 `vllm serve` 命令里加上 `--reasoning-parser deepseek_r1`，让 Qwen3 的思考过程作为独立字段返回（不是必需，但有帮助），然后本地运行这段代码（只需要任务 ID）：

```
import gradio as gr
from gradio import ChatMessage
from huggingface_hub import get_token
from openai import OpenAI

client = OpenAI(base_url="https://<job_id>--8000.hf.jobs/v1", api_key=get_token())

def chat(message, history):
    messages = [{"role": m["role"], "content": m["content"]} for m in history if not m.get("metadata")]
    messages.append({"role": "user", "content": message})
    stream = client.chat.completions.create(model="Qwen/Qwen3-4B", messages=messages, stream=True)

    thinking, answer = "", ""
    for chunk in stream:
        delta = chunk.choices[0].delta
        thinking += delta.model_extra.get("reasoning", "")
        answer += delta.content or ""
        out = []
        if thinking.strip():
            status = "done" if answer.strip() else "pending"
            out.append(ChatMessage(role="assistant", content=thinking, metadata={"title": "💭 Thinking", "status": status}))
        if answer.strip():
            out.append(ChatMessage(role="assistant", content=answer))
        yield out

gr.ChatInterface(chat).launch()
```

运行后打开 `http://127.0.0.1:7860` 开聊——推理内容流式进入可折叠面板，回答在下方。

## 更进一步：SSH 进入运行中的服务器

需要调试启动失败、观察 GPU 显存、或以交互方式 tail 日志？你可以直接开 shell 进入运行中的任务。用 `--ssh` 启动，并确保你的公钥已登记在 [huggingface.co/settings/keys](https://huggingface.co/settings/keys)：

```
hf jobs run --flavor a10g-large --expose 8000 --timeout 2h --ssh \
  vllm/vllm-openai:latest \
  vllm serve Qwen/Qwen3-4B --host 0.0.0.0 --port 8000
```

然后用任务 ID 连接：

```
hf jobs ssh <job_id>
```

现在你就在容器里了，可以运行 `nvidia-smi`、检查进程、或直接摆弄模型——比从外面读日志做调试和监控容易得多。SSH 支持需要 `huggingface_hub >= 1.20.0`。

## 更进一步：作为 Pi 的 coding agent 后端

同一个端点也能给终端 coding agent 做后端。[Pi](https://pi.dev) 是一个不绑定提供商的 agent harness。把它指向你的任务，就得到一个在你的自托管模型上运行的 Read/Write/Edit/Bash agent。

需要先配置一件事：agent 通过 tool call 驱动模型，而 vLLM 只有在启动时启用 tool calling 才接受它们。所以要用 `--enable-auto-tool-choice` 和与模型家族匹配的 `--tool-call-parser`（Qwen3 用 `hermes`）重新启动。agent 也受益于更强的模型，所以这里正好换上那个大的：

```
hf jobs run --flavor h200x2 --expose 8000 --timeout 2h \
  vllm/vllm-openai:latest \
  vllm serve Qwen/Qwen3.5-122B-A10B \
  --host 0.0.0.0 --port 8000 --tensor-parallel-size 2 \
  --max-model-len 32768 --max-num-seqs 256 \
  --reasoning-parser deepseek_r1 \
  --enable-auto-tool-choice --tool-call-parser hermes
```

然后在 `~/.pi/agent/models.json` 里把该任务添加为自定义 provider：

```
{
  "providers": {
    "hf-jobs": {
      "baseUrl": "https://<job_id>--8000.hf.jobs/v1",
      "api": "openai-completions",
      "apiKey": "!hf auth token",
      "models": [
        { "id": "Qwen/Qwen3.5-122B-A10B" }
      ]
    }
  }
}
```

接着启动 agent：

```
pi
```

刚才只用几条命令拉起的那个模型，现在正驱动着你终端里的交互式 coding agent。

## HF Jobs 还是 Inference Endpoints？

HF Jobs 不是在 Hugging Face 上服务模型的唯一方式。[Inference Endpoints](https://huggingface.co/docs/inference-endpoints) 是同一件事的托管产品，选哪个取决于你要什么。

当你想要最大的灵活性与控制力时，选 **HF Jobs**：它就是 HF 基础设施上的 `docker run`，镜像、具体的 `vllm serve` 参数、硬件都由你定，任务运行期间按秒付费。这让它非常适合实验、一次性评估、批量生成，或在正式投入前先摸摸一个模型的底。

当你想要更生产就绪的东西时，选 **Inference Endpoints**。它补上了长期服务需要的运维要件：更细粒度的访问控制（endpoint 可以是公开、受保护或私有），以及 scale-to-zero，闲置期不计费。如果你要立一个持久的 endpoint 而不是跑一个任务，就该拿这个工具。
