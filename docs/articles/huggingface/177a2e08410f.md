# 🤗 社区开源文本到图像生成偏好数据集

Data is Better Together 社区又发布了一份对开源开发很重要的数据集。由于缺乏面向文本到图像生成的开放偏好数据集，我们着手发布了一个 Apache 2.0 许可证的文生图数据集。这份数据集聚焦常见图像生成类别上的文生图偏好数据对（preference pairs），同时混合了不同的模型家族和不同的提示词复杂度。

太长不看版？所有结果都在 [Hugging Face Hub 的这个 collection](https://huggingface.co/collections/data-is-better-together/open-image-preferences-675135cc9c31de7f912ce278) 里，预处理和后处理代码在 [这个 GitHub 仓库](https://github.com/huggingface/data-is-better-together)。最重要的是，有一个[开箱即用的偏好数据集](https://huggingface.co/datasets/data-is-better-together/open-image-preferences-v1-binarized)和一个 [flux-dev-lora-finetune](https://huggingface.co/data-is-better-together/open-image-preferences-v1-flux-dev-lora)。如果你想现在就表达支持，别忘了在阅读之前先点赞、订阅并关注我们。

还不了解 Data is Better Together 社区？

[Data is Better Together](https://huggingface.co/data-is-better-together) 是 🤗 Hugging Face 与开源 AI 社区的协作组织。我们希望通过协作的方式构建有影响力的数据集，赋能开源社区。关注该组织即可随时了解最新的数据集、模型和社区冲刺活动（community sprint）。

类似工作

此前已有多个创建开放图像偏好数据集的努力，但我们这份工作的独特之处在于提示词复杂度和类别的多样性，以及数据集和代码的开放程度。以下是一些相关工作：

```
- [yuvalkirstain/pickapic_v2](https://huggingface.co/datasets/yuvalkirstain/pickapic_v2)

- [artificialanalysis image arena](https://artificialanalysis.ai/text-to-image/arena)
```

## 输入数据集

为了给这次冲刺准备合适的输入数据集，我们从一些基础提示词出发，对其进行清洗、毒性过滤，并用 [distilabel](https://github.com/argilla-io/distilabel) 做合成数据生成，注入类别和复杂度。最后，我们用 Flux 和 Stable Diffusion 模型生成图像。最终产出 [open-image-preferences-v1](https://huggingface.co/datasets/data-is-better-together/open-image-preferences-v1)。

### 输入提示词

[Imgsys](https://imgsys.org/) 是由 [fal.ai](http://fal.ai) 托管的一个生成式图像模型竞技场（arena），人们在其中提交提示词，并在两个模型的生成结果之间做出偏好选择。遗憾的是，生成的图像并未公开发布，但[相关提示词托管在 Hugging Face 上](https://huggingface.co/datasets/fal/imgsys-results)。这些提示词代表了图像生成的真实使用场景，包含大量日常生成的优秀示例；但真实使用也意味着其中有重复和有毒提示词，因此我们不得不仔细检查数据并做过滤。

### 降低毒性

我们的目标是在社区活动开始前从数据集中移除所有 NSFW 提示词和图像。最终我们采用多模型方案：用两个基于文本和两个基于图像的分类器作为过滤器。过滤之后，我们又对每张图像逐一人工检查，确保没有遗留有毒内容——幸运的是，我们的方法奏效了。

我们使用的流程如下：

- 将图像分类为是否 NSFW
- 移除所有阳性样本
- Argilla 团队人工审阅数据集
- 根据审阅结果重复上述步骤

### 合成提示词增强

数据多样性对数据质量很重要，因此我们决定基于不同类别和复杂度对提示词做合成改写来增强数据集。这通过一个 [distilabel 流水线](https://github.com/huggingface/data-is-better-together/blob/main/community-efforts/image_preferences/01_synthetic_data_generation_total.py)完成。

| 类型 | 提示词 | 图像 |
| --- | --- | --- |
| Default | a harp without any strings | ![Default Harp Image](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/image-preferences/basic.jpeg) |
| Stylized | a harp without strings, in an anime style, with intricate details and flowing lines, set against a dreamy, pastel background | ![Stylized Harp Image](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/image-preferences/stylized.jpeg) |
| Quality | a harp without strings, in an anime style, with intricate details and flowing lines, set against a dreamy, pastel background, bathed in soft golden hour light, with a serene mood and rich textures, high resolution, photorealistic | ![Quality Harp Image](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/image-preferences/quality.jpeg) |

#### 提示词类别

[InstructGPT](https://arxiv.org/pdf/2203.02155) 为文本到文本生成描述了基础任务类别，但文生图领域还没有对应的明确分类。为弥补这一点，我们用两个主要来源作为类别输入：[google/sdxl](https://huggingface.co/spaces/google/sdxl/blob/main/app.py) 和 [Microsoft](https://www.microsoft.com/en-us/bing/do-more-with-ai/ai-art-prompting-guide/ai-genres-and-styles?form=MA13KP)。由此得到如下主类别：["Cinematic", "Photographic", "Anime", "Manga", "Digital art", "Pixel art", "Fantasy art", "Neonpunk", "3D Model", "Painting", "Animation" "Illustration"]。此外我们还选择了一些互斥的子类别，以便进一步丰富提示词的多样性。这些类别和子类别采用随机采样，因此在大致均匀地分布在整个数据集中。

#### 提示词复杂度

[Deita 论文](https://arxiv.org/pdf/2312.15685)证明，提升提示词的复杂度和多样性可以带来更好的模型生成和微调效果，但人们并不总是花时间写详尽的提示词。因此我们决定把同一个提示词分别用复杂和简化两种形式作为两个数据点，用于不同的偏好生成。

### 图像生成

[ArtificialAnalysis/Text-to-Image-Leaderboard](https://huggingface.co/spaces/ArtificialAnalysis/Text-to-Image-Leaderboard) 概览了表现最好的图像模型。我们基于许可证及其在 Hub 上的可用性选择了两个表现最佳的模型。同时，我们还确保所选模型来自不同的模型家族，避免在不同类别间偏袒某一类生成。因此我们选择了 [stabilityai/stable-diffusion-3.5-large](https://huggingface.co/stabilityai/stable-diffusion-3.5-large) 和 [black-forest-labs/FLUX.1-dev](https://huggingface.co/black-forest-labs/FLUX.1-dev)。在同一风格类别下，每个模型分别针对简化和复杂两个版本的提示词各生成一张图像。

## 结果

所有标注数据的原始导出包含多项选择题的回答：每位标注者选择两个模型中哪个更好、两个都好，或两个都差。基于此，我们考察了标注者一致性、模型在各分类下的表现，甚至还做了一次模型微调——你现在就可以在 [Hub 上试玩](https://huggingface.co/black-forest-labs/FLUX.1-dev)！下面是标注后的数据集情况：

### 标注者一致性

标注者一致性（annotator agreement）是检验任务有效性的一种方式。任务太难时，标注者可能意见不一致；任务太简单时，又可能过度一致。想把握好这个平衡并不容易，但这次冲刺我们做到了恰到好处。我们[用 Hugging Face datasets SQL 控制台做了这项分析](https://huggingface.co/datasets/data-is-better-together/open-image-preferences-v1-results/embed/sql-console/0KQAlsp)。整体而言，在我们的测试设置中 SD3.5-XL 更倾向于获胜。

### 模型表现

基于标注者一致性分析，两个模型都证明各有胜场，于是[我们做了额外分析](https://huggingface.co/datasets/data-is-better-together/open-image-preferences-v1-results/embed/sql-console/FeTQ7Ib)，看不同类别之间是否存在差异。简言之：FLUX-dev 在动漫类上更好，SD3.5-XL 在艺术和电影感场景上更好。

- 平局：Photographic、Animation
- FLUX-dev 更好：3D Model、Anime、Manga
- SD3.5-XL 更好：Cinematic、Digital art、Fantasy art、Illustration、Neonpunk、Painting、Pixel art

### 模型微调

为了验证数据集质量、同时不投入过多时间和资源，我们决定基于 [diffusers 的 GitHub 示例](https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/train_dreambooth_lora_flux.py)对 [black-forest-labs/FLUX.1-dev](https://huggingface.co/black-forest-labs/FLUX.1-dev) 模型做一次 LoRA 微调。在此过程中，我们把被选中的样本作为 FLUX-dev 模型的期望输出纳入训练，舍弃未被选中的样本。有趣的是，被选中的微调后模型在原本欠缺的艺术和电影感场景下表现明显更好！你可以[在这里测试微调后的 adapter](https://huggingface.co/data-is-better-together/open-image-preferences-v1-flux-dev-lora)。

## 社区

简而言之，我们在标注者重叠度为 2/3 的情况下标注了 1 万组偏好数据对，250 多位社区成员在不到 2 周内产生了超过 3 万条回答！图像排行榜显示，有些社区成员给出的偏好甚至超过 5000 条。我们要感谢每一位参与本次冲刺的人，并特别鸣谢前三名用户——他们将各获得一个月的 Hugging Face Pro 会员。记得在 Hub 上关注他们：[aashish1904](https://huggingface.co/aashish1904)、[prithivMLmods](https://huggingface.co/prithivMLmods)、[Malalatiana](https://huggingface.co/Malalatiana)。

## 接下来做什么？

又一次成功的社区冲刺之后，我们会继续在 Hugging Face Hub 上组织这类活动。关注 [Data Is Better Together 组织](https://huggingface.co/data-is-better-together)以保持更新。我们也鼓励社区成员自己采取行动，我们很乐意提供指导，并在社交媒体和 Hub 的组织内帮你转发。你可以通过多种方式参与贡献：

- 加入并参与其他冲刺活动。
- 提出你自己的冲刺计划或对高质量数据集的需求。
- 基于[偏好数据集](https://huggingface.co/datasets/data-is-better-together/open-image-preferences-v1-binarized)微调模型。一个思路是对 SDXL 或 FLUX-schnell 做完整的 SFT 微调；另一个思路是做 DPO/ORPO 微调。
- 评估 [LoRA adapter](https://huggingface.co/data-is-better-together/open-image-preferences-v1-flux-dev-lora) 相对原始 SD3.5-XL 和 FLUX-dev 模型的性能提升。
