## 引言

🤗 Datasets 是一个用于下载和准备各领域数据集的开源库。其极简的 API 让用户一行 Python 代码即可下载并准备好数据集，并配有一整套函数实现高效的预处理。可用数据集的数量无与伦比，所有最热门的机器学习数据集都可以下载。

不仅如此，🤗 Datasets 还内置了多个音频专用特性，让研究人员和从业者处理音频数据集变得轻松。本博客将演示这些特性，展示为什么 🤗 Datasets 是下载和准备音频数据集的首选之地。

## The Hub

Hugging Face Hub 是一个托管模型、数据集与演示的平台，全部开源且公开可用。这里汇聚了一个不断增长的音频数据集集合，覆盖多种领域、任务和语言。通过与 🤗 Datasets 的紧密集成，Hub 上的所有数据集都可以一行代码下载。

我们来到 Hub，按任务筛选数据集：

- [Hub 上的语音识别数据集](https://huggingface.co/datasets?task_categories=task_categories:automatic-speech-recognition&sort=downloads)
- [Hub 上的音频分类数据集](https://huggingface.co/datasets?task_categories=task_categories:audio-classification&sort=downloads)

写作本文时，Hub 上有 77 个语音识别数据集和 28 个音频分类数据集，而且数量只增不减。你可以任选其中一个来满足自己的需要。我们点开语音识别搜索结果的第一条：点击 [`common_voice`](https://huggingface.co/datasets/common_voice) 会打开数据集卡片：

在这里，我们可以找到关于该数据集的补充信息、查看有哪些模型在该数据集上训练，而最令人兴奋的是可以直接试听真实的音频样本。Dataset Preview（数据集预览）展示在数据集卡片中间，显示每个子集和每个划分的前 100 个样本。更重要的是，音频样本已经加载好，可以实时试听。点击第一个样本的播放按钮，我们就能边听音频边看对应的文本。

Dataset Preview 是在决定是否使用某个音频数据集之前体验它的绝佳方式。你可以在 Hub 上任选一个数据集，滚动浏览样本、试听不同子集与划分的音频，判断它是否符合你的需求。一旦选定了数据集，加载数据也是轻而易举的事。

## 加载音频数据集

🤗 Datasets 的一个关键定义性特性，是一行 Python 代码即可下载并准备好数据集。这通过 [`load_dataset`](https://huggingface.co/docs/datasets/loading#load) 函数实现。传统上，加载数据集需要：i) 下载原始数据，ii) 从压缩格式中解包，iii) 准备单个样本和各个划分。使用 `load_dataset`，所有脏活累活都在幕后完成。

以加载 Speech Colab 的 [GigaSpeech](https://huggingface.co/datasets/speechcolab/gigaspeech) 数据集为例。GigaSpeech 是相对较新的语音识别数据集，用于对学术语音系统进行基准评测，也是 Hugging Face Hub 上众多音频数据集之一。

要加载 GigaSpeech，只需拿到它在 Hub 上的标识符（`speechcolab/gigaspeech`）并传给 [`load_dataset`](https://huggingface.co/docs/datasets/loading#load) 函数。GigaSpeech 有五种规模递增的配置，从 `xs`（10 小时）到 `xl`（10,000 小时）。本教程中我们加载最小的配置。数据集标识符和期望的配置就是下载该数据集所需的全部信息：

```
from datasets import load_dataset

gigaspeech = load_dataset("speechcolab/gigaspeech", "xs")

print(gigaspeech)
```

**打印输出：**

就这样，GigaSpeech 数据集已经就绪！没有比这更简单的音频数据集加载方式了。可以看到，训练、验证和测试划分已经预先分好，并各自带有对应的信息。

`load_dataset` 函数返回的 `gigaspeech` 对象是一个 [`DatasetDict`](https://huggingface.co/docs/datasets/package_reference/main_classes#datasets.DatasetDict)。我们可以像对待普通 Python 字典一样使用它。要取得 train 划分，只需把对应的键传给 `gigaspeech` 字典：

用 🤗 Datasets 加载数据集只是乐趣的一半。我们现在可以使用配套的工具集，为模型训练或推理高效地预处理数据。本节将进行三个阶段的数据预处理：

### 1. 重采样音频数据

`load_dataset` 函数会按照音频样本发布时的采样率来准备它们。这未必是我们模型期望的采样率。此时需要将音频*重采样*到正确的采样率。

我们可以用 🤗 Datasets 的 [`cast_column`](https://huggingface.co/docs/datasets/package_reference/main_classes.html?highlight=cast_column#datasets.DatasetDict.cast_column) 方法把音频输入设置为期望的采样率。该操作不会就地修改音频，而是向 `datasets` 发出信号：在加载音频样本时*在线（on the fly）*重采样。下面的代码单元会把采样率设为 8kHz：

```
from datasets import Audio

gigaspeech = gigaspeech.cast_column("audio", Audio(sampling_rate=8000))
```

重新加载 GigaSpeech 数据集中的第一个音频样本，它就会重采样到目标采样率：

```
print(gigaspeech["train"][0])
```

**打印输出：**

```

 'audio': {'path': '/home/sanchit_huggingface_co/.cache/huggingface/datasets/downloads/extracted/7f8541f130925e9b2af7d37256f2f61f9d6ff21bf4a94f7c1a3803ec648d7d79/xs_chunks_0000/YOU0000000315_S0000660.wav',

        0.00083484,  0.00080221], dtype=float32),

可以看到采样率已降采样到 8kHz。数组值也不同了，因为现在每两个原来的振幅值大约只剩一个。我们把数据集采样率设回 16kHz——多数语音识别模型期望的采样率：

```

print(gigaspeech["train"][0])

### 2. 预处理函数

处理音频数据集最具挑战性的方面之一，是把数据整理成模型要求的格式。使用 🤗 Datasets 的 [`map`](https://huggingface.co/docs/datasets/v2.6.1/en/process#map) 方法，我们可以写一个函数预处理数据集中的单个样本，然后不加任何代码改动地应用到每个样本。

首先，从 🤗 Transformers 加载一个 processor 对象。该 processor 会预处理音频得到输入特征，并把目标文本分词得到标签。`AutoProcessor` 类用于从给定模型 checkpoint 加载 processor。示例中我们从 OpenAI 的 [Whisper medium.en](https://huggingface.co/openai/whisper-medium.en) checkpoint 加载，你也可以换成 Hugging Face Hub 上的任意模型标识符：

```
from transformers import AutoProcessor

processor = AutoProcessor.from_pretrained("openai/whisper-medium.en")
```

很好！现在我们可以写一个函数，取单个训练样本并传入 `processor`，为模型做好准备。我们还会计算每个音频样本的输入长度，这是下一步数据准备所需的信息：

```
def prepare_dataset(batch):
    audio = batch["audio"]
    batch = processor(audio["array"], sampling_rate=audio["sampling_rate"], text=batch["text"])
    
    batch["input_length"] = len(audio["array"]) / audio["sampling_rate"]
    return batch
```

我们可以用 🤗 Datasets 的 `map` 方法把数据准备函数应用到所有训练样本。这里我们同时移除 `text` 和 `audio` 列，因为音频已预处理为输入特征、文本已分词为标签：

```
gigaspeech = gigaspeech.map(prepare_dataset, remove_columns=gigaspeech["train"].column_names)
```

### 3. 过滤函数

在训练之前，我们可能有一条过滤训练数据的启发式规则。例如，我们可能想过滤超过 30 秒的音频样本，以防止音频被截断或冒内存溢出的风险。做这件事的方式与上一步准备数据几乎相同。

我们先写一个函数，指明哪些样本保留、哪些丢弃。这个函数 `is_audio_length_in_range` 返回布尔值：短于 30 秒的样本返回 True，超出的返回 False。

```
MAX_DURATION_IN_SECONDS = 30.0

def is_audio_length_in_range(input_length):
    return input_length < MAX_DURATION_IN_SECONDS
```

我们可以用 🤗 Datasets 的 [`filter`](https://huggingface.co/docs/datasets/process#select-and-filter) 方法把这个过滤函数应用到所有训练样本，保留短于 30 秒（True）的样本、丢弃超出的（False）：

```
gigaspeech["train"] = gigaspeech["train"].filter(is_audio_length_in_range, input_columns=["input_length"])
```

至此，GigaSpeech 数据集已完全为模型准备好了！从加载数据集到最后的过滤步骤，总共只需要 13 行 Python 代码。

为了让 notebook 尽可能通用，我们只执行了最基本的数据准备步骤。但你可以对音频数据集应用的函数并没有限制。你可以扩展 `prepare_dataset` 函数来执行更复杂的操作，例如数据增强、语音活动检测或噪声抑制。有了 🤗 Datasets，凡是你都能用 Python 函数写出来的操作，就能应用到你的数据集上！

## 流式模式：银弹

音频数据集面临的最大挑战之一是其庞大的体积。GigaSpeech 的 `xs` 配置只包含 10 小时训练数据，但下载和准备却占用超过 13GB 存储空间。如果我们想训练更大的划分怎么办？完整的 `xl` 配置包含 10,000 小时训练数据，需要超过 1TB 的存储空间。对多数语音研究者来说，这远远超出一块典型机械硬盘的规格。我们需要掏钱买额外存储吗？还是说有办法在**不受磁盘空间约束**的情况下训练这些数据集？

🤗 Datasets 让我们恰好做到这一点。这得益于[*流式（streaming）*](https://huggingface.co/docs/datasets/stream)模式，图 1 给出了示意。流式模式允许我们在遍历数据集时渐进地加载数据，而不是一次性下载整个数据集——我们按样本逐个加载，在遍历数据集时按需*在线*加载和准备样本。这样，我们永远只加载正在使用的样本，而不加载用不上的！一个样本用完，就继续遍历加载下一个。

这与*下载*一部剧集和*流式观看*的类比一致。下载剧集时，我们把整个视频离线下载并存到磁盘，必须等整个视频下载完才能观看，还要占用与视频文件同样大的磁盘空间。而流式观看时，我们不把视频的任何部分下载到磁盘，而是遍历远程视频文件，按需实时加载每一部分。我们不必等整个视频缓冲完才能开始看，第一部分就绪即可开始观看！数据集加载采用的正是同一个*流式*原则。

图 1：

流式模式。数据集在遍历时被渐进加载。

流式模式相比一次性下载整个数据集有三大主要优势：

- **磁盘空间**：样本在遍历时逐个加载到内存。由于数据不下载到本地，没有任何磁盘空间要求，你可以使用任意大小的数据集。
- **下载与处理时间**：音频数据集很大，下载和处理需要大量时间。流式模式下加载与处理都是在线完成的，意味着第一个样本就绪就能开始使用数据集。
- **便于实验**：你可以在少量样本上做实验验证脚本可行，而不必下载整个数据集。

流式模式有一个注意事项。下载数据集时，原始数据和处理后的数据都会保存到本地磁盘。若要复用该数据集，可以直接从磁盘加载处理后的数据，跳过下载和处理步骤。也就是说，下载和处理操作只需执行一次，之后即可复用准备好的数据。而流式模式不把数据下载到磁盘，因此下载和处理结果都不缓存。若要复用数据集，必须重复流式步骤，再次在线加载和处理音频文件。因此，建议对你可能会多次使用的数据集采用下载模式。

如何启用流式模式？简单！加载数据集时设置 `streaming=True` 即可。其余的都会替你处理好：

```
gigaspeech = load_dataset("speechcolab/gigaspeech", "xs", streaming=True)
```

本教程前面涵盖的所有步骤都可以不加代码改动地应用到流式数据集上。唯一的变化是不再用 Python 索引访问单个样本（即 `gigaspeech["train"][sample_idx]`），而必须用 `for` 循环等方式遍历数据集。

流式模式可以把你的研究提升一个档次：不仅最大的数据集触手可及，你还可以一次性在多个数据集上评测系统而无需担心磁盘空间。与单一数据集评测相比，多数据集评测能更好地反映语音识别系统的泛化能力（*参见* [End-to-end Speech Benchmark (ESB)](https://arxiv.org/abs/2210.13352)）。配套的 [Google Colab](https://colab.research.google.com/github/sanchit-gandhi/notebooks/blob/main/audio_datasets_colab.ipynb) 提供了一个示例：用流式模式在一个脚本中于八个英语语音识别数据集上评测 Whisper 模型。

以下数据集描述大部分取自 [ESB Benchmark](https://arxiv.org/abs/2210.13352) 论文。

#### LibriSpeech ASR

LibriSpeech 是评测 ASR 系统的标准大规模数据集。它由来自 [LibriVox](https://librivox.org/) 项目、约 1,000 小时的朗读有声书构成。LibriSpeech 为研究者利用海量已有转写语音数据铺平了道路，也因此成为学术语音系统基准评测中最受欢迎的数据集之一。

```
librispeech = load_dataset("librispeech_asr", "all")
```

#### Common Voice

Common Voice 是一系列众包、开放许可的语音数据集，由说话人以多种语言朗读来自维基百科的文本。任何人都可以贡献录音，因此音频质量和说话人差异都很大。音频条件颇具挑战：存在录音伪影、口音、犹豫以及外来词。转写同时带有大小写和标点。第 11.0 版的英语子集约含 2,300 小时经验证的数据。使用该数据集需要你同意 Common Voice 的使用条款，可在 Hugging Face Hub 上查看：[mozilla-foundation/common_voice_11_0](https://huggingface.co/datasets/mozilla-foundation/common_voice_11_0)。同意条款后即可获得数据集访问权限，之后加载数据集时需提供 Hub 的[认证 token](https://huggingface.co/settings/tokens)。

```
common_voice = load_dataset("mozilla-foundation/common_voice_11", "en", use_auth_token=True)
```

#### VoxPopuli

VoxPopuli 是一个大规模多语种语音语料库，数据源自 2009-2020 年欧洲议会活动录音。因此它占据了一个独特的领域：演讲式、政治性发言，且大多来自非母语者。英语子集约含 550 小时带标注语音。

```
voxpopuli = load_dataset("facebook/voxpopuli", "en")
```

#### TED-LIUM

TED-LIUM 基于英语 TED Talk 会议视频构建。说话风格是演讲式教育讲座。转写的讲座涵盖文化、政治与学术等多种主题，词汇偏技术向。最新第 3 版（Release 3）约含 450 小时训练数据。验证与测试数据沿用 legacy set，与早期版本保持一致。

```
tedlium = load_dataset("LIUM/tedlium", "release3")
```

#### GigaSpeech

GigaSpeech 是由有声书、播客和 YouTube 精选构建的多领域英语语音识别语料库，涵盖艺术、科学、体育等多种主题下的朗读式与自发式语音。训练划分从 10 小时到 10,000 小时不等，并配有标准化的验证与测试划分。

```
gigaspeech = load_dataset("speechcolab/gigaspeech", "xs", use_auth_token=True)
```

#### SPGISpeech

SPGISpeech 是一个英语语音识别语料库，由公司财报电话会议构成，经 S&P Global, Inc. 人工转写。转写按专业风格指南完整格式化，涵盖演讲式与自发式语音。训练划分从 200 小时到 5,000 小时不等，并配有标准验证与测试划分。

```
spgispeech = load_dataset("kensho/spgispeech", "s", use_auth_token=True)
```

#### Earnings-22

Earnings-22 是一个 119 小时的英语财报电话会话语料，收集自全球公司。构建目标是聚合广泛的说话人与口音，覆盖多种真实金融话题。说话人与口音多样性很高，来自七个不同的语言区域。Earnings-22 发布时主要作为纯测试数据集。Hub 上有一个将其划分为 train-validation-test 三个划分的版本。

```
earnings22 = load_dataset("revdotcom/earnings22")
```

#### AMI

AMI 包含 100 小时使用不同录制方式采集的会议录音。语料含人工标注的正字法转写，并按词级对齐。AMI 的单个样本包含很大的音频文件（10 到 60 分钟），会被切分为适合训练多数语音识别系统的长度。AMI 有两个划分：IHM 与 SDM。IHM（individual headset microphone，个人头戴麦克风）是较容易的近场语音，SDM（single distant microphone，单一远场麦克风）是较难的远场语音。

```
ami = load_dataset("edinburghcstr/ami", "ihm")
```

### 多语种语音识别

多语种语音识别指英语之外所有语言的语音识别（speech-to-text）。

#### Multilingual LibriSpeech

Multilingual LibriSpeech 是 [LibriSpeech ASR](https://huggingface.co/datasets/librispeech_asr) 语料库的多语种版本。它由来自 [LibriVox](https://librivox.org/) 项目的大量朗读者有声书构成，很适合学术研究。数据分为八种高资源语言：英语、德语、荷兰语、西班牙语、法语、意大利语、葡萄牙语和波兰语。

#### Common Voice

Common Voice 是一系列众包、开放许可的语音数据集，由说话人以多种语言朗读来自维基百科的文本。任何人都可以贡献录音，因此音频质量和说话人差异都很大。音频条件颇具挑战：存在录音伪影、口音、犹豫以及外来词。转写同时带有大小写和标点。自第 11 版起提供超过 100 种语言，涵盖低资源与高资源语言。

#### VoxPopuli

VoxPopuli 是一个大规模多语种语音语料库，数据源自 2009-2020 年欧洲议会活动录音。因此它占据了一个独特的领域：演讲式、政治性发言，且大多来自非母语者。它为 15 种欧洲语言提供带标注的音频-转写数据。

#### FLEURS

FLEURS（Few-shot Learning Evaluation of Universal Representations of Speech）是一个用于评测 102 种语言语音识别系统的数据集，其中许多被归类为「低资源」语言。数据源自 [FLoRes-101](https://arxiv.org/abs/2106.03193) 数据集——一个包含 3001 个句子从英语到另外 101 种语言翻译的机器翻译语料。以母语者用其母语朗读句子转写的方式录音，录得的音频数据与句子转写配对，形成覆盖全部 101 种语言的多语种语音识别数据。训练集每种语言约含 10 小时有监督音频-转写数据。

### 语音翻译

语音翻译是把口头语音映射为书面文本的任务，且语音与文本为不同语言（例如英语语音译成法语文本）。

#### CoVoST 2

CoVoST 2 是大规模多语种语音翻译语料库，覆盖从 21 种语言译入英语以及从英语译入 15 种语言的翻译。数据集基于 Mozilla 开源的 Common Voice 众包语音数据库构建，语料共代表 2,900 小时语音。

#### FLEURS

FLEURS（Few-shot Learning Evaluation of Universal Representations of Speech）是一个用于评测 102 种语言语音识别系统的数据集，其中许多被归类为「低资源」语言。数据源自 [FLoRes-101](https://arxiv.org/abs/2106.03193) 数据集——一个包含 3001 个句子从英语到另外 101 种语言翻译的机器翻译语料。以母语者用其母语朗读句子转写的方式录音，并将录得的音频数据与 101 种语言各自的句子转写配对，构建出多路平行的语音翻译语料。训练集每个源-目标语言组合约含 10 小时有监督音频-转写数据。

### 音频分类

音频分类是把原始音频输入映射为类别标签输出的任务。音频分类的实际应用包括关键词唤醒、说话人意图与语言识别。

#### SpeechCommands

SpeechCommands 由一秒时长的音频文件构成，每个文件包含一个英语单词朗读或背景噪声。单词来自一小套命令集，由多位不同说话人朗读。该数据集旨在帮助训练和评测小型端侧关键词唤醒系统。

#### Multilingual Spoken Words

Multilingual Spoken Words 是大规模的一秒音频语料，每条含一个朗读单词。数据集涵盖 50 种语言和超过 340,000 个关键词，总计 2,340 万条朗读示例、超过 6,000 小时音频。音频-转写数据源自 Mozilla Common Voice 项目。通过为每条话语生成词级时间戳，抽取出单个朗读词及其对应转写，形成一个新的单词朗读语料库。该数据集的目标用途是多语种关键词唤醒与口语检索的学术研究与商业应用。

#### FLEURS

FLEURS（Few-shot Learning Evaluation of Universal Representations of Speech）是一个用于评测 102 种语言语音识别系统的数据集，其中许多被归类为「低资源」语言。数据源自 [FLoRes-101](https://arxiv.org/abs/2106.03193) 数据集——一个包含 3001 个句子从英语到另外 101 种语言翻译的机器翻译语料。以母语者用其母语朗读句子转写的方式录音，并将录得的音频数据与其说话语言的标签配对。该数据集可作为音频分类数据集用于*语言识别*：训练系统预测语料中每条话语的语言。
