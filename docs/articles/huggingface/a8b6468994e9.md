# Gemma 4 有什么新东西？

与 Gemma-3n 类似，Gemma 4 支持图像、文本和音频输入，并生成文本回复。文本解码器基于 Gemma 模型，支持长上下文窗口。图像编码器与 Gemma 3 的类似，但有两项关键改进：可变宽高比，以及可配置的图像 token 输入数量，让你在速度、内存和质量之间找到最佳平衡点。所有模型都支持图像（或视频）和文本输入；小尺寸变体（E2B、E4B）和 12B Unified 模型还支持音频。

Gemma 4 共有五种尺寸，均提供 base 和指令微调两个版本：

| 模型 | 参数规模 | 上下文窗口 | Checkpoints |
| --- | --- | --- | --- |
| Gemma 4 E2B | 有效 2.3B，含嵌入 5.1B | 128k | [base](https://huggingface.co/google/gemma-4-E2B)、[IT](https://huggingface.co/google/gemma-4-E2B-it) |
| Gemma 4 E4B | 有效 4.5B，含嵌入 8B | 128k | [base](https://huggingface.co/google/gemma-4-E4B)、[IT](https://huggingface.co/google/gemma-4-E4B-it) |
| Gemma 4 12B Unified | 11.95B 稠密，无编码器 | 256K | [base](https://huggingface.co/google/gemma-4-12B)、[IT](https://huggingface.co/google/gemma-4-12B-it) |
| Gemma 4 31B | 31B 稠密模型 | 256K | [base](https://huggingface.co/google/gemma-4-31B)、[IT](https://huggingface.co/google/gemma-4-31B-it) |
| Gemma 4 26B A4B | 混合专家，激活 4B/总计 26B 参数 | 256K | [base](https://huggingface.co/google/gemma-4-26B-A4B)、[IT](https://huggingface.co/google/gemma-4-26B-A4B-it) |

## 能力与架构概览

Gemma 4 复用了此前 Gemma 版本和其他开放模型中的多个架构组件，同时去掉了 Altup 这类复杂或尚无定论的特性。这套组合的目标是高度兼容各种库和设备、高效支持长上下文和 agentic 场景，并且非常适合量化。

正如上面的基准所示，这套特性组合（配合训练数据和配方）让 31B 稠密模型取得了约 1452 的 LMArena 估计分（仅文本），而 26B MoE 只用 4B 激活参数就达到 1441 🤯。正如我们将看到的，至少在非正式、主观的测试中，多模态表现与文本生成相当。

Gemma 4 的主要架构特性：

- **局部滑动窗口**与**全局全上下文**注意力层交替使用。较小的稠密模型用 512 token 的滑动窗口，较大的模型用 1024 token。
- **双 RoPE 配置**：滑动层用标准 RoPE，全局层用剪枝 RoPE，以支持更长上下文。
- **逐层嵌入（Per-Layer Embeddings，PLE）**：第二张嵌入表，向每个解码器层馈入一个小残差信号。
- **共享 KV Cache**：模型最后 N 层复用早先层的 key-value 状态，省去冗余的 KV 投影。
- **视觉编码器（12B 除外）**：使用学习到的 2D 位置与多维 RoPE，保留原始宽高比，可按多种 token 预算编码图像（70、140、280、560、1120）。
- **音频编码器（E2B、E4B）**：USM 风格的 conformer，基础架构与 Gemma-3n 相同。
- **统一无编码器多模态（仅 12B）**：12B Unified 变体去掉独立的视觉和音频编码器，把原始图像 patch 和音频波形直接投影进 LLM 的嵌入空间。见 [Unified Multimodal (12B)](https://huggingface.co/blog/gemma4#unified-multimodal-12b)。

#### 逐层嵌入（PLE）

较小 Gemma 4 模型最有特色的功能之一是逐层嵌入（PLE），它最早在 Gemma-3n 引入。标准 transformer 里，每个 token 只在输入端获得一个嵌入向量，所有层都在同一个初始表示上沿残差流构建，迫使嵌入预先打包模型可能需要的一切。PLE 在主残差流之外增加了一条并行的低维条件通路：对每个 token，它通过组合两个信号为每一层生成一个小的专属向量——一个 token 标识分量（来自嵌入查表）和一个上下文感知分量（来自主嵌入的学习投影）。每个解码器层随后用对应的向量，在注意力和前馈之后通过一个轻量残差块调制隐藏状态。这给了每一层自己的通道，只在需要时接收 token 特定信息，而不必把所有内容压进一个 upfront 嵌入。由于 PLE 维度比主隐藏维度小得多，这以较低的参数成本换取了有意义的逐层专门化。对于多模态输入（图像、音频、视频），PLE 要在 soft token 并入嵌入序列之前计算——因为一旦多模态特征替换了占位符，PLE 依赖的 token ID 就丢失了。多模态位置使用 pad token ID，实际上收到的是中性的逐层信号。

#### 共享 KV Cache

**共享 KV cache** 是一项同时减少推理计算和内存的效率优化。模型最后 `num_kv_shared_layers` 层不计算自己的 key 和 value 投影，而是**复用**相同注意力类型（滑动或全上下文）中最后一个非共享层的 K、V 张量。

实践中，这对质量影响极小，同时显著更高效（内存和计算都是如此），尤其适合长上下文生成和端侧使用。

#### 统一多模态（12B）

Gemma 4 12B Unified 模型没有独立的视觉或音频编码器。原始图像 patch 和音频波形通过轻量线性层直接投影进 LLM 的嵌入空间，所有模态流入同一个 decoder-only transformer。这降低了多模态延迟，并允许整个模型一次完成微调。其 checkpoint 体积让它在消费级硬件上易于部署。

## 多模态能力

我们的测试表明，Gemma 4 开箱即用地支持全面的 multimodal 能力。我们不知道训练数据配比，但用它做 OCR、语音转文本、目标检测或指点等任务都很成功。它还支持纯文本和多模态的 function calling、推理、代码补全与纠错。

### 多模态输入顺序

Gemma 4 在训练时采用了一种特定的模态交错约定：

- **图像内容放在文本*之前***。
- **音频内容放在文本*之后***。

具体地说，这是一个为聊天模板准备输入的正确片段：

```
image_url = "https://huggingface.co/datasets/huggingface/documentation-images/resolve/0052a70beed5bf71b92610a43a52df6d286cd5f3/diffusers/rabbit.jpg"
audio_url = "instructions.m4a"      # A recording of "describe this image"
messages = [
    {
        "role": "user",
        "content": [
            {"type": "image", "image": image_url},
            {"type": "text", "text": "Answer in French."},
            {"type": "audio", "audio": audio_url},
        ]
    }
]
# Cette image montre un personnage anthropomorphe ressemblant à un lapin, vêtu d'un manteau bleu et d'un pantalon beige, se tenant sur un chemin de terre dans un paysage rural idyllique ...

### 视频理解

较小号的 Gemma 4 模型可以接收带音频的视频，较大的可以接收不带音频的视频。虽然模型没有针对视频显式做后训练，但它们能理解带音频和不带音频的视频。模型在音频方面尤其强。

推理代码

```
messages = [
    {
        "role": "user",
        "content": [
            {"type": "video", "url": "https://huggingface.co/datasets/merve/vlm_test_images/resolve/main/concert.mp4"},
            {"type": "text", "text": "What is happening in the video? What is the song about?"},
        ],
    },
]
inputs = processor.apply_chat_template(
    messages,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
    add_generation_prompt=True,
    load_audio_from_video=True, # disable this for larger models
).to(model.device)
output = model.generate(**inputs, max_new_tokens=200)
input_len = inputs.input_ids.shape[-1]
generated_text_ids = output[0][input_len:]
generated_text = processor.decode(generated_text_ids, skip_special_tokens=True)
print(result["content"])
```

## transformers

Gemma 4 从第一天起就获得 transformers 的一等支持 🤗。这一集成让你能配合 bitsandbytes、PEFT、TRL 等其他库使用模型。请确保安装最新版 transformers。

```

对小号 Gemma 4 模型推理，最简单的方式是通过 `any-to-any` pipeline，可以这样初始化。

```
from transformers import pipeline
pipe = pipeline("any-to-any", model="google/gemma-4-e2b-it")
```

然后可以这样传入图像和文本。

```
messages = [
    {
        "role": "user",
        "content": [
            {
                "type": "image",
                "image": "https://huggingface.co/datasets/merve/vlm_test_images/resolve/main/thailand.jpg",
            },
            {"type": "text", "text": "Do you have travel advice going to here?"},
        ],
    }
]
output = pipe(messages, max_new_tokens=100, return_full_text=False)
output[0]["generated_text"]
# Based on the image, which appears to show a magnificent, ornate **Buddhist temple or pagoda**, likely in Southeast Asia (such as Thailand, Myanmar, or Cambodia), here is some general travel advice..
```

messages = [

再往下走一层，你可以用 `AutoModelForMultimodalLM` 类加载 Gemma 4，这对微调尤其有用。内置的 chat template 会负责正确格式化输入，请务必使用它，避免手工构建提示词时出现不易察觉的错误。

推理代码

```
from transformers import AutoModelForMultimodalLM, AutoProcessor
model = AutoModelForMultimodalLM.from_pretrained("google/gemma-4-E2B-it", device_map="auto")
processor = AutoProcessor.from_pretrained("google/gemma-4-E2B-it")
messages = [
    {
        "role": "user",
        "content": [
            {
                "type": "video",
                "image": "https://huggingface.co/datasets/merve/vlm_test_images/resolve/main/rockets.mp4",
            },
            {"type": "text", "text": "What is happening in this video?"},
        ],
    }
]
inputs = processor.apply_chat_template(
    messages,
    tokenize=True,
    add_generation_prompt=True,
    return_dict=True,
    return_tensors="pt"
).to(model.device)

generated_ids = model.generate(**inputs, max_new_tokens=128)
generated_ids_trimmed = [
    out_ids[len(in_ids) :] for in_ids, out_ids in zip(inputs.input_ids, generated_ids)
]
output_text = processor.batch_decode(
    generated_ids_trimmed, skip_special_tokens=True, clean_up_tokenization_spaces=False
)
print(output_text)
```

通过开源的 [`mlx-vlm` 库](https://github.com/Blaizzy/mlx-vlm)，Gemma 4 在 MLX 上提供完整的多模态支持。下面是让模型描述一张图片的方法：

## 多 Token 预测草稿模型（MTP）

Google 为 Gemma 4 家族发布了多 Token 预测（Multi-Token Prediction，MTP）草稿模型：一组通过投机解码加速推理的小型*助手*模型。草稿模型一次提出多个未来 token，目标模型在单次前向传播中验证它们。你得到与目标模型完全相同的输出，只是更快——没有质量损失，不改变推理行为。据报道，端到端加速最高约 3 倍，具体取决于硬件、batch size 和负载。

助手模型覆盖 Gemma 4 全部四种尺寸（E2B、E4B、26B A4B、31B）。它们与目标模型共享 KV cache 以避免重复计算上下文；较小的端侧变体还额外使用了 embedder 聚类技巧，以在设备端保持低内存和低计算。

Checkpoints 见 [Gemma 4 collection](https://huggingface.co/collections/google/gemma-4) 和 [mlx-community collection](https://huggingface.co/collections/mlx-community/gemma-4-assistant-mtp)。

## DiffusionGemma：用扩散做文本生成

除自回归的 Gemma 4 家族外，Google DeepMind 还发布了 [**DiffusionGemma**](https://huggingface.co/google/diffusiongemma-26B-A4B-it)——一个用**离散扩散**而非逐 token 自回归生成文本的多模态模型。它构建在相同的 26B A4B 混合专家基座之上（总计 25.2B / 激活 3.8B 参数，128 个专家中激活 8 个加 1 个共享），接收文本和图像输入、生成文本，支持最高 256K 上下文——全部采用 Apache 2.0 许可证。

标准因果语言模型一次只输出一个 token，而 DiffusionGemma 并行去噪整块 token。架构是 encoder-decoder：自回归编码器预填充提示词并构建 KV cache，解码器在一个 256 token 的"画布"上施加**双向注意力**。在**多画布采样**中，模型用扩散采样器迭代去噪整张画布；一张画布定稿后即被编码并追加到 KV cache，然后开始下一张画布。这种块自回归方式提升了生成速度。

最大的卖点是**吞吐量**：并行去噪每次前向大约生成 15-20 个 token，在小 batch 下（H100、FP8）单用户生成速度可**超过 1100 tokens/秒**。推理计算还是自适应的——简单的提示和代码等结构化任务需要更少的去噪步数，因此每秒 token 数随任务复杂度而变。它保留了 Gemma 4 的完整工具箱：thinking 模式、function calling、长上下文、原生 system prompts，以及可变宽高比和分辨率下的图像理解（OCR、文档解析、目标检测、指点）。

基准测试显示了速度与评测指标之间符合预期的权衡——DiffusionGemma 在多数任务上落后于自回归的 26B A4B（如 MMLU Pro 77.6% 对 82.6%、AIME 2026 69.1% 对 88.3%、GPQA Diamond 73.2% 对 82.3%），换来的是巨大的速度优势，同时在少数任务上略有领先（HLE 无工具 11.0% 对 8.7%）。

上手方式与 Gemma 4 其他模型相同，使用专用的 diffusion 类：

```
from transformers import DiffusionGemmaForBlockDiffusion, AutoProcessor

MODEL_ID = "google/diffusiongemma-26B-A4B-it"

processor = AutoProcessor.from_pretrained(MODEL_ID)
model = DiffusionGemmaForBlockDiffusion.from_pretrained(
    MODEL_ID,
    dtype="auto",
    device_map="auto",
)

message = [{"role": "user", "content": "Why is the sky blue?"}]
input_ids = processor.apply_chat_template(
    message,
    tokenize=True,
    add_generation_prompt=True,
    return_dict=True,
    return_tensors="pt",
).to(model.device)
output = model.generate(**input_ids, max_new_tokens=512)
text = processor.decode(output[0], skip_special_tokens=False)
```

为获得最佳效果，Google 推荐使用带自适应停止的 **Entropy-Bounded（EB）采样器**（最多 48 个去噪步、温度从 0.8 衰减到 0.4 的调度，token 选择的熵界为 0.1）。与 Gemma 4 一样，把图像内容放在提示词中文本**之前**，并用 `<|think|>` 控制 token 切换推理。

Gemma-4-26b-a4b-it Bartowski 训练的量化版本是我这个模型最喜欢的迭代。26b-a4b 是我用过的最好的 LLM。它的智能令人惊叹，就像一部交互式百科全书，还不用受云端打扰。断网时，我照样能用上企业级前沿 AI。它编程挺强、调试挺强、思考问题并找解决方案也挺强（哪怕是还没出现过的新问题），它对深层主题合成答案的能力令人印象深刻。生物和化学知识令人惊讶，数学非常强。最近开始把它用在 Odysseus 上，它在工具 agent 方面表现不错，而且不慢。这就很棒了，运行相当流畅相当快，20 到 30 tokens/秒。它不吃内存，在 LM Studio、llama.cpp 和 rocm 里内存管理到位。它真的快、真的聪明，能处理视觉；最近我还让它自己写 whisper 和 piper/kokoro 的代码，把它变成一个语音智能体。它帮我调试了所有问题，piper 和 kokoro 都跑通了。它写 Python 脚本真的很强。
