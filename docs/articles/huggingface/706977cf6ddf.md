生成模型一路上奇迹不断，文本到视频是下一站。顾名思义，text-to-video 是一个相当新的计算机视觉任务：从文本描述生成一个在时间和空间上都连贯的图像序列。这个任务看似与 text-to-image 极其相似，实际难度却高出一个量级。这些模型如何工作？它们与文本到图像模型有何不同？我们能对它们的性能抱有什么期待？

在这篇博客中，我们讨论文本到视频模型的过去、现在和未来。先回顾 text-to-video 与 text-to-image 任务的差异，再讨论无条件生成和文本条件视频生成各自独特的挑战。接着梳理 text-to-video 模型的最新进展，探索这些方法如何工作、能做到什么。最后分享我们在 Hugging Face 正在做的工作，以推动这些模型的集成与使用，并给出 Hub 内外一些很酷的 demo 和资源。

## 文本到视频 vs 文本到图像

近期进展太多，想跟上文本到图像生成模型的现状不容易。先快速回顾一下。

就在两年前，首批开放词表、高质量的文本到图像生成模型出现。第一波 text-to-image 模型——VQGAN-CLIP、XMC-GAN 和 GauGAN2——都是 GAN 架构。紧随其后的是 2021 年初 OpenAI 大受欢迎的基于 transformer 的 DALL-E、2022 年 4 月的 DALL-E 2，以及 Stable Diffusion 和 Imagen 开启的新一波扩散模型。Stable Diffusion 的巨大成功催生了许多产品化的扩散模型，如 DreamStudio 和 RunwayML GEN-1，也带来了与现有产品的集成，例如 Midjourney。

尽管扩散模型在文本到图像生成上能力惊艳，但无论扩散还是非扩散路线的文本到视频模型，其生成能力都要受限得多。Text-to-video 模型通常在极短的视频片段上训练，意味着要生成长视频就得用计算昂贵且缓慢的滑动窗口方式。因此这些模型出了名地难部署、难扩展，上下文和长度也都受限。

文本到视频任务在多个方向上面临独特挑战。主要挑战包括：

- 计算挑战：确保帧与帧之间的空间和时序一致性会产生长期依赖，计算成本极高，多数研究者根本训不起这类模型。
- 缺乏高质量数据集：用于文本到视频生成的多模态数据集稀缺，且标注往往稀疏，难以学到复杂的运动语义。
- 视频描述（captioning）的模糊性：如何用让模型更容易学习的方式描述视频，仍是一个开放问题。要完整描述一个视频，单条短文本提示是不够的。生成的视频必须以一串提示词——也就是按时间叙事的故事线——作为条件。

下一节我们梳理 text-to-video 领域的发展时间线，以及为分别应对这些挑战提出的各种方法。从更高层看，text-to-video 工作大致提出以下三类东西：

- 新的、质量更高、更易于学习的数据集。
- 在没有配对文本-视频数据的情况下训练这类模型的方法。
- 计算上更高效的、生成长视频和高分辨率视频的方法。

## 如何从文本生成视频？

我们来看看文本到视频生成如何工作，以及这个领域的最新进展。我们将看到 text-to-video 模型如何沿着与 text-to-image 研究类似的路径演化，以及到目前为止文本到视频生成的特有挑战是如何被应对的。

和 text-to-image 一样，文本到视频生成的早期研究也只是几年前的事情。早期研究主要用基于 GAN 和 VAE 的方法，给定描述（caption）自回归地逐帧生成（见 [Text2Filter](https://huggingface.co/papers/1710.00421) 和 [TGANs-C](https://huggingface.co/papers/1804.08264)）。这些工作为一个新计算机视觉任务打下地基，但分辨率低、范围短、动作单一且彼此孤立。

![tgans-c](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/140_text-to-video/TGANs-C.png)
 *最早的文本到视频模型在分辨率、上下文和长度上极其受限，图片来自 [TGANs-C](https://arxiv.org/abs/1804.08264)。*

从文本（GPT-3）和图像（DALL-E）领域大规模预训练 transformer 模型的成功中汲取灵感，新一波文本到视频生成研究转向了 transformer 架构。[Phenaki](https://huggingface.co/papers/2210.02399)、[Make-A-Video](https://huggingface.co/papers/2209.14792)、[NUWA](https://huggingface.co/papers/2111.12417)、[VideoGPT](https://huggingface.co/papers/2104.10157) 和 [CogVideo](https://huggingface.co/papers/2205.15868) 都提出了基于 transformer 的框架；而 [TATS](https://huggingface.co/papers/2204.03638) 这类工作提出混合方法，用 VQGAN 生成图像、用对时间敏感的 transformer 模块按序生成帧。这第二波工作中，Phenaki 特别有意思：它能以一串提示词（也就是故事线）为条件生成长短任意（arbitrary long）的视频。类似地，[NUWA-Infinity](https://huggingface.co/papers/2207.09814) 提出自回归上的自回归生成机制，从文本输入合成无限的图像与视频，能生成长且高清的视频。不过 Phenaki 和 NUWA 模型都没有公开可用。

![phenaki](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/140_text-to-video/phenaki.png)
 *Phenaki 采用基于 transformer 的架构，图片来自[这里](https://arxiv.org/abs/2210.02399)。*

第三波也是当前这一波文本到视频模型，以扩散架构为主。扩散模型在多样、超写实、上下文丰富的图像生成上取得了非凡成功，人们因此有兴趣把扩散模型推广到音频、3D，以及最近的视频等其他领域。这波模型由 [Video Diffusion Models](https://huggingface.co/papers/2204.03458)（VDM，把扩散模型扩展到视频领域）和 [MagicVideo](https://huggingface.co/papers/2211.11018，提出在低维潜空间生成视频片段、报告了相对 VDM 的巨大效率提升）开启。另一个值得一提的工作是 [Tune-a-Video](https://huggingface.co/papers/2212.11565)：用一组文本-视频对微调预训练的文本到图像模型，可以在保留动作的同时改变视频内容。随后不断扩充的 text-to-video 扩散模型清单包括 [Video LDM](https://huggingface.co/papers/2304.08818)、[Text2Video-Zero](https://huggingface.co/papers/2303.13439)、[Runway Gen1 和 Gen2](https://huggingface.co/papers/2302.03011) 以及 [NUWA-XL](https://huggingface.co/papers/2303.12346)。

Text2Video-Zero 是一个文本引导的视频生成与编辑框架，工作方式与 ControlNet 类似。它可以直接根据文本输入生成（或编辑）视频，也能结合文本-姿态或文本-边缘数据输入。正如其名，Text2Video-Zero 是零样本模型，把可训练的运动动态模块与预训练的文本到图像 Stable Diffusion 模型结合，完全不用配对的文本-视频数据。与 Text2Video-Zero 类似，Runway 的 Gen-1 和 Gen-2 能以文本或图像描述的内容为引导合成视频。这些工作中的大多数都在短视频片段上训练，靠滑动窗口的自回归生成来产出更长的视频，不可避免地出现上下文断层。NUWA-XL 针对这一问题，提出"扩散上的扩散"（diffusion over diffusion）方法，在 3376 帧上训练模型。此外还有一些开源的文本到视频模型和框架，如阿里巴巴 / DAMO 视觉智能实验室的 ModelScope、腾讯的 VideoCrafter，它们尚未在同行评审的会议或期刊上发表。

## 数据集

和其他视觉-语言模型一样，文本到视频模型通常在大规模配对的"视频+文本描述"数据集上训练。这些数据集里的视频通常被切成短的固定长度片段，而且往往局限于少量物体的孤立动作。这部分源于计算限制，部分源于"有意义地描述视频内容"本身很难。可以看到，多模态视频-文本数据集的进展与 text-to-video 模型的发展常常交织在一起：一些工作专注于打造更好、更可泛化、更易于学习的数据集；[Phenaki](https://phenaki.video/?mc_cid=9fee7eeb9d#) 这类工作则探索替代方案，比如把文本-图像对与文本-视频对联合用于文本到视频任务。Make-a-Video 走得更远：提出仅用文本-图像对来学习世界长什么样，再用单模态视频数据以无监督方式学习时空依赖。

这些大型数据集遇到的问题与文本到图像数据集类似。最常用的文本-视频数据集 [WebVid](https://m-bain.github.io/webvid-dataset/) 包含 1070 万对文本-视频对（5.2 万小时视频），其中有相当多带无关视频描述的噪声样本。其他数据集则通过聚焦特定任务或领域来缓解这一问题。例如 [Howto100M](https://www.di.ens.fr/willow/research/howto100m/) 数据集包含 1.36 亿条带描述的视频片段，描述如何一步步完成烹饪、手工、园艺、健身等复杂任务。[QuerYD](https://www.robots.ox.ac.uk/~vgg/data/queryd/) 数据集则聚焦事件定位任务，视频描述详细说明了物体和动作的相对位置。[CelebV-Text](https://celebv-text.github.io/) 是一个 7 万多条视频的大规模人脸文本-视频数据集，用于生成具有真实人脸、表情和手势的视频。

用 Hugging Face Diffusers，你可以轻松下载、运行和微调各种预训练的文本到视频模型，包括 [Alibaba / DAMO 视觉智能实验室](https://huggingface.co/damo-vilab)的 Text2Video-Zero 和 ModelScope。我们正在把其他一些激动人心的工作集成进 Diffusers 和 🤗 Transformers。

### Hugging Face Demos

在 Hugging Face，我们的目标是让使用顶尖研究成果、在其之上构建变得更容易。欢迎来 hub 看看并试玩 🤗 团队、众多社区贡献者和论文作者贡献的 Spaces demos。目前我们托管了 [VideoGPT](https://huggingface.co/spaces/akhaliq/VideoGPT)、[CogVideo](https://huggingface.co/spaces/THUDM/CogVideo)、[ModelScope Text-to-Video](https://huggingface.co/spaces/damo-vilab/modelscope-text-to-video-synthesis) 和 [Text2Video-Zero](https://huggingface.co/spaces/PAIR/Text2Video-Zero) 的 demo，未来还会有更多。想看看这些模型能做什么？来看 Text2Video-Zero 的 demo：它不仅演示文本到视频生成，还支持多种其他生成模式——文本引导的视频编辑，以及结合姿态、深度、边缘输入与文本提示的联合条件视频生成。

除了用 demo 试验预训练的文本到视频模型，你还可以用 [Tune-a-Video 训练 demo](https://huggingface.co/spaces/Tune-A-Video-library/Tune-A-Video-Training-UI)，拿你自己的文本-视频对微调一个现有的文本到图像模型。上手方式：上传一段视频，输入一条描述该视频的文本提示。训练完成后，你可以把模型上传到 Hub 的 Tune-a-Video 社区或你自己的账号下，公开或私有都行。训练完成后，直接切到 demo 的 *Run* 标签页，就能从任意文本提示生成视频。

🤗 Hub 上的所有 Spaces 都是 Git 仓库，你可以克隆后在本地或部署环境运行。我们把 ModelScope 的 demo 克隆下来、装好依赖、本地跑起来。

```
git clone https://huggingface.co/spaces/damo-vilab/modelscope-text-to-video-synthesis
cd modelscope-text-to-video-synthesis
pip install -r requirements.txt
python app.py
```

就这样！ModelScope 的 demo 现在在你电脑上本地运行了。注意 ModelScope 文本到视频模型已在 Diffusers 中获得支持，你可以直接用几行代码加载模型生成新视频。

```
import torch
from diffusers import DiffusionPipeline, DPMSolverMultistepScheduler
from diffusers.utils import export_to_video

pipe = DiffusionPipeline.from_pretrained("damo-vilab/text-to-video-ms-1.7b", torch_dtype=torch.float16, variant="fp16")
pipe.scheduler = DPMSolverMultistepScheduler.from_config(pipe.scheduler.config)
pipe.enable_model_cpu_offload()

prompt = "Spiderman is surfing"
video_frames = pipe(prompt, num_inference_steps=25).frames
video_path = export_to_video(video_frames)
```

## 结论

文本到视频研究正在指数级推进，但现有工作在上下文上仍受限，还面临很多挑战。这篇博客我们讲了 text-to-video 生成模型的约束、独特挑战与现状，也看到了最初为其他任务设计的架构范式如何让文本到视频生成大幅跃迁、这对未来研究意味着什么。虽然进展令人印象深刻，相比文本到图像模型，文本到视频模型仍然任重道远。最后，我们也展示了如何利用 Hub 上的 demo 或 🤗 Diffusers pipeline 把这些模型用于各种任务。
