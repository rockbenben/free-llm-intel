我们很高兴推出 Messages API，让 Text Generation Inference（TGI）和 Inference Endpoints 兼容 OpenAI。

从 1.4.0 版本开始，TGI 提供与 OpenAI Chat Completion API 兼容的 API。新的 Messages API 让客户和用户可以从 OpenAI 模型平滑迁移到开放 LLM。该 API 可直接配合 OpenAI 的客户端库或 LangChain、LlamaIndex 这类第三方工具使用。

> "新的 OpenAI 兼容 Messages API 让 Ryght 的实时 GenAI 编排平台可以轻松地把 LLM 用例从 OpenAI 切换到开放模型。我们从 GPT4 迁移到 Inference Endpoints 上的 Mixtral/Llama2 毫不费力，现在的工作流更简单，对 AI 方案的掌控也更强。" —— Johnny Crupi，Ryght 首席技术官

新的 Messages API 现在也已上线 Inference Endpoints，专属版（dedicated）和 Serverless 版都支持。为了让你快速上手，我们给出了以下详细示例：

- [创建 Inference Endpoint](https://huggingface.co/blog/tgi-messages-api#create-an-inference-endpoint)
- [用 OpenAI 客户端库调用 Inference Endpoints](https://huggingface.co/blog/tgi-messages-api#using-inference-endpoints-with-openai-client-libraries)
- [与 LangChain 和 LlamaIndex 集成](https://huggingface.co/blog/tgi-messages-api#integrate-with-langchain-and-llamaindex)

**限制：** Messages API 目前不支持函数调用（function calling），且仅对 tokenizer 配置中定义了 `chat_template` 的 LLM 有效，例如 [Mixtral 8x7B Instruct](https://huggingface.co/mistralai/Mixtral-8x7B-Instruct-v0.1/blob/125c431e2ff41a156b9f9076f744d2f35dd6e67a/tokenizer_config.json#L42) 就是这种情况。

## 创建 Inference Endpoint

[Inference Endpoints](https://huggingface.co/docs/inference-endpoints/index) 提供安全的生产级方案，可以把 Hub 上的任何机器学习模型轻松部署到由 Hugging Face 管理的专属基础设施上。

在这个示例中，我们将把微调过的 Mixtral 模型 [Nous-Hermes-2-Mixtral-8x7B-DPO](https://huggingface.co/NousResearch/Nous-Hermes-2-Mixtral-8x7B-DPO) 用 [Text Generation Inference](https://huggingface.co/docs/text-generation-inference/index) 部署到 Inference Endpoints。

可以[在 UI 里点几下](https://ui.endpoints.huggingface.co/new?vendor=aws&repository=NousResearch%2FNous-Hermes-2-Mixtral-8x7B-DPO&tgi_max_total_tokens=32000&tgi=true&tgi_max_input_length=1024&task=text-generation&instance_size=2xlarge&tgi_max_batch_prefill_tokens=2048&tgi_max_batch_total_tokens=1024000&no_suggested_compute=true&accelerator=gpu&region=us-east-1)完成部署，也可以用 `huggingface_hub` Python 库以编程方式创建和管理 Inference Endpoints。这里演示后者的用法。

在下面展示的 API 调用中，需要指定端点名称和模型仓库，以及 `text-generation` 任务。本例使用 `protected` 类型，访问已部署端点需要有效的 Hugging Face token。我们还需要配置硬件需求：厂商、地域、加速卡、实例类型和规格。可用资源清单可以[用这个 API 调用](https://api.endpoints.huggingface.cloud/#get-/v2/provider)查询，部分模型推荐配置见我们的[目录](https://ui.endpoints.huggingface.co/catalog)。

*注意：你可能需要向 [api-enterprise@huggingface.co](mailto:api-enterprise@huggingface.co) 发邮件申请提升配额。*

```
from huggingface_hub import create_inference_endpoint

endpoint = create_inference_endpoint(
    "nous-hermes-2-mixtral-8x7b-demo",
    repository="NousResearch/Nous-Hermes-2-Mixtral-8x7B-DPO",
    framework="pytorch",
    task="text-generation",
    accelerator="gpu",
    vendor="aws",
    region="us-east-1",
    type="protected",
    instance_type="nvidia-a100",
    instance_size="x2",
    custom_image={
        "health_route": "/health",
        "env": {
            "MAX_INPUT_LENGTH": "4096",
            "MAX_BATCH_PREFILL_TOKENS": "4096",
            "MAX_TOTAL_TOKENS": "32000",
            "MAX_BATCH_TOTAL_TOKENS": "1024000",
            "MODEL_ID": "/repository",
        },
        "url": "ghcr.io/huggingface/text-generation-inference:sha-1734540", # use this build or newer
    },
)

endpoint.wait()
print(endpoint.status)
```

部署启动需要几分钟。可以用 `.wait()` 工具阻塞当前线程，直到端点进入最终的 "running" 状态。运行起来后，可以确认它的状态，并通过 UI Playground 试一把：

[![IE UI Overview](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/messages-api/endpoint-overview.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/messages-api/endpoint-overview.png)

太好了，端点跑通了！

## 用 OpenAI 客户端库调用 Inference Endpoints

TGI 对 Messages 的支持让 Inference Endpoints 直接兼容 OpenAI Chat Completion API。也就是说，任何通过 OpenAI 客户端库调用 OpenAI 模型的现有脚本，都可以直接换成运行在 TGI 端点上的开放 LLM！

借助这种无缝切换，你可以立即享受开放模型带来的诸多好处：

- 对模型和数据完全的掌控与透明
- 不用再担心速率限制
- 可以按照自身特定需求完全定制系统

来看怎么做。

### 使用 Python 客户端

下面的示例展示如何用 [OpenAI Python Library](https://github.com/openai/openai-python) 完成这个切换。只需把 `<ENDPOINT_URL>` 替换成你的端点 URL（记得包含 `v1/` 后缀），并在 `<HF_API_TOKEN>` 填入有效的 Hugging Face 用户 token。`<ENDPOINT_URL>` 可以在 Inference Endpoints 的 UI 里获取，也可以用上面创建的 endpoint 对象的 `endpoint.url`。

之后照常用这个客户端，给 Inference Endpoint 传一个 messages 列表即可流式获取响应。

```
from openai import OpenAI

# initialize the client but point it to TGI
client = OpenAI(
    base_url="<ENDPOINT_URL>" + "/v1/",  # replace with your endpoint url
    api_key="<HF_API_TOKEN>",  # replace with your token
)
chat_completion = client.chat.completions.create(
    model="tgi",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Why is open-source software important?"},
    ],
    stream=True,
    max_tokens=500
)

# iterate and print stream
for message in chat_completion:
    print(message.choices[0].delta.content, end="")
```

在幕后，TGI 的 Messages API 会自动用模型的 [chat template](https://huggingface.co/docs/transformers/chat_templating) 把消息列表转换成模型所需的指令格式。

> 💡 某些 OpenAI 功能（如函数调用）与 TGI 不兼容。目前 Messages API 支持的 chat completion 参数有：stream、max_tokens、frequency_penalty、logprobs、seed、temperature 和 top_p。

### 使用 JavaScript 客户端

这是上面同一个流式示例，改用 [OpenAI Javascript/Typescript Library](https://github.com/openai/openai-node)。

```
import OpenAI from "openai";

const openai = new OpenAI({
  baseURL: "<ENDPOINT_URL>" + "/v1/", // replace with your endpoint url
  apiKey: "<HF_API_TOKEN>", // replace with your token
});

async function main() {
  const stream = await openai.chat.completions.create({
    model: "tgi",
    messages: [
      { role: "system", content: "You are a helpful assistant." },
      { role: "user", content: "Why is open-source software important?" },
    ],
    stream: true,
    max_tokens: 500,
  });
  for await (const chunk of stream) {
    process.stdout.write(chunk.choices[0]?.delta?.content || "");
  }
}

main();
```

## 与 LangChain 和 LlamaIndex 集成

接下来看看如何把新建的端点用于你偏好的 RAG 框架。

### 与 LangChain 的用法

要在 [LangChain](https://python.langchain.com/docs/get_started/introduction) 中使用，只需创建一个 `ChatOpenAI` 实例并按如下方式传入 `<ENDPOINT_URL>` 和 `<HF_API_TOKEN>`：

```
from langchain_community.chat_models.openai import ChatOpenAI

llm = ChatOpenAI(
    model_name="tgi",
    openai_api_key="<HF_API_TOKEN>",
    openai_api_base="<ENDPOINT_URL>" + "/v1/",
)
llm.invoke("Why is open-source software important?")
```

我们直接复用原本面向 OpenAI 模型的 `ChatOpenAI` 类。这让既有代码只需改一行就能用上我们的端点。现在把一个这样声明的 LLM 用于一个简单的 RAG 流水线，回答一个关于某篇 HF 博客内容的问题。

```
from langchain_core.runnables import RunnableParallel
from langchain_community.embeddings import HuggingFaceEmbeddings

# Load, chunk and index the contents of the blog
loader = WebBaseLoader(
    web_paths=("https://huggingface.co/blog/open-source-llms-as-agents",),
)
docs = loader.load()

# Declare an HF embedding model and vector store
hf_embeddings = HuggingFaceEmbeddings(model_name="BAAI/bge-large-en-v1.5")

text_splitter = RecursiveCharacterTextSplitter(chunk_size=512, chunk_overlap=200)
splits = text_splitter.split_documents(docs)
vectorstore = Chroma.from_documents(documents=splits, embedding=hf_embeddings)

# Retrieve and generate using the relevant pieces of context
retriever = vectorstore.as_retriever()
prompt = hub.pull("rlm/rag-prompt")

def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)

rag_chain_from_docs = (
    RunnablePassthrough.assign(context=(lambda x: format_docs(x["context"])))
    | prompt
    | llm
    | StrOutputParser()
)

rag_chain_with_source = RunnableParallel(
    {"context": retriever, "question": RunnablePassthrough()}
).assign(answer=rag_chain_from_docs)

rag_chain_with_source.invoke("According to this article which open-source model is the best for an agent behaviour?")
```

```
{
    "context": [...],
    "question": "According to this article which open-source model is the best for an agent behaviour?",
    "answer": " According to the article, Mixtral-8x7B is the best open-source model for agent behavior, as it performs well and even beats GPT-3.5. The authors recommend fine-tuning Mixtral for agents to potentially surpass the next challenger, GPT-4.",
}
```

### 与 LlamaIndex 的用法

类似地，也可以在 [LlamaIndex](https://www.llamaindex.ai/) 中使用 TGI 端点。我们用 `OpenAILike` 类，实例化时额外配置几个参数（`is_local`、`is_function_calling_model`、`is_chat_model`、`context_window`）。注意 context window 的取值应与端点里设置的 `MAX_TOTAL_TOKENS` 一致。

```
from llama_index.llms import OpenAILike

# Instantiate an OpenAILike model
llm = OpenAILike(
    model="tgi",
    api_key="<HF_API_TOKEN>",
    api_base="<ENDPOINT_URL>" + "/v1/",
    is_chat_model=True,
    is_local=False,
    is_function_calling_model=False,
    context_window=32000,
)

# Then call it
llm.complete("Why is open-source software important?")
```

现在可以把它用于类似的 RAG 流水线。要记住，Inference Endpoint 中先前设置的 `MAX_INPUT_LENGTH` 会直接影响模型能处理的检索块数量（`similarity_top_k`）。

```
from llama_index import (
    ServiceContext,
    VectorStoreIndex,
)
from llama_index import download_loader
from llama_index.embeddings import HuggingFaceEmbedding
from llama_index.query_engine import CitationQueryEngine

SimpleWebPageReader = download_loader("SimpleWebPageReader")

documents = SimpleWebPageReader(html_to_text=True).load_data(
    ["https://huggingface.co/blog/open-source-llms-as-agents"]
)

# Load embedding model
embed_model = HuggingFaceEmbedding(model_name="BAAI/bge-large-en-v1.5")

# Pass LLM to pipeline
service_context = ServiceContext.from_defaults(embed_model=embed_model, llm=llm)
index = VectorStoreIndex.from_documents(
    documents, service_context=service_context, show_progress=True
)

# Query the index
query_engine = CitationQueryEngine.from_args(
    index,
    similarity_top_k=2,
)
response = query_engine.query(
    "According to this article which open-source model is the best for an agent behaviour?"
)
```

```
According to the article, Mixtral-8x7B is the best performing open-source model for an agent behavior [5]. It even beats GPT-3.5 in this task. However, it's worth noting that Mixtral's performance could be further improved with proper fine-tuning for function calling and task planning skills [5].
```
