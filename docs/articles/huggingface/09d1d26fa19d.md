[![Holo4 基准测试运行时的屏幕墙，涵盖 Web 应用、桌面软件与移动端。](https://assets.hcompanyprod.fr/holo4/hf/holo4-cover.jpg)](https://assets.hcompanyprod.fr/holo4/hf/holo4-cover.jpg)

Holo4 是我们全新的一系列 agentic 模型。它有两个尺寸：27B dense 和 35B-A3B Mixture of Experts。两者都已上线 H Models API。我们同时发布 Holotron 3 的更新版本：Holotron4 Nano。

Holo4 建立在我们上一代模型之上，可以通过任何可用接口与软件交互：GUI、代码、MCP 和 API。它在学术基准上得分不错，但我们是为真实业务工作流而构建它的。它是在一大批环境与任务上通过监督学习与强化学习训练出来的，其中包含由我们的 Agentic Task Factory 生成的环境与任务。

## 为每一种接口构建的模型

Holo4 会在屏幕上点击和输入、编写并运行它自己的代码，并调用 MCP 或 API 工具。它选用最契合当前任务的那一种。多数 agentic 模型只为单一接口训练过：以 GUI 为主的模型离开屏幕就是瞎的，而偏好 tool calling 的模型面对一个没有 API 的应用就会卡住。真实工作并不是这样割裂的，单个业务任务往往需要把这几种不同做法结合起来。

Holo4 能跑在桌面、Web、Android、代码沙箱里，也能对接业务 API。每一种情况下都是同一个模型，调用方式也完全一样。你不需要为每个平台另选一个模型。

[![Holo4 的基准测试结果与每个任务的成本，对比 Qwen3.8 27B 与前沿模型](https://assets.hcompanyprod.fr/holo4/hf/holo4-benchmark-table.png)](https://assets.hcompanyprod.fr/holo4/hf/holo4-benchmark-table.png)

Holo4 模型相对其 Qwen 基座有显著提升。在长流程工作流上，Holo4 只落后于最强的闭源模型：在 OSWorld 2.0 上，Holo4 27B 得分 61.7%，而 Opus 5.5 为 81.8%，Holo4 35B-A3B 达到 30.9%。但它做到这些所用的参数量少了几个数量级，成本也低得多。我们公开了我们在公开基准上每一项分数背后的全部轨迹：在 [trajectories.hcompany.ai](https://trajectories.hcompany.ai) 逐步回放每一步，或从 [Hugging Face](https://huggingface.co/datasets/Hcompany/trajectories) 下载。

## 与前沿模型竞争力相当，成本只占一小部分

在桌面控制（OSWorld 2.0）和 API 使用（AutomationBench）这两类最难的学术基准上，Holo4 能以低得多的单任务成本与前沿模型竞争。

[![OSWorld 2.0：平均部分得分 vs. 每个任务的成本](https://assets.hcompanyprod.fr/holo4/hf/holo4-cost-osworld2.png)](https://assets.hcompanyprod.fr/holo4/hf/holo4-cost-osworld2.png)

[![AutomationBench：得分 vs. 每个任务的成本](https://assets.hcompanyprod.fr/holo4/hf/holo4-cost-automationbench.png)](https://assets.hcompanyprod.fr/holo4/hf/holo4-cost-automationbench.png)

关于成本-性能图表的说明

**OSWorld 2.0。** 成本由每次 agentic 运行的输入与输出 tokens 估算得出。Holo4 按 H Models API 的费率计价（单次运行）。Qwen3.8 27B：分数取自 model card，成本由我们这次运行的 tokens 按 Alibaba Cloud 挂牌价计算。Qwen3.6 35B-A3B：在我们 harness 中的单次运行，按 Alibaba Cloud 挂牌价计算，缓存命中按输入价格的 20% 计费。GPT 与 Opus 的各 effort 档扫描数据来自 OpenAI 的发布数据；其余闭源与 open-weight 数据点使用 [OSWorld 2.0 官方排行榜](https://osworld-v2.xlang.ai/)。各点的发布版本、harness 与任务子集并不相同。连线只连接闭源模型中未被支配的得分与成本组合；Holo4 不在连线之内。

**AutomationBench。** Holo4、Qwen3.8 27B 与 Qwen3.6 35B-A3B：AutomationBench v1.0.6，分数与成本均在我们的内部 harness 中测得。其他模型：公开集分数来自 [AutomationBench README](https://github.com/zapier/AutomationBench)，每个任务的成本来自[官方排行榜](https://zapier.com/benchmarks)，该排行榜跑的是私有集。一旦 Holo4 在私有集上完成评测，我们会予以报告。

## 真正能干活的 AI

Holo4 模型在我们 Agentic Task Factory 的环境与任务上训练，在专业软件上表现出色。下面的示例把 Holo4 27B 与它的基座模型 Qwen3.8 27B 并列展示。两个模型使用同样的 prompt 和 harness。

### 3D 建模 · 埃菲尔铁塔

> 在 FreeCAD 中建立一个埃菲尔铁塔的 3D 模型，比例为 1 mm 对应 1 米，以原点为中心并与 X 轴和 Y 轴对齐。请按这份设计来做。
> 塔身在任何高度的平面都是正方形，绝不是圆形。其半宽（从中轴量到角点）在地面为 62.5 mm，在高度 57 处为 32.5 mm，在高度 115 处为 17.5 mm，在高度 276 处为 9.35 mm。在这些高度之间，半宽沿一条平滑曲线变化：靠近地面处下降陡峭，越往上越平缓，绝不是一条直线。
> 四条相同的塔腿，每个象限一条，每条都是一根外角沿该轮廓变化的方形立柱。每条塔腿在地面的宽度为 14 mm，到高度 276 处收窄为 4 mm。塔腿从地面直到第一层平台彼此分开，并随高度上升而收拢。它们之间的空间不作任何填充：塔是通透的，从每一侧都能一眼看穿。
> 三个平台，每个都是一块以中轴为中心的实心方板：高度 57 处宽 72 mm、厚 4 mm；高度 115 处宽 40 mm、厚 3 mm；高度 276 处宽 22 mm、厚 3 mm。
> 一根从高度 276 到 324 的桅杆，截面为方形，底部宽 8 mm，向顶端收窄至 2 mm。
> 每个部件都必须是非零体积的闭合实体，且任何部件都不得填充塔腿之间的空间。

**Holo4 27B**（84 次调用，1.3M tokens）

**Qwen3.8 27B**（60 次调用，1.0M tokens）

### 3D 建模 · H 标志

> 在 FreeCAD 中建立 H company 标志的 3D 模型：一个实心填充的圆盘紧挨着一个方正的无衬线大写字母 H，两者挤出到同样的厚度，两个形状高度相近并彼此分开、不重叠，圆盘的中心与 H 的中间高度齐平。把两个形状都染成黑色。

**Holo4 27B**（94 次调用，1.5M tokens）

**Qwen3.8 27B**（118 次调用，1.9M tokens）

### 游戏设计 · Pac-Man

> 在 Godot 里做一个 Pac-Man 风格的游戏，并让它保持运行。
> 一个由墙按网格排成的矩形迷宫，每条通路都铺满豆子。一个玩家标记沿通路持续移动，吃掉它经过的每一颗豆子并为此得一分。三只幽灵在同一片通路中移动并追逐玩家。若幽灵抓住玩家，玩家损失一条命，一切复位到起始位置。得分与剩余生命数绘制在屏幕上。
> 不会有人来玩这个游戏。玩家由一条简单的启发式规则自行驱动：在每个岔路口它朝最近的豆子走去，除非有幽灵靠近，此时它会远离那个幽灵。游戏必须在无人值守的情况下无限运行，完全不接收键盘输入。
> 调通之后，把游戏启动并让它一直玩下去。

**Holo4 27B**（68 次调用，2.4M tokens，268 行）

**Qwen3.8 27B**（197 次调用，11.4M tokens，327 行）

## 我们是如何构建 Holo4 的

### Agentic task factory

我们内部的一套 agentic 流水线仅凭文档就能构建可交互的环境与可验证的任务，例如真实网站的截图或开源软件。到目前为止，它已经产出了约 10,000 个任务，覆盖 Web 应用、MCP server 与桌面环境，其中包括通过 GUI 和 MCP 暴露同一份状态的混合环境。

[![Agentic Task Factory：来源、构建、关卡、运行时与产出](https://assets.hcompanyprod.fr/holo4/hf/holo4-task-factory.png)](https://assets.hcompanyprod.fr/holo4/hf/holo4-task-factory.png)

### 训练

[![Holo4 训练：在 127B tokens 上做 supervised fine-tuning，两个 RL 专家模型，合并为一个模型](https://assets.hcompanyprod.fr/holo4/hf/holo4-training.png)](https://assets.hcompanyprod.fr/holo4/hf/holo4-training.png)

### Harness

除了训练，我们还重做了自己的 harness——那个在上百步之中执行模型动作并管理其上下文的循环——依据的是 agentic 表现在 OSWorld 2.0 上给出的反馈。由 agent 标注每个任务失败的原因，工程师再评审它们给出的修复。改动最大的是给 agent 一份能跟踪上百步的可靠 memory，以及在桌面机器本机上开一个 shell。

[![自动化的 harness 工程：随时间变化的每次评测运行的 OSWorld 2.0 得分](https://assets.hcompanyprod.fr/holo4/hf/holo4-harness-history.png)](https://assets.hcompanyprod.fr/holo4/hf/holo4-harness-history.png)

*Opus 5（70.2%）与 GPT-5.6 Sol（66.2%）用的是 v2026.08.08 离线集上 max-effort 的部分奖励（partial rewards），取自 [OpenAI 的发布图表](https://openai.com/index/introducing-gpt-6-sol-and-luna/)，与成本-性能图的口径一致。其余参考分数来自 model card 和官方排行榜。任务发布版本、子集与 harness 各不相同。*

## Holotron4 Nano

我们的 post-training 技术栈就是为适配新的 foundation model、产出能跨接口与跨环境泛化的 agent 而设计的。作为 [NVIDIA Nemotron Coalition](https://hcompany.ai/newsroom/h-joins-nemotron-coalition) 的成员，我们把最新一版技术栈用在 Nemotron 3 Nano Omni 模型上，作为 Holotron 3 的后续。

同一套配方把 Nemotron 3 Nano Omni 变成了 Holotron4 Nano，一个通用型 agentic 模型，在 GUI 工作流以及暴露 MCP、API 或代码沙箱的环境中都相对基座模型有显著提升。

[![Holotron4 Nano 与 Nemotron 3 Nano Omni 在五个基准上的对比](https://assets.hcompanyprod.fr/holo4/hf/holotron4-benchmarks.png)](https://assets.hcompanyprod.fr/holo4/hf/holotron4-benchmarks.png)

*提升幅度为相对 Nemotron 3 Nano Omni 的绝对百分点改进。*

这些提升说明我们的配方迁移性很好，能把一个通用模型变成一个 agentic 专家。其中没有任何部分是绑定某个尺寸的。
