# Open R1：更新 #4

[![image/png](https://cdn-uploads.huggingface.co/production/uploads/5e48005437cb5b49818287a5/3u0jnJp209mSxfhW0aAr6.png)](https://cdn-uploads.huggingface.co/production/uploads/5e48005437cb5b49818287a5/3u0jnJp209mSxfhW0aAr6.png)

## 欢迎 DeepSeek-V3 **0324**

本周，DeepSeek 的一个[新模型](https://huggingface.co/deepseek-ai/DeepSeek-V3-0324)悄然登陆 Hub。它是 DeepSeek-V3 的更新版本——V3 正是 R1 推理模型背后的基座模型。关于这个新模型目前公开信息不多，但我们确实知道一些事情！

## 目前已知

新模型与原版 DeepSeek-V3 架构相同，并且改用 MIT 许可证——之前的 V3 用的是自定义模型许可证。这次发布的重心是提升指令遵循以及代码和数学能力。看看吧！

### 有多强？

DeepSeek 团队在一系列数学和编程任务上评估了该模型，相比其他前沿模型，模型实力强劲：

[![image/png](https://cdn-uploads.huggingface.co/production/uploads/5e48005437cb5b49818287a5/LKg5VHl_eKTRO1wuKjoBw.png)](https://cdn-uploads.huggingface.co/production/uploads/5e48005437cb5b49818287a5/LKg5VHl_eKTRO1wuKjoBw.png)

显然，这个模型跻身顶级梯队：常与 GPT-4.5 持平，整体强于 Claude-Sonnet-3.7。

概括来说，模型在各基准上进步显著：

- MMLU-Pro：75.9 → 81.2（+5.3）（衡量综合理解的好基准）
- GPQA：59.1 → 68.4（+9.3）
- AIME：39.6 → 59.4（+19.8）（MATH 能力的代理指标）
- LiveCodeBench：39.2 → 49.2（+10.0）（编程能力的指标）

具体来说，模型卡里 DeepSeek 提到了以下方向的针对性改进：

- **前端 Web 开发** 代码可执行性更好，网页和游戏前端的观感更美观
- **中文写作能力** 风格与内容质量提升，与 R1 写作风格对齐，中长文写作质量更好。特性增强：多轮交互式改写改进，翻译质量与书信写作优化
- **中文搜索能力** 报告分析请求的输出更详尽
- **Function Calling 改进** 函数调用准确率提升，修复了之前 V3 版本的问题

那么问题可能来了：他们到底怎么做到的？我们不妨猜测一番！

### 他们是怎么做到的？

从命名和架构看，可以合理假定新模型是在之前 V3 模型基础上继续训练的。改进可能来自两个方向：

- **持续预训练（Continual pretraining）**：从 V3 模型出发，a) 用更新、更及时的数据继续预训练，b) 用筛选更好、质量更高的数据。这会提升近期事件的事实准确性，并全面增强能力。
- **后训练（post-training）改进**：尤其在指令遵循与风格为王的时代，后训练扮演的角色最重。他们很可能改进了后训练数据配比，甚至可能改进了算法。

在团队发布技术报告之前，无法确定他们具体调了什么，但后训练流水线升级很可能是主因，或许还额外加了点预训练。下面来看看怎么用这个模型！

## 如何使用模型

### Inference Providers

你可以用 Hugging Face 的 [Inference Providers](https://huggingface.co/blog/inference-providers) 快速体验这个模型，Fireworks、Hyperbolic 和 Novita 都提供它。

下面是用 `huggingface_hub` 库的例子。你也可以用 OpenAI 客户端库，就像这个[例子](https://huggingface.co/deepseek-ai/DeepSeek-V3-0324?inference_api=true&inference_provider=novita&language=python)里那样。

```
from huggingface_hub import InferenceClient

client = InferenceClient(
    provider="fireworks-ai",
    #api_key="your hf or provider token"
)

messages = [
    {
        "role": "user",
        "content": "My first is second in line; I send shivers up your spine; not quite shining bright. I glitter in the light."
    }
]

completion = client.chat.completions.create(
    model="deepseek-ai/DeepSeek-V3-0324",
    messages=messages,
    temperature=0.3,
)

print(completion.choices[0].message['content'])
# ...**Final Answer: ice**
```

### Text Generation Inference

TGI 最新 release 也支持运行 DeepSeek V3-0324。你可以直接用打标签的 docker 镜像在一个 H100 节点上跑：

```
docker run --gpus all --shm-size 1g -p 8080:80 -v $ volume:/data \
    ghcr.io/huggingface/text-generation-inference:3.2.1 --model-id deepseek-ai/DeepSeek-V3-0324
```

**SGLang**

SGLang 开箱支持运行 DeepSeek V3-0324，同样支持 Multi Latent Attention 和数据并行优化。在一个 H100 节点上直接运行以下命令即可。更多信息见[这里](https://github.com/sgl-project/sglang/tree/main/benchmark/deepseek_v3)。

```
docker pull lmsysorg/sglang:latest

docker run --gpus all --shm-size 32g -p 30000:30000 -v ~/.cache/huggingface:/root/.cache/huggingface --ipc=host --network=host --privileged lmsysorg/sglang:latest \
    python3 -m sglang.launch_server --model deepseek-ai/DeepSeek-V3-0324 --tp 8 --trust-remote-code --port 30000
```

**Unsloth 与 Llama.cpp 的动态量化**

运行 DeepSeek V3-0324 这样的大 LLM 计算量可观，需要大量 GPU 显存。量化正是为此而生：让最终用户以低得多的显存消耗使用同一个模型，只付出下游性能的小幅代价。

Unsloth AI 制作了动态量化版本，让你用相当于一个 H100 节点一半的算力跑 DeepSeek V3，配合 llama.cpp 运行时基准性能也没有太大劣化。详情阅读：[https://huggingface.co/unsloth/DeepSeek-V3-0324-GGUF](https://huggingface.co/unsloth/DeepSeek-V3-0324-GGUF)

## 它安全吗？

安全地运行语言模型，自第一批 GPT 模型发布以来就一直备受瞩目。随着 DeepSeek 模型爆火及其出身背景，这个问题重新引发关注。我们来梳理一下哪些做法是安全的、哪些领域最好谨慎些。这不只针对 DeepSeek——对任何开放模型都成立！

首先——下载模型安全吗？

### 下载与运行模型

是的，下载是安全的。Hub 侧有不少保障措施，确保模型可安全下载和运行：

- **Safetensors**：DeepSeek 模型权重在 Hub 上以 `safetensors` 格式存储，确保不可能隐藏代码执行——这正是旧的 PyTorch `pickle` 格式的风险。所以恶意代码无法藏在权重文件里。详情阅读 [Safetensors 安全审计博客](https://huggingface.co/blog/safetensors-security-audit)。
- **建模代码**：运行模型时，建模代码也要和权重文件一起下载。这里有三重机制提升安全性：1. 文件在 Hub 上完全可见，2. 用户必须显式设置 `trust_remote_code=True` 才会执行与模型关联的任何代码，3. 安全扫描器会扫描 Hub 上的文件并标记任何恶意代码文件。如果你想格外小心，可以用 `revision` 设置锁定模型版本，确保下载的是经过审阅的那版建模代码。

所以下载权重是安全的；在代码审阅之后，执行建模代码也安全。这意味着你可以在本地运行 DeepSeek 模型，不用担心后门或恶意代码执行。

那么，下载和运行之外的主要风险是什么？取决于你拿模型输出做什么！

### 模型输出

以下建议不针对任何特定模型，对开放和封闭模型同样适用——无论考虑的是模型内置隐秘行为带来的风险，还是模型意外产出糟糕输出的风险。

我们从对齐、代码生成和智能体三个领域来谈风险。

**对齐偏差（Alignment mismatch）**：每个模型供应商都自行决定模型按什么价值观、以何种方式对齐。这些价值观是什么、如何选定，通常并不透明，而且也可能随时间变化（[见这项研究](https://www.nature.com/articles/s41599-025-04465-z)）。开放模型的好处是：之后仍可以通过自定义微调改变对齐，[Perplexity 的 DeepSeek 1776](https://www.perplexity.ai/hub/blog/open-sourcing-r1-1776)就是例子。

GPT-3.5-turbo 的经济与社会价值漂移

模型拒答频率：DeepSeek 的模型 vs. Perplexity 的 R1 1776。

作为通例，用户应当意识到任何 LLM 都带有这样那样的偏向，并据此对待模型输出。

**代码生成**：LLM 最流行的用途之一就是当编程助手，但不加甄别地使用模型输出，这里造成的负面影响也最大。模型在海量已公开代码上训练过，有新款也有老代码，其中通常包括潜在的恶意代码或含有已知漏洞的代码。所以模型给出的代码方案可能带有类似的漏洞。

那么，用 LLM 做代码开发时如何防范安全问题？对提出的改动认真做代码评审，用合适的工具扫描代码漏洞——就像对待任何代码贡献一样。

**智能体（Agents）**：过去几个月智能体应用大火，但给 LLM 更多自主权和行动力同样伴随风险。务必留意智能体拥有什么样的系统访问权限、你向它提供了哪些信息。一些好的实践：

- **沙箱**：不要在你的电脑上运行有权限、能控制你计算机的智能体，避免泄露隐私信息或误删重要文件。
- **私有信息**：不要把登录凭据等隐私信息分享给 LLM。如果确实需要让模型访问某个系统，使用带严格访问规则的专用访问密钥。
- **人在回路**：想交给智能体自动化的高风险流程，务必留人工环节做最终确认。

**TL;DR**：跑这些模型安全吗？是的，下载和运行模型是安全的；但和任何模型一样，使用模型的生成内容时应当采取适当的安全措施。
