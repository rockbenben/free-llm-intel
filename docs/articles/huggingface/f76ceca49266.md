# 在 PyTorch 中可视化并理解 GPU 内存

Quentin Gallouédec（[qgallouedec](https://huggingface.co/qgallouedec)）

这条消息你一定不陌生 🤬：

```
RuntimeError: CUDA out of memory. Tried to allocate 20.00 MiB (GPU 0; 7.93 GiB total capacity; 6.00 GiB already allocated; 14.88 MiB free; 6.00 GiB reserved in total by PyTorch)
```

GPU 显存满了很容易看出来，但搞明白为什么满、怎么解决就没那么轻松了。这篇教程会一步步带你可视化并理解 PyTorch 训练期间的 GPU 显存占用，还会看看如何估算显存需求、优化显存使用。

## 🔎 PyTorch 可视化工具

PyTorch 提供了一个趁手的 GPU 显存可视化工具：

```
import torch
from torch import nn

# Start recording memory snapshot history
torch.cuda.memory._record_memory_history(max_entries=100000)

model = nn.Linear(10_000, 50_000, device ="cuda")
for _ in range(3):
    inputs = torch.randn(5_000, 10_000, device="cuda")
    outputs = model(inputs)

# Dump memory snapshot history to a file and stop recording
torch.cuda.memory._dump_snapshot("profile.pkl")
torch.cuda.memory._record_memory_history(enabled=None)
```

运行这段代码会生成一个 `profile.pkl` 文件，里面记录了执行期间 GPU 显存的使用历史。你可以在这里可视化这段历史：[https://pytorch.org/memory_viz](https://pytorch.org/memory_viz)。

把你的 `profile.pkl` 文件拖进去，就能看到这样一张图：

我们把这张图拆成几个关键部分：

- **模型创建（Model Creation）**：显存增加了 2 GB，正好对应模型的尺寸：10,000×50,000 个权重 + 50,000 个偏置，float32（4 字节）⟹ (5×10⁸)×4 字节 = 2 GB。10{,}000 \times 50{,}000 \text{ weights} + 50{,}000 \text{ biases in } \texttt{float32 }\text{(4 bytes)} \implies (5 \times 10^8) \times 4 \, \text{bytes} = 2 \, \text{GB}. 10,000×50,000 weights+50,000 biases in float32 (4 bytes)⟹(5×108)×4bytes=2GB. 这部分显存（蓝色）在整个执行期间一直存在。
- **输入张量创建（第 1 轮循环）**：显存增加 200 MB，对应输入张量的大小：5,000×10,000 个元素，float32（4 字节）⟹ (5×10⁷)×4 字节 = 0.2 GB。5{,}000 \times 10{,}000 \text{ elements in } \texttt{float32 }\text{(4 bytes)} \implies (5 \times 10^7) \times 4 \, \text{bytes} = 0.2 \, \text{GB}.5,000×10,000 elements in float32 (4 bytes)⟹(5×107)×4bytes=0.2GB.
- **前向传播（第 1 轮循环）**：输出张量让显存增加 1 GB：5,000×50,000 个元素，float32（4 字节）⟹ (25×10⁷)×4 字节 = 1 GB。5{,}000 \times 50{,}000 \text{ elements in } \texttt{float32 }\text{(4 bytes)} \implies (25 \times 10^7) \times 4 \, \text{bytes} = 1 \, \text{GB}.5,000×50,000 elements in float32 (4 bytes)⟹(25×107)×4bytes=1GB.
- **输入张量创建（第 2 轮循环）**：新的输入张量又让显存增加 200 MB。这时你可能会以为第 2 步的那个输入张量该被释放了，但并没有：模型保留了它的激活值（activation），所以即使张量不再赋值给变量 `inputs`，它仍然被模型前向计算所引用。模型之所以保留激活值，是因为神经网络的反向传播过程需要这些张量。可以试试加上 `torch.no_grad()` 看看区别。
- **前向传播（第 2 轮循环）**：新的输出张量让显存增加 1 GB，与第 3 步同理。
- **释放第 1 轮循环的激活值**：第 2 轮循环的前向传播结束后，第 1 轮的输入张量（第 2 步）就可以被释放了。持有第一个输入张量的模型激活值，被第 2 轮的输入覆盖了。第 2 轮循环完成后，第一个张量不再被引用，其显存随之释放。
- **更新 `output`**：第 3 步的输出张量被重新赋值给变量 `output`，原来的张量不再被引用、被删除，显存得到释放。
- **输入张量创建（第 3 轮循环）**：同第 4 步。
- **前向传播（第 3 轮循环）**：同第 5 步。
- **释放第 2 轮循环的激活值**：第 4 步的输入张量被释放。
- **再次更新 `output`**：第 5 步的输出张量被重新赋值给变量 `output`，释放了之前的张量。
- **代码执行结束**：所有显存全部释放。

## 📊 可视化训练过程中的显存

前面的例子是简化过的。真实场景里，我们训练的往往不是单个线性层，而是复杂的模型；而且刚才那个例子也没有包含训练过程。接下来我们看看一个真实大语言模型（LLM）的完整训练循环中 GPU 显存的表现。

```
import torch
from transformers import AutoModelForCausalLM

# Start recording memory snapshot history
torch.cuda.memory._record_memory_history(max_entries=100000)

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-1.5B").to("cuda")
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)

for _ in range(3):
    inputs = torch.randint(0, 100, (16, 256), device="cuda")  # Dummy input
    loss = torch.mean(model(inputs).logits)  # Dummy loss
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()

# Dump memory snapshot history to a file and stop recording
torch.cuda.memory._dump_snapshot("profile.pkl")
torch.cuda.memory._record_memory_history(enabled=None)
```

**💡 提示：** 做性能分析时尽量限制步数。每一次 GPU 显存事件都会被记录，文件可能变得非常大。例如上面的代码就会生成一个 8 MB 的文件。

这是这个例子的显存剖面图：

这张图比前面的例子复杂，但依然可以逐步拆解。注意那三个尖峰，分别对应训练循环的一次迭代。我们把图简化一下，方便解读：

- **模型初始化**（`model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-1.5B").to("cuda")`）：
第一步是把模型加载到 GPU 上。模型参数（蓝色）占用显存，并一直保留到训练结束。
- **前向传播**（`model(inputs)`）：
前向传播期间，各层的中间输出（激活值）被计算出来并存储到显存中，供反向传播使用。这些激活值用橙色表示，逐层增长直到最后一层。损失在橙色区域的峰值处计算。
- **反向传播**（`loss.backward()`）：
这一阶段计算并存储梯度（黄色）。同时不再需要的激活值被丢弃，橙色区域随之收缩。黄色区域表示梯度计算占用的显存。
- **优化器步进**（`optimizer.step()`）：
用梯度更新模型参数。首先优化器自身要初始化（绿色区域），这个初始化只做一次。之后优化器用梯度更新模型参数；更新时优化器会临时存储一些中间值（红色区域）。更新完成后，梯度（黄色）和优化器中间值（红色）都被丢弃，显存得到释放。

到这里，一次训练迭代就结束了。剩下的迭代重复这个过程，于是图中出现了三个显存尖峰。

这类训练剖面图通常呈现一致的规律，因此可以拿它来估算给定模型和训练循环的 GPU 显存需求。

## 📐 估算显存需求

照上面的分析，估算 GPU 显存需求似乎很简单：所需总显存应对应显存剖面图中的最高峰值，而峰值出现在**前向传播**期间。这种情况下，显存需求为（蓝 + 绿 + 橙）：Model Parameters+Optimizer State+Activations \text{Model Parameters} + \text{Optimizer State} + \text{Activations} Model Parameters+Optimizer State+Activations

真有这么简单吗？其实有个坑。剖面图会随训练配置不同而变化。比如把 batch size 从 16 降到 2，图就变了：

```
- inputs = torch.randint(0, 100, (16, 256), device="cuda")  # Dummy input
+ inputs = torch.randint(0, 100, (2, 256), device="cuda")  # Dummy input
```

现在最高峰值出现在**优化器步进**期间，而不是前向传播。这种情况下，显存需求变成（蓝 + 绿 + 黄 + 红）：Model Parameters+Optimizer State+Gradients+Optimizer Intermediates \text{Model Parameters} + \text{Optimizer State} + \text{Gradients} + \text{Optimizer Intermediates} Model Parameters+Optimizer State+Gradients+Optimizer Intermediates

要把显存估算一般化，就必须把所有可能出现的峰值都算进去，不管它们出现在前向传播还是优化器步进阶段。Model Parameters+Optimizer State+max⁡(Gradients+Optimizer Intermediates,Activations) \text{Model Parameters} + \text{Optimizer State} + \max(\text{Gradients} + {\text{Optimizer Intermediates}, \text{Activations}}) Model Parameters+Optimizer State+max(Gradients+Optimizer Intermediates,Activations)

公式有了，接下来看看每个部分怎么估算。

### 模型参数

模型参数是最容易估算的。Model Memory=N×P \text{Model Memory} = N \times P Model Memory=N×P

其中：

- N N N 是参数数量。
- P P P 是精度（以字节计，例如 `float32` 为 4）。

例如，一个 15 亿参数、精度 4 字节的模型需要：

在上面这个例子里，模型占用：Model Memory=1.5×10⁹×4 字节=6 GB \text{Model Memory} = 1.5 \times 10^9 \times 4 \, \text{bytes} = 6 \, \text{GB} Model Memory=1.5×109×4bytes=6GB

### 优化器状态

优化器状态所需的显存取决于优化器类型和模型参数。比如 `AdamW` 优化器为每个参数存储两个动量（一阶和二阶）。因此优化器状态的大小为：Optimizer State Size=2×N×P \text{Optimizer State Size} = 2 \times N \times P Optimizer State Size=2×N×P

### 激活值

激活值所需的显存比较难估算，因为它包含前向传播计算出的所有中间值。要计算激活值显存，可以用 forward hook 测量各输出的大小：

```
import torch
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-1.5B").to("cuda")

activation_sizes = []

def forward_hook(module, input, output):
    """
    Hook to calculate activation size for each module.
    """
    if isinstance(output, torch.Tensor):
        activation_sizes.append(output.numel() * output.element_size())
    elif isinstance(output, (tuple, list)):
        for tensor in output:
            if isinstance(tensor, torch.Tensor):
                activation_sizes.append(tensor.numel() * tensor.element_size())

# Register hooks for each submodule
hooks = []
for submodule in model.modules():
    hooks.append(submodule.register_forward_hook(forward_hook))

# Perform a forward pass with a dummy input
dummy_input = torch.zeros((1, 1), dtype=torch.int64, device="cuda")
model.eval()  # No gradients needed for memory measurement
with torch.no_grad():
    model(dummy_input)

# Clean up hooks
for hook in hooks:
    hook.remove()

print(sum(activation_sizes))  # Output: 5065216
```

对 Qwen2.5-1.5B 模型来说，结果是**每个输入 token 5,065,216 个激活值**。要估算一个输入张量的总激活值显存，用：Activation Memory=A×B×L×P \text{Activation Memory} = A \times B \times L \times P Activation Memory=A×B×L×P

其中：

- A A A 是每个 token 的激活值数量。
- B B B 是 batch size。
- L L L 是序列长度。

不过直接这么测并不总是可行。最好能有一个不用跑模型就能估算激活值显存的启发式方法。而且凭直觉也知道，越大的模型激活值越多。这就引出一个问题：**模型参数数量和激活值数量之间有没有关系？**

没有直接关系，因为每个 token 的激活值数量取决于模型架构。但 LLM 的结构总体相似。分析不同模型后，我们发现参数数量和激活值数量大致呈线性关系：

基于这条线性关系，可以用启发式公式估算激活值：A=4.6894×10⁻⁴×N+1.8494×10⁶ A = 4.6894 \times 10^{-4} \times N + 1.8494 \times 10^{6} A=4.6894×10−4×N+1.8494×106

虽然只是近似，但它提供了一种不用为每个模型做复杂计算就能估算激活值显存的实用方法。

### 梯度

梯度好估算得多。梯度所需的显存与模型参数相同：Gradients Memory=N×P \text{Gradients Memory} = N \times P Gradients Memory=N×P

### 优化器中间值

更新模型参数时，优化器会存储中间值。这些值所需显存与模型参数相同：Optimizer Intermediates Memory=N×P \text{Optimizer Intermediates Memory} = N \times P Optimizer Intermediates Memory=N×P

### 总显存

总结一下，训练一个模型所需的总显存为：Total Memory=Model Memory+Optimizer State+max⁡(Gradients,Optimizer Intermediates,Activations) \text{Total Memory} = \text{Model Memory} + \text{Optimizer State} + \max(\text{Gradients}, \text{Optimizer Intermediates}, \text{Activations}) Total Memory=Model Memory+Optimizer State+max(Gradients,Optimizer Intermediates,Activations)

各组成部分如下：

- **模型显存（Model Memory）**：N×P N \times P N×P
- **优化器状态（Optimizer State）**：2×N×P 2 \times N \times P 2×N×P
- **梯度（Gradients）**：N×P N \times P N×P
- **优化器中间值（Optimizer Intermediates）**：N×P N \times P N×P
- **激活值（Activations）**：A×B×L×P A \times B \times L \times P A×B×L×P，其中 A 用启发式公式 A=4.6894×10⁻⁴×N+1.8494×10⁶ A = 4.6894 \times 10^{-4} \times N + 1.8494 \times 10^{6} A=4.6894×10−4×N+1.8494×106 估算
