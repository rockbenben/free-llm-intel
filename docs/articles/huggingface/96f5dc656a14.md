大型扩散 Transformer 能创造惊艳的图像（甚至视频、音频片段，如今还有文本），但以 BF16 精度加载一个现代文生图模型往往需要 20-30 GB VRAM，这让大多数消费级 GPU 望而却步。量化是解决这个问题的有力手段，Diffusers 已经集成了若干量化后端，如 bitsandbytes、GGUF、torchao 和 Quanto，我们在[《探索 Diffusers 中的量化后端》](https://huggingface.co/blog/diffusers-quantization)中做过介绍。

这些后端大多只量化权重（*weight-only*）。也就是说，它们以低精度存储权重，在计算时再反量化回高精度。这能大幅减少内存占用，但通常不会让推理更快，甚至可能增加一点延迟开销。

[SVDQuant](https://arxiv.org/abs/2411.05007)——广受欢迎的 [Nunchaku](https://github.com/nunchaku-tech/nunchaku) 推理引擎背后的量化方法——走了另一条路。它的主 Transformer 层以 4-bit 权重和激活（W4A4）运行，在减少内存的同时还加速了去噪循环。细节见下文，但在此之前，使用这类检查点需要一个独立的推理库。

如今配合当前版本的 Diffusers，加载 Nunchaku 检查点和调用 `from_pretrained()` 一样简单；得益于 [`kernels`](https://github.com/huggingface/kernels) 包，无需本地 CUDA 编译。此外，配套的 [diffuse-compressor](https://github.com/rootonchair/diffuse-compressor) 工具包让你可以自己量化新架构，并将其作为普通 Diffusers 仓库发布。

## Nunchaku Lite 快速上手

首先安装依赖。你需要较新版本的 Diffusers 和 Hugging Face 的 `kernels` 包：

```
pip install -U diffusers transformers accelerate kernels bitsandbytes
```

然后像加载任何其他 Diffusers 模型一样，加载一个预量化 pipeline：

```
import torch
from diffusers import ErnieImagePipeline

pipe = ErnieImagePipeline.from_pretrained(
    "lite-infer/ERNIE-Image-Turbo-nunchaku-lite-nvfp4_r32-bnb4-text-encoder",
    torch_dtype=torch.bfloat16,
).to("cuda")

image = pipe(
    prompt="A cinematic portrait of a red fox in a misty forest at sunrise, "
           "detailed fur, volumetric light",
    height=1024,
    width=1024,
    num_inference_steps=8,
    guidance_scale=1.0,
    generator=torch.Generator("cuda").manual_seed(42),
).images[0]
image.save("output.png")
```

不需要自定义 pipeline 类，不需要单独的推理引擎，也没有任何东西需要在本地编译。NVFP4 kernel 会在首次使用时通过 [Nunchaku Lite kernels 页面](https://huggingface.co/kernels/rootonchair/nunchaku-lite-kernels)从 Hub 下载。这个检查点把 Nunchaku NVFP4 Transformer 与 bitsandbytes NF4 文本编码器配对，在 RTX 5090 上生成一张 1024x1024 图像约需 1.7 秒，峰值内存约 12 GB，而 BF16 pipeline 约为 24 GB。关于 Nunchaku Lite 检查点格式的更多细节，请见 [Diffusers 官方文档](https://huggingface.co/docs/diffusers/main/en/quantization/nunchaku)。

> NVFP4 检查点需要 NVIDIA Blackwell GPU（RTX 50 系列、RTX PRO 6000、B200）。更早几代显卡请使用 INT4 变体。详见下文硬件支持表。

## 背景：SVDQuant 与 Nunchaku

**SVDQuant** 是 **Nunchaku**（其参考 CUDA 推理引擎）背后的量化方法。对扩散 Transformer 来说，标准 4-bit 量化很难做好，因为权重和激活中都存在大量离群值。SVDQuant 的做法是把激活离群值移入权重：用一个小的 16-bit 低秩分支表示每个权重矩阵中最难量化的部分，剩下的残差再量化为 4-bit。Nunchaku 通过为 4-bit 计算路径和低秩分支提供融合 kernel 来保证速度。

Nunchaku 把低秩下投影与量化 kernel 融合、把低秩上投影与 4-bit 计算 kernel 融合，消除了 16-bit 分支的内存访问开销。图片来自 SVDQuant 论文。

## Nunchaku Lite 介绍

原版 [Nunchaku 引擎](https://github.com/nunchaku-ai/nunchaku)的速度很大一部分来自[模型专用的融合执行路径](https://huggingface.co/blog/nunchaku-diffusers#quantizing-models-with-structural-rewrites)，例如融合 QKV 投影、融合 GELU/MLP kernel。这些优化与各架构的模块布局和检查点格式绑定，所以支持一个新模型家族通常需要模型专属的集成工作。

**Nunchaku Lite** 是 Diffusers 中的新集成路径。有了它，Diffusers 无需自定义 pipeline 或独立推理引擎就能加载 Nunchaku 风格检查点。其内部原理是：在加载检查点之前，Nunchaku Lite 把现成 Diffusers 模型中相关的 `nn.Linear` 模块替换为运行时的 SVDQ/AWQ 线性层。CUDA kernel 通过 `kernels` 包从 Hub 获取。一共用到两族 kernel：

- **`svdq_w4a4`**：4-bit 权重与激活，配合 SVDQuant 低秩校正。该层用于 Transformer 的注意力和 MLP 投影——几乎全部计算量都在这里，提供 INT4 和 NVFP4 两种变体。
- **`awq_w4a16`**：4-bit 权重、16-bit 激活，用于自适应归一化和调制投影，例如 FLUX 的 `adanorm_single` / `adanorm_zero` 或 Qwen-Image 的调制层。这些层是内存带宽受限且对精度敏感，AWQ 因此是保住精度同时省内存省空间的好选择。

代价是：没有架构专属的融合 kernel 和模块，Nunchaku Lite 达不到原版 Nunchaku 引擎的加速比。不过这个精简实现仍能带来约 **30% 的加速**，同时保持同等水平的 **VRAM 节省**。

## Diffusers 原生加载

如果你用过 Diffusers 里的 bitsandbytes 或 torchao，这套机制会很眼熟。Nunchaku Lite 模型仓库就是一个普通的 Diffusers 仓库。唯一特别的地方是 Transformer 的 `config.json` 里有一个 `quantization_config` 块：

```
"quantization_config": {
    "quant_method": "nunchaku_lite",
    "compute_dtype": "bfloat16",
    "svdq_w4a4": {
        "precision": "nvfp4",
        "group_size": 16,
        "rank": 32,
        "targets": [
            "layers.0.self_attention.to_q",
            "layers.0.self_attention.to_k",
            "..."
        ]
    },
    "awq_w4a16": {
        "precision": "int4",
        "group_size": 64,
        "targets": [
            "adaLN_modulation.1",
            "..."
        ]
    }
}
```

这份配置告诉 Diffusers 哪些模块被量化了、各用了什么方案，以及该实例化哪个 Nunchaku Lite 运行时层（`SVDQW4A4Linear` 或 `AWQW4A16Linear`）。

由于量化模型保持与稠密模型完全相同的模块结构，下游的一切（调度器、LoRA 加载钩子、offloading、`torch.compile`）看到的都是一个普通的 Diffusers 模型。

### 硬件支持

Nunchaku Lite 根据 GPU 代际和检查点精度使用不同的 kernel 变体：

| 方案 | 精度 | 支持的 GPU |
| --- | --- | --- |
| `svdq_w4a4` | `nvfp4` | Blackwell（RTX 50 系列、RTX PRO 6000、B200） |
| `svdq_w4a4` | `int4` | Turing / Ampere / Ada（RTX 30 & 40 系列、A100、L40S） |
| `awq_w4a16` | `int4` | Turing / Ampere / Ada（RTX 30 & 40 系列、A100、L40S） |

> Volta 和 Hopper GPU 目前不被 4-bit kernel 支持。量化器会在加载时校验 GPU 的 CUDA 计算能力，并给出清晰的报错，而不是产出错误结果。

## 更快、更省内存

Nunchaku Lite 可以与 Diffusers 的其他内存和速度优化组合使用。

**`torch.compile`。** 编译 Transformer 后端到端加速从 1.35x 提升到 1.8x：

```
pipe.transformer.compile(fullgraph=True)

# or compile_repeated_blocks() for faster compilation

pipe.transformer.compile_repeated_blocks(fullgraph=True)
```

**量化文本编码器。** Transformer 不是唯一占用大量内存的组件。T5 或 Qwen3 这类文本编码器自己就能占据数 GB。用 bitsandbytes NF4 进一步量化文本编码器，在我们的基准中可减少约 22% 的峰值 VRAM。

**Offloading。** 如果需要把 pipeline 塞进更小的 GPU，Diffusers 的 offloading 辅助函数（如 `enable_model_cpu_offload()` 和 `enable_sequential_cpu_offload()`）照常用。

## 基准测试

以下所有数字均在 NVIDIA RTX PRO 6000（Blackwell）上、1024x1024 分辨率、使用 [rootonchair/ERNIE-Image-Turbo-nunchaku-lite-int4-bnb4-text-encoder](https://huggingface.co/rootonchair/ERNIE-Image-Turbo-nunchaku-lite-int4-bnb4-text-encoder) 测得。

### 端到端延迟与内存

| 配置 | 完整 pipeline | 去噪循环 | 峰值 VRAM | 加速比 |
| --- | --- | --- | --- | --- |
| BF16 基线 | 3.00 s | 2.86 s | 31.1 GB | 1.0x |
| Nunchaku Lite NVFP4 | 2.27 s | 2.13 s | 20.6 GB | 1.35x |
| Nunchaku Lite NVFP4 + `torch.compile` | 1.68 s | 1.53 s | 20.6 GB | 1.8x |
| Nunchaku Lite NVFP4 + NF4 文本编码器 | 2.29 s | 2.13 s | 16.0 GB | 1.35x |

如上所示，Nunchaku 最多能将峰值 VRAM 降低 50%，同时把延迟改善约 30%。剩余的开销主要来自额外的 kernel 启动，`torch.compile` 可以缓解这一点，把完整 pipeline 压到 1.68 秒，即比 BF16 基线快 1.8 倍。

## 量化你自己的模型

Diffusers 对 Nunchaku Lite 的支持是架构无关的，[diffuse-compressor](https://github.com/rootonchair/diffuse-compressor) 工具包为 Diffusers 模型提供了端到端的 SVDQuant 工作流：校准、量化、打包、发布。

下面以量化 FLUX.2 Klein 4B 为例走一遍。涵盖主要步骤：检查模型、校准并量化 Transformer、把结果打包成 Diffusers pipeline，然后验证并推送到 Hub。[完整教程](https://github.com/rootonchair/diffuse-compressor/blob/main/docs/quantize_new_hf_model.md)对每个参数都有详细说明。

### 1. 检查将被量化的内容

通用扫描器会遍历模型并决定目标：重复 Transformer 块堆栈内的兼容线性层成为 SVDQ W4A4 目标，识别出的调制线性层成为 AWQ W4A16 目标，其余保持稠密。

```
python examples/text_to_image/quantize_hf.py black-forest-labs/FLUX.2-klein-4B \
  --precision int4 --rank 32 --inspect-config
```

量化之前务必先读这份报告。对 FLUX.2 Klein 4B，预期结果是 100 个 SVDQ 目标、3 个 AWQ 目标、6 个稠密外部线性层，无遗漏模式、无重名。

### 2. 运行量化

以下命令对 Transformer 执行 SVDQuant，并把量化后的检查点写入 `outputs/checkpoints/svdq-int4_r32-flux-2-klein-4b.safetensors`：

```
python examples/text_to_image/quantize_hf.py black-forest-labs/FLUX.2-klein-4B \
  --precision int4 \
  --output outputs/checkpoints/svdq-int4_r32-flux-2-klein-4b.safetensors
```

把 `--precision int4` 换成 `nvfp4` 即可构建 Blackwell 原生权重。

### 3. 打包成 Diffusers pipeline

转换器把量化后的 Transformer 与基础 pipeline 的其他组件组合起来，将精简的 `nunchaku_lite` 配置写入 `transformer/config.json`，并可选地把文本编码器转为 NF4：

```
python examples/convert_nunchaku_lite_diffusers.py \
  --checkpoint outputs/checkpoints/svdq-int4_r32-flux-2-klein-4b.safetensors \
  --model-id black-forest-labs/FLUX.2-klein-4B \
  --bnb4-text-encoder text_encoder \
  --compute-dtype bfloat16 \
  --output-dir outputs/diffusers/FLUX.2-klein-4B-nunchaku-lite-int4-bnb4-text-encoder
```

### 4. 加载、验证并推送到 Hub

```
import torch
from diffusers import DiffusionPipeline

pipe = DiffusionPipeline.from_pretrained(
    "outputs/diffusers/FLUX.2-klein-4B-nunchaku-lite-int4-bnb4-text-encoder",
    device_map="cuda",
)
image = pipe(
    "A glass robot in a greenhouse, cinematic lighting",
    num_inference_steps=4, guidance_scale=1.0,
    generator=torch.Generator("cuda").manual_seed(12345),
).images[0]
```

输出看起来没问题后，运行 `pipe.push_to_hub("your-name/your-model-nunchaku-lite-int4")`。其他用户就能用上面展示的同一种 `from_pretrained()` 模式加载它。

### 量化带有结构性重写的模型

注意，通用路径假设该架构可以在不做结构性重写的情况下量化。为了进一步提速，原版 Nunchaku 引擎会把成组的 Diffusers 层重写为融合模块。通用路径无法自行推断这些改动，例如把独立的 Q、K、V 投影合并为一个模块，或把一个融合投影拆分到多个模块。

FLUX.1-dev 的 QKV 投影就是一个具体例子。[Diffusers 定义了三个独立模块](https://github.com/huggingface/diffusers/blob/main/src/diffusers/models/transformers/transformer_flux.py#L313-L329)：

```
self.to_q = torch.nn.Linear(query_dim, self.inner_dim, bias=bias)
self.to_k = torch.nn.Linear(query_dim, self.inner_dim, bias=bias)
self.to_v = torch.nn.Linear(query_dim, self.inner_dim, bias=bias)
```

[Nunchaku 的 FLUX 模块把这些层合并](https://github.com/nunchaku-ai/nunchaku/blob/main/nunchaku/models/transformers/transformer_flux_v2.py#L63-L79)为一个量化的 `to_qkv` 模块：

```
to_qkv = fuse_linears([other.to_q, other.to_k, other.to_v])
self.to_qkv = SVDQW4A4Linear.from_linear(to_qkv, **kwargs)
```

之所以需要这种分组模块，是因为 Nunchaku 的融合算子会把 QKV 投影、Q/K 归一化和旋转位置编码（rotary embeddings）一起消化掉。相比之下，[Diffusers 默认路径](https://github.com/huggingface/diffusers/blob/main/src/diffusers/models/transformers/transformer_flux.py#L45-L116)是分开执行的：

```
query = attn.to_q(hidden_states)
key = attn.to_k(hidden_states)
value = attn.to_v(hidden_states)

query = query.unflatten(-1, (attn.heads, -1))
key = key.unflatten(-1, (attn.heads, -1))
value = value.unflatten(-1, (attn.heads, -1))

query = attn.norm_q(query)
key = attn.norm_k(key)

if image_rotary_emb is not None:
    query = apply_rotary_emb(query, image_rotary_emb, sequence_dim=1)
    key = apply_rotary_emb(key, image_rotary_emb, sequence_dim=1)
```

[Nunchaku 路径](https://github.com/nunchaku-ai/nunchaku/blob/main/nunchaku/models/attention_processors/flux.py#L69-L93)把分组投影、归一化模块和旋转位置编码一次性交给一个融合算子：

```
qkv = fused_qkv_norm_rottary(
    hidden_states, attn.to_qkv, attn.norm_q, attn.norm_k, image_rotary_emb
)
```

这正是通用路径无法推断的结构性重写。Diffusers 有三个分别带 `to_q`、`to_k`、`to_v` 参数前缀的目标模块，而 Nunchaku 只有一个归在 `to_qkv` 下的分组模块。必须由模型专属的目标配置或适配器来声明：Q、K、V 参数应按此顺序沿输出维度拼接并加载进 `to_qkv`。

这类结构性重写在量化时由模型专属的目标配置描述，在加载检查点时由一个小型运行时适配器处理。[FLUX.2 Klein 4B 量化脚本](https://github.com/rootonchair/diffuse-compressor/blob/main/examples/text_to_image/quantize_flux2_klein_4b.py)给出了一个生成结构性重写检查点的目标配置实例，而 [rootonchair/nunchaku-lite](https://github.com/rootonchair/nunchaku-lite) 提供了加载分组 QKV 张量、拆分融合投影及其他融合操作所需的运行时适配器。完整工作流可查看 [Adding A New Model](https://github.com/rootonchair/diffuse-compressor/blob/main/docs/adding_new_model.md) 指南。

## 结论

Nunchaku 的 SVDQuant kernel 是让扩散 Transformer 在消费级硬件上高效运行的最有效手段之一，如今已在 Diffusers 中获得原生支持。预量化检查点直接用 `from_pretrained()` 加载，而 diffuse-compressor 工具包让量化新架构不必再等待引擎支持。通过同时量化权重和激活，W4A4 路径在降低内存占用的同时改善了去噪延迟，并把图像质量保持在接近 BF16 原图的水平。
