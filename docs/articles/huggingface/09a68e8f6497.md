# 欢迎 aMUSEd：高效的文生图生成

[![amused_grid](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/amused/main_image_grid.jpeg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/amused/main_image_grid.jpeg)

我们很高兴发布一款高效的非扩散文生图模型 **aMUSEd**。它之所以叫这个名字，因为它是对 [Google 的 MUSE](https://muse-model.github.io/) 的开放复现。aMUSEd 的生成质量并非顶尖，我们以宽松许可证发布的是一个研究预览版。

与常用的潜在扩散方法（[Rombach et al. (2022)](https://arxiv.org/abs/2112.10752)）不同，aMUSEd 采用掩码图像建模（Masked Image Model，MIM）方法。正如 [Chang et al. (2023)](https://arxiv.org/abs/2301.00704) 所指出的，这不仅需要更少的推理步数，还提升了模型的可解释性。

与 MUSE 一样，aMUSEd 展现出仅凭单张图像进行风格迁移的出色能力，[Sohn et al. (2023)](https://arxiv.org/abs/2306.00983) 对这一特性做了深入探讨。这一点有可能为个性化和特定风格的图像生成开辟新路径。

在这篇博客中，我们会介绍 aMUSEd 的内部机制，演示如何把它用于不同任务（包括文生图），并展示如何微调它。过程中我们会给出所有与 aMUSEd 相关的重要资源，包括其训练代码。开始吧 🚀

## 它是怎么工作的？

aMUSEd 基于***掩码图像建模（Masked Image Modeling）***。对于社区来说，这是一个很有吸引力的用例：把语言建模中已被验证有效的组件放到图像生成的语境下来探索。

下图给出了 aMUSEd 工作流程的图示概览。

[![amused_architecture](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/amused/amused_architecture.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/amused/amused_architecture.png)

***训练***期间：

- 输入图像用 VQGAN 分词，得到图像 token
- 图像 token 按余弦掩码调度进行掩蔽
- 被掩蔽的 token（以通过 [CLIP-L/14 文本编码器](https://huggingface.co/openai/clip-vit-large-patch14)计算的 prompt embedding 为条件）送入 [U-ViT](https://arxiv.org/abs/2301.11093) 模型，由它预测被掩蔽的 patch

***推理***期间：

- 输入 prompt 用 [CLIP-L/14 文本编码器](https://huggingface.co/openai/clip-vit-large-patch14)做 embedding。
- 迭代直到达到 `N` 步：从随机掩蔽的 token 出发，连同 prompt embedding 一起送入 U-ViT 模型预测被掩蔽的 token，依据 `N` 和掩码调度只保留置信度最高的一定比例预测，其余重新掩蔽后再交给 U-ViT 模型
- 将最终输出送入 VQGAN 解码器，得到最终图像

如开头所述，aMUSEd 与 MUSE 有大量相同之处，但也有几处值得注意的差异：

- aMUSEd 不采用两阶段方式来预测最终的被掩蔽 patch。
- 文本条件不用 T5，而是用 CLIP L/14 计算文本 embedding。
- 参照 Stable Diffusion XL（SDXL），额外的条件信息（如图像尺寸和裁剪）也被传给 U-ViT，这被称为"micro-conditioning"。

想深入了解 aMUSEd，建议阅读[技术报告](https://huggingface.co/papers/2401.01808)。

## 在 🧨 diffusers 中使用 aMUSEd

aMUSEd 已完整集成进 🧨 diffusers。要使用它，先安装库：

```
pip install -U diffusers accelerate transformers -q
```

从文生图开始：

```
import torch
from diffusers import AmusedPipeline

pipe = AmusedPipeline.from_pretrained(
    "amused/amused-512", variant="fp16", torch_dtype=torch.float16
)
pipe = pipe.to("cuda")

prompt = "A mecha robot in a favela in expressionist style"
negative_prompt = "low quality, ugly"

image = pipe(prompt, negative_prompt=negative_prompt, generator=torch.manual_seed(0)).images[0]
image
```

[![text2image_512.png](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/amused/text2image_512.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/amused/text2image_512.png)

我们可以在固定随机种子下研究 `num_inference_steps` 对图像质量的影响：

```
from diffusers.utils import make_image_grid 

images = []
for step in [5, 10, 15]:
    image = pipe(prompt, negative_prompt=negative_prompt, num_inference_steps=step, generator=torch.manual_seed(0)).images[0]
    images.append(image)

grid = make_image_grid(images, rows=1, cols=3)
grid
```

[![image_grid_t2i_amused.png](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/amused/image_grid_t2i_amused.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/amused/image_grid_t2i_amused.png)

除模型名称外，二元组的格式为：(timesteps, resolution)。基准测试在 A100 上进行。更多细节见技术报告。

作为其预训练目标的直接副产品，aMUSEd 可以零样本做图像修复（inpainting），这一点与 SDXL 等其他模型不同。

```
import torch
from diffusers import AmusedInpaintPipeline
from diffusers.utils import load_image
from PIL import Image

pipe = AmusedInpaintPipeline.from_pretrained(
    "amused/amused-512", variant="fp16", torch_dtype=torch.float16
)
pipe = pipe.to("cuda")

prompt = "a man with glasses"
input_image = (
    load_image(
        "https://huggingface.co/amused/amused-512/resolve/main/assets/inpainting_256_orig.png"
    )
    .resize((512, 512))
    .convert("RGB")
)
mask = (
    load_image(
        "https://huggingface.co/amused/amused-512/resolve/main/assets/inpainting_256_mask.png"
    )
    .resize((512, 512))
    .convert("L")
)   

image = pipe(prompt, input_image, mask, generator=torch.manual_seed(3)).images[0]
```

[![inpainting_grid_amused.png](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/amused/inpainting_grid_amused.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/amused/inpainting_grid_amused.png)

aMUSEd 是 `diffusers` 中第一个非扩散系统。它预测被掩蔽 patch 的迭代调度方式使它成为 `diffusers` 的合适候选。我们很期待看到社区如何发挥它的价值。

我们鼓励你阅读技术报告，了解我们用 aMUSEd 探索的全部任务。

## 微调 aMUSEd

我们提供了一个简单的[训练脚本](https://github.com/huggingface/diffusers/blob/main/examples/amused/train_amused.py)，用于在自定义数据集上微调 aMUSEd。使用 8-bit Adam 优化器和 float16 精度时，不到 11GB 的 GPU 显存即可完成微调。配合 LoRA，内存需求可进一步降到仅 7GB。

用 aMUSEd 生成的像素风角色示例 prompt：a pixel art character with square red glasses

aMUSEd 采用 OpenRAIL 许可证，因此商业上可以自由改编。微调的更多细节参见[该目录](https://github.com/huggingface/diffusers/tree/main/examples/amused)。

## 局限性

就图像质量而言，aMUSEd 并不是最先进的图像生成模型。我们发布 aMUSEd 是希望鼓励社区探索 MIM 这类非扩散框架在图像生成上的应用。我们相信 MIM 的潜力尚未被充分挖掘，考虑到它的这些优势：

- 推理效率高
- 体积更小，可支持端侧应用
- 任务迁移无需昂贵的微调
- 可继承语言建模领域成熟组件的优势

*（注意，MUSE 的原始工作是闭源的）*

关于 aMUSEd 定量评估的详细描述，请参阅技术报告。

我们希望社区觉得这些资源有用，并有动力把面向图像生成的 MIM 水准推向更高。
