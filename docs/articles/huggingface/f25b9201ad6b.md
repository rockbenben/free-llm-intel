## TL;DR

**[NVIDIA Cosmos](https://www.nvidia.com/en-us/ai/cosmos/)** 世界模型开发平台在其 [Cosmos 3](https://huggingface.co/collections/nvidia/cosmos3) 模型家族中新增了四个开放权重 checkpoint，用于生成交互式世界模拟以及多传感器、多视角的驾驶场景：

- 🌦️ **[Cosmos3-Nano-Transfer-Auto](https://huggingface.co/nvidia/Cosmos3-Nano-Transfer-Auto)**：生成带有不同天气、光照和时段的多种多视角驾驶数据。
- 🚗 **[Cosmos3-Nano-Sim-Auto](https://huggingface.co/nvidia/Cosmos3-Nano-Sim-Auto)**：为驾驶模拟流式输出同步的相机与 LiDAR 观测。
- 🎨 **[Cosmos3-Nano-Sim-Transfer](https://huggingface.co/nvidia/Cosmos3-Nano-Sim-Transfer)**：把模拟器控制量和一段文本 prompt 变成照片级真实的视频。
- 🤖 **[Cosmos3-Nano-Sim-Bimanual](https://huggingface.co/nvidia/Cosmos3-Nano-Sim-Bimanual)**：根据机器人或相机的动作预测视频。

这四个模型都是 Cosmos 3 Nano 经过 post-training 得到的示例，各有 16B 可训练参数。模型采用 OpenMDW1.1，按其条款允许商业与非商业用途。

[下载 checkpoint](https://huggingface.co/collections/nvidia/cosmos3-examples) · [阅读技术报告](https://research.nvidia.com/labs/cosmos-lab/cosmos-simulation/technical-report.pdf) . [观看演示](https://research.nvidia.com/labs/cosmos-lab/cosmos-simulation/)

## 为什么需要这些 checkpoint？

🦾 机器人需要能够在这种问题上一路给出答案的环境，而场景与视角都在不断变化。这些 checkpoint 提供了互补的构建路径：Sim-Bimanual 从动作预测视觉后果，而 Sim-Transfer 把物理模拟器的控制量变成生成的观测。

🚦 对自动驾驶来说，外观与几何必须彼此吻合。同步的相机与 LiDAR 生成把视觉观测和 3D 感知连接起来。场景与红绿灯控制量让研究者能够改变道路布局和信号状态，进而研究驾驶 policy 如何响应。

🔄 每一条观测都能塑造下一个动作。流式生成把视频预测与正在持续的交互连接起来，为世界模型研究者提供了一条探索动作与观测如何一同展开的路径。

🌐 供他人继续构建的开放基座。NVIDIA 的愿景是帮助研究者和开发者创造更丰富、响应更灵敏的模拟世界。开放权重与 post-training 配方为模型适配、方法比较和贡献改进提供了共同的起点。这些问题仍然很难：接下来的工作是度量这些模型在哪些地方能忠实地支撑 policy 学习与评测、理解它们的局限，并在不足的地方加以改进。

### 用 Cosmos3-Nano 构建自动驾驶车辆世界

## 🌦️Transfer-Auto：驾驶场景 → 多传感器数据

**[Cosmos3-Nano-Transfer-Auto](https://huggingface.co/nvidia/Cosmos3-Nano-Transfer-Auto)** 是一个用于离线合成驾驶数据生成的双向模型。它能生成最多 11 个相机视角（含鱼眼）的同步视频，并支持 RGB–LiDAR 联合生成。按相机给定的 World Scenario Map（WSM）控制量用于指定场景结构与交通运动，而文本 prompt 用于引导外观。

开发者可以通过改变环境条件来扩大训练与评测的覆盖范围，并可选地用初始 RGB 图像来锚定场景外观。LiDAR 联合生成额外使用与相机控制量对齐的 HD-map range map 控制量。Transfer-Auto 也是把 Cosmos 适配到你自己的传感器套件与驾驶领域的基础。先在你的数据上对它做 post-training，以适配你的相机布局、LiDAR 配置和目标环境。适配后的模型可以直接用于离线数据生成，也可以再进行因果训练与少步蒸馏，得到快速流式模拟——这正是创建 Cosmos3-Nano-Sim-Auto 时走的开发路径。

## 🚗Sim-Auto：驾驶控制量 → 流式观测

**[Cosmos3-Nano-Sim-Auto](https://huggingface.co/nvidia/Cosmos3-Nano-Sim-Auto)** 是 Transfer-Auto 经因果蒸馏得到的流式变体。它只需几个去噪步骤就能生成一段接一段的小块同步相机视频与 LiDAR，并利用已生成的历史与更新后的驾驶控制量，支撑快速流式输出和长时长的交互式 rollout。

请提供按相机的 caption 与同步的 WSM 控制量，并可选地加入初始 RGB 图像。若要生成 LiDAR，还要提供与相机控制量对齐的 HD-Map range 控制量。蒸馏后的模型用其滚动历史连续生成一个个数据块。闭环交互需要一个模拟运行时和 WSM 渲染器，根据驾驶输入更新这些控制量。若面向新的传感器套件或领域，先适配 Transfer-Auto，再把它蒸馏成 Sim-Auto。

## 🎨 Sim-Transfer：模拟器控制量 → RGB

你的模拟器负责计算运动、接触和物理状态。Sim-Transfer 使用它的空间控制量和一段文本 prompt，渲染出 policy 可以直接消费的颜色观测。

动作 → 模拟器更新 → 空间控制量 → 生成的 RGB → 下一个 policy 动作

- **Depth：** 与相机的相对距离。
- **Segmentation：** 区域与物体边界。
- **Edges：** 场景轮廓。
- **Blur：** 粗略的外观与布局。

文本负责引导外观；物理与 ground-truth 状态仍留在模拟器一侧。

## 流式生成是怎么工作的

Cosmos 3 的 Mixture-of-Transformers 主干通过 attention 把彼此独立的文本处理网络与视觉生成网络连接起来。生成器根据 prompt、可用的控制量以及已生成的历史来预测每一个短片段。

控制量 + 历史 → 生成数据块 → 解码图像 → 更新历史

去噪把带噪声的压缩视频表示细化成一个片段。时间因果 attention 让它能读取可用的历史与控制量，同时屏蔽未来的目标观测。key/value 缓存会为下一次预测保留 attention 信息。

模型在称为 latents 的压缩视频表示上工作。初始图像之后，每个 latent 时间步代表四帧 RGB。Transfer 每个数据块预测一步；报告中优化后的 Bimanual 配置预测两步。更小的数据块能让新的控制量更频繁地影响生成。

### 四阶段训练配方

- **Stage 0** — 双向适配：从完整录制的片段学习该领域及其控制量到视频的关系。
- **Stage 1** — Teacher forcing：根据更早录制的观测与可用的控制量预测每个数据块，同时把干净的答案和未来的目标掩码掉。
- **Stage 2** — 一致性蒸馏：用一个冻结的 teacher 训练 student，让它用四个去噪步骤生成每个数据块。
- **Stage 3** — Self-forcing：在 student 自己生成的历史之上训练。一个冻结的 teacher 与一个辅助 score 模型提供分布匹配的信号。

为什么最后一个阶段很关键：一个略微预测偏了的物体此后会变成后续帧的上下文，误差因此可能不断累积。Self-forcing 让训练直面这种自己生成的历史。蒸馏与缓存降低了产出每一段观测的成本。

## 🛠️ 用你自己的数据做适配

post-training 配方从 Cosmos3-Nano 或兼容的基础权重出发，覆盖全部四个阶段。请保留完整的训练 checkpoint 以便续训；导出的推理权重会省掉优化器及其他训练状态。

- [Transfer-auto](https://github.com/NVIDIA/cosmos-framework/tree/main/.agents/skills/cosmos3-nano-transfer-auto/post-training)：在你的驾驶数据上做 post-training，以适配你的传感器套件与领域，并生成离线合成数据。
- [Sim-auto](https://github.com/NVIDIA/cosmos-framework/tree/main/.agents/skills/cosmos3-nano-sim-auto/post-training)：对已适配的 Transfer-Auto 模型施加因果训练与蒸馏，得到快速流式模拟。
- [Sim-Transfer ](https://github.com/NVIDIA/cosmos-framework/blob/main/.agents/skills/cosmos3-nano-sim-transfer/post-training/SKILL.md)：为你的环境对 checkpoint 做 post-training，包含本地数据准备、各阶段配置与续训。
- [Sim-Bimanual](https://github.com/NVIDIA/cosmos-framework/blob/main/.agents/skills/cosmos3-nano-sim-bimanual/post-training/SKILL.md)：为你的 embodiment 做 post-training，包含数据校验、各阶段配置、checkpoint 交接与导出。

把 skill 和数据集位置交给你的 coding agent。按顺序做完环境检查、校验一个样本，并在跑更长的任务之前先测试训练与重启。用留出的 episode 评估质量：一次成功的短程运行只验证了能执行，并不说明已收敛。
