## 什么是 Hugging Face LLM 推理 DLC？

Hugging Face LLM DLC 是一个全新特制的推理容器（Inference Container），用于在安全托管的环境中轻松部署 LLM。该 DLC 由 [Text Generation Inference (TGI)](https://github.com/huggingface/text-generation-inference) 驱动——这是一套开源、专为部署和服务大语言模型而打造的方案。TGI 用张量并行（Tensor Parallelism）和动态批处理（dynamic batching）为最流行的开源 LLM 提供高性能文本生成，包括 StarCoder、BLOOM、GPT-NeoX、Llama 和 T5。Text Generation Inference 已被 IBM、Grammarly 等客户使用，Open-Assistant 计划也在使用它。TGI 为所有受支持的模型架构实现了优化，包括：

- 张量并行与自定义 cuda 内核
- 在最流行的架构上用 [flash-attention](https://github.com/HazyResearch/flash-attention) 优化的推理 transformer 代码
- 用 [bitsandbytes](https://github.com/TimDettmers/bitsandbytes) 做量化
- [对传入请求做连续批处理](https://github.com/huggingface/text-generation-inference/tree/main/router)，提升整体吞吐
- 用 [safetensors](https://github.com/huggingface/safetensors) 加速权重加载（启动时间）
- Logits 重塑（温度缩放、topk、重复惩罚……）
- 基于 [A Watermark for Large Language Models](https://arxiv.org/abs/2301.10226) 的水印
- 停止序列（Stop sequences）、对数概率
- 用 Server-Sent Events (SSE) 实现 token 流式输出

当前官方支持的模型架构有：

- [BLOOM](https://huggingface.co/bigscience/bloom) / [BLOOMZ](https://huggingface.co/bigscience/bloomz)
- [MT0-XXL](https://huggingface.co/bigscience/mt0-xxl)
- [Galactica](https://huggingface.co/facebook/galactica-120b)
- [SantaCoder](https://huggingface.co/bigcode/santacoder)
- [GPT-Neox 20B](https://huggingface.co/EleutherAI/gpt-neox-20b)（joi、pythia、lotus、rosey、chip、RedPajama、open assistant）
- [FLAN-T5-XXL](https://huggingface.co/google/flan-t5-xxl)（T5-11B）
- [Llama](https://github.com/facebookresearch/llama)（vicuna、alpaca、koala）
- [Starcoder](https://huggingface.co/bigcode/starcoder) / [SantaCoder](https://huggingface.co/bigcode/santacoder)
- [Falcon 7B](https://huggingface.co/tiiuae/falcon-7b) / [Falcon 40B](https://huggingface.co/tiiuae/falcon-40b)

借助 Amazon SageMaker 上新的 Hugging Face LLM 推理 DLC，AWS 客户可以使用与 [HuggingChat](https://hf.co/chat)、[OpenAssistant](https://open-assistant.io/) 以及 Hugging Face Hub 上 LLM Inference API 这些高并发、低延迟 LLM 体验同源的底层技术。

开始动手吧！

## 1. 搭建开发环境

我们将使用 `sagemaker` Python SDK 把 BLOOM 部署到 Amazon SageMaker。前提是已配置好 AWS 账号并安装了 `sagemaker` Python SDK。

```
!pip install "sagemaker==2.175.0" --upgrade --quiet
```

如果你要在本地环境使用 Sagemaker，需要能访问一个具备 Sagemaker 所需权限的 IAM Role。可以[在这里](https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-roles.html)了解更多。

```
import sagemaker
import boto3
sess = sagemaker.Session()
# sagemaker session bucket -> used for uploading data, models and logs
# sagemaker will automatically create this bucket if it not exists
sagemaker_session_bucket=None
if sagemaker_session_bucket is None and sess is not None:
    # set to default bucket if a bucket name is not given
    sagemaker_session_bucket = sess.default_bucket()

try:
    role = sagemaker.get_execution_role()
except ValueError:
    iam = boto3.client('iam')
    role = iam.get_role(RoleName='sagemaker_execution_role')['Role']['Arn']

sess = sagemaker.Session(default_bucket=sagemaker_session_bucket)

print(f"sagemaker role arn: {role}")
print(f"sagemaker session region: {sess.boto_region_name}")
```

## 2. 获取新的 Hugging Face LLM DLC

与部署普通 Hugging Face 模型不同，我们需要先获取容器 URI，并通过指向该镜像的 `image_uri` 传给 `HuggingFaceModel` 类。要在 Amazon SageMaker 中获取新的 Hugging Face LLM DLC，可以使用 `sagemaker` SDK 提供的 `get_huggingface_llm_image_uri` 方法。该方法允许我们根据指定的 `backend`、`session`、`region` 和 `version` 获取所需 Hugging Face LLM DLC 的 URI。可用版本见[这里](https://github.com/aws/deep-learning-containers/blob/master/available_images.md#huggingface-text-generation-inference-containers)。

```
from sagemaker.huggingface import get_huggingface_llm_image_uri

# retrieve the llm image uri
llm_image = get_huggingface_llm_image_uri(
  "huggingface",
  version="1.0.3"
)

# print ecr image uri
print(f"llm image uri: {llm_image}")
```

## 3. 把 Open Assistant 12B 部署到 Amazon SageMaker

*注意：Amazon SageMaker 的配额因账号而异。如果收到超出配额的报错，可以在 [Service Quotas 控制台](https://console.aws.amazon.com/servicequotas/home/services/sagemaker/quotas)提升配额。*

要把 [Open Assistant 模型](https://huggingface.co/blog/OpenAssistant/pythia-12b-sft-v8-7k-steps)部署到 Amazon SageMaker，我们创建一个 `HuggingFaceModel` 类，并定义端点配置，包括 `hf_model_id`、`instance_type` 等。我们使用 `g5.12xlarge` 实例类型，它配 4 张 NVIDIA A10G GPU、96GB 显存。

*注意：我们也可以为优化成本改用 `g5.2xlarge` 实例并开启 int-8 量化。*

```
import json
from sagemaker.huggingface import HuggingFaceModel

# sagemaker config
instance_type = "ml.g5.12xlarge"
number_of_gpu = 4
health_check_timeout = 300

# Define Model and Endpoint configuration parameter
config = {
  'HF_MODEL_ID': "OpenAssistant/pythia-12b-sft-v8-7k-steps", # model_id from hf.co/models
  'SM_NUM_GPUS': json.dumps(number_of_gpu), # Number of GPU used per replica
  'MAX_INPUT_LENGTH': json.dumps(1024),  # Max length of input text
  'MAX_TOTAL_TOKENS': json.dumps(2048),  # Max length of the generation (including input text)
  # 'HF_MODEL_QUANTIZE': "bitsandbytes", # comment in to quantize
}

# create HuggingFaceModel with the image uri
llm_model = HuggingFaceModel(
  role=role,
  image_uri=llm_image,
  env=config
)
```

创建好 `HuggingFaceModel` 后，用 `deploy` 方法把它部署到 Amazon SageMaker。我们将以 `ml.g5.12xlarge` 实例类型部署，TGI 会自动把模型分布并分片到所有 GPU 上。

```
# Deploy model to an endpoint
# https://sagemaker.readthedocs.io/en/stable/api/inference/model.html#sagemaker.model.Model.deploy
llm = llm_model.deploy(
  initial_instance_count=1,
  instance_type=instance_type,
  # volume_size=400, # If using an instance with local SSD storage, volume_size must be None, e.g. p4 but not p3
  container_startup_health_check_timeout=health_check_timeout, # 10 minutes to be able to load the model
)
```

SageMaker 随后会创建端点并把模型部署上去，这可能需要 5-10 分钟。

## 4. 运行推理并与模型聊天

端点部署完成后，就可以用 `predictor` 的 `predict` 方法对它做推理。我们可以通过 payload 中 `parameters` 属性里的各种参数控制生成。目前 TGI 支持以下参数：

- `temperature`：控制模型随机性。值越小模型越确定，值越大越随机。默认值 1.0。
- `max_new_tokens`：最多生成的 token 数。默认值 20，最大值 512。
- `repetition_penalty`：控制重复的可能性，默认 `null`。
- `seed`：随机生成的种子，默认 `null`。
- `stop`：用于停止生成的 token 列表。一旦生成其中某个 token 即停止。
- `top_k`：top-k 过滤保留的最高概率词表 token 数量。默认 `null`，即关闭 top-k 过滤。
- `top_p`：核采样（nucleus sampling）保留的最高概率词表 token 的累计概率，默认 `null`。
- `do_sample`：是否使用采样，否则用贪心解码。默认 `false`。
- `best_of`：生成 best_of 条序列并返回 token logprobs 最高的那条，默认 `null`。
- `details`：是否返回生成的详细信息，默认 `false`。
- `return_full_text`：返回全文还是仅返回生成部分，默认 `false`。
- `truncate`：是否把输入截断到模型最大长度，默认 `true`。
- `typical_p`：典型概率（typical probability），默认 `null`。
- `watermark`：是否为生成添加水印，默认 `false`。

TGI 的 open api 规范见 [swagger 文档](https://huggingface.github.io/text-generation-inference/)。

`OpenAssistant/pythia-12b-sft-v8-7k-steps` 是一个对话式模型，我们可以用如下提示词与它聊天：

```
<|prompter|>[Instruction]<|endoftext|>
<|assistant|>
```

先试一下，问问夏天有什么酷点子：

```
chat = llm.predict({
    "inputs": """<|prompter|>What are some cool ideas to do in the summer?<|endoftext|><|assistant|>"""
})

print(chat[0]["generated_text"])
#     <|prompter|>What are some cool ideas to do in the summer?<|endoftext|><|assistant|>There are many fun and exciting things you can do in the summer. Here are some ideas:
```

下面演示如何在 payload 的 `parameters` 属性中使用生成参数。除了自定义 `temperature`、`top_p` 等，我们还在轮到 `bot` 之外的回合结束时停止生成。

```
# define payload
prompt="""<|prompter|>How can i stay more active during winter? Give me 3 tips.<|endoftext|><|assistant|>"""

# hyperparameters for llm
payload = {
  "inputs": prompt,
  "parameters": {
    "do_sample": True,
    "top_p": 0.7,
    "temperature": 0.7,
    "top_k": 50,
    "max_new_tokens": 256,
    "repetition_penalty": 1.03,
    "stop": ["<|endoftext|>"]
  }
}

# send request to endpoint
response = llm.predict(payload)

# print(response[0]["generated_text"][:-len("<human>:")])
print(response[0]["generated_text"])
```

## 5. 创建由 Amazon SageMaker 支撑的 Gradio 聊天机器人

我们还可以做一个 gradio 应用来与模型聊天。Gradio 是一个 Python 库，可以快速围绕机器学习模型创建可定制的 UI 组件。更多介绍见[这里](https://gradio.app/)。

```
!pip install gradio  --upgrade
```

```
import gradio as gr

# hyperparameters for llm
parameters = {
    "do_sample": True,
    "top_p": 0.7,
    "temperature": 0.7,
    "top_k": 50,
    "max_new_tokens": 256,
    "repetition_penalty": 1.03,
    "stop": ["<|endoftext|>"]
  }

with gr.Blocks() as demo:
    gr.Markdown("## Chat with Amazon SageMaker")
    with gr.Column():
        chatbot = gr.Chatbot()
        with gr.Row():
            with gr.Column():
                message = gr.Textbox(label="Chat Message Box", placeholder="Chat Message Box", show_label=False)
            with gr.Column():
                with gr.Row():
                    submit = gr.Button("Submit")
                    clear = gr.Button("Clear")

    def respond(message, chat_history):
        # convert chat history to prompt
        converted_chat_history = ""
        if len(chat_history) > 0:
          for c in chat_history:
            converted_chat_history += f"<|prompter|>{c[0]}<|endoftext|><|assistant|>{c[1]}<|endoftext|>"
        prompt = f"{converted_chat_history}<|prompter|>{message}<|endoftext|><|assistant|>"

        # send request to endpoint
        llm_response = llm.predict({"inputs": prompt, "parameters": parameters})

        # remove prompt from response
        parsed_response = llm_response[0]["generated_text"][len(prompt):]
        chat_history.append((message, parsed_response))
        return "", chat_history

    submit.click(respond, [message, chatbot], [message, chatbot], queue=False)
    clear.click(lambda: None, None, chatbot, queue=False)

demo.launch(share=True)
```

## 结论

新的 Hugging Face LLM 推理 DLC 让客户能够在 Amazon SageMaker 上轻松、安全地部署开源 LLM。好用的 API 和部署流程让客户可以基于 Open Assistant 这类最先进模型构建可扩展的 AI 聊天机器人和虚拟助手。总体而言，这个新 DLC 将赋能开发者和企业用上自然语言生成领域的最新进展。
