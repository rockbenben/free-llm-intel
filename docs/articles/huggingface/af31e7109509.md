# 在 24GB 消费级 GPU 上用 RLHF 微调 20B LLM

我们很高兴正式发布 `trl` 与 `peft` 的集成，让任何人通过强化学习微调大语言模型（LLM）都变得更触手可及！在这篇文章里，我们会解释为什么这是现有微调方案之外一个有竞争力的替代选择。

注意 `peft` 是一个通用工具，可应用于很多机器学习场景，但对 RLHF 它格外有意义——因为这种方法尤其吃显存！

想直接看代码，请移步 [TRL 文档页](https://huggingface.co/docs/trl/main/en/sentiment_tuning_peft)上的示例脚本。

## 引言

### LLM 与 RLHF

LLM 加上 RLHF（基于人类反馈的强化学习）似乎是构建 ChatGPT 这类强大 AI 系统的下一个标配路线。

用 RLHF 训练语言模型通常包括三步：

1. 在特定领域或指令与人类示范语料上微调一个预训练 LLM
2. 收集人类标注数据集并训练一个奖励模型
3. 用强化学习（如 PPO），结合奖励模型和数据集，进一步微调第 1 步的 LLM

| [![openai_diagram](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/openai-diagram.png)](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/openai-diagram.png) |
| --- |
| **ChatGPT 训练流程总览，从数据采集到 RL 部分。来源：[OpenAI's ChatGPT blogpost](https://openai.com/blog/chatgpt)** |

基座 LLM 的选择在这里非常关键。就当前而言，能对许多任务"开箱即用"的"最好"开源 LLM 是指令微调过的 LLM。代表模型有：[BLOOMZ](https://huggingface.co/bigscience/bloomz)、[Flan-T5](https://huggingface.co/google/flan-t5-xxl)、[Flan-UL2](https://huggingface.co/google/flan-ul2) 和 [OPT-IML](https://huggingface.co/facebook/opt-iml-max-30b)。这些模型的短板是体积：想要一个像样的模型，至少得玩 10B+ 规模的，全精度下光把模型装进一块 GPU（还不开始训练）就要多达 40GB 显存！

### TRL 是什么？

`trl` 库的目标是让 RL 这一步更简单、更灵活，任何人都能用自己的数据、自己的训练配置，通过 RL 微调语言模型。应用场景众多，比如你可以用这个算法微调模型来生成[正面影评](https://huggingface.co/docs/trl/sentiment_tuning)、做[受控生成](https://github.com/lvwerra/trl/blob/main/examples/sentiment/notebooks/gpt2-sentiment-control.ipynb)，或[降低模型毒性](https://huggingface.co/docs/trl/detoxifying_a_lm)。

使用 `trl`，你可以在分布式环境或单设备上运行最受欢迎的深度 RL 算法之一——[PPO](https://huggingface.co/deep-rl-course/unit8/introduction?fw=pt)！我们借助 Hugging Face 生态的 `accelerate` 实现了这一点，让用户可以把实验扩展到有意义的规模。

用 RL 微调语言模型大体遵循下面详述的流程。这要求保留原始模型的两份拷贝：为避免被优化的模型偏离原始行为/分布太多，每个优化步都要计算参考模型的 logits。这对优化过程构成了硬约束——每块 GPU 至少需要模型的两份拷贝。模型越大，这套配置塞进单卡就越难。

| [![trl_diagram](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/images/trl_overview.png)](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/images/trl_overview.png) |
| --- |
| **TRL 中 PPO 训练设置总览。** |

在 `trl` 中，你也可以让参考模型与活动模型共享层，避免整份拷贝。这个功能的具体用法见 detoxification 示例。

### 规模化训练

大规模训练可能很棘手。第一个挑战是把模型和优化器状态装进可用的 GPU。单个参数占多少显存取决于它的"精度"（更准确地说是 `dtype`）。最常见的 `dtype` 是 `float32`（32 位），其次是 `float16` 和 `bfloat16`（16 位）。最近 `int8`（8 位）这类" exotic"精度也被开箱支持用于训练和推理（有特定条件和约束）。简言之：在 GPU 上加载模型，float32 精度下每十亿参数要 4GB，float16 要 2GB，int8 要 1GB。想深入了解，可以看这篇博文：[https://huggingface.co/blog/hf-bitsandbytes-integration](https://huggingface.co/blog/hf-bitsandbytes-integration)。

如果使用 AdamW 优化器，每个参数还需要 8 字节（例如 1B 参数的模型，完整 AdamW 优化器状态就要 8GB 显存——[来源](https://huggingface.co/docs/transformers/v4.20.1/en/perf_train_gpu_one)）。

应对这些规模化挑战的技术有很多，最主流的范式是流水线并行（Pipeline Parallelism）、张量并行（Tensor Parallelism）和数据并行（Data Parallelism）。

| [![model-parallelism](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/model-parallelism.png)](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/model-parallelism.png) |
| --- |
| **图片来源：[this blogpost](https://towardsdatascience.com/distributed-parallel-training-data-parallelism-and-model-parallelism-ec2d234e3214)** |

数据并行把同一个模型并行地部署在多台机器上，每个实例喂不同的数据批次。这是最直白的并行策略，本质上是单 GPU 场景的复制，`trl` 已原生支持。流水线并行和张量并行则把模型本身分布式地铺开：流水线并行按层切分模型，张量并行把张量运算（如矩阵乘法）切分到多块 GPU。采用这些模型并行策略时，你需要把模型权重分片到多个设备，并定义激活与梯度在进程间的通信协议。这并不容易实现，可能要引入 [`Megatron-DeepSpeed`](https://github.com/microsoft/Megatron-DeepSpeed) 或 [`Nemo`](https://github.com/NVIDIA/NeMo) 这类框架。同样要强调的是自适应激活检查点、融合 kernel 等对扩展 LLM 训练不可或缺的工具。关于并行范式的更多阅读见[这里](https://huggingface.co/docs/transformers/v4.17.0/en/parallelism)。

于是我们问自己：只靠数据并行能走多远？能不能用现有工具把超大训练流程（包括活动模型、参考模型和优化器状态）塞进一块设备？答案是可以。关键原料是：适配器（adapters）和 8-bit 矩阵乘法！下面两节分别介绍：

### 8-bit 矩阵乘法

高效 8-bit 矩阵乘法最早在论文 LLM.int8() 中提出，旨在解决大规模模型量化时的性能退化问题。该方法把 Linear 层底层的矩阵乘法拆成两段：离群隐藏状态部分用 float16 计算，"非离群"部分用 int8 计算。

| [![8bit-matmul](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/8bit-matmul.png)](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/8bit-matmul.png) |
| --- |
| **高效 8-bit 矩阵乘法最早在论文 [LLM.int8()](https://arxiv.org/abs/2208.07339) 中提出，目标是解决大规模模型量化时的性能退化问题。该方法把 Linear 层底层矩阵乘法分成两段：离群隐藏状态部分用 float16 计算，"非离群"部分用 int8 计算。** |

简言之，使用 8-bit 矩阵乘法可以把全精度模型的体积缩小 4 倍（半精度模型则缩小 2 倍）。

### 低秩适配与 PEFT

2021 年，一篇名为 LoRA: Low-Rank Adaptation of Large Language Models 的论文证明：微调大语言模型可以通过冻结预训练权重、为注意力层中 query 和 value 矩阵创建低秩版本来实现。这些低秩矩阵的参数比原模型少得多，微调所需的 GPU 显存也少得多。作者证明，低秩适配器的微调效果可与全量预训练模型微调相媲美。

| [![lora-gif](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/lora-animated.gif)](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/lora-animated.gif) |
| --- |
| **原始（冻结）预训练权重的输出激活（左）由一个低秩适配器增强，适配器由权重矩阵 A 和 B 组成（右）。** |

这项技术让 LLM 微调只需一小部分显存。不过它也有缺点：前向和反向大约慢一倍，因为适配器层带来了额外的矩阵乘法。

### PEFT 是什么？

[Parameter-Efficient Fine-Tuning (PEFT)](https://github.com/huggingface/peft) 是一个 Hugging Face 库，用于创建并微调 LLM 上的适配器层。`peft` 与 🤗 Accelerate 无缝集成，可借助 DeepSpeed 和 Big Model Inference 支撑大规模模型。

该库支持许多先进模型，并配有丰富的示例，包括：

- 因果语言建模
- 条件生成
- 图像分类
- 8-bit int8 训练
- Dreambooth 模型的低秩适配
- 语义分割
- 序列分类
- 词元分类

库仍在活跃开发中，未来几个月还会有大量新功能上线。

## 用低秩适配器微调 20B 参数模型

铺垫讲完，我们逐步过一遍整个流程，并用图示说明：如何在单块 24GB GPU 上用上面提到的工具以 RL 微调一个 20B 参数 LLM！

### 第 1 步：以 8-bit 精度加载活动模型

| [![step1](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/step1.png)](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/step1.png) |
| --- |
| **以 8-bit 精度加载模型，相比全精度最多可省 4 倍显存** |

用 `transformers` 给 LLM"白嫖"减重的办法，就是按 LLM.int8 描述以 8-bit 精度加载模型。做法很简单：调用 `from_pretrained` 时加上 `load_in_8bit=True`（详见[这里](https://huggingface.co/docs/transformers/main/en/main_classes/quantization)）。

如前所述，估算加载模型需要多少显存有个"土办法"：按"十亿参数"算。1 字节需要 8 位，所以全精度模型每十亿参数要 4GB（32 位 = 4 字节），半精度每十亿 2GB，int8 模型每十亿 1GB。

所以第一件事：先把活动模型以 8-bit 加载进来，再看看第二步要做什么！

### 第 2 步：用 `peft` 添加额外的可训练适配器

| [![step2](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/step2.png)](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/step2.png) |
| --- |
| **在冻结的 8-bit 模型上轻松添加适配器，只训练一小部分参数，从而大幅削减优化器状态的显存需求** |

第二步是在模型内加载适配器并让它们可训练。这能显著减少活动模型所需的可训练权重数量。这一步利用 `peft` 库，几行代码就能完成。注意：适配器训练完成后，可以便捷地推到 Hub 留待后用。

### 第 3 步：用同一个模型获取参考与活动 logits

| [![step3](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/step3.png)](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/step3.png) |
| --- |
| **通过 `peft` API 可以轻松地禁用/启用适配器。** |

由于适配器可以被禁用，我们能用同一个模型取得 PPO 所需的参考 logits 和活动 logits，无需复制两份模型！这利用了 `peft` 库的 `disable_adapters` 上下文管理器。

### 训练脚本概览：

我们将说明如何结合 `transformers`、`peft` 和 `trl` 训练一个 20B 参数的 [gpt-neox 模型](https://huggingface.co/EleutherAI/gpt-neox-20b)。这个例子的最终目标是在显存受限的场景下微调 LLM 生成正面影评。同样的步骤也适用于其他任务，比如对话模型。

总体有三步、三个训练脚本：

- **[脚本](https://github.com/lvwerra/trl/blob/main/examples/sentiment/scripts/gpt-neox-20b_peft/clm_finetune_peft_imdb.py)** —— 在冻结的 8-bit 模型上训练低秩适配器，用于在 imdb 数据集上做文本生成。
- **[脚本](https://github.com/lvwerra/trl/blob/main/examples/sentiment/scripts/gpt-neox-20b_peft/merge_peft_adapter.py)** —— 把适配器层合并进基座模型权重并存到 hub。
- **[脚本](https://github.com/lvwerra/trl/blob/main/examples/sentiment/scripts/gpt-neox-20b_peft/gpt-neo-20b_sentiment_peft.py)** —— 用低秩适配器做情感微调，生成正面影评。

我们在 24GB 的 NVIDIA 4090 上测试了这些步骤。虽然整个训练在一块 24GB 卡上可行，但完整训练是在 🤗 研究集群的一台 A100 上跑的。

训练流程的第一步是在预训练模型上微调。通常这一步要好几张高端 80GB A100，所以我们选择训练一个低秩适配器。这按因果语言建模设置处理，在 [imdb](https://huggingface.co/datasets/imdb) 数据集上训练一个 epoch——该数据集包含影评以及正面/负面情感标签。

| [![loss-20b](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/loss-20b.png)](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/loss-20b.png) |
| --- |
| **gpt-neox-20b 模型在 imdb 数据集上训练一个 epoch 的训练损失** |

要把适配后的模型拿去用 RL 做进一步微调，我们首先需要合并适配权重：用 16-bit 浮点分别加载预训练模型和适配器，然后按（施加了适当缩放的）权重矩阵合并。

最后，就可以在冻结的 imdb 微调模型之上再训练一个低秩适配器。我们用 [imdb 情感分类器](https://huggingface.co/lvwerra/distilbert-imdb)为 RL 算法提供奖励。

| [![reward-20b](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/reward-20b.png)](https://huggingface.co/datasets/trl-internal-testing/example-images/resolve/main/blog/133_trl_peft/reward-20b.png) |
| --- |
| **对 20B 参数 peft 模型做 RL 微调以生成正面影评时的平均奖励。** |

完整 Weights and Biases 报告在[这里](https://wandb.ai/edbeeching/trl/runs/l8e7uwm6?workspace=user-edbeeching)，有更多曲线和文本生成结果。

## 结论

我们在 `trl` 中实现了新功能：借助 `peft` 和 `bitsandbytes` 库，用户可以以合理成本用 RLHF 微调大语言模型。我们证明了在 24GB 消费级 GPU 上微调 `gpt-neo-x`（`bfloat16` 下 40GB！）是可行的，也预期这一集成会被社区广泛用于 RLHF 微调更大的模型、分享出色的成果。

我们也识别了一些有意思的下一步方向，可以继续推动这一集成的极限：

- *多 GPU 场景下如何扩展？* 我们会主要探索这一集成随 GPU 数量的扩展性——数据并行能否开箱即用，还是需要在某个相关库里新增特性。
- *有什么工具能提升训练速度？* 我们观察到这一集成的主要短板是整体训练速度，未来我们想探索让训练快起来的方向。
