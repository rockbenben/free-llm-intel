# DeepSeek-V4：智能体真正用得上的百万 token 上下文

DeepSeek 今日发布了 V4。Hub 上有两个 MoE 权重：DeepSeek-V4-Pro 总参数 1.6T、激活参数 49B；DeepSeek-V4-Flash 总参数 284B、激活参数 13B。两者都有 1M token 的上下文窗口。基准跑分有竞争力，但并非 SOTA。这不重要。真正的创新在于 DeepSeek V4 如何为高效支持大上下文长度而设计，也因此成为智能体任务的最佳候选之一。

重点瞄准长时间运行的智能体负载。今天把一个前沿开源模型当智能体跑，会以可预见的方式崩掉：模型停了，你得重新提示；轨迹冲破上下文预算，或 KV cache 撑满 GPU，或者长任务进行到一半时工具调用往返开始劣化。**V4 就是为修复这些已知失败而构建的**，也为社区指出了跟进方向。

这篇文章讲三件事：架构做了哪些不同的设计来让长上下文推理变便宜；在此之上叠加的面向智能体的后训练决策；以及论文中一些有助于理解这些变化的要点。

## 智能体的 KV cache 问题

1M 上下文窗口只是容量，不是性能。能不能用起来，取决于在那个深度下每次前向传播的成本。对于一个跑长工具使用轨迹的智能体（SWE-bench 任务、多步浏览会话、含数百条命令的终端会话），每个工具结果都会追加进上下文，之后每个 token 都要对前面所有内容付出完整的注意力成本。

两个数字最关键：单 token 推理 FLOPs 与 KV cache 大小。两者都随序列长度增长。在 1M token 时，DeepSeek-V4-Pro 的单 token 推理 FLOPs 仅为 DeepSeek-V3.2 的 27%，因此同样硬件上跑得更快；KV cache 内存也只占 10%。V4-Flash 压得更低：FLOPs 占 10%、KV cache 占 7%。

如果拿 KV cache 内存与一个成熟架构对比——8 头分组查询注意力（GQA），按常规 bfloat16 格式存储——DeepSeek V4 只需大约 2% 的缓存大小。这让超大上下文的部署容易得多。

## 混合注意力：CSA 与 HCA

效率提升来自把注意力拆成两种机制并在层间交错。

**压缩稀疏注意力（Compressed Sparse Attention，CSA）**用带学习位置偏置的 softmax 门控池化，沿序列维度把 KV 条目压缩 4 倍。一个「闪电索引器」（lightning indexer，FP4、ReLU 打分的多头点积）为每个 query 挑选 top-k 个压缩块。它继承了 V3.2 中 DeepSeek Sparse Attention 的稀疏选择思想，但作用在比原始序列短 4 倍的块上，索引器的搜索空间也随之缩小。

[![图 3：压缩稀疏注意力，展示压缩器、作用于压缩块的闪电索引器和滑动窗口分支](https://huggingface.co/buckets/burtenshaw/deepseek-v4-figures/resolve/v4_fig3_csa.png)](https://huggingface.co/buckets/burtenshaw/deepseek-v4-figures/resolve/v4_fig3_csa.png) *图 3：CSA。压缩器把每 4 个 token 折叠成一个压缩 KV 条目。闪电索引器为每个 query 选出 top-k 压缩块。一条滑动窗口分支处理最近的未压缩 token。*

**重压缩注意力（Heavily Compressed Attention，HCA）**把 KV 条目压缩 128 倍，并去掉稀疏选择。每个 query 密集地关注所有压缩块。压缩后的序列足够短，密集注意力因此很便宜。

[![图 4：重压缩注意力，128 倍压缩后对压缩块做密集 MQA](https://huggingface.co/buckets/burtenshaw/deepseek-v4-figures/resolve/v4_fig4_hca.png)](https://huggingface.co/buckets/burtenshaw/deepseek-v4-figures/resolve/v4_fig4_hca.png) *图 4：HCA。更重的压缩器（128 倍 vs 4 倍），随后对压缩流做密集注意力，同样有一条处理近期性的滑动窗口分支。*

各层在 CSA 与 HCA 之间交替。不同层承载不同的注意力模式，强行让所有层用同一种机制会浪费容量。在 V4-Pro 的 61 层堆栈中，第 0–1 层是 HCA，第 2–60 层在 CSA 与 HCA 之间交替，末尾的 MTP 块只用滑动窗口。

两条路径对大多数 KV 条目使用 FP8 存储，只有 RoPE 维度用 BF16。CSA 内部的闪电索引器以 FP4 运行。这些存储选择与压缩率叠加，得出 2% KV cache 这个数字。

[![图 2：总体架构，展示 embedding、混合 CSA/HCA 注意力、DeepSeekMoE、流形约束超连接](https://huggingface.co/buckets/burtenshaw/deepseek-v4-figures/resolve/v4_fig2_architecture.png)](https://huggingface.co/buckets/burtenshaw/deepseek-v4-figures/resolve/v4_fig2_architecture.png) *图 2：总体架构。注意力层在 CSA 与 HCA 间交替。前馈层使用 DeepSeekMoE。残差连接被替换为流形约束超连接（mHC）。*

## 对智能体意味着什么

高效的长上下文注意力对智能体工作流是必要条件但不充分。论文描述了三项直接针对智能体用例的后训练与基础设施选择。

### 跨工具调用的交错思考

V3.2 在工具结果轮次之间保留推理轨迹，但每当新用户消息到来就丢弃它们。对只处理单轮用户输入的智能体，这没问题。但对多轮智能体工作流——用户已经等智能体串了好几个工具调用之后再发追问——模型会丢失累积的推理，不得不重建状态。

V4 在对话包含工具调用时，跨用户消息边界保留推理内容。模型在所有轮次（包括跨用户轮次）保留完整推理历史。这让智能体在长程任务上能形成连贯、累积的思维链。对于不带工具的纯对话，旧行为保持不变：每轮清空推理以让上下文保持精简。

[![图 7：思考管理，带工具（上）跨轮保留推理；不带工具（下）在每条新用户消息时丢弃推理](https://huggingface.co/buckets/burtenshaw/deepseek-v4-figures/resolve/v4_fig7_thinking.png)](https://huggingface.co/buckets/burtenshaw/deepseek-v4-figures/resolve/v4_fig7_thinking.png) *图 7：带工具的思考（上）在所有轮次保留推理。不带工具的思考（下）在每条新用户消息时丢弃推理。*

### 带专用 token 的工具调用 schema

V4 引入了 `|DSML|` 特殊 token 和基于 XML 的工具调用格式。与「把 JSON 塞进字符串」的工具调用相比，XML 格式减少了转义失败——那是模型输出嵌套引号内容时的常见失败模式。

该 schema 把字符串参数（以 `string="true"` 原样传递）与结构化参数（以 `string="false"` 按 JSON 传递）分开。这消除了 JSON 工具调用格式在数字和布尔值上反复出现的一整类解析错误。

### DSec：为 RL rollout 打造的沙箱

智能体行为是面向真实工具环境用 RL 训练出来的。论文为此描述了专门构建的沙箱基础设施。DeepSeek Elastic Compute（DSec）是一个 Rust 平台，在一个 Python SDK 后面暴露四种执行底座：函数调用、容器、microVM（Firecracker）和完整 VM（QEMU）。单个集群可运行数十万个并发沙箱。

对智能体训练而言，DSec 有三项特性重要：通过分层 3FS 存储实现快速镜像加载（这样 RL rollout 不必等容器启动）、可抢占安全的轨迹回放（这样被打断的训练步骤无需重跑工具调用即可恢复）、以及跨底座的统一 API（这样训练框架面向函数调用或完整 VM 都无需重写代码）。这些基础设施决策支撑起了智能体基准上的分数。

知识与推理数字有竞争力但不领先。V4-Pro-Max 真正拉开差距的地方在智能体数字上。

## 使用模型

Hub 上有四个权重。instruct 模型的 MoE 专家权重用 FP4，其余用 FP8；base 模型全程 FP8。

- [deepseek-ai/DeepSeek-V4-Pro](https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro)（1.6T / 激活 49B，instruct）
- [deepseek-ai/DeepSeek-V4-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash)（284B / 激活 13B，instruct）
- [deepseek-ai/DeepSeek-V4-Pro-Base](https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro-Base)（1.6T / 激活 49B，base）
- [deepseek-ai/DeepSeek-V4-Flash-Base](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-Base)（284B / 激活 13B，base）

两个 instruct 模型支持三种推理模式：Non-think（快速，无思维链）、Think High（在 `<think>` 块中显式推理）、Think Max（配合专用系统提示词的最大推理强度）。Think Max 需要至少 384K token 的上下文窗口。所有模式下推荐的采样参数是 `temperature=1.0, top_p=1.0`。

V4-Pro 在 SWE Verified、MCPAtlas 和内部研发基准上的数字，让它在智能体任务上与前沿闭源模型处于同等水平。开放的问题是：社区的工具框架如何适配 `|DSML|` schema，以及交错思考的收益能否迁移到域外的智能体框架。
