## 引言

上个月，MetaAI 发布了 [Wav2Vec2-BERT](https://huggingface.co/docs/transformers/main/en/model_doc/wav2vec2-bert)，作为其 [Seamless Communication](https://ai.meta.com/research/seamless-communication/)（一族 AI 翻译模型）的组成部分。

[Wav2Vec2-BERT](https://huggingface.co/docs/transformers/main/en/model_doc/wav2vec2-bert) 是在一个原始模型基础上不断改进的成果：**Wav2Vec2** 是一个用于自动语音识别（ASR）的预训练模型，由 *Alexei Baevski、Michael Auli 和 Alex Conneau* 在 [2020 年 9 月](https://ai.facebook.com/blog/wav2vec-20-learning-the-structure-of-speech-from-raw-audio/) 发布。Wav2Vec2 只需 10 分钟量级的带标注音频数据就能被微调，在 [LibriSpeech](https://huggingface.co/datasets/librispeech_asr) 数据集上达到 5% 的单词错误率，首次展示了 ASR 的低资源迁移学习。

经过一系列多语言改进（[XLSR](https://huggingface.co/docs/transformers/model_doc/xlsr_wav2vec2)、[XLS-R](https://huggingface.co/docs/transformers/model_doc/xls_r) 和 [MMS](https://huggingface.co/docs/transformers/model_doc/mms)）之后，Wav2Vec2-BERT 成为一个拥有 5.8 亿参数的通用音频模型，在 **450 万** 小时的无标注音频数据上完成预训练，覆盖 **超过 143 种语言**。作为对比，**XLS-R** 用了近 **50 万** 小时的音频数据、覆盖 **128 种语言**，而 **MMS** 检查点则在超过 **50 万小时音频**、**1400 多种语言** 上预训练。把时长提升到百万小时级别，让 Wav2Vec2-BERT 无论哪种语言都能在语音相关任务上取得更具竞争力的结果。

要把 Wav2Vec2-BERT 用于 ASR，可以用连接时序分类（Connectionist Temporal Classification，CTC）来做微调。CTC 是一种用于训练序列到序列问题神经网络的算法，比如 ASR 和手写识别。我们强烈推荐阅读 Awni Hannun 写的那篇 [*用 CTC 做序列建模（2017）*](https://distill.pub/2017/ctc/) 博客，以了解更多 CTC 算法细节。

本 notebook 的目标是把训练 Wav2Vec2-BERT 模型所需的全部要素都交给你——更具体地说，是预训练检查点 [**facebook/w2v-bert-2.0**](https://huggingface.co/facebook/w2v-bert-2.0)——并使用开源工具和模型在 ASR 任务上训练它。文章先完整介绍预处理流程，然后做一次 W2V2-BERT 的微调。最后一部分收集了 Hugging Face 专家关于如何扩展 CTC 训练的训练心得。

为了演示，我们在 [Common Voice 16.0](https://huggingface.co/datasets/mozilla-foundation/common_voice_16_0) 的低资源蒙古语 ASR 数据集上微调模型，该数据集包含大约 14 小时经过验证的训练数据。

## 动机

[Whisper](https://huggingface.co/blog/fine-tune-whisper#introduction) 是一族 ASR 模型，公认是 ASR 任务上表现最好的模型。它在英语 ASR 上提供最先进的性能，同时也很适合从有限资源做多语言微调。

然而，当面对蒙古语这类"资源稀缺"的语言时，Whisper 表现很差，[Whisper 论文](https://cdn.openai.com/papers/whisper.pdf) 的 D.2.2 节可以看到——蒙古语或马拉雅拉姆语在每个 Whisper 检查点上的 WER 都超过 100%。可用的检查点词表也有限，因此无法在字母表与该词表不重叠的语言上做微调。

此外，Whisper 是一个序列到序列模型，以自回归方式执行 ASR，天生就"慢"。对于训练数据集中出现频率很低的那些语言，Whisper 的慢会被进一步放大。这种情况下，Whisper 平均每个词要生成更多 token，因此耗时更长。

面对有限资源——无论是训练数据的可得性还是推理约束——我们需要更"节俭"的模型。这种情况下，Wav2Vec2-BERT 正合适。

**Wav2Vec2-BERT** 一次前向就预测出 ASR 结果，比 Whisper 快得多。正如本 notebook 将要展示的，它只需要 **很少的数据** 就能达到 **有竞争力的性能**、**易于适配** 任意字母表，而且 **更节省资源**。

实际上，经过相近的微调之后，它在蒙古语 ASR 上取得的 **WER 表现与 [Whisper-large-v3](https://huggingface.co/openai/whisper-large-v3) 相近**，却快 **10 到 30 倍**、**资源效率高 2.5 倍**。

**注意**：该基准在 Google Colab 的一块 16GB V100 上进行，在蒙古语 CV16 测试集上使用了从 1 到 8 的批量大小。

## 准备数据、Tokenizer、Feature Extractor

ASR 模型把语音转写为文本，这意味着我们既需要一个把语音信号处理为模型输入格式（例如特征向量）的特征抽取器（feature extractor），又需要一个把模型输出格式转回文本的分词器（tokenizer）。

在 🤗 Transformers 中，Wav2Vec2-BERT 模型因此同时配有 tokenizer（叫 [Wav2Vec2CTCTokenizer](https://huggingface.co/transformers/master/model_doc/wav2vec2.html#wav2vec2ctctokenizer)）和 feature extractor（叫 [SeamlessM4TFeatureExtractor](https://huggingface.co/docs/transformers/v4.36.1/en/model_doc/seamless_m4t#transformers.SeamlessM4TFeatureExtractor)，它与 [第一版](https://huggingface.co/docs/transformers/main/en/model_doc/seamless_m4t) 和 [第二版](https://huggingface.co/docs/transformers/main/en/model_doc/seamless_m4_v2t) 的 Seamless-M4T 共用，因为它们都以相同方式处理音频）。

先从创建 tokenizer 开始，用来把预测的输出类别解码成转写文本。

### 创建 `Wav2Vec2CTCTokenizer`

记住，类似 Wav2Vec2 的、在 CTC 上微调过的模型，通过一次前向把音频文件转写：先把音频输入处理成一串上下文表示序列，然后用最后的词表输出层把每个上下文表示分类为代表转写内容的字符。

该层的输出大小对应词表中的 token 数量，因此只取决于微调所用的带标注数据集。所以在第一步，我们要看一看所选的 Common Voice 数据集，并基于转写内容定义一个词表。

本 notebook 中，蒙古语我们使用 [Common Voice 16.0 数据集](https://huggingface.co/datasets/mozilla-foundation/common_voice_16_0)。蒙古语对应的语言代码是 `"mn"`。

现在可以用 🤗 Datasets 的简单 API 下载数据。数据集名是 `"mozilla-foundation/common_voice_16_0"`，配置名对应语言代码，本例中是 `"mn"`。

**注意**：在下载数据集之前，你必须登录 Hugging Face 账号、到 [数据集仓库页](https://huggingface.co/datasets/mozilla-foundation/common_voice_16_0) 点击 "Agree and Access repository" 来获取访问权限。

Common Voice 有很多不同的划分，包括 `invalidated`，指的是没有被评级为"足够干净"、因而被视为有用的数据。本 notebook 只使用 `"train"`、`"validation"` 和 `"test"` 这几个划分。

可以看到转写中包含一些特殊字符，例如 `,.?!;:`。没有语言模型的情况下，把语音片段分类到这类特殊字符要难得多，因为它们并不真正对应某个特征性的声音单元。*例如*，字母 `"s"` 有一个大致清晰的声音，而特殊字符 `"."` 没有。而且为了理解语音信号的含义，通常也不必在转写中包含特殊字符。

我们干脆移除所有不参与词义、且无法真正用声音表示的字符，并归一化文本。

```
import re
chars_to_remove_regex = '[\,\?\.\!\-\;\:\"\“\%\‘\”\\'\»\«]'

def remove_special_characters(batch):
    # remove special characters
    batch["sentence"] = re.sub(chars_to_remove_regex, '', batch["sentence"]).lower()

    return batch

common_voice_train = common_voice_train.map(remove_special_characters)
common_voice_test = common_voice_test.map(remove_special_characters)
```

在 CTC 中，通常把语音片段分类到字母，所以这里我们也这样做。让我们从训练和测试数据中提取所有不同的字母，并基于这组字母构建词表。

我们写一个映射函数，把所有转写拼接成一长串转写，然后把这个字符串转换成一个字符集合。重要的是要给 `map(...)` 函数传入 `batched=True` 参数，这样映射函数才能一次性访问所有转写。

```
def extract_all_chars(batch):
  all_text = " ".join(batch["sentence"])
  vocab = list(set(all_text))
  return {"vocab": [vocab], "all_text": [all_text]}

vocab_train = common_voice_train.map(extract_all_chars, batched=True, batch_size=-1, keep_in_memory=True, remove_columns=common_voice_train.column_names)
vocab_test = common_voice_test.map(extract_all_chars, batched=True, batch_size=-1, keep_in_memory=True, remove_columns=common_voice_test.column_names)
```

清理数据集是一个需要小心来回打磨的过程。

看训练集和测试集里分离出来的字母，会发现拉丁字母和蒙古语西里尔字母混在一起。在与目标语言的母语者沟通之后（感谢 [Mishig](https://github.com/mishig25) 帮忙查看），我们决定移除拉丁字符，理由有两个：

- CTC 算法受益于更小的词表，所以建议移除冗余字符
- 本例完全聚焦于蒙古语字母表。

```
def remove_latin_characters(batch):
```

很好，我们看到蒙古语字母表的所有字母都出现在数据集中（这并不意外），并且也提取到了特殊字符 `" "`。我们没有排除这个特殊字符，原因是：模型必须学会预测一个词何时结束，否则模型的预测将永远是一串字符，从而无法把词彼此分开。

要始终记住，预处理是在训练模型之前非常重要的一步。例如，我们不想因为忘了归一化数据，就让模型去区分 `a` 和 `A`。`a` 和 `A` 之间的差异根本不取决于这个字母的"声音"，而更多取决于语法规则——*例如* 句首字母大写。因此移除大小写字母之间的差异是合理的，这样模型学习转写语音时会更轻松。关于预处理对 ASR 任务的影响，可以在 [Audio Transformers 课程](https://huggingface.co/learn/audio-course/chapter5/evaluation#normalisation) 阅读更多内容。

为了让 `" "` 拥有自己的 token 类别更清晰，我们给它一个更显眼的字符 `|`。此外，我们还加了一个"未知"token，好让模型之后能够处理在 Common Voice 训练集中未出现过的字符。

```
vocab_dict["|"] = vocab_dict[" "]
del vocab_dict[" "]
```

最后，我们再添加一个对应 CTC "*blank token*"（空白 token）的 padding token。"blank token" 是 CTC 算法的核心组件。更多信息请查看这篇 [博客](https://distill.pub/2017/ctc/) 的 "Alignment" 一节。

```
vocab_dict["[UNK]"] = len(vocab_dict)
vocab_dict["[PAD]"] = len(vocab_dict)
len(vocab_dict)
```

```
37
```

很好，现在我们的词表完成了，由 37 个 token 组成，这意味着我们加在预训练 Wav2Vec2-BERT 检查点之上的线性层将有 37 的输出维度。

### 创建 `SeamlessM4TFeatureExtractor`

`SeamlessM4TFeatureExtractor` 的作用是把原始音频输入准备成模型能"看懂"的格式。因此它把一维振幅值序列（即原始音频输入）映射成二维的对数梅尔谱（log-mel spectrogram）值矩阵。后者把信号频率信息编码为时间的函数。查看 Audio Transformers 课程的 [这一节](https://huggingface.co/learn/audio-course/chapter1/audio_data#the-frequency-spectrum) 来了解更多关于频谱图以及它为何重要的内容。

与 tokenizer 不同，feature extractor 不需要从数据中"学习"，所以我们直接可以从 [初始模型检查点](https://huggingface.co/facebook/w2v-bert-2.0) 加载它。

```

```

很好，Wav2Vec2-BERT 的特征抽取流程至此全部定义完成！

```

    audio = batch["audio"]
    batch["input_features"] = processor(audio["array"], sampling_rate=audio["sampling_rate"]).input_features[0]
    batch["input_length"] = len(batch["input_features"])

    batch["labels"] = processor(text=batch["sentence"]).input_ids
    return batch
```

## 训练

数据已经处理好，可以开始搭建训练流程。我们将使用 🤗 Transformer 的 [Trainer](https://huggingface.co/transformers/master/main_classes/trainer.html?highlight=trainer) 类，基本上需要做以下几件事：

- 定义一个数据整理器（data collator）。与大多数 NLP 模型不同，Wav2Vec2-BERT 的输入长度远大于输出长度。鉴于输入很大，动态地填充训练批次要高效得多，意味着每个训练样本只应填充到其所在批次里最长的那个样本，而不是全局最长的那个样本。因此微调 Wav2Vec2-BERT 需要特殊的填充数据整理器，我们在下面定义。
- 评估指标。训练期间，模型应在单词错误率上做评估。我们要相应地定义一个 `compute_metrics` 函数。
- 加载预训练检查点。我们需要加载一个预训练检查点并正确配置它用于训练。
- 定义训练配置。

微调完模型之后，我们会在测试数据上正确评估它，并验证它确实学会了正确转写语音。

### 配置 Trainer

先从定义数据整理器开始。数据整理器的代码复制自 [这个示例](https://github.com/huggingface/transformers/blob/7e61d56a45c19284cfda0cee8995fb552f6b1f4e/examples/pytorch/speech-recognition/run_speech_recognition_ctc.py#L219)。

不深入太多细节，与常见数据整理器不同，这个数据整理器对 `input_features` 和 `labels` 的处理方式不同，因而对它们分别应用不同的 padding 函数。这是必要的，因为在语音中输入和输出属于不同模态，不应被同一个 padding 函数处理。与常见数据整理器类似，标签里的 padding token 用 `-100` 替换，这样在计算损失时这些 token **不会** 被计入。

```
import torch

from dataclasses import dataclass, field
from typing import Any, Dict, List, Optional, Union

@dataclass
class DataCollatorCTCWithPadding:

    processor: Wav2Vec2BertProcessor
    padding: Union[bool, str] = True

    def __call__(self, features: List[Dict[str, Union[List[int], torch.Tensor]]]) -> Dict[str, torch.Tensor]:
        # split inputs and labels since they have to be of different lengths and need
        # different padding methods
        input_features = [{"input_features": feature["input_features"]} for feature in features]
        label_features = [{"input_ids": feature["labels"]} for feature in features]

        batch = self.processor.pad(
            input_features,
            padding=self.padding,
            return_tensors="pt",
        )

        labels_batch = self.processor.pad(
            labels=label_features,
            padding=self.padding,
            return_tensors="pt",
        )
        # replace padding with -100 to ignore loss correctly
        labels = labels_batch["input_ids"].masked_fill(labels_batch.attention_mask.ne(1), -100)

        batch["labels"] = labels

        return batch

data_collator = DataCollatorCTCWithPadding(processor=processor, padding=True)
```

接下来定义评估指标。如前所述，ASR 的主要指标是单词错误率（WER），因此本 notebook 也使用它。

```
wer_metric = load_metric("wer")
```

模型将返回一串 logit 向量：y1,…,ym \mathbf{y}_1, \ldots, \mathbf{y}_m y1​,…,ym​，其中 y1=fθ(x1,…,xn)[0] \mathbf{y}_1 = f_{\theta}(x_1, \ldots, x_n)[0] y1​=fθ​(x1​,…,xn​)[0] 且 n>>m n >> m n>>m。

一个 logit 向量 y1 \mathbf{y}_1 y1​ 包含我们先前定义的词表中每个词的对数几率（log-odds），因此 len(yi)= \text{len}(\mathbf{y}_i) = len(yi​)= `config.vocab_size`。我们关心模型最可能的预测，因此取 logits 的 `argmax(...)`。另外，通过把 `-100` 替换成 `pad_token_id` 来把编码后的标签解码回原始字符串，并在解码 id 时确保连续的 token 不会按 CTC 风格 1 {}^1 1 被合并成同一个 token。

```
def compute_metrics(pred):
    pred_logits = pred.predictions
    pred_ids = np.argmax(pred_logits, axis=-1)

    pred.label_ids[pred.label_ids == -100] = processor.tokenizer.pad_token_id

    pred_str = processor.batch_decode(pred_ids)
    # we do not want to group tokens when computing the metrics
    label_str = processor.batch_decode(pred.label_ids, group_tokens=False)

    wer = wer_metric.compute(predictions=pred_str, references=label_str)

    return {"wer": wer}
```

现在，我们可以加载主预训练 [检查点](https://huggingface.co/facebook/w2v-bert-2.0)。tokenizer 的 `pad_token_id` 必须用来定义模型的 `pad_token_id`，在 `Wav2Vec2BertForCTC` 的情况下也对应 CTC 的 *blank token* 2 {}^2 2。为节省 GPU 显存，我们启用 PyTorch 的 [梯度检查点](https://pytorch.org/docs/stable/checkpoint.html)，并把损失归约设为 "*mean*"。

由于我们只训练一小部分权重，模型不容易过拟合。因此我们确保禁用所有 dropout 层。

**注意**：当用本 notebook 在 Common Voice 的另一种语言上训练 Wav2Vec2-BERT 时，这些超参数设置可能并不合适。请根据用例自行调整。

```
from transformers import Wav2Vec2BertForCTC

model = Wav2Vec2BertForCTC.from_pretrained(
    "facebook/w2v-bert-2.0",
    attention_dropout=0.0,
    hidden_dropout=0.0,
    feat_proj_dropout=0.0,
    mask_time_prob=0.0,
    layerdrop=0.0,
    ctc_loss_reduction="mean",
    add_adapter=True,
    pad_token_id=processor.tokenizer.pad_token_id,
    vocab_size=len(processor.tokenizer),
)
```

在最后一步，我们定义所有与训练相关的参数。对其中一些参数多作解释：

- `group_by_length` 通过把输入长度相近的训练样本分到同一批次来提高训练效率。通过大幅减少传入模型的无用 padding token 总数，它能显著加快训练。
- `learning_rate` 经过试探性调参直到微调变得稳定。注意这些参数强烈依赖 Common Voice 数据集，对其他语音数据集可能并非最优。

关于其他参数的更多解释，可以看 [文档](https://huggingface.co/transformers/master/main_classes/trainer.html?highlight=trainer#trainingarguments)。

训练期间，每 600 个训练步骤会异步上传一个检查点到 hub。这让你即使模型还在训练也能试玩演示组件。

1 {}^1 1 为了让模型不受说话人语速的影响，在 CTC 中连续且相同的 token 会被简单合并成一个 token。然而，解码时编码后的标签不应被合并，因为它们并不对应模型的预测 token，这就是必须传入 `group_tokens=False` 参数的原因。如果不传这个参数，像 `"hello"` 这样的词会被错误地编码并解码为 `"helo"`。 2 {}^2 2 blank token 让模型能够预测像 `"hello"` 这样的词，办法是强制它在两个 l 之间插入 blank token。我们模型一个符合 CTC 的 `"hello"` 预测会是 `[PAD] [PAD] "h" "e" "e" "l" "l" [PAD] "l" "o" "o" [PAD]`。

### 数据集相关建议

CTC ASR 通常用小写、无标点的转写来做。这简化了 CTC 任务，因为模型被视为"纯声学"的，意味着它的预测主要基于音频的语音学声音，而不是所说话句的任何语言建模上下文。

非常低频的字符会通过错误目标引起损失尖峰，从而在训练中显著影响损失。默认情况下，本文创建的 CTC tokenizer 会把这些字符加入词表，即便它们的频率相比高频字符微不足道。我们可以把这些字符当作数据标注中的"错误"处理，从而把它们从词表中移除，在训练期间直接分类为 `"[UNK]"`。

因此，务必重新检查 tokenizer 的词表，并移除所有低频字符，就像我们在创建 tokenizer 时移除拉丁字符那样。

注意 Common Voice 数据集尤其容易出现这类"错误"字符，例如来自其他语言的字符（阪）。

### 训练相关建议

**每个 CTC token 看到的平均时长**：通过实验我们发现，每个 CTC token 看到的理想时长比例是 10 到 35 毫秒。换言之，为了让 CTC token 能正确学习并预测，它需要看到的声学信息时长既不能太低也不能太高。实际上，它大致应相当于我们人类发出一个音素所需时间的一小部分。

[我的某次](https://wandb.ai/ylacombe/huggingface/runs/4y8pd2gq) 训练记录的损失曲线起初按预期平稳下降，但到了某个点开始爆炸。我意识到我用的 [是一个不带架构改动的基础检查点](https://huggingface.co/facebook/w2v-bert-2.0)，而每个 CTC token 看到的信号片段是 30 到 60 毫秒。沿时间维度对编码器隐状态做子采样、添加一个卷积 [适配层](https://huggingface.co/docs/transformers/model_doc/wav2vec2-bert#transformers.Wav2Vec2BertConfig.add_adapter)，足以把信号块采样到期望时长，并防止这类损失曲线。

**训练不足**：同事们看了我的训练记录后很快发现模型严重训练不足，这一点本可以从损失曲线看出来——它看起来像是在一次陡峭下降的中途被停下了。这也指出了其他问题， notably 损失曲线不够平滑，是超参数设置不当的信号。

以下是几种在我们这种情况下解决训练不足的方法：

- 预热率（warm-up rate）可能太高，导致学习率下降过快。解决办法是把 warmup ratio 保持在 5% 到 15%，并把 epoch 数提高上去。预热步骤对于逐步把新的语言模型头权重对齐到预训练模型至关重要。
- 损失曲线不平滑可以通过 [AdamW](https://pytorch.org/docs/stable/generated/torch.optim.AdamW.html) 的 β2 \beta_2 β2​ 来调节，它通常默认值可从 0.95 设到 0.98。
