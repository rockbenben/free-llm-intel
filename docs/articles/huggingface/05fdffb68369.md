# 为 Intel Gaudi 带来更快的辅助生成支持

随着模型规模不断增大，生成式 AI 的部署需要大量的推理资源。这不仅推高了每次生成的成本，也增加了服务这些请求所消耗的电力。

针对文本生成的推理优化，对于降低延迟、基础设施成本和功耗至关重要，从而能够改善用户体验、提升文本生成任务的效率。

辅助解码（assisted decoding）是一种加速文本生成的流行方法。我们将其适配并优化到 Intel Gaudi 上——[此前的文章](https://huggingface.co/blog/bridgetower)已表明 Gaudi 能带来与 Nvidia H100 GPU 相近的性能，而价格则与 Nvidia A100 80GB GPU 处于同一水平。这项工作现已并入 Optimum Habana，它扩展了 Transformers、Diffusers 等 Hugging Face 库，使你的 AI 工作流在 Intel Gaudi 处理器上得到充分优化。

## Speculative Sampling——辅助解码

投机采样（speculative sampling）是一种用于加速文本生成的技术。它的做法是：先由一个草稿模型（draft model）生成 K 个 token，再在目标模型（target model）中对这些 token 进行验证。如果草稿模型被拒绝，就使用目标模型来生成下一个 token，如此反复。借助投机采样，我们能够提升文本生成的速度，并获得与自回归采样相近的采样质量。该技术允许我们在生成文本时指定一个草稿模型。实践表明，这种方法对大型 transformer 模型可带来约 2 倍的加速。总体而言，这些技术能够加速文本生成并提升 Intel Gaudi 处理器上的性能。

不过，草稿模型与目标模型大小不同，它们都会体现在 KV cache 中，因此挑战在于同时利用两套独立的优化策略。在本文中，我们假设使用量化模型，并将 KV caching 与投机采样结合使用。请注意，每个模型都有各自的 KV cache：草稿模型用于生成 K 个 token，然后在目标模型中评估；当草稿模型被拒绝时，由目标模型生成下一个 token；接着草稿模型再用于生成接下来的 K 个 token，如此循环。

需要说明的是，作者[2]证明了：进行投机采样时会还原出目标分布——这保证了与直接对目标模型做自回归采样相同的采样质量。因此，不采用投机采样不划算的情形，是草稿模型的相对大小不足以带来节省，或草稿模型的接受率不够高、无法从其较小的尺寸中获益。

还有一种与投机采样类似的技术，称为辅助生成（Assisted Generation），它几乎在同一时间被独立提出[3]。作者将该方法集成进了 Hugging Face Transformers，如今 *.generate()* 调用新增了一个可选的 *assistant_model* 参数来启用此方法。

## 用法与实验

辅助生成的用法很直观。一个示例见[这里](https://github.com/huggingface/optimum-habana/tree/main/examples/text-generation#run-speculative-sampling-on-gaudi)。正如预期的那样，通过参数 `--assistant_model` 来指定草稿模型。草稿模型用于生成 K 个 token，然后在目标模型中评估；当草稿模型被拒绝时，由目标模型生成下一个 token；草稿模型再用于生成接下来的 K 个 token，如此循环。草稿模型的接受率部分取决于输入文本。通常，对于大型 transformer 模型，我们观察到约 2 倍的加速。

## 结论

现在在 Gaudi 上使用辅助生成来加速文本生成已经得到支持，并且易于使用。这可以用来提升 Intel Gaudi 处理器上的性能。该方法基于投机采样，而投机采样已被证明在提升大型 transformer 模型性能方面行之有效。
