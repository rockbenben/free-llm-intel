# 🐯 Liger GRPO 与 TRL 携手

TL;DR [Liger](https://github.com/linkedin/Liger-Kernel) 为 [TRL](https://github.com/huggingface/trl) 的组相对策略优化（Group Relative Policy Optimization）[GRPO Trainer](https://huggingface.co/docs/trl/grpo_trainer) 加了强力buff：**峰值内存削减 40%**，模型质量零损失。我们还新增了 **FSDP** 和 **PEFT** 支持，让 GRPO 在多 GPU 上的扩展前所未有地轻松。

## 动机

用强化学习（RL）微调语言模型，是模型训练生命周期中的关键一步——它把模型引导向理想的、超出一般监督微调所能达到的复杂行为。RL 传统上通过近端策略优化（PPO）算法来优化大语言模型（LLM）。这种常与"基于人类反馈的强化学习"（RLHF）挂钩的做法，依赖一个单独训练的奖励模型来引导主模型的微调。

然而，用 PPO 的 RLHF 极其消耗资源——PPO 需要同时把多个模型装进内存（策略模型、价值模型、奖励模型、参考模型），还要多轮迭代微调奖励模型和基座模型才能得到理想结果。RLHF 的成败还取决于奖励模型能否有效区分模型的理想行为与不良行为。

随着 DeepSeek 的 R1 模型大热，组相对策略优化（GRPO）近期获得广泛关注。GRPO 抛弃了 RLHF 所用的预训练奖励模型和价值模型，转而依赖*可验证的奖励函数*——以封闭形式直接检验模型输出是否正确，无需外部奖励模型。这使得在易于验证的领域（如教模型推理、做好数学和编程任务）用 GRPO 替代 PPO 微调时，效果大幅提升。

下图展示了 GRPO 与 PPO 的训练流水线（参考 [DeepSeekMath：Pushing the Limits of Mathematical Reasoning in Open Language Models](https://huggingface.co/papers/2402.03300) 的 Figure 4）：

[![PPO-vs-GRPO](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/liger-grpo/image5.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/liger-grpo/image5.png)

话虽如此，RL 训练仍然吞掉海量 GPU 内存，这里还有很大的优化空间。在这篇博客中，我们介绍 TRL 最近加入的一项优化——它把 GRPO 训练的峰值内存砍掉 40%；同时我们还会深入讲解如何在多 GPU、多节点上扩展 GRPO 而不损失性能或正确性。

## Liger Kernel 如何为 GRPO 砍内存

我们把 Liger 的分块损失（Chunked Loss）方案扩展到了 GRPO 损失上，从此不必在每个训练步骤都把完整 logits 保存在内存里。logits 的计算涉及模型的输出头（lm_head），是峰值内存的主要来源——尤其当词表很大、序列很长或批量很大时。我们的办法是把 `lm_head` 的输入沿 batch 维度切块，逐块运行前向传播。

但如果只是照这个思路直白实现，其实还是降不了峰值内存——因为反向传播仍需把全部 logits 留在 GPU 内存里。为绕开这一点，我们在前向传播过程中就为每个损失块计算梯度（对 `input` 块和 `lm_head` 权重），并在逐块推进时把它们累加起来。

## 与 TRL 的即插即用集成

我们最近在 PR [#3184](https://github.com/huggingface/trl/pull/3184) 中把 Liger GRPO 集成进了 TRL，现在只需在 `GRPOConfig` 里把 `use_liger_loss` 设为 `True`，就能用上 Liger GRPO 损失、坐享内存节省！

注意：这些特性还没进最新的 TRL 正式版，暂时需要从源码安装 TRL：

```
pip install "trl[liger] @ git+https://github.com/huggingface/trl.git"
```

然后就可以这样使用：

```
from trl import GRPOConfig, GRPOTrainer
from datasets import load_dataset


train_dataset = load_dataset("trl-lib/tldr", split="train")
training_args = GRPOConfig(output_dir="Qwen3-0.6B-GRPO", use_liger_loss=True)

def reward_len(completions, **kwargs):
    return [-abs(20 - len(completion)) for completion in completions]

trainer = GRPOTrainer(
    model="Qwen/Qwen3-0.6B-Instruct",
    reward_funcs=reward_len,
    args=training_args,
    train_dataset=train_dataset,
)
trainer.train()
```

## 借助 FSDP 与 PEFT 进一步扩展

我们还分别在 PR [#3260](https://github.com/huggingface/trl/pull/3260) 和 PR [#3355](https://github.com/huggingface/trl/pull/3355) 中为 Liger GRPO Loss 加入了 FSDP 和 [PEFT](https://github.com/huggingface/peft) 支持，让用户可以轻松把实验扩展到多 GPU 或多节点。LoRA、QLoRA 这类 PEFT 技术只在原模型之上训练更小的 adapter 权重，大幅减少可训练参数——整模型的梯度、激活和优化器状态无须全部驻留内存，内存压力显著降低。此外，在 GRPO 中使用 PEFT 可以省去加载单独参考模型的开销，因为只要在训练时禁用 LoRA adapter，就能得到原始未修改的模型。

下面是一张使用 FSDP 和 PEFT 的多 GPU GRPO 训练图，我们对比了在不同 Qwen3 模型规模下，带与不带 Liger Loss 所能达到的最大训练批量。我们发现，有了 Liger，批量可以提高大约 **1.5 到 1.8 倍**！

[![peft-batch-size-vs-model-size](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/liger-grpo/image6.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/liger-grpo/image6.png)

## 再进一步：结合 vLLM

要加速训练期间的文本生成，Liger Loss 还可以与 TRL 集成的 [vLLM](https://vllm.ai/) server 有效结合。这能以极小的开销显著加快 rollout 数据的采集，且集成体验顺滑。

设置方法如下：

- **启动 vLLM Server：** 首先启动 vLLM server，它将处理你训练脚本的生成请求。打开一个终端并运行：`CUDA_VISIBLE_DEVICES=1 trl vllm-serve --model "Qwen/Qwen3-0.6B" ` *注意：我们用 `CUDA_VISIBLE_DEVICES=1` 把 vLLM server 绑定到特定 GPU（本例为 GPU 1），把其他 GPU 留给训练。*
- **配置并运行训练脚本：** 接着修改训练脚本以使用 vLLM server。关键改动是在 `GRPOConfig` 中设置 `use_vllm=True`。 `from trl import GRPOConfig, GRPOTrainer from datasets import load_dataset def reward_len(completions, **kwargs): return [-abs(20 - len(completion)) for completion in completions] dataset = load_dataset("trl-lib/tldr", split="train[:1%]") training_args = GRPOConfig( output_dir="Qwen3-0.6B-GRPO", use_liger_loss=True, use_vllm=True, # Enable vLLM integration logging_steps=10 ) trainer = GRPOTrainer( model="Qwen/Qwen3-0.6B", # Ensure this matches the model served by vLLM reward_funcs=reward_len, args=training_args, train_dataset=dataset, ) trainer.train() `
- **启动训练：** 最后用 `accelerate launch` 运行训练脚本（如果多 GPU/分布式训练不用 [Accelerate](https://github.com/huggingface/accelerate)，就直接用 `python`）。如果 vLLM server 已占了一块 GPU，训练务必指向另一块。 `CUDA_VISIBLE_DEVICES=0 accelerate launch train.py ` *（假设脚本名为 `train.py`，你想在 GPU 0 上训练）*。

按这些步骤操作，你就能在用 Liger Loss 做 GRPO 训练时借助 vLLM 获得更快的生成周转。

## 结论

随着 Liger-GRPO 集成进 TRL，再加上 FSDP 和 PEFT 支持，用 GRPO 微调语言模型在内存效率和可扩展性上达到了新高度。我们鼓励社区试试这些新功能并分享反馈，帮助我们进一步改进 LLM 的 RL 训练。
