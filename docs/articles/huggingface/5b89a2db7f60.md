今天我们以 Apache 2.0 许可证开源 [Rumble-2-Flash](https://huggingface.co/Reson8/Rumble-2-Flash)。它是一个 0.5B 参数的语音识别模型，覆盖 40 多种语言，能跟比它大 3 到 60 倍的模型掰手腕。

- **哪里都能跑**：🤗 Transformers 与 vLLM 原生支持，不需要自定义代码
- **40 多种语言**：自动检测语种
- **输出可控**：数字写成阿拉伯数字或文字、填充词、逐字重复、强制语种
- **极快**：一小时音频约半秒，整批处理时超过 7,000 RTFx
- **真实电话通话也扛得住**：在 302 小时的呼叫中心基准上，与 NVIDIA 的 Nemotron 3.5 Transcribe (30B) 持平

## 快速上手

用 🤗 Transformers 转写

```
uv pip install torch transformers accelerate
```

```
from transformers import AutoProcessor, AutoModelForMultimodalLM

model_id = "Reson8/Rumble-2-Flash"
processor = AutoProcessor.from_pretrained(model_id)
model = AutoModelForMultimodalLM.from_pretrained(model_id, device_map="auto")

inputs = processor.apply_transcription_request(
    audio="https://hf.co/datasets/hf-internal-testing/dummy-audio-samples/resolve/main/bcn_weather.mp3",
    language="English",  # omit to detect automatically
).to(model.device, dtype=model.dtype)

output = model.generate(**inputs, max_new_tokens=512)
generated = output[:, inputs["input_ids"].shape[-1]:]
print(processor.decode(generated, return_format="transcription_only")[0])  # return_format="parsed" if detecting language
```

`audio` 接受本地路径、URL、NumPy 数组，或这些组成的列表。

## 它是怎么构建的

Rumble-2-Flash 采用 Qwen3-ASR 架构，从而做到 day-0 支持。只要你的栈跑得动 Transformers 或 vLLM，就跑得动 Rumble-2-Flash，既不需要 fork 运行时，也不需要 `trust_remote_code`。

为了找出模型在精度塌掉之前能小到什么程度，我们用 on-policy 蒸馏，把更大的生产模型 Rumble-2 蒸馏进它。学生模型不是照老师写好的转写稿学：它自己转录音频，老师逐 token 给这份转写打分——在每个位置给出自己对下一个 token 的概率，学生学着去对齐。因为学习材料出自它自己的输出，被纠正的正是它犯的错，而且每个 token 都有反馈，不是一段音频只给一个分数。

on-policy 蒸馏通常要求教师和学生共用 tokenizer，而我们两边不共用：选了 Qwen3-ASR，就等于把它的词表一并接下。[GOLD](https://huggingface.co/spaces/HuggingFaceH4/on-policy-distillation) 去掉了这个限制。当两个 tokenizer 对同一段文本切分不一致时，它会把 token 合并，让两个模型在同一段文本上比较。两边词表都有的 token 直接比，其余按排序后的概率比。

使用 GOLD 的 on-policy 蒸馏

## 结果

### 同尺寸下的精度

在 Open ASR Leaderboard 的[多语言](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard?languages=Reson8%2FRumble-2-Flash&proprietary=false)赛道上，Rumble-2-Flash 在中文、德语、法语、意大利语、西班牙语、葡萄牙语、印地语、荷兰语和英语上的平均错误率为 **6.96%**，优于大它 15 倍的 Meta omniASR-LLM 7B，也领先 Whisper large-v3。在[英语](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard)赛道上平均 **6.6% WER**。

同尺寸下的最好成绩

### 速度

Rumble-2-Flash 也很快。吞吐取决于 batch 填得多满：在 HF Open ASR Leaderboard 中较大的数据集上，batch 一直是满的，它能跑到 **超过 7,000 RTFx**，也就是一小时音频约半秒。

### 真实电话通话

干净音频不难。电话通话经过压缩、带噪声，说话人的口音还常常差别很大。在 [AppTek 的呼叫中心基准](https://huggingface.co/datasets/apptek-com/apptek_callcenter_dialogues) 上（302 小时求助热线录音、14 种英语口音，按 AppTek 自己的脚本评分），Rumble-2-Flash 达到 **7.86% WER**，与 NVIDIA 的 Nemotron 3.5 Transcribe (30B) 的 7.78% 基本持平。这明显领先同门的 Qwen3-ASR 0.6B（8.7%），也接近 Qwen3-ASR 1.7B（7.4%）——对比中唯一更好的模型。
