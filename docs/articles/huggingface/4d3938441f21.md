向前沿模型询问幻灯片，你会得到一个很好的幻灯片。如果要十个，它们就会开始看起来很相似：相同的雅致默认设置、相同的房屋风格、淡淡的“人工智能生成的牌组”外观。这很好，直到您希望这套牌看起来像“您的”模板。前沿模特有自己的风格，再多的提示也无法阻止他们回归这种风格。有时内容是机密的，根本无法离开您的系统。

这两者都指向您拥有的模型：开放权重，在您自己的基础设施上运行，使用您自己的设计语言进行训练。问题是小型开放模型（实际上是自我托管的那种）在这方面“很糟糕”。他们的幻灯片被破坏了：标题消失在背景中，文本从幻灯片上消失，形状堆叠在一起。

**Palette** 测试了一个赌注：一个小型开放权重模型，用您的设计语言对合成数据进行训练并通过线束进行检查，可以与前沿系统竞争，同时您保留对结果的所有权。我们对 20B 模型进行了微调，以按照人们的方式构建幻灯片：设计师规划幻灯片，编码员绘制每张幻灯片。其训练数据遵循 [IBM 设计语言](https://www.ibm.com/design/language/resources/)，并且在 [PresentBench](https://huggingface.co/datasets/PresentBench/PresentBench) 上，它在我们测量的三个领域中的两个领域排名第一。这篇文章介绍了我们如何合成数据、训练模型并围绕它构建一个工具。

## 为什么套牌对于小模型来说很难

幻灯片看起来很简单，但制作幻灯片需要模型完成小模型不擅长的三件事。

**它在看不到幻灯片的情况下布置幻灯片。** 模型不绘制幻灯片；而是绘制幻灯片。它编写的代码将每个元素放置在 x、y、宽度和字体大小处。 75 个字符的标题是否适合 56 磅的两行是模型在其头脑中进行的算术运算，只有在代码渲染后才发现它是错误的。小模型经常会犯这个错误，这就是幻灯片上重叠的形状和文本的来源。

**它同时做出两种决定。** 决定每张幻灯片的内容以及如何显示它（图表还是表格？要剪切什么？）是编辑判断。精确地放置它是几何学。一次传递必须完成 10-20 张幻灯片，同时保持调色板、类型和布局一致。

**没有数据显示套牌是如何制作的。** 存在大量成品套牌，但没有设计选择背后的基本原理或生成它们的代码。

## 像人一样构建它：设计师和编码员

没有人能够一次性完成一副牌。您首先决定故事（多少张幻灯片，每张讲什么，哪张有图表，哪张有表格），然后才构建每张幻灯片。 Palette 以同样的方式将工作拆分为由单个 LoRA 适配器服务的两个角色：

- 设计师阅读计划并编写结构化 JSON 简介：调色板、类型系统以及每张幻灯片的布局、确切内容和简短的设计原理。
- 编码员从简报中获取一张幻灯片的规格，并编写绘制它的 [pptxgenjs](https://gitbrent.github.io/PptxGenJS/) JavaScript，然后是其推理。

现在，每个角色都做出一种决定：设计师处理编辑判断，编码员处理几何。它们之间的摘要是可读和可编辑的，因此人员或代理可以更改幻灯片的布局，而无需重新生成幻灯片。由于每张幻灯片的上下文在编写任何代码之前都是固定的，因此编码器调用并行运行，每张幻灯片一个，这使得编码阶段速度提高了约 6-7 倍。

我们使用 LoRA 来训练适配器，而不是完全微调：它在有能力的基础上教授一种格式和技能，而不会干扰基础已经知道的内容，并且它使每个实验都很便宜。一个教训：编码器示例比设计器示例长大约 5 倍，因此天真的混合对设计器的训练不足，直到我们对其示例进行了 5 倍过采样。

## 综合牌组及其推理

没有计划、设计决策和幻灯片代码的公共语料库，因此我们用一位大型开放教师生成了一个语料库。每套牌都从一个配方开始，该配方设置了其类型、长度、布局和任何用户指令，因此我们可以控制数据涵盖的内容。计划范围从整洁的轮廓到原始内容转储，因此模型学习剪切和压缩。我们生成了大约 1000 个幻灯片，涵盖大约 10,000 张幻灯片。

每个示例都带有其背后的推理，以反事实的形式编写：跟踪权衡了一个替代方案并说明了它被拒绝的原因，因此模型学习了选择背后的规则，而不仅仅是选择。设计师对内容和形式进行推理。例如：

> “四个季度的收入，有明显的上升趋势。我考虑了一张表格，但这张幻灯片的重点是趋势，而不是确切的数字，所以条形图使其一目了然。”

编码员关于几何的原因：

> “标题有 62 个字符。在 44 磅时，它会换行成三行并进入下面的图表，因此我将其设置为 36 磅，适合两行并在图表上方留出空间。”

仅靠老师的力量是无法让数据变得良好的。它周围的循环确实如此。每个合成的牌组都会由线束在推理时使用的同一检查器进行渲染和检查是否有重叠和溢出。损坏的幻灯片被修复，它们的推理被重写为同一种反事实，涵盖了原始布局的错误以及修复的原因。检查员发现的每个错误都会成为更好的训练示例。

最困难的问题是忠诚。最严重的失败是幻灯片中包含的事实不在输入中，我们发现提示规则无法阻止它。如果简报要求六乘五的表格，但只包含三个项目符号，则编码人员必须发明其余部分。

修复它的是参考资料库，而不是规则：修复参考资料可以可靠地改变教师的输出，而添加规则则很少能改变教师的输出。老师在提示中看到一些参考资料，并复制它们，远远多于遵循指示。

## 用简单的英语指导牌组

用户通常希望对特定的设计选择进行更细粒度的控制：图表而不是表格、特定的颜色、较暗的封面。 Palette 允许他们通过*指令*来请求这些，直接写在计划中并包含在“[[ ]]”中的简短指令：
```
## Rollout plan
- March: pilot with two teams
- May: security review complete
- July: rollout to all of engineering
- September: company-wide launch
- November: first adoption review
[[make this a timeline]]
```
设计师将每个指令构建到摘要中，编码员在绘制幻灯片时遵循它。如果没有该指令，模型将合理地将这些里程碑显示为表格；有了它，模型就会绘制一条时间线。

该模型遵循指令，因为它经过了训练。数据配方包括来自 12 个类别的指令，其中一些如下所示，每个类别都有几种不同的表达方式，因此模型学习的是意图而不是固定的短语。

|类别 |指令示例 |
| ---| ---|
|布局| `[[将此作为时间线]]` |
|语气| `[[坦白，不要旋转]]` |
|观众| `[[这是给董事会的]]` |
|订单| `[[以询问开头]]` |
|遗漏| `[[无定价]]` |
|强调| `[[突出显示标题编号]]` |

## 构建检查和维修线束

即使训练有素的模型有时也会产生损坏的幻灯片：标题与背景颜色相同，或者两个盒子堆叠在一起。所以 Palette 不会直接返回模型的输出；每个甲板首先经过安全带。

[！[调色板管道：计划→设计器→编码器→检查和修复→甲板]（https://cdn-uploads.huggingface.co/product/uploads/63890e3843d8b0797a0ad606/PZoiyAFg_nrWRryQhjGN_.pn g)](https://cdn-uploads.huggingface.co/product/uploads/63890e3843d8b0797a0ad606/PZoiyAFg_nrWRryQhjGN_.png) *图 2。设计人员起草概要，编码人员并行编写每张幻灯片的代码，而线束在返回幻灯片之前检查并修复每张幻灯片。*

首先，简单的规则可以修复已知的错误，例如格式错误的颜色代码，否则会使每张幻灯片变成黑色。然后对每张幻灯片进行渲染和测量：几何检查器标记重叠、被剪切或脱离幻灯片的文本。标记的幻灯片会转到单独的编辑器模型，该模型会重写该幻灯片的代码。

关键规则是只有当检查人员确认幻灯片得到改进时才保留重写；否则原件将保留。这使得安全带可以在每个甲板上安全运行。它可以修复幻灯片，但不能使幻灯片变得更糟。

[！[之前/之后：重叠的卡片修复成干净的网格](https://cdn-uploads.huggingface.co/product/uploads/63890e3843d8b0797a0ad606/iZzBRJXOUxncecFIEgw-B.pn g)](https://cdn-uploads.huggingface.co/product/uploads/63890e3843d8b0797a0ad606/iZzBRJXOUxncecFIEgw-B.png) *图 3. 修复示意图。生成后（左），每张卡的标题都堆叠在其描述之上；线束检测重叠并将卡片回流成 2×2 网格（右）。*

为了测量其效果，我们生成了每个 PresentBench 套牌一次，并在使用和不使用安全带的情况下对其进行评分。在 131 个牌组中，安全带平均增加 3.5 分。

## 评价

我们在 [PresentBench](https://huggingface.co/datasets/PresentBench/PresentBench) 上进行评估，它根据五个标准对生成的牌组进行评分：基础知识、视觉设计、完整性、正确性和保真度。 PresentBench 提供源文档而不是计划，因此对于这些运行，一个单独的前沿模型根据其文档起草了每个计划，而 Palette 根据该计划构建了平台。我们报告三个领域；基线数字来自 PresentBench 论文。

[![PresentBench 得分域名](https://cdn-uploads.huggingface.co/product/uploads/63890e3843d8b0797a0ad606/QiWVeHtadoTFYsfdPjkDr.p ng）]（https://cdn-uploads.huggingface.co/product/uploads/63890e3843d8b0797a0ad606/QiWVeHtadoTFYsfdPjkDr.png） *图 4. 按领域划分的 PresentBench 分数。调色板（蓝色）与 NotebookLM、Manus 1.6 和其他五个系统（灰色）相对应。 Palette 在经济和教育方面排名第一，在 Talk 方面排名第三，在三领域平均值方面排名第二。*

Palette 在结构化内容和数字准确性决定分数的方面做得最好，在经济和教育方面排名第一。在 Talk 中，套牌是叙事和语音驱动的，两个封闭系统得分更高，Palette 排名第三。作为单一 20B 开放重量模型，它在这三个领域中排名第二，落后 NotebookLM（59.7 比 60.8）1.1 分，领先于该领域的其他产品。

PresentBench衡量一套牌是否好，但不衡量它是否遵循特定的设计语言。我们不知道有哪个基准可以做到这一点，我们希望帮助缩小这一差距。

## 接下来是什么

该工具已经计算出廉价的、可验证的信号：幻灯片是否渲染，是否有任何重叠或溢出，是否每个事实都可以追溯到摘要。今天我们用它们来修复一代又一代的输出。接下来，我们希望使用相同的检查作为强化学习的奖励，以便模型首先停止犯这些错误。由于编码员一次只处理一张幻灯片，因此每张幻灯片都是一个简短的、可独立检查的卷展栏，非常适合 GRPO 式训练。

我们还希望通过从源文档中提取图形（例如使用 [Docling](https://github.com/docling-project/docling)）并将其与线束放在一起来缩小图形密集的甲板上的差距。我们正在探索一种更轻松的方式来引入您自己的模板：从一个或两个现有的“.pptx”文件重新设计输出，而无需重新训练。

## 我们学到了什么

构建调色板教会了我们一些有效的方法，这些方法可以自然地扩展到其他任务，这些任务的输出具有可以在代码中检查的结构，从图表和图表到 UI 布局：

- 将推理放入数据中。关于为什么做出选择（包括拒绝什么）的培训所教的不仅仅是选择本身。
- 在添加规则之前修复示例。当老师出错时，我们的第一反应是在提示中添加一条规则，但这几乎没有帮助。老师复制参考资料的次数远多于遵循指示的次数，因此修复参考资料才是真正改变其输出的原因。
- 默认情况下确保维修安全。仅当修复有明显帮助时才保留，可以在每个输出上运行。
- 首先构建检查器。这使得数据值得信赖，输出可以安全运输。
