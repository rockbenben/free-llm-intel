两周前，我们开放了 Phonon，这是我们在您自己的设备上运行的小型文本转语音模型。它不需要服务器和网络，您输入的内容会一直留在您身边。

到目前为止，我们对接待情况感到非常满意。以下是发布的故事：我们为何构建 Phonon、它能做什么、附带的演示以及它在 Hugging Face 的 Open TTS 排行榜上的表现。

## 为什么你的设备上应该有声音

大多数语音人工智能都存在于云端：每个句子都会往返服务器。 Phonon 在您自己的设备上运行。您的文本会保留在那里，并且语音可以在没有网络的情况下工作。我们还打开了权重。 Phonon 31m 是 Apache 2.0，因此您可以免费使用它，甚至在商业产品中也是如此。其他模型是 CC BY-NC，因此它们对于非商业项目是免费的。如果你正在用这些东西构建商业产品，定价是基于你的用户数量，而不是你产生的言论量。

在小型设备上运行良好的声音一直很困难。您可以将模型变小，但听起来不太好。或者你可以让它听起来很棒，但那就不合适了。我们解决了这两个问题。

我们于 4 月份发布了 Phonon，并在接下来的六个月里与合作伙伴和早期用户一起进行开发。他们的反馈帮助我们塑造了这个版本。模型变得更小，我们通过语音克隆和语音设计添加了更多语言和对自定义语音的支持。

Phonon 基于 [Pocket TTS](https://huggingface.co/kyutai/pocket-tts) 谱系，因此使用流匹配来生成音频，这与其他 TTS 系统中使用的建模技术非常不同。这使我们能够为如此小的模型带来这种质量水平，但它在训练模型时带来了新的挑战。训练最初在数值上不稳定，需要一些技巧才能在所有五种语言上产生高质量的结果。

## 我们发布了什么

Phonon 有两种大小，大约 65 MB 和 75 MB。他们一起讲英语、法语、德语、西班牙语和葡萄牙语。有超过 100 种内置声音，您可以在 [Gradium Studio](https://studio.gradium.ai/) 中创建自己的声音。 Phonon 还可以处理大多数其他 TTS 系统经常遇到的重要问题，例如电话号码、日期和代码。

它可以在手机、笔记本电脑、单板计算机和浏览器选项卡中运行，因此您可以[立即听到](https://huggingface.co/spaces/gradium/phonon)。 Phonon 31m 讲英语并且是 Apache 2.0，因此您可以在其上自由构建，包括商业产品。 Phonon 40m 在非商业许可下涵盖所有五种语言。

## 演示和第一个项目

[发布](https://gradium.ai/blog/release-phonon-open-weight) 附带了来自朋友和我们自己团队的演示。在 Wi-Fi 关闭的 Apple Watch 上，Phonon 会逐步指导您冲泡咖啡。在没有信号的 iPhone 上，它会计算您的重复次数并让您继续前进。来自 Autonomous 的一个名为 Lamp 的机器人戴着分院帽，能用性格说话。在浏览器中，离线恐龙跑步者变成了雷克斯主持的广播节目。还有一个科幻游戏在玩家自己的机器上配音，普鲁斯特一页一页地大声朗读。

Hugging Face 团队构建了 Transformers 集成，因此开发人员从第一天起就可以在 Transformers 中使用 Phonon。

开发人员也开始在此基础上进行开发。 [ExecuTorch conversion](https://huggingface.co/executorch-community/Phonon-31M-EN-ExecuTorch-WebGPU) 在浏览器中访问者的 GPU 上运行 Phonon，[Micdrop](https://micdrop.dev/docs/ai-integration/provided-integrations/phonon.md) 将其带到 Node.js 应用程序和 Spaces 中，例如[smallest-s2s](https://huggingface.co/spaces/Steveeeeeeen/smallest-s2s) 在此基础上构建。

Phonon 在发布的前两周内下载量就超过 20 万次，并且仍然是 Hugging Face 上的热门话题。

## Phonon 在 Hugging Face Open TTS 排行榜上的表现如何

[开放 TTS 排行榜](https://huggingface.co/spaces/hf-audio/open_tts_leaderboard) 是 Hugging Face 的一个非常新的项目，我们喜欢它。 [Hugging Face Hub](https://huggingface.co/models?pipeline_tag=text-to-speech) 上有超过 9,000 个 TTS 模型，排行榜为开发人员提供了一个比较开放模型并并排聆听它们的地方。在 23 种语言中，模型根据**清晰度**（*输出的字错误率*）、**速度**（*逆实时因子和首次音频时间*）和**自然度**（*英语的 UTMOS 和韩语的 KOMOS*）进行评估。评估固定语音和语音克隆，并为后者提供额外的说话者相似度度量。排行榜还有一个“聆听”选项卡，您可以在其中方便地自己比较 TTS 输出并为您最喜欢的输出投票。

在清晰度方面，Phonon 在[德语](https://huggingface.co/spaces/hf-audio/open_tts_leaderboard?languages=de) 和[西班牙语](https://huggingface.co/spaces/hf-audio/open_tts_leaderboard?languages=es) 中排名第一，并且在我们评估的每种语言中均排名前三，仅次于其大小 100 倍的模型。

速度是我们看到 Phonon 真正出彩的地方，因为该模型在首次音频时间上超过了 [CPU 流基准](https://huggingface.co/spaces/hf-audio/open_tts_leaderboard?streaming-cpu)。

[![首个音频时间第 95 个百分点的前 10 个模型的条形图。 Phonon 31m en 以 28 毫秒排名第一，Phonon 40m en 以 38 毫秒排名第二，领先于 Pocket TTS 的 165 毫秒。越低越好。](https://huggingface.co/datasets/olesiagradium/video/resolve/main/phonon-ttfa-chart.png)](https://huggingface.co/datasets/olesiagradium/video/resolve/main/phonon-ttfa-chart.png)

## 推论

我们专门针对 Phonon 构建了一个新的推理框架 [ptts](https://github.com/gradium-ai/xn-ptts)。 ptts 的目标是在各种设备上获得最佳性能，因此支持 10 多个后端：CPU（Intel、Arm、WebAssembly）、GPU（CUDA、Vulkan、Metal、WebGPU）和 NPU（Apple Core ML、Snapdragon®）。

从 v5.21 开始，Phonon 也可在🤗 Transformers 中使用，作为其参考 PyTorch 实现。 “ptts”在设备上运行单个流，而 Transformers 则以 GPU 吞吐量为目标：批量生成、全图“torch.compile”，例如用于大规模合成语音数据集。作为原生 PyTorch，无论是将 Phonon 集成到您自己的堆栈中还是研究模型本身，它都是构建的基础。

它属于 Pocket TTS 血统，因此我们首先将 Pocket TTS 添加到变形金刚中。声子作为一个[模块化](https://huggingface.co/docs/transformers/modular_transformers)模型位于顶部：大约[200行](https://github.com/huggingface/transformers/blob/main/src/transformers/models/gradium_phonon_tts/modular_gradium_phonon_tts.py)仅描述不同之处。

Phonon 以自回归方式生成音频潜伏：每个步骤都会输出一个潜伏，该潜伏将作为下一个输入反馈，并根据它们计算训练损失。潜在变量是模型的输入、输出和目标，就像文本标记用于语言模型一样，因此将音频映射到潜在变量的编解码器起着标记器的作用。 Transformers 是这样提供的：一个[音频分词器](https://huggingface.co/docs/transformers/model_doc/pocket_tts_audio_tokenizer)，由文本分词器旁边的处理器持有：
```
from transformers import AutoProcessor, GradiumPhononTTSForConditionalGeneration

model_id = "gradium/phonon-31m-en"
processor = AutoProcessor.from_pretrained(model_id, device_map="auto")
model = GradiumPhononTTSForConditionalGeneration.from_pretrained(model_id, device_map="auto")

print(f"{model.num_parameters():,}")  # 30,788,354
print(f"{processor.audio_tokenizer.num_parameters():,}")  # 10,305,313
```
声音不是录音，而是说话者潜在的张量。 Phonon 从不直接使用其音频分词器对音频进行编码，该分词器仅提供解码器，并且语音是预先计算的：[gradium/phonon-voices](https://huggingface.co/gradium/phonon-voices)。
```
from huggingface_hub import hf_hub_download
from safetensors.torch import load_file

path = hf_hub_download("gradium/phonon-voices", "voices/LMDIYE0Oa377Qh6Z.safetensors")
voice = load_file(path)["speaker_wavs"][0].T  # (num_frames, 512)
```
与 Transformers 中的其他多模式模型一样，提示布局（语音位置、文本，然后是打开音频的令牌）作为聊天模板随检查点一起提供。您编写一个标准对话，其中有一个空的“音频”项目，其中有语音，并且您的代码在各个检查点保持不变。然后，处理器将语音占位符扩展到每帧一个位置，对文本进行标准化和标记化，并对输入进行批处理：
```
conversation = [
    {"role": "user", "content": [{"type": "audio"}, {"type": "text", "text": "Hello from Phonon."}]}
]
inputs = processor.apply_chat_template(
    conversation,
    tokenize=True,
    return_dict=True,
    add_generation_prompt=True,
    processor_kwargs={"audio_prompt_latents": [voice]},
).to(model.device)
# prompt: <|audio_prompt|> × num_frames, "Hello from Phonon.", <|audio_bos|>
```
`generate` 返回潜在值，处理器将其解码为音频：
```
outputs = model.generate(**inputs)  # audio_latents: (batch_size, num_frames, 32)
audio = processor.decode(outputs.audio_latents, outputs.audio_latents_mask)
processor.save_audio(audio, "phonon.wav")
```
请参阅 [文档](https://huggingface.co/docs/transformers/model_doc/gradium_phonon_tts) 🤗 了解更多！

## 接下来是什么

声子可以用任何声音说话。经演讲者同意，从简短录音中克隆一段录音，或在 [Gradium Studio](https://studio.gradium.ai/) 中以纯文本描述新录音。然后下载语音文件，将其加载到 Phonon 中，它就可以在设备上完全运行。

我们还与设计合作伙伴一起训练定制声子模型。如果您的内存预算紧张，我们可以缩小模型。如果您需要韩语、阿拉伯语或日语，我们也可以提供培训。如果您的产品有自己的词汇，我们可以对其进行微调。 [联系](https://gradium.ai/contact?subject=Sales) 并告诉我们您的需求。

感谢 Hugging Face 团队，以及在前两周尝试 Phonon 的所有人。

Phonon 是我们的第一个开放版本。 [尝试一下](https://huggingface.co/spaces/gradium/phonon) 并告诉我们您构建了什么。
