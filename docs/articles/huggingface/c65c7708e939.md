两周前，我们开放了 Phonon，这是我们那个能在你自己的设备上运行的小型 text-to-speech 模型。它不需要服务器，也不需要网络，你输入什么就留在你这里。

到目前为止我们对它收到的反响非常满意。所以这里讲讲这次发布的故事：我们为什么构建 Phonon、它能做什么、随它一起推出的演示，以及它在 Hugging Face 的 Open TTS Leaderboard 上表现如何。

## 为什么语音应该驻留在你的设备上

大多数语音 AI 都活在云端：每一句话都要往服务器往返一趟。Phonon 相反，它运行在你自己的设备上。你的文本留在那儿，语音没有网络也能工作。我们也开放了权重。Phonon 31m 是 Apache 2.0，所以你可以免费使用它，甚至用在商业产品里。其他模型是 CC BY-NC，所以在非商业项目里它们免费。如果你要用它们构建商业的东西，定价按你的用户数量计，而不是按你生成了多少语音。

让一副好嗓音跑在小设备上一直是件难事。你可以把模型做小，但那样它听起来就不够好；或者让它听起来很好，但那样它就装不下。这两头我们都处理了。

我们在 4 月宣布了 Phonon，接下来的六个月一直和合作伙伴与早期用户在它之上做构建。他们的反馈帮助我们塑造了这次发布。模型变得更小，我们还增加了更多语言，以及通过 voice cloning 和 voice design 支持自定义音色。

Phonon 基于 [Pocket TTS](https://huggingface.co/kyutai/pocket-tts) 这一谱系，因此用 flow matching 来生成音频，这和其他 TTS 系统所用的建模技术很不一样。正是这一点让我们能把这个水平的质量放进如此小的模型，但它也在训练模型的过程中制造了新挑战。训练起初在数值上不稳定，需要好几个 trick 才能在全部五种语言上产出有质量的结果。

## 我们发布了什么

Phonon 有两种尺寸，大约 65 MB 和 75 MB。它们合起来会说英语、法语、德语、西班牙语和葡萄牙语。内置音色超过 100 个，你也可以在 [Gradium Studio](https://studio.gradium.ai/) 里创建自己的音色。Phonon 还能处理大多数其他 TTS 系统经常栽跟头的那些要紧事，比如电话号码、日期和代码。

它能在手机、笔记本、单板计算机以及浏览器标签页里运行，所以你现在就可以[试听一下](https://huggingface.co/spaces/gradium/phonon)。Phonon 31m 说英语且是 Apache 2.0，所以你可以自由地在它之上构建，包括用于商业产品。Phonon 40m 在非商业许可下覆盖全部五种语言。

## 演示与首批项目

[这次发布](https://gradium.ai/blog/release-phonon-open-weight)带来了一些来自朋友和我们自己团队的演示。在一块关掉 Wi-Fi 的 Apple Watch 上，Phonon 一步一步地带着你冲好一杯咖啡。在一部没有信号的 iPhone 上，它替你数动作次数、推着你继续练下去。Autonomous 出品的一台名叫 Lamp 的机器人戴着分院帽，以角色的口吻说话。在浏览器里，一款离线的小恐龙跑酷游戏变成了一档由 Rex 主持的广播节目。此外还有一款在玩家自己机器上完成配音的科幻游戏，以及一页一页朗读 Proust 的内容。

Hugging Face 团队构建了 Transformers 集成，所以开发者从第一天起就能在 Transformers 里使用 Phonon。

开发者们也已经开始在它之上构建。一份 [ExecuTorch 转换版本](https://huggingface.co/executorch-community/Phonon-31M-EN-ExecuTorch-WebGPU)在浏览器里用访客的 GPU 运行 Phonon，[Micdrop](https://micdrop.dev/docs/ai-integration/provided-integrations/phonon.md)把它带进了 Node.js 应用，而像 [smallest-s2s](https://huggingface.co/spaces/Steveeeeeeen/smallest-s2s) 这样的 Spaces 也在它之上搭建。

Phonon 在头两周里被下载超过 20 万次，如今在 Hugging Face 上依然处于热门之中。

## Phonon 在 Hugging Face Open TTS Leaderboard 上的表现

[Open TTS Leaderboard](https://huggingface.co/spaces/hf-audio/open_tts_leaderboard) 是 Hugging Face 一个非常新的项目，我们很喜欢它。[Hugging Face Hub](https://huggingface.co/models?pipeline_tag=text-to-speech) 上有超过 9,000 个 TTS 模型，这个榜单给了开发者一个可以比较开源模型、并把它们放在一起试听的地方。在 23 种语言上，模型按**可懂度**（*输出的 word error rate*）、**速度**（*inverse real-time factor 和 time-to-first audio*）以及**自然度**（*英语用 UTMOS、韩语用 KOMOS*）来评估。固定音色和 voice cloning 都会被评估，后者还额外多一个说话人相似度指标。榜单还有一个 Listen 标签页，你可以在那里方便地自己比较 TTS 的输出，并给你最喜欢的结果投票。

在可懂度上，Phonon 在[德语](https://huggingface.co/spaces/hf-audio/open_tts_leaderboard?languages=de)和[西班牙语](https://huggingface.co/spaces/hf-audio/open_tts_leaderboard?languages=es)排名第一，在我们评估的每一种语言里都位居前三，与它同榜的模型体积最多可达它的 100 倍。

速度是我们看到 Phonon 真正闪光的地方，因为这几个模型在 time-to-first audio 上登上了 [CPU 流式基准测试](https://huggingface.co/spaces/hf-audio/open_tts_leaderboard?streaming-cpu)的榜首。

## 推理

我们构建了一个新的推理框架 [ptts](https://github.com/gradium-ai/xn-ptts)，专门为 Phonon 而做。ptts 的目标是在各种各样的设备上拿到最好的性能，因此它支持超过 10 种后端：CPU（Intel、Arm、WebAssembly）、GPU（CUDA、Vulkan、Metal、WebGPU），以及 NPU（Apple Core ML、Snapdragon®）。

Phonon 也从 v5.21 起进入 🤗 Transformers，作为它的参考 PyTorch 实现。`ptts` 在设备上跑单条流，Transformers 则瞄准 GPU 吞吐量：批量生成、整图 `torch.compile`，例如大规模合成语音数据集。由于是原生 PyTorch，它是一个可供继续构建的底座，无论你是要把 Phonon 集成进自己的技术栈，还是要研究模型本身。

它属于 Pocket TTS 谱系，所以我们先把 Pocket TTS 加进了 Transformers。Phonon 作为一个 [modular](https://huggingface.co/docs/transformers/modular_transformers) 模型叠在它之上：大约 [200 行](https://github.com/huggingface/transformers/blob/main/src/transformers/models/gradium_phonon_tts/modular_gradium_phonon_tts.py)代码，只描述不同的那部分。

Phonon 以自回归的方式生成音频 latent：每一步输出一个 latent，它被回喂作为下一个输入，训练损失就在这些 latent 上计算。latent 就是这个模型的输入、输出和目标，如同文本 token 之于语言模型，因此把音频映射成 latent 的 codec 扮演着 tokenizer 的角色。Transformers 就是这样发布它的：一个[音频 tokenizer](https://huggingface.co/docs/transformers/model_doc/pocket_tts_audio_tokenizer)，和文本 tokenizer 一起由 processor 持有：

```
from transformers import AutoProcessor, GradiumPhononTTSForConditionalGeneration

model_id = "gradium/phonon-31m-en"
processor = AutoProcessor.from_pretrained(model_id, device_map="auto")
model = GradiumPhononTTSForConditionalGeneration.from_pretrained(model_id, device_map="auto")

print(f"{model.num_parameters():,}")  # 30,788,354
print(f"{processor.audio_tokenizer.num_parameters():,}")  # 10,305,313
```

一个音色不是一段录音，而是一个说话人 latent 的 tensor。Phonon 从不直接用自己的音频 tokenizer 编码音频，该 tokenizer 是以只有解码器的形式发布的，而音色是预先算好的：[gradium/phonon-voices](https://huggingface.co/gradium/phonon-voices)。

```
from huggingface_hub import hf_hub_download
from safetensors.torch import load_file

path = hf_hub_download("gradium/phonon-voices", "voices/LMDIYE0Oa377Qh6Z.safetensors")
voice = load_file(path)["speaker_wavs"][0].T  # (num_frames, 512)
```

prompt 的排布（音色位置、文本，然后一个开启音频的 token）作为 chat template 随 checkpoint 一起发布，这和 Transformers 里其他多模态模型一样。你写一段标准的对话，在放音色的位置留一个空的 `audio` 项，你的代码在不同 checkpoint 之间保持不变。processor 随后把音色占位符按每帧一个位置展开，对文本做归一化和 tokenize，并把输入打包成 batch：

```
conversation = [
    {"role": "user", "content": [{"type": "audio"}, {"type": "text", "text": "Hello from Phonon."}]}
]
inputs = processor.apply_chat_template(
    conversation,
    tokenize=True,
    return_dict=True,
    add_generation_prompt=True,
    processor_kwargs={"audio_prompt_latents": [voice]},
).to(model.device)
# prompt: <|audio_prompt|> × num_frames, "Hello from Phonon.", <|audio_bos|>
```

`generate` 返回 latent，processor 把它们解码成音频：

```
outputs = model.generate(**inputs)  # audio_latents: (batch_size, num_frames, 32)
audio = processor.decode(outputs.audio_latents, outputs.audio_latents_mask)
processor.save_audio(audio, "phonon.wav")
```

更多内容请看[文档](https://huggingface.co/docs/transformers/model_doc/gradium_phonon_tts) 🤗！

## 接下来

Phonon 可以用任何音色说话。在取得说话人同意的前提下，用一段简短的录音克隆一个音色，或者在 [Gradium Studio](https://studio.gradium.ai/) 里用纯文本描述一个新的音色。然后下载音色文件，在 Phonon 里加载它，它就完全在设备上运行。

我们也会和设计伙伴一起训练自定义的 Phonon 模型。如果你的内存预算很紧，我们可以把模型做得更小。如果你需要韩语、阿拉伯语或日语，我们也能为此训练。如果你的产品有自己的一套词汇，我们可以在它之上做 fine-tuning。[联系我们](https://gradium.ai/contact?subject=Sales)，说说你需要什么。

感谢 Hugging Face 团队，也感谢在头两周里试用过 Phonon 的每一个人。

Phonon 是我们的第一个开放发布。[试用一下](https://huggingface.co/spaces/gradium/phonon)，告诉我们你构建出了什么。
