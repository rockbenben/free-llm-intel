# 介绍 AMD 第五代 EPYC™ CPU

Mohit Sharma（mohitsha）、Morgan Funtowicz（mfuntowicz）

AMD 刚刚发布了基于 Zen5 架构的第五代服务器级 EPYC CPU——也被称为 `Turin`。它在性能上有显著提升，尤其是更高的核心数，可达 `192` 核和 `384` 线程。

从大语言模型（LLM）到 RAG 场景，Hugging Face 用户可以利用这一代新服务器来提升他们的性能能力：

- 降低部署的目标延迟。
- 提升最大吞吐量。
- 降低运营成本。

在过去几周里，我们一直在与 AMD 合作，验证 Hugging Face 生态在这一代新 CPU 上得到全面支持，并在不同任务上交付预期的性能。

此外，我们还在酝酿一些全新的方式，通过 `AMD ZenDNN PyTorch 插件（zentorch）` 来在 AMD CPU 上利用 `torch.compile`，进一步加速我们下面要讨论的那类工作负载。

我们得以提前接触到这部分工作，用来测试 Hugging Face 的模型和库，并与大家分享性能表现；我们预计 AMD 会很快向社区开放——敬请期待！

## AMD Turin vs AMD Genoa 性能——2 倍加速

本节我们给出对两款 AMD EPYC CPU 做基准测试的结果：Turin（128 核）和 Genoa（96 核）。在这些基准中，我们使用了 PyTorch 的 **ZenDNN** 插件（zentorch），它为在 AMD EPYC CPU 上的深度学习工作负载提供推理优化。该插件与 torch.compile 图编译流程无缝集成，能在 torch.fx 图上做多轮图级优化，实现进一步的性能加速。

为确保最佳性能，我们使用 `bfloat16` 数据类型，并采用 `ZenDNN 5.0`。我们配置了多实例部署，让多个 [Meta LLaMA 3.1 8B](https://huggingface.co/meta-llama/Llama-3.1-8B-Instruct) 模型实例跨所有核心并行执行。每个模型实例在每 socket 上分配 32 个物理核心，从而充分利用服务器的处理能力，实现高效的数据处理和计算速度。

我们用两个不同的 batch size——16 和 32——在五个不同用例上跑基准：

- 摘要（1024 输入 token / 128 输出 token）
- 聊天机器人（128 输入 token / 128 输出 token）
- 翻译（1024 输入 token / 1024 输出 token）
- 论文写作（128 输入 token / 1024 输出 token）
- 实时字幕（16 输入 token / 16 输出 token）。

这些配置不仅便于全面分析每台服务器在不同工作负载下表现如何，也模拟了 LLM 的真实应用。具体来说，我们为每个用例绘制了解码吞吐量（不含第一个 token），以展示性能差异。

## 结论

如所展示，与前一代 AMD Genoa 相比，AMD EPYC Turin CPU 在 AI 用例上带来了显著的性能提升。为增强可复现性、简化基准测试流程，我们使用了 [optimum-benchmark](https://github.com/huggingface/optimum-benchmark)，它提供了一个统一框架，可在各种配置下高效做基准测试。这让我们能够有效使用 `torch.compile` 的 `zentorch` 后端做基准。

此外，我们开发了一个优化的 `Dockerfile`，连同基准代码将很快发布。这将便于部署和复现我们的结果，确保其他人能有效利用我们的发现。

你可以在 [AMD Zen Deep Neural Network (ZenDNN)](https://www.amd.com/en/developer/zendnn.html) 找到更多信息。
