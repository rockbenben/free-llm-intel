[Black Forest Labs](https://huggingface.co/black-forest-labs) 的 FLUX.3 Image Klein 来了，而且从第一天起就能跑在 Diffusers 里。一个模型同时做文生图和多参考图生图，还带来了一点新东西：**布局控制**。你把边界框写进 prompt，就能说明图像的每一部分该放在哪里，或者参考图中的哪几部分要被移动。

两个开源 checkpoint 都在 [FLUX.3 Image Klein collection](https://huggingface.co/collections/black-forest-labs/flux-3-image-klein) 里：

| Checkpoint | 是什么 | 默认设置 |
| --- | --- | --- |
| [`black-forest-labs/flux-3-image-klein`](https://huggingface.co/black-forest-labs/flux-3-image-klein) | 时间步蒸馏版，用于快速推理 | 16 步，无 CFG |
| [`black-forest-labs/flux-3-image-klein-base`](https://huggingface.co/black-forest-labs/flux-3-image-klein-base) | 基础模型 | 50 步，CFG |

## TL;DR

- 一个模型覆盖文生图、多参考图生图，以及边界框布局控制。
- 蒸馏版 checkpoint 在 H100 上生成一张 1024 × 1024 的图像大约需要 **2 秒**。
- NVFP4 和 FP8 权重可以用 `from_single_file` 加载，适合更小的 GPU。
- 文生图和图像编辑两种任务都提供 LoRA 训练脚本。
- 以 [Modular Diffusers](https://huggingface.co/blog/flux-3#modular-diffusers) 管线的形式发布，所以你可以把某些 block 拆出来，或者加上你自己的。

## 开始使用

安装最新的 `diffusers` 和 `transformers`（为了 Qwen3-VL 文本编码器）：

```
pip install -U diffusers transformers
```

加载蒸馏版 checkpoint 并生成一张图像：

```
import torch
from diffusers import ModularPipeline

pipe = ModularPipeline.from_pretrained("black-forest-labs/flux-3-image-klein")
pipe.load_components(dtype=torch.bfloat16)
pipe.to("cuda")

pipe(prompt="a red fox", output="images")[0].save("fox.png")
```

## FLUX.3 能做什么

### 文生图

FLUX.3 对完整的场景描述响应最好：主体、环境、光线、构图和风格都写清楚。Black Forest Labs 的[官方 prompting 指南](https://docs.bfl.ai/guides/prompting_summary)里还有更多技巧。蒸馏版 checkpoint 默认用 `16` 步生成一张 `1024 × 1024` 的图像。传入 `height`、`width` 或 `num_inference_steps` 就能改变这些值。

```
prompt = (
    "A wide-angle wildlife photograph of a red fox standing alert in a snow-covered forest clearing at golden hour. "
    "The fox is centered in the frame, its thick orange winter coat contrasting with the fresh white snow, breath "
    "visible in the cold air. Snow-laden pine trees fill the softly blurred background, and low warm sunlight rakes "
    "across the scene from the left, casting long blue shadows."
)

fox = pipe(
    prompt=prompt,
    generator=torch.Generator().manual_seed(0),
    output="images"
)[0]
fox.save("fox.png")
```

### 图生图

用 `image` 参数传入一张参考图（或者更多）。把 prompt 写成你*想要*的那张图的描述文字，并把要做的改动包含在里面。

```
prompt = (
    "The same red fox in the same snow-covered forest clearing, now at night under a full moon: cool blue "
    "moonlight, deep shadows, stars visible through the pine branches, the fox's eyes catching the light."
)
night = pipe(
    prompt=prompt,
    image=fox, # from the previous text to image example
    generator=torch.Generator().manual_seed(0),
    output="images",
)[0]
night.save("night.png")
```

有多张参考图时，在 prompt 里用 `<ref_image_0>`、`<ref_image_1>`……按它们被传给 `image` 的顺序来指代它们：

```
red_fox = pipe(prompt="a red fox", generator=torch.Generator().manual_seed(0), output="images")[0]
bench = pipe(prompt="a wooden bench", generator=torch.Generator().manual_seed(0), output="images")[0]

combined = pipe(
    prompt="The fox from <ref_image_0> sitting on the wooden bench from <ref_image_1> in a snowy setting.",
    image=[red_fox, bench],
    output="images",
)[0]

combined.save("combined.png")
```

### 布局控制

在描述文字之后加上一份区域的 JSON 列表。每个区域有一个 `id`、一个 `bbox` 和一个 `desc`，描述文字里用 `<id>` 提到它。

> 框写作 [y_min, x_min, y_max, x_max]，y 在前，按 0–1000 的刻度。因为刻度是归一化的，同一个框适用于任意图像尺寸。

#### 在新图像里放置区域

```
layout_prompt = (
    "Minimalist graphic illustration featuring a black silhouette of a person <silhouette_1> centered against a "
    "solid, vibrant chartreuse background <background_1>. The figure is captured in a dynamic, mid-stride running "
    "pose, facing toward the left side of the frame. "
    '[{"id": "background_1", "bbox": [0, 0, 1000, 1000], "desc": "A flat field of neon yellow-green with a subtle '
    'paper texture and fine, organic grain."}, {"id": "silhouette_1", "bbox": [150, 150, 850, 850], "desc": "A '
    "black silhouette of a person in motion, made of dense stippled ink. The leading edges are solid; the trailing "
    'arm and leg dissolve into coarse square pixels and scattered dots."}]'
)

runner = pipe(prompt=layout_prompt, generator=torch.Generator().manual_seed(0), output="images")[0]
```

#### 在参考图内移动区域

做编辑时，每个区域要说明它的内容**来自**哪里（参考图里的 `src_bbox`）、要落到哪里（输出里的 `tgt_bbox`）。两个框一致的区域就留在原地。

这个例子把针织骑士往上、往左移动，同时钉住背景、悬崖、针、龙和火焰：

```
from diffusers.utils import load_image

knight_image = load_image("knight_orig.png")
edit_prompt = (
    "In <ref_image_0>, move the miniature grey amigurumi knight figure <knight_1> upwards and to the left along the "
    "yarn cliff <cliff_1>. Keep the rest of the image completely unchanged, preserving the blurred yarn backdrop "
    "<backdrop_1>, the large knitted dragon <dragon_1>, and the fiery orange thread <fire_1>. "
    '[{"id": "knight_1", "from": "ref_image_0", "src_bbox": [500, 150, 850, 350], "tgt_bbox": [194, 55, 544, 255], '
    '"desc": "A miniature amigurumi knight crocheted from thick grey woolen yarn."}, '
    '{"id": "backdrop_1", "from": "ref_image_0", "src_bbox": [0, 0, 1000, 1000], "tgt_bbox": [0, 0, 1000, 1000], '
    '"desc": "A soft, out-of-focus backdrop of cream and indigo knitted yarn."}, '
    '{"id": "cliff_1", "from": "ref_image_0", "src_bbox": [300, 0, 1000, 450], "tgt_bbox": [300, 0, 1000, 450], '
    '"desc": "A steep cliff of stacked yarn skeins in mustard, terracotta, and indigo."}, '
    '{"id": "needle_1", "from": "ref_image_0", "src_bbox": [420, 250, 550, 450], "tgt_bbox": [420, 250, 550, 450], '
    '"desc": "An oversized polished steel tapestry needle."}, '
    '{"id": "dragon_1", "from": "ref_image_0", "src_bbox": [100, 600, 950, 1000], "tgt_bbox": [100, 600, 950, 1000], '
    '"desc": "A large, fluffy knitted dragon in terracotta and mustard yarn."}, '
    '{"id": "fire_1", "from": "ref_image_0", "src_bbox": [350, 400, 650, 650], "tgt_bbox": [350, 400, 650, 650], '
    '"desc": "Curled puffs of fiery orange angora thread suspended in mid-air."}]'
)

moved = pipe(prompt=edit_prompt, image=knight_image, generator=torch.Generator().manual_seed(0), output="images")[0]
```

## 基础模型与量化变体

### 基础模型

上面的所有内容用的都是蒸馏版 checkpoint。base checkpoint 带 classifier-free guidance 跑 50 步，也是拿来做微调的那个（见 [LoRA 微调](https://huggingface.co/blog/flux-3#lora-finetuning)）。

```
pipe = ModularPipeline.from_pretrained("black-forest-labs/flux-3-image-klein-base")
pipe.load_components(dtype={"vae": torch.float32, "default": torch.bfloat16})
pipe.to("cuda")

pipe.guider = pipe.guider.new(guidance_scale=5.0)  # optional
image = pipe(prompt=prompt, output="images")[0]
```

### 单文件格式 checkpoint

Black Forest Labs 也把 transformer 以单个文件发布，有 `bf16`，也有两种量化格式：`fp8r`（按行 FP8）和 `nvfp4`。用 `from_single_file` 加载其中任意一个，然后按名称加载其余组件，这样就不会顺带把 bf16 的 transformer 也下载下来。

```
from diffusers import BFLQuantizationConfig, Flux3Transformer2DModel, ModularPipeline

model_id = "black-forest-labs/flux-3-image-klein-base"
variant = "fp8r"  # or "nvfp4"

transformer = Flux3Transformer2DModel.from_single_file(
    f"https://huggingface.co/{model_id}/blob/main/variants/{variant}/model.safetensors",
    config=model_id,
    subfolder="transformer",
    quantization_config=BFLQuantizationConfig(compute_dtype=torch.bfloat16),
    dtype=torch.bfloat16,
)

pipe = ModularPipeline.from_pretrained(model_id)
pipe.load_components(dtype=torch.bfloat16)
pipe.update_components(transformer=transformer)
pipe.to("cuda")
```

至于未量化的单文件，改用 `https://huggingface.co/{model_id}/blob/main/model.safetensors`，并去掉 `quantization_config`。

| 变体 | 有快速 kernel 的平台 | 其他 GPU |
| --- | --- | --- |
| `fp8r` | 计算能力 8.9 及以上（Ada、Hopper、Blackwell） | 每一步都对权重做反量化：显存更省，但没有加速 |
| `nvfp4` | Blackwell，需要版本一致的 `flashinfer-python` 和 `flashinfer-cubin` | 同上 |

## LoRA 微调

FLUX.3 同时支持文生图和图生图，这让它成为定制 LoRA 的绝佳底座。`diffusers` 为这两种任务都提供了 DreamBooth LoRA 训练脚本（你也可以用 [Ostris' AI Toolkit](https://github.com/ostris/ai-toolkit) 训练）。

下面是一个文生图的例子，从 [`multimodalart/1920-raider-waite-tarot-public-domain`](https://huggingface.co/datasets/multimodalart/1920-raider-waite-tarot-public-domain) 数据集学习塔罗牌风格，用 `trtcrd` 触发：

```
accelerate launch train_dreambooth_lora_flux3_klein.py \
  --pretrained_model_name_or_path="black-forest-labs/flux-3-image-klein-base" \
  --dataset_name="multimodalart/1920-raider-waite-tarot-public-domain" \
  --caption_column="caption" \
  --instance_prompt="trtcrd" \
  --output_dir="trained-flux3-tarot-lora" \
  --mixed_precision="bf16" \
  --resolution=1024 \
  --use_aspect_ratio_buckets \
  --train_batch_size=1 \
  --rank=16 \
  --lora_alpha=16 \
  --learning_rate=1e-4 \
  --lr_scheduler="constant" \
  --max_train_steps=1500 \
  --validation_prompt="a trtcrd of a cat, tarot style" \
  --validation_epochs=25 \
  --seed=0 \
  --push_to_hub
```

> 要降低显存占用，可以加上几个优化 flag：
>   --gradient_checkpointing \
>   --cache_latents \
>   --use_8bit_adam
> 
> --gradient_checkpointing 在反向传播时重算激活值（显存更低、稍慢一些），--cache_latents 预先编码图像并释放 VAE，--use_8bit_adam 把优化器状态保持在 8-bit。

有几个旋钮值得动手试验。下面的图组用不同的 LoRA rank 和优化器训练同一种塔罗风格；这些 adapter 都在 Hub 上的 [`diffusers-modular/flux3-tarot-lora`](https://huggingface.co/diffusers-modular/flux3-tarot-lora)。更多训练特性与配置记录在 [DreamBooth FLUX.3 README](https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/README_flux3_klein.md) 里。

[![FLUX.3 塔罗风格 LoRA 在不同 rank 与优化器下的表现：不加 LoRA 的 base 模型，然后是 rank 16、rank 8 和 rank 32（AdamW，lr 1e-4）以及一次 Prodigy 训练，用两条留出的 prompt 生成](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/flux3/tarot-lora-sweep.png)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/flux3/tarot-lora-sweep.png)

至于基于指令的编辑，图生图脚本（`train_dreambooth_lora_flux3_klein_img2img.py`）用（参考图、目标图、指令）三元组训练，其中参考图在 prompt 里以 `<ref_image_0>` 来指代。

## 运行成本

这一节我们谈谈这些模型的显存消耗和生成速度。

### 显存

| 名称 | 峰值已分配（加载后）GiBs | 峰值已分配（推理后）GiBs |
| --- | --- | --- |
| nvfp4 (RTX6000) | 13.4 | 15.3 |
| fp8r (H100) | 14.35 | 16.27 |
| bf16 (H100) | 18.80 | 20.72 |

如果你的显存更少：

- 加载一个[量化 transformer](https://huggingface.co/blog/flux-3#base-model-and-quantized-variants)。
- 单独运行文本编码器再把它释放掉。每张图片它只在去噪之前运行一次（见[编码一次，生成多张](https://huggingface.co/blog/flux-3#encode-once-generate-many)）。
- 打开自动 CPU offloading，它只在某个组件运行时才把它搬到 GPU 上（这一点我们没有做基准测试）

```
from diffusers import ComponentsManager, ModularPipeline

manager = ComponentsManager()
manager.enable_auto_cpu_offload(device="cuda")

pipe = ModularPipeline.from_pretrained("black-forest-labs/flux-3-image-klein", components_manager=manager)
pipe.load_components(dtype={"vae": torch.float32, "default": torch.bfloat16})
# no pipe.to("cuda"): the manager handles device placement
```

### 速度

蒸馏版 checkpoint（16 步）的端到端耗时，warmup 之后取三次运行的平均值：

| 工作流 | 输出尺寸 | 耗时 | 峰值显存 |
| --- | --- | --- | --- |
| 文生图 | 1024 × 1024 | 1.93 s | 23.8 GiB |
| 图生图，一张 1024 × 1024 的参考图 | 1024 × 1024 | 3.87 s | 23.8 GiB |
| 布局编辑（那个骑士），一张 1360 × 768 的参考图 | 1360 × 768 | 4.10 s | 23.8 GiB |

> 单张 NVIDIA H100 80GB，不做 offloading，使用默认 attention backend。

一张参考图大致会让耗时翻倍。参考 token 与文本、正在生成的图像进入同一个序列，所以一张 1024 × 1024 的参考图会给每次 transformer 调用加上 4,096 个 token

## 架构

我们把模型打开来看，一块一块来。模型接收三类 token：

- **文本**
- 正在生成的**带噪图像**
- 以及可选的**参考图像**

### 从像素到 token

FLUX.3 是一个用于图像生成的 latent-space flow 模型。也就是说，去噪器以 latents 为输入，也以 latents 为输出。我们用 VAE 把 latents 解码回像素。FLUX.3 用的是与 Flux.2 相同的 VAE 架构。

FLUX.2 的 VAE 在每个方向上把图像压缩 8 倍，得到 32 个通道；随后这份 latent 的每个 2 × 2 patch 被打包成一个 128 通道的 token。

所以**一个 token 覆盖 16 × 16 像素的 patch**，一张 1024 × 1024 的图像变成由 4,096 个 token 组成的 64 × 64 网格。带噪图像一开始就是形状完全一致的随机噪声。参考图走同一套 VAE 编码和打包流程，并保留它自己的尺寸。

### 从 prompt 到 token

文本编码器是 Qwen3-VL，一个视觉-语言模型。FLUX.3 不只取它的最后一层。它会读取该模型 36 层中**八**层的 hidden states（第 4、8、…、32 层）并把它们堆叠起来，于是每个文本 token 先变成一个 8 × 2560 = 20,480 维的向量，再由一个线性层把它投影到 transformer 的 3072 宽度。

这让 transformer 拿到语言模型好几个深度的特征，而不只是最后一层。prompt 会被 pad 到 80 个 token 的整数倍，而 transformer 也会 attend 到这些 padding，这就是管线每次调用只接收一条 prompt 的原因。

### 两个阶段

transformer 分两个阶段处理这些 token：

- **阶段 1：按模态分开的 blocks。** 每条流各自经过 5 个拥有独立权重的 block。文本有自己的 blocks，带噪图像有自己的，参考图像也有自己的。
- **阶段 2：joint blocks。** 几条流被拼接成一个序列 `[text | image | reference]`，随后经过 28 个共享同一组权重的 block。

两个阶段的差别在于*谁能 attend 到谁*。

在阶段 1，每条流只 attend 到自己，所以每类 token 先按自己的那套方式各自打磨。在阶段 2，一切都 attend 到一切，图像在这里从文本和参考图里学习。作为对比，FLUX.2 的 double-stream blocks 同样给文本和图像各自独立的权重，但从一开始就允许它们互相 attend。FLUX.3 是先把几条流彻底分开，再合并它们。

到最后，文本和参考 token 直接丢掉。只有图像 token 经过输出层，由它预测该把这些 token 朝干净图像推进哪一步。

### 一个 block 的内部

无论在哪个阶段，每个 block 的形状都一样。Attention 和 MLP 在同一个归一化后的输入上**并行**运行，两者之和被加回到 residual stream 上。

每个 block 都从一个自身不带可学习 scale 或 shift 的 LayerNorm 开始。scale、shift 和 gate 改由 timestep embedding 提供（这叫做 *modulation*）。在 attention 内部，query 和 key 会做 RMS 归一化，并加上旋转位置编码（RoPE），我们下面会看它。

在 joint block 里，所有 token 共享同一套权重，但文本、图像和参考 token 各自拿到自己的 scale、shift 和 gate。

```
def block(x, shift, scale, gate):      # shift, scale, gate come from the token's timestep embedding
    h = layer_norm(x)                  # no learned scale or shift
    h = (1 + scale) * h + shift
    q, k, v = to_q(h), to_k(h), to_v(h)
    q, k = rope(rms_norm(q)), rope(rms_norm(k))
    out = attention(q, k, v) + mlp(h)  # parallel, MLP is SwiGLU
    return x + gate * out
```

### 每个 token 都有自己的 timestep

在 FLUX.1 和 FLUX.2 里，一个 timestep embedding 调制所有 token。在 FLUX.3 里，调制取决于 token 是哪一类。

带噪图像的 token 由当前 timestep `t` 调制。文本和参考 token 始终由 timestep **0** 调制，意思是“干净，这里没有要去噪的东西”。所以哪怕一张参考图看起来和输出几乎一样，它也被标记成给定的上下文，而不是要生成的东西。

蒸馏版 checkpoint 是一个 *flow map*。它还会被告知其每一步跳到的 timestep。这第二个 timestep 有自己的 embedding，并被加到每个 token 的调制上，所以它的 16 步里每一步都能迈出更大的跨度。

### 四个维度上的位置

attention 自己并不知道一个 token 在哪里（这种现象叫 permutation equivariance）。RoPE 通过按 token 的位置旋转每个 query 和 key 来修正这一点。FLUX.3 使用四个位置轴 `(t, h, w, l)`（timestep、高度、宽度、序列长度），并给每个轴分配每个 128 维 attention head 的四分之一（32 个维度）：

| Token | t: timestep | h: 高度 | w: 宽度 | l: 序列长度 |
| --- | --- | --- | --- | --- |
| 文本 token *i* | 0 | 0 | 0 | *i* |
| 位于 (row, col) 的图像 token | 0 | row / 2 | col / 2 | 0 |
| 位于 (row, col) 的参考图 *k* | 0 | row / 2 | col / 2 | −(*k* + 1) |

文本 token 沿 `l` 排开，就像句子里的单词。图像和参考图是 `(h, w)` 上的二维网格，沿 `l` 彼此分开。因为一张参考图用的是和输出相同的 `(h, w)` 坐标，“参考图里的同一个位置”对模型来说有确切的含义，这正是 `src_bbox` / `tgt_bbox` 编辑所依赖的东西。

### 去噪循环

FLUX.3 是一个 flow-matching 模型。生成从纯噪声开始，在 50 步中的每一步，transformer 预测一个 *velocity*。这就是从噪声指向干净图像的方向。scheduler 沿它走一步。

在每一步，你还能读出模型当前对最终图像的猜测。在若干步上把这份猜测解码出来，就能看到图像是如何成形的：

## Modular Diffusers

FLUX.3 以 [Modular Diffusers](https://huggingface.co/docs/diffusers/main/en/modular_diffusers/overview) 管线的形式发布。

### 查看 workflows

你可以列出各个 workflow，并打印出每个 workflow 具体的 blocks，而不加载任何权重。

```
from diffusers import Flux3AutoBlocks

blocks = Flux3AutoBlocks()
print(blocks.available_workflows)
# ['text2image', 'image_conditioned']

print(list(blocks.get_workflow("text2image").sub_blocks))
# ['text_encoder', 'denoise.input', 'denoise.prepare_latents', 'denoise.set_timesteps',
#  'denoise.prepare_rope_inputs', 'denoise.denoise', 'denoise.after_denoise', 'decode']
```

`get_workflow()` 会解析掉 auto 分支，把实际将要运行的那串平铺步骤交给你。`print(blocks.get_workflow("image_conditioned").doc)` 会打印该 workflow 的组件、输入、默认值和输出。

### 编码一次，生成多张

把文本编码器拆出来，把 prompt 编码一次，释放它，然后从缓存的 embeddings 生成图像。

```
import torch
from diffusers import ModularPipeline

model_id = "black-forest-labs/flux-3-image-klein-base"

blocks = ModularPipeline.from_pretrained(model_id).blocks
text_blocks = blocks.sub_blocks.pop("text_encoder")  # `blocks` now starts at the VAE encoder

text_pipe = text_blocks.init_pipeline(model_id)
text_pipe.load_components(dtype=torch.bfloat16)
text_pipe.to("cuda")

state = text_pipe(prompt=prompt, negative_prompt="")  # no guider here, so ask for the negative embeddings

prompt_embeds = state.get("prompt_embeds")
negative_prompt_embeds = state.get("negative_prompt_embeds")

del text_pipe
torch.cuda.empty_cache()

image_pipe = blocks.init_pipeline(model_id)  # no text encoder to load
image_pipe.load_components(dtype={"vae": torch.float32, "default": torch.bfloat16})
image_pipe.to("cuda")

for seed in range(3):
    image = image_pipe(
        prompt_embeds=prompt_embeds,
        negative_prompt_embeds=negative_prompt_embeds,
        generator=torch.Generator().manual_seed(seed),
        output="images",
    )[0]
    image.save(f"{seed}.png")
```

### 在循环里加一步

上面那张去噪图就来自一个额外的 block，它记录模型在每一步对干净图像的猜测：

```
from diffusers.modular_pipelines import Flux3AutoBlocks, InputParam, ModularPipelineBlocks, OutputParam


class Flux3PreviewStep(ModularPipelineBlocks):
    model_name = "flux3"

    @property
    def inputs(self):
        return [InputParam("latents"), InputParam("noise_pred")]

    @property
    def intermediate_outputs(self):
        return [OutputParam("x0_previews", type_hint=list)]

    @torch.no_grad()
    def __call__(self, components, block_state, i, t):
        if i == 0:
            block_state.x0_previews = []
        sigma = t / 1000  # timesteps are sigmas scaled to [0, 1000]
        block_state.x0_previews.append(block_state.latents - sigma * block_state.noise_pred)  # x0 = x_t - sigma * v
        return components, block_state


blocks = Flux3AutoBlocks()
denoise_loop = blocks.sub_blocks["denoise"].sub_blocks["text2image"].sub_blocks["denoise"]
denoise_loop.sub_blocks.insert("preview", Flux3PreviewStep(), 1)  # between "denoiser" and "after_denoiser"

pipe = blocks.init_pipeline(model_id)
pipe.load_components(dtype={"vae": torch.float32, "default": torch.bfloat16})
pipe.to("cuda")

out = pipe(prompt=prompt, generator=torch.Generator().manual_seed(0), output=["x0_previews", "images"])
```
