## Inference for PROs 快速上手

使用方式简单到就是向你想跑的模型的 API 端点发一个 POST 请求。你需要在[token 设置页](https://huggingface.co/settings/tokens)获取 PRO 账户鉴权 token 并在请求中携带。例如在终端里用 [Meta Llama 3 8B Instruct](https://huggingface.co/meta-llama/Meta-Llama-3-8B-Instruct) 生成文本：

```
curl https://api-inference.huggingface.co/models/meta-llama/Meta-Llama-3-8b-Instruct \
    -X POST \
    -d '{"inputs": "In a surprising turn of events, "}' \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer <YOUR_TOKEN>"
```

会输出类似：

```
[
  {
    "generated_text": "In a surprising turn of events, 2021 has brought us not one, but TWO seasons of our beloved TV show, \"Stranger Things.\""
  }
]
```

你也可以使用很多熟悉的 transformers 生成参数，如 `temperature` 或 `max_new_tokens`：

```
curl https://api-inference.huggingface.co/models/meta-llama/Meta-Llama-3-8b-Instruct \
    -X POST \
    -d '{"inputs": "In a surprising turn of events, ", "parameters": {"temperature": 0.7, "max_new_tokens": 100}}' \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer <YOUR_TOKEN>"
```

生成参数细节见下文[*控制文本生成*](https://huggingface.co/blog/inference-pro#controlling-text-generation)。

想用 Python 发请求，可以利用 `huggingface_hub` Python 库中的便捷工具 `InferenceClient`：

```
pip install huggingface_hub
```

`InferenceClient` 是一个好用的包装器，让你轻松调用 Inference API 与 Inference Endpoints：

```
from huggingface_hub import InferenceClient

client = InferenceClient(model="meta-llama/Meta-Llama-3-8b-Instruct", token=YOUR_TOKEN)

output = client.text_generation("Can you please let us know more details about your ")
print(output)
```

如果不想每次实例化客户端时显式传 token，可以用 `notebook_login()`（Jupyter notebook）、`huggingface-cli login`（终端）或 `login(token=YOUR_TOKEN)`（其他场合）登录一次。之后 token 会被自动使用。

除 Python 外，你也可以用 JavaScript 把推理调用集成进你的 JS 或 Node 应用。看看 [huggingface.js](https://huggingface.co/docs/huggingface.js/index)！

## 应用

### 与 Llama 2 和 Code Llama 34B 聊天

为对话准备的模型，是按各自非常特定的聊天模板训练的。你必须注意模型期望的格式并在请求里复现它。

下面例子取自[我们的 Llama 2 博客](https://huggingface.co/blog/llama2#how-to-prompt-llama-2)，该文完整详细地描述了如何对模型发起对话查询：

```
prompt = """<s>[INST] <<SYS>>
You are a helpful, respectful and honest assistant. Always answer as helpfully as possible, while being safe.  Your answers should not include any harmful, unethical, racist, sexist, toxic, dangerous, or illegal content. Please ensure that your responses are socially unbiased and positive in nature.

If a question does not make any sense, or is not factually coherent, explain why instead of answering something not correct. If you don't know the answer to a question, please don't share false information.
<</SYS>>

There's a llama in my garden 😱 What should I do? [/INST]
"""

client = InferenceClient(model="codellama/CodeLlama-13b-hf", token=YOUR_TOKEN)
response = client.text_generation(prompt, max_new_tokens=200)
print(response)
```

这个例子展示了多轮对话第一条消息的结构。注意 `<<SYS>>` 分隔符用来提供*系统提示词*，告诉模型我们期望它如何表现。然后我们的查询插在 `[INST]` 分隔符之间。

如果想继续对话，要把模型回复追加进序列，然后发出新的追问指令。Llama 2 的提示模板总体结构如下：

```
<s>[INST] <<SYS>>
{{ system_prompt }}
<</SYS>>

{{ user_msg_1 }} [/INST] {{ model_answer_1 }} </s><s>[INST] {{ user_msg_2 }} [/INST]
```

Code Llama Instruct 也用同样格式，可以和一个懂代码的助手展开技术对话！

更多细节见[我们的 Llama 2 博客](https://huggingface.co/blog/llama2#how-to-prompt-llama-2)。

### 用 Code Llama 做代码填充

Code Llama 这类代码模型可以做代码补全，策略与前面的例子相同：给一个含代码或注释的起始字符串，模型会尝试用合理内容续写。代码模型还可以做*填充（infilling）*——更专门的任务：你提供前缀和后缀序列，模型预测中间该放什么。这对 IDE 扩展等应用很理想。看一个 Code Llama 例子：

```
client = InferenceClient(model="codellama/CodeLlama-13b-hf", token=YOUR_TOKEN)

prompt_prefix = 'def remove_non_ascii(s: str) -> str:\n    """ '
prompt_suffix = "\n    return result"

prompt = f"<PRE> {prompt_prefix} <SUF>{prompt_suffix} <MID>"

infilled = client.text_generation(prompt, max_new_tokens=150)
infilled = infilled.rstrip(" <EOT>")
print(f"{prompt_prefix}{infilled}{prompt_suffix}")
```

```
def remove_non_ascii(s: str) -> str:
    """ Remove non-ASCII characters from a string.

    Args:
        s (str): The string to remove non-ASCII characters from.

    Returns:
        str: The string with non-ASCII characters removed.
    """
    result = ""
    for c in s:
        if ord(c) < 128:
            result += c
    return result
```

如你所见，填充所用的格式遵循这个模式：

```
prompt = f"<PRE> {prompt_prefix} <SUF>{prompt_suffix} <MID>"
```

任务细节见 [https://huggingface.co/blog/codellama#code-completion](https://huggingface.co/blog/codellama#code-completion)。

### Stable Diffusion XL

```
sdxl = InferenceClient(model="stabilityai/stable-diffusion-xl-base-1.0", token=YOUR_TOKEN)
image = sdxl.text_to_image(

```

## Messages API

所有文本生成模型现在都支持 Messages API，兼容 OpenAI 客户端库，包括 LangChain 和 LlamaIndex。下面的片段演示如何用官方 `openai` 客户端库调用 Llama 3.1 70B：

```
from openai import OpenAI
import huggingface_hub

# Initialize the client, pointing it to one of the available models
client = OpenAI(
    base_url="https://api-inference.huggingface.co/v1/",
    api_key=huggingface_hub.get_token(),
)
chat_completion = client.chat.completions.create(
    model="meta-llama/Meta-Llama-3.1-70B-Instruct",
    messages=[
        {"role": "system", "content": "You are a helpful an honest programming assistant."},
        {"role": "user", "content": "Is Rust better than Python?"},
    ],
    stream=True,
    max_tokens=500
)

# iterate and print stream
for message in chat_completion:
    print(message.choices[0].delta.content, end="")
```

Messages API 更多细节请[看这篇帖子](https://huggingface.co/blog/tgi-messages-api)。

## 生成参数

### 控制文本生成

文本生成是个丰富的主题，针对不同目的存在多种生成策略，推荐[这篇优秀的综述](https://huggingface.co/blog/how-to-generate)。文本生成端点支持多种生成算法，可用以下参数配置：

- `do_sample`：设为 `False`（默认）时使用*贪心搜索*——在你给的提示词之后选概率最高的续写序列。贪心是确定性的，同样的输入总返回同样的结果。当 `do_sample` 为 `True` 时，token 从概率分布中采样，因此各次调用会有差异。
- `temperature`：控制我们想要的生成变化幅度。`0` 等价于贪心搜索。设置 `temperature` 时 `do_sample` 会自动开启，`top_k`、`top_p` 同理。做代码相关任务时我们希望变化小，因此推荐低 `temperature`。其他任务如开放式文本生成则推荐高一些。
- `top_k`：开启 Top-K 采样——模型从输入序列之后最可能的 `K` 个 token 中选。常见取值 10 到 50。
- `top_p`：开启 nucleus 采样——模型按需选取覆盖特定概率质量所需的尽量多的 token。若 `top_p` 为 0.9，则最可能的 90% token 参与采样，尾部 10% 忽略。
- `repetition_penalty`：尽量避免生成序列中的重复词。
- `seed`：可与采样结合使用的随机种子，用于复现。

除采样参数外，还可以用下列参数控制生成的整体方面：

- `max_new_tokens`：最多生成的新 token 数。默认 `20`，想要更长序列请调大。
- `return_full_text`：端点返回结果里是否包含输入序列。`InferenceClient` 默认 `False`，端点本身默认 `True`。
- `stop_sequences`：一系列在输出中出现即停止生成的字符串。

### 控制图像生成

想更细粒度控制 SDXL 端点生成的图像，可用以下参数：

- `negative_prompt`：一段文字，描述希望模型*避开*的内容。
- `guidance_scale`：希望模型多贴合提示词。过低不准，过高可能降低画质或产生伪影。
- `width` 与 `height`：目标图像尺寸。SDXL 在 768 到 1024 之间效果最好。
- `num_inference_steps`：去噪步数。越大质量可能更好但更慢。常见 20 到 50 步。

文生图更多细节建议查 [diffusers 库文档](https://huggingface.co/docs/diffusers/using-diffusers/sdxl)。

### 缓存

如果你重复跑同一个生成，会发现 API 返回的结果一样（即使你在用采样而非贪心）。因为近期结果会被缓存。要强制每次不同的响应，用 HTTP header 告诉服务器每次都重新生成：`x-use-cache: 0`。

用 `InferenceClient` 时，直接加到 `headers` 客户端属性上即可：

```
client = InferenceClient(model="meta-llama/Meta-Llama-3-8b-Instruct", token=YOUR_TOKEN)
client.headers["x-use-cache"] = "0"

output = client.text_generation("In a surprising turn of events, ", do_sample=True)
print(output)
```

### 流式

token 流式指服务器按模型生成顺序逐个返回 token。它可以向用户渐进展示生成过程，而不是等整段生成完。流式是终端体验的关键一环——它降低延迟，而延迟是流畅体验最要紧的因素之一。

用 `InferenceClient` 流式只需传 `stream=True` 并迭代响应：

```
for token in client.text_generation("How do you make cheese?", max_new_tokens=12, stream=True):
    print(token)

# To
# make
# cheese
#,
# you
# need
# to
# start
# with
# milk
```

要用 curl 访问 generate_stream 端点，加上 `-N`/`--no-buffer` 参数，禁用 curl 默认缓冲，让数据从服务器到达即显示。

```
curl -N https://api-inference.huggingface.co/models/meta-llama/Meta-Llama-3-8b-Instruct \
    -X POST \
    -d '{"inputs": "In a surprising turn of events, ", "parameters": {"temperature": 0.7, "max_new_tokens": 100}}' \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer <YOUR_TOKEN>"
```

**这会影响免费 Inference API 吗？**

不会。我们仍通过免费 API 开放数千个模型，让大家快速打样和探索模型能力。

**这会影响企业用户吗？**

**我能用自己的模型接 PRO Inference API 吗？**

免费 Inference API 已支持大量中小模型，涵盖多种库（diffusers、transformers、sentence transformers 等）。如果你有自定义模型或自定义推理逻辑，我们推荐用 [Inference Endpoints](https://ui.endpoints.huggingface.co/catalog)。
