# 到底在和谁对齐？重新思考 MiniMax M2 中的智能体泛化

很高兴看到社区深入探索我们的新 [MiniMax M2](https://huggingface.co/MiniMaxAI/MiniMax-M2)，许多人强调了它在复杂智能体任务上的出色技能。这让我尤其兴奋，因为我的工作正是围绕其后训练中的智能体对齐部分。在本文中，我想分享在该过程中我们学到的部分关键洞见和经验教训。

## 真正的智能体对齐问题：基准还是现实？

如果你用过 LLM 智能体，你一定感受过这种痛点：同一个模型在某个框架里可能表现得聪明绝顶，在另一个框架里却一无是处。一个智能体可能在工具使用排行榜上大杀四方，却在简单的真实世界任务上惨烈失败。这种基准表现与实际可用性之间的鸿沟，是该领域最大的挑战之一。

在设计 M2 时，我们就知道必须正面解决这个问题。这把我们引向两个核心、有时相互冲突的目标：

- **在开源基准上出类拔萃。** 基准对于衡量"纯粹"能力不可或缺。例如 BrowseComp 这样的基准测试的是精巧的搜索技能。虽然用户几乎不会问出"找到第 n 位作者姓名第三个字母是 'x' 的那篇论文"这样刻意编造的问题，但一个能解决它的模型证明了它具备强大的基础能力。
- **稳健地泛化到真实世界。** 这是更难、也更重要的部分。一个优秀的智能体必须在陌生的工具、IDE/CLI、智能体脚手架和用户配置下都可靠表现。它不能只会一招；它需要能够泛化。

那么，我们和谁对齐？答案是两者都是。我们与基准对齐以构建技能，但我们最终必须通过确保这些技能到处都能奏效来与用户对齐。

虽然拿下基准的方法值得改天深入探讨，我想聚焦于那个更棘手的第二个目标：我们如何为一个"狂野"世界训练智能体？

## 对交错式思考的需求

在项目早期，我们撞上了一堵令人沮丧的墙。智能体表现不一致，我们苦苦诊断原因。经过多次讨论，尤其与 @Junxian He 教授和 @Wenhu Chen 的交流，我们得出了第一个重大结论：智能体需要交错式思考（Interleaved Thinking）。

这意味着智能体的内心独白——它的"思考"——可以且应该在任务的任何时刻发生，而不像标准推理模型那样只在开头发生一次。这一设计至关重要，原因有二：

- **在长视界任务上保持专注。** 复杂的智能体任务有极长的上下文。开头的一次思考过程不足以维持指令遵循和连贯性。
- **适应外部扰动。** 这是关键区别。智能体任务引入了来自外部世界（即工具输出）持续、不可预测的扰动。模型必须足够鲁棒以处理这些扰动、诊断错误并提取有用信息。"思考"过程让模型能够不断重新评估并适应来自环境的新信息。

这一原则成为 M2 有效性的基石。

> M2 用户小贴士：因为 M2 依赖交错式思考，它的上下文就是它的记忆。为获得最佳性能，你必须保留完整的会话历史，包括思考步骤。我们注意到，许多关于性能差距的社区反馈都源于意外丢弃了这一关键上下文，而这在更简单的推理模型上是一种常见做法。

## 真正的泛化关乎扰动

我们最初的理论很简单：工具扩展就是智能体泛化。

我们从一个最小工具集（一个 Python 解释器、搜索引擎、一个浏览器）开始，构建工具调用能力的一个基线。路线图很清晰：扩展工具的数量和种类，智能体对未见工具的泛化能力就会自然跟上。

起初，这奏效了。我们的基准分数攀升到了可观的水平。但随着我们深挖，我们意识到我们在解决一个错误的问题。模型通过了测试，可只要我们稍微改变环境——比如换成不同的脚手架框架——它的性能就会暴跌。我们距离"实际可用"模型的目标还很远。

这引出了我们第二个、更深刻的认识：**智能体泛化不仅关乎适应新工具，更关乎适应模型整个操作空间中的扰动。**

[![Clipboard_Screenshot_1761817571](https://cdn-uploads.huggingface.co/production/uploads/676e38ad04af5bec20bc9faf/aK2lphyX3gNHePXgKrp2v.png)](https://cdn-uploads.huggingface.co/production/uploads/676e38ad04af5bec20bc9faf/aK2lphyX3gNHePXgKrp2v.png)

这听起来很抽象，所以我们来拆解一下。想想在一个智能体任务中有哪些东西可以改变：

- **工具信息**（Tool Info）和可用的工具集。
- 定义智能体人格与规则的**系统提示**（System Prompt）。
- **用户提示**（User Prompt）及其具体目标。
- **环境**本身（文件、代码库、API）。
- 每一步返回的**工具响应**（Tool Responses）。我们旧的"工具扩展"方法只处理了第一项，忽略了过程中其他所有部分的扰动。带着这一新理解，我们的团队构建了一条面向**全轨迹泛化**的完整数据流水线。它生成的数据训练模型在每一步都对扰动保持稳定。结果令人备受鼓舞。在内部测试中，我们向 M2 抛出晦涩的"冷启动"脚手架——我们几乎不曾考虑过的框架——它的表现超出了我们的预期。它的工具调用和指令遵循能力都漂亮地泛化了。

## 下一步是什么？

我们在 M2 上的工作教会了我们大量关于智能体、泛化和数据的知识，但它引出的问题比回答的还多。我们的许多想法还停留在白板上。在未来几个月里，我们将更深入地探索这些前沿，我们迫不及待地想为你带来下一代强大且真正有用的模型。
