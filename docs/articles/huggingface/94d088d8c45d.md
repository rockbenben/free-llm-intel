# Text Generation Inference 推出多后端（TRT-LLM、vLLM）支持

## 引言

自 2022 年首次发布以来，Text-Generation-Inference（TGI）一直为 Hugging Face 和 AI 社区提供一个专注于性能、可以轻松部署大语言模型（LLM）的解决方案。TGI 起初几乎无需写代码，就能从 Hugging Face Hub 加载模型并部署到 NVIDIA GPU 生产环境。之后支持逐步扩展到 AMD Instinct GPU、Intel GPU、AWS Trainium/Inferentia、Google TPU 和 Intel Gaudi。
多年来，涌现了多个推理解决方案，包括 vLLM、SGLang、llama.cpp、TensorRT-LLM 等，使整个生态出现分裂。不同的模型、硬件和用例可能需要特定的后端才能达到最优性能。然而，正确配置每个后端、管理许可证、并把它们集成到现有基础设施，对用户来说是挑战。

为了解决这个问题，我们很高兴引入 TGI Backends 的概念。这一新架构可以通过 TGI 作为统一的前端层，灵活接入上述任何方案。这一变化让社区更容易为其生产工作负载获得最佳性能，按自身的建模、硬件和性能需求切换后端。

Hugging Face 团队很高兴能与构建 vLLM、llama.cpp、TensorRT-LLM 的团队，以及 AWS、Google、NVIDIA、AMD 和 Intel 的团队共同贡献与协作，无论用户想使用哪个后端和哪种硬件，都能为 TGI 用户提供稳健且一致的用户体验。

## TGI Backend：揭秘底层

TGI 由多个组件构成，主要用 Rust 和 Python 编写。Rust 负责 HTTP 和调度层，Python 依然是建模的首选。

简而言之：Rust 让我们通过静态分析和基于编译器的内存安全保证，提升服务层的整体稳健性；它让我们能以同样的安全保证更容易地扩展到多核。在 HTTP 层和调度器上利用 Rust 的强类型系统，可以在绕开 Python 环境全局解释器锁（GIL）的同时避免内存问题、最大化并发。

说到 Rust……惊喜：这正是 TGI 集成新后端的起点 - 🤗

今年早些时候，TGI 团队着手开放底层的调节旋钮，把实际 HTTP 服务器与调度器这对耦合体解耦。这项工作引入了新的 Rust `trait Backend`，用于对接当前的推理引擎以及未来的引擎。

有了这个新的 `Backend` 接口（用 Rust 的说法是 trait），便为模块化铺平了道路，并真正可以把进来的请求路由到不同的建模与执行引擎。

## 展望未来：2025

TGI 新的多后端能力打开了许多有影响力的路线图机会。展望 2025，我们很高兴分享一些最让我们期待的 TGI 进展：

- **NVIDIA TensorRT-LLM 后端**：我们正在与 NVIDIA TensorRT-LLM 团队合作，把 NVIDIA GPU + TensorRT 的全部优化性能带给社区。这项工作将在随后的博客文章中更详细地介绍。它与我们的使命紧密相关——让 AI 构建者同时受益于开源的 `optimum-nvidia`（量化/构建/评估 TensorRT 兼容制品）以及 TGI+TRT-LLM，从而在 NVIDIA GPU 上轻松部署、执行和扩展。
- **Llama.cpp 后端**：我们正在与 llama.cpp 团队合作，扩展其对服务器生产场景的支持。TGI 的 llama.cpp 后端将为想在 Intel、AMD 或 ARM CPU 服务器上部署的人提供强大的 CPU 方案。
- **vLLM 后端**：我们正在为 vLLM 项目贡献代码，并计划在 2025 年第一季度把 vLLM 集成为 TGI 后端。
- **AWS Neuron 后端**：我们正在与 AWS 的 Neuron 团队合作，在 TGI 中原生支持 Inferentia 2 和 Trainium 2。
- **Google TPU 后端**：我们正在与 Google 的 Jetstream 和 TPU 团队合作，通过 TGI 提供最佳性能。

我们确信 TGI Backends 将帮助简化 LLM 部署，为所有 TGI 用户带来灵活性与性能。很快你就能直接在 [Inference Endpoints](https://huggingface.co/inference-endpoints/) 中使用 TGI Backends。客户将能够在多种硬件上使用 TGI Backends 轻松部署模型，开箱即得一流的性能与可靠性。

敬请期待下一篇博客，届时我们将深入探讨技术细节和即将推出的后端的性能基准！
