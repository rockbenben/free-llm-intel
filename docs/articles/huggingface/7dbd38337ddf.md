# 用 Inference Endpoints 实现极速 Whisper 转写

今天我们很高兴推出一款全新的、极速的 OpenAI Whisper 部署选项，托管在 [Inference Endpoints](https://endpoints.huggingface.co) 上。相比上一版本，它带来最高 8 倍的性能提升，让每个人都能一键部署专用、强大的转写模型，以高性价比的方式借助 AI 社区所做的出色工作。

通过这次发布，我们希望让 Inference Endpoints 更加以社区为中心，让任何人都能来参与贡献，在 Hugging Face 平台上打造出色的推理部署。我们希望携手社区，借助那些优秀且现成的开源技术，为广泛的任务提供优化过的部署方案。

Hugging Face 的独特之处在于它身处开源 AI 社区的核心位置，与个人、机构及产业伙伴紧密协作，这使它在面向各种硬件与软件部署 AI 推理时，成为多样性最强的平台。

## 推理技术栈

新的 Whisper 端点借助了优秀的开源社区项目。推理由 [vLLM 项目](https://github.com/vllm-project/vllm)驱动，它提供了在各种硬件系列——尤其是但不限于 NVIDIA GPU——上高效运行 AI 模型的方式。我们使用 vLLM 实现的 OpenAI Whisper 模型，从而能够在软件栈的更底层启用进一步优化。

在这次首发版本中，我们面向计算能力达到 8.9 或更高的 NVIDIA GPU（Ada Lovelace 架构），例如 L4 与 L40s，这解锁了一系列软件优化：

- PyTorch 编译（torch.compile）
- CUDA graphs
- float8 KV cache 使用 `torch.compile` 编译会以即时（JIT）方式生成优化过的 kernel，它可以修改计算图、重排运算、调用专用方法等等。

CUDA graphs 记录在 GPU 上发生的一系列顺序运算（即 kernel）的流程，并尝试把它们归并为更大的工作单元在 GPU 上执行。这种归并操作通过执行单个大得多的工作单元而非多个小单元，减少了数据搬运、同步和 GPU 调度开销。

最后同样重要的是，我们对激活进行动态量化，以降低 KV cache 带来的内存需求。计算以半精度进行（此处为 bfloat16），而输出以精简精度存储（float8 为 1 字节，bfloat16 为 2 字节），这让我们能在 KV cache 中存储更多元素，从而提高缓存命中率。

继续推进这一方向的路径有很多，我们正准备与社区携手把它做得更好！

## 基准测试

Whisper Large V3 的 RTFx 提升近 8 倍，在不损失转写质量的前提下实现快得多的推理。

我们评估了若干基于 Whisper 的模型——Whisper Large V3、Whisper Large V3-Turbo 与 Distil-Whisper Large V3.5——的转写质量与运行效率，并将它们与各自在 Transformers 库中的实现作对比，以在相同条件下评估准确率与解码速度。

我们跨 [Open ASR Leaderboard](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard) 的 8 个标准数据集计算了词错误率（WER），涵盖 AMI、GigaSpeech、LibriSpeech（Clean 与 Other）、SPGISpeech、Tedlium、VoxPopuli 和 Earnings22。这些数据集跨越不同领域和录音条件，确保对泛化能力和真实世界转写质量进行稳健评估。WER 通过计算被错误预测（插入、删除或替换）的词所占百分比来衡量转写准确率；WER 越低表示性能越好。三种 Whisper 变体的 WER 都与其 Transformer 基线相当。![Word Error Rate comparison](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/endpoints/fast-whisper-endpoints-bench-1.png)

为评估推理效率，我们从 rev16 长音频数据集中采样，该数据集包含超过 45 分钟的音频片段，代表真实的转写工作负载，例如会议、播客或访谈。我们测量了实时因子（RTFx），定义为音频时长与转写时间之比，并在各样本上取平均。所有模型都在单张 L4 GPU 上以 `bfloat16` 评估，并使用一致的解码设置（语言、beam size 与 batch size）。

## 推理

在已部署的模型端点上运行推理，只需几行 Python 代码即可完成；你也可以用相同的结构在 Javascript 或任何你熟悉的语言中实现。

下面是一小段代码，用于快速测试已部署的检查点。

```
import requests

ENDPOINT_URL = "https://<your‑hf‑endpoint>.cloud/api/v1/audio/transcriptions"  # 🌐 replace with your URL endpoint
HF_TOKEN     = "hf_xxxxxxxxxxxxxxxxxxxxxxxxxxxxx"                              # 🔑 replace with your HF token
AUDIO_FILE   = "sample.wav"                                                    # 🔊 path to your local audio file

headers = {"Authorization": f"Bearer {HF_TOKEN}"}

with open(AUDIO_FILE, "rb") as f:
    files = {"file": f.read()}

response = requests.post(ENDPOINT_URL, headers=headers, files=files)
response.raise_for_status()

print("Transcript:", response.json()["text"])
```
