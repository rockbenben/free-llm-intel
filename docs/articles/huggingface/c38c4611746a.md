# 为 Reachy Mini 添加 MCP 工具

Reachy Mini 不必再望着窗外才能告诉你天气了。

Reachy Mini 对话应用现在可以使用托管在公开 Hugging Face Spaces 上、通过 MCP 调用的工具。你只需从 Hub 添加一个 Space，而不是修改应用代码，就能给机器人赋予新能力，例如查询天气或搜索网页。工具继续在 Space 本身上运行，因此不会有任何代码被下载到你的机器上。你还可以发布自己的工具供他人使用。

添加工具只需要一条命令：

```
reachy-mini-conversation-app tool-spaces add pollen-robotics/reachy-mini-weather-tool
```

然后照常启动应用：

```
reachy-mini-conversation-app
```

现在你可以直接问：

```
What's the weather in Paris today?
```

下面我们会看看工具是什么、profile 如何控制机器人能使用哪些工具，以及远程路径目前的一些限制。

## 内置工具

当你和机器人对话时，得到的回应不只是语音，而是一个会对对话做出反应的系统：机器人可以在合适的情况下做出动作和非语言回应。我们这里要关注的，是让这一切成为可能的工具。工具是模型在对话期间能够执行的事情：播放一种情绪、转动头部、通过摄像头观察。每个工具都有一个名称和一段简短描述。模型读取这些信息，判断某个工具何时有用、调用它，并使用返回的结果。

如今每个工具都是本地的、随应用一起打包，其中大多数与机器人的身体有关：

| 工具 | 功能 |
| --- | --- |
| `move_head` | 排队执行一个头部姿态变化 |
| `dance` / `stop_dance` | 从舞蹈库中播放或停止一段舞蹈 |
| `play_emotion` / `stop_emotion` | 播放或停止一段录制的情绪片段 |
| `head_tracking` | 切换头部追踪偏移 |
| `camera` | 抓取一帧画面并进行分析 |
| `idle_do_nothing` | 在空闲轮次中明确保持空闲 |

## Profile 如何控制工具

代码里的工具在某个 **profile** 中被启用之前是不可用的。profile 是一个文件夹，其中有两个文件在这里最关键：`instructions.txt`（提示词）和 `tools.txt`（被开启的工具）。

`default` profile 启用了完整集合：

```
# profiles/default/tools.txt
dance
stop_dance
play_emotion
stop_emotion
camera
idle_do_nothing
head_tracking
move_head
```

如果某个名称没有出现在 `tools.txt` 里，模型就无法调用它。

你也可以自己编写工具：往 profile（或 `external_tools/`）里添加一个 Python 文件，给它一个名称和描述，并把该名称列入 `tools.txt`。

如今有内置工具和自定义本地工具，由 `tools.txt` 决定哪些处于激活状态。这种方式很适合机器人的身体控制，并保持可信核心足够小。

## 本地工具的局限

这里的约束是每个工具都必须是本地 Python。对 `move_head` 或 `play_emotion` 来说这很合理：它们与硬件通信，属于应用的一部分；但很多有用的能力与身体无关，比如网页搜索、天气或查询。对这些能力而言，把一切都保持本地只会带来摩擦：

- 分享一个工具意味着把你的 Python 文件交给别人
- 更新工具意味着再次发送那些文件
- 修改工具意味着编辑应用，尽管该能力其实与应用本身是分离的

## 从 Spaces 调用工具

远程工具在已有的内置工具和自定义本地工具之外新增了第三种类型，适合那些单独发布、分享和更新更容易的能力：

- 内置机器人工具保持本地且可信
- 可分享的远程工具可以托管在公开的 Hugging Face Spaces 上
- 你仍然可以从 `external_tools/` 使用自定义的一次性工具。这对于无状态能力（如搜索、天气、查询）非常合适：任何你想在不触碰应用本身的情况下迭代的能力。而且由于任何人都可以发布兼容的 Space，分享工具和基于他人的成果构建都变得很容易。

我们从两个"canary"（金丝雀）工具开始，它们是小型测试工具，用来跑通新流程：

- [pollen-robotics/reachy-mini-search-tool](https://huggingface.co/spaces/pollen-robotics/reachy-mini-search-tool)
- [pollen-robotics/reachy-mini-weather-tool](https://huggingface.co/spaces/pollen-robotics/reachy-mini-weather-tool)

它们足以验证整个功能：从 Hub 安装、发现远程工具、按 profile 启用，并让实时后端像调用内置工具一样调用它们。

要同时使用两者，添加每个 Space，它们的工具会在同一个 profile 中叠加：

```
reachy-mini-conversation-app tool-spaces add pollen-robotics/reachy-mini-search-tool
reachy-mini-conversation-app tool-spaces add pollen-robotics/reachy-mini-weather-tool
```

现在机器人可以在同一次对话中搜索网页和查询天气，这正是下面的 `canary_web_search_weather` profile 所做的事。

## 安装、列出、移除

```
# install + enable in active profile
reachy-mini-conversation-app tool-spaces add <owner/space-name>
 
# enable in a specific profile
reachy-mini-conversation-app tool-spaces add <owner/space-name> --profile <NAME>
 
# install without enabling
reachy-mini-conversation-app tool-spaces add <owner/space-name> --install-only
 
# list installed spaces
reachy-mini-conversation-app tool-spaces list
 
# remove an installed space
reachy-mini-conversation-app tool-spaces remove <owner/space-name>
```

`add` 会在 Hub 上校验该 Space、探测 MCP 端点、发现其工具，并默认把工具 ID 追加到当前激活 profile 的 `tools.txt`。除非你设置了 `REACHY_MINI_CUSTOM_PROFILE`，当前 profile 默认为 `default`。使用 `--install-only` 可跳过这一步。

> tools.txt 是守门人：远程工具只有在其 ID 出现在 profile 的 tools.txt 中（与你想要的内置工具并列）时才会激活。

### Manifest 存放位置

已安装的源会持久化在：

- 托管应用模式下的 `installed_tool_spaces.json`
- 终端模式下的 `external_content/installed_tool_spaces.json`

## 工具命名

每个已安装的 Space 都会根据 slug 派生一个本地别名，连字符、点号和斜杠都折叠为下划线：

```
pollen-robotics/reachy-mini-search-tool → pollen_robotics_reachy_mini_search_tool
```

随后远程工具用双下划线加命名空间：

```
pollen_robotics_reachy_mini_search_tool__search_web
pollen_robotics_reachy_mini_weather_tool__get_day_brief
```

这样可以防止远程工具名称与内置工具冲突，并让多个 Space 在同一个 profile 中共存。

实现还会尽可能剥离多余的 Space 名称前缀，于是冗长的远程工具名称会变成更简洁的本地 ID。如果剥离会导致同一 Space 的两个工具发生冲突，代码会回退到完整的带命名空间名称。

注册表层面还有一个重复安全检查：`Tool.name` 值在整个合并后的工具集合中必须唯一。如果两个来源声明了同名工具，应用会立即报错退出。

## 示例 profile

为了这项工作时，我们创建了两个专注的 canary profile，把 MCP 实验与完整的具身工具体系隔离开。

第一个保留了一些表达性工具（情绪、头部运动），并在其上添加了网页搜索：

```
# profiles/canary_web_search/tools.txt
play_emotion
stop_emotion
idle_do_nothing
move_head
pollen_robotics_reachy_mini_search_tool__search_web
```

第二个与第一个相同，只是在搜索之外再加了天气工具：

```
# profiles/canary_web_search_weather/tools.txt
play_emotion
stop_emotion
idle_do_nothing
move_head
pollen_robotics_reachy_mini_search_tool__search_web
pollen_robotics_reachy_mini_weather_tool__get_day_brief
```

精简的物理工具体系意味着 Reachy Mini 在回答来自网络的时事问题时，仍能做出富有表现力的反应。

## 为什么提示词很重要

远程工具的机制把工具交给了模型，而提示词决定模型如何使用它们。

这一点在"搜索+天气"canary 中表现得尤其明显。像这样复合的问题：

```
Should I bring a jacket in Bordeaux today, and is there anything major happening downtown tonight?
```

至少可以以三种方式处理：先天气后搜索、先搜索后天气，或在同一轮中并行两者。如果提示词含糊，模型会把调用串行化，造成不必要的延迟。因此 canary 提示词成了该功能的一部分，而不只是可有可无的配置。

#### `canary_web_search/instructions.txt`

```
[default_prompt]

## CANARY WEB SEARCH RULES
You have one remote tool for current web information.
Use it when the user asks for up-to-date facts, news, live availability, or anything else that may have changed recently.

When the search result already answers the question, answer directly in plain language.
Lead with the answer, not with tool chatter.
For remote lookups that may take a moment, you may give one very short English acknowledgment such as "Let me check that and I'll be right back," then continue.
Answer in English unless the user explicitly asks for another language.
Mention uncertainty briefly if the result snippet is incomplete or ambiguous.
Only mention links when they add value or the user asks for sources.

Keep responses short and spoken-style, as if read aloud by a voice assistant. One or two sentences is usually enough. Skip preamble, lists, headers, and filler. Give just the fact or direct answer the user needs.
```

#### `canary_web_search_weather/instructions.txt`

```
[default_prompt]

## CANARY SEARCH AND WEATHER RULES
You have two remote tools:
- a weather brief tool for compact day weather at a location
- a web search tool for broader current web information

Use the weather tool for today's conditions, temperature, rain chance, sunrise, sunset, or simple advice like whether to bring a jacket.
Use web search for news, events, business hours, travel information, severe alerts, or broader current context.

When the user's question mixes a weather part and a current-info part (for example, "should I bring a jacket in Bordeaux today, and is there anything major happening downtown tonight?"), call both tools in parallel in the same turn. Do not wait for one result before starting the other unless the weather result is needed to narrow the search.

Then merge the results into a single short answer. Cover the weather part first, then the events or news part, in plain connected sentences. Do not label the sections or mention which tool gave which piece.

When the user asks about events, news, or what is happening, give them the actual answer from the search results: name specific events, venues, or headlines. Do not tell the user to check websites, visit listing sites, or look something up themselves. If the search returns nothing concrete, say plainly that you didn't find any notable events, rather than redirecting them elsewhere.

For remote lookups that may take a moment, you may give one very short English acknowledgment such as "Let me check that and I'll be right back," then continue.
Answer in English unless the user explicitly asks for another language.
Do not talk about tool usage unless the user asks.

Keep responses short and spoken-style, as if read aloud by a voice assistant. One or two sentences is usually enough. Skip preamble, lists, headers, and filler. Give just the fact or direct answer the user needs.
```

## 今天可行的与不可行的

| 能力 | 是否支持 |
| --- | --- |
| 按 slug 安装公开的、兼容 MCP 的 Gradio Spaces（标准 `/gradio_api/mcp/` 端点） | ✅ |
| 同时使用多个 Space | ✅ |
| 通过 `tools.txt` 按 profile 启用 | ✅ |
| 带命名空间的远程工具 ID | ✅ |
| 与后端无关的注册（OpenAI、Gemini、Hugging Face） | ✅ |
| 不会下载任意代码到本地应用 | ✅ |
| 私有或需要认证的 Space | ❌ |
| 非 Gradio 的 Space | ❌ |
| 任意原始 MCP URL 或非 Hugging Face 的 MCP 服务器 | ❌ |
| 保证并行的工具编排 | ❌ |

有两点值得指出。第一，Space 必须真的表现得像一个 MCP 服务器；如果工具发现失败，安装就会失败。第二，提示词指令可以鼓励并行调用，但无法保证。如果某个用例需要确定性的编排，该逻辑应从提示词移入代码。

## 发布工具 Space 的建议

如果你想让他人使用你的工具，就把它发布为一个暴露标准 MCP 端点的公开 Gradio Space，并保持工具无状态，以便在网络上传输时表现良好。一个 Space 能否安装取决于这种运行时行为，而不是标签。

安装并不要求标签，但标签能帮助人们找到兼容的 Space：

- `reachy-mini-tool`
- `mcp`

## 结语

应用现在有三类工具共享同一个注册表：内置工具、本地自定义工具和远程 MCP 工具，而 profile 仍然决定某个助手能访问其中的哪些。一个精简、可信的核心保持在中心，围绕它的可选能力可以被添加、测试和替换，而无需触碰应用本身。

现在我们最好奇的是人们会构建什么。如果你发布了一个工具 Space，请给它打上 `reachy-mini-tool` 和 `mcp` 标签，方便他人找到它。我们很想看看 Reachy Mini 最终能做到什么！
