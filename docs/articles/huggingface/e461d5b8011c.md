[Dreambooth](https://dreambooth.github.io/) 是一种用特殊形式的微调给 [Stable Diffusion](https://huggingface.co/blog/stable_diffusion) 教授新概念的技术。有人用它加上自己的几张照片，把自己放进各种奇幻场景；也有人用它来引入新的风格。[🧨 Diffusers](https://github.com/huggingface/diffusers) 提供了一个 Dreambooth [训练脚本](https://github.com/huggingface/diffusers/tree/main/examples/dreambooth)。训练本身花不了太久，但难的是选对一组超参数，而且很容易过拟合。

我们做了大量实验来分析 Dreambooth 中不同设置的影响。这篇博客介绍我们的发现，以及一些在 Stable Diffusion 上用 Dreambooth 微调时提升效果的小技巧。

开始之前请注意：这种方法绝不能用于恶意目的、绝不能以任何方式造成伤害、也不能在当事人不知情的情况下冒充他们。用该方法训练出的模型仍然受约束于规范 Stable Diffusion 模型分发的 [CreativeML Open RAIL-M 许可证](https://huggingface.co/spaces/CompVis/stable-diffusion-license)。

*注：本文的早期版本曾[以 W&B 报告的形式发布](https://wandb.ai/psuraj/dreambooth/reports/Dreambooth-Training-Analysis--VmlldzoyNzk0NDc3)*。

## TL;DR：推荐设置

- Dreambooth 很容易快速过拟合。要得到高质量图像，必须在训练步数和学习率之间找到"甜蜜点"。我们建议使用较低的学习率，并逐步增加训练步数直到效果满意为止。
- Dreambooth 训练人脸需要更多步数。在我们的实验里，batch size 为 2、学习率 1e-6 时，800–1200 步效果不错。
- 训练人脸时，prior preservation（先验保持）对避免过拟合很重要。对其他主体则影响不大。
- 如果生成的图像噪点多或质量下降，多半是过拟合了。先按上面的建议避免过拟合；若图像仍有噪声，改用 DDIM scheduler 或多跑一些推理步数（我们的实验中约 100 步效果良好）。
- 在微调 UNet 的同时一并训练文本编码器，对质量影响很大。我们最好的结果来自"微调文本编码器 + 低学习率 + 合适步数"的组合。不过微调文本编码器需要更多显存，最好有至少 24 GB RAM 的 GPU。借助 8-bit Adam、`fp16` 训练或梯度累积等技术，在 Google Colab 或 Kaggle 提供的 16 GB GPU 上也能训练。
- 带 EMA 与不带 EMA 微调，结果差不多。
- 训练 Dreambooth 并不一定要用 `sks` 这个词。最早的实现用它，因为它是词表里一个罕见的 token——但它其实是"步枪"的意思。我们的实验以及例如 [@nitrosocke](https://huggingface.co/nitrosocke) 的实验都表明：直接选用你描述目标对象时自然会用的词即可。

## 学习率的影响

Dreambooth 过拟合非常快。要得到好结果，得针对你的数据集调好学习率和训练步数。在我们的实验中（详见下文），我们在四个不同数据集上分别用高、低学习率微调。所有情况下，低学习率的结果都更好。

## 实验设置

所有实验都使用 [`train_dreambooth.py`](https://github.com/huggingface/diffusers/tree/main/examples/dreambooth) 脚本、`AdamW` 优化器，在 2 块 40GB A100 上完成。我们使用相同的随机种子，各次运行保持除学习率、训练步数、是否使用 prior preservation 之外的所有超参数一致。

前 3 个例子（各种物件）以 batch size 4（每卡 2）微调 400 步，高学习率取 `5e-6`、低学习率取 `2e-6`，未使用 prior preservation。

最后一组实验是往模型里加入一个人类主体。这次我们使用 prior preservation，batch size 为 2（每卡 1），分别训练 800 和 1200 步。高学习率同样为 `5e-6`，低学习率为 `2e-6`。

注意：可以用 8-bit Adam、`fp16` 训练或梯度累积来降低显存需求，从而在 16 GB 显存的 GPU 上复现类似实验。

### 初步结果小结

用 Dreambooth 训练 Stable Diffusion 想得到好结果，针对数据集调好学习率和训练步数非常关键。

- 高学习率 + 过多训练步数会导致过拟合：无论用什么提示词，模型基本都只会生成训练数据里的图像。
- 低学习率 + 步数太少会导致欠拟合：模型生成不出我们试图引入的概念。

人脸更难训练。我们的实验里，物件用 `2e-6` 学习率、`400` 步就够了，但人脸需要 `1e-6`（或 `2e-6`）配合约 1200 步。

一旦过拟合，图像质量会明显恶化，而过拟合发生在：

- 学习率太高时。
- 训练步数太多时。
- 训练人脸时不使用 prior preservation——下一节会展示。

## 训练人脸时使用 Prior Preservation

Prior preservation 是一种微调技术，会把待训练类别的额外图像也纳入训练。例如，如果我们想往模型里加入一个新人物，需要保持的*类别*就是*人*。Prior preservation 的思路是：用新人物照片和其他人的照片一起训练，从而减轻过拟合。美妙之处在于，这些额外的类别图像可以直接用 Stable Diffusion 模型自己生成！训练脚本可以自动完成这件事，你也可以自己准备一个存放 prior preservation 图像的文件夹。

使用 prior preservation，1200 步，lr=`2e-6`。 [![Faces, prior preservation](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dreambooth-assets/7_faces_with_prior.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dreambooth-assets/7_faces_with_prior.jpg)

不使用 prior preservation，1200 步，lr=`2e-6`。 [![Faces, prior preservation](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dreambooth-assets/8_faces_no_prior.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dreambooth-assets/8_faces_no_prior.jpg)

可以看到，使用 prior preservation 效果更好，但仍有一些噪斑。是时候上点额外的技巧了！

## Scheduler 的影响

在之前的例子里，我们在推理过程中使用 `PNDM` scheduler 采样。我们观察到，当模型过拟合时，`DDIM` 通常明显好于 `PNDM` 和 `LMSDiscrete`。此外，多跑几步推理也能提升质量：100 步是个不错的选择。额外的步骤有助于把一些噪斑"展开"成图像细节。

## 微调文本编码器

Dreambooth 原论文描述的方法是微调模型的 UNet 组件、保持文本编码器冻结。但我们观察到，微调编码器能带来更好的结果。在其他 Dreambooth 实现中看到这种做法后，我们也做了实验——结果令人惊艳！

冻结文本编码器 [![Frozen text encoder](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dreambooth-assets/f_froxen_encoder.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dreambooth-assets/f_froxen_encoder.jpg)

微调文本编码器 [![Fine-tuned text encoder](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dreambooth-assets/g_unfrozen_encoder.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dreambooth-assets/g_unfrozen_encoder.jpg)

微调文本编码器能产生最好的结果，尤其是人脸。它生成的图像更真实、更不容易过拟合，提示词遵循能力也更好，能处理更复杂的提示词。

## 尾声：Textual Inversion + Dreambooth

最后我们还做了一个把 [Textual Inversion](https://textual-inversion.github.io) 与 Dreambooth 结合的实验。两种技术目标相似，但做法不同。

实验中我们先跑了 2000 步 textual inversion；然后在此基础上用 `1e-6` 的学习率再跑 500 步 Dreambooth。结果如下：

[![Textual Inversion + Dreambooth](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dreambooth-assets/h_textual_inversion_dreambooth.jpg)](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/blog/dreambooth-assets/h_textual_inversion_dreambooth.jpg)

我们认为这比单纯跑 Dreambooth 好得多，但仍不如整体微调文本编码器的效果。它似乎更容易照搬训练图的风格，可能对这些图过拟合了。我们没有继续深挖这个组合，但它可能是提升 Dreambooth 又能把流程塞进 16 GB GPU 的一个有趣替代方案。欢迎尝试并向我们分享你的结果！
