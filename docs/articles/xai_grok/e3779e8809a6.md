### 回合结束后自动捕捉

回合完成后，Grok 会在后台复盘该回合，记录任何有长期价值的东西：规约、决策和项目事实。捕捉在每个完成的回合上运行，不会打断会话。

### 以 Markdown 存储

笔记是 markdown 文件，一个主题一个文件。每个项目有自己的 workspace 作用域，另有一个全局作用域存放适用于所有地方的偏好。`/dream` 会把新观察合并到所属主题中，`/memory` 则按磁盘上的原样展示这些文件。

### 在后续会话中读回

在开始相关工作之前，Grok 会读取覆盖该区域的主题并加以应用——包括那些对话中从未提到该主题的会话。当前对话中的指令优先于任何笔记内容。

### 回合结束后自动捕捉

回合完成后，Grok 会在后台复盘该回合，记录任何有长期价值的东西：规约、决策和项目事实。捕捉在每个完成的回合上运行，不会打断会话。

## [它记住什么](https://x.ai/news/grok-build-memory#what-it-remembers)

记忆保存的是最可能在后续会话中有用的细节：团队如何编写和评审代码、决策及其背后的理由、关于项目的持久事实——从某个子系统在哪里，到用哪条命令跑测试套件。任务状态、未定的结论、机密，以及仓库或其文档已经覆盖的内容，都会被排除在外。

笔记按项目分别保存，另有一套全局笔记存放处处适用的偏好。

## [在后台写入](https://x.ai/news/grok-build-memory#written-in-the-background)

捕捉在回合完成后运行，从不阻塞会话。Grok 复盘完成的回合，把值得保留的内容写成 markdown 笔记，然后继续。随着时间推移，`/dream` 会把这些笔记折叠进一个主题一个文件的主题文件里，于是每个项目最终拥有一小组整理有序的参考。

当你回到一个项目，Grok 会读取覆盖其即将改动区域的主题。当前对话中的指令优先于任何笔记内容。

## [浏览记忆](https://x.ai/news/grok-build-memory#browsing-memory)

`/memory` 打开一个只读浏览器，按作用域分组展示每个记忆文件，并预览选中文件。这是查看某次会话产出了什么的最快方式，也是当笔记出错时找到该编辑文件的最快方式。

## [新命令](https://x.ai/news/grok-build-memory#new-commands)

- `/memory` 打开上面所示的浏览器。
- `/dream` 把近期的笔记整理进主题文件，例如 `topics/testing.md`。Dream 也会在后台定期自动运行。

## [可用性](https://x.ai/news/grok-build-memory#availability)

记忆功能现已在 Grok Build 中提供。它作用于新会话：运行 `/new` 或启动一个全新的 `grok`，笔记会在第一个完成的回合之后开始积累。
