## [何时使用 workflow](https://x.ai/news/workflows#when-to-use-a-workflow)

Workflow 是为那些单靠一场对话装不下的复杂多面任务而生：审阅一个巨大 PR 里的每个特性、分诊最近 100 个 issue、针对某类 bug 审计整个代码库。如果工作能拆成许多独立的部分、并且应以一份清晰报告收尾，就要一个 workflow。

## [工作原理](https://x.ai/news/workflows#how-it-works)

Grok 把任务规划成一个小脚本：工作的各个阶段、每个阶段的智能体，以及它们的结果如何汇总。每个智能体都从干净、聚焦的上下文开始，规划还能内置单次执行做不到的检查——比如让独立的质疑者在任何发现进入最终报告前先验证它。

每次运行有 128 个智能体的预算，大型任务最多 1,024。进度随运行实时保存，暂停与恢复绝不会重做已完成的工作。运行 `/workflows` 可实时观看：逐阶段推进，附每个智能体的 token 数。

## [保存与复用 workflow](https://x.ai/news/workflows#saving-and-reusing-workflows)

Grok 根据你的请求编写 workflow，启动前先做冒烟检查，并在多次运行之间持续改进——你从不需要自己写脚本。一个好用的就留下：`.grok/workflows/` 中的 workflow 与团队共享，`~/.grok/workflows/` 中的则随你去到任何地方。每个保存的 workflow 变成一条可带参数的专属斜杠命令——所以保留了上面演示的 PR 审阅后，下一次审阅只需 `/pr-review 5137`。

`/deep-research` 内建随发：它把研究问题扇出给并行调查员，逐条对照来源验证每个论断，最后返回一份带引用的报告。

## [今天就来试试](https://x.ai/news/workflows#try-it-today)

一些可以试试的例子：

- "triage the last 100 Linear issues and give me a top-10 action list"
