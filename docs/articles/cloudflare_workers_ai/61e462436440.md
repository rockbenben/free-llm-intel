# Workers AI - 为 gpt-oss 模型提供 Chat Completions API 支持并改进工具调用

为 gpt-oss 模型提供 Chat Completions API 支持并改进 tool calling

- [`@cf/openai/gpt-oss-120b`](https://developers.cloudflare.com/workers-ai/models/gpt-oss-120b/) 和 [`@cf/openai/gpt-oss-20b`](https://developers.cloudflare.com/workers-ai/models/gpt-oss-20b/) 现已支持 Chat Completions API 格式。可以把 `/v1/chat/completions` 与 `messages` 数组配合使用，也可以使用 `/ai/run`——它会动态识别你的输入格式，并接受 Chat Completions（`messages`）、旧版 Completions（`prompt`）或 Responses API（`input`）。
- **[Bug 修复]** 修复了多个文本生成模型 schema 中的一个缺陷：消息对象里的 `content` 字段此前只接受字符串值。现在该字段正确接受字符串内容和数组内容（用于多模态输入的结构化 content part）。该修复适用于所有受影响的 chat 模型，包括 GPT-OSS 系列模型、Llama 3.x、Mistral、Qwen 等。
- **[Bug 修复]** tool call 的往返现在可以正常工作。binding 不再拒绝由它自己生成的 `tool_call_id` 值，修复了多轮 tool calling 会话的问题。
- **[Bug 修复]** `content: null` 且带 `tool_calls` 的 assistant 消息，现在在 Workers AI binding 和 REST API（`/v1/chat/completions`）中都能被接受，修复了 tool call 往返失败的问题。
- **[Bug 修复]** 流式响应现在只在 usage chunk 上正确上报 `finish_reason`，与 OpenAI 的流式行为保持一致，避免出现重复的 finish 事件。
- **[Bug 修复]** `/v1/chat/completions` 现在保留模型返回的原始 tool call ID，而不再重新生成。此前该 endpoint 会生成新 ID，导致多轮 tool calling 被破坏，因为 AI SDK 客户端无法把工具结果对应回它原本的调用。
- **[Bug 修复]** 用到工具时，`/v1/chat/completions` 现在会在最后一个 usage chunk 中正确上报 `finish_reason: "tool_calls"`。此前它硬编码为 `finish_reason: "stop"`，导致 AI SDK 客户端以为对话已经完成，从而不去执行 tool call。
