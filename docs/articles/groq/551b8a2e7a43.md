# 提示词缓存上线

### 新增[Prompt Caching](#prompt-caching)

prompt caching 会在近期请求共享同一前缀时，自动复用这些请求已经完成的计算，从而带来显著的成本节省和更快的响应时间；同时缓存只存放在会自动过期的易失性（volatile）存储中，因此数据隐私也得以保持。

**工作原理**

* 前缀匹配：当你发送一次请求时，系统会检查并识别出与近期请求相匹配的前缀，这些都临时存放在易失性内存中。可匹配的前缀包括 system prompt、工具定义、few-shot 示例等等。
* 缓存命中：如果找到了匹配的前缀，就会复用已缓存的计算，大幅降低延迟，并且缓存部分的 token 成本下降 50%。
* 缓存未命中：如果没有匹配，你的 prompt 会被正常处理，同时该前缀会被临时缓存起来，以备后续可能的匹配。
* 自动过期：所有缓存数据都会在几小时内自动过期，这有助于在保留上述收益的同时确保隐私。

prompt caching 从今天起陆续上线到 [Kimi K2](https://console.groq.com/docs/model/moonshotai/kimi-k2-instruct)，很快还会支持更多模型。这项能力在你所有的 API 请求上自动生效，无需改动代码，也不额外收费。

[在我们的文档中了解更多关于 prompt caching 的信息。](https://console.groq.com/docs/prompt-caching)
