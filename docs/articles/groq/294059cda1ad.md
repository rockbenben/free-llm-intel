## 什么是上下文长度？

当企业寻求利用大语言模型（LLM）构建对话式 AI、生成式 AI 和分析能力时，一个关键因素常被忽视：上下文长度（context length），也叫上下文窗口（context window）。LLM 能处理的输入文本长度，不仅显著影响其性能与质量，还决定了它能支撑哪类解决方案和用户体验。本文将探讨 LLM 上下文长度的重要性，并就如何为你的业务应用选择最佳上下文长度给出实用建议，确保你从 AI 投资中获得最大回报。

上下文长度指 LLM 单次输入能处理的最大 token 数（词、字符或子词）。这个上限通常由模型架构、训练数据和计算资源决定。例如，主流 LLM 的规模从 GPT-1 的 512 tokens，到 Llama 系列——Llama 2 的 4,096、Llama 3 的 8,192，一路到 Llama 3.1 的 128,000。

在接受 [Lex Friedman 关于 LLM 未来的访谈](https://www.youtube.com/watch?v=pJ3aygJnc9M)时，OpenAI CEO Sam Altman 评论道：**"如果我们大胆畅想遥远的未来……上下文长度将达到数十亿。你会把你所有的信息、你所有的历史都喂给它，它会越来越了解你。"**

## 上下文长度对 LLM 性能与质量的影响

上下文长度对 LLM 性能有重大影响，尤其是在要求准确性和相关性的业务应用中。一般来说，更长的上下文带来更高质量的输出，而更短的上下文则带来更快的性能。

上下文长度可能从以下几个方面影响你的 LLM 应用：

- 理解问题：更长的上下文意味着用户可以输入更长的指令，让 LLM 有机会对提示中的词句与想法建立更细腻的理解。这能提升对话式 AI、文本摘要、情感分析等任务的理解力和准确度。此外，更长的上下文对编程任务（如代码补全和调试）也有帮助，因为 LLM 可以理解代码的更大范围语境，给出更准确、更相关的建议。
- 更多上下文与迭代：模型输入不仅可以包含用户的查询，还可以包含给模型提供更多背景的其他信息，比如到目前为止的整段对话，或者可能有用或必要的内容。例如，用户想让模型帮忙改写一篇文章，输入就不只要包含请求，还要包含原稿。这在聊天机器人等应用中尤其重要——理解整段对话和额外的相关用户信息至关重要。这些额外上下文还能让 LLM 通过迭代改进回应，用户可能因此看到更高质量的输出。
- 效率与可扩展性：更短的上下文可以带来更快的处理速度和更低的计算成本，但代价可能是准确性和相关性的下降。

一些提供商会标榜自己的速度，但对上下文长度这个关键参数——无论选模型还是选提供商来驱动应用都必须弄清——并不总是透明。别的厂商靠削减上下文长度来拼速度，而 Groq 为部分模型提供多种上下文长度供你按用例选择优化，全部信息都清楚列在我们的定价页上。

## 何时使用短上下文长度

有些 AI 应用用短上下文长度就够了。例如，处理产品评论短句或社交媒体帖子、评论等短输入的情感分析方案，可能只需要 256 个 token 就能胜任。只允许有限用户输入的聊天机器人也一样。在这些情况下，开发者可以选择限制上下文长度，以优化推理速度和效率。

短上下文长度需要考虑的一些影响：

- 更明确的指令：系统提示（给模型的、指导其如何回应用户查询的指令）需要更简洁、更聚焦，为 LLM 提供清晰明确的指示，因为模型可用于理解任务的上下文有限。提醒一下：系统提示本身也占用 token，会计入模型的上下文长度。
- 更少的假设：系统提示不应过多假设用户意图或语境，因为 LLM 可能没有足够信息推断出正确含义。
- 更具体的关键词：系统提示应包含具体关键词或短语，帮助 LLM 理解任务并生成相关回应。
- 更少的上下文依赖：系统提示可能无法依赖既往对话或用户历史等上下文信息来为 LLM 的回答提供参考。

## 何时需要更长的上下文长度

许多 AI 方案需要更长的上下文长度才能输出高质量结果。例如，凡是交付长文本内容（文章、博客、论文）的方案，都需要大量输入来帮助构建语境，才能产出高质量的输出。那些与用户来回对话、后续问题建立在此前输出之上的方案，输入会迅速膨胀，同样需要更长的上下文。

我们以 [GroqChat](https://groq.com/) 演示一下。假设你要去一座远方城市——我们选阿姆斯特丹。你问 GroqChat："帮我规划一份阿姆斯特丹三天的行程，包括具体的玩乐推荐和餐厅推荐。"GroqChat 瞬间（使用 Llama 3-8b，8196 上下文长度，1200 tokens/秒）生成了一份行程。把鼠标移到 1200 这个速度指标上，你会看到输入只有 49 个 token。

但接下来你想在这个查询上继续迭代，问它："再加点冒险色彩，多推荐几家本地人常去的隐秘餐厅。"回应仍然是瞬间返回，但这次把鼠标移到速度指标上，你会看到输入是 946 个 token（大约），因为输入串包含了上一次查询的全部输出。如此迭代几次，你就会看到，很快便会超出模型 8196 token 的上下文上限。

类似地，医疗或金融等特定领域可能需要更长的上下文长度来捕捉输入文本中的复杂关系与细微差别。输入可能包含大量客户数据。把这些数据放进输入，意味着模型可以在回答中使用这些语境但不会存储它，这对隐私很重要（例如 HIPAA 合规）。

在更长的上下文下，系统提示可以更加细腻、更依赖语境。用户可以在系统提示中提供更多背景信息，告诉模型自己的"人设"，并添加何时调用特定工具（agent）的指令。长上下文长度需要考虑的一些影响：

- 更少的显式指令：系统提示可以不必那么直白，依靠 LLM 从对话中先前消息理解语境并生成相关回应的能力。
- 更多的假设：由于能包含更多上下文，更长的系统提示可以对用户意图或语境做更多假设，因为 LLM 有更多信息来推断正确含义。
- 更少的特定关键词：系统提示可能不需要包含特定关键词或短语，因为 LLM 能自行理解语境并生成相关回应。

## 长上下文的潜在应用场景

### 多智能体方案

构建更复杂 AI 方案的企业和开发者，常采用多智能体（multi-agent）方式来开发。这类程序使用多个模型，通常各司其职，并行或串行运行。这些模型处理完各自的任务后，会把输出作为输入传给下一个模型，因此输入长度可能变得相当长。在考虑上下文长度需求时，业务技术人员和开发者需要评估自己是否会使用多智能体 AI 方案。

### 检索增强生成

LLM 可以通过 Retrieval Augmented Generation (RAG) 框架增强：把 LLM 的文本生成能力与一个更小、更专门的模型结合，从数据库或知识图谱中检索相关信息，再用检索到的信息增强生成的文本。在更长的上下文窗口下，RAG 模型能更好地理解主题、实体及相关系，从而给出更准确、更相关的回答。更长的上下文还能让模型捕捉细微差别与细节、理解歧义术语、生成佐证和示例。这意味着更连贯、流畅、有说服力的回答，能更好地处理复杂主题和追问。上下文长度足够长甚至可以让 RAG 变得不必要——如果上下文窗口足够大、文档足够短，全部内容都能直接放进上下文窗口。

### 代码类方案

借助更长的上下文窗口，代码类方案可以分析处理跨越很长时间段的序列数据，如文本或时间序列数据。这些方案能捕捉数据中细腻的模式与关系，提升准确性和决策能力。这在语言建模等应用中特别有价值——更长的上下文窗口能实现更准确的预测和更自然的语言生成。代码类方案还能快速高效地处理海量数据，使预测性维护、需求预测、异常检测等应用得以进行实时分析与处理。此外，这些方案易于适配不同用例和领域，是希望从数据中挖掘洞察与价值的开发者和组织的有力选择。

## 该问哪些问题

上下文长度是对比和选择 AI 方案所用模型时的关键考量。短上下文模型通常性能更快，但质量可能较低，尤其是复杂任务；长上下文模型生成更高质量的输出，但性能可能较低。

业务技术人员应该问的问题：

- 我的方案的用例和用户体验要求是什么？我的用户可以接受短上下文的限制吗？
- 我的方案有多复杂？模型是否需要输入流中提供更多上下文（如用户数据、源材料、累计对话）才能给出好结果？
- 开发者是否会使用多个智能体和模型来构建该方案？

## 处理上下文长度的最佳实践

要让你的 LLM 应用发挥最大价值，请遵循这些最佳实践：

- 尝试不同上下文长度：用不同上下文长度测试你的应用，确定特定用例下的最优长度。
- 把上下文长度当作超参数：将上下文长度视为可以为你的具体应用调节和优化的超参数。
- 考虑使用分层或多分辨率模型：这类模型可以在多种分辨率上处理输入文本，对长输入文本的处理更高效、更有效。
- 监控性能并调整：持续监控应用性能，按需调整上下文长度，确保最优结果。
- 探索 LLM 增强工具：某些工具可以帮助你优化所选上下文长度，例如 [Toolhouse](https://toolhouse.ai/blog/accelerating-semantic-search-with-new-toolhouse-tools-powered-by-groq-fast-ai-inference) 的 [Semantic Memory Search 工具](https://toolhouse.ai/blog/accelerating-semantic-search-with-new-toolhouse-tools-powered-by-groq-fast-ai-inference)，它让 LLM 无需额外提示即可检索过往对话。

## 结语

在为业务构建 LLM 应用时，上下文长度是一个关键考量。理解上下文长度对 LLM 性能的影响，并为你的具体用例选择合适的上下文长度，你就能释放应用的全部潜力。记住：尝试不同的上下文长度、把上下文长度当作超参数、考虑使用分层或多分辨率模型来优化应用性能。选对了上下文长度，你就能构建更准确、更相关、更有效的 LLM 应用，驱动业务成功。
