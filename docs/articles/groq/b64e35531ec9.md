### [CHANGELOG.md](https://github.com/groq/groq-changelog/commit/c0a023365aa7c2a11fd52d0c4e380a0e180e0e03#diff-06572a96a58dc510037d5efa622f9bec8519bc1beab13c9f251e97e657a9d4ed)

行数变化：新增 12 行，删除 3 行

本次提交细化了 2025-04-23 (Python SDK v0.23.0, TypeScript SDK v0.20.0) 条目下的 **主要变更**，修改后的内容如下：

 - `groq.files.content` 现在返回 `Response` 对象，以便将 `jsonl` 文件解析为文本，或将通用文件类型解析为 blob。此前把返回类型当作 JSON 对象是不正确的，会导致 SDK 报错而不是返回文件内容。TypeScript 用法示例：

```ts
const response = await groq.files.content("file_XXXX");
const file_text = await response.text();
```

 - `BatchCreateParams` 的 `completion_window` 输入现接受 `string` 类型，以支持 `24h` 到 `7d` 之间的时长。使用更长的完成窗口可以让批处理任务有更大机会成功完成而不超时。对于较大的批量请求，建议拆分为多个批处理任务。[了解更多批处理最佳实践](https://console.groq.com/docs/batch)。
 - 更新了 chat completion 的 `model` 参数，移除已弃用的模型并加入更新的 production 模型。
 - 移除：`gemma-7b-it` 和 `mixtral-8x7b-32768`。
 - 新增：`gemma2-9b-it`、`llama-3.3-70b-versatile`、`llama-3.1-8b-instant` 和 `llama-guard-3-8b`。
 - 关于 Groq 模型的最新信息请见 [models 页面](https://console.groq.com/docs/models)，或了解我们的[弃用政策](https://console.groq.com/docs/deprecations)。
 - 新增可选的 chat completion `metadata` 参数，以更好地兼容 OpenAI chat completion API。[了解更多关于从 OpenAI 切换到 Groq 的信息](https://console.groq.com/docs/openai)。
