# 现在在 OpenRouter 上嵌入 5 并重新排序 5

通过单一 API 访问 Cohere 最先进的检索模型，统一计费，无需额外的 SDK。

![宣布 Cohere Embed 5 和 Rerank 5 在 OpenRouter 上可用的宣传图片，以白色文本和徽标与抽象的黑色、蓝色和紫色渐变为特色背景。](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/2bf7ca0269bb95916830cc2a5116d517ddf6353f-3840x2160.png?auto=format&fit=max&q=80&w=1130)

[Embed 5](https://openrouter.ai/cohere/embed-5-pro) 和 [Rerank 5](https://openrouter.ai/cohere/rerank-5-pro) 现已在 OpenRouter 上上线。以下是如何通过一个 [单一 API](https://openrouter.ai/docs/cookbook/evaluate-and-optimize/rag) 将它们变成一个工作的 RAG 管道，只需几十行 Python 代码。

Cohere 拥有迄今为止最强大的检索模型，可为企业文档和复杂的检索任务提供领先的性能。如果您已经在使用 OpenRouter，则可以立即开始 - 使用与现有模型相同的 API 密钥和积分，无需额外设置。

RAG 通过在写入之前获取相关块，将 LLM 的答案建立在您自己的数据中。嵌入搜索提供了快速有效的第一阶段近似。然后，重新排序器会一起读取查询和每个候选，从而增加检索到的内容的精度。

Cohere 模型的两个特点塑造了这种设计：

- **Embed 5 Pro 和 Fast 共享一个嵌入空间。** 使用“embed-5-pro”建立索引以获取质量，然后使用“embed-5-fast”查询延迟。
- **Rerank 5 分数经过校准。** 分数在查询和领域中意味着相同的事情，因此一个相关性阈值可以在达到 LLM 之前过滤掉弱上下文。

最后，您将获得一个简短的 Python 脚本，该脚本可以通过评分引用来回答有关文档的问题。这种方法几乎可以应用于任何检索用例，从企业搜索和客户支持到知识管理和文档发现。

RAG 管道有两部分：一个构建可搜索索引的离线作业，以及一个针对每个问题运行的在线路径。了解哪些调用发生一次以及每个请求发生哪些调用有助于解释管道的大部分成本和延迟。每个语料库索引运行一次。然后，每个问题都需要一次 Embed 5 Fast 调用、一次 Rerank 5 调用和一次聊天调用，全部通过 OpenRouter 的 API 进行。

### 设置

您需要 Python 3.10 或更高版本、[OpenRouter API 密钥](https://openrouter.ai/docs/api/api-reference/api-keys/create-a-new-api-key)、[OpenRouter Python SDK](https://openrouter.ai/docs/client-sdks/overview) 以及用于内存向量存储的 NumPy。
```
pip install openrouter numpy
export OPENROUTER_API_KEY="sk-or-..."
```

```
import os
import numpy as np
from openrouter import OpenRouter

client = OpenRouter(api_key=os.environ["OPENROUTER_API_KEY"])

EMBED_INDEX_MODEL = "cohere/embed-5-pro"   # indexing: highest quality
EMBED_QUERY_MODEL = "cohere/embed-5-fast"  # queries: lowest latency
RERANK_MODEL      = "cohere/rerank-5-pro"  # or cohere/rerank-5-fast
CHAT_MODEL        = "deepseek/deepseek-v4.1-flash-1017"       # any chat model on OpenRouter
DIMS = 1024                                    # 256 | 512 | 768 | 1024 | 1536 | 2048
```
Embed 5 返回六种大小的俄罗斯套娃向量，默认为 2048。我们[建议](https://cohere.com/blog/embed-5) 1,024-dim int8 向量作为最佳质量成本点； OpenRouter 的 [embeddings API](https://openrouter.ai/docs/api/api-reference/embeddings/submit-an-embedding-request) 返回浮点数，因此本文使用 1,024-dim 浮点数。

NumPy 商店使这个演示变得简单。对于生产，请将其替换为您首选的载体数据库，例如 pgvector、Qdrant、Pinecone 或 Weaviate。

### 索引

索引将每个文本块转换为一个向量，即相似含义紧密相连的数字列表。它每个语料库运行一次，因此这是最高质量模型获得回报的步骤。

将每个文档分割成块，使用 Embed 5 Pro 将它们嵌入为“search_document”，并对向量进行归一化，使点积等于余弦相似度。

示例语料库是一个虚构的 API 文档，其中有一些故意的错误：
```
docs = [
    {"title": "Rotating API keys",
     "text": "To rotate a key without downtime, create a second key, deploy it to every service, "
             "confirm traffic on the new key in the usage dashboard, then revoke the old key."},
    {"title": "Creating API keys",
     "text": "Create keys under Settings > API Keys. Each key can be scoped to read or write and to one project."},
    {"title": "Revoking API keys",
     "text": "Revoking a key takes effect immediately. Requests with a revoked key return 401 Unauthorized."},
    {"title": "Webhook signing secrets",
     "text": "Rotate your webhook signing secret from the Webhooks page. The old secret stays valid "
             "for 24 hours so you can update your verifier."},
    {"title": "Log rotation",
     "text": "Request logs rotate daily and are kept for 30 days. Export them to S3 for longer retention."},
    {"title": "Rate limits",
     "text": "Each API key is limited to 600 requests per minute. Going over returns 429 Too Many Requests."},
]
```

```
def chunk(doc, max_chars=1500):
    """Split on blank lines, packing paragraphs up to ~max_chars."""
    out, buf = [], ""
    for para in doc["text"].split("\n\n"):
        if buf and len(buf) + len(para) > max_chars:
            out.append({"title": doc["title"], "text": buf.strip()})
            buf = ""
        buf += para + "\n\n"
    if buf.strip():
        out.append({"title": doc["title"], "text": buf.strip()})
    return out

def embed(texts, model, input_type, batch=96):
    vecs = []
    for i in range(0, len(texts), batch):
        res = client.embeddings.generate(
            model=model,
            input=texts[i:i + batch],   # one request per batch
            input_type=input_type,      # "search_document" | "search_query"
            dimensions=DIMS,
        )
        vecs += [d.embedding for d in res.data]
    v = np.array(vecs, dtype=np.float32)
    return v / np.linalg.norm(v, axis=1, keepdims=True)

chunks = [c for d in docs for c in chunk(d)]
doc_vecs = embed([c["text"] for c in chunks], EMBED_INDEX_MODEL, "search_document")
```
需要指出的三个关键细节：

- `input_type**:**` 告诉 Embed 5 文本位于搜索的哪一侧。 OpenRouter 将其传递给 Cohere。
- **批处理：**每个请求发送许多块，这减少了往返并加快了索引速度。它不会改变成本，因为嵌入是按代币定价的。
- **块大小：**打包整个段落遵循[OpenRouter指南](https://openrouter.ai/docs/cookbook/evaluate-and-optimize/rag)中的逐段落策略，1,500个字符大约是300-400个英语标记。 Embed 5 接受最多 128k 个令牌，但每个块也会经过 Rerank 5，它读取查询和块组合的最多 32k 个令牌，并将更长的内容拆分为多个通道。

### 检索

检索找到向量最接近问题向量的块。这充当两个内容之间的语义相似性的表示。

使用 Embed 5 Fast 将问题嵌入为“search_query”，然后通过余弦相似度拉取包含 20 个块的广泛候选集。
```
def retrieve(query, k=20):
    q = embed([query], EMBED_QUERY_MODEL, "search_query")[0]
    scores = doc_vecs @ q                 # cosine, since both sides are normalized
    top = np.argsort(-scores)[:k]
    return [(chunks[i], float(scores[i])) for i in top]
```
使用 Fast 查询 Pro-built 索引是可行的，因为只要双方使用相同的“维度”，两个模型就会[共享嵌入空间](http://www.cohere.com/blog/embed-5)。这是我们建议的划分：在 [Cohere 的测试](https://cohere.com/blog/embed-5) 中，在 40 个数据集上，Pro 索引上的快速查询保持了全 Pro 检索质量的 98.4%，而两侧的 Fast 检索质量为 96.6%。对于任何其他型号系列，您必须在两侧使用相同的型号。

让我们在这个阶段撒一张大网：召回率是检索器的工作，精确度是重新排序的工作。 OpenRouter 的指南建议 10-20 个候选者提供前 3-5 名的重新排名。

### 重新排名

重新排名通过一起阅读问题和每个块来重新对入围名单进行评分。这对于运行整个索引来说太慢了，但比向量相似度更准确，因此它只在最重要的候选者上运行。 Rerank 不需要 Embed - 或任何嵌入模型。它可以作为现有语义、关键字或混合搜索系统的简单第二阶段。

将查询和 20 个候选者发送到 Rerank 5，保留前 5 个，并删除相关性阈值以下的任何内容。
```
MIN_SCORE = 0.3

def rerank(query, candidates, top_n=5):
    res = client.rerank.rerank(
        model=RERANK_MODEL,
        query=query,
        documents=[c["text"] for c, _ in candidates],
        top_n=top_n,
    )
    return [
        (candidates[r.index][0], r.relevance_score)
        for r in res.results          # sorted by relevance, highest first
        if r.relevance_score >= MIN_SCORE
    ]
```
每个结果都包含候选人在列表中的位置（“index”）和一个“relevance_score”，根据[重新排名响应架构](https://openrouter.ai/docs/sdks/typescript/api-reference/operations/creatererankresponsebody)。

[Rerank 5](https://docs.cohere.com/changelog/rerank-v5) 在这一步添加了什么：

- **校准分数。** 分数在查询和域之间保持一致，因此单个“MIN_SCORE”决定了达到 LLM 的内容。
- **32k-token 上下文。** 长块被整体评分。
- **半结构化数据。** JSON 记录和表在格式化为 YAML 字符串时可以很好地重新排名。
- **无需重新索引即可升级。** Rerank 在查询时读取原始文本，因此切换模型只需一行更改。

使用“rerank-5-pro”进行大量推理查询和长文档或特定领域文档。使用“rerank-5-fast”进行大容量搜索和每个任务搜索多次的代理。需要注意的一件事是：[Rerank 5](https://docs.cohere.com/docs/rerank) 仅为文本，但适用于已解析的 pdf。

###一代

Generation 将最好的部分作为编号来源交给LLM，并要求其仅从这些来源中回答。这样可以使答案扎根于您的文档，并为读者提供可以检查的引用。如果没有任何东西可以清除阈值，则完全跳过 LLM 调用。
```
SYSTEM = (
    "Answer using only the numbered sources. "
    "Cite them inline like [1]. "
    "If the sources don't contain the answer, say you don't know."
)

def answer(query):
    hits = rerank(query, retrieve(query))
    if not hits:
        return "I couldn't find that in the docs."

    sources = "\n\n".join(
        f"[{i}] {c['title']}\n{c['text']}" for i, (c, _) in enumerate(hits, 1)
    )
    res = client.chat.send(
        model=CHAT_MODEL,
        messages=[
            {"role": "system", "content": SYSTEM},
            {"role": "user", "content": f"Sources:\n\n{sources}\n\nQuestion: {query}"},
        ],
    )
    return res.choices[0].message.content

print(answer("How do I rotate an API key without downtime?"))
```
发送每个块的标题及其文本可以让模型引用可读的内容；如果您的文档有 URL，也请添加它们。 OpenRouter 的指南使用响应 API 来执行此步骤。要遵循它，请调用“client.responses.send”，其中系统提示符为“instructions”，源和问题为“input”，然后从“res.output”中的消息项而不是从“choices”中读取答案。

### 结果

在这里，我们将验证我们实施的步骤是否改善了我们的响应。 

当重新排名自信地选择正确的块并放弃险些错过的嵌入搜索排名时，它就会获得额外的关注。
```
q = "How do I rotate an API key without downtime?"

cands = retrieve(q)
hits = rerank(q, cands)

print("Embedding only (top 3):")
for c, s in cands[:3]:
    print(f"  {s:.3f}  {c['title']}")

print("After Rerank 5:")
for c, s in hits:
    print(f"  {s:.3f}  {c['title']}")
```

### 总结

Everything in this pipeline ran through one API key and one client. Embed 5 Pro 构建索引，Embed 5 Fast 和 Rerank 5 处理每个问题，聊天模型编写答案，无需处理单独的 SDK、帐户或账单。

That single surface is also what makes the pipeline easy to evolve. Every model is just a string, so trying `rerank-5-fast` instead of `rerank-5-pro`, or a different chat model, is a one-line change. 

Start with the sample corpus, swap in your own docs, and see what Rerank 5 moves to the top.

接下来去哪里：

- **混合搜索。** 在矢量命中旁边添加关键字 (BM25) 命中。 Rerank 读取原始文本，因此它可以在一次调用中对两个列表进行评分。
- **较小的索引。** 降至 512 或 256 维，或通过 Cohere 自己的 API 使用 int8 或二进制向量。
- **图像和 PDF。** Embed 5 嵌入图像和混合文本和图像输入，例如 PDF 页面，并且 OpenRouter 的嵌入 API 接受 `image_url` 内容部分。重新排名 5 仅限文本，因此对这些结果的文本（例如解析的页面文本或标题）重新排名，或者跳过对它们的重新排名。
- **评估。** 标记一小组真实查询，比较有和没有重新排名的情况下 5 的命中率，并在同一组上调整“MIN_SCORE”。
- **探索[指南针](http://www.cohere.com/compass)**。 Cohere 的企业搜索和检索平台将 Embed 和 Rerank 整合到一个解决方案中，从而更轻松地跨企业数据构建强大的搜索和 AI 应用程序。现在可供[云客户](http://www.cohere.com/blog/compass-cloud-beta)使用。
