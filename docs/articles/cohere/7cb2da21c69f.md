# 推出 Parse：规模化的企业文档智能

一款高吞吐视觉解析模型，拥有市场上最强的性价比。

核心要点

- **同类最优的价值**：超越领先的文档解析方案和超大规模云服务商的服务，同时在企业规模下保持成本效益。
- **不止 OCR**：理解表格、表单、示意图和图像，在主要全球商业语言中提取更丰富的语义上下文。
- **企业优先**：为处理金融、保险、科研等主要行业和领域的业务文档而训练。
- **空间感知**：为视觉元素返回 bounding box，为检索、grounding 和自动化保留文档结构。
- **已在 Compass 中提供**：今天起可将 Parse 作为 Cohere Compass 搜索与检索栈的一部分使用——与 Embed 和 Rerank 并驾。
- **安全部署**：在任何私有云或本地环境运行，匹配组织的安全与合规要求。

Cohere Parse 是一款高性价比的视觉语言模型，用于处理海量企业文档。它把复杂的多模态文件转换为结构化、机器可读的数据，驱动企业知识类用例——包括文档索引、RAG 和 agentic 检索。

Parse 不止于文本识别：它能检测并理解关键视觉元素——如表格和嵌入图像——并输出干净的 Markdown 文件供下游处理与应用。用 Parse 处理九种主要世界语言的文档和图像。

Parse 的设计目标是随工作负载扩张仍保持解析质量并让推理成本可预测，支持生产环境所需的高吞吐。客户可通过 [Cohere API](http://dashboard.cohere.com) 使用 Parse，每 1,000 页仅 $1.50；或在 [Model Vault](http://dashboard.cohere.com) 中部署，获得安全的单租户推理和更低的每页成本。受监管行业的团队可以用极小的服务占用足迹，把 Parse 安全部署在自己的基础设施上。

想先试试？用我们的 [Space](https://huggingface.co/spaces/CohereLabs/cohere-parse) 免费体验 Cohere Parse 如何处理你的文档。

### 性能

Cohere Parse 在我们评估的模型中交付*最强的价格-性能权衡*。它的竞争力极强：超越领先的专用文档解析方案，同时保持适合从数十万到数百万页高流量工作负载的价格。

各评估模型的性能（ParseBench 三维度平均）与价格（每 1,000 页美元）的帕累托前沿。价格采用对数刻度以涵盖其宽跨度。

在 [ParseBench](https://www.parsebench.ai/)（衡量适合 agent 的解析性能）上，Parse 在三个评估维度上得 79.2 分——对比 Mistral OCR 4 的 74.5、Databricks AI Parse 的 72.4，以及 LlamaParse Cost Effective 方案的 78.3。

与超大规模云服务商的文档智能方案相比，这一差距更大：比 AWS Textract 和 Google Document AI 均高出 20 分以上。在我们的评估集中，Parse 只输给前沿 LLM（GPT-5.5、Opus 4.8 和 Gemini 3.5 Flash）——它们都是通用模型，且显著大于 Parse。

### 你能用 Parse 构建什么

Parse 提供完整文档智能栈的地基。Parse 可用于：

*自动化文档处理*——从理赔单、合同、发票等高流量文档中抽取结构化数据，无需人工审读或录入。

*语义搜索与 RAG*——用为分块、索引和引用优化的表示，构建更高质量的检索系统。

*多模态 agent*——为 AI agent 提供自主工作流和采取行动所需的上下文。

### Cohere 搜索生态

Parse 也作为 [Compass](https://cohere.com/compass) 的一部分提供，与 [Embed](https://cohere.com/embed) 和 [Rerank](https://cohere.com/rerank) 集成。

我们所有模型既能独立工作，也能协同。按需采用组件，或部署完整的托管平台，获得一体化的文档到答案管线。

这非常适合希望获得以下能力的用户：

- 单一、易于配置的界面，覆盖文档摄取、解析、分块、embedding、索引、混合搜索与两阶段检索。
- 支持更广的文档格式（包括 .xlsx、.docx 和 .html），无需自建自维护定制预处理管线。
- 智能解析：自动把文档路由到文本或视觉路径，优化延迟与 token 用量。
- 全托管索引：embedding 模型升级无缝完成，无需重新摄取数据。
- 带文档级访问控制的多租户部署，适合敏感工作负载。
- 面向 SharePoint、Google Drive 等云存储系统的开箱即用连接器。

### 开始使用

Parse 现已在 Cohere API、Model Vault、Microsoft Foundry 和 AWS SageMaker 正式可用。

[访问我们的 dashboard](https://app.notion.com/p/Announcement-blog-39c4398375db801bbe89cc3b63b3ad68?pvs=21)创建 API key 或配置新的 Vault，然后用下面的代码开始解析。

```
import base64
import os
import requests

API_KEY = os.environ["CO_API_KEY"]
IMAGE_PATH = "YOUR_IMAGE.png"

with open(IMAGE_PATH, "rb") as f:
    image = base64.b64encode(f.read()).decode("utf-8")

response = requests.post(
    "https://api.cohere.com/v2/parse",
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={
        "model": "parse-v5.0",
        "document": {
            "type": "image_url",
            "image_url": f"data:image/png;base64,{image}",
        },
        "output_format": "markdown",
    },
)

response.raise_for_status()
result = response.json()

markdown = "\n\n".join(
    page["markdown"]["content"] for page in result["pages"]
)

with open("parsed_output.md", "w", encoding="utf-8") as f:
    f.write(markdown)

print("Saved to parsed_output.md")
```

2

我们从 ParseBench 比较中排除 Layout 和 Chart 两个维度，因为它们衡量的能力超出我们当前的产品范围，而非模型质量缺陷：

- Layout 打分元素级空间检测（bbox + 类别标签匹配）。我们的模型设计为产出按阅读顺序的 markdown——只对表格或图像输出 bounding box，不对文本逐元素输出。该维度得分低反映的是刻意的输出格式选择，而非转写失败。
- Chart 打分从图表图像中抽取数值数据系列成结构化表格。我们的模型把图表视为带描述性元数据的视觉元素，而非数据抽取对象。这是产品范围决策——图表数据抽取已列入下一版 Parse 的计划。

在与我们产品目标对齐的三个维度——Tables、Text Content 和 Text Formatting——我们报告完整结果。它们覆盖我们模型训练和优化所针对的结构化转写与语义保真。
