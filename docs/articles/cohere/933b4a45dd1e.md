# 推出 Rerank 5：精准高效的企业文档检索

让 AI 在每次请求中都拿到最相关的上下文，如今精确到段落级。

![Rerank 5 logo](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/001e212cb8f99611514f36805a3c3ef32a51f7d9-3840x2160.png?auto=format&fit=max&q=80&w=1130)

要点

- **业界领先的检索能力**：Rerank 5 Pro 在主要公开基准上领跑，而 Rerank 5 Fast 以更低的成本提供接近顶尖的表现。
- **在企业各领域都很强**：Rerank 5 在金融、医疗健康、科学研究、解析文档与多语种检索上都确立了领先地位。
- **Context Focus**：Rerank 5 的全新能力 —— 一次 Rerank 调用就能返回每篇文档内最相关的段落，在回答质量几乎无损的前提下削减 LLM 的 token 成本。
- **校准过的相关性分数**：跨查询、跨领域保持一致的分数，让团队只需设定一个阈值，就能决定哪些内容进入 LLM。
- **随处可部署**：可通过 Cohere API、Model Vault、Microsoft Foundry、Amazon SageMaker 使用，也可在你的自有 VPC 或本地环境私有化部署，并向所有 North 用户开放。只需几行代码即可上手。

## 引言

今天，我们发布 Rerank 5，这是我们迄今最先进的企业级检索模型，提供 Pro 与 Fast 两个档位。

[Rerank 5](http://www.cohere.com/rerank) 帮助团队找到正确的信息，把最相关的上下文发送给他们的 LLM，并为客户带来更贴合需求的搜索体验。借助 Rerank 5 Pro，我们在重排质量上立起了新标准，尤其是在推理密集型搜索、视觉内容丰富的文档以及关键企业领域。Rerank 5 Fast 则把这种质量带给对时延和成本敏感的工作负载。两款模型都引入了 Context Focus，它能精准定位文档内最相关的文本片段，超越文档级或 chunk 级检索，把真正重要的信息准确呈现出来。

你的 LLM 读到的每一个 token 都是你要付费的 token，而检索决定了那些 token 是什么。随着 agents 在更长的文档上运行更多次搜索，检索已经成为企业掌控自身 AI 成本、时延与回答质量的关键杠杆。

Rerank 5 与 [Embed 5](https://cohere.com/blog/embed-5) 和 [Parse 5](https://cohere.com/blog/parse) 一起，构成我们最新一代搜索模型。它即日起在 [Cohere API](http://dashboard.cohere.com) 与 [Model Vault](https://vault.cohere.com/)、[Microsoft Foundry](https://ai.azure.com/catalog/models/Cohere-rerank-v5-pro)、[Amazon SageMaker](https://aws.amazon.com/marketplace/pp/prodview-6hcingojlkj32) 正式可用，并向所有 [North](http://cohere.com/north) 用户开放。API 定价为 Pro 每 1M tokens $0.05，Fast 为 $0.02。

## 性能

Rerank 5 Pro 在 [ViDoRe V3](https://huggingface.co/blog/QuentinJG/introducing-vidore-v3)、[nanoMTEB](https://huggingface.co/collections/zeta-alpha-ai/nanobeir)、[BRIGHT](https://brightbenchmark.github.io/) 和 [BEIR](https://arxiv.org/abs/2104.08663) 等公开基准上领先 —— 超过了所有受测的竞品模型。在所评测的 46 个复合数据集中，Rerank 5 Pro 在 39 个上排名第一，并在 43 个上至少排名第二。模型评测采用 [RCP-nDCG@10](http://www.cohere.com/blog/rcp-ndcg)，这是一套由 Cohere 开发的方法，用于解决传统 nDCG 因相关性标注不完整（qrel coverage）而产生的局限。

这一优势在 BRIGHT 上尤为突出。该基准测试推理密集型检索，找出相关文档需要超越关键词或语义相似度的更深理解。Rerank 5 Pro 得分 82.2，比 Voyage AI Rerank 3 高 5.8 分，比 Rerank 4 Pro 高 12.4 分，是四项头条基准中代际增幅最大的一项。Pro 在 ViDoRe V3 上以 1.6 分领先最强的外部竞品，在 BEIR 上领先 1.8 分，在 nanoMTEB 上领先 3.4 分。这些增幅对 agentic 工作流愈发重要：复杂的多步查询要求模型能够对相关性进行推理，并返回可能与原始查询并不相似的证据。

Rerank 5 Fast 在速度优化档位上带来了实质的质量提升。在全部四项基准上，它都优于 Voyage AI Rerank 3 Lite 和 Qwen3-Reranker-0.6B，也胜过大得多的 Qwen3-Reranker-8B 以及上一代的 Rerank 4 Pro。

头条基准。四项公开基准上的重排质量（RCP-nDCG@10）：ViDoRe V3（8 个数据集）、BEIR（13 个）、BRIGHT（12 个）和 nanoMTEB（13 个）。分数为各项基准下所有数据集的平均值。

### 领域专项表现

在面向企业的专业领域，Rerank 5 表现出一致的领先。在金融与经济领域，Rerank 5 Pro 在金融文档的视觉检索（ViDoRe Finance）、财报的数值推理（[FinQA](https://arxiv.org/abs/2109.00122)）以及复杂的经济学问题（BRIGHT Economics）上都保持领先。这也是它领先幅度最大的地方，比 Voyage AI Rerank 3 高 9.6 分。

同样的结果延伸到医疗健康、科学研究和能源方向的检索，这些基准考察的是从专业科学文献、生物医学研究和气候相关内容中找出相关信息的能力。完整结果清单见[这里](https://docs.google.com/spreadsheets/d/1FYXax6vFdKE4ph3eXj935jCl7mpeczvYe5jye2h1f9U/edit?gid=0#gid=0)。

### 时延与吞吐

Rerank 5 Fast 为海量场景而生。在持续负载下，Fast 在一张 NVIDIA A100 GPU 上每秒可重排约 187 篇标准长度文档（1,000 tokens），吞吐量为 Pro 的 2.9 倍。

Fast 的响应时间也比 Pro 快近 3 倍，非常适合时延敏感的应用，以及单个任务要运行很多次搜索的 agents。对于排序质量优先于速度的应用，Pro 仍然是最佳选择。

Rerank 5 Fast 与 Pro 在单张 NVIDIA A100 Tensor Core GPU 上、经由 Cohere API 测得的文档吞吐与请求中位时延：每个请求 96 篇文档、并发度 8，每种文档长度执行超过 1,000 个请求。文档长度为近似值。

## Context Focus：解锁更聪明的 token 经济性

随着文档越来越长、AI agent 从更多来源取信息，传给 LLM 的上下文量持续增长。但往往每篇文档里只有寥寥几句与查询相关。处理不必要的内容会推高 token 成本、增加时延，还可能引入降低回答质量的噪声。

Context Focus 是随 Rerank 5 一同上线的全新可选能力，它不止于识别相关文档，而是进一步精准定位其中最关键的段落。可配置的阈值让开发者在削减上下文与保留证据之间取得平衡，而一次 Rerank API 调用会同时返回文档级相关性分数和带分数的文本片段。应用随后可以只把最相关的证据交给 LLM，而不必在检索链路里增加步骤。

### 把上下文规模与回答质量解耦

我们在 30 个问答数据集上测量了随着 Context Focus 移除更多检索到的文本，回答质量如何变化。移除一半上下文只牺牲 2 个百分点的回答质量（保留 96%），移除四分之三只损失 7 个百分点（保留 87% 的回答质量）。因此 Context Focus 更像一个旋钮：温和的设置几乎不付代价，而需要更大节省的团队可以用一部分质量换取最多 10 倍的上下文缩减。

随着检索到的文本被移除时的回答质量。每个模型都从同一组 50 个候选中挑选自己的 top 5 文档，然后在一系列阈值下移除文本（每个点对应一个阈值）：带 Context Focus 的 Rerank 5，以及各自使用自家压缩器的基线。Qwen3.5-9B 依据剩下的内容作答，Qwen3.5-35B 为答案评分。横轴：被移除的已检索 token 占比；纵轴：平均裁判分数；两者均在 30 个单轮 QA 数据集上取平均，数据集来自 ViDoRe、UNICORN、BRIGHT-Pro 和 agentic QA（每个至多 500 条查询）。

接着，我们给一个搜索 agent 配上逐步搭起来的检索栈，起点是关键词搜索（BM25）。加入 Rerank 5 Pro 后，准确率从 46% 升到 49%。再打开 Context Focus，token 随之减少，准确率进一步提高。在默认阈值（0.1）下，每个任务的 token 下降 19%，准确率升到 57%。阈值为 0.4 时，token 下降 34%，在每一个数据集上都更低，准确率达到 58%。总体而言，在 0.4 阈值下启用 Context Focus 的完整检索栈比单独使用 BM25 少用 35% 的 token，准确率却更高（58% vs 46%）。在六个深度搜索基准上，它少用 41% 的 token，准确率从 39% 升到 52%，而且每个基准在两项指标上都有改善。

搜索 agent 的结果，在 17 个数据集上取平均，其中包括六个深度搜索基准（BrowseComp-Plus、MedBrowseComp、WebWalkerQA、SealQA、HERB 和 DRBench），每个数据集 50 个问题。我们沿用 BrowseComp-Plus 的评测设置。agent 为 glm-5-3-flash，搜索是它唯一的工具，每次搜索返回 5 条结果。检索先由 BM25 开始，再由 Rerank 5 Pro 对 top 100 重新排序，此时关闭 Context Focus。随后展示默认阈值（0.1）和 0.4 下的 Context Focus，各自都叠加在 Rerank 5 Pro 之上。准确率是回答正确的问题占比。token 是每个任务的平均总量，累加运行过程中每一次 LLM 调用：输入、输出与推理 token。每次调用的 prompt 都包含此前的完整对话，并计入缓存 token。

## 校准过的相关性分数

有了 Rerank 5，0.7 分现在意味着这篇文档有用的概率是 70%。

每个 reranker 都会返回一个相关性分数，但在此之前，这些分数大多只适合用来排序。什么算「好」分数，换一个模型就变一套。团队得为每个模型调一个 cutoff，并且每次升级都要重新调。

Rerank 5 的分数开箱即带校准：每条结果返回的 `relevance_score` 可以直接读作这篇文档有用的概率，无需改动你的请求或响应格式。Pro 和 Fast 对这条线的位置也有一致的判断：就 Pro 而言，「更可能有用而非没用」对应 0.50 分；就 Fast 而言是 0.45 分。

Rerank 5 的原始分数可以直接读作概率。文档按分数被分到十个 bin 中，每条线连接某个模型的各个 bin：横向是该 bin 的平均分数，纵向是该 bin 中被判为有用的文档占比。在虚线对角线上，分数恰好等于概率；位于对角线下方的线高估了相关性，位于上方的线低估了相关性。所用分数即为返回值，未做任何重新校准。左图：盲评的人工打分组，2,262 篇文档；有用 = 在五级量表（Off-topic、Topical、Useful、Answers、Complete）上平均分达到「Useful」或更高。右图：NIST TREC-DL 评审，20,646 篇文档；有用 = 在 NIST 的 0–3 量表上达到 2 级（「highly relevant」）或更高。

我们把它与两组独立的人工判断做了核对，任何模型都没有在这些数据上训练过：一组盲评打分员，以及 NIST 的 TREC Deep Learning 评审。在两组数据上，Rerank 5 都比其他任何 reranker 更贴近对角线。竞品模型落在这条线下方，高估了相关性：Voyage AI Rerank 3 打里约 0.55 分的文档，在人工打分员看来只有 24% 真的有用。

下表用期望校准误差（ECE）概括这一点：模型的分数与真正有用的文档占比之间的平均差距，0 为完美。Rerank 5 在两组判断上的 ECE 都约为 0.06；我们测过的其他每个 reranker，误差都接近它的四倍或更高。校准也没有牺牲排序质量：在两组判断上，Rerank 5 Pro 和 Fast 的 average precision 分列第一和第二。

### 为什么重要

- **按相关性过滤，而不是按条数。** 不要再给 LLM 传固定的 top-k，而是保留每一篇高于阈值的文档。窄查询放进去的文档少，宽查询放进去的多，而模型看到的噪声更少。
- **知道什么都没检索到。** 如果没有任何文档越过阈值，agent 可以改写查询，或者承认自己不知道，而不是拿排在最前面的内容作答。
- **跨领域、跨模型规模共用一个阈值。** 在 BRIGHT、NanoBEIR 和 ViDoRe V3 上，Pro 的默认阈值始终落在 0.47 到 0.53 之间，而 Pro 与 Fast 彼此的差距不超过 0.05。

## 开始重排

Rerank 5 Pro 与 Rerank 5 Fast 已正式可用，可通过 [Cohere API](http://dashboard.cohere.com)、[Model Vault](https://vault.cohere.com/)、Microsoft Foundry（[Fast](https://ai.azure.com/catalog/models/Cohere-rerank-v5-fast)、[Pro](https://ai.azure.com/catalog/models/Cohere-rerank-v5-pro)）和 Amazon SageMaker（[Fast](https://aws.amazon.com/marketplace/pp/prodview-uu644hmeoibm2)、[Pro](https://aws.amazon.com/marketplace/pp/prodview-6hcingojlkj32)）使用，并向所有 North 用户开放。如需在自己的 VPC 或本地环境中私有化部署，[请与我们联系团队的一位成员](https://cohere.com/contact-sales)。

Rerank 5 叠加在你已有的检索栈之上。它与任何关键词、向量或混合搜索都能配合工作，无需重建索引，并可通过 LangChain、Haystack、Elasticsearch 和 Weaviate 等框架接入。[阅读文档](https://docs.cohere.com/docs/integrations)。

先[创建一个 API key](http://dashboard.cohere.com)，然后用下面的代码片段快速发出你的第一次查询。

```
#rerank with Context Focus
import os
import requests

query = "How much did card provisions rise in Q3?"

documents = [
    "Market update. Commercial real estate prices fell 6% this year as office "
    "vacancies climbed. Analysts expect refinancing pressure on landlords to "
    "persist into next year.",
    "Q3 credit quality. Net charge-offs held steady at 0.42% of average loans. "
    "Commercial real estate loans stood at $14.3 billion, or 9% of total loans. "
    "Office properties accounted for $2.1 billion of that balance. Card "
    "provisions rose $85 million on higher delinquencies.",
    "Q3 mortgage lending. Residential mortgage originations rose 11% as rates "
    "eased. The average loan-to-value ratio on new lending was 68%.",
]

response = requests.post(
    "https://api.cohere.com/v2/rerank",
    headers={"Authorization": f"Bearer {os.environ['CO_API_KEY']}"},
    json={
        "model": "rerank-v5.0-pro",
        "query": query,
        "documents": documents,
        "top_n": 2,
        "relevant_spans": {"mode": "enabled", "threshold": 0.4, "max_spans": 10}, #toggle Context Focus
    },
)
response.raise_for_status()

for result in response.json()["results"]:
    document = documents[result["index"]]
    print(f"{result['relevance_score']:.2f}  {document[:60]}...")
    for span in result.get("relevant_spans") or []:
        print(f"      {span['score']:.2f}  {document[span['start']:span['end']]}")
```
