# Cohere Model Vault 内部：构建可验证的机密 AI 推理

Model Vault 如何结合机密 CPU 和 GPU 执行、端到端加密请求内容以及远程证明来保护正在处理的敏感 AI 工作负载。

![](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/fc96d67622cfc9c2b113f533f1385f1ceedb9638-1920x1080.png?auto=format&fit=max&q=80&w=1130)

在我们的产品发布会上，我们推出了 [**Cohere Model Vault 上的机密计算**](https://docs.google.com/document/d/1BvbHFNbT-GjlvSG7UMaaahsM4OX3A4YtZPp_330XT0g/edit?tab=t.0#heading=h.vv3sfmm4rp2q)，目前在 Microsoft Azure 上使用 NVIDIA GPU 进行公开测试。

本文将更深入地介绍该系统的工作原理。

目标不仅仅是加密推理。这是为了减少客户必须信任的明文数据的基础设施，并为他们提供可以在敏感信息发布之前验证的加密证据。

这需要的不仅仅是机密虚拟机。机密推理系统必须保护计算本身、向其传送敏感请求的路径以及客户用来决定目的地是否可信的机制。

Model Vault 将这些部分整合到一个专用的模型部署中。

![](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/c445146fb507dd0bfeaf2815fc6a5dacb46eccee-3840x2540.png?auto=format&fit=max&q=80&w=800)

### **从机密硬件到机密推理**

当应用程序或模型主动处理数据时，机密计算可以保护**使用中的数据**。

其基础是两个属性：

- **隔离**，它使用硬件强制控制来保护工作负载内存免受机密环境之外的基础设施的影响。
- **证明**，它生成有关环境的加密签名证据，以便另一方可以在发布敏感数据之前对其进行评估。

这些属性共同改变了传统的基础设施信任模型。对底层主机的特权访问不再自动意味着对机密环境中运行的工作负载的访问。

然而，对于 AI 推理来说，边界不能止于 CPU。

模型计算的很大一部分在加速器上运行。如果 CPU 受到保护，而加速器仍处于机密边界之外，则敏感模型状态和中间计算可能会在推理转移到 GPU 时暴露。

NVIDIA GPU 上的机密计算可保护 GPU 内存免受受保护环境之外的基础设施的影响，并加密 CPU 和 GPU 之间的通信。这允许机密边界跨越机密虚拟机，并且加速器执行推理。

### **在机密模型库内**

没有任何一个组件可以使推理请求保密。

Model Vault 结合了围绕专用模型部署的多个控件，每个控件都解决信任问题的不同部分。

**机密 CPU 和 GPU 执行**

模型服务堆栈在机密虚拟机内运行。

通过硬件支持的隔离，保护操作系统、驱动程序、推理服务器及其内存免受主机环境的影响。工作负载还受到策略的限制，因此只有经过批准的软件才能在环境中运行，并且操作员没有进入工作负载的交互路径。

NVIDIA 机密计算将保护扩展到加速器并加密 CPU 和 GPU 之间的流量。

这很重要，因为安全边界需要覆盖实际执行推理的系统，而不仅仅是协调推理的 CPU。

Microsoft Azure 提供底层机密计算基础设施。 Model Vault 围绕该基础构建托管模型服务、加密请求、证明和客户验证层。

结果是客户不需要独立组装、集成和操作这些控件。

### **加密请求本身**

保护计算环境只能解决部分问题。

敏感数据也必须到达该环境。

TLS 保护网络连接，但仅连接级加密并不能保证参与操作服务的每个中介都位于明文路径之外。

因此，Model Vault 可以保护**应用程序有效负载本身**。

它使用 **Oblivious HTTP 或 OHTTP** 将敏感请求内容加密到与经过验证的机密环境关联的公钥。然后，加密的消息可以作为密文通过中间基础设施。

只有机密环境内的OHTTP网关才能访问相应的私钥并可以解密受保护的请求。响应在返回路径上以相同的方式受到保护。

这在**操作服务**和**访问请求的内容**之间形成了重要的分离。

中间基础设施仍然可以执行托管平台所需的功能，例如路由流量，而无需访问敏感应用程序负载。

应用程序继续使用 Model Vault API 和熟悉的请求格式。额外的保护是在客户端和基础设施层实施的，而不需要客户重新设计其应用程序有效负载。

### **远程证明：证明什么将处理请求**

隔离可防止机密边界之外的基础设施直接读取受保护的工作负载内存。

但仅靠隔离仍然留下一个重要问题：

**客户如何知道目的地实际上正在运行其期望的硬件和软件配置？**

远程认证解决了这个问题。

机密环境生成描述正在运行的环境的加密签名证据。这包括与硬件、固件、操作环境和应用软件相关的测量和安全相关属性。

然后根据批准的政策评估这些证据。

**证据**和**政策**之间的这种分离是根本性的。

证明证据答案： 
**实际运行的环境是什么？
**

政策给出的答案是： 
**这是一个我愿意信任我的数据的环境吗？**

在发布受保护的请求之前，验证者可以要求特定属性与批准的值匹配。

这些要求可以包括机密环境的预期软件测量和安全状态，包括 GPU 是否在预期机密模式下运行。

因此，客户不需要仅仅依赖 Cohere 的断言，即特定环境是值得信赖的。在发布敏感数据之前会进行验证。

### **证明作为执行机制**

当证明改变系统的功能时，它最为重要。

在 Model Vault 中，验证是决定是否发布受保护数据的一部分。

在发送受保护的请求之前，客户端会根据批准的策略评估目的地。

如果预期属性丢失或不正确，例如由于软件测量已更改或 GPU 未在所需的机密模式下运行，验证将失败并且客户端拒绝发送受保护的有效负载。

因此，敏感请求保留在客户环境内，而不是发送到不满足验证的目的地。

这将认证从审计工件转变为**主动安全控制**。

证明证据经常更新。每次刷新时，客户端都会根据批准的策略验证新的测量和安全状态，然后再继续发送受保护的请求。

这就是**先验证再信任**的实际意义。

### **信任边界和威胁模型**

机密计算减少了必须信任明文数据的基础设施的数量。

它并没有完全消除信任。

因此，了解剩余的信任边界与了解保护本身同样重要。

**什么仍然值得信赖**

多个组件仍然是可信计算基础的一部分，包括：

- 底层机密计算硬件
- 固件
- 测量在机密环境中运行的软件
- 用于定义批准配置的参考测量值
- 用于评估和签署证据的认证基础设施

重要的区别在于，这种信任可以变得更加明确和可衡量。

硬件会生成有关环境的证据，而客户控制的验证会在受保护的数据发布之前根据批准的值检查证据。

因此，该系统用一组较小的组件（其状态可以测量和评估）取代了某些形式的广泛的、隐式的基础设施信任。

**受保护的内容**

在其威胁模型中，Model Vault 上的机密计算可在处理提示、文档、响应和模型执行时对其进行保护。

机密环境之外的中介机构（包括主机操作系统、虚拟机管理程序、基础设施管理员、云提供商和 Cohere 操作员）无法读取受保护的工作负载内存。

由于敏感应用程序有效负载在机密环境中是端到端加密的，因此它们的内容在跨越中间基础设施时也仍然受到保护。

因此，保护涵盖以下两个方面：

- 承载敏感请求内容到机密环境的路径
- 执行推理的环境

这种区别很重要。仅机密执行环境并不能防止请求路径中其他地方的明文暴露。

### **保护边界之外的内容**

有用的威胁模型还需要说明它**不**保护什么。

机密计算并不声称可以防止所有可能的攻击。

**物理和旁道攻击**

一些物理和旁道攻击仍然在保护边界之外。例如，攻击者可能能够从计时或其他共享硬件行为间接推断信息，即使不直接读取受保护的内存。

**可用性**

无法读取受保护工作负载的操作员仍然可以停止它、延迟它或阻止它运行。

因此，机密计算本身并不能防止拒绝服务攻击或提供可用性保证。

**应用程序级漏洞**

在机密环境中运行的软件仍然需要安全。

即时注入、不安全的工具使用、授权错误、应用程序漏洞和其他软件级风险并不能仅仅通过将应用程序放置在机密计算硬件中来解决。

**可观察的元数据**

受保护的应用程序有效负载的内容已加密，但某些信息在该有效负载之外仍然可见。

这可以包括：

- 请求时间
- 消息大小
- 交通量
- 路由信息

在当前架构中，身份验证和路由所需的信息（包括 API 凭证和模型标识符）也保留在 OHTTP 保护的应用程序有效负载之外。

在推理系统隐藏什么和不隐藏什么时，这种区别是有意且重要的。

### **机密计算不是什么**

机密计算是更广泛架构中的一种安全控制。

它不是：

- **应用程序安全性的替代品。** 机密边界内的软件仍然需要正确设计、审查和保护。
- **数据驻留机制。** 机密计算控制计算期间对数据的访问。它并不确定计算发生的管辖范围。
- **替代合规性或合同控制。** DPA、访问控制、认证、安全审查和法律义务仍然是必要的。
- **同态加密。** 该模型仍然在受保护环境内的明文上运行。机密计算可以保护该环境，而不是直接对加密值进行计算。

仅当签名的证据实际上根据适当的策略进行验证时，证明才能提供保证。

证据描述了正在运行的内容。

策略决定该环境是否值得信任。

机密计算不会消除信任。**它使信任变得更小、更明确、可测量和可验证。**

### **开放式内置**

当客户和安全研究人员能够理解他们正在验证的内容时，验证就变得更有意义。

Model Vault 上的机密计算基于开源技术，包括 **Kata Containers** 和 **Confidential Containers**。

Cohere 打算开源机密推理堆栈，以便客户和研究人员可以检查实施情况、了解正在执行的策略，并重现验证过程中使用的测量结果。

这很重要，因为证明不应要求客户接受另一个黑匣子。

当客户能够理解测量的内容、检查与其关联的代码并独立推理该状态是否值得信任时，测量会更有用。

开放实施和可重复的测量使验证过程更加透明，并使安全团队能够在更深层次上评估系统。

### **下一步是什么**

当前的公开测试版在 Microsoft Azure 上的 **NVIDIA H100 GPU 上运行。

随着我们迈向全面上市，我们还致力于支持 **NVIDIA Blackwell 基础设施，包括 NVIDIA B200 GPU**。

Model Vault 上的机密计算是更广泛目标的一部分：为企业提供强大的技术控制，而不要求每个组织自行构建和运营机密 AI 推理。

目的不是要求客户信任更多基础设施或托管平台。

它为他们提供了一种验证他们选择信任的平台和基础设施合作伙伴的方法。
