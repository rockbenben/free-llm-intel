# 走进 Cohere Model Vault：构建可验证的机密 AI 推理

Model Vault 把机密的 CPU 与 GPU 执行、端到端加密的请求内容以及远程证明结合起来，在敏感 AI 工作负载被处理的过程中为它们提供保护。

![](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/fc96d67622cfc9c2b113f533f1385f1ceedb9638-1920x1080.png?auto=format&fit=max&q=80&w=1130)

在产品发布时，我们推出了 [**Cohere Model Vault 上的机密计算**](https://docs.google.com/document/d/1BvbHFNbT-GjlvSG7UMaaahsM4OX3A4YtZPp_330XT0g/edit?tab=t.0#heading=h.vv3sfmm4rp2q)，现已在 Microsoft Azure 上配合 NVIDIA GPU 进入公开测试阶段。

本文会更深入地介绍这套系统的工作原理。

目标不只是给推理加密，而是减少客户不得不托付明文数据的基础设施，并为客户提供密码学证据，让他们能在敏感信息被释放之前先行验证。

这需要的不只是一个机密虚拟机。机密推理系统必须保护计算本身，保护把敏感请求送达计算的那条路径，还要保护客户用来判断目的地是否可信的那套机制。

Model Vault 把这些部件围绕一次专用的模型部署整合到一起。

![](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/c445146fb507dd0bfeaf2815fc6a5dacb46eccee-3840x2540.png?auto=format&fit=max&q=80&w=800)

### **从机密硬件到机密推理**

机密计算保护的是**使用中的数据**，也就是应用或模型正在处理它的那份数据。

这一切的基础是两项属性：

- **隔离**：借助硬件强制的控制手段，保护工作负载内存不受机密环境之外的基础设施影响。
- **证明**：生成关于该环境的密码学签名证据，让另一方能在释放敏感数据之前对它进行评估。

这两项属性合在一起，改变了传统的基础设施信任模型。对底层宿主拥有特权访问权，不再自动意味着可以访问机密环境内运行的工作负载。

但对 AI 推理而言，边界不能止于 CPU。

模型计算中有相当大一部分跑在加速器上。如果 CPU 受到保护，而加速器仍留在机密边界之外，那么在推理转移到 GPU 的那一刻，敏感的模型状态和中间计算就可能暴露出来。

NVIDIA GPU 上的机密计算既保护 GPU 内存不受受保护环境之外的基础设施影响，也加密 CPU 与 GPU 之间的通信。这让机密边界得以覆盖机密虚拟机，连同在其中执行推理的加速器。

### **走进机密 Model Vault 内部**

没有任何单一组件能让一次推理请求变成机密的。

Model Vault 在一次专用的模型部署周围组合了多项控制手段，每一项各自处理信任问题的一个不同侧面。

**机密的 CPU 与 GPU 执行**

模型服务栈运行在一台机密虚拟机内。

操作系统、驱动、推理服务器及其内存都通过硬件支持的隔离手段受到保护，不受宿主环境侵扰。工作负载同时受策略约束：环境中只有经过批准的软件才能运行，运维人员也没有一条可以交互式进入工作负载的路径。

NVIDIA Confidential Computing 把保护延伸到加速器，并加密 CPU 与 GPU 之间的流量。

这一点很重要，因为安全边界需要覆盖真正执行推理的系统，而不只是负责协调的 CPU。

Microsoft Azure 提供底层的机密计算基础设施。Model Vault 则在这一基础上构建托管模型服务、加密请求、证明与客户验证等各层。

这样一来，客户不必再自行拼装、集成和运维这些控制手段。

### **加密请求本身**

保护计算环境只解决了问题的一部分。

敏感数据还必须能够抵达那个环境。

TLS 保护的是网络连接，但仅有连接级加密并不能保证所有参与服务运维的中间环节都留在明文路径之外。

因此，Model Vault 保护的是**应用程序负载本身**。

它使用 **Oblivious HTTP（OHTTP）**，把敏感的请求内容加密给一个与已证明的机密环境关联的公钥。这样，加密后的消息就能以密文形态穿过中间基础设施。

只有机密环境内的 OHTTP 网关能拿到对应的私钥，并解密受保护的请求。响应在回程路径上以同样的方式受到保护。

这在**运维服务**与**访问请求内容**之间划出了一道重要界限。

中间基础设施仍然可以执行托管平台所需的功能（比如流量路由），而无需访问敏感的应用程序负载。

应用照常使用 Model Vault API 和熟悉的请求格式。这层额外保护是在客户端与基础设施层实现的，客户不必重新设计自己的应用程序负载。

### **远程证明：证明将处理请求的东西**

隔离让机密边界之外的基础设施无法直接读取受保护的工作负载内存。

但仅有隔离，仍留下一个重要问题：

**客户怎么知道，目的地实际运行的正是它所预期的硬件与软件配置？**

远程证明正是为了回答这个问题。

机密环境会生成密码学签名的证据，用以描述正在运行的环境。其中包括与硬件、固件、运行环境以及应用软件相关的度量值和安全相关属性。

随后，这段证据会针对一份已批准的策略进行评估。

**证据**与**策略**之间的这种分工是根本性的。

证明证据回答的是： 
**实际运行的到底是什么环境？
**

策略回答的是： 
**这是一个我愿意信任、愿意把数据托付给它的环境吗？**

验证方可以要求特定属性与已批准的取值一致之后，受保护的请求才被释放。

这些要求可以包括机密环境预期的软件度量值与安全状态，其中包括 GPU 是否正运行在预期的机密模式下。

因此，客户不必仅仅依赖 Cohere 关于某个环境值得信任的断言。验证是在敏感数据被释放之前完成的。

### **把证明用作执行机制**

证明只有在能够改变系统行为的时候才最有价值。

在 Model Vault 中，验证本身就是「是否释放受保护数据」这一决定的一部分。

在发送受保护请求之前，客户端会依据已批准的策略对目的地进行评估。

如果某项预期属性缺失或不正确——比如软件度量值发生了变化，或者 GPU 没有运行在要求的机密模式下——验证就会失败，客户端会拒绝发送受保护的负载。

于是，敏感请求会留在客户自己的环境内，而不会被发往一个未通过验证的目的地。

这把证明从一份审计材料变成了**主动生效的安全控制**。

证明证据会频繁更新。每次刷新之后，客户端都会先把新的度量值与安全状态对照已批准的策略进行验证，然后才继续发送受保护的请求。

这就是**「信任之前先验证」**的实际含义。

### **信任边界与威胁模型**

机密计算减少了必须托付明文数据的基础设施规模。

但它并没有彻底消除信任。

因此，理解剩余的信任边界，与理解这些保护措施本身同样重要。

**哪些部分仍然被信任**

若干组件仍属于可信计算基，包括：

- 底层的机密计算硬件
- 固件
- 运行在机密环境内、被纳入度量的软件
- 用于定义已批准配置的参考度量值
- 用于评估并签署证据的证明基础设施

关键区别在于，这类信任可以被做得更明确、更可度量。

硬件产出关于环境的证据，而由客户掌控的验证则在受保护数据被释放之前，用已批准的取值去核对这段证据。

因此，这套系统用一组规模更小、状态可度量可评估的组件，替代了某些范围更宽、隐式的基础设施信任。

**哪些内容受到保护**

在其威胁模型范围内，Model Vault 上的机密计算会在 prompts、文档、响应和模型执行被处理的过程中保护它们。

机密环境之外的中间环节——包括宿主操作系统、hypervisor、基础设施管理员、云服务商以及 Cohere 的运维人员——都无法读取受保护的工作负载内存。

由于敏感的应用程序负载是端到端加密到机密环境的，它们在穿越中间基础设施时内容同样受到保护。

因此，保护同时覆盖：

- 把敏感请求内容送达机密环境的那条路径
- 执行推理的那个环境

这个区分很重要。仅有机密执行环境，并不能阻止明文在请求路径的其他环节暴露。

### **哪些内容仍在保护边界之外**

一个有用的威胁模型还需要说明它**不**保护什么。

机密计算并不声称能阻止每一种可能的攻击。

**物理攻击与侧信道攻击**

部分物理攻击与侧信道攻击仍在保护边界之外。例如，攻击者可能通过时序或其他共享的硬件行为间接推断出信息，即便并没有直接读取受保护的内存。

**可用性**

一个读不到受保护工作负载的运维人员，仍然可能让它停止、延迟，或干脆让它跑不起来。

因此机密计算本身既不能阻止拒绝服务攻击，也不提供可用性保证。

**应用层漏洞**

运行在机密环境内的软件仍然必须是安全的。

仅仅把应用放进机密计算硬件，并不能解决提示注入、不安全的工具使用、授权错误、应用漏洞以及其他软件层面的风险。

**可观测的元数据**

受保护应用程序负载的内容是加密的，但负载之外仍有一些信息是可见的。

这可能包括：

- 请求时序
- 消息大小
- 流量体量
- 路由信息

在当前架构下，认证与路由所需的信息（包括 API 凭证和模型标识符）同样留在 OHTTP 保护的应用程序负载之外。

这一区分是有意为之，在判断系统隐藏了什么、没有隐藏什么时很重要。

### **机密计算不是什么**

机密计算只是更宏大架构中的一项安全控制。

它不是：

- **应用安全的替代品。** 机密边界内的软件仍然需要被正确地设计、评审和加固。
- **数据驻留机制。** 机密计算管的是计算期间对数据的访问，它并不决定计算发生在哪个司法辖区。
- **合规或合同控制的替代品。** DPA、访问控制、认证、安全审查和法律义务依然必要。
- **同态加密。** 模型在受保护环境内仍以明文运行。机密计算保护的是那个环境，而不是直接对加密值进行计算。

只有当签名证据真正被针对合适的策略验证过时，证明才能提供保证。

证据描述正在运行的是什么。

策略决定这个环境是否应当被信任。

机密计算并不能消除信任。**它只是让信任更小、更明确、更可度量、更可验证。**

### **在开放中构建**

当客户和安全研究者能够理解自己验证的究竟是什么时，验证才更有意义。

Model Vault 上的机密计算构建在包括 **Kata Containers** 与 **Confidential Containers** 在内的开源技术之上。

Cohere 打算把这套机密推理栈开源，让客户与研究者可以检视实现、了解正在被执行的策略，并复现验证过程中使用的度量值。

这一点很重要，因为证明不该要求客户再接受一个黑盒。

当客户能理解测的是什么、能检视与之相关的代码，并能独立判断这个状态是否值得信任时，一项度量值才更有用。

开放的实现与可复现的度量让验证过程更加透明，也让安全团队得以在更深的层次上评估这套系统。

### **接下来**

当前的公开测试运行在 **Microsoft Azure 上的 NVIDIA H100 GPU** 之上。

随着我们迈向正式可用，我们也在推进对 **NVIDIA Blackwell 基础设施（包括 NVIDIA B200 GPU）** 的支持。

Model Vault 上的机密计算是一个更大目标的一部分：让企业不必各自搭建和运维机密 AI 推理，也能用上强有力的技术控制手段。

目标不是让客户去信任更多的基础设施或托管平台。

而是给他们一条路径，去验证自己选择信任的平台与基础设施伙伴。
