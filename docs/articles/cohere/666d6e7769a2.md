# 多语言之桥：数据混合如何解锁语言内推理

当一个 reasoning model 答错时，你会去读它的推理，来弄清楚是为什么。但如果那段推理用的是一种你不会说的语言呢？

![](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/b416a7d67e66515c45c29ca7b0664a6491ee9d5a-3840x2160.png?auto=format&fit=max&q=80&w=1130)

关键要点

- **真正多语言的 AI 应当用用户的语言来推理，而不只是用用户的语言来作答。** 今天的 reasoning model 大多用英文思考，这可能让 prompt 里的细微含义在内部翻译中丢失，让特定语言独有的文化知识闲置不用，并把不会英语的人挡在「检视或参与 reasoning trace」之外。从多语言作答走向语言内推理（被称为 “L2” reasoning），是迈向真正在不同语言之间都可及的推理系统的下一步。
- **我们发现，语言内推理可以通过建立在三根支柱之上的数据混合来实现。** 第一，在推理训练数据中确保更广的语言覆盖，能提升对没有推理监督的语言的泛化能力。第二，纳入一小部分多语言非推理数据，同时提升准确率和语言内推理。第三，使用英文推理数据提供了完成任务的主干。
- **由此得到的模型 Tiny Aya L2-Thinker（3.35B），在 60 种语言上有 93% 以上的情况用 prompt 的语言进行推理。** 它做到这一点而准确率损失极小，在低资源语言上站得住，并且比可比的模型使用更少的推理 token。
- **模型的推理能力与它用来推理的语言，并不总是彼此绑定的，所以 L2 reasoning 不必一种语言一种语言地建造。** 这让语言内推理即使在多语言推理数据稀缺的地方也变得可及。我们开放模型权重和多语言推理数据，以支持关于可及的语言内推理的后续工作。

![前后对比图，展示阿拉伯语、印地语、斯瓦希里语、葡萄牙语、威尔士语绕道英文 vs. 在推理中保留原语言 ](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/21cf3c78f41276deb0647d65936e3ed260548f5f-3141x1218.png?auto=format&fit=max&q=80&w=800)

### 推理所用的语言很重要

近来语言模型最大的一些进步，来自一个简单的想法：让模型在作答之前先“思考”。这个想法的成果，是发展出那些一步一步把一道题做下来、并写下“reasoning trace”的 reasoning model。这让语言模型完成数学和编程这类任务的能力大幅提升。然而这些模型主要关注给出正确答案，而我们要问一个常常被忽略的问题：用户真的能跟得上这些 reasoning trace 吗？

![Command A Reasoning 的卡片，展示 AI prompt、reasoning trace、最终答案 ](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/5f2548e59c4dfe20283e850df23ed599adc5200e-3732x2433.png?auto=format&fit=max&q=80&w=800)

对许多用户来说，今天的答案是不能：当一个问题是用西班牙语、阿拉伯语或斯瓦希里语提出时，这些模型往往用英文推理。最终答案可能以用户的语言返回，但答案背后的推理步骤，对不会英语的人依然够不着。这并不是一个无解的问题。通过让多语言的 reasoning model 能够用用户的语言推理——我们称之为“*in-language*”或“*L2*”推理——用户可以读 reasoning trace、逐步核验、在答案不对时找出哪里出了问题，并在需要时介入。

L2 reasoning 也可能帮到模型自身。很多知识，例如文化语境和语言上的细微之处，用它的源语言表达最为自然。L2 reasoning 可以让模型更有效地调用这种嵌在文化里的知识，在语言类和开放式生成任务上尤其如此。下面的例子展示了这在实践中是什么样子：用印地语问哪件事预示好运，我们的 Tiny Aya L2-Thinker 模型用印地语就印度迷信的讲究进行推理并得到正确答案，而用英语思考时，它直接断言了一个带西方偏向的答案，并没有权衡各个选项。

![一个迷信问题的印地语与英语 reasoning trace，展示文化锚点与预测答案](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/bc9b07ba79cb39e52e6d7cd4c221e766c47d8621-2460x1466.png?auto=format&fit=max&q=80&w=800)

在这篇博客里，我们介绍最近的这项研究：它展示了更好的数据混合如何带来有效的 L2 reasoning 而不太损害准确率。在 [32K 上下文长度的 Tiny Aya base model](https://huggingface.co/CohereLabs/tiny-aya-base-32K) 之上，我们施加自己的数据混合策略，做出 **Tiny Aya L2-Thinker**——一个大规模多语言的模型，在 60 种语言上达到 93% 以上的语言内推理比例。

### 已有工作缺了什么

让模型用用户的语言推理并不是新想法，但早前的尝试在三个方面力有未逮。第一，它们表明 L2 reasoning 往往是有代价的：被推着用另一种语言推理的模型[会把更多答案答错](https://aclanthology.org/2025.findings-emnlp.1103/)，而能避开这种下降的做法[又依赖复杂、昂贵的训练](https://aclanthology.org/2026.acl-long.951/)。第二，大多数研究只在数学和科学题上评测模型。数学是检验推理的好题目，但它同时也是语言最无关紧要的任务，所以它几乎告诉不了我们关于文化知识或开放式写作的任何事情。第三，它们只覆盖为数不多的几种语言，而且通常是那些已经获得 AI 研究者和开发者大量关注的语言。

我们的模型 Tiny Aya L2-Thinker 处理了这三个短板：它用用户的语言推理，同时在一系列任务上保持几乎与用英文推理一样准确，竞赛级数学除外。我们在数学推理、常识理解、文化推理、开放式写作和指令遵循上测试它。它在训练中还支持 45 种语言，并有证据表明它能把这一能力带到那些它从未见过推理示例的语言上。

我们还发现，推理时的语言强制手段补不上这些缺口：让 Qwen3.5-4B 用用户的语言思考，几乎不改变它的行为；而更强硬地强制——预先填入它 reasoning trace 的开头几个词——效果更好一些，但代价是准确率，而且这不是大多数用户能做的事。可靠的语言内推理必须来自训练，这就留下了「要训练什么」这个问题，也是我们接下来聚焦的主题。

![散点图，把 Tiny Aya 的 L2-Thinker 与 En-Thinker 同更大的模型在任务和推理比例上进行比较](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/286ec7c86a2740d3ad4f78e31ffca3c5be98b505-3564x2409.png?auto=format&fit=max&q=80&w=800)

### 为把推理迁移到英文之外而优化数据

我们的方法以训练数据为核心。我们怎样设计训练数据，才能让模型学会用英文之外的语言推理？我们组合了三种数据，称之为支柱（pillar），每一种教给模型不同的东西。

第一根支柱是**英文推理数据（ER）**：约 170 万条由一个更大的模型 gpt-oss-120b 生成的分步解答样例。模型在这里学会如何解题，它对数学最为关键。但单独使用它，得到的是一个几乎总是用英文思考的模型：它只在 12.8% 的情况下用用户的语言推理，即使被明确指示要这样做。

第二根支柱是**多语言推理数据（MR）**：我们把数学、科学和一般主题的英文推理样例自动翻译成 44 种语言。翻译长的 reasoning trace 代价高昂，所以我们每种语言只有约 5,000 个样例，与英文数据相比是极小的量。然而这一小批就足够教会模型用用户的语言推理：加上它，这一比例从 12.8% 提升到 86.1%，准确率也随之改善。

第三根也是重要的支柱是**多语言非推理数据（NR）**：问题与答案用目标语言、但没有 reasoning trace 的样本。这类数据在历史上要多得多，因为之前的多语言指令模型就在用它。这根支柱帮助模型把「用用户的语言推理」这一能力迁移到新的语言上，包括那些它从未见过推理示例的语言。

下面的图表展示了每一根数据支柱如何在前一根之上叠加，并逐步提升 L2 reasoning 的比例与准确率。关于每根支柱、以及我们如何选定最终数据配比的详细分析，见[我们的论文](https://arxiv.org/pdf/2609.10445)。

![柱状图：ER（36.7%、12.8%）、ER+MR（45.3%、86.1%）、ER+MR+NR（57.4%、96.4%）的准确率与推理比例](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/9545b79e9d7ef694689e96a3b3ac5a8f4c8c2631-8451x3269.png?auto=format&fit=max&q=80&w=800)

### 我们测了什么，以及发现了什么

除了 reasoning 基准通常报告的准确率分数之外，我们尤其关注三个方面，我们认为它们是让 reasoning model 在全球可及的关键：

- 我们是否在不牺牲质量的前提下实现了 L2 reasoning？
- 在较低资源的语言上，表现是否站得住？
- 推理本身质量如何？

我们在 60 种语言上的六个基准进行测试，覆盖数学（[MGSM](https://arxiv.org/abs/2210.03057) 与 [PolyMath](https://www.arxiv.org/abs/2504.18428)）、文化与常识推理（[Macaron‑MCQ](https://www.arxiv.org/abs/2602.10732) 与 [GlobalPIQA](https://www.arxiv.org/abs/2510.24081)）、指令遵循（[Marco‑Bench‑MIF](https://www.arxiv.org/abs/2507.11882)），以及开放式写作（[MIST‑OEG](https://aclanthology.org/2025.wmt-1.24/)）。

***我们是否在不牺牲质量的前提下实现了 L2 reasoning？***

这正是早前工作撞上的那个取舍，所以它是要检查的第一件事。我们把 Tiny Aya L2-Thinker 与它自己的孪生模型做比较：Tiny Aya En-Thinker 在同一个 base model 和同一批底层数据上训练，但用英文推理。

除了准确率，我们还衡量 L2 reasoning 的比例：即模型确实以目标语言完成推理的回答占比，我们通过在各条 reasoning trace 上运行一个语言识别模型来判定。一个模型可能在准确率上得分很好、而在这里彻底失败，而这个差距正是我们要去弥合的东西。

![柱状图，在多个基准上比较 Tiny Aya 的 En-Thinker 与 L2-Thinker 的任务准确率与 L2 reasoning](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/38182dc8659f3a3183dfa75bfa69682090507dfd-4567x1903.png?auto=format&fit=max&q=80&w=800)

准确率几乎没动。在六个基准中的五个上，它最多下降两到三个点；而在我们的开放式写作基准 MIST-OEG 上，它反而略有上升。英文表现同样站得住：面对英文 prompt，模型仍然用英文推理，并在多数基准上追平那个英文推理模型。作为交换，用用户的语言写成的 trace 占比从接近零升到了 93% 以上。

例外是 PolyMath，一个竞赛级数学基准，题目远在小学算术之上。这里准确率下滑得更明显。我们怀疑原因在于我们的模型从未经历强化学习阶段，而难度高的数学恰恰是从中受益最多的，同时它也能抹平我们在翻译训练 trace 时引入的伪影；这是一个可以作为未来方向去推进的路子，聚焦在数学上。

***在较低资源的语言上，表现是否站得住？***

对可用于训练的数据更少的语言，语言内推理通常更难做到。当我们与现有的、为 L2 reasoning 构建的更大模型相比时观察到了这一点：M-Thinker-7B 与 Magistral-Small-24B。在下面的图中，我们展示在四个资源等级上，每个模型用用户的语言推理的频率有多高、它有多准确，以及它把多少 token 花在推理上（作为效率的度量）。评测语言依据各自存在多少网络文本被划分为不同等级，tier 1 是资源最丰富的（例如英语、德语、法语），tier 4 是最少的（例如斯瓦希里语、祖鲁语、威尔士语）。

随着资源可得性下降，Tiny Aya L2-Thinker 是唯一在全部三个维度上都保持强劲的模型。它的 L2 reasoning 比例在 tier 1 和 tier 2 上贴近上限（99%），在最低的两档上只略微下滑（94.3% 和 94.5%）。相比之下，Magistral 的 L2 reasoning 比例从 72% 崩到 5%，M-Thinker 在每个维度上都退化、其 trace 长度大致翻倍，而被强制语言的 Qwen 把 L2 reasoning 比例维持在相当高的水平，但代价是准确率和效率。

整体而言，我们的模型也非常节省，平均思考 token 数不到 5,000，这要[归功于它做多语言优化的 tokenizer](https://cohere.com/blog/cohere-labs-tiny-aya)。

![柱状图，按语言等级把 Tiny Aya 的 L2-Thinker 与其他模型比较；更高的推理比例与准确率、更少的 token](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/4bf6086f6326f4d42f00395748bed6acc9f3ccfe-6264x2521.png?auto=format&fit=max&q=80&w=800)

***避开典型的推理失效模式：推理本身质量如何？***

一个思考得更久的模型，原则上应当是在“更努力地思考”，与用的是哪种语言无关。更难的问题值得更多推敲，更多的 token 也可能意味着更细致的工作。但在我们测过的模型上，长的 reasoning trace 通常意味着另一回事：模型在原地打转。

我们用一个重复度分数来衡量这一点——一条 trace 内短文本序列重复得多频繁——并把它与推理运行了多久做比较，见下面的散点图。两者一起上升：模型推理得更久时，重复率通常也更高。读这些 trace 会让这个规律变得具体：很多 trace 之所以长，并不是因为模型在探索备选方案；它们之所以长，是因为它在同样几步里循环往复，一遍又一遍，直到用完它的 token 预算、停下来而没有给出任何答案。这通常被称为 "doomlooping"。

![散点图：思考长度与 4-gram 重复度；Tiny Aya 的 L2-Thinker 在长度与低重复之间取得平衡](https://cdn.sanity.io/images/rjtqmwfu/web3-prod/3d22f1c64179714f5c2407399217b31ecff6f1c0-3116x1612.png?auto=format&fit=max&q=80&w=800)

Qwen3.5-4B 是最清楚的例子：它经常花 10,000 到 25,000 个 token 做那些未必提升表现的推理。用目标语言预填它的推理并不能救它：被强制语言的 Qwen 仍然待在同一个高 token、高重复的角落，而正如我们在上面的语言等级图中看到的，它在资源更少的语言上效率低得多。

Tiny Aya L2-Thinker 大体避开了这一点。在多数基准上，它用几百到几千个 token 完成推理，重复很少，并且在所有语言等级上都很高效，包括资源少的那些。高效推理还没有被解决，但它不必为了语言内推理而被拿去做交换。

### 小结与展望

我们已经表明，推理能力与推理语言是可分的。一个模型可以主要从英文推理数据中学会解题，从少量多语言推理数据中学会用哪种语言推理，并借助多语言非推理数据把这一行为泛化到新的语言上。

然而，用对的语言推理只是图景的一部分。一条 reasoning trace 可能对用户来说可以理解，却仍然在循环、跑题、始终得不到解，或者并没有真正对解产生有意义的影响。还需要做进一步的工作，让 reasoning trace 对下游用户更有意义、更高效、也更容易解释。
