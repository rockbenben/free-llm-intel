# Compass 即将登陆云端

无需为基础设施操心，即可用上我们最先进的搜索与检索引擎

[Compass](https://cohere.com/compass) 是 Cohere 的检索平台，面向用企业数据构建 AI 应用的开发者。它从公司的语料中浮现出最相关的信息，用于 retrieval-augmented generation（RAG）、搜索和 agentic 工作流。现在，Compass 以托管服务的形式进入私有 beta——**Compass Cloud**。

Compass 是为创造者而建的。它提供检索底座，开发者可以围绕自己的数据与工作流需求自由配置。团队不必自己拼装和运维整套技术栈，而是通过它的 API、MCP server 或 [Python SDK](https://github.com/cohere-ai/cohere-compass-sdk) 访问 Compass，塑造他们想要的终端用户体验。

此前，Compass 主要在为 [North](https://cohere.com/north) 提供检索——那是 Cohere 的企业 agent 工作台，包括其文档库和 MCP 生态。我们也已把 Compass 交付给受监管行业的合作伙伴，部署到高安全性的 self-hosted 环境中，他们的工作负载无法外包给 SaaS。

客户对托管选项的需求清晰而一致：团队想要 Compass 一流的检索能力，但许多人不想要 self-hosting 带来的运维负担。

我们听到了这些呼声。Compass Cloud 把 Compass 扩展到了更广阔的市场。它让 Cohere 同时托管整条流水线*和*模型推理，客户可以更专注于构建。同时，self-hosted 部署对有隐私约束的项目仍然可用。

我们正在与有限的若干企业团队作为 beta 伙伴合作。有兴趣吗？[申请访问](https://cohere.com/compass#compass-form)。

### Compass 在解决企业搜索中的开放难题

搜索与检索已经进步了很多，但企业级性能早已不再由单次查询的相关性和延迟来定义。随着检索成为生成式 AI 与 agent 的关键支撑基础设施，三个趋势正在改变需求：

- **Token 经济学: **传给模型的每一条不相关结果都会消耗 token、占用有限的上下文空间。更精准的检索产生更小、更高质量的输入，降低推理成本、缩短完成任务所需的时间。检索是当今企业手中最有效的成本杠杆之一。
- **Agentic 访问模式: **agent 在完成一项任务时可能发起几十次查询，重新表述请求、遍历多个数据源。在这些多跳循环里，延迟会累积、相关性会漂移、权限必须在每一步得到执行。因此，检索必须在成串的机器生成查询上稳定表现，而不只是单发搜索。
- **碎片化的检索技术栈: **生产流水线常常拼接着彼此独立的系统：摄取、索引、rerank、访问控制、编排。不同的中间件与各处「真相源」让团队把大量精力花在集成上，而不是检索质量上。

Compass 的存在正是为了逐一应对：1）为生成式工作负载提供相关的、受治理的上下文；2）同时支持 agentic 与常规搜索应用；3）把核心检索栈整合成一个一体化的企业平台。

### 全栈搜索与检索

Compass 把文档处理与检索打包成一个可配置的服务。团队可以访问一个统一界面，而不必集成和运维多个独立服务。

Cohere Compass 架构图：一个受治理的企业检索栈，经由解析、embedding、混合搜索与 rerank，把数据源连接到前端应用。

**Connect: **为你的文件共享与云存储工作区提供开箱即用的连接器，例如 SharePoint、OneDrive 和 Google Drive。凭借 Compass 近乎通用的数据兼容性——多语言、多模态、与文件格式无关——快速取到你需要的内容。

**Parse: **把复杂文档变成可搜索的结构化数据。Compass 将多模态企业文件转化为 AI 就绪的内容，为每份文档选用合适的解析策略，只在能增值的地方使用视觉处理，减少不必要的模型调用。

**Embed: **既捕捉语义，也捕捉精确术语。Compass 同时生成 dense 与 sparse 表示，让搜索在文本与多模态内容上既能匹配语义意图，也能匹配领域专有语言。

**Index: **把源文件、解析后内容和 embeddings 作为彼此独立的记录保存，这样换用新的 embedding 模型时无需重新爬取并上传同样的内容。检索时，它们连同元数据位于同一个索引中，减少了让各系统保持同步的需要。

**Retrieve: **在一次请求中组合多种搜索策略。语义搜索、sparse 搜索与关键词搜索可以独立或组合运行，在召回与精确之间取得平衡。权限在检索过程中执行，而不是留给应用层处理。

**Rerank: **把更有力的证据送给模型。Cohere 一流的 reranker 从宽泛的候选集中识别最相关的段落，减少无关上下文以及生成所需的 token。

**Govern: **在检索期间执行多租户访问控制与文档级权限，让应用不必自己过滤结果。在 Compass 中，保留策略会自动让过期内容失效，并防止已删除文档被重新同步。

### 高端的检索精度

Compass 的核心目标很简单：提升为企业知识应用——无论是一条 RAG 流水线还是一个自主 agent——所浮现信息的相关性。这种质量植根于 Cohere 一流的搜索与文档处理模型，加上 Compass 的混合搜索：lexical、sparse 与 dense 检索，再做 rerank。

下图是在一个有代表性的金融行业 RAG 工作负载上，相对传统或独立搜索基础设施的精度增益实例：embed 一条查询、从索引中检索演示材料、为最前面的结果打分。在 Cohere 构建的投行业务基准 High Finance 上，Compass 相对 Azure Search 提升了 14-16 个点（从 64.8 到 81.1）。这样的差距，可能就是终端用户得到一个不满意的回答与一个出色回答之间的差别。

High Finance 上的检索精度（nDCG@10）。High Finance 是一组内部的、由 Cohere 标注的问题，要求模型检索相关的投资银行与对冲基金演示材料。Azure Search 的文档用 GPT-4.1 Mini 解析。Cohere Embed 4 没有使用单独的解析方案，而是在搜索前把输入 PDF 直接作为图像 embedding。

### 按你的方式构建

用户可以根据自己想把检索集成进应用的方式，通过两条主要途径用 Compass Cloud 提升搜索性能：

- **Compass API: **最适合构建自定义 RAG 与搜索应用的团队。使用 Compass API 直接集成驱动 Compass 的模型与检索组件，让开发者对内容的表示、检索、排序以及如何并入应用拥有更多控制。
- **Model Context Protocol（MCP）: **最适合 agentic 检索。Compass 自带一个独立的、单独版本管理的 MCP server，通过开放标准把检索作为可复用工具暴露出来。兼容 MCP 的客户端可以直接发现并调用这些工具，使 Compass 无需为每个 agent 框架做定制集成就能跨框架移植。

Agentic 检索是大语言模型与信息检索交叉处的一种新兴做法。agent 不依赖单次的查询-响应检索步骤，而是可以决定找什么、搜索相关信息、评估结果，并在回答前不断精炼自己的搜索。

这对无法靠一次查找解决的任务尤其有用。借助 Compass MCP server，agent 可以逐步收窄检索语料，减少不必要的上下文，让复杂检索任务更快、更省 token。

在 North 中把企业 agent 连接到 Compass MCP。
