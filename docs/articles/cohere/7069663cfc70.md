# 自动化的早期足迹

AI Agent 正在（以及尚未）被构建的方向

核心要点

- 我们把七个公开的 AI 工具目录聚合成一个新数据集：**Agentic Task Ecosystem（ATE）**，收录约 **69.6 万个已发布工具、分布于 12.3 万个 MCP server**，是同类中最大的开放数据集。
- 在一个严格标准下——工具必须能*执行*某项职业任务，而不仅仅是为执行该任务的人提供信息——只有 **2.6%** 的工具过关。**对已认可工作的自动化只是这个庞大生态中很小的一片。**在那些能归入可识别类别的工具中，三种模式占主导：**比职业数据库记录粒度更细的既有工作、供 agent 自身运行的基础设施，以及少量真正的新工作——其中大部分是管理 agent 的工作。**
- **美国近半数职业没有任何 agent 工具覆盖。**在 923 个职业中，419 个没有任何形式的 agent 工具活动。
- **被构建的东西跟随可被构建的东西。**专家对技术可行性的判断能预测哪些职业获得工具；工人自己希望自动化什么的偏好则什么都预测不了。
- **决定劳动力市场结果的问题不是某个职业有多大比例暴露于自动化，而是哪些部分被自动化。**在 178 个职业中，我们把所需工作任务从最常规到最专业化排序。在医疗和计算领域，agent 工具存在于职业中偏专业化一端的任务上，把更常规的剩余留给人。在法律、生产和销售职业中，工具停留在常规边缘，把专业化核心留给人。**当专业化工作是体力或人际性的时，它抗拒自动化；当它已经通过软件进行时，它就让位于自动化。**

数十万工具已被发布，让 AI 系统代表我们行动：写代码、查询数据库、更新记录、安排会议、在应用之间搬移信息。但这层快速扩张的 agentic AI 基础设施到底加起来是什么？我们正在构建 AI 去自动化哪些工作？

我们关于 AI 与工作的多数认知来自两个视角之一。一些研究估计 AI 理论上能做什么，依据 AI 系统可以合理承担的职业任务百分比来计算[暴露度](https://cohere.com/blog/the-future-of-work-debate-has-an-evidence-problem)。另一些则观察人们要求 AI 做什么，分析数百万次对话，看用户把哪些任务带给聊天机器人 [[AI Observatory, 2026](https://www.ai-observatory.org/); [Handa et al., 2025](https://www.anthropic.com/economic-index); [Iscenko et al., 2026](https://arxiv.org/abs/2608.00038); [OpenAI, 2026](https://openai.com/index/how-ai-is-expanding-what-people-do-at-work/); [Tomlinson et al., 2025](https://arxiv.org/abs/2507.07935)]。两者都是 AI 如何影响工作这幅大拼图的独立一块，但单凭各自都不代表完整图景。在 Cohere Labs，我们致力于帮助拼上这幅拼图，我们的研究从第三个互补视角——*agentic 任务生态*——提供新证据。

[我们从 12.3 万个公开 MCP server 收集了近 70 万个工具，构建了 **Agentic Task Ecosystem（ATE）**](https://huggingface.co/datasets/CohereLabs/ATE) 数据集，并提问：*开发者构建了哪些工具，让 AI agent 得以完全自动化某些工作任务？*我们的发现让"agent 正把一个任务接一个任务地吞掉职业"这一简单想象变得复杂。

### 什么是 MCP 工具？

过去两年，AI 系统已从生成文本走向自主行动。一个曾经只在聊天窗口里回答问题的模型，如今可以查询数据库、编辑文件、开 pull request、安排会议，或按顺序运行这一系列任务。

[Model Context Protocol](https://www.anthropic.com/news/model-context-protocol)（MCP）是把 AI 系统连接到外部软件和数据的开放标准。一个 server 可能让模型操作 GitHub，另一个可能给它访问日历、电子表格、支付系统或公司内部文档的能力。实践中，开发者编写一个 MCP server，它由一组工具构成，每个工具附带一段简短的功能描述。

### 把 MCP 工具作为"我们在自动化什么"的记录

研究自动化的经济学家通常权衡[三个变量](https://economics.mit.edu/sites/default/files/2022-11/ACSS-NewFrontiers-20220814.pdf)之间的关系：（1）人类做什么工作，（2）什么工作被交给机器，（3）对双方而言出现了什么真正的新工作。自动化把工人从机器可执行的任务上置换下来，而涌现出的、人类仍握有优势的新任务则把他们重新安置回去。哪种效应更大，决定了这项技术总体上[抬高还是压低](https://www.aeaweb.org/articles?id=10.1257/jep.33.2.3)对人类工作的需求。

这个方程里的第一个变量有相对充分的记录——[O*NET 等职业数据库](https://cohere.com/labormap)在任务粒度上分解并描述人类工作（至少在美国语境下如此）。第二和第三个变量要难测量得多，这正是 ATE 与使用数据、暴露数据并列时价值所在。

每一个已发布的 MCP 工具，都是一份关于某项被认为可完全自动化的任务的小型、带日期、公开的记录。某个开发者或建造者看到一块工作，判断它足够具体、足够可靠可以交给机器，于是把它打包成机器可以调用的东西。这并不意味着该工具被广泛使用、能自动化[长时程任务](https://cruxevals.com/)，或可靠到适合每个职场。作为一个衡量"什么已被做出来"而非"什么被使用"的供给侧信号，ATE 告诉我们关于工作未来拼图的独特信息——**开发者在哪里判断自动化已经就绪，*早于*任何关于是否有人采用它的证据。**

### 构建 ATE

2026 年 5 月，我们跨越七个目录从 123,069 个公开 MCP server 条目中收集了 696,291 个工具。对每个 server，我们记录所有列出工具的名称和描述，并去重，使得在多处重复发布的 server 只计一次。

公开的 MCP 语料此前已被汇编过，多数是为了研究基础设施本身是否健全与安全 [[Guo et al., 2025](https://arxiv.org/abs/2509.25292); [Lin et al., 2025](https://arxiv.org/abs/2506.23474); [Wu et al., 2025](https://arxiv.org/abs/2512.15144)]。其中最大的 MCPZoo 收录 56,053 个不同的 server；我们覆盖了其中 85%，外加它没有的约 6.6 万个。与我们问题最接近的是 [Stein (2026)](https://arxiv.org/abs/2603.23802)，该研究分析了取自 GitHub 和 Smithery 注册表的 19,388 个 server 上的 177,436 个工具——追问一个工具是否让 agent 得以感知、推理或行动，以及受影响职业的重要性。他们报告 67% 的工具和 90% 的下载集中于软件和 IT 工作，这个集中度我们也看到了：在我们的语料中能映射到任何职业的工具里，计算类占多数。

对每个工具，我们找到最接近的现有 O*NET 任务陈述，并让一个语言模型判断该工具是否执行了那项任务。该协议有意过滤掉那些只向用户提供信息的工具，或只处理仍由人协调的流程中某一步的工具，因此留下的是真正*执行*任务陈述所命名的任务、而非协助他人执行的工具。

在这一标准下，**约四十分之一的工具**——2.6%——端到端地执行一项被记录的工作任务。

一个局限是我们只能观察公开目录。企业会针对自己的系统构建 MCP server 而从不发布，这个缺失的层级很可能偏向职业数据库所描述的后台流程类型。厂商发布的企业级 server 已包含在内；缺席的是定制的内部层级。这一偏差反而不利于我们的结论，因为我们的计数只会漏掉工具而不会多算，因此 2.6% 最好被读作一个下限。

### 那匹配上的 2% 工具告诉我们什么

在工具确实匹配到现有工作的地方，它们的落点很不均匀。匹配上的工具挂在 1,380 个不同的任务陈述上，约为 O*NET 所记录的可由软件执行的工作的 15%；覆盖率最高的职业正是那些大部分工作已经通过软件完成的角色——例如平面设计师，其 15 项可由软件执行的任务中有 11 项有工具匹配。覆盖不仅在职业之间集中，在职业内部同样如此。匹配到平面设计的工具中超过一千个挂在同一个任务陈述上——"使用计算机软件生成新图像"——这种宽泛措辞的任务恰是大量通用工具都能真正执行的那类。

拉远视角**，O*NET 收录的 923 个职业中有 419 个完全没有 agent 工具活动**。对于任何在问 agentic AI 冲着哪些工作来的人，供给侧的诚实回答是：对其中大量职业，还没有人在构建任何东西。

### 剩下 98% 未匹配的工具呢

按相似性对未匹配工具分组，得到 1,136 个描述某种工作的类别。逐类检视后，我们有三条独立的观察：

**1）大部分是既有工作，只是粒度不对。**我们发现 693 个类别属于我们所说的*亚原子（subatomic）*：被拆成比职业数据库更小单元的、可识别的工作。任务陈述说"维护配置控制"时，ATE 里有几十个工具分别对应该任务的单个组件。另有 411 个 MCP 类别朝反方向：跨越多个被记录的任务、或把它们捆绑成没有任何单一任务陈述命名的工作流，例如会议记录管理要跨 O*NET 记录为独立任务的多个环节收集、组织、分析 transcript。两类都不在已认可工作之外——亚原子工具只是不完成任务陈述描述的整个流程，复合工具则把若干任务缝在一起。

**2）供 agent 运行的基础设施。**语料中相当一部分是使 agent 得以运转而存在的工具：注册 agent、发现其他 agent、管理会话、处理彼此之间的身份。这是真正前所未有的工作，但更准确的描述是自动化的运营开销，而非一种新的产出。

**3）少量真正的新工作，大多与管理 agent 有关。**从对既非亚原子也非复合、也非基础设施的工作类型的早期探索看，确实存在少量真正崭新的人类工作。只有 35 个类别（约 3%）描述在工作记录中没有合理对应物的工作，其中大多数是因为 agent 存在才存在的工作：挑选合成语音、开发和切换 AI persona、评估一个 agent 是否可信。为检验这一分类站得住，我们在不查看模型答案的情况下对 120 个类别做了盲法人工标注；人工标注指向同样的方向，如果说有差别，是找到略少的真正新类别。

### 理论说对了什么，遗漏了什么

我们把使用最广的[暴露度评分](https://cohere.com/blog/the-future-of-work-debate-has-an-evidence-problem)与实际被构建的东西做了对比。这些来自 [Eloundou et al.](https://arxiv.org/abs/2303.10130) 的评分对每条 O*NET 任务陈述评级：语言模型配合相关软件能否在不损失质量的前提下把完成时间至少砍半。我们发现职业的理论暴露度与可用 MCP 工具数量之间存在关联。

在 178 个职业上，理论暴露度与已实现的 MCP 覆盖度的相关系数为 0.54——对两个基于完全不同的证据构建的指标而言这是很强的关系。在*一个职业有多大比例可被触达*这个问题上，暴露度评分表现良好。

然而暴露度不告诉你的，是工具触达的是一份工作的哪一部分。它与匹配任务在职业自身任务组合中所处位置的相关性，与零无异。

覆盖深度同理。一个职业拥有多少工具，并不能说明这些工具触碰的是它的常规边缘还是专业化核心——两者在统计上相互独立。工具密集的职业并*不*因此就在其核心承压。作为预测因子，工人偏好同样糟糕。针对 65 个职业，[WORKBank](https://futureofwork.saltlab.stanford.edu/) 既调查了工人希望哪些任务被自动化，也调查了专家判断 AI 有多大能力执行它们——实际被构建出来的东西跟随专家判断，而与工人真正希望自动化的任务类型毫无关系。

那么，针对职业常规边缘的自动化与针对专业化核心的自动化，含义分别是什么？

**自动化落在工作内部的哪里很重要**

**两个职业对某项技术的总体暴露度可以相近，自动化的结果却大不相同。例如在计算机化时代，会计文员和库存文员的工作被自动化触达的比例几乎相等，但[会计文员的工资上涨而库存文员下降](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=6134506)。差别不在于技术触达了多少工作，而在于暴露之后留下了什么类型的任务。**

如果相对常规的任务被委派给 AI 系统，而专业化工作留给人，人类精力可能集中于一份工作中最需要专业专长的部分。经济学家称之为[**提升专业性的自动化**（expertise-raising automation）](https://www.nber.org/papers/w33941)。如果 AI 反而执行了区分专家与其他人的专业化任务，效应可能朝相反方向运行。简言之，专业性框架给了我们一种区分自动化形式的方法——即使自动化总量看起来相似，它们对工人的后果可能非常不同。

我们使用该框架对 ATE 数据集做了首次分析。具体而言，我们问*：相对于每个职业自身的任务组合，MCP 工具匹配到该职业专业性要求的哪个位置？*

### 我们在 ATE 中看到的专业性

在所有 178 个覆盖足够可测的职业中，平均而言工具几乎恰好落在一份工作自身范围的——既不显著偏向常规侧，也不显著偏向专业化侧。

但这个均值掩盖了方向相反的模式。在医疗和计算职业中，存在的工具朝工作的专业化一端延伸，把更常规的剩余留给人，即经济学家所说的*降低专业性的自动化（expertise-lowering automation）*。在生产和销售职业中，工具停留在常规边缘，把专业化核心留给人并抬高进入门槛：*提升专业性的自动化*。为给出量化数字，我们按"若匹配任务被交给 AI 工具，剩余工作的平均专业性会如何变化"为每个职业打分。该度量改编自 [Autor and Thompson (2025)](https://www.nber.org/papers/w33941)，在下方图表中以 ΔExpertise 表示（剩余工作对工人要求更高时为正，更低时为负）。

图表按匹配工具数量展开各职业，而沿该轴的平坦本身就是一个发现：**一份工作吸引多少工具，并不能告诉你工具触达工作的哪一端**。工具密集的职业与工具稀少的职业相比，其专业化工作受影响的可能性并无更高。处于专业化一侧的各群组共有的，是它们处理信息的工种类型。在全部 178 个职业中，工具在核心职能为结构化、分析或管理信息的角色上延伸进专业化工作最远，而在交付某一领域首要服务的角色上延伸最近。与特定专业领域绑定的信息工作位置最高：临床数据管理员和生物统计师是最清楚的案例，分别有 143 和 82 个匹配工具。即使考虑到这些职业可用工具数量本来就高，模式依然成立。

计算是工具延伸进专业化工作最远的群组之一，也是样本中证据最充分的案例，建立在三十个职业之上。医疗从业者是唯一在同一方向上更靠前的职业群组，但只基于五个职业。

解读技术类工作内部发现的一种解释是：开发者先为自己构建。这很可能是部分原因——MCP 生长自软件世界，其公开目录偏向开发者工具，使技术类职业在这里异常可见。

但医疗语境中匹配工具的大量存在表明这不是唯一原因。医疗和计算都是大量专业判断已经在软件内部行使的领域。我们给出的解读是：专业化工作并非一律难以自动化——当它是体力或人际性的时候难以自动化，而当它已经通过软件进行时则相对可控。

### 在转型发生时为其测量

ATE 数据告诉我们开发者为哪些类型的任务构建了开源 agentic 能力。单凭它本身，不能告诉我们企业是否部署这些工具、工人是否使用它们。结合[近期证据](https://openai.com/index/how-enterprises-put-ai-to-work/)——显示企业环境中 agentic 使用明显激增——与 AI 共事看来将越来越意味着部署 agentic 能力。ATE 衡量的是供给，不是采用率也不是经济影响：一个工具的存在只说明某位开发者判断该任务足够具体可以交给机器，而它的缺席说明还没人做出这一判断。对于追问 AI 自动化轨迹的问题，那 419 个没有任何构建的职业与那些有数百个工具的职业同样重要。因为供给位于采用链条的上游，它可以帮助研究者在下游效应见于就业或工资数据之前进行监测，帮助开发者有意识地构建。

我们的专业性分析把这一早期信号与一个有形的框架连接起来，以理解对劳动力市场的预期影响。跨职业平均，工具没有系统性方向，但该平均值掩盖了医疗和计算（工具触达专业化核心、把常规剩余留给人）与法律、生产和销售（工具停留在边缘、专业化工作仍归人）的对照。

然而这引出了关于提升/降低专业性的自动化对工人真实结果的新问题。这不是把一个结果定为正面、另一个定为负面那么简单——首先，工资和就业的效应并不同向。提升所需专业性的自动化可能提高在岗工人的工资，但缩小合格申请人池。降低一个职业进入门槛的自动化可以被视为[专业性的民主化](https://www.nber.org/papers/w32140)，但这没有考虑技能和专长如何由经验塑造。入门级[工人常常通过](https://mitsloan.mit.edu/ideas-made-to-matter/how-can-we-preserve-human-ability-age-machines)资深同事和导师交接的常规任务来学习。已有观察表明，在 AI 高暴露职业中年轻入门级工人的[招聘已远落后](https://digitaleconomy.stanford.edu/news/canariesaug26/)于其同龄组，而且这一差距在过去一年只扩大未缩小。如果那部分工作越来越多由机器完成，"人如何成为专家"在我们看来是关于 AI 与工作最重要的开放问题之一。

我们发布 ATE 数据集，以便他人继续对它提出自己的问题。公开的 agent 版图庞大、碎片化且变化迅速。ATE 是我们让这种变化可度量的一次尝试——不仅追踪 AI 变得能做什么，还追踪开发者实际把哪些能力变成了工具、这些工具触达人类工作的哪些部分，以及最终这些选择与工人想要和使用的东西相比如何。如果目标只是创造在多数经济价值最高工作上胜过人类的高能力技术，[核心职业角色将处于风险之中](https://economics.mit.edu/sites/default/files/2026-03/Building%20Pro-Worker%20Artificial%20Intelligence.pdf)。如果一个人的替代品永远是另一个人的互补品，这项技术对财富与权力的真实影响[就不能靠简单地把技术分为增强型与自动化型来计算](https://www.brookings.edu/articles/the-turing-transformation-artificial-intelligence-intelligence-augmentation-and-skill-premiums/)。机器能力扩展人类机会、抬升劳动价值的未来是可能的，但需要早而有分量的干预。通过观察早期趋势，开发者可以带着意图和目标构建工具，决策者可以为下游影响做好准备。工作的未来不会只由 AI 能力决定。
