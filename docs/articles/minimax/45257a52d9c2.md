Mini App 是一种带前端和后端、可以长期运行的应用，以插件形式安装，能和 Agent 互相调用，让 Agent 干的活留在一个一直在跑的页面上。

![封面：一只手把卡片放进由股市看板、3D 模型、地图和对话等 Mini App 组成的拼图，一条线连到 Agent](https://filecdn.minimax.chat/public/minimax-code-mini-app-cn-cover-1-1792651248999.jpg?x-oss-process=image/format,webp)

今天，我们在 MiniMax Code 桌面端推出 [Mini App](https://agent.minimax.cn/docs/miniapp/overview)。它是一种带前端和后端、可以长期运行的应用，以插件形式安装，能和 Agent 互相调用。我们想让 Agent 干的活留在一个一直在跑的页面上，不用再去各个会话里翻。

现在很多工作已经交给 Agent 去做，比如重构代码、整理消息。可每件事都在单独的会话里推进，接着做之前，得先在一堆会话里找到上下文，回忆这个会话当初在做什么。让 Agent 生成一个 HTML 看板能把信息聚到一起，但页面上只有生成那一刻的数据。要持续更新、推进任务、保存结果，还得回到聊天里重新交代。AI 与人的交付从来不是一次性，有时我们需要一些人类的修订，有时又需要一些 AI 的协作。

Agent 插件让你改造 Agent，Mini App 让你在 Agent 之上做应用。端口、Agent 和数据目录这些系统级的事交给宿主 MiniMax Code，由它划清边界；工具长什么样，用户自己和 Agent 一起讨论。

## Mini App

Mini App 是一个兼容 [MiniMax Plugin 协议](https://agent.minimax.cn/docs/code/agents/plugin-submission)的扩展，多了一份 `miniapp.json` 声明，以及前端和 Node.js 服务端。结构很简单：Node.js 服务负责取数、保存结果，并把业务能力通过托管 MCP 交给 Agent；页面显示在会话侧栏，也可以弹出为独立窗口；进程、端口、鉴权、凭证和可回滚的发布都由宿主负责。

![Mini App 架构：上层是以插件形式安装的 Mini App，各自有页面、Node 服务和数据；下层是宿主 MiniMax Code，提供端口、Agent 和数据目录；两者通过托管 MCP 和 Agent API 互相调用，你跟 Agent 说想要什么工具](https://filecdn.minimax.chat/public/minimax-code-mini-app-cn-architecture-2-1792651248999.jpg?x-oss-process=image/format,webp)

今天发布的内容包括三部分：

- Mini App 运行时：Node 后端与持久数据目录、托管 MCP、Agent API、Host Connector，以及在页面中处理工具审批
- `/miniapp-creator`：在聊天里用一句话，从需求走到可用的页面
- 插件市场中的官方 Mini App，和开源社区仓库 MiniMax-Code-MiniApps

用 `/miniapp-creator` 时，Agent 会先对每个数据源做一次只读查询，确认能拿到真实数据，再写页面和后端、发布、打开，最后用内置浏览器截图验收。

首批官方 Mini App 里，有几款是团队里的非研发同事这样做出来的：

- 股市 Mini App 把分散在知识星球、进门财经、腾讯文档里的股票信息集中到一个看板；
- CadQuery Viewer 让你在 3D 模型上标出位置，发回对话让 Agent 修改；
- 自驾规划把地图算路、搜索和图片生成串成一个行程工作台。
- MiniMax Bot 本身也是一个 Mini App。主 bot 组建团队，把耗时任务交给后台 Agent 会话，做完再统一验收和汇报；会话里的 Agent 又能调用 Bot 的工具发消息、保存和查找记忆。大多数 Bot 功能的更新只需要改插件，不必等 MiniMax Code 发版。它的源码已经放进开源社区。

开源社区里也陆续出现了开发者自己做的 Mini App，比如按日期和模型查看 Token 用量的看板、用泳道图浏览 Git 提交历史的 Git Commit Tree，以及回看一次对话模型轨迹的 Session Trajectory；也有偏生活和创作的，比如每天记心情、抽灵感卡的心屿，和让 Agent 新建、修改交互式图解的 Anatomy 画廊。

> “从早期的工作流，到 RAG、Agentic Search 以及在 MiniMax 的实践的启发下，我发现，比起酷炫的 Agent，专业工作更需要一个让 Agent 与人深度协作、高度内聚的原生环境。之前，作为金融行业的分析师，我的多数时间都花在零散的信息整理上，现在用 Mini App 把他们融入到我的工作台，我可以更加专注于思考和判断，把信息的整理和分析推演完全交给 Mini App。”—— MiniMax 产品经理

安全上，账号凭证由宿主保管，插件和页面都拿不到；Connector 和 Agent 权限必须在清单里声明才能使用；服务端口只对 Mini App 自己的页面和 Agent 开放。页面想把内容交给 Agent 时，内容先进入你的输入框，由你确认、修改后再发送。**Mini App 的代码以你的身份在本机运行，请只安装来源可信的包**。

## 开始使用

Mini App 现已在 MiniMax Code 桌面端（macOS / Windows）的本地会话中可用。

你可以从插件市场安装现成的 Mini App，也可以在聊天里描述需求，让 Agent 当场做一个，用一段时间后再让它按你的习惯改。

开始构建：

下载 MiniMax Code：

- 国内 [https://agent.minimax.cn/download](https://agent.minimax.cn/download)
- 海外 [https://agent.minimax.io/download](https://agent.minimax.io/download)

阅读快速上手，用 `/miniapp-creator` 做出第一个 Mini App：[https://agent.minimax.cn/docs/miniapp/authors/quickstart](https://agent.minimax.cn/docs/miniapp/authors/quickstart)

## 开放的社区

MiniMax Bot 的源码和社区作品都放在开源仓库 [MiniMax-Code-MiniApps](https://github.com/MiniMax-AI/MiniMax-Code-MiniApps) 里。做了好用的 Mini App，欢迎提 Pull Request 分享出来。

需要 Mini App 还没有的运行时能力，可以到开源社区置顶的[能力许愿单](https://github.com/MiniMax-AI/MiniMax-Code-MiniApps/issues/9)留言。
