通过 Together AI 的生产推理平台，用 Inkling——一个为高级推理设计的新型多模态 mixture-of-experts 模型——进行构建。

今天，Thinking Machines Lab 发布了 Inkling——一个为 token 高效推理、原生多模态理解和广泛任务多面性而构建的新型多模态 mixture-of-experts 模型。Together AI 很高兴与 Thinking Machines Lab 团队合作，在我们的推理平台上把 Inkling 提供给开发者。

Inkling 接收文本、图像和音频输入，通过统一 decoder 架构产出文本输出。它支持可控推理强度，让开发者根据每个任务的需要调节模型投入多少推理。其训练后处理也覆盖广泛能力，包括科学推理、编码、agentic 工作流、预测和校准预测。

底层，Inkling 引入了若干超出常规 decoder-only Transformer 的架构创新，包括 query 条件化的相对注意力、贯穿全模型的短因果卷积，以及带共享 expert sink 的 mixture-of-experts 架构。这些组件合起来，旨在支撑强推理与多模态能力的同时保持高效的模型执行。在规模上高效服务它并不容易，而这恰恰是 Together AI 推理栈为之优化的负载类型，让你在真实生产推理中拿到模型的效率红利。在 Together AI 上，Inkling 运行在优化的[基于 FlashAttention-4 的注意力 kernel](https://www.together.ai/blog/flashattention-4)上，专为高效支持其 query 条件化相对注意力机制在生产中的运行而设计。

祝贺 Thinking Machines Lab 团队的发布。

## **Inkling 速览**

- **Token 高效、可控的推理：** 开发者可调推理强度，在不同负载之间平衡推理深度、token 用量和延迟。
- **原生多模态输入：** Inkling 接收音频、图像和文本输入，通过单一模型生成文本输出。
- **广泛任务多面性：** 模型在推理、编码、agentic、预测和校准预测任务上做了训练后处理。
- **差异化的架构：** Inkling 结合分组查询注意力、学习式相对位置偏置、短因果卷积和 shared-sink MoE 路由。
- **强劲的初步评估：** 在其最高评估强度档位，Inkling 在科学推理、数学、编码、agentic、视觉和音频基准上表现强劲。
- **已在 Together AI 上线：** 开发者可以通过 serverless 访问 Inkling，1M 上下文窗口，OpenAI 兼容 API。

**Day 0 访问，零设置：** Inkling 今天在 Together AI Serverless 上线。不用等容量、不用开通基础设施、不用管理 GPU。

## **面向推理与多模态的新架构**

Inkling 是一个 decoder-only mixture-of-experts 模型，总参数 **975B**、每 token 激活参数 **40B**，上下文窗口 **1M token**。

Inkling 不用 RoPE 或绝对位置嵌入，而是通过学习式的、query 条件化相对偏置，把 token 位置直接融入注意力。每个注意力层把常规的 query-key 相似度分数与一个基于 token 间相对距离的额外分数结合。这给模型一个灵活的机制来表达 token 顺序与邻近上下文。

Inkling 在整个网络中混合滑动窗口与完全因果注意力。标准架构是五个局部注意力层后跟一个完全注意力层，让多数层高效聚焦近期上下文、同时周期性地把信息整合进整个序列。

模型还引入了 **sconv**——感受野为四个 token 的轻量逐通道因果卷积。Sconv 在注意力之前应用到 key 与 value 流，也应用到注意力和前馈子层的输出。这些短卷积给每一层一个额外机制来组合相邻 token 的信息，而不付出又一次完全注意力操作的成本。

Inkling 的前馈层使用带**共享 expert sink** 的 mixture-of-experts 架构。对每个 token，路由器选择少量 routed experts，同时给 shared experts 分配权重。与常规 shared-expert MoE 设计不同，Inkling 把 shared experts 与被选中的 routed experts 一起归一化，允许共享路径在每个 token 上动态争夺 mixture 权重。

Inkling 还支持图像与音频输入。轻量嵌入塔把图像 patch 与量化音频特征转换为与文本 token 同宽的嵌入。这些嵌入直接插入模型的输入序列，由同一个 decoder 栈处理。

## **统一的文本、图像与音频输入**

Inkling 接受三种输入模态：文本、图像、音频。三种模态都由同一个 decoder 栈处理，文本生成为输出。

轻量嵌入塔把图像 patch 与量化音频特征转换为与文本 token 嵌入同宽的嵌入。这些表示直接插入模型的输入序列，让语言模型能联合推理文本、视觉与音频信息。

这种统一设计使以下应用成为可能：视觉问答、文档分析、音频理解、多模态 agent，以及在同一个对话中结合多种输入类型的工作流。

## **开始在 Together Serverless 上用 Inkling 构建**

Inkling 今天通过 **Together AI Serverless** 可用。

开发者可以：

- 用统一模型构建文本、图像和音频应用
- 从初步实验扩展到专属生产容量

from together import Together

client = Together()

response = client.chat.completions.create(
    model="[INKLING MODEL ID]",
    messages=[
        {
            "role": "user",
            "content": "Analyze this problem carefully and provide the answer."
        }
    ],
    # 替换为最终支持的 API 参数。
    reasoning_effort="[SUPPORTED VALUE]",
)

print(response.choices[0].message.content)
