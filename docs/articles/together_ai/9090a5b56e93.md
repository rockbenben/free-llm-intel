TL;DR

LLM 遵循用户指令至关重要。已有研究评估的是模型主要响应中的指令遵循，而我们主张：大推理模型（LRM）在整个推理过程中遵循用户指令同样重要。

我们推出 [ReasonIF](https://huggingface.co/datasets/ykwon-hf/reasonIF)，一个系统性的基准，用于评估跨多语言推理、格式与长度控制的推理指令遵循能力。

我们发现包括 GPT-OSS-120B、Qwen3-235B、DeepSeek-R1 在内的前沿 LRM，超过 75% 的时间未能遵循推理指令。值得注意的是，随着任务难度上升，推理指令遵循进一步恶化。

更多信息见[我们的论文](https://www.arxiv.org/abs/2510.15211)和 [GitHub 仓库](https://github.com/ykwon0407/reasonIF)。

## **引言**

从探索研究想法，到构建大规模软件系统、做出知情决策——大推理模型（LRM）通过在特殊标签之间生成逐步推理 trace（如 *DeepSeek* 家族的 <think>...</think>，*GPT-OSS* 家族的 <|channel|>analysis<|message|>...<|end|>）迅速流行。它们的推理能力不仅提升可解释性，还支持迭代精化，使其在需要大量推理的任务上非常有效。在 Together AI，我们看到 LRM 在整个 AI 生命周期中的爆炸式兴趣——然而一个关键问题仍未解答：

> 这些高性能模型会在其推理 trace 中遵循用户指令吗？

在整个推理 trace 中——而不仅在最终响应中——遵循用户指令，能提升可控性、透明度与安全性。

- 过程级指令遵循让交互更可预测、更以用户为中心，让用户能引导模型**怎么想**，而不只是输出什么。
- 结构化的推理 trace（如 JSON 步骤、引用证据）让程序化审计逻辑与合规成为可能。
- 持续遵循推理指令有助于防止 reward hacking 和产生表面正确答案的捷径。
- 忠实、与指令对齐的推理对对抗操纵也更鲁棒，因为用户显式定义的规则约束着模型的内部步骤。

受这些点驱动，我们推出一项新基准，评估 LRM 在生成推理 trace 时对指令的遵循程度。***我们的关键发现***：模型通常在最终响应中遵从，但在推理步骤中失败率高得多——且这一缺口随任务难度加剧。

## **2. ReasonIF：新基准数据集**

为推动该领域，我们推出 **ReasonIF**——一个评估推理 trace 内指令遵循能力的新基准数据集。ReasonIF 包含 300 道数学与科学题，每题配一条具体的推理指令。每个输入 prompt 由两部分组成。

- 一条**问题**，采样自既有基准集合（GSM8K、AMC、AIME、GPQA-diamond、ARC-Challenge），确保覆盖广泛的推理风格。
- 一条**指令**，从六个用户导向的、模型必须在逐步求解全程遵守的指令集合中随机选取。

遵循此前工作 IFEval（Zhou et al., 2023）——它考察大语言模型的一般指令遵循能力——我们使用可验证指令，无需依赖另一个 LLM 即可自动评估。但与 IFEval 不同，我们的焦点是推理 trace 本身。六种指令类型针对真实用户需求设计——能精确、自动地验证模型是否遵循规定的推理引导。

- **多语言：** 将推理限制在特定语言（如印地语、阿拉伯语）。
- **词数上限：** 限制冗长度以节约成本、提升简洁。
- **免责声明：** 强制在末尾逐字追加一条安全提醒。
- **JSON 格式：** 确保结构化、机器可读的输出。
- **全大写：** 强制严格格式，考察细粒度句法控制。
- **去除逗号：** 与"全大写"类似。

## **3. LRM 在推理过程中经常未能遵循指令**

我们测试的所有最先进 LRM 在推理 trace 中都表现出糟糕的指令遵循（IF），即便是最好的模型在我们的分析中也只取得低于 25% 的遵循分数。相比主要响应中的 IF，指令遵循分数（IFS）在推理 trace 中暴跌（见*图 1*）。例如 Qwen-3-235B——最强的开源 LRM 之一——IFS 下降超过 50%，显示 LRM 在推理全程遵循指令的能力不足。注意我们从实验中排除了闭源模型，因为其 API 不提供推理 trace。其他实现细节见论文。

图 1。

推理 trace（蓝）与主要响应（红）中的指令遵循对比。全部六个最先进 LRM 都显著下滑，有些失去超过一半的 IFS。

进一步，指令专项分析（图 2）显示这一模式对所有指令类型都成立。值得注意的是，对全大写和 JSON 格式约束，没有任何模型能在推理 trace 中持续产出有效输出——成功率在 0% 附近徘徊，最好的模型也只有百分之几的遵循。这证实当前 LRM 在推理期间经常无法遵循显式格式指令。

图 2。

推理 trace 内（左）与主要响应中（右）的指令专项分析。失败在 JSON 格式和全大写这类格式敏感任务上尤为刺眼。

## **4. 推理指令遵循能力随任务难度下降**

我们的分析揭示了一个清晰且令人担忧的模式：**任务越难，模型在推理中遵循指令越不忠实。**

随着基准难度上升——从 GSM8K 相对简单的算术到 AIME、GPQA-diamond 的高等数学与科学问题——LRM 的推理 IFS 稳步下降。这一衰退在各模型家族间一致。如*图 3*所示，模型准确率与 IFS 的相关性最高可达 0.863（Qwen3-235B），即便是取值最小的模型（DeepSeek-R1）也有 0.387 的相关性。这一发现支持我们的主张，也呼应 Fu et al.（2025）关于主要响应的类似结论：越难，推理中越不遵循指令。

这一趋势有重要含义。在真实部署中——问题复杂、指令微妙——用户不能假设模型会在推理期间尊重其要求。这限制了 LRM 的关键性、可复现性，以及将其安全整合进关键工作流的能力。

图 3。

跨基准难度等级的模型准确率与推理 IFS。所有 LRM 呈现正斜率，表明更难的任务会对推理 IF 表现产生负面影响。

## **结论**

我们推出 **ReasonIF**——一个考察最先进开源 LRM 推理 IF 能力的新基准数据集。我们观察到 LRM 推理 trace 与主要响应的 IF 能力之间存在显著差距。进一步，我们发现推理 IF 能力与任务难度之间存在负相关（任务越难，IF 越低）。在[论文](https://www.arxiv.org/abs/2510.15211)中，我们进一步探索了两种提升推理指令忠实度的策略：(1) 多轮推理和 (2) 用合成数据做推理指令微调（RIF），其中 RIF 把 GPT-OSS-20B 的 IFS 从 0.11 提升到 0.27——显示可度量的进展，但改进空间仍然很大。更多信息见我们的论文和[代码库](https://github.com/ykwon0407/reasonIF)。
