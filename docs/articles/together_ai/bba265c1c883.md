- **Cartesia Sonic-3（TTS）与 Deepgram（STT）**现已原生托管在 Together 基础设施上，扩展了同栈的模型选择
- **一个 API、一个计费面、一个部署面**——企业部署支持零数据保留、SOC 2 Type II、HIPAA 和专属数据驻留

今天，Together AI——AI Native Cloud——推出了完整的能力套件，交付业界首个基于同云 STT、LLM、TTS 基础设施构建实时语音 agent 的统一方案。Together 把整个语音栈留在同一朵云上，降低延迟、简化部署、提升可靠性。我们还通过原生集成业界领先的语音模型——Cartesia（TTS）和 Deepgram（STT）——为构建者带来更多选择。

生产级语音系统通常迫使团队在速度、模型选择和运维稳定性之间做取舍。Together 的统一方案旨在消除这种取舍：面向实时对话的低延迟基础设施、语音栈各环节灵活的模型支持，以及一个安全、可用于生产的平台——让团队从评估走到部署，无需跨供应商推倒重来。

### **架构：统一模块化 vs. 多供应商堆栈**

你刚才拨打的 demo 之所以能保持实时，是因为它把那些交接都留在同一个 Together AI 集群内，并由贴近呼叫方的区域提供服务，保持往返延迟很低。每个组件——STT、LLM、TTS——都运行在预留了预热容量的 dedicated endpoint 上，从用户语音结束到第一个音频 token 的端到端延迟实测低于 500ms。

跨多家供应商搭建语音管线，通常意味着在公共互联网上把音频和文本在独立的 STT、LLM、TTS 系统之间来回传输。每一次交接都增加延迟、提高运维复杂度，让技术栈在生产中更难管理。Together AI 的统一模块化架构把 STT、LLM、TTS 放在同一个集群内、由贴近终端用户的区域提供服务，从设计上消除这部分开销。

这一架构的意义有三点：

- **速度：**语音 agent 通常在 STT、LLM、TTS 跨多家云供应商交接音频和文本时变慢。那些跨供应商的网络跳转在管线每个阶段都增加延迟，让实时对话难以维持。Together 把这些交接留在本地数据中心网络内而不是公共互联网上，实现低于 500 毫秒的端到端延迟，达到自然轮换所需的响应速度。
- **灵活性：**模型灵活性需要选择权。Together 在单一平台上托管领先的转录、推理与合成语音模型，让团队兼具配置各用例所需技术栈的速度与掌控力。而且与不透明的 speech-to-speech 系统不同，Together 的模块化设计保留了对中间转录文本和响应文本的访问，团队可以在流中途检视、修改和路由数据，作为自己应用逻辑的一部分。
- **可靠性：**生产要求可靠性。Together 的零信任架构为敏感语音数据而设计，而精简的端到端管理体验消除了把多家供应商方案拼在一起的复杂度。在单一平台上运行完整管线，团队就拥有 API、一个认证层、一个计费面和统一指标——降低运维开销、降低延迟、让成本在生产中更可预测。

面向企业部署，平台可支持严格的要求，包括零数据保留、SOC 2 Type II、HIPAA 和专属数据驻留选项。

### **一个平台上的模型选择**

团队经常为速度、富表现力合成或声音克隆拼凑不同供应商，把基础设施变成脆弱的多供应商补丁堆。Together AI 用一个统一的、模型无关的平台取代这一切。开发者可以精确配置所需的 STT、LLM、TTS 技术栈，并无需重建集成地更换模型。

通过一个平台，团队可以把音频和文本路由过 Whisper Large v3、Minimax Speech 2.6 Turbo、[Rime Arcana](https://rime.ai/resources/rime-together-ai-better-voice-agents)、Kokoro 以及完整的 Together LLM 目录等模型。完整的支持模型目录见我们的 [STT](https://docs.together.ai/docs/speech-to-text#available-models) 和 [TTS](https://docs.together.ai/docs/text-to-speech#available-models) 文档。

为扩展模型库，我们推出 [Deepgram](https://deepgram.com/learn/together-ai-deepgram-voice-partnership)（STT）和 [Cartesia（TTS）](https://cartesia.ai/customers/together-ai?utm_medium=social&utm_source=twitter&utm_campaign=together)的原生集成。把这些模型直接托管在 Together AI 上，意味着团队既能获得业界领先的转录与合成能力，又能让每一次交接安全地留在同云技术栈内。

**Cartesia** 把 [Sonic-3](https://www.together.ai/models/cartesia-sonic-3) 和 [Sonic-2](https://www.together.ai/models/cartesia-sonic-3) 带上平台，提供专为语音 agent 与生产部署打造的、富表现力、超低延迟的 TTS。

> "在 Cartesia，我们致力于突破实时、富表现力语音 AI 的极限。与 Together AI 合作，我们很高兴把这项技术带给更多构建下一代语音应用的开发者。—— Arjun Desai，Cartesia 联合创始人

**Deepgram** 把 [Nova-3](https://together.ai/models/nova-3)、[Nova-3 Multilingual](https://together.ai/models/nova-3-multi)（STT）、[Flux](https://together.ai/models/flux)（对话式 STT）和 [Aura-2](https://together.ai/models/aura-2)（TTS）带上平台，覆盖从实时转录到企业级语音合成的全部场景。

> "语音 agent 生死系于延迟，供应商之间的每一个网络跳转都是体验崩坏的地方。把 Deepgram 的 STT 原生托管在 Together AI 基础设施上，我们让开发者无需取舍就能获得生产级转录——快、准，且与管线其余部分同云部署。" —— Abe Pursell，Deepgram 合作生态副总裁

### **生产中的语音 agent：Decagon**

Decagon 已在这套技术栈上生产运行 [concierge 语音 agent](https://www.together.ai/customers/decagon)。他们的 agent 规模化地处理复杂的企业客服工作流——如解决账单查询、管理账户更新、执行技术排障。在这些环境中，转录准确性、低延迟和基础设施在线率对维持自然的客户体验至关重要。在 Together AI 上运行管线，提供了流畅对话所需的严格延迟边界，同时保留了 Decagon 对中间转录文本和响应文本的掌控。
