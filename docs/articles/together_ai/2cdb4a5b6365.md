## 摘要

分布感知推测解码（distribution-aware speculative decoding，DAS）是一个新框架，能显著缓解 RL 后训练中的 rollout 瓶颈——不碰模型输出，带来最高 **50% 的加速**。

## Rollout 瓶颈

强化学习已成为现代 LLM 后训练的基石。DeepSeek-R1 这类模型的推理能力正归功于 RL 微调。但随着模型变大，一个关键瓶颈浮现出来：rollout 阶段。

RL 训练中，模型必须为一个批次中每个 prompt 生成完整响应，下一个训练步才能开始。*最慢的*那条生成决定整个步时长——教科书式的长尾问题。

> 训练总时间的 70% 被 rollout 阶段吃掉——超过反向传播加参数更新的总成本。

- 同步屏障：所有 rollout 完成后训练才能推进。一条慢生成阻塞整个批次。
- 长度在增长：现代推理模型生成的思维链越来越长，放大长尾效应。
- GPU 空转：掉队者在跑的时候，其他 GPU 无事可做——每次训练浪费数千美元的算力。

长尾问题的实际形态：大多数序列早早完成，但少数掉队者迫使整批等待——GPU 一直闲置到最慢的生成完成。

## 关键洞察

RL 后训练的 rollout 阶段有三个结构特性，把它与标准 LLM 服务工作负载区分开。这些特性构成了 DAS 核心设计选择的动机。

- **长尾 rollout 导致 GPU 利用不足：** RL rollout 服从长尾分布：多数生成很快结束，少数产生极长的轨迹。由于训练步必须等所有 rollout 完成，这些长序列成为决定步延迟的掉队者。短请求提前完成后 GPU 空转，造成严重的硬件利用不足。
- **历史轨迹信号：** 与服务（每个请求都独特）不同，RL 训练跨 epoch 反复访问相同 prompt——形成可供利用的丰富历史生成记录。
- **演化中的模型权重：** 模型在每个优化器步后都在变化。在早期 checkpoint 上训练出来的静态 drafter 会迅速与当前策略错位。

## DAS 框架

每个特性都指向一个设计要求：

- 一个无需重训练就能保持同步的 drafter
- 一个能中和掉队者的调度器
- 一个能利用 RL 特有 prompt 复用现象的系统

DAS 通过两个紧密集成的组件同时解决三者。第一是自适应后缀树 drafter，加速生成并在长训练周期中优雅扩展。第二是长度感知调度策略，通过 GPU 间负载均衡和 GPU 内推测预算分配来减少 rollout 掉队者。

### 自适应后缀树 drafter

**为什么用后缀树？**

随着策略在 RL 训练中不断演化，静态 drafter 会迅速过期。DAS 因此使用一个由近期 rollout 构建的**免训练 drafter**，可以随时适应策略变化，无需任何梯度更新。

**如何工作**

DAS 从一个近期轨迹滑动窗口构建后缀树。解码期间，它在当前上下文与已索引历史之间找**前缀匹配**。候选下一 token **按其在匹配子树中的出现频率打分**，得分最高的 token 被选为推测草稿。

**为什么契合 RL rollout**

草稿序列由目标模型并行验证，新验证的 token 立即插回树中，让 drafter 与最新策略**始终保持同步**。由于 RL rollout 往往有很强的轨迹复用，这种非参数化设计无需独立的神经 drafter，就能有效利用重复前缀。

**可扩展性**

后缀树在 rollout 前构建、每个训练步后释放，因此内存不会随长训练周期累积。树的构建与清理按问题并行，并与 actor 更新重叠，使 actor 更新延迟**波动小于 5%**，把开销挡在关键路径之外。

### 长度感知调度

**GPU 间均衡**

DAS 把长请求**交错分布到各 rank 上**。这防止长生成集中在单个 worker 上，减少 rollout 掉队者。

**长请求提早推测**

DAS 从 rollout 开始就对长请求应用推测解码。Rollout 延迟由少数撑到晚期的长掉队者主导，而那时解码变成小批量、强内存受限。对这些请求提早投入额外算力是划算的——避免昂贵的晚期模型前向，缩短 rollout 尾部。

**GPU 内预算分配**

在每块 GPU 内部，请求基于历史 rollout 统计被动态划分为**Long、Medium、Short** 三类。长请求获得激进的推测解码预算，中等请求用适中预算，短请求**完全跳过推测**——在推测无法减少模型前向的地方避免浪费算力。这个分类策略在运行时动态更新。

这套设计简单到几段话就能讲清。真正证明它的是结果。

## 实验结果

DAS 在两个 RL 后训练任务上评估——数学推理和代码生成。两种情况下，真正重要的指标都是：rollout 时间减少且奖励质量零退化。

### 数学 RL — DeepSeek-R1-Distill-Qwen-7B

DSR-sub 数据集（1,209 个样本）。DAS 实现超过 50% 的 rollout 时间减少，同时与基线奖励曲线完全重合。

在 DSR-sub（1,209 个样本）上 rollout 时间减少超过 50%，与基线奖励曲线无偏差——训练信号被完整保留。

### 代码 RL — Qwen3-8B

单元测试奖励信号。DAS 实现约 25% 的 rollout 时间减少并保持奖励质量。

在单元测试奖励信号上 rollout 时间减少约 25%。奖励质量全程跟随基线，证实 DAS 不干扰策略学习。

DAS 在序列长度（8k–16k）和批大小（16–32）范围内保持加速优势，说明收益不依赖单一工作点。

## 为什么这很重要

DAS 同时交付三个难得一见的特性：

- **无损加速：** DAS 保持分布——输出与标准解码完全一致，训练曲线完全一致。
- **跨配置鲁棒：** 加速在序列长度（8k–16k）和批大小（16–32）范围内成立。
- **零成本适应：** 后缀树 drafter 从 rollout 历史自我演化。无梯度更新，无维护。

随着 AI 社区推动越来越大的模型用 RL 在越来越复杂的任务上训练，rollout 瓶颈只会更严峻。对大规模运行 RL 后训练的实践者，DAS 提供了一条有说服力的路径：最多削减 50% 的算力成本、模型质量零退化——在资源受限的大规模 AI 训练世界里，这是罕见的双赢。
