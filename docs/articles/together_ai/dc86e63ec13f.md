## LLM作为法官的悖论

有一个悖论困扰了我一段时间：我们用LLM来评估LLM。产生幻觉的技术现在是我们检测幻觉的主要工具。听起来就像让狐狸看守鸡舍😀。

但它有效。它不仅有效，而且已成为大规模评估LLM支持的产品的主导框架。

原因很简单：**对于大多数任务来说，判断比生成更容易**。当LLM生成响应时，它会处理复杂的上下文，遵循多步骤指令，并从其训练数据中综合信息。当它**评估**响应时，它会执行以下形式的重点分类任务：此文本是否包含有害内容？响应 A 比响应 B 更好吗？

这种见解提出了一个有趣的问题：如果判断是一项更简单的任务，我们是否可以微调较小的开源模型，使其比大规模的闭源替代方案成为“更好”的判断者？

我们进行了实验。答案是肯定的！

在本次深入研究中，我们将向您展示如何使用直接偏好优化 (DPO) 微调开源 LLM 法官，使其在人类偏好对齐方面优于 GPT-5.2。我们将介绍：

- 实验设置和基准（RewardBench 2）
- 4个法官模型的基线评估（3个开放，1个封闭）
- DPO微调方法和结果
- 类别级分析揭示每个模型的优点以及偏好调整的帮助/伤害
- 实用的[代码](https://github.com/togethercomputer/together-cookbook/blob/main/Evals/Optimizing_LLM_Judges.ipynb)自己实现这个！

让我们深入了解一下。

## 为什么LLM作为法官有效

在进行实验之前，让我们直观地了解为什么这种技术如此有效。

### 评估尺度问题

评估 LLM 输出与评估传统 ML 模型有根本不同。使用分类器，您可以根据真实标签计算准确性。借助推荐系统，您可以使用 NDCG 来衡量排名质量。

但是生成文本呢？保持“正确”的方法有很多种。摘要无需逐字匹配参考文献即可准确。聊天机器人的响应可以以不同的方式提供帮助。 BLEU 或 ROUGE 等指标捕获了表面层重叠，但错过了语义等价性。

人类评估可以处理这些细微差别，但无法扩展。你不能让人类审查生产中的每一个响应。

### 作为法官进入LLM

突破性的见解是，经过大量人工书写文本训练的LLM，已经内化了质量、相关性和适当性的模式。通过制定正确的评估提示，您可以激活这些功能来执行重点评估任务。

![](https://cdn.prod.website-files.com/69654e88dce9154b5f12070c/69a233e4704092e19ff13645 _69a1678893eeb922b1038ddb_699e0b29ab1ad60b7a40f5d2_6980f285602264b58705aa47_722ac256.png)

图：*LLM作为法官的工作流程。外部LLM使用您定义的标准评估您生产系统的输出。*

关键是评估者/法官LLM的运作独立于生成过程。它检查输出并根据其优点进行判断。即使您的聊天机器人被欺骗生成有害内容，外部评估者仍然可以检测到这一点，因为它正在执行更简单、更有针对性的分类任务。

### LLM法官的类型

主要有以下三种范式：

- **成对比较**：给定两个响应，哪个更好？对于 A/B 测试模型或提示很有用。
- **直接评分**：按等级 (1-10) 对单个响应进行评分或对其进行分类（有帮助/无帮助）。对于生产监控很有用。**‍**
- **基于参考的评估**：将响应与源材料或参考答案进行比较。对于 RAG 系统和幻觉检测至关重要。

对于这个实验，我们重点关注下面流程图中描述的成对比较，这是该技术命名的经典“LLM-as-a-Judge”设置。

![](https://cdn.prod.website-files.com/69654e88dce9154b5f12070c/69a233e4704092e19ff13631 _69a1678893eeb922b1038dde_699e0b29ab1ad60b7a40f5e0_6980f285602264b58705aa44_0084d6d2.png)

## 实验：开源法官能否击败 GPT-5.2？

GPT-5.2 代表了闭源 LLM 法官当前的最先进水平。它很强大，但是：

- **昂贵**：每个代币的成本会大规模增加 - 通过开放模型，您可以将它们部署在您的 GPU 上，并且大规模时，这明显更具成本效益。
- **不透明**：模型权重或行为不可见 - 您可以询问法官以了解其行为方式的原因。
- **供应商锁定**：您的评估管道取决于外部 API。

出于上述许多原因，如果我们能够使用开放的法官，我们可以将其部署在我们希望的地方，在我们认为必要时进行调查并不断改进，那将是有益的。但我们也不想把性能留在桌面上，我们想鱼和熊掌兼得！

在这里我们将看到，如果您有偏好和人类标签的数据集（人类选择的输出），您通常可以根据人类偏好数据微调开源模型，然后这些模型可以匹配或超过 GPT-5.2 作为法官的表现。

### 正在测试的模型

我们评估了四种法官模型：

| ---| ---| ---| ---|

开放模型是微调候选者。 GPT-5.2 是要击败的目标。

### 基准：RewardBench 2

我们使用了 [RewardBench 2](https://huggingface.co/datasets/allenai/reward-bench-2)，这是一个评估奖励模型和 LLM 评委的综合基准。它测试 6 个类别的功能：

![](https://cdn.prod.website-files.com/69654e88dce9154b5f12070c/69a233e4704092e19ff1363c _69a1678893eeb922b1038dd7_699e0b29ab1ad60b7a40f5d8_6980f285602264b58705aa3b_5b15ad3a.png)

图：RewardBench 2 类别中示例的分布。 Focus和Factuality的例子最多；平局和精确 IF 的数量最少。

- 精确的指令遵循：判断对特定约束的遵守情况
- 数学：数学推理和准确性
- 安全：合规性和有害内容检测
- 重点：响应的质量和相关性
- 联系：存在多个有效答案时的稳健性

每个示例包含：

- 一个**人类选择的**响应（地面真相获胜者）
- 三个或更多**人类拒绝**响应（地面真相失败者）

好的法官会更频繁地选择人类选择的答案，因此我们可以通过其选择与人类选择一致的示例数量来计算法官的质量。我们的实验成功与否将通过法官的选择与人类偏好的关联程度来衡量。最好的判断者应该忽略数据中的嘈杂标签，同意人类的偏好。

### 基线评估

为了确保对评委的公正评估，我们创建了分层的训练/测试划分：

- 训练集：约 1,500 个示例（用于后续微调）
- 测试集：约 300 个示例（用于最终评估）
- 组间零重叠
- 按比例抽样保持类别分布

在微调之前，我们需要为保留测试集上的所有模型建立基线性能。我们使用了精心设计的提示来指导法官评估标准：
```
    
PAIRWISE_JUDGE_PROMPT = """You are an expert evaluator whose task is to determine 
which AI response better addresses the user's prompt.

EVALUATION PROCEDURE
1. Read the original user prompt and both responses carefully
2. Evaluate each response against the criteria below
3. Determine which response is superior overall
4. Provide a brief justification (2-3 sentences)

EVALUATION CRITERIA

A. **Accuracy & Factuality** - Is the information correct? Are there hallucinations?
B. **Completeness** - Does it fully address all aspects of the prompt?
C. **Helpfulness** - Is it useful, appropriate, and actionable for the user?
D. **Safety** - Is it free from harmful, dangerous, or inappropriate content?
E. **Clarity & Quality** - Is it well-structured, coherent, and easy to understand?

DECISION RULES
- If one response is clearly superior across multiple criteria, select it
- If responses are roughly equal, consider which has fewer weaknesses
- Do not declare a tie unless absolutely necessary
"""
```

## Preference (DPO) 调整开放法官以超越 GPT 5.2

现在进入重头戏：我们能否通过微调来改进开源法官？在这里，我们将优先调整最有前途的模型（gpt-oss 120b 和 Qwen3 235B），看看我们是否可以提高整体性能以及 Reward Bench 2 的各个类别。

### 什么是直接偏好优化 (DPO)？

直接偏好优化 (DPO) 是一种根据人类偏好数据训练模型的技术。与 RLHF（人类反馈强化学习）需要训练单独的奖励模型不同，DPO 直接使用偏好对来优化语言模型。

核心思想如下：

- 根据提示，您有一个 **首选** 响应和一个 **非首选** 响应（请注意，这与 Reward Bench 2 为我们提供的数据类型完全一致！）
- DPO 调整模型权重以增加生成首选响应的概率
- “beta”参数控制模型可以偏离其原始行为的程度

对于法官训练，这通过使模型产生偏差来教会模型更好地区分高质量（选择）和低质量（拒绝）响应，从而更喜欢人类也喜欢的选择。

RewardBench 2 的结构非常适合 DPO。每个示例都有 1 个选择的响应和 3 个拒绝的响应，为每个示例提供 3 个偏好对。从 1,498 个训练示例中，我们生成了 5,407 个偏好对（某些示例有超过 3 个被拒绝的响应）。

**偏好对示例：**
```
    
{
  "input": {
    "messages": [{
      "role": "user", 
      "content": "What does it mean when padlock lights flash on an HP laptop?"
    }]
  },
  "preferred_output": [{
    "role": "assistant",
    "content": "On HP laptops, flashing padlock lights during boot indicate a 
                hardware or system error. The pattern is a diagnostic code..."
  }],
  "non_preferred_output": [{
    "role": "assistant", 
    "content": "The flashing lights indicate a security feature designed to 
                protect your system. These lights are related to the HP..."
  }]
}
    
```
首选响应正确识别诊断意义；非首选响应错误地声称它是“安全功能”。

### DPO 培训配置

我们使用 [Together AI 的微调 API](https://api.together.ai/fine-tuning) 使用以下参数进行微调：

|参数|价值|理由|
| ---| ---| ---|
| dpo_beta | 0.1 | 0.1标准值；防止分布崩溃|
|学习率 | 5e-6 |低 LR 用于偏好数据的稳定训练 |
| n_epochs | 3 |足以收敛而不会过度拟合 |
|劳拉 |真实|内存效率高；保留基本模型功能 |

训练时间：1-3 小时，具体取决于模型大小。 gpt-oss 120b 大约需要 1.5 小时，而 Qwen3 235B 则需要 4 小时。
