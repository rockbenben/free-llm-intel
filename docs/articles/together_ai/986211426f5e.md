# 推出 Together Storage Accelerator：为您的 GPU 集群提供快速、免费的数据缓存

每个 GPU 节点上都有一层分布式缓存：热读取快约 20 倍，每个集群只回源一次，应用侧无需任何改动。随 Together GPU Clusters 免费提供。

GPU 有多快，取决于你的数据管道有多快。每一次训练都要先花 30 分钟下载模型，每个节点都从千里之外重新拉取同一份数据集，每一次 Hugging Face 限流都把作业卡住——这些都会让算力空转等着数据，而账单照付。

今天我们推出 **Together Storage Accelerator（TSA）**，这是面向 Together GPU Clusters 的分布式缓存层，免去从对象存储和 Hugging Face Hub 反复读数据的开销，在显著加速 AI 数据管道的同时压低数据传出费用。现在每个 Together GPU Cluster 都**免费**附带 TSA。

## 问题所在：数据离 GPU 太远

多数 AI 团队把数据的权威副本放在对象存储里（Amazon S3、Cloudflare R2、Together AI 的 T4*），或者直接从 Hugging Face Hub 拉模型。这意味着每次冷启动都要交一笔「WAN 税」：跨云、跨区域读取又慢又贵（从 AWS 传出的费用最高达 0.09 美元/GB），还会被限流。当成百个节点同时拉取同一份 checkpoint 时，浪费成倍叠加，既耗时间、耗钱，源站一限流还会让作业失败。

**T4 是 Together AI 的自建数据中心 S3 兼容对象存储方案，目前处于 Limited Preview。如有兴趣试用，请联系销售或你的客户团队。*

## TSA 缓存数据，同时改善性能、可靠性与成本

TSA 为 GPU 集群提供分布式缓存层。它运行在集群里的每个 GPU 节点上，为你正在使用的存储提供可直接替换的 endpoint。任何一个节点首次读取某个对象时，TSA 会把它缓存到集群的 NVMe 上。此后无论哪个节点再次读取，都由集群内部以高得多的本地速度提供。

在 Together GPU Cluster 的一个 H100 节点上测得的结果：

- **热读取约快 20 倍**（相比从跨云源站拉取），单节点最高 **3.4 GB/s**。一个从 Cloudflare R2 下载需要 13-15 秒的 2 GiB 对象，从缓存读取只需 0.6 - 0.7 秒
- **冷读取不产生额外成本**：首次经 TSA 读取的耗时与直接下载相差在 ~5% 以内
- **每个集群只回源一次。** 一个 70 GB 的 checkpoint 被 200 个节点拉取时，从源站只下载一次，而不是 200 次
- **不惧故障与限流。** 即使上游不可用，已缓存的数据仍可继续提供服务。

使用 TSA **无需对应用做任何改动**：不用接新的 SDK，不用重写 data loader，一条命令即可开始。

**快速开始：**

```
# S3-compatible storage (S3, R2, T4, ...)
export AWS_ENDPOINT_URL=http://tsa.tsa.svc.cluster.local:18080

# Hugging Face Hub
export HF_ENDPOINT=http://tsa.tsa.svc.cluster.local:18080
```

现有的 boto3 代码、transformers 调用和 CLI 工作流照常可用。TSA 使用你配置的凭证完成鉴权，凭证经过加密，安全存放在 secrets vault 中。

## 实测结果

![](https://cdn.prod.website-files.com/69654e88dce9154b5f12070c/6afe92cf7001ead389e131e7_tsa-results-chart-brand.png)

于 2026-10-28 在 Together GPU Cluster（us-central）的一个 H100 节点上，从该节点上的一个 pod 内测得。除特别说明外均为单流读取；客户端写入 /dev/null 或节点 NVMe。

- **从跨云 bucket（Cloudflare R2）读取 2 GiB 对象：** 不用 TSA 时 143–169 MB/s（12.7–15.0 秒），TSA 缓存命中时 3.0–3.4 GB/s（0.64–0.72 秒）。**约 20 倍**
- **从同一 bucket 读取小文件（5 KB、2.4 MB）：** 不用 TSA 时分别为 320 ms 和 680 ms，TSA 缓存命中时为 5 ms 和 8 ms，延迟低 **约 60–80 倍**
- **200 节点集群拉取同一 checkpoint：** 不用 TSA 时回源 200 次，用 TSA 时 1 次，传出流量减少 **200 倍**

*在 Together GPU Clusters 的 preview 部署上测得（TSA chart 0.6.0）；实际结果取决于源站、对象大小和网络路径。源站速度存在区域差异：同一个 Hugging Face 下载在 us-central 比在 ca-west 快 5 倍，因此源站越慢，TSA 的收益越大。测试方法：在 GPU 节点上的 pod 内用单流 curl 和 aws s3 cp 读取，重复读取同一对象，并用 MD5 与直接下载结果比对。*

## 由 ASTRA 驱动

TSA 基于 [**ASTRA**](https://docs.together.ai/docs/astra)（Accelerated Storage Transport & Retrieval Architecture），这是我们为支撑全球最大的若干 GPU 集群（包括我们自己的推理集群）而构建的分布式缓存技术。我们会在后续一篇工程博客中深入介绍 ASTRA 的技术细节。

## 搭配 T4 效果更好

TSA 可与任何 S3 兼容存储配合使用，与 Together AI 的托管对象存储方案 **T4** 更是天然一对。今天就可以把 TSA 指向现有的 S3 或 R2 bucket，无需迁移数据。当你希望热数据长期驻留在 GPU 旁边时，改一处配置即可切到 T4。T4 目前处于 **limited preview**：请联系销售或你的客户团队申请使用。
