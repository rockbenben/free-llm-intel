## 最新动态

- **Tool call 微调：** 通过 OpenAI 兼容 schema 的端到端微调与推理，确保 agent 可靠地执行结构化动作。
- **Reasoning 微调：** 专门支持在推理 trace 的"thinking" token 上训练模型，让模型学习复杂逻辑。
- **视觉-语言模型微调：** 原生的视觉训练支持，让视觉-语言模型对齐复杂的领域专属视觉数据。**‍**
- **大模型支持：** 在我们高度优化、易于使用的服务上训练最大 1T 参数的最新模型。

随着 AI 团队从单轮 prompt 走向先进的多轮工作流，可靠性会在可预测的地方崩坏：与 schema 不匹配的工具调用、长交互中退化的推理、漏掉领域专属视觉信号的模型。修复这些问题通常需要训练后处理，但工作流往往碎片化、迭代慢、难以规划。

今天，Together AI——AI Native Cloud——扩展 Together Fine-Tuning，原生支持工具调用、推理和视觉-语言模型（VLM）微调。为支撑前沿规模的训练后处理，我们还升级了训练栈以更高效地处理 100B+ 参数的模型，吞吐最高提升 6 倍。此外，我们现已支持最大 100GB 数据集的微调。最后，我们现在提供训练前的任务成本估算和训练中的 ETA，让团队能更好地规划实验。

> "Together AI 之于微调和推理，就像 Vercel 之于 LLM 应用——移除基础设施层，让我们专注产品。我们通过简单的 API 调用微调和部署客户专属模型。这让我们现有团队从周迭代走向日迭代，成本削减 2–3 倍，准确率从 77% 提升到 87%。" —— Lamara De Brouwer，XY.AI Labs 联合创始人兼 CTO

## Tool Call 微调

Tool calling 对许多现代 agentic 用例至关重要。然而开箱即用的模型常常在工具调用上挣扎：参数幻觉、选错函数、或无法跟随多步序列。在工具调用工作流里，哪怕微小的不一致也会级联成下游故障。

我们的微调服务现在提供端到端的解决方案，覆盖从微调到推理的可靠、生产级工具调用。训练数据可以用 OpenAI 兼容 schema 包含工具调用：函数定义在顶层 tools 数组中，我们的服务会校验每个 tool_calls 条目与已声明的工具匹配，在训练开始前确保结构正确的数据。

在推理时，我们大幅提升了工具调用的可靠性，确保 tool call 微调的收益转化为生产表现。增强的解析与校验在广泛的真实用例中提升正确性，并由社区贡献与内部研究共同 curated 的推理工具调用数据集支撑。

Tool-call 微调已对 Qwen、Moonshot AI 和 Z.AI 的模型开放。参见[工具调用文档](https://docs.together.ai/docs/fine-tuning-function-calling)开始使用。想看代码中的工具调用示例，请看我们的 [cookbook](https://github.com/togethercomputer/together-cookbook/blob/main/Finetuning/Function_Calling_Finetuning.ipynb)。

## Reasoning 微调

推理模型在给出最终答案前生成中间思维 trace，实现逐步推理。然而推理格式在各模型间并不标准，给推理微调流程引入了复杂性。

Together Fine-tuning 现已支持直接在思维 trace 上微调，通过在 assistant 消息中使用 reasoning 或 reasoning_content 字段。这让你在领域专属的推理模式上训练模型，同时保持 trace 结构化和可复现。与工具调用一样，我们改进了推理侧的服务表现，确保微调出的能力转化为可靠的下游表现。

Reasoning 微调已对 Qwen 和 Z.AI 的模型开放。支持的模型和细节见[文档页](https://docs.together.ai/docs/fine-tuning-reasoning)。想看推理微调的端到端代码演示，[请看我们的 cookbook](https://github.com/togethercomputer/together-cookbook/blob/main/Finetuning/Reasoning_Finetuning.ipynb)。

## 视觉-语言模型微调

许多 AI 工作流需要能解读图像输入的模型。对医学影像、电商等领域专属任务，视觉-语言模型（VLM）可能需要学习新的视觉模式才能胜任。

Together Fine-tuning 服务现已支持视觉-语言模型微调。视觉训练数据通过消息 content 数组内联提供，图像用 base64 编码。微调任务支持混合数据集，允许在同一次运行中同时包含图文样本和纯文本样本。

默认情况下，我们冻结视觉编码器、只更新语言层。设置 train_vision=true 可启用联合训练，同时更新视觉编码器和语言层。

VLM 微调已对 Qwen、Google 和 Meta 的模型开放。支持列表与用法详见[视觉-语言文档](https://docs.together.ai/docs/fine-tuning-vlm)。也可以看我们[视觉语言微调的 cookbook](https://github.com/togethercomputer/together-cookbook/blob/main/Finetuning/Vision_Language_Finetuning.ipynb)。

## 大模型微调

随着开放模型规模增长、上下文窗口扩大，底层训练设施必须跟上。万亿参数的模型装不进单个节点，需要跨多机精细的通信与内存管理。即便数小时训练运行中的一次硬件故障也会导致进度丢失，而实现全部优化和容错保护是一项巨大投入。

Together Fine-Tuning 现已支持最新开放权重模型的微调。提交一个训练任务，所有必要优化由我们在底层处理。新开放微调的模型包括：

- Qwen 3.5-397B-A17B
- Qwen 3.5-122B-A10B
- Qwen 3.5-35B-A3B
- Qwen 3.5-35B-A3B-Base
- Kimi K2.5
- Kimi K2（Instruct、Thinking）
- GLM-4.7
- GLM-4.6

支持的模型完整列表及其上下文长度见[我们的文档](https://docs.together.ai/docs/fine-tuning-models)。

## 训练加速

本次更新中，我们继续聚焦训练栈中收益最高的优化机会。具体地，我们瞄准 mixture-of-experts 架构——过去一年内最强的模型发布绝大多数都是 MoE。为加速其训练，我们集成了 [SonicMoE](https://github.com/Dao-AILab/sonic-moe) 的一个变体——I/O 与 tile 感知的优化 kernel，把内存操作与计算重叠。在我们的训练负载中使用这些 kernel，显著降低了训练期间的激活内存占用，最大限度减少算力浪费。

我们还为损失计算编写了定制 CUDA kernel，并消除了训练循环中若干导致无谓停顿的 GPU-CPU 同步点，显著提升整体流水线效率。

结果是，每个模型的吞吐至少提升 2 倍，像 Kimi-K2 这样更大的模型提升超过 6 倍。更快的训练意味着每天更多实验、更短的生产之路。
