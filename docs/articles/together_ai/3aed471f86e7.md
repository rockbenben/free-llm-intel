FlashAttention-4 发布：[[Paper](https://arxiv.org/abs/2603.05451)] [[Code](https://github.com/Dao-AILab/flash-attention)]

像 Blackwell GPU 这样的现代加速器延续了**非对称硬件扩展**的趋势：tensor core 吞吐的增长远快于其他资源——共享内存带宽、用于指数等超越函数的特殊功能单元（SFU）、通用整数与浮点 ALU。例如从 Hopper 的 [H100](https://www.together.ai/gpu/nvidia-h100) 到 Blackwell 的 [B200](https://www.together.ai/gpu/nvidia-hgx-b200)，BF16 tensor core 吞吐从 1 PFLOPs 增至 2.25 PFLOPs，而 SFU 数量和共享内存带宽保持不变。

这种扩展的非对称性对为 Blackwell 架构优化 attention 这类复杂 kernel 有深远影响。本质上，attention 由两个 GEMM（$S=Q \cdot K^T$ 和 $O=P \cdot V$）加中间的 softmax 组成；实践中它还有大量管线与簿记工作：数据移动、同步、布局变换、逐元素操作、调度、掩码等等。

对 attention 的天真看法可能是：GEMM 的速度完全决定 kernel 性能，其他成分至少在一阶近似下可以忽略。然而对 B200 做一次"feeds and speeds"分析恰恰得到相反的结论：主要性能瓶颈不在 tensor core 做 MMA 有多快，而在 (a) FWD 计算中 softmax 指数所用的 SFU 单元，(b) BWD 计算中的共享内存流量。

在这篇博客中，我们呈现 **FlashAttention-4**——一种算法与 kernel 的协同设计，最大化矩阵乘与这些其他资源瓶颈之间的重叠。在 B200 的 BF16 上，它最高达到 *1605 TFLOPs/s*（71% 利用率），比 cuDNN *9.13* 版最高快 *1.3×*，比 Triton 快 *2.7×*。

我们主要的算法与 kernel 协同设计思想如下：

- **面向最大重叠的新流水线**：全新的前向与后向软件流水线，利用 Blackwell 完全异步的 MMA 和更大的 tile 尺寸，让 tensor core、softmax 指数与内存操作相互重叠。
- **前向（FWD）pass**：用软件在 FMA 单元上以多项式近似实现指数函数，缓解指数瓶颈；外加条件化 online softmax 重标定。**‍**
- **后向（BWD）pass**：把中间结果存入 tensor memory 以缓解共享内存流量；结合 Blackwell 新的 2-CTA MMA 模式进一步减少共享内存流量并把原子归约减半；并额外支持确定性执行模式以实现可复现训练。**‍**
- **调度**：新的 tile 调度器，缓解因果掩码和变长序列带来的负载不均。

## Blackwell 上的新硬件特性

- **Tensor memory（TMEM）：** 在 B200 上，148 个 SM 各有 256 KB 的 TMEM——一块接入 tensor core、用于 warp 同步中间存储的片上暂存器。
- **完全异步的第 5 代 tensor core：** `tcgen05.mma` 是异步的，在 TMEM 中累加。对 BF16 和 FP16，单 CTA UMMA 的最大 tile 是 128×256×16，约为 Hopper 最大 WGMMA atom 的 2 倍。UMMA 由单线程启动，降低寄存器压力，使更大的 tile 和更深的流水线变得可行，避免了 Hopper warpgroup MMA 的寄存器溢出痛点。这也让 warp 专业化更可行：一些 warp 搬运 tile，另一些发起 MMA，把矩阵乘累加与 softmax 和内存流量重叠。`tcgen05.mma` 还能从 TMEM 取操作数 A。
- **2-CTA MMA：** Blackwell 可以在同一 cluster 的 CTA 对上执行一个跨两个 CTA 的 UMMA，覆盖两个 peer CTA 的 TMEM。由 leader CTA 中的一个线程启动 MMA，但飞行期间两个 CTA 都必须保持活跃。通过在配对间切分 M 和 N，MMA tile 维度可放大至 256×256×16，减少冗余流量并降低每 CTA 占用。CTA group 大小（1 或 2）在一个 kernel 内的 TMEM 与 tensor core 操作之间必须保持恒定。

## Feeds and Speeds

对 M=N=D=128

B200 上的 **Feeds**（每 SM）：

- Tensor Core（BF16）：$\frac{8192 \text{ ops}}{cycle}$
- 指数单元：$\frac{16 \text{ ops}}{cycle}$
- 共享内存流量：$\frac{128 \text{ bytes}}{cycle}$

**Speeds**（每 tile 的时钟周期数）：

- 前向（2 个 MMA + MN 次 exp）：Tensor Cores: $1024$；Exp: $1024$；SMEM: $768$
- 后向（5 个 MMA + MN 次 exp）1-CTA：Tensor Cores: $2560$；Exp: $1024$；SMEM: $3328$

**结论：** 前向受计算和指数瓶颈限制，后向受共享内存带宽限制。所以我们在前向把 softmax 与 MMA 重叠，在后向减少共享内存流量。

## **前向 pass：带条件重标定的新 softmax 流水线**

前向 pass 有两个矩阵乘 `QK^T` 和 `PV`。在 Blackwell 上 tensor core 快了很多，但指数单元（MUFU.EX2）没有。因此 softmax 不再是"夹在两个矩阵乘之间的那点事"，而是一个必须精心流水线的瓶颈。

**FWD pass 简言之：**

- **Ping-pong 调度，每 CTA 2x Q 与 2x O tile：** 最大化 MMA 与 Softmax 的重叠
- **2 个 softmax warpgroup：** 每 tile 一个 softmax，彼此同步以免同时计算指数；**$2^x$ 的软件模拟：** 把指数计算分摊到硬件 MUFU 与 FMA 上的软件模拟；**分阶段把 P 存入 TMEM：** 缓解寄存器压力
- **Correction warpgroup：** 指定的"校正"warpgroup 执行重标定，把它移出关键路径；**Online softmax（条件）重标定：** 更低频地重标定，最小化非矩阵乘操作

### 流水线：Ping-pong Q tile 加专用校正阶段

FlashAttention-4 每 CTA 计算**两个** query tile——$Q^H$ 和 $Q^L$——各覆盖 128 个 query token，以 ping-pong 调度交替。

Blackwell 改变了 softmax 的映射方式。`S = QK^T` 的累加器 tile 是 128×128、位于 tensor memory；但读入寄存器时，按硬件规定该 tile 的划分是**每行一个线程**。我们使用两个 128 线程的 warpgroup，每个 Q tile 一组，每个 **softmax warpgroup** 执行如下序列：

- 每线程从 tensor memory 把 `S` 的一行 128 个元素加载到寄存器
- 归约出 `rowmax` 和 `rowsum`
- 用一个可调参数决定 128 个元素中哪部分用硬件 MUFU、哪部分用软件模拟的 $e^x$
- 计算 `P = softmax(S)` 并转换为 `BF16` 精度
- 分阶段把 `P` 存回 tensor memory 以缓解寄存器压力（而不是同时持有 *128* 个 S 元素和 *64* 个 BF16 的 P 元素）
- `P` 存到第 $\frac{3}{4}$ 块时就立即触发对应的 `PV` 矩阵乘

关键细节是 exp 是瓶颈段。我们显式同步两个 softmax warpgroup，让它们不同时求值 exp，从而减少 MUFU 争用。

为了让重标定不占关键路径，kernel 把它分配给一个专用 warpgroup。**Correction warpgroup** 计算：

- 仅在最大值跳变很大时重标定：
- $O_j =\begin{cases}\exp(m_{j-1}-m_j)\,O_{j-1} + \exp(S_j-m_j)\,V_j, & \text{if } m_j - m_{j-1} > \tau,\\O_{j-1} + \exp(S_j-m_{j-1})\,V_j, & \text{otherwise.}\end{cases}$
- 在迭代末尾施加最终归一化 $O_{final} = \frac{O}{l_{final}}$
- 可选地计算并存储 LSE

结束时我们仍用真实最终统计量做归一化，因此跳过小的重标定步骤在保住最终输出的同时，从关键路径上删去了大量向量计算。我们在 warp 粒度做该决定以避免分支发散。

### 更快的指数：把 $2^x$ 分摊到 MUFU.EX2 与 FMA（软件模拟）

Softmax 需要大量指数运算，而 MUFU 吞吐远低于 tensor core 吞吐。FlashAttention-4 让 `exp2` 的软件模拟与硬件 `MUFU.EX2` 路径并行运行，利用本来未被充分利用的 FMA 单元，提高有效指数吞吐。

**范围归约（Cody-Waite）：** 我们用经典的 Cody-Waite 范围归约技术把指数计算分解为整数部分和小数部分：$2^x = 2^{n} \cdot 2^{f}$。在 IEEE 754 float32 中，按 $2^{n}$ 缩放只是更新指数域。

**$2^{x_{frac}}$ 的多项式近似（Horner 方法）：** 为近似 $2^{f}$，我们把它重写为便于高效求值的 Horner 形式。

$$2^{x_{\mathrm{frac}}} \approx p_0 + p_1 x_{\mathrm{frac}} + p_2 x_{\mathrm{frac}}^{2} + p_3 x_{\mathrm{frac}}^{3}$$

系数 `p0 = 1.0`、`p1 ≈ 0.6951`、`p2 ≈ 0.2276`、`p3 ≈ 0.0771` 使用 Sollya 软件包选定，以最小化 $[0, 1)$ 上的相对近似误差。

**指数位移位与相加：** 最后一步把整数部分 n 和小数近似 2^{f} 组合成 2^{x} \approx 2^{n}\cdot 2^{f}。由于 2^f \in[1,2) 的 float32 指数为 127，乘以 2^{n} 只需把整数 n 移入指数域，再加上 2^{f} 的尾数位。

## 后向 pass：共享内存流量主导之地

优化 FlashAttention 的反向传播就像把一张过大的地毯塞进房间：压平一个角，另一个角又鼓起来。反向要计算前向约 2.5 倍的 tensor core 工作——链式执行五个 MMA 来重算 S 并运行 dQ、dK、dP、dV 的 QK 和 PV 梯度矩阵乘，外加 P 和 dS 的逐元素工作。在 Blackwell 上，限制反向的不是 FLOPs，而是共享内存带宽。

### **流水线：让 MMA 与 *softmax* 重叠**

Hopper 时代的 FlashAttention-3 把 MMA 累加器放在寄存器里，寄存器压力常常迫使更串行的调度。在 Blackwell 上，累加器住在 TMEM，使得在 CUDA core 处理 P 和 dS 的逐元素工作的同时保持多个 MMA 在飞行中变得可行。由于在我们的 roofline 上指数吞吐与两个 MMA 相当，把它藏起来是值得的。

**关键重叠很简单**：在计算 tile j 的 softmax 时，我们已经发起 tile j−1 的 **dK** 和 **dQ** MMA。

为减少共享内存流量，反向 pass 相对前向以转置 tile 重算 S 和 P，因此中间量本来就是 $S^T$ 和 $P^T$。这样我们可以把 $P^T$（以及之后的 $dS^T$）直接按 dV 和 dK MMA 作为操作数 A 消费的确切布局存入 TMEM。

TMEM 无法同时容纳五个完整累加器和中间量，所以 FA4 跨阶段复用 TMEM 列：S 和 P 共享一组列，dP、dS 和 dQ 共享另一组。

### 2-CTA 反向 pass：减少共享内存流量与全局原子加

**共享内存流量。** 即便有了改进的流水线、并把十个 GEMM 操作数中的两个保存在 tensor memory，反向 pass 仍受共享内存带宽限制。我们用 Blackwell 的 2-CTA MMA 模式缓解：它把输出累加器切分到 CTA 对上。取 M=256、N=K=128，两个 CTA 协作当作一个 tile：每个 CTA 只暂存操作数 B 的一半、只保留自己那份累加器切片。这把操作数 B 的共享内存流量大约减半。

**归约轴冲突。** 我们在五个反向 GEMM 上用 M=256、N=K=128 的 MMA tile 来削减 B 流量，但 dQ MMA 的性质引入了不匹配。FlashAttention 反向中，每 CTA 拥有一个固定的 KV tile（外层循环在 N 个 CTA 上并行），内层循环遍历 M tile。dQ 更新在外层循环沿 KV 序列归约。2-CTA MMA 切分的是输出 tile 而不是归约，而 dQ 的归约维是 N——它已经在 CTA 对间切分了。每个 CTA 仍需要它所拥有各行的完整归约。

**解法：DSMEM 交换。** 我们通过在 cluster 内使用分布式共享内存（DSMEM）在两个 CTA 间交换一半的 dS 来解决。这重新打包 dS，使其沿非归约轴切分：每 CTA 拥有 M/2 行，同时持有完整的 2N 归约量。每 CTA 的 dQ MMA 变成 (M/2, 2N)(2N, d)，在 tensor memory 中累加一个 (M/2, d) 的 tile。在 2-CTA 模式下，S、dP、dV、dK 的 MMA 保持 M=256，而 dQ 用 M=128、归约加倍为 2N=256。随后我们重排流水线以隐藏 DSMEM 延迟：先为当前 tile 计算 dP，再为上一个 tile 计算 dQ。由于 dQ tile 与 P 一起能装进 TMEM，它可以复用原本给 S 的 TMEM 区域，于是 dP 和 dQ 不再像 1-CTA 模式那样共享一个区域。在这个顺序下，当前 tile 的逐元素 dS 与上一轮迭代的 dQ MMA 重叠。

**dQ 原子加。** 附带的好处是 dQ 的分解使全局原子归约次数减半。原子操作非确定且昂贵，并且发生在每次内层循环迭代中。因此在 2CTA 反向 pass 中，每 CTA 只写 dQ tile 的一半，全局原子归约次数只有 1-CTA 版本的一半。

### 确定性模式：不压垮吞吐地实现可复现的 `dQ`

非确定性的根源是 `dQ` 的全局原子累加。FA4 提供一个确定性模式，用信号量式锁和内存栅栏把全局归约串行化，强制固定的累加顺序。但确定性不必意味着"一切停摆"。FA4 用 CTA swizzling 降低锁争用，并对因果掩码采用最短处理时间优先（SPT）的顺序来减少停顿。实践中，在我们的基准中确定性反向可达非确定性吞吐的约 85-90%。

## 调度

因果掩码和变长序列让 attention 负载不均，因为不同 worktile 的主循环长度不同，所以 FA4 改进了 grid 线性化，并应用***最长处理时间优先（LPT）***调度来削减尾部。事实上，这些思想并不特定于 Blackwell 或任何 GPU 架构，我们在 FA3 中同样使用。

对于**因果掩码**，标准的 (mblocks, heads, batches) grid 顺序会从最短到最长处理 tile，并非最优；FA4 把 batch-head 以 L2 大小为单元 swizzle 分组，按 batch-head 单元遍历 grid，在每个单元内逆序迭代 mblocks。

对于**变长序列**，不同 batch 的工作量不同，给定的批处理顺序从 LPT 调度启发式的角度看通常不优。为纠正这一点，可以启动一个预处理 kernel，按每 worktile 最大执行时间对 batch 排序，写入一个"虚拟到实际"的 batch 索引映射，attention kernel 按排序顺序遍历 batch；而且元数据可缓存，排序不带来性能损失。截至写作时，我们已验证该想法并在 FA3 中实现，预计不久将把排序及其他元数据准备更普遍地纳入 FA4。

## 语言与框架：CuTe-DSL

FA4 完全用 CuTe-DSL 实现——CUTLASS 的 Python kernel DSL。Kernel 用 Python 编写；DSL 降级到 PTX，再由 CUDA 工具链编译成 GPU 机器码。其编程模型镜像 CuTe/CUTLASS 抽象，并带 PTX 逃生舱口，同时相比 C++ 模板把编译时间削减约 20–30 倍。

## Attention 基准

我们展示 FlashAttention-4 在 B200（BF16）上的结果，并与 FlashAttention-2 以及 Triton、Gluon、cuDNN 的实现比较。对 cuDNN，我们对比 9.13 版和最新版 9.19.1.2。从 9.13、9.14 版开始，我们与 cuDNN 团队合作把 FlashAttention-4 的若干技术纳入 cuDNN，让我们的工作能惠及尽可能多的实践者。反向方面，FlashAttention-4 在大序列长度上稳定超越其他基线。前向方面，FlashAttention-4 比 cuDNN 9.13 快 1.1-1.3 倍，比 Triton 快 2.1-2.7 倍。
