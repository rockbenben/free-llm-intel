自动扩缩容、访问控制、全栈可观测性与自愈运维——内建于集群。

AI 基础设施已经悄然变成生产基础设施。团队不再只是拿几块 GPU 做实验。一个单节点原型可能迅速膨胀成横跨数百加速器的分布式训练负载；服务真实用户的推理系统可能经历不可预测的流量尖峰。而当集群成为共享环境，运维标准对所有人——从 ML 研究员到企业平台工程师——都变了。

但随着基础设施扩张，手动管理成为一种负债。静态供给低效且昂贵；权限管理变得脆弱；可观测性缺口掩盖性能瓶颈；而当 GPU 硬件出故障——这是必然——单个不稳定节点就能让数小时的训练时间泡汤。

今天，我们为 **Together GPU Clusters**（前身 Instant Clusters）引入一系列企业级增强。我们把自动扩缩容、基于角色的访问控制（RBAC）、全栈可观测性、自助节点修复和主动健康检查直接集成进核心集群体验——让团队兼得虚拟化技术栈的弹性与裸金属的性能画像。

### **自动扩缩容：弹性容量，不过度供给**

不再为峰值负载静态分配 GPU 容量，你可以开启"auto-scaling"，让集群基于实时资源需求扩张或收缩。

底层是 [Kubernetes Cluster Autoscaler](https://github.com/kubernetes/autoscaler)，它监控受 GPU 资源限制的工作负载（pending pod）——来自分布式训练或突发推理流量。需求飙升时，额外节点自动上线；需求回落时，容量缩下来。

结果很直白：你在负载下保持性能，同时不为闲置 GPU 节点付费。这让 Together GPU Clusters 同时适合长时间运行的训练任务和多变的推理负载。了解更多请访问[文档](https://docs.together.ai/docs/gpu-clusters-management#cluster-autoscaling)。

### **主动健康检查、更深的验收测试与自助节点修复：缩短故障 MTTR**

在大型 GPU 舰队里，硬件不稳定不是假想风险——是运维现实。对分布式训练负载，单个节点故障能让整个任务运行作废。

Together GPU Clusters 现在内建自助主动健康检查。在启动大规模训练任务之前，用户可以直接从 UI 触发从基础 DCGM Diag 3 到多节点 NCCL 或 InfiniBand 写带宽测试的检验，获得带详细输出的 pass/fail 结果。

这一能力对分布式训练负载尤为关键——单个节点故障会作废整个任务运行。用户现在可以在拉起大训练任务前对基础设施触发一系列深度检查，保住工作负载连续性、减少浪费的算力周期。

如果节点出故障，用户三次点击即可完成自助修复。控制平面会自动 cordon、drain，并在新的或现有主机上重建节点，几分钟内让集群回到健康状态。验收测试现在在开通期间自动运行，集群通过之前不会被标记为 Ready。完整验收测试清单见[文档](https://docs.together.ai/docs/health-checks)。

### **基于角色的访问控制：结构化的多团队治理**

当集群从实验走向共享基础设施，访问控制就成了根基。在 Together GPU Clusters 中，"Projects" 定义团队的协作与隔离边界，集群和存储卷严格限定在项目内。

管理员可以实施与企业治理对齐的结构化访问控制。项目默认包含两种角色：

- **Admin：** 对控制平面完全读写（创建/删除集群），以及 Slurm 集群的 sudo 访问。
- **Member：** 对数据平面写访问（访问 GPU worker 节点和运行中的负载）。

这种清晰切分让平台工程师锁定基础设施开通权，同时给研究与应用团队在边界内安全运行负载的自由。

你可以在[云控制台](https://api.together.ai/)中前往 Settings > GPU Cluster Projects 管理项目成员与用户角色。

了解更多请访问[文档](https://docs.together.ai/docs/cluster-user-management)。

### **全栈可观测性（私有预览）**

每个 Together GPU Cluster 项目现在自带一个专属 Grafana 实例，内含预建 dashboard，可从集群详情页直接访问。

遥测覆盖全栈：

- **GPU 利用率：** DCGM 指标直接透视加速器的健康与性能。
- **网络：** InfiniBand 与网卡级遥测暴露吞吐与带宽模式。
- **存储与编排：** I/O 性能指标浮现隐藏瓶颈，Kubernetes 遥测提供编排健康与资源分配的可见性。

集群开通即有遥测。对平台团队，这加速了调试与性能调优；对财务与运营团队，这改善容量规划与成本效率。

该功能处于私有预览，请联系支持或你的客户团队获取 Grafana 实例访问。

## **从实验走向运维**

有了自动扩缩容、RBAC、可观测性、交钥匙健康检查和平台内集成的修复流程，Together GPU Clusters 从裸 GPU 供给迈入生产就绪的全托管基础设施。

这让团队有信心运行大规模分布式训练任务，而不必担心硬件故障级联成损失的算力时间。它也为组织各角色提供定制价值：

- **平台工程师**可以在共享环境中安全服务多个内部干系人。
- **运维人员**能在网络或存储瓶颈劣化模型性能之前精确定位。
- **财务团队**可以让 GPU 支出与实际利用模式更紧密对齐。

最重要的是，组织可以从实验性 AI 系统迈向运维化 AI 平台——无需拼接第三方工具或从零构建内部控制平面。
