# 安全事件：2026 年 6 月与 7 月请求的 prompt 泄露

我们正在通知客户：2026 年 6 月和 7 月提交到 Together AI 无服务器推理服务的一部分 prompt 发生了一起安全事件。一个私有代码仓库的凭证被暴露在公开代码仓库中后，未经授权的第三方下载了已存储的 prompt 样本。

我们就此事件致歉。我们正在审查受影响的数据，以确定暴露了哪些信息，以及哪些客户需要直接通知。

## 发生了什么

作为常规软件测试的一部分，我们收集了获准用于该用途的 prompt 样本，并将其存储在一个私有的 Hugging Face 仓库中。这些样本来自对 MiniMax M3、GLM-5.2 和 Kimi K2.6 模型的请求，主要集中在 2026 年 6 月 24 日、7 月 4 日、7 月 8 日和 7 月 14 日。

在开发我们的公开 GitHub 仓库 xorl 期间，一个 AI 编码 agent 提交了一个可访问该私有 Hugging Face 仓库的凭证。我们的自动扫描发现了该暴露的凭证，并回滚了该提交。

在暴露窗口期内，未经授权的第三方获取了该凭证，并用它下载了已存储的 prompt 样本。此后，该方在这些样本中检索指向其他服务的凭证，并测试这些凭证是否有效。被测试的凭证中有 5 个是与 Dragos 安全实验相关的 canary 凭证。

我们没有理由认为该未经授权的第三方进一步泄露了这些数据，并了解到该数据现已被删除。

## 调查与范围

我们已与一家外部取证调查机构和执法部门合作调查此事件。

根据我们的审查，除本事件外，我们尚未发现其他 prompt 泄露的证据。我们仍在审查受影响的 prompt 内容，以确定是否暴露了敏感个人信息或其他客户数据。视需要，我们会直接联系受影响客户，并向其提供与其相关的发现。

## 我们已做的变更

事件发生后，我们加强了对开发工作流、凭证和客户数据的管控。这些变更包括：

- 使用限定范围或短时效的凭证，并在支持的情况下采用无密钥访问，以降低凭证暴露的潜在影响。
- 对所有 pull request 进行凭证检查。
- 将零数据保留（ZDR）设为新账户的默认设置。
- 更新我们关于使用 AI 编码 agent 的开发流程。

## 客户可以做什么

处理敏感 prompt 数据的客户应在账户设置中启用 ZDR。

如果你对本事件或其可能对贵组织造成的影响有疑问，请联系 security@together.ai。
