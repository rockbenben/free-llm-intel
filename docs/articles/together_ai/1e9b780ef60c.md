训练基础模型需要编排成百上千块 GPU 并行工作。本文带你走过大规模分布式训练所需的基础设施、技术与实操步骤。

### 如何在 GPU 集群上大规模训练基础模型？

**什么是多节点 GPU 训练？**

多节点训练把模型训练分布在多台机器（节点）上，每台节点有多块 GPU。不再是单台 8 GPU 服务器上训练，而是把几十乃至上百个节点连在一起，让你在合理时间内训练数十亿参数的模型。这涉及使用数据并行、张量并行与流水并行、参数分片等并行策略，把模型和数据切分到各 GPU，同时通过 NVLink、InfiniBand 这类高速互连协调执行。

**为什么多节点训练重要**

基础模型已从数十亿参数增长到数万亿参数。在单节点上训练这些模型是不可能的——模型装不进内存，训练要花好几个月。多节点集群把训练时间从数月压缩到数天或数周，加速迭代周期和上市时间。

转向分布式训练也意味着基础设施变得至关重要。糟糕的网络配置会把 GPU 利用率卡到 40-50%；在一个 100 节点集群里，硬件故障成为日常事件，你必须在不丢失训练进度的前提下处理它们。把分布式训练做对，决定了你的模型是成功训练，还是烧光算力预算颗粒无收。

### 分布式训练如何工作

- **并行策略**把工作切分到 GPU。**数据并行**在每块 GPU 上复制完整模型、把批次分到各卡——简单但受内存限制。**模型并行**把模型本身切分到多 GPU，支持更大的模型但需要精细协调。**流水线并行**把模型层划分为若干阶段，不同批次同时在不同阶段处理。多数生产训练会组合这些方法。
- **网络互连**在 GPU 之间传输梯度和激活。节点内，NVLink 提供 GPU 之间 900 GB/s 带宽。节点间，InfiniBand 或 RoCE 网络通常提供每节点 400-800 Gb/s。网络延迟与带宽直接影响训练速度——每一个百分点的网络开销都是损失掉的 GPU 利用率。
- **Checkpoint 与容错**定期保存训练状态。100 节点集群里硬件故障每天都会发生。每隔几百步向分布式存储做 checkpoint，让你能从最后一个保存点恢复。现代框架支持最少量代码的自动 checkpoint/恢复。

### 多节点训练能做什么

- **训练装不进单节点的模型：** 70B 参数模型混合精度仅权重就需要约 140GB。加上优化器状态和激活，你需要 400-600GB——远超单节点容量。
- **把训练时间从数月缩到数天：** 从 8 块到 128 块 GPU 的扩展，在恰当调优下可提供 12-15 倍加速。单节点要跑 30 天的训练，在集群上 2-3 天完成。
- **更快地迭代模型架构：** 训练周期更短意味着更多实验。测试不同架构、超参数或数据混合，不必等上几周。
- **处理生产规模的数据集：** 加载和预处理 TB 级训练数据需要分布式 I/O。带并行存储的多节点集群能维持喂饱 GPU 所需的吞吐。

### 生产案例：训练 Qwen2.5-72B

在 B300 GPU 集群上训练一个 72B 参数模型展示了真实的分布式训练。使用 16 个节点、每节点 8 块 B300（共 128 块 GPU）：

- 模型用张量并行（TP=8）和流水并行（PP=2）分布到各 GPU。最优配置会随序列长度、batch size 和互连性能而变化。
- 在网络恰当调优下达到 45-50% MFU（模型 FLOPs 利用率）
- InfiniBand RDMA 提供节点间合计 6.4 TB/s 带宽
- 每 500 步向分布式存储做 checkpoint
- 训练吞吐：约每 GPU 2,500 tokens/秒

常见的问题包括：个别 GPU 的 PCIe 总线错误导致节点掉线、需要重置 GPU 的 NVLink 连接故障、梯度同步期间需要调交换机配置的网络拥塞。

### 多节点训练起步

- **验证你的基础设施：** 训练前用 `nvidia-smi nvlink` 状态检查和带宽测试验证节点内 GPU 间带宽。用 `ib_write_bw` 或类似工具检查节点间网络吞吐。开始训练前确保拿到了预期带宽。
- **配置你的分布式框架：** 用正确的分布式初始化搭建训练脚本。PyTorch：初始化进程组、为 GPU 通信设置 NCCL 后端、在模型里配置张量/流水并行。先用一个小模型测试。
- **实现 checkpoint：** 按迭代时长和集群可靠性决定的间隔，配置向分布式存储的自动 checkpoint，在恢复时间与 checkpoint 开销之间做平衡。测试从 checkpoint 恢复，确认你能在不丢数据的情况下从故障中恢复。设置 checkpoint 清理以免写满存储。
- **跑一个扩展性测试：** 从 2 个节点开始，测吞吐和 GPU 利用率。扩到 4、8、16 个节点，逐步检查效率。目标 >80% 的扩展效率（节点翻倍应有 >1.6 倍加速）。在全规模训练前调试瓶颈。
- **监控你的训练运行：** 持续跟踪 GPU 利用率、内存使用和网络带宽。为节点故障、GPU 错误或指标异常下跌设置告警。硬件故障时准备好从 checkpoint 重启。

### FAQ

**我怎么知道集群配置是否正确？** 训练前跑合成基准。节点内 NVLink GPU 带宽应达到 800+ GB/s。节点间带宽应达到 InfiniBand 规格的 80% 以上。如果实际训练运行 GPU 利用率 <70% 又没有明显瓶颈，检查网络配置和存储 I/O。

**多节点训练多数失败的原因是什么？**

- **硬件问题：** GPU 显存错误、GPU 掉出总线、ECC 与 XID 错误、PCIe 总线故障、NVLink 掉线、GPU 温度/降频
- **网络问题：** 拥塞、交换机配置错误、RDMA 问题
- **存储问题：** InfiniBand 连接问题、挂载与 MTU 配置错误、checkpoint 写入超时、元数据服务器过载、磁盘故障
- **软件问题：** 驱动、VBIOS、固件不兼容，NCCL 配置错误

**我该用数据并行还是模型并行？** 装得进单 GPU 内存的模型从数据并行开始——更简单、扩展性好。模型超出 GPU 内存时用张量/流水并行。超大模型两者结合：节点内模型并行，节点间数据并行。
