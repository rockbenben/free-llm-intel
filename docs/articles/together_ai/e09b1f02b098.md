## 摘要

当前的数据科学基准依赖互不兼容的评估接口。而且许多任务不使用底层数据也能解答。我们通过提出 DSGym 来解决这些局限——一个在自包含执行环境中评估与训练数据科学 agent 的一体化框架。借助 DSGym，我们训练出了一个最先进的开源数据科学 agent。

arXiv 论文：[https://arxiv.org/abs/2601.16344](https://arxiv.org/abs/2601.16344)

GitHub 仓库：[https://github.com/fannie1208/DSGym](https://github.com/fannie1208/DSGym)

数据科学是现代科学发现的计算引擎。然而，评估和训练基于 LLM 的数据科学 agent 仍然充满挑战，因为现有基准在异构执行环境中评估孤立的技能，使集成代价高昂、公平对比困难。

我们推出 **DSGym**：一个统一框架，用单一 API 把多样的数据科学评估套件整合在一起，并为数据集、agent 和指标提供标准化抽象。DSGym 统一并精炼了现有基准，同时以新型科学分析任务（来自学术文献的 90 个生物信息学任务）和高难度端到端建模竞赛（92 个 Kaggle 竞赛）扩展了范围。除评估外，DSGym 还提供用于 agent 训练的轨迹生成与合成查询流水线——我们的示范是：用 2k 生成样本训练一个 4B 模型，取得开源模型中最先进的表现。

## **框架与数据集**

**DSGym** 的主要贡献之一，是把代码执行的复杂性抽象到可实时分配、安全执行代码的容器之后；这些容器自带预装依赖和供处理的数据。

DSGym 为所有基准提供统一的 JSON 接口，每个任务表达为：数据文件、查询 prompt、评估指标和元数据。我们力求设计模块化、简单直白，让用户新增任务、agent 脚手架、工具和评估脚本都更容易。DSGym 的任务分为两条主赛道：

- **数据分析（Data Analysis）**：通过程序化分析回答问题。
- **数据预测（Data Prediction）**：端到端 ML 流水线开发。

除整合 MLEBench、QRData 等既有基准外，DSGym 还引入原创数据集。具体地，我们创建两个新套件扩展总体范围：**DSBio**（来自学术文献的 90 个生物信息学任务，考察领域专属工作流）和 **DSPredict**（92 个 Kaggle 竞赛，涵盖时间序列、计算机视觉、分子性质预测和单细胞扰动）。下图总结这两个套件的创建过程：

DSGym 构建流水线。左：由生物信息学论文导出的科学任务，含论文报告的查询和专家提炼的查询（90 个任务）。右：来自存档竞赛的 Kaggle 任务，经筛选并按难度分为 Easy（38）与 Hard（54）两个子集。

为支持任务执行与数据生成，DSGym 提供一条数据生成流水线，执行查询并生成轨迹，把框架变成一座能有效训练模型的数据工厂。

用这条流水线，我们生成了 3,700 条合成查询。经基于 LLM 的质量过滤后，得到 **2,000 个高质量"查询-轨迹"配对**用于监督微调。我们的结果（见下文）证明，这些数据是提升模型在数据科学任务上表现的有效途径——即使对小模型也成立。

## **结果**

这里呈现主要发现。更多结果见论文。

### 应对记忆缺口

第一个重要结果关乎记忆。我们观察到许多现有基准的查询信号很弱：相当比例的题目**即使无法访问数据文件**也能解答，说明 LLM 可能在训练中已经"学过"这些任务。

我们展示了多数模型不看数据就能回答数据科学问题，转而依赖训练时记住的信息。这是个大问题，意味着模型并没有真正在做数据分析。

因此我们确保标记并剔除这些很可能落入模型训练集的例子。DSGym 应用质量过滤和"仅凭 prompt 走捷径"过滤，剔除这类任务，产出精炼数据集：**DAEval-Verified、QRData-Verified、DABStep 和 MLEBench-Lite。**

### 基准表现与失败模式

创建这些新基准后，我们在通用数据科学任务和领域专属科学任务上测试前沿专有模型与开放权重 LLM。

我们训练的 4B 模型（**Qwen3-4B-DSGym-SFT-2k**）在通用分析基准上与远大于它的模型表现相当。

有趣的是，多数模型离在这些基准上拿满分仍很远。为理解模型为何在这些任务上失败，我们对每个模型、每个任务族随机抽取 50 条失败轨迹做人工错误分析。分析揭示一个有趣的模式：通用分析任务的失败模式多样，最常见的是统计知识缺口和规划错误；而科学分析任务的失败则由单一模式主导。

四种 LLM 在 (a) 通用分析任务（QRData 和 DAEval）与 (b) 科学分析任务（DSBio）上的错误类型分布。

对每个模型和任务族，我们均匀抽样 50 条失败轨迹并人工指定主错误类别。一个关键转变浮现：通用任务的失败以统计知识和规划问题为主，而 DSBio 上的失败绝大多数由领域落地（domain-grounding）错误驱动（各模型 85–96%）。

### 数据预测表现

DSPredict 评估 agent 构建完整机器学习流水线——从原始数据到最终模型——的能力，模拟 Kaggle 竞赛的复杂度。

我们在 **DSPredict-Easy** 和 **DSPredict-Hard** 两个子集上评估模型。度量包括：

- **有效提交（Valid Submission）：** 成功生成格式正确的输出文件。
- **中位/百分位（Median/Percentile）：** 相对原竞赛排行榜的表现。
- **奖牌（Medal）：** 达到相当于铜牌、银牌或金牌的分数门槛。

我们使用一个简单的 CodeAct 式脚手架。每个 agent 的总时限为 10 小时，每次代码执行 2 小时。

| Valid | Medal | Median | Valid | Percentile | Median |  |
| GPT-5.1 (high) | 85.7 | 4.8 | 14.3 | 100 | 60.4 | 75 |
| GPT-5.1 (medium) | 81.0 | 4.8 | 7.1 | 91.7 | 55.7 | 63.9 |

**表 2：DSPredict 基准上的性能指标。** 每列最佳成绩以橙色标出。Valid = 有效提交率，Medal = 任意奖牌率，Median = 超过中位数率；DSPredict-Easy 中 Percentile 替代 Medal。

对 DSPredict 结果的分析揭示了当前 LLM agent 在端到端 ML 工作流中的能力与局限的若干关键洞见。

**高可靠性，低竞争力：** 前沿模型（如 GPT-5.1 和 Claude 4.5）在构建可用流水线上表现出色——有效提交率超过 85%——但很难有竞争力。在"Hard"任务上能稳定超过人类中位数的模型寥寥无几。

一个主要瓶颈是模型倾向于选阻力最小的路。面对技术摩擦或复杂数据，agent 常常退回到简单基线或"安全"启发式，而不是追求高性能建模策略。

**推理 vs. 规模：** 高推理模型（GPT-5.1-high）明显领先，说明数据科学所需的"怀疑式"韧性——调优、验证、迭代——目前比原始参数量更关键。

## **结论**

DSGym 提供了评估与训练数据科学 agent 的统一框架。我们揭示了当前方法的一个根本挑战：模型在通用任务上严重依赖记忆，而在科学问题上又无法把分析建立在领域知识之上。

通过提供横跨两类任务的标准化基准，DSGym 让系统性研究"如何构建真正对数据推理而非回忆模式的 agent"成为可能。我们还发布了一个能力出众、易于开发和部署的开源数据科学 agent。我们希望这份资源能加速通往更可靠、更可泛化的数据科学自动化的进程。
