# DeepSeek-V4 Pro 现已登陆 Together AI

1.6T 参数 MoE 推理模型，在 Together AI 上提供 512K 上下文、可控推理模式，以及面向长上下文工作负载的缓存输入定价。

## 最新动态

- [**Together AI 上的 DeepSeek V4 Pro：**](https://www.together.ai/models/deepseek-v4-pro) DeepSeek V4 Pro 现已在 Together AI 上线，提供 512K token 上下文窗口，面向长上下文推理工作负载。
- **大规模 MoE 架构：** DeepSeek V4 Pro 采用 1.6T 参数的 Mixture-of-Experts 架构，激活参数 49B。
- **可控推理模式：** Non-Think、Think High、Think Max 三种模式，让团队在快速响应、更深推理和最大推理强度之间选择。
- **透明的 serverless 定价：** DeepSeek V4 Pro 价格为**每 100 万输入 token \$2.10、每 100 万缓存输入 token \$0.20、每 100 万输出 token \$4.40。**

长上下文推理改变了人们能让模型做的事。整个代码仓库、大型文档集、长 agent trace 和工具输出都能装进模型的工作上下文，而不必被压缩成脆弱的摘要。但能用这么多上下文的模型也最难服务：一个 1.6T 参数的 MoE、支持百万 token 上下文，不是多数团队想自己部署、调优和运维的东西。

DeepSeek-V4 Pro 现已在 Together AI——AI Native Cloud——上线：团队可以从 512K 上下文的 Serverless Inference 起步，再迁移到专属基础设施以获得完整 1M 上下文、预留容量和生产级控制。DeepSeek-V4 Flash 即将推出，为看重速度和成本胜过最大推理深度的团队提供另一个 V4 选项。

## **为长上下文推理而生**

DeepSeek V4 Pro 为那些模型需要在远超短 prompt 的内容上推理的工作负载而建：大型代码仓库、长篇技术文档、密集检索包、工具调用历史和研究语料。

DeepSeek V4 Pro 在模型级支持百万 token 上下文；在 Together AI 上目前以 512K token 上下文窗口提供。这个区别很重要，因为模型能力和已部署的服务形态不总是一回事。Together AI 首发即配一个为可靠生产服务设计的上下文窗口，同时给团队留足严肃长上下文负载的空间。

架构同样重要，因为长上下文不只是一个产品参数。随着上下文增长，服务成本、内存压力、KV 缓存占用、延迟和并发都成为系统设计的一部分。DeepSeek V4 Pro 采用混合注意力，结合压缩稀疏注意力（Compressed Sparse Attention）与重度压缩注意力（Heavily Compressed Attention），DeepSeek 报告在百万 token 上下文下，单 token 推理 FLOPs 降至 DeepSeek V3.2 的 27%、KV 缓存降至 10%。

## **按工作负载选择推理强度**

DeepSeek V4 Pro 支持三种推理模式，让团队按任务难度匹配推理深度，而不是一视同仁地处理每个请求。

| 模式 | 适用时机 | 权衡 |
| --- | --- | --- |
| Non-Think | 抽取、分类、简单问答、常规回复 | 低复杂度任务的最快路径 |
| Think High | 代码规划、文档分析、多步推理 | 更复杂工作配更深推理 |
| Think Max | 疑难调试、深度研究综合、agent 决策点 | 最大推理强度；预期更高延迟和 token 用量 |

一个文档助手可能对简单抽取用 Non-Think，对跨条款冲突分析用 Think High，只在模型需要推理艰难决策时用 Think Max。一个代码 agent 可能在规划迁移时用 Think High，调试微妙的跨服务故障时用 Think Max。

DeepSeek 报告了编码、推理、长上下文和 agent 任务的基准结果，包括 93.5% LiveCodeBench、90.1% GPQA Diamond、80.6% SWE-bench Verified、83.5% MRCR 1M 和 62.0% CorpusQA 1M。

## **用缓存输入定价降低重复长上下文查询的成本**

长上下文系统常常在多个问题之间复用同一大上下文：一份仓库快照、一个文档包、一套政策档案、一次检索载荷或一条长 agent trace。缓存输入定价让这些重复负载更可行。

DeepSeek V4 Pro 定价为 \$2.10 / 1M 输入 token，缓存输入 \$0.20 / 1M token，输出 \$4.40 / 1M token。这代表复用上下文**成本降低 90%**——当请求的昂贵部分是一个在后续分析中被反复使用的稳定文本块时，这一点至关重要。

**示例模式：**

- 加载一个大型稳定上下文，如 300K token 的仓库摘要、合同集或政策档案。
- 在同一上下文上连续提出多个后续问题。
- 适用处使用缓存输入定价，大幅降低重复分析的成本。

## **工作负载模式**

**代码 agents**

当 agent 需要跨仓库切片、issue trace、内部文档、既往工具调用和候选补丁进行推理时，使用 DeepSeek V4 Pro。规划变更、调试故障或解析跨文件依赖时，Think High 或 Think Max 最有用。

**文档智能**

用长上下文处理需要在单个请求里彼此对照的合同、政策集、技术手册或研究合集。Non-Think 足以应付抽取和简单问答；冲突分析、解读与综合更适合 Think High。

**长上下文 agent trace**

用 DeepSeek V4 Pro 检查长工具调用历史、中间结果和执行 trace。更高的推理模式在决策点最有用：agent 需要决定是继续、再调用一个工具、修订计划还是停止时。

**研究综合**

对合并论文、笔记、基准报告、检索文档和既往分析的工作流，使用 DeepSeek V4 Pro。当同一证据集跨多个问题复用时，缓存输入定价尤其有用。

## **从 serverless 起步，走向预留容量**

DeepSeek V4 Pro 在 Together AI Serverless Inference 和 Monthly Reserved 基础设施上可用。Serverless 是评估、开发和波动流量的正确起点。对于更平稳的生产需求——团队需要更可预测的容量和成本控制——Monthly Reserved 更合适。

对长上下文工作负载，部署路径很重要。团队不只在选择一个模型，还在选择随着上下文规模增长如何管理吞吐、并发、延迟、KV 缓存压力和成本。Together AI 给团队一条从评估到生产的路，无需自己搭建服务栈。

## 立即试用

DeepSeek-V4 Pro 今天在 Together AI Serverless Inference 和 Dedicated Endpoints 上可用。

```
    
from together import Together

client = Together()

stream = client.chat.completions.create(
    model="deepseek-ai/DeepSeek-V4-Pro",
    messages=[
        {
            "role": "user",
            "content": "Prove that the square root of 2 is irrational.",
        }
    ],
    stream=True,
)

for chunk in stream:
    if not chunk.choices:
        continue
    delta = chunk.choices[0].delta

    if hasattr(delta, "reasoning") and delta.reasoning:
        print(delta.reasoning, end="", flush=True)
    if hasattr(delta, "content") and delta.content:
        print(delta.content, end="", flush=True)

    
```
