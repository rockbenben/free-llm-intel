## DSGym: A Holistic Framework for Evaluating and Training Data Science Agents

1,000+ 任务

10+ 领域，一个 API

**来自 10+ 领域的一千多个数据科学任务，统一在一个评估与训练 API 之后。** 数据科学 agent 一直难以公平度量——每个基准有自己的接口，其中许多任务根本不打开数据也能解。DSGym 标准化了度量并堵上了这个漏洞。

它把多样的评估套件收进一个 API、共享数据集/agent/指标的抽象，并让每个任务运行在自包含执行环境中——agent 必须与数据打交道，而不是回忆答案。在精炼后的既有套件之上，它新增 90 个基于学术文献的专家生物信息学任务和 92 个端到端 Kaggle 风格建模竞赛。同一环境随后"反过来"作为训练引擎运行：轨迹生成与合成查询流水线产出经执行验证的数据，我们用这些数据把 4B 模型训练成最先进的开源数据科学 agent——全程无人工标注。诚实评估、从同一套具合成、微调、再评估——尽在一个框架内。

*作者：Fan Nie, Junlin Wang, Harper Hua, Federico Bianchi, Yongchan Kwon, Zhenting Qi, Owen Queen, Shang Zhu, James Zou。合作者来自 Stanford、Duke 和 Harvard。*

论文：[arXiv:2601.16344](https://arxiv.org/abs/2601.16344)

论文 2

## ThunderAgent: A Simple, Fast and Program-Aware Agentic Inference System

最高 3.6×

agent 吞吐

**用三行代码接入，agent 工作负载的服务吞吐提升 1.5 到 3.6 倍。** 并行 agent 工作负载不再在负载下崩溃，而解法不是更快的模型。

问题在于推理引擎根本不知道自己在运行一个 agent：它把多轮工作流的每一步当作孤立请求处理，负载下延迟膨胀至多 7.14 倍。ThunderAgent 让工作流本身成为调度器可以端到端推理的一等对象。除吞吐提升外，它还带来 1.8 到 3.9 倍更快的 RL rollout，磁盘节省最高 4.2 倍（相对最先进系统）。

*作者：Hao Kang, Ziyang Li, Xinyu Yang, Weili Xu, Yinfang Chen, Junxiong Wang, Beidi Chen, Tushar Krishna, Chenfeng Xu, Simran Arora。合作者来自 Georgia Tech、CMU 和 UIUC。*

论文：[arXiv:2602.13692](https://arxiv.org/abs/2602.13692)

论文 3

## Learning to Discover at Test Time (TTT-Discover)

超过人类最佳

开源模型，约 \$500

**跨四个领域的前沿发现——数学、GPU kernel、竞赛算法、生物学——全部用开源模型完成。** 此前每一例这种水平的结果都依赖只能通过 API 调用、无法检视也无法自跑的闭源前沿模型。TTT-Discover 用一个开源 120B 模型、一套不变的method，每道题花几百美元就达到同样高度。

AI 发现的常规配方是搜索：把冻结的模型 prompt 数千次、留最好的样本。TTT-Discover 转而"在测试时"对眼前的单一问题运行强化学习，让每次尝试都成为下一次的训练数据，模型边工作边变强；同样采样预算下，朴素的 best-of-N 永远追不上。同一套未改动的设置，给出了一个 60 年历史 Erdős 问题的更紧边界（超过此前用闭源模型创造的 AI 记录），发现了比 GPUMode 排行榜最佳既往提交更快的 GPU kernel，在竞赛编程赛中取得第一梯队成绩，并在生物学的单细胞去噪基准上创出新高——全部跑在开源的 gpt-oss-120b 上。代码和创纪录的 kernel 均已公开。

*作者：Mert Yuksekgonul, Daniel Koceja, Xinhao Li, Federico Bianchi, Jed McCaleb, Xiaolong Wang, Jan Kautz, Yejin Choi, James Zou, Carlos Guestrin, Yu Sun。合作者来自 Stanford、NVIDIA、UC San Diego 和 Astera Institute。*

论文：[arXiv:2601.16175](https://arxiv.org/abs/2601.16175)

## Escaping the Verifier: Learning to Reason via Demonstrations (RARO)

25% vs 5.9%

对专家 · 无验证器

**无需任何验证器，对专家响应取得 25% 的胜率（监督微调只有 5.9%）。** 你可以在没有检查器的任务上——比如写诗或金融分析，而不仅是数学和代码——获得 RL 级别的推理。

基于 RL 的推理通常假设有能判断正确性的验证器。RARO（Relativistic Adversarial Reasoning Optimization）用一个对抗博弈取而代之：一个模型同时扮演产出专家级答案的策略，和一个学习在两条响应中挑更好的"相对主义批评家"。带平局选项的成对比较对训练稳定性至关重要。在 Countdown 上，RARO 达到 54.4% 准确率，对比使用 ground-truth 验证器的 RL 的 57.7%——而它并未使用验证器；对照组里 SFT 和迭代 DPO 无法超过 40.7%。学到的批评家还能兼任测试时重排器，在 7B 上把 DeepMath 从 57.5% 提升到 68.4%。

*作者：Locke Cai, Max Ryabinin, Ivan Provilkov*

论文：[arXiv:2511.21667](https://arxiv.org/abs/2511.21667)

论文 5

## V1: Unifying Generation and Self-Verification for Parallel Reasoners

+10%

Pass@1 · 相同算力

**最高多 10% 的正确答案，从你已经付费的生成中提取。** 收益来自更好的答案选择，不是更多算力。

当你采样大量答案又没有 oracle 时，给每个答案独立打分会失效——裁判几乎给所有答案 10 分，失去鉴别能力。V1 把"选择"重构为"比较"，用一个近线性复杂度的瑞士制锦标赛验证器。训练配方 V1-PairRL 教会单个模型同时生成并对自己的输出做两两验证，即使在测试时完全不做验证也能提升基础准确率。

*作者：Harman Singh, Xiuyu Li, Kusha Sareen, Monishwaran Maheswaran, Sijun Tan, Xiaoxia Wu, Junxiong Wang, Alpay Ariyak, Qingyang Wu, Samir Khaki, Rishabh Tiwari, Long Lian, Yucheng Lu, Boyi Li, Alane Suhr, Ben Athiwaratkun, Kurt Keutzer。合作者来自 UC Berkeley、NVIDIA 和 Mila。*

论文：[arXiv:2603.04304](https://arxiv.org/abs/2603.04304)

## When RL Meets Adaptive Speculative Training: A Unified Training-Serving System (Aurora)


随流量迁移

**在 MiniMax M2.1 229B、Qwen3-Coder-Next 80B 这样全新发布的前沿模型上 day-0 快 1.5 倍，并且随着流量迁移，在强大的静态推测器之上再多快 1.25 倍。** Day 0 就快、跑得越久越快的推测解码。

多数部署离线训练推测器然后冻结它，于是部署慢、且随流量与目标模型变化而过期。Aurora 把在线推测器学习重构为生产中运行的异步强化学习问题：被接受与被拒绝的 token 就是奖励信号，训练服务器持续更新推测器，新权重零停机热切换进服务器。

*作者：Junxiong Wang, Fengxiang Bie, Jisen Li, Zhongzhu Zhou, Zelei Shao, Yubo Wang, Yinghui Liu, Qingyang Wu, Avner May, Sri Yanamandra, Yineng Zhang, Ce Zhang, Tri Dao, Percy Liang, Ben Athiwaratkun, Shuaiwen Leon Song, Chenfeng Xu, Xiaoxia Wu。*

论文：[arXiv:2602.06932](https://arxiv.org/abs/2602.06932)

## Untied Ulysses: Memory-Efficient Context Parallelism via Headwise Chunking

5M tokens

单节点 · 约省 87.5% 内存

**在单个 8xH100 节点上训练 5M token 上下文，attention 内存最高减少 87.5%。** 不需要更大集群，也能在超长上下文训练。

attention 层内部的激活内存限制了长上下文训练，而加 GPU 移动不了这个天花板。UPipe 一次只处理少数几个 attention 头、跨阶段复用同一批缓冲区，在 32B Transformer 上把 attention 峰值内存削减最高 87.5%。结果是单节点 5M token——超出此前方法约 25%——以及双节点 8M token，同时匹敌它们的吞吐。它可以在同样的 FlashAttention-3 kernel 上即插即换 DeepSpeed-Ulysses，代码开源。

*作者：Ravi Ghadia, Maksim Abraham, Sergei Vorobyov, Max Ryabinin。*

论文：[arXiv:2602.21196](https://arxiv.org/abs/2602.21196)

论文 8

## Opportunistic Expert Activation: Batch-Aware Expert Routing for Faster Decode Without Retraining (OEA)

最高 39%

更快 MoE 解码

**MoE 解码延迟最多降 39%，不重训练、不改架构。** 你免费收回被批处理悄悄毁掉的稀疏性。

Mixture-of-Experts 模型本该便宜，因为每个 token 只碰少数几个专家；但一旦组批，稀疏性就坍塌：batch size 16 时，每个 token 只要八个专家的模型最终要加载约 82 个。OEA 的批感知路由在推理时分两阶段收回稀疏性，第二阶段让 token 复用批次已经加载好的专家，以零延迟代价买回质量。在 AIME24、GPQA、LiveCodeBench、MATH 500 上准确率保持平稳，且只有一个超参数要调。

*作者：Costin-Andrei Oncescu, Qingyang Wu, Wai Tong Chung, Robert Wu, Bryan Gopal, Junxiong Wang, Tri Dao, Ben Athiwaratkun。合作者来自 Harvard 和 Princeton。*

论文：[arXiv:2511.02237](https://arxiv.org/abs/2511.02237)

## ParallelKernelBench: Benchmarking LLMs on Multi-GPU Kernel Generation

87 个工作负载

多 GPU kernel 基准

我们构建了第一个面向多 GPU kernel 生成的基准。它包含 87 个真实分布式工作负载，而当今最好的前沿模型解决不到三分之一。

ParallelKernelBench 从 Megatron-LM、DeepSpeed、NeMo-RL、TensorRT-LLM 等生产代码库中提取 87 道题，横跨 12 种并行形态。每道题要求模型用利用 symmetric memory 做直接 NVLink 通信的 CUDA kernel 替换 PyTorch+NCCL 参考实现。Zero-shot 下，最好的模型通过 87 题中的 28 题。在带编译、正确性和性能反馈的 agentic 循环中，Gemini 3 Pro 从 24 题爬到 35 题，并在 26 题上击败 PyTorch 基线。有少数几题跑得比任何公开实现都快。单 GPU 代码生成正在被解决；多 GPU 才是崩坏之处，因为设定天花板的是通信，不是计算。

*作者：Willy Chan, Nathan Paek, Simon Guo, Simran Arora, Daniel Y. Fu。*

论文：https://www.alphaxiv.org/abs/2606.parallel-kernel-bench
