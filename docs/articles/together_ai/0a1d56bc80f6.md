## 摘要

Together Evaluations 现已支持 OpenAI、Anthropic 和 Google 模型做全面基准对比。任意模型并排比较——开源、微调或专有——基于质量、成本与性能做数据驱动的决策。

## Together Evaluations：评估模型质量

现代 LLM 开发由一套复杂的取舍定义：**质量、成本与性能**，横跨不断扩张的开源、专有与微调模型生态。**Together Evaluations** 提供一个统一框架，让团队能比较模型——开源、微调或专有——并基于经验质量数据做模型选型决策。

Together Evaluations 提供一个结构化、可复现的 LLM 质量评估框架，让团队能够：

- **并排比较模型：** 用同一套方法学与指标评估开源、微调与专有模型。
- **做数据驱动的架构决策：** 判断 prompt 优化还是微调能为特定任务带来最佳回报。
- **随时间跟踪质量改进：** 用可复现的自动评估监控模型质量的进展。

### 新增内容

今天我们很高兴宣布支持闭源前沿模型——包括 **OpenAI、Anthropic 和 Google** 的模型——作为严格跨模型基准的裁判（judge）与被评估目标（target）。

我们加入了这些呼声很高的能力：

### **1. 支持专有模型提供商**

Evaluations API 现在[支持](https://docs.together.ai/docs/evaluations-supported-models)领先专有提供商的模型，包括：用户也可以指定任何 OpenAI Chat Completions 兼容的 URL 来评估自托管的外部模型。

- **OpenAI** `openai/gpt-5` `openai/gpt-5.2`
- **Anthropic** `anthropic/claude-sonnet-4-5` `anthropic/claude-haiku-4-5` `anthropic/claude-opus-4-5`
- **Google** `google/gemini-2.5-pro` `google/gemini-2.5-flash`

#### **2. 支持评估 Together 微调模型**

用户现在可以直接在 Evaluations API 中评估用 [Together AI Fine-Tuning 服务](https://docs.together.ai/docs/fine-tuning-quickstart)微调的模型，使用两种部署选项之一：

- [LoRA serverless Inference](https://docs.together.ai/docs/adapter-upload)
- [Dedicated Endpoints for Inference](https://docs.together.ai/docs/dedicated-inference)

#### **3. 优化与评估开源模型的新配方**

- [深度解读](https://www.together.ai/blog/fine-tuning-open-llm-judges-to-outperform-gpt-5-2)和 [Cookbook](https://github.com/togethercomputer/together-cookbook/blob/main/Evals/Optimizing_LLM_Judges.ipynb)：展示如何用我们的平台微调超越 GPT-5.2 的开放模型裁判。在这个 notebook 里，我们演示如何用 DPO 在 RewardBench 2 偏好数据上微调开源 LLM 裁判（GPT-OSS 120B、Qwen3 235B），**作为评估者超过 GPT-5.2 的表现**——准确率 62.63% 对 GPT-5.2 的 61.62%。它提供一条端到端工作流，使用 Together AI 的 Evaluation 与 Fine-tuning API，展示开放模型如何以**低 10 倍的成本、快 15 倍的速度**击败闭源裁判。
- 我们在这个 [notebook](https://github.com/togethercomputer/together-cookbook/blob/main/Evals/GEPA_Optimization.ipynb) 中演示如何把我们的评估服务与流行的 GEPA 框架一起使用，自动优化 prompt、无需人工 prompt 工程。使用 CNN/DailyMail 数据集，GEPA 通过 LLM 引导的反思与两两对比评估，迭代精化一个基线摘要 prompt。这一过程把 prompt 的胜率从 50% 提升到 62.12%，展示自动 prompt 优化如何交付可观的质量增益。

## 分步指南

- **上传你的数据**，JSONL 或 CSV 格式
- **选择评估类型**：`classify`、`score` 或 `compare`
- **描述你要评估什么**：给裁判一个 Jinja2 格式的 `system_template`。你可以用如下 Jinja 模板引用数据集里的参考答案："Please use the reference answer: {{reference_answer_column_name}}"
- **配置被评估的模型：** 外部模型：设置 `model_source='external'` 并提供你的 API key。微调模型：从你的 LoRA serverless 部署或 Dedicated Inference endpoint 复制模型 ID。定义你的 `input_template` 以引用数据集中包含 prompt 的列。例如："Answer the following: {{prompt_column}}"
- **取回结果！** 我们同时提供聚合评估指标和一个包含裁判完整反馈的结果文件。

你可以用 [UI](https://api.together.ai/evaluations)、[API](https://docs.together.ai/reference/chat-completions-1) 或 [Python 客户端](https://github.com/togethercomputer/together-python)提交评估请求。完整文档在[这里](https://docs.together.ai/docs/ai-evaluations)。
