## 摘要

TorchForge RL 流水线现已运行在 Together AI 的 Instant Clusters 上，支持分布式训练与沙箱环境。本博客提供 TorchForge RL 流水线的演示，并给出面向更广泛应用场景的配置指引。这些能力将成为 Together AI 即将推出的 RL 服务的基础组件。

### AI Native Cloud 为下一代 RL 服务打下地基

构建灵活、可扩展的强化学习（RL）系统，需要彼此兼容且高效的算力、框架和工具链。现代 RL 流水线远不止简单的训练循环——它们依赖分布式 rollout、高吞吐推理、基于工具的环境、奖励评估器，以及 CPU 与 GPU 资源间的紧密协同。

今天，完整的 PyTorch 技术栈——包括 [TorchForge](https://pytorch.org/blog/introducing-torchforge/) 和 [Monarch](https://pytorch.org/blog/introducing-pytorch-monarch/)——已经在 [Together Instant Clusters](https://www.together.ai/instant-gpu-clusters) 上以分布式训练能力运行，后者提供：

- **低延迟 GPU 通信：** InfiniBand/NVLink 拓扑正合 TorchForge 与 Monarch 对基于 RDMA 的数据传输和分布式 actor 消息的要求。
- **一致的集群拉起：** Instant Clusters 启动时预配置好驱动、NCCL、CUDA 和 GPU operator，让 PyTorch 分布式作业（SPMD 或基于 Monarch）零手动设置即可运行。
- **异构 RL 负载调度：** GPU 节点服务 policy 副本与训练器，CPU 优化节点服务环境、工具执行和代码执行。

Together 集群天然契合那些混合 GPU 侧模型计算与 CPU 侧环境负载的 RL 框架。

很大比例的 RL 负载涉及调用工具、运行代码或与沙箱环境交互。Together AI 原生支持这些需求：

- [**Together CodeSandbox**](https://www.together.ai/blog/code-sandbox) → 完整的 microVM 环境，适合 tool-use、编码任务、仿真，以及无法在标准容器里运行的环境逻辑。
- [**Together Code Interpreter**](https://www.together.ai/blog/code-interpreter) → 快速、隔离的 Python 执行，非常适合单元测试式奖励函数或代码评估任务。

两者都与 [OpenEnv](https://huggingface.co/blog/openenv) 和 TorchForge 环境服务集成，让 rollout worker 在训练期间调用这些工具。

### 演示：在 Together Instant Clusters 上用 PyTorch 做 RL 训练

今天，我们发布一个演示：TorchForge RL 流水线运行在 Together Instant Clusters 上，并与托管在 Together CodeSandbox 上的 OpenEnv 环境交互。演示改编自 Meta 的[参考实现](https://github.com/meta-pytorch/OpenEnv/tree/main/examples/grpo_blackjack)，用 GRPO 训练一个 Qwen 1.5B 模型打 Blackjack（21 点）。该 RL 流水线集成 vLLM policy server、Blackjack 环境、reference 模型、off-policy 经验回放池和 TorchTitan 训练器——通过 Monarch 的 actor mesh 连接、使用 TorchStore 做权重同步。

OpenEnv GRPO BlackJack [仓库](https://github.com/togethercomputer/together-cookbook/tree/main/OpenEnv_GRPO_BlackJack)包含 Kubernetes manifests 和设置脚本。要部署并启动 RL 训练，只需运行[入门指南](https://github.com/togethercomputer/together-cookbook/blob/main/OpenEnv_GRPO_BlackJack/README.md)中的三条 kubectl 命令。你可以自由实验：通过配置文件换不同模型，调整 GRPO 超参数（如 KL 惩罚系数），或修改奖励函数鼓励新的打法策略。

我们还发布一个[独立集成](https://github.com/togethercomputer/together-cookbook/tree/main/OpenEnv_Code_Interpreter)，把 Together 的 Code Interpreter 包装为 OpenEnv 环境。这让 RL agent 可以像与任何其他环境交互一样与 Interpreter 交互——把代码片段作为动作发出、把执行输出作为观测接收、用自定义奖励为这些观测打分。结果是，同一套用于打游戏的 RL 流水线可以应用于编码任务、数学推理，或任何可以用代码表达的计算。

这些演示表明：复杂的多组件 RL 训练可以像在本地 GPU 上跑一个简单训练脚本一样，轻松运行在 Together AI Cloud 上。而这只是开始！我们正与 Meta 在这个基础上打造 PyTorch 生态中灵活的开放 RL 框架，并以可扩展、高性能的服务形态交付在 Together AI Cloud 上。我们很高兴继续这段旅程，并在推进强化学习前沿的过程中持续分享。敬请期待！
