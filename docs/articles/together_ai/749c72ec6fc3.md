# 训练后一起：前沿级模型塑造，适合你的方式

- 作者Ivan Provilkov、Gleb Khaykin、Denis Mazur、Nikita Smetanin、Egor Timofeev、Conner Manuel、Felix 张、Alex Mazitov、Jasmine Li、Gleb Vazhenin、Sergei Vorobyov、Qingyang Wu、Derek Petersen、Arseniy Belorukov、Artem Chumachenko、Aman Singhal、Alpay Ariyak、Jisen Li、Vladimir Malinovskii、Maksim Abraham、Zhongzhu Zhou、Denis Fedorenko、Sonny Khan、David Wang、Jennifer Wu、Max Ryabinin

我们正在推出 Together Post-Training，这是一项新服务，用于在我们的平台上构建自定义模型 - 包括通过 RL 的环境奖励和通过 SFT 的监督数据。该服务旨在为您提供灵活高效的模型塑造，而无需承担沉重的基础设施负担。

Together Post-Training 可以轻松定义训练循环，同时我们共同优化底层系统和基础设施，以提高模型质量和训练速度。现在没有什么可以阻挡您和“独一无二”的最佳模型。

## 定制模型的价值

到 2026 年，为 AI 工作负载训练自定义模型不再是一个小众话题。公司正在积极探索它以降低成本并提高特定任务的绩效。许多人工智能原生和人工智能前向组织不是通过上下文或利用工程来修复模型行为并提高其效率，而是培训专业代理，以一小部分成本和运行时间来匹配前沿模型的质量。最重要的是，自己训练模型可以带来更大的所有权和灵活性：生成的检查点可以部署在任何位置，进一步完善，甚至可以在本地使用。

在 Together，我们希望让每个人工智能开发人员能够尽可能方便地获得适合其任务的最佳模型。训练后一个优秀的模型需要对数据管理、训练算法和评估协议进行多次迭代。最重要的是，强化学习的基础设施变得越来越复杂，“效率优化”和“阻碍运行的无声错误”之间只有一线之隔。对于大型模型来说，可靠且大规模地这样做会带来一系列挑战。

前沿实验室有整个团队来解决上述每个问题。由于同时应对所有挑战是一项巨大的投资，因此许多可以从后期培训中受益的公司却从未开始，或者开始后就停滞不前。培训后一起处理所有优化和基础设施，而不会妨碍我们，我们的前沿部署团队与客户合作，帮助完成端到端工作流程。这让每个研究人员或领域专家都可以专注于他们最擅长的事情，而我们则负责其余的事情。

## Together 培训后概览

随着后期培训的复杂性不断发展，围绕它的工具也应该不断发展。 Together Post-Training 提供了一组 ML 开发人员熟悉的通用抽象，以及对每个实验使用的资源的控制，同时确保幕后的所有计算快速、经济高效，而且最重要的是正确。

我们的服务旨在为您的实验提供最高程度的灵活性。您可以运行 LoRA 训练，包括共享相同 GPU 容量的多个 LoRA 适配器，以及针对选定模型的全权重实验。与我们的[微调服务](https://www.together.ai/fine-tuning) 相比，Together Post-Training 的整个训练循环由您定义。您可以使用最适合您的设置的任何数据、环境或代理工具，并在整个训练过程中添加您需要的任何步骤（例如日志记录或外部基准测试）。整个工作流程如下：

![](https://cdn.prod.website-files.com/69654e88dce9154b5f12070c/6ad63421bade9a234b1c05a1_6ad6340765d98d48127a6d24_post-training-workflow-overview.png)

*使用 Together Post-Training 的高级总结。左：用户端执行的命令，右：Together 端运行的服务组件。*

所有实验都在模型资源上运行——完全属于您的 GPU 分配，不会与其他人的优先级请求竞争。每个模型资源可以举办一个或多个培训课程，其中每个培训课程对应于使用相同基础模型（例如，一组 LoRA 适配器）的单个实验。这意味着您可以获得最佳的部署和训练性能，因为您永远不必与在同一硬件上执行的其他用户的请求竞争。同时，专用 GPU 分配意味着您可以运行全权重微调，在适应大型知识密集型任务时超越 LoRA。

分配模型资源并启动会话后，您可以执行训练循环的每个步骤。每个会话都包含一个负责运行前向/后向步骤并更新权重的 Trainer 实例，以及用于执行策略推出的 Generator 实例。对于每个模型，我们都大力优化训练和部署性能，确保所有操作快速且跨堆栈进行数字对齐。对于SFT，您可以使用0个生成器启动模型资源以节省成本。您决定将训练器参数发送到生成器的点；我们还支持异步 RL，以便始终保持两个组件的高 GPU 利用率，尤其是在长时间代理部署的情况下。

虽然我们支持许多标准损失（从交叉熵和 GRPO 到 CISPO 和 DPPO），但我们还允许在本地计算自定义训练目标并将其梯度发送到训练器以计算更新。

![](https://cdn.prod.website-files.com/69654e88dce9154b5f12070c/6ad63420bade9a234b1c0599_6ad63405c21d46af1248bce7_post-training-custom-loss-example.png)

*使用自定义损失进行训练的示例*[*Together Post-Training 文档*](https://docs.together.ai/docs/post-training/custom-loss-functions)

Together Post-Training 推出了一系列领先的开放重量模型，包括 Muse Spark Open、GLM 5.3、Kimi K3 和 Qwen 3.8-27B。我们将在未来几周内扩大选择范围，确保您既可以使用能力最高的前沿法学硕士，也可以使用高效的小型模型。

## 质量、性能和效率

授权培训后基础设施的内部可能是一个令人畏惧的决定。我们的团队拥有捕捉复杂机器学习系统中无声错误的第一手经验，从推动强化学习研究的前沿到培训已为数百万用户提供服务的法学硕士。我们知道，**最好的训练堆栈能够为您提供最好的模型**，而构建此类基础设施需要跨所有组件进行仔细的实施和共同设计。

出于这些原因，我们将输出模型的质量作为服务开发中的北极星。影响 RL 结果的问题的一个臭名昭著的例子是训练和推理引擎之间的一致性：如果相同的模型权重由于数字不匹配而产生略有不同的输出，则整个运行可能会表现不佳甚至崩溃。我们使用 [Rollout Routing Replay](https://arxiv.org/abs/2510.11370) 等标准技术以及由我们对训练稳定性的研究驱动的高级优化，消除了训练和推理过程中的众多策略漂移来源。

除了模型质量之外，我们还努力使每次运行尽可能快速和高效，因为训练后需要多次迭代：运行越早完成，成本越低，您可以测试的想法就越多。强化学习的大部分时间都花在生成部署上，这使我们能够利用 Together 推理产品背后多年的研究和工程经验。我们的推出引擎采用与我们的服务堆栈相同的优化。对于多轮代理，智能缓存和路由可以最大限度地减少冗余计算，同时保持内存成本有限。在训练方面，优化的并行性和序列打包加速了 SFT 和 RL 步骤。

通过 Together Post-Training，您可以根据需要调整每次实验的规模，而无需支付更多费用。如果您的实验因部署并发性而出现瓶颈，您可以请求确切数量的采样器副本。多个 LoRA 实验可以共享一个模型资源，因此运行扫描并不意味着为每个设置保留更多 GPU。我们按 GPU 分钟对每个模型资源进行计费，但由于我们的专用和多 LoRA 服务堆栈的许多优化，一旦扩大实验规模，训练的总体成本就会低于基于令牌的定价。

## 训练后优化部署

训练后实验完成后，并排运行每个结果模型以比较它们的输出可能很重要。我们现在在专用模型推理中支持[多 LoRA 适配器服务](https://docs.together.ai/docs/post-training/multi-lora-deployment)：您可以在单个 GPU 部署中方便地交换适配器，而不是为每次运行启动单独的生产部署，从而帮助您降低服务成本。

![](https://cdn.prod.website-files.com/69654e88dce9154b5f12070c/6ad63420bade9a234b1c059e_6ad63406492c6c1fe7742748_post-training-train-evaluate-serve.png)

最后，将模型转换为在生产中以最高吞吐量运行意味着与推出一代相比，它可能以较低的精度、不同的硬件配置和不同的内核执行。通过算法和系统改进的结合，我们确保每个训练检查点保持服务质量，即使在从多 LoRA 采样切换到完全高性能的 [FP4 精度的合并推理](https://docs.together.ai/docs/post-training/prepare-for-fp4-inference)之后也是如此。

## 开始使用

要开始首次训练后实验，请安装最新的 [Together SDK](https://github.com/togethercomputer/together-py) 并[阅读文档](https://docs.together.ai/docs/post-training/overview)。我们还提供了一系列食谱，可以帮助您开始使用 Together Post-Training，这些食谱可在 [github.com/togethercomputer/post-training-cookbook](https://github.com/togethercomputer/post-training-cookbook) 上找到。这些食谱提供了在标准 GSM8K 基准上使用 GRPO 进行训练、将 DPO 实现为自定义损失或在同一模型资源中训练多个 LoRA 适配器的示例。如果您已经拥有使用 Tinker API 等培训后服务的设置，我们还提供了一种简单的迁移方法。您可以替换脚本中的一行，其他所有内容都可以保持不变：
```
-import tinker
+import together.post_training.tinker as tinker
```
请阅读我们的 [Tinker 迁移指南](https://docs.together.ai/docs/post-training/migrate-from-tinker) 了解更多信息。
