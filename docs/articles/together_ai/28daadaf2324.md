# ATLAS（自适应学习推测系统）：以运行时学习加速器和推测系统开创 LLM 推理新范式

ATLAS 带来最高 4 倍的 LLM 推理加速，由 Together Turbo 的最新研究驱动。

在 Together AI——AI Native Cloud——我们对性能有着执念。让大语言模型更快、更便宜、更高效不是一个单点技巧问题，它需要在多个维度上同时优化。这正是 **Together Turbo** 背后的理念：一个由算法、架构和建模配方研究驱动的推理创新套件。我们很高兴推出自适应学习推测系统（AdapTive-LeArning Speculator System，ATLAS）——首个同类型的推测器（speculator），无需任何人工调优即可自动获得性能提升。

ATLAS 提供了一种做推测解码（speculative decoding）的新方式——在运行时动态自我改进——并且能与我们的其他 Turbo 技术无缝并行使用，例如专有的 [Together Turbo Speculator](https://www.together.ai/blog/fastest-inference-for-deepseek-r1-0528-with-nvidia-hgx-b200) 或 [Custom Speculators](https://www.together.ai/blog/customized-speculative-decoding)。但为什么要做一个自适应学习推测系统？

标准推测器是为通用工作负载训练的。定制推测器在你的专属数据上训练，但只对应某个特定时间点的快照。然而，随着工作负载演化（代码库增长、流量模式迁移、请求分布变化），即使是高度定制的推测器也可能落后。相比之下，ATLAS 随使用自动演化，同时从历史模式和实时流量中学习，持续实时对齐目标模型的行为。这意味着你越是用我们的推理服务，ATLAS 的表现就越好！

ATLAS 构建在 Together Turbo Speculator 之上，在完全适配的场景下，[DeepSeek-V3.1](https://artificialanalysis.ai/models/deepseek-v3-1/providers#output-speed) 上最高达到 500 TPS，[Kimi-K2](https://artificialanalysis.ai/models/kimi-k2-0905/providers#output-speed) 上最高达到 460 TPS——比标准解码快 2.65 倍，甚至超越了 Groq 等专用硬件（图 1）。

## **1. 推测解码**

推测解码是加速推理最有力的杠杆之一。2 与其让目标模型逐 token 生成，不如由一个更快的**推测器（speculator，也称 draft model 草稿模型）**提前提出多个 token，目标模型在单次前向传播中并行*验证*它们。验证过程保证输出质量与非推测解码的分布一致，同时通过一次接受多个 token 实现加速。

整体速度受接受率 α（即目标模型与推测器草稿 token 一致的比例）以及草稿相对于目标模型的延迟比 c 影响。通常，参数量更大的推测器容量更高、接受率更高，但生成草稿 token 更慢。因此进展来自两个方向：对齐草稿模型与目标模型以提高 α（训练目标、数据和算法），以及设计在保持 α 的同时压低 c 的草稿模型/kernel（稀疏化、量化、轻量且 kernel 高效的架构）。最佳点在于高 α 遇上低 c，使端到端延迟最小化。

接受率（α）0.85，草稿速度（c）0.100

图 2：推测解码的交互式加速计算器。不同的优化技术影响接受率或草稿延迟，形成一个为最大化加速而竞争的复杂优化空间。最优前瞻步数（γ）本身也随模型配置而变——强的推测器（高 α、低 c）能从更长的前瞻中持续获益（γ = 5+），而弱的配置（低 α、高 c）很早便进入平台期（γ = 3-4）。

在 Together AI，Turbo 团队开发了高性能推测器，借鉴架构、稀疏化、算法、后训练配方和数据方面的多项进展 [1-9]，达成了 [**NVIDIA Blackwell 上全球最快的解码速度**](https://www.together.ai/blog/fastest-inference-for-deepseek-r1-0528-with-nvidia-hgx-b200)。我们构建了**推测器设计与选择框架**，用于确定最优的推测器架构（宽度/深度、前瞻步数、稀疏化/量化、KV 复用），以及**可扩展的训练系统**，能够快速、可复现地为最大、最有挑战的开源目标模型训练推测器（如 DeepSeek-V3.1 和 Kimi-K2）。例如，Kimi 发布时没有现成的推测器，我们可以快速训练并部署一个，在同一硬件和批设置下把 Kimi 从开箱约 150 TPS 提到 270+ TPS，同时保持目标模型的质量（见图 1 黄条）。这条流水线支撑起提供业界领先解码延迟的 Turbo Speculators，也为下一步奠定基础：**一个能实时按工作负载调整 token 起草的自适应学习推测系统**。

## **2. Turbo 的自适应学习推测系统登场**

在 Together AI，我们支撑着广泛多样的推理工作负载。但今天的推测解码方法受限于**静态**推测器——在固定数据集上训练。一旦部署，推测器无法再适应，当输入分布演化时性能就会下降。这个问题在 serverless、多租户环境中尤其突出，因为那里输入多样性极高。新用户源源不断到来，带来固定推测器在训练时可能从未见过的独特工作负载。此外，这些推测器通常使用*固定的前瞻步数*，无论推测器置信度如何都预测相同数量的 token。简言之，*静态推测器跟不上节奏*。

图 3：两个推测器——一个静态、一个自适应——与一个置信度感知的控制器协作，控制器在两者之间做选择并调整前瞻步数，以获得最佳准确率和速度。

为解决这些限制，我们设计了带两个协作推测器的**自适应学习推测系统**，如图 3 所示：

- **一个重型*静态*推测器**，在广泛语料上训练，提供强劲、通用的推测能力。
- **一个轻量*自适应*推测器**，支持来自实时流量的快速、低开销更新，即时专精于新兴领域。
- 一个**置信度感知控制器**，在每一步决定信任哪个推测器、使用怎样的推测前瞻步数——当推测器置信度高时使用更长的推测。

**通过静态推测器提供效率护栏。**静态 Turbo Speculator 充当一条始终在线的速度底线：它在广泛语料上训练、跨工作负载保持稳定，因此当流量迁移或自适应路径尚冷时 TPS 不会崩落。在 ATLAS 中，我们用它来快速起步提速并提供兜底回退——一旦置信度下降或检测到漂移，控制器会缩短前瞻步数或路由回静态路径，在自适应推测器重新学习期间保住延迟。

**定制推测器 vs. 自适应学习。**我们此前的研究表明，在反映预期用量的真实流量样本上训练的[定制推测器](https://www.together.ai/blog/customized-speculative-decoding)能带来额外的速度提升。自适应学习推测器让我们得以实时实现更高程度的定制。例如，在一次 vibe-coding 会话中，自适应系统可以为正在编辑、训练时未见过的相关代码文件特化一个轻量推测器，进一步提升接受率和解码速度。这种即时专精是静态推测器难以做到的。

**加速 RL 训练。**强化学习（RL）在两个阶段之间交替：(1) rollout 阶段，当前策略生成轨迹并获得奖励；(2) 更新阶段，用奖励更新策略。实践中，rollout 往往是瓶颈，约占总墙钟时间的 70%3。一般来说，由于策略分布在训练过程中持续移动，静态推测器会很快与目标策略失去对齐，导致吞吐不理想。4 ATLAS 通过在线适应演化的策略和具体的 RL 领域来解决这一点，保持对齐并缩短整体 rollout 时间。RL 的领域特定、迭代式特性进一步促成快速适应，带来持续且不断增长的速度提升。如图 4 所示，把 ATLAS 应用于 RL-MATH 流水线，速度提升随训练推进不断增大。

图 4：我们在 NVIDIA Hopper H100 GPU 上使用 ATLAS 对 Qwen/Qwen2.5-7B-Instruct-1M 在 DeepScaler 子集上进行 RL 训练。接受率在 1.4k 个训练步内从低于 10% 升至 80% 以上，在不改变 RL 训练算法的情况下，整体训练时间缩短超过 60%。

**作为 Turbo 优化套件的一部分构建。**自适应学习推测系统是更广泛 Turbo 优化套件的核心组件，其中每一层优化都会叠加放大其他层的收益。如图 5 所示，性能经由近无损量化（经校准以保质量）、Turbo Speculator，直至自适应学习推测系统逐级提升。套件中的其他优化还包括用于降低首 token 延迟的 TurboBoost-TTFT（图中未展示），进一步贡献端到端加速。

图 5：Together Turbo 优化套件各层的性能收益，展示从原始 FP8 DeepSeek 基线（105 TPS）到自适应学习推测系统（501 TPS）的逐级速度提升。实验基于 NVIDIA HGX B200、batch-size 1，细节同图 1。

**极限峰值效率。**当输入分布狭窄、输出紧密复现此前见过的 token 时，自适应系统会迅速专精。在此场景下，控制器更有信心更多地利用轻量推测器的输出并加长前瞻 token，从而维持比静态或一次性定制推测器更高、更稳定的 TPS。如图 1 和图 5 所示，一旦完全适配 Arena-Hard 流量，DeepSeek 在 4 块 B200 GPU、batch size 1 下达到每秒 500 token，相较 FP8 基线提速 400%（从 105 TPS 提升到 501 TPS）。
