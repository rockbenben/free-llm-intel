TL;DR

- 📚 **迁移指南：** 我们发布了详细的 [**Python SDK 迁移指南**](https://docs.together.ai/docs/pythonv2-migration-guide)，覆盖逐个 API 的变化、类型更新和排障提示。
- 🧑‍💻 代码与文档：你可以访问 [Together Python v2](https://github.com/togethercomputer/together-py) 仓库，并参考带代码示例的[参考文档](https://docs.together.ai/reference/chat-completions-1)。
- 🎯 **主要目标：** 用一个现代的、强类型的、OpenAPI 生成的客户端取代遗留 v1 Python SDK——更贴近 API 面、与新特性保持同步。
- ✨ **全新内容：** 所有新功能今后都将构建在 v2 上。首个版本已包含我们 Instant Clusters 的 beta API！

今天，我们发布 [**Python SDK v2.0 Release Candidate**](https://pypi.org/project/together/2.0.0a9/)——一个为 Together API 新做的、类型安全的、OpenAPI 驱动的客户端，设计目标：更快、更易维护、为我们接下来构建的一切做好准备。

## **为什么需要新的 Python SDK？**

核心原因：

- **现代架构**
新 SDK 由我们的 [**OpenAPI**](https://github.com/togethercomputer/openapi) 规范经 **Stainless** 生成，给你与我们 API 更贴近 1:1 的映射、更少的边角不一致，以及一条让我们快速交付新功能的路径。
- **更好的类型安全与 DX**
SDK 为 Python 带来"TypeScript 风格"的类型，包括类型化参数、响应，以及 chat 消息与 eval 参数的辅助类型。这让构建大型代码库更有信心、编辑器支持更好。
- **面向未来、功能优先**
活跃开发与新 API 特性会最先落地 v2。RC 期结束后，v1 转入维护、随后弃用。
- **`uv` 支持**
兼容快速 Python 包安装器 [uv](https://github.com/astral-sh/uv)——`uv add together`
- **现代 HTTP 客户端与性能**
底层上，新 SDK 使用 [**`httpx`**](https://github.com/encode/httpx) 而非 [**`requests`**](https://github.com/psf/requests)，有更好的超时与连接处理，在我们的基准中平均每请求**快约 20ms**。

## **起步**

#### **1. 安装 RC**

```
    
    # 安装 Together Python SDK
    uv add together

    # pip 同样可用
    pip install together
    
```

#### **2. 浏览迁移指南**

从 [**Python SDK 迁移指南**](https://docs.together.ai/docs/pythonv2-migration-guide) 开始了解概览、[逐 API 说明](https://docs.together.ai/reference/chat-completions-1)与代码片段、[破坏性变更](https://docs.together.ai/docs/pythonv2-migration-guide#global-breaking-changes)、[新错误处理](https://docs.together.ai/docs/pythonv2-migration-guide#error-handling-migration)等。

指南还包含一个 [**Feature Parity Matrix**](https://docs.together.ai/docs/pythonv2-migration-guide#feature-parity-matrix)，把 API 分为：

- ✅ **容易迁移：** Chat、completions、embeddings、images、models、audio 转录/翻译、多数 fine-tuning 流程。
- ⚠️ **中等投入：** Files、fine-tuning checkpoints/下载、batches、endpoints、evals、code interpreter、部分 audio speech 变化。
- 🆕 **新能力：** Jobs API、Hardware API、增强 evals、code interpreter 会话、raw response 辅助方法。

## **需要知道的破坏性变更要点**

细节在迁移指南的 [**Breaking Changes**](https://docs.together.ai/docs/pythonv2-migration-guide#global-breaking-changes) 一节，但以下是测试 RC 时需要记住的要点。

- **构造参数**
supplied_headers → default_headers；新可选参数：default_query、http_client、_strict_response_validation
- **错误处理**
`TogetherException` 类内部方法与属性有变化；若干旧异常被移除或并入 `APIStatusError`/具体 HTTP 状态类
- **参数**
**不再支持位置参数**——所有调用必须用关键字参数；`**kwargs` 被显式的 `extra_headers, extra_query, extra_body, timeout` 取代
- **类型**
`together.types.*` 中许多响应类型名已变化

### **Files**

- `client.files.retrieve_content(...)` 移除
- 改用 `client.files.content(file_id)`；它返回流式二进制响应，**默认不再写入磁盘**

### **Batches**

- 方法改名：`create_batch` → `create`；`get_batch` → `retrieve`；`list_batches` → `list`；`cancel_batch` → `cancel`
- 参数变化：`file_id` → `input_file_id`
- 响应变化：`create` 现在返回完整 API 响应；你自己访问 `.job`

### **Endpoints**

- `client.endpoints.get(...)` → `client.endpoints.retrieve(...)`
- `min_replicas / max_replicas` 现在在 `create` 中嵌套于 `autoscaling` 参数下
- 列表方法（`list`、`list_avzones`）现在返回对象包装而非裸数组

### **Evals**

- 命名空间变化：`client.evaluation` → `client.evals`
- `evals.create` 现在接受强类型 parameters 对象（如 `ParametersEvaluationClassifyParameters`），不再是松散的字典

### **Audio Speech**

- 新增 `client.audio.speech.with_streaming_response.create(...)` 方法用于流式输出音频

### **Code Interpreter**

- `client.code_interpreter.run(...)` → `client.code_interpreter.execute(...)`
- 结果结构与会话有更新（`result.data.outputs[0].data`、`client.code_interpreter.sessions.list()`）

- 一些遗留 CLI 命令（如 `chat.completions`、`completions`、`images generate`）在 v2 中被移除或重塑

## **2.0 版本里有什么？**

### **"开箱即用"的 API（无需改代码）**

对多数常见负载，你可以几乎不改代码就升级。以下 API 在 v1 与 v2 之间实质 drop-in 兼容：

- `client.chat.completions.create`
- `client.completions.create`
- `client.embeddings.create`
- `client.images.generate`
- `client.rerank.create`
- `client.fine_tuning.create / list / retrieve / cancel`
- `client.models.list`

如果你的应用主要围绕调用模型、流式结果、生成图像、转录，可能再加微调，迁移应该是顺畅的。你可以看看新的[错误模型](https://docs.together.ai/docs/pythonv2-migration-guide#error-handling-migration)和[破坏性变更一节](https://docs.together.ai/docs/pythonv2-migration-guide#global-breaking-changes)。

### **有一些变化的 API**

其他 API 在 RC 中**可用，但签名或响应形状更新**：

- Files（`client.files.*`）
- Batches（`client.batches.*`）
- Speech（`client.audio.speech.*`）
- Transcriptions/Translations（`client.audio.translations.*`）
- Endpoints（`client.endpoints.*`）
- Evals（`client.evals.*`，此前为 client.evaluation）
- Code Interpreter（`client.code_interpreter.*`）
- 部分 Fine-tuning 与 Models 辅助方法

这些在[迁移指南的这一节](https://docs.together.ai/docs/pythonv2-migration-guide#apis-with-changes-required)中详细说明。

### **新 SDK 专属 API**

RC 还引入了旧 SDK 中从未存在的**全新特性**：

- **Beta API（`client.beta.clusters.*`）**——新功能正在开发并以 beta 提供，比如我们的 Instant Clusters
- **Raw response 与流式辅助方法**——用于调试、观测与细粒度控制

### **Python SDK v2 的全新特性**

#### 1. 新错误模型

错误层级被彻底重设计，**更精确、更可预测**。

遗留（v1）：

- 基类：`TogetherException`
- 一堆混合异常，如 `ResponseError`、`JSONError`、`InstanceError`、`Timeout`、`InvalidRequestError` 等。

新（v2）：

- 基类：`TogetherError`（取代 `TogetherException`）
- HTTP 错误：`APIStatusError` 加具体状态码类：`BadRequestError (400)`、`AuthenticationError (401)`、`PermissionDeniedError (403)`、`NotFoundError (404)`、`ConflictError (409)`、`UnprocessableEntityError (422)`、`RateLimitError (429)`、`InternalServerError (5xx)`
- 传输与超时：`APIConnectionError`、`APITimeoutError`（取代 `Timeout`）
- 校验：`APIResponseValidationError`
- 领域特定：`FileTypeError`、`DownloadError`（新模块路径）。

#### 2. 现代参数与类型系统

新 SDK 大力投入**仅关键字参数与显式可选语义**：

- 所有 API 方法使用**仅关键字参数**，不再支持位置参数。
- 可选参数使用 **`NOT_GIVEN` 哨兵**（及其代表的"omit"行为），不再重载 `None`。
- "Extra" 参数这样传：extra_headers、extra_query、extra_body、timeout

通过 `together.types.*` 你还能获得更丰富的消息与响应类型。

#### 3. Raw response 与流式辅助方法

你现在可以轻松访问**原始 HTTP 响应**，或用**带上下文管理器的流式**：

Raw response：

```
    
    response = client.chat.completions.with_raw_response.create(
        model="meta-llama/Meta-Llama-3.1-8B-Instruct-Turbo",
        messages=[{"role": "user", "content": "Hello"}],
    )

    print(response.status_code)
    print(response.headers)
    completion = response.parse()
    
```

带上下文管理器的流式：

```
    
    with client.chat.completions.with_streaming_response.create(
        model="meta-llama/Meta-Llama-3.1-8B-Instruct-Turbo",
        messages=[{"role": "user", "content": "Write a story"}],
        stream=True,
    ) as stream:
        for line in stream.iter_lines():
            print(line)
    
```

#### 4. Code Interpreter 会话

新 SDK 暴露 **Code Interpreter 的会话管理**：

```
    
    result = client.code_interpreter.execute(
        code="print('Hello, world!')",
        language="python",
    )

    print("Output:", result.data.outputs[0].data)

    sessions = client.code_interpreter.sessions.list()
    for session in sessions.data.sessions:
        print("Session:", session.id)
    
```
