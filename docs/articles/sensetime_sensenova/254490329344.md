## 🚀 SenseNova-Loop-9B：以更少参数实现更深计算

我们正式发布 SenseNova-Loop-9B。在 Preview 对参数效率探索的基础上，该模型通过循环架构复用层权重，并结合流形约束超连接（manifold-constrained hyper-connections，mHC），在紧凑的参数预算内扩展计算深度。它面向复杂推理、编程、工具使用和多模态任务设计。

自 Preview 发布以来，我们收到了社区在模型使用、推理部署和生态集成方面的关注与反馈。正式版本保留循环架构和双流 mHC，进一步提升智能体、编程和数据分析任务上的性能，同时继续探索循环计算的能力。

SenseNova-Loop-9B 拥有约 9B 参数。通过重复执行共享中间层，它将 32 个物理解码器层扩展为 56 次层执行。该模型接受文本和图像输入并生成文本，支持长上下文理解和多步任务。在智能体和数据分析评测中，该模型与 Qwen3.8-27B 具有竞争力：在 NL2Repo 上得分为 41.36 对 44.60，在 AIDABench 上为 65.31 对 65.01。

### 模型亮点

- **共享循环块：** 24 个解码器层按顺序执行两次，每次前向传播由 32 个不同层产生 56 次层计算。
- **双流 mHC：** 学习到的映射在循环块内的两个残差流之间路由并组合信息。
- **混合注意力：** 解码器以重复的四层模式交替使用线性注意力和全注意力。
- **长上下文多模态训练：** 训练方案包含文本、图像、代码和工具使用轨迹，上下文长度扩展至 512K tokens。
- **低内存部署：** 使用 4-bit 权重和 8-bit KV 缓存时，256K 上下文长度的多模态推理大约需要 15 GiB GPU 内存。
- **官方量化发布：** 发布当天提供官方 AWQ 4-bit 版本，便于部署。

## 🧠 模型架构

SenseNova-Loop-9B 基于 32 层多模态解码器构建，结合共享权重循环计算、混合注意力和双流流形约束超连接（mHC）。它通过复用中间层参数扩展计算深度，接受文本和图像输入，生成文本，并支持最长 512K tokens 的上下文长度。

### 模型规格

| 属性 | SenseNova-Loop-9B |
| --- | --- |
| 架构 | 自回归多模态解码器；带双流 mHC 的循环块 |
| 参数规模 | 总参数约 9B；推理等效参数约 14.6B |
| 输入 / 输出 | 文本和图像 / 文本 |
| 不同解码器层数 | 32 |
| 循环层范围 / 循环次数 | [4, 28) / 2，权重共享 |
| 解码器层执行次数 | 每次前向传播 56 次 |
| mHC 残差流数量 | 2 |
| 上下文长度 | 512K tokens |
| 权重精度 | BF16 主干；FP32 mHC 路由参数 |

### 循环解码器

输入首先经过第 0–3 层，然后两次经过相同的第 4–27 层块，最后经过第 28–31 层和输出头。若 B 表示循环块，h 表示其输入，则循环计算可写为 B(B(h))。

推理期间，每次前向传播执行 56 次解码器层计算，但仅存储 32 组解码器层权重。循环块在两遍中共享相同权重，第一遍的输出作为第二遍的输入。

### 混合注意力

解码器交替使用线性注意力和全注意力。每组四层包含三个线性注意力层，后接一个全注意力层。循环边界与完整的四层组对齐，因此两遍均保持相同的注意力模式。

### 双流 mHC

在循环块内，mHC 使用两个残差流在解码器层计算周围传递信息。学习到的映射决定每一层如何从这些流中读取、如何在它们之间混合信息，以及如何将其输出写回残差状态。流混合映射通过 Sinkhorn 归一化进行约束，在模型配置中使用 20 次迭代。

这两个流可视为并行携带的两组隐藏状态。循环层从这些流中读取，应用注意力或前馈计算，然后将其输出写回。重复的行归一化和列归一化约束信息在流之间的混合方式。这 20 次归一化迭代是 mHC 的内部操作，与循环块的两遍计算相互独立。

循环范围、循环次数和 mHC 路由参数共同定义检查点的执行配置。兼容的推理实现必须加载这些参数，并保持相同的计算顺序。

| 配置 | 值 |
| --- | --- |
| 不同解码器层数 / 执行次数 | 32 / 56 |
| 循环层范围 / 循环次数 | [4, 28) / 2 |
| 隐藏维度 | 4,096 |
| 前馈维度 | 12,288 |
| 词表大小 | 248,320 |
| 全注意力头数 / KV 头数 | 16 / 4 |
| mHC 残差流数量 / Sinkhorn 迭代次数 | 2 / 20 |

## 🔬 循环扩展：探索循环计算的优势

[![循环扩展：在四项基准上匹配训练和推理循环次数](https://huggingface.co/sensenova/SenseNova-Loop-9B/media/main/assets/loop_scaling_zh_latest.png)](https://huggingface.co/sensenova/SenseNova-Loop-9B/blob/main/assets/loop_scaling_zh_latest.png)

循环 Transformer 展现出有前景的性能扩展性，为通过重复计算扩展模型能力提供了另一种方式。我们以采用标准单次前向传播（Loop 1）的原始 9B 模型为基线，在保持训练数据和其他设置不变的情况下改变循环次数。四项任务的总体性能均有提升，在三或四次循环时取得最佳结果。AIDABench-QA 和 Workbuddy-office 在三次循环时达到峰值，相对于基线分别提升 6.42% 和 16.93%；LiveCodeBench V6 和 AIDABench 数据可视化在四次循环时达到峰值，分别提升 8.10% 和 8.55%。

为平衡推理效率，Preview 和正式版默认均使用两次循环。不过，更深的循环带来进一步提升：从两次循环增加到四次循环，LiveCodeBench V6 提升 1.04 个百分点，AIDABench 数据可视化提升 1.35 个百分点。这些实验覆盖一至四次循环，更深层循环的潜力仍有待进一步研究。

不同任务对循环深度的响应不同。我们将继续探索更深层计算，以及根据每个输入调整循环次数的 Dynamic Loop 架构，从而按任务复杂度分配计算。

## 💾 低内存部署

共享循环架构使用约 9B 个不同参数。采用 4-bit 权重量化后，模型权重占用约 4.9 GB。使用 8-bit 或 4-bit KV 缓存可进一步降低长上下文推理的内存需求。部署所需的最低 GPU 内存估计如下：

| 上下文长度 | 8-bit KV 缓存 | 4-bit KV 缓存 |
| --- | --- | --- |
| 64K | ~10 GiB | ~9 GiB |
| 128K | ~12 GiB | ~10 GiB |
| 256K | ~15 GiB | ~12 GiB |

### 使用 Transformers 进行文本生成

使用 Transformers 从 Hugging Face 仓库或本地模型目录加载模型。以下示例涵盖单 GPU 文本生成以及使用推理引擎进行服务化部署。

#### 环境要求

已验证的 Preview 环境使用 Transformers 5.18.0、PyTorch 2.11.0 和 CUDA 13.0。模型目录必须包含配置、分词器、聊天模板、自定义模型代码以及所有权重分片。

首先安装兼容 CUDA 的 [PyTorch](https://pytorch.org/get-started/locally/) 构建，然后安装其余依赖：

```
python -m pip install "transformers==5.18.0" accelerate safetensors
```

将 model_id 设置为正式版模型目录或仓库 ID，然后运行：

```
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "/path/to/SenseNova-Loop-9B"
device = "cuda:0"

tokenizer = AutoTokenizer.from_pretrained(model_id, trust_remote_code=True)
model = AutoModelForCausalLM.from_pretrained(
    model_id,
    trust_remote_code=True,
    dtype=torch.bfloat16,
    device_map={"": device},
).eval()

messages = [{"role": "user", "content": "What is 13 times 7?"}]
prompt = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True,
    enable_thinking=True,
)
inputs = tokenizer(prompt, return_tensors="pt").to(device)
with torch.inference_mode():
    outputs = model.generate(
        **inputs,
        max_new_tokens=512,
        do_sample=False,
        use_cache=True,
    )
response = tokenizer.decode(
    outputs[0, inputs.input_ids.shape[1]:],
    skip_special_tokens=True,
)
print(response)
```

该示例启用思考模式，使用贪心解码，并最多生成 512 个新 tokens。将 enable_thinking 设为 False 可禁用思考，或更改 device 以选择 GPU。trust_remote_code=True 加载自定义 SenseNova Loop 模型实现。

### 部署

以下命令改编自 Preview 部署示例。请将模型路径替换为正式版检查点目录；正式版引擎版本和配置将随模型更新。

#### LightLLM

四 GPU 部署示例：

```
docker pull ghcr.io/modeltc/lightllm:main

docker run --rm --gpus all --ipc=host -p 8000:8000 \
  -v /path/to/SenseNova-Loop-9B:/model \
  -e LOADWORKER=4 -e LIGHTLLM_TRITON_AUTOTUNE_LEVEL=1 \
  ghcr.io/modeltc/lightllm:main \
  python -m lightllm.server.api_server \
    --model_dir /model --model_name SenseNova-Loop-9B \
    --tp 4 --host 0.0.0.0 --port 8000
```

## ⚠️ 已知限制

鉴于其规模和开发时间，SenseNova-Loop-9B 在以下方面仍有改进空间：

- **复杂指令遵循：** 当给定许多复杂工具定义或多重约束时，模型可能误解或遗漏需求。
- **编程和通用智能体任务：** 在编程和通用智能体任务上，性能可能不稳定。模型可通过额外步骤纠正一些错误，但其处理复杂、长程任务的能力仍需提升。
- **复杂网页生成：** 具有复杂 3D 场景和丰富动画的网站可能无法在单轮中完成。部分示例需要用户反馈以及两到三轮细化。

我们将继续改进模型，并计划未来将 Loop 架构应用于更大的模型。我们欢迎社区反馈和问题报告。
