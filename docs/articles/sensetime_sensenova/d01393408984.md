## 🌟 概述

🚀 **SenseNova U1** 是一系列新的原生多模态模型，它将多模态理解、推理和生成统一在一个整体架构中。它标志着多模态人工智能的根本范式转变：**从模态集成到真正的统一**。 SenseNova U1 不依赖适配器在模态之间进行转换，而是对跨语言和视觉的思考和行动进行原生建模。

在从像素到文字的端到端架构中统一视觉理解和生成，开启了巨大的可能性，以原生多模态方式实现高效且强大的理解、生成和交错推理。

![雷达图](https://huggingface.co/sensenova/SenseNova-U1-A3B-MoT-SFT/resolve/main/docs/assets/teaser_1.webp)

#### 🏗️ *关键支柱：*

SenseNova U1 的核心是**[NEO-unify](https://huggingface.co/blog/sensenova/neo-unify)**，这是一种根据多模态 AI 的第一原理设计的新颖架构：*它消除了视觉编码器 (VE) 和变分自动编码器 (VAE)，其中像素字信息本质上且深度相关。* 几个重要功能如下：

- 🔗 模型语言和视觉信息端到端作为一个统一的复合体。
- 🖼️ 保留语义丰富性，同时保持像素级视觉保真度。
- 🧠 通过原生 MoT 以高效率和最小冲突进行跨模式推理。

#### ✨ *这将解锁什么：*

在这种新的核心架构的支持下，SenseNova U1 在多模式学习方面提供了卓越的效率：

- 🏆 **理解和生成方面的开源 SoTA**：SenseNova U1 为统一的多模态理解和生成设定了新标准，在广泛的理解、推理和生成基准上实现了开源模型中最先进的性能。
- 📖 **原生交错图像文本生成**：SenseNova U1 可以通过一个模型在单一流程中生成连贯的交错文本和图像，从而实现实用指南和旅行日记等用例，将清晰的沟通与生动的故事讲述相结合，并将复杂的信息转化为直观的视觉效果。
- 📰 **高密度信息渲染**：SenseNova U1展现出强大的密集视觉传达能力，可为知识插图、海报、演示文稿、漫画、简历等信息丰富的格式生成结构丰富的布局。

#### 🌍 *超越多模态：*

- 🤖 愿景-语言-行动（VLA）
- 🌐 世界建模 (WM)

## ⚠️ 持续改进

尽管跨任务表现强劲，但仍存在一些有待改进的限制：

- **视觉理解**：
当前模型仅支持最多 **32K** 令牌的上下文长度，这可能会限制需要更长或更复杂的视觉上下文的场景中的性能。
- **以人为本的一代**：
人体的细粒度细节可能具有挑战性，特别是当人们在场景中显示为小元素或与周围物体进行复杂的交互时。
- **基于文本的生成**：
文本渲染有时可能会产生拼写错误、字符扭曲或格式不一致，这对提示的措辞方式很敏感，尤其是在文本较多的情况下。 （有关最佳实践，请参阅 [`prompt enhancement`](https://huggingface.co/sensenova/SenseNova-U1-A3B-MoT-SFT/blob/main/docs/prompt_enhancement.md)）
- **交错生成**：作为一项实验性功能，交错生成仍在不断发展，可能尚未与专用文本到图像 (T2I) 管道的性能相匹配。   **测试版状态：** RL 尚未针对可视化编辑、推理和交错任务进行专门优化，当前性能与 SFT 模型相当。

我们将这些领域视为积极的方向，并期望在未来的迭代中继续改进。

### 💾 内存高效推理（GGUF + VRAM 模式）

对于在单个消费类 GPU 上运行的用户，两个互补功能可降低 `transformers` 路径的 VRAM 占用空间。它们可以自由组合。

#### GGUF 量化检查点

将 `--gguf_checkpoint` 传递到四个推理脚本（`t2i`、`editing`、`interleave`、`vqa`）中的任何一个，以通过 `diffusers` GGUF Linear 层而不是 bf16 safetensors 权重加载量化的 `.gguf` 文件。仍然需要基本 `--model_path`（对于分词器/配置/非 LM 权重）。

```
# install the optional extra once
uv pip install -e ".[gguf]"   # or: pip install "gguf>=0.10.0" "diffusers>=0.30.0"

python examples/t2i/inference.py \
  --model_path sensenova/SenseNova-U1-8B-MoT \
  --gguf_checkpoint /path/to/SenseNova-U1-8B-MoT-Merger-Q4_K_M.gguf \
  --prompt "A male peacock trying to attract a female" \
  --output output.png
```

`SenseNova-U1-8B-MoT-Merger` 的 GGUF 权重（多个量化级别：Q3 / Q4 / Q5 / Q6 / Q8）可在以下位置获取：

|量化权重 |高频链接|
| --- | --- |
| SenseNova-U1-8B-MoT-合并-gguf | [🤗 smthem/SenseNova-U1-8B-MoT-Merger-gguf](https://huggingface.co/smthem/SenseNova-U1-8B-MoT-Merger-gguf) |

> 🙏 感谢 GitHub 用户@smthem 向社区贡献量化的 GGUF 权重。

#### `--vram_mode`：单 GPU 层卸载

通过 `--vram_mode` 将语言模型层保留在 CPU 固定内存上，并在转发过程中按需将它们流式传输到 GPU，从而释放 VRAM 的重量，同时保持设备上的激活。

|模式|行为 |何时使用 |
| --- | --- | --- |
| `full` *（默认）* |无需卸载； GPU 上的整个模型 |充足的 VRAM，最佳速度 |
| `low` |同步每层CPU↔GPU交换|最低的 VRAM 占用空间 |
| `balanced` |异步预取与计算重叠 H2D 复制 | VRAM 紧张但希望恢复速度 |

```
python examples/t2i/inference.py \
  --model_path sensenova/SenseNova-U1-8B-MoT \
  --vram_mode balanced \
  --prompt "..." --output output.png
```

`--gguf_checkpoint` 和 `--vram_mode` 组成：Q4 GGUF + `balanced` 是 ~10–12 GB 消费卡的推荐设置。

### ⚡ 使用 LightLLM + LightX2V 运行（推荐）

对于生产服务，我们在 **[LightLLM](https://github.com/ModelTC/lightllm)**（理解）和 **[LightX2V](https://github.com/ModelTC/lightx2v)**（生成）之上共同设计了专用推理堆栈。这两个引擎被分解，以便每条路径都可以使用自己的并行性和资源预算，并且中间有一个低开销的传输通道。

在具有 `TP2 + CFG2` 的单个节点上，该堆栈为 H100 / H200 上的 **2048×2048** 图像提供大约 **~0.15 s/step** 和 **~9 s 端到端**，并且基于 Triton 基线的基于 FA3 的混合掩模注意力实现了 ~**2.4–3.2×** 预填充加速。 [`docs/inference_infra.md`](https://github.com/OpenSenseNova/SenseNova-U1/blob/main/docs/inference_infra.md) 中报告了每个 GPU 的完整性能。

官方提供了一个 docker 镜像，用于单命令部署：

```
docker pull lightx2v/lightllm_lightx2v:20260407
```
