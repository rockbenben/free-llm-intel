# 用可复用资产加速生成式 AI 交付

如果你在构建生成式 AI 解决方案，可复用资产能让你不必反复重造已有的组件：Retrieval Augmented Generation（RAG）流水线、文档处理器、agent 脚手架等等。这种重复是有复利代价的：本该用来解决客户真实问题的时间被耗掉了。

本文教你如何取用一套经过整理的目录，里面是来自 AWS Generative AI Innovation Center（现隶属 AWS Frontier AI Engineering & Services）的 23 个生产就绪资产。这些资产能把你的开发时间从数月压缩到数周，[DoorDash](https://aws.amazon.com/solutions/case-studies/doordash-bedrock-case-study/)、[Lyft](http://lyft.com/blog/posts/aws-and-lyft-bringing-agentic-ai-to-life-for-riders-and-drivers) 和 [Ricoh](https://aws.amazon.com/blogs/machine-learning/how-ricoh-built-a-scalable-intelligent-document-processing-solution-on-aws/) 等公司已给出实证。

自 2023 年以来，AWS Generative AI Innovation Center 持续发布开源的可复用资产。这些生产级的构建块，让你从一个经过验证的地基起步，而不是面对一个空文件。这些资产支撑的客户方案交出了可量化的成果：测试容量提升 50 倍、工程工时减少 90%，部署周期从数月压缩到数周。本文你会了解到：团队为何总在重造生成式 AI 组件、什么样的资产才算真正可复用、DoorDash 和 Ricoh 这类公司如何借这些资产拿到可量化成果，以及如何取用和部署目录里的 23 个开源资产。全部可用资产的完整清单，见文末的资产目录。

## 问题：团队为何总在重造

生成式 AI 团队里重复开发有三个根因：

- **没有单一事实来源** – 资产散落在各个 repository、wiki 和网盘里。构建者找不到已有的东西，只好从零重做。
- **没有质量信号** – 缺少对生产就绪度、安全审查和维护状态的核验，构建者无从信任现成方案，默认就自己写代码。
- **没有复用文化** – 分享仍是非正式、无治理的。一个团队做的东西就留在这个团队，同一个问题被反复解决。

重造的代价会越滚越大。每一次重复构建都消耗工程工时、拖延客户交付，还背上维护负担。即便是 AI 生成的代码，也需要生产加固、安全审查、规模化测试和持续维护。而这些资产交付时就已经过验证、通过安全审查、达到生产级，省掉了那份核验负担。等团队终于走到生产，往往已在无差别的苦活上耗掉数周——这些工作本该从第一天就可复用。AWS Frontier AI Engineering & Services 正是用可复用资产来解决这一难题。

## 可复用资产到底是什么

可复用资产不是一段代码片段，也不是一个示例。它是实现某一项独立生成式 AI 能力的、生产级、可组合的构建块。可复用资产在发布前会经过质量与安全验证。它们带有清晰的部署指南以便检索，并埋点以跟踪在客户项目中的采用情况，且在整个生命周期内持续维护。

目录里的例子包括 RAG 流水线组件、文档摄取模块、agent 脚手架模板、评测框架和 prompt 管理范式。这些资产在生产环境里测试过、按安全合规审查过，并依据真实客户反馈打磨过。

这正是「一次性产物」与「你能信赖的构建块」之间的区别。

## 真实成效：客户成功案例

可复用资产的价值不是空谈。下面就是团队站在现成地基上、而非从零开始时发生的事。

### Contact Center GenAI Agent：DoorDash 与 Lyft

据 AWS 案例研究，[DoorDash](https://aws.amazon.com/solutions/case-studies/doordash-bedrock-case-study/) 用 [Contact Center GenAI Agent](http://github.com/aws-samples/contact-center-genai-agent) 资产，构建了一套全语音自助的生成式 AI 联络中心方案。据报告，该方案每天处理超过 10 万通电话，响应时延 2.5 秒，测试容量提升 50 倍。借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/)，开发时间缩短了 50%，团队用 2 个月就达到实网测试就绪。

[Lyft](http://lyft.com/blog/posts/aws-and-lyft-bringing-agentic-ai-to-life-for-riders-and-drivers) 用同一个 [Contact Center GenAI Agent](http://github.com/aws-samples/contact-center-genai-agent) 资产，为乘客和司机落地了 agentic AI，展示了该资产在不同客户交互模式下的通用性。

Contact Center GenAI Agent 为文本和语音两个渠道提供自动问答能力。它采用 RAG 架构来支撑多轮对话并维持上下文。方案与 [Amazon Connect](https://docs.aws.amazon.com/connect/latest/adminguide/what-is-amazon-connect.html) 集成，并用 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)（一项全托管的 RAG 能力）做混合检索与元数据过滤。

### GenAI Intelligent Document Processing：Ricoh

Ricoh 服务大型医疗保险公司、管理式医疗组织和医疗服务提供方。这些客户每月要处理数十万份关键文档，包括保险理赔、投诉、申诉和临床记录。随着 Ricoh 扩大规模、服务更多医疗客户，他们需要一套标准化、多租户的文档处理方式，且新实施上线时不必为每一家单独开发和调优。

Ricoh 以 [Accelerated Intelligent Document Processing on AWS](http://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws) 资产为地基，构建了一套标准化、多租户的自动文档分类与抽取方案。这把他们的文档处理从定制工程的瓶颈，变成了可规模化、可复制的服务。

成效：据已发布的案例研究记载，[Ricoh](https://aws.amazon.com/blogs/machine-learning/how-ricoh-built-a-scalable-intelligent-document-processing-solution-on-aws/) 实现了 7 倍吞吐提升，从每月 1 万份增至 7 万份文档。每次部署的工程工时下降超过 90%（从 80 小时降到 5 小时以内）。上线时间从 4–6 周缩短到 2–3 天。如今系统在流量高峰时几分钟内就能处理 1,000 份文档，每年可节省逾 1,900 个潜在人工工时。

[这篇 2025 年博文](https://aws.amazon.com/blogs/machine-learning/accelerate-intelligent-document-processing-with-generative-ai-on-aws/)介绍的 GenAI IDP Accelerator，是一套可扩展、无服务器的方案，用 AWS 服务自动处理文档并抽取信息。系统把 optical character recognition（OCR）与生成式 AI 结合，规模化地把非结构化文档转成结构化数据。AWS Frontier AI Engineering & Services 也在持续维护这些资产。

## 新资产：构建 agentic AI 的未来

当团队把重心从基础设施转向业务逻辑，可复用资产会更有价值。最近发布的两个资产，展示了可复用构建块如何加速下一代 agentic 应用的开发。

### Fullstack AgentCore Solution Template (FAST)

[Fullstack AgentCore Solution Template (FAST)](http://github.com/awslabs/fullstack-solution-template-for-agentcore) 是一个起步项目 repository。借助 FAST，你可以快速部署一个安全的 React 前端，连接到 Amazon Bedrock AgentCore——一个用任意框架或模型规模化构建、连接和优化 agent 的平台。在这个实现里，FAST 用基于 React 的前端搭配 AgentCore 的托管基础设施，把构建全栈 agentic 应用从数周缩短到数天。

FAST 用 infrastructure as code（IaC）在 30 分钟内部署完成，内置与 AgentCore memory（Amazon Bedrock AgentCore 的一项能力）以及 Gateway、Code Interpreter 和 Observability 的集成。认证用 Amazon Cognito，按企业安全最佳实践配置；模板为 AI 辅助开发而设计，配有详尽的文档和 steering docs。

有了 FAST，你能拿到一套完整的参考架构，看清各部件如何拼合，还有一个可运行、可学习、可继续扩展的全栈应用。模块化设计让你能在需求演进时替换主要组件（身份提供方、前端框架、托管方案或 agent 框架）。

了解更多：

- [FullStack AgentCore Solution Template](http://github.com/awslabs/fullstack-solution-template-for-agentcore)
- [Accelerate agentic application development with a full-stack starter template for Amazon Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/accelerate-agentic-application-development-with-a-full-stack-starter-template-for-amazon-bedrock-agentcore/)

### Agentic Chatbot Accelerator

[Agentic Chatbot Accelerator](http://github.com/aws-samples/sample-agentic-chatbot-accelerator) 是一套 Web 应用部署方案，用 AWS Cloud Development Kit（AWS CDK）做 infrastructure as code，让你创建 agentic chatbot。它构建在 Strands Agents 和 Amazon Bedrock AgentCore 之上，简化 agentic chatbot 应用的开发。

这套加速器借助 AWS CDK 快速部署，通过 Strands Agents 和 Amazon Bedrock AgentCore 提供可扩展的 agent runtime 管理。它可配置、可扩展，适配多种 chatbot 场景，预置了认证、托管和扩缩容范式，并已在客户部署中验证。

了解更多：

## 实操：从资产库取用一个资产

我们用一个具体例子，走一遍如何从开源目录里挑选并使用 [Contact Center GenAI Agent](http://github.com/aws-samples/contact-center-genai-agent) 资产。

### 前置条件

跟着本实操走，你需要：

- 一个 AWS 账户，具备创建 AWS CloudFormation 堆栈、Amazon Connect 实例、Amazon Bedrock 资源和 Amazon Quick Sight 仪表盘的权限。
- 已安装并配置好相应凭证的 AWS Command Line Interface（AWS CLI）。
- 一个 Amazon Connect 实例（或有权限创建一个）。
- 能在 Amazon Bedrock 上访问 Anthropic Claude Sonnet 和 Anthropic Claude Haiku。
- 一个用于验证测试的 Jupyter notebook 环境。

### 场景

你要构建一套客服方案：既要处理语音也要处理文本交互，用公司的知识库回答问题，并把复杂问题升级给人工客服。

#### 找到资产

在 GitHub 上打开 [Contact Center GenAI Agent](http://github.com/aws-samples/contact-center-genai-agent)。README 清楚地概述了能力、架构和部署步骤。下图是 Contact Center GenAI Agent 的方案架构。

![Contact Center GenAI Agent 方案架构，集成 Amazon Connect 与 Amazon Bedrock Knowledge Bases](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/02/ML-20608-1-3.png)

图 1：Contact Center GenAI Agent 的方案架构

#### 评估资产

该资产包含经安全审查的代码、以 AWS CDK 编写的 infrastructure as code、与 Amazon Connect 的语音和聊天集成，以及用于问答的 Amazon Bedrock Knowledge Bases（一项全托管 RAG 能力）。自动化测试框架和对话分析仪表盘都是内置的。

Responsible-AI 控制是架构里不可或缺的一部分。Amazon Bedrock Guardrails 强制执行生产级的安全控制，包括幻觉检测、内容过滤和话题级边界，确保 agent 从第一天起就在既定安全参数内运行。

repository 显示维护活跃、文档完备，并链接到客户成功案例（DoorDash、Lyft），印证其生产就绪度。

### 部署方案

部署分四步：

- 克隆 repository 并安装依赖。
- 部署两个 AWS CloudFormation 模板：一个给 Knowledge Base 堆栈，一个给 RAG 方案堆栈。
- 用 repository 里预置的 contact flows 与 Amazon Connect 集成。
- 用随附的 Jupyter notebooks 验证部署。

整个过程不到一小时。方案还带一个 Amazon Quick Sight 仪表盘，用于实时对话分析。

详细部署说明与前置条件，见 [deployment guide](https://github.com/aws-samples/contact-center-genai-agent?tab=readme-ov-file#deploy-and-test-the-solution)。

## 清理

为避免持续产生费用，请删除本实操中创建的资源。部署用了两个 AWS CloudFormation 堆栈，因此按相反顺序删除：

- 在 AWS CloudFormation 控制台删除 RAG 方案堆栈。
- 在 AWS CloudFormation 控制台删除 Knowledge Base 堆栈。
- 移除集成时创建的 Amazon Connect contact flows。
- 删除 Amazon Quick Sight 仪表盘及任何关联的 SPICE 数据集。
- 详细清理说明见 [deployment guide](https://github.com/aws-samples/contact-center-genai-agent?tab=readme-ov-file#deploy-and-test-the-solution)。

### 结果

与其花数周从零搭一套联络中心方案，你可以在几天内部署一个经过安全审查、测试过的地基。团队则专注于按你的领域定制知识库、打磨 prompt、与现有系统集成。这才是让你的方案真正与众不同的高价值工作。

**可能节省的时间：** 4–6 周开发时间
**你转而专注的事：** 领域定制、prompt engineering、业务逻辑集成
