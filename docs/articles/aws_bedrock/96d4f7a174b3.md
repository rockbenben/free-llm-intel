# Amazon Bedrock AgentCore Runtime 推出 agent 到 agent 协议支持

我们近期宣布，Amazon Bedrock AgentCore Runtime 已支持 Agent-to-Agent（A2A）协议。借助这一新增能力，agent 可以使用标准化的通信方式发现对等 agent、共享能力，并跨平台协调行动。

Amazon Bedrock AgentCore Runtime 提供安全、无服务器的环境，专为部署 AI agent 和工具而设计。它可与[任何框架](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/using-any-agent-framework.html)和[任何模型](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/using-any-model.html)配合使用，支持[实时](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/response-streaming.html)和[长时间运行的工作负载](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-long-run.html)，并通过[内置身份验证](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-oauth.html)支持[会话隔离](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-sessions.html)。在支持 [MCP](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-mcp.html) 以及如今的 [A2A 协议](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-a2a.html)之后，Bedrock AgentCore Runtime 让 agent 之间的通信变得无缝。使用不同框架构建的 agent —— [Strands Agents](https://strandsagents.com/latest/)、[OpenAI Agents SDK](https://openai.github.io/openai-agents-python/)、[LangGraph](https://www.langchain.com/langgraph)、[Google ADK](https://google.github.io/adk-docs/) 或 [Claude Agents SDK](https://docs.claude.com/en/api/agent-sdk/overview) —— 都能以通用、可验证的格式共享上下文、能力和推理过程。

本文将演示如何让使用不同框架构建的 AI agent 借助 A2A 协议无缝协作。你将学到如何在 AgentCore Runtime 上部署 A2A 服务器、配置 agent 发现与身份验证，以及构建一个用于事件响应的真实多 agent 系统。我们还会介绍完整的 A2A 请求生命周期，从 agent card 发现到任务委派，展示标准化协议如何消除多 agent 协作的复杂性。

## 理解多 agent 系统

构建有效的 agent 系统需要若干基础组件。其中包括[记忆](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html)：既有用于维持对话上下文的[短期记忆](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/using-memory-short-term.html)，也有用于跨会话保留洞察的[长期记忆](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/long-term-memory-long-term.html)；[工具](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/built-in-tools.html)，agent 可以原生访问，也可以通过 MCP 服务器访问；[身份](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity.html)，用于更安全的身份验证和权限管理，让 agent 可以代表用户行事或自主访问资源；以及[护栏](https://aws.amazon.com/bedrock/guardrails/)，用于检测有害内容、帮助防止幻觉，并确保响应符合策略与事实准确性。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/06/ML-19929-1.png)

MCP 把单个 agent 连接到它的工具和数据，而 A2A 则让多个 agent 相互协调。例如，一个零售库存 agent 可以用 MCP 查询商品数据库，再用 A2A 与外部供应商 agent 通信来下单。

A2A 协议通过跨越各种边界的无缝互操作性为多 agent 系统带来好处。用 Strands 或 OpenAI 等不同框架构建、由 Anthropic Claude、GPT-4 或 Llama 等各种 LLM 驱动、部署在 AWS 或边缘设备等不同系统上的 agent，都能毫不费力地通信与协调，无需复杂的转换层。这种互操作性还辅以松耦合和模块化：每个 agent 都作为独立单元运行，可以单独开发、测试、部署甚至升级，而不打乱整个系统。新的专用 agent 可以无缝加入环境，而单个 agent 的故障由于交互边界定义清晰而保持隔离，有助于防止故障在整个系统中级联扩散。该协议还支持动态的 agent 发现与编排。agent 通过标准化的 schema 公布自己的能力，编排 agent 则可以根据实时任务需求发现并调用专用 agent。

## Amazon Bedrock AgentCore Runtime 上的 A2A 请求生命周期

A2A 协议定义了一套结构化的请求生命周期，其中的特定组件协同工作以协调多 agent 通信。关键要素如下：

- **用户**：通过客户端 agent 发起请求，既可以是人类操作员，也可以是定义需要多 agent 协助之目标的自动化服务。
- **A2A 客户端（客户端 agent）**：代表用户行事，使用 A2A 协议发起通信，以发现远程 agent 并向其请求任务。
- **A2A 服务器（远程 agent）**：对外暴露实现 A2A 协议的 HTTP 端点，用于接收请求、处理任务并返回结果。不同的 agent 都可以担任这一角色，通过基于 HTTP/S 的 JSON-RPC 2.0 或 Server-Sent Events 处理同步和异步交互。
- **Agent Card**：每个 agent 发布的一份 JSON 元数据文件，用于公布其身份、能力、端点和身份验证要求。这实现了动态发现功能：agent 在委派任务之前会先查询对等 agent 能做些什么。
- **任务对象**：表示系统中流动的每个工作单元，带有唯一 ID 和生命周期。在 agent 协调过程中，任务可能长时间运行、包含多个轮次，并跨越多个协同工作的 agent。
- **产物**：任务完成时产生的输出，可以包括结构化文本、JSON、图像、音频或其他多模态内容。agent 在协作完成用户原始请求的过程中会交换这些产物。

## 多 agent 用例：监控与事件响应

为了展示在 Amazon Bedrock AgentCore Runtime 上使用 A2A 的多 agent 系统的能力，我们将带你看一个企业监控与事件响应解决方案。这个真实用例展示了用不同框架构建的专用 agent 如何通过 A2A 协议无缝协调，应对复杂的运营挑战。

## 端到端事件响应工作流

本节我们将走一遍端到端工作流：主机 agent 管理对话、从用户处获取需求，并选择最合适的 agent 来路由请求（监控或运营 agent）。监控和运营 agent 会公开各自的 agent card，供主机 agent 用于编排。在本例中，我们将测试来自各个日志组的简单错误分析，并搜索修复策略。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/06/ML-19929-10.jpg)

该工作流包含以下步骤：

- **初始问候**：用户向主机 agent 发送一条问候消息“Hi! How are you?”。主机 agent 处理该请求，并以友好的问候回复用户“I’m doing well, thank you!”。
- **能力查询**：用户问主机 agent “What are your capabilities?”，以了解它能做什么。主机 agent 向用户说明，它是一个编排 agent，基于其可访问的远程 agent 连接，专为 AWS 监控与运维而设计。
- **列出日志组和仪表盘**：用户要求主机 agent 列出其 AWS 账户中的日志组和仪表盘。主机 agent 识别出这是监控任务，于是执行 `transfer_to_agent` 工具来委派工作。请求从主机 agent 转移到监控 agent 进行专门处理。监控 agent 使用 Agent-to-Agent（A2A）Json RPC Transport 协议通信。监控 agent 检索信息并返回结果，显示账户中找到 0 个仪表盘和 153 个日志组。主机 agent 接收来自监控 agent 的结果，并向用户展示仪表盘和日志组信息。
- **分析特定日志组**：用户要求主机 agent 在路径 `/aws/bedrock-agentcore/runtimes/hostadk-<runtimeId>-DEFAULT` 下的特定日志组中查找错误。主机 agent 判断这需要监控方面的专业能力，于是执行 `transfer_to_agent` 工具。请求被转移到监控 agent，并附带分析指定日志组错误的指示。监控 agent 分析该日志组，发现 9 个错误和 18 个警告，具体识别出 OTLP Export Failures。主机 agent 接收分析结果，并向用户展示详细的错误分析报告。
- **调试与修复建议**：用户要求主机 agent 调试这些错误，并就所需的修复提供报告。请求被转移到运营 agent，以搜索与 OTLP 导出失败相关的解决方案。运营 agent 使用 A2A JsonRPC Transport 尝试搜索，并执行 Web 搜索以提供解决方案。

## Amazon Bedrock AgentCore Runtime 上 A2A 的安全性

Amazon Bedrock AgentCore Runtime 支持两种身份验证方法来保障 A2A 通信的安全：

**OAuth 2.0 身份验证**：A2A 客户端向外部授权服务器进行身份验证以获取 JSON Web Token（JWT），随后该令牌会随所有发往 A2A 服务器的请求一并发送。这种基于令牌的方式支持使用机器对机器（M2M）凭证或用户联合身份进行安全、标准化的身份验证，让 A2A 服务器可以校验客户端身份，并根据令牌中的声明执行访问控制。

**AWS IAM 身份验证**：A2A 客户端代入一个具有调用 A2A 服务器 agent 权限的 IAM 角色。这种方式利用 AWS SigV4 请求签名和 IAM 策略来控制访问，免去了外部令牌管理的需要，同时提供细粒度权限。

## Amazon Bedrock AgentCore Runtime 搭配 A2A 支持的能力

Amazon Bedrock AgentCore Runtime 为 A2A 通信提供全面支持。以下是部分受支持的能力：

- **无状态服务器**：Amazon Bedrock AgentCore Runtime 可以托管对外暴露 HTTP 接口的 A2A 服务器，在 9000 端口运行无状态 HTTP 服务器，并支持 JSON-RPC 消息传递。runtime 充当透明代理，原样转发 JSON-RPC 请求和响应，以保持协议的保真度。
- **已认证的 agent card：** 支持位于 `/.well-known/agent-card.json` 的已认证 agent card，其中包含该 agent 的能力与技能，让其他 agent 可以自动发现它。
- **通过安全入站认证实现身份验证**：Amazon Bedrock AgentCore Runtime 通过 [AWS SigV4](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_sigv.html) 和 [OAuth 2.0](https://oauth.net/2/) 支持安全身份验证，确保 agent 之间的通信经过授权且安全。A2A 服务器借助 [Amazon Bedrock AgentCore Identity](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity.html)，使用 HTTP 头中提供的凭证对每个传入请求进行认证。
- **通过安全出站认证实现授权**：Amazon Bedrock AgentCore Runtime 通过 IAM 执行角色和 AgentCore Identity 两条路径启用安全的出站授权。每个 agent 都会代入一个已定义的 IAM 执行角色，从而获得更安全地访问 AWS 资源所需的权限。在与外部服务交互时，agent 可以使用 Amazon Bedrock AgentCore Identity，它为 Google、GitHub、Slack 等第三方身份提供方提供托管的 OAuth 2.0 支持。
- **VPC 连接**：你可以配置 Amazon Bedrock AgentCore Runtime 连接到你的 [Amazon Virtual Private Cloud（VPC）](https://aws.amazon.com/vpc/)中的资源。通过配置 [VPC 连接](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-vpc.html)，你可以安全访问 VPC 内的数据库、内部 API 和服务等私有资源。
- **利用 AWS PrivateLink**：Amazon Bedrock AgentCore 使用 [AWS PrivateLink](https://aws.amazon.com/privatelink/)，在你的 Virtual Private Cloud（VPC）与 AgentCore 服务之间建立安全、私密的连接。通过创建[接口 VPC 端点](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/vpc-interface-endpoints.html)，你可以让 A2A 服务器通信保持在 VPC 内，而不经过公共互联网。
- **生命周期管理：** Amazon Bedrock AgentCore Runtime 让你可以配置[生命周期规则](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-lifecycle-settings.html)，通过 `idleRuntimeSessionTimeout` 和 `maxLifetime` 管理资源用量。空闲或长时间运行的会话会被自动终止，以实现高效的资源利用并保持系统性能。

## 结语

Amazon Bedrock AgentCore Runtime 中的 Agent-to-Agent 协议支持为构建可扩展、可互操作的多 agent 系统提供了支撑。通过在 AI agent 之间提供标准化通信（无论它们底层使用什么框架、模型或托管基础设施），组织可以用 A2A 协议组合出精密的 agent 解决方案。AWS 的监控与事件响应示例展示了这一方法的实际力量：一个基于 Google ADK 的编排器与 Strands 和 OpenAI SDK 的 agent 协调配合，全部部署在 AgentCore Runtime 上，共同检测问题、搜索解决方案并推荐修复方案。这种级别的互操作过去需要大量定制集成工作，而 A2A 通过标准化协议让它变得简单直接。随着 AI 系统从单一用途的工具演进为协作环境，A2A 和 MCP 这类协议成为必不可少的构建块。它们创造了这样一个未来：agent 可以被动态地发现、组合和编排，让组织构建一次就能在任何地方集成。
