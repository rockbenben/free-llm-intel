# 用 Amazon Nova Sonic 和 WebRTC 构建实时语音流式应用

构建具备实时语音交互的端到端直播应用会带来若干挑战：网络带宽限制会在时间敏感的应用中造成高延迟和质量下降。语言障碍限制了多语言语音通信中有效的人机交互。可扩展性与韧性需要在性能与基础设施成本之间取得困难的平衡。跨浏览器和移动端的兼容性需要投入大量开发工作，对初创公司尤其如此。

本文介绍一个基于 [Amazon Nova 2 Sonic](https://docs.aws.amazon.com/ai/responsible-ai/nova-2-sonic/overview.html)（Nova Sonic）和 [Amazon Kinesis Video Streams WebRTC](https://docs.aws.amazon.com/kinesisvideostreams-webrtc-dg/latest/devguide/what-is-kvswebrtc.html)（WebRTC）的解决方案，用来应对这些挑战。WebRTC 负责在不稳定的网络中动态调整比特率，有助于在减少连接中断的同时保持音频质量。Nova Sonic 提供有效的人类语言对话能力，让用户可以用自己选择的语言更自然地交互。这两项服务都由 AWS 完全托管，因此可以自动扩展并具备高韧性。AWS 还提供开源示例，你可以把它们作为自己应用的起点。

本文将带你了解解决方案架构、实现模式，以及两个真实场景示例。

## Nova Sonic 与 WebRTC

传统的语音 agent pipeline 通常包含语音识别、语言处理和语音合成等相互独立的模块。[Nova Sonic](https://aws.amazon.com/nova/speech/) 提供统一的语音到语音架构，使用户与 AI agent 之间能够以低延迟进行实时语音对话。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/09/ML-200271.jpeg)

凭借统一的语音理解与生成，Nova Sonic 交付自然、近似真人的对话式 AI。Nova Sonic 模型提供多种说话风格，以及面向外部 agent 的工具接口。你可以用它构建响应更及时、更直观、上下文感知更强的语音界面。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/09/ML-200272.png)

一个典型的流式 pipeline 由三个主要组件构成：媒体源、媒体服务器和媒体消费者。上图展示了这些组件及各自对应的协议，例如 RTMP、RTSP、HLS、MPEG-DASH 和 WebRTC。

[Web 实时通信（WebRTC）](https://webrtc.org/) 是一个公开协议，通过提供无需额外插件或软件安装的实时点对点直连，使直播现代化。这种做法免去了中间服务器，显著降低了延迟。在所有媒体流协议中，WebRTC 的延迟最低，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/09/ML-200273.png)

WebRTC 还内置了[自适应比特率（ABR）](https://en.wikipedia.org/wiki/Adaptive_bitrate_streaming)流、[前向纠错（FEC）](https://www.rfc-editor.org/rfc/rfc8854.html)和[抖动缓冲（jitter buffer）](https://developer.mozilla.org/en-US/docs/Glossary/Jitter#jitter_buffer)管理等特性。这些特性可以自动调整带宽占用，并在连接较弱时解决丢包或抖动问题。即使在网络条件很差的情况下，你也能保持流畅的对话。

WebRTC 的开源特性与广泛的浏览器兼容性（Chrome、Firefox、Safari、Edge、Android、iOS 等）将加速方案的采用并推动持续改进。它也非常适合与 AI 功能结合，对媒体流做实时处理。

## 解决方案架构

在以下场景中，你可能希望部署支持多语言语音交互的直播方案：**互联汽车**，借助实时翻译能力为驾驶员提供协助。**智能工厂**，通过语音激活的质量控制系统支持跨文化的操作员沟通。**机器人**应用，提供多语言的客户服务交互。**智能家居**设备，用不同语言提供即时语音控制，让你可以通过实时音频翻译和可视化引导获得全球技术支持。

下图展示了如何把 Nova Sonic 方案与作为托管 WebRTC 服务的 Kinesis Video Streams 一起部署。图中还展示了与检索增强生成（RAG）、模型上下文协议（MCP）和 Strands Agents 等常用来源的工具集成。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/09/ML-200274.png)

[1] 在客户端 App 中，用户通过连接 Kinesis Video Streams WebRTC 信令通道来建立 [WebRTC 协商流程](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Perfect_negotiation)。音频和视频数据经双向 WebRTC 连接传输。

[2] 在完成[会话描述协议（SDP）offer/answer](https://datatracker.ietf.org/doc/html/rfc3264) 与[交互式连接建立（ICE）候选](https://datatracker.ietf.org/doc/html/rfc8445)的信令消息交换后，客户端与服务端发起双向对等连接尝试。随后，视频和音频数据便可经成功的 RTC 连接以低延迟传输。

[3] 媒体通道负责实时音视频流传输，具备自适应比特率控制和编解码协商。数据通道则为任意应用数据提供可靠且有序的传输，例如文本、文件和控制消息。两者都使用[数据报传输层安全（DTLS）](https://datatracker.ietf.org/doc/html/rfc6347)加密和[用于 NAT 的会话穿越工具（STUN）](https://datatracker.ietf.org/doc/html/rfc8489)/[通过 NAT 中继的穿越（TURN）](https://datatracker.ietf.org/doc/html/rfc5766)协议，实现网络地址转换（NAT）穿越。

[4] 语音到语音事件处理器编排与 Nova Sonic 之间的[输入事件](https://docs.aws.amazon.com/nova/latest/userguide/input-events.html)和[输出事件](https://docs.aws.amazon.com/nova/latest/userguide/output-events.html)交互。在我们的方案中，它们分为通过 WebRTC 媒体通道传输的媒体事件，以及通过 WebRTC 数据通道传输的文本数据。

[5] 你使用 [Python SDK](https://github.com/aws-samples/amazon-nova-samples/tree/main/speech-to-speech/amazon-nova-2-sonic/sample-codes/console-python) 与 Nova Sonic 建立 HTTP/2 双向流式连接。该连接支持实时媒体数据通信，并为用户把延迟降到最低。

[6] 除了基于预训练知识的语音到语音音频对话，Nova Sonic 还支持[异步工具调用](https://docs.aws.amazon.com/nova/latest/nova2-userguide/sonic-async-tools.html)，以访问 MCP 服务器、Strands agent 或 RAG。本文用示例演示了工具使用功能。

如果你已经在使用 Nova Sonic，你会注意到这个架构与 WebSocket 方案相似。下面我来展示关键差异。

## 方案对比

与 [WebSocket 部署](https://github.com/aws-samples/amazon-nova-samples/tree/main/speech-to-speech/workshops) 方案相比，这个[基于 WebRTC 的语音到语音方案](https://github.com/aws-samples/sample-nova-sonic-speech2speech-webrtc)提供了适合移动端和 IoT 设备的另一种网络层。这类设备往往需要低延迟连接，而带宽要求并不高。该方案还引入了定制的语音活动检测（VAD）层，以提升用户体验。

### 音频流协议从 WebSocket 改为 WebRTC

语音数据通过 WebRTC 媒体通道以流式方式传输，即通过 [Secure Real-time Transport Protocol（SRTP）](https://datatracker.ietf.org/doc/html/rfc3711) 格式的对等连接音频轨道传输，而不再通过 WebSocket 消息。我们使用 [aiortc](https://github.com/aiortc/aiortc) Python 库实现了 WebRTC 特性（例如 SDP offer/answer、DTLS、流控制传输协议（SCTP）、SRTP 和对等连接）。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/09/ML-200275.png)

### 人声检测机制

React WebRTC 客户端持续采集音频并发送给 Python WebRTC 服务端。为了抑制噪声、提升语音准确率并减少送给 Nova Sonic 的音频 token，该方案在服务端 pipeline 中应用了[语音活动检测](https://en.wikipedia.org/wiki/Voice_activity_detection)（VAD）。基于 [Python WebRTCVAD 库](https://github.com/wiseman/py-webrtcvad) 的代码实现如下图所示。该库基于高斯混合模型（GMM）构建，轻量、稳定，处理 WebRTC 帧级音频时速度很快。你也可以使用其他库，例如 [Silero VAD](https://github.com/snakers4/silero-vad)、[Pyannote VAD](https://huggingface.co/pyannote/voice-activity-detection)。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/09/ML-200276.png)

### 音频数据格式适配

WebRTC 定义了特定的音视频格式标准。通过 WebRTC 连接收发音频数据时，你必须做一些格式适配：[[1]](https://github.com/aws-samples/sample-nova-sonic-speech2speech-webrtc/blob/main/docs/AudioDataAdaption.md#interleaved-layout-unpacking) 交错立体声帧需要取出左声道或右声道；[[2]](https://github.com/aws-samples/sample-nova-sonic-speech2speech-webrtc/blob/main/docs/AudioDataAdaption.md#sampling-rate-48khz-to-16khz) 48kHz 或其他采样率会被重采样为 Nova Sonic API 所要求的 16kHz；[[3]](https://github.com/aws-samples/sample-nova-sonic-speech2speech-webrtc/blob/main/docs/AudioDataAdaption.md#type-conversion-from-int16-to-float32) Int16 数据值会被转换为 Float32，以提升计算精度。更多信息请参阅 [GitHub 文档](https://github.com/aws-samples/sample-nova-sonic-speech2speech-webrtc/blob/main/docs/AudioDataAdaption.md)。

## 结论
