# 在 Amazon Bedrock 上使用 TwelveLabs Marengo 解锁视频理解能力

媒体与娱乐、广告、教育以及企业培训内容融合了视觉、音频和动态元素来讲述故事、传递信息，因此远比文本复杂——文本中每个词都有清晰的含义。这给需要理解视频内容的 AI 系统带来了独特挑战。视频内容是多维的，结合了视觉元素（场景、物体、动作）、时间动态（运动、转场）、音频成分（对话、音乐、音效）以及文字叠加（字幕、说明文字）。这种复杂性带来了重大的业务挑战：组织难以搜索视频档案、定位特定场景、自动分类内容，也难以从媒体资产中提取洞见以支撑有效决策。

该模型通过多向量架构应对这一问题，为不同的内容模态生成独立的嵌入。模型不会把所有信息强行压缩进一个向量，而是生成专门化的表示。这种方法保留了视频数据丰富、多维的特质，从而能够在视觉、时间和音频维度上进行更精准的分析。

Amazon Bedrock 扩展了能力，支持 TwelveLabs Marengo Embed 3.0 模型，可通过同步 inference 实现实时文本与图像处理。借助这一集成，企业能够用自然语言查询实现更快的视频搜索功能，同时通过复杂的图像相似度匹配支持交互式产品发现。

在本文中，我们将展示通过 [Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-marengo-3.html) 提供的 TwelveLabs Marengo 嵌入模型如何利用多模态 AI 增强视频理解。我们将使用 Marengo 模型生成的嵌入，并以 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/) 作为向量数据库，构建一个视频语义搜索与分析解决方案，其语义搜索能力超越简单的元数据匹配，实现智能内容发现。

## 理解视频嵌入

嵌入是在高维空间中捕捉数据语义含义的密集向量表示。可以把它们理解为数字指纹，以机器能够理解和比较的方式编码内容的本质。对于文本，嵌入可以捕捉到“king”和“queen”是相关概念，或者“Paris”和“France”存在地理关联。对于图像，嵌入能够理解 **golden retriever** 和 **labrador** 都是狗，即使它们看起来不同。下面的热力图展示了这些句子片段之间的语义相似度得分：“two people having a conversation”、“a man and a woman talking”以及“cats and dogs are lovely animals.”![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/21/ML-19664-1.png)

### 视频嵌入的挑战

视频带来了独特的挑战，因为它本质上是多模态的：

- **视觉信息**：物体、场景、人物、动作以及视觉美感
- **音频信息**：语音、音乐、音效以及环境噪声
- **文本信息**：字幕、屏幕文字以及转录的语音

传统的单向量方法将所有这些丰富信息压缩成一种表示，往往会丢失重要的细微差别。这正是 TwelveLabs Marengo 的方法在有效应对这一挑战时的独特之处。

**Twelvelabs Marengo：一种多模态嵌入模型**

Marengo 3.0 模型会生成多个专门化向量，每个向量捕捉视频内容的不同方面。典型的电影或电视节目会结合视觉与听觉元素，营造出统一的叙事体验。Marengo 的多向量架构在理解这类复杂视频内容方面具有显著优势。每个向量捕捉一种特定模态，避免了将多样数据类型压缩为单一表示所带来的信息损失。这使得搜索更加灵活，可针对特定内容方面——仅视觉、仅音频或组合查询。专门化向量在复杂的多模态场景中提供更高的准确性，同时为大型企业视频数据集保持高效的可扩展性。

### 创建视频嵌入

Amazon Bedrock 使用异步 API 来生成 Marengo 视频嵌入。以下是一个 python 代码片段，展示了调用 API 并从 S3 bucket 位置获取视频的示例。有关完整支持的功能，请参阅[文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-marengo-3.html)。

```
bedrock_client = boto3.client("bedrock-runtime")
model_id = 'us.twelvelabs.marengo-embed-3-0-v1:0'
video_s3_uri = "<s3 bucket location for the video>" # Replace by your s3 URI
aws_account_id = "<the AWS account owner for the bucket>" # Replace by bucket owner ID
s3_bucket_name = "<s3 bucket name>" # Replace by output S3 bucket name
s3_output_prefix = "<output prefix>" # Replace by output prefix

response = bedrock_client.start_async_invoke(
            modelId=model_id,
            modelInput={
                "inputType": "video",
		        "video": {
                    "mediaSource": {
                      "s3Location": {
                        "uri": video_s3_uri,
                        "bucketOwner": aws_account_id
                       }
         	     }
		 }
           },
           outputDataConfig={
               "s3OutputDataConfig": {
                  "s3Uri": f's3://{s3_bucket_name}/{s3_output_prefix}'
                }
           }
        )
```

上面的示例从单个视频中生成了 280 个独立的嵌入——每个片段一个，从而实现精确的时间搜索与分析。视频多向量输出可能包含以下嵌入类型：

```
[ 
 {'embedding': [0.053192138671875,...], 'embeddingOption': "visual", 'embeddingScope' : "clip", "startSec" : 0.0, "endSec" : 4.3 },
 {'embedding': [0.053192138645645,...], 'embeddingOption': "transcription", 'embeddingScope' : "clip", "startSec" : 3.9, "endSec" : 6.5 },
 {'embedding': [0.3235554er443524,...], 'embeddingOption': "audio", 'embeddingScope' : "clip", "startSec" : 4.9, "endSec" : 7.5 }
]
```

- **visual**——视频的视觉嵌入
- **transcription **——转录文本的嵌入
- **audio**——视频中音频的嵌入

在处理音频或视频内容时，你可以设置每个片段的长度以用于生成嵌入。默认情况下，视频片段会在自然的场景变化处（镜头边界）自动切分。音频片段则被均匀切分为尽可能接近 10 秒的片段——例如，一个 50 秒的音频文件会变成 5 个各 10 秒的片段，而一个 16 秒的文件会变成 2 个各 8 秒的片段。默认情况下，单次 Marengo 视频嵌入 API 会生成 visual-text、visual-image 和 audio 嵌入。你也可以更改默认设置，只输出特定类型的嵌入。使用以下代码片段，可通过 Amazon Bedrock API 以可配置选项为视频生成嵌入：

```
response = bedrock_client.start_async_invoke(
            modelId=model_id,
            modelInput={
               "modelId": model_id,
               "modelInput": {
                    "inputType": "video",
                    "video": {
                       "mediaSource": {
                            "base64String": "base64-encoded string", // base64String OR s3Location, exactly one
                            "s3Location": {
                               "uri": "s3://amzn-s3-demo-bucket/video/clip.mp4",
                               "bucketOwner": "123456789012"
                             }
                       },
                      "startSec": 0,
                      "endSec": 6,
                      "segmentation": {
                         "method": "dynamic", // dynamic OR fixed, exactly one
                         "dynamic": {
                           "minDurationSec": 4
                         }
                         "method": "fixed",
                         "fixed": {
                           "durationSec": 6
                         }
                      },
                      "embeddingOption": [
                          "visual",
                          "audio", 
                          "transcription"
                       ], // optional, default=all
                      "embeddingScope": [
                          "clip",
                          "asset"
                       ] // optional, one or both
               },
               "inferenceId": "some inference id"
            }
          }
         )
```

### 向量数据库：Amazon OpenSearch Serverless

在我们的示例中，我们将使用 Amazon OpenSearch Serverless 作为向量数据库，用于存储由 Marengo 模型从给定视频生成的文本、图像、音频和视频嵌入。作为向量数据库，OpenSearch Serverless 让你能够通过语义搜索快速找到相似内容，而无需操心服务器或基础设施的管理。以下代码片段演示了如何创建 Amazon OpenSearch Serverless collection：

```
aoss_client = boto3_session.client('opensearchserverless')

try:
    collection = self.aoss_client.create_collection(
        name=collection_name, type='VECTORSEARCH'
    )
    collection_id = collection['createCollectionDetail']['id']
    collection_arn = collection['createCollectionDetail']['arn']
except self.aoss_client.exceptions.ConflictException:
    collection = self.aoss_client.batch_get_collection(
        names=[collection_name]
    )['collectionDetails'][0]
    pp.pprint(collection)
    collection_id = collection['id']
    collection_arn = collection['arn']
```

创建 OpenSearch Serverless collection 后，我们将创建一个包含各项属性（其中含一个向量字段）的 index：

```
index_mapping = {
    "mappings": {
        "properties": {
            "video_id": {"type": "keyword"},
            "segment_id": {"type": "integer"},
            "start_time": {"type": "float"},
            "end_time": {"type": "float"},
            "embedding": {
                "type": "dense_vector",
                "dims": 1024,
                "index": True,
                "similarity": "cosine"
            },
            "metadata": {"type": "object"}
        }
    }
}
credentials = boto3.Session().get_credentials()
awsauth = AWSV4SignerAuth(credentials, region_name, 'aoss')
oss_client = OpenSearch(
            hosts=[{'host': host, 'port': 443}],
            http_auth=self.awsauth,
            use_ssl=True,
            verify_certs=True,
            connection_class=RequestsHttpConnection,
            timeout=300
        )
response = oss_client.indices.create(index=index_name, body=index_mapping)
```

### 索引 Marengo 嵌入

以下代码片段演示了如何将 Marengo 模型输出的嵌入摄取到 OpenSearch index 中：

```
documents = []  
for i, segment in enumerate(video_embeddings):
    document = {
        "embedding": segment["embedding"],
        "start_time": segment["startSec"],
        "end_time": segment["endSec"],
        "video_id": video_id,
        "segment_id": i,
        "embedding_option": segment.get("embeddingOption", "visual")
    }
documents.append(document)

# Bulk index documents
bulk_data = []
for doc in documents:
    bulk_data.append({"index": {"_index": self.index_name}})
    bulk_data.append(doc)

# Convert to bulk format
bulk_body = "\n".join(json.dumps(item) for item in bulk_data) + "\n"
response = oss_client.bulk(body=bulk_body, index=self.index_name)
```

借助 Marengo 的多向量设计，你可以跨不同模态进行搜索，这是单向量模型无法做到的。通过为视觉、音频、运动和上下文元素创建独立但对齐的嵌入，你可以使用自己选择的输入类型来搜索视频。例如，“jazz music playing” 这一文本查询会返回音乐家表演的视频片段、爵士乐音轨以及音乐厅场景。
