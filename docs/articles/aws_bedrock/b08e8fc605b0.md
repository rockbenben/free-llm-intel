# Totogi 如何借助 Totogi BSS Magic 与 Amazon Bedrock 实现变更请求处理自动化

*本文由 Totogi 的 Nikhil Mathugar、Marc Breslow 和 Sudhanshu Sinha 合著。*

本文介绍 Totogi 如何实现变更请求处理的自动化。[Totogi](https://totogi.com/) 是一家 AI 公司，专注于帮助电信（telco）企业创新、加速增长并大规模采用 AI。[BSS Magic](https://totogi.com/products/bss-magic/) 是 Totogi 的旗舰产品，它连接并建模电信业务运营，用 AI 层叠加在遗留系统之上。借助 BSS Magic，电信企业无需依赖厂商、也无需漫长的实施周期，就能扩展、定制并现代化其系统。通过与 [AWS Generative AI Innovation Center](https://aws.amazon.com/ai/generative-ai/innovation-center/) 合作，并利用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的快速创新能力，我们加速了 BSS Magic 的开发，帮助 Totogi 的客户更快创新，并对其技术栈拥有更多掌控。

在本文中，我们探讨传统业务支撑系统（BSS）面临的相关挑战，以及 Totogi BSS Magic 提供的创新解决方案。我们介绍电信本体（ontology）的复杂性，以及支撑变更请求处理自动化的多 agent 框架。此外，本文还将概述 AI agent 的编排方式，以及这种方法为电信运营商及其他行业带来的收益。

## BSS 面临的挑战

BSS 素来难以管理。典型的 BSS 技术栈由来自不同厂商的数百个应用组成。但这些 BSS 应用难以集成，要么把电信企业限制在厂商的生态内，要么要求它们投入高昂的定制开发。由于依赖专门的工程人才，这类定制既缓慢又耗费资源。

每一项变更请求都需要全面分析其在相互关联的模块之间可能产生的影响，耗费大量时间和精力。即便是很小的更新，也可能需要多轮编码、测试和重新配置才能达到稳定状态。对系统可靠性至关重要的电信运营商而言，这些保障措施没有商量余地，但代价不菲。此外，具备必要专业技能的工程师稀缺，使这一过程更加复杂，推高了成本并拉长了周期。结果，新功能或新服务的开发周期往往要数月才能完成，运营商难以跟上快速变化的市场需求。

[TM Forum 的开放数字架构（ODA）](https://www.tmforum.org/oda/about/) 等倡议旨在解决这一问题，但多数厂商在采纳这类开放标准上进展缓慢。这种局面放大了技术债，并抬高了运营费用。

## BSS Magic 解决方案概览

Totogi BSS Magic 通过 AI 生成的互操作性来降低复杂度，有助于简化集成、定制和应用开发。BSS Magic 有两个关键方面：

- **电信本体（telco ontology）**：理解数据结构的语义含义及其相互关系，把孤立的数据连接成连贯的知识网络。
- **多 agent 框架**：用于全自动处理变更请求（CR），把 CR 处理时间从 7 天缩短到几小时。

## 电信本体：互操作性的关键

本体充当语义蓝图，详细描述概念、关系和领域知识。在电信领域，这意味着把 BSS 全景转化为一个清晰、可复用且可互操作的生态。Totogi 的电信本体有助于深入理解数据交互，并实现跨任意厂商或系统的无缝集成。
 通过采纳 FAIR 原则（可发现性、可访问性、互操作性和可复用性），这套本体驱动的架构把静态的、孤立的数据转化为动态、互联的知识资产——释放被禁锢的数据并加速创新。本体的概览图如下图所示。

## 用于变更请求自动化的多 agent 框架

AI agent 是经过训练、可自主执行特定任务的高级软件应用。Totogi 的 BSS Magic AI agent 拥有广泛的领域知识，并利用这种理解来管理跨多个厂商系统的复杂数据交互。这些 agent 自动生成并测试电信级代码，用智能的、AI 生成的应用取代传统的集成与定制。BSS Magic 的核心是采用带反馈回路的多 agent AI 方法，实现整个软件开发流水线的自动化。每个 agent 都针对流水线中的特定角色而设计：

- **业务分析 agent**：把非结构化需求转化为正式的业务规格说明。
- **技术架构 agent**：接收这些业务规格，定义技术架构、API 和依赖关系。
- **开发者 agent**：生成高质量、可部署的代码，并包含模块化设计与优化。
- **QA agent**：验证代码是否符合最佳实践，提升质量与安全性。它给出反馈，供开发者 agent 更新代码。
- **测试 agent**：生成健壮的单元测试用例，简化验证与部署。测试用例的结果供开发者 agent 改进代码。

系统的概览如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/15/totogi-1.png)

这条集成流水线把完成一项变更请求的时间从 7 天缩短到几小时，人工介入极少。实施该系统的先决条件包括：一个可访问 Amazon Bedrock、[AWS Step Functions](https://aws.amazon.com/step-functions/)、[AWS Lambda](https://aws.amazon.com/pm/lambda/) 的 AWS 账户，以及已配置好的 Amazon 凭证。这些 AI agent 通过 Amazon Bedrock 使用 Anthropic Claude 大语言模型（LLM）实现。状态管理和工作流协调由 Step Functions 负责，确保每个阶段可靠推进。AWS 基础设施提供了电信级解决方案所必需的企业级可靠性、安全性和可扩展性。

为构建该框架，Totogi 与 AWS Generative AI Innovation Center（GenAIIC）合作。GenAIIC 提供了 AI 专业能力、业界领先的人才，以及严格的迭代流程来优化 AI agent 和代码生成工作流。它还就 prompt engineering、检索增强生成（RAG）、模型选择、自动化代码审查、反馈回路、用于评估 AI 生成输出的健壮性能指标等方面提供了指导。这次合作帮助确立了在平台上扩展自动化的同时保持可靠性的方法。该解决方案编排多个专门的 AI agent，处理从需求分析到测试执行的完整软件开发生命周期。各 AI agent 的细节在下面各节中说明。

## 多 agent 编排层

编排层通过 Step Functions 与 Lambda 函数的组合来协调专门的 AI agent。每个 agent 通过 RAG 和 few-shot prompting 技术维持上下文，以生成准确的领域特定输出。系统管理 agent 之间的通信与状态转换，同时保留对决策和操作的完整审计轨迹。

## 业务分析生成

Business Analyst agent 利用 Claude 的自然语言理解能力处理工作说明书（SOW）文档和验收标准。它使用针对电信 BSS 领域知识优化的自定义 prompt 模板提取关键需求。该 agent 生成结构化的规格说明以供下游处理，同时保持业务需求与技术实现之间的可追溯性。

## 技术架构生成

Technical Architect agent 把业务需求转化为具体的 AWS 服务配置和架构模式。它生成完整的 API 规格说明和数据模型，并纳入 [AWS Well-Architected](https://aws.amazon.com/architecture/well-architected/) 原则。该 agent 依据既有模式和最佳实践验证架构决策，产出用于自动化部署的基础设施即代码模板。

## 代码生成流水线

Developer agent 利用 Claude 强大的代码生成能力，把技术规格转化为实现代码。它产出健壮、可直接用于生产的代码，其中包含恰当的错误处理和日志记录机制。该流水线纳入来自验证步骤的反馈，以迭代改进代码质量，并保持与 AWS 最佳实践的一致性。

## 自动化质量保证

QA agent 基于 Claude 构建，用于执行全面的代码分析与验证。它评估代码质量并识别潜在的性能问题。系统与开发阶段保持持续的反馈回路，基于质量指标和最佳实践的符合程度，促进生成代码的快速迭代与改进。QA 过程由精心设计的 prompt 组成。

QA 代码分析 prompt：

```
"You are a senior QA backend engineer analyzing Python code for serverless applications.
Your task is to:
Compare requirements against implemented code
Identify missing features
Suggest improvements in code quality and efficiency
 Provide actionable feedback
Focus on overall implementation versus minor details
Consider serverless best practices"
```

该 prompt 帮助 QA agent 执行彻底的代码分析、评估质量指标，并与开发阶段保持持续的反馈回路。

## 测试自动化框架

Tester agent 创建全面的测试套件，验证功能性与非功能性需求。它使用 Claude 理解测试上下文并生成合适的测试场景。该框架通过评估循环管理测试的细化，在覆盖全部业务需求的同时保持测试代码的质量与可靠性。测试框架采用多阶段 prompt 方式。

初始测试结构 prompt：

```
"As a senior QA engineer, create a pytest-based test structure including:
Detailed test suite organization
Resource configurations
Test approach and methodology
Required imports and dependencies"
```

测试实现 prompt：

```
"Generate complete pytest implementation including:
Unit tests for each function
Integration tests for API endpoints
AWS service mocking
Edge case coverage
Error scenario handling"
```

测试结果分析 prompt：

```
"Evaluate test outputs and coverage reports to:
Verify test completion status
Track test results and outcomes
Measure coverage metrics
Provide actionable feedback"
```

这种结构化方式在保持高质量标准的同时实现了全面的测试覆盖。该框架目前达到 76% 的代码覆盖率，并成功验证了功能性和非功能性需求。

Tester agent 向 Development agent 提供反馈回路，以改进代码。

## 结论

Totogi BSS Magic 与 Amazon Bedrock 的集成，为现代电信运营商提供了一套完整的解决方案。以下是一些可供你参考的要点：

- **端到端自动化：** BSS Magic 实现了从想法到部署的整个开发生命周期的自动化。AI agent 处理从需求、架构、代码生成到测试和验证的一切工作。
- **成果：** 该 agentic 框架显著提升了效率，把变更请求处理时间从七天缩短到几小时。自动化测试框架达到 76% 的代码覆盖率，持续交付高质量的电信级代码。
- **对电信运营商的独特价值：** 借助 Totogi BSS Magic，电信运营商可以加快上市时间并降低运营成本。BSS Magic 使用自主 AI 独立管理复杂任务，使电信运营商可以专注于战略性创新。该解决方案由 Amazon Bedrock 提供支持，后者提供可扩展的 AI 模型与基础设施，以及电信行业至关重要的高安全性与可靠性。
- **对其他行业的影响：** 虽然 BSS Magic 面向电信行业，但其多 agent 框架可以改造用于其他行业的一般软件开发。
- **后续工作：** 未来的增强将聚焦于扩展模型在电信及其他领域的领域知识。另一项可能的扩展是集成一个 AI 模型，基于历史数据预测变更请求中的潜在问题，从而提前应对常见陷阱。
