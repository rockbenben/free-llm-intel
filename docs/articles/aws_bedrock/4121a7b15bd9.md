# 为监督式微调准备数据 第 2 部分：高级数据策略

监督式微调（SFT）的数据准备，并不会在数据集干净且格式正确之后就结束。更难的问题紧随其后：你到底需要多少数据？是应该收集更多数据，还是从现有数据中挑选一个更好的子集？当人工标注无法规模化时，你如何生成高质量的样本？以及，如何在不抹掉模型通用能力的前提下让它专精于某一领域？本文假设你已经准备好了一份经过质量检查、符合 schema 的 SFT 数据集，并准备针对训练对它进行优化。本系列的第一篇[为监督式微调准备数据 第 1 部分：格式与质量](https://aws.amazon.com/blogs/machine-learning/preparing-data-for-supervised-fine-tuning-part-1-formatting-and-quality/)涵盖了这些基础工作：Amazon Nova 期望的对话格式、能够捕获格式错误与低信号样本的质量检查，以及如何在不发生泄漏的情况下划分训练集与评估集。如果你的数据集还没有走过这些步骤，请从那里开始。

这第二篇覆盖四种高级策略：用学习曲线分析评估数据就绪度、数据子集选择与过滤、数据增强，以及数据混合。全文我们会引用 Amazon Nova 定制方面的发现，而这些指导适用于你选择的任何模型。

## 数据就绪度评估

在数据完成清洗和格式化之后，要评估你是否有足够的信号来有效训练。

### 数据量与分布评估

作为一般的起点，针对典型的 SFT 任务，可以按大约 2,000 个高质量训练样本做规划。请把这只当作粗略估计：合适的规模取决于任务难度，以及模型当前行为距离你的目标有多远。简单的格式或风格调整，少至 500 个样本就可能奏效；而复杂的多步推理任务可能需要 10,000 个甚至更多。每个任务和领域都有不同的饱和特性。

在开展这些实验之前，有一项前提比什么都重要：清晰定义的评估基准。这意味着一个能代表生产流量的评估集，以及能够反映「对你的用例而言什么算好」的指标。大多数团队发现这比准备训练数据本身更难。如果你还没有这样的基准，请先把它建起来。[Amazon Bedrock evaluations](https://aws.amazon.com/bedrock/evaluations/) 支持用你自己的数据集和指标来评估模型，AWS Machine Learning Blog 上的[评估大语言模型的质量与责任性](https://aws.amazon.com/blogs/machine-learning/evaluate-large-language-models-for-quality-and-responsibility/) 一文则完整介绍了如何构建评估 pipeline。

基准就位之后，通过学习曲线分析以实证方式确定你的数据集规模：

- **训练一次，评估多个检查点。** 在完整数据集上只跑一次训练任务，并保存中间检查点，例如每完成 10–20% 的训练就保存一次。在留出的评估集上评估每个检查点。在第一个 epoch 中，第 N 步的检查点大约已经看过你的独有数据中的 N/total_steps 部分，因此这能在不进行多次训练的情况下近似出一条数据扩展曲线。
- **绘制性能随数据规模变化的曲线。** 把下游指标对已消耗的训练 token 作图。你要找的是饱和点——在那里，数据翻倍在你的一级指标上带来的提升不到 1–2%。
- **收益递减时就停手。** 如果曲线在变平，同类型的更多数据不会有帮助。要么提前停止训练以节省算力，要么加入性质不同的数据，专门针对模型仍然会出错的失败案例。图 1 展示了如何通过逐次检查点的增益，区分一条正在变平的曲线和一条仍在改善的曲线。

### 为什么更多数据并不总是意味着更好的性能

SFT 并不遵循与预训练相同的单调幂律扩展规律。[SFT 扩展研究](https://arxiv.org/html/2509.06463v2)表明，仅靠数据量并不能保证成比例的收益。真正重要的是指令集的覆盖度与深度。[Data Repetition Beats Scaling](https://arxiv.org/abs/2602.11149) 令人瞩目地证明了这一点：在固定的算力预算下，用 400 个推理样本训练 128 个 epoch，在 AIME 和 GPQA 上比在 51,200 个样本上单 epoch 训练高出 12–26 个百分点。一个更小但高质量、被训练到充分记忆的数据集，可以胜过模型只见过一次的大数据集。训练 token 准确率可作为实用的停止判据，因为当模型达到近乎完美的训练准确率之后，收益就会趋于平缓。

## 数据子集选择与过滤

当收益递减出现时，智能的数据选择可以胜过在全集上训练。像 [DEITA](https://arxiv.org/abs/2312.15685)、[DELIFT](https://arxiv.org/abs/2411.04425) 以及 coreset 选择这样的方法，会找出在保持质量与多样性的前提下覆盖你任务空间的最小数据子集。这些方法从质量、多样性以及每个样本实际能教会模型多少这三个维度给候选样本打分。有两点收益尤为突出：

- **用更少的样本达到或超过全量数据的性能。** 去掉冗余或低质量的样本能提供更干净的梯度信号。[AlpaGasus](https://arxiv.org/abs/2307.08701) 表明，按质量过滤到前 20% 后，训练更快且得分高于全集。[Rethinking Data Selection](https://arxiv.org/abs/2406.14115) 也证明子集选择可以超过全数据集训练。
- **减少灾难性遗忘。** 更少、更有针对性的样本意味着更少的梯度更新把模型拉离其预训练能力。这使子集选择成为数据混合的自然补充：你以更少的遗忘获得任务专精，甚至可能降低混合的必要性。

一个实用的 workflow 把就绪度评估与子集选择串在一起。学习曲线是一种诊断手段（一次训练任务并保存检查点），因此你无需反复进行全规模训练就能做出这些决定：

- 在完整数据集上运行学习曲线诊断。
- 找出饱和点。
- 如果它很早就饱和，说明数据集的长尾几乎没在增加信号。精选一个高价值子集（做质量与多样性过滤），并把它作为今后训练用的数据集。这并不是为了同样的结果再跑一次诊断：精选后的子集在今后每一次重训练周期中都训得更快，而且质量过滤常常因为去掉了给梯度增加噪声的低价值样本而得分高于全集（即本节前面引用的 AlpaGasus 结果）。
- 如果到 100% 时仍在改善，那么数据量就是瓶颈。应针对错误分析中得出的失败案例收集更多数据，而不是收集更多同分布的数据。
- 如果定向数据很昂贵，可以考虑用带程序化验证的强化微调作为更高效的路径。

## 数据增强

当你的数据集太小或太窄时，数据增强可以在不产生成比例标注成本的情况下扩充它。对现代 SFT 而言，影响最大的增强形式是生成推理轨迹和合成示例。在实践中，大多数团队通过以下三种方式之一获得增强数据：

- **从更强的模型蒸馏。** 用像 [DeepSeek-R1](https://arxiv.org/abs/2501.12948) 这样能力强的 teacher 模型或某个前沿商业模型生成轨迹或回答，校验最终答案，并只保留最终答案正确的样本上的输出。大多数开源推理数据集都是这样构建的。
- **自我生成再过滤。** 让你正在微调的基座模型以较高 temperature 为每个问题生成多个候选回答，然后只保留最终答案正确、或推理在多个样本之间自洽的那些。这就是 [STaR](https://arxiv.org/abs/2203.14465) 背后的核心思想。
- **为高风险领域放大人工编写的数据。** 当正确性比数量更重要时，例如在医疗、法律或安全攸关的场景中，由专家编写的样本仍是黄金标准。你可以用大语言模型（LLM）在保留逻辑步骤的前提下，把专家的推理改写为多种风格，从而放大这些样本。

除了推理轨迹之外，经典的增强技术会直接扩充指令数据集。[Self-Instruct](https://arxiv.org/abs/2212.10560) 从一小批种子样本自举出新的指令-回答对，而 [Evol-Instruct](https://arxiv.org/abs/2304.12244) 沿着受控维度（例如增加约束或提出更深的推理要求）演化已有指令。更简单的变换同样有效：改写 prompt 以覆盖不同措辞，以及重排回答格式以匹配你的目标输出风格。这些技术直接作用于预测 SFT 泛化能力的覆盖度与深度属性。

有两条质量原则统领增强数据。第一，风格上的多样性很重要，而不只是内容。两个都正确但结构不同的解法比同一个解法的两份拷贝更有用——[MAmmoTH](https://arxiv.org/abs/2309.05653) 就利用了这一模式。第二，验证不可妥协。每个增强样本都应通过与人工精编数据相同的质量门槛，因为合成生成是重复样本和细微错误最常见的来源之一。在增强数据进入训练集之前，先套用第一篇中的去重与过滤步骤。

## 数据混合模式

当你为某个特定任务微调模型时，就有可能在模型的其他能力上造成退化，这一现象被称为灾难性遗忘。数据混合通过把你的目标任务数据与能够保住模型既有强项的样本混在一起来解决这个问题。在 Amazon Nova 定制方面，[Amazon Nova Forge](https://aws.amazon.com/nova/forge/) 支持这一模式，因此你可以在定制的每个阶段把专有数据与 Amazon 精编的训练数据混合。

一个重要细节：数据混合并不总能帮到你的目标任务。它的主要目的是在专精的同时保留通用能力，而混入通用数据往往会直接损害你的领域指标，因为每一个通用数据的 token 都挤掉了一个领域数据的 token。当数据源共享底层推理模式时，正迁移确实会发生：[Qwen2.5-Coder](https://arxiv.org/abs/2409.12186) 发现，代码、文本和数学按 70:20:10 的比例混合，其表现超过了 100% 代码训练，即使在编码基准上也是如此。

反过来，当 token 长度不平衡让通用数据主导损失时，混合也会造成伤害：如果通用数据的序列长得多，那么按样本数只占 5% 的通用数据混合，在按 token 数计算时可能占梯度信号的 80% 以上。要监控 token 级别的比例，而不只是样本级别的比例。

实际含义是：把数据混合当作针对通用能力的一份保险，而不是提升目标任务的性能助推器。

### 数据混合如何工作

你不必只使用任务特定数据训练，而是按受控比例从多个数据源组合出每一个训练 batch。一个典型的混合可能是 70% 目标任务、20% 通用指令遵循、10% 安全数据。混合发生在 batch 层面，因此模型在整个训练过程中看到的分布是一致的。

在开始实验之前，SFT 混合文献中有几项实证发现值得了解。[Dong 等人](https://arxiv.org/abs/2405.14908)发现，每项技能上数据的绝对量对性能的驱动作用，比类别之间的精确比例更大，因此如果某项技能较弱，应先为它增加数据，再考虑重新配比。[Dual-stage Mixed Fine-Tuning](https://arxiv.org/abs/2311.14316) 表明，先训专门数据、再训「通用数据掺少量专门数据」的混合，胜过纯顺序训练（会遗忘）和平铺混合（会互相干扰）。而 [Cao 等人](https://arxiv.org/abs/2503.09837) 表明，最优混合会随模型规模和数据预算而变化，因此不存在通用比例，你应当做好实验的计划。

### 自动化混合优化

当候选数据源很多、又负担不起手动遍历所有组合时，自动化方法可以用一小部分算力找到接近最优的权重。[DoReMi](https://arxiv.org/abs/2305.10429) 训练一个小规模的 proxy 模型，并上调超额损失最高的那些领域的权重，由此得到的权重可以可靠地迁移到全规模训练。[RegMix](https://arxiv.org/abs/2407.01492) 通过多次小规模训练拟合一个从混合权重预测性能的回归，这在你在意特定下游基准时很有用。[Dynamic Data Mixing](https://arxiv.org/abs/2405.14908) 在训练过程中根据每个数据源仍在贡献多少来调整权重，通常比最好的静态混合高出 2–5%。

| **场景** | **推荐做法** |
| --- | --- |
| 2–3 个数据源，优先级清晰 | 手动：尝试 3 组固定比例，选出最好的 |
| 超过 5 个数据源，交互关系不明 | RegMix：用 50 次小规模训练拟合一个回归 |
| 大规模训练，可负担 proxy 预算 | DoReMi：训练一个小规模 proxy 来寻找权重 |
| 反复训练、数据持续演进 | 动态：在每次训练中调整权重 |

对大多数刚上手的实践者来说，手动方法就足够了：挑 3–5 组体现不同优先级的候选混合，各做一次短训练，评估，然后把胜出的那组放大。当你有超过五个数据源，或者要跑规律的重训练周期时，再升级到自动化方法。

### 选择你的混合比例

不存在通用的最优比例。按经验法则，任务越专，混合就越偏向目标任务：像医疗编码这样高度专门化的任务可以用到 80% 的目标数据，而语气调整这类轻量适配则更接近于均分；无论哪种情况，都建议保留 5% 到 10% 的安全数据。

针对 Amazon Nova 模型的实验显示，50/50 的划分能在专精与能力保留之间提供很好的平衡。另外三项发现值得带入你自己的实验：

- 纳入「推理-指令遵循」这一类数据。它能显著提升通用基准上的表现。
- 关注学习率。带数据混合的 SFT 对学习率很敏感，因此可以把 Low-Rank Adaptation（LoRA）默认的 1e-5 与全秩默认的 5e-6 作为起点。
- 对于多模态数据集，把视频保持在 20% 以上。这有助于维持通用基准上的表现。

### 决策框架：混还是不混？

大多数客户微调的是一个经过指令微调的模型（例如 Amazon Nova Lite 2.0 或任何开箱即用的 chat 模型），它已经被后训练过，能够遵循指令、进行对话并安全地回应。本框架假设的就是这个起点。少见的例外是从一个只做过下一 token 预测预训练的基座检查点出发——这种情况下始终要混合，因为没有什么指令遵循或安全行为需要保留。从指令微调的起点出发，先不加混合做一次短训练并评估各检查点。决策归结为两个问题，而这一次训练就能回答它们：

- **不加混合的这一轮是否过拟合了你的目标数据？** 观察这些信号：训练损失持续下降而验证损失停滞或上升，或者目标任务上的验证性能在某个中间检查点达到峰值随后退化。几千个样本的小数据集会提高这种风险，但并没有硬性阈值，它取决于 epoch 数、学习率，以及你训的是 LoRA 还是全秩。应先从训练配置上修：更少的 epoch、更早停止、更低的学习率。如果过拟合依然存在，混入通用数据可以增加梯度多样性，起到进一步的模型正则化作用。
- **同一轮训练是否让你需要的通用技能退化了？** 评估你的应用在生产中需要的能力，例如指令遵循、对话，或数学与编码。如果它们保持稳定，就不加混合直接上线，省下这笔训练成本。如果退化超出了你能容忍的范围，就加入混合，并按退化的严重程度调整通用数据的比例。

仅凭数据集规模和多样性无法回答这两个问题中的任何一个。一个 20,000 样本的医疗数据集，无论在其领域内多么多样，只要你的应用依赖数学或编码能力，它仍可能侵蚀这些能力。这正是本框架选择测量而不是假设的原因。

数据混合并不是对抗遗忘的唯一办法。如果你会随着时间反复更新模型，像 [OSFT](https://arxiv.org/abs/2409.01858) 这样的算法化方法会把每次训练限制在权重空间中不会扰动已有知识的方向上。OSFT 在 Hugging Face PEFT 中可作为即插即用的选项使用。

## 结论

本文介绍的高级策略有一个共同的主线：先测量，再行动。学习曲线分析告诉你更多数据是否有帮助。子集选择告诉你哪些数据重要。数据增强填补了靠收集无法经济地触达的缺口。而一次受控的混合实验告诉你，保留能力是否值这份训练成本。把这些当作实证问题、而不是套用默认值的团队，总能以更少的算力得到更好的模型。
