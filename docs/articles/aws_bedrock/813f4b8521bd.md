由大语言模型（LLM）驱动的搜索智能体正在改变企业检索信息的方式。搜索智能体不要求用户构造完美的查询，而是自主决定搜什么、用哪种检索策略，以及何时停止搜索。它跨多轮交互来做到这一点，基于已经检索到的内容优化自己的方法。

然而，要让这种多步行为运作良好很难。没有哪个基础模型天生就了解你的工具或你的环境。提示一个小模型，你很少能得到可靠的多轮行为。提示一个前沿模型，它通常能奏效，但你在延迟和成本上为那份能力买单。微调提供第三条路：你直接把你的工具和环境教给一个小模型。结果是一个小模型的速度和成本，配上原本只有前沿模型才有的可靠性。

尽管微调是自然的下一步，传统方法各有不足。监督微调（SFT）依赖对理想多轮轨迹的专家演示，这类演示采集成本高，且通常你的场景下根本不存在。单轮强化学习（RL），比如带可验证奖励的 RL（RLVR），一次给一个响应打分。但一个搜索智能体在多个轮次上做出相互依存的决策，每一个都建立在其前面的上下文之上。孤立地优化单个步骤会完全漏掉那些依赖关系。

你需要的是一个跨 *完整多轮轨迹* 优化智能体的训练方法。奖励信号只需反映最终结果是否好。这正是多轮强化学习（MTRL）所提供的。它训练智能体在一整个步骤序列上做出好的决策、把你环境特定的行为内建进去，并让你控制输出质量。因为你运行一个更小、更专用的模型，你还得到更快、更便宜的推理。

在本文中，我们描述如何用 *Amazon SageMaker AI 多轮强化学习（MTRL）* 微调一个搜索智能体，并分享我们在检索质量和可靠性上观察到的结果。我们先解释 Amazon SageMaker AI MTRL 是什么以及它如何工作。

## 什么是 Amazon SageMaker AI MTRL？

借助 [Amazon SageMaker AI MTRL](https://docs.aws.amazon.com/sagemaker/latest/dg/model-customize-mtrl.html)，你可以在多轮交互场景中使用强化学习微调 LLM。它把一个智能体任务框定为一个决策序列，用多轮 rollout 生成训练数据，并用策略梯度算法优化模型。

Amazon SageMaker AI MTRL 提供：

- **模块化的智能体-环境接口**：你让集成保持低代码。你定义自定义奖励、自定义工具循环和多轮对话形态。
- **无服务器执行**：你以按-token 计价获得生产规模智能体式 RL，无需配置或管理 GPU 集群。
- **异步 rollout 与轨迹采集**：你在有界的离策略陈旧度（off-policy staleness）下并行运行生成和梯度更新，因此训练保持快速而不会偏离当前策略太远。
- **原生算法库**：你可以从近端策略优化（PPO）、截断重要性采样策略优化（CISPO）和重要性采样（IS）损失中选择，配上基于组的优势估计器（GRPO、GRPO pass@k、RLOO 等）。
- **可恢复训练**：你可以把长训练运行拆成多个作业，以突破单作业时间限制。
- **轨迹与奖励可观测性**：你可以在由 Amazon SageMaker AI 管理的 MLflow 中，逐轮、跨训练步检查你的智能体做了什么。
- **评估作业**：你可以在部署到 Amazon SageMaker AI 端点或 Amazon Bedrock 之前，报告奖励、pass@k 和轨迹指标。

这让 MTRL 成为搜索智能体的天然之选：你有一个清晰的奖励信号（检索质量）、一个多轮交互循环（智能体发出查询并接收结果），以及一个定义良好的环境（搜索工具）。

## 环境设置与准备

我们的设置依赖以下条件：

- 一个 AWS 账户，可在美国西部（俄勒冈）AWS 区域（us-west-2）访问 Amazon SageMaker AI。
- 已按所需格式上传到 Amazon Simple Storage Service (Amazon S3) 的训练和验证数据集（细节见 MTRL 文档）。
- 一个已部署的智能体端点，向 MTRL 环境暴露 BM25 和向量搜索工具以供 rollout 期间调用。
- 熟悉 Amazon SageMaker AI 和 Python。

## 方案概览

在本文中，我们用 Amazon SageMaker AI MTRL 为一个搜索智能体微调一个 Qwen3.6-27B 模型（在美国西部（俄勒冈）区域 us-west-2 支持）。搜索智能体是一个 LLM 驱动的系统，它自主使用搜索工具来查找、收集和综合信息，以回答问题或完成任务。

我们聚焦于一个企业搜索场景，其中智能体有两个可用工具：

- **词汇搜索（BM25）：** 通过统计词频查找精确的关键词匹配。最适合带特定术语或标识符的查询。
- **向量搜索：** 把查询和文档转换成嵌入向量并计算相似度。这对语义或概念查询推荐。

我们还限制轮次数（一轮是一次 user-assistant 交互），防止智能体生成过长的响应并鼓励高效的搜索行为。

## 训练设置

本节演练我们训练设置的三个关键组件：数据集、奖励函数和 MTRL 作业配置。

我们按 [文档](https://docs.aws.amazon.com/sagemaker/latest/dg/model-customize-mtrl-assets.html#model-customize-mtrl-assets-prompt-dataset-format) 把这些数据集预处理成 MTRL 服务识别的格式。我们进一步在每个数据集内保留 5% 的训练实例作为验证实例。

### 奖励函数

我们的主要指标是 *nDCG@10*（前 10 位归一化折损累积增益，[Normalized Discounted Cumulative Gain at rank 10](https://en.wikipedia.org/wiki/Discounted_cumulative_gain#Normalized_DCG)）。nDCG@10 是一个标准的信息检索指标，衡量前 10 个检索到的文档在多大程度上匹配理想排序。它奖励那些把高度相关文档放在列表前列的系统，得分 1.0 意味着完美排序，0.0 意味着没有检索到相关文档。我们直接把 nDCG@10 用作 MTRL 中的奖励函数。这是一个轨迹级奖励：智能体完成它完整的多轮搜索，奖励反映最终检索到的文档在多大程度上匹配真值。

当智能体在单轮中达到最大轮数或最大采样 token 数时，我们赋一个 -1 的奖励，以显式地教模型避免这些失败模式。这种基于惩罚的奖励设计，无需手工构造复杂的中间奖励，就能有效地引导模型远离不良行为。

### MTRL 作业配置

Amazon SageMaker AI MTRL 的吸引力之一是你上手需要配置的东西很少。我们改动三个超参数，其余全部保持默认值。下面的代码片段展示如何用 MultiTurnRLTrainer SDK 配置并启动训练作业：

```
from sagemaker.modules.train import MultiTurnRLTrainer

trainer = MultiTurnRLTrainer(
    model_id="qwen3.6-27b",
    agent_endpoint="<your-agent-endpoint>",
    training_dataset_s3_uri="s3://amzn-s3-demo-bucket/datasets/train/",
    validation_dataset_s3_uri="s3://amzn-s3-demo-bucket/datasets/validation/",
    hyperparameters={
        "max_epochs": 1,
        "global_batch_size": 128,
        "rollout_max_concurrency": 32,
    },
    output_s3_uri="s3://amzn-s3-demo-bucket/output/",
)

trainer.train()
```

我们改动的关键超参数是：

- **max_epochs: 1** 控制对整个训练数据做多少遍完整遍历。
- **global_batch_size: 128** 设置每个训练步的 prompt 数。
- **rollout_max_concurrency: 32** 控制在轨迹采集期间并行运行多少次 rollout。

以上就是全部设置。那些通常需要 RL 专业知识的抉择——算法、优势估计器、离策略陈旧度界限——全都按默认运行。从基础模型到下一节的结果，只需要上面这份配置即可。

## 结果

MTRL 微调在四个留出基准中的三个上改进了搜索智能体，并让它在所有基准上显著更可靠。最大的收益来自 BrowseComp-Plus（nDCG@10 +23.7%）和 WixQA（+18.4%），Wands 上收益较小，FreshStack 上有轻微退化。可靠性提升是更引人注目的结果。在 BrowseComp-Plus 上，失败率从 22.89% 降到 0.68%。这意味着智能体不仅学会了更好地搜索，还学会了在其轮次和 token 预算内完成任务。下面各节逐一演练训练曲线和逐基准数字。

### 测试性能

**列定义：**

- **Size** 是数据集中的问题数。

结果表明 RL 微调带来了实质性的差异：

- **更好的搜索质量：** 如上面表格所示，nDCG@10 在 WixQA（从 0.5725 到 0.6781，+18.4%）、Wands（从 0.5762 到 0.6112，+6%）和 BrowseComp-Plus（从 0.5136 到 0.6354，+23.7%）上有所提升。FreshStack 上的分数略有下降。
- **更少的失败：** 对失败案例赋一个 -1 的奖励非常有效。在 BrowseComp-Plus 上，失败率从 22.89% 降到仅 0.68%。

## 结论

在本文中，我们描述了用 Amazon SageMaker AI MTRL 以强化学习微调一个 LLM 驱动的搜索智能体的经验。用最少的配置，微调后的模型在检索质量、失败率和轮次效率（每问更少轮次）上表现出显著提升。

我们从 Amazon SageMaker AI MTRL 经验中的关键要点：

- **入门门槛低：** 默认配置效果良好，上手不需要深厚的 RL 专业知识。
- **无服务器基础设施：** 无需配置 GPU 或管理分布式训练集群。你按 token 付费。
- **可恢复训练：** 长训练运行可拆分到多个作业。
- **直接优化：** 你针对实际任务指标训练，而非代理损失。
- **完全可观测：** 你可以在由 Amazon SageMaker AI 管理的 MLflow 中逐轮检查轨迹，以理解智能体学到了什么。
