# PropHero 如何用 Amazon Bedrock 构建带持续评估的智能房产投资顾问

*本文与 PropHero 的 Lucas Dahan、Dil Dolkun 和 Mathew Ng 共同撰写。*

[PropHero](https://prophero.com.au/) 是一家领先的房产财富管理服务商，通过大数据、AI 和机器学习（ML）让智能房产投资建议惠及更多人。面向西班牙和澳大利亚的消费者群体，PropHero 需要一个 AI 驱动的顾问系统，能够与客户展开准确的房产投资讨论。目标是提供个性化的投资洞见，并在用户投资旅程的每个阶段提供引导与协助：从了解流程、看清时间线、安全上传文件，到实时跟踪进度。

PropHero 与 [AWS Generative AI Innovation Center](https://aws.amazon.com/generative-ai/innovation-center/) 合作，利用 AWS 生成式 AI 服务并配合持续评估，落地了一个智能房产投资顾问。该方案帮助用户以自然语言讨论房产投资策略，并基于 PropHero 全面的市场知识获得个性化建议。

本文探讨我们如何使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 构建一个多 agent 对话式 AI 系统，提供以知识为依据的房产投资建议。我们会介绍 agent 架构、模型选择策略，以及支撑高质量对话、便于快速迭代改进的全面持续评估体系。

## 挑战：让房产投资知识更易获得

房产投资领域对新手和有经验的投资者都提出了诸多挑战。信息不对称造成壁垒，全面的市场数据要么昂贵要么难以获取。传统的投资流程依靠人工、耗时，且需要大量市场知识才能有效推进。具体到西班牙和澳大利亚的消费者，我们需要构建一个能用西班牙语提供准确、切合语境的房产投资建议的方案，同时应对关于投资策略的复杂多轮对话。系统需要在规模化交付响应的同时保持高准确率，并从客户交互中持续学习与改进。最重要的是，它要在用户旅程的每个阶段提供协助，从最初的入门引导一直到最终结算，确保整个投资过程都得到全面支持。

## 方案概览

我们使用 AWS 生成式 AI 服务构建了一套完整的端到端方案，围绕一个多 agent AI 顾问进行架构设计，并集成持续评估。系统实现了从数据摄取到智能顾问对话的无缝数据流，并带实时质量监控。下图展示了这一架构。

![架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/16/ML-18952-arch.jpeg)

该方案架构由四个虚拟层组成，每一层在整体系统设计中承担特定职能。

### 数据基础层

数据基础层为系统各组件提供存储与检索基础设施：

- [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) – 快速存储对话历史、评估指标和用户交互数据
- [Amazon Relational Database (Amazon RDS) for PostgreSQL](https://aws.amazon.com/rds/postgresql/) – 一个 PostgreSQL 数据库，存储 LangFuse 可观测性数据，包括大语言模型（LLM）的 trace 和延迟指标
- [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/s3/) – 一个中央数据湖，存储西班牙语 FAQ 文档、房产投资指南和对话数据集

### 多 agent AI 层

AI 处理层包含驱动对话体验的核心智能组件：

- [Amazon Bedrock](https://aws.amazon.com/bedrock/) – 基础模型（FM），如支撑各类专用 agent 的 LLM 和 reranker
- [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) – 带语义分块的语义搜索引擎，面向 FAQ 类内容
- [LangGraph](https://www.langchain.com/langgraph) – 编排多 agent 工作流并管理对话状态
- [AWS Lambda](https://aws.amazon.com/lambda/) – 无服务器函数，执行多 agent 逻辑并检索用户信息以获得更丰富的上下文

### 持续评估层

评估基础设施通过以下组件实现持续的质量监控与改进：

- [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) – 实时监控质量指标，具备自动告警和阈值管理
- [Amazon EventBridge](https://aws.amazon.com/eventbridge/) – 为对话完成和质量评估提供实时事件触发
- [AWS Lambda](https://aws.amazon.com/lambda/) – 自动评估函数，衡量上下文相关性、响应有据性和目标准确率
- [AWS Quick Sight](https://aws.amazon.com/quicksight/) – 交互式仪表盘与分析，用于监控各项指标

### 应用与集成层

集成层为外部通信提供安全接口：

- [Amazon API Gateway](https://aws.amazon.com/api-gateway/) – 为对话界面和评估 webhook 提供安全的 API 端点

## 多 agent AI 顾问架构

这个智能顾问使用一个通过 [LangGraph](https://www.langchain.com/langgraph) 编排的多 agent 系统，它位于单个 Lambda 函数中，每个 agent 都针对特定任务做了优化。下图展示了 Lambda 函数内各 agent 之间的通信流程。

![多 agent 图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/16/ML-18952-flow.png)

### agent 组成与模型选择

我们的模型选择策略包含大量测试，以便把每个组件的算力需求匹配到最具性价比的 Amazon Bedrock 模型。我们评估了响应质量、延迟要求和每 token 成本等因素，为每类 agent 确定最优的模型分配。系统中的每个组件都为其指定职能使用最合适的模型，如下表所示。

| **组件** | **Amazon Bedrock 模型** | **用途** |
| --- | --- | --- |
| Router Agent | Anthropic Claude 3.5 Haiku | 查询分类与路由 |
| General Agent | Amazon Nova Lite | 常见问题与对话管理 |
| Advisor Agent | Amazon Nova Pro | 专业的房产投资建议 |
| Settlement agent | Anthropic Claude 3.5 Haiku | 专注于投资结算前阶段的客户支持 |
| Response Agent | Amazon Nova Lite | 最终响应的生成与格式化 |
| Embedding | Cohere Embed Multilingual v3 | 上下文检索 |
| Retriever | Cohere Rerank 3.5 | 上下文检索与排序 |
| Evaluator | Anthropic Claude 3.5 Haiku | 质量评估与打分 |

### 端到端对话流程

对话处理遵循一套结构化的工作流，在保持质量标准的同时促成准确响应：

- 用户查询通过 API Gateway 进入，并被路由到 router agent。
- router agent 根据查询分析确定合适的专用 agent。
- 开始时先检索用户信息以获得更丰富的上下文，知识密集型的查询会触发 retriever 访问 Amazon Bedrock 知识库。
- 专用 agent 结合检索到的用户信息和知识库中的相关上下文处理查询。
- response agent 以恰当的语气组织并生成最终面向用户的响应。
- 并行的评估流程会评估上下文相关性、响应有据性和目标准确率。
- 对话数据存入 DynamoDB，用于分析与改进。

### Amazon Bedrock Knowledge Bases 配置

知识库使用多项 AWS 服务以获得最佳性能：

- **数据源** – S3 存储桶
- **分块策略** – 针对 FAQ 类内容优化的语义分块
- **Embedding 模型** – Cohere Embed Multilingual v3，用于理解西班牙语
- **Reranker** – Cohere Rerank 3.5，用于对检索到的西班牙语内容重新排序
- **向量数据库** – [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/)，用于可扩展的语义搜索

## 集成的持续评估体系

持续评估体系已集成到架构中，作为核心组件运行。这种做法支持在处理对话的同时实时监控质量。

### 评估指标

我们使用 [Ragas](https://docs.ragas.io/en/stable/) 库中的以下指标进行评估：

- **上下文相关性（0–1）** – 衡量检索到的上下文与用户查询的相关程度，评估 RAG 系统的有效性
- **响应有据性（0–1）** – 确保响应在事实上准确，且源自 PropHero 的官方信息
- **agent 目标准确率（0–1）** – 以二元方式衡量响应是否成功回应用户的投资目标

### 实时评估工作流

评估体系在对话架构中无缝运行：

- **Amazon **DynamoDB Streams** 触发** – 写入 DynamoDB 的对话数据会通过 [Amazon DynamoDB Streams](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Streams.html) 自动触发一个 Lambda 函数进行评估
- **并行处理** – Lambda 函数与响应交付并行执行评估逻辑
- **多维评估** – 每段对话都会同时按三个关键维度进行评估
- **基于 LLM-as-a-judge 的智能打分** – Anthropic 的 Claude 3.5 Haiku 作为 LLM 裁判提供一致的评估，为各段对话给出标准化的评估标准。
- **监控与分析** – CloudWatch 采集评估过程中的指标，Quick Sight 提供用于趋势分析的仪表盘

## 实现心得与最佳实践

我们的开发历程是与 PropHero 技术团队共 6 周的迭代过程。我们在不同模型组合上做了测试，并用真实的客户 FAQ 数据评估了分块策略。这段历程带来了若干架构优化，提升了系统性能、实现了显著的成本下降，并改善了用户体验。

### 模型选择策略

我们在模型选择上的做法说明了把模型能力与具体任务匹配的重要性。通过把较简单的任务交给 Amazon Nova Lite、把复杂推理交给 Amazon Nova Pro，该方案在保持高准确率标准的同时取得了最优的成本性能平衡。

### 分块与检索优化

对于 FAQ 类内容，语义分块被证明优于层级分块和固定分块。Cohere Rerank 3.5 模型让系统在使用更少分块的情况下（10 个对 20 个）仍保持准确率，从而降低延迟与成本。

### 多语言能力

系统利用 Amazon Bedrock 上支持西班牙语的 FM，有效处理西班牙语和英语查询。

## 业务影响

PropHero AI 顾问带来了可衡量的业务价值：

- **提升客户参与度** – 90% 的目标准确率确保客户获得相关且可执行的房产投资建议。超过 50% 的用户（以及超过 70% 的付费用户）正在积极使用 AI 顾问。
- **运营效率** – 常见问题的自动回复把客服工作量降低了 30%，让员工可以把精力放在复杂的客户需求上。
- **可扩展增长** – 无服务器架构可自动扩展以应对不断增长的客户需求，无需人工干预。
- **成本优化** – 有策略的模型选择在实现高性能的同时，把 AI 成本相比全程使用高端模型降低了 60%。
- **扩大消费者基础** – 成功的西班牙语支持让 PropHero 凭借本地化的专业能力拓展到西班牙消费者群体。
