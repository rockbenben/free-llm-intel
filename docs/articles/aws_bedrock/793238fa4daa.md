# 使用 Amazon Nova 和 Amazon Bedrock Data Automation 构建 agentic 多模态 AI 助手

现代企业的数据非常丰富，且跨越多种模态——从文本文档和 PDF 到演示文稿、图像、录音等等。想象一下向 AI 助手询问公司的季度财报电话会议：助手不仅要阅读文字记录，还应“看到”演示文稿中的图表，并“听到” CEO 的发言。Gartner 预测，到 2027 年，[40% 的生成式 AI 解决方案将是多模态的](https://www.gartner.com/en/newsroom/press-releases/2024-09-09-gartner-predicts-40-percent-of-generative-ai-solutions-will-be-multimodal-by-2027)（文本、图像、音频、视频），而 2023 年这一比例仅为 1%。这一转变凸显了多模态理解对业务应用正变得多么关键。要实现这一点，需要一个多模态生成式 AI 助手——它能够理解并组合文本、视觉与其他数据类型。它还需要一种 agentic 架构，使 AI 助手能够主动检索信息、规划任务并就工具调用做出决策，而不是仅仅被动地响应 prompt。

本文中，我们探讨一个正是这样做的解决方案——使用来自 AWS 的多模态大语言模型（LLM）[Amazon Nova Pro](https://aws.amazon.com/ai/generative-ai/nova/) 作为中央编排器，并结合 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的强大新特性，例如用于处理多模态数据的 [Amazon Bedrock Data Automation](https://aws.amazon.com/bedrock/bda/)。我们演示[检索增强生成](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）、[多工具编排](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-multi-agent-collaboration.html) 以及使用 [LangGraph](https://www.langchain.com/langgraph) 的条件路由等 agentic 工作流模式，如何构成端到端解决方案，供人工智能与机器学习（AI/ML）开发者和企业架构师采用并扩展。我们会走查一个财务管理 AI 助手的示例，它通过分析财报电话会议（音频）和演示文稿（图像）以及相关财务数据源，提供量化研究与有依据的财务建议。我们还会说明如何把这一模式应用到金融、医疗和制造业等行业。

## agentic 工作流概览

agentic 模式的核心由以下几个阶段组成：

- **推理（Reason）** – agent（通常是 LLM）检查用户的请求以及当前的上下文或状态。它决定下一步应该做什么——是直接给出答案，还是调用工具或子任务以获取更多信息。
- **行动（Act）** – agent 执行该步骤。这可能意味着调用工具或函数，例如搜索查询、数据库查询，或使用 Amazon Bedrock Data Automation 进行文档分析。
- **观察（Observe）** – agent 观察行动的结果。例如，它读取工具返回的检索文本或数据。
- **循环（Loop）** – 手握新信息，agent 再次推理，判断任务是否完成或是否需要另一步。这一循环持续进行，直到 agent 确定它可以为用户给出最终答案。

这种迭代式决策使 agent 能够处理单个 prompt 无法完成的复杂请求。然而，实现 agentic 系统可能颇具挑战。它们会在控制流中引入更多复杂性，而且朴素的 agent 可能效率低下（发起过多工具调用或进行不必要的循环），或者随着规模扩大而难以管理。这正是 LangGraph 这类结构化框架的用武之地。LangGraph 让定义潜在动作的有向图（或状态机）成为可能，其节点（如“Report Writer”或“Query Knowledge Base”这类动作）和边（允许的转换）都定义明确。尽管仍然由 agent 的内部推理决定走哪条路径，LangGraph 确保整个过程可控且透明。这种受控的灵活性意味着助手拥有足够的自主性来处理多样任务，同时确保整体工作流稳定且可预测。

## 解决方案概述

该解决方案是一个财务管理 AI 助手，旨在帮助分析师查询投资组合、分析公司并生成报告。其核心是 Amazon Nova，一个充当智能推理引擎的 LLM。Amazon Nova 处理文本、图像或文档（例如财报电话会议的幻灯片），并动态决定使用哪些工具来满足请求。Amazon Nova 针对企业任务做了优化，并支持[函数调用](https://docs.aws.amazon.com/nova/latest/userguide/tool-use.html)，因此模型可以以结构化方式规划动作并调用工具。凭借[大上下文窗口](https://docs.aws.amazon.com/nova/latest/userguide/what-is-nova.html)（在 Amazon Nova Lite 和 Amazon Nova Pro 中最高可达 300,000 个 token），它在推理时可以管理长文档或对话历史。

该工作流由以下关键组件组成：

- **知识库检索** – 财报电话会议音频文件和 PowerPoint 文件都由 Amazon Bedrock Data Automation 处理，这是一项托管服务，可提取文本、转录音频和视频，并为分析准备数据。如果用户上传 PowerPoint 文件，系统会把每张幻灯片转换为图像（PNG），以便高效搜索和分析，这一技巧借鉴了 [Manus](https://manus.im/) 等生成式 AI 应用。Amazon Bedrock Data Automation 本质上就是一个开箱即用的多模态 AI 管道。在我们的架构中，Amazon Bedrock Data Automation 充当原始数据与 agentic 工作流之间的桥梁。随后 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 使用 [Amazon Titan Text Embeddings V2](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html) 把从 Amazon Bedrock Data Automation 提取的这些 chunk 转换为向量嵌入，并将这些向量存储在 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/) 数据库中。
- **Router agent** – 当用户提出问题（例如“总结这份 Q3 财报中的关键风险”）时，Amazon Nova 会先判断该任务是需要检索数据、处理文件，还是生成回答。它维护对话的记忆、解释用户的请求，并规划要采取哪些动作来满足请求。解决方案示意图中的“Memory & Planning”模块表明，router agent 可以使用对话历史和思维链（chain-of-thought，CoT）提示来确定后续步骤。关键在于，router agent 会判断该查询能否用公司内部数据回答，还是需要外部信息和工具。
- **多模态 RAG agent** – 对于与音频和视频信息相关的查询，Amazon Bedrock Data Automation 通过统一的 API 调用从此类多媒体数据中提取洞察，并把提取的洞察存储在 Amazon Bedrock Knowledge Bases 中。Amazon Nova 使用 Amazon Bedrock Knowledge Bases 通过语义搜索检索事实性答案。这确保回答以真实数据为依据，将幻觉降到最低。如果 Amazon Nova 生成了答案，还会有一次二级幻觉检查，把回答与可信来源交叉比对，以捕捉缺乏支撑的说法。
- **幻觉检查（质量门）** – 为进一步验证可靠性，工作流可以包含一个后处理步骤，使用 Amazon Nova 系列之外的其他基础模型（FM），例如 Anthropic 的 Claude、Mistral 或 Meta 的 Llama，对答案的忠实度进行评分。例如，在 Amazon Nova 生成响应后，幻觉检测模型或函数可以把答案与检索到的来源或已知事实进行比对。如果检测到潜在的幻觉（答案不被参考数据支持），agent 可以选择进行额外的检索、调整答案，或升级给人工处理。
- **多工具协作** – 这种多工具协作让 AI 不仅能够查找信息，还能在形成最终答案之前采取行动。这引入了多工具选项。supervisor agent 可以派生或协调多个特定工具的 agent（例如，一个执行通用网页搜索的 web search agent、一个获取市场数据的 stock search agent，或针对公司财务指标与行业新闻的其他专用 agent）。每个 agent 执行一项聚焦的任务（某个可能调用 API，或在互联网上执行查询），并把发现返回给 supervisor agent。Amazon Nova Pro 具备强大的推理能力，使 supervisor agent 能够合并这些发现。这种多 agent 方法遵循把复杂任务分派给专家 agent 的原则，提升了复杂查询的效率与可靠性。
- **报告生成 agent** – 架构中另一个值得注意的方面是使用 Amazon Nova Canvas 进行输出生成。Amazon Nova Canvas 是 Amazon Nova 系列中专用的图像生成模型，但在此上下文中，我们更形象地使用“canvas”这一概念，指代结构化的模板或格式化的内容输出。例如，我们可以为“投资者报告”定义一个模板，由助手来填写：第 1 节：关键亮点（要点列表），第 2 节：财务摘要（数据表格），第 3 节：值得注意的引述，等等。agent 可以通过向 Amazon Nova 提供包含所需格式的 system prompt 来引导其填充这样的模板（这类似于 few-shot prompting，即给定布局）。结果是，助手不仅回答临时提出的问题，还能生成看起来像人类分析师撰写的全面报告，把文本、图像和对视觉素材的引用结合起来。

这些组件在一个 agentic 工作流中进行编排。该解决方案不使用固定的脚本，而是使用动态决策图（在 notebook 解决方案中用开源的 LangGraph 库实现）在各步骤之间路由。其结果是，这个助手感觉上不太像聊天机器人，而更像一位协作型分析师——它能够解析财报电话会议录音、点评一份幻灯片，或在极少人工干预的情况下起草投资者备忘录。

## 多工具协作工作流示例

为演示多工具协作 agent 工作流，我们探讨一个示例，说明一次问答交互在我们已部署的多工具协作系统中可能如何流转：

- **用户 prompt** – 在聊天 UI 中，最终用户提出一个问题，例如“XXX 今年的股票表现如何，与其网约车行业的同行相比又如何？”
- **agent 的初始响应** – agent（Amazon Nova FM 编排器）收到问题并回应：  `Received your question. Routing to the reasoning engine…`
- **规划与工具选择** – agent 判断它需要以下内容：  公司（XXX）的股票代码  实时股价与年初至今（YTD）变化  关键财务指标（营收、净收入、市盈率）  行业基准（同行 YTD 表现、平均营收增长率）
- **使用工具调用规划执行** – agent 调用工具执行以下动作：  查询股票代码：  `Agent → WebSearchTool.lookupTicker("XXX Inc") WebSearchTool → Agent: returns "XXX"`  使用检索到的股票代码获取实时股价表现：  `Agent → StockAnalysisTool.getPerformance( symbol="XXX", period="YTD" ) StockAnalysisTool → Agent: { currentPrice: ytdChange: 52wkRange: volume: }`  使用检索到的股票代码获取公司财务指标：  `Agent → CompanyFinancialAnalysisTool.getMetrics("UBER") CompanyFinancialAnalysisTool → Agent: { revenueQ4_2024: xxx B, netIncomeQ4_2024: xxx M, peRatio: xxx }`  使用检索到的股票代码收集行业基准数据：  `Agent → IndustryAnalysisTool.comparePeers( symbol="XXX", sector="Rideshare" ) IndustryAnalysisTool → Agent: { avgPeerYTD: avgRevenueGrowth: }`  **验证循环** – agent 运行验证循环：  `Agent: validate() ↳ Are all four data points present? • Ticker :heavy_check_mark: • Stock performance :heavy_check_mark: • Financial metrics :heavy_check_mark: • Industry benchmark :heavy_check_mark: ↳ All set—no retry needed.`

如果有任何内容缺失，或某个工具遇到错误，FM 编排器会触发错误处理器（最多重试三次），然后从失败的那一步继续执行计划。

- **综合与最终回答** – agent 使用 Amazon Nova Pro 综合这些数据点，并基于这些数据点生成最终回答。

## 使用 Amazon Bedrock 实现可扩展生成式 AI agent 工作流的优势

该解决方案构建在 Amazon Bedrock 之上，因为 AWS 提供了一体化的生态系统，可用于大规模构建此类复杂解决方案：

- Amazon Bedrock 提供 Amazon Nova 等顶级 FM，并配有托管基础设施——无需预置 GPU 服务器，也无需处理扩展的复杂性。
- Amazon Bedrock Data Automation 提供开箱即用的解决方案，可把文档、图像、音频和视频处理为可操作的数据。Amazon Bedrock Data Automation 可以把演示文稿转换为图像、把音频转换为文本、执行 OCR，并生成文本摘要或说明文字，随后在 Amazon Bedrock knowledge bases 中建立索引。
- Amazon Bedrock Knowledge Bases 可以存储来自非结构化数据的嵌入，并支持使用相似度搜索进行检索操作。
- 除了 LangGraph（如本解决方案所示），你还可以使用 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 开发 agentic 工作流。Amazon Bedrock Agents 简化了工具流和操作组的配置，因此你可以声明式地管理 agentic 工作流。
- 由 LangGraph（LangChain 的扩展）等开源框架开发的应用，也可以在 [Amazon Elastic Compute Cloud](https://aws.amazon.com/ec2)（Amazon EC2）或 [Amazon SageMaker](https://aws.amazon.com/sagemaker/) 实例等 AWS 基础设施上运行和扩展，因此你可以为 agent 编排定义有向图，轻松管理多步推理与工具链。

你无需拼装十几个彼此割裂的系统；AWS 为生成式 AI 工作流提供了集成化的网络。

## 注意事项与定制

该架构通过模块化的设计原则展现出非凡的灵活性。系统的核心使用 Amazon Nova FM，可根据任务复杂度进行选择。Amazon Nova Micro 以极低延迟处理分类等直接的任务。Amazon Nova Lite 以均衡的性能管理中等复杂度的操作，而 Amazon Nova Pro 擅长需要高级推理或生成全面回答的复杂任务。

该解决方案的模块化特性（Amazon Nova、工具、知识库和 Amazon Bedrock Data Automation）意味着每一部分都可以替换或调整，而无需大改整个系统。解决方案架构师可以把这一参考架构作为基础，按需实施定制。你可以通过 [AWS Lambda](https://aws.amazon.com/lambda) 函数为专门的操作无缝集成新能力，而 LangGraph 编排则支持动态模型选择和精细路由逻辑。这种架构方法确保系统能够有机演进，同时保持运营效率与成本效益。

将其投入生产需要周密的设计，但 AWS 提供了可扩展性、安全性和可靠性。例如，你可以通过加密和访问控制保护知识库内容；把 agent 与 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）集成，确保它只执行被允许的操作（例如，如果某个 agent 可以访问敏感的财务数据，要验证它会检查用户权限）；并监控成本（你可以跟踪 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/) 和工具使用情况；对于稳定的高用量场景，你可能会使用[预置吞吐量](https://docs.aws.amazon.com/bedrock/latest/userguide/prov-throughput.html)）。此外，借助 AWS，当条件成熟时，你可以用同样的构建模块（若作为服务部署，则与 [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 或 Lambda 等适当的 AWS 基础设施集成）从 notebook 中的实验扩展到完整的生产部署。

## 可受益于该解决方案的垂直行业

我们描述的架构相当通用。下面简要看一下这种多模态 agentic 工作流如何在不同行业创造价值：

- **金融服务** – 在金融领域，该解决方案集成多媒体 RAG，把财报电话会议记录、演示文稿（转换为可搜索的图像）和实时市场数据源统一到单一分析框架中。多 agent 协作让 Amazon Nova 能够编排 Amazon Bedrock Data Automation（用于幻灯片文本提取）、针对监管文件的语义搜索，以及用于趋势检测的实时数据 API 等工具。这使系统能够生成可操作的洞察——例如识别投资组合风险或建议行业再平衡——同时自动化投资者报告或交易审批的内容创作（并保留人工监督）。通过模仿分析师交叉引用多种数据类型的能力，该 AI 助手把零散的输入转化为连贯的策略。
- **医疗** – 医疗工作流使用多媒体 RAG 处理临床记录、检验 PDF 和 X 光片，让回答以同行评审文献和患者音频访谈为依据。多 agent 协作在分诊等场景中表现出色：Amazon Nova 解读症状描述，Amazon Bedrock Data Automation 从扫描文档中提取文本，集成的 API 检查药物相互作用，同时还会对照可信来源验证输出。内容创作的范围从简洁的患者摘要（“重症肺炎，已用 levofloxacin 治疗”）到针对复杂查询的循证回答，例如总结糖尿病指南。该架构严格的幻觉检查和来源引用保证了可靠性，这对维持医疗决策中的信任至关重要。
- **制造业** – 工业团队使用多媒体 RAG 为设备手册、传感器日志、工人音频对话和示意图建立索引，从而实现快速排障。多 agent 协作让 Amazon Nova 能够把传感器异常与手册片段关联起来，Amazon Bedrock Data Automation 则在技术图纸中标出故障部件。系统会生成维修指南（例如“更换示意图中的 Part 4 阀门”），或为历史维护数据提供上下文，从而弥合资深专家与新手技术员之间的差距。通过把文本、图像和时间序列数据统一为可操作的内容，该助手减少了停机时间并留存了机构知识——证明即使在以硬件为中心的领域，AI 驱动的洞察也能够提升效率。

这些示例凸显了一个共同模式：数据自动化、强大的多模态模型与 agentic 编排的协同，产生了极为接近人类专家协助的解决方案。金融 AI 助手像分析师那样交叉核对数字与解释，临床 AI 助手像敬业的医生那样关联图像与记录，工业 AI 助手像资深工程师那样忆起图纸与日志。这一切都得益于我们构建的底层架构。

## 结论

只处理单一输入类型的孤立 AI 模型时代正走向终结。正如我们所讨论的，把多模态 AI 与 agentic 工作流结合，为企业应用开启了全新的能力层级。本文中，我们演示了如何使用 AWS 服务构建这样的工作流：我们用 Amazon Nova 作为核心 AI 编排器，发挥其多模态、对 agent 友好的能力；用 Amazon Bedrock Data Automation 把复杂数据（文档、幻灯片、音频）摄取并索引到 Amazon Bedrock Knowledge Bases，实现自动化；还使用了 agentic 工作流图这一概念（借助 LangChain 或 LangGraph）来编排多步推理与工具使用。最终得到的 AI 助手运作方式很像一位敬业的分析师：做研究、交叉核对多个来源并交付洞察——但是以机器的速度与规模。该解决方案表明，构建复杂的 agentic AI 系统不再是学术幻想——借助今天的 AWS 技术，它既实用又可实现。通过把 Amazon Nova 用作强大的多模态 LLM、把 Amazon Bedrock Data Automation 用于多模态数据处理，再加上 LangGraph（或 Amazon Bedrock Agents）这类工具编排框架，开发者就有了先发优势。许多挑战（例如 OCR、文档解析或对话编排）都由这些托管服务或库来处理，因此你可以专注于业务逻辑和特定领域的需求。

[BDA_nova_agentic](https://github.com/aws-samples/amazon-nova-samples/tree/main/multimodal-understanding/repeatable-patterns/16-multimodal-agentic-workflow) 示例 notebook 中给出的解决方案是实验这些想法的绝佳起点。我们鼓励你动手尝试、扩展它，并根据组织的需求进行调整。我们很期待看到你会构建什么——当你把多种模态与智能 agent 结合时，本文讨论的技术只代表了可能性的很小一部分。
