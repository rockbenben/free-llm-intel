# 在 Amazon Quick Sight 图层地图中使用 GeoJSON 可视化点和路线

借助 Amazon Quick Sight 图层地图，您现在可以绘制点和路线，例如城市中的商店位置或离开机场的航班。地理空间地图可帮助企业发现与位置相关的模式，例如某个地区的表现或客户集中的地方。 Amazon Quick Sight 支持多种地图类型，包括点地图、填充地图和图层地图。当[图层地图首次启动](https://aws.amazon.com/blogs/business-intelligence/create-custom-shape-maps-in-amazon-quicksight/)时，您可以上传 GeoJSON 文件来绘制自定义形状图层（例如销售区域或地区），并将这些形状加入数据集。这很好地处理了区域和边界，但它没有涵盖其中的各个位置或它们之间的路线。

图层图现在支持同一 GeoJSON 工作流程中的另外两种几何类型：*Point* 和 *LineString*。点标记特定位置，例如单个商店或设施地点。 LineString 跟踪位置之间的路线，例如送货路径或机场之间的航班。

[Amazon Quick Sight](https://aws.amazon.com/quick/quicksight/) 是 [Amazon Quick](https://aws.amazon.com/quick/) 的商业智能 (BI) 功能，是一项统一的 BI 服务。它提供现代交互式仪表板、自然语言查询、像素完美的报告、机器学习 (ML) 见解和大规模嵌入式分析。 Amazon Quick 将用于业务洞察、研究和自动化的 AI 代理整合到一种集成体验中，帮助您更智能、更快速地工作，同时维护安全性和访问策略。

在这篇文章中，我们将介绍图层地图所需的数据集和 GeoJSON 结构。我们还解释了点和线在图层图视觉效果中的工作原理以及何时选择它们。最后，我们介绍了用于控制视口、分层几何图形以及以编程方式更新 GeoJSON 文件的高级技术。

## 数据集结构注意事项

图层图从 GeoJSON 文件获取其形状，从 Quick Sight 数据集获取其指标，并通过共享密钥将两者连接起来。构建每一个地图的方式决定了地图可以显示的内容。本节介绍开始之前您需要做的事情以及 GeoJSON 文件的组织方式。

### 先决条件

以下是在 Quick Sight 中创建图层图之前需要满足的先决条件：

- 描述几何图形的 GeoJSON 文件。
- 包含指标和维度的 Quick Sight 数据集。
- Quick Sight 数据集和 GeoJSON 文件之间共享的连接键。
- GeoJSON 文件必须以 .geojson 格式保存，支持的最大文件大小为 100 MB。

### GeoJSON 文件的结构

GeoJSON 是一种基于 JSON 的格式，用于描述点和线等地理特征。
```
{
  "type": "FeatureCollection",
  "features": [{
    "type": "Feature",
    "geometry": {
      "type": "Point",
      "coordinates": [88.4, 22.6]
    },
    "properties": { "prop0": "value0" }
  }, {
    "type": "Feature",
    "geometry": {
      "type": "LineString",
      "coordinates": [
        [88.2, 22.4],
        [88.9, 23.1],
        [89.5, 22.8],
        [90.1, 23.6]
      ]
    },
    "properties": { "prop0": "value0" }
  }]
}
```
文件结构如下：

- **FeatureCollection** 是整个文件。它具有 **FeatureCollection** 类型和 **features** 数组。
- **功能**是单个地图元素。它携带一个**几何**（形状）和一个**属性**对象，该对象保存连接键。
- **几何图形**具有**类型**（点、线串或多边形）及其**坐标**。 **坐标** 保存 **Point** 的单个 **[longitude, latitude]** 位置，以及 **LineString** 的位置的有序列表。

## 配置 Quick Sight 数据集及其 GeoJSON

在 Quick Sight 中，当您在图层图视觉对象中配置图层时，需要考虑两个主要设置。第一个是 **要可视化的几何类型**，它设置要渲染的 GeoJSON 文件中的几何图形：点、线或多边形。图层一次渲染一种几何类型，因此当文件像前面的示例一样混合类型时，只有所选类型的要素才会出现在地图上。第二个是将 **Shape 文件关键字段** 与 **Dataset 关键字段** 相匹配，它将 GeoJSON 中的每个要素链接到 Quick Sight 数据集中的一行。字段名称不需要相同，但值必须相同。以下两个示例显示了这种端到端的情况，首先是 **LineString** 层，然后是 **Point** 层。

### 示例：LineString 层

考虑显示从肯尼迪机场飞往目的地城市（例如洛杉矶）的航班的示例数据。单个数据点的 GeoJSON 结构配置如下：
```
{
  "type": "Feature",
  "geometry": {
    "type": "LineString",
    "coordinates": [
      [-73.7781, 40.6413],
      [-85.5627, 40.6407],
      [-97.1415, 39.4569],
      [-108.1612, 37.1753],
      [-118.4085, 33.9416]
    ]
  },
  "properties": { "route_id": "JFK-LAX" }
}
```

## 图层图视觉效果上的线条

图层图视觉效果现在支持 **LineString** 几何图形，将有序的坐标列表连接到单个路径中。正如数据结构部分所述，每条路线都是一个要素，其坐标是地图按顺序连接的有序位置。

当您想要显示位置之间的关系（例如飞行路径、交货路线、运输航线或管道段）时，请使用线条。视觉效果根据 GeoJSON 文件中的坐标绘制每条路径，而不是在加载时根据数据生成路径。加入的数据集中的字段可以确定线路颜色编码，因此您可以根据该字段表示的内容对路线进行分组。除了颜色之外，您还可以自定义线条的宽度和不透明度控件，以调整地图上的视觉突出度和清晰度。 GeoJSON 属性对象中的连接键将每个 LineString 与其工具提示和颜色后面的数据集行联系起来。

例如，机场运营团队可能会绘制特定日期从纽约 (JFK) 出发的航班的地图。 GeoJSON 文件为每条路线保存一个 LineString，由连接到数据集的路线 ID 键入。每条线路的起点都为 JFK，终点站为目的地，例如洛杉矶、芝加哥或迈阿密。数据集提供工具提示中显示的出发地、目的地和承运人。

## 图层图视觉效果上的点

Amazon Quick Sight 提供原生[点图视觉类型](https://docs.aws.amazon.com/quick/latest/userguide/point-maps.html)，可自动对位置名称进行地理编码并使用 SPICE 计划或直接查询连接进行刷新。它支持动态点大小、颜色编码和点样式，例如聚类点和热图密度梯度。它最适用于经常更改的数据以及您希望地图以视觉方式响应这些更改的位置。

通过在图层地图视觉效果中增加对 GeoJSON 点图层的支持，Quick Sight 现在提供了第二种点映射功能，但有一些关键差异。图层图视觉点使用统一的标记大小，并且不支持地理编码，因此您在 GeoJSON 文件中提供显式坐标。作为回报，您可以精确控制视口，将地图锁定到确切的地理区域，并禁用平移和缩放。

下表总结了主要差异：

| **功能** | **点图** | **图层图视觉点** |
| --- | --- | --- |
| **数据来源** |数据集中的纬度/经度值或地理位置名称 | GeoJSON Point 要素通过共享密钥连接到您的数据集 |
| **地理编码** |自动识别城市、县、州、国家和邮政编码 |无法使用。必须在 GeoJSON 文件中提供显式坐标 |
| **位置更新** |当位置值发生变化时，通过 SPICE 刷新或直接查询自动更新地图 | Visual 使用静态 GeoJSON 文件来表示点位置。需要手动重新上传或 API 调用来更新几何图形 |
| **视口** |自动适应您的数据，始终启用平移和缩放 |默认自动调整，可配置是否允许平移和缩放 |
| **外观** |大小和颜色可以从数据集中编码。可用点样式配置（基本、集群、热图）|可定制的统一标记尺寸、填充不透明度、边框颜色和厚度。颜色可以从数据集中编码 |

在以下情况下选择图层图视觉点：

- 您需要一个锁定的、不可滚动的视口。
- 您的位置是固定的和精心策划的（例如区域办事处、配送中心、零售店），而不是随着每次数据刷新而改变。
- 您计划将点与其他几何类型组合（在高级用例部分中介绍）。

考虑一个零售品牌，其区域经理使用 Quick Sight 仪表板来跟踪整个都市区的商店绩效。 GeoJSON 文件包含每个商店的点要素，以及连接到数据集的商店 ID 属性。该数据集包含驱动工具提示和颜色编码的指标（商店类型、每月收入、每日人流量）。您将地图定位在覆盖都市区的缩放级别，然后禁用地图导航，以便地图在每次加载时以一致的视图呈现。管理者不能意外地将视野缩小到全国或全球视野。

## 高级用例

前面的部分介绍了标准图层图设置。当您需要更多地控制读者所看到的内容、想要在单个视图中组合几何类型或需要随时间变化的几何时，请使用以下技术。

### 控制视口

当您需要控制图层图视觉效果中的视口时，您可以手动平移和缩放到所需的视图。然后禁用地图导航以将其锁定到位。对于需要更精确边界或编程控制的用例，您可以使用 Quick Sight API 通过视觉定义设置精确的视口坐标。

图层图视觉对象将其视口配置存储在“ChartConfiguration”内的“MapState”属性中。该属性接受两个字段：

- **边界**：定义最小可见区域的地理坐标（北、南、东、西）。
- **MapNavigation**：“启用”或“禁用”来控制读者是否可以平移和缩放。

尽管边界属性未在控制台上公开，但您可以在使用仪表板定义 JSON 进行编程资产管理时设置这些边界。例如，要定义边界，请修改可视化定义中的“MapState”块，然后调用 [CreateDashboard](https://docs.aws.amazon.com/quicksight/latest/APIReference/API_CreateDashboard.html) 或 [UpdateDashboard](https://docs.aws.amazon.com/quicksight/latest/APIReference/API_UpdateDashboard.html) API。

边界定义了保证可见的最小区域。地图会缩放以确保整个区域都适合视觉容器。为了在地图上添加最少的额外空间的情况下实现最紧密的配合，请将边界的纵横比与视觉容器的形状相匹配。

要对几何图形进行分层，您可以按照以下步骤将多个图层地图视觉效果堆叠在一起：

- **使用自由格式布局：** 将[工作表布局设置更改为自由格式](https://docs.aws.amazon.com/quick/latest/userguide/types-of-layout.html#free-form-layout.title)，以便视觉效果可以重叠和堆叠。
- **创建两层地图视觉效果：** 创建合并到单个视图中的两层地图视觉效果，例如一个使用 Point GeoJSON 文件，一个使用 LineString GeoJSON 文件。
- **使用匹配边界：** 使用前面描述的控制视口的方法，验证所有图层地图视觉效果使用相同的边界以具有相同的底层地图视图。
- **禁用平移和缩放：** 对于每个图层地图视觉效果，禁用地图选项下的平移和缩放，以便对齐保持不变。
- **隐藏上层的底图和背景：** 在显示设置下将上层视觉效果的背景设置为隐藏，并在地图选项下禁用底图。
- **堆叠视觉效果：** 使用拖放操作或通过在显示设置下匹配精确的大小和位置坐标，将顶部视觉效果移动到基础层的顶部。

层顺序遵循自由格式布局中的视觉堆叠顺序。要更改视觉对象在堆栈中的位置，请选择视觉对象上的菜单图标（三个点），然后选择 **向后发送** 或 **向前移动**。读者可以访问最顶部视觉效果的工具提示，因此将读者需要详细信息的图层放在顶部。每张纸最多支持五层地图视觉效果。

### 动态更新 GeoJSON

与其他通过 SPICE 或直接查询刷新数据的 Quick Sight 视觉效果不同，图层地图几何图形位于 GeoJSON 文件本身中。当数据集按计划刷新时，指标会更新（例如，颜色更改和工具提示值刷新），但几何图形仍保留在其原始位置。

要更新地图上显示的内容（例如新路线、新点位置或更新的边界），您需要更新 GeoJSON 文件并重新发布仪表板。您可以通过 Quick Sight 控制台手动替换 GeoJSON 文件，方法是在分析中编辑图层图视觉对象并上传新文件。这适用于不频繁的更改，例如每季度更新区域边界或添加新的商店位置。

对于自动、按需或动态更新，该过程涉及 Amazon Simple Storage Service (Amazon S3) 和 Quick Sight API，如以下步骤所述：

- **将新的 GeoJSON 上传到 Amazon S3：** 生成更新的几何图形并将其保存到 [Amazon S3](https://aws.amazon.com/s3/) 存储桶。自定义解决方案可以使用其他 AWS 服务（例如 [Amazon Location Service](https://aws.amazon.com/location/)）来创建 GeoJSON 文件。
- **引用仪表板定义上的文件：** 仪表板定义包含一个 [StaticFiles](https://docs.aws.amazon.com/quicksight/latest/APIReference/API_StaticFile.html) 数组，其中每个 GeoJSON 文件都有一个 `SpatialStaticFile` 条目。将文件引用修改为每个 GeoJSON 文件的更新文件条目的 S3 位置。
- **调用 UpdateDashboard API：** 使用 [UpdateDashboard](https://docs.aws.amazon.com/quicksight/latest/APIReference/API_UpdateDashboard.html) API 提交带有新文件引用的更新定义。
- **调用 UpdateDashboardPublishedVersion API：** 发布更改，以便使用 [UpdateDashboardPublishedVersion](https://docs.aws.amazon.com/quicksight/latest/APIReference/API_UpdateDashboardPublishedVersion.html) API 对仪表板读者可见。
