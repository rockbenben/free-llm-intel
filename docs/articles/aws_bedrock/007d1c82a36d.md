# 使用生成式 AI 和 Amazon Bedrock Data Automation 大规模开展智能文档处理

从非结构化文档中大规模提取信息是一项反复出现的业务任务。常见用例包括根据描述创建产品特性表、从文档中提取元数据，以及分析法律合同、客户评论、新闻文章等。从文本中提取信息的一种经典方法是命名实体识别（named entity recognition，NER）。NER 从预定义的类别（例如人物和组织）中识别实体。尽管各种 AI 服务和解决方案都支持 NER，但这种方法仅限于文本文档，且只支持一组固定的实体。此外，经典 NER 模型无法处理其他数据类型，例如数值分数（如情感）或自由格式文本（如摘要）。[生成式 AI](https://aws.amazon.com/generative-ai/) 无需昂贵的数据标注或模型训练即可释放这些可能性，从而实现更全面的智能文档处理（intelligent document processing，IDP）。

AWS [最近宣布](https://aws.amazon.com/about-aws/whats-new/2025/03/amazon-bedrock-data-automation-generally-available/) [Amazon Bedrock Data Automation](https://aws.amazon.com/bedrock/bda/) 正式可用，这是 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的一项功能，可自动从文档、图像、视频和音频等非结构化多模态内容中生成有价值的洞察。该服务通过统一的 API 提供用于 IDP 和信息提取的预置能力，免去了复杂的 prompt engineering 或 fine-tuning 的需求，使其成为大规模文档处理工作流的理想选择。要了解更多关于 Amazon Bedrock Data Automation 的信息，请参阅[使用 Amazon Bedrock Data Automation 简化多模态生成式 AI](https://aws.amazon.com/blogs/machine-learning/simplify-multimodal-generative-ai-with-amazon-bedrock-data-automation/)。

Amazon Bedrock Data Automation 因其简洁性、行业领先的准确性以及托管服务能力，成为 IDP 用例的推荐方案。它会自动处理文档解析、上下文管理和模型选择等复杂工作，使开发人员能够专注于业务逻辑，而非 IDP 的实现细节。

尽管 Amazon Bedrock Data Automation 能满足大多数 IDP 需求，但某些组织需要在其 IDP 流水线中进行额外的定制。例如，公司可能由于合规要求而需要将自托管的基础模型（foundation model，FM）用于 IDP。有些客户拥有 builder 团队，他们可能希望完全掌控 IDP 流水线，而不是使用托管服务。最后，某些组织可能在 Amazon Bedrock Data Automation 尚不可用的 AWS 区域中运行（截至 2025 年 6 月，仅在 us-west-2 和 us-east-1 可用）。在这些情况下，builder 可能会直接使用 Amazon Bedrock FM，或使用 [Amazon Textract](https://aws.amazon.com/textract/) 执行光学字符识别（optical character recognition，OCR）。

本文介绍一个由 Amazon Bedrock Data Automation 和其他 AWS 服务驱动的[端到端 IDP 应用](https://github.com/aws-samples/intelligent-document-processing-with-amazon-bedrock)。它提供可复用的 AWS 基础设施即代码（infrastructure as code，IaC），用于部署 IDP 流水线，并提供直观的 UI，以便大规模地将文档转换为结构化表格。该应用只要求用户提供输入文档（例如合同或电子邮件）以及要提取的属性列表，然后使用生成式 AI 执行 IDP。

应用代码和部署说明已在 [GitHub 上提供](https://github.com/aws-samples/intelligent-document-processing-with-amazon-bedrock)，采用 MIT 许可证。

## 解决方案概览

本文介绍的 [IDP 解决方案](https://github.com/aws-samples/intelligent-document-processing-with-amazon-bedrock) 使用 [AWS Cloud Development Kit](https://aws.amazon.com/cdk/)（AWS CDK）以 IaC 方式部署。Amazon Bedrock Data Automation 充当信息提取的主引擎。对于需要进一步定制的场景，该解决方案还提供使用 Amazon Bedrock FM 和 Amazon Textract 集成的替代处理路径。

我们使用 [AWS Step Functions](https://aws.amazon.com/step-functions/) 来编排 IDP 工作流，并对多个文档并行处理。在该工作流中，我们使用 [AWS Lambda](https://aws.amazon.com/lambda/) 函数来调用 Amazon Bedrock Data Automation，或调用 Amazon Textract 与 Amazon Bedrock（取决于所选择的解析模式）。处理后的文档和提取出的属性存储在 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）中。

包含业务逻辑的 Step Functions 工作流通过 AWS SDK 发起的 API 调用来触发。我们还构建了一个容器化 Web 应用，运行在 [Amazon Elastic Container Service](https://aws.amazon.com/ecs/)（Amazon ECS）上，并通过 [Amazon CloudFront](https://aws.amazon.com/cloudfront/) 向最终用户提供，以简化他们与该解决方案的交互。我们使用 [Amazon Cognito](https://aws.amazon.com/cognito/) 进行身份验证和对 API 的安全访问。

下图展示了该 IDP 解决方案的架构和工作流。

![部署消息](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/24/architecture-3.png)

IDP 工作流包括以下步骤：

- 用户使用 Amazon Cognito 管理的凭据登录 Web 应用，选择输入文档，并在 UI 中定义要从这些文档中提取的字段。用户还可以选择指定解析模式、要使用的 LLM 以及其他设置。
- 用户启动 IDP 流水线。
- 应用为文档创建预签名 S3 URL，并将其上传到 Amazon S3。
- 应用触发 Step Functions，以 S3 URI 和 IDP 设置作为输入来启动状态机。[Map state](https://docs.aws.amazon.com/step-functions/latest/dg/amazon-states-language-map-state.html) 开始并发处理这些文档。
- 根据文档类型和解析模式，流程会分支到不同的 Lambda 函数，由它们执行 IDP、将结果保存到 Amazon S3 并回传到 UI：  **Amazon Bedrock Data Automation** – 文档被定向到 “Run Data Automation” Lambda 函数。该 Lambda 函数使用用户定义的字段 schema 创建 blueprint，并启动一个异步的 Amazon Bedrock Data Automation 任务。Amazon Bedrock Data Automation 使用优化的 prompt 和模型来处理文档处理和属性提取的复杂工作。当任务结果就绪后，会保存到 Amazon S3 并回传到 UI。对于大多数 IDP 用例，这种方法在准确性、易用性和可扩展性之间提供了最佳平衡。 **Amazon Textract** – 如果用户指定 Amazon Textract 作为解析模式，IDP 流水线会拆分为两个步骤。首先，调用 “Perform OCR” Lambda 函数来运行异步文档分析任务。OCR 输出使用 [amazon-textract-textractor](https://github.com/aws-samples/amazon-textract-textractor) 库进行处理，并格式化为 Markdown。其次，文本被传递给 “Extract attributes” Lambda 函数（第 6 步），该函数根据文本和属性 schema 调用 Amazon Bedrock FM。输出保存到 Amazon S3 并发送到 UI。 **处理 Office 文档** – 后缀为 .doc、.ppt 和 .xls 的文档由 “Parse office” Lambda 函数处理，该函数使用 [LangChain](https://python.langchain.com/docs/introduction/) 文档加载器提取文本内容。输出被传递给 “Extract attributes” Lambda 函数（第 6 步），以继续执行 IDP 流水线。
- 如果用户选择 Amazon Bedrock FM 进行 IDP，文档会被发送到 “Extract attributes” Lambda 函数。该函数将文档转换为一组图像，这些图像与属性 schema 一起作为自定义 prompt 的一部分发送给多模态 FM。它解析 LLM 响应以提取 JSON 输出，保存到 Amazon S3，并回传到 UI。此 flow 支持 .pdf、.png 和 .jpg 文档。
- Web 应用会定期检查状态机的执行结果，并在提取结果就绪时将其返回给用户。

## 部署解决方案

要将解决方案部署到你的 AWS 账户，请完成以下步骤：

- 打开 [AWS 管理控制台](https://aws.amazon.com/console)，选择要在其中部署 IDP 解决方案的区域。
- [启动 SageMaker 笔记本实例](https://docs.aws.amazon.com/sagemaker/latest/dg/howitworks-create-ws.html)。提供笔记本实例名称和笔记本实例类型（可设置为 `ml.m5.large`）。其他选项保持默认。
- 导航到笔记本实例，打开附加到该笔记本的 IAM 角色。在 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）控制台上打开该角色。
- 为该角色附加一个内联策略，并插入以下策略 JSON：

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "cloudformation:*",
        "s3:*",
        "iam:*",
        "sts:AssumeRole"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "ssm:GetParameter",
        "ssm:GetParameters"
      ],
      "Resource": "arn:aws:ssm:*:*:parameter/cdk-bootstrap/*"
    }
  ]
}
```

- 当笔记本实例状态显示为 **InService** 时，选择 **Open JupyterLab**。
- 在 JupyterLab 环境中，依次选择 **File**、**New** 和 **Terminal**。
- 运行以下命令克隆[解决方案仓库](https://github.com/aws-samples/intelligent-document-processing-with-amazon-bedrock)：

```
cd SageMaker
git clone https://github.com/aws-samples/intelligent-document-processing-with-amazon-bedrock.git
```

- 导航到仓库文件夹，运行脚本安装依赖：

```
cd intelligent-document-processing-with-amazon-bedrock
sh install_deps.sh
```

- 运行脚本创建虚拟环境并安装依赖：

```
sh install_env.sh
source .venv/bin/activate
```

- 在仓库文件夹中，将 `config-example.yml` 复制为 `config.yml`，以指定你的堆栈名称。你可以选择配置各项服务并指明要部署的模块（例如，要禁用 UI 部署，可将 `deploy_streamlit` 改为 `False`）。确保将你的用户邮箱添加到 Amazon Cognito 用户列表中。

- 在你的账户中引导并部署 AWS CDK：

```
cdk bootstrap
cdk deploy
```

请注意，此步骤可能需要一些时间，尤其是在首次部署时。部署完成后，你应该会看到如下图所示的消息。你可以使用 [AWS CloudFormation](https://aws.amazon.com/cloudformation) 输出中提供的 CloudFront 分发 URL 访问 Streamlit 前端。部署期间，临时登录凭据将发送到 `config.yml` 中指定的邮箱。

## 使用解决方案

### 示例 1：分析财务文档

在此场景中，我们使用 Amazon Bedrock Data Automation 从一份多页财务报表中提取关键特征。我们使用一份包含表格、图像和文本混合内容的 PDF 格式[样本文档](https://github.com/aws-samples/intelligent-document-processing-with-amazon-bedrock/tree/main/demo/originals)，提取若干财务指标。请完成以下步骤：

- 通过解决方案 UI 附加文件以上传文档。

![文件上传页面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/08/ML-17229-image-3-1.png)

- 在** Describe Attributes **选项卡上，手动列出属性名称和描述，或[以 JSON 格式上传这些字段](https://github.com/aws-samples/intelligent-document-processing-with-amazon-bedrock/blob/main/demo/example_attributes/attributes_financial.json)。我们要查找以下指标：  2018 年资产中的当前现金 2019 年资产中的当前现金 2018 年营业利润 2019 年营业利润

![属性页面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/08/ML-17229-image-4-1.png)

- 选择 **Extract attributes **以启动 IDP 流水线。

提供的属性会与推断出的属性列表一起集成到一个自定义 blueprint 中，然后用它在上传的文档上调用 data automation 任务。

IDP 流水线完成后，你会在 UI 中看到一个结果表。它在 `_doc` 列中为每份文档提供一个索引，为你定义的每个属性提供一列，还有一个包含文档名称的 `file_name` 列。

### 示例 2：处理客户电子邮件

在此场景中，我们要使用 Amazon Bedrock Data Automation 从一系列因产品发货延迟而引发客户投诉的电子邮件中提取多个特征。对于每封邮件，我们希望找到以下内容：

- 客户姓名
- 发货 ID
- 邮件语言
- 邮件情感
- 发货延迟（天数）
- 问题摘要
- 建议回复

请完成以下步骤：

- 以 .txt 文件形式上传输入邮件。你可以从 [GitHub](https://github.com/aws-samples/intelligent-document-processing-with-amazon-bedrock/tree/main/demo/originals) 下载示例邮件。

![文件上传页面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/08/ML-17229-11.png)

- 在** Describe Attributes **选项卡上，列出属性的名称和描述。

![属性页面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/08/ML-17229-12.png)

你可以为某些字段（例如延迟）添加 few-shot 示例，以向 LLM 说明应如何提取这些字段的值。具体做法是在描述中添加一个示例输入以及该属性的预期输出。

- 选择 **Extract attributes **以启动 IDP 流水线。

提供的属性及其描述会与推断出的属性列表一起集成到一个自定义 blueprint 中，然后用它在上传的文档上调用 data automation 任务。IDP 流水线完成后，你将看到结果。

该应用允许将提取结果下载为 CSV 或 JSON 文件。这使得将结果用于下游任务（例如汇总客户情感分数）变得非常简单。

## 定价

在本节中，我们估算使用我们的解决方案在 AWS 上执行 IDP 的成本。

Amazon Bedrock Data Automation 提供[透明的定价方案](https://aws.amazon.com/bedrock/pricing/)，具体取决于输入文档的大小（页数、图像数或分钟数）。使用 Amazon Bedrock FM 时，定价取决于信息提取调用中使用的输入和输出 token 数量。最后，使用 Amazon Textract 时，会单独执行 OCR 并根据文档页数计费。

以前面的场景为例，我们可以根据所选择的解析模式估算成本。在下表中，我们使用两个数据集展示成本：100 份 20 页的财务文档，以及 100 份 1 页的客户电子邮件。我们忽略 Amazon ECS 和 Lambda 的成本。

| **AWS 服务** | **用例 1** **（100 份 20 页财务文档）** | **用例 2** **（100 份 1 页客户电子邮件）** |
| --- | --- | --- |
| **IDP 选项 1：Amazon Bedrock Data Automation** |  |  |
| Amazon Bedrock Data Automation（自定义输出） | $20.00 | $1.00 |
| **IDP 选项 2：Amazon Bedrock FM** |  |  |
| Amazon Bedrock（FM 调用，Anthropic 的 Claude 4 Sonnet） | $1.79 | $0.09 |
| **IDP 选项 3：Amazon Textract 与 Amazon Bedrock FM** |  |  |
| Amazon Textract（带布局的文档分析任务） | $30.00 | $1.50 |
| Amazon Bedrock（FM 调用，Anthropic 的 Claude 3.7 Sonnet） | $1.25 | $0.06 |
| **编排与存储（共享成本）** |  |  |
| Amazon S3 | $0.02 | $0.02 |
| AWS CloudFront | $0.09 | $0.09 |
| Amazon ECS | – | – |
| AWS Lambda | – | – |
| **总成本：Amazon Bedrock Data Automation** | $20.11 | $1.11 |
| **总成本：Amazon Bedrock FM** | $1.90 | $0.20 |
| **总成本：Amazon Textract 与 Amazon Bedrock FM** | $31.36 | $1.67 |

成本分析表明，使用带有自定义 prompt 模板的 Amazon Bedrock FM 是一种经济高效的 IDP 方法。不过，这种方式需要更大的运维开销，因为流水线需要根据 LLM 进行优化，并且需要手动管理安全与隐私。Amazon Bedrock Data Automation 提供托管服务，可通过单一 API 使用多种高性能 FM。

## 结论

从非结构化文档中大规模提取信息是一项反复出现的业务任务。本文讨论了一个端到端的 IDP 应用，它使用多种 AWS 服务执行信息提取。该解决方案由 Amazon Bedrock Data Automation 驱动，提供全托管服务，可从文档、图像、音频和视频中生成洞察。Amazon Bedrock Data Automation 处理文档处理和信息提取的复杂工作，在优化性能与准确性的同时，无需具备 prompt engineering 方面的专业知识。为了在特定场景中提供更大的灵活性和可定制性，我们的解决方案还支持使用 Amazon Bedrock 自定义 LLM 调用进行 IDP，并使用 Amazon Textract 执行 OCR。

该解决方案支持多种文档类型，包括文本、图像、PDF 和 Microsoft Office 文档。在撰写本文时，只有 PDF 和图像能够准确理解富含图像、表格和其他视觉元素的文档中的信息。我们建议将复杂的 Office 文档转换为 PDF 或图像，以获得最佳性能。该解决方案的另一个限制是文档大小。截至 2025 年 6 月，Amazon Bedrock Data Automation 支持最多 20 页的文档进行自定义属性提取。使用自定义 Amazon Bedrock LLM 进行 IDP 时，Amazon Nova LLM 的 300,000-token 上下文窗口可处理最多约 225,000 个单词的文档。要从更大的文档中提取信息，目前需要将文件拆分为多个文档。

在 IDP 解决方案的后续版本中，我们计划持续增加对 Amazon Bedrock 上可用的先进语言模型的支持，并迭代 prompt engineering 以进一步提高提取准确性。我们还计划实现相关技术，扩大所支持文档的大小，并向用户精确指明提取的信息在文档中的具体来源位置。

要使用所述解决方案开始 IDP，请参阅 [GitHub 仓库](https://github.com/aws-samples/intelligent-document-processing-with-amazon-bedrock)。要了解更多关于 Amazon Bedrock 的信息，请参阅[文档](https://docs.aws.amazon.com/bedrock/)。
