# Bring structured and unstructured data together with Amazon Quick

Organizations collect data in many forms. Structured data lives in databases and spreadsheets, whereas unstructured data sits in documents, reports, and files stored across file systems. Analyzing both together typically requires switching between multiple tools, running separate queries, and manually correlating results.

[Amazon Quick](https://docs.aws.amazon.com/quick/latest/userguide/welcome.html) addresses this with a unified experience. You can connect structured data through [enriched datasets](https://docs.aws.amazon.com/quick/latest/userguide/working-with-datasets.html) and unstructured data through [S3-backed knowledge bases](https://docs.aws.amazon.com/quick/latest/userguide/s3-integration.html). You can then query both through a single conversational AI agent.

In this post, you learn how to:

- Connect Amazon Simple Storage Service (Amazon S3) as a data source and create a knowledge base.
- Build a Space that combines structured and unstructured data.
- Create and configure a custom chat agent that queries across both data types.
- Ask questions that span structured and unstructured sources in a single conversation.

## Solution architecture

The following diagram illustrates how each component connects to deliver a unified data experience through Amazon Quick.

![Architecture diagram showing the data, workspace, and agent layers that connect structured datasets and an Amazon S3 knowledge base to a chat agent in Amazon Quick](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-1.png)

Figure 1: Solution architecture for combining structured and unstructured data in Amazon Quick

The architecture has three layers:

- **Data layer:** Your data exists in two forms. Unstructured content (documents, PDFs, reports) is stored in Amazon S3 and indexed through a knowledge base. Structured data (metrics, sales figures, and operational key performance indicators) is loaded as enriched datasets with semantic descriptions that the agent uses to translate questions into SQL.
- **Workspace layer:** A Space brings both data types together into a single workspace. The Space references your knowledge base for unstructured queries and your datasets for structured queries. It can also include dashboards, file uploads, and action connectors. This is the layer where data from different sources converges into a unified context.
- **Agent layer:** The custom chat agent links to the Space and uses it as its knowledge source. When a user asks a question, the agent determines whether to query the knowledge base, the dataset, or both, and returns a combined response with citations. Amazon Quick also applies built-in [AI guardrails](https://docs.aws.amazon.com/quick/latest/userguide/guardrails.html), such as content safety screening, to chat interactions.

With this layered approach, you can expand the solution over time. When you add a new data source to the Space, the agent linked to that Space can use it, and responses respect the permissions of the user who asks.

## Prerequisites

To follow along with this walkthrough, you need:

- An Amazon Quick account with an Enterprise subscription for the user who follows this walkthrough (creating datasets requires Enterprise). For details, see [Amazon Quick pricing](https://aws.amazon.com/quick/pricing/).
- An Amazon S3 bucket for your business documents. To create one, see the [Amazon S3 User Guide](https://docs.aws.amazon.com/AmazonS3/latest/userguide/create-bucket-overview.html).
- [Amazon Quick access to your S3 bucket](https://docs.aws.amazon.com/quick/latest/userguide/s3-admin-setup.html#s3-grant-bucket-access), granted by an Amazon Quick administrator. In the admin console, the administrator chooses Permissions, then AWS resources, selects Amazon S3, and chooses Select S3 buckets. Selected buckets have read-only permissions by default.
- Permissions to create integrations, knowledge bases, datasets, spaces, and chat agents in Amazon Quick.

## Step 1: Create an Amazon S3 integration

Start by connecting Amazon Quick to your S3 bucket. From the Amazon Quick console, select **Knowledge** in the left navigation panel.

The knowledge page shows available connector types, including Amazon Q Business, Web Crawler, Amazon S3, and third-party options like Google Drive, OneDrive, and Microsoft SharePoint.

Under Amazon S3, choose **Add**. In the Create S3 knowledge base dialog, on the Connect S3 bucket page, provide the following details:

- **Name:** A descriptive name for your integration (for example, “My Data Access Integration”).
- **S3 bucket location:** Choose **Quick Suite instance account** to use a bucket in the same AWS account as Amazon Quick, or **Other AWS account** for a bucket in a different account.
- **S3 bucket URL:** The S3 URI of the bucket containing your data. The bucket must be in the same Region as Amazon Quick.

Choose **Next**.

![Create S3 knowledge base dialog showing the Connect S3 bucket fields for name, bucket location, and bucket URL](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-2.png)

Figure 2: Create integration dialog showing the S3 connection fields

## Step 2: Create a knowledge base

After the S3 integration is created, Amazon Quick prompts you to create a knowledge base. The knowledge base indexes your S3 content for AI-powered search.

Configure the knowledge base:

- **Name:** “Business Knowledge Base”.
- **Description (optional):** Notes about how the knowledge base will be used.
- **Content:** Select “Add all content” to index everything in the connected S3 bucket, or “Add specific content” to specify the S3 prefixes for the folders and files to include (prefix filters are case-sensitive).

**Next:** Additional settings opens optional settings for document-level access control lists (ACLs) and a metadata files folder. Decide whether to use ACLs before you create the knowledge base, because you can’t change that choice later. This walkthrough uses sample data, so the default settings are sufficient. For details, see [Set up and manage Amazon S3 integration](https://docs.aws.amazon.com/quick/latest/userguide/s3-setup-manage.html).

Choose **Create**. A success banner confirms the S3 integration, and the knowledge base begins indexing in the background.

## Step 3: Create and enrich a dataset

A [dataset](https://docs.aws.amazon.com/quick/latest/userguide/working-with-datasets.html) is your structured data file loaded into Amazon Quick. By enriching the dataset with semantic descriptions, custom instructions, and correct data types, the AI agent can interpret your data more accurately. It can then translate natural language questions into SQL queries.

### Create the dataset

- From the Amazon Quick home page, navigate to **Data** in the left navigation.
- Choose **Create dataset**, then select **Upload file**.
- Select the **Product_Sales.csv** file you downloaded earlier and choose **Open**.
- On the confirmation screen, review the column names and data types. Choose **Next** to create the dataset.

Amazon Quick ingests the file into SPICE (the in-memory calculation engine) and the dataset appears in your dataset list.

The dataset takes its name from the uploaded file, so it appears as Product_Sales.csv in your account.

### Enrich the dataset

Enriching your dataset with semantic information helps the AI understand your data in business context. The agent uses this context to translate natural language questions into more accurate SQL queries. From the dataset page, choose **Edit dataset** to enter the data preparation view.

### Transform: Fix data types

In the **Transform** tab, update data types for columns that were auto-detected incorrectly. For this dataset:

- Change **Order Date** and **Date Key** from String to Date.
- Change **Customer ID** from String to Integer.
- Change **Sales**, **Discount**, and **Profit** from String to Decimal.
- Change **Quantity** and **Unit Price** from String to Integer.

![Transform tab showing data type changes applied to columns in the Product_Sales.csv dataset](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-4.png)

Figure 4: Transform view showing data type changes applied to the Product_Sales.csv dataset

### Output: Add semantic context

Select the **Output** tab to access the dataset-level enrichment fields. Here you provide context that helps the AI understand what your data represents and how to use it.

**Description:** Add a dataset-level description:

“Product sales transaction data for AnyCompany, covering orders from FY2024-FY2025 across North America, EMEA, Asia Pacific, and Latin America. Includes order details, customer information, product lines, and revenue metrics.”

**Custom instructions:** Add guidance for how the AI should query this data:

**USAGE GUIDELINES:**

- Revenue values are in USD.
- When comparing performance, group by Region (North America, EMEA, Asia Pacific, Latin America).
- Order Date should be used for time-based trend analysis. The fiscal year matches the calendar year.
- Date Key is a numeric YYYYMMDD representation of Order Date.
- Sales = Quantity x Unit Price x (1 – Discount)

**COMMON USE CASES:**

- Regional sales performance comparison.
- Product line revenue analysis.
- Quarterly trend identification.
- Customer segmentation by industry and segment.

**TAGS:** Sales, revenue, orders, regional performance, product analytics

**Column descriptions:** Select each column in the left panel and add a description. For example:

- Order ID: “Unique identifier for each sales transaction (format: `REGION-YYYY-NNNNNN`)”
- Region: “Geographic sales region: North America, EMEA, Asia Pacific, or Latin America”
- Product: “AnyCompany product name: Analytics Pro, Connect, Automate, AI Assistant, Data Catalog, or Integration Hub”
- Sales: “Order revenue in USD after discount”
- Segment: “Customer size segment: Enterprise, Mid-Market, or SMB”

![Output tab showing the dataset Description and Custom instructions fields filled in](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-5.png)

Figure 5: Output view showing dataset details with Description and Custom instructions configured

Choose **Save & publish** to save your changes. The dataset summary now shows the columns with their correct data types and the descriptions you added.

![Enriched Product_Sales.csv dataset summary listing 16 columns with their data types and descriptions](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-6.png)

When the agent receives a natural language question about sales data, it uses these descriptions and instructions to generate more accurate SQL queries. Combined with the knowledge base from Step 2, you now have both structured and unstructured data ready to bring together in a Space.

## Step 4: Create a Space

[Spaces](https://docs.aws.amazon.com/quick/latest/userguide/working-with-spaces.html) in Amazon Quick act as unified data workspaces. A Space can hold file uploads, dashboards, knowledge bases, actions, and datasets, giving your chat agent a single location to query across data types.

From the left navigation, select **Spaces** and create a new Space. Name it “Business Intelligence Hub”.

Add your knowledge base and dataset to the Space:

- Choose **Add knowledge** and select **Knowledge bases** from the list. Select “Business Knowledge Base” from the list.
- Choose **Add knowledge** again and select **Datasets** from the list. Select “Product_Sales.csv” from the list.

The Space now shows both your knowledge base (unstructured documents) and your enriched dataset (structured sales data) linked as data sources. This is the central hub where both data types come together, giving your chat agent a single place to query across everything. Figure 7 shows the Space with both resources in the Ready state.

![Business Intelligence Hub Space showing the Product_Sales.csv dataset and Business Knowledge Base linked as data sources in the Ready state](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-7.png)

Figure 7: Business Intelligence Hub Space showing the Product_Sales.csv dataset and Business Knowledge Base

## Step 5: Create a custom chat agent

Navigate to **Chat agents** in the left navigation and choose **Create chat agent**. Amazon Quick presents a prompt builder where you can describe your agent in natural language or choose from templates like Training Guide, Project Coordinator, and Onboarding Helper.

For this walkthrough, choose **Skip** to configure the agent manually.

### Configure the agent persona

The configuration panel has several sections. Start with the Agent Persona:

- **Agent identity:** “Business Intelligence Assistant”
- **Description:** “An AI assistant that breaks down information silos by analyzing business data from your knowledge base”

For Agent Persona instructions, enter:

```
You are a Business Intelligence Assistant designed to help organizations break down information silos. Your primary functions are:

1. Analyze business data stored in S3
2. Retrieve relevant findings from the reports and memos in the knowledge base
3. Provide comprehensive insights that connect internal data with external trends
4. Generate clear, actionable recommendations based on data analysis

When answering questions, always cite your sources and explain how you arrived at your conclusions. Focus on delivering practical business value and highlighting patterns across different information sources.
```

You can also attach reference documents (PDF, TXT, HTML, MD, CSV, DOC, DOCX) directly to the agent for additional context. Amazon Quick extracts up to 100,000 characters of text from the reference documents that you upload.

## Step 8: Share the agent

When you launch a chat agent, it remains private until you share it. After you test the agent, share it with your team:

- From the left navigation, choose **Chat agents**.
- In the **Actions** column for Business Intelligence Assistant, choose the menu icon, and then choose **Share**.
- Enter the users or groups to share with, assign **Owner** or **Viewer** permissions, and then choose **Share**.

The agent returns permissions-aware responses, and a knowledge base is available only to its creator until you update its permissions. Make sure that the people you share the agent with also have access to the Space, the knowledge base, and the dataset. For details, see [Custom chat agents](https://docs.aws.amazon.com/quick/latest/userguide/custom-agents.html).

## Best practices

Use the following practices as you move from this walkthrough to your own data:

- **Organize your S3 data:** Use clear folder structures and file naming conventions. A clear structure also makes it more straightforward to scope a knowledge base to specific S3 prefixes.
- **Write specific persona instructions:** The more specific your instructions, the more consistent the agent responses. Include guidance on how to cite sources and handle ambiguous queries.
- **Use Spaces to control scope:** Rather than giving an agent access to everything, create focused Spaces with only the data sources relevant to that agent’s purpose.
- **Start with suggested prompts:** Suggested prompts help users understand what the agent can do. Choose prompts that demonstrate the agent’s range across both structured and unstructured data.
- **Test before sharing:** Use the preview panel to test your agent with representative questions before sharing it with your team.

## Security considerations

Under the [AWS shared responsibility model](https://aws.amazon.com/compliance/shared-responsibility-model/), you are responsible for configuring access to your data, knowledge bases, and agents. Consider the following as you adapt this solution:

- **Grant least-privilege S3 access:** Give Amazon Quick access only to the buckets that your knowledge bases need. Buckets that an administrator selects have read-only permissions by default. If you create knowledge bases through the API, you can provide a custom AWS Identity and Access Management (IAM) role for an individual S3 data source instead of granting account-wide S3 access.
- **Control document access:** If documents require per-user or per-group access, enable document-level ACLs when you create the knowledge base. You can’t change this choice later.
- **Encrypted buckets:** If your bucket uses AWS Key Management Service (AWS KMS) keys, follow the AWS KMS steps in the [administrator setup guide](https://docs.aws.amazon.com/quick/latest/userguide/s3-admin-setup.html).
- **Add only trusted content:** The agent uses the documents in your knowledge base to form responses, so include only content from sources you trust.
- **Share selectively:** Chat agents and knowledge bases are private by default. Share them only with the users and groups that need them.
- **Use guardrails as one layer:** Amazon Quick includes built-in content safety screening, and administrators can add up to 50 blocked words or phrases. These controls help reduce risk but don’t replace your responsibility to configure access and permissions. For details, see [AI guardrails in Amazon Quick](https://docs.aws.amazon.com/quick/latest/userguide/guardrails.html).

## Clean up

To avoid ongoing charges, remove the resources you created:

- Delete the chat agent from the Chat agents page.
- Delete the Space from the Spaces page.
- Delete the Product_Sales.csv dataset from the Datasets page.
- Delete the knowledge base and S3 integration from the Knowledge page.
- If you created an S3 bucket specifically for this walkthrough, empty and delete it. Deleting a bucket and its objects is permanent, so back up any data that you want to keep.

Amazon Quick user subscriptions and account fees are billed separately from these resources. For details, see [Amazon Quick pricing](https://aws.amazon.com/quick/pricing/).
