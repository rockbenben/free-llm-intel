# 在 Amazon Bedrock AgentCore Browser 中使用 proxy、配置文件和扩展定制 AI agent 的浏览行为

浏览网页的 AI agent 需要的远不止基本的页面导航。客户告诉我们，他们需要 agent 能够在多次交互之间保持会话状态、通过企业 proxy 基础设施路由流量，并以自定义的浏览器配置运行。[AgentCore Browser](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html) 为你的 agent 提供了一个安全、隔离的浏览器环境，用于与 Web 应用交互。在此之前，Agent Core Browser 中每个浏览器会话都从空白状态开始，使用默认设置并直接访问互联网，这限制了 agent 在真实企业环境中能够完成的工作。

今天，我们宣布推出三项满足这些需求的新能力：[proxy 配置](https://aws.amazon.com/about-aws/whats-new/2026/02/bedrock-agentcore-browser-proxy/)、[浏览器配置文件](https://aws.amazon.com/about-aws/whats-new/2026/02/amazon-bedrock-agentcore-browser-profiles/)和[浏览器扩展](https://aws.amazon.com/about-aws/whats-new/2026/01/amazon-bedrock-agentcore-browser-custom-extensions/)。这些功能结合在一起，让你可以细粒度地控制 AI agent 与 Web 交互的方式。

这三项能力让你可以控制 AgentCore Browser 会话如何连接到互联网、保留哪些状态以及如何表现。proxy 配置让你把浏览器流量路由到自己的 proxy 服务器，从而获得 IP 稳定性并与企业网络基础设施集成。浏览器配置文件在会话之间持久化 cookie 和 local storage，这样 agent 就能从中断处继续已认证的工作流，而无需重复登录流程。浏览器扩展把 Chrome 扩展加载到会话中，以便针对你的用例定制浏览器行为。本文将通过配置示例和实际用例逐一介绍每项能力，帮助你快速上手。

## 持久化浏览器配置文件如何让 AI agent 平稳运行

为电商测试、已认证工作流和多步骤用户旅程构建 agent 的客户，需要能够记住状态的浏览器会话。如果没有持久化的配置文件，agent 就不得不在每个会话开始时重新认证并重建上下文，这会给自动化工作流增加延迟和脆弱性。浏览器配置文件通过在会话之间保存和恢复 cookie 与 local storage 解决了这个问题，因此昨天登录过某个门户的 agent 今天可以从上次中断的地方继续。

IP 稳定性是另一项常见需求。医疗和金融门户会根据源 IP 地址校验会话，而轮换的 AWS IP 地址会导致频繁的重新认证循环，打断长时间运行的工作流。proxy 支持让你把流量路由到具有稳定出口 IP 的服务器，从而保持会话连续性并满足 IP 允许列表的要求。需要将流量经由企业 proxy 路由的组织，也需要把这一做法扩展到 AI agent 的浏览器会话。proxy 配置使你能够访问需要基于 proxy 连接才能抵达的内部网页和资源。

浏览器扩展支持自定义配置，例如广告拦截、认证辅助工具或其他浏览器层面的定制。与 proxy 日志结合使用时，这些能力有助于提供访问控制和审计证据，从而可能支持 [合规项目](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/compliance-validation.html)，例如 FedRAMP、HITRUST 和 PCI。

## 功能 1：proxy 配置

AgentCore Browser 现在支持将浏览器流量路由到你自己的外部 proxy 服务器。当你使用 proxy 配置创建浏览器会话时，AgentCore 会配置浏览器，把 HTTP 和 HTTPS 流量通过你指定的 proxy 服务器路由。

### 工作原理

你调用 `StartBrowserSession`，并传入指定 proxy 服务器的 `proxyConfiguration`。如果使用认证，AgentCore 会从 AWS Secrets Manager 获取 proxy 凭证。浏览器会话在应用你的 proxy 配置后启动，浏览器流量会依据你的域名路由规则通过你的 proxy 服务器路由。

### proxy 快速上手

在继续之前，请先完成这些[前提条件](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-proxies.html#browser-proxies-prerequisites)。

**步骤 1：** 创建凭证 secret（如果你的 proxy 需要认证）

```
import boto3 
import json 
client = boto3.client('secretsmanager') 
client.create_secret( 
    Name='my-proxy-credentials', 
    SecretString=json.dumps({ 
        'username': '<your-username>', 
        'password': '<your-password>' 
    }) 
) 
```

**步骤 2：** 创建带 proxy 配置的浏览器会话

```
session_client = boto3.client('bedrock-agentcore', region_name='<region>') 
 
response = session_client.start_browser_session( 
    browserIdentifier="aws.browser.v1", 
    name="my-proxy-session", 
    proxyConfiguration={ 
        "proxies": [{ 
            "externalProxy": { 
                "server": "<your-proxy-hostname>", 
                "port": 8080, 
                "credentials": { 
                    "basicAuth": { 
                        "secretArn": "arn:aws:secretsmanager:<region>:<account-id>:secret:<secret-name>" 
                    } 
                } 
            } 
        }] 
    } 
) 
print(f"Session ID: {response['sessionId']}")
```

对于不需要认证的 proxy，credentials 字段是可选的。

### 基于域名的路由

使用 `domainPatterns` 将特定域名路由到指定的 proxy，使用 `bypass.domainPatterns` 指定应直接连接的域名：

```
proxyConfiguration={ 
    "proxies": [ 
        { 
            "externalProxy": { 
                "server": "corp-proxy.example.com", 
                "port": 8080, 
                "domainPatterns": [".company.com", ".internal.corp"] 
            } 
        }, 
        { 
            "externalProxy": { 
                "server": "general-proxy.example.com", 
                "port": 8080 
            } 
        } 
    ], 
    "bypass": { 
        "domainPatterns": [".amazonaws.com"] 
    } 
}
```

使用此配置，发往 `*.company.com` 和 `*.internal.corp` 的请求会通过企业 proxy 路由，发往 `*.amazonaws.com` 的请求会绕过所有 proxy，其余请求则通过通用 proxy 路由。这些字段只是一个示例。bypass 域名可以匹配 `bypass.domainPatterns` 以直接连接，外部 proxy 可以是有效的 proxy `domainPatterns` 并通过该 proxy 路由（按数组顺序，先匹配者生效）。

### 路由优先级

当 AgentCore Browser 处理一个出站请求时，它会依次经过三层路由规则来决定把流量发往何处。它首先检查 bypass 列表。如果目标域名匹配 `bypass.domainPatterns` 中的某一项，请求会直接连接到互联网，不使用任何 proxy。如果域名不匹配任何 bypass 规则，AgentCore 会按顺序检查每个 proxy 的 `domainPatterns`，并把请求通过第一个匹配该模式的 proxy 路由。如果没有任何 proxy 模式匹配，请求会落到默认 proxy，也就是没有定义 `domainPatterns` 的那个 proxy 条目。

你可以用这个[代码示例](https://github.com/awslabs/amazon-bedrock-agentcore-samples/tree/main/01-tutorials/05-AgentCore-tools/02-Agent-Core-browser-tool/11-browser-with-proxy)测试新的 proxy 功能。

## 功能 2：浏览器配置文件

浏览器配置文件让你可以在多个浏览器会话之间持久化并复用会话数据，包括 cookie 和 local storage。在一个会话中通过某个 Web 门户完成认证的 agent，可以在之后的会话中恢复该状态，无需再次登录。这对于以下场景很有用：重新登录会增加延迟的已认证工作流、购物车和表单数据需要跨会话保留的电商测试，以及跨越多次浏览器调用的多步骤用户旅程。

配置文件的完整生命周期有四个阶段。你首先调用 `create_browser_profile()` 创建一个具名配置文件。在会话结束时，你调用 `save_browser_session_profile()` 把当前 cookie 和 local storage 捕获到该配置文件中。当你启动新会话时，在 `start_browser_session()` 的 `profileConfiguration` 参数中传入配置文件标识符，它会把已保存的状态恢复到新浏览器中。当你不再需要该配置文件时，调用 `delete_browser_profile()` 将其清理掉。

以下示例展示了一个 agent：它在一个会话中把商品加入购物车，并在后续会话中验证这些商品仍然存在。

在继续之前，请先完成这些[前提条件](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-profiles.html#browser-profiles-prerequisites)。

```
import boto3 

control_client = boto3.client('bedrock-agentcore-control', region_name='<region>') # replace by your region 

session_client = boto3.client('bedrock-agentcore', region_name='<region>') # replace by your region  
 
# Create a browser profile 
profile = control_client.create_browser_profile(name="ecommerce_profile") 
profile_id = profile['profileId'] 
 
# Session 1: Add items to cart 
session1 = session_client.start_browser_session( 
    browserIdentifier=”aws.browser.v1”, 
    name="shopping-session-1" 
) 
# ... agent navigates and adds items to cart ... 
 
# Save session state to profile 
session_client.save_browser_session_profile( 
    sessionId=session1['sessionId'], 
    browserIdentifier=”aws.browser.v1”, 
    profileIdentifier=profile_id 
) 
session_client.stop_browser_session(sessionId=session1['sessionId'], browserIdentifier="aws.browser.v1") 
 
# Session 2: Resume with saved profile 
session2 = session_client.start_browser_session( 
    browserIdentifier=”aws.browser.v1”, 
    name="shopping-session-2", 
    profileConfiguration={"profileIdentifier": profile_id} 
) 
# Cart items from Session 1 are now available 
```

你可以用这个[代码示例](https://github.com/awslabs/amazon-bedrock-agentcore-samples/tree/main/01-tutorials/05-AgentCore-tools/02-Agent-Core-browser-tool/10-browser-with-profile)测试新的配置文件功能。

## 功能 3：浏览器扩展

浏览器扩展让你可以把 Chrome 扩展加载到 AgentCore Browser 会话中，以定制浏览器行为。你把扩展打包成 ZIP 文件，上传到 [Amazon Simple Storage Service](https://www.google.com/search?q=Amazon+Simple+Storage+Service&rlz=1C1GCEA_enUS1107US1107&oq=amazon+s3&gs_lcrp=EgZjaHJvbWUyBggAEEUYOTIGCAEQRRg8MgYIAhBFGDzSAQgyNTAyajBqN6gCALACAA&sourceid=chrome&ie=UTF-8&ved=2ahUKEwi4xuC6v9eSAxURm2oFHUlqEwMQgK4QegYIAQgAEAU)（Amazon S3），并在启动浏览器会话时引用它们。这样就能使用通过 Chrome extension API 提供的功能，从 proxy 路由和广告拦截，到认证辅助工具和内容修改。例如，你可以为内部应用注入认证 token、移除广告、跟踪干扰 agent 导航的脚本，或者修改页面内容以改善 agent 与站点的交互方式。

你的扩展应遵循标准的 [Chromium 扩展](https://www.chromium.org/developers/design-documents/extensions/)格式，并遵守 Chromium 扩展的相关准则。

在继续之前，请先完成这些[前提条件](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-extensions.html#browser-extensions-prerequisites)。

- 将扩展上传到 Amazon S3：  `# Upload extension to S3 import boto3 s3 = boto3.client('s3') s3.upload_file( 'my-extension.zip', 'amzn-s3-demo-bucket-extensions', 'extensions/my-extension.zip' ) `
- 然后，启动一个带扩展的会话，指向你上传了 zip 文件的 Amazon S3 存储桶：  `import boto3 region = "<region>" # replace by your region client = boto3.client('bedrock-agentcore', region_name=region) response = client.start_browser_session( browserIdentifier="aws.browser.v1", name="my-session-with-extensions", sessionTimeoutSeconds=1800, viewPort={ 'height': 1080, 'width': 1920 }, extensions=[ { "location": { "s3": { "bucket": "amzn-s3-demo-bucket-extensions", "prefix": "extensions/my-extension.zip" } } }, { "location": { "s3": { "bucket": "amzn-s3-demo-bucket-extensions", "prefix": "extensions/another-extension.zip", "versionId": "abc123" # Optional - for versioned S3 buckets } } } ] ) print(f"Session ID: {response['sessionId']}") print(f"Status: {response['status']}") print(f"Automation Stream: {response['streams']['automationStream']['streamEndpoint']}") `

你可以用这个[代码示例](https://github.com/awslabs/amazon-bedrock-agentcore-samples/tree/main/01-tutorials/05-AgentCore-tools/02-Agent-Core-browser-tool/12-browser-extensions)测试新的扩展功能。

## 结论

proxy 配置、浏览器配置文件与浏览器扩展为 AgentCore Browser 带来了客户在生产环境中部署浏览 Web 的 AI agent 所需的 proxy 路由、会话持久化和可扩展性控制。你可以让流量通过企业 proxy 基础设施路由、在多次交互之间保持会话连续性，并用扩展定制浏览器行为，同时把凭证安全地保存在 AWS Secrets Manager 中。客户可以在会话之间携带电商上下文和信息，在发布前创建自己的扩展并在安全环境中测试，还可以让浏览器通过 proxy 接入自己的网络。
