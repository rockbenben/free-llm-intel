# SageMaker AI 无服务器模型定制上的全量微调（FFT）

微调是指用企业自有数据继续训练预训练大语言模型（LLM）的过程，让模型适应特定领域、任务或风格，而不是只依赖通用知识。对企业来说，价值是双重的：微调后的模型在领域工作上准确率有可衡量的提升，同时成本更低——一个更小的专用模型就能在你的任务上达到甚至超过前沿模型，而每 token 推理价格只有后者的一小部分。这些节省会在数百万次请求上累积。因此，对希望以更低成本从 LLM 中获得更多价值的企业而言，微调已经是必不可少的环节。

低秩适配（LoRA）这类参数高效微调（PEFT）方法已成为把 LLM 适配到下游任务的实用方案，它只更新 LLM 参数的一小部分，从而降低 GPU 容量需求。LoRA 试图在效率与表达能力之间取得平衡，但权重更新的低秩特性本身限制了 LoRA 微调模型的表示能力，在复杂任务上可能拖累性能。这一取舍使 LoRA 难以捕捉多样任务所需的复杂模式。为应对这些挑战，全量微调（FFT）同时更新模型参数，突破低秩限制，让 LLM 充分吸收复杂的领域知识。

[Amazon SageMaker AI Serverless Model Customization](https://aws.amazon.com/sagemaker/ai/model-customization/) 现已支持[全量微调（FFT）](http://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-fft.html)，你无需管理基础设施就能获得更好的模型质量：不用预置 GPU，不用搭建集群，也不用配置分布式训练。本文探讨 FFT 在何时、哪些关键基准上稳定优于 LoRA，剖析能解释这一质量差距的模型权重矩阵谱特性，给出基于 SageMaker AI Serverless Model Customization 受控实验的实用超参数调优建议，并演示如何在 SageMaker AI 上开始使用 FFT。

## 全量微调：为何重要

LoRA 这类模型定制方式通过冻结预训练模型的权重，并向模型各层注入少量独立的替换矩阵对（即低秩矩阵）来减少可训练参数。这种方式对简单适配足够好用，但低秩结构本身限制了微调模型的表示能力。当任务变得更复杂、数据集超过数万条样本时，LoRA 会撞上准确率平台期：此时提高秩（也就是增加可训练参数）也无法弥合与标准微调之间的差距。这个平台期说明，性能差距并不只是参数更少造成的，根源是秩亏缺本身——低秩更新无法承载深度任务适配所需的全部权重变化。

而对于存在大规模高质量数据的复杂任务与领域，全秩微调通过同时更新模型参数而胜出。FFT 整体地修改模型的权重矩阵，用满权重矩阵的全部表示能力，而不是把更新限制在一个小子空间里，也不会带来低秩方法那种突发的局部失真。结果是模型收敛更好、各层之间的激活对齐更好，模型既能忠实贴合目标任务分布，也保留了预训练知识的丰富度。FFT 的质量优势随数据规模扩大而增强：在 100K+ 训练样本时，FFT 在代码生成任务的 LLM-as-Judge 语义正确率上达到 90.0%，如下图所示。

## 实验与基准结果

本文使用[监督微调（SFT）技术](https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-sft.html)，在 [Amazon SageMaker AI Studio](https://console.aws.amazon.com/sagemaker) 提供的 Qwen3-4B 基础模型上，通过 [SageMaker AI Serverless Model Customization](https://docs.aws.amazon.com/sagemaker/latest/dg/customize-model.html) 完成了 LoRA 与 FFT 两种训练方式的全部微调实验。每个实验中，两种方法拿到的 prompt、目标和评估代码完全相同。

## 数据集：代码生成 110K 指令对

全部实验都在 [Magicoder-Evol-Instruct-110K](https://huggingface.co/datasets/ise-uiuc/Magicoder-Evol-Instruct-110K) 数据集上微调 Qwen3-4B 基础模型。该数据集是经过整理的语料，包含 110,000 组编码指令-响应对，覆盖算法设计、调试、数据结构和系统编程。我们按 90/5/5 划分数据：99,000 条用于训练，5,500 条用于验证，在定制作业期间监控收敛情况与训练损失，另外 5,500 条留作测试集，用于对最终模型做无偏评估。这些数据注册在 SageMaker AI 数据集资产中，如下图所示。

![110K 指令对数据集及其在 SageMaker AI 数据集资产中注册的训练、验证和测试划分](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-3.png)

图 3：在 SageMaker AI 数据集资产中注册的 110K 指令对数据集

### Serverless Model Customization 作业

本文所有模型定制实验都在 Amazon SageMaker AI Serverless Model Customization 上完成。SageMaker AI 上的 Serverless Model Customization 让数据科学家和机器学习（ML）工程师不必管理基础设施、也不必规划 GPU 容量，可以把精力放在模型微调上。你只需指定基础模型、数据集和超参数，服务会以无服务器方式自动处理计算资源分配和 checkpoint 管理。下面的代码片段展示了如何用 SageMaker Python SDK 在 Serverless Model Customization 上启动一个全量微调（FFT）作业。

```
from sagemaker.train.sft_trainer import SFTTrainer
from sagemaker.train.common import TrainingType

trainer = SFTTrainer(
    model=base_model_id,
    training_type=TrainingType.FULL,
    model_package_group=model_package_group_name,
    training_dataset=training_dataset,
    validation_dataset=val_dataset,
    s3_output_path=output_path,
    sagemaker_session=sess,
    role=role,
)

# Configure hyperparameters as needed
trainer.hyperparameters.learning_rate = 2e-5
trainer.hyperparameters.global_batch_size = 8
trainer.hyperparameters.max_epochs = 2
trainer.hyperparameters.lr_warmup_steps_ratio = 0.1

trainer.train(wait=False)
```

这段代码会触发一个无服务器模型定制作业（如下图所示），训练指标在作业中跟踪，可在关联的 MLflow 应用中查看。

![SageMaker AI 中的无服务器模型定制作业，训练指标被跟踪并关联到 MLflow 应用](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-4.png)

图 4：在 MLflow 中跟踪训练指标的无服务器模型定制作业

从全量微调换成 LoRA 只需改一处：把 `TrainingType.FULL` 改为 `TrainingType.LORA`，其余代码完全不变：

```
trainer = SFTTrainer(
    model=base_model_id,
    training_type=TrainingType.LORA,  # ← only change
    model_package_group=model_package_group_name,
    training_dataset=training_dataset,
    validation_dataset=val_dataset,
    ...
)
```

### 模型评估与基准测试

我们用 SageMaker AI Serverless Model Customization 内置的三种[评估方法](https://docs.aws.amazon.com/sagemaker/latest/dg/model-customize-evaluation-types.html)，对定制后的模型做了测试：LLM-as-Judge、PRIMECODE 和 MMLU，如下图所示。三者分别针对模型质量的不同维度——语义正确性、代码生成保真度和通用知识留存，合起来构成对定制质量的完整画像。

![SageMaker AI Serverless Model Customization 中的三种内置评估方法（LLM-as-Judge、PRIMECODE 和 MMLU）](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-5.png)

图 5：SageMaker AI Serverless Model Customization 中的三种内置评估方法

LLM-as-Judge 指标使用一个前沿模型（本文中是 Amazon Nova Pro）作为自动评估器，它读取模型生成的代码和原始 prompt，判断解法在逻辑上是否正确。在无服务器模型定制上，你可以同时评估定制模型和基础模型，如下图所示。

![SageMaker AI 中用 LLM-as-Judge 评估比较定制模型和基础模型](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-6.png)

图 6：比较定制模型和基础模型的 LLM-as-Judge 评估

PRIMECODE 是一种自定义评分器评估，用确定性文本相似度指标衡量模型生成代码与参考解的接近程度：BLEU（n-gram 精确率）、ROUGE-1/2/L（偏向召回的重叠度）和 F1（精确率与召回率的平衡）。这些指标完全可复现，很适合用于受控消融实验。我们把 PRIMECODE 作为表层代码质量的主指标，因为它能度量模型对训练数据中编码模式、格式约定和实现风格的学习程度。BLEU 分数高，说明模型生成的代码在结构上与专家写法接近，结果如下图所示。

![定制模型的 PRIMECODE 文本相似度分数（BLEU、ROUGE 和 F1）](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-7.png)

图 7：定制模型的 PRIMECODE 文本相似度分数

MMLU（Massive Multitask Language Understanding）是一项内置基准，覆盖从抽象代数、解剖学到营养学、哲学的 57 个学科。它衡量模型在领域微调后是否还保住了广博的通用知识，如下图所示。我们把 MMLU 当作遗忘检测的护栏：在代码上微调可能会覆盖权重中存储的通用能力。对比微调前后的 MMLU 准确率，就能精确量化模型为提升代码生成牺牲了多少通用知识，以及我们的超参数选择是加速还是缓解了这一取舍。

![领域微调前后 57 个学科的 MMLU 准确率](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-8.png)

#### 大规模快速实验

SageMaker AI Serverless Model Customization 易于搭建和使用，让我们不用重新预置基础设施就能快速做实验。我们在 LoRA 和 FFT 之间切换训练类型、扫描超参数、在多个基础模型上测试。在很短的时间窗口内，我们围绕[多个受支持的基础模型](https://docs.aws.amazon.com/sagemaker/latest/dg/model-customize-open-weight.html)（Qwen3-4B、DeepSeek-R1-1.5B、Nemotron-30B、Gemma-4-26B）跑了几十个模型定制实验，系统地消融学习率、批大小、预热比例、epoch 数和数据集规模。每个实验从提交作业到拿到评估结果只需几个小时，产出的微调模型会自动以带版本的 Model Package 注册到 SageMaker Model Registry，可直接审查或部署。

## 超参数选项

SageMaker AI Serverless Model Customization 支持很多超参数。本节结合我们在前述代码生成任务上跨多组超参数配置做的一系列实验，解释其中几个重要的超参数。有效取值会因任务而异，但这些实验中呈现的规律可以作为配置 FFT 定制作业时的有用起点。关于启动 FFT 模型定制作业前可配置的超参数，详见[超参数文档页面](https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-sft.html#customizing-models-sft-hyperparameters)。

### 1. learning_rate

在全量微调中，学习率决定每个权重被更新的猛烈程度。LoRA 只改动小型适配矩阵，FFT 则不同：学习率过高会永久覆盖预训练知识。在我们的实验中，下面的「学习率 × 数据规模」风险图显示，在大数据集（超过 10 万条）上学习率取 2e-5 属于安全区。

![学习率 × 数据规模风险图，显示在 100K+ 数据集上 2e-5 为安全区](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-9.png)

图 9：全量微调的学习率与数据规模风险图

### 2. max_epochs

FFT 中的 epoch 数本质上是一个遗忘问题，而不是损失曲线问题。训练损失会一直下降，留出验证集看起来也很健康，因为它与训练数据同分布；但模型在所有未训练内容上的能力正在悄悄退化。LLM-as-Judge 正确率在 3 个 epoch 时升到 90.0%，超过 3 个 epoch 后，我们试过的每个变体都出现了退化。

### 3. global_batch_size

批大小决定每个梯度步骤有多少样本参与。学习率固定时，批越小，更新噪声越大，效果很像提高了学习率，遗忘风险随之上升；批越大，噪声越小，但优化步数也变少，可能欠拟合。

![固定学习率下全局批大小对模型质量的影响](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-10.png)

图 10：全局批大小对模型质量的影响

### 灾难性遗忘风险

FFT 会修改模型中的每一个参数，包括编码预训练阶段所获通用知识的那些参数。当微调把这些参数过于猛烈地推向一个狭窄领域时，模型可能「忘记」自己更广泛的能力，这就是灾难性遗忘。我们用 MMLU 系统地检验了这一点，测量了所有微调配置下的通用知识留存。warmup=5%、批大小 8、LR=2e-5 的基线配置对通用知识（MMLU）的保留最好，如下图所示。

![跨超参数配置的 MMLU 通用知识留存](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-11.png)

图 11：跨超参数配置的 MMLU 通用知识留存

因此需要注意，FFT 并非全面优于 LoRA，其效果对超参数选择极其敏感。例如在我们的实验中，FFT 和 LoRA 在 MATH 精确匹配上都低于基础模型，这凸显了在领域微调中保住推理能力的难度。FFT 下激进的学习率（LR ≥ 5e-5）破坏性尤其明显，MATH 分数跌到 2–3%，MMLU 准确率降到 3.6%，是灾难性遗忘的确凿证据。此外，LoRA 在 LLM-as-Judge 指标上略胜 FFT（81.5% 对 79.5%），说明参数高效方法在主观质量评估上仍可能占优。这些结果再次说明，FFT 与 LoRA 之间的取舍应当建立在认真实验、数据集特征和对相关权衡的清晰理解之上。

## 结论

借助 [Amazon SageMaker AI Serverless Model Customization 上的全量微调](https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-fft.html)，当任务复杂度和数据规模有需要时，你的模型可以充分吸收领域知识。如果你的场景需要深度适配——例如专门的推理、代码生成或领域语言理解——并且有足够的高质量训练数据，FFT 能带来可衡量的更强结果。

你可以在 [SageMaker AI Serverless Model Customization](https://console.aws.amazon.com/sagemaker/home) 上开始使用 FFT：无服务器训练、内置评估，无需规划基础设施或算力，从而专注于数据和超参数选择。你可以用 [SageMaker Python SDK](https://sagemaker.readthedocs.io/en/stable/) 以编程方式配置和启动训练与评估作业。关于 Serverless Model Customization 上全量微调支持哪些基础模型，请参阅[受支持基础模型的文档](https://docs.aws.amazon.com/sagemaker/latest/dg/model-customize-open-weight.html)。
