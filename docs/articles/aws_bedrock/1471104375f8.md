# 在 SageMaker AI Serverless Model Customization 上进行全量微调（FFT）

微调是指使用企业自有数据继续训练预训练大语言模型（LLM）的过程，使其适应特定领域、任务或风格，而不是仅依赖通用知识。对企业而言，其价值是双重的。微调后的模型在特定领域工作上能带来可衡量的更高准确率，同时降低成本：一个更小的专用模型可以在你的任务上达到或超越前沿模型，而每 token 推理价格仅为其一小部分。这些节省会在数百万次请求中不断累积。因此，对于希望以更低成本从 LLM 中获取更多价值的企业来说，微调已成为一项必不可少的流程。

低秩适配（LoRA）等参数高效微调（PEFT）方法已成为将 LLM 微调至下游任务的实用解决方案，它仅更新 LLM 参数的一小部分，从而降低 GPU 容量需求。LoRA 旨在在效率与表达能力之间取得平衡，然而，权重更新的低秩特性本质上限制了 LoRA 微调模型的表示能力，可能损害其在复杂任务上的性能。这种权衡妨碍了 LoRA 方法捕获多样任务所需的复杂模式。为应对这些挑战，全量微调（FFT）同时更新模型参数，克服低秩限制，使 LLM 能够充分吸收复杂的领域特定知识。

[Amazon SageMaker AI Serverless Model Customization](https://aws.amazon.com/sagemaker/ai/model-customization/) 现已支持 [全量微调（FFT）](http://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-fft.html)，因此你无需管理基础设施即可获得更优的模型质量。无需进行 GPU 预置、集群设置或分布式训练配置。在本文中，我们探讨 FFT 在何时、何处于关键基准上持续优于 LoRA，考察可解释这一质量差距的模型权重矩阵的谱特性，提供由使用 SageMaker AI Serverless Model Customization 的受控实验支持的实用超参数调优指南，并展示如何在 SageMaker AI 上开始使用 FFT。

## 全量微调：为何重要

LoRA 等模型定制类型通过冻结预训练模型的权重，并向模型层中注入小型、独立的替换矩阵对（称为低秩矩阵）来减少可训练参数。这对于简单适配效果良好，但低秩结构本质上限制了微调模型的表示能力。随着任务变得更加复杂、数据集规模超过数万条示例，LoRA 会达到准确率平台期，此时增加秩（从而增加可训练参数）也无法弥合与标准微调之间的准确率差距。这一平台期表明，性能差距并不只是因为参数更少。它是由秩亏缺本身造成的。低秩更新无法捕获深度任务适配所需的权重变化的全部复杂性。

然而，对于存在大规模高质量数据集的复杂任务和领域，全秩微调通过同时更新模型参数而表现出色。FFT 均匀地修改模型的权重矩阵，利用模型权重矩阵的全部表示能力，而不是将更新限制在一个小子空间中，也不会引入低秩方法特有的突然、局部化的失真。其结果是更强的模型收敛、跨模型层更好的激活对齐，以及一个忠实捕获目标任务分布和其预训练知识丰富性的模型。FFT 的质量优势随数据集规模增长而扩大：在 100K+ 训练示例时，FFT 在代码生成任务的 LLM-as-Judge 语义正确率上达到 90.0%，如下图所示。

## 实验与基准结果

在本文中，我们在 [Amazon SageMaker AI Studio](https://console.aws.amazon.com/sagemaker) 中提供的 Qwen3-4B 基础模型上使用了[监督微调（SFT）技术](https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-sft.html)，并使用 [SageMaker AI Serverless Model Customization](https://docs.aws.amazon.com/sagemaker/latest/dg/customize-model.html) 在 LoRA 和 FFT 训练方法上完成了所有微调实验。在每个实验中，两种方法都接收相同的提示、目标和评估代码。

## 数据集：代码生成 110K 指令对

在所有实验中，我们在 [Magicoder-Evol-Instruct-110K](https://huggingface.co/datasets/ise-uiuc/Magicoder-Evol-Instruct-110K) 数据集上微调 Qwen3-4B 基础模型，这是一个精选语料库，包含 110,000 个编码指令-响应对，涵盖算法设计、调试、数据结构和系统编程。我们对数据集应用了 90/5/5 划分：99,000 条记录用于训练，5,500 条用于验证以在定制作业期间监控收敛和训练损失，5,500 条保留作为留出测试集用于对最终模型进行无偏评估，并注册在 SageMaker AI 数据集资产中，如下图所示。

![110K 指令对数据集及其在 SageMaker AI 数据集资产中注册的训练、验证和测试划分](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-3.png)

### Serverless Model Customization 作业

本文中的所有模型定制实验均在 Amazon SageMaker AI Serverless Model Customization 上执行。SageMaker AI 上的 Serverless Model Customization 让数据科学家和机器学习（ML）工程师无需管理基础设施或规划 GPU 容量，即可专注于模型微调。你指定基础模型、数据集和超参数，该服务以无服务器方式自动处理计算分配和检查点管理。以下代码片段展示了使用 SageMaker Python SDK 在 Serverless Model Customization 上启动全量微调（FFT）作业的一个此类实验。

```
from sagemaker.train.sft_trainer import SFTTrainer
from sagemaker.train.common import TrainingType

trainer = SFTTrainer(
    model=base_model_id,
    training_type=TrainingType.FULL,
    model_package_group=model_package_group_name,
    training_dataset=training_dataset,
    validation_dataset=val_dataset,
    s3_output_path=output_path,
    sagemaker_session=sess,
    role=role,
)

# Configure hyperparameters as needed
trainer.hyperparameters.learning_rate = 2e-5
trainer.hyperparameters.global_batch_size = 8
trainer.hyperparameters.max_epochs = 2
trainer.hyperparameters.lr_warmup_steps_ratio = 0.1

trainer.train(wait=False)
```

该代码触发一个无服务器模型定制作业，如下图所示，训练性能指标在作业中跟踪，并可在链接的 MLflow 应用中查看。

![SageMaker AI 中的无服务器模型定制作业，跟踪训练指标并链接 MLflow 应用](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-4.png)

图 4：在 MLflow 中跟踪训练指标的无服务器模型定制作业

从全量微调切换到 LoRA 只需一处更改：将 `TrainingType.FULL` 设置为 `TrainingType.LORA`。其余代码保持相同：

```
trainer = SFTTrainer(
    model=base_model_id,
    training_type=TrainingType.LORA,  # ← only change
    model_package_group=model_package_group_name,
    training_dataset=training_dataset,
    validation_dataset=val_dataset,
    ...
)
```

### 模型评估与基准测试

我们在 SageMaker AI Serverless Model Customization 内置的三种多样化[评估方法](https://docs.aws.amazon.com/sagemaker/latest/dg/model-customize-evaluation-types.html)上测试了生成的定制模型：LLM-as-Judge、PRIMECODE 和 MMLU，如下图所示。每种方法针对模型质量的不同维度：语义正确性、代码生成保真度和通用知识保留度。它们共同提供了模型定制质量的全面图景。

LLM-as-Judge 指标使用前沿模型（本文中为 Amazon Nova Pro）作为自动评估器，它读取模型生成的代码及原始提示，并判断解决方案在逻辑上是否正确。在无服务器模型定制上，你可以同时评估定制模型和基础模型，如下图所示。

![SageMaker AI 中比较定制模型和基础模型的 LLM-as-Judge 评估](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-6.png)

PRIMECODE 是一种自定义评分器评估，使用确定性文本相似度指标衡量模型生成的代码与参考解决方案的匹配程度：BLEU（n-gram 精确率）、ROUGE-1/2/L（面向召回的重叠度）和 F1（精确率-召回率平衡）。这些指标完全可复现，使其非常适合受控消融研究。我们使用 PRIMECODE 作为表面级代码质量的主要指标，因为它量化了模型对训练数据中编码模式、格式约定和实现风格的学习程度。高 BLEU 分数意味着模型生成的代码在结构上看起来与专家编写的解决方案相似，如下方结果所示。

![定制模型的 PRIMECODE 文本相似度分数（BLEU、ROUGE 和 F1）](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-7.png)

图 7：定制模型的 PRIMECODE 文本相似度分数

MMLU（Massive Multitask Language Understanding）是一项内置基准，在从抽象代数和解剖学到营养学和哲学的 57 个学科上测试模型。它衡量模型在领域特定微调后是否保留其广泛的通用知识，如下图所示。我们使用 MMLU 作为遗忘检测护栏。在代码上微调可能会覆盖存储在模型权重中的通用能力。通过跟踪微调前后的 MMLU 准确率，我们可以精确量化模型为提升代码生成而牺牲了多少通用知识，以及我们的超参数选择是加速还是缓解这一权衡。

#### 大规模快速实验

SageMaker AI Serverless Model Customization 的设置和使用简便性让我们无需重新预置基础设施即可进行快速实验。我们在 LoRA 和 FFT 之间切换训练类型、扫描超参数，并在多个基础模型上测试。在短时间内，我们在[多个支持的基础模型](https://docs.aws.amazon.com/sagemaker/latest/dg/model-customize-open-weight.html)（Qwen3-4B、DeepSeek-R1-1.5B、Nemotron-30B、Gemma-4-26B）上运行了数十个模型定制实验，系统地消融学习率、批大小、预热比例、epoch 数和数据集规模。每个实验从作业提交到评估结果完成只需几小时，生成的微调模型自动注册到 SageMaker Model Registry 中作为带版本的 Model Packages，可供审查或部署。

## 超参数选项

SageMaker AI Serverless Model Customization 支持许多超参数。在本节中，我们解释其中几个重要的超参数，这些解释基于我们在前述代码生成任务中跨多个超参数配置运行的一系列实验。虽然有效值会因任务而异，但在这些实验中观察到的模式为配置 FFT 模型定制作业提供了有用的起点。有关在启动 FFT 模型定制作业前可配置的超参数的更多信息，请参阅[超参数文档页面](https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-sft.html#customizing-models-sft-hyperparameters)。

### 1. learning_rate

在全量微调中，学习率控制每个权重更新的激进程度。与 LoRA 只改变小型适配矩阵不同，FFT 学习率过高会永久覆盖预训练知识。在我们的实验中，以下 LR × 数据集规模风险图显示，在大数据集（超过 10 万）上 LR 为 2e-5 是安全区。

![学习率 × 数据集规模风险图，显示在 100K+ 数据集上 2e-5 为安全区](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-9.png)

图 9：全量微调的学习率与数据集规模风险图

### 2. max_epochs

FFT 中的 epoch 数本质上是一个遗忘问题，而不是损失曲线问题。训练损失会持续下降，你的留出验证看起来会很健康，因为它与训练数据共享同一分布，但模型在你未训练过的所有内容上的能力会悄然退化。LLM-as-Judge 正确率分数在 3 个 epoch 时升至 90.0%，而超过 3 个 epoch 会降低我们实验过的每个变体。

### 3. global_batch_size

批大小决定每个梯度步骤有多少示例参与。在固定学习率下，较小的批产生更多噪声更新，其行为很像更高的学习率，增加遗忘风险。较大的批减少噪声，但也减少优化步骤数，可能导致欠拟合。

![固定学习率下全局批大小对模型质量的影响](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-10.png)

图 10：全局批大小对模型质量的影响

### 灾难性遗忘风险

FFT 修改模型中的每个参数，包括编码预训练期间获得的通用知识的参数。当微调将这些参数过于激进地推向狭窄领域时，模型可能会“忘记”其更广泛的能力，这种现象称为灾难性遗忘。我们使用 MMLU 系统地测试了这一点，测量了所有微调配置下的通用知识保留度。warmup=5%、批大小 8、LR=2e-5 的基线配置最好地保留了通用知识（MMLU），如下图所示。

![跨微调超参数配置的 MMLU 通用知识保留度](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/16/ML-21644-11.png)

图 11：跨超参数配置的 MMLU 通用知识保留度

因此，务必注意 FFT 并非普遍优于 LoRA，其有效性对超参数选择极为敏感。例如，在我们的实验中，FFT 和 LoRA 在 MATH 精确匹配上都低于基础模型，突显了在领域特定微调期间保留推理能力的挑战。FFT 中激进的学习率（LR ≥ 5e-5）被证明尤其具有破坏性，导致 MATH 分数骤降至 2–3%，MMLU 准确率降至 3.6%，这是灾难性遗忘的明确证据。此外，LoRA 在 LLM-as-Judge 指标上略优于 FFT（81.5% 对 79.5%），表明参数高效方法在主观质量评估上仍可占据优势。这些发现强化了一点：FFT 与 LoRA 之间的选择应以仔细的实验、数据集特征以及对相关权衡的清晰理解为指导。

## 结论

借助 [Amazon SageMaker AI Serverless Model Customization 上的全量微调](https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-fft.html)，当任务复杂性和数据规模需要时，你的模型可以充分吸收领域特定知识。如果你的用例需要深度适配，例如专门推理、代码生成或领域特定语言理解，并且你有足够的高质量训练数据，FFT 能带来可衡量的更强结果。

你可以通过无服务器训练、内置评估，且无需基础设施或计算容量规划，在 [SageMaker AI Serverless Model Customization](https://console.aws.amazon.com/sagemaker/home) 上开始使用 FFT，从而专注于你的数据和超参数选择。你可以使用 [SageMaker Python SDK](https://sagemaker.readthedocs.io/en/stable/) 以编程方式配置和启动训练与评估作业。你可以查看[支持的基础模型文档](https://docs.aws.amazon.com/sagemaker/latest/dg/model-customize-open-weight.html)，了解可用于 Serverless Model Customization 上全量微调的模型。
