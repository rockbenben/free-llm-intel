# 在 Flo Health 使用 Amazon Bedrock 扩展医疗内容审核规模（第 1 部分）

*本文基于与 Flo Health 共同开发的成果。*

医疗科学正在快速进步。维护准确且最新的医疗内容，直接影响人们的生活、健康决策与福祉。当人们搜索健康信息时，往往正处于最脆弱的时刻，因此准确性不仅重要，还可能关乎生命。

[Flo Health](https://flo.health/) 每年创作数千篇医疗文章，为全球数百万用户提供关于女性健康的医学可信信息。核验这一庞大内容库的准确性与相关性是一项重大挑战。医学知识持续演进，逐篇人工审核不仅耗时，而且容易产生人为错误。这正是 Flo Health（领先女性健康应用 Flo 背后的公司）团队使用[生成式 AI](https://aws.amazon.com/ai/generative-ai/) 来大规模保障医疗内容准确性的原因。通过与 [AWS Generative AI Innovation Center](https://aws.amazon.com/ai/generative-ai/innovation-center/) 合作，Flo Health 正在开发一种创新方法，称为“医疗内容自动审核与修订优化方案”（*MACROS*），用于核验并维护其庞大健康信息库的准确性。这套 AI 驱动的方案能够：

- 基于可信的科学来源，高效处理大量医疗内容。
- 基于可信的科学资源，识别潜在的不准确或过时信息。
- 基于最新的医学研究与指南提出更新建议，并吸收用户反馈。

这套由 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 驱动的系统，使 Flo Health 能够大规模开展医疗内容审核与修订评估，确保内容保持最新且准确，并支持更明智的医疗健康决策。系统会执行详细的内容分析，就医疗标准与指南的遵循情况提供全面洞察，供 Flo 的医学专家审阅。它还被设计为可与 Flo 现有的技术基础设施无缝集成，在适当之处实现自动更新。

这个由两部分组成的系列将探讨 Flo Health 在医疗内容核验中使用生成式 AI 的历程。第 1 部分考察我们的概念验证（PoC），包括初始方案、能力与早期结果。第 2 部分聚焦规模化挑战与真实落地。每篇文章都可独立阅读，合起来则展示了 AI 如何在大规模下改变医疗内容管理。

## 概念验证的目标与成功标准

在深入技术方案之前，我们为 PoC 医疗内容审核系统确立了明确的目标：

关键目标：

- 验证使用生成式 AI 进行医疗内容核验的可行性
- 确定与人工审核相比的准确率水平
- 评估处理时间与成本的改善

成功指标：

- 准确率：内容召回率达到 90%
- 效率：将每条指南的检测时间从数小时缩短到数分钟
- 成本降低：减少专家审核工作量
- 质量：维持 Flo 的编辑标准与医学准确性
- 速度：比人工审核流程快 10 倍

为核验该方案是否达到 Flo Health 对医疗内容的高标准，Flo Health 的医学专家与内容团队通过定期评审会议，与 AWS 技术专家密切合作，提供关键反馈与医学专业知识，持续提升 AI 模型的性能与准确率。其成果就是 MACROS——我们为 AI 辅助医疗内容核验量身打造的方案。

## 内容审核与修订

MACROS 的核心是基于 Amazon Bedrock 基础模型的内容审核与修订功能。内容审核与修订模块由五个主要组件构成：1）可选的**过滤**阶段 2）**分块** 3）**审核** 4）**修订** 5）**后处理**，如图 3 所示。

图 3. 内容审核与修订流水线

下面是 MACROS 处理上传医疗内容的方式：

- **过滤**（可选）：流程从可选的过滤步骤开始。这一智能特性会检查规则集是否与该文章相关，可能节省花在不必要处理上的时间与资源。
- **分块**：源文本随后被切分为段落。这一关键步骤有助于保证评估质量，并帮助避免对无关文本产生非预期的修订。分块可以使用启发式方法（例如基于标点或正则表达式的切分），也可以使用大语言模型（LLM）来识别语义完整的文本块。
- **审核**：每个段落或小节都会依据相关规则与指南接受细致审核。
- **修订**：只有被标记为不合规的段落才进入修订阶段，从而精简流程并保持合规内容的完整性。AI 会给出更新建议，使不合规段落符合最新指南与 Flo 的风格要求。
- **后处理**：最后，经过修订的段落被无缝整合回原文，得到一份更新后的合规文档。

**过滤**步骤可以通过再次调用 Amazon Bedrock 上的 LLM 来完成，它会用如下 prompt 结构分别评估每个小节：

图 4. 简化的基于 LLM 的过滤步骤

此外，非 LLM 的方法也可以支撑**过滤**步骤：

- 把规则与文章编码为稠密 embedding 向量，并计算它们之间的相似度。通过设定相似度阈值，我们可以判断哪套规则集与输入文档相关。
- 类似地，可以使用 BLEU 或 ROUGE 指标识别文档与规则之间直接的关键词级重叠。

**内容审核**，如前所述，是逐文本小节、依据一组规则进行的，输出为 XML 格式，例如：

```
<xml>
<section_text> Section text without any changes </section_text>
<adherence> 0 <adherence>
<rule_name> Text of the non-adherent rule </rule_name>
<reason> Reason why the section is non-adherent to the rule </reason>
<rule_name> Text of the non-adherent rule </rule_name>
<reason> Reason why the section is non-adherent to the rule </reason>
<section_text> Section text without any changes </section_text>
<adherence> 1 <adherence>
<section_text> Section text without any changes </section_text>
<adherence> 1 <adherence>
</xml>
```

这里，1 表示文本遵循指定规则，0 表示不遵循。使用 XML 格式有助于实现可靠的输出解析。

这一**审核**步骤会遍历文本中的各小节，确保 LLM 分别关注每一小节，这在我们的实验中带来了更稳健的结果。为帮助提升不合规小节的检测准确率，用户还可以使用**多次调用**模式：不再用一次 Amazon Bedrock 调用评估文章对所有规则的遵循情况，而是为每条规则各做一次独立调用。

**修订**步骤接收**审核**的输出（不合规小节及其不合规原因），以及按相似语气生成修订的指令。随后它会对不合规句子给出风格与原文本相近的修订建议。最后，**后处理**步骤把原文与新修订合并，确保其他小节不被改动。

流程的不同步骤对 LLM 模型的复杂度要求不同。分块这类较简单的任务，用 Claude Haiku 系列这样相对较小的模型就能高效完成；而内容审核与修订这类更复杂的推理任务，则需要 Claude Sonnet 或 Opus 系列等更大的模型，以实现准确的分析与高质量的内容生成。这种分层选择模型的做法同时优化了方案的性能与成本效率。

## 从非结构化数据中提取规则与指南

可执行且准备充分的指南并不总是现成可用。有时它们以非结构化文件的形式给出，有时还需要自行查找。借助**规则优化器**功能，我们可以从多个复杂文档中提取并精炼出可执行的指南。

**规则优化器**处理原始 PDF 文档以提取文本，然后依据文档标题把文本切分为有意义的段落。这些分段内容会通过 [Amazon Bedrock](https://aws.amazon.com/de/bedrock/?gclid=Cj0KCQiA4-y8BhC3ARIsAHmjC_HI-0NZkYadpbfdRCPUw13_1NrG_AzsnUfhVAm41Ya_Gy5IE49gat8aAhwAEALw_wcB&trk=ef63b8f9-8bab-42d8-949e-d4b30149c6e9&sc_channel=ps&ef_id=Cj0KCQiA4-y8BhC3ARIsAHmjC_HI-0NZkYadpbfdRCPUw13_1NrG_AzsnUfhVAm41Ya_Gy5IE49gat8aAhwAEALw_wcB:G:s&s_kwcid=AL!4422!3!691967569191!e!!g!!amazon%20bedrock!21054971687!157173595137) 使用专门的 system prompt 进行处理，并有两种不同模式：**风格/语气**模式与 **Medical** 模式。

**风格/语气**模式专注于提取关于文本应如何书写的指南：风格如何，哪些格式与词语可用或不可用。

**规则优化器**会为每条规则指定优先级：高、中、低。优先级表示规则的重要程度，用来指导内容审核的顺序，把注意力首先集中在关键区域。**规则优化器**包含一个手工编辑界面，用户可以精炼规则文本、调整分类并管理优先级。因此，如果用户需要更新某条规则，改动会保存在 [Amazon S3](https://aws.amazon.com/pm/serv-s3/?gclid=Cj0KCQiA4-y8BhC3ARIsAHmjC_FSC7URGVCHPG51tz_HAQjvfBiurbG-isAdtPX6DXhvFmfncSKpJU0aAhxnEALw_wcB&trk=518a7bef-5b4f-4462-ad55-80e5c177f12b&sc_channel=ps&ef_id=Cj0KCQiA4-y8BhC3ARIsAHmjC_FSC7URGVCHPG51tz_HAQjvfBiurbG-isAdtPX6DXhvFmfncSKpJU0aAhxnEALw_wcB:G:s&s_kwcid=AL!4422!3!645186213484!e!!g!!amazon%20s3!19579892800!143689755565) 中供后续使用。

**Medical** 模式专为处理医疗文档而设计，适配更偏科学的语言。它允许把提取出的规则归入三个类别：

- 医疗状况指南
- 治疗专项指南
- 健康建议与趋势的变更

图 6. 简化的医疗规则优化 prompt

图 6 给出了一个医疗规则优化 prompt 的示例，它由三个主要部分构成：角色设定——医学 AI 专家；对什么算作优质规则的描述；以及最终期望的输出。当一条规则满足以下条件时，我们认定其质量足够好：

- 清晰、无歧义且可执行
- 相关、一致且简洁（最多两句）
- 以主动语态书写
- 避免不必要的术语

## 实施考量与挑战

在 PoC 开发过程中，我们识别出若干对其他实施类似方案的人有帮助的关键考量：

- **数据准备**：这成为一项基础性挑战。我们认识到为医疗内容与指南统一输入格式、同时保持一致的文档结构的重要性。事实证明，为不同医学主题构建多样化测试集对全面验证至关重要。
- **成本管理**：监控并优化成本很快成为关键优先事项。我们实施了 token 用量跟踪，并优化 prompt 设计与批处理，以在性能与效率之间取得平衡。
- **监管与伦理合规**：鉴于医疗内容的敏感性，严格的监管与伦理保障至关重要。我们为 AI 决策建立了健全的文档记录实践，对医疗指南实施严格的版本控制，并对 AI 生成的建议保持持续的医学专家人工监督。整个实施过程中都审慎考虑了各地区的医疗监管要求。
- **集成与扩展**：我们建议从独立的测试环境起步，同时规划通过设计良好的 API 端点在未来集成内容管理系统（CMS）。带着模块化思维来构建，对后续增强很有价值。整个过程里，我们也遇到了一些常见挑战，例如在长篇医疗文章中保持上下文、在处理速度与准确率之间取得平衡，以及让 AI 建议的修订保持一致的语气。
- **模型优化**：[Amazon Bedrock](https://aws.amazon.com/bedrock) 多样的模型选择能力尤为有价值。通过其平台，我们可以为特定任务选择最优模型、在不牺牲准确率的前提下实现成本效率，并平滑升级到更新的模型——同时保持现有架构不变。

## 初步结果

我们的概念验证在各项关键成功指标上取得了扎实成果，展示了 AI 辅助医疗内容审核的潜力。该方案超出了处理速度提升的目标，同时在识别需要更新的内容方面保持了 80% 的准确率和超过 90% 的召回率。最值得注意的是，这套 AI 驱动的系统在应用医疗指南方面比人工审核更一致，并显著减轻了医学专家的时间负担。

## 关键要点

在实施过程中，我们发现了若干对优化医疗内容分析中 AI 性能至关重要的洞见。内容分块对长文档的准确评估不可或缺，而解析规则的专家校验则帮助医学专家保持临床精确性。最重要的是，项目确认了成功落地的关键在于人机协作，而非完全自动化。定期的专家反馈与清晰的性能指标指导着系统的精炼与渐进改进。尽管系统显著精简了审核流程，它最好作为增强工具使用，医学专家仍是最终核验不可或缺的一环，从而形成一种更高效的混合式医疗内容管理方式。
