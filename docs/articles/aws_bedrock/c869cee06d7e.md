# 使用 Amazon Bedrock Knowledge Bases 与 Amazon S3 Vectors 构建高性价比的 RAG 应用

向量 embedding 已成为现代[检索增强生成（RAG）](https://aws.amazon.com/what-is/retrieval-augmented-generation/)应用不可或缺的组成部分，但组织在扩展规模时会面临显著的成本挑战。随着知识库增长并需要更细粒度的 embedding，许多依赖 SSD 或内存方案等高性能存储的向量数据库会变得昂贵到难以承受。这一成本门槛常常迫使组织限制 RAG 应用的范围，或牺牲向量表示的粒度，从而可能影响结果质量。此外，对于仍需要保持可检索的历史或归档数据用例，将向量存放在专为高吞吐工作负载优化的专用向量数据库中，意味着不必要的持续性开销。

自 7 月 15 日起，[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 客户可以选择 [Amazon S3 Vectors](https://aws.amazon.com/s3/features/vectors/)（预览版）作为向量存储——这是首个内置支持以低成本存储和查询向量的云对象存储。Amazon Bedrock Knowledge Bases 用户现在可以将向量上传、存储和查询成本降低最多 90%。S3 Vectors 专为大规模向量数据集的持久且成本优化的存储而设计，提供亚秒级查询性能，非常适合需要长期存储海量向量、并且能够接受相比高 QPS、毫秒级延迟的向量数据库在性能上有所折衷的 RAG 应用。与 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的集成意味着你可以构建更经济的 RAG 应用，同时保留获得高质量结果所需的语义搜索性能。

本文中，我们演示如何将 Amazon S3 Vectors 与 Amazon Bedrock Knowledge Bases 集成以用于 RAG 应用。你将学到一种实用方法：在保持检索质量并使用 S3 Vectors 高性价比存储的前提下，将知识库扩展到可处理数百万文档的规模。

## Amazon Bedrock Knowledge Bases 与 Amazon S3 Vectors 集成概览

在 Amazon Bedrock 中创建知识库时，你可以选择 S3 Vectors 作为向量存储选项。采用这种方式，你无需预置或管理复杂的基础设施，就能构建高性价比、可扩展的 RAG 应用。该集成在保持亚秒级查询性能的同时带来显著的成本节省，因此非常适合处理从文本、图像、音频和视频等海量非结构化数据中生成的大规模向量数据集。S3 Vectors 采用低价位的按需付费定价模式，提供业界领先的成本优化，相比其他方案可将向量上传、存储和查询成本降低最多 90%。高级搜索能力包括丰富的元数据过滤，因此你可以按日期、类别和来源等文档属性来细化查询。S3 Vectors 与 Amazon Bedrock 的组合非常适合构建大规模知识库、既要求成本效益又要求高性能检索的组织——从管理庞大的文档仓库到历史归档，以及需要细粒度向量表示的应用。整个操作流程遵循以下高层步骤：

- 创建新的知识库
- 配置数据源
- 配置数据源与处理
- 同步数据源
- 测试知识库

## 先决条件

在开始之前，请确保你已具备以下先决条件：

- 一个具有相应服务访问权限的 AWS 账户。
- 一个具有访问 Amazon Bedrock 和 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）相应权限的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色。
- 为 [Amazon Titan Text Embeddings V2](https://aws.amazon.com/bedrock/amazon-models/titan/) 和 [Amazon Nova Pro](https://aws.amazon.com/ai/generative-ai/nova/) 等 embedding 模型与推理模型启用[模型访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)。

## Amazon Bedrock Knowledge Bases 与 Amazon S3 Vectors 集成操作指南

本节中，我们使用 [AWS Management Console](https://aws.amazon.com/console/) 逐步演示如何创建使用 Amazon S3 Vectors 的知识库。我们涵盖从配置向量存储到摄取文档并测试检索能力的端到端流程。

对于更愿意以程序方式而非使用控制台配置知识库的读者，GitHub 上的 [Amazon Bedrock Knowledge Bases with S3 Vectors 仓库](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/rag/knowledge-bases/features-examples/10-s3-vectors/knowledge-base-s3-vector.ipynb) 提供了一个引导式 notebook，你可以按它在你自己的账户中部署该设置。

### 创建新的知识库

要创建新的知识库，请按以下步骤操作：

- 在 Amazon Bedrock 控制台的左侧导航窗格中，选择 **Knowledge Bases**。要启动创建流程，在 **Create** 下拉列表中选择 **Knowledge Base with vector store**。
- 在 **Provide Knowledge Base details** 页面，为知识库输入一个描述性名称，并可选择输入描述以说明其用途。选择你的 IAM 权限方式——新建一个服务角色或使用已有角色——以授予访问 AWS 服务所需的权限，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ml-19266-image-1.jpeg)

- 选择 **Amazon S3**。可选地，添加标签以帮助组织和分类资源，并配置日志投递目的地（例如 S3 桶或 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/)）以便监控和排查问题。
- 选择 **Next** 以进入数据源配置。

### 配置数据源

要配置数据源，请按以下步骤操作：

- 为你的知识库数据指定一个描述性名称。
- 在 **Data source location** 中，选择该 S3 桶位于你当前的 AWS 账户还是其他账户，然后指定文档的存储位置，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ml-19266-image-2.png)

在此步骤中，配置解析策略，以确定 Amazon Bedrock 如何处理你的文档。对于纯文本文档，选择 **Amazon Bedrock default parser**，不产生额外费用。对于处理含视觉元素的复杂文档，选择 **Amazon Bedrock Data Automation as parser or Foundation models as a parser**。

分块策略配置同样关键，因为它决定了内容如何被切分为有意义的单元以进行向量嵌入，直接影响检索质量和上下文保留。由于 token 尺寸可预测且简单，本示例中我们选择了 **Fixed-size chunking**。由于解析和分块决策在创建后都无法修改，请选择最贴合你内容结构和检索需求的选项。对于敏感数据，你可以使用高级设置来实施 [AWS Key Management Service](https://aws.amazon.com/kms/)（AWS KMS）加密，或应用自定义转换函数在摄取前优化文档。默认情况下，S3 Vectors 将使用服务端加密（SSE-S3）。

### 配置数据存储与处理

要配置数据存储与处理，首先选择 embeddings 模型，如下图所示。embeddings 模型会将你的文本 chunk 转换为数值向量表示，以支持语义搜索能力。如果要连接到已有的 S3 Vector 作为向量存储，请确保 embedding 模型的维度与创建向量存储时所用的维度一致，因为维度不匹配会导致摄取失败。Amazon Bedrock 提供多个 embeddings 模型可供选择，各自具有不同的向量维度和性能特性，并针对不同用例优化。做选择时请同时考虑模型的语义丰富度和成本影响。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ml-19266-image-3.jpeg)

接下来，配置向量存储。在向量存储选择中，选择 Amazon Bedrock Knowledge Bases 将如何通过以下两种方式之一，在 Amazon S3 Vectors 中存储和管理由你的文档生成的向量 embedding：

#### *方案 1：快速创建新的向量存储*

这一推荐方案如下图所示，会在创建知识库期间自动在你的账户中创建一个 S3 vector 桶。系统会为你的向量存储进行优化，以实现大规模向量数据集的高性价比、持久存储，并为你创建 S3 vector 桶和向量索引。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ml-19266-image-4.png)

#### *方案 2：使用已有的向量存储*

在创建 Amazon S3 Vector 作为供 Amazon Bedrock Knowledge Bases 使用的向量存储索引时，你可以为每个向量附加元数据（例如年份、作者、类型和位置）作为键值对。默认情况下，元数据字段可用于相似性查询中的过滤，除非在创建向量索引时被指定为不可过滤元数据。S3 Vector 索引支持字符串、数字和布尔类型，每个向量最多 40 KB，其中可过滤元数据上限为每个向量 2 KB。

为容纳更大的文本 chunk 和更丰富的元数据，同时仍允许对其它重要属性进行过滤，可将 `"AMAZON_BEDROCK_TEXT"` 添加到索引配置中的 `nonFilterableMetadataKeys` 列表。这种方法在为文档内容优化存储分配的同时，保留了对类别或日期等有意义属性的过滤能力。请记住，添加到 `nonFilterableMetadataKeys` 数组的字段无法在查询中用于元数据过滤，且索引创建后无法修改。

以下是以正确的元数据配置创建 Amazon S3 Vector 索引的示例：

```
s3vectors.create_index(
    vectorBucketName="my-first-vector-bucket",
    indexName="my-first-vector-index",
    dimension=1024,
    distanceMetric="cosine",
    dataType="float32",  
    metadataConfiguration={"nonFilterableMetadataKeys": ["AMAZON_BEDROCK_TEXT"]} 
)
```

关于如何创建向量存储的详细信息，请参阅 AWS News Blog 中的 [Introducing Amazon S3 Vectors](https://aws.amazon.com/blogs/aws/introducing-amazon-s3-vectors-first-cloud-storage-with-native-vector-support-at-scale/)。

在拥有 S3 Vector 桶和索引之后，你可以将其连接到知识库。你需要同时提供 S3 Vector 桶的 [Amazon Resource Name](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference-arns.html)（ARN）和向量索引 ARN，如下图所示，以便正确地将知识库链接到你已有的 S3 Vector 索引。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ml-19266-image-5.jpeg)

### 同步数据源

使用 S3 Vectors 配置好知识库后，你需要同步数据源以生成并存储向量 embedding。在 Amazon Bedrock Knowledge Bases 控制台中，打开你创建的知识库，找到已配置的数据源并选择 **Sync** 以启动该过程，如下图所示。同步期间，系统会按你的解析和分块配置处理文档，使用你所选的模型生成 embedding，并将其存入你的 S3 向量索引。如果你已配置 [Amazon CloudWatch Logs](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/WhatIsCloudWatchLogs.html)，还可以实时监控同步进度，并在测试知识库的检索能力之前确认完成状态。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ml-19266-image-6.jpeg)

### 测试知识库

使用 S3 Vectors 成功配置知识库后，你可以使用内置的测试界面验证其功能。你可以在这个交互式控制台中试验不同类型的查询，并查看检索结果和生成的回答。在 **Retrieval only**（Retrieve API）模式之间选择，以检查原始源 chunk；或选择 **Retrieval and Response generation**（`RetrieveandGenerate` API），了解 Amazon Nova 等[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM）如何使用检索到的内容。测试界面会展示源 chunk、它们的相关性分数以及关联的元数据，从而让你深入了解知识库处理查询的方式。

你还可以像使用其他向量存储选项那样为知识库配置查询设置，包括基于元数据选择的过滤器、确保回答适当的 guardrails、重排序能力以及查询修改选项。这些工具有助于优化检索质量，确保向你的 FM 呈现最相关的信息。S3 Vectors 目前支持语义搜索功能。通过这种动手验证，你可以在将知识库集成到生产应用之前完善配置。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ml-19266-image-7.jpeg)

## 以程序方式创建 Amazon Bedrock 知识库

在之前几节中，我们使用 AWS Management Console 演示了如何创建使用 Amazon S3 Vectors 的知识库。对于更愿意自动化此流程或将其集成到现有工作流的读者，也可以使用 [AWS SDK](https://aws.amazon.com/developer/tools/) 以程序方式创建知识库。

以下示例代码展示了在使用已有 Amazon S3 Vector 索引以程序方式创建 Amazon Bedrock 知识库时，API 调用是什么样子：

```
response = bedrock.create_knowledge_base(
    description='Amazon Bedrock Knowledge Base integrated with Amazon S3 Vectors',
    knowledgeBaseConfiguration={
        'type': 'VECTOR',
        'vectorKnowledgeBaseConfiguration': {
             'embeddingModelArn': f'arn:aws:bedrock:{region}::foundation-model/amazon.titan-embed-text-v2:0',
             'embeddingModelConfiguration': {
                 'bedrockEmbeddingModelConfiguration': {
                     'dimensions': vector_dimension, #Verify this is the same value as S3 vector index configuration
                     'embeddingDataType': 'FLOAT32'
                 }
             },
        },
    },
     name=knowledge_base_name,
     roleArn=roleArn,
     storageConfiguration={
         's3VectorsConfiguration': {
             'indexArn': vector_index_arn
         },
         'type': 'S3_VECTORS'
     }
)
```

附加到知识库的角色应当附加若干策略，包括访问 S3 Vectors API、用于 embedding、生成和重排序（如使用）的模型，以及作为数据源的 S3 桶的权限。如果你的 S3 Vector 作为向量存储使用了客户托管密钥，还需要额外提供一条策略以允许解密数据。以下是访问作为向量存储的 Amazon S3 Vector 所需的策略：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "BedrockInvokeModelPermission",
            "Effect": "Allow",
            "Action": [
                "bedrock:InvokeModel"
            ],
            "Resource": [
                "arn:aws:bedrock:{REGION}::foundation-model/amazon.titan-embed-text-v2:0"
            ]
        },
        {
            "Sid": "KmsPermission",
            "Effect": "Allow",
            "Action": [
                "kms:GenerateDataKey",
                "kms:Decrypt"
            ],
            "Resource": [
                "arn:aws:kms:{REGION}:{ACCOUNT_ID}:key/{KMS_KEY_ID}"
            ]
        },
        {
            "Sid": "S3ListBucketPermission",
            "Effect": "Allow",
            "Action": [
                "s3:ListBucket"
            ],
            "Resource": [
                "arn:aws:s3:::{SOURCE_BUCKET_NAME}"
            ],
            "Condition": {
                "StringEquals": {
                    "aws:ResourceAccount": [
                        "{ACCOUNT_ID}"
                    ]
                }
            }
        },
        {
            "Sid": "S3GetObjectPermission",
            "Effect": "Allow",
            "Action": [
                "s3:GetObject"
            ],
            "Resource": [
                "arn:aws:s3:::{SOURCE_BUCKET_NAME}/{PREFIX}/*"
            ],
            "Condition": {
                "StringEquals": {
                    "aws:ResourceAccount": [
                        "{ACCOUNT_ID}"

            ],
            "Resource": "arn:aws:s3vectors:{REGION}:{ACCOUNT_ID}:bucket/{VECTOR_BUCKET_NAME}/index/{VECTOR_INDEX_NAME}",
            "Condition": {
                "StringEquals": {
                    "aws:ResourceAccount": "{ACCOUNT_ID}"
                }
            }
        }
    ]
}
```

## 清理

要清理资源，请完成以下步骤。删除知识库：

- 在 Amazon Bedrock 控制台上，选择 **Knowledge Bases**
- 选择你的知识库，并记下 IAM 服务角色名称和 S3 Vector 索引 ARN
- 选择 **Delete** 并确认

要删除作为向量存储的 S3 Vector，请使用以下 [AWS Command Line Interface](https://aws.amazon.com/cli/)（AWS CLI）命令：

```
aws s3vectors delete-index --vector-bucket-name YOUR_VECTOR_BUCKET_NAME --index-name YOUR_INDEX_NAME --region YOUR_REGION
aws s3vectors delete-vector-bucket --vector-bucket-name YOUR_VECTOR_BUCKET_NAME --region YOUR_REGION
```

- 在 IAM 控制台上，找到先前记下的角色
- 选择并删除该角色

要删除示例数据集：

- 在 Amazon S3 控制台上，找到你的 S3 桶
- 选择并删除你为本教程上传的文件

## 结论

Amazon Bedrock Knowledge Bases 与 Amazon S3 Vectors 的集成，代表着在让 RAG 应用在规模化时更易获得且更经济可行方面的重要进展。借助 Amazon S3 Vectors 成本优化的存储，组织现在能够以更高的成本效率构建规模化知识库。这意味着客户可以在性能与经济性之间取得最优平衡，从而专注于通过 AI 驱动的应用创造价值，而不必管理复杂的向量存储基础设施。

要开始使用 Amazon Bedrock Knowledge Bases 与 Amazon S3 Vectors 的集成，请参阅 Amazon S3 User Guide 中的 [Using S3 Vectors with Amazon Bedrock Knowledge Bases](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-bedrock-kb.html)。
