# 用生成式 AI 加速保单审查：Verisk 的 Mozart companion

*本文与来自 Verisk 的 Sundeep Sardana、Malolan Raman、Joseph Lam、Maitri Shah 和 Vaibhav Singh 合写。*

[Verisk](https://www.nasdaq.com/market-activity/stocks/vrsk)（Nasdaq: VRSK）是全球保险行业领先的战略数据分析与技术合作伙伴，帮助客户提升运营效率、改善承保与理赔成果、打击欺诈，并就全球风险做出明智决策。通过先进的数据分析、软件、科学研究和深厚的行业知识，Verisk 帮助在个人、社区和企业层面构建全球韧性。作为在保险行业使用[生成式 AI](https://aws.amazon.com/generative-ai/)的先行者，Verisk 的生成式 AI 驱动解决方案（例如 Mozart）始终扎根于合乎伦理且负责任的 AI 使用。Mozart 是用于创建和更新保险表单的领先平台，让客户能够无缝地组织、编写和提交表单；而它的 companion 使用生成式 AI 在数分钟内比较保单文档并提供变更摘要，将变更采纳时间从数天或数周缩短到数分钟。

由生成式 AI 驱动的 Mozart companion 使用先进的 AI 来比较法律保单文档，并以易于理解的结构化格式提供它们之间的关键差异。新的 Mozart companion 使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 构建。Amazon Bedrock 是一项完全托管的服务，通过单一 API 提供来自 AI21 Labs、Anthropic、Cohere、Meta、Mistral AI、Stability AI 和 Amazon 等领先 AI 公司的高性能基础模型（FM）选择，并提供一整套能力，让你以安全、隐私和负责任 AI 的方式构建生成式 AI 应用。Mozart 应用可快速比较保单文档，并以修订痕迹格式呈现全面的变更详情，例如变更描述、位置和摘录。

以下截图展示了 Mozart companion 的输出示例，其中显示两份法律文档之间的变更摘要、原始文档版本中的摘录、新文档版本中更新后的摘录，以及用红线标注的修订痕迹。

## 数据：保单表单

Mozart 旨在编写保单表单，例如承保范围和批单。这些文档提供有关保单承保范围和除外责任的信息（如下图所示），并有助于确定与保单相关的风险和保费。

![Document Example](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/15/Picture2-3.png)

## 解决方案概览

保单文档存放在 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）存储中。一个 [AWS Batch](https://aws.amazon.com/batch/) 作业读取这些文档，将它们切分成更小的片段，然后使用 [Amazon Titan Text Embeddings](https://aws.amazon.com/bedrock/titan/) 模型通过 Amazon Bedrock 为文本块创建嵌入，并把它们存储在 [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 向量数据库中。除了每个文档片段，我们还使用内部 Metadata API 存储与之关联的元数据，该 API 提供文档类型、司法管辖区、版本号和生效日期等文档特征。此过程已实现为定期作业，以便用新文档保持向量数据库的更新。在解决方案设计过程中，Verisk 也考虑过使用 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)，因为它专为在 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/) 中创建和存储嵌入而构建。未来，Verisk 打算使用 Amazon Titan Embeddings V2 模型。

用户可以选择他们想要比较的两份文档。此操作会调用一个 [AWS Lambda](https://aws.amazon.com/lambda) 函数，从 OpenSearch Service 数据库检索文档嵌入，并将它们提交给通过 Amazon Bedrock 访问的 Anthropic 的 Claude 3 Sonnet FM。结果存储在 JSON 结构中，并通过 API 服务提供给 UI，供最终用户使用。

## 安全与治理

生成式 AI 是非常新的技术，随之带来与安全和合规相关的新挑战。Verisk 设有一个治理委员会，负责审查生成式 AI 解决方案，确保它们符合 Verisk 在安全、合规和数据使用方面的标准。Verisk 还针对 IP 保护和合同合规进行法律审查。对 Verisk 而言，重要的是确保 FM 所共享的数据安全传输，并且 FM 不会保留他们的任何数据或将其用于自身训练。解决方案的质量、速度、成本和易用性，是促使 Verisk 在其生成式 AI 解决方案中选择 Amazon Bedrock 和 Anthropic 的 Claude Sonnet 的关键因素。

## 评估标准

为了评估生成式 AI 所产出的结果质量，Verisk 基于以下标准进行评估：

- 准确性
- 一致性
- 对上下文的遵循
- 速度与成本

为了评估生成式 AI 结果的准确性和一致性，Verisk 在内部保险领域专家的帮助下设计了人工评估指标。Verisk 对生成的结果进行了多轮人工评估。在这些测试中，内部领域专家会以 1–10 的手工评分量表对准确性、一致性和对上下文的遵循程度打分。Verisk 团队通过跟踪延迟来测量生成结果所需的时间。每一轮测试的反馈都会被纳入后续测试。

Verisk 从模型获得的初始结果不错，但离期望的准确性和一致性水平还有距离。开发过程经历了迭代改进，包括重新设计、对 FM 进行多次调用以及测试各种 FM。评估 FM 与非 FM 解决方案是否成功的主要指标是人工评分系统，由业务专家对结果打分并进行比较。FM 解决方案正在快速进步，但为了达到期望的准确性水平，Verisk 的生成式 AI 软件解决方案需要包含 FM 之外的更多组件。为了实现期望的准确性、一致性和效率，Verisk 采用了超出单纯使用 FM 的各种技术，包括 prompt 工程、检索增强生成和系统设计优化。

## Prompt 优化

变更摘要不同于在文本中展示两份文档之间的差异。Mozart 应用需要能够描述实质性变更，并忽略无意义变更带来的噪声。Verisk 利用其内部领域专家的知识创建 prompt，以实现这些目标。每一轮测试中，Verisk 都向 prompt 中加入详细指令，以捕获关键信息并减少可能的噪声和幻觉。新增指令聚焦于减少审阅最终结果的业务专家所发现的问题。为了获得最佳结果，Verisk 需要根据所用的 FM 调整 prompt——每个 FM 对 prompt 的响应方式存在差异，使用针对特定 FM 的 prompt 能带来更好的结果。通过这一过程，Verisk 向模型说明了它所扮演的角色，以及常见术语和除外责任的定义。除了为 FM 优化 prompt，Verisk 还探索了有效切分和处理文档文本本身的技术。

## 切分文档页面

Verisk 测试了多种文档切分策略。对于此用例，块大小为 500 个字符、重叠 15% 的递归字符文本切分器提供了最佳结果。该切分器属于 [LangChain](https://python.langchain.com/docs/get_started/introduction/) 框架；它是一个语义切分器，会考虑文本中的语义相似性。Verisk 还考虑过 [NLTK 切分器](https://www.nltk.org/api/nltk.tokenize.html)。有了将文档文本切分为可处理块的有效方法后，Verisk 随后专注于提升摘要输出的质量和相关性。

## 摘要质量

质量评估从确认选择了正确的文档进行比较开始。Verisk 通过使用文档元数据缩小搜索结果范围来提升解决方案质量——指定哪些文档纳入或排除在查询之外，从而使 FM 生成更相关的响应。对于生成式 AI 的变更描述，Verisk 希望捕捉变更的本质，而不只是标出差异。结果由其内部的保单编写专家审阅，他们的反馈被用于确定 prompt、文档切分策略和 FM。在具备了提升输出质量和相关性的技术之后，Verisk 也优先优化其生成式 AI 解决方案的性能和成本效率。这些技术具体针对 prompt 工程；一些例子包括 [few-shot prompting](https://www.promptingguide.ai/techniques/fewshot)、[chain of thought prompting](https://www.promptingguide.ai/techniques/cot) 以及 [needle in a haystack 方法](https://arxiv.org/abs/2404.08865)。

## 性价比

为了实现更低的成本，Verisk 定期评估各种 FM 选项，并在有成本更低、性能更好的新选项发布时进行更换。在开发过程中，Verisk 重新设计了解决方案以减少对 FM 的调用次数，并在可能的情况下使用非 FM 的方案。

如前所述，整体解决方案由几个不同的组件组成：

- 变更位置
- 变更摘录
- 变更摘要
- 以修订痕迹格式显示的变更

Verisk 通过识别包含差异的章节，再把这些章节传给 FM 生成变更摘要，从而减轻了 FM 的负载并提升了准确性。为了构建包含红线标注的修订差异格式，Verisk 使用了非 FM 的方案。除了优化性能和成本，Verisk 还专注于为其生成式 AI 解决方案开发模块化、可复用的架构。

## 可复用性

良好的软件开发实践同样适用于生成式 AI 解决方案的开发。你可以创建由可复用组件构成的解耦架构。Mozart 生成式 AI companion 以 API 的形式提供，这使其与前端开发解耦，并允许复用这项能力。同样，该 API 由许多可复用组件组成，例如通用 prompt、通用定义、检索服务、嵌入创建和持久化服务。通过模块化、可复用的设计方法和迭代优化过程，Verisk 的生成式 AI 解决方案取得了非常令人满意的结果。

## 结果

基于 Verisk 的评估模板问题和多轮测试，他们得出结论：结果中超过 90% 的摘要为良好或可接受。测试方式是把解决方案的结果提供给业务专家，由这些专家使用评分量表对结果打分。

## 业务影响

Verisk 的客户会定期花费大量时间审阅保单表单的变更。由生成式 AI 驱动的 Mozart companion 可以摄取这些复杂且非结构化的保单文档，并在数分钟内提供变更摘要，从而简化审阅过程。这使 Verisk 的客户能够将变更采纳时间从数天缩短到数分钟。采纳速度的提升不仅提高了生产力，也使得变更能够及时实施。

## 结论

Verisk 由生成式 AI 驱动的 Mozart companion 使用先进的自然语言处理和 prompt 工程技术，为保险保单文档之间的变更提供快速而准确的摘要。通过发挥 Anthropic 的 Claude 3 Sonnet 等大语言模型的能力并融入领域专业知识，Verisk 开发出了一个能显著加速其客户保单审查流程的解决方案，将变更采纳时间从数天或数周缩短到仅仅数分钟。生成式 AI 的这种创新应用为保险行业带来了切实的生产力提升和运营效率。凭借促进负责任 AI 使用的强健治理框架，Verisk 正处于释放生成式 AI 潜力的前沿，以转变工作流并推动全球风险格局的韧性。
