# 使用 Amazon Bedrock Agents 进行代码扫描、优化与修复

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项全托管服务，通过 API 提供来自领先 AI 初创公司和 Amazon 的基座模型（FM），让你可以从广泛的 FM 中挑选最适合自己用例的模型。借助 Amazon Bedrock 的 serverless 体验，你可以快速上手，用自己的数据私有化定制 FM，并使用 [Amazon Web Services](https://aws.amazon.com/)（AWS）工具把它们集成和部署到你的应用中，而无需管理任何基础设施。

对于处在云计算和软件开发领域的企业而言，提供安全的代码仓库至关重要。随着复杂的网络安全威胁日益普遍，组织必须采取主动措施来保护其资产。Amazon Bedrock 提供了一个强大的解决方案：自动扫描仓库中的漏洞并对其进行修复。本文探讨如何使用 Amazon Bedrock 提升仓库的安全性，并保持对组织标准和监管标准的合规。

本解决方案演示如何配置 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/)，使其扫描指定的代码仓库、修复漏洞，并把更改推送到一个新分支。这种方法可以加速开发、减少错误并遵循安全准则。

## 解决方案概述

部署该解决方案分为三个高层步骤：

- 配置 Amazon Bedrock Agent
- 为 [action group](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-action-create.html) 配置 [AWS Lambda](https://aws.amazon.com/lambda) 函数
- 把 action group 添加到 Amazon Bedrock agent

如下图所示，该架构包含两个关键步骤：

- 用户通过 Amazon Bedrock agent 聊天控制台提供必要信息。他们提供代码仓库 URL，例如 `https://github.com/abc/test`，并指定要扫描的分支名称，例如 *main*。然后他们列出要从扫描中排除的文件夹，例如 *test*，并指定要排除的文件扩展名，例如 *.md* 和 *.txt*。最后他们提供一个新分支名称，用于上传修复后的代码。
- Amazon Bedrock agent 把这些细节转发给 action group，由它调用 Lambda 函数。该函数获取代码，使用预先选定的 large language model（LLM）扫描其中的漏洞，应用修复，并把修复后的代码推送到新分支供用户验证。被排除的文件夹和文件扩展名不会被扫描。完成后，action group（Lambda 函数）把信息回传给 Amazon Bedrock agent，后者随即向用户显示状态。

## 先决条件

要实施该解决方案，你需要具备以下条件：

- 了解 Amazon Bedrock Agents、[prompt engineering](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-prompt-engineering.html)、[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)、Lambda 函数和 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）。
- 一个 [AWS 账户](https://docs.aws.amazon.com/accounts/latest/reference/manage-acct-creating.html)，具备在 Amazon Bedrock 中创建 agent 和知识库、创建 Lambda 函数以及 IAM 角色所需的 [IAM 权限](https://docs.aws.amazon.com/accounts/latest/reference/security-iam.html)。
- 为 Amazon Bedrock Agents 创建的[服务角色](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-permissions.html)。
- 已为所需的 Amazon Bedrock 启用[模型访问](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)。
- 一个拥有仓库的 GitHub 账户，以及一个用于存储扫描后代码的[个人访问令牌](https://docs.github.com/en/organizations/managing-programmatic-access-to-your-organization/setting-a-personal-access-token-policy-for-your-organization#restricting-access-by-personal-access-tokens-classic)。

## 配置 Amazon Bedrock agent

要配置 Amazon Bedrock agent，请完成以下步骤：

- 在 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock/home)的导航窗格中选择 **Agents**，然后选择 **Create Agent**。
- （可选）提供 agent 的详细信息，包括 agent 名称和描述。
- 通过 IAM 服务角色为 agent 授予访问 AWS 服务的权限。这让你的 agent 可以访问所需服务，例如 [Lambda](https://aws.amazon.com/lambda/)。
- 在 Amazon Bedrock 中选择一个 FM（例如 Anthropic 的 Claude 3 Sonnet）。
- 要通过 Amazon Bedrock Agents 扫描代码仓库并修复漏洞，请为 agent 附加以下指令：

> 你是一个进行代码扫描与修复的 AI 助手。向用户致意，并询问需要扫描的 repository_url 和 branch_name。询问需要从扫描中排除的文件夹列表，并询问需要从扫描中排除的特定文件扩展名列表。询问用于推送修复后代码的新分支名称。把这些输入传给 code-scan-remediation action group 以触发它。

## 配置 action group 的 Lambda

完成初始的 agent 配置并把上述指令添加到 agent 之后，你需要创建一个将用于 action group 的 Lambda 函数。

创建一个 [Lambda 函数](https://docs.aws.amazon.com/lambda/latest/dg/getting-started.html)，用于扫描代码仓库中的漏洞、修复这些漏洞，并把更改推送到用户指定的新分支。该函数将由 action group 使用，而 action group 会在用户输入代码仓库 URL、分支名称以及要从扫描中排除的文件夹和文件扩展名列表后，由 Amazon Bedrock agent 调用。请参阅 [Lambda 代码](https://github.com/aws-samples/code-scanning-remediation-using-amazon-bedrock/blob/main/Code-Scanning-Remediation/lamda_function.py)。确认该 Lambda 函数具备所需的 IAM 权限，并在该 Lambda 函数上设置[基于资源的策略](https://docs.aws.amazon.com/lambda/latest/dg/access-control-resource-based.html)，以允许 Amazon Bedrock Agent 使用 `lambda:InvokeFunction` 动作调用该 Lambda。策略参见[此处](https://github.com/aws-samples/code-scanning-remediation-using-amazon-bedrock/blob/main/Code-Scanning-Remediation/resource-based-policy.json)。

## 把 action group 添加到 Amazon Bedrock agent

完成以下步骤，把 action group 添加到 Amazon Bedrock agent：

- [添加一个 action group](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-action-add.html) 到 Amazon Bedrock agent。
- 为 action group 分配一个描述性名称，并在描述字段中详细说明其功能。这有助于明确该 action group 在 workflow 中的用途。
- 对于 **Action group type**，选择 [Define with function details](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-action-function.html)。
- 对于 **Action group invocation**，选择你此前创建的 Lambda 函数。

该函数运行 action 被调用时所需的业务逻辑。务必选择正确版本的 Lambda 函数，并确保 GitHub token 已设置为环境变量。关于如何为 action group 配置 Lambda 函数的更多内容，请参阅[配置 Lambda 函数以发送 Amazon Bedrock agent 从用户处获取的信息](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-lambda.html)。

- 对于 **Action group function 1**，选择 **JSON Editor** 并添加所需参数。参见 [JSON 文件](https://github.com/aws-samples/code-scanning-remediation-using-amazon-bedrock/blob/main/Code-Scanning-Remediation/function-details.json)。

## 最佳实践

请遵循以下最佳实践：

- 添加自动化测试，在把代码提交到仓库之前进行验证，并在把修复后的代码合并到默认分支之前进行评审
- 在修复过程中创建新分支时使用描述性的分支名称，以保持清晰的版本控制
- 按照最小权限原则配置 IAM 角色和权限，以保障 Amazon Bedrock agent 和 Lambda 函数的安全
- 更新 prompt，以针对并修复特定用例的漏洞

## 清理

本演示中使用的服务会产生费用。请完成以下步骤清理你的资源：

- 如果不再需要，删除该 Lambda 函数
- 删除你创建的 [action group](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-action-delete.html) 和 [agent](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-delete.html)
- 从 GitHub 仓库中删除生成的分支

## 结论

Amazon Bedrock Agents 使用[生成式 AI](https://aws.amazon.com/ai/generative-ai/) 通过扫描漏洞并自动应用修复来改造代码仓库。这项能力对工程师至关重要，因为它从起点就加快了代码安全加固与遵循既定最佳实践的速度。

Amazon Bedrock Agents 的交互式功能自动化了漏洞扫描与修复过程，不仅简化了初始设置，还显著增强了持续的代码维护。尽管本文聚焦代码扫描与修复，Amazon Bedrock Agents 的交互能力可应用于各类 AWS 服务，为管理和优化云基础设施提供动态而全面的解决方案。
