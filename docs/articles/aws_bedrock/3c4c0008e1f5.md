# 使用 Amazon Bedrock AgentCore 构建交互式 MCP Apps

随着客户转向通过 ChatGPT、Claude 这类 AI host 与数字服务交互，组织需要一种方式让自己的服务能在这些应用中以丰富的 UI（而不只是纯文本）被访问。他们还需要在做到这一点的同时不锁定到单一 host。[MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview) 与 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 正好提供了这样的能力。MCP Apps 用直接在 AI host 内渲染的交互式 HTML widget 扩展了 [Model Context Protocol（MCP）](https://modelcontextprotocol.io/)。Amazon Bedrock AgentCore 是一个用于大规模构建、连接和优化 agent 的平台，支持任意框架或模型。具体到 MCP Apps，[AgentCore runtime（Amazon Bedrock AgentCore 的一项能力）](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 提供了一个安全、无服务器、会话隔离且原生支持 MCP 的 host。[AgentCore Gateway（Amazon Bedrock AgentCore 的一项能力）](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 通过一个 MCP Apps 兼容 host 可以访问的单一安全端点把它暴露出来。AgentCore 承担了这些无差异的重体力工作，因此你可以专注于业务逻辑与 widget 设计。

本文演示如何在 Amazon Bedrock AgentCore 上构建并部署一个带交互式 HTML widget 的 MCP App。由于 MCP Apps 是与 host 无关的标准，该应用能在所有支持 Apps 扩展的 AI host 中提供同样丰富的体验。借助[示例应用](https://github.com/aws-samples/sample-agentcore-mcp-apps) Unicorn Rentals，客户可以浏览可租用的独角兽、预订租赁、查看进行中的预订，以及归还独角兽。无论客户是在 ChatGPT、Claude 还是其他受支持的 host 中打开 Unicorn Rentals，观感与体验都一致。

## 工作原理

在深入架构之前，先看看应用的实际运行效果。Unicorn Rentals 被部署为一个 MCP App 并连接到 AI host。下面的示例使用 ChatGPT，但同一个 server 在 Claude 或其他支持 MCP Apps 扩展的 host 中同样可用。我们将依次走完四个步骤，从浏览车队到归还独角兽。现在开始。

### 第 1 步：列出可租用的独角兽

我们先从一个自然语言问题开始：“Can you show all unicorns?”。host 会解析该问题，并为每只独角兽渲染一张交互式卡片，展示其图片、名称、描述、小时费率与可用状态，而不是纯文本列表。

图 1：AI host 将可租用的独角兽渲染为交互式卡片。

### 第 2 步：预订一只独角兽

如果你最喜欢的独角兽是 Stardust，只要说 “I would like to book Stardust unicorn” 就能租下它。应用会记录该预订并立即确认，展示预订 ID、日期、小时费率以及你预订的那只独角兽。

### 第 3 步：查看你的预订

要查看你当前租了什么，你可以说 “Show me my unicorn bookings”。应用会返回你进行中的租赁，以及已租时长和迄今产生的费用。这一次的响应以文本而非卡片形式返回，因为并非每个请求都需要丰富的界面。

最后，“I would like to return my unicorn” 会结束这次租赁。应用根据时长与小时费率计算总费用，并在对话中反馈出来。

你刚才看到的一切，都由一个运行在 Amazon Bedrock AgentCore runtime 上、前置 AgentCore Gateway 的单一 MCP server 提供。本文余下部分将展示它是如何构建的，以及你如何自行部署。

## 解决方案概览

本方案在 Amazon Bedrock AgentCore 上部署一个 MCP App，通过 Model Context Protocol 暴露业务逻辑和交互式 HTML widget。用户与 AI host 交互，host 使用 MCP Apps 模式渲染交互式 HTML widget。一个专用的 [AWS Lambda](https://aws.amazon.com/lambda/) 函数实现业务逻辑，并使用 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 实现持久化。

下图展示了这些组件如何协同工作，向 AI host 提供交互式 widget。

![架构图：AI host 经 AWS WAF 到达 AgentCore Gateway，后者调用承载 MCP App 的 AgentCore runtime，后端是 AWS Lambda 函数与 Amazon DynamoDB](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/09/09/ML-20314-5.png)

图 5：Amazon Bedrock AgentCore 上 MCP App 的架构

下面是在 AI host 中注册一个 MCP App 时发生的过程：

- 你提供 App 的详细信息，包括 MCP Server URL。
- AI host 向 AgentCore Gateway 暴露的 MCP Server URL 发出 [tools/list](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#listing-tools) 和 [resources/list](https://modelcontextprotocol.io/specification/2025-11-25/server/resources#listing-resources) 两个 MCP 调用。MCP server 提供 `list_unicorns`、`book_unicorn`、`view_bookings` 和 `return_unicorn` 等工具，以及 `unicorn-list` 和 `booking-confirmation` 等资源，后者为每个响应提供 widget 的 HTML。
- AWS WAF 通过其 IP 允许列表和托管规则校验该请求，随后 AgentCore Gateway 将其路由到 AgentCore runtime。
- AgentCore Gateway 使用其 AWS Identity and Access Management（IAM）执行角色调用 AgentCore runtime。托管在其上的 MCP App 定义了 [MCP 工具](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) 和 [MCP 资源](https://modelcontextprotocol.io/specification/2025-11-25/server/resources)。
- MCP App 接收请求，并在响应中返回其中的工具或资源列表。
- AI host 可能会缓存这些信息以备后续使用。

下面是用户从 AI host 访问独角兽租赁服务时发生的过程。

### 阶段 1 — 工具调用

- 用户在 ChatGPT 或 Claude 这类 AI host 中发出自然语言请求（例如 “Show me all unicorns”）。
- AI host 把该请求转换为 MCP [tools/call](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#calling-tools) 消息（例如 `list_unicorns`），并发送到 AgentCore Gateway 端点。
- AWS WAF 在请求到达 AgentCore Gateway 端点之前对其进行筛查。
- AgentCore Gateway 调用托管 MCP App 的 AgentCore runtime。
- MCP App 接收请求，并把业务操作委托给 Unicorn Rental Service 的 AWS Lambda。
- 该 AWS Lambda 针对 DynamoDB 执行业务逻辑并返回结果。
- MCP App 按 MCP 格式封装响应并返回给 AI host。

### 阶段 2 — Widget 渲染

- 如果工具关联了资源 URI（例如 `ui://widget/unicorn-list`），AI host 就会启动此阶段。没有关联 widget 的工具（例如 `view_bookings` 和 `return_unicorn`）只返回纯文本内容，完全跳过此阶段。
- host 针对该 URI 发送 MCP [resources/read](https://modelcontextprotocol.io/specification/2025-06-18/server/resources#reading-resources) 请求。
- 该请求经 AgentCore Gateway 到达 MCP App。
- MCP App 解析资源 URI，并返回 widget 自包含的 HTML。AI host 可能会缓存这些数据以获得更好的性能。
- host 在沙箱化的 `iframe` 中渲染该 HTML，并通过 MCP Apps 生命周期注入来自工具响应的结构化数据。
- widget 从 [Amazon CloudFront](https://aws.amazon.com/cloudfront/) 获取所需图片，后者以 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/) 作为源站。

## 使用 AgentCore runtime 构建 MCP server

本节介绍 MCP server 的结构，以及 AgentCore runtime 如何托管它。

### MCP App

本方案中的 MCP App 是一个 TypeScript 应用，构建在官方 [@modelcontextprotocol/sdk](https://github.com/modelcontextprotocol/typescript-sdk) 之上，并使用 [@modelcontextprotocol/ext-apps](https://github.com/modelcontextprotocol/ext-apps) 扩展，该扩展提供了从 MCP server 交付交互式 widget 的标准方式。它以一个 [Express.js](https://expressjs.com/) HTTP server 的形式运行，由 AgentCore runtime 在内部管理。该 MCP App 提供以下能力：

#### **MCP 工具**

该应用注册了 AI host 可以调用的 [MCP 工具](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)，例如 `list_unicorns`、`book_unicorn`、`view_bookings` 和 `return_unicorn`。工具通过 [registerAppTool](https://apps.extensions.modelcontextprotocol.io/api/functions/server-helpers.registerAppTool.html) 注册，需要提供工具名称、工具配置以及包含该工具业务逻辑的处理函数。该应用注册了 `list_unicorns` 工具。它负责处理 AI host 发来的、用于发现工具的 [tools/list](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#listing-tools) MCP 请求，以及用于调用工具的 [tools/call](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#calling-tools) MCP 请求。

工具配置中的 `_meta.ui.resourceUri` 字段告诉 AI host 用哪个 widget 来展示该工具的响应。tool/call 响应中的 `structuredContent` 包含数据载荷。AI host 在渲染 widget 时会把这些数据注入其中。

#### **MCP App 资源**

该应用把 widget 注册为 AI host 可用的 [MCP 资源](https://modelcontextprotocol.io/specification/2025-11-25/server/resources)。资源通过 [registerAppResource](https://apps.extensions.modelcontextprotocol.io/api/functions/server-helpers.registerAppResource.html) 注册，需要提供资源名称、URI 以及返回该 widget HTML 数据的处理函数。该应用注册了 `unicorn-list-widget` 资源。它负责处理 AI host 发来的、用于发现资源的 [resource/list](https://modelcontextprotocol.io/specification/2025-11-25/server/resources#listing-resources) MCP 请求，以及用于获取 widget HTML 的 [resource/read](https://modelcontextprotocol.io/specification/2025-11-25/server/resources#reading-resources) MCP 请求。

### AgentCore runtime 上的 MCP App

本方案把 MCP App 部署在 AgentCore runtime 上。构建过程会把 MCP App 代码打包成 zip 文件。部署步骤将其上传到某个 Amazon S3 存储桶，并创建一个引用它的 AgentCore runtime 资源。运行时配置指定 `NODE_22` 环境、入口点以及 MCP 协议模式。

AgentCore runtime 提供一个安全、无服务器且专门为此目的构建的托管环境，用于部署和运行 MCP App。它会根据传入的请求量自动扩缩容。MCP 协议配置告诉 AgentCore 这是一个 MCP server，从而启用针对该协议的优化。基于资源的策略限制哪些主体可以调用该 runtime。在本方案中，该策略只允许 AgentCore Gateway 执行角色，并拒绝其他主体。

## 通过 AgentCore Gateway 暴露 MCP server

AgentCore runtime 支持以 IAM（SigV4）和 OAuth 进行调用认证。本方案在 runtime 之前放置一个 Amazon Bedrock AgentCore Gateway，使外部 AI host 可以通过单一托管端点访问该 MCP server。Gateway 以 No Auth 方式接受入站请求，并使用自己的 IAM 执行角色通过 SigV4 调用 runtime，因此调用方无需自行处理 AWS 凭证。AWS WAF 通过 IP 允许列表、托管威胁检测规则和速率限制保护 AgentCore Gateway 端点。

## 业务逻辑层

一个 AWS Lambda 函数实现独角兽租赁的业务逻辑。它针对 Amazon DynamoDB 处理库存查询与预订操作。它对 MCP 一无所知。在真实世界的实现中，这也可以是你运行在 [Amazon Elastic Container Service（Amazon ECS）](https://aws.amazon.com/ecs/)、[Amazon Elastic Kubernetes Service（Amazon EKS）](https://aws.amazon.com/eks/) 或其他计算服务上的既有服务。关键在于，MCP server 充当一层薄薄的协议适配器。你的核心业务逻辑仍留在它原本所在的地方，你通过 HTTP 调用或 SDK 客户端等标准调用方式把它接入 MCP 层。

## 部署演练

本节将带你完成该方案的部署。

### 前置条件

开始之前，请确认你已具备：

- 一个具备部署 AgentCore runtime 所需权限的 AWS 账户。有关所需的 IAM 权限，请参阅 [AgentCore runtime 的 IAM 权限](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-permissions.html)。
- [Node.js](https://nodejs.org/en/download/) 22+。
- 已安装并配置好的 [AWS Command Line Interface（AWS CLI）](https://aws.amazon.com/cli/) V2.0 或更高版本（`aws configure`）。
- 已全局安装 AWS Cloud Development Kit（AWS CDK）CLI。操作说明请参阅 [AWS CDK 入门](https://docs.aws.amazon.com/cdk/v2/guide/getting-started.html)。

### 部署解决方案

部署使用单个 `deploy.sh` 脚本，由它编排构建与 CDK 堆栈部署。

第 1 步：下载解决方案代码：

```
git clone https://github.com/aws-samples/sample-agentcore-mcp-apps.git
cd sample-agentcore-mcp-apps
```

第 2 步：在你的 AWS 账户中部署所需资源。运行部署脚本以部署 CDK 堆栈：

```
bash deploy.sh
```

请记下部署后打印的输出。连接 AI host 时你会用到 `GatewayResourceUrl`。

## 从 AI host 连接

由于该 MCP server 实现了 MCP Apps 开放标准，其他支持 MCP Apps 扩展的 AI host 也能连接并渲染完整的交互式 widget 体验。

仓库中包含了针对特定 AI host 的详细连接配置指南：

### ChatGPT

- 打开 [https://chatgpt.com/](https://chatgpt.com/)，选择 **User Profile**、**Plugins**、**Developer Mode**，然后开启 **Developer mode**。
- 进入 **Plugins**，选择 **New Plugin**。
- 在 **Name** 中填入 `UnicornRentals`。
- 在 **Description** 中填入：“Browse unicorns, book rentals, view active bookings, and return unicorns. Shows rich UI cards with pricing and booking confirmations”。
- 在 **Connection** 中填入 CDK 输出里的 `GatewayResourceUrl` 值。
- 在 **Authentication** 中选择 **No Auth**。
- 选择 **Create**。

### Claude.ai

- 打开 [https://claude.ai](https://claude.ai)，选择 **Customize**，然后进入 **Connectors**。
- 选择 **Add Connector**。
- 在 **Name** 中填入 `UnicornRentals`。
- 在 **Remote MCP server URL** 中填入 CDK 输出里的 `GatewayResourceUrl` 值。
- 选择 **Save**。

## 生产部署注意事项

将本方案投入生产时，请考虑以下方面。

在监控与可观测性方面，使用 Amazon CloudWatch 监控 AgentCore Gateway 的请求指标、Unicorn Service Lambda 的调用以及 AgentCore runtime 容器的健康状态。针对错误率和延迟阈值设置告警，并开启日志记录，以跟踪 MCP 方法调用和响应时间。

在成本优化方面，请注意 AgentCore runtime 采用基于容器运行时长和调用次数的按用量计费。为控制成本，请合理配置容器内存与 CPU 分配，并根据预期流量模式检查 Lambda 并发设置。

在负责任 AI 方面，请在你的信任边界上增加安全控制。在 MCP server 中用严格的 schema 校验工具参数，并在 Unicorn Service Lambda 中再次校验，使业务逻辑不信任未经校验的输入。对于跨越边界的非结构化文本，使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 过滤有害内容、拦截被禁止的话题，并在响应到达客户端之前对个人可识别信息（PII）等敏感数据做脱敏处理。

## 结论

本文展示了如何在 Amazon Bedrock AgentCore runtime 上构建并部署一个带交互式 widget UI 的 MCP server。该架构模式是在 AgentCore runtime 上的一层薄 MCP 协议层，它把业务逻辑委托给专用的 Lambda 函数，并以 MCP App 资源的形式提供自包含的 widget HTML。它通过一个 AgentCore Gateway 端点暴露该堆栈，为你提供一个可扩展且运维开销极低的 MCP Apps 部署。

这一方法的强大之处在于你无需构建的东西。AgentCore runtime 承担了扩缩容、会话隔离、健康监控和基础设施管理等无差异的重体力工作，因此你的团队可以专注于对客户真正重要的业务逻辑与 widget 体验。你只需编写一层薄协议适配器，把它指向既有服务，其余交给 AgentCore。

由于本方案构建于开放的 MCP Apps 标准之上，你的投入不会被锁定在单一 AI host 上。同一个 server、同一批工具、同一套交互式 widget，都能在其他支持 MCP Apps 扩展的 host 中工作。你构建一次，就能在客户选择与 AI 交互的任何地方触达他们。而且由于该架构把协议处理与业务逻辑清晰地分离，你可以独立演进：更换数据存储、新增工具、重新设计 widget，或接入更多后端服务，这些变更都不需要重新架构部署。MCP 层保持轻薄，你的服务保持可移植，而 AgentCore runtime 让一切持续运行。
