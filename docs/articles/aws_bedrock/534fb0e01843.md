# 使用 Datadog Cloud Security 检测 Amazon Bedrock 错误配置

*本文与 Datadog 的 Nick Frichette 和 Vijay George 合写。*

随着组织越来越多地采用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 来构建生成式 AI 应用，防范可能导致数据泄露或未授权模型访问的错误配置变得至关重要。[AWS Generative AI Adoption Index](https://amazongca.getbynder.com/share/F5DE1F38-F55B-4953-9B66D6D023045E27/?viewType=grid) 调查了分布在九个国家的 3,739 位资深 IT 决策者，结果显示 45% 的组织把生成式 AI 工具列为 2025 年的首要预算优先事项。随着越来越多的 AWS 和 Datadog 客户加快 AI 采用步伐，把 AI 安全融入既有流程将变得不可或缺，尤其是在监管要求日趋严格之际。但孤立地看待 AI 风险是不够的；AI 风险必须与身份暴露、错误配置等其他风险放在同一语境中评估。Amazon Bedrock 与 Datadog 全面的安全监控相结合，帮助组织在保持稳健安全控制的同时更快创新。

Amazon Bedrock 通过内置保护措施提供了企业级安全性，涵盖数据隐私、访问控制、网络安全、合规以及负责任的 AI 防护。客户数据在传输过程中使用 TLS 1.2 或更高版本加密，静态存储时则通过 [AWS Key Management Service](https://aws.amazon.com/kms)（AWS KMS）加密，并且组织对加密密钥拥有完全控制权。数据隐私是核心：您的输入、prompt 和输出不会与模型提供商共享，也不会被用于训练或改进基础模型（FM）。微调与定制在模型的私有副本上进行，从而提供数据保密性。访问通过 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）和基于资源的策略严格管控，支持对用户和角色进行细粒度授权。Amazon Bedrock 与 [AWS PrivateLink](https://aws.amazon.com/privatelink/) 集成，并支持虚拟私有云（VPC）endpoint 以实现私有的内部通信，因此流量不会离开 Amazon 网络。该服务符合 ISO、SOC、CSA STAR、HIPAA 资格、GDPR 和 FedRAMP High 等关键行业标准，适合受监管行业使用。此外，Amazon Bedrock 还提供可配置的护栏，用于过滤敏感或有害内容、促进负责任的 AI 使用。安全责任按照 AWS 共享责任模型来划分：AWS 负责管理基础设施安全，客户则负责其 Amazon Bedrock 环境内的安全配置与访问控制。

在这些稳健的 AWS 安全特性之上，Datadog 与 AWS 携手提供对 AI 基础设施风险、漏洞、敏感数据暴露及其他错误配置的整体视图。[Datadog Cloud Security](https://www.datadoghq.com/product/cloud-security/) 同时采用无 agent 与基于 agent 的扫描，帮助组织识别、定级并修复各类云资源风险。这一集成帮助 AWS 用户依据业务关键性对风险排序，并结合可观测性数据充实安全发现，从而提升其 AI 实施的整体安全态势。

我们很高兴宣布 Datadog Cloud Security 推出了新的安全能力，帮助您在 Amazon Bedrock 错误配置演变成安全事件之前发现并修复它们。这一集成通过提供三项关键优势，帮助组织嵌入稳健的安全控制、安全地使用 Amazon Bedrock 的强大能力：把 AI 安全纳入更广泛的云安全战略从而实现整体的 AI 安全；通过及时发现潜在的 AI 相关安全问题实现实时风险检测；以及凭借预置检测规则简化合规工作，帮助满足不断演进的 AI 法规要求。

## AWS 与 Datadog：助力客户安全地采用 AI

AWS 与 Datadog 的合作聚焦于帮助客户安全、高效地运营其云基础设施。随着组织快速采用 AI 技术，把这一合作扩展到 Amazon Bedrock 是自然的演进。Amazon Bedrock 是一项全托管服务，通过统一的 API 提供来自领先 AI 公司和 Amazon 的高性能 FM，因而成为 Datadog 开展 AI 安全能力的理想起点。

优先集成 Amazon Bedrock 的决定由若干因素驱动，包括强劲的客户需求、全面的安全需要以及既有的集成基础。凭借 900 多项集成与由合作伙伴构建的 Marketplace，Datadog 与 AWS 长期的合作关系及深厚的集成能力，使其能够利用自身在云安全方面的专业经验，快速为 Amazon Bedrock 开发全面的安全监控。

在整个 2024 年第四季度，[Datadog Security Research](https://securitylabs.datadoghq.com/articles/2024-q4-threat-roundup/#threat-actors-target-cloud-ai-environments) 观察到威胁行为者针对云上 AI 环境的兴趣持续上升，这让此次集成尤为及时。把 AWS 强大的 AI 能力与 Datadog 的安全专长结合起来，您就能在保持稳健安全控制的同时安全地加快 AI 采用。

## Datadog Cloud Security 如何帮助保护 Amazon Bedrock 资源

在把 [AWS 集成](https://docs.datadoghq.com/integrations/amazon_web_services/#aws-resource-collection-iam-policy) 添加到您的 Datadog 账户并启用 Datadog Cloud Security 之后，Datadog Cloud Security 会持续监控您的 AWS 环境，识别错误配置、身份风险、漏洞和合规违规。这些检测借助 [Datadog Severity Scoring 体系](https://docs.datadoghq.com/security/cloud_security_management/severity_scoring/#cloud-security-severity-scoring-framework) 依据基础设施上下文为其排定优先级。评分会考虑多种变量，包括该资源是否位于生产环境、是否可公开访问，或是否能够访问敏感数据。这种多层分析结合运行时行为，可以帮助您减少噪声，把注意力集中在最关键的错误配置上。

与 AWS 合作，Datadog 很高兴为 Datadog Cloud Security 客户提供如下检测：

- Amazon Bedrock 自定义模型不应把模型数据输出到可公开访问的 S3 存储桶
- Amazon Bedrock 自定义模型不应从可公开写入的 S3 存储桶读取训练数据
- Amazon Bedrock 护栏应启用 prompt 攻击过滤器，并以高灵敏度阻止 prompt 攻击
- Amazon Bedrock agent 护栏应启用敏感信息过滤器，并阻止高度敏感的 PII 实体

## 使用 Datadog Cloud Security 检测 AI 错误配置

为理解这些检测如何帮助保护您的 Amazon Bedrock 基础设施，我们来看一个具体的用例：Amazon Bedrock 自定义模型不应从可公开写入的 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）存储桶读取训练数据。

借助 Amazon Bedrock，您可以通过[在领域特定数据上微调](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-prepare.html)来定制 AI 模型。为此，这些数据需要存放在 S3 存储桶中。威胁行为者一直在评估 S3 存储桶的配置，寻找访问敏感数据甚至向 S3 存储桶写入的机会。

如果威胁行为者发现某个 S3 存储桶的错误配置允许公开写入，而该存储桶中又存放着用于训练 AI 模型的数据，那么恶意行为者就可能污染该数据集，向模型引入恶意行为或输出。这被称为[数据投毒攻击](https://owasp.org/www-project-machine-learning-security-top-10/docs/ML02_2023-Data_Poisoning_Attack.html)。

通常，检测这类错误配置需要多个步骤：一步识别存在写入权限错误配置的 S3 存储桶，另一步确认该存储桶正被 Amazon Bedrock 使用。使用 Datadog Cloud Security，这项检测只是[开箱即用](https://docs.datadoghq.com/security/default_rules/)的数百项检测之一。

在 Datadog Cloud Security 系统中，您可以使用 Cloud Map 把该问题与周边基础设施一起查看。它提供您云架构的实时图景，如下图所示。AI 风险随后会与敏感数据暴露、身份风险、漏洞及其他错误配置放在一起评估，让您获得 360 度视角的风险全貌。

![Datadog Cloudcraft 的 Cloud Security 视图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/20/ML-18870-datadog-cloudcraft-1.png)

例如，您可能会看到自己的应用在 Amazon Bedrock 上使用 Anthropic 的 Claude 3.7，并访问存放在某个同样具有公开写入权限的 S3 存储桶中的训练数据或 prompt 数据。这可能向大语言模型（LLM）引入未经批准的数据，从而在无意中影响模型完整性，因此您需要更新这项配置。尽管很基础，但大多数安全工作的第一步就是识别问题。借助无 agent 扫描，Datadog 每隔 15 分钟到 2 小时扫描一次您的 AWS 环境，使用户在错误配置被引入环境时就能发现它们。下一步是修复该风险。Datadog Cloud Security 会针对每项风险自动生成修复指引（见下图）。您将获得逐步说明，了解如何修复每一项发现。在此情形下，我们可以通过修改 S3 存储桶策略来修复该问题，帮助阻止公开写入访问。您可以直接在 AWS 中操作、创建 JIRA 工单，或使用内置的工作流自动化工具。在此基础上，您还可以直接在 Datadog 内执行修复步骤，并确认错误配置已经解决。

解决该问题将对您的合规态势产生积极影响，这一点可从 Datadog Cloud Security 中的态势评分看出来，它帮助团队满足内部基线和监管标准。团队还可以创建自定义框架，或对已有框架进行迭代，以获得贴合自身需求的合规控制。

## Datadog Cloud Security 如何检测您云环境中的错误配置

您可以使用 Datadog 的 [agent](https://docs.datadoghq.com/agent/?tab=Linux)、以[无 agent 方式](https://docs.datadoghq.com/security/cloud_security_management/setup/agentless_scanning)，或两者并用来部署 Datadog Cloud Security，以最大化云环境中的安全覆盖。Datadog 客户可以先在 Datadog 中添加 [AWS 集成](https://docs.datadoghq.com/integrations/amazon_web_services/" \l "aws-resource-collection-iam-policy) 开始监控其 AWS 账户是否存在错误配置。这使 Datadog 能够爬取客户 AWS 账户中的云资源。

当 Datadog 系统发现资源后，会针对这些资源运行包含数百条[开箱即用检测](https://docs.datadoghq.com/security/default_rules/)规则的目录，查找错误配置以及攻击者可利用的威胁路径。
