# 借助 Verisk rating insights 和 Amazon Bedrock 简化对 ISO 费率变更内容的获取

*本文与 Verisk 的 Samit Verma、Eusha Rizvi、Manmeet Singh、Troy Smith 和 Corey Finley 共同撰写。*

Verisk Rating Insights 作为 [ISO Electronic Rating Content](https://www.verisk.com/products/erc/)（ERC）的一项功能，是一款强大的工具，旨在提供两次发布之间的 ISO 费率变更摘要。传统上，提取具体的申报（filing）信息或识别多个发布版本之间的差异，需要手动下载完整的包，既耗时又容易产生低效。这一挑战，再加上对准确、及时的客户支持的需求，促使 [Verisk](https://www.verisk.com/) 探索创新方式来提升用户的可访问性并自动化重复流程。借助[生成式 AI](https://aws.amazon.com/generative-ai/) 和 [Amazon Web Services](https://aws.amazon.com/)（AWS）服务，Verisk 在打造对话式用户界面方面取得了显著进展，用户可以轻松检索具体信息、识别内容差异，并提升整体运营效率。

在本文中，我们深入探讨由 [Amazon Bedrock](https://aws.amazon.com/bedrock/)、[large language models](https://aws.amazon.com/what-is/large-language-model/)（LLM）和 [Retrieval Augmented Generation](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）驱动的 Verisk Rating Insights 如何改变客户与 ISO ERC 变更交互并获取这些变更的方式。

## 挑战

Rating Insights 提供了有价值的内容，但在用户可访问性以及提取可执行洞察所需的时间方面存在显著挑战：

- **手动下载** – 客户为了获取哪怕一小部分相关信息，也不得不下载整个包。这种做法效率低下，尤其是在只需要审阅申报材料中一小部分内容时。
- **数据检索效率低** – 如果不下载并手动比对，用户无法快速找出两个内容包之间的差异，而这种比对可能耗费数小时甚至数天的分析时间。
- **客户支持耗时** – Verisk 的 ERC 客户支持团队每周要花 15% 的时间来处理受这些低效问题影响的客户咨询。此外，为新客户做入门引导需要半天的重复性培训，以确保他们了解如何访问和解读数据。
- **人工分析耗时** – 客户通常要为每个测试用例花 3–4 小时分析各份申报材料之间的差异。当需要处理多个测试用例时，这会导致关键决策出现显著延迟。

## 解决方案概览

为解决这些挑战，Verisk 踏上了用生成式 AI 技术增强 Rating Insights 的旅程。通过集成 Amazon Bedrock 中可用的 [Anthropic 的 Claude](https://aws.amazon.com/bedrock/claude/) 和 [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/)，Verisk 构建了一个成熟的对话式平台，用户可以毫不费力地访问并分析费率内容变更。

数据摄取过程的步骤如下：

- 当有新文件投放时即触发该过程。它负责使用自定义分块策略对文档进行分块。该策略会递归检查每个章节并保持其完整、互不重叠。随后该过程对分块做 embedding，并作为向量 embedding 存入 OpenSearch Service。
- Amazon Bedrock 中使用的 embedding 模型是 amazon titan-embed-g1-text-02。
- 使用 Amazon OpenSearch Serverless 作为具备元数据过滤能力的向量 embedding 存储。

下图展示了生成用户响应的推理循环（inference loop）中涉及的架构组件和高层步骤。

![AWS 聊天系统架构，包含用户反馈、Verisk gateway、负载均衡、缓存和双 AI 模型集成](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/12/ML-18632-inference.png)

推理循环的步骤如下：

- 该组件负责多项任务：用最近的聊天历史补充用户问题、对问题进行 embedding、从向量数据库检索相关分块，最后调用生成模型来综合出响应。
- 使用 Amazon ElastiCache 存储最近的聊天历史。
- Amazon Bedrock 中使用的 embedding 模型是 amazon titan-embed-g1-text-02。
- 实现 OpenSearch Serverless 以支持 RAG（Retrieval-Augmented Generation）。
- 为生成对用户查询的响应，系统使用通过 Amazon Bedrock 提供的 Anthropic 的 Claude Sonnet 3.5（模型 ID：anthropic.claude-3-5-sonnet-20240620-v1:0）。

## 使用的关键技术与框架

我们使用 Anthropic 的 Claude Sonnet 3.5（模型 ID：anthropic.claude-3-5-sonnet-20240620-v1:0）来理解用户输入并提供详细、贴合上下文的响应。Anthropic 的 Claude Sonnet 3.5 增强了平台解读用户查询、并从复杂的内容变更中给出准确洞察的能力。开源框架 LlamaIndex 作为链式框架，用于高效连接和管理不同数据源，实现内容和洞察的动态检索。

我们实现了 RAG，使模型能够从 OpenSearch Serverless 向量数据库中拉取具体、相关的数据。这意味着系统可以基于用户查询生成精确、最新的响应，无需在大量下载内容中逐一筛选。向量数据库实现了智能搜索和检索，对内容变更进行组织，使其能够被快速、轻松地访问。这消除了手动搜索或下载整个内容包的需要。Verisk 在 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 中应用了护栏，同时围绕生成模型设置了自定义护栏，使输出符合特定的合规与质量标准，保障响应的完整性。

Verisk 的生成式 AI 解决方案是一项全面、安全且灵活的服务，用于构建生成式 AI 应用和 agent。Amazon Bedrock 将你连接到领先的 FM、用于部署和运行 agent 的服务，以及用于微调、防护和优化模型的工具，并提供知识库将应用连接到最新数据，让你拥有从实验快速走向真实环境部署所需的一切。

鉴于生成式 AI 的新颖性，Verisk 成立了一个治理委员会来监督其解决方案，确保其符合安全、合规和数据使用标准。Verisk 在 RAG pipeline 内实施了严格的管控，确保数据仅对获授权的用户可访问。这有助于维护敏感信息的完整性与隐私。法律审查确保 IP 保护和合同合规。

## 工作原理

这些先进技术的集成带来了无缝、友好的用户体验。以下是 Verisk Rating Insights 如今为客户工作的方式：

- **对话式用户界面** – 用户可以通过对话式界面与平台交互。用户不再手动审阅内容包，而是输入自然语言查询（例如“两次近期申报之间的保障范围有哪些变化？”）。系统使用 Anthropic 的 Claude Sonnet 3.5 理解意图，并即时给出相关变更的摘要。
- **动态内容检索** – 得益于 RAG 和 OpenSearch Service，平台无需下载整个文件。它改为动态检索并呈现用户所要查找的具体变更，从而实现更快的分析和决策。
- **自动化差异分析** – 系统可以自动比较两个内容包，突出显示差异而无需人工介入。用户可以查询精确的对比（例如“显示 Release 1 和 Release 2 之间费率标准（rating criteria）的差异”）。
- **定制化洞察** – 所设置的护栏确保响应准确、合规且可执行。此外，如有需要，系统还可以帮助用户理解变更的影响，并协助他们应对申报材料的复杂性，提供清晰、简洁的洞察。

## 质量基准

Verisk Rating Insights 团队分别实施了全面的评估框架和反馈闭环机制（如上图所示），以支持持续改进并解决可能出现的问题。

确保响应具有高准确性和一致性，对 Verisk 的生成式 AI 解决方案至关重要。然而，LLM 有时会产生幻觉或提供无关细节，影响可靠性。为此，Verisk 实施了：

- **评估框架** – 集成到查询 pipeline 中，在交付前校验响应的精确性和相关性。
- **广泛测试** – 产品领域专家（SME）和质量专家对解决方案进行了严格测试，以确保准确性和可靠性。Verisk 与内部保险领域专家合作，制定了用于衡量准确性和一致性的 SME 评估指标。共进行了多轮 SME 评估，专家以 1–10 分制对这些指标打分。同时跟踪延迟以评估速度。每轮的反馈都会被纳入后续测试，以推动改进。
- **模型持续改进** – 利用客户反馈是推动生成模型持续演进和优化的关键环节，可同时提升准确性和相关性。通过将用户交互和反馈与聊天历史无缝集成，构建了一条稳健的数据 pipeline，把用户交互流式写入 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）桶，该桶充当数据中心。这些交互随后进入 Snowflake——一个基于云的数据平台和数据库即服务，提供数据仓库、数据湖、数据共享和数据交换等能力。通过这一集成，我们构建了全面的分析 dashboard，为了解用户体验模式和痛点提供了有价值的洞察。

尽管最初的结果令人鼓舞，但并未达到期望的准确性和一致性水平。开发过程经历了多轮迭代改进，例如重新设计系统并多次调用 LLM。成功的主要指标是一套人工评分系统，由业务专家比较结果并持续提供反馈，以改进整体基准。

## 业务影响与机会

通过将生成式 AI 集成到 Verisk Rating Insights，业务发生了显著的转变。客户获得了可观的时间节省。由于不再需要下载整个包并手动查找差异，用于分析的时间大幅减少。客户不再为每个测试用例花费 3–4 小时。过去需要数天的工作，现在只需几分钟。

这种时间节省带来了生产力的提升。借助能即时提供相关洞察的自动化解决方案，客户可以把更多精力放在决策上，而不是花时间手动检索数据。通过自动化差异分析并提供集中、省力的平台，客户对自己的结果准确性更有信心，也不会遗漏关键变更。

对 Verisk 而言，收益是客户支持负担的降低，因为 ERC 客户支持团队现在处理咨询的时间更少。借助 AI 驱动的对话式界面，用户可以自助服务并实时获得答案，从而释放支持资源以应对更复杂的咨询。

重复性培训任务的自动化意味着更快、更高效的客户入门。这减少了对冗长培训课程的需求，新客户也能更快上手。生成式 AI 的集成减少了冗余工作流和人工介入的需要。这精简了多个部门的运营，使业务更加敏捷、响应更快。

## 结论

展望未来，Verisk 计划从两方面继续增强 Rating Insights 平台。第一，我们将扩展查询范围，支持针对不同申报类型和更细致的保障领域的更复杂查询。第二，我们将扩展平台规模。在 Amazon Bedrock 提供基础设施的支撑下，Verisk 计划进一步扩展该解决方案，以支持更多用户以及跨多个产品线的更多内容集。

Verisk Rating Insights 如今由生成式 AI 和 AWS 技术驱动，已经改变了客户与费率内容变更交互和获取这些变更的方式。通过对话式用户界面、RAG 和向量数据库，Verisk 希望消除低效环节，为客户节省宝贵的时间和资源，同时提升整体的可访问性。对 Verisk 而言，该解决方案提升了运营效率，并为持续创新奠定了坚实基础。

凭借 Amazon Bedrock 和对自动化的专注，Verisk 正在推动智能客户支持与内容管理的未来，让客户和内部团队都能做出更明智、更快速的决策。
