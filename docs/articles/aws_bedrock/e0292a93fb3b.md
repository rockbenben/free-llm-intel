# 使用合成数据微调 LLM，在 Amazon Bedrock 上实现基于上下文的问答

客户越来越希望将生成式 AI 融入自身业务。许多用例通过 Retrieval Augmented Generation（RAG）这类方式来使用预训练的大语言模型（LLM）。然而，对于进阶的、特定领域的任务，或需要特定格式的任务，有时仍需要采用微调之类的模型定制技术。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 让你能够定制领先的基础模型（FM），例如 Anthropic 的 Claude 3 Haiku 和 Meta 的 Llama 3.1。

Amazon Bedrock 是一项全托管服务，通过 API 提供来自领先 AI 初创公司和 Amazon 自身的 FM，因此你可以从种类繁多的 FM 中挑选最适合自身用例的模型。Amazon Bedrock 提供无服务器体验，让你可以快速上手，用自有数据私密地定制 FM，并使用 AWS 工具把它们集成、部署到你的应用中，而无需管理任何基础设施。

微调是一种有监督的训练过程，用带标签的 prompt 与回复配对数据进一步训练预训练模型，以提升其在特定用例上的表现。微调始终存在的一个痛点是缺少数据来有效定制这些模型。收集相关数据本身就很困难，维持其质量又是另一道坎。此外，微调 LLM 需要投入大量资源。在这种情况下，合成数据生成提供了一种有前景的解决方案。你可以用更大的语言模型生成合成训练数据，再用它微调更小的模型，好处是周转时间更快。

本文探讨如何使用 Amazon Bedrock 生成合成训练数据来微调 LLM。此外，我们还提供了具体的评估结果，展示在数据稀缺时合成数据用于微调的效果。

## 解决方案概览

该解决方案包含两个主要步骤：

- 使用 Amazon Bedrock InvokeModel API 生成合成数据。
- 使用 Amazon Bedrock 自定义模型进行微调。

在合成数据生成中，我们使用一个更大的语言模型（例如 [Amazon Bedrock 上的 Anthropic Claude 3 Sonnet](https://aws.amazon.com/bedrock/claude/)）作为教师模型，并使用一个更小的语言模型（例如 Amazon Bedrock 上的 Anthropic Claude Instant 1.2 或 Claude 3 Haiku）作为学生模型来进行微调。我们用更大的教师模型基于其知识生成新数据，再用这些数据训练更小的学生模型。这一概念类似深度学习中的知识蒸馏，区别在于我们是用教师模型基于其知识生成新数据集，而不是直接修改学生模型的架构。

## 前提条件

要使用 Amazon Bedrock 生成合成数据并微调模型，你首先需要创建一个具有相应权限的 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 服务角色。Amazon Bedrock 使用该角色代表你访问所需资源。

## 使用 Amazon Bedrock InvokeModel API 生成合成数据

我们使用 [Amazon Bedrock InvokeModel API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_InvokeModel.html) 生成用于微调的合成数据。你可以用该 API 以编程方式向你选择的模型发送推理（文本生成）请求。你需要的只是一个为数据合成精心设计的 prompt。我们的用例使用了以下示例 prompt：

```
PROMPT = """
You are an AI assistant who is an expert in Amazon services. Your task is to understand a system that takes in a list of documents, and based on that, answers a question by providing citations for the documents that it referred the answer from.

Your job is to generate three new Question/Answer pairs, emulating the tone, style, and grammar of the original data provided.

Here is the original data :
Input Documents and Question : {document}\n\nQuestion: {question}
Output Answer : {answer}

Strictly return a jsonl with the keys (question, answer, topic). Every topic should be different. The answers should be in the exact same format as the original. The question and the answer should be different in content from the original data provided, and all questions should be diverse and different from each other. Do not answer in any other format. The response should be parsable as a jsonl.
"""
```

我们用例的目标是微调一个模型，使其能基于给定的参考文档和问题生成相关且连贯的回答。RAG 是此类问答任务常用的流行技术；然而 RAG 的一个显著挑战是可能检索到无关或不相关的文档，从而导致回答不准确。你可以应用微调来引导模型更好地关注文档与问题的相关性，而不是不加区分地用所提供的文档来回答问题。

我们的数据集包含围绕 AWS 服务的问答对及参考文档。每个样本最多包含五份参考文档作为上下文，随后是一个单行问题。下表展示了一个示例。

在数据合成中，我们要求模型为每份参考文档生成三个新的问答对。不过你可以按需调整数量。关键在于让模型深入思考各种主题。因为生成合成数据的目的是丰富训练数据集，所以让模型关注文档的不同部分、并生成与原始问答对不同主题的问答对会更有价值。

以下示例展示如何使用 Amazon Bedrock InvokeModel API 生成合成数据。我们用 Anthropic 的 Claude 3 Sonnet 测试了前面的 prompt。如果你想测试其他模型，请从 [Amazon Bedrock 模型 ID](https://docs.aws.amazon.com/bedrock/latest/userguide/model-ids.html) 中获取相应的模型 ID，并替换函数中的 modelId 变量。

```
import boto3
import json

bedrock = boto3.client(service_name="bedrock-runtime")

def generate_synthetic_data(document, question, answer):
    
    values = {
        "document": document,
        "question": question,
        "answer": answer
    }
    
    body = {
        "messages": [{
            "role": "user", "content": PROMPT.format(**values)
        }],
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 2048,
        "temperature" : 0.5
    }
    
    response = bedrock.invoke_model(
        body=json.dumps(body),
        modelId="anthropic.claude-3-sonnet-20240229-v1:0",
        accept="application/json",
        contentType="application/json"
    )
    
    response_body = json.loads(response.get('body').read())
    
    return response_body['content'][0]['text']
```

前面的函数以字符串形式返回三条 JSONL 记录，键为 question、answer 和 topic。下面的 parse_llm_output 函数加载这些字符串，并使用正则表达式提取生成的问题和答案。然后，create_synthetic_samples 函数把这两项功能结合起来，生成最终的合成训练样本。

```
import re
import pd

def parse_llm_output(jsonl_string):
    
    question_pattern = re.compile(r'"question":\s*"([^"]+)"')
    answer_pattern = re.compile(r'"answer":\s*"(.*?)"\s*,\s*"topic"') 
    questions = question_pattern.findall(jsonl_string)
    answers = answer_pattern.findall(jsonl_string)
    
    return questions, answers


def create_synthetic_samples(row: pd.Series) -> pd.DataFrame:

    jsonl_string = generate_synthetic_data(row['document'], row['question'], row['answer'])
    questions, answers = parse_llm_output(jsonl_string)
    
    return pd.DataFrame({
        "document": [row['document']] * len(questions),
        "question": questions,
        "answer": answers
    })


def to_customization_format(row):

    msg = {
        "messages": [
            {"role": "user", "content": f"{row['document']}\n\nQuestion: {row['question']}"},
            {"role": "assistant", "content": row['answer']}
        ]
    }
    
    return msg
```

以下脚本把前面所有函数组合起来，给出同时包含原始样本和合成样本的最终训练集。我们使用 to_customization_format 函数把样本转换成定制作业所需的格式，并保存为 train.jsonl。假设输入数据是一个包含三列 document、question 和 answer 的 CSV 文件。

```
import pandas as pd

# Load original training samples
original_train = pd.read_csv(input_df_path)

# Create synthetic training samples
synthetic_train = pd.concat(original_train.apply(create_synthetic_samples, axis=1).tolist())

# Combine original and synthetic samples
final_train_df = pd.concat([original_train, synthetic_train])

# Convert to the format required by the customization job
final_train = final_train_df.apply(to_customization_format, axis=1).tolist()

# Write to JSONL file    
with open('train.jsonl', 'w') as file:
    for item in final_train:
        json.dump(item, file)
        file.write('\n')
```

## 使用 Amazon Bedrock 自定义模型进行微调

现在你已经有了教师模型生成的合成数据以及原始数据，是时候训练学生模型了。我们使用 Amazon Bedrock 的自定义模型功能来微调学生模型。

模型定制是向 FM 提供训练数据以提升其在特定用例上表现的过程。截至本文撰写时，Amazon Bedrock 提供三种模型定制方法：

- 微调
- 持续预训练
- 蒸馏（预览）

你可以通过 Amazon Bedrock 控制台或 API，用上述任一方法创建自己的自定义模型。关于各定制方法支持的模型和 AWS 区域的更多信息，请参阅[模型定制用户指南](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-models.html)。本节我们重点介绍如何使用 API 微调模型。

要在 Amazon Bedrock 中创建微调作业，请完成以下前提步骤：

- 为训练数据创建一个 [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/s3) 存储桶，并为输出数据创建另一个存储桶（名称必须唯一）。
- 将 jsonl 文件上传到训练数据存储桶。
- 确保你已按[前提条件](https://aws.amazon.com/blogs/machine-learning/fine-tune-llms-with-synthetic-data-for-context-based-qa-using-amazon-bedrock/#_Prerequisites)所述创建了 IAM 角色。

完成这些步骤后，运行以下代码提交新的微调作业。在我们的用例中，学生模型是 Anthropic 的 Claude Instant 1.2。截至本文撰写时，Anthropic 的 Claude 3 Haiku 已正式可用，我们建议使用 Anthropic 的 Claude 3 Haiku 完成其余代码。发布公告见 [Amazon Bedrock 中 Anthropic Claude 3 Haiku 的微调现已正式可用](https://aws.amazon.com/about-aws/whats-new/2024/11/fine-tuning-anthropics-claude-3-haiku-amazon-bedrock/)。

如果你想尝试不同的模型，必须自行查看模型提供商的服务条款。许多提供商限制使用其模型训练竞争模型。关于最新的模型支持信息，请参阅[模型定制支持的区域和模型](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-model-supported.html)，并相应替换 baseModelIdentifier。不同模型的超参数不同。更多信息请参阅[自定义模型超参数](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-models-hp.html)。

```
import boto3
import json
import time

bedrock = boto3.client(service_name='bedrock')
    
# Set parameters
customizationType = "FINE_TUNING"
baseModelIdentifier = "arn:aws:bedrock:us-east-1::foundation-model/anthropic.claude-instant-v1:2:100k"
roleArn = "${customization-role-arn}"
jobName = "${customization-job-name}"
customModelName = "${customization-model-name}"
hyperParameters = {
    "epochCount": "1",
    "batchSize": "96",
    "learningRateMultiplier": "0.5",
 }
trainingDataConfig = {"s3Uri": "s3://${training-bucket}/train.jsonl"}
outputDataConfig = {"s3Uri": "s3://${output-bucket}/myOutputData"}

# Create job
response_ft = bedrock.create_model_customization_job(
    jobName=jobName, 
    customModelName=customModelName,
    roleArn=roleArn,
    baseModelIdentifier=baseModelIdentifier,
    hyperParameters=hyperParameters,
    trainingDataConfig=trainingDataConfig,
    outputDataConfig=outputDataConfig
)

jobArn = response_ft.get('jobArn')

# Check job status
while True:
    status = bedrock.get_model_customization_job(jobIdentifier=jobArn).get('status')
    if status != 'InProgress':
        print(status)
        break
    else:
        print(status)
    time.sleep(30)
```

当状态变为 **Completed** 时，你微调好的学生模型即可使用。要使用该自定义模型运行推理，你需要购买 *provisioned throughput*（预置吞吐量）。自定义模型提供灵活的 **No commitment**（无承诺）选项，不用时可关闭，按小时计费。购买预置吞吐量之前，控制台会提供成本估算。

在 Amazon Bedrock 控制台的导航窗格中，选择 **Custom models**。选择你微调的模型，然后选择 **Purchase provisioned throughput**。

![购买预置吞吐量的界面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/31/ML-17494-image-c.jpg)

模型名称和类型会自动为你选定。为 **Commitment term** 选择 **No commitment**。做出选择后，会显示预估成本。如果你接受该价格，请选择 **Confirm purchase**。

![购买预置吞吐量界面的详情](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/31/ML-17494-image-d.jpg)

当预置吞吐量可用后，获取该预置自定义模型的 ARN 并运行推理：

## 评估

本节我们分享实验结果，为教师模型生成的合成数据如何提升学生模型性能提供数据点。在评估方法上，我们采用了 LLM-as-a-judge 方法，由裁判模型比较两个不同模型的回复并选出更好的一个。此外，我们还在一个小规模子集上做了人工评估，以判断 LLM-as-a-judge 与人类裁判的偏好是否一致。

我们开展了对照实验，比较以下四个不同的模型：第 4 个模型的 1,500 条合成训练样本由 Anthropic 的 Claude 3 Sonnet 生成，我们为每份原始参考文档生成三条合成样本（3 条样本 * 500 份原始参考文档 = 1,500 条合成样本）。

| **Instant 基础模型** | 未经任何定制的 Anthropic Claude Instant |
| --- | --- |
| **微调 500 条原始样本** | 用 500 条原始训练样本微调的 Anthropic Claude Instant |
| **微调 2,000 条原始样本** | 用 2,000 条原始训练样本微调的 Anthropic Claude Instant |
| **用合成数据微调** | 用 500 条原始训练样本加 1,500 条合成训练样本微调的 Anthropic Claude Instant |

### LLM-as-a-judge 结果

LLM 输出评估是开发生成式 AI 应用的重要一步，但如果人工完成，成本高昂且耗时较多。要系统性地大规模评估输出质量，另一种替代方案是 LLM-as-a-judge 方法，即用一个 LLM 评估另一个 LLM 的回复。

在我们的用例中，我们使用 Anthropic 的 Claude 3 Sonnet 和 Meta Llama 3 70B 作为裁判。我们让 LLM 裁判比较两个不同模型的输出，选择其中一个，或判定为平局。下图汇总了裁判的判定结果。每个数字表示相应模型被评为提供更好回答的次数占比，不含平局情况。测试集包含 343 个样本。

![LLM 裁判结果（Sonnet 3.0）](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/31/ML-17494-image-e.jpg)

如上图所示，Anthropic Claude 3 Sonnet 裁判更偏好使用合成示例微调后的模型回复，胜过 Anthropic Claude Instant 基础模型（84.8% 偏好）和用 500 条原始样本微调后的模型（72.3% 偏好）。然而，裁判认为用 2,000 条原始样本微调后的模型优于使用合成示例微调后的模型（32.3% 偏好）。这符合预期：当有大量高质量原始数据可用时，最好使用能够准确反映目标数据分布的大规模训练数据。

![LLM 裁判结果（Llama 3 70B）](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/31/ML-17494-image-f.jpg)

Meta Llama 裁判得出了类似结论。如上图所示，它更偏好使用合成样本微调后的模型回复，胜过 Anthropic Claude Instant 基础模型（75.6% 偏好）和用 500 条原始样本微调后的模型（76.4% 偏好），但用 2,000 条原始样本微调后的模型才是最终赢家。

### 人工评估结果

为补充 LLM-as-a-judge 的结果，我们用两名人工裁判进行了人工评估。我们要求两名人工评估者执行与 LLM 裁判相同的成对比较任务，但只针对 20 个示例。下图汇总了结果。

![人工评估结果](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/31/ML-17494-image-g.jpg)

如上图所示，两名人工评估者得出了类似结论，印证了 LLM-as-a-judge 的结果。使用合成示例微调后的模型产生的输出，比 Anthropic Claude Instant 基础模型和用 500 条原始样本微调后的模型更受偏好；不过它未能胜过用 2,000 条原始示例微调后的模型。

来自 LLM 裁判和人工裁判的这些对比评估结果有力地证明了在训练数据稀缺时使用数据合成的威力和潜力。此外，通过使用教师模型的高质量数据，我们可以有效地训练学生模型，后者轻量且部署在生产环境中具有成本效益。

## 结论

本文探讨了如何使用 Amazon Bedrock，借助大型教师语言模型生成合成训练数据，并用合成数据微调更小的学生模型。我们给出了使用 Amazon Bedrock InvokeModel API 生成合成数据、以及使用 Amazon Bedrock 自定义模型微调学生模型的说明。我们的评估结果基于 LLM-as-a-judge 方法和人工评估，证明了在原始训练数据有限时，合成数据能有效提升学生模型的性能。

尽管用大量高质量原始数据进行微调仍是理想做法，但我们的发现凸显了在数据稀缺时合成数据生成作为一种可行方案的良好潜力。该技术可以为领域特定或专门化的用例带来更高效、更具成本效益的模型定制。
