# 使用 Slack 和 Amazon Bedrock 创建生成式 AI 助手

客户体验、协作工具和相关数据的无缝集成，是实现基于知识的生产力提升的基础。在本文中，我们展示如何把广受欢迎的 Slack 消息服务与 [AWS 生成式 AI](https://aws.amazon.com/ai/generative-ai/) 服务集成，构建一个自然语言助手，让业务用户可以对非结构化数据集提问。

为作演示，我们创建一个启用生成式 AI 的 Slack 助手，它与[ Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 集成，能够呈现 [AWS Well-Architected Framework](https://aws.amazon.com/architecture/well-architected) 的综合知识，同时使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 实施防护措施与负责任 AI。

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项全托管服务，通过单一 API 提供来自 AI21 labs、Anthropic、Cohere、Meta、Stability AI 和 Amazon 等领先 AI 公司的高性能基座模型（FM）供你选择。

Amazon Bedrock Knowledge Bases 提供全托管的 Retrieval Augmented Generation（RAG）workflow，这是一种从公司数据源获取数据并丰富 prompt 的技术，可针对自然语言查询给出更相关、更准确的响应。这让 Amazon Bedrock Knowledge Bases 成为一个有吸引力的选项：无需深厚的 machine learning 专业知识，就能把先进生成式 AI 能力融入产品与服务。

Amazon Bedrock Guardrails 让你可以实施防护措施，为生成式 AI 应用构建并定制安全性、隐私性和真实性保护，以符合负责任 AI 政策。Guardrails 可以帮助阻止不良内容、拦截 prompt injection，并为隐私移除敏感信息，从而保护公司的品牌与声誉。

本文以 [Deploy a Slack gateway for Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/deploy-a-slack-gateway-for-amazon-bedrock/) 等文章为基础，增加了与 Amazon Bedrock Knowledge Bases 和 Amazon Bedrock Guardrails 的集成，并使用 Bolt for Python 库来简化 Slack 消息确认与认证要求。

## 解决方案概述

本解决方案提供的配套 GitHub 仓库中的代码，可自动部署 Amazon Bedrock Knowledge Bases、Amazon Bedrock Guardrails，以及使用 Bolt for Python 库把 Amazon Bedrock Knowledge Bases API 与 Slack slash command 助手集成所需的资源。

在本示例中，我们把 Amazon Well-Architected Framework 的文档摄取到知识库中。然后我们使用与 Amazon Bedrock Knowledge Bases API 的集成，提供一个能回答用户关于 AWS 架构最佳实践问题的 Slack 助手。你可以把示例文档替换为企业数据集，例如企业、HR、IT 或安全政策，或设备使用与维护指南。

### Slack 集成

Slack 集成通过 [Slack Bolt Library](https://slack.dev/bolt-python/) for Python 提供，运行在 Request Processor [AWS Lambda](https://aws.amazon.com/lambda) 函数中。Slack Bolt Library 处理我们所构建 Slack 应用的认证与权限，并内置对异步请求处理的支持。Slack Bolt 提供[专门的用户指南](https://slack.dev/bolt-js/deployments/aws-lambda/)，说明如何在 Lambda 函数中部署和运行该库。

### 检索增强生成

Amazon Bedrock Knowledge Bases 为 FM 提供来自你私有数据源的上下文信息，供 RAG 使用，从而给出更相关、准确和定制的响应。

RAG workflow 由两个关键组件构成：数据摄取和文本生成。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/20/2-ML-16159-Rag-overview.png)

- 数据摄取 workflow – 在数据摄取过程中，来自数据源的非结构化数据被切分为 chunk。chunk 是来自每份源文档的一小段文本，按固定词数、段落或单一想法切分。chunk 会被向量化并存入向量数据库。Amazon Bedrock Knowledge Bases 支持多种[向量数据库](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-setup.html)，例如 [Amazon OpenSearch Serverless、Amazon Aurora](https://aws.amazon.com/rds/aurora/)、Pinecone、Redis Enterprise Cloud 和 Mongo DB Atlas。在本示例中，我们使用 OpenSearch Serverless 这一默认选项。
- 文本生成 workflow – 源数据摄取到向量数据库后，我们可以执行语义搜索，基于上下文化含义而非单纯的字面字符串匹配，找出与用户查询相关的数据 chunk。为完成该过程，用户查询与相关数据 chunk 会一起呈现给所选的大语言模型（LLM），以生成自然语言响应。

### Amazon Bedrock Knowledge Bases APIs

Amazon Bedrock Knowledge Bases 提供全托管的 RAG workflow，通过两个主要 API 对外提供：

- [Retrieve](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_Retrieve.html) – 该 API 使用语义搜索检索相关数据 chunk，你可以在应用逻辑中进一步处理
- [RetrieveAndGenerate](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_RetrieveAndGenerate.html) – 该 API 完成完整的 RAG 文本生成 workflow，针对给定数据集上的人类查询返回自然语言响应

本文的解决方案调用 `RetrieveAndGenerate` API，把自然语言响应返回给 Slack Bolt 集成库。

### Amazon Bedrock Guardrails

Amazon Bedrock Guardrails 在 FM 提供的内置保护之上，提供额外的可定制防护措施，交付业内领先的安全功能。

在本解决方案中，我们为 Amazon Bedrock Guardrails 配置内容过滤器、敏感信息过滤器和词过滤器。

内容过滤器帮助检测并过滤六个类别中的有害用户输入和模型生成输出：prompt injection、不当行为、侮辱、仇恨、暴力和色情内容。在本解决方案中，我们使用了全部六个内容过滤器类别。

敏感信息过滤器检测 prompt 或模型响应中的敏感信息，例如个人可识别信息（PII）数据。为契合你的具体情况，你可以用正则表达式（regex）定义自定义敏感信息过滤器。

在本解决方案中，我们按如下方式配置敏感信息过滤器：

- `Email`，动作为 `Anonymize`
- `Phone`，动作为 `Anonymize`
- `Name`，动作为 `Anonymize`
- `Credit_Debit_Card_Number`，动作为 `Block`

词过滤器用于屏蔽输入 prompt 和模型响应中的词语与短语。在本解决方案中，我们启用了 AWS 提供的不雅词过滤器。为契合你的用例，你可以创建自定义词过滤器。

## 解决方案演练

Slack 通过一个简单的 REST API 交互，该 API 配置了 Lambda 代理集成，并进而与 Amazon Bedrock Knowledge Bases API 交互。

该解决方案按以下高层步骤部署：

- 创建一个新的 Slack 应用。
- 在 Amazon Bedrock 中启用第三方模型访问权限。
- 使用 [AWS Cloud Development Kit](https://aws.amazon.com/cdk/)（AWS CDK）部署 Slack 到 Amazon Bedrock 的集成。
- 把 AWS Well-Architected Framework 文档摄取到知识库。

#### 部署 Slack 到 Amazon Bedrock 的集成

在本节中，你把本文的配套代码部署到你的 AWS 账户，这会部署 API Gateway 上的一个 API、一个 Lambda 函数，以及一个以 OpenSearch Serverless 作为向量数据库的 Amazon Bedrock 知识库。

本节要求你的本地集成开发环境（IDE）中安装了 AWS CDK 和 TypeScript，并且已为 AWS 账户执行 bootstrap。如果尚未完成，请参阅 [Getting started with the AWS CDK](https://docs.aws.amazon.com/cdk/v2/guide/getting_started.html)。

- 从 [GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-knowledgebase-slackbot)克隆代码：  `git clone https://github.com/aws-samples/amazon-bedrock-knowledgebase-slackbot.git`
- 在你偏好的 IDE 中打开 `amazon-bedrock-knowledgebase-slackbot` 目录，并打开 `lib/amazon-bedrock-knowledgebase-slackbot-stack.ts` 文件。
- 如有需要，为 RAG 查询模型和 embeddings 模型更新变量（取决于模型访问权限和 Region 支持）：  `const RAG_MODEL_ID = "anthropic.claude-3-sonnet-20240229-v1:0" const EMBEDDING_MODEL = "amazon.titan-embed-text-v2:0"`
- 所有更新完成后保存更改。
- 在仓库根目录运行命令 `npm install`。
- 运行命令 `cdk synth` 对 AWS CDK 代码做基本校验。这会从 AWS CDK 堆栈生成 CloudFormation 模板，你可以在仓库根目录创建的 `cdk.out` 目录中查看。
- 要部署应用堆栈，运行以下命令，并把值替换为你之前创建的 token 和签名密钥：  `cdk deploy --context slackBotToken=%slackBotToken% --context slackSigningSecret=%slackSigningSecret%`

AWS CDK 会把堆栈作为 CloudFormation 模板部署。你可以在 AWS CloudFormation 控制台监控部署进度。

此外，AWS CDK 会使用默认凭据文件配置，尝试把应用堆栈部署到默认账户和 Region。要更改配置，请添加 `profile` 标志。例如：

```
cdk deploy --profile [my-profile]
```

部署完成后，你会看到类似下图的输出，其中详细说明了刚刚部署的 API 端点。

#### 测试 Slack 应用与 Amazon Bedrock 的集成

完成以下步骤测试集成：

- 打开前面步骤中选择的 Slack 频道，输入 `/ask-aws`。

Slack 应用将会显示。

- 选择该 Slack 应用并输入你的 prompt。本次测试中，我们使用 prompt “*Tell me about the AWS Well Architected Framework.*”

Slack 应用会以 Processing Request 和所输入 prompt 的副本作为响应。随后应用会为该 prompt 提供响应。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/20/24-ML-16159-response.png)

- 要测试 guardrails 是否按要求生效，请编写一个会触发 guardrail 干预的 prompt。

发生干预时，你会收到以下预定义消息作为响应。

## 结论

在本文中，我们实现了一个把 Amazon Bedrock 知识库与 Slack 聊天频道集成的解决方案，让业务用户可以在熟悉的界面中对非结构化数据集提出自然语言问题。你可以通过把它配置到不同的 Slack 应用、并用相关数据集填充知识库，将该解决方案用于多种用例。
