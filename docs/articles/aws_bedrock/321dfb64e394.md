# Amazon Bedrock AgentCore 与 Claude：用 agentic AI 变革业务

企业 AI 的讨论已经发生根本性转变。我们不再问「AI 能否理解语言？」，而是在问「AI 能否自主执行复杂且能带来真实价值的业务流程？」根据 [McKinsey 的研究](https://www.mckinsey.com/industries/automotive-and-assembly/our-insights/empowering-advanced-industries-with-agentic-ai)，到 2030 年 agentic AI 有望每年额外创造 4500 亿至 6500 亿美元的收入，相当于各行业收入提升 5% 到 10%。

竞争优势的窗口正在收窄。当你的竞争对手还在试验 AI 试点时，那些把 agentic AI 投入生产的组织已经在今天获取可衡量的收益。但我们不断看到这样一个悖论：企业构建出令人印象深刻的原型，却始终无法规模化。差距不在于模型能力，而在于部署 agent 所需的运营基础设施——这些 agent 要能自主工作数小时、与企业系统安全集成，并在规模化下保持可靠性。下图概述了组织在把 agent 推向生产时可能面临的各种挑战。

但有些组织已经跨过了这道鸿沟。它们此刻就在生产环境中运行 AI agent，处理真实的业务流程，服务成千上万的客户，并交出了几个月前还看似不可能的结果。让我们从它们已经取得的成果说起。

### Druva：最高 63% 的自主解决率，响应时间最快提升 58%

Druva 的客户在网络安全方面面临不断升级的挑战：在复杂基础设施中领先于不断演变的数据异常。人工威胁调查意味着要在多个仪表盘、日志和告警之间来回切换。在安全领域，漏掉威胁信号可能导致灾难性后果——但潜在信号的数量之大，使全面人工审查根本不可能。

想想这个规模：超过 7,500 家客户，每家都有自己的基础设施形态、威胁态势和安全要求。挑战在于构建一个能在这个规模下可靠、安全运行的 AI 解决方案。

Druva 与 AWS Generative AI Innovation Center 合作构建了 [DruAI,](https://www.druva.com/about/press-releases/druva-introduces-ai-agents-to-simplify-cyber-resilience?sc_channel=sm&sc_publisher=LINKEDIN&sc_country=global&sc_geo=GLOBAL&sc_outcome=awareness&linkId=853661217) ——一个运行在 Amazon Bedrock AgentCore 上、由 Claude 驱动的多 agent 系统。该系统使用多个协同工作的 AI agent，从数百个选项中自动选择正确的工具，处理遥测分析、威胁调查和修复。AgentCore Runtime 提供更安全、隔离的执行环境并支持自动伸缩，让 Druva 团队可以专注于交付客户价值，而不必构建和维护复杂的安全基础设施。

影响：目前已有超过 3,000 家客户和 10,000 名用户部署了 DruAI，实现解决时间最快提升 58%，并可在无人干预的情况下解决最多 63% 的客户问题。在网络安全领域，速度决定了威胁是被控制住，还是演变成冲击业务的入侵事件。

> “我们在 Druva 的客户需要改造人工威胁调查流程，而这一流程涉及在多个仪表盘、日志和告警之间来回切换。使用 AgentCore 的 Runtime，我们快速部署了 DruAI——我们面向客户的 AI 能力套件——具备完整的会话隔离与自动伸缩，使我们能够专注于为客户交付价值，而不必构建和维护复杂的安全基础设施。我们的系统负责遥测分析、威胁调查与修复，目前已有超过 3,000 家客户和 10,000 名用户在使用。DruAI 将解决时间缩短了 58%，并在无人干预的情况下解决了 63% 的客户问题。”

## 为什么选择 Amazon Bedrock AgentCore 与 Anthropic 的 Claude

生产环境中的 agentic AI 需要两样东西：能够处理复杂自主 workflow 的前沿 AI 能力，以及为这些 agent 在生产中运行提供安全性、可靠性和运营基础的企业级基础设施。Amazon Bedrock AgentCore 与 Claude 恰好提供了这种组合。AgentCore 包含多个完全托管的服务，可作为 Amazon Bedrock AgentCore 的组成部分一起或独立使用：Runtime、Memory、Identity、Gateway、Code Interpreter、Browser Tool 和 Observability。

## Agent 智能与逻辑：专注于真正重要的事

企业构建 agentic AI 时，工程团队通常要花几个月搭建会话管理、凭据保管库、工具编排、可观测性框架和伸缩逻辑等基础设施。等到他们终于可以专注于真正的 agent 逻辑与业务价值时，人已经精疲力竭，用例也可能早已演变。Amazon Bedrock AgentCore 是一个全面的 agentic 平台，用于大规模构建、部署和运行能力强大的 agent。它与模型无关，这意味着它承担了基础设施与运营方面的挑战，让开发者能够专注于真正构成业务差异的部分：agent 的逻辑以及它需要完成的特定任务。这一做法让 Claude 的高性能与上下文理解能力得到最大化发挥。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/17/ML-19937-2.png)

AgentCore 可与你的团队已经熟悉的框架配合使用，例如 [Strands Agents](https://strandsagents.com/latest/)、CrewAI、LangGraph、LlamaIndex。你也可以把它与任何基础模型一起使用，无论该模型托管在 Amazon Bedrock 还是别处。这消除了开源灵活性与企业级可靠性之间由来已久的取舍。

### 内建的企业级安全与可靠性

尽管 Claude 针对 agentic AI workflow 做了优化，但仅靠它并不提供复杂 agent 所需的生产基础设施。这正是 Amazon Bedrock AgentCore 的用武之地。AgentCore 提供完整的会话隔离，确保每次执行都被完全封闭；安全的凭据保管库帮助保护敏感 token；身份感知的授权机制精确控制 agent 可以访问什么。agent 可以自主工作最长 8 小时，并支持自动伸缩，提供业务流程所要求的可靠性。

### 增强的 agent 能力

AgentCore 提供内置工具，扩展由 Claude 驱动的 agent 所能完成的工作。Code Interpreter 为数据处理与分析提供安全的代码执行环境，Browser 则让 agent 能够与 Web 应用交互、浏览页面、提取数据并执行交易。

但真正的放大器是 **AgentCore Gateway**：它把你现有的 REST API 和 AWS Lambda 函数转化为具备语义路由的、可直接供 agent 使用的工具。你的 agent 可以与现有业务系统、数据库和服务交互，无需为 AI 重建一切。该 gateway 负责双向安全与智能工具选择，因此即使你扩展到数百或数千个工具，agent 依然能找到并使用正确的工具。

这些要素结合在一起，创造了任何一方都无法单独实现的东西：具备前沿智能、企业级可靠性，以及在生产环境中交付业务价值的运营基础——不是在搭完基础设施之后的六个月，而是现在。上图展示了 AgentCore Gateway 带来的好处。

## 这些成果背后的技术

让我们来看看让这些成果成为可能的技术基础，同时不必陷入实现细节。

### 可支撑生产负载伸缩的基础设施

Amazon Bedrock AgentCore 是为生产环境 agentic AI 专门构建的基础设施。可以把它看作把有能力的 AI 模型转化为可用业务系统的运营基础。你不必再花几个月做无差别的重复性重活，或从零构建可用于生产的 agent，它以托管 agentic 平台的形式直接可用。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/17/ML-19937-4.png)

AgentCore Runtime 与 AgentCore Identity 服务提供更安全的无服务器执行环境，agent 可在完整会话隔离下自主工作最长 8 小时。身份管理与你现有的身份提供方集成——Okta、Microsoft Entra 或 Amazon Cognito——处理 OAuth、token 管理以及全面的审计轨迹，帮助满足最严格的合规要求，包括 AWS GovCloud (US) 客户所信赖的那些要求。Gateway 把 REST API 和 Lambda 函数转化为具备智能语义路由的、与 agent 兼容的工具；而 AgentCore Memory 让开发者可以直截了当地构建上下文感知的 agent，大幅减少复杂的记忆基础设施，使 agent 能够跨对话保持上下文并逐步积累知识库。

Observability 通过 CloudWatch 提供完整的可见性，并兼容 OpenTelemetry，可对接 Dynatrace、Datadog、Arize Phoenix、LangSmith 和 Langfuse 等系统。你可以跟踪 agent 正在做什么、监控性能、识别错误，并维持生产系统所要求的运营可见性。AgentCore 的各项服务支持 VPC、AWS PrivateLink、CloudFormation 和资源标记，以增强企业级安全。

### Claude 处理复杂长时任务的智能

基础设施让部署成为可能，而模型能力决定了 agent 能完成什么。[Claude Sonnet 4.5](https://www.anthropic.com/news/claude-sonnet-4-5) 是 Anthropic 在 agentic AI 用例上表现最好的模型，其能力专为自主、长时间运行的 workflow 而设计。

Claude Sonnet 4.5 可以长时间独立工作，同时保持清晰与专注。该模型在任务上稳步推进，而不是试图同时处理所有事情，并给出准确反映进展的、基于事实的更新。对于需要数小时持续关注并逐步推进的复杂 workflow，这种能力至关重要。

该模型在整个对话过程中跟踪 token 使用量，并对自身的工作上下文保持感知。这有助于防止过早放弃任务，并让长时间运行的操作执行得更加有效。结合能够在即时上下文窗口之外存储和检索信息的记忆能力，agent 可以跨会话保持状态，并随着时间推移构建知识库。

Claude 采用 Anthropic 的 Constitutional AI 方法构建，被设计为有用、无害且诚实。大量安全训练已显著减少了包括谄媚、欺骗和追求权力在内的令人担忧的行为。这一对齐基础对企业部署尤为重要——在这些部署中，agent 的可靠性与恰当行为是不可妥协的要求。当 agent 自主运行数小时，信任是根本。

Claude Sonnet 4.5 在编码与推理任务上达到最先进水平，并具备更强的规划与系统设计能力。该模型擅长跨越数小时甚至数天的自主任务，同时保持一致的表现。除编码之外，Claude 在财务分析、研究 workflow 和网络安全应用方面展现出高级推理能力，从而使复杂的 agent 应用能够覆盖多种企业用例。

## 对企业领导者的战略含义

你在 agentic AI 基础设施上所做的决策，实质上是在为多年期的 AI 路线图奠定基础。请考虑以下几点：

### 把系统选择当作竞争定位

你的竞争对手也在评估同样的机会。率先建立生产级 agentic AI 的组织能够获得随时间累积的优势：既能降低成本又能改善服务的运营效率、原本不可能的能力变成常规做法，以及从真实部署中获得的组织学习能力。

AI 正在变革你所在的行业。你是要引领这场变革，还是要被动应对？

### 创新速度：能力自动提升

Claude Sonnet 4.5 在 Claude Opus 4.1 发布仅七周后推出。这种模型改进的速度如今已成为基准预期。你选择的系统决定了你是能自动享受这些进步，还是每次能力提升都要面对迁移项目。

基于 Amazon Bedrock 构建的组织可以在新模型能力可用时即刻获得，无需重新改造、无需启动迁移项目，也不会产生技术债。你的 agent 会随着时间变得更强，而团队则始终专注于业务价值而非系统维护。

AgentCore 不断扩展的能力也沿着类似的轨迹演进。近期的新增内容包括用于多 agent 协作的增强版 Agent-to-Agent（A2A）协议支持、扩展的可观测性集成，以及 Browser 和 Code Interpreter 等新工具。这些能力一经发布即可供你的 agent 使用，在保持向后兼容的同时让你的投资面向未来。

### 多 agent 的未来：协调与专业化

随着单个 agent 在你的组织内证明价值，下一个前沿是协调式的多 agent 系统——由专用 agent 在复杂业务挑战上协作。Amazon Bedrock 通过 A2A 协议支持多 agent 协作，可实现多种复杂模式：

**专用 agent 团队**：你部署专注的 agent，各自擅长特定领域，例如财务分析、代码审查、客户交互、安全监控，并在智能编排下协同工作。

**Supervisor agent**：把复杂 workflow 拆解为可管理的子任务，委派给合适的专家 agent，并将结果综合为连贯的成果。

像 Druva 这样的组织已经在生产环境中运行多 agent 系统，相应的架构模式也正在确立。你所选择的基础设施基础，将决定你明天向这些复杂部署演进时有多顺畅。

## 风险缓解：安全、治理与合规

企业部署要求把安全与治理内建到基础之中。AgentCore 为合规提供完整的审计轨迹、随 agent 环境扩展的细粒度授权，以及有助于控制潜在问题的会话隔离。Claude Sonnet 4.5 中的 Constitutional AI 帮助提供额外的可靠性层：当 agent 自主运行时，你需要确信它们会恰当行事并遵循你的指令。
