# 用 Amazon Bedrock Projects 管理 AI 成本

随着组织在 Amazon Bedrock 上扩大 AI 工作负载的规模，搞清楚是什么在推高支出变得至关重要。团队可能需要做内部计费分摊、排查成本尖峰，并为优化决策提供依据，而这些都要求在工作负载层面做成本归属。

借助 [Amazon Bedrock Projects](https://docs.aws.amazon.com/bedrock/latest/userguide/projects.html)，你可以把推理成本归到具体的工作负载上，并在 AWS Cost Explorer 和 AWS Data Exports 中分析它们。在本文中，你将学会端到端地设置 Projects，从设计标签策略一直到分析成本。

## Amazon Bedrock Projects 与成本分摊的工作方式

Amazon Bedrock 中的项目（project）是一个逻辑边界，代表一个工作负载，例如某个应用、环境或实验。要把项目的成本归属出来，你需要附加资源标签，并在 API 调用中传入项目 ID。之后你可以在 AWS Billing 中启用[成本分配标签](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/cost-alloc-tags.html)，在 AWS Cost Explorer 和 AWS Data Exports 中筛选、分组和分析支出。

- 不带项目 ID 的请求会自动关联到你 AWS 账户中的默认项目。

## 先决条件

要跟着本文的步骤操作，你需要：

- 具备使用 OpenAI SDK 访问 Amazon Bedrock 的权限。请参阅 [Amazon Bedrock 快速入门](https://docs.aws.amazon.com/bedrock/latest/userguide/getting-started.html) 开始。
- 针对 Amazon Bedrock Projects、推理和标签的 IAM 权限。对本示例，你可以附加 AWS 托管策略 [AmazonBedrockMantleFullAccess](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/AmazonBedrockMantleFullAccess.html)。用于生产环境时，请参阅[为 Amazon Bedrock 实施最小权限](https://aws.amazon.com/blogs/security/implementing-least-privilege-access-for-amazon-bedrock/)。
- 访问 [AWS Billing and Cost Management 控制台。](https://console.aws.amazon.com/costmanagement/)

## 定义你的标签策略

你附加到项目上的标签，会成为成本报告中可供筛选和分组的维度。我们建议在创建第一个项目之前就规划好它们。一种常见做法是按应用、环境、团队和成本中心打标签：

| **标签键** | **用途** | **示例值** |
| --- | --- | --- |
| Application | 哪个工作负载或服务 | CustomerChatbot, Experiments, DataAnalytics |
| Environment | 生命周期阶段 | Production, Development, Staging, Research |
| Team | 归属 | CustomerExperience, PlatformEngineering, DataScience |
| CostCenter | 财务映射 | CC-1001, CC-2002, CC-3003 |

关于构建成本分摊策略的更多指引，请参阅 [Best Practices for Tagging AWS Resources](https://docs.aws.amazon.com/whitepapers/latest/tagging-best-practices/building-a-cost-allocation-strategy.html)。标签策略确定后，你就可以创建项目并开始归属成本了。

## 创建项目

在标签策略和权限就位之后，你可以创建第一个项目。每个项目都有自己的一组成本分配标签，它们会流入你的账单数据。下面的示例展示如何使用 [Projects API](https://docs.aws.amazon.com/bedrock/latest/userguide/projects.html) 创建项目。

首先，安装所需的依赖：

```
$ pip3 install openai requests
```

**用你的标签分类法创建项目：**

OpenAI SDK 使用 `OPENAI_API_KEY` 环境变量。把它设置为你的 Bedrock API key。

```
import os
import requests

# Configuration
BASE_URL = "https://bedrock-mantle.<YOUR-REGION-HERE>.api.aws/v1"
API_KEY  = os.environ.get("OPENAI_API_KEY")  # Your Amazon Bedrock API key

def create_project(name: str, tags: dict) -> dict:
    """Create a Bedrock project with cost allocation tags."""
    response = requests.post(
        f"{BASE_URL}/organization/projects",
        headers={
            "Authorization": f"Bearer {API_KEY}",
            "Content-Type": "application/json"
        },
        json={"name": name, "tags": tags}
    )

    if response.status_code != 200:
        raise Exception(
            f"Failed to create project: {response.status_code} - {response.text}"
        )

    return response.json()

# Create a production project with full tag taxonomy
project = create_project(
    name="CustomerChatbot-Prod",
    tags={
        "Application": "CustomerChatbot",
        "Environment": "Production",
        "Team":        "CustomerExperience",
        "CostCenter":  "CC-1001",
        "Owner":       "alice"
    }
)
print(f"Created project: {project['id']}")
```

API 会返回项目详情，包括项目 ID 和 ARN：

```
{
  "id": "proj_123",
  "arn": "arn:aws:bedrock-mantle:<YOUR-REGION-HERE>:<YOUR-ACCOUNT-ID-HERE>:project/<YOUR-PROJECT-ID>"
}
```

保存项目 ID。下一步你会用它把推理请求关联起来。ARN 用于挂接 IAM 策略，以便在你需要限制对该项目的访问时使用。每个工作负载都重复一遍。下表展示了一个拥有三个应用的组织的示例项目结构：

| **项目名称** | **应用** | **环境** | **团队** | **成本中心** |
| --- | --- | --- | --- | --- |
| CustomerChatbot-Prod | CustomerChatbot | Production | CustomerExperience | CC-1001 |
| CustomerChatbot-Dev | CustomerChatbot | Development | CustomerExperience | CC-1001 |
| Experiments-Research | Experiments | Production | PlatformEngineering | CC-2002 |
| DataAnalytics-Prod | DataAnalytics | Production | DataScience | CC-3003 |

每个 AWS 账户最多可以创建 1,000 个项目，以满足你组织的需要。

## 把推理请求与项目关联

项目创建好之后，你就可以在 API 调用中传入项目 ID 来关联推理请求。下面的示例使用 Responses API：

```
from openai import OpenAI

client = OpenAI(
    base_url="https://bedrock-mantle.<YOUR-REGION-HERE>.api.aws/v1",
    project="<YOUR-PROJECT-ID>", # ID returned when you created the project
)
response = client.responses.create(
    model="openai.gpt-oss-120b",
    input="Summarize the key findings from our Q4 earnings report."
)
print(response.output_text)
```

为保持成本归属的清晰，请始终在 API 调用中指定项目 ID，而不要依赖默认项目。

## 启用成本分配标签

在你的项目标签出现在成本报告之前，你必须先在 AWS Billing 中把它们启用为成本分配标签。这项一次性设置会把你的项目标签接入账单 pipeline。关于[启用成本分配标签](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/custom-tags.html)的更多信息，请参阅 AWS Billing 文档。

标签传播到 AWS Cost Explorer 和 AWS Data Exports 最多可能需要 24 小时。你可以在创建第一个项目后立即启用标签，以避免成本数据出现缺口。

## 查看项目成本

项目已创建、推理请求已打标签、成本分配标签也已启用，现在你就能看清你的 Amazon Bedrock 支出究竟花在哪里了。你在分类法中定义的每个维度，现在都可在 AWS Billing 成本报告中作为筛选条件或分组方式使用。

**AWS Cost Explorer**

AWS Cost Explorer 提供了按项目可视化成本的最快方式。请完成以下步骤来按项目查看成本：

- 打开 AWS Billing and Cost Management 控制台，选择 **Cost Explorer**。
- 在 Filters 窗格中展开 **Service**，选择 **Amazon** **Bedrock**。
- 在 **Group by** 下选择 **Tag**，然后选择你的标签键（例如 **Application**）。

![Amazon Bedrock 在 AWS Cost Explorer 中的应用项目视图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/07/ML-20677-image-2.png)

*图 2：Cost Explorer 按 Application 标签分组的 Amazon Bedrock 每日支出*

要了解精修视图的更多方式，请参阅[使用 AWS Cost Explorer 分析你的成本与用量](https://docs.aws.amazon.com/cost-management/latest/userguide/ce-what-is.html)。

要结合项目标签做更细粒度的分析和明细行查看，请参阅 AWS Billing 文档中的[创建 Data Exports](https://docs.aws.amazon.com/cur/latest/userguide/dataexports-create.html)。

## 结论

借助 Amazon Bedrock Projects，你可以把成本归到单个工作负载上，并用组织已经在依赖的 AWS 工具跟踪支出。随着工作负载扩展，请沿用本文介绍的标签策略与成本可见性做法，在团队和应用之间维持问责。

更多信息请参阅 [Amazon Bedrock Projects](https://docs.aws.amazon.com/bedrock/latest/userguide/projects.html) 文档和 [AWS Cost Management 用户指南](https://docs.aws.amazon.com/cost-management/latest/userguide/what-is-costmanagement.html)。
