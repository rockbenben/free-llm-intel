# 在 Amazon SageMaker AI 上使用基于 rubric 的 Amazon Nova LLM judge 评估生成式 AI 模型（第 2 部分）

在[在 Amazon SageMaker AI 上使用 Amazon Nova 以 LLM-as-a-Judge 评估生成式 AI 模型](https://aws.amazon.com/blogs/machine-learning/evaluating-generative-ai-models-with-amazon-nova-llm-as-a-judge-on-amazon-sagemaker-ai/)一文中，我们介绍了 [Amazon Nova](https://nova.amazon.com/chat) 的 LLM-as-a-judge 能力，它是一个通过 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/) 提供的专用评估模型，可用于系统地衡量生成式 AI 系统的相对性能。

SageMaker AI 现在提供由 Amazon Nova 驱动的基于 rubric 的大语言模型（LLM）judge。它不再对每个任务使用相同的通用规则，而是为每个单独的 prompt 自动创建具体的评估标准。这帮助生成式 AI 开发者和机器学习（ML）工程师为其 LLM 和生成式 AI 产品自动生成精确、针对具体场景的评估标准，而无需为每个用例手工编写规则集。

在本文中，我们探讨 Amazon Nova 基于 rubric 的 judge 功能：什么是基于 rubric 的 judge、该 judge 如何训练、应考虑哪些指标，以及如何校准该 judge。我们分享了 Amazon Nova 基于 rubric 的 LLM-as-a-judge 方法的 notebook 代码，用于使用 SageMaker 训练作业评估和比较两个不同 LLM 的输出。

## Amazon Nova 基于 rubric 的 judge 概述

基于 rubric 的 LLM judge 使用一个能力很强的 LLM（具体来说是 Amazon Nova）充当 judge，对其他 AI 模型生成的响应或人类生成的响应做出评判。该能力可在模型迭代之间提供成对比较，让你可以满怀信心地就模型改进做出数据驱动的决策。rubric 是用于评估表现的评分指南。传统上，为了评估一个 AI 模型，人们会手工编写一份适用于每个任务的规则清单（静态 rubric）。例如：“回答是否礼貌？”或“回答是否简短？”这种做法的问题在于，这些通用规则无法扩展到所有用户。创意写作 prompt 需要的评分标准不同于编码 prompt 或法律摘要，而不是一份通用清单。由 Amazon Nova 驱动的 judge 会为不同交互创建自定义清单。用户向系统发送一个具体的 prompt（例如“为患者总结这份医疗文档”）。judge 会分析该具体 prompt，并即时判断理想答案应该是什么样子。它会自动编写如下标准：

- 是否使用简单、非医学的术语？
- 是否准确捕捉到诊断结果？
- 语气是否有同理心？

随后，judge 查看你的 LLM 模型生成的输出，并按照它刚刚创建的这些具体标准给出评分。你得到的质量分数基于与该具体任务相关的规则，而不是通用规则。

## 企业实施示例

Amazon Nova 基于 rubric 的 LLM judge 可应对不同场景中的关键评估挑战：

- **模型开发与 checkpoint 选择** – 开发团队把 Amazon Nova 基于 rubric 的 judge 评估集成到训练 pipeline 中，自动评估 checkpoint。按标准给出的分数可以揭示哪些能力在不同迭代之间增强或退化，从而支持就超参数调整和数据整理做出数据驱动的决策。
- **训练数据质量控制** – 团队使用 Amazon Nova 基于 rubric 的 judge 评估，通过在相关性标准上生成逐点分数来过滤监督微调数据集，识别低质量样本。对于偏好数据集，计算出的响应对之间的差值可支持课程学习策略，从而过滤掉压倒性偏向一侧、只能提供有限学习信号的样本。
- **自动化深入分析与根本原因分析** – 大规模部署生成式 AI 的组织可以使用 Amazon Nova 基于 rubric 的 judge 评估，对数以千计的模型输出进行系统分析，无需人工审阅。当模型出现质量问题时，开发者可以检查哪些具体标准驱动了偏好判断，识别出系统性弱点，从而指导有针对性的改进，而不是大规模重新训练。

## 动态 rubric 生成的工作原理

Amazon Nova 基于 rubric 的 LLM judge 以三元组 `<prompt, response_1, response_2>` 作为输入。judge 针对给定 prompt 比较两个响应的质量，并输出一个偏好标签。除总体标签之外，judge 还会在 rubric 的引导下为其决定生成理由。

rubric 是一组用于评估这两个响应的加权标准。基于 rubric 的 LLM judge 经过训练，能够生成权重之和为 1 的标准。rubric 中的每个标准都有 `short_name`、`description` 和 `weight`。judge 的决定包含每个响应在 rubric 中每个标准上的得分，以及对这些得分的理由说明。

Amazon Nova 基于 rubric 的 LLM judge 采用一种评估方法，其中每个判断都由动态生成的、针对具体 prompt 的标准来支撑。当 judge 收到包含 prompt 和候选响应的评估请求时，它会分析 prompt 以理解其上下文，并基于该上下文生成标准。这一动态生成过程确保评估建立在直接适用于当前任务的标准之上，提供透明且可解释的评估。

对于每次评估，judge 都会生成结构化的 YAML 输出，其中包含生成的标准及其定义、按 1–5 分制给出的各标准得分，以及解释每个得分的详细理由。最终输出包含四种偏好标签之一：`[[A>B]]`、`[[B>A]]`、`[[A=B]]` 或 `[[A=B (bothbad)]`。每个标准得分都附有理由，把评估建立在响应的可观察特征之上，从而支持深入分析和调试模型行为。

### 将基于 rubric 的 Amazon Nova LLM-as-a-judge 与之前的版本对比

基于 rubric 的 judge 与之前版本的区别在于它如何呈现评估结果以及提供哪些信息。

之前版本的 Amazon Nova LLM-as-a-judge 模型返回简单的偏好标签（`[[A>B]]` 或 `[[B>A]]`）。基于 rubric 的版本会生成结构化的 YAML 输出，包含以下内容：

- 用于评估响应的、针对具体 prompt 的 rubric，它组织为一组标准，并带有对应的各标准重要性权重（权重之和为 1）
- 对每个标准的简短自然语言描述
- 对输入中每个候选响应的每个标准给出 [Likert 分数](https://en.wikipedia.org/wiki/Likert_scale)（1–5 分制）或二元（true/false）判断
- 针对每个候选响应的每个标准得分的理由
- 总体偏好判断：A>B、B>A、A=B 或 A=B（both bad）之一

新的详细输出格式支持广泛而细致的用例。例如，rubric 中的具体标准可以对响应进行更具针对性的比较。简洁的响应在某些用例中可能更合适，而其他用例可能需要全面的响应。理由说明和明确的标准评分帮助用户舍弃不适合其需求的某些标准，并在不重新通过 LLM judge 运行查询的情况下重新计算偏好判断。

## 指标说明

在我们的 judge 评估流程中，我们使用若干重要指标，作为对 judge 质量排序的比较基准。forward agreement 是一个指标，它在选定的响应与被拒绝的响应以特定顺序呈现时，计算 judge 与人类偏好的一致程度，这确保整个数据集的正确标签始终是 A>B 或 B>A 之一。由于位置一致性是可信赖 LLM judge 的重要期望属性，我们以 reconciled agreement 来评估 checkpoint——也就是说，我们让响应以两种可能的顺序呈现给 judge，获得两个判断（针对两个响应的偏好判断）。只有当 judge 在两个方向上判断一致、且判断与人类偏好相符时，我们才将其计为正确。按定义，这个数值总是低于 forward agreement。但正因为真实世界的数据集并非排好序的，它能更准确地代表 LLM judge 模型在真实世界中的表现。

加权分数（`weighted_score_A` 和 `weighted_score_B`）是添加到 rubric judge 评估输出中的新指标，它们提供了对判断置信度的观察视角。加权分数之间的较大差异表明对某个响应的强烈偏好。这些分数按样本计算，基于 rubric 中每个标准被赋予的分数。每个标准得分都归一化到 0–1 区间（其中 1–5 分制的量表分数映射到 0.0–1.0，二元 True/False 映射到 1.0/0.0），然后乘以该标准的权重并求和，得到每个响应的加权分数。

`score_margin` 显示加权分数之间的差值，负值表示偏向响应 B，正值表示偏向响应 A。在最终评估输出中，这些指标以所有样本的平均值形式报告。逐样本的标准细分、单项得分和理由可在详细的 Parquet 输出文件中找到。

对每个比较样本，我们可以获得新的 rubric judge 模型在比较两个结果时所使用的具体标准，如下面的示例代码所示：

```
================================================================================
Row 1:
  Preference: ['B>A']
  A wins: 0.0
  B wins: 2.0
  Weighted A: 0.225
  Weighted B: 1.000
  Margin: -0.775

  Overall Justification:
    Response B provides a comprehensive and detailed explanation of photosynthesis, covering the process, location, chemical equation, and importance. Response A only provides a brief, surface-level description without explaining the mechanism or significance.

  Criteria:

    completeness:
      Score A: 2, Score B: 5
      Weight: 0.5, Type: scale
      Description: How thoroughly the response explains the photosynthesis process.
      Justification A: Response A mentions the basic inputs and outputs but lacks detail on the mechanism, location in the cell, or the chemical equation.
      Justification B: Response B provides a complete explanation including the process, chloroplasts, chemical equation, and the importance to life on Earth.

    clarity:
      Score A: 3, Score B: 5
      Weight: 0.3, Type: scale
      Description: How clearly the response communicates the concept.
      Justification A: Response A is clear but overly simplistic, lacking the detail needed for full understanding.
      Justification B: Response B is well-structured and clearly explains each component of photosynthesis in an accessible way.

    accuracy:
      Score A: 4, Score B: 5
      Weight: 0.2, Type: scale
      Description: How accurate the scientific information is.
      Justification A: Response A is accurate in what it states but incomplete.
      Justification B: Response B is fully accurate and includes the correct chemical equation and scientific terminology.
================================================================================
```

这些加权指标是参考性的，提供对评分细分的定量洞察，但决定最终胜场数的实际偏好决定（A>B、B>A 或 A=B）基于 judge 模型的总体偏好输出。

## judge 的训练方法

Amazon Nova 基于 rubric 的 judge 使用多维度奖励包进行训练。在我们的训练方法中，我们通过有效的奖励公式针对 LLM judge 的若干理想特性进行优化。我们主要针对以下标准：

- **偏好准确性 **– 当 judge 做出与人类金标准偏好一致的判断时，它会获得奖励。当它在两个响应之间选择其中一个时，模型会获得奖励。
- **位置一致性 **– judge 的判断经过训练，能在给定特定候选响应顺序时对位置不一致问题保持稳健。
- **理由质量 **– judge 为做出判断而给出的理由必须与生成的 rubric、分数和最终判断一致。
- **分数校准 **– 响应的加权分数必须与判断准确性相校准（高置信度判断正确出现的频率必须高于低置信度判断）。

我们从人工标注的偏好数据出发，采用定制的数据过滤和合成数据生成方案，以获得与 rubric 对齐的偏好理由。我们从生成的合成 rubric 中采样，并开发了一条定制 pipeline，训练 Amazon Nova 基于 rubric 的 LLM judge 熟练生成粒度精确的合适标准，从而实现一致而稳健的决策。

### 校准

在我们的训练过程以及后处理过程中，我们评估 Amazon Nova 基于 rubric 的 judge 做出良好校准判断的能力。为实现平衡的校准，我们在人工标注的偏好数据集上观察置信度分桶。我们观察响应对的加权分数差值。我们的目标是让置信度与准确性相校准。理想情况下，LLM judge 在高置信度决策时应更准确，而在低置信度决策时允许准确性较低。我们发现这种校准方法能在分布内和分布外数据集上都产生一致的决策。我们还会观察不同标准生成分数的分布。我们希望在评估数据集上 Likert 量表分数（1–5）大致呈正态分布。这种双管齐下的校准检查流程帮助我们在若干表现同样良好的 checkpoint 中识别出更好的 LLM judge checkpoint。

## 基于 rubric 的判断的用例

动态生成 rubric 的可靠性源自三项决策：

- judge 在代表真实世界用例的多样化、高质量、带 rubric 标注的偏好数据上训练，教会它区分有效评估标准与表面化标准的模式。
- 我们在训练期间的过滤机制优先选择具备理想属性的 rubric——全面性、互斥性、恰当的粒度和任务相关性——确保模型从最佳示例中学习。
- 我们的奖励公式直接激励 rubric 质量：能带来准确、位置不变且置信度良好校准的偏好判断的标准会获得正向奖励，而产生不一致判断的标准则会被惩罚。

#### 如何使用 rubric 改进实际应用

许多现代应用在无参考环境中运行，其中不存在金标准的人类答案。在这些情况下，rubric 的有用性至关重要。本节我们重点介绍 judge 生成的 rubric 可能作为知情决策有用输入的实例。我们展示基于 rubric 的 judge 的输出——具体来说是加权标准、细粒度分数和明确的理由——如何作为关键的控制机制。

## 评估 RAG 系统

在检索增强生成（RAG）中，主要的失败模式是幻觉。传统的偏好 judge 通常会把“这个响应好吗？”与“它是否流畅？”“它格式是否良好？”“它的内部逻辑是否站得住？”等问题混为一谈。一个流畅但事实错误的响应，往往被认为比一个包含准确信息却支离破碎的响应更可信。以事实性为重点的评估可以帮助你选择摘要模型，因为检索结果不会产生幻觉。对此类判断使用基于 rubric 的 judge，有助于理解偏好判断究竟基于流畅度和格式之类的标准，还是基于忠实性、上下文相关性等相关标准。用户可以忽略无关标准的分数，并根据其应用中关心的标准子集重新评估判断。

#### 创意批评者

在这个示例中，我们看向另一个方向：创意和原创性比忠实于现实事实或先前上下文更受青睐。设想一个用例：你使用 LLM 生成原创的短篇故事或脚本，但用户提供了几个过往脚本的示例来说明需求。从这些生成结果中挑选好的输出，要求生成的故事与示例有足够差异、有创意、原创，并且不直接借用现有训练数据。使用我们基于 rubric 的 judge 时，最终用户可以侧重原创性、连贯性和吸引力等标准，针对这一用例优化偏好判断。你还可以进一步查看标准分数的明确理由，以了解所期望的具体原创性和创意类型。

## 解决方案概述

本解决方案演示如何在 SageMaker AI 上使用基于 rubric 的 judge 能力评估生成式 AI 模型。你也可以评估人类生成的响应，但在本解决方案中，我们展示如何使用 Amazon Nova 作为基于 rubric 的 judge 来评估 Qwen 等其他 LLM 生成的响应。

首先，我们从 Stanford Question Answering Dataset（SQuAD）中采样问题，并由 Qwen2.5 1.5B Instruct 和 Qwen2.5 7B Instruct 生成候选响应，从而准备一个数据集。两个模型都通过 SageMaker 托管的 Hugging Face endpoint 访问。两个模型的响应保存在一个 JSONL 文件（`llm_judge.jsonl`）中，其中包含 prompt、`response_A`（来自 Qwen2.5 1.5B Instruct）和 `response_B`（来自 Qwen2.5 7B Instruct）。

接下来，JSONL 文件被上传到一个 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）存储桶。随后，一个 PyTorch Estimator 使用 Amazon Nova 基于 rubric 的 LLM-as-a-judge recipe 启动评估作业。judge 模型动态生成针对每个任务定制的评估 rubric 和标准，然后依据这些标准比较两个候选响应。该作业在 ml.g5.12xlarge 等 GPU 实例上运行，并产出评估指标，包括各标准得分、理由、比较评估、偏好计数和置信度度量。结果保存到 Amazon S3 以供分析。

最后，一个可视化函数渲染图表和表格，汇总生成的 rubric、各评估维度上的分数分布、两个 Qwen2.5 模型之间的性能对比，以及带理由的详细示例。通过这种端到端的方法，你可以评估哪个模型表现更好、找出具体的优势与劣势、跟踪改进，并就部署生成模型做出数据驱动的决策——全程无需人工标注。

## 准备数据集

为了创建用于比较 Qwen 模型的贴近真实的评估数据集，我们使用了 SQuAD——一个在自然语言理解领域被广泛采用的 benchmark，以 CC BY-SA 4.0 许可发布。SQuAD 由数千个众包问答对组成，覆盖多样化的 Wikipedia 文章。通过从该数据集采样，我们确保评估 prompt 反映高质量、事实性的问答任务，能代表真实世界应用。

我们首先加载一小部分示例，以保持工作流快速且可复现。具体来说，我们使用 Hugging Face 的 `datasets` 库下载并加载 SQuAD 训练集中的前 20 个示例：

```
from datasets import load_dataset
squad = load_dataset("squad", split="train[:20]")
```

该命令检索完整数据集的一个切片，包含 20 个条目，其结构化字段包括 context、question 和 answers。为验证内容并查看一个示例，我们打印了一个示例问题及其 ground truth 答案：

```
print(squad[3]["question"])
print(squad[3]["answers"]["text"][0])
```

对于评估集，我们从这个子集中选取了前六个问题：`questions = [squad[i]["question"] for i in range(6)]`

## 生成评估数据集

在从 SQuAD 准备好一组评估问题之后，我们由两个 Qwen2.5 模型生成输出，并把它们组装成结构化数据集，供 Amazon Nova 基于 rubric 的 LLM-as-a-judge 工作流使用。该数据集是 SageMaker AI 评估 recipe 的核心输入。为此，我们遍历每个问题 prompt，并对两个 SageMaker endpoint 调用生成函数：

- `generate_response("qwen25-15b-instruct-endpoint", q)` 用于获取 Qwen2.5 1.5B Instruct 模型的补全
- `generate_response("qwen25-7b-instruct-endpoint", q)` 用于获取 Qwen2.5 7B Instruct 模型的补全

对于每个 prompt，工作流都会尝试从每个模型生成一个响应。以下代码调用 Qwen 2.5 模型的两个不同版本。这让 LLM judge 之后可以判断更大的模型是否提供了显著更好的准确性，还是较小的模型就足以完成任务。

```
# Define the output file path for the LLM judge dataset

output_path = "llm_judge.jsonl"

with open(output_path, "w") as f:
    for q in questions:
        try:
# Generate response from Model A (1.5B parameter model)
            response_a = generate_response("qwen25-15b-instruct-endpoint", q)
        except Exception as e:
# Fallback error message if the API call fails
            response_a = f"[Qwen2.5 generation failed: {e}]"
        try:
# Generate response from Model B (7B parameter model)
            response_b = generate_response("qwen25-7b-instruct-endpoint", q)
        except Exception as e:
# Fallback error message if the API call fails
            response_b = f"[ qwen25-7b generation failed: {e}]"
# Construct a dictionary containing the prompt and both model responses
        row = {
            "prompt": q,
            "response_A": response_a,
            "response_B": response_b
        }
        f.write(json.dumps(row) + "\n")
# Write the record to the JSONL file as a single line

print(f"JSONL file created at: {output_path}")
```

该工作流生成了一个名为 `llm_judge.jsonl` 的 JSON Lines 文件。每一行包含一条评估记录，结构如下：

```
{
  "prompt": "What is the capital of France?",
  "response_A": "The capital of France is Paris.",
  "response_B": "Paris is the capital city of France."
}
```

然后，我们把 `llm_judge.jsonl` 上传到一个 S3 存储桶：

```
upload_to_s3(
    "llm_judge.jsonl",
    "s3://<YOUR_BUCKET_NAME>/datasets/byo-datasets-dev/custom-llm-judge/llm_judge.jsonl"
)
```

## 启动 Amazon Nova 基于 rubric 的 LLM-as-a-judge 评估作业

准备好数据集并创建评估 recipe 之后，最后一步是启动执行 Amazon Nova 基于 rubric 的 LLM-as-a-judge 评估的 SageMaker 训练作业。在此工作流中，训练作业充当一个完全托管、自包含的进程：它加载 judge 模型、处理比较数据集、应用动态生成的 rubric，并在你指定的 Amazon S3 位置生成全面的评估指标。我们使用 SageMaker Python SDK 中的 PyTorch estimator 类来封装评估运行的配置。该 estimator 定义了计算资源、容器镜像、评估 recipe 以及用于存储结果的输出路径：

```
estimator = PyTorch(
    output_path=output_s3_uri,
    base_job_name=job_name,
    role=role,
    instance_type=instance_type,
    training_recipe=recipe_path,
    sagemaker_session=sagemaker_session,
    image_uri=image_uri,
    disable_profiler=True,
    debugger_hook_config=False,
)
```

配置好 estimator 后，你使用 `fit()` 方法启动评估作业。该调用把作业提交到 SageMaker 控制平面、预置计算集群（ml.g5.12xlarge 实例），并开始处理你的评估数据集：

`estimator.fit(inputs={"train": evalInput})` 该作业将执行基于 rubric 的比较，由 Amazon Nova judge 模型动态生成评估标准并为两个 Qwen2.5 模型的输出打分。结果（包括各标准得分、理由和比较评估）会自动保存到你指定的 S3 输出路径，供下游分析和可视化使用。

## 结论

大规模评估生成式 AI 输出所需的不仅仅是简单的偏好标签，还需要透明地了解某个响应为何优于另一个。Amazon Nova 基于 rubric 的 LLM judge 通过动态生成任务特定的评估标准、提供带明确理由的各标准得分，并给出校准良好的置信度信号来满足这一需求。与之前的 judge 实现相比，基于 rubric 的方法提供三项关键优势：通过带标准级细分的结构化 YAML 输出实现可解释性；灵活性，让用户可针对其具体用例重新加权或过滤标准；以及更高的准确性，在标准 benchmark 上取得显著提升——包括在 JudgeBench 的复杂评估场景上提升 49%。如果你在开发过程中选择模型 checkpoint、为质量过滤训练数据，或在大规模上调试生产模型行为，Amazon Nova 基于 rubric 的 LLM-as-a-judge 评估能把不透明的偏好决定转化为可付诸行动的洞察。通过揭示每个判断背后的推理，团队可以识别系统性弱点、验证评估与其质量优先事项一致，并对自动化评估 pipeline 建立更大的信任。

要在 SageMaker AI 上开始使用 Amazon Nova 基于 rubric 的 LLM judge，请参阅[基于 rubric 的 Judge](https://docs.aws.amazon.com/sagemaker/latest/dg/nova-rubric-judge-evaluation.html)。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/28/IMG_3756-100x120.jpg)**Joseph Moulton** 是 Amazon AGI Customization 团队的软件工程师，支持 AWS Nova Forge 的评估和推理工作流的实现。目前的工作重点是为客户开发和实施评估其自定义训练的 Nova 模型的新策略。他在公司担任软件工程师已有 4 年，2022 年加入 Alexa AI Machine Learning 平台团队，2025 年转入 Nova Forge 团队。业余时间他喜欢打高尔夫和组装电脑。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/28/badgephotos.corp_.amazon2-100x133.jpg)**Morteza Ziyadi** 是 Amazon AGI 的资深科学负责人兼经理，在那里他领导 Amazon AGI Foundation 建模团队中多个关于后训练 recipe 和（多模态）大语言模型的项目。加入 Amazon AGI 之前，他在 Microsoft Cloud and AI 工作了四年，领导专注于为各种产品开发自然语言到代码生成模型的项目。他还曾担任 Northeastern University 的兼职教师。他于 2017 年在 University of Southern California（USC）获得博士学位，此后积极参与众多 NLP、计算机视觉和机器学习会议，担任工作坊组织者和审稿人。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/28/rajkumar_pujari-100x100.png)**Rajkumar Pujari** 是 Amazon AGI Nova Models 后训练团队的应用科学家 II。他在 Purdue University 获得计算机科学博士学位，专攻面向计算社会科学的机器学习。目前，他的工作重点是大型语言模型的后训练和强化学习。他为前沿模型开发大规模、动态的评估 pipeline，并构建 LLM-as-a-Judge 框架。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/29/image-6-7-100x100.png)**Swastik Roy** 是 Amazon AGI Foundation 团队的资深应用科学家，专攻泛化性研究以及 Amazon Nova 系列模型的后训练。他的专长涵盖微调、强化学习和评估方法，在这里他推动提升基础 AI 系统稳健性的工作。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/16/joel-100x133.jpeg)**Joel Catapano** 是 Amazon AGI foundation modeling 团队的资深应用科学家。他主要致力于开发提升 Nova 系列模型 LLM-as-a-Judge 能力的新方法。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/04/28/headshot-mona-100x100.jpg)**Mona Mona** 是 Amazon SageMaker AI 团队的高级全球生成式 AI 专家解决方案架构师，专注于生成式 AI 解决方案。加入 Amazon 之前，她是 Google 的生成式 AI 首席专家。她出版了两本书——《Natural Language Processing with AWS AI Services》和《Google Cloud Certified Professional Machine Learning Study Guide》。她撰写了 20 多篇关于 AI/ML 和云技术的博客，并是一篇关于 CORD19 Neural Search 的研究论文的合著者，该论文在著名的 AAAI（Association for the Advancement of Artificial Intelligence）会议上获得最佳研究论文奖。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/16/natarap.png)**Pradeep Natarajan** 是 Amazon AGI Foundation 建模团队的资深首席科学家，从事后训练 recipe 和多模态大语言模型的工作。他在开发和发布多个大规模机器学习系统方面拥有 20 多年经验。他拥有 University of Southern California 的计算机科学博士学位。
