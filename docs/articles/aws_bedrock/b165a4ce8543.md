# 借助 Amazon Bedrock 面向 Anthropic Claude Sonnet 4.5 的全新全球跨区域推理，释放全球 AI 推理的可扩展能力

***2026 年 10 月：本文已复核并更新，以确保内容准确。***

*本文由 Anthropic 的 Gareth Jones 共同撰写。*

各组织越来越多地将生成式 AI 能力集成到应用中，以改善客户体验、简化运营并推动创新。随着生成式 AI 工作负载持续增长，组织在保持 AI 驱动应用的稳定性能方面面临新的挑战。客户希望跨多个 AWS 区域扩展其 AI 推理工作负载，以支撑一致的性能。

为满足这一需求，我们推出了[面向 Amazon Bedrock 的跨区域推理（CRIS）](https://aws.amazon.com/blogs/machine-learning/getting-started-with-cross-region-inference-in-amazon-bedrock/)。这项托管能力会自动将推理请求路由到一组区域，使开发者能够访问更广泛的基础模型（FM）。CRIS 通过[推理配置文件](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles.html)工作，后者定义基础模型以及请求可被路由到的区域。

我们很高兴宣布，[Amazon Bedrock](https://aws.amazon.com/bedrock/) 上面向 Anthropic Claude Sonnet 4.5 的全球跨区域推理现已可用。现在，借助跨区域推理，你可以选择特定地理范围的推理配置文件，也可以选择全球推理配置文件。从特定地理路由演进到这一步，为组织提供了更大的灵活性。全球 CRIS 通过将推理请求路由到全球受支持的商业区域，进一步增强了跨区域推理。此外，全球 CRIS 还支持 Amazon Bedrock 的关键功能，包括 [prompt caching](https://aws.amazon.com/bedrock/prompt-caching/)、[批量推理](https://docs.aws.amazon.com/bedrock/latest/userguide/batch-inference.html)、[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/)、[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)、[以及更多](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html#cross-region-inference-use)。

在本博文中，我们将探讨全球跨区域推理如何工作、相比区域级推理配置文件它具有哪些优势，以及如何借助 Anthropic Claude Sonnet 4.5 在你自己的应用中实施它。

## 全球跨区域推理的核心功能

全球跨区域推理通过使用不同区域的计算资源，帮助组织应对计划外的流量突发。本节将探讨该功能如何工作，以及支撑其能力的技术机制。

### 理解推理配置文件

Amazon Bedrock 中的[推理配置文件](https://docs.aws.amazon.com/en_us/bedrock/latest/userguide/inference-profiles.html)定义了一个基础模型以及一个或多个可路由模型调用请求的区域。[面向 Anthropic Claude Sonnet 4.5 的全球跨区域推理配置文件](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)将这一概念扩展到地理边界之外，把请求路由到全球受支持的 Amazon Bedrock 商业区域之一，因此你可以通过将流量分散到多个区域来为计划外的流量突发做准备。

推理配置文件基于两个关键概念运作：

- **源区域（Source Region）**：发起 API 请求的区域。
- **目标区域（Destination Region）**：Amazon Bedrock 可将请求路由到该区域进行推理。

在撰写本文时，全球 CRIS 支持[20 多个源区域，目标区域由 Amazon Bedrock 动态选择一个受支持的商业区域](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)。

### 监控与日志

使用全球跨区域推理时，[Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 和 [AWS CloudTrail](https://aws.amazon.com/cloudtrail) 仍然只在请求发起的源区域记录日志条目。由于无论推理请求最终在何处处理，所有记录都保留在单一区域，这简化了监控与日志。要跟踪是哪个区域处理了请求，CloudTrail 事件会包含一个 `additionalEventData` 字段，其中 `inferenceRegion` 键指定了目标区域。组织可以监控并分析其推理请求在 AWS 全球基础设施上的分布。

### 数据安全与合规

全球跨区域推理维持高标准的数据安全性。跨区域推理过程中传输的数据[经过加密，并保留在安全的 AWS 网络内](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)。无论由哪个区域处理请求，敏感信息在整个推理过程中都受到保护。由于安全与合规是共同责任，你还必须考虑在不同地理位置处理推理请求所带来的法律或合规要求。由于全球跨区域推理允许请求在全球范围内路由，具有特定数据驻留或合规要求的组织可以根据自身合规需要，选择使用特定地理范围的推理配置文件，以确保数据保留在特定区域内。这种灵活性帮助企业根据自身具体需求，在冗余性与合规性之间取得平衡。

## 实施全球跨区域推理

要使用 Anthropic Claude Sonnet 4.5 的全球跨区域推理，开发者必须完成以下关键步骤：

- **使用全球推理配置文件 ID**：调用 Amazon Bedrock 的 API 时，指定全球 Anthropic Claude Sonnet 4.5 推理配置文件 ID（`global.anthropic.claude-sonnet-4-5-20250929-v1:0`），而不是区域特定的模型 ID。这同时适用于 `InvokeModel` 和 `Converse` API。
- **配置 IAM 权限**：授予适当的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）权限，以访问推理配置文件以及潜在目标区域中的基础模型。下一节将提供更多细节。你也可以进一步阅读[推理配置文件的前置条件](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-prereq.html)。

使用 Anthropic Claude Sonnet 4.5 实施全球跨区域推理，只需对你现有的应用代码做少量改动。以下是在 Python 中更新代码的示例：

```
import boto3
import json
bedrock = boto3.client('bedrock-runtime', region_name='us-east-1')

# KEY CHANGE: Use global inference profile instead of direct model or GEO CRIS inference profile
model_id = "global.anthropic.claude-sonnet-4-5-20250929-v1:0"  # Global CRIS
# GEO CRIS: "us.anthropic.claude-sonnet-4-5-20250929-v1:0"        #GEO CRIS

# Make request - automatically routes to optimal AWS Region globally
response = bedrock.converse(
    messages=[{"role": "user", "content": [{"text": "Explain cloud computing in 2 sentences."}]}],
    modelId=model_id,
)


print("Response:", response['output']['message']['content'][0]['text'])
print("Token usage:", response['usage']) 
print("Total tokens:", response['usage']['totalTokens'])
```

如果你使用的是 Amazon Bedrock 的 [InvokeModel API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_InvokeModel.html)，可以通过更改模型 ID 快速切换到其他模型，如[调用模型的代码示例](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-invoke.html#inference-example-invoke)所示。

## 全球 CRIS 的 IAM 策略要求

本节讨论全球 CRIS 的 IAM 策略要求。

### 启用全球 CRIS

要为你的用户启用全球 CRIS，你必须对该角色应用一份由三部分组成的 IAM 策略。以下是一份示例 IAM 策略，用于提供细粒度控制。你可以将示例策略中的 `<REQUESTING REGION>` 替换为你运营所在的区域。

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "GrantGlobalCrisInferenceProfileRegionAccess",
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:<REQUESTING REGION>:<ACCOUNT>:inference-profile/global.<MODEL NAME>"
            ],
            "Condition": {
                "StringEquals": {
                    "aws:RequestedRegion": "<REQUESTING REGION>"
                }
            }
        },
        {
            "Sid": "GrantGlobalCrisInferenceProfileInRegionModelAccess",
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:<REQUESTING REGION>::foundation-model/<MODEL NAME>"
            ],
            "Condition": {
                "StringEquals": {
                    "aws:RequestedRegion": "<REQUESTING REGION>",
                    "bedrock:InferenceProfileArn": "arn:aws:bedrock:<REQUESTING REGION>:<ACCOUNT>:inference-profile/global.<MODEL NAME>"
                }
            }
        },
        {
            "Sid": "GrantGlobalCrisInferenceProfileGlobalModelAccess",
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:::foundation-model/<MODEL NAME>"
            ],
            "Condition": {
                "StringEquals": {
                    "aws:RequestedRegion": "unspecified",
                    "bedrock:InferenceProfileArn": "arn:aws:bedrock:<REQUESTING REGION>:<ACCOUNT>:inference-profile/global.<MODEL NAME>"
                }
            }
        }
    ]
}
```

策略的第一部分授予对请求区域内区域级推理配置文件的访问权限。该策略允许用户从其请求区域调用指定的全球 CRIS 推理配置文件。策略的第二部分提供对区域级基础模型资源的访问权限，这是服务在区域上下文中理解请求的是哪个模型所必需的。策略的第三部分授予对全球基础模型资源的访问权限，从而启用使全球 CRIS 得以运行的跨区域路由能力。实施这些策略时，请确保三个资源 Amazon Resource Name（ARN）都包含在你的 IAM 语句中：

- 区域级推理配置文件的 ARN 遵循 `arn:aws:bedrock:REGION:ACCOUNT:inference-profile/global.MODEL-NAME` 模式。它用于授予对源区域中全球推理配置文件的访问权限。
- 区域级基础模型使用 `arn:aws:bedrock:REGION::foundation-model/MODEL-NAME`。它用于授予对源区域中基础模型的访问权限。
- 全球基础模型需要使用 `arn:aws:bedrock:::foundation-model/MODEL-NAME`。它用于授予对不同全球区域中基础模型的访问权限。

全球基础模型 ARN 未指定区域或账户，这是有意为之，也是跨区域功能所必需的。

如果你的组织使用区域特定的服务控制策略（SCP），请确保 `"aws:RequestedRegion": "unspecified"` 不在拒绝区域列表中，因为全球 CRIS 请求会使用该区域值。使用限制性 SCP（除特定获批区域外拒绝所有区域）的组织，需要在其 SCP 中显式允许 `"aws:RequestedRegion": "unspecified"` 才能启用全球 CRIS 功能。不过，如果你有数据驻留要求，在实施全球 CRIS 之前应仔细评估你的用例，因为请求可能会在任何受支持的商业区域中被处理。

### 禁用全球 CRIS

你可以从两种主要方法中选择一种，为特定 IAM 角色实施针对全球 CRIS 的拒绝策略，两者各有不同的用例和影响：

- **移除 IAM 策略**：第一种方法是从用户权限中移除三项必需 IAM 策略中的一项或多项。由于全球 CRIS 需要三项策略齐备才能工作，移除其中一项就会导致访问被拒。
- **实施拒绝策略**：第二种方法是实施一项显式拒绝策略，专门针对全球 CRIS 推理配置文件。这种方式能清晰记录你的安全意图，并确保即使日后有人误加了所需的允许策略，显式拒绝也会优先生效。拒绝策略应使用 `StringEquals` 条件，匹配模式 `"aws:RequestedRegion": "unspecified"`。该模式专门针对带有 `global` 前缀的推理配置文件。

实施拒绝策略时，需要理解全球 CRIS 改变了 `aws:RequestedRegion` 字段的行为。使用 `StringEquals` 条件并指定具体区域名称（如 `"aws:RequestedRegion": "us-west-2"`）的传统基于区域的拒绝策略，在全球 CRIS 下不会按预期生效，因为服务会把该字段设为 `global` 而不是实际的目标区域。不过，如前所述，`"aws:RequestedRegion": "unspecified"` 会产生拒绝效果。

**注意**：如果你的组织使用区域特定的服务控制策略（SCP），请确保 `"aws:RequestedRegion": "unspecified"` 不在拒绝区域列表中，因为全球 CRIS 请求会使用该区域值。使用限制性 SCP（除特定获批区域外拒绝所有区域）的组织，需要在其 SCP 中显式允许 `"aws:RequestedRegion": "unspecified"` 才能启用全球 CRIS 功能。不过，如果你有数据驻留要求，在实施全球 CRIS 之前应仔细评估你的用例，因为请求可能会在任何受支持的商业区域中被处理。

## 为 Anthropic Claude Sonnet 4.5 的全球 CRIS 申请提高请求限额

使用全球 CRIS 推理配置文件时，你可以从 20 多个受支持的源区域使用全球 CRIS。由于这将是全球限额，查看、管理或提高全球跨区域推理配置文件配额的请求，必须在所请求的源区域通过 [Service Quotas 控制台](https://console.aws.amazon.com/servicequotas/) 或 [AWS Command Line Interface](https://aws.amazon.com/cli)（AWS CLI）发起。

完成以下步骤以申请提高限额：

- 登录到你的 AWS 账户中的 Service Quotas 控制台。

![显示 AWS 服务列表的 Service Quotas 控制台](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/23/REVBLOG-1365-1.jpg)

图 1：Service Quotas 控制台

- 在导航窗格中，选择 **AWS services**。
- 在服务列表中找到并选择 **Amazon Bedrock**。
- 在 Amazon Bedrock 的配额列表中，使用搜索过滤器找到具体的全球 CRIS 配额。例如：Global cross-Region model inference tokens per minute for Anthropic Claude Sonnet 4.5 V1。
- 选择你要提高的配额。
- 选择 **Request increase at account level**。

![带有按账户级申请提高选项的 Amazon Bedrock 配额详情页面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/23/REVBLOG-1365-2.jpg)

图 2：在账户级申请配额提升

- 输入你想要的新配额值。
- 选择 **Request** 提交你的请求。

在计算所需的配额提升时，请记得考虑[消耗速率（burndown rate）](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-token-burndown.html)，它定义为输入和输出 token 被换算为限流系统所用 token 配额消耗的比率。以下模型对输出 token 具有 **5 倍消耗速率（1 个输出 token 消耗你配额中的 5 个 token）：**

- Anthropic Claude Opus 4。
- Anthropic Claude Sonnet 4.5。
- Anthropic Claude Sonnet 4。
- Anthropic Claude 3.7 Sonnet。

对于所有其他模型，消耗速率为 **1:1**（1 个输出 token 消耗你配额中的 1 个 token）。对于输入 token，token 与配额的比例为 1:1。每次请求的总 token 数计算方式如下：

`Input token count + Cache write input tokens + (Output token count x Burndown rate)`

## 使用 Anthropic Claude Sonnet 4.5 的全球跨区域推理

Claude Sonnet 4.5 是 Anthropic 最智能的模型（在撰写本文时），最适合编码和复杂 agent 场景。Anthropic Claude Sonnet 4.5 在 agent 能力方面展现了进步，在工具处理、记忆管理和上下文处理上的表现都有增强。该模型在代码生成与分析方面有明显提升，包括识别最优改进点，以及在重构决策中运用更强的判断力。它尤其擅长自主的长程编码任务，能够有效规划和执行历时数小时甚至数天的复杂软件项目，并在整个开发周期中保持一致的性能与可靠性。

面向 Anthropic Claude Sonnet 4.5 的全球跨区域推理相比传统的地理跨区域推理配置文件带来多重优势：

- **成本效率**：与地理跨区域推理相比，面向 Anthropic Claude Sonnet 4.5 的全球跨区域推理[在输入和输出 token 定价上均可节省约 10%](https://aws.amazon.com/bedrock/pricing/)。价格按发起请求的区域（源区域）计算。这意味着组织可以在更低的成本下获得更好的韧性。这种定价模式使全球跨区域推理成为希望优化其生成式 AI 部署的组织的经济高效方案。通过提升资源利用率并在不增加成本的情况下支持更高吞吐，它帮助组织从对 Amazon Bedrock 的投资中获得最大价值。
- **简化的监控**：使用全球跨区域推理时，CloudWatch 和 CloudTrail 仍会在你的源区域记录日志条目，简化了可观测性和管理。即使你的请求在全球不同区域处理，你仍可以通过熟悉的 AWS 监控工具，对应用性能和用量模式保持集中视图。
- **按需配额的灵活性**：借助全球跨区域推理，你的工作负载不再受单个区域容量限制。你的请求可以跨 AWS 全球基础设施路由，而不再被限制在特定区域可用的容量内。这让你能访问大得多的资源池，处理高流量工作负载也就不再那么复杂。

如果你目前正在 Amazon Bedrock 上使用 Anthropic 的 Sonnet 模型，升级到 Claude Sonnet 4.5 是增强 AI 能力的好机会。它在智能和能力上有显著跃升，且可作为直接替换方案、以与 Sonnet 4 相当的价格点提供。切换的主要原因是 Sonnet 4.5 在关键的高价值领域表现更优。它是 Anthropic 迄今为止构建复杂 agent 最强大的模型，在[编码](https://www.anthropic.com/news/claude-sonnet-4-5)、推理和计算机使用方面展现出最先进的性能。此外，其先进的 agent 能力，例如更长时间的自主运行和更有效地使用并行工具调用，使构建更复杂的 AI 工作流成为可能。
