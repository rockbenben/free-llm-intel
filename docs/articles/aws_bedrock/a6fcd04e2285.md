# 在 Amazon Bedrock 上推出 Kimi K3

开放权重模型正在改变大规模构建和部署 AI 的经济账。智能与效率的快速提升，意味着企业可以为每种工作负载匹配能力、速度与成本之间的恰当平衡。AWS 正在为一个未来而建设：组织能够采纳开放权重的创新，同时具备生产环境所要求的可靠性与安全性。

今天，[来自 Moonshot AI 的 Kimi K3](https://www.kimi.ai/blog/kimi-k3) 已在 Amazon Bedrock 上可用，为你在编码和知识工作方面提供了一个强大的新选择。据 Moonshot AI 介绍，Kimi K3 是其能力最强的模型，也是首个参数量达到 2.8 万亿的开放模型。它将原生视觉能力与 100 万 token 的上下文窗口结合在一起，相比 Kimi K2 在扩展效率上带来约 [2.5 倍的提升](https://www.kimi.com/blog/kimi-k3)。这些进步使 Kimi K3 非常适合长时间运行的编码与知识工作流，这类工作流需要在大规模代码仓库、文档和图像之间保持持续的上下文。Kimi K3 是 Amazon Bedrock 上首个支持[显式 prompt caching](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html) 的开放权重模型，可帮助你在多次模型调用之间复用上下文时降低延迟和输入成本。

Kimi K3 的发布反映了 AWS 对 Amazon Bedrock 上开放权重模型的持续投入。自 2025 年以来，Bedrock 已新增来自 DeepSeek、Google、MiniMax、Mistral AI、Moonshot AI、NVIDIA、OpenAI 和 Qwen 等提供方的数十个开放权重模型。支撑这一不断扩大的模型选择的，是用于大规模服务这些模型的推理技术的持续进步。2026 年，Bedrock 新增了对工具调用、结构化输出、推理、响应流式传输，以及 Responses 和 Chat Completions API 的支持。由于这些是平台级能力而非针对单个模型的集成，新的开放权重模型在上线 Amazon Bedrock 后即可直接受益。

与 Amazon Bedrock 上的所有开放权重模型一样，你可以采纳 Kimi K3 而无需改变安全姿态。你的数据在 AWS 数据边界内处理，不会与模型提供方共享，也不会用于训练底层模型。推理请求始终启用零数据保留，而零操作员访问可防止即便是 AWS 的操作人员在推理过程中访问你的 prompt 和补全结果。这些保护措施共同让你能够放心使用开放权重模型，同时保持对数据的控制。

## 开始使用 Amazon Bedrock 上的 Kimi K3

要试用 Kimi K3，请打开 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock/)，前往 **Test > Playground**，然后选择 Kimi K3 作为模型。在那里，你可以测试你的第一个 prompt。

在编程层面，你可以通过 `bedrock-runtime` 端点调用该模型，该端点支持兼容 OpenAI 的 [Responses](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html) 和 [Chat Completions](https://docs.aws.amazon.com/bedrock/latest/userguide/bedrock-mantle.html#bedrock-mantle-responses) API，以及 Amazon Bedrock [Invoke](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html) 和 [Converse API](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html)。

你可以通过跨区域推理配置文件调用 Kimi K3。对于没有区域限制的工作负载，我们建议使用全球配置文件 `global.moonshotai.kimi-k3`，它会把每个请求路由到全球范围内任意受支持的商业 AWS 区域。全球跨区域推理的成本比地理配置文件低约 10%。美国地理配置文件 `us.moonshotai.kimi-k3` 会将处理限制在美国地理范围内，以满足数据驻留要求。

### 先决条件

- 一个已激活且可访问 Amazon Bedrock 的 AWS 账户。
- Python 3.10+。
- 调用该模型所需的 AWS Identity and Access Management（AWS IAM）权限：`bedrock:InvokeModel`、`bedrock:InvokeModelWithResponseStream` 和 `bedrock:CallWithBearerToken`。

下面是一个快速示例，使用 [OpenAI SDK](https://pypi.org/project/openai/) 和 [aws-bedrock-token-generator](https://pypi.org/project/aws-bedrock-token-generator/) Python 库生成短期 bearer token，用于向 Amazon Bedrock 进行身份验证。
```
from aws_bedrock_token_generator import provide_token
from openai import OpenAI

region = "us-west-2"
oai_client = OpenAI(
    api_key=provide_token(region=region),
    base_url=f"https://bedrock-runtime.{region}.amazonaws.com/openai/v1",
)

resp = oai_client.responses.create(
    input="What is Byte-Pair Encoding, in AI?",
    model="global.moonshotai.kimi-k3",
)
print(resp.output_text)
```
## 通过显式 prompt caching 优化推理

长时间运行的编码与知识工作流经常会重复发送稳定的上下文，例如代码仓库说明、工具定义或参考文档。使用[显式 prompt caching](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)，你可以标识可复用的 prompt 前缀，使后续请求能够使用缓存内容。当请求与缓存前缀匹配时，Amazon Bedrock 可以降低响应延迟和输入 token 成本。

Kimi K3 在 Amazon Bedrock 上的缓存机制：

- 你可以通过在受支持的输入内容中添加 `prompt_cache_breakpoint`，标记可复用 prompt 前缀的确切结束位置（至少 1,024 个 token 之后）。
- 在显式模式下，写入缓存的 token 按更高的费率计费，但随后会在缓存中保留至少 30 分钟。
- 对于命中缓存的后续匹配请求，输入 token 将按折扣费率计费，并且不计入每分钟输入 token 配额。

使用 OpenAI Python API 时，可按以下示例配置显式缓存：
```
resp = oai_client.responses.create(
    model="global.moonshotai.kimi-k3",
    # Enable explicit caching mode:
    extra_body={"prompt_cache_options": {"mode": "explicit"}},
    input=[
        {
            "type": "message",
            "role": "system",
            "content": [
                {
                    "type": "input_text",
                    "text": SYSTEM_PROMPT,
                    # A long, static system prompt is a great target for caching:
                    "prompt_cache_breakpoint": {"mode": "explicit"},
                },
            ]
        },
        {
            "type": "message",
            "role": "user",
            "content": [
                {
                    "type": "input_text",
                    "text": USER_INPUT,
                    # Multiple breakpoints can also be defined, for layered cache:
                    "prompt_cache_breakpoint": {"mode": "explicit"},
                },
            ],
        },
    ],
)
if resp.usage.input_tokens_details.cached_tokens:
    print("Hit cache!")
```
你可以浏览 [Moonshot AI on AWS 示例仓库](https://github.com/aws-samples/sample-moonshotai-on-aws)，了解更多示例。

## Kimi K3 的实践应用

除了直接使用这些 API，你还可以通过广泛支持 Amazon Bedrock（或一般而言兼容 OpenAI 的模型提供方）的各类编码助手、个人 agent 和 agent 框架来使用 Kimi K3。

### 编码助手

如今构建者可以选用多款流行的编码 agent，这里以 [OpenCode](https://opencode.ai/) 为例。OpenCode 是开源的、与模型无关的，并且内置了 [amazon-bedrock 模型提供方](https://opencode.ai/docs/providers/#amazon-bedrock)，它使用 Converse API。

要开始使用，你可以在用户级或项目级的 `opencode.json` 配置文件中配置 `amazon-bedrock` 提供方，[如 OpenCode 文档所示](https://opencode.ai/docs/providers/#amazon-bedrock)。配置好提供方后，OpenCode 会自动检测可用的 Amazon Bedrock 模型，你可以使用 `/models` 命令从中选择。例如，一个最小的 `~/.config/opencode.json` 文件可以如下所示：
```
{
    "$schema": "https://opencode.ai/config.json",
    "model": "amazon-bedrock/global.moonshotai.kimi-k3",
    "provider": {
        "amazon-bedrock": {
            "options": {
                "region": "us-west-2",
                "profile": "PLACEHOLDER-YOUR-AWS-PROFILE-NAME"
            }
        }
    }
}
```
一旦配置好 Amazon Bedrock 提供方，你就可以使用 `/models` 命令将模型切换为 `global.moonshotai.kimi-k3` 并开始构建。

### 生产力 agent

在编码之外，[Hermes Agent](https://hermes-agent.nousresearch.com/) 是面向通用生产力的一款开源助手示例。它可以通过桌面应用、流行的消息应用以及终端使用，并支持深度研究和任务自动化等用例，而在这些场景中 Kimi K3 同样表现出色。

[如其文档所述](https://hermes-agent.nousresearch.com/docs/guides/aws-bedrock#prerequisites)，Hermes 原生支持 Amazon Bedrock 上的模型。要开始使用：

- 在终端中运行 `hermes model`。
- 在提供方列表中向下滚动到「AWS Bedrock」（Hermes 将「Amazon Bedrock」错误标为「AWS Bedrock」）。
- 如果出现提示，选择你希望 Hermes 将请求发送到的源 AWS 区域。
- 选择默认凭证链（推荐）以使用环境中已配置好的 AWS Command Line Interface 凭证，或[生成 Amazon Bedrock API key](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-generate.html)。
- 从自动发现的模型列表中选择 Kimi K3；如果没有该模型，则输入 `global.moonshotai.kimi-k3` 作为自定义模型名称。

如果你使用[命名配置文件](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html#cli-configure-files-using-profiles)来管理环境中的多个 AWS 凭证，那么在撰写本文时，你需要为 Hermes 设置 `AWS_PROFILE` 环境变量，或使用你的默认配置文件。或者，你也可以改用 API key。关于通过 Hermes 配置文件设置 AWS profile 的支持进展，请关注[此处的 open issue](https://github.com/NousResearch/hermes-agent/issues/43143)。

可以在 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock)中试用 Kimi K3，或在 GitHub 上浏览 [Moonshot AI on AWS 示例仓库](https://github.com/aws-samples/sample-moonshotai-on-aws)。
