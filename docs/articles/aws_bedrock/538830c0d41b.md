# 用 Amazon Bedrock Guardrails 的多模态毒性检测守护时尚行业的伦理标准

据估算，2025 年全球时尚产业的价值达到 1.84 万亿美元，约占全球 GDP 的 1.63%（[Statista, 2025](https://www.statista.com/outlook/emo/fashion/worldwide)）。如此庞大的资本产出，也伴随着巨量的有毒内容与滥用风险。

在时尚行业，团队常常快速创新，并且往往借助 AI。分享内容——无论是视频、设计稿还是其他形式——都会带来内容审核的挑战。不当、冒犯或有毒的内容仍存在被产出和传播的风险（无论是有意还是无意）。这可能违反公司政策，并造成无法挽回的品牌声誉损害。在这个行业里一边利用 AI 加速创新、一边实施护栏，能带来持久的收益。

本文介绍如何使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 的[多模态毒性检测功能](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-mmfilter.html)来防范有毒内容。无论你是时尚行业的巨头企业，还是崭露头角的新品牌，都可以用这套方案在潜在有害内容影响品牌声誉与伦理标准之前将其筛出。就本文而言，伦理标准指的是时尚设计师可能创作出的有毒、不尊重他人或有害的文本与图像。

品牌声誉是一种超越流行趋势、无价的货币，企业争夺的不只是销量，还有消费者的信任与忠诚。随着技术演进，有效的声誉管理策略也应当包含以负责任的方式使用 AI。在这个创新不断增长的时代，随着时尚产业演进、创意人员更快地创新，那些在适应消费者偏好变化与全球趋势的同时战略性地管理自身声誉的品牌，将在行业中脱颖而出（[来源](https://shorturl.at/IOuXp)）。用 Amazon Bedrock Guardrails 迈出在创意实践中负责任地使用 AI 的第一步。

## 方案概览

要在基于 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的图像生成工作流中加入多模态毒性检测护栏，你可以使用以下 AWS 服务：

- [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3），用于存储时尚图像
- [Amazon S3 Event Notifications](https://docs.aws.amazon.com/AmazonS3/latest/userguide/EventNotifications.html)，在新图像上传时触发工作流处理
- [AWS Lambda](https://aws.amazon.com/lambda/)，用于处理图像
- Amazon Bedrock Guardrails，用于分析内容

以下步骤带你完成在基于 Amazon Bedrock 的图像生成工作流中加入多模态毒性检测护栏。

## 在 Amazon Bedrock 中创建多模态护栏

我们审核系统的基础，是在 Amazon Bedrock 中专门针对图像内容配置的护栏。要创建[多模态毒性检测护栏](https://aws.amazon.com/blogs/aws/amazon-bedrock-guardrails-now-supports-multimodal-toxicity-detection-with-image-support/)，请完成以下步骤：

- 在 Amazon Bedrock 控制台的导航窗格中，在 **Safeguards** 下选择 **Guardrails**。
- 选择 **Create guardrail**。
- 输入名称与可选描述，然后创建护栏。

## 为多种模态配置内容过滤器

接下来配置内容过滤器。请完成以下步骤：

- 在 **Configure content filters** 页面上，在 **Filter for prompts** 下选择 **Image**。这让护栏可以同时处理视觉内容与文本。
- 为 **Hate**、**Insults**、**Sexual** 与 **Violence** 这几类配置类别，以同时过滤文本与图像内容。**Misconduct** 与 **Prompt** 威胁类别仅可用于文本内容过滤。
- 创建过滤器。

通过设置这些过滤器，你建立起一套全面的防护措施，能够跨多种模态检测潜在有害内容，从而提升 AI 应用的安全性与可靠性。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/26/ML-18310-2.jpeg)

## 创建 S3 存储桶

你需要一个地方，让用户（或其他流程）上传需要审核的图像。要创建 S3 存储桶，请完成以下步骤：

- 在 Amazon S3 控制台的导航窗格中选择 **Buckets**。
- 选择 **Create bucket**。
- 输入唯一名称，并选择你希望存放该存储桶的 AWS 区域。
- 对于这个基础设置，标准配置通常已经足够。
- 创建存储桶。

工作流正是从这个存储桶开始——新图像落入这里就会触发下一步。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/26/ML-18310-3.jpg)

## 创建 Lambda 函数

我们使用一个用 Python 编写的 Lambda 函数（一种无服务器计算服务）。当新图像到达 S3 存储桶时，该函数会被调用。函数会把图像发送给我们在 Amazon Bedrock 中的护栏进行分析。请完成以下步骤来创建你的函数：

- 在 Lambda 控制台的导航窗格中选择 **Functions**。
- 选择 **Create function**。
- 输入名称，并选择一个较新的 Python 运行时。
- 使用 IAM 执行角色授予正确的权限。该函数需要从你的 S3 存储桶读取新上传对象的权限（`s3:GetObject`），以及针对你的特定护栏、使用 `bedrock:ApplyGuardrail` 动作与 Amazon Bedrock Guardrails 交互的权限。
- 创建你的护栏。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/26/ML-18310-4.jpg)

我们来看看支撑这个函数的 Python 代码。我们使用 [AWS SDK for Python (Boto3)](https://aws.amazon.com/sdk-for-python/) 与 Amazon S3 和 Amazon Bedrock 交互。代码首先从 S3 事件触发中识别出上传的图像。然后检查图像格式是否受支持（JPEG 或 PNG），并验证大小不超过护栏 4 MB 的限制。

关键步骤是为 `ApplyGuardrail` API 调用准备图像数据。我们把原始图像字节连同其格式打包成 Amazon Bedrock 能够理解的结构。我们使用 `ApplyGuardrail` API；这样做很高效，因为无需调用完整的基础模型就能按已配置的策略检查图像。

最后，函数调用 `ApplyGuardrail`，传入图像内容、护栏 ID 以及你之前记下的版本号。然后它解读来自 Amazon Bedrock 的响应，记录内容是 `BLOCKED` 还是 `NONE`（表示通过了检查），如果被拦截，还会记录检测到的具体有害类别。

下面是可作为起点的 Python 代码（记得替换占位符）：

```
import boto3
import json
import os
import traceback

s3_client = boto3.client('s3')
# Use 'bedrock-runtime' for ApplyGuardrail and InvokeModel
bedrock_runtime_client = boto3.client('bedrock-runtime')

GUARDRAIL_ID = '<YOUR_GUARDRAIL_ID>' 
GUARDRAIL_VERSION = '<SPECIFIC_VERSION>' #e.g, '1'

# Supported image formats by the Guardrail feature
SUPPORTED_FORMATS = {'jpg': 'jpeg', 'jpeg': 'jpeg', 'png': 'png'}

def lambda_handler(event, context):
    # Get bucket name and object key
    bucket = event['Records'][0]['s3']['bucket']['name']
    key = event['Records'][0]['s3']['object']['key']

    print(f"Processing s3://{bucket}/{key}")

    # Extract file extension and check if supported
    try:
        file_ext = os.path.splitext(key)[1].lower().lstrip('.')
        image_format = SUPPORTED_FORMATS.get(file_ext)
        if not image_format:
            print(f"Unsupported image format: {file_ext}. Skipping.")
            return {'statusCode': 400, 'body': 'Unsupported image format'}
    except Exception as e:
         print(f"Error determining file format for {key}: {e}")
         return {'statusCode': 500, 'body': 'Error determining file format'}


    try:
        # Get image bytes from S3
        response = s3_client.get_object(Bucket=bucket, Key=key)
        image_bytes = response['Body'].read()

        # Basic size check (Guardrail limit is 4MB)
        if len(image_bytes) > 4 * 1024 * 1024:
             print(f"Image size exceeds 4MB limit for {key}. Skipping.")
             return {'statusCode': 400, 'body': 'Image size exceeds 4MB limit'}

        # 3. Prepare content list for ApplyGuardrail API 
        content_to_assess = [
            {
                "image": {
                    "format": image_format, # 'jpeg' or 'png' 
                    "source": {
                        "bytes": image_bytes # Pass raw bytes 
                    }
                }
            }
        ]

        # Call ApplyGuardrail API 
        print(f"Calling ApplyGuardrail for {key} (Format: {image_format})")
        guardrail_response = bedrock_runtime_client.apply_guardrail(
            guardrailIdentifier=GUARDRAIL_ID,
            guardrailVersion=GUARDRAIL_VERSION,
            source='INPUT', # Assess as user input
            content=content_to_assess
        )

        # Process response
        print("Guardrail Assessment Response:", json.dumps(guardrail_response))

        action = guardrail_response.get('action')
        assessments = guardrail_response.get('assessments', [])
        outputs = guardrail_response.get('outputs', []) # Relevant if masking occurs

        print(f"Guardrail Action for {key}: {action}")

        if action == 'BLOCKED':
            print(f"Content BLOCKED. Assessments: {json.dumps(assessments)}")
            # Add specific handling for blocked content
        elif action == 'NONE':
             print("Content PASSED.")
             # Add handling for passed content
        else:
             # Handle other potential actions (e.g., content masked)
             print(f"Guardrail took action: {action}. Outputs: {json.dumps(outputs)}")


        return {
            'statusCode': 200,
            'body': json.dumps(f'Successfully processed {key}. Guardrail action: {action}')
        }

    except bedrock_runtime_client.exceptions.ValidationException as ve:
        print(f"Validation Error calling ApplyGuardrail for {key}: {ve}")
        # You might get this for exceeding size/dimension limits or other issues
        return {'statusCode': 400, 'body': f'Validation Error: {ve}'}
    except Exception as e:
        print(f"Error processing image {key}: {e}")
        # Log the full error for debugging
        traceback.print_exc()
        return {'statusCode': 500, 'body': f'Internal server error processing {key}'}
```

检查函数的默认执行超时时间（位于 **Configuration** 下的 **General configuration**），确认它有足够时间下载图像并等待 Amazon Bedrock API 响应，或许可以把它设为 30 秒。

## 为 Lambda 函数创建 Amazon S3 触发器

S3 存储桶已就绪、函数也写好了，现在需要把两者连接起来。这通过在 Lambda 函数上设置 Amazon S3 触发器来完成：

- 在该函数的配置页面上，选择 **Add trigger**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/02/ml-18310-5.jpg)

- 选择 S3 作为源。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/02/ml-18310-6.jpg)

- 将其指向你之前创建的 S3 存储桶。
- 把触发器配置为在 All object create events 时激活。这确保每当有新文件成功上传到 S3 存储桶，你的 Lambda 函数都会被自动调用。

## 清理资源

当你准备拆除所构建的审核 pipeline 时，必须清理已创建的资源，以避免不必要的费用。请完成以下步骤：

- 在 Amazon S3 控制台上，删除存储桶中触发 Lambda 函数的事件通知配置。
- 删除该存储桶。
- 在 Lambda 控制台上，删除你创建的审核函数。
- 在 IAM 控制台上，删除你为 Lambda 函数创建的执行角色。
- 如果你专门为该项目创建了护栏、且其他用途不需要它，请通过 Amazon Bedrock 控制台将其删除。

完成这些清理步骤后，你就成功移除了图像审核 pipeline 的各个组件。将来你可以按照本文列出的步骤重新创建这套方案——这也体现了基于云的无服务器架构的便捷之处。
