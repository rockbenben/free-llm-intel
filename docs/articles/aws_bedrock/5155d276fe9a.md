# 让人工智能走出演示并进入全球企业

*AWS 前向部署工程现已在美国、墨西哥、巴西、加拿大、澳大利亚、新加坡、印度、韩国、日本、英国、德国、荷兰、法国、瑞典和沙特阿拉伯等 15 个国家/地区为商业和公共部门客户提供服务；并由数十个内置的生产就绪加速器提供支持。*

我接触过的每家企业都利用人工智能构建了一些行之有效的东西。读取声明的原型。解决卡纠纷的代理人。在几秒钟内回答客户问题的模型。

原型可以工作。该演示给利益相关者留下了深刻的印象。然后组织尝试将其投入生产，真正的问题就开始了。生产数据比测试集更混乱。审计员想知道代理人做出每项决定的原因。数量从试点小组扩大到整个公司。事实证明，最重要的规则存在于人们的头脑中。

这些都不是模型问题。它们是商业问题，它们决定人工智能是否能带来回报。从演示到生产是最后一英里，大多数人工智能都在这一步停滞不前。这也是我们团队消磨时间的地方。

我们于 6 月份推出了 AWS 前向部署工程 (FDE)，以缩小这一差距。 Since then, we’ve worked through these problems with commercial and public sector customers in financial services, healthcare, sports, media, retail, and more.以下是我们学到的知识，以及它如何塑造我们的产品。

## 问题分为三层

模型提供商、云提供商和咨询公司都在将工程师嵌入到客户中。在 AWS FDE，我们通过工程师离开后剩下的东西来衡量成功：您的团队拥有的基础、不断学习的工作流程以及您可以信任的治理。

对于客户来说，最困难的问题出现在三个层面：基础、工作流程和治理。每一项都比看起来更难，而且每一项都建立在前一项的基础上。无论您是重新开始还是在现有系统上构建，这都适用。在绿地建设中，您可以快速行动，但还没有立足的基础。在棕地系统上，代理必须在数十年的数据、规则和集成范围内工作。

## 第一层：复合的基础

在代理能够大规模完成有用的工作之前，它需要一个基础：身份、安全、上下文、治理和操作控制。该基础必须从第一天起就可以投入生产，并由随后的每个用例共享。背景往往是最大的差距。大多数客户的数据分布在各个系统中，并且没有共同的本体论，即代理需要推理的业务运作方式的共享模型。

由于没有共享基础，第二个试点的成本几乎与第一个相同。整合被重建，经验教训未能继续下去。大多数组织都会停下来，首先构建基础，因此每个新用例都从上一个用例开始，而不是从头开始。我们称之为人工智能重置。

三星人寿保险公司有四家附属公司，每家都从头开始构建自己的人工智能点解决方案。在 45 天内，FDE 团队构建了一个受管理的代理平台，具有单一控制平面和内置合规性。新代理现在通过注册和策略分配而不是重建进行部署。

## 第二层：自动化工作流程

接下来是工作本身：大批量、规则繁重的流程，例如索赔处理、了解你的客户 (KYC) 审核、卡争议、贷款发放、发票核对、许可和客户服务。这就是人工智能可以提供即时且可衡量的成果的地方。回报很快，但驱动这些过程的知识很少存在于系统中。它与从事这项工作的人一起生活。

困难的部分不是自动化本身。它正在揭示每个决策背后的业务规则。当发票和采购订单不一致时，哪条记录胜出？什么时候异常可以自行清除，什么时候需要人？经验丰富的员工根据判断来回答这些问题，而这种判断很少被写下来。

有时知识隐藏在系统本身中。

力拓铁矿石公司 (Rio Tinto Iron Ore) 在拥有 30 年历史的 Oracle 系统上运行着世界上最复杂的从矿山到船舶的供应链之一。该系统拥有 5,000 多个数据库表和 140 个应用程序。绘制地图是一项持续数月的工作。 FDE 团队在几周内构建了映射它的代理，暴露了 Rio Tinto 团队可以验证和构建的依赖关系。

绘制现有的地图只是一个开始。当组织不再询问人工智能如何使现有工作更加高效，而是开始询问人工智能如何改变工作完成方式时，最大的机会就会出现。

## 第三层：随着一切变化而持续的治理

治理不是项目的一个阶段。它是架构的一部分。随着代理数量的增加，安全风险、成本和您必须解释的决策也会随之增加。每个代理都需要自己的身份、权限和审计跟踪，与人类身份分开。由于底层模型是概率性的，代理需要进行监控，以确保其结果在发布后很长时间内可预测和可审计。

当周围的一切发生变化时，系统还必须继续工作。模型发生变化、业务规则发生变化、数据格式发生变化、法规收紧。新的安全问题出现，代码也过时了。随着新型号的到来，它们周围的说明和工具也会发生变化。您需要评估和护栏，使座席能够在必须做到的地方保持可预测性，在能够做到的地方保持创造性。

当治理到最后时，它就成为停止生产的大门。从第一天起就内置它，它可以让您的业务快速发展。

达信是一家全球领先的专业服务公司，需要能够遵守其自身审计标准的代理商。 FDE 团队从一开始就构建了这些控件，第一个用例在工作开始大约两个月后投入生产。目标区域的效率提升高达 70%，一些流程步骤从几小时缩短到几秒钟。此后，马什扩大了工作范围，并不断扩展系统本身。

## 我们如何解决这个问题：速度、规模和控制

我们的观点来自于我们自己构建和运行这些系统。 AWS FDE 将一个由 AWS 工程师、科学家和产品经理组成的小团队与您的工程师和专业 AI 代理团队配对。我们的许多 FDE 来自构建 Amazon Bedrock、Amazon Bedrock AgentCore、Kiro、AWS Quick 和 AWS Security Hub 的服务团队。他们构建并运行了 AWS 规模的 AI 产品，并将这些工程实践引入您的环境中。我们的团队将共同在 45 天的冲刺时间内，在您自己的 AWS 账户中将高价值的业务问题投入生产。客户不需要在速度、规模和控制之间进行选择。 FDE 旨在实现这三个目标。

**速度 –** 您可能会带着一个广泛的目标或一个模糊的问题来找我们。我们与您的业务利益相关者一起完善它，然后从第一天开始就在您的环境中基于您的数据并通过您的身份和安全控制进行构建。我们与从事这项工作的人员一起在短周期内进行建设。每个周期都会将真实的案例摆在他们面前，不成文的规则随着他们的反应而浮现出来。我们在生活环境中捕捉这些规则，因此系统在我们退后一步后会继续学习。原型和生产之间没有任何内容被重建。您可以在整个过程中看到工作演示，评估可以根据您关心的结果跟踪进度，并且您可以在一个季度或更短的时间内拥有一个生产系统。

**规模 –** 单点解决方案可以在一个用例上快速发展，但不会为接下来的五个用例留下基础。每个 FDE 团队都以相同的方式工作，使用人工智能驱动的开发生命周期 (AI-DLC)，我们自己的服务团队使用该方法将广泛的问题转化为工作成果。我们部署了一个固执己见的 AWS 堆栈，它反映了我们在构建适合您的环境的 AI 服务方面所学到的知识：您的业务如何运作的实时环境、您的工程师和代理人员构建的工作台、Amazon Bedrock AgentCore 上的运行时以及用于治理、结果、成本和代理性能的控制塔。用于常见任务（例如文档处理和客户情绪分析）的加速器可以处理标准部分，因此每个新工作负载都可以专注于您的业务的特定内容。固执己见的 AWS 堆栈、上下文和控件从一个用例延伸到下一个用例。

您的环境使扩展成为可能。假设您的第一个用例是销售自动化工作流程。由于其上下文位于您的 AWS 账户中，因此下一个用例（供应链优化）将在此基础上构建，而不是重新开始。您的上下文、工具和 AWS 服务都位于一个位置，因此每个用例的构建速度都比上一个用例更快。

**控制 –** 您拥有我们构建的内容。一切都在您的 AWS 账户中在您的身份、网络和安全控制下运行。您的工程师从第一个冲刺开始就与我们的工程师一起工作，学习解决实际业务问题的架构和交付方法。然后，他们可以在合作结束后很长时间内运行并扩展该解决方案。当我们退后一步时，您的团队从控制塔运行系统，通过单一视图来管理、保护和监控每个代理。我们衡量成功的标准是您的团队在没有我们的情况下能取得多大的成就。

在第一个或第二个项目之后，我们希望您运行自己的人工智能软件工厂。一位金融服务客户正是通过 AI-DLC 做到了这一点，代理人和工程师一起构建。吞吐量提高了 53%，代码审查速度提高了 56%。

您也可以保留自己的选择。模型正在快速改进。当更好或更具成本效益的模型出现时，您可以通过 Amazon Bedrock 采用它而无需重建，因此您可以同时控制功能和成本。您也可以携带自己的编码代理。我们固执己见的 AWS 堆栈适合您的环境，通过 API、开放标准和连接器连接到您的系统，并且可以在混合环境中工作。您保留已经使用的工具和合作伙伴。

## 一个让每个人都变得更好的飞轮

你的团队会变得更好。您的能力随着每个用例而增长。生活环境、固执己见的 AWS 堆栈以及您团队的技能会继续发展，因此第二个用例不会重建第一个用例所构建的内容。

AWS 服务变得更好。我们的工程师将从客户那里学到的知识带回到产品中。您构建的是最新的服务，而不是过时的自定义解决方案。

AWS 的所有工作都围绕着您进行。客户开发工程探索早期想法，FDE 将最困难的问题投入生产，AWS 专业服务和 AWS 合作伙伴将工作扩展到整个组织，AWS Support 保持其运行。您可以全面了解 AI 背后的 AWS，并且可以掌控如何使用它。

## 新功能以及如何开始

AWS FDE 现已在 15 个国家/地区向商业和公共部门客户开放，而且购买起来更加简单。每个 45 天的冲刺都有 FDE 条款规定的固定价格，并通过您的 AWS 账户计费。

无论客户处于转型阶段，我们都会与他们合作。对于刚起步的客户，我们构建了一个安全、受管控的基础，并在其上构建了第一个工作流程。对于那些准备改变工作完成方式的人，我们重建了索赔处理和 KYC 审查等工作流程，以及客户直接使用的工作流程，例如购物和问题解决。然后代理运行工作。对于那些受遗留应用程序阻碍的人，我们与他们的工程师合作构建软件工厂，他们可以为每个新工作流程重用。对于那些已经扩大生产规模的企业，我们通过发现并解决问题的代理来保证系统的安全，并降低每个结果的成本。

如果您准备好开始，请与您的 AWS 客户团队联系。带来一位拥有成果的高管和准备与我们一起构建的工程师。我们已经了解了项目在开始前停滞的地方，因此我们的代理承担了大部分设置工作，例如访问、数据和安全检查。工作可以在几天内开始。然后我们就第一个冲刺将交付的内容以及我们如何衡量成功达成一致。

有效的人工智能与改变业务成果的人工智能之间的差距是真实存在的。它是一个工程、运营和组织方面的问题，我们的团队每天都会帮助客户完成它。在人工智能方面取得成功的组织不一定拥有最先进的模型。他们将构建基础、工作流程和治理，以在整个企业中扩展人工智能。

我们还早，我们会从每位客户身上学到一些新东西。模型将继续发展，围绕模型的工具也将继续发展。值得持久的是您拥有的基础、不断学习的工作流程以及您可以信任的治理。这就是我们所说的工程师离开后剩下的东西的意思。

要开始使用，请联系您的 AWS 客户团队或[了解有关 AWS FDE 的更多信息](https://aws.amazon.com/professional-services/forward-deployed-engineering/)。
