# 用 AWS AI 服务让井字棋焕发活力

大语言模型（LLM）如今支持广泛的用例，从内容摘要到对复杂任务进行推理的能力。一个令人兴奋的新话题是将生成式 AI 应用到机器人和物理硬件，从而走进物理世界。

受此启发，我们使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/)、[Strands Agents](https://strandsagents.com/latest/)、[AWS IoT Core](https://aws.amazon.com/iot-core/)、[AWS Lambda](https://aws.amazon.com/lambda) 和 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 为 AWS re:Invent 2024 Builders Fair 开发了一款游戏。我们的目标是展示 LLM 如何对游戏策略、复杂任务进行推理，并实时控制物理机器人。

RoboTic-Tac-Toe 是一款互动游戏，两个物理机器人在井字棋棋盘上移动，游戏过程和机器人动作都由 LLM 编排。玩家可以用自然语言指令控制机器人，指挥它们把棋子放到棋盘上。在这篇博文中，我们探讨用于推理井字棋对局、并为当前玩家决定下一步最佳策略和移动方案的架构与 prompt engineering 技术。

## 互动体验

RoboTic-Tac-Toe 展示了人、机器人与 AI 之间的直观互动。参与者可以扫描二维码访问游戏门户，并从多种模式中选择：

- **Player vs. Player** – 挑战人类对手
- **Player vs. LLM **– 与 AI 驱动的 LLM 一较高下
- **LLM vs. LLM **– 观看两个 AI 模型自主制定策略并展开对决

当玩家选择目标格子时，位于井字棋棋盘旁的两个机器人会响应指令，执行精确移动以放置 X 或 O 棋子。下面的视频展示了实际效果。

## 方案概览

RoboTic-Tac-Toe 实现了 AWS 服务的无缝集成，无需预先编排的动作序列。相反，AI 会实时动态生成描述性指令。下图描述了基于 AWS IoT Core 构建的架构，它支持 Raspberry Pi 控制的机器人与云端之间的通信。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/10/Architecture-1.png)

该方案使用以下关键服务：

- [Amazon Bedrock LLM ](https://aws.amazon.com/bedrock/agents/) – 使用 LLM 和 prompt engineering 生成移动方案和游戏策略
- [Strands Agents](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/model-providers/amazon-bedrock/) – 一个开源 SDK，采用模型驱动的方法来构建和运行 AI agent
- [Amazon SageMaker](https://aws.amazon.com/sagemaker/) – 支撑 AI 驱动的决策制定和机器人移动规划
- [AWS Lambda](https://aws.amazon.com/lambda) – 执行游戏逻辑，实现流畅运行和实时响应
- [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3) – 存储游戏状态数据和对局期间拍摄的图像

## 硬件与软件

- 该项目的物理装置包含一块嵌有 LED 指示灯的井字棋棋盘，用于高亮显示 X 和 O 的落子位置。
- 两个机器人（改装的玩具模型）通过配备红外和 RF 模块的 Raspberry Pi 控制器运行。
- 安装的 Raspberry Pi 摄像头支持基于视觉的分析，捕捉棋盘状态并传输数据以供进一步的计算机视觉处理。此外，一个专用硬件控制器作为 IoT 设备连接到 AWS IoT Core，促进流畅的对局交互。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/18/IMG_3145.jpg)

- 在软件方面，AWS Lambda 负责调用*supervisor* Strands Agent，以处理核心游戏逻辑和编排。
- 由 OpenCV 驱动的计算机视觉能力分析棋盘布局，并实现精确的机器人移动。Amazon Bedrock agent 编排任务，生成移动方案和游戏策略。

## Strands Agents 实战

Strands Agents 通过编排基础模型（foundation model，FM）、数据源、软件应用和用户对话之间的交互，为应用用户自动执行任务。

### Supervisor Agent

Supervisor Agent 充当编排者，管理 Move Agent 和 Game Agent，协调并简化整个系统的决策。该过程包括以下步骤：

- 该 agent 接收高层指令或对局事件（例如“玩家 X 移动到 2B，生成机器人的响应”），并确定应调用哪个专门 agent——Move Agent 还是 Game Agent。
- Supervisor AWS Lambda 函数作为中央控制器。被触发时，它解析传入请求、校验上下文，然后将请求路由到相应的 Strands Agent。整个工作流启用了 tracing，以便监控和调试。
- 根据请求类型：  如果涉及更新或分析游戏状态，Supervisor 会调用 Game Agent，由后者检索棋盘状态并生成下一步 AI 驱动的走法。如果涉及物理机器人导航，Supervisor 会调用 Move Agent，由后者以 Python 代码生成移动指令。
- Supervisor Agent 汇总来自下层 agent 的响应，并将其组织为统一的输出格式。无论结果是机器人指令、游戏走法还是两者兼有，这都有助于保持一致性。
- 包括决策路径和最终输出在内的交互会记录在 S3 bucket 中。这一日志机制提供了跨多个 agent 的可追溯性，并在出现问题时返回结构化错误消息，从而支持错误处理。

该模块在 AI 驱动的环境之上提供了一层治理，支持跨 agent 的可扩展编排。通过智能分发请求并统一响应，Supervisor Agent 实现了可靠执行、简化监控和更好的用户体验。

### Move Agent

Move Agent 生成分步的 Python 代码。该过程包括以下步骤：

- 该 agent 接收网格上的起点和终点位置（例如“3A 到 4B，朝北”），确定所需移动，并向相应的机器人发送指令。
- LLM Navigator AWS Lambda 函数使用 Strands Agents 为机器人生成移动指令。被触发时，它收到一个请求，其中包含会话 ID 和指定机器人起点与终点的输入文本。随后该函数调用 Strands Agent，发送请求并启用 tracing 以便调试。
- agent 的响应包含移动指令，例如转向和以厘米为单位向前移动。
- 这些指令会被处理并记录到 S3 bucket 中的 CSV 文件里。如果日志文件已存在，则追加新条目；否则创建一个新文件。
- 该函数返回一个 JSON 响应，其中包含生成的指令和执行请求所花费的时间。如果发生错误，则返回结构化错误消息。

该模块通过 AI 驱动的指令生成，为机器人提供高效且可追溯的导航，同时维护稳健的日志机制，用于监控和调试。

### Game Agent

Game Agent 扮演对手角色，能够与人类用户对弈。为提升易用性，玩家使用适配移动端的 web 门户与游戏互动，其中包含一个用于管理 AI 驱动对局的管理面板。LLM 玩家是一个 serverless 应用，结合 AWS Lambda、Amazon DynamoDB 和 Strands Agent 来管理和自动化走子。它通过将走子历史存储在 Amazon DynamoDB 表中来跟踪游戏进度，从而能够在需要时重建当前棋盘状态。对局过程包括以下步骤：

- 当玩家落子时，supervisor Strands Agent 检索该状态函数，然后调用 Strands Agent 函数生成下一步走法。agent 的选择取决于玩家的棋子（`‘X’` 或 `‘O’`），以确保使用正确的模型进行决策。
- 该 agent 以当前棋盘作为输入进行处理，并通过事件流返回推荐的下一步走法。
- 整个工作流由 supervisor Strands Agent 编排。该 agent 接收 API 请求、校验输入、检索棋盘状态、调用 LLM 模型，并返回包含更新后游戏状态的结构化响应。

该系统支持实时的、AI 驱动的对局，使玩家能够与由 LLM 驱动的智能对手较量。

## 用计算机视觉驱动机器人导航

在我们的 RoboTic-Tac-Toe 项目中，计算机视觉在实现精确机器人移动和准确对局方面发挥着关键作用。让我们来看看如何使用 AWS 服务和先进的计算机视觉技术实现该方案。我们的装置包含安装在棋盘上方的 Raspberry Pi 摄像头，持续监控机器人的位置和移动。摄像头拍摄的图像会自动上传到 Amazon S3，构成我们视觉处理流水线的基础。

我们使用主成分分析（Principal Component Analysis，PCA）来准确检测和跟踪机器人在棋盘上的朝向和位置。该技术有助于降低维度，同时保留机器人跟踪所需的关键特征。朝向角度根据机器人视觉特征的主成分计算得出。

我们的 OpenCV 模块经过容器化，并以 Amazon SageMaker endpoint 的形式部署。它处理存储在 Amazon S3 中的图像，以确定以下信息：

- 机器人在棋盘上的精确定位
- 当前朝向角度
- 移动校验

一个专用的 AWS Lambda 函数编排视觉处理工作流。它负责以下事项：

- SageMaker endpoint 调用
- 视觉分析结果的处理
- 实时位置和朝向更新

这一计算机视觉系统有助于实现精确的机器人导航和游戏状态跟踪，为 RoboTic-Tac-Toe 带来流畅的对局体验。将 PCA 用于朝向检测、OpenCV 用于图像处理，以及 AWS 服务用于部署，三者结合有助于构建一个稳健且可扩展的计算机视觉方案。
