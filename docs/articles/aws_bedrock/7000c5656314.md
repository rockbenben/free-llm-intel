# 用 Amazon Bedrock API key 加速 AI 开发

今天，我们很高兴宣布 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 开发者体验的一项重要改进：API key。API key 提供了一种访问 Amazon Bedrock API 的新方式，简化了认证流程，让开发者可以专注于构建，而不是配置。

CamelAI 是一个开源、模块化的框架，用于构建面向数据生成、世界模拟和任务自动化的智能多 agent 系统。

> “作为一家资源有限的初创公司，精简的客户上手流程对我们的成功至关重要。Amazon Bedrock 的 API key 让我们能在几分钟而不是几小时内完成企业客户的上手。借助 Bedrock，我们的客户可以快速获得领先 AI 模型的访问权限，并把这些能力无缝集成到 CamelAI 中，”
>         CamelAI CTO Miguel Salinas 说。

本文探讨 API key 的工作方式，以及你今天就可以如何开始使用它。

## API key 认证

Amazon Bedrock 现在提供 API key 访问方式，以简化与那些期望基于 API key 认证的工具和框架的集成。Amazon Bedrock 与 Amazon Bedrock runtime 的 SDK 已支持 API key 认证，涵盖按需推理、预置吞吐量推理、模型微调、蒸馏和评估等方法。

该图对比了访问 Amazon Bedrock 的默认认证流程（橙色）与 API key 方式（蓝色）。在默认流程中，你必须先在 [AWS IAM Identity Center](https://aws.amazon.com/iam/identity-center/) 或 [AWS IAM](https://aws.amazon.com/iam/) 中创建身份，挂载 IAM 策略以授予执行 API 操作的权限，并生成凭证，然后才能用这些凭证发起 API 调用。图中的灰色方框标出了 Amazon Bedrock 在生成 API key 时所简化掉的步骤。开发者现在只需极少的设置开销就能完成认证并访问 Amazon Bedrock API。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/12/REVBLOG-949-img1.png)

你可以在 Amazon Bedrock 控制台中生成 API key，并可在两种类型之间选择。

**短期 API key** 使用你当前 IAM 主体的 IAM 权限，会在你账户的会话结束时过期，最长可维持 12 小时，以先到期者为准。短期 API key 使用 [AWS Signature Version 4](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_sigv.html) 进行认证。若要在应用程序中持续使用，你可以参照[这些示例](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-generate.html)实现 API key 刷新，并使用你[选定的凭证提供程序](https://docs.aws.amazon.com/sdkref/latest/guide/standardized-credentials.html#credentialProviderChain)。

当你创建**长期 API key**时，Amazon Bedrock 会自动创建一个 IAM 用户并把该 key 与之关联。你可以设置从 1 天到永不过期的过期时间。Amazon Bedrock 会把 [AmazonBedrockLimitedAccess](https://docs.aws.amazon.com/bedrock/latest/userguide/security-iam-awsmanpol.html#security-iam-awsmanpol-AmazonBedrockLimitedAccess) 托管策略附加到该 IAM 用户上，你可以按需通过 IAM 服务修改权限。这些 key 专属于 Amazon Bedrock，不能用于其他 AWS 服务。对于需要更高安全性的环境，我们建议使用[临时 AWS IAM 凭证](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html#bp-workloads-use-roles)或短期 API key；而在探索 Amazon Bedrock 时，可使用带过期日期的长期 key。

## 发起你的第一次 API 调用

一旦你[获得](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)对基础模型的访问权限，上手 Amazon Bedrock API key 就很简单了。下面介绍如何使用 [AWS SDK for Python](https://aws.amazon.com/sdk-for-python/)（Boto3 SDK）和 API key 发起你的第一次 API 调用：

### 生成 API key

要生成 API key，请按以下步骤操作：

- 登录 AWS Management Console 并打开 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock/)
- 在左侧导航面板中选择 **API keys**
- 选择 **Generate short-term API key** 或 **Generate long-term API key**
- 对于长期 key，设置你期望的过期时间，并可选择配置高级权限
- 选择 **Generate** 并复制你的 API key

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/30/ML-19021-image-2.gif)

### 将 API key 设置为环境变量

你可以把 API key 设置为环境变量，这样在发起 API 请求时它会被自动识别：

```
# To set the API key as an environment variable, you can open a terminal and run the following command:
export AWS_BEARER_TOKEN_BEDROCK=<YOUR API KEY HERE>
```

Boto3 与 AWS JavaScript SDK 在你创建 Amazon Bedrock 客户端时会自动检测该环境变量。请确保使用最新的 SDK 版本。

### 发起你的第一次 API 调用

现在你可以通过多种方式向 Amazon Bedrock 发起 API 调用：

- 使用 curl  `curl -X POST "https://bedrock-runtime.us-east-1.amazonaws.com/model/us.anthropic.claude-3-5-haiku-20241022-v1:0/converse" \ -H "Content-Type: application/json" \ -H "Authorization: Bearer $AWS_BEARER_TOKEN_BEDROCK" \ -d '{ "messages": [ { "role": "user", "content": [{"text": "Hello"}] } ] }'`
- 使用 Amazon Bedrock 的 Boto3 SDK：  `import boto3 # Create an Amazon Bedrock client client = boto3.client( service_name="bedrock-runtime", region_name="us-east-1" # If you've configured a default region, you can omit this line ) # Define the model and message model_id = "us.anthropic.claude-3-5-haiku-20241022-v1:0" messages = [{"role": "user", "content": [{"text": "Hello"}]}] response = client.converse( modelId=model_id, messages=messages, ) # Print the response print(response['output']['message']['content'][0]['text'])`
- 你也可以使用 Python Requests 之类的原生库：  `import requests import os url = "https://bedrock-runtime.us-east-1.amazonaws.com/model/us.anthropic.claude-3-5-haiku-20241022-v1:0/converse" payload = { "messages": [ { "role": "user", "content": [{"text": "Hello"}] } ] } headers = { "Content-Type": "application/json", "Authorization": f"Bearer {os.environ['AWS_BEARER_TOKEN_BEDROCK']}" } response = requests.request("POST", url, json=payload, headers=headers) print(response.text)`

## 在开发者体验与企业安全需求之间架起桥梁

作为管理员，你可以启用短期 API key，在简化用户上手 Amazon Bedrock 基础模型流程的同时确保更高的安全性。这些 key 使用 AWS Signature Version 4 与现有的 IAM 主体，从而维持你既有的访问控制。

出于审计与合规目的，所有 API 调用都会记录在 [AWS CloudTrail](https://aws.amazon.com/cloudtrail/) 中。API key 作为授权头传递给 API 请求，不会被记录到日志中。

**控制 API key 的权限**

你可以配合 [Amazon Bedrock 条件键](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-permissions.html)使用服务控制策略（SCP），按组织要求自定义 API key 的生成与使用。

例如，你可以用以下策略拒绝 API key 的使用：

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Deny",
      "Action": "bedrock:CallWithBearerToken",
      "Resource": "*"
    }
  ]
}
```

你还可以对长期 API key 强制设置过期上限，以确保定期轮换。以下 SCP 会阻止创建有效期超过 30 天的 key：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Deny",
            "Action": "iam:CreateServiceSpecificCredential",
            "Resource": "*",
            "Condition": {
                "StringEquals": {
                    "iam:ServiceSpecificCredentialServiceName": "bedrock.amazonaws.com" 
                },
                "NumericGreaterThanEquals": {
                    "iam:ServiceSpecificCredentialAgeDays": "30" 
                }
            }
        }
    ]
}
```

更多 SCP 示例请参阅 [Amazon Bedrock 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-permissions.html)。
