# LinqAlpha 如何在 Amazon Bedrock 上使用 Devil’s Advocate 评估投资论点

* 本文是 LinqAlpha 的 Suyeol Yun、Jaeseon Ha、Subeen Pang 和 Jacob (Chanyeol) Choi 与 AWS 合作撰写的客座文章。 *

[LinqAlpha](https://linqalpha.com/) 是一个位于波士顿的 multi-agent AI 系统，专为机构投资者构建。全球有 170 多家对冲基金和资产管理公司使用 LinqAlpha，为公开股票及其他流动性证券精简投资研究流程，把数小时的人工尽职调查转化为由 multi-agent [大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLM）系统产出的结构化洞察。该系统支持并精简了公司筛选、入门报告（primer）生成、股价催化剂梳理等 agentic 工作流，如今还通过一个名为 Devil’s Advocate 的新 AI agent 对投资想法进行压力测试。

在本文中，我们分享 LinqAlpha 如何使用 Amazon Bedrock 构建并扩展 Devil’s Advocate。

## 挑战

信念驱动投资决策，但一个未经审视的投资论点会引入风险。在配置资本之前，投资者常问：“我忽略了什么？”识别盲点通常意味着要耗时地交叉比对专家电话会议、券商报告与监管申报文件。确认偏误与分散的工作流，让人很难客观地质疑自己的想法。以这样一个示例论点为例：“ABCD 将成为生成式 AI 的受益者，能够成功实现 AI 变现并具备竞争定位。”这个论点看起来很合理，直到你去追问：开源替代方案是否会侵蚀定价能力，或者整条产品栈上的变现机制是否已被充分理解。这些细微之处常常被漏掉。这正是 devil’s advocate 发挥作用的地方——一种刻意挑战论点、以揭示隐藏风险与薄弱假设的角色或思维方式。对投资者来说，这种结构化的怀疑精神是避免盲点、做出更高信心决策的必要条件。

投资者历来通过人工流程进行 devil’s advocate 式思考：在团队会议上辩论想法，或通过非正式的情景分析梳理利弊。LinqAlpha 着手用 AI 来把这个手工、即兴的过程结构化。

## 解决方案

Devil’s Advocate 是一个专为投资者构建的 AI 研究 agent，帮助他们用自己信任的来源系统地压力测试投资论点，速度是传统审阅的 5–10 倍。为帮助投资者更严谨地检验投资论点，LinqAlpha 中的 Devil’s Advocate agent 遵循一个结构化的四步流程：从论点定义、文档导入，到自动化的假设分析和结构化的反论点生成：

- 定义你的论点
- 上传参考文档
- AI 驱动的论点分析
- 结构化批评与反论点

本节概述该系统如何端到端运行：投资者如何与该 agent 交互，AI 如何利用可信证据解析并挑战假设，以及结果如何呈现。我们尤其会重点说明：系统如何把论点分解为假设、如何把每条批评与原始材料关联，以及如何通过 [Amazon Bedrock 中的 Anthropic Claude Sonnet 4.0](https://aws.amazon.com/bedrock/anthropic/) 高效地扩展这一过程。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项完全托管的服务，通过统一的 API 让你使用来自领先 AI 公司和 Amazon 的高性能[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FMs）。

### AI 驱动的论点分析

Devil’s Advocate 把论点解构为显式断言与隐式假设。它扫描证据库，找出挑战或反驳这些假设的内容。

### 结构化批评与反论点

系统会生成结构化的批评，其中每个假设都会被重述并直接受到挑战。每条反论点都有出处，并链接到所上传材料中的具体摘录。下面的截图展示了系统如何产出结构化、有证据链接的批评。它从投资者的论点出发，提取假设、对假设提出挑战，并把每条反论点锚定到具体来源。在这个例子中，“ABCD 将从生成式 AI 中受益”这一主张受到两项核心弱点的检验：一是尽管有 Product 等新功能，却缺乏经过验证的变现路径；二是有鉴于客户对价格敏感而回避涨价的历史。每一条论证都建立在所上传的研究之上，例如专家电话会议与分析师评论，并带有可点击的引用。投资者可以把每条挑战追溯回它的来源，并评估自己的论点在压力之下是否仍然成立。

## 应用流程

Devil’s Advocate agent 是一个 **multi-agent 系统**，负责编排用于文档解析、检索和反驳生成的专用 agent。与固定 pipeline 不同，这些 agent 会迭代交互：分析 agent 分解假设，检索 agent 查询来源，综合 agent 生成反论点，然后再回到循环中做细化。正是这种来回迭代让系统具备 agentic 特性，而不是一个静态工作流。整体架构可以描述为从数据导入到批评交付的四个相互依赖阶段。该架构遵循从数据导入到批评交付的四阶段流程。

### 输入论点

用户提交投资论点，通常是一份投资委员会（IC）备忘录。输入由一个运行在 [Amazon Elastic Compute Cloud](https://aws.amazon.com/ec2/)（Amazon EC2）实例中的定制应用接收，该应用把请求路由到 Amazon Bedrock。Amazon Bedrock 中由 Anthropic 提供的 Claude Sonnet 4 会解读这条陈述，并把它分解为核心假设。Amazon EC2 上运行着 LinqAlpha 构建的基于 Python 的编排层，负责协调 API 调用、管理日志并控制 agent 执行。

### 上传文档

这些文档由**运行在 EC2 实例中的预处理 pipeline**处理，该 pipeline 提取原始数据并转换为结构化分块。EC2 实例运行 LinqAlpha 用 Python 编写的解析应用，并集成了用于文档解析的 [Amazon Textract](https://aws.amazon.com/textract/)。[AWS Lambda](https://aws.amazon.com/lambda/) 或 [AWS Fargate](https://aws.amazon.com/fargate/) 本来也可以是替代方案，但最终选择 Amazon EC2，是因为受监管金融环境中的客户需要**具备可审计日志与严格网络控制能力的持久计算资源。**原始文件存放在 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3），结构化输出进入 [Amazon Relational Database Service](https://aws.amazon.com/rds/)（Amazon RDS），解析后的内容由 [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 索引以供检索。

### 分析论点

Amazon Bedrock 中由 Anthropic 提供的 Claude Sonnet 4 会在 Amazon OpenSearch Service 上发出**有针对性的检索查询**，并从 Amazon RDS 和 Amazon S3 汇总反证据。结构化 prompt 模板会强制反驳输出保持一致。例如，该 agent 会收到这样的 prompt：

```
You are an institutional research assistant designed to act as a Devil’s Advocate. 
Your task is to challenge investment theses with structured, evidence-linked counterarguments. 
Always use provided documents (expert calls, broker reports, 10-Ks, transcripts). 
If no relevant evidence exists, clearly state "no counter-evidence found".
Thesis: {user_thesis}
Step 1. Identify Assumptions
- Extract all explicit assumptions (stated directly in the thesis).
- Extract implicit assumptions (unstated but required for the thesis to hold).
- Label each assumption with an ID (A1, A2, A3...).
Step 2. Retrieve and Test
- For each assumption, issue retrieval queries against uploaded sources (OpenSearch index, RDS, S3).
- Prioritize authoritative sources in this order:
   1. SEC filings (10-K, 10-Q, 8-K)
   2. Expert call transcripts
   3. Broker/analyst reports
- Identify passages that directly weaken, contradict, or raise uncertainty about the assumption.
Step 3. Structured Output
For each assumption, output in JSON with the following fields:
{
  "assumption_id": "A1",
  "assumption": "<concise restatement of assumption>",
  "counter_argument": "<evidence-backed critique, phrased in analyst style>",
  "citation": {
       "doc_type": "10-K",
       "doc_id": "ABCD_10K_2023",
       "page": "47",
       "excerpt": "Management noted that monetization of Product features remains exploratory, with no committed pricing model."
  },
  "risk_flag": "<High | Medium | Low> (relative importance of this counterpoint to the thesis)"
}
Step 4. Output Formatting
- Return all assumptions and critiques as a JSON array.
- Ensure every counter_argument has at least one citation.
- If no evidence found, set counter_argument = "No counter-evidence found in provided sources" and citation = null.
- Keep tone factual and neutral (avoid speculation).
- Avoid duplication of evidence across assumptions unless highly relevant.
Step 5. Analyst Voice Calibration
- Write counter_arguments in the style of an institutional equity research analyst. 
- Be concise (2–3 sentences per counter_argument).
- Focus on material risks to the investment case (competitive dynamics, regulation, margin compression, technology adoption).
```

### 系统组件

Devil’s Advocate agent 作为一个 multi-agent 系统运行，在多个 AWS 服务之间编排解析、检索与反驳生成。专用 agent 迭代工作，每一阶段都会反馈到下一阶段，从而同时兼顾文档保真度与推理深度。投资者以两种方式与该系统交互，这两种方式构成后续处理的基础。投资者可以用自然语言陈述投资观点来输入论点，通常采取 IC 备忘录的形式。另一种方式则是上传文档。投资者可以上传收益电话会议记录、10-K、券商报告或专家电话会议笔记等金融专用材料。

上传的材料在建立索引之前会被解析为结构化文本，并补充语义结构：

- **Amazon Textract** – 从 PDF 与扫描文档中提取原始文本
- **Claude Sonnet 3.7 vision-language model (VLM)** – 通过重建表格、解读视觉内容并切分文档结构（标题、脚注、图表）来增强 Amazon Textract 的输出
- **Amazon EC2 编排层** – 运行 LinqAlpha 基于 Python 的 pipeline，负责协调 Amazon Textract、Amazon Bedrock 调用与数据路由

处理后的数据会被存储并建立索引，以便快速检索和复现：

- **Amazon S3** – 存储原始源文件，便于审计
- **Amazon RDS** – 维护结构化的内容输出
- **Amazon OpenSearch Service** – 为解析并增强后的内容建立索引，以支持有针对性的检索

推理与反驳生成由 Amazon Bedrock 中 Anthropic 的 Claude Sonnet 4 提供支持。它执行以下功能：

- **假设分解** – Sonnet 4 把论点拆解为显式与隐式假设
- **检索 agent** – Sonnet 4 针对 OpenSearch Service 构造有针对性的查询，并从 Amazon RDS 与 Amazon S3 汇总反证据
- **综合 agent** – Sonnet 4 生成结构化反驳，并附上指向源文档的引用链接，然后通过 Amazon EC2 编排层把结果返回用户界面

LinqAlpha 的 Devil’s Advocate agent 采用模块化的 multiagent 设计，不同的 Claude 模型各自承担不同角色：

- **解析 agent** – 把用于 OCR 的 Amazon Textract 与用于文档结构增强的 Claude Sonnet 3.7 VLM 结合起来。这一阶段确保表格、图表与章节层级在建立索引之前被忠实重建。
- **检索 agent** – 由 Claude Sonnet 4 驱动，针对 OpenSearch Service 构造检索查询，并借助长上下文推理从 Amazon RDS 与 Amazon S3 汇总反证据。
- **综合 agent** – 同样使用 Claude Sonnet 4，撰写结构化反驳并附上指向原始来源的引用链接，同时把输出格式化为机器可读的 JSON 以便审计。

这些 agent 迭代运行：解析 agent 丰富文档，检索 agent 找出潜在反证据，综合 agent 生成批评，而批评又可能触发额外的检索轮次。这种来回编排由 Amazon EC2 上基于 Python 的服务管理，使系统真正具备 multi-agent 特性，而不是一条线性 pipeline。

## 在 Amazon Bedrock 中实现 Claude 3.7 与 4.0 Sonnet

LinqAlpha 的 Devil’s Advocate agent 在 Amazon Bedrock 上采用**混合方式**：把支持视觉语言的 Claude Sonnet 3.7 用于文档解析，把 Claude Sonnet 4.0 用于推理与反驳生成。这种分工既有利于准确的文档保真，也有利于高级的分析严谨性。关键能力包括：

- **用 Claude Sonnet 3.7 VLM 增强解析** – Sonnet 3.7 的多模态能力通过重建纯 OCR 常常扭曲的表格、图表与章节层级，来增强 Amazon Textract。这确保财务申报文件、券商报告与扫描转写稿在进入检索工作流之前保持结构完整。
- **用 Claude Sonnet 4.0 做高级推理** – Sonnet 4.0 提供更强的思维链推理、更犀利的假设分解，以及更可靠的结构化反论点生成。与之前的版本相比，它更贴近金融分析师的工作流，产出的反驳既严谨又带有引用链接。
- **在 AWS 上可扩展地部署 agent** – 运行在 Amazon Bedrock 上，使 LinqAlpha 能够跨大量投资材料并行扩展数十个 agent。Amazon EC2 上的编排层负责协调 Amazon Bedrock 调用，在实时分析师工作负载下实现快速迭代，同时把基础设施开销降到最低。
- **大上下文与输出窗口** – 拥有 1M token 的上下文窗口并支持最多 64,000 token 的输出，Sonnet 4.0 可以分析完整的 10-K 申报文件、长达数小时的专家电话会议转写稿和长篇 IC 备忘录而无需截断。这使得此前用短上下文模型无法实现的文档级综合成为可能。
- **与 AWS 服务集成** – 通过 Amazon Bedrock，该方案与用于原始存储的 Amazon S3、用于结构化输出的 Amazon RDS 以及用于检索的 OpenSearch Service 集成。这为 LinqAlpha 带来了更安全的部署、对客户数据的完全控制，以及机构金融客户所需的弹性伸缩能力。

对对冲基金、资产管理公司和研究团队而言，选择 Amazon Bedrock 配合 Anthropic 模型不只是技术问题；它直接针对投资研究中的**核心运营痛点**：

- **可审计性与合规** – 每条反论点都会链接回其源文档（10-K、券商报告、转写稿），形成符合机构治理标准的可审计链路。
- **数据控制** – Amazon Bedrock 与私有 S3 桶、部署在 [Amazon Virtual Private Cloud](https://aws.amazon.com/vpc/)（Amazon VPC）中的 EC2 实例集成，把敏感文档保留在公司安全的 AWS 环境内，这对受监管的投资者是关键要求。
- **工作流速度** – 通过并行扩展 agentic 工作流，分析师在财报季或 IC 准备期间可节省数小时，把审阅周期从数天压缩到数分钟，而不牺牲深度。
- **决策质量** – Sonnet 3.7 保障文档保真，Sonnet 4.0 增加金融推理强度，两者结合帮助投资者发现那些在传统工作流中原本会一直隐藏的盲点。

这种基于 AWS 的 **multi-agent 编排与 LLM 可扩展性**结合，使 LinqAlpha 的 Devil’s Advocate agent 格外适合机构金融——在这个领域，**速度、合规与分析严谨性必须并存**。借助 Amazon Bedrock，该方案获得了托管式编排，以及同 Amazon S3、Amazon EC2 和 OpenSearch Service 等 AWS 服务的内置集成，从而实现了快速部署、数据完全控制和弹性伸缩。

## 结论

Devil’s Advocate 是 LinqAlpha multi-agent 研究系统中 50 多个智能 agent 之一，每个都针对机构投资工作流中的一个不同环节而设计。传统流程往往强调建立共识，而 Devil’s Advocate 把研究延伸到**结构化异见**这一关键阶段：挑战假设、暴露盲点，并提供直接链接到原始材料的可审计反论点。

通过在 Amazon Bedrock 上结合 **Claude Sonnet 3.7（用于支持 VLM 的文档解析）**与 **Claude Sonnet 4.0（用于推理与反驳生成）**，该系统同时兼顾文档保真与分析深度。与 **Amazon S3、Amazon EC2、Amazon RDS 和 OpenSearch Service** 的集成，使部署能够在投资者自控的 AWS 环境内更安全、更具可扩展性。

对机构客户来说，影响是实实在在的。通过自动化重复性的尽职调查任务，Devil’s Advocate agent 让分析师腾出更多时间投入更高层次的投资辩论与依赖判断的分析。IC 备忘录与股票陈述可以受益于结构化、有来源依据的怀疑精神，从而使推理更清晰、决策更有纪律。

LinqAlpha 的 agentic 架构展示了 **Amazon Bedrock 上的 multi-agent LLM 系统**如何把投资研究从碎片化、手工化转变为可扩展、可审计、达到决策级质量的工作流，并专门针对公开股票及其他流动性证券的研究需求量身定制。
