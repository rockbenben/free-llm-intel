## [人工智能](https://aws.amazon.com/blogs/machine-learning/)

# 在 Amazon Bedrock 托管知识库中自定义每个租户的答案

根据 [Amazon Bedrock 托管知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-build-management.html) 中的检索说明，您可以自定义每个租户的答案。相同的产品和政策文档往往服务于多个受众，例如不同地区的客户或内部团队，每个受众都需要自己的答案。您可以设置[代理检索](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-agentic-retrieve.html)应用于每个请求的语音、格式、检索指导和应答策略。在此功能之前，您无法设置答案样式，因此代理检索可以在一个请求到下一个请求之间使用不同的样式。对于固定语音或结构化输出，您必须关闭响应生成，自己调用模型，并在每个应用程序中维护提示。

现在，您将该指南作为托管、版本化的 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 资源编写一次，并且每个请求都会引用它。当您更改指令时，您可以固定版本，以便每个应用程序在您准备好时切换到新版本。

以 AnyCompany Smart Home 为例，这是一家虚构的公司，在三个销售区域销售家庭控制器和房间传感器。其客户助理为所有三个地区提供服务，其支持、现场销售和法律团队使用基于相同文档构建的内部助理。 AnyCompany在这里将每个区域和内部团队定义为租户，每个人都需要不同的答案。销售区域中部的客户需要带有日/月/年日期的西班牙语，而支持代理需要简短的票据说明。为了保持示例紧凑，每个租户都会查询一个知识库。但是，代理检索可以在单个请求中搜索最多 [五个知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-agentic-retrieve.html#kb-agentic-retrieve-api)，并且租户的指令适用于所有知识库。

检索指令会改变助理的回答方式，但它们不是授权或数据隔离边界。使用元数据过滤器或单独的知识库来控制每个租户可以检索的内容。在这篇文章中，我们展示了如何从共享知识库中为每个租户提供自己的答案，同时保持每个租户的数据独立。最后，您可以对一个租户的指令进行更改，并确认哪个版本回答了每个请求。

## 为什么租户需要自己的指示

共享文件的租户在语言、日期和货币惯例、声音以及他们可以引用的保单价值方面仍然存在差异。检索指令有四个字段来表示这些差异：

- **`角色`**：助理是谁，包括身份、语气和语言。
- **`answerFormat`**：答案的结构如何，包括如何引用来源。
- **`retrievalGuidance`**：代理如何解释问题以及搜索时的优先级。
- **`answerPolicy`**：是否以及如何回答，包括范围之外的问题。

仅当“generateResponse”为“true”（默认值）时，“persona”、“answerFormat”和“answerPolicy”字段才适用，并且“retrievalGuidance”均适用。有关详细信息，请参阅[创建和管理检索指令](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-agentic-retrieve-instruction.html)。表 1 显示了当请求包含销售区域中心指令并指定客户区域时，同一退货问题的答案如何变化。

| **比较** | **无说明** | **根据说明和客户所在区域** |
| --- | --- | --- |
|回答 |每个地区的退货窗口，然后是有关单位在哪里购买的问题 |交货后 45 天，西班牙语 |
|最后一行 |无 | `来源：central-returns-addendum.md` |

*表 1：有和没有销售区域中心指令的相同退货问题*

这些模式出现在各个行业。企业软件提供商可以为自己的许多客户运行一个助手。每个客户都会上传自己的政策、标准操作流程和公司价值观，而“persona”和“answerPolicy”则赋予每个客户自己的声音和规则。受监管企业可以在“answerPolicy”中放置固定的免责声明，并在“answerFormat”中放置固定的引用形式，因此每个答案都包含两者。将答案发送到下游代码的团队可以从“answerFormat”获取严格的 JSON，而无需单独的生成步骤。在每种情况下，文档都是共享的，并且语音、格式和策略因呼叫者而异。

## 检索指令如何工作

指令属于您的 AWS 账户和 AWS 区域，而不是知识库，并经历以下阶段：

- **创建 –** `CreateRetrievalInstruction` 返回 HTTP 202。
- **审核 –** Amazon Bedrock 异步审核指令的字段，然后您轮询结果。如果审核失败，“lastTransitionStatusReasons”会说明原因。
- **激活 –** 通过审查使指令“ACTIVE”，并且“DRAFT”指向其当前内容。
- **版本 –** `CreateRetrievalInstructionVersion` 保存不可变的编号版本。
- **应用 –** 请求命名指令和版本（可选），默认为“DRAFT”。
- **报告 –** 第一个 `Planning` 跟踪事件包括 `appliedInstruction`。

### 范围和权衡

指令规定了声音、格式、惯例和政策措辞。他们不限制代理可以检索哪些文档，也不选择租户自己的值，这些值来自请求中指定的租户。使用[元数据过滤器](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-management-test-config.html)或单独的知识库来限制每个租户可以检索的内容。

## 解决方案概述

每个租户都有自己的指令和元数据过滤器。该指令设置答案的语音、格式和策略，以及过滤器限制代理检索的文档。您的后端从经过身份验证的租户中选择两者，因此一个共享知识库可以为每个租户提供服务。在图 1 中，您的后端将经过身份验证的租户映射到指令版本和元数据过滤器，并向消息添加一个短的租户行。然后它在一个共享托管知识库上调用“AgenticRetrieveStream”。

图 1：一个包含每个租户指令和过滤器的托管知识库

相同的模式适用于每个租户的单独知识库。一个请求可以同时查询共享的全局知识库和租户自己的知识库，每个知识库都有自己的过滤器。

该示例使用 AnySmartProduct-5 家庭控制器和 AnySmartProduct-6 房间传感器的 32 个简短的虚构 AnyCompany 智能家居策略和产品文档。它们存储在 [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/s3/) 存储桶中，每个存储桶都有“region”、“audience_team”和“sensitivity”元数据。六个租户（三个区域和三个团队）中的每一个都有自己固定到版本 1 的指令。两个受限工程注释不属于任何租户，因此任何租户的过滤器都不应返回它们。

该代码位于 [GitHub 存储库](https://github.com/aws-samples/sample-management-knowledge-base-patterns/tree/main/retrieval-instructions)，采用 Python 和 TypeScript，默认在美国东部（弗吉尼亚北部）区域 (us-east-1) 运行。要使用其他 AWS 区域，请设置“AWS_REGION”。有关最新区域支持，请参阅[支持的 AWS 区域](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-management-regions.html)。

## 先决条件

您需要以下内容：

- 有权创建检索指令、AWS Identity and Access Management (IAM) 角色和 S3 存储桶的 AWS 账户。
- 一个或多个托管知识库，其中包含您要过滤的每个文档的元数据文件。
- Python 3.10 或更高版本以及适用于 Python 的 AWS 开发工具包 (Boto3) 的当前版本。较旧的 Boto3 版本不包含检索指令操作。
- 用于控制平面命令的 AWS 命令​​行界面 (AWS CLI) 的当前版本。 `AgenticRetrieveStream` 没有 CLI 命令，因此通过 SDK 调用它。
- 可选：如果您想使用自己的密钥加密指令，则需要 [AWS Key Management Service (AWS KMS)](https://aws.amazon.com/kms/) 客户托管密钥。

示例将 Python 与这两个客户端一起使用。后面的片段省略了客户端设置和导入行。
```
# Illustrative. Checked with AWS SDK for Python (Boto3) 1.43.118.
import os

import boto3

region = os.environ.get("AWS_REGION", "us-east-1")
agent = boto3.client("bedrock-agent", region_name=region)  # retrieval instructions
runtime = boto3.client("bedrock-agent-runtime", region_name=region)  # agentic_retrieve_stream
```
## 为每个租户创建一条检索指令

销售区域中心指令设置语言、日期和货币格式以及保单措辞：
```
{
  "persona": "You are the AnyCompany customer assistant for Sales Region Central. You help customers who bought an AnySmartProduct-5 or AnySmartProduct-6 in Sales Region Central. Answer in Spanish, in a friendly and plain customer voice, and address the customer as 'usted'.",
  "answerFormat": "Start with a one-sentence direct answer, then add short supporting detail. Write dates as day/month/year with slashes, for example 31/12/2026. Write amounts with a decimal comma followed by the currency code, for example 5,00 USD. End with a final line that starts with 'Source:' (keep this English label) followed by the file name of the main document you used.",
  "retrievalGuidance": "This assistant serves Sales Region Central. For warranty, returns, restocking fees, holiday returns and support contacts, search the Sales Region Central documents (central-warranty-addendum, central-returns-addendum, central-local-support-and-conventions) together with the global policies, and include the words 'Sales Region Central' in those queries. Write search queries in English, because the documents are in English. Prefer the Sales Region Central addenda over the global base and over any other sales region's addenda. Do not search internal team documents.",
  "answerPolicy": "Answer only from the retrieved content and quote numbers exactly as written. Apply the Sales Region Central terms; use the global base only where Sales Region Central has no addendum. This assistant covers Sales Region Central only: if a question is about a unit bought in another sales region, explain that the rules of the sales region of purchase apply, do not state that sales region's terms, and refer the customer to the global support contacts. }
```
要创建并固定每个租户的指令：

- 为名称和“tenant”标签选择一个租户键，例如“sales-region-central”。
- 输入该租户的说明字段。
- 发送包含内容和标签的“CreateRetrievalInstruction”。
- 轮询“GetRetrievalInstruction”，直到“lastTransitionStatus”既不是“CREATING”也不是“UPDATING”。
- 如果状态不是“ACTIVE”，请阅读“lastTransitionStatusReasons”，修改并更新。
- 创建一个版本并将其记录在您的发布配置中。

此代码运行步骤 3 和 6。repo 版本添加了步骤 4 和 5 的轮询。
```
# Illustrative. Checked with AWS SDK for Python (Boto3) 1.43.118.
# Full version with polling and error handling is in the repo.
created = agent.create_retrieval_instruction(
    name=f"assistant-{tenant}",
    instruction=instruction,  # persona, answerFormat, retrievalGuidance, answerPolicy
    tags={"tenant": tenant},  # IAM conditions on aws:ResourceTag/tenant
)
instruction_id = created["retrievalInstructionId"]
# Poll get_retrieval_instruction until lastTransitionStatus is no longer CREATING, then confirm the status is ACTIVE.
version = agent.create_retrieval_instruction_version(retrievalInstructionId=instruction_id)["version"]
```
更新会替换整个指令，包括说明，因此请重新发送您想要保留的每个字段。要使用您自己的密钥加密指令，请在创建它时设置“customerEncryptionKeyArn”。您以后无法添加或更改密钥。您的密钥策略还需要[检索指令加密](https://docs.aws.amazon.com/bedrock/latest/userguide/encryption-kb.html#encryption-kb-retrieval-instruction)中的声明。

## 使用元数据过滤器将租户数据分开

指令不限制代理检索哪些文档。在共享知识库上，北销售区域客户的问题可以返回中销售区域和南销售区域的附录，甚至可以指出任何租户都不应看到。要让每个租户保留自己的文档，请添加根据经过身份验证的租户构建的元数据过滤器，或者为租户提供自己的知识库。请求仍然可以查询租户的知识库以及共享知识库。图 2 比较了这三种方法。

![三个租户隔离选项：仅指令、指令加租户元数据过滤器以及每个租户一个单独的知识库](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/10/ML-22295-2.png)

图 2：租户隔离从何而来

元数据过滤器保持一个知识库的同步和维护，但每个文档都需要准确的元数据，并且您的后端必须根据每个请求正确构建过滤器。每个租户都有一个单独的知识库，通过设计隔离租户数据，但每个租户都会添加一个知识库和数据源来创建、同步和付费。您可以将它们组合起来：一个请求可以查询共享知识库和租户自己的知识库，每个知识库都有自己的过滤器。

通过租户过滤器或单独的知识库，代理仅检索租户有权访问的文档，因此答案不会引用其他区域的值。将助手限制在一个区域的答案策略会有所帮助，但如果没有过滤器，答案仍然可以引用另一区域的值。

从经过身份验证的租户在您的服务器上构建过滤器，因为 Amazon Bedrock 会应用请求发送的任何过滤器：
```
# Illustrative. Checked with AWS SDK for Python (Boto3) 1.43.118.
# Build on the server from the authenticated tenant, never from user input.

def eq(key: str, value: str) -> dict:
    return {"equals": {"key": key, "value": value}}

def filter_for(region: str | None = None, team: str | None = None) -> dict:
    # Region tenant: global plus own region, audience "all".
    # Team tenant: any region, audience "all" plus own team.
    region_f = {"orAll": [eq("region", "global"), eq("region", region)]} if region else None
    audience_f = (
        {"orAll": [eq("audience_team", "all"), eq("audience_team", team)]} if team else eq("audience_team", "all")
    )
    return {"andAll": [audience_f, region_f]} if region_f else audience_f
```
此过滤器对文档元数据使用“equals”、“andAll”和“orAll”运算符。它不是通过“userContext”进行每个用户的访问过滤。

答复政策是尽最大努力。诸如“切勿共享受限制的工程笔记”之类的一行可以将价值观排除在答案之外。不过，如果检索到注释，答案仍然可以命名机制或记录 ID。要将受限内容排除在答案之外，请使用元数据过滤器将其排除。

## 作为租户回答

对于每个请求，您的后端都会发送租户的指令 ID 和版本、租户过滤器和租户行。租户行是一个简短的句子，例如“客户销售区域：销售区域中部。”，放置在问题之前：
```
# Illustrative. Checked with AWS SDK for Python (Boto3) 1.43.118.
# Full version with timeouts and error handling is in the repo.
knowledge_base = {"knowledgeBaseId": knowledge_base_id, "retrievalOverrides": {"filter": tenant_filter}}
response = runtime.agentic_retrieve_stream(
    messages=[{"role": "user", "content": {"text": f"{tenant_line}\n{question}"}}],
    retrievers=[{"configuration": {"knowledgeBase": knowledge_base}}],
    agenticRetrieveConfiguration={"foundationModelType": "MANAGED", "rerankingModelType": "MANAGED"},
    # omit version for DRAFT
    retrievalInstructionConfiguration={"retrievalInstructionId": instruction_id, "version": version},
)
answer = None
for event in response["stream"]:
    if "result" in event:
        answer = event["result"].get("generatedResponse", {}).get("answer")
```
以下是相同的返回问题，在一个知识库上用三个租户指令回答，并进行了修剪：
```
[Sales Region North instruction, version 1]
You have 40 days from the delivery date to return your AnySmartProduct-5 if you bought it in
Sales Region North. ... opened units carry a $15.00 restocking fee ...
Source: north-returns-addendum.md

[Sales Region Central instruction, version 1]
Si compró su AnySmartProduct-5 en la Región de Ventas Central, tiene 45 días desde la fecha de entrega
para devolverlo. ... se aplica una tarifa de reposición de 12,00 USD ...
Source: central-returns-addendum.md

[Support team instruction, version 1]
Ticket note:
- Return window depends on sales region of purchase; no region specified in this query.
- Global base policy: 30 days from delivery date (opened units allowed, $10 restocking fee if opened).
- North: 40 days; Central: 45 days; South: 14 days, unopened only.
Next action: Confirm the customer's sales region of purchase before quoting the exact return window.
```
租户热线告诉代理人谁在询问，这有助于答案引用租户的价值观。它不会设置租户的语言、答案格式或日期和金钱格式，因此请将其与租户的指令配对。如果没有说明，销售区域中心答案可能会以英语返回，没有“来源：”行，或者以错误的日期格式。

在没有指令的情况下，客户答案还可以从租户可以检索的文档中引用内部折扣等级。禁止它们的应答策略（例如销售区域中心策略）可以将它们排除在外，但为了确保这一点，请过滤掉包含它们的文档。并不能保证每个答案都具有团队格式（例如票据说明），因此请在依赖于它的任何代码中验证格式。

说明改变了答案的书写方式。事实仍然来自代理检索的文档，因此请计算准确的值，例如申请中的返回截止日期。

## 覆盖属于某个地区、某个团队的用户

一个请求只能引用一个检索指令。当用户同时属于一个区域和一个团队时，该指令必须涵盖两者。例如，南部销售区域的支持代理需要支持团队的声音以及该区域的日期和货币格式。表 2 比较了为 N 个地区和 M 个团队设置的两种方法。

| **方法** | **维护说明** | **应用该地区的格式** |
| --- | --- | --- |
|针对每个地区和团队的一项综合指导 | N x M，加上您已有的 N 个地区和 M 个团队说明 |是的 |
|团队的指示，以及租户行中指定的区域 | N + M |不，团队的格式适用 |

*表 2：用一条指令覆盖一个地区和一个团队的两种方法*

从团队的指令和区域租户行开始，这将计数保持在 N + M。仅针对格式与团队默认值不同的对添加组合指令。这两种方法都不会限制代理检索的内容，因此请对每个请求保留租户过滤器。过滤器也无法从租户有权访问的共享文档中删除值，例如列出每个区域日期的全局策略。截至撰写本文时，默认配额为每个 AWS 区域每个账户 50 条检索指令，您可以请求增加配额。合并指令加起来很快，3 个地区 3 支球队有 15 条指令，10 个地区 5 支球队有 65 条指令。

## 具有指令标签的范围租户角色

如果您的应用程序为每个租户调用相同角色的代理检索，则 [IAM](https://aws.amazon.com/iam/) 无法区分租户，并且您的代码将单独选择每个请求的指令和过滤器。当每个租户的请求在该租户自己的凭据下运行时，标记条件会添加第二次检查，检查请求可以应用哪个指令以及谁可以更改它。这些凭据可以来自每个租户的角色或使用租户会话标签承担的角色。

`AgenticRetrieveStream` 没有 IAM 资源。要应用指令，调用者需要指令的 Amazon 资源名称 (ARN) 上的“bedrock:GetRetrievalInstruction”，这就是标签条件所在的位置。示例的 [AWS Cloud Development Kit (AWS CDK)](https://aws.amazon.com/cdk/) 应用程序中的这些基于属性的访问控制 (ABAC) 语句适用于一个租户：
```
# Illustrative. From the example's AWS CDK app, trimmed.
# Applier: apply only instructions tagged with its tenant.
- Sid: ApplyOwnTenantOnly
  Effect: Allow
  Action: bedrock:GetRetrievalInstruction
  Resource: !Sub arn:${AWS::Partition}:bedrock:${AWS::Region}:${AWS::AccountId}:retrieval-instruction/*
  Condition:
    StringEquals:
      aws:ResourceTag/tenant: !Ref TenantTagValue

# Tenant admin: tag only when the request and the resource carry its tenant.
- Sid: TagOnlyWhenRequestAndResourceAreOwnTenant
  Effect: Allow
  Action: bedrock:TagResource
  Resource: !Sub arn:${AWS::Partition}:bedrock:${AWS::Region}:${AWS::AccountId}:retrieval-instruction/*
  Condition:
    StringEquals:
      aws:RequestTag/tenant: !Ref TenantTagValue
      aws:ResourceTag/tenant: !Ref TenantTagValue
```
通过这些语句，租户的应用程序角色只能应用标记有其租户的指令，并且其租户管理员角色只能管理这些指令。平台管理员可以管理任何租户的指令。需要“TagResource”上的两个标签条件。仅通过请求标记条件，租户管理员就可以将另一个租户的指令重新标记到其自己的范围内。要添加租户，请将其密钥添加到“tenantRoles”上下文值，并使用相同的“trustedPrincipalArn”再次部署 AWS CDK 应用程序。应用权限不会限制检索，因此将“bedrock:Retrieve”范围限定为每个角色的知识库。 `ListRetrievalInstructions` 不能按标签限定范围，因此请确保指令名称不含敏感信息。

## 跟踪每个答案的租户和版本

正如[使用代理检索的检索指令](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-agentic-retrieve.html)所述，第一个“Planning”跟踪事件包括“appliedInstruction”，以及所应用指令的 ID 和版本。使用租户 ID 进行记录：
```
{"step": "Planning", "status": "IN_PROGRESS", "message": "Agent planning started",
 "appliedInstruction": {"id": "abcde12345", "version": "1"}}
```
对于每种事件类型，请参阅 [AgenticRetrieveStream API 参考](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_AgenticRetrieveStream.html)。要捕获应用的指令，请检查读取答案的循环中的第一个“Planning”事件：
```
# Illustrative. Checked with AWS SDK for Python (Boto3) 1.43.118.
applied = answer = None
for event in response["stream"]:
    attrs = event.get("traceEvent", {}).get("attributes", {})
    if attrs.get("step") == "Planning" and applied is None:
        applied = attrs.get("appliedInstruction")  # log with the tenant ID
    if "result" in event:
        answer = event["result"].get("generatedResponse", {}).get("answer")
```
对于应用程序外部的审核记录，请使用 [AWS CloudTrail](https://aws.amazon.com/cloudtrail/)。 CloudTrail 将 Amazon Bedrock Runtime 操作的代理（包括“AgenticRetrieveStream”）记录为数据事件。仅当您启用数据事件后，跟踪才会记录数据事件。有关详细信息，请参阅[使用 CloudTrail 监控 Amazon Bedrock API 调用](https://docs.aws.amazon.com/bedrock/latest/userguide/logging-using-cloudtrail.html)。

## 发布指令一次更改一个租户

Amazon Bedrock 不会在版本之间路由流量。为每个租户保留一个发布配置，在每个请求上固定其版本，并通过更改该固定来进行金丝雀、升级或回滚。跟踪确认哪个版本满足每个请求，而不是新版本是否更好地响应，因此请根据您自己的检查来控制每个促销。此版本配置来自存储库的路由器：
```
# Illustrative. Checked with AWS SDK for Python (Boto3) 1.43.118.
# The application owns routing. Amazon Bedrock serves the version you pin on each request.
@dataclass(frozen=True)
class Canary:
    version: str  # version that gets the canary share, for example "2"
    every: int  # one request in `every` goes to `version`

@dataclass(frozen=True)
class ReleaseConfig:
    live: str  # version for normal traffic, for example "1"
    canary: Canary | None = None

def version_for(cfg: ReleaseConfig, request_index: int) -> str:
    if cfg.canary and request_index % cfg.canary.every == 0:
        return cfg.canary.version
    return cfg.live
# Promote: ReleaseConfig(live="2"). Roll back: ReleaseConfig(live="1").
```
要更改一个租户，请更新其指令，等待审核，创建版本，然后仅移动该租户的 PIN。例如，将支持租户移至版本 2 后，其他五个租户仍保留在版本 1 上：
```
# Illustrative. Checked with AWS SDK for Python (Boto3) 1.43.118.
# Full version with polling and error handling is in the repo.
current = agent.get_retrieval_instruction(retrievalInstructionId=instruction_id)
agent.update_retrieval_instruction(
    retrievalInstructionId=instruction_id,
    instruction={**current["instruction"], "answerFormat": answer_format},
    description=current["description"],
)
# Poll until lastTransitionStatus is UPDATE_SUCCESSFUL.
version = agent.create_retrieval_instruction_version(retrievalInstructionId=instruction_id)["version"]
```
大头针固定了说明，而不是每个答案的确切措辞。在更新审核期间，“DRAFT”将继续提供以前的内容。审核期间的版本创建或第二次更新失败并出现 HTTP 409，因此请轮询直至审核完成，如[检索指令推出步骤](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-agentic-retrieve-instruction.html)所述。

## 更多使用检索指令的方法

检索说明不仅适用于多租户设置。相同的字段适用于单个应用程序，例如必须为下游代码返回 JSON 或在每个答案中保留一个声音的助手。该存储库包含前三个的代码。

### 返回结构化 JSON

`answerFormat` 可以替换您自己的生成步骤：
```
Reply with exactly one JSON object and nothing else. Do not use markdown, do not use code
fences, and do not write any text before or after the object. The object has exactly these
five keys and no others: "answer", "sources", "confidence", "followUpQuestion", "outOfScope".
If you cannot answer, set "outOfScope" to true.
```
通过这个“answerFormat”，代理检索可以直接返回 JSON，因此您不需要单独的生成步骤。在使用代码之前验证代码中的 JSON。

### 服务多个受众

为每个受众提供自己的“角色”和“answerFormat”，例如客户答案和票据说明，因此相同的知识库可以为他们所有人提供服务，而无需混合其格式。

### 在知识库中应用一条指令

多个检索器可以共享一个指令版本：
```
# Illustrative. Checked with AWS SDK for Python (Boto3) 1.43.118.
knowledge_base_ids = ["<first-kb-id>", "<second-kb-id>"]
request = {
    "messages": [{"role": "user", "content": {"text": "<question>"}}],
    "retrievers": [{"configuration": {"knowledgeBase": {"knowledgeBaseId": kb}}} for kb in knowledge_base_ids],
    "agenticRetrieveConfiguration": {"foundationModelType": "MANAGED", "rerankingModelType": "MANAGED"},
    "retrievalInstructionConfiguration": {"retrievalInstructionId": "<instruction-id>", "version": "1"},
}
response = runtime.agentic_retrieve_stream(**request)
```
### 保持一致的品牌声音

在“人物角色”中设置身份、语气和语言，例如“使用友好、简洁的语气。用问题的语言回答。”

### 添加免责声明或引用格式

将所需的行放在“answerPolicy”中，将引文形式放在“answerFormat”中，并给出一个真实的引文示例，例如“来源：central-returns-addendum.md”，而不是占位符。

### 移交范围之外的问题

使用“answerPolicy”来命名后备方案，例如“如果文档没有回答问题，请说明并提供支持联系方式。”

### 教授领域词汇

使用“retrievalGuidance”作为首字母缩略词和首选来源，例如“将型号视为完全匹配的术语”。检查“Planning”跟踪事件以查看代理如何搜索。使用过滤器而不是指导来限制它检索的内容。

## 编写检索指令的最佳实践

编写和推出检索说明时请遵循以下做法：

- **在消息中添加租户行。** 它有助于答案引用租户自己的价值观。
- **将过滤器绑定到服务器上经过身份验证的租户。** Amazon Bedrock 应用请求发送的任何过滤器。
- **生产中的引脚版本。** 在“DRAFT”上进行测试，然后通过更改引脚进行升级。
- **等待每个审核完成。** 创建或更新后，轮询直至审核成功，然后再创建版本。审核期间创建的版本失败并显示 HTTP 409。
- **尽最大努力对待答案策略。** 为了将记录的事实排除在答案之外，请过滤掉包含它的文档。
- **验证您的代码所依赖的格式。** 不能保证每个答案都采用票证等格式。

## 清理

为了避免持续产生费用，请使用以下命令删除检索指令。然后按照 [repo README](https://github.com/aws-samples/sample-management-knowledge-base-patterns/tree/main/retrieval-instructions) 中的知识库、数据源、S3 存储桶和角色的清理步骤进行操作。
```
# Illustrative. Syntax checked against AWS CLI 2.38.4.
aws bedrock-agent list-retrieval-instruction-versions --retrieval-instruction-id <instruction-id>
aws bedrock-agent delete-retrieval-instruction --retrieval-instruction-id <instruction-id> \
  --retrieval-instruction-version <n>   # repeat for each version
aws bedrock-agent delete-retrieval-instruction --retrieval-instruction-id <instruction-id>
```
## 结论

检索指令为每个租户提供自己的声音、答案格式、日期和金钱格式以及共享托管知识库的答案策略。将它们与元数据过滤器配对，以将租户数据分开，并固定版本以一次向一个租户推出更改。跟踪显示哪个版本应答，并且 CloudTrail 可以记录“AgenticRetrieveStream”调用。当租户拥有自己的凭据时，标记条件会添加检查。

要开始使用，请参阅 [AgenticRetrieveStream API 参考](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_AgenticRetrieveStream.html) 和 [GitHub 存储库](https://github.com/aws-samples/sample-management-knowledge-base-patterns/tree/main/retrieval-instructions)。要了解更多信息，请阅读 [Amazon Bedrock 托管知识库的代理检索](https://aws.amazon.com/blogs/machine-learning/agentic-retrieval-for-amazon-bedrock-management-knowledge-base/)。
