# 使用 Amazon Bedrock 知识库评估来评估 RAG 应用

构建和部署 AI 应用的组织——尤其是那些将[大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLM）与[检索增强生成](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）系统结合使用的组织——面临一个重大挑战：如何在整个应用生命周期中有效地评估 AI 输出。随着这些 AI 技术变得更加复杂并被广泛采用，保持一致的质量与性能变得越来越困难。

传统的 AI 评估方法存在明显局限。人工评估虽然全面，但在规模化时耗时且昂贵。自动指标虽然快速且成本低，但它只能评估 AI 响应的正确性，无法覆盖其他评估维度，也无法解释答案为何有问题。此外，传统自动评估指标通常需要 ground truth 数据，而这对许多 AI 应用来说很难获得。特别是涉及开放式生成或检索增强系统的场景，定义一个唯一的“正确”答案实际上是不可能的。最后，ROUGE 和 F1 之类的指标可能被 ground truth 与 LLM 响应之间浅层的语言相似性（词重叠）所欺骗，即使实际含义相差很大。这些挑战使得组织难以在其 AI 应用中维持一致的质量标准，对于[生成式 AI](https://aws.amazon.com/generative-ai/) 输出尤其如此。

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 最近推出了两项新能力来应对这些评估挑战：[LLM-as-a-judge ](https://aws.amazon.com/blogs/aws/new-rag-evaluation-and-llm-as-a-judge-capabilities-in-amazon-bedrock/)[(LLMaaJ) ](https://aws.amazon.com/blogs/aws/new-rag-evaluation-and-llm-as-a-judge-capabilities-in-amazon-bedrock/)（位于 [Amazon Bedrock Evaluations](https://aws.amazon.com/bedrock/evaluations/) 之下），以及一个全新的 [RAG 评估](https://aws.amazon.com/blogs/aws/new-rag-evaluation-and-llm-as-a-judge-capabilities-in-amazon-bedrock/)工具，面向 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)。两项功能底层都依赖相同的 LLM-as-a-judge 技术，只是根据被评估的是模型还是用 Amazon Bedrock Knowledge Bases 构建的 RAG 应用而略有差异。这些评估功能把自动方法的速度与类似人类的细腻理解结合起来，使组织能够：

- 在各种任务与上下文中评估 AI 模型输出
- 同时评估 AI 性能的多个评估维度
- 系统性地评估 RAG 系统中的检索质量与生成质量
- 在数千条响应上规模化评估，同时维持质量标准

这些能力可以无缝融入 AI 开发生命周期，使组织能够提升模型与应用质量、推广[负责任 AI](https://aws.amazon.com/ai/responsible-ai/) 实践，并就模型选择与应用部署做出数据驱动的决策。

本文聚焦于使用 Amazon Bedrock Knowledge Bases 进行 RAG 评估，提供功能设置指南，讨论在评估 prompt 与响应时需要考虑的细节，最后讨论最佳实践。读完本文，你将了解最新的 Amazon Bedrock 评估功能如何简化你的 AI 质量保障工作，从而更高效、更有信心地开发 RAG 应用。

## 关键功能

在深入实现细节之前，我们先看看让 Amazon Bedrock Knowledge Bases 上的 RAG 评估能力尤为强大的关键功能。关键功能包括：

- Amazon Bedrock Evaluations  可在该服务内直接评估 Amazon Bedrock Knowledge Bases；系统性地评估 RAG 系统中的检索质量与生成质量，以便调整知识库的构建时参数或运行时参数
- 全面、易理解且可执行的评估指标  [检索指标](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-evaluation-rag.html)：使用 LLM 作为评判者来评估上下文相关性和覆盖率；[生成质量指标](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-eval-retrieve-generate.html)：衡量正确性、忠实度（用于检测幻觉）、完整性等；在输出中和控制台上为每个分数提供自然语言解释；跨多个评估作业比较检索与生成的结果；指标分数归一化到 0 与 1 区间
- 可扩展且高效的评估  在数千条响应上规模化评估，相比人工评估降低成本，同时维持高标准的质量要求
- 灵活的评估框架  同时支持有 ground truth 和无参考（reference-free）的评估；让用户可以从多种指标中选择用于评估；支持评估 Amazon Bedrock 上经过微调或蒸馏的模型；提供多种评估器模型可选
- 模型选择与比较  比较不同生成模型的评估作业；便于以数据驱动的方式优化模型性能
- 负责任 AI 集成  纳入内置的负责任 AI 指标，例如 harmfulness、answer refusal 和 stereotyping；与 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 无缝集成

这些功能使组织能够全面评估 AI 性能、推动负责任的 AI 开发，并在整个 AI 应用生命周期中就模型选择与优化做出明智决策。既然已经说明了关键功能，接下来我们看看这些能力如何在实际实现中协同工作。

## 功能概览

Amazon Bedrock Knowledge Bases 的 RAG 评估功能为评估和优化 RAG 应用提供了全面的端到端方案。这一自动化流程借助 LLM 的能力来评估检索质量与生成质量，提供的洞察可以显著改进你的 AI 应用。

工作流如下，对应下图中从左到右的顺序：

- **Prompt 数据集** – 准备好的 prompt 集合，可选地包含 ground truth 响应
- **JSONL 文件** – 转换为 [JSONL 格式](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-evaluation-prompt.html)的 prompt 数据集，供评估作业使用
- [Amazon Simple Storage Service](https://aws.amazon.com/s3/)**（Amazon S3）存储桶** – 存放准备好的 JSONL 文件
- **Amazon Bedrock Knowledge Bases RAG 评估作业** – 处理数据的核心组件，与 Amazon Bedrock Guardrails 和 Amazon Bedrock Knowledge Bases 集成。
- **自动报告生成** – 生成包含详细指标和洞察的完整报告，粒度到单条 prompt 或单段对话
- 分析报告，为 RAG 系统优化得出可执行的洞察

## 设计整体性 RAG 评估：平衡成本、质量与速度

RAG 系统评估需要一种平衡的方法，兼顾三个关键方面：成本、速度和质量。尽管 Amazon Bedrock Evaluations 主要关注质量指标，但理解这三个组成部分有助于制定全面的评估策略。下图展示了这些组件如何相互作用并汇聚为完整的评估策略，接下来的小节将逐一详细讨论每个组件。

[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image002.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image002.jpg)

### 成本与速度方面的考量

RAG 系统的效率取决于模型选择和使用模式。成本主要来自数据检索以及检索与生成过程中的 token 消耗，而速度取决于模型规模与复杂度，以及 prompt 和上下文的大小。对于需要以较低延迟和成本生成高性能内容的应用，例如[模型蒸馏](https://aws.amazon.com/blogs/machine-learning/a-guide-to-amazon-bedrock-model-distillation-preview/)可以是用来创建生成器模型的有效方案。由此，你可以针对具体用例创建更小、更快同时保持较大模型质量的模型。

### 质量评估框架

Amazon Bedrock 知识库评估通过多个质量维度提供全面洞察：

- 技术质量：通过上下文相关性和忠实度等指标体现
- 业务契合度：通过正确性和完整性分数体现
- 用户体验：通过 helpfulness 和逻辑连贯性度量体现
- 纳入内置的负责任 AI 指标，例如 harmfulness、stereotyping 和 answer refusal。

### 建立基线认知

评估过程从在知识库（向量或图数据库）中选择默认配置开始，例如默认的分块策略、embedding 模型和 prompt 模板。这些只是众多可选方案中的一部分。这种做法建立起基线性能，帮助你在优化之前了解 RAG 系统在现有评估指标下的当前效果。接下来，创建一个多样化的评估数据集。确保该数据集包含能准确反映你的用例的多样化查询和知识来源。数据集的多样性将为你提供 RAG 应用在生产环境中表现的全面视图。

### 迭代改进过程

理解不同组件如何影响这些指标，可以帮助你对以下方面做出有依据的决策：

- 知识库配置（分块策略、embedding 维度或模型）与推理参数的精调
- 检索策略调整（语义检索或混合检索）
- prompt 工程优化
- 模型选择与推理参数配置
- 在不同向量存储（包括图数据库）之间做选择

### 持续评估与改进

对持续评估实施系统化的方法：

- 安排与知识库更新对齐的定期离线评估周期
- 跟踪指标随时间的变化趋势，识别需要改进的方面
- 利用洞察来指导知识库优化、生成器模型的定制与选择

## 先决条件

要使用知识库评估功能，请确保你已满足以下要求：

- 一个有效的 [AWS 账户](https://signin.aws.amazon.com/signup?request_type=builderId)。
- 已在 Amazon Bedrock 中启用所选的 *evaluator* 与 *generator* 模型。你可以在 [Amazon Bedrock 控制台](https://aws.amazon.com/bedrock/)的 **Model access** 页面确认这些模型已为你的账户启用。
- 确认 [AWS 区域](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region)，以及模型的[可用性及配额](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。
- 完成知识库评估[先决条件](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-evaluation-prereq.html)，其中包括创建 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 并为 S3 存储桶添加访问和写入输出数据的权限。你还需要在 S3 存储桶上[设置并启用 CORS](https://docs.aws.amazon.com/bedrock/latest/userguide/model-evaluation-security-cors.html)。
- 已创建一个 [Amazon Bedrock 知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-create.html)并[同步数据](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-data-source-sync-ingest.html)，使其可供知识库评估作业使用。
- 如果你为生成器模型使用自定义模型而非按需模型，请确保有足够配额在推理期间运行[预置吞吐量](https://docs.aws.amazon.com/bedrock/latest/userguide/prov-throughput.html)（Provisioned Throughput）。前往 [Service Quotas 控制台](https://console.aws.amazon.com/servicequotas/home?region=us-east-1#!/dashboard)检查以下配额：所有自定义模型的 Model units no-commitment Provisioned Throughputs；“[你的自定义模型名称]”的每个预置模型 model units。这两个字段都需要有足够配额来支撑你的 Provisioned Throughput 模型单元。如有必要，请申请提高配额以容纳预期的推理负载。

## 准备输入数据集

要为知识库评估作业准备数据集，你需要遵循两个重要步骤：

- 数据集要求：每个评估作业最多 1,000 段对话（一段对话对应数据集格式中 `conversationTurns` 键内的内容）；每段对话最多 5 个轮次（prompt）；文件必须使用 JSONL 格式（`.jsonl` 扩展名）；每一行必须是有效的 JSON 对象和完整的 prompt；存放在已启用 CORS 的 S3 存储桶中
- 遵循以下格式：仅检索评估作业。

**特别说明**：在 2025 年 3 月 20 日结束的公开预览期间，下面的数据集格式包含一个名为 `referenceContexts` 的键。该字段现已改为 `referenceResponses`，以与 Retrieve and Generate 评估保持一致。`referenceResponses` 的内容应是端到端 RAG 系统在给定该 prompt 时应生成的期望标准答案，*而不是*从知识库中检索到的期望段落/分块。

```
{
    "conversationTurns": [{
        ## required for Context Coverage metric
        "referenceResponses": [{
            "content": [{
                "text": "This is a reference response for retrieved contexts"
            }]
        }],
        ## your prompt to the model
        "prompt": {
            "content": [{
                "text": "This is a prompt"
            }]
        }
    }]
}
```

- 检索并生成评估作业

```
{
    "conversationTurns": [{
        ##optional
        "referenceResponses": [{
            "content": [{
                "text": "This is a reference response used as ground truth"
            }]
        }],
        ## your prompt to the model
        "prompt": {
            "content": [{
                "text": "This is a prompt"
            }]
        }
    }]
}
```

## 使用控制台启动知识库 RAG 评估作业

Amazon Bedrock Evaluations 提供了通过控制台引导式界面运行评估作业的选项。要通过控制台启动评估作业，请按以下步骤操作：

- 在 Amazon Bedrock 控制台的导航窗格中，在 **Inference and Assessment** 下选择 **Evaluations**，然后选择 **Knowledge Bases**。
- 选择 **Create**，如下方截图所示。[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image003.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image003.jpg)
- 填写 **Evaluation name** 和 **Description**，并选择 **Evaluator model**，如下方截图所示。该模型将作为评判者来评估 RAG 应用的响应。[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image004.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image004.jpg)
- 选择知识库和评估类型，如下方截图所示。如果你只想评估检索组件，选择 **Retrieval only**；如果想评估端到端的检索与响应生成，选择 **Retrieval and response generation**。选择一个模型，它将用于本次评估作业中的响应生成。
- （可选）要修改推理参数，选择 **configurations**。你可以更新或试验不同的 temperature、top-P 取值，更新知识库 prompt 模板、关联 guardrails、更新检索策略，以及配置检索的 chunk 数量。[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image005.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image005.jpg)下方截图展示了 **Configurations** 界面。[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/07/ML-17707-image006-1.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/07/ML-17707-image006-1.jpg)
- 选择你想用来评估 RAG 应用的 **Metrics**，如下方截图所示。[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image007.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image007.jpg)
- 提供 **S3 URI**，如第 3 步所示，分别用于评估数据和评估结果。你可以使用 **Browse S3**[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image008.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image008.jpg)
- 选择一个具有[相应权限](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-evaluation-prereq.html)的服务（IAM）角色。这包括对 Amazon Bedrock、评估作业中的 S3 存储桶、作业中的知识库以及作业中所用模型的服务访问权限。你也可以在评估设置中新建 IAM 角色，服务会自动为该角色授予作业所需的正确权限。
- 选择 **Create**。
- 你可以在 **Knowledge Base evaluations** 界面上查看评估作业的 **In Progress** 状态，如下方截图所示。[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image009.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-17707-image009.jpg)

- 你可以比较两个评估作业，了解不同配置或选择的表现。你可以查看比较两个 RAG 评估作业性能指标的雷达图，轻松可视化不同维度的相对优势与劣势，如下方截图所示。

## 使用 Python SDK 和 API 启动知识库评估作业

要使用 Python SDK 创建知识库评估作业，请按以下步骤操作。首先，设置所需的配置：

```
import boto3
from datetime import datetime

# Generate unique name for the job
job_name = f"kb-evaluation-{datetime.now().strftime('%Y-%m-%d-%H-%M-%S')}"

# Configure your knowledge base and model settings
knowledge_base_id = "<YOUR_KB_ID>"
evaluator_model = "mistral.mistral-large-2402-v1:0"
generator_model = "anthropic.claude-3-sonnet-20240229-v1:0"
role_arn = "arn:aws:iam::<YOUR_ACCOUNT_ID>:role/<YOUR_IAM_ROLE>"

# Specify S3 locations for evaluation data and output
input_data = "s3://<YOUR_BUCKET>/evaluation_data/input.jsonl"
output_path = "s3://<YOUR_BUCKET>/evaluation_output/"

# Configure retrieval settings
num_results = 10
search_type = "HYBRID"

# Create Bedrock client
bedrock_client = boto3.client('bedrock')
```

对于仅检索评估，创建一个专注于评估检索上下文质量的作业：

```
retrieval_job = bedrock_client.create_evaluation_job(
    jobName=job_name,
    jobDescription="Evaluate retrieval performance",
    roleArn=role_arn,
    applicationType="RagEvaluation",
    inferenceConfig={
        "ragConfigs": [{
            "knowledgeBaseConfig": {
                "retrieveConfig": {
                    "knowledgeBaseId": knowledge_base_id,
                    "knowledgeBaseRetrievalConfiguration": {
                        "vectorSearchConfiguration": {
                            "numberOfResults": num_results,
                            "overrideSearchType": search_type
                        }
                    }
                }
            }
        }]
    },
    outputDataConfig={
        "s3Uri": output_path
    },
    evaluationConfig={
        "automated": {
            "datasetMetricConfigs": [{
                "taskType": "Custom",
                "dataset": {
                    "name": "RagDataset",
                    "datasetLocation": {
                        "s3Uri": input_data
                    }
                },
                "metricNames": [
                    "Builtin.ContextRelevance",
                    "Builtin.ContextCoverage"
                ]
            }],
            "evaluatorModelConfig": {
                "bedrockEvaluatorModels": [{
                    "modelIdentifier": evaluator_model
                }]
            }
        }
    }
)
```

如需对检索和生成做完整评估，使用以下配置：

```
retrieve_generate_job=bedrock_client.create_evaluation_job(
    jobName=job_name,
    jobDescription="Evaluate retrieval and generation",
    roleArn=role_arn,
    applicationType="RagEvaluation",
    inferenceConfig={
        "ragConfigs": [{
            "knowledgeBaseConfig": {
                "retrieveAndGenerateConfig": {
                    "type": "KNOWLEDGE_BASE",
                    "knowledgeBaseConfiguration": {
                        "knowledgeBaseId": knowledge_base_id,
                        "modelArn": generator_model,
                        "retrievalConfiguration": {
                            "vectorSearchConfiguration": {
                                "numberOfResults": num_results,
                                "overrideSearchType": search_type
                            }
                        }
                    }
                }
            }
        }]
    },
    outputDataConfig={
        "s3Uri": output_path
    },
    evaluationConfig={
        "automated": {
            "datasetMetricConfigs": [{
                "taskType": "Custom",
                "dataset": {
                    "name": "RagDataset",
                    "datasetLocation": {
                        "s3Uri": input_data
                    }
                },
                "metricNames": [
                    "Builtin.Correctness",
                    "Builtin.Completeness",
                    "Builtin.Helpfulness",
                    "Builtin.LogicalCoherence",
                    "Builtin.Faithfulness"
                ]
            }],
            "evaluatorModelConfig": {
                "bedrockEvaluatorModels": [{
                    "modelIdentifier": evaluator_model
                }]
            }
        }
    }
)
```

要监控评估作业的进度，使用以下配置：

```
# depending on job type, we can retrieve the ARN of the job and monitor to to take any downstream actions.
evaluation_job_arn = retrieval_job['jobArn']
evaluation_job_arn = retrieve_generate_job['jobArn']

response = bedrock_client.get_evaluation_job(
    jobIdentifier=evaluation_job_arn 
)
print(f"Job Status: {response['status']}")
```

## 实施最佳实践

以下最佳实践有助于为你的 RAG 评估策略打下坚实基础：

- 谨慎设计评估策略，使用能反映生产场景和用户模式的代表性测试数据集。如果你的负载超过每批 1,000 条 prompt，可通过分层抽样等技术优化负载，以便在完成时间和评估成本等约束下提升多样性与代表性。
- 安排与知识库更新和内容刷新对齐的定期批量评估，因为该功能支持批量分析而非实时监控。
- 通过选择直接影响应用成功标准的评估维度，让指标与业务目标保持平衡。
- 利用评估洞察，通过迭代优化系统性地改进知识库内容和检索设置。
- 保持评估作业的清晰文档记录，包括所选指标以及基于结果所做的改进。结果页面中的作业创建配置设置可以帮助保留历史记录。
- 根据应用需求和资源约束优化评估批量大小与频率，以实现高性价比的质量保障。
- 让评估框架的结构能够适应不断增长的知识库，在评估标准中同时纳入技术指标和业务 KPI。
