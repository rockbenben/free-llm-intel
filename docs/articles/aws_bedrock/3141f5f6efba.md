# 在 Amazon Bedrock Model Evaluation 上使用 LLM-as-a-judge

对大语言模型（LLM）性能的评估——尤其是在面对各种 prompt 时的表现——对于希望充分释放这项快速演进技术潜力的组织至关重要。*LLM-as-a-judge* 框架的引入，标志着在简化与精简模型评估流程方面向前迈出了重要一步。这种方法让组织能够使用预定义的指标来评估其 AI 模型的效果，确保技术与自身具体需求和目标相契合。采用这一方法后，企业可以更准确地衡量其 AI 系统的性能，就模型选型、优化和部署做出有依据的决策。这不仅提升了 AI 应用的可靠性与效率，也有助于组织以更具战略性和信息支撑的方式来采用技术。

[Amazon Bedrock](https://aws.amazon.com/bedrock) 是一项全托管服务，通过单一 API 提供来自领先 AI 公司的高性能基座模型，它最近推出了两项重要的评估能力：[Amazon Bedrock Model Evaluation 下的 LLM-as-a-judge，以及面向 Amazon Bedrock Knowledge Bases 的 RAG 评估](https://aws.amazon.com/blogs/aws/new-rag-evaluation-and-llm-as-a-judge-capabilities-in-amazon-bedrock/)。这两项功能在幕后都使用 LLM-as-a-judge 技术，但评估的对象不同。本文探讨 Amazon Bedrock Model Evaluation 中的 LLM-as-a-judge，就功能设置、通过控制台以及 Python SDK 与 API 启动评估作业给出全面指导，并演示这一创新的评估功能如何在质量、用户体验、指令遵循和安全性等多个指标类别上增强生成式 AI 应用。

在深入技术层面和实现细节之前，我们先来看看那些使 Amazon Bedrock Model Evaluation 上的 LLM-as-a-judge 格外强大、并使其区别于传统评估方法的关键功能。理解这些核心能力，有助于说明为什么该功能代表了 AI 模型评估领域的一次重要进步。

## LLM-as-a-judge 的关键功能

- **自动化智能评估**：LLM-as-a-judge 使用预训练模型自动评估回答，在提供接近人工的评估质量的同时，最多可节省 98% 的成本。该系统把评估时间从数周大幅缩短到数小时，同时在大型数据集上保持一致的评价标准。
- **全面的指标类别**：该评估系统覆盖四个关键指标领域：质量评估（正确性、完整性、忠实度）、用户体验（有帮助性、连贯性、相关性）、指令遵循（遵循指令、专业风格）以及安全监控（有害性、刻板印象、拒答处理）。
- **无缝集成**：该功能与 Amazon Bedrock 直接集成，并与现有的 Amazon Bedrock Model Evaluation 功能保持兼容。用户可以通过 Amazon Bedrock 的 AWS Management Console 使用该功能，并快速接入自己的自定义数据集用于评估。
- **灵活的实现方式**：系统支持评估托管在 Amazon Bedrock 上的模型、自定义微调模型和导入的模型。用户可以通过 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3) 存储桶无缝接入评估数据集，使评估流程简洁高效。
- **精选的评委模型**：Amazon Bedrock 提供预先选定的高质量评估模型，并针对准确的评估优化了 prompt 工程。用户无需自带外部评委模型，因为 Amazon Bedrock 团队会维护并更新一组精选的评委模型以及相关的评估评委 prompt。
- **高性价比的扩展**：该功能使组织能够大规模开展全面的模型评估，而无需承担人工评估通常带来的成本与时间投入。这一自动化流程在保持高质量评估的同时，显著降低了运营开销。

这些功能构成了一个强大的评估框架，帮助组织在保持高质量与安全标准的同时优化其 AI 模型性能，而且这一切都在其安全的 AWS 环境中完成。

## 产品概览

既然你已经了解了 LLM-as-a-judge 的关键功能，接下来我们看看如何在 Amazon Bedrock Model Evaluation 中实现并使用这一能力。本节全面介绍其架构并逐一讲解各个组件，展示它们如何协同工作，交付准确而高效的模型评估。

Amazon Bedrock Model Evaluation 上的 LLM-as-a-judge 提供了一套全面的端到端方案，用于评估和优化 AI 模型性能。这一自动化流程借助 LLM 的能力，跨多个指标类别评估回答，提供能够显著改进 AI 应用的洞见。我们结合下图，逐一讲解该方案的关键组件：

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-18078-image001.jpg)

Amazon Bedrock Model Evaluation 上的 LLM-as-a-judge 遵循一套精简的工作流，支持系统化的模型评估。以下是评估过程中各组件如何协同工作：

- **Prompt 数据集**：流程始于一个准备好的数据集，其中包含用于测试模型性能的 prompt。评估可以在提供或不提供 ground truth 回答的情况下进行——提供 ground truth 会增加额外的比较点，但它完全是可选的，并不是成功完成评估所必需的。
- **JSONL 文件准备**：prompt 数据集会被转换为 JSONL 格式，该格式专为 LLM-as-a-judge 评估作业而设计。这种格式有助于正确加工评估数据。
- **Amazon S3 存储**：准备好的 JSONL 文件被上传到 S3 存储桶，作为评估数据的安全存储位置。
- **评估处理**：Amazon Bedrock 的 LLM-as-a-judge 模型评估作业会处理已存储的数据，在所选的指标类别（包括质量、用户体验、指令遵循和安全性）上运行全面评估。
- **自动生成报告**：完成后，系统会生成详细的评估报告，包含聚合层面和单条回答层面的指标、得分与洞见。
- **专家分析**：数据科学家或机器学习工程师分析所生成的报告，从中提炼可执行的洞见并做出有依据的决策。

在了解了这一方案架构之后，我们来看看如何有效地实施 LLM-as-a-judge 模型评估，确保你从评估过程中获得最有价值的洞见。

## 先决条件

要使用 LLM-as-a-judge 模型评估，请确保你已满足以下要求：

- 一个有效的 [AWS 账户](https://signin.aws.amazon.com/signup?request_type=builderId)。
- 在 Amazon Bedrock 中启用所选的 *evaluator*（评估）模型和 *generator*（生成）模型。你可以通过 Amazon Bedrock 控制台的 **Model access** 页面确认这些模型已为你的账户启用。
- 确认模型[可用性以及配额](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)所在的 AWS 区域。
- 完成与 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam/) 创建相关的模型评估[先决条件](https://docs.aws.amazon.com/bedrock/latest/userguide/model-evaluation-type-judge.html)，并为 S3 存储桶添加访问和写入输出数据的权限。你还需要在 S3 存储桶上[设置并启用 CORS](https://docs.aws.amazon.com/bedrock/latest/userguide/model-evaluation-security-cors.html)。
- 如果你的 generator 模型使用自定义模型而非按需模型，请确保你有足够的配额在推理期间运行 [Provisioned Throughput](https://docs.aws.amazon.com/bedrock/latest/userguide/prov-throughput.html)。请完成导入自定义模型的[先决条件](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-model-import-prereq.html)。进入 AWS Service Quotas 控制台，检查以下配额：跨自定义模型的 Model units no-commitment Provisioned Throughputs；[你的自定义模型名称]每个预置模型的 Model units。这两个字段都需要有足够配额来支撑你的 Provisioned Throughput 模型单元。如有必要，请申请提高配额，以满足预期的推理负载。

### 准备输入数据集

在为 LLM-as-a-judge 模型评估作业准备数据集时，每个 prompt 都必须包含特定的键值对。以下是必填字段和可选字段：

- **prompt（必填）**：该键表示各类任务的输入。它可用于一般文本生成（模型需要给出回答）、问答任务（模型必须回答某个具体问题）、文本摘要任务（模型需要对给定文本进行摘要）或分类任务（模型必须对所提供的文本进行分类）。
- **referenceResponse（用于带 ground truth 的特定指标）**：该键包含 ground truth 或正确回答。如果提供，它将作为评估模型回答时对照的基准点。
- **category（可选）**：该键用于生成按类别报告的评估得分，帮助组织和切分评估结果，以便更好地分析。

**数据集要求：**

- 每一行都必须是合法的 JSON 对象
- 文件必须使用 JSONL 格式
- 数据集应存储在 Amazon S3 存储桶中

不带 ground truth 的 JSONL 格式示例（`category` 为可选）：

```
{
    "prompt": "What is machine learning?"
    "category": "technical"
}
{
    "prompt": "Summarize climate change impacts",
    "category": "environmental"
}
```

带 ground truth 的 JSONL 格式示例（`category` 为可选）：

```
{
    "prompt": "What is machine learning?",
    "referenceResponse": "Machine learning is a subset of artificial intelligence that enables systems to learn and improve from experience without being explicitly programmed. It uses algorithms and statistical models to analyze and draw inferences from patterns in data, allowing computers to perform specific tasks without explicit instructions.",
    "category": "technical"
}
{
    "prompt": "Summarize climate change impacts",
    "referenceResponse": "Climate change leads to rising global temperatures, extreme weather events, sea level rise, and disruption of ecosystems. These changes result in more frequent natural disasters, threats to food security, loss of biodiversity, and various public health challenges. The impacts affect agriculture, coastal communities, and vulnerable populations disproportionately.",
    "category": "environmental"
}
```

## 使用 Python SDK 与 API 启动 LLM-as-a-judge 评估作业

要使用 Python SDK 创建 LLM-as-a-judge 模型评估作业，请按以下步骤操作。首先，设置所需的配置：

```
import boto3
from datetime import datetime

# Generate unique name for the job
job_name = f"Model-evaluation-{datetime.now().strftime('%Y-%m-%d-%H-%M-%S')}"

# Configure your knowledge base and model settings
evaluator_model = "mistral.mistral-large-2402-v1:0"
generator_model = "amazon.nova-pro-v1:0"
role_arn = "arn:aws:iam::<YOUR_ACCOUNT_ID>:role/<YOUR_IAM_ROLE>"

# Specify S3 locations for evaluation data and output
input_data = "s3://<YOUR_BUCKET>/evaluation_data/input.jsonl"
output_path = "s3://<YOUR_BUCKET>/evaluation_output/"

# Create Bedrock client
bedrock_client = boto3.client('bedrock')
```

创建 LLM-as-a-judge 模型评估作业：

```
def create_llm_judge_evaluation(
    client,
    job_name: str,
    role_arn: str,
    input_s3_uri: str,
    output_s3_uri: str,
    evaluator_model_id: str,
    generator_model_id: str,
    dataset_name: str = None,
    task_type: str = "General" # must be General for LLMaaJ
):    
    # All available LLM-as-judge metrics
    llm_judge_metrics = [
        "Builtin.Correctness",
        "Builtin.Completeness", 
        "Builtin.Faithfulness",
        "Builtin.Helpfulness",
        "Builtin.Coherence",
        "Builtin.Relevance",
        "Builtin.FollowingInstructions",
        "Builtin.ProfessionalStyleAndTone",
        "Builtin.Harmfulness",
        "Builtin.Stereotyping",
        "Builtin.Refusal"
    ]

    # Configure dataset
    dataset_config = {
        "name": dataset_name or "CustomDataset",
        "datasetLocation": {
            "s3Uri": input_s3_uri
        }
    }

    try:
        response = client.create_evaluation_job(
            jobName=job_name,
            roleArn=role_arn,
            applicationType="ModelEvaluation",
            evaluationConfig={
                "automated": {
                    "datasetMetricConfigs": [
                        {
                            "taskType": task_type,
                            "dataset": dataset_config,
                            "metricNames": llm_judge_metrics
                        }
                    ],
                    "evaluatorModelConfig": {
                        "bedrockEvaluatorModels": [
                            {
                                "modelIdentifier": evaluator_model_id
                            }
                        ]
                    }
                }
            },
            inferenceConfig={
                "models": [
                    {
                        "bedrockModel": {
                            "modelIdentifier": generator_model_id
                        }
                    }
                ]
            },
            outputDataConfig={
                "s3Uri": output_s3_uri
            }
        )
        return response
        
    except Exception as e:
        print(f"Error creating evaluation job: {str(e)}")
        raise
        
 # Create evaluation job
try:
    llm_as_judge_response = create_llm_judge_evaluation(
        client=bedrock_client,
        job_name=job_name,
        role_arn=ROLE_ARN,

    )
    print(f"✓ Created evaluation job: {llm_as_judge_response['jobArn']}")
except Exception as e:
    print(f"✗ Failed to create evaluation job: {str(e)}")
    raise
```

### LLM-as-a-judge 评估的相关性分析

你可以使用 [Spearman 秩相关系数](https://en.wikipedia.org/wiki/Spearman%27s_rank_correlation_coefficient) 来比较在 Amazon Bedrock 中使用 LLM-as-a-judge 时不同 generator 模型之间的评估结果。从 S3 存储桶取回包含各项指标评估得分的评估结果后，就可以开始相关性分析。

使用 `scipy.stats` 计算成对 generator 模型之间的相关系数，过滤掉常量值或错误信息，以获得有效的统计比较。所得的相关系数有助于判断不同模型对相同 prompt 的响应有多相似。系数越接近 1.0，说明模型回答之间的一致性越强；越接近 0，则意味着行为差异越大。这种分析为模型一致性提供了有价值的洞见，并有助于找出不同模型对相同输入可能产出显著不同输出的情况。

```
import json
import boto3
import numpy as np
from scipy import stats

def read_and_organize_metrics_from_s3(bucket_name, file_key):
    s3_client = boto3.client('s3')
    metrics_dict = {}
    
    try:
        response = s3_client.get_object(Bucket=bucket_name, Key=file_key)
        content = response['Body'].read().decode('utf-8')
        
        for line in content.strip().split('\n'):
            if line:
                data = json.loads(line)
                if 'automatedEvaluationResult' in data and 'scores' in data['automatedEvaluationResult']:
                    for score in data['automatedEvaluationResult']['scores']:
                        metric_name = score['metricName']
                        if 'result' in score:
                            metric_value = score['result']
                            if metric_name not in metrics_dict:
                                metrics_dict[metric_name] = []
                            metrics_dict[metric_name].append(metric_value)
        return metrics_dict
    
    except Exception as e:
        print(f"Error: {e}")
        return None

def get_spearmanr_correlation(scores1, scores2):
    if len(set(scores1)) == 1 or len(set(scores2)) == 1:
        return "undefined (constant scores)", "undefined"
    
    try:
        result = stats.spearmanr(scores1, scores2)
        return round(float(result.statistic), 4), round(float(result.pvalue), 4)
    except Exception as e:
        return f"error: {str(e)}", "undefined"

# Extract metrics
bucket_name = "<EVALUATION_OUTPUT_BUCKET>"
file_key1 = "<EVALUATION_FILE_KEY1>"
file_key2 = "<EVALUATION_FILE_KEY2>"

metrics1 = read_and_organize_metrics_from_s3(bucket_name, file_key1)
metrics2 = read_and_organize_metrics_from_s3(bucket_name, file_key2)

# Calculate correlations for common metrics
common_metrics = set(metrics1.keys()) & set(metrics2.keys())

for metric_name in common_metrics:
    scores1 = metrics1[metric_name]
    scores2 = metrics2[metric_name]
    
    if len(scores1) == len(scores2):
        correlation, p_value = get_spearmanr_correlation(scores1, scores2)
        
        print(f"\nMetric: {metric_name}")
        print(f"Number of samples: {len(scores1)}")
        print(f"Unique values in Model 1 scores: {len(set(scores1))}")
        print(f"Unique values in Model 2 scores: {len(set(scores2))}")
        print(f"Model 1 scores range: [{min(scores1)}, {max(scores1)}]")
        print(f"Model 2 scores range: [{min(scores2)}, {max(scores2)}]")
        print(f"Spearman correlation coefficient: {correlation}")
        print(f"P-value: {p_value}")
    else:
        print(f"\nMetric: {metric_name}")
        print("Error: Different number of samples between models")
```

## LLM-as-a-judge 实施的最佳实践

你还可以比较多个基座模型，以确定哪一个最适合你的需求。在所有比较中使用相同的 evaluator 模型，可以获得一致且可扩展的结果。以下最佳实践将帮助你在比较不同基座模型时建立标准化的基准测试。

- 构建多样化的测试数据集，覆盖真实用例和边缘情况。对于大型工作负载（超过 1,000 个 prompt），使用分层抽样，在控制成本和完成时间的同时保持覆盖的全面性。同时包含简单和复杂的 prompt，以测试模型在不同难度级别上的能力。
- 选择与你的具体业务目标和应用需求相匹配的评估指标。在质量指标（correctness、completeness）与用户体验指标（helpfulness、coherence）之间取得平衡。部署面向客户的应用时，应纳入安全指标。
- 在比较不同模型时保持一致的评估条件。在所有比较中使用相同的 evaluator 模型，以实现标准化的基准测试。记录你的评估配置和参数，以保证可复现性。
- 定期安排评估作业，以跟踪模型性能随时间的变化。监测各指标类别的趋势，找出需要改进的方面。为每个指标设定性能基线和阈值。
- 根据评估需求和成本约束优化批次大小。可以考虑用较小的测试集做快速迭代，用较大的测试集做全面评估。在评估频率与资源利用之间取得平衡。
- 详细记录评估作业，包括配置和结果。跟踪模型性能随时间的改进与变化。记录基于评估洞见所做的任何修改。可选的作业描述字段在这方面可以帮到你。
- 用评估结果指导模型选型和优化。建立反馈闭环，持续改进 prompt 工程。根据新出现的需求和用户反馈，定期更新评估标准。
- 设计评估框架时考虑不断增长的工作负载。在增加模型或用例时，为复杂度的提升做好规划。可以考虑用自动化工作流处理常规评估任务。

这些最佳实践有助于在 Amazon Bedrock 上使用 LLM-as-a-judge 建立稳健的评估框架。若想深入了解这些实践的科学验证，包括案例研究以及与人工判断的相关性，请关注我们即将发布的技术深度文章。
