# 面向企业工作流管理的 AI agent 驱动浏览器自动化

企业组织越来越依赖基于 Web 的应用来支撑关键业务流程，但许多工作流仍以人工为主，造成运营效率低下与合规风险。尽管在技术上投入巨大，知识工作者在标准工作流中仍经常要在八到十二个不同的 Web 应用之间来回穿行，不断切换上下文并手工在系统之间搬运信息。数据录入与校验任务约占用员工 25-30% 的时间，而手工流程还会造成合规瓶颈，以及需要持续人工核验的跨系统数据一致性问题。传统自动化手段存在明显局限。机器人流程自动化（RPA）适用于结构化、基于规则的过程，但应用一更新就变得脆弱，且需要持续维护。基于 API 的集成仍是最优解，但许多遗留系统缺乏现代能力。业务流程管理平台提供编排能力，却在复杂决策点和直接操作 Web 页面上力不从心。结果，多数企业只能采用混合方式：只有 30% 的工作流任务实现全自动，50% 需要人工监督，20% 仍完全手工。

这些挑战在常见企业工作流中随处可见。例如，采购订单校验需要智能地在多个系统中穿行，在采购订单（PO）、收货单与发票之间完成三单匹配，同时保留审计留痕。员工入职需要在身份管理、客户关系管理（CRM）、企业资源规划（ERP）与协作平台之间协调权限开通，并按角色做出决策。最后，电商订单处理必须智能地在多个缺少原生 API 接入的零售商网站上下单。人工智能（AI）agent 相较这些传统方案是一次显著跃升：它能智能地穿行于复杂环境、适应动态变化的系统，并大幅减少企业工作流中的人工介入。

本文演示一个电商订单管理平台如何借助 [Amazon Nova Act](https://nova.amazon.com/act) 与 [Strands agent](https://strandsagents.com/latest/) 这类 AI agent，使用 [Amazon Bedrock AgentCore Browser](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html) 在规模化场景下自动完成跨多个零售网站的订单处理工作流。

## 电商订单自动化工作流

该工作流展示了 AI agent 如何智能地自动化处理复杂的多步订单流程：在缺乏原生 API 集成的各类零售网站上操作，把自适应浏览器导航与人工监督处理异常结合起来。

[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/17/image-1-10-1.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/16/image-1-10.png)

以下组件协同工作，支撑可扩展、由 AI 驱动的订单处理：

- ECS Fargate 任务运行容器化的 Python FastAPI 后端与 React 前端，提供 WebSocket 连接用于实时订单自动化。任务按需自动伸缩。
- 应用与 Amazon Bedrock 及 Amazon Nova Act 集成，实现由 AI 驱动的订单自动化。AgentCore Browser Tool 提供安全、隔离的浏览器环境用于 Web 自动化。Main Agent 编排 Nova Act Agent 与 Strands + Playwright Agent，实现智能浏览器控制。

该电商订单自动化工作流对应一类常见的企业难题：企业需要在不具备原生 API 接入的多个零售商网站上处理订单。该工作流完整展示了 AI 驱动浏览器自动化的能力，从最初的页面导航、复杂的决策，一直到 human-in-the-loop 介入。我们已构建了一个 agentic 电商自动化示例，并已在 [aws-samples repository on GitHub](https://github.com/aws-samples/sample-browser-order-automation-agentcore) 开源。

### **工作流过程**

电商订单管理系统的用户通过 Web 界面或批量 CSV 上传提交客户订单，其中包含商品详情（URL、尺码、颜色）、客户信息与收货地址。系统为订单分配优先级并排队等待处理。订单开始处理时，Amazon Bedrock AgentCore Browser 会创建一个隔离的浏览器会话，具备 Chrome DevTools Protocol（CDP）连接能力。Amazon Bedrock AgentCore Browser 提供安全的云端浏览器，让 AI agent（本例中为 Amazon Nova Act 与 Strands agent）能够与网站交互。它包含会话隔离、通过实时查看实现的内建可观测性、[AWS CloudTrail](https://aws.amazon.com/cloudtrail/) 日志记录以及会话回放等安全特性。系统从 [AWS Secrets Manager](https://aws.amazon.com/secrets-manager/) 获取零售商凭据，并使用 [Amazon DCV](https://aws.amazon.com/hpc/dcv/) 串流生成实时查看 URL，以便实时监控。下图展示了订单的完整工作流过程。

[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/16/image-2-9.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/16/image-2-9.png)

### **通过表单填写与下单实现浏览器自动化**

表单填写是一项关键能力：agent 能智能识别并填写不同零售商结算页布局中的各类字段。AI agent 访问商品页面，按需处理认证，并分析页面以识别尺码选择器、颜色选项与购物车按钮。它选择指定选项、将商品加入购物车并进入结算，再通过智能字段识别在不同零售商布局中填写收货信息。若商品缺货或不可用，agent 会连同备选方案的上下文一起升级给人工审核。

[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/16/image-3-9.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/16/image-3-9.png)

示例应用根据自动化方式采用两种不同做法。[Amazon Nova Act](https://github.com/aws/nova-act) 利用网页的视觉理解与 DOM 结构，让 Nova Act agent 接收“填写收货地址”这类自然语言指令，并从截图中自动识别表单字段，无需预定义选择器即可适应不同布局。相比之下，[Strands](https://strandsagents.com/latest/)** + **Playwright 的 Model Context Protocol（MCP）组合则使用 Bedrock 模型分析页面的 Document Object Model（DOM）结构，确定合适的表单字段选择器，再由 Playwright MCP 执行底层浏览器交互，把客户数据填入字段。两种方式都能自动适应各式零售商结算界面，消除传统基于选择器的自动化的脆弱性。

### **Human-in-the-loop（人工介入）**

遇到 CAPTCHA 或复杂难题时，agent 会暂停自动化，并通过 WebSocket 通知操作员。操作员进入实时查看，看到确切的浏览器状态，手工解决问题后触发恢复。AgentCore Browser 支持人工接管浏览器，并把控制权交还给 agent。agent 从当前状态继续，无需重启整个流程。

### **可观测性与规模**

执行全程，系统会捕获会话录制并存入 S3、在关键步骤截图，并保留带时间戳的详细执行日志。操作员通过实时仪表盘监控进度，仪表盘显示订单状态、当前步骤与进度百分比。在高并发场景下，批处理支持多订单并行执行，工作线程数可配置（1-10），并提供基于优先级的排队，以及针对瞬时故障的自动重试逻辑。

## 结语

AI agent 驱动的浏览器自动化，标志着企业开展工作流管理方式的根本转变。通过把智能决策、自适应导航与 human-in-the-loop 能力结合起来，组织可以超越传统自动化 30-50-20 的分布，在复杂的多系统工作流中获得显著更高的自动化率。电商订单自动化示例表明，AI agent 并不取代传统 RPA——它们让此前被认为过于动态、过于复杂而不适合自动化的流程得以自动化：处理各不相同的用户界面、做出结合上下文的判断，同时保持完整的合规性与可审计性。

当企业既要应对遗留系统与复杂集成，又面临提升运营效率的日益增长的压力时，AI agent 提供了一条务实的进阶路径。企业无需投入昂贵的系统重构，也不必接受手工流程的低效，而是可以部署能适配既有技术版图的智能浏览器自动化。其结果是更低的运营成本、更快的处理速度、更好的合规性，而最重要的是把知识工作者从重复性的数据录入与系统导航中解放出来，让他们专注于能创造业务价值的更高价值工作。
