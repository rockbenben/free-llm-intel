# 利用 Amazon Bedrock 生成式 AI 打造有韧性的供应链

从疫情停工到地缘政治紧张，近些年全球供应链被推入意想不到的混乱。这段动荡时期给政府和企业都上了一堂关键课：供应链卓越不仅取决于效率，还取决于通过战略性风险管理来应对中断的能力。借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的生成式 AI 能力与工具，你可以构建一个智能中枢，连接多样化的数据源，把数据转化为可执行的洞察，并制定全面的计划来缓解供应链风险。

Amazon Bedrock 是一项全托管服务，让你通过单一 API 使用来自领先 AI 公司的高性能[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM）来开发和部署生成式 AI 应用。

[Amazon Bedrock Flows](https://aws.amazon.com/bedrock/flows/) 让你可以通过连接 FM、prompt、[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)、[Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents) 以及 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）、[AWS Lambda](https://aws.amazon.com/lambda/) 和 [Amazon Lex](https://aws.amazon.com/lex/) 等其他 AWS 服务，快速构建并扩展预定义的生成式 AI 工作流。其可视化工作流构建器与无服务器基础设施让企业能够加速开发、部署 AI 驱动的供应链解决方案，在面对不断变化的挑战时提升敏捷性与韧性。我们很高兴地宣布，Flows 现已在两个 AWS GovCloud (US) 区域以及 [15 个商业区域](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-supported.html) 可用。

本文介绍 Amazon Bedrock Flows 如何连接你的业务系统、监控医疗器械短缺，并基于 Amazon Bedrock Knowledge Bases 的知识或直接存储在 Amazon S3 中的数据提供缓解策略。你将学到如何构建一个始终领先于供应链风险的系统。

## 业务工作流

以下是在 Flows 中实现的供应链业务工作流。

![工作流](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-workflow.png)

以下是该工作流各步骤的详细说明：

- 带有医疗器械名称的 JSON 请求被提交到 prompt flow。
- 工作流按以下步骤判断该医疗器械是否需要复核：

- 助手调用一个 Lambda 函数来检查器械分类以及是否存在短缺。如果没有短缺，工作流会告知用户无需采取行动。如果器械分类为 3（维持生命或健康所必需的高风险医疗器械）且存在短缺，助手会确定必要的缓解步骤。分类为 3 的器械被视为高风险器械，需要全面的缓解策略。此场景下执行以下步骤。 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 的 RetrieveAndGenerate API 生成一份全面的策略。流程把缓解措施通过电子邮件发送到给定的电子邮箱地址。 如果器械分类为 2（可能对患者造成伤害的中风险医疗器械）且存在短缺，流程会把缓解步骤列为输出。分类为 2 的器械不需要全面的缓解策略。我们建议在检索到的信息能适配模型上下文大小时采用这种方式。缓解措施直接从 Amazon S3 获取。如果器械分类为 1（不会对患者构成重大风险的低风险器械）且存在短缺，流程只输出短缺的详细信息，因为无需采取行动。

## 解决方案概览

下图展示了解决方案架构。该方案使用 Amazon Bedrock Flows 编排生成式 AI 工作流。一个 Amazon Bedrock flow 由[节点](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-nodes.html)（即流程中的一个步骤）以及用于连接各种数据源或执行各种条件的 connections（连接）构成。

![架构](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-architecture.png)

系统工作流包含以下步骤：

- 用户与生成式 AI 应用交互，这些应用与 Amazon Bedrock Flows 连接。用户提供关于器械的信息。
- Flows 中的工作流是一个由名称、描述、权限、一组节点以及节点之间的连接构成的结构。
- Flows 中的 Lambda 函数节点用于调用 AWS Lambda，以获取供应短缺和器械分类。AWS Lambda 基于 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 中的数据计算这些信息。
- 如果器械分类为 3，流程会查询 knowledge base 节点以查找缓解措施并制定全面计划。[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 可以应用在 knowledge base 节点中。
- Flows 中的 Lambda 函数节点调用另一个 Lambda 函数，把缓解计划通过电子邮件发送给用户。AWS Lambda 使用 [Amazon Simple Email Service](https://aws.amazon.com/ses/)（Amazon SES）SDK 向已验证的身份发送邮件。
- Lambda 函数位于 [Amazon Virtual Private Cloud](https://aws.amazon.com/vpc/)（Amazon VPC）的私有[子网](https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html)中，并通过[角色](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html)和[权限策略](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies.html)向各服务提供最小权限访问。AWS Lambda 分别使用[网关端点](https://docs.aws.amazon.com/vpc/latest/privatelink/gateway-endpoints.html)或 [NAT 网关](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-nat-gateway.html)连接到 Amazon DynamoDB 或 Amazon SES。
- 如果器械分类为 2，流程会查询 Amazon S3 获取缓解措施。这种情况下不需要全面的缓解措施，且内容能放入模型上下文。这降低了总体成本并简化了维护。

## 前提条件

构建该解决方案之前，需要完成以下前提条件。

- 拥有一个 AWS 账户。
- [拥有一个 Amazon VPC](https://docs.aws.amazon.com/lambda/latest/dg/configuration-vpc-internet.html)，其中包含私有子网、公有子网和出站互联网访问。
- 该解决方案仅在 US East (N. Virginia) us-east-1 [AWS 区域](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region)受支持。你可以对 [AWS CloudFormation](https://aws.amazon.com/cloudformation/) 模板做必要的修改，以部署到其他区域。
- 拥有创建 Lambda 函数和配置 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 的权限。
- [拥有](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-management-prereq.html)创建 Amazon Bedrock prompt 的权限。
- 在 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock)上申请模型访问权限（更多信息请参阅 Amazon Bedrock 文档中的[模型访问](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)）。关于使用 Amazon Bedrock 的定价信息，请参阅 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。本文使用 Anthropic 的 Claude 3.5 Sonnet，所有说明均针对该模型。
- [启用 AWS CloudTrail 日志记录](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-create-and-update-a-trail.html)以进行运营与风险审计。
- [启用预算策略](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-controls.html)通知，以保护客户免受意外计费。

## Amazon Bedrock Flow 配置

本节演练创建 flow 的过程。使用 Amazon Bedrock Flows，你可以通过可视化 flow builder 快速构建复杂的生成式 AI 工作流。以下步骤逐一配置业务流程中的不同组件。

- 在 Amazon Bedrock 控制台，从左侧导航窗格选择 **Flows**。
- 在 **Amazon Bedrock Flows** 中选择一个 flow。
- 选择 **Edit in flow builder**。
- 在 **Flow builder** 区域，中间窗格会显示 **Flow input** 节点和 **Flow output**。它们是 flow 的输入和输出节点。![flow builder](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-flowbuilde.png)

- 选择 **Flow** **Input**。
- 在左侧菜单的 **Configure** 中，把 **Output** 的 **Type** 改为 **Object**，如下图所示。
![configure](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-configure.png)

- 在 **Flow builder** 窗格中，选择 **Nodes**。

## 添加 prompt 节点处理传入数据

prompt 节点定义要在 flow 中使用的 prompt。你用该节点为 Lambda 处理细化输入。

- 将 **Prompts** 节点拖放到中间窗格。![prompt-node](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-prompt-node.png)

- 选择你刚添加的节点。
- 在 **Flow builder** 窗格的 **Configure** 部分，选择 **Define in node**。
- 定义以下值：选择 **Select model** 和 **Anthropic Claude 3 Sonnet**。在 **Message** 部分添加以下 prompt：
`Given a supply chain issue description enclosed in description tag <desc> </desc>, classify the device and problem type. Respond only with a JSON object in the following format: { "device": "<device_name>", "problem_type": "<problem_type>" } Device types include but are not limited to: Oxygen Mask Ventilator Hospital Bed Surgical Gloves Defibrillator pacemaker Problem types include but are not limited to: scarcity malfunction quality_issue If an unknown device type is provided respond with unknown for any of the fields <desc> {{description}}</desc>`![prompt-configure](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-prompt-configure.png)

- 在 **Input** 部分，把输入变量 *description* 的 **Expression** 改为以下内容，如下图所示：`$.data.description`
![prompt-inputexpression](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-prompt-inputexpression.png)

- 节点上的圆圈是连接点。要把 **Prompt** 节点连接到 input 节点，从 **Flow input** 节点上的圆圈拖一条线到 **Prompt** 的 **Input** 部分的圆圈。
- 双击 **Flow Input** 节点与 **Flow Output** 节点之间的连接，将其删除。以下视频演示了第 6 步和第 7 步。

![](https://d2908q01vomqb2.cloudfront.net/artifacts/DBSBlogs/ml-17903/ML-17903-connectnodes_compressed.gif)

## 添加 Lambda 节点从数据库获取分类

Lambda 节点让你调用 Lambda 函数，在其中定义执行业务逻辑的代码。该方案使用 Lambda 节点获取短缺信息、器械分类、Amazon S3 对象键，以及从 knowledge base 检索信息的指令。

- 将 **Lambda** 节点拖到中间添加。
- 在节点配置中，从下拉菜单选择名称含 **SupplyChainMgmt** 的 Lambda 函数，如下图所示。

![lambda getsupply](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-lambda-getsupply.png)

- 把 **Output** 类型更新为 **Object**，如下图所示。

![lambda getsupply to output](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-lambda-getsupply-output.png)

- 将 **Lambda** 节点的输入连接到 **Prompt** 节点的输出。

## 添加条件节点判断是否需要缓解措施

条件节点根据所定义的条件把来自上一个节点的数据发送到不同节点。条件节点可以接受多个输入。该节点判断是否存在短缺，并沿相应路径继续。

- 将 **Condition** 节点拖到中间添加。

![condition node](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-condition.png)

- 在 **Condition** 节点的配置中，于 **Input** 部分用以下详细信息更新第一个输入：

- **Name**：classification **Type**：Number **Expression**：`$.data.classification`
![condition1](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-condition1.png)

- 选择 **Add input** 添加新的输入，详细信息如下：**Name**：shortage **Type**：Number **Expression**：`$.data.shortage`
- 把 **Lambda** 节点的输出连接到 **Condition** 的两个输入。

![lambdacondition](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-lambdacondition.png)

- 在 **Condition** 节点的配置中，于 **Conditions** 部分添加以下详细信息：**Name**：Device2Condition **Condition**：(classification == 2) and (shortage >10)
- 选择 **Add condition** 并输入以下详细信息：**Name**：Device3Condition **Condition**：(classification == 3) and (shortage >10)![condition 2 and 3](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-condition23.png)

- 把 **If all conditions are false** 的圆圈连接到默认 **Flow output** 的输入。
- 把 **Lambda 节点**的输出连接到默认 **Flow output** 输入节点。![condition to defaultoutput](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-condition-defaultoutput.png)

- 在默认 **Flow output** 节点的配置中，把表达式更新为以下内容：`$.data.message`

## 使用 S3 Retrieval 节点获取缓解措施

S3 检索节点让你从 Amazon S3 位置检索数据并引入 flow。该节点将为类型 2 器械直接从 Amazon S3 获取缓解措施。

- 将 **S3 Retrieval** 节点拖到中间添加。
- 在节点配置中，选择名称含 **device2mitigationsbucket** 的新建 S3 存储桶。
- 把输入的 **Expression** 更新为以下内容：`$.data.S3instruction`![s3retrieval](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-s3retrieval.png)

- 把 **Condition** 节点的 **Device2Condition** 条件的圆圈连接到 **S3 Retrieval**。
- 把 **Lambda 节点**的输出连接到 **S3 Retrieval** 的输入。![lambda to s3retrieval](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-lambda-s3retrieval.png)

- 将 **Flow output** 节点拖到中间添加。
- 在节点配置中，给节点**命名**。
- 把 **S3 Retrieval** 节点的输出连接到 S3Output 节点。
![ s3retrieval to ouput](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-s3retrieval-ouput.png)

## 使用 Knowledge Base 节点获取缓解措施

Knowledge Base 节点让你从 Amazon Bedrock Knowledge Bases 中的 knowledge base 发送查询。该节点将为类型 3 器械从 Knowledge Bases 获取全面的缓解策略。

- 将 **Knowledge Base** 节点拖到中间添加。
- 在 **Knowledge Base** 节点的配置中，选择前面创建的 knowledge base。
- 选择 **Generate responses based on retrieved results**，并在 **Select model** 的下拉菜单中选择 **Claude 3 Sonnet**。
![knowledge base node](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-kb.png)

- 在 **Input** 部分，把输入表达式更新为以下内容：**Expression**：`$.data.retrievalQuery`
