# 自动化复杂的文档处理：Onity Group 如何用 Amazon Bedrock 构建智能方案

在抵押贷款服务行业，高效的文档处理可能意味着业务增长与错失机会的分野。本文探讨一家专注抵押贷款服务与发起的金融服务公司 [Onity Group](https://www.onitygroup.com/) 如何借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和其他 AWS 服务来改造其文档处理能力。

Onity Group 成立于 1988 年，总部位于佛罗里达州西棕榈滩。通过其主要运营子公司 PHH Mortgage Corporation 以及 Liberty Reverse Mortgage 品牌，公司为房主、企业客户、投资者等提供抵押贷款服务与发起解决方案。

Onity 每年要处理数百种文档类型、数百万页的内容，其中包括信托契约（deed of trust）等法律文件，关键信息往往就埋在大段密集的文字里。公司还必须应对不统一的手写条目，并核验公证与法律印章——这些任务，传统的光学字符识别（OCR）与 [AI 与机器学习](https://aws.amazon.com/training/learn-about/machine-learning/)（AI/ML）方案都难以有效处理。通过使用 Amazon Bedrock 提供的[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM），Onity 把文档抽取成本降低了 50%，同时相比之前的 OCR 与 AI/ML 方案把整体准确率提升了 20%。

Onity 的[智能文档处理](https://aws.amazon.com/ai/generative-ai/use-cases/document-processing/)（IDP）方案会根据内容复杂度动态路由抽取任务，同时发挥其自定义 AI 模型和 [Amazon Web Services](https://aws.amazon.com/)（AWS）通过 Amazon Bedrock 提供的[生成式 AI](https://aws.amazon.com/generative-ai/) 能力的长处。这种双模型方法让 Onity 能更高效地应对抵押贷款服务文档的规模与多样性，在成本和准确率两方面都带来了显著改善。

> “我们需要一个能像我们的文档处理需求一样快速演进的方案，”Onity Group 数字化转型副总裁 Raghavendra（Raghu）Chinhalli 说。
>         “通过把 AWS AI/ML 与生成式 AI 服务结合起来，我们在成本、性能、准确率和上市速度之间取得了完美的平衡，”数字化转型与智能自动化总监 Priyatham Minnamareddy 补充道。

## 为什么传统 OCR 与 ML 模型力有不逮

传统文档处理带来了若干根本性挑战，促使 Onity 去寻找更成熟的方案。以下是一些典型例子：

- **文档冗长，数据元素未被清晰标识**  **问题 –** 抵押贷款服务中的关键文档包含冗长文字，其中的关键数据元素被嵌入进来，却没有清晰的标识或结构 **示例 – **从信托契约中识别准确的法律描述，而它可能被埋在好几段法律术语之中
- **手写文本不统一**  **问题 –** 文档中的手写内容在质量、风格和可读性上差异很大 **示例 –** 书写格式上的细微差异——例如州名（*GA* 和 *Georgia*）或金额（*200K* 或 200,000）——就会造成显著的抽取挑战
- **公证与法律印章检测**  **问题 –** 判断文档是否经过公证、检测法院的法律印章、核实公证人的任期是否已过期，或从形状各异的法律印章中抽取数据，都需要对视觉与文本线索有更深入的理解，而传统方法可能漏掉这些线索
- **上下文理解能力有限**  **问题** – 传统 OCR 模型虽然擅长把文字数字化，但往往缺乏解读文档内语义上下文的能力，因而难以真正理解其中包含的信息

抵押贷款服务文档中的这些复杂性——从冗长的文字，到不统一的手写，再到对专用印章检测的需求——事实证明是传统 OCR 与 ML 模型的重大局限。这促使 Onity 去寻找更成熟的方案来应对这些根本性挑战。

## 解决方案概览

为应对这些文档处理挑战，Onity 构建了一套结合 AWS AI/ML 与生成式 AI 服务的智能方案。

[Amazon Textract](https://aws.amazon.com/textract/) 是一项 ML 服务，可自动从文档和图像中抽取文本、数据和洞察。使用 Amazon Textract，组织可以精简文档处理工作流，并释放有价值的数据来驱动智能应用。

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项全托管服务，提供来自领先 AI 公司的高性能 FM 供你选择。通过单一 API，Amazon Bedrock 提供对 AI21 Labs、Anthropic、Cohere、Meta、Mistral AI、Stability AI 和 Amazon 等厂商模型的访问，并提供一整套能力来构建安全、私有且负责任的生成式 AI 应用。

Amazon Bedrock 让你可以灵活选择最符合需求的 FM。对于 IDP，常见的方案会使用文本和视觉模型，例如 [Amazon Nova Pro](https://aws.amazon.com/ai/generative-ai/nova/) 或 Anthropic 的 Claude Sonnet。除模型访问之外，Amazon Bedrock 还提供企业级安全（在你的 Amazon 虚拟私有云（VPC）内处理数据）、用于[负责任 AI](https://aws.amazon.com/ai/responsible-ai/) 的内置护栏，以及处理敏感金融文档所必需的全面数据保护能力。你可以选出在准确率、性能和成本效率上最契合具体应用的那个模型。

**下图展示了该方案的运作方式。**

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/08/ML-17794-architecture_diagram-1.png)

- **文档摄取** – 文档被上传到 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）。上传会触发自动化的处理工作流。
- **预处理** – 在分析之前，文档会通过图像增强、降噪和版面分析进行优化。这些预处理步骤有助于让后续的 OCR 处理获得尽可能高的准确率。
- **分类** – 分类通过一个由 Onity 文档分类应用编排的三步智能工作流完成。该过程以 JSON 格式输出每页的文档类型和页码：应用使用 Amazon Textract 抽取文档内容。抽取到的内容由 Onity 的自定义 AI 模型处理。如果模型的置信度分数达到预设阈值，分类即告完成。如果文档未被识别（因为模型没有针对该文档类型训练过），应用会自动把文档路由到 Amazon Bedrock 中的 Anthropic 的 Claude Sonnet。这个基础模型连同 Anthropic 的 Claude、Amazon Nova 等其他文本与视觉模型，无需额外训练就能对文档分类，同时分析文本和图像。这种同时使用 Onity 自定义模型和 Amazon 生成式 AI 能力的双模型方法，有助于在成本效率与上市速度之间取得最佳平衡。
- **抽取** – Onity 的文档抽取应用采用算法驱动的方法，查询内部数据库以获取每种文档类型和每个数据元素对应的抽取规则。然后根据内容的复杂度，在 Amazon Textract 和 Amazon Bedrock 的 FM 之间动态路由抽取任务。
 例如，核验公证需要复杂的视觉与文本分析。在这类情况下，应用会使用 Amazon Bedrock 进阶文本与视觉模型的能力。该方案构建在 Amazon Bedrock API 之上，让 Onity 可以使用能为每种文档类型在成本与准确率之间提供最佳平衡的不同 FM。这种动态路由抽取任务的方式，让 Onity 得以优化成本、性能与准确率之间的平衡。
- **持久化** – 抽取到的信息以结构化格式存储在 Onity 的运营数据库中，并以半结构化格式存储在 Amazon S3 中，供进一步的下游处理使用。

## 安全概览

在处理敏感的金融文档时，Onity 实施了稳健的数据保护措施。数据在静态存储时使用 [AWS Key Management Service](https://aws.amazon.com/kms/)（AWS KMS）加密，在传输过程中使用 TLS 协议加密。对数据的访问通过 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）策略严格管控。关于在 AWS 上构建金融服务行业（FSI）应用的架构最佳实践，请参阅 [AWS Financial Services Industry Lens](https://docs.aws.amazon.com/wellarchitected/latest/financial-services-industry-lens/welcome.html)。该方案依照 [Security Pillar – AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/security-pillar/welcome.html) 中的 AWS 安全最佳实践指导实施。有关 AWS 安全与合规的最佳实践，请参阅[《安全、身份与合规最佳实践》](https://aws.amazon.com/architecture/security-identity-compliance/)。

### 信托契约数据抽取

信托契约是一份关键的法律文件，它会在不动产上设定担保权益。这类文档通常十分冗长，包含多页法律文字，其中的关键信息包括公证细节、法律印章、房产描述和附加条款（rider）附件。这套智能抽取方案把数据抽取成本降低了 50%，同时相比之前的 OCR 与 AI/ML 方案把整体准确率提升了 20%。

### 房屋评估文档清单式复核的自动化

房屋评估报告包含详细的房产对比和估值，需要仔细复核多个数据点，包括房间数、平方英尺数和房产特征。传统上，这一复核过程需要人工核验和交叉比对，既耗时又容易出错。现在这套自动化方案会校验房产对比结果并识别潜在差异，显著缩短了复核时间，同时相比人工流程把准确率提升了 65%。

## 结论

Onity 在 AWS 生成式 AI 服务之上实施的智能文档处理，展示了组织如何把复杂的文档处理挑战转化为战略优势。借助 Amazon Bedrock 的生成式 AI 能力，Onity 把文档抽取成本显著降低了 50%，同时相比之前的 OCR 与 AI/ML 方案把整体准确率提升了 20%。在具体用例中影响更为可观——其信用报告处理的准确率最高达到 85%——展现出该方案在处理复杂、多格式文档方面出色的能力。

Amazon Bedrock 提供的灵活 FM 选择，让组织可以随时间推移选择和演进自己的 AI 能力，从而为每个具体用例在性能、准确率和成本之间取得最佳平衡。该方案能够处理复杂文档，包括冗长的法律文件、手写文本和经公证的材料，展现了现代 AI 技术在金融服务领域的变革潜力。除了降本增效带来的直接收益之外，这一实施还为那些希望在保持敏捷、以适应不断变化的业务需求的同时推进文档处理现代化的组织提供了一份蓝图。该方案的成功证明，深思熟虑地应用 AWS AI/ML 与生成式 AI 服务能够带来切实的业务成果，同时让组织在文档处理能力上持续创新。

如果你也面临类似的文档处理挑战，我们建议先从 Amazon Textract 入手，评估其核心 OCR 和数据抽取能力是否满足你的需求。对于需要进阶上下文理解和视觉分析的更复杂用例，请使用 Amazon Bedrock 的文本与视觉基础模型，例如 Amazon Nova Lite、Nova Pro、Anthropic 的 Claude Sonnet 和 Anthropic 的 Claude。借助 [Amazon Bedrock 模型 playground](https://docs.aws.amazon.com/bedrock/latest/userguide/playgrounds.html)，你可以快速试验这些多模态模型，然后用 Amazon Bedrock 模型评估在不同指标（例如准确率、鲁棒性和成本）上比较最佳的基础模型。通过这一过程，你可以就哪个模型能为你的具体用例提供性能与成本效益的最佳平衡做出有依据的决策。
