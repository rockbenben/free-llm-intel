# PolyAI Dialog-RSN-1 现已出现在 Amazon SageMaker JumpStart 上

Dialog-RSN-1 是一种为实时复杂对话而构建的推理模型，现已在 AWS Marketplace 和 Amazon SageMaker JumpStart 上推出。它为前沿对话提供动力：代理可以听到实时呼叫，对其进行推理并实时采取行动。

作为 AWS 客户，您可以[通过 AWS Marketplace 订阅 Dialog-RSN-1](https://aws.amazon.com/marketplace/pp/prodview-l4qyhvfxnkq7e) 并将其部署为您自己的 AWS 环境中的 SageMaker 终端节点。您还可以按照[使用 Amazon SageMaker JumpStart 部署和评估模型](https://aws.amazon.com/blogs/machine-learning/deploy-and-evaluate-models-with-amazon-sagemaker-jumpstart/) 中的步骤直接从 Amazon SageMaker Studio 进行部署。这意味着旨在处理客户对话的模型可以像其他具有 AWS Marketplace 订阅的 Amazon SageMaker 模型一样进行部署。

## 在 AWS 中部署 Dialog-RSN-1

Dialog-RSN-1 是第一个通过 [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-l4qyhvfxnkq7e) 提供的 PolyAI 模型。它在您自己的 AWS 环境中运行，位于为 PolyAI 的计算、模型训练和服务提供支持的同一 AWS 云上。

Dialog-RSN-1 只需一次即可直接感知呼叫者的音频，推断他们的需求，并实时响应。在 SageMaker 上，它像您在其中运行的其他模型一样部署为端点。它可以从您自己的架构访问，通过您的 AWS 账户计费，并由相同的 Virtual Private Cloud (VPC)、AWS Identity and Access Management (IAM) 角色以及您已有的监控覆盖。

您保留编排、电话集成和业务逻辑的所有权。 Dialog-RSN-1 帮助您解决了自己构建最困难的部分：理解实时呼叫并实时响应。端点使用 OpenAI Realtime 协议，因此现有的 Realtime 客户端通过更改其基本 URL 通过 PolyAI 的 [bridge](https://github.com/polyai/dialog-rsn-1-sagemaker) 进行连接。音频输入为 16 或 24 kHz 的 16 位 PCM 单声道（首先转码 G.711 或 Opus）。连接持续长达 30 分钟，并且该模型目前仅支持英语。

首先，[在 AWS Marketplace 上找到 Dialog-RSN-1](https://aws.amazon.com/marketplace/pp/prodview-l4qyhvfxnkq7e)，然后将其直接部署到您自己账户中的 Amazon SageMaker 终端节点中。或者您可以直接从 [Amazon SageMaker JumpStart](https://aws.amazon.com/sagemaker/ai/jumpstart/) 进行部署。

Dialog-RSN-1 现已加入 SageMaker JumpStart，只需单击一下即可部署 Dialog-RSN-1。在 Amazon SageMaker AI 控制台中，打开模型中心，从 JumpStart 目录中选择 Dialog-RSN-1，然后选择部署。然后，SageMaker JumpStart 在已为您调整的服务堆栈上启动实时推理端点。无需争论容器，无需事后猜测实例类型，也无需手动基准测试。对于自动化工作流程，相同的一键部署也在 SageMaker Python SDK 的几行中运行。

Dialog-RSN-1 终端节点完全在您自己的 AWS 账户中运行。它部署在您的 VPC 中，通过您的 IAM 角色进行访问，并使用您用于所有其他工作负载的相同 Amazon CloudWatch 日志记录和指标进行监控。由于推理发生在您的帐户内，因此呼叫者的音频和文字记录会保留在您控制的范围内。对于处理实时客户对话的模型，这有助于支持您的数据驻留和可审核性要求。

## 专为速度和准确性而打造

为实时通话构建的模型可能会让您在速度和理解之间做出选择。为速度而构建的模型可能会忽略其含义，而为推理而构建的模型可能会导致呼叫者等待时间。 Dialog-RSN-1 避免了这种权衡。

借助 PolyAI，您可以构建对话代理，以像人工代理一样收听和处理呼叫。这些特工能够抓住犹豫，在挫折升级之前听到挫折，并知道何时说话。

实时客户对话是 PolyAI Dialog-RSN-1 的目标，目前它已经在生产中处理实时呼叫。因为该模型直接通过呼叫者的音频进行推理，所以它会拾取语气、犹豫和时间，以及普通文字记录丢失的信号，并自行决定响应的正确时机。

## 一个像人类一样听到呼叫的模型

Dialog-RSN-1 是一个专注于实时对话的模型。没有单独的语音到文本步骤，也没有在适当的谈话时刻的推理模型，因此没有多次切换。

实际上，这意味着调用者可以更快地得到响应：

- 即使呼叫量激增，插入功能也能继续工作，而不是为了保护性能而关闭。
- 响应保持同步，因此模型在推理要说什么时不会落后于对话。
- 转录是根据音频本身生成的，因为 Dialog-RSN-1 正在读取实际的音频，而不是其他人对它的最佳猜测。

## 针对您的工作负载的一键部署和优化

从同一模型卡中，您选择部署，Amazon SageMaker JumpStart 将使用预配置的服务堆栈建立实时推理终端节点。没有手动容器选择或实例猜测。真正的便利在于指定的优化配置文件：您无需手动调整基础设施，而是选择与运行 Dialog-RSN-1 的方式相匹配的目标。延迟优化可最大程度地缩短交互式实时呼叫的首次令牌时间。吞吐量优化可最大程度地提高每秒令牌数，以实现高呼叫量。成本优化可最大限度地降低每个请求的基础设施成本。平衡是通用用途的均衡折衷。

由于 Dialog-RSN-1 专为实时响应而构建，因此您可以使用延迟优化配置文件将响应能力直接传送到您自己的端点。在部署之前，SageMaker JumpStart 会显示关键性能指标：P50 延迟、首次令牌时间和吞吐量。这使您可以根据流量调整 ml.* 实例的大小，而不是手动对数十个组合进行基准测试。您可以从控制台运行整个流程，或通过 SageMaker Python SDK 编写脚本，将部署连接到持续集成和持续交付 (CI/CD)。
