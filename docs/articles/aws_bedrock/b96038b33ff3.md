# PolyAI Dialog-RSN-1 现已上线 Amazon SageMaker JumpStart

Dialog-RSN-1 是一个为实时复杂对话打造的推理模型，今天已在 AWS Marketplace 和 Amazon SageMaker JumpStart 上线。它支撑的是前沿对话场景：agent 听见一通实时通话，对它进行推理，并实时采取行动。

作为 AWS 客户，你可以[通过 AWS Marketplace 订阅 Dialog-RSN-1](https://aws.amazon.com/marketplace/pp/prodview-l4qyhvfxnkq7e)，并把它作为 SageMaker endpoint 部署在自己的 AWS 环境中。你也可以按照[使用 Amazon SageMaker JumpStart 部署和评估模型](https://aws.amazon.com/blogs/machine-learning/deploy-and-evaluate-models-with-amazon-sagemaker-jumpstart/)中的步骤，直接从 Amazon SageMaker Studio 部署。也就是说，这个专为处理客户对话而设计的模型，可以像其他通过 AWS Marketplace 订阅的 Amazon SageMaker 模型一样部署。

## 在 AWS 内部部署 Dialog-RSN-1

Dialog-RSN-1 是 PolyAI 第一个通过 [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-l4qyhvfxnkq7e) 提供的模型。它运行在你自己的 AWS 环境里，所用的 AWS 云也正是承载 PolyAI 计算、模型训练与推理服务的同一朵云。

Dialog-RSN-1 一次处理就能直接感知来电者的音频，推理出对方需要什么，并实时作出回应。在 SageMaker 上，它和你在此运行的其他模型一样以 endpoint 形式部署。你可以从自己的架构访问它，通过自己的 AWS 账户计费，并沿用现有的虚拟私有云（VPC）、AWS Identity and Access Management（IAM）角色和监控体系。

编排、电话系统集成和业务逻辑仍归你所有。Dialog-RSN-1 接手的是你自己最难搭的那部分：听懂一通实时通话，并当场回应。该 endpoint 使用 OpenAI Realtime 协议，因此现有的 Realtime 客户端只需改一下 base URL，就能通过 PolyAI 的 [bridge](https://github.com/polyai/dialog-rsn-1-sagemaker) 连上来。输入音频为 16 位 PCM 单声道，采样率 16 或 24 kHz（需先把 G.711 或 Opus 转码）。单次连接最长 30 分钟，该模型目前只支持英语。

上手方式：先在 [AWS Marketplace 上找到 Dialog-RSN-1](https://aws.amazon.com/marketplace/pp/prodview-l4qyhvfxnkq7e)，然后把它直接部署到你自己账户里的 Amazon SageMaker endpoint；也可以直接从 [Amazon SageMaker JumpStart](https://aws.amazon.com/sagemaker/ai/jumpstart/) 部署。

Dialog-RSN-1 已经接入 SageMaker JumpStart，部署只需一次点击。在 Amazon SageMaker AI 控制台打开 Model Hub，从 JumpStart 目录中选中 Dialog-RSN-1，点 Deploy。SageMaker JumpStart 会在一个已经替你调好的服务栈上启动实时推理 endpoint。不用折腾容器，不用反复猜实例类型，也不用手工做 benchmark。要做自动化流程，同样的一键部署也可以用几行 SageMaker Python SDK 跑起来。

Dialog-RSN-1 的 endpoint 完全跑在你自己的 AWS 账户内：部署在你的 VPC 里，通过你的 IAM 角色访问，用你给其他所有工作负载用的那套 Amazon CloudWatch 日志和指标来监控。因为推理发生在你的账户里，来电者的音频和转写文本都留在一个你掌控的边界之内。对于处理实时客户对话的模型来说，这有助于满足数据驻留和可审计性方面的要求。

## 为速度与准确率而生

面向实时通话的模型，常常逼你在速度和理解之间二选一：为速度打造的模型可能听不懂意思，为推理打造的模型又可能让来电者干等。Dialog-RSN-1 绕开了这个取舍。

借助 PolyAI，你可以构建像人工坐席那样接听和处理通话的对话 agent。这些 agent 能察觉迟疑，在不满升级之前就听出情绪，也知道什么时候该开口。

实时客户对话正是 PolyAI Dialog-RSN-1 的专长，而且它今天已经在生产环境中处理真实通话。由于模型直接在来电者的音频上推理，它能捕捉语气、迟疑和节奏——这些正是纯文本转写会丢掉的信号——并自行判断回应的最佳时机。

## 像人一样听电话的模型

Dialog-RSN-1 是一个专注实时对话的模型。它没有单独的语音转文本步骤，也没有一个专门判断该在何时说话的推理模型，因此不存在多次交接。

落到实际使用中，来电者能更快拿到回应：

- 即使通话量激增，barge-in 依然有效，而不是为了保护性能被关掉。
- 回应跟得上节奏，模型在琢磨该说什么时不会落后于对话。
- 转写直接来自音频本身，因为 Dialog-RSN-1 读的是真实音频，而不是别人对这段音频的最佳猜测。

## 一键部署，并为你的工作负载做优化

在同一张模型卡上选择 Deploy，Amazon SageMaker JumpStart 就会用一个预配置好的服务栈撑起实时推理 endpoint。无需手工挑容器，也不用猜实例规格。真正省事的是那几个命名优化 profile：你不必手动调基础设施，只需挑一个与 Dialog-RSN-1 使用方式匹配的目标。延迟优化把交互式实时通话的首 token 时间压到最低；吞吐优化为高通话量把每秒 token 数拉到最高；成本优化把每个请求的基础设施成本压到最低；Balanced 则是通用场景下的均衡取舍。

Dialog-RSN-1 天生就是实时响应的，因此你可以用延迟优化 profile 把这种响应能力直接带到自己的 endpoint 上。部署之前，SageMaker JumpStart 会给出关键性能指标：P50 延迟、首 token 时间和吞吐。这样你就能按流量给 ml.* 实例选对规格，而不必手工对几十种组合做 benchmark。整个流程可以在控制台里跑完，也可以用 SageMaker Python SDK 写成脚本，把部署接进持续集成与持续交付（CI/CD）。
