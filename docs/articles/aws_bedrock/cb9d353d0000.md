# 让机构知识普惠：用 AWS 构建 AI 驱动的知识管理系统

各行各业的组织都在为管理机构知识而苦恼——那是多年运营中积累起来的集体智慧与经验。这种「部落知识」往往会随着关键人员离开而消失，造成影响效率与创新的知识缺口。传统的文档方法已被证明力不从心，往往在最需要的时候给出过时或无法获取的信息。

在本文中，我们介绍一个可定制、带智能缓存的云端方案，它通过一套智能 avatar 系统来捕获、维护并交付机构知识，并由 AWS 服务提供支撑。

## 谁适合使用该方案

各行各业的组织都可以用这套系统来保存关键知识。例如，制造企业可以在经验丰富的技术员退休之前，把生产流程和维护规程记录下来。医疗机构、金融服务公司、能源企业和政府机构等其他组织，也可以针对自己的用例对这套方案做定制。知识工作者可以通过自然语言查询获取流程与政策，而不必在多个仓库中逐个搜索；主题专家和即将退休的员工则可以上传文档，把自己的专业知识留给后来者。

组织部署这套系统时，可以同时提供桌面浏览器访问用于细致研究、语音交互用于免手操作，以及文本查询用于快速查阅，从而适配各行业具体的运营场景。

## 方案概览

我们的方案使用 AWS 服务构建一个可扩展、可配置的知识管理系统，你可以按组织的需要加以调整。其核心架构把先进的 AI 能力与稳健的云基础设施结合起来，交付一套直观、响应迅速的知识交付系统。

方案的基础是一个同时支持文本与语音交互的浏览器界面，让知识可以通过自然对话获得。该界面连接到一套可配置的 avatar 系统，它可以与任何 AI avatar 方案配合使用，使组织能够灵活选择或更换自己偏好的 avatar 技术。

图 1：知识管理系统的方案架构

在幕后，[Amazon Cognito](https://aws.amazon.com/cognito/?p=pm&c=cog&z=4) 负责访问管理的安全，而 Amazon API Gateway 提供对系统各组件的受控、可监控访问。知识处理核心使用 Amazon Bedrock Knowledge Bases 来实现托管式的检索增强生成（RAG）：存放在 Amazon Simple Storage Service（Amazon S3）中的机构知识是数据源，Amazon Bedrock 负责分块、嵌入（使用 Amazon Titan Text Embeddings）和检索，并把每个回答都建立在你自己文档的基础之上。该 knowledge base 由 Amazon OpenSearch Serverless 向量存储提供支撑。Amazon DynamoDB 提供回答缓存，AWS Lambda 函数负责编排整个 workflow。

**成本提示：** Amazon OpenSearch Serverless 向量存储由部署过程在你的账户中创建，按 OpenSearch Compute Unit（OCU）计费，并且有一个常开的最低量，与查询量无关。做预算时请把它当作一项常驻的基线成本（在默认下限下大约是每月几百美元的量级）。它是该方案成本中最大的固定组成部分。关于缓存如何在这项基线之上降低可变推理成本，请参阅「通过智能缓存优化成本」一节。

## 为什么选择这个方案？

希望保存机构知识的组织有多种可选路径，从在 Amazon Bedrock 上构建自定义方案，到部署基于文本的 chat agent。本方案通过三项核心能力形成差异化。

**语音优先、avatar 驱动的交付：** 本方案围绕与 AI 驱动的 avatar 进行语音交互来构建，而不是一个只有文本的聊天界面。非技术背景的最终用户几乎或完全不需要学习成本。他们对着 avatar 说话，就能听到语音回答，就像向同事请教一样。在培训室、控制室、质量实验室和维护计划办公室等联网场景中，工作人员可以在查阅规程的同时免手查询系统。与纯文本 chatbot 相比，基于 avatar 的交互还能提高非技术人群的采用率与信任度。（这是一个依赖云连接的方案。连接性要求见「可扩展性与性能特征」一节。）

**对知识所有者足够简单：** 内容管理不需要任何技术专长。知识所有者只需把现有文档上传到 Amazon S3（Word、PDF、纯文本、Markdown 或 JSON）。随后一次摄取同步会把每份文档分块并嵌入到向量存储中，之后它就可被查询。新文档在上传后不久、待这次自动化同步完成即可查询，但并不是瞬时的。无需重构内容、不用打元数据标签，也不必手工搭建检索 pipeline。

**快速部署并内建成本优化：** 整个原型通过 AWS CloudFormation 在数小时内完成部署。内建的 DynamoDB 缓存会为重复问题复用先前的回答，从而降低可变的 AI 推理成本。在我们的测试中，对于以重复问题为主的工作负载，缓存命中率可以达到 50–70%。实际节省取决于你的查询组合有多重复。

### 与其他做法相比

在 Amazon Bedrock 上构建自定义方案可以完全掌控架构，但需要独立设计并集成语音处理、avatar 渲染、缓存和检索 pipeline。这通常要花数周到数月，并假定团队在多个 AWS 服务上具备深厚的技术专长。

像 Amazon Q 这样的基于文本的 chat agent，以及自定义的 Amazon Bedrock 聊天界面，提供了更快的部署路径，并且在键盘输入式的知识检索上表现出色。本方案在其之上增加了语音优先的交互和 avatar 参与，这能提升一线员工的采用率，因为他们受益于免手访问。

本方案填补了这一空白：一个可在数小时内完成部署、达到生产质量的加速器，语音优先并配有可视化 avatar 交互，且通过智能缓存实现成本优化。对于需要快速且低成本地把机构知识交到非技术员工手中的组织来说，这个加速器免去了自行拼装这些能力的复杂性。

### 何时选择本方案

当你的组织需要以下事项时，可以选择这个加速器：

- 通过语音与可视化交互，把机构知识交付给非技术员工或一线员工。
- 用经过验证的原型快速部署，而不是从零构建。
- 通过智能缓存降低 AI 推理成本。
- 以最小的摩擦保存即将退休的专家的知识。

## 实施路径

实施路径包含三个主要阶段：知识基础搭建、基础设施部署和 AI 集成。每个阶段都在前一阶段之上叠加，最终构成一套完整的知识管理系统。

**阶段 1：知识基础搭建。** 实施过程从整理机构知识开始。文档被上传到 Amazon S3 知识仓库，Amazon Bedrock Knowledge Bases 从那里摄取它们。如果你的源内容存在于其他系统或以其他格式存在，可以选择性地增加一个 AWS Glue ETL 作业，在上传之前把它转换为面向 AI 优化的格式。这个 ETL 步骤是一个独立的可选集成，不由 CloudFormation 部署创建。如果组织的文档已经是下面列出的受支持格式，就可以直接上传到 S3。

**关键考虑事项：**

- **支持的格式**：文档可以是多种格式（Word、PDF、纯文本、Markdown、JSON）。
- **最优输出**：为获得最佳的 AI 检索表现，建议使用 Markdown（.md）或结构化 JSON。
- **ETL 负责转换：** 如果你使用可选的 AWS Glue ETL 作业，它会在源文档上传到 S3 之前把它们转换为推荐的输出格式。

关于使用 AWS Glue 进行数据抽取与转换的详细指导，请参阅 [AWS Glue ETL 文档](https://docs.aws.amazon.com/glue/latest/dg/author-job-glue.html)。

**阶段 2：基础设施部署。** 核心基础设施部署从 AWS CloudFormation 模板开始，从而实现一致且可重复的部署。这个阶段包括：

- 配置 Amazon Cognito，用于安全的用户身份验证与访问控制。
- 配置 API Gateway 端点，用于管理组件之间的通信。
- 建立基于 S3 的知识存储仓库。
- 实现 DynamoDB 用于回答缓存。

**阶段 3：AI 集成。** 最后这个阶段集成 AI 能力与处理 pipeline：

- 配置 Amazon Bedrock，用于知识处理与查询理解。
- 配置 Lambda 函数，用于请求编排与回答处理。
- 实现音频处理 pipeline：用 Amazon Transcribe 把语音输入转换为文本，用 Amazon Polly 把文本回答转换为自然语音。
- 集成所选的 avatar 系统，以实现类人交互。

系统通过智能缓存算法保持高性能，在显著缩短响应时间的同时保住信息准确性。这些组件组合起来，形成这样一段体验：你可以用自己偏好的沟通方式与 knowledge base 交互，无论是文本还是语音。

**实施步骤：** 本指南概述了部署 Auto Demo 应用的步骤。接下来的步骤是针对 `us-east-1` 编写并测试的，我们选择它是因为这里用到的基座模型（FM）与 avatar 流式能力的可用范围最广。如果你要部署到其他 AWS 区域，请在开始之前确认所选的 Amazon Bedrock 模型与 avatar 提供方在该区域可用，并更新源码中硬编码的区域。

## 先决条件

首次部署需要 IT 或 DevOps 团队具备一定的技术能力来完成一次性配置，包括基本的 AWS Management Console 操作、对基础设施即代码的理解，以及对身份管理的熟悉。

最终用户不需要任何技术能力。会话式界面消除了门槛。用户只需访问一个 URL，就能像与人类专家交流那样，通过文本或语音自然地交互。

### AWS 账户

- 拥有一个 AWS 账户的访问权限，且具备创建 S3 存储桶、CloudFormation 堆栈以及调用 Amazon Bedrock 模型的权限。
- 具备用于部署和管理 AWS 资源的相应 AWS Identity and Access Management（IAM）权限。

### 按服务划分所需的 IAM 权限

该 CloudFormation 堆栈会跨多个 AWS 服务创建并管理资源。要部署和运行本方案，执行部署的 IAM 角色或用户需要以下服务的权限：

- Amazon Bedrock（调用基座模型以及检索 Amazon Bedrock Knowledge Bases）
- Amazon S3（knowledge base 存储与应用文件）
- AWS Lambda（用于请求编排的无服务器计算）
- Amazon Cognito（用户身份验证与访问管理）
- API Gateway（HTTP 端点管理）
- Amazon OpenSearch Serverless（为 Amazon Bedrock knowledge base 提供支撑的向量存储）
- Amazon Polly（把文本转为语音以生成语音回答）
- Amazon Transcribe（把语音转为文本以处理语音输入）
- Amazon CloudWatch Logs（集中式日志）
- IAM PassRole（为 Lambda 与 knowledge-base 执行角色做服务角色委派）

**注意：** 对于生产部署，请遵循最小权限原则，把资源 ARN 限定到你的具体账户与区域。CloudFormation 堆栈会自动创建必要的执行角色，并为运行时操作配上适当范围的权限。

**基座模型访问权限：** 本方案使用 Amazon Titan Text Embeddings（`amazon.titan-embed-text-v1`）把文档嵌入到向量存储，并使用 Amazon Nova Pro（`amazon.nova-pro-v1:0`）与 Anthropic Claude 3 Sonnet（`anthropic.claude-3-sonnet-20240229-v1:0`）作为可用于生成回答的可选模型。Amazon Bedrock 对 Amazon 自有的无服务器模型提供自动访问，因此 Amazon Nova Pro 与 Amazon Titan Text Embeddings 默认即可用，无需手动启用。Anthropic Claude 模型并非在所有区域都享有自动访问：在发出第一次 Claude 请求之前，请在 Amazon Bedrock 控制台完成一次性的 Anthropic 模型访问申请，并确认你的账户具备所需的 AWS Marketplace 订阅权限。账户管理员还可以通过 IAM 策略与服务控制策略（SCP）进一步限制或替换模型。更多信息请参阅 [Amazon Bedrock 现已在你所在的 AWS 区域提供对无服务器基座模型的自动访问](https://aws.amazon.com/blogs/security/simplified-amazon-bedrock-model-access/)。

## 优化性能与用户体验

我们的知识管理系统采用双层缓存策略，以最大限度地提升响应速度与效率。在前端，浏览器侧缓存使用 LRU（最近最少使用）算法把最近的交互直接存放在用户的浏览器内存中。这层本地缓存把重复问题产生的服务端请求降到最低，为常见查询提供即时回答。后端的 DynamoDB 缓存则维护一个覆盖面更广的知识仓库，并配有智能的 TTL（存活时间）设置，按内容类型区分：基础知识留存较长、操作流程留存中等、时效性信息留存较短。这种分层做法在保证信息新鲜的同时，降低了 AI 服务上的处理负载。请注意，当前实现是按完全相同的查询文本匹配缓存条目的，因此当用户重复提出那些已成惯例、经常出现的问题时，缓存最为有效。语义（基于嵌入的）匹配是一种自然的增强，但不在本原型范围内。

avatar 系统不只是一个可视化界面。它是让复杂信息变得易懂、有吸引力的关键组件。该 avatar 基于 DeepBrain AI 技术构建，提供实时唇形同步、结合语境的面部表情，以及与对话流程相匹配的自然手势。组织可以定制 avatar 的外观、声音和行为，使其与自身的品牌识别和沟通风格一致。

技术实现上使用 WebRTC 实现流畅的视频流，并集成 Amazon Polly 实现自然的语音合成，同时用 WebSocket 连接实现响应灵敏的 avatar 控制。

通过 Amazon CloudWatch 进行的性能监控，持续提供关于缓存有效性与响应时间的洞察。系统会根据使用模式自动调整缓存策略，预热频繁访问的信息并优化 TTL 设置。高效缓存与自然的 avatar 交互相结合，形成一套响应迅速、富有吸引力的知识交付系统，并随组织需求一起扩展。

## 可扩展性与性能特征

无服务器架构在各组件上提供自动的水平扩展，确保系统无需人工介入就能承载从试点到企业级部署的增长。随着并发请求增长，函数会自动配置更多执行环境，在不降低性能的前提下应对流量峰值。API 层在扩展以应对变化负载的同时提供限流，缓存层则随查询量的波动自动调整容量。

并发用户支持能力随配置而扩展。以下数字是我们在测试中得出的指示性估计，并非保证，并且取决于区域、模型选择、文档大小、缓存命中率以及已配置的服务配额。默认配置下大约能支撑 50 到 100 个并发用户，缓存查询的响应在亚秒级。提高相关服务配额后可扩展到大约 500 到 1,000 个并发用户；在同样的架构下，超过 5,000 个并发用户的企业级用量是可以实现的，但需要主动提升服务配额。

性能会随缓存效果而不同。在我们的测试中，缓存命中时的响应远低于一秒，而全新的 knowledge base 查询大约需要 2–4 秒，具体取决于模型和文档大小。语音交互还会在其上叠加语音处理时间。这些都是指示性数字，因此在确定延迟目标之前，请针对你自己的工作负载做测量。请注意这是一个依赖云的设计：每次查询都要往返 AWS，而 avatar 依赖实时的 WebRTC/WebSocket 流式传输，这需要稳定、低延迟且带宽足够的连接。本原型不提供边缘、离线或降级模式的能力，因此它适合联网环境（培训室、工程与维护计划办公室、质量实验室、控制室、自助终端），而不适合断网或间歇联网的车间与 OT 场景。要支持那些场景，需要另做一套边缘模式，例如本地缓存、离线回退以及优雅降级为文本。

对于有增长计划的组织：试点阶段从默认配置开始，监控指标以找出瓶颈，在接近阈值时提高容量上限，并为大规模企业部署主动申请提升服务配额。无服务器架构确保你只为实际用量付费，因此从小规模起步、随采用扩大而扩展，在成本上是划算的。

## 通过智能缓存优化成本

对效率的一项关键贡献来自缓存层，它削减了最大的可变成本：对基座模型的重复调用。DynamoDB 缓存会存储并复用重复查询的回答，因此一个已经被回答过的问题不会再次触发模型调用。在我们的测试中，这使推理成本大约按缓存命中率的比例下降。对于 50–70% 的问题是重复的工作负载，推理成本下降了大致相当的比例。由于节省量直接是命中率的函数，我们只给出一组数字，而不把两者当作彼此独立的保证。这项可变节省叠加在先前提到的 Amazon OpenSearch Serverless 固定基线之上，因此两项都要纳入预算。

对于部落知识类用例——其中很多问题都与既有的流程、政策和机构惯例有关——系统的智能缓存机制尤其有效。通过实现基于时间的缓存失效，我们在成本效率与信息准确性之间保持了最优平衡。

## 维护与演进系统

长期成功的关键，在于把知识管理系统当作一个随组织共同成长的动态体。为了让 knowledge base 保持最新，部署过程会在知识仓库上配置 Amazon S3 事件通知：当文档被新增或删除时，存储桶会调用一个 AWS Lambda 函数，后者自动启动 Bedrock Knowledge Bases 摄取作业，无需任何人工步骤就把变更重新嵌入到向量存储中。由于摄取不是瞬时的，更新后的内容会在该同步完成后不久变得可查询。回答缓存上按内容类型区分的 TTL 设置与这一机制形成互补：基础流程留存更久，动态信息刷新更频繁。

为保证准确性，回答由 Amazon Bedrock Knowledge Bases 生成，它把每个回应都建立在从你自己经过核实的文档中检索出的段落之上，而不是模型的通用训练数据。这种以检索内容为根基（grounding）的做法降低了编造或离题回答的可能性，knowledge base 还能返回来源引用，你可以把它们呈现给用户以便核实。这种 grounding 降低但不能消除错误回答的风险：对于高后果或与安全相关的决策，请保留人在环中，并把系统当作决策支持，而不是权威来源。对于这类用例，显式的置信度阈值或回答校验检查是建议的增强项，本原型并未实现。

安全始终是系统维护中不可分割的一部分。定期的自动化审计会核查访问控制与数据保护措施，而模块化架构支持直接了当的安全更新。组织可以集成新的安全要求或合规措施，而不打断现有功能。

系统的灵活性也延伸到内容管理。当团队记录新流程或更新既有流程时，可以把它们上传到 knowledge base，后者会自动纳入这些变更。这种持续演进确保系统始终是机构知识的可靠来源，在适应组织变化的同时，在需要处保留历史脉络。

## 结论

借助我们的知识管理方案，你可以打造一件保存机构知识的有力工具。通过使用 AWS 服务并遵循模块化设计，组织既能维护自己的智力资本，又能促进知识在员工之间高效传递。系统的灵活性与可扩展性使其适用于多种行业和用例，为数字时代的可持续知识管理提供基础。要开始使用，请在 GitHub 网站上克隆[示例仓库](https://github.com/aws-samples/sample-bedrock-knowledge-management-avatar-system)，并在你自己的 AWS 账户中部署该方案。要进一步了解，请在 Amazon Bedrock 控制台中探索 Amazon Bedrock Knowledge Bases。
