# Announcing AI data preparation capabilities in Amazon SageMaker: Build high-quality datasets for model development workflows

Teams that ship generative AI to production know that a model is only as good as its data. That is why preparing high-quality training and evaluation data comes first. Fine-tuning an open-weight model, running reinforcement learning, or building an evaluation suite all depend on data that is accurate, well-labeled, and representative of your task. For narrow, well-defined tasks, a smaller model customized on clean, task-specific data can often match or exceed the accuracy of a larger general-purpose model prompted into shape, at a lower cost per inference.

In practice, though, preparing that data is often the slowest part of the project. Labeled examples are scarce or expensive, and privacy rules limit what you can use. Quality problems such as duplicates, label noise, and answer leakage go unnoticed until a training run disappoints, and every training technique expects data in its own format. As a result, data scientists spend weeks wrangling data instead of building models.

Today, we’re expanding Amazon SageMaker AI with new AI data preparation capabilities for model development workflows. You can generate synthetic examples, assess and improve existing datasets, and bring expert feedback into the process through Python SDK APIs and the AWS AI-ML agent skill. You work in your notebook or IDE, with specifications and code that you can inspect and change.

## Prepare data without hand-building pipelines

With AI Data Preparation capabilities, you don’t need to stitch together labeling tools, generation scripts, and validation jobs. Each capability is a standalone building block. You can use one of them on its own or chain them together according to the workflow you want.

- **Auto-labeling:** Label data at scale from an unlabeled dataset, a small labeled seed set, or no labels at all. Built-in task types include classification, named entity recognition, extractive question answering, ordinal rating, and summarization, and you can define custom tasks. You describe the task in a short labeling spec, which is validated against your own examples before the full dataset is labeled. For tasks with a fixed set of possible answers, such as classification, named entity recognition, and extractive question answering, a jury of several models labels each row, and their level of agreement becomes that row’s confidence score.
- **Human review:** Rows below your confidence threshold go to a review queue in Amazon SageMaker Studio, which uses the open-source Label Studio Community Edition. Outside subject matter experts can access the review app through the link in the partner app box in SageMaker Studio. Reviewer corrections feed back into auto-labeling, and you can generate consensus metrics and labeling reports.
- **Synthetic data generation:** Generate training, evaluation, and test data from a specification. You can ground the output in your own seed data and documents, and the service generates a code-based data generation pipeline that you can review, modify, reuse, and scale.
- **Data quality evaluation:** Check datasets against your own business rules, built-in metrics, and LLM-as-a-judge metrics. Find duplicates and near-duplicates, and surface issues you didn’t think to check for, such as label noise or answer leakage.
- **Data transformation:** Clean and reshape data for your target training technique. Describe the change in plain language and have the code generated for you, use built-in operations such as dedupe, merge, split, and filter, or run your own Python at scale.

You work wherever you already work. Use the SageMaker Python SDK directly or provide your coding agent the AI-ML skill in the agent toolkit and let your agent invoke the APIs according to established data science best practices. Describe what you need, and the agent selects and runs the right capability in SageMaker Studio JupyterLab, Kiro, or your local IDE with your coding assistant of choice.

## Chain capabilities from raw data to training

The value grows when you combine the capabilities. Some common patterns:

Build a golden evaluation dataset: Auto-label your raw data from a small seed set. High-confidence rows are accepted automatically, and low-confidence rows go to human reviewers. Their corrections improve the next labeling pass, resulting in a trusted, human-validated dataset to benchmark your models against.

Go from raw documents to a trained model in one workflow:

- **Generate data:** Synthetic data generation creates task-specific examples grounded in your documents and seed data.
- **Transform it:** Data transformation reshapes the data into the format your training technique expects, such as supervised fine-tuning (SFT), direct preference optimization (DPO), or reinforcement learning (RL).
- **Validate it:** Data quality evaluation checks the dataset for duplicates, leakage, and rule violations before you spend compute on training.
- **Train:** Train with SageMaker AI model customization.

## How it works

Consider a team preparing data to evaluate agentic customer support assistants. Its product guide says that a factory reset erases saved settings. The team wants to test whether the assistant preserves that warning when answering reset questions.

One pass through the preparation workflow looks like this:

- **Define the requirements:** Supply the product guide as context and describe the questions and reference answers you need. Include the requirement that answers about a factory reset preserve the warning about saved settings. Review the specification produced with your coding agent.
- **Generate and inspect a sample:** Generate a small batch and check the records against the guide. Review the generation and check the code. Confirm that the examples cover the intended questions and that the reference answers follow the source material.
- **Assess and review:** Run a data quality assessment and inspect the record-level findings. Ask a subject matter expert to review ambiguous answers or disputed assessments. Use the results and annotations to request improvement recommendations.
- **Apply changes and repeat:** Revise the specification if the requirements need clarification or transform the dataset to address issues such as duplicates. Generate additional examples where needed, then reassess the revised dataset before using it to evaluate the assistant.

This example workflow illustrates how the capabilities fit together.

## Keep control of your preparation workflow and data

With the AI-ML skill, you describe the task in natural language while your coding agent helps build specifications, prepare code, and coordinate the data preparation steps. You can open those artifacts to see how the workflow is configured and make changes directly.

If you prefer to invoke the APIs yourself, use the Python SDK APIs to call individual capabilities from your own code. The SDK APIs take a specification as input, so we recommend creating it with the help of an agent. You can add quality assessment to an existing process, generate data for a new task, or combine several operations. You choose the preparation steps your project needs and how they fit into your model customization and evaluation processes.

AI Data Preparation runs with an AWS Identity and Access Management (IAM) execution role that you control. Your source data, generated datasets, and labels stay in your own Amazon Simple Storage Service (Amazon S3) buckets, in the AWS Region you choose.

## Get started today

The AI data preparation capabilities are generally available in the US East (N. Virginia) and US West (Oregon) Regions.

There are two ways to get started:

- **With your coding agent –** Set up the [data preparation skills](https://github.com/aws/agent-toolkit-for-aws/tree/main/skills/core-skills/aws-ai-ml/references) in your supported notebook or IDE. Describe one training or evaluation task and review the resulting specification before generating a sample.
- **With Python –** Use the SageMaker Python SDK directly to run individual data preparation capabilities from your own code. The SDK takes a specification as input, so we recommend creating your specifications with the AI-ML skill first, then using the SDK to run them in your workflow.

For more information, see the [Amazon SageMaker AI](https://docs.aws.amazon.com/sagemaker/latest/dg/ai-data-preparation.html) documentation.
