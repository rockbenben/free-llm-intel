# Amazon SageMaker 推出 AI 数据准备功能：为模型开发工作流构建高质量数据集

把生成式 AI 交付到生产环境的团队都清楚一个道理：模型的表现，最终取决于它所使用的数据。也正因如此，准备高质量的训练数据和评估数据，必须放在整个项目的第一位。不论是微调一个开放权重模型、运行强化学习，还是搭建一套评估套件，背后都依赖准确、标注良好、并且足以代表你的任务的数据。而对于范围窄、定义明确的任务，用一个在干净的任务专属数据上定制出来的小模型，往往就能以更低的单次推理成本，达到甚至超过一个需要靠 prompt 反复调教才能胜任的大型通用模型。

但在实践中，准备这些数据常常是整个项目里最慢的一环。可用的标注样本要么稀缺，要么昂贵，隐私方面的规则又限定了你能够使用哪些数据。重复样本、标签噪声、答案泄漏这类质量问题，往往要等到某一次训练结果令人失望时才会被发现；与此同时，每一种训练技术又都要求数据符合自己的一套格式。结果是，数据科学家把几周的时间花在整理数据上，而不是用来构建模型。

今天，我们为 Amazon SageMaker AI 增加了一组面向模型开发工作流的 AI 数据准备功能。你可以生成合成样本，可以评估并改进现有的数据集，还可以通过 Python SDK API 和 AWS AI-ML agent skill 把专家反馈引入到流程当中。你依然在自己的 notebook 或 IDE 里工作；整个过程中产生的规格说明和代码，你都可以打开查看，也可以按需修改。

## 无需手工搭建流水线即可准备数据

借助 AI 数据准备功能，你不必再自己动手，把标注工具、生成脚本和验证作业硬拼成一条流水线。这里的每一项功能都是一个独立的构建块：你既可以单独使用其中的某一项，也可以按照自己想要的工作流，把它们依次串联起来，组成一条完整的链路。

- **自动标注：** 可以从一份无标注数据集出发，也可以只靠一个小型的标注种子集，甚至在完全没有标签的情况下，对大规模的数据完成标注。内置的任务类型包括分类、命名实体识别、抽取式问答、序数评分和摘要，你也可以定义自己的自定义任务。你用一份简短的标注规格来描述任务，在开始全量标注之前，这份规格会先拿你自己的示例做一遍验证。对于答案集合固定的任务，例如分类、命名实体识别和抽取式问答，系统会让多个模型组成一个评审团，为每一行数据打标，它们之间的一致程度，就成为这一行的置信度分数。
- **人工复核：** 低于你所设置信度阈值的行，会进入 Amazon SageMaker Studio 里的复核队列，这个队列使用的是开源的 Label Studio Community Edition。外部领域专家可以通过 SageMaker Studio 合作伙伴应用框里的链接，访问这个复核应用。复核者做出的修正会回流到自动标注环节，你还可以据此生成共识指标和标注报告。
- **合成数据生成：** 按一份规格生成训练、评估和测试所需的数据。你可以让自己的种子数据和文档作为输出的依据，服务则会生成一条基于代码的数据生成流水线，供你审查、修改、复用和扩展。
- **数据质量评估：** 用你自己的业务规则、内置指标以及 LLM-as-a-judge 指标来检查数据集。它会帮你找出重复项和近似重复项，并暴露出你原本没想到要去检查的问题，例如标签噪声或者答案泄漏。
- **数据转换：** 为目标训练技术清洗并重塑数据。你可以用自然语言描述想要做的改动，让系统为你生成代码；也可以使用去重、合并、拆分、过滤等内置操作；还可以大规模地运行你自己的 Python 代码。

你可以在自己本来就熟悉的环境里工作。你可以直接使用 SageMaker Python SDK，也可以把 agent 工具包中的 AI-ML skill 提供给你的编码 agent，让 agent 按照既定的数据科学最佳实践去调用这些 API。你只需要描述清楚自己的需求，agent 就会在 SageMaker Studio JupyterLab、Kiro 或者本地 IDE 中，挑选并运行合适的功能，配合你自己选择的编码助手。

对于构建专用模型的团队来说，最困难的部分往往是为特定的任务找到足够的数据。Cisco 旗下的 Splunk 在为其 Agent Observability 产品构建评估模型时，遇到的正是这个问题。

> “对 Splunk Agent Observability 而言，我们能否训练出稳健的 GenAI Eval 模型，取决于能否拿到高质量、多样化的数据集，而这类数据在非常具体的任务上极难整理。Amazon SageMaker AI 面向合成数据生成的数据准备功能，正在切实帮助我们把这些能力规模化。我们能够可靠且快速地生成具备统计代表性的合成数据集，同时保留模型所依赖的底层模式。与 SageMaker 工作流其余部分的无缝集成，意味着我们的数据科学家和客户花在整理数据上的时间更少，花在构建真正通过 Splunk 创造企业价值的模型上的时间更多。”
>         — Yash Sheth，Splunk Agent Observability 工程总监

## 从原始数据一路串到训练

把几项功能组合起来使用，价值会进一步放大。下面列出几种常见的组合方式。

构建一份黄金评估数据集：先用手头一个小型的种子集，对原始数据做自动标注。置信度高的行会被自动采纳，置信度低的行则转给人工复核。复核者做出的修正，会用来改进下一轮标注，最终得到的是一份可信、经过人工验证的数据集，用来对你的模型做基准测试。

从原始文档到训练好的模型，用一条工作流就能走完：

- **生成数据：** 合成数据生成会以你的文档和种子数据为依据，创建出任务专属的样本。
- **转换数据：** 数据转换把数据重塑成目标训练技术所要求的格式，例如监督微调（SFT）、直接偏好优化（DPO）或者强化学习（RL）。
- **验证数据：** 在你把算力花到训练上之前，数据质量评估会先检查数据集里是否存在重复、泄漏和规则违规。
- **训练：** 使用 SageMaker AI 的模型定制功能进行训练。

## 工作原理

设想有一个团队正在准备数据，用来评估 agentic 客户支持助手。它的产品指南里写着：恢复出厂设置会清除已保存的设置。团队想要测试的是，助手在回答重置类问题时，是否保住了这条警告。

把数据准备流程完整地走一遍，大致是这样的：

- **明确需求：** 把产品指南作为上下文提供给系统，并描述你需要哪些提问、以及各自对应的参考答案。其中要包含一条要求：凡是关于恢复出厂设置的答案，都必须保留“已保存设置会被清除”这条警告。审查由你的编码 agent 生成的规格。
- **生成并抽查样本：** 先生成一小批数据，再对照指南逐条检查其中的记录。审查生成过程，也审查用来检查的代码。确认这些示例覆盖了你预期的问题，并且参考答案遵循了源材料。
- **评估与复核：** 运行一次数据质量评估，查看记录级别的发现。请领域专家复核那些含义模糊的答案，或者有争议的评估结论。再根据这些结果和标注，请系统给出改进建议。
- **应用改动并重复：** 如果需求需要澄清，就修订规格；或者转换数据集，来处理重复之类的问题。在需要的地方补充更多示例，然后对修订后的数据集重新评估一次，确认没问题之后，再拿它去评估助手。

上面这个示例工作流，展示了这些功能在实际项目中是如何彼此衔接的。

## 掌控你的数据准备流程与数据

借助 AI-ML skill，你用自然语言描述任务，编码 agent 会帮你构建规格、准备代码，并协调数据准备的各个步骤。你随时可以打开这些产物，看清工作流是如何配置的，也可以直接在上面做修改。

如果你更愿意自己调用 API，也可以用 Python SDK API 从自己的代码里调用单项功能。SDK API 以规格作为输入，因此我们建议在 agent 的协助下，先把规格创建好。你可以把质量评估加到已有的流程里，可以为新任务生成数据，也可以把多项操作组合起来。项目需要哪些准备步骤，以及这些步骤如何嵌入你的模型定制与评估流程，都由你来决定。

AI 数据准备以你掌控的 AWS Identity and Access Management（IAM）执行角色运行。你的源数据、生成的数据集和标签，都保留在你自己的 Amazon Simple Storage Service（Amazon S3）存储桶中，位于你选定的 AWS 区域。

## 立即开始

AI 数据准备功能目前在美国东部（弗吉尼亚北部）和美国西部（俄勒冈）区域正式可用。

目前有两种方式可以上手：

- **用你的编码 agent——** 在受支持的 notebook 或 IDE 中配置[数据准备 skills](https://github.com/aws/agent-toolkit-for-aws/tree/main/skills/core-skills/aws-ai-ml/references)。描述一个训练或评估任务，并在生成样本之前，先审查产出的规格。
- **用 Python——** 直接使用 SageMaker Python SDK，从自己的代码中运行各项数据准备功能。SDK 以规格作为输入，所以我们建议先用 AI-ML skill 创建规格，再用 SDK 在工作流中运行它们。

更多信息，请参阅 [Amazon SageMaker AI](https://docs.aws.amazon.com/sagemaker/latest/dg/ai-data-preparation.html) 文档。
