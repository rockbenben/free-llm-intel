# 使用 Amazon Bedrock AgentCore 构建 FinOps agent

在多个 AWS 账户之间管理成本，往往需要财务团队从多个来源查询数据，才能得到支出与优化机会的完整视图。在本文中，你将学习如何使用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 构建一个 FinOps agent，帮助你的财务团队跨多个账户管理 AWS 成本。这个对话式 agent 把来自 [AWS Cost Explorer](https://aws.amazon.com/aws-cost-management/aws-cost-explorer/)、[AWS Budgets](https://aws.amazon.com/aws-cost-management/aws-budgets/) 和 [AWS Compute Optimizer](https://aws.amazon.com/compute-optimizer/) 的数据整合到一个界面里，让你的团队可以问“这个月我的主要成本驱动因素是什么？”并立刻得到答案。

你将学会搭建架构、使用 [AWS Cloud Development Kit（AWS CDK）](https://aws.amazon.com/cdk/) 部署方案，并通过自然语言查询与成本数据交互。该方案使用 AgentCore、[Anthropic Claude Sonnet 4.5](https://aws.amazon.com/blogs/aws/introducing-claude-sonnet-4-5-in-amazon-bedrock-anthropics-most-intelligent-model-best-for-coding-and-complex-agents/)、[Strands Agent SDK](https://strandsagents.com/) 和 [Model Context Protocol（MCP）](https://aws.amazon.com/solutions/guidance/deploying-model-context-protocol-servers-on-aws/)。

你将拥有保留 30 天上下文的对话记忆，因此可以追问而不必重复信息。20 多个专用工具覆盖从分析到优化的完整成本管理谱系，免去在多个 AWS 控制台之间手动切换的需要。自然语言交互让组织内各团队成员都能方便地使用成本数据。

## 方案概览

该方案由两个主要部分组成：身份验证与前端层，以及带工具和记忆的 [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html)。[Amazon Cognito](https://aws.amazon.com/cognito/) 管理用户身份验证，AgentCore Runtime 处理成本管理查询。身份验证与前端层使用 [AWS Amplify](https://aws.amazon.com/amplify/) 托管 Web 应用界面，并用 Amazon Cognito 做用户身份验证。Amazon Cognito 负责用户认证，并通过 Identity Pools 提供临时 AWS 凭证。

用于 FinOps 的自定义 agent 托管在 AgentCore Runtime 上，用 Strands Agent 构建，并与 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 集成以访问[大语言模型（LLM）](https://aws.amazon.com/what-is/large-language-model/)。[Amazon Bedrock AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 通过 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam/) 身份验证来管理工具调用，并把请求路由到后端服务。MCP Server 托管在 AgentCore Runtime 上，提供对 AWS Billing and Cost Management 工具的访问。[AgentCore Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html) 维护对话历史，最多保留 30 天上下文。[AgentCore Identity](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity.html) 管理 OAuth 2.0 凭证的生命周期，保障 Gateway 与 MCP server 运行时之间的安全通信。它把 Amazon Cognito 的 M2M 客户端凭证存为 OAuth 凭证提供者，并在 Gateway 需要与 MCP 运行时认证时，代表 Gateway 签发 token。

这些组件就位之后，下一节将审视它们在完整架构中如何协同工作。

## 架构图

下图展示了方案架构，其中包含五个关键部分：

[![FinOps AgentCore Agent 架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/17/1.FinOpsAgentCoreAgent-Diagram-1.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/17/1.FinOpsAgentCoreAgent-Diagram-1.png)

**A 部分**——身份验证基础设施**：**首先，`FinOpsAuthStack` CDK 堆栈部署身份验证基础设施（Amazon Cognito User Pool、Identity Pool、M2M 客户端、resource server 和 IAM 角色）。User Pool 负责用户身份验证，M2M 客户端在 Gateway 与 MCP 运行时之间启用机器对机器的 OAuth 2.0 流程，Identity Pool 则提供临时 AWS 凭证，让前端应用能安全地与 AgentCore Runtime 通信。

**B 部分**——镜像构建基础设施**：**接着，`FinOpsImageStack` CDK 堆栈部署容器镜像构建 pipeline（Amazon S3 存储桶、[AWS CodeBuild](https://aws.amazon.com/codebuild/) 项目和 [Amazon Elastic Container Registry（Amazon ECR）](https://aws.amazon.com/ecr/) 仓库）。CodeBuild 克隆上游 AWS Labs 的 MCP server，应用 stdio 到 HTTP 的转换（为 streamable-http 传输打补丁），并构建 AWS Graviton（ARM64）容器镜像，存入 Amazon ECR 供 AgentCore Runtime 使用。

**C 部分**——MCP Server 运行时**：**`FinOpsMCPRuntimeStack` CDK 堆栈部署两个 AgentCore Runtime，分别运行转换后的 AWS Labs MCP server（Billing 与 Pricing）。每个运行时都用 AuthStack 的 Amazon Cognito 配置 JWT 授权，并对其访问的 AWS API 拥有特定的 IAM 权限。例如，Billing 运行时对应 AWS Billing and Cost Management 和 AWS Compute Optimizer，Pricing 运行时对应 AWS Pricing。

**D 部分**——AgentCore Gateway**：**`FinOpsAgentCoreGatewayStack` CDK 堆栈部署 AgentCore Gateway，使用 AWS_IAM 授权、一个 OAuth 凭证提供者（用 AuthStack 的 Cognito M2M 凭证注册到 AgentCore Identity），以及两个指向 Billing 和 Pricing 运行时的 MCP server target。Gateway 提供统一的工具发现与调用端点，处理向 MCP 运行时出站认证所需的 OAuth token 交换。

**E 部分**——主 Agent Runtime**：**最后，`FinOpsAgentRuntimeStack` CDK 堆栈部署主 AgentCore Runtime。它使用 Strands Agent Framework 和 Claude Sonnet 3.7，通过 Gateway 编排模型调用与工具调用。它还部署 AgentCore Memory 以保存对话历史。Runtime 通过 IAM SigV4 身份验证连接到 Gateway，从两个 MCP server 发现 24 个工具，并把工具请求经 Gateway 路由，以取回成本、账单和定价数据。

### 使用 Web 应用

现在你已经理解了架构，我们来走一遍示例请求流程。例如，当用户问“我 2026 年 1 月的 AWS 费用是多少？”时会发生什么？

- FinOps 用户访问托管在 AWS Amplify 上的 Web 应用，该应用提供前端（HTML、CSS、JavaScript）。
- 用户通过 Amazon Cognito 进行身份验证。Amazon Cognito 校验凭证，并从 Identity Pool 返回临时 AWS 凭证。
- 前端把用户的问题发送到 AgentCore Runtime，并用临时 AWS 凭证调用 `InvokeAgentRuntime`。
- 运行时内的 Strands agent 把问题连同 24 个可用工具定义一起发送给 Amazon Bedrock 上的 Claude Sonnet 4.5。模型分析问题后，判断需要调用 `billingMcp__cost_explorer`
- agent 收到模型发来的工具调用请求，并用 IAM SigV4 身份验证（`InvokeGateway`）把它路由到 AgentCore Gateway。
- Gateway 必须与 MCP 运行时完成身份验证。它联系 AgentCore Identity，用已注册的凭证提供者（由 Cognito M2M 客户端凭证支持）获取 OAuth 2.0 token。
- Gateway 带着 OAuth token 把 MCP tools/call 请求发送到 Billing MCP Runtime。
- Billing MCP Runtime 使用其执行角色，向 AWS Cost Explorer 执行实际的 API 调用，请求 2026 年 1 月的成本与用量数据。
- 成本数据沿链路回流。Billing MCP Runtime 响应 Gateway，然后 Gateway 响应 agent。agent 把成本数据发回 Amazon Bedrock，由 Claude 生成 2026 年 1 月成本的自然语言摘要。
- 格式化后的响应返回给 FinOps 用户，在聊天界面中展示成本明细。

## 先决条件

开始之前，请确认你已具备：

- 一个 [AWS 账户](https://signin.aws.amazon.com/signup?request_type=builderId)，并对以下服务拥有相应权限：Amazon Bedrock、AgentCore、Amazon ECR、AWS Lambda、Amazon Cognito、AWS CodeBuild 和 IAM
- 已配置凭证的 [AWS Command Line Interface（AWS CLI）](https://aws.amazon.com/cli/)（v2.x）
- 已安装 [Node.js](https://nodejs.org/)（v18 或更高版本）和 [npm](https://www.npmjs.com/)
- 已安装 [Python](https://www.python.org/) 3.13 或更高版本
- 已安装 [AWS CDK](https://docs.aws.amazon.com/cdk/v2/guide/getting-started.html)，并已在你的 AWS 账户中完成 bootstrap。安装：`npm install -g aws-cdk`；bootstrap：`cdk bootstrap aws://AWS-ACCOUNT-NUMBER/AWS-REGION`

## 使用 AWS CDK 部署方案

该方案部署到 `us-east-1` AWS 区域。部署使用 AWS CDK，通过三个 [AWS CloudFormation](https://aws.amazon.com/cloudformation/) 堆栈来置备基础设施。

部署步骤如下：

### 步骤 1：克隆仓库

```
git clone https://github.com/aws-samples/sample-finops-agent-amazon-bedrock-agentcore
cd sample-finops-agent-amazon-bedrock-agentcore
```

### 步骤 2：设置环境变量

把 your-email@example.com 替换成你的邮箱地址，以接收临时管理员密码：

```
export ADMIN_EMAIL="your-email@example.com"
```

### 步骤 3：使用 CDK 部署

```
cd cdk && npm install && npm run build && npx cdk bootstrap && npx cdk deploy --all --require-approval never
```

部署脚本会安装 CDK 依赖、构建 TypeScript 代码、在需要时 bootstrap CDK，然后依次部署三个堆栈。整个过程大约需要 15-20 分钟。完成后，你的账户中将有五个 CloudFormation 堆栈。

最后一个 CloudFormation 堆栈 `FinOpsAgentRuntimeStack` 部署完成后，请记下终端中的以下输出：

- `User Pool Id` – Cognito Identity Pool ID
- `User Pool Client Id` – Cognito User Pool Client ID
- `Identity Pool Id` – Identity Pool ID
- `AgentCore ARN` – AgentCore runtime ARN

下面的截图展示了这些输出会是什么样子。

[![FinOps AgentCore 的 CloudFormation 输出](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/17/2.FinOpsAgentCore-CFN-Output.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/17/2.FinOpsAgentCore-CFN-Output.png)

## 部署 Amplify 应用

虽然我们提供了一个托管在 AWS Amplify 上的示例前端，但你可以把方案集成到你自己的定制前端，或连接到现有的企业沟通工具。前端应用需要用 GitHub 仓库中的代码手动部署：

- 从 [GitHub](https://github.com/aws-samples/sample-finops-agent-amazon-bedrock-agentcore/blob/main/amplify-frontend/AWS-Amplify-Frontend.zip) 下载前端代码 `AWS-Amplify-Frontend.zip`。
- 在 [AWS Management Console](https://console.aws.amazon.com/) 中打开 AWS Amplify。
- 选择 **Deploy without Git provider**。
- 上传应用的 .zip 文件。
- 等待部署完成。
- 记下生成的域名 URL。

## 理解 MCP server

MCP server（[AWS Billing and Cost Management MCP Server](https://awslabs.github.io/mcp/servers/billing-cost-management-mcp-server/) 和 [AWS Pricing MCP Server](https://awslabs.github.io/mcp/servers/aws-pricing-mcp-server)）提供成本管理与定价工具。每个 MCP server 都设计用来处理特定类型的查询。AWS Billing and Cost Management MCP Server 侧重历史支出分析、预算监控、成本异常检测和优化建议，使用的是你实际的 AWS 账户数据。AWS Pricing MCP Server 处理前瞻性查询，从 AWS Price List API 提供实时定价数据，从而能为新工作负载和基础设施即代码（IaC）项目做成本估算。

## 使用 Web 应用

打开创建 AWS Amplify 应用后得到的 URL。系统会提示你输入 Amazon Cognito 和 AgentCore 的配置信息。填入你（先前收集的）堆栈输出中的值。在 Agent Type 菜单里选择 **AgentCore Agent**，输入部署区域，并选择一个 Agent Name（本例中我们使用 **AgentCore Agent**）。保存配置，如下图所示：

[![FinOps 前端配置界面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/17/3.FinOpsFrontEndConfiguration-632x1024.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/17/3.FinOpsFrontEndConfiguration.png)

用你的用户名和发送到邮箱的临时密码登录。首次登录时，系统会要求你重置密码。重置密码后，你就可以开始提问了。例如，问一句“`What are my AWS costs for January 2026?`”。当你询问成本时，系统会用 `get_cost_and_usage` 工具取回你的成本数据，并按服务给出详细明细。

问一句“`What are my current cost savings opportunities?`”。agent 会调用多个工具来识别优化机会：

- `get_rightsizing_recommendations` – 识别过度配置或利用率不足的资源
- `get_savings_plans_recommendations` – 建议基于承诺的折扣计划
- `get_compute_optimizer_recommendations` – 提供计算优化洞察

接着问“`Can you give me details of any underutilized EC2 instances?`”。因为有对话记忆，追问会延续上一个问题的上下文，并给出关于具体实例的详细信息。

## 清理

为避免产生后续费用，请删除本方案创建的资源。

**删除堆栈：**

```
cd sample-finops-agent-amazon-agentcore/cdk

npx cdk destroy --all
```

系统会询问：

`Are you sure you want to delete: FinOpsAgentRuntimeStack, FinOpsAgentCoreGatewayStack, FinOpsMCPRuntimeStack, FinOpsAuthStack, FinOpsImageStack (y/n)`

输入 `y` 即可删除这些堆栈。

**删除 Amplify 应用：**

- 在 Amplify 控制台中，从你应用的左侧导航选择 **App settings**，然后选择 **General settings**。
- 在 **General settings** 区域选择 **Delete app**。

## 结论

在本文中，我们展示了如何使用 AgentCore 构建一个 FinOps agent。这个 agent 通过整合来自 AWS Cost Explorer、AWS Budgets 和 Compute Optimizer 的数据，提供对成本分析和优化建议的自然语言访问。

该架构结合了 AgentCore Runtime、Gateway、Memory、Identity，以及 Strands Framework、MCP 和 Claude Sonnet 4.5。你可以把这一基础扩展到其他使用场景，例如 DevOps 自动化、安全分析和合规监控。今天就从访问 [GitHub 仓库](https://github.com/aws-samples/sample-finops-agent-amazon-agentcore) 开始吧。
