# Harnessing Amazon Bedrock generative AI for resilient supply chain

From pandemic shutdowns to geopolitical tensions, recent years have thrown our global supply chains into unexpected chaos. This turbulent period has taught both governments and organizations a crucial lesson: supply chain excellence depends not just on efficiency but on the ability to navigate disruptions through strategic risk management. By leveraging the generative AI capabilities and tooling of [Amazon Bedrock](https://aws.amazon.com/bedrock/), you can create an intelligent nerve center that connects diverse data sources, converts data into actionable insights, and creates a comprehensive plan to mitigate supply chain risks.

Amazon Bedrock is a fully managed service that enables the development and deployment of generative AI applications using high-performance [foundation models](https://aws.amazon.com/what-is/foundation-models/) (FMs) from leading AI companies through a single API.

[Amazon Bedrock Flows](https://aws.amazon.com/bedrock/flows/) enable you to quickly build and scale predefined generative AI workflows by linking FMs, prompts, [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/), [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents) and other AWS services such as [Amazon Simple Storage Service](https://aws.amazon.com/s3/) (Amazon S3), [AWS Lambda](https://aws.amazon.com/lambda/) and [Amazon Lex](https://aws.amazon.com/lex/). Its visual workflow builder and serverless infrastructure enables organizations to accelerate the development and deployment of AI-powered supply chain solutions, improving agility and resilience in the face of evolving challenges. We are excited to announce that Flows is now available in both AWS GovCloud (US) Regions in addition to [15 commercial regions](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-supported.html).

This post walks through how Amazon Bedrock Flows connects your business systems, monitors medical device shortages, and provides mitigation strategies based on knowledge from Amazon Bedrock Knowledge Bases or data stored in Amazon S3 directly. You’ll learn how to create a system that stays ahead of supply chain risks.

## Business workflow

The following is the supply chain business workflow implemented in Flows.

![workflow](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-workflow.png)

The following are the steps of the workflow in detail:

- The JSON request with the medical device name is submitted to the prompt flow.
- The workflow determines if the medical device needs review by following these steps:

- The assistant invokes a Lambda function to check the device classification and any shortages. If there is no shortage, the workflow informs the user that no action is required. If the device classification is 3 (high-risk medical devices that are essential for sustaining life or health) and there is a shortage, the assistant determines the necessary mitigation steps Devices with classification 3 are treated as high-risk devices and require a comprehensive mitigation strategy. The following steps are followed in this scenario.  [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) RetrieveAndGenerate API creates a comprehensive strategy. The flow emails the mitigation to the given email address.  If the device classification is 2 (medium-risk medical devices that can pose harm to patients) and there is a shortage, the flow lists the mitigation steps as output. Classification device 2 doesn’t require a comprehensive mitigation strategy. We recommend to use these when the information retrieved fits the context size of the model. Mitigation is fetched from Amazon S3 directly. If the device classification is 1(low-risk devices that don’t pose significant risk to patients) and there is a shortage, the flow outputs only the details of the shortage because no action is required.

## Solution overview

The following diagram illustrates the solution architecture. The solution uses Amazon Bedrock Flows to orchestrate the generative AI workflow. An Amazon Bedrock flow consists of [nodes](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-nodes.html), which is a step in the flow and connections to connect to various data sources or to execute various conditions.

![architecture](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML-17903-architecture.png)

The system workflow includes the following steps:

- The user interacts with generative AI applications, which connect with Amazon Bedrock Flows. The user provides information about the device.
- A workflow in Flows is a construct consisting of a name, description, permissions, a collection of nodes, and connections between nodes.
- A Lambda function node in Flows is used to invoke AWS Lambda to get supply shortage and device classifications. AWS Lambda calculates this information based on the data from [Amazon DynamoDB](https://aws.amazon.com/dynamodb/).
- If the device classification is 3, the flow queries the knowledge base node to find mitigations and create a comprehensive plan. [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) can be applied in a knowledge base node.
- A Lambda function node in Flows invokes another Lambda function to email the mitigation plan to the users. AWS Lambda uses [Amazon Simple Email Service](https://aws.amazon.com/ses/) (Amazon SES) SDK to send emails to verified identities.
- Lambda functions are within the private [subnet](https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html) of [Amazon Virtual Private Cloud](https://aws.amazon.com/vpc/) (Amazon VPC) and provide least privilege access to the services using [roles](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html) and [permissions policies](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies.html). AWS Lambda uses [gateway endpoints](https://docs.aws.amazon.com/vpc/latest/privatelink/gateway-endpoints.html) or [NAT gateways](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-nat-gateway.html) to connect to Amazon DynamoDB or Amazon SES, respectively
- If the device classification is 2, the flow queries Amazon S3 to fetch the mitigation. In this case, comprehensive mitigation isn’t needed, and it can fit in the model context. This reduces overall cost and simplifies maintenance.

## Prerequisites

The following prerequisites need to be completed before you can build the solution.

- Have an AWS account.
- [Have an Amazon VPC](https://docs.aws.amazon.com/lambda/latest/dg/configuration-vpc-internet.html) with private subnet and public subnet and egress internet access.
- This solution is supported only in US East (N. Virginia) us-east-1 [AWS Region](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region). You can make the necessary changes to your [AWS CloudFormation](https://aws.amazon.com/cloudformation/) template to deploy to other Regions.
- Have permission to create Lambda functions and configure [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/)
- [Have permissions](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-management-prereq.html) to create Amazon Bedrock prompts.
- Sign up for model access on the [Amazon Bedrock console](https://console.aws.amazon.com/bedrock) (for more information, refer to [model access](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html) in the Amazon Bedrock documentation). For information about pricing for using Amazon Bedrock, refer to [Amazon Bedrock pricing](https://aws.amazon.com/bedrock/pricing/). For this post, we use Anthropic’s Claude 3.5 Sonnet, and all instructions pertain to that model.
- [Enable AWS CloudTrail logging](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-create-and-update-a-trail.html) for operational and risk auditing.
- [Enable budget policy](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-controls.html) notification to protect the customer from unwanted billing.
