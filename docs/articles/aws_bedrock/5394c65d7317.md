# 使用 Amazon Bedrock AgentCore 的全栈入门模板加速 agentic 应用开发

生成式 AI 与 agentic 应用正在重塑企业的运营方式——从客户支持机器人到研究助理——团队需要快速从原型走向生产。去年，AWS 发布了 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/)——一个用于在生产环境中构建、部署和扩展 AI agent 的开发平台。AgentCore 提供运行时托管、memory、工具集成和可观测性等核心构建块，并具备企业级安全性和动态扩展能力。

[全栈 AgentCore 解决方案模板（FAST，Fullstack AgentCore Solution Template）](https://github.com/awslabs/fullstack-solution-template-for-agentcore)从一开始就向你展示这些组件如何协同工作。它是一个可直接部署的入门项目，把 AgentCore Runtime、Gateway、Memory 和 Code Interpreter 与 [React](https://react.dev/) 前端和 [Amazon Cognito](https://aws.amazon.com/cognito/) 认证连接起来——所有这些都用 [AWS Cloud Development Kit（AWS CDK）](https://aws.amazon.com/cdk/) 定义。FAST 提供完整的参考架构，展示各部分如何集成，并附带一个可运行的聊天应用，供你学习并在此基础上继续构建。

在本文中，你将学习如何把 FAST 部署到你的 [Amazon Web Services（AWS）](https://aws.amazon.com/)账户，理解其架构，并了解如何按你的需求扩展它。你将学习如何构建自己的 agent，而由 FAST 负责认证、基础设施即代码（IaC）、部署流水线和服务集成。

## 解决方案概述

FAST 提供了在 Amazon Bedrock AgentCore 上部署 agent 的完整全栈架构。该模板默认处理认证、前端应用托管、agent 运行时、memory、可观测性以及 Model Context Protocol（MCP）工具集成。

![AWS 架构图：一个使用 Amazon Bedrock AgentCore 的 AI agent 应用，包含多 agent 编排，用户通过 Cognito 认证，涉及 API Gateway、Lambda 计算层、带 code interpreter 的 AgentCore Runtime、memory、gateway 和可观测性组件、DynamoDB 存储以及 CloudWatch/X-Ray 监控。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/02/03/ML-20357-1.png)

该架构以托管你 agent 的 [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 为中心。在 FAST 中，用户通过 Amazon Cognito 认证，它为四个集成点提供安全保障：

- 用户登录托管在 [Amazon CloudFront](https://aws.amazon.com/cloudfront/) 上的前端 Web 应用
- 前端访问 AgentCore Runtime 的基于 token 的认证
- agent 访问 AgentCore Gateway 的基于 token 的认证
- 发往 [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 的 API 请求的基于 token 的认证

前端是一个使用 [Tailwind CSS](https://tailwindcss.com/) 和 [shadcn](https://ui.shadcn.com/) 组件的 React 应用，托管在 [AWS Amplify Hosting](https://aws.amazon.com/amplify/hosting/) 上。它使用可流式传输的 HTTP 与 AgentCore Runtime 通信，以实现实时响应流式输出。

提供反馈机制是为了演示如何通过 API Gateway 发起同步且需认证的 HTTP 调用，并把应用数据存储在 Dynamo DB 中。AgentCore Runtime 连接到多项 AgentCore 能力：

- [AgentCore Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html) – 存储对话历史（短期）和提取出的洞察，例如用户偏好（长期），这样你的 agent 无需自行编写数据库逻辑就能跨会话记住上下文。（FAST 默认包含短期 memory，长期 memory 只需少量修改即可无缝添加。）
- [AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) – 将 API 作为与 [Model Context Protocol（MCP）](https://modelcontextprotocol.io/) 兼容的工具暴露给你的 agent
- [AgentCore Code Interpreter](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/code-interpreter-tool.html) – 在隔离的沙箱环境中安全执行 Python 代码
- [AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html) – 把兼容 Open Telemetry（OTEL）的指标和日志发送到 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch)，把 trace 发送到 [AWS X-Ray](https://docs.aws.amazon.com/xray/latest/devguide/aws-xray.html)

该模板包含 [Strands Agents](https://strandsagents.com/latest/) 和 [LangGraph](https://www.langchain.com/langgraph) 的模式。FAST 和 AgentCore 都与 agent 框架无关，因此你可以使用自己选择的 agent SDK。基础设施用 AWS CDK 定义，以实现可重复的部署。

该架构在设计上就是模块化的。前端与由 AgentCore 驱动的后端集成，你可以把它作为与自己的前端应用集成的示例。这个前端可以是你自己的 React 应用，也可以是完全不同前端框架的应用。

### 为 AI 辅助开发而设计

FAST 在设计上就包含详尽的文档。该仓库包括：

- **Steering 文档** – 编码助手会自动遵循的规则与约定
- **功能指南** – 关于 gateway、memory、流式输出及其他集成的详细文档
- 遍布代码库的 **README** – 每个组件的上下文说明

当你让编码助手做修改时，它可以阅读这些文档并遵循其中记录的范式。这种做法适用于许多 AI 编码助手，包括 [Kiro](https://kiro.dev/)、Cline、Claude Code、Cursor 等。这些文档和 steering 文档与具体系统无关。

AI 辅助开发是可选的。指导编码助手的同一套文档，对更喜欢自己写代码的开发者同样有用。

## 前提条件

在部署 FAST 之前，请确保已安装以下内容：

- Node.js 20 或更高版本
- Python 3.11 或更高版本
- Docker
- 已配置[至少这些最低凭证](https://github.com/awslabs/fullstack-solution-template-for-agentcore/blob/main/infra-cdk/minimal-deploy-policy.json)的 [AWS Command Line Interface（AWS CLI）](https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-getting-started.html)
- [AWS CDK](https://docs.aws.amazon.com/cdk/v2/guide/getting-started.html)

你使用的 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam) 用户必须具有进行必要的 AWS 服务调用和管理本文所述 AWS 资源的权限。为 IAM 用户授予权限时，请遵循最小权限原则。

## 解决方案部署演练

首先在本地环境中部署该解决方案。

### 步骤 1：克隆仓库

首先使用以下命令克隆仓库。

```
git clone https://github.com/awslabs/fullstack-solution-template-for-agentcore.git
cd fullstack-solution-template-for-agentcore
```

### 步骤 2：配置你的部署

编辑 `infra-cdk/config.yaml` 以自定义你的部署：

```
stack_name_base: your-project-name 
admin_user_email: admin@example.com # Optional: auto-creates user and emails credentials 
backend: pattern: strands-single-agent # Available: strands-single-agent, langgraph-single-agent 
deployment_type: docker # Available: docker, zip
```

### 步骤 3：使用 CDK 部署后端

使用以下命令部署后端。

```
cd infra-cdk 
npm install 
cdk bootstrap # Only required once per account/region 
cdk deploy
```

这会创建 Cognito 用户池、构建 agent 容器并推送到 [Amazon Elastic Container Registry（Amazon ECR）](https://aws.amazon.com/ecr)、创建 AgentCore Runtime，并设置 CloudFront 分配。部署大约需要 5–10 分钟。

### 步骤 4：部署前端

使用以下命令部署前端。

```
cd ..
python scripts/deploy-frontend.py
```

该脚本从 CDK 堆栈输出中生成认证配置、安装依赖、构建 React 应用，并部署到 [AWS Amplify](https://aws.amazon.com/amplify) Hosting。脚本完成后会输出应用 URL：

```
✓ Deployment completed successfully!

Console: https://console.aws.amazon.com/amplify/apps
App URL: https://main.d123490abcdef.amplifyapp.com
```

### 步骤 5：创建 Amazon Cognito 用户

如果你在配置中提供了 `admin_user_email`，你会收到一封包含临时凭证的电子邮件，可用其登录。然后进入下一步。

如果你没有提供 `admin_user_email`，请手动创建用户：

- 打开 Amazon Cognito 控制台。
- 找到你的**用户池**（命名为 `{stack_name_base}-user-pool`）。
- 进入 **Users** 并选择 **Create user**。
- 输入电子邮件地址和临时密码。
- 选择 **Mark email as verified**。
- 选择 **Create user**。

### 步骤 6：访问并测试应用

你现在可以按以下步骤访问并测试应用：

- 在浏览器中打开 Amplify Hosting URL（部署前端后终端中会打印出来）。
- 使用你的 Amazon Cognito 用户凭证登录。
- 在系统提示时修改你的临时密码。

![GIF 演示：使用用户名和密码登录默认的 FAST 应用，然后输入一个示例查询，并看到响应流式返回到屏幕上。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/02/03/FAST-blog-gif-2.gif)

FAST 示例应用是一个简洁的多轮聊天界面。UI 在设计上保持极简；它是为了被替换成你自己的前端或集成到现有应用中而构建的。基线 agent 包含两个工具来演示该架构：

- **文本分析工具** – 位于 AgentCore Gateway 之后、基于 [AWS Lambda](https://aws.amazon.com/pm/lambda) 的工具，用于统计词数并分析字母频率。它演示了 Gateway 集成范式。
- **Code Interpreter** – 直接集成 AgentCore Code Interpreter，以便在隔离沙箱中更安全地执行 Python。

尝试以下示例查询，验证工具是否正常工作：

- “Analyze the text: The quick brown fox jumps over the lazy dog” – agent 应返回词数统计和字母频率分析
- “Calculate the first 20 Fibonacci numbers” – 观察 agent 实时编写并执行 Python 代码

与 UI 一样，提供的这些工具同样是为了被替换而存在的。它们用于演示添加工具的两种不同架构（如文本分析工具那样位于 AgentCore Gateway 之后，以及如 code interpreter 工具那样直接接入 agent），并为你提供一个可运行的起点。此外，反馈收集机制的存在是为了演示如何通过 API Gateway 发起同步且需认证的 HTTP 调用，它可以被无缝移除或改作他用。

## 按你的需求定制应用

如果你需要的是文档分析 agent 而不是聊天机器人呢？或者你想与公司现有的身份提供商集成？FAST 正是为此而设计的；基线应用只是一个起点，而不是约束。

以下是一段直播录像，来自 [AWS Events YouTube 频道](https://www.youtube.com/@AWSEventsChannel)，其中使用 FAST 实时构建了一个 agentic 个人助理应用。

### 更换 agent 模式

该模板在 `patterns/` 目录中包含两种 agent 模式：

- **strands-single-agent** – 使用 Strands 框架并集成 MCP 工具的基础对话 agent
- **langgraph-single-agent** – 使用 LangGraph 并集成 MCP 工具的基础对话 agent

要切换模式，请更新 `infra-cdk/config.yaml` 中的 `backend.pattern`，然后用 `cdk deploy` 重新部署。

要创建自己的模式，请在 `patterns/` 下新增一个目录，放入你的 agent 实现、`requirements.txt` 文件和 `Dockerfile`。然后更新配置，指向你的新模式。

### 使用 Gateway 添加新工具

AgentCore Gateway 会把工具调用路由到 AWS Lambda 函数。要添加新工具：

- 创建一个实现你工具逻辑的 Lambda 函数。
- 在 CDK 堆栈中定义工具 schema（名称、描述和输入参数）。
- 把该 Lambda 函数添加为 AgentCore Gateway 目标。
- 使用 `cdk deploy` 重新部署。

agent 会通过 MCP 自动发现 Gateway 中的工具。实现细节和示例请参见 `docs/GATEWAY.md`。

### 使用 Code Interpreter

Code Interpreter 已经集成在基线 agent 中。它在隔离的沙箱环境中提供更安全的 Python 执行，并支持会话持久化。用户可以要求 agent 执行计算、生成数据或运行任意 Python 代码。

### 修改前端

前端是 `frontend/` 目录中的标准 React 应用。像 [Kiro](https://kiro.dev/) 这样的 AI 编码助手很擅长修改 React 前端。描述你想要的改动，让助手去实现。

完成修改后，用 `python scripts/deploy-frontend.py` 重新部署

由于 FAST 使用 AWS Amplify Hosting，你可以选择集成受支持的版本控制系统，以利用 Amplify Hosting 内置的持续集成与交付（CI/CD）能力，从而取代提供的 `deploy-frontend.py` 脚本。

## 聊天之外：其他用例

基线应用以聊天界面为中心，但 FAST 支持许多 agentic 用例。例如，一个文档分析 agent 可以在前端增加文件上传组件、增加一个从 PDF 中提取文本的 Lambda 工具，以及汇总发现结果的 agent 逻辑。或者，一个工作流自动化 agent 可以监控 Slack 频道，并根据支持请求自动创建 Jira ticket。架构依然适用，你只是替换其中的部件。这些定制都能在 FAST 的默认架构内实现。但如果你需要完全替换某个核心组件呢？

### 灵活性：替换主要组件

该架构有意设计成模块化的，因此你可以随着需求演进替换主要组件。以下是一些示例：

- **身份提供商** – 用 Okta、Microsoft Entra ID、Auth0 或你现有的兼容 OAuth 2.0 的身份系统替换 Amazon Cognito
- **前端框架** – 把 React 前端换成 Vue、Angular，或把 agent 后端集成到现有应用中
- **托管** – 从 AWS Amplify Hosting 迁移到 Vercel、Netlify、自管理的 CloudFront 分配，或你偏好的托管方案
- **Agent 框架** – 使用 Strands Agents、LangGraph、CrewAI，或甚至使用 TypeScript、Java 等其他语言的 agent SDK

这些只是 FAST 提供的一部分灵活性。模块化的 CDK 基础设施与解耦的架构让把模板调整为你的具体需求变得简单直接。

## 清理

使用以下命令删除 FAST 创建的资源：

```
cd infra-cdk 
cdk destroy --force
```

这会删除 AWS 资源，包括 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/) 存储桶和 [Amazon Elastic Container Registry（Amazon ECR）](https://aws.amazon.com/ecr) 镜像。如果你让资源继续运行，部分正在运行的资源可能会产生费用。请注意，Amazon Bedrock AgentCore 采用按使用量付费。

## 结论
