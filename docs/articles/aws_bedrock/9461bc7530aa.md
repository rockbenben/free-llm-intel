# Amazon Bedrock AgentCore payments 现已正式可用：让 agent 能够安全地大规模自主交易

Agent 已经从简单的聊天应用演化为自主的长时间运行系统，它们可以在没有人工监督的情况下，为每个任务动态发现并组合数十种工具。而在另一侧，服务与内容提供方正在从以人为中心、基于订阅、一刀切的定价，转向按使用、按执行付费的模式，其成本往往只有几美分。如今，agent 在推理、选择工具和完成任务方面表现出色，但一旦涉及付款就会撞墙。为解决这一问题，我们在 5 月与 Coinbase 和 Stripe 合作推出了预览版的 AgentCore payments，让 agent 开发者只需几行代码，就能让自己的 agent 为付费 API、MCP 和内容自主付款。今天，我们很高兴地宣布该服务已正式可用，使企业能够为生产工作负载打造具备安全性、防护措施与可观测性的 agentic 支付。

## 主要功能

### 钱包支持

Agent 需要资金来源才能进行 agentic 交易。AgentCore payments 通过与 Coinbase 和 Stripe Privy 钱包集成来解决这一问题，开发者只需提供 Coinbase 或 Privy 的 API key 和 secret，即可建立支付能力。这些是专为高性价比的小额交易支付（通常以美分为单位）而构建的稳定币钱包。最终用户可以通过信用卡等传统支付方式，或通过 USDC 稳定币为其 agent 的钱包充值，并且必须授予该 agent 代为消费的委托权限。在安全方面，AgentCore 会把开发者凭证存储在 AgentCore Identity Secrets Manager 中，agent 看不到原始凭证。AgentCore payments 使用由这些凭证派生的短期 token，指示钱包提供方按照开发者 agent 的指令执行钱包操作（例如交易签名），从而为这些交互增加了一层额外保护。

为正式可用版本，我们在 AgentCore Payments 内直接为 Coinbase 构建了“Quick Create”选项（可通过控制台或 CLI 使用），让开发者无需离开 AgentCore 就能配置凭证，节省了时间和精力。对于 Stripe Privy，开发者需要从 [Privy 仪表盘](https://docs.privy.io/authentication/overview#api-authentication)获取凭证，并提供给 AgentCore payments。

### 支付编排

AgentCore payments 在设计上是协议无关的，它把复杂性抽象掉，让开发者只需集成一次，就能与使用任意协议的商户合作。在预览阶段，我们发布时支持 x402 协议。到正式可用版本，我们扩展了协议支持，加入了 Machine Payment Protocol（MPP）——这是由 Stripe 和 Tempo 共同编写的另一种机器支付标准——使开发者无需额外写一行代码，就能为任何兼容 MPP 的服务付费。此外，我们还引入了对 x402 中“upto”方案的支持，它让 agent 可以设定支出上限，而不必承诺固定价格。这解锁了真正的按推理付费和动态定价：提供 LLM token、算力或任何按使用计量的 API 的商户，现在可以在调用结束时按实际消耗量收费，而不必像（当前支持的“exact”方案那样）对请求要求固定价格。

### 按使用付费端点的可发现性

AgentCore 通过 AgentCore Gateway 把 Coinbase 提供的按使用付费 x402 端点作为 MCP server 暴露出来，使 agent 开发者可以根据自身用例发现并选择合适的付费端点。我们现已增强这一发现体验，把该 MCP server 更新为一份精选的高质量端点清单，筛选依据包括社会证明、元数据丰富度、描述质量和可用性。

### 支付限额

Agent 本质上具有非确定性，因此它们可能把某个响应误解为支出授权，或因意外的重试而重复付款。在 AgentCore payments 中，交易在支付会话（payment session）内运行，这是针对单次 agent 交互的限定支付上下文。一个支付会话有两个可配置的上限：以指定货币表示的最高支出金额，以及过期时间。在签署支付之前，AgentCore payments 会用会话预算检查请求，并拒绝那些会使会话超出上限的请求。这一检查是确定性的，并且运行在基础设施层。

### 可观测性

随着 agent 执行自主交易，开发者需要全面的可观测性——包括支付审计线索、详细日志，以及成功率、平均交易金额等关键指标——以保持可见性并审计 agent 的支出行为。AgentCore payments 与 [AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-payments-metrics.html) 集成，让开发者看清支付生命周期，并自动向你的 Amazon CloudWatch 日志组发送 vended logs、向 AgentCore Observability 发送 vended spans。AgentCore Observability 包含预置仪表盘，可按 agent、支付会话和时间段展示端到端交易健康状况（例如交易成功率、平均交易金额）。

## 使用场景

### 为付费网页内容付费

如今在网络上托管内容的发布方正在阻止 agent 访问，并把 agent 流量变现。部署需要实时访问网络的 AI agent 的企业（无论是用于信息检索还是基于网络的自动化）、AI 浏览器工具提供方以及 agentic 网络搜索提供方，都能从集成 AgentCore payments 服务中受益，因为该服务能让他们的 agentic 解决方案为付费墙后的网页内容付费，而不会打断 agent 工作流。为实现这一点，我们继续与包括 Amazon CloudFront 和 Cloudflare 在内的内容分发网络（CDN）合作。我们的客户之一 [Anchor Browser](https://anchorbrowser.io/) 集成了 AgentCore payments，为其客户解锁付费墙后的网页内容。

> “Anchor Browser 是为企业服务的领先云端浏览器自动化平台之一，每天承载数百万流量，专为 AI agent 打造。我们很高兴集成 AgentCore payments，让客户能够在基于网络的 agentic 工作流中解锁付费网页内容。这次集成很顺畅，它提供了一种带有内置支付限额、安全处理 agentic 交易的方式。”
>         — Idan Raman，Anchor Browser 首席执行官、联合创始人
>         “发布方花了多年时间构建付费墙。现在 AI agent 需要穿过它们。Amazon CloudFront 和 AWS WAF 为内容所有者提供了针对 AI 流量的单一控制平面——哪些 agent 可以访问哪些内容、以什么价格、用于什么用途——并在边缘通过开放的 x402 协议验证支付。构建在 AgentCore 上的 agent 可以付费访问这些内容，而不打断自己的工作流。内容所有者按自己的条件开放 agent 流量——这把对话从防御转向了商业。”
>         — Nishit Sawhney，AWS Edge Services 总经理
>         “Cloudflare 位于全球相当大份额的内容、API 和 MCP server 之前。我们的 Monetization Gateway 让这些资产的所有者可以直接向 agent 收费，按请求计费、价格自定，并使用开放的 x402 协议。借助 AgentCore payments，在 AgentCore 上构建 agent 的企业从第一天起就能访问并为这些资产付费。”
>         — Stephanie Cohen，Cloudflare 首席战略官

### 按推理付费

按推理付费是 agentic 交易的一个新兴用例，它让 agent 开发者能够动态切换模型，以在不牺牲质量的前提下优化成本，也免去了与各个模型提供方分别管理 API key 和订阅的负担。我们的客户之一 SpreadX 在其新的 AI 产品 Incarna 中使用 AgentCore Payments，通过 BlockRun 为推理付费——BlockRun 是一个路由与支付层，agent 在其上通过 x402 协议按调用付费。

> “我们很高兴与 AgentCore payments 合作，它提供了一个托管服务，让 agent 能够轻松、安全地访问 BlockRun 的按使用付费端点并为其付费，解锁了一个全新的按推理付费用例。”

— Vicky Fu，BlockRun 创始人兼首席执行官

### 消费者与深度研究用例

旅游服务提供方 Travala 已将 AgentCore payments 集成到其 Travala Travel MCP server 中，使通过 Claude 等 agentic 平台使用服务的最终客户，可以在单次聊天中安全可靠地以对话方式预订酒店。同样，Elsa AI 和 Heurist AI 使用 AgentCore payments，通过 x402 协议访问按使用付费的 API，为最终客户提供财务研究与咨询。

> “将 AgentCore payments 集成到 Travala Travel MCP，为我们全球 220 万处房源简化了 agentic 预订流程。这次集成提供了一种带有内置支付限额、安全处理 agentic 交易的方式，改善了客户的整体 agentic 预订体验。”

— Juan Otero，Travala 首席执行官

## AgentCore payments 入门

AgentCore payments 在以下[区域](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html)可用。开发者体验与选择权是 AgentCore payments 的基础设计原则。借助开箱即用的 skill、直观的控制台，以及与主流开源框架的集成，我们让开发者能够轻松地用 AgentCore payments 构建，从而专注于最重要的事情：*其买方 agent 在大规模下的安全质量与性能。* 你可以通过多种方式设置并使用 AgentCore payments：

### 编码助手 skill

无论你是第一次构建交易型 agent，还是为现有 agent 添加自主支付能力，都可以把编码助手（Claude Code、Kiro、Codex）指向该 skill。你的编码助手将获得搭建支持支付的 agent 所需的完整上下文——从凭证设置到交易执行——从而让你的 agent 开箱即能自主为付费服务或内容付款。更多细节请参阅[快速入门指南](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments-getting-started.html)。

- [AWS Agent toolkit 插件](https://github.com/aws/agent-toolkit-for-aws/tree/main/plugins/aws-agents)
- [Payment Skills 与 CLI 示例](https://github.com/awslabs/agentcore-samples/tree/main/01-features/08-agents-that-transact/01-payments-skills-and-cli)

### AgentCore CLI

安装 AgentCore CLI，即可用几条命令搭建、配置并部署完整的交易型 agent。它会接好支付能力——包括凭证配置和交易路由——让你在几分钟（而不是几天）内得到一个端到端、支持支付的 agent。更多细节请参阅[快速入门指南](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments-getting-started.html)。

### AWS 管理控制台

你可以从 [Amazon Bedrock AgentCore 控制台](https://console.aws.amazon.com/bedrock-agentcore/)开始。在导航窗格中，在 **Build** 下选择 **Payments**。**Quick Create** 选项提供了一种在控制台创建 Coinbase 凭证并设置 AgentCore payments 资源的方式。

### 开源框架集成

在构建进行交易的 agent 时，开发者需要处理被其 agent 框架执行循环拦截的 HTTP *402 Payment Required* 响应。AgentCore payments 可与主流开源框架以及任何模型配合工作。AgentCore payments 提供的集成能以最小的代码改动加入支付能力。请在以下小节中浏览各框架的具体实现：

- **Strands Agents 插件**  [文档](https://strandsagents.com/docs/integrations/plugins/agentcore-payments/) [示例](https://github.com/awslabs/agentcore-samples/blob/main/01-features/08-agents-that-transact/00-getting-started/01-agents-payments-and-limits/strands_payment_agent.py)

```
plugin = AgentCorePaymentsPlugin(config=AgentCorePaymentsPluginConfig(
    payment_manager_arn=os.environ["PAYMENT_MANAGER_ARN"],
    user_id="test-user-123",
    payment_instrument_id=os.environ["PAYMENT_INSTRUMENT_ID"],
    payment_session_id=os.environ["PAYMENT_SESSION_ID"],
))
agent = Agent(model=BedrockModel(model_id=MODEL_ID, streaming=True), tools=[], plugins=[payment_plugin], system_prompt=SYSTEM_PROMPT)
```

- **LangGraph middleware**  [文档](https://docs.langchain.com/oss/python/integrations/middleware/aws#agentcore-payments) [AgentCore 上的示例](https://github.com/awslabs/agentcore-samples/blob/main/01-features/08-agents-that-transact/00-getting-started/01-agents-payments-and-limits/langgraph_payment_agent.py) [使用 LangSmith 的示例](https://github.com/langchain-samples/langchain-aws-samples/tree/main/examples/agentcore-payments) [博客文章](https://www.langchain.com/blog/langchain-agentcore-payments)

```
payments = AgentCorePaymentsMiddleware(config)
agent = create_agent(model, tools=[], system_prompt=SYSTEM_PROMPT, middleware=[payments])
```

- **OpenClaw 插件**  [浏览 ClawHub](https://clawhub.ai/packages/@aws/aws-agents-pay) [示例](https://github.com/awslabs/agentcore-samples/tree/main/01-features/08-agents-that-transact/01-payments-skills-and-cli/converse-with-openclaw-agent/) [博客文章](https://aws.amazon.com/blogs/machine-learning/build-openclaw-agents-that-transact-with-amazon-bedrock-agentcore-payments/)

> agents-pay skill 使 agent 能够在运行时为受 x402 保护的内容付费——通过 AgentCore payments 在任务执行中途拦截 402 Payment Required 付费墙，从而在无需人工干预的情况下自主完成任务。

## 结论

今天，AgentCore payments 已正式可用，这标志着让 agentic 经济成为现实的一步——在这个经济里，AI agent 不仅推理和行动，还能自主、安全且大规模地交易。通过抽象掉支付协议、钱包管理和交易编排的复杂性，我们让开发者能够专注于构建智能 agent，而由 AgentCore 负责基础设施。我们的客户已经在证明，当支付成为 agent 技术栈原生的一等能力时，可能的空间有多大。凭借协议无关的支持、内置的支出防护措施和生产级可观测性，AgentCore payments 让开发者有信心在几分钟（而不是几天）内把交易型 agent 部署到生产。今天就开始使用，让你的 agent 具备交易能力。
