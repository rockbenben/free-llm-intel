# Amazon Bedrock Agents 中的 computer use 入门

[Computer use](https://www.anthropic.com/news/3-5-models-and-computer-use) 是 Anthropic 的一项突破性能力，它让基础模型（FM）能够以视觉方式感知并解读数字界面。这项能力让 Anthropic 的 Claude 模型可以识别屏幕上有什么、理解 UI 元素的上下文，并识别应当执行的动作，例如点击按钮、输入文本、滚动以及在应用之间切换。不过，模型本身并不执行这些动作——它需要一个编排层来安全地实施这些受支持的动作。

今天，我们宣布在 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 中支持 [computer use](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-computer-use.html)，在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上使用 Anthropic 的 Claude 3.5 Sonnet V2 和 Anthropic 的 Claude Sonnet 3.7 模型。这项集成把 Anthropic 的视觉感知能力作为 Amazon Bedrock Agents 中的一个托管工具引入，为你提供一种安全、可追溯且受管理的方式，在你的工作流中实施 computer use 自动化。

各行各业的组织都在为难于自动化那些跨越多个应用和记录系统的重复性任务而苦恼。无论是处理发票、更新客户记录，还是管理人力资源（HR）文档，这些工作流往往需要员工在不同系统之间手工搬运信息——这个过程耗时、易错，而且难以规模化。

传统的自动化方法需要为每个应用做自定义 API 集成，开发开销巨大。computer use 能力改变了这一范式，让机器可以像人一样感知已有的界面。

在本文中，我们构建一个 computer use agent 示例，它提供关键的编排层，把 computer use 从一种感知能力转化为可执行的自动化。如果没有这一编排层，computer use 只会识别出可能的动作而不会执行。由 Amazon Bedrock Agents 驱动的这个 computer use agent 示例提供以下优势：

- **安全的执行环境** – 在沙箱环境中执行 computer use 工具，对 AWS 生态和互联网的访问受到限制。必须特别指出，目前 Amazon Bedrock Agent 并不提供沙箱环境
- **全面的日志记录** – 能够追踪每一个动作和交互，用于审计和调试
- **细粒度的追踪能力** – 可以看清自动化工作流的每一个步骤
- **简化的测试与试验** – 通过受管理的控制措施，在使用这项实验性能力时降低风险
- **无缝编排** – 无需自定义代码即可协调跨多个系统的复杂工作流

这项集成把 Anthropic 对数字界面的感知理解与 Amazon Bedrock Agents 的编排能力结合起来，构建出一个强大的 agent，用于自动化跨应用的复杂工作流。开发者不必再为每个系统构建自定义集成，而是可以以受管理、安全的方式创建能够感知并操作现有界面的 agent。

借助 computer use，Amazon Bedrock Agents 可以通过基础 GUI 操作和内置的 Linux 命令来自动化任务。例如，你的 agent 可以截取屏幕、创建和编辑文本文件，并运行内置的 Linux 命令。使用 Amazon Bedrock Agents 和兼容的 Anthropic 的 Claude 模型，你可以使用以下 action group：

- **Computer tool** – 支持与用户界面交互（点击、输入、滚动）
- **Text editor tool** – 提供编辑和操作文件的能力
- **Bash** – 允许执行内置的 Linux 命令

## **解决方案概览**

一个 computer use 工作流示例包含以下步骤：

- 创建一个 Amazon Bedrock agent，用自然语言描述该 agent 应该做什么以及应如何与用户交互，例如：“你是一个 computer use agent，能够使用 Firefox 网页浏览器进行网络搜索。”
- 使用 [CreateAgentActionGroup API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent_CreateAgentActionGroup.html) 把 Amazon Bedrock Agents 支持的 computer use action group 添加到你的 agent。
- 用一个需要 computer use 工具的用户查询来调用该 agent，例如：“Amazon Bedrock 是什么，你能上网搜索一下吗？”
- Amazon Bedrock agent 利用手头的工具定义，决定使用 computer action group 去点击环境的截图。借助 Amazon Bedrock Agents 的 [return control](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-returncontrol.html) 能力，agent 会返回它想要执行的一个或多个工具。要把 computer use 与 Amazon Bedrock Agents 一起使用，return control 能力是必需的。
- 工作流解析 agent 的响应，并在沙箱环境中执行返回的工具。输出会回传给 Amazon Bedrock agent 做进一步处理。
- Amazon Bedrock agent 持续用它手头的工具作出响应，直到任务完成。

你可以按照 [GitHub 仓库](https://github.com/awslabs/amazon-bedrock-agent-samples/tree/main/examples/agents/computer_use)中的说明，在 us-west-2 AWS 区域用 [AWS Cloud Development Kit](https://aws.amazon.com/cdk/)（AWS CDK）复现这个示例。该示例在 us-west-2 区域的两个可用区中，使用 [AWS Fargate](https://aws.amazon.com/fargate/) 部署一个容器化应用。基础设施运行在一个虚拟私有云（VPC）中，每个可用区都有公有子网，并由一个互联网网关提供对外连接。架构还配有必要的支撑服务，包括用于安全的 [AWS Key Management Service](https://aws.amazon.com/kms)（AWS KMS）和用于监控的 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/)，构成一个有韧性、无服务器的容器环境，既免去了管理底层基础设施的负担，又保持了稳健的安全性和高可用性。

方案的核心是通过 [Amazon Elastic Container Service](https://aws.amazon.com/ecs/)（Amazon ECS）管理的两个 Fargate 容器，各自受自己的安全组保护。第一个是编排容器，它不仅负责 Amazon Bedrock Agents 与最终用户之间的通信，还负责编排使工具得以执行的工作流。第二个是环境容器，它充当安全的沙箱，Amazon Bedrock agent 可以在其中安全地运行它的 computer use 工具。环境容器对生态的其余部分和互联网的访问都受到限制。我们使用[服务发现](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/service-discovery.html)，通过 DNS 名称连接 Amazon ECS 服务。

编排容器包含以下组件：

- **Streamlit UI** – 便于最终用户与 computer use agent 交互的 [Streamlit UI](https://streamlit.io/)
- **Return control 循环** – 负责解析 agent 想要执行的工具并返回这些工具输出的工作流

环境容器包含以下组件：

- **UI 与预装应用 **– 一个轻量级 UI 和预装的 Linux 应用（例如 Firefox），可用于完成用户的任务
- **工具实现** – 可以在环境中执行 “screenshot” 或 “double-click” 等 computer use 工具的代码
- **Quart（RESTful）JSON API** – 一个编排容器，使用 [Quart](https://github.com/pallets/quart) 在沙箱环境中执行工具

## **创建一个带 computer use 的 Amazon Bedrock agent**

你可以使用以下代码示例创建一个包含 computer、bash 和 text editor action group 的简单 Amazon Bedrock agent。在使用 Anthropic 的 Claude 3.5 Sonnet V2 和 Anthropic 的 Claude 3.7 Sonnet 时，必须提供兼容的 action group signature，如[此处](https://docs.anthropic.com/en/docs/agents-and-tools/computer-use#claude-3-7-sonnet-tools)所示。

| 模型 | Action Group Signature |
| --- | --- |
| Anthropic 的 Claude 3.5 Sonnet V2 | computer_20241022  text_editor_20241022  bash_20241022 |
| Anthropic 的 Claude 3.7 Sonnet | computer_20250124  text_editor_20250124  bash_20250124 |

```
import boto3
import time

# Step 1: Create the bedrock agent client

bedrock_agent = boto3.client("bedrock-agent", region_name="us-west-2")

# Step 2: Create an agent

create_agent_response = create_agent_response = bedrock_agent.create_agent(
        agentResourceRoleArn=agent_role_arn, # Amazon Bedrock Agent execution role
        agentName="computeruse",
        description="""Example agent for computer use. 
				This agent should only operate on 
				Sandbox environments with limited privileges.""",
        foundationModel="us.anthropic.claude-3-7-sonnet-20250219-v1:0",      
		instruction="""You are computer use agent capable of using Firefox 
                 web browser for web search.""",
)

time.sleep(30) # wait for agent to be created

# Step 3.1: Create and attach computer action group

bedrock_agent.create_agent_action_group(
    actionGroupName="ComputerActionGroup",
    actionGroupState="ENABLED",
    agentId=create_agent_response["agent"]["agentId"],
    agentVersion="DRAFT",
    parentActionGroupSignature="ANTHROPIC.Computer",
    parentActionGroupSignatureParams={
        "type": "computer_20250124",
        "display_height_px": "768",
        "display_width_px": "1024",
        "display_number": "1",
    },
)

# Step 3.2: Create and attach bash action group

bedrock_agent.create_agent_action_group(
    actionGroupName="BashActionGroup",
    actionGroupState="ENABLED",
    agentId=create_agent_response["agent"]["agentId"],
    agentVersion="DRAFT",
    parentActionGroupSignature="ANTHROPIC.Bash",
    parentActionGroupSignatureParams={
        "type": "bash_20250124",
    },
)

# Step 3.3: Create and attach text editor action group

bedrock_agent.create_agent_action_group(
    actionGroupName="TextEditorActionGroup",
    actionGroupState="ENABLED",
    agentId=create_agent_response["agent"]["agentId"],
    agentVersion="DRAFT",
    parentActionGroupSignature="ANTHROPIC.TextEditor",
    parentActionGroupSignatureParams={
        "type": "text_editor_20250124",
    },
)

# Step 3.4 Create Weather Action Group

bedrock_agent.create_agent_action_group(
        actionGroupName="WeatherActionGroup",
        agentId=create_agent_response["agent"]["agentId"],
        agentVersion="DRAFT",
        actionGroupExecutor = {
            'customControl': 'RETURN_CONTROL',
        },
        functionSchema = {
            'functions': [
                {
                    "name": "get_current_weather",
                    "description": "Get the current weather in a given location.",
                    "parameters": {
                        "location": {
                            "type": "string",
                            "description": "The city, e.g., San Francisco",
                            "required": True,
                        },
                        "unit": {
                            "type": "string",
                            "description": 'The unit to use, e.g., 
									fahrenheit or celsius. Defaults to "fahrenheit"',
                            "required": False,
                        },
                    },
                    "requireConfirmation": "DISABLED",
                }
            ]
        },
)
time.sleep(10)
# Step 4: Prepare agent

bedrock_agent.prepare_agent(agentId=create_agent_response["agent"]["agentId"])
```

### **示例用例**

在本文中，我们演示一个使用 Amazon Bedrock Agents 的 computer use 能力填写网页表单的示例。该示例中，computer use agent 还能切换 Firefox 标签页，与一个[客户关系管理（CRM）agent](https://github.com/aws-samples/amazon-bedrock-samples/tree/main/agents-and-function-calling/bedrock-agents/use-case-examples/customer-relationship-management-agent) 交互，以获取填写表单所需的信息。虽然这个示例使用一个样例 CRM 应用作为记录系统，但只要配置了合适的身份认证框架，同样的方法也适用于 [Salesforce](https://www.salesforce.com/)、[SAP](https://www.sap.com/index.html)、[Workday](https://www.workday.com/) 或其他记录系统。

在这个演示的用例中，你可以看到 Amazon Bedrock agent 使用 computer use 工具的表现如何。我们的实现通过查看 excel 数据完成了客户 ID、客户名称和电子邮件的填写。然而对于概览字段，它决定选中单元格并复制数据，因为该信息在屏幕上未能完整显示。最后，它使用 CRM agent 获取了该客户的额外信息。

## **最佳实践**

以下是一些可以提升你的用例表现的方法：

- 实施[安全组](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html)、[网络访问控制列表（NACL）](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-network-acls.html)和 [Amazon Route 53 Resolver DNS Firewall 域名列表](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/resolver-dns-firewall.html)，以控制对沙箱环境的访问。
- 应用 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam/)和[最小权限原则](https://community.aws/content/2dsQs3aTnwV3LKeUDFkXNSndHjp/understanding-the-principle-of-least-privilege-in-aws?lang=en)，为沙箱环境分配受限的权限。
- 向 Amazon Bedrock agent 提供指令时，要简洁直接。把任务指定得简单明确，并为每一步给出清晰指令。
- 了解 computer use 的局限，Anthropic 在[此处](https://docs.anthropic.com/en/docs/agents-and-tools/computer-use#understand-computer-use-limitations)有相关说明。
- 为 return control 配合[用户确认](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-userconfirmation.html)，在调用 computer use 工具之前请求用户确认，以帮助保护你的应用免受恶意 prompt 注入的影响。
- 使用多 agent 协作，并把 computer use 与 Amazon Bedrock Agents 结合，来自动化复杂的工作流。
- 按照你为应用制定的负责任 AI 政策，通过把 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 关联到你的 agent 来过滤有害的多模态内容，从而落实防护措施。

## **注意事项**

按照 AWS 服务条款的定义，computer use 特性作为一项 beta 服务提供给你。它受你与 AWS 的协议、AWS 服务条款以及适用的模型 EULA 约束。computer use 会带来与标准 API 特性或聊天界面不同的独特风险。在使用 computer use 特性与互联网交互时，这些风险会被放大。为把风险降到最低，请考虑采取以下预防措施：

- 在权限最小的专用虚拟机或容器中运行 computer use 功能，以减少直接的系统漏洞利用或意外
- 为帮助防止信息被盗，避免让 computer use API 访问敏感账户或数据
- 把 computer use API 的互联网访问限制在必需的域名上，以减少接触恶意内容的机会
- 为落实适当的监督，对敏感任务（例如可能产生现实世界重大后果的决策）以及任何需要明确同意的操作（例如接受 cookie、执行金融交易或同意服务条款）保持人在环路中

你让 Anthropic 的 Claude 看到或访问的任何内容，都可能覆盖指令，或导致模型出错、执行非预期的动作。采取适当的预防措施（例如让 Anthropic 的 Claude 与敏感界面隔离）至关重要——包括避免与 prompt 注入相关的风险。在你自己的产品中启用或申请启用 computer use 功能所需的权限之前，请告知最终用户相关风险，并酌情取得他们的同意。

## **结论**

各行各业的组织在跨应用工作流上都面临重大挑战，这些工作流传统上需要人工录入数据或复杂的自定义集成。把 Anthropic 的 computer use 能力与 Amazon Bedrock Agents 集成，是应对这些挑战的一种变革性方法。

通过把 Amazon Bedrock Agents 用作编排层，组织可以免去为每个应用开发自定义 API 的需要，享用到企业部署所必需的全面日志记录和追踪能力，并快速实施自动化方案。

当你开始探索 Amazon Bedrock Agents 的 computer use 时，不妨想想你组织里哪些工作流能从这种方法中受益。从发票处理到客户入驻，从 HR 文档到合规报告，潜在的应用广泛而具有变革性。

我们很期待看到你如何用 Amazon Bedrock Agents 的 computer use 能力，安全地精简运营，并通过 AI 驱动的自动化重新构想业务流程。
