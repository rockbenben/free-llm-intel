# 革新客户服务：MaestroQA 与 Amazon Bedrock 的集成带来可执行的洞察

*本文由 MaestroQA 的 CTO 兼联合创始人 Harrison Hunter 共同撰写。*

[MaestroQA](https://www.maestroqa.com/) 通过强化质量保证（QA）流程和客户反馈分析来增强呼叫中心运营，从而提升客户满意度并推动运营效率。它协助处理 QA 报告、辅导、工作流自动化和根因分析等运营工作。

在本文中，我们深入介绍 MaestroQA 的一项关键功能——对话分析，它借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 帮助支持团队发现客户关切、解决摩擦点、调整支持工作流并找出可改进辅导的领域。我们讨论 MaestroQA 克服的独特挑战，以及他们如何使用 AWS 构建新功能、提炼客户洞察并改善运营中的低效环节。

Amazon Bedrock 是一项完全托管的服务，通过单一 API 提供来自 AI21 Labs、Anthropic、Cohere、Meta、Mistral、Stability AI 和 Amazon 等领先 AI 公司的高性能基础模型（FM）供选择，并提供构建生成式 AI 应用所需的广泛能力，涵盖安全、隐私和负责任的 AI。

## 企业级开放式对话分析的机遇

MaestroQA 服务于横跨电商、市场平台、医疗健康、人才招聘、保险和金融科技等多个行业的多元客户群。这些客户都面临一个共同挑战：需要分析大量与客户的交互。分析这些客户交互对改进产品、改善客户支持、提升客户满意度以及识别关键行业信号至关重要。然而，呼叫中心录音、聊天消息和电子邮件等客户交互数据高度非结构化，需要先进的处理技术才能准确、自动地抽取洞察。

当客户的呼叫中心接到来电时，MaestroQA 会使用其专有转录技术（在开源转录模型基础上增强而来）对对话进行转录。数据转录完成后，MaestroQA 使用他们自研的技术，并结合 [Amazon Comprehend](https://aws.amazon.com/comprehend/) 等 AWS 服务，对客户交互数据运行多种分析。例如，MaestroQA 为客户提供[情感分析](https://docs.aws.amazon.com/comprehend/latest/dg/how-sentiment.html)，用于识别其终端客户在支持交互过程中的情绪，使 MaestroQA 的客户能对交互排序并人工检查最好或最差的交互。MaestroQA 还提供基于逻辑／关键词的规则引擎，可根据其他因素对客户交互分类，例如时间安排或流程步骤，包括平均处理时长（AHT）、合规或流程检查、SLA 达成情况等指标。

MaestroQA 的客户很喜欢这些分析功能，因为它们让客户能持续提升支持质量，并找出可以改进产品以更好地满足终端客户的领域。不过，他们也对更高级的分析感兴趣，例如提出“客户要求升级有多少次？”这类开放式问题。MaestroQA 现有的规则引擎并不总能回答这类查询，因为终端用户可以用许多不同方式表达同一个诉求。例如，“Can I speak to your manager?”（我能和你的经理谈谈吗？）和“I would like to speak to someone higher up”（我想和更高层的人谈）并不共享相同的关键词，但都是在要求升级。MaestroQA 需要一种能基于开放式问题准确分类客户交互的方法。

MaestroQA 还面临另一个障碍：其客户管理的客户交互规模极为庞大。客户的月度客户互动量从数千到数百万不等，因此迫切需要对这一海量交互中的支持团队表现进行全面分析。相应地，MaestroQA 必须开发出能够扩展以满足客户广泛需求的解决方案。

为开始开发这一产品，MaestroQA 首先推出了一款名为 AskAI 的产品。AskAI 允许客户针对最多 1,000 条对话的定向列表运行开放式问题。例如，客户可以用 MaestroQA 的过滤器找出俄勒冈州过去两个月内的客户交互，然后运行根因分析查询，例如“俄勒冈州的客户对什么感到不满？”，以找出流失风险案例。客户非常喜欢这一功能，他们所覆盖的用例广度也让 MaestroQA 感到惊讶，包括分析营销活动、服务问题和产品机会。客户开始要求能够在全部转录（数量可能达数百万条）上运行这类分析，以便量化他们所看到情况的影响，并找出重要问题的实例。

## 解决方案概述

MaestroQA 决定使用 Amazon Bedrock 来满足客户对客户交互转录的高级分析需求。Amazon Bedrock 提供来自领先 AI 公司的广泛 FM 选择，加之其可扩展性与安全特性，使其成为 MaestroQA 的理想方案。

MaestroQA 使用 [Amazon Elastic Container Service](https://aws.amazon.com/ecs)（Amazon ECS）把 Amazon Bedrock 集成到其现有架构中。客户交互转录存储在 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）存储桶中。

以下架构图展示了 AskAI 的请求流程。当客户通过 MaestroQA 的 Web 应用提交分析请求时，ECS 集群会从 Amazon S3 取回相关转录、清洗并格式化 prompt、使用客户选定的 FM 将其发送到 Amazon Bedrock 进行分析，并把结果存储到托管于 [Amazon Elastic Compute Cloud](https://aws.amazon.com/ec2)（Amazon EC2）的数据库中，供 MaestroQA 的前端 Web 应用读取。

![解决方案架构](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/03/MaestroQA-Solution-Architecture.png)

MaestroQA 让客户可以灵活地从 Amazon Bedrock 提供的多个 FM 中选择，包括 Anthropic 的 Claude 3.5 Sonnet、Anthropic 的 Claude 3 Haiku、Mistral 7b/8x7b、Cohere 的 Command R 和 R+，以及 Meta 的 Llama 3.1 模型。这使客户可以选择最契合其具体用例和需求的模型。

以下截图展示了 AskAI 功能如何让 MaestroQA 的客户使用 Amazon Bedrock 上种类丰富的 FM 提出开放式问题，例如“这些工单中有哪些常见问题？”，并从客户服务交互中生成有用的洞察。

![产品截图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/27/ML-17486-figure-1.png)

为处理海量客户交互转录并提供低延迟响应，MaestroQA 利用了 Amazon Bedrock 的[跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)能力。此前，他们自行做负载均衡，分别为北美和欧洲客户把请求分发到可用的 AWS 美国区域（`us-east-1`、`us-west-2` 等）和可用的欧盟区域（`eu-west-3`、`eu-central-1` 等）。现在，Amazon Bedrock 的跨区域推理能力使 MaestroQA 的吞吐量达到单区域推理的两倍，这是把方案扩展到服务更多客户的关键因素。MaestroQA 团队不再需要花时间和精力预测需求波动，这在电商客户于假日季用量上升时尤为关键。跨区域推理会在多个区域之间动态路由流量，为每个请求提供最佳可用性，并在这些高用量期间保持更平稳的性能。MaestroQA 使用 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch)监控该设置的性能与可靠性。

## 收益：Amazon Bedrock 如何创造价值

Amazon Bedrock 使 MaestroQA 能够更快创新，并通过为客户提供用于分析客户交互转录的强大生成式 AI 功能而获得竞争优势。借助 Amazon Bedrock，MaestroQA 现在可以为客户提供在数百万条转录上运行开放式查询的能力，释放此前无法获取的宝贵洞察。

Amazon Bedrock 提供的广泛 FM 选择，使 MaestroQA 能够满足客户多样化的需求与偏好。客户可以选择最契合其具体用例的模型，在性能与价格之间找到合适的平衡。

Amazon Bedrock 的可扩展性与跨区域推理能力，使 MaestroQA 能够处理海量客户交互转录，同时保持低延迟，无论客户身处何地。

MaestroQA 利用 Amazon Bedrock 稳健的安全特性和合乎伦理的 AI 实践来增强客户信心。这些措施确保客户数据在处理过程中保持安全，且不会被第三方提供商用于模型训练。此外，Amazon Bedrock 在欧洲的可用性及其地理控制能力，使 MaestroQA 能够无缝地把 AI 服务扩展到欧洲客户。这一扩展无需引入额外复杂性，从而在遵守区域数据法规的同时保持运营效率。

采用 Amazon Bedrock 对 MaestroQA 精简的开发团队而言是颠覆性的改变。其无服务器架构让团队能够快速做原型并迭代应用，而不必承担管理复杂硬件基础设施的负担。这一转变使 MaestroQA 能把精力投入到优化应用性能，而不是忙于资源分配。此外，Amazon Bedrock 与其现有 AWS 环境无缝兼容，实现了顺畅的集成过程，进一步简化了他们的开发工作流。MaestroQA 能够沿用现有的认证流程，使用 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）安全地认证其应用以调用 Amazon Bedrock 中的大语言模型（LLM）。他们还能使用熟悉的 AWS SDK，快速、轻松地把 Amazon Bedrock 集成到应用中。

总体而言，通过使用 Amazon Bedrock，MaestroQA 能够为客户提供强大而灵活的方案，从客户交互数据中提炼宝贵洞察，推动其产品和支持流程的持续改进。

## 成效指标

早期结果非常出色。

一家贷款公司使用 MaestroQA 对 100% 的对话检测合规风险。此前，如果消费者抱怨贷款或表示自己处于脆弱状态，坐席会发起内部升级。但这一流程是人工的、容易出错，该贷款公司会漏掉许多这类风险。现在，他们能够以接近 100% 的准确率检测合规风险。

一家医疗器械公司被要求向 FDA 报告器械问题，他们不再只依赖坐席在内部上报客户反馈的问题，而是使用该服务分析其全部对话，以确保所有投诉都被标记。

一家教育公司用自动化的客户情感评分取代了人工调查评分，把抽样范围从 15% 的对话提升到 100%。

最好的还在后头。

## 结论

借助 AWS，MaestroQA 能够更快创新并获得竞争优势。来自金融服务、医疗健康与生命科学、EdTech 等不同行业的公司都怀有同一个愿望：为客户提供更好的服务。MaestroQA 通过快速转向、提供解决实际业务问题并增强整体合规的强大生成式 AI 功能，帮助他们实现了这一点。

如果你希望更好地理解客户对话和调查评分，可以看看 MaestroQA 的 [AskAI](https://www.maestroqa.com/features/ask-ai) 功能及其由 LLM 驱动的 AI Classifiers。想进一步了解 Amazon Bedrock，请参阅[Amazon Bedrock 入门](https://docs.aws.amazon.com/bedrock/latest/userguide/getting-started.html)，并了解[跨区域推理](https://aws.amazon.com/blogs/machine-learning/getting-started-with-cross-region-inference-in-amazon-bedrock/)等功能，以帮助你在全球范围扩展生成式 AI 功能。
