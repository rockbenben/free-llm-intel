# Tealium 如何借助 Ragas 与 Auto-Instruct，使用 AWS 生成式 AI 服务构建聊天机器人评估平台

*本文由 Tealium 的 Varun Kumar 共同撰写*

检索增强生成（RAG）pipeline 因能够基于作为上下文输入的外部数据生成领域特定输出而广受欢迎。然而，评估和改进这类系统存在挑战。两个开源库——Ragas（一个用于 RAG 评估的库）和 Auto-Instruct——使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 驱动了一个用于评估并改进 RAG 的框架。

在本文中，我们说明[生成式 AI](https://aws.amazon.com/ai/generative-ai/) 在 Tealium 与 [AWS 生成式 AI 创新中心（GenAIIC）](https://aws.amazon.com/ai/generative-ai/innovation-center/) 团队合作中的重要性，即自动化以下工作：

- 基于由 Amazon Bedrock 提供支持的 [Ragas 仓库](https://github.com/explodinggradients/ragas/tree/main)，评估 RAG 系统的检索器和生成的答案。

- 使用基于 [Auto-Instruct 仓库](https://github.com/ytyz1307zzh/Auto-Instruct)的自动 prompt engineering 技术，为每个问答对生成改进后的指令。指令指的是给模型的、用于指导其生成回答的总体方向或命令。这些指令是使用 Amazon Bedrock 上 Anthropic 的 Claude 生成的。

- 提供一个供人工反馈的 UI，与由 Amazon Bedrock 驱动的评估系统互补。

Amazon Bedrock 是一项完全托管的服务，通过 API 提供热门 FM，因此你可以从广泛的基础模型（FM）中选择最适合你用例的模型。由于 Amazon Bedrock 是无服务器的，你可以快速上手，用自己的数据私有地定制 FM，并把它们集成和部署到你的应用中，而无需管理任何基础设施。

## Tealium 的背景与用例

[Tealium](https://tealium.com/) 是实时客户数据集成与管理领域的领先者。他们帮助组织构建完整的基础设施，以跨渠道和系统收集、管理和激活客户数据。Tealium 使用 AI 能力来集成数据并大规模获取客户洞察。他们的 AI 愿景是为客户提供一个持续从客户行为中学习、并实时优化互动的活跃系统。

Tealium 使用 RAG pipeline 构建了一个问答（QA）机器人，用于帮助识别常见问题并回答有关使用该平台的问题。该机器人被期望充当虚拟助手，回答常见问题、识别并解决问题、监控平台健康状况，并提供最佳实践建议，所有这些都旨在帮助 Tealium 客户从其客户数据平台中获得最大价值。

与 Tealium 合作的这一解决方案的主要目标，是评估和改进 Tealium 用来驱动其 QA 机器人的 RAG 解决方案。这是通过构建以下内容实现的：

- 评估 pipeline。

- 纠错机制，以半自动方式改进评估所产生的指标。在这次合作中，自动 prompt engineering 是唯一使用的技术，但根据你的用例，还可以探索其他技术，例如不同的分块策略，以及用语义搜索替代混合搜索。

- 人在回路（human-in-the-loop）的反馈系统，允许人工批准或不批准 RAG 输出

Amazon Bedrock 在驱动评估 pipeline 和纠错机制方面至关重要，因为它能够灵活选择广泛的一流 FM，并能为各种任务定制模型。这使得可以针对特定数据测试多种类型的专用模型，来驱动此类框架。Amazon Bedrock 在自动 prompt engineering 的文本生成以及评估用文本摘要方面的价值，在本次与 Tealium 的合作中发挥了巨大作用。最后，Amazon Bedrock 能够实现更安全的生成式 AI 应用，让 Tealium 完全掌控自己的数据，同时在静态存储和传输过程中对其进行加密。

## 解决方案前提条件

要测试 Tealium 的解决方案，请从以下内容开始：

- 获取[一个 AWS 账户](https://docs.aws.amazon.com/signin/latest/userguide/how-to-sign-in.html)。

- 创建一个 [SageMaker 域实例](https://docs.aws.amazon.com/sagemaker/latest/dg/onboard-quick-start.html)。

- 在 Amazon Bedrock 上[获取对以下模型的访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)：Anthropic 的 Claude Instant、Claude v2、Claude 3 Haiku，以及 Titan Embeddings G1 – Text。使用 Ragas 的评估可以使用 Amazon Bedrock 上任何可用的基础模型（FM）来完成。自动 prompt engineering 必须使用 Anthropic 的 Claude v2、v2.1 或 Claude Instant。

- 获取一组黄金问答对。具体而言，你需要提供将要向 RAG 机器人提出的问题示例及其预期的标准答案。

- 克隆[自动 prompt engineering](https://github.com/aws-samples/automatic-prompt-engineering/tree/main)和[人在回路](https://github.com/aws-samples/human-in-the-loop-llm-eval-blog/tree/main)仓库。如果你希望获得一个对 Amazon Bedrock 上 Anthropic Claude 模型更友好的 Ragas prompt 仓库版本，请克隆并浏览这个[仓库](https://github.com/aws-samples/Prompt-Migration-OpenAI-to-Amazon-Bedrock/tree/main/use-case-examples/call-summarization/libraries/ragas-evaluation)和这个[notebook](https://github.com/aws-samples/Prompt-Migration-OpenAI-to-Amazon-Bedrock/blob/main/features-examples/ragas_evaluation_example.ipynb)。

这些代码仓库允许在最少改动下灵活使用各种 FM 和定制模型，体现了 Amazon Bedrock 在本次合作中的价值。

下图展示了一个示例解决方案架构，包含评估框架、纠错技术（Auto-Instruct 与自动 prompt engineering）以及人在回路。如你所见，生成式 AI 是评估 pipeline 和自动 prompt engineering pipeline 的重要组成部分。

该工作流包含以下步骤：

- 你首先向 Tealium RAG QA 机器人输入一个查询。RAG 解决方案使用 [FAISS](https://github.com/facebookresearch/faiss) 为指定查询检索合适的上下文。然后它输出一个回答。

- Ragas 接收该查询、上下文、答案以及你输入的标准答案，并计算忠实度、上下文精确率、上下文召回率、答案正确性、答案相关性和答案相似度。Ragas 可以与 Amazon Bedrock 集成（参见 notebook 中的 Ragas 部分[链接](https://github.com/aws-samples/automatic-prompt-engineering/blob/main/notebooks/Prompt_Engineer_Ragas.ipynb)）。这体现了 Amazon Bedrock 在不同框架中的集成能力。

- 如果任一指标低于某个阈值，该问答对就会交由 [Auto-Instruct 库](https://github.com/ytyz1307zzh/Auto-Instruct/tree/mainhttps://github.com/ytyz1307zzh/Auto-Instruct/tree/mainhttps://github.com/ytyz1307zzh/Auto-Instruct/tree/mainhttps://github.com/ytyz1307zzh/Auto-Instruct/tree/mainhttps://github.com/ytyz1307zzh/Auto-Instruct/tree/mainhttps://github.com/ytyz1307zzh/Auto-Instruct/tree/main)处理，由它使用 Amazon Bedrock 生成候选指令。这一文本生成用例可以使用各种 FM。

- 新的指令会被追加到原始查询上，准备交由 Tealium RAG QA 机器人执行。

- QA 机器人执行评估，以判定是否有所改进。步骤 3 和步骤 4 可以反复迭代，直到所有指标都高于某个阈值。此外，你可以设置步骤 3 和步骤 4 迭代的最大次数，以防止无限循环。

- 人在回路 UI 用于让主题专家（SME）对给定模型输出提供自己的评估。它也可以用来为由生成式 AI 驱动的系统提供防护栏。

在下面的小节中，我们讨论如何对一个示例问题、其上下文、其答案（RAG 输出）和标准答案（期望答案）进行评估和修订，以获得更理想的输出。评估使用 Ragas 完成——这是一个 RAG 评估库。然后，根据与问答的相关性自动生成 prompt 和指令。最后，你可以基于自动 prompt engineering 步骤所生成的特定指令，批准或不批准 RAG 输出。

## Ragas —— RAG pipeline 的评估

[Ragas](https://github.com/explodinggradients/ragas/tree/main) 是一个帮助评估 RAG pipeline 的框架。一般来说，RAG 是一种使用外部数据来扩展 FM 上下文的自然语言处理技术。因此，该框架评估机器人检索相关上下文以及对给定问题输出准确回答的能力。AWS GenAIIC 与 Tealium 团队的合作表明，Amazon Bedrock 与 Ragas 的集成只需极少改动即可成功。

Ragas 的输入包括一组问题、标准答案、答案和上下文。对每个问题，输入一个期望答案（标准答案）、LLM 输出（答案）和一个上下文列表（检索到的分块）。上下文召回率、精确率、答案相关性、忠实度、答案相似度和答案正确性都使用 Amazon Bedrock 上 Anthropic 的 Claude（任意版本）进行了评估。供你参考，以下是通过 Amazon Bedrock 成功计算出的指标：

- **忠实度** – 该指标衡量生成的答案相对于给定上下文的事实一致性，因此需要答案和检索到的上下文作为输入。这是一个两步 prompt：首先把生成的答案拆解为多个独立陈述与命题，然后由评估 LLM 验证生成陈述对上下文的归属是否成立。如果归属无法被验证，就假定该陈述存在幻觉风险。答案会被缩放到 0–1 区间，越高越好。

- **上下文精确率** – 评估上下文与答案的相关性，换言之，即检索器捕获最佳上下文以回答你查询的能力。评估 LLM 用单一的“是”或“否”来验证给定上下文中的信息是否与问题直接相关。上下文是以列表形式传入的，因此如果列表长度为 1（一个分块），则上下文精确率的指标要么是 0（表示上下文与问题不相关），要么是 1（表示相关）。如果上下文列表长度大于 1（即包含多个分块），则上下文精确率介于 0–1 之间，表示一种特定的加权平均精确率计算。这包括：第一个分块的上下文精确率权重高于第二个分块，第二个分块又高于第三个分块，依此类推，同时将作为上下文输出的分块顺序纳入考虑。

- **上下文召回率** – 衡量上下文与期望的 RAG 输出（标准答案）之间的一致性。与忠实度类似，会检查标准答案中的每条陈述是否归属于上下文（从而评估上下文）。

- **答案相似度** – 评估 RAG 输出（答案）与期望答案（标准答案）之间的语义相似度，取值范围为 0–1。分数越高表示表现越好。首先生成答案和标准答案的 embedding，然后使用交叉编码器 Tiny BERT 模型预测一个 0–1 之间的分数，表示这些 embedding 的语义相似度。

- **答案相关性** – 关注生成的 RAG 输出（答案）与问题的相关程度。对不完整或包含冗余信息的答案会给出更低分数。为计算该分数，会要求 LLM 根据给定答案生成多个问题。然后使用 Amazon Titan Embeddings 模型，为生成的问题和实际问题生成 embedding。因此该指标是所有生成问题与实际问题之间的平均余弦相似度。

- **答案正确性** – 这是生成答案与标准答案之间的准确程度。它的计算基于答案与标准答案之间的语义相似度指标，并结合通过查看上下文得出的事实相似度。如果你想采用 0 或 1 的二元答案正确性分数，可以使用一个阈值；否则会生成 0–1 之间的数值。

## AutoPrompt —— 为 RAG 自动生成指令

其次，生成式 AI 服务已被证明能够成功生成并选择用于提示 FM 的指令。简而言之，指令由 FM 生成，它们能基于某种风格，最好地把问题和上下文映射到 RAG QA 机器人的答案。这一过程使用 [Auto-Instruct 库](https://github.com/ytyz1307zzh/Auto-Instruct)完成。该方法利用 FM 生成候选指令的能力，再用一个评分模型对候选指令排序，以确定最有效的 prompt。

首先，你需要请 Amazon Bedrock 上的 Anthropic Claude 模型为一组输入（问题和上下文）生成一条指令，使其映射到一个输出（答案）。然后要求该 FM 生成特定类型的指令，例如一段式指令、一句话指令或分步指令。随后会生成许多候选指令。[查看 generate_candidate_prompts() 函数以了解代码中的逻辑。](https://github.com/aws-samples/automatic-prompt-engineering/blob/main/src/utils/functions.py)

接着，用评估 FM 让这些候选指令相互比较测试。为此，首先把每条指令与其他所有指令进行比较。然后使用评估 FM，评估在给定任务（查询加待回答的上下文对）下这些 prompt 的质量。一对候选指令的评估逻辑见 [test_candidate_prompts() 函数。](https://github.com/aws-samples/automatic-prompt-engineering/blob/main/src/utils/functions.py)

这会输出该框架生成的最理想 prompt。对每个问答对，输出包括最佳指令、次佳指令和第三佳指令。

要演示如何执行自动 prompt engineering（以及调用 Ragas）：

- 浏览以下 [notebook](https://github.com/aws-samples/automatic-prompt-engineering/blob/main/notebooks/Prompt_Engineer_Ragas.ipynb)。

- 生成和评估候选 prompt 的代码片段包含在这个[源文件](https://github.com/aws-samples/automatic-prompt-engineering/blob/main/notebooks/Prompt_Engineer_Ragas.ipynb)中，其相关 prompt 包含在这个[配置文件](https://github.com/aws-samples/automatic-prompt-engineering/blob/main/src/utils/configs.py)中。

你可以在[完整仓库](https://github.com/aws-samples/automatic-prompt-engineering)中查看使用 Amazon Bedrock 的 FM 进行自动 prompt engineering 的示例。

## 结语

总体而言，AWS 团队能够使用 Ragas 库，借助 Amazon Bedrock 上的各种 FM，在输入查询、RAG 响应、检索到的上下文和期望标准答案的情况下评估 Tealium 的 RAG QA 机器人。它通过查明以下几点实现了这一评估：

- RAG 响应是否归属于上下文。

- 上下文是否归属于查询。

- 标准答案是否归属于上下文。

- RAG 响应是否与问题相关、且与标准答案相似。

因此，它能够评估 RAG 解决方案检索相关上下文并准确回答示例问题的能力。

此外，FM 能够从一个问答对生成多条指令，并基于回答质量对它们排序。生成指令之后，它能够小幅改进 LLM 回答中的错误。人在回路演示为不同 prompt 和指令的输出提供了并排视图。这是一种增强的点赞/点踩方式，可基于人工反馈进一步改进输入到 RAG 机器人的内容。

该解决方案的一些后续步骤包括：

- 基于特定指标，使用不同模型或不同分块策略来提升 RAG 表现

- 试验不同策略以优化评估自动 prompt engineering 阶段所生成指令的成本（FM 调用次数）

- 允许在人工评估步骤中采纳 SME 反馈，以自动改进标准答案或指令模板

在与 Tealium 的整个合作过程中，Amazon Bedrock 的价值得到了体现。Amazon Bedrock 在选择广泛的一流 FM 方面的灵活性，以及为特定任务定制模型的能力，使 Tealium 能够在未来以最少改动、以专业化的方式驱动该解决方案。Amazon Bedrock 在文本生成中的重要性以及评估的成功，在本次合作中得到了体现，为 Tealium 在该解决方案上继续构建提供了潜力与灵活性。它对安全的重视让 Tealium 有信心构建和交付更安全的应用。
