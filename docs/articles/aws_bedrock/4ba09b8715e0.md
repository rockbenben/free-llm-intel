# 使用 Amazon Bedrock Evaluations 评估模型或 RAG 系统——现已正式可用

部署生成式 AI 应用的组织需要可靠的方式来评估其性能与可靠性。当我们在 AWS re:Invent 2024 上以公开预览形式[推出 LLM-as-a-judge（LLMaJ）和检索增强生成（RAG）评估能力](https://aws.amazon.com/blogs/aws/new-rag-evaluation-and-llm-as-a-judge-capabilities-in-amazon-bedrock/)时，客户用它们来评估自己的基础模型（FM）和生成式 AI 应用，但希望获得超越 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 模型与知识库的更多灵活性。今天，我们很高兴宣布这些评估功能已在 [Amazon Bedrock Evaluations](https://aws.amazon.com/bedrock/evaluations/) 中正式可用，并带来了一系列重要增强，使其完全与环境无关。

正式可用版本为 RAG 评估和模型评估引入了“自带推理响应”（bring your own inference responses）能力。这意味着，只要以要求的格式提供评估数据，你现在就能评估一个 RAG 系统或模型——无论它运行在 Amazon Bedrock、其他云厂商还是本地环境。你甚至可以评估一个已经建成的应用的最终响应。我们还为原本就很强大的 RAG 评估套件新增了引用指标，包括引用精确率（citation precision）和引用覆盖率（citation coverage），帮助你更好地衡量 RAG 系统使用检索到的信息的准确程度。这些指标能更深入地揭示响应是否有据可依地建立在源文档之上，以及是否用到了最相关的检索段落。

在本文中，我们详细探讨这些新功能，并通过实际示例展示如何评估 RAG 系统和模型。我们会演示如何使用对比能力对不同实现进行基准测试，并为你的人工智能部署做出数据驱动的决策。无论你的生成式 AI 应用运行在 Amazon Bedrock 还是其他环境，这些评估工具都能帮助你优化性能，并在整个生成式 AI 组合中提升质量。

## RAG 评估的新变化

本节讨论 RAG 评估的新变化，包括引入 Bring Your Own Inference 响应以评估外部 RAG 系统，以及衡量 RAG 引用精确率与覆盖率的新指标。

### 自带推理响应（Bring Your Own Inference responses）

RAG 评估能力已大幅扩展，现在可以通过 Amazon Bedrock 中的评估环境，评估托管在任何位置的 RAG 系统的输出。借助自带推理（BYOI）响应，只要以要求的格式提供输出，你现在就能评估来自各类来源的检索与生成结果，包括其他 FM 提供商、自建的 RAG 系统或已部署的开源权重方案。此外，新引入的引用指标与我们此前发布的质量指标、负责任 AI 指标一起，能更深入地揭示 RAG 系统使用其知识库和源文档的效果。

在评估知识库的检索结果时，每个评估作业只允许评估一个知识库。对于每条数据集条目，你可以提供一个对话轮次列表。每个对话轮次目前包含一个 prompt 和 `referenceResponses`。使用 BYOI 时，你必须在名为 output 的新字段中提供检索结果（该字段对 BYOI 作业是必填的，对非 BYOI 作业可选且不需要）。你必须为每个 output 提供 `knowledgeBaseIdentifier`。此外，对你带来的每个检索结果，你都可以提供名称以及以键值对形式给出的附加元数据。以下是 RAG 评估作业（Retrieve）的输入 JSONL 格式。带 ? 的字段为可选字段。

在 2025 年 3 月 20 日结束的公开预览期间，以下数据集格式包含一个名为 `referenceContexts` 的键。该字段现已改为 `referenceResponses`，以与 Retrieve and Generate 评估保持一致。`referenceResponses` 的内容应是端到端 RAG 系统在给定该 prompt 时应生成的期望标准答案，而不是从知识库中检索到的期望段落或分块。

### 引用指标

引用精确率衡量 RAG 系统引用其来源的准确程度，具体做法是评估被引用的段落是否真的包含响应中所使用的信息。该指标有助于识别响应中包含不必要或不相关引用的情况——这是一个常见问题，模型可能引用实际上并未用于生成响应内容的段落。该指标给出 0–1 之间的分数，1 表示引用精确率完美（所有被引段落都相关且被用于响应），0 表示完全不精确（被引段落都不该被使用）。这有助于团队识别并修复 RAG 系统不加区分地引用段落、而不是只挑出对响应有贡献的段落的问题。

引用覆盖率评估响应的内容在多大程度上得到其引用的支撑，重点在于所有来自检索段落的信息是否都被恰当引用。该指标会比较响应相对于被引段落和全部检索段落的忠实度，然后计算两者的比值。在响应与检索段落完全不符（例如幻觉）的情况下，该指标会表明引用覆盖率评估不适用。该指标给出 0–1 的分数，越接近 0 表示模型未能引用相关的支撑段落，越接近 1 表示已恰当引用来自检索段落的信息。重要的是，满分 1 并不必然意味着响应中的所有信息都被引用——它表示所有本可被引用的信息（基于检索到的段落）都得到了恰当的引用。这有助于团队发现 RAG 系统错失引用相关源材料机会的情况。

## 模型评估的新变化

本节讨论模型评估的新变化，包括扩展后的 Bring Your Own Inference 能力——你可以通过 LLMaaJ 和人工评估两种工作流，评估来自外部提供商和已部署方案的模型响应。

### 自带推理响应（Bring Your Own Inference responses）

模型评估能力已大幅扩展，现在可以评估通过 Amazon Bedrock 评估环境可用的模型输出。借助 BYOI 响应，只要以要求的格式提供输出，你现在就能评估来自其他 FM 提供商或已部署方案的模型响应。BYOI 同时适用于 LLMaJ 和人工评估工作流。

你不必把这些评估局限在基础模型上。由于 BYOI 评估接收 prompt 和输出，如果你选择把完整应用的最终响应带入数据集，它就能评估该响应。

使用 LLMaaJ 时，每个评估作业只能评估一个模型。因此，每次评估你只需在 `modelResponses` 列表中提供一条记录，不过你可以运行多个评估作业来比较不同模型。`modelResponses` 字段对 BYOI 作业是必填的，对非 BYOI 作业则不需要。以下是带 BYOI 的 LLMaaJ 的输入 JSONL 格式。带 `?` 的字段为可选字段。

```
{
    "prompt": string
    "referenceResponse"?: string
    "category"?: string
     "modelResponses"?: [
        {
            "response": string
            "modelIdentifier": string
        }
    ]
}
```

使用人工评估时，每个评估作业最多可评估两个模型。因此，你最多可以在 `modelResponses` 列表中提供两条记录，每个响应都需要一个唯一标识符。`modelResponses` 字段对 BYOI 作业是必填的，对非 BYOI 作业则不需要。以下是带 BYOI 的人工评估的输入 JSONL 格式。带 `?` 的字段为可选字段。

```
{
    "prompt": string
    "referenceResponse"?: string
    "category"?: string
    "modelResponses"?: [
        {
            "response": string
            "modelIdentifier": string
        },
        {
            "response": string
            "modelIdentifier": string
        }
    ]
}
```

带 BYOI 的 LLMaaJ 评估工作流让你能使用 Amazon Bedrock 模型评估能力，系统性地评估来自你所选来源的模型输出。整个流程简单直观：先选择评估器模型并配置 BYOI，再挑选合适的指标、上传评估数据集、运行评估，最后分析详细结果。这条完整的评估 pipeline（如下图所示）有助于让你的 AI 实现在任何部署位置都保持一致的质量。

## 先决条件

要结合 BYOI 使用 LLMaaJ 模型评估和 RAG 评估功能，你必须具备以下先决条件：

- AWS 账户与模型访问权限：一个有效的 [AWS 账户](https://signin.aws.amazon.com/signup?request_type=builderId)；已在 Amazon Bedrock 中启用所选的评估器模型（可在 [Amazon Bedrock 控制台](https://aws.amazon.com/bedrock/)的 **Model access** 页面确认）；已确认 [AWS 区域](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region)，以及这些模型在该区域的[可用性及配额](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)
- [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）与 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）配置：已完成 IAM 设置并获得模型评估与 RAG 评估所需的[权限](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-evaluation-prereq.html)；已配置具备访问和写入输出数据相应权限的 [S3 存储桶](https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-policy-language-overview.html)；已在 S3 存储桶上启用 [CORS](https://docs.aws.amazon.com/bedrock/latest/userguide/model-evaluation-security-cors.html)

## 数据集说明与准备

为演示带 BYOI 的 LLMaaJ 评估作业，我们使用第三方模型构建了一个购物数学题数据集。该数据集包含 30 道折扣计算题，每道题都按要求的 BYOI 格式给出 prompt、参考答案和模型响应。每条记录在 `modelResponses` 数组中使用 `"third-party-model"` 标识符，使 LLMaaJ 评估器能够按照你选定的指标评估响应质量。

我们用于带 BYOI 的 RAG 评估作业的数据集，是使用 Amazon 的 10-K SEC 备案信息构建的。数据集中的每条记录都包含关于 Amazon 公司信息的问题（例如 SEC 文件编号、经营分部和财年报告）、参考响应，以及第三方模型生成的答案及其对应的检索段落和引用。该数据集遵循要求的 BYOI 格式，每条记录都使用 `"third-party-RAG"` 作为知识库标识符。这种结构使你能同时评估检索与生成的质量指标以及引用准确性，展示组织如何评估部署在任何位置的 RAG 系统。

## 使用 Python SDK 和 API 启动带 BYOI 的 LLMaaJ 评估作业

## 结论

Amazon Bedrock 上 LLM-as-a-judge 与 RAG 评估的正式可用版本带来了与环境无关的“自带推理”（bring your own inference）能力，使组织无论 RAG 系统或模型运行在哪里都能对其进行评估。作为 RAG 评估指标列表的一部分发布的新引用指标，通过提供引用精确率和覆盖率的度量，增强了信息质量评估，并支持在不同实现之间进行数据驱动的比较。

随着组织部署越来越多的生成式 AI 应用，稳健的评估对维持质量、可靠性和负责任使用变得至关重要。我们鼓励你通过 Amazon Bedrock 控制台以及 AWS Samples [GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-samples/tree/main/evaluation-observe/bedrock-eval-bring-your-own-inference)中提供的示例来探索这些新功能。通过实施定期的评估工作流，你可以持续改进模型和 RAG 系统，为你的具体用例交付最高质量的输出。

我们鼓励你探索 Amazon Bedrock Evaluations 的这些能力，并了解系统性评估如何增强你的生成式 AI 应用。
