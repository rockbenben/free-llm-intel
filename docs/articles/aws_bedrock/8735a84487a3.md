# 基准测试 Amazon Nova：通过 MT-Bench 与 Arena-Hard-Auto 展开的综合分析

大语言模型（LLM）发展迅速，已成为从对话式 AI 到复杂推理任务等各种应用不可或缺的组成部分。然而，随着模型规模与能力的增长，有效评估其性能变得越来越具有挑战性。困惑度（perplexity）和 BLEU 分数等传统基准测试指标往往无法捕捉真实世界交互中的细微差别，这使得与人类判断对齐的评估框架变得至关重要。理解 LLM 是如何被评估的，有助于实现更可靠的部署，并在不同模型之间进行公平比较。

本文中，我们探讨基于 LLM-as-a-judge 的自动化评估与人类对齐评估方法。LLM-as-a-judge 是指用一个能力更强的 LLM，依据正确性、连贯性、有用性或推理深度等预设标准，对其他 LLM 生成的回答进行评估与排序。与完全依赖人类评审员相比，这种方法具备可扩展性、一致性、更快的迭代速度与成本效率，因此日益流行。我们讨论 LLM-as-a-judge 的不同评估场景，包括成对比较（pairwise comparison）——让两个模型或两条回答相互对判——以及单回答评分（single-response scoring）——依据预设标准对单个输出评分。为了提供具体见解，我们使用 MT-Bench 和 Arena-Hard 这两个被广泛采用的评估框架。MT-Bench 提供结构化的多轮评估方式，针对类聊天机器人的交互而设计；Arena-Hard 则侧重于通过在具有挑战性的推理与指令遵循任务中开展正面对决，对 LLM 进行排名。这些框架旨在弥合自动化判断与人类判断之间的差距，确保 LLM 不仅依据合成基准被评估，也被放在实际用例中检验。

[MT-Bench](https://github.com/lm-sys/FastChat/blob/main/fastchat/llm_judge/README.md) 和 [Arena-Hard](https://github.com/lmarena/arena-hard-auto/blob/main/README.md) 的代码仓库最初是基于 OpenAI 的 GPT API 开发的，主要使用 GPT-4 作为评审模型。我们的团队将其与 [Amazon Bedrock](https://aws.amazon.com/bedrock/) API 集成，从而可以使用 Amazon 上的 Anthropic Claude Sonnet 作为评审，扩展了其功能。本文中，我们同时使用 MT-Bench 和 Arena-Hard，把 [Amazon Nova](https://aws.amazon.com/blogs/aws/introducing-amazon-nova-frontier-intelligence-and-industry-leading-price-performance/) 模型与通过 Amazon Bedrock 可用的其他领先 LLM 进行比较，对其进行基准测试。

## Amazon Nova 模型与 Amazon Bedrock

我们的研究评估了 Amazon Nova 家族的全部四款模型，包括该家族最新加入的 Amazon Nova Premier。Amazon Nova 模型于 2024 年 12 月在 AWS re:Invent 上推出，旨在以领先的性价比提供前沿水平的智能。这些模型在各自所处的智能类别中都跻身速度最快、最经济的选择之列，并且专门针对以高性价比、安全、可靠的方式支撑企业级生成式 AI 应用而优化。

理解模型家族包含四个不同的层级：Amazon Nova Micro（纯文本，面向超高效的边缘部署设计）、Amazon Nova Lite（多模态，针对通用性进行优化）、Amazon Nova Pro（多模态，为大多数企业应用在智能与速度之间提供理想平衡）以及 Amazon Nova Premier（多模态，代表处理复杂任务的最先进 Nova 模型，并作为模型蒸馏的教师模型）。Amazon Nova 模型支持广泛的应用场景，包括编码、推理与结构化文本生成。

此外，通过 [Amazon Bedrock Model Distillation](https://aws.amazon.com/bedrock/model-distillation/)，客户可以将 Nova Premier 的智能能力迁移到 Nova Pro 或 Nova Lite 等更快、更具成本效益的模型上，并针对特定领域或用例进行定制。该功能可通过 Amazon Bedrock 控制台和 API（包括 Converse API 与 Invoke API）使用。

## MT-Bench 分析

MT-Bench 是一个使用 LLM-as-a-judge 的统一框架，基于一组[预定义问题](https://github.com/lm-sys/FastChat/blob/main/fastchat/llm_judge/data/mt_bench/question.jsonl)。评估问题是一组具有挑战性的多轮开放式问题，用于评估聊天助手。用户也可以灵活地按自身需求定义自己的问题与答案对。该框架向模型提出横跨八个关键领域的具有挑战性的多轮问题：

- 写作
- 角色扮演
- 推理
- 数学
- 编码
- 数据抽取
- STEM
- 人文

LLM 使用两类评估方式进行评估：

- **单回答评分** —— 此模式要求 LLM 评审员直接为模型的回答打分，不做成对比较。每一轮中，LLM 评审员按 0–10 的量表给出分数，然后对所有轮次计算平均分。
- **基于胜率的评分** —— 此模式使用两个指标：**pairwise-baseline** —— 与基线模型进行成对比较。**pairwise-all** —— 在所有问题上对所有模型两两进行成对比较。

### 评估设置

本研究中，我们采用 Anthropic 的 Claude 3.7 Sonnet 作为我们的 LLM 评审员，因为在我们开展研究时，它属于可用的最先进语言模型之一。我们只关注单回答评分，即由 LLM 评审员直接评估并为模型生成的回答打分，不进行成对比较。

我们研究覆盖的八个领域大致可分为两类：具有确定标准答案（ground truth）的领域和没有确定标准答案的领域。具体来说，推理、数学、编码与数据抽取属于前者，因为它们通常有参考答案，可以据此对回答进行客观评估。相反，写作、角色扮演、STEM 与人文往往缺乏这种明确的标准答案。下面给出 `Writing` 和 `Math` 类别的一个示例问题：

```
{
    "question_id": 81,
    "category": "writing",
    "turns": [
        "Compose an engaging travel blog post about a recent trip to Hawaii, 
        highlighting cultural experiences and must-see attractions.", 
        "Rewrite your previous response. Start every sentence with the letter A."
    ]
}
{
    "question_id": 111,
    "category": "math",
    "turns": [
        "The vertices of a triangle are at points (0, 0), (-1, 1), and (3, 3). 
         What is the area of the triangle?",
        "What's area of the circle circumscribing the triangle?"
    ],
    "reference": [
        "Area is 3",
        "5pi"
    ]
}
```

为处理这一区别，MT-Bench 为每个类别采用不同的评审 prompt（参见下面的 [GitHub repo](https://github.com/lm-sys/FastChat/blob/main/fastchat/llm_judge/data/mt_bench/question.jsonl)），使评估过程贴合当前任务的性质。如下面的评估 prompt 所示，对于没有参考答案的问题，MT-Bench 采用 `single-v1` prompt，只传入问题与模型生成的回答。评估有参考答案的问题时，它只额外传入 `reference_answer`，如 `single-math-v1` prompt 所示。

```
{
    "name": "single-v1",
    "type": "single",
    "system_prompt": "You are a helpful assistant.",
    "prompt_template": 
        "[Instruction]\nPlease act as an impartial judge and evaluate the quality of
         the response provided by an AI assistant to the user question displayed below. 
         Your evaluation should consider factors such as the helpfulness, relevance, accuracy, 
         depth, creativity, and level of detail of the response. Begin your evaluation by providing a short explanation. Be as objective as possible. 
        After providing your explanation, you must rate the response on a scale of 1 to 10 by strictly following this format: \"[[rating]]\", 
        for example: \"Rating: [[5]]\".\n\n[Question]\n{question}\n\n[The Start of Assistant's Answer]\n{answer}\n[The End of Assistant's Answer]",
    "description": "Prompt for general questions",
    "category": "general",
    "output_format": "[[rating]]"
}
{	
    "name": "single-math-v1",
    "type": "single",
    "system_prompt": "You are a helpful assistant.",
    "prompt_template": 
        "[Instruction]\nPlease act as an impartial judge and evaluate the quality of the response provided by an AI assistant 
        to the user question displayed below. Your evaluation should consider correctness and helpfulness. 
        You will be given a reference answer and the assistant's answer. Begin your evaluation by comparing the assistant's answer with the reference answer. 
        Identify and correct any mistakes. Be as objective as possible. After providing your explanation, 
        you must rate the response on a scale of 1 to 10 by strictly following this format: \"[[rating]]\", for example: \"Rating: [[5]]\".
        \n\n[Question]\n{question}\n\n[The Start of Reference Answer]\n{ref_answer_1}\n[The End of Reference Answer]
        \n\n[The Start of Assistant's Answer]\n{answer}\n[The End of Assistant's Answer]",
    "description": "Prompt for general questions",
    "category": "math",
    "output_format": "[[rating]]"
}
```

### Amazon Nova 模型的整体性能分析

在以 Anthropic 的 Claude 3.7 Sonnet 作为 LLM-as-a-judge 框架的评估中，我们观察到 Amazon Nova 模型之间存在清晰的性能层级。分数范围为 8.0 至 8.6，其中 Amazon Nova Premier 取得了最高的中位数分数 8.6，Amazon Nova Pro 以 8.5 紧随其后。Amazon Nova Lite 与 Nova Micro 都取得了 8.0 这一相当不错的中位数分数。

除中位数分数之外，区分这些模型的还有其性能一致性。Nova Premier 在各评估类别中表现最为稳定，最小值与最大值之间的差距仅 1.5（从 7.94 到 9.47）。相比之下，Nova Pro 的波动更大，极差为 2.7（从 6.44 到 9.13）。同样，从各自的极差可以看出，Nova Lite 的表现比 Nova Micro 更一致。对于响应时间至关重要的企业部署，Nova Lite 与 Nova Micro 表现出色，单次问题–回答生成的平均延迟均低于 6 秒。这一性能特征使它们尤其适合边缘部署场景以及对延迟有严格要求的应用。考虑到其更低的成本，对于许多性能分数略有下降是可接受取舍的实际用例来说，这些模型都是极具吸引力的选择。

有趣的是，我们的分析显示，Amazon Nova Premier 尽管是最大的模型，却展现出更优的 token 效率。它生成的回答更简洁，单次问题–回答生成所消耗的 token 比同类模型最多少 190 个。这一观察与研究结论一致：更复杂的模型通常更善于过滤无关信息并高效地组织回答。

表现最好与表现最差的模型之间仅有 0.6 分的差距，这表明 Amazon Nova 的所有变体都展现出强劲的能力。尽管 Nova Premier 等更大的模型提供了略好的性能与更高的一致性，但当延迟与成本被优先考虑时，较小的模型是颇具吸引力的替代方案。这样的性能画像让开发者能够根据自身具体的应用需求灵活选择合适的模型。

本研究中，我们采用 Anthropic 的 Claude 3.7 Sonnet 作为唯一的 LLM 评审员。然而，尽管 Anthropic 的 Claude 3.7 Sonnet 因其能力而成为 LLM 评审的常见选择，但已有研究表明它确实存在某些偏差（例如偏好更长的回答）。如果时间与资源允许，可以考虑采用多 LLM 评审员的评估框架，以有效降低单个 LLM 评审员固有的偏差，提高评估的可靠性。

## Arena-Hard-Auto 分析

Arena-Hard-Auto 是一个基准，它使用 500 条具有挑战性的 prompt 作为数据集，通过 LLM-as-a-judge 评估不同的 LLM。该数据集由一个名为 [BenchBuilder](https://arxiv.org/pdf/2406.11939) 的自动化 pipeline 精选而成，它使用 LLM 自动对来自 [Chatbot-Arena](https://lmarena.ai/) 等大型众包数据集的开放式 prompt 进行聚类、评分与过滤，从而在无需人工介入的情况下实现持续基准测试。论文报告称，与 MT-Bench 相比，新的评估指标对模型性能的区分度高出三倍，并且与人类偏好排名的相关性达到 98.6%。

### 测试框架与方法

Arena-Hard-Auto 基准框架通过成对比较来评估不同的 LLM。每个模型的性能都通过与一个强大的基线模型比较来量化，并采用结构化、严谨的设置以生成可靠且细致的判断。我们在评估中使用以下组件：

- **成对比较设置** —— 模型不再被孤立评估，而是直接与一个强大的基线模型比较。该基线提供了固定标准，使人可以直观地理解这些模型相对于一个本身已属高性能的模型表现如何。
- **具备细粒度类别的评审模型** —— 使用一个强大的模型（Anthropic 的 Claude 3.7 Sonnet）作为评审员。该评审员不仅仅判定哪个模型更好，还会把比较结果归入五种细致的偏好标签。通过使用这种有层次的量表，大的性能差距会比小的差距受到更重的惩罚，从而有助于依据性能差异更有效地区分模型：`A >> B`（A 显著优于 B）`A > B`（A 优于 B）`A ~= B`（A 与 B 相近）`B > A`（B 优于 A）`B >> A`（B 显著优于 A）
- **思维链（CoT）prompting** —— CoT prompting 鼓励评审模型在给出最终判断前解释其推理过程。这一过程帮助模型深入分析每条回答而不是草率决策，从而带来更周详、更可靠的评估。
- **双局设置以规避位置偏差** —— 为尽量减少某个模型总是被排在第一位或第二位可能带来的偏差，每一对模型都会被评估两次，并交换模型的顺序。这样，如果存在对某个位置上的模型的偏好，该设置也能加以控制。判断总数因此翻倍（例如 500 次查询 x 2 个位置 = 1,000 次判断）。
- **使用 Bradley-Terry 模型打分** —— 完成比较后，应用 [Bradley-Terry](https://blog.lmarena.ai/blog/2024/extended-arena/) 模型计算每个模型的最终分数。该模型利用成对比较数据估计每个模型的相对实力，这种估计不仅反映获胜次数，也反映获胜的强度。与简单计算胜率相比，这种打分方法更稳健，因为它考虑了各模型之间的成对结果。
- **用 Bootstrapping 保证统计稳定性** —— 通过对比较结果反复重采样（bootstrapping），评估在统计上变得稳定。这种稳定性之所以有益，是因为它确保模型排名可靠，并且对数据中的随机波动不那么敏感。
- **风格控制** —— 使用[风格控制](https://lmsys.org/blog/2024-08-28-style-control/)把回答长度、markdown 格式等某些风格特征与内容质量分离开来，以便更清晰地评估每个模型的内在能力。

原始工作只关注成对比较。在我们的基准测试中，我们还加入了自行实现的单分判断，灵感来自 MT-Bench。我们同样使用 Anthropic 的 Claude 3.7 Sonnet 作为评审员，并在没有参考模型的情况下使用以下 prompt 进行评审：

```
{	
	"system_prompt": 
		"Please act as an impartial judge and evaluate the quality 
		of the response provided by an AI assistant to the user question 
		displayed below. Your evaluation should consider factors 
		such as the helpfulness, relevance, accuracy, depth, creativity, 
		and level of detail of the response. 
		Begin your evaluation by providing a short explanation. 
		Be as objective as possible. After providing your explanation, 
		you must rate the response on a scale of 1 to 10 by strictly 
		following this format: \"[[rating]]\", for example: \"Rating: [[5]]\"."
}
```

### 性能对比

我们评估了五个模型，包括 Amazon Nova Premier、Amazon Nova Pro、Amazon Nova Lite、Amazon Nova Micro、DeepSeek-R1 以及一个强大的参考模型。如前所述，Arena-Hard 基准通过 bootstrapping 生成置信区间。95% 置信区间体现了模型的不确定性，也指示了模型性能。从下图可以看到，所有 Amazon Nova 模型都取得了较高的成对 Bradley-Terry 分数。需要说明的是，参考模型的 Bradley-Terry 分数为 5；这是因为 Bradley-Terry 分数由成对比较计算得出，而参考模型本身就是配对中的一个模型。因此，对参考模型而言，得分将是 50%，又因为总分被归一化到 0 与 10 之间，所以参考模型的分数为 5。

每输出 token 的成本是构成 LLM 模型总体成本的要素之一，并会影响使用。成本基于 500 条回答的平均输出 token 数计算得出。尽管 Amazon Nova Premier 在性能上领先（85.22），但 Nova Light 与 Nova Micro 尽管置信区间更宽，仍提供了极具吸引力的价值。Nova Micro 以便宜 89 倍的成本实现了 Nova Premier 69% 的性能，而 Nova Light 以低 52 倍的价格达到了 Nova Premier 79% 的能力。这些惊人的成本效率使更实惠的 Nova 模型成为许多并不要求绝对顶尖性能的应用的诱人选择，也凸显了 Amazon Nova 家族在性能与成本之间的有效权衡。

## 结论

本文中，我们探讨了如何借助 MT-Bench 与 Arena-Hard 基准，通过 LLM-as-a-judge 严格评估模型性能。随后我们把 Amazon Nova 模型与一个领先的推理模型——即托管在 Amazon Bedrock 上的 DeepSeek-R1——进行比较，分析它们在各种任务上的能力。我们的发现表明，Amazon Nova 模型交付了强劲的性能，尤其在抽取、人文、STEM 与角色扮演方面，同时保持了较低的运营成本，这使其成为希望在不牺牲质量的前提下优化效率的企业的有竞争力选择。这些见解凸显了基准测试方法论在指导真实应用中的模型选择与部署决策方面的重要性。
