任何处理语音音频的团队在通用语音转文本上都会撞上同一堵墙。想想联络中心通话、全员会议、播客、取证证词和广播媒体。这些工作负载需要两样标准转录做不对的东西。第一，时间戳落在话语级别，偏差几秒。第二，没有对“谁说了什么”的可靠答案。这些缺口让转录稿难以大规模搜索、加字幕、脱敏或分析。一个缺失的说话人标签会破坏合规审阅，而一个不精确的时间戳会破坏一个字幕或一次脱敏。

WhisperX 弥合了这两个缺口。它用批量推理封装 OpenAI 的 Whisper，为精确的逐词时间戳加上 wav2vec2 强制对齐，并加上说话人分离来标注谁说了话。这些能力直接映射到真实工作负载。联络中心可以测量通话时长、检查脚本遵循度并运行情感分析，而团队把会议变成可搜索的笔记。媒体和在线学习团队为大型内容库生成准确的字幕（以 SubRip Subtitle (SRT) 和 Web Video Text Tracks (VTT) 格式）。时间敏感的用例在某人说话的当下就得到文本。在医疗、法律和金融这类受监管领域，带说话人标签的转录稿支持审计和法律取证。

AWS WhisperX Deep Learning Container (DLC) 把这一切打包进一个 GPU 就绪的镜像。你把它部署到一个 Amazon SageMaker AI 实时或异步端点，而无需构建自定义镜像。在本文中，我们展示如何部署这两种端点类型，以及何时各选其一。我们还涵盖那些重要的生产细节：GPU AMI 固定、伸缩、Amazon Simple Storage Service (Amazon S3) 设置，以及成本控制。本文是展示专用 AWS DLC 的一个多模态系列的一部分。该系列跨三个 AWS DLC、覆盖四个用例：(1) vLLM-Omni 用于文本转语音，(2) vLLM-Omni 用于图像和视频，(3) WhisperX 用于语音转文本（本文），以及 (4) llama.cpp。

## 什么是 WhisperX，它解锁了哪些工作负载

Whisper 是 OpenAI 一个流行的开源自动语音识别（ASR）模型家族，它把语音音频在多语言上准确地转录成文本。它聚焦于高质量转录，并在短语或段级别产生时间戳。WhisperX 是一个建立在 Whisper 之上、为生产工作负载扩展它的开源项目。它加上逐词时间戳、说话人标签和更快的转录——这三项能力合起来把原始音频变成结构化、可分析的转录稿。

## 为什么用一个专为该目的打造的深度学习容器

AWS WhisperX DLC 是一个受维护、GPU 就绪的镜像，已经含有 Whisper、对齐模型和分离权重，且不需要 Hugging Face token。它遵循标准的 Amazon SageMaker AI 服务契约，因此你像部署任何其他模型一样部署它。

- **服务契约：** 容器在端口 `8080` 上服务，暴露 `POST /invocations` 做推理，`GET /ping` 做健康检查。
- **请求格式：** 端点期待 `multipart/form-data`，音频作为 `file` 部分，加上可选的字符串字段，如 `language`、`diarize` 和 `response_format`。Amazon SageMaker AI 把 `ContentType` 头（含 multipart 边界）原样传给容器。
- **输出格式：** `json`、`verbose_json`、`srt` 和 `vtt`，于是同一个端点同时喂养分析流水线和视频编辑器。

## 在实时与异步端点之间选择

Amazon SageMaker AI 同时支持实时和异步端点，因此你可以通过任一种模式服务同一个 WhisperX DLC。这个决定通常归结为片段长度和交互性。对于长音频，用异步端点：当转录、对齐和分离需要更多时间运行时，它是推荐的路径。把实时端点留给那些能在 Amazon SageMaker AI 60 秒响应上限内完成的、短的交互式片段。

| **维度** | **实时端点** | **异步端点** |
| --- | --- | --- |
| 最适合 | 短的交互式片段 | 长音频、高容量批处理 |
| 延迟 | 同步，必须在 < 60 秒内完成 | 提交并轮询。无响应上限 |
| 调用 | InvokeEndpoint（内联体） | InvokeEndpointAsync（S3 引用） |
| I/O | 请求/响应中的体 | 输入 + 输出在 Amazon S3 |
| 伸缩 | 添加实例（一请求/容器） | 添加实例。可缩放到零 |
| 成本特征 | 端点起来时计费 | 空闲时缩放到零节省成本 |

## 方案架构

两种模式共享同一个容器契约。Amazon SageMaker AI 把每个请求转发到端口 `8080` 上的 WhisperX DLC。实时模式是同步的，而异步模式通过 Amazon S3 中介输入和输出。实例选择（`ml.g4dn.xlarge` 为成本，`ml.g5.2xlarge` 为余量）和必需的 GPU AMI 固定都适用于两者，而你通过添加实例而非并发来伸缩吞吐。每种端点类型的请求/响应序列在其演练一节展示。

## 前提条件

- 一个 AWS 账户和一个能 `create_model`、`create_endpoint`，以及（对异步推理）读写 S3 的 Amazon SageMaker AI execution 角色。
- 为你的端点实例类型（例如 `ml.g4dn.xlarge` 或 `ml.g5.2xlarge`）的 **GPU 服务配额**。
- 来自 Amazon Elastic Container Registry (Amazon ECR) 的 **WhisperX DLC 镜像 URI**（例如 `763104351884.dkr.ecr.<region>.amazonaws.com/whisperx:3.8.6-cu128-amzn2023-sagemaker`）。
- 对于异步推理，一个名字含“sagemaker”的 S3 桶。默认的 `AmazonSageMakerFullAccess` 策略只授予对这类桶的 S3 访问。

[AWS Samples 仓库](https://github.com/aws-samples/sagemaker-genai-hosting-examples/tree/main/03-features/speech-to-text-whisperx-sagemaker)中有一个完整、可运行的 JupyterLab notebook，端到端演练这些步骤。你可以在 Amazon SageMaker AI Studio 中针对你自己的音频运行它。

## 演练：实时端点

实时端点在同一同步调用中返回转录稿。把它用于那些能从容在 60 秒上限内完成的短片段。图 1 是一个序列图，端到端追踪单个实时请求，从客户端调用，到容器内转录，到内联转录稿。

图 1：实时端点同步 InvokeEndpoint 流程、容器内转录，以及 60 秒上限内的内联转录稿

端到端读这一序列：客户端组装一个 `multipart/form-data` 体（音频作为 `file` 部分，加上 `language`、`diarize` 和逐词时间戳粒度这类字段）并调用 `InvokeEndpoint`。Amazon SageMaker AI 把请求转发到端口 `8080` 上的容器，把 `ContentType` 及其 multipart 边界原样传入。在容器内，WhisperX 运行语音活动检测和批量 Whisper 转录、用于逐词时间戳的 wav2vec2 强制对齐，以及用于标注谁在说话的说话人分离。然后它序列化结果。运行时把转录稿（段、带时间戳的词和说话人标签）内联返回给客户端，而这必须在 Amazon SageMaker AI 的 60 秒响应上限内完成。

### 创建模型和端点配置

把 WhisperX DLC 注册为一个模型，其中 `IMAGE_URI` 指向 Amazon ECR 中的 WhisperX DLC，然后创建一个端点配置。在每个 GPU 变体上，你必须把 `InferenceAmiVersion` 设为 `al2-ami-sagemaker-inference-gpu-3-1`。没有这个固定，端点启动失败并报一个零日志的 `CannotStartContainerError`。留一个宽松的启动健康检查超时，因为权重是懒加载的。

```
sm = boto3.client("sagemaker")
# The WhisperX Deep Learning Container image (Python 3.12, CUDA 12.8, Amazon Linux 2023).
REGION = "us-west-2"
IMAGE_URI = f"763104351884.dkr.ecr.{REGION}.amazonaws.com/whisperx:3.8.6-cu128-amzn2023-sagemaker"

sm.create_model(
    ModelName=MODEL_NAME,
    PrimaryContainer={"Image": IMAGE_URI},  # WhisperX DLC; large-v2 is the default model
    ExecutionRoleArn=ROLE_ARN,
)

sm.create_endpoint_config(
    EndpointConfigName=ENDPOINT_CONFIG_NAME,
    ProductionVariants=[{
        "VariantName": "AllTraffic",
        "ModelName": MODEL_NAME,
        "InitialInstanceCount": 1,
        "InstanceType": "ml.g4dn.xlarge",
        "InferenceAmiVersion": "al2-ami-sagemaker-inference-gpu-3-1",  # required for CUDA 12.8 DLC
        "ContainerStartupHealthCheckTimeoutInSeconds": 900,
    }],
)

sm.create_endpoint(EndpointName=ENDPOINT_NAME, EndpointConfigName=ENDPOINT_CONFIG_NAME)
sm.get_waiter("endpoint_in_service").wait(EndpointName=ENDPOINT_NAME)
```

### 用分离和逐词时间戳调用

用一个以音频作 `file` 部分、加 `language=en`、`diarize=true` 和 `response_format=verbose_json` 这类字段构建一个 `multipart/form-data` 体。响应含段、逐词时间戳和说话人标签。

```
def build_multipart(audio_path, fields):
    """Audio as the `file` part + optional string fields, per the WhisperX DLC contract."""
    boundary = uuid.uuid4().hex
    body = b""
    for name, value in fields.items():
        body += (f"--{boundary}\r\n"
                 f'Content-Disposition: form-data; name="{name}"\r\n\r\n'
                 f"{value}\r\n").encode()
    body += (f"--{boundary}\r\n"
             f'Content-Disposition: form-data; name="file"; filename="audio.wav"\r\n'
             f"Content-Type: audio/wav\r\n\r\n").encode()
    body += open(audio_path, "rb").read() + b"\r\n"
    body += f"--{boundary}--\r\n".encode()
    return body, f"multipart/form-data; boundary={boundary}"

body, content_type = build_multipart("audio.wav", {
    "language": "en",
    "response_format": "verbose_json",
    "timestamp_granularities[]": "word",  # word-level timestamps
    "diarize": "true",  # speaker labels
})

resp = sm_runtime.invoke_endpoint(
    EndpointName=ENDPOINT_NAME, ContentType=content_type, Body=body,
)
transcription = json.loads(resp["Body"].read())
```

## 演练：异步端点

异步端点去掉 60 秒上限，是长音频的推荐路径。输入和输出通过 Amazon S3 中介，而你轮询结果。图 2 是一个序列图，端到端追踪完整的异步生命周期，从 S3 上传和 InvokeEndpointAsync 调用，到容器处理，到 S3 输出和失败路径。

图 2：异步端点经 S3 引用调用 InvokeEndpointAsync 的流程、单 worker 处理，以及经 S3 输出和失败路径的结果

端到端读这一序列：客户端把多部分体上传到 Amazon S3，并用对象的 `InputLocation` 调用 `InvokeEndpointAsync`。它立即收到一个 `OutputLocation` 和 `FailureLocation`，而非等待转录稿。Amazon SageMaker AI 从 Amazon S3 读取输入并转发到端口 `8080` 上的容器。在那里，同样的语音活动检测、批量转录、强制对齐和分离流水线运行，一容器一请求。成功时，容器把转录稿写到 S3 输出路径，或把一个错误文档写到失败路径。客户端轮询输出路径以取结果并检查失败路径，因此一个失败的作业会浮现一个错误而非无限循环。因为工作通过 Amazon S3 中介，这条路径不受 60 秒上限约束，适合长音频。

### 创建异步端点配置

与实时端点唯一的结构差别是端点配置：它加了一个带 S3 `OutputPath` 和 `S3FailurePath` 的 `AsyncInferenceConfig`。设 `MaxConcurrentInvocationsPerInstance=1` 以匹配容器的单 worker 上限，并保持同样的 `InferenceAmiVersion` 固定。`IMAGE_URI` 是与实时端点所用的同一个 WhisperX DLC。

```
# Same WhisperX DLC image as the real-time endpoint.
IMAGE_URI = f"763104351884.dkr.ecr.{REGION}.amazonaws.com/whisperx:3.8.6-cu128-amzn2023-sagemaker"

sm.create_model(
    ModelName=ASYNC_MODEL_NAME,
    PrimaryContainer={"Image": IMAGE_URI},  # WhisperX DLC
    ExecutionRoleArn=ROLE_ARN,
)

sm.create_endpoint_config(
    EndpointConfigName=ASYNC_ENDPOINT_CONFIG_NAME,
    ProductionVariants=[{
        "VariantName": "AllTraffic",
        "ModelName": ASYNC_MODEL_NAME,
        "InitialInstanceCount": 1,
        "InstanceType": "ml.g5.2xlarge",
        "InferenceAmiVersion": "al2-ami-sagemaker-inference-gpu-3-1",
        "ContainerStartupHealthCheckTimeoutInSeconds": 1200,
    }],
    AsyncInferenceConfig={
        "OutputConfig": {
            "S3OutputPath": f"s3://{BUCKET}/whisperx-async/output/",
            "S3FailurePath": f"s3://{BUCKET}/whisperx-async/failure/",
        },
        "ClientConfig": {"MaxConcurrentInvocationsPerInstance": 1},  # 1 request/container
    },
)

sm.create_endpoint(EndpointName=ASYNC_ENDPOINT_NAME, EndpointConfigName=ASYNC_ENDPOINT_CONFIG_NAME)
sm.get_waiter("endpoint_in_service").wait(EndpointName=ASYNC_ENDPOINT_NAME)
```

工作流的其余部分与实时演练相同。构建 `multipart/form-data` 请求（`build_multipart` 辅助函数和转录字段）不变。你用 `invoke_endpoint_async` 通过 S3 引用而非 `invoke_endpoint` 提交它，然后从 `OutputLocation` 读取转录稿并检查 `FailureLocation`。清理也一样。

## 清理

一个 GPU 端点在你删除它之前持续计费。完成时，删除两个端点的**端点**、**端点配置**和**模型**，并移除任何你不再需要的 S3 输入和输出产物。

```
# A GPU endpoint bills until deleted. Delete endpoint -> config -> model for each endpoint.
for name, cfg, model in [
    (ENDPOINT_NAME, ENDPOINT_CONFIG_NAME, MODEL_NAME),
    (ASYNC_ENDPOINT_NAME, ASYNC_ENDPOINT_CONFIG_NAME, ASYNC_MODEL_NAME),
]:
    sm.delete_endpoint(EndpointName=name)
    sm.delete_endpoint_config(EndpointConfigName=cfg)
    sm.delete_model(ModelName=model)
```

## 最佳实践与生产考量

- **固定 GPU AMI** – 在 GPU 变体上始终设 `InferenceAmiVersion=al2-ami-sagemaker-inference-gpu-3-1`。默认主机 AMI 带的驱动会让这个 CUDA 12.8 镜像启动失败。
- **按实例而非并发伸缩** – 推理被序列化为一个容器一请求。在异步端点上设 `MaxConcurrentInvocationsPerInstance=1`，并为吞吐添加实例或容器。
- **把异步端点缩放到零** – 对于突发批处理工作负载，空闲时把异步端点缩到零实例以削减成本，并用 [Amazon Simple Notification Service (Amazon SNS)](https://docs.aws.amazon.com/sns/latest/dg/welcome.html) 完成通知取代密集轮询。
- **为 GPU 定合适的大小，并用实例池保可用性** – 用 `ml.g4dn.xlarge`（T4）为成本，或 `ml.g5.2xlarge`（A10G）为余量。为避免容量不足错误，在一个 Amazon SageMaker AI 实例池中列出最多五种实例类型。它先配置最高优先级的类型，并在容量不可用时自动退回。
- **保护 S3 产物** – 在异步桶上开启 S3 Block Public Access、默认 SSE-S3 或 SSE-KMS 加密，以及 BucketOwnerEnforced 所有权。把 execution 角色限定到具体的桶和键。
- **负责任地处理可识别个人身份信息（PII）** – 通话和会议的转录稿可能含敏感数据，因此加密产物、限制访问，并用逐词时间戳在下游施加脱敏。
- **观测并重试** – 用 Amazon CloudWatch 监控、对失败设告警，并围绕前述冷启动行为重试。要更深的 GPU 和推理可见性，开启 [Amazon SageMaker AI 在 CloudWatch 上的详细指标与洞察仪表盘](https://aws.amazon.com/blogs/machine-learning/monitor-and-debug-generative-ai-inference-with-sagemaker-detailed-metrics-and-insights-dashboard-on-cloudwatch/)。
