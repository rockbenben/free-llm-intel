# Pixtral Large 现已在 Amazon Bedrock 上线

今天，我们宣布，[Mistral AI](https://mistral.ai) 的 Pixtral Large 基础模型（FM）现已在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 正式可用。借助此次上线，您现在可以访问 Mistral 的前沿级多模态模型，在 AWS 上构建、试验并负责任地扩展您的生成式 AI 创意。AWS 是首家以全托管、serverless 模型形式提供 Pixtral Large 的主要云服务商。

在本文中，我们将讨论 Pixtral Large 的特性及其可能的应用场景。

## Pixtral Large 概览

[Pixtral Large](https://aws.amazon.com/bedrock/mistral/) 是 Mistral AI 开发的一款先进多模态模型，拥有 1,240 亿参数。该模型将一个强大的 1,230 亿参数多模态解码器与一个专用的 10 亿参数视觉编码器相结合。它能无缝处理复杂的视觉与文本任务，同时保留其前身 [Mistral Large 2](https://mistral.ai/news/mistral-large-2407) 卓越的语言处理能力。

Pixtral Large 的一大特点是其高达 128,000 个 token 的宽敞上下文窗口，使其能够同时处理多张图像以及大量文本数据。这一能力使其在分析文档、精细图表、图形和自然图像时尤为有效，可满足广泛的实际应用需求。

以下是 Pixtral Large 的关键能力：

- **多语言文本分析 **– Pixtral Large 能够准确地从图像和文档中解读并提取多种语言的文字信息。这对于自动处理收据或发票等任务尤为有用，它可以执行计算和上下文相关的评估，从而简化费用跟踪或财务分析等流程。
- **图表与数据可视化解读 **– 该模型在理解复杂的可视化数据表示方面展现出非凡的能力。它可以毫不费力地识别图形化可视化中的趋势、异常和关键数据点。例如，Pixtral Large 非常擅长发现训练损失曲线或性能指标中的异常或有价值的趋势，从而提升数据驱动决策的准确性。
- **通用视觉分析与上下文理解 **– Pixtral Large 擅长分析通用视觉数据，包括截图和照片，能够提取细微的洞察，并有效地回应基于图像内容的查询。这一能力显著拓宽了其适用范围，使其能够支持各种场景——从在演示文稿中解释视觉上下文，到自动化内容审核和上下文图像检索。

其他模型细节包括：

- 以下区域支持跨区域推理：  `us-east-2` `us-west-2` `us-east-1` `eu-west-1` `eu-west-3` `eu-north-1` `eu-central-1`
- Model ID：`us` 或 `eu`，然后是 `mistral.pixtral-large-2502-v1:0`
- 上下文窗口：`128,000`

## 在 Amazon Bedrock 中开始使用 Pixtral Large

如果您是首次使用 Mistral AI 模型，可以在 [Amazon Bedrock 控制台](https://us-west-2.console.aws.amazon.com/bedrock/home?region=us-west-2#/modelaccess) 申请模型访问权限。有关更多信息，请参阅[访问 Amazon Bedrock 基础模型](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)。

要在 Amazon Bedrock 控制台上测试 Pixtral Large，请在导航窗格的 **Playgrounds** 下选择 **Text** 或 **Chat**。然后，选择 **Select model**，并将 **Mistral** 选为类别、将 **Pixtral Large** 选为模型。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/04/10/image1.jpg)

通过选择 **View API**，您还可以使用 [AWS Command Line Interface](https://aws.amazon.com/cli/)（AWS CLI）和 AWS SDK 中的代码示例来访问该模型。您可以使用诸如 `mistral.mistral-large-2407-v1:0` 这样的 Model ID，如下面的代码所示：

```
$ aws bedrock-runtime invoke-model \ 
--model-id mistral.pixtral-large-2502-v1:0 \
--body "{\"prompt\":\"<s>[INST] this is where you place your input text [/INST]\", \"max_tokens\":200, \"temperature\":0.5, \"top_p\":0.9, \"top_k\":50}" \ 
--cli-binary-format raw-in-base64-out \
--region eu-north-1 \ 
invoke-model-output.txt
```

## Pixtral Large 用例

在本节中，我们通过示例 prompt 展示 Pixtral Large 的应用用例。由于 Pixtral Large 基于 Mistral Large 2 构建，它包含原生 JSON 输出模式。此功能使开发者能够以结构化且易于阅读的格式接收模型的响应，并可将其无缝集成到各种应用和系统中。由于 JSON 是一种广泛使用的数据交换标准，此功能简化了处理模型输出的过程，使其对不同行业和用例的开发者更加易用和实用。有关使用 Converse API 生成 JSON 的更多信息，请参阅[使用 Amazon Bedrock Converse API 生成 JSON](https://community.aws/content/2hWA16FSt2bIzKs0Z1fgJBwu589/generating-json-with-the-amazon-bedrock-converse-api?lang=en)。

此外，Pixtral Large 支持 [Converse API](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html#:~:text=To%20use%20the%20Converse%20API,for%20the%20bedrock%3AInvokeModelWithResponseStream%20operation.) 和[工具使用](https://docs.aws.amazon.com/bedrock/latest/userguide/tool-use.html)。通过使用 Amazon Bedrock API，您可以授予模型访问工具的权限，以辅助生成对您所发送消息的响应。

### 从数据库实体关系图生成 SQL 代码

实体关系（entity-relationship，ER）图是数据库设计中用于描述实体及其属性之间关系的一种可视化表示。它是概念建模的关键工具，可帮助开发者和分析师理解并交流数据库内的数据结构。

本示例测试模型生成与 PostgreSQL 兼容的 `SQL CREATE TABLE` 语句以创建实体及其关系的能力。

我们使用以下 prompt：

```
prompt = """
You are a database designer. You have created an ER diagram. You need to generate PostgreSQL compatible SQL statements to create the tables"
"""
```

我们输入以下 ER 图。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/04/10/image2-2.jpg)

模型响应如下：

```
Sure! Below are the SQL statements to create the tables based on the provided 
ER diagram for a PostgreSQL database.

```sql
-- Create the Airport table
CREATE TABLE Airport (
    Airport_ID SERIAL PRIMARY KEY,
    AirportCity VARCHAR(255),
    AirportCountry VARCHAR(255)
);

-- Create the Calendar table
CREATE TABLE Calendar (
    Day_Date DATE PRIMARY KEY,
    Business_Day_YN BOOLEAN
);

-- Create the Flight_Details table
CREATE TABLE Flight_Details (
    Flight_ID SERIAL PRIMARY KEY,
    Source_Airport_ID INT REFERENCES Airport(Airport_ID),
    Destination_Airport_ID INT REFERENCES Airport(Airport_ID),
    Departure_Date_Time TIMESTAMP,
    Arrival_Date_Time TIMESTAMP,
    Airplane_Type VARCHAR(255)
);

-- Create the Travel_Class table
CREATE TABLE Travel_Class (
    Travel_Class_ID SERIAL PRIMARY KEY,
    Travel_Class_Name VARCHAR(255),
    Travel_Class_Capacity INT
);

-- Create the Seat_Details table
CREATE TABLE Seat_Details (
    Seat_ID SERIAL PRIMARY KEY,
    Travel_Class_ID INT REFERENCES Travel_Class(Travel_Class_ID),
    Flight_ID INT REFERENCES Flight_Details(Flight_ID)
);

-- Create the Flight_Cost table
CREATE TABLE Flight_Cost (
    Seat_ID INT REFERENCES Seat_Details(Seat_ID),
    Valid_From_Date DATE,
    Cost DECIMAL(10, 2),
    Valid_To_Date DATE,
    PRIMARY KEY (Seat_ID, Valid_From_Date)
);

-- Create the Flight_Service table
CREATE TABLE Flight_Service (
    Service_ID SERIAL PRIMARY KEY,
    Service_Name VARCHAR(255)
);

-- Create the Service_Offering table
CREATE TABLE Service_Offering (
    Travel_Class_ID INT REFERENCES Travel_Class(Travel_Class_ID),
    Service_ID INT REFERENCES Flight_Service(Service_ID),
    Offered_YN BOOLEAN,
    From_Date DATE,
    To_Date DATE,
    PRIMARY KEY (Travel_Class_ID, Service_ID)
);

-- Create the Passenger table
CREATE TABLE Passenger (
    Passenger_ID SERIAL PRIMARY KEY,
    P_FirstName VARCHAR(255),
    P_LastName VARCHAR(255),
    P_Email VARCHAR(255),
    P_PhoneNumber VARCHAR(255),
    P_Address VARCHAR(255),
    P_City VARCHAR(255),
    P_State VARCHAR(255),
    P_Zipcode VARCHAR(255),
    P_Country VARCHAR(255)
);

-- Create the Reservation table
CREATE TABLE Reservation (
    Reservation_ID SERIAL PRIMARY KEY,
    Passenger_ID INT REFERENCES Passenger(Passenger_ID),
    Seat_ID INT REFERENCES Seat_Details(Seat_ID),
    Date_Of_Reservation DATE
);

-- Create the Payment_Status table
CREATE TABLE Payment_Status (
    Payment_ID SERIAL PRIMARY KEY,
    Payment_Status_YN BOOLEAN,
    Payment_Due_Date DATE,
    Payment_Amount DECIMAL(10, 2),
    Reservation_ID INT REFERENCES Reservation(Reservation_ID)
);
```

These SQL statements will create the tables as per the ER diagram you provided. Make sure to run these statements in the order they are listed to ensure that foreign key constraints are satisfied.
