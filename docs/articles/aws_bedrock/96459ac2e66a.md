## [人工智能](https://aws.amazon.com/blogs/machine-learning/)

# 使用 Amazon Bedrock AgentCore 构建 WhatsApp AI 代理

在拉丁美洲、印度和东南亚，WhatsApp 是使用最广泛的消息应用程序之一。这使得它成为构建人工智能代理的明显场所。对于许多最终用户来说，这是他们期望与企业互动的方式。然而，即使您的代理已经在 [Amazon Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html) 上运行，这也是一个真正难以构建的表面。

代理很少是最困难的部分。整合是。入站消息以深度嵌套、类型相关的有效负载形式到达，必须先对其进行身份验证和规范化，然后代理才能读取它们。语音笔记、图像和文档等媒体都需要自己的处理管道。除了消息处理之外，您还需要在会话中保留的对话内存、持久的提醒时间表以及外部系统触发出站消息的经过身份验证的路径。在最终用户发送最后一条消息 24 小时后发送的任何内容都必须使用预先批准的元消息模板。

连接起来意味着配置 10 多个 AWS 服务，并学习一组 WhatsApp 系统行为，而大多数团队只能通过点击它们才能发现这些行为。客户看不到所有这些，但所有这些都必须起作用。大多数团队要么从头开始构建它，要么将集成交给第三方服务。

[SMART（社交消息代理运行时工具包）](https://github.com/awslabs/social-messaging-agent-runtime-toolkit) 是第三个选项：开源 Python SDK 和 Terraform 堆栈，为您提供完整的通道层。您提供一个在 Amazon Bedrock AgentCore 运行时运行的代理，SMART 会处理其余的事情。一条命令即可将整个基础设施部署到您的 AWS 账户。

团队已经使用 Amazon Bedrock AgentCore 在 SMART 上运行。 Webmotors 最初的合作期限为两个月，后来将交付时间压缩为六周，并在全面推出之前将其内部团队转移到受控生产中。

无论您是从头开始还是迁移现有代理，您都拥有代理的逻辑。您让 SMART 处理该通道。

## 代理层

Amazon Bedrock AgentCore 是一个使用任何框架或模型大规模构建、连接和优化代理的平台。 SMART 建立在其两个主要功能之上：

- *AgentCore 运行时* 托管和扩展您的代理，无需您管理基础设施。
- *AgentCore 内存*跨会话和部署保留对话历史记录，自动限定到每个电话号码。

因为 AgentCore 与框架无关，所以 SMART 也是如此。 [Strands Agents](https://strandsagents.com/) 自动连接内存。 LangGraph、Pydantic-AI 或其他可以让您控制对话循环的框架也可以集成。无论框架如何，SDK 都会公开相同的内存和会话挂钩。您可以完全控制使您的产品脱颖而出的元素：框架、模型、提示和业务逻辑。

SMART 和您的代理人之间的合同故意很小。您的代理接收入站消息并返回文本，还可以选择包含丰富的消息附件。其他一切，会话连接、内存绑定、交付调度，都为您处理。

以下示例是 SMART 项目的完整 `agent.py`。脚手架命令 (`socialagent init`) 创建项目结构和围绕它的配置。该文件是您的代理逻辑所在的位置。
```
# --- AgentCore: runtime entry point ---
from bedrock_agentcore.runtime import BedrockAgentCoreApp
from strands import Agent
from strands.models import BedrockModel
# --- SMART: channel helpers ---
from socialagent_runtime import create_session_manager, socialagent_notify_context, SocialAgentResponse

app = BedrockAgentCoreApp()                                # AgentCore Runtime
model = BedrockModel(model_id="us.anthropic.claude-haiku-5-5")          #Or any Bedrock model

@app.entrypoint
async def invoke(payload: dict, context: object = None) -> SocialAgentResponse:
    agent = Agent(
        model=model,
        system_prompt="You are a helpful WhatsApp assistant. Keep replies short.",
        session_manager=create_session_manager(payload),   # AgentCore Memory, pre-wired
    )
    with socialagent_notify_context() as outbound:         # SMART: collects outbound messages
        result = agent(payload["prompt"], invocation_state={"phone": payload["phone"]})
    return SocialAgentResponse(result=str(result), outbound_messages=outbound)  # SMART: response envelope

app.run()
```
The `create_session_manager()` function binds the agent to AgentCore memory scoped to that phone number, so history survives across sessions and deployments for the memory retention period (7 days by default).

`socialagent_notify_context()` 包装器是另一个值得保留的模式。工具有时需要在代理仍在工作时发送某些内容，例如按钮列表或进度更新。立即发送它会破坏对话历史记录，并且用户的下一条消息会失败。相反，包装器会收集这些消息，并在回合结束后按顺序发出。您的工具正常发送消息并且不处理时间。

## 架构

下图显示了入站消息如何从 WhatsApp 传输到您的代理并返回，以及共享基础设施所在的位置。

图 1：入站 WhatsApp 消息如何通过 SMART 通道层流向代理并返回

SMART 核心堆栈分为不同的层：消息处理、代理层和服务层。 AWS End User Messaging Social 接收入站 WhatsApp 消息并将其路由到处理层。 AWS Lambda 函数处理通道逻辑，而 Amazon Bedrock AgentCore 为代理本身提供运行时、内存和可观察性。 Amazon DynamoDB（可选，针对每个用户状态）、AWS Secrets Manager、Amazon CloudWatch 和 Amazon Simple Storage Service (Amazon S3) 等支持服务提供整个堆栈的状态管理、凭证、监控和存储。

入站事件通过 Amazon Simple Notification Service (Amazon SNS) 到达。对于每个事件，Webhook Lambda 函数都会验证 SNS 消息签名、规范负载并限制每个用户的速率（默认情况下每分钟 20 条消息，启用 DynamoDB 状态表）。然后，它会触发已读回执和输入指示器，因此在模型完成之前，对话会感觉很活跃。语音笔记通过 Amazon Transcribe。如果您想要自定义处理，其他媒体将成为描述符或转到您注册的挂钩。当代理受到限制或失败时，用户会收到一条可自定义的可读消息，而不是静默。

基于 SMART 构建的代理直接与最终用户交互，因此生产部署应包括适当的保护措施。 Terraform 堆栈默认创建并配置 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 资源。通过环境配置中的单个 `guardrail` 变量，您可以使用堆栈的默认护栏、自带护栏或完全退出。您应用的控制措施取决于您。 SMART 确保接线已就位。

消息准备好后，Webhook 函数将其传递给 AgentCore 运行时。 AgentCore 内存维护跨会话的对话上下文，而 AgentCore Observability（Amazon Bedrock AgentCore 的一项功能）可跟踪调试和审核的每个步骤。

Webhook 功能会发送您的工具在轮次期间排队的回复和消息。通知功能处理轮次之外的发送，例如主动或预定消息。外部系统通过发布到受 API 密钥和 Lambda 授权者保护的 Amazon API Gateway 终端节点来触发您的事件处理程序。该事件将发布到 Amazon SNS，并且事件 Lambda 运行您的处理程序。 Amazon EventBridge Scheduler 处理基于时间的外展活动，例如提醒和定期签到。借助通过 AWS End User Messaging 管理的消息模板，您可以在 24 小时 WhatsApp 会话窗口之外发送结构化通知。

单个 `socialagent deploy` 提供以下资源（它在后台运行 `terraform apply`）。

- Amazon Bedrock AgentCore 运行时和 AgentCore 内存。
- Python 3.12 上的 Webhook、通知、事件和调度程序 Lambda 函数，每个函数都具有 AWS X-Ray 跟踪和死信队列。
- Amazon SNS 摄取主题和事件 API。
- Amazon EventBridge 调度程序。
- 用于媒体和审计跟踪的 Amazon S3 存储桶。
- Amazon CloudWatch 仪表板和警报。

代理容器映像和 Lambda 层在应用期间在 AWS CodeBuild 中构建。本地不需要 Docker。

## 你需要什么

在部署之前，请确认您具备以下条件。

- AWS 最终用户消息社交，已链接 WhatsApp 企业账户 (WABA) 并注册了电话号码。该帐户是元向企业发出的身份信息。有关分步指南，请参阅 [AWS End User Messaging Social 入门](https://docs.aws.amazon.com/social-messaging/latest/userguide/getting-started.html)，该指南将引导您完成链接 WABA 和注册电话号码的过程。
- AWS 账户，在您的 AWS 区域中具有可用的 AgentCore 运行时和 AgentCore 内存，并且启用了模型访问。本演练默认使用 Amazon Bedrock 上的 Claude Haiku 5.5。您可以通过 Bedrock 访问更多基础模型 (FM)。请参阅[按地区支持的型号](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。
- 本地 Python 3.11 或更高版本。
- Terraform 1.7 或更高版本、uv 和 AWS 命令​​行界面 (AWS CLI)。该存储库为部署者角色提供了一个起点 AWS Identity and Access Management (IAM) 策略。请参阅基础设施自述文件以获取完整的操作列表。

**注意：** 这是示例代码，用于非生产用途。在部署之前，您应与安全和法律团队合作，以满足组织的安全、监管和合规性要求。

## 发货

首先克隆存储库并搭建项目。
```
git clone https://github.com/awslabs/social-messaging-agent-runtime-toolkit smart && cd smart && make install
uv run socialagent init my-bot --blueprint personal-assistant
```
`--blueprint` 标志选择项目蓝图。提供了三个蓝图，如果不传递参数，则 `minimal` 是默认值：

- `minimal`：一个简单的回显代理，没有工具、技能或消息模板。从这里开始从头开始构建。
- `personal-assistant`：一款基于 Strands 的通用助手，具有对话记忆、每个用户状态、日程安排、技能和丰富/语音/图像媒体工具。从这里开始，寻找对话式、全能的代理。
- `appointment-scheduler`：预订代理，引导用户浏览项目目录和时段、确认预约、将其存储为每个用户状态并发送提醒。从这里开始安排和预订流程。

您将获得一个项目，其中包含 `agent.py`、`socialagent.dev.yaml`（项目的部署配置）、Webhook 的处理程序存根、通知、事件和调度程序路径以及 `socialagent_runtime/` 的供应副本。个人助理和约会安排程序蓝图还为您的消息模板带来了工具、技能和 `templates.yaml`。 `minimal` 不提供这些内容，因此您可以根据需要添加它们。

接下来，在根本没有基础设施的情况下进行本地迭代。
```
cd projects/my-bot
uv run socialagent dev --entrypoint agent.py
```
`socialagent dev` 命令在终端读取-评估-打印循环 (REPL) 中运行真实代理循环和真实工具，并存根 AWS 通道 I/O。内存成为本地文件支持的会话，状态成为在开发会话之间共享的本地 JSON 文件。通知打印到终端，包括按钮和列表行。一次性计划立即运行。重复出现的会被注册但不会触发。工具调用以内联方式出现。回复以一条消息形式到达，就像在 WhatsApp 上一样。 `/event` 和 `/schedule` 命令执行处理程序路径。不涉及部署，因此您可以在保存更改后立即测试更改。

有两个注意事项适用。模型调用是真实的，因此 `minimal` 之外的蓝图需要 AWS 凭证和 Amazon Bedrock 访问权限。 REPL 也不会模拟 IAM 或 Meta 的模板审核。在您考虑完成某些操作之前，强烈建议通过已部署的堆栈进行测试。

您可以将功能添加为配方。每个配方都是一个简单的 Python 函数加上一个 Markdown 技能，可以指导代理何时使用它。
```
uv run socialagent recipe add voice-reply    # or rich-messages, generate-image
```
将配方连接到代理层是开发人员的责任，这就是在更改代理框架时保持配方可移植性的原因。

当本地行为正确时，部署堆栈。
```
uv run socialagent bootstrap   # once per account and stage
# set whatsapp.phone_number_id in socialagent.dev.yaml, then:
uv run socialagent deploy
```
Terraform 无法为您完成一步。 AWS End User Messaging Social 需要知道在哪里传送入站消息。将您的 WhatsApp Business 账户指向堆栈创建的 Amazon SNS 主题。该设置存在于企业帐户中，而不是堆栈中。使用管理控制台的绑定操作或使用 CLI 中的 `aws socialmessaging put-whatsapp-business-account-event-destinations` 将 WABA 的事件目标指向堆栈的 SNS 主题。在链接之前，入站消息将无处可去，也不会出现任何错误。

当项目包含 `templates.yaml` 时，部署步骤还会将消息模板与 Meta 同步。如果您需要独立同步模板，请运行 `uv run socialagent templates sync`，它会从 `socialagent.dev.yaml` 读取电话号码 ID 和前缀，并从 `templates.yaml` 读取模板定义。被拒绝的模板将使部署失败，因此请在重试之前修正措辞。

元按用途对模板进行排序，交易型模板比促销型模板具有更宽松的发送规则。保持措辞简单。表情符号和营销语言是模板被重新分类为促销的常见原因。运行 `templates sync --force` 会重新注册每个模板，并通过元审核将批准的模板发回。普通同步会跳过它们。除非您需要更改其内容，否则请保留已批准的模板。

现在您可以向您的 WhatsApp 号码发送消息了。

## 操作一下

运送一个机器人是一个项目。运营它们的舰队是没有人预算的部分，因此您还可以获得一个带有自己的 Terraform 根的可选管理控制台。部署一次。每个设置 `admin_registry_bucket` 的 SMART 堆栈都会在部署时将自身注册到共享 Amazon S3 注册表，管理控制台会从那里发现这些堆栈。

该控制台让您可以一目了然地了解车队的健康状况，以及每个机器人的深度。从单个堆栈视图中，您可以执行以下操作。

- 阅读真实对话并手工回复。
- 检查并取消 Amazon EventBridge 计划，并浏览每个用户的状态。
- 重新启动单个 Lambda 函数或运行时。
- 查看部署历史记录、最近的错误和 Amazon CloudWatch 日志。
- 触发测试事件。
- 使用 WhatsApp 风格的渲染管理消息模板，并在 Meta 重新分类时看到警告。

控制台还拥有前面描述的电话号码绑定，因此将号码重新绑定到不同的堆栈是一个 UI 操作。

登录通过 Amazon Cognito 运行，需要多重身份验证 (MFA)。然后，在每个 API 路由上强制执行基于角色的权限。控制台本身由 Amazon CloudFront 通过私有 Amazon S3 存储桶提供服务。

该控制台在 AWS 服务上端到端运行。每个对话都在两个提供商内进行：Meta 和 AWS。模型调用可以通过 Amazon Bedrock 跨区域推理在其他 AWS 区域进行处理。有关推理路由、媒体处理和服务选择退出选项的详细信息，请参阅存储库中的 `docs/data-flows.md`。

## 清理

为避免持续收费，请按以下顺序拆除堆栈。
```
uv run socialagent destroy
make ui-destroy   # if you deployed the console
```
Terraform 不会删除三件事。媒体和审计 S3 存储桶在保存对象时会阻止销毁，除非设置了 `enable_force_destroy`。使用 Meta 注册的模板仍然存在。您的电话号码注册是帐户级别的并且保持不变。
