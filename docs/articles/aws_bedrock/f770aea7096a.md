# 使用 Skyflow 和 Amazon Bedrock AgentCore Gateway 保护代理工具调用

在这篇文章中，我们将展示 [Skyflow](https://www.skyflow.com/) 和 Amazon Bedrock [AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 如何将敏感数据保留在您的 AI 代理调用的工具之外，以及这些工具提供的模型上下文之外。我们将 Skyflow Detect 添加到 Amazon Bedrock AgentCore Gateway 作为请求和响应 [拦截器](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-interceptors.html)。 Skyflow 拦截器在数据到达工具之前对其进行去标识化，在代理读取结果之前将其恢复，并在代理打开文档之前用干净的副本替换文档。您的代理和工具不会改变。

Skyflow 可在 AWS Marketplace 中使用，拦截器在 GitHub 上开源。

## 代理通过工具行动，工具移动数据

代理已从回答问题转向采取行动，他们通过工具采取行动：模型上下文协议 (MCP) 服务器、SaaS API、文档存储和 Web 搜索。每个代理工具调用都是一个数据流。大多数企业控制涵盖模型的进出内容。很少有报道涉及代理向其工具发送的内容或这些工具发回的内容。

这种差距表现在三个方面：

- **敏感数据通过工具参数留下。** 模型从其上下文中的所有内容写入参数，包括工具不需要的详细信息。向代理询问客户的情况，客户的姓名、帐号或电子邮件会直接进入第三方服务器的查询中。该服务器位于您的 AWS 账户和合规范围之外。
- **敏感数据返回到工具结果中。** 抓取的网页、CRM 记录和案例注释会出现在模型的上下文、内存、跟踪和日志中。即使任务从来不需要它们，这种情况也会发生。
- **文档绕过文本检查。** Amazon Simple Storage Service (Amazon S3)、Box 和 Google Drive 等文档工具返回签名 URL，而不是文本。检查字符串的过滤器会看到链接并允许其通过，然后代理打开原始文件。

修补每个代理不会跨团队和框架扩展，并且无法访问第三方工具。控件需要位于每个工具调用经过的地方，因此授权、内容安全和数据保护以相同的方式应用于每个代理和工具。

AgentCore 网关就是那个地方。它面向代理使用的每个工具，无论代理运行在什么框架或模型上。它的作用不仅仅是路由流量。借助 AgentCore Gateway 拦截器，您可以在每次通过它的调用时以 AWS Lambda 函数的形式运行您自己的代码。请求拦截器在每个调用到达工具之前查看每个调用，而响应拦截器在每个结果到达代理之前查看每个结果。任何一方都可以检查有效负载、重写它或阻止调用。这使得网关成为与策略和防护栏一起添加数据保护的自然场所。这个单一的控件，附加一次，涵盖网关后面的每个代理和每个工具，无需对代理或工具代码进行任何更改。

### 示例：欧洲一家大型银行的争议解决代理人

考虑一家拥有零售和企业银行业务以及严格的数据驻留义务的大型欧洲银行。其运营团队正在聘请代理人来调查卡纠纷。

分析师要求代理人调查有争议的交易。代理在网络上搜索商家，然后从 Amazon S3 中提取争议案例记录进行总结。如果没有保护，会发生三种情况：

- 该模型根据上下文中的所有内容构建搜索查询。搜索提供商收到“Mateo Jackson 争议 AnyCompany Electronics London”。这是客户的姓名，发送给第三方，以便仅需要商家进行搜索。
- 抓取的商家页面将不相关的个​​人数据带入模型的上下文中。
- 代理阅读原始案例说明，其中包含客户的全名、电子邮件、电话号码和银行卡详细信息。

使用网关上的 Skyflow 拦截器，相同的工作流程会以不同的方式进行：

- 搜索提供商收到“[NAME_AJbrIud] 争议 AnyCompany Electronics London”，其中 [NAME_AJbrIud] 是可逆保管库令牌。商家返回的结果是一样的，提供商永远不知道客户是谁，分析师仍然在代理的答案中看到真实姓名。
- 网页内容到达的模型已经去识别化。
- 代理只会收到案例说明的去识别化副本的链接。

## 解决方案概述

Skyflow 拦截器是附加到两个 AgentCore 网关拦截点的单个 AWS Lambda 函数：

- `REQUEST` 在网关调用工具之前运行。
- `RESPONSE` 在工具应答之后、代理看到结果之前运行。

在每个点上，它都会调用 Skyflow Detect 来查找敏感实体，例如姓名、电子邮件地址、电话号码、身份证件、卡号、出生日期和位置。它用令牌替换它们，或恢复原始内容。 Skyflow Vault 存储原始值，以便授权系统可以反转令牌。

Skyflow 网关配置决定对于每个工具，应用三种保护模式中的哪一种：屏蔽工具、屏蔽模型和屏蔽文档。

| **模式** | **发生了什么** | **谁看到真实数据** | **它是如何工作的** | **典型用途** |
| --- | --- | --- | --- | --- |
| **屏蔽该工具** |敏感值在退出时从参数中删除，并在返回时在结果中恢复 |代理和用户，而不是工具 |使用可逆保管库令牌，因此工具回显的值会在代理读取它们之前恢复 |不需要客户身份即可完成工作的网络搜索、丰富和第三方 API |
| **屏蔽模型** |提示、历史记录、文件和工具结果在模型读取之前会被取消识别。回归途中重新认定答案 |代理和用户，而不是模型|模型调用通过网关的推理端点。在返回的过程中，仅恢复为该调用铸造的代币 |客户对话、抓取的网页内容、跨区域或第三方模型 |
| **屏蔽文档** |文件的签名 URL 被交换为指向去识别化副本的 URL |代理方无人| Skyflow Detect v2（预览版）获取文件、清理文件并将副本存储在批准的区域中。文件永远不会通过 Lambda，因此负载限制不会限制文件大小 | Amazon S3、Box、Google Drive 中的案例说明、声明、合同 |

生产中的四个属性很重要：

- **代理或工具没有变化。** 代理像以前一样使用其 AWS Identity and Access Management (AWS IAM) 角色发现网关并签署请求。为了屏蔽模型，代理将其模型客户端指向网关的推理端点。否则拦截器对他们来说是不可见的。
- **无需重新部署的配置。** 该策略设置每个服务器和每个工具的方向、实体类型和令牌类型（可逆保管库令牌或单向令牌）。它位于 AWS Systems Manager Parameter Store 中，更改无需重新部署即可生效。
- **失败关闭。** 如果无法完成去识别化，则呼叫将被保留而不是以明文形式发送。拦截器仅从允许列表中的位置获取文件，并阻止它无法检查的流量，而不是静默地传递它。
- **基于 AWS 构建的操作。** Skyflow API 密钥位于 AWS Secrets Manager 中。每个决策都会记录到 Amazon CloudWatch 中，并包含警报指标，并且拦截器从不记录凭证或原始值。

## 它如何与 AgentCore 的其余部分配合

该拦截器补充了 AgentCore 和 Amazon Bedrock 已提供的控件：

- **Amazon Bedrock AgentCore 中的策略**使用 Cedar 和 Dogwood 授权代理可以执行的操作。它不仅仅是决定主体是否可以调用工具。它可以根据代理轨迹中的早期操作做出决策，控制对代理和模型的访问，阻止将特定参数发送到特定工具，并使用 Amazon Bedrock Guardrails 检查通过网关的数据。 Skyflow 与 Policy 一起工作。当策略允许调用时，Skyflow 会将其中的敏感值交换为可逆令牌，因此调用可以在不向工具或模型暴露真实数据的情况下进行。策略决定代理可以做什么，Skyflow 控制敏感数据在执行时的处理方式。
- **Amazon Bedrock Guardrails** 处理模型交互的内容安全和敏感信息编辑。 Skyflow 在同一网关中添加了保险库支持的标记化和文档去标识化。将它们一起使用可在每个模型和工具调用中提供分层保护。
- **AgentCore Identity（Amazon Bedrock AgentCore 的一项功能）和 AWS IAM** 保持原样。拦截器不添加代理程序管理的凭据。
- **AgentCore 可观察性，Amazon Bedrock AgentCore 的一项功能，以及 Amazon CloudWatch** 记录拦截器决策以及网关跟踪。

## 部署解决方案

Skyflow 拦截器是在 GitHub 上的 [agentcore-skyflow](https://github.com/SkyflowFoundry/agentcore-skyflow) 存储库中根据 MIT 许可证开源的。 Skyflow 可在 [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-zysz3tjic76qg) 中使用。要将拦截器添加到您已经运行的网关：

- 在 AWS Marketplace 中订阅 Skyflow，创建保管库并将其 API 密钥存储在 AWS Secrets Manager 中。
- 使用 AWS 云开发工具包 (AWS CDK) 从存储库部署拦截器堆栈。它创建 Lambda 函数、其策略参数、用于模型调用记录的 DynamoDB 表以及 Amazon CloudWatch 指标和警报。
- 将拦截器连接到网关的两个拦截点。存储库中的脚本执行此操作并授予网关角色仅调用该函数的权限。如果您使用 AWS CloudFormation 或 AWS CDK 管理网关，请在其中声明拦截器，以便以后的堆栈更新保留它。
- 要屏蔽模型，请将推理目标添加到网关，并将代理的模型客户端指向网关的推理端点。

该存储库还包含本文中的完整参考部署，包括代理、网关及其目标，您可以使用 AgentCore CLI（Amazon Bedrock AgentCore 的一项功能）进行部署。

有五种方式：

- **现有网关。** 将拦截器附加到您已运行的网关。代理和工具保持原样。
- **新代理。** 从第一天起就将工具置于 AgentCore Gateway 后面。
- **AWS 外部的 MCP 服务器。** 将它们作为网关 MCP 服务器目标，以便它们的流量通过拦截器。
- **文档存储。** 通过将返回签名 URL 的位置添加到策略的允许列表中来涵盖返回签名 URL 的工具。
- **模型调用。** 添加推理目标并通过网关发送代理的模型调用。

Skyflow 提供多种保管库部署模型和区域选择来满足驻留要求。请参阅[Skyflow 部署模型](https://docs.skyflow.com/docs/fundamentals/product-overview)。

## 注意事项

- **格式。** 文本和 Office 格式（TXT、JSON、CSV、XML、JSONL、DOCX、XLSX 和 PPTX）保留可逆的保管库令牌。 PDF 和图像完全去标识化，但会接收单向令牌，因此无法从这些文件恢复原始值。
- **可用性。** 字符串去标识和重标识普遍可用。通过签名 URL 进行文档去标识化使用 Skyflow Detect v2，该版本处于预览状态。 AgentCore 网关的可用性因 AWS 区域而异。在部署之前，请检查 Amazon Bedrock AgentCore 文档中的[支持的 AWS 区域](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html)。
- **文档大小和延迟。** 文档去标识化受到设计的限制。拦截器在提交之前检查文件大小，因此超出配置限制的文件会立即被拒绝，而不是超时。限制内的文件在 AgentCore Gateway 允许的连接窗口内完成。去识别化时间随文档大小而变化，因此请设置大小限制以匹配您的文档。 Skyflow Detect v2 处于预览状态。在扩大部署之前，在试点期间根据您自己的工作负载和区域验证延迟。

## 结论

代理的可信度取决于他们移动的数据。借助 AgentCore Gateway 和 Skyflow 拦截器，您可以在每个工具调用经过的一处实施隐私控制。它可以双向工作，涵盖文档和文本，并且无需更改代理代码。

### 从哪里开始

- 选择一种涉及客户数据并调用您帐户之外的至少一种工具的代理工作流程。
- 列出永远不能离开的实体类型，以及允许查看它们的工具。
- 从 [GitHub 存储库](https://github.com/SkyflowFoundry/agentcore-skyflow) 部署拦截器并将其附加到该工作流的网关。
- 从屏蔽工具开始。然后为您的文档存储添加屏蔽文档，并在代理的模型调用通过网关后屏蔽模型。
- 在扩大部署之前，观察拦截器的 CloudWatch 指标一周。
- 如果您还有其他疑问，请参阅[Skyflow SDK 文档](https://docs.skyflow.com/docs/sdks/overview)。
