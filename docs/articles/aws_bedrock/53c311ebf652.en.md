Fixed the Anthropic Messages API Python sample on the

Overview

page, which previously used

anthropic.Anthropic()

with no base URL and failed with a validation exception. Every Anthropic Messages API Python sample now uses the plain

Anthropic

client from the Anthropic SDK, targets the

bedrock-runtime

endpoint's

/anthropic

route directly with

base_url="https://bedrock-runtime.{region}.amazonaws.com/anthropic"

, and authenticates with a short-term Amazon Bedrock bearer token generated by

aws-bedrock-token-generator

's

provide_token()

. Updated the Sample Code section of every Anthropic model card that supports

bedrock-runtime

(Claude Opus 5, Opus 4.8, Opus 4.7, Sonnet 5, Haiku 4.5, and Fable 5) to use this pattern with the model's Global inference ID, and updated the corresponding

pip install

line to

pip install -U anthropic aws-bedrock-token-generator

. Updated the same sample on the

Quickstart

page, the

Messages API

topic, and the

Tool use

reference topic. Reordered the code sample tabs on the Messages API topic to lead with

bedrock-runtime

variants (Anthropic SDK, boto3, AWS CLI, curl) and moved the

bedrock-mantle

curl tab to the end. Repointed the

OPENAI_BASE_URL

environment variable on 49 non-Anthropic model cards (OpenAI, Mistral AI, DeepSeek, Google, Meta, Qwen, MiniMax, NVIDIA, Moonshot AI, Z.AI, Writer, xAI) from the

bedrock-mantle

/v1

route to the

bedrock-runtime

/openai/v1

route (

https://bedrock-runtime.{region}.amazonaws.com/openai/v1

) so the Responses API and Chat Completions API samples in the Sample Code section run against

bedrock-runtime

by default. The

bedrock-mantle

endpoint continues to be fully supported and pages that document mantle-only features (Web Search, Projects, Workspaces, Chat Completions on mantle, the mantle Responses API page) still show

bedrock-mantle

URLs.
