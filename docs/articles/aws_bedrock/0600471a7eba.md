# 从澳大利亚通过全球跨 Region 推理访问 Amazon Bedrock 上的 OpenAI 模型

使用 OpenAI 模型的澳大利亚团队现在可以通过 Amazon Bedrock 访问最新的 OpenAI 模型。Amazon Bedrock 在澳大利亚的 Asia Pacific（Sydney）和 Asia Pacific（Melbourne）AWS Region 提供带[全球跨 Region 推理](https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html)的 OpenAI [GPT-5.6 Sol](https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html)、[Terra](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-openai-gpt-56-terra.html) 和 [Luna](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-openai-gpt-56-luna.html)。你的应用调用 Asia Pacific（Sydney）或 Asia Pacific（Melbourne）的 Amazon Bedrock Runtime endpoint，Amazon Bedrock 随后将请求路由到受支持的商业 AWS Region 进行处理。这样既能访问更大的容量池，又无需应用管理目标 Region 的路由。GPT-5.6 Sol 适合高要求的推理、编码和 agentic 工作负载。Terra 在日常生产使用中平衡性能与成本。Luna 为高吞吐量和延迟敏感的应用提供快速、经济的推理。这三个模型都接受文本和图像输入，生成文本，并支持高达 100 万 token 的上下文窗口。借助 Amazon Bedrock Runtime endpoint，你可以从 Asia Pacific（Sydney）和 Asia Pacific（Melbourne）使用 Responses API、Chat Completions API 和 Converse API 调用这些模型。

本文将介绍如何使用 prompt caching 优化推理成本、如何使用基于 OpenID Connect（OIDC）的认证来设置 Codex，以及如何使用 Amazon CloudWatch 和 Coding Agent Insights 监控用量。

## GPT-5.6 全球推理配置

下表列出本文涉及的三个全球配置 ID 和澳大利亚源 Region。

| **全球推理配置** | **源 Region** | **目标 Region** |
| --- | --- | --- |
| global.openai.gpt-5.6-sol global.openai.gpt-5.6-terra global.openai.gpt-5.6-luna | Asia Pacific (Sydney) ap-southeast-2 Asia Pacific (Melbourne) ap-southeast-4 | 路由到受支持的商业 AWS Region |

配置归属和模型可用性可能会变化。部署前请查看[跨 Region 推理支持情况](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference-support.html)。

## 开始使用

在进入本节之前，你可以按照 [GPT-5.6](https://aws.amazon.com/blogs/machine-learning/introducing-cross-region-inference-for-openai-gpt-5-6-models-on-amazon-bedrock/) 博文设置以下前置条件：

- 一个已启用 Asia Pacific（Sydney）或 Asia Pacific（Melbourne）作为源 Region 的 AWS 账户。
- 如果你的组织使用服务控制策略（SCP），请确认 SCP 允许在所选源 Region 中使用 GPT-5.6 全球推理配置。
- 一个具备调用 GPT-5.6 推理配置所需权限的 AWS Identity and Access Management（IAM）角色或用户。
- Python 3.9 或更高版本，并已安装 `openai`、`boto3` 和 `aws-bedrock-token-generator` 包。

下一节将介绍如何分别使用 AWS Command Line Interface（AWS CLI）和 Amazon Bedrock 控制台验证当前生效的全球推理配置。

**使用 AWS CLI。** 以下命令列出当前生效的 GPT-5.6 配置，并从 Sydney Region 检查 Terra 配置。你也可以通过更改推理配置 ID，将这些命令用于 Sol 或 Luna。要从 Melbourne Region 执行同样的检查，请把 `ap-southeast-2` 替换为 `ap-southeast-4`。

```
aws bedrock list-inference-profiles \
--region ap-southeast-2 \
--type-equals SYSTEM_DEFINED \
--query "inferenceProfileSummaries[?contains(inferenceProfileId, 'openai.gpt-5.6')].[inferenceProfileId,status]" \
--output table

aws bedrock get-inference-profile \
--region ap-southeast-2 \
--inference-profile-identifier global.openai.gpt-5.6-terra
```

**使用 Amazon Bedrock 控制台。** 打开 Amazon Bedrock 控制台，选择 Sydney 或 Melbourne 作为 Region，在 Infer 下选择 Inference profiles，并筛选 Global OpenAI GPT-5.6 Terra。以下截图显示来自 Sydney 源 Region 的生效配置。

### 通过 Amazon Bedrock Runtime 调用 GPT-5.6

GPT-5.6 在 Amazon Bedrock Runtime endpoint 上支持三种访问路径：OpenAI Responses API、OpenAI Chat Completions API 和 Amazon Bedrock Converse API。OpenAI 兼容的 API 通过该 endpoint 的 `/openai/v1` 路径调用，而非通过 AWS SDK。该 endpoint 接受 AWS Signature Version 4（SigV4）或 Amazon Bedrock 模型推理 API key。以下示例使用 [AWS Bedrock Token Generator for Python](https://github.com/aws/aws-bedrock-token-generator-python) 从当前 AWS 凭证创建短期 Amazon Bedrock 模型推理 API key，因此应用无需存储静态 key。随后你可以使用这个短期 API key 创建 OpenAI 客户端，以使用受支持的 API。

**OpenAI Responses API。** 对于已经通过 OpenAI SDK 使用 Responses API 的应用，你可以将客户端指向区域 Amazon Bedrock Runtime endpoint。

```
from aws_bedrock_token_generator import provide_token
from openai import OpenAI

region = "ap-southeast-2" # Use "ap-southeast-4" for Melbourne.
model_id = "global.openai.gpt-5.6-terra"
prompt = (
    "In three short bullet points, explain how Availability Zones "
    "help make an AWS application highly available."
)

openai_client = OpenAI(
    base_url=f"https://bedrock-runtime.{region}.amazonaws.com/openai/v1",
    api_key=provide_token(region=region),
)

responses_result = openai_client.responses.create(
    model=model_id,
    input=prompt,
    max_output_tokens=300,
)

print(responses_result.output_text)
```

对于流式输出，设置 `stream=True` 并遍历响应事件。以下示例在文本到达时将其打印出来：

```
response_stream = openai_client.responses.create(
    model=model_id,
    input=prompt,
    max_output_tokens=300,
    stream=True,
)

for event in response_stream:
    if event.type == "response.output_text.delta":
        print(event.delta, end="", flush=True)
```

**OpenAI Chat Completions API。** 如果你的应用已经使用 Chat Completions API，也可以继续使用它。

```
from aws_bedrock_token_generator import provide_token
from openai import OpenAI

region = "ap-southeast-2" # Use "ap-southeast-4" for Melbourne.
model_id = "global.openai.gpt-5.6-terra"
prompt = (
    "In three short bullet points, explain how Availability Zones "
    "help make an AWS application highly available."
)

openai_client = OpenAI(
    base_url=f"https://bedrock-runtime.{region}.amazonaws.com/openai/v1",
    api_key=provide_token(region=region),
)

chat_result = openai_client.chat.completions.create(
    model=model_id,
    messages=[{"role": "user", "content": prompt}],
    max_completion_tokens=300,
    reasoning_effort="low",
)

print(chat_result.choices[0].message.content)
```

**Amazon Bedrock Converse API。** 当你的应用通过 AWS SDK 调用 Amazon Bedrock 时，请使用 Converse API。Boto3 通过标准 AWS 凭证链解析凭证。

```
import boto3

region = "ap-southeast-2" # Use "ap-southeast-4" for Melbourne.
model_id = "global.openai.gpt-5.6-terra"
prompt = (
    "In three short bullet points, explain how Availability Zones "
    "help make an AWS application highly available."
)
messages = [
    {
        "role": "user",
        "content": [{"text": prompt}],
    }
]

bedrock_client = boto3.client("bedrock-runtime", region_name=region)
converse_result = bedrock_client.converse(
    modelId=model_id,
    messages=messages,
    inferenceConfig={"maxTokens": 300},
)

print(converse_result["output"]["message"]["content"][0]["text"])
```

对于流式输出，使用相同 Region 和配置 ID 调用 `converse_stream`，然后遍历返回的事件流。

```
stream_result = bedrock_client.converse_stream(
    modelId=model_id,
    messages=messages,
    inferenceConfig={"maxTokens": 300},
)

for event in stream_result["stream"]:
    if "contentBlockDelta" in event:
        delta = event["contentBlockDelta"]["delta"]
        if "text" in delta:
            print(delta["text"], end="", flush=True)
print()
```

上述示例在 Asia Pacific（Sydney）调用 Amazon Bedrock。要在 Asia Pacific（Melbourne）运行同样的示例，请将 Region 设置为 `ap-southeast-4` 并运行代码。

### 使用 prompt caching

GPT-5.6 的 prompt caching 可通过受支持的 API 使用。GPT-5.6 在 Amazon Bedrock 上支持两种缓存模式。隐式缓存默认启用，无需更改代码；而使用显式缓存时，你可以定义可复用的前缀、缓存边界和缓存 key。[GPT-5.6 博文](https://aws.amazon.com/blogs/machine-learning/introducing-cross-region-inference-for-openai-gpt-5-6-models-on-amazon-bedrock/)提供了示例来说明 prompt caching 能力。

## 在 Amazon Bedrock 上使用 GPT-5.6 设置 Codex

Codex 可以通过 Amazon Bedrock Runtime 使用相同的全球推理配置。安装最新的 Codex CLI，即可使用原生 Amazon Bedrock Runtime 模型提供程序。此处，我们使用 codex-cli 0.149.1 搭配来自 Asia Pacific（Sydney）的 GPT-5.6 Sol 验证了以下配置。

```
npm install -g @openai/codex@alpha
codex --version
```

对于身份提供程序为 Okta、Auth0、Microsoft Entra ID、Amazon Cognito 或 AWS IAM Identity Center 的组织，[AWS OIDC Auth Helper 仓库](https://github.com/aws-samples/sample-openai-on-aws/tree/main/aws-oidc-auth)提供了一个示例凭证助手。首先，按照指南配置你的身份提供程序、相应的 AWS federation 资源，以及带有前面所示 Amazon Bedrock 权限的 IAM 角色。然后在 `~/.aws/config` 中添加一个命名 profile，这样助手就不会替换由默认 profile 解析的凭证。请将占位符替换为已安装助手的路径和 `~/.aws/config` 文件中定义的 profile 名称。

```
[profile <AWS_OIDC_PROFILE>]
credential_process = <ABSOLUTE_PATH_TO_CREDENTIAL_PROCESS> --profile <OIDC_HELPER_PROFILE>
region = ap-southeast-2
output = json
```

该 federation 助手用 OIDC token 换取临时 AWS 凭证，Codex 通过标准 AWS 凭证链读取，无需进一步配置。接下来，创建或更新 `~/.codex/config.toml` 并引用该 AWS profile；其他受支持的设置请参阅 [Codex 配置参考](https://developers.openai.com/codex/config-reference/)：

```
model = "global.openai.gpt-5.6-sol"
model_provider = "amazon-bedrock-runtime"
model_reasoning_effort = "high"

[model_providers.amazon-bedrock-runtime.aws]
profile = "<AWS_OIDC_PROFILE>"
region = "ap-southeast-2"
```

如果助手没有有效的缓存会话，它会在浏览器中打开配置好的登录页面。认证完成后，助手通过 `credential_process` 返回临时 AWS 凭证。请求使用 AWS SigV4 签名，因此推理路径中不涉及 API key。当 profile 由 AWS IAM Identity Center 支撑时，凭证本身就是短期的，并随单点登录会话轮换。要在 Asia Pacific（Melbourne）Region 中使用此配置，请在 AWS profile 和 Codex 配置中将 Region 设置为 `ap-southeast-4`。

## 配额管理

GPT-5.6 的按需配额以每分钟请求数（RPM）和每分钟 token 数（TPM）衡量。token 消耗速率决定每个请求如何消耗 TPM。token 用量由输入 token、缓存写入输入 token 和输出 token 乘以模型的[消耗速率](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-token-burndown.html)计算得出。例如，对于 GPT-5.6，输入 token 和缓存写入输入 token 按 1:1 计算，而每个输出 token 会从配额中消耗 10 个 token。请在你的应用所使用的源 Region——Asia Pacific（Sydney）Region（`ap-southeast-2`）或 Asia Pacific（Melbourne）Region（`ap-southeast-4`）——的 Service Quotas 控制台中查看 GPT-5.6 配额。在正式上线前，请尽早申请提升配额、监控配额利用率，并测试有代表性的 prompt、输出长度、流式行为、并发和峰值流量。当前数值和 token 消耗速率请参阅 [Amazon Bedrock 配额](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas.html)。

## 监控与日志

由于 GPT-5.6 请求使用 Amazon Bedrock Runtime API，通过全球推理配置发出的请求会与其他按需请求一样出现在[模型调用日志](https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html)中。启用日志记录后，记录会包含用于调用的模型或推理配置 ID 以及调用元数据。Codex 使用 OpenTelemetry（OTel）并通过 OTLP/HTTP 导出指标，详情请参阅[为 OpenAI Codex 设置 OpenTelemetry](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/coding-agents-codex.html)。

CloudWatch [Coding Agent Insights](https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html) 提供 Codex 遥测仪表板，包括 token 用量、API 请求、活跃用户、对话活动以及可选的组织维度。在 CloudWatch 中为 Codex 配置 Coding Agent Insights 有两条路径：使用 [Bearer token](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/coding-agents-codex-bearer-token.html) 或[企业版部署](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/coding-agents-codex-enterprise.html)。

以下示例展示如何使用 Bearer 方式为 Codex 配置 Coding Agent Insights。首先，[获取 CloudWatch 指标 API key](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-OTLP-MetricsBearerTokenAuth.html)，然后将以下部分添加到 `~/.codex/config.toml` 中。

```
[otel]
environment = "production"

[otel.metrics_exporter]
otlp-http = { endpoint = "https://monitoring.ap-southeast-2.amazonaws.com/v1/metrics", protocol = "binary", headers = { "Authorization" = "Bearer YOUR_CLOUDWATCH_METRICS_API_KEY" } }
```

将 `YOUR_CLOUDWATCH_METRICS_API_KEY` 替换为在 CloudWatch 中创建的 key，然后启动 Codex。该 CloudWatch 指标 API key 随后可授权向区域 CloudWatch endpoint 导出数据。遥测数据到达后，在 Asia Pacific（Sydney）Region 打开 CloudWatch 控制台，选择 GenAI Observability、Coding Agent Insights，然后点击 Codex 选项卡。你将看到 Coding Agent Insights 仪表板显示 Codex token 用量、请求活动、缓存命中率等信息。

![Asia Pacific（Sydney）的 CloudWatch Coding Agent Insights 仪表板，显示 Codex token 用量和请求活动。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/08/31/ML-21760-2.png)

图 2：Asia Pacific（Sydney）的 CloudWatch Coding Agent Insights 中的 Codex token 和请求活动

要填充 Organization、Environment、Department、Cost Center、Location、Team 和 User 筛选器，请通过 `OTEL_RESOURCE_ATTRIBUTES` 提供相应的值。AWS 将该 CloudWatch 指标 API key 归类为长期凭证，建议仅在无法使用短期 AWS 凭证的场景中使用。请将 `config.toml` 视为机密文件，并限制其文件权限。

对于通过企业单点登录联合开发者身份的组织，我们建议使用企业版部署方式：由本地收集器使用开发者的联合凭证通过 SigV4 对导出数据进行签名，且无需分发 token。

## 结论

本文介绍了如何从 Asia Pacific（Sydney）和 Asia Pacific（Melbourne）Region 发现并调用 GPT-5.6 Sol、Terra 和 Luna 全球推理配置。我们还介绍了如何配置 Codex 以使用 Amazon Bedrock Runtime，并将 Codex 遥测数据导出到 CloudWatch Coding Agent Insights。

要开始使用，请按照本文示例在你的账户中测试 GPT-5.6 模型。如果你使用 Codex，可以配置 [Amazon Bedrock Runtime](https://aws.amazon.com/bedrock/) 提供程序，并在 [AWS Console](https://console.aws.amazon.com/bedrock/) 中启用 CloudWatch Coding Agent Insights，以监控 Codex 用量。定价详情请参阅 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。
