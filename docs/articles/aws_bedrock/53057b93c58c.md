# 使用 Amazon SageMaker Unified Studio 为 Amazon Bedrock 模型配置精细化访问控制

采用先进 AI 解决方案的企业都认识到，稳固的安全性与精确的访问控制对于保护宝贵数据、维持合规性和维护用户信任至关重要。随着组织在各团队和应用中扩大 AI 的使用，他们需要细粒度权限来保护敏感信息，并管理谁可以访问强大的模型。[Amazon SageMaker Unified Studio](https://aws.amazon.com/sagemaker/unified-studio/) 正是为满足这些需求而生，让组织能够配置细粒度访问策略，确保只有获得授权的用户才能与基础模型（FM）交互，同时支持大规模、安全且协作式的创新。

SageMaker Unified Studio 于 2025 年推出，是一个统一的数据与 AI 开发环境，你可以在这里查找并访问组织内的数据，并使用覆盖各类用例的最佳工具对其加以利用。SageMaker Unified Studio 汇集了现有 AWS 分析与 AI/ML 服务的功能和工具，包括 [Amazon EMR](https://aws.amazon.com/emr/)、[AWS Glue](https://aws.amazon.com/glue/)、[Amazon Athena](https://aws.amazon.com/athena/)、[Amazon Redshift](https://aws.amazon.com/redshift/)、[Amazon Bedrock,](https://aws.amazon.com/bedrock/) 和 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker-ai/)。

SageMaker Unified Studio 中的 Amazon Bedrock 提供了多种发现和试用 Amazon Bedrock 模型与应用的方式。例如，你可以使用聊天 playground 试用 Anthropic 的 Claude 的 prompt，而无需编写代码。你还可以创建一个生成式 AI 应用，使用 Amazon Bedrock 模型以及知识库或 guardrail 之类的特性。要了解更多信息，请参阅 [SageMaker Unified Studio 中的 Amazon Bedrock](https://docs.aws.amazon.com/sagemaker-unified-studio/latest/userguide/bedrock.html)。

本文演示如何使用 SageMaker Unified Studio 和 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）为 Amazon Bedrock 模型建立稳固的权限框架。我们展示管理员如何在一套安全的协作环境中，精确管理哪些用户和团队可以访问特定模型。我们会引导你创建用于控制模型访问的细粒度权限，并针对常见的企业治理场景给出代码示例。读完本文，你将了解如何定制对生成式 AI 能力的访问，以满足组织的要求——在保持开发者灵活性的同时维持强安全标准，从而解决企业采用 AI 过程中的一个核心难题。

## 方案概览

在 SageMaker Unified Studio 中，*domain* 是主要的组织结构，因此你可以从单一界面统管多个 AWS Region、账户和工作负载。每个 domain 都会被分配一个唯一 URL，并对 studio 配置、用户账户和网络设置提供集中控制。

在每个 domain 内部，*project* 让协作更加顺畅。Project 可以跨越不同 Region，也可以跨越同一 Region 内的不同账户，其元数据包含关联的 Git 仓库、团队成员及其权限等细节。项目资源所在的每个账户都会被分配至少一个 project role，它决定了项目成员可以访问哪些工具、计算资源、数据集以及人工智能与机器学习（AI/ML）资产。要管理数据访问，你可以调整与 project role 绑定的 IAM 权限。SageMaker Unified Studio 会使用多个 IAM 角色。完整列表请参阅 [Amazon SageMaker Unified Studio 的身份与访问管理](https://docs.aws.amazon.com/sagemaker-unified-studio/latest/adminguide/security-iam.html)。

用户在 SageMaker Unified Studio 中与 Amazon Bedrock 模型交互主要有两种方式：SageMaker Unified Studio [playground](https://docs.aws.amazon.com/sagemaker-unified-studio/latest/userguide/bedrock-playgrounds.html) 和 SageMaker Unified Studio [projects](https://docs.aws.amazon.com/sagemaker-unified-studio/latest/userguide/projects.html)。

在 SageMaker Unified Studio playground 场景中，模型消费角色（model consumption role）为 Amazon Bedrock FM 提供安全访问。你可以选择为每个模型自动创建角色，也可以为所有模型配置单一角色。默认的 `AmazonSageMakerBedrockModelConsumptionRole` 预置了消费 Amazon Bedrock 模型所需的权限，包括调用为特定 SageMaker Unified Studio domain 创建的 Amazon Bedrock 应用推理配置文件（application inference profile）。要进一步细化访问控制，你可以为这些角色添加内联策略（inline policy），显式允许或拒绝访问特定的 Amazon Bedrock 模型。

- 受限访问路径（上方流程）：从 SageMaker Unified Studio 直接访问 Amazon Bedrock 的尝试会被拒绝。IAM 策略阻止了对 FM 的访问。对 Anthropic 的 Claude 3.7 Sonnet 的访问被拒绝（标记为 X）。对 Anthropic 的 Claude 3.5 Haiku 的访问被拒绝（标记为 X）。

- 治理机制：IAM 策略是模型访问的控制点。不同角色决定了不同级别的访问权限。每个 FM 的访问控制都被显式定义。

在 SageMaker Unified Studio project 场景中，SageMaker Unified Studio 使用模型预置角色（model provisioning role）在项目内为 Amazon Bedrock 模型创建推理配置文件。项目需要该推理配置文件才能与模型交互。你可以让 SageMaker Unified Studio 自动创建唯一的模型预置角色，也可以提供自定义的模型预置角色。默认的 `AmazonSageMakerBedrockModelManagementRole` 附带了 AWS 策略 [AmazonDataZoneBedrockModelManagementPolicy](https://docs.aws.amazon.com/sagemaker-unified-studio/latest/adminguide/security-iam-awsmanpol-AmazonDataZoneBedrockModelManagementPolicy.html)。你可以通过自定义信任策略将访问限制到特定的账户 ID。你还可以附加内联策略，并使用 `CreateApplicationInferenceProfileUsingFoundationModels` 语句来允许或拒绝访问项目中的特定 Amazon Bedrock 模型。

## 为 playground 场景创建模型消费角色

在以下步骤中，你将创建一个带信任策略的 IAM 角色，添加两个内联策略，并把它们附加到该角色上。

### 使用信任策略创建 IAM 角色

完成以下步骤，创建一个带信任策略的 IAM 角色：

- 在 IAM 控制台的导航窗格中，选择 **Roles**，然后选择 **Create role**。
- 在 **Trusted entity type** 中，选择 **Custom trust policy**。
- 删除编辑器中的默认策略，然后输入以下信任策略（将 `aws:SourceAccount` 字段中的 account-id 替换为你的 AWS 账户 ID）：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": {
                "Service": "datazone.amazonaws.com"
            },
            "Action": [
                "sts:AssumeRole",
                "sts:SetContext"
            ],
            "Condition": {
                "StringEquals": {
                    "aws:SourceAccount": "[account-id]"
                }
            }
        }
    ]
}
```

- 选择 **Next**。
- 通过选择 **Next** 跳过 **Add permissions** 页面。
- 为角色输入名称（例如 `DataZoneBedrock-Role`）以及可选描述。
- 选择 **Create role**。

### 添加第一个内联策略

完成以下步骤，添加一个内联策略：

- 在 IAM 控制台上，打开新建角色的详情页面。
- 在 **Permissions** 选项卡上，选择 **Add permissions**，然后选择 **Create inline policy**。
- 在 **JSON** 选项卡上，删除默认策略并输入第一个内联策略：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "InvokeDomainInferenceProfiles",
            "Effect": "Allow",
            "Action": [
                "bedrock:InvokeModel",
                "bedrock:InvokeModelWithResponseStream"
            ],
            "Resource": "arn:aws:bedrock:*:*:application-inference-profile/*",
            "Condition": {
                "StringEquals": {
                    "aws:ResourceTag/AmazonDataZoneDomain": "${datazone:domainId}",
                    "aws:ResourceAccount": "${aws:PrincipalAccount}"
                },
                "Null": {
                    "aws:ResourceTag/AmazonDataZoneProject": "true"
                }
            }
        }
    ]
}
```

- 选择 **Review policy**。
- 为策略命名（例如 `DataZoneDomainInferencePolicy`），然后选择 **Create policy**。

### 添加第二个内联策略

完成以下步骤，添加另一个内联策略：

- 在角色的 **Permissions** 选项卡上，选择 **Add permissions**，然后选择 **Create inline policy**。
- 在 **JSON** 选项卡上，删除默认策略并输入第二个内联策略（将 `bedrock:InferenceProfileArn` 字段中的 account-id 替换为你的账户 ID）：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowInferenceProfileToInvokeFoundationModels",
            "Effect": "Allow",
            "Action": [
                "bedrock:InvokeModel",
                "bedrock:InvokeModelWithResponseStream"
            ],
            "Resource": [
                "arn:aws:bedrock:us-east-1::foundation-model/anthropic.claude-3-5-haiku-20241022-v1:0",
                "arn:aws:bedrock:us-east-2::foundation-model/anthropic.claude-3-5-haiku-20241022-v1:0",
                "arn:aws:bedrock:us-west-2::foundation-model/anthropic.claude-3-5-haiku-20241022-v1:0"
            ],
            "Condition": {
                "ArnLike": {
                    "bedrock:InferenceProfileArn": "arn:aws:bedrock:*:[account-id]:application-inference-profile/*"
                }
            }
        }
    ]
}
```

- 选择 **Review policy**。
- 为策略命名（例如 `BedrockFoundationModelAccessPolicy`），然后选择 **Create policy**。

## 策略详解

本节讨论这些策略的细节。

### 信任策略详解

该信任策略定义了谁可以担任这个 IAM 角色：

- 它允许 [Amazon DataZone](https://aws.amazon.com/datazone/) 服务（`datazone.amazonaws.com`）担任该角色
- 该服务可以执行 `sts:AssumeRole` 和 `sts:SetContext` 操作
- 有一个条件将其限制为仅在你指定的 AWS 账户就是你自己的 AWS 账户时才成立

这确保了只有来自你指定账户的 Amazon DataZone 才能担任该角色。

### 第一个内联策略详解

该策略控制对 Amazon Bedrock 推理配置文件的访问：

- 它允许调用 Amazon Bedrock 模型（`bedrock:InvokeModel` 和 `bedrock:InvokeModelWithResponseStream`），但仅限应用推理配置文件资源（`arn:aws:bedrock:::application-inference-profile/*`）
- 它有三个重要条件：
- 配置文件必须带有与调用方的 domain ID 相匹配的 `AmazonDataZoneDomain` 标签
- 资源必须与发起请求的 principal 位于同一个 AWS 账户
- 资源不得带有被设为 `"true"` 的 `AmazonDataZoneProject` 标签

这实际上把访问限制在仅属于与调用方相同的 Amazon DataZone domain、且未关联任何特定项目的推理配置文件上。

### 第二个内联策略详解

该策略控制可以访问哪些具体的 FM：

- 它允许相同的 Amazon Bedrock 模型调用操作，但仅限于三个 Region 中特定的 Anthropic Claude 3.5 Haiku 模型：`us-east-1` `us-east-2` `us-west-2`
- 它带有一个条件：请求必须经由你账户中的推理配置文件发出

### 对 SageMaker Unified Studio domain 生成式 AI playground 的综合效果

这些策略共同作用，通过以下方式为在 SageMaker Unified Studio domain 中通过 playground 使用 Amazon Bedrock 模型营造出安全可控的环境：

- **限制模型访问** —— 只能使用指定的 Anthropic Claude 3.5 Haiku 模型，不能使用其他 Amazon Bedrock 模型
- **强制通过推理配置文件访问** —— 模型只能通过正确配置的应用推理配置文件访问
- **保持 domain 隔离** —— 访问被限制在带有用户 Amazon DataZone domain 标签的推理配置文件上
- **帮助防止跨账户访问** —— 资源必须与 principal 位于同一账户
- **Region 限制** —— 仅允许在三个特定 AWS Region 中访问该模型

该实现遵循最小权限原则，只提供预期用例所需的最小权限，同时在不同 domain 与 project 之间维持恰当的安全边界。

## 为 project 场景创建模型预置角色

本节将带你走完这些步骤：创建一个带信任策略的 IAM 角色，并添加所需的内联策略，以确保模型被限制在已批准的范围内。

### 使用信任策略创建 IAM 角色

完成以下步骤，创建一个带信任策略的 IAM 角色：

- 在 **Trusted entity type** 中，选择 **Custom trust policy**。

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": {
                "Service": "datazone.amazonaws.com"
            },
            "Action": [
                "sts:AssumeRole",

- 在 **Permissions** 选项卡上，选择 **Add permissions**，然后选择 **Create inline policy**。
- 在 **JSON** 选项卡上，删除默认策略并输入以下内联策略：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "ManageApplicationInferenceProfile",
            "Effect": "Allow",
            "Action": [
                "bedrock:CreateInferenceProfile",
                "bedrock:TagResource"
            ],
            "Resource": [
                "arn:aws:bedrock:*:*:application-inference-profile/*"
            ],
            "Condition": {
                "StringEquals": {
                    "aws:ResourceAccount": "${aws:PrincipalAccount}"
                },
                "ForAnyValue:StringEquals": {
                    "aws:TagKeys": [
                        "AmazonDataZoneProject"
                    ]
                },
                "Null": {
                    "aws:ResourceTag/AmazonDataZoneProject": "false",
                    "aws:RequestTag/AmazonDataZoneProject": "false"
                }
            }
        },
        {
            "Sid": "DeleteApplicationInferenceProfile",
            "Effect": "Allow",
            "Action": [
                "bedrock:DeleteInferenceProfile"
            ],
            "Resource": [
                "arn:aws:bedrock:*:*:application-inference-profile/*"
            ],
            "Condition": {
                "StringEquals": {
                    "aws:ResourceAccount": "${aws:PrincipalAccount}"
                },
                "Null": {
                    "aws:ResourceTag/AmazonDataZoneProject": "false"
                }
            }

## 策略详解

本节讨论这些策略的细节。

### 信任策略详解

该信任策略定义了谁可以担任这个 IAM 角色：

- 它允许 Amazon DataZone 服务担任该角色
- 该服务可以执行 `sts:AssumeRole` 和 `sts:SetContext` 操作
- 有一个条件将其限制为仅在源 AWS 账户就是你自己的 AWS 账户时才成立

这确保了只有来自你特定账户的 Amazon DataZone 才能担任该角色。

### 内联策略详解

该策略控制对 Amazon Bedrock 推理配置文件和模型的访问：

- 它允许创建和管理应用推理配置文件（`bedrock:CreateInferenceProfile`、`bedrock:TagResource`、`bedrock:DeleteInferenceProfile`）
- 它特别允许仅为 `anthropic.claude-3-5-haiku-20241022-v1:0` 模型创建推理配置文件
- 访问通过若干条件控制：资源必须与发起请求的 principal 位于同一个 AWS 账户；操作依据 `AmazonDataZoneProject` 标签进行限制；创建配置文件需要正确打上 `AmazonDataZoneProject` 标签；删除配置文件仅允许对带有相应 `AmazonDataZoneProject` 标签的资源执行

### 对 SageMaker Unified Studio domain project 的综合效果

这些策略共同作用，通过以下方式为在 SageMaker Unified Studio domain project 中使用 Amazon Bedrock 模型营造出安全可控的环境：

- **限制模型访问** —— 只能使用指定的 Anthropic Claude 3.5 Haiku 模型
- **强制正确打标签** —— 资源必须正确打上 `AmazonDataZoneProject` 标识符
- **保持账户隔离** —— 资源必须与 principal 位于同一账户
- **实施最小权限** —— 对推理配置文件只允许特定操作（创建、打标签、删除）
- **提供项目级隔离** —— 访问被限制在带有相应项目标识符标签的推理配置文件上

该实现遵循最小权限原则，只提供项目特定用例所需的最小权限，同时在不同项目之间维持恰当的安全边界，并确保只能访问已批准的 FM。

## 配置 SageMaker Unified Studio domain 以使用这些角色

完成以下步骤，创建一个 SageMaker Unified Studio domain 并将其配置为使用你创建的角色：

- 在 SageMaker 控制台上，选择合适的 Region。
- 选择 **Create a Unified Studio domain**，然后选择 **Quick setup**。
- 在 **Name** 中，输入一个有意义的 domain 名称。
- 向下滚动到 **Generative AI resources**。
- 在 **Model provisioning role** 下，选择上一节创建的模型管理角色。
- 在 **Model consumption role** 下，选择 **Use a single existing role for all models**，然后选择上一节创建的模型消费角色。
- 根据你的 [AWS IAM Identity Center](https://aws.amazon.com/iam/identity-center/) 配置完成其余步骤，并创建你的 domain。
