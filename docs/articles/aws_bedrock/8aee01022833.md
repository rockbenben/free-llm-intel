# 使用 Amazon Nova 2 Sonic 构建医疗预约 agent

如果你经营一家诊所或一个医院网络，你早已知道爽约的代价。美国医疗行业的平均 no-show 率在 5%–30% 之间，[具体取决于专科](https://www.healthcarefinancenews.com/news/missed-appointments-cost-providers-150-billion-annually-report-says)。每一个空出的时段都意味着收入损失、提供方时间闲置以及患者照护被延误。标准的解法——逐一给患者打电话确认或改约——无法扩展。

在本文中，你将学习如何构建一个语音 agent，使用 [Amazon Nova 2 Sonic](https://docs.aws.amazon.com/nova/latest/nova2-userguide/using-conversational-speech.html) 和 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 来处理预约提醒对话。该 agent 通过语音验证患者身份、管理预约（确认、取消或改期）、收集就诊前的健康信息，并在需要时升级给人工员工。你以规模化的方式处理常规来电，从而帮助降低 no-show 率。这个示例聚焦于问题中 agentic 的一面：语音对话与工具编排。为便于测试，其中包含一个基于浏览器的界面。要把该 agent 接入实际电话线路进行外呼，你需要集成一个电话服务，例如 [Amazon Connect Customer](https://aws.amazon.com/connect/)。

本文的演练将带你走完整个构建过程。你会得到一个在 Amazon Bedrock 上可用的语音 agent，它借助 Amazon Nova 2 Sonic 的语音到语音能力进行自然的预约对话；此外还有七个医疗行业专用的工具，使用 Strands Agents SDK 构建，用于患者身份验证、排程和升级。这套 serverless 部署运行在 Amazon Bedrock AgentCore 上，使用 [Amazon Cognito](https://aws.amazon.com/cognito/) 认证、[Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 持久化和 [Amazon Simple Notification Service（Amazon SNS）](https://aws.amazon.com/sns/) 通知。一个基于浏览器的 React 前端通过已认证的 WebSocket 连接传输双向音频。

## 解决方案概览

要有效自动化预约来电，你需要一个能在单次交互中处理多个步骤的对话式 AI 系统：验证身份、呈现预约详情、处理变更，以及收集健康信息。

传统做法是把彼此独立的服务串联起来。语音转文本模型转写患者的话语，基于文本的大语言模型（LLM）生成回复，再由文本转语音模型读出来。每一次交接都会引入延迟并丢失上下文。转写这一步丢弃了语调、迟疑和急迫等声音线索。LLM 听不到患者是*如何*说的，只知道他们说了*什么*。在医疗场景中，患者的焦虑或困惑本应改变 agent 的回应方式，这种信息损失很要紧。

这个 agent 采取了不同的做法：组合两项 AWS 服务。

### Amazon Nova 2 Sonic

Amazon Nova 2 Sonic 是 Amazon Bedrock 上可用的语音到语音模型，它通过双向流式传输实现实时对话式 AI。Nova 2 Sonic 不是在串联独立的转写、推理和合成服务，而是在单个模型中原生地处理语音——因此语调、语速这类声音上下文不会在转写中丢失。关于 Nova 2 Sonic 如何处理语音并适应声学上下文的更多信息，请参阅 [Introducing Amazon Nova Sonic](https://aws.amazon.com/blogs/aws/introducing-amazon-nova-sonic-human-like-voice-conversations-for-generative-ai-applications/) 博文。

对这个 agent 而言，Nova 2 Sonic 提供了若干关键能力。它原生的语音到语音处理在多轮对话中保留了声音上的细微差别，因此 agent 能捕捉到迟疑或担忧，同时不丢失上下文。工具调用的准确性让多步骤的医疗 workflow 保持在正轨上。模型知道何时验证身份、何时查询排程、何时完成预约。低延迟的双向流式传输让对话保持即时响应。该模型还被设计为能处理家庭与临床环境中常见的背景噪声，以及带口音的英语。最后，多语言支持让 agent 可以在对话中途切换到患者的首选语言，而无需改动配置。支持的语言请参阅 [Amazon Nova 2 Sonic 文档](https://docs.aws.amazon.com/nova/latest/nova2-userguide/using-conversational-speech.html)。

### Amazon Bedrock AgentCore

Amazon Bedrock AgentCore 提供一个 serverless、与框架无关的运行时，用于以企业级安全性大规模运行 AI agent。你把 agent 逻辑以容器形式部署，AgentCore 负责基础设施、伸缩以及经 AWS Identity and Access Management（IAM）认证的 WebSocket 端点。本实现使用 Strands Agents SDK 的 `BidiAgent` 类来管理与 Nova 2 Sonic 的双向语音流式传输。

*图 1：医疗预约 agent 的架构*

React 前端在浏览器中采集麦克风音频，并通过 WebSocket 把音频流式传输给 agent；WebSocket 是一种在客户端与服务器之间保持持久双向连接的协议。为保障该连接的安全，前端通过 Amazon Cognito（一个签发临时 AWS 凭证的身份服务）对用户进行认证，并用 SigV4 对每个请求签名——SigV4 是 AWS 标准的请求签名协议。

Amazon Bedrock AgentCore Runtime 托管容器化的 Strands `BidiAgent`，负责管理基础设施与伸缩。Nova 2 Sonic 接收音频输入、为对话进行推理、在需要时调用工具，并生成音频回复。三张 DynamoDB 表分别存储患者记录、预约详情和可用时段。当患者要求与人工通话时，Amazon SNS 会发布升级通知。

### 把它们接起来

Strands SDK 处理了双向语音流式传输的复杂性。整个 agent 的设置只需几行代码：

```
from strands.experimental.bidi import BidiAgent
from strands.experimental.bidi.models import BidiNovaSonicModel

model = BidiNovaSonicModel(
    region="us-east-1",
    model_id="amazon.nova-2-sonic-v1:0",
    provider_config={
        "audio": {
            "input_sample_rate": 16000,
            "output_sample_rate": 16000,
            "voice": "tiffany",
        }
    },
    tools=tools,  # The seven healthcare tools listed below
)

agent = BidiAgent(
    model=model,
    tools=tools,
    system_prompt=system_prompt,
)

# In the WebSocket handler, connect inputs and outputs
await agent.run(
    inputs=[receive_audio],
    outputs=[send_audio],
)
```

你把工具列表和 system prompt 传给 `BidiAgent`，把它指向 Nova 2 Sonic，SDK 便负责管理流式会话。它接收音频，在模型决定时调用工具，并把音频回复发送回去。

## 医疗工具

该语音 agent 使用七个工具来推进每一通电话。每个工具都实现为一个 Python 函数，并用 Strands Agents SDK 的 `@tool` 装饰器修饰。Nova 2 Sonic 根据患者所说的话决定何时调用每个工具。例如，当患者要求改期时，Nova 2 Sonic 会调用 `find_available_slots` 查询 DynamoDB，以语音呈现选项，然后调用 `book_appointment_slot` 完成变更。

这种基于工具的设计意味着你可以替换或扩展单个工具，而不必重写 agent 的其他部分。要新增一项能力（例如收集保险信息），你只需编写一个新的 `@tool` 函数并更新 system prompt。

| **工具** | **作用** | **工作方式** |
| --- | --- | --- |
| `authenticate_patient` | 使用名字、姓氏和 SSN 的后四位验证身份。 | 通过[全局二级索引（GSI）](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/GSI.html)查询 DynamoDB 的 Patients 表。对每个姓名组合强制三次尝试上限。成功时返回患者详情与即将到来的预约。 |
| `confirm_appointment` | 确认已有预约。 | 在 DynamoDB 中把预约状态从 `Scheduled` 或 `Rescheduled` 更新为 `Confirmed`。包含幂等检查，防止重复确认。 |
| `cancel_appointment` | 取消预约，可附带原因。 | 把状态更新为 `Canceled` 并附上带时间戳的备注。仅对 `Scheduled`、`Confirmed` 或 `Rescheduled` 的预约操作。 |
| `find_available_slots` | 查询可用于改期的开放时段。 | 从预约记录中查找提供方，并通过 `ProviderDateIndex` GSI 查询 `AvailableSlots` 表。最多返回三个选项，以保持语音对话简洁。 |
| `book_appointment_slot` | 预订选定的时段。 | 使用 DynamoDB 条件写入原子性地把该时段标记为已占用，防止并发请求下的重复预订。用新的日期和时间更新预约。 |
| `record_health_update` | 采集就诊前的健康信息。 | 向预约记录追加带时间戳的备注。收集四项内容（既往病史、过敏、陪同情况、具体关切）；每次只问一项。 |
| `escalate_to_agent` | 标记该通话需要人工回电。 | 生成六位参考号，把预约状态更新为 `Escalated`，并发布一条包含患者信息和升级原因的 Amazon SNS 消息。 |

## agent 如何处理一通电话

当 agent 与患者建立连接后，`BidiAgent` 会通过四个阶段管理整段对话。对话流程定义在 [agent 的 system prompt](https://github.com/aws-samples/sample-Nova-Sonic-AgentCore-Healthcare-Call-Center/blob/main/backend/prompts/healthcare_system_prompt.txt) 中，你可以针对自己的用例定制它。下面是改期流程的一段摘录，展示了 prompt 如何驱动多工具编排：

```
## RESCHEDULE FLOW
If the patient wants to reschedule:
1. Ask about their preferred time (morning/afternoon, specific days)
2. Use the find_available_slots tool to find available slots
3. Present 2-3 options and let them choose
4. After rescheduling, gather health information (same 4 questions as confirmation)
```

Nova 2 Sonic 遵循这些指令来决定何时调用每个工具。你可以通过编辑 prompt 来添加新流程或修改已有流程。

- **身份验证** – Nova 2 Sonic 向患者问好，并询问他们的全名和社会保障号码的后四位。在验证之前，agent 会复述它听到的内容，请患者确认。这能捕捉姓名或数字上的语音识别错误。`authenticate_patient` 工具会查询 DynamoDB 以验证身份。如果三次尝试后仍验证失败，出于安全考虑，agent 会升级给人工。
- **预约管理** – 验证之后，Nova 2 Sonic 呈现即将到来的预约详情，包括提供方姓名、日期和时间。患者选择确认、取消或改期。如果要改期，agent 会收集偏好（上午或下午、首选日期）、查询可用时段、呈现最多三个选项，并预订新的时间。
- **健康信息收集** – 对于已确认或已改期的预约，agent 会收集就诊前的健康信息。它会询问既往病史、过敏情况、是否有人陪同患者，以及本次就诊的任何具体关切。每个问题都逐个提出，以保持自然的对话节奏。
- **升级** – 在任何时点，如果患者要求与人工通话，agent 会记录原因、生成六位参考号，并发布一条 Amazon SNS 通知，以便员工在 24 小时内回电给患者。

## 部署该 agent

完整源代码见 [GitHub 代码仓库](https://github.com/aws-samples/sample-Nova-Sonic-AgentCore-Healthcare-Call-Center)。按照以下步骤在你自己的 AWS 账户中部署该 agent。

### 先决条件

在开始之前，请确保你具备以下条件：

- 一个 [AWS 账户](https://aws.amazon.com/free/)，并在目标 AWS 区域中拥有对 [Amazon Bedrock](https://aws.amazon.com/bedrock) 和 Nova 2 Sonic 模型的访问权限。
- 已安装 [AWS Cloud Development Kit（AWS CDK）v2](https://docs.aws.amazon.com/cdk/v2/guide/getting-started.html)，并在你的账户中完成 [bootstrap](https://docs.aws.amazon.com/cdk/v2/guide/bootstrapping.html)。
- [Python 3.12](https://www.python.org/downloads/) 或更高版本。
- [Node.js 20](https://nodejs.org/en/download) 或更高版本。
- [Docker](https://docs.docker.com/get-docker/)。

### 步骤 1：克隆代码仓库

```
git clone https://github.com/aws-samples/sample-Nova-Sonic-AgentCore-Healthcare-Call-Center.git
cd sample-Nova-Sonic-AgentCore-Healthcare-Call-Center
```

### 步骤 2：部署基础设施

AWS CDK 栈会预置你所需的全部资源：Cognito 用户池与身份池、DynamoDB 表、一个 Amazon SNS 主题，以及承载你容器化 agent 的 AgentCore Runtime。

```
cd infrastructure
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cdk deploy --require-approval never
```

部署完成后，请记下 AWS CloudFormation 的输出。配置前端需要 Cognito User Pool ID、Client ID、Identity Pool ID 以及 AgentCore Runtime ARN。

### 步骤 3：创建测试用户

创建一个用于测试的 Cognito 用户。把 `<UserPoolId>` 替换为 CDK 输出中的值：

```
aws cognito-idp admin-create-user \
    --user-pool-id <UserPoolId> \
    --username testuser \
    --temporary-password TempPass123!

aws cognito-idp admin-set-user-password \
    --user-pool-id <UserPoolId> \
    --username testuser \
    --password <YourSecurePassword> \
    --permanent
```

### 步骤 4：配置并运行前端

复制环境变量模板，并填入 CDK 输出中的值：

```
cd ../frontend
npm install
cp .env.example .env
# Edit .env with your CDK output values
npm run dev
```

在浏览器中打开 `http://localhost:5173`，用你的测试用户登录，从菜单中选择一位患者，然后选择 **Start Call** 开始语音对话。

### 步骤 5：填充演示数据

CDK 栈会在部署期间自动填充示例患者记录。如果你需要重新填充或自定义数据，请运行：

```
python3 scripts/seed_data.py
```

测试时，可以使用以下任一预配置患者：

| **患者姓名** | **SSN 后四位** |
| --- | --- |
| John Smith | 1234 |
| Jane Doe | 5678 |
| Michael Johnson | 9012 |
