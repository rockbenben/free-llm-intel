# 使用 GitHub Actions 在 Amazon Bedrock AgentCore 上部署 AI agent

近期，AWS 发布了 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/)，这是一个灵活的服务，可帮助开发者在不同框架与模型之间无缝创建和管理 AI agent，无论托管在 [Amazon Bedrock](https://aws.amazon.com/bedrock/?trk=e61dee65-4ce8-4738-84db-75305c9cd4fe&sc_channel=el) 还是其他环境中。具体而言，[AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 提供了一个安全、无服务器且专为部署和运行 AI agent 或工具而构建的托管环境。AgentCore Runtime 与框架无关，可与 LangGraph、Strands 和 CrewAI 等流行框架无缝协作，以自动扩缩和内置安全性来部署你的 AI agent 与工具。

在本文中，我们演示如何使用 [GitHub Actions workflow](https://github.com/features/actions) 自动化在 AgentCore Runtime 上部署 AI agent。这一方式提供了可扩缩的解决方案，并具备企业级安全控制，实现了完整的持续集成与交付（CI/CD）自动化。通过实现一条完整的 pipeline，我们得以遵循 AWS 最佳实践实现无缝的 agent 部署，包括 OpenID Connect（OIDC）身份验证、最小权限访问控制和环境隔离。我们的解决方案便于对已有 agent 进行高效更新，并整合了持续安全扫描与严格的代码质量检查。其结果是形成一套稳健的部署策略，有助于降低运维复杂度、增强安全性，并在企业环境中加速 AI agent 开发。

## Amazon Bedrock AgentCore Runtime 的优势

AgentCore Runtime 是生产环境 agent 部署的理想服务：

- 提供与框架无关的环境来运行你的 agent
- 可与 Amazon Bedrock 和 Anthropic Claude 提供的模型等大语言模型（LLM）配合使用
- 通过在专用 microVM 中运行每个用户会话，并隔离 CPU、内存和文件系统资源，实现会话隔离
- 同时支持实时交互以及最长 8 小时的长时间运行工作负载
- 提供内置的身份验证与可观测性能力

## 解决方案概览

我们基于 GitHub Actions 开发了一条完整的 CI/CD pipeline，可简化符合安全标准的 agent 部署流程。这条 pipeline 以开箱即用的解决方案形式提供，可与现有开发工作流无缝集成。该解决方案由以下关键组件构成：

- [GitHub Actions](https://help.github.com/en/actions) – 用于托管该 pipeline 的工作流编排工具
- [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-getting-started.html) – 用于托管并运行已部署 agent 的 AWS 服务
- [Amazon Elastic Container Registry (Amazon ECR)](https://docs.aws.amazon.com/AmazonECR/latest/userguide/what-is-ecr.html) – 用于存储、管理和部署 agent 容器镜像的 AWS 服务
- [Amazon Inspector](https://docs.aws.amazon.com/inspector/latest/user/what-is-inspector.html) – 用于对容器镜像执行高级且持续的漏洞扫描的 AWS 服务
- [IAM OIDC identity provider](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_providers_create_oidc.html) – 一种联合身份验证服务，用于在 GitHub 与 AWS 之间建立信任，使 GitHub Actions 无需维护 AWS secrets 和凭证即可在 AWS 上部署

下图展示了该解决方案的架构。

[![Architecture](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ml-19418-image-1.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ml-19418-image-1.png)

数据流包含以下步骤：

- 开发者在本地仓库中将代码变更提交到 GitHub 仓库。在本解决方案中，GitHub Action 为手动触发，但这一过程可以自动化。
- GitHub Action 触发构建阶段。
- GitHub 的 OIDC 使用 token 向 AWS 进行身份验证并访问资源。
- GitHub Actions 调用命令，直接从 Dockerfile 构建 agent 容器镜像并推送到 Amazon ECR。
- 镜像上传后，AWS Inspector 会触发一次高级安全扫描。
- 使用该容器镜像创建一个 AgentCore Runtime 实例。
- agent 还可以根据其配置查询 Amazon Bedrock 模型并调用工具。

以下各节将逐步介绍部署该解决方案的步骤：

- 从 GitHub 仓库下载源代码。
- 创建你的 agent 代码。
- 配置 GitHub secrets。
- 创建 IAM 角色与策略。
- 创建 GitHub Actions workflow。
- 触发并监控 pipeline。
- 验证部署。

## 前提条件

在使用我们这条安全的 CI/CD pipeline 将 agent 部署到 AgentCore Runtime 之前，请确认以下前提条件已就绪：

- 一个 [AWS 账户](https://aws.amazon.com/console/)，具备创建 [IAM Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色所需的足够权限
- 可访问 Amazon Bedrock 中[受支持的基础模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)里所需的 LLM 模型
- 已启用 Actions 的 [GitHub 账户](https://github.com/)（GitHub.com 或 GitHub Enterprise）
- 用于本地开发与测试的 [Python 3.10+](https://www.python.org/)

## 创建 agent 代码

使用 [AgentCore Runtime toolkit](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-toolkit.html) 与你选择的框架来创建 agent。该 toolkit 使用 BedrockAgentCoreApp 创建一个应用，提供一种标准化的方式把你的 AI agent 代码打包进一个可在 AgentCore Runtime 托管基础设施上运行的容器。它还使用 `app.entrypoint`——一个把某个函数标记为主入口点的 Python 装饰器。当 Amazon Bedrock agent 收到传入的 API 请求时，该函数接收并处理用户的请求。在这段示例 agent 代码中，当有人通过 API 调用你的 Amazon Bedrock agent 时，AgentCore Runtime 会自动调用 strands_agent_bedrock(payload) 函数。

在本文中，我们使用 `agents/strands_agent.py` 文件，借助 Strands Agents 框架创建一个 agent：

```
"""
This module defines a conversational AI agent that can perform calculations
using the Strands framework.
"""
from bedrock_agentcore.runtime import BedrockAgentCoreApp
from strands import Agent
from strands.models import BedrockModel
from strands_tools import calculator
# Initialize the Bedrock AgentCore application
app = BedrockAgentCoreApp()
# Configure the Claude model for the agent with guardrail
model_id = "us.anthropic.claude-sonnet-4-20250514-v1:0"
# Load guardrail ID if available
guardrail_config = None
try:
    with open("guardrail_id.txt", "r", encoding="utf-8") as f:
        guardrail_id = f.read().strip()
        if guardrail_id:
            guardrail_config = {
                "guardrailIdentifier": guardrail_id,
                "guardrailVersion": "1",
            }
            print(f"Loaded guardrail: {guardrail_id}")
except FileNotFoundError:
    print("No guardrail file found - running without guardrail")
model = BedrockModel(model_id=model_id, guardrail=guardrail_config)
# Create the agent with tools and system prompt
agent = Agent(
    model=model,
    tools=[calculator],
    system_prompt="You're a helpful assistant. You can do simple math calculation.",
)
@app.entrypoint
def strands_agent_bedrock(payload):
    """
    Main entrypoint for the Bedrock AgentCore Runtime.
    This function is called by AWS Bedrock AgentCore when the agent receives
    a request. It processes the user input and returns the agent's response.
    Args:
        payload (dict): Request payload containing user input
                       Expected format: {"prompt": "user question"}
    Returns:
        str: The agent's text response to the user's prompt
    """
    # Extract the user's prompt from the payload
    user_input = payload.get("prompt")
    # Process the input through the agent (handles tool selection and model inference)
    response = agent(user_input)
    # Extract and return the text content from the response
    return response.message["content"][0]["text"]
if __name__ == "__main__":
    # Run the application locally for testing
    # In production, this is handled by Bedrock AgentCore Runtime
    app.run()
```

## 配置 GitHub secrets

GitHub Actions workflow 必须能访问你 AWS 账户中的资源。在本文中，我们使用 IAM OpenID Connect 身份提供方，以及带 IAM 策略的 IAM 角色来访问 AWS 资源。OIDC 使你的 GitHub Actions workflow 无需将 AWS 凭证存为长期有效的 GitHub secrets，即可访问 AWS 中的资源。这些凭证作为 GitHub secrets 存储在你的 GitHub 仓库中，位于 **Settings** 下的 **Secrets** 选项内。更多信息请参阅 [Using secrets in GitHub Actions](https://help.github.com/en/actions/automating-your-workflow-with-github-actions/creating-and-using-encrypted-secrets)。

## 创建 IAM 角色与策略

要在 AgentCore Runtime 中运行 agent 或工具，你需要一个 IAM 执行角色。有关创建 IAM 角色的信息，请参阅 [IAM role creation](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_create.html)。

在本文中，我们为 AgentCore Runtime 创建所需的信任策略与执行角色。更多细节请参阅 [IAM Permissions for AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-permissions.html)。

以下代码为 AgentCore Runtime 的信任策略：

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AssumeRolePolicy",
      "Effect": "Allow",
      "Principal": {
        "Service": "bedrock-agentcore.amazonaws.com"
      },
      "Action": "sts:AssumeRole",
      "Condition": {
            "StringEquals": {
                "aws:SourceAccount": "accountId"
            },
            "ArnLike": {
                "aws:SourceArn": "arn:aws:bedrock-agentcore:region:accountId:*"
            }
       }
    }
  ]
}
```

以下代码为 AgentCore Runtime 的执行角色：

```
{
        "Version": "2012-10-17",
        "Statement": [
            {
                "Effect": "Allow",
                "Action": [
                    "bedrock:InvokeModel",
                    "bedrock:InvokeModelWithResponseStream",
                    "bedrock:Converse",
                    "bedrock:ConverseStream"
                ],
                "Resource": [
                    "arn:aws:bedrock:*::foundation-model/us.anthropic.claude-sonnet-4-*",
                    "arn:aws:bedrock:*::foundation-model/anthropic.claude-*",
                    "arn:aws:bedrock:*:*:inference-profile/us.anthropic.claude-sonnet-4-*",
                    "arn:aws:bedrock:*:*:inference-profile/anthropic.claude-*"
                ]
            },
            {
                "Effect": "Allow",
                "Action": [
                    "ecr:GetAuthorizationToken",
                    "ecr:BatchCheckLayerAvailability",
                    "ecr:GetDownloadUrlForLayer",
                    "ecr:BatchGetImage"
                ],
                "Resource": "arn:aws:ecr:::repository/bedrock-agentcore-*"
            },
            {
                "Effect": "Allow",
                "Action": [
                    "logs:CreateLogGroup",
                    "logs:CreateLogStream",
                    "logs:PutLogEvents"
                ],
                "Resource": "arn:aws:logs:*:*:*"
            }
        ]
    }
```

## 创建 GitHub Actions workflow

创建 workflow 的细节请参考位于 `.github/workflows/deploy-agentcore.yml` 的 CI/CD workflow 文件。该 workflow 将执行以下步骤：

- 它使用默认的 Ubuntu GitHub Runner 来执行 pipeline 中提供的任务。
- 该 workflow 安装 `requirement.txt` 文件中提到的所需依赖。
- 它构建 Docker 镜像并将其部署到 ECR 仓库。
- 使用 Amazon Inspector 扫描该镜像，以识别潜在漏洞。
- AgentCore Runtime 将 agent 部署为一个端点。
- 该 workflow 测试 agent 端点以验证功能。

## AgentCore Runtime 的版本管理与端点

Amazon Bedrock AgentCore 为 AgentCore Runtime 实现了自动版本管理，并允许你使用端点管理不同的配置。端点提供了一种引用 AgentCore Runtime 特定版本的方式。更多细节与示例代码请参阅 [AgentCore Runtime versioning and endpoints](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agent-runtime-versioning.html)。

## 清理

为避免产生后续费用，请完成以下步骤：

- 在 Amazon ECR 控制台中删除通过 GitHub Actions 部署所创建的 ECR 镜像。
- 删除在 AgentCore Runtime 中部署的 agent。
