# ZURU 如何借助 Amazon Bedrock 与 Amazon SageMaker 将户型图生成的准确率提升 109%

[ZURU Tech](https://zuru.tech/) 的使命是改变我们的建造方式，从联排住宅、医院到办公塔楼、学校、公寓楼等等。[Dreamcatcher](https://zuru.tech/design) 是 ZURU 开发的一个易用平台，让任何经验水平的用户都能参与建筑设计并协作推进建造流程。只需点击一个按钮，整栋建筑就可以被订购、制造并交付到施工现场进行组装。

ZURU 与 [AWS Generative AI Innovation Center](https://aws.amazon.com/generative-ai/innovation-center/) 以及 [AWS Professional Services](https://aws.amazon.com/professional-services/) 合作，使用[生成式 AI](https://aws.amazon.com/generative-ai/) 实现了一个更准确的文本到户型图生成器。借助它，用户可以用自然语言描述想要设计的建筑。例如，用户不必从零开始设计地基、墙体和建筑的关键部分，只需输入“创建一栋有三间卧室、两个卫生间，以及一个用于娱乐的户外空间的房子。”该解决方案会在 3D 设计空间内生成一份独特的户型图，让不具备建筑与施工专业知识的用户也能创建出设计良好的房屋

本文说明我们为什么选择基于[大语言模型（LLM）](https://aws.amazon.com/what-is/large-language-model/)的解决方案。我们探讨如何利用模型选择、prompt engineering 和微调来改进结果。我们还会解释团队如何借助评估框架，通过 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和 [Amazon SageMaker](https://aws.amazon.com/sagemaker/) 等关键服务实现快速迭代。

## 理解挑战

要在 Dreamcatcher 的 3D 建筑系统中生成房屋，基础前提是首先确认我们能够根据用户的 prompt 生成 2D 户型图。ZURU 团队发现，使用不同的[机器学习](https://aws.amazon.com/ai/machine-learning/)（ML）技术生成如下图中所示的 2D 户型图，需要在两项关键标准上同时取得成功。

[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/04/23/House7_Use_For_Article_Org-cropped-gimp5mb-1-1024x1008.jpg)](https://zuru.tech/)

首先，模型必须理解房间、每个房间的用途，以及它们在二维向量系统中彼此的朝向关系。这也可以描述为模型能在多大程度上遵循用户 prompt 中描述的特征。其次，还有数学层面的要求，即确保房间满足特定尺寸和楼面面积等标准。为了确认方向正确并支持快速的研发迭代，ZURU 团队构建了一套新颖的评估框架，通过展示这两项关键指标上的准确率水平，来衡量不同模型的输出。

ZURU 团队最初考虑使用[生成对抗网络（GAN）](https://aws.amazon.com/what-is/gan/)来生成户型图，但基于该测试框架对 GPT2 LLM 的试验取得了积极结果。这进一步印证了基于 LLM 的方法可以为文本到户型图生成器提供所需的准确率。

## 改进结果

为了在 GPT2 模型的结果之上继续改进，我们协同工作，定义了另外两项实验。第一项是 prompt engineering 方法。团队使用 [Amazon Bedrock 中的 Anthropic Claude 3.5 Sonnet](https://aws.amazon.com/bedrock/claude/)，评估在 prompt 中附带上下文示例时，一个领先的专有模型能带来什么影响。第二项方法聚焦于使用 Llama 3B 变体进行微调，评估当模型权重直接受高质量示例影响时准确率的提升情况。

## 数据集准备与分析

为了创建初始数据集，我们从公开来源收集了数千栋房屋的户型图，并由内部建筑师团队审阅。为简化审阅流程，ZURU 团队构建了一个自定义应用，采用类似流行社交匹配应用中的简单是/否决策机制，让建筑师能够快速批准与 ZURU 建筑系统兼容的方案，或拒绝带有不合格特征的方案。这种直观的做法显著加快了 ZURU 的评估过程，同时为每份户型图保持了清晰的判定标准。

为进一步增强该数据集，我们先进行细致的数据准备，包括通过评估 ground truth 数据集的指标分数过滤掉低质量数据（30%）。在这一过滤机制之后，指令遵循度未达到 100% 准确率的数据点会从训练数据集中移除。这一数据准备技术将微调和 prompt engineering 的效率与质量提升了 20% 以上。

在探索性数据分析中我们发现，数据集中存在可匹配多份户型图的 prompt，也存在可匹配多个 prompt 的户型图。通过把所有相关的 prompt 与户型图组合移入同一个数据划分（训练集、验证集或测试集），我们得以防止数据泄漏并促成稳健的评估。

## prompt engineering 方法

作为方法的一部分，我们为 few-shot prompting 实现了动态匹配，这与传统的静态采样方法不同。将其与 prompt 分解的实现相结合，我们能够提高所生成户型图内容的整体准确率。

采用动态 few-shot prompting 方法时，我们会在运行时根据输入 prompt 的细节，从高质量数据集中检索最相关的示例，并将其作为 prompt 的一部分提供给生成式 AI 模型。

动态 few-shot prompting 方法还通过 prompt 分解得到进一步增强，即把复杂任务拆解为更小、更易处理的组成部分，从而从语言模型获得更好的结果。通过分解查询，每个组成部分都可以针对其特定目的进行优化。我们发现，将这些方法结合后，示例选择的相关性更高、检索示例数据的延迟更低，从而带来更好的性能和更高质量的结果。

## prompt engineering 架构

下图所示用于原型验证的工作流与架构，展示了一种系统化的 AI 模型优化方法。当用户输入诸如“帮我建一栋有三间卧室和两个卫生间的房子”这样的查询时，工作流按以下步骤执行：

- 我们使用 prompt 分解执行三个更小的任务，以检索与用户所请求房屋特征高度匹配的示例
- 我们把这些相关示例注入 prompt，执行动态 few-shot prompting 来生成户型图
- 我们使用 reflection 技术，要求生成式 AI 模型自我反思并评估生成内容是否符合我们的要求

## 深入解析工作流与架构

工作流的第一步是理解房屋的独特特征，这些特征可作为搜索条件，用于在后续步骤中找到最相关的示例。这一步我们使用 Amazon Bedrock，它提供无服务器的、由 API 驱动的推理端点。在 Amazon Bedrock 提供的众多生成式 AI 模型中，我们选择 Mistral 7B，它在这一小型分解步骤所需的成本、延迟和准确率之间取得了恰当的平衡。

第二步是使用我们找到的独特特征搜索最相关的示例。我们使用以 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/) 作为向量数据库后端的 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)，实现元数据过滤与混合搜索，以检索最相关的记录标识符。[Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）用于存储数据集，Amazon Bedrock Knowledge Bases 则提供托管方案，把元数据向量化并索引到向量数据库中。

第三步，我们使用 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 按记录标识符检索实际的户型图数据。通过把户型图示例的搜索与检索拆分为两步，我们得以使用 Amazon OpenSearch 这样为特定目的构建的服务来实现低延迟搜索，并用 DynamoDB 实现按键值的低延迟数据检索，从而优化了性能。

在检索到与用户 prompt 最相关的示例之后，第四步我们使用 Amazon Bedrock 和 Anthropic Claude 3.5 Sonnet——一个在深度推理与数学方面基准领先的模型——来生成新的户型图。

最后，第五步我们实现 reflection。我们再次使用 Amazon Bedrock 上 Anthropic 的 Claude 3.5 Sonnet，把原始 prompt、指令、示例和新生成的户型图一并传回，并附带最后一条指令，要求模型反思并复核其生成的户型图，纠正错误。

## 微调方法

我们探索了两种为自动户型图生成优化 LLM 的方法：全参数微调与基于低秩适配（LoRA）的微调。全量微调会调整 LLM 的所有参数，这需要大量内存和训练时间。相比之下，LoRA 只调整一小部分参数，从而降低内存需求和训练时间。

### 深入解析微调工作流

我们实验中的一个关键洞见是数据集质量与多样性的极端重要性。在初始数据集准备之外，我们还发现在微调模型时，仔细挑选多样性更高的训练样本有助于模型学到更稳健的表示。此外，尽管更大的 batch size 通常能提升性能（在内存限制之内），我们必须仔细权衡这一点与算力资源（ml.p4.24xlarge 实例中的 320 GB GPU 内存）和训练时间（理想情况下在 1–2 天内完成）。

我们进行了多轮迭代以优化性能，试验了多种方案，包括最初的少量样本快速指令微调、更大数据集微调、带 early stopping 的微调、比较 Llama 3.1 8B 与 Llama 3 8B 模型，以及改变微调样本中的指令长度。经过这些迭代，我们发现使用 200,000 个样本的精选数据集对 Llama 3.1 8B 模型进行全量微调效果最好。

使用 BF16 和 micro batch size 3 对 Llama 3.1 8B 进行全量微调的训练过程包含 8 个 epoch、30,000 步，耗时 25 小时完成。相比之下，LoRA 方法展现出显著的计算效率，仅需 2 小时训练时间，并产生一个 89 MB 的 checkpoint。

### 评估框架

测试框架实现了一套高效的评估方法，在保持统计有效性的同时优化资源利用与时间。关键组成部分包括：

- 一套 prompt 去重系统，用于识别并合并测试数据集中的重复指令，减少计算开销，并为模型改进带来更快的迭代周期
- 一种基于分布的性能评估，筛选出独特的测试用例，通过统计分析促成有代表性的采样，并把结果投射到整个数据集
- 一种基于指标的评估，在关键标准上实现打分，从而可以与基线 GPT2 模型和其他方法进行对比分析。

## 结果与业务影响

为了了解实验中每种方法的表现如何，我们使用评估框架比较了几个关键指标。就本文而言，我们聚焦其中两项关键指标。第一项反映模型在多大程度上能遵循用户指令，体现房屋所要求的特征。第二项指标考察房屋特征在数学、位置与朝向方面对指令的遵循程度。下图以图表形式展示这些结果。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/11/results-graph.png)

我们发现，使用 Anthropic Claude 3.5 Sonnet 的 prompt engineering 方法，以及使用 Llama 3.1 8b 的全量微调方法，都把指令遵循质量相比基线 GPT2 模型提升了 109%，说明根据团队的技能组合，两种方法都可以用来提升 LLM 在生成户型图这类内容时的理解质量。

在数学正确性方面，我们的 prompt engineering 方法未能相比基线取得显著改进，而全量微调则是明显的赢家，比基线 GPT2 的结果提升了 54%。

基于 LoRA 的微调方法得分略低：与全量微调相比，指令遵循指标低 20%，数学正确性得分低 50%，这表明在时间、成本和硬件与模型准确率之间可以做出权衡。

## 结语

ZURU Tech 的愿景是从根本上改变我们设计与建造建筑的方式。本文中，我们重点介绍了基于 LLM 构建并改进文本到户型图生成器的方法，以在 3D 建模系统中实现高度可用且精简的工作流。我们深入探讨了使用 Amazon Bedrock 进行 prompt engineering 的高级概念，并详述了使用 Amazon SageMaker 微调 LLM 的方法，展示了你可以做出的不同权衡，以显著提升所生成内容的准确率。
