# MRH Trowe 如何在金融服务领域实现安全的自助式 AI agents

对于需要安全、自助式 AI agents 的金融服务机构而言，基础的 AI 聊天并不够用。在金融服务领域，员工需要的 AI 能够与内部系统和敏感客户数据协作、停留在受治理的环境之内，并且保持可审计和成本透明。所有这一切都必须在无需每个团队各自搭建工具的前提下实现。

本文介绍 [MRH Trowe](https://www.mrh-trowe.com/en/)——德国领先的商业与工业保险经纪商之一——如何为约 400 名员工提供对自助式 AI agents 的安全访问。该推广在投产后的第一个月就达到这一规模。该框架结合了 [Strands Agents](https://strandsagents.com/)、[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 和 [LibreChat](https://www.librechat.ai/)，以满足德国金融行业所需的安全性、数据驻留和合规控制。首月初始生产成本约为每席位 $14，并且有明确路径通过合理调整规格和定时扩缩容将基础设施成本降低约 40%。

## 关于 MRH Trowe

MRH Trowe 是一家由所有者管理的商业与工业保险经纪商，业务主要覆盖德国、瑞士和奥地利。通过有机扩张与并购成长，MRH Trowe 是最早完全基于云的 IT 基础设施运营的德国保险经纪商之一。AWS 是这一战略的首选合作伙伴，而使用 AI 是一项公司战略目标，具体用于精简内部流程、提升效率。

## 挑战：在不失控的前提下实现自助式 AI

作为高度监管行业中的商业保险经纪商，MRH Trowe 看到公司各部门员工对在日常工作中使用生成式 AI 的需求日益增长。个别团队开始自行尝试 AI，这带来了工具碎片化、缺乏管理，以及敏感客户和保险数据可能泄露的风险。

MRH Trowe 需要一种方式，让员工无需深厚技术技能就能快速自行构建和使用 AI agents。与此同时，一切都必须停留在安全、集中治理的环境内，满足金融行业的数据保护和合规要求。核心矛盾很明确：在广泛的自助式 AI 访问与组织所需的安全性、管控和成本透明之间取得平衡。MRH Trowe 的愿景是：“任何问题都应先由 AI 回答，再由人工介入；重复性流程应由过去做这些事的人来实现自动化。”

基础聊天界面在业务所需的几项能力上有所欠缺：

- **上下文响应** – 基于内部数据，而非仅依赖模型的通用知识。
- **多步骤工作流** – 需要收集信息、对其推理并跨多个步骤采取行动的任务。
- **机构数据集成** – 与内部系统和文档存储库的安全连接。
- **集中治理** – 一个统一的、受治理的应用，而非散布在各团队的影子 AI 工具。

## 构建模块

该方案将三项技术结合在一起，各自应对挑战中的一个具体部分。

### Strands Agents

MRH Trowe 的构建者使用 Strands Agents，这是一个只需几行代码即可创建 agents 的开源 SDK。Strands 负责编排和推理等 agent 模式，并能从构建者的笔记本电脑扩展到生产环境，使团队专注于用例而非基础设施。

### Amazon Bedrock AgentCore

为了在生产环境中运行 agents，MRH Trowe 使用 Amazon Bedrock AgentCore 作为平台，以任意框架或模型大规模构建、连接和优化 agents。AgentCore 是 MRH Trowe 的决定性因素：它原生支持 Strands Agents 等开源框架，在计算和文件系统层面隔离每个 agent 会话，并提供按用量计费的模式，使团队在采用规模扩大时仍能保持成本透明。这意味着团队既保留了 Strands 的灵活性，又没有放弃受监管经纪商所要求的安全性和会话隔离。

### LibreChat

LibreChat 是商业 AI 聊天界面的开源替代方案。它为 MRH Trowe 提供了一种熟悉、可定制品牌的聊天体验，能够迅速推动采用，同时具备受监管组织所需的控制能力：

- **用户管理** – 强大的身份验证与授权，以适当权限管理全体员工的访问。
- **Token 预算** – LibreChat 内置的 token 预算系统可避免意外成本。
- **多模型支持** – 可灵活为每个用例选择最合适的模型，同时避免供应商锁定。
- **对话管理** – 员工可以整理自己的 AI 交互，形成结构化的环境。
- **可定制界面** – 可按 MRH Trowe 的品牌形象定制。

### 实践：几分钟内将 Microsoft Teams 会议变成结构化会议纪要

MRH Trowe 投入生产的第一个 agent 能把 Microsoft Teams 会议变成可直接使用的会议纪要。在 LibreChat 中，员工用德语请求查询与某位参与者最近的一次会议。agent 在员工日历中找到该会议，检索转录文本，并起草一份结构化的会议摘要，包含日期、参与者、议程、主题和行动项。每次通话后手动做笔记，变成了一条单行请求。

两项设计选择让这对受监管经纪商而言是安全的。首先，每个请求都以已登录员工的身份运行。LibreChat 通过 Microsoft Entra ID 进行身份验证，并在服务端将用户身份传递给 agent，因此 agent 只能访问该员工自己的日历和转录文本。身份无法从聊天框中设置。其次，处理保留在区域内：agents、模型和数据都运行在 AWS 欧洲（法兰克福）区域，使客户和会议数据留在德国。Amazon Bedrock AgentCore 以及本方案中使用的基础模型在欧洲（法兰克福）区域（eu-central-1）均可用。服务和[模型可用性](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html)因 AWS 区域而异。

- **数据层**。  **Amazon DocumentDB**（兼容 MongoDB）用于存储用户、会话和对话数据。**Amazon ElastiCache** 用于缓存和会话状态。**Amazon Relational Database Service (Amazon RDS) for PostgreSQL** 作为关系型和向量存储，支撑 LibreChat 针对上传文档的 RAG API。**Amazon OpenSearch Service** 作为 Amazon Bedrock 的向量存储，支持对从 Confluence 摄取的内容进行检索。**Amazon Elastic File System (Amazon EFS)** 用于 MeiliSearch 索引。**Amazon Simple Storage Service (Amazon S3)** 用于上传文件和聊天产物。
- **Agent 层（Strands + AgentCore）** – Strands Agents 托管在 AgentCore runtime（Amazon Bedrock AgentCore 的一项能力）上，并通过由 AWS Lambda 和 Amazon API Gateway 支撑的自定义端点暴露给 LibreChat。借助这一模式，团队可以在 LibreChat 中加载新 agents，无需更新聊天应用或造成停机，并随着采用规模扩大独立推出新的 agentic 应用。

### 请求如何流转

以下步骤描述一个典型请求如何穿过系统，从员工的浏览器到 agent 再返回。

- 员工打开 LibreChat，从一个切换面板中选择 agent。
- LibreChat 通过 MRH Trowe 现有的身份提供商 Microsoft Entra ID 对用户进行身份验证。LibreChat 管理面板中的访问控制列表（ACL）决定用户可以访问哪些端点和模型。
- 当用户调用 agent 时，LibreChat 通过 API Gateway 调用一个自定义端点，并使用 API key 加以保护。或者，如果该端点支持 On-behalf-of（OBO）认证流程，也可将其用于用户身份验证。
- 一个 Lambda 函数使用 AWS Identity and Access Management（IAM）角色来调用运行在 AgentCore runtime 上的 Strands agent。
- agent 对请求进行推理，调用其工具和已授权的数据源，并在隔离、受治理的会话中通过 LibreChat 返回响应。

## 受监管环境的安全与合规

在德国金融行业运营意味着数据保护与治理不是可选项。该架构采用分层方法：

- **数据驻留德国** – 敏感的客户和保险数据停留在所选 AWS 区域内。
- **私有连接** – 传输网关配置结合零信任，使员工流量不经过公共互联网。
- **会话隔离** – AgentCore runtime 在计算和文件系统层面隔离每个 agent 会话。
- **集中治理** – 一个统一的、受管理的环境取代碎片化、无人管理的工具，使组织能够看见并控制 AI 的使用方式。
- **强大的身份验证与授权机制** – 基于 Active Directory 组的角色和访问权限，用于单点登录（SSO）和零信任方案。

有了这一基础，MRH Trowe 能够在安全且高度灵活的环境中为员工提供服务。AI 如今触手可及，每位员工都被鼓励去探索，而 AWS 的实现则在大规模下保持安全与治理。

## 结论

MRH Trowe 表明，受监管的金融服务机构既可以拥有广泛的自助式 AI 访问，也能具备行业所要求的管控能力。通过将开源（Strands Agents 和 LibreChat）的灵活性与 Amazon Bedrock AgentCore 的安全性、可扩展性和可靠性相结合，MRH Trowe 在第一个月就为约 400 名员工提供了一种集中治理的方式来构建和使用 AI agents，并且随着采用规模扩大，还有明确路径使其更加经济。

通过打造数据与 AI 实践社区，MRH Trowe 的目标是到 2026 年底由领域专家创建并维护 10–15 个 agents。
