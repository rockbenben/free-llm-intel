# Amazon Bedrock Flows 现已支持 DoWhile 循环

今天，我们很高兴宣布 [Amazon Bedrock Flows](https://aws.amazon.com/bedrock/flows/) 现已支持 [DoWhile loops](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent_LoopFlowNodeConfiguration.html)。借助这一强大新能力，你可以直接在 Amazon Bedrock flow 中创建迭代式、基于条件的工作流，在循环结构中使用 Prompt 节点、[AWS Lambda](https://aws.amazon.com/lambda/) 函数、[Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/)、Amazon Bedrock Flows 内联代码、[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)、[Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）以及其他 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 节点。该功能免去复杂变通方案的必要，支持使用 Amazon Bedrock Flows 全系列组件实现精细的迭代模式。内容打磨、递归分析和多步骤处理等任务，如今可以在重复循环中无缝集成 AI 模型调用、自定义代码执行和知识检索。通过为多种节点类型提供循环支持，该功能简化了生成式 AI 应用开发，并加速企业对复杂、自适应 AI 方案的采用。

使用 Amazon Bedrock Flows 的组织现在可以用 DoWhile loops 设计和部署工作流，完全在 Amazon Bedrock 环境内构建更具可扩展性和效率的生成式 AI 应用，同时实现以下目标：

- **迭代处理** – 反复执行操作直到满足特定条件，实现动态的内容打磨和递归式改进
- **条件逻辑** – 基于 AI 输出和业务规则，在 flow 中实现精细的决策
- **复杂用例** – 管理需要反复执行和打磨的多步骤生成式 AI 工作流
- **对构建者友好** – 通过 [Amazon Bedrock API](https://docs.aws.amazon.com/bedrock/latest/APIReference/welcome.html) 和 [AWS Management Console](https://aws.amazon.com/console) 在 traces 中创建和管理循环
- **可观测性** – 对循环迭代、条件和执行路径进行无缝跟踪

本文讨论这一新特性的优势，并展示如何在 Amazon Bedrock Flows 中使用 DoWhile loops。

## Amazon Bedrock Flows 中 DoWhile loops 的优势

在 Amazon Bedrock Flows 中使用 DoWhile loops 有以下优势：

- **简化 flow 控制** – 无需复杂编排或外部服务即可创建精细的迭代工作流
- **灵活处理** – 实现动态、基于条件的执行路径，可根据 AI 输出和业务规则调整
- **更佳开发体验** – 通过直观界面帮助用户构建复杂的迭代工作流，无需外部工作流管理

## 方案概览

在以下各节中，我们展示如何用 Do-while loops 和 Lambda 函数创建一个简单的 Amazon Bedrock flow。我们的示例展示了一个实际应用：构建一个 flow，以迭代方式针对给定主题生成博客文章，直到满足某些验收标准。该 flow 展示了在循环结构中组合不同类型 Amazon Bedrock Flows 节点的威力：Prompt 节点生成并微调博客文章，Inline Code 节点允许编写自定义 Python 代码来分析输出，S3 Storage 节点则能在过程中保存博客文章的每个版本以供参考。DoWhile 循环持续执行，直到博客文章的质量满足循环控制器中设定的条件。这个例子说明不同的 flow 节点如何在循环中协同工作，逐步转换数据直至达到期望条件，为理解包含各种节点组合的更复杂迭代工作流打下基础。

## 前置条件

在实现这些新能力之前，请确保你具备以下条件：

- 一个 AWS 账户
- 就绪的其他 Amazon Bedrock 服务：  在 [Amazon Bedrock Prompt Management](https://aws.amazon.com/es/bedrock/prompt-management/) 中[创建并测试基础 prompt](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-create.html)，用于客户服务交互；使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) [创建带有相关规则的 guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-components.html)
- 工作流所需的辅助 AWS 服务资源，例如 Lambda、[Amazon DynamoDB](https://aws.amazon.com/dynamodb)，以及 Amazon S3
- 所需的 [AWS Identity and Access Management](https://aws.amazon.com/iam/) (IAM) 权限：  [访问 Amazon Bedrock Flows](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-permissions.html) [在 Amazon Bedrock 中对大型语言模型 (LLM) 的适当访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access-permissions.html)

这些组件就绪后，你就可以在自己的生成式 AI 用例中使用带 DoWhile 循环能力的 Amazon Bedrock Flows。

## 使用 DoWhile Loop 节点创建 flow

完成以下步骤来创建你的 flow：

- 在 Amazon Bedrock 控制台的导航窗格中，选择 **Builder tools** 下的 **Flows**。
- 创建一个新 flow，例如 dowhile-loop-demo。有关创建 flow 的详细说明，请参阅 [Amazon Bedrock Flows is now generally available with enhanced safety and traceability](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-flows-is-now-generally-available-with-enhanced-safety-and-traceability/)。
- 添加一个 DoWhile loop 节点。
- 按照方案工作流（下一节讨论）添加其他节点。

Amazon Bedrock 提供多种[节点类型](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-nodes.html)来构建你的 prompt flow。本例中，我们用一个 DoWhile Loop 节点来调用生成式 AI 应用中的不同类型节点，该应用针对给定主题创建博客文章，并在每次循环中检查质量。flow 中只有一个 DoWhile Loop 节点。这个新节点类型位于左窗格的 **Nodes** 选项卡上，如下图所示。

## DoWhile 循环工作流

DoWhile 循环由两部分组成：**loop** 和 **loop controller**。loop controller 验证循环逻辑，并决定继续还是退出循环。本例中，每次执行循环时它都会执行 Prompt、Inline Code 和 S3 Storage 节点。

下面按步骤梳理这个 flow，如上图所示：

- 用户要求就某个特定主题撰写博客文章（例如使用如下 prompt：{“topic”: “AWS Lambda”, “Audience”: “Chief Technology Officer”, “word_count”:”500}）。该 prompt 被发送到 Prompt 节点 (Content_Generator)。
- Prompt 节点 (Content_Generator) 使用该 prompt，借助 Amazon Bedrock 提供的某个 LLM（例如 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) 或 Anthropic 的 Claude）撰写博客文章，并发送给 Loop Input 节点。这是 DoWhile Loop 节点的入口。
- 三个步骤依次发生：  Loop Input 节点把博客文章内容转发给另一个 Prompt 节点 (Blog_Analysis_Rating)，按照 prompt 中列明的标准对文章评分。这个 Prompt 节点的输出是如下示例那样的 JSON 代码。Prompt 节点的输出始终是 String 类型。你可以按需修改 prompt 来获得不同类型的输出。不过，你也可以让 LLM 只输出一个评分数字。  `{ "overall_rating": 8.5, "category_ratings": { "clarity_and_readability": 9, "value_to_target_audience": 8, "engagement_level": 8, "technical_accuracy": 9 }`  每次迭代期间，博客文章都会被发送到 flow 输出。当循环条件不满足（退出循环）或达到最大循环迭代次数时，这就是最终版本。与此同时，前一个 Prompt 节点 (Content_Generator) 的输出会被 Loop Input 节点转发给另一个 Prompt 节点 (Blog_Refinement)。该节点根据分析反馈重新创作或修改博客文章。
- Prompt 节点 (Blog_Analysis_Rating) 的输出被送入 Inline Code 节点，提取必要的评分，并以数字或检查循环控制器内条件所需的其他信息形式返回，作为输入变量（例如一个评分值）。

```
def __func(variable):
 return float(variable["overall_rating"])
__func(variable)
```

Inline Code 中的 Python 代码必须视为不可信，应实施适当的解析、校验和数据处理。

- Inline Code 节点的输出被送入循环控制器内的循环条件，用来对照我们在 continue loop 中设定的条件进行验证。本例中，我们检查生成的博客文章评分是否小于或等于 9。你最多可以检查五个条件。此外，一个最大循环迭代次数参数确保循环不会无限继续。
- 该步骤由两部分组成：  Prompt 节点 (Blog_Refinement) 把新生成的博客文章转发给循环控制器内的 loopinput。循环控制器把该文章版本存储到 Amazon S3，供日后参考和比较生成的不同版本。
- 如果 continue loop 中的某个条件以及最大循环迭代次数被满足，这条路径就会执行。若循环继续，前面新修改的博客文章会作为 LoopInput 被转发到 Loop Input 节点的输入字段，循环随之继续。
- 在 DoWhile 循环条件满足或最大迭代次数完成后，产生最终输出。输出即为博客文章的最终版本。

## 注意事项

在 Amazon Bedrock Flows 中使用 DoWhile Loop 节点时，需要注意以下重要事项：

- DoWhile Loop 节点不支持嵌套循环（循环中的循环）
- 每个循环控制器最多可评估五个输入条件作为退出标准
- 必须指定最大迭代次数限制，以帮助防止无限循环并实现可控执行

## 结论

DoWhile loops 与 Amazon Bedrock Flows 的集成标志着迭代工作流能力的一次重大进步，支持精细的基于循环的处理，可纳入 Prompt 节点、Inline Code 节点、S3 Storage 节点、Lambda 函数、agent、DoWhile Loop 节点和 Knowledge Base 节点。这一增强直接回应了企业客户在 AI 工作流中处理复杂重复任务的需求，帮助开发者无需外部编排工具即可创建自适应、基于条件的方案。通过支持迭代处理模式，DoWhile loops 帮助组织构建更精密的 AI 应用，能够在 Amazon Bedrock 环境内直接打磨输出、执行递归操作并实现复杂业务逻辑。Amazon Bedrock Flows 的这一强大补充让高级 AI 工作流的开发变得更加普惠，使各组织都能更轻松地构建和管理迭代式 AI 处理。
