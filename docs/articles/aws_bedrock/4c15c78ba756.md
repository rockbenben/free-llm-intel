# Travelers Insurance 如何借助 Amazon Bedrock 与提示词工程对邮件分类

*这是一篇客座博客文章，由 Travelers 的 Jordan Knight、Sara Reynolds 和 George Lee 共同撰写。*

基础模型（FM）的用途多种多样，在文本生成、文本摘要和问答等任务上表现良好。越来越多的 FM 正在完成过去由监督学习解决的任务；监督学习是机器学习（ML）的一个子集，指使用带标签的数据集训练算法。在某些场景中，较小的监督模型已被证明能够在生产环境中运行并满足延迟要求。然而，使用 Amazon Bedrock 这类 API 服务构建基于 FM 的分类器也自有其好处，例如系统开发速度快、可在模型之间切换、能快速迭代提示词工程实验，以及可扩展到其他相关的分类任务。FM 驱动的解决方案还能为输出给出理由，而传统分类器不具备这一能力。除这些特性之外，现代 FM 的能力已足够强大，能够在准确率和延迟要求上取代监督学习模型。

在本文中，我们介绍生成式 AI 创新中心（GenAIIC）如何与领先的财产与意外险保险公司 Travelers 合作，通过提示词工程开发出一套基于 FM 的分类器。Travelers 每年收到数百万封邮件，内容是代理人或客户提出的保单服务请求。GenAIIC 与 Travelers 构建的系统利用 FM 的预测能力，把复杂、有时甚至含义模糊的服务请求邮件归入若干类别。这个 FM 分类器为自动化系统提供支撑，可节省数万小时的人工处理时间，并把这段时间投入到更复杂的任务上。借助 Amazon Bedrock 上的 Anthropic Claude 模型，我们把该问题形式化为分类任务，并通过提示词工程以及与业务领域专家的合作，实现了 91% 的分类准确率。

## 问题构建

主要任务是把 Travelers 收到的邮件归入某个服务请求类别。这些请求涉及的领域包括地址变更、保额调整、工资单更新或风险敞口变更。虽然我们使用的是预训练 FM，但仍将问题形式化为文本分类任务。不过，我们没有采用通常需要训练资源的监督学习，而是使用带 few-shot 提示的提示词工程来预测邮件类别。这让我们可以使用预训练 FM，而无需承担训练成本。工作流从一封邮件开始，随后模型根据邮件文本以及可能存在的 PDF 附件，为该邮件给出分类。

需要指出的是，微调 FM 是另一种可以提升分类器性能的方法，但会带来额外成本。通过整理更长的示例与期望输出清单，可以训练 FM 在特定任务上表现更好。在本案例中，仅使用提示词工程就已获得较高的准确率，因此微调后的准确率必须足以证明其成本是值得的。尽管在项目开展时，Anthropic 的 Claude 模型尚不能在 Amazon Bedrock 上进行微调，但如今 Anthropic 的 Claude Haiku 微调已通过 Amazon Bedrock 进入 beta 测试。

## 解决方案概览

下图展示了用于对邮件进行分类的解决方案流水线。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/16/ML-16545-arch-diagram.jpg)

该工作流包含以下步骤：

- 原始邮件被摄取到流水线中。系统从邮件文本文件中提取正文。
- 如果邮件带有 PDF 附件，则对该 PDF 进行解析。
- PDF 被拆分为单页。每一页都保存为图像。
- 这些 PDF 页面图像由 Amazon Textract 处理，利用光学字符识别（OCR）提取文本、特定实体和表格数据。
- 邮件中的文本被解析。
- 随后如有必要，会清除文本中的 HTML 标签。
- 邮件正文与 PDF 附件中的文本被合并为大语言模型（LLM）的单一提示词。
- Anthropic 的 Claude 将这些内容归入 13 个已定义类别之一，然后返回该类别。每封邮件的预测结果还会进一步用于性能分析。

Amazon Textract 承担了多种用途，例如提取作为邮件附件包含的表单的原始文本。其中还包含额外的实体抽取和表格数据检测，用于识别姓名、保单号、日期等信息。随后，Amazon Textract 的输出与邮件文本合并，一起交给模型判定合适的类别。

该解决方案是无服务器的，这对组织有很多好处。采用无服务器方案时，AWS 提供托管式解决方案，有助于降低总体拥有成本并减少维护复杂性。

## 数据

标准答案数据集包含 4,000 多个带标签的邮件样本。原始邮件为 Outlook .msg 格式和原始 .eml 格式。大约 25% 的邮件带有 PDF 附件，其中大多数是 ACORD 保险表单。这些 PDF 表单包含额外的细节，为分类器提供了信号。为限定范围，只处理 PDF 附件，其他附件被忽略。对大多数样本而言，正文文本包含了与 13 个类别之一相对应的主要预测信号。

## 提示词工程

要构建一个有力的提示词，我们需要充分理解各类别之间的差异，才能为 FM 提供足够的解释。通过人工分析邮件文本并咨询业务专家，提示词中包含了一组关于如何对邮件分类的明确指令。另外的指令向 Anthropic 的 Claude 说明如何识别有助于将该邮件的类别与其他类别区分开的关键短语。提示词还包含演示如何执行分类的 few-shot 示例，以及展示 FM 应如何组织回复格式的输出示例。通过向 FM 提供示例及其他提示技巧，我们得以显著降低 FM 输出在结构和内容上的波动，从而获得可解释、可预测、可重复的结果。

提示词的结构如下：

- 角色设定
- 总体指令
- Few-shot 示例
- 每个类别的详细定义
- 邮件数据输入
- 最终输出指令

要了解更多关于 Anthropic Claude 的提示词工程，请参阅 Anthropic 文档中的提示词工程部分。

> “Claude 理解复杂保险术语和细微保单语言的能力，使它在邮件分类这类任务上尤为擅长。它能够解读上下文和意图，即使面对含义模糊的沟通内容也是如此，这与保险运营中面临的挑战完全契合。我们很高兴看到 Travelers 与 AWS 运用这些能力打造出如此高效的解决方案，展示了 AI 变革保险流程的潜力。”
>         – Jonathan Pelosi, Anthropic

## 结果

基于 FM 的分类器要投入生产使用，必须表现出很高的准确率。未使用提示词工程的初始测试准确率为 68%。在对 Anthropic 的 Claude v2 采用多种技术（如提示词工程、精简类别、调整文档处理流程和改进指令）之后，准确率提升到 91%。Amazon Bedrock 上的 Anthropic Claude Instant 同样表现良好，准确率为 90%，并识别出了进一步改进的方向。

## 结论

在本文中，我们讨论了 FM 如何通过提示词工程可靠地实现保险服务邮件的分类自动化。当把问题形式化为分类任务时，FM 的表现足以满足生产环境的需要，同时还能扩展到其他任务并快速落地。所有实验均使用 Amazon Bedrock 上的 Anthropic Claude 模型完成。
