# 使用 Amazon Nova Sonic 与 LiveKit 构建实时对话式 AI 体验

生成式 AI 技术的快速成长推动着企业生产力增长，创造了提高效率、改善客户服务体验和获得更佳客户成果的新机会。今天生成式 AI 的进步正在帮助既有技术实现它们长久以来承诺的潜力。例如，语音优先应用多年来在各行各业逐渐受到青睐——从客户服务到教育，再到个人语音助手与 agent。但这项技术的早期版本难以理解人类语音，也难以模仿真实对话。构建实时、听起来自然、低延迟的语音 AI 直到最近都仍然复杂，尤其是在与流式基础设施和语音基础模型（FM）配合时。

对话式 AI 技术的快速进步带来了强大的模型，它们解决了传统语音优先应用长期存在的难题。[Amazon Nova Sonic](https://aws.amazon.com/ai/generative-ai/nova/speech/) 是一个最先进的语音到语音 FM，专为在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 中构建实时对话式 AI 应用而设计。该模型提供业界领先的性价比和低延迟。Amazon Nova Sonic 的架构把语音理解与生成统一到单一模型中，从而在 AI 应用中实现真正的、类人的语音对话。

Amazon Nova Sonic 能够容纳人类语言的广度与丰富性。它可以理解不同说话风格的语音，并以富有表现力的嗓音生成语音，包括听起来偏男性和偏女性的嗓音。Amazon Nova Sonic 还能调整生成语音的轻重音、语调和风格模式，使其与语音输入的上下文和内容相契合。此外，Amazon Nova Sonic 支持函数调用，并支持使用检索增强生成（RAG）以企业数据做知识落地。为进一步简化充分利用这项技术的过程，Amazon Nova Sonic 现已与 [LiveKit Agents](https://docs.livekit.io/agents/?utm_source=aws&utm_medium=blog&utm_campaign=nova_sonic_plugin) 集成，这是一个被广泛使用的框架，让开发者能够构建实时音频、视频和数据通信应用。这一集成使开发者能够构建对话式语音界面，而无需管理复杂的音频 pipeline 或信令协议。本文说明这一集成如何工作、如何解决语音优先应用长期存在的难题，以及开始使用该方案的一些初始步骤。

## 解决方案概览

[LiveKit](https://livekit.io/?utm_source=aws&utm_medium=blog&utm_campaign=nova_sonic_plugin) 是一个开源平台，用于构建能够看、能听、能说的语音、视频和物理 AI 应用。它按全栈方案设计，提供覆盖 Web、移动端和后端系统的客户端 SDK、用于低延迟网络传输的 WebRTC 服务器，以及轮次检测、agent 负载均衡、电话通信和第三方集成等内置功能。无论自托管、部署到 AWS，还是运行在 LiveKit 的云服务上，开发者都可以为实时应用构建健壮的 agent 工作流，而无需操心底层基础设施。

构建实时、语音优先的 AI 应用需要管理复杂的基础设施——从音频采集与流式传输，到信令、路由和延迟优化——在使用 Amazon Nova Sonic 这类双向模型时尤其如此。为简化这一点，我们把一个 [Nova Sonic 插件](https://docs.livekit.io/agents/integrations/realtime/nova-sonic/?utm_source=aws&utm_medium=blog&utm_campaign=nova_sonic_plugin)集成进 LiveKit 的 Agents 框架，免去了管理自定义 pipeline 或传输层的需要。LiveKit 负责实时音频路由和会话管理，Nova Sonic 则负责语音理解与生成。开发者开箱即可获得全双工音频、语音活动检测和噪声抑制等功能，从而可以专注于为 AI 语音应用设计出色的用户体验。

## 先决条件

要实施该解决方案，你必须具备以下先决条件：

- Python 3.12 或更高版本
- 一个拥有 Amazon Bedrock 相应 [Identity and Access Management](https://aws.amazon.com/iam/)（IAM）权限的 AWS 账户
- Amazon Bedrock 上 [Amazon Nova Sonic 的访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html#:~:text=To%20request%20access%20to%20a,want%20to%20add%20access%20to.)
- 一个支持 WebRTC 的 Web 浏览器（例如 Google Chrome 或 Mozilla Firefox）

## 部署解决方案

按以下步骤开始通过 LiveKit 与 Amazon Nova Sonic 对话：

- 安装必要的依赖：

```
brew install livekit livekit-cli
curl -LsSf https://astral.sh/uv/install.sh | sh
```

`uv` 是 `pip` 的快速直接替代品，用于 LiveKit Agents SDK（你也可以选择使用 `pip`）。

- 新建一个本地虚拟环境：

```
uv init sonic_demo
cd sonic_demo
uv venv --python 3.12
uv add livekit-agents python-dotenv 'livekit-plugins-aws[realtime]'
```

- 要在本地运行 LiveKit 服务器，请打开一个新终端（例如一个新的 UNIX 进程）并运行以下命令：

```
livekit-server --dev
```

在整个 Amazon Nova Sonic agent 运行期间，你必须让 LiveKit 服务器持续运行，因为它负责在各参与方之间代理数据。

- 使用以下代码生成访问 token。`api-key` 和 `api-secret` 的默认值分别是 `devkey` 和 `secret`。为加入 LiveKit 房间的权限创建访问 token 时，你必须指定房间名称和用户身份。

```
lk token create \
 --api-key devkey --api-secret secret \
 --join --room my-first-room --identity user1 \
 --valid-for 24h
```

- 创建环境变量。你必须指定 AWS 凭证：

```
vim .env

// contents of the .env file
AWS_ACCESS_KEY_ID=<aws access key id>
AWS_SECRET_ACCESS_KEY=<aws secret access key>

# if using a permanent identity (e.g. IAM user)
# then session token is optional
AWS_SESSION_TOKEN=<aws session token>
LIVEKIT_API_KEY=devkey
LIVEKIT_API_SECRET=secret
```

- 创建 `main.py` 文件：

```
from dotenv import load_dotenv
from livekit import agents
from livekit.agents import AgentSession, Agent, AutoSubscribe
from livekit.plugins.aws.experimental.realtime import RealtimeModel

load_dotenv()

async def entrypoint(ctx: agents.JobContext):
    # Connect to the LiveKit server
    await ctx.connect(auto_subscribe=AutoSubscribe.AUDIO_ONLY)
    
    # Initialize the Amazon Nova Sonic agent
    agent = Agent(instructions="You are a helpful voice AI assistant.")
    session = AgentSession(llm=RealtimeModel())
    
    # Start the session in the specified room
    await session.start(
        room=ctx.room,
        agent=agent,
    )

if __name__ == "__main__":
    agents.cli.run_app(agents.WorkerOptions(entrypoint_fnc=entrypoint))
```

- 运行 `main.py` 文件：

```
uv run python main.py connect --room my-first-room
```

现在你就可以连接到 agent 前端了。

- 访问 [https://agents-playground.livekit.io/](https://agents-playground.livekit.io/)。
- 选择 **Manual**。
- 在第一个文本框中输入 `ws://localhost:7880`。
- 在第二个文本框中输入你生成的访问 token。
- 选择 **Connect**。

现在你应该能够与 Amazon Nova Sonic 实时对话了。

如果你与 LiveKit 房间断开连接，就必须重启 agent 进程（`main.py`）才能再次与 Amazon Nova Sonic 对话。

## 清理

本示例在本地运行，也就是说不需要特殊的拆卸步骤来清理。你只需退出 agent 和 LiveKit 服务器进程即可。唯一产生的成本是调用 Amazon Bedrock 与 Amazon Nova Sonic 对话的费用。在你与 LiveKit 房间断开连接之后，就不会再产生费用，也不会有任何 AWS 资源继续被占用。

## 结论

多亏生成式 AI，语音优先应用长久以来许诺的质性收益如今得以实现。把 Amazon Nova Sonic 与 LiveKit 的 Agents 框架结合，开发者可以以更低的复杂度和更快的部署构建实时、语音优先的 AI 应用。这一集成减少了对自定义音频 pipeline 的需求，让团队能够专注于构建引人入胜的对话体验。
