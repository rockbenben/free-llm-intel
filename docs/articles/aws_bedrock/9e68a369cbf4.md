# Baz 如何利用 Amazon Bedrock AgentCore 提升其 AI Agent 代码评审的准确率

代码评审一直是手动进行且效率低下的，因为代码与产品之间存在固有的脱节。开发者可以评审代码能否编译、能否运行，却无法评审它是否满足了全部功能与设计需求。过去，QA 团队要花上数小时手动点击预览环境中的各个页面，确认功能是否按预期运行，还要花更多时间让实现与设计意图保持一致。这种手动验证拖慢了交付、引入了不一致，也提高了回归的概率。随着开发团队的节奏加快，Baz 希望把这一缺失的验证层自动化，将意图、行为与实现收拢到同一个评审工作流中。

本文介绍 [Baz](https://baz.co/) 如何借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 与 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 构建其 Spec Review agent。我们将讨论其中的架构决策、实现细节，以及他们利用这些 AWS 服务自动化代码评审流程所取得的业务成果。

## Baz 试图解决的关键问题

[Baz](https://baz.co/) 的目标是超越传统的、只看 diff 的评审，转而验证某个功能是否满足其预期的产品需求。早在起步阶段，Baz 就发现团队很苦恼于只关注语法而不关注行为的评审：诸如“它能工作吗”“它符合规格吗”“它的行为符合预期吗”这类关键问题，只能留到流程后期靠人工回答。代码与产品意图之间的这道鸿沟拖慢了团队、造成了设计上的不一致，也让团队严重依赖 QA 未写入文档的内部知识。Baz 着手弥合这道鸿沟，办法是构建不仅评估代码、还评估实际交付体验的 agent。

## 解决方案概览

Baz Spec Review agent 编排了一条精密的多阶段验证 pipeline：一旦被触发（webhook 或手动调用），它就会并发地通过 MCP 查询 Figma、通过 REST API 查询 Jira，汇总涵盖技术、产品与设计规格的完整需求制品。随后系统派生相互隔离的 sub-agent worker（每个需求一个），负责验证该需求。这个 subagent 把基于源码仓库的代码检查，与使用 Amazon Bedrock AgentCore Browser Tool 的动态运行时验证结合起来。subagent 与临时环境交互，执行 DOM 检查、事件模拟和视觉测试，确保部署后的实现既符合 Figma 设计规格，也符合行为需求，并借助 AWS 原生编排，在整个“规格到实现”的生命周期上提供端到端验证。

下图展示了 Spec Reviewer 的架构：这套由 Baz 与 AWS 联合打造的方案，可以在你的代码评审工作流中实现设计与产品的自动化验证。整个 agentic 流程由通过 Amazon Bedrock 提供服务的大语言模型驱动，在整条 pipeline 上提供可扩展且安全的 AI 推理能力。流程由 GitHub 在新 pull request 上触发的 webhook 开始，流量经 Application Load Balancer（ALB）与 Network Load Balancer（NLB）进入 Amazon EKS 集群。Baz Platform 作为中央编排层，协调多 agent 的评审过程。

在 Amazon EKS 集群内部，Baz 的 Spec Review Agent 把验证工作流拆分为若干专用 subagent。由 Amazon Bedrock 驱动的 Specification Subagent 同时摄取来自 Figma 的视觉规格与来自 Jira 的功能规格，再把它们分解为一条条独立需求——视觉需求（例如间距、颜色与组件层级）和功能需求（例如验收标准与用户故事意图）。

Implementation Subagent 是这套架构的核心。这些由 Amazon Bedrock 驱动的 agent 会针对抽取出的规格执行深度代码分析，而让它们与众不同的是与 Amazon Bedrock AgentCore Browser Use 能力的集成。Implementation Subagent 不单纯依赖静态代码分析，而是能在实时的 Preview Environment 中渲染真实实现，并以视觉方式验证 UI 与预期的 Figma 设计一致、功能行为与 Jira 中规定的一致。这种代码理解与基于浏览器的验证的组合，让 Baz 能够捕捉到传统代码评审工具完全会漏掉的偏差。

Report Generator 把所有 subagent 的发现汇总成一份连贯的评审摘要。评审完成后，发现会被分发到相应渠道：评论直接发布到 GitHub PR，通知发送到 Slack 以便团队了解情况，识别出的问题可以自动回链到 Jira 进行跟踪与解决。

## Baz 如何落地 Amazon Bedrock AgentCore 来应对这些挑战

Amazon Bedrock AgentCore 成为了构建能够验证真实产品行为的 AI 代码评审器的基础。其安全、隔离、无服务器的浏览器会话，让 Spec Reviewer agent 能够打开预览环境、浏览各项功能，并完全像用户那样检查 UI 行为。通过把用于运行与工单系统集成的 MCP 服务器的 Amazon Bedrock AgentCore runtime，与带有轻量自动化与上下文模块的 Amazon Bedrock AgentCore Browser 工具结合起来，Baz Reviewer 无需任何浏览器基础设施或自定义编排，就能把实时行为与代码同工单和设计规格进行比对。Amazon Bedrock AgentCore 的隔离、沙箱与可观测性帮助 Baz 扩展多个 MCP 服务器，并让 agent 安全、可靠地大规模执行全栈验证。

## 借助 Amazon Bedrock 实现智能代码评审

Amazon Bedrock 为 Spec Reviewer agent 背后的推理与决策层提供动力，使其能够解读需求、理解设计意图，并评估在浏览器中观察到的各项行为是否与需求相关。借助 Amazon Bedrock 托管的基础模型，该 agent 可以综合规格上下文、分析 UI 状态，并就某个功能是否达到预期给出精确、可执行的结论。Amazon Bedrock 提供生产级 agentic 工作流所需的可靠性、安全性与规模，让 Baz 可以把复杂的解读与验证逻辑卸载到高性能 LLM，同时把浏览器执行隔离在 AgentCore 之内。这一组合使评审者能够弥合“原本想要什么”与“实际构建了什么”之间的差距。

## 结论

Baz Spec Review agent 展示了 Amazon Bedrock 与 Amazon Bedrock AgentCore 如何帮助组织自动化那些过去需要大量人工投入的产品验证工作流。凭借 Amazon Bedrock 基础模型完成需求解读与决策，再加上 AgentCore 安全的浏览器自动化能力，Baz 打造出一套能在整个开发生命周期中对照规格验证实现的方案，使报告的缺陷最多减少 50%，合并所需时间缩短 30–70%。

采用 Spec Reviewer 的客户在手动产品验证工作上有了显著减少：功能验证更早进入开发周期，并在 pull request 上自动执行。团队反馈评审更快、回归更少，对变更在合并前满足需求也更有信心。
