# 使用 Amazon Nova Multimodal Embeddings 实现跨模态搜索

[Amazon Nova Multimodal Embeddings](https://docs.aws.amazon.com/ai/responsible-ai/nova-multimodal-embeddings/overview.html) 通过单一模型架构处理文本、文档、图像、视频和音频。该模型可通过 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 使用，将不同的输入模态转换为同一向量空间内的数值 embedding，支持直接进行相似度计算，而不受内容类型限制。我们开发这一统一模型，是为了减少对独立 embedding 模型的需求——这些模型会使架构复杂化、难以维护和运营，并进一步将用例局限在单一维度的方法上。

在本文中，我们通过一个实际的电商用例，探讨 Amazon Nova Multimodal Embeddings 如何应对跨模态搜索的挑战。我们考察传统方法的技术局限，并展示 Amazon Nova Multimodal Embeddings 如何实现跨文本、图像及其他模态的检索。你将学习如何通过生成 embedding、处理查询和衡量性能来实现跨模态搜索系统。我们提供可运行的代码示例，并分享如何将这些能力添加到你的应用中。

## 搜索问题

传统方法包括基于关键字的搜索、基于文本 embedding 的自然语言搜索或混合搜索，但它们无法有效处理视觉查询，从而造成用户意图与检索能力之间的鸿沟。典型的搜索架构将视觉与文本处理分离，在这一过程中丢失了上下文。文本查询通过关键字匹配或文本 embedding 针对商品描述执行。图像查询（如果支持的话）通过多个计算机视觉流水线运行，与文本内容的集成有限。这种分离使系统架构复杂化，并削弱了用户体验。多个 embedding 模型需要独立的维护和调优周期，而跨模态查询无法在单一系统中原生处理。视觉与文本的相似度分数位于不同的数学空间中，难以跨内容类型对结果进行一致的排序。这种分离需要复杂的映射，而映射并非总能做到，因此 embedding 系统被分开维护，在此过程中形成数据孤岛并限制功能。复杂的商品内容进一步加剧了这一问题，因为商品页面会结合图像、描述、规格，有时还有视频演示。

## 跨模态 embedding

跨模态 embedding 将文本、图像、音频和视频映射到一个共享向量空间，其中语义相似的内容会聚集在一起。例如，当处理文本查询 `red summer dress` 和一张红色连衣裙的图片时，两种输入都会在 embedding 空间中生成彼此接近的向量，反映出它们的语义相似性，从而实现跨模态检索。

通过使用跨模态 embedding，你可以跨不同内容类型进行搜索，而无需为每种模态维护独立的系统，从而解决分段式多模态系统的问题——在这类系统中，组织管理着多个 embedding 模型，由于不同模态的 embedding 不兼容，这些模型几乎无法有效集成。单一模型架构有助于确保你在所有内容类型上生成一致的 embedding，同时相关内容（例如商品图片、视频及其描述）会由于联合训练目标而生成相似的 embedding。应用可以使用相同的 API 端点和向量维度为所有内容类型生成 embedding，从而降低系统复杂度。

## 用例：电商搜索

设想一位顾客在电视上看到一件衬衫，想找到相似的商品购买。他们可以用手机给这件商品拍照，或尝试用文字描述所看到的内容，并以此搜索商品。传统搜索能较好地处理引用元数据的文本查询，但当顾客想用图像搜索或描述商品的视觉属性时，就无法执行了。这种"从电视到购物车"的购物体验展示了视觉与文本搜索如何协同工作。顾客上传一张照片，系统会将其与同时包含图像和描述的商品目录进行匹配。跨模态电商工作流如下图所示。

## Amazon Nova Multimodal Embeddings 如何提供帮助

[Amazon Nova](https://aws.amazon.com/nova/) 通过同一模型处理不同类型的搜索查询，这既创造了新的搜索能力，也带来了技术优势。无论你是上传图像、用文本输入描述，还是将两者结合，处理流程都是一样的。

### 跨模态搜索能力

如前所述，Amazon Nova Multimodal Embeddings 通过统一模型架构处理所有受支持的模态。输入内容可以是文本、图像、文档、视频或音频，随后它会在同一向量空间中生成 embedding。这支持不同内容类型之间直接进行相似度计算，而无需额外的转换层。当顾客上传图像时，系统会将其转换为 embedding，并使用余弦相似度在商品目录中搜索。你会得到具有相似视觉特征的商品，而不受其文本描述方式的限制。文本查询的工作方式相同——顾客可以描述他们想要的东西，并找到视觉上相似的商品，即使商品描述使用了不同的词语。如果顾客上传带有文字描述的图像，系统会通过同一 embedding 模型处理两种输入，以进行统一的相似度评分。系统还通过自动商品标注从图像中提取商品属性，支持超越人工分类的语义标签生成。

### 技术优势

统一架构相比独立的文本与图像 embedding 有多项优势。单模型设计和共享语义空间解锁了管理多个 embedding 系统所无法实现的用例。应用使用相同的 API 端点和向量维度为所有内容类型生成 embedding。单个模型处理全部五种模态，因此相关内容（例如商品图片及其描述）会产生相似的 embedding。你可以计算文本、图像、音频和视频任意组合之间的距离，以衡量它们的相似程度。

Amazon Nova Multimodal Embeddings 模型使用 [Matryoshka representation learning](https://assets.amazon.science/de/d4/149300334682a464963f01553ffb/nova-mme-technical-report-10.pdf)，支持多种 embedding 维度：3072、1024、384 和 256。Matryoshka embedding learning 将最重要的信息存储在靠前的维度中，将较不关键的细节存储在靠后的维度中。你可以从末尾截断（如下图所示），在保持特定用例准确性的同时减少存储空间。

### 架构

构建此方法需要三个主要组件：embedding 生成、向量存储和相似度搜索。商品目录经过预处理，为所有内容类型生成 embedding。查询处理使用同一模型将用户输入转换为 embedding。相似度搜索将查询 embedding 与存储的商品 embedding 进行比较，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/29/ML-20065-image-6.png)

向量存储系统必须支持所选的 embedding 维度，并提供高效的相似度搜索操作。选项包括专用的向量数据库、带向量扩展的传统数据库，或以云为中心的向量服务，例如 [Amazon S3 Vectors](https://aws.amazon.com/s3/features/vectors/)，这是 [Amazon S3](https://aws.amazon.com/s3/) 的一项功能，可原生支持直接在 S3 中存储和查询向量 embedding。

### 前提条件

要有效使用此功能，此实现需要一些关键条件。需要一个拥有 Amazon Nova Multimodal Embeddings 模型 Amazon Bedrock 访问权限的 AWS 账户。所需的额外服务包括 [S3 Vectors](https://aws.amazon.com/s3/features/vectors/)。你可以按照我们 [Amazon Nova samples](https://github.com/aws-samples/amazon-nova-samples) 仓库中提供的 [notebook](https://github.com/aws-samples/amazon-nova-samples/blob/main/multimodal-embeddings/repeatable-patterns/visual-product-search-with-image-text-embeddings/product-multimodal-search-s3-vectors.ipynb) 进行操作。

### 实现

在以下各节中，我们跳过初始的数据下载和提取步骤，但完整端到端的方法可在该 notebook 中供你跟随操作。省略的步骤包括下载 Amazon Berkeley Objects (ABO) 数据集归档，其中包含商品元数据、目录图片和 3D 模型。这些归档需要解压和预处理，以便从压缩的 JSON 和 tar 文件中解析约 398,212 张图片和 9,232 条商品列表。提取后，数据需要在商品描述与其对应的视觉资产之间进行元数据对齐。我们在这些预备步骤完成后开始本次演练，聚焦于核心工作流：设置 S3 Vectors、使用 Amazon Nova Multimodal Embeddings 生成 embedding、大规模存储向量，以及实现跨模态检索。让我们开始吧。

**S3 Vector 桶与索引创建：**

为 embedding 创建向量存储基础设施。S3 Vectors 是一项托管服务，用于大规模存储和查询高维向量。桶充当向量数据的容器，而索引定义结构和搜索特征。我们将索引配置为余弦距离度量，它基于向量方向而非幅值来衡量相似度，因此非常适合来自 Amazon Nova Multimodal Embeddings 等服务所提供模型的归一化 embedding。

```
*# S3 Vectors configuration*
s3vector_bucket = "amzn-s3-demo-vector-bucket-crossmodal-search"
s3vector_index = "product"
embedding_dimension = 1024
s3vectors = boto3.client("s3vectors", region_name="us-east-1")
*# Create S3 vector bucket*
s3vectors.create_vector_bucket(vectorBucketName=s3vector_bucket)
*# Create index*
s3vectors.create_index(
    vectorBucketName=s3vector_bucket,
    indexName=s3vector_index,
    dataType='float32',
    dimension=embedding_dimension,
    distanceMetric='cosine'
)
```

**商品目录预处理：**

在这里我们生成 embedding。商品图片和文本描述都需要生成 embedding，并与适当的元数据一起存储以供检索。Amazon Nova Embeddings API 独立处理每种模态，将文本描述和商品图像转换为 1024 维向量。这些向量位于统一的语义空间中，这意味着同一商品的文本 embedding 和图像 embedding 在几何上会彼此接近。

```
# Initialize Nova Embeddings Client

class NovaEmbeddings:
    def __init__(self, region='us-east-1'):
        self.bedrock = boto3.client('bedrock-runtime', region_name=region)
        self.model_id = "amazon.nova-2-multimodal-embeddings-v1:0"

    def embed_text(self, text: str, dimension: int = 1024, purpose: str = "GENERIC_INDEX"):
        request_body = {
            "taskType": "SINGLE_EMBEDDING",
            "singleEmbeddingParams": {
                "embeddingDimension": dimension,
                "embeddingPurpose": purpose, 
                "text": {
                    "truncationMode": "END",
                    "value": text
                }
            }
        }
        response = self.bedrock.invoke_model(modelId=self.model_id, body=json.dumps(request_body))
        result = json.loads(response['body'].read())
        return result['embeddings'][0]['embedding']

    def embed_image(self, image_bytes: bytes, dimension: int = 1024, purpose: str = "GENERIC_INDEX"):
        request_body = {
            "taskType": "SINGLE_EMBEDDING",
            "singleEmbeddingParams": {
                "embeddingDimension": dimension,
                "embeddingPurpose": purpose,
                "image": {
                    "format": "jpeg",
                    "source": {"bytes": base64.b64encode(image_bytes).decode()}
                }
            }
        }
        response = self.bedrock.invoke_model(modelId=self.model_id, body=json.dumps(request_body))
        result = json.loads(response['body'].read())
        return result['embeddings'][0]['embedding']

embeddings = NovaEmbeddings()
```

我们使用以下代码生成 embedding 并将数据上传到向量存储。

```
# Generate embeddings and upload to Amazon S3 Vectors

def get_product_text(product):
    name = product.get('item_name', [{}])[0].get('value', '') if isinstance(product.get('item_name'), list) else str(product.get('item_name', ''))
    brand = product.get('brand', [{}])[0].get('value', '') if product.get('brand') else ''
    return f"{name}. {brand}".strip()

vectors_to_upload = []
batch_size = 10
catalog = []  # Keep for local reference

for product in tqdm(sampled_products, desc="Processing products"):
    img_path = get_image_path(product)
    text = get_product_text(product)
    product_id = product.get('item_id', str(len(catalog)))
    
    with open(img_path, 'rb') as f:
        img_bytes = f.read()
    
    # Generate embeddings
    text_emb = embeddings.embed_text(text)
    image_emb = embeddings.embed_image(img_bytes)
    
    # Store in catalog for local use
    catalog.append({
        'text': text,
        'image_path': str(img_path),
        'text_emb': text_emb,
        'image_emb': image_emb,
        'product_id': product_id
    })
    
    # Prepare vectors for S3 upload
    vectors_to_upload.extend([
        {
            "key": f"text-{product_id}",
            "data": {"float32": text_emb},
            "metadata": {"product_id": product_id, "text": text, "image_path": str(img_path), "type": "text"}
        },
        {
            "key": f"image-{product_id}",
            "data": {"float32": image_emb},
            "metadata": {"product_id": product_id, "text": text, "image_path": str(img_path), "type": "image"}
        },
        {
            "key": f"combined-{product_id}",
            "data": {"float32": np.mean([text_emb, image_emb], axis=0).tolist()},
            "metadata": {"product_id": product_id, "text": text, "image_path": str(img_path), "type": "combined"}
        }
    ])
    
    # Batch upload
    if len(vectors_to_upload) >= batch_size * 3:
        s3vectors.put_vectors(vectorBucketName=s3vector_bucket, indexName=s3vector_index, vectors=vectors_to_upload)
        vectors_to_upload = []

# Upload remaining vectors
if vectors_to_upload:
    s3vectors.put_vectors(vectorBucketName=s3vector_bucket, indexName=s3vector_index, vectors=vectors_to_upload)
```

**查询处理：**

这段代码通过 API 处理客户输入。文本查询、图像上传或两者的组合都会转换为与商品目录相同的向量格式。对于结合文本和图像的多模态查询，我们采用均值融合来创建一个单一的查询向量，捕捉来自两种模态的信息。查询处理逻辑处理三种不同的输入类型，并为针对 S3 Vectors 索引的相似度搜索准备适当的 embedding 表示。

```
def search_s3(query=None, query_image=None, query_type='text', search_mode='combined', top_k=5):
    """
    Search using S3 Vectors
    query_type: 'text', 'image', or 'both'
    search_mode: 'text', 'image', or 'combined'
    """
    # Get query embedding
    if query_type == 'both':
        text_emb = embeddings.embed_text(query)
        with open(query_image, 'rb') as f:
            image_emb = embeddings.embed_image(f.read())
        query_emb = np.mean([text_emb, image_emb], axis=0).tolist()
        query_image_path = query_image
    elif query_type == 'text':
        query_emb = embeddings.embed_text(query)
        query_image_path = None
    else:
        with open(query_image, 'rb') as f:
            query_emb = embeddings.embed_image(f.read())
        query_image_path = query_image
```

**向量相似度搜索：**

接下来，我们使用 S3 Vectors 查询 API 添加跨模态检索。系统会找到与查询最接近的 embedding 匹配，无论查询是文本还是图像。我们使用余弦相似度作为距离度量，它衡量向量之间的夹角而非绝对距离。这种方法很适合归一化 embedding，且资源效率高，与近似最近邻算法配合时适用于大型目录。S3 Vectors 负责索引和搜索基础设施，因此你可以专注于应用逻辑，而由该服务管理可扩展性和性能优化。

```
# Query S3 Vectors
    response = s3vectors.query_vectors(
        vectorBucketName=s3vector_bucket,
        indexName=s3vector_index,
        queryVector={"float32": query_emb},
        topK=top_k,
        returnDistance=True,
        returnMetadata=True,
        filter={"metadata.type": {"equals": search_mode}}
    )
```

**结果排序：**

S3 Vectors 计算出的相似度分数提供了排序机制。查询与目录 embedding 之间的余弦相似度决定了结果顺序，分数越高表示匹配越好。在生产系统中，你通常会收集点击数据和相关性判断，以验证排序是否与实际用户行为相关。S3 Vectors 返回距离值，我们将其转换为相似度分数（1 – 距离），以便于直观理解，数值越高表示匹配越接近。

```
# Extract and rank results by similarity
    ranked_results = []
    for result in response['vectors']:
        metadata = result['metadata']
        distance = result.get('distance', 0)
        similarity = 1 - distance  # Convert distance to similarity score
        
        ranked_results.append({
            'product_id': metadata['product_id'],
            'text': metadata['text'],
            'image_path': metadata['image_path'],
            'similarity': similarity,
            'distance': distance
        })
    
    # Results are sorted by S3 Vectors (best matches first)
    return ranked_results
```

## 结论

Amazon Nova Multimodal Embeddings 通过使用一个模型而非管理多个独立系统，解决了跨模态搜索的核心问题。你可以使用 Amazon Nova Multimodal Embeddings 构建这样的搜索：无论顾客上传图像、以文本输入描述，还是两种方式结合，都能正常工作。

使用 Amazon Bedrock API 实现起来非常直接，而且 [Matryoshka embedding dimensions](https://assets.amazon.science/de/d4/149300334682a464963f01553ffb/nova-mme-technical-report-10.pdf) 让你可以针对特定的准确性和成本需求进行优化。如果你正在构建电商搜索、内容发现，或用户会与多种内容类型交互的应用，这种统一方法既能降低开发复杂度，也能减少运营开销。

Matryoshka representation learning 在不同维度上保持 embedding 质量 [2]。性能下降遵循可预测的模式，使应用能够针对特定用例进行优化。
