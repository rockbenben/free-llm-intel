# NVIDIA Nemotron 3.5 Super VL 现已在 Amazon SageMaker JumpStart 中提供

今天，我们宣布 Amazon SageMaker JumpStart 中提供 NVIDIA Nemotron 3.5 Super VL。您可以在 SageMaker Studio 中通过几个步骤或使用 SageMaker Python SDK 的几行代码来部署它。 Super VL 是 NVIDIA Nemotron 3.5 系列中的视觉语言模型 (VLM)。它接受图像、视频和文本作为输入并生成文本。

该模型将 120B 参数混合专家混合 (MoE) 语言主干与 12B 活动参数和 C-RADIO 视觉编码器配对。它支持高达 100 万个令牌的上下文长度，并包含支持推测性解码的内置多令牌预测 (MTP) 头。您可以根据请求配置推理。

NVIDIA 构建了 Super VL，用于文档智能、计算机使用代理的 GUI 理解、视频问答和多模式代理应用程序。 JumpStart 提供两种变体：NVFP4（通过量化感知蒸馏从 BF16 量化以优化推理）和 BF16 全精度参考权重。在这篇文章中，我们将介绍该模型的功能和 JumpStart 部署配置。然后，我们展示测量的推理性能并演示文本、图像和视频推理。

## 模型概述

Nemotron 3.5 Super VL 是一个 120B 参数模型，每个代币有 12B 个活动参数。它将混合语言主干与专用视觉编码器相结合。

- **语言骨干**：88 个层，交错 Mamba-2 和 MoE 层（512 个路由专家，每个令牌 22 个活动专家），带有 8 个注意力层，加上共享的 MTP 头。主干从 Nemotron 3 Super Base 初始化，并从 Nemotron 3 Ultra Base 蒸馏而来。
- **视觉编码器**：C-RADIO 视觉编码器对图像和采样视频帧进行编码，视觉语言连接器将它们映射到语言主干的嵌入空间中。两种型号的编码器和连接器均采用 BF16。
- **训练**：模型首先经过持续的预训练、长上下文和软件工程中期训练以及视觉语言训练。然后，它对视觉、推理、代码、工具、聊天、安全和长上下文数据进行两阶段多模式监督微调 (SFT)。接下来是强化学习 (RL)，在 NeMo RL 和 NeMo Gym 中提供可验证的奖励和人类反馈，多教师的策略蒸馏，以及进一步训练 MTP 头部的最后阶段。 NVFP4 检查点是使用 NVIDIA 模型优化器和量化感知蒸馏从 BF16 生成的。它保留了 BF16 中的视觉编码器、连接器、Mamba 卷积和嵌入，以及 FP32 中的 MoE 路由器。它在 Blackwell GPU 上以 4 位权重和激活 (W4A4) 运行。

## 关键用例

Super VL 针对的是必须查看和阅读的代理工作负载。它针对的是结合了推理、编码、工具使用、文档理解和视频理解的视觉语言代理。

- **文档智能**：光学字符识别 (OCR)、图表、表格和多页文档。每个 1,536 x 1,024 页面图像大约需要 1,536 个上下文标记。 JumpStart 服务配置接受每个请求一张图像和一个视频。
- **GUI理解**：导航应用程序的计算机使用代理的屏幕基础和推理。
- **视频理解**：分析和总结 MP4 视频短片，包括回答有关视觉内容的问题。您可以提供内嵌视频作为 Base64 编码内容，但须遵守端点的请求负载大小限制。
- **多模式代理**：工具调用、通过“response_format”的 JSON 模式输出以及可配置推理支持多模式代理工作流程。
- **定制 (BF16)**：下载用于 SFT、RL、蒸馏、域适应或创建您自己的量化变体的 BF16 参考权重。 JumpStart 端点仅提供基本权重，不加载 LoRA 适配器。

## 模型质量基准

NVIDIA 模型卡报告推理、编码、代理、长上下文和多模式基准测试中两个检查点的结果，评估设置保持不变，因此只有检查点有所不同。下表重点介绍了与视觉语言工作负载（推理）最相关的多模式基准。

| **基准** | **能力** | **BF16** | **NVFP4** |
| --- | --- | --- | --- |
| MMLongBench-文档 |长文档多模式理解 | 62.82 | 62.82 |
| OCRBench v2，EN | OCR 和文档理解 | 68.12 | 68.34 |
| CharXiv 推理 |图表和图形推理 | 80.82 | 79.88 |
|视频-MME v2 |视频理解 | 32.85 | 32.85 32.54 | 32.54
| OSWorld 验证 |视觉计算机的使用和代理任务| 51.14 | 51.14 52.30 | 52.30

NVFP4（JumpStart 默认值）在 MMLongBench-Doc 上与 BF16 相匹配，并且与其他选项的差距约为 1 分，在 OCRBench v2 和 OSWorld-Verified 上的得分略高。如需与其他公开型号和评估设置的完整比较，请参阅 [NVIDIA Nemotron 3.5 Super VL 和 Lightning 技术报告](https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3.5-Super-and-Lightning-Technical-Report.pdf)。

## SageMaker JumpStart 上的推理性能

我们使用生成工作负载配置文件测量了 JumpStart 发布容器的推理性能：250 个输入令牌、1,500 个输出令牌和 5 个并发流请求。吞吐量是每个请求每秒的平均输出令牌，第一个令牌的时间是跨请求的平均值。

| **实例类型** | **变体** | **每个请求的输出吞吐量（平均值）** | **第一个令牌的时间（平均值）** |
| --- | --- | --- | --- |
| ml.g7.24xlarge | NVFP4 | 63.07 令牌/秒 | 0.45 秒 |
| ml.g7.48xlarge | NVFP4 | 64.01 令牌/秒 | 0.51 秒 |
| ml.p5en.48xlarge | BF16 | 140.85 个令牌/秒 | 0.53 秒 |

这些结果说明了可通过 JumpStart 进行的部署选择。 NVFP4 变体在 GPU 占用空间较小的 G7 实例上运行。在此测试中，ml.p5en.48xlarge 上的 BF16 变体实现了每个请求每秒 140.85 个输出令牌。在所有三种配置中，第一个令牌的时间保持在半秒左右。由于这些变体在不同的 GPU 系统和配置上运行，因此这些测量结果并不是孤立的“BF16 与 NVFP4”精度比较。较长的提示会改变情况：使用摘要配置文件（10,000 个输入令牌），ml.g7.24xlarge 上第一个令牌的时间为 12.62 秒。

## 使用 SageMaker JumpStart 部署 Nemotron 3.5 Super VL

您可以使用 SageMaker Python SDK 从 SageMaker Studio 或从 Hugging Face 模型页面部署模型。

### 先决条件

在部署之前，请确保您具备以下条件：

- 有权创建 Amazon SageMaker AI 终端节点的 AWS 账户。
- 有权访问 SageMaker AI 的 AWS Identity and Access Management (IAM) 角色。
- ml.g7.24xlarge、ml.g7.48xlarge 或 ml.p5en.48xlarge 端点使用的服务配额。新帐户中的 ml.g7 配额从零开始，因此在部署之前通过服务配额请求增加配额。

### 使用 SageMaker Python SDK 进行部署
```
# Install the SageMaker Python SDK v3: pip install "sagemaker>=3.25"
from sagemaker.core.helper.session_helper import get_execution_role
from sagemaker.core.jumpstart.configs import JumpStartConfig
from sagemaker.core.training.configs import Compute
from sagemaker.serve import ModelBuilder

# BF16 variant: model_id "huggingface-vlm-nvidia-nemotron-3-5-super-vl-120b-a12b-bf16" on ml.p5en.48xlarge.
jumpstart_config = JumpStartConfig(
    model_id="huggingface-vlm-nvidia-nemotron-3-5-super-vl-120b-a12b-nvfp4",
    inference_config_name="modify_best_price_performance",
)
model_builder = ModelBuilder.from_jumpstart_config(
    jumpstart_config=jumpstart_config,
    role_arn=get_execution_role(),
    compute=Compute(instance_type="ml.g7.24xlarge", instance_count=1),
)
model_builder.build()
endpoint = model_builder.deploy(endpoint_name="nemotron-3-5-super-vl")
```
该示例使用 SageMaker Python SDK v3 类：“JumpStartConfig”命名模型，“ModelBuilder”构建并部署模型，“deploy”返回“Endpoint”资源。在“Compute”中传递实例类型，因为当实例类型不存在时，SDK 会回退到 ml.m5.large，然后构建会失败。部署调用将等待端点处于 InService 状态，这在 ml.g7.24xlarge 上大约需要 10 分钟。

`inference_config_name` 参数选择一个服务配置，每个配置设置不同的上下文长度。默认生成配置提供 2,275 个令牌的上下文，大小适合简短提示。摘要配置提供 13,650 个令牌，修改配置提供 15,600 个令牌。该示例使用修改配置，因为本文中的推理示例，尤其是图像、视频和推理请求，需要更大的上下文。以下所有推理示例均假设修改配置。

## 运行推理

JumpStart 端点公开了由 vLLM 支持的聊天完成 API，因此应用程序可以使用熟悉的聊天消息格式发送推理请求。 NVIDIA 建议对于文本请求使用温度 1.0 和 `top_p` 0.95，对于图像和视频请求使用温度 0.6 和 `top_p` 0.95。您必须以 Base64 数据 URL 的形式内联发送媒体，因为端点在网络隔离下运行并且无法获取 URL。

### 文字，带有推理

默认情况下推理处于启用状态，您可以根据请求进行配置。推理文本在消息的推理字段中返回，与内容分开。
```
import json

payload = {
    "messages": [{"role": "user", "content":
        "Explain the difference between OCR and document understanding."}],
    "max_tokens": 2000,
    "temperature": 1.0,
    "top_p": 0.95,
}
response = endpoint.invoke(
    body=json.dumps(payload), content_type="application/json", accept="application/json"
)
result = json.loads(response.body.read())
print(result["choices"][0]["message"]["reasoning"])
print(result["choices"][0]["message"]["content"])
```
### 图片，推理关闭

对于直接提取式任务，您可以使用“chat_template_kwargs”中的“enable_thinking=False”禁用推理。
```
import base64

with open("invoice.png", "rb") as f:
    image_b64 = base64.b64encode(f.read()).decode("utf-8")

payload = {
    "messages": [{
        "role": "user",
        "content": [
            {"type": "image_url",
             "image_url": {"url": f"data:image/png;base64,{image_b64}"}},
            {"type": "text",
             "text": "Extract the vendor, date, and total as JSON."},
        ],
    }],
    "max_tokens": 1024,
    "temperature": 0.6,
    "top_p": 0.95,
    "chat_template_kwargs": {"enable_thinking": False},
}
response = endpoint.invoke(
    body=json.dumps(payload), content_type="application/json", accept="application/json"
)
result = json.loads(response.body.read())
print(result["choices"][0]["message"]["content"])
```
该模型接受图像而不是原始 PDF 文件。要处理 PDF，请先将每个页面渲染为图像（例如 PNG），然后再将其发送到模型。一个 1,536 x 1,024 的页面大约需要 1,536 个上下文令牌，一个请求可以携带一张图像。

### 视频

以下示例将一个简短的 MP4 剪辑作为 Base64 编码的数据 URL 发送，并要求模型对其进行总结，并禁用直接响应的推理。
```
import base64

with open("demo.mp4", "rb") as f:
    video_b64 = base64.b64encode(f.read()).decode("utf-8")

payload = {
    "messages": [{
        "role": "user",
        "content": [
            {"type": "video_url",
             "video_url": {"url": f"data:video/mp4;base64,{video_b64}"}},
            {"type": "text", "text": "Summarize what happens in this video."},
        ],
    }],
    "max_tokens": 2000,
    "temperature": 0.6,
    "top_p": 0.95,
    "chat_template_kwargs": {"enable_thinking": False},
}
response = endpoint.invoke(
    body=json.dumps(payload), content_type="application/json", accept="application/json"
)
result = json.loads(response.body.read())
print(result["choices"][0]["message"]["content"])
```
对于视频推理，请使用简短的压缩剪辑，并将编码请求保持在端点支持的负载限制内。对于推理密集型视频请求，请将“max_tokens”设置得足够高，以允许模型完成推理，同时考虑响应长度和端点调用限制。

## 最佳实践

在 SageMaker JumpStart 上运行 Nemotron 3.5 Super VL 时请考虑以下建议：

- **媒体输入**：模型接受图像而不是原始 PDF 文件，因此首先将 PDF 页面渲染为图像。
- **视频配置**：帧采样在端点启动时设置，而不是根据请求设置。 JumpStart 端点使用 vLLM 默认采样并拒绝每个请求“media_io_kwargs”。
- **带有推理的视频**：对于启用推理的视频，将“max_tokens”设置为至少 8,192，或者当您想要直接响应时禁用推理。
- **上下文预算**：`max_tokens` 限制完成。提示和完成一起必须适合服务配置的模型长度：用于生成配置的 2,275 个令牌、用于交互的 520 个令牌、用于总结的 13,650 个令牌以及用于修改的 15,600 个令牌。图像和视频帧也会消耗上下文。
- **多页文档**：JumpStart 服务配置接受每个请求一张图像。每个请求发送一页，或将页面拼接到一张图像中，并检查上下文预算。
- **推理模式**：使用推理进行多步骤分析和代理任务。当您想要更短、直接的响应时，请禁用它进行提取或添加字幕。
- **采样**：按照 NVIDIA 的建议，从温度 1.0 和 `top_p` 0.95 开始，用于文本，温度 0.6 和 `top_p` 0.95 用于图像和视频。

## 清理

为了避免持续产生费用，请在完成后删除端点、端点配置和模型：
```
from sagemaker.core.resources import EndpointConfig, Model

endpoint_config = EndpointConfig.get(endpoint_config_name=endpoint.endpoint_config_name)
model_name = endpoint_config.production_variants[0].model_name
endpoint.delete()
endpoint_config.delete()
Model.get(model_name=model_name).delete()
```
