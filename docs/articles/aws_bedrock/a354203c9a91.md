# 微调 Amazon Nova 模型以实现准确的邮件数据提取

*作者们还要感谢 Karan Bhandarkar、Sue Cha、Yash Shah 与 Nieves Garcia 为使这项工作成为可能所做出的贡献。*

如果你每天要处理数百万封电子邮件，微调 Amazon Nova 模型可以帮助你实现准确的数据提取自动化，同时降低成本与幻觉。[Parcel Perform](https://www.parcelperform.com/) 是面向全球电商企业提供 AI 配送体验平台的领先厂商，它在从格式各异的邮件中提取结构化信息时，正面临这样的挑战——这些邮件从简单的通知，到含有大量 JavaScript 元素的复杂 HTML 文档不等。

常见的挑战包括模型幻觉、相似数据类型之间的混淆（例如订单号与物流单号），以及处理 HTML 格式邮件时高得难以承受的 token 成本。

在本文中，你将了解使用 Amazon SageMaker AI 微调 Amazon Nova 模型如何解决这些具体问题：让模型学会识别你精确的数据模式、区分相似的字段，并更高效地处理信息——在把成本降低 50% 的同时，实现最高 94.77% 的提取准确率。

## 合作背景

Parcel Perform 与 AWS Generative AI Innovation Center（GenAIIC）合作，后者在整个客户旅程中提供业务与技术咨询。团队从 Parcel Perform 的问题陈述出发反向推导，规划了一个通过多种定制技术与参数优化来优化 Nova 模型的项目。

这次合作使准确率、延迟与成本等多项指标得以同时改善。Parcel Perform 的 AI 团队负责人 Le Vy 表示，微调后的 Nova Micro 模型在测试数据集上达到了最高 94.77% 的提取准确率，相比基线提升多达 16.6 个百分点。与 Parcel Perform 此前的模型相比，微调后的 Nova Micro 把推理延迟降低了 30% 以上，并把成本减半，同时以更低的成本达到或超过微调后的 Nova Lite 模型。凭借这些结果，Parcel Perform 把该方案投入生产，以改进其电商物流运营。

## 方案概览

你可以使用 Amazon SageMaker AI 的自定义模型微调，让 Amazon Nova Lite 与 Amazon Nova Micro 模型适配电商邮件中的专用实体提取。本方案采用监督式微调（SFT），并通过低秩适配（LoRA）实现参数高效微调（PEFT）。借助 PEFT，你可以在有限的训练数据下有效地定制模型，同时保持计算效率。

你也可以用 PEFT 把模型部署到 Amazon Bedrock，并以按 token 计价的按需推理来调用它。Amazon Bedrock 提供灵活的部署选项：使用 PEFT 时，你可以通过[按需推理](https://docs.aws.amazon.com/bedrock/latest/userguide/deploy-custom-model-on-demand.html)部署；而全秩 SFT 既支持通过 [Amazon Bedrock 上的 Provisioned Throughput](https://docs.aws.amazon.com/bedrock/latest/userguide/prov-throughput.html)部署，也支持通过 [SageMaker AI 端点](https://docs.aws.amazon.com/sagemaker/latest/dg/deploy-model.html)部署。

自定义模型微调使用 [Amazon Nova recipes](https://docs.aws.amazon.com/nova/latest/nova2-userguide/nova-model-recipes.html)，这些 YAML 配置文件向 Amazon SageMaker AI 提供运行模型定制作业所需的细节，包括基础模型名称、训练超参数、优化设置以及其他选项。下图展示了该方案的架构。

![drawing](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/10/ML-20559-1.png)

工作流的运作方式如下：

- 以 Amazon Bedrock 对话格式准备训练数据，把邮件内容作为输入、提取出的实体作为输出。
- 把训练数据上传到 Amazon Simple Storage Service（Amazon S3）。
- 使用低秩适配（LoRA）配置在 SageMaker AI 中创建微调作业。
- 使用 Amazon Bedrock 的按需推理部署微调后的模型。
- 运行推理，从新邮件中提取实体。

## 前提条件

微调并部署 Nova 模型需要以下条件：

- **具备相应权限的 AWS 账户**：用于访问 AWS 服务并创建资源。
- **对 Amazon Bedrock 与 Amazon Nova 模型的访问权限**：所选 AWS 区域中必须已提供这些模型。
- **IAM 服务角色**：一个具备 Amazon Bedrock 模型定制权限的 AWS Identity and Access Management（IAM）角色。
- **S3 存储桶**：用于存储训练数据与输出产物。
- **JSONL 格式的训练数据**：请遵循数据格式与准备指南。
- **足够的 Service Quotas**：为你在 SageMaker AI Training 中选定的实例类型与规格建立足够的配额。

有关创建服务角色的说明，请参阅 [Create a service role for model customization](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-iam-role.html)。

## 准备训练数据

你的训练数据必须遵循 Amazon Bedrock 对话 schema 格式。每个样本包含作为用户输入的邮件内容，以及作为助手响应的提取出的实体。

下面是一个简化后的所需格式示例：

```
{
  "schemaVersion": "bedrock-conversation-2024",
  "system": [
    {
      "text": "You are an expert at extracting structured data from e-commerce order emails. Extract all relevant fields accurately without fabricating any information."
    }
  ],
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "text": "<email_content>Your order #12345 has shipped! Track your package: TRK789456123</email_content>"
        }
      ]
    },
    {
      "role": "assistant",
      "content": [
        {
          "text": "{\"order_number\": \"12345\", \"tracking_number\": \"TRK789456123\", \"status\": \"shipped\"}"
        }
      ]
    }
  ]
}
```

在我们的实验中，我们准备了两套训练数据集：一套较小的含 1,300 个样本，一套较大的含 4,900 个样本。这让我们得以评估训练数据规模对模型性能的影响。

你可以把 Amazon SageMaker Studio 作为开发环境，在数据准备这一步运行 Jupyter Notebook。

## 把训练数据上传到 S3 存储桶

SageMaker AI Training 在与你的代码和数据开发环境相互独立的运行环境中执行作业。借助 SageMaker AI Training，你可以高效地使用一个或多个强大的 GPU 实例，它们在训练结束后会自动停止。由于这些实例与你的数据准备环境相互独立，你需要把数据上传到一个集中位置：Amazon S3。

以下代码演示如何把数据从 SageMaker Studio 上传到 S3 存储桶：

```
import boto3

s3 = boto3.client('s3')
s3.upload_file('train.jsonl', 'your-training-bucket', 'train.jsonl')
```

## 微调 Amazon Nova 模型

训练数据准备好之后，你可以通过 SageMaker SDK 使用 Amazon SageMaker AI API 创建微调作业。请遵循 [Amazon Nova Customization Hub](https://github.com/aws-samples/amazon-nova-samples/tree/main/customization) 中的示例。这会借助 Amazon SageMaker AI Training 预置一个训练作业，在容器中运行于一个或多个你选定类型与规格的独立实例上。

下表汇总了我们实验中的关键微调参数：

| **参数** | **描述** |
| --- | --- |
| model_type | “amazon.nova-lite-v1:0:300k” 或 “amazon.nova-micro-v1:0:128k” |
| model_name_or_path | “nova-lite/prod” 或 “nova-micro/prod” |
| replicas | g5/g6 为 1，p5 为 4 |
| max_length | g5/g6 为 8192，p5 为 32768 |
| global_batch_size | 64 |
| max_epochs | 2 |
| peft_scheme | lora |
| loraplus_lr_ratio | 8.0 |
| alpha | 32 |

我们选择 Nova Lite 与 Nova Micro，是因为与 Amazon Nova Pro 及其他模型相比，它们成本更低且性能具有竞争力。

## 部署并运行推理

当你的微调作业成功完成后，你可以在 Amazon Bedrock 中创建一个自定义模型，以导入由 Amazon SageMaker AI 训练出的 PEFT 微调 Nova 模型。详细步骤请遵循 [Create a custom model](https://docs.aws.amazon.com/bedrock/latest/userguide/create-custom-model-sdks.html)。然后你就可以用该自定义模型运行推理，如下例所示：

```
import boto3
import json

bedrock_runtime = boto3.client(service_name="bedrock-runtime")

def extract_entities(email_content, provisioned_model_arn):
    body = {
        "messages": [{
            "role": "user",
            "content": f"Extract all relevant data fields from this email:\n\n{email_content}"
        }],
        "max_tokens": 2048,
        "temperature": 0.1
    }

    response = bedrock_runtime.invoke_model(
        body=json.dumps(body),
        modelId=provisioned_model_arn,
        accept="application/json",
        contentType="application/json"
    )

    response_body = json.loads(response.get('body').read())
    return response_body['output']['message']['content'][0]['text']

# Example usage
email = """
Dear Customer,
Your order has been shipped!
Carrier: FedEx
Estimated Delivery: January 15, 2025
"""

result = extract_entities(email, "arn:aws:bedrock:us-east-1:${account-id}:provisioned-model/your-model-id")
```

该函数返回的提取字段类似如下：

```
{
  Carrier: FedEx,
  Date: January 15, 2025
}
```

你也可以选择用另一种方法对模型进行迭代训练。例如，你可以把 SFT-PEFT 调优得到的检查点作为后续 Direct Preference Optimization（DPO）训练的基础。请参阅[迭代训练文档](https://docs.aws.amazon.com/sagemaker/latest/dg/nova-iterative-training.html)。

## 评估结果

微调后的模型在基线上把准确率提升了 5.6–16.6 个百分点，其中 Nova Micro 尽管是较小的模型，却取得了最高的整体准确率 94.77%。微调还把推理延迟降低了约 32%，并且相比按使用量计价的现有模型，通过对更轻量模型做 PEFT 调优把成本削减了约 50%。准确率、速度与成本上的这些综合收益，使 Parcel Perform 得以把调优后的 Amazon Nova 模型部署到生产环境。

### 准确率对比

Parcel Perform 使用其加权准确率指标，把微调后的模型与基线模型做了对比评估，该指标综合了各个数据字段的提取准确率。我们在两个具有代表性的数据集上进行了测试，分别包含 100 个与 200 个样本。

**关键发现：**

微调在所有这些模型上都带来了准确率提升，相比各自的基线版本提高了 5.6 到 16.6 个百分点。Nova Micro 的跃升最大，微调后从 76.63% 攀升到 93.27%。把训练数据从 1,300 个样本扩展到 4,900 个样本，又把性能进一步提升了最多 3.3%，说明训练量的适度增加仍能带来可观的回报。尽管是较小的模型，Nova Micro 在 200 个样本的测试集上仍取得了最高的整体准确率 94.77%。一个调优良好的紧凑模型，在领域特定任务上可以胜过更大的替代方案。

### 延迟改善

微调还显著降低了推理延迟：Nova Lite 降低了 31%，Nova Micro 降低了 32%，这是因为与 Parcel Perform 此前的模型相比，Nova Micro 的模型体量更小、参数更少。这相当于每次推理约 7.7 秒，使每天处理大量邮件变得更快。

### 影响

与 Parcel Perform 此前的模型相比，处理时间显著缩短。成本降低约 50%，因为 PEFT 让更轻量的模型在特定任务上表现更好，同时支持按使用量计价的部署方式。提升后的准确率，加上更低的成本与延迟，使 Parcel Perform 能够把微调后的 Amazon Nova 模型用于生产。

## 结语

在本文中，我们演示了如何使用 Amazon SageMaker AI 微调 Amazon Nova 模型，以从电商邮件中准确提取实体。我们与 Parcel Perform 的合作表明，使用 LoRA 的参数高效微调可以带来显著的准确率提升，同时把推理延迟降低 30% 以上。

**本次合作的关键收获：**

微调被证明能有效减少幻觉。模型能够正确区分订单号与物流单号，而不会编造源材料中并不存在的数据。你不需要海量数据集就能看到真实效果：仅用 1,300 个训练样本、覆盖 25 个实体，就取得了可观的准确率提升，这使得即使标注数据有限的团队也能把微调作为一种可行选项。一个反直觉的发现是，较小的 Nova Micro 模型在微调后超过了更大的 Nova Lite，说明针对任务的优化足以补偿基础模型规模上的差异。这有成本上的含义：把 Nova Micro 这样更小更快的模型与更低的推理延迟相结合，为规模化处理大量邮件提供了高性价比的方案。能够把 PEFT 微调后的模型直接部署到 Amazon Bedrock 并按 token 的按需方式计价，意味着你可以按使用量运行一个完全定制的模型，无需预置和维护专用的 LLM 托管基础设施。

### 开始使用

要实施这一方案，请先按前文的格式准备训练数据。如本文所示，从至少 1,300 个样本的数据集开始，就能得到有意义的结果。要获得最佳效果，请确保你的训练数据覆盖你在生产环境中会遇到的各种邮件格式。

如果你面临类似的实体提取挑战，可以使用 SageMaker AI 的模型定制来构建准确、可用于生产的方案。这一方法展示了如何把 Nova Micro 与 Nova Lite 这类快速且高性价比的模型，适配到兼顾准确、速度与成本效益的生产用例中。
