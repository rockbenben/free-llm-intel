# 在 AWS 上构建基于 Amazon Bedrock 的数字借贷方案

数字借贷是银行和金融机构的关键业务赋能手段。客户在完成了解你的客户（KYC）流程后在线申请贷款。典型的数字借贷流程涉及多种活动，例如用户引导（包括通过 KYC 验证用户的步骤）、信用核验、风险核验、信贷承保和贷款批准。目前，其中一些活动仍靠人工完成，导致贷款批准延迟并影响客户体验。

在印度，KYC 验证通常包括通过印度公民的身份证明文件（如 PAN 卡或 Aadhar 卡）进行身份验证、地址验证和收入验证。印度的信用核查通常使用客户的 PAN 号码完成。应对这些挑战的理想方式是在可能范围内将它们自动化。

数字借贷方案主要需要编排一系列步骤，并需要自然语言理解、图像分析、实时信用核查和通知等其他能力。你可以使用 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 围绕这些能力无缝构建自动化。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项完全托管的服务，通过单一 API 提供来自 AI21 Labs、Anthropic、Cohere、Meta、Mistral AI、Stability AI 和 Amazon 等领先 AI 公司的高性能基础模型（FM）供选择，并提供构建生成式 AI 应用所需的一整套能力，兼顾安全性、隐私和负责任 AI。借助 Amazon Bedrock Agents，你可以用自然语言指令编排多步骤流程并集成企业数据。

在本文中，我们提出一个使用 [DigitalDhan](https://github.com/aws-samples/DigiDhan-GenAI-FSI-LendingSolution-India/blob/main/README.md) 的方案，这是一个基于生成式 AI 的方案，用于自动化客户引导和数字借贷。该方案使用 Amazon Bedrock Agents 来自动化与 KYC 验证、信用与风险评估以及通知相关的服务。金融机构可以使用该方案来帮助实现客户引导、KYC 验证、信用决策、信贷承保和通知流程的自动化。本文演示如何利用基于 Amazon Bedrock Agents 的复杂业务流程自动化来获得竞争优势。

## 为什么生成式 AI 最适合支持客户旅程的助手

使用基于规则导航或基于自然语言处理（NLP）引导的传统 AI 助手，在处理复杂人类对话的细微之处时力不从心。例如，在真实的客户对话中，客户可能提供不充分的信息（例如缺少文件）、提出不属于预定义流程的随机或不相关问题（例如在验证身份证件时询问贷款提前还款选项），或使用自然语言输入（例如混用各种货币写法，把两万表示为“20K”、“20000”或“20,000”）。此外，基于规则的助手不提供额外的推理和解释（例如贷款为何被拒）。一些僵化、线性的流程规则要么迫使客户重新开始整个流程，要么需要人工协助。

[生成式 AI](https://aws.amazon.com/generative-ai/) 助手擅长处理这些挑战。有了精心编写的指令和 prompt，基于生成式 AI 的助手可以主动询问缺失细节、以类人的语言对话，并在需要时解释其行动的推理过程，同时优雅地处理错误。你可以加入防护栏（guardrails），确保这些助手不偏离主题，并提供能应对真实世界复杂性的灵活导航选项。具备上下文感知能力的助手还能灵活回应各种偏离流程的客户提问，从而提升客户参与度。

## 方案概览

DigitalDhan 是本文提出的数字借贷方案，由 Amazon Bedrock Agents 驱动。他们开发了一个方案，完全自动化客户引导、KYC 验证和信贷承保流程。DigitalDhan 服务提供以下功能：

- 客户可以通过该方案了解分步的贷款流程以及所需文件
- 客户可以上传 PAN 和 Aadhar 等 KYC 文件，DigitalDhan 通过自动化工作流进行验证
- DigitalDhan 完全自动化信贷承保和贷款申请流程
- DigitalDhan 通过电子邮件向客户通知贷款申请情况

我们按照贴近真实场景的方式对数字借贷流程进行建模。DigitalDhan 方案的高层步骤如下图所示。

[![数字借贷流程](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/09/ML-17498-Fig1.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/09/ML-17498-Fig1.png)

关键业务流程步骤如下：

- 贷款申请人通过访问 DigitalDhan 方案来启动贷款申请流程。
- 贷款申请人开始贷款申请旅程。贷款申请的示例 prompt 包括：  “申请贷款的流程是什么？”“我想申请贷款。”“我叫 Adarsh Kumar。PAN 是 ABCD1234，邮箱是 john_doe@example.org。我需要一笔 150000 的贷款。”申请人上传其 PAN 卡。申请人上传其 Aadhar 卡。
- DigitalDhan 处理每一条自然语言 prompt。作为文件验证流程的一部分，该方案从上传的 PAN 和 Aadhar 卡中提取关键信息，例如姓名、地址、出生日期等。随后该方案使用 PAN 判断用户是否为现有客户。  如果用户是现有客户，方案获取该客户的内部风险评分。如果用户是新客户，方案根据 PAN 详情获取信用评分。
- 对于现有客户，方案使用内部风险评分来核查信用状况。
- 对于新客户，方案使用外部信用评分来核查信用状况。
- 信贷承保流程包括基于信用评分和风险评分做出信用决策，并为获批客户计算最终贷款金额。
- 贷款申请详情连同决策结果通过电子邮件发送给客户。

## 技术方案架构

该方案主要使用 Amazon Bedrock Agents（编排多步骤流程）、[Amazon Textract](https://aws.amazon.com/textract/)（从 PAN 和 Aadhar 卡中提取数据）以及 [Amazon Comprehend](https://aws.amazon.com/comprehend/)（从 PAN 和 Aadhar 卡中识别实体）。方案架构如下图所示。

![Digital Dhan 方案的技术方案架构](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/09/ML-17498-Fig2.png)

DigitalDhan 方案架构的关键组件包括：

- 用户通过 DigitalDhan 应用开始引导流程。作为 KYC 的一部分，他们提供各种文件（包括 PAN 和 Aadhar）以及一个贷款金额
- 文件上传后，会使用各种人工智能与机器学习（AI/ML）服务自动处理。
- Amazon Textract 用于从上传的文件中提取文本信息。
- Amazon Comprehend 用于识别 PAN 和 Aadhar 等实体。
- 信贷承保流程由 Amazon Bedrock Agents 驱动。  知识库中包含与贷款相关的文档，用于回答贷款相关问题。贷款处理 [AWS Lambda](https://aws.amazon.com/lambda) 函数使用 KYC 文件中的信息来核查信用评分和内部风险评分。信用核查完成后，该函数计算贷款资格并处理贷款申请。通知 Lambda 函数通过电子邮件把贷款申请信息发送给客户。
- Lambda 函数可以集成外部信用 API。
- [Amazon Simple Email Service](https://aws.amazon.com/ses)（Amazon SES）用于向客户通知其贷款申请的状态。
- 事件使用 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 记录日志。

## Amazon Bedrock Agents 深入解析

由于我们在 DigitalDhan 方案中大量使用了 Amazon Bedrock Agents，下面来看 Amazon Bedrock Agents 的整体运作方式。Amazon Bedrock Agents 各组件之间的流转如下图所示。

![Amazon Bedrock Agents 流程](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/09/ML-17498-Fig3.png)

Amazon Bedrock agent 会把每个任务拆分为子任务，确定正确的执行顺序，并执行动作和知识库搜索。具体步骤如下：

- 处理贷款申请是 Amazon Bedrock agent 在 DigitalDhan 方案中执行的主要任务。
- Amazon Bedrock agent 使用用户 prompt、对话历史、知识库、指令和 action group 编排与贷款处理相关的步骤序列。Amazon Bedrock agent 接收自然语言 prompt 作为输入。以下是提供给该 agent 的指令：

```
You are DigitalDhan, an advanced AI lending assistant designed to provide personal loan-related information create loan application. Always ask for relevant information and avoid making assumptions. If you're unsure about something, clearly state "I don't have that information."

Always greet the user by saying the following: Hi there! I am DigitalDhan bot. I can help you with loans over this chat. To apply for a loan, kindly provide your full name, PAN Number, email, and the loan amount."

When a user expresses interest in applying for a loan, follow these steps in order, always ask the user for necessary details:

1. Determine user status: Identify if they're an existing or new customer.

2. User greeting (mandatory, do not skip): After determining user status, welcome returning users using the following format:

  Existing customer: Hi {customerName}, I see you are an existing customer. Please upload your PAN for KYC.

  New customer: Hi {customerName}, I see you are a new customer. Please upload your PAN and Aadhar for KYC.

3. Call Pan Verification step using the uploaded PAN document

4. Call Aadhaar Verification step using the uploaded Aadhaar document. Request the user to upload their Aadhaar card document for verification.

5. Loan application: Collect all necessary details to create the loan application.

6. If the loan is approved (email will be sent with details):

   For existing customers: If the loan officer approves the application, inform the user that their loan application has been approved using following format: Congratulations {customerName}, your loan is sanctioned. Based on your PAN {pan}, your risk score is {riskScore} and your overall credit score is {cibilScore}. I have created your loan and the application ID is {loanId}. The details have been sent to your email.

   For new customers: If the loan officer approves the application, inform the user that their loan application has been approved using following format: Congratulations {customerName}, your loan is sanctioned. Based on your PAN {pan} and {aadhar}, your risk score is {riskScore} and your overall credit score is {cibilScore}. I have created your loan and the application ID is {loanId}. The details have been sent to your email.

7. If the loan is rejected ( no emails sent):

   For new customers: If the loan officer rejects the application, inform the user that their loan application has been rejected using following format: Hello {customerName}, Based on your PAN {pan} and aadhar {aadhar}, your overall credit score is {cibilScore}. Because of the low credit score, unfortunately your loan application cannot be processed.

   For existing customers: If the loan officer rejects the application, inform the user that their loan application has been rejected using following format: Hello {customerName}, Based on your PAN {pan}, your overall credit score is {creditScore}. Because of the low credit score, unfortunately your loan application cannot be processed.

Remember to maintain a friendly, professional tone and prioritize the user's needs and concerns throughout the interaction. Be short and direct in your responses and avoid making assumptions unless specifically requested by the user.

Be short and prompt in responses, do not answer queries beyond the lending domain and respond saying you are a lending assistant
```

- 我们配置了 agent 的预处理与编排指令，以验证并按预定义顺序执行各步骤。在 agent 指令中指定的 few-shot 示例提升了 agent 表现的准确性。基于指令和 API 描述，Amazon Bedrock agent 会为完成某个动作创建逻辑步骤序列。在 DigitalDhan 示例中，指令的指定方式使得 Amazon Bedrock agent 创建如下序列：  向客户问候。收集客户的姓名、邮箱、PAN 和贷款金额。索要 PAN 卡和 Aadhar 卡以读取并验证 PAN 与 Aadhar 号码。基于验证后的 PAN 将客户归类为现有客户或新客户。对于现有客户，计算客户的内部风险评分。对于新客户，获取外部信用评分。使用内部风险评分（针对现有客户）或信用评分（针对外部客户）进行信贷承保。如果内部风险评分低于 300，或信用评分高于 700，则批准该贷款金额。把信用决策发送到客户的电子邮箱地址。
- Action group 定义了用于执行动作的 API，例如创建贷款、核查用户、获取风险评分等。我们在 OpenAPI schema 中描述了每一个 API，agent 据此选择最合适的 API 来执行动作。
- Lambda 与 action group 关联。以下代码是 `create_loan` API 的一个示例。Amazon Bedrock agent 在执行动作时会使用 `create_loan` API 的描述。该 API schema 还把 `customerName`、`address`、`loanAmt`、`PAN` 和 `riskScore` 指定为 API 的必需要素。因此，相应的 API 会在调用 `create_loan` API 之前读取客户的 PAN 号码（`verify_pan_card` API）、计算客户的风险评分（`fetch_risk_score` API），并识别客户的姓名和地址（`verify_aadhar_card` API）。

```
"/create_loan":
  post:
    summary: Create New Loan application
    description: Create new loan application for the customer. This API must be
      called for each new loan application request after calculating riskscore and
      creditScore
    operationId: createLoan
    requestBody:
      required: true
      content:
        application/json:
          schema:
            type: object
            properties:
              customerName:
                type: string
                description: Customer’s Name for creating the loan application
                minLength: 3
              loanAmt:
                type: string
                description: Preferred loan amount for the loan application
                minLength: 5
              pan:
                type: string
                description: Customer's PAN number for the loan application
                minLength: 10
              riskScore:
                type: string
                description: Risk Score of the customer
                minLength: 2
              creditScore:
                type: string
                description: Risk Score of the customer
                minLength: 3
            required:
            - customerName
            - address
            - loanAmt
            - pan
            - riskScore
            - creditScore
    responses:
      '200':
        description: Success
        content:
          application/json:
            schema:
              type: object
              properties:
                loanId:
                  type: string
                  description: Identifier for the created loan application
                status:
                  type: string
                  description: Status of the loan application creation process
```

- [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 为客户提供基于云的检索增强生成（RAG）体验。我们添加了与贷款处理相关的文档、通用信息、贷款信息指南以及知识库。我们指定了何时使用知识库的指令。因此，在客户旅程开始时，当客户处于探索阶段，他们能得到带操作指引的响应和一般贷款相关信息。例如，如果客户问“申请贷款的流程是什么？”，Amazon Bedrock agent 会从知识库中获取相关的分步详情。
- 所需步骤完成后，Amazon Bedrock agent 会整理给客户的最终响应。

## 部署方案

完成以下步骤即可部署该方案。更多详情请参阅 [GitHub 仓库](https://github.com/aws-samples/DigiDhan-GenAI-FSI-LendingSolution-India/blob/main/README.md)。

- 克隆仓库：  `git clone https://github.com/aws-samples/DigitalDhan-GenAI-FSI-LendingSolution-India.git`
- 进入代码示例的后端目录：  `cd DigitalDhan-GenAI-FSI-LendingSolution-India/`
- 安装依赖包：  `npm install npm install -g aws-cdk`
- 在 AWS 账户上引导（bootstrap）AWS CDK 资源。如果部署在 `us-east-1` 以外的任何 AWS 区域，堆栈可能因 Lambda 层依赖而失败。你可以注释掉该层并在其他区域部署，也可以部署在 `us-east-1`。  `cdk bootstrap aws://<ACCOUNT_ID>/<REGION>`
- 在模型可用于 Amazon Bedrock 服务之前，你必须显式启用对模型的访问。请按[访问 Amazon Bedrock 基础模型](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)中的步骤启用对模型（Anthropic::Claude (Sonnet) 和 Cohere::Embed English）的访问。
- 在你的账户中部署示例。以下命令将在你的账户中部署一个堆栈 `cdk deploy --all`
 为防范可能影响安全态势的意外变更，AWS CDK 会在部署前提示你批准与安全相关的变更。你需要回答 yes 才能完整部署该堆栈。

[AWS Identity and Access Management](https://aws.amazon.com/iam)（IAM）角色的创建在本示例中仅用于说明。始终应以最小必要权限来预置 IAM 角色。堆栈部署大约需要 10–15 分钟。堆栈成功部署后，你可以在堆栈的输出部分找到 `InsureAssistApiAlbDnsName`——这就是应用端点。

## 总结

本文讨论的数字借贷方案通过验证 KYC 文件（包括 PAN 和 Aadhar 卡）为客户完成引导，并把客户归类为现有客户或新客户。对于现有客户，方案使用内部风险评分；对于新客户，方案使用外部信用评分。

该方案使用 Amazon Bedrock Agents 编排数字借贷的处理步骤。文件先用 Amazon Textract 和 Amazon Comprehend 处理，之后由 Amazon Bedrock Agents 处理工作流步骤。客户识别、信用核查和客户通知通过 Lambda 实现。

该方案演示了如何借助 Amazon Bedrock Agents 自动化复杂业务流程，并通过自然语言界面和灵活的导航选项提升客户参与度。
