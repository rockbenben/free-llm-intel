# 在 Amazon Bedrock Knowledge Bases 上使用 GraphRAG 打击金融欺诈

金融欺诈检测不只是对银行重要——它至关重要。全球欺诈损失每年超过 [400 亿美元](https://www.paymentsdive.com/news/fraud-losses-realtime-payments-banks-aci-push-payment-scams/653219/)，加上犯罪网络不断演进其手法，金融机构面临着日益复杂的威胁格局。如今的欺诈手法跨多个账户、机构和渠道运作，编织出专门为规避检测系统而设计的错综网络。

金融机构已在检测能力上投入巨资，但核心挑战依然存在：如何在碎片化的信息版图中把点连起来——欺诈的证据并不存在于单个文档或交易之中，而存在于它们之间的关系里。

在本文中，我们展示如何使用 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) GraphRAG 配合 [Amazon Neptune Analytics](https://docs.aws.amazon.com/neptune-analytics/latest/userguide/what-is-neptune-analytics.html) 构建一套金融欺诈检测方案。

## 传统 RAG 系统的局限

近年来，检索增强生成（RAG）已成为构建以组织知识为基础的 AI 系统的一种有前景的方法。然而，传统基于 RAG 的系统在应对复杂的金融欺诈检测时存在局限。根本的局限在于传统 RAG 处理信息的方式。标准 RAG 把文档分块当作孤立的单元来检索与处理，寻找查询与单个文本片段之间的语义相似性。这种做法在直接的信息检索上表现良好，但在以下场景中严重不足：

- 证据分散在多个文档与系统之中
- 实体之间的连接比实体本身更重要
- 复杂的关系链路需要多跳推理
- 结构性上下文（例如文档的层级组织）提供了关键线索
- 跨不同指代的实体消解必不可少

欺诈分析师会凭直觉沿着关联路径追踪——把一个账户关联到一个电话号码，把该电话号码关联到另一位客户，再把该客户关联到某个已知的欺诈团伙。而传统 RAG 系统缺乏这种关系推理能力，导致复杂的欺诈网络在被发现之前损失就已经发生。

## 面向金融欺诈检测的 Amazon Bedrock Knowledge Bases 与 GraphRAG

[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) GraphRAG 帮助金融机构实施欺诈检测系统，而无需从头构建复杂的图基础设施。通过提供一项全托管服务，把知识图谱的构建、维护与查询与强大的基础模型（FM）无缝集成，[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 大幅降低了实施关系感知型欺诈检测的技术门槛。金融机构现在可以在图上下文中使用其现有的交易数据、客户画像与风险信号，既保留实体之间的关键关联，又能受益于 FM 的自然语言理解能力。这一强大组合让欺诈分析师可以用直观的自然语言查询复杂的金融关系，从而发现可能导致金融欺诈的可疑模式。

## 欺诈检测用例示例

为演示这一用例，我们使用一家位于澳大利亚的虚构银行（AnyCompany Bank），其客户在该行持有储蓄账户、支票账户与信用卡账户。这些客户使用借记卡与信用卡在全国各地的商户处交易购买商品与服务。AnyCompany Bank 希望利用 GraphRAG 与生成式 AI 技术的最新进展，检测欺诈行为中的细微模式，从而获得更高的准确率并减少误报。AnyCompany Bank 的一位欺诈分析师希望用自然语言查询来获得以下这类问题的答案：

- **基础查询** – 例如“把 ABC Electronics 处理的所有交易展示给我”或“Michael Green 拥有哪些账户？”
- **关系探索查询** – 例如“哪些设备访问过账户 A003？”或“展示 Jane Smith 与其设备之间的所有关系。”
- **时间模式检测查询** – 例如“哪些账户在同一天既有交易又有设备访问？”或“哪些账户的交易发生在惯常位置模式之外？”
- **欺诈检测查询** – 例如“找出与账户历史相比异常的交易金额”或“是否存在 24 小时内先有失败交易、随后又有成功交易的账户？”

## 先决条件

要跟随本文操作，请确保你拥有一个已激活的 AWS 账号，并具备访问 Amazon Bedrock 与创建 S3 桶作为数据源的相应权限。此外，请确认你已启用对 [Anthropic 的 Claude 3.5 Haiku](https://aws.amazon.com/bedrock/anthropic/?ams%23interactive-card-vertical%23pattern-data.filter=%257B%2522filters%2522%253A%255B%255D%257D) 与某个嵌入模型（例如 [Amazon Titan Text Embeddings V2](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html)）的访问权限。

## 将文档上传到 Amazon S3

在这一步，你创建一个 S3 桶作为数据源，并把六张表（accounts、individuals、devices、transactions、merchants 与 relationships）作为 Excel 数据表上传。下列截图展示了我们的 S3 桶及其内容。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18896-image-8.png)

## 创建知识库

完成以下步骤来创建知识库：

- 在 Amazon Bedrock 控制台的导航窗格中，选择 **Builder tools** 下的 **Knowledge Bases**。
- 选择 **Create** 与 **Knowledge Base with vector store**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18896-image-9.png)

- 在 **Knowledge Base details** 区块中提供以下信息：  为知识库输入一个有意义的名称。对于 **IAM permissions**，选择 **Create and use a new service role** 以创建新的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色。对于 **Choose data source**，选择 **Amazon S3**。选择 **Next**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18896-image-10.png)

- 在 **Configure data source **区块中提供以下信息：  输入数据源名称。对于 **Data source location**，选择你的数据源所在位置（例如我们选择 **This AWS account**）。对于 **S3 source**，选择 **Browse S3 **并选择你上传文件的位置。对于 **Parsing staretgy**，选择 **Amazon Bedrock default parser**。对于 **Chunking strategy**，选择 **Default chunking**。选择 **Next**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18896-image-11.png)

- 在 **Configure data storage and processing **区块中提供以下信息：  对于 **Embeddings model**，选择 **Titan Text Embeddings V2**。对于 **Vector store creation method**，选择 **Quick create a new vector store**。对于 **Vector store type**，选择 **Amazon Neptune Analytics (GraphRAG)**。选择 **Next**

Amazon Bedrock 会选择 Anthropic 的 Claude 3 Haiku v1 作为 FM，为我们的知识库自动构建图。这会自动启用上下文增强（contextual enrichment）。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18896-image-12.png)

- 选择 **Create knowledge base**。
- 当知识库处于 **Available** 状态时，选择该知识库。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18896-image-13.png)

- 选择数据源并选择 **Sync**，然后等待同步过程完成。

在同步过程中，Amazon Bedrock 从 Amazon S3 摄取数据文件、创建分块与嵌入，并自动抽取实体与关系，从而构建出图。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18896-image-14.png)

## 测试知识库并运行自然语言查询

- 在 **Test Knowledge Base** 区块中，选择 **Select model**。
- 将模型设为 Anthropic 的 Claude 3.5 Haiku（或你选择的其他模型），然后选择 **Apply**。

## 清理资源

为避免产生额外费用，请清理你创建的资源。这包括删除 Amazon Bedrock 知识库、其关联的 IAM 角色以及用于存放源文档的 S3 桶。此外，你还必须单独删除 Amazon Bedrock Knowledge Bases 在设置过程中自动创建的 Neptune Analytics 图。

## 结语

Amazon Bedrock 中的 GraphRAG 在打击金融欺诈的斗争中成为一项颠覆性的功能。通过自动串联交易数据、客户画像、历史模式与欺诈报告之间的关系，它显著提升了金融机构检测传统系统可能漏掉的复杂欺诈手法的能力。它跨多个文档与数据源理解并关联信息的独特能力，在调查跨越多个触点与时间段的复杂欺诈模式时价值无可估量。对金融机构与欺诈检测团队而言，GraphRAG 的智能文档处理意味着更快、更准确的欺诈调查。它能迅速把相关事件拼合起来、识别欺诈报告中的共性模式，并把看似无关的活动关联起来——这些活动可能指向有组织的欺诈团伙。这种更深层次的洞察，加上其提供全面、上下文感知回复的能力，让安全团队能够始终比不断演进手法的欺诈者领先一步。随着金融犯罪日益精密，Amazon Bedrock 中的 GraphRAG 成为欺诈预防的强大工具，改变了你分析、关联并处置欺诈相关信息的方式。欺诈检测的未来需要能够像人一样思考并建立关联的工具——而 GraphRAG 正引领这一方向成为现实。
