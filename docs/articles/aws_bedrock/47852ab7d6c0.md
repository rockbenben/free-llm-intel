# 借助知识图谱支撑的 LLM 搜索企业数据资产

由于管理海量数据的复杂性不断增加，企业在访问分散在各个来源中的数据资产时面临挑战。传统搜索方法往往无法提供全面且具有上下文相关性的结果，尤其是面对非结构化数据或复杂查询时。

现代大数据管理中的搜索方案必须能够高效、准确地搜索企业数据资产，并能适应新资产的到来。客户希望搜索组织内的所有数据和应用程序，并希望看到所有被检索文档的来源信息。应用需要搜索目录，并展示与搜索上下文相关的所有数据资产的元数据信息。为了实现这些目标，方案应包含以下特性：

- 在相关实体与数据源之间建立连接
- 整合包含元数据的分散数据编目系统
- 为搜索结果提供推理依据

本文将介绍一个由[生成式 AI](https://aws.amazon.com/generative-ai/) 驱动的语义搜索方案，让业务用户能够快速、准确地跨各类企业数据源找到相关的数据资产。在该方案中，我们集成托管在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的大语言模型（LLM），并由一个知识库提供支撑，该知识库源自构建在 [Amazon Neptune](https://aws.amazon.com/neptune/) 上的知识图谱，从而形成一种强大的搜索范式：用自然语言提问，即可综合搜索存储在 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）中的文档、托管在 [AWS Glue](https://aws.amazon.com/glue/) Data Catalog 上的数据湖表，以及 [Amazon DataZone](https://aws.amazon.com/datazone/) 中的企业资产。

Amazon Bedrock 上的基础模型（FM）为文本与语言任务提供了强大的生成模型。然而，FM 缺乏领域特定的知识与推理能力。Neptune 上可用的[知识图谱](https://aws.amazon.com/neptune/knowledge-graphs-on-aws/) 提供了一种手段，用推理与推断能力来表示领域内相互关联的事实与实体。用领域特定的知识图谱为 FM 装备结构化推理能力，可以兼取两种方式的优势。这使 FM 得以保留其归纳能力，同时把语言理解与生成建立在结构良好的领域知识与逻辑推理之上。在由 Amazon DataZone、AWS Glue 等服务的元数据目录以及其他第三方目录驱动的企业数据资产搜索场景中，知识图谱有助于整合这些关联数据，并支持一种可扩展的搜索范式，把随时间演进的元数据整合起来。

## 方案概述

该方案与你现有的数据目录和存储库集成，在整个数据版图上构建统一、可扩展的语义层。当用户用自然语言提问时，搜索不再只是匹配关键词；它会理解查询的意图与上下文，将其与组织中相关的表、文档和数据集关联起来。这种语义理解带来更准确、更具上下文相关性且更有洞察力的搜索结果，使整个公司的数据像使用消费级搜索引擎一样易于访问和搜索，同时具备你的业务所需的深度与精确度。通过释放数据资产的全部潜力，这显著提升了整个组织的决策水平、效率与创新能力。下面的视频展示了示例工作方案的运行情况。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/26/ML16564-blogvideo.gif)

借助图数据处理以及在嵌入式图上集成基于自然语言的搜索，这些混合系统能够从复杂的数据结构中挖掘出有力的洞察。

本文介绍的方案由一个摄取流水线和一个搜索应用 UI 组成，用户可以在这个 UI 中用自然语言提交查询来搜索数据资产。

下图展示了端到端架构，由元数据 API 层、摄取流水线、embedding 生成工作流和前端 UI 组成。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/26/ML16565-arch-new.jpg)

摄取流水线（3）把来自各项服务（2）——包括 Amazon DataZone、AWS Glue 和 [Amazon Athena](https://aws.amazon.com/athena)——的元数据（1），在把服务 API 返回的 JSON 响应转换为 RDF 三元组格式之后，摄取到 Neptune 数据库中。RDF 会被转换为文本并加载到 S3 桶中，[Amazon Bedrock](https://aws.amazon.com/bedrock)（4）将其作为知识库的来源访问。你还可以扩展该方案，把第三方编目方案的元数据也纳入进来。最终用户访问托管在 [Amazon CloudFront](https://aws.amazon.com/cloudfront/)（5）上的应用。

[AWS Step Functions](https://aws.amazon.com/step-functions/) 中的状态机通过调用 [AWS Lambda](https://aws.amazon.com/lambda/) 函数来定义摄取流程的工作流，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16564-img1-235x300.png)

这些函数执行以下操作：

- 以 JSON 格式从各项服务（Amazon DataZone、AWS Glue 和 Athena）读取元数据。通过添加上下文把 JSON 格式的元数据增强为 [JSON-LD](https://json-ld.org/) 格式，并以 RDF 三元组的形式把数据加载到 [Amazon Neptune Serverless](https://docs.aws.amazon.com/neptune/latest/userguide/neptune-serverless.html) 数据库中。下面是 N-triples 文件格式的 RDF 三元组示例：  `<arn:aws:glue:us-east-1:123456789012:table/default/market_sales_table#sales_qty_sold> <http://www.w3.org/2000/01/rdf-schema#label> "sales_qty_sold" . <arn:aws:glue:us-east-1:123456789012:table/sampleenv_pub_db/mkt_sls_table#disnt> <http://www.w3.org/2000/01/rdf-schema#label> "disnt" . <arn:aws:glue:us-east-1:123456789012:table/sampleenv_pub_db/mkt_sls_table> <http://www.amazonaws.com/datacatalog/hasColumn> <arn:aws:glue:us-east-1:123456789012:table/sampleenv_pub_db/mkt_sls_table#item_id> . <arn:aws:glue:us-east-1:123456789012:table/sampledata_pub_db/raw_customer> <http://www.w3.org/2000/01/rdf-schema#label> "raw_customer" .`  关于 RDF 数据格式的更多细节，请参阅 [W3C 文档](https://www.w3.org/RDF)。
- 在 Neptune 数据库中运行 [SPARQL 查询](https://www.w3.org/TR/sparql11-query/)，从推断规则中填充更多三元组。这一步利用图的推断与推理能力来丰富元数据。下面这条 SPARQL 查询插入由现有三元组推断出的新元数据：  `PREFIX xsd: <http://www.w3.org/2001/XMLSchema#> INSERT { ?asset <http://www.amazonaws.com/datacatalog/exists_in_aws_account> ?account } WHERE { ?asset <http://www.amazonaws.com/datacatalog/isTypeOf> "GlueTableAssetType" . ?asset <http://www.amazonaws.com/datacatalog/catalogId> ?account . }`
- 从 Neptune 数据库读取三元组，并使用托管在 Amazon Bedrock 上的 LLM 把它们转换为文本格式。该方案使用 Anthropic 的 Claude 3 Haiku v1 完成 RDF 到文本的转换，并把生成的文本文件存储在 S3 桶中。

[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 被配置为使用前面提到的 S3 桶作为数据源来创建知识库。Amazon Bedrock Knowledge Bases 使用 Amazon Titan Text Embeddings v2 模型从文本文件生成向量 embedding。

一个 [Streamlit](https://streamlit.io/) 应用作为任务托管在 [Amazon Elastic Container Service](https://aws.amazon.com/ecs/)（Amazon ECS）中，它提供聊天机器人 UI，供用户针对 Amazon Bedrock 中的知识库提交查询。

## 前置条件

部署该方案需要以下前置条件：

- 一个 [AWS 账户](https://console.aws.amazon.com)。
- 必须启用以下 LLM 模型。更多信息请参阅[添加或移除对 Amazon Bedrock 基础模型的访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access-modify.html)。  **Anthropic Claude Haiku 3.5** – 用于把三元组转换为文本。  **Anthropic Claude Sonnet 4.5** – 在应用中用于生成响应。  **Amazon Titan Text Embeddings v2** – 用于对文档做 embedding 并存入知识库。
- 一个具有运行 [AWS CloudFormation](https://aws.amazon.com/cloudformation) 权限的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）[role](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/using-iam-servicerole.html)
- 在 [Amazon Cognito](https://aws.amazon.com/cognito/) 中创建的一个[用户池](https://docs.aws.amazon.com/cognito/latest/developerguide/getting-started-with-identity-pools.html)。需要为该用户池创建一个[用户池应用客户端](https://docs.aws.amazon.com/cognito/latest/developerguide/user-pool-settings-client-apps.html)。在 **Cognito user pool sign-in options** 中选择 **User name**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16564-img2.png)

- 记录用户池 ID 和应用客户端 ID，在启动用于构建 Web 应用的 CloudFormation 堆栈时会用到。
- 为你的 Amazon Cognito 用户池创建一个 [Amazon Cognito 用户](https://docs.aws.amazon.com/cognito/latest/developerguide/how-to-create-user-accounts.html#creating-a-new-user-using-the-console)（例如 *username=test_user*），用于登录该应用。创建用户时必须填写电子邮件地址。

## 准备测试数据

测试该方案的功能需要一个示例数据集。在你的 AWS 账户中，按照 [Amazon DataZone QuickStart with AWS Glue data](https://docs.aws.amazon.com/datazone/latest/userguide/quickstart-glue.html) 完成 Step 1 到 Step 8，使用 Amazon DataZone 和 Athena 准备一张表。这会创建一张表，并在 Data Catalog 和 Amazon DataZone 中记录其元数据。

为了测试该方案如何合并来自不同数据目录的元数据，再创建一张只存在于 Data Catalog、不在 Amazon DataZone 中的表。在 Athena 控制台中打开查询编辑器，运行以下查询来创建新表：

```
CREATE TABLE raw_customer AS SELECT 203 AS cust_id, 'John Doe' AS cust_name
```

## 部署应用

完成以下步骤来部署应用：

- 要启动 CloudFormation 模板，请选择 **Launch Stack**，或下载模板文件（[yaml](https://aws-blogs-artifacts-public.s3.amazonaws.com/ML-16564/main.yaml)），并在你的 AWS 账户中[启动 CloudFormation 堆栈](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/cfn-console-create-stack.html)。
[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/10/16/LaunchStack.png)](https://us-east-1.console.aws.amazon.com/cloudformation/home?region=us-east-1#/stacks/create?stackName=mm-enterprise-search&templateURL=https://aws-blogs-artifacts-public.s3.amazonaws.com/ML-16564/main.yaml)
- 修改堆栈名称或保留默认值，然后选择 **Next**。
- 在 **Parameters** 区域，输入 Amazon Cognito 用户池 ID（*CognitoUserPoolId*）和应用客户端 ID（*CognitoAppClientId*）。这是堆栈成功部署所必需的。

- 按需检查并更新其他 AWS CloudFormation 参数。你可以对所有参数使用默认值，直接继续部署堆栈。

- 启动堆栈。

CloudFormation 堆栈通过调用一系列嵌套堆栈来创建启动应用所需的资源。它会在你的 AWS 账户中部署以下资源：

- 一个 S3 桶，用于保存来自 AWS Glue、Athena 和 Amazon DataZone 的元数据详情及其对应的文本数据
- 另一个 S3 桶，用于存放与部署相关的代码、构件和日志
- 一个虚拟私有云（VPC）、子网和网络基础设施
- 一个 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/) 索引
- 一个 Amazon Bedrock 知识库
- 知识库的一个数据源，连接已预置的 S3 数据桶，并带有同步数据的事件规则
- 一个 Lambda 函数，用于监视被放入以参数 *S3DataPrefixKB* 配置的 S3 前缀下的对象，并通过 Amazon Bedrock Knowledge Bases API 启动摄取作业：该作业会从 Amazon S3 读取数据、对其进行分块、使用 Amazon Titan Embeddings 模型把分块转换为 embedding，并把这些 embedding 存入 OpenSearch Serverless
- 一个用于存储 RDF 三元组的无服务器 Neptune 数据库
- 一个 Step Functions 状态机，它调用一系列 Lambda 函数，从不同 AWS 服务读取数据、生成 RDF 三元组，并把它们转换为文本文档
- 一个用于托管 Streamlit Web 应用的 ECS 集群与服务

CloudFormation 堆栈部署完成后，会自动运行一个 Step Functions 工作流，它编排元数据的抽取、转换与加载（ETL）作业，并把最终结果存入 Amazon S3。从 CloudFormation 堆栈获取状态机的 Amazon Resource Name（ARN），即可查看该工作流的执行状态与详情。如果该账户中的 AWS Glue 数据库和数据表启用了 [AWS Lake Formation](https://aws.amazon.com/lake-formation/)，请在 CloudFormation 堆栈部署完成后完成以下步骤，以更新权限、从 AWS Glue 提取元数据详情，并更新元数据详情以加载到知识库：

- 为 AWS Glue 相关的 Lambda 函数[添加一个 role](https://docs.aws.amazon.com/lake-formation/latest/dg/permissions-reference.html)，授予访问 AWS Glue 数据库的权限。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16564-img5.png)
- 从 CloudFormation 堆栈获取状态机 ARN。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16564-img6.png)
- 使用默认输入值[运行状态机](https://docs.aws.amazon.com/step-functions/latest/dg/statemachine-starting.html)，提取元数据详情并写入 Amazon S3。

## 使用应用

你可以使用部署步骤中创建的 Amazon CloudFront 分配的域名，从 Web 浏览器访问该应用。使用 Amazon Cognito 用户池中已有的用户凭据登录。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16564-img8-300x272.png)

现在你可以通过文本输入框提交查询。本示例使用的 AWS 账户包含与销售和营销相关的示例表。我们提出一个问题：“如何查询销售数据？”答案中包含了前面步骤中创建的表 *mkt_sls_table* 的元数据。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16564-img9.png)

我们又问了一个问题：“如何从销售数据中获取客户名称？”在前面的步骤中，我们创建了 raw_customer 表，它并未在 Amazon DataZone 中作为数据资产发布。该表只存在于 Data Catalog 中。应用返回的答案合并了来自 Amazon DataZone 和 AWS Glue 的元数据。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16564-img10.png)

这一强大的方案为企业数据发现与洞察打开了令人兴奋的可能性。我们鼓励你在自己的环境中部署它，并针对数据资产尝试不同类型的查询。试着组合来自多个来源的信息、提出复杂的问题，看看语义理解如何改善你的搜索体验。

## 清理

运行这套环境的总体成本低于每天 $10。不过，我们建议在用完后[删除 CloudFormation 堆栈](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/cfn-console-delete-stack.html)，因为已部署的资源会产生费用。删除主堆栈也会因依赖关系而一并删除除 VPC 之外的所有嵌套堆栈。你还需要[从 Amazon VPC 控制台删除该 VPC](https://docs.aws.amazon.com/vpc/latest/userguide/delete-vpc.html#delete-vpc-console)。
