# 用生成式 AI 加速 AWS Well-Architected 评审

基于经过验证的最佳实践构建云基础设施，有助于提升安全性、可靠性和成本效益。为实现这些目标，[AWS Well-Architected Framework](https://aws.amazon.com/architecture/well-architected/) 提供了构建和改进云架构的全面指导。随着系统规模扩大，开展彻底的 AWS Well-Architected Framework Review（WAFR）变得更加关键，它提供更深入的洞察与战略价值，帮助组织优化其不断增长的云环境。

本文探讨一个利用 Amazon Bedrock 的生成式 AI 解决方案，以精简 WAFR 流程。我们演示如何借助 LLM 的能力构建一个智能、可扩展的系统，用于分析架构文档，并基于 AWS Well-Architected 最佳实践生成有洞察力的建议。该解决方案自动化了 WAFR 报告创建中的部分工作，帮助解决方案架构师提升架构评估的效率与彻底性，同时支持其决策过程。

## 使用生成式 AI 驱动的解决方案扩展 Well-Architected 评审

随着组织扩大其云足迹，在遵循 Well-Architected Framework 方面会面临若干挑战：

- 耗时且耗费资源的人工评审
- 不同团队对 Well-Architected 原则的应用不一致
- 难以跟上最新的最佳实践
- 为大型或数量众多的架构扩展评审规模存在挑战

为应对这些挑战，我们构建了 [WAFR Accelerator 解决方案](https://github.com/aws-samples/sample-well-architected-acceleration-with-generative-ai)，它使用生成式 AI 帮助精简并加速 WAFR 流程。通过自动化初始评估和文档编写过程，该解决方案显著减少了评估所花的时间，同时针对 AWS Well-Architected 原则提供一致的架构评估。这让团队能更专注于落实改进和优化 AWS 基础设施。该解决方案包含以下关键特性：

- 该系统采用检索增强生成（RAG）架构，生成具备上下文感知的详细评估。评估内容包括解决方案摘要、针对 Well-Architected 支柱的评估、对最佳实践遵循情况的分析、可操作的改进建议以及风险评估。
- 交互式聊天界面可用于更深入地探究原始文档和生成的内容。
- 与 AWS Well-Architected Tool 集成，可预填工作负载信息和初始评估回答。

该解决方案带来以下关键收益：

- **快速分析与资源优化** —— 过去需要数天人工评审的工作，现在可以在几分钟内完成，从而更快地迭代和改进架构。这种时间效率转化为显著的成本节省和评审过程中更优的资源配置。
- **一致性与更高准确性** —— 该方法在各次评审中一致地应用 AWS Well-Architected 原则，减少人为偏差与疏忽。这种系统化做法带来更可靠、更标准化的评估。
- **洞察深度** —— 高级分析能够识别人工评审中可能被忽略的细微模式和潜在问题，从而更深入地洞察架构的优势与弱点。
- **可扩展性** —— 该解决方案可以同时处理多项评审，适合从初创公司到大型企业的各种规模组织。这种可扩展性使评审可以更频繁、更全面。
- **交互式探索** —— 生成式 AI 驱动的聊天界面让用户可以更深入地探究评估结果、提出追问，并更好地理解建议。这种交互性增强了参与感，并促进对结果更彻底的理解。

## 解决方案概览

[WAFR Accelerator](https://github.com/aws-samples/sample-well-architected-acceleration-with-generative-ai) 旨在通过 Amazon Bedrock 及其他 AWS 服务利用生成式 AI 的能力，精简并增强架构评审流程。该解决方案自动化了复杂架构文档的分析，对照 AWS Well-Architected Framework 的各支柱进行评估，并提供详细的评估与建议。

该解决方案由以下能力构成：

- **生成式 AI 驱动的分析** —— 使用 Amazon Bedrock 对照 AWS Well-Architected 最佳实践快速分析架构文档，生成详细的评估与建议。
- **知识库集成** —— 使用 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 纳入最新的 WAFR 文档和云最佳实践，提供准确且具备上下文感知的评估。
- **可定制** —— 使用 [prompt engineering](https://aws.amazon.com/what-is/prompt-engineering/)，可对驱动大语言模型（LLM）的 prompt 进行定制与迭代优化，从而不断改进和持续增强评估过程。
- **与 AWS Well-Architected Tool 集成** —— 为评估创建 Well-Architected 工作负载里程碑，并基于生成式 AI 的评估结果预填 WAFR 问题的答案。
- **生成式 AI 辅助聊天** —— 提供 AI 驱动的聊天界面，用于深入探究评估结果，支持带上下文管理的多轮对话。
- **可扩展的架构** —— 使用 [AWS Lambda](https://aws.amazon.com/lambda/) 和 [Amazon Simple Queue Service (Amazon SQS)](https://aws.amazon.com/sqs/) 等 AWS 服务高效处理多项评审。
- **数据隐私与网络安全** —— 借助 Amazon Bedrock，你的数据由你掌控，所有输入和定制内容都只保留在你的 AWS 账户内。你的数据（例如 prompt、补全结果、自定义模型，以及用于微调或持续预训练的数据）不会被用于服务改进，也绝不会与第三方模型提供商共享。你的数据保留在处理 API 调用的 AWS 区域中。所有数据在传输中和静态存储时均加密。你可以使用 [AWS PrivateLink](https://aws.amazon.com/privatelink/) 在 VPC 与 Amazon Bedrock 之间创建私有连接。

人工参与的评审仍然至关重要，用于验证生成式 AI 的发现，检查其准确性和是否符合组织要求。

下图展示了该解决方案的技术架构。

![solution-architecture](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/15/brijespm-architecture.png)

该 workflow 包含以下步骤：

- WAFR 指导文档被上传到 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/) 中的一个存储桶。这些文档构成 RAG 架构的基础。示例解决方案使用 Amazon Bedrock Knowledge Base 摄取这些文档并生成嵌入，随后把嵌入存储并索引到 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/) 中。这样就创建了一个向量数据库，可在评审过程中检索相关的 WAFR 指导内容
- 用户通过 [Amazon CloudFront](https://aws.amazon.com/cloudfront/) 访问 WAFR Accelerator Streamlit 应用，它提供安全且可扩展的内容分发。用户认证由 [Amazon Cognito](https://aws.amazon.com/cognito/) 处理，确保只有已认证用户才能访问。
- 用户通过运行在 [Amazon Elastic Compute Cloud（Amazon EC2）](https://aws.amazon.com/ec2/) 实例上的 Streamlit 应用上传 PDF 格式的解决方案架构文档，该实例会把文档存入 S3 存储桶。提交后，WAFR 评审流程由 [Amazon SQS](https://aws.amazon.com/sqs/) 触发，由它把评审请求放入队列。
- 基于 Lambda 和 [AWS Step Functions](https://aws.amazon.com/step-functions/) 的 WAFR reviewer 由 Amazon SQS 激活。它编排整个评审流程，包括文档内容提取、prompt 生成、解决方案摘要、知识嵌入检索和生成。
- [Amazon Textract](https://aws.amazon.com/textract/) 从上传的文档中提取内容，使其可被机器读取以便进一步处理。
- WAFR reviewer 使用 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 的全托管 RAG workflow 查询 OpenSearch Serverless 中的向量数据库，根据选定的 WAFR 支柱和问题检索相关的 WAFR 指导内容。使用元数据过滤来提升检索准确性。
- WAFR reviewer 利用提取的文档内容和检索到的嵌入，使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 生成评估。系统会在 AWS Well-Architected Tool 中创建工作负载，并用评估结果填充答案。这使用户可以在评估完成后从 AWS Well-Architected Tool 控制台下载 AWS Well-Architected 报告的初始版本。
- 评估结果还会存储在 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 表中，便于快速检索和日后参考。
- WAFR Accelerator 应用从 DynamoDB 表读取评审状态，以便及时告知用户。
- 用户可以使用 Amazon Bedrock 与内容对话，从而更深入地探究文档、评估结果和建议。
- 评估完成后，人工评审者可以在 AWS Well-Architected Tool 中查看它。

### 提升评估质量

该解决方案使用 prompt engineering 来优化送入基础模型（FM）的文本输入，以获得期望的评估响应。prompt（此处指 system prompt）的质量对模型输出有显著影响。该解决方案提供了一个示例 system prompt 用于驱动评估。你可以进一步改进这个 prompt，使其符合组织的具体需求。在定义和摄取自己的自定义 lens 时，这一点变得更加关键。

另一个重要因素是用于评估的上传文档的质量。详尽且架构信息丰富的文档能带来更好的推理，从而得到更精细的评估。prompt 的设计方式是：如果用于评估的信息不足，会在输出中予以突出提示。这能最大限度减少 FM 的幻觉，并为让你的设计模板与 AWS Well-Architected 内容保持一致提供了潜在机会。

你还可以使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 进一步改进该解决方案，以进一步减少幻觉，并让响应基于你自己的源信息。

在撰写本文时，仅预置了 AWS Well-Architected Framework、Financial Services Industry 和 Analytics 这几种 lens。不过，其他 lens（包括自定义 lens）只需对 UI 应用和底层数据存储做一些调整即可添加。

在你完成对解决方案的探索或使用、不再需要这些资源之后，请务必清理它们以避免持续产生费用。按以下步骤删除所有相关资源：

- 出现提示时确认删除。

- 确认所有相关资源均已成功删除。
