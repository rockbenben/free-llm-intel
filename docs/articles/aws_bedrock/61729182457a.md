# 使用 Amazon Bedrock AgentCore 与 Amazon Bedrock Knowledge Bases 构建智能活动 agent

大型会议和活动会产生海量信息——从数百场分论坛和工作坊，到演讲嘉宾简介、场地地图以及不断更新的日程。基础 AI 助手虽然能回答关于活动后勤的简单问题，但大多无法提供参会者所需的个性化指引和上下文感知，难以高效应对复杂的多日活动。更重要的是，把这些原型从演示推向生产——具备企业级安全、支撑数千并发用户的可扩展性以及可靠性能——通常需要数月的基础设施建设。

本文演示如何利用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 的各个组件，快速部署一个可上生产的活动助手。我们将构建一个智能伴侣，它能记住参会者的偏好并随着时间推移构建个性化体验，而 Amazon Bedrock AgentCore 负责生产部署中的繁重工作：Amazon Bedrock AgentCore Memory 无需自建存储方案即可同时维护对话上下文和长期偏好，Amazon Bedrock AgentCore Identity 提供安全的多 IDP 身份验证，Amazon Bedrock AgentCore Runtime 提供无服务器扩缩容和会话隔离。我们还会使用 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 实现托管的 RAG 和活动数据检索。

读完之后，你将了解如何部署一个随着每次交互而愈发有用的助手——一位主动的向导，确保参会者能发现自己最有价值的分论坛——它具备企业级的安全与可靠性，可服务数千名并发参会者，而无需你管理基础设施。

如果你是 Amazon Bedrock AgentCore 的新用户，可以先阅读以下博文，在深入本次实现之前理解基础概念：

- [Amazon Bedrock AgentCore Runtime](https://aws.amazon.com/blogs/machine-learning/securely-launch-and-scale-your-agents-and-tools-on-amazon-bedrock-agentcore-runtime/)
- [Amazon Bedrock AgentCore Memory](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-agentcore-memory-building-context-aware-agents/)

### 解决方案如何运作

下面我们逐节展开：

**1. 用户登录与身份获取**

用户使用 [Amazon Cognito](https://aws.amazon.com/pm/cognito/?trk=36e1404e-1051-48b6-9dd0-51db40b9c756&sc_channel=ps&gad_campaignid=23527793912&gbraid=0AAAAADjHtp-3aDu95QEBk69FCnc5u98zu&gclid=CjwKCAiAncvMBhBEEiwA9GU_ftMAwtAoVyxS5TBBzR1T6eflVJ6YxJymyw0ntHi7EIwzqzHH4ZfzLRoC31kQAvD_BwE) （AgentCore Identity 还支持 Okta、Auth0 以及符合 OIDC 的 IDP 等其他身份提供商）登录应用，登录成功后生成 bearer token。该 token 包含用户相关信息，并会在整个工作流中用于身份验证和获取用户特定数据。

**2. agent 调用与初始化**

当用户与应用交互并提交查询时，应用会调用 Amazon Bedrock AgentCore Runtime，并传入三个关键参数：用户的查询、会话 ID（例如 `SessionA`）以及来自 Amazon Cognito 的 bearer token。这会把交互同时关联到用户及其当前会话。AgentCore Identity 会在允许访问 agent 之前对用户进行身份验证和授权。

在首次交互时，[Strands Agent](https://strandsagents.com/latest/) 会在 Amazon Bedrock AgentCore Runtime 内初始化，并从 Amazon Bedrock AgentCore Memory 的长期存储中获取可用的用户偏好，用个性化上下文完成预热。在同一会话内的后续交互中，agent 会带着已经建立的上下文继续对话。

**3. 消息处理**

agent 会把用户消息和助手消息都存入 Amazon Bedrock AgentCore Memory 的短期存储，其中包含 `actor_id` 和 `session_id`。`actor_id` 是从 Amazon Cognito bearer token 中提取的 sub（主体标识符）声明。对话上下文保持私密，仅对当前会话中的特定用户可用。在后台，Amazon Bedrock AgentCore Memory 通过一条转换流水线，使用已配置的记忆策略自动处理这些对话事件。

每种记忆策略都使用模式识别和自然语言理解来分析原始对话数据，识别特定类型的有价值信息——例如用户偏好——并提取值得长期保留的有意义的洞察。随后系统把这些提取出的信息结构化为标准化的记忆记录，打上相关元数据标签，并存入长期记忆中的专用命名空间，供 agent 用来跨多个会话不断细化对用户的理解。

**4. 知识与记忆检索**

为满足用户请求，agent 可能会触发专门的工具。它可以调用 Amazon Bedrock knowledge base 获取最新的活动详情，例如分论坛描述、日程或演讲嘉宾简介。

**5. 响应生成**

agent 处理查询时，会叠加三层上下文：来自长期记忆的洞察（个性化的参会者历史）、来自短期记忆的上下文（会话中最近的消息），以及来自知识库的当前活动数据。然后它生成一个有上下文、个性化的响应。这套架构把类似“我明天该参加哪些分论坛？”这样的简单查询，转化为个性化体验——agent 会回想起用户昨天感兴趣的话题，结合当前对话，给出贴合用户兴趣和历史的具体推荐。

## 解决方案组件

下面我们来了解各组件在解决方案中的作用。

### agent（AgentCore Runtime 与身份集成）

我们活动助手解决方案的核心是 Amazon Bedrock AgentCore Runtime，它提供一个安全、无服务器的环境来托管我们的 agent。Runtime 通过隔离的会话管理用户交互的完整生命周期——每个会话运行在专用的 microVM 中，拥有独立的 CPU、内存和文件系统资源。这种会话隔离确保数千名参会者可以同时与各自个性化的 agent 实例交互，而不会出现跨会话的数据污染。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/02/17/ML-19838-4-edited.png)

安全与身份验证由 Amazon Bedrock AgentCore Identity 负责，它与 Amazon Cognito（以及其他 IDP）无缝集成。当参会者向活动助手发送查询时，Amazon Bedrock AgentCore Identity 会先校验来自 Amazon Cognito 的 bearer token，再允许交互继续。bearer token 通过 headers 传递，agent 取出该 token 调用 Amazon Cognito 的 discovery server，从中提取用户的 sub 及其他相关用户信息。在本用例中，我们用用户 sub 作为会话信息的 `actor_id`，使 agent 能够维护用户特定上下文并给出个性化推荐。这种身份感知有助于确保每位参会者的偏好、对话历史和会话数据都保持私密与安全。

通过把 Runtime 可扩展的托管基础设施与 Identity 的身份验证框架结合，我们的活动助手可以更安全地服务大型会议，同时为每位参会者持续提供个性化的指引。

### agent 记忆

Amazon Bedrock AgentCore Memory 提供了关键的上下文感知能力，把我们的活动助手从简单的问答工具变成真正个性化的向导。该服务由短期记忆和长期记忆组成，二者协同工作，使参会者与活动助手之间能够建立持续演进的关系。

#### 短期记忆：捕获对话

短期记忆是交互的起点。随着对话展开，agent 会把每一次消息交换同步存储为短期记忆中的不可变事件。这些事件按 `actor_id` 和 `session_id` 分层组织，如下图所示。请注意，`actor_id` 提取自 Cognito bearer token（用户的 sub），而 `session_id` 来自 AgentCore Runtime 的会话标识符。

这种组织方式有两个关键用途。第一，它维护每段对话的时间顺序叙事，保留对话的自然流程。第二，它提供精确的隔离——Actor A 在会话 A1 中的对话与会话 B 或另一个 actor 的会话保持分离。这有助于保护隐私，并使 agent 能够准确检索到正确的对话上下文，而无需加载无关数据。agent 可以从短期记忆快速检索最近的消息，以维持对话的连续性。当参会者追问“那个分论坛几点开始？”时，agent 之所以知道刚刚讨论的是哪一场，是因为它可以即时访问对话历史。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/02/17/ML-19838-5-edited.png)

#### 长期记忆：构建持久智能

短期记忆捕获说了什么，长期记忆则提取其中要紧的内容。随着对话发生，AgentCore Memory 服务会自动处理这些交互，识别并存储可跨会话保留的有意义洞察。我们的活动 agent 使用 **User Preferences** 策略来捕获关于分论坛形式、主题或演讲风格的明确偏好。例如，“比起讲座更喜欢动手工作坊”或“对 serverless 和机器学习话题感兴趣”。

这些偏好被存放在长期记忆中的专用命名空间（例如 `/event-agent/actor-A/preferences`），以便清晰组织并支持定向检索。

#### agent 与记忆的编排

Strands Agent 与 AgentCore Memory 之间的无缝集成通过 agent hooks 实现——这些事件驱动的接入点会在 agent 的整个生命周期中自动触发记忆操作。如下图所示：

- **Agent Initialized Event** hook 会在会话开始时从长期记忆获取用户偏好，加载参会者的兴趣和偏好的分论坛类型，从而在第一次查询时就能给出个性化推荐。
- **Message Added Event** hook 会捕获每条用户消息和助手消息，同步存入短期记忆以维护对话历史。

**Note**：*虽然 AgentCore 提供了一个实现记忆工具自动化的 *[*自动记忆管理器*](https://github.com/aws/bedrock-agentcore-sdk-python/tree/main/src/bedrock_agentcore/memory/integrations/strands)*，但本解决方案使用 hooks 来精确控制记忆操作的调用时机与方式——针对活动助手的具体工作流做细粒度优化。*

除这些自动操作外，如果信息不足，agent 还会使用 **Retrieve sessions data** 工具查询 Amazon Bedrock knowledge base，以获取当前活动详情。

这种双管齐下的方式——在启动时预加载关键上下文，并按需选择性检索细节——既保证了速度和精度，又不会用不必要的信息膨胀会话上下文。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/02/17/ML-19838-7-edited.png)

### Amazon Bedrock Knowledge Bases

AgentCore Memory 负责维护个性化上下文和对话历史，而大型会议会产生大量结构化信息——数百条分论坛详情、演讲嘉宾简介、场地地图和日程更新——这些都需要高效的组织与检索。

Amazon Bedrock Knowledge Bases 是一项完全托管的服务，通过把基础模型连接到你的数据源来支持检索增强生成（RAG）。它会自动完成文档的摄取、处理和索引，把文档转换为向量嵌入并存储在向量数据库中。这使 agent 能够执行语义搜索——依据含义和上下文而非精确关键词匹配来检索信息。

该架构把知识库实现为 Strands 框架中的一个专用工具。当参会者就分论坛、演讲嘉宾或场地后勤提出具体问题时，agent 会调用该工具检索精确且最新的信息。记忆与知识库之间的集成形成了强大的组合。当参会者问“我该参加哪些 AI 分论坛？”时，agent 会从知识库检索分论坛详情，同时利用记忆依据参会者先前表达的兴趣来筛选并排序推荐。这有助于给出既在事实上完整、又与个人相关的响应，把大型会议令人不知所措的复杂性转化为可管理、量身定制的指引。

## 结论

在本文中，我们探讨了如何使用 Amazon Bedrock AgentCore 的各个组件，快速把活动助手投入生产——从原型走向企业级的大规模部署。虽然构建智能对话 agent 用各种工具都能实现，真正的挑战在于生产部署。Amazon Bedrock Knowledge Bases 与 Amazon Bedrock AgentCore 的价值在于提供开箱即用的托管服务，涵盖身份验证、扩缩容、记忆管理和 RAG 能力——帮助你省去数月的基础设施工作。

其成果是一个活动助手：它记得参会者昨天对话中对 serverless 技术的兴趣，理解他们更偏好动手工作坊，并利用这些上下文从明天的日程中给出相关推荐——同时保持正在进行的规划会话的对话流。

这正是“展示智能行为的原型”与“能够以企业级安全与可靠性为数千名并发参会者提供个性化体验的生产就绪系统”之间的差别。无论你是在筹备一场小型企业内部聚会，还是一场为期数天的大型会议，Amazon Bedrock AgentCore 都能提供托管基础设施，让你在数天内而非数月内完成智能助手的部署。
