# 通过微调 Amazon Nova 模型并结合按需推理，优化文档 AI 与结构化输出

多模态微调是一种强大的手段，可用于定制视觉大语言模型（LLM），使其在同时涉及视觉与文本信息的特定任务上表现出色。虽然基座多模态模型具备令人印象深刻的通用能力，但在面对专门的视觉任务、特定领域内容或输出格式要求时，它们往往力有未逮。微调通过让模型适配你的特定数据和用例来解决这些局限，大幅提升对业务至关重要的任务表现。

一个常见用例是文档处理，包括从发票、采购订单、表单、表格或技术图纸等复杂版面中提取结构化信息。虽然现成的 LLM 在处理税表、发票和贷款申请这类专门文档时常常力有不逮，但微调后的模型能够从高度变化的数据中学习，在降低处理成本的同时显著提升准确率。

本文提供一份完整的动手实践指南，介绍如何为文档处理任务微调 Amazon Nova Lite，重点放在税表数据提取上。借助我们的开源 [GitHub 仓库代码示例](https://github.com/aws-samples/amazon-nova-samples/tree/main/customization/bedrock-finetuning/understanding/doc-ocr-fine-tuning)，我们演示从数据准备到模型部署的完整工作流。由于 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 为 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) 提供按 token 计费的按需推理，我们可以享受模型定制带来的准确率提升，同时保持按使用量付费的成本结构。

## 文档处理的挑战

给定一份单页或多页文档，目标是从中提取或推导出特定的结构化信息，以便供下游系统使用，或用于获得进一步的洞察。下图展示了如何利用视觉 LLM，基于文本与视觉能力的组合来推导结构化信息。

![智能文档处理工作流的高层概览](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/07/image-1-8.png)

企业在处理发票或 W2 税表这类文档、实现工作流自动化时，面临以下关键挑战：

- **复杂版面**：专用表单包含多个区块，其中特定字段以结构化格式排布。
- **文档类型的多样性：** 存在许多不同的文档类型（发票、合同、表单）。
- **同一文档类型内部的差异：** 每个供应商发来的发票格式、样式或类型都可能不同。
- **数据质量差异**：扫描文档在质量、方向和完整度上各不相同。
- **语言障碍：** 文档可能使用多种语言。
- **严苛的准确率要求**：税务相关数据的提取要求极高的准确率。
- **结构化输出需求**：提取出的数据必须以一致的格式呈现，以供下游处理。
- **可扩展性与集成：** 随业务需求增长，并与现有系统集成，例如企业资源计划（ERP）系统。

使用 LLM 或视觉 LLM 的智能文档处理方法主要分为三大类：

- **零样本提示（zero-shot prompting）：** 使用 LLM 或视觉 LLM，基于输入文档、指令和目标 schema 推导结构化信息。
- **少样本提示（few-shot prompting）：** 这是一种与 LLM 或视觉 LLM 配合使用的技术，在 prompt 中提供少量额外示例（文档 + 目标输出），引导模型完成特定任务。与仅依赖自然语言指令的零样本提示不同，少样本提示通过一组示例展示期望的输入-输出行为，从而提升准确率与一致性。
- **微调（fine-tuning）：** 通过提供大量标注文档（输入/输出对）来定制或微调给定 LLM 或视觉 LLM 的权重，教会模型究竟该如何提取或解释相关信息。

对于前两种方法，请参考 [amazon-nova-samples 仓库](https://github.com/aws-samples/amazon-nova-samples/blob/main/multimodal-understanding/repeatable-patterns/14-document-understanding-idp/01_document_understanding_invoices_processing.ipynb)，其中包含如何使用 Amazon Bedrock Converse API 通过工具调用获得结构化输出的示例代码。

现成的 LLM 擅长通用文档理解，但可能无法最优地处理特定领域的挑战。微调后的 Nova 模型可以通过以下方式提升表现：

- 学习特定文档的版面与字段关系
- 适应你的文档数据集中常见的质量差异
- 提供一致的结构化输出
- 在不同的文档变体之间保持高准确率。例如，发票文档可能涉及数百个不同供应商，每个供应商的格式、版面甚至语言都可能不同。

## 构建标注数据集并选择定制技术

虽然 Amazon Nova 模型提供[多种定制方法](https://aws.amazon.com/ai/generative-ai/nova/customization/)，但与文档处理最相关的是以下两种：

- **为特定任务微调：** 使用监督微调（SFT）让 Nova 模型适配特定任务。在用于数据有限、轻量适配的参数高效微调（PEFT）与用于拥有大量训练数据集、需要更新模型全部参数的全量微调之间做出选择。
- **通过蒸馏创建更小、更快的模型**：使用知识蒸馏，把知识从 Nova Premier 等更大、更智能的模型（教师）迁移到更小、更快、更具成本效益的模型（学生）；当你没有足够的标注训练数据集，而教师模型能提供满足要求的准确率时，这是理想选择。

要从既往示例中学习，你需要么拥有一份可供学习的标注数据集，要么拥有一个对你的任务而言足够好、可作为教师模型的模型。

- **利用企业资源计划（ERP）系统（例如 SAP）中的历史数据自动标注数据集：** 许多客户已经拥有经过人工处理、并已被下游系统（如 ERP 或客户关系管理（CRM）系统）消费的历史文档。请考察 SAP 这类现有下游系统及其中包含的数据。这些数据通常可以映射回其来源的原始文档，帮助你非常快速地引导（bootstrap）出一份标注数据集。
- **人工标注数据集**：识别最相关的文档和格式，由人工标注员进行标注，从而得到文档/JSON 对，其中 JSON 包含你想从源文档中提取或推导的目标信息。
- **用教师模型标注：** 考察 Nova Premier 这类更大的模型通过 prompt 工程能否给出足够准确的结果。如果确实如此，你也可以使用蒸馏。

对于第一种和第二种方案，我们推荐监督式模型微调。对于第三种方案，模型蒸馏才是正确的做法。

Amazon Bedrock 目前同时提供微调和蒸馏技术，因此任何具备基础数据科学技能的人都能非常轻松地提交作业。这些作业运行在完全由 Amazon 托管的计算资源上，你无需担心实例规格或容量限制。

Nova 定制也可以通过 [Amazon SageMaker](https://aws.amazon.com/blogs/aws/announcing-amazon-nova-customization-in-amazon-sagemaker-ai/) 使用，并提供更多选项和控制能力。例如，如果你拥有充足的高质量标注数据，并希望针对自己的用例做更深入的定制，全秩（full rank）微调可能带来更高的准确率。全秩微调在 SageMaker 训练作业和 SageMaker HyperPod 上均受支持。

## 数据准备最佳实践

训练数据的质量与结构从根本上决定微调的成败。以下是准备高效多模态数据集以及配置微调作业的关键步骤与考量：

### 数据集分析与基座模型评估

我们的演示使用一个合成的 W2 税表数据集：[the Fake W-2 (US Tax Form) Dataset](https://www.kaggle.com/datasets/mcvishnu1/fake-w2-us-tax-form-dataset)。这个公开数据集由模拟的美国纳税申报表（2016-19 年的 W-2 报表）构成，其中包含模仿低质量扫描 W2 税表的含噪图像。

在微调之前，关键是要：

- 分析数据集特征（图像质量、字段完整度、类别分布），定义针对具体用例的评估指标，并建立基座模型的性能基线。
- 将每个预测字段值与真值（ground truth）对比，计算单个字段以及整体的精确率、召回率和 F1 分数。

### Prompt 优化

精心设计有效的 prompt 对于让模型对齐任务要求至关重要。我们的系统由两个关键部分组成：

- System prompt：定义任务，为每个待提取字段提供详细指令，并规定输出格式。
- User prompt：遵循 Nova 视觉理解最佳实践，采用 [Amazon Nova 模型用户指南](https://docs.aws.amazon.com/nova/latest/userguide/prompting-vision-prompting.html)中所述的 `{media_file}-then-{text}` 结构。

在微调之前，先使用基座模型迭代优化你的 prompt，以提升性能。

### 数据集准备

以 JSONL 格式准备数据集，并将其划分为训练集、验证集和测试集：

- 训练集：数据的 70-80%
- 验证集：数据的 10-20%
- 测试集：数据的 10-20%

## 微调作业的配置与监控

数据集准备就绪并上传到 Amazon Simple Storage Service（Amazon S3）存储桶后，我们便可以在 Bedrock 上配置并提交微调作业。在 Amazon Bedrock 上配置微调作业时，关键参数包括：

| **参数** | **定义** | **用途** |
| --- | --- | --- |
| **Epochs** | 完整遍历训练数据集的次数 | 决定训练过程中模型看到整个数据集多少次 |
| **Learning rate** | 梯度下降优化的步长 | 控制在估计误差下模型权重被调整的幅度 |
| **Learning rate warmup steps** | 逐步提升学习率所经历的步数 | 通过把学习率从小值缓慢提升到目标值来防止不稳定 |

Amazon Bedrock 的模型定制在整个训练过程中提供验证损失指标。监控这些指标可以：

- 评估模型收敛情况
- 发现潜在的过拟合
- 提前了解模型在未见数据上的表现

下图展示了一个指标分析示例：

![Nova 微调训练作业按步统计的训练损失与验证损失指标](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/07/image-3-4.png)

在分析训练损失与验证损失曲线时，这些指标之间的相对行为能为了解模型的学习动态提供关键洞察。最优的学习模式可以表现为：

- 训练损失和验证损失都随时间稳定下降
- 两条曲线保持相对平行的走势
- 训练损失与验证损失之间的差距保持稳定
- 最终损失值收敛到相近的区间

## 定制模型的推理选项

自定义模型在 Bedrock 中创建完成后，有两种主要方式对该模型进行推理：使用[按需自定义模型推理（ODI）部署](https://aws.amazon.com/blogs/machine-learning/implementing-on-demand-deployment-with-customized-amazon-nova-models-on-amazon-bedrock/)，或使用 [Provisioned Throughput](https://docs.aws.amazon.com/bedrock/latest/userguide/prov-throughput.html) 端点。下面来说明为什么以及何时选择其中一种而非另一种。

按需自定义模型部署提供了一种灵活且具成本效益的方式来使用你在 Bedrock 上的自定义模型。在按需部署模式下，你只需按推理过程中处理的 token 数量，为实际使用的计算资源付费。这使按需模式成为使用量波动或难以预测的工作负载的理想选择，让你避免资源超配。按需方式还提供自动扩缩容，因此你无需操心基础设施容量的管理。Bedrock 会自动预置所需的计算能力，近实时地处理你的请求。这种自助式、无服务器的体验可以简化你的运维与部署工作流。

另一方面，对于流量模式稳定、持续需要高吞吐的工作负载，推荐使用 [Provisioned Throughput 端点](https://docs.aws.amazon.com/bedrock/latest/userguide/prov-throughput.html)，它相比按需扩缩容能提供可预测的性能和成本优势。

本示例使用 ODI 选项以利用按 token 计费的方式；下面的代码片段展示了如何为你的自定义模型创建 ODI 端点：

```
# Function to create on-demand inferencing deployment for custom model
def create_model_deployment(custom_model_arn):
    """
    Create an on-demand inferencing deployment for the custom model
    
    Parameters:
    -----------
    custom_model_arn : str
        ARN of the custom model to deploy
        
    Returns:
    --------
    deployment_arn : str
        ARN of the created deployment
    """
    try:
        print(f"Creating on-demand inferencing deployment for model: {custom_model_arn}")
        
        # Generate a unique name for the deployment
        deployment_name = f"nova-ocr-deployment-{time.strftime('%Y%m%d-%H%M%S')}"
        
        # Create the deployment
        response = bedrock.create_custom_model_deployment(
            modelArn=custom_model_arn,
            modelDeploymentName=deployment_name,
            description=f"on-demand inferencing deployment for model: {custom_model_arn}",
        )
        
        # Get the deployment ARN
        deployment_arn = response.get('customModelDeploymentArn')
        
        print(f"Deployment request submitted. Deployment ARN: {deployment_arn}")
        return deployment_arn
    
    except Exception as e:
        print(f"Error creating deployment: {e}")
        return None
```

## 成本分析

在我们的示例中，我们选择使用 Bedrock 的微调作业，采用 PEFT 方式，并且可以使用 ODI。以 PEFT 方式微调 Nova Lite 并配合按需推理能力，为增强文档处理提供了一种具成本效益且可扩展的解决方案。成本结构简单透明：

**一次性成本：**

- 模型训练：每 1,000 token $0.002 × epoch 数

**持续成本：**

- 存储：每个自定义模型每月 $1.95
- 按需推理：与基座模型相同的按 token 定价  以上述数据集中的 1 页为例：1895 tokens/1000 * $0.00006 + 411 tokens/1000 * $0.00024 = $0.00021

按需推理让你无需维护预置端点即可运行自定义 Nova 模型，从而按实际 token 使用量进行按需付费。这种方式免去了容量规划的需要，同时确保扩缩容的成本效率。

## 结论

在本文中，我们演示了微调 Amazon Nova Lite 如何在保持成本效率的同时改变文档处理的准确率。我们的评估显示出显著的性能提升，关键字段的精确率最高提升 39%，关键文档类别的召回率达到 100%。虽然我们的实现并不需要约束解码（constrained decoding），但在处理更复杂的结构化输出时，尤其是面对错综复杂的 JSON schema 时，使用 Nova 进行工具调用可以提供额外的可靠性。更多信息请参阅关于[通过工具调用实现结构化输出](https://aws.amazon.com/blogs/machine-learning/structured-outputs-with-amazon-nova-a-guide-for-builders/)的资料。

灵活的部署选项（包括按使用量付费的按需推理）消除了基础设施开销，同时保持与基座模型相同的推理成本。使用本示例所用的数据集，每页运行时推理成本为 $0.00021，使其成为一种具成本效益的解决方案。通过实践示例和分步指南，我们展示了如何准备训练数据、微调模型，并用清晰的指标评估性能。

**![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/07/image-8-1-100x133.png)Arlind Nocaj** 是负责欧洲中部 AI/ML 与生成式 AI 的 GTM 专家解决方案架构师，常驻 AWS 苏黎世办公室，指导企业客户推进数字化转型。他拥有网络分析与可视化（图绘制）博士学位，并拥有十余年作为研究科学家和软件工程师的经验，为其岗位带来了学术严谨性与实践专长的独特融合。他的主要关注点在于充分释放数据、算法和云技术的潜力，以推动创新与效率。他的专长领域包括机器学习、生成式 AI，尤其是用于文档处理和结构化洞察的多模态 LLM agentic 系统。
