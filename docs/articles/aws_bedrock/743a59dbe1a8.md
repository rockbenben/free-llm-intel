# 使用 Amazon Bedrock、LlamaIndex 和 RAGAS 评估 RAG 回答

在快速演进的人工智能领域，[检索增强生成](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）已成为游戏规则的改变者，彻底重塑了基座模型（FM）与组织专属数据的交互方式。随着企业日益依赖 AI 驱动的解决方案，对准确、具备上下文感知且量身定制的回答的需求从未如此迫切。

现在，[Amazon Bedrock](https://aws.amazon.com/bedrock/)、[LlamaIndex](https://www.llamaindex.ai/) 和 [RAGAS](https://docs.ragas.io/en/stable/) 组成的三强登场——这一前沿组合将重新定义 RAG 回答的评估与优化。本文深入探讨这些创新工具如何协同作用，提升 AI 应用的性能，确保它们不仅达到、而且超越企业级部署的严苛标准。

无论你是经验丰富的 AI 从业者，还是正在探索生成式 AI 潜力的业务领导者，本指南都会为你提供所需的知识与工具，以便：

- 充分释放 Amazon Bedrock 强大基座模型的潜力
- 利用 RAGAS 为 RAG 系统提供的全面评估指标

本文将探讨如何借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/)、[LlamaIndex](https://www.llamaindex.ai/) 和 [RAGAS](https://docs.ragas.io/en/stable/) 来增强你的 RAG 实现。你将学到评估和优化 AI 系统的实用技巧，从而获得更准确、具备上下文感知、且契合组织具体需求的回答。让我们深入其中，看看这些强大的工具如何帮助你构建更有效、更可靠的 AI 驱动解决方案。

## RAG 评估

RAG 评估对于确保 RAG 模型产出准确、连贯且相关的回答非常重要。通过既联合又独立地分析检索组件与生成组件，RAG 评估有助于发现瓶颈、监控性能并改进整个系统。当前的 RAG pipeline 经常采用 [ROUGE](https://en.wikipedia.org/wiki/ROUGE_(metric))、[BLEU](https://en.wikipedia.org/wiki/BLEU) 和 [BERTScore](https://arxiv.org/abs/1904.09675) 等基于相似度的指标来评估生成回答的质量，这对于打磨和增强模型能力至关重要。

上述概率性指标 [ROUGE](https://en.wikipedia.org/wiki/ROUGE_(metric))、[BLEU](https://en.wikipedia.org/wiki/BLEU) 和 [BERTScore](https://arxiv.org/abs/1904.09675) 在评估相关性和检测幻觉方面存在局限。要评估事实一致性与准确性，需要更精细的指标。

## 用基座模型评估 RAG 各组件

我们也可以使用基座模型作为评委，为检索和生成计算各种指标。以下是这些指标的一些示例：

- **检索组件**  **上下文精确率**——评估上下文中出现的所有 ground truth 相关条目是否被排得更靠前。**上下文召回率**——确保上下文包含回答问题所需的全部相关信息。
- **生成组件**  **忠实度**——验证生成的答案在所提供的上下文基础上是否事实准确，帮助识别错误或“幻觉”。**答案相关性**：衡量答案与问题的匹配程度。得分越高，说明答案完整且相关；得分越低，则意味着信息缺失或冗余。

## **方案概览**

本文引导你使用 [RAGAS](https://docs.ragas.io/en/stable/) 和 [LlamaIndex](https://www.llamaindex.ai/) 这类评估框架，配合 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 来评估 RAG 回答的质量。

本文中，我们还会借助 LangChain 创建一个示例 RAG 应用。

[**Amazon Bedrock**](https://aws.amazon.com/bedrock/?sc_channel=ps) 是一项全托管服务，通过单一 API 提供来自 AI21 Labs、Anthropic、Cohere、Meta、Stability AI 和 Amazon 等领先 AI 公司的高性能基座模型（FM）供你选择，并提供构建安全、注重隐私且负责任的生成式 AI 应用所需的广泛能力。

检索增强生成评估（[RAGAS](https://docs.ragas.io/en/stable/)）框架提供[多种指标](https://docs.ragas.io/en/stable/concepts/metrics/index.html)，用于评估 RAG 系统 pipeline 的每个部分并找出可改进之处。它利用基座模型测试各个组件，帮助精确定位需要改进的模块，从而提升整体效果。

[**LlamaIndex**](https://www.llamaindex.ai/) 是一个用于构建 LLM 应用的框架。它简化了来自各种数据源的数据集成，并提供数据索引、引擎、agent 和应用集成的工具。它针对搜索与检索做了优化，精简了查询 LLM 和检索文档的流程。本文重点使用它的 [Observability](https://docs.llamaindex.ai/en/stable/module_guides/observability/)/[Evaluation](https://docs.llamaindex.ai/en/stable/optimizing/evaluation/evaluation/) 模块。

[**LangChain**](https://www.llamaindex.ai/) 是一个开源框架，可简化由基座模型驱动的应用的创建过程。它提供用于串联 LLM 操作、管理上下文以及集成外部数据源的工具。LangChain 主要用于构建聊天机器人、问答系统以及其他需要复杂语言处理能力的 AI 驱动应用。

## 导入 FAQ 数据

第一步是导入 SageMaker FAQ 数据。为此，LangChain 提供了 WebBaseLoader 对象，可将 HTML 网页中的文本加载为文档格式。然后我们把每个文档切分为多个 2,000 token 的分块，重叠 100 个 token。参见以下代码：

## 使用 Amazon Bedrock 和 LangChain 设置 embedding 与 LLM

为了构建示例 RAG 应用，我们需要一个 LLM 和一个 embedding 模型：

- **LLM**——Anthropic Claude 3 Sonnet

- **Embedding**——Amazon Titan Embeddings – Text V2

以下代码使用 Amazon Bedrock 搭建了一个 LangChain 应用，用 Titan 配置 embedding，并使用 Claude 3 Sonnet 模型进行文本生成，同时设定了用于控制模型输出的特定参数。参见 [notebook](https://github.com/aws-samples/sample-rag-evaluation-ragas/blob/main/ragas_notebook.ipynb) 中的以下代码：

```
from botocore.client import Config
from langchain.llms.bedrock import Bedrock
from langchain_aws import ChatBedrock
from langchain.embeddings import BedrockEmbeddings
from langchain.retrievers.bedrock import AmazonKnowledgeBasesRetriever
from langchain.chains import RetrievalQA
import nest_asyncio
nest_asyncio.apply()

#URL to fetch the document
SAGEMAKER_URL="https://aws.amazon.com/sagemaker/faqs/"

#Bedrock parameters
EMBEDDING_MODEL="amazon.titan-embed-text-v2:0"
BEDROCK_MODEL_ID="anthropic.claude-3-sonnet-20240229-v1:0"

bedrock_embeddings = BedrockEmbeddings(model_id=EMBEDDING_MODEL,client=bedrock_client)

model_kwargs = {
    "temperature": 0, 
    "top_k": 250, 
    "top_p": 1,
    "stop_sequences": ["\\n\\nHuman:"]
}    

llm_bedrock = ChatBedrock(
    model_id=BEDROCK_MODEL_ID,
    model_kwargs=model_kwargs
)
```

## 构建 Q&A 链以查询检索 API

数据库填充完成后，创建一个[问答检索链](https://python.langchain.com/docs/tutorials/rag/)，利用从向量存储中提取的上下文来执行问答。你还会按照 [Claude prompt 工程指南](https://docs.anthropic.com/claude/docs/roleplay-dialogue#complex-customer-support-agent)定义一个 prompt 模板。参见 [notebook](https://github.com/aws-samples/sample-rag-evaluation-ragas/blob/main/ragas_notebook.ipynb) 中的以下代码：

```
from langchain_core.prompts import ChatPromptTemplate
from langchain.chains.combine_documents import create_stuff_documents_chain
from langchain.chains import create_retrieval_chain

system_prompt = (
    "Use the given context to answer the question. "
    "If you don't know the answer, say you don't know. "
    "Use three sentence maximum and keep the answer concise and short. "
    "Context: {context}"
    )

prompt_template = ChatPromptTemplate.from_messages([
    ("system", system_prompt),
    ("human", "{input}")
    ]
)
question_answer_chain = create_stuff_documents_chain(llm_bedrock, prompt_template)
chain = create_retrieval_chain(retriever_db, question_answer_chain)
```

## 构建用于评估 RAG 应用的数据集

要评估 RAG 应用，我们需要以下数据集的组合：

- **问题**——作为 RAG pipeline 输入的用户查询
- **上下文**——根据所提供查询从企业或外部数据源中检索到的信息
- **答案**——由 LLM 生成回答
- **Ground truth**——由人工标注的、针对这些问题的理想回答，可作为基准与 LLM 生成的答案进行比较

现在可以评估 RAG 应用了。正如引言所述，我们选择 3 项指标来评估我们的 RAG 方案：

- 忠实度
- 答案相关性
- 答案正确性

更多信息请参阅[指标](https://docs.ragas.io/en/latest/concepts/metrics/index.html#))。

这一步需要定义一个包含一组 ground truth 问题与答案的评估数据集。本文从 SageMaker FAQ 中随机选取四个问题。参见 [notebook](https://github.com/aws-samples/sample-rag-evaluation-ragas/blob/main/ragas_notebook.ipynb) 中的以下代码：

```
EVAL_QUESTIONS = [

"""No. You can create and run multiple notebooks on the same compute instance.

"No. Your inference and training data will not be used nor shared to update or train the base model that SageMaker JumpStart surfaces to customers."
```

## 使用 RAGAS 评估 RAG

评估 RAG 方案需要把 LLM 的预测结果与 ground truth 答案进行比较。为此，我们使用 [LangChain](https://python.langchain.com/v0.1/docs/expression_language/interface/#batch) 的 batch() 函数对评估数据集中的所有问题执行推理。

然后我们可以使用 RAGAS 的 evaluate() 函数对每项指标（答案相关性、忠实度和答案正确性）执行评估。它会使用 LLM 计算指标。你也可以随意使用 RAGAS 提供的其他[指标](https://docs.ragas.io/en/latest/concepts/metrics/index.html#))。

参见 [notebook](https://github.com/aws-samples/sample-rag-evaluation-ragas/blob/main/ragas_notebook.ipynb) 中的以下代码：

```
from ragas.metrics import answer_relevancy, faithfulness, answer_correctness
from ragas import evaluate

#Batch invoke and dataset creation
result_batch_questions = chain.batch([{"input": q} for q in EVAL_QUESTIONS])

dataset= build_dataset(EVAL_QUESTIONS,EVAL_ANSWERS,result_batch_questions, text_chunks)

result = evaluate(dataset=dataset, metrics=[ answer_relevancy, faithfulness, answer_correctness ],llm=llm_bedrock, embeddings=bedrock_embeddings, raise_exceptions=False )
df = result.to_pandas()
df.head()
 The following screenshot shows the evaluation results and the RAGAS answer relevancy score.
```

## 使用 LlamaIndex 评估 RAG

与 Ragas 类似，LlamaIndex 提供了全面的 RAG（检索增强生成）评估模块。该模块提供多种指标来评估你的 RAG 系统性能。评估过程会产生两类关键输出：

- **Feedback**：作为评委的 LLM（语言模型）以字符串形式给出详细的评估反馈，提供关于系统性能的定性洞见。
- **Score**：该数值表示答案满足评估标准的程度。评分体系因所评估的具体指标而异。例如，Answer Relevancy 和 Faithfulness 这类指标通常按 0 到 1 的尺度评分。

这些输出既能对 RAG 系统性能做定性评估，也能做定量评估，让你能够找出可改进之处并跟踪长期进展。

以下是 [notebook](https://github.com/aws-samples/sample-rag-evaluation-ragas/blob/main/ragas_notebook.ipynb) 中的代码示例：

```
from llama_index.llms.bedrock import Bedrock
from llama_index.core.evaluation import (
    AnswerRelevancyEvaluator,
    CorrectnessEvaluator,
    FaithfulnessEvaluator
)
from utils import evaluate_llama_index_metric

bedrock_llm_llama = Bedrock(model=BEDROCK_MODEL_ID)
faithfulness= FaithfulnessEvaluator(llm=bedrock_llm_llama)
answer_relevancy= AnswerRelevancyEvaluator(llm=bedrock_llm_llama)
correctness= CorrectnessEvaluator(llm=bedrock_llm_llama)
```

## 结语

尽管基座模型具备令人印象深刻的生成能力，但它们在处理组织专属查询时的有效性一直是个持续的挑战。[检索增强生成](https://aws.amazon.com/what-is/retrieval-augmented-generation/) 框架作为一套有力方案出现，通过让 LLM 利用外部的、组织专属的数据源来弥合这一差距。

要真正释放 RAG pipeline 的潜力，[RAGAS](https://docs.ragas.io/en/stable/) 框架与 [LlamaIndex](https://www.llamaindex.ai/) 相结合，提供了一套全面的评估方案。通过细致评估检索与生成两个组件，这一方法让组织能够精准定位可改进之处并打磨其 RAG 实现。结果如何？回答不仅事实准确，而且与用户查询高度相关。

通过采用这种整体性评估方法，企业可以充分释放生成式 AI 应用的变革力量。这不仅最大化了从这些技术中获得的价值，也为更智能、具备上下文感知且更可靠的 AI 系统铺平了道路，使它们能够真正理解并满足组织的独特需求。

随着我们不断突破 AI 的可能性边界，[Amazon Bedrock](https://aws.amazon.com/bedrock/)、[LlamaIndex](https://www.llamaindex.ai/) 和 [RAGAS](https://docs.ragas.io/en/stable/) 这类工具将在塑造企业 AI 应用的未来中发挥关键作用。通过拥抱这些创新，组织可以从容地探索生成式 AI 这一激动人心的前沿，开启更高水平的效率、洞见和竞争优势。

如需进一步探索，有兴趣提升 AI 生成内容可靠性的读者可以了解 Amazon Bedrock 的 Guardrails 功能，它提供了诸如 [Contextual Grounding Check](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-contextual-grounding-check.html) 这样的额外工具。
