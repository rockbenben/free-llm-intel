# 使用 GraphRAG 提升检索增强生成的准确率

客户需要更高的准确率，才能把生成式 AI 应用投入生产。在决策日益数据驱动的世界里，信息的完整性和可靠性至关重要。为此，客户通常会先通过基于向量的检索系统和[检索增强生成](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）架构模式来提升生成式 AI 的准确率，该模式整合稠密嵌入，让 AI 的输出以相关上下文为依据。当需要更高的精度和上下文保真度时，解决方案会演进为图增强 RAG（GraphRAG），由图结构提供更强的推理与关系建模能力。

AWS 合作伙伴 [Lettria](https://www.lettria.com/) [展示](https://www.lettria.com/blogpost/vectorrag-vs-graphrag-a-convincing-comparison)了：把基于图的结构集成到 RAG 工作流中，可将答案精度相较于纯向量检索方法提升最多 35%。这一提升得益于图能够对数据点之间的复杂关系和依赖关系建模，从而为生成式 AI 的输出提供更细致、上下文更准确的基础。

本文探讨 GraphRAG 为何比单纯的向量 RAG 更全面、更具可解释性，以及如何借助 AWS 服务和 [Lettria](https://www.lettria.com/case-study/better-together-lettria-aws) 使用这种方法。

## 图如何让 RAG 更准确

本节讨论图在哪些方面让 RAG 更准确。

### 用图捕捉复杂的人类查询

人类的问题本质上很复杂，往往需要把多条信息联系起来。传统的数据表示方式很难在不丢失上下文的情况下容纳这种复杂性。而图则被设计用来映射人类自然思考和提问的方式。它们以机器可读的格式表示数据，同时保留实体之间丰富的关系。

通过把数据建模为图，你可以捕捉到更多的上下文和意图。这意味着你的 RAG 应用可以以与人类思维过程高度一致的方式访问和解释数据。结果就是对复杂查询给出更准确、更相关的答案。

### 避免数据表示中的上下文丢失

当你仅依赖向量相似度进行信息检索时，就会错过数据中存在的细微关系。把自然语言转换为向量会削弱信息的丰富度，可能导致答案不够准确。此外，终端用户的查询并不总在语义上与所提供文档中的有用信息对齐，这会使向量搜索排除掉构建准确答案所需的关键数据点。

图保留了数据的自然结构，使问题与答案之间能够更精确地映射。它们让 RAG 系统能够理解并在数据内部的复杂连接中穿行，从而提升准确率。

Lettria 展示了答案正确率的提升：在混合方法中使用 GraphRAG，可把传统 RAG 的 50% 提升到 80% 以上。测试覆盖了金融（Amazon 财务报告）、医疗健康（关于 COVID-19 疫苗的科学研究）、工业（航空建筑材料的技术规格）和法律（欧盟环境法规指令）等领域的数据集。

## 证明图更准确

为证实图增强 RAG 带来的准确率提升，Lettria [开展了一系列基准测试](https://www.lettria.com/blogpost/vectorrag-vs-graphrag-a-convincing-comparison)，把他们的 GraphRAG 解决方案（同时使用向量库和图库的混合 RAG）与仅使用向量的基线 RAG 参考实现进行比较。

### Lettria 的混合 RAG 方法

Lettria 的混合问答方法结合了向量相似度搜索和图搜索的优点，以优化 RAG 应用处理复杂文档时的表现。通过整合这两套检索系统，Lettria 在处理复杂查询时同时具备结构化的精确性和语义上的灵活性。

GraphRAG 擅长使用细粒度、上下文相关的数据，非常适合回答那些需要实体之间显式连接的问题。相比之下，向量 RAG 擅长检索语义相关的信息，提供更宽泛的上下文洞察。这套双系统还有一层回退机制加以强化：当一套系统难以提供相关数据时，另一套系统予以补足。例如，在存在显式关系时由 GraphRAG 精确定位，而在结构缺失时由向量 RAG 填补关系空白或增强上下文。

## 基准测试过程

为展示这种混合方法的价值，Lettria 在来自多个行业的数据集上开展了广泛的基准测试。他们使用自己的解决方案，把 GraphRAG 的混合流水线与一个领先的开源 RAG 包 [Verba by Weaviate](https://verba.weaviate.io/)（仅依赖向量库的基线 RAG 参考实现）进行比较。数据集包括 Amazon 财务报告、关于 COVID-19 疫苗的科学文本、航空领域的技术规格，以及欧盟环境指令——构成了一个多样且具代表性的测试床。

评估聚焦六类不同的问题来应对真实世界的复杂性，包括基于事实的、多跳的、数值的、表格的、时间的和多约束的查询。问题从简单的事实查找（例如识别疫苗配方）到多层推理任务（例如比较不同时间段的营收数字）。金融领域的一个多跳查询示例是“把 Amazon 最早的营收记录与最近的营收进行比较”。

Lettria 的内部团队用详细的评估矩阵人工评估答案，把结果分类为正确、部分正确（可接受或不可接受）或错误。这一过程衡量了混合 GraphRAG 方法在多大程度上优于基线，特别是在处理需要把结构化关系与语义广度结合起来的多维查询时。通过发挥向量检索和基于图的检索各自的优势，Lettria 的系统展示了以精确性和灵活性应对各行业细微需求的能力。

### 基准测试结果

[结果](https://www.lettria.com/blogpost/vectorrag-vs-graphrag-a-convincing-comparison)显著且令人信服。GraphRAG 的正确答案率达到 80%，而传统 RAG 为 50.83%。把可接受的答案也计算在内时，GraphRAG 的准确率升至接近 90%，而向量方法达到 67.5%。

下图展示了向量 RAG 与 GraphRAG 的结果。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/20/ML-17959-image001.png)

在工业领域，面对复杂的技术规格，GraphRAG 给出了 90.63% 的正确答案，几乎是向量 RAG 的 46.88% 的两倍。这些数字凸显了 GraphRAG 相较纯向量方法的显著优势，对于专注于结构化复杂数据的客户尤其如此。

GraphRAG 的整体可靠性和对复杂查询的出色处理能力，让客户能够更有信心地做出更明智的决策。通过提供最多提升 35% 的准确答案，它显著提升了效率，并减少了在非结构化数据中筛选所花的时间。这些令人信服的结果表明，把图纳入 RAG 工作流不仅能提升准确率，更是应对真实世界问题复杂性的必要手段。

## 使用 AWS 和 Lettria 增强 RAG 应用

本节讨论如何结合 AWS 和 Lettria 来增强 RAG 应用。

### AWS：生成式 AI 的坚实基础

AWS 提供了一整套全面的工具和服务来构建和部署生成式 AI 应用。借助 AWS，你可以获得可扩展的基础设施和诸如 [Amazon Neptune](https://aws.amazon.com/neptune/) 这样的高级服务，后者是一项完全托管的图数据库服务。Neptune 让你能够高效地对数据中的复杂关系建模并穿行其间，是实施基于图的 RAG 系统的理想选择。

从零开始实施 GraphRAG 通常需要类似下图的流程。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/20/ML-17959-image003.png)

该流程可以拆解如下：

- 基于领域定义，大语言模型（LLM）可以识别非结构化数据中所含的实体与关系，随后把它们存入 Neptune 之类的图数据库。
- 在查询时，根据领域定义把用户意图转换为高效的图查询，以检索相关实体与关系。
- 随后用检索结果扩充 prompt，生成比标准向量 RAG 更准确的回答。

实施这样的流程，需要团队掌握图建模、图查询、prompt 工程或 LLM 工作流维护等特定技能。AWS 发布了一个开源 [GraphRAG Toolkit](https://github.com/awslabs/graphrag-toolkit)，让希望构建和定制自身 GraphRAG 工作流的客户可以更简单地实现。为了获得准确率提升，抽取过程和图查找的迭代是预期之中的。

### 托管的 GraphRAG 实现

在 AWS 上有两种托管 GraphRAG 方案：Lettria 的解决方案（即将登陆 [AWS Marketplace](https://aws.amazon.com/marketplace)），以及 [Amazon Bedrock 与 Neptune 集成的 GraphRAG 支持](https://aws.amazon.com/about-aws/whats-new/2024/12/amazon-bedrock-knowledge-bases-graphrag-preview/)。Lettria 提供了一种易用的方式，把 GraphRAG 集成到你的应用中。把 Lettria 在自然语言处理（NLP）和图技术方面的专长，与可扩展的托管 AWS 基础设施相结合，你就可以开发出更准确、更可靠的 RAG 解决方案。

以下是 Lettria on AWS 的关键优势：

- **简单集成** – Lettria 的解决方案简化了复杂数据集的摄取与处理
- **更高的准确率 **– 在问答任务中，你可以获得高达 35% 的性能提升
- **可扩展性** – 你可以使用可扩展的 AWS 服务来应对不断增长的数据量和用户需求
- **灵活性** – 混合方法结合了向量表示和图表示的优势

除 Lettria 的解决方案之外，[Amazon Bedrock 于 2024 年 12 月 4 日推出了托管 GraphRAG 支持](https://aws.amazon.com/about-aws/whats-new/2024/12/amazon-bedrock-knowledge-bases-graphrag-preview/)，直接与 Neptune 集成。与 Neptune 配合的 GraphRAG 内建于 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)，提供一体化体验，除底层服务费用外无需额外设置或额外收费。GraphRAG 在同时提供 Amazon Bedrock Knowledge Bases 和 [Amazon Neptune Analytics](https://docs.aws.amazon.com/neptune-analytics/latest/userguide/what-is-neptune-analytics.html) 的 AWS 区域可用（见[当前受支持区域列表](https://docs.aws.amazon.com/neptune-analytics/latest/userguide/analytics-limits.html)）。更多信息请参阅[使用 Amazon Bedrock Knowledge Bases 检索数据并生成 AI 回答](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base.html)。

## 结论

数据准确性是采用生成式 AI 应用的企业面临的关键问题。通过把图纳入 RAG 工作流，你可以显著提升系统的准确率。图提供了更丰富、更细致的数据表示，能够捕捉人类查询的复杂性并保留上下文。

对于希望充分释放数据潜力的组织来说，GraphRAG 是一个值得考虑的关键选项。借助 AWS 与 Lettria 的联合能力，你可以构建先进的 RAG 应用，帮助满足当今数据驱动企业的严苛需求，并获得最高 35% 的准确率提升。
