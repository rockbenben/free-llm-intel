# 在 Amazon Q Business 中使用 LLM 从图像文件中提取上下文

为了有效传达复杂信息，各类组织越来越依赖由示意图、图表和技术插图构成的视觉文档。尽管文本文档已很好地融入现代知识管理系统，但示意图、图表、技术原理图和视觉文档中蕴含的丰富信息，往往仍无法被搜索和 AI 助手获取。这在组织的知识库中造成了明显缺口，导致人们只能手工解读视觉数据，也使自动化系统无法利用这些关键视觉信息来形成全面洞察并支持决策。虽然 [Amazon Q Business](https://aws.amazon.com/q/business/) 已经能够处理文档内嵌的图像，但 [custom document enrichment](https://docs.aws.amazon.com/amazonq/latest/qbusiness-ug/custom-document-enrichment.html)（CDE）功能通过处理独立的图像文件（例如 JPG 和 PNG）显著扩展了这些能力。

本文介绍在 [Amazon Q Business 应用程序](https://docs.aws.amazon.com/amazonq/latest/qbusiness-ug/create-application.html)中使用 CDE 功能的分步实施方案。我们会带你了解如何在 CDE 中配置一个 [AWS Lambda](https://aws.amazon.com/lambda/) 函数来处理多种图像文件类型，并展示一个示例场景，说明这种集成如何增强 Amazon Q Business 提供全面洞察的能力。按照这份实用指南操作，你可以显著扩展组织内可搜索的知识库，从而给出融合文本与视觉信息源的更完整答案与洞察。

## 示例场景：分析区域教育人口统计数据

设想这样一个场景：你就职于一家全国性的教育咨询机构，该机构把跨不同 [AWS 区域](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region)的图表、图形和人口统计数据存储在 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）存储桶中。下图用柱状图展示各城市学生按年龄段的分布。此类可视化中的洞察对决策很有价值，但传统上它们被封存在 S3 存储桶及其他存储的图像格式里。

借助 Amazon Q Business 和 CDE，我们展示如何对此类可视化启用自然语言查询。例如，你的团队可以直接通过 Amazon Q Business 应用程序界面提出诸如“哪个城市在 13–15 岁年龄段的学生人数最多？”或“比较 City 1 与 City 4 的学生人口统计数据”这样的问题。

![Distribution Chart](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/19/image-1-2.jpg)

你可以使用 Amazon Q Business 的 CDE 功能来弥合这一差距：

- 在文档摄取过程中检测并处理图像文件
- 结合 AWS Lambda 使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 解读视觉信息
- 从图表和图形中提取结构化数据与洞察
- 让这些信息可通过自然语言查询被检索到

## 解决方案概述

在本解决方案中，我们带你了解如何为教育人口统计数据可视化实施基于 CDE 的方案。该方案利用 Amazon Q Business 的 [CDE 能力](https://docs.aws.amazon.com/amazonq/latest/qbusiness-ug/cde-basic-operations.html)，使组织能够从图像文件中提取有意义的信息。当 Amazon Q Business 在摄取过程中遇到 S3 路径时，CDE 规则会自动触发一个 Lambda 函数。该 Lambda 函数识别出图像文件并调用 Amazon Bedrock API，后者使用多模态[大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLM）来分析并提取每张图像中的上下文信息。提取出的文本随后被无缝集成到 Amazon Q Business 的知识库中。最终用户随后可以基于图像的实际上下文，快速检索其中有价值的数据与洞察。通过弥合视觉内容与可搜索文本之间的差距，该方案帮助组织释放此前藏在图像库中的宝贵洞察。

实施本方案需要以下前提条件：

## 为 Amazon S3 数据源配置 Amazon Q Business 应用程序的 CDE

借助 Amazon Q Business 的 CDE 功能，你可以充分利用 Amazon S3 数据源，在摄取过程中修改、增强和筛选文档，最终让企业内容更易被发现、更有价值。将 Amazon Q Business 连接到 S3 存储库时，你可以使用 CDE 无缝转换原始数据，施加能显著提升搜索质量与信息可访问性的修改。这一强大功能通过与 Amazon Bedrock 服务的集成，还可扩展到从图像等二进制文件中提取上下文，使组织能够从以往无法访问的内容格式中释放洞察。通过为 Amazon S3 数据源实施 CDE，企业可以最大化其在 Amazon Q 中企业数据的效用，构建更全面、更智能、能够有效响应用户查询的知识库。要为 Amazon S3 数据源配置 Amazon Q Business 应用程序的 CDE，请完成以下步骤：

- 配置预提取规则，以便在满足特定 S3 存储桶条件时触发 Lambda 函数。示例配置请参见下方截图。

## 从图像中提取上下文

为了从图像文件中提取洞察，该 Lambda 函数使用 Anthropic 的 Claude 3.7 Sonnet 模型发起 Amazon Bedrock API 调用。你可以根据自身用例修改代码，改用其他 Amazon Bedrock 模型。

构建 prompt 是代码中的关键一环。我们建议针对自身用例尝试多种 prompt，以获得期望的输出。Amazon Bedrock 提供了[优化 prompt](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-management-optimize.html)的能力，可用于增强你特定用例的输入。

请查看以下用 Python 编写的 Lambda 函数代码片段，以了解 Amazon Bedrock 模型的设置方式，以及一份用于从图像中提取洞察的示例 prompt。

在以下代码片段中，我们先导入相关的 Python 库，定义常量，并为 Amazon S3 和 [Amazon Bedrock runtime](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_Operations_Amazon_Bedrock_Runtime.html) 初始化 [AWS SDK for Python (Boto3)](https://aws.amazon.com/sdk-for-python/) 客户端。更多信息请参阅 [Boto3 文档](https://boto3.amazonaws.com/v1/documentation/api/latest/index.html)。

```
import boto3
import logging
import json
from typing import List, Dict, Any
from botocore.config import Config

MODEL_ID = "us.anthropic.claude-3-7-sonnet-20250219-v1:0"
MAX_TOKENS = 2000
MAX_RETRIES = 2
FILE_FORMATS = ("jpg", "jpeg", "png")

logger = logging.getLogger()
logger.setLevel(logging.INFO)
s3 = boto3.client('s3')
bedrock = boto3.client('bedrock-runtime', config=Config(read_timeout=3600, region_name='us-east-1'))
```

`lambda_handler` 是 Lambda 函数的主入口。调用该 Lambda 函数时，CDE 会通过 `event` 对象输入传递数据源的信息。在此例中，S3 存储桶与 S3 对象键连同文件格式一起从 `event` 对象中取出。只有当 `file_format` 与预期的文件类型匹配时，才会对输入做进一步处理。对于生产就绪的代码，请为意外错误实现妥善的错误处理。

```
def lambda_handler(event, context):
    logger.info("Received event: %s" % json.dumps(event))
    s3Bucket = event.get("s3Bucket")
    s3ObjectKey = event.get("s3ObjectKey")
    metadata = event.get("metadata")
    file_format = s3ObjectKey.lower().split('.')[-1]
    new_key = 'cde_output/' + s3ObjectKey + '.txt'
    if (file_format in FILE_FORMATS):
        afterCDE = generate_image_description(s3Bucket, s3ObjectKey, file_format)
        s3.put_object(Bucket = s3Bucket, Key = new_key, Body=afterCDE)
    return {
        "version" : "v0",
        "s3ObjectKey": new_key,
        "metadataUpdates": []
    }
```

`generate_image_description` 函数调用另外两个函数：第一个用于构造传给 Amazon Bedrock 模型的消息，第二个用于调用模型。它返回模型调用从图像文件中提取出的最终文本输出。

```
def generate_image_description(s3Bucket: str, s3ObjectKey: str, file_format: str) -> str:
    """
    Generate a description for an image.
    Inputs:
        image_file: str - Path to the image file
    Output:
        str - Generated image description
    """
    messages = _llm_input(s3Bucket, s3ObjectKey, file_format)
    response = _invoke_model(messages)
    return response['output']['message']['content'][0]['text']
```

`_llm_input` 函数接收作为输入传入的 S3 对象详情以及文件类型（`png`、`jpg`），并按 Amazon Bedrock 所调用模型期望的格式构建消息。

```
def _llm_input(s3Bucket: str, s3ObjectKey: str, file_format: str) -> List[Dict[str, Any]]:
    s3_response = s3.get_object(Bucket = s3Bucket, Key = s3ObjectKey)
    image_content = s3_response['Body'].read()
    message = {
        "role": "user",
        "content": [
            {"text": prompt_prefix},
            {
                "image": {
                    "format": file_format,
                    "source": {
                        "bytes": image_content
                    }
                }
            },
            {"text": prompt_suffix}
        ]
    }
    return [message]
```

`_invoke_model` 函数使用 Amazon Bedrock runtime 客户端调用 `converse` API。该 API 返回模型生成的响应。`inferenceConfig` 设置中的 `maxTokens` 与 `temperature` 值分别用于限制响应长度、让响应更具确定性（减少随机性）。

```
def _invoke_model(messages: List[Dict[str, Any]]) -> Dict[str, Any]:
    """
    Call the Bedrock model with retry logic.
    Input:
        messages: List[Dict[str, Any]] - Prepared messages for the model
    Output:
        Dict[str, Any] - Model response
    """
    for attempt in range(MAX_RETRIES):
        try:
            response = bedrock.converse(
                modelId=MODEL_ID,
                messages=messages,
                inferenceConfig={
                    "maxTokens": MAX_TOKENS,
                    "temperature": 0,
                }
            )
            return response
        except Exception as e:
            print(e)
    
    raise Exception(f"Failed to call model after {MAX_RETRIES} attempts")
```

## Amazon S3 CDE 配置的最佳实践

为 Amazon S3 数据源设置 CDE 时，请考虑以下最佳实践：

- 使用**条件规则**，只处理需要转换的特定文件类型。
- 用 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) **监控 Lambda 执行**，以跟踪处理错误与性能。
- **为 Lambda 函数设置合适的超时值**，尤其是在处理大文件时。
- **考虑增量同步**，只处理 S3 存储桶中新增或修改过的文档。
- **使用文档属性**来跟踪哪些文档已由 CDE 处理。
