# 认识 Boti：借助 Amazon Bedrock 改变布宜诺斯艾利斯市民获取政府信息方式的 AI 助手

*本文与来自布宜诺斯艾利斯政府的 Julieta Rappan、Macarena Blasi 和 María Candela Blanco 共同撰写。*

布宜诺斯艾利斯政府持续致力于改善市民服务。2019 年 2 月，该政府推出了一款名为 Boti 的 AI 助手，通过阿根廷使用最广泛的消息服务 WhatsApp 提供服务。借助 Boti，市民可以便捷快速地获取各种城市信息，例如续签驾照、获取医疗服务以及了解文化活动。这款 AI 助手已成为首选的沟通渠道，每月促成超过 300 万次对话。

随着 Boti 日益普及，布宜诺斯艾利斯政府希望提供新的对话体验，利用 [生成式 AI](https://aws.amazon.com/ai/generative-ai/) 的最新进展。市民经常面临的一个挑战是，在这座城市复杂的办事流程中摸索。市政府的[网站](https://buenosaires.gob.ar/gobierno/atencion-ciudadana/tramites)包含 1,300 多项政府办事流程，每一项都有自身的逻辑、细微差别和例外情况。市政府认识到，Boti 可以通过直接回答市民问题、将他们引导至正确的办事流程，来改善这些信息的获取。

为试点这一新方案，布宜诺斯艾利斯政府与 [AWS Generative AI Innovation Center（GenAIIC）](https://aws.amazon.com/ai/generative-ai/innovation-center/)展开合作。两支团队共同使用 [LangGraph](https://www.langchain.com/langgraph) 和 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 开发了一款 agentic AI 助手。该解决方案包含两个主要组件：输入 guardrail 系统和政府办事流程 agent。输入 guardrail 使用一个定制的 LLM 分类器来分析传入的用户查询，根据请求内容决定批准还是拦截。获批的请求由政府办事流程 agent 处理，它会检索相关的流程信息并生成响应。由于大多数用户查询只关注单一办事流程，我们开发了一套新颖的推理检索系统来提高检索准确性。该系统首先检索对比摘要，以消除相似流程之间的歧义，然后应用大语言模型（large language model，LLM）选出最相关的结果。agent 利用这些信息，以 Boti 特有的风格组织响应，用阿根廷的 Rioplatense 西班牙语方言输出简短、实用且富有表现力的消息。我们重点关注这一方言的显著语言特征，包括 voseo（使用“vos”而非“tú”）和 periphrastic future（在动词前使用“ir a”）。

在本文中，我们深入探讨这一 agentic AI 系统的实现。首先概览解决方案，介绍其设计和主要特性。然后讨论 guardrail 和 agent 这两个子组件，并评估它们的性能。我们的评估表明，guardrails 能有效拦截有害内容，包括冒犯性语言、有害观点、prompt injection 尝试和不道德行为。借助推理检索器，agent 的 top-1 检索准确率最高达到 98.9%，比标准的检索增强生成（retrieval-augmented generation，RAG）方法提升 12.5–17.5%。领域专家发现，Boti 的响应在 voseo 使用上的准确率为 98%，在 periphrastic future 使用上的准确率为 92%。这一解决方案的可喜成果，开启了市民与政府互动的新时代。

## 解决方案概览

布宜诺斯艾利斯政府与 GenAIIC 使用 Amazon Bedrock 和 LangGraph 构建了一个 agentic AI 助手，其中包含用于保障交互安全的输入 guardrail 系统，以及用于回答用户问题的政府办事流程 agent。该 workflow 如下图所示。

![包含用于保障交互安全的输入 guardrail 系统和用于回答用户问题的政府办事流程 agent 的 AI 助手 workflow](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/06/ML-17604-agent-1.png)

流程从用户提交问题开始。该问题会并行传递给输入 guardrail 系统和政府办事流程 agent。输入 guardrail 系统判断问题是否包含有害内容。如果触发，它会停止图执行，并引导用户转而询问政府办事流程相关的问题。否则，agent 继续组织其响应。agent 要么调用检索工具，从存储在 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 中的政府办事流程获取相关上下文和元数据，要么直接响应用户。输入 guardrail 和政府办事流程 agent 都使用 [Amazon Bedrock Converse API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.html) 进行 LLM 推理。该 API 提供对多种 LLM 的访问，帮助我们针对不同子任务优化性能和延迟。

## 输入 guardrail 系统

输入 guardrails 有助于防止 LLM 系统处理有害内容。尽管 [Amazon Bedrock Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html) 提供一种实现方式，可针对特定词语、内容或敏感信息进行过滤，但我们开发了一套定制方案。这为我们提供了更大的灵活性，可针对 Rioplatense 西班牙语优化性能，并监控特定类型的内容。下图展示了我们的方法：LLM 分类器会分配一个主类别（“批准”或“拦截”）以及一个更详细的子类别。

![展示 LLM 将内容分类为批准或拦截类别的输入 guardrail 系统](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/06/ML-17604-guardrails.png)

获批的查询属于政府办事流程 agent 的处理范围。它们包括聚焦政府办事流程的相关请求，以及低风险的闲聊类问题（agent 会直接回应）。被拦截的查询包含 Boti 应避免的高风险内容，包括冒犯性语言、有害观点、prompt injection 攻击或不道德行为。

我们在一个包含正常和有害用户查询的数据集上评估了输入 guardrail 系统。该系统成功拦截了 100% 的有害查询，但偶尔也会将正常查询标记为有害。这种性能平衡确保 Boti 能提供有用的信息，同时为用户保持安全、适当的交互。

## Agent 系统

政府办事流程 agent 负责回答用户问题。它决定何时使用检索工具获取相关流程信息，并以 Boti 特有的风格生成响应。在以下小节中，我们考察这两个过程。

### 推理检索器

agent 可以使用检索工具，提供关于政府办事流程的准确且最新的信息。检索工具通常采用 RAG 框架，在用户查询与包含以 embedding 形式存储的文档块的知识库之间执行语义相似度搜索，然后将最相关的样本作为上下文提供给 LLM。然而，政府办事流程给这一标准方法带来了挑战。相关的流程（例如续签和补印驾照）可能难以区分。此外，每个用户问题通常只需要某一特定流程的信息。标准 RAG 方法返回的块混杂在一起，增加了生成错误响应的可能性。

为更好地区分政府办事流程，布宜诺斯艾利斯团队与 GenAIIC 开发了一种推理检索方法，使用对比摘要和 LLM 选择。下图概述了这一方法。

![推理检索器 (1) 从知识库检索 M 条对比摘要，(2) 执行可选的基于 LLM 的推理步骤以选出最相关的结果，(3) 检索 N 项全文流程](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/06/ML-17604-reasoning-retriever-1.png)

检索前必要的预处理步骤是创建政府办事流程知识库。为同时捕捉流程中包含的关键信息以及它们之间的关联，我们创建了对比摘要。每条摘要包含基本信息（例如流程的目的、目标受众）和内容信息（例如费用、步骤和要求）。我们将基础摘要聚成小组，平均每组 5 条，并使用 LLM 生成描述，说明每项流程与其相邻流程的差异。我们将这些区分性描述附加到基础信息中，形成最终摘要。我们注意到，这种方法与 [Anthropic 的 Contextual Retrieval](https://www.anthropic.com/news/contextual-retrieval) 有相似之处，后者会在文档块前添加解释性上下文。

知识库就绪后，我们便可以根据用户查询检索相关的政府办事流程。推理检索器完成三个步骤：

- **检索 *M* 条摘要**：我们使用语义搜索检索 1 到 *M* 条对比摘要。
- **可选推理**：在某些情况下，初次检索会出现相似流程。为确保将最相关的流程返回给 agent，我们应用一个可选的 LLM 推理步骤。该步骤的触发条件是：第一次与第二次检索得分的比值低于阈值。LLM 遵循思维链（chain-of-thought，CoT）过程，将用户查询与检索到的摘要进行比较。它会丢弃不相关的流程，并按相关性对剩余流程重新排序。如果用户查询足够具体，这一过程通常只返回一个结果。通过有选择地应用这一推理步骤，我们在保持高检索准确率的同时，将延迟和 token 使用量降到最低。
- **检索 *N* 项全文流程**：确定最相关的流程后，我们从 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 表中获取它们的完整文档和元数据。元数据包含来源 URL 和流程情感等信息。agent 通常收到 1 到 *N* 个结果，其中 *N* ≤ *M*。

agent 在其上下文窗口中接收检索到的全文流程。它遵循自身的 CoT 过程，在生成答案时确定相关内容及 URL 来源归属。

我们使用一个由已知来源流程生成的 1,908 个问题组成的合成数据集，将推理检索器与标准 RAG 技术进行了评估对比。性能通过判断每个问题的正确流程是否出现在 top-k 检索结果中来衡量。下图比较了不同模型下各方法的 top-k 检索准确率，按性能从左到右递增排列。这些指标根据每项流程的网页访问频率按比例加权，确保我们的评估反映真实的使用模式。

![标准 RAG 技术与推理检索器的 top-k 检索准确率](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/05/ML-17604-top-k-accuracy.png)

前三种方法代表标准的基于向量的检索方法。第一种方法 Section Titan，按文档章节对流程进行分块，目标约为每块 250 个单词，然后使用 [Amazon Titan Text Embeddings v2](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html) 对块进行 embedding。第二种方法 Summaries Titan，使用相同的 embedding 模型对流程摘要进行 embedding。通过 embedding 摘要而非文档文本，检索准确率提升了 7.8–15.8%。第三种方法 Summaries Cohere，使用 Amazon Bedrock 上的 Cohere Multilingual v3 对流程摘要进行 embedding。与 Amazon Titan embedding 模型相比，Cohere Multilingual embedding 模型在检索准确率上有显著提升，所有 top-k 值均超过 90%。

接下来三种方法使用推理检索器。我们使用 Cohere Multilingual 模型对流程摘要进行 embedding，在初次检索步骤中检索 10 条摘要，并可选地应用基于 LLM 的推理步骤，使用 Amazon Bedrock 上的 Anthropic Haiku 3、Claude 3 Sonnet 或 Claude 3.5 Sonnet。三种推理检索器都持续优于标准 RAG 技术，top-k 准确率提高了 12.5–17.5%。Anthropic 的 Claude 3.5 Sonnet 表现最佳，top-1 准确率达到 98.9%。这些结果展示了将基于 embedding 的检索与 LLM 驱动的推理相结合，如何提升 RAG 性能。

### 答案生成

收集到必要信息后，agent 会使用 Boti 特有的沟通风格进行响应：用 Rioplatense 西班牙语给出简洁、实用的消息。我们通过 prompt engineering 保持了这一风格，具体要求如下：

- **个性** – 传达温暖友好的语气，为日常问题提供快速解决方案
- **响应长度** – 将响应限制在几句话以内
- **结构** – 使用列表组织内容，并用粗体突出关键信息
- **表达** – 使用 emoji 标记重要要求并添加视觉提示
- **方言** – 融入 Rioplatense 语言特征，包括 voseo、periphrastic future 以及地区词汇（例如“acordate”、“entrar”、“acá”和“allá”）。

政府办事流程常常涉及敏感话题，例如事故、健康或安全。为实现恰当的响应，我们将情感分析作为元数据纳入知识库。这使我们的系统能够路由到不同的 prompt 模板。敏感话题会被导向减少 emoji 使用、采用更具同理心语言的 prompt，而中性话题则使用标准模板。

下图展示了一个关于借阅图书馆书籍问题的示例响应。为方便起见，已将其翻译成英文。

![以西班牙语和英文展示的关于借阅图书馆书籍问题的示例响应](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/06/ML-17604-examples-1.png)

为验证我们的 prompt engineering 方法，布宜诺斯艾利斯政府的领域专家抽查了 Boti 的响应样本。他们的分析证实，响应高度贴合 Rioplatense 西班牙语，voseo 使用准确率为 98%，periphrastic future 使用准确率为 92%。

## 结论

本文介绍了布宜诺斯艾利斯政府与 GenAIIC 构建的 agentic AI 助手，用于回答市民关于政府办事流程的问题。该解决方案包含两个主要组件：输入 guardrail 系统（帮助防止系统响应有害的用户查询）和政府办事流程 agent（检索相关信息并生成响应）。输入 guardrails 能有效拦截有害内容，包括带有冒犯性语言、有害观点、prompt injection 和不道德行为的查询。政府办事流程 agent 采用新颖的推理检索方法来消除相似政府办事流程之间的歧义，top-1 检索准确率最高达到 98.9%，比标准 RAG 方法提升 12.5–17.5%。通过 prompt engineering，响应以 Boti 的语气用 Rioplatense 西班牙语输出。领域专家对 Boti 的语言表现评价很高，voseo 使用准确率为 98%，periphrastic future 使用准确率为 92%。

随着生成式 AI 不断进步，我们期望持续改进解决方案。Amazon Bedrock 中可用的 LLM 目录不断扩充，使我们能够尝试更新、更强大的模型。这既包括本文方案中所探索的处理文本的模型，也包括处理语音的模型，后者可实现直接的语音到语音交互。我们还可以探索 Amazon Bedrock 的 fine-tuning 能力，对模型进行定制，使其更好地捕捉 Rioplatense 西班牙语的语言特征。除模型改进之外，我们还可以迭代 agent 框架。agent 的工具集可以扩展，以支持与政府办事流程相关的其他任务，例如账户创建、表单填写和预约安排。随着市政府为市民开发新的体验，我们可以考虑实现多 agent 框架，由政府办事流程 agent 这样的专门 agent 处理特定任务。
