# 为 Amazon Bedrock Knowledge Bases 推出多模态检索

我们宣布 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 的多模态检索正式可用。这项新能力在文本和图像之上增加了对视频和音频内容的原生支持。借助它，你可以构建检索增强生成（Retrieval Augmented Generation，RAG）应用，跨文本、图像、音频和视频搜索与检索信息——所有这些都在一项完全托管的服务中完成。

现代企业以多种格式存储有价值的信息。产品文档包含图表和截图，培训材料包含教学视频，客户洞察则记录在会议录音中。在此之前，构建能够有效跨这些内容类型搜索的人工智能（artificial intelligence，AI）应用，需要复杂的自定义基础设施和大量工程投入。

此前，Bedrock Knowledge Bases 使用基于文本的 embedding 模型进行检索。虽然它支持文本文档和图像，但图像必须使用基础模型（foundation model，FM）或 [Bedrock Data Automation](https://aws.amazon.com/bedrock/bda/) 处理以生成文本描述——这种文本优先的方式会丢失视觉上下文，并阻碍视觉搜索能力。视频和音频需要自定义的外部预处理流水线。现在，借助多模态 embedding，检索器在单个 embedding 模型中原生支持文本、图像、音频和视频。

借助 Bedrock Knowledge Bases 中的多模态检索，你现在可以用单一统一的工作流，从文本、图像、视频和音频中摄取、索引和检索信息。内容通过保留视觉和音频上下文的多模态 embedding 进行编码，使应用能够跨媒体类型找到相关信息。你甚至可以用图像搜索视觉上相似的内容，或在视频中定位特定场景。

在本文中，我们将指导你构建多模态 RAG 应用。你将了解多模态 Knowledge Base 的工作原理，如何根据内容类型选择合适的处理策略，以及如何通过控制台和代码示例来配置和实现多模态检索。

## 理解多模态 Knowledge Base

Amazon Bedrock Knowledge Bases 会自动完成整个 RAG 工作流：从数据源摄取内容，解析并分块为可搜索的片段，将片段转换为向量 embedding，并存储在向量数据库中。检索时，用户查询会被 embedding 并与已存储的向量匹配，以找到语义相似的内容，从而增强发送给基础模型的 prompt。

有了多模态检索，该工作流现在可以通过两种处理方式，在文本之外处理图像、视频和音频。[Amazon Nova Multimodal Embeddings](https://docs.aws.amazon.com/ai/responsible-ai/nova-multimodal-embeddings/overview.html) 将内容原生编码到统一的向量空间中，支持跨模态检索：你可以用文本查询检索视频，或用图像搜索视觉内容。

另一种方式是，Bedrock Data Automation 在 embedding 之前将多媒体转换为丰富的文本描述和转录文本，从而对口语内容提供高准确度的检索。选择哪一种取决于对你的用例而言，视觉上下文还是语音精度更为重要。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ML-20078-image-1.png)

我们将在本文探讨这些方法中的每一种。

### Amazon Nova Multimodal Embeddings

[Amazon Nova Multimodal Embeddings](https://docs.aws.amazon.com/ai/responsible-ai/nova-multimodal-embeddings/overview.html) 是首个统一的 embedding 模型，可将文本、文档、图像、视频和音频编码到单个共享向量空间中。内容无需转换为文本即可原生处理。该模型支持文本最多 8,172 个 token、视频/音频片段最多 30 秒，可处理 200 多种语言，并提供四种 embedding 维度（默认 3072 维，以及 1,024、384、256），以平衡准确性和效率。Bedrock Knowledge Bases 会自动将视频和音频切分为可配置的片段（5-30 秒），每个片段独立进行 embedding。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ML-20078-image-3.png)

对于视频内容，Nova embedding 会捕获视觉元素——场景、物体、运动和动作——以及音乐、声响和环境噪声等音频特征。对于口语对话对你的用例很重要的视频，你可以使用 Bedrock Data Automation 在视觉描述之外提取转录文本。对于独立的音频文件，Nova 会处理音乐、环境声和音频模式等声学特征。这种跨模态能力支持以下用例：用文字描述视觉场景来检索匹配的视频、上传参考图片查找相似产品，或在影像中定位特定动作——所有这些都无需预先存在的文本描述。

**最适合：** 产品目录、视觉搜索、制造视频、体育影像、监控摄像头，以及视觉内容主导用例的场景。

### Amazon Bedrock Data Automation

Bedrock Data Automation 采用不同的方式：在 embedding 之前将多媒体内容转换为丰富的文本表示。对于图像，它会生成详细描述，包括物体、场景、图中的文字以及空间关系。对于视频，它会生成逐场景摘要，识别关键视觉元素，并提取画面上的文字。对于带语音的音频和视频，Bedrock Data Automation 提供带时间戳和说话人识别的准确转录文本，以及概括所讨论要点的片段摘要。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ML-20078-image-5.png)

转换为文本后，这些内容会被分块，并使用 [Amazon Titan Text Embeddings](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html) 或 Amazon Nova Multimodal Embeddings 等文本 embedding 模型进行 embedding。这种文本优先的方式能够对口语内容实现高准确度的问答——当用户询问会议中的具体发言或播客中讨论的话题时，系统会搜索精确的转录文本，而非音频 embedding。这使得它对于需要精确引述和逐字记录以用于审计轨迹的合规场景、会议分析、客服通话挖掘，以及需要检索和验证特定口语信息的用例尤其有价值。

**最适合：** 会议、网络研讨会、访谈、播客、培训视频、支持通话，以及需要精确检索特定发言或讨论的场景。

## 用例场景：电商的视觉商品搜索

多模态 Knowledge Base 可用于多种应用，从提升客户体验、员工培训，到维护运营和法律分析。传统电商搜索依赖文本查询，要求客户用恰当的关键词表达自己要找什么。当客户在别处见过某件商品、手头有喜欢的物品照片，或想找到与视频中相似的商品时，这种方式就失效了。现在，客户可以用文本描述搜索你的商品目录、上传自己拍摄的商品图片，或引用视频中的某个场景来查找匹配商品。系统会将查询的 embedding 表示（无论是文本、图像还是视频）与商品库存的多模态 embedding 进行比较，检索视觉上相似的商品。对于这一场景，Amazon Nova Multimodal Embeddings 是理想选择。商品发现本质上是视觉性的——客户关心颜色、款式、形状和视觉细节。通过将商品图片和视频编码到 Nova 统一向量空间，系统基于视觉相似度进行匹配，而不依赖可能遗漏细微视觉特征的文本描述。虽然完整的推荐系统还会纳入客户偏好、购买历史和库存情况，但从多模态 Knowledge Base 检索提供了基础能力：无论客户选择如何搜索，都能找到视觉上相关的商品。

## 控制台演练

在以下部分，我们将梳理为电商商品搜索示例设置和测试多模态 Knowledge Base 的高级步骤。我们创建一个包含智能手机商品图片和视频的 Knowledge Base，然后演示客户如何使用文本描述、上传的图片或视频引用来搜索。[GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/rag/knowledge-bases/features-examples/06-multi-modal-rag/nova-mme-multimodal-rag/multimodal-knowledge-bases.ipynb)提供了一个引导式 notebook，你可以照着它在自己的账户中部署该示例。

### 前提条件

开始之前，请确保具备以下先决条件：

- 一个具有相应服务访问权限的 AWS 账户
- 一个 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色，具有访问 Amazon Bedrock 和 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）的相应权限

### 提供 Knowledge Base 详情和数据源类型

首先打开 Amazon Bedrock 控制台并[创建新的 Knowledge Base](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-multimodal-create.html)。为 Knowledge Base 提供一个描述性名称，并选择数据源类型——在本例中为存储商品图片和视频的 [Amazon S3](https://aws.amazon.com/pm/serv-s3/)。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ML-20078-image-6.png)

### 配置数据源

连接包含商品图片和视频的 S3 存储桶。对于解析策略，选择 **Amazon Bedrock default parser**。由于我们使用 Nova Multimodal Embeddings，图片和视频会被原生处理并直接 embedding 到统一向量空间中，保留其视觉特征，无需转换为文本。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ML-20078-image-7.png)

### 配置数据存储和处理

选择 Amazon Nova Multimodal Embeddings 作为 embedding 模型。这一统一的 embedding 模型会将商品图片和客户查询编码到同一向量空间，实现跨模态检索：文本查询可以检索图片，图片查询可以找到视觉上相似的商品。在本例中，我们使用 [Amazon S3 Vectors](https://aws.amazon.com/s3/features/vectors/) 作为向量存储（你也可以选择其他可用的向量存储），它提供经济高效且持久的存储，针对大规模向量数据集进行了优化，同时保持亚秒级查询性能。你还需要通过指定 S3 位置来配置多模态存储目的地。Knowledge Bases 使用该位置存储从数据源中提取的图片和其他媒体。当用户查询 Knowledge Base 时，会从该存储中检索相关媒体。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ML-20078-image-8.png)

### 检查并创建

检查配置设置，包括 Knowledge Base 详情、数据源配置、embedding 模型选择（我们使用具有 3072 向量维度的 Amazon Nova Multimodal Embeddings v1；更高维度提供更丰富的表示，你可以使用 1,024、384 或 256 等更低维度来优化存储和成本）以及向量存储设置（Amazon S3 Vectors）。确认一切无误后，创建你的 Knowledge Base。

### 创建摄取任务

创建完成后，[启动同步过程](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-multimodal-add-data-source-and-ingest.html#kb-multimodal-start-ingestion)以摄取商品目录。Knowledge Base 会处理每张图片和视频，生成 embedding 并存储在托管向量数据库中。监控同步状态，确认文档已成功建立索引。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ML-20078-image-9.png)

### 使用 prompt 中的文本作为输入测试 Knowledge Base

Knowledge Base 就绪后，在控制台中使用文本查询进行测试。用 “A metallic phone cover” 之类的商品描述（或任何与你的商品媒体相关的等效描述）进行搜索，以验证基于文本的检索在整个目录中正常工作。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ML-20078-image-11.png)

### 使用参考图片测试 Knowledge Base 并检索不同模态

现在来到强大的部分——视觉搜索。上传你想查找商品的参考图片。例如，假设你在另一个网站上看到一款手机壳，想在自己的目录中找到相似商品。只需上传图片，无需额外的文本 prompt。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ML-20078-image-13.png)

多模态 Knowledge Base 会从上传的图片中提取视觉特征，并从目录中检索视觉上相似的商品。如结果所示，系统会返回具有相似设计图案、颜色或视觉特征的手机壳。请注意 **Source** **details** 面板中与每个片段关联的元数据。`x-amz-bedrock-kb-chunk-start-time-in-millis` 和 `x-amz-bedrock-kb-chunk-end-time-in-millis` 字段指示该片段在源视频中的精确时间位置。以编程方式构建应用时，你可以利用这些时间戳提取并展示与查询匹配的特定视频片段，从而实现“跳转到相关时刻”或直接从源视频生成剪辑等功能。这种跨模态能力改变了购物体验——客户不再需要用语言描述想要什么；他们可以直接展示给你看。

### 使用参考图片测试 Knowledge Base 并使用 Bedrock Data Automation 检索不同模态

接下来我们看看，如果在数据源设置时配置了 Bedrock Data Automation 解析，结果会是什么样子。在以下截图中，请注意 **Source details** 面板中的转录文本部分。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/09/ML-20078-image-14.png)

对于每个检索到的视频片段，Bedrock Data Automation 会自动生成详细的文本描述——在本例中，描述了这款智能手机的金属玫瑰金饰面、摄影棚灯光和视觉特征。这段转录文本直接显示在测试窗口中，与视频并列，提供丰富的文本上下文。你既能获得来自多模态 embedding 的视觉相似度匹配，也能获得详细的产品描述，后者可以回答有关功能、颜色、材质以及视频中可见的其他属性的具体问题。

### 清理

要清理资源，请完成以下步骤，从删除 Knowledge Base 开始：

- 在 Amazon Bedrock 控制台上，选择 **Knowledge Bases**
- 选择你的 Knowledge Base，并记录 IAM 服务角色名称和 S3 Vector 索引 ARN
- 选择 **Delete** 并确认

要删除作为向量存储的 S3 Vector，请使用以下 [AWS Command Line Interface（AWS CLI）](https://aws.amazon.com/cli/)命令：

```
aws s3vectors delete-index --vector-bucket-name YOUR_VECTOR_BUCKET_NAME --index-name YOUR_INDEX_NAME --region YOUR_REGION
aws s3vectors delete-vector-bucket --vector-bucket-name YOUR_VECTOR_BUCKET_NAME --region YOUR_REGION
```

- 在 IAM 控制台上，找到前面记录的角色
- 选择并删除该角色

要删除示例数据集：

- 在 Amazon S3 控制台上，找到你的 S3 存储桶
- 选择并删除你为本教程上传的文件

## 结语

Amazon Bedrock Knowledge Bases 的多模态检索消除了构建跨文本、图像、视频和音频的 RAG 应用的复杂性。凭借对视频和音频内容的原生支持，你现在可以构建全面的 Knowledge Base，从企业数据中释放洞察——而不仅限于文本文档。

在 Amazon Nova Multimodal Embeddings 与 Bedrock Data Automation 之间做选择，让你可以针对特定内容进行优化。Nova 统一向量空间为视觉驱动的用例实现跨模态检索，而 Bedrock Data Automation 的文本优先方式为语音密集的内容提供基于转录文本的精确检索。两种方式都能无缝集成到同一完全托管工作流中，免除了自定义预处理流水线的需求。

### 可用性

区域可用性取决于为多模态支持所选的功能，详情请参阅[文档](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-multimodal.html)。
