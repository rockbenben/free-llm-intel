# 使用 AgentCore Observability 监控本地与多云环境的 AI agent

当你部署用 Strands Agents、LangGraph 和 CrewAI 等框架构建的 AI agent 时，你需要对它们的性能具备可观测性。无论它们运行在 Amazon Elastic Kubernetes Service（Amazon EKS）、Amazon Elastic Container Service（Amazon ECS）、AWS Lambda、本地环境，还是 Google Cloud Platform（GCP）或 Microsoft Azure 等其他云平台上，这一点都成立。

[Amazon Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html) 是一个可以按任意框架或模型大规模构建、连接和优化 agent 的平台。虽然 [Amazon Bedrock AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html)（Amazon Bedrock AgentCore 的一项能力）提供了本地云监控工具开箱即不具备的原生追踪、监控与分析能力，但它原生只支持部署在 AWS 云中 AgentCore runtime 上的 agent。如果你的 agent 运行在其他任何地方，就需要额外配置才能把遥测发送到该仪表盘。

本文介绍如何为运行在 AWS 之外的 agent 设置可观测性。你将学会如何在非 AWS 环境中配置 AWS Distro for OpenTelemetry（ADOT）自动埋点，把遥测路由到 AgentCore Observability 仪表盘，并端到端验证整套配置。

## 方案概览

该方案使用在 agent 应用进程内运行的 [AWS Distro for OpenTelemetry（ADOT）](https://aws-otel.github.io/)。ADOT 会自动为 agent 框架埋点，捕获遵循生成式 AI 语义约定的 span，然后使用 SigV4 认证（凭 AWS Identity and Access Management（IAM）凭证）把遥测直接导出到 Amazon CloudWatch 的 OpenTelemetry Protocol（OTLP）端点。

要把 AI agent 的遥测发送到 Amazon Bedrock AgentCore Observability，需要三个核心组件：

- **ADOT 自动埋点**：AWS Distro for OpenTelemetry 负责处理从非 AWS 环境导出遥测的复杂性。
- **IAM 凭证**：ADOT 用这些访问密钥向 CloudWatch 认证，并把 agent 的遥测（traces、metrics 和 logs）转发到 AgentCore Observability 仪表盘。
- **环境变量**：其中包含与路由和认证相关的特定 OpenTelemetry 设置。

如下图所示，这套跨平台可观测性方案整合了多个 AWS 服务。Amazon CloudWatch 作为基础，负责遥测的摄取与存储。Amazon Bedrock AgentCore Observability 增加了面向 AI agent 的专用监控仪表盘。AWS Distro for OpenTelemetry（ADOT）提供跨平台的埋点能力。IAM 则保障你的外部环境与 AWS 之间的认证安全。

图 2：跨平台可观测性架构及所涉及的 AWS 服务

可观测性是负责任 AI 的基础支柱之一。通过把遥测路由到 AgentCore Observability，你可以获得对 agent 推理链、工具调用和模型输出的可见性。这让你能够检测幻觉、监控有害或偏题的回复、跟踪 token 用量以便治理成本，并跨环境审计 agent 的行为。对于运行在 AWS 之外的 agent，这一点尤为关键——缺少集中式的可观测性，有问题的输出可能不被察觉。

## 前置条件

开始之前，请确认你已经具备：

- 一个 AWS 账户：已配置 Amazon Bedrock 模型访问（本演练使用 [Claude Haiku](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-haiku-4-5.html)）。有关按 AWS 区域划分的模型可用性，请参阅 Amazon Bedrock 中[按 AWS 区域支持的模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html)。用于指定的 AgentCore Observability 与指定的日志组。
- 你的账户中已开启 [CloudWatch Transaction Search](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/Enable-TransactionSearch.html)（一次性设置）。
- 在非 AWS 环境中已安装 Python 3.10 或更高版本。
- 具备以下权限的 IAM 用户凭证（访问密钥 ID 与私有访问密钥）：`bedrock:InvokeModel`。`logs:CreateLogGroup`、`logs:CreateLogStream`、`logs:PutLogEvents`。`xray:PutTraceSegments`、`xray:PutTelemetryRecords`、`xray:GetSamplingRules` 和 `xray:GetSamplingTargets`。`cloudwatch:PutMetricData`。
- 你的环境能通过 HTTPS 出站访问 AWS 端点。

## 开启 CloudWatch Transaction Search

如果你还没有开启 Transaction Search，请执行以下命令（每个账户一次）：

```
aws xray update-trace-segment-destination --destination CloudWatchLogs --region us-east-1
```

验证它已经生效：

```
aws xray get-trace-segment-destination --region us-east-1
# Expected: {"Destination": "CloudWatchLogs", "Status": "ACTIVE"}
```

## 工作原理

ADOT 自动埋点（`aws-opentelemetry-distro`）负责处理把遥测从非 AWS 环境导出到 CloudWatch 的复杂性：

- **自动埋点**：`opentelemetry-instrument` 命令把 ADOT 注入 Python 运行时。它会自动为 `boto3`（用于 Amazon Bedrock 调用）和 Strands 框架（用于 agent 推理 span）打补丁，以发出 OpenTelemetry trace。
- **SigV4 认证**：`aws_configurator` 使用 `boto3` 凭证链以 SigV4 签署 OTLP 导出请求。在非 AWS 环境中，这会使用 `AWS_ACCESS_KEY_ID` 和 `AWS_SECRET_ACCESS_KEY` 环境变量。
- **CloudWatch OTLP 端点**：ADOT 把 trace 和日志导出到 CloudWatch 原生 OTLP 摄取端点。`OTEL_EXPORTER_OTLP_LOGS_HEADERS` 头会把日志指向特定的 AgentCore 日志组，CloudWatch 正是据此把数据索引到生成式 AI 可观测性仪表盘下。关于 CloudWatch OTLP 端点 URL 如何确定和配置的细节，请参阅 [CloudWatch OTLP endpoint](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch-OTLPEndpoint.html)。
- **生成式 AI 语义约定**：Strands 的 `[otel]` 包会按 [OpenTelemetry generative AI semantic conventions](https://opentelemetry.io/docs/specs/semconv/gen-ai/) 发出 span，包括 agent 推理步骤、工具调用以及带 token 用量的模型调用。

## 操作演练

按以下步骤在非 AWS 环境中配置并运行一个 Strands agent，并把遥测路由到 AgentCore Observability。

### 步骤 1：安装依赖

在你的非 AWS 环境（本地服务器、GCP 虚拟机、Azure 虚拟机，或任何能上网的计算资源）上执行：

```
pip install "aws-opentelemetry-distro>=0.10.0" boto3 "strands-agents[otel]"
```

`aws-opentelemetry-distro` 包包含 ADOT 自动埋点、AWS 专用的 OTLP 导出器，以及负责 SigV4 认证的 `aws_configurator`。`strands-agents[otel]` 包提供从 Strands 框架发出 OpenTelemetry trace 的能力。

### 步骤 2：配置 AWS 凭证

把你的 IAM 用户凭证设置为环境变量。

```
export AWS_ACCESS_KEY_ID=<your-access-key-id>
export AWS_SECRET_ACCESS_KEY=<your-secret-access-key>
export AWS_REGION=us-east-1
```

**安全提示**：对于生产部署，考虑使用 [IAM Roles Anywhere](https://docs.aws.amazon.com/rolesanywhere/latest/userguide/introduction.html) 而不是长期有效的访问密钥。借助 IAM Roles Anywhere，本地工作负载可以使用 X.509 证书获取临时凭证。

### 步骤 3：设置 OpenTelemetry 环境变量

这些环境变量用于配置 [ADOT 把遥测路由到 AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-get-started.html#enabling-observability-non-runtime-hosted) 仪表盘：

```
export AGENT_OBSERVABILITY_ENABLED=true
export OTEL_PYTHON_DISTRO=aws_distro
export OTEL_PYTHON_CONFIGURATOR=aws_configurator
export OTEL_RESOURCE_ATTRIBUTES="service.name=my-external-agent,aws.log.group.names=/aws/bedrock-agentcore/runtimes/my-external-agent"
export OTEL_EXPORTER_OTLP_LOGS_HEADERS="x-aws-log-group=/aws/bedrock-agentcore/runtimes/my-external-agent,x-aws-log-stream=runtime-logs,x-aws-metric-namespace=bedrock-agentcore"
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_TRACES_EXPORTER=otlp
```

关键配置细节：

- `AGENT_OBSERVABILITY_ENABLED=true` 会激活 ADOT 中面向生成式 AI 的遥测处理。
- `OTEL_PYTHON_DISTRO=aws_distro` 与 `OTEL_PYTHON_CONFIGURATOR=aws_configurator` 激活 AWS 专用的 OpenTelemetry 配置，包括对 CloudWatch OTLP 端点的 SigV4 签名。
- 带 `aws.log.group.names` 的 `OTEL_RESOURCE_ATTRIBUTES` 告诉 CloudWatch 把遥测索引到 AgentCore Observability 仪表盘下。缺少它，trace 会进入通用的 Amazon CloudWatch Logs。
- 带 `x-aws-metric-namespace=bedrock-agentcore` 的 `OTEL_EXPORTER_OTLP_LOGS_HEADERS` 会把以[嵌入式指标格式](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch_Embedded_Metric_Format.html)发送的 metrics 路由到正确的 CloudWatch 命名空间。

### 步骤 4：创建 agent 应用

创建一个名为 `agent_test.py` 的文件，其中包含一个 Strands agent：

```
from strands import Agent
from strands.models.bedrock import BedrockModel
from opentelemetry import baggage
from opentelemetry.context import attach
import time

# Configure the Bedrock model
model = BedrockModel(
    model_id="us.anthropic.claude-haiku-4-5-20251001-v1:0",
    region_name="us-east-1"
)
# Create the agent
agent = Agent(
    model=model,
    system_prompt="You are a helpful travel assistant."
)

# Set session ID for AgentCore session tracking
# All agent calls after attach() share same session ID for multiple requests/responses
session_id = f"external-session-{int(time.time())}"
ctx = baggage.set_baggage("session.id", session_id)
attach(ctx)

# Run the agent
response = agent("What are the top 3 things to do in Tokyo?")
print(response)
```

### 步骤 5：用 ADOT 自动埋点运行

`opentelemetry-instrument` 命令会用 ADOT 包裹你的 Python 进程，自动为 Amazon Bedrock 调用和 Strands 框架操作埋点：

```
opentelemetry-instrument python3.12 agent_test.py
```

agent 的回复会显示在终端中。在幕后，ADOT 捕获 traces、spans 和 logs，并把它们导出到 CloudWatch。

### 步骤 6：在 AgentCore Observability 中验证

执行后两到三分钟内你就能看到遥测数据。打开 Amazon CloudWatch 控制台：

- 选择 **GenAI Observability**，然后选择 **Bedrock AgentCore**。
- 在 **Agents** 标签页中，找到 `my-external-agent`。
- 选择该 agent，以查看会话、trace 和 span 指标。

在选择如何部署你的 AI agent 时，理解不同运行时环境之间在可观测性上的权衡，有助于你做出正确的架构决策。直接部署在 Amazon Bedrock AgentCore runtime 上的 agent 可以享受自动的可观测性配置。运行在非 AWS 环境中的 agent 则需要额外的手动设置，但提供更大的部署灵活性。下面的对比突出了在遥测采集、凭证管理和适用场景上的关键差异，帮助你判断哪种方式最符合你的需求。

| **方面** | **非 AWS 运行时** | **AgentCore runtime** |
| --- | --- | --- |
| 支持的遥测 | ADOT —— 需要手动设置 OTEL 变量 | ADOT —— 自动内置 OTEL 变量 |
| 凭证管理 | IAM 访问密钥/私有密钥，或 IAM Roles Anywhere | 自动（IAM 角色） |
| 最适合 | 本地、GCP、Azure 或其他非 AWS 环境中的 agent | 部署在 AWS 上并使用 AgentCore 的 agent |

## 最佳实践

基于我们的测试，在设置跨平台的 AgentCore Observability 时，我们推荐以下做法：

- **使用一致的命名**：`OTEL_RESOURCE_ATTRIBUTES` 中的 `service.name` 会成为仪表盘上的 agent 名称。请使用能标识环境的描述性名称（例如 `prod-onprem-support-agent` 和 `staging-gcp-research-agent`）。
- **先用 `get-caller-identity` 验证**：运行 agent 之前，先用 `python -c "import boto3; print(boto3.client('sts').get_caller_identity())"` 确认你的凭证可用。如果这一步失败，ADOT 也会静默失败。
- **使用 Python 3.10 或更高版本**：ADOT 要求 Python 3.10 或更高版本。我们推荐 Python 3.12，以获得与所有依赖的最佳兼容性。
- **为多轮对话设置会话 ID**：使用 OpenTelemetry baggage API 传播会话 ID：

```
from opentelemetry import baggage
from opentelemetry.context import attach
ctx = baggage.set_baggage("session.id", "my-session-123")
attach(ctx)
```

- **定期轮换凭证**：对于生产部署，避免使用长期有效的访问密钥。本地工作负载可以考虑 [IAM Roles Anywhere](https://docs.aws.amazon.com/rolesanywhere/latest/userguide/introduction.html)，或者使用你所在云厂商的身份联邦来代入 AWS IAM 角色。

## 结论

Amazon Bedrock AgentCore Observability 并不局限于运行在 AgentCore runtime 上或 AWS 内部的 agent。借助 ADOT 自动埋点、IAM 凭证以及正确的 OpenTelemetry 环境变量，你可以从任何能上网的环境中发送遥测。你的 agent 可以运行在本地、GCP、Azure 或任何其他地方，仍然向同一个 AgentCore Observability 仪表盘汇报。

这套设置只需要一次 `pip install` 和一组环境变量。得到的遥测与 AgentCore runtime 托管的 agent 所产生的完全一致：会话、trace、span 指标和 token 用量，全都在同一个统一视图中。

要开始使用，请克隆 [GitHub 上的示例代码](https://github.com/aws-samples/sample-external-agents-telemetry-on-agentcore-observability)，并按照 README 中的说明在你的环境中配置并运行 agent。

对于已经运行在 AWS 上但不在 AgentCore runtime 中的 agent（EKS、ECS、Lambda），请参阅 [面向 EKS 托管 agent 的 AgentCore Observability](https://github.com/awslabs/agentcore-samples/tree/main/03-integrations/agents-hosted-outside-runtime) 教程。对于运行在 AgentCore runtime 上的 agent，可观测性是自动配置好的。请参阅[为你的 AgentCore 资源添加可观测性](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-configure.html)。
