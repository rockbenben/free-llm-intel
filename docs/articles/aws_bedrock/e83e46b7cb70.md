# 使用 Amazon Bedrock 构建生成式 AI 解决方案

[生成式 AI](https://aws.amazon.com/generative-ai/) 正在彻底改变企业的运营方式、与客户的互动方式以及创新方式。如果你正要踏上构建生成式 AI 驱动解决方案的旅程，或许会想知道如何理顺从挑选合适的模型到管理 prompt、再到落实数据隐私这一系列复杂性。

本文介绍如何利用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的能力在 [Amazon Web Services（AWS）](https://aws.amazon.com/) 上构建生成式 AI 应用，并重点说明在生成式 AI 旅程的每个阶段可以怎样使用 Amazon Bedrock。无论你是经验丰富的 AI 工程师，还是生成式 AI 领域的新手，本指南都有价值，能帮助你充分发挥 Amazon Bedrock 的潜力。

Amazon Bedrock 是一项全托管服务，提供统一的 API，用于访问来自 Anthropic、Cohere、Meta、Mistral AI、AI21 Labs、Stability AI 和 Amazon 等领先 AI 公司的一系列高性能基础模型（FMs）。它提供一整套功能强大的工具与特性，旨在帮助你高效构建生成式 AI 应用，同时遵循安全、隐私和负责任 AI 方面的最佳实践。

## 通过 API 调用 LLM

你希望通过与大语言模型（LLM）进行一次简单直接的单轮交互，把生成式 AI 功能集成到应用中。也许你需要生成文本、回答一个问题，或者根据用户输入给出摘要。Amazon Bedrock 通过统一的 API 访问多样化且领先的 FM，简化了生成式 AI 应用的开发与扩展。它既支持 Amazon 自研模型，也支持领先的 AI 提供商，因此你可以自由试验，而不必被锁定在单一模型或单一提供商上。鉴于 AI 领域的快速演进，你可以无缝切换模型以获得优化后的性能，而无需改写应用。

除了直接访问模型，Amazon Bedrock 还通过 [Amazon Bedrock Marketplace](https://aws.amazon.com/bedrock/marketplace/) 拓展你的选择。该市场让你可以访问 100 多个专用 FM；你可以借助全托管端点来发现、测试并集成新的能力。无论你需要的是文本生成、图像合成方面的最新创新，还是特定领域的 AI，Amazon Bedrock 都能灵活地帮你轻松适配并扩展解决方案。

只需一个 API，你就能保持敏捷，轻松在模型之间切换、升级到最新版本，并以极少的代码改动为生成式 AI 应用做好面向未来的准备。总而言之，Amazon Bedrock 提供以下优势：

- **简单性：** 无需管理基础设施，也无需应对多个 API
- **灵活性：** 试验不同模型，找到最合适的那个
- **可扩展性：** 扩展应用，而无需担心底层资源

要开始使用，可[使用 Chat 或 Text playground 进行试验](https://docs.aws.amazon.com/bedrock/latest/userguide/inference.html)，尝试不同的 FM，并使用 [Converse API](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html) 将 FM 集成到应用中。

在集成了基础的 LLM 功能之后，下一步就是优化性能，并确保你使用的是符合需求的模型。这就引出了评估和比较模型的重要性。

## 为你的用例选择正确的模型

为用例选择合适的 FM 至关重要，但可选方案如此之多，你怎么知道哪一个能为你的应用带来最佳性能？无论是生成更相关的回答、总结信息，还是处理细微复杂的查询，选择最佳模型都是实现最优性能的关键。

你可以使用 [Amazon Bedrock 模型评估](https://docs.aws.amazon.com/bedrock/latest/userguide/evaluation.html)严格测试不同的 FM，找出在你的用例中表现最好的那个。无论你处于开发的早期阶段还是正准备上线，选对模型都会显著影响生成式 AI 解决方案的实际效果。

模型评估过程由以下部分组成：

- **自动评估与人工评估：** 首先使用准确率、稳健性或毒性等自动化评估指标试验不同模型。你也可以引入人工评估者来衡量更主观的因素，例如友好度、风格，或模型与你的品牌语气契合的程度。
- **自定义数据集与指标：** 使用你自己的数据集或预置选项来评估模型性能。针对项目最看重的指标进行定制，确保所选模型符合你的业务或运营目标。
- **迭代式反馈：** 在开发过程中反复运行评估，从而更快地改进。这有助于你并排比较模型，以便在选择适合用例的 FM 时做出数据驱动的决策。

设想你正在为一家电商服务构建客户支持 AI 助手。你可以使用模型评估，用真实客户查询测试多个 FM，评估哪个模型能给出最准确、最友好且最贴合上下文的回答。通过并排比较模型，你可以选出能为客户带来最佳用户体验的模型。在评估并选定理想模型之后，下一步就是确保它与你的业务需求保持一致。现成模型可能表现不错，但要获得真正贴合需求的体验，你还需要更多定制。这就引出生成式 AI 旅程中的下一个重要步骤：让模型个性化，以反映你的业务语境。你需要确保模型生成最准确、最贴合上下文的回答。即便是最好的 FM 也无法获取对你的业务至关重要的最新信息或特定领域信息。为解决这个问题，模型需要使用你的专有数据源，确保其输出反映最新且相关的信息。这时你可以使用检索增强生成（RAG），通过纳入组织独有的知识库来丰富模型的回答。

## 用专有数据丰富模型回答

公开可用的 LLM 在通用知识任务上可能表现不错，但在面对过时信息时会力不从心，或者缺乏来自组织专有数据的上下文。你需要一种方式，为模型提供最相关、最新的洞见，以保证准确性和上下文深度。有两种关键方法可以用来丰富模型回答：

- **RAG：** 使用 RAG 在查询时动态检索相关信息，无需重新训练即可丰富模型回答
- **微调：** 使用 RAG 在专有数据上训练所选模型来定制它，提升其处理组织特定任务或领域知识的能力

我们建议从 RAG 入手，因为它灵活且易于实现。之后如有需要，再通过微调对模型进行更深入的领域适配。RAG 在查询时动态检索相关信息，确保模型回答保持准确并具备上下文感知。在这种方法中，数据首先被处理并索引到向量数据库或类似的检索系统中。当用户提交查询时，Amazon Bedrock 会在这些已索引的数据中搜索，找出相关上下文并注入 prompt。随后模型基于原始查询和检索到的洞见生成回答，无需额外训练。

[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 自动完成 RAG pipeline——包括数据摄取、检索、prompt 增强和引用——从而降低搭建自定义集成的复杂度。通过无缝集成专有数据，你可以确保模型生成准确、上下文丰富且持续更新的回答。

Bedrock Knowledge Bases 支持多种数据类型，可针对业务特定需求定制 AI 生成的回答：

- **非结构化数据：** 从文档、PDF 和电子邮件等以文本为主的数据源中提取洞见
- **结构化数据：** 在数据库、数据湖和数据仓库上启用自然语言查询，无需迁移或预处理数据
- **多模态数据：** 使用 [Amazon Bedrock Data Automation](https://aws.amazon.com/bedrock/bda/) 处理文档和图像中的文本与视觉元素
- **GraphRAG：** 借助基于图的关系增强知识检索，让 AI 理解实体之间的关联，从而给出更贴合上下文的回答

凭借这些能力，Amazon Bedrock 减少数据孤岛，让用实时知识与历史知识丰富 AI 应用变得简单直接。无论处理的是文本、图像、结构化数据集还是相互关联的知识图谱，Amazon Bedrock 都提供全托管、可扩展的解决方案，无需复杂的基础设施。总而言之，在 Amazon Bedrock 上使用 RAG 带来以下优势：

- **最新信息：** 回答中包含来自你知识库的最新数据
- **准确性：** 降低给出错误或不相关回答的风险
- **无需额外基础设施：** 你可以免去搭建和管理自有向量数据库或自定义集成的工作

当模型从最准确、最相关的数据中取用信息时，你可能会发现它的一般行为仍需要打磨——或许是语气、风格，或是对行业特定语言的理解。这时你可以进一步微调模型，让它与业务需求更加契合。

## 让模型贴合业务需求

开箱即用的 FM 提供了很好的起点，但往往缺乏真实应用所需的精确度、品牌语气或行业专长。也许语言风格与你的品牌不符，或者模型在专业术语上表现吃力。你可能已经用 prompt engineering 和 RAG 尝试过用额外上下文来增强回答。尽管这些技术有帮助，但它们有局限（例如，更长的 prompt 会增加延迟和成本），而且模型可能仍然缺乏特定领域任务所需的深厚领域专长。要充分发挥生成式 AI 的潜力，企业需要一种安全地适配模型的方式，确保 AI 生成的回答不仅准确，而且相关、可靠，并与业务目标一致。

Amazon Bedrock 简化了[模型定制](https://aws.amazon.com/blogs/aws/customize-models-in-amazon-bedrock-with-your-own-data-using-fine-tuning-and-continued-pre-training/)，使企业可以用专有数据微调 FM，而无需从零构建模型或管理复杂的基础设施。

Amazon Bedrock 无需重新训练整个模型，而是提供全托管的微调流程，创建基础 FM 的私有副本。这确保你的专有数据保持机密，不会用于训练原始模型。Amazon Bedrock 提供两种强大的技术，帮助企业高效地打磨模型：

- **微调：** 你可以用带标签的数据集训练 FM，提升其在行业特定术语、品牌语气和公司工作流方面的准确性。这让模型无需依赖复杂 prompt 就能生成更精确、更贴合上下文的回答。
- **持续预训练：** 如果你有未标注的领域特定数据，可以使用持续预训练在专业知识上进一步训练 FM，无需人工标注。这种方法对监管合规、领域特定行话或不断演进的业务运营尤为有用。

将用于核心领域专长的微调与用于实时知识检索的 RAG 结合，企业可以打造高度专用的 AI 模型，既保持准确又具备适应性，并确保回答风格与业务目标一致。总而言之，Amazon Bedrock 提供以下优势：

- **隐私受保护的定制：** 安全地微调模型，同时确保你的专有数据保持私有
- **高效：** 在无需从零构建模型这一复杂度的情况下，实现高准确度和领域相关性

随着项目演进，管理和优化 prompt 变得至关重要，尤其是在处理不同迭代版本或测试多个 prompt 版本时。下一步就是精炼 prompt，让模型性能最大化。

## 管理和优化 prompt

随着 AI 项目规模扩大，高效管理多个 prompt 成为越来越大的挑战。跟踪版本、与团队协作以及测试各种变体很快就会变得复杂。缺乏结构化的方法，prompt 管理会拖慢创新、增加成本，让迭代变得笨重。为一个 FM 优化好的 prompt 并不总能很好地迁移到另一个 FM。在某个 FM 上表现良好的 prompt，在另一个上可能产生不一致或不理想的输出，需要大量返工。这让模型切换既耗时又低效，限制了你有效试验不同 AI 能力的能力。如果没有集中的方式来管理、测试和精炼 prompt，AI 开发会变得更慢、成本更高，也更难适应不断变化的业务需求。

Amazon Bedrock 通过 [Amazon Bedrock Prompt Management](https://aws.amazon.com/bedrock/prompt-management/) 简化 prompt engineering，这是一个集成系统，帮助团队轻松创建、精炼、版本化和共享 prompt。无需花费数月手动调整 prompt，Amazon Bedrock 无需额外代码就能加速试验并提升回答质量。Bedrock Prompt Management 引入以下能力：

- **版本管理与协作：** 在共享工作区中管理 prompt 迭代，让团队可以跟踪变更并复用已优化的 prompt。
- **并排对比测试：** 同时比较最多两个 prompt 变体，分析模型行为并找出最有效的格式。
- **自动 prompt 优化：** 根据所选 FM 精炼和改写 prompt，以提升回答质量。你可以选择模型、应用优化，并生成更准确、更贴合上下文的 prompt。

Bedrock Prompt Management 提供以下优势：

- **效率：** 无需编写额外代码即可快速迭代与优化 prompt
- **团队协作：** 通过共享访问和版本控制增强协作
- **有洞见的测试：** 找出哪些 prompt 最适合你的用例

在把 prompt 优化到最佳效果之后，下一个挑战是为给定任务在同一个模型家族内挑选最合适的模型，从而优化应用的成本和延迟。这时智能 prompt 路由可以派上用场。

## 通过智能模型选择提升效率

并非所有 prompt 都需要同等程度的 AI 处理。有些简单直接、需要快速响应，而另一些则需要更深的推理和更多算力。即便更轻、更快的模型也能给出同样有效的回答，对所有请求都使用高性能模型仍会增加成本和延迟。反过来，只依赖较小的模型又可能降低复杂查询的准确性。没有自动化方法，企业就必须为每个请求手动决定使用哪个模型，导致成本上升、效率下降、开发周期变慢。

[Amazon Bedrock Intelligent Prompt Routing](https://aws.amazon.com/bedrock/intelligent-prompt-routing/) 通过为每个请求动态选择最合适的 FM 来优化 AI 性能与成本。你无需手动选择模型，Amazon Bedrock 会在模型家族内自动完成模型选择，确保每个 prompt 都被路由到与其复杂度最匹配的最佳模型。Bedrock Intelligent Prompt Routing 提供以下能力：

- **自适应模型路由：** 自动把简单 prompt 交给轻量模型，把复杂查询交给更先进的模型，在速度与效率之间取得恰当的平衡
- **性能平衡：** 确保只在必要时使用高性能模型，最多可将 AI 推理成本降低 30%
- **轻松集成：** 在模型家族内自动选择正确的模型，简化部署

通过自动化模型选择，Amazon Bedrock 免去手动决策的需要，降低运维开销，并确保 AI 应用在规模化下高效运行。借助 Amazon Bedrock Intelligent Prompt Routing，每个查询都由最高效的模型处理，带来速度、成本节约和高质量的回答。优化 AI 效率的下一步是减少频繁使用的 prompt 中的重复计算。许多 AI 应用需要在多次交互中保持上下文，这可能带来性能瓶颈、成本上升和不必要的处理开销。

## 减少重复处理，加快响应

随着生成式 AI 应用规模扩大，效率与准确性同样关键。反复使用同一上下文的应用——例如文档问答系统（用户对同一文档提出多个问题），或需要维护代码文件上下文信息的编码助手——往往因重复处理而遭遇性能瓶颈和成本上升。当查询中包含冗长的静态上下文时，模型每次都会重新处理未变化的信息：模型反复分析相同内容导致延迟增加，而多余的 token 用量又会推高算力开销。要让 AI 应用保持快速、经济且可扩展，优化 prompt 的复用与处理方式至关重要。

[Amazon Bedrock Prompt Caching](https://aws.amazon.com/bedrock/prompt-caching/) 通过存储 prompt 中频繁使用的部分来提升效率——减少重复计算并改善响应时间。它带来以下优势：

- **处理更快：** 跳过对已缓存 prompt 前缀的不必要重算，提升整体吞吐
- **更低延迟：** 缩短长而重复的 prompt 的处理时间，带来更顺畅的用户体验，对受支持的模型最多可降低 85% 的延迟
- **成本效益：** 通过避免重复的 token 处理来最小化算力资源占用，最多可降低 90% 的成本

借助 prompt 缓存，AI 应用响应更快、运营成本更低，并在保持高性能的同时高效扩展。在 Bedrock Prompt Caching 带来更快响应和成本效益之后，下一步是让 AI 应用超越静态的 prompt-响应交互。这就是 agentic AI 的用武之地，它让应用能够动态编排多步骤流程、自动化决策并驱动智能工作流。

## 用 agentic AI 自动化多步骤任务

随着 AI 应用变得更加复杂，自动化复杂的多步骤任务变得必不可少。你需要一个能与内部系统、API 和数据库交互并自主执行复杂工作流的解决方案。目标是减少人工干预、提升效率，并打造更具动态性和智能的应用。传统 AI 模型是被动的：它们基于输入生成回答，但缺乏规划和执行多步骤任务的能力。Agentic AI 指以自主方式行动的 AI 系统，它把复杂任务拆解为合乎逻辑的步骤、做出决策，并在无需持续人工输入的情况下执行动作。与只对 prompt 做出响应的传统模型不同，agentic AI 模型具备以下能力：

- **自主规划与执行：** 把复杂任务拆成更小的步骤、做出决策，并规划动作以完成工作流
- **能力串联：** 基于单个请求处理一系列动作，让 AI 能够管理那些原本需要人工干预或多次交互的复杂任务
- **与 API 和系统交互：** 连接你的企业系统，自动调用必要的 API 或数据库来获取或更新数据

[Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 借助 FM 规划、编排并执行工作流，实现 AI 驱动的任务自动化。凭借全托管的编排层，Amazon Bedrock 简化了 AI agent 的部署、扩展和管理。Bedrock Agents 提供以下优势：

- **任务编排：** 利用 FM 的推理能力拆解任务、规划执行并管理依赖关系
- **API 集成：** 自动调用企业系统内的 API，与业务应用交互
- **记忆保持：** 在多次交互中保持上下文，让 agent 记住之前的步骤，提供无缝的用户体验

当任务需要多个专用 agent 时，[Amazon Bedrock 支持多 agent 协作](https://aws.amazon.com/blogs/aws/introducing-multi-agent-collaboration-capability-for-amazon-bedrock/)，确保 agent 之间高效协同，同时减轻人工编排的负担。这解锁以下能力：

- **监督者 agent 协调：** 由监督者 agent 把任务委派给专用子 agent，实现工作负载的最优分配
- **高效任务执行：** 支持并行任务执行，加快处理速度并提升准确性
- **灵活的协作模式：** 你可以在以下模式中选择：  **完全编排的监督者模式：** 由中心 agent 管理工作流全流程，提供无缝协调 **路由模式：** 基础任务绕过监督者直接交给子 agent，减少不必要的编排
- **无缝集成：** 与企业 API 和内部知识库协同工作，让跨多个领域的业务运营自动化变得简单直接

通过使用多 agent 协作，你可以提高任务成功率、缩短执行时间并提升准确性，让 AI 驱动的自动化在真实世界的复杂工作流中更有效。总而言之，agentic AI 提供以下优势：

- **自动化：** 减少复杂流程中的人工干预
- **灵活性：** agent 可以适应需求变化，或按需收集更多信息
- **透明性：** 你可以使用 trace 能力调试并优化 agent 行为

虽然用 agent 自动化任务可以简化运营，但处理敏感信息、落实隐私保护至关重要，尤其是在与用户数据和内部系统交互时。随着应用变得更为复杂，安全与合规挑战也随之而来。

## 维护安全性、隐私和负责任 AI 实践

当你把生成式 AI 集成到业务中，安全、隐私和合规就成为关键问题。AI 生成的回答必须安全、可靠并与组织策略一致，以避免违反品牌准则或监管政策，并且不得包含不准确或误导性的回答。

[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 提供一个全面的框架，用于增强 AI 生成输出的安全性、隐私与准确性。借助内置的防护措施，你可以执行策略、过滤内容，并提升 AI 交互的可信度。Bedrock Guardrails 提供以下能力：

- **内容过滤：** 拦截用户输入和模型回答中的不良话题与有害内容。
- **隐私保护：** 检测并脱敏个人可识别信息（PII）和机密数据等敏感信息，帮助防止数据泄露。
- **自定义策略：** 定义组织特定的规则，确保 AI 生成内容符合内部策略和品牌准则。
- **幻觉检测：** 通过以下能力识别并过滤掉未以你的数据源为依据的回答：  **上下文依据检查：** 通过对照企业数据源验证模型回答，确保其事实正确且相关。当输出包含未经验证或不相关的信息时检测出幻觉。 **用于提升准确性的自动推理：** 通过对 AI 输出应用数学上严谨的逻辑与结构化推理来验证事实正确性，从 *trust me* 迈向 *prove it*。

有了安全与隐私措施，你的 AI 解决方案不仅强大，而且负责任。不过，如果你已经在自定义模型上投入了大量资源，下一步就是将它们无缝集成到 Amazon Bedrock 中。

## 通过 Amazon Bedrock Custom Model Import 使用现有的自定义模型

如果你已经在 Amazon Bedrock 之外投入开发了自定义模型，并希望在不管理额外基础设施的情况下将它们集成到新的生成式 AI 解决方案中，请使用 [Amazon Bedrock Custom Model Import](https://aws.amazon.com/bedrock/custom-model-import/)。

Bedrock Custom Model Import 包含以下能力：

- **无缝集成：** 把你的自定义模型导入 Amazon Bedrock
- **统一 API 访问：** 通过同一个 API 与基础模型和自定义模型交互
- **运营效率：** 让 Amazon Bedrock 处理模型生命周期和基础设施管理

Bedrock Custom Model Import 提供以下优势：

- **成本节约：** 最大化现有模型的价值
- **简化管理：** 通过整合模型运维来降低开销
- **一致性：** 在多个模型之间保持一致统一的开发体验

通过导入自定义模型，你可以沿用此前的投入。要充分释放模型和 prompt 结构的潜力，你可以自动化更复杂的工作流，组合多个 prompt 并与其他 AWS 服务集成。

## 用 Amazon Bedrock Flows 自动化工作流

你需要构建涉及多个 prompt、并与其他 AWS 服务或业务逻辑集成的复杂工作流，但又希望避免大量编码。

[Amazon Bedrock Flows](https://aws.amazon.com/bedrock/flows/) 具备以下能力：

- **可视化构建器：** 拖放组件来创建工作流
- **工作流自动化：** 把 prompt 与 AWS 服务关联起来并自动化执行序列
- **测试与版本管理：** 直接在控制台中测试 flow 并管理版本

Amazon Bedrock Flows 提供以下优势：

- **无代码方案：** 无需编写代码即可构建工作流
- **速度：** 加速复杂应用的开发与部署
- **协作：** 在团队内共享和管理工作流

工作流现在已实现自动化并完成优化，你几乎可以部署生成式 AI 驱动的解决方案了。最后阶段是确保生成式 AI 解决方案能够高效扩展，并在需求增长时保持高性能。

## 通过监控和日志闭环 AI 运营

在准备把生成式 AI 应用投入生产时，实现完善的日志记录与可观测性至关重要，可用于监控系统健康状况、验证合规性并快速排查问题。Amazon Bedrock 提供内置的可观测性能力，与 AWS 监控工具无缝集成，让团队能够跟踪性能、理解使用模式并保持运营掌控

- **模型调用日志：** 你可以启用模型调用的详细日志，捕获输入 prompt 和输出回答。这些日志可以流式传输到 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 或 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3)，用于实时监控或长期分析。日志可通过 AWS 管理控制台或 `CloudWatchConfig` API 进行配置。
- **CloudWatch 指标：** Amazon Bedrock 开箱即用提供丰富的运维指标，包括：  调用次数 token 用量（输入/输出） 响应延迟 错误率（例如无效输入和模型失败）

这些能力对于放心地大规模运行生成式 AI 解决方案至关重要。借助 CloudWatch，你可以获得覆盖从输入 prompt 到模型行为的完整 AI pipeline 的可见性，从而在应用成长过程中轻松保持可用性、性能与合规性。

## 完成并扩展你的生成式 AI 解决方案

你已准备好部署生成式 AI 应用，需要在提供可靠性能的同时高效扩展。无论你是要应对不可预测的工作负载、增强韧性，还是需要稳定的吞吐量，都必须选择合适的扩展方式。Amazon Bedrock 提供三种灵活的扩展选项，可针对你的工作负载需求来调整基础设施：

- **按需：** 从按需扩展的灵活性开始，只为实际用量付费。这一选项适合早期部署或流量多变、不可预测的应用。它带来以下优势：  无需承诺。只为处理的 token（输入/输出）付费。适合动态或波动的工作负载。
- **跨区域推理： **当流量增长或变得不可预测时，你可以使用[跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)把算力分布到多个 AWS 区域来处理突发流量，在不增加额外成本的情况下提升可用性。它带来以下优势：  突发容量最多提升至两倍。更好的韧性与可用性。无额外费用，价格与你的主区域相同。
- **预置吞吐量：** 对于规模大且稳定的工作负载，[预置吞吐量](https://docs.aws.amazon.com/bedrock/latest/userguide/prov-throughput.html)可维持固定的性能水平。当你需要可预测的吞吐量时，这一选项非常合适，对自定义模型尤其如此。它带来以下优势：  为高需求应用提供稳定的性能。自定义模型必需。灵活的承诺期限（1 个月或 6 个月）。
