# AI 评判 AI：用 Amazon Nova 扩展非结构化文本分析

设想这样一个场景：你的团队刚收到 10,000 条客户反馈。传统做法意味着数周的人工分析。但如果 AI 不仅能分析这些反馈，还能验证自己的工作呢？欢迎进入部署在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 之上、由[大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLM）构成的评审团系统的世界。

随着越来越多组织采用[生成式 AI](https://aws.amazon.com/generative-ai/)，尤其是把 LLM 用于各类应用，一个新的挑战随之出现：如何确保这些 AI 模型的输出与人类视角一致，并且准确、切合业务语境。对大型数据集做人工分析既耗时又耗费资源，因而并不现实。例如，人工审阅 2,000 条评论可能需要 80 小时以上，具体取决于评论长度、复杂度以及研究人员的分析方法。LLM 提供了一种可扩展的方式，可以用作定性文本标注器、摘要器，甚至评判其他 AI 系统文本输出的评审者。

这就引出一个问题：「但我们要怎样有效部署这类 LLM-as-a-judge 系统，再用其他 LLM 来评估其表现？」

本文介绍如何在一个 [Amazon Bedrock](https://aws.amazon.com/bedrock/?gclid=Cj0KCQjw1um-BhDtARIsABjU5x7a3RN7Oy5Z17Ncy-JlQQYbqGw8_nzvoaVd0M0llyx5qh7DZeQpBKUaAmkrEALw_wcB&trk=36201f68-a9b0-45cc-849b-8ab260660e1c&sc_channel=ps&ef_id=Cj0KCQjw1um-BhDtARIsABjU5x7a3RN7Oy5Z17Ncy-JlQQYbqGw8_nzvoaVd0M0llyx5qh7DZeQpBKUaAmkrEALw_wcB:G:s&s_kwcid=AL!4422!3!692006004850!e!!g!!amazon%20bedrock!21048268689!159639953975) 中部署多个生成式 AI 模型，指示某个 LLM 模型为文本回答（例如面向客户的开放式调研问题）生成主题摘要，然后使用多个 LLM 模型组成评审团，审阅这些由 LLM 生成的摘要，并给出评分，以判断摘要标题与摘要描述之间的内容一致性。这种安排通常被称为 *LLM 评审团系统*（LLM jury system）。可以把 LLM 评审团看作一个由 AI 评审组成的评审小组，每一位都从自己的视角评估内容。与依赖单个模型可能有偏的视角相比，多个模型协同工作能给出更均衡的评估。

## 问题：分析文本反馈

你的组织会收到成千上万条客户反馈。对回答做传统人工分析可能相当艰难且耗费资源，耗时数天甚至数周，取决于你收到的自由文本评论数量。其他自然语言处理技术虽然通常更快，但也需要大量数据清洗工作和编码能力，才能有效分析数据。预训练 LLM 提供了一种有前景、相对低代码的方案，可以快速从文本类数据中生成主题摘要，因为这类模型已被证明能扩展数据分析规模并减少人工审阅时间。然而，如果同时把同一个预训练 LLM 用于分析和评估，就会引发关于偏见的担忧，例如模型幻觉（即生成不准确的信息）或确认偏误（即偏好预期结果）。如果没有交叉验证机制，例如比较多个模型的输出，或以人工审阅过的数据作为基准，未受检视的错误风险就会上升。使用多个预训练 LLM 可以通过提供稳健而全面的分析来化解这一担忧，甚至还能引入 human-in-the-loop 监督，并相较单模型评估提升可靠性。把 LLM 用作评审团这一概念，指的是部署多个生成式 AI 模型，让它们相互独立地评估或验证彼此的输出。

## 方案：在 Amazon Bedrock 上部署 LLM 作为评审

你可以使用 Amazon Bedrock 比较各类前沿[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM），例如 [Anthropic 的 Claude 3 Sonnet](https://aws.amazon.com/bedrock/anthropic/?ams%23interactive-card-vertical%23pattern-data.filter=%257B%2522filters%2522%253A%255B%255D%257D)、[Amazon Nova Pro](https://aws.amazon.com/ai/generative-ai/nova/) 和 [Meta 的 Llama 3](https://aws.amazon.com/bedrock/meta/)。统一的 [Amazon Web Services](https://aws.amazon.com/aws/)（AWS）环境与标准化 API 调用，简化了为做主题分析和评判模型输出而部署多个模型的过程。Amazon Bedrock 还通过统一的安全与合规管控体系，以及在所有模型之间保持一致性的模型部署环境，满足运维层面的需求。

我们提出的工作流如下图所示，包含以下步骤：

- 预处理后的原始数据会整理成 .txt 文件并上传到 Amazon Bedrock。先编写并测试主题生成 prompt，然后在 [Amazon SageMaker Studio](https://aws.amazon.com/sagemaker-ai/studio/) 中用选定的预训练 LLM 运行数据与 prompt。
- LLM 生成的摘要会转换为 .txt 文件，摘要数据再上传到 SageMaker Studio。

- 随后将 human-as-judge 的评分与模型表现做统计比较。我们使用百分比一致率（percentage agreement）、[Cohen's kappa](https://en.wikipedia.org/wiki/Cohen%27s_kappa)、[Krippendorff's alpha](https://en.wikipedia.org/wiki/Krippendorff%27s_alpha) 和 [Spearman's rho](https://en.wikipedia.org/wiki/Spearman%27s_rank_correlation_coefficient)。

我们使用以下几种常用的一致性指标来比较对齐程度，并据此比较各模型之间以及模型内部的表现：

- **百分比一致率（Percentage agreement）**——百分比一致率告诉我们，两位评分者对同一对象的评分（例如 1–5 分）有多少次相同，就像两个人给同一部电影打了同样的 5 星。相同次数越多越好。该指标以占全部被评案例的百分比表示，计算方法是用一致次数除以评分总次数再乘以 100。
- **Cohen's kappa**——Cohen's kappa 本质上是更聪明的百分比一致率。就像两个人每天猜自己 5 位同事里有几位会在办公室穿蓝色衣服。有时两个人纯属碰巧猜中同一个数字（例如 1–5）。Cohen's kappa 考虑的是两人在幸运猜中之外的一致程度。系数取值范围从 −1 到 +1，其中 1 表示完全一致，0 表示一致性等同于随机，负值表示一致性低于随机水平。
- **Spearman's rho**——Spearman's rho 就像数字的「友谊测量仪」。它显示两组数字彼此「合得来」，也就是同向变动的程度。如果一组数字上升、另一组也上升，它们就是正相关；如果一组上升而另一组下降，就是负相关。系数取值范围从 1 到 +1，越接近 ±1 表示相关性越强。
- **Krippendorff's alpha**——Krippendorff's alpha 是一种检验，用来判断所有评分者在某件事上的总体一致程度。设想两个人在餐厅试吃不同的食物，并按 1–5 分给食物打分。Krippendorff's alpha 会给出一个分数，显示两人在食物评分上的一致性有多高，即便他们并没有尝遍餐厅里的每道菜。alpha 系数取值范围为 0–1，越接近 1 表示评分者之间的一致性越高。一般来说，alpha 高于 0.80 表示强一致，介于 0.67 与 0.80 之间表示一致程度可接受，低于 0.67 则说明一致程度较低。如果按照等级（1、2、3）是定序的（ordinal）这一前提计算，Krippendorff's alpha 不仅考虑一致与否，还考虑不一致的幅度。与 kappa 相比，它受边际分布的影响更小，并且在评分是有序等级（ordinal）时能给出更细致的评估。也就是说，百分比一致率和 kappa 把所有不一致一视同仁，而 alpha 能区分轻微不一致（例如「1」与「2」）和重大不一致（例如「1」与「3」）。

## 结果

本文展示了如何使用 Amazon Bedrock 顺畅地调用多个 LLM，对定性数据（例如客户反馈）生成并评判主题摘要。我们还展示了如何把人工评估者对调研回答数据文本摘要的评分，与多个 LLM（如 Anthropic 的 Claude 3 Sonnet、Amazon Nova Pro 和 Meta 的 Llama 3）的评分做比较。在[近期发表的研究](https://arxiv.org/abs/2501.08167)中，Amazon 的科学家表明，模型之间的一致性最高可达 91%，而人与模型之间的一致性最高为 79%。我们的发现表明，尽管 LLM 能够在大规模场景下提供可靠的主题评估，但人工监督依然重要，因为需要识别 LLM 可能遗漏的细微语境差别。

最妙的一点是什么？借助 Amazon Bedrock 的模型托管，你可以用同一份预处理数据在所有模型之间做比较，从而挑出最适合你的语境与需求的模型。

## 结论

随着各类组织转向用生成式 AI 分析非结构化数据，本文介绍了使用多个 LLM 来验证 LLM 所生成分析结果这一做法的价值。LLM-as-a-judge 模型的强劲表现，为大规模扩展文本数据分析打开了机会，而 Amazon Bedrock 可以帮助组织与多个模型交互并加以使用，从而落地 LLM-as-a-judge 框架。
