# 构建 Supercharger：Rocket Close 如何用 agentic AI 优化产权业务

[Rocket Close](https://www.rocketclose.com/) 是 [Rocket Companies](https://www.rocket.com/) 旗下的一家总部位于底特律的产权代理与评估管理公司，提供产权保险、房产估值与过户结算服务。随着抵押贷款与贷款需求增长，产权业务成为购房流程中的瓶颈。各州特有的产权审查耗时漫长，再加上人工检索与彼此割裂的系统，拖慢了吞吐，也让团队难以跟上不断扩大的客户群。

产权审查员必须核实来自不同来源的数据。这需要在多个系统、各州指南以及县级要求之间逐一检索。围绕遗嘱认证（probate）或税号（tax ID）的地方规则进一步增加了工作的复杂性。例如，一位产权审查员若要弄清某个县特有的登记要求，可能要花上数小时在多个来源之间翻找。

为解决这些挑战，Rocket Close 与 AWS 合作打造了 Supercharger。Supercharger 是一个 agentic AI 解决方案，旨在减少贷款与购房流程中的摩擦，并优化产权业务工作流。它汇集产权与过户交割方面的知识，引导团队完成订单处理流程，并以自然语言与内部运营团队动态交互。通过集中知识、自动化检索密集型任务，该解决方案能就订单生成可执行的洞察、提升效率，并减少用于查找信息的时间。最终，它同时提升了运营效率与客户体验。

在本文中，我们探讨 Rocket Close 如何借助 [Strands Agents](https://strandsagents.com/)、[大语言模型（LLM）](https://aws.amazon.com/what-is/large-language-model/)、[Amazon Bedrock](https://aws.amazon.com/bedrock)、[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 以及 [Model Context Protocol（MCP）](https://aws.amazon.com/blogs/machine-learning/unlocking-the-power-of-model-context-protocol-mcp-on-aws/) 工具构建了一套解决方案。我们介绍该解决方案的功能、技术栈的选型理由、经验教训，以及在 Rocket Close 产生的业务影响。

## 解决方案概述

Supercharger 解决方案由 Strands Agents 驱动。Strands Agents 是 AWS 推出的开源 agent harness SDK，用于通过 Amazon Bedrock 调用 Anthropic Claude 大语言模型（LLM）来构建 agent，其灵活性让 Supercharger 可以随着产权助手的演进而选用不同的 LLM。在安全方面，该解决方案将 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 与行级数据授权相结合，通过智能访问控制帮助防止意外访问客户敏感数据。对话会被记录并保留完整的审计线索，以满足合规要求。它与 Rocket Close 的运营数据库集成，这些数据库包含订单信息、标准流程以及州级产权审查政策。下图展示了 Supercharger 六项相互关联的能力。

![Supercharger 能力示意图，展示六项相互关联的功能：对话式分析、州级产权审查辅助、基于 API 的集成、Guardrails 与响应准确性、日志记录与监控，以及统一数据访问](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/10/ML-20329-1.png)

Supercharger 解决方案的核心是一个领域专用 agent，它通过六项相互关联、协同工作的能力来驱动与运营团队的对话，从而简化购房流程。对话式分析（Conversation Analytics）支持自然语言处理，能够理解多轮对话中的上下文与意图，使交互显得直观、自然，而不是僵硬的事务性应答。在此基础上，州级产权审查辅助针对具体的产权审查要求提供全面的检查清单与指引，在恰当的时点为团队提供恰当的信息。该解决方案基于 API 的集成可与现有系统相连，保持数据一致性并避免手工录入，从而减少错误，让团队专注于高价值工作。Guardrails 与响应准确性（Guardrails and Response Accuracy）确保每一次响应都符合质量标准与监管要求，保护公司及其客户。全面的日志记录与监控让系统性能和用户交互完全可见，并提供满足合规要求的完整审计线索。最后，对多个数据源的统一访问为决策保留完整上下文，把过去需要查询多个系统的信息汇集在一起，为在复杂产权工作流中操作的运营团队带来统一的体验。

当运营团队成员提出问题时，请求会流经下图所示的工作流。

![Supercharger 架构示意图，展示请求从用户出发，经过 WebSocket 握手、token 校验、Strands agent 调用、知识库查询、工具选择、MCP 工具执行、上下文综合到响应交付的流动过程](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/10/ML-20329-2.png)

- **WebSocket 握手** – 用户通过携带 JWT token 的 HTTP 请求发起连接。
- **token 校验** – 身份提供方通过 Istio 校验该 token，并建立 WebSocket 连接。
- **产权审查 agent 调用** – 调用 Strands Agent，依据系统 prompt 与用户输入触发 agentic 工作流。
- **知识库查询** – agent 在知识库中检索相关的策略与流程。
- **工具选择** – agent 决定要调用哪个函数以及使用哪些参数。
- **MCP 工具执行** – MCP 工具处理请求，从 Atlas Web API 获取订单信息。
- **上下文综合** – 系统查询知识库，获取针对具体订单的上下文。
- **响应交付** – 合并后的响应通过 WebSocket 流式返回给用户。
- **响应渲染** – 综合后的响应以渐进方式流式返回聊天机器人 UI。

在接下来的章节中，我们说明为何选择 Strands Agents 以及基于 MCP 工具的架构。

### Strands Agents

Strands Agents 是一个开源 agent harness SDK，它以模型驱动的方式，让你只需几行代码即可构建并运行 AI agent。它既能覆盖从简单到复杂的用例，也能从本地开发扩展到生产环境。Strands Agents 利用 LLM 的规划、工具调用与反思能力来驱动 agent 的行为。

使用 Strands Agents 时，开发者在代码中定义一个 prompt 和一组工具，然后在本地测试 agent 并部署到云端。该 SDK 通过模型的推理能力规划 agent 的后续步骤并运行工具。对于更复杂的用例，开发者可以自定义 agent 的行为。例如，你可以指定工具如何被选择、自定义上下文如何管理、选择会话状态与记忆的存储位置，以及构建多 agent 应用。

### Model Context Protocol（MCP）工具

该解决方案实现了基于 MCP 工具的架构，其中每个数据源都作为一个独立工具暴露出来，供 Strands Agents 调用。这种做法带来三项优势：

- **可扩展性** – 新增数据源可以作为额外工具加入，而无需重构核心架构。团队有意做出这一设计选择，以容纳未来的扩展。
- **关注点分离** – 与每个系统交互的逻辑都封装在各自的工具中，这使整体架构更易维护、更易测试。
- **灵活性** – Strands agent 会根据每个查询动态选择使用哪些工具，从而支持跨多个数据源的工作流。

## 业务影响

> “通过利用 Rocket Close 的专有知识库，并用 agentic AI 能力增强 Supercharger，我们的团队得以改变团队成员与复杂订单数据交互、执行日常任务的方式。这不仅提升了生产力，也改变了工作的完成方式。通过将 Supercharger 的问答能力与我们外部的聊天界面集成，我们每月为联络中心节省了数千次电话与电子邮件，从而获得更大的规模和更好的客户体验。”
>         — Bryan Bedard，Rocket Close 数据科学副总裁

Supercharger 理解订单级上下文并给出精确、贴合角色的指导，这在多方面改变了 Rocket Close 的端到端工作流。该解决方案为运营团队与客户关系团队带来了立竿见影的运营效率提升：借助其问答能力，打入联络中心的电话与电子邮件数量减少了 30%。通过在既有工作流中提供关于订单的实时洞察，州级审查的准确性得以提高，这降低了认知负担、缩短了检索时间，并提升了决策的准确性。客户满意度因例行任务的自动化、订单级流程的执行以及代客户起草沟通内容而得到提升。借助 Supercharger 由 AI 引导的州级审查辅助，运营一致性也有所改善。最后，通过架构优化与更好的 prompt 技巧减少 agent 调用 LLM 的次数，性能得到优化，实现了延迟改善 3 倍并降低了成本。

## 经验教训

在 Rocket Close 交付 Supercharger 的整个过程中，团队总结出若干关键经验，这些经验塑造了他们的 AI 战略与实施方式。

这段经历表明，高效的数据检索是性能的基石，因此他们设计了一套精简的方案：先由 MCP 工具在一次调用中取回所需的订单信息，再用 LLM 综合提取相关细节，从而免去多次数据库查询。这一架构理念延伸到保持 Strands Agents 与 MCP 工具之间清晰的关注点分离，为随需求变化而演进奠定了灵活的基础。团队发现，基于 WebSocket 的流式传输能带来即时的用户反馈，即便处理复杂查询也能提升性能观感。团队还认识到，有效的 LLM prompt 应侧重于描述 agent 应当完成什么，而不是规定如何完成，因为去掉确定性步骤后，agent 得以运用自身固有能力进行动态编排，比定制化实现更具适应性。其他洞察还包括：知识库中的元数据过滤可提升检索精度；描述性的工具命名与连贯的 docstring 至关重要，它们构成了 agent 推理的自然语言接口；把安全策略的执行下放到会话属性，而不是嵌入业务逻辑或逐步的 agent prompt，有助于实现干净、一致的访问控制。团队也认识到，高管层的支持与变革管理对按时交付至关重要，这促使他们与 AWS 展开合作。

这些经验汇成一个统一原则：设计解决方案时应发挥 agent 的固有智能，而不是约束它，这使 Supercharger 在长期内既更强大，也更易维护。
