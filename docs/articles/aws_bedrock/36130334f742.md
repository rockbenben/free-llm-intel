# Lumi 如何借助 Amazon SageMaker AI 精简贷款审批

*本文与 Lumi 的 Paul Pagnan 合著。*

[Lumi](https://www.lumi.com.au/) 是澳大利亚领先的金融科技贷款机构，为小型企业提供快速、灵活且透明的融资方案。他们使用实时数据与机器学习（ML）提供定制化贷款，助力可持续增长，并解决获取资金方面的难题。他们的目标是实现快速周转——以小时而非天计——从而与传统贷款机构形成差异化。本文探讨 Lumi 如何使用 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker-ai/) 达成这一目标、增强其交易处理与分类能力，并最终通过更快处理贷款申请、更准确的信贷决策与更好的客户体验来推动业务增长。

## 概览：Lumi 如何用机器学习实现智能信贷决策

在 Lumi 的客户入驻与贷款申请流程中，他们需要一个稳健的方案来处理海量企业交易数据。分类过程必须以低延迟运行，以支撑 Lumi 在市场领先的“决策速度”承诺。它需要依据交易描述与企业相关的其他上下文因素对交易进行智能归类，确保映射到恰当的分类。这些分类后的交易随后成为下游信用风险 AI 模型的关键输入，从而更准确地评估企业的信用状况。为此，Lumi 基于 [BERT（Bidirectional Encoder Representations from Transformers）](https://aws.amazon.com/what-is/transformers-in-artificial-intelligence/) 开发了一个分类模型——这是一种先进的自然语言处理（NLP）技术。他们使用自有数据集与内部数据科学专长对该模型进行了微调。基于 BERT 的模型擅长理解文本中的上下文与细微差别，因而在以下方面尤为有效：

- 分析复杂的金融交易
- 理解与行业等上下文因素之间的关系
- 处理来自多种来源的非结构化文本数据
- 适应新的金融产品与交易类型

身处金融服务业，Lumi 必须确保模型输出的准确性，以保证风险评估准确。因此，Lumi 实施了 human-in-the-loop 流程，纳入其风险与合规团队的专业判断，对一部分分类结果进行复核与纠正，以确保模型持续保持准确。这种方法以如下方式把机器学习的效率与人的判断结合起来：

- ML 模型快速处理并分类交易。
- 置信度低的结果会被标记，并自动路由到相应团队。
- 经验丰富的风险分析师审阅这些案例，提供额外一层审查。
- 分类正确的数据被纳入模型重训练，以帮助确保持续准确性。

这种混合方法使 Lumi 在保持高标准风险管理的同时，仍能快速做出贷款决策。它还形成了一条反馈闭环，持续改进 ML 模型的性能，因为人的洞察会被用来随时间打磨与更新系统。

## 挑战：扩展 ML 推理，实现高效、低延迟的交易分类与风险分析

要把模型部署到生产环境，Lumi 需要一个能满足其业务需求的推理平台，包括：

- **高性能：**平台需要快速高效地处理海量交易。
- **低延迟：**为保持出色的客户体验与贷款申请的快速周转，平台需要提供快速的结果。
- **规模化的成本效益：**考虑到每日处理的大量交易以及业务的快速增长，方案必须随运营扩张仍具经济可行性。
- **自适应伸缩：**平台需要随工作负载波动动态调整，在峰值处理时段高效应对且不牺牲性能，同时在低活跃时段收缩。关键在于，它需要具备夜间缩容到零的能力，在系统并未主动处理交易时消除不必要的成本。这种灵活性有助于在各类运营需求水平下确保最优的资源利用与成本效率。
- **可观测性：**平台需要提供强健的监控与日志能力，深入洞察模型性能、资源利用与推理模式。这种程度的可观测性对于跟踪模型准确性随时间的变化与漂移、识别潜在瓶颈、监控系统健康度以及快速排障至关重要。它还能通过详细的审计轨迹帮助满足监管要求，并为持续改进提供数据驱动的决策依据。通过清晰掌握生产环境中整个 ML 生命周期，Lumi 可以主动管理模型、优化资源分配，并维持高标准的服务质量与可靠性。

在评估了多家 ML 模型托管服务商、并就成本效益与性能做了基准比较之后，Lumi 选择了 [Amazon SageMaker Asynchronous Inference](https://docs.aws.amazon.com/sagemaker/latest/dg/async-inference.html) 作为其解决方案。

## 解决方案：在 Amazon SageMaker AI 上使用异步推理

Lumi 使用 SageMaker Asynchronous Inference 托管其机器学习模型，并充分利用了与其需求相符的几项关键优势。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/28/Architecture-Lumi-and-SageMaker-AI-1.png)

**排队机制：**SageMaker Asynchronous Inference 的[托管队列](https://docs.aws.amazon.com/sagemaker/latest/dg/async-inference.html#async-inference-how-it-works)能高效应对变化的工作负载，确保所有推理请求都能被处理，且高峰时段系统不过载。这对 Lumi 至关重要，因为请求通常在 100 MB 到 1 GB 之间，包含特定时间窗口内超过 100,000 笔交易，并为多家申请贷款的企业批量提交。

**缩容到零的能力：**该服务会在非活跃时段自动缩容到零个实例，显著降低成本。这一特性对 Lumi 尤其有利，因为贷款申请通常发生在营业时间内。

**高性能与低延迟：**SageMaker Asynchronous Inference 专为大负载与长时推理作业设计，非常适合处理复杂的金融交易数据。这一能力使 Lumi 能够提供快速的客户体验，对其风险与合规团队的复核流程至关重要。

**自定义容器优化：**Lumi 构建了一个精简的[自定义容器](https://docs.aws.amazon.com/sagemaker/latest/dg/docker-containers-adapt-your-own.html)，只包含必要的库，例如 [MLFlow](https://docs.aws.amazon.com/sagemaker/latest/dg/mlflow.html)、[Tensorflow](https://docs.aws.amazon.com/sagemaker/latest/dg/tf.html) 与 [MLServer](https://github.com/SeldonIO/MLServer)。能够自带容器意味着他们可以显著减小容器体积、缩短冷启动时间，从而加快整体处理。

**模型部署与治理：**Lumi 使用 SageMaker 部署其交易分类模型，并利用其[模型注册表与版本管理](https://docs.aws.amazon.com/sagemaker/latest/dg/model-registry-version.html)能力。这实现了稳健的模型治理，满足合规要求，并确保对模型迭代做恰当管理。

**与 AWS 上现有系统的集成：**Lumi 把 SageMaker Asynchronous Inference 端点与其现有的贷款处理流水线无缝集成。模型训练使用 [AWS 上的 Databricks](https://aws.amazon.com/blogs/apn/zero-to-generative-ai-with-databricks-and-aws/)，他们构建了一条流水线，把模型托管在 SageMaker AI 中，并优化数据流与结果获取。该流水线利用了 Lumi 团队熟悉的若干 AWS 服务。贷款申请到达时，托管在 Amazon Elastic Kubernetes Service（EKS）上的应用会调用 [InvokeEndpointAsync](https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_runtime_InvokeEndpointAsync.html) 发起异步推理。[Amazon Simple Storage Service（S3）](https://aws.amazon.com/s3/)既存储推理所需的批量数据，也存储输出结果。[Amazon Simple Notification Service（SNS）](https://aws.amazon.com/sns/)向相关干系人告知作业状态更新。

**实例选型与性能基准：**为优化部署，Lumi 就延迟、成本与可扩展性，对包括实时端点与多种实例类型在内的多个推理服务选项做了基准测试。他们基于对生产中真实数据的分析，准备了一系列不同规模的银行交易输入，并使用 [JMeter](https://aws.amazon.com/solutions/implementations/distributed-load-testing-on-aws/) 调用 Asynchronous Inference 端点，在集群上模拟真实的生产负载。分析结果表明：虽然较大实例上的实时推理能为单个请求提供更低延迟，但对 Lumi 这种面向批处理的负载而言，使用 [c5.xlarge](https://aws.amazon.com/ec2/instance-types/c5/) 实例的异步推理方案在成本效益与性能之间取得了最佳平衡。这次分析确认了 Lumi 对 SageMaker Asynchronous Inference 的选择，也帮助他们选出了符合需求的最优实例规格。在把模型改为使用 Tensorflow CUDA 之后，Lumi 又进一步优化，迁移到启用 GPU 的 [ml.g5.xlarge](https://aws.amazon.com/ec2/instance-types/g5/) 集群，性能提升 82%，同时成本下降 10%。

## 最佳实践与建议

对于希望实施类似方案的企业，可参考以下最佳实践：

**优化你的容器：**效仿 Lumi 的做法，构建一个只包含必要依赖的精简自定义容器。这种做法可以显著提升推理速度并降低成本。

**利用异步处理：**对于数据量波动或处理时间较长的负载，异步推理在可扩展性与成本效益方面能带来可观收益。

**为扩展做好规划：**在设计 ML 基础设施时就考虑未来的增长。SageMaker AI 的灵活性让你可以随需求演进而轻松添加新模型与新能力。

**模型可观测性与治理：**在评估推理与托管平台时，请考虑可观测性与治理能力。SageMaker AI 强健的可观测性与治理特性可以轻松诊断问题、维持模型性能、确保合规，并促进持续改进与生产质量。

## 结论

通过实施 SageMaker AI，Lumi 的业务取得了显著改进。迁移到基于 BERT 的新模型后，他们的交易分类准确率提升了 56%。以异步方式处理大批量交易的能力，使贷款申请的整体处理时间大幅缩短了 53%。自动伸缩与缩容到零的特性在非高峰时段带来了可观的成本节省，使模型的成本效率提升了 47%。此外，Lumi 现在可以轻松应对贷款申请的突发峰值，而不牺牲处理速度或准确性。

> “Amazon SageMaker AI 对我们的业务而言是一场变革。它让我们能够比以往更快、更高效、更准确地处理贷款申请，同时显著降低运营成本。在高峰时段处理海量交易、在低谷时段缩容到零的能力，赋予了我们快速增长所需的灵活性，而无需在性能或客户体验上妥协。这套方案在帮助我们实现为小型企业提供快速、可靠贷款决策的目标方面发挥了关键作用。”Lumi 首席技术官 Paul Pagnan 表示

受实施成功的鼓舞，Lumi 正探索把 Amazon SageMaker AI 的使用扩展到其他模型，并研究 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 等工具以支持生成式 AI 用例。公司计划在该平台上托管更多模型，通过机器学习进一步增强其贷款流程，包括：增强其本已成熟的信用评分与风险评估模型，以更准确地评估贷款适用性；构建客户分群模型，以更好地理解客户群并个性化贷款产品；以及引入预测分析，主动识别市场趋势并据此调整放贷策略。
