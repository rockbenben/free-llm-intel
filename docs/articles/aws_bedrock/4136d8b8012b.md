# 使用 LlamaIndex 和 Amazon Bedrock 中的 Mistral 构建用于高级知识发现的 agentic RAG 应用

Agentic 检索增强生成（RAG）应用代表了 AI 中的一种进阶方法，它把基础模型（FM）与外部知识检索和自主 agent 能力集成在一起。这类系统会动态访问和处理信息、拆解复杂任务、使用外部工具、进行推理，并适应各种上下文。它们超越简单的问答，能执行多步流程、做出决策并生成复杂的输出。

本文中，我们演示一个使用 [LlamaIndex](https://www.llamaindex.ai/) 框架构建 agentic RAG 应用的示例。LlamaIndex 是一个把 FM 与外部数据源连接起来的框架。它帮助从数据库、API、PDF 等来源摄取、组织并检索信息，为 AI 应用实现 agent 与 RAG。

该应用充当研究工具，使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的 [Mistral Large 2](https://mistral.ai/news/mistral-large-2407) FM 为 agent 流程生成响应。这个示例应用与知名网站交互，例如 [Arxiv](https://arxiv.org/)、[GitHub](https://github.com/)、[TechCrunch](https://techcrunch.com/) 和 [DuckDuckGo](https://duckduckgo.com/)，并且可以访问包含文档与内部知识的知识库。

该应用还可进一步扩展，以适配更广泛的用例：需要与内外部 API 动态交互，并集成内部知识库，为用户查询提供更具上下文感知的回答。

## 解决方案概述

该解决方案使用 LlamaIndex 框架构建 agent 流程，包含两个主要组件：[AgentRunner 和 AgentWorker](https://docs.llamaindex.ai/en/stable/module_guides/deploying/agents/agent_runner/)。AgentRunner 充当编排器，负责管理对话历史、创建并维护任务、执行任务步骤，并提供易于使用的交互界面。AgentWorker 负责逐步推理与任务执行。

在推理与任务规划方面，我们使用 Amazon Bedrock 上的 Mistral Large 2。你也可以使用 Amazon Bedrock 提供的其他文本生成 FM。受支持模型的完整列表请参阅 [Amazon Bedrock 中支持的基础模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)。该 agent 集成 GitHub、arXiv、TechCrunch 和 DuckDuckGo 的 API，同时通过 RAG 框架访问内部知识，以提供具上下文感知的回答。

在该解决方案中，我们提供两种构建 RAG 框架的选项：

- **与 Amazon OpenSearch Serverless 集成文档** – 第一种选项是使用 LlamaIndex 以编程方式加载和处理文档。它使用[多种分块策略](https://docs.llamaindex.ai/en/stable/module_guides/loading/node_parsers/)把文档切分为 chunk，然后把这些 chunk 存入 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/) 向量存储，供后续检索。
- **与 Amazon Bedrock Knowledge Bases 集成文档** – 第二种选项使用 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)，这是一项全托管服务，负责文档的加载、处理和分块。该服务只需少量配置和点击，就能为你快速创建新的向量存储。你可以从 Amazon OpenSearch Serverless、[Amazon Aurora PostgreSQL-Compatible Edition Serverless](https://aws.amazon.com/rds/aurora/serverless/) 和 [Amazon Neptune Analytics](https://docs.aws.amazon.com/neptune-analytics/latest/userguide/what-is-neptune-analytics.html) 中选择。此外，该解决方案还包含文档检索重排功能，以提升回答的相关性。

你可以选择最适合自身偏好与开发者技能水平的 RAG 实现选项。

以下代码示例展示了与 GitHub API 集成的函数。函数创建完成后，使用 `FunctionTool.from_defaults()` 方法把该函数包装为工具，并无缝集成到 LlamaIndex 工作流中。

与 TechCrunch API 集成的函数的完整代码示例，请参阅[代码仓库](https://github.com/aws-samples/mistral-on-aws/tree/main/notebooks/mistral-llamaindex-agentic-rag)。

```
# Define a function to search GitHub repositories by topic, sorting by stars or update date, and return top results
import requests
def github_search(topic: str, num_results: int = 3, sort_by: str = "stars") -> list:
    """
    Retrieve a specified number of GitHub repositories based on a given topic, 
    ranked by the specified criteria.

    This function uses the GitHub API to search for repositories related to a 
    specific topic or keyword. The results can be sorted by the number of stars 
    (popularity) or the most recent update, with the most relevant repositories 
    appearing first according to the chosen sorting method.

    Parameters:
    -----------
    topic : str
        The topic or keyword to search for in GitHub repositories.
        The topic cannot contain blank spaces.
    num_results : int, optional
        The number of repository results to retrieve. Defaults to 3.
    sort_by : str, optional
        The criterion for sorting the results. Options include:
        - 'stars': Sort by the number of stars (popularity).
        - 'updated': Sort by the date of the last update (most recent first).
        Defaults to 'stars'.

    Returns:
    --------
    list
        A list of dictionaries, where each dictionary contains information 
        about a repository. Each dictionary includes:
        - 'html_url': The URL of the repository.
        - 'description': A brief description of the repository.
        - 'stargazers_count': The number of stars (popularity) the repository has.
    """

    url = f"https://api.github.com/search/repositories?q=topic:{topic}&sort={sort_by}&order=desc"
    response = requests.get(url).json()
    code_repos = [
        {
            'html_url': item['html_url'],
            'description': item['description'],
            'stargazers_count': item['stargazers_count'],
        }
        for item in response['items'][:num_results]
    ]
    return code_repos

github_tool = FunctionTool.from_defaults(fn=github_search)
```

接下来，使用以下代码实现一个基于 LlamaIndex 并与 Amazon OpenSearch Serverless 集成的文档搜索系统。它首先设置 AWS 认证，以安全地访问 OpenSearch Service，然后配置一个可处理 1024 维嵌入的向量客户端（专为 Amazon Titan Embedding V2 模型设计）。该代码处理输入文档时，把它们切分为以 1,024 个 token 为单位、带 20 个 token 重叠的可管理 chunk，把这些 chunk 转换为向量嵌入，并存入 OpenSearch Serverless 向量索引。你可以通过修改 `VectorStoreIndex.from_documents()` 方法中的 transformations 参数，选择不同或更高级的分块策略。更多信息和示例请参阅 [LlamaIndex 文档](https://docs.llamaindex.ai/en/stable/module_guides/loading/node_parsers/modules/#file-based-node-parsers)。

```
import boto3
from llama_index.vector_stores.opensearch import  OpensearchVectorStore,   OpensearchVectorClient
from opensearchpy import RequestsHttpConnection, AWSV4SignerAuth
from llama_index.core import VectorStoreIndex, StorageContext
from llama_index.core.node_parser import SentenceSplitter

## integrate Amazon OpenSearch Serverless collection and index to llamaindex 

dim = 1024 # Amazon Titan Embedding V2 model dimension 
service = 'aoss'
credentials = boto3.Session().get_credentials()
awsauth = AWSV4SignerAuth(credentials, region_name, service)

client = OpensearchVectorClient(
    endpoint, 
    index_name, 
    dim, 
    embedding_field="vector", 
    text_field="chunk",
    http_auth=awsauth,
    use_ssl=True,
    verify_certs=True,
    connection_class=RequestsHttpConnection,
)

# initialise vector store and save document chunks to the vector store 
vector_store = OpensearchVectorStore(client)
storage_context = StorageContext.from_defaults(vector_store=vector_store)

index = VectorStoreIndex.from_documents(
    documents, 
    storage_context=storage_context,
    transformations=[SentenceSplitter(chunk_size=1024, chunk_overlap=20)]
)
```

## RAG 选项 2：与 Amazon Bedrock Knowledge Bases 集成文档

本节中，你使用 Amazon Bedrock Knowledge Bases 构建 RAG 框架。你可以在 [Amazon Bedrock 控制台](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-create.html)上创建 Amazon Bedrock 知识库，也可以按照提供的 [notebook 示例](https://github.com/aws-samples/amazon-bedrock-workshop/blob/main/02_KnowledgeBases_and_RAG/0_create_ingest_documents_test_kb.ipynb) 以编程方式创建。为该知识库新建一个 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3) 存储桶，然后把之前下载的文件上传到这个 S3 存储桶。你可以选择更适合你数据的不同嵌入模型和分块策略。创建知识库后，记得同步数据。数据同步可能需要几分钟。

要让你新建的知识库能够调用 rerank 模型，你需要修改其权限。首先打开 Amazon Bedrock 控制台，找到与下方截图所示一致的服务角色。

![Amazon Bedrock 控制台，展示知识库设置，包括执行角色、向量存储配置和数据源控制项](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/20/ML-17742-KB-permission.png)

选择该角色，并把下面提供的 IAM 权限策略作为内联策略添加。这一额外授权为你的知识库授予在 Amazon Bedrock 上成功调用 rerank 模型所需的权限。

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": "arn:aws:bedrock:us-west-2::foundation-model/amazon.rerank-v1:0"
        },
        {
            "Effect": "Allow",
            "Action": "bedrock:Rerank",
            "Resource": "*"
        }
    ]
}
```

使用以下代码把知识库集成到 LlamaIndex 框架中。具体配置可以在 `retrieval_config` 参数中提供，其中 `numberOfResults` 是从向量存储检索到的 chunk 的最大数量，`overrideSearchType` 有两个有效值：`HYBRID` 和 `SEMANTIC`。在 `rerankConfiguration` 中，你可以选择性地提供 `rerank modelConfiguration` 和 `numberOfRerankedResults`，按相关性评分对检索到的 chunk 排序，并只选取指定数量的结果。`retrieval_config` 可用配置的完整列表，请参阅 [Retrieve API 文档](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_Retrieve.html)。

```
# Configure a knowledge base retriever using AmazonKnowledgeBasesRetriever
from llama_index.core.query_engine import RetrieverQueryEngine
from llama_index.retrievers.bedrock import AmazonKnowledgeBasesRetriever

# maximum number of relevant text chunks that will be retrieved
# If you need quick, focused answers: lower numbers (1-3)
# If you need detailed, comprehensive answers: higher numbers (5-10)
top_k = 10

# search mode options: HYBRID, SEMANTIC
# HYBRID search combines the strengths of semantic search and keyword search 
# Balances semantic understanding with exact matching
# https://docs.llamaindex.ai/en/stable/examples/retrievers/bedrock_retriever/
search_mode = "HYBRID"

kb_retriever = AmazonKnowledgeBasesRetriever(
    knowledge_base_id=knowledge_base_id,
    retrieval_config={
        "vectorSearchConfiguration": {
            "numberOfResults": top_k,
            "overrideSearchType": search_mode,
            'rerankingConfiguration': {
                'bedrockRerankingConfiguration': {
                    'modelConfiguration': {
                        'modelArn': 'arn:aws:bedrock:us-west-2::foundation-model/amazon.rerank-v1:0'
                    },
                    'numberOfRerankedResults': 3
                },
                'type': 'BEDROCK_RERANKING_MODEL'
            }
        },
        
    }
)
kb_engine = RetrieverQueryEngine(retriever=kb_retriever)
```

与第一种选项类似，你可以在 LlamaIndex 中把知识库创建为 `QueryEngineTool`，并与其他 API 工具组合。然后，你可以使用这些组合后的工具创建一个 `FunctionCallingAgentWorker`，并初始化一个 `AgentRunner` 与它们交互。通过这种方式，你可以与集成后的工具对话并利用它们的能力。

```

        query_engine=kb_engine,
        metadata=ToolMetadata(
            name="kb_tool",

            They cover pre-built solutions, customizable platforms, and infrastructure options for ML workflows, 
            while outlining how generative AI can automate processes, personalize content, augment data, reduce costs, 
            and enable faster experimentation in various business contexts.""",
        ),
    )

# Update the agent to include all API tools and the Knowledge Base tool.
all_tools = api_tools +[kb_tool]

agent_worker = FunctionCallingAgentWorker.from_tools(
    all_tools, 
    llm=llm, 
    verbose=True, # Set verbose=True to display the full trace of steps. 
    system_prompt = system_prompt,
    # allow_parallel_tool_calls = True  # Uncomment this line to allow multiple tool invocations
)
agent = AgentRunner(agent_worker)
response = agent.chat(text_input)
```
