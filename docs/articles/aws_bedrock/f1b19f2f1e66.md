# AgentCore 上 Web Search 的域名与发布日期过滤器

当 AI agent 使用 Web Search 代表客户为答案提供依据时，该 agent 背后的组织需要域名和日期过滤器，以控制 agent 查阅哪些来源，以及这些来源必须有多新。一个金融服务 agent 不应该把未经审查的博客作为答案依据。一个产品信息 agent 在用户询问当前是否有货时，不应该引用三年前的定价或库存数据，因为库存水平和定价变化很快。

今天，我们宣布为 Amazon Bedrock AgentCore 上的 Web Search 推出运行时域名过滤与发布日期过滤。Amazon Bedrock AgentCore 是一个可以用任意框架或模型大规模构建、连接和优化 agent 的平台。该能力随 web-search connector 1.2.0 版本发布。这些能力让开发者可以按调用控制其 agent 能搜索哪些 web 域名，以及结果必须落在哪个发布日期窗口内，且全部在服务端强制执行，无需任何外部编排。与现有的管理员级域名策略结合后，组织就拥有了一套分层过滤模型：既强制执行企业治理，又让单个 API 调用可以按请求灵活地动态收窄范围。

除运行时过滤之外，本次发布还将 Web Search 的可用范围扩展到两个新的 AWS 区域：eu-west-1（都柏林）和 ap-northeast-1（东京）。欧洲和亚太地区的客户现在可以从更靠近其工作负载的区域端点调用 Web Search，从而降低延迟，并为有数据就近要求的组织提供一个位于欧盟的入口。AgentCore 采用零出站架构，搜索查询始终留在 AWS 内。这一区域扩展让这些区域中受监管的客户可以在不让流量跨越大西洋的情况下构建有依据的 agent。

在本文中，我们将介绍运行时过滤是什么、它为什么重要、管理员加运行时的分层模型如何运作、如何上手使用新的 API 参数，以及区域可用性对你的工作负载意味着什么。

## connector 1.2.0 版本的新增内容

本次发布在 Web Search 工具输入 schema 的 filters 对象中引入两项新能力：

### 1. 运行时域名过滤

在每次 `tools/call` 调用时传入一个域名的 **include**（允许列表）或 **exclude**（拒绝列表）。这样就能按请求控制 agent 可以查阅哪些来源。

| **字段** | **说明** |
| --- | --- |
| filters.domainFilter.include | 返回来自这些域名的结果 |
| filters.domainFilter.exclude | 屏蔽来自这些域名的结果 |

每个列表最多支持 **100 个域名**，各自独立计数。

### 2. 发布日期过滤

使用 ISO-8601 UTC 边界，把结果限制在特定日期范围内发布的内容：

| **字段** | **说明** |
| --- | --- |
| filters.publishedDateFilter.from | 最早的发布日期（含） |
| filters.publishedDateFilter.to | 最晚的发布日期（含） |

两个过滤器都是**可选的**，且按请求生效。省略它们会保留现有行为，即所有已索引的内容都可被选中。

## 运行时过滤为什么重要

真实世界的 agent 工作负载需要比仅靠组织级策略更细粒度的控制：

- **按任务限制来源**：一个分析监管更新的合规 agent 应只搜索 .gov 域名和已批准的发布者，而不是整个开放 web。
- **时间范围限定**：一个总结“本周财报电话会”的市场情报 agent 绝不应把上几个季度的结果顶上来，即使它们在查询中排名很高。
- **调用时的动态允许/拒绝**：一个服务不同客户的多租户平台可能需要按请求使用不同的域名策略，而不必为每个租户创建单独的目标。
- **内容新鲜度保证**：一个回答“最新版本有什么变化”的客户支持 agent 应只返回过去 7 天内发布的文档。

运行时过滤通过把控制权移入 API 调用本身来满足这些需求。

## 工作原理：请求流程

下图展示了一次带过滤的搜索请求的生命周期：你的 agent 发送一个带 query 和 filters 的 `tools/call`，Gateway 将你的运行时过滤器与管理员级策略合并，对 web 索引执行带过滤的查询，对原始结果执行合规校验，最后只返回经过验证的结果，供你的 agent 为其响应提供依据。

图 1：一次带过滤的 Web Search 请求的生命周期，从 tools/call 到经过验证的结果

整个生命周期都在服务端完成。没有客户端过滤循环，没有后处理，也没有额外的往返。

## 分层过滤模型：管理员 + 运行时

本次发布的一项关键设计原则是：**运行时过滤器可以收窄管理员设定的范围，但绝不能扩大它**。这确保企业策略始终被执行，无论运行时调用方请求什么。管理员级域名列表在创建 connector 资源时设定。

### 合并逻辑

下图说明了管理员级与运行时过滤列表如何组合：include 列表按交集合并（只有同时出现在两个列表中的域名才会保留），而 exclude 列表按并集合并（在任一层被屏蔽的域名都保持被屏蔽）。请注意 d.com 为何被从生效的允许列表中剔除——它只出现在运行时列表中，不在管理员策略里。

图 2：管理员与运行时域名列表如何合并——include 列表取交集，exclude 列表取并集

**域名 include（允许列表）：** 生效的允许列表是管理员列表与运行时列表的**交集**。如果管理员允许 [a.com, b.com, c.com]，而运行时调用包含 [b.com, c.com, d.com]，那么只会搜索 b.com 和 c.com。域名 d.com 不在管理员域名列表之内，会被静默丢弃。

**域名 exclude（拒绝列表）：** 生效的拒绝列表是管理员列表与运行时列表的**并集**。如果管理员屏蔽了 [x.com]，而运行时调用排除了 [y.com]，那么两者都会被屏蔽。

**注意：** 运行时调用方无法搜索管理员未允许的域名，也无法解禁管理员已拒绝的域名。运行时过滤器只能*进一步限制*搜索空间。

### 过滤器合规行为

当过滤器生效时，Web Search 优先保证精确率而不是召回率。无法对照你的过滤条件得到验证的结果会被排除，而不是不加过滤地直接返回：

- **域名过滤器生效时：** 无法识别域名的结果会被排除在考虑范围之外。
- **日期过滤器生效时：** 无法识别发布日期的结果会被排除。

过滤器生效时你可能会收到更少的结果，但你收到的每一个结果都满足你指定的过滤条件。

### 上限强制

共有四个列表：管理员 include、管理员 exclude、运行时 include 和运行时 exclude。每个都独立支持最多 **100 个条目**。完整的配置细节与组合规则，请参阅开发者指南中的[配置域名过滤](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-connector-web-search-tool.html#gateway-target-connector-web-search-tool-domain-filtering)。

## 快速上手

Web Search 通过 AgentCore Gateway 提供。AgentCore Gateway 是 Amazon Bedrock AgentCore 的一项能力，它提供一个与 Model Context Protocol（MCP）兼容的托管端点，用于把 agent 连接到工具。按以下步骤为你的 Web Search 目标启用运行时域名过滤和日期过滤。

### 前置条件

- 一个 Amazon Bedrock AgentCore Gateway，其 Web Search 目标固定在 connector 1.2.0 或更高版本。
- AWS Identity and Access Management（IAM）权限：调用方 agent 或应用需要拥有网关 Amazon Resource Name（ARN）上的 `bedrock-agentcore:InvokeGateway`，而 Gateway 的服务角色需要 `bedrock-agentcore:InvokeWebSearch`。完整策略请参阅[配置 Gateway 服务角色](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-add-target-api-target-config.html#gateway-add-target-api-connector-web-search-service-role)。
- 最新的 AWS SDK（Python、JavaScript、Java、.NET、Go、Ruby 或 PHP）。

### 步骤 1：创建一个 1.2.0 版本的 Web Search 目标

使用 AWS SDK for Python（Boto3）创建一个固定在 1.2.0 版本、并带管理员级域名策略的目标（或更新现有目标）。如果你已有 1.1.0 版本的 Web Search 目标，可以用 UpdateGatewayTarget 把它固定到 1.2.0，而不必新建目标。包括 AgentCore CLI 和控制台在内的其他设置方式，请参阅[设置 Web Search 工具](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-add-target-api-target-config.html#gateway-add-target-api-connector-web-search-setup)。

```
import boto3

gateway_client = boto3.client("bedrock-agentcore-control", region_name="us-east-1")

# Create a Web Search target pinned to version 1.2.0 with admin-level domain filtering
target = gateway_client.create_gateway_target(
    gatewayIdentifier="your-gateway-id",
    name="web-search-filtered",
    targetConfiguration={
        "mcp": {
            "connector": {
                "source": {"connectorId": "web-search", "version": "1.2.0"},
                "configurations": [
                    {
                        "name": "WebSearch",
                        "parameterValues": {
                            "domainFilter": {
                                "include": [
                                    "approved-wire-1.com",
                                    "approved-wire-2.com",
                                    "sec.gov",
                                    "investor.gov",
                                ],
                                "exclude": ["unreliable-source.net"],
                            }
                        },
                    }
                ],
            }
        }
    },
    credentialProviderConfigurations=[
        {"credentialProviderType": "GATEWAY_IAM_ROLE"}
    ],
)

print(f"Target ID: {target['targetId']}")
print(f"Status: {target['status']}")
```

### 步骤 2：带运行时过滤器发起调用

设想你的 agent 为法务团队监控 SEC 执法行动。该团队只信任 sec.gov 作为一手来源，并且需要当月的行动，而不是历史备案。下面是你的 agent 发送的 `tools/call` 载荷：

```
{
    "jsonrpc": "2.0",
    "id": "1",
    "method": "tools/call",
    "params": {
        "name": "WebSearch",
        "arguments": {
            "query": "latest SEC enforcement actions 2026",
            "filters": {
                "domainFilter": {
                    "include": ["sec.gov"],
                    "exclude": []
                },
                "publishedDateFilter": {
                    "from": "2026-07-01T00:00:00Z",
                    "to": "2026-08-04T23:59:59Z"
                }
            }
        }
    }
}
```

该 agent 只会收到 sec.gov 上过去五周内发布的结果。结果中不会有第三方法律评论，也不会有过时的备案文件。

**注意：** 你的 `tools/call` 请求中的工具名，是通过 `tools/list` 发现的名称，遵循 `<target-name>___WebSearch` 的模式。对于前面创建的目标，那就是 `web-search-filtered___WebSearch`。运行时 include 列表（sec.gov）与管理员列表（approved-wire-1.com、approved-wire-2.com、sec.gov、investor.gov）取交集。由于 sec.gov 同时出现在两者中，因此会被搜索。如果你传入 some-other-site.com，它会被静默丢弃，因为它不在管理员允许列表中。

## 代码示例

下面是一些示例，展示如何在运行时把由 AgentCore Gateway 创建的 MCP 客户端与新的过滤器一起使用。[用于调用工具的 MCP 客户端创建代码示例](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-using-mcp-call.html)

### 示例 1：有监管引用要求的临床研究助手

你正在为一家制药公司的监管事务团队构建研究助手。公司政策要求每个答案只能引用 FDA、NIH 或 ClinicalTrials.gov。引用健康博客不只是质量问题，它还是可能在审计中暴露的合规违规。该 agent 需要对每次搜索都强制执行这一点，无论模型构造出什么查询。

```
import json

# Pharma research assistant: only approved regulatory sources
compliance_request = json.dumps({
    "jsonrpc": "2.0",
    "id": "req-001",
    "method": "tools/call",
    "params": {
        "name": "WebSearch",
        "arguments": {
            "query": "FDA drug approval process 2026 guidance",
            "maxResults": 10,
            "filters": {
                "domainFilter": {
                    "include": ["fda.gov", "nih.gov", "clinicaltrials.gov"]
                }
            }
        }
    }
})

# Send via your MCP client (SigV4-signed or OAuth-authenticated)
response = mcp_client.send(compliance_request)
results = json.loads(response)

# Every result is from fda.gov, nih.gov, or clinicaltrials.gov
for result in results["result"]["content"]:
    print(result["text"])
```

你的 agent 引用的每一个结果现在都可以被验证为来自已批准的监管来源。即使某篇 WebMD 文章在该查询中排名第一，它也永远不会进入模型的上下文窗口。

### 示例 2：股票更新 agent，只用本周的报道

你的交易台运行一个在交易时段内持续生成股票更新的 agent。问题在于：当交易员问“半导体股票最新情况如何？”时，这个 agent 过去会把上季度一篇排名很高的分析顶上来，而依据过时报道行动的交易员会亏钱。你需要每个结果都来自过去 7 天，没有例外。

```
from datetime import datetime, timedelta, timezone

# Calculate the 7-day window
now = datetime.now(timezone.utc)
seven_days_ago = now - timedelta(days=7)

stock_update_request = json.dumps({
    "jsonrpc": "2.0",
    "id": "req-002",
    "method": "tools/call",
    "params": {
        "name": "WebSearch",
        "arguments": {
            "query": "semiconductor stocks latest developments",
            "maxResults": 15,
            "filters": {
                "publishedDateFilter": {
                    "from": seven_days_ago.strftime("%Y-%m-%dT%H:%M:%SZ"),
                    "to": now.strftime("%Y-%m-%dT%H:%M:%SZ")
                }
            }
        }
    }
})

response = mcp_client.send(stock_update_request)
```

该 agent 的股票更新现在只依据过去七天内发布的报道。那篇上季度排名很高的分析呢？它永远到不了模型，因此也永远不会误导交易员。

**注意：** 当日期过滤器生效时，无法识别发布日期的结果会被排除。这确保每个返回的结果都可以被验证落在你的时间窗口内。

### 示例 3：投资者关系合规，只用一手来源与当季内容

你的投资者关系团队用一个 agent 起草财报分析稿。有两条硬性规则：(1) 只用一手来源：SEC 备案和官方投资者页面，绝不用众包的金融评论站点；(2) 只用本季度的出版物，因为在当季分析中引用上季度的数字是重大错误。你需要这两条约束在每次搜索中同时生效。

```
# IR compliance agent: primary sources + current quarter only
financial_request = json.dumps({
    "jsonrpc": "2.0",
    "id": "req-003",
    "method": "tools/call",
    "params": {
        "name": "WebSearch",
        "arguments": {
            "query": "AMZN quarterly earnings report Q2 2026",
            "maxResults": 10,
            "filters": {
                "domainFilter": {
                    "include": ["sec.gov", "investor.gov"],
                    "exclude": ["example-crowd-commentary-1.com", "example-crowd-commentary-2.com"]
                },
                "publishedDateFilter": {
                    "from": "2026-04-01T00:00:00Z",
                    "to": "2026-08-04T23:59:59Z"
                }
            }
        }
    }
})

response = mcp_client.send(financial_request)
```

该 agent 的草稿现在只引用 2026 年 Q2 和 Q3 的官方备案与通讯社报道。众包评论和观点文章即使与查询完美匹配也会被屏蔽。任何来自更早季度的内容，无论来源如何，都会被排除。

### 示例 4：按租户来源策略提供服务的 SaaS 平台

你运营一个研究型 agent 的 SaaS 平台，服务于医疗、法律和金融服务客户。每个租户都有合同约定的来源策略。你的医疗客户在《商业伙伴协议》（BAA）中要求只能引用 PubMed、CDC 和已批准的医学研究数据库。你的法律客户坚持使用 Cornell LII 和官方法院记录。你的金融客户强制要求 SEC、美联储和已批准的通讯社。你无法为每个租户单独起一个网关目标（你已有 200 个租户且还在增加），所以你用 Strands Agents SDK 在运行时施加租户专属的过滤器。

```
from strands import Agent
from strands.models import BedrockModel
from strands.tools.mcp.mcp_client import MCPClient
from mcp.client.streamable_http import streamablehttp_client

# Per-tenant domain policies (from your config database)
TENANT_POLICIES = {
    "tenant-healthcare": {
        "include": ["pubmed.ncbi.nlm.nih.gov", "who.int", "cdc.gov"],
        "exclude": ["example-consumer-health-site.com"],
    },
    "tenant-legal": {
        "include": ["law.cornell.edu", "supremecourt.gov", "uscourts.gov"],
        "exclude": [],
    },
    "tenant-finance": {
        "include": ["sec.gov", "federalreserve.gov", "example-approved-wire.com"],
        "exclude": ["example-social-forum-site.com"],
    },
}


def search_for_tenant(tenant_id: str, query: str, days_back: int = 30):
    """Execute a policy-compliant web search for a specific tenant."""
    from datetime import datetime, timedelta, timezone

    policy = TENANT_POLICIES[tenant_id]
    now = datetime.now(timezone.utc)
    date_from = (now - timedelta(days=days_back)).strftime("%Y-%m-%dT%H:%M:%SZ")

    def create_transport():
        return streamablehttp_client(
            gateway_url,
            headers={"Authorization": f"Bearer {get_token()}"},
        )

    mcp_client = MCPClient(create_transport)

    model = BedrockModel(
        model_id="us.anthropic.claude-sonnet-4-20250514-v1:0",
        max_tokens=2048,
    )

    with mcp_client:
        tools = mcp_client.list_tools_sync()
        agent = Agent(model=model, tools=tools)

        # The agent's system prompt instructs it to pass these filters
        # on every WebSearch invocation
        system_prompt = f"""You are a research assistant. When using WebSearch,
ALWAYS include these filters in your tool call:

- domainFilter.include: {policy['include']}
- domainFilter.exclude: {policy['exclude']}
- publishedDateFilter.from: {date_from}

Never search outside approved domains."""

        result = agent(query, system_prompt=system_prompt)
        return result.message


# Usage
answer = search_for_tenant(
    "tenant-healthcare",
    "What are the latest clinical trial results for GLP-1 drugs?"
)
```

一个网关目标服务 200 个租户，每个租户都有自己的来源策略，并在调用时动态强制执行。你的医疗租户的 agent 永远不会引用 Reddit 或 WebMD，你的金融租户的 agent 也永远不会引用博客文章，尽管它们共享同一套底层基础设施。

**重要：** 基于 system prompt 的过滤（如前所示）依赖 agent 遵循指令，它并不是硬性强制。要做到硬性强制，请在目标层（管理员 include 列表）配置允许的域名。直接放在 `tools/call` 载荷里的运行时过滤器提供 API 级强制，模型无法绕过。

## 输入 schema 参考

connector 1.2.0 版本引入的 filters 对象在现有的 `query` 和 `maxResults` 字段之外，新增了 `domainFilter`（include/exclude 列表，各自最多 100 个域名）和 `publishedDateFilter`（含端点的 ISO-8601 UTC 边界）。完整的输入 schema 与逐字段参考，请参阅 Amazon Bedrock AgentCore 开发者指南中的[输入 schema](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-connector-web-search-tool.html#gateway-target-connector-web-search-tool-input-schema)。

## 可用性与零数据出站

运行时域名过滤与日期过滤现已在以下区域为 Amazon Bedrock AgentCore 上的 Web Search 提供：美国东部（弗吉尼亚北部）（us-east-1）、欧洲（爱尔兰）（eu-west-1）和亚太（东京）（ap-northeast-1）。

Web Search 受益于 AgentCore 的零数据出站架构：搜索查询完全在 AWS 基础设施内处理。客户查询不会被发送到第三方搜索引擎，也不会被路由到 AWS 之外。对于金融服务、医疗和政府等受监管行业的组织来说，这直接消除了一整类合规审查。

## 向后兼容性

这些功能完全向后兼容：

- **无破坏性变更。** 1.2.0 是次要版本。新字段是增量添加的，filters 对象是可选的。不带过滤器的现有 API 调用行为完全不变。
- **SDK 支持。** 覆盖各类 AWS SDK（Python（Boto3）、JavaScript/TypeScript、Java、.NET、Go、Ruby 和 PHP SDK）、AWS Command Line Interface（AWS CLI）以及 [AgentCore CLI](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-tools.html#_web_search)。
- **控制台支持。** AgentCore Web Search 目标的 AWS 控制台现在会在 connector 配置 UI 中展示 include 和 exclude 两个域名列表输入项。

## 结论

运行时域名过滤与发布日期过滤，为在 Amazon Bedrock AgentCore Gateway 上构建的开发者提供了按调用所需的精确度，让他们能够构建可信、符合策略的 agent，同时不必牺牲托管式服务端搜索工具的简洁性。

无论你是把 agent 限制在已批准的监管来源、把结果限定在过去 24 小时内，还是动态施加租户专属策略，AgentCore 上的 Web Search 都能让你保持掌控：零数据出站、IAM 原生身份验证，且没有外部依赖。

这些功能现已在以下 AWS 区域为 Amazon Bedrock AgentCore 上的 Web Search 提供：美国东部（弗吉尼亚北部）（us-east-1）、欧洲（爱尔兰）（eu-west-1）和亚太（东京）（ap-northeast-1）。
