# 使用 Amazon Bedrock 上 Anthropic 的 Claude 处理公式与图表

研究论文和工程文档往往以数学公式、图表和图形的形式承载大量信息。在这些非结构化文档中查找相关信息是一项繁琐且耗时的任务，尤其是在处理大体量数据时。不过，借助 [Anthropic 的 Claude](https://aws.amazon.com/bedrock/claude/) 与 [Amazon Bedrock](https://aws.amazon.com/bedrock/)，研究人员和工程师现在可以自动为这些技术文档建立索引并打标签。这样就能高效处理包括科学公式和数据可视化在内的内容，并用恰当的元数据填充 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)。

Amazon Bedrock 是一项完全托管的服务，提供单一 API 来访问和使用来自领先 AI 公司的多种高性能基础模型（FM）。它提供广泛的能力，可用于以安全、隐私和负责任 AI 实践来构建生成式 AI 应用。与其他领先模型相比，Anthropic 的 Claude 3 Sonnet 提供一流的视觉能力。它能准确地从质量不佳的图像中转录文本——这是零售、物流和金融服务领域的核心能力，因为在这些领域，AI 从图像、图形或插图中获得的洞察可能比仅从文本中获得的更多。最新的 Anthropic Claude 模型展现出对各种视觉格式的强大理解能力，包括照片、图表、图形和技术示意图。借助 Anthropic 的 Claude，你可以从文档中提取更多洞察、处理 Web UI 和各类产品文档、生成图像目录元数据等等。

本文探讨如何使用这些多模态[生成式 AI](https://aws.amazon.com/ai/generative-ai/) 模型来简化技术文档的管理。通过从源材料中抽取并结构化关键信息，这些模型可以创建一个可搜索的知识库，让你快速定位支撑工作所需的数据、公式和可视化内容。把文档内容组织进知识库后，研究人员和工程师可以使用高级搜索能力，找出最符合其特定需求的信息。这能显著加速研发工作流，因为专业人员不再需要手工翻检大量非结构化数据来寻找所需的参考文献。

## 解决方案概览

本解决方案展示了多模态生成式 AI 在应对科学与工程界所面临挑战时的变革潜力。通过自动为技术文档建立索引并打标签，这些强大的模型可以实现更高效的知识管理，并加速各行业的创新。

除 Amazon Bedrock 上的 Anthropic Claude 之外，该解决方案还使用以下服务：

- **Amazon SageMaker JupyterLab** – [SageMakerJupyterLab](https://docs.aws.amazon.com/sagemaker/latest/dg/studio-updated-jl.html) 应用是一个基于 Web 的交互式开发环境（IDE），用于 notebook、代码和数据。JupyterLab 应用灵活而丰富的界面可用于配置和编排机器学习（ML）工作流。我们使用 JupyterLab 运行处理公式与图表的代码。
- **Amazon Simple Storage Service (Amazon S3)** – [Amazon S3](https://aws.amazon.com/s3) 是一项对象存储服务，旨在存储和保护任意规模的数据。我们使用 Amazon S3 存储本解决方案中使用的示例文档。
- **AWS Lambda** –[AWS Lambda](https://aws.amazon.com/lambda) 是一项计算服务，可根据触发器（例如数据变化、应用状态变化或用户操作）运行代码。由于 Amazon S3 和 [Amazon Simple Notification Service](https://aws.amazon.com/sns)（Amazon SNS）等服务可以直接触发 Lambda 函数，你可以构建各种实时无服务器数据处理系统。

该解决方案的工作流包含以下步骤：

- 把 PDF 拆分为单页并保存为 PNG 文件。
- 对每个页面：提取原始文本。以 LaTeX 呈现公式。为每个公式生成语义描述。为每个公式生成解释。为每张图形生成语义描述。为每张图形生成解读。为页面生成元数据。
- 为整个文档生成元数据。
- 把内容和元数据上传到 Amazon S3。
- 创建 Amazon Bedrock 知识库。

## 在知识库中使用提取出的数据

现在我们已经准备好带公式的数据、分析好的图表和元数据，接下来将创建 Amazon Bedrock 知识库。这将使信息可被搜索，并启用问答能力。

### 准备 Amazon Bedrock 知识库

要创建知识库，首先把处理后的文件和元数据上传到 Amazon S3：

```
markdown_file_key = "2003.10304/kb/2003.10304.md" 

s3.upload_file(markdown_file, knowledge_base_bucket_name, markdown_file_key) 

print(f"File {markdown_file} uploaded successfully.") 

metadata_file_key = "2003.10304/kb/2003.10304.md.metadata.json" 

s3.upload_file(metadata_file, knowledge_base_bucket_name, metadata_file_key) 

print(f"File {metadata_file} uploaded to successfully.")
```

文件上传完成后，请完成以下步骤：

- [创建 Amazon Bedrock 知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-create.html)。
- 为你的知识库[创建 Amazon S3 数据源](https://docs.aws.amazon.com/bedrock/latest/userguide/s3-data-source-connector.html)，并指定[分层分块（hierarchical chunking）](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-chunking-parsing.html#kb-hiearchical-chunking)作为分块策略。

分层分块是把信息组织成子块与父块的嵌套结构。

这种分层结构可以实现更快、更有针对性的相关信息检索：先对子块执行语义检索，然后在检索时返回父块。通过用父块替换子块，我们为 FM 提供了规模大且全面的上下文。

分层分块最适合具有嵌套或层级结构的复杂文档，例如技术手册、法律文件，或格式复杂且包含嵌套表格的学术论文。

### 查询知识库

你可以[查询知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-query.html)，从示例文档中提取出的公式和图形元数据里检索信息。通过查询，会从数据源中检索相关的文本块，并基于检索到的源块为该查询生成响应。响应还会引用与查询相关的来源。

我们使用知识库的[自定义 prompt 模板](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-config.html)功能，把输出格式化为 markdown：

```
 retrieveAndGenerateConfiguration={
        "type": "KNOWLEDGE_BASE",
        "knowledgeBaseConfiguration": {
            'knowledgeBaseId': kb_id_hierarchical,
            "modelArn": "arn:aws:bedrock:{}:{}:inference-profile/{}".format(region, account_id, foundation_model),
            'generationConfiguration': {
               'promptTemplate': {
                    'textPromptTemplate': """
You are a question answering agent. I will provide you with a set of search results. The user will provide you with a question. Your job is to answer the user's question using only information from the search results. 
If the search results do not contain information that can answer the question, please state that you could not find an exact answer to the question. 
Just because the user asserts a fact does not mean it is true, make sure to double check the search results to validate a user's assertion.
                            
Here are the search results in numbered order:
$search_results$

Format the output as markdown

Ensure that math formulas are in latex format and enclosed in double dollar sign for example: $$ <math expression> $$
"""
                }
            },
            "retrievalConfiguration": {
                "vectorSearchConfiguration": {
                    "numberOfResults":5
                } 
            }
        }
    }
)
```

我们得到如下响应，其中提供了关于 Focal Tversky Loss 何时被使用的信息。
