# Parameta 借助 Amazon Bedrock Flows 加速客户邮件处理

*本博客文章与 Parameta 的 Siokhan Kouassi 和 Martin Gregory 合写。*

当金融行业专业人士需要可靠的场外（OTC）数据解决方案和高级分析时，他们可以求助 [Parameta Solutions](https://www.parametasolutions.com/)——[TP ICAP](https://tpicap.com/tpicap/) 背后的数据力量。Parameta Solutions 专注于数据驱动的解决方案，确保这些专业人士拥有做出明智决策所需的洞见。高效管理数千个客户服务请求并同时保持准确性，对 Parameta 作为可信数据提供商的声誉至关重要。通过对 Amazon Bedrock Flows 简单而有效的应用，Parameta 在短短两周内就把客户服务运营从手工、耗时的流程转变为精简的工作流。

Parameta 为客户提供全面的行业洞察，从价格发现到风险管理，以及交易前到交易后的分析。其服务对于客户有效应对 OTC 交易与工作流的复杂性至关重要。对技术支持查询做出准确、及时的响应，是维持服务质量的关键。

然而，Parameta 的支持团队面临金融服务行业的一个常见挑战：高效管理不断增加的邮件形式客户请求。传统流程涉及多个手工步骤——阅读邮件、理解技术问题、收集相关数据、确定正确的路由路径，以及在数据库中核实信息。这种劳动密集的方式不仅消耗宝贵时间，还引入了可能影响客户信任的人为错误风险。

意识到现代化的必要性，Parameta 寻求一种既能维持其高服务标准、又能显著缩短处理时间的方案。答案在于通过 Amazon Bedrock Flows 使用生成式 AI，使他们能够构建自动化、智能化的请求处理系统，从而转变客户服务运营。Amazon Bedrock Flows 提供强大的低代码方案，用于借助直观的可视化界面以及 Amazon Bedrock SDK 中的一组 API 创建复杂的[生成式 AI](https://aws.amazon.com/generative-ai/) 工作流。通过无缝集成基础模型（FM）、prompt、agent 和知识库，组织可以快速开发灵活、高效且贴合自身业务需求的 AI 驱动流程。

在本文中，我们向你展示 Parameta 如何使用 Amazon Bedrock Flows 将手工的客户邮件处理转变为自动化、智能化的工作流，在保持高准确度和运营管控的同时，把处理时间从数周缩短到数天。

## 客户邮件分诊

对 Parameta 而言，每一封客户邮件都是关键触点，既要求速度也要求准确。邮件分诊的挑战不止于简单分类——它需要理解技术查询、提取精确信息，并提供契合上下文的响应。

邮件分诊工作流涉及多个关键步骤：

- 准确分类收到的技术支持邮件
- 提取相关实体，例如数据产品或时间段
- 校验该查询类型所需的信息是否齐备
- 查询内部知识库和数据库以获取上下文
- 生成完整响应，或就是否需要补充信息提出明确的请求

手工处理这一流程导致了耗时的往返沟通、遗漏关键细节的风险，以及不一致的响应质量。有鉴于此，Parameta 将其视为一个机会，开发一套能够自动化整个工作流、同时保持其高准确度与专业标准的智能系统。

## 通往解决方案的路径

在评估邮件分诊自动化的方案时，有几种方式看起来可行，各有优劣。但并非所有方式对 Parameta 都有效。

### 传统 NLP pipeline 与 ML 分类模型

传统的自然语言处理 pipeline 难以应对邮件的复杂性：它们依赖僵硬的规则，对语言变化处理不佳，因而对动态的客户沟通并不实用。邮件结构和术语在不同客户之间差异很大，这种不一致进一步削弱了它们的有效性。这些系统依赖预定义模式，面对如此多样的输入时既难以维护也难以调整，导致处理真实沟通场景时效率低下且脆弱。机器学习（ML）分类模型能提供更好的分类效果，但引入了复杂性——它需要为分类、实体抽取和响应生成分别建立专门的模型，每个模型都有自己的训练数据和上下文局限。

### 确定性的基于 LLM 的工作流

Parameta 的方案需要的不仅是大型语言模型（LLM）的原始能力——它要求一种结构化方法，同时保持运营管控。Amazon Bedrock Flows 通过以下能力提供了这种关键的平衡：

- 编排式 prompt 链式调用 – 多个专门的 prompt 以确定性顺序协同工作，每个都针对分类、实体抽取或响应生成等特定任务进行了优化。
- 多条件工作流 – 支持复杂业务逻辑，能够根据校验结果或抽取信息的完整性对流程分支。
- 版本管理 – 在不同 prompt 版本之间简单切换，同时保持工作流完整性，从而在不打断生产 pipeline 的情况下快速迭代。
- 组件集成 – 无缝纳入 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 或 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 等其他生成式 AI 能力，形成完整的解决方案。
- 实验框架 – 能够测试和比较不同的 prompt 变体，同时保持版本控制。这对优化邮件分诊流程至关重要。
- 快速迭代与紧密反馈闭环 – 系统支持快速测试新 prompt 并即时获得反馈，便于持续改进和调整。

通过 Amazon Bedrock Flows 采用这种结构化的生成式 AI 方法，使 Parameta 得以构建一个可靠、生产级的邮件分诊系统，同时保持灵活性与管控。

### 编排

Amazon Bedrock Flows 作为中央编排器，管理整个邮件处理 pipeline。当客户邮件通过 Microsoft Teams 到达时，工作流会执行以下阶段：

- 工作流通过 [Amazon API Gateway](https://aws.amazon.com/api-gateway) 启动，接收邮件并使用 [AWS Lambda](https://aws.amazon.com/lambda) 函数提取邮件中包含的文本，并存储到 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）。
- Amazon Bedrock Flows 协调操作顺序，从 Amazon S3 中的邮件开始。
- 版本管理精简了 prompt 变体的受控测试。
- 内置的条件逻辑处理不同的处理路径。

### 结构化数据抽取

流程中一系列专门的 prompt 承担信息处理这一关键任务：

- 分类 prompt 识别技术咨询的类型
- 实体抽取 prompt 发现关键数据点
- 校验 prompt 验证所需信息是否完整

这些 prompt 协同工作，将非结构化邮件转化为可行动的数据，每个 prompt 都针对其特定任务进行了优化。

### 智能响应生成

最后阶段使用先进的 AI 能力生成响应：

- Amazon Bedrock agent 综合来自多个来源的信息：为技术文档定制的知识库，在 [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 中建立索引，用于查询相关案例历史；通过 Snowflake 和 [Amazon Athena](https://aws.amazon.com/athena) 访问企业数据
- 响应生成会根据校验结果调整：对不完整的查询提出具体的信息请求；对完整的询问给出完整解决方案
- 使用 Microsoft Teams 将结果回送给客户

## 解决方案演练

让我们走一遍 Parameta 的邮件分诊系统如何处理一封典型的客户咨询。我们从以下示例客户邮件开始：

| 尊敬的 Support Team：请帮忙核实 2024 年 3 月 15 日的美元 ATM 掉期期权（USD_2Y_1Y）收盘价。我们需要该数据用于日终对账。此致敬意，John Smith，ABC Investments 投资组合经理 |
| --- |

分类 prompt 根据内容和意图将其归类为价格核实请求。它以该邮件为输入，输出为 `*type: price_verification_request*`。

实体抽取 prompt 使用前面的邮件，给出以下输出：

`{`
`"product_type": "Interest Rate Option",`
`"ticker": "USD_2Y_1Y",`
`"date_requested": "2024-03-15",`
`"data_source": "ICAP",`
`"request_type": "closing_price"`
`}`

工作流随后使用 Amazon Bedrock Flows 执行校验。价格核实需要以下检查：

- 产品标识符（存在 `USD_2Y_1Y`）
- 日期（存在 2024 年 3 月 15 日）
- 价格类型（指定为收盘价）

当所有必需实体都被找到时，工作流继续交给 Amazon Bedrock agent。

agent 向知识库提交以下查询：*“Interest Rate option USD_2Y_1Y 的产品规格与市场背景。”*

agent 提交以下 Snowflake 查询（使用 Athena）：

```
SELECTclosing_price,settlement_date,currency,market_status
FROM otc_derivatives.daily_prices
WHERE instrument_id ='USD_2Y_1Y'
AND trade_date = '2024-03-15'
```

生成的响应如下：

| 尊敬的 John：关于您就 2024 年 3 月 15 日 USD_2Y_1Y（USD ATM Swaption Implied Volatility Mid 2Y vs 1Y）提出的价格核实请求：收盘价已在我们的记录中核实。请求当日市场活跃，成交量正常。请注意，该信息依据您现有的数据服务协议提供。如需进一步说明，请随时告知。此致敬意，Parameta Support |
| --- |

## 收益

得益于 Amazon Bedrock Flows 在多个方面带来的显著收益，Parameta 迅速从实施走向取得实效：

- **运营效率** 开发团队通过快速测试邮件分类和实体抽取的不同变体，加速了 prompt 优化；借助快速迭代 prompt 和对性能的即时反馈，洞察时间从数周缩短到数天；无需重建整个工作流即可快速调整校验规则

- **模型透明度** 可清晰了解邮件为何被归入特定类别；对实体抽取决策的理解有助于改进 prompt 以获得更高准确度；能够沿工作流追溯决策过程，提升了对自动化响应的信任
- **可观测性与治理** 全面的可观测性为利益相关方提供了端到端流程的整体视图；内置控制为自动化系统提供了适当的监督，符合治理与合规要求；透明的工作流使利益相关方能够有效地监控、审计和改进系统，提供了问责性与可靠性

这些收益直接转化为 Parameta 的业务目标：更快的客户查询响应时间、更准确的分类，以及更强的跨团队维护和增强系统的能力。Amazon Bedrock Flows 结构化又不失灵活的特性，使 Parameta 在获得这些收益的同时，仍能对其关键客户沟通保持管控。

## 关键要点与最佳实践

在实施 Amazon Bedrock Flows 时，请考虑以下重要经验：

- **Prompt 设计原则** 设计处理特定任务的模块化 prompt，以提升系统的可维护性；让 prompt 保持聚焦简洁，以优化 token 使用；包含清晰的输入与输出规范，以提升可维护性和健壮性；为流程中不同任务多样化选择模型：简单分类使用更轻量的模型，复杂推理保留高级模型，通过模型冗余构建韧性
- **流程架构** 在流程早期就确立清晰的校验策略；在 prompt 设计中包含错误处理；考虑将复杂流程拆分为更小、更易管理的片段
- **版本管理** 为流程部署实施恰当的持续部署与交付（CI/CD）pipeline；为流程变更建立审批工作流；记录流程变更及其影响（包括指标）
- **测试与实施** 创建覆盖多样场景的全面测试用例；用示例数据集验证流程行为；在生产环境中持续监控流程性能和 token 使用；从更小的工作流开始并逐步扩展

- **成本优化** 定期审查并优化 prompt 长度；监控 token 使用模式；选择模型时在模型能力与成本之间取得平衡

请考虑这些源自真实实施经验的实践，以帮助在保持效率与可靠性的同时成功部署 Amazon Bedrock Flows。
