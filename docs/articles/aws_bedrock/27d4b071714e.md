# 使用 Pipecat 和 Amazon Bedrock 构建智能 AI 语音 agent —— 第 2 部分

语音 AI 正在改变我们使用技术的方式，让对话变得更加自然和直观。与此同时，先进的 AI agent 现在能够理解复杂的问题，并代表我们自主采取行动。

在本系列的[第 1 部分](https://aws.amazon.com/blogs/machine-learning/building-intelligent-ai-voice-agents-with-pipecat-and-amazon-bedrock-part-1/)中，你了解了如何结合 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和 [Pipecat](https://github.com/pipecat-ai/pipecat)（一个用于语音和多模态对话式 AI agent 的开源框架）来构建具有类人对话能力的 AI 应用。你了解了语音 agent 的常见用例，以及级联模型（cascaded models）方法——即编排多个组件来构建语音 AI agent。

在本文（第 2 部分）中，你将探索如何使用语音到语音（speech-to-speech）基础模型 [Amazon Nova Sonic](https://aws.amazon.com/ai/generative-ai/nova/speech/)，以及使用统一模型的好处。

## 架构：使用 Amazon Nova Sonic 的语音到语音

[Amazon Nova Sonic](https://aws.amazon.com/ai/generative-ai/nova/speech/) 是一个语音到语音基础模型，能以业界领先的性价比和低延迟提供实时、类人的语音对话。第 1 部分中介绍的级联模型方法虽然灵活且模块化，但需要编排自动语音识别（ASR）、自然语言处理（NLU）和文本转语音（TTS）模型。对于对话式用例，这可能引入延迟，并导致语调和韵律的损失。Nova Sonic 把这些组件合并成一个统一模型，通过单次前向传递实时处理音频，既降低延迟又简化开发。

通过统一这些能力，模型可以根据输入的声学特征和对话上下文动态调整语音响应，创造更流畅、更贴合上下文的对话。系统能识别自然的停顿、犹豫和轮次转换提示等对话中的细微之处，从而在合适的时机做出回应，并无缝处理对话中的打断。Amazon Nova Sonic 还支持工具调用和基于 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 的 agentic RAG，使你的语音 agent 能够检索信息。请参考下图了解端到端 flow。

两种方法之间的选择取决于你的用例。虽然 Amazon Nova Sonic 的能力处于业界领先水平，但如果你需要为高级用例提供额外的灵活性或模块化能力，第 1 部分中介绍的级联模型方法可能更合适。

## 开始使用 Amazon Nova Sonic 和 Pipecat

为给你的实现提供指引，我们提供了一个演示基本功能的完整代码示例。该示例展示了如何使用 Amazon Nova Sonic 和 Pipecat 构建一个完整的语音 AI agent。

### 先决条件

在把提供的代码示例与 Amazon Nova Sonic 一起使用之前，请确保你具备以下条件：

- Python 3.12+
- 一个具有相应 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 权限的 AWS 账户，权限需覆盖 [Amazon Bedrock](https://aws.amazon.com/bedrock)、[Amazon Transcribe](https://aws.amazon.com/transcribe) 和 [Amazon Polly](https://aws.amazon.com/polly)
- 在 Amazon Bedrock 上[访问](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html#:~:text=To%20request%20access%20to%20a,want%20to%20add%20access%20to.) Amazon Nova Sonic 的权限
- [访问](https://docs.daily.co/reference/rest-api) Daily API key 的权限
- 支持 WebRTC 的现代 Web 浏览器（例如 Google Chrome 或 Mozilla Firefox）

### 实施步骤

完成先决条件后，你就可以开始设置示例语音 agent：

- **克隆仓库：**

```
git clone https://github.com/aws-samples/build-intelligent-ai-voice-agents-with-pipecat-and-amazon-bedrock
cd build-intelligent-ai-voice-agents-with-pipecat-and-amazon-bedrock/part-2
```

- **设置虚拟环境：**

```
cd server
python3 -m venv
venv source venv/bin/activate # On Windows: venv\Scripts\activate
pip install -r requirements.txt
```

- **创建 **`.env`** 文件并填入你的凭证：**

```
DAILY_API_KEY=your_daily_api_key
AWS_ACCESS_KEY_ID=your_aws_access_key_id
AWS_SECRET_ACCESS_KEY=your_aws_secret_access_key
AWS_REGION=your_aws_region
```

- **启动服务器：**

```
python server.py
```

- **使用浏览器**访问 `http://localhost:7860` 并授予麦克风访问权限。
- **开始与你的 AI 语音 agent 对话**。

## 使用 Strands Agents 增强 agentic 能力

提升 agentic 能力和理解力的一种实用方法是实现一个通用工具调用，把工具选择委派给外部 agent，例如 [Strands Agent](https://strandsagents.com/latest/)。被委派的 Strands Agent 随后可以对你的复杂查询进行推理或思考，通过工具调用执行多步任务，并返回汇总后的响应。

为说明这一点，我们来看一个简单的例子。如果用户提出这样的问题：*“西雅图水族馆附近的天气怎么样*？”，语音 agent 可以通过诸如 `handle_query` 这样的通用工具调用委派给 Strands agent。

Strands agent 会处理该查询并思考任务，例如：

```
<thinking>I need to get the weather information for the Seattle Aquarium. To do this, I need the latitude and longitude of the Seattle Aquarium. I will first use the 'search_places' tool to find the coordinates of the Seattle Aquarium.</thinking> 
```

随后，Strands Agent 会执行 `search_places` 工具调用、随后的 `get_weather` 工具调用，并作为 `handle_query` 工具调用的一部分把响应返回给父 agent。这也被称为 [agent as tools](https://strandsagents.com/0.1.x/user-guide/concepts/multi-agent/agents-as-tools/) 模式。

要了解更多信息，请参阅我们的[动手实践工作坊](https://catalog.workshops.aws/voice-ai-agents/en-US/module2) 中的示例。
