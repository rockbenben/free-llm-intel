# 推出 Amazon SageMaker AI 双向流式的按用量计费

面向双向流式的按用量计量，解决了实时语音 AI 的一个软件计费难题。在 [Amazon SageMaker AI bidirectional streaming](https://aws.amazon.com/blogs/machine-learning/introducing-bidirectional-streaming-for-real-time-inference-on-amazon-sagemaker-ai/) 上部署流式模型的客户，要为承载模型的 endpoint 基础设施付费；与此同时，在 AWS Marketplace 上架的模型供应商，需要一种方式对客户在一次实时流里消费掉的东西收费。今天，我们宣布 Amazon SageMaker 双向（bidi）流式推理支持按用量计量，好让模型供应商为 AWS Marketplace 软件费用上报实际用量。Amazon SageMaker AI 的 endpoint 基础设施费用照旧适用。

实时语音 AI 公司 [Deepgram](https://deepgram.com/) 是这项能力的首发合作伙伴，把按用量的 Speech-to-Text（STT）与 Text-to-Speech（TTS）计费带到 AWS Marketplace。本文建立在 Deepgram 与 AWS 一系列创新之上。首先，我们[为 Amazon SageMaker AI 上的实时推理推出了双向流式](https://aws.amazon.com/blogs/machine-learning/introducing-bidirectional-streaming-for-real-time-inference-on-amazon-sagemaker-ai/)，支持客户端与模型服务器之间长时存在的双向流。随后，Deepgram [用 AWS Identity and Access Management（AWS IAM）临时委派增强了 Amazon SageMaker AI 支持](https://aws.amazon.com/blogs/machine-learning/deepgram-enhances-amazon-sagemaker-ai-support-with-aws-iam-temporary-delegation/)，简化企业部署的安全认证，并[用增强指标扩展了可观测性](https://aws.amazon.com/blogs/machine-learning/deepgram-deepens-amazon-sagemaker-ai-observability-with-enhanced-metrics/)。如今有了按用量计量，我们进一步夯实生产级实时 AI 的地基，让计费与客户消费流式、实时 AI 工作负载的方式对齐。

## 流式为什么打破了既有计费模式

对 SageMaker AI 实时请求-响应推理，AWS Marketplace 软件计量允许模型供应商在一个 HTTP 响应头里上报单位数，AWS Marketplace 拿这个数量算软件费。这对「响应发出时即可知道计费数量」的请求-响应 API 行得通。

双向流式不一样。客户端通过 SageMaker AI API、以 HTTP/2 event stream 流式送入音频并接收转写；SageMaker AI 则通过 WebSockets 连到模型服务器。一次会话可能持续 30 秒，也可能 30 分钟。用量随会话进行不断累积，最终总量要到结束时才知道。光靠一个响应头，没法在这场实时会话期间周期性地报用量。

按小时的软件定价会在模型可用期间向客户收费，空闲时段也算。有了按用量计量，供应商就能让 AWS Marketplace 软件费与上报用量对齐。SageMaker AI 的 endpoint 基础设施费用仍然独立，且在 endpoint 预置期间继续适用。

## companion metadata streaming 如何工作

方案在既有推理流之外引入第二条 WebSocket 连接。双向流式会话启动时，SageMaker AI 与模型服务器建立两条连接：

- **数据连接**：承载推理请求与响应数据，即既有的双向流。
- **元数据连接**：一条专用于计量数据的 companion WebSocket。

模型服务器通过在 WebSocket upgrade 响应里返回一个头来 opt in：

`X-Amzn-SageMaker-Metadata-Stream-Supported: true`

随后 SageMaker AI 在 `/invocations-bidirectional-stream-metadata` 处向模型服务器打开一条 companion WebSocket。两条连接带着同一个 `X-Amzn-SageMaker-Request-Id` 头，模型服务器用它把计量记录与活跃的推理会话关联起来。

模型服务器在元数据连接上以 JSON text frame 发送计量数据。发送频率要与计费模型匹配：随用量累积增量上报（推荐）——要么每消费一个单位就报，要么把自上一条记录以来消费的单位攒成周期批次。会话一结束就立刻发出最后一条记录。每个 frame 恰好含一条计量记录，而不是一个记录数组。元数据流有速率配额：每连接每秒一条消息，最大消息 512 字节。

我们建议随用量累积增量发送计量记录。这样在会话意外结束时，未上报的用量会少一些。仅传输送达本身并不能证明用量已被计费。请把上报单位与 AWS Marketplace 报告及买方扣费对账。

```
{
  "Metering": {
    "Dimension": "inference.count",
    "ConsumedUnits": 720,
    "ClientToken": "a3f2b1c0-unique-uuid"
  }
}
```

计量消息用 `inference.count` 这个 dimension，`ConsumedUnits` 给出该 dimension 的数量。若产品按音频秒数收费，一条报告 12 分钟计费音频的记录就带 `ConsumedUnits: 720`（720 秒）。dimension 名并不表示「每请求一个单位」。哪段音频算计费用量由供应商定义，AWS Marketplace offer 把这个单位映射到价格。listing 里每单位显示一个价格、标注为 per request，最多三位小数。`ClientToken` 字段支持幂等。若同一连接上来了重复 token，SageMaker AI 会静默丢弃重复消息。

元数据连接跑在 TCP 上，传输层提供有序、可靠的送达。若它建立失败或会话中途掉线，推理默认仍继续，因为 `X-Amzn-SageMaker-Metadata-Stream-Required` 默认是 `false`。当供应商必须在元数据流不可用时停止推理，就把这个头设为 `true`。这是在「推理可用性」与「计量连续性」之间做取舍，它并不保证畸形或被丢弃的记录会被计费。

## 对客户意味着什么

如果你为转写、联络中心、语音 agent 或字幕部署实时 AI 模型，新的计量模式会改变 AWS Marketplace 软件费的计算方式。SageMaker AI 的 endpoint 基础设施费用照旧适用。

通过 AWS Marketplace 做透明的按单位计费，意味着用量直接汇进你的 AWS 账单。你得到合并的 AWS 计费、通过 private offers 拿到的议价费率，也无需再和模型供应商单独维护一套计费关系。

按产品定义的单位，为处理过的音频付费。若产品按音频秒数收费，12 分钟计费音频等于 720 个计费秒、`ConsumedUnits: 720`。一条持续 12 分钟的连接本身并不定义可计费的音频量。计费用量由供应商的计数规则决定，而 endpoint 基础设施费用仍然独立。

模型供应商可以通过 AWS Marketplace private offers 提供议定的按单位费率或固定价合同。

我们建议直接与你的 AWS 客户经理或合作伙伴代表沟通。

## 对模型供应商意味着什么

如果你是在 AWS Marketplace 上架的模型供应商，可以把模型服务器配置成：在流式推理会话期间通过 companion metadata streaming 上报用量。

[SageMaker Marketplace Onboarding Agent Skill](https://github.com/aws-samples/sample-sagemaker-marketplace-onboarding-skill) 用一条 opt-in 的推理计量路径加速接入。它的起步模板会声明支持 metadata-stream，并为 companion WebSocket 构造经过校验的、增量式的 `ConsumedUnits` frame。提交前请评审代码并做生产加固。

定义「一个单位代表什么」，并随会话推进上报单位，让计费与你的定价模型对齐。AWS Marketplace 对实时推理按一个每单位价格收费。

下面这个三步实操，讲如何集成模型服务器，使其在双向流式推理会话期间上报计量数据。

### 第 1 步：用数据 WebSocket 响应头 opt in

当 SageMaker AI 向你的模型服务器打开数据 WebSocket 连接时，在 WebSocket upgrade（101）响应里带上这些头：

|  | **头** | **是否必需** | **取值** | **说明** |
| --- | --- | --- | --- | --- |
| 1 | `X-Amzn-SageMaker-Metadata-Stream-Supported` | **是**（用于 opt in） | TRUE | 表示你的模型服务器支持 companion metadata stream。缺失或不为 `true` 时，不会尝试建立元数据连接。没有元数据流，该会话就不会为模型供应商的软件费计量。 |
| 2 | `X-Amzn-SageMaker-Metadata-Stream-Required` | 否 | `true` / `false` | 仅当 `X-Amzn-SageMaker-Metadata-Stream-Supported` 为 `true` 时生效。为 true 时，元数据连接失败即停止推理；为 false 或缺失时，推理以 data-only 模式继续。默认 false。当计量连续性优先于推理可用性时选 true。此设置不保证畸形或被丢弃的记录会被计费。 |
| 3 | `X-Amzn-SageMaker-Metadata-Invocation-Path` | 否 | 自定义路径字符串 | 覆盖默认的 metadata WebSocket 路径。默认 `/invocations-bidirectional-stream-metadata`。 |

### 第 2 步：接受元数据 WebSocket 连接

模型服务器返回 `X-Amzn-SageMaker-Metadata-Stream-Supported: true` 之后，SageMaker AI 会在默认路径 `/invocations-bidirectional-stream-metadata`（或你用 `X-Amzn-SageMaker-Metadata-Invocation-Path` 指定的自定义路径）向模型服务器打开第二条 WebSocket 连接。

SageMaker AI 在数据与元数据两次 WebSocket 握手里都带上 `X-Amzn-SageMaker-Request-Id` 头。你的模型服务器必须做到：

- 在 metadata 路径上接受 WebSocket upgrade。
- 用 `X-Amzn-SageMaker-Request-Id` 把元数据连接与同一推理会话对应的数据连接关联起来。

### 第 3 步：发送计量消息

在元数据连接上，把计量数据作为一个 JSON 对象放进 WebSocket text frame 发送。每个 frame 必须恰好含一条计量记录。本例里产品按音频秒数收费，该记录把 12 分钟计费音频报为 720 个单位：

```
{
  "Metering": {
    "Dimension": "inference.count",
    "ConsumedUnits": 720,
    "ClientToken": "a3f2b1c0-unique-uuid"
  }
}
```

**消息字段：**

|  | **字段** | **是否必需** | **类型** | **约束** | **说明** |
| --- | --- | --- | --- | --- | --- |
| 1 | `Metering` | 是 | Object | — | 计量记录的容器。 |
| 2 | `Metering.Dimension` | 是 | String | 必须是 `inference.count` | 计费 dimension，必须是 `inference.count`。 |
| 3 | `Metering.ConsumedUnits` | 是 | Number | 0 或以上 | 自上一条记录以来消费掉的单位。每条记录单独计费。0 会被接受但不计费。 |
| 4 | `Metering.ClientToken` | 否 | String | 最多 64 字符 | 用于幂等的唯一 token（例如一个 UUID）。同一连接上重复发送同一 `ClientToken`，只记录第一次。 |

随用量累积增量发送计量记录，以减少会话意外结束时未上报的用量。把上报数量与 AWS Marketplace 报告及买方扣费对账来核验计费，其中要包含会话中断的测试。

### 约束与限额

|  | **限额** | **取值** | **备注** |
| --- | --- | --- | --- |
| 1 | 最大消息大小 | 512 字节 | JSON text frame 的总大小 |
| 2 | 最大发送速率 | 每连接每秒 1 条消息 | 超出可能导致消息被丢弃 |
| 3 | Dimension 最大长度 | 128 字符 | — |
| 4 | ClientToken 最大长度 | 64 字符 | — |
| 5 | 每 frame 消息数 | 恰好 1 | 不要在单个 frame 里批量塞多条计量记录 |
| 6 | frame 类型 | 仅 text frame | 计量不支持 binary frame |

### 错误处理与失效模式

Required 头控制元数据连接不可用时会发生什么。设为 `true` 可停止推理，用默认 `false` 则让推理以 data-only 模式继续。这是在计量连续性与推理可用性之间做选择。无论哪种设置，畸形消息都可能被丢弃。

|  | **场景** | **Required = true** | **Required = false（默认）** |
| --- | --- | --- | --- |
| 1 | 元数据 WebSocket 连接失败 | 数据流被终止 | 数据流正常继续（data-only 模式） |
| 2 | 元数据 WebSocket 会话中途掉线 | 数据流被终止 | 数据流正常继续，计量停止 |
| 3 | 计量消息畸形 | 消息被丢弃，元数据连接保持打开 | 消息被丢弃，元数据连接保持打开 |
| 4 | 数据连接中途断开 | 元数据流被关闭 | 元数据流被关闭 |

### 把模型上架到 AWS Marketplace

- 把你的 AWS 账户注册为 AWS Marketplace 卖家。付费产品需补齐税务与银行信息。
- 在受支持的发布 Region 里，用你的容器创建 SageMaker AI model package，并建一个 AWS Marketplace 可代入以读取它的 AWS Identity and Access Management（IAM）role。
- 在 AWS Partner Central 里依次选 **Build**、**Machine learning**、**Create machine learning product**，把 model package 加为第一个版本。
- 选 per-inference 定价。对实时推理，你为所有实例类型设一个每单位价格，按 per request 显示、最多三位小数；另为每种 batch transform 实例类型设一个每小时价格。定价模型要在创建 listing 时选定，因为已发布的 listing 不能在 hourly 与 per-inference 定价之间切换。
- 校验通过后，申请 Public 可见性。对企业买方，可用 private offers 附上议定的按单位费率或固定价合同。

### 发布前验证计费

用 [Limited listing](https://docs.aws.amazon.com/marketplace/latest/userguide/ml-product-lifecycle.html) 和一个加白名单的测试买方验证集成。用恰当的 offer（需要时含 private offer），让测试真正走一遍预期的单位与价格映射。

- 跑一次已知数量测试。对按音频秒数计价的产品，送入 12 分钟计费音频，检查上报记录合计 720 个单位。
- 把模型服务器记录与卖家用量报告、买方扣费对账。给报告留出填充时间，并核对 usage type `<region code>-SMMP:inference.count.m.i.c`（例如 `us-east-1` 里的 `USE1-SMMP:inference.count.m.i.c`）。确认 offer 的单位与价格映射，别假定上报延迟是固定的。
- 测试正常结束、会话中断、元数据流丢失和畸形消息。发布前，就每种情形的上报量与计费量，与 SageMaker AI 和 AWS Marketplace 团队逐一比对。
- 测试完成后删除测试 endpoint，避免持续产生基础设施费用。

## 在 AWS Marketplace 上开始用 Deepgram

要在 SageMaker AI 上部署带按用量计量的 Deepgram，按下面几步来。

- 在 AWS Marketplace 订阅你需要的 Deepgram Voice AI 流式模型，例如 [Deepgram Nova-3 Monolingual Speech-to-Text (STT) Streaming](https://aws.amazon.com/marketplace/pp/prodview-rwbcd44ekb2r6)。
- 用 AWS Marketplace 订阅里的 Deepgram model package 部署一个 SageMaker AI real-time endpoint。
- 用 SageMaker AI bidirectional streaming API 连到 endpoint，通过其 HTTP/2 event stream 送入音频。

Deepgram 的模型服务器会自动计算计量，Amazon SageMaker AI 与 AWS Marketplace 负责处理。客户端不需要配置任何东西。

## 清理

测试结束后，删除 SageMaker AI real-time endpoint 和模型资源，停止基础设施费用。若不再需要该产品，移除 AWS Marketplace 订阅。

## 结语

有了双向流式的按用量计量，模型供应商能让 AWS Marketplace 软件定价与实时会话期间上报的用量对齐。客户为产品与 offer 所定义的计费单位支付软件费。Amazon SageMaker AI 的 endpoint 基础设施费用仍然独立、且照旧适用。了解更多，见 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker-ai/)。

开始使用：

- 客户：在 AWS Marketplace 订阅一个 Deepgram Voice AI 流式模型，例如 [Deepgram Nova-3 Monolingual Speech-to-Text (STT) Streaming](https://aws.amazon.com/marketplace/pp/prodview-rwbcd44ekb2r6)
- 模型供应商：按本文的集成实操，给你自己的模型服务器加上按用量计量。
