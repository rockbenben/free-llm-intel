# 用 Amazon Bedrock AgentCore、Managed Knowledge Base 和 Nova Sonic 构建语音旅行礼宾

航空公司早已有了自己的 App 和网站，旅客在上面查航班、选座位、管理订单，而增加一层自然的语音能力，就能把这些任务变成口头请求。有了这层语音能力，旅客开口说一句话就能换座位或查询延误，不用离开 App，也不用在一屏屏界面里翻找。构建它需要在多个方面做精细的工程。你要双向流式传输音频，并在多轮对话中保持对话脉络的连贯。你还要触达既有的后端系统，又不让 agent 与它们紧耦合；而且要在假期周末前流量激增时弹性扩容。

本篇将展示如何为航空公司应用添加一个语音旅行礼宾，它构建在三项托管服务之上。[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 是一个 agentic 平台，让你能以自选的框架和模型，安全、大规模地构建、部署和运营 AI agent。Bedrock 上的 [Amazon Nova Sonic](https://aws.amazon.com/nova/models/) 是面向实时语音的 speech-to-speech 模型。[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 是一项全托管的检索增强生成服务，让回答以你自己的文档为据。旅客开口说话，礼宾就会调出其行程、更换座位、更新餐食偏好、回答政策问题，并在旅客要求时转接真人客服。

礼宾与既有界面并行运行而非取代它们，旅客可以在同一次会话里在点按与说话之间自由切换。它运行在按需扩缩的服务之上，让你把精力花在体验上而不是基础设施上。这个 AI 层对接的是一个使用合成数据的示例航空后端，当你把这套模式适配到自己的系统时，它能加速你的落地实现。项目按模块拆分，你可以复用与自己后端契合的部分，并把它们作为工具（tools）暴露给 agent。

你将学会如何做以下事情：

- 使用 [AWS Cloud Development Kit (AWS CDK)](https://aws.amazon.com/cdk/) 在 AWS 上部署一个语音 AI 礼宾。
- 用 [Strands Agents](https://strandsagents.com/) 框架和 [Amazon Nova 2.5 Sonic](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-nova-2.5-sonic/) 构建一个具备实时语音能力的 agent，托管在 AgentCore runtime 上——Amazon Bedrock AgentCore 框架的一项能力。
- 通过 AgentCore Gateway（Amazon Bedrock AgentCore 的一项能力），用 [Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro) 将 agent 连接到后端服务。
- 用 Amazon Bedrock Knowledge Bases 回答航空政策问题。
- 把旅客转接给真人客服，并附上一个参考编号和预计等待时长。

## 方案总览

这套架构把前端、AI agent 和后端服务分离为彼此独立的层，让每一层都能独立开发和扩展。MCP 是一个把 AI 应用连接到外部工具与数据的开放标准。它在 agent 与后端之间传递标准化消息，使两者保持松耦合。

该方案部署了以下服务。

- [Amazon Cognito](https://aws.amazon.com/cognito/) 负责用户认证，并为签名 API 访问签发临时 AWS 凭证。
- [Amazon Bedrock AgentCore runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 托管该 agent，每个会话都有 microVM 隔离。
- [Amazon Bedrock AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 把后端 endpoint 暴露为可发现的 MCP 工具。
- [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 以后端形式发布 [REST](https://aws.amazon.com/what-is/restful-api/) endpoint，并采用 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 授权。
- [AWS Lambda](https://aws.amazon.com/lambda/) 运行行程、座位图、旅客信息更新、航班状态、常旅客、政策查询与升级转接的业务逻辑。
- [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 存储客户档案、订票、旅客、座位图、购买历史、偏好、对话记录与航班数据。
- [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 以你的航司政策文档为依据回答问题，处理政策类提问。
- [Amazon Simple Email Service (Amazon SES)](https://aws.amazon.com/ses/) 发送邮件通知。
- [AWS Amplify](https://aws.amazon.com/amplify/) 托管 React 前端。

## 架构

下图展示了方案的架构，分为四个部分。

图 1：横跨后端、AgentCore Gateway、AgentCore runtime 与前端的端到端架构

**A 部分覆盖后端基础设施。** 五个 CDK stack 部署 DynamoDB 表、Lambda 函数、API Gateway endpoint、Amazon Bedrock Knowledge Bases 和 Amazon Cognito。

**B 部分覆盖 AgentCore Gateway。** 一个 CDK stack 创建采用 MCP 协议的 Amazon Bedrock AgentCore Gateway，把每个后端 endpoint 暴露为 agent 可按名称调用的工具。

**C 部分覆盖 AgentCore runtime。** 两个 CDK stack 开通 runtime 基础设施。Amazon Elastic Container Registry (Amazon ECR) 存放容器镜像，Amazon Simple Storage Service (Amazon S3) 保存源码上传，AWS CodeBuild 构建 ARM64 Docker 镜像。Amazon Bedrock AgentCore runtime 带 WebSocket 支持运行，使用 Strands Agents 框架搭配 Amazon Nova 2.5 Sonic。

**D 部分覆盖前端。** 一个 CDK stack 把 React 应用部署到 AWS Amplify。

## 用户请求流程

- 用户在浏览器或移动设备上打开托管于 AWS Amplify 的 Web 应用。
- 用户在登录页输入凭证。Amazon Cognito 对该请求进行认证，返回 JSON Web Tokens (JWTs) 和临时 AWS 凭证。
- 前端向 Amazon Bedrock AgentCore 发起一条 SigV4 签名的 WebSocket 连接，开启语音礼宾会话。
- runtime 用 Amazon Cognito 校验 token，并通过 Amazon Bedrock 初始化 Amazon Nova 2.5 Sonic。
- 用户说出请求。Amazon Nova 2.5 Sonic 处理音频并触发 tool calls。agent 通过 MCP 调用 AgentCore Gateway 来取航班数据、管理订票、更新旅客偏好，完成工具集成。
- AgentCore Gateway 把请求转发为 REST API 调用发给 Amazon API Gateway，后者将其路由到 AWS Lambda 函数。
- AWS Lambda 函数查询 Amazon DynamoDB 表中的订票、旅客、座位图、常旅客状态与航班信息。邮件通知经由 Amazon SES 发送。
- Amazon Nova 2.5 Sonic 生成结合上下文的语音回答，经 AgentCore runtime 沿 WebSocket 连接流式返回给用户。
- 遇到政策类问题，AgentCore Gateway 通过 MCP Knowledge Base 连接器直接查询 Amazon Bedrock Knowledge Bases。知识库把相关政策段落作为引用（citations）返回给 agent。
- 当用户要求真人客服时，AWS Lambda 把这次升级转接记录到 Amazon DynamoDB 并返回一个参考编号。随后 AWS Amplify 从用户设备发起呼叫，把用户接通到真人客服。

## 构建与运营

下面两个步骤处在实时会话之外，描述该方案如何构建、如何日常运行。

- AWS CDK 用单个脚本部署整个方案。构建过程把 agent 源码上传到 Amazon S3，并触发 AWS CodeBuild 生成容器镜像，镜像存入 Amazon ECR 供 AgentCore runtime 使用。

## 示例航空数据模型

API Gateway 发布一个带 IAM 授权 endpoint 和 Lambda 集成的 REST API。Amazon DynamoDB 存储示例航空数据模型，提供个位数毫秒级延迟与按需扩缩。数据涵盖客户档案、订票、旅客、座位图、购买历史、偏好、对话记录与航班状态。

## 用知识库回答政策问题

旅客会问行李限额、改签费、宠物托运和常旅客条款。该方案通过 Amazon Bedrock Knowledge Bases 使用 [Retrieval Augmented Generation (RAG)](https://aws.amazon.com/what-is/retrieval-augmented-generation/) 回答这些问题，让回答以你的航司政策文档为依据。仓库自带示例政策文档，覆盖行李、取消与退款、改签与重新预订、舱位规则、常旅客条款、宠物托运、特殊协助与升舱。

你把文档上传到 Amazon S3，然后[一次性创建知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-managed-create.html)。此后 Amazon Bedrock 处理其余一切，包括 embedding、分块、索引、存储与检索。存储运行在 Amazon S3 Vectors（Amazon S3 的一项能力）之上。Smart Parsing 对源 PDF 做预处理，让表格和结构化版式能被准确检索。当政策文档更新时，你同步一下知识库，新内容立即可用，无需重新部署任何管道。

通过 AgentCore Gateway 把知识库连到 agent 非常直接。你把知识库添加为 Connectors target，选择标准检索或 agentic 检索，Gateway 就把它与你的后端 API 工具并列，暴露为一个具名 MCP 工具。agent 随后在运行时发现它并按名称调用，无需编写自定义 Lambda 或检索代码。设置步骤参见 [Add a knowledge base as a gateway target](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-gateway-target.html)。

要使用你自己的政策，把你的 PDF 或文本文件放进政策文档文件夹，然后重新部署知识库 stack。

## 用 Amazon Bedrock AgentCore 做语音 AI 处理

每个会话都在 AgentCore runtime 上以托管容器运行，具备 microVM 隔离，即使高负载下也能让各旅客的对话彼此隔离。AgentCore 提供自动扩缩、内建监控和会话路由。

生产部署建议加上 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/)，过滤 prompt injection 尝试并校验回答的 grounded 程度。本方案中的 confirm-before-write 模式会在做出变更前请旅客确认。这一模式，加上可把回答追溯到源文档的知识库引用，已经提供了负责任 AI 实践的基线。

agent 使用 [Strands BidiAgents](https://strandsagents.com/docs/user-guide/concepts/bidirectional-streaming/agent/) 框架定义 system prompt、工具与对话流程。Amazon Nova 2.5 Sonic 为礼宾带来以下能力。

- 覆盖各种口音的语音识别，以及对背景噪声的鲁棒性。
- 能适配旅客语气的语音回答。
- 低延迟的双向流式传输。
- 异步 tool calling：并行取数据或发起 tool calls 而不中断对话。
- 延迟掩盖（latency masking）：在等待工具结果时先生成过渡性的口头回应，让对话保持自然。
- 打断（barge-in）与自然的轮换说话。
- 跨多轮延续的上下文。

音频以前端经 WebSocket 到 AgentCore runtime 的 16 kHz PCM 形式流式传输。Amazon Nova 2.5 Sonic 转写语音，agent 挑选合适的工具并通过 MCP 调用。AgentCore Gateway 把每次 MCP 调用翻译为 REST 请求，Lambda 执行逻辑并返回结果，Amazon Nova 2.5 Sonic 再把这些结果融进一句口头回复。

## Amazon Nova 2.5 Sonic 的新特性

本方案使用 [Amazon Nova 2.5 Sonic](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-nova-2.5-sonic/)，一个具备强推理能力、面向实时语音的 speech-to-speech 模型。对于一个要调用后端工具、遵循详细 system prompt 的语音礼宾来说，这种推理能力体现在几个务实的方面：

**更好的 tool calling 与 agentic 任务完成** —— agent 能在多步请求中可靠地选对并串联工具，例如在一次对话中先查出行程、再更换座位。

**强的指令遵循与推理** —— 模型严格贴合 system prompt，包括像逐字符朗读确认码和航班号这样的格式化规则。

**准确的负责任 AI 处理** —— 模型对旅客的真实请求给予有益回应，同时安全地处理不当请求。

## 用户认证

该方案使用 Amazon Cognito User Pools 和 Identity Pools 实现基于角色的访问。旅客用用户名和密码登录，获得 JWTs：一个 access token 和一个 ID token。前端拿 ID token 到 Cognito Identity Pool 换取临时 AWS 凭证，由 access key、secret key 和 session token 组成。这些凭证用 Signature Version 4 (SigV4) 对到 AgentCore runtime 的 WebSocket 连接及对 API Gateway 的请求进行签名。只有完成认证的旅客才能访问应用和服务 API。

## 认证与 WebSocket 连接流程

前端使用临时 AWS 凭证向 AgentCore runtime 发起一条 SigV4 签名的 WebSocket 连接，并发送 access token 用于身份核验。随后浏览器流式传输 16 kHz PCM 音频，并在同一条连接上接收语音回答与工具通知。中间没有服务端代理。

## 语音交互与动态 tool calling

旅客提出想查看自己的座位。Nova 2.5 Sonic 转写请求，agent 选定所需工具。它通过 MCP 经 AgentCore Gateway 并行调用这些工具，Gateway 把每次调用翻译为对 API Gateway 的 REST 请求。Lambda 函数查询 DynamoDB 并返回结果，Nova 2.5 Sonic 把一切融合成一段口头回答流式播出。由于 tool calls 是[异步](https://docs.aws.amazon.com/nova/latest/nova2-userguide/sonic-async-tools.html)运行的，对话不会在加载数据时卡住。

## 升级转接真人客服

当礼宾无法满足请求、或旅客主动要求时，礼宾会把旅客转交给真人。旅客确认后，agent 调用 EscalateToAgent 工具。Lambda 把这次转接记录到 DynamoDB，返回一个参考编号和预计等待时长。agent 告知该参考编号，Amplify 前端随后拨打支持热线。这个示例不包含呼叫中心应用，因此接通真人取决于你配置的支持号码。

## 结论

本篇展示了如何在 AWS 上构建语音旅行礼宾。它用 Amazon Cognito 做认证，Amazon Bedrock AgentCore 做 agent 托管，API Gateway 和 Lambda 承载业务逻辑，DynamoDB 做存储，Amazon Bedrock Knowledge Bases 回答政策问题。分层设计把前端、agent 和后端分离，各自独立开发和扩展。礼宾通过 MCP 工具管理行程、换座、餐食偏好、航班状态、常旅客问题、政策查询和真人客服升级转接。Amazon Nova 2.5 Sonic 带来低延迟语音、并行 tool calling 和自然的打断处理。按量计费与自动扩缩让成本与流量同步，而借助 MCP 集成，你可以新增一个 Lambda 函数而完全不碰 agent 代码。要开始使用，请访问 [GitHub 上的方案仓库](https://github.com/aws-samples/sample-travel-concierge-with-amazon-bedrock-agentcore-and-nova-sonic)，并按你自己的航空系统做适配。
