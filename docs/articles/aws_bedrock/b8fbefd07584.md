# Popsa 如何用 Amazon Nova 为客户带来个性化标题灵感

*本文与 Popsa 的 Bradley Grantham 和 Hugo Dugdale 共同撰写。*

[Popsa](https://popsa.com/) 是一家技术公司，帮助用户重新发现并重温藏在照片库中的珍贵回忆。我们的服务覆盖 50 多个国家和 12 种语言，用设计自动化和 AI 把日常照片转化为个人化、可分享的体验，其中包括精美印刷的照片书（Photo Books）。

2016 年，我们发布了 *PrintAI*，这是一个开创性的算法，可以完全掌控从用户照片中生成丰富而有趣的设计。我们的客户可以用这个算法在不到 5 分钟内制作出看起来像专业设计的照片书。

我们业务的一个核心理念是*技术应当为用户承担繁重的工作*，因此自动化一直是我们产品的内在组成部分。在当今的*生成式 AI* 时代，我们可以开发更多方式来提升客户体验，而不必让软件变得更难用。

在本文中，我们分享如何应用 Amazon Bedrock 和 Amazon Nova 系列模型，重新构想我们的标题建议（Title Suggestion）功能。通过结合元数据、计算机视觉和检索增强生成式 AI，我们现在可以自动生成富有创意、契合品牌的标题和副标题，覆盖 12 种语言。借助 Amazon Bedrock 的统一 API、Anthropic 的 Claude 3 Haiku，以及 Amazon Nova Lite 和 Pro，我们提升了质量、降低了成本，并缩短了响应时间。这带来了更高的客户满意度、可测量的参与度和购买率提升，以及 2025 年生成的超过 550 万个个性化标题。

## 用 Amazon Bedrock 生成标题建议

当客户收到自己的照片书时，第一眼看到的是封面，上面有醒目的标题和副标题。高质量的标题和副标题能提升照片书的设计感，但大多数客户并不是专业文案，很多人只能凑合用“France 2024”“Photos from Spain”甚至“Photos”这类简单标题。

为了帮助用户提升照片的呈现效果，我们开发并上线了一个名为 **Title Suggestion** 的功能，自 2021 年起向用户提供。

当用户为照片书设计挑选照片时，我们的移动应用会读取图像中的元数据——比如时间戳和地理坐标——并在设备端运行卷积神经网络来提取相关特征，例如图像中是否有海滩、烧烤还是宠物。

为了使用这些数据，我们创建了一个名为 *Title Suggestion Graph* 的算法。该算法利用所选照片的元数据与数据构建候选标题列表，按照一套规则和模板推导出一组合适的建议。例如：

**如果**设计中的所有照片都是在同一天拍摄的

**那么**建议以“On this Day”作为标题，并用具体日期作为副标题

2024 年 6 月，我们发现了用生成式 AI 改进 Title Suggestion 的机会，目标是给用户带来更有创意的标题灵感。我们从清晰定义问题、建立评估指标开始。我们的解决方案必须满足严格的要求：

- **字符限制**  标题和副标题都不得超过 36 个字符，因为版式限制会影响文字在封面上的呈现方式。
- **标题类别**  每个标题–副标题对还必须带有一个关联类别，它决定向用户展示的配套图标。类别想象错误或不正确都会导致图标无法渲染。
- **JSON 格式**  最后，所有输出都必须是合法 JSON，并带有 `title`、`subtitle` 和 `category` 键。这有助于在应用中稳定地解析、校验和渲染。

这些规则有助于评估，因为它们可以用代码定义，所以我们构建了一个包含 100 多个示例照片书的数据集，并在评估 pipeline 中定义了指标：

- **在字符限制内的标题/副标题建议占比**
- **有效标题类别的占比**
- **以正确 JSON 格式返回的响应占比**

除了这些硬性规则，我们还需要解决方案满足一些更宽泛的准则：

- **主题一致性**  类别应与内容相符（例如，如果设计主题是海滩度假，*滑雪*图标就不合适）
- **品牌风格**  建议应体现 Popsa 的语气与品牌识别
- **标题与副标题的衔接**  两者应相互补足；不应重复或割裂。
- **多语言质量**  建议在我们支持的 12 种语言中都必须是高质量的。

我们决定用 *LLM-as-a-judge* 针对这些准则评估效果。这帮助我们快速测试不同的模型、prompt 和方法，找出最可靠的方案。在缩小到两三个选项之后，我们做了大量内部测试。

我们最好的结果来自*基于检索的少样本 prompt* 做法。我们建立了一个示例照片书与可接受标题建议的数据库。对于新的照片书，我们会检索几个相似的照片书设计，并随机选取其中一些建议标题。

使用 **Amazon Bedrock** 和 [**Anthropic 的 Claude 3 Haiku**](https://www.anthropic.com/news/claude-3-haiku)，我们先用这些示例作为 *<user> – <assistant>* 消息为对话打底，再把用户的新设计文档作为最后一条 *<user>* 消息追加进去。这让大语言模型（LLM）能够模仿此前的回答，同时自然地遵循我们定义的规则。

该解决方案的完整架构如下图所示：

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/07/ts_diagram-1.png)

当我们的 Title Suggestion 服务收到请求时，它首先解密并处理用户的设计以提取时间戳。然后，对设计中包含的纬度和经度做逆向地理编码，接着根据物体地标对设计主题进行分类。

这会生成类似“*一本滑雪主题照片书，含 21 张照片，拍摄于 2025 年 1 月 21 日至 2025 年 1 月 23 日的阿尔卑斯山*”这样的描述。随后我们把这段描述传给*基于检索的少样本 prompt* 组件，生成最终面向用户的建议集合。

与我们先前的基于图的方法相比，结果更好：

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/01/ml-19401-2.png)

为了量化改进，我们依靠一个反馈回路，客户可以把建议评为正面、中性或负面。我们还对数十万用户进行了多变量测试。反馈明显偏向生成式 AI 生成的标题，**Design Created** 和 **Purchase** 等关键指标也有所提升。几个月后，我们把该功能向 100% 的用户推出。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/01/ml-19401-3.png)

通过把标题建议从图算法切换到 Claude 3 Haiku，我们把正面的用户反馈提升了 13%（从 58% 到 71%）。

## 用 Amazon Nova 提升客户满意度并降低成本

自 2024 年基于生成式 AI 重新上线 Title Suggestions 以来，LLM 技术在性能、成本和速度上都有显著提升。Amazon Bedrock 的统一 API 让我们只需更换模型 ID 就能比较和测试新模型，把实验周期从数周缩短到数小时。我们最近测试了支持 200 多种语言且低延迟的 **Amazon Nova** 系列（Micro、Lite 和 Pro）。

2025 年初，我们开展了一次多变量 A/B 测试，比较 Claude 3 Haiku 与 Nova 模型，跟踪护栏指标，并通过应用内反馈功能收集用户的直接偏好。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/01/ml-19401-4.png)

对多种标题生成模型的测试显示，虽然 Claude 3 Haiku（71% 正面）表现良好，但 Nova Pro 取得了最高的用户满意度，正面反馈为 73%，负面反馈最低，为 12%。

Nova Micro 虽然优于我们原有的 *Graph* 方法，但在用户满意度上落后于其他 LLM，因此被搁置一旁。在其余模型中，我们不仅关注质量，也关注成本、延迟和吞吐，如下表所示。这些对比清楚地表明，Nova Lite 以更低的成本和更快的响应时间提供了与 Claude Haiku 几乎相同的质量。

| **模型** | **每 1,000 输入 token 价格** | **每 1,000 输出 token 价格** | **响应时间（输出 500 token 所需秒数）** |
| --- | --- | --- | --- |
| Claude 3 Haiku | $0.00025 | $0.00125 | 6.8 |
| Amazon Nova Lite | **$0.000069** | **$0.000276** | **2.4** |
| Amazon Nova Pro | $0.00092 | $0.00368 | 3.4 |

*价格取自 [Amazon Bedrock 定价页面](https://aws.amazon.com/bedrock/pricing/)

*性能指标取自 [Artificial Analysis](https://artificialanalysis.ai/)

## 用 ConverseStream API 缩短首个建议的等待时间

我们跟踪的关键延迟指标之一是*首个建议时间*（Time to First Suggestion，TTFS），它衡量用户发出请求后，第一个有效建议多快出现。即使后台还在生成更多选项，降低 TTFS 也能让功能显得更灵敏，使用户在离开之前就看到建议。

为改善 TTFS，我们从 Amazon Bedrock 的 **InvokeModel API** 迁移到 **ConverseStream API**，在 token 生成的同时进行流式输出。因为我们的服务要求输出合法的标题-副标题-类别三元组，我们扩展了 FastAPI 以实时解析流，在首个建议通过校验时立即返回。其余建议继续在后台流式生成，而客户端已经有内容可以展示。

这一转变把第一条打磨完成的建议的 TTFS 大幅降到一秒以内，而不必等一整批建议全部生成。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/01/ml-19401-5.png)

通过迁移到 ConverseStream API，我们把首个建议的平均时间从 1.41 秒降到 0.92 秒，让标题建议送达用户的速度提升 35%。

## 下一步计划

2025 年，我们的 Title Suggestion 功能已生成**超过 550 万个标题**，让我们得以了解哪些内容能引起共鸣、哪些不能，以及人们如何与我们的建议互动。这个反馈回路将继续推动该功能的演进。

展望未来，我们计划为一部分用户群体使用 **Nova Pro** 这类更大的模型，以获取创造力与细腻度，同时仍能在大规模下保持成本效益。我们从这些实验中收集的数据将帮助我们**微调更小的模型**，让它们继承更大模型的优势，同时不牺牲延迟或可负担性。

未来的工作还包括**工具集成**，为 LLM 提供关于每本照片书的更丰富上下文，从事件细节到季节性线索，目标是生成更个性化、更具主题性、更契合品牌的标题。

这些进展延续着我们的使命：让任何人，无论技能水平如何，都能快速把照片变成有意义、有创意、值得珍藏的纪念。
