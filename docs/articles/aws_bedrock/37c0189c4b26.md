# 构建 AI 驱动的语音应用：Amazon Nova Sonic 电话系统集成指南

越来越多的组织希望通过在其电话系统中提供自然、响应及时的语音交互来改善客户体验。[Amazon Nova Sonic](https://aws.amazon.com/ai/generative-ai/nova/speech/) 正是为满足这一需求而生：它是一种语音到语音（speech-to-speech）生成式 AI 模型，能够以低延迟和自然的轮流对话方式实现实时语音交流。它能理解不同口音和说话风格的语音，用多种语言以富有表现力的声音作答，并能从容处理中断。Nova Sonic 通过 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 双向流式 API 提供，可连接你的业务数据和外部工具，并能直接与电话系统集成。

语音这一模态让 Amazon Nova Sonic 天然适合那些必须保留对话细微差别、并把延迟降到最低的电话应用。Nova Sonic 非常适用于需要类人交互的自动化呼叫中心、主动电话外呼活动，以及 AI 前台等场景。

要将 Amazon Nova Sonic 集成到你的电话架构中，你需要一台应用服务器来连接并维持与 Nova Sonic 的持久双向流式连接。本文将为最常见的电话场景介绍示例实现：与传统电话基础设施的直接会话发起协议（SIP）集成，与 [Vonage](https://www.vonage.com/?bypassgeoloc=true)、[Twilio](https://www.twilio.com/en-us) 和 [Genesys](https://www.genesys.com/) 等电话服务商的直接集成，以及使用 [Pipecat](https://www.pipecat.ai/) 和 [LiveKit](https://livekit.io/) 等开源框架构建电话应用。这些方案覆盖了从传统 PBX 系统到现代云通信的整个范围，为你提供多条将 Nova Sonic 接入电话网络的路径。

## Amazon Nova Sonic 的常见电话应用场景

Nova Sonic 可用于以下常见的电话应用场景：

- **呼叫中心运营**：Amazon Nova Sonic 可以通过自然对话处理客户服务来电、技术支持咨询和常规交易，作为呼入电话的主要 agent。它还可以替代传统的 IVR 系统，让客户直接描述自己的需求，而不用在电话菜单里逐层选择。在高话务量时段，它可以处理溢出呼叫，并附上完整对话摘要把复杂问题升级给人工 agent。
- **前台与外呼职能**：Amazon Nova Sonic 可以连接 CRM 和日历等公司系统来处理日程安排、回答关于公司的问题，并根据对话内容转接来电。在外呼场景中，它可以进行带改约能力的预约提醒、用于收集反馈的跟进电话以及问卷调查活动。语音到语音的设计在保持自然对话流的同时还能访问实时数据，从而根据客户历史记录实现个性化互动。

## Amazon Nova Sonic 的 SIP 集成

将 Amazon Nova Sonic 与会话发起协议（SIP）基础设施集成，需要一台充当中间层的应用服务器。这台服务器同时管理 SIP 信令和实时传输协议（RTP）媒体流，并维持与 Nova Sonic 双向流式 API 的连接。服务器在现有电话基础设施与 Nova Sonic 之间架起桥梁，负责通话会话管理以及两个系统之间的音频路由。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/25/image-1-21.png)

示例实现有两种：一个是基于 Java 的 [SIP 网关](https://github.com/aws-samples/sample-s2s-voip-gateway)，使用 mjSIP 协议栈和 AWS SDK for Java；另一个是 [JavaScript SIP 服务器](https://github.com/aws-samples/sample-sonic-sip-server-js)，使用 Node.js 搭配 SIP.js 和 AWS SDK for JavaScript。两个示例展示的是同一套核心架构，只是实现语言不同。

核心组件包括用于呼叫控制信令的 SIP 协议栈、用于音频流处理的 RTP 处理器，以及维护与 Amazon Bedrock 持久连接的 Amazon Nova Sonic 客户端。当有呼入电话到达时，SIP 服务器通过 SIP 应答，建立 RTP 媒体会话，并创建对应的 Sonic 流式会话。音频双向流动：

- 来自呼叫方的 RTP 数据包被解码，转换为合适的音频格式，并流式传输给 Nova Sonic
- Nova Sonic 的音频响应被编码，并通过 RTP 传输回去

在部署方面，你可以在 Amazon Elastic Compute Cloud（Amazon EC2）实例上运行这些 SIP 服务器，并为 SIP 信令（端口 5060）和 RTP 媒体流（通常是 10000-20000 端口）配置好安全组；也可以使用 Amazon Elastic Container Service（Amazon ECS）以容器化方式部署，采用 host 网络模式来访问所需的 UDP 端口范围。两种方式都：

- 需要具备访问 Amazon Bedrock 的 IAM 权限以及适当的凭证管理。
- 在你把现有电话基础设施配置为将来电路由到网关的公网端点后，都支持与 PBX 系统、VoIP 服务商（如 Vonage）或传统电话网络无缝集成

## 与电话服务商的集成

Vonage、Twilio、Genesys 和 Amazon Connect 等云电话服务商提供托管语音服务，通过简单的 API 来处理传统电话基础设施的复杂性。与直接进行 SIP 集成不同，这些服务商把底层协议抽象掉，并提供全球电话号码开通、自动故障转移、通话分析以及合规能力等功能。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/25/image-3-13.png)

### Vonage

Vonage 是一个云通信平台，为企业提供语音、消息和视频 API。Amazon Nova Sonic 与 Vonage 的集成于 2025 年 7 月发布，通过 Vonage Voice API 提供了一条把电话通话接入对话式 AI 的直接路径。借助这一集成，企业无需管理复杂的电话基础设施，就能在各类电话渠道上部署实时语音 agent，因为通话路由、音频流传输和协议转换都由 Vonage 负责。集成的实现方式是配置 Vonage webhook，在来电或发起呼叫时触发。你的应用服务器接收这些 webhook 事件，建立 Nova Sonic 流式会话，并在 Vonage 通话与 Nova Sonic 之间创建双向音频桥接。Vonage 负责编解码转换和网络传输等电话侧的复杂性，而你的服务器负责 AI 对话流程并连接你的业务系统和数据源。

有关详细的实现指导，请参阅[使用 Vonage 与 Amazon Nova Sonic 部署对话式 agent](https://aws.amazon.com/blogs/machine-learning/deploy-conversational-agents-with-vonage-and-amazon-nova-sonic/)这篇博客文章，以及 aws-samples GitHub 仓库中的[示例实现](https://github.com/aws-samples/sample-sonic-contact-center-with-vonage/tree/main)。

### Twilio

Twilio 是一个基于云的客户互动平台，提供语音、短信、邮件和视频能力。它为开发者提供 API 和 SDK，用于构建定制的通信解决方案、实现消息自动化以及实时通知。该平台是企业高效创建和管理客户沟通的基础。Twilio 与 AWS 集成，把通信领域的专业能力与云基础设施和 AI 能力结合起来。集成通过基于 webhook 的事件处理以及基于 WebSocket 连接的实时媒体流实现。当来电或发起呼叫时，Twilio webhook 会触发事件，由客户的应用服务器接收。服务器随后建立 Amazon Nova Sonic 流式会话，并创建媒体流连接，在 Twilio 通话与应用服务器之间进行实时音频处理。Twilio 负责编解码转换和网络传输等通信侧的复杂性，而 Sonic 负责自然语言对话。这一集成使企业能够部署 AI 驱动的语音 agent、实施预测分析，并利用 Twilio 与 AWS 两侧的全面客户数据打造个性化的客户体验。

有关详细的实现指导，请参阅 aws-samples GitHub 仓库中的[示例实现](https://github.com/aws-samples/sample-amazon-nova-sonic-twilio-integration)。

### Genesys

Genesys 是一个基于云的客户体验编排平台，提供联络中心和客户互动解决方案，具备全渠道路由、劳动力优化和 AI 驱动的分析能力。Genesys 通过 Genesys Cloud 平台 API 以及 Genesys AppFoundry 上提供的 Amazon Bedrock 集成来对接 Amazon Nova Sonic，来电会触发路由决策，把对话转接给由 Sonic 驱动的虚拟 agent。你的应用服务器从 Genesys Cloud 接收通话事件，建立 Nova Sonic 流式会话，并在 Genesys 通话与 Nova Sonic 之间创建双向音频桥接。Genesys 负责呼叫路由、队列管理和 agent 编排等联络中心的复杂性，你的服务器负责 AI 对话流程并连接业务系统，同时可以无缝转接给真人 agent，并保持完整的对话上下文以及通过 Genesys 报表仪表盘获得完全可见性。

有关详细的实现指导，请参阅 Genesys AppFoundry 上的 [Amazon Nova Sonic Connector](https://appfoundry.genesys.com/filter/genesyscloud/listing/4575bf30-9975-49ef-8dc3-09b6235ae11f)。

## 与开源框架的集成

Pipecat 和 LiveKit 等开源框架为开发者提供强大、由社区支持的工具，与 Amazon Nova Sonic 集成后可以显著加快对话式 AI 应用的开发。这些框架提供预构建组件、标准化接口和抽象层，处理构建语音体验所涉及的许多技术复杂性。借助这些集成，团队可以专注于打造与众不同的对话体验，而不必重新发明基础性的基础设施组件。

### Pipecat

Pipecat 是一个开源 Python 框架，旨在简化在语音、文本等各种渠道上创建智能对话式 agent 的过程。它应对开发 AI 驱动通信系统的复杂性，为开发者提供统一的框架来设计和管理对话体验。Pipecat 支持灵活的 pipeline 架构，该架构表示把用户输入转换为智能响应的数据流和处理步骤。它还提供与先进语音到语音模型的无缝集成，以实现高质量的语音交互，包括与 Amazon Nova Sonic 的集成。Sonic-Pipecat 集成建立一条双向音频流式通道，处理基于语音的交互的各个方面。当有通话到达时，Pipecat 把音频直接流式传输给 Nova Sonic，由后者处理语音并实时生成语音响应。Pipecat 负责音频传输、缓冲和连接处理，Nova Sonic 负责语音智能。这些技术复杂性都在后台自动完成，让开发者可以专注于设计出色的对话，而不是管理基础设施。

有关详细指导，请参阅《使用 Pipecat 与 Amazon Bedrock 构建智能 AI 语音 agent》[第 1 部分](https://aws.amazon.com/blogs/machine-learning/building-intelligent-ai-voice-agents-with-pipecat-and-amazon-bedrock-part-1/)和[第 2 部分](https://aws.amazon.com/blogs/machine-learning/building-intelligent-ai-voice-agents-with-pipecat-and-amazon-bedrock-part-2/)这两篇博客文章。

### LiveKit

LiveKit 是一个用于构建实时音频和视频应用的开源平台，为开发者提供 WebRTC 基础设施和 API，用于创建具备可扩展、低延迟媒体流能力的交互式通信体验。借助 Amazon Nova Sonic 与 LiveKit 的集成，开发者可以构建复杂的对话式 AI 应用：LiveKit 负责实时音频流传输和参与者连接，Sonic 负责 AI 驱动的对话处理。这一组合支持无缝的语音交互：LiveKit 把音频流式传输给 Nova Sonic 处理，接收 AI 生成的响应，并以最小的延迟把它们回传给参与者。该集成支持多方对话，并且可以扩展以处理并发语音会话，因此适用于带 AI 助手的虚拟会议以及呼叫中心等场景。

有关详细的实现指导，请参阅[使用 Amazon Nova Sonic 与 LiveKit 构建实时对话式 AI 体验](https://aws.amazon.com/blogs/machine-learning/build-real-time-conversational-ai-experiences-using-amazon-nova-sonic-and-livekit/)这篇博客文章。

## 清理资源

在完成 Amazon Nova Sonic 电话解决方案的实施后，为避免持续产生费用，请记得删除你创建的所有资源：

- 终止任何用于托管 SIP 服务器或应用服务器的 EC2 实例
- 如果你以容器化方式部署了应用，删除相应的 ECS 任务和服务
- 移除专为这一集成创建的 IAM 权限
- 删除电话服务商（Vonage、Twilio、Genesys）上的测试电话号码和配置
- 清理从 aws-samples GitHub 仓库部署的任何示例应用

具体需要清理哪些资源取决于你选择的集成方式。请始终通过 AWS Billing Dashboard 核实你已成功移除所有会产生费用的资源。

## 结语

Amazon Nova Sonic 的语音到语音能力为在各种电话架构上构建自然、响应及时的语音应用开辟了新的可能。无论你使用的是传统 SIP 基础设施、现代云电话服务商，还是开源框架，本指南介绍的集成路径都提供了灵活的选择，以匹配你的技术要求和组织约束。直接 SIP 集成方式让你拥有最大控制权，并且能与现有 PBX 系统和传统电话网络无缝协作。Vonage、Twilio、Genesys 和 Amazon Connect 等云电话服务商提供托管服务，把基础设施的复杂性抽象掉，同时带来企业级可靠性和全球覆盖。Pipecat 和 LiveKit 等开源框架通过为对话式 AI 应用提供预构建组件和标准化接口来加快开发速度。每种集成方式各有所长：SIP 集成适合直接控制和传统兼容性，云服务商适合托管基础设施和快速部署，开源框架适合开发速度和社区支持。理解这些选项后，你就可以选出最符合自身用例、现有基础设施和团队能力的路径。要开始上手，请查看本指南各处链接的示例实现，试用适合你需求的集成方式，并利用 Amazon Nova Sonic 的低延迟、多语言能力打造真正具有对话感的语音体验。在构建过程中请记住，这些集成模式可以组合和定制，以满足你的特定需求。供你参考，以下是一些帮助你开始使用 Amazon Nova Sonic 的关键资源：
