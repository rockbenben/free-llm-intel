# 用 Claude Code 和 Amazon Bedrock 为受监管工作负载加速

*请注意，以下文章仅供参考。下文详述的方案未必适合所有组织或合规计划。重要的是，要根据你所在组织的合规要求以及你可能承担的任何适用监管义务，来评估这一潜在方案。*

Anthropic Claude Opus 5.5 和 Claude Sonnet 5.5 在 AWS GovCloud (US) 区域上线，为带有监管或合规要求（包括《国际武器贸易条例》(ITAR)）的工作负载引入了一条通往 AI 辅助开发的通道。Claude Sonnet 5 已获得 FedRAMP Class D（原 High）认证以及美国国防部 (DoD) 影响等级 4 和 5（IL4/IL5）授权，而 Claude Opus 5.5 和 Claude Sonnet 5.5 在 Amazon Bedrock 上已获得 FedRAMP Class D 认证（[查看当前模型认证状态](https://aws.amazon.com/compliance/services-in-scope/FedRAMP/amazon-bedrock-models/)）。

在本文中，我们探讨如何在 AWS GovCloud (US) 的 [Amazon Bedrock](https://aws.amazon.com/bedrock) 上使用这些模型，配合 [Claude Code](https://code.claude.com)——Anthropic 的智能体式（agentic）编程工具。借助这套方案，你可以运行能加快日常开发任务的 AI 辅助工作流，同时保持合规一致性。

## AWS GovCloud (US) 中的 Amazon Bedrock

[AWS GovCloud (US) 区域](https://aws.amazon.com/govcloud-us/)专门为具有更高[合规需求](https://docs.aws.amazon.com/govcloud-us/latest/UserGuide/govcloud-compliance.html)的美国客户而设计。你可以在保持合规控制的同时，把生成式 AI 工作负载部署到敏感环境中。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 以安全为核心的特性构建，包括：

[内置数据保护](https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html)，客户内容不会被存储、记录，也不会用于训练 AWS 模型或分享给第三方。

FedRAMP Class D（原 High）认证以及 DoD 云服务提供商 (CSP) SRG IL4/IL5 授权路径，支持政府机构的合规要求。当前模型级认证状态请参见 [Amazon Bedrock 模型合规页面](https://aws.amazon.com/compliance/services-in-scope/FedRAMP/amazon-bedrock-models/)。

与 AWS GovCloud (US) 中现有的安全控制和合规框架集成，在提供额外授权路径的同时，保持与其他 AWS 区域相同的高安全标准。

AWS GovCloud (US) 中的 Amazon Bedrock 支持两个端点（endpoint）接口：bedrock-runtime 和 bedrock-mantle，二者都由同一个底层 Mantle 推理引擎驱动，并采用零运维人员访问（Zero Operator Access, ZOA）架构。**bedrock-runtime** 端点使用 AWS SDK（InvokeModel 和 Converse API），并支持 Amazon Bedrock Guardrails、Amazon Bedrock 知识库 (Knowledge Bases)、Agents 以及调用日志。这使它成为大多数新应用的首选，尤其是那些需要审计轨迹的应用。**bedrock-mantle** 端点原生支持 Anthropic Messages API，并提供对目前仅在该接口上可用的能力的访问，例如[服务端工具、后台推理和 Projects](https://aws.amazon.com/blogs/machine-learning/exploring-the-zero-operator-access-design-of-mantle/)。Claude Opus 5.5、Claude Sonnet 5.5 和 Claude Sonnet 5 均可通过这两个端点访问，其中 bedrock-runtime 在两个 AWS GovCloud (US) 区域（US-West 和 US-East）都可用，而 bedrock-mantle 仅在 AWS GovCloud (US-West) 可用。

## Claude Code

[Claude Code](https://code.claude.com) 是 Anthropic 的智能体式编程工具，它能读取你的代码库、编辑文件、运行命令，并与你的开发工具集成。在 AWS GovCloud (US) 中由 Amazon Bedrock 上的 Claude Opus 5.5 和 Claude Sonnet 5.5 等模型驱动，它直接在你的终端、你首选的集成开发环境（[IDE](https://docs.anthropic.com/en/docs/claude-code/ide-integrations)）（如 VS Code 和 JetBrains）中运行，也能借助 [Claude Agent SDK](https://docs.anthropic.com/en/docs/claude-code/agent-sdk/overview) 在后台运行。Claude Code 理解你的整个代码库，能够跨多个文件和工具协同工作以完成任务。Claude Code 可以：

- 编写代码并修复横跨代码库多个文件的 bug。
- 回答关于你的代码架构与逻辑的问题。
- 执行并修复测试、lint 以及其他命令。
- 搜索 Git 历史、解决合并冲突，并创建 commit 和 pull request。
- 通过 [Model Context Protocol (MCP)](https://docs.anthropic.com/en/docs/claude-code/mcp) 连接外部工具和数据源，包括 [AWS 命令行界面 (AWS CLI)](https://aws.amazon.com/cli)、Terraform 和 Kubernetes。
- 派生[子智能体（sub-agents）](https://docs.anthropic.com/en/docs/claude-code/sub-agents)，让它们同时处理一个任务的不同部分。
- 使用 [CLAUDE.md](https://docs.anthropic.com/en/docs/claude-code/memory) 记忆文件、用于可重复工作流的 [skills](https://docs.anthropic.com/en/docs/claude-code/skills)，以及用于前/后动作自动化的 [hooks](https://docs.anthropic.com/en/docs/claude-code/hooks) 来定制行为。
- 自动化重复性任务，并通过 [GitHub Actions](https://docs.anthropic.com/en/docs/claude-code/github-actions) 或 [GitLab CI/CD](https://docs.anthropic.com/en/docs/claude-code/gitlab-ci-cd) 与持续集成和持续交付 (CI/CD) 集成。

要了解更多，请参阅 Anthropic 的文章：[Claude Code 教程](https://docs.anthropic.com/en/docs/claude-code/tutorials)和 [Claude Code：智能体式编程的最佳实践](https://www.anthropic.com/engineering/claude-code-best-practices)。

## 方案概览：在 AWS GovCloud (US) 中用 Amazon Bedrock 试用 Claude Code

本节提供分步说明，介绍如何设置和配置 Claude Code，使其在 AWS GovCloud (US) 中配合 Amazon Bedrock 工作，涵盖前置条件、安装命令、环境配置和验证步骤。

### 前置条件

开始之前，请确认你已具备以下条件：

- 一个可访问 Amazon Bedrock 的 [AWS GovCloud (US) 账户](https://signin.amazonaws-us-gov.com/)。
- 适用于 Amazon Bedrock 的恰当 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 角色与权限。至少，你的 IAM 策略应包含： 对于 bedrock-runtime：`bedrock:InvokeModel`、`bedrock:InvokeModelWithResponseStream`、`bedrock:ListInferenceProfiles` 和 `bedrock:GetInferenceProfile`。对于 bedrock-mantle（如果使用 Mantle 端点）：`bedrock-mantle:CreateInference`、`bedrock-mantle:GetProject`、`bedrock-mantle:ListProjects` 和 `bedrock-mantle:ListModels`。或者，附加 `AmazonBedrockMantleInferenceAccess` 托管策略。
- 在你的 AWS GovCloud (US) 账户中为 Claude Opus 5.5、Claude Sonnet 5.5 和 Claude Sonnet 5 启用 [Amazon Bedrock 模型访问](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access-modify.html)。
- 已配置好有效 AWS 会话凭证的 [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)，使用短期 API 密钥或 AWS SSO 登录。

### 在 AWS GovCloud (US) 中用 Amazon Bedrock 设置 Claude Code

用你的凭证配置好 AWS CLI 后，用以下方法之一安装 Claude Code：

**macOS、Linux、WSL：**

```
curl -fsSL https://claude.ai/install.sh | bash
```

**Windows PowerShell：**

```
irm https://claude.ai/install.ps1 | iex
```

**Windows CMD：**

```
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

**Homebrew（macOS/Linux）：**

```
brew install --cask claude-code
```

有关其他安装方法，请参阅 [Claude Code 安装文档](https://code.claude.com/docs/en/quickstart)。

#### 方案 A：交互式设置向导（推荐）

- 进入你的项目：  `cd your-code-project`
- 启动 Claude Code：  `claude`
- 走完登录向导：  `/login`

在登录提示处，选择 **3rd-party platform（第三方平台）**，然后选择 **Amazon Bedrock**。按照向导提示选择你的认证方式、区域（us-gov-west-1），并固定（pin）你的模型。向导会自动把配置保存到你的设置文件中。

如果你此前已配置过 Claude Code，运行 `/setup-bedrock` 重新打开向导，更新你的凭证、区域或模型固定设置。

#### 方案 B：手动配置环境变量

对于脚本化或企业级部署，设置以下环境变量：

```
export CLAUDE_CODE_USE_BEDROCK=1
export AWS_REGION='us-gov-west-1'
export ANTHROPIC_MODEL='us-gov.anthropic.claude-sonnet-5-5'
```

要改为使用 Claude Opus 5.5 作为主模型：

```
export ANTHROPIC_MODEL='us-gov.anthropic.claude-opus-5-5'
```

要固定特定的模型版本以保证团队部署的一致性：

```
export ANTHROPIC_DEFAULT_OPUS_MODEL='us-gov.anthropic.claude-opus-5-5'
export ANTHROPIC_DEFAULT_SONNET_MODEL='us-gov.anthropic.claude-sonnet-5-5'
```

然后进入你的项目并启动 Claude Code：

```
cd your-code-project
claude
```

#### 方案 C：使用 Bedrock Mantle 端点

Bedrock Mantle 原生支持 Anthropic Messages API，并在 AWS GovCloud (US-West) 可用。要让 Claude Code 通过 Mantle 路由：

```
export CLAUDE_CODE_USE_MANTLE=1
export AWS_REGION='us-gov-west-1'
```

当同一会话中既需要 bedrock-runtime 又需要 bedrock-mantle 时：

```
export CLAUDE_CODE_USE_BEDROCK=1
export CLAUDE_CODE_USE_MANTLE=1
```

注意：Guardrails 和调用日志仅可通过 bedrock-runtime 端点获得。对于需要这些合规特性的部署，请使用 bedrock-runtime 端点（方案 A 或 B）。

#### 验证你的配置

通过在终端中查看 **Welcome to Claude Code!** 消息，确认 Claude Code 正在运行。运行 `/status` 命令以确认你的模型和提供商（provider）。根据你的配置，提供商这一行应显示 Amazon Bedrock 或 Amazon Bedrock (Mantle)。

要了解更多关于为 Amazon Bedrock 配置 Claude Code 的信息，请参阅 [Amazon Bedrock 上的 Claude Code](https://code.claude.com/docs/en/amazon-bedrock)。

## 在组织中部署 Claude Code 时的考量

既然 Claude Code 现已正式发布（generally available），下一步就是决定如何在整个组织中部署它。请考虑你在安全、治理和合规方面的基础架构：

**使用** [AWS IAM Identity Center](https://aws.amazon.com/iam/identity-center/) **集中治理对 Claude Code 的身份和访问。** 这可验证只有获授权的开发者才能访问。此外，借助 IAM Identity Center，开发者可以用[临时的、基于角色的凭证](https://docs.aws.amazon.com/singlesignon/latest/userguide/howtogetcredentials.html)访问资源，从而免去对静态访问密钥的需求，有助于增强安全性。在打开 Claude Code 之前，请确保已使用 `aws configure sso --profile <PROFILE_NAME>` 把 AWS CLI 配置为使用一个 IAM Identity Center 配置文件（profile）。然后用你创建的配置文件登录：`aws sso login --profile <PROFILE_NAME>`。

**考虑对默认环境变量进行自动化配置。** 这包括本文中提到的环境变量，例如 `AWS_REGION`、`CLAUDE_CODE_USE_BEDROCK`、`ANTHROPIC_MODEL`、`ANTHROPIC_DEFAULT_OPUS_MODEL` 和 `ANTHROPIC_DEFAULT_SONNET_MODEL`。这会把 Claude Code 配置为自动连接到 Amazon Bedrock，为各团队提供一致的开发基线。组织可以先向开发者提供自助式说明，或使用[设置文件](https://docs.anthropic.com/en/docs/claude-code/settings)来集中管理配置。

**对于大型企业部署，考虑实施** [Guidance for Claude Code with Amazon Bedrock](https://aws.amazon.com/solutions/guidance/claude-code-with-amazon-bedrock/)。**该指南帮助组织在部署 Claude Code 的同时，对 AI 资源访问保持严格管控，连接现有身份基础设施，并为开发者生产力和使用模式提供可观测性。

**审阅** [服务配额](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas.html) **，并根据活跃开发者数量设置合适的每分钟 token 数 (TPM) 和每分钟请求数 (RPM)。** 确保你有足够的 TPM 和 RPM 配额来支撑团队的使用。相关指导请遵循[速率限制建议](https://docs.anthropic.com/en/docs/claude-code/costs)。

**固定模型版本以保证团队部署的一致性。** 若不加固定，`sonnet` 和 `opus` 这类别名会解析为 Claude Code 的内置默认值，而这些默认值可能在不同版本之间发生变化。Claude Code 默认使用 Claude Opus 5.5 作为其主模型，因此未固定的部署将按 Opus 的每 token 费率计费。要让团队保持在 Claude Sonnet 5.5 上，请把 `ANTHROPIC_MODEL` 设为其完整模型 ID。使用 `ANTHROPIC_DEFAULT_OPUS_MODEL` 和 `ANTHROPIC_DEFAULT_SONNET_MODEL` 来控制团队何时迁移到新模型。在 AWS GovCloud (US) 中，跨区域推理配置（cross-region inference profile）ID 请使用 `us-gov.` 前缀。

**实施成本监控和按用户的 token 护栏。** Claude Code 会话可能非常耗费 token，尤其是 Claude Opus 5.5，其每 token 成本高于 Claude Sonnet 5.5。据 Anthropic 称，Claude Opus 5.5 完成任务所用的 token 比 Claude Opus 5 更少，且每 token 价格更低。请考虑以下几点：

- 实施[按用户的 token 护栏](https://aws.amazon.com/blogs/publicsector/implementing-per-user-token-guardrails-for-amazon-bedrock-in-government-agencies/)，为每位开发者强制执行每日 token 上限，并在达到 80% 和 100% 阈值时告警。这一模式使用 Amazon CloudWatch 调用日志、AWS Lambda 和 Amazon DynamoDB，以近乎实时的方式跟踪并强制执行限额。
- 使用提示缓存（prompt caching）来降低成本并改善响应时间。受支持的模型同时提供 5 分钟和 [1 小时 TTL](https://aws.amazon.com/about-aws/whats-new/2026/01/amazon-bedrock-one-hour-duration-prompt-caching/) 两种选项。
- 考虑让团队默认使用 Claude Sonnet 5.5（成本低于 Claude Opus 5.5），并把 Claude Opus 5.5 保留给需要更深推理或更长自主运行的任务。对于需要 IL4/IL5 授权的工作负载，默认使用 Claude Sonnet 5。

有关更多可观测性模式，请参阅 [Claude Code 监控实施指南](https://github.com/aws-solutions-library-samples/guidance-for-claude-code-with-amazon-bedrock/blob/main/assets/docs/MONITORING.md)。

**为你的组织考虑权限、记忆和 MCP 服务器。** 安全团队可以为 Claude Code 允许和不允许做什么配置托管的[权限](https://docs.anthropic.com/en/docs/claude-code/security)，这些设置无法被本地配置覆盖。此外，你可以跨项目配置 [CLAUDE.md 记忆文件](https://docs.anthropic.com/en/docs/claude-code/memory)，自动加入常见工作流、风格约定和编码规范，以契合你所在组织的偏好。把你的 CLAUDE.md 文件部署到一个企业级目录中，让所有开发者都继承同一份基线。使用 [hooks](https://docs.anthropic.com/en/docs/claude-code/hooks) 来强制执行前/后动作自动化，例如自动格式化或 lint 检查。

**根据你的合规要求选择合适的端点。** bedrock-runtime 端点在两个 AWS GovCloud (US) 区域（US-West 和 US-East）内支持 Guardrails、调用日志和跨区域推理。bedrock-mantle 端点原生支持 Anthropic Messages API，并在 AWS GovCloud (US-West) 可用。目前 Guardrails 和调用日志是 bedrock-runtime 独有的，因此对于需要完整审计轨迹和内容过滤的部署，推荐使用 bedrock-runtime。

**在部署前进行一次彻底的安全评估。** 根据你组织的安全策略来评估 Claude Code 的能力。Amazon Bedrock 保护的是推理层，但 Claude Code 运行在本地开发者机器上，需要单独的评估与风险管理。像对待环境中运行的其他第三方软件一样，施加托管权限、调用日志和按用户 token 上限等控制。

## 结论

Claude Opus 5.5 和 Claude Sonnet 5.5 在 AWS GovCloud (US) 的 Amazon Bedrock 上上线，为组织提供了一条面向受监管工作负载、与合规一致的 AI 辅助开发路径。Claude Sonnet 5 拥有 FedRAMP Class D（原 High）认证和 DoD IL4/IL5 授权，为敏感环境提供最全面的合规覆盖。Claude Sonnet 5.5 拥有 FedRAMP Class D 认证，在编程和知识工作上比 Claude Sonnet 5 更进一步，且每任务成本更低。Claude Opus 5.5 拥有 FedRAMP Class D 认证，为那些该认证级别已足够的工作负载带来更深的推理和更长的自主任务能力。

结合 Claude Code，团队可以直接在终端、IDE 或 CI/CD 流水线中采用智能体式编程工作流，同时数据始终留在 AWS GovCloud (US) 基础设施之内。无论你选择支持完整 Guardrails 和日志的 bedrock-runtime 端点，还是选择原生 Anthropic Messages API 访问的 bedrock-mantle 端点，你都可以让部署契合你组织的合规与运营要求。
