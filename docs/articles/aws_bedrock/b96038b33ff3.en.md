# PolyAI Dialog-RSN-1 is now on Amazon SageMaker JumpStart

Dialog-RSN-1, a reasoning model built for real-time complex dialog, is available today on AWS Marketplace and Amazon SageMaker JumpStart. It powers frontier dialog: agents that hear a live call, reason about it, and act in real time.

As an AWS customer, you can [subscribe to Dialog-RSN-1 through AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-l4qyhvfxnkq7e) and deploy it as a SageMaker endpoint inside your own AWS environment. You can also deploy directly from Amazon SageMaker Studio following the steps in [Deploy and evaluate models with Amazon SageMaker JumpStart](https://aws.amazon.com/blogs/machine-learning/deploy-and-evaluate-models-with-amazon-sagemaker-jumpstart/). That means the model designed to handle your customer conversations can be deployed like other Amazon SageMaker models with an AWS Marketplace subscription.

## Deploying Dialog-RSN-1 inside AWS

Dialog-RSN-1 is the first PolyAI model available through [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-l4qyhvfxnkq7e). It runs inside your own AWS environment on the same AWS cloud that powers PolyAI’s compute and model training and serving.

All in a single pass, Dialog-RSN-1 perceives a caller’s audio directly, reasons about what they need, and responds in real time. On SageMaker, it deploys as an endpoint like other models you run there. It is reachable from your own architecture, billed through your AWS account, and covered by the same virtual private cloud (VPC), AWS Identity and Access Management (IAM) roles, and monitoring you already have in place.

You keep ownership of orchestration, telephony integration, and business logic. Dialog-RSN-1 takes off your plate the hardest part to build yourself: understanding a live call and responding to it in real time. The endpoint speaks the OpenAI Realtime protocol, so an existing Realtime client connects through PolyAI’s [bridge](https://github.com/polyai/dialog-rsn-1-sagemaker) by changing its base URL. Audio in is 16-bit PCM mono at 16 or 24 kHz (transcode G.711 or Opus first). Connections last up to 30 minutes, and the model is English-only today.

To get started, [find Dialog-RSN-1 on AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-l4qyhvfxnkq7e), then deploy it straight into an Amazon SageMaker endpoint in your own account. Or you can deploy directly from [Amazon SageMaker JumpStart](https://aws.amazon.com/sagemaker/ai/jumpstart/).

With Dialog-RSN-1 now onboarded to SageMaker JumpStart, deploying Dialog-RSN-1 takes one click. From the Amazon SageMaker AI console, open the Model Hub, select Dialog-RSN-1 from the JumpStart catalog, and choose Deploy. SageMaker JumpStart then spins up a real-time inference endpoint on a serving stack it has already tuned for you. No containers to wrangle, no instance types to second-guess, and no manual benchmarking. For automated workflows, the same one-click deployment also runs in a few lines of the SageMaker Python SDK.

The Dialog-RSN-1 endpoint runs entirely within your own AWS account. It is deployed in your VPC, accessed through your IAM roles, and monitored with the same Amazon CloudWatch logging and metrics you use for every other workload. Because inference happens inside your account, your callers’ audio and transcripts stay within a boundary you control. For a model handling live customer conversation, this helps support your data residency and auditability requirements.

## Built for speed and accuracy

Models built for live calls may make you choose between speed and understanding. And models built for speed may miss the meaning, and ones built for reasoning may lead to wait time for callers. Dialog-RSN-1 avoids the tradeoff.

With PolyAI, you can build dialog agents that hear and handle calls the way your human agents would. These agents catch hesitation, hear frustration before it escalates, and know when to speak.

Real-time customer conversation is the job PolyAI’s Dialog-RSN-1 is built for, and it is already handling live calls in production today. Because the model reasons directly over the caller’s audio, it picks up tone, hesitation, and timing, the signals a plain transcript loses, and decides for itself the right moment to respond.

## A model that hears calls the way humans do

Dialog-RSN-1 is a model focused on real-time conversations. There is no separate speech-to-text step and no reasoning model on the appropriate moment to talk, so thereby no multiple handoffs.

In practice, that means the callers get responses faster:

- Barge-in keeps working even when call volume spikes, instead of getting switched off to protect performance.
- Responses keep pace, so the model is not lagging behind the conversation while it reasons through what to say.
- Transcription is produced from the audio itself, because Dialog-RSN-1 is reading the actual audio, not someone else’s best guess at it.

## One-click deploy and optimizations for your workload

From the same model card you choose Deploy, and Amazon SageMaker JumpStart stands up a real-time inference endpoint with a pre-configured serving stack. There is no manual container selection or instance guesswork. The real convenience is the named optimization profiles: instead of hand-tuning infrastructure, you pick the target that matches how you run Dialog-RSN-1. Latency optimized minimizes Time to First Token for interactive, real-time calls. Throughput optimized maximizes tokens per second for high call volumes. Cost optimized minimizes infrastructure cost per request. Balanced is an even tradeoff for general-purpose use.

Because Dialog-RSN-1 is built to respond in real time, you can use the latency-optimized profile to carry that responsiveness straight to your own endpoint. Before you deploy, SageMaker JumpStart surfaces the key performance metrics: P50 latency, Time to First Token, and throughput. This lets you right-size the ml.* instance for your traffic instead of benchmarking dozens of combinations by hand. You can run the whole flow from the console, or script it through the SageMaker Python SDK to wire deployments into continuous integration and continuous delivery (CI/CD).
