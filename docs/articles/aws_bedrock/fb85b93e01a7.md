# Syngenta 使用 Amazon Bedrock Agents 开发生成式 AI 助手来支持销售代表

*本文由 Syngenta 的 Zach Marston 与 Serg Masis 共同撰写。*

[Syngenta](https://www.syngenta.com/) 与 AWS 合作开发了 [Cropwise AI](https://www.cropwise.com/innovations/cropwise_ai)——一个由 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 驱动的创新方案，用于加速其销售代表在北美洲为各地种植者落实 Syngenta 种子产品的能力。Cropwise AI 借助 AWS 发挥[生成式 AI](https://aws.amazon.com/generative-ai/) 的力量，增强 Syngenta 的种子选择工具，并简化农户与销售代表的决策流程。这一对话式 agent 提供了一种直观的新方式来访问海量种子产品信息，从而支持种子推荐，为农户和销售代表提供一件额外工具，用来快速检索相关的种子信息，补充他们的专业判断，并支持协作式的知情决策。

生成式 AI 正在重塑企业，并在各个行业释放新的机会。作为农业领域的全球领导者，Syngenta 一直率先使用数据科学与机器学习（ML）来提升客户体验，始终不渝地致力于创新。在多年部署 ML 与计算机视觉以应对复杂挑战的经验基础上，Syngenta 推出了 [NemaDigital](https://www.syngenta.com/en/company/media/syngenta-news/year/2022/syngenta-launches-worlds-first-commercial-digital-tool-detect)、Moth Counter 和 Productivity Zones 等应用。如今，Syngenta 更进一步，使用大语言模型（LLM）与 Amazon Bedrock Agents 在 AWS 上实现 Cropwise AI，标志着农业技术进入新时代。

本文将介绍 Syngenta 开发 Cropwise AI 的历程。

## 业务挑战

Syngenta 在北美提供多样化的种子产品组合，体现了公司到田间地头与种植者面对面沟通的承诺。种子选择过程需要仔细权衡多种因素，包括种子产品的特性、具体的种植环境，以及每位农户特有的耕作方式与目标。许多农户难以应对这一复杂的决策过程，未必总能为自己特定的条件选出最合适的种子，这可能会影响作物产量与盈利水平。

Syngenta 看到了改进这一选择流程的机会，于是与 [AWS Generative AI Innovation Center](https://aws.amazon.com/generative-ai/innovation-center/) 合作，这是 AWS 一个促进客户与 AWS 专家协作的项目。这一合作产出了 Cropwise AI，它提升了销售代表与客户互动、推荐 Syngenta 种子产品的效率。

## Cropwise AI

Cropwise AI 以多种有力的方式改变了种子选择流程。它把复杂的图表和表格简化为自然、对话式的体验，让用户能在移动设备上快速、按需地访问详细的种子产品信息。该工具还精简了数据浏览方式，使用户能够高效地探索并比较 Syngenta 庞大的种子目录。此外，Cropwise AI 能够规模化地提供个性化推荐，让种子选择与本地条件和具体农场需求相匹配，从而形成更精准、更易获取的选择流程。

Cropwise AI 作为销售代表专业知识与农户决策过程的有价值伙伴，增强了种子选择流程。对销售代表而言，它赋予他们更深入的洞察，使其能给出更有依据的推荐。对农户而言，它提供了一个易于使用的资源来探索和比较种子选项。下面的示例展示了 GHX 2.0 中的 Cropwise AI 移动应用：左侧为描述一款常见种子产品，右侧为转录的对话。

Syngenta 与 AWS 的合作展现了 LLM 与 AI agent 的变革力量。生成式 AI 能够内嵌人类专业知识并以自然语言交流，从而放大人的能力，让组织可以规模化地运用知识。这个项目只是 Syngenta 利用先进的 AWS AI 服务推动农业创新的一个例子。

在接下来的几节中，我们将深入剖析底层工作流，详细概述 Cropwise AI 方案。我们会探讨如何把 Amazon Bedrock Agents 与生成式 AI 以及前沿的 AWS 技术结合使用，这些技术为支持该行业（乃至其他行业）的销售代表提供了一条具有变革性的路径。

## 方案概述

Cropwise AI 构建在一套 AWS 架构之上，该架构通过可扩展性、可维护性和安全性来应对这些挑战。该架构分为两个主要部分：agent 架构与知识库架构。该方案还通过 [AWS Cloud Development Kit](https://aws.amazon.com/cdk/)（AWS CDK）部署，这是一个开源软件开发框架，可用现代编程语言定义云基础设施，并通过 [AWS CloudFormation](https://aws.amazon.com/cloudformation/) 进行预置。

### Agent 架构

下图展示了带标准授权与实时交互的无服务器 agent 架构，以及一个 LLM agent 层：该层使用 Amazon Bedrock Agents 实现多知识库编排，并使用 API 或 Python 执行器实现后端编排。按域划分的 agent 使代码可以在多个 agent 之间复用。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/02/f6a0ac0baf7f9f185c53f61623639964951ef689.png)

与 [LangGraph](https://www.langchain.com/langgraph) 等其他方案相比，Amazon Bedrock Agents 为 Syngenta 带来了几项关键优势：

- **灵活的模型选择** – Syngenta 可以访问多个最先进的基础模型（FM），例如 Anthropic 的 Claude 3.5 Haiku 和 Sonnet、Meta Llama 3.1 等，并且无需修改代码就能在这些模型之间切换。他们可以选择对特定工作流足够准确、同时成本合理的模型。
- **易于部署** – 它与其他 AWS 服务无缝集成，并拥有统一的开发与部署工作流。
- **企业级安全** – 借助 AWS 稳健的安全基础设施，Amazon Bedrock 已纳入 ISO、SOC 和 CSA STAR Level 2 等常见合规标准的适用范围；符合 HIPAA 资格；并且你可以在遵守 GDPR 的前提下使用 Amazon Bedrock。
- **可扩展性与集成** – 它可以直接与现有系统做 API 集成，并内置对多个动作编排的支持。这使 Syngenta 能够轻松构建并扩展其 AI 应用。

agent 架构负责处理用户交互并处理数据，以给出准确的推荐。它使用了以下 AWS 服务：

- **基于 AWS Lambda 的无服务器计算** – 该架构从 [AWS Lambda](https://aws.amazon.com/lambda) 开始，它提供无服务器计算能力，可根据工作负载需求自动伸缩。当需要执行自定义处理任务时，例如调用 Amazon Bedrock agent 或与各类数据源集成，Lambda 函数会被触发以高效地完成这些任务。
- **基于 Lambda 的 action group** – Amazon Bedrock agent 会把用户查询导向功能动作，这些动作可能通过 API 连接从各类来源为工作流收集数据，通过模型集成利用所收集的数据生成推荐，或通过执行 Python 提取与用户工作流相关的特定信息以辅助产品比较。
- **安全的用户与数据管理** – 用户身份验证与授权通过 [Amazon Cognito](https://aws.amazon.com/cognito/) 集中、安全地管理。该服务确保用户身份与访问权限得到有效处理，维持系统的保密性与安全性。用户身份会通过一条安全的旁路通道（[会话属性](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-session-state.html)）传递到 agent 和 action group。这使它们能够访问用户专属或受限的信息，而每次访问都可以在工作流内获得授权。会话属性不会与 LLM 共享，从而确保授权决策基于经过校验且不可篡改的数据。关于这种做法的更多信息，请参阅[为生成式 AI 应用中所用数据实施有效的数据授权机制](https://aws.amazon.com/blogs/security/implement-effective-data-authorization-mechanisms-to-secure-your-data-used-in-generative-ai-applications/)。
- **使用 AWS AppSync 实现实时数据同步** – 为确保用户始终能访问最新信息，该方案使用了 [AWS AppSync](https://aws.amazon.com/appsync/)。它通过 GraphQL API 实现实时数据同步与更新，提供顺畅、响应迅速的用户体验。
- **使用 Amazon DynamoDB 高效存储元数据** – 为支持快速、高效的数据检索，文档元数据存储在 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 中。这一 NoSQL 数据库针对快速访问做了优化，确保知识库保持响应迅速且可检索。
- **使用 Amazon CloudWatch 集中记录日志并监控** – 为保持卓越的运维水平，方案采用 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 进行集中式日志记录与监控。它提供深入的运维洞察，有助于排查故障、调优性能，并确保系统平稳运行。

该架构在设计上兼顾灵活性与韧性。AWS Lambda 支持顺畅执行各类任务，包括数据处理与 API 集成；AWS AppSync 则在用户与系统之间提供实时交互与数据流。通过使用 Amazon Cognito 进行身份验证，agent 得以维持保密性，保护敏感的用户数据。

### 知识库架构

下图展示了知识库架构。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/02/7616e1a8610853cc65442ecb07007422883b388f.png)

知识库架构侧重于处理与存储农艺数据，为关键信息提供快速、可靠的访问。关键组件包括：

- **使用 AWS Step Functions 编排文档处理** – 文档处理工作流从 [AWS Step Functions](https://aws.amazon.com/step-functions/) 开始，它负责编排流程中的每一步。从文档最初摄取到最终存储，Step Functions 确保数据处理顺畅高效。
- **使用 Amazon Textract 自动提取文本** – 当文档上传到 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）时，会触发 [Amazon Textract](https://aws.amazon.com/textract/) 自动从这些文档中提取文本。提取出的文本随后可用于进一步分析并生成元数据，为原始数据补充基于版面的结构与含义。
- **使用 Amazon S3 做主要数据存储** – 处理后的文档及其关联元数据会安全地存储在 Amazon S3 中。该服务充当主存储方案，为所有存储内容提供一致的访问与有条理的数据管理。
- **使用 DynamoDB 高效存储元数据** – 为支持快速、高效的数据检索，文档元数据存储在 DynamoDB 中。
- **Amazon Bedrock Knowledge Bases** – 最终的文本内容与元数据信息会被摄取到 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 中，以便在 agent 工作流中高效检索，其底层由 [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 向量库支撑。agent 可以根据使用场景选择使用一个或多个知识库。

这一架构实现了全面的数据管理与检索，支撑 agent 给出精准推荐的能力。通过把 Step Functions 与 Amazon Textract 集成，系统自动化了文档处理，减少人工干预并提升效率。

## 用例

Cropwise AI 覆盖多个关键用例，为销售代表和种植者带来实实在在的收益：

- **产品推荐** – 销售代表或种植者就特定环境条件下的最佳种子选择寻求建议，例如“我所在的地区非常干燥且多风。你建议我的地块种哪些玉米杂交品种？”。agent 使用自然语言处理（NLP）理解查询，并调用底层农艺模型，针对具体地块条件与农艺需求推荐最优的种子选择。通过整合多个数据源以及可解释的研究结果（包括天气模式与土壤数据），agent 给出个性化且贴合具体情境的推荐。
- **查询农艺模型** – 种植者对种植密度或其他影响产量的农艺因素有疑问，例如“玉米杂交品种 G11V76 在不同播种密度下预期产量是多少？”。agent 会解析查询、调用相应的农艺模型，并给出种植者容易理解的简明解释。这使种植者能够基于科学洞察做出有依据的决策，改进作物管理策略。
- **整合多个数据源** – 种植者可以要求给出会考虑实时数据（如当前天气条件或市场价格）的推荐，例如“现在适合给玉米地施除草剂吗？”。agent 会从多个来源获取数据，将其与现有农艺模型结合，并给出考虑当前条件的推荐。这种整体式方法确保推荐及时、相关且可执行。

## 成果

Cropwise AI 的落地显著提升了农产品推荐的效率与准确性：

- 销售代表现在用分析模型生成推荐的速度提升至原来的五倍，使他们能把更多时间用于与客户建立关系和探索新机会
- 自然语言界面简化了交互，降低了新用户的学习曲线，并减少了大量培训的需求
- agent 追踪推荐结果的能力为了解客户偏好提供了有价值的洞察，并有助于持续改进个性化

为评估成果，Syngenta 从销售代表那里收集了 100 组问答对组成数据集，并用它们跑测 agent。除了人工评估之外，他们还使用 LLM 作为评判者（[Ragas](https://docs.ragas.io/)）来评估 Cropwise AI 生成的回答。下图展示了这次评估的结果，表明所提供回答的相关性、简洁性和忠实度都非常高。

## 结语

Cropwise AI 通过应对种子代表（尤其是那些为种植者管理多种种子产品的人）所面临的独特挑战，正在革新农业行业。这一 AI 驱动的工具精简了多类种子产品落地的流程，使销售代表能够轻松给出针对每位种植者独特需求的精准推荐。通过使用先进的生成式 AI 与 Amazon Bedrock Agents 等 AWS 技术，Cropwise AI 显著提升了运营效率，并改善了产品推荐的准确性、速度与用户体验。

该方案的成功凸显了 AI 改造传统农业实践的潜力，为整个行业进一步的创新打开了大门。随着 Cropwise AI 持续演进，工作重点将放在扩展能力、强化数据集成，以及持续符合不断变化的监管标准上。

归根结底，Cropwise AI 不仅优化了销售流程，还为销售代表和种植者提供了在动态变化的农业环境中蓬勃发展所必需的可执行洞察与可靠工具。通过打造高效、直观的推荐流程，Cropwise AI 优化了作物产量并提升了整体客户满意度，使其成为现代农业销售团队不可或缺的资源。
