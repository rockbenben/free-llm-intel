# 保障 Amazon Bedrock 跨区域推理的安全：地理级与全球级

随着各组织在规模化生产中构建更多使用 AI 能力的运营型工作负载，[生成式 AI](https://aws.amazon.com/generative-ai/) 推理的采用与实施不断增加。为帮助客户实现其生成式 AI 应用的规模，[Amazon Bedrock](https://aws.amazon.com/bedrock/) 提供[跨区域推理（CRIS）配置文件](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)，这是一项强大的功能，组织可以用它把推理处理无缝分布到多个 [AWS 区域](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region)。该能力帮助你在规模化构建时获得更高吞吐量，并在高负载下保持生成式 AI 应用的响应能力。

本文探讨实施 Amazon Bedrock 跨区域推理配置文件时的安全考量与最佳实践。无论你是在构建生成式 AI 应用，还是需要满足特定的区域合规要求，本指南都将帮助你理解 Amazon Bedrock CRIS 的安全架构，以及如何正确配置你的实施。

推理配置文件围绕两个关键概念运作：

- **源区域（Source Region）** – 发起 API 请求的区域
- **目标区域（Destination Region）** – Amazon Bedrock 可将推理请求路由到的区域

当你在 Amazon Bedrock 中调用跨区域推理配置文件时，请求会走一条智能路由路径。请求从你发起 API 调用的源区域出发，被自动路由到该推理配置文件中定义的某个目标区域。跨区域推理通过安全的 AWS 网络运行，传输中的数据采用端到端加密。

关键区别在于，CRIS 不改变数据的存储位置——使用跨区域推理时，任何客户数据都不会存储在目标区域，客户托管的日志（例如模型调用日志）、知识库和已存储的配置都只保留在源区域。推理请求经由由 Amazon Bedrock 管理的 [AWS 全球网络](https://aws.amazon.com/about-aws/global-infrastructure/global-network/) 传输，响应以加密方式返回给源区域中的应用程序。

Amazon Bedrock 提供两类跨区域推理配置文件：

- **地理级跨区域推理** – Amazon Bedrock 在指定地理范围（例如美国、欧盟、澳大利亚和日本）内自动选择最优区域来处理你的推理请求。该配置文件将推理处理保持在特定地理边界内，可帮助组织满足区域数据驻留要求。
- **全球级跨区域推理** – 全球级 CRIS 通过允许把推理请求路由到全球受支持的商业区域，进一步增强跨区域推理，优化可用资源并实现更高的模型吞吐量。该配置文件在无地理限制的情况下，把请求路由到全球所有受支持的商业区域。

如果你有严格的数据驻留或合规要求，应仔细评估跨区域推理是否符合你的策略与法规，因为你的推理数据可能会在推理配置文件中定义的多个预先配置区域间被处理。

## IAM 权限要求与服务控制策略（SCP）考量

## 理解地理级 CRIS 与全球级 CRIS 的 SCP 要求

本节概述 SCP 要求，并说明地理级 CRIS 与全球级 CRIS 配置文件在特定区域 SCP 条件行为上的主要差异。

### 地理级 CRIS 的 SCP 要求

许多组织出于安全和合规考虑，通过在 [AWS Organizations](https://aws.amazon.com/organizations/) 中使用 SCP 来实施区域访问控制。如果你的组织使用 SCP 屏蔽未使用的区域，则必须确保你的特定区域 SCP 条件在地理级 CRIS 配置文件列出的所有区域都允许访问 Amazon Bedrock 的最低必需权限，它才能正常工作。例如，美国版 Anthropic Claude Sonnet 4.5 地理级跨区域推理需要访问 `us-east-1`、`us-east-2` 和 `us-west-2`。如果某个 SCP 仅允许访问 `us-east-1`，跨区域推理请求就会失败。因此，你需要在 SCP 中专门为 Amazon Bedrock 跨区域推理配置文件访问放开全部三个区域。为提升安全性，可以考虑使用 [`bedrock:InferenceProfileArn`](https://docs.aws.amazon.com/service-authorization/latest/reference/list_amazonbedrock.html#amazonbedrock-bedrock_InferenceProfileArn) 条件把访问限制到特定推理配置文件。示例策略请参阅 [在多账户环境中启用 Amazon Bedrock 跨区域推理](https://aws.amazon.com/blogs/machine-learning/enable-amazon-bedrock-cross-region-inference-in-multi-account-environments/)。

### 全球级 CRIS 的 SCP 要求

你可以使用 SCP 作为组织范围的管控手段。如果你的组织使用特定区域 SCP，请确保 `"aws:RequestedRegion": "unspecified"` 没有被包含在 **deny** 区域列表中，因为全球级 CRIS 请求会使用该区域值。该条件仅针对 Amazon Bedrock 全球级跨区域推理，不会影响其他 AWS 服务的 API 调用。

例如，假设你有一个 SCP，根据合规要求屏蔽除少数已批准区域（如 `us-east-1`、`us-east-2` 或 `ap-southeast-2`）之外的所有 AWS 区域访问。在这种情况下，要在保留其他服务区域限制的同时允许全球级跨区域推理功能，你必须专门为 Amazon Bedrock 操作在允许区域列表中加入 `"unspecified"`。为此，先把 Amazon Bedrock API 调用从更宽泛的特定区域 SCP 中排除，再为 Amazon Bedrock 操作单独添加一条语句，把允许区域列表扩展到包含 `"unspecified"`。

以下示例 SCP 用两条语句演示了这种做法：

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      // ⚠️ Bedrock is excluded here to enable separate policy control
      "Sid": "DenyServicesOutsideAllowedRegions",
      "Effect": "Deny",
      "NotAction": [
        "bedrock:*",
        "iam:*",
        "organizations:*",
        "route53:*",
        "cloudfront:*",
        "support:*",
        [Truncated]
        "account:*"
      ],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "aws:RequestedRegion": [
            "ap-southeast-2",
            "us-east-1",
            "us-west-2"
          ]
        }
      }
    },
    {
    // ⚠️ Add this statement to enable Global CRIS
      "Sid": "DenyBedrockOutsideAllowedRegions",
      "Effect": "Deny",
      "Action": "bedrock:*",
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "aws:RequestedRegion": [
            "ap-southeast-2",
            "us-east-1",
            "us-west-2",
            "unspecified"
          ]
        }
      }
    }
  ]
}
```

第一条语句拒绝三个已批准区域（`ap-southeast-2`、`us-east-1`、`us-west-2`）之外的所有 AWS 服务，但 Amazon Bedrock 除外（在 `NotAction` 列表中指定）。这一排除意味着 Amazon Bedrock 不受与其他服务相同的区域限制，从而可由其专用的策略语句来管控。

第二条语句专门处理 Amazon Bedrock，允许它在三个已批准区域以及 `"unspecified"` 中运行，以支持全球级 CRIS 功能。

使用该策略前，你需要把允许区域列表更新为贵组织批准的区域，并删除行内注释（//）。

## 地理级与全球级跨区域推理的 IAM 策略要求

本节概述地理级与全球级跨区域推理的 IAM 策略要求。

### 地理级 CRIS 的 IAM 策略要求

要允许 IAM 用户或角色调用地理级跨区域推理配置文件，你可以使用以下示例策略。该示例策略授予使用带美国地理级跨区域推理配置文件的 Claude Sonnet 4.5 [基础模型（FM）](https://aws.amazon.com/what-is/foundation-models/) 所需的权限，其中源区域为美国东部（弗吉尼亚北部）– `us-east-1`，配置文件中的目标区域为美国东部（弗吉尼亚北部）– `us-east-1`、美国东部（俄亥俄）–

`us-east-2`，以及美国西部（俄勒冈）– `us-west-2`。要查看所有可用跨区域推理配置文件、受支持模型、源区域和目标区域的完整列表，请参阅 Amazon Bedrock 用户指南中的 [推理配置文件受支持的区域和模型](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html#inference-profiles-support-system)。

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "GrantGeoCrisInferenceProfileAccess",
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:us-east-1:<ACCOUNT_ID>:inference-profile/us.anthropic.claude-sonnet-4-5-20250929-v1:0"
            ]
        },
        {
            "Sid": "GrantGeoCrisModelAccess",
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:us-east-1::foundation-model/anthropic.claude-sonnet-4-5-20250929-v1:0",
                "arn:aws:bedrock:us-east-2::foundation-model/anthropic.claude-sonnet-4-5-20250929-v1:0",
                "arn:aws:bedrock:us-west-2::foundation-model/anthropic.claude-sonnet-4-5-20250929-v1:0"
            ],
            "Condition": {
                "StringEquals": {
                    "bedrock:InferenceProfileArn": "arn:aws:bedrock:us-east-1:<ACCOUNT_ID>:inference-profile/us.anthropic.claude-sonnet-4-5-20250929-v1:0"
                }
            }
        }
    ]
}
```

第一条语句为源自请求区域（`us-east-1`）的请求授予对地理级跨区域推理的 `bedrock:InvokeModel` API 访问权限。第二条语句授予对请求区域以及推理配置文件中列出的所有目标区域（`us-east-1`、`us-east-2` 和 `us-west-2`）中 FM 的 `bedrock:InvokeModel` API 访问权限。

你需要把占位符 `<ACCOUNT_ID>` 替换为实际的 AWS 账户 ID。确认区域代码（`us-east-1`、`us-east-2`、`us-west-2`）、模型标识符（`anthropic.claude-sonnet-4-5-20250929-v1:0`）和推理配置文件的 [Amazon Resource Name](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference-arns.html)（ARN）与你具体的部署需求以及目标区域中可用的模型相匹配。

### 全球级 CRIS 的 IAM 策略要求

地理级和全球级 CRIS 的 IAM 策略都需要访问源区域中的推理配置文件和基础模型。不过，对于全球级 CRIS，你在目标区域基础模型访问条件中使用 `"aws:RequestedRegion": "unspecified"`，而地理级 CRIS 需要显式列出地理级跨区域推理配置文件中列出的所有目标区域。

要允许 IAM 用户或角色调用全球级跨区域推理配置文件，你可以使用以下示例策略。该示例策略授予使用带全球级跨区域推理配置文件的 Claude Sonnet 4.5 FM 所需的权限，其中源区域为 `us-east-1`。

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "GrantGlobalCrisInferenceProfileRegionAccess",
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:us-east-1:<ACCOUNT_ID>:inference-profile/global.anthropic.claude-sonnet-4-5-20250929-v1:0"
            ]
        },
        {
            "Sid": "GrantGlobalCrisInferenceProfileInRegionModelAccess",
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:us-east-1::foundation-model/anthropic.claude-sonnet-4-5-20250929-v1:0"
            ],
            "Condition": {
                "StringEquals": {
                    "bedrock:InferenceProfileArn": "arn:aws:bedrock:us-east-1:<ACCOUNT_ID>:inference-profile/global.anthropic.claude-sonnet-4-5-20250929-v1:0"
                }
            }
        },
        {
            "Sid": "GrantGlobalCrisInferenceProfileGlobalModelAccess",
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:::foundation-model/anthropic.claude-sonnet-4-5-20250929-v1:0"
            ],
            "Condition": {
                "StringEquals": {
                    "aws:RequestedRegion": "unspecified",
                    "bedrock:InferenceProfileArn": "arn:aws:bedrock:us-east-1:<ACCOUNT_ID>:inference-profile/global.anthropic.claude-sonnet-4-5-20250929-v1:0"
                }
            }
        }
    ]
}
```

在该策略中，第一条语句授予调用源区域 `us-east-1` 中全球级跨区域推理配置文件资源的权限。该配置文件使用前缀 `global` 表示跨区域路由。第二条语句允许在 `us-east-1` 区域调用全球级基础模型，但仅当调用通过指定的全球级推理配置文件发起时才允许。第三条语句允许使用不带具体区域的 ARN 模式 `"arn:aws:bedrock:::foundation-model/anthropic.claude-sonnet-4-5-20250929-v1:0"` 在任意受支持的 AWS 商业区域调用全球级基础模型。要限制对全球级跨区域推理的访问，你可以使用条件 `"aws:RequestedRegion": "unspecified"`，它支持全球级跨区域推理请求中的动态区域路由。此外，为确认权限仅适用于特定的全球级跨区域推理配置文件，你可以使用条件 `bedrock:InferenceProfileArn`，取值为该全球级跨区域推理配置文件的 ARN。有关该 IAM 策略更详细的说明，请参阅 [利用 Amazon Bedrock 上新的全球级跨区域推理与 Anthropic 的 Claude Sonnet 4.5 解锁全球 AI 推理可扩展性](https://aws.amazon.com/blogs/machine-learning/unlock-global-ai-inference-scalability-using-new-global-cross-region-inference-on-amazon-bedrock-with-anthropics-claude-sonnet-4-5/)。

你需要把 `<ACCOUNT_ID>` 替换为实际的 AWS 账户 ID。确认模型标识符（`anthropic.claude-sonnet-4-5-20250929-v1:0`）和推理配置文件 ARN 与你具体需求以及全球级跨区域推理可用的模型相匹配。

## 禁用跨区域推理

有数据驻留或合规要求的组织应评估全球级跨区域推理或地理级跨区域推理是否符合其合规框架，因为请求可能会在其主要运营区域之外的其他受支持 AWS 区域中被处理。对于需要禁用地理级或全球级跨区域推理的组织，可以从以下方法中选择。

### 限制地理级跨区域推理

实施一条 deny SCP，限制 AWS 组织中各 AWS 账户内的所有 IAM 用户和角色访问特定的地理级跨区域推理配置文件。该方法提供组织范围的控制，在组织单位内所有账户中屏蔽特定的地理级跨区域推理配置文件，即使之后又添加了单独的 IAM allow 策略也一样。

以下示例 SCP 显式拒绝所有使用非美国地理配置文件的 Amazon Bedrock 推理配置文件调用。该策略使用设为 "false" 的 **Null** 条件，确保仅在使用了推理配置文件时才适用；并对 `bedrock:InferenceProfileArn` 键使用 `ArnNotLike` 条件，屏蔽除带美国前缀（us.*）之外的所有跨区域配置文件。**两项条件都必须为真，拒绝才会生效**——也就是说，该策略只屏蔽那些正在使用推理配置文件、且该配置文件不是美国地理配置文件的请求。

```
{ 
  "Version": "2012-10-17", 
  "Statement": [ 
    { 
      "Sid": "DenyNonUSGeographicCRIS", 
      "Effect": "Deny", 
      "Action": "bedrock:*", 
      "Resource": "*", 
      "Condition": { 
        "Null": { 
          "bedrock:InferenceProfileArn": "false" 
        }, 
        "ArnNotLike": { 
          "bedrock:InferenceProfileArn": [ 
            "arn:aws:bedrock:*:*:inference-profile/us.*" 
          ] 
        } 
      } 
    } 
  ] 
}
```

要限制特定 IAM 角色或用户使用地理级跨区域推理，就不要给特定 IAM 用户或角色分配带地理级跨区域推理权限的 IAM 策略。

### 禁用全球级跨区域推理

实施一条 deny SCP，限制 AWS 组织中各 AWS 账户内的所有 IAM 用户和角色访问全球级跨区域推理配置文件。该方法提供组织范围的控制，在组织单位内所有账户中屏蔽全球级跨区域推理功能，即使之后又添加了单独的 IAM allow 策略也一样。以下示例 SCP 通过 `"aws:RequestedRegion": "unspecified"` 显式拒绝全球级跨区域推理，并用 `"ArnLike"` 条件定位 ARN 中带 `global` 前缀的推理配置文件。

```
{
	"Version": "2012-10-17",
	"Statement": [
		{
			"Effect": "Deny",
			"Action": "bedrock:*",
			"Resource": "*",
			"Condition": {
				"StringLike": {
					"aws:RequestedRegion": [
						"unspecified"
					]
				},
				"ArnLike": {
					"bedrock:InferenceProfileArn": "arn:aws:bedrock:*:*:inference-profile/global.*"
				}
			}
		}
	]
}
```

要限制特定 IAM 角色或用户使用全球级跨区域推理，就不要给特定 IAM 用户或角色分配带全球级跨区域推理权限的 IAM 策略。

## 使用 AWS Control Tower 的高级实施

如果你使用 AWS Control Tower，需要更新 SCP，以控制组织中的跨区域推理。

**重要：** 强烈不建议手动编辑由 AWS Control Tower 管理的 SCP，因为这可能导致“漂移”。你应改用 AWS Control Tower 提供的机制来管理这些例外。

### 启用或禁用地理级跨区域推理

要启用或禁用地理级跨区域推理，请参阅 [在多账户环境中启用 Amazon Bedrock 跨区域推理](https://aws.amazon.com/blogs/machine-learning/enable-amazon-bedrock-cross-region-inference-in-multi-account-environments/)。

#### 如何禁用全球级跨区域推理

要在组织级别禁用全球级跨区域推理服务，你需要修改由 [AWS Control Tower](https://aws.amazon.com/controltower/) 自动创建的 SCP。使用 [Customizations for AWS Control Tower](https://docs.aws.amazon.com/controltower/latest/userguide/cfct-overview.html)（CfCT）拒绝对名称为 unspecified 的区域的 Amazon Bedrock 操作，如下例所示。

```
{
      "Effect": "Deny",
      "Action": "bedrock:*",
      "Resource": "*",
      "Condition": {
        "StringLike": {
          "aws:RequestedRegion": [
            "unspecified"
          ]
        },
        "ArnLike": {
          "bedrock:InferenceProfileArn": "arn:aws:bedrock:*:*:inference-profile/global.*"
        }
      }
}
```

#### 如何启用全球级跨区域推理

要使用 AWS Control Tower 启用全球级跨区域推理，你需要修改由 AWS Control Tower 自动创建的 SCP。请使用 CfCT 进行此修改，因为 AWS Control Tower 本身不支持启用名为 `"unspecified"` 的区域。

以下是一个经过修改、添加了 `"unspecified"` 以允许全球级跨区域推理的 SCP 示例：

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
	      "Condition": {
        "StringNotEquals": {
          "aws:RequestedRegion": [
            "ap-northeast-1",
            "ap-south-1",
            "ap-southeast-1",
            "ap-southeast-2",
            "us-east-1",
            "us-east-2",
            "us-west-2",
            "unspecified"
          ]
        },
        "ArnNotLike": {
          "aws:PrincipalARN": [
            "arn:*:iam::*:role/AWSControlTowerExecution"
          ]
        }
      },
      "Resource": "*",
      "Effect": "Deny",
      "NotAction": [
        "a4b:*",
        "access-analyzer:*",
        "account:*",
        "acm:*",
        [Truncated]
        "waf-regional:*",
        "waf:*",
        "wafv2:*"
      ],
      "Sid": "GRREGIONDENY"
    }
  ]

```

## AWS 区域启用

Amazon Bedrock 使用推理配置文件把模型调用请求路由到配置文件中列出的所有区域，无论这些区域在你的 AWS 账户中是默认启用还是需要手动选择加入。你无需手动选择加入区域。这种做法消除了逐个启用多个区域并为每个区域管理独立安全控制的需要，从而降低了运营复杂度。例如，如果你使用面向澳大利亚配置文件的特定地理范围跨区域推理，从源区域悉尼调用 Claude Sonnet 4.5，那么你的请求将路由到悉尼和墨尔本。同样，使用全球级跨区域推理时，请求可以路由到任意受支持的 AWS 商业区域，包括你 AWS 账户中尚未选择加入的 AWS 商业区域。

有两类 [AWS 商业区域](https://docs.aws.amazon.com/global-infrastructure/latest/regions/aws-regions.html)。有些区域对 AWS 账户默认启用（例如弗吉尼亚北部、爱尔兰和悉尼），还有些区域需要先手动选择加入才能使用（例如墨尔本、阿联酋和海得拉巴）。这些手动启用的区域较新，是在 2019 年 3 月 20 日之后推出的。更多细节请参阅 [AWS 区域](https://docs.aws.amazon.com/global-infrastructure/latest/regions/aws-regions.html)。

## 结论

Amazon Bedrock 跨区域推理为构建可扩展、高吞吐的生成式 AI 应用提供了强大能力。通过理解跨区域推理与安全控制之间的基本相互作用，并使用 IAM 策略和 SCP 等工具实施精确的条件化例外，你就能在维持安全态势的同时安全地启用该功能。遵循本文概述的策略和最佳实践，你的团队即可在治理与合规态势保持稳固的前提下用跨区域推理进行创新。
