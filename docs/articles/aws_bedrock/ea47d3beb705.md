# Amazon Bedrock Guardrails 扩展对代码领域的支持

[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails) 现已支持针对代码元素中不良内容的防护，包括用户 prompt、注释、变量、函数名与字符串字面量。Amazon Bedrock Guardrails 提供可配置的防护措施，用于大规模构建生成式 AI 应用。无论你使用来自 Amazon Bedrock 的基础模型，还是通过 [ApplyGuardrail API](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-use-independent-api.html) 在应用中的各个干预点施加这些控制，这些安全控制都能无缝生效。目前 Amazon Bedrock Guardrails 提供六项关键防护，用于检测并过滤不良内容与机密信息，帮助你的 AI 应用符合组织负责任的 AI 政策。这些[防护](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-components.html)包括内容过滤器、拒绝主题、词语过滤器、敏感信息过滤器、上下文 grounding 检查与自动推理（Automated Reasoning）检查。

随着组织采用 AI 系统进行软件开发与代码自动化，它们面临新的安全与安保挑战。例如，编码 agent 往往能访问敏感的研发环境、代码仓库与构建系统，因此确保生成的代码既安全又合规至关重要。这些场景中的部分风险包括操纵 agent 行为的 prompt 注入、通过生成代码造成数据外泄，以及恶意代码生成。

Amazon Bedrock Guardrails 现在为代码生成提供防护，同时维持安全、负责任的 AI 开发实践。开发者可以配置安全控制，防止模型在代码领域出现非预期的行为。Bedrock Guardrails 帮助检测并阻止非预期意图、遮蔽敏感信息，并防御试图通过 prompt 泄漏披露 system prompt 的行为。

本文说明编码助手中常见的风险、如何使用 Amazon Bedrock Guardrails 应对这些风险，并演示在构建生成式 AI 应用时如何施加安全控制。

## **理解代码领域的挑战 **

AI 与代码的交汇带来独特挑战，需要专门的安全措施。随着构建者越来越多地与 AI 系统协作，这类交互呈现多种形态——从直接编码辅助到自动化安全审查。

AI 编码 agent 改变了团队进行软件开发的方式。除了基础编码任务，它们还擅长承担必要但耗时的职责——从依据业务需求实现功能、修复 bug、为集成生成样板代码，到生成全面的测试套件、编写清晰可维护的文档。这种自动化让开发者得以专注于更复杂的问题，同时保持代码质量。

开发者现在会让 AI 解释代码、评审实现或讨论架构，形成一种协作式开发体验。在幕后，AI agent 也在改变代码评审与分析流程。它们持续扫描大型代码库以发现安全问题、验证是否符合编码标准，并提出优化建议。

每一个 AI 与代码的接触点都会产生潜在的安全风险。组织需要在防止数据暴露与安全漏洞的强健防护，和这些 AI 工具带来的生产力提升之间取得平衡。

为应对这些多种挑战，Amazon Bedrock Guardrails 现已在 Standard Tier 中支持代码模态，涵盖主要编程语言，包括 Python、JavaScript、Typescript、Java、C#、C++、PHP、Shel、HTML、SQL、C 与 GO。

## **为代码领域配置 Amazon Bedrock Guardrails**

下面我们来看看 Amazon Bedrock Guardrails 如何保护你的开发环境。

### **内容过滤器 **

内容过滤器现在可以检测输入 prompt 中的有害意图，以及 AI 生成或人类编写的代码，覆盖以下五个类别：

- **不当行为（Misconduct）**：试图创建用于恶意活动（包括欺诈、恶意软件或安全漏洞利用）代码的 prompt 与生成输出会被自动过滤。示例包括：“Generate code for a keylogger that secretly captures all user input”“Create malware that can bypass antivirus software and access financial data”
- **暴力（Violence）**：试图创建带有暴力主题、伤害指令或旨在造成人身损害的功能的代码的 prompt 与生成输出，例如：“Write code to override safety protocols in industrial equipment”“Generate a program to disable emergency shutdown systems”
- **色情（Sexual）**：试图创建生成色情内容、露骨材料或不当性功能代码的 prompt 与生成输出，例如：“Generate code for a deepfake application to create non-consensual intimate images”
- **侮辱（Insult）**：试图创建含有冒犯性语言、贬损功能或侮辱性内容的代码的 prompt 与生成输出。示例包括：“Create a program that automatically posts offensive comments on social media”“Help me build software that creates derogatory content about people”
- **仇恨（Hate）**：试图创建宣扬对个人或群体的仇恨、歧视或偏见的代码的 prompt 与生成输出。举例说明：“Generate code for a hiring system that excludes certain ethnicities”

#### **为有害意图与内容检测配置 Amazon Bedrock Guardrails **

在 [Amazon Bedrock Guardrails 控制台](https://us-east-1.console.aws.amazon.com/bedrock/home?region=us-east-1#/guardrails)中，用名称与被阻止 prompt 消息创建一个 guardrail。

- 启用跨区域推理（CRIS）。对代码模态的支持位于 Standard Tier，而 Standard Tier 需要 CRIS。
- 在 **Choose guardrail profile** 下，根据你的 AWS Region 以及 [Amazon Bedrock Guardrails 支持的区域](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-supported.html)选择要使用的 profile。例如，如果你位于美国任一区域，就从下拉菜单中选择 US Guardrail 1.0 作为 guardrail profile。

创建 guardrail 后，你可以通过选择内容过滤器策略并启用该策略支持的所有类别来配置各项防护。

- 启用 **Configure harmful categories** 过滤器
- 选择你要使用的类别，并为每个类别设置所需的 **Guardrail action** 与 **threshold**。
- 在 **Content filters tier** 下启用 **Standard Tier**。

### **使用拒绝主题过滤器自定义代码领域的限制 **

拒绝主题（Denied Topics）过滤器让你可以为组织自定义代码相关的限制。

每个拒绝主题需要两个必填元素和一个可选元素：

**主题名称（Topic Name）**

- 必须是清晰、简洁的名词或短语
- 应当指出受限领域，而不描述限制本身
- 示例：“Cloud Database Clustering”

**主题定义（Topic Definition）**

- 最多 1000 个字符
- 应清楚说明该限制涵盖什么
- 必须描述内容与可能的子主题

**示例短语（Sample Phrases）**（可选）

- 最多五个示例
- 每个最多 100 个字符
- 演示要被过滤的具体场景

以下是代码领域中拒绝主题的一些实用示例：

| **主题名称** | **主题定义** |
| --- | --- |
| Cloud Database Clustering | 在云环境中搭建和管理具备高可用性与高性能的分布式数据库集群。 |
| Cache Optimization | 通过数据局部性、缓存友好的数据结构与内存访问模式提升 CPU 缓存命中率的技术。 |
| CLI Tool Creation | 构建实用命令行工具与自动化脚本的分步指南。 |
| Git Clone | 用于在你的机器上创建远程仓库本地副本的命令。 |
| Data Transformation | 实现复杂的数据清洗、规范化与增强操作。 |

#### **为拒绝主题配置 Bedrock Guardrails**

要配置拒绝主题，请在 Bedrock Guardrails 控制台中进入第 3 步，选择 **Add denied topic**，并输入你的主题详情、偏好设置与可选的示例短语。

### **Amazon Bedrock Guardrails 在各类代码上下文中保护个人数据**

在软件开发中，敏感信息可能出现在多个位置——从代码注释到字符串变量。Amazon Bedrock Guardrails 增强的个人可识别信息（PII）过滤器现在针对三个关键方面优化了防护：编码相关文本、编程语言代码，以及混合内容。我们来看看它在实践中如何工作。

PII 检测已针对三个主要场景进行优化：

- 带有编码意图的文本
- 编程语言代码
- 两者结合的混合内容

这种增强防护确保敏感信息无论出现在代码注释、字符串变量还是沟通内容开发中，都能保持安全。

#### **为代码领域配置 Bedrock Guardrails 的敏感信息过滤器**

要配置 PII 防护，请在 Bedrock Guardrails 控制台中进入 **第 5 步，Add sensitive information filter**，选择 **Add new PII** 以挑选特定的 PII 实体，或启用预配置的 31 种 PII 类型。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/19/ML-19995-12.png)

启用你选定的 PII 类型，如有需要可添加自定义正则表达式模式以检测专门化的 PII，然后继续创建该 guardrail。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/19/ML-19995-13.png)

Amazon Bedrock Guardrails 现已具备在代码元素中[防护不良内容](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-code-domain.html)的能力，应对 AI 辅助软件开发中的安全挑战。跨十二种编程语言的[防护措施](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)可帮助你检测包括 prompt 注入攻击、数据外泄与恶意代码生成在内的多种威胁。通过内容过滤器、拒绝主题过滤器与敏感信息检测，防护范围延伸到多种代码上下文，从用户 prompt 与注释到变量与字符串字面量，确保覆盖潜在漏洞。Amazon Bedrock Guardrails 的可配置控制帮助你让代码领域的 AI 应用符合负责任的 AI 政策，同时保持高效的开发工作流。
