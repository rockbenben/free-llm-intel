# 使用 Amazon Bedrock Data Automation 处理财务文档

金融机构每天要处理成千上万份文档，包括税表、贷款对账单和采购订单。每份文档都有独特的格式、结构和字段名，因此使用光学字符识别（OCR）软件来构建自动化工作流颇具挑战。[Amazon Bedrock Data Automation](https://aws.amazon.com/bedrock/bda/)（BDA）通过自动完成财务文档中数据的抽取、校验和分析，帮助解决这些挑战。BDA 超越了简单的 OCR，它使用基础模型来：

- 理解文档上下文
- 识别不同章节之间的关系
- 抽取结构化、可操作的数据
- 跨多个来源校验信息

虽然 Anthropic Claude 等基础模型可以从 PDF 中[抽取内容](https://docs.anthropic.com/en/docs/build-with-claude/pdf-support)，但 Amazon Bedrock Data Automation 提供了[自定义抽取](https://aws.amazon.com/blogs/machine-learning/scalable-intelligent-document-processing-using-amazon-bedrock-data-automation/)，以更低的成本实现业界领先的准确率，并提供带置信度分数的视觉定位（visual grounding）以支撑可解释性，以及内置的幻觉缓解能力。

在本文中，我们探讨 Amazon Bedrock Data Automation 如何从四类常见的财务文档中准确抽取信息：银行对账单、W-2 表、1099-B 税表和供应商合同。我们会指出这些文档中的复杂性，详细介绍在 Amazon Bedrock Data Automation 中创建的自定义抽取，并描述抽取过程的结果。

## 解决方案概览

Amazon Bedrock Data Automation 让你可以使用 blueprint 根据处理需求配置输出。Amazon Bedrock Data Automation 中的 blueprint 是一个配置模板，定义应如何从文档中抽取数据。它规定了：

- 正在处理的文档类型
- 要抽取的数据字段
- 对抽取数据的校验规则
- 输出的结构和格式

你可以把它看作一张地图，准确告诉 Amazon Bedrock Data Automation 要查找哪些信息以及如何处理。使用 blueprint 进行抽取时，你可以使用目录中的 blueprint，也可以使用自定义创建的 blueprint。自定义 blueprint 让组织能够针对自身特定需求创建抽取模式。在本文中，我们创建了自定义 blueprint，并使用 BDA 控制台生成和校验输出。

## 如何为 4 类财务文档开发 blueprint

以下各节将带你为银行对账单、W-2 表、1099-B 表和供应商合同创建自定义 blueprint。

### 前提条件

- 具有相应 IAM 权限的有效 AWS 账户（[BDA 研讨会的示例策略](https://github.com/aws-samples/sample-document-processing-with-amazon-bedrock-data-automation)）
- 必须已获得模型访问权限（通过 AWS 控制台申请访问）
- 使用 [Amazon Bedrock 入门](https://docs.aws.amazon.com/bedrock/latest/userguide/getting-started.html)指南设置 Amazon Bedrock Data Automation
- 用于测试的示例财务文档

如果你不熟悉如何创建自定义 blueprint，请按照 [Amazon Bedrock 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/bda-blueprints-console.html)中的说明操作。在我们的评估中，我们在 BDA 控制台上传文档、优化 AI 生成的 prompt，并下载结果。通常，在抽取一致字段时，单个自定义 blueprint 就足以应对某一特定文档类型。不过，如果工作流需求不同，或文档格式发生显著变化，可能需要创建多个自定义 blueprint 来适应这些差异。创建 blueprint 后，你可以把它作为工作流的一部分，用于一致的下游处理。对于同一个 blueprint，如果输入文档的数据不同，BDA 可能返回略有差异的输出（例如，有些银行对账单可能包含借方和贷方总额）。不过，由于 BDA 输出是结构化 JSON，基于下游处理工作流创建相应规则很直接（例如，如果工作流是为会计目的对单笔借方和贷方交易分类，则丢弃总额）。

### 财务文档类型与自定义 blueprint

Amazon Bedrock Data Automation 为银行对账单和 W-2 表等常见文档类型提供内置 blueprint。这些内置 blueprint 开箱即用即可完成全面的抽取。在本文中，我们使用自定义 blueprint 来演示组织如何针对其特定工作流需求定制抽取。例如，你可以只从银行对账单中抽取交易数据用于自动化会计，或将 W-2 字段分组为与下游税务处理系统一致的逻辑结构（联邦税、州税、代码—金额对）。对于没有内置 blueprint 的文档类型，自定义 blueprint 也是可行的方法，例如本文后面展示的 1099-B 表和供应商合同。

**1. 银行对账单**——银行出具的文档，详细列示账户在特定期间（通常为一个月）内的财务活动，包括存款、取款和费用。

银行对账单带来一项复杂的挑战：它们包含大量月度交易，往往跨越多个页面，格式和细节各不相同。在许多工作流中，关键任务是精确捕获交易数据，包括日期、金额、描述和参考编号，这些数据随后可直接输入自动化会计工作流，例如在会计账簿中[对交易进行分类](https://quickbooks.intuit.com/learn-support/en-us/help-article/banking/categorize-match-online-bank-transactions-online/L1bTafTz3_US_en_US)。这种自动抽取能最大限度减少手工录入错误，并简化对账流程。作为评估流程的一部分，我们选取了以下银行对账单来试用抽取过程：

![用于抽取测试的示例银行对账单](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/05/ML-19347-3.png)

*使用 Amazon Nova Pro 基础模型生成的账户对账单*

**为 Amazon Bedrock Data Automation 定制的 blueprint 指令：**

```
Create a transaction log blueprint with the following structure:

Main Field:
- Transactions: [TRANSACTION_DETAILS]

Custom Type:
1. TRANSACTION_DETAILS type containing:
   - Date
   - Description
   - Debit: number
   - Credit: number
```

**2. W-2 表**——报告个人或企业的收入和预扣税款。

W-2 税表因其标准化却又复杂的结构，带来了独特的抽取挑战。作为评估流程的一部分，我们使用以下 W-2 表来试用抽取过程：

![用于抽取测试的示例 W-2 表](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/05/ML-19347-5.png)

*使用 Amazon Nova Pro 基础模型生成的 W2*

**为 Amazon Bedrock Data Automation 定制的 blueprint 指令：**

```
Create a detailed W2 form blueprint with the following structure:

Main Fields:
- employer_info: EmployerInfo
- employee_general_info: EmployeeInfo
- federal_tax_info: FederalTaxInfo
- federal_wage_info: FederalWageInfo
- filing_info: FilingInfo
- state_taxes_table: [StateTaxInfo]
- codes: [CodeAmount]
- nonqualified_plans_income: number
- other

Custom Types:
1. EmployerInfo type containing:
   - ein
   - employer_name
   - employer_address
   - employer_zip_code: number
   - control_number

2. EmployeeInfo type containing:
   - ssn
   - first_name
   - employee_last_name
   - employee_name_suffix
   - employee_address
   - employee_zip_code: number

3. FederalWageInfo type containing:
   - wages_tips_other_compensation: number
   - social_security_wages: number
   - medicare_wages_tips: number
   - social_security_tips: number

4. FederalTaxInfo type containing:
   - federal_income_tax: number
   - social_security_tax: number
   - medicare_tax: number
   - allocated_tips: number

5. StateTaxInfo type containing:
   - state_name
   - employer_state_id_number: number
   - state_wages_and_tips: number
   - state_income_tax: number
   - local_wages_tips: number
   - local_income_tax: number
   - locality_name

6. CodeAmount type containing:
   - code
   - amount: number

7. FilingInfo type containing:
   - omb_number
   - verification_code
```

经过审查，我们可以确认系统成功且准确地抽取了这些交易。项目中还专门验证了几项抽取难点：

- 表格上没有针对联邦税和州税信息的具体分组，但它们需要一起处理，因此抽取结果应把它们归并在一起。
- 在 W2 的单个 Box 12 中，最多可以有 26 个代码，用于报告某些薪酬和福利金额。以成对方式抽取代码和值很重要。
- 雇主几乎可以在 box 14 中填写任何内容。它有助于捕捉 W-2 上没有专属栏位的项目，因此这些内容应单独分组。
