# Cohere Health 如何使用 Amazon Bedrock AgentCore 实现临床策略数字化

预先授权（prior authorization）是健康计划在承保某些医疗服务或药物之前所要求的审批流程。它仍是医疗行业中最依赖人工的流程之一，原因不在于要求审批的医学推理存在缺陷，而在于治理该流程的策略被困在静态、非结构化的格式中，难以自动化。这类内容处于日常临床运营的核心，每年影响数亿患者。然而，策略内容会因临床领域、地域、业务线和健康计划而异，并随着医学和技术的进步而演进。历史上，健康计划没有系统化的方式来管理、分析和优化这些策略。使用标准术语把临床策略数字化为结构化、机器可读的数据，可以支持更一致、可计算的工作流，帮助健康计划在保持适当临床监督的同时大规模实现预先授权运营的现代化，从而缓解一个关键运营瓶颈。

[Cohere Health(R)](https://www.coherehealth.com/) 是一家为健康计划运营提供支撑的临床智能公司，它使用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 构建了 [Cohere Policy Studio(TM)](https://www.coherehealth.com/utilization-management/policy-studio)。AgentCore 为其健康计划客户提供了所需的多租户隔离，以及一个托管 agent 运行时，可在不重建基础设施的情况下加速部署。该应用采用灵活的多租户 agentic 架构，通过完善的工作流管理和自动版本跟踪来加速策略数字化。

本文介绍 Cohere Health 如何在 AgentCore 上构建多租户 agentic 架构：使用 [AgentCore Runtime 的安全 MicroVM 隔离](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html)、通过 [AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 实现统一的工具访问、[AgentCore Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html)，以及 [Agent Skills](https://agentskills.io) 开放标准，从而快速扩展策略数字化能力，同时保持透明度、版本控制和人工监督。

## 挑战：策略数字化瓶颈

要在预先授权中实现 AI 辅助工作流的价值，前提是解决一个基础性挑战：把困在静态文档和 PDF 中的规则转换为结构化、机器可读的数据，使 AI 系统能够更一致地使用这些数据，同时在需要临床判断的地方仍由医疗专业人员负责临床审查。健康计划在为支撑快速变化的要求而管理临床策略时面临复杂的挑战。自动化的策略数字化有助于健康计划适应这些变化。

Cohere Health 在为该工作流构建 AI 方案时识别出三个挑战：

- **政府法规**——根据 Centers for Medicare & Medicaid Services（CMS）的[法规](https://www.cms.gov/priorities/burden-reduction/overview/interoperability/policies-regulations/cms-interoperability-prior-authorization-final-rule-cms-0057-f)，健康计划必须在 2027 年 1 月之前支持基于 API 的电子预先授权。
- **America’s Health Insurance Plans（AHIP）**——[AHIP 承诺](https://www.coherehealth.com/thought-leadership/ahip-prior-authorization-commitments)要求健康计划对提交的电子预先授权实现 80% 的实时批准率。每条业务线都有各自独特的要求，这增加了快速管理、审计和部署临床策略的需求。
- **技术架构要求**——方案需要摄取多种输入格式，并为不同的下游消费者生成每条策略的不同表示形式，而每个消费者都有自己的反馈回路。

AgentCore 以托管运行时基础设施、会话隔离和统一的工具访问来应对这些挑战。

- 使用 [LangChain](https://www.langchain.com/) 部署包含 AgentCore Gateway 和 AgentCore Memory 的 AgentCore Runtime，构成完整的 agentic 系统。
- 配置 AgentCore Gateway 以获取工具和技能。

你可以运用同样的模式来构建自己的多租户 agentic 系统。

### 使用可复用的 Amazon Elastic Container Registry（Amazon ECR）基础镜像部署 AI agent

Cohere Health 服务于多个健康计划，这些客户要求租户之间严格的数据隔离。AgentCore Runtime 的安全 microVM 隔离通过为每个会话提供专用的计算、内存和文件系统资源来强制执行这一点。

在跨团队部署多个 AI agent 实例时，既要保持一致，又要允许定制，这很重要。每个团队都需要自己的 agent 配置，但为每次部署重建整个运行时环境会造成不必要的开销和漂移。你可以用下面的基础镜像模式，借助极简的 Dockerfile 把新的 agent 部署到 AgentCore Runtime microVM 上。

#### 基础镜像与消费者模式

Cohere Health 设计了一种两层部署架构，把稳定的运行时环境与团队专属配置分开：

```
FROM {account_id}.dkr.ecr.{aws_region}.amazonaws.com/cohere-agent:v1
COPY agent_config.yaml /app/src/agent_config.yaml
```

`FROM` 行拉取共享的基础镜像，其中包含 LangChain agent 框架和公共依赖。`COPY` 行添加团队专属的 `agent_config.yaml`，它控制以下选项：

- 内存模式——在无状态（`NO_MEMORY`）或持久化（`AGENTCORE`）的对话历史之间选择。
- 存储策略——纠错工作流使用 `full_trace`，需要干净的历史则使用 `conversation_only`。
- 会话上下文缓存——自动缓存技能定义和文档，避免重复的 Amazon Simple Storage Service（Amazon S3）拉取。
- prompt 缓存——通过缓存系统 prompt 和常用内容，有助于降低成本与延迟。
- 灵活的工具配置——按部署启用或禁用工具。
- 模型配置——使用 Amazon Bedrock 上的基础模型，可配置 token 上限、temperature 和其他推理参数。
- [LiteLLM](https://www.litellm.ai/) 配置——把 LiteLLM 配置为模型与 agent 之间的反向代理。

运行时部署完成后，下一步是把它连接到工具和技能。

### 借助 AgentCore Gateway 实现统一的工具与技能访问

Cohere Health 的 agent 会访问多种工具类型，包括用于获取技能和文档的 AWS Lambda 函数，以及由不同团队维护的内部 API。AgentCore Gateway 把它们整合在一个经过身份验证的端点之后，团队因此可以在不重新部署 agent 的情况下添加新工具。

#### AgentCore Gateway 架构

Cohere Health 使用 AgentCore Gateway 实现了这一点，为共享工具和项目专属工具设置了不同的目标。

##### 工具 Lambda 函数结构

AgentCore Gateway 会为每个工具请求调用一个 AWS Lambda 函数。该函数根据网关上下文中传入的工具名路由到正确的处理程序。

```
# jobs/generic-tools-lambda/app.py
import json
from tools.fetch_skill import handler as fetch_skill_handler

# Routing dictionary for tool discovery
TOOL_HANDLERS = {
    "fetch_skill": fetch_skill_handler
}

def lambda_handler(event, context):
    """Gateway-compliant Lambda handler with MCP routing"""

    # Extract tool name from gateway context
    tool_name = context.client_context.custom.get('bedrockAgentCoreToolName', '')

    # Strip gateway prefix (gateway adds {target}__ to tool names)
    if '__' in tool_name:
        tool_name = tool_name.split('__', 1)[1]

    # Route to appropriate handler
    if tool_name not in TOOL_HANDLERS:
        return {
            "statusCode": 404,
            "body": json.dumps({"error": f"Tool {tool_name} not found"})
        }

    try:
        result = TOOL_HANDLERS[tool_name](event)
        return {
            "statusCode": 200,
            "body": json.dumps(result)
        }
    except Exception as e:
        return {
            "statusCode": 500,
            "body": json.dumps({"error": str(e)})
        }
```

##### 工具实现

每个工具处理程序都从特定来源获取数据。下面的示例从 Amazon S3 获取技能定义。

```
# tools/fetch_skill.py
import boto3
import os

def handler(event: dict) -> dict:
    """Fetch skill definition from S3"""

    skill_id = event.get('skill_id')
    if not skill_id:
        return {"error": "skill_id required"}

    # Use environment variables for configuration
    bucket = os.environ.get('SKILLS_BUCKET')
    prefix = os.environ.get('SKILLS_PREFIX')

    s3 = boto3.client('s3')

    try:
        response = s3.get_object(
            Bucket=bucket,
            Key=f"{prefix}/{skill_id}.yaml"
        )
        content = response['Body'].read().decode('utf-8')

        return {"content": content}
    except Exception as e:
        return {"error": f"Failed to fetch skill: {str(e)}"}
```

##### agent 配置

agent 配置定义了 agent 可以访问哪些网关目标，以及它如何进行身份验证。

```
# agent_config.yaml
mcp:
  gateway_url: {gateway_url}
  allowed_targets:
    - generic-tools    # AIP-maintained tools
    - digitization-tools  # Project-specific tools
  auth_mode: "bearer_token"
```

运行时和工具就位后，Cohere Health 转而构建领域专业知识层。

### 技能开发与评估

AI agent 需要领域特定的知识才能有效执行专门任务。通用 prompt 会产生不一致的结果、消耗大量 token，并且缺乏领域专家所能带来的细致理解。传统上，每个新用例都需要从零重建 agent 基础设施，造成部署速度上的瓶颈。模块化的技能框架通过把领域专业知识与基础设施解耦来解决这个问题。对 Cohere Health 来说，这意味着临床策略专家可以直接编写和完善新技能，帮助确保系统以扎根于专家审查和治理的方式支撑策略工作流。

#### 模块化技能框架

团队通过模块化、带版本的技能定义来部署新能力，无需重建 agent。

#### 开发工作流

Cohere Health 遵循结构化的工作流，在每项技能进入生产之前对其进行开发和验证。

##### 评估流程

评估技能需要机器学习工程与数据科学之间的协作。流程从包含每项技能真值输出的参考数据集开始。团队定义成功指标（准确性、完整性和一致性），并针对这些测试用例运行评估套件。当某项技能未通过时，团队分析失败模式，在重新测试之前迭代技能定义。

某项技能通过评估套件后，数据科学团队会对照验收标准审查结果，并批准该技能投入生产部署。

部署之后，Arize AI 在生产环境中跟踪有效性指标。临床策略分析师会为样本输出做标注，以捕捉自动指标漏掉的错误。团队监控技能随时间出现的退化，并利用这些数据点来确定优化工作的优先级。

#### 技能版本管理与部署

技能通过分层版本方案和分阶段部署管道进入生产。

##### 双层版本管理

技能采用双层版本管理：用于跟踪能力变化的语义化版本，以及用于记录部署历史的 Amazon S3 对象版本。第一层跟踪 `SKILL.md` 中的能力变化，每个版本都在 git 中打上标签（例如 `skill/policy_ingestion/v1.2.3`）。Amazon S3 对象版本提供第二层，为每次上传维护不可变的历史，支持回滚能力，并区分非生产桶与生产桶。

##### 部署流程

- 开发人员提交代码并向 develop 分支发起 PR。
- 持续集成与持续交付（CI/CD）在合并时打包带元数据的 `skill.tar.gz`。
- 管道上传到 Amazon S3 非生产桶并更新清单。
- 在非生产环境中进行评估。
- 向 main 分支发起 PR。
- 以渐进式发布和监控的方式部署到生产环境。

## 结果与影响

通过这次实施，Cohere Health 在策略数字化速度、部署速度和覆盖范围方面都取得了可衡量的改善。

**策略数字化效率：** 花在策略数字化上的整体时间减少了 30%，从每条策略 2 小时 15 分钟降到 1 小时 35 分钟。迄今为止，Cohere Health 已使用人工和半自动化工作流数字化了数千条策略。随着基于 agent 的框架在现有策略库中扩展，它的目标是进一步缩短每条策略的处理时间。

**部署速度：** 产品中的完整 agent 部署从 3–4 个月缩短到 2–6 周。可复用的 ECR 基础镜像模式让团队只需极简的 Dockerfile 就能搭建新 agent，而模块化技能框架意味着新能力无需重建 agent 运行时即可交付。系统抽象掉了 DevOps 相关事项，因此传统的机器学习（ML）和数据科学工程师无需大量编码经验便能部署 agent。策略数字化产品运行的是单 agent、多技能架构，包含一个 agent、一个带子技能的主技能，以及三处参考注入。

**策略覆盖范围：** Cohere Policy Studio 以逐字文本加标准化的编码证据层来表示策略内容，两者打包在一起，并在原始策略的各种格式与来源中均可获得。

> “预先授权的策略审查一直要求极高水平的临床关注——策略文档中的每一个词都可能对患者产生下游后果。但这种关注历来被分散在解读和验证两件事上：不仅要理解某项策略在临床上意味着什么，还要确认是哪个版本支配了某次决定，以及该版本是否正是健康计划发布给提供方的那个版本。这些不是行政问题——它们直接关系到临床完整性。Amazon Bedrock AgentCore 给了我们同时应对两者的架构——AI 驱动的 agentic 工作流帮助驾驭临床语言的解释复杂性，内置的记忆和版本跟踪让来源追溯成为一等关注点，而不是事后补丁。结构化、带版本的策略输出使某项决定得以在临床上可追溯、可审查，而且这是设计自带的；AgentCore 安全的多租户运行时意味着我们可以在不牺牲隔离的前提下，向所服务的每一个健康计划交付这种能力。”

— Brian Covino，医学博士，FAAOS，Cohere Health 首席医疗官

把这些模式用于取得类似成效：用可复用的基础镜像实现一致的部署、用单一网关实现统一的工具访问，以及用模块化技能在不重建基础设施的前提下扩展。

## 未来：通过知识图谱连接策略

在 Cohere Policy Studio 于 AgentCore 上取得成功的基础上，下一步演进引入一张智能知识图谱，这项工作已经在推进中。Cohere Health 与 AWS Generative AI Innovation Center 合作，原型化了基础的语义层，把临床策略映射到标准化本体（UMLS、SNOMED），以使用标准化医疗术语支持更强的互操作性。借助 Amazon Neptune，这一层把策略概念夯实为 AI 可以遍历和追溯的结构。该图谱在扩展后的适应症范围内把临床策略与决策产品连接起来。

### 增强后的架构

知识图谱层位于策略表示引擎与下游决策系统之间，形成一个语义网络，它可以：

- **映射关系**：建立跨治疗领域的策略、临床指南、医疗编码（ICD-10、CPT、HCPCS）、药品目录和预先授权标准之间的关系。
- **扩展适应症覆盖**：通过识别跨临床领域的模式和相似性，让新的策略类型无需手工配置即可快速部署。
- **连接策略片段**：把策略片段连接到多个决策上下文，使单次策略更新能正确地传播到受影响的授权工作流。

### 关键能力

随着新策略通过 AgentCore 完成数字化，知识图谱被设计用来帮助识别相关连接、标记潜在冲突，并建议可复用的模式，以支撑审查人员和策略团队的工作流。图谱会从各临床领域的策略结构中学习，给出模板建议，并把新适应症类型的上线时间从数天缩短到数小时。决策引擎使用自然语言或 Fast Healthcare Interoperability Resources（FHIR）资源查询知识图谱，以获取可能相关的策略片段及其完整的来源追溯和版本历史。图谱还在 CMS 要求、AHIP 承诺和内部策略表示之间维护双向链接，从而在大规模上支持监管对齐。

这些能力带来全面的适应症覆盖，而无需等比例的工程投入；在相互连接的决策产品之间实现实时策略更新；通过自动化冲突检测帮助防止不一致的授权结果；并为授权请求提供亚秒级的策略检索。

这一知识图谱基础支撑了 Cohere Health 帮助健康计划实现 80% 电子预先授权实时批准的能力。图谱保持了当前 AgentCore 架构中已确立的安全性、多租户和审计能力。

## 结论

本文介绍了 Cohere Health 如何借助 AgentCore 和三项架构决策，把 AI agent 部署从数月缩短到数周。三种模式（可复用的 ECR 基础镜像、通过 AgentCore Gateway 实现的统一工具访问，以及模块化的技能开发）帮助 Cohere Health 在多种格式之上支撑了更具可扩展性的策略数字化工作流，同时把数字化时间减少了 30%。

ECR 基础镜像模式缓解了重复的基础设施工作，团队因此可以用极简的 Dockerfile 部署新 agent。Cohere Health 可以在不重建运行时的情况下扩展 AI 系统。AgentCore Gateway 架构为这些工具（无论它们是基于 AWS Lambda 的实用工具还是 OpenAPI 服务）提供单一的、经过身份验证的端点。技能框架构建在 Agent Skills 开放标准之上，把领域专业知识与 agent 机制分离，支持快速迭代，并通过 Arize AI 和临床策略分析师进行持续评估。

医疗 AI 的未来取决于能够快速适应变化的要求、同时保持可靠性和安全性的系统。借助 AgentCore 和这些架构模式，你今天就可以构建这样的系统。
