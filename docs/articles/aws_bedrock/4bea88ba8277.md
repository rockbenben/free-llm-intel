# 使用 Amazon Nova 2 Lite 进行目标检测

传统计算机视觉方案往往需要大量前期投入。搭建数据流水线、模型训练基础设施、计算资源，以及组建专职的数据科学团队，对小公司或团队来说常常难以承受。[Amazon Nova 2 Lite](https://aws.amazon.com/nova/) 可通过 Amazon Bedrock 使用，提供了一个很有吸引力的替代方案。这个多模态基础模型通过自然语言提示检测目标，无需任何训练。只要指定“vehicle”、“person”或“dent”，Nova 就会以结构化 JSON 格式返回精确的边界框坐标。

本文将带你实现使用 Amazon Nova 2 Lite 进行目标检测。你将了解如何使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/)、[AWS Lambda](https://aws.amazon.com/lambda/) 和 [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 部署一个目标检测应用，还将学习如何编写有效的提示、处理结构化 JSON 输出并对结果进行可视化。我们还会探讨制造业、农业和物流领域的实际应用。

## 解决方案概览

在开始之前，请确保你具备以下条件：

**AWS 账户与权限**

- 已启用 Amazon Bedrock 访问权限的有效 AWS 账户
- `bedrock:InvokeModel` 的 IAM 权限
- 在你所在区域对 Amazon Nova 2 Lite 模型的访问权限
- 已配置 AWS Command Line Interface (AWS CLI)（用于部署）

**开发环境**（用于本地测试）

- Python 3.8 或更高版本
- AWS SDK for Python (Boto3) 版本 1.28.0+
- Python Imaging Library (PIL/Pillow)

**安装：**

```
pip install boto3 pillow
```

**预计成本**

- Amazon Bedrock：每千个输入 token $0.0003，每千个输出 token $0.0025
- 典型图像：230 个输入 token（每张图约 $0.000069）与约 200 个输出 token（每张图约 $0.0005）
- 示例：10,000 张图像 ≈ $5.69
- AWS Lambda、Amazon API Gateway：按使用付费（测试时金额极小）

**预计用时：** 30-45 分钟

该目标检测方案通过四个主要步骤来识别并定位图像中的目标。

**步骤：**

- **提示工程** – 组织提示词，指定要检测的目标和期望的 JSON 输出格式
- **Amazon Bedrock** – 调用 Amazon Bedrock 访问 Amazon Nova 2 Lite，无需管理基础设施，并从响应中提取边界框信息
- **坐标处理** – 把 [Nova 的归一化坐标（0-1000 尺度）](https://docs.aws.amazon.com/nova/latest/userguide/modalities-image.html) 转换为像素位置
- **可视化** – 在图像上绘制边界框以进行校验

你通过 [Amazon Bedrock 的 Converse API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.html) 发送一张图像和一份待检测目标列表。Amazon Nova 2 Lite 分析图像，并返回包含每个被检测目标边界框坐标的 JSON 响应。然后你按图像尺寸把归一化坐标（0-1000 尺度）转换为像素位置。最后，你在原始图像上绘制边界框来实现可视化。

只需数小时即可部署目标检测——无需模型训练、机器学习（ML）专业知识或基础设施管理。

### 提示词

提示工程在实现准确检测方面起着重要作用。提示模板（如下例所示）包含一套精心编写的指令，明确了关键要求。模板中有两个变量：`elements` 和 `schema`，它们会根据要检测的目标类型动态构造，使该模板无需修改就能处理任意目标类别。

````
# Object Detection and Localization

## Objective

Your task is to detect and localize objects in the target image with high precision and recall.

## Instruction

- The objects to be detected are: {elements}

- Analyze the provided target image and return only the reasoning and a JSON object with bounding box data for detected objects

- Think step-by-step and then provide precise bounding box coordinates for each detection

- Detect all instances of the specified objects

- Fit bounding boxes tightly around each object

- Do not output duplicate bounding boxes

- Coordinates should use the format [x_min, y_min, x_max, y_max] where:

  * (x_min, y_min) is the top-left corner of the bounding box

  * (x_max, y_max) is the bottom-right corner of the bounding box

## Output Requirements and Examples

The JSON output should strictly follow this structure including the word json:

```json

{schema}

```

### Example JSON Structure:

```json

{{
"car": [{{
    "bbox": [321, 432, 543, 876],
}}],
"pedestrian": [{{
    "bbox": [432, 543, 654, 987],
}},
{{
    "bbox": [123, 234, 345, 678],
}}],
// Continue for all detected elements...
}}

```

Briefly explain the detection results and provide the specified JSON format wrapped within triple backticks.
````

完整的实现细节请参见我们的 [GitHub 仓库](https://github.com/aws-samples/sample-object-detection-nova-2-lite)。

## 在云上部署

Amazon Bedrock 为 Amazon Nova 2 Lite 提供 API 访问，这意味着你可以从任何 AWS 计算服务调用它。请选择最契合你工作负载的服务。

### 选择计算平台

对于事件驱动的工作负载和 API 端点，AWS Lambda 提供自动扩缩容和按调用付费的模式，消除了空闲成本。如果你需要对运行时环境有更多控制，或有长时间运行的进程，[Amazon Elastic Compute Cloud (Amazon EC2)](https://aws.amazon.com/ec2/) 让你可以完全灵活地按需配置实例。对于基于容器的部署并需要自动扩缩容的场景，请使用 [Amazon Elastic Container Service (Amazon ECS)](https://aws.amazon.com/ecs/) 或 [Amazon Elastic Kubernetes Service (Amazon EKS)](https://aws.amazon.com/eks/)。

无论你选择哪种计算服务，它们都调用同一个 Amazon Bedrock Converse API 来与 Nova 模型交互。这种一致性使得把目标检测集成到现有基础设施，或随着需求变化在计算平台之间迁移，都变得简单直接。

### 构建目标检测应用

我们构建了一个示例无服务器 Web 应用，用于展示 Amazon Nova 2 Lite 的目标检测能力。这个概念验证包含 Web 界面、安全的基础设施和自动扩缩容。你可以在几分钟内把它部署到自己的 AWS 账户。

该应用采用无服务器优先的架构，多个 AWS 服务协同工作。[Amazon CloudFront](https://aws.amazon.com/cloudfront/) 从私有的 Amazon Simple Storage Service (Amazon S3) 存储桶提供该单页应用，并通过源访问控制（Origin Access Control）实现全球分发和强制 HTTPS。当用户上传图像并指定要检测的目标时，前端把请求发送到 Amazon API Gateway，后者将其路由到 AWS Lambda 函数。

该 Lambda 函数充当编排层，调用 Amazon Bedrock 的 Converse API 把图像和检测提示发送给 Amazon Nova 2 Lite。Nova 返回每个被检测目标的归一化边界框坐标，Lambda 函数将其转换为像素位置，并在图像上渲染为标注框。标注后的结果沿同一路径返回：从 Lambda 到 API Gateway 再到前端。用户随后就能看到自己的图像中被检测到的目标被高亮标注。

Amazon CloudFront 在全球范围分发前端。API Gateway 把请求路由到 Lambda，Lambda 再调用 Amazon Bedrock 运行目标检测。该架构可自动扩缩容，并让每个组件只专注于一项职责。

## 实际应用

以下示例展示了 Amazon Nova 2 Lite 如何应用于各行各业的真实用例。

### 制造业质量控制

一家金属加工厂每月处理 10,000 个零件。每个流出工厂的缺陷零件会带来 50-200 美元的退货和返工成本。训练传统计算机视觉模型所需的高额前期投入，对其运营来说往往难以承受。

借助 Amazon Nova 2 Lite，该工厂实现了质量检验的自动化。他们指定“scratch”、“dent”或“rust spot”等缺陷，系统便会自动识别它们。每个零件分析 5 张图像，每月成本约 8 美元。

### 精准农业

一个 5,000 英亩的农场在 20 周的种植季里每周拍摄无人机图像，以便及早发现作物问题。及早发现可以避免过量施用化学品和作物损害。

该农场指定：“diseased leaf”、“pest damage”、“fungus”。每季处理 120 万张高分辨率图像的成本约为 200 美元。

同样的方法可让 GPS 制导设备检测障碍物（例如“vehicle”、“equipment”、“debris”），从而有可能实现自主田间作业。

### 物流与履约

配送中心通过指定“torn box”、“crushed package”、“water damage”来识别破损包裹。系统会自动标记待检验的物品并把它们路由到质量控制区域，确保各作业环节的标准一致。

这种方法还可扩展到库存监控（例如“empty shelf”、“misplaced item”）和安全合规（例如“hard hat”、“safety vest”、“safety glasses”），使任何规模的运营都能用上计算机视觉。
