# 使用 Amazon Bedrock 上的 Prompt Optimization 提升生成式 AI 应用的性能

Prompt 工程是指编写指令、以从基础模型（FM）获得期望响应的实践。为达到期望的输出，你可能需要花费数月时间实验和迭代你的 prompt，并遵循每个模型的最佳实践。此外，这些 prompt 是针对特定模型和任务的，当它们被用于不同的 FM 时，性能无法保证。prompt 工程所需的这种人工投入，会拖慢你测试不同模型的速度。

今天，我们很高兴宣布 [Prompt Optimization](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-management-optimize.html) 已在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上可用。借助这项能力，你现在只需一次 API 调用，或在 Amazon Bedrock 控制台上点一下按钮，就能为多种用例优化你的 prompt。

本文通过一个示例用例讨论如何开始使用这项新功能，并讨论一些性能基准测试结果。

## 解决方案概览

撰写本文时，Amazon Bedrock 的 Prompt Optimization 支持对 Anthropic 的 Claude 3 Haiku、Claude 3 Sonnet、Claude 3 Opus 和 Claude-3.5-Sonnet 模型，Meta 的 Llama 3 70B 和 Llama 3.1 70B 模型，Mistral 的 Large 模型以及 Amazon 的 Titan Text Premier 模型进行 Prompt Optimization。Prompt Optimization 可为生成式 AI 任务带来显著改善。我们针对若干任务进行了一些示例性能基准测试，并在此讨论。

在接下来的几节中，我们演示如何使用 Prompt Optimization 功能。在我们的用例中，我们想优化一个 prompt，让它查看通话或聊天记录，并对下一步最佳行动进行分类。

## 使用自动 prompt 优化

要开始使用这项功能，请完成以下步骤：

- 在 Amazon Bedrock 控制台上，在导航窗格中选择 [**Prompt management**](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-management.html)。
- 选择 **Create prompt**。
- 为你的 prompt 输入名称和可选描述，然后选择 **Create**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/20/image1-3.jpeg)

- 在 **User message** 中，输入你想优化的 prompt 模板。

例如，我们想优化一个 prompt，让它查看通话或聊天记录，并把下一步最佳行动分类为以下之一：

- 等待客户输入
- 分配 agent
- 升级处理

以下截图展示了我们的 prompt 在 prompt 构建器中的样子。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/20/image2-4.jpeg)

- 在 **Configurations** 窗格中，为 **Generative AI resource** 选择 **Models**，然后选择你偏好的模型。本例中我们使用 Anthropic 的 Claude 3.5 Sonnet。
- 选择 **Optimize**。

会弹出一个提示框，表明你的 prompt 正在被优化。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/20/image3-1.jpeg)

优化完成后，你应该会看到针对你的用例的原始 prompt 与优化后 prompt 的并排对比视图。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/20/image4-3.jpeg)

- 为你的测试变量（本例中为 `transcript`）添加值，然后选择 **Run**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/29/image5-1-1.jpg)

随后你就可以看到模型以期望格式给出的输出。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/29/ML-17782-Picture21.png)

从这个例子可以看到，优化后的 prompt 更加明确，清楚说明了如何处理作为变量提供的原始记录。这带来了符合所需输出格式的正确分类。prompt 优化完成后，可以通过创建版本（即对其配置创建快照）把它部署到应用中。可以存储多个版本，以便在不同用例的 prompt 配置之间切换。有关 prompt 版本控制与部署的更多细节，请参阅 [prompt management](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-management-deploy.html)。

我们在多个开源数据集上运行了 Prompt Optimization 功能。我们很高兴分享在我们观察到客户常用的一些重要用例中所取得的改进：

- 摘要（[XSUM](https://huggingface.co/datasets/EdinburghNLP/xsum)）
- 基于 RAG 的对话续写（[DSTC](https://github.com/alexa/dstc11-track5)）
- 函数调用（[GLAIVE](https://huggingface.co/datasets/glaiveai/glaive-function-calling-v2)）

## 结论

Amazon Bedrock 上的 [Prompt Optimization](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-management-optimize.html) 让你只需一次 API 调用，或在 Amazon Bedrock 控制台上点几下，就能毫不费力地提升 prompt 在广泛用例中的性能。在摘要、对话续写和函数调用等任务的开源基准上所展示的大幅改进，凸显了这项新功能显著简化 prompt 工程流程的能力。Amazon Bedrock 上的 Prompt Optimization 让你能够轻松地为生成式 AI 应用测试许多不同的模型，并遵循每个模型的最佳 prompt 工程实践。人工投入的减少，将大大加速你组织中生成式 AI 应用的开发。
