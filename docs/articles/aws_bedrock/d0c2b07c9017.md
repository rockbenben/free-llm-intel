# 使用 Terraform 构建基于 Amazon Bedrock 与 Amazon Transcribe 的 AI 自动摘要系统

从非结构化数据中提取有价值的洞察，对许多组织而言是重大挑战。会议录音、客户互动与访谈中蕴含着极具价值的商业情报，但由于人工审阅的时间和资源成本过高，这些情报在很大程度上仍难以获取。组织常常难以高效地捕捉并利用这些交互中的关键信息，结果不仅造成生产力缺口，也错失了利用关键决策信息的机会。

本文介绍一个无服务器会议摘要系统，它借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 与 [Amazon Transcribe](https://aws.amazon.com/transcribe/) 的先进能力，把音频录音转换为简洁、结构化、可执行的摘要。通过把这一流程自动化，组织可以省回无数小时，同时确保关键洞察、行动项与决策被系统地记录，并让利益相关方能够获取。

许多企业已把基于 [Terraform](https://developer.hashicorp.com/terraform) 的基础设施即代码（IaC）实践作为标准，往往还写进组织政策。这些实践通常源于以下需要：跨环境的一致性、与现有持续集成与持续交付（CI/CD）pipeline 的无缝集成，以及与更广泛 DevOps 策略的一致。对这些组织而言，用 Terraform 实现 AWS 方案有助于它们在采用新技术的同时维持治理标准。随着组织认识到自动化、版本受控的基础设施部署带来的好处，企业对 IaC 的采用仍在快速增长。

本文通过提供一个无服务器音频摘要系统的完整 Terraform 实现来满足这一需求。借助该方案，组织可以在维持基础设施治理标准的前提下部署 AI 驱动的会议摘要方案。其业务收益十分可观：缩短会议后续跟进时间、改善知识共享、一致地跟踪行动项，以及跨历史会议内容检索的能力。团队可以专注于落实会议成果，而不必为记录和分发会议内容而费力，从而加快决策并提升组织协同。

## **什么是 Amazon Bedrock 与 Amazon Transcribe？**

Amazon Bedrock 是一项全托管服务，通过单一 API 提供来自领先 AI 公司的高性能基础模型（FM）供你选择，例如 [AI21 Labs](https://aws.amazon.com/bedrock/ai21/)、[Anthropic](https://aws.amazon.com/bedrock/anthropic)、[Cohere](https://aws.amazon.com/bedrock/cohere/)、[DeepSeek](https://aws.amazon.com/bedrock/deepseek)、[Luma](https://aws.amazon.com/bedrock/luma-ai/)、[Meta](https://aws.amazon.com/bedrock/llama/)、[Mistral AI](https://aws.amazon.com/bedrock/mistral/)、[poolside](https://aws.amazon.com/bedrock/poolside/)（即将推出）、[Stability AI](https://aws.amazon.com/bedrock/stability-ai/)、[TwelveLabs](https://aws.amazon.com/bedrock/twelvelabs/)（即将推出）、[Writer](https://aws.amazon.com/bedrock/writer) 与 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/)，并提供一整套广泛能力，帮助你以兼顾安全、隐私与负责任 AI 的方式构建生成式 AI 应用。借助 Amazon Bedrock，你可以针对自身用例试验并评估顶尖 FM，使用微调与检索增强生成（RAG）等技术以自有数据定制模型，并构建能利用企业系统与数据源执行任务的 agent。

Amazon Transcribe 是一项全托管的自动语音识别（ASR）服务，让开发者可以轻松为应用添加语音转文本能力。它由下一代、参数规模达数十亿的语音 FM 驱动，能为流式与录制语音提供高准确率的转写。各行业成千上万的客户用它自动化人工任务、挖掘丰富洞察、提升可访问性，并增强音视频内容的可发现性。

## **方案概览**

我们这套完整的音频处理系统整合了多项强大的 AWS 服务，构成一个无缝的端到端方案，用于从音频内容中提取洞察。该架构由两个主要部分组成：一个易用的前端界面，负责客户交互与文件上传；以及一个后端处理 pipeline，负责把原始音频转换为有价值的结构化信息。这一无服务器架构带来可扩展性、可靠性与成本效益，同时提供富有洞察力的 AI 驱动分析能力，且无需专门的基础设施管理。

前端工作流包含以下步骤：

- 用户通过基于 React 的前端上传音频文件，该前端使用 [Amazon CloudFront](https://aws.amazon.com/cloudfront/) 面向全球分发。
- [Amazon Cognito](https://aws.amazon.com/cognito/) 为用户提供安全的身份认证与授权。
- 应用通过 [AWS AppSync](https://aws.amazon.com/appsync/) GraphQL API 获取会议摘要与统计数据，该 API 会调用 [AWS Lambda](https://aws.amazon.com/lambda) 函数执行查询。

处理流程包含以下步骤：

- 音频文件存储在 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）存储桶中。
- 当音频文件被上传到 Amazon S3 的 audio/{user_id}/ 前缀下时，S3 事件通知会向 [Amazon Simple Queue Service](https://aws.amazon.com/sqs/)（Amazon SQS）队列发送消息。
- SQS 队列触发一个 Lambda 函数，由它启动处理工作流。
- [AWS Step Functions](https://aws.amazon.com/step-functions/) 编排整个转写与摘要工作流，并内置错误处理与重试。
- Amazon Transcribe 以高准确率完成语音转文本。
- 使用 FM（具体为 Anthropic 的 Claude）生成完整、结构化的摘要。
- 结果同时存储在 Amazon S3（原始数据）与 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/)（结构化数据）中，以实现持久化与快速检索。

为进一步加强安全，[AWS Identity and Access Management](https://aws.amazon.com/iam) 帮助管理身份以及对 AWS 服务与资源的访问。

我们的方案使用 Terraform，以一致、可重复的方式定义并预置 AWS 基础设施。主 Terraform 配置负责编排各个模块。以下代码展示了其中三个：

# Orchestration Module - Step Functions
module "orchestration" {
  source = "./modules/orchestration"
  
  aws_region                              = var.aws_region

### **使用 Amazon Bedrock 完成摘要**

摘要组件由 Amazon Bedrock 驱动，它提供对前沿 FM 的访问。我们的方案使用 Anthropic 的 Claude 3.7 Sonnet version 1 生成完整的会议摘要：

`prompt = **f**"""Even if it is a raw transcript of a meeting discussion, lacking clear structure and context and containing multiple speakers, incomplete sentences, and tangential topics, PLEASE PROVIDE a clear and thorough analysis as detailed as possible of this conversation. DO NOT miss any information. CAPTURE as much information as possible. Use bullet points instead of dashes in your summary.`
`IMPORTANT: For ALL section headers, use plain text with NO markdown formatting (no #, ##, **, or * symbols). Each section header should be in ALL CAPS followed by a colon. For example: "TITLE:" not "# TITLE" or "## TITLE".`

`CRITICAL INSTRUCTION: DO NOT use any markdown formatting symbols like #, ##, **, or * in your response, especially for the TITLE section. The TITLE section MUST start with "TITLE:" and not "# TITLE:" or any variation with markdown symbols.`

`FORMAT YOUR RESPONSE EXACTLY AS FOLLOWS:`

`TITLE: Give the meeting a short title 2 or 3 words that is related to the overall context of the meeting, find a unique name such a company name or stakeholder and include it in the title `

`TYPE: Depending on the context of the meeting, the conversation, the topic, and discussion, ALWAYS assign a type of meeting to this summary. Allowed Meeting types are: Client meeting, Team meeting, Technical meeting, Training Session, Status Update, Brainstorming Session, Review Meeting, External Stakeholder Meeting, Decision Making Meeting, and Problem Solving Meeting. This is crucial, don't overlook this.`

### **前端实现**

### **安全考量**

安全是我们方案的首要事项，我们通过以下措施加以保障：

- 用户身份认证由 Amazon Cognito 处理
- API 访问通过 Amazon Cognito 用户池进行保护
- S3 存储桶访问仅限通过认证的用户
- IAM 角色遵循最小权限原则
- 数据在静态存储与传输中均加密
- Step Functions 提供安全的编排与恰当的错误处理

### **使用 Amazon Bedrock 的优势**

对会议摘要系统而言，Amazon Bedrock 提供了几项关键优势：

- **可访问前沿模型**——Amazon Bedrock 提供对 Anthropic 的 Claude 3.7 Sonnet version 1 等领先 FM 的访问，无需训练定制模型即可获得高质量摘要能力。
- **全托管集成**——Amazon Bedrock 与其他 AWS 服务无缝集成，可支撑完全无服务器的架构，并随需求自动扩缩容。
- **成本高效**——按需（On-Demand）计价意味着只为实际处理时间付费，对波动的工作负载颇具成本效益。
- **安全与合规**——Amazon Bedrock 维持数据隐私与安全，确保敏感的会议内容在你的 AWS 环境中受到保护。
- **可定制的 prompt**——能够编写详细的 prompt，就允许产出贴合需求的摘要，精确提取组织需要从会议中获得的信息。Amazon Bedrock 还提供 [prompt 管理](https://aws.amazon.com/es/bedrock/prompt-management/) 与 [优化](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-management-optimize.html)，以及用于快速原型的 [playground](https://docs.aws.amazon.com/bedrock/latest/userguide/playgrounds.html)。
- **多语言支持**——Amazon Bedrock 可处理多种语言的内容，适合全球化组织。
- **缩短开发时间**——预训练模型将对大量 AI 开发专业知识和基础设施的需求降到最低。
- **持续改进**——Amazon Bedrock 提供模型选择，用户只需改动一个字符串即可更新现有模型。

- 对 Terraform 与 AWS 服务有基本了解

以下各节将带你逐步部署会议音频摘要方案。

### **克隆仓库**

首先，克隆包含 Terraform 代码的仓库：

```
git clone https://github.com/aws-samples/sample-meeting-audio-summarizer-in-terraform
cd sample-meeting-audio-summarizer-in-terraform
```

### **配置 AWS 凭证**

请确认你的 AWS 凭证已正确配置。你可以使用 AWS CLI 设置凭证：

```
aws configure --profile meeting-summarizer
```

系统会提示你输入 AWS access key ID、secret access key、默认 AWS Region 与输出格式。

### **安装前端依赖**

要搭建前端开发环境，请进入 frontend 目录并安装所需依赖：

```
cd frontend
npm install
```

### **创建配置文件**

切换到 terraform 目录：

```
cd ../backend/terraform/  
```

用你自己的取值更新 `backend/terraform` 目录中的 `terraform.tfvars` 文件。该配置为先前在 `variables.tf` 文件中定义的变量提供取值。

你可以按需定制 `variables.tf` 中定义的其他变量。在 `terraform.tfvars` 文件中，你为 `variables.tf` 中声明的变量提供实际取值，从而无需修改核心配置文件即可定制部署：

```
aws_region                              = "us-east-1"                                  
aws_profile                             = "YOUR-AWS-PROFILE"                           
environment                             = "prod"                                       
app_name                                = "meeting-audio-summarizer"                   
dynamodb_read_capacity                  = 5                                            
dynamodb_write_capacity                 = 5                                            
cognito_allowed_email_domains           = ["example.com"]                              
model_id                                = "anthropic.claude-3-7-sonnet-20250219-v1:0"  
inference_profile_prefix                = "us"                                         
frontend_bucket_name                    = "a-unique-bucket-name"                       
storage_bucket                          = "a-unique-bucket-name"                       
cognito_domain_prefix                   = "meeting-summarizer"                         
meeting_statistics_table_name           = "MeetingStatistics"                          
meeting_summaries_table_name            = "MeetingSummaries"  
```

对于 `a-unique-bucket-name`，请选择一个有意义且对你有直观含义的唯一名称。

### **初始化并应用 Terraform**

进入 terraform 目录并初始化 Terraform 环境：

```
terraform init
```

要把先前选定的插件升级到符合配置版本约束的最新版本，请使用以下命令：

```
terraform init -upgrade
```

这会让 Terraform 忽略依赖锁文件中记录的选定版本，改取符合已配置版本约束的最新可用版本。

**审阅计划中的改动：**

```
terraform plan
```

**应用 Terraform 配置以创建资源：**

```
terraform apply
```

出现提示时输入 yes 以确认部署。你也可以运行 terraform apply -auto-approve 来跳过确认问题。

### **部署方案**

后端部署完成后，使用提供的部署脚本部署整个方案：

```
cd ../../scripts
sudo chmod +x deploy.sh
./deploy.sh
```

该脚本处理整个部署过程，包括：

- 使用 Terraform 部署后端基础设施
- 用后端资源信息自动配置前端
- 构建并部署前端应用
- 建立 CloudFront 分发
- 使 CloudFront 缓存失效，确保对外提供最新内容

## **清理资源**

要清理该方案，你必须运行此命令。

```
terraform destroy
```

该命令会彻底移除 Terraform 在你的环境中预置的 AWS 资源。执行时，它会显示一份详细计划，列出将被销毁的资源，并在继续之前提示确认。由于它要按正确的依赖顺序系统地移除基础设施组件，该过程可能耗时数分钟。

*记得检查 AWS 控制台，确认销毁已彻底完成，没有仍在运行的可计费资源。*

## **成本考量**

成本的主要部分来自 Amazon Transcribe（约占总成本的 73%，为 $72.00），AWS AppSync 是第二大成本项（约占 20%，为 $20.00）。Amazon Bedrock 虽提供核心 AI 功能，却只约占总成本的 3%（$3.00），DynamoDB、CloudFront、Lambda、Step Functions、Amazon SQS 与 Amazon S3 合计占其余 4%。

我们可以利用以下成本优化机会：

- 实施音频压缩以降低存储与处理成本
- 对医疗类会议使用 Amazon Transcribe Medical（如适用）以获得更高准确率
- 为高频访问的摘要实施缓存策略，以降低 AppSync 与 DynamoDB 成本

## **后续步骤

会议摘要方案的下一阶段将引入多项先进 AI 技术，以交付更大的业务价值。[Amazon Sonic Model](https://aws.amazon.com/blogs/aws/introducing-amazon-nova-sonic-human-like-voice-conversations-for-generative-ai-applications/) 可以通过更好地处理多位说话人、口音与专业术语来提升转写准确率——这正好解决了团队多元的全球化组织的一大痛点。同时，[Amazon Bedrock Flows](https://aws.amazon.com/bedrock/flows/) 可以通过实现会议自动归类、基于角色的摘要定制，以及与公司知识库集成以提供相关上下文，来增强系统的分析能力。这些改进能帮助组织提取原本会湮没在对话中的可执行洞察。

加入实时处理能力，可以帮助团队在会议进行中即时看到关键要点、行动项与决策，便于当场澄清并减少后续追问。增强的分析功能会长期跟踪会议之间的模式，让管理层看清沟通有效性、决策过程与项目进展。通过与日历、每日议程、任务管理系统和通信服务等现有生产力工具集成，该方案确保会议情报直接流入日常工作流，最大限度减少人工搬运信息，并确保关键洞察在各部门推动切实的业务成果。

## **结论**

我们的会议音频摘要器把 AWS 无服务器技术与生成式 AI 结合，解决一项关键的生产力挑战。它会自动转写并摘要会议内容，为组织省下数千小时，同时确保洞察与行动项被系统地记录并与利益相关方共享。

该无服务器架构能随会议量的波动轻松伸缩，平均每场会议仅需 $0.98，并将基础设施管理与维护开销降到最低。Amazon Bedrock 提供企业级 AI 能力，无需专门的机器学习专业知识或大量开发资源；而基于 Terraform 的基础设施即代码则支持跨环境快速部署、按组织特定要求定制，并与现有 CI/CD pipeline 无缝集成。

随着生成式 AI 领域持续演进、更强的新模型不断出现，该方案完成任务的能力也会在性能与准确率上自动提升，而无需额外开发投入，从而改善摘要质量、语言理解与上下文感知。这使会议音频摘要器成为现代企业日益重要的资产——对那些希望优化会议工作流、加强知识共享并提升组织生产力的企业尤其如此。
