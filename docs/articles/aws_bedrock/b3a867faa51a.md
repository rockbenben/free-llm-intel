# 通过 Amazon Bedrock 托管知识库中的表格搜索从表格中获取答案

[Amazon Bedrock 托管知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-build-management.html) 现在支持表格搜索，因此您可以通过代理检索从表格中获取答案。当问题需要 CSV、XLSX 或 XLS 文件中的数据时，表格搜索会查找值并在一个或多个表格或工作表中的每个相关行上运行计算。然后，它将结果与相关文档中的事实相结合，以回答需要几个步骤的分析问题。

财务团队在季度末需要知道“哪些部门必须编写差异评论？”没有一个文件能给出答案。它取决于差异政策的阈值、季度结算备忘录的预算修订以及损益 (P&L) 工作簿中每个部门的数学。

就像这个财务团队一样，大多数团队将他们的叙述和数据保存在同一个地方。例如，Microsoft SharePoint 网站将工作簿放在策略旁边，而 [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/s3/) 存储桶将 CSV 导出放在 PDF 旁边。表格搜索通过您已用于文档的相同“AgenticRetrieveStream”请求回答这些文件中的问题。它在隔离沙箱中的原始文件上运行代码，因此答案使用整个表而不是仅检索返回的行。对于财务团队来说，一项请求会返回必须撰写评论的部门。答案引用了策略和备忘录，跟踪命名了代码读取的工作簿。

在这篇文章中，您将了解表格搜索如何回答需要表格数据和文档事实的问题，以及何时使用其他工具更合适。您还可以使用示例财务文件构建知识库，并使用跟踪来查看代码读取了哪个文件。

## 为什么表很难检索

检索增强生成 (RAG) 返回与问题最匹配的固定数量的段落，这对于散文非常有效。当表格被分成段落时，它们会丢失信息，其方式取决于表格的形状：

- **长表 –** 包含数千行的表跨越许多段落，检索仅返回与问题最匹配的少数内容。根据它们构建的答案使用少量行，因此总计、比较或阈值检查可能不完整。
- **宽表 –** 在具有数百列的表中，一行可以容纳的文本比一段段落或搜索模型一次容纳的文本还要多。因此，后面列中的值更难匹配。宽表中的长段落还可以匹配许多不相关的问题，并从结果中推出更相关的段落。

检索还必须将问题与正确的表相匹配。问题使用业务术语，例如“可控支出”，但表格包含成本中心代码、帐户名称和号码。草稿和最终工作簿在搜索时看起来几乎相同。赋予数字含义的规则通常位于单独的文档中，例如政策。

因此，表格搜索会分散工作。检索只需从右表文件中返回一段内容，然后代码读取整个表。由于检索仍然必须首先找到该文件，因此在问题中命名该文件会有所帮助。

表 1 显示了简单检索和表格搜索如何处理财务团队的问题“哪些部门必须编写差异注释？”

| **比较** | **仅检索** | **通过表格搜索进行代理检索** |
| --- | --- | --- |
|你得到什么 |政策、备忘录、业务回顾和工作簿中的段落，但没有完整的答案 |一个名为销售、工程和运营的答案，以及每个部门与其修订后预算的差异|
|修订后的方差百分比 |无法使用。没有文件存储它们，因此没有段落可以包含它们 |根据最终工作簿中的每个部门行计算 |
|来源 |每个段落都链接到其自己的文件，但没有一个包含答案 |引用财务政策和关闭备忘录。跟踪命名代码读取的工作簿 |

## 表格搜索在代理检索中的工作原理

在[代理检索](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-agentic-retrieve.html)中，代理使用检索来确定哪些文档重要，然后写入答案。表格搜索是该流程的一部分，因此无需打开任何内容。

当问题需要表中的数据时，请求会经历以下阶段：

- **检索 –** 段落返回，包括表文件中的段落。
- **计划 –** 代理使用问题和表结构来确定是否在一个或多个检索到的表上运行代码。
- **阶段 –** 表格搜索将原始文件复制到没有网络访问权限的隔离沙箱中。
- **计算 –** 模型编写的代码在整个表格或工作表上运行。
- **返回 –** 代理仅返回代码打印的内容，例如总计或匹配行。
- **回答 –** 代理根据结果和段落进行回答，并附有引文。

当检索的段落来自 CSV、XLSX 或 XLS 文件并且问题需要跨行计算或查找特定值时，表格搜索就会开始。

### 知识库、连接器和 API

一个“AgenticRetrieveStream”请求可以搜索一个或多个知识库。 “Retrieve” API 不断返回段落并且不运行代码。

无论哪个连接器将文件引入知识库，表格搜索的工作方式都是相同的，包括 Amazon S3、Microsoft SharePoint、Atlassian Confluence 等。

### 范围和权衡

表格搜索是为需要计算或查找其检索的表格文件的问题而构建的。运行代码至少会增加一个代理轮次，因此使用表数据的答案比纯文本答案需要更长的时间。受管理的指标、重复仪表板、仓库规模的联接和报告控制仍然属于您的商业智能 (BI) 工具。表格搜索适用于存储在文档旁边的表文件，并且您无需定义架构。

## 将文件上传到 Amazon S3

将表文件和相关文档放在一个前缀下。

- 打开 Amazon S3 控制台并选择 **创建存储桶**。
- 输入全局唯一的存储桶名称（本文使用“amzn-s3-demo-bucket”），保持选中“阻止所有公共访问”，然后选择“创建存储桶”。
- 选择存储桶，选择**创建文件夹**，然后输入“finance”。
- 打开“finance”文件夹并选择“**上传**”。
- 选择 **添加文件**，选择您的表格文件和文档，然后选择 **上传**。

## 创建知识库和数据源

知识库需要 Amazon Bedrock 可以承担的 IAM 角色。此信任策略仅允许“bedrock.amazonaws.com”服务主体，并且仅允许您帐户中的知识库。
```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "BedrockKnowledgeBaseAssume",
      "Effect": "Allow",
      "Principal": {"Service": "bedrock.amazonaws.com"},
      "Action": "sts:AssumeRole",
      "Condition": {
        "StringEquals": {"aws:SourceAccount": "111122223333"},
        "ArnLike": {
          "aws:SourceArn": "arn:aws:bedrock:<region>:111122223333:knowledge-base/*"
        }
      }
    }
  ]
}
```
接下来，设置剩余资源：

- 使用信任策略创建名为“kb-finance-role”的角色。
- 附加一个内联策略，允许在存储桶上使用“s3:ListBucket”，并在其对象上使用“s3:GetObject”。
- 使用托管嵌入模型创建“MANAGED”类型的知识库。
- 为存储桶创建“MANAGED_KNOWLEDGE_BASE_CONNECTOR”数据源，仅限于“finance/”前缀。
- 将“maxFileSizeInMegaBytes”设置为高于最大文件。

步骤 2 的内联策略仅允许读取此存储桶：
```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListBucket",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::amzn-s3-demo-bucket",
      "Condition": {"StringEquals": {"aws:ResourceAccount": "111122223333"}}
    },
    {
      "Sid": "ReadObjects",
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::amzn-s3-demo-bucket/*",
      "Condition": {"StringEquals": {"aws:ResourceAccount": "111122223333"}}
    }
  ]

```
此脚本运行步骤 3 到 5 并打印 ID：
```
import time
import boto3

agent = boto3.client("bedrock-agent")

kb = agent.create_knowledge_base(
    name="finance-kb",
    roleArn="arn:aws:iam::111122223333:role/kb-finance-role",
    knowledgeBaseConfiguration={
        "type": "MANAGED",
        "managedKnowledgeBaseConfiguration": {"embeddingModelType": "MANAGED"},
    },
)
kb_id = kb["knowledgeBase"]["knowledgeBaseId"]

# Wait until the knowledge base is ACTIVE before adding a data source.
status = "CREATING"
while status in ("CREATING", "UPDATING"):
    time.sleep(10)
    status = agent.get_knowledge_base(knowledgeBaseId=kb_id)["knowledgeBase"]["status"]
if status != "ACTIVE":
    raise RuntimeError(f"Knowledge base status is {status}")

ds = agent.create_data_source(
    knowledgeBaseId=kb_id,
    name="finance-s3",
    dataSourceConfiguration={
        "type": "MANAGED_KNOWLEDGE_BASE_CONNECTOR",
        "managedKnowledgeBaseConnectorConfiguration": {
            "connectorParameters": {
                "type": "S3",
                "version": "1",
                "connectionConfiguration": {
                    "bucketName": "amzn-s3-demo-bucket",
                    "bucketOwnerAccountId": "111122223333",
                },
                "filterConfiguration": {
                    # In MB. Set this above your largest table.
                    "maxFileSizeInMegaBytes": "200",
                    "inclusionPrefixes": ["finance/"],
                },
                "aclEnabled": False,
            }
        },
    },
    vectorIngestionConfiguration={
        "parsingConfiguration": {"parsingStrategy": "SMART_PARSING"}
    },
)
print("knowledge base:", kb_id, "data source:", ds["dataSource"]["dataSourceId"])
```
## 同步数据源并检查文件类型

仅当知识库分配正确的文件类型时，表格搜索才能启动，因此请在第一次同步后检查文件类型。

- 启动数据源的摄取作业。
- 轮询作业，直到其状态为“COMPLETE”。
- 查看失败文档的作业统计信息。
- 针对您的问题运行“检索”调用。
- 确认表格段落将“_file_type”显示为“CSV”（对于 CSV 文件）或“MS_EXCEL”（对于 XLSX 和 XLS 文件）。

第一个脚本运行步骤 1 到 3：
```
import time
import boto3

agent = boto3.client("bedrock-agent")
KB_ID, DS_ID = "<your-knowledge-base-id>", "<your-data-source-id>"

job_id = agent.start_ingestion_job(knowledgeBaseId=KB_ID, dataSourceId=DS_ID)[
    "ingestionJob"]["ingestionJobId"]
while True:
    job = agent.get_ingestion_job(
        knowledgeBaseId=KB_ID, dataSourceId=DS_ID, ingestionJobId=job_id
    )["ingestionJob"]
    if job["status"] in ("COMPLETE", "FAILED", "STOPPED"):
        break
    time.sleep(15)
print(job["status"], job.get("statistics"), job.get("failureReasons"))
```
第二个脚本运行步骤 4 和 5，以便您可以在使用代理检索询问问题之前检查表文件类型。对于您自己的文件，提出一个问题，将您的一个文档中的规则与表上的计算配对，并命名两者。
```
import boto3

runtime = boto3.client("bedrock-agent-runtime")
question = (
    "In fiscal Q2 of FY2026, which cost center had the largest overspend in "
    "controllable spend, as the finance policy defines it? Compare the Actuals "
    "and Budget sheets of the FY2026 P&L workbook and give the cost center and "
    "the overspend in US dollars."
)
response = runtime.retrieve(
    knowledgeBaseId="1234567890",
    retrievalQuery={"text": question},
    retrievalConfiguration={"managedSearchConfiguration": {"numberOfResults": 10}},
)
for result in response["retrievalResults"]:
    print(result["metadata"].get("_file_type"), result.get("documentId"))
```
## 跨表和文档提出问题

通过 `AgenticRetrieveStream` 发送相同的问题。该脚本打印答案、每个“CodeExecution”状态以及代码读取的文件。
```
import boto3

runtime = boto3.client("bedrock-agent-runtime")
question = (
    "In fiscal Q2 of FY2026, which cost center had the largest overspend in "
    "controllable spend, as the finance policy defines it? Compare the Actuals "
    "and Budget sheets of the FY2026 P&L workbook and give the cost center and "
    "the overspend in US dollars."
)

response = runtime.agentic_retrieve_stream(
    messages=[{"role": "user", "content": {"text": question}}],
    retrievers=[{"configuration": {"knowledgeBase": {"knowledgeBaseId": "1234567890"}}}],
    agenticRetrieveConfiguration={
        "foundationModelType": "MANAGED",
        "rerankingModelType": "MANAGED",
    },
)

for event in response["stream"]:
    if "traceEvent" in event:
        attributes = event["traceEvent"]["attributes"]
        # CodeExecution steps report IN_PROGRESS, then SUCCEEDED or FAILED.
        if attributes.get("step") == "CodeExecution":
            print(attributes["status"], attributes.get("message"))
        # A Planning event lists the files the code will read.
        for action in attributes.get("actions", []):
            for doc in action.get("codeExecution", {}).get("documents", []):
                print("code read:", doc["documentId"])
    elif "responseEvent" in event:
        print(event["responseEvent"]["text"], end="")
```
对于这些文件，答案将两个工作簿表与两个文档结合起来：

- **来自文件。** 财务政策将可控支出定义为承包商、差旅、软件和营销计划账户，其中不包括工资和设施。业务回顾解释了主要差异。
- **从表格中。** 代码使用“实际值”和“预算”表中的每一行，筛选财务第二季度和四个帐户，然后比较成本中心。
- **回答。** CC-3010（平台）超出了 124,559.90 美元，实际支出为 394,859.90，而预算为 270,300.00。业务审查将差异归因于为数据平台迁移引入的承包商。计算每个运营费用帐户的结果是 133,434.05。

## 读取跟踪

跟踪事件按以下顺序到达：

- **Planning.** 状态为“SUCCEEDED”的“Planning”事件包含一个“codeExecution”操作，用于命名代码将读取的文档。
- **代码步骤。** 状态为“IN_PROGRESS”的“CodeExecution”事件（“在 1 个文档上运行代码”），然后是状态为“SUCCEEDED”的事件。 “SUCCEEDED”消息命名代码读取的每个文件及其大小。
- **答案。** 第二轮规划和响应文本先于包含引文的最终“结果”事件。引文指向答案所使用的段落，因此代码读取的表格文件并不总是在其中。

在此示例中，“规划”事件仅命名最终工作簿，因为政策和业务审查作为检索到的段落到达。
```
{
  "traceEvent": {
    "attributes": {
      "step": "Planning",
      "status": "SUCCEEDED",
      "message": "Agent planning completed",
      "actions": [
        {
          "retrieve": {},
          "codeExecution": {
            "documents": [
              {
                "documentId": "s3://amzn-s3-demo-bucket/finance/anycompany-pnl-fy2026.xlsx",
                "sourceRetriever": {"identifier": "1234567890"}
              }
            ]
          }
        }
      ]
    }
  }
}
```
对于较长的调用，流每 10 秒重复一次“IN_PROGRESS”事件，因此不会触发读取超时。无法完成的代码步骤会报告“FAILED”，代理通常会重试或回退。

表格搜索作为响应生成的一部分运行，默认情况下处于启用状态，因此脚本未设置“generateResponse”。如果将“generateResponse”设置为 false，代理将返回检索结果而不运行代码。有关详细信息，请参阅[代理检索](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-agentic-retrieve.html)。

## 尝试更多问题

以下每个问题还将文档与工作簿配对。

### 将备忘录修订应用于季度总计

这个问题需要一个只有在备忘录修改后才存在的预算：
```
Did total operating expense for fiscal Q3 of FY2026 stay within the Q3 budget
as revised in the Q3 close memo? Give the actual Q3 operating expense, the
revised Q3 budget and the difference, in US dollars.
```
答案使用备忘录中的修订以及工作簿中的第三季度实际值和原始预算。修订后的预算支出为 49,572.40 美元，因此答案是肯定的，尽管相同的支出超出了原始预算。简单的“检索”返回备忘录和工作簿段落，但它们都不包含这些数字。

### 预算修改后应用政策阈值

以下是财务团队引言中问题的完整版本。它需要政策的门槛、备忘录的修订和工作簿：
```
Applying the budget revisions approved in the Q3 close memo, which
departments must write variance commentary for fiscal Q3 of FY2026 under
the finance policy?
```
当差异超过批准预算的 5%（包括批准的修订）时，该政策需要进行评论，并且备忘录批准营销增加和工程削减。答案是销售（-6.50%）、工程（+5.79%）和运营（+6.20%）。工程跨越门槛只是因为批准的削减降低了预算。

### 继续对话

表格搜索也适用于多轮对话。在“消息”中发送较早的轮次，它会在需要该表的轮次中运行。第一个问题要求从工作簿中进行计算：
```
Calculate the Customer Support department's actual operating expense and its
budget for fiscal Q2 of FY2026 from the Actuals and Budget sheets of the final
FY2026 P&L workbook, in US dollars.
```
对于后续操作，发送第一个问题及其答案（`"role": "assistant"`），以及 `messages` 中的新问题：
```
Under the finance policy, does that variance need written commentary, and does
anyone besides the Controller have to review it?
```
差异超出预算 12.40%，因此需要书面评论。由于超过 10%，该政策还需要首席财务官 Nikki Wolf 的审核。在这里，第一轮通常在工作簿上运行代码，第二轮回答历史记录中的策略问题。

对于较长的会话，您可以通过在请求上设置“memoryConfiguration”将对话历史记录保留在 Amazon Bedrock AgentCore 内存资源中，而不是重新发送之前的会话。有关详细信息，请参阅[代理检索](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-agentic-retrieve.html)。

## 表格问题的最佳实践

小心地表达你的问题，因为检索会选择代码读取的表。指出其来源的重点问题有助于检索选择正确的表格。

- **将一条规则与一张表配对。** 命名包含该规则的文档，例如“按照第三季度结束备忘录中的修订”。
- **当存在多个版本时，为文件命名。** 例如，“使用最终的 2026 财年损益工作簿，anycompany-pnl-fy2026.xlsx。”
- **需要计算时要求计算。** 如果汇总表包含数字，代理可以从中回答。说“计算每个部门与实际值和预算表的差异”以根据详细信息行进行计算。
- **提出有针对性的问题。** 在几个回合中建立更大规模的分析。

一些数据和应用程序选择也有帮助：

- **将表格保留在 CSV、XLSX 或 XLS 文件中。** 首先从 PDF 或 Word 文档导出表格。
- **将文件大小过滤器设置在最大的表格上方。** 大于“maxFileSizeInMegaBytes”的文件不会被摄取，因此代码无法读取它们。
- **将 Excel 工作表保持在 200 MB 以内。** 截至撰写本文时，表格搜索在最大 500 MB（摄取限制）的 CSV 文件上运行代码，但在最大 200 MB 的 Excel 工作表上运行代码。您仍然可以提取较大的 Excel 文件，因此在依赖全表计算之前请检查工作表大小。
- **使用表格搜索进行分析。**运行代码会增加代理轮次，因此请保留简单的“检索”以在文本中快速查找。
- **具有元数据过滤器的范围文件。** `retrievalOverrides` 下的过滤器（例如 `_document_title` 上的过滤器）控制代码可以读取哪些文件。
- **使用跟踪进行审核。** 根据设计，生成的代码不会返回，因为它可以回显单元格值。跟踪显示代码读取了哪些文件。

## 清理

为了避免持续产生费用，请按顺序删除这些资源：

- 在 Amazon Bedrock 控制台中，选择 **知识库**，然后选择 `finance-kb`。
- 选择“finance-s3”数据源并选择“**删除**”。
- 删除`finance-kb`知识库。
- 在 Amazon S3 控制台中，选择存储桶，选择 **空**，然后选择 **删除**，除非其他工作负载使用它。
- 在 IAM 控制台中，选择 **角色**，选择 `kb-finance-role`，然后选择 **删除**。

如果您使用存储库中的 AWS CDK 应用程序进行部署，请从其“infra”文件夹运行“npx cdk destroy”，而不是执行这些步骤。它会删除堆栈创建的所有内容。

## 结论

财务团队成员需要知道“哪些部门必须写差异注释？”通过 Amazon Bedrock 托管知识库中的表格搜索，您可以通过一个同时使用工作簿、策略和备忘录的代理检索请求来回答该问题。

在这篇文章中，您了解了表格搜索如何回答需要表格数据和文档事实的问题，以及何时使用其他工具更合适。您还构建了一个包含示例财务文件的知识库，并使用跟踪来查看代码读取了哪个文件。
