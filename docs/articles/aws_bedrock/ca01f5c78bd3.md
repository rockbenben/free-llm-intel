# 在 SageMaker Unified Studio 中使用 Amazon Bedrock 快速构建生成式 AI 应用

构建[生成式 AI](https://aws.amazon.com/ai/generative-ai/) 应用对组织而言意味着重大挑战：它需要专门的 ML 专业知识、复杂的基础设施管理，以及对多个服务的细致编排。为应对这些挑战，我们推出 [Amazon Bedrock in SageMaker Unified Studio](https://aws.amazon.com/bedrock/ide)，这是一个用于开发和定制生成式 AI 应用的集成环境。Amazon Bedrock in SageMaker Unified Studio 此前称为 Amazon Bedrock Studio，现已并入 [Amazon SageMaker Unified Studio](https://aws.amazon.com/sagemaker/unified-studio/)（目前处于预览阶段）。SageMaker Unified Studio 把包括 [Amazon Bedrock](https://aws.amazon.com/bedrock/)、[Amazon SageMaker](https://aws.amazon.com/sagemaker)、[Amazon Redshift](https://aws.amazon.com/redshift/)、[Amazon Glue](https://aws.amazon.com/glue/)、[Amazon Athena](https://aws.amazon.com/athena/) 和 [Amazon Managed Workflows for Apache Airflow (MWAA)](https://aws.amazon.com/managed-workflows-for-apache-airflow/) 在内的多种 AWS 服务，整合成一个全面的数据与 AI 开发平台。在这篇博客文章中，我们将聚焦 Amazon Bedrock in SageMaker Unified Studio 及其在 Amazon SageMaker Unified Studio 环境中的生成式 AI 能力。

设想一个跨多个区域和国家运营的全球零售网站。它的销售分析师每天都面临一个挑战：他们需要做出数据驱动的决策，却被庞大的可用信息量所淹没。他们拥有存储在数据库中的结构化数据，例如销售交易和收入指标；同时还有从各个渠道收集的非结构化数据，例如客户评论和营销报告。这些分析师既不具备专门的结构化查询语言（SQL）知识，也不具备检索增强生成（RAG）专长，因此难以有效地把两类来源的洞察结合起来。

在本文中，我们将展示公司里任何人都能如何使用 Amazon Bedrock in SageMaker Unified Studio 快速创建一个生成式 AI 聊天 agent 应用，用来分析销售业绩数据。通过简单的对话，业务团队就能用该聊天 agent 从结构化和非结构化数据源中提取有价值的洞察，而无需编写代码或管理复杂的数据管道。下图展示了使用 Amazon Bedrock in SageMaker Unified Studio 的 AI 助手的概念架构。

![SageMaker Unified Studio simple architecture diagram ](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16903-simple-arch-diag.png)

## 解决方案概览

该 AI 聊天 agent 应用通过 Amazon Bedrock in SageMaker Unified Studio 把结构化与非结构化数据分析结合起来：

- **对于结构化数据**：连接到 Amazon Athena 中的销售记录，把自然语言转换为 SQL 查询
- **对于非结构化数据**：使用 [Amazon Titan Text Embeddings](https://aws.amazon.com/bedrock/amazon-models) 和 [Amazon OpenSearch](https://aws.amazon.com/opensearch-service/) 在客户评论和营销报告中启用语义搜索

Amazon Bedrock in SageMaker Unified Studio 的界面会无缝整合来自这两类来源的结果，提供全面的洞察，而用户无需了解底层的数据结构或查询语言。下图展示了从用户初始交互到最终响应的流程。关于用户交互流程的更多细节，请查看我们配套的 [GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-ide-genai-demo)。

### 先决条件

在 Amazon Bedrock in SageMaker Unified Studio 中创建应用之前，你需要在 AWS 账户中设置一些资源。这会预置销售分析应用所依赖的后端基础设施与服务，包括设置 [Amazon API Gateway](https://aws.amazon.com/api-gateway)、[AWS Lambda](https://aws.amazon.com/lambda) 函数和 Amazon Athena，以便查询结构化的销售数据。

- 部署所需的 AWS 资源：在你偏好的 AWS 区域中启动 [AWS CloudFormation](https://aws.amazon.com/pm/cloudformation/) 堆栈：
[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16903-sc-07.png)](https://us-east-1.console.aws.amazon.com/cloudformation/home?region=us-east-1#/stacks/quickcreate?templateUrl=https://aws-blogs-artifacts-public.s3.us-east-1.amazonaws.com/artifacts/ML-16903/cloudformation.yaml) 堆栈部署完成后，从 CloudFormation 的 outputs 选项卡记下 API Gateway URL 的值：`TextToSqlEngineAPIGatewayURL`。前往 [AWS Secrets Manager](https://console.aws.amazon.com/secretsmanager/) 控制台，找到密钥 `*<StackName>*-api-keys`。选择 **Retrieve secret**，并从明文串 `{"clientId":"default","allowedOperations":["query"],"apiKey":"xxxxxxxx"}` 中复制 `apiKey` 的值。

稍后在设置 Amazon Bedrock in SageMaker Unified Studio 函数时，你会用到这些值。

- 下载全部三个示例数据文件。这些文件包含由生成式 AI 模型生成的合成数据，其中包括客户评论、客户问卷答复以及全球新闻，你将用它们来构建知识库：[product-reviews.txt](https://github.com/aws-samples/amazon-bedrock-ide-genai-demo/blob/main/knowledge_base_example_files/product-reviews.txt) – 来自用户的产品特定评论 [survey-response.txt](https://github.com/aws-samples/amazon-bedrock-ide-genai-demo/blob/main/knowledge_base_example_files/survey-responses.txt) – 通过问卷调查收集的用户反馈 [world-news.txt](https://github.com/aws-samples/amazon-bedrock-ide-genai-demo/blob/main/knowledge_base_example_files/world-news.txt) – 近期的行业与经济新闻
- 下载 API 配置：[openapi_schema.json](https://github.com/aws-samples/amazon-bedrock-ide-genai-demo/blob/main/openapi_schema/openapi_schema.json)。在设置用于查询销售数据的函数时，你会用到这个文件。

就是这样！这些资源准备好之后，你就可以创建自己的销售分析应用了。后续每一节都会准确告诉你何时以及如何使用这些文件。

### 聊天 agent 的指令配置

进入 Amazon Bedrock in SageMaker Unified Studio 的聊天 agent 应用。从下拉菜单中选择模型（之后可以更改——请确保它支持数据和函数）。在聊天 agent 的 instructions 字段中，输入：

```
You are a Sales Analytics agent with access to sales data in the "sales" database, table "sales_records". Your tasks include analyzing metrics, providing sales insights, and answering data questions.
Table Schema:
- region, country: Location data
- item_type: Product category
- sales_channel: Online/Offline
- order_priority: H/M/L/C
- order_date, ship_date: Timing
- order_id: Unique identifier
- units_sold: Quantity
- unit_price, unit_cost: Price metrics
- total_revenue, total_cost, total_profit: Financial metrics.
Use Amazon Athena SQL queries to provide insights. Format responses with:
	1	SQL query used
	2	Business interpretation
	3	Key insights/recommendations
You can also access sales-repo which contains details on products categories, customer reviews, etc.
Error Handling:
- If the user's query cannot be translated into a valid SQL query, or the SQL is invalid or fails to execute, provide a clear and informative error message.
```

该指令会引导 AI 应用充当销售分析 agent，除了访问产品评论和其他销售相关数据之外，还会基于给定的销售数据 schema 提供结构化响应。

![Chat agent application building view](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16903-sc-08.png)

对于这个应用，你将创建两个主要组件：一个用于处理非结构化数据的知识库，以及一个使用 Amazon Athena 查询结构化数据的函数。这些组件将协同工作，为你的生成式 AI 应用处理和检索信息。

### 创建知识库

知识库让你的应用能够分析客户评论和新闻故事等非结构化数据。

- 在当前聊天 agent 屏幕上选择 **Data** 部分。
- 选择 **Create new Knowledge Base**，并为你新建的知识库输入名称。你还需要为聊天 agent 输入一段简短描述，以便它理解该知识库的用途：

`This contains product-specific reviews from users, user feedback gathered via survey, and recent industry and economic news`

- 在配置知识库数据源时，你有两个选项：使用本地文件，或配置 Web 爬虫。网页抓取会自动从你有权限访问的公开网页中提取内容。通过把网站 URL 添加到该工具，它会爬取这些站点，并基于所有已定义的 URL 创建知识库。这一过程让你能够高效地从多个网络来源收集并结构化信息，为你的需求构建全面的数据集。

在本文中，你将上传此前提到的包含非结构化数据的文件（`product-reviews.txt`、`survey-response.txt` 和 `world-news.txt`）。

- 选择 **Click to upload**，上传这三个文件。保留默认的解析设置。
- 对于 embeddings 模型，选择 **Amazon Titan Text Embeddings V2** 或任何其他 embeddings 模型。
- 选择 **OpenSearch Serverless** 作为你的向量存储。
- 完成这些选择后，选择 **Create** 创建知识库。
- 知识库创建完成后，在 **Select** **Knowledge Base** 下拉菜单下为你的应用选择它。

这些非结构化数据将用于增强生成式 AI 应用的知识库，使其能够基于客户评论、问卷答复以及与你的业务领域相关的当前新闻进行处理并提供洞察。

![Create Knowledge Base](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16903-sc-09.png)

要验证非结构化数据连接是否正常工作，请把下面这个示例 prompt 提交到应用中。请注意，生成式 AI 系统是非确定性的，因此每次的响应不会完全相同。

**Prompt：**

```
What is the customer sentiment surrounding our Office Supplies products?
```

**预期响应：**

```
Based on the customer reviews and feedback, the sentiment surrounding our Office Supplies products is mixed. While there are many positive reviews praising the product selection, store environment, and helpful staff, there are also a significant number of negative reviews citing issues like:

Poor product quality (e.g. flimsy materials, inconsistent paper quality, adhesive issues)

Frustrating in-store experiences (e.g. long wait times, rude staff, messy/disorganized stores)

Problems with online ordering and apps (e.g. filters not working properly, payment issues, logging out repeatedly)

To improve customer sentiment, we should focus on addressing these common pain points through better quality control, more efficient inventory management and staffing, and improving the online/app user experience.
```

### 创建函数

在本节中，你将创建一个函数，它会与 Amazon API Gateway 交互以查询数据库，随后把请求转发给 Lambda 函数，后者从 [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/s3) 检索数据并使用 Amazon Athena 处理 SQL 查询。相关 AWS 基础设施已作为 CloudFormation 模板的一部分部署完成。该结构化数据集包含 2010 年至 2017 年期间产品的订单信息。这些历史数据将让函数能够分析这七年间的销售趋势、产品表现和其他相关指标。应用将使用该函数集成结构化数据分析能力，从而能够基于具体销售数据以及已纳入的评论和新闻等非结构化数据提供洞察。

- 在你的 Amazon Bedrock in SageMaker Unified Studio 聊天 agent 应用中，展开屏幕上的 **Functions** 部分。选择 **Create New Function**。
- 为函数输入名称并提供描述。
- 对于函数 schema，选择 **Import JSON/YAML**。从你此前下载的 `openapi_schema.json` 文件中导入 API schema。
- 重要：导入之后，你需要修改 schema 中的 API 端点 URL。把它替换为 CloudFormation 堆栈输出 `TextToSqlEngineAPIGatewayURL` 中的实际值。这一步确保你的函数正确链接到应用相应的 API 端点。

![Create a function ](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16903-sc-10.png)

- 对于 **Authentication method**，选择 **API Keys (Max. 2 Keys)** 并填写以下细节：密钥发送位置：Header 密钥名称：`x-api-key` 密钥值：填入 Amazon Secrets Manager 中的 `apiKey` 值。
- 选择 **Create**，等待函数创建完成。
- 函数创建完成后，在 **Functions** 下拉菜单下为你的应用选择它。

![Create a function confirmation ](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/27/ML-16903-sc-11.png)

要验证结构化数据连接是否正常工作，请把以下示例查询提交到应用中。请注意，生成式 AI 系统是非确定性的，因此每次的响应不会完全相同。

**Prompt：**

```
List all the regions that we do business in.
```

**预期响应：**

```
Based on the query to get distinct region values from the sales_records table, the regions where we do business are:
Europe
Australia and Oceania
North America
Central America and the Caribbean
Sub-Saharan Africa
Middle East and North Africa
Asia
```

应用构建完成后，你可以通过 SageMaker Unified Studio 与组织中的其他用户共享它。

- 在应用界面中，找到并选择右上角的 **Share**。

用户必须拥有有效的 SageMaker Unified Studio 访问凭证才能使用共享的应用。如果用户遇到访问问题，请联系你的 AWS 管理员。

## 示例

以下示例展示了某全球零售网站如何使用这一解决方案改造其销售分析流程并提取有价值的洞察。让我们来看看三类能够体现这种方法威力的查询：

- 分析结构化数据以了解销售业绩
- 分析非结构化客户反馈以提取洞察
- 结合两类数据源实现全面的商业智能

在下面的示例中，我们将展示销售分析师如何通过基础的对话式查询提取有价值的洞察。

请记住，生成式 AI 系统是非确定性的，因此每次的响应不会完全相同。生成式 AI 系统还可能产生幻觉信息，应当注意评估响应的正确性。此外，结构化数据源在下载时是随机生成的，因此我们的结果不一定彼此吻合。你可以访问 Amazon S3 中的 CSV 数据源手动评估结果。我们的示例使用了 Anthropic Claude 3 Sonnet 模型，但欢迎你尝试其他模型。

### 结构化数据示例

可查询的功能列如下：Region、Country、Item Type、Sales Channel、Order Priority、Order Date、Order ID、Ship Date、Units Sold、Unit Price、Unit Cost、Total Revenue、Total Cost 和 Total Profit。数据覆盖七个区域和一百多个国家，包含以下商品类型：Baby Food、Beverages、Cereal、Clothes、Cosmetics、Fruits、Household、Meat、Office Supplies、Personal Care、Snacks 和 Vegetables。

**Prompt 1：**

```
What region accounts for our highest revenue, and how much revenue is that?
```

**预期响应 1：**

```
The region that accounts for our highest revenue is "Sub-Saharan Africa" with a total revenue of $356,724,250.12.
```

**Prompt 2：**

```
Which 3 item types account for our most units sold?
```

**预期响应 2：**

```
The 3 item types that account for our most units sold are:
Beverages with 504,905 units
Personal Care with 475,724 units
Vegetables with 471,276 units
```

### 非结构化数据示例

以下示例展示了几个可用于查询非结构化数据的自然语言 prompt。这些查询的目标是查询文本数据以回答问题并找出共同主题。

可查询的数据包括来自用户的产品特定评论、通过问卷调查收集的线上与线下反馈，以及近期的行业与经济新闻。

**Prompt 1：**

```
Search our customer surveys to see if customers seem to prefer our online or offline shopping experience
```

**预期响应 1：**

```
Based on the customer survey results from the knowledge base, there seems to be a preference for the in-store/offline shopping experience over the online experience (website and mobile app). 
The in-store reviews frequently mention positive aspects like helpful staff, clean stores, good product selection and organization. In contrast, the online reviews cite many issues with the website and mobile app like slow loading times, crashes, poor search functionality, and difficulties during checkout. 
While there are some positive online reviews as well, the negative experiences seem more prevalent for the online channels compared to the offline in-store experience.
```

**Prompt 2：**

```
Were there any major world events in 2016 affecting the sale of Vegetables?
```

**预期响应 2：**

