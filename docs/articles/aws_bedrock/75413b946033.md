# Aetion 如何用生成式 AI 与 Amazon Bedrock 解锁患者群体中的隐藏洞见

*本文由 Aetion 的 Javier Beltrán、Ornela Xhelili 与 Prasidh Chhabri 共同撰写。*

从患者诊疗历程中采集并推导出的真实世界数据，为洞察患者特征与结局，以及医疗创新的有效性与安全性，提供了丰富的信息。研究人员以结构化查询的形式提出关于患者群体的问题；然而，如果没有选对结构化查询，又缺乏对复杂真实世界患者数据集的深入了解，许多趋势与模式可能一直不为人所发现。

[Aetion](https://aetion.com/) 是一家领先的供应商，为生物制药企业、支付方和监管机构提供决策级真实世界证据软件。该公司为医疗健康与生命科学客户提供全面的解决方案，把真实世界数据转化为真实世界证据。

在半结构化数据上使用无监督学习方法，再结合[生成式 AI](https://aws.amazon.com/generative-ai/)，在解锁隐藏洞见方面带来了变革性的效果。借助 [Aetion Discover](https://aetion.com/products/discover/)，用户可以基于真实世界数据开展快速的探索性分析，同时以结构化的方式处理研究问题。为帮助加速数据探索与假设生成，Discover 采用无监督学习方法挖掘出 Smart Subgroups。这些亚组是更大群体中具有相似特征或画像的患者，其相似性横跨诊断、手术与治疗等大量因素。

本文将介绍 Aetion 的 Smart Subgroups Interpreter 如何让用户通过自然语言查询与 Smart Subgroups 交互。该解释器由 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和 [Anthropic 的 Claude 3](https://aws.amazon.com/bedrock/claude/) 大语言模型（LLM）驱动，能够回答用户以对话式语言提出的关于患者亚组的问题，并提供洞见以生成进一步的假设与证据。Aetion 之所以选择用 Amazon Bedrock 来处理 LLM 相关的工作，是因为它汇聚了来自多家提供商的丰富模型选择，并且在安全态势、可扩展性和易用性方面表现出色。

Amazon Bedrock 是一项完全托管的服务，通过统一的 API 提供对来自领先 AI 初创公司和 Amazon 的高性能[基础模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)（FM）的访问。它提供种类繁多的 FM，让你可以挑选最适合自身具体用例的模型。

## Aetion 的技术

Aetion 运用因果推断科学，就药物与临床干预的安全性、有效性和价值生成真实世界证据。Aetion 已与前 20 大生物制药企业中的大多数、领先的支付方以及监管机构建立合作。

Aetion 为美国、加拿大、欧洲和日本的生命科学机构、监管机构（包括 FDA 和 EMA）、支付方以及卫生技术评估（HTA）客户带来深厚的科学专业能力与技术，其分析能力可实现以下目标：

- 通过识别目标人群、创建外部对照组，并为受控环境中代表性不足的场景与人群补充背景信息，来优化临床试验
- 通过标签变更、定价、报销覆盖范围和处方集决策，扩大行业可及性
- 针对药物、治疗手段和诊断产品开展安全性与有效性研究

Aetion 的应用（包括 Discover 和 Aetion Substantiate）由 Aetion Evidence Platform（AEP）驱动。AEP 是一个核心的纵向分析引擎，能够对数以亿计的患者诊疗历程应用严谨的因果推断与统计方法。

AetionAI 是一组生成式 AI 能力，嵌入在核心环境和各个应用之中。Smart Subgroups Interpreter 是 Discover 中的一项 AetionAI 功能。

## Smart Subgroups

针对用户指定的患者群体，Smart Subgroups 功能会识别出具有相似特征的患者聚类（例如诊断、手术和治疗的发生率分布相似）。

这些亚组随后由生成式 AI 模型根据每个亚组的主要特征进一步分类并打上标签。例如，如下图所示生成的热力图，在接受 GLP-1 激动剂处方的患者群体中，前两个 Smart Subgroups 分别被标记为“白内障与视网膜疾病”和“炎症性皮肤状况”，以概括其界定性特征。

![Smart Subgroups](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/21/ML-17577-smart-subgroups.png)

亚组展示出来之后，用户可以借助 AetionAI，用自然语言提出的问题进一步探查。用户可以就这些亚组提出问题，例如“白内障疾病亚组中患者最常见的特征是什么？”如下图所示，AetionAI 会以自然语言回复用户，并在回答中引用相关的亚组统计数据。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/27/ML-17577-ui-1-resized-1.png)

用户也可以向 AetionAI 提出更细致的问题，例如“比较‘Dulaglutide’组与总体人群中心血管疾病或状况的发生率。”下图展示了 AetionAI 的回答。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/27/ML-17577-ui-2-resized.png)

在这个例子中，这些洞见让用户可以提出假设：使用 Dulaglutide 的患者可能出现的循环系统体征和症状更少。他们可以在 Aetion Substantiate 中进一步探索，通过因果推断产出决策级证据，以评估 Dulaglutide 使用对心血管疾病结局的效果。

## 解决方案概览

Smart Subgroups Interpreter 将无监督机器学习的要素与生成式 AI 结合，以发现在真实世界数据中隐藏的模式。下图展示了工作流程。

下面我们逐步详细说明：

- **创建患者群体** – 用户使用 Aetion Measure Library（AML）特征来定义患者群体。AML 特征库使用经科学验证的算法对变量定义进行标准化。用户选择用于定义待分析患者群体的 AML 特征。
- **为患者群体生成特征** – AEP 会针对每位患者，跨诊断、治疗和手术等不同类别计算超过 1,000 个 AML 特征。
- **构建聚类并汇总聚类特征** – Smart Subgroups 组件利用患者特征训练主题模型，以确定最优聚类数量并把患者分配到各个聚类。每个聚类中最具区分度的特征的发生率（由训练好的分类模型判定）用于描述该聚类的特征。
- **生成聚类名称并回答用户查询** – 针对 Amazon Bedrock 上 Anthropic 的 Claude 3 Haiku 采用的一种 prompt 工程技术，可生成描述性的聚类名称并回答用户查询。Amazon Bedrock 提供对来自多种模型提供商的 LLM 的访问。之所以选择 Anthropic 的 Claude 3 Haiku 作为模型，是因为它的速度与令人满意的智能水平。

该解决方案使用 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）和 [Amazon Aurora](https://aws.amazon.com/rds/aurora/) 实现数据持久化与数据交换，并使用集成了 Anthropic 的 Claude 3 Haiku 模型的 Amazon Bedrock 来生成聚类名称。Discover 及其事务型与批处理应用部署在 [Kubernetes on AWS](https://aws.amazon.com/kubernetes/) 集群上并可弹性伸缩，以优化性能、用户体验和可移植性。

下图展示了解决方案架构。

![解决方案 - 流程](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/21/ML-17577-solution-flow.png)
![解决方案架构](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/21/ML-17577-solution-arch.png)

该工作流包含以下步骤：

- 用户为其感兴趣的患者群体创建 Smart Subgroups。
- AEP 使用真实世界数据和一种自定义查询语言，为用户选定的群体计算超过 1,000 个经科学验证的特征。这些特征存储在 Amazon S3 中，并使用 [AWS Key Management Service](https://aws.amazon.com/kms/)（AWS KMS）加密，供下游使用。
- Smart Subgroups 组件训练聚类算法，并汇总每个聚类最重要的特征。聚类特征摘要存储在 Amazon S3 中，并以热力图的形式展示给用户。Smart Subgroups 以 Kubernetes job 的形式部署，按需运行。
- 用户通过以自然语言表达的问题与 Interpreter API 微服务交互，以检索描述性的亚组名称。传输到该服务的数据使用 Transport Layer Security 1.2（TLS）加密。Interpreter API 使用复合 prompt 工程技术，配合 Anthropic 的 Claude 3 Haiku 来回答用户查询：带版本的 prompt 模板负责生成描述性亚组名称并回答用户查询。AML 特征会被加入 prompt 模板。例如，特征“Benign Ovarian Cyst”的描述会在给 LLM 的 prompt 中展开为“该指标涵盖可在女性卵巢内或卵巢表面形成的不同类型囊肿，包括卵泡囊肿、黄体囊肿、子宫内膜异位症以及未特指的卵巢囊肿。”最后，每个亚组的主要特征发生率也会加入 prompt 模板。例如：“在 Smart Subgroup 1 中，‘Cornea and external disease (EYE001)’ 的相对发生率为 30.32%；在 Smart Subgroup 1 中，‘Glaucoma (EYE003)’ 的相对发生率为 9.94%…”
- Amazon Bedrock 将结果返回给应用，由应用向用户展示热力图。

## 成效

Smart Subgroups Interpreter 让不熟悉真实世界数据的 AEP 用户能够通过自然语言查询发现患者群体中的模式。用户现在可以把这类探索得到的发现转化为假设，在 Aetion 的各款软件中开展进一步分析，从而在几分钟而非几天内产出决策级证据，并且无需支持人员的协助。

## 结语

本文展示了 Aetion 如何利用 Amazon Bedrock 和其他 AWS 服务，帮助用户即使没有真实世界数据的既有专业知识，也能发现患者群体中有意义的模式。这些探索为在 Aetion 的 Evidence Platform 中开展更深入的分析奠定基础，产出决策级证据，推动更明智、由数据支撑的成果。

在我们持续扩展生成式 AI 能力的过程中，Aetion 始终致力于提升用户体验，并加速从真实世界数据到真实世界证据的进程。
