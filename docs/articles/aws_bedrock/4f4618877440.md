# 使用 Amazon Bedrock AgentCore 与 Amazon Nova 2 Sonic 实现全渠道点单

## 简介

构建一个能在移动应用、网站和语音界面之间通用的语音点单系统（即 [omnichannel](https://en.wikipedia.org/wiki/Omnichannel) 全渠道方式）会带来实实在在的挑战。你需要处理双向音频流、在多个轮次之间维持对话上下文、以低耦合方式集成后端服务，并扩展系统以应对高峰流量。

本文将展示如何使用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 这一 agentic 平台，以及 [Amazon Nova 2 Sonic](https://aws.amazon.com/nova/models/)，构建一套完整的全渠道点单系统——借助任意框架和基础模型，安全地大规模构建、部署和运营高效的 AI agent。你将部署可处理身份验证、处理订单并提供基于位置推荐的基础设施。系统使用可自动扩缩的托管服务，降低构建语音 AI 应用的运维开销。读到最后，你将拥有一个可跨多个客户触点处理语音订单的可用系统。AI 编排层连接到一个带示例菜单数据的示例后端架构，让你在实施这类项目时已有现成起点。本项目被划分为多个模块，如果你希望复用组件以集成到现有的后端 API，也能获得灵活性。

本文将介绍如何：

- 使用 [AWS Cloud Development Kit（AWS CDK）](https://aws.amazon.com/cdk/) 部署多通道语音 AI 点单基础设施
- 使用 Strands 与 Amazon Nova 2 Sonic 实现一个 agent，在 AgentCore Runtime 上承载实时语音处理
- 通过 AgentCore Gateway，使用 [Model Context Protocol（MCP）](https://modelcontextprotocol.io/docs/getting-started/intro) 将 AI agent 连接到后端服务
- 用贴近真实场景的点单流程测试系统，其中包括基于路线的自提点推荐

Amazon Nova 2 Sonic 是可通过 Amazon Bedrock 使用的语音到语音基础模型，可用于实时语音交互。与 Amazon Bedrock AgentCore 结合后，你就能在所有客户触点上实现自然的语音点单。

## 方案概览

该方案架构将前端、AI agent 与后端服务拆分为彼此独立的组件。这种拆分让你能独立开发和扩展每个组件。MCP 是一项开放标准，用于将 AI 应用连接到外部数据源、工具与工作流；它在你的 agent 与后端服务之间提供标准化的通信方式。

该方案将部署：

- [**Amazon Cognito**](https://aws.amazon.com/cognito/) – 负责用户身份验证，并提供用于安全访问 API 的临时 AWS 凭证。只要你的身份提供方（IDP）符合 OAuth 2.0 规范，就可以将其替换为任意实现。
- [**Amazon Bedrock AgentCore** **Runtime**](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) – 以 microVM 隔离方式承载你的 AI agent。每个用户会话都运行在独立的虚拟机中，即使在高负载下也能保证客户会话的安全与性能，并防止某个客户的会话影响其他会话的性能或访问他们的数据。
- [**Amazon Bedrock AgentCore** **Gateway**](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) – 为开发者提供安全的方式来大规模构建、部署、发现和连接工具，从而在 agent 与你的业务逻辑之间建立标准化通信而不产生紧耦合，因此你可以修改后端或新增工具而无需重写集成代码
- [**Amazon API Gateway**](https://aws.amazon.com/api-gateway/) – 通过 [表述性状态转移（REST）](https://aws.amazon.com/what-is/restful-api/#what-is-rest--1hfzuqn)端点暴露你的后端服务，并采用基于 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam/) 的授权
- [**AWS Lambda**](https://aws.amazon.com/lambda/) – 执行菜单检索、订单处理和位置服务等业务逻辑
- [**Amazon DynamoDB**](https://aws.amazon.com/dynamodb/) – 以个位数毫秒级延迟存储客户档案、订单、菜单项和购物车
- [**AWS Location Services**](https://aws.amazon.com/location/) – 为自提点推荐提供基于位置的功能
- [**AWS Amplify**](https://aws.amazon.com/amplify/) – 托管前端应用

**A 部分：后端基础设施**

该部分以基础设施即代码的方式，部署一套示例餐厅架构作为后端服务。它为客户信息、订单、菜单、购物车和位置配置数据存储，还设置了用于地址处理与地图的位置服务、用于业务逻辑的 Lambda 函数、用于外部访问的 API 层，以及用户身份验证与授权服务。各资源按恰当的依赖顺序部署。

**B 部分：AgentCore Gateway**

该部分部署 AgentCore Gateway 基础设施。它配置所需的 IAM 服务权限，创建 AgentCore Gateway 服务，并配置 API 集成，将后端端点暴露为 agent 可访问的工具。

**C 部分：AgentCore Runtime 与 ECR 镜像**

该部分部署 AgentCore Runtime 环境。它配置用于容器存储的 Amazon ECR、用于源码上传的 Amazon S3、用于构建自动化的 AWS CodeBuild，以及所需的 IAM 权限。AgentCore Runtime 服务以 WebSocket 协议配置。

**D 部分：AWS Amplify**

该部分使用 AWS Amplify 部署前端应用。它配置带部署设置的 Amplify 托管服务，并根据后端输出生成所需的前端配置。构建完成的 Web 应用会被部署，并在完成后可通过 Amplify URL 访问。

## **用户请求流程：**

- 用户从浏览器或移动设备访问托管在 AWS Amplify 上的 Web 应用。
- 用户用其用户名和密码通过 Amazon Cognito 完成身份验证，并获得 JWT token（Access Token 与 ID Token）。
- 前端用 ID Token 向 Cognito Identity Pool 换取临时 AWS 凭证（Access Key、Secret Key、Session Token）。
- 前端建立一条经 SigV4 签名的 WebSocket 连接指向 AgentCore Runtime，并将 Access Token 作为第一条消息发送，用于身份核验。
- 承载在 AgentCore Runtime 中的 agent 通过调用 Cognito 的 GetUser API 校验 Access Token，并提取客户经核验的姓名、邮箱与 customerId。
- AgentCore Runtime 在 Amazon Bedrock 上初始化 Nova 2 Sonic 模型，并结合已核验的客户上下文构建个性化的 system prompt。
- AgentCore Runtime 以 MCP 客户端身份、使用 SigV4 认证连接到 AgentCore Gateway，并发现可用的工具。
- 用户说出自己的订单。agent 通过 Nova 2 Sonic 处理语音输入，并通过 AgentCore Gateway 以 MCP 异步调用工具。
- AgentCore Gateway 将后端 REST API 暴露为 MCP 工具，agent 因此可以按名称发现并调用它们。当 agent 调用某个工具时，AgentCore Gateway 会把请求作为 REST API 调用转发给 API Gateway，由其路由到相应的 Lambda 函数。Lambda 函数查询 DynamoDB 表和 AWS Location Services。
- Nova 2 Sonic 生成融合了工具结果的上下文相关语音响应，并通过 WebSocket 连接回传给用户。

## 理解无服务器数据管理

API Gateway 创建了一个 REST API，通过八个经 IAM 认证的端点并配合 Lambda 集成，把你的前端连接到后端服务。

你的后端使用五张 DynamoDB 表来支撑完整的点单工作流。**Customers 表**存储客户档案（姓名、邮箱、电话、忠诚度等级、积分），用于个性化推荐。**Orders 表**存储带位置数据的订单历史，并使用全局二级索引按位置查询，以识别热门商品。**Menu 表**存储按位置划分的菜品，其价格与可售情况因餐厅而异。**Carts 表**存储带 24 小时 TTL 的临时购物车，到期自动清理。**Locations 表**存储餐厅数据（坐标、营业时间、税率），用于订单计算与推荐。DynamoDB 的按需容量会随流量自动扩缩。

## 理解基于位置的服务

Location Services 提供基于位置的功能，帮助客户找到方便的自提点。系统部署三类资源：用于地理编码与地址搜索的 **Place Index**（Esri）、用于计算行车路线与绕行时间的 **Route Calculator**（Esri），以及用于面向驾驶场景优化的交互式可视化的 **Map**（VectorEsriNavigation 样式）。

Lambda 函数提供三项能力：**最近位置搜索**使用 GPS 坐标和 haversine 公式，找出按距离排序的最近餐厅；**基于路线的搜索**使用实际行车时间而非直线距离，找出在指定绕行时间（默认 10 分钟）内的餐厅；**地址地理编码**在没有 GPS 可用时把街道地址转换为坐标。

这些功能可实现上下文感知的推荐，例如“我找到了一个距离你路线 2 分钟的位置”或“你常用的位置在 5 英里之外”。

## 理解通过 Amazon Bedrock AgentCore 进行的语音 AI 处理

你的 AI agent 通过 Amazon Bedrock AgentCore 处理语音交互。每个用户会话都运行在独立的 microVM 中，即使在高负载下也能保证客户会话的安全与性能，并防止某个客户的会话影响其他会话的性能或访问他们的数据。AgentCore 提供自动扩缩、内置监控以及面向实时语音的 WebSocket 支持。

该 agent 使用 Strands 框架定义 system prompt、工具与对话流程。Nova 2 Sonic 提供：

- 可容忍背景噪声、跨口音的语音识别
- 根据用户语调与情绪调整语音响应
- 低延迟的双向流式传输
- 异步工具调用，可并行取数而不阻塞对话
- 处理打断，实现自然的轮流对话
- 跨多个对话轮次的上下文感知

语音处理流程如下：音频从前端（16 kHz PCM）经 WebSocket 流式传输到 AgentCore Runtime。Nova 2 Sonic 转写语音，agent 判定意图并选择工具，通过 MCP 异步调用这些工具，AgentCore Gateway 再把 MCP 调用转换为 REST API 调用。Lambda 函数执行业务逻辑并返回结果，agent 将其纳入响应。Nova 2 Sonic 生成语音输出，流式回传给前端。

该架构将为对话式点单把延迟降到最低。

## 用户身份验证

该方案使用 Amazon Cognito 用户池与身份池实现安全、基于角色的访问控制。用户池管理身份验证与用户组，身份池提供与 IAM 角色关联的临时 AWS 凭证。用户用其用户名和密码登录 Cognito 用户池，获得 JSON Web Token（JWT）token（Access Token 与 ID Token）。前端用 ID Token 向 Cognito 身份池换取临时 AWS 凭证（Access Key、Secret Key、Session Token）。这些凭证使用签名版本 4（SigV4）为指向 AgentCore Runtime 的 WebSocket 连接和 API Gateway 请求签名。该架构确保只有通过身份验证的用户才能访问应用与点单 API。

## 结论

本文展示了如何使用 Amazon Cognito 做身份验证、Amazon Bedrock AgentCore 做 agent 托管、API Gateway 做数据通信、DynamoDB 做存储、Location Services 做路线优化，从而构建一套全渠道点单系统。三层架构把前端、agent 与后端组件彼此分离，便于独立开发与扩展。系统通过 MCP 集成支持菜单管理、购物车功能、忠诚度计划、订单处理和基于位置的服务。Amazon Nova 2 Sonic 提供低延迟的语音交互、异步工具调用和打断处理。并行工具调用缩短了等待时间，语音识别可跨口音工作，个性化推荐使用订单历史，路线优化的自提点帮助客户找到方便的落脚点。按用量计价的模式和自动扩缩能在用量增长时控制成本；借助 MCP 集成，你可以通过新增 Lambda 函数来适配方案，而无需修改 agent 代码。要开始使用，请访问 [GitHub](https://github.com/aws-samples/sample-omnichannel-ordering-with-amazon-bedrock-agentcore-and-nova-sonic) 上的方案仓库，并针对你的点单平台定制该方案。更多信息请参阅 Amazon Bedrock 文档与 Introducing Amazon Nova 2 Sonic。
