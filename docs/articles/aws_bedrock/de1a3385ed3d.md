# 智能医疗助手：以个性化支持与数据驱动洞察赋能各方干系人

[大语言模型（LLMs） ](https://aws.amazon.com/what-is/large-language-model/)已经彻底改变了自然语言处理领域，使机器能够以惊人的准确度理解并生成类人文本。然而，尽管语言能力出众，LLM 本质上仍受限于其训练所用的数据。它们的知识是静态的，局限在训练时所接触的信息之内——在处理医疗健康这类动态且不断演进的领域时，这就成了问题。

医疗健康行业是一个复杂且不断变化的领域，知识体量庞大且增长迅速。医学研究、临床实践与治疗指南不断更新，使得即便最先进的 LLM 也会很快过时。此外，患者数据——包括电子健康记录（EHR）、诊断报告与病史——高度个性化，每位患者都各不相同。仅依靠 LLM 的预训练知识，不足以给出准确且个性化的医疗健康建议。

此外，医疗决策往往需要整合来自多个来源的信息，例如医学文献、临床数据库与患者记录。LLM 缺乏无缝访问并综合这些多样且分布式数据源的能力。这限制了它们为医疗健康应用提供全面且有充分依据的洞察的潜力。

要充分发挥 LLM 在医疗健康领域的潜力，克服这些挑战至关重要。患者、医疗服务提供者与研究人员需要这样的智能 agent：它能依据最新的医学知识与单个患者的数据，提供及时、个性化且具备上下文感知的支持。

于是有了 [LLM function calling](https://docs.aws.amazon.com/bedrock/latest/userguide/tool-use.html)——这项强大的能力通过让 LLM 与外部函数或 API 交互，使其能够访问并使用预训练知识之外的数据源或计算能力，从而应对这些挑战。把 LLM 的语言理解与生成能力同外部数据源和服务结合起来，LLM function calling 为智能医疗 agent 开启了无限可能。

本篇博客将探讨 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的 [Mistral LLM](https://aws.amazon.com/bedrock/mistral/) 如何应对这些挑战，使开发具备 LLM function calling 能力的智能医疗 agent 成为可能，同时通过 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 维持强健的数据安全与隐私保护。

具备 LLM function calling 能力的[医疗 agent](https://www.youtube.com/watch?v=FOU_Kiul4RI) 可以充当面向各类干系人的智能助手，包括患者、医疗服务提供者与研究人员。它们能帮助患者回答医学问题、解读检查结果，并依据其病史与当前状况提供个性化的健康建议。对医疗服务提供者而言，这些 agent 可以协助完成总结患者记录、给出潜在诊断或治疗方案建议、跟进最新医学研究等任务。此外，研究人员可以使用 LLM function calling 分析海量科学文献，识别模式与洞察，加速药物研发或疾病预防等领域的发现。

## LLM function calling 的优势

LLM function calling 为企业应用带来多项优势，包括更强的决策能力、更高的效率、个性化的体验以及可扩展性。把 LLM 的语言理解能力同外部数据源与计算资源结合起来，企业可以做出更有依据、更数据驱动的决策，自动化并简化各项任务，为单个用户或客户提供量身定制的建议与体验，并处理海量数据、并发处理多个请求。

LLM function calling 在医疗健康领域的潜在用例包括患者分诊、医学问答与个性化治疗建议。由 LLM 驱动的 agent 可以通过分析症状、病史与风险因素来协助患者分诊，并给出初步评估或就医建议。借助 LLM 理解自然语言查询、从多个数据源获取相关医学知识的能力，患者与医疗服务提供者可以得到准确且及时更新的医学问题解答。此外，通过与电子健康记录（EHR）和临床决策支持系统集成，LLM function calling 可以给出贴合单个患者病史、病情与偏好的个性化治疗建议。

Amazon Bedrock 支持多种[基础模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)。本文我们将探索如何使用来自 Amazon Bedrock 的 Mistral 执行 function calling。Mistral 支持[ function calling](https://docs.mistral.ai/capabilities/function_calling/)，它允许 agent 在对话流程内调用外部函数或 API。这一能力使 agent 能够检索数据、执行计算，或使用外部服务来增强其对话能力。Mistral 中的 function calling 通过特定的函数调用块实现，这些块定义要调用的外部函数，并处理响应或输出。

## 解决方案概览

LLM function calling 通常涉及把 LLM 模型与提供额外数据源或计算能力的外部 API 或函数集成起来。LLM 模型充当接口，处理自然语言输入，并基于其预训练知识以及从外部函数或 API 获得的信息生成回答。该架构通常由 LLM 模型、函数或 API 集成层，以及外部数据源与服务组成。

医疗 agent 可以通过一系列步骤集成 LLM 模型并调用外部函数或 API：[自然语言输入处理](https://www.promptingguide.ai/techniques)、自我纠错、思维链（chain of thought）、通过集成层调用函数或 API、数据整合与处理，以及人格设定（persona adoption）。agent 接收自然语言输入，经 LLM 模型处理，在需要额外数据或计算时调用相关的外部函数或 API，把 LLM 模型的输出与外部数据或结果结合，并向用户给出全面的回答。

## 安全与隐私考量

由于个人健康信息（PHI）的敏感性，以及数据泄露或未授权访问可能造成的后果，数据隐私与安全在医疗健康行业至关重要。对于处理患者数据的医疗机构而言，遵守 [HIPAA](https://www.cdc.gov/phlp/php/resources/health-insurance-portability-and-accountability-act-of-1996-hipaa.html) 与 [GDPR](https://gdpr-info.eu/) 等法规至关重要。为维持强健的数据保护与监管合规，医疗机构可以使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/)——这是 [Amazon Web Services（AWS）](https://aws.amazon.com/) 提供的一整套安全与隐私控制措施。

Amazon Bedrock Guardrails 提供多层的数据安全方案，包括静态与传输中加密、访问控制、审计日志、真值（ground truth）校验以及事件响应机制。它还提供数据驻留控制等高级安全特性，允许组织指定数据可以存储与处理的地理区域，从而保持对当地数据隐私法的合规。

在医疗健康领域使用 LLM function calling 时，必须落实强健的安全措施，并遵循处理敏感患者信息的最佳实践。在这方面，Amazon Bedrock Guardrails 能发挥关键作用，为部署和运营使用 LLM 能力的医疗应用与服务提供安全基础。

Amazon Bedrock Guardrails 支持的一些关键安全措施包括：

- **数据加密**：由 LLM 函数处理的患者数据可以在静态与传输中加密，确保即便发生未授权访问或数据泄露，敏感信息依然安全。
- **访问控制**：Amazon Bedrock Guardrails 支持细粒度访问控制，使医疗机构能够定义并强制执行严格的权限，明确谁能通过 LLM 函数访问、修改或处理患者数据。
- **安全的数据存储**：患者数据可以存放在 Amazon S3 或 [Amazon Elastic File System（Amazon EFS）](https://aws.amazon.com/efs) 等安全且加密的存储服务中，确保敏感信息即便处于静态也受到保护。
- **匿名化与假名化**：医疗机构可以使用 Amazon Bedrock Guardrails 实施数据匿名化与假名化技术，确保用于训练或测试 LLM 模型的患者数据不包含个人可识别信息（PII）。
- **审计日志与监控**：Amazon Bedrock Guardrails 提供的全面审计日志与监控能力，使医疗机构能够跟踪并监控 LLM 函数对患者数据的所有访问与使用，从而及时发现并响应潜在的安全事件。
- **定期安全审计与评估**：Amazon Bedrock Guardrails 有助于开展定期的安全审计与评估，确保医疗机构的数据保护措施在面对不断演变的安全威胁与监管要求时依然及时有效。

借助 Amazon Bedrock Guardrails，医疗机构可以放心地在应用与服务中部署 LLM function calling，在保持强健的数据安全、隐私保护与监管合规的同时，获得 AI 驱动医疗助手带来的变革性收益。

## 案例研究与真实示例

[3M Health Information Systems ](https://www.solventum.com/en-us/home/health-information-technology/resources-education/blog/2023/4/3m-health-information-systems-collaborates-with-aws-to-accelerate-ai-innovation-in-clinical-documentation/)正与 AWS 合作，利用 AWS 的机器学习（ML）服务、算力与 LLM 能力，加速临床文档领域的 AI 创新。这一合作旨在增强 3M 的自然语言处理（NLP）与环境临床语音技术，使智能医疗 agent 能够更高效、更准确地记录并归档患者就诊信息。这些由 LLM 驱动的 agent 可以理解并处理医疗服务提供者输入的自然语言（如口头记录或查询），并借助 LLM function calling 从 EHR、知识库及其他数据源访问并整合相关医疗数据。把 3M 的领域专长与 AWS 的 ML 与 LLM 能力结合起来，双方可以改进临床文档工作流，减轻医疗服务提供者的行政负担，并最终通过更准确、更全面的文档提升患者照护水平。

[GE Healthcare](https://aws.amazon.com/solutions/case-studies/ge-healthcare/) 开发了运行在 AWS 上的安全智能解决方案 Edison，用于摄取并分析来自医疗设备与医院信息系统的数据。该方案使用 AWS 的分析、ML 与物联网（IoT）服务生成洞察与分析结果，并可通过由 LLM 驱动的智能医疗 agent 交付。这些具备 LLM function calling 能力的 agent 能够无缝访问并整合 Edison 生成的洞察与分析，从而帮助医疗服务提供者提升运营效率、改善患者结局，并支持新型智能医疗设备的开发。通过使用 LLM function calling 从 Edison 检索并处理相关数据，agent 可以为医疗服务提供者提供数据驱动的建议与个性化支持，最终实现更好的患者照护与更有效的医疗服务交付。

[多模态模型](https://aws.amazon.com/health/solutions/mmmo/)等新兴技术能够同时处理并生成文本、图像及其他数据格式，可通过对医疗数据做更全面的分析与可视化来增强医疗健康领域的 LLM function calling。基于单个患者数据训练的个性化语言模型，可以提供更为贴合、更准确的回答。联邦学习技术允许在去中心化数据上训练模型同时保护隐私，可应对医疗健康领域的数据共享难题。

这些进步与新兴技术可以通过让医疗 agent 更智能、更自适应、更个性化来塑造其未来。agent 可以把医学图像、检验报告等多模态数据无缝整合进其分析与建议中。它们还能持续学习并适应单个患者的偏好与健康状况，提供真正个性化的照护。此外，联邦学习可以在保持数据隐私的同时实现协同的模型开发，促进医疗机构之间的创新与知识共享。
