# 使用 Weights & Biases 与 Amazon Bedrock AgentCore 加速企业 AI 开发

*本文由 Weights & Biases（W&B）的 Thomas Capelle 与 Ray Strickland 合作撰写。*

生成式人工智能（AI）在企业中的采用正在加速，从简单的基础模型交互演进为复杂的 agentic 工作流。随着组织从概念验证走向生产部署，它们需要稳健的工具来规模化地开发、评估与监控 AI 应用。

本文演示如何使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的 Foundation Models（FM）与新近推出的 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/)，配合 [W&B Weave](https://wandb.ai/site/weave/) 来构建、评估与监控企业 AI 方案。我们覆盖完整的开发生命周期，从跟踪单次 FM 调用一直到监控生产环境中复杂的 agent 工作流。

## W&B Weave 概览

[Weights & Biases（W&B）](https://wandb.ai/site) 是一套 AI 开发者系统，为各行业各种规模的企业提供训练模型、微调以及利用基础模型的完整工具。

W&B Weave 提供统一的开发者工具套件，支撑 agentic AI 工作流的每个阶段。它可以：

- **追踪与监控：** 跟踪大语言模型（LLM）调用与应用逻辑，以便调试和分析生产系统。
- **系统性迭代：** 打磨并迭代 prompt、数据集与模型。
- **实验：** 在 [LLM Playground](https://wandb.ai/site/playground/) 中试验不同模型与 prompt。
- **评估：** 使用自定义或预置 scorer 配合我们的对比工具，系统性地评估并提升应用性能。收集用户与专家反馈，用于贴近真实场景的测试与评估。
- **Guardrail：** 通过内容审核、prompt 安全等防护措施帮助保护你的应用。可使用自定义或第三方 guardrail（包括 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/)）或 W&B Weave 原生 guardrail。

W&B Weave 既可由 Weights & Biases 在多租户或单租户环境中全托管，也可直接部署在客户的 [Amazon Virtual Private Cloud (VPC)](https://aws.amazon.com/vpc/) 中。此外，W&B Weave 集成进 W&B Development Platform，让组织在模型训练/微调工作流与 agentic AI 工作流之间获得无缝统一的体验。

开始使用：通过 [AWS Marketplace](https://aws.amazon.com/marketplace) 订阅 [Weights & Biases AI Development Platform](https://aws.amazon.com/marketplace/pp/prodview-42j3r4pt3dtns)。个人与学术团队可零额外成本订阅 W&B。

## 用 W&B Weave SDK 跟踪 Amazon Bedrock FM

W&B Weave 通过 Python 与 TypeScript SDK 与 Amazon Bedrock 无缝集成。安装该库并对你的 Bedrock 客户端打补丁后，W&B Weave 会自动跟踪 LLM 调用：

```
!pip install weave
import weave
import boto3
import json
from weave.integrations.bedrock.bedrock_sdk import patch_client

weave.init("my_bedrock_app")

# Create and patch the Bedrock client
client = boto3.client("bedrock-runtime")
patch_client(client)

# Use the client as usual
response = client.invoke_model(
    modelId="anthropic.claude-3-5-sonnet-20240620-v1:0",
    body=json.dumps({
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 100,
        "messages": [
            {"role": "user", "content": "What is the capital of France?"}
        ]
    }),
    contentType='application/json',
    accept='application/json'
)
response_dict = json.loads(response.get('body').read())
print(response_dict["content"][0]["text"])
```

## 在 W&B Weave Playground 中试验 Amazon Bedrock FM

[W&B Weave Playground](https://weave-docs.wandb.ai/guides/tools/playground/) 以直观的界面加速 prompt 工程，用于测试与对比 Bedrock 模型。主要特性包括：

- 直接编辑 prompt 与重试消息
- 模型并排对比
- 从 trace 视图直接进入，方便快速迭代

开始时，在 Playground 设置中添加你的 [AWS credentials](https://weave-docs.wandb.ai/guides/tools/playground#add-provider-credentials-and-information)，选择偏好的 [Amazon Bedrock FMs](https://docs.wandb.ai/weave/guides/tools/playground#amazon-bedrock)，然后开始实验。该界面支持对 prompt 的快速迭代，同时保持实验的完整可追溯性。

## 用 W&B Weave Evaluations 评估 Amazon Bedrock FM

[W&B Weave Evaluations](https://wandb.ai/site/evaluations/) 提供专用工具来高效评估生成式 AI 模型。把 W&B Weave Evaluations 与 Amazon Bedrock 一起使用，用户可以高效评估这些模型、分析输出，并可视化它们在关键指标上的表现。用户可以使用 W&B Weave 的内置 scorer、第三方或自定义 scorer，以及人工/专家反馈。这一组合让人更深入地理解模型之间的取舍，例如在成本、准确率、速度与输出质量上的差异。

W&B Weave 通过 Model 与 Evaluation 类提供一等公民的评估跟踪方式。要建立评估任务，客户可以：

- 定义一个 [dataset](https://docs.wandb.ai/weave/guides/core-types/datasets)，或一份包含待评估样本集合的字典列表
- 创建一组打分函数。每个函数应带有 model_output，可选地还带有你样本中的其他输入，并返回一个包含分值的字典
- 使用 Model 类定义一个 Amazon Bedrock 模型
- 通过调用 Evaluation 来评估该模型

下面是一个建立评估任务的示例：

```

from weave import Evaluation

# Collect your examples
examples = [
```

## 用 W&B Weave 增强 Amazon Bedrock AgentCore 可观测性

Amazon Bedrock AgentCore 是一整套服务，用于在企业规模上更安全地部署与运营能力强大的 agent。它提供更安全的运行时环境、工作流执行工具与运营控制能力，可配合 [Strands Agents](https://strandsagents.com/latest/)、CrewAI、LangGraph、LlamaIndex 等流行框架以及众多 LLM 模型使用——无论来自 Amazon Bedrock 还是外部来源。

AgentCore 通过 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 仪表盘提供内建可观测性，跟踪 token 用量、延迟、会话时长与错误率等关键指标。它还会追踪工作流步骤，显示调用了哪些工具以及模型如何响应，为生产环境的调试与质量保障提供必要的可见性。

同时使用 AgentCore 与 W&B Weave 时，团队既可以利用 AgentCore 内建的运营监控与安全基础，也可以在与既有开发工作流契合的情况下使用 W&B Weave。已经投入 W&B 环境的组织，可以选择在 AgentCore 原生能力之外再引入 W&B Weave 的可视化工具。这种做法让团队在开发串联多个工具与推理步骤的复杂 agent 时，灵活选用最贴合自身既定流程与偏好的可观测性方案。

[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/11/ML-17566-image-4.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/11/ML-17566-image-4.png)

为你的 AgentCore agent 添加 W&B Weave 可观测性有两种主要方式：使用 W&B Weave 原生 SDK，或通过 OpenTelemetry 集成。

## 原生 W&B Weave SDK

最简单的方式是使用 W&B Weave 的 @weave.op 装饰器来自动跟踪函数调用。用你的项目名初始化 W&B Weave，并包装你想监控的函数：

```
import weave
import os

os.environ["WANDB_API_KEY"] = "your_api_key"
weave.init("your_project_name")

@weave.op()
def word_count_op(text: str) -> int:
    return len(text.split())

@weave.op()
def run_agent(agent: Agent, user_message: str) -> Dict[str, Any]:
    result = agent(user_message)
    return {"message": result.message, "model": agent.model.config["model_id"]}
```

由于 AgentCore 以 docker 容器方式运行，请把 W&B weave 加入你的依赖（例如 uv add weave），以便打进容器镜像。

## OpenTelemetry 集成

对于已经在使用 OpenTelemetry 或希望采用厂商中立埋点的团队，W&B Weave 直接支持 OTLP（OpenTelemetry Protocol）：

```
from opentelemetry import trace
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter

auth_b64 = base64.b64encode(f"api:{WANDB_API_KEY}".encode()).decode()
exporter = OTLPSpanExporter(
    endpoint="https://trace.wandb.ai/otel/v1/traces",
    headers={"Authorization": f"Basic {auth_b64}", "project_id": WEAVE_PROJECT}
)

# Create spans to track execution
with tracer.start_as_current_span("invoke_agent") as span:
    span.set_attribute("input.value", json.dumps({"prompt": user_message}))
    result = agent(user_message)
    span.set_attribute("output.value", json.dumps({"message": result.message}))
```

这种方式在与 AgentCore 既有 OpenTelemetry 基础设施保持兼容的同时，把 trace 路由到 W&B Weave 进行可视化。同时使用 AgentCore 与 W&B Weave 时，团队在可观测性上有多种选择。AgentCore 的 CloudWatch 集成监控系统健康、资源利用率与错误率，同时为 agent 推理与工具选择提供追踪。W&B Weave 提供的可视化能力，以已在使用 W&B 环境的团队所熟悉的形式呈现执行数据。两套方案都能让组织看清 agent 如何处理信息、如何做决策，从而选择与既有工作流和偏好最契合的可观测性做法。这种双层方式意味着用户可以：

- 通过 CloudWatch 告警监控生产服务级别协议（SLA）
- 在 W&B Weave 的 trace explorer 中调试复杂的 agent 行为
- 借助详细的执行拆解优化 token 用量与延迟
- 跨不同 prompt 与配置对比 agent 表现

该集成只需极少的代码改动，保留你既有的 AgentCore 部署，并可随 agent 复杂度的增长而扩展。无论你是在构建简单的工具调用 agent，还是编排多步工作流，这套可观测性栈都能提供快速迭代、放心部署所需的洞察。

实现细节与完整代码示例请参阅我们的[上一篇文章。](https://wandb.ai/byyoung3/testotel/reports/Adding-observability-and-tracing-to-your-Bedrock-AgentCore-Agents--VmlldzoxMzk0MDI0Mg)

## 结语

本文演示了如何把 Amazon Bedrock 的 FM 与 AgentCore 同 W&B Weave 的完整可观测性工具包结合起来，构建并优化企业级 agentic AI 方案。我们探讨了 W&B Weave 如何增强 LLM 开发生命周期的每个阶段——从在 Playground 中的初步实验，到对模型表现的系统性评估，最后到对复杂 agent 工作流的生产监控。

Amazon Bedrock 与 W&B Weave 之间的集成提供了若干关键能力：

- 使用 W&B Weave SDK，以极少的代码改动自动跟踪 Amazon Bedrock FM 调用
- 通过 W&B Weave Playground 直观的界面快速实验，测试 prompt 并对比模型
- 用自定义打分函数进行系统性评估，评估不同的 Amazon Bedrock 模型
- 面向 AgentCore 部署的完整可观测性：CloudWatch 指标提供更稳健的运营监控，并以详细的执行 trace 作为补充
