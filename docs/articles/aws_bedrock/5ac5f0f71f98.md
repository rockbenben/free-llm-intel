# LoanPro 如何用 Amazon Bedrock AgentCore 构建 agentic AI 贷款服务助手

*本文由 AWS 的 Mariah Miller 与 LoanPro 的 Colin Terry 合著*

你有没有想过，当你打电话给银行寻求支持时，电话另一端的人是什么体验？当借款人打电话给贷款机构时，应答坐席必须先翻出几十个字段的账户数据、交易历史和工作流队列，才能在帮助借款人之前理清情况。而时钟一直在走。手工拼装这些上下文意味着更长的通话、不稳定的服务质量，以及坐席的挫败感。一个基于 agentic AI 构建的贷款服务助手改变了这一点。

[LoanPro](https://www.loanpro.io/)是面向现代贷款机构的操作系统，它着手改变这一现状。LoanPro 与 AWS 合作伙伴 [AllCloud](https://allcloud.io/) 以及 [AWS Generative AI Innovation Center](https://aws.amazon.com/ai/generative-ai/innovation-center/) 合作，构建了一个多 agent AI 助手，让服务坐席能立即拿到综合好的借款人上下文和可执行的下一步建议。根据 AllCloud 公布的案例研究，早期结果显示客户通话时长最多缩短了 15%。

本文介绍业务挑战、构建在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 上的 agentic AI 架构，以及 LoanPro 取得的成果。Amazon Bedrock 是一项完全托管的服务，通过单一 API 提供来自领先 AI 公司的一系列高性能基础模型，并提供以安全、隐私和负责任 AI 构建生成式 AI 应用所需的能力。

## 关于 LoanPro

LoanPro 是一个现代的、API 优先的借贷与信贷平台，自动化从放款到还款结清的整个贷款生命周期。LoanPro 成立于 2015 年，是各类贷款机构的记录系统（system of record）：既包括金融科技公司，也包括银行与信用合作社，以及把借贷作为增值服务提供的企业。据 LoanPro 称，该平台服务超过 450 家贷款机构，其平台上管理的贷款覆盖约 31% 的美国家庭。该平台在企业级规模上支撑着整个金融服务行业的贷款管理。

LoanPro 本身不是贷款机构，而是贷款机构运行其业务的操作系统。这个区别很重要，因为 LoanPro 的 AI 战略旨在让它所服务的机构在平台上共同受益，而不是服务于某一家借贷业务。

## 挑战

LoanPro 的核心用户群体之一是服务坐席：他们负责管理借款人账户、接听来电、处理付款并解决问题。在与客户的实时交互中，坐席可能需要查看：

- 借款人完整的还款历史，包括逾期和退票的付款。
- 当前有效的贷款条款、费用和当前余额。
- 以往的交互记录和未关闭的支持工单。
- 可用的工作流动作，例如还款计划、延期或升级处理。

在引入 AI 助手之前，坐席要在多个界面和标签页之间来回切换，手工拼出完整情况。经验较少的坐席耗时更长，结果也因接电话的人不同而不一致。LoanPro 需要的方案能够：

- 即时把账户数据综合成一份连贯的摘要。
- 根据账户上下文推荐正确的下一步动作。
- 让不同经验水平的坐席交付更一致的服务质量。

## 解决方案概览

LoanPro 与 AllCloud 合作，在 AWS Generative AI Innovation Center 的协助下，用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 设计并构建了一个多 agent AI 助手。该助手在 Amazon Bedrock 上运行 Anthropic 的 [Claude Sonnet 5.5](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-sonnet-5-5.html)、[Claude Haiku 5.5](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-haiku-5-5.html) 和 [Claude Opus 5.5](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-opus-5-5.html)（参见 [Models at a glance in Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html)）。模型可用性因 AWS Region 而异。按 Region 查询模型可用性，请参阅 [Regional availability by models in Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html)。整条链路由 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 编排，这是一个可用任意框架、任意模型大规模构建、连接和优化 agent 的平台。agent 逻辑用 [Strands Agents SDK](https://strandsagents.com/) 构建，这是一个用于构建具备工具调用能力的 AI agent 的开源框架。系统通过一个 composer 协调各个专用 agent，由它把每个请求路由到合适的专家，这样每个 agent 都只处理一项聚焦任务，可以独立评估和改进。团队选择这些托管服务，而不是自建 agent 运行时和模型访问层。Amazon Bedrock 通过单一 API 提供对领先基础模型的访问，让团队无需管理单独的 endpoint 就能灵活采用新模型。Amazon Bedrock AgentCore 提供托管的 agent 运行时，免去在生产环境运行 agent 的运维负担。

图 1 从实现角度展示了这一流程。用户请求通过 [Amazon API Gateway](https://docs.aws.amazon.com/apigateway/) 上的 LoanPro API v2 进入。一个 [AWS Lambda](https://docs.aws.amazon.com/lambda/) handler 把请求放入 [Amazon Simple Queue Service（Amazon SQS）](https://docs.aws.amazon.com/sqs/) 队列。随后 Agent Interceptor Lambda 函数调用 Loan Summary Agent。该 agent 运行在 Amazon Bedrock AgentCore 的 AgentCore runtime（Amazon Bedrock AgentCore 的一项能力）上，并使用 Amazon Bedrock 上 Anthropic 的 Claude 模型。它通过 Amazon Bedrock AgentCore Gateway（Amazon Bedrock AgentCore 的一项能力）上的 [Model Context Protocol（MCP）](https://modelcontextprotocol.io/) 服务器访问工具。该 gateway 从一份目录中查找正确的工具，这份目录由 Loan Summary Service 注册到 AWS Systems Manager [Parameter Store](https://docs.aws.amazon.com/systems-manager/latest/userguide/systems-manager-parameter-store.html) 中。Loan Summary Tool Lambda 函数会针对 LoanPro 的单点登录（SSO）服务校验调用方的签名。随后它从 LoanPro 的贷款管理系统获取账户数据，该系统运行在 [Amazon Elastic Compute Cloud（Amazon EC2）](https://docs.aws.amazon.com/ec2/) 上，位于 [Network Load Balancer](https://docs.aws.amazon.com/elasticloadbalancing/latest/network/introduction.html) 之后。该系统基于角色的访问控制也会校验同一个签名。LoanPro 还会对照用户权限和合规控制检查每个请求，然后把该动作写入审计留痕。后续各节将分别介绍这些部分：多 agent 系统、它调用的工具，以及 gateway。

该架构有四个关键组件，它们把图 1 中的各个部分与负责协调和执行的 composer agent 及 Invoke API Tool 结合起来：

### 使用 Strands Agents SDK 的多 agent 架构

该方案采用基于 Strands Agents SDK 构建的多 agent 架构。不是一个单一的大一统模型处理所有任务，而是多个专用 agent 协作，服务贷款服务工作流的不同环节。一个 agent 专注于数据获取和账户摘要，另一个负责动作选择和流程推荐，还有一个 composer agent 把每个请求路由到正确的专家并组合出最终响应。这种关注点分离让每个 agent 更容易独立评估、调优和扩展。

### 工具使用：Data Retrieval 与 Invoke API

agent 通过**工具使用**（tool use，Amazon Bedrock 中用于调用外部函数和 API 的能力）从 LoanPro 的内部系统获取借款人数据。支撑该助手的主要有两个工具：

- **Data Retrieval Tool：** 从 LoanPro 的数据层获取账户详情、还款历史、贷款条款和借款人元数据，在图 1 中表现为 Loan Summary Tool。它横跨 8 个不同的 API 端点，为每个账户综合约 1400 个字段。
- **Invoke API Tool：** 在 LoanPro 平台内触发工作流动作，例如向坐席呈现信息面板，或发起一段预定义的自动化序列。

通过连接 LoanPro 现有的 API，该助手可以直接使用实时生产数据，无需单独的数据管道或数据仓库。

### 搭配 AWS Lambda 的 Amazon Bedrock AgentCore Gateway

AgentCore Gateway 是 agent 与其所调用工具之间的安全访问层。它通过 Model Context Protocol（MCP）把 LoanPro 的 API 作为工具暴露给 agent，处理认证并管理这些连接。[AWS Lambda](https://aws.amazon.com/lambda/) 是一项无需预置或管理服务器即可运行代码的 serverless 计算服务，它在 gateway 与 LoanPro 的 API 之间提供集成层。团队选择 AgentCore Gateway 搭配 Lambda，而不是直接集成，原因有三：它把认证集中到一个托管入口点，把 LoanPro 的 API 隔离在托管边界之后，并让新工具无需重新部署 agent 就能加入。这种 serverless 做法使基础设施保持轻量，并能随请求量自动扩缩。在图 1 中，Agent Interceptor（一个 AWS Lambda 函数）调用 AgentCore runtime 上的 agent。AgentCore Gateway 执行这层访问控制，在请求到达 Loan Summary Tool 之前逐一筛查。由于该助手运行在受监管的借贷场景中，生产部署为这些组件配备了额外控制：LoanPro 基于角色的访问控制和合规护栏作用于每个请求，AI 动作会写入 LoanPro 的审计留痕，并归属到一位具名的责任人。

### 集成到 LoanPro 现有的 Web 门户

该助手直接嵌入 LoanPro 现有的 Web 门户，也就是服务坐席已经在用的同一个界面。坐席通过两个组件与 AI 助手交互：

- **Account summary view（账户摘要视图）：** 当坐席打开某个借款人账户时，助手会自动生成一段叙述式摘要，涵盖该账户的健康状况、近期活动和未了结的问题。原始数据由此变成一段关于借款人处境的连贯叙事。
- **Conversational chat interface（对话式聊天界面）：** 坐席可以用自然语言追问，深入查看具体的账户细节。团队把这一能力形容为让坐席「与贷款对话」。坐席在聊天界面中的每次交互都会被记录，从而保留借款人对话期间所执行操作的审计记录。

## 实施方法

LoanPro 与 [AWS Generative AI Innovation Center](https://aws.amazon.com/ai/generative-ai/innovation-center/)（它把 AWS 的应用科学家与客户和合作伙伴配对，以加速生成式 AI 举措）以及 AWS Premier Consulting Partner AllCloud 共同构建了该助手。三个团队一起设计并构建了这套方案。最初只是一次聚焦的合作，如今已进入生产运行，为 LoanPro 的服务坐席提供支持。

这项工作分为两条并行的工作流：

### 工作流 1：服务坐席助手

主要工作流构建了如今已在生产环境运行的 AI 助手。关键活动包括：

- 选择并梳理 agent 需要获取的数据源（应用数据、贷款历史、借款人记录）。
- 开发 agent 的自主数据获取和智能动作选择功能。
- 反复迭代 prompt，以提升获取准确度和输出质量。
- 记录 LoanPro 的安全模型和集成模式，为生产路线图提供依据。

### 工作流 2：LLM 账户规则自动化咨询

LoanPro 已有一个概念验证（POC），用大语言模型（LLM）为其 Clojure 规则引擎把自然语言转换成规则自动化代码。核心功能可用，但该方案已知有若干限制：频繁超时、缺少监控、没有部署策略。AllCloud 进行了架构评审并给出建议，把这个既有 POC 推进到可上生产的状态，包括一份书面的生产架构和风险评估。

## 评估流水线

一条结构化评估流水线，对照 LoanPro 领域专家（SME）建立的基准来验证 agent 的准确度。团队组装了 150 个由 SME 标注账户组成的基准集。在该基准上，他们衡量 agent 获取数据、总结发现和选择合适动作的能力，要求达到 99% 的准确率目标，agent 达成了该目标。这套框架延续到生产中，让 LoanPro 拥有一套可重复的流程来长期衡量和改进 agent 表现。

## 成果

部署 AI 助手带来了可衡量的运营影响：

- **客户通话时长最多缩短 15%**（来源：AllCloud 案例研究）。在 LoanPro 早期上线贷款机构合作伙伴的 800 多名服务专业人员中，坐席此前每次通话要花 18–20% 的时间（5–7 次点击、1–2.5 分钟）来了解账户情况。AI 助手把这份上下文整合成一次点击，每次通话节省 1 到近 2 分钟。对这些坐席而言，相当于每个坐席每工作小时最多收回 9 分钟，也就是每个工作小时约 120 小时的坐席产能。
- **内部工单量下降近 8%**（来源：LoanPro）。平台上的贷款机构报告支持升级工单减少，因为坐席在首次通话中就解决了更多问题。
- **15 秒内生成账户摘要**（来源：LoanPro 内部基准）。叙述式摘要会在打开账户后 15 秒内把原始借款人数据转成连贯的账户故事，而此前坐席需要手动浏览 3–5 分钟。
- **一致的服务质量**。该助手为平台上所有坐席提供同等水平的账户上下文和动作建议，减少了与个人经验水平相关的波动。
- **符合合规要求的交互日志**。坐席通过 AI 助手执行的每个动作和查询都会被记录，为借款人对话期间的交互提供可审计记录。
- **负责任的 AI 控制**。[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 对 agent 响应应用内容过滤和 grounding 校验，与 LoanPro 的合规护栏和基于角色的访问控制（RBAC）一起，确保输出在到达服务坐席和借款人之前符合策略。

> “AI 助手改变了服务坐席的工作方式。坐席不再需要把每次通话的头几分钟花在浏览界面和拼装上下文上，而是打开账户就能立刻看到全貌，并附有关于下一步该做什么的规范性建议。这份时间节省会在成千上万次通话中不断累积。”
>         — Colin Terry，LoanPro 首席产品官

## 展望

在服务坐席助手取得成功的基础上，LoanPro 与 AllCloud 正在扩大合作。团队正在开发更多 AI agent，把智能能力扩展到借贷工作流的更多环节，从贷款服务走向催收和放款支持等领域。

模块化的多 agent 架构让这种扩展切实可行。新的 agent 可以基于同一套 Amazon Bedrock AgentCore 基础设施独立构建和部署，无需重新设计核心系统。随着 Strands Agents SDK 和 Amazon Bedrock AgentCore 持续演进，LoanPro 计划在有新能力可用时加以引入。

## 结语

本文展示了 LoanPro、AWS Generative AI Innovation Center 与 AllCloud 如何用 Amazon Bedrock 和 Amazon Bedrock AgentCore 构建多 agent AI 助手，帮助服务坐席更快、更一致地处理借款人来电。该方案自主获取数据、实时生成账户摘要，并推荐最佳下一步动作，把客户通话时长最多缩短了 15%。

如果你正在为客户面向的工作流构建 agentic AI 方案，以下资源可供参考：

- [Strands Agents SDK](https://strandsagents.com/)：用于构建具备工具调用能力的 AI agent 的开源框架。
