# LoanPro 如何使用 Amazon Bedrock AgentCore 构建代理 AI 贷款服务助手

*本文由 AWS 的 Mariah Miller 和 LoanPro 的 Colin Terry 共同撰写*

您是否想知道当您致电银行寻求支持时，电话另一端的人会是什么样的体验？当借款人致电贷方时，应答代理必须从数十个字段、交易历史记录和工作流队列中提取帐户数据，以进行自我定位，然后才能帮助借款人。时钟一直在运转。手动组装上下文意味着更长的通话时间、不一致的服务质量和座席的挫败感。基于代理人工智能的贷款服务助理改变了这一点。

[LoanPro](https://www.loanpro.io/)，现代贷方的操作系统，致力于改变这一现状。 LoanPro 与 AWS 合作伙伴 [AllCloud](https://allcloud.io/) 和 [AWS Generative AI Innovation Center](https://aws.amazon.com/ai/generative-ai/innovation-center/) 合作，构建了一个多代理 AI 助手，使服务代理能够立即访问综合的借款人背景和可操作的下一步建议。根据 AllCloud 发布的案例研究，早期结果显示客户呼叫时间减少了 15%。

在这篇文章中，我们将介绍业务挑战、基于 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 构建的代理 AI 架构，以及 LoanPro 取得的成果。 Amazon Bedrock 是一项完全托管的服务，通过单个 API 提供来自领先 AI 公司的高性能基础模型选择，以及构建具有安全性、隐私性和负责任的 AI 的生成式 AI 应用程序所需的功能。

## 关于 LoanPro

LoanPro 是一个现代化的、API 优先的贷款和信贷平台，可实现从发放到还款的整个贷款生命周期的自动化。 LoanPro 成立于 2015 年，为各种类型的贷方提供记录系统：金融科技公司、银行和信用合作社，以及提供贷款作为增值服务的企业。据 LoanPro 称，该平台为 450 多家贷方提供服务，其平台上管理的贷款覆盖了约 31% 的美国家庭。该平台为整个金融服务行业的企业级贷款管理提供支持。

LoanPro 不是贷方。这是贷方运行的操作系统。这种区别很重要，因为 LoanPro 的人工智能战略旨在使整个平台上服务的机构受益，而不是单个贷款业务。

## 挑战

LoanPro 的核心用户群之一是服务代理：管理借款人账户、处理呼入电话、处理付款和解决问题的人员。在实时客户交互过程中，客服人员可能需要检查：

- 借款人完整的付款历史记录，包括错过的付款和退回的付款。
- 有效的贷款条款、费用和当前余额。
- 事先互动并开放支持票证。
- 可用的工作流程操作，例如付款计划、延期或升级。

在人工智能助手出现之前，客服人员需要手动浏览这些信息，通过多个屏幕和选项卡来组合出完整的图片。经验不足的客服人员需要更长的时间，而且结果因接电话的人而异。 LoanPro 需要一个能够：

- 立即将帐户数据合成为连贯的摘要。
- 根据帐户上下文推荐正确的下一步操作。
- 为不同经验水平的座席提供更一致的服务质量。

## 解决方案概述

通过 AWS Generative AI 创新中心，LoanPro 与 AllCloud 合作，使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 设计和构建多代理 AI 助手。该助手在 Amazon Bedrock 上的 Anthropic 的 [Claude Sonnet 5.5](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-sonnet-5-5.html)、[Claude Haiku 5.5](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-haiku-5-5.html) 和 [Claude Opus 5.5](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-opus-5-5.html) 上运行（请参阅 [Amazon Bedrock 中的模型一览](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html)）。模型可用性因 AWS 区域而异。有关按区域划分的模型可用性，请参阅 [Amazon Bedrock 中按模型划分的区域可用性](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html)。它与 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 协调，这是一个使用任何框架或模型大规模构建、连接和优化代理的平台。代理逻辑是使用 [Strands Agents SDK](https://strandsagents.com/) 构建的，这是一个用于使用工具构建 AI 代理的开源框架。该系统通过一个编写器来协调专业代理，将每个请求发送给正确的专家，因此每个代理都可以处理重点任务，并且可以独立评估和改进。该团队选择了这些托管服务，而不是在内部构建代理运行时和模型访问。 Amazon Bedrock 通过单个 API 提供对领先基础模型的访问，使团队能够灵活地采用新模型，而无需管理单独的终端节点。 Amazon Bedrock AgentCore 提供托管代理运行时，消除了在生产中运行代理的操作开销。

图 1 以实施方式显示了此流程。用户请求通过 [Amazon API Gateway](https://docs.aws.amazon.com/apigateway/) 上的 LoanPro API v2 输入。 [AWS Lambda](https://docs.aws.amazon.com/lambda/) 处理程序将请求放入 [Amazon Simple Queue Service (Amazon SQS)](https://docs.aws.amazon.com/sqs/) 队列中。然后，代理拦截器 Lambda 函数调用贷款摘要代理。该代理在 Amazon Bedrock AgentCore 运行时（Amazon Bedrock AgentCore 的一项功能）上运行，并在 Amazon Bedrock 上使用 Anthropic 的 Claude 模型。它通过 Amazon Bedrock AgentCore Gateway（Amazon Bedrock AgentCore 的一项功能）上的 [模型上下文协议 (MCP)](https://modelcontextprotocol.io/) 服务器访问其工具。网关在贷款摘要服务在 AWS Systems Manager [Parameter Store](https://docs.aws.amazon.com/systems-manager/latest/userguide/systems-manager-parameter-store.html) 中注册的目录中找到正确的工具。贷款摘要工具 Lambda 函数根据 LoanPro 的单点登录 (SSO) 服务验证调用者的签名。然后，它从 LoanPro 的贷款管理系统检索账户数据，该系统在 [网络负载均衡器](https://docs.aws.amazon.com/elasticloadbalancing/latest/network/introduction.html) 后面的 [Amazon Elastic Compute Cloud (Amazon EC2)](https://docs.aws.amazon.com/ec2/) 上运行。系统基于角色的访问控制验证相同的签名。 LoanPro 还根据用户的权限和合规性控制检查每个请求，然后将操作写入其审计跟踪。接下来的部分描述了这些部分：多代理系统、它调用的工具和网关。

该架构有四个关键组件，它们将图 1 中的各个部分与协调并作用于它们的作曲家代理和调用 API 工具结合起来：

### 使用 Strands Agents SDK 的多代理架构

该解决方案使用使用 Strands Agents SDK 构建的多代理架构。专业代理协作为服务工作流程的不同部分提供服务，而不是使用单个整体模型来处理每项任务。一名代理专注于数据检索和账户汇总。另一个处理操作选择和工作流程建议。作曲代理将每个请求发送给正确的专家并撰写最终响应。这种关注点分离使得每个代理更容易独立评估、调整和扩展。

### 工具使用：数据检索和调用API

代理通过**工具使用**从 LoanPro 的内部系统检索借款人数据，工具使用是 Amazon Bedrock 中用于调用外部函数和 API 的功能。两个主要工具为助手提供支持：

- **数据检索工具：** 从 LoanPro 的数据层获取帐户详细信息、付款历史记录、贷款条款和借款人元数据，如图 1 中的贷款摘要工具所示。它跨越 8 个不同的 API 端点，每个帐户综合了大约 1,400 个字段。
- **调用 API 工具：** 触发 LoanPro 平台内的工作流程操作，例如向代理呈现信息面板或启动预定义的自动化序列。

通过连接到 LoanPro 的现有 API，该助手可以处理实时生产数据，而无需单独的数据管道或数据仓库。

### 使用 AWS Lambda 的 Amazon Bedrock AgentCore 网关

AgentCore Gateway 是代理与其调用的工具之间的安全访问层。它将 LoanPro 的 API 作为模型上下文协议 (MCP) 上的工具向代理公开，处理身份验证并管理这些连接。 [AWS Lambda](https://aws.amazon.com/lambda/) 是一种无服务器计算服务，无需配置或管理服务器即可运行代码，提供网关和 LoanPro 的 API 之间的集成层。该团队选择使用具有 Lambda 的 AgentCore Gateway，而不是直接集成，原因有以下三个。它将身份验证集中在托管入口点，将 LoanPro 的 API 隔离在托管边界后面，并允许添加新工具而无需重新部署代理。这种无服务器方法使基础设施保持轻量级，并根据请求量自动扩展。在图 1 中，代理拦截器（AWS Lambda 函数）调用 AgentCore 运行时上的代理。 AgentCore Gateway 强制执行此访问控制，在每个请求到达贷款汇总工具之前对其进行筛选。由于助手在受监管的贷款环境中运行，因此生产部署将这些组件与附加控件配对。 LoanPro 基于角色的访问控制和合规护栏适用于每个请求，人工智能操作会写入 LoanPro 的审计跟踪中，并归因于指定的负责人。

### 集成到 LoanPro 现有的门户网站

该助手直接嵌入到 LoanPro 现有的门户网站中，与服务代理已经使用的界面相同。代理通过两个组件与人工智能助手交互：

- **账户摘要视图：** 当代理开设借款人账户时，助手会自动生成账户健康状况、近期活动和未决问题的叙述性摘要。原始数据成为有关借款人情况的连贯故事。
- **对话式聊天界面：** 客服人员可以用自然语言提出后续问题，以更深入地了解特定的帐户详细信息。该团队将此描述为允许代理商“与贷款交谈”。代理与聊天界面的每次交互都会被记录下来，从而维护借款人对话期间所采取操作的可审计记录。

## 实现方式

LoanPro 与 [AWS 生成式 AI 创新中心](https://aws.amazon.com/ai/generative-ai/innovation-center/) 和 AWS 高级咨询合作伙伴 AllCloud 一起构建了该助手，该中心将 AWS 应用科学家与客户和合作伙伴配对，以加速生成式 AI 计划。三个团队共同设计并构建了该解决方案。最初的重点参与现在已投入生产，为 LoanPro 的服务代理提供服务。

这项工作分为两个并行的工作流程：

### 工作流程 1：服务代理助理

主要工作流构建了现已在生产环境中运行的人工智能助手。主要活动包括：

- 选择并映射代理需要检索的数据源（申请数据、贷款历史记录、借款人记录）。
- 开发用于自主数据检索和智能操作选择的代理功能。
- 迭代提示以提高检索准确性和输出质量。
- 记录 LoanPro 的安全模型和集成模式，以告知生产路线图。

### 工作流 2：LLM 帐户规则自动化咨询

LoanPro 拥有现有的概念验证 (POC)，它使用大型语言模型 (LLM) 将自然语言转换为 Clojure 规则引擎的规则自动化代码。核心功能有效，但该解决方案存在已知的局限性：频繁超时、无监控、无部署策略。 AllCloud 进行了架构审查并提供了建议，以使现有的 POC 达到生产就绪状态，包括记录的生产架构和风险评估。

## 评估流程

结构化评估流程根据 LoanPro 主题专家 (SME) 建立的基准验证了代理的准确性。该团队收集了 150 个中小企业标签账户的基准。根据该基准，他们测量了代理检索数据、总结结果和选择适当操作的能力，使其达到代理达到 99% 的准确度目标。该框架继续投入生产，为 LoanPro 提供了一个可重复的流程，用于随着时间的推移衡量和改进代理绩效。

## 结果

部署人工智能助手带来了可衡量的运营影响：

- **客户呼叫时间最多减少 15%**（来源：AllCloud 案例研究）。在 LoanPro 早期推出的贷方合作伙伴的 800 多名服务专业人员中，代理商之前每次通话（1-2.5 分钟，5-7 次点击）的时间都花在了 18-20% 的时间来定位账户。 AI 助手只需单击一次即可将上下文整合在一起，每次通话可节省 1 到近 2 分钟的时间。在这些代理中，每个代理每个工作小时最多可回收 9 分钟的代理容量，每个工作小时大约可回收 120 小时的代理容量。
- **内部票据量减少了近 8%**（来源：LoanPro）。平台上的贷方报告称，随着代理在初次通话期间解决更多案例，支持升级次数减少。
- **在 15 秒内完成账户摘要**（来源：LoanPro 内部基准）。叙述性摘要可在开户后 15 秒内将原始借款人数据转换为连贯的账户故事，取代了代理商之前需要 3 至 5 分钟的手动导航。
- **一致的服务质量**。该助理向整个平台的客服人员提供相同级别的帐户背景和操作建议，从而减少与个人经验水平相关的可变性。
- **符合合规性的交互日志记录**。代理通过人工智能助手进行的每个操作和查询都会被记录下来，从而提供借款人对话期间交互的可审计记录。
- **负责任的人工智能控制**。 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 将内容过滤和接地验证与 LoanPro 的合规护栏和基于角色的访问控制 (RBAC) 一起应用于代理响应，从而在输出到达服务代理和借款人之前将其保持在策略范围内。

> “人工智能助理改变了客服人员的工作方式。客服人员现在不再需要在每次通话的前几分钟浏览屏幕和组装上下文，而是打开一个帐户，立即查看整体情况，并提供有关下一步要采取的行动的说明性建议。数千次通话所节省的时间会进一步增加。”
> — Colin Terry，LoanPro 首席产品官

## 展望未来

在服务代理助理取得成功的基础上，LoanPro 和 AllCloud 正在扩大合作。这些团队正在开发更多的人工智能代理，以将智能功能扩展到贷款工作流程的更多部分，从服务范围扩展到催收和发起支持等领域。

模块化的多代理架构使这种扩展变得切实可行。可以使用相同的 Amazon Bedrock AgentCore 基础设施独立构建和部署新代理，而无需重新设计核心系统。随着 Strands Agents SDK 和 Amazon Bedrock AgentCore 的不断发展，LoanPro 计划在新功能可用时将其纳入其中。

＃＃ 结论

在这篇文章中，我们展示了 LoanPro、AWS 生成式 AI 创新中心和 AllCloud 如何使用 Amazon Bedrock 和 Amazon Bedrock AgentCore 构建多代理 AI 助手，以帮助服务代理更快、更一致地解决借款人呼叫。该解决方案自动检索数据，实时生成帐户摘要，并推荐下一个最佳操作，从而将客户呼叫时间减少多达 15%。
