# 推出 Amazon Bedrock Trusted Access API，集成 Anthropic 的 Enterprise Frontier Safeguards 与 Enterprise Data Controls

今天，我们宣布 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的 trusted access program API 全面可用。该 API 为您提供一个统一入口，用于发现、申请和加入模型提供方的 trusted access program。我们还宣布首批两个产品的公开预览：Anthropic 的 Enterprise Frontier Safeguards（EFS）和 Enterprise Data Controls（EDC）。两者均可在 Amazon Bedrock 上使用，涵盖 Claude Fable、Claude Mythos，以及通过 [Cyber Verification Program](https://support.claude.com/en/articles/14604842-cyber-verification-program)（CVP）使用的 Claude Opus 5.5 和 Sonnet 5.5。

前沿 AI 实验室对其最强大的模型要求更严格的安全监控策略，这些策略在 Amazon Bedrock 上仍然适用。对于符合条件的客户，模型提供方还让客户对这些策略的满足方式拥有更多控制权，例如保留数据存储在哪里以及如何被审查。每个产品都有各自的条款、审批和设置。

Amazon Bedrock trusted access program API 为每个提供方的产品提供一致的 Amazon Bedrock 体验。您的团队以相同方式为每个提供方发现产品、检查资格并加入。您的管理员使用现有 IAM 策略和服务控制策略决定谁可以加入。随着更多模型提供方增加产品，这些产品会出现在同一位置。

EFS 和 EDC 由 AWS 与 Anthropic 合作构建。它们让您从模型使用和客户数据两个角度安全地访问 Anthropic 最强大的模型。使用 EFS 和 EDC 时，当自动化安全监控发现风险，会创建一个 Safety Case 供您的团队审查。使用 EFS 时，客户将数据存储在自己的 AWS 账户中，提示和补全内容不会被 Anthropic 或 Amazon Bedrock 保留。使用 EDC 时，保留数据存储在 Amazon 托管存储中，而非您的账户中，且提示和补全内容不会被 Anthropic 保留。一份申请即可访问两个计划。

在本文中，我们解释 trusted access program API 如何工作，然后介绍 EFS 和 EDC 的存储选项与设置。

## trusted access programs 如何工作

trusted access program 是模型提供方的一项具名计划，客户接受该计划条款，即可在安全审查和模型能力访问方面获得更多控制权。Amazon Bedrock trusted access program API 现在为您提供一个统一入口，用于查找您的账户可用的模型和用例计划。EFS 和 EDC 是今天首批可用的产品。提供方之后新增的产品会出现在同一位置，并遵循相同步骤。

任何有权访问 trusted access program API 的人，都可以列出产品，并检查某个账户、AWS Organizations 中的某个组织或某个 Amazon Bedrock 项目的状态。状态会告诉您下一步该做什么。`eligible` 表示您符合该产品的资格并且可以加入，`requestable` 表示您需要先获得资格审批，响应中的 `statusReason` 字段会说明如何申请。模型提供方（或经模型提供方授权的 AWS）批准您的资格。

加入是一个单独步骤，您在该步骤中接受提供方施加的产品条款。您在获批的范围内加入：一个账户、从管理账户加入组织中的每个账户，或单个项目。您可以随时退出。每个步骤都是对 trusted access program API 的一次调用，因此您可以通过 AWS Identity and Access Management（IAM）策略和服务控制策略（SCP）控制谁可以加入。更多信息请参阅 [trusted access programs documentation](https://docs.aws.amazon.com/bedrock/latest/userguide/trusted-access-programs.html)。

## Enterprise Frontier Safeguards

借助 Enterprise Frontier Safeguards（EFS），您可以将数据保留在自己的 AWS 环境中并拥有完全控制权。它是与 100 多家客户共同设计的，包括四分之一的 Fortune 100 企业，以及医疗、金融服务和法律等对数据可见性有严格规定的行业中的许多公司。

自动化安全监控寻找仅在大量请求中才会出现的模式。这些模式包括可能导致严重伤害的故意滥用，例如攻击性网络行动。还包括超出用户请求范围的 agent 行为，例如利用软件漏洞访问内部系统。

在 Amazon Bedrock 上，AWS 运营 EFS，客户输入和输出保留在客户的 AWS 账户内。只有 AWS 内的自动化安全监控会读取保留的输入和输出。AWS 人工审查员不会为 EFS 审查内容。审查由您负责。AWS 和 Anthropic 的人员均不会访问您保留的输入或输出。您的输入和输出绝不会用于训练。

### 工作原理

Amazon Bedrock 以单个 AWS 服务主体身份，仅通过您编写的密钥策略和存储桶策略，访问您的 [AWS Key Management Service](https://aws.amazon.com/kms/)（AWS KMS）密钥和 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）存储桶。您可以随时移除该访问权限，但在 Amazon Bedrock 失去对您的密钥或存储桶的访问权限 24 小时后，它将停止提供受覆盖模型的服务。

当您调用受覆盖模型（包括 Claude Fable、Claude Mythos，以及通过 Cyber Verification Program（CVP）使用的 Claude Opus 5.5 和 Sonnet 5.5）时：

- 您的应用程序调用模型。推理的工作方式与任何 Amazon Bedrock 模型相同。
- Amazon Bedrock 将提示和响应写入其保留服务和密钥服务。
- 这些服务使用您的 AWS KMS 密钥加密数据。
- Bedrock 将提示和响应写入您的存储桶（使用您的密钥加密），或写入 Amazon 托管存储。写入您的存储桶时，Amazon 会在几分钟内写入内容。若您的密钥或存储桶出现某些故障，我们最多可重试 72 小时。
- 自动化安全监控在 AWS 拥有并运营的账户中运行，扫描数据并查找跨请求的滥用行为。
- 如果自动化安全监控发现潜在风险，会在您的存储桶中创建一个 Case 供您审查。

### 您的团队如何处理 Case

一个 Case 概述自动化安全监控发现的内容，并引用相关转录记录。保留记录会到达您的存储桶中 `transcripts/` 前缀下，案例文件会到达 `review-cases/` 下。您的团队审查每个 Case，并将响应文件写入 `review-responses/`，说明是否发现违规（`violation` 或 `no_violation`），若发现违规，还要说明适用的策略类别。

## Enterprise Data Controls

EDC 提供与 EFS 相同的自动化安全监控，对被标记活动的人工审查仍由您的团队负责。与 EFS 不同，EDC 将保留数据存储在 Amazon 托管存储中，使用 AWS 托管密钥加密，因此无需设置存储桶或密钥。符合条件的客户可通过一份加入申请访问 EFS 和 EDC。如果您的策略允许保留数据留在 Amazon 托管存储中并使用 AWS 托管密钥加密，请加入 EDC。如果您的策略要求保留数据使用您的 AWS KMS 密钥加密并留在您的 S3 存储桶中，请加入 EFS。无论哪种方式，您的团队都能审查被标记的活动。

除 EFS 和 EDC 外，您目前可以通过两种方式在 Amazon Bedrock 上使用 Claude Fable 模型：

- 使用 `aws_review` 数据保留模式时，Amazon Bedrock 最多保留输入和输出 30 天，在此期间可在 AWS 边界内审查。
- 符合条件的客户可将当前 Fable 模型用于内部使用，并采用零数据保留（ZDR），至少持续到 2027 年 6 月 30 日。ZDR 结束后，EFS 是长期路径。

## 选择保留数据的存储位置

使用 EFS 时，保留数据仅存储在您自己的 S3 存储桶中，并使用您的 KMS 密钥加密。Anthropic 和 AWS 都不会将其保存在自己的存储中。下表比较 EFS 与其他路径。

|  | **不符合 ZDR、EFS 或 EDC 资格** | **ZDR 例外（临时）** | **EFS，您自己的 Amazon S3 存储桶（公开预览）** | **EDC，Amazon 托管存储（公开预览）** |
| --- | --- | --- | --- | --- |
| **数据保留** | 最多 30 天 | 无；对于当前 Fable 模型和现有 Cyber Verification Program 模型，内部使用至少持续到 2027 年 6 月 30 日 | Amazon Bedrock 不保留副本。适用您的生命周期规则，最短 30 天。 | 最多 30 天，之后 Amazon Bedrock 将其删除 |
| **保留数据的存储位置** | AWS 托管存储 | 不保留 | 您的 Amazon S3 存储桶 | Amazon 托管存储 |
| **加密密钥** | AWS 托管 | 不适用 | 您的 AWS Key Management Service（AWS KMS）密钥 | AWS 托管 |
| **安全监控** | 可在 AWS 边界内审查 | 无 | 自动化。Case 会进入您的存储桶，供您的团队审查。 | 自动化。您的团队审查被标记的 Case。公开预览期间不会交付 Case。 |
| **您的 [AWS CloudTrail](https://aws.amazon.com/cloudtrail/) 显示的内容** | 您的 Amazon Bedrock API 调用 | 您的 Amazon Bedrock API 调用 | 您的 Amazon Bedrock API 调用，以及 Amazon Bedrock 对您的密钥和存储桶的使用 | 您的 Amazon Bedrock API 调用 |
| **存储成本** | 不适用 | 不适用 | 常规的 Amazon S3 和 AWS KMS 费用 | 不适用 |

*表 1：Amazon Bedrock 上 Claude Fable 模型的路径。*

存储配置一次仅适用于一个区域，没有配置的区域使用 Amazon 托管存储。在您调用受覆盖模型的每个区域中保存配置。

## 开始使用

首先使用 trusted access program API 检查您的 EFS 状态：

```
aws bedrock list-trusted-access-programs --region us-east-1
```

如果状态为 `eligible`，您的账户已获批。如果为 `requestable`，请按照 `statusReason` 字段中的步骤申请访问权限。加入预览会为您添加的账户关闭零数据保留。

获批后，在您调用受覆盖模型的每个区域中设置 EFS：

- **在同一区域创建一个 AWS KMS 密钥和一个 Amazon S3 存储桶**。密钥策略和存储桶策略仅通过其服务主体授予 Amazon Bedrock 访问权限，且仅针对您账户的数据。
- **授予您的角色权限**以保存存储配置。
- **保存您的存储配置。** Amazon Bedrock 会在保存前检查您的密钥和存储桶设置，如果任何检查失败，错误信息会指出失败的检查项。
- **将您的数据保留模式设置为** `aws_review`。
- **调用 Claude Fable 模型**，然后确认 AWS CloudTrail 显示 Amazon Bedrock 使用了您的密钥。保留记录通常会在几分钟内出现在您的存储桶中，但如果 Amazon Bedrock 必须重试，则可能需要长达 72 小时。

[EFS documentation](https://docs.aws.amazon.com/bedrock/latest/userguide/anthropic-efs-enterprise-data-controls.html) 提供了每个步骤的完整密钥策略、存储桶策略、IAM 策略和 API 调用。它还涵盖组织和项目配置以及故障排除。若要改用企业数据控制，请跳过步骤 1 和 2，并在步骤 3 中选择 Amazon 托管存储。

## 结论

trusted access program API 现已全面可用，为您提供一种统一方式，在 Amazon Bedrock 上查找模型提供方产品、检查您的状态并加入，同时由 IAM 策略和 SCP 控制谁可以加入。EFS 和 EDC 是首批进入公开预览的产品。它们让您在使用 Claude Fable 和 Cyber Verification Program 模型时掌控自己的数据。使用您自己的 Amazon S3 存储桶时，Amazon Bedrock 不保留数据副本，您的 AWS KMS 密钥对其进行加密，每次访问都会显示在您自己的 AWS CloudTrail 日志中。

要开始使用，请通过 `aws bedrock list-trusted-access-programs` 检查您的 EFS 状态，并加入 EFS 预览。要了解更多信息，请参阅 [trusted access programs documentation](https://docs.aws.amazon.com/bedrock/latest/userguide/trusted-access-programs.html) 和 [EFS/EDC documentation](https://docs.aws.amazon.com/bedrock/latest/userguide/anthropic-efs-enterprise-data-controls.html)。

要加入 EFS 和 EDC 公开预览，请与您的 AWS 账户团队合作提交请求。请准备好 AWS 账户 ID（对于项目，请准备 Amazon Bedrock 运行时项目 ARN），并注意该预览面向已加入 EFS ZDR 的客户。
