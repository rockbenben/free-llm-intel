# Amazon Bedrock 推出 Trusted Access API，支持 Anthropic 的 Enterprise Frontier Safeguards 和 Enterprise Data Controls

今天，我们宣布可信访问计划 API 在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 正式推出。你可以通过这一入口查找模型提供商的可信访问计划、申请资格并加入。我们也宣布首批两项服务开放公开预览，分别是 Anthropic 的 Enterprise Frontier Safeguards（EFS）和 Enterprise Data Controls（EDC）。两项服务均可在 Amazon Bedrock 上使用，覆盖 Claude Fable、Claude Mythos，以及通过 [Cyber Verification Program](https://support.claude.com/en/articles/14604842-cyber-verification-program)（CVP）使用的 Claude Opus 5.5 和 Sonnet 5.5。

前沿 AI 实验室会针对能力最强的模型制定更严格的安全监控策略。这些策略在 Amazon Bedrock 上也适用。对于符合资格的客户，模型提供商还会让客户自行控制更多策略执行细节，例如保留数据的存放位置和审查方式。各服务有各自的条款、审批流程和设置。

Amazon Bedrock 的可信访问计划 API 为不同提供商的服务提供统一的使用方式。无论提供商是谁，你的团队都可以按相同流程查找服务、检查资格并加入。管理员可以利用现有的 IAM 策略和服务控制策略决定哪些人可以加入。更多模型提供商上线服务后，也会出现在同一入口。

EFS 和 EDC 由 AWS 与 Anthropic 合作开发，让你在安全使用模型和保护客户数据的前提下访问 Anthropic 能力最强的模型。对 EFS 和 EDC 来说，自动化安全监控一旦发现风险，就会创建一条 Safety Case 记录供你的团队审查。使用 EFS 时，客户把数据保存在自己的 AWS 账户中，Anthropic 和 Amazon Bedrock 均不保留提示词和补全结果。使用 EDC 时，保留的数据存放在 Amazon 托管的存储中，Anthropic 不保留提示词和补全结果。提交一份申请即可获得两项计划的使用资格。

本文先介绍可信访问计划 API 的工作方式，再说明 EFS 和 EDC 的存储选项及设置流程。

## 可信访问计划如何运作

可信访问计划是由模型提供商设立并命名的计划。客户接受计划条款后，即可获得相应的模型能力，并对安全审查拥有更多控制权。现在，你可以通过 Amazon Bedrock 的可信访问计划 API，集中查找对你的账户开放的模型与用例计划。EFS 和 EDC 是今天上线的首批服务。提供商之后新增的服务也会在同一入口显示，使用流程相同。

有权访问可信访问计划 API 的用户，可以列出服务，并查看账户、AWS Organizations 中的组织或 Amazon Bedrock 项目的资格状态。状态会提示下一步操作。`eligible` 表示已有资格，可以加入。`requestable` 表示要先申请资格，响应中的 `statusReason` 字段会说明如何申请。资格由模型提供商审批，也可由提供商授权 AWS 审批。

加入是单独的一步，你需要接受提供商规定的服务条款。你可以在获批的范围内加入，范围可以是单个账户、由管理账户代表组织内的所有账户加入，或单个项目。你可以随时退出。每一步都会调用可信访问计划 API，因此可以使用 AWS Identity and Access Management（IAM）策略和服务控制策略（SCP）控制谁可以加入。详情见[可信访问计划文档](https://docs.aws.amazon.com/bedrock/latest/userguide/trusted-access-programs.html)。

## Enterprise Frontier Safeguards

借助 Enterprise Frontier Safeguards（EFS），你可以将数据保留在自己的 AWS 环境中，并完全掌控它。EFS 在设计过程中与 100 多家客户合作，其中包括四分之一的 Fortune 100 企业，以及医疗、金融服务、法律等对数据可见性有严格规定的行业中的许多公司。

自动化安全监控会查找只有结合多条请求才会显现的模式。其中包括可能造成严重危害的故意滥用，例如进攻性网络行动，也包括 agent 超出用户要求采取的行动，例如利用软件漏洞访问内部系统。

在 Amazon Bedrock 上，EFS 由 AWS 运营，客户的输入和输出始终留在客户自己的 AWS 账户中。只有在 AWS 内运行的自动化安全监控可以读取保留的输入和输出。AWS 审查人员不为 EFS 审查内容，审查由你的团队负责。AWS 和 Anthropic 的人员均不访问保留的输入或输出。输入和输出也绝不会用于训练。

### 工作方式

Amazon Bedrock 以单一 AWS 服务主体的身份访问你的 [AWS Key Management Service](https://aws.amazon.com/kms/)（AWS KMS）密钥和 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）存储桶，访问完全受你编写的密钥策略和存储桶策略约束。你可以随时撤销访问权限。Amazon Bedrock 在失去对密钥或存储桶的访问权限 24 小时后，会停止提供适用的模型。

图 1　Amazon Bedrock 上的 EFS 工作流程

调用适用模型时，包括 Claude Fable、Claude Mythos，以及通过 Cyber Verification Program（CVP）使用的 Claude Opus 5.5 和 Sonnet 5.5，流程如下。

- 应用调用模型。推理方式与其他 Amazon Bedrock 模型相同。
- Amazon Bedrock 将提示词和响应写入其数据保留和密钥服务。
- 这些服务使用你的 AWS KMS 密钥加密数据。
- Bedrock 将提示词和响应写入你的存储桶，使用你的密钥加密，或写入 Amazon 托管的存储。写入你的存储桶时，Amazon 会在几分钟内完成。遇到某些密钥或存储桶故障时，我们最多可重试 72 小时。
- 自动化安全监控在 AWS 拥有并运营的账户内运行，扫描数据并查找跨请求的滥用行为。
- 如果自动化安全监控发现潜在风险，就会在你的存储桶中创建一条案例记录供审查。

### 团队如何处理案例

Case 会概述自动化安全监控发现的问题，并引用相关的对话记录。保留的数据记录写入存储桶的 `transcripts/` 前缀，案例文件写入 `review-cases/` 前缀。你的团队审查每条 Case，并将响应文件写入 `review-responses/`，说明是否发现违规（`violation` 或 `no_violation`），有违规时还要注明适用的策略类别。

## Enterprise Data Controls

EDC 提供与 EFS 相同的自动化安全监控。被标记活动的人工审查也由你的团队负责。EDC 将保留的数据存放在 Amazon 托管的存储中，并使用 AWS 托管的密钥加密，因此无需自行设置存储桶或密钥。符合资格的客户只需提交一份加入申请，即可访问 EFS 和 EDC。如果你的策略允许将保留的数据放在 Amazon 托管的存储中并使用 AWS 托管的密钥加密，可以加入 EDC。如果你的策略要求以自己的 AWS KMS 密钥加密保留数据，并将其留在自己的 S3 存储桶中，可以加入 EFS。采用任一方案，你的团队都可以审查被标记的活动。

除 EFS 和 EDC 外，目前还有两种方式在 Amazon Bedrock 上使用 Claude Fable 模型。

- 在 `aws_review` 数据保留模式下，Amazon Bedrock 最多保留输入和输出 30 天，保留期间可在 AWS 边界内进行审查。
- 符合资格的客户至少在 2027 年 6 月 30 日之前，可以采用零数据保留（ZDR）方式在内部使用当前的 Fable 模型。ZDR 到期后，可长期使用 EFS。

## 选择保留数据的存放位置

使用 EFS 时，保留的数据仅存放在你自己的 S3 存储桶中，由你的 KMS 密钥加密。Anthropic 和 AWS 均不会在自己的存储中保留这些数据。下表比较了 EFS 和其他方案。

|  | **不具备 ZDR、EFS 或 EDC 资格** | **ZDR 例外（过渡期）** | **EFS，使用自己的 Amazon S3 存储桶（公开预览）** | **EDC，使用 Amazon 托管的存储（公开预览）** |
| --- | --- | --- | --- | --- |
| **数据保留** | 最多 30 天 | 不保留，至少持续至 2027 年 6 月 30 日，适用于当前 Fable 模型和现有 Cyber Verification Program 模型的内部使用 | Amazon Bedrock 不保留副本。由你的生命周期规则决定，至少保留 30 天。 | 最多 30 天，之后由 Amazon Bedrock 删除 |
| **保留数据的存放位置** | AWS 托管的存储 | 不保留 | 你的 Amazon S3 存储桶 | Amazon 托管的存储 |
| **加密密钥** | AWS 托管 | 不适用 | 你的 AWS Key Management Service（AWS KMS）密钥 | AWS 托管 |
| **安全监控** | 可在 AWS 边界内审查 | 无 | 自动化监控。案例写入你的存储桶，由你的团队审查。 | 自动化监控。你的团队审查被标记的 Case。公开预览期间不交付 Case。 |
| **[AWS CloudTrail](https://aws.amazon.com/cloudtrail/) 显示的信息** | 你的 Amazon Bedrock API 调用 | 你的 Amazon Bedrock API 调用 | 你的 Amazon Bedrock API 调用，以及 Amazon Bedrock 对你的密钥和存储桶的使用情况 | 你的 Amazon Bedrock API 调用 |
| **存储成本** | 不适用 | 不适用 | 正常的 Amazon S3 和 AWS KMS 费用 | 不适用 |

*表 1　Amazon Bedrock 上使用 Claude Fable 模型的方案。*

存储配置按区域生效。未配置的区域使用 Amazon 托管的存储。请在调用适用模型的每个区域分别保存配置。

## 开始使用

先用可信访问计划 API 检查你的 EFS 资格状态。

```
aws bedrock list-trusted-access-programs --region us-east-1
```

状态为 `eligible` 表示你的账户已获批。若状态为 `requestable`，请按照 `statusReason` 字段中的步骤申请访问权限。加入预览后，你所添加的账户将关闭零数据保留。

获批后，在调用适用模型的每个区域中设置 EFS。

- **在同一区域创建 AWS KMS 密钥和 Amazon S3 存储桶。** 密钥和存储桶策略只允许 Amazon Bedrock 通过其服务主体访问，且只允许访问你的账户数据。
- **为你的角色授予权限**，以便保存存储配置。
- **保存存储配置。** Amazon Bedrock 会在保存前检查密钥和存储桶设置，出错时会指出哪项检查未通过。
- **将数据保留模式设置为** `aws_review`。
- **调用 Claude Fable 模型**，然后通过 AWS CloudTrail 确认 Amazon Bedrock 使用了你的密钥。保留的记录通常会在几分钟内出现在存储桶中。如果 Amazon Bedrock 需要重试，最多可能需要 72 小时。

[EFS 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/anthropic-efs-enterprise-data-controls.html)列出了完整的密钥策略、存储桶策略和 IAM 策略，以及每一步的 API 调用。文档也涵盖组织和项目级配置及故障排查。如果选择 Enterprise Data Controls，跳过第 1 和第 2 步，在第 3 步选择 Amazon 托管的存储。

## 结语

可信访问计划 API 已正式推出。你可以在同一入口查找 Amazon Bedrock 上的模型提供商服务、查询状态并加入。哪些人可以加入，由 IAM 策略和 SCP 控制。EFS 和 EDC 是首批开放公开预览的服务，让你在使用 Claude Fable 和 Cyber Verification Program 模型时掌控自己的数据。使用你自己的 Amazon S3 存储桶时，Amazon Bedrock 不保留任何副本。数据由你的 AWS KMS 密钥加密，每次访问都会出现在你自己的 AWS CloudTrail 日志中。

要开始使用，请通过 `aws bedrock list-trusted-access-programs` 查询你的 EFS 资格状态，并加入 EFS 预览。更多信息参见[可信访问计划文档](https://docs.aws.amazon.com/bedrock/latest/userguide/trusted-access-programs.html)和 [EFS/EDC 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/anthropic-efs-enterprise-data-controls.html)。

要加入 EFS 和 EDC 的公开预览，请联系你的 AWS 客户团队提交申请。请准备好 AWS 账户 ID。如果申请范围是项目，则准备 Amazon Bedrock runtime 项目 ARN。预览面向已加入 EFS ZDR 的客户。
