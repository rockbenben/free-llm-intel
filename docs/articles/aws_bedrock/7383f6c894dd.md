# 释放 Amazon Bedrock Data Automation 的多模态能力，把非结构化数据转化为可执行的洞察

Gartner 预测：“到 2027 年，[40% 的生成式 AI 解决方案将是多模态的](https://www.gartner.com/en/newsroom/press-releases/2024-09-09-gartner-predicts-40-percent-of-generative-ai-solutions-will-be-multimodal-by-2027)（文本、图像、音频和视频），高于 2023 年的 1%。”

《[McKinsey 2023 年 AI 现状报告](https://www.the-digital-insurer.com/library/library-mckinsey-the-state-of-ai-in-2023-generative-ais-breakout-year/)》把数据管理列为 AI 应用与规模化的主要障碍。企业会产生海量非结构化数据，从法律合同到客户交互记录，然而提取有意义的洞察仍然是一大挑战。传统上，把原始数据转化为可执行的智能需要大量的工程投入，往往要管理多个机器学习（ML）模型、设计复杂的工作流，并把多元数据源整合成可用于生产的格式。

结果就是昂贵、脆弱的工作流，需要持续维护和工程资源。而根据 [Gartner](https://researchworld.com/articles/possibilities-and-limitations-of-unstructured-data#:~:text=According%20to%20Gartner%2C%20unstructured%20data,and%20how%20fast%20it's%20growing.%E2%80%9D) 的说法，在一个超过 80% 的企业数据都是非结构化的世界里，企业需要更好的方式来提取有意义的信息，以驱动创新。

今天，我们很高兴宣布 [Amazon Bedrock Data Automation](https://aws.amazon.com/bedrock/bda/) 正式可用。它是 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 中一项强大且全托管的特性，能为你的 AI 应用自动从文档、图像、音频和视频等非结构化多模态内容中生成有用的洞察。它让组织可以从多模态内容中提取有价值的信息，释放数据的全部潜力，而无需深厚的 AI 专业能力，也不必管理复杂的多模态 ML 流水线。借助 Amazon Bedrock Data Automation，企业可以加速 AI 应用，并开发出安全、可扩展且负责任的解决方案。

## 使用 Amazon Bedrock Data Automation 的优势

Amazon Bedrock Data Automation 提供一个统一的 API，自动处理非结构化多模态内容，把编排多个模型、微调 prompt 以及拼接输出的复杂性降到最低。它有助于确保高准确率和成本效率，同时显著降低处理成本。

Amazon Bedrock Data Automation 以负责任 AI 为构建基础，通过可视化溯源和置信度分数提升透明度，让输出在进入关键业务工作流之前可以被验证。它遵循企业级的安全与合规标准，让你可以放心地部署 AI 解决方案。它还让你可以定义数据何时按原样抽取、何时应当被推断，从而对整个流程拥有完全的控制。

跨区域推理通过使用不同 AWS 区域的计算资源，无缝管理计划外的流量高峰。Amazon Bedrock Data Automation 会通过在同一地理范围内的区域之间自动路由，充分利用可用的 AWS 区域容量，在不增加额外费用的情况下最大化吞吐量。例如，在美国发起的请求会留在美国的区域内。Amazon Bedrock Data Automation 目前在美国西部（俄勒冈）和美国东部（弗吉尼亚北部）AWS 区域可用，有助于确保请求的无缝路由和更高的可靠性。Amazon Bedrock Data Automation 正在扩展到更多区域，请务必查看[文档](http://docs.aws.amazon.com/bedrock/latest/userguide/bda-cris.html)以获取最新信息。

Amazon Bedrock Data Automation 提供透明且可预测的定价，依据是所处理内容的模态和所使用的输出类型（[标准输出](https://docs.aws.amazon.com/bedrock/latest/userguide/bda-standard-output.html) 与[自定义输出](https://docs.aws.amazon.com/bedrock/latest/userguide/bda-custom-output-idp.html)）。按页面数、图像数量以及音频和视频文件的时长付费。这种直观的定价模式比基于 token 的定价模式更容易计算成本。

### 智能文档处理

根据 [Fortune Business Insights](https://www.fortunebusinessinsights.com/intelligent-document-processing-market-108590)，**智能文档处理行业**预计将从 2025 年的 105.7 亿美元增长到 2032 年的 666.8 亿美元，复合年增长率（CAGR）为 30.1%。[IDP](https://aws.amazon.com/ai/generative-ai/use-cases/document-processing/) 正在为各行业的关键工作流提供动力，让企业以速度和准确性扩展规模。**金融机构**用 IDP 自动化**税务表单和欺诈检测**，**医疗健康机构**则简化**理赔处理和病历数字化**。**法务团队**加速**合同分析与合规审查**；在**石油天然气**行业，IDP 强化**安全报告**。**制造商和零售商**优化**供应链与发票处理**，帮助确保运营顺畅。在**公共部门**，IDP 改善**市民服务、立法文件管理和合规追踪**。随着企业追求更高程度的自动化，IDP 不再是一个选项，而是**降低成本、提升运营效率、实现数据驱动决策**的必需品。

让我们来看一个真实用例，展示 Amazon Bedrock Data Automation 如何提升贷款处理的效率。

贷款处理是一个复杂的多步流程，涉及文件核验、信用评估、政策合规检查和审批工作流，每个阶段都要求精确与高效。下图展示了使用传统 AWS AI 服务进行贷款处理的过程。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/10/Idp-diagram-01.gif)

如上图所示，贷款处理是一个多步工作流，需要处理多种文件类型、管理模型输出，并在多个服务之间拼接结果。传统做法中，来自门户、电子邮件或扫描件的文档存储在 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/) 中，需要自定义逻辑来拆分多文档包。接着，由 [Amazon Comprehend](https://aws.amazon.com/comprehend/) 或自定义分类器把它们归入 W2、银行对账单、结算披露等类型，同时由 [Amazon Textract](https://aws.amazon.com/textract) 抽取关键细节。还需要额外的处理来统一格式、管理 JSON 输出并对齐数据字段，这往往需要人工集成和多次 API 调用。在某些情况下，基础模型（FM）还会生成文档摘要，进一步增加复杂度。此外，对于阈值偏低的输出，可能还需要人在环路中核验。

借助 Amazon Bedrock Data Automation，整个流程现在被简化为一次统一的 API 调用。它自动完成文档分类、数据抽取、校验和结构化，不再需要人工拼接、API 编排和自定义集成，从而显著降低复杂度并加速贷款处理工作流，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/10/idp-diagram-02.gif)

如上图所示，使用 Amazon Bedrock Data Automation 时，来自第三方系统、门户、电子邮件或扫描件的贷款包存储在 Amazon S3 中，由 Amazon Bedrock Data Automation 自动完成文档拆分和处理，不再需要自定义逻辑。贷款包被摄取之后，Amazon Bedrock Data Automation 在一步之内就对 W2、银行对账单和结算披露等文档完成分类，免去了单独调用分类模型的需要。随后，Amazon Bedrock Data Automation 依据客户需求抽取关键信息，捕获 W2 中的雇主信息、银行对账单中的交易历史、结算披露中的贷款条款等关键细节。

与需要人工做数据归一化的传统工作流不同，Amazon Bedrock Data Automation 会依据客户提供的输出 schema 自动把抽取到的数据标准化，帮助确保日期格式、货币金额和字段名称一致，而无需额外处理。此外，Amazon Bedrock Data Automation 通过提供摘要输出、抽取字段的边界框和置信度分数来提升合规性与准确性，以极少的投入为下游应用交付结构化、已验证、可直接使用的数据。

总之，Amazon Bedrock Data Automation 让金融机构只需一次统一的 API 调用，就能从摄取到最终输出无缝处理贷款文档，不再需要多个彼此独立的步骤。

虽然这个例子聚焦于金融服务，但同样的原则适用于各行业，用来简化复杂的文档处理工作流。Amazon Bedrock Data Automation 为规模、安全和透明而构建，遵循企业级合规标准，提供可靠的数据保护。借助可视化溯源、置信度分数以及与知识库的无缝集成，它支撑由检索增强生成（RAG）驱动的文档检索，并让生产级 AI 工作流的部署在几天而非几个月内完成。

它还在数据抽取上提供灵活性，同时支持显式抽取和隐式抽取。显式抽取用于明确陈述的信息，例如姓名、日期或具体取值；隐式抽取则推断那些并未直接陈述、但可以通过上下文和推理得出的洞察。这种在抽取类型之间切换的能力，让不同类型的文档都能得到更全面、更细致的数据处理。

这一切通过负责任 AI 实现：Amazon Bedrock Data Automation 让每一个流程都经过负责任 AI 模型，以帮助确保文档自动化的公平性、准确性和合规性。

通过自动化**文档分类、抽取和归一化**，它不仅加速了文档处理，也**增强了知识管理和智能搜索等下游应用**。**有了结构化、已验证的数据，组织可以**释放更深入的洞察**并改进决策**。

这种无缝集成延伸到高效的文档搜索与检索，通过让用户快速访问庞大数据仓库中的关键信息来改变业务运营。通过把非结构化文档集合转化为可搜索的知识库，组织可以无缝地查找、分析并使用自己的数据。对于需要处理海量文档、且快速获取特定信息至关重要的行业尤其有价值。法务团队可以高效检索案件卷宗，医疗健康机构可以调取患者病史和研究论文，政府机构可以管理立法记录和政策文件。在 Amazon Bedrock Data Automation 和 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases) 的支持下，这种集成简化了投资研究、监管申报、临床方案和公共部门记录管理，显著提升各行业的效率。

上面的架构图展示了使用 Amazon Bedrock Data Automation 和 Amazon Bedrock Knowledge Bases 处理并检索多模态内容洞察的流水线。文档、图像、视频和音频等非结构化数据首先被摄取到 Amazon S3 存储桶。随后 Amazon Bedrock Data Automation 处理这些内容，抽取关键洞察并转化为可供进一步使用的形式。处理后的数据存储在 Amazon Bedrock Knowledge Bases 中，由嵌入模型转换为向量表示，再存入向量数据库以支持高效的语义搜索。Amazon API Gateway（WebSocket API）负责实时交互，让用户可以通过 chatbot 或其他界面动态查询知识库。这种架构增强了自动化数据处理、高效检索以及对洞察的无缝实时访问。

### 媒体资产分析与变现

媒体与娱乐（M&E）、广告、游戏和教育行业的公司拥有大量数字资产，例如视频、图像和音频文件，并且需要高效的方式来分析它们。从这些资产中获得洞察，可以实现更好的索引、更深入的分析，并支撑变现与合规工作。

Amazon Bedrock Data Automation 的图像和视频模态为高效抽取和分析提供了进阶特性。

- **图像模态**：支持图像摘要、[IAB 分类法](https://www.iab.com/guidelines/content-taxonomy/)和内容审核。它还包括带边界框和置信度分数的文本检测与 logo 检测。此外，它支持通过 blueprint 对场景分类等用例做可定制的分析。
- **视频模态**：自动完成视频分析工作流、章节切分以及视觉和音频处理。它会生成完整视频摘要、章节摘要、IAB 分类法、文本检测、视觉与音频审核、logo 检测以及音频转录文本。

对视频内容做定制化抽取与分析的方法，涉及从视频的画面和音频两个部分收集信息的复杂过程，构建和管理都相当复杂。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/10/bda-media-then.gif)

如上图所示，定制化的视频分析流水线会从视频的画面部分采样图像帧，并运用专用模型和 FM 来抽取信息，再在镜头（shot）层面聚合。它还会把音频转写成文本，并把视觉和音频数据结合起来做章节级分析。此外，还会应用基于大语言模型（LLM）的分析来得出更深入的洞察，例如视频摘要和分类。最后，数据被存入数据库，供下游应用消费。

现在，使用 Amazon Bedrock Data Automation 进行媒体视频分析，可以把这一工作流简化为一次统一的 API 调用，降低复杂度并减少集成投入，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/10/bda-media-now.gif)

客户可以用 Amazon Bedrock Data Automation 支持以下常见的媒体分析用例：

- **数字资产管理：** 在 M&E 行业，数字资产管理（DAM）指的是对视频、图像、音频文件和元数据等数字内容进行有组织的存储、检索和管理。随着内容库不断增长，媒体公司需要高效的方式来分类、搜索和复用资产，以支持制作、分发和变现。

Amazon Bedrock Data Automation 自动完成视频、图像和音频分析，让 DAM 更具扩展性、更高效、更智能。

- **上下文广告投放：** 上下文广告通过让广告与内容对齐来增强数字营销，但要在视频点播（VOD）中实现它相当有挑战。传统方法依赖人工打标，使这一过程缓慢且难以扩展。

Amazon Bedrock Data Automation 自动完成视频、音频和图像的内容分析，消除了复杂的工作流。它抽取场景摘要、音频片段和 IAB 分类法来支撑视频广告方案，改善上下文广告投放并提升广告投放效果。

- **合规与审核：** 媒体合规与审核确保数字内容遵守法律、伦理以及特定环境的准则，以保护用户并维护品牌形象。这在 M&E、游戏、广告和社交媒体等行业尤为重要，因为这些行业需要审查大量内容是否存在有害内容、版权侵权、品牌安全和监管合规问题。

Amazon Bedrock Data Automation 通过 AI 驱动的内容审核来分析媒体的画面与音频两部分，从而简化合规工作。这让用户可以定义并应用定制策略，依据其特定的合规要求来评估内容。

### 智能语音分析

Amazon Bedrock Data Automation 被用于智能语音分析，以速度和准确性从音频数据中提炼跨多个行业的洞察。金融机构依靠智能语音分析来监控呼叫中心的合规情况并发现潜在欺诈，医疗健康机构则用它来记录患者交互并优化远程医疗沟通。在零售和酒店行业，语音分析通过从实时反馈和录音交互中挖掘洞察来驱动客户参与。随着语音数据指数级增长，智能语音分析已不再是奢侈品——它是降低成本、提升效率、推动更明智决策的重要工具。

#### 客户服务 – 由 AI 驱动的通话分析，带来更好的客户体验

企业可以大规模分析通话录音，从而获得关于客户情绪、合规和服务质量的可执行洞察。联络中心可以用 Amazon Bedrock Data Automation 来：

- 每天转录并总结数以千计的通话，支持说话人分离和关键时刻检测。
- 抽取情绪洞察并对客户投诉分类，以便主动解决问题。
- 通过检测合规缺口和培训需求来改进坐席辅导。

下图展示了一种传统的通话分析方法。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/10/speech-01.gif)

处理客服通话录音涉及多个步骤，从音频采集到先进的 AI 驱动分析，具体如下：

- **音频采集与存储** 来自客户服务交互的通话录音被收集并存储在彼此分散的系统中（例如多个 S3 存储桶和呼叫中心服务商的输出）。由于格式和质量各异，每个文件都可能需要自定义处理。
- **多步处理**：每个处理阶段都需要多个彼此独立的 AI 与机器学习（AI/ML）服务和模型：**转录**：音频文件被送到语音转文本 ML 模型，例如 [Amazon Transcribe](https://aws.amazon.com/transcribe)，以生成不同的音频片段。**通话摘要**：使用 [Amazon Transcribe Call Analytics](https://aws.amazon.com/transcribe/call-analytics/) 或其他生成式 AI FM 生成通话摘要，包含主要问题描述、行动项和结果。**说话人分离与识别**：确定谁在何时说话，需要 Amazon Transcribe 或类似的第三方工具。**合规分析**：必须编排独立的 ML 模型来检测合规问题（例如识别脏话或情绪升级）、实施[个人可识别信息（PII）脱敏](https://docs.aws.amazon.com/transcribe/latest/dg/call-analytics-pii-redaction.html)*，*并标记关键时刻。这些分析由 [Amazon Comprehend](https://aws.amazon.com/comprehend/) 或针对 FM 的独立 prompt 工程来实现。**发现实体**：使用 Amazon Comprehend 或自定义实体检测模型，或可配置的字符串匹配，来发现通话中提到的实体。**音频元数据抽取**：对格式、时长、比特率等文件属性的抽取，由 Amazon Transcribe Analytics 或其他呼叫中心解决方案完成。

- **碎片化的工作流**：这些流程彼此割裂，导致延迟增加、集成复杂度上升，出错风险也更大。需要拼接输出来形成完整视图，这让仪表盘集成和决策变得更加复杂。
