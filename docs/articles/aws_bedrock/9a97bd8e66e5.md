# 在 Amazon Bedrock AgentCore 上运行深度研究 AI agent

AI agent 正在从处理单一任务的基础助手，演变为能够规划、批判并与其他 agent 协作解决复杂问题的更强系统。[Deep Agents](https://blog.langchain.com/deep-agents/) 是最近推出的、基于 LangGraph 构建的框架，它让这些能力成为现实，支持模拟真实团队协作动态的多 agent 工作流。然而，挑战不仅在于构建这类 agent，还在于在生产环境中可靠、安全地运行它们。这正是 [Amazon Bedrock AgentCore Runtime](https://aws.amazon.com/blogs/machine-learning/securely-launch-and-scale-your-agents-and-tools-on-amazon-bedrock-agentcore-runtime/) 的用武之地。Runtime 提供专为 AI agent 和工具打造的、安全无服务器的环境，让 Deep Agents 能够在企业级规模上完成部署，而无需承担管理基础设施的繁重工作。

在本文中，我们演示如何在 AgentCore Runtime 上部署 Deep Agents。如下图所示，AgentCore Runtime 可以扩展任意 agent，并通过为每个新会话分配新的 microVM 来提供会话隔离。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/19/ml19539-1.png)

## 什么是 Amazon Bedrock AgentCore？

[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 同时与框架无关、与模型无关，让你能够灵活、安全且大规模地部署和运行高级 AI agent。无论你使用 [Strands Agents](https://strandsagents.com/latest/)、[CrewAI](https://www.crewai.com/)、[LangGraph](https://www.langchain.com/langgraph)、[LlamaIndex](https://www.llamaindex.ai/) 还是其他框架来构建——并运行在大语言模型（LLM）上——AgentCore 都提供支撑它们的基础设施。其模块化服务专为动态 agent 工作负载打造，既提供扩展 agent 能力的工具，也提供生产使用所需的控制手段。通过消除构建和管理专用 agent 基础设施中那些无差别的繁重工作，AgentCore 让你带上自己偏好的框架和模型即可部署，无需重写代码。

Amazon Bedrock AgentCore 提供一整套全面的能力，旨在把本地的 agent 原型转化为可投入生产的系统。这些能力包括：用于在对话内和跨对话保持上下文的持久记忆；使用 Model Context Protocol（MCP）访问现有 API；与企业身份验证系统的无缝集成；用于网页浏览和代码执行的专用工具；以及对 agent 推理过程的深度可观测性。在本文中，我们专门聚焦 [AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 组件。

## AgentCore Runtime 的核心能力

AgentCore Runtime 提供专为 agentic 工作负载设计的、安全无服务器的托管环境。它把代码打包进一个轻量容器，并提供简单一致的接口，因此同样适合运行 agent、工具、MCP 服务器，或其他能从无缝扩缩容和集成式身份管理中获益的工作负载。AgentCore Runtime 为复杂推理任务提供最长 8 小时的延长执行时间，可处理多模态内容的大负载，并采用按用量计费的方式——仅在活跃处理期间计费，等待 LLM 或工具响应时不计费。每个用户会话都在专用的微型虚拟机（microVM）中完全隔离运行，从而保持安全性，并有助于防止 agent 交互之间发生跨会话污染。该 runtime 可与多种框架（例如 LangGraph、CrewAI、Strands 等）以及多家基础模型提供方配合工作，同时通过单一 SDK 提供内置的企业身份验证、专门的 agent 可观测性，以及对更广泛 AgentCore 环境的统一访问。

## 真实案例：Deep Agents 集成

在本文中，我们将把最近发布的 [Deep Agents 实现示例](https://github.com/hwchase17/deepagents) 部署到 AgentCore Runtime 上——展示让最新的 agent 创新跑起来所需的努力有多么小。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/19/ml19539-2.png)

上图中的示例实现包括：

- 一个**研究 agent**，使用 Tavily API 进行深入的互联网搜索
- 一个**批判 agent**，审查生成的报告并提供反馈
- 一个**主编排器**，管理工作流并处理文件操作

Deep Agents 使用 LangGraph 的状态管理构建一个多 agent 系统，具备：

- 通过 `write_todos` 工具实现的**内置任务规划**，帮助 agent 拆解复杂请求
- **虚拟文件系统**，agent 可以在其中读写文件，以在多次交互之间保持上下文
- **子 agent 架构**，允许为特定任务调用专用 agent，同时保持上下文隔离
- **递归推理**，具有很高的递归上限（超过 1,000），以处理复杂的多步工作流

这一架构使 Deep Agents 能够处理需要多轮信息收集、综合与精炼的研究任务。我们代码中的关键集成点展示了 agent 如何与 AgentCore 配合。其精妙之处在于简单——只需增加几行代码，就能让一个 agent 与 AgentCore 兼容：

```
# 1. Import the AgentCore runtime
from bedrock_agentcore.runtime import BedrockAgentCoreApp
app = BedrockAgentCoreApp()

# 2. Decorate your agent function with @app.entrypoint
@app.entrypoint
async def langgraph_bedrock(payload):
    # Your existing agent logic remains unchanged
    user_input = payload.get("prompt")
    
    # Call your agent as before
    stream = agent.astream(
        {"messages": [HumanMessage(content=user_input)]},
        stream_mode="values"
    )
    
    # Stream responses back
    async for chunk in stream:
        yield(chunk)

# 3. Add the runtime starter at the bottom
if __name__ == "__main__":
    app.run()
```

就是这样！其余代码——模型初始化、API 集成和 agent 逻辑——完全保持原样。AgentCore 负责基础设施，你的 agent 负责智能。这一集成模式适用于大多数 Python agent 框架，使 AgentCore 真正做到与框架无关。

## 部署到 AgentCore Runtime：分步操作

让我们用 [AgentCore Starter ToolKit](https://github.com/aws/bedrock-agentcore-starter-toolkit) 走一遍实际的部署流程，它大幅简化了部署工作流。

### 前提条件

在开始之前，请确保你已具备：

- Python 3.10 或更高版本
- 已配置 AWS 凭证
- 已安装 Amazon Bedrock AgentCore SDK

### 第 1 步：IAM 权限

在 AgentCore Runtime 中部署 agent 时，需要考虑两种不同的 [AWS Identity and Access Management（IAM）](https://docs.aws.amazon.com/iam) 权限——你作为开发者用于创建 AgentCore 资源的角色，以及 agent 在 AgentCore Runtime 中运行所需的执行角色。后者现在可以由 AgentCore Starter Toolkit 自动创建（`auto_create_execution_role=True`），而前者必须按 [IAM Permissions for AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-permissions.html) 中所述进行定义。

### 第 2 步：为你的 agent 添加包装层

如前面的 Deep Agents 示例所示，把 AgentCore 的 import 和装饰器添加到现有 agent 代码中。

### 第 3 步：使用 AgentCore starter toolkit 部署

[starter toolkit](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/getting-started-starter-toolkit.html) 提供三步式部署流程：

```
from bedrock_agentcore_starter_toolkit import Runtime

# Step 1: Configure
agentcore_runtime = Runtime()
config_response = agentcore_runtime.configure(
    entrypoint="hello.py", # contains the code we showed earlier in the post
    execution_role=role_arn, # or auto-create
    auto_create_ecr=True,
    requirements_file="requirements.txt",
    region="us-west-2",
    agent_name="deepagents-research"
)

# Step 2: Launch
launch_result = agentcore_runtime.launch()
print(f"Agent deployed! ARN: {launch_result['agent_arn']}")

# Step 3: Invoke
response = agentcore_runtime.invoke({
    "prompt": "Research the latest developments in quantum computing"
})
```

### 第 4 步：幕后发生了什么

当你执行部署时，starter kit 会自动：

- **生成优化的 Docker file**，基于 Python 3.13-slim 基础镜像并集成 OpenTelemetry 埋点
- **构建你的容器**，使用 `requirements.txt` 中的依赖
- **创建 **[Amazon Elastic Container Registry（Amazon ECR）](https://aws.amazon.com/ecr)** 仓库**（当 `if auto_create_ecr=True` 时）并推送你的镜像
- **部署到 AgentCore Runtime** 并监控部署状态
- **配置网络与可观测性**，集成 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 和 [AWS X-Ray](https://aws.amazon.com/xray)

整个过程通常耗时 2–3 分钟，之后你的 agent 就准备好大规模处理请求了。每个新会话都会在其专属的全新 AgentCore Runtime microVM 中启动，保持完整的环境隔离。

starter kit 会生成一个配置文件（`.bedrock_agentcore.yaml`），其中记录你的部署设置，使后续重新部署或更新 agent 变得非常简单。

## 调用已部署的 agent

部署完成后，你有两种方式调用你的 agent：

方式 1：使用 start kit（如第 3 步所示）

```
response = agentcore_runtime.invoke({
    "prompt": "Research the latest developments in quantum computing"
})
```

方式 2：直接使用 boto3 SDK

```
import boto3
import json

agentcore_client = boto3.client('bedrock-agentcore', region_name='us-west-2')
response = agentcore_client.invoke_agent_runtime(
    agentRuntimeArn=agent_arn,
    qualifier="DEFAULT",
    payload=json.dumps({
        "prompt": "Analyze the impact of AI on healthcare in 2024"
    })
)

# Handle streaming response
for event in response['completion']:
    if 'chunk' in event:
        print(event['chunk']['bytes'].decode('utf-8'))
```

## 结论

Amazon Bedrock AgentCore 代表了我们在部署 AI agent 方式上的一次范式转变。通过抽象掉基础设施的复杂性，同时保持框架和模型的灵活性，AgentCore 让开发者能够专注于构建精密的 agent 逻辑，而不是管理部署 pipeline。我们的 Deep Agents 部署表明，即便是带有外部 API 集成的复杂多 agent 系统，也能以极少的代码改动完成部署。企业级安全、内置可观测性和无服务器扩缩容的结合，使 AgentCore 成为生产环境 AI agent 部署的最佳选择。具体到深度研究 agent，AgentCore 提供以下独特能力供你探索：

- AgentCore Runtime 可以处理异步处理和长时间运行（最长 8 小时）的 agent。异步任务让 agent 可以在响应客户端之后继续处理，并在不阻塞响应的情况下执行长时间运行的操作。你的后台研究子 agent 可以异步研究数小时之久。
- AgentCore Runtime 可与 [AgentCore Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-getting-started.html) 配合，实现诸如在既有发现之上继续构建、记住研究偏好，以及维护复杂的调查上下文而在会话之间不丢失进度等能力。
- 你可以使用 [AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 把深度研究扩展到企业服务和数据源中的专有洞察。通过把这些差异化资源暴露为 MCP 工具，你的 agent 可以快速加以利用，并与公开可用的知识结合起来。

准备好把你的 agent 部署到生产环境了吗？以下是入门方式：

- **安装 AgentCore starter kit**：`pip install bedrock-agentcore-starter-toolkit`
- **动手试验**：按照这份[分步指南](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-getting-started-toolkit.html)部署你的代码。

生产就绪的 AI agent 时代已经到来。借助 AgentCore，从原型到生产的旅程从未如此之短。
