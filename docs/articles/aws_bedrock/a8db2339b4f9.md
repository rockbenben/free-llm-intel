# 使用 AWS CloudFormation 构建基于 Amazon Bedrock AgentCore 的 AI agent

Agentic-AI 已成为部署生产就绪 AI 应用不可或缺的能力，但许多开发者仍苦于在多个环境中手工配置 agent 基础设施的复杂性。[基础设施即代码](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/what-is-iac.html)（IaC）能够提供自主 AI 系统所需的一致、安全且可扩展的基础设施。它通过自动化的资源管理和声明式模板把手工配置错误降到最低，把部署时间从数小时缩短到数分钟，同时促进各环境之间基础设施的一致性，有助于防止不可预测的 agent 行为。它提供版本控制和回滚能力，以便在出现问题时快速恢复，这对保持 agentic 系统的可用性至关重要；它还通过参数化模板实现自动扩缩容和资源优化，使基础设施能够从轻量级开发环境适配到生产级部署。对于在极少人工干预下运行的 agentic 应用而言，IaC 的可靠性、安全标准的自动校验，以及与 DevOps 工作流的无缝集成，对于稳健的自主运行是不可或缺的。

为了简化资源的部署与管理，[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 的各项服务现在已获得多种 IaC 框架的支持，例如 [AWS Cloud Development Kit](https://aws.amazon.com/cdk/)（AWS CDK）、[Terraform](https://developer.hashicorp.com/terraform/tutorials/aws-get-started) 和 [AWS CloudFormation Templates](https://aws.amazon.com/cloudformation/resources/templates/)。这一集成把 IaC 的能力直接带给 AgentCore，开发者因此可以预置、配置并管理其 AI agent 基础设施。在本文中，我们使用 CloudFormation 模板为一个天气活动规划器构建端到端应用。使用 CDK 和 Terraform 的示例可在 [GitHub Sample Library](https://github.com/awslabs/amazon-bedrock-agentcore-samples/tree/main/04-infrastructure-as-code) 中找到。

## 构建基于天气的活动规划 agent

该示例创建了一个天气活动规划器，演示了一个实际应用：它处理实时天气数据，基于关注地点给出个性化的活动推荐。该应用由多个集成组件构成：

- **实时天气数据采集** – 应用从 weather.gov 等权威气象来源获取当前天气状况，收集温度读数、降水概率预报、风速测量以及其他影响户外活动适宜性的相关大气条件等关键数据点。
- **天气分析引擎** – 应用通过定制逻辑处理原始气象数据，基于多个天气因素评估某一天是否适合户外活动：  **温度舒适度评分** – 当温度低于 50°F 时，活动的适宜性评分会被下调  **降水风险评估** – 降雨概率超过 30% 会触发对户外活动推荐的调整  **风力条件影响评估** – 风速超过 15 mph 会影响各类活动的整体舒适度与安全性评级
- **个性化推荐系统** – 应用结合用户偏好和基于位置的感知来处理天气分析结果，生成量身定制的活动建议。

下面我们看看如何用 AgentCore 服务实现这一应用：

- [**AgentCore Browser**](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html) – 用于自动浏览 weather.gov 等来源的天气数据
- [**AgentCore Code Interpreter**](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/code-interpreter-tool.html) – 用于执行处理天气数据、完成计算并实现评分算法的 Python 代码
- [**AgentCore Runtime**](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) – 用于托管一个 agent，由它编排应用流程、管理数据处理流水线并协调各组件之间的交互
- [**AgentCore Memory**](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html) – 用于把用户偏好存储为长期记忆

## 部署 CloudFormation 模板

- 从 github 下载 [End-to-End-Weather-Agent.yaml](https://github.com/awslabs/amazon-bedrock-agentcore-samples/blob/main/04-infrastructure-as-code/cloudformation/end-to-end-weather-agent/end-to-end-weather-agent.yaml) 的 CloudFormation 模板到本地机器
- 在 AWS 控制台中打开 CloudFormation
- 点击 **Create stack** → **With new resources (standard)**
- 选择模板来源（upload file）并选中你的模板
- 输入堆栈名称，并按需修改任何必需参数
- 检查配置并确认 IAM 能力
- 点击 **Submit**，并在 Events 标签页上监控部署进度

## 添加可观测性与监控

AgentCore Observability 提供了关键优势。它通过详细的工作流可视化和实时性能监控带来质量与信任。借助由 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 驱动的仪表板，你可以加快上市时间，这些仪表板减少了来自多个来源的手工数据集成，使你可以基于可落地的洞察采取纠正措施。与 OpenTelemetry 兼容格式的集成灵活性支持 [CloudWatch](https://aws.amazon.com/cloudwatch/)、[DataDog](https://www.datadoghq.com/)、[Arize Phoenix](https://phoenix.arize.com/)、[LangSmith](https://www.langchain.com/langsmith/observability) 和 [LangFuse](https://langfuse.com/docs/observability/overview) 等现有工具。

该服务提供跨框架和[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM）的端到端可追溯性，捕获 token 用量和工具选择模式等关键指标，并同时支持对托管在 AgentCore Runtime 上的 agent 进行自动插桩，以及对部署在其他服务上的 agent 进行可配置监控。这种全面的可观测性方法帮助组织在规模化构建可信赖 AI agent 的同时，实现更快的开发周期、更可靠的 agent 行为和更好的运营可见性。

## 针对你的用例进行定制

天气活动规划器的 AWS CloudFormation 模板采用模块化组件设计，可以无缝适配各种应用。例如，你可以定制 AgentCore Browser 工具，从不同的 Web 应用中采集信息（例如用于投资指导的金融网站、用于情绪监测的社交媒体信息流，或用于价格跟踪的电商网站）；修改 AgentCore Code Interpreter 的算法以处理你特定的业务逻辑（例如销售预测的预测建模、保险的风险评估，或制造业的质量控制）；调整 AgentCore Memory 组件以存储相关的用户偏好或业务上下文（例如客户画像、库存水平或项目需求）；并重新配置 [Strands Agents](https://strandsagents.com/latest/) 的任务，以编排你所属领域的特定工作流（例如供应链优化、客服自动化或合规监控）。

## 部署最佳实践

我们建议在部署时采用以下实践：

- **模块化组件架构** – 为每项 AWS 服务设计独立的区块来组织 AWS CloudFormation 模板。
- **参数化模板设计** – 使用 AWS CloudFormation 参数表示可配置元素，以便模板可跨环境复用。例如，这可以帮助把同一个基础容器关联到多个 agent 部署、指向两套不同的构建配置，或把所选 LLM 参数化以驱动你的 agent。
- [**AWS Identity and Access Management**](https://aws.amazon.com/iam/)**（IAM）安全与最小权限** – 为每个 AgentCore 组件实现细粒度的 IAM 角色，并绑定具体的资源 [Amazon Resource Names](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference-arns.html)（ARN）。请参阅我们关于 [AgentCore 安全注意事项](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/security.html) 的文档。
- **全面的监控与可观测性** – 在各组件上启用 CloudWatch 日志、自定义指标、[AWS X-Ray](https://docs.aws.amazon.com/xray/latest/devguide/aws-xray.html) 分布式追踪和告警。
- **版本控制与持续集成、持续交付（CI/CD）集成** – 在 GitHub 中维护模板，配合自动化校验、全面测试，并使用 AWS CloudFormation StackSets 实现跨区域的一致部署。

你可以在 [CloudFormation 最佳实践](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/best-practices.html) 中找到更完整的最佳实践集合。
