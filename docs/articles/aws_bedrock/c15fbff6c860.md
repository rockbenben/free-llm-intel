# 用 managed entitlements 管理 Amazon Bedrock 的 private pricing offer

在数十乃至数百个 AWS 账户中管理 AI 模型访问，如果每个工作负载账户都必须单独订阅并接受 AWS Marketplace Private Pricing Offer（MPPO），就会产生运维摩擦。[Amazon Bedrock with managed entitlements](https://aws.amazon.com/blogs/machine-learning/simplify-multi-account-access-to-amazon-bedrock-models-with-managed-entitlements/) 简化了第三方 AI 模型的跨账户访问：你只需在中心账户订阅一次，即可把访问权限分发到整个组织。

本文介绍两种在 AWS License Manager 中激活 AWS Marketplace Private Pricing Offer（MPPO）entitlement 的方式。如果你已经信任收到的许可证，只想做一次性的、无需搭建基础设施的处理，就用轻量脚本；如果你想要持续的事件驱动处理——校验卖方、创建并激活分布式 grant——就使用 CDK 自动化方案。

## 为什么要自动化 grant 激活

通过 AWS Marketplace Private Pricing Offer，你可以为 Amazon Bedrock 上的第三方模型协商专属价格。符合条件的 private offer 被接受后，AWS Marketplace 会在 AWS License Manager 中创建一份许可证。在启用了所有功能的 AWS Organizations 中，组织级 grant 会被自动接受，但状态一直保持 Disabled，直到你激活它们。

很多团队的做法是查看 AWS License Manager 控制台、手动激活 grant。人工检查可行，但增加了工作量，也容易遗漏。在有人激活 grant 之前，协商好的 pricing 不会生效。团队每接入新模型或续约一次，同样的工作量就会再现。

## 方案概览

示例代码仓库提供两条路径：

- **路径 1——轻量路径**：一个独立脚本，列出收到的许可证并打印 dry-run 计划。只有当你用 `--apply --confirm-account-id` 重新运行时，它才会创建并激活覆盖整个组织的 grant。它没有卖方 allow-list，因此只有在管理账户中所有收到的许可证都值得信赖时才使用它。
- **路径 2——事件驱动路径**：使用 AWS Cloud Development Kit（AWS CDK）在你的 AWS 管理账户中部署持续运行的自动化。

请从以下两条实现路径中选择其一。不想用 CDK、只做一次性激活，就用路径 1；需要持续的事件驱动自动化，就用路径 2。

### 路径 1：轻量脚本（一次性激活）

当你需要不部署 CDK 的一次性激活时，使用此路径。脚本会列出管理账户中所有收到的许可证，因此请把 dry run 当作应用变更前的审查关卡。

- 将示例仓库克隆到本地并进入项目目录。  `git clone https://github.com/aws-samples/sample-bedrock-managed-entitlements.git cd sample-bedrock-managed-entitlements`
- 以 dry-run 模式运行轻量脚本。  `python3 lightweight/distribute_licenses.py`
- 逐条审查列出的许可证，确认 ISV Partner 发行方和账户范围与你预期的 private offer 一致。
- 在同一个 AWS Organizations 管理账户中应用已审查的计划。  `python3 lightweight/distribute_licenses.py --apply --confirm-account-id ACCOUNT_ID`
- grant 生效之后，在生产环境依赖该 private offer 之前，先验证计费链路。AWS Cost Explorer 中的账单数据可能有延迟，应在费用出现后用它来对比受覆盖的 Amazon Bedrock 用量的实际计费金额。要做可复现的检查，可改造示例 [scripts/bedrock_discount_check.py](https://github.com/aws-samples/sample-bedrock-managed-entitlements/blob/main/scripts/bedrock_discount_check.py) 工具，匹配你的 ISV Partner 发行方，确认预期的折扣链路。

### 路径 2：CDK 自动化（持续激活）

当你希望新的 private pricing 协议被自动处理时，使用此路径。CDK stack 会监听符合条件的 AWS Marketplace 协议事件，检查你的卖方 allowlist，创建分布式 grant，并在 License Manager 需要更多时间时重试激活。该方案包含三个组件：

- **Amazon EventBridge 规则**：stack 在 `us-east-1` 的默认事件总线上监听 AWS Marketplace 协议事件。规则匹配 source `aws.agreement-marketplace` 与 detail type `Purchase Agreement Created - Acceptor`，然后调用 AWS Lambda 函数。
- **AWS Lambda 函数**：该函数接收 AWS Marketplace 协议事件，校验卖方 allow-list，发现许可证，创建分布式 grant，并通过 `CreateGrantVersion(Status=ACTIVE)` 请求激活。函数会把执行结果记录到 [Amazon CloudWatch Logs](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/WhatIsCloudWatchLogs.html)，以便审计。
- **AWS License Manager entitlements**：grant 的目标可以是你的组织、选定的组织单元（OU）或特定账户。只有在 grant 被激活并达到 `ACTIVE` 或 `WORKFLOW_COMPLETED` 状态后，协商的 pricing 才会生效。

这种方式的主要收益：

- **更快用上协商 pricing。**分布式 grant 达到 `ACTIVE` 或 `WORKFLOW_COMPLETED` 后，协商费率即生效，无需等待人工到控制台检查。
- **跨账户处理一致。**同一个 AWS Lambda 函数与 Amazon EventBridge 规则的部署模式，可为每个接收第三方模型 grant 的组织重复部署，激活逻辑不会因操作人员而异。
- **内建审计轨迹。**每次激活尝试或跳过决策都会记录到 CloudWatch Logs，留下每个 grant 何时被激活、延迟或忽略的记录。

#### 前提条件

部署此路径前，确认以下前提条件：

- 使用 `us-east-1` 的 AWS Organizations 管理账户，并已配置 Python 3.12+、AWS Command Line Interface（AWS CLI）和 AWS CDK v2。
- 确认 AWS Organizations 启用了所有功能，且该 private offer 针对的是由 License Manager 支持的 Bedrock 模型。Software as a service（SaaS）产品不在本自动化范围内。

#### 实施步骤

- 将示例仓库克隆到本地并进入项目目录。  `git clone https://github.com/aws-samples/sample-bedrock-managed-entitlements.git cd sample-bedrock-managed-entitlements`
- 验证或启用组织前提条件。  `python3 scripts/bootstrap_prereqs.py --check --region us-east-1`  在做出任何变更前，先检查所有标记为 `APPLY` 或 `MANUAL` 的条目。bootstrap 脚本可以启用 License Manager 组织集成、License Manager 受信访问、AWS Marketplace 许可证管理受信访问，以及所需的服务关联角色。  `python3 scripts/bootstrap_prereqs.py --apply --region us-east-1 --confirm-account-id ACCOUNT_ID`
- 配置部署输入。  `python3 scripts/setup_config.py`  检查 `config/sellers.json`，配置你的 Organization ID、卖方 allow-list、通知，以及可选的 grant 目标。默认情况下，grant 面向整个组织；可用 `grantTargets` 把 grant 的范围限定到选定的 OU 或 AWS 账户。
- 部署 CDK stack。  `cd cdk pip install -r requirements.txt cdk bootstrap aws://ACCOUNT_ID/us-east-1 cdk deploy`
- 用 `config/sellers.json` 为 Amazon DynamoDB 中的卖方 allow-list 灌入初始数据。  `cd .. python scripts/seed_sellers.py --config config/sellers.json`  把卖方 allow-list 当作一条安全边界。在向表中写入数据之前，对照你已接受的 AWS Marketplace private offer 或收到的 License Manager 许可证，逐一核验每个卖方账户 ID。不要添加范围过宽或未经验证的卖方条目，因为匹配上的卖方会在你配置的所有 grant 目标上触发 grant 的创建与激活。完成部署和卖方数据灌入后，stack 即可处理符合条件的 AWS Marketplace 协议事件。只有 allowlist 中经过验证的卖方才会触发 grant 的创建和激活，且激活可能被推迟，直到 License Manager 完成 grant 工作流的处理。
- 验证已部署的自动化。  `python scripts/e2e_validate.py --org-id o-xxxxxxxxxx --seller-account SELLER_ACCOUNT_ID --simulate`
- 在符合条件的 AWS Marketplace 协议事件发生后，验证 grant 是否已激活。  `aws logs tail /aws/lambda/mppo-grants-handler --follow --region us-east-1 python scripts/bedrock_discount_check.py --issuer "ISV Partner"`  激活和账单可见都可能需要数小时甚至数天。事件驱动工作流接受并激活 grant 后，先在 AWS License Manager 中确认 grant 状态，再待账单数据出现后，在 AWS Cost Explorer 中验证受覆盖的 Amazon Bedrock 用量。要做可复现的检查，可改造示例 [scripts/bedrock_discount_check.py](https://github.com/aws-samples/sample-bedrock-managed-entitlements/blob/main/scripts/bedrock_discount_check.py) 工具，匹配你的 ISV Partner 发行方和目标关联账户。

## 清理

如果你只是为了测试部署了这个 stack，请将其删除，以免产生 Lambda 和 Amazon EventBridge 的少量持续费用：

```
cdk destroy
```

## 总结

本文介绍了两种为 Amazon Bedrock private pricing offer 激活 managed entitlements 的方式：对已确认信任的、收到的许可证做一次性激活，用轻量脚本即可；需要针对新的 AWS Marketplace 协议做持续的事件驱动处理，则部署 CDK 自动化。两种方式都能减少人工投入，帮助协商 pricing 在分布式 grant 激活后生效。

要开始使用，请在你的 AWS 管理账户中试用[示例代码](https://github.com/aws-samples/sample-bedrock-managed-entitlements)，让模型订阅自动化。
