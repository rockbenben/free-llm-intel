# Amazon Bedrock 上 Anthropic Claude 模型的结构化输出

Amazon Bedrock 现在支持所有 Anthropic Claude 模型的结构化输出，在模型可用的基岩运行时和基岩地幔端点上。

无论您是通过 Boto3 和 bedrock-runtime API 还是通过 Messages API 和 bedrock-mantle 端点调用 Claude，您现在都可以接收符合已定义结构的符合模式的 JSON 响应。您不再需要自定义解析、重试逻辑或后处理。

## 实际应用

借助 Amazon Bedrock 上 Claude 的结构化输出，您可以跨行业自动执行可靠、符合架构的任务。示例包括从财务收益报告和合规文件中提取每个必填字段、将临床记录解析为电子健康记录 (EHR)，以及通过一致、经过验证的结果丰富产品目录。您还可以分析合同中的关键条款、各方和义务，或者支持智能支持票证路由，其中​​意图、情绪和实体始终与您的应用程序的数据模型相匹配。

## Amazon Bedrock 上的结构化输出有何变化

结构化输出使用约束解码在令牌生成期间（而不是事后）强制执行 JSON 架构。该模型不会生成违反您的架构的标记。这会将输出格式从概率性更改为确定性。

现在，两个 Amazon Bedrock 终端节点都提供了两种补充机制：

| **功能** | **目的** | **用例** |
| --- | --- | --- |
| JSON 模式输出格式 |控制模型的响应结构 |数据提取、报告生成、API 响应 |
|严格工具使用|根据模式验证工具参数 |代理工作流程、函数调用、多步骤自动化 |

## 这对您意味着什么

每个响应都是有效的 JSON，因此您不再遇到“JSON.parse()”错误或解析异常。响应也是类型安全的：强制执行字段类型，并且始终存在必填字段。由于输出始终符合您的架构，因此您无需重试来处理架构违规，从而使您的集成更加可靠。结构化输出还限制仅响应您的架构定义的字段，这减少了输出令牌计数，并可以降低大容量工作负载的推理成本。这些属性使结构化输出做好生产准备，因此您可以大规模部署，而无需额外的架构验证代码。

## 支持的型号和可用性

结构化输出与批量推理配合使用，因此您可以异步处理大量请求，同时仍然接收符合架构的输出。在基岩运行时终端节点上，它还支持跨区域推理，因此您可以跨 AWS 区域使用它，而无需进行额外设置。如果您需要实时响应，您可以将结构化响应作为类型化事件进行流式传输。

## 它是如何工作的

当您使用 JSON 模式发出请求时，幕后会发生以下情况：

- **架构验证 –** Amazon Bedrock 根据支持的 JSON 架构草案 2020-12 子集验证您的 JSON 架构。
- **语法编译 –** 对于新架构，Amazon Bedrock 会编译语法工件（第一个请求可能需要稍长的时间）。
- **缓存 –** 编译后的语法缓存24小时，使后续请求更快。
- **受限生成 –** 模型生成令牌，这些令牌生成与您的架构匹配的有效 JSON。

## 性能考虑

为了提高性能，使用新架构的第一个请求可能需要更长的时间，因为 Amazon Bedrock 在生成开始之前编译语法工件。在初始编译之后，使用相同模式的后续请求将以最小的开销运行，因为编译的语法已被缓存。此缓存的范围仅限于您的帐户，自首次访问起持续 24 小时。更改 JSON 模式的结构会使缓存失效并触发新的编译，而仅更改名称或描述字段会使缓存的语法保持不变。

## 入门：使用 InvokeModel API 进行结构化输出（基岩运行时）

InvokeModel API 采用 Anthropic-native 请求正文，因此模式以 JSON 对象而不是 JSON 字符串的形式进入“output_config.format”。以下示例展示了如何使用 boto3 和 Anthropic Claude 模型从客户电子邮件中提取结构化潜在客户数据：

蟒蛇
```
import boto3
import json

REGION = "us-east-1" # Choose your preferred region
bedrock_runtime = boto3.client(service_name="bedrock-runtime", region_name=REGION)

# Define the JSON schema for structured output
schema = {
    "type": "object",
    "properties": {
        "name": {"type": "string", "description": "Customer name"},
        "email": {"type": "string", "description": "Customer email address"},
        "plan_interest": {"type": "string", "description": "Product plan of interest"},
        "demo_requested": {"type": "boolean", "description": "Whether a demo was requested"}
    },
    "required": ["name", "email", "plan_interest", "demo_requested"],
    "additionalProperties": False
}

# Make a request with structured outputs via the InvokeModel API
# (reusing the schema defined for the Converse example)
response = bedrock_runtime.invoke_model(
    modelId="global.anthropic.claude-sonnet-5-5",
    body=json.dumps({
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 512,
        "messages": [
            {"role": "user", "content": (
                "Paulo Santos (paulo@example.com) is interested in our Enterprise plan "
                "and wants to schedule a demo for next Tuesday at 2pm."
            )}
        ],
        "output_config": {"format": {"type": "json_schema", "schema": schema}}
    })
)

body = json.loads(response["body"].read())

# Check the stop reason before parsing
if body["stop_reason"] == "end_turn":
    result_text = next(b["text"] for b in body["content"] if b["type"] == "text")
    print(json.dumps(json.loads(result_text), indent=2))
elif body["stop_reason"] == "max_tokens":
    print("Response truncated: increase max_tokens and retry.")
```

## 代理工作流程中严格使用工具

[Amazon Bedrock Mantle](https://docs.aws.amazon.com/bedrock/latest/userguide/endpoints.html) 专为具有服务器端工具、后台推理和状态对话的代理应用程序而设计。通过在基岩-地幔端点上严格使用工具，您现在可以保证工具参数与您的输入模式完全匹配。以下示例展示了如何定义具有严格架构强制执行的工具：
```
Import json
from anthropic import AnthropicBedrockMantle

# Reusing the client created in the Messages API example
client = AnthropicBedrockMantle(aws_region="us-east-1")

message = client.messages.create(
    model="anthropic.claude-sonnet-5",
    max_tokens=512,
    messages=[{"role": "user", "content": "What's the weather like in San Francisco?"}],
    tools=[
        {
            "name": "get_weather",
            "description": "Get the current weather for a specified location",
            "strict": True,
            "input_schema": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "The city and state, e.g., San Francisco, CA"
                    },
                    "unit": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                        "description": "Temperature unit"
                    }
                },
                "required": ["location", "unit"],
                "additionalProperties": False
            }
        }
    ]
)

#Tool inputs conform to the schema
for block in message.content:
    if block.type == "tool_use":
        print(f"Tool: {block.name}")
        print(f"Input: {json.dumps(block.input, indent=2)}")
```
设置“strict: true”会限制模型的工具输入与您的模式完全匹配。位置字段始终是字符串，单位字段始终是摄氏度或华氏度。该模型无法添加架构之外的字段，因此工具输入仅包含架构指定的内容。

这对于 Amazon Bedrock Mantle 上的代理用例尤其有价值，其中模型使用 Web 搜索和代码解释器等服务器端工具编排多步骤工作流程。

## Claude 结构化输出的主要用例

结构化输出在三种常见模式中最大程度地降低了错误处理复杂性：

- **数据提取：** 将发票、合同、电子邮件和文字记录中的字段提取到始终与您的架构匹配的 JSON 中，准备好加载到数据库或客户关系管理 (CRM) 系统中。
- **可靠的代理工具调用：** 在生成时根据其模式验证工具参数，因此多步骤代理工作流运行时不会因格式错误的输入而失败。
- **大规模分类：** 按意图、优先级和情绪对工单、潜在客户或内容进行分类，以进行路由、审核和评估。

Claude Haiku 5.5 可靠地处理快速且重复的工作负载，例如摘要、压缩、数据库查询和分类请求。以下示例演示如何使用 Invoke API 和 Haiku 5.5 对传入数据进行分类和路由：
```
import boto3
import json

REGION = "us-east-1" # Choose your preferred region
bedrock_runtime = boto3.client(service_name="bedrock-runtime", region_name=REGION)

# Classification schema: enums restrict output to a fixed set of labels
schema = {
    "type": "object",
    "properties": {
        "category": {
            "type": "string",
            "enum": ["billing", "technical", "account", "sales", "other"],
            "description": "Primary ticket category"
        },
        "priority": {
            "type": "string",
            "enum": ["low", "medium", "high", "urgent"],
            "description": "Urgency based on business impact"
        },
        "sentiment": {
            "type": "string",
            "enum": ["positive", "neutral", "negative"],
            "description": "Customer sentiment"
        },
        "escalate": {"type": "boolean", "description": "Whether a human should review immediately"},
        "reason": {"type": "string", "description": "One-sentence justification for the classification"}
    },
    "required": ["category", "priority", "sentiment", "escalate", "reason"],
    "additionalProperties": False
}

ticket = (
    "Our production API calls have been failing with 500 errors since this morning. "
    "We're losing orders every minute. This is the second outage this month!"
)

# Make a request with structured outputs via the InvokeModel API
response = bedrock_runtime.invoke_model(
    modelId="global.anthropic.claude-haiku-5-5",
    body=json.dumps({
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 512,
        "system": "You are a support ticket classifier. Classify the ticket accurately.",
        "messages": [
            {"role": "user", "content": f"Classify this support ticket:\n\n{ticket}"}
        ],
        "output_config": {"format": {"type": "json_schema", "schema": schema}}
    })
)

body = json.loads(response["body"].read())

# Check the stop reason before parsing
if body["stop_reason"] == "end_turn":
    result_text = next(b["text"] for b in body["content"] if b["type"] == "text")
    result = json.loads(result_text)
    print(json.dumps(result, indent=2))
    # Route the ticket based on the guaranteed-valid labels
    if result["escalate"]:
        print(f"Escalating to on-call: {result['category']} / {result['priority']}")
elif body["stop_reason"] == "max_tokens":
    print("Response truncated: increase max_tokens and retry.")
```
## 要求和最佳实践

要在 Amazon Bedrock 上有效使用结构化输出，请遵循以下准则：

- **在所有对象上设置 extraProperties: false**：这是结构化输出正常工作所必需的。没有它，您的架构将不会被接受。
- **使用描述性字段名称和描述**：模型使用属性名称和描述来了解要提取的数据。像“customer_email”这样的清晰名称优于像“field1”这样的通用名称。
- **使用 enum 来约束值**：当字段具有一组有限的有效值时，使用 `enum` 来约束选项。
- **从基础开始，然后增加复杂性**：从最少的必填字段开始，逐步增加复杂性。基本模式编译速度更快，更容易调试，并保持请求负载精简，因为模式计入 Converse API 负载大小。
- **重用架构以从缓存中受益**：构建应用程序以跨请求重用架构。 24小时语法缓存提高了重复查询的性能。
- **检查每个响应中的停止原因**：两种情况可能会产生不合格的响应：拒绝（当模型出于安全原因而拒绝时）和令牌限制（当在完成之前达到“max_tokens”时）。在代码中处理这两种情况。
- **部署前使用实际数据进行测试**：根据生产代表输入验证您的架构。真实数据中的边缘案例通常会揭示模式设计问题。

有关其他最佳实践和架构设计建议，请参阅 Amazon Bedrock 用户指南中的[结构化输出](https://docs.aws.amazon.com/bedrock/latest/userguide/structured-output.html)。

## 支持的 JSON 模式功能

- 所有基本类型：`object`、`array`、`string`、`integer`、`number`、`boolean`、`null`。
- `enum`（仅限字符串、数字、布尔值或空值）。
- `const`、`anyOf`、`allOf` （有限制）。
- `$ref`、`$def` 和 `definitions`（仅限内部引用）。
- 字符串格式：`日期时间`、`时间`、`日期`、`持续时间`、`电子邮件`、`主机名`、`uri`、`ipv4`、`ipv6`、`uuid`。
- 数组“minItems”（仅值 0 和 1）。

### 不支持

这些关键字被 API 接受，但在生成过程中不会强制执行。包含它们的请求会返回成功的响应，并且模型仍然可以返回违反它们的值。在应用程序中验证这些约束，而不是依赖架构来强制执行它们。

- 递归模式。
- 外部“$ref”引用。
- 数值约束（“最小值”、“最大值”、“multipleOf”）。
- 字符串约束（`minLength`、`maxLength`）。
- `additionalProperties` 设置为 false 以外的任何值。
