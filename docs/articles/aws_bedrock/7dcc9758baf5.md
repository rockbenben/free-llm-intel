# Worldwide Express 如何通过 Amazon Bedrock 自动处理货运异常

Worldwide Express（ShipStation Global 的一部分）取得了巨大成就：全系统收入约为 50 亿美元、超过 75 家零担 (LTL) 承运商和超过 130,000 家客户。但同样的规模也有隐性成本。每个月都有 1500 万美元的自由现金流被冻结，陷入尚未解决的账单异常之中。每一艘都必须由专人逐一逐个航母地追捕，并按照自己的规则进行检查。全球快递外包给一个团队，一次处理一个案例，为每个争议致电客户和承运人。例外情况越来越多，现金陷入困境，每笔订单都需要更长的时间才能变成金钱。

Worldwide Express 与 AWS 和 LTM 合作，利用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 构建多代理 AI 解决方案，该解决方案直接插入其运输管理系统 (TMS) SpeedShip。推出六个月后，该公司报告称，主动例外情况减少了 75%，现金周转时间缩短了 4 周，每年节省 100 万美元，并且一次性注入 1000 万美元的自由现金流。

在这篇文章中，我们描述了挑战，解释了 Worldwide Express 如何设计多代理解决方案，并分享结果。

## 挑战

在 LTL 货运中，大约 14% 的发票未能满足采购订单、收货和承运人发票之间标准的三向匹配。当匹配失败时，发票进入异常处理。对于 Worldwide Express，例外情况分为三类：

- **行项目不匹配：** 数量或服务代码与装运记录不符。
- **定价差异：** 运营商收取的费率与合同价格不同。
- **意外附加费用：** 原始报价中未包含的升降门费、住宅附加费或重新称重调整费。

每个异常都会触发一个包含五个步骤的手动流程：

- 通过对照采购订单、收货和定价交叉引用发票来识别异常类型。
- 研究供应商记录中的根本原因。
- 向承运商或仓库发送包含争议详细信息的电子邮件。
- 等待回复。
- 在 TMS 中执行决议。

由于每个运营商都按照自己的资费结构和争议工作流程运营，因此该流程消耗了 FinOps 团队的大部分带宽。

基于规则的流程自动化 (RPA) 可以处理结构化、可预测的工作流程。然而，异常解决需要上下文判断：解释承运人的辅助政策，将费用与货运数据进行比较，并根据承运人、异常类型和金额确定有效性。这种可变性使得该问题适合代理人工智能框架。

## 从评估到生产

2025 年 6 月，Worldwide Express 与 AWS 业务转型和价值咨询团队合作，确定了整个订单到现金生命周期中的 19 个自动化机会。了解异常自动化的商业价值后，Worldwide Express 在不到 6 个月的时间内从评估转向生产。

## 它是如何工作的

该解决方案在 AWS 上运行。 Amazon Bedrock 提供 AI 推理，[Amazon Elastic Compute Cloud (Amazon EC2)](https://aws.amazon.com/ec2/) 是引擎。该设计要求对每个代理的推理方式、决策边界的位置以及异常在代理之间的路由方式进行细粒度控制。直接在 Amazon EC2 上构建框架，并使用 Amazon Bedrock 提供推理，使编排逻辑完全掌握在团队手中，并支持开源代理库。业务逻辑的生产控制使每个代理的角色、输入和决策边界变得明确且可审计。在计费争议工作流程中，每个自动化决策都需要可解释。

### 代理

当检测到发票异常时，系统会将其路由到三个专门的人工智能代理之一，每个代理处理特定类型的计费争议：

- **发票匹配代理** 找到匹配的装运记录并标记不相符的记录。
- **定价差异代理** 将承运商的收费与合同费率进行比较，并确定差额是否有效。
- **辅助验证代理** 检查实际交付事件是否支持意外费用（例如住宅交付或升降门费用）。

每个代理在提出建议之前都会提取特定的运营商计费规则和政策。解决异常后，系统会生成一个简单语言注释，解释发现的内容以及采取的操作。

每个自定义代理都有一个指令提示（定义其角色、决策边界和输出格式）、一组操作（集成到 SpeedShip 中）以及对特定于运营商的知识库的访问。通过使用 Amazon Bedrock，每个代理都可以通过单个 API 访问合适的基础模型，同时继承现有的 AWS 治理。有关各区域的模型可用性，请参阅 [Amazon Bedrock 中 AWS 区域支持的模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。

### 行动

这些代理通过分析师使用的相同 API 连接到 SpeedShip。这意味着人工智能可以准确地看到人类审阅者会看到的内容（合同费率、发货详细信息、交货证明），并将其解决方案写入相同的工作流程中。 SpeedShip 在 AWS 上有 API，因此代理连接到与其他现有系统相同的端点。

### 运营商知识库

每个运营商都有不同的计费规则、费用定义和争议程序。 Worldwide Express 存储每个承运商的文档：关税规则、附加费定义、争议步骤和差异阈值。当代理处理异常情况时，它会在做出决定之前检索特定承运人的政策和标准操作程序 (SOP) 文件，因此每个决定都基于承运人自己的规则。相同的三个代理处理所有运营商，无需任何运营商特定代码。

### 人机交互

在最初推出期间，批准步骤对于 FinOps 的采用是必要的。最初，人工审核员将使用现有的 SpeedShip UI 在建议最终确定之前批准建议。最终，当准确率超过 99% 时，批量批准成为默认设置。

### 可观察性

Worldwide Express 的团队构建了仪表板，用于跟踪承运商的自动化率、异常类型的错误率、解决时间和人工覆盖频率。当审阅者拒绝建议时，系统会记录反馈。该团队根据拒绝历史记录完善指令提示和知识库，稳步提高自动化覆盖范围。

## 结果

六个月后，Worldwide Express 已在 40 多家零担运输承运商中部署了该解决方案。目前，代理每周会关闭 10,000 个（约 50%）例外情况，错误率低于 1%。这将 FinOps 团队的时间从常规解决方案转移到复杂、高价值的争议上。

这种影响在积压的活跃例外中表现得最为明显，积压从 2025 年 6 月的 1500 万美元下降到六个月后的 400 万美元，减少了 75%。 Worldwide Express 释放了 1000 万美元的现金流，每年节省了超过 100 万美元的成本，并且第一年的投资回报率达到了 60 倍。该公司报告称，兑现时间缩短了四个星期。

> “借助 AWS，我们已经自动化了超过 40% 的每周账单例外情况，显着降低了成本，并将账单周期从几天缩短到了几分钟。今天，我们每周多发放约 1000 万美元的客户账单，速度之快在以前是不可能的。”
> — Nathanael Pearson，全球快递 FinOps 副总裁

## 期待

Worldwide Express 已经将这种方法扩展到订单到现金周期的其他部分。对于管理大量承运量的物流公司来说，前进的道路是从小事做起。首先自动化最重复的异常类型，证明准确性，然后扩展到投资组合的其余部分。

## 结论

Worldwide Express 的异常自动化展示了当代理 AI 遇到范围广泛的业务问题时的可能性。 Amazon Bedrock、特定于运营商的知识库和人机交互审批设计相结合，让 Worldwide Express 在不到 6 个月的时间内从评估转向生产，同时保持财务控制。该公司目前正在将自动化扩展到其他订单到现金流程。
