# 用 Amazon Bedrock AgentCore 在 React 应用中嵌入实时的 AI 浏览器 agent

构建 AI 驱动的应用时，你的用户必须能够理解和信任那些代替他们浏览网站、与网页内容交互的 AI agent。当 agent 自主地与网页内容交互时，用户需要对这些操作有可见性，才能保持信心与掌控——而这正是他们目前所缺少的。

[Amazon Bedrock AgentCore Browser](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html) 的 `BrowserLiveView` 组件通过在 React 应用内直接提供 agent 浏览会话的实时视频流来应对这一挑战。该组件是 [Bedrock AgentCore TypeScript SDK](https://github.com/aws/bedrock-agentcore-sdk-typescript/tree/main) 的一部分，只需三行 JavaScript XML（JSX）就能嵌入实时浏览器流，从而简化集成。

`BrowserLiveView` 组件使用 [Amazon DCV](https://aws.amazon.com/hpc/dcv/) 协议渲染浏览器会话，为 agent 的操作创造透明度。实现只需要你的服务器提供一个预签名 URL，无需自行构建流媒体基础设施。

本文分三步带你走过：启动会话并生成 Live View URL、在 React 应用中渲染该流，以及接入一个驱动浏览器的 AI agent，让你的用户在旁观看。最后你会得到一个可克隆并运行的可工作示例应用。

## 为什么要在应用中嵌入 Live View

把 Live View 嵌入你自己的应用，可以在规模化下为用户解锁额外价值。

借助嵌入的 Live View，用户可以跟随 agent 执行的每一次导航、表单提交和搜索查询。他们能立即得到视觉确认：agent 在正确的页面上、与正确的元素交互、并且正在推进工作流。这种实时反馈闭环让终端用户无需等待最终结果，就能直接洞察 agent 的行为。

把浏览任务委托给 AI agent 的用户，在能够观察工作过程时会更有信心。看着 agent 逐个填写表单字段，比收到一条文字确认更让人安心。对于受监管的工作流，agent 操作的视觉证据可以支撑审计要求。

在需要人工监督的工作流中，例如处理客户账户和处理敏感数据，主管可以使用嵌入的 Live View 实时观看 agent 并在需要时介入，而无需离开你的应用。

组织还能通过 agent 操作的视觉证据获得审计追踪支持，这对合规要求和故障排查场景都很有价值。再结合向 Amazon Simple Storage Service（Amazon S3）的会话录制和控制台端的会话回放，你同时获得实时观察与事后复核。

## 工作原理

该集成包含三个组件。

用户的网页浏览器运行包含 `BrowserLiveView` 组件的 React 应用，该组件接收 SigV4 预签名 URL，并建立持久 WebSocket 连接，以接收来自远程浏览器会话的 DCV 视频流。React 应用负责视频渲染和界面呈现，同时维持 WebSocket 连接以持续串流。

应用服务器在 Amazon Bedrock 会话生命周期内充当 AI agent，编排客户端浏览器与云端托管浏览器会话之间的连接。它使用 Amazon Bedrock AgentCore API 启动会话，并生成 SigV4 预签名 URL，授予对 Live View 流的安全、限时访问。这一层负责会话管理、认证和流分发。

AWS Cloud 托管 Amazon Bedrock AgentCore Browser 与 Amazon Bedrock 服务，提供底层的浏览器自动化和流媒体能力。Amazon Bedrock AgentCore 在 AWS Cloud 内托管隔离的云浏览器会话，并同时提供自动化端点（Playwright CDP）和 Live View 流端点（DCV）。

这种架构的关键效率优势在于，DCV Live View 流直接从 Amazon Bedrock AgentCore 流向用户浏览器。它不经过你的应用服务器。你的服务器生成 URL 并运行 agent，但视频流是 AWS 到客户端的直接 WebSocket 连接。这有助于最小化延迟并降低基础设施要求。

## 前提条件

开始之前，请确认你具备以下条件：

- [Node.js 20 或更高版本](https://nodejs.org/)
- 位于[受支持的 AWS 区域](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html)的 **AWS 账户**
- 具有 [Amazon Bedrock AgentCore Browser 权限](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-quickstart.html#browser-prerequisites)的 AWS 凭证
- 可访问一个用于驱动 agent 的 AI 模型（本文使用 [Amazon Bedrock Converse API](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference-call.html) 配合 Anthropic Claude，但 Live View 与模型无关，你可以使用自己选择的模型提供商或 agent 框架）

> 重要：Live View（步骤 1 和 2）只需要 Amazon Bedrock AgentCore 权限。它不依赖 Amazon Bedrock 或任何特定 AI 模型。步骤 3 中的 AI agent 使用 Amazon Bedrock Converse API，需要额外的 Amazon Bedrock 权限，但这是本示例特有的。你可以替换为自己选择的模型提供商或 agent 框架。请使用来自 AWS IAM Identity Center 或 AWS Security Token Service（AWS STS）的临时凭证。不要使用长期访问密钥。配置 AWS Identity and Access Management（IAM）权限时请遵循最小权限原则。

安装 [Amazon Bedrock AgentCore TypeScript SDK](https://github.com/aws/bedrock-agentcore-sdk-typescript)：

```
npm install bedrock-agentcore
```

步骤 3 中的 AI agent 还需要 AWS SDK for JavaScript：

```
npm install @aws-sdk/client-bedrock-runtime
```

本文的代码运行在两个环境中：服务端代码（步骤 1 和 3）运行在 Node.js 中，客户端代码（步骤 2）运行在由 Vite 打包的 React 应用中。本文末尾的示例应用把所有内容打包在一起。

## 分步实现

### 1：启动浏览器会话并生成 Live View URL

在你的应用服务器上，使用 `Browser` 类启动会话并生成预签名 URL。API 返回会话标识符和流 URL，服务器把它转换为预签名 URL，默认有效期为 300 秒。它在查询参数中携带 SigV4 凭证，因此不会有密钥进入浏览器。通过一个 API 端点把这个 URL 传给前端。

```
import { Browser } from 'bedrock-agentcore/browser'

const browser = new Browser({
  region: 'us-west-2'
})
await browser.startSession({
  viewport: { width: 1920, height: 1080 }
})

const signedUrl =
  await browser.generateLiveViewUrl()
// Send signedUrl to your frontend via API
```

### 2：在 React 应用中渲染 BrowserLiveView 组件

在浏览器端，从 Bedrock AgentCore TypeScript SDK 导入 `BrowserLiveView` 组件，并用预签名 URL 渲染它。该组件负责 WebSocket 连接、DCV 协议协商、视频流解码和帧渲染。它会自动缩放以适应父容器，同时保持宽高比。`remoteWidth` 和 `remoteHeight` 必须与你在步骤 1 中设置的视口一致。值不匹配会导致裁剪或黑边。

```
import { BrowserLiveView }
  from 'bedrock-agentcore/browser/live-view'

<BrowserLiveView
  signedUrl={presignedUrl}
  remoteWidth={1920}
  remoteHeight={1080}
/>
```

添加该组件后，只要预签名 URL 有效且浏览器会话处于活动状态，Live View 就开始串流。你应该会看到远程浏览器的桌面出现在组件的容器中。如果容器保持空白，请确认预签名 URL 尚未过期，并且浏览器会话仍在运行。

### 3：接入 AI agent 来驱动浏览器操作

有了 Live View 在串流，你还得有点值得一看的东西。下面的示例使用 Amazon Bedrock Converse API，但 Live View 与模型无关。你可以使用自己选择的 AI 模型或 agent 框架来驱动浏览器。

这段代码创建了一个 `PlaywrightBrowser` 客户端，它会启动一个新的 AgentCore Browser 会话，并用 Playwright Chrome DevTools 协议连接到它。这与步骤 1 是同一类型的云浏览器会话，只是通过 Playwright 自动化接口而不是 Live View 接口访问。

模型决定调用哪些浏览器工具，包括 `navigate`、`click`、`type`、`getText`、`getHtml` 和 `pressKey`。你的服务器运行这些工具，并把结果回送给模型用于下一轮迭代。

```
import { BedrockRuntimeClient, ConverseCommand }
  from '@aws-sdk/client-bedrock-runtime'
import { PlaywrightBrowser }
  from 'bedrock-agentcore/browser/playwright'

const browser = new PlaywrightBrowser({
  region: 'us-west-2'
})
await browser.startSession()

// Define browser tools as JSON Schema
// (navigate, click, type, getText, and more)

while (step < maxSteps) {
  const response = await bedrockClient.send(
    new ConverseCommand({
      modelId: modelId,
      system: [{ text: systemPrompt }],
      messages,
      toolConfig: browserTools,
    })
  )

  if (response.stopReason === 'tool_use') {
    // Run browser tool, add result
    // to conversation, continue loop
  } else {
    break // Final answer from model
  }
}
```

模型是可配置的。你可以使用 Anthropic Claude、Amazon Nova，或任何支持 tool use 的 Amazon Bedrock 模型。模型发起的每一次工具调用都通过 Live View 对你的用户可见。他们能看到浏览器导航、搜索框被填入、结果页加载。

**注意：**TypeScript SDK 还包含一个 [Vercel AI SDK 集成](https://github.com/aws/bedrock-agentcore-sdk-typescript/tree/main/src/tools/browser/integrations/vercel-ai)（`BrowserTools`），把这些浏览器操作包装成框架原生的工具。

## Bundler 配置

`BrowserLiveView` 组件使用 [Amazon DCV Web Client SDK](https://docs.aws.amazon.com/dcv/latest/websdkguide/what-is.html)，它在 `bedrock-agentcore` npm 包内自带（vendored）相关文件。你无需单独下载或安装 DCV。你的 Vite 配置需要三处补充：

- `resolve.alias` 把 `dcv` 和 `dcv-ui` 这两个裸模块说明符（bare specifier）指向随包附带的 SDK 文件。
- `resolve.dedupe` 确保 React 与共享依赖从你的 `node_modules` 解析，而不是从随包附带的路径解析。
- `viteStaticCopy` 把 DCV 运行时文件（worker、WASM 解码器）复制到你的构建产物中。

示例应用的 `vite.config.ts` 里有完整可用的配置。关于 `BrowserLiveView` 组件的更多细节，参见 TypeScript SDK 中的[**live-view 源码目录**](https://github.com/aws/bedrock-agentcore-sdk-typescript/tree/main/src/tools/browser/live-view)。
