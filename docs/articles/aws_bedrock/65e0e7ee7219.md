# 通过将 Salesforce Agentforce 与 Amazon Bedrock Agents 集成来自动化企业工作流

AI agent 正在迅速改变企业运营。尽管单个 agent 能够有效执行特定任务，但复杂的业务流程往往横跨多个系统，需要在不同系统之间完成数据检索、分析、决策与动作执行。借助多 agent 协作，专门的 AI agent 可以协同工作，将错综复杂的工作流自动化。

本文探讨一种实际的协作方式：将 [Salesforce Agentforce](https://www.salesforce.com/agentforce/) 与 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 以及 [Amazon Redshift](https://aws.amazon.com/pm/redshift) 集成，实现企业工作流的自动化。

## 企业 AI 中的多 agent 协作

如今的企业环境十分复杂，在多个系统中并存着多样化的技术。Salesforce 与 AWS 为客户提供各自独特的优势。许多组织已经在 AWS 上维护着大量基础设施，包括数据、AI，以及 ERP、财务、供应链、HRMS 和劳动力管理等各类业务应用。Agentforce 提供强大的 AI 驱动 agent 能力，并以企业上下文和数据为基础。虽然 Salesforce 是可信业务数据的丰富来源，但客户越来越需要能够跨多个系统访问信息并对其采取行动的 agent。通过将 AWS 驱动的 AI 服务集成到 Agentforce 中，组织可以编排在 Salesforce 与 AWS 之上运行的智能 agent，释放两个平台各自的优势。

Agentforce 与 Amazon Bedrock Agents 可以以灵活的方式协同工作，借助两个平台的独特优势交付更智能、更全面的 AI 工作流。协作模式示例包括：

- Agentforce 作为主要编排者：管理端到端的面向客户的工作流；按需通过自定义操作将专门任务委派给 Amazon Bedrock Agents；协调跨系统对外部数据与服务的访问

这种集成打造出更强大的解决方案，最大化 Salesforce 与 AWS 双方的收益，让你可以通过增强的 AI 能力和跨系统功能取得更好的业务成果。

## Agentforce 概览

[Agentforce](https://www.salesforce.com/agentforce/) 将数字劳动力带给每位员工、每个部门和每个业务流程，为团队提供增强并提升客户体验。它可以与你现有的应用、数据和业务逻辑无缝协作，在整个企业范围内采取有意义的行动。而且由于它构建在值得信赖的 Salesforce 平台上，你的数据始终安全、受治理并由你掌控。借助 Agentforce，你可以：

- 部署为特定角色、行业或用例设计的预构建 agent
- 让 agent 借助现有的工作流、代码和 API 采取行动
- 安全地将 agent 连接到企业数据
- 通过 [Atlas Reasoning Engine](https://www.salesforce.com/agentforce/what-is-a-reasoning-engine/atlas/) 交付准确且有依据的成果

## Amazon Bedrock Agents 与 Amazon Bedrock Knowledge Bases 概览

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项完全托管的 AWS 服务，通过单个 API 提供对来自多家 AI 公司的高性能基础模型（FM）的访问。本文讨论以下功能：

- [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) – 托管 AI agent 使用 FM 理解用户请求、将复杂任务拆解为步骤、维护对话上下文并编排动作。它们可以通过 API（通过 action group 配置）与公司系统和数据源交互，并通过知识库访问信息。你以自然语言提供指令、选择 FM 并配置数据源和工具（API），Amazon Bedrock 负责编排。
- [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) – 该功能使 agent 能够使用公司私有数据源执行检索增强生成（RAG）。你将知识库连接到托管在 AWS 上的数据，例如 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）或 Amazon Redshift 中的数据，它会自动处理向量化与检索过程。当被提问或被赋予任务时，agent 可以查询知识库以找到相关信息，从而提供更准确、具备上下文感知的响应与决策，而无需重新训练底层 FM。

## Agentforce 与 Amazon Bedrock Agent 的集成模式

Agentforce 可以通过不同方式调用 Amazon Bedrock agent，从而灵活构建不同的架构。下图展示了同步与异步两种模式。

对于异步调用，Agentforce 使用 [Salesforce Event Relay](https://developer.salesforce.com/docs/platform/event-relay/overview) 和 [Flow](https://help.salesforce.com/s/articleView?id=platform.flow.htm&type=5) 配合 [Amazon EventBridge](https://aws.amazon.com/eventbridge/) 来调用 Amazon Bedrock agent。

## 解决方案概述

为说明 Agentforce 与 AWS 之间的多 agent 协作，我们使用以下架构，它向 Agentforce agent 提供对物联网（IoT）传感器数据的访问，并以多 agent 方法处理可能出错的传感器读数。

[![说明 Agentforce 工作流从 Salesforce CRM 贯穿 AWS 服务（包括 Lambda、Bedrock Agent 和安全控制）的完整架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/26/ml-18549-image-4.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/26/ml-18549-image-4.png)

该示例工作流包含以下步骤：

- Coral Cloud 为其房间配备了智能空调和温度传感器。这些 IoT 设备采集室温和错误码等关键信息，并将其存储在 Coral Cloud 位于 Amazon Redshift 的 AWS 数据库中。
- Agentforce agent 通过 Agent Wrapper API 调用 Amazon Bedrock agent，提出诸如“123 房间的温度是多少”之类的问题，以回答与房间舒适度相关的客户问题。该 API 以 [AWS Lambda](https://aws.amazon.com/lambda) 函数实现，充当 AWS 云中的入口点。
- Amazon Bedrock agent 在收到请求后需要上下文。它通过生成必要的 SQL 查询来查询其配置的知识库。
- 该知识库连接到包含历史传感器数据或上下文信息（例如传感器的阈值和维护历史）的 Redshift 数据库。它根据 agent 的查询检索相关信息并返回答案。
- 结合初始数据和来自知识库的上下文，Amazon Bedrock agent 使用其底层 FM 和自然语言指令来决定适当的动作。在此场景中，当它从传感器接收到错误读数时，检测到错误会促使它创建一个案例（case）。
- 该 action group 包含 Agentforce Agent Wrapper Lambda 函数。Amazon Bedrock agent 将必要的详细信息（例如哪个传感器或房间需要创建案例）安全地传递给该函数。
- Agentforce Agent Wrapper Lambda 函数充当适配器。它将来自 Amazon Bedrock agent 的请求转换为 Agentforce 服务的 API 或接口所需的特定格式。
- 该 Lambda 函数调用 Agentforce，指示其创建与该传感器（即发送错误读数的设备）所关联的联系人或账户相关的案例。
- Agentforce 使用其内部逻辑（agent、topics 和 actions）在 Salesforce 内创建或升级该案例。

该工作流展示了 Amazon Bedrock Agents 如何编排任务：使用 Amazon Bedrock Knowledge Bases 获取上下文，并通过 action group（经由 Lambda）与 Agentforce 交互，从而完成端到端流程。

## 前置条件

在构建此架构之前，请确保你具备以下条件：

- **AWS 账户** – 一个有效的 AWS 账户，具有使用 Amazon Bedrock、Lambda、Amazon Redshift、[AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）和 API Gateway 的权限。
- **Amazon Bedrock 访问权限** – 在你所选的 AWS 区域中启用的对 Amazon Bedrock Agents 以及 Anthropic 的 Claude 3.5 Haiku v1 的访问权限。
- **Redshift 资源** – 一个可运行的 Redshift 集群或 [Amazon Redshift Serverless](https://aws.amazon.com/redshift/redshift-serverless/) 端点。包含传感器数据（历史读数、传感器阈值和维护历史）的相关表必须已创建并填充数据。
- **Agentforce 系统** – 对 Agentforce 系统的访问权限和了解，包括如何配置它。你可以[注册](https://www.salesforce.com/form/developer-signup/?d=pb)带有 Agentforce 和 Data Cloud 的开发者版本。
- **Lambda 知识** – 熟悉创建、部署和管理 Lambda 函数（使用 Python）。
- **IAM 角色与策略** – 了解如何为 Amazon Bedrock Agents、Lambda 函数（用于调用 Amazon Bedrock、Amazon Redshift 和 Agentforce API）以及 Amazon Bedrock Knowledge Bases 创建具有[必要权限](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html#grant-least-privilege)的 IAM 角色。

## 创建 IAM 角色

本文中我们创建两个 IAM 角色：

- `custom_AmazonBedrockExecutionRoleForAgents`：为该角色附加以下 AWS 托管策略：`AmazonBedrockFullAccess`、`AmazonRedshiftDataFullAccess`。在信任关系中，提供以下信任策略（请填写你的 AWS 账户 ID）：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AmazonBedrockAgentBedrockFoundationModelPolicyProd",
            "Effect": "Allow",
            "Principal": {
                "Service": "bedrock.amazonaws.com"
            },
            "Action": "sts:AssumeRole",
            "Condition": {
                "StringEquals": {
                    "aws:SourceAccount": "YOUR_ACCOUNT_ID"
                }
            }
        }
    ]
}
```

- `custom_AWSLambdaExecutionRole`：为该角色附加以下 AWS 托管策略：`AmazonBedrockFullAccess`、`AmazonLambdaBasicExecutionRole`。在信任关系中，提供以下信任策略（请填写你的 AWS 账户 ID）：

```
{
    "Version": "2012-10-17",
   "Statement": [
       {
           "Effect": "Allow",
           "Principal": {
               "Service": "lambda.amazonaws.com"
           },
           "Action": "sts:AssumeRole",
           "Condition": {
               "StringEquals": {
                   "aws:SourceAccount": "YOUR_ACCOUNT_ID"
               }
           }
       }
   ]
}
```

## 创建 Amazon Bedrock agent

完成以下步骤以创建 Amazon Bedrock agent：

- 在 Amazon Bedrock 控制台的导航窗格中，选择 **Agents**。
- 选择 **Create agent**。
- 在 **Agent details** 页面，提供以下信息：输入名称和可选的描述。对于 **Agent resource role**，选择 **Use an existing service role** 并选择 `custom_AmazonBedrockExecutionRoleForAgents`。

[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/29/ml-18549-image-11-resized.jpeg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/26/ml-18549-image-11.jpeg)

- 为你的 agent 提供详细指令。以下是一个示例：

```
You are an IoT device monitoring and alerting agent. 
You have access to the structured data containing reading, maintenance, threshold data for IoT devices. 
You answer questions about device reading, maintenance schedule and thresholds. 
You can also create case via Agentforce. 
When you receive comma separated values parse them as device_id, temperature, voltage, connectivity and error_code. 
First check if the temperature is less than min temperature, more than max temperature and connectivity is more than the connectivity threshold for the product associated with the device id. 
If there is an error code, send information to agentforce to create case. The information sent to agentforce should include device readings such as device id, error code. 
It should also include the threshold values related to the product associated with the device such as min temperature, max temperature and connectivity, 
In response to your call to agentforce just return the summary of the information provided with all the attributes provided. 
Do not omit any information in the response. Do not include the word escalated in agent.
```

- 选择 **Save** 保存该 agent。
- 将你在上一步创建的知识库添加到该 agent。

- 通过提问来测试该 agent（在以下示例中，我们询问传感器读数）。

## 创建 Lambda 函数

完成以下步骤以创建用于接收来自 Agentforce 请求的 Lambda 函数：

- 在 Lambda 控制台的导航窗格中，选择 **Functions**。
- 选择 **Create function**。
- 使用以下逻辑配置该函数，以通过 API Gateway 接收请求并调用 Amazon Bedrock agent：

```
import boto3
import uuid
import json
import pprint
import traceback
import time
import logging
from agent_utils import invoke_agent_generate_response
logger = logging.getLogger()
logger.setLevel(logging.INFO)
bedrock_agent_runtime_client = boto3.client(
service_name="bedrock-agent-runtime",
region_name="REGION_NAME", # replace with the region name from your account
)
def lambda_handler(event, context):
    logger.info(event)
    body = event['body']
    input_text = json.loads(body)['inputText']
    agent_id = 'XXXXXXXX' # replace with the agent id from your account
    agent_alias_id = 'XXXXXXX' # replace with the alias id from your account
    session_id:str = str(uuid.uuid1()) # random identifier
    enable_trace:bool = False
    end_session:bool = False
    final_answer = None
    response = call_agent(input_text, agent_id, agent_alias_id)
    print("response : ")
    print(response)
 
    return {
        'headers': {
            'Content-Type' : 'application/json',
            'Access-Control-Allow-Headers': '*',
            'Access-Control-Allow-Origin': '*',
            'Access-Control-Allow-Methods': '*'
        },
        
        'statusCode': 200,
        'body': json.dumps({"outputText" :  response  })
    }
def call_agent(inputText, agentId, agentAliasId): 
    session_id = str(uuid.uuid1())
    enable_trace = False
    end_session = False
    while True:
        try:
            agent_response = bedrock_agent_runtime_client.invoke_agent(
                inputText=inputText,
                agentId=agentId,
                agentAliasId=agentAliasId,                
                sessionId=session_id,
                enableTrace=enable_trace,
                endSession=end_session
            )
            logger.info("Agent raw response:")
            pprint.pprint(agent_response)
            if 'completion' not in agent_response:
                raise ValueError("Missing 'completion' in agent response")
            for event in agent_response['completion']:
                chunk = event.get('chunk')
                # print('chunk: ', chunk)
                if chunk:
                    decoded_bytes = chunk.get("bytes").decode()
                    # print('bytes: ', decoded_bytes)
                    return decoded_bytes
        except Exception as e:
            print(traceback.format_exc())
            return f"Error: {str(e)}"
```

- 通过分配 `custom_AWSLambdaExecutionRole` 来定义必要的 IAM 权限。

## 清理

为避免产生额外费用，请在不再需要时删除你创建的资源：

- 删除 Amazon Bedrock 知识库：在 Amazon Bedrock 控制台的导航窗格中，选择 **Knowledge Bases**。选择你创建的知识库并选择 **Delete**。
- 删除 Amazon Bedrock agent：在 Amazon Bedrock 控制台的导航窗格中，选择 **Agents**。选择你创建的 agent 并选择 **Delete**。
- 删除 Lambda 函数：在 Lambda 控制台的导航窗格中，选择 **Functions**。选择你创建的函数并选择 **Delete**。
- 删除 REST API：在 API Gateway 控制台的导航窗格中，选择 **APIs**。选择你创建的 REST API 并选择 **Delete**。
