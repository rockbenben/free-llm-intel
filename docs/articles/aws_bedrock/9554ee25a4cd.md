# 使用 Amazon Bedrock Data Automation 与 Amazon Bedrock Knowledge Bases 构建多模态 RAG 应用

如今，组织要处理海量非结构化数据，格式包括文档、图像、音频文件和视频文件。这些文档常常相当大，带来处理时间变慢、存储成本上升等显著挑战。过去，要从这些多样格式中提炼有意义的洞察，需要复杂的处理 pipeline 和大量开发工作。在 [generative AI](https://aws.amazon.com/ai/generative-ai/?trk=38195029-2030-4f0d-850e-6b07e1e527ee&sc_channel=ps&ef_id=CjwKCAjw5PK_BhBBEiwAL7GTPRM3DaCX9H-nf8c0SLhneklxbsLLPCpcrUKbtSi4kEXE2-NeXucNuRoCvnoQAvD_BwE:G:s&s_kwcid=AL!4422!3!686122490521!e!!g!!aws%20generative%20ai!20901656360!158309139258&gclid=CjwKCAjw5PK_BhBBEiwAL7GTPRM3DaCX9H-nf8c0SLhneklxbsLLPCpcrUKbtSi4kEXE2-NeXucNuRoCvnoQAvD_BwE) 出现之前，组织不得不依赖多种专用工具、自建解决方案和大量人工复核流程，使得大规模处理与分析这些文档既耗时又容易出错。生成式 AI 技术正在革新这一局面，它提供强大的能力，可自动处理、分析这些多样的文档格式并从中提炼洞察，大幅减少人工投入，同时提升准确性与可扩展性。

借助 [Amazon Bedrock Data Automation](https://aws.amazon.com/bedrock/bda/) 和 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)，你现在可以以极少的投入构建强大的多模态 RAG 应用。Amazon Bedrock Data Automation 提供自动化工作流，可大规模高效处理各种文件格式；Amazon Bedrock Knowledge Bases 则创建一个统一、可搜索、能理解自然语言查询的存储库。二者结合，使组织能够高效处理、整理并检索其多模态内容中的信息，改变他们管理和使用非结构化数据的方式。

在本文中，我们完整走一遍构建全栈应用的过程：使用 Amazon Bedrock Data Automation 处理多模态内容，把抽取出的信息存入 Amazon Bedrock knowledge base，并通过基于 RAG 的问答界面实现自然语言查询。

## 真实场景用例

Amazon Bedrock Data Automation 与 Amazon Bedrock Knowledge Bases 的集成，为各行业处理海量非结构化数据提供了强大方案，例如：

- **医疗健康**：组织要处理大量患者记录，包括医疗表单、诊断影像和问诊录音。Amazon Bedrock Data Automation 自动抽取并结构化这些信息，Amazon Bedrock Knowledge Bases 则让医护人员可以用自然语言查询，例如“What was the patient’s last blood pressure reading?”或“Show me the treatment history for diabetes patients.”
- **金融机构**每天处理数千份文档，从贷款申请到财务报表。Amazon Bedrock Data Automation 抽取关键财务指标与合规信息，Amazon Bedrock Knowledge Bases 则让分析师可以提问，例如“What are the risk factors mentioned in the latest quarterly reports?”或“Show me all loan applications with high credit scores.”
- **律师事务所**处理大量案件卷宗，包括法庭文件、证据照片和证人证言。Amazon Bedrock Data Automation 处理这些多样的来源，Amazon Bedrock Knowledge Bases 让律师可以查询“What evidence was presented about the incident on March 15?”或“Find all witness statements mentioning the defendant.”
- **媒体公司**可以利用这项集成做智能情境广告投放。Amazon Bedrock Data Automation 处理视频内容、字幕和音频，以理解场景上下文、对话与情绪，同时分析广告素材与投放活动要求。Amazon Bedrock Knowledge Bases 随后支持复杂查询，把广告与合适的内容时刻匹配起来，例如“Find scenes with positive outdoor activities for sports equipment ads”或“Identify segments discussing travel for tourism advertisements.”这种智能情境匹配在保持品牌安全的同时，带来更相关、更有效的广告投放。

这些示例表明，Amazon Bedrock Data Automation 的抽取能力与 Amazon Bedrock Knowledge Bases 的自然语言查询相结合，可以如何改变组织与其非结构化数据交互的方式。

## 方案概述

这套完整方案展示了 [Amazon Bedrock](https://aws.amazon.com/bedrock/?trk=8228be07-d2ee-417f-b236-33eb068829a6&sc_channel=ps&ef_id=Cj0KCQjwh_i_BhCzARIsANimeoFTF7mP7kuQKSV11Ju13TxJaB5xz_Da1JfjZcJuV9O5yu1ETBorpdgaAqcgEALw_wcB:G:s&s_kwcid=AL!4422!3!692006005915!e!!g!!amazon%20bedrock!21054971261!157173597057&gbraid=0AAAAADjHtp8N1dHy-3ibiVi66oa3emzPH&gclid=Cj0KCQjwh_i_BhCzARIsANimeoFTF7mP7kuQKSV11Ju13TxJaB5xz_Da1JfjZcJuV9O5yu1ETBorpdgaAqcgEALw_wcB) 通过三个关键组件处理和分析多模态内容（文档、图像、音频文件和视频文件）的高级能力：Amazon Bedrock Data Automation、Amazon Bedrock Knowledge Bases，以及通过 Amazon Bedrock 提供的 [foundation](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html) model。用户可以上传多种类型的内容，包括音频文件、图像、视频或 PDF，以进行自动处理与分析。

当你上传内容时，Amazon Bedrock Data Automation 会使用标准或自定义 [blueprint](https://docs.aws.amazon.com/bedrock/latest/userguide/bda-blueprint-info.html) 进行处理，以提炼有价值的洞察。抽取出的信息以 JSON 形式存储在 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/) bucket 中，任务状态则通过 [Amazon EventBridge](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-what-is.html) 跟踪，并保存在 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 中。该方案会对抽取出的 JSON 做自定义解析，生成与 knowledge base 兼容的文档，随后这些文档会被存储并索引到 Amazon Bedrock Knowledge Bases 中。

通过直观的用户界面，该方案同时展示上传的内容及其抽取出的信息。用户可以借助由 Amazon Bedrock foundation model 驱动的检索增强生成（RAG）问答系统，与处理后的数据交互。这种一体化方式让组织能够高效处理各种内容格式、进行分析并从中获得洞察，同时依托使用 [AWS Cloud Development Kit（AWS CDK）](https://aws.amazon.com/cdk/) 部署的健壮且可扩展的基础设施。

## 架构

[![架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/19/ml-18747-arc-diagram.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/19/ml-18747-arc-diagram.jpg)

上图展示了本方案的数据流：

- 用户与前端应用交互，并通过 [Amazon Cognito](https://aws.amazon.com/cognito/) 完成身份验证
- API 请求由 [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 和 [AWS Lambda](https://aws.amazon.com/lambda/) 函数处理
- 文件上传到 S3 bucket 进行处理
- Amazon Bedrock Data Automation 处理文件并抽取信息
- EventBridge 管理任务状态并触发后处理
- 任务状态存入 DynamoDB，处理后的内容存入 Amazon S3
- 一个 Lambda 函数解析处理后的内容，并将其索引到 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)
- 基于 RAG 的问答系统使用 Amazon Bedrock foundation model 回答用户查询

## 先决条件

### 后端

后端方面，你需要具备以下先决条件：

- 一个 AWS 账户。
- 已安装 [AWS Command Line Interface（AWS CLI）](https://aws.amazon.com/cli/) 并配置好凭证：  `aws configure --profile [your-profile] AWS Access Key ID [None]: xxxxxx AWS Secret Access Key [None]:yyyyyyyyyy Default region name [None]: us-east-1 Default output format [None]: json`
- [Python](https://www.python.org/downloads/) 3.11 或更高版本。
- [Docker](https://docs.docker.com/engine/install/)。
- GitHub（如果使用代码仓库）。
- AWS CDK。更多细节与先决条件请参阅[《AWS CDK 入门》](https://docs.aws.amazon.com/cdk/v2/guide/getting_started.html)。
- 在 Amazon Bedrock 中[启用 foundation model 访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access-modify.html)：

要使用问答功能，请确保你在所需的 AWS Region 中启用了计划使用的 Amazon Bedrock foundation model 的访问权限。

- 对于下拉列表中标记为 On demand 的模型，在部署此 stack 的 Region 中启用模型访问权限。
- 对于下拉列表中标记为 CRIS 的模型，在系统定义的 inference profile 所使用的每个 Region（跨 Region）中启用模型访问权限。例如，要使用 `Amazon Nova Pro - CRIS US`，请确保为此 inference profile 使用的每个 Region 都启用 Amazon Nova Pro 模型的访问权限：US East（Virginia）us-east-1、US West（Oregon）us-west-2 以及 US East（Ohio）us-east-2。
- 本方案使用的模型包括：Anthropic 的 Claude 3.5 Sonnet v2.0 Amazon Nova Pro v1.0 Anthropic 的 Claude 3.7 Sonnet v1.0

### 前端

前端方面，你需要具备以下先决条件：

- Node/npm：v18.12.1
- 已部署的后端。
- 至少向对应的 Amazon Cognito user pool 添加一个用户（认证 API 调用所需）。

你需要的一切都以开源代码形式提供在我们的 [GitHub 仓库](https://github.com/aws-samples/generative-ai-cdk-constructs-samples/tree/main/samples/multimodal-rag) 中。


### 部署后端

使用以下步骤部署后端 AWS 资源：

- 如果还没做过，请克隆此仓库：  `git clone https://github.com/aws-samples/generative-ai-cdk-constructs-samples.git`
- 进入 backend 目录  `cd samples/multimodal-rag/backend`
- 在 MacOS 和 Linux 上创建一个 [virtualenv](https://virtualenv.pypa.io/en/latest/)：  `python3 -m venv .venv`
- 激活 `virtualenv`  `source .venv/bin/activate`
- `virtualenv` 激活后，你可以安装所需的依赖。  `pip install -r requirements.txt`
- 引导（bootstrap）CDK。引导是为搭配 AWS CDK 使用而准备 AWS 环境的过程。  `cdk bootstrap`
- 运行 AWS CDK Toolkit，部署后端 stack 及其运行时资源。  `cdk deploy`

为帮助防止影响你安全状况的意外更改，AWS CDK Toolkit 会在部署前提示你批准与安全相关的更改。你需要回答 yes 才能部署该 stack。

后端部署完成后，你需要创建一个用户。首先，使用 AWS CLI 定位 Amazon Cognito user pool ID：

```
$ aws cloudformation describe-stacks 
--stack-name BDAMediaSolutionBackendStack
--query "Stacks[0].Outputs[?contains(OutputKey, 'UserPoolId')].OutputValue"

[
    "OutputValue": "<region>_a1aaaA1Aa"
]
```

随后你可以前往 AWS Management Console 中的 Amazon Cognito 页面，搜索该 user pool 并添加用户。

### 部署前端

该仓库提供了一个演示前端应用。借助它，你可以上传并查看由后端应用处理后的媒体文件。要部署 UI，请按以下步骤操作：

- 进入 frontend 目录  `cd samples/multimodal-rag/frontend`
- 复制随附的 `example.env` 创建 `.env` 文件，并把属性值替换为从 `MainBackendStack` 输出中获取的值。

```
VITE_REGION_NAME=<BDAMediaSolutionBackendStack.RegionName>
VITE_COGNITO_USER_POOL_ID=<BDAMediaSolutionBackendStack.CognitoUserPoolId>
VITE_COGNITO_USER_POOL_CLIENT_ID=<2BDAMediaSolutionBackendStack.CognitoUserPoolClientId>
VITE_COGNITO_IDENTITY_POOL_ID=<BDAMediaSolutionBackendStack.CognitoIdentityPoolId>
VITE_API_GATEWAY_REST_API_ENDPOINT=<BDAMediaSolutionBackendStack.ApiGatewayRestApiEndpoint>
VITE_APP_NAME="Bedrock BDA Multimodal Media Solution"
VITE_S3_BUCKET_NAME=<BDAMediaSolutionBackendStack.BDAInputBucket>
```

如果你希望自动化上述步骤，可以运行下面提供的脚本：

```
./generate-dev-env.sh
```

- 安装依赖  `npm install`
- 启动 Web 应用  `npm run dev`

会显示类似 `http://localhost:5173/` 的 URL，你可以从浏览器打开该 Web 应用。用在 Amazon Cognito 中创建的用户档案登录应用。

### 上传文件时

文件上传后会触发以下流程：

- 文件存储在 S3 bucket 中
- 通过后端 API 启动 Amazon Bedrock Data Automation 任务
- 任务状态在 DynamoDB 中跟踪与更新
- 处理完成后，抽取出的信息会通过 UI 提供

[![BDA 分析结果](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/19/ml-18747-anakysis-results.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/19/ml-18747-anakysis-results.jpg)

处理时间因文件大小而异。你可以选择刷新按钮查看处理任务的状态。任务完成后，你可以在首页的表格中选择文件名，以查看文件详情。

你可以通过屏幕右侧的标签页，访问 Amazon Bedrock Data Automation 生成的任务详情。Standard 和 Custom Output 标签页提供 Amazon Bedrock Data Automation 抽取出的信息详情。

- Anthropic 的 Claude 3.5 Sonnet v2.0
- Amazon Nova Pro v1.0
- Anthropic 的 Claude 3.7 Sonnet v1.0

## 清理

删除该 stack 以避免意外费用。

- 首先确保移除为此方案创建的 S3 bucket 中的数据。
- 运行 `CDK destroy`
- 删除 S3 bucket。
- 删除各服务为此方案创建、写入 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 日志的相关日志。
