# 用 Amazon Bedrock AgentCore harness 构建 serverless 图像编辑 agent

构建一个能根据自然语言编辑图像的 AI agent，需要编排循环、工具路由、记忆管理，以及运行这一切的计算环境。[Amazon Bedrock AgentCore harness](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness.html) 用配置就能处理整套栈。你只需声明 agent 做什么，harness 就会在有状态、隔离的 microVM 中运行它，内置记忆、工具路由与可观测性。

本文将带你构建一个 serverless 图像编辑器：用户上传照片，用自然语言描述想要的编辑，数秒内得到结果。agent 运行在 AgentCore harness 上，无需自定义编排代码。我们用一条部署命令部署完整方案，包括认证、加密存储、三个图像编辑工具以及一个 React 前端。基础设施使用 [AWS Cloud Development Kit（AWS CDK）](https://aws.amazon.com/cdk/)定义。

## 图像编辑应用

该应用接受诸如「把汽车颜色改成蓝色」或「把图像向右扩展 200 像素」这样的 prompt。由 [Claude Sonnet 4.6](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-sonnet-4-6.html) 驱动的 agent 把需求拆解成一系列步骤，并编排工具调用，每个工具对应不同的 [Stability AI](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-stability-ai.html) 模型。随后它执行编辑，在 microVM 上通过 shell 命令加水印（不消耗 token），并返回结果。

该应用展示了 AgentCore harness 的以下能力：

- **配置驱动的 agent 创建。** agent 完全通过 API 参数定义。没有 Python 编排代码，没有框架，没有容器。
- **按调用切换模型。** 前端把基础聊天路由到 [Claude Haiku 4.5](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-haiku-4-5.html)，把编辑请求路由到 Claude Sonnet 4.6。agent 能在模型切换之间保留对话上下文。
- **按调用覆盖 persona。** 用户可选择行业 persona（Real Estate、Retail、Automotive），从而注入领域专用的 system prompt，无需重新部署。
- AgentCore 记忆在 AgentCore 服务中保存 30 天的对话历史。agent 在一次会话内跨轮次保留完整上下文，因此可以引用此前的编辑，而无需前端重新发送历史。本示例把 session ID 持久化在 `localStorage` 中，因此对话在浏览器刷新后仍然存在。清除浏览器数据会在前端开启一个新会话，但对话历史仍可通过 `ListEvents` API 在 AgentCore 中获取。
- **[AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 配合 MCP。** 三个由 AWS Lambda 支撑的工具通过 Model Context Protocol（MCP）暴露，并带有语义路由。agent 根据 prompt 选择正确的工具。
- **InvokeAgentRuntimeCommand。** 每次编辑后，Python 脚本直接在 AgentCore runtime 的 microVM 上运行以添加水印。无需模型推理，不消耗 token。

## 方案概览

图像编辑应用的架构分为四层。

- 托管在 [AWS Amplify](https://aws.amazon.com/amplify/) 上的 React 前端，用户在此上传图像、绘制 mask 并输入编辑指令。
- 一个 [AWS Lambda](https://aws.amazon.com/lambda/) 代理，充当浏览器凭证与 harness API 之间的安全边界，并控制允许使用哪些 system prompt。
- 一个 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) harness agent，配合 [AgentCore Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-memory.html) 实现对话持久化。
- 三个工具 Lambda 函数，通过 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 调用 Stability AI 基础模型来生成图像。

## 用配置创建 agent

使用 AgentCore harness 时，agent 的定义就是传给 `create_harness` API 的一组参数。下面是在 `cdk deploy` 期间创建 agent 的预置代码核心部分。

```
harness_params = {
    'harnessName': 'img_editor',
    'executionRoleArn': execution_role_arn,
    'model': {'bedrockModelConfig': {'modelId': 'us.anthropic.claude-sonnet-4-6'}},
    'systemPrompt': [{'text': system_prompt}],
    'tools': [{'type': 'agentcore_gateway', 'name': 'gateway',
        'config': {'agentCoreGateway': {'gatewayArn': gateway_arn}}}],
    # Scope the agent to exactly the three tools the gateway exposes
    # rather than allowing every tool with a wildcard.
    'allowedTools': [
        'inpaint-target___inpaint',
        'outpaint-target___outpaint',
        'search-replace-target___search_and_replace',
    ],
    'maxIterations': 10,
    'timeoutSeconds': 300,
}

# Attach memory for conversation persistence
harness_params['memory'] = {
    'agentCoreMemoryConfiguration': {'arn': memory_arn}
}

response = client.create_harness(**harness_params)
```

这就是 agent 的全部。没有编排循环，没有工具执行逻辑，没有流式处理 handler，没有错误重试代码。AgentCore harness 把这些全都包办了。

## 通过 AgentCore Gateway 声明工具

让 agent 使用工具通常需要写代码：接收模型发来的工具调用、解析参数、调用目标函数、处理错误并把结果传回。有了 harness，这些全都可以跳过。你在 [AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 上声明工具 schema，并指向一个 Lambda 函数。harness 会发现这些工具，在推理过程中把它们呈现给模型，通过 Gateway 调用被选中的工具，并自动把结果送回对话。

下面是我们如何在 CDK stack 中声明 search-and-replace 工具。

```
this.gateway.addLambdaTarget('SearchReplaceTarget', {
  gatewayTargetName: 'search-replace-target',
  lambdaFunction: this.searchReplaceLambda,
  toolSchema: agentcore.ToolSchema.fromInline([{
    name: 'search_and_replace',
    description: 'Find an object in the image by description and replace it. '
      + 'Does NOT require a mask. Use when the user wants to replace a specific object.',
    inputSchema: {
      type: agentcore.SchemaDefinitionType.OBJECT,
      properties: {
        source_image_key: { type: agentcore.SchemaDefinitionType.STRING },
        search_prompt: { type: agentcore.SchemaDefinitionType.STRING },
        prompt: { type: agentcore.SchemaDefinitionType.STRING },
      },
      required: ['source_image_key', 'search_prompt', 'prompt'],
    },
  }]),
});
```

agent 读取这些工具描述，并根据用户 prompt 选择正确的工具。无需任何路由逻辑。harness 通过模型的推理来完成工具选择。

## 按调用切换模型与 persona

harness 在每次调用时都接受一个 model 参数。传入不同的 model ID 就会改变由哪个基础模型处理该轮对话。harness 会自动从 AgentCore Memory 加载完整对话历史，并为新模型格式化，因此上下文无需额外代码就能延续。你不需要编写模型切换逻辑、历史检索或输入格式化。只要改一个参数，harness 就会在内部管理这一切。

Lambda 代理借此把基础聊天路由到 Haiku，把图像编辑路由到 Sonnet。

```
invoke_params = {
    'harnessArn': harness_arn,
    'runtimeSessionId': session_id,
    'messages': [{'role': 'user', 'content': [{'text': input_text}]}],
    'actorId': actor_id,
}

# Switch model per invocation (Haiku for chat, Sonnet for edits)
if model_override:
    invoke_params['model'] = {
        'bedrockModelConfig': {'modelId': model_override}
    }

# Switch persona per invocation (Real Estate, Retail, Automotive)
if persona_text:
    invoke_params['systemPrompt'] = [{'text': persona_text}]

response = client.invoke_harness(**invoke_params)
```

前端根据 prompt 是否包含编辑关键词来决定使用哪个模型。像「hi」或「what can you do」这样的短消息会走 Haiku，以获得更低延迟。编辑请求会走 Sonnet，以获得更高质量的工具选择。用户也可以从菜单中手动选择模型。

无论 harness 中配置了怎样的模型变更，AgentCore Memory 都会保留完整对话历史。当 Sonnet 处理完「change the car to black」之后，Haiku 收到「how about blue?」时也知道「blue」指的是那辆车，因为 Memory 会把完整历史喂给当前激活的模型。

## 用 shell 命令做后处理（不消耗 token）

agent 生成图像后，我们直接在 harness microVM 上运行 Python 脚本以添加水印。这里使用 InvokeAgentRuntimeCommand，它让你无需经过模型就能获得 agent 环境的 shell 访问权限。

```
# Build a Python script and base64 encode it to avoid shell escaping issues
script = '\n'.join([
    'from PIL import Image, ImageDraw, ImageFont',
    'import boto3, io',
    's3 = boto3.client("s3")',
    f'obj = s3.get_object(Bucket="{bucket_name}", Key="{result_key}")',
    'img = Image.open(io.BytesIO(obj["Body"].read())).convert("RGBA")',
    '# ... tile watermark text across the image ...',
    's3.put_object(Bucket=bucket, Key=key, Body=buf.getvalue())',
])

encoded_script = base64.b64encode(script.encode()).decode()

# Run on the microVM: no model reasoning, no tokens consumed
client.invoke_agent_runtime_command(
    agentRuntimeArn=harness_arn,
    runtimeSessionId=session_id,
    body={'command': f'echo {encoded_script} | base64 -d | python3'},
)
```

这一模式适用于确定性的后处理：在发送给模型之前调整图像尺寸（节省输入 token）、对 agent 输出做校验、提取结构化数据，或应用业务逻辑。microVM 默认提供 Python 与 bash，你也可以在运行时安装额外的软件包。

由于 harness 只接受配置，不存在可以添加自定义逻辑的 agent 脚本。InvokeAgentRuntimeCommand 就是在 agent 所运行的同一 microVM 上、但在 agent 循环之外运行你自己代码的方式。Lambda 代理会在 agent 完成该轮之后调用它。命令执行、完成工作并返回。agent 并不知道这一切发生过。

## 前提条件

要部署该方案，你需要以下条件。

- 一个具备创建 AWS Identity and Access Management（IAM）角色、Lambda 函数、Amazon Simple Storage Service（Amazon S3）bucket、Amazon Cognito pool 与 AgentCore 资源权限的 [AWS 账户](https://signin.aws.amazon.com/signin?redirect_uri=https%3A%2F%2Fportal.aws.amazon.com%2Fbilling%2Fsignup%2Fresume&client_id=signup)。
- [Node.js](https://nodejs.org/) 20.x 或更高版本。
- [Python](https://www.python.org/downloads/) 3.13 或更高版本（用于 Lambda 函数运行时）。
- 已配置凭证的 [AWS Command Line Interface（AWS CLI）](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) 2.x。
- 在 Amazon Bedrock 中访问 Anthropic Claude 模型（Sonnet、Haiku）的权限。
- 在 Amazon Bedrock 中访问 Stability AI 模型的权限。

预计部署时间为 3 到 5 分钟。

## 部署方案

部署脚本会端到端处理所有事情。它安装依赖、打包 Lambda 依赖、部署 CDK stack、构建前端、上传到 Amplify，并创建一个测试用户。

克隆 [GitHub 仓库](https://github.com/aws-samples/sample-serverless-image-editing-agent-bedrock-agentcore-harness)并进入项目目录。

```
git clone https://github.com/aws-samples/sample-serverless-image-editing-agent-bedrock-agentcore-harness
cd sample-serverless-image-editing-agent-bedrock-agentcore-harness
```

运行部署脚本。

```
./deploy.sh
```

结束时，它会打印线上 URL 与登录凭证。

CDK stack 在单个 [AWS CloudFormation](https://aws.amazon.com/cloudformation/) stack 中创建所有资源。方案使用 Amazon Cognito 的 user pool 与 identity pool 来处理认证。图像存储在由 AWS Key Management Service（AWS KMS）加密保护的 Amazon S3 bucket 中。图像编辑能力由三个 Lambda 函数提供，它们通过 AgentCore Gateway 暴露为 MCP 工具。这些工具由配备记忆的 AgentCore harness agent 编排，并经由 Lambda 代理访问。前端方面，由 AWS Amplify 应用提供基于 React 的用户界面。

## 操作演练

登录后，编辑器左侧是画布，右侧是聊天界面。

**1. 上传图像。** 图像会上传到 S3，位于以用户身份为作用域的前缀之下。

**2. 描述你的编辑。** 在聊天输入框中输入自然语言指令。对于对象替换（例如「把天空换成日落」），agent 会自动使用 search-and-replace。

**3. 为区域编辑绘制 mask。** 要编辑图像的特定区域，请在画布上绘制 mask 以定义区域，然后输入要在该 mask 区域生成的内容。

**4. 查看结果。** 编辑后的图像会出现在聊天线程中，并带有由 microVM shell 命令平铺添加的水印。「Behind the Scenes」面板会显示使用了哪个模型、调用了哪个工具、token 数量、延迟，以及是否已添加水印。

**5.（可选）切换模型或 persona。** 使用聊天顶部的菜单更改推理模型，或切换到特定行业的 persona。更改会在下一条消息生效，且不会丢失对话历史。

## harness 为本项目具体减少了什么

该方案不需要一行 agent 编排代码。没有模型调用循环，没有工具执行 handler，没有流式解析器，没有错误重试逻辑，没有容器镜像。

我们实际编写的部分。

- 一个 Lambda 代理（80 行），充当安全边界并控制哪些 system prompt 能到达 harness。
- 三个工具 Lambda 函数（每个 Stability AI 模型一个），负责实际的图像处理。
- 一个部署期间调用 `create_harness` API 的预置脚本（AgentCore harness 处于预览阶段，目前还没有原生 CDK construct）。

agent 本身就是配置。改变它的行为（换模型、加新工具、更新指令）只需一次 API 调用，而不是代码部署。

## 何时改用 AgentCore Runtime

AgentCore harness 很适合工具调用模式直截了当的 agent：接收 prompt、选择工具、调用工具、返回结果。如果你的 agent 需要自定义编排逻辑，例如在轮次之间预处理输入、运行 LangGraph 状态机，或在每次模型调用前后执行任意 Python，[AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime.html) 能给你完全的控制权。

harness 与 AgentCore Runtime 运行在相同的底层基础设施上（microVM、Memory、Gateway、Observability）。你可以从 harness 开始，随着复杂度增长再迁移到 AgentCore Runtime。

## 清理

运行销毁脚本会永久删除所有资源，包括 S3 bucket 与已上传的图像。继续之前，请备份你想保留的任何数据。

**删除 stack：**

```
./destroy.sh
```

## 结论

AgentCore harness 让我们无需编写编排代码就能构建可用于生产的图像编辑 agent。agent 通过配置与按调用的参数来处理工具选择、模型切换、persona 定制、对话持久化与确定性后处理。每次会话都在隔离的 microVM 中运行，在那里我们可以零 token 成本执行 shell 命令来完成加水印之类的任务。

对于工具调用模式直截了当的 agent，harness 消除了运维开销，你可以以配置变更的速度迭代行为。完整源代码与一条命令即可完成部署的脚本见 [GitHub](https://github.com/aws-samples/sample-serverless-image-editing-agent-bedrock-agentcore-harness)。

要开始使用 AgentCore harness，请访问 [AgentCore harness 文档](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness.html)，或浏览 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 产品页了解定价与可用性详情。
