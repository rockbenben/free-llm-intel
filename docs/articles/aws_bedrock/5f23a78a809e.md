# 在欧洲释放 AI 灵活性：面向欧盟数据处理与模型访问的跨区域推理指南

随着最新[生成式 AI 模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)和高性能加速计算资源在全球范围内需求高涨，AWS 客户需要相应的工具，在满足自身安全与隐私要求的同时，利用跨多个 AWS 区域的[模型可用性](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)与容量。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的[跨区域推理（cross-Region Inference，CRIS）](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)通过在预定义地理边界内自动路由请求来满足这些需求。这让生成式 AI 应用能够在地理范围内使用广泛的容量，帮助客户构建更具韧性、并能反映各地区域复杂性的应用。

本文深入介绍跨区域推理（CRIS），并说明欧洲客户如何从中受益。我们重点介绍 AWS 为客户提供的功能、服务与资源，帮助他们符合本地的数据保护与处理要求，其中包括在使用 CRIS 期间可能适用于其活动的《通用数据保护条例》（General Data Protection Regulation，GDPR）。

## 跨区域推理配置文件

跨区域推理（CRIS）是 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 中的一项托管能力，可在受支持的 AWS 区域之间路由模型推理请求。推理配置文件（inference profile）是 Amazon Bedrock 中的一种资源，用于定义请求可以路由到的区域。这些配置文件在特定的区域集合内路由请求。CRIS 的路由设计目标是以尽可能低的延迟开销优化模型吞吐量。

Amazon Bedrock 引入了系统定义的推理配置文件。这些推理配置文件的命名来自模型及其支持的地理区域。这些配置文件帮助 Amazon Bedrock 的使用者借助 AWS 的全球规模化基础设施来构建生成式 AI 解决方案。要理解跨区域推理配置文件如何处理推理请求，需要先理解以下关键概念：

**源区域（Source Region）** —— 你发起 API 请求、指定推理配置文件时所处的区域。

**目标区域（Destination Region）** —— Amazon Bedrock 服务可以将请求从你的源区域路由到的区域。

系统定义的 CRIS 配置文件要么是全局范围，要么是地理范围。在接下来的小节中，我们介绍全局范围与欧盟地理范围，以及客户如何使用不同的配置文件来应对监管与合规义务。

### 全局推理

全局推理配置文件将模型推理请求路由到任意受支持的 AWS 商业区域。输入 prompt 会被传输到目标区域以完成模型推理，模型输出在目标区域生成后返回源区域。跨区域推理期间传输的数据[经过加密，并始终留在安全的 AWS 网络内](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)。目标区域会被自动选择，以针对可用的模型容量进行优化，并以最小的开销返回响应。

通过使用所有受支持的可用区域，采用全局推理配置文件的生成式 AI 应用更能抵御高峰时段的潜在容量短缺或其他区域性模型可用性问题。相比直接的区域内调用或地理 CRIS 调用，若干模型通过全局 CRIS 还可享受[折扣价格](https://aws.amazon.com/bedrock/pricing/)，这让全局推理更具吸引力。

### 基于欧盟地理范围的推理

[地理 CRIS（Geographic CRIS，Geo CRIS）](https://docs.aws.amazon.com/bedrock/latest/userguide/geographic-cross-region-inference.html)是与全局推理配置文件不同的系统定义推理配置文件。这些配置文件把模型绑定到某个地理范围，从配置文件内定义的不同区域提供同一模型的副本。Amazon Bedrock 客户可以根据自身需求，选择不同的 Geo CRIS 配置文件。本节重点介绍面向欧盟的推理配置文件（EU CRIS）。

创建 EU CRIS 配置文件是为了帮助客户应对欧盟数据驻留相关问题。CRIS 只能在一组目标区域内优化流量。对于 EU CRIS，所有目标区域都位于欧盟境内。源自欧盟之外区域的请求也可以借助 EU CRIS 进行优化。这类请求的源区域位于欧盟之外。对于此类请求，CRIS 会在相应的源区域之外，再在欧盟区域内优化推理。使用 EU CRIS 配置文件的客户会看到以下效果：

- 来自欧盟境内源区域的请求，只能路由到欧盟境内的其他 AWS 区域。
- 使用 EU CRIS 时，来自欧盟源区域的请求不会被路由到非欧盟区域。例如，苏黎世和伦敦不会被视为这类请求的目标区域。
- 源自伦敦区域的请求，只能在可用的欧盟区域与伦敦区域之间路由。
- 来自苏黎世区域的请求，只能在可用的欧盟区域与苏黎世区域之间路由。
- 对于源自欧盟之外的请求，使用 EU CRIS 时：优化只考虑源区域与欧盟区域。

## 跨区域推理的安全与控制

在 AWS，客户数据的安全是[我们的最高优先级](https://aws.amazon.com/security/culture-of-security/)，这一点同样体现在 Amazon Bedrock 跨区域推理的设计中。

AWS 到 AWS 的流量，例如区域到区域（包括边缘站点与 AWS Direct Connect 路径），始终经由 AWS 自营骨干网络传输。跨区域操作期间传输的数据始终留在 AWS 网络上，不经过公共互联网。AWS 会加密在 AWS 区域之间传输的数据。使用方应用在调用模型进行跨区域推理时，必须在代码中显式声明：用 CRIS 配置文件 ID 代替普通模型 ID。例如，下面的代码片段展示了 Amazon Nova Lite 模型的两次调用——一次使用 EU CRIS，一次使用全局 CRIS：

```
import boto3
import json

from botocore.exceptions import ClientError
bedrock_runtime = boto3.client("bedrock-runtime", region_name="eu-south-1") # Source Region: Milan

model_id = "eu.amazon.nova-2-lite-v1:0" 
# Amazon Nova Lite EU CRIS profile ID
# Request can be processed within available destination Regions in EU CRIS

response = bedrock_runtime.converse(modelId=model_id, messages=[...], additionalModelRequestFields={...}) 


model_id = "global.amazon.nova-2-lite-v1:0" 
# Amazon Nova Lite Global CRIS profile ID
# Request can be processed by any AWS Commercial Region

response = bedrock_runtime.converse(modelId=model_id, messages=[...], additionalModelRequestFields={...}) 
```

地理推理配置文件（因而也包括欧盟推理配置文件）是静态的。这意味着 AWS 不会向配置文件中新增区域。如果必须向某个特定地理范围的配置文件（包括 EU CRIS）新增目标区域，Amazon Bedrock 会发布一个带有新推理配置文件 ID 的新地理专用配置文件。

「默认即数据保护」（data protection by design）是 GDPR 引入的关键概念。借助 [AWS Identity and Access Management（AWS IAM）](https://aws.amazon.com/iam/)，客户可以安全地控制对 AWS 资源与数据的访问，包括允许哪些应用访问数据或调用 Amazon Bedrock 上的不同基础模型或 CRIS 配置文件。IAM 通过仅允许获得授权的管理员、用户与应用访问 AWS 资源与数据，帮助客户满足这一要求。IAM 有助于落实最小权限原则，控制谁可以访问你在源区域中的数据。这有助于防止客户不希望被目标区域处理的内容被纳入输入 prompt。[保护 Amazon Bedrock 跨区域推理](https://aws.amazon.com/blogs/machine-learning/securing-amazon-bedrock-cross-region-inference-geographic-and-global/)一文更详细地介绍了如何配置地理范围与全局范围的配置文件以及 IAM。

## 透明度与可审计性

许多数据处理法规要求控制者或使用方保存数据处理活动的记录。全局 CRIS 与地理 CRIS 都能满足这一要求。

借助 [AWS CloudTrail，](https://aws.amazon.com/cloudtrail/)客户可以持续监控 AWS 账户活动。CloudTrail 会记录客户账户的 AWS API 调用历史，包括通过 AWS 管理控制台、AWS SDK、命令行工具以及更高层 AWS 服务发起的 API 调用。具体到 Amazon Bedrock，每一次被计为[管理事件](https://docs.aws.amazon.com/bedrock/latest/userguide/logging-using-cloudtrail.html#service-name-data-events-cloudtrail)的 API 调用，其元数据都会被默认记录。这包括 Converse 和 InvokeModel 之类的模型调用 API，但只记录元数据，不记录实际负载。在筛选事件来源为 “bedrock.amazonaws.com” 时，可以在**事件历史（Event History）**中查看过去 90 天的这些日志。若需持续保留事件记录，你可以[配置 CloudTrail](https://docs.aws.amazon.com/bedrock/latest/userguide/logging-using-cloudtrail.html) 将这些事件保存更长时间。

在 CloudTrail 中检查相关事件时，客户可以看到模型调用的源区域与目标区域，additionalEventData 部分的 inferenceRegion 字段会显示请求实际在何处处理。

客户还可以选择启用[模型调用日志记录](https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html)。此功能会在你账户的源区域收集每次调用的详细信息，包括完整的请求、响应与元数据。客户可以将日志发送到 Amazon CloudWatch Logs 或 Amazon Simple Storage Service（Amazon S3）。模型调用日志记录默认关闭，如有需要，客户必须显式启用。

使用跨区域推理时，Amazon CloudWatch、AWS CloudTrail 与模型调用日志记录仍只在请求发起的客户 AWS 账户*源区域*记录日志条目。这种设计简化了监控与日志管理，并通过把日志存储在源位置来维持本地数据处理要求，无论实际处理请求的是哪个目标区域。

### 如何查看可用的 CRIS 配置文件？

希望查看可用系统配置文件的客户有以下几种方式：

- 使用[此官方文档页面](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)，其中列出了所有系统定义的推理配置文件以及相应的源区域与目标区域。
- 在 AWS 控制台页面中导航到跨区域推理，查看某个源区域可用的推理配置文件。下面的截图展示了[伦敦的控制台页面](https://eu-west-2.console.aws.amazon.com/bedrock/home?region=eu-west-2#/inference-profiles)（eu-west-2）。
- 使用 AWS SDK，例如 Boto3，如下面的代码片段所示：

```
# pip install boto3
import boto3
region = "eu-central-1" # Frankfurt Region
bedrock = boto3.client('bedrock', region_name=region)
system_response = bedrock.list_inference_profiles(typeEquals='SYSTEM_DEFINED')
#https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/bedrock/client/list_inference_profiles.html
```

## 推理配置文件与本地数据处理

许多客户有本地数据处理要求，并且需要清楚了解数据在何处被处理。这同样适用于全局推理配置文件与地理推理配置文件。

AWS 客户可以在[符合 GDPR 要求](https://aws.amazon.com/blogs/security/all-aws-services-gdpr-ready/)的前提下，使用 AWS 服务处理上传到其 AWS 账户下各项 AWS 服务的个人数据（按 GDPR 的定义）（即客户数据）。

Amazon Bedrock 是纳入 [CISPE 数据处理行为准则](https://aws.amazon.com/compliance/services-in-scope/CISPE/)范围的众多服务之一。这为客户提供了独立验证和额外一层保证，表明我们的云服务可以在符合《通用数据保护条例》（GDPR）的前提下使用。CISPE 准则是首个面向云基础设施服务提供商的泛欧数据保护行为准则。2021 年 5 月，CISPE 准则获得代表欧洲 27 家数据保护机构行事的欧洲数据保护委员会（EDPB）批准。2021 年 6 月，该准则由担任牵头监管机构的 CNIL 正式通过。

AWS 客户可以继续使用 AWS 服务，在符合 GDPR 的前提下，将客户数据从欧洲经济区（EEA）传输到尚未获得欧盟委员会充分性认定的非 EEA 国家（包括美国）。全局与地理 CRIS 配置文件既能帮助客户使用模型推理，也为客户的推理合规要求与风险偏好提供了选择。

在 AWS，我们的最高优先级是保护客户数据，无论客户选择了哪个 [AWS 区域](https://aws.amazon.com/about-aws/global-infrastructure/regions_az/?p=ngi&loc=2)，我们都会实施严格的技术与组织措施来保护数据的机密性、完整性与可用性。我们知道透明度对客户很重要。我们在[隐私功能](https://aws.amazon.com/compliance/privacy-features/)网页上列出了涉及客户数据传输的 AWS 服务。

随着监管与立法环境不断演变，我们始终致力于帮助客户无论在哪里运营，都能继续享受 AWS 服务带来的益处。更多信息请参阅我们[面向客户的欧盟-美国隐私盾更新](https://aws.amazon.com/blogs/security/customer-update-aws-and-the-eu-us-privacy-shield/)，以及关于 [AWS 数据处理附录补充附录](https://aws.amazon.com/blogs/security/aws-and-eu-data-transfers-strengthened-commitments-to-protect-customer-data/)的博客文章。

## 结论

跨区域推理（CRIS）让生成式 AI 应用能够访问在其主要 AWS 区域中可能不可用的模型。它提升了对计划外流量突增或特定区域容量短缺的韧性，同时保持最高水平的信任、隐私与安全。

本文展示了如何在使用 CRIS 的同时遵守欧盟本地数据处理要求。Amazon Bedrock 为客户提供了灵活性，可依据自身具体用例的需求选择全局或受地理范围约束的跨区域推理配置文件。两种方式都符合 GDPR 等数据保护法规，同时让客户在满足工作负载需求与风险偏好方面拥有更大灵活性。

AWS 持续努力将新服务纳入其合规计划范围，帮助你满足架构与监管需求。AWS 团队可以协助你评估风险并开展数据隐私影响评估。如对 AI 工作负载与跨区域推理有疑问，请联系[你的 AWS 客户团队](https://pages.awscloud.com/global-ln-gc-400-ai-contact-us.html)。如需进一步了解我们的合规与安全计划，请参阅 [AWS 合规计划](https://aws.amazon.com/compliance/programs/)。
