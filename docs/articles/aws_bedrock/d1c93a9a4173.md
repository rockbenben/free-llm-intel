# Abnormal AI：用 Amazon Bedrock AgentCore 实现大规模 agentic 邮件安全

AI agent 如今已在生产环境中以每天数十亿次操作的规模运行，一种反复出现的架构模式也随之显现：agent 需要一块计算暂存区（compute scratch pad）。这不仅用于编码任务，也用于数据聚合、分析、验证，以及任何仅靠语义推理不够的 workflow。

Abnormal AI 是一项行为安全服务，保护着超过 25% 的《财富》500 强企业。它部署了 Amazon Bedrock AgentCore Code Interpreter（Amazon Bedrock AgentCore 的一项能力），用于支撑其实时内联（inline）邮件威胁检测的 agent。这些系统今天已在生产环境运行，处理数十亿封邮件，并以同样的规模执行由 agent 驱动的代码，在威胁抵达收件箱之前就完成内联检测与拦截。

这项工作也是 Abnormal AI 构建软件方式的一部分。如今，他们 80% 的代码变更以某种方式由 agent 构建，40% 由后台 agent 端到端构建（完全由 AI 构建，而非 AI 辅助）。他们把 AgentCore Code Interpreter 用于威胁检测，正是同一套 AI 原生（AI-native）方法在生产运行时上的延伸。

本文将分享 Abnormal AI 如何架构这些系统、其 sandbox 方案背后的设计决策，以及为大规模部署 Code Interpreter 的构建者总结的实践经验。

## 什么是 Amazon Bedrock AgentCore Code Interpreter？

[Amazon Bedrock AgentCore Code Interpreter](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/code-interpreter-tool.html) 为 agent 提供全托管、无服务器（serverless）的运行时，让 agent 动态执行代码。关键特性包括：

- 临时 MicroVM 会话：time-to-live 可配置，从 15 分钟（默认）到 8 小时，以支持长时间运行的任务。
- 安全性：会话运行在安全的 sandbox 中，在宿主操作系统层面完全隔离，旨在帮助防止会话之间发生意外泄露。
- 灵活的网络：可配置为 sandbox 虚拟私有云（VPC）模式，或开放公共互联网访问。
- 文件处理：通过 API 可直接处理最大 100 MB 的文件；更大的数据集可连接 Amazon Simple Storage Service（Amazon S3）。
- 预加载的运行时：Python 与 `Node.js` 环境，内置常用的可视化、统计与数据处理库。
- 内置可观测性：日志发送至 Amazon CloudWatch 与 AWS CloudTrail 以便监控。

关键在于，Code Interpreter 以 API 的形式暴露。这意味着它不会规定 agent 的 workflow，而是提供一个盒子：agent 在其中运行命令、上传文件并取回结果。对于已有 agent 基础设施的团队，这种即插即用的设计让集成变得非常直接。

## 为什么 agent 需要计算暂存区

大语言模型（LLM）擅长推理与语义连贯性，但许多现实中的操作并不能映射为语义推理：

- 基础数学与计数：“过去一小时我们检测到多少封钓鱼邮件？”需要的是计算，而不是语言生成。
- 数据处理与可视化：把原始数据转换为图表、PDF 或结构化报告。
- 代码验证：运行单元测试、linting 与集成测试，以验证 agent 生成的输出。

把大语言模型与 Code Interpreter 搭配使用，可以把 agent 的能力提升到仅靠推理无法达到的水平。

> “几乎任何 agent，无论它是否写代码，都需要一个代码解释器 sandbox，让它能够真正处理数据并得出答案。”

—— Shrivu Shankar，Abnormal AI 的 AI 战略副总裁

## Abnormal AI 的架构：十亿级邮件规模下的三层检测

Abnormal AI 通过三层检测架构处理数十亿封邮件，如图 2 所示。

![三层邮件检测 pipeline：从 Tier 1 启发式规则，到 Tier 2 机器学习模型，再到 Tier 3 搭配 Code Interpreter 的内联 agent](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/09/11/ML-21301-2.png)

图 2：Abnormal AI 的三层邮件检测 pipeline——Tier 1（启发式规则，每天数十亿封）、Tier 2（机器学习模型，每天数百万封）、Tier 3（搭配 Code Interpreter 的内联 agent，每天数万封）；每一层处理上一层没有把握的、难度更高的情况

### Tier 1 — 高流量的轻量分类（每天数十亿封）

小模型、启发式规则和轻量分类器（逻辑回归）处理最大的流量。在这种规模下，运行更大的模型既不经济，也没有必要。大多数邮件无需深入分析即可完成分类。

### Tier 2 — 为不确定情况引入中等规模模型（每天数百万封）

Tier 1 没有把握的邮件会流入深度学习与机器学习（ML）模型，进行更多行为信号分析。

### Tier 3 — 搭配 Code Interpreter 的内联 agent（每天数万封）

最难的情况通常需要人类分析师来评估，现在由内联 agent 处理。这些 agent 接收威胁情报数据，使用 sandbox 进行分析，并动态编写脚本。随后它们评估这些情报如何嵌入整体行为模型，并做出判定。误分类由另一套独立系统处理，该系统会持续学习并改进系统本身。多种监控系统负责验证线上系统。

## 分析师 agent —— 批量情报

除了图 2 所示的实时分类 pipeline，Abnormal 还部署了一个*分析师 agent*（analyst agent），以批量模式运行（图 3）：

- 摄取来自检测 pipeline 的误分类与调优信号。
- 在大量邮件集合中识别模式与趋势。
- 基于 Abnormal AI 自身检测 pipeline 的特征与信号，为 Tier 1 自主编写候选启发式规则草稿。
- 为 Tier 2 提供改进后的模型。
- 以每周约 100 个批量作业的规模运行。

![分析师 agent 的反馈闭环：把批量分析得到的改进版启发式规则与模型回流到 Tier 1 与 Tier 2](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/09/11/ML-21301-3.png)

图 3：分析师 agent 的反馈闭环——批量 agent 从实时 pipeline 摄取误分类，使用 Code Interpreter 会话分析模式，并把改进后的启发式规则与模型回流至 Tier 1 与 Tier 2

这些批量作业可以持续运行 30 分钟以上，其间 Code Interpreter 会话一直保持。它们也可以跨越长达一天的作业，agent 间歇性地使用 Code Interpreter。例如：先运行一个会话，在外部训练模型，然后重新调用 Code Interpreter 处理结果。

## 安全：零信任 sandbox 设计

Abnormal 为 Code Interpreter 选择了 sandbox（无出网）配置，出于两点考虑：

- 可复现性 —— 由于 sandbox 没有外部网络访问，任何不受 Abnormal AI 控制的因素都无法影响该会话期间 agent 的行为。该环境被设计为完全确定性的。
- 防止数据外泄 —— 威胁情报数据进入 sandbox 进行分析。即使 agent 因 prompt injection 或随机行为而变得具有恶意，该设计也能阻止这些数据外泄到互联网。

其他安全实践：

- 受控的数据摄取：明确哪些类型的数据可以进入 Code Interpreter，以及允许哪些写入操作。
- 子处理者对齐：Code Interpreter 运行在既有的 AWS 子处理者（subprocessor）关系之下，降低合规开销。
- 网络隔离分层：在既有网络隔离 harness 之上再叠加 sandbox 隔离，形成纵深防御。

## 经验总结与最佳实践

在 Abnormal AI 的生产环境中运行 Code Interpreter，沉淀出若干实践。

### 1. 给 agent 它真正需要的东西

相比僵化的分步 workflow，轻量、通用的 harness 能让 agent 表现更好。给出解决问题的高层原则，让 agent 运用自身的智能来决定做法。

### 2. 每个 agent 都需要暂存区

Code Interpreter 并不只服务于编码 agent。分析邮件的安全 agent 同样受益于计算暂存区，用于数据聚合、模式分析与验证。

### 3. 用程序化校验器作为 guardrail

当 agent 拥有程序化验证工具时，其输出质量更高。单元测试、集成测试与 linting 让 agent 在交付最终结果之前，能够先在 sandbox 内自测。

### 4. 把文件系统作为长任务的恢复点

对于超出 Code Interpreter 会话时长的操作（例如模型训练），把文件系统当作检查点。用 Code Interpreter 做计算，把状态持久化到文件，在外部执行长时间运行的操作，然后重新调用 Code Interpreter 处理结果。分析师 agent（图 3）在长达一天的模型训练作业中就采用了这一模式。

## 结论

Abnormal AI 的实现揭示了一个关于生产级 agent 系统的关键洞见：Code Interpreter 不仅仅是编码工具，它是 agent 用来进行计算式推理的基础设施。通过把 AgentCore Code Interpreter 托管且安全的 sandbox 与自身轻量的 agent harness 相结合，Abnormal 实现了：

- 通过 sandbox 隔离形成零信任安全态势，帮助防止数据外泄。
- 把 agent 算力留给最难的情况（图 2），从而支撑十亿级邮件规模。

无论你是在构建安全 agent，还是在构建让 agent 处理数据并验证自身输出的系统，这个模式都很清晰：给 agent 一块暂存区，并且相比它们的断言，更信任它们的评估结果。
