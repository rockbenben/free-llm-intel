# 使用 Amazon Bedrock Agents 编排无缝的业务系统集成

生成式 AI 通过生成内容与解决复杂问题，彻底改变了技术格局。要充分释放这一潜力，与现有业务系统的无缝集成以及对数据的高效访问至关重要。[Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 提供了集成能力，可把生成式 AI 模型与组织内已有的丰富信息和工作流连接起来，从而创建高效且有影响力的生成式 AI 应用。

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项全托管服务，让你能通过单一 API，借助领先 AI 公司的高性能基础模型（FM）开发和部署生成式 AI 应用。Amazon Bedrock Agents 让你能够精简 workflow，并跨公司系统与数据源自动化重复性任务，同时保持安全、隐私和负责任的 AI 实践。借助这些 agent，你可以让生成式 AI 应用跨公司系统与数据源执行多项任务。企业现在可以释放生成式 AI 的力量来自动化任务、生成内容并解决复杂问题——同时保持与关键企业系统和数据源的连接。

本文通过一个虚构的业务流程，展示如何利用生成式 AI 进行逻辑处理、推理并编排集成。文中演示了编排 Amazon Bedrock agent 与 action group 的策略和技术，以便把生成式 AI 与现有业务系统无缝集成，实现高效的数据访问，释放生成式 AI 的全部潜力。

本解决方案还与 [Appian Case Management Studio](https://docs.appian.com/suite/help/24.4/case-management-studio-overview.html) 集成。用例（case）是用例管理应用的关键组成部分，代表一系列待完成的任务或一个待解决的多步问题。Appian Case Management Studio 是一套开箱即用的应用套件，可加速用例管理应用的开发。本文使用的虚构业务流程会在 Appian 中创建一个用例以供进一步审查。

## 业务流程

下面的 workflow 展示了这个虚构的业务流程。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/22/ml-17263_businessflow.png)

该 workflow 包含以下步骤：

- 用户要求生成式 AI 助手判断某台设备是否需要审查。
- 如果提供了设备类型，助手会检查它是否为 Type 3 设备。
- 如果是 Type 3 设备，助手会向用户询问设备名称。
- 助手检查是否存在使用所提供名称的文档。
- 如果文档存在，助手会在 Appian 中创建一个用例以启动审查。
- 如果文档不存在，助手会发送一封邮件请求审查。

## 解决方案概览

下图展示了该解决方案的架构。

![architecture](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/22/ml-17263_architecture.png)

系统 workflow 包含以下步骤：

- 用户与生成式 AI 应用交互，该应用连接到 Amazon Bedrock Agents。
- 该应用使用 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 回答用户的问题。这些知识库以 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）作为数据源、以 [Amazon Titan](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html)（或你选择的其他模型）作为嵌入模型创建。
- Amazon Bedrock Agents 使用 action group 与不同系统集成。
- action group 调用虚拟私有云（VPC）私有子网中的不同 [AWS Lambda](https://aws.amazon.com/lambda) 函数。
- agent 使用 tree-of-thought（ToT）prompt 执行 action group 中的不同动作。
- 一个 Lambda 函数从 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 获取设备的分类。该函数通过[网关端点](https://docs.aws.amazon.com/vpc/latest/privatelink/gateway-endpoints.html)调用 DynamoDB。
- 一个 Lambda 函数检查 Amazon S3 中是否存在质量文档。该函数通过[接口端点](https://docs.aws.amazon.com/vpc/latest/privatelink/create-interface-endpoint.html)调用 Amazon S3。
- 一个 Lambda 函数使用公有[子网](https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html)中的 [NAT 网关](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-nat-gateway.html)调用 Appian REST API。
- Appian 密钥存储在 [AWS Secrets Manager](https://aws.amazon.com/secrets-manager/) 中。
- 一个 Lambda 函数使用 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）权限对 [Amazon Simple Email Service](https://aws.amazon.com/ses)（Amazon SES）发起 SDK 调用。Amazon SES 通过 SMTP 向用户提供的已验证邮箱发送邮件。

## 先决条件

在构建该解决方案之前，你需要满足以下先决条件：

- 一个有效的 AWS 账户。
- 对 Anthropic 的 Claude 3 Sonnet 或你打算使用的模型的访问权限（更多信息请参见[访问 Amazon Bedrock 基础模型](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)）。本文使用 Anthropic 的 Claude 3 Sonnet，所有说明均针对该模型。如果你想使用其他 FM，请相应更新 prompt。
- 账户中具有足够权限以创建所需资源的 IAM 角色。
- 已为运营和风险审计启用 [AWS CloudTrail](https://aws.amazon.com/cloudtrail) 日志记录。更多详情请参见[为你的 AWS 账户创建跟踪](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-create-and-update-a-trail.html)。
- 已启用 [AWS Budgets](https://aws.amazon.com/aws-cost-management/aws-budgets/) 策略通知，以免产生意外账单。更多详情请参见[启用 Budget 策略](https://docs.aws.amazon.com/cost-management/latest/userguide/budgets-controls.html)。
- 两个用于发送和接收邮件的邮箱地址。不要使用 Amazon SES 中已有的已验证身份作为这两个邮箱地址，否则 [AWS CloudFormation](https://aws.amazon.com/cloudformation) 模板会失败。

该解决方案仅在 `us-east-1` AWS 区域受支持。你可以对 CloudFormation 模板做必要修改，以部署到其他区域。

## 编写有效的 prompt

在配置 agent 之前，我们先定义一个 prompt。prompt 是释放 Amazon Bedrock agent 全部潜力的关键。prompt 是引导 agent 行为与响应的文本输入。编写设计良好的 prompt，对于确保 agent 理解上下文、意图和期望输出至关重要。

在编写 prompt 时，请考虑以下最佳实践：

- 提供清晰、简洁的说明
- 包含相关的背景信息和上下文
- 遵循模型的最佳实践来格式化 prompt

Amazon Bedrock Agents 支持高级 prompt 技术：[思维链（CoT）](https://www.promptingguide.ai/techniques/cot)与[思维树（ToT）](https://www.promptingguide.ai/techniques/tot)prompt。CoT prompt 通过把复杂问题或任务拆解为更小、更易管理的步骤，增强 FM 的推理能力。ToT prompt 则通过把更大的问题陈述拆解为树状结构（每个问题被拆分为更小的子问题）来提升 FM 的推理能力。我们使用[思维树（ToT）](https://www.promptingguide.ai/techniques/tot)prompt，先把业务流程拆解为逻辑步骤，再套用模型要求的格式。

以下是为 Anthropic 的 Claude 3 Sonnet 编写的 prompt：

```
You are an agent that helps determine if device requires a quality review and you always use actions groups to answer. To verify if a review is needed, follow these steps:

1. Ask the user to provide the device type. If not provided, prompt for it.
2. Fetch the device classification from the database based on the provided device type using deviceClassification action group
3. If the classification returned from action group is Class III or 3
4. Ask the user for the specific device name.
5. Check if the device name has quality review forms using the verifyifformsExists action group
6. If a quality review document exists:
7. Prepare an email with the relevant content.
8. Ask for to email address and from email address
9. Send the email to the user.
10. If no quality review document exists, create a case.
```

## 创建 action group

完成以下步骤，为新建的 agent 创建 action group：

- 在 Amazon Bedrock 控制台的导航窗格中选择 **Agents**。
- 选择新建的 agent，然后选择 **Edit in Agent Builder**。
- 在 **Action groups** 部分，选择 **Add**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ml-17263actiongroup-resized.png)

- 在 **Action group details** 部分，把自动生成的名称改为 `checkdeviceclassification`，并为 action group 提供可选的描述。
- 在 **Action group type** 部分，选择 **Define with API schemas** 以使用 OpenAPI schema。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ml-17263_defineschema-resized.png)

- 在 **Action group invocation **部分，选择 **Select an existing Lambda function** 以使用现有的 Lambda 函数。
- 在下拉菜单中选择名称包含 `DeviceClassification` 的 Lambda 函数。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ml-17263_selectLambda-resized.png)

- 在 **Action group schema** 部分，选择 **Define via in-line schema editor** 以定义 schema。
- 在旁边的下拉菜单中选择 **JSON **
- 打开前面下载的设备分类文件，复制 schema 文件的内容。
- 在 schema 编辑器中输入这些内容。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ml-17263_schema-resized.png)

- 选择 **Create** 创建 action group。
- 重复前面的步骤创建更多 action group。使用下表把 action group 对应到各自的 Lambda 函数和 Open API schema。

| **Action group 名称** | **包含该名称的 Lambda 函数 ** | **Open API schema** |
| --- | --- | --- |
| **checkdeviceclassification** | DeviceClassification | deviceclassification.json |
| **verifyqualitydocuments** | VerifyQualityDocuments | verifyQualityDocuments.json |
| **emailreviewers** | EmailReviewers | emailReviewers.json |
| **appiancase** | Appian | appian-case.json |

要针对你的具体用例定制 agent 的行为，你可以修改预处理、编排、知识库响应生成和后处理步骤的 prompt 模板。更多信息请参见[在 Amazon Bedrock 中使用高级 prompt 模板提升 agent 的准确性](https://docs.aws.amazon.com/bedrock/latest/userguide/advanced-prompts.html)。

由于 HIV diagnostic tests 的分类是 Type 3，agent 会询问设备名称，以校验质量文档是否存在。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ml-17263_companyname-resize.png)

- 输入 `anytech`。

agent 会校验名为 `anytech` 的文档是否存在于 Amazon S3 中。（前面你已经为 `anytech` 上传了一个示例文档。）

agent 现在应该会要求提供一个接收质量审查请求的邮箱地址。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ml-17263_emailaddress-resize.png)

系统会发送一封包含审查详情的邮件。

- 重复前面的步骤，但这次把文档名称输入为 `anytechorg`。

我们没有上传名为 `anytechorg` 的文档，因此 agent 会通过询问以下信息来创建一个用例：

- 名字
- 姓氏
- 手机号码
- 描述
- 用例标题

- 向 agent 提供所需信息。

在构建高效且架构良好的生成式 AI 应用时，请考虑以下最佳实践：
