# Amazon Bedrock Model Distillation（预览）指南

在使用生成式 AI 时，用低成本、低延迟的模型实现高性能往往是一大挑战，因为这些目标之间会相互冲突。借助新推出的 Amazon Bedrock Model Distillation 功能，你可以使用更小、更快、成本更低的模型，在特定用例上达到与 Amazon Bedrock 中最大、能力最强的模型相当的、针对具体用例的准确率。

模型蒸馏（model distillation）是把知识从能力更强的高级模型（teacher）迁移到更小模型（student）的过程，这样做速度更快、成本更低，可以让 student 模型在特定用例上达到与 teacher 相当的性能。为了完成知识迁移，会先用你针对具体用例的 prompt 让 teacher 模型生成回答，再用 teacher 的回答去微调 student 模型。

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项完全托管的服务，提供多种高性能的[基础模型（FM）](https://aws.amazon.com/what-is/foundation-models/)，以及一整套用于构建[生成式 AI](https://aws.amazon.com/ai/generative-ai/) 应用的能力，并通过安全性、隐私保护和负责任 AI 简化开发工作。借助 Amazon Bedrock Model Distillation，你现在可以用能力很强的模型生成的合成数据，为你的用例定制模型。在预览阶段，Amazon Bedrock Model Distillation 支持三家模型提供商：Amazon、Anthropic 和 Meta。teacher 模型和 student 模型必须来自同一家模型提供商。

本文介绍 Amazon Bedrock Model Distillation 的工作流。我们首先介绍 Amazon Bedrock 中模型蒸馏的总体概念，然后重点讲解模型蒸馏中的关键步骤，包括设置权限、选择模型、提供输入数据集、启动模型蒸馏作业，以及在模型蒸馏完成后对 student 模型进行评估和部署。

## Amazon Bedrock Model Distillation 的主要优势

- **效率**：蒸馏后的模型能提供与能力最强的模型相当的、针对具体用例的高准确率，同时速度可与一些最小的模型媲美。
- **成本优化**：与更大的高级模型相比，蒸馏模型的推理成本更低。
- **高级定制**：Amazon Bedrock Model Distillation 免去了为微调创建带标签数据集的麻烦。Amazon Bedrock 在幕后加入数据合成（最多 15,000 条 prompt-response 配对）和增强技术，自动生成高质量的 teacher 回答，从而构建多样且大规模的训练数据集用于微调 student 模型；这些技术会自动适配你的用例，优化蒸馏模型的性能。
- **易用性**：Amazon Bedrock Model Distillation 提供单一工作流，自动生成 teacher 回答、加入数据合成以改进 teacher 回答，并通过优化的超参数调优来微调 student 模型。

## Amazon Bedrock Model Distillation 的用例

通过把知识从更大的模型蒸馏到更小、更灵活的模型中，组织能够开发经过优化的 AI 解决方案，从而获得更高的投资回报。以下是蒸馏模型可以产生显著影响的一些应用场景：

- **检索增强生成（RAG）**：支撑企业级搜索与知识检索系统，以远低于大型模型的成本处理数千条并发查询，让大规模部署变得更加可行。
- **文档摘要**：实时处理海量业务内容，例如每天汇总数千份客户通话记录，从而在以往受延迟制约的规模上获得洞察。
- **聊天机器人部署**：为客服聊天机器人提供支持，以持续稳定的低延迟处理数千个并发实时会话，交付大型模型的质量，但运营成本显著更低。
- **文本分类**：构建更快的模型，大规模地对大量并发的 support ticket、电子邮件或客户反馈进行分类；或在必要时高效地把请求路由到更大的模型。这种方式可以在保持分类准确率的同时显著降低处理成本，并实时响应客户需求。

### Amazon Bedrock Model Distillation 工作流

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/02/ML-17891-image001.png)

Amazon Bedrock 在使用 Amazon Bedrock Model Distillation 时提供两种方式。在第一种方式中，你可以通过提供生产数据来创建蒸馏模型，这些数据来自你此前在 Amazon Bedrock 中交互时留下的历史调用日志。在生产环境中，你继续使用现有的 Amazon Bedrock 推理 API，例如 `InvokeModel` 或 `Converse` API，并开启会存储模型输入数据（prompt）和模型输出数据（response）的调用日志。你还可以选择在这些推理请求中加入请求元数据，以便按具体用例筛选调用日志。默认情况下，Amazon Bedrock 只从调用日志中读取 prompt，并由你在蒸馏作业中选择的 teacher 模型生成回答。在这种情形下，Amazon Bedrock 可能会应用专有的数据合成技术，由 teacher 模型生成多样且高质量的回答，以扩充微调数据集，从而有可能提升蒸馏后 student 模型的性能。随后，student 模型使用 prompt 与 teacher 回答构成的配对进行微调。你也可以配置 Amazon Bedrock，让它同时从调用日志中提取 prompt 和回答。在这种情形下，蒸馏作业中选择的 teacher 模型必须与调用日志中的 teacher 模型一致。此时不会应用数据合成技术。prompt-response 配对按调用日志中的原样取用，并据此微调 student 模型。

在第二种方式中，你可以把针对具体用例的 prompt 直接上传到 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3) 的 JSONL 文件中，文件中包含你针对具体用例的 prompt 或标注好的 prompt-completion 配对。Amazon Bedrock 会针对所提供的 prompt 由 teacher 模型生成回答。如果你提供了代表标准答案的人工标注数据集，Amazon Bedrock 可以把这些 prompt-response 配对作为金标准示例，用来生成更好的 teacher 回答。随后，student 模型使用由 teacher 模型生成的 prompt-response 配对进行微调。

## 先决条件

要使用模型蒸馏功能，请确保你已满足以下要求：

- 一个有效的 [AWS 账户](https://signin.aws.amazon.com/signup?request_type=builderId)。
- 已在 Amazon Bedrock 中启用所选的 teacher 模型和 student 模型。你可以在 Amazon Bedrock 控制台的 **Model access** 页面确认这些模型是否已启用。
- 确认模型可用的 [AWS 区域](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)以及配额。
- 要使用 Amazon Bedrock 创建模型蒸馏作业，你需要创建一个 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam/) 角色并授予以下权限：  一个[信任关系](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-iam-role.html#model-customization-iam-role-trust)，允许 Amazon Bedrock 担任该角色 访问 Amazon S3 中输入数据和历史调用日志的权限 向 Amazon S3 写入输出数据的权限 可选：如果你使用 KMS 密钥加密了资源，还需要解密 [AWS Key Management Service（AWS KMS）](https://aws.amazon.com/kms) 密钥的权限

- 一个 S3 存储桶，用于存放蒸馏作业的输出指标。
- 如果你为蒸馏提供输入数据集，请使用 Amazon S3 存储输入数据  或者，如果你使用历史调用日志进行模型蒸馏，请确保已在 AWS 管理控制台中启用调用日志，并且历史调用日志已存储在某个 S3 位置。为此，请前往 Amazon Bedrock 控制台，选择左下角的 **Settings**，如截图所示：
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/02/ML-17891-image003.png) 在下一页，确认已启用 **Model invocation logging**，并选择 **S3 only** 作为日志记录目标。（可选，你也可以选择 **Both S3 and CloudWatch Logs ** 作为目标。）
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/02/ML-17891-image005.png)
- 确保你有足够的配额，以便在推理期间运行 Provisioned Throughput。前往 **AWS Service Quotas** 控制台，检查以下配额：  **Model units no-commitment Provisioned Throughputs across custom models**  **Model units per provisioned model for [student model name]**

这两个字段都需要有足够的配额来支撑你的 Provisioned Throughput 模型单元。如有必要，请申请提高配额，以满足预期的推理负载。

## 模型选择

目前，Amazon Bedrock Model Distillation 支持同一模型提供商（例如 Amazon、Anthropic 或 Meta）内部的 student-teacher 组合。

为蒸馏选择合适的模型至关重要。这个过程包括选择一个 teacher 模型用于生成合成数据，以及选择一个 student 模型来学习 teacher 的输出。teacher 模型通常更大、能力更强，而 student 模型更小、更快、成本更低。

选择模型时，请考虑三个关键维度：性能、延迟和成本。这些因素相互关联，调整其中一个就可能影响其他两个。

- **性能**：为你的用例设定清晰的性能目标，例如准确率、一致性或无毒性。选择一个达到或超过你期望性能水平的 teacher 模型。蒸馏的预期是提升 student 模型的性能，使其接近 teacher 模型。
- **延迟**：选择满足你延迟要求的 student 模型。最终蒸馏出的模型会具有你所选 student 模型相同的延迟特征。
- **成本**：考虑模型整个生命周期内的总拥有成本（TCO），包括为生成合成数据而进行的 teacher 模型推理、student 模型微调、蒸馏模型的推理成本，以及自定义模型存储。

## 蒸馏输入数据集

为在 Amazon Bedrock 中进行蒸馏，准备针对具体用例的输入数据主要有两种方式：

- 将 JSONL 文件上传到 Amazon S3
- 使用历史调用日志

### 将 JSONL 文件上传到 S3

如果你有 JSON Lines（JSONL）格式的数据集，可以将其上传到某个 S3 存储桶。该 JSONL 文件中的每条记录使用以下结构：

```
{
    "schemaVersion": "bedrock-conversation-2024",
    "system": [
        {
            "text": string
        }
    ],
    "messages": [
        {
            "role": "user",
            "content": [
                {
                    "text": string
                }
            ]
        },
        {
            "role": "assistant"
            "content": [
               {
                   "text": string
               }
            ]
        }
    ]
}
```

具体来说，每条记录都有一个必填字段 `schemaVersion`，在本次发布中其值必须为 `bedrock-conversation-2024`。记录可以选择包含一个 system prompt，用于指明赋予模型的角色。在 messages 字段中，user 角色是必需的，它包含提供给模型的输入 prompt；而包含期望回答的 assistant 角色则是可选的。

在预览阶段，Anthropic 和 Meta 模型只接受单轮对话 prompt，也就是说你只能有一个 user prompt。Amazon（Nova）模型支持多轮对话，允许你在一条记录中提供多组 user 与 assistant 的往复。

### 使用历史调用日志

另一种做法是，使用存储在 Amazon S3 中的历史调用日志进行模型蒸馏。这些日志记录了此前模型交互的 prompt、回答和元数据，是很有价值的数据来源。要使用这种方法：

- **启用调用日志**：确认你已为账户启用调用日志。如果还没有，请参阅先决条件部分了解具体做法。
- **为模型调用添加元数据**：在使用 [InvokeModel ](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_InvokeModel.html)或 [Converse API](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html) 调用模型时，加入一个 `requestMetadata` 字段，其键值为 `paris`。这样你之后就能对交互进行分类和筛选。下面是一个使用 `Converse` API 的示例：

```
{
    "additionalModelRequestFields": JSON value,
    "additionalModelResponseFieldPaths": ["string"],
    "guardrailConfig": {
        "guardrailIdentifier": "string",
        "guardrailVersion": "string",
        "trace": "string"
    },
    "inferenceConfig": {
        "maxTokens": number,
        "stopSequences": ["string"],
        "temperature": number,
        "topP": number
    },
    "messages": [{
        "content": [{
            ...
        }],
        "role": "string"
    }],
    "system": [{
        ...
    }],
    "toolConfig": {
        "toolChoice": {
            ...
        },
        "tools": [{
            ...
        }]
    },
    "requestMetadata": {
        "string": "string", // {"key": "value"}
        "string": "string", // {"key": "value"}
        "string": "string"  // {"key": "value"}
    }
}
```

针对一个示例用例，`requestMetadata` 字段的一个具体示例如下：

```
 "requestMetadata":{ 
    "project": "CustomerService", 
    "intent": "BestPractices", 
    "priority": "Medium" }
```

- **选择用于蒸馏的日志**：创建模型自定义作业时，你可以指定筛选条件，选择使用哪些调用日志。该 API 支持多种筛选选项：  包含特定日志：  ` "requestMetadataFilters": { "equals": {"project": "CustomerService"} }`  排除特定日志：  ` "requestMetadataFilters": { "notEquals": {"priority": "Low"} }`  组合多个条件：  `"requestMetadataFilters": { "andAll": [ {"equals": {"project": "CustomerService"}}, {"notEquals": {"priority": "Low"}} ] }`  使用 `OR` 逻辑：  `"requestMetadataFilters": { "orAll": [ {"equals": {"intent": "ComplaintResolution"}}, {"equals": {"intent": "ProductInquiry"}} ] }`

按照这些步骤，你就能精确控制调用日志中的哪些数据用于蒸馏，从而针对特定的用例、项目或工作流。

### 选择合适的数据

在为蒸馏选择数据时，无论是通过新的训练 JSONL 文件还是历史调用日志，关键是要挑选与你的用例相关的 prompt 和回答。数据的质量和多样性会直接影响蒸馏模型的性能。

一般来说，你应当力求纳入覆盖与用例相关的广泛主题和场景的 prompt；更重要的是，一种好的做法还包括针对 teacher 模型优化 prompt 以获得更好的回答，这样蒸馏才能完成从 teacher 到 student 的高质量知识迁移。具体来说，对于 RAG 这类用例，请确保纳入包含相关上下文、可供模型使用的 prompt。对于需要特定回答风格或格式的任务，纳入符合期望风格或格式的示例很重要。

在整理用于蒸馏的数据时要多加留意，帮助确保蒸馏模型能从 teacher 模型学到最相关、最有价值的知识，从而针对你的具体用例优化其性能。

## 运行模型蒸馏

你可以通过 Amazon Bedrock 控制台启动蒸馏作业，也可以使用 Amazon Bedrock API 以编程方式启动。蒸馏过程需要训练数据，可以按我们在上一节准备的方式，把 JSONL 格式的训练数据上传到 Amazon S3，或使用历史模型调用日志。

在启动模型蒸馏作业之前，请确保你的操作在 [Amazon Bedrock 蒸馏服务配额](https://docs.aws.amazon.com/general/latest/gr/bedrock.html)范围内。

接下来我们看看如何用不同方式启动蒸馏作业。在下面的示例中，我们使用 Llama 3.1 70B 作为 teacher 模型，使用 Llama 3.1 8B 作为 student 模型。

### 使用控制台启动蒸馏作业

Amazon Bedrock Model Distillation 允许你通过控制台中引导式的用户界面来运行蒸馏作业。要使用控制台启动蒸馏作业，请按以下步骤操作：

- 前往 **Amazon Bedrock ** 控制台。在导航窗格中选择 **Foundation models**，然后选择 **Custom models**。在 **Customization methods** 部分选择 **Create Distillation job**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/02/ML-17891-image007.png)

- 在 **Distilled model name** 中输入模型名称。选择 **Model encryption** 以添加 KMS 密钥。可选：展开 **Tags** 部分以添加用于跟踪的标签。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/02/ML-17891-image009.png)
- 在 **Job name** 中输入训练作业的名称。可选：展开 **Tags** 部分以添加用于跟踪的标签。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/02/ML-17891-image011.png)
- 选择 **Select model**，挑选你想要的 teacher 模型。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/02/ML-17891-image013.png)
- 在 **Categories** 中选择 **Meta ** 模型族。在 **Models available for distillation** 中选择 **Llama 3.1 70B Instruct**。选择 **Apply**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/03/ML-17891-image015-1.png)
- 打开 **Select a student model** 下的下拉列表。在本示例中，选择** Llama 3.1 8B Instruct**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/03/ML-17891-image017-1.png)
- 通过滑块或直接在输入框中指定 **Max response length **。此配置将作为 teacher 模型生成合成数据的推理参数。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/03/ML-17891-image019-1.png)
- 正如上一节所述，提供蒸馏输入数据集有两种方式。

你还可以配置 Amazon Bedrock，让它只读取你的 prompt，或者使用 prompt-response 配对。如果选择只读取 prompt，Amazon Bedrock 会由 teacher 模型重新生成回答；如果选择使用 prompt-response 配对，Amazon Bedrock 会直接使用日志中已有的回答，不再重新生成。

如果你希望 Amazon Bedrock 复用调用日志中的回答，请确保用于蒸馏的 teacher 模型与调用日志中使用的模型是同一个。

### 使用 API 以 S3 JSONL 数据启动蒸馏作业

要使用 API 以存储在 S3 存储桶中的训练数据启动蒸馏作业，请按以下步骤操作：

- 首先，创建并配置一个 Amazon Bedrock 客户端：  `import boto3 from datetime import datetime bedrock_client = boto3.client(service_name="bedrock") # Generate unique names for the job and model job_name = f"distillation-job-{datetime.now().strftime('%Y-%m-%d-%H-%M-%S')}" model_name = f"distilled-model-{datetime.now().strftime('%Y-%m-%d-%H-%M-%S')}" # Configure your models and IAM role teacher_model = "arn:aws:bedrock:us-west-2::foundation-model/meta.llama3-1-70b-instruct-v1:0" student_model = "arn:aws:bedrock:us-west-2::foundation-model/meta.llama3-1-8b-instruct-v1:0:128k" role_arn = "arn:aws:iam::<YOUR_ACCOUNT_ID>:role/<YOUR_IAM_ROLE>" # Specify S3 locations for training data and output training_data = "s3://<YOUR_BUCKET>/training-data.jsonl" # Replace by your training file output_path = "s3://<YOUR_BUCKET>/output/" # Specify MaxResponseLengthForInference parameter max_response_length = 1000`
- 使用 `create_model_customization_job` 创建蒸馏作业：  `distillation_job_response = bedrock_client.create_model_customization_job( jobName=job_name, customModelName=model_name, roleArn=role_arn, baseModelIdentifier=student_model, customizationType="DISTILLATION", trainingDataConfig={ "s3Uri": training_data }, outputDataConfig={ "s3Uri": output_path }, customizationConfig={ "distillationConfig": { "teacherModelConfig": { "teacherModelIdentifier": teacher_model, "maxResponseLengthForInference": max_response_length } } } )`
- 提供模型蒸馏作业的 `job_arn`，即可监控蒸馏作业的进度：  `response = bedrock_client.get_model_customization_job( jobIdentifier=job_arn # Replace by your distillation job_arn )`

### 使用 API 以调用日志启动蒸馏作业

要以模型调用日志作为训练数据，请确保你已在 S3 存储桶中收集了足够的调用日志。首先，按照数据准备部分提到的支持逻辑定义日志筛选条件：

```
# Configure the training data using invocation logs
training_data_config = {
    'invocationLogsConfig': {
        'usePromptResponse': False,
        'invocationLogSource': {
            's3Uri': 's3://<YOUR_BUCKET>/<BUCKET_PREFIX>/AWSLogs' # Replace by your S3 location
        },
        'requestMetadataFilters': {
            'equals': {
                'project': 'CustomerService'  # Filter logs based on metadata
            }
        }
    }
}
```

`invocationLogsConfig` 允许你指定存储调用日志的 Amazon S3 位置、是使用日志中的 prompt-response 配对还是由 teacher 模型生成新回答，以及基于请求元数据选择特定日志的筛选条件。

然后，用同一个 `create_model_customization_job` API 创建蒸馏作业（配置参数与上一节相同）：

```
distillation_job_response = bedrock_client.create_model_customization_job(
    jobName=job_name,
    customModelName=model_name,
    roleArn=role_arn,
    baseModelIdentifier=student_model,
    customizationType="DISTILLATION",
    trainingDataConfig=training_data_config,
    outputDataConfig={
        "s3Uri": output_path
    },
    customizationConfig={
        "distillationConfig": {
            "teacherModelConfig": {
                "teacherModelIdentifier": teacher_model,
                "maxResponseLengthForInference": max_response_length
            }
        }
    }
)
```

## 部署并评估模型蒸馏

蒸馏模型之后，你可以评估过程中记录的蒸馏指标。这些指标存储在指定的 S3 存储桶中供评估使用，其中包括按步记录的训练指标，列名为 `step_number`、`epoch_number` 和 `training_loss`。

当你对蒸馏指标满意后，可以购买 Provisioned Throughput 来部署微调后的模型，从而在应用中使用蒸馏模型提升后的性能和专项能力。Provisioned Throughput 指的是模型处理和返回的输入与输出的数量和速率。要使用蒸馏模型，你必须购买 Provisioned Throughput，按小时计费。Provisioned Throughput 的价格取决于以下因素：

- 所选的 student 模型。
- 为 Provisioned Throughput 指定的模型单元（MU）数量。MU 是用于指定某个模型吞吐容量的单位；每个 MU 定义了它在 1 分钟内所有请求中可处理的输入 token 数量和可生成的输出 token 数量。
- 承诺时长，可以是无承诺、1 个月或 6 个月。承诺时间越长，每小时费率的折扣越大。

Provisioned Throughput 设置完成后，你可以使用 [InvokeModel](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_InvokeModel.html) 或 [Converse API](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html) 调用蒸馏模型，方式与调用基础模型类似。这样可以实现无缝迁移，并保持与现有应用或工作流的兼容性。

评估蒸馏模型的性能至关重要，以确保它满足期望的标准，并在特定任务上表现更优。你可以进行多种评估，包括将蒸馏模型与 teacher 模型进行比较，以验证其性能。

### 使用 Amazon Bedrock API 部署蒸馏模型

要使用 [Amazon Bedrock API](https://docs.aws.amazon.com/pdfs/bedrock/latest/APIReference/bedrock-api.pdf) 部署蒸馏模型，请完成以下步骤：

- 从作业输出中获取蒸馏模型的 ID，并用所需的模型单元创建一个 Provisioned Throughput 模型实例：  `import boto3 bedrock_client = boto3.client(service_name="bedrock") job_arn = distillation_job_response['jobArn'] custom_model_id = bedrock_client.get_model_customization_job(jobIdentifier=job_arn)['outputModelArn'] provisioned_model_id = bedrock_client.create_provisioned_model_throughput( modelUnits=1, # Update model unites with desired number provisionedModelName='distilled-model', modelId=custom_model_id )['provisionedModelArn']`
- 运行以下命令检查 Provisioned Throughput 模型的状态：  `bedrock_client.get_provisioned_model_throughput(provisionedModelId=provisioned_model_id)['status']`
- 当 Provisioned Throughput 模型就绪后，你可以使用 `InvokeModel` 或 `Converse` API 调用该模型，用蒸馏模型生成文本：  `bedrock_runtime = boto3.client(service_name='bedrock-runtime') conversation = [ { "role": "user", "content": [{"text": <YOUR_INPUT_TEXT_PROMPT>}], } ] inferenceConfig = {"maxTokens": 2048, "temperature": 0.1, "topP": 0.9} response = bedrock_runtime.converse(modelId=provisioned_model_id, messages=conversation, inferenceConfig=inferenceConfig, ) response_text = response["output"]["message"]["content"][0]["text"]`

按照这些步骤，你可以通过 Amazon Bedrock API 部署并使用蒸馏模型，从而生成针对你的用例量身定制的、高效且高性能的 student 模型。部署蒸馏模型后，你可以在多种 Amazon Bedrock 服务中用它进行推理，包括 [Knowledge Base](https://aws.amazon.com/bedrock/knowledge-bases/) 推理、[Playground](https://docs.aws.amazon.com/bedrock/latest/userguide/playgrounds.html)，以及任何可以使用自定义模型进行推理的其他服务。

## 结论

Amazon Bedrock Model Distillation 让你能够创建高效、成本优化的 student 模型，在特定用例上接近更大 teacher 模型的性能。通过把从高级模型到更小模型的知识迁移这一复杂过程自动化，Amazon Bedrock 简化了更快、更便宜的 AI 解决方案的部署，同时不牺牲准确率。客户可以获得效率提升、易用性、科学创新，以及在 Anthropic 和 Amazon 等提供商之间蒸馏模型的独占访问能力。借助 Amazon Bedrock Model Distillation，企业可以在优化延迟、成本和资源约束的同时，发挥基础模型的力量，推动金融服务、内容审核、医疗健康和客户服务等各行业的 AI 创新。

我们鼓励你从访问 Amazon Bedrock 控制台开始，踏上实现高性价比 AI 创新的旅程，探索模型蒸馏如何改变你的业务。
