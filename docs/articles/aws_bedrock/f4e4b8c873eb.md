# 在 Amazon Bedrock 中用 Cohere Embed 4 多模态嵌入模型驱动企业搜索

[Cohere Embed 4](https://cohere.com/embed) 多模态嵌入模型现已作为全托管、无服务器选项在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 中提供。用户可以选择[跨区域推理（CRIS）或全球跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html#inference-profiles-support-system)，利用不同 AWS 区域的计算资源来应对计划外的流量突发。实时信息请求与时区集中，就是可能导致推理需求超出预期流量的示例事件。

Amazon Bedrock 上新的 Embed 4 模型专为分析商业文档而构建。该模型提供领先的多语言能力，并在各项关键基准上相比 Embed 3 有显著提升，因此非常适合企业搜索等用例。

本文深入探讨 Embed 4 在企业搜索用例中的优势与独特能力。我们将展示如何利用 Embed 4 在 Amazon Bedrock 上快速上手，并借助与 [Strands Agents](https://strandsagents.com/latest/)、[S3 Vectors](https://aws.amazon.com/s3/features/vectors/) 以及 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 的集成，构建强大的 agentic 检索增强生成（RAG）工作流。

Embed 4 原生支持由文本、图像以及交错的文本与图像构成的复杂商业文档，并将其统一为单一的向量表示，从而推进了多模态嵌入能力。Embed 4 最多可处理 128,000 个 token，最大限度减少了繁琐的文档切分与预处理流水线。Embed 4 还提供可配置的压缩嵌入，把向量存储成本最多降低 83%（[推出 Embed 4：面向商业的多模态搜索](https://cohere.com/blog/embed-4)）。再加上对 100 多种语言的多语言理解能力，金融、医疗与制造等受监管行业的企业可以高效处理非结构化文档，加快为优化的 RAG 系统提取洞察。如需了解 Embed 4，请阅读[这篇 2025 年 7 月的发布博客](https://aws.amazon.com/blogs/machine-learning/cohere-embed-4-multimodal-embeddings-model-is-now-available-on-amazon-sagemaker-jumpstart/)，探索如何在 [Amazon SageMaker JumpStart](https://aws.amazon.com/sagemaker-ai/jumpstart/) 上部署。

你可以通过 [InvokeModel API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_InvokeModel.html) 把 Embed 4 集成到应用中，下面是一个把 [AWS SDK for Python (Boto3)](https://aws.amazon.com/sdk-for-python/?trk=769a1a2b-8c19-4976-9c45-b6b1226c7d20&sc_channel=el) 与 Embed 4 配合使用的示例：

仅文本输入时：

```
import boto3
import json

# Initialize Bedrock Runtime client
bedrock_runtime = boto3.client('bedrock-runtime', region_name='us-east-1')

# Request body
body = json.dumps({
"texts": [
text1,
          text2],
     "input_type":"search_document",
     "embedding_types": ["float"]
})

# Invoke the model
model_id = 'cohere.embed-v4:0'

response = bedrock_runtime.invoke_model(
    modelId=model_id,
    body=json.dumps(body),
    accept= '*/*',
    contentType='application/json'
)

# Parse response
result = json.loads(response['body'].read())
```

### 企业搜索用例

本节聚焦 Embed 4 在金融行业企业搜索用例中的应用。Embed 4 为希望实现以下目标的企业解锁了一系列能力：

- 简化信息发现
- 增强生成式 AI 工作流
- 优化存储效率

在 Amazon Bedrock 中使用基础模型是完全无服务器的环境，免去了基础设施管理，并简化了与其他 Amazon Bedrock 能力的集成。如需了解更多 [Embed 4 的可能用例](https://aws.amazon.com/blogs/machine-learning/cohere-embed-4-multimodal-embeddings-model-is-now-available-on-amazon-sagemaker-jumpstart/)，请参阅详情。

## 方案概览

借助 Amazon Bedrock 提供的无服务器体验，你可以快速上手，而无需在基础设施管理上投入太多精力。接下来的章节将展示如何开始使用 Cohere Embed 4。Embed 4 在设计时就已经考虑了存储效率。

我们选择 [Amazon S3 vectors](https://aws.amazon.com/s3/features/vectors/) 做存储，因为它是一种成本优化、面向 AI 就绪的存储，原生支持大规模存储与查询向量。S3 vectors 可存储数十亿条向量嵌入，查询延迟低于 1 秒，相比传统向量数据库可将总成本[降低多达 90%](https://aws.amazon.com/s3/features/vectors/)。我们利用可扩展的 Strands Agent SDK 简化 agent 开发，并获得模型选择的灵活性。我们还使用 [Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/)，因为它提供全托管的无服务器运行时，专为处理动态、长时间运行的 agentic 工作负载而构建，具备业界领先的会话隔离、安全性与实时监控。

### 先决条件

开始使用 Embed 4 之前，请确认已具备以下先决条件：

- **IAM 权限**：为你的 IAM 角色配置必要的 Amazon Bedrock 权限，或通过控制台或 SDK 生成 API key 用于测试。详情见 [Amazon Bedrock API key](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-generate.html)。
- **安装 Strands SDK**：为你的开发环境安装所需的 SDK。详情见 [Strands 快速开始指南](https://strandsagents.com/latest/documentation/docs/user-guide/quickstart/)。
- **配置 S3 Vectors**：创建一个 S3 向量存储桶与向量索引，用于存储与查询向量数据。详情见 [S3 Vectors 入门教程](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-getting-started.html)。

### 初始化 Strands agents

[Strands Agents SDK](https://strandsagents.com/latest/) 提供开源、模块化的框架，简化 AI agent 的开发、集成与编排。凭借灵活的架构，开发者可以构建可复用的 agent 组件，并轻松创建自定义工具。系统支持多种模型，让用户可以自由选择最适合其特定用例的方案。模型可以托管在 Amazon Bedrock、Amazon SageMaker 或其他地方。

例如，[Cohere Command A](https://cohere.com/command) 是一个拥有 111B 参数与 256K 上下文长度的生成式模型。该模型擅长工具使用，可以扩展基线功能，同时避免不必要的工具调用。该模型也适合多语言任务，以及金融场景中处理数值信息这类 RAG 任务。当它与专为金融服务等高度受监管行业打造的 Embed 4 配合时，这一组合凭借其适应性带来可观的竞争优势。

我们首先定义一个 Strands agent 可用的工具。该工具使用语义相似度搜索存储在 S3 中的文档。它先用 Cohere Embed 4 把用户查询转换为向量，然后通过查询存储在 S3 向量存储桶中的嵌入，返回最相关的文档。下面的代码只展示推理部分。由金融文档生成的嵌入在查询之前已存入 S3 向量存储桶。

```
# S3 Vector search function for financial documents
@tool
def search(query_text: str, bucket_name: str = "my-s3-vector-bucket", 
           index_name: str = "my-s3-vector-index-1536", top_k: int = 3, 
           category_filter: str = None) -> str:
    """Search financial documents using semantic vector search"""
    
    bedrock = boto3.client("bedrock-runtime", region_name="us-east-1")
    s3vectors = boto3.client("s3vectors", region_name="us-east-1")
    
    # Generate embedding using Cohere Embed v4
    response = bedrock.invoke_model(
        modelId="cohere.embed-v4:0",
        body=json.dumps({
            "texts": [query_text],
            "input_type": "search_query",
            "embedding_types": ["float"]
        }),
        accept='*/*',
        contentType='application/json'
    )
    
    response_body = json.loads(response["body"].read())
    embedding = response_body["embeddings"]["float"][0]
    
    # Query vectors
    query_params = {
        "vectorBucketName": bucket_name,
        "indexName": index_name,
        "queryVector": {"float32": embedding},
        "topK": top_k,
        "returnDistance": True,
        "returnMetadata": True
    }
    
    if category_filter:
        query_params["filter"] = {"category": category_filter}
    
    response = s3vectors.query_vectors(**query_params)
    return json.dumps(response["vectors"], indent=2)
```

接着我们定义一个金融研究 agent，它可以调用该工具搜索金融文档。随着用例变得更复杂，可以增加更多 agent 来处理专门任务。

```

    name="FinancialResearchAgent",
    system_prompt="You are a financial research assistant that can search through financial documents, earnings reports, regulatory filings, and market analysis. Use the search tool to find relevant financial information and provide helpful analysis.",
    tools=[search])
```

### 部署到 Amazon Bedrock AgentCore

agent 构建并测试完成后，就可以部署了。AgentCore Runtime 是专为部署和扩展动态 AI agent 而构建的安全无服务器运行时。使用[入门工具包](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/getting-started-starter-toolkit.html)可自动创建 [IAM 执行角色](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-permissions.html#runtime-permissions-execution-role)、容器镜像与 [Amazon Elastic Container Registry](https://aws.amazon.com/ecr/) 仓库，以便在 AgentCore Runtime 中托管 agent。你可以为 agent 定义多个可用工具。在本例中，我们使用由 Embed 4 驱动的 Strands Agent：

```
# Using bedrock-agentcore<=0.1.5 and bedrock-agentcore-starter-toolkit==0.1.14
from bedrock_agentcore_starter_toolkit import Runtime
from boto3.session import Session
boto_session = Session()
region = boto_session.region_name

agentcore_runtime = Runtime()
agent_name = "search_agent"
response = agentcore_runtime.configure(
    entrypoint="example.py", # Replace with your custom agent and tools
    auto_create_execution_role=True,
    auto_create_ecr=True,
    requirements_file="requirements.txt",
    region=region,
    agent_name=agent_name
)
response
launch_result = agentcore_runtime.launch()
invoke_response = agentcore_runtime.invoke({“prompt”: “Compare earnings growth rates mentioned in the documents”}) 
```

## 结语

Amazon Bedrock 上的 Embed 4 对希望释放非结构化、多模态数据价值的企业很有助益。凭借对最多 128,000 个 token 的支持、面向成本效率的压缩嵌入，以及覆盖 100 多种语言的多语言能力，Embed 4 提供了企业级大规模搜索所需的可扩展性与精确度。

Embed 4 具备先进能力，并针对金融、医疗与制造等受监管行业的数据做了领域特定理解的优化。与 S3 Vectors（成本优化存储）、Strands Agents（agent 编排）以及 Bedrock AgentCore（部署）结合后，组织可以构建安全、高性能的 agentic 工作流，而无需承担管理基础设施的开销。请查看[完整区域列表](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)以获取后续更新。

如需了解更多，请参阅 [Amazon Bedrock 中的 Cohere 产品页](https://aws.amazon.com/bedrock/cohere/)与 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)页面。如果你希望深入了解，请查看[代码示例](https://github.com/aws-samples/Cohere-on-AWS/blob/main/embed-model/multimodal_embed/embedv4_bedrock/cohereembed4.ipynb)与 [Cohere on AWS GitHub 仓库](https://github.com/aws-samples/Cohere-on-AWS)。
