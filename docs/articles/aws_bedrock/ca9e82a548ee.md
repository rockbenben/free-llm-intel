# 在南非使用 Amazon Bedrock 全球跨区域推理与 Anthropic Claude 4.5 模型扩展 AI 规模

*本文由 Anthropic 的 Gareth Jones 共同撰写。*

使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 构建 AI 应用会面临吞吐量挑战，进而影响应用的可扩展性。`af-south-1` AWS 区域中的全球[跨区域推理](https://aws.amazon.com/blogs/machine-learning/unlock-global-ai-inference-scalability-using-new-global-cross-region-inference-on-amazon-bedrock-with-anthropics-claude-sonnet-4-5/)改变了这一局面。现在你可以从开普敦区域调用模型，而 Amazon Bedrock 会自动把请求路由到有空闲容量的区域。你的应用获得一致的响应时间，你的用户获得可靠的体验，而你的 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 和 [AWS CloudTrail](https://aws.amazon.com/cloudtrail/) 日志仍然集中保存在 `af-south-1`。

在开普敦区域（`af-south-1`）的 Amazon Bedrock 上，Anthropic Claude Sonnet 4.5、Haiku 4.5 和 Opus 4.5 的全球跨区域推理让你能够使用 Claude 4.5 模型家族。南非客户现在可以使用全局推理配置文件访问这些模型，获得更高的吞吐量和韧性。全球跨区域推理会把请求路由到全球受支持的商业区域，从而优化资源利用并实现更高吞吐量——在用量高峰期尤其有价值。该功能支持 [Amazon Bedrock prompt caching](https://aws.amazon.com/bedrock/prompt-caching/)、[batch inference](https://docs.aws.amazon.com/bedrock/latest/userguide/batch-inference.html)、[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/)、[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 等。

本文将逐一说明全球跨区域推理如何路由请求、你的数据驻留在何处，然后演示如何配置所需的 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 权限，并使用全局推理配置文件的 Amazon Resource Name（ARN）调用 Claude 4.5 模型。我们还会介绍如何为你的工作负载申请配额提升。读完之后，你将拥有一套可运行的 `af-south-1` 全球跨区域推理实现。

## 理解跨区域推理

跨区域推理是一项强大的功能，组织可以用它把推理处理无缝分布到多个区域。这项能力让你在规模化构建时获得更高吞吐量，使生成式 AI 应用即便在高负载下也能保持响应能力和可靠性。

Amazon Bedrock 中的[推理配置文件](https://docs.aws.amazon.com/en_us/bedrock/latest/userguide/inference-profiles.html)定义了一个基础模型（FM）以及它可以路由模型调用请求的一个或多个区域。推理配置文件基于两个关键概念运行：

- **源区域（Source Region）** – 发起 API 请求的区域
- **目标区域（Destination Region）** – Amazon Bedrock 可以把请求路由到该区域进行推理

跨区域推理通过安全的 AWS 网络运行，对传输中的数据和静态数据都提供端到端加密。当客户从源区域提交推理请求时，跨区域推理会通过 Amazon Bedrock 托管网络，智能地把请求路由到该推理配置文件配置的某个目标区域。

关键区别在于：虽然推理处理（临时计算）可能发生在另一个区域，但静态数据——包括日志、知识库和存储的配置——被设计为保留在你的源区域。请求经由 Bedrock 托管的 [AWS Global Network](https://aws.amazon.com/about-aws/global-infrastructure/global-network/) 传输。跨区域推理期间传输的数据经过加密，并保持在安全的 AWS 网络内。无论由哪个区域处理请求，敏感信息在设计上都受到全程保护，加密后的响应会返回到源区域中的应用。

Amazon Bedrock 提供两种类型的跨区域推理配置文件：

- **地理跨区域推理（Geographic cross-Region inference）**：Amazon Bedrock 在既定地理范围（US、EU、Australia 和 Japan）内自动选择最优商业区域来处理你的推理请求。（推荐用于有数据驻留需求的用例。）
- **全球跨区域推理（Global cross-Region inference）**：全球跨区域推理进一步增强了跨区域推理，可把推理请求路由到全球受支持的商业区域，优化可用资源并实现更高的模型吞吐量。（推荐用于没有数据驻留需求的用例）。

### 监控与日志

借助 `af-south-1` 的全球跨区域推理，你的请求可以在 AWS 全球基础设施的任意位置处理。不过，[Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 和 [AWS CloudTrail](https://aws.amazon.com/cloudtrail/) 日志仍记录在 `af-south-1`，让你的记录集中在一处，从而简化监控。

### 数据安全与合规

安全与合规是 AWS 与每位客户共同承担的责任。全球跨区域推理在设计上维护数据安全。跨区域推理期间传输的数据由 Amazon Bedrock 加密，并被设计为保持在安全的 AWS 网络内。无论由哪个区域处理请求，敏感信息在整个推理过程中都受到保护。客户负责适当地配置自己的应用和 IAM 策略，并评估全球跨区域推理是否满足其特定的安全与合规要求。由于全球跨区域推理会把请求路由到全球受支持的商业区域，你应当评估这种做法是否符合你的监管义务，包括《个人信息保护法》（POPIA）以及其他行业特定要求。我们建议咨询法务与合规团队，为你的具体用例确定合适的做法。

## 实现全球跨区域推理

要使用 Claude 4.5 模型的全球跨区域推理，开发者必须完成以下关键步骤：

- **使用全局推理配置文件 ID** – 在向 Amazon Bedrock 发起 API 调用时，指定全球 Claude 4.5 模型的推理配置文件 ID（例如 `global.anthropic.claude-opus-4-5-20251101-v1:0`）。这对 `InvokeModel` 和 `Converse` API 都适用。
- **配置 IAM 权限** – 授予访问推理配置文件以及潜在目标区域中 FM 的 IAM 权限。下一节会提供更多细节。你也可以阅读更多关于[推理配置文件前提条件](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-prereq.html)的内容。

使用 Claude 4.5 模型实现全球跨区域推理非常直接，只需对现有应用代码做少量改动。下面是一个用 Python 更新代码的示例：

```
import boto3
import json

# Connect to Bedrock from your deployed region
bedrock = boto3.client('bedrock-runtime', region_name='af-south-1')

# Use global cross-Region inference inference profile for Opus 4.5
model_id = "global.anthropic.claude-opus-4-5-20251101-v1:0"  

# Make request - Global CRIS automatically routes to optimal AWS Region globally
response = bedrock.converse(
    messages=[
        {
            "role": "user", 
            "content": [{"text": "Explain cloud computing in 2 sentences."}]
        }
    ],
    modelId=model_id,
)

print("Response:", response['output']['message']['content'][0]['text'])
print("Token usage:", response['usage'])
print("Total tokens:", response['usage']['totalTokens'])
```

如果你使用 Amazon Bedrock [InvokeModel API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_InvokeModel.html)，只需更改模型 ID 就能快速切换到另一个模型，如[调用模型代码示例](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-invoke.html#inference-example-invoke)所示。

## 全球跨区域推理的 IAM 策略要求

全球跨区域推理需要三项特定权限，因为路由机制跨越多个作用域：你的区域级推理配置文件、源区域中的 FM 定义，以及全局级别的 FM 定义。缺少这三项，服务就无法解析模型、验证你的访问权限并在区域之间路由请求。访问 Anthropic 模型需要在调用模型之前提交用例。该提交既可以在单个账户级别完成，也可以通过组织的管理账户集中完成。要提交用例，可使用 `PutUseCaseForModelAccess` API，或在 Amazon Bedrock 的 AWS Management Console 模型目录中选择一个 Anthropic 模型。启用模型需要 AWS Marketplace 权限，在支持的情况下可将其限定到特定产品 ID。

下面的示例 IAM 策略提供了细粒度控制：

```
{
    "Version": "2012-10-17",
    "Statement": [{
            "Sid": "GrantGlobalCrisInferenceProfileRegionAccess",
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:af-south-1:<ACCOUNT>:inference-profile/global.<MODEL NAME>"
            ],
            "Condition": {
                "StringEquals": {
                    "aws:RequestedRegion": "af-south-1"
                }
            }
        },
        {
            "Sid": "GrantGlobalCrisInferenceProfileInRegionModelAccess",
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:af-south-1::foundation-model/<MODEL NAME>"
            ],
            "Condition": {
                "StringEquals": {
                    "aws:RequestedRegion": "af-south-1",
                    "bedrock:InferenceProfileArn": "arn:aws:bedrock:af-south-1:<ACCOUNT>:inference-profile/global.<MODEL NAME>"
                }
            }
        },
        {
            "Sid": "GrantGlobalCrisInferenceProfileGlobalModelAccess",
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:::foundation-model/<MODEL NAME> "
            ],
            "Condition": {
                "StringEquals": {
                    "aws:RequestedRegion": "unspecified",
                    "bedrock:InferenceProfileArn": "arn:aws:bedrock:af-south-1:<ACCOUNT>:inference-profile/global.<MODEL NAME>"
                }
            }
        }
    ]
}
```

该策略由三部分组成。第一条语句授予对 `af-south-1` 中区域级推理配置文件的访问权限，使用户能够从南非调用指定的全球跨区域推理配置文件。第二条语句提供对区域级 FM 资源的访问权限，服务需要借此了解在区域上下文中请求的是哪个模型。第三条语句授予对全局 FM 资源的访问权限，使跨区域路由能够正常工作。

实施这些策略时，请确认包含以下三个 ARN：

- 区域级推理配置文件的 ARN 遵循 `arn:aws:bedrock:af-south-1:<ACCOUNT>:inference-profile/global.`<MODEL NAME> 这一模式。它授予对源区域中全局推理配置文件的访问权限。
- 区域级 FM 使用 `arn:aws:bedrock:af-south-1::foundation-model/`<MODEL NAME>。它授予对 `af-south-1` 中模型定义的访问权限。
- 全局 FM 需要 `arn:aws:bedrock:::foundation-model/`<MODEL NAME>。它授予跨区域访问该模型的权限——注意这个 ARN 有意省略了区域和账户段，以支持跨区域路由。

全局 FM 的 ARN 没有指定区域或账户，这是有意为之，也是跨区域功能所必需的。

**关于服务控制策略（SCP）的重要说明：**如果你的组织使用限制区域的 SCP，请确认 `"aws:RequestedRegion": "unspecified"` 不在拒绝区域列表中，因为全球跨区域推理的请求会使用这个区域值。使用限制性 SCP（除明确批准的区域外拒绝多个区域）的组织需要显式允许该值，才能启用全球跨区域推理功能。

如果你的组织因数据驻留或合规要求认为全球跨区域推理不适合某些工作负载，可以通过以下两种方法之一将其禁用：

- **移除 IAM 权限** – 移除三项必需 IAM 策略语句中的一条或多条。由于全球跨区域推理需要三条语句才能工作，移除其中任何一条都会导致对全局推理配置文件的请求返回访问被拒绝错误。
- **实施显式拒绝策略** – 创建一条使用条件 `"aws:RequestedRegion": "unspecified"` 专门针对全球跨区域推理配置文件的拒绝策略。这种做法清晰地记录了你的安全意图，而且即便日后有人误加了允许策略，显式拒绝也会优先生效。

## 申请全球跨区域推理的限额提升

从 `af-south-1` 使用全球跨区域推理配置文件时，你可以通过 [AWS Service Quotas 控制台](https://console.aws.amazon.com/servicequotas/) 申请配额提升。由于这是全局限额，请求必须在你的源区域（`af-south-1`）中提出。

在申请提升之前，请使用你所用模型的 [burndown rate](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-token-burndown.html) 计算所需配额。对于 Sonnet 4.5 和 Haiku 4.5，输出 token 的 burndown rate 为五倍——每个输出 token 消耗你配额中的 5 个 token——而输入 token 保持 1:1 的比例。每次请求的总 token 消耗为：

```
Input token count + Cache write input tokens + (Output token count x Burndown rate)
```

如需申请限额提升：

- 在 `af-south-1` 中登录 [AWS Service Quotas 控制台](https://console.aws.amazon.com/servicequotas/)。
- 在导航窗格中，选择 **AWS services**。
- 找到并选择 **Amazon Bedrock**。
- 搜索特定的全球跨区域推理配额（例如 *Global cross-Region model inference tokens per minute for Claude Sonnet 4.5 V1*）。
- 选择该配额，然后选择 **Request increase at account level**。
- 输入你期望的配额值并提交请求。
