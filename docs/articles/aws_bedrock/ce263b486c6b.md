# 使用 Amazon Nova 进行基于自然语言的数据库分析

在本文中，我们探讨基于自然语言的数据库分析如何借助[大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLM）agent 的能力，彻底改变组织与其结构化数据交互的方式。面向数据库的自然语言接口长期以来一直是数据管理领域的目标。agent 通过把复杂查询拆解为明确、可验证的推理步骤，并通过校验循环实现自我纠错——该循环能够捕获错误、分析失败并改进查询，直至其准确符合用户意图与 schema 要求——从而增强数据库分析。我们将演示这种现代方法如何在保持精确性与可靠性的同时，实现对复杂数据库系统的直观、类对话式交互。

为在最小代价下取得最佳表现，我们使用 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) 系列[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM）：[Amazon Nova Pro、Amazon Nova Lite 和 Amazon Nova Micro](https://docs.aws.amazon.com/nova/latest/userguide/what-is-nova.html)。这些 FM 编码了海量世界知识，有助于进行复杂数据分析所必需的细腻推理与上下文理解。我们的方案采用 ReAct（reasoning and acting，推理与行动）模式，通过 LangGraph 灵活的架构实现。这一做法把 Amazon Nova LLM 在自然语言理解方面的优势与显式的推理步骤和行动结合起来。

## 基于自然语言的数据库分析面临的挑战

许多正在经历[生成式 AI](https://aws.amazon.com/generative-ai/) 转型的客户都有一个共同认识：他们庞大的数据存储中蕴含着用于自动化分析与自然语言查询的未开发潜力。这一洞见促使他们探索基于 SQL 的方案，其中查询可以简单到 SELECT 与 WHERE 子句，也可以复杂到涉及精巧聚合与函数的多页语句。

归根结底，成功的分析取决于识别并取回正确的数据集。这一基础步骤支撑着所有下游活动，包括可视化、进一步分析与探索。把用户的意图——无论是明说还是隐含——转换为高性能、精确且合法的 SQL 查询，是一项重大挑战。

我们的方案擅长生成具备上下文与元数据感知能力的查询，能够取回精确的数据集并执行精细的分析。为充分释放 agent 与 Amazon Nova FM 的能力，友好的界面至关重要。我们开发了一个直观的界面，借助人在回路（HITL）能力引导用户走完分析旅程，允许在关键决策点提供输入、批准和修改。

## 解决方案概览

方案架构由三个核心部分组成：UI、生成式 AI 与数据。方案中的 agent 充当中央协调者，把问题理解、决策、工作流编排、智能路由以及生成完整的自然语言答复等关键能力结合起来。它通过改善文本质量、统一术语并维持对话上下文来增强问题，帮助用户以一系列相关查询延展分析，同时保留精确的分析意图。agent 的智能路由能力意味着每个用户问题都会调用正确的工具，从而实现连贯的端到端查询处理。此外，它还能处理表格与可视化数据，并利用完整上下文生成完整摘要，解释发现、突出关键洞见，并建议相关的后续问题。还有一项额外收益：agent 可以推荐相关的后续问题与相关主题，帮助用户更深入地探索数据，发现意料之外的洞见。以下工具接入了该 agent：

- **Text2SQL** —— 当编排器判定需要取回数据时，它会使用 Text2SQL 工具；该工具依托一个完整的知识库，其中包含元数据、表 schema、带结果的示例查询以及详细的数据字典。借助这些丰富的上下文，该工具把自然语言问题转换为精确的 SQL 查询。
- **SQLExecutor** —— 该工具直连结构化数据存储，执行 agent 借助 Text2SQL 工具生成的 SQL 查询。它针对结构化数据库端点（例如 [Amazon Athena](https://aws.amazon.com/athena/)、[Amazon Redshift](https://aws.amazon.com/redshift/) 或 Snowflake）执行生成的 SQL。
- **Text2Python** —— 当分析需要数据的可视化呈现时（无论是用户请求还是编排器决定），Text2Python 工具会把分析结果转换为有说服力的可视化。该 agent 同时处理用户的查询与 Text2SQL 工具取回的数据表，以生成合适的 Python 脚本。这些脚本使用业界标准的可视化库在本地执行，生成最能表现数据的示意图、图形或图表。与对应的 SQL 部分一样，该 agent 具备自我修复能力。当执行出错时，它利用错误反馈与上下文重新生成 Python 脚本，从而可靠地交付可视化。
- **PythonExecutor** —— PythonExecutor 接收生成的 Python 脚本并在本地执行。这样可以借助业界标准的库创建高质量的数据可视化。

随后 agent 评估返回的数据集是否完整回答了用户的问题。如果结果不足，它会自动重新生成并执行更精细的查询，以取回最优数据。一个关键特性是 agent 的自我修复能力。当执行出错时，agent 会利用这些错误与完整上下文重新生成修正后的 SQL 查询。这种自愈方式即使在复杂场景下也能提供稳健可靠的查询处理。agent 会处理这些输入——重写后的问题、分析结果与上下文——生成自然语言摘要并回应用户，其中包括带推理的表格结果、带解释的可视化，以及带关键洞见的摘要。

agent 通过对话维持上下文，这意味着用户只需提供很少的后续输入。它会自动利用先前上下文重建简略的问题，以便确认。此外，在每一轮问答之后，agent 都会给出相关的后续探索性问题，供进一步探索。agent 按行业标准、客户准则与品牌要求，推行一致的术语。它对输入和输出中的缩写都会做标准化，将其展开为完整形式。例如，无论是在用户输入还是 agent 回复中，"GDPR" 始终展开为 General Data Protection Regulation。agent 通过保持清晰、纠正语法、优化句式来提升文本质量。所有内容都会经过处理，以提供专业、易读的输出。该方案使用以下 AWS 服务与资源：

- [Amazon Athena](https://aws.amazon.com/athena/) —— Athena 用作存储和查询数据的结构化数据库
- [Amazon Bedrock](https://aws.amazon.com/bedrock/) —— 本方案的核心构建在 Amazon Bedrock 上，它支持生成式 AI agent 与 Amazon Nova 的集成
- [AWS Glue](https://aws.amazon.com/glue/) —— 我们使用 AWS Glue 准备数据集并将其加载到 Athena
- [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) —— 来自 Amazon 的前沿 FM 是关键组件，提供自然语言理解与生成能力
- [Amazon SageMaker](https://aws.amazon.com/sagemaker/) —— 我们使用 SageMaker 创建 notebook 实例来运行代码与实验

## 创建 SageMaker notebook 实例

按以下步骤创建 SageMaker notebook 实例：

- 在 SageMaker 控制台的导航窗格中选择 **Notebook instances**。
- 选择 **Create notebook instance**。
- 在 **Notebook instance name** 处输入名称（例如 `text2sql-nova-nb`）。
- 在 **Notebook Instance type** 处选择 **ml.t3.medium**。
- 在 notebook 上点击 "IAM role ARN"，并在 **Trust relationships** 标签页中添加 `sagemaker.amazonaws.com` 与 `glue.amazonaws.com`。

## 评估

我们在 Spider 文本到 SQL 数据集上评估了 Amazon Nova 的表现，该数据集是复杂跨领域语义解析与文本到 SQL 任务中被广泛使用的基准。评估为了解 Amazon Nova 相较其他前沿方法的能力提供了洞见。Spider 数据集包含 200 个数据库上、覆盖 138 个不同领域的 10,181 个问题和 5,693 条唯一的复杂 SQL 查询，这些数据库具有多张表。评估在零样本设置下进行，模型并未在该数据集的示例上做微调，以考察其通用的文本到 SQL 转换能力。我们使用以下评估指标：

- **执行准确率** —— 执行准确率指标衡量预测的 SQL 查询在数据库上执行时，是否与基准真值 SQL 查询产生相同结果。执行准确率提供了对模型表现的实用评估，因为它衡量了把自然语言问题转换为可执行 SQL 查询的端到端能力。表现最好的模型在 Spider 数据集上展现出很强的执行准确率，其中 Amazon Nova 模型的表现尤其有竞争力。与其他前沿模型相比，Amazon Nova 在各类查询复杂度上都取得相近或略高的准确率。对于最具挑战性的查询，Amazon Nova 优于其他领先模型，显示出其处理复杂自然语言到 SQL 转换的能力。
- **延迟** —— 除准确率外，文本到 SQL 转换的速度与响应性也是一项重要考量。在这方面，Amazon Nova 模型表现突出，与其他表现最好的模型相比，其处理时间显著更快。在一组有代表性的数据库查询上，Amazon Nova 生成 SQL 并取回结果的速度明显更快（延迟改善约 60%）。这一延迟改善可以转化为更好的用户体验与生产力，意味着业务用户能够更顺畅地使用自然语言接口与数据库交互。

总体而言，评估结果凸显了 Amazon Nova 在文本到 SQL 转换任务上兼具准确率与效率的优势。其有竞争力的表现、低延迟，以及在最复杂查询上的优势，使其成为希望借助自然语言接口普及数据访问与分析的组织的有力选项。
