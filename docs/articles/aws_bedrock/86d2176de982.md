*GPT-6 Sol 和 GPT-6 Luna 现已在 Amazon Bedrock 上正式可用（GA），为你提供更多选项，把智能与效率匹配到每个工作负载。*

规模化 AI 的价值取决于两个维度：模型能做什么，以及你能多频繁地把它投入使用。更强的智能扩展了模型可处理的复杂度——从微妙的编码问题到跨工具的多步流程。效率则决定这份智能能在多大范围内支撑日常活动和可重复任务——在那些场景里，每一个额外的 token、每一次重试、每一秒延迟都会随请求成倍累积。

[GPT-6 Astra](https://aws.amazon.com/blogs/machine-learning/take-on-your-most-ambitious-work-with-gpt-6-astra-on-amazon-bedrock/) 为最有雄心的项目确立了 GPT-6 家族的上限——在那里，取得最高质量的成果比成本更重要。组织也需要先进智能来处理那些让产品和运营持续运转的常规任务。GPT-6 Sol 把强推理和编码能力带到贯穿整周的复杂任务中，其经济性适合常规使用。GPT-6 Luna 让聚焦、可重复的任务在大批量下变得可行——在那些场景里，延迟和成本的微小差异会随请求成倍放大。

今天，来自 OpenAI 的 [GPT-6 Sol 和 GPT-6 Luna](https://aws.amazon.com/bedrock/openai/) 在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上正式可用，运行在一个为高性能、安全和大规模可靠性而构建的推理引擎上。两款模型的 API 定价都比它们的前代 GPT-5.6 显著更低，为你提供更多方式把 GPT-6 智能带入生产，并满足你的工作负载所需的性能、控制和灵活性。

## 每天解决更难的问题

GPT-6 Sol 为开发和运维中反复出现的苛刻任务而设计。它能实现功能、调试问题、重构和评审代码、分析数据，并跨工具和应用程序完成多步流程。相比 GPT-5.6 Sol，它在编码和计算机使用上的改进，帮助它把一项任务从调查贯穿到实现和验证，同时保留其决策背后的上下文。

随着 GPT-6 Sol 承担更多这一流程，开发者需要看清它改了什么、验证了什么、以及它无法确认什么。在一项内部的真实性（factuality）评测中，OpenAI 发现 GPT-6 Sol 的事实性错误大约只有 GPT-5.6 Sol 的一半。GPT-6 Sol 还受益于关于其工作和结果更清晰的沟通，帮助团队更早识别缺口，并理解哪里仍需人类判断。

更强的执行加上更清晰的报告，使 GPT-6 Sol 在整个开发周期中都很实用。那里的相关衡量标准是达成一个可用成果的总成本，包括输出质量、token 用量、重试和延迟。

## 让聚焦的智能在大批量下经济可行

当一项任务每天运行数千次时，每次调用的经济性决定了工作流能否扩展。单个分类或摘要本身并不贵，但整条文档流水线上提取、路由和后续跟进的成本会随每一个额外请求累积放大。

GPT-6 Luna 为那些批量重要的工作负载而设计。你可以用它从大型文档集合中提取信息、总结新到的材料、分类输入，并在大量用户或应用之间回答聚焦的问题。

大批量下的高效还需要一致的输出。OpenAI 的评测显示 GPT-6 Luna 在事实可靠性上有所改进，并能更清晰地传达结果。你还可以按请求调整推理强度（reasoning effort），以在每个任务所需的质量、响应速度和成本之间取得平衡。

## 把智能匹配到每一步而无需重建上下文

随着一个请求推进，单个应用可能需要不同层次的智能。你可以用 GPT-6 Luna 分类传入请求、用 GPT-6 Sol 调查复杂案例，并在额外的推理深度能实质改变一个决策时使用 GPT-6 Astra。这把智能集中在最能创造价值的地方，同时管理系统范围内的延迟和成本。

在每个阶段内，对同一模型的重复调用可能会复用指令、工具定义、策略和参考材料。重新处理那份上下文会侵蚀掉因选择合适模型而赢得的效率。

GPT-6 Sol 和 GPT-6 Luna 在 Amazon Bedrock 上支持显式的 prompt 缓存。你可以标记要复用的 prompt 内容，让后续请求把处理集中到新输入上。这对复用仓库指令的编码助手、以相同策略为接地的支持应用，以及应用一致提取架构（schema）的文档流程都很有用。

## 以性能与控制大规模运行 GPT-6

随着 AI 用量增长，模型质量只是决定应用能否在生产中成功的因素之一。团队还需要在需求变化时维持性能的基础设施、在重复请求中保持稳定成本的经济性，以及保护敏感数据的控制。Amazon Bedrock 通过一个为大规模安全与可靠性构建的高性能推理引擎，为 GPT-6 Sol 和 GPT-6 Luna 提供了这一基础。

你可以通过 AWS Identity and Access Management (IAM) 策略管理模型访问，并通过 AWS CloudTrail 审计每一次调用。由 AWS PrivateLink 驱动的专有网络（VPC）端点帮助把流量保持在你的网络边界内。推理运行在硬件隔离、零运维人员访问（zero-operator access）的基础设施上，因此即使是 AWS 运维人员在推理期间也无法访问你的 prompt 或补全。

你的推理数据不会被用于模型训练，使用 GPT-6 Sol 和 GPT-6 Luna 也不要求你选择加入与 OpenAI 共享你的数据。对于[自动滥用检测](https://docs.aws.amazon.com/bedrock/latest/userguide/abuse-detection.html)，被分类器标记的流量会由 AWS 保留最多 30 天并以编程方式处理。你可以通过你的 AWS 账户团队申请零数据保留。详情见[数据保留](https://docs.aws.amazon.com/bedrock/latest/userguide/data-retention.html#data-retention-zdr)。

## 开始上手

你可以在 [Amazon Bedrock 控制台](https://us-east-1.console.aws.amazon.com/bedrock/home?region=us-east-1#/)中开始使用 GPT-6 Sol 和 GPT-6 Luna，或通过受支持的 Amazon Bedrock API 以编程方式使用。有关受支持的 [AWS 区域](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html)、端点、API、特性、推理配置和定价的信息，参见 [Amazon Bedrock 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-openai.html)。
