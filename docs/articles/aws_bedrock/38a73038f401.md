# MoEngage 如何在 Amazon Bedrock AgentCore 上建立代理客户互动

*本文由 MoEngage 的 Ashwin Srinivasan、Nishan Das 和 Karthik Baile 共同撰写。*

计划周末闪购的营销或产品团队成员通常会在编写一行文案之前打开三个工具。首先，他们打开分析仪表板来查看上次的效果，然后打开内容库来找到正确的基调，然后打开活动构建器来构建活动本身。在电子邮件、推送、短信和 WhatsApp 中重复这一点，营销团队一周的大部分时间都花在使用工具而不是做出决策上。

MoEngage 模型上下文协议 (MCP) 连接器为兼容 MCP 的助手（例如 Claude 或 ChatGPT）提供了对品牌细分、活动历史记录和内容库的安全、租户范围的访问。

这种能力意味着软件平台将发生更广泛的转变。除了业务用户的用户界面和工程团队的 API 之外，第三层正在兴起，用户用简单的语言描述结果，代理在平台上执行步骤。对于客户互动平台来说，这意味着已经作为 API 公开的功能可以成为代理调用的工具，而曾经跨多个工具进行的活动现在可以通过一个对话进行。

MoEngage 是一个代理客户参与平台，超过 1,350 个消费品牌跨渠道使用，包括推送、电子邮件、应用内、短信、WhatsApp 和丰富通信服务 (RCS)，它着手构建这一层。 MoEngage 构建了 Merlin AI，这是一组处理实时平台数据的人工智能 (AI) 代理。营销和产品团队现在可以通过一次对话起草、分析和调整营销活动，而代理则决定向每个客户发送什么内容。一位客户 Glance 发现推送通知点击率因此提高了 38%。

MoEngage 将此视为架构问题。问题是如何让代理能够在租户范围内安全地访问实时数据，而无需重建数百个现有 API。在这篇文章中，我们将介绍 MoEngage 如何使用 Amazon Bedrock 和 Amazon Bedrock AgentCore 解决这个问题，这是一个使用任何框架或模型大规模构建、连接和优化 AI 代理的平台。这篇文章介绍了 Merlin AI 中的四种代理模式、MoEngage 如何将其现有 API 公开为 MCP 工具，以及该架构如何保持每个租户的数据隔离。最后介绍了 MoEngage 客户看到的结果以及其他软件提供商可以重复使用的模式。

## 解决方案概述：Merlin AI 中的四种代理模式

Merlin AI 运行四种代理。所有四个都共享相同的基础：Amazon Bedrock 中用于推理和生成的基础模型、AgentCore 运行时、用于托管的 Amazon Bedrock AgentCore 功能以及用于标准化数据访问的 MCP。在所有四种模式中，Merlin AI 在 Amazon Bedrock 上使用 Anthropic Claude Sonnet 4.6、Claude Sonnet 5 和 Claude Sonnet 5.5 进行推理、工具调用规划和内容生成。有关模型的完整列表，请参阅 [Amazon Bedrock 中支持的基础模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)。

### Merlin AI Studio 中的嵌入式代理

Merlin AI Studio 将专门构建的代理放置在工作流程中营销和产品团队执行该工作的确切位置：

- **文案**生成与品牌声音保持一致的个性化推送和交易副本。
- **设计师**根据文本描述制作营销横幅或图像。
- **细分辅助**将简单语言的受众描述转换为正确的属性和过滤器集。例如，营销或产品团队成员可以询问过去 2 小时内放弃购物车的用户。
- **Jinja Assist** 将自然语言请求转换为动态内容的工作 Jinja 和 Liquid 标记。
- **应用内模板生成器**为应用内消息创建响应灵敏、可访问的 HTML 模板，包括游戏化格式、潜在客户捕获弹出窗口和调查。
- **Flow Assist** 将高级创意转变为可立即部署的客户旅程。在幕后，一系列专门的步骤解释请求、建议路径、构建流结构、使用历史数据对其进行细化，并将其打包以进行部署。

### 会话代理

对话代理跨活动、分析、细分和流程工作。用户可以用简单的语言提出问题，代理会调用正确的工具来回答问题或采取行动。嵌入在分析页面上的营销活动洞察代理将委托给专门的子代理。一个子代理同时对多个指标进行分析。第二个诊断指标为何表现不佳，第三个指标比较不同时间段或段的绩效。最后一步将调查结果转化为明确的答案。

### 定制代理

自定义代理允许生命周期和客户关系管理 (CRM) 团队设计在 MoEngage 数据和工具上持续运行的代理，并遵循产品和营销团队定义的规则。每个代理通过其提取的数据、其做出的决策、其接触的渠道以及其发送的内容的活动日志来显示其工作。团队可以完全自主地运行代理，或者在执行任何操作之前需要人工审核。

### 决策者

决策代理为每个客户行事。每个代理决定说什么、何时、多久以及在哪个渠道上，并从每个结果中学习。产品和营销团队设定内容、目标和护栏，代理负责处理其余的事情，并且可以了解每个决策。报价决策选择网络和应用程序表面上的最佳报价。营销活动决策通过电子邮件、推送、短信和 WhatsApp 提供 1:1 决策。与工作流程代理一起，这将代理营销的两部分整合到一个系统中。

## 架构概述

该架构有四层。每一层都有单一的职责，并且可以在不影响其他层的情况下进行更改。

- **客户端。** MoEngage 产品内的 Merlin AI 代理以及外部 MCP 客户端（例如 Claude 和 ChatGPT）通过 MoEngage MCP 连接器连接到 MoEngage MCP 服务器。支持 MCP 的客户端可以连接。
- **AgentCore 运行时上的 MCP 服务器。** MoEngage 在 AgentCore 运行时上托管其 MCP 服务器。服务器将 MoEngage 平台功能公开为 MCP 工具。它不运行自己的模型。推理发生在调用它的代理中。
- **MoEngage 平台 API。** MCP 服务器调用 MoEngage 客户已使用的相同 OpenAPI 3.0 兼容 API。这些 API 强制执行现有权限和数据驻留规则。
- **Amazon Bedrock 中的基础模型。** 代理使用 Amazon Bedrock 中的基础模型来规划工具调用、生成内容并汇总结果。有关各区域的模型可用性，请参阅 [Amazon Bedrock 中 AWS 区域支持的模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。

在典型的请求中，用户登录 MoEngage 并提出问题。客户端使用用户现有的 JSON Web 令牌 (JWT) 发送请求。 AgentCore 运行时验证令牌并为该用户启动隔离会话。代理询问 Amazon Bedrock 中的模型要调用哪些工具。 MCP 服务器使用用户的租户上下文调用 MoEngage API 并返回结果。然后代理撰写答案。

### 将现有 API 转变为 MCP 工具

MoEngage 通过 MCP 服务器和代理可调用 API 向代理开放其平台。其用于活动、分析、细分、内容和流程的平台 API 已与 OpenAPI 3.0 兼容，因此 MoEngage 使用 FastMCP 框架根据这些规范生成 MCP 工具。每个操作都成为一个具有结构化模式、描述和参数验证的工具。

以下简化示例显示了该模式：
```
import httpx
from fastmcp import FastMCP

spec = httpx.get(MOENGAGE_OPENAPI_URL).json()
client = httpx.AsyncClient(base_url=MOENGAGE_API_BASE)
mcp = FastMCP.from_openapi(openapi_spec=spec, client=client, name='moengage')

if __name__ == '__main__':
    mcp.run(transport='streamable-http', host='0.0.0.0', port=8000)
```
这些工具分为五组：

- **营销活动工具**跨渠道创建、编辑、安排和发送营销活动。
- **分析工具**查询交付渠道、点击率、转化率和群组绩效。
- **细分工具**根据行为和属性过滤器列出、检查和创建细分。
- **内容工具**管理内容块、模板和动态内容规则。
- **流程工具** 检查、暂停或修改自动化旅程。

这些工具来自规范，因此它们与 API 保持同步。当团队更新规范时，工具定义也会随之更新。

### 保持租户隔离并使身份远离模型的影响范围

多租户系统不能让模型决定读取谁的数据。 MoEngage 做出了三种设计选择来帮助防止这种情况发生。首先，MCP 服务器重用现有的身份验证模型，接受 MoEngage API 已使用的基于 JWT 的身份验证，并且 AgentCore 运行时会在请求到达服务器之前验证每个令牌。其次，工作区和用户上下文在 AgentCore 运行时转发到服务器的请求标头中传输，而不是作为工具参数，因此模型看不到这些值，也无法更改它们。第三，AgentCore运行时在其自己的隔离环境中运行每个用户会话，因此一个用户的会话无法读取另一个用户的会话状态。

除此之外，Amazon Bedrock Guardrails 将内容安全和个人身份信息 (PII) 过滤器应用于代理响应。然后，前端后端层会在 MoEngage 界面渲染生成的内容之前验证其结构。

**让用户控制代理。**用户对每个代理可以执行的操作设置护栏，查看其活动日志中的每个操作，并在自主执行和人工审核执行之间进行选择。

### 为什么 MoEngage 选择 AgentCore 运行时

AgentCore 运行时提供多租户 MCP 服务器所需的生产功能，每一项功能都满足 MoEngage 工作负载的特定要求。 AgentCore 运行时会根据需求变化来扩展会话，因此 MoEngage 不会针对其客户工作区中的流量爆发来规划容量。默认情况下，每个会话都在自己的隔离环境中运行，这使一个品牌的对话和数据与另一个品牌的对话和数据分开。内置 JWT 授权方根据 MoEngage 的现有身份提供商验证令牌，因此 MCP 服务器使用与 API 相同的身份验证模型。

AgentCore 运行时托管也是与框架无关的。 MoEngage 可以在不接触 MCP 服务器的情况下更改模型或代理框架，这随着代理层的发展而变得很重要。通过 Amazon CloudWatch 内置的指标、日志和跟踪使 MoEngage 工程师能够了解每个会话。这些功能共同让团队能够专注于代理逻辑和营销情报，而不是托管基础设施。

通过 Amazon Bedrock 的推理为 MoEngage 带来了另外两个好处。 Merlin AI 代理在 Amazon Bedrock 上的 Anthropic Claude Sonnet 4.6、Claude Sonnet 5 和 Claude Sonnet 5.5 上运行，MoEngage 通过相同的 Amazon Bedrock API 在这些版本之间移动。 MoEngage 还按代币付费，而不是操作 GPU 基础设施。 Amazon Bedrock 不使用客户提示或响应来训练基础模型，这对于大规模处理客户参与数据的系统很重要。

## 一场活动，一场对话

以下示例显示用户如何在不离开对话的情况下构建营销活动。

- 索要草稿。用户类型：
  为我们的高价值细分市场起草周末闪购活动，使用与我们表现最佳的 12 月活动相同的基调。  代理调用分析工具来查找 12 月份最热门的营销活动，调用细分工具来确认高价值细分市场，调用内容工具来拉动品牌声音。它返回包含多个副本变体的草稿。
- 检查哪些方面表现不佳。用户询问：
  上个月哪些推送通知的点击率 (CTR) 低于 2%，它们有什么共同点？  营销活动洞察代理会比较这些营销活动并报告共享模式，例如发送时间或受众重叠。
- 调整行程。用户询问：
  显示入职流程第 3 步的下降情况，如果转化率低于 5%，则暂停 SMS 分支。  代理通过流程工具读取流程状态，并在用户确认后暂停分支。这就是实践中的人工审核模式。

每个步骤都使用为 MoEngage 界面提供支持的相同工具。用户不会打开单独的仪表板。

## 结果

基于该架构的 Merlin AI 代理已投入生产 6 个多月。 Glance 是一位客户，其活动上线速度提高了 50%，推送通知点击率提高了 38%。借助 Merlin AI Copywriter，Glance 团队还可以为每个营销活动制作约三倍多的内容变体。

MoEngage 报告称，在整个平台上，营销和产品团队在渠道、时间和频率决策方面的人工工作量减少了 60-70%，基于目标的决策的转化率提高了 20-30%。与自托管模型相比，Amazon Bedrock 中的托管按代币付费推理将 AI 基础设施成本降低了 50% 以上。

AgentCore 功能的可用性因 AWS 区域而异。有关受支持的区域，请参阅 [Amazon Bedrock AgentCore 文档](https://docs.aws.amazon.com/bedrock-agentcore/)。

## 结论

MoEngage 无需重建即可使其平台代理就绪。现有的 OpenAPI 规范成为 MCP 工具。 AgentCore 运行时提供托管、身份验证和会话隔离。 Amazon Bedrock 中的基础模型提供推理和生成。其结果是建立了一个平台，营销和产品团队在一次对话中从问题转向行动，MoEngage 工程师将时间花在营销情报而不是基础设施上，代理处理团队的工作流程和每个客户的决策，同时用户保持控制。

同样的模式也适用于其他拥有成熟 API 接口的软件提供商。从现有规范开始，将身份保留在模型之外，并让托管运行时处理生产问题。

要在同一基础上构建您自己的 MCP 服务器，请从 [Amazon Bedrock AgentCore 文档](https://docs.aws.amazon.com/bedrock-agentcore/) 开始，并按照 AgentCore 运行时指南来托管它。要为您的代理选择基础模型并查看安全性和数据处理控制，请参阅 [Amazon Bedrock 用户指南](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-bedrock.html)。要根据现有 OpenAPI 规范生成 MCP 工具，请查看 [FastMCP 文档](https://gofastmcp.com/)。要查看 Merlin AI 的实际应用，请访问 [MoEngage Merlin AI](https://www.moengage.com/merlin-ai/)。要规划类似的架构，请联系您的 AWS 客户团队或解决方案架构师。
