# NVIDIA Nemotron 3.5 Super VL is now available in Amazon SageMaker JumpStart

Today, we’re announcing that NVIDIA Nemotron 3.5 Super VL is available in Amazon SageMaker JumpStart. You can deploy it with a few steps in SageMaker Studio or with a few lines of the SageMaker Python SDK. Super VL is the vision-language model (VLM) in the NVIDIA Nemotron 3.5 family. It accepts images, video, and text as input and generates text.

The model pairs a 120B-parameter hybrid Mixture-of-Experts (MoE) language backbone with 12B active parameters and a C-RADIO vision encoder. It supports context lengths of up to 1 million tokens and includes a built-in Multi-Token Prediction (MTP) head that supports speculative decoding. You can configure reasoning per request.

NVIDIA built Super VL for document intelligence, GUI understanding for computer-use agents, video question answering, and multimodal agentic applications. JumpStart offers two variants: NVFP4, quantized from BF16 with quantization-aware distillation for optimized inference, and the BF16 full-precision reference weights. In this post, we walk through the model’s capabilities and the JumpStart deployment configurations. We then show the measured inference performance and demonstrate text, image, and video inference.

## Model overview

Nemotron 3.5 Super VL is a 120B-parameter model with 12B active parameters per token. It combines a hybrid language backbone with a dedicated vision encoder.

- **Language backbone**: 88 layers that interleave Mamba-2 and MoE layers (512 routed experts, 22 active per token) with 8 attention layers, plus a shared MTP head. The backbone is initialized from Nemotron 3 Super Base and distilled from Nemotron 3 Ultra Base.
- **Vision encoder**: A C-RADIO vision encoder encodes images and sampled video frames, and a vision-language connector maps them into the language backbone’s embedding space. The encoder and connector stay in BF16 in both variants.
- **Training**: The model first goes through continued pre-training, long-context and software-engineering mid-training, and vision-language training. It then goes through two-stage multimodal supervised fine-tuning (SFT) on vision, reasoning, code, tool, chat, safety, and long-context data. Next come reinforcement learning (RL) with verifiable rewards and human feedback in NeMo RL and NeMo Gym, multi-teacher on-policy distillation, and a final stage that further trains the MTP head. The NVFP4 checkpoint is produced from BF16 with NVIDIA Model Optimizer and quantization-aware distillation. It keeps the vision encoder, connector, Mamba convolutions, and embeddings in BF16 and the MoE router in FP32. It runs with 4-bit weights and activations (W4A4) on Blackwell GPUs.

The following table compares the specifications of the two variants available in JumpStart.

| **Specification** | **NVFP4** | **BF16** |
| --- | --- | --- |
| Parameters | 120B total, 12B active | 120B total, 12B active |
| Intended for | Optimized inference (latency and throughput) | Full-precision reference weights for customization: SFT, RL, distillation, domain adaptation, and custom quantization |
| Inputs / output | Image, video, text / text | Image, video, text / text |
| Context length | Up to 1M tokens (JumpStart serving configurations use 520 to 15,600 tokens) | Same |
| Checkpoint size | About 75 GB | About 249 GB |
| JumpStart instances | ml.g7.24xlarge (default), ml.g7.48xlarge | ml.p5en.48xlarge |
| Speculative decoding | Built-in MTP head. Not enabled in the JumpStart serving configuration | Same |
| LoRA adapter serving | No | No |
| Languages | English, French, German, Italian, Japanese, Spanish, Chinese | Same |
| Reasoning | On by default. Configurable with `enable_thinking` | Same |
| Outputs | Tool calling, JSON schema output, configurable reasoning | Same |
| License | [OpenMDW License Agreement, version 1.1](https://openmdw.ai/license/1-1/) | Same |

## Key use cases

Super VL is aimed at agentic workloads that must see and read. It targets vision-language agents that combine reasoning, coding, tool use, document understanding, and video understanding.

- **Document intelligence**: Optical character recognition (OCR), charts, tables, and multipage documents. Each 1,536 x 1,024 page image costs about 1,536 tokens of context. The JumpStart serving configuration accepts one image and one video per request.
- **GUI understanding**: Screen grounding and reasoning for computer-use agents that navigate applications.
- **Video understanding**: Analyze and summarize short MP4 video clips, including answering questions about visual content. You can provide videos inline as base64-encoded content, subject to the endpoint’s request payload size limits.
- **Multimodal agents**: Tool calling, JSON schema output through `response_format`, and configurable reasoning support multimodal agent workflows.
- **Customization (BF16)**: Download the BF16 reference weights for SFT, RL, distillation, domain adaptation, or creating your own quantized variants. The JumpStart endpoint serves the base weights only and does not load LoRA adapters.

## Model-quality benchmarks

The NVIDIA model cards report results for both checkpoints across reasoning, coding, agentic, long-context, and multimodal benchmarks, with evaluation settings held constant so that only the checkpoint differs. The following table highlights the multimodal benchmarks most relevant to vision-language workloads (reasoning on).

| **Benchmark** | **Capability** | **BF16** | **NVFP4** |
| --- | --- | --- | --- |
| MMLongBench-Doc | Long-document multimodal understanding | 62.82 | 62.82 |
| OCRBench v2, EN | OCR and document understanding | 68.12 | 68.34 |
| CharXiv reasoning | Chart and figure reasoning | 80.82 | 79.88 |
| Video-MME v2 | Video understanding | 32.85 | 32.54 |
| OSWorld-Verified | Visual computer use and agentic tasks | 51.14 | 52.30 |

NVFP4, the JumpStart default, matches BF16 on MMLongBench-Doc and stays within about one point on the others, scoring slightly higher on OCRBench v2 and OSWorld-Verified. For the full comparison against other publicly available models and the evaluation settings, see the [NVIDIA Nemotron 3.5 Super VL and Lightning Technical Report](https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3.5-Super-and-Lightning-Technical-Report.pdf).

## Inference performance on SageMaker JumpStart

We measured inference performance with the JumpStart release container using the generate workload profile: 250 input tokens, 1,500 output tokens, and five concurrent streaming requests. Throughput is the mean output tokens per second for each request, and time to first token is the mean across requests.

| **Instance type** | **Variant** | **Output throughput per request (mean)** | **Time to first token (mean)** |
| --- | --- | --- | --- |
| ml.g7.24xlarge | NVFP4 | 63.07 tokens/sec | 0.45 sec |
| ml.g7.48xlarge | NVFP4 | 64.01 tokens/sec | 0.51 sec |
| ml.p5en.48xlarge | BF16 | 140.85 tokens/sec | 0.53 sec |

These results illustrate the deployment choices available through JumpStart. The NVFP4 variant runs on G7 instances with a smaller GPU footprint. The BF16 variant on ml.p5en.48xlarge achieved 140.85 output tokens per second per request in this test. Time to first token remained about half a second across all three configurations. Because the variants run on different GPU systems and configurations, these measurements are not an isolated `BF16-versus-NVFP4` precision comparison. Longer prompts change the picture: with the summarize profile (10,000 input tokens), time to first token on ml.g7.24xlarge is 12.62 seconds.

## Supported instances

SageMaker JumpStart supports Nemotron 3.5 Super VL on the following validated instance types. NVFP4 runs on G7 instances with NVIDIA RTX PRO 4500 Blackwell Server Edition GPUs, and BF16 runs on P5en instances with NVIDIA H200 GPUs. The JumpStart default instance for NVFP4 is ml.g7.24xlarge, which serves as the recommended starting point for the generate profile.

| **Variant** | **Instance type** | **GPUs** | **GPU memory** | **Tensor parallel** |
| --- | --- | --- | --- | --- |

## Deploy Nemotron 3.5 Super VL with SageMaker JumpStart

You can deploy the model from SageMaker Studio, with the SageMaker Python SDK, or from the Hugging Face model page.

### Prerequisites

Before you deploy, make sure you have the following:

- An AWS account with permissions to create Amazon SageMaker AI endpoints.
- An AWS Identity and Access Management (IAM) role with access to SageMaker AI.
- Service quota for ml.g7.24xlarge, ml.g7.48xlarge, or ml.p5en.48xlarge endpoint usage. The ml.g7 quotas start at zero in new accounts, so request an increase through Service Quotas before you deploy.
- For the SDK path, the SageMaker Python SDK v3 (version 3.25 or later).

### Deploy with the SageMaker Python SDK

```
# Install the SageMaker Python SDK v3: pip install "sagemaker>=3.25"
from sagemaker.core.helper.session_helper import get_execution_role
from sagemaker.core.jumpstart.configs import JumpStartConfig
from sagemaker.core.training.configs import Compute
from sagemaker.serve import ModelBuilder

# BF16 variant: model_id "huggingface-vlm-nvidia-nemotron-3-5-super-vl-120b-a12b-bf16" on ml.p5en.48xlarge.
jumpstart_config = JumpStartConfig(
    model_id="huggingface-vlm-nvidia-nemotron-3-5-super-vl-120b-a12b-nvfp4",
    inference_config_name="modify_best_price_performance",
)
model_builder = ModelBuilder.from_jumpstart_config(
    jumpstart_config=jumpstart_config,
    role_arn=get_execution_role(),
    compute=Compute(instance_type="ml.g7.24xlarge", instance_count=1),
)
model_builder.build()
endpoint = model_builder.deploy(endpoint_name="nemotron-3-5-super-vl")
```

The example uses the SageMaker Python SDK v3 classes: `JumpStartConfig` names the model, `ModelBuilder` builds and deploys it, and `deploy` returns an `Endpoint` resource. Pass the instance type in `Compute`, because the SDK falls back to ml.m5.large when the instance type is absent, and the build then fails. The deploy call waits until the endpoint is InService, which takes about 10 minutes on ml.g7.24xlarge.

The `inference_config_name` argument selects a serving configuration, and each configuration sets a different context length. The default generate configurations serve a 2,275-token context sized for short prompts. The summarize configurations serve 13,650 tokens, and the modify configurations serve 15,600 tokens. The example uses a modify configuration because the inference examples in this post, especially image, video, and reasoning requests, need the larger context. All the inference examples that follow assume the modify configuration.

## Run inference

The JumpStart endpoint exposes a vLLM-powered chat completions API, so applications can send inference requests using a familiar chat-message format. NVIDIA recommends temperature 1.0 and `top_p` 0.95 for text, and temperature 0.6 and `top_p` 0.95 for image and video requests. You must send media inline as base64 data URLs because the endpoint runs with network isolation and cannot fetch URLs.

### Text, with reasoning on

Reasoning is on by default, and you can configure it per request. The reasoning text is returned in the reasoning field of the message, separate from content.

```
import json

payload = {
    "messages": [{"role": "user", "content":
        "Explain the difference between OCR and document understanding."}],
    "max_tokens": 2000,
    "temperature": 1.0,
    "top_p": 0.95,
}
response = endpoint.invoke(
    body=json.dumps(payload), content_type="application/json", accept="application/json"
)
result = json.loads(response.body.read())
print(result["choices"][0]["message"]["reasoning"])
print(result["choices"][0]["message"]["content"])
```

### Image, with reasoning off

For direct extraction-style tasks, you can disable reasoning with `enable_thinking=False` in `chat_template_kwargs`.

```
import base64

with open("invoice.png", "rb") as f:
    image_b64 = base64.b64encode(f.read()).decode("utf-8")

payload = {
    "messages": [{
        "role": "user",
        "content": [
            {"type": "image_url",
             "image_url": {"url": f"data:image/png;base64,{image_b64}"}},
            {"type": "text",
             "text": "Extract the vendor, date, and total as JSON."},
        ],
    }],
    "max_tokens": 1024,
    "temperature": 0.6,
    "top_p": 0.95,
    "chat_template_kwargs": {"enable_thinking": False},
}
response = endpoint.invoke(
    body=json.dumps(payload), content_type="application/json", accept="application/json"
)
result = json.loads(response.body.read())
print(result["choices"][0]["message"]["content"])
```

The model accepts images rather than raw PDF files. To process a PDF, render each page to an image such as PNG before sending it to the model. A 1,536 x 1,024 page costs about 1,536 tokens of context, and one request can carry one image.

### Video

The following example sends a short MP4 clip as a base64-encoded data URL and asks the model to summarize it, with reasoning disabled for a direct response.

```
import base64

with open("demo.mp4", "rb") as f:
    video_b64 = base64.b64encode(f.read()).decode("utf-8")

payload = {
    "messages": [{
        "role": "user",
        "content": [
            {"type": "video_url",
             "video_url": {"url": f"data:video/mp4;base64,{video_b64}"}},
            {"type": "text", "text": "Summarize what happens in this video."},
        ],
    }],
    "max_tokens": 2000,
    "temperature": 0.6,
    "top_p": 0.95,
    "chat_template_kwargs": {"enable_thinking": False},
}
response = endpoint.invoke(
    body=json.dumps(payload), content_type="application/json", accept="application/json"
)
result = json.loads(response.body.read())
print(result["choices"][0]["message"]["content"])
```

For video inference, use short, compressed clips and keep the encoded request within the endpoint’s supported payload limits. For reasoning-intensive video requests, set `max_tokens` high enough to allow the model to complete its reasoning while considering response length and endpoint invocation limits.

## Best practices

Consider the following recommendations when you run Nemotron 3.5 Super VL on SageMaker JumpStart:

- **Media inputs**: The model accepts images rather than raw PDF files, so render PDF pages to images first.
- **Video configuration**: Frame sampling is set when the endpoint launches, not per request. The JumpStart endpoint uses the vLLM default sampling and rejects per-request `media_io_kwargs`.
- **Video with reasoning**: Set `max_tokens` to at least 8,192 for video with reasoning enabled, or disable reasoning when you want a direct response.
- **Context budget**: `max_tokens` caps the completion. Prompt and completion together must fit in the serving configuration’s model length: 2,275 tokens for the generate configurations, 520 for interact, 13,650 for summarize, and 15,600 for modify. Images and video frames also consume context.
- **Multipage documents**: The JumpStart serving configuration accepts one image per request. Send one page per request, or stitch pages into one image, and check the context budget.
- **Reasoning mode**: Use reasoning for multi-step analysis and agentic tasks. Disable it for extraction or captioning when you want a shorter, direct response.
- **Sampling**: Start with temperature 1.0 and `top_p` 0.95 for text, and temperature 0.6 and `top_p` 0.95 for image and video, as NVIDIA recommends.

## Clean up

To avoid ongoing charges, delete the endpoint, the endpoint configuration, and the model when you are done:

```
from sagemaker.core.resources import EndpointConfig, Model

endpoint_config = EndpointConfig.get(endpoint_config_name=endpoint.endpoint_config_name)
model_name = endpoint_config.production_variants[0].model_name
endpoint.delete()
endpoint_config.delete()
Model.get(model_name=model_name).delete()
```
