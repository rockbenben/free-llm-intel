# 推出 Amazon Bedrock AgentCore Gateway：重塑企业 AI agent 工具开发

为完成任务，AI agent 需要访问各种能力，包括工具、数据存储、提示模板和其他 agent。随着组织扩大其 AI 计划，他们面临一个呈指数级增长的挑战：把每个 agent 连接到多个工具，从而形成 M×N 的集成问题，这显著拖慢开发并增加复杂度。

尽管 [Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro)（MCP）和 Agent2Agent（A2A）等协议已经出现以解决互操作性问题，但实现这些方案仍需大量工程投入。组织必须构建 MCP 服务器、转换现有 API、管理基础设施、构建智能工具发现能力并实施安全控制，同时还要在协议快速演进、新的大版本不断发布的背景下长期维护这些集成。当部署规模增长到数百个 agent 和数千个工具时，企业需要一个更具可扩展性、更易管理的解决方案。

## 推出 Amazon Bedrock AgentCore Gateway

我们很高兴宣布推出 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) Gateway，这是一项全托管服务，彻底改变了企业将 AI agent 与工具及服务连接的方式。[AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 充当集中式工具服务器，提供一个统一接口，让 agent 能够发现、访问并调用工具。

Gateway 原生支持 MCP，实现 agent 到工具的无缝通信，同时把安全、基础设施与协议层面的复杂性抽象掉。该服务可从 API 和 [AWS Lambda](https://aws.amazon.com/lambda/) 函数零代码创建 MCP 工具，提供智能工具发现、内置的入站与出站授权，以及面向 MCP 服务器的无服务器基础设施。你可以专注于打造智能化的 agent 体验，而不必管理工具与服务的连接性。下图展示了 AgentCore Gateway 的工作流。

### Amazon Bedrock AgentCore Gateway 的关键能力

Amazon Bedrock AgentCore Gateway 引入了一整套全面的能力，旨在彻底改变 AI agent 的工具集成方式。在核心层面，Gateway 提供强大且安全的 API 集成功能，可将现有的 REST API 转化为 MCP 服务器。这一集成同时支持 OpenAPI 规范和 Smithy 模型，因此组织可以无缝地把企业 API 转换为兼容 MCP 的工具。除 API 集成之外，Gateway 还内置对 Lambda 函数的支持，使开发者能够把其无服务器计算资源作为具有既定 schema 的工具接入。Gateway 提供以下关键能力：

- **安全守卫（Security Guard）**——管理 OAuth 授权，确保只有合法的用户和 agent 才能访问工具与资源。我们将在下一节进一步深入探讨安全性。
- **转换（Translation）**——把使用 MCP 等协议的 agent 请求转换为 API 请求和 Lambda 调用，免去管理协议集成或版本支持的需要。
- **组合（Composition）**——将多个 API、函数和工具组合为单一 MCP 端点，简化 agent 的访问。
- **目标可扩展性（Target extensibility）**——AgentCore gateway 是一个集中式访问点，作为统一接口供 AI agent 发现工具并与之交互。它负责身份验证、请求路由，以及 MCP 与你的 API 之间的协议转换。每个 gateway 可以管理多个目标。目标代表你希望作为工具暴露给 AI agent 的后端服务或一组 API。目标可以是 AWS Lambda 函数、OpenAPI 规范或 Smithy 模型。每个目标可以暴露多个工具，Gateway 会自动处理 MCP 与目标内置协议之间的转换。Gateway 支持 streamable http 传输。
- **基础设施管理器（Infrastructure Manager）**——作为全托管服务，Gateway 为组织免除了基础设施管理的负担。它提供具备内置安全特性和强大可观测性能力的完备基础设施。团队不再需要担心托管问题、扩展问题或维护底层基础设施。该服务会自动处理这些方面，随着需求增长提供可靠的性能与无缝的扩展。
- **语义工具选择（Semantic Tool Selection）**——智能工具发现是 Gateway 的另一项核心能力。当组织扩展到数百或数千个工具时，为 AI agent 找到正确的工具变得越来越困难。此外，当 agent 同时面对过多工具时，会出现所谓的“工具过载”，导致幻觉、错误的工具选择或低效的执行路径，显著影响表现。Gateway 通过提供一个名为 `'x_amz_bedrock_agentcore_search'` 的特殊内置工具来应对这些挑战，该工具可以使用标准的 MCP tools 和 call 操作来访问。

## 安全与身份验证

Gateway 实现了精巧的双侧安全架构，既处理对 Gateway 自身的入站访问，也处理到目标服务的出站连接。

对于入站请求，Gateway 遵循 MCP [授权规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)，使用基于 OAuth 的授权来验证并授权传入的工具调用。Gateway 充当 OAuth 资源服务器。这意味着它可以与你所在组织可能使用的 OAuth 身份提供商配合工作——无论是 [Amazon Cognito](https://aws.amazon.com/cognito/)、Okta、Auth0，还是你自己的 OAuth 提供商。创建 gateway 时，你可以指定多个已获批的客户端 ID 和受众，从而精细控制哪些应用和 agent 可以访问你的工具。Gateway 会依据你的 OAuth 提供商验证传入请求，同时支持授权码流程（3LO）和客户端凭证流程（2LO，常用于服务到服务通信）。

出站安全模型同样灵活，但会因目标类型而异：

对于 AWS Lambda 和 Smithy 模型目标，AgentCore Gateway 使用基于 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）的授权。gateway 会代入你配置的 IAM 角色，该角色可以为每个目标服务设定精确限定的权限。这与现有的 AWS 安全实践和 IAM 策略能够平滑集成。

对于 OpenAPI 目标（REST API），Gateway 支持两种身份验证方式：

- **API key**——你可以配置将密钥放在请求头或查询参数中发送，参数名称可自定义
- **用于 2LO 的 OAuth token**——对于到目标 API 的出站 OAuth 身份验证，Gateway 支持两方 OAuth（2LO）客户端凭证授予类型，可在无需用户交互的情况下实现安全的机器到机器通信

凭证通过 AgentCore Identity 的资源凭证提供商进行安全管理。每个目标都精确关联一个身份验证配置，有助于形成清晰的安全边界和审计线索。AgentCore Identity 处理复杂的安全机制，同时向开发者呈现干净、简单的接口。你在设置时一次性配置好安全，之后 Gateway 会负责 token 验证、出站 token 缓存（通过 AgentCore Identity）以及安全通信。

## 开始使用 Amazon Bedrock AgentCore Gateway

你可以通过多种界面创建 gateway 并添加目标：

- [AWS SDK for Python (Boto3)](https://aws.amazon.com/sdk-for-python/)
- [AWS Management Console](https://aws.amazon.com/console/)
- [AWS Command Line Interface](https://aws.amazon.com/cli/) (AWS CLI)
- [用于快速、直接完成设置的 AgentCore starter toolkit](https://github.com/aws/bedrock-agentcore-starter-toolkit/tree/main/src/bedrock_agentcore_starter_toolkit/operations/gateway)

以下实用示例和代码片段演示了设置并使用 Amazon Bedrock AgentCore Gateway 的过程。

### 创建 gateway

要创建 gateway，请使用 AWS Boto3 通过 [Amazon Cognito](https://aws.amazon.com/cognito/) 进行入站身份验证：

```
gateway_client = boto3.client('bedrock-agentcore-control')
auth_config = {
    "customJWTAuthorizer": { 
        "allowedClients": '<cognito_client_id>‘, # Client MUST match with the ClientId configured in Cognito.
        "discoveryUrl": '<cognito_oauth_discovery_url>'
    }
}
create_response = gateway_client.create_gateway(name='DemoGateway',
    roleArn = '<IAM Role>' # The IAM Role must have permissions to create/list/get/delete Gateway 
    protocolType='MCP',
    authorizerType='CUSTOM_JWT',
    authorizerConfiguration=auth_config, 
    description='Demo AgentCore Gateway'
)
# Values with < > needs to be replaced with real values
```

以下是 Amazon Bedrock AgentCore 的[控制平面](https://docs.aws.amazon.com/bedrock-agentcore-control/latest/APIReference/Welcome.html)和[数据平面](https://docs.aws.amazon.com/Bedrock-AgentCore/latest/APIReference/Welcome.html) API 参考。

### 实现语义搜索

你可以在创建 gateway 时选择启用语义搜索。它会自动预置一个名为 `x_amz_bedrock_agentcore_search` 的强大内置工具，可通过自然语言查询实现智能工具发现。请使用搜索工具的输出替代 MCP 的 list 操作，以获得可扩展且高性能的工具发现。下图展示了如何使用 MCP 的搜索工具。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/14/ML-19425-image-3.jpeg)

要启用语义搜索，请使用以下代码：

```
 # Enable semantic search of tools
    search_config = {
        "mcp": {"searchType": "SEMANTIC", "supportedVersions": ["2025-03-26"]}
    }
    # Create the gateway
    response = agentcore_client.create_gateway(
        name=gateway_name,
        roleArn=gateway_role_arn,
        authorizerType="CUSTOM_JWT",
        description=gateway_desc,
        protocolType="MCP",
        authorizerConfiguration=auth_config,
        protocolConfiguration=search_config,
    )
def tool_search(gateway_endpoint, jwt_token, query):
    toolParams = {
        "name": "x_amz_bedrock_agentcore_search",
        "arguments": {"query": query},
    }
    toolResp = invoke_gateway_tool(
        gateway_endpoint=gateway_endpoint, jwt_token=jwt_token, tool_params=toolParams
    )
    tools = toolResp["result"]["structuredContent"]["tools"]
    return tools
```

## 通过监控与可观测性评估 Gateway 表现

Amazon Bedrock AgentCore Gateway 通过与 [Amazon CloudWatch](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-advanced-observability-metrics.html) 和 [AWS CloudTrail](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-cloudtrail.html) 的集成提供可观测性，用于对你的工具集成进行详细监控与问题排查。可观测性功能通过详细指标从多个维度覆盖 gateway 操作：[使用指标](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-advanced-observability-metrics.html#gateway-metrics-usage)（`TargetType`、`IngressAuthType`、`EgressAuthType`、`RequestsPerSession`）、[调用指标](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-advanced-observability-metrics.html#gateway-metrics-invocation)（`Invocations`、`ConcurrentExecutions`、`Sessions`）、[性能指标](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-advanced-observability-metrics.html#gateway-metrics-invocation)（`Latency`、`Duration`、`TargetExecutionTime`）以及错误率（`Throttles`、`SystemErrors`、`UserErrors`）。性能指标可以使用多种统计方法（Average、Minimum、Maximum、p50、p90、p99）进行分析，并带有相关维度标签以便细粒度分析，包括 Operation、Resource 和 Name。在运营日志方面，Gateway 与 CloudTrail 集成，可捕获管理事件和[数据事件](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/understanding-gateway-cloudtrail-log-entries.html)，提供 API 交互的完整审计线索。这些指标可在 Amazon Bedrock AgentCore 控制台和 CloudWatch 控制台中查看，你可以在其中创建自定义仪表板、设置自动化[告警](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-advanced-observability-metrics.html#gateway-advanced-observability-alarms)，并执行详细的性能分析。

## 最佳实践

Gateway 通过 `exceptionLevel` 属性提供增强的调试选项，可在创建 Gateway 时启用，或按下述代码示例进行更新：

```
create_response = gateway_client.create_gateway(name='DemoGateway',
    roleArn = '<IAM Role>' # The IAM Role must have permissions to create/list/get/delete Gateway 
    protocolType='MCP',
    authorizerType='CUSTOM_JWT',
    authorizerConfiguration=auth_config, 
    description='Demo AgentCore Gateway',
    exceptionLevel="DEBUG"   # Debug mode for granular error messages
)
```

启用后，该功能会在 Gateway 测试期间在内容文本块（带有 `isError:true`）中提供更细粒度的错误信息，便于更快地排查问题与完成集成。在为 Gateway 编写文档和提取 Open API 时，请聚焦于清晰、用自然语言表述的描述，说明真实世界的用例。为复杂数据结构包含详细的字段说明、验证规则和示例，同时在全文中保持术语一致。为实现最佳的工具发现效果，请在描述中自然地融入相关业务领域关键词，并提供关于何时使用每个 API 的上下文。最后，测试语义搜索的有效性，确保工具可以通过自然语言查询被发现。定期审查和更新对于在 API 演进过程中维持文档质量至关重要。从较大的规范中提取 API 时，要识别 agent 任务所需的核心功能，保持各组件之间的语义关系，并保留安全定义。遵循系统化的提取流程：审阅完整规范，把 agent 用例映射到具体端点，在保持依赖关系的同时提取相关路径和 schema，并验证提取出的规范。以下是将 API 分组到 Gateway 目标的最佳实践：

- 从用例出发，参照适用于微服务范式的领域驱动设计原则，按 agentic 应用的业务领域对 MCP 工具进行分组。
- 一个 Gateway 目标只能附加一个用于出站授权的资源凭证提供商。请根据出站授权器对工具进行分组。
- 根据 API 的类型（即 OpenAPI、Smithy 或 AWS Lambda）对 API 进行分组，作为通往其他企业 API 的桥梁。

在把工具接入 Gateway 时，组织应遵循包含安全检查与漏洞检查的结构化流程。实施一条审查流水线，扫描 API 规范中的潜在安全风险，维护恰当的身份验证机制，并验证数据处理实践。对于运行时工具发现，可使用 Gateway 中的语义搜索能力，但也要为关键工作流考虑设计时的 agent 与工具映射，以提供可预期的行为。

用详细的描述、用法示例和性能特征丰富工具元数据，以提升可发现性，并帮助 agent 做出恰当的工具选择。为在企业范围内保持一致，请将 Gateway 与作为唯一真实来源的集中式工具注册表集成。这可以通过 [MCP Registry Publisher Tool](https://github.com/modelcontextprotocol/registry/tree/main/tools/publisher) 等开源方案实现，该工具会把 MCP 服务器的详细信息发布到 MCP 注册表。定期将 Gateway 的工具清单与该中央注册表同步，以确保你的 AI 版图中的工具可用性保持最新且一致。这些实践有助于在 Gateway 内维持一个安全、组织良好且易于高效发现的工具方案，促进无缝的 agent 与工具交互，同时符合企业治理标准。

## 结论

Amazon Bedrock AgentCore Gateway 代表了企业 AI agent 开发的一次重大进步。通过为工具集成提供全托管、安全且可扩展的解决方案，Gateway 让组织能够在保持企业级安全与治理的同时加速其 AI 计划。作为更广泛的 Amazon Bedrock AgentCore 套件的一部分，Gateway 可与 Runtime、Identity、Code Interpreter、Memory、Browser 和 Observability 等其他能力无缝协作，为构建并扩展 AI agent 应用提供完整的领域。
