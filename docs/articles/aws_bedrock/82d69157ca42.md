xAI 的 Grok 4.7 现已在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上可用，为 Bedrock 模型目录增加了一个为编码、长时间运行的智能体和知识工作而打造的前沿模型。它提供 50 万 token 的上下文窗口，并支持四个级别的、可配置的推理强度：`low`、`medium`、`high` 和 `xhigh`。

Grok 4.7 通过跨区域推理配置在 `bedrock-runtime` 端点上服务，并支持 Responses、Chat Completions 和 Converse API。据 xAI 称，这是其最强大的编码和知识工作模型：它在困难任务上工作更久，并在继续之前更仔细地验证自身输出。

本文涵盖 xAI 所说 Grok 4.7 为何而设计、它在 Amazon Bedrock 上如何打包，以及如何发送你的第一个请求。

## Grok 4.7 为何而生

本节的能力和训练细节来自 xAI 于 2026 年 9 月 21 日发布的上线公告 [Introducing Grok 4.7](https://x.ai/news/grok-4-7) 和 [Grok 4.7 模型文档](https://docs.x.ai/developers/models/grok-4.7)。

xAI 把 Grok 4.7 定位为它最强大的编码和知识工作模型。其主题是耐力而非原始速度：模型在困难任务上工作更久，并在继续之前更仔细地检查自身工作。

关于训练，xAI 报告 Grok 4.7 使用了一个新的、更大的基础模型。它是在一批更困难的任务组合上、经过一次更长的强化学习训练得到的，并有意识地偏向那些需要数小时才能完成的问题。这带来两项能力：模型更善于验证自身工作，并在长任务上更有效地利用其 50 万 token 上下文窗口。xAI 还训练它原生理解 Grok Bot harness，并将其在对话任务和一般知识工作上的改进归功于此。

对任何构建智能体的人而言，自我验证行为是值得一留意的细节。一个在继续之前检查自身输出的模型，在长轨迹上往往不会那么灾难性地失败——否则一个早期错误会通过每一个后续步骤不断累积。

xAI 还强调了更强的文档和演示生成，并描述了在律师、护士和金融分析师所做的那类专业知识工作上的提升。xAI 报告在其公布的各项评测上都有收获。这些涵盖用 CursorBench 和 DeepSWE 做的软件工程、用 Terminal-Bench 和 AA Briefcase 做的数小时终端与办公工作、用 EEBench 做的电气工程、用 Harvey Legal Agent Benchmark 做的法律工作，以及用 HealthBench Professional 做的临床推理。要看结果本身，参见 xAI 的[公告](https://x.ai/news/grok-4.7)。

### 独立评测

Artificial Analysis 运行自己的评测而非依赖开发者自报的数字，这使它成为 xAI 公布结果之外一个有用的第二参照。

据 [Artificial Analysis](https://artificialanalysis.ai/articles/benchmarking-grok-4-7)，Grok 4.7 在其评测套件上有所改进。最大的收益在长时程智能体式知识工作，以及在 xAI 自己的 harness 中运行的编码智能体上。Intelligence Index 是一个由多项独立评测构成的综合指数，涵盖智能体工具使用、推理与知识、知识可靠性以及长上下文工作。

| **指标（Artificial Analysis）** | **Grok 4.7** | **Grok 4.6** |
| --- | --- | --- |
| Intelligence Index | 46 | 44 |
| Coding Agent Index | 56 | 47 |
| AA-Briefcase，长时程知识工作（Elo） | 1,657 | 1,546 |
| GDPval-AA，专业工作产品（Elo） | 1,695 | 1,605 |
| AA-Omniscience Index | 32 | 30 |
| AA-Omniscience 幻觉率 | 29% | 34% |
| 每个 Intelligence Index 任务的输出 token | ~81k | ~38k |

Grok 4.7 在 `xhigh` 推理强度下测量，而 Grok 4.6 在 Artificial Analysis 为每项指标所报告的强度级别下测量。最后一行是要规划的那个权衡：收益伴随着大约每任务翻倍的输出 token。这正是为什么刻意设定强度级别——而非沿用默认——是划算的。

### 安全与网络安全

据 xAI，Grok 4.7 由一套全新的安全防护栈构建，是它测试过的在拒绝和越狱抵抗上最强的模型。xAI 把在网络安全和生物工作这类双重用途领域中的目标描述为同时守住两件事：对合法任务保持有用，同时拒绝危险的任务。

具体到网络安全，xAI 报告模型只放行极小比例的风险双重用途 prompt，而很少阻止合法的安全工作。xAI 也开始向选定的网络安全合作伙伴提供仅限邀请的、访问 Grok 4.7 红队能力的权限，用于防御研究。

## Grok 4.7 在 Amazon Bedrock 上如何打包

Grok 4.7 接受文本和图像输入并返回文本。该模型通过跨区域推理配置在 `bedrock-runtime` 端点上服务，因此请求指定的是一个配置（profile）而非裸 model ID：

| **推理选项** | **Model ID** | **Base URL** |
| --- | --- | --- |
| 地理跨区域 | us.xai.grok-4.7 | `https://bedrock-runtime.{region}.amazonaws.com/openai/v1` |
| 全球跨区域 | global.xai.grok-4.7 | `https://bedrock-runtime.{region}.amazonaws.com/openai/v1` |

Grok 4.7 支持 Responses API、Chat Completions API、InvokeModel 和 Converse API。

因为该模型兼容 OpenAI，你可以在客户端之间选择。OpenAI SDK 可用一个 bearer token 针对 `/openai/v1` 路径工作，该 token 可以是一个 Amazon Bedrock API key，或一个从你的 AWS Identity and Access Management (IAM) 凭证签发的短期 token。AWS SDK 通过 Converse 触及同一模型，用你普通的 AWS 凭证对请求签名。如果你在移植一个现有集成，用 OpenAI SDK。如果你想让你账户内的模型共用一种消息形态，并想通过标准 Bedrock 事件类型获得调用日志和响应流式传输，用 Converse。

### 把 Grok 4.7 与 Bedrock 特性一起用

隐式 prompt 缓存会自动应用于重复的 prompt 前缀，因此每轮重发一个大 system prompt 或参考文档的智能体，对那份前缀按缓存价付费。Amazon Bedrock Guardrails 在请求上按 ID 和版本附加，对 prompt 和响应都应用内容过滤器、禁用主题、可识别个人身份信息（PII）脱敏和词策略。这对一个可能跨很多步无人值守运行的模型很有用。借助结构化输出，你可以把响应约束到一个 JSON Schema，以便下游代码直接解析。调用日志把每次调用连同请求、响应和 token 计数（包括推理 token）捕获到 Amazon CloudWatch。这为你在长智能体运行上提供一个审计轨迹。

### 区域与推理选项

Grok 4.7 通过两个跨区域推理配置之一路由，而非锁定到单个区域。

Global 配置 `global.xai.grok-4.7` 把每个请求路由到任何受支持的商业 AWS 区域，在更大的容量间分散负载，且定价低于地理配置。其权衡是对某个请求在哪被服务有较少的控制，这可能意味着更可变的延迟。

美国地理配置 `us.xai.grok-4.7` 把处理保持在美国地理范围内，这满足美国数据驻留要求。当你有驻留约束或延迟敏感流量时选它，当成本和吞吐更重要时选 Global。

### 服务层级与定价

Standard 是按 token 付费、无承诺，通过设 `"service_tier": "default"` 或省略该字段来选择。Priority 为溢价（`"service_tier": "priority"`）提供更快的、优先的处理。Flex 对时间不敏感的工作提供更低成本的访问（`"service_tier": "flex"`）。

服务层级是一个由你掌控的重要成本杠杆。各层级的每-token 定价参见 [Amazon Bedrock 定价页面](https://aws.amazon.com/bedrock/pricing/)。

## 发送你的第一个请求

在你第一次调用之前，确认该模型在你计划使用的 AWS 区域中的 Bedrock 控制台里对你可用。

安装 OpenAI SDK，如果你打算使用 Converse API 则安装 `boto3`：

```
pip install openai
pip install boto3
```

从 Amazon Bedrock 控制台生成一个长期 Amazon Bedrock API key 用于探索，然后设置你的环境：

```
export OPENAI_API_KEY="<provide your Bedrock API key>"
export OPENAI_BASE_URL="https://bedrock-runtime.us-east-1.amazonaws.com/openai/v1"
```

用 Chat Completions API 的第一个请求：

```
from openai import OpenAI

client = OpenAI()

response = client.chat.completions.create(
    model="us.xai.grok-4.7",
    messages=[
        {"role": "user", "content": "Can you explain the features of Amazon Bedrock?"}
    ],
)
print(response.choices[0].message.content)
```

通过 Responses API 的同一调用：

```
response = client.responses.create(
    model="us.xai.grok-4.7",
    input="Can you explain the features of Amazon Bedrock?",
)
print(response.output_text)
```

以及用 `boto3` 通过 Converse API。因为推理始终活跃，第一个内容块携带推理而答案在后面的块里，所以搜索各块取文本，而不是索引 `content[0]`：

```
import boto3

client = boto3.client("bedrock-runtime", region_name="us-east-1")

response = client.converse(
    modelId="us.xai.grok-4.7",
    messages=[
        {"role": "user", "content": [{"text": "Can you explain the features of Amazon Bedrock?"}]}
    ],
    inferenceConfig={"maxTokens": 2048},
)

blocks = response["output"]["message"]["content"]
text = next(b["text"] for b in blocks if "text" in b)
print(text)
```

在 Converse 上，你通过 `additionalModelRequestFields` 而非一个 `reasoning` 参数设置强度级别：

```
response = client.converse(
    modelId="us.xai.grok-4.7",
    messages=[{"role": "user", "content": [{"text": "What is 17*23? Number only."}]}],
    inferenceConfig={"maxTokens": 3000},
    additionalModelRequestFields={"reasoning_effort": "xhigh"},
)
```

三条运维说明。首先，请求必须指定 `us.xai.grok-4.7` 或 `global.xai.grok-4.7`。

其次，`bedrock:InvokeModel` 会针对三种资源求值：你账户的默认项目、你指定的推理配置，以及底层基础模型（FM）。基础模型的 Amazon Resource Name (ARN) 跨区域是通配的，因为跨区域配置会把请求路由到调用区域之外。Bearer-token 认证还额外要求 `bedrock:CallWithBearerToken`，而 `boto3` 和 Converse 不需要它：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:{region}:{account-id}:project/default",
                "arn:aws:bedrock:{region}:{account-id}:inference-profile/us.xai.grok-4.7",
                "arn:aws:bedrock:*::foundation-model/xai.grok-4.7"
            ]
        },
        {
            "Effect": "Allow",
            "Action": "bedrock:CallWithBearerToken",
            "Resource": "*"
        }
    ]
}
```

列出你计划调用的每一个推理配置。配置是逐个限定范围的，因此一个指定 `us.xai.grok-4.7` 的策略并不覆盖 `global.xai.grok-4.7`。

第三，两种认证机制覆盖不同的代码路径。`OPENAI_API_KEY` 中的 Amazon Bedrock API key 作为 bearer token 传输，认证那些 OpenAI 兼容的调用。`boto3` 的 Converse 示例改用 SigV4 签名，从环境、一个 profile 或一个角色取用你普通的 AWS 凭证。如果你打算在 OpenAI 兼容 API 之外同时使用 Converse，两者都配置。

把长期 API key 当作仅限探索的凭证对待。对于生产，使用 `aws-bedrock-token-generator` 包从你的 IAM 凭证生成短期 bearer token，因为它们会自动过期并把访问绑定到你的 IAM 身份。

## 使用推理强度

Grok 4.7 上推理是活跃的，而强度级别是你对成本和延迟的一个主要控制。你在 Responses API 上用 `reasoning` 参数（配 `low`、`medium`、`high` 或 `xhigh`）配置它，并在 Converse 上用 `additionalModelRequestFields` 配置。

默认是 `high`。值得显式设置它而非沿用，因为在延迟敏感或高流量的调用上不设置它会花掉超出这些调用所需的推理 token。

因为模型经过训练要工作更久并验证自身输出，更高的强度买到的不只是对单个答案更多的斟酌：它买到跨一个长任务更多的自检。短的抽取和分类调用属于 `low`。多步规划、长智能体轨迹，以及早期错误会传播的工作，才是 `high` 和 `xhigh` 值回其 token 的地方。

推理内容是加密的。你可以在 Responses API 请求上通过传入以下内容让它被返回：`include: ["reasoning.encrypted_content"]`。然后在后续回合把那份内容回传，以在一段多轮对话中把模型自身先前的推理作为上下文交给它。Chat Completions API 不返回推理 token。

```
from openai import OpenAI

client = OpenAI()  # OPENAI_BASE_URL points at the bedrock-runtime endpoint

response = client.responses.create(
    model="us.xai.grok-4.7",
    reasoning={"effort": "high"},
    include=["reasoning.encrypted_content"],
    input="Explain quantum entanglement simply.",
)
print(response.output_text)
```

要找到额外推理在何处不再值回成本，用你自己的工作负载对各强度级别做基准测试。

## 开始上手

有了 Amazon Bedrock 上的 Grok 4.7，你得到 50 万 token 上下文窗口、四个推理强度级别、图像输入、工具调用，以及地理和全球跨区域路由。这一切都可通过 Responses、Chat Completions 和 Converse API 触达。

要开始构建，查看 Grok 4.7 模型卡以了解当前区域列表、特性矩阵和参数细节，并查 [Amazon Bedrock 定价页面](https://aws.amazon.com/bedrock/pricing/) 了解 token 费率。如果你生成了一个长期 Amazon Bedrock API key 用于探索，完成后请从 Amazon Bedrock 控制台删除它。一个你不再需要的常备凭证只会扩大你账户的攻击面。
