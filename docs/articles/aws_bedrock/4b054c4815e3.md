# 在 Amazon Bedrock AgentCore Identity 中引用你自己的 AWS Secrets Manager 密钥

AI agent 的能力上限取决于它能访问哪些工具。无论是在 CRM 中检索客户数据、向 Slack 发布更新，还是查询 GitHub 仓库，agent 都需要调用外部 API，而这意味着要在运行时安全地传递凭证。把这件事做对——既不在代码里硬编码密钥，也不在 agent 的 prompt 中泄露它们——是构建生产级 agentic 系统最具代表性的挑战之一。

[Amazon Bedrock AgentCore Identity](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity.html) 通过 credential provider 与 token vault 应对这一挑战：为每一个 Outbound credential provider 资源，在你的账户中的 [AWS Secrets Manager](https://aws.amazon.com/secrets-manager/) 里自动创建并管理一个密钥。该密钥包含 API key 或 client secret，以及外部身份供应商的其他元数据。虽然 AgentCore Identity 完整地创建并管理这些密钥，但客户无法在创建时配置自定义标签、轮换策略，也无法指定用[客户托管的 AWS Key Management Service（AWS KMS）](https://docs.aws.amazon.com/kms/latest/developerguide/concepts.html#customer-mgn-key)密钥来加密。

今天，我们很高兴宣布 AgentCore Identity 现在可以引用 AWS Secrets Manager 中的密钥，因此你可以引用自己在 Secrets Manager 中预先配置好的密钥，并对它的管理方式保留完整控制。借助这项能力，你可以把组织现有的密钥治理流程延伸到 AgentCore。你可以提供一个已有的、预先配置好的 AWS Secrets Manager 密钥，与你的 [credential provider](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/resource-providers.html) 资源一起使用。你对它的加密配置、轮换、复制、标签与资源策略保留完整控制，就像管理 Secrets Manager 中的其他密钥一样。你也可以选择同一 AWS 区域内另一个 AWS 账户中的密钥，但不支持跨区域共享密钥。这项能力还支持通过 AWS Secrets Manager 外部连接器引入的密钥，从而可与第三方密钥管理器集成。

在本文中，我们会过一遍示例用例，并演示如何开始用已有密钥配置你的 credential provider 资源。

## 示例用例

以下是一些示例用例：

- **你的 agent 访问团队已经有密钥的外部 API：**把那个已有密钥的 ARN 提供给你的 credential provider 资源，而不是让 AgentCore Identity 新建一个。你也可以引用同一区域内另一个 AWS 账户中的密钥；通过 AWS Secrets Manager 外部连接器引入的密钥也受支持，可与第三方密钥管理器集成。
- **你出于安全最佳实践想轮换密钥，并希望 agent 在轮换过程中继续工作：**当你轮换密钥值时，AgentCore Identity 会在下一次读取时获取更新后的值。你无需更新或重建 credential provider 资源。
- **你把密钥访问限定在预期的 agent 用途上：**直接在 AWS Secrets Manager 中配置密钥上的资源策略。你可以控制哪些 AWS Identity and Access Management（IAM）主体能够访问该密钥，并限定访问条件。
- **你的 agent 运行在受监管环境中，每个凭证都必须用你的客户托管密钥加密：**在把密钥提供给 AgentCore Identity 之前，先用你的客户托管加密密钥创建它。如果你的组织通过 SCP 与 RCP 来帮助确保所有数据都使用客户托管 CMK 加密，这尤其有用。通过引用已有密钥，你的加密配置被完整保留。
- **你的组织要求密钥上带资源标签，用于成本分摊、合规追踪或治理审计：**按你的标准创建并标记该密钥，然后再提供给 AgentCore Identity。

想进一步了解可用的密钥配置选项，请参阅 [AWS Secrets Manager 用户指南](https://docs.aws.amazon.com/secretsmanager/latest/userguide/managing-secrets.html)。

## 先决条件

要跟做本文，你需要以下条件：

- 一个已有的 AWS Secrets Manager 密钥，其中包含 API key 或 OAuth client secret。
- IAM 权限，用来授予 AgentCore Identity 服务主体对该密钥的 `secretsmanager:GetSecretValue` 访问权限。
- 如果你使用客户托管的 AWS KMS 密钥，还需为该服务主体授予该密钥上的 `kms:Decrypt` 权限。
- 对 Amazon Bedrock AgentCore Identity 控制台或 AWS Command Line Interface（AWS CLI）的访问权限。

## 开始使用

要引用 AWS Secrets Manager 中的密钥，在通过 AgentCore Identity API 创建 credential provider 资源时提供密钥 ARN 与 JSON 键。AgentCore Identity 会在运行时从你密钥中指定的 JSON 键取出凭证值。

下面几节展示如何使用 AWS 管理控制台、AWS CLI 或 AI agent 创建一个带引用密钥的 credential provider 资源。

### 使用控制台

在直接从 Amazon Bedrock AgentCore Identity 控制台创建新的 credential provider 资源时，你可以配置被引用的密钥。该功能同时支持 API key 与 OAuth 客户端凭证两种类型。

![AgentCore Identity 控制台，展示创建带引用密钥的 Outbound Auth 资源](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/01/ML-21022-1.png)

*图 1：AgentCore Identity 控制台，创建带引用密钥的 Outbound Auth 资源。*

### A. 添加带引用密钥的 API key

要添加带引用密钥的 API key，请完成以下步骤：

- 打开 [Amazon Bedrock AgentCore 控制台](https://console.aws.amazon.com/bedrock-agentcore/)。
- 在左侧导航窗格中，选择 **Identity**。
- 在 **Outbound Auth** 区域，选择 **Add Outbound Auth**。
- 选择 **Add API key**。
- 为你的 Outbound Auth 资源输入一个 **Name**。
- 在 **API key selection method** 下，选择 **Provide API key via Secrets Manager**。
- 在 **Secrets Manager ARN** 字段中，输入或选择你已有密钥的 ARN。列表会显示你账户中可用的密钥。例如：`arn:aws:secretsmanager:us-east-1:123456789012:secret:myApiKeySecret-AbCdEf`。
- 在 **JSON key** 字段中，指定你 Secrets Manager 密钥中包含 API key 值的那个键。
- 选择 **Add**。
- 检查该 credential provider 是否出现在 Outbound Auth 列表中，以确认它已创建。

![AgentCore Identity 控制台，展示如何从 Secrets Manager 添加 API key](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/01/ML-21022-2.png)

*图 2：AgentCore Identity 控制台，从 Secrets Manager 添加 API key。*

### B. 添加带引用密钥的 OAuth client secret

要添加带引用密钥的 OAuth client secret，请完成以下步骤：

- 在 **Identity** 页面上，选择 **Add Outbound Auth**。
- 选择 **Add OAuth client**。
- 为你的 OAuth 客户端输入一个 **Name**（例如 `google-oauth-client-v5fz5`）。
- 在 **Provider** 下，选择你想要的内置或自定义供应商。
- 输入身份供应商分配给你的 **Client ID**。
- 在 **Client secret** 下，选择 **Provide Client secret via Secrets Manager**。
- 在 **Secrets Manager ARN** 字段中，输入包含你 OAuth client secret 的密钥 ARN。
- 在 **JSON key** 字段中，指定该密钥中包含 client secret 值的那个键。
- 选择 **Add OAuth Client**。
- 检查该 credential provider 是否出现在 Outbound Auth 列表中，以确认它已创建。

![AgentCore Identity 控制台，展示如何从 Secrets Manager 添加 OAuth client secret](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/01/ML-21022-3.png)

*图 3：AgentCore Identity 控制台，从 Secrets Manager 添加 OAuth client secret。*

### 使用 AWS CLI

在直接从 AWS CLI 创建面向 OAuth client secret 的新 Outbound Auth 资源时，你可以配置被引用的密钥，如下面的代码所示：

```
aws bedrock-agentcore-control create-oauth2-credential-provider \
    --name "google-oauth-client-v5fz5" \
    --credential-provider-vendor "GoogleOauth2" \
    --oauth2-provider-config-input '{
        "googleOauth2ProviderConfig": {
            "clientId": "<clientId>",
            "clientSecretSource": "EXTERNAL",
            "clientSecretConfig": {
                "secretId": "arn:aws:secretsmanager:us-east-1:123456789012:secret:myGoogleKeySecret-AbCdEf",
                "jsonKey": "key"
            }
        }
    }'
```

### 在桌面端使用 AI agent

如果你在使用 AI 编码 agent（例如 [Kiro](https://kiro.dev/) 或类似工具），可以直接提示它去配置被引用的密钥：

> “我在 AWS Secrets Manager 里有一个已有的密钥，ARN 为 arn:aws:secretsmanager:us-east-1:123456789012:secret:my-api-key。请在 Amazon Bedrock AgentCore Identity 中创建一个名为 <client-name> 的 OAuth2 credential provider，供应商使用 GoogleOauth2。client ID 为 <clientId>，client secret 来源为 EXTERNAL，密钥的 JSON 键为 key。”
>         注意：把 <client-name> 与 <clientId> 替换为你自己的值。

**重要：**通过给密钥添加一条资源策略，允许该服务主体调用 `secretsmanager:GetSecretValue`，从而授予 AgentCore Identity 读取你密钥的权限。如果你的密钥用客户托管 KMS 密钥加密，还要为该服务主体授予该密钥上的 `kms:Decrypt` 权限。

## 结语

有了引用 AWS Secrets Manager 中密钥的能力，AgentCore Identity 让你在为 AI agent 配置出站认证时，可以灵活地延用已有的密钥与密钥管理实践。你可以对凭证如何加密、如何轮换、如何被访问保留完整控制，而由 AgentCore Identity 负责在运行时取用它们。

要开始使用，请参阅 [Amazon Bedrock AgentCore Identity 文档](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity.html)。有关密钥管理的更多内容，请参阅 [AWS Secrets Manager 用户指南](https://docs.aws.amazon.com/secretsmanager/latest/userguide/)。
