# ICYMI：2026 年 10 月 AI 构建者迎来了什么

在 AWS，我们相信 AI 构建者应当能为每项任务挑对模型，能在生产环境里信任自己的 agent，也能清楚看到 AI 工作负载花了多少钱。这一信念指引着我们在整个产品组合上如何投入。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 让你用上领先的模型，以及安全地构建和规模化 AI 应用所需的工具。我们用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 进一步夯实这一底座，它提供了用任意模型、任意框架来构建、连接和优化 agent 的平台，其中也包括我们的开源 agent 开发工具包 [Strands](https://strandsagents.com/)。两者一起，把你从第一个原型带到生产环境。

随着 agent 进入核心业务工作流，门槛也在抬高。当任务、预算和时延目标变化时，你需要能灵活切换不同模型。当主模型被限流或不可达时，你的 agent 必须继续工作。它们还必须在你设定的边界内行动，返回其它软件可直接使用的输出。它们的回答必须始终有你允许的信源作依据，成本也得在高用量下站得住脚。

我们在 10 月发布的内容，正是对这些需求的一一回应。新模型帮你把每项任务匹配到合适的价格和速度，从高并发的 subagent 到实时语音都有。Amazon Bedrock 与 AgentCore 的更新让 agent 保持可用、恪守你定义的流程，帮你信任它们返回的结果。新的定价与成本报表让支出更可预测。Strands 则新增了构建、约束和测试 agent 的方式。

## 在 Amazon Bedrock 上按任务挑模型

**跑得快、成本低的 subagent。** [Claude Haiku 5.5](https://aws.amazon.com/about-aws/whats-new/2026/10/claude-haiku-5-5-aws/) 专为 subagent 和高并发、成本敏感的工作而生。据 Anthropic 称，它是迄今能力最强的 Haiku，多数任务上比 Claude Haiku 4.5 便宜约 75%。它也是首个带 effort controls 的 Haiku，让你能按任务在成本与智能之间调校。在多 agent 架构里，可以让 Claude Opus 5.5 这类模型负责规划，再把边界明确的编码、工具调用和浏览器自动化任务交给 Haiku。这样并行跑很多 agent 也负担得起。

**以更低价格拿到接近旗舰的效果。** [OpenAI GPT-6.1 Terra](https://aws.amazon.com/about-aws/whats-new/2026/10/openai-gpt-6-1-terra-on-amazon-bedrock/) 现已在 Amazon Bedrock 正式可用。在 OpenAI 的 Agents' Last Exam 评测里，它的表现与 GPT-6 Astra 相当，完成任务的速度却比 GPT-6 Astra 和 GPT-6.1 Sol 快三倍以上。它的输入与输出 token 价格至少比 GPT-6.1 Sol 和 GPT-5.6 Terra 低 50%。它接受文本和图片，输入最多 100 万 token，适合起草方案、解读技术图纸，以及构建跨业务系统工作的 agent。对实时编码助手这类时延敏感的工作，GPT-6.1 Sol 现在还提供 [Ultrafast mode](https://aws.amazon.com/about-aws/whats-new/2026/10/openai-gpt-sol-ultrafast-amazon/)。

**构建能实时推理的语音 agent。** [Amazon Nova 2.5 Sonic](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-nova-2.5-sonic/) 是我们最新的 speech-to-speech 模型，在推理、指令遵循和工具调用准确率上都有提升，时延更低，价格与 Amazon Nova 2 Sonic 相同。客服 agent 现在能在一次对话里查订单、核对退货资格并发起退货。

**为编码和视频挑专用模型。** [GLM 5.3 by Z.ai](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-bedrock-glm-5-3/) 是面向 agentic 编码和长周期软件工程的开放权重模型，带 100 万 token 上下文窗口和 prompt caching，面向符合条件的企业客户开放。[TwelveLabs Pegasus 1.5](https://aws.amazon.com/about-aws/whats-new/2026/10/twelve-labs-pegasus-1-5-aws/) 能把整段视频变成结构化、带时间码的元数据。它一次遍历就能读取画面、音频和屏幕上的文字，无需单独的接入流水线。

**在 AWS GovCloud (US) 里用上更多模型。** [Claude Haiku 5.5](https://aws.amazon.com/about-aws/whats-new/2026/10/claude-haiku-5-5-aws-govcloud/) 和[支持跨区域推理的 OpenAI GPT-5.6 模型](https://aws.amazon.com/about-aws/whats-new/2026/10/bedrock-openai-runtime-govcloud/)现已在 AWS GovCloud (US) 可用。面向授权安全工作的 [Daybreak Red from OpenAI](https://aws.amazon.com/about-aws/whats-new/2026/10/openai-daybreak-red-govcloud-east/) 已在 AWS GovCloud (US-East) 面向符合条件的客户开放。受监管的团队能在维持美国数据主权的同时用上更多模型。

## 构建和运行可信赖的 agent

**在终端里构建和运维 agent。** AgentCore CLI 是 Amazon Bedrock AgentCore 的一项能力，现已[发布 1.0 正式版](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-bedrock-agentcore-cli-version-1-0-available/)。我们重写了它，启动更快、命令结构更一致，并支持更多 AgentCore 资源。你可以直接或通过项目来操作 harnesses、runtimes、memory、identity、gateways 和 payments。现有项目一条命令即可升级到版本 1。结果是从本地开发到日常运维只需一个工具。

**主模型被限流时仍让 agent 保持可用。** AgentCore Gateway 是 Amazon Bedrock AgentCore 的一项能力，现已[支持 Amazon Bedrock InvokeModel API 和模型回退](https://aws.amazon.com/about-aws/whats-new/2026/10/agentcore-gateway-invokemodel-fallback/)。你现有的 Amazon Bedrock SDK 代码可以直接指向 gateway，无需为每个供应商改代码。当主模型被限流或不可达时，gateway 会把请求路由到你定义的链路里的下一个模型或供应商。circuit breaker 会跳过正在故障的目的地。gateway 还能用[你自有私有证书颁发机构签发的证书](https://aws.amazon.com/about-aws/whats-new/2026/10/agentcore-gateway-private-tls-vpc/)访问 virtual private cloud（VPC）里的私有目标。你的 agent 不必在每个客户端里写重试逻辑就能保持可用。

**把业务工作流变成 agent 工具。** 你现在可以通过 AgentCore Gateway，把 [AWS Step Functions 工作流](https://aws.amazon.com/about-aws/whats-new/2026/10/step-functions-workflows-ai-agent-tools/)（包括已有的 Standard 和 Express 工作流）当作工具来用。业务逻辑留在你已经在跑、并且信任的工作流里，不必在 agent 内部重建，也不必靠 prompt 去遵循它。由 agent 决定何时运行工作流，Step Functions 则严格按你的定义执行每一步。例如，一个客服 agent 可以启动你的退款工作流，而每一笔退款仍会走同样的资格核验、审批和入账步骤。

**拿到系统可直接使用的 JSON。** [Structured outputs](https://aws.amazon.com/about-aws/whats-new/2026/10/claude-structured-outputs-bedrock/) 现已对 Amazon Bedrock 上的所有 Claude 模型可用。你无需自定义解析或重试，就能拿到符合 schema 的 JSON。你可以从财报里抽出每一个必填字段，或用始终匹配你数据模型的实体来路由工单。

**让回答始终以你信任的信源为依据。** [Web Search on Amazon Bedrock](https://aws.amazon.com/about-aws/whats-new/2026/10/bedrock-web-search-domain-user-location/) 现已对通过 OpenAI Responses API 发起的请求支持域名过滤和用户位置。你最多可允许 100 个域名、屏蔽 100 个域名，并返回与某个地理区域相关的结果。随后 [Amazon Bedrock Guardrails](https://aws.amazon.com/about-aws/whats-new/2026/10/bedrock-guardrails-grounding-standard/) 会检查回答是否忠实于其信源。它新增的 Standard 层级用于上下文事实核验，价格与 Classic 层级相同，覆盖对话式和推理式回答，并支持更多语言。两者结合，你既能控制回答来自哪里，又能在更多应用里发现幻觉。

## 预测并降低运行 agent 的成本

**按实际用量支付 agent memory 的费用。** AgentCore memory 是 Amazon Bedrock AgentCore 的一项能力，现已[按 agent 摄取、检索和存储的数据量来给短期记忆定价](https://aws.amazon.com/about-aws/whats-new/2026/10/agentcore-memory-consumption-based-pricing)，而不再按每次事件收固定费率。多数工作负载成本会下降，小 payload 的场景降幅最大。你还可以为[长期记忆记录设置 time-to-live](https://aws.amazon.com/about-aws/whats-new/2026/10/agentcore-memory-long-term-memory-ttl)，以满足留存要求并控制存储成本。

**看清 Amazon Bedrock 的花费花在哪里。** [AWS Cost Explorer、AWS Budgets 和 AWS Cost Management Dashboards](https://aws.amazon.com/about-aws/whats-new/2026/10/aws-bedrock-attributes-in-cost-explorer/) 现已按模型、模型供应商、推理类型和特性拆分 Amazon Bedrock 成本，不额外收费。财务和平台团队可以在自己已在用的计费工具里，找出最贵的模型，或为单个模型设置预算告警。为降低输入成本，[Advanced Prompt Optimization](https://aws.amazon.com/about-aws/whats-new/2026/10/bedrock-prompt-optimization-shortening/) 现在还能缩短你的 prompt——只有当缩短版在你的评测里得分不低于原版时，才返回这个更短的版本。

## 用 Strands 构建语音、本地和经过充分测试的 agent

**几行代码就能交付语音 agent。** [Strands Bidi Agents](https://strandsagents.com/blog/bidi-agents-now-ga/) 用于构建双向 speech-to-speech 语音 agent，现已正式可用，直接支持 Amazon Nova Sonic、OpenAI 和 Gemini 模型。Bidi Agents 会在后台重连模型，因此长通话能越过供应商的会话上限继续。语音 agent 还能把研究这类耗时较长的工作交给另一个 agent，并把结果口述出来。

**让本地 agent 在你的边界内工作。** [Strands Box](https://strandsagents.com/blog/strands-box-the-big-picture/) 现已进入开发者预览，是面向 AI agent 的开源本地沙箱。它把操作系统级隔离与语义策略结合起来。你为每种工具设定策略，由 Box 确定性地执行——无论 agent 是直接调用工具、通过 Model Context Protocol（MCP）调用，还是生成代码来调用。Box 适配任意模型和任意 agent 框架，因此 agent 可以在你的项目里工作，却碰不到你未允许的文件和服务。

**在客户之前先找出 agent 会在哪里崩。** [Strands Evals 里的 red teaming](https://strandsagents.com/blog/red-team-your-agent-strands-evals/) 会针对你的 agent 跑对抗性对话，比如 prompt injection 和越狱尝试，并展示它失败时的消息和工具调用。Strands Evals 现在还能[逐字段给结构化输出打分](https://strandsagents.com/blog/structured-output-similarity-strands-evals/)，当 agent 大多数字段答对时给出部分得分。用它们在 agent 进入生产之前修好薄弱环节。要上手，可看 [Strands Evals 文档](https://strandsagents.com/docs/user-guide/evals-sdk/quickstart/)。

**削减常规 agent 决策的成本。** [Strands Decider](https://strandsagents.com/blog/strands-decider-gemma-4-models/) 是我们[上月回顾](https://aws.amazon.com/blogs/machine-learning/icymi-what-landed-for-ai-builders-in-september-2026/)里介绍过的小型开源决策模型，如今基于 Gemma 4 提供四种尺寸。它不生成文本，而是在你定义的选项之间做选择，比如调用哪个工具、把请求路由到哪里。当 Amazon 的一个团队[把某套最大的内部工单系统里的工单分类切换到 Decider](https://strandsagents.com/blog/amazon-saves-millions-replacing-sonnet-with-strands-decider/) 后，估算的每单成本下降了约 98%，平均响应时间下降了 78%。
