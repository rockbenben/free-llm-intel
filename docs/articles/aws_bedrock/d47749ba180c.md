# 使用 Amazon Bedrock Knowledge Bases 结构化数据查询 Amazon Aurora PostgreSQL

[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 提供全托管的检索增强生成（RAG）功能，可将大语言模型（LLM）连接到内部数据源。该功能用来自私有数据的上下文信息增强 foundation model（FM）的输出，使回答更具相关性和准确性。

在 AWS re:Invent 2024 上，我们[宣布](https://aws.amazon.com/about-aws/whats-new/2024/12/amazon-bedrock-knowledge-bases-structured-data-retrieval/) Amazon Bedrock Knowledge Bases 支持通过自然语言查询，从 [Amazon Redshift](https://aws.amazon.com/redshift/) 和 [Amazon SageMaker Lakehouse](https://aws.amazon.com/sagemaker/lakehouse/) 检索结构化数据。该功能提供托管工作流，用于构建可访问并整合结构化与非结构化数据源信息的[生成式 AI](https://aws.amazon.com/generative-ai/) 应用。通过自然语言处理，Amazon Bedrock Knowledge Bases 将自然语言查询转换为 SQL 查询，使用户无需了解数据库结构或 SQL 语法即可从受支持的源检索数据。

在本文中，我们讨论如何让 [Amazon Aurora PostgreSQL-Compatible Edition](https://aws.amazon.com/rds/aurora/postgresql-features/) 数据可通过 Amazon Bedrock Knowledge Bases 进行自然语言查询，同时保持数据新鲜度。

## Amazon Bedrock Knowledge Bases 中的结构化数据检索与 Amazon Redshift Zero-ETL

Amazon Bedrock Knowledge Bases 中的结构化数据检索通过将用户查询转换为 SQL 语句，实现与数据库的自然语言交互。当你连接 Amazon Redshift 等受支持的数据源时，Amazon Bedrock Knowledge Bases 会分析你的数据库 schema、表关系、查询引擎和历史查询，以理解你的信息的上下文与结构。这种理解使该服务能够根据自然语言问题生成准确的 SQL 查询。

截至本文撰写时，Amazon Bedrock Knowledge Bases 支持直接从 Amazon Redshift 和 SageMaker Lakehouse 进行结构化数据检索。虽然目前尚不直接支持 Aurora PostgreSQL-Compatible，但你可以使用 Aurora PostgreSQL-Compatible 与 Amazon Redshift 之间的 zero-ETL 集成，让你的数据可被 Amazon Bedrock Knowledge Bases 结构化数据检索访问。[Zero-ETL](https://aws.amazon.com/rds/aurora/zero-etl/) 集成会以近实时方式自动将你的 Aurora PostgreSQL 表复制到 Amazon Redshift，从而省去复杂的提取、转换和加载（ETL）管道或数据移动流程。

对于希望对其存储在 [Amazon Aurora](https://aws.amazon.com/rds/aurora/) 数据库表中的结构化应用数据启用自然语言查询的组织来说，这种架构模式尤其有价值。通过将 zero-ETL 集成与 Amazon Bedrock Knowledge Bases 结合，你可以构建强大的应用，例如使用 LLM 基于其运营数据提供自然语言回答的 AI 助手。

## 解决方案概览

下图展示了我们将用于通过 zero-ETL 将 Aurora PostgreSQL-Compatible 连接到 Amazon Bedrock Knowledge Bases 的架构。

![架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/26/ML-18260-arch-diagram.png)

该工作流包含以下步骤：

- 数据存储在私有子网中的 Aurora PostgreSQL-Compatible 内。我们使用堡垒主机从公有子网安全地连接到数据库。
- 通过 zero-ETL 集成，这些数据在同样位于私有子网中的 Amazon Redshift 里可用。
- Amazon Bedrock Knowledge Bases 使用 Amazon Redshift 作为其结构化数据源。
- 用户可以使用 [AWS Management Console](https://aws.amazon.com/console) 或 AWS SDK 客户端与 Amazon Bedrock Knowledge Bases 交互，发送自然语言查询。这些查询由 Amazon Bedrock Knowledge Bases 处理，以检索存储在 Amazon Redshift（源自 Aurora）中的信息。

## 先决条件

请确保你登录所使用的用户角色有权创建 Aurora 数据库、运行 DDL（CREATE、ALTER、DROP、RENAME）和 DML（SELECT、INSERT、UPDATE、DELETE）语句、创建 Redshift 数据库、设置 zero-ETL 集成，以及创建 Amazon Bedrock 知识库。

## 设置 Aurora PostgreSQL 数据库

在本节中，我们将演示如何创建和配置一个带有示例 schema 的 Aurora PostgreSQL 数据库。我们创建三张相互关联的表：`products`、`customers` 和 `orders`。

### 预置数据库

让我们先设置数据库环境。创建一个新的 Aurora PostgreSQL 数据库集群，并启动一个 [Amazon Elastic Compute Cloud](https://aws.amazon.com/ec2)（Amazon EC2）实例，作为管理数据库的访问入口。该 EC2 实例将使创建表以及在整个过程中管理数据变得简单直接。

以下截图展示了我们的数据库集群和 EC2 实例的详细信息。

![Aurora PostgreSQL 集群](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/26/ML-18260-aurorapg.jpeg)

有关设置数据库的说明，请参阅 [Creating and connecting to an Aurora PostgreSQL DB cluster](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/CHAP_GettingStartedAurora.CreatingConnecting.AuroraPostgreSQL.html)。

### 创建数据库 schema

在通过 EC2 实例上的 SSH 连接到你的数据库后（如 [Creating and connecting to an Aurora PostgreSQL DB cluster](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/CHAP_GettingStartedAurora.CreatingConnecting.AuroraPostgreSQL.html) 所述），就可以创建数据结构了。我们使用以下 DDL 语句创建三张表：

```
-- Create Product table
CREATE TABLE product (
    product_id SERIAL PRIMARY KEY,
    product_name VARCHAR(100) NOT NULL,
    price DECIMAL(10, 2) NOT NULL
);

-- Create Customer table
CREATE TABLE customer (
    customer_id SERIAL PRIMARY KEY,
    customer_name VARCHAR(100) NOT NULL,
    pincode VARCHAR(10) NOT NULL
);

-- Create Orders table
CREATE TABLE orders (
    order_id SERIAL PRIMARY KEY,
    product_id INTEGER NOT NULL,
    customer_id INTEGER NOT NULL,
    FOREIGN KEY (product_id) REFERENCES product(product_id),
    FOREIGN KEY (customer_id) REFERENCES customer(customer_id)
);
```

### 向表中填充数据

创建表之后，你可以用示例数据填充它们。向 `orders` 表插入数据时，请记得通过核实以下内容来维护引用完整性：

- `product_id` 存在于 `product` 表中
- `customer_id` 存在于 `customer` 表中

我们使用以下示例代码填充表：

```
INSERT INTO product (product_id, product_name, price) VALUES (1, 'Smartphone X', 699.99);
INSERT INTO product (product_id, product_name, price) VALUES (2, 'Laptop Pro', 1299.99);
INSERT INTO product (product_id, product_name, price) VALUES (3, 'Wireless Earbuds', 129.99);
INSERT INTO customer (customer_id, customer_name, pincode) VALUES (1, 'John Doe', '12345');
INSERT INTO customer (customer_id, customer_name, pincode) VALUES (2, 'Jane Smith', '23456');
INSERT INTO customer (customer_id, customer_name, pincode) VALUES (3, 'Robert Johnson', '34567');
INSERT INTO orders (order_id, product_id, customer_id) VALUES (1, 1, 1);
INSERT INTO orders (order_id, product_id, customer_id) VALUES (2, 1, 2);
INSERT INTO orders (order_id, product_id, customer_id) VALUES (3, 2, 3);
INSERT INTO orders (order_id, product_id, customer_id) VALUES (4, 2, 1);
INSERT INTO orders (order_id, product_id, customer_id) VALUES (5, 3, 2);
INSERT INTO orders (order_id, product_id, customer_id) VALUES (6, 3, 3);
```

在向 `orders` 表填充数据时，务必维护引用完整性，以避免外键约束冲突。

你也可以使用类似的示例来构建你的 schema 并为此填充数据。

## 设置 Redshift 集群并配置 zero-ETL

现在你已设置好 Aurora PostgreSQL 数据库，可以建立与 Amazon Redshift 的 zero-ETL 集成。此集成会自动在 Aurora PostgreSQL-Compatible 与 Amazon Redshift 之间同步你的数据。

### 设置 Amazon Redshift

首先，创建一个 [Amazon Redshift Serverless](https://aws.amazon.com/redshift/redshift-serverless/) 工作组和命名空间。有关说明，请参阅 [Creating a data warehouse with Amazon Redshift Serverless](https://docs.aws.amazon.com/redshift/latest/gsg/new-user-serverless.html#serverless-console-resource-creation)。

### 创建 zero-ETL 集成

zero-ETL 集成过程包含两个主要步骤：

- 从你的 Aurora PostgreSQL 数据库[创建 zero-ETL 集成](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/zero-etl.creating.html)到 Redshift Serverless。
- 在 Aurora 侧建立集成后，[在 Amazon Redshift 中创建相应的映射数据库](https://docs.aws.amazon.com/redshift/latest/mgmt/zero-etl-using.creating-db.html)。此步骤对于促成两个服务之间的正确数据同步至关重要。

以下截图展示了我们的 zero-ETL 集成详细信息。

![Zero ETL 集成](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/30/ML-18260-aurora-zeroetl-1.jpeg)

完成集成后，你可以通过几种检查来验证其是否成功。

首先，你可以在 Amazon Redshift 控制台中查看 zero-ETL 集成详细信息。你应该会看到集成的 **Active** 状态，以及源和目标信息，如下图所示。

此外，你可以使用 [Redshift Query Editor v2](https://docs.aws.amazon.com/redshift/latest/mgmt/query-editor-v2.html) 验证数据是否已成功填充。像 `SELECT * FROM customer;` 这样的简单查询应返回从你的 Aurora PostgreSQL 数据库同步过来的数据，如下图所示。

## 使用结构化数据设置 Amazon Bedrock 知识库

最后一步是创建一个 Amazon Bedrock 知识库，以对我们的数据启用自然语言查询。

### 创建 Amazon Bedrock 知识库

使用结构化数据选项创建新的 Amazon Bedrock 知识库。有关说明，请参阅 [Build a knowledge base by connecting to a structured data store](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-build-structured.html)。然后你必须同步查询引擎以启用数据访问。

### 配置数据访问权限

在同步过程能够成功之前，你需要向 Amazon Bedrock Knowledge Bases 的 [AWS Identity and Access Management](https://aws.amazon.com/iam/identity-center/)（IAM）角色授予适当的权限。这涉及为 Redshift 数据库中的每张表执行 `GRANT SELECT` 命令。

在 Redshift Query Editor v2 中为每张表运行以下命令：`GRANT SELECT ON <table_name> TO "IAMR:<KB Role name>";` 例如：`GRANT SELECT ON customer TO "IAMR:AmazonBedrockExecutionRoleForKnowledgeBase_ej0f0";`

对于生产环境设置，将最终用户身份整合进数据访问流程需要身份联合。有关基于角色的访问模型，请参阅 [AWS 结构化数据库访问文档](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-prereq-structured.html)。若要从 Web 客户端联合身份，可能需要 [Amazon Cognito](https://aws.amazon.com/cognito/) 或 [SAML 联合](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_providers_saml.html)，并配合 [AWS Security Token Service](https://docs.aws.amazon.com/STS/latest/APIReference/welcome.html)（AWS STS），具体取决于你的架构。

### 验证设置

完成配置后，你的知识库应显示以下详细信息：

- 状态为 **Available**
- 查询引擎已成功与 Amazon Redshift 同步
- 数据库同步状态为 **COMPLETE**

现在你可以开始使用自然语言查询数据了。

## 自然语言查询示例

现在你已设置好 Amazon Bedrock 知识库，可以开始通过对其结构化数据运行自然语言查询来测试其能力。Amazon Bedrock Knowledge Bases 结构化数据会将通俗的英语问题转换为 SQL，并使用 FM 生成人类可读的回答。

你可以通过两种方式测试你的 Amazon Bedrock 知识库：

- **Amazon Bedrock 控制台** —— 在 Amazon Bedrock 控制台中，于导航窗格选择 **Knowledge Bases**，并选择你已配置的知识库。打开 **Test** 选项卡即可与你的数据交互。
- **AWS SDK 或 API** —— 使用 AWS SDK（例如 [Python 的 Boto3](https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/bedrock-agent-runtime/client/retrieve_and_generate.html)）或直接调用 [RetrieveAndGenerate API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_RetrieveAndGenerate.html) 以编程方式发送查询。

在本节中，我们展示控制台体验。在 Amazon Bedrock 控制台中，你可以通过两种模式与 Amazon Bedrock 知识库交互：

- **Generate SQL queries** —— 该选项显示根据你的自然语言问题生成的原始 SQL 查询

![Amazon Bedrock 知识库](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/26/ML-18260-bedrock-kb.jpeg)

- **Retrieval and response generation** —— 该选项使用 LLM 提供自然语言回答
