# 使用 Amazon Bedrock Agents 创建虚拟股票技术分析师

股票技术分析的问题可以像提出问题的分析师本人一样独特。查询往往涉及多个技术指标，例如简单移动平均（SMA）、指数移动平均（EMA）、相对强弱指数（RSI）等。要回答这些各式各样的问题，意味着要编写复杂的业务逻辑，把查询拆解为各个部分并获取必要的数据。考虑到可用的指标数量、其中任一种或多种指标任意组合的可能性，以及每个指标又跨不同时间周期，把这样的业务逻辑写成代码会相当复杂。

随着 AI 技术持续演进，[生成式 AI](https://aws.amazon.com/generative-ai/) agent 的能力也在不断扩展，为你赢得竞争优势提供了更多机会。处于这一演进前沿的是 [Amazon Bedrock](https://aws.amazon.com/bedrock/)，这项完全托管的服务通过单一 API 提供来自 Amazon 及其他领先 AI 公司的高性能基础模型（FM）。借助 Amazon Bedrock，你可以以安全性、隐私保护和负责任 AI 构建并扩展生成式 AI 应用。[Amazon Bedrock Agents](https://docs.aws.amazon.com/bedrock/latest/userguide/agents.html) 使用公司系统和数据源规划并运行多步骤任务——从回答客户关于产品可用性的问题，到为他们下单。使用 Amazon Bedrock，你只需几个简单步骤就能创建 agent：先选择一个 FM，再为它提供访问企业系统、知识库和动作的权限，以便安全地执行你的 API。这些动作可以使用 [AWS Lambda](https://aws.amazon.com/lambda/) 在云端实现，也可以使用带返回控制的本地业务逻辑。agent 会分析用户请求，并自动调用必要的 API 和数据源来满足请求。Amazon Bedrock Agents 提供更强的安全性和隐私保护——你无需编写 prompt、管理会话上下文或手动编排任务。

本文中，我们使用 Amazon Bedrock Agents 创建一个虚拟分析师，它可以回答以自然语言提出的、筛选符合特定技术指标条件的股票的问题。作为 agent 的一部分，我们配置由 Lambda 函数组成的 action group，使 agent 具备执行各种动作的能力。Amazon Bedrock agent 会把用户的自然语言查询转换为相应的 Lambda 调用，传入技术指标及其所需的时间跨度。Lambda 会访问预先抓取到 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）存储桶中的开源股票数据，实时计算技术指标，并把结果回传给 agent。agent 会根据任务继续执行其他动作，例如其他 Lambda 调用，或进行过滤与排序。

## 解决方案概览

该技术分析助手解决方案使用 Amazon Bedrock Agents 回答以自然语言提出的技术分析查询，从简单的问题（例如“你能给我一份 NASDAQ 100 指数中的股票列表吗”）到复杂的问题（例如“NASDAQ 100 指数中哪些股票在过去 6 个月涨幅超过 10%，且收盘价高于其 20 日 SMA？”）。agent 利用 FM 的推理能力来编排和分析任务，并将其拆解为正确的逻辑顺序。agent 会自动调用必要的 Lambda 函数获取相关的股票技术分析数据，并在过程中判断是否可以继续，或是否需要收集更多信息。

下图展示了解决方案的架构。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/26/ML-16790_IMG1.jpg)

该工作流包含以下步骤：

- 该解决方案启动一个基于 Python 的 Lambda 函数，使用 `yfinance` 包获取过去一年的每日股票数据。该 Lambda 函数通过 [Amazon EventBridge](https://aws.amazon.com/eventbridge/) 每天触发运行，把最近 1 年的股票数据放入一个 S3 存储桶。
- 用户提出自然语言查询，例如“你能给我一份 NASDAQ 100 指数中的股票列表吗”，或“FTSE 100 指数中哪些股票的收盘价同时高于 20 SMA 和 50 EMA？”
- 该查询被传给由 Anthropic 的 Claude 3 Sonnet 驱动的 Amazon Bedrock agent。agent 解构用户查询、制定行动计划，并逐步执行以获取回答问题所需的各种数据。为获取所需数据，agent 有三个 action group，每个都由一个 Lambda 函数驱动，该函数可以使用存储在 S3 存储桶中的原始数据计算技术指标和其他与股票相关的信息。根据 action group 的响应和 agent 的行动计划，agent 会继续发起调用或执行其他动作，例如过滤或汇总，直到得出问题的答案。这些 action group 如下：  **get-index** – 获取给定指数成分股的股票代码。本示例目前配置了 Nasdaq 100、FTSE 100 和 Nifty 50 指数的成分股。  **get-stock-change** – 针对给定股票或股票列表，基于 Amazon S3 中预先抓取的原始数据，计算其在给定周期内的变化百分比。该解决方案目前配置为包含过去 1 年的数据。  **get-technical-analysis** – 针对给定股票或股票列表，计算其在给定时间周期内的指定技术指标。它还会基于 Amazon S3 中预先抓取的原始数据获取该股票的最新收盘价。该解决方案目前配置为处理最长 1 年的 SMA、EMA 和 RSI 技术指标。

## 先决条件

要设置该解决方案，你需要具备 AWS 及相关 AWS 服务的基础知识。此外，请为 Anthropic 的 Claude 3 Sonnet [在 Amazon Bedrock 上申请模型访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)。

该 CloudFormation 堆栈会创建解决方案概览中描述的解决方案，以及以下关键资源：

- **StockDataS3Bucket** – 用于存储 1 年股票数据的 S3 存储桶。
- **YfinDailyLambda** – 一个 Python Lambda 函数，使用 `yfinance` 包从 Yahoo Finance 获取 Nasdaq 100、FTSE 100 和 Nifty 50 指数最近 1 年的股票数据：

```
# Example call to Yahoo finance to get stock history
import yfinance as yf
stock_ticker = yf.Ticker(<Stock Symbol>)
stock_history = stock_ticker.history(period= <Time duration to fetch history e.g. 1y>))
```

- **YfinDailyLambdaScheduleRule** – 一条 EventBridge 规则，每天触发 `YfinDailyLambda` 函数以获取最新股票数据。
- **InvokeYfinDailyLambda 和 InvokeLambdaFunction** – 一个自定义 CloudFormation 资源及其 Lambda 函数，用于在堆栈创建过程中调用 `YfinDailyLambda` 函数以获取初始数据。
- **GetIndexLambda** – 该函数接收指数名称作为输入，返回给定指数中的股票列表。
- **GetStockChangeLambda** – 该函数接收股票列表和天数作为输入，从 S3 存储桶获取股票数据，计算这些股票在该周期内的变化百分比，并返回数据。
- **GetStockTechAnalysisLambda** – 该函数接收股票列表、天数和某个技术指标作为输入，返回给定股票列表的最新收盘价以及在该天数周期内的技术指标。例如：

```
# Sample code to calculate Simple Moving Average,  a technical indicator
from ta.trend import SMAIndicator
indicator_ta = SMAIndicator(<PAndas series with Close price>, window=<SMA window number of days>)
stock_SMA = indicator_ta.sma_indicator()
```

- **StockBotAgent** – 使用 Anthropic 的 Claude 3 Sonnet 模型创建的 Amazon Bedrock agent，带有三个 action group，每个都映射到一个 Lambda 函数。我们用自然语言给 agent 下达指令。在我们的解决方案中，指令的一部分是“你可以获取给定指数中的股票列表”，这样 agent 就知道它可以获取某个指数中的股票。我们在 agent 中配置 action group，并使用 OpenAPI 3 schema 标准来描述 Lambda 的功能，使 agent 理解何时以及如何调用这些 Lambda 函数。以下是 get-index action group 的 OpenAPI schema 片段，其中描述了它的功能、输入输出参数和格式：

```

"info": {
"title": "Get Index list of stocks api",
"version": "1.0.0",
"description": "API to fetch the list of stocks in a given index"
},

"paths": {
"/get-index": {
"get": {
"summary": "Get list of stock symbols in index",
"description": "Based on provided index, return list of stock symbols in the index",
"operationId": "getIndex",
"parameters": [
{
"name": "indexName",
"in": "path",
"description": "Index Name",
"required": true,
"schema": {
"type": "string"
}
}
],

"responses": {
"200": {
"description": "Get Index stock list",
"content": {
"application/json": {
"schema": {
"type": "array",
```

## 以编程方式调用 agent

当你对 agent 的表现满意后，可以构建一个应用，使用 [InvokeAgent](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_InvokeAgent.html) API 以编程方式调用该 agent。以编程方式调用 agent 别名所需的 agent ID 和 agent 别名 ID，可以在 CloudFormation 堆栈的 **Outputs ** 选项卡上找到，分别名为 `AgentId` 和 `AgentAliasId`。要了解有关以编程方式调用的更多信息，请参阅以下 [Python 示例](https://github.com/awsdocs/aws-doc-sdk-examples/tree/main/python/example_code/bedrock-agent-runtime#code-examples)和 [JavaScript 示例](https://github.com/awsdocs/aws-doc-sdk-examples/tree/main/javascriptv3/example_code/bedrock-agent-runtime#code-examples)。
