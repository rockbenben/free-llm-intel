# 在 AWS 上推出 Visa Intelligent Commerce：用 Amazon Bedrock AgentCore 实现 agentic commerce

*本文由 Visa 的 Sangeetha Bharath 与 Seemal Zaman 共同撰写。*

在每一个行业，[agentic AI](https://aws.amazon.com/what-is/agentic-ai/) 都在重新定义工作的完成方式：它把数字体验从人工的、由用户驱动的交互，转变为自主的、以结果为导向的工作流。与传统 AI 系统只是回答问题或提供建议不同，agentic AI 引入了具备推理、行动、与其他 agent 协作，并能代表用户完成多步任务的智能 agent。这一转变已经在旅行、医疗、银行、物流和客户服务等行业引发变革——在这些领域，agent 能够以最少的人工干预完成调研、规划、优化并执行端到端流程。

支付行业也正经历一场重大变革，因为 agentic commerce 正在改变消费者和企业发起、授权和完成交易的方式。自主 agent 不再需要在多个应用和网站之间手动操作，而是可以在后台协调商品发现、决策与安全支付。这一变化与 2000 年代初向电子商务的转变如出一辙，当时数字结账重塑了客户的期待。今天，agentic commerce 正在奠定类似的基础，让支付更加无缝、更具上下文感知、更智能。构建 agent 的开发者需要相应的赋能与支持，才能让这一切真正安全、规模化地运转。直到不久之前，即便是先进的 AI agent 也只能协助规划、比较选项和准备购物车，要完成购买，消费者仍得拿出信用卡或借记卡，自己走完结账流程。如果没有与现有支付网络之间可信、标准化且合规的集成，agent 无法可靠、安全地端到端发起交易。

为支持这一转变，[Amazon Web Services](https://aws.amazon.com/)（AWS）与 [Visa](https://visa.com) 携手合作，帮助同时服务消费者与企业对企业（B2B）客户的企业，为新的 agentic commerce 世界做好准备。2025 年 4 月，Visa 面向开发者（甚至非开发者）推出了 [Visa Intelligent Commerce](https://corporate.visa.com/en/products/intelligent-commerce.html)，让他们把 agentic 支付应用直接连接到 Visa 的支付网络，并通过直白的自然语言指令触发交易。这一倡议与产品还提供[支持](https://developer.cas.visaacceptance.com/products/intelligent_commerce.html)，用于构建与网络无关（network-agnostic）的 agentic commerce 流程，并借助 Visa 的 [Trusted Agent Protocol](https://developer.visa.com/capabilities/trusted-agent-protocol/overview) 实现 agent 与商户之间的安全通信。

作为与 AWS 合作的一部分，Visa 计划使用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 托管 [Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro)（MCP）工具，使合作伙伴可以在该平台上构建端到端、与网络无关的 agentic 工作流。

目标很明确：为构建下一代智能商业解决方案提供安全、可扩展的基础。

## 在 AWS 上推出 Visa Intelligent Commerce

Visa Intelligent Commerce 让企业和开发者能够构建下一代的 agentic 支付体验。在 [AWS Marketplace](https://aws.amazon.com/marketplace/pp/prodview-sh3l33k56yguq?sr=0-1&ref_=beagle&applicationId=AWSMPContessa) 中，开发者可以了解 Visa 的一整套核心 agentic commerce 工具，包括身份验证、agentic tokenization 与用户意图捕获，这些工具旨在实现自主、安全且具上下文感知的支付流程。Visa 与 AWS 通过 Amazon Bedrock [AgentCore 示例](https://github.com/awslabs/amazon-bedrock-agentcore-samples) 仓库提供的 blueprint，是为与 Visa 的 MCP server 和 agentic API 集成而设计的，支持安全、token 化的交易；对多网络 agentic commerce 流程的额外支持也即将推出。通过这一倡议，Visa 与 AWS 让把支付融入 agentic 工作流变得更简单、更易实现。

## Amazon Bedrock AgentCore 如何支撑这些方案

在深入具体用例之前，有必要理解 Amazon Bedrock AgentCore 作为支撑这些 agentic commerce 体验的基础设施所扮演的角色。Bedrock AgentCore 并不只是又一个组件——它是让生产级多 agent 系统成为可能的安全、可扩展的骨干。

Amazon Bedrock AgentCore 带来的价值：

- 该方案的核心是 [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html)，一个专为 AI agent 与 MCP server 打造的安全、无服务器托管环境。每个 agent 都运行在隔离的微型虚拟机（VM）沙箱中，因此旅行行程、支付凭证和个人可识别信息（PII）等敏感数据在整个工作流中始终受到保护。Bedrock AgentCore Runtime 可自动扩展以承载数千名并发用户，无需手动做容量规划，既能从容应对节假日峰值流量，也能处理淡季的查询。与典型的请求-响应式 API 不同，它支持长会话时长和大上下文负载，使 agent 能够在多日行程规划或复杂的比价购物会话中保持上下文。
- 支撑 Bedrock AgentCore Runtime 的是 [Amazon Bedrock AgentCore Identity](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity.html)，它提供入站身份验证（在本方案中使用 [AWS Amplify](https://aws.amazon.com/amplify/)）以实现用户登录，并提供出站身份验证，以安全访问在线旅行社（OTA）或零售 MCP server 等端点，以及 Visa Intelligent Commerce MCP，使用户身份、同意状态和已授权的支付凭证能够在工作流中安全传递，而不暴露敏感信息。
- 通过 [Amazon Bedrock AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html)，agent 可以以受治理、可审计的方式访问工具与 MCP server，涵盖航班与酒店搜索、商品搜索，以及用于支付、同意与卡片生命周期操作的 Visa Intelligent Commerce MCP。Amazon Bedrock AgentCore Gateway 处理 agent 的工具请求，并使工具调用满足受监管支付流程所要求的可信访问控制。
- [Amazon Bedrock AgentCore Memory ](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html)在旅行规划、商品研究和结账等长时间、多步骤的旅程中维持长期上下文。这使 agent 能够更有效地推理并记住复杂数据——例如多城市行程、酒店套餐、天气洞察或商户优惠——且不影响性能。当前实现使用 Bedrock AgentCore 短期记忆来维持对话上下文与会话状态，同时也支持跨 agent 的安全、可控的上下文共享。未来的更新将纳入长期记忆能力，用于提取用户偏好并生成会话摘要。
- 为满足监管与合规要求，[Amazon Bedrock AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html) 基于 OpenTelemetry（OTEL）构建，通过捕获每一次 agent 操作的完整、可用于审计的记录——包括推理轨迹、单个 span、工具调用、MCP server 调用、身份验证流程和延迟指标——为整个工作流中的 agent 运行提供完全透明的可见性。用户可以在 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) [生成式 AI 可观测性](https://aws.amazon.com/cloudwatch/features/generative-ai-observability/) 仪表板中查看这些操作。

## 可复用的 supervisor 架构

这些示例展示的一个关键架构优势是可复用的 supervisor 模式。该模式采用「agents as tools」范式，即把 subagent 作为可供 supervisor 调用的工具暴露出来。旅行预订与购物助手两个方案共享同一套 supervisor agent 设计，它作为中央编排者协调用户交互。这个共享 supervisor 的工作方式如下：

- 根据用户意图把请求路由到相应的专用 agent
- 通过 [Strands AgentCore Memory Session Manager](https://strandsagents.com/latest/documentation/docs/community/session-managers/agentcore-memory/) 使用 Amazon Bedrock AgentCore Memory 维持对话上下文，跨会话保留状态
- 格式化并呈现 subagent 返回给用户的响应
- 以具备完整上下文感知的方式处理多轮对话

这意味着你可以为旅行和购物两类用例——乃至任何其他 agentic commerce 场景——部署同一套 supervisor 基础设施，只需替换专用的 subagent（并按需更新 system prompt）即可。supervisor 的编排逻辑、记忆管理与对话处理保持一致。这一点很重要，因为这种模块化做法能降低开发开销。开发者不必为每个用例单独构建编排系统，而是可以：

- 在多个领域复用同一个 supervisor agent
- 在不修改核心编排逻辑的前提下新增专用 agent（例如保险、租车或日用杂货）
- 在不同商业场景中维持一致的用户体验模式
- 在部署中复用同一套 Amazon Bedrock AgentCore 基础设施（例如 Runtime、Memory、Identity、Gateway 或 Observability）

本文包含两个使用 Visa Intelligent Commerce 的多 agent 示例：

- 旅行预订 agent
- 购物助手 agent

## 第一部分：用 Amazon Bedrock AgentCore 与 Visa 重塑旅行预订体验

旅行者面临割裂的行程规划体验：为规划一次旅行，他们要在航空公司网站、OTA、酒店平台、常旅客门户、评测渠道和支付页面之间来回跳转。价格每分钟都在波动，会员计划条款复杂，个性化程度参差不齐；即便研究数小时，也无法保证找到了最优选项，或把信用卡权益的价值用足。

为应对这些挑战，我们使用 Amazon Bedrock AgentCore、[Strands Agents](https://strandsagents.com/latest/) 和 Visa Intelligent Commerce 构建了一套旅行预订多 agent 系统，能够代表用户规划、优化并预订端到端的旅行体验，同时具备治理与安全保障。它把商品发现、个性化与安全支付整合到一个由自然语言驱动的无缝统一工作流中。

Amazon Bedrock AgentCore 提供专为编排多 agent 系统而打造的安全、无服务器运行时，适配长时间运行的会话、大上下文负载以及受治理的工具访问。其内置的隔离、身份、可观测性与 MCP 集成，使其非常适合在生产规模下处理敏感的旅行与支付交互。

借助 Visa Intelligent Commerce，用户可以对自身意图进行批准或确认，从而让构建行程的同一套多 agent 系统获得授权以预订并执行支付，创造无缝且高度个性化的旅行商业体验，远远超越传统的旅行调研类 agent。

旅行 agent blueprint 由三个专用 agent 协同工作，提供全面的旅行规划：

- **Supervisor** – 协调各交互的主 agentic 编排者
- **Travel assistant** – 负责旅行规划、预订与目的地信息
- **Cart manager** – 管理购物车、支付与购买流程

supervisor 充当整个体验的中央编排者。它编排对话、把任务分派给专用 agent，并管理用户的行程。supervisor agent 运行在 Amazon Bedrock AgentCore Runtime 上，通过 AgentCore Memory 跨会话维持对话上下文，使其即便在长时间跨度的规划会话中也能记住用户偏好、进行中的行程和此前的决策。核心能力包括：

- 把用户请求路由到相应的专用 agent
- 使用 AgentCore Memory 跨会话维持对话上下文与记忆
- 格式化并呈现 subagent 的响应给用户
- 以具备上下文感知的方式处理多轮对话
- 支持航班、酒店、活动、餐厅和交通等多种条目类型

旅行助手专注于旅行相关查询，包括目的地调研、天气信息、航班与酒店搜索，以及通过 Amazon Bedrock AgentCore Gateway 使用 OTA MCP 工具给出的本地推荐。它会比较报价、组装行程、管理变更，并使航段、酒店、活动等行程要素与用户偏好和约束条件相匹配。尽管这些 OTA 工具并非原生支持 MCP server，我们仍可使用 Amazon Bedrock AgentCore Runtime 托管它们，并通过 AgentCore Gateway 以兼容 MCP 的工具形式暴露给 agent。

工具：

- **天气信息** – `get_weather(query)`
- **互联网搜索** – `search_tool(query)`
- **本地地点搜索** – `google_places_tool(query)`
- **航班搜索** – `get_flight_offers_tool(origin, destination, departure_date, adults, max_price, currency)`
- **酒店搜索** – `get_hotel_data_tool(city_code, ratings, amenities, max_price)`
- **日期更新** – `update_itinerary_date(user_id, identifier, item_type, new_date)`

购物车管理器负责购物车操作、支付处理与购买流程。正是在这里，Amazon Bedrock AgentCore 的安全能力变得至关重要。Bedrock AgentCore Identity 管理与 Visa Intelligent Commerce 之间的安全移交，使用户身份、同意状态和 token 化凭证能够在支付授权过程中顺畅流转，而不暴露敏感数据。Bedrock AgentCore Runtime 的隔离执行在受保护的沙箱中运行支付操作，Bedrock AgentCore Observability 则捕获完整的交易流程，以满足监管合规与审计要求。

在继续执行支付之前，agent 会请求人工确认：用户设定明确的参数，并允许 agent 代表其消费。`request_purchase_confirmation` 工具首先捕获用户的显式授权，随后在授权到手之后由 `confirm_purchase` 工具完成交易。接着 agent 使用 Visa Intelligent Commerce API 请求支付凭证、触发身份验证，并安全地完成购买。这一 human-in-the-loop 环节意味着用户在享受 agentic 自动化的同时仍保留控制权。

工具：

- **查看购物车** – `get_cart(user_id)`
- **向购物车添加条目** – `add_to_cart(user_id, items)`
- **移除条目** – `remove_from_cart(user_id, identifiers, item_type)`
- **支付卡管理** – `onboard_card(user_id, card_number, expiration_date, cvv, card_type, is_primary), request_purchase_confirmation, confirm_purchase`

## 第二部分：由 Amazon Bedrock AgentCore 与 Visa 驱动的 agentic commerce 购物未来

网上门户、购物应用、会员计划和结账流程如此之多，彼此争夺注意力，购物者买一件商品也必须在复杂的迷宫中穿行。收到促销优惠时，商品链接会把你带到另一个站点；会员积分藏在又一个门户里；结账时还要在多个商户重复输入相同的卡片信息。价格不断变动，库存按小时变化；即便把所有选项都手动比较一遍，购物者仍然不确定自己是否拿到了最优价格、最快配送，或把奖励价值用到了最大。

借助由 Amazon Bedrock AgentCore 驱动并与 Visa Intelligent Commerce 集成的多 agent 购物助手，购物变得顺畅，因为工作从购物者转移到了 agent 身上。用户不必再在标签页之间来回切换、逐一比价，只需说一句类似：*“帮我找 Sony PlayStation 5 Pro 的最优优惠，跨商户比较黑色星期五促销，查看送达日期，并用上我的奖励。我的预算在 $500 以内。”* 在幕后，一支协同的 agent 团队会在各个商户站点和门户中搜索该商品，检查并比较包括促销在内的价格，核对配送时效并应用会员权益。

集成 Visa Intelligent Commerce 之后，购物助手可以验证用户身份、取回与该次具体请求绑定的 token 化凭证，并在用户无需访问任何结账页面的情况下完成购买。整个购物流程——从调研、比较、优化到支付——都自主进行，用户只需用自然语言引导过程，而不用手动点击。购物助手 agent blueprint 由三个专用 agent 协同工作，提供全面的购物规划：

- **Supervisor **– 协调各交互的主编排者
- **Shopping **– 负责商品搜索与推荐
- **Cart manager** – 管理购物车、支付与购买流程

如前文所述，我们在旅行助手与购物助手两个方案中都采用了可复用的 supervisor agent 架构。在多 agent 购物助手用例中，supervisor agent 充当整个体验的中央编排者。它编排对话、把任务分派给专用 agent，并管理用户的行程。supervisor agent 运行在 Amazon Bedrock AgentCore Runtime 上，通过 Bedrock AgentCore Memory 跨会话维持对话上下文，使其即便在长时间跨度的规划会话中也能记住用户偏好、进行中的行程和此前的决策。

核心能力包括：

- 把用户请求路由到相应的专用 agent
- 使用 Bedrock AgentCore Memory 跨会话维持对话上下文与记忆
- 格式化并呈现 sub-agent 的响应给用户
- 以具备上下文感知的方式处理多轮对话

购物助手专注于商品发现、推荐和打包清单生成。它使用 Amazon Bedrock AgentCore Gateway 连接零售 MCP server 进行商品搜索，同时为每次查询保留审计轨迹。Bedrock AgentCore Memory 在整个购物旅程中保存购物上下文——记住预算约束、偏好品牌以及已考虑过的商品。

工具：

- **商品搜索** – `single_productsearch(user_id, question)`
- **打包清单生成** – `generate_packinglist(user_id, question)`

购物车管理器负责购物车操作、支付处理与购买流程。正是在这里，Amazon Bedrock AgentCore 的安全能力变得至关重要。Bedrock AgentCore Identity 管理与 Visa Intelligent Commerce 之间的安全移交，使用户身份、同意状态和 token 化凭证能够在支付授权过程中顺畅流转，而不暴露敏感数据。Bedrock AgentCore Runtime 的隔离执行在受保护的沙箱中运行支付操作，Bedrock AgentCore Observability 则捕获交易流程以及与 Amazon Bedrock AgentCore Runtime、Bedrock AgentCore Memory 和 Bedrock AgentCore Gateway 之间的交互，以满足监管合规与审计要求。

## 结论
