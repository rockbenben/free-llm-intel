# 使用 Amazon Bedrock Data Automation 实现可扩展的智能文档处理

智能文档处理（IDP）是一种自动从各类文档中抽取、分析与解读关键信息的技术。通过使用先进的机器学习（ML）与自然语言处理算法，IDP 解决方案能够高效地从非结构化文本中抽取并处理结构化数据，从而精简以文档为中心的工作流。

在增强生成式 AI 能力之后，IDP 使组织能够通过更深入的理解、结构化数据抽取与自动分类来改造文档工作流。由生成式 AI 驱动的 IDP 解决方案能够更好地处理传统 ML 模型此前可能从未见过的各类文档。这种技术组合在子女抚养服务、保险、医疗健康、金融服务与公共部门等多个行业都能产生实际影响。传统人工处理会造成瓶颈并增加出错风险，而通过实施这些先进解决方案，组织可以大幅提升其文档工作流效率与信息检索能力。AI 增强的 IDP 解决方案在改善服务交付的同时，也减轻了各种文档处理场景下的行政负担。

这种文档处理方式提供可扩展、高效且高价值的文档处理能力，从而提升生产力、降低成本并改善决策。拥抱生成式 AI 增强的 IDP 能力的企业，可以从效率提升、客户体验改善与增长加速中获益。

在[《使用 Amazon Bedrock 实现可扩展的智能文档处理》](https://aws.amazon.com/blogs/machine-learning/scalable-intelligent-document-processing-using-amazon-bedrock/)这篇博客文章中，我们演示了如何在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上使用 Anthropic 的基座模型构建可扩展的 IDP pipeline。尽管该方法表现稳健，但 [Amazon Bedrock Data Automation](https://aws.amazon.com/bedrock/bda/) 的推出为 IDP 解决方案带来了新的效率与灵活性水平。本文探讨 Amazon Bedrock Data Automation 如何增强文档处理能力并简化自动化之旅。

## Amazon Bedrock Data Automation 的优势

Amazon Bedrock Data Automation 引入了若干功能，可显著提升 IDP 解决方案的可扩展性与准确性：

- **置信度得分与边界框数据 – **Amazon Bedrock Data Automation 提供置信度得分与边界框数据，增强了数据的可解释性与透明度。借助这些功能，你可以评估抽取信息的可靠性，从而做出更明智的决策。例如，较低的置信度得分可以提示需要对特定数据字段进行额外的人工复核或核验。
- **用于快速开发的 Blueprint **– Amazon Bedrock Data Automation 提供预构建的 blueprint，简化文档处理 pipeline 的创建，帮助你快速开发并部署解决方案。Amazon Bedrock Data Automation 提供灵活的输出配置，以满足多样的文档处理需求。对于简单的抽取用例（OCR 与版面），或需要把文档中的文本线性化输出时，你可以使用标准输出。若需要定制输出，你可以从零开始设计专属的抽取 schema，或把我们目录中的预配置 blueprint 作为起点。你可以根据具体的文档类型与业务需求自定义 blueprint，以实现更有针对性、更准确的信息检索。
- **自动分类支持 – **Amazon Bedrock Data Automation 把文档拆分并匹配到合适的 blueprint，从而实现精确的文档归类。这种智能路由免去了人工分拣文档的需要，大幅减少人工干预并缩短处理时间。
- **归一化 **– Amazon Bedrock Data Automation 通过其全面的归一化框架解决了 IDP 的一个常见难题，该框架同时处理 key 归一化（把各种字段标签映射到标准名称）与 value 归一化（把抽取数据转换为一致的格式、单位与数据类型）。这种归一化方法有助于降低数据处理的复杂度，使组织能够自动把文档的原始抽取结果转换为标准化数据，从而更顺畅地与其现有系统和工作流集成。
- **转换（Transformation）** – Amazon Bedrock Data Automation 的转换功能把复杂的文档字段转换为结构化、可直接用于业务的数据，其方式是自动把组合信息（例如地址或姓名）拆分为离散且有意义的组成部分。该能力简化了组织处理各种文档格式的方式，帮助团队定义与其现有数据库 schema 和业务应用相匹配的自定义数据类型与字段关系。
- **校验（Validation）** – Amazon Bedrock Data Automation 通过对抽取数据使用自动校验规则来提升文档处理的准确性，支持数值范围、日期格式、字符串模式与跨字段检查。该校验框架帮助组织自动识别数据质量问题、在需要时触发人工复核，并确保抽取的信息在下游系统使用之前满足特定的业务规则与合规要求。

## 解决方案概述

下图展示了一个完全无服务器的架构，它使用 Amazon Bedrock Data Automation 以及 [AWS Step Functions](https://aws.amazon.com/step-functions/) 与 [Amazon Augmented AI](https://aws.amazon.com/augmented-ai/)（Amazon A2I），为不同规模的文档处理工作负载提供高性价比的扩展能力。

![展示使用 Amazon Bedrock Data Automation 与人在回路（human-in-the-loop）进行文档处理的 AWS 架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/31/ML-17996-arch-diag.jpeg)

该 Step Functions 工作流使用 Amazon Bedrock Data Automation 处理多种文档类型，包括多页 PDF 与图像。它在同一个项目中使用多种 Amazon Bedrock Data Automation blueprint（标准与自定义），从而能够处理免疫记录、契税证明、子女抚养服务登记表与驾驶证等各类文档。

该工作流按以下步骤处理包含单个或多个文档的文件（PDF、JPG、PNG、TIFF、DOC、DOCX）：

- 对于多页文档，沿逻辑文档边界进行拆分
- 把每个文档匹配到合适的 blueprint
- 应用该 blueprint 的具体抽取指令，从每个文档中检索信息
- 按照 blueprint 中指定的指令对抽取数据执行归一化、转换与校验

Step Functions 的 [Map state](https://docs.aws.amazon.com/step-functions/latest/dg/state-map.html) 用于处理每个文档。如果文档达到置信度阈值，输出会被发送到 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）存储桶。如果有任何抽取数据的置信度低于阈值，该文档会被送往 Amazon A2I 进行人工复核。复核者使用带边界框高亮的 Amazon A2I UI 对选定字段进行核验，以确认抽取结果。人工复核完成后，使用[回调任务令牌](https://docs.aws.amazon.com/step-functions/latest/dg/connect-to-resource.html#connect-wait-token)恢复状态机，并把人工复核后的输出发送到 S3 存储桶。

要在 [AWS 账户](https://signin.aws.amazon.com/signup?request_type=builderId)中部署该解决方案，请按照配套 [GitHub 仓库](https://github.com/aws-samples/sample-scalable-intelligent-document-processing-with-amazon-bedrock-data-automation/blob/main/README.md)中提供的步骤操作。

在接下来的章节中，我们以一份子女抚养登记表为例，回顾该解决方案所部署的具体 Amazon Bedrock Data Automation 功能。

## 数据归一化

我们使用数据归一化来确保下游系统收到的数据格式统一。我们同时使用显式抽取（针对文档中明确可见的信息）与隐式抽取（针对需要转换的信息）。例如，如下方截图所示，出生日期被标准化为 YYYY-MM-DD 格式。

![Bedrock Data Automation 界面，展示已抽取并归一化的出生日期数据](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/31/ML-17996-bda-extraction.jpeg)

同样，社会保障号码（Social Security Number）的格式会被改为 XXX-XX-XXXX。

## 数据转换

针对子女抚养登记申请，我们实现了自定义数据转换，使抽取数据符合特定要求。其中一个例子是我们为地址定义的自定义数据类型，它把单行地址拆解为结构化字段（Street、City、State、ZipCode）。这些结构化字段在登记表的不同地址字段中复用（雇主地址、家庭地址、另一位家长的地址），从而实现一致的格式，并与现有系统直接集成。

![Amazon Bedrock Data Automation 界面，展示带显式字段映射的自定义地址类型配置](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/31/ML-17996-bda-custom-field.jpeg)

## 结论

Amazon Bedrock Data Automation 通过引入置信度评分、边界框数据、自动分类以及借助 blueprint 的快速开发，显著推进了 IDP 的发展。在本文中，我们演示了如何利用其在数据归一化、转换与校验方面的进阶能力。通过升级到 Amazon Bedrock Data Automation，组织可以显著缩短开发时间、提升数据质量，并构建更稳健、可扩展且能与人工复核流程集成的 IDP 解决方案。
