# PerformLine 如何在 Amazon Bedrock 上运用 prompt engineering 检测合规违规

*本文与 PerformLine 的 Bogdan Arsenie 和 Nick Mattei 合写。*

[PerformLine](https://performline.com/?utm_source=adwords&utm_campaign=Brand_Retargeting&utm_medium=ppc&utm_term=performline&hsa_kw=performline&hsa_mt=e&hsa_tgt=kwd-625842813327&hsa_src=g&hsa_ad=581606402854&hsa_ver=3&hsa_cam=12044521576&hsa_net=adwords&hsa_acc=4720098273&hsa_grp=115417481479&gad_source=1&gbraid=0AAAAADuacYpOCH1ObtZo44RbYAxGXZabO&gclid=Cj0KCQjwkZm_BhDrARIsAAEbX1FMy8jI74mrIcqjkhYuQFTtWfiKhhcOsUHIvj7AE1m0cf_yvoUbjqUaAjccEALw_wcB) 的业务属于营销合规（marketing compliance）行业，这是更广泛的合规软件市场中的一个细分领域，后者还包括反洗钱（AML）、了解你的客户（KYC）等各种合规解决方案。具体而言，营销合规指的是遵循政府机构制定的法规与指引，确保公司的营销、广告和销售内容及沟通对消费者而言真实、准确、不具误导性。PerformLine 是在营销、销售和合作伙伴渠道上提供全面合规监督的领先服务商。作为营销合规行业的先驱，PerformLine 在过去 10 多年中完成了超过 11 亿次合规观察，把整个合规流程自动化——从材料的发布前审核，到对网站、电子邮件和社交媒体等面向消费者的渠道进行持续监控。PerformLine 受到消费金融品牌和全球组织的信赖，以 AI 驱动的解决方案保护品牌及其消费者，把合规工作转化为竞争优势。

**“Discover. Monitor. Act.** 这不仅仅是我们的口号——它是我们在 PerformLine 创新的根基，”PerformLine 的 CTO Bogdan Arsenie 表示。PerformLine 的工程团队通过开发 AI 驱动的技术解决方案，让这些原则落地。本文中，PerformLine 与 AWS 一起探讨 PerformLine 如何利用 Amazon Bedrock 加速合规流程、生成可执行的洞察并提供上下文数据——交付大规模监督所必需的速度与准确性。

## **问题**

PerformLine 的一家大型企业客户需要更高效的流程，对刚上线的产品页面执行合规检查，尤其是那些在同一视觉与文本框架内整合了多个产品的页面。这类复杂页面往往包含重叠的内容，同一段内容可能适用于一个产品、多个产品，甚至同时适用于全部产品，因此需要一种具备上下文感知能力的解读方式，模仿普通消费者查看并与内容交互的方式。通过采用 AWS 以及本文讨论的架构，PerformLine 能够借助 AI 驱动的处理来获取并分析这些错综复杂的页面，生成细致的洞察与上下文数据，捕捉各产品元素之间微妙的相互作用。相关信息被提取并结构化之后，会直接送入他们的规则引擎，从而实现稳健的合规检查。这构成了从数据摄取到基于规则的分析的无缝流程。它既保留了每个产品呈现方式的深度，又交付了大规模监督所必需的速度与准确性。每天为上百万网页做合规监控，要求系统能够大规模地智能解析、提取和分析内容——这与 PerformLine 为其企业客户开发的方式十分相似。在这样一个动态的环境里，网页内容不断演变，对传统的静态解析构成挑战，因此需要上下文感知且具备适应性的解决方案。该架构不仅能离线处理批量数据，还能为一次性请求提供接近实时的性能，并动态伸缩以应对每个页面各不相同的复杂度。通过使用 AI 驱动的推理，PerformLine 能够为网上的每个产品和营销元素提供全面覆盖，同时在准确性、性能与成本之间取得谨慎的平衡。

## **解决方案概览**

凭借这一灵活、可适应的解决方案，PerformLine 能够处理即使最具挑战性的网页，在提取和分析包含多个产品的内容时提供全面覆盖。同时，通过把一致性与基础模型（FM）的适应性结合起来，PerformLine 可以在客户所监控的各类产品和网站上保持可靠的性能。这种对敏捷性与运营一致性的双重关注，确保客户既能获得稳健的合规检查与数据完整性，又不必牺牲保持竞争力所需的速度或规模。

PerformLine 的上游摄取 pipeline 以批处理方式高效收集数百万个网页及其相关元数据。下游资产会被提交到 PerformLine 的规则引擎和合规审查流程。必须确保不打断这些流程，也不为这套解决方案引入连锁变更。

PerformLine 决定使用生成式 AI 和[ Amazon Bedrock](https://aws.amazon.com/bedrock/?refid=cr_card) 来应对他们的核心挑战。Amazon Bedrock 提供了广泛的模型选择，包括 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/)。Amazon Bedrock 围绕大规模使用 FM 持续扩展功能集。这为构建高可用、高效率的内容处理系统提供了可靠的基础。

PerformLine 的解决方案包含以下关键组件：

- **使用 Amazon Bedrock 进行 AI 推理 –** 为内容提取和分析提供对 FM 的无缝访问
- [**应用程序推理配置文件**](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-create.html)** –** 可精确追踪并优化推理成本
- **事件驱动的无服务器处理 pipeline –**通过 [Amazon EventBridge](https://aws.amazon.com/eventbridge/)、[Amazon Simple Queue Service](https://aws.amazon.com/sqs/)（Amazon SQS）、[AWS Lambda](https://aws.amazon.com/lambda/)、[Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）和 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/)，提供轻量、可扩展的方式来处理动态负载。
- [**Bedrock 中的 prompt 管理**](https://aws.amazon.com/bedrock/prompt-management/)** – **支持 prompt 的版本管理、测试和部署，以提升 AI 的一致性与可控性
- **任务编排 –** 使用 Amazon SQS 高效管理工作队列，促成顺畅且可扩展的任务执行

PerformLine 实现了一套可扩展、无服务器、事件驱动的架构（如下图所示），它能与现有系统无缝集成，开发与部署耗时不到一天。这使得团队可以把精力放在 prompt 优化、评估和成本管理上，而非基础设施开销。该架构让 PerformLine 能够以高可靠性、灵活性和成本效益动态解析、提取和分析网页内容。

系统实现了多种队列类型（Incoming、DLQ、Results），并包含错误处理机制。数据流经多种 AWS 服务，包括：Amazon RDS 用于初始数据存储，Amazon MQ RabbitMQ 用于消息处理，Amazon S3 用于资产存储，Amazon EventBridge 用于事件管理，Amazon SQS 用于队列管理，AWS Lambda 用于无服务器处理，Amazon DynamoDB 用于 NoSQL 数据存储。

PerformLine 的流程由若干步骤组成，包括处理（第 1 步）、事件触发与存储（第 2–6 步）、结构化输出与存储（第 7 步），以及下游处理与合规检查（第 8–9 步）：

- 数百万个页面由来自 PerformLine 运行在 AWS Cloud 上的核心系统的上游提取、转换和加载（ETL）流程处理。
- 当一个页面被获取时，会在合规检查系统中触发一个事件。
- Amazon S3 按照元数据存储来自某个页面的数据。
- EventBridge 使用事件驱动的处理，把 Amazon S3 事件路由到 Amazon SQS。
- Amazon SQS 将消息排队等待处理，并在失败时支持消息重试。
- 一个 Lambda 函数消费 SQS 消息，并动态伸缩以应对甚至不可预测的负载：该函数使用 Amazon Bedrock 对来自 Amazon SQS 的内容执行提取和生成式 AI 分析。Amazon Bedrock 在挑选合适模型方面提供了最大的灵活性。对于 PerformLine 的用例，Amazon 的 Nova Pro 最适合复杂请求——这类请求需要强大的模型，同时仍能保持较高的性能成本比。Anthropic 的 Claude Haiku 模型则支持经过优化的快速调用，在需要后续处理时，快速响应至关重要。Amazon Bedrock 的功能，包括 [Amazon Bedrock Prompt Management](https://aws.amazon.com/es/bedrock/prompt-management/) 和[推理配置文件](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles.html)，被用来提高输入代码的多样性而不影响输出，并降低通过 Amazon Bedrock 使用 FM 的复杂度。[该函数把客户定义的产品 schema 存储在 Amazon DynamoDB 中](https://aws.amazon.com/dynamodb/)，从而实现动态的大语言模型（LLM）定位与 schema 驱动的输出生成。
- Amazon S3 存储提取出的数据，这些数据会被格式化为符合目标 schema 的结构化 JSON。
- EventBridge 把 Amazon S3 事件转发到 Amazon SQS，使提取出的数据可供下游处理使用。
- 运行在 PerformLine 其他系统上的合规检查与业务规则会被应用，以验证并强制执行监管要求。

## **成本优化**

该解决方案提供了多项成本优化，包括网页上的变更数据捕获（CDC）以及有策略的多轮推理。页面内容被分析并格式化之后，会被写回到一个包含该资产元数据哈希的分区中。这使上游流程能够判断某个页面是否已经处理过，以及其内容是否发生了变化。这种方式的主要好处包括：

- 减少对相同页面的重复处理，帮助 PerformLine 在人工评估任务上实现了 **15% 的工作量下降。** 这为人工评估员腾出了时间，让他们能专注于关键页面，而不是所有页面。
- 避免重新处理未变化的页面，使 PerformLine 分析员的工作量在去重收益之外再动态降低 **50%** 以上。

LLM 推理成本在大规模下可能迅速攀升，而上下文和精心构造的 prompt 对准确性至关重要。为在保持精确度的同时优化成本，PerformLine 使用 Amazon Bedrock 实现了多轮处理方式：

- 用 Amazon Nova Micro 做初筛——这个轻量模型以最低成本高效识别相关产品。
- 用 Amazon Nova Lite 做定向提取——识别出的产品被分批成更小的组，交给 Amazon Nova Lite 做更深入的分析。这让 PerformLine 保持在 token 限制之内，同时提升提取准确性。
- 通过上下文感知的处理提升准确性——先识别目标内容，再以更小的批次处理，PerformLine 在把 token 消耗降到最低的同时显著提升了准确性。

## **Amazon Bedrock 的使用**

在初始测试期间，PerformLine 很快意识到需要一种更可扩展的 prompt 管理方式。随着 PerformLine 不断迭代和协作，手工跟踪多个 prompt 版本和模板变得低效。

Amazon Bedrock 的 Prompt Management 服务提供了集中式解决方案，使他们能够对 prompt 做版本管理、维护，并无缝部署到生产环境。prompt 部署之后，可以在 AWS Lambda 中动态引用，从而实现灵活配置。此外，通过使用 [Amazon Bedrock 应用程序配置文件推理端点](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-create.html)，PerformLine 可以动态调整 Lambda 函数调用的模型、按调用追踪成本，并通过设置成本标签把成本归因到具体的应用实例。

为简化模型交互，PerformLine 选择了 [Amazon Bedrock Converse API](https://aws.amazon.com/bedrock/model-access/)，它提供了对开发者友好、标准化的模型调用接口。与推理端点和 prompt 管理结合使用时，使用 Amazon Bedrock Converse API 的 Lambda 函数就变得高度可配置——PerformLine 的开发者可以快速测试新的模型和 prompt、评估结果并迭代，而无需重新构建或重新部署。下图展示了 prompt 管理的简化，以及通过 Amazon Bedrock 部署多种模型的能力。

全面的 AWS ML 模型配置架构，突出三个主要部分：推理系统：模型 ID 集成、配置文件配置、内容管理、推理设置；Prompt 管理：版本控制（V1 与 Draft 版本）、发布 ID 跟踪、Model A 规格、存储配置；环境控制：独立的 PROD 与 DEV 路径、按环境划分的参数存储、调用 ID 管理、工程迭代跟踪

### **未来计划与增强**

PerformLine 很期待深入使用 Amazon Bedrock 的更多功能，包括 [prompt caching](https://aws.amazon.com/bedrock/prompt-caching/) 和 [Amazon Bedrock Flows](https://aws.amazon.com/bedrock/flows/)。

借助 prompt caching，用户可以为 prompt token 设置检查点，从而有效地缓存上下文，供后续 API 调用复用。与未使用 prompt caching 的调用相比，Amazon Bedrock 上的 prompt caching 带来最高 85% 的延迟改善和 90% 的成本降低。PerformLine 认为 prompt caching 将成为今后的标准配置。他们在自己的数据上有许多用例，而能够以更低的成本对同一内容做进一步分析，为功能扩展和开发创造了新的机会。

Amazon Bedrock Flows 是一个可视化工作流构建器，让用户无需大量编码，通过连接 FM 和 API 来编排多步骤生成式 AI 任务。[Amazon Bedrock Flows](https://aws.amazon.com/bedrock/flows/) 是简化 PerformLine 对知识库、prompt caching，乃至未来对 Amazon Bedrock agents 编排的下一步。创建 flow 有助于缩短功能部署与维护的时间。

## **总结**

PerformLine 实现了一套高度可扩展、无服务器、AI 驱动的架构，提升了网页内容处理 pipeline 的效率、成本效益和合规性。通过使用 Amazon Bedrock、EventBridge、Amazon SQS、Lambda 和 DynamoDB，他们构建了一套能够动态伸缩、优化 AI 推理成本并减少重复处理的解决方案——同时保持运营灵活性与合规完整性。按照他们当前的体量与工作流，PerformLine 预计每天处理 150 万到 200 万个页面，并期望从中提取约 40 万到 50 万个产品。此外，PerformLine 预计对每个资产应用规则，从而每天产生约 50 万条需要审查的规则观察。在整个设计过程中，PerformLine 都确保解决方案尽可能简单，同时仍交付运营灵活性与完整性。这种方式降低了复杂度、提升了可维护性、加快了部署，使他们无需不必要的开销即可快速适应不断变化的业务需求。

通过构建在 Amazon Bedrock 之上的无服务器 AI 驱动架构，PerformLine 帮助客户以卓越的准确性和效率应对即使是最复杂的多产品网页。这种整体方式像普通消费者一样解读视觉与文本元素，确认每个产品变体都被准确评估合规性。由此产生的洞察会直接送入规则引擎，支持快速、数据驱动的决策。对 PerformLine 的客户而言，这意味着更少的重复处理、更低的运营成本以及大幅简化的合规工作流，且不牺牲速度或准确性。通过降低大规模数据分析的开销并简化合规检查，PerformLine 的解决方案最终让团队得以专注于推动创新并交付价值。
