# ICYMI：2026 年 9 月，AI 构建者们拿到了什么

*2026 年 9 月 Amazon Bedrock、Amazon Bedrock AgentCore 与 Strands 最新动态回顾*

在 AWS，我们相信通往企业级 AI 最快的路径，是在模型、运行时和工具链每一层都给予构建者真正的选择。这份信念决定了我们在 Amazon Bedrock、AgentCore 和 Strands 上的投入方式。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 持续扩大对领先前沿模型的接入，让你能安全地构建并扩展 AI 应用。[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 提供托管基础设施，用任意框架或模型来构建、连接和部署企业智能体。[Strands](https://strandsagents.com/) 则是一套开源工具包，让你构建智能体并在任何地方运行。

随着 AI 模型能力增强、可选模型增多，行业里的讨论也在转移。模型性能不再是唯一的问题。客户现在会针对自己的具体场景权衡成本与收益，而当生产环境把工作交给智能体时，这些权衡尤其要紧。AI 智能体已经进入这样一类工作流：它们需要对企业知识做推理，要跨越长周期任务执行，还要在安全、准确性和治理都举足轻重的系统里采取行动。关注点正在从模型本身转向它周围更大的系统，包括智能体可以访问哪些上下文、能够采取哪些操作，以及企业数据如何被治理和保护。

9 月，Amazon Bedrock、AgentCore 和 Strands 的一系列更新把这些底座又加固了一层。新增能力扩展了模型选择，让智能体运维更高效、更可度量，也让 AI 应用与当前业务信息之间有了更直接的连接方式。

## 运行更快的智能体，评估真正要紧的事

**构建针对 OpenAI 模型优化的智能体。** 由 OpenAI 驱动的 [Amazon Bedrock Managed Agents](https://aws.amazon.com/about-aws/whats-new/2026/09/bedrock-managed-agents-preview/) 现已进入公开预览，帮助你在不牺牲企业安全性的前提下构建可上生产的 AI 智能体。你现在可以使用 OpenAI 模型，同时把数据留在 AWS 之内，复用已有的 AWS Identity and Access Management (IAM) 权限，并通过 AWS CloudTrail 保持完整的可审计性。持久化会话和内置的人工审批流程有助于减少开发开销、降低风险。

**智能体现在启动更快、基础设施开销更小。** 最新的 [AgentCore runtime](https://aws.amazon.com/blogs/machine-learning/the-new-agentcore-runtime-elastic-optimized-and-consistently-fast-starts/) 是 Amazon Bedrock AgentCore 的一项能力，为 serverless 智能体提供了更高效的内存管理和更低的冷启动延迟，因此你按实际用量付费，而不是按峰值内存付费。你可以用更低的成本跑更快的智能体，按量计价，无需预先配置容量。会话在空闲时可以缩容到零，并运行在硬件隔离的环境中。

**用前沿性能把 token 成本降下来。** [Strands harness](https://strandsagents.com/blog/introducing-strands-harness/) 是一个新的开源智能体 harness，准确率与主流 harness 持平，token 用量却少 28%。用一行 Python 或 TypeScript 就能拉起一个可直接上生产的智能体，内置上下文管理、prompt caching 和记忆，之后可以部署到任何地方。

**让模型在本地安全地做出重大决策。** [Strands Decider 2B](https://strandsagents.com/blog/introducing-strands-decider/) 是一个小型、开源的 2B 参数决策模型，它在预定义选项之间做选择（而不是生成文本），在本地约 115ms 给出答案。它针对工具选择、路由和 guardrails 这类 agentic AI 任务做了优化，全部代码、数据和权重都在 GitHub 和 Hugging Face 上开放。

## 为每个工作负载找到合适的模型

**日常工作中可选的 OpenAI 模型更广了。** OpenAI 的 Astra、Sol 和 Luna 模型现已在 Amazon Bedrock 正式可用，分别对应高要求项目、反复出现的复杂工作以及高吞吐任务。

[GPT-6 Astra](https://aws.amazon.com/blogs/machine-learning/take-on-your-most-ambitious-work-with-gpt-6-astra-on-amazon-bedrock/) 是面向你最有挑战性的工作的旗舰模型，为复杂决策、文档分析和软件开发带来更深的推理，输入最多可达 100 万 token。它在复杂业务决策上提供更强的推理和更精准的判断，能跨软件和文件展开操作，并交付与组织的语气、模板和规范保持一致的专业级输出。[GPT-6 Astra Ultrafast](https://aws.amazon.com/about-aws/whats-new/2026/09/openai-gpt-6-astra-ultrafast-on-amazon-bedrock/) 为 GPT-6 Astra 增加了一个高端速度档位，为最看重速度的工作负载而打造，在 API 中把推理速度提升到最高 6 倍，可达每秒 300 token。

Sol 把接近 Astra 的智能带到编码、computer use 以及频繁运行的专业工作负载上。[GPT-6.1 Sol](https://aws.amazon.com/blogs/machine-learning/bring-near-astra-intelligence-to-everyday-work-with-gpt-6-1-sol-on-amazon-bedrock/) 和 [GPT-6 Sol](https://aws.amazon.com/blogs/machine-learning/bring-more-intelligence-to-everyday-work-with-gpt-6-sol-and-gpt-6-luna-on-amazon-bedrock/) 都已在 Amazon Bedrock 上提供。[GPT 6.1 Luna](https://aws.amazon.com/blogs/machine-learning/bring-more-intelligence-to-everyday-work-with-gpt-6-sol-and-gpt-6-luna-on-amazon-bedrock/) 为抽取、摘要、分类和路由这类高吞吐任务而设计。它们合在一起，帮助你在不同工作负载之间平衡智能、延迟和成本。

**用 Claude 承接长时间运行的编码与研究**。Claude 的模型选择现已包含最新版本，用于推进你的编码和科学工作。[Claude Fable 5.1](https://aws.amazon.com/blogs/machine-learning/introducing-claude-fable-5-1-on-aws/) 扩展了编码、科学研究和企业工作流上的选项。[Claude Opus 5.5](https://aws.amazon.com/blogs/machine-learning/claude-opus-5-5-is-now-available-on-aws/) 为 agentic coding、知识工作和长时间运行的任务而构建。它用 adaptive thinking 判断一个任务需要多少推理，并用 effort 参数为推理深度设定上限。[Claude Sonnet 5.5](https://aws.amazon.com/blogs/machine-learning/introducing-claude-sonnet-5-5-on-aws/) 是更聪明、更高效的 Sonnet，适合聚焦的编码和知识工作，单任务成本比 Claude Sonnet 5 低 30%，速度快 30%。

**用更广的模型组合来推理复杂问题。** Moonshot AI 的 Kimi K3 现已在 Amazon Bedrock 上提供。按 Moonshot AI 的说法，[Kimi K3](https://aws.amazon.com/blogs/machine-learning/introducing-kimi-k3-on-amazon-bedrock/) 是其能力最强的模型，也是首个参数量达到 2.8 万亿的开放模型。它有 100 万 token 的上下文窗口、原生视觉能力和内置 prompt caching，帮助你以更低的成本、快 2.5 倍的速度构建更聪明的应用。

xAI 的前沿模型 [Grok 4.6](https://aws.amazon.com/blogs/machine-learning/xais-grok-4-6-is-now-available-in-amazon-bedrock/) 和 [Grok 4.7](https://aws.amazon.com/blogs/machine-learning/grok-4-7-is-now-available-on-amazon-bedrock/) 提供 50 万 token 上下文窗口，并支持可配置的 reasoning effort 与自我校验，让长时间运行的任务更可靠。

这些新增模型合在一起，让你在按上下文长度、延迟、吞吐量和成本等要求匹配模型时有更大的余地。

## 更多地掌控你的企业 AI 智能体

**让智能体的知识保持最新。** 借助 Amazon Bedrock Managed Knowledge Base 新增的[自动同步调度](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-bedrock-managed-knowledge-base-automatic-sync-scheduling-data-source-connectors/)，你现在可以为所有原生数据源连接器配置每日、每周和每月的刷新选项，企业的 AI 智能体因此检索到的都是最新信息。当你本身已经具备所需访问权限时，[SharePoint、OneDrive 和 Confluence 的用户自管配置](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-bedrock-managed-knowledge-base-user-managed-setup-sharepoint-onedrive-confluence/)可以减少对管理员托管服务账号的依赖。

**接入更多企业数据源，而不必自己维护摄取管道。** Amazon Bedrock Managed Knowledge Base 现已支持 [ServiceNow](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-bedrock-managed-knowledge-base-servicenow-native-data-source-connector/)、[Confluence Data Center](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-bedrock-managed-knowledge-base-confluence-data-center-native-data-source-connector/) 以及 [Salesforce 和 Zendesk](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-bedrock-managed-knowledge-base-salesforce-zendesk-native-data-source-connectors/) 作为原生连接器，自动处理数据爬取、元数据提取和增量同步。这些连接器减少了你为构建和维护支持内容、内部文档与运营知识所需要编写的自定义摄取代码量。
