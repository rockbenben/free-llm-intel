# ICYMI：2026 年 9 月为 AI 构建者带来的内容

*2026 年 9 月以来最新 Amazon Bedrock、Amazon Bedrock AgentCore 和 Strands 更新回顾*

在 AWS，我们相信实现企业 AI 的最快途径是为构建者在每一层提供真正的选择：模型、运行时和工具。这种信念决定了我们在 Amazon Bedrock、AgentCore 和 Strands 上的投资方式。 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 继续扩大对领先前沿模型的访问，以便您可以安全地构建和扩展 AI 应用程序。 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 提供托管基础设施，用于使用任何框架或模型构建、连接和部署企业代理。 [Strands](https://strandsagents.com/) 为您提供了一个开源工具包来构建代理并在任何地方运行。

随着人工智能模型的能力越来越强，模型选择范围不断扩大，行业对话正在发生变化。模型性能不再是唯一的问题。客户现在会权衡其特定用例的成本与收益，并且在将工作委托给生产中的代理时，这些决策很重要。人工智能代理已经进入了工作流程，要求它们对企业知识进行推理，跨长期任务进行操作，并在安全性、准确性和治理都很重要的系统中采取行动。现在的重点已经从模型本身转移到围绕它的更广泛的系统，包括代理可以访问的上下文、他们可以采取的操作以及如何管理和保护企业数据。

9 月份，Amazon Bedrock、AgentCore 和 Strands 的更新加强了这些基础。新功能扩大了模型选择，使代理操作更加高效和可衡量，并创建了更直接的方式将人工智能应用程序与当前业务信息连接起来。

## 运行更快的代理并评估重要的事情

**构建针对 OpenAI 模型优化的代理。** 由 OpenAI 提供支持的 [Amazon Bedrock Managed Agents](https://aws.amazon.com/about-aws/whats-new/2026/09/bedrock-management-agents-preview/) 现已推出公共预览版，可帮助您构建可用于生产的 AI 代理，而无需牺牲企业安全性。现在，您可以使用 OpenAI 模型，同时将数据保留在 AWS 中，重复使用现有的 AWS Identity and Access Management (IAM) 权限，并通过 AWS CloudTrail 保持全面的可审计性。持久的会话和内置的人工审批工作流程有助于减少开发开销并降低风险。

**代理现在启动速度更快，基础设施开销更少。** 最新的 [AgentCore 运行时](https://aws.amazon.com/blogs/machine-learning/the-new-agentcore-runtime-elastic-optimized-and-consistly-fast-starts/) 是 Amazon Bedrock AgentCore 的一项功能，为无服务器代理提供更高效的内存管理和更低的冷启动延迟，因此您可以根据实际使用情况而不是峰值内存付费。您可以通过即用即付定价方式以更低的成本更快地运行代理，并且无需预先配置容量。空闲时会话会缩放为零并在硬件隔离的环境中运行。

**通过前沿性能降低代币成本。** [Strandsharness](https://strandsagents.com/blog/introducing-strands-harness/) 是一种新的开源代理工具，在准确性上与流行的工具相匹配，同时使用的代币数量减少了 28%。您可以使用一行 Python 或 TypeScript 启动生产就绪代理，并使用内置上下文管理、提示缓存和内存，然后将其部署到任何地方。

**让您的模型在本地安全地做出重大决策。** [Strands Decider 2B](https://strandsagents.com/blog/introducing-strands-decider/) 是一个小型开源 2B 参数决策模型，可以在预定义选项之间进行选择（而不是生成文本），并在本地约 115 毫秒内提供答案。它针对工具选择、路由和护栏等代理 AI 任务进行了优化，所有代码、数据和权重都可以在 GitHub 和 Hugging Face 上找到。

## 为每个工作负载找到合适的模型

**从更广泛的 OpenAI 模型中进行选择，以适应您的日常工作。** OpenAI 的 Astra、Sol 和 Luna 模型现已在 Amazon Bedrock 上全面提供，可为要求较高的项目、重复性复杂工作和大批量任务提供选项。

[GPT-6 Astra](https://aws.amazon.com/blogs/machine-learning/take-on-your-most-ambitious-work-with-gpt-6-astra-on-amazon-bedrock/) 是您最雄心勃勃的工作的旗舰模型，通过多达 100 万个输入令牌为复杂决策、文档分析和软件开发带来更深入的推理。它为复杂的业务决策带来更强的推理和更精确的判断，跨软件和文件操作，并提供符合组织声音、模板和标准的专业品质输出。 [GPT-6 Astra Ultrafast](https://aws.amazon.com/about-aws/whats-new/2026/09/openai-gpt-6-astra-ultrafast-on-amazon-bedrock/) 为 GPT-6 Astra 添加了高级速度层，专为速度最重要的工作负载而构建。它在 API 中的推理速度提高了 6 倍，每秒最多可处理 300 个令牌。

Sol 为编码、计算机使用和频繁运行的专业工作负载带来了近乎 Astra 的智能。 [GPT-6.1 Sol](https://aws.amazon.com/blogs/machine-learning/bring-near-astra-intelligence-to-everyday-work-with-gpt-6-1-sol-on-amazon-bedrock/) 和 [GPT-6 Sol](https://aws.amazon.com/blogs/machine-learning/bring-more-intelligence-to-everyday-work-with-gpt-6-sol-and-gpt-6-luna-on-amazon-bedrock/) 可在 Amazon Bedrock 上使用。 [GPT 6.1 Luna](https://aws.amazon.com/blogs/machine-learning/bring-more-intelligence-to-everyday-work-with-gpt-6-sol-and-gpt-6-luna-on-amazon-bedrock/) 专为提取、汇总、分类和路由等大容量任务而设计。它们共同帮助您平衡工作负载的智能、延迟和成本。

**与 Claude 一起进行长时间运行的编码和研究**。 Claude 的模型选择现在包括最新版本，以推进您的编码和科学工作。 [Claude Fable 5.1](https://aws.amazon.com/blogs/machine-learning/introducing-claude-fable-5-1-on-aws/) 扩展了编码、科学研究和企业工作流程的选项。 [Claude Opus 5.5](https://aws.amazon.com/blogs/machine-learning/claude-opus-5-5-is-now-available-on-aws/) 专为代理编码、知识工作和长时间运行的任务而构建。它使用适应性思维来衡量任务需要多少推理，并使用工作量参数来设置推理深度的上限。 [Claude Sonnet 5.5](https://aws.amazon.com/blogs/machine-learning/introducing-claude-sonnet-5-5-on-aws/) 是一种更智能、更高效的 Sonnet，适合集中编码和知识工作，每项任务的成本比 Claude Sonnet 5 低 30%，速度快 30%。

**通过更广泛的模型组合对复杂性进行推理。** Moonshot AI 的 Kimi K3 现已在 Amazon Bedrock 上提供。据 Moonshot AI 称，Kimi K3 是其最强大的模型，也是第一个达到 2.8 万亿个参数的开放模型。凭借 100 万个令牌上下文窗口、原生视觉和内置提示缓存，它可以帮助您以比以前版本低 2.5 倍的速度构建更智能的应用程序。

xAI 的前沿模型 [Grok 4.6](https://aws.amazon.com/blogs/machine-learning/xais-grok-4-6-is-now-available-in-amazon-bedrock/) 和 [Grok 4.7](https://aws.amazon.com/blogs/machine-learning/grok-4-7-is-now-available-on-amazon-bedrock/) 提供了500K 令牌上下文窗口并支持可配置的推理工作和自我验证，以实现更可靠的长期运行任务。

这些新增功能共同为您提供了更大的灵活性，可以根据您的需求（例如上下文长度、延迟、吞吐量和成本）匹配模型。

## 更好地控制您的企业 AI 代理

**保持代理知识最新。** 通过 Amazon Bedrock 托管知识库中的新[自动同步计划](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-bedrock-management-knowledge-base-automatic-sync-scheduling-data-source-connectors/)，您现在可以为所有本机数据源连接器配置每日、每周和每月刷新选项。因此，您的企业 AI 代理会检索最新信息。当您已拥有所需的访问权限时，[SharePoint、OneDrive 和 Confluence 的用户管理设置](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-bedrock-management-knowledge-base-user-management-setup-sharepoint-onedrive-confluence/) 可减少对管理员管理服务帐户的依赖。

**连接更多企业源，无需维护自定义提取管道。** Amazon Bedrock 托管知识库现在支持 [ServiceNow](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-bedrock-management-knowledge-base-servicenow-native-data-source-connector/)、[Confluence Data中心](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-bedrock-management-knowledge-base-confluence-data-center-native-data-source-connector/)、[Salesforce 和Zendesk](https://aws.amazon.com/about-aws/whats-new/2026/09/amazon-bedrock-management-knowledge-base-salesforce-zendesk-native-data-source-connectors/) 作为本机连接器来自动处理数据爬行、元数据提取和增量同步。这些连接器减少了构建和维护支持内容、内部文档和操作知识所需的自定义摄取代码的数量。
