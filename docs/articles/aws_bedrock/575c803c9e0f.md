# Asure 借助生成式 AI 与 AWS Quick Sight 提升呼叫中心体验的做法

[Asure](https://www.asuresoftware.com/) 是一家拥有 600 多名员工的公司，也是领先的基于云的劳动力管理解决方案提供商，旨在帮助中小型企业简化薪资与人力资源（HR）运营并确保合规。其产品包括面向薪资与税务、HR 合规服务、工时跟踪、401(k) 计划等的全面人力资本管理（HCM）解决方案套件。

Asure 预计[生成式 AI](https://aws.amazon.com/ai/generative-ai/)可以帮助联络中心负责人了解团队的支持表现、识别产品中的缺口与痛点，并利用通话记录找出培训客服代表最有效的策略。Asure 团队此前一直手动分析数千份通话记录来发现主题与趋势，这种方式缺乏可扩展性。本次合作的总目标是改进这种手动做法。若不采用更自动化的方法，可能会导致客户满意度得分下降，进而造成未来收入损失。因此，为 Asure 提供一个通话后分析 pipeline、使其能够提供有价值的洞见，从而提升整体客户支持体验并推动业务增长，是有价值的。

Asure 认识到生成式 AI 在进一步提升用户体验、更好地理解客户需求方面的潜力，并希望找到合作伙伴来帮助实现这一目标。

Asure 董事长兼 CEO Pat Goepel 分享道：

> “在与 AWS 生成式 AI 创新中心的合作中，我们利用 Amazon Bedrock、Amazon Comprehend 和 AWS Quick Sight 来理解自身客户交互中的趋势、确定产品开发的优先级，并更早发现问题，从而能够更加主动地为客户提供支持。我们与 AWS 的合作，以及我们作为 Amazon Bedrock 等创新技术早期采用者的承诺，体现了我们让各种规模的企业都能获得先进 HCM 技术的决心。”
>         “我们非常高兴能与 AWS 合作开展这个开创性的生成式 AI 项目。稳健的 AWS 基础设施和先进的 AI 能力为我们提供了创新的完美基础，推动我们突破可能性的边界。这次合作将使我们能够交付不仅满足、而且超越客户期望的前沿解决方案。我们将携手改变 AI 驱动技术的格局，为客户创造前所未有的价值。”
>         ——Asure CTO Yasmine Rodriguez。
>         “当我们在 Asure 踏上将生成式 AI 集成到解决方案中的旅程时，找到合适的合作伙伴至关重要。能与 AWS 的生成式 AI 创新中心合作，不仅带来了 AI 方面的技术专长，还带来了大规模开发解决方案的经验。这次合作印证了我们的 AI 解决方案不仅具有创新性，而且具备韧性。我们相信，可以携手驾驭 AI 的力量来提升效率、改善客户体验，并在快速演进的市场中保持领先。”
>         ——Asure 工程副总裁 John Canada。

在本文中，我们探讨 Asure 为何采用 [Amazon Web Services](https://aws.amazon.com/)（AWS）的通话后分析（PCA）pipeline——它借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和 [AWS Quick Sight](https://aws.amazon.com/quicksight/q/) 等由生成式 AI 驱动的服务的高级能力，跨呼叫中心大规模生成洞见。Asure 选择这一方案，是因为它提供了深入的消费者分析，围绕常见主题对通话记录进行分类，并让联络中心负责人能够用自然语言回答查询。这最终使 Asure 能够为客户带来产品与客户体验上的改进。

## 解决方案概览

在高层上，该方案首先使用 [Amazon Transcribe](https://aws.amazon.com/pm/transcribe/?gclid=CjwKCAiArva5BhBiEiwA-oTnXSCAjd_vaCZHIy7aHFLUJoIrmXdr_UIwYApXyCsaa5Ad7f3noj2f1BoCAuIQAvD_BwE&trk=aae0a267-33fa-4d21-a4d5-30b7b3fd731e&sc_channel=ps&ef_id=CjwKCAiArva5BhBiEiwA-oTnXSCAjd_vaCZHIy7aHFLUJoIrmXdr_UIwYApXyCsaa5Ad7f3noj2f1BoCAuIQAvD_BwE:G:s&s_kwcid=AL!4422!3!648922763916!e!!g!!amazon%20transcribe!19597968945!143908652045) 将音频转换为通话记录，并使用 Amazon Bedrock 为每份记录生成和评估摘要字段。此外，问答可以针对单次通话使用 Amazon Bedrock 完成，或针对多次通话使用 AWS Quick Sight 完成。本节其余部分将更详细地描述这些组件与所用服务。

我们在现有 [PCA 解决方案](https://github.com/aws-samples/amazon-transcribe-post-call-analytics)基础上增加了以下服务：

- [Amazon Bedrock](https://aws.amazon.com/bedrock/)
- [AWS Quick Sight](https://aws.amazon.com/quicksight/q/)

客户服务与呼叫中心运营高度动态，不断演变的客户期望、市场趋势和技术进步正快速重塑这个行业。要在这种竞争格局中保持领先，需要敏捷、可扩展且智能的解决方案来适应不断变化的需求。

在此背景下，Amazon Bedrock 成为开发生成式 AI 驱动的客服通话记录分析方案的绝佳选择。这项全托管服务提供来自领先 AI 提供商的尖端基础模型（FM），可无缝集成针对文本分析任务定制的最先进语言模型。Amazon Bedrock 提供微调能力，让您可以使用专有的通话记录数据定制这些预训练模型，无需大量机器学习（ML）专业知识即可获得高准确性与相关性。此外，Amazon Bedrock 提供与其他 AWS 服务（如 [Amazon SageMaker](https://aws.amazon.com/sagemaker/)）的集成，简化了部署流程；其可扩展架构确保方案能够轻松适应不断增长的通话量。

凭借强大的安全措施、数据隐私保障以及颇具成本效益的按需付费模式，Amazon Bedrock 提供安全、灵活且高性价比的服务，帮助释放生成式 AI 在增强客服分析方面的潜力，最终改善客户体验并提升运营效率。

此外，通过集成包含组织数据、政策和领域专属信息的知识库，生成式 AI 模型可以从通话记录中提供更具上下文、更准确、更相关的洞见。该知识库让模型能够基于公司特有的术语、产品和流程来理解并回应，从而对客户交互进行更深入的分析并挖掘更可执行的智能。

在本用例中，Amazon Bedrock 同时用于为样本通话记录生成摘要字段，以及将这些摘要字段与 ground truth 数据集对照评估。其价值来自它能简单集成到现有 pipeline 和多种评估框架中。Amazon Bedrock 还允许您为不同用例选择不同模型，凭其灵活性成为该方案的显然选择。使用 Amazon Bedrock 可以借助知识库迭代方案，便于简单存储与访问通话记录，同时使用 guardrails 构建负责任的 AI 应用。

## Amazon Bedrock

Amazon Bedrock 是一项全托管服务，通过 API 提供 FM，因此您可以从广泛的 FM 中选择最适合自身用例的模型。借助 Amazon Bedrock 的 serverless 体验，您可以快速上手，用自有数据私下定制 FM，并使用 AWS 工具快速集成和部署到应用中，而无需管理基础设施。

## AWS Quick Sight

AWS Quick Sight 是一个生成式 AI 助手，凭借生成式商业智能（BI）能力加速决策并提升业务生产力。

原始 PCA 解决方案包含以下服务：

- [AWS Lambda](https://aws.amazon.com/lambda/)
- [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/s3/)
- [Amazon CloudFront](https://aws.amazon.com/cloudfront/)
- [Amazon Athena](https://aws.amazon.com/athena/)
- [Amazon Comprehend](https://aws.amazon.com/comprehend/)
- [Amazon Transcribe](https://aws.amazon.com/transcribe/)
- [Amazon Cognito](https://aws.amazon.com/cognito/)

该解决方案由以下组件构成：

- **通话元数据生成** – 在文件摄取步骤之后，当使用 Amazon Transcribe 为每份通话记录生成记录时，会使用 Amazon Bedrock 中 Anthropic 的 Claude Haiku FM 生成与通话相关的元数据。这包括从通话记录生成的摘要、类别、根因及其他高层字段。该流程由 [AWS Step Functions](https://aws.amazon.com/step-functions/) 编排。
- **单次通话问答** – 对于需要特定通话的问题，例如“客户在通话 ID X 中如何反应”，使用 Anthropic 的 Claude Haiku 驱动位于 CloudFront 应用中的问答助手。该助手由架构图（下一节提供）中的 Web 应用部分提供支持。
- **聚合通话问答** – 要回答需要多次通话的问题，例如“检测到的最常见问题是什么”，使用 Quick Sight 上的 Amazon Q 增强 Agent Assist 界面。该步骤体现为业务分析师在存储与可视化步骤中通过自然语言与 Quick Sight 交互。

要了解更多 PCA 解决方案的架构组件，包括文件摄取、洞见提取、存储与可视化以及 Web 应用组件，请参阅[为您的联络中心使用 Amazon 语言 AI 服务进行通话后分析](https://aws.amazon.com/blogs/machine-learning/post-call-analytics-for-your-contact-center-with-amazon-language-ai-services/)。

## 架构

下图说明了解决方案架构。评估框架、通话元数据生成和 AWS Quick Sight 是在原 PCA 解决方案基础上引入的新组件。

![Asure 的架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/26/asure-blogpost-pics.jpg)

[Ragas](https://github.com/explodinggradients/ragas) 和一个 human-in-the-loop UI（如与 Tealium 合作的[客户博客文章](https://aws.amazon.com/blogs/machine-learning/how-tealium-built-a-chatbot-evaluation-platform-with-ragas-and-auto-instruct-using-aws-generative-ai-services/)所述）被用于评估元数据生成和单次通话问答部分。Ragas 是一个开源评估框架，有助于评估 FM 生成的文本。

这项工作的高层要点如下：

- [Anthropic 的 Claude 3 Haiku](https://aws.amazon.com/blogs/aws/anthropics-claude-3-haiku-model-is-now-available-in-amazon-bedrock/) 成功接收一份通话记录，并判定其摘要、根因、问题是否已解决，以及若为回电则判定客户与坐席的后续步骤（生成式 AI 驱动的字段）。与 Anthropic 的 Claude Instant 相比，使用 Anthropic 的 Claude 3 Haiku 时延迟有所降低。借助思维链推理，如主题专家（SME）所衡量，整体质量有所提升（包括回答的事实性、可理解性和相关性如何，采用 1–5 分制，本文稍后详述）。借助 Amazon Bedrock，可以根据不同用例选择不同模型，体现了它在此应用中的灵活性。
- AWS Quick Sight 被证明是一个强大的分析工具，可通过直观的图表和表格可视化来理解数据并生成相关洞见。它可以在必要时执行简单计算，同时也便于深入探究问题、从多个角度探索数据，在洞见生成方面展现出巨大价值。
- human-in-the-loop UI 加 Ragas 指标被证明对评估整个 pipeline 中所用 FM 的输出是有效的。具体而言，答案正确性、答案相关性、忠实度以及摘要指标（对齐度与覆盖度得分）被用于借助 Amazon Bedrock 评估通话元数据生成和单次通话问答组件。它在各种 FM 上的灵活性使得可以测试多种类型的模型来生成评估指标，包括 Anthropic 的 Claude Sonnet 3.5 和 Anthropic 的 Claude Haiku 3。

通话元数据生成 pipeline 包括：使用 Amazon Transcribe 将音频文件转换为 JSON 格式的通话记录，然后使用 Amazon Bedrock 和 Amazon Comprehend 为每份记录生成关键信息。下图展示了前述架构图的一个子集，用来说明这一点。

![简化架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/26/asure-blogpost-pics-2.jpg)

前面链接的原始 PCA 文章展示了 Amazon Transcribe 和 Amazon Comprehend 如何在元数据生成 pipeline 中使用。

Step Functions 工作流中 Amazon Transcribe 步骤输出的通话记录输入，遵循以下代码示例中的格式：

```
{
call_id: <call id>,
agent_id: <agent_id>
customer_id: <customer_id>

   Customer: <Customer message>
   Agent: <Agent message>.
   Customer: <Customer message>
   Agent: <Agent message>.
   Customer: <Customer message>
   ...........
    """
}
```

元数据使用 Amazon Bedrock 生成。具体来说，它提取摘要、根因、主题和后续步骤，并回答诸如该通话是否为回电、问题最终是否解决等关键问题。

## 评估框架

本节概述所用评估框架的组件。它最终让 Asure 能够突出其用例的重要指标，并让人们对生成式 AI 应用的优势与不足有所了解。这是通过 Ragas、DeepEval 提供的自动化定量指标、传统 ML 指标，以及 SME 执行的 human-in-the-loop 评估来完成的。

### 定量指标

生成的通话元数据和单次通话问答的结果，使用 Ragas 提供的定量指标来评估：答案正确性、答案相关性和忠实度；以及 [DeepEval](https://github.com/confident-ai/deepeval/tree/main)：对齐度和覆盖度，二者均由 Amazon Bedrock 的 FM 驱动。它与外部库的简单集成使 Amazon Bedrock 可以与现有库配合配置。此外，对于“是/否”类回答使用了传统 ML 指标。以下是方案不同组件所用的指标：

- **通话元数据生成** – 这包括以下内容：  **摘要** – 对齐度和覆盖度（可在 [DeepEval 仓库](https://github.com/confident-ai/deepeval/blob/main/docs/docs/metrics-summarization.mdx)中找到这些指标的说明）以及答案正确性 **问题已解决、回电** – F1 分数与准确率 **主题、后续步骤、根因** – 答案正确性、答案相关性和忠实度
- **单次通话问答** – 答案正确性、答案相关性和忠实度
- **人工介入** – 单次通话问答和通话元数据生成都使用了 human-in-the-loop 指标

关于答案正确性、答案相关性和忠实度的说明，请参阅与 Tealium 合作的客户[博客文章](https://aws.amazon.com/blogs/machine-learning/how-tealium-built-a-chatbot-evaluation-platform-with-ragas-and-auto-instruct-using-aws-generative-ai-services/)。

在评估框架中使用 Amazon Bedrock，可以针对不同用例灵活选用不同模型。例如，Anthropic 的 Claude Sonnet 3.5 被用于生成 DeepEval 指标，而 Anthropic 的 Claude 3 Haiku（凭借其低延迟）则适合 Ragas。

### 人工介入

human-in-the-loop UI 在与 Tealium 合作的客户[博客文章](https://aws.amazon.com/blogs/machine-learning/how-tealium-built-a-chatbot-evaluation-platform-with-ragas-and-auto-instruct-using-aws-generative-ai-services/)的“Human-in-the-Loop”一节中有描述。要使用它来评估本方案，需要做出一些修改：

- 用户可以选择分析某次通话的某一个已生成元数据字段（例如摘要）或某个特定的问答对。
- 用户可以引入两个模型输出进行对比。这可以包括同一 FM 但使用不同 prompt 的输出、不同 FM 但使用相同 prompt 的输出，以及不同 FM 且使用不同 prompt 的输出。
- 增加了对流畅性、连贯性、创造性、有害性、相关性、完整性和整体质量的额外检查，用户根据模型输出对这些指标给出 0–4 的评分。

### 使用 AWS Quick Sight 进行自然语言问答

与 Amazon Q 集成的 Quick Sight 让 Asure 能够使用自然语言查询进行全面的客户分析。通过对情感、通话量、问题解决情况和坐席表现等查询进行解释，该服务交付了数据驱动的可视化。这使 Asure 能够快速识别痛点、优化运营，并通过为呼叫中心运营量身打造的简捷、可扩展分析方案交付卓越的客户体验。

### 将 AWS Quick Sight 与 PCA 解决方案集成

AWS Quick Sight 的集成通过以下三个高层步骤完成：

- 在 Quick Sight 上创建数据集。
- 基于该数据集在 Quick Sight 上创建 topic。
- 使用自然语言查询。

### 在 Quick Sight 上创建数据集

我们使用 Athena 作为数据源，它从 Amazon S3 查询数据。Quick Sight 可以通过多种数据源进行配置（更多信息请参阅[支持的数据源](https://docs.aws.amazon.com/quicksight/latest/user/supported-data-sources.html)）。在本用例中，我们使用 PCA pipeline 生成的数据作为数据源，以便在 AWS Quick Sight 中做进一步分析并进行自然语言查询。PCA pipeline 将数据存储在 Amazon S3 中，可以在 Athena 中查询——Athena 是一项交互式查询服务，让您可以使用标准 SQL 直接分析 Amazon S3 中的数据。

- 在 Quick Sight 控制台的导航窗格中，选择 **Datasets**。
- 选择 **Create new**。
- 选择 Athena 作为数据源，并输入 AWS Quick Sight 将引用的特定 catalog、数据库和表。

确认数据集创建成功，然后进入下一步。

![QuickSight 添加数据集](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/26/quicksight1.jpg)

### 基于所创建的数据集在 AWS Quick Sight 上创建 topic

用户可以使用 Quick Sight 中由 Amazon Q 集成驱动的 topic，对数据执行自然语言查询。该功能让用户可以用平实语言提问，从而进行直观的数据探索与分析，无需复杂的 SQL 查询或专门的技术技能。在设置 topic 之前，请确保用户拥有 Pro 级别访问权限。要设置 topic，请按以下步骤操作：

- 选择 **New topic**。
- 输入 topic 名称，并选择所创建的数据源。
- 选择所创建的 topic，然后选择 **Open Q&A** 开始用自然语言查询

## 成功指标

从该方案获得的主要成功指标是提升员工生产力，主要方式是快速理解通话中的客户交互以发现主题与趋势，同时识别产品中的缺口与痛点。合作之前，分析师需要 14 天才能手动过完每份通话记录以提取洞见。合作之后，Asure 看到 Amazon Bedrock 和 AWS Quick Sight 可以将这一时间缩短到几分钟甚至几秒，既可直接从所有已存储的通话记录中查询洞见，也可生成可用于报告的可视化。

在 pipeline 中，使用 Anthropic 的 Claude 3 Haiku 获取初始通话元数据字段（如摘要、根因、后续步骤和情感），并存储在 Athena 中。这让每份通话记录都可以通过 AWS Quick Sight 的自然语言进行查询，使业务分析师能够在几秒内回答关于问题、主题以及客户和坐席洞见的高层问题。

## 要点

我们得到以下要点：

- 为通话元数据生成组件中的每个 prompt 启用思维链推理和特定的助手 prompt，并使用 Anthropic 的 Claude 3 Haiku 调用它，改善了每份记录的元数据生成。首先，Amazon Bedrock 在使用各种 FM 方面的灵活性，使得只需最小改动即可对多种模型进行全面试验。使用 Amazon Bedrock 可以根据用例选用各种模型，凭其灵活性成为此应用的显然选择。
- Ragas 指标，特别是忠实度、答案正确性和答案相关性，被用于评估通话元数据生成和单次问答。然而，摘要需要不同的指标——对齐度和覆盖度，它们不需要 ground truth 摘要。因此，使用 DeepEval 计算摘要指标。总体而言，集成 Amazon Bedrock 的便利性使它能够以对评估库的最小改动来驱动定量指标的计算。这也使得可以为不同的评估库使用不同类型的模型。
- SME 可以使用 human-in-the-loop 方法进一步评估 Amazon Bedrock 的输出。有机会基于这些反馈改进 Amazon Bedrock FM，但本次合作中没有开展这项工作。
- 借助 Amazon Bedrock，通话后分析工作流未来还可以使用诸如 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 针对特定数量的通话记录执行问答，以及使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 检测有害与幻觉回答，同时构建更负责任的 AI 应用，从而继续迭代。
- AWS Quick Sight 能够回答关于客户分析、根因和坐席分析的自然语言问题，但有些问题需要重新表述才能得到有意义的回答。
- AWS Quick Sight 中的数据字段需要正确定义，并需要添加同义词，以使 Amazon Q 在自然语言查询上更稳健。
