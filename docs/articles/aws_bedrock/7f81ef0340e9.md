# 在 Amazon Bedrock 上进行迭代式微调，实现有策略的模型改进

组织在为其生成式 AI 模型实施一次性微调（single-shot fine-tuning）方法时经常会遇到挑战。一次性微调方法是选定训练数据、配置超参数，然后指望结果符合预期，却无法做增量调整。一次性微调常常导致次优结果，并且在需要改进时必须从头开始整个流程。

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 现在支持迭代式微调，可通过受控的增量训练轮次实现系统化的模型改进。借助这项能力，你可以在先前定制过的模型基础上继续构建，无论这些模型是通过[微调](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-model-fine-tuning.html)还是[蒸馏](https://docs.aws.amazon.com/bedrock/latest/userguide/model-distillation.html)创建的，从而为持续改进提供基础，而不必承担完全重新训练带来的风险。

在本文中，我们将探讨如何实施 Amazon Bedrock 的迭代式微调能力，以系统化地改进你的 AI 模型。我们会介绍相比一次性方法的主要优势，分别用控制台和 SDK 走一遍实际实现，讨论部署选项，并分享最大化迭代式微调成果的最佳实践。

## **何时使用迭代式微调**

迭代式微调相比一次性方法具有多项优势，使其在生产环境中很有价值。通过增量改进可以实现风险缓解，因此你可以在做出较大改动之前先测试和验证变更。采用这种方法，你可以基于真实性能反馈做数据驱动的优化，而不是凭对什么可能有效的理论假设。该方法论还帮助开发者依次应用不同的训练技术来改进模型行为。最重要的是，迭代式微调能够适应由持续的真实数据流量驱动的业务需求变化。随着用户行为随时间变化、以及初始训练中并不存在的新用例出现，你可以利用这些新数据来改进模型性能，而不必从头开始。

## **如何在 Amazon Bedrock 上实施迭代式微调**

配置迭代式微调需要准备好环境，并创建基于现有定制模型的新训练作业，既可以通过控制台界面，也可以用 SDK 以编程方式完成。

### **前提条件**

在开始迭代式微调之前，你需要一个先前已定制好的模型作为起点。这个基础模型可以来自微调或蒸馏过程，并支持 Amazon Bedrock 上可用的可定制模型和变体。你还需要：

- 用于 Amazon Bedrock 模型定制的标准 [IAM 权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-iam-role.html)
- 聚焦于解决具体性能差距的增量训练数据
- 用于存放训练数据和作业输出的 S3 存储桶

你的增量训练数据应针对当前模型需要改进的特定方面，而不是试图对所有可能的场景重新训练。

### **使用 AWS Management Console**

[Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock)提供了用于创建迭代式微调作业的简明界面。

导航到 **Custom Models** 区域并选择 **Create fine-tuning job**。迭代式微调的关键区别在于基础模型的选择：你选择的是先前定制过的模型，而不是基础模型（foundation model）。

### **使用 SDK**

以编程方式实现迭代式微调与标准微调的流程类似，但有一个关键区别：要把先前定制过的模型指定为基础模型标识符。下面是一个实现示例：

```
import boto3
from datetime import datetime
import uuid

# Initialize Bedrock client
bedrock = boto3.client('bedrock')

# Define job parameters
job_name = f"iterative-finetuning-{datetime.now().strftime('%Y-%m-%d-%H-%M-%S')}"
custom_model_name = f"iterative-model-{str(uuid.uuid4())[:8]}"

# Key difference: Use your previously customized model ARN as base
# This could be from previous fine-tuning or distillation
base_model_id = "arn:aws:bedrock:<Region>:<AccountID>:custom-model/<your-previous-custom-model-id>"

# S3 paths for training data and outputs
training_data_uri = "s3://<your-bucket>/<iterative-training-data>"
output_path = "s3://<your-bucket>/<iterative-output-folder>/"

# Hyperparameters adjusted based on previous iteration learnings
hyperparameters = {
    "epochCount": "3" # Example
}

# Create the iterative fine-tuning job
response = bedrock.create_model_customization_job(
    customizationType="FINE_TUNING",
    jobName=job_name,
    customModelName=custom_model_name,
    roleArn=role_arn,
    baseModelIdentifier=base_model_id,  # Your previously customized model
    hyperParameters=hyperparameters,
    trainingDataConfig={
        "s3Uri": training_data_uri
    },
    outputDataConfig={
        "s3Uri": output_path
    }
)

job_arn = response.get('jobArn')
print(f"Iterative fine-tuning job created with ARN: {job_arn}")
```

## **为迭代式微调后的模型设置推理**

迭代式微调作业完成后，你有两种主要的模型推理部署选择：预置吞吐量和按需推理，它们各自适合不同的使用模式和需求。

### **预置吞吐量（Provisioned Throughput）**

[Provisioned Throughput](https://docs.aws.amazon.com/bedrock/latest/userguide/prov-throughput.html) 为具有稳定吞吐量需求的、负载可预测的场景提供稳定性能。该选项提供专用容量，使迭代式微调后的模型在高峰使用时段也能保持性能标准。配置时需要根据预期流量模式与性能需求购买模型单元。

### **按需推理**

[On-demand inference](https://docs.aws.amazon.com/bedrock/latest/userguide/deploy-custom-model-on-demand.html) 为负载波动和试验性场景提供灵活性。Amazon Bedrock 现在支持 Amazon Nova Micro、Lite 和 Pro 模型以及 Llama 3.3 模型进行按需推理，采用按 token 付费的定价方式。该选项无需容量规划，因此你可以在没有前期投入的情况下测试迭代式微调后的模型。其定价模式随用量自动伸缩，对推理模式不可预测或用量较低的应用来说更具成本效益。

## **最佳实践**

成功的迭代式微调需要关注几个关键方面。最重要的是，你的数据策略在增量数据集上应强调质量而非数量。与其加入大量新的训练样本，不如聚焦于能够解决前几轮迭代中发现的具体性能差距的高质量数据。

为了有效跟踪进展，跨迭代保持评估一致性才能对改进做出有意义的比较。在第一轮迭代中建立基线指标，并在整个过程中保持相同的评估框架。你可以使用 [Amazon Bedrock Evaluations](https://aws.amazon.com/blogs/machine-learning/evaluate-models-or-rag-systems-using-amazon-bedrock-evaluations-now-generally-available/)，在每次定制训练后系统地找出模型性能中的差距所在。这种一致性有助于你判断相关变更是否带来了有意义的改进。

最后，识别何时停止迭代过程有助于防止投入产出递减。请监控各轮迭代之间的性能改进，当增益相对于所需投入变得微小时，就可以考虑结束该过程。

## **结论**

Amazon Bedrock 上的迭代式微调提供了一套系统化的模型改进方法，在降低风险的同时支持持续优化。借助迭代式微调方法论，组织可以在需要调整时基于已有的定制模型投入继续构建，而不必从头开始。

要开始使用迭代式微调，请访问 Amazon Bedrock 控制台并导航到 **Custom models** 区域。详细的实施指导请参阅 [Amazon Bedrock 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-submit.html)。
