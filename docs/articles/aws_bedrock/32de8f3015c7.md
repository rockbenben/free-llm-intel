# 使用 Amazon SageMaker AI 与 Model Context Protocol（MCP）借助预测型 ML 模型增强 AI agent

[机器学习](https://aws.amazon.com/ai/machine-learning/)（ML）已从实验阶段演进为业务运营中不可或缺的一环。组织如今积极部署 ML 模型，用于精确的销售预测、客户分群和流失预测。传统 ML 仍在改造业务流程，而[生成式 AI](https://aws.amazon.com/generative-ai/) 已成为一股革命性力量，带来了强大且易用的工具，重塑客户体验。

尽管生成式 AI 风头正盛，传统 ML 方案对于特定的预测任务依然不可或缺。销售预测依赖历史数据与趋势分析，用成熟的 ML 算法来处理最为有效，包括随机森林、梯度提升机（如 XGBoost）、自回归积分滑动平均（ARIMA）模型、长短期记忆（LSTM）网络和线性回归技术。K-means 和层次聚类这类传统 ML 模型在客户分群和流失预测场景中同样表现出色。尽管生成式 AI 在内容生成、产品设计和个性化客户互动等创造性任务上展现出非凡能力，传统 ML 模型在数据驱动的预测上仍保持优势。组织把两种方法结合使用，就能得到最佳结果：既给出准确的预测，又保持成本效率。

为此，本文展示客户如何在 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker-ai) 上，通过整合预测型 ML 模型与 [Model Context Protocol（MCP）](https://modelcontextprotocol.io/introduction)来扩展 AI agent 的能力——MCP 是一个开放协议，用于标准化应用如何向[大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLM）提供上下文。我们演示了一套完整的工作流，让 AI agent 借助托管在 SageMaker 上的 ML 模型做出数据驱动的业务决策。通过使用 [Strands Agents SDK](https://strandsagents.com/)——一个开源 SDK，只需几行代码就能以模型驱动的方式构建和运行 AI agent——以及包括直接访问 endpoint 和 MCP 在内的灵活集成方式，我们展示如何构建智能且可扩展的 AI 应用，把对话式 AI 与预测分析的能力结合起来。

## 解决方案概览

本方案通过让部署在 Amazon SageMaker AI endpoint 上的 ML 模型与 AI agent 集成，使 AI agent 能借助 ML 预测做出数据驱动的业务决策，从而增强其能力。AI agent 是一种由 LLM 驱动的应用，它把 LLM 当作核心“大脑”，以最少的人工输入自主观察环境、规划行动并执行任务。它整合推理、记忆和工具使用，通过动态创建和修改计划、与外部系统交互、从以往交互中学习来优化结果，从而完成复杂的多步问题求解。这使 AI agent 能够超越单纯的文本生成，成为能够在各种真实世界与企业场景中自主决策、执行目标导向行动的独立实体。在本方案中，AI agent 使用 Strands Agents SDK 开发，该 SDK 支持从简单助手到复杂工作流的快速开发。预测型 ML 模型托管在 Amazon SageMaker AI 上，并将作为工具供 AI agent 使用。这可以通过两种方式实现：agent 可以直接调用 SageMaker endpoint，以更直接地使用模型的推理能力；也可以使用 MCP 协议来促进 AI agent 与 ML 模型之间的交互。两种方式都可行：直接调用工具无需额外基础设施，只需把工具调用直接嵌入 agent 自身的代码；而 MCP 通过引入额外的架构组件——MCP server——实现了工具的动态发现，以及 agent 与工具执行的解耦。对于可扩展且安全的工具调用逻辑实现，我们推荐 MCP 方式。尽管我们推荐 MCP，本文也会讨论并实现直接访问 endpoint 的方式，让读者可以自由选择自己喜欢的做法。

Amazon SageMaker AI 提供两种在单个 endpoint 后托管多个模型的方法：推理组件（inference component）和多模型 endpoint。这种整合式托管方式可以在一个环境中高效部署多个模型，从而优化计算资源并缩短模型预测的响应时间。为便于演示，本文只在一个 endpoint 上部署一个模型。如需进一步了解推理组件，请参阅 Amazon SageMaker AI 文档[多模型共享资源利用](https://docs.aws.amazon.com/sagemaker/latest/dg/realtime-endpoints-deploy-models.html#deployed-shared-utilization)。如需进一步了解多模型 endpoint，请参阅 Amazon SageMaker AI 文档[多模型 endpoint](https://docs.aws.amazon.com/sagemaker/latest/dg/multi-model-endpoints.html)。

## 架构

本文定义了一套工作流，让 AI agent 通过调用基于 Amazon SageMaker AI 的预测型 ML 模型来做出数据驱动的业务决策。流程始于用户通过某个界面（例如聊天式助手或应用）进行交互。该输入由使用开源 Strands Agents SDK 开发的 AI agent 处理。Strands Agents 采用模型驱动的方式，这意味着开发者只需一个 prompt 和一组工具就能定义 agent，从而支持从简单助手到复杂自主工作流的快速开发。

当 agent 收到需要做预测的请求时（例如“2025 年下半年的销售额会是多少？”），驱动该 agent 的 LLM 会决定与托管 ML 模型的 Amazon SageMaker AI endpoint 交互。这可以通过两种方式实现：把 endpoint 直接作为 Strands Agents Python SDK 的自定义工具使用，或通过 MCP 调用该工具。使用 MCP 时，客户端应用可以发现 MCP server 暴露的工具、获取所需参数列表，并格式化发往 Amazon SageMaker 推理 endpoint 的请求。另一种方式是，agent 可以使用工具注解（例如 `@tool`）直接调用 SageMaker endpoint，绕过 MCP server，更直接地使用模型推理能力。

最后，SageMaker 托管模型生成的预测经由 agent 回传，最终送达用户界面，实现实时的智能响应。

## 前提条件

要开始使用本方案，请确保您具备：

- 一个将容纳您所有 AWS 资源的 AWS 账户。
- 一个用于访问 SageMaker AI 的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色。如需了解 IAM 如何与 SageMaker AI 配合工作，请参阅 [AWS Identity and Access Management for Amazon SageMaker AI](https://docs.aws.amazon.com/sagemaker/latest/dg/security-iam.html)。
- 对 [Amazon SageMaker Studio](https://aws.amazon.com/sagemaker/studio/) 的访问权限，以及一个 SageMaker AI notebook 实例，或 [PyCharm](https://www.jetbrains.com/pycharm/)、[Visual Studio Code](https://code.visualstudio.com/) 之类的交互式开发环境（IDE）。我们建议使用 SageMaker Studio，以便直接完成部署和推理。
- 对用于托管 LLM 的加速实例（GPU）的访问权限。

## 方案实现

在本方案中，我们实现了一套完整的工作流，演示如何把部署在 Amazon SageMaker AI 上的 ML 模型用作 AI agent 的专用工具。这种方式让 agent 无需深厚的 ML 专业知识就能访问并使用 ML 能力来增强决策。我们扮演一位数据科学家的角色，任务是构建一个能预测某个产品需求的 agent。为此，我们训练一个时间序列预测模型、部署它，并把它暴露给 AI agent。

第一阶段使用 Amazon SageMaker AI 训练模型。首先准备训练数据：生成合成时间序列数据，其中包含趋势、季节性和噪声成分，以模拟贴近真实的需求模式。数据准备之后进行特征工程，从时间序列数据中提取相关特征，包括星期几、月份和季度等时间特征，以有效捕捉季节性模式。在我们的示例中，我们使用 Amazon SageMaker AI 中以 1P 容器形式提供的 XGBoost 容器训练一个 XGBoost 模型，以构建能够基于历史模式预测未来需求值的回归模型。尽管本例选用 XGBoost 是因为它在许多用例中广为使用，您也可以根据要解决的问题选用自己偏好的容器和模型。限于本文篇幅，我们不会详细展开使用 XGBoost 训练模型的端到端示例。如需进一步了解，建议查阅文档 [Use XGBoost with the SageMaker Python SDK](https://sagemaker.readthedocs.io/en/stable/frameworks/xgboost/using_xgboost.html#use-xgboost-with-the-sagemaker-python-sdk)。使用以下代码：

```
from sagemaker.xgboost.estimator import XGBoost

xgb_estimator = XGBoost(...)
xgb_estimator.fit({'train': train_s3_path, 'validation': val_s3_path})
```

随后，训练好的模型被打包并部署到 SageMaker AI endpoint，使其可通过 API 调用进行实时推理：

```
predictor = xgb_estimator.deploy(
    initial_instance_count=1,
    instance_type=instance_type,
    serializer=JSONSerializer(),
    deserializer=JSONDeserializer()
)
```

模型部署完成并可用于推理后，您需要了解如何调用该 endpoint。要调用 endpoint，可以编写如下函数：

```
ENDPOINT_NAME = "serverless-xgboost"
REGION = boto3.session.Session().region_name

def invoke_endpoint(payload: list):
    """
        Use the model deployed on the Amazon SageMaker AI endpoint to generate predictions.
        Args:
            payload: a list of lists containing the inputs to generate predictions from
        Returns:
            predictions: an NumPy array of predictions
    """
    sagemaker_runtime = boto3.client("sagemaker-runtime", region_name=REGION)
    response = sagemaker_runtime.invoke_endpoint(
        EndpointName=ENDPOINT_NAME,
        Body=json.dumps(payload),
        ContentType="application/json",
        Accept="application/json"
    )
    predictions = json.loads(response['Body'].read().decode("utf-8"))
    return np.array(predictions)
```

请注意，`invoke_endpoint()` 函数已经写好了文档字符串（docstring）。这是确保它能被 LLM 当作工具使用的关键，因为描述正是让 LLM 为合适的任务选择合适的工具的依据。借助 `@tool` 装饰器，您可以把该函数变成一个 Strands Agents 工具：

```
from strands import tool

@tool()
def invoke_endpoint(payload: list):
    ....
```

要使用它，把它传给一个 Strands agent：

```
from strands import Agent

agent = Agent(
    model="us.amazon.nova-pro-v1:0", 
    tools=[generate_prediction_with_sagemaker]
)

agent(
    "Invoke the endpoint with this input:\n\n"
    f"<input>{test_sample}</input>\n\n"
    "Provide the output in JSON format {'predictions':<predictions>}"
)
```

运行这段代码时，您可以确认 agent 的输出——它正确识别出需要调用该工具，并执行了函数调用循环：

```
<thinking> To fulfill the User's request, I need to invoke the Amazon SageMaker 
endpoint with the provided input data. The input is a list of lists, which is the 
required format for the 'generate_prediction_with_sagemaker' tool. I will use this 
tool to get the predictions. </thinking> 

Tool #1: generate_prediction_with_sagemaker The predictions from the Amazon SageMaker
endpoint are as follows: 
```json {  "predictions": [89.8525238, 52.51485062, 58.35247421, 62.79786301, 85.51475525] } ```
```

当 agent 从 endpoint 工具收到预测结果后，它可以把这个结果作为其他流程的输入。例如，agent 可以编写代码，基于这些预测生成图表，并在对话式 UX 中展示给用户。它也可以把这些数值直接发送到 [AWS Quick Sight](https://aws.amazon.com/quicksight) 或 [Tableau](http://www.tableau.com/) 等商业智能（BI）工具，并自动更新 [SAP](http://www.sap.com/) 或 [Salesforce](http://www.salesforce.com/) 等企业资源规划（ERP）或客户关系管理（CRM）工具。

### 通过 MCP 连接 endpoint

您还可以进一步演进这一模式：让 MCP server 而不是 agent 本身去调用 endpoint。这样可以实现 agent 与工具逻辑的解耦，并形成更好的安全模式，因为拥有调用 endpoint 权限的将是 MCP server。为此，请使用 [FastMCP](https://gofastmcp.com/getting-started/welcome?gad_source=1&gad_campaignid=22521620347&gbraid=0AAAAACeCpg_Hi0k3Ql_OeCU0q96xoSh9M&gclid=CjwKCAjwprjDBhBTEiwA1m1d0n-o5wCNkDPbAbxBPgTP5-ui-wwO_LZaNqvVmUKj-1QsJ9SjpEBh-xoCJnwQAvD_BwE) 框架实现一个 MCP server，用它封装 SageMaker endpoint 并把它暴露为具有明确定义接口的工具。必须指定工具 schema，清晰定义该工具的输入参数和返回值，便于 AI agent 直接理解和使用。在定义函数时写好文档字符串即可达到这一效果。此外，server 必须配置为安全地处理身份验证，使其能够使用 AWS 凭证或 AWS 角色访问 SageMaker endpoint。在本示例中，我们把 server 运行在与 agent 相同的计算环境上，并使用 `stdio` 作为通信协议。对于生产工作负载，我们建议把 MCP server 运行在独立的 AWS 计算资源上，并使用基于 HTTPS 的传输协议（例如 Streamable HTTP）。如果您想了解如何以无服务器方式部署 MCP server，请参阅[这个 AWS 官方 GitHub 仓库](https://github.com/awslabs/run-model-context-protocol-servers-with-aws-lambda)。以下是一个 MCP server 示例：

```
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("SageMaker App")
ENDPOINT_NAME = os.environ["SAGEMAKER_ENDPOINT_NAME"]

@mcp.tool()
async def invoke_endpoint(payload: list):
    """ Use the model ... """
    [...]
    
if __name__ == "__main__":
    mcp.run(="stdio")
```

最后，把 ML 模型与 agent 框架集成。这首先要设置 Strands Agents，使其与 MCP server 建立通信，并把 ML 模型作为工具纳入其中。必须创建一套完整的工作流，确定 agent 应在何时、以何种方式使用 ML 模型来增强自身能力。实现内容包括编写决策逻辑，使 agent 能够基于从 ML 模型收到的预测做出有依据的判断。这一阶段以测试与评估收尾：让 agent 为测试场景生成预测，并据此采取相应操作，从而验证端到端的完整工作流。

```
from mcp import StdioServerParameters
from mcp.client.stdio import stdio_client
from strands.tools.mcp import MCPClient

# Create server parameters for stdio connection
server_params = StdioServerParameters(
    command="python3",  # Executable
    args=["server.py"],  # Optional command line arguments
    env={"SAGEMAKER_ENDPOINT_NAME": "<your-endpoint-name>"}
)

# Create an agent with MCP tools
with stdio_mcp_client:
    # Get the tools from the MCP server
    tools = stdio_mcp_client.list_tools_sync()
    # Create an agent with these tools
    agent = Agent(model="us.amazon.nova-pro-v1:0", tools=tools)
    # Invoke the agent
    agent(
        "Invoke the endpoint with this input:\n\n"
        f"<input>{test_sample}</input>\n\n"
        "Provide the output in JSON format {'predictions':<predictions>}"
    )
```

## 清理资源

当您完成对 Strands Agents Python SDK 与 Amazon SageMaker AI 上模型的试验后，可以删除自己创建的 endpoint，以免继续产生不必要的费用。为此，您可以使用 [AWS Management Console](https://aws.amazon.com/console/)、[SageMaker Python SDK](https://sagemaker.readthedocs.io/en/stable/) 或 [AWS SDK for Python（boto3）](https://boto3.amazonaws.com/v1/documentation/api/latest/index.html)：

```
# SageMaker Python SDK
predictor.delete_model()
predictor.delete_endpoint()

# Alternatively, boto3
sagemaker_runtime.delete_endpoint(EndpointName=endpoint_name)
```

## 结论

本文演示了如何通过使用 Amazon SageMaker AI 和 MCP 整合预测型 ML 模型来增强 AI agent 的能力。借助开源的 Strands Agents SDK 和 SageMaker AI 灵活的部署选项，开发者可以构建把对话式 AI 与强大的预测分析能力结合起来的高级 AI 应用。我们给出的方案提供两条集成路径：通过工具注解直接访问 endpoint，以及基于 MCP 的集成，让开发者可以灵活选择最适合自身用例的方式。无论您是在构建需要预测能力的客户服务聊天助手，还是在开发复杂的自主工作流，这套架构都为您的 AI 应用提供了安全、可扩展且模块化的基础。随着组织不断寻求让 AI agent 更智能、更数据驱动的方法，Amazon SageMaker AI、MCP 和 Strands Agents SDK 的组合为构建下一代 AI 驱动应用提供了强有力的方案。

对于不熟悉如何把 MCP server 连接到 Amazon SageMaker AI 上运行负载的读者，我们推荐 AWS 人工智能博客上的 [Extend large language models powered by Amazon SageMaker AI using Model Context Protocol](https://aws.amazon.com/blogs/machine-learning/extend-large-language-models-powered-by-amazon-sagemaker-ai-using-model-context-protocol/) 一文，其中详细说明了使用 Amazon SageMaker AI 构建 agentic AI 方案所需的流程与步骤。

如需进一步了解 AWS 对 MCP 标准的承诺，我们建议阅读 AWS 开源博客上的 [Open Protocols for Agent Interoperability Part 1: Inter-Agent Communication on MCP](https://aws.amazon.com/blogs/opensource/open-protocols-for-agent-interoperability-part-1-inter-agent-communication-on-mcp/)，我们在那里宣布 AWS 加入 MCP 指导委员会，以确保开发者无需绑定单一标准即可构建突破性的 agentic 应用。如需进一步了解如何把 MCP 与 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 等其他 AWS 技术配合使用，我们建议阅读 AWS 人工智能博客上的 [Harness the power of MCP servers with Amazon Bedrock Agents](https://aws.amazon.com/blogs/machine-learning/harness-the-power-of-mcp-servers-with-amazon-bedrock-agents/)。最后，AWS Solutions Library 中的 [Guidance for Deploying Model Context Protocol Servers on AWS](https://aws.amazon.com/solutions/guidance/deploying-model-context-protocol-servers-on-aws/) 提供了在 AWS 上安全部署和扩展 MCP server 的优秀方案。
