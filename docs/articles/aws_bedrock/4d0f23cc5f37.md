# Amazon Bedrock Flows 现已在公开预览版中支持内联代码节点

今天，我们欣然宣布，[Amazon Bedrock Flows](https://aws.amazon.com/bedrock/flows/) 现已支持[内联代码节点](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-nodes.html#flows-nodes-data)的公开预览。借助这一强大的新能力，你可以直接在工作流中编写 Python 脚本，不再需要为简单逻辑单独创建 [AWS Lambda](https://aws.amazon.com/lambda) 函数。该功能简化了预处理和后处理任务（例如数据归一化和响应格式化），让生成式 AI 应用的开发更简单，也使组织内更多人能够参与其中。通过消除采用障碍并降低维护开销，内联代码功能加速了企业对生成式 AI 解决方案的采用，带来更快的迭代周期，并让更多人参与到 AI 应用构建中。

使用 Amazon Bedrock Flows 的组织现在可以使用内联代码节点来设计和部署工作流，在 Amazon Bedrock 环境内完整地构建更具可扩展性和效率的生成式 AI 应用，同时实现以下目标：

- **预处理** – 在将输入数据发送给大语言模型（LLM）之前对其进行转换，而无需设置单独的 Lambda 函数。例如，从 JSON 中提取特定字段、格式化文本数据或归一化数值。
- **后处理** – 直接在工作流中对模型输出执行操作。例如，从响应中提取实体、为下游系统格式化 JSON，或对结果应用业务规则。
- **复杂用例** – 管理复杂的多步骤生成式 AI 工作流的执行，这些工作流可以调用 opencv、scipy 或 pypdf 等流行包。
- **对构建者友好** – 通过 [Amazon Bedrock API](https://docs.aws.amazon.com/bedrock/latest/APIReference/welcome.html) 和 [AWS Management Console](https://aws.amazon.com/console) 创建和管理内联代码。
- **可观测性** – 无缝的用户体验，能够追踪每个节点的输入和输出。

在本文中，我们讨论这项新功能的优势，并展示如何在 Amazon Bedrock Flows 中使用内联代码节点。

## Amazon Bedrock Flows 中内联代码的优势

[Thomson Reuters](https://www.thomsonreuters.com/) 是一家全球信息服务公司，为法律、税务、会计、媒体和企业等领域的专业人士提供重要的新闻、洞察和技术解决方案。它处理复杂的多步骤生成式 AI 用例，这些用例需要在工作流中进行简单的预处理和后处理。借助 Amazon Bedrock Flows 的内联代码功能，Thomson Reuters 现在可以从以下方面受益：

- **简化的流程管理** – 免去了为每个自定义代码块创建和维护单独 Lambda 函数的需要，使在庞大用户群（超过 16,000 名用户和 6,000 个链）中管理数千个工作流变得简单直接，同时减少运维开销。
- **灵活的数据处理** – 支持在调用 LLM 之前直接预处理数据，并对 LLM 响应进行后处理，包括通过单一接口与内部 AWS 服务和第三方 API 交互。
- **DIY 流程创建** – 帮助用户通过自助式界面用自定义代码块构建复杂工作流，既不让用户面对底层基础设施的复杂性，也无需管理 Lambda 函数。

## 解决方案概览

在接下来的章节中，我们展示如何创建一个简单的 Amazon Bedrock 流程并添加内联代码节点。我们的示例展示了一个实际应用：我们将构建一个处理用户音乐播放列表请求的流程，并加入预处理和后处理内联代码节点，以处理数据校验和响应格式化。

## 先决条件

在实施这些新能力之前，请确保你具备以下条件：

- 一个 AWS 账户
- 其他 Amazon Bedrock 服务已就位：在 [Amazon Bedrock Prompt Management](https://aws.amazon.com/es/bedrock/prompt-management/) 中为客服交互[创建并测试你的基础 prompt](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-create.html)；使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 并遵循相关规则[创建护栏](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-components.html)
- 工作流所需的辅助 AWS 服务中的资源，例如 [Amazon DynamoDB](https://aws.amazon.com/dynamodb)、[Amazon Simple Storage Service](https://docs.aws.amazon.com/s3)（Amazon S3）和 [Amazon Simple Notification Service](https://aws.amazon.com/sns/)（Amazon SNS）
- 所需的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）权限：[访问 Amazon Bedrock Flows](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-permissions.html) 的权限，以及对 [Amazon Bedrock 中 LLM 的适当访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access-permissions.html)

这些组件就位后，你就可以在生成式 AI 用例中使用具备内联代码能力的 Amazon Bedrock Flows。

## 使用内联代码节点创建流程

请完成以下步骤来创建你的流程：

- 在 Amazon Bedrock 控制台的导航窗格中，在 **Builder tools** 下选择 **Flows**。
- 创建一个新流程，例如 easy-inline-code-flow。有关创建流程的详细说明，请参阅 [Amazon Bedrock Flows is now generally available with enhanced safety and traceability](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-flows-is-now-generally-available-with-enhanced-safety-and-traceability/)。
- 添加一个内联代码节点。（在本示例中，我们为两个独立的 prompt 创建两个节点。）

Amazon Bedrock 提供不同的[节点类型](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-nodes.html)来构建你的 prompt 流程。在本示例中，我们使用内联代码节点，而不为生成式 AI 应用的自定义代码调用 Lambda 函数。该流程中有两个内联代码节点。我们扩展了文档中[使用单个 prompt 创建流程](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-ex-prompt.html)的示例。新的节点类型 **Inline Code** 位于左侧窗格的 **Nodes** 标签页上。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/14/ml-19171-image-1.png)

- 在将数据发送到 prompt 节点 `prompt_1` 之前，在 `Preprocessing_InlineCode` 节点中添加一些处理代码。撰写本文时仅支持 Python 3。在本示例中，我们检查用户请求的歌曲数量是否超过 10，若超过则将其设为 10。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/14/ml-19171-image-2.png)

此外还提供用于编写代码的 Python 代码编辑器和示例代码模板。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/14/ml-19171-image-3.png)

```
import json
def __func():
    try:
```

## 注意事项

在 Amazon Bedrock Flows 中使用内联代码节点时，需要注意以下几点：

- 代码在由 AWS 托管、安全且不与他人共享的沙箱环境中执行，该环境没有互联网访问
- 该功能支持 Python 3.12 及以上版本
- 它能高效处理二进制大小最高 4 MB（约 400 万个字符）的代码
- 它支持 opencv、scipy 和 pypdf 等流行包
- 每个 AWS 账户支持 25 个并发的代码执行会话

## 结论

Amazon Bedrock Flows 中内联代码节点的集成标志着在推动生成式 AI 开发普惠化方面的重要进步，减少了为基础处理任务管理单独 Lambda 函数的复杂性。这一增强直接回应了企业客户对更精简开发体验的需求，帮助开发者专注于构建复杂的 AI 工作流，而不是管理基础设施。

Amazon Bedrock Flows 中的内联代码现已在以下 [AWS 区域](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region) 的公开预览版中可用：美国东部（弗吉尼亚北部、俄亥俄）、美国西部（俄勒冈）和欧洲（法兰克福）。要开始使用，请打开 Amazon Bedrock 控制台或使用 Amazon Bedrock API，开始用 Amazon Bedrock Flows 构建流程。了解更多信息，请参阅 [Create your first flow in Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-get-started.html) 和 [Track each step in your flow by viewing its trace in Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-trace.html)。
