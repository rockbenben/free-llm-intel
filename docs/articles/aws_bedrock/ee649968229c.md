# 使用 K8sGPT 与 Amazon Bedrock 简化 Kubernetes 集群维护

随着 Kubernetes 集群日益复杂，高效地管理它们也变得愈发困难。排查现代 Kubernetes 环境的问题，需要横跨多个领域的深厚专业知识——网络、存储、安全，以及不断扩张的 CNCF 插件生态。由于 Kubernetes 如今承载着关键业务负载，快速解决问题已成为维持业务连续性的首要任务。

把 [K8sGPT](https://k8sgpt.ai/) 与 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 这类先进的[生成式 AI](https://aws.amazon.com/generative-ai/) 工具集成起来，可以彻底改变 Kubernetes 集群的运维与维护方式。这些方案远不止于简单的 AI 辅助排障，它们提供企业级的运维智能，改变了团队管理基础设施的方式。凭借预训练知识以及内置分析器和自定义分析器，这些工具能够实现快速调试、持续监控和主动的问题识别——让团队在问题影响到关键负载之前就将其解决。

作为 CNCF 沙箱项目，K8sGPT 通过扫描集群，并借助包括 Anthropic 的 Claude、OpenAI 以及 [Amazon SageMaker](https://aws.amazon.com/sagemaker/) 自定义模型和开源模型在内的前沿 AI 模型，用通俗易懂的英文给出可执行的洞察，从而革新 Kubernetes 管理。除基础排障之外，K8sGPT 还具备成熟的[自动修复](https://github.com/k8sgpt-ai/k8sgpt-operator/blob/main/AUTO_REMEDIATION.md)能力，其表现就像一位经验丰富的站点可靠性工程师（SRE）：对照当前集群状态跟踪变更差异、强制执行可配置的风险阈值，并通过 Mutation 自定义资源提供回滚机制。它对 [Model Communication Protocol（MCP）服务器](https://k8sgpt.ai/docs/reference/mcp)的支持，使 AI 助手能够以结构化、实时的方式交互，实现持久的集群分析和自然语言操作。Amazon Bedrock 则通过提供与 AWS 无缝集成的全托管基础模型访问能力，为这一生态提供补充。这种做法代表着从被动排障到主动运维智能的范式转变——AI 在企业级管控和完整审计轨迹之下协助解决问题。

本文演示在 AWS 上以两种模式运行 K8sGPT 与 Amazon Bedrock 的最佳实践：K8sGPT CLI 和 K8sGPT Operator，并展示该方案如何帮助 SRE 通过持续监控和运维智能来简化 Kubernetes 集群管理。

## 解决方案概览

K8sGPT 有两种运行模式：用于本地按需分析的 K8sGPT CLI，以及用于集群内持续监控的 K8sGPT Operator。CLI 通过命令行交互提供灵活性；Operator 则与 Kubernetes 工作流集成，把结果存储为自定义资源并支持自动化修复。两种运行模式都可以调用 Amazon Bedrock 模型来提供详细的分析和建议。

### K8sGPT CLI 架构

下面的架构图显示：用户的角色通过 [AWS IAM Identity Center](https://aws.amazon.com/iam/identity-center/) 完成身份验证后，用户运行 K8sGPT CLI 扫描 [Amazon Elastic Kubernetes Service](https://aws.amazon.com/eks/)（Amazon EKS）资源，并调用 Amazon Bedrock 模型进行分析。K8sGPT CLI 提供交互式界面用于获取扫描结果，模型调用日志则发送到 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 以便进一步监控。这一套配置便于在 CLI 中排查和分析 Kubernetes 资源，同时由 Amazon Bedrock 模型针对 Amazon EKS 环境给出洞察和建议。

K8sGPT CLI 自带丰富的功能，包括自定义分析器、过滤器、匿名化、远程缓存以及多种集成选项。更多细节参见[入门指南](https://docs.k8sgpt.ai/getting-started/getting-started/)。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/19/ML-17546-image-1-1024x719.png)

### K8sGPT Operator 架构

下面的架构图展示了一种方案：安装在 EKS 集群中的 K8sGPT Operator 使用 Amazon Bedrock 模型实时分析和解释来自 EKS 集群的发现结果，帮助用户理解问题并优化工作负载。用户只需通过 `kubectl` 这类标准 Kubernetes 方式发起查询，就能从 K8sGPT Operator 收集这些实例洞察。模型调用日志（其中包含 K8sGPT Operator 的详细发现结果）会记录到 CloudWatch 中以便进一步分析。

在这种模式下，除了 `kubectl` CLI 之外不需要安装其他 CLI 工具。此外，用户所担任的单点登录（SSO）角色无需具备 Amazon Bedrock 访问权限，因为 K8sGPT Operator 会担任一个 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）机器角色来调用 Amazon Bedrock 大语言模型（LLM）。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/30/ML-17546-image-11.png)

### 何时使用哪种模式

下表对比了这两种模式及其常见使用场景。

|  | **K8sGPT CLI** | **K8sGPT Operator** |
| --- | --- | --- |
| 访问管理 | 人工角色（IAM Identity Center） | 机器角色（IAM） |
| 特性 | 功能丰富：分析器、过滤器、匿名化、集成 | 持续扫描与错误协调；与 AWS 服务的直接集成；IAM 权限变更灵活 |
| 常见使用场景 | 与受支持的工具（例如 Prometheus 和 Grafana）集成；使用自定义分析器和过滤实现细致且定制的分析；有匿名化需求；基于用户的排障 | 持续监控与运维；Kubernetes 运维仪表盘与日常运营（BAU）；与可观测性工具或额外的[自定义分析器](https://docs.k8sgpt.ai/tutorials/custom-analyzers/)集成 |

下面几节将带你走完 K8sGPT 的两种安装模式。

## 安装 K8sGPT CLI

按以下步骤安装 K8sGPT CLI：

- 在 US West（Oregon）AWS 区域启用 Amazon Bedrock。务必包含以下附加到角色上的策略，以便申请或修改对 Amazon Bedrock FM 的访问权限： `aws-marketplace:Subscribe` `aws-marketplace:Unsubscribe` `aws-marketplace:ViewSubscriptions`
- 在 US West（Oregon）区域申请访问 Amazon Bedrock FM：在 Amazon Bedrock 控制台的导航窗格中，于 **Bedrock configurations** 下选择 **Model access**。在 **Model access** 页面上选择 **Enable specific models**。选中相应模型，然后依次选择 **Next** 和 **Submit** 来申请访问权限。
- 按照[官方说明](https://docs.k8sgpt.ai/getting-started/installation/)安装 K8sGPT。
- 将 Amazon Bedrock 及 FM 作为 AI 后端提供商添加到 K8sGPT 配置中：

```
k8sgpt auth add --backend amazonbedrock --model anthropic.claude-3-5-sonnet-20240620-v1 --providerRegion <region-name>
```

**注意：在撰写本文时，K8sGPT 已支持 Anthropic 最先进的 Claude 4 Sonnet 和 3.7 Sonnet 模型。**

- 把 Amazon Bedrock 后端设为默认：

```
k8sgpt auth default -p amazonbedrock
```

- 更新 `Kubeconfig` 以连接到 EKS 集群：

```
aws eks update-kubeconfig --region <region-name> --name my-cluster
```

- 使用 Amazon Bedrock 分析集群内的问题：

```
k8sgpt analyze --explain --backend amazonbedrock
```

## 安装 K8sGPT Operator

要安装 K8sGPT Operator，请先完成以下前置条件：

- 安装最新版本的 [Helm](https://helm.sh/docs/intro/install/)。要检查版本，请运行 `helm version`。
- 安装最新版本的 [eksctl](https://eksctl.io/installation/)。要检查版本，请运行 `eksctl version`。

### 创建 EKS 集群

使用预先定义好的 `eksctl` 配置文件，通过 `eksctl` 创建 EKS 集群：

```
cat >cluster-config.yaml <<EOF
apiVersion: eksctl.io/v1alpha5
kind: ClusterConfig
metadata:
  name: eks
  region: us-west-2
  version: "1.32"
  tags:
    environment: eks
iam:
  withOIDC: true
  podIdentityAssociations: 
  - namespace: kube-system
    serviceAccountName: cluster-autoscaler
    roleName: pod-identity-role-cluster-autoscaler
    wellKnownPolicies:
      autoScaler: true  
managedNodeGroups:
  - name: managed-ng
    instanceType: m5.large
    minSize: 2
    desiredCapacity: 3
    maxSize: 5
    privateNetworking: true
    volumeSize: 30
    volumeType: gp3 
    tags:
      k8s.io/cluster-autoscaler/enabled: "true"
      k8s.io/cluster-autoscaler/eks: "owned"      
addonsConfig:
  autoApplyPodIdentityAssociations: true
addons:
  - name: eks-pod-identity-agent 
    tags:
      team: eks
  - name: vpc-cni
    version: latest  
  - name: aws-ebs-csi-driver
    version: latest  
  - name: coredns
    version: latest 
  - name: kube-proxy
    version: latest
cloudWatch:
 clusterLogging:
   enableTypes: ["*"]
   logRetentionInDays: 30
EOF

eksctl create cluster -f cluster-config.yaml
```

你应该会看到如下预期输出：
`EKS cluster "eks" in "us-west-2" region is ready`

### 创建 Amazon Bedrock 与 CloudWatch 的 VPC 私有终端节点（可选）

为实现 Amazon EKS 与 Amazon Bedrock 以及 CloudWatch 之间的私有通信，建议使用虚拟私有云（VPC）私有终端节点。这样可以确保通信保留在 VPC 内部，提供安全且私密的通道。

请参考[创建 VPC 终端节点](https://docs.aws.amazon.com/vpc/latest/privatelink/create-interface-endpoint.html#create-interface-endpoint-aws)来设置 Amazon Bedrock 和 CloudWatch 的 VPC 终端节点。

### 创建 IAM 策略、信任策略和角色

按以下步骤创建 IAM 策略、信任策略和角色，以最小权限原则只允许 K8sGPT Operator 与 Amazon Bedrock 交互：

- 创建带有 Amazon Bedrock 权限的角色策略：

```
cat >k8sgpt-bedrock-permission.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream"
      ],
      "Resource": "arn:aws:bedrock:us-west-2::foundation-model/anthropic.claude-3-5-sonnet-20240620-v1:0" 
    }
  ]
}
EOF
```

- 创建权限策略：

```
aws iam create-policy \
    --policy-name bedrock-k8sgpt-policy \
    --policy-document file://k8sgpt-bedrock-permission.json
```

- 创建信任策略：

```
cat >k8sgpt-bedrock-Trust-Policy.json <<EOF
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowEksAuthToAssumeRoleForPodIdentity",
            "Effect": "Allow",
            "Principal": {
                "Service": "pods.eks.amazonaws.com"
            },
            "Action": [
                "sts:AssumeRole",
                "sts:TagSession"
            ]
        }
    ]
}
EOF
```

- 创建角色并附加信任策略：

```
aws iam create-role \
    --role-name k8sgpt-bedrock \
    --assume-role-policy-document file://k8sgpt-bedrock-Trust-Policy.json
aws iam attach-role-policy --role-name k8sgpt-bedrock --policy-arn=arn:aws:iam::123456789:policy/bedrock-k8sgpt-policy
```

### 安装 Prometheus

Prometheus 将用于监控。使用以下命令通过 Helm 在 `k8sgpt-operator-system` 命名空间中安装 Prometheus：

```
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update 
helm install prometheus prometheus-community/kube-prometheus-stack -n k8sgpt-operator-system --create-namespace
```

### 通过 Helm 安装 K8sGPT Operator

通过 Helm 安装 K8sGPT Operator，并启用 Prometheus 和 Grafana：

```
helm upgrade --install release k8sgpt/k8sgpt-operator -n k8sgpt-operator-system --set serviceAccount.annotations."eks\.amazonaws\.com/role-arn"=arn:aws:iam::123456789:role/k8sgpt-bedrock --set serviceMonitor.enabled=true --set grafanaDashboard.enabled=true
```

给 K8sGPT 控制器管理器打补丁，使其能被 Prometheus operator 识别：

```
kubectl -n k8sgpt-operator-system patch serviceMonitor release-k8sgpt-operator-controller-manager-metrics-monitor -p '{"metadata":{"labels":{"release":"prometheus"}}}' --type=merge
```

### 关联 EKS Pod Identity

EKS Pod Identity 是一项 AWS 功能，它让集群管理员可以直接通过 Amazon EKS，把具备最小权限的 IAM 角色与 Kubernetes 服务账户关联起来，从而简化 Kubernetes 应用获取 IAM 权限的方式。它提供了一种简单的方法，让 EKS pod 可以调用 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）等 AWS 服务。更多细节参见[了解 EKS Pod Identity 如何为 pod 授予 AWS 服务访问权限](https://docs.aws.amazon.com/eks/latest/userguide/pod-identities.html)。

使用以下命令执行关联：

```
aws eks create-pod-identity-association \
          --cluster-name eks \
          --namespace k8sgpt-operator-system \
          --service-account k8sgpt-k8sgpt-operator-system  \
          --role-arn arn:aws:iam::123456789:role/k8sgpt-bedrock
```

### 以 Amazon Bedrock 作为后端扫描集群

完成以下步骤：

- 使用下面的 YAML 部署 K8sGPT 资源，以 Amazon Bedrock 上 Anthropic 的 Claude 3.5 模型作为后端：

```
cat > k8sgpt-bedrock.yaml<<EOF
apiVersion: core.k8sgpt.ai/v1alpha1
kind: K8sGPT
metadata:
  name: bedrock
  namespace: k8sgpt-operator-system
spec:
  ai:
    enabled: true
    model: anthropic.claude-3-5-sonnet-20240620-v1:0

    backend: amazonbedrock
    language: english
  noCache: false
  repository: ghcr.io/k8sgpt-ai/k8sgpt
  version: v0.4.12

kubectl apply -f k8sgpt-bedrock.yaml
```

- 当 `k8sgpt-bedrock` pod 运行起来后，使用以下命令查看扫描结果列表：

```
kubectl get results -n k8sgpt-operator-system
```

- 使用以下命令查看每条扫描结果的详情：

```
kubectl get results <scanresult> -n k8sgpt-operator-system -o json
```

## 使用场景——用 K8sGPT Operator 持续扫描 EKS 集群

本节演示如何利用 K8sGPT Operator 对 Amazon EKS 集群进行持续监控。通过与常用的可观测性工具集成，该方案通过两个关键界面提供全面的集群健康可见性：一个可视化扫描结果和集群健康指标的 Grafana 仪表盘，以及记录 Amazon Bedrock 提供的详细 AI 分析和建议的 CloudWatch 日志。这种自动化方式免去了手工执行 kubectl 命令的需要，同时确保主动识别并解决潜在问题。与现有监控工具的集成简化了运维，并通过持续评估和智能洞察帮助维持集群处于最佳健康状态。

### 使用 CloudWatch 仪表盘查看已识别的问题并获取建议

Amazon Bedrock 模型调用日志会记录到我们之前设置好的 CloudWatch 中。你可以使用 CloudWatch Logs Insights 查询来过滤模型调用的输入与输出，获取集群扫描建议，并把结果输出为一个仪表盘以便快速查看。完成以下步骤：

- 在 CloudWatch 控制台上[创建仪表盘](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/create_dashboard.html)。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/19/ML-17546-image-6-1024x874.jpeg)

- 在 CloudWatch 控制台上选择 CloudWatch 日志组，并运行以下查询，以过滤 K8sGPT Operator 执行的扫描结果：

```
fields ,input.inputBodyJson.prompt,output.outputBodyJson.completion
| sort  desc
| filter identity.arn like "k8sgpt-bedrock"
```

- 选择 **Create Widget** 保存该仪表盘。

它会自动展示带有 K8sGPT Operator 输入和输出的模型调用日志。你可以展开日志，查看模型输入中的错误，以及 Amazon Bedrock 后端给出的建议输出。

## 用自定义分析器扩展 K8sGPT

K8sGPT 的自定义分析器功能让团队可以为其 Kubernetes 环境创建专门的检查项，突破内置分析能力的边界。这一强大的扩展机制使组织能够把特定的运维要求和最佳实践固化到 K8sGPT 的扫描流程中，从而可以监控默认分析器覆盖不到的集群健康维度。

你可以创建自定义分析器来监控集群健康的各个方面。例如，你可能想监控节点上的 Linux 磁盘使用率——这是一个常见且可能影响集群稳定性的运维关注点。下面的步骤演示如何实现并部署这样一个分析器：

首先，创建分析器代码：

```
package analyzer

import (
    "context"
    rpc "buf.build/gen/go/k8sgpt-ai/k8sgpt/grpc/go/schema/v1/schemav1grpc"
    v1 "buf.build/gen/go/k8sgpt-ai/k8sgpt/protocolbuffers/go/schema/v1"
    "github.com/ricochet2200/go-disk-usage/du"
)

func (a *Handler) Run(context.Context, *v1.RunRequest) (*v1.RunResponse, error) {
    usage := du.NewDiskUsage("/")
    diskUsage := int((usage.Size() - usage.Free()) * 100 / usage.Size())
    return &v1.RunResponse{
        Result: &v1.Result{
            Name:    "diskuse",
            Details: fmt.Sprintf("Disk usage is %d%%", diskUsage),
            Error: []*v1.ErrorDetail{{
                Text: fmt.Sprintf("High disk usage detected: %d%%", diskUsage),
            }},
        },
    }, nil
}
```

把你的分析器构建成 docker 镜像，并将分析器部署到集群中：

```
apiVersion: apps/v1
kind: Deployment
metadata:
  name: diskuse-analyzer
  namespace: k8sgpt-system
spec:
  replicas: 1
  selector:
    matchLabels:
      app: diskuse-analyzer
  template:
    metadata:
      labels:
        app: diskuse-analyzer
    spec:
      containers:
      - name: diskuse-analyzer
        image: <your-registry>/diskuse-analyzer:latest
        ports:
        - containerPort: 8085
---
apiVersion: v1
kind: Service
metadata:
  name: diskuse-analyzer
  namespace: k8sgpt-system
spec:
  selector:
    app: diskuse-analyzer
  ports:
    - protocol: TCP
      port: 8085
      targetPort: 8085
```

最后，配置 K8sGPT 使用你的自定义分析器：

```
apiVersion: core.k8sgpt.ai/v1alpha1
kind: K8sGPT
metadata:
  name: k8sgpt-instance
  namespace: k8sgpt-system
spec:
  customAnalyzers:
    - name: diskuse
      connection:
        url: diskuse-analyzer
        port: 8085
```

这种做法让你在扩展 K8sGPT 能力的同时，保持它与 Kubernetes 生态的集成。自定义分析器可用于实现专门的健康检查、安全扫描，或任何符合你组织需求的集群分析逻辑。当与 K8sGPT 通过 Amazon Bedrock 提供的 AI 分析结合时，这些自定义检查会用通俗易懂的英文给出详细且可执行的洞察，帮助团队快速理解并解决潜在问题。

## K8sGPT 的隐私考量

K8sGPT 通过其分析器收集数据，包括容器状态消息和 pod 详情；在使用 `--explain` 标志时，这些数据可能展示给用户或发送给 AI 后端。只有在用户通过该标志主动选择、并向该后端完成身份验证时，数据才会与 AI 后端共享。为增强隐私，你可以在共享之前使用 `--anonymize` 标志对 deployment 名称和命名空间等敏感数据做匿名化处理。除了分析功能所必需的数据之外，K8sGPT 不会收集日志或 API server 数据。这些做法确保用户对自己的数据拥有控制权，且数据被安全、透明地处理。更多信息请参见 K8sGPT 文档中的 Privacy 部分。
