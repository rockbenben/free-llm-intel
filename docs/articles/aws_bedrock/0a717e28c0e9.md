# 商业智能民主化：BGL 与 Claude Agent SDK 和 Amazon Bedrock AgentCore 的历程

*本文与 BGL 的 James Luo 共同撰写。*

数据分析正在成为 AI agents 的高影响力用例。根据 Anthropic 的[《2026 年 AI agents 现状报告》](https://cdn.sanity.io/files/4zrzovbb/website/cd77281ebc251e6b860543d8943ede8d06c4ef50.pdf)，60% 的组织将数据分析和报告生成列为最具影响力的 agentic AI 应用。65% 的企业将其列为首要任务。在实践中，企业面临两个常见挑战：

- 不具备技术知识的业务用户依赖数据团队进行查询，这既耗时又形成瓶颈。
- 传统的 text-to-SQL 解决方案无法提供一致且准确的结果。

与许多其他企业一样，BGL 在数据分析和报告用例上也面临类似挑战。[BGL](https://www.bglcorp.com/) 是自助管理退休金基金（SMSF）管理解决方案的领先提供商，帮助个人管理自己或客户退休储蓄的复杂合规与报告事务，服务覆盖 15 个国家的 12,700 多家企业。BGL 的方案通过 400 多张分析表处理复杂的合规与财务数据，每张表代表一个特定业务领域，例如汇总的客户反馈、投资表现、合规跟踪和财务报告。BGL 的客户和员工需要从数据中寻找洞察。例如，*上季度哪些产品的负面反馈最多？*或者*向我展示高净值账户的投资趋势*。通过与 [Amazon Web Services（AWS）](https://aws.amazon.com/) 合作，BGL 构建了一个使用 Claude Agent SDK 的 AI agent，托管在 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 上。借助该 AI agent，业务用户可以用自然语言检索分析洞察，同时满足金融服务的安全与合规要求，包括会话隔离和基于身份的访问控制。

在这篇博文中，我们探讨 BGL 如何使用 [Claude Agent SDK](https://platform.claude.com/docs/en/agent-sdk/overview) 和 Amazon Bedrock AgentCore 构建其可用于生产的 AI agent。我们涵盖 BGL 实施的三个关键方面：

- 为什么构建坚实的数据基础对于可靠的、基于 AI agent 的 text-to-SQL 解决方案至关重要
- BGL 如何使用 Claude Agent SDK 设计其 AI agent，以实现代码执行、上下文管理和特定领域专业知识
- BGL 如何使用 AgentCore 在生产环境中提供理想的有状态执行会话，从而打造更安全、更可扩展的 AI agent。

## 为基于 AI agent 的 text-to-SQL 方案奠定坚实的数据基础

当工程团队为分析用例实现 AI agent 时，一种常见的反模式是让 agent 处理所有事情，包括理解数据库模式、转换复杂数据集、理清分析所需的业务逻辑以及解读结果。这样的 AI agent 很可能产生不一致的结果，并因错误地连接表、遗漏边界情况或给出错误的聚合而失败。

BGL 使用其现有的、由 [Amazon Athena](https://aws.amazon.com/athena/) 和 [dbt Labs](https://www.getdbt.com/) 支撑的成熟大数据方案，来处理和转换来自各种业务数据源的数 TB 原始数据。提取、转换和加载（extract, transform, and load，ETL）过程构建分析表，每张表回答某一类特定的业务问题。这些表是经过聚合、非规范化的数据集（包含指标与汇总），为商业智能（business intelligence，BI）工具、AI agents 和应用提供可直接使用的*单一事实来源*。有关如何用 Athena 和 dbt 构建 serverless 数据转换架构的详情，请参阅[宝马集团如何用 dbt 和 Amazon Athena 构建 serverless 太字节级数据转换架构](https://aws.amazon.com/blogs/big-data/how-bmw-group-built-a-serverless-terabyte-scale-data-transformation-architecture-with-dbt-and-amazon-athena/)。

AI agent 的职责是在数据系统内处理复杂的数据转换，专注于解读用户的自然语言问题、进行转换，并针对结构良好的分析表生成 SQL SELECT 查询。必要时，AI agent 会编写 Python 脚本进一步处理结果并生成可视化。这种职责分离显著降低了幻觉风险，并带来几项关键好处：

- **一致性**：数据系统以更确定性的方式处理复杂的业务逻辑：连接、聚合和业务规则都由数据团队提前验证。AI agent 的任务变得简单直接：解读问题并针对这些表生成基本的 SELECT 查询。
- **性能**：分析表经过预聚合，并通过适当的索引进行了优化。agent 执行基本查询，而不是跨原始表做复杂连接，因此即使面对大型数据集也能获得更快的响应时间。
- **可维护性与治理**：业务逻辑位于数据系统中，而不是 AI 的上下文窗口里。这有助于确保 AI agent 与其他使用者（例如 BI 工具）依赖同一个*单一事实来源*。如果业务规则发生变化，数据团队会在 dbt 中更新数据转换逻辑，AI agent 会自动使用反映这些变化的更新后的分析表。

> “许多人认为 AI agent 非常强大，可以跳过数据平台的建设；他们希望 agent 包办一切。但你无法用这种方式获得一致且准确的结果。每一层都应当在恰当的层级解决复杂性”
>         – James Luo，BGL 数据与 AI 负责人

BGL 的开发团队一直在使用由 [Amazon Bedrock](https://aws.amazon.com/bedrock/?trk=1f887566-8561-4bf2-a30b-f383e290b094&sc_channel=ps&trk=1f887566-8561-4bf2-a30b-f383e290b094&sc_channel=ps&ef_id=Cj0KCQiAyP3KBhD9ARIsAAJLnnZ8Kn-sydoV8ec5Q0NwcVcZUiCDLjtjRh9Ksd2TKJgZK4Y35g2vglsaAi23EALw_wcB:G:s&s_kwcid=AL!4422!3!785447157285!e!!g!!amazon%20bedrock&gad_campaignid=23296345364&gbraid=0AAAAADjHtp9hOwczjO4_Fpn6xLENuR6XO&gclid=Cj0KCQiAyP3KBhD9ARIsAAJLnnZ8Kn-sydoV8ec5Q0NwcVcZUiCDLjtjRh9Ksd2TKJgZK4Y35g2vglsaAi23EALw_wcB) 支撑的 [Claude Code](https://code.claude.com/docs/en/overview) 作为其 AI 编程助手。这种集成使用临时的、基于会话的访问来降低凭证暴露风险，并与现有身份提供商集成，以符合金融服务合规要求。有关集成详情，请参阅[《Claude Code 与 Amazon Bedrock 指南》](https://aws.amazon.com/solutions/guidance/claude-code-with-amazon-bedrock/)。

在日常使用 Claude Code 的过程中，BGL 认识到它的核心能力不仅限于编程。BGL 利用了它对复杂问题进行推理、编写和执行代码，以及自主与文件和系统交互的能力。[Claude Agent SDK](https://platform.claude.com/docs/en/agent-sdk/overview) 将同样的 agentic 能力打包成 Python 和 TypeScript SDK，使开发者能够在 Claude Code 之上构建自定义 AI agents。对 BGL 而言，这意味着他们可以构建一个具备以下能力的分析型 AI agent：

- **代码执行**：agent 编写并运行 Python 代码，处理分析表返回的数据集并生成可视化
- **自动上下文管理**：长时间运行的会话不会突破 token 限制
- **沙箱化执行**：生产级的隔离与权限控制
- **模块化记忆与知识**：用 `CLAUDE.md` 文件保存项目上下文，用 Agent Skills 保存产品线特定的领域专业知识

### 为什么代码执行对数据分析很重要

分析查询往往返回数千行，有时甚至超过数 MB 的数据。标准的工具使用、函数调用和 Model Context Protocol（MCP）模式常常把检索到的数据直接传入上下文窗口，很快就会触及模型的上下文窗口上限。BGL 采用了不同的方法：agent 编写 SQL 查询 Athena，然后编写 Python 代码，在其文件系统中直接处理 CSV 文件结果。这使 agent 能够处理大型结果集、执行复杂聚合、生成图表，而不会触及上下文窗口限制。你可以在[《使用 MCP 进行代码执行：构建更高效的 agents》](https://www.anthropic.com/engineering/code-execution-with-mcp)中了解更多代码执行模式。

### 模块化知识架构

为应对 BGL 多样化的产品线和复杂的领域知识，该实现采用了一种模块化方法，其中包含两种无缝协作的关键配置类型。

#### CLAUDE.md（项目上下文）

`CLAUDE.md` 文件为 agent 提供全局上下文——项目结构、环境配置（测试、生产等），以及至关重要的 SQL 查询执行方式。它定义了哪些文件夹存放中间结果和最终输出，确保文件落在用户可访问的既定文件路径中。下图展示了 `CLAUDE.md` 文件的结构：

![此图展示了一个名为 CLAUDE.md 的技术文档文件，概述了数据分析项目的层级结构。文档以三个注释段落开头，分别描述项目上下文、设置说明和数据文件夹构建。主体内容是一个编号列表，说明每张分析表中的三种文件类型：schema.md 用于模式描述和数据字典，sample_data.csv 用于样本数据，statistics.md 用于数据统计。其下方是一幅 ASCII 树状图，展示文件夹层级，从 data 目录开始，其中包含多个标注为 mart 层的数据库，如 database_1 和 database_2。每个数据库都包含分析表，如 analytics_table_1、analytics_table_2 和 analytics_table_3。每张分析表一致地包含上述三种文件类型。省略号表示更多数据库和表遵循相同模式。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/30/ML-20204-image-1.jpg)

#### SKILL.md（产品领域专业知识）

BGL 使用 `SKILL.md` 配置文件按产品线组织其 agent 领域知识。每个 skill 都充当特定产品的专业数据分析师。例如，BGL CAS 360 产品有一个名为 *CAS360 Data Analyst agent* 的 skill，负责公司与信托管理并对齐 ASIC 合规要求；而 BGL 的 Simple Fund 360 产品有一个名为 *Simple Fund 360 Data Analyst agent* 的 skill，具备 SMSF 管理与合规相关的领域技能。一个 `SKILL.md` 文件定义三件事：

- **何时触发**：哪些类型的问题应激活这个 skill
- **使用或映射哪些表**：指向数据文件夹中相关分析表的引用（如上图所示）
- **如何处理复杂场景**：针对多表查询或特定业务问题的分步指导（如需）

借助 `SKILL.md` 文件，agent 可以动态发现并加载合适的 skill，从而获得执行相应任务所需的领域专业知识。

- **统一上下文**：当某个 skill 被触发时，Claude Agent SDK 会动态地将其专用指令与全局 `CLAUDE.md` 文件合并为一个 prompt。这使 agent 能够同时应用项目级标准（例如*始终保存到磁盘*），并使用领域特定知识（例如将用户问题映射到一组表）。
- **渐进式发现**：并非所有 skill 都需要一次性加载进上下文窗口。agent 先读取查询，确定需要触发哪个 skill。它加载 skill 主体和引用，以了解需要哪些分析表的元数据，然后进一步探索相应的数据文件夹。这既保持了上下文使用的高效性，又提供了全面的覆盖。
- **迭代优化**：如果 AI agent 因缺乏新的领域知识而无法处理某些业务知识，团队会收集用户反馈、找出缺口，并通过 human-in-the-loop 流程向现有 skill 添加新知识，从而对 skill 进行迭代更新和优化。

![这张技术架构图展示了一个为 AI 自动化与 skill 管理设计的 Agent Virtual Machine 系统。图分为两个主要部分：顶层提供两种脚本执行环境：用于执行 shell 命令的 Bash 和用于运行 Python 脚本的 Python。这些环境使 agent 能够执行各种计算任务。下半部分展示文件系统架构，以一个浅蓝色容器表示。在这个文件系统内，skill 按照 “skills/[skillname]360/” 的模式以标准化目录结构组织。图中展示了三个具体的 skill 模块：skills/sf360/ 包含一个 SKILL.md 文档文件和一个 references 子目录；skills/cas360/ 包含一个 SKILL.md 文档文件和一个 references 子目录；skills/smartdocs360/ 包含一个 SKILL.md 文档文件和一个 references 子目录。省略号表示更多 skill 目录遵循相同的组织模式。每个 skill 模块都保持一致的结构，文档（SKILL.md）和支持性参考材料存放在专门的子目录中。这种模块化架构使 AI agent 系统能够以编程方式访问、执行和管理多种能力，每个 skill 与其文档和资源打包在一起，从而实现高效的自动化工作流。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/30/ML-20204-image-2.jpg)

## 高层解决方案架构

为了提供更安全、更可扩展的 text-to-SQL 体验，BGL 使用 Amazon Bedrock AgentCore 托管 Claude Agent SDK，同时将数据转换保留在现有的大数据方案中。

![这张 AWS 云架构图展示了 dbt、Amazon Athena 与 Claude Agent 的集成。该架构图描绘了一个基于 AWS 云的数据管道系统，它集成了多个 AWS 服务以及 dbt 和 Slack，以实现智能数据处理和 AI 驱动的交互。组件：该图展示了 AWS 云环境中的七个关键组件：dbt（data build tool）：位于左侧的数据转换工具，以其标志性 logo 表示；Amazon Athena：AWS 的 serverless 交互式查询服务，用于分析数据；Amazon S3：AWS 的对象存储服务，用于存储和检索数据；托管 Claude agent 的 AgentCore runtime：运行由 Claude 驱动的 AI agent 的核心编排组件；Amazon Bedrock：AWS 用于基础模型和生成式 AI 能力的全托管服务；Slack：作为用户界面的外部通信平台。数据流：该架构展示了七步数据流模式：用户从 Slack 向 AgentCore runtime 发起请求；AgentCore runtime 与 Amazon Bedrock 通信进行 AI 处理；agent 查询 Amazon Athena 进行结构化数据分析；Amazon Athena 从 Amazon S3 存储中检索数据；数据从 Amazon S3 回传到 AgentCore runtime；Amazon Bedrock 向 agent 返回 AI 生成的响应；AgentCore runtime 将最终结果发回 Slack。此外，dbt 与 Amazon Athena 保持双向连接，支持数据转换工作流。用途：该架构使用户能够通过 Slack 与 AWS 数据服务和 AI 能力交互。Claude agent 跨多个 AWS 服务编排请求，将数据查询、转换和 AI 驱动分析结合起来，为用户查询提供智能响应。法律声明：dbt 及 dbt logo 是 dbt Labs, Inc. 的商标。本图不表示与 dbt Labs 存在关联或获得其背书。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/30/ML-20204-image-3.jpg)

上图展示了高层架构和工作流。分析表使用 Athena 和 dbt 每日预先构建，并作为*单一事实来源*。一次典型的用户交互会经过以下阶段：

- **用户请求**：用户通过 Slack 提出业务问题（例如*上季度哪些产品的负面反馈最多？*）。
- **模式发现与 SQL 生成**：agent 使用 skills 识别相关表并编写 SQL 查询。
- **SQL 安全校验**：为防止意外的数据修改，安全层只允许 SELECT 查询，并阻止 DELETE、UPDATE 和 DROP 操作。
- **查询执行**：Athena 执行查询，并将结果存入 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3)。
- **结果下载**：agent 将生成的 CSV 文件下载到 AgentCore 的文件系统，完全绕过上下文窗口以避免 token 限制。
- **分析与可视化**：agent 编写 Python 代码分析 CSV 文件，并根据业务问题生成可视化或精细化的数据集。
- **响应交付**：最终的洞察和可视化经过格式化后返回给 Slack 中的用户。

## 为什么使用 Amazon Bedrock AgentCore 托管 Claude Agent SDK

部署一个执行任意 Python 代码的 AI agent 需要慎重考虑基础设施。例如，你需要隔离机制，以帮助确保不存在跨会话的数据或凭证访问。[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 提供全托管的有状态执行会话，每个会话都有自己隔离的 microVM，拥有独立的 CPU、内存和文件系统。会话结束时，microVM 会完全终止并清理内存，帮助确保不会有残留物留给后续会话。BGL 发现这项服务尤其有价值：

- **有状态执行会话**：AgentCore 可将会话状态保持长达 8 小时。用户可以与 agent 持续对话，回看之前的查询而不会丢失上下文。
- **框架灵活性: **它不绑定特定框架。只需几行代码即可部署 [Strands Agents SDK](https://strandsagents.com/latest/)、Claude Agent SDK、[LangGraph](https://www.langchain.com/langgraph) 和 [CrewAI](https://www.crewai.com/) 等 AI agents。
- **契合安全最佳实践**：它提供会话隔离、VPC 支持，以及基于 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam) 或 OAuth 的身份，帮助大规模开展受治理、符合合规要求的 agent 操作。
- **系统集成**：这是一个面向未来的考量。

> “有 Gateway、Memory、Browser 工具，以及围绕它构建的完整生态。我知道 AWS 正在朝这个方向投入，所以我们现在构建的一切未来都能与这些服务集成。”
>         – James Luo，BGL 数据与 AI 负责人。

BGL 已在计划集成 AgentCore Memory，用于存储用户偏好和查询模式。

## 成果与影响

对 BGL 的 200 多名员工而言，这代表着他们获取商业智能方式的重大转变。产品经理现在可以即时验证假设，无需等待数据团队。合规团队无需学习 SQL 就能发现风险趋势。客户成功经理可以在客户通话期间实时提取特定账户的分析数据。这种数据访问的民主化有助于把分析从瓶颈转变为竞争优势，让整个组织能够更快地决策，同时使数据团队从一次性查询请求中解放出来，专注于战略性举措。

## 结论与关键要点

BGL 的历程展示了如何将坚实的数据基础与 agentic AI 相结合，从而让商业智能民主化。通过使用 Amazon Bedrock AgentCore 和 Claude Agent SDK，BGL 构建了一个更安全、更可扩展的 AI agent，使员工能够利用自己的数据回答业务问题。以下是一些关键要点：

- **投资于坚实的数据基础**：准确性始于坚实的数据基础。通过使用数据系统和数据管道处理复杂的业务逻辑（连接与聚合），agent 可以专注于基本且可靠的逻辑。
- **按领域组织知识**：使用 Agent Skills 封装特定领域的专业知识（例如*税法*或*投资表现*）。这能让上下文窗口保持干净且易于管理。此外，建立反馈回路：持续监控用户查询以发现缺口，并迭代更新这些 skill。
- **使用代码执行进行数据处理**：不要用 agent 借助大语言模型（LLM）上下文来处理大型数据集。相反，应指示 agent 编写并执行代码来过滤、聚合和可视化数据。
- **选择有状态的、基于会话的基础设施来托管 agent**：对话式分析需要持久的上下文。Amazon Bedrock AgentCore 通过内置的状态持久化（最长 8 小时的会话）简化了这一点，免去在无状态计算之上构建自定义状态处理层的需要。

如果您已准备好为组织构建类似能力，可以先探索 [Claude Agent SDK](https://github.com/anthropics/claude-agent-sdk-python)，以及一个简短演示：[在 Amazon Bedrock AgentCore Runtime 上部署 Claude Agent SDK](https://builder.aws.com/content/30O5JJPjEeCugL5MAfSM9TTcd9p/deploying-claude-agent-sdk-on-amazon-bedrock-agentcore-runtime)。如果您有类似用例，或在架构设计上需要支持，请联系您的 AWS 客户团队。
