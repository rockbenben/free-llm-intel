# 用 Amazon Bedrock 为产品团队构建可扩展的创意方案

创意团队和产品开发者一直在寻找简化工作流、缩短上市时间同时保持质量与品牌一致性的方法。本文演示如何使用 AWS 服务（尤其是 [Amazon Bedrock](https://aws.amazon.com/bedrock/)）通过生成式 AI 改造创意流程。你可以落地一套安全、可扩展的解决方案，加快创意工作流，例如管理产品发布、制作营销活动或开发多媒体内容。

本文探讨产品团队如何部署一个生成式 AI 应用，实现跨多种格式的快速内容迭代。该方案覆盖从产品描述、营销文案到视觉概念和社交媒体视频内容的全方位需求。通过与品牌指南和合规要求集成，团队可以显著缩短上市时间，同时保持创意质量与一致性。

## 方案概览

设想某电商公司的产品开发团队正为季节性产品发布制作多媒体营销活动。他们的传统工作流存在瓶颈：反复修改耗时、合规审核靠人工、创意团队之间的协作复杂。该团队正在寻找方案，以便快速迭代创意概念，并生成多种版本的营销素材。

借助 Amazon Bedrock 和 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) 模型，团队可以改造创意流程。Amazon Nova 模型能够生成产品描述和营销文案。团队用 Amazon Nova Canvas 制作概念视觉和产品效果图，用 Amazon Nova Reel 生产有吸引力的视频内容以支撑社交媒体曝光。[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 可帮助团队通过可配置的防护措施和治理，在大规模运行生成式 AI 应用时保持一致品牌指南。

团队还可以通过 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 进一步增强品牌一致性，它可以充当品牌风格指南、视觉识别文档和成功营销素材的集中式仓库。这个全面的知识库确保生成内容都参考了组织的历史成功经验与既定品牌标准。产品规格、市场调研和已批准的传讯信息无缝融入创意过程，从而生成更相关、更有效的内容。

借助这套方案，团队可以同时为多个渠道开发素材，并在所有内容中保持一致的品牌调性。创意专业人员如今可以把精力放在战略决策而非重复性任务上，从而产出更高质量的成果并提升团队满意度。

下面的示例应用构建了一个可扩展环境，用于简化创意工作流。它帮助产品团队从初始概念顺畅走到可上市素材，整个过程中由自动化系统处理合规与一致性检查。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/09/ml-16351-1.png)

该方案的工作流从应用工程师的配置开始：

- 创意素材和品牌指南安全存储在加密的 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）存储桶中。随后这些内容会被索引到 [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 中，构成一个全面的知识库。
- 配置 Guardrails 以强制执行品牌标准和合规要求。

用户体验从认证到内容交付依次展开：

- 创意团队成员通过托管在 Amazon S3 中的安全门户访问界面。
- 认证由 [Amazon Cognito](https://aws.amazon.com/cognito/) 管理。
- 团队成员提交的创意简报或需求会路由到 [Amazon API Gateway](https://aws.amazon.com/api-gateway)。
- 一个 [AWS Lambda](https://aws.amazon.com/lambda) 函数从知识库中查询相关的品牌指南和素材。
- Lambda 函数把知识库提供的上下文信息连同用户的创意简报一起发送给 Amazon Bedrock。
- prompt 和生成的响应会经过 Amazon Bedrock Guardrails 过滤。
- [Amazon Polly](https://aws.amazon.com/polly/) 把文本转换为逼真的语音，生成可立即播放的音频流，并存入 S3 存储桶供后续使用。
- 模型生成的内容交付给用户。
- 聊天历史存储在 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 中。

## 先决条件

继续之前需要满足以下先决条件：

- 一个 AWS 账户
- 一个 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色，具备管理 AWS Marketplace 订阅和 AWS 服务的权限
- AWS 服务：[AWS CloudFormation](https://aws.amazon.com/cloudformation')、Amazon API Gateway、AWS CloudFormation、Amazon Cognito、Amazon DynamoDB、Amazon Polly、Amazon S3、[Amazon Virtual Private Cloud](https://aws.amazon.com/vpc)（Amazon VPC），并配置两个[公有子网](https://docs.aws.amazon.com/vpc/latest/userguide/configure-subnets.html)
- 已启用的 Amazon Bedrock 模型：Amazon Nova Canvas、Amazon Nova Reels、Amazon Nova Pro、Amazon Nova Lite
- Anthropic 模型（可选）：Anthropic 的 Claude 3 Sonnet

## 选择要在 Amazon Bedrock 中使用的模型

在使用 Amazon Bedrock 构建生成式 AI 应用时，最先要做的几步之一就是选择希望访问哪些基础模型。Amazon Bedrock 提供来自不同提供商的多种模型，你需要显式启用本博文计划使用的模型。

- 在 [Amazon Bedrock 控制台](https://us-east-1.console.aws.amazon.com/bedrock/home?region=us-east-1&/)中，从左侧导航菜单找到并选择 [Model access](https://us-east-1.console.aws.amazon.com/bedrock/home?region=us-east-1&modelaccess)。
- 单击 **Modify model access **按钮开始选择模型。
- 选择以下 Amazon 模型：Nova Canvas、Nova Premier Cross-region inference、Nova Pro、Titan Embeddings G1 – Text、Titan Text Embeddings V2
- 选择 Anthropic Claude 3.7 Sonnet 模型。
- 选择 **Next**。
- 在摘要页面仔细检查你的选择，然后选择 **Submit** 确认。

## 配置 CloudFormation 模板

我们使用一个 CloudFormation 模板来部署方案所需的全部资源。按以下步骤准备安装文件：

- 克隆 GitHub 仓库： `git clone https://github.com/aws-samples/aws-service-catalog-reference-architectures.git `
- 进入方案目录： `cd aws-service-catalog-reference-architectures/blog_content/bedrock_genai `（记下这个位置，后续步骤会用到）
- 使用管理员权限登录你的 AWS 账户，确保可以创建所有必需的 AWS 资源。
- 在计划部署该方案的 AWS Region 中创建一个 S3 存储桶。记住存储桶名称，后续步骤会用到。
- 把整个 content 文件夹上传到刚创建的 S3 存储桶。
- 在你的 S3 存储桶中进入 `content/genairacer/src` 文件夹。
- 复制 `content/genairacer/src/genairacer_setup.json` 文件的 URL。部署阶段会用到该 URL。

## 部署 CloudFormation 模板

按以下步骤使用提供的 CloudFormation 模板，在你的 AWS 账户中自动创建并配置应用组件：

- 在 CloudFormation 控制台的导航窗格中选择 **Stacks**。
- 选择 **Create stack **，然后选择 **with new resources (standard)**。
- 在 **Create stack** 页面的 **Specify template** 下，为 **Object URL** 输入上一步复制的 URL，然后选择 **Next**。
- 在 **Specify stack details** 页面输入堆栈名称。
- 在 **Parameters** 下选择 **Next**。
- 在 **Configure stack options** 页面选择 **Next**。
- 在 **Review** 页面勾选确认复选框并选择 **Submit**。

## 登录 Amazon Bedrock 生成式 AI 应用

访问刚部署的应用简单直接。按以下步骤首次登录，开始探索 Amazon Bedrock 生成式 AI 界面。

- 在 **CloudFormation **控制台上选择你部署的堆栈，然后选择 **Outputs **标签页。
- 找到 **FrontendURL **值并打开所提供的链接。
- 出现登录界面时，输入你在 CloudFormation 部署过程中指定的用户名。
- 输入在配置时提供的邮箱收到的临时密码。
- 登录后按提示修改密码。
- 选择 **Send **确认新凭据。

通过认证后，你会被带到 Amazon Bedrock 生成式 AI 主仪表盘，可以开始探索这个新应用的全部功能。

## 使用该应用

应用部署完成后，就可以用于文本、图像和音频管理。下面几节我们看几个示例用例。

### 文本生成

这家电商公司的创意团队想撰写有吸引力的产品描述。只要输入产品的基本特性和期望的语气，LLM 就会生成引人入胜、有说服力的文案，突出每件商品的独特卖点，确保网店的产品页既有信息量，又能吸引潜在客户。

要使用文本生成功能，并通过 Amazon Bedrock 调用受支持的文本模型，请按以下步骤操作：

- 在 AWS CloudFormation 控制台中进入你创建的堆栈。
- 选择 **Outputs** 标签页。
- 选择 **FrontendURL** 的链接。
- 使用堆栈部署过程中发送到你所提供邮箱的凭据登录。
- 在 **Text **标签页的输入框中输入期望的 prompt。
- 从可用选项中，选择你希望 Amazon Bedrock 使用的具体模型 ID。
- 选择 **Run**。

对你想处理的其他 prompt 重复此过程。

### 图像生成

创意团队现在可以构思并产出惊艳的产品图像。通过描述期望的场景、风格和产品摆放方式，他们可以提升网购体验，并提高客户参与和购买的可能性。要使用图像生成功能，请按以下步骤操作：

- 在 UI 中选择 **Images **标签页。
- 在输入框中输入期望的文本生成图像 prompt。
- 从可用选项中，选择你希望 Amazon Bedrock 使用的具体模型 ID。

- 选择 **Generate Image**。

对你想处理的其他 prompt 重复此过程。

- 在输入框中输入期望的 prompt。
- 选择 **Run**。
 音频文件会出现并开始播放。

## Amazon Bedrock Knowledge Bases

借助 Amazon Bedrock Knowledge Bases，你可以为基础模型（FM）和 agent 提供来自组织私有数据源的上下文信息，从而给出更相关、更准确、更贴合需求的响应。它是检索增强生成（RAG）方法的一种强大且易用的实现。本文展示的应用在后端使用 Amazon Bedrock 的各项组件，把流程简化为：通过应用的 GUI 上传一份文档，然后输入会查询你所上传文档的 prompt。

在我们的示例用例中，创意团队现在需要查询内部流程和客户数据方面的信息，这些信息通常存放在文档里。当这些文档存入知识库后，他们就可以在 **KnowledgeBase** 标签页中查询。在该标签页执行的查询会在文档中搜索他们要找的具体信息。

### 管理文档

你上传的文档会列在 **KnowledgeBase **标签页上。要添加更多文档，请完成以下步骤：

- 在 UI 中选择 **KnowledgeBase** 标签页。
- 选择 **Manage Document**。
- 选择 **Browse**，然后选择一个文件。
- 选择 **Upload**。

你会看到一条消息，确认文件已成功上传。文件上传后会触发 Amazon Bedrock Knowledge Bases 的同步过程。应用将在一分钟内准备好对新文档进行查询。

### 查询知识库

要查询知识库，请完成以下步骤：

- 在 UI 中选择 **KnowledgeBase **标签页。
- 在输入框中输入查询。
- 在 **Model** 处选择你希望 Amazon Bedrock 用于执行查询的模型。
- 选择 **Run**。

Amazon Bedrock 生成的文本响应会出现。

## Amazon Bedrock 防护机制

你可以用 **Guardrails** 标签页管理防护机制，按需创建和删除。在 **Text** 标签页执行查询时会用到防护机制。

### 创建防护机制

要创建新的防护机制，请完成以下步骤：

- 在 UI 中选择 **Guardrails** 标签页。
- 填写必填字段或选择适当的选项。
- 在 **Content Filter Type** 下选择防护机制类型。
- 选择 **Create Guardrail**。

新建的防护机制会出现在右侧窗格中。

### 删除防护机制

要删除防护机制，请完成以下步骤：

- 在 UI 中选择 **Guardrails** 标签页。
- 在右侧窗格中选择要删除的防护机制。
- 选择防护机制旁的 X 图标。

按这些步骤操作，你就能有效管理防护机制，在 **Text** 标签页执行查询时获得无缝可控的体验。

### 使用防护机制

创意团队需要访问内部流程和客户数据方面的信息，这些信息安全地存放在知识库的文档中。为落实对个人身份信息（PII）防护机制的合规要求，通过 Text 标签页执行的查询会在文档中搜索具体的非敏感信息，同时避免 PII 在 prompt 和答案中暴露或出现。这种做法帮助团队在不损害隐私或安全标准的前提下取回必要数据。

要使用防护机制功能，请完成以下步骤：

- 在 UI 中选择 **Text** 标签页。
- 在输入框中输入 prompt。
- 在 **Model ID** 处选择你希望 Amazon Bedrock 使用的具体模型 ID。
- 打开 **Guardrails**。
- 在 **Select Filter** 处选择要使用的防护机制。
- 选择 **Run**。

Amazon Bedrock 生成的文本会在几秒内出现。对你想处理的其他 prompt 重复此过程。

## 清理资源

为避免产生费用，请删除不再需要的资源。如果你不再需要这套方案，请完成以下步骤，从 AWS 账户中删除你创建的全部资源：

- 在 AWS CloudFormation 控制台的导航窗格中选择 **Stacks**。
- 选择你部署的堆栈，然后选择 **Delete**。

## 结语

通过把 Amazon Bedrock、Knowledge Bases 和 Guardrails 与 Cognito、API Gateway、Lambda 结合，组织可以为员工提供处理文本、图像和数据工作的强大 AI 工具。这种无服务器方式把生成式 AI 安全、可扩展地融入日常工作流，提升各团队的生产力与创新能力。

想进一步了解生成式 AI 和 Amazon Bedrock，请参阅 AWS News Blog 中的 [Amazon Bedrock 分类](https://aws.amazon.com/blogs/aws/category/artificial-intelligence/amazon-machine-learning/amazon-bedrock/)。
