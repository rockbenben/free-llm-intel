# Apollo Tyres 如何借助 agentic AI 驱动的 Manufacturing Reasoner 解锁机器洞见

*本文是与 Apollo Tyres Ltd. 数字创新中心全球负责人 Harsh Vardhan 合写的联合文章。*

[Apollo Tyres](https://www.apollotyres.com/en-in/) 总部位于印度古尔冈，是一家知名的国际轮胎制造商，在印度和欧洲设有生产设施。公司以 Apollo 和 Vredestein 两个全球品牌推广其产品，产品通过庞大的品牌店、专营店和多品类门店网络销往 100 多个国家。公司的产品组合涵盖乘用车、SUV、MUV、轻型卡车、卡车-客车、两轮车、农业、工业、特种、自行车和越野轮胎的全系列产品，以及翻胎材料。

Apollo Tyres 已开启雄心勃勃的数字化转型之旅，以理顺其整个业务价值流程，包括制造。公司与 [Amazon Web Services](https://aws.amazon.com/)（AWS）合作，使用 AWS 服务构建了集中式数据湖。此外，Apollo Tyres 通过由 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 驱动的[生成式 AI](https://aws.amazon.com/generative-ai/)，在各项业务价值中从数据湖里挖掘洞见，进一步增强了自身能力。

在这一探索中，他们开发了由 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 驱动的 Manufacturing Reasoner，这是一个自定义解决方案，通过与公司的系统、API 和数据源无缝连接来自动化多步骤任务。该解决方案已完成开发、部署、试点并向外推广，用于在高自动化硫化机的[总有效设备性能（TEEP）](https://en.wikipedia.org/wiki/Overall_equipment_effectiveness)和[整体设备效率（OEE）](https://en.wikipedia.org/wiki/Overall_equipment_effectiveness)之外，识别可改进、可标准化并可做基准对比的周期时间区域。硫化机的数据流通过工业[物联网](https://aws.amazon.com/what-is/iot/)（IoT）接入 AWS Cloud，机器会向 AWS Cloud 发送实时的传感器、工艺、运营、事件和状态监测数据。

本文分享 Apollo Tyres 如何借助 Amazon Bedrock 使用生成式 AI，以自然语言交互的方式利用其机器数据中的洞见，全面了解其制造流程，从而实现数据驱动的决策并优化运营效率。

## 挑战：缩短高自动化硫化机的干循环时间并提升运营效率

在 Manufacturing Reasoner 解决方案之前，工厂工程师使用工业 IoT 描述性仪表板，对所有机器、SKU、硫化介质、供应商、机器类型、子元素、子子元素等的硫化机干循环时间（DCT）进行人工分析，以识别瓶颈和重点关注领域。在实时运营中跨越数百万参数、针对各台硫化机完成这些关注领域的分析与识别，过去每个问题大约需要 7 小时，平均每个问题需要 2 小时的实际耗时。此外，使用传统的根本原因分析（RCA）工具无法进行子元素级分析（即对子元素和子子元素活动进行瓶颈分析）。这项分析需要来自制造、技术、工业工程等不同部门的主题专家（SMEs）共同进行 RCA。由于洞见并非实时生成，纠正措施也被延迟。

## 解决方案成效

借助 agentic AI 的 Manufacturing Reasoner，目标是让工厂工程师能够基于加速的 RCA 洞见采取纠正措施，从而缩短硫化 DCT。这一 agentic AI 解决方案和虚拟专家（agent）帮助工厂工程师以自然语言（英语）与接入大数据的工业 IoT 交互，检索相关洞见，并就解决 DCT 流程中的运营问题提供有见地的建议。RCA agent 提供详细的洞见和自诊断或建议，指出在 250 多台自动化硫化机、140 多个库存单位（SKU）、三种硫化介质和两类机器供应商之间，应重点关注 25 个以上自动化子元素或活动中的哪些。目标是在三个工厂实现 DCT 的最大可能降幅。通过这项创新，工厂工程师现在可以透彻理解其制造瓶颈。这种全面的视图支持数据驱动的决策并提升运营效率。他们通过基于流式实时数据对瓶颈区域进行自诊断，在辅助 DCT 的 RCA 方面实现了约 88% 的工作量减少。生成式 AI 助手把 DCT 的 RCA 从每个问题最多 7 小时缩短到每个问题不到 10 分钟。总体而言，仅乘用车轮胎（PCR）事业部在三个制造工厂的预期效益就约为每年节省 1,500 万印度卢比（INR）。

这个虚拟 reasoner 还提供实时触发器，用于突出 DCT 中持续出现的异常偏移，从而依照 [Poka-yoke](https://en.wikipedia.org/wiki/Poka-yoke)（防错）方法实现 mistake-proofing 或错误预防，并促成相应的预防措施。以下是 Manufacturing Reasoner 提供的额外收益：

- 可观测元素级的周期时间，并配有图表和统计过程控制（SPC）图表，可在实时流式数据上直接进行机台对机台对比
- 基于流式数据的按需 RCA，以及向制造 SMEs 发送每日告警

> “想象这样一个世界：业务伙伴可以做出实时的、数据驱动的决策，而 AI 与人类协同。我们这套变革性的生成式 AI 解决方案正是为实现这一愿景而设计、开发和部署的。这个由生成式 AI 驱动的自研 Manufacturing Reasoner 并不是要取代人类智能，而是要放大它。”
>         – Harsh Vardhan，Apollo Tyres Ltd. 数字创新中心全球负责人

## 解决方案概览

借助 Amazon Bedrock 的各项功能，Apollo Tyres 实现了先进的自动诊断 Manufacturing Reasoner，旨在理顺 RCA 并增强决策。该工具使用基于生成式 AI 的机器根本原因 reasoner，通过自然语言查询促成准确分析、提供预测性洞见，并引用可靠的 [Amazon Redshift](https://aws.amazon.com/redshift/) 数据库来获取可执行的数据。该系统通过预测潜在问题、优化周期时间并减少低效，实现了主动维护。此外，它通过动态报告和可视化能力为员工提供支持，显著提升了整体生产率和运营效率。

为启用该工作流，Apollo Tyres 遵循以下步骤：

- 用户通过 UI 以自然语言提问，该 UI 是托管在 [Amazon Elastic Compute Cloud](https://aws.amazon.com/pm/ec2/)（Amazon EC2）上的 [Chainlit](https://docs.chainlit.io/get-started/overview) 应用。
- 所提问题由主 AI agent 接收，它判断问题的复杂程度，并借助不同的 AWS 服务决定调用哪个 agent 进行多步骤推理。
- Amazon Bedrock Agents 使用 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 和 [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 的向量数据库能力，为请求提取相关上下文：  **复杂转换引擎 agent** – 该 agent 作为按需的复杂转换引擎，处理上下文和具体问题。 **RCA agent** – 这个用于 Amazon Bedrock 的 agent 构建多步骤、多 LLM（大语言模型）工作流，以执行详细的自动化 RCA，这对复杂的诊断场景尤为有用。
- 主 agent 使用多个线程并发调用 explainer agent 和 visualization agent：  **Explainer agent** – 这个用于 Amazon Bedrock 的 agent 使用 Anthropic 的 Claude Haiku 模型分两部分生成解释：  **证据** – 对已执行的查询或 CTE 提供逐步的逻辑解释。 **结论** – 给出问题的简要回答，并引用 Amazon Redshift 记录。  **Visualization agent** – 这个用于 Amazon Bedrock 的 agent 使用 Anthropic 的 Claude Sonnet 模型生成 [Plotly](https://plotly.com/) 图表代码，以创建可视化图表。
- 主 agent 合并两个 agent 的输出（记录、解释、图表代码），并以流式方式发送到应用。
- UI 通过动态展示统计图表并把记录格式化为表格，把结果呈现给用户。
- [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 帮助设置定制的过滤器和响应限制，确保与机器数据的交互不仅安全，而且相关并符合既定的运营准则。Guardrails 还通过自动校验信息的有效性来帮助防止错误和不准确，这对准确识别制造问题的根本原因至关重要。

## 经验总结

Apollo Tyres 从这段旅程中总结了以下经验：

- 把生成式 AI 应用于流式实时工业 IoT 数据需要大量研究，因为每个用例都有其独特性。为针对自动化 RCA 场景开发有效的 manufacturing reasoner，Apollo Tyres 从原型到概念验证阶段探索了多种策略。
- 最初，解决方案在使用 Amazon Bedrock 时响应时间出现明显延迟，尤其是在涉及多个 agent 时。由全部三个 agent 完成数据检索和处理的初始响应时间超过 1 分钟。为解决这个问题，团队着手优化性能。通过仔细选择合适的 LLM 和小语言模型（SLMs）并禁用 agent 内未使用的工作流，响应时间成功降至约 30–40 秒。这些优化对提升解决方案的效率与响应性起到关键作用，使系统运行更顺畅，并带来更好的用户体验。
- 在利用 LLM 的能力生成用于图表可视化数据的代码时，Apollo Tyres 在处理大规模数据集时遇到了挑战。最初生成的代码常常存在不准确之处，或无法正确处理海量数据。为解决这个问题，他们启动了持续改进的过程，多次迭代以改进代码生成流程。他们的努力集中在开发一种动态方法，能够准确生成图表代码，并高效管理数据框中的数据，无论记录数量有多少。通过这种迭代方式，他们显著提升了图表生成流程的可靠性与稳健性，确保它能在不牺牲准确性或性能的前提下处理大规模数据集。
- 一致性问题通过确保以正确的数据格式把数据摄入 Amazon 数据湖供知识库使用而得到有效解决，结构如下：

```
{
"Question": <Question in natural language>, 
"Query": < Complex Transformation Engine scripts >, 
“Metadata” :<metadata>
}
```

## 后续步骤

Apollo Tyres 团队正在把这一成功解决方案从轮胎硫化推广到不同地点的各个领域，朝着 Industry 5.0 的目标推进。为此，Amazon Bedrock 将在扩展多 agentic [检索增强生成](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）解决方案中发挥关键作用。这一扩展涉及使用各司其职的专用 agent，每个 agent 负责特定功能。通过部署具有不同角色的 agent，团队希望提升解决方案在多样运营领域中的能力。

此外，团队还专注于对交付准确查询响应所需的时间进行基准测试和优化。这项持续的工作将理顺流程，在扩展后的解决方案中提供更快、更高效的决策与问题解决能力。Apollo Tyres 也在探索使用 Amazon Bedrock 的生成式 AI，用于其其他制造和非制造流程。

## 结语

总而言之，Apollo Tyres 通过 Amazon Bedrock 和 Amazon Bedrock Agents 使用生成式 AI，把原始机器数据转化为可执行的洞见，实现了对其制造运营的全面视图。这让决策更加明智、更加数据驱动，并提升了运营效率。通过集成基于生成式 AI 的 manufacturing reasoner 和 RCA agent，他们打造出一个机器周期时间诊断助手，能够在 25 个以上子流程、250 多台自动化硫化机、140 多个 SKU、三种硫化介质和两家机器供应商中精准定位关注领域。该解决方案帮助推动了三个工厂 DCT 的针对性改进，仅在 PCR 板块的年度化节省目标就约为 1,500 万印度卢比，并在根本原因分析方面实现了约 88% 的人工工作量减少。

> “通过采纳这种 agentic AI 驱动的方法，Apollo Tyres 正在重新定义运营卓越——以先进的‘资产压榨（asset sweating）’释放隐藏产能，同时让我们的工厂工程师能够用自然语言与机器对话。这些大胆的自研 AI 举措不仅在优化当下的绩效，更在为由数据和人类-机器协作驱动的未来智能工厂夯实基础。”
>         – Harsh Vardhan。
