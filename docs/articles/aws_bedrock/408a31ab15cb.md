# 在 Amazon Bedrock AgentCore Browser 中使用 Web Bot Auth（预览版），为浏览 Web 的 AI agent 减少 CAPTCHA

AI agent 需要代你浏览 Web。当你的 agent 访问某个网站以收集信息、填写表单或核实数据时，它会遭遇那些同样用来阻止不受欢迎 bot 的防护机制：CAPTCHA、速率限制以及直接封禁。

今天，我们很高兴分享 AWS 的解决方案。[Amazon Bedrock AgentCore Browser](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html) 是我们为 AI agent 与网站交互提供的安全、基于云的浏览器，它现在支持 Web Bot Auth（预览中）——这是一项 IETF 草案协议，可为 agent 提供可验证的密码学身份。

## CAPTCHA 带来的摩擦

客户告诉我们，CAPTCHA 摩擦是构建可靠的、基于浏览器的 agentic workflow 的最大障碍之一。你的 agent 会在任务中途停滞，等待人工介入去解一个用来证明「你不是 bot」的谜题——可你的 agent 恰恰就是 bot，而这正是重点。CAPTCHA 的存在有其充分理由。网站在保护其内容、库存和评论方面持续面临挑战。Web Application Firewall（WAF）和 bot 检测服务保护着这些站点，但它们几乎把所有自动化流量都视为可疑，因为它们没有可靠的方法区分合法 agent 与恶意 agent。

一些自动化提供方试图以程序化方式破解 CAPTCHA——用计算机视觉模型识别扭曲文字，或反复点击图像网格直到谜题通过。这种做法脆弱、昂贵，而且是在绕过域名所有者为其内容设定的管控。另一些做法依赖 IP allowlist 或 User-Agent 字符串。当你在地址频繁变化的云环境中运行 agent 时，IP allowlist 就会失效。User-Agent 字符串任何人都能伪造，因此不提供任何验证，还带来有人仿冒高信任度字符串的风险。这两种方法都要求与你想访问的每个网站逐一人工协调，无法规模化。

## Web Bot Auth：为浏览 Web 的 agent 提供密码学身份

Web Bot Auth 是一项[ IETF 草案协议](https://datatracker.ietf.org/doc/html/draft-meunier-web-bot-auth-architecture)，为 agent 提供可验证的密码学身份。当你在 AgentCore Browser 中启用 Web Bot Auth 时，我们会签发网站可验证的密码学凭据。agent 在每次请求时都会出示这些凭据。WAF 现在可以额外校验签名、确认它与受信任的目录匹配，并在域名所有者允许已验证 bot 且其他 WAF 检查均通过时放行该请求。

AgentCore 正与 [AWS WAF](https://aws.amazon.com/waf/)、[Cloudflare](https://www.cloudflare.com/)、[HUMAN Security](https://www.humansecurity.com/) 和 [Akamai Technologies](https://www.akamai.com/) 以及 AWS WAF 合作支持这一验证流程。这些提供方保护着数百万个网站。当你在配置中启用签名并创建 AgentCore Browser 时，我们会自动把你的 agent 签名目录注册到这些提供方。许多域名已经默认把 WAF 配置为允许已验证 bot，这意味着在这类情况下，你无需额外设置就能立即看到 CAPTCHA 减少。

## 域名所有者如何控制访问

WAF 提供方通过 Web Bot Auth 为网站所有者提供三个层级的控制：

- **阻止所有 bot **——有些站点选择完全阻止自动化流量。Web Bot Auth 不会绕过这一点——如果某个域名不想要任何自动化，这个选择会得到尊重。
- **允许已验证 bot**——许多域名把 WAF 配置为允许任何提交有效密码学签名的 bot。对于越来越多受 AWS WAF、Cloudflare、HUMAN Security 和 Akamai Technologies 保护的站点，这是默认策略。当你把签名作为 AgentCore Browser 配置中的一个参数启用时，这一策略就会适用于你的 agent。
- **允许特定的已验证 bot 仅执行特定操作**——例如，一家将供应商门户访问自动化的金融服务公司可以与这些供应商共享其唯一目录。供应商可以制定规则，例如「允许 FinCo 的 agent 每分钟 100 次请求，不允许它们创建新账户，并阻止所有其他已签名 agent」。这让网站拥有细粒度控制，同时保留密码学验证带来的好处。

今天发布的 AgentCore Browser 对 Web Bot Auth 的支持预览版，通过让你的 agent 呈现为已验证 bot，帮助减少在允许已验证 bot 的域名上遇到的 CAPTCHA 摩擦。一旦 Web Bot Auth 协议定稿，AgentCore 计划转向客户专属密钥，这样 AgentCore 用户就能使用仅允许指定已验证 bot 的那一层控制。

## 使用 Web Bot Auth 协议

要让浏览器使用 Web Bot Auth 协议对请求签名，请创建一个带 `browserSigning` 配置的 browser 工具：

```
import boto3
cp_client = boto3.client('bedrock-agentcore-control')
response = cp_client.create_browser(
    name="signed_browser",
    description="Browser tool with Web Bot Auth enabled",
    networkConfiguration={
        "networkMode": "PUBLIC"
    },
    executionRoleArn="arn:aws:iam::123456789012:role/AgentCoreExecutionRole",
    browserSigning={
        "enabled": True
    }
)
browserId = response['browserId']
```

把 browser 标识符传给你的 agent 框架。以下是使用 Strands Agents 的示例：

```
from strands import Agent
from strands_tools.browser import AgentCoreBrowser
agent_core_browser = AgentCoreBrowser(
    region="us-west-2",
    identifier=browserId
)
strands_agent = Agent(
    tools=[agent_core_browser.browser],
    model="anthropic.claude-4-5-haiku-20251001-v1:0",
    system_prompt="You are a website analyst. Use the browser tool efficiently."
)
result = strands_agent("Analyze the website at <https://example.com/>")
```

现在该 agent 已配置为使用这个会对每个 HTTP 请求签名的新 browser 工具。只要域名所有者允许已验证 bot，受 AWS WAF、Cloudflare、HUMAN Security 或 Akamai Technologies 保护的网站就能验证签名并放行请求，无需弹出 CAPTCHA。

## 协议进展

Web Bot Auth 协议正在获得行业推动力，因为它解决了一个真实问题：没有可验证的身份，合法自动化与滥用行为无从区分。你可以阅读草案协议规范 [HTTP Message Signatures for automated traffic Architecture](https://datatracker.ietf.org/doc/html/draft-meunier-web-bot-auth-architecture)。该架构定义了 agent 如何生成签名、WAF 如何验证签名，以及密钥目录如何实现发现。[Amazon 正与 Cloudflare 合作](https://blog.cloudflare.com/agent-registry)，并与众多主流 WAF 提供方一起，帮助确定客户专属密钥目录格式并推动草案定稿。

## 结论

Amazon Bedrock AgentCore Browser 已正式可用，其中 Web Bot Auth 功能处于预览阶段。AgentCore Browser 使用 Web Bot Auth 协议对请求签名，有助于在允许已验证 bot 的域名上减少 CAPTCHA 摩擦。随着协议定稿，AgentCore Browser 计划签发客户专属的密钥与目录，让你可以向特定网站证明 agent 的身份，并与你需要访问的域名直接建立信任关系。

Web Bot Auth 让 agent 在被质疑时能够证明自身身份，减少自动化 workflow 中的运营摩擦，并让网站所有者能够控制哪些 agent 可以访问其资源。[Amazon Bedrock AgentCore Browser 对 Web Bot Auth（预览版）的支持](http://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-web-bot-auth.html) 提供了让这一切成为可能的基础设施层。欢迎在你的账户中试用 AgentCore Browser，并参考我们的 [GitHub 示例](https://github.com/awslabs/amazon-bedrock-agentcore-samples/tree/main/01-tutorials/05-AgentCore-tools/02-Agent-Core-browser-tool/)。
