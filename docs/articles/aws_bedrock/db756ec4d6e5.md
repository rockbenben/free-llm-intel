# Mobileye 如何借助 Amazon Bedrock AgentCore 改造支持运营

如果部署生产级 AI agent 既不需要任何基础设施管理，又自带企业级可观测性，还能轻松对接你现有的本地系统，会怎样？

[Mobileye](https://www.mobileye.com/) 是自动驾驶领域的先行者，全球约 1,200 款车型上部署了超过 2.3 亿颗 EyeQ 系统级芯片。它看到了一个机会：把熟练工程师从例行的内部工单状态查询中解放出来。

Mobileye 的数据采集处理（Data Collection Processing）管道每天摄取数以千计的行驶记录会话，由此产生源源不断来自工程师和数据团队的状态查询。此前，每次查询都需要跨多个系统进行手工操作——识别会话、交叉比对可视化工具、验证输出、查阅日志——然后才能撰写回复。借助 Amazon Bedrock AgentCore，Mobileye 部署了一个 AI Support Agent，把响应时间缩短了 90%，超过了 95% 的准确率目标，并且没有任何基础设施开销。结果非常有说服力，以至于 Mobileye 把 AgentCore 改造成一个自助式平台，供公司内各团队部署自己的 AI agent。

本文将探讨 Mobileye 如何在 Amazon Bedrock AgentCore 上部署 AI 支持 agentic 方案——从引发这个想法的支持瓶颈，到验证它的概念验证，再到连接本地系统与 AWS 云服务的混合架构。这种做法对许多企业都有借鉴意义：它们正在努力扩展 AI agent，同时又要维持企业级的治理与安全标准。

## 从手工瓶颈到 AI 驱动的支持

随着 Mobileye 数据采集管道规模扩大，66% 的支持工单变成了例行的状态查询，需要工程师在多个后端系统之间手动点击 15 次。这个耗时的过程把熟练工程师从复杂问题中抽走，而内部用户则面临更长的等待时间。

传统的自动化方式——脚本、静态工作流和基于规则的决策树——被证明并不够用。它们虽然能处理可预测的查询，但缺乏解读真实世界支持请求多样变化所需的上下文理解能力。团队因此选择构建一个能够理解上下文、适应各种询问模式的 AI agent。

## 验证方案：概念验证

在全面投产之前，Mobileye 团队进行了一次概念验证，目标是在工单分类上达到 95% 的准确率，响应时间低于 2 分钟。

该 agent 使用 Anthropic Claude 基础模型，通过 Mobileye 内部的 LLM Gateway 访问，该网关为 [Amazon Bedrock](https://aws.amazon.com/bedrock/?trk=5d83343f-40c5-4167-8ec4-5b70bac566f7&sc_channel=ps&trk=a3a1d5b1-eaa2-4ade-8305-ede5684ce2b6&sc_channel=ps&ef_id=Cj0KCQjwzqXQBhD2ARIsAKrIeU8vkPVSqjltCQs3bC26UGwaCmkOvh3ehg29TjuFN7YkKSN2UkIJpvwaAlyzEALw_wcB:G:s&s_kwcid=AL!4422!3!808746982981!e!!g!!amazon%20bedrock!23846236754!200318271070&gad_campaignid=23846236754&gbraid=0AAAAADjHtp-iaMgCRiTZQsuvNZVOgOlNe&gclid=Cj0KCQjwzqXQBhD2ARIsAKrIeU8vkPVSqjltCQs3bC26UGwaCmkOvh3ehg29TjuFN7YkKSN2UkIJpvwaAlyzEALw_wcB) 上的基础模型提供受治理、带配额管理的访问。关键的使能因素是 Model Context Protocol（MCP），它让 agent 能够实时访问行驶数据处理平台的 API——从而在推理过程中查询会话状态、获取处理日志并拉取诊断信息。

这意味着该 agent 远远超出了简单的工单分类，成为一个智能调查员，能够处理过去需要耗费大量手工劳动才能解决的询问。当用户询问行驶记录会话时，agent 可以判断当前状态并给出回答：为已完成的会话确认结果并提供访问详情，为失败的会话呈现具体错误、给出调试建议和日志链接，或对缺失的请求引导用户完成提交流程——全部在两分钟内完成，无需人工介入。

## 评估可选方案

在成功用 AI agent 验证了概念之后，Mobileye 需要把它投入生产。这一转变要求方案既能满足企业级要求，又能保持概念验证中展现的灵活性。经过仔细评估，他们选择把 AI Agent 部署在 Amazon Bedrock AgentCore 上——这是一个完全托管的平台，可以用任意框架或模型大规模构建、连接和优化 AI agent。决策归结为五个关键因素：

- **面向企业工作负载的无服务器基础设施**
- **加快支持查询的解决时间**
- **全面的内置可观测性**
- **支持多种 agentic 框架**
- **混合架构支持，可轻松对接他们现有的本地工单系统**

最后一点尤为重要。Mobileye 的内部工单系统运行在本地，无法从 AWS 访问，因此任何方案都需要在不牺牲安全性或合规性的前提下弥合这道鸿沟。

## 生产架构：连接两个世界

在概念验证成功之后，Mobileye 以一个精细的混合架构投入生产，在两种环境中清晰界定了各组件的职责。

### 本地组件

下表描述了负责本地工单操作、并桥接到云端 AI 处理的本地组件。

| **组件** | **角色** |
| --- | --- |
| **Local Orchestrator** | 在本地处理工单操作，提取新工单并把已完成的回复回写到工单系统中。 |
| **Internal ticketing system** | 本地的工单管理系统既是支持工单的来源，也是 AI 生成回复的去处。它无法从 AWS 访问，这是混合设计的主要动因。 |

### AWS 云组件

下表描述了为 AI agent 提供无服务器计算、安全和可观测性基础设施的 AWS 云组件。

| **组件** | **角色** |
| --- | --- |
| **AgentCore Runtime** | Mobileye 在 AgentCore 的无服务器运行时上运行其 AI Support Agent，从而免除所有基础设施管理。团队无需预置服务器即可部署和迭代，享受自动伸缩以应对支持量的峰值，并保留使用任意 agentic 框架的完全灵活性。只需一次 API 调用就能触发该 agent——使他们与现有系统的集成保持简单直接。 |
| **AgentCore Observability ** | Mobileye 的工程团队使用内置可观测性，端到端追踪每一次 agent 交互——从最初的请求，经 MCP 工具调用到后端系统，直到最终回复。详细的日志和回溯能准确呈现 agent 如何推理、获取了哪些数据、错误发生在何处，从而大幅缩短调试时间、加快迭代周期。 |
| **AWS Secrets Manager** | Mobileye 使用 Secrets Manager 为其 GenAI 平台实现无需直接接触凭证（faceless）的安全身份验证。调用 AI agent 的团队从不直接处理凭证——与 agent 和后端系统交互所需的密钥以程序化方式存储、轮换和获取，在不为最终用户增加摩擦的前提下落实企业安全标准。 |

### Mobileye 服务

下表描述了 Mobileye 自有、为 agent 提供数据连接和受治理模型访问的服务。

| **组件** | **角色** |
| --- | --- |
| **Data Pipeline Model Context Protocol (MCP)** | Data Pipeline MCP 服务器支持在推理期间实时查询生产数据，包括行驶会话预热状态、请求进度和处理错误——让 agent 能够即时给出结合上下文的回复。 |
| **AI LLM Gateway** | Mobileye 对 Amazon Bedrock 及其他 LLM 提供商上基础模型的受治理、带配额管理的访问 |

## 各部分如何协同工作

这条自动化工作流遵循精简的四步流程：

- **Local Orchestrator** 提取新工单，并把它们发送给运行在 **AgentCore Runtime** 上的 **AI Support Agent**。
- **AI Support Agent** 端到端处理每张工单——对询问进行分类，通过 **MCP Server** 查询实时生产系统以获取会话数据，并通过 **AI LLM Gateway** 访问 Claude——从而生成一份格式完整、包含链接、建议和可执行后续步骤的回复。
- **Local Orchestrator** 接收已完成的回复，并带着相应的注释和标签把它回写到 **Internal Ticketing System**。
- **AgentCore Observability** 捕获 agent 活动——会话指标、延迟、token 用量和追踪——用于持续监控和调试

## 不言自明的可衡量成果

Mobileye 的 AI Support Agent 在 AgentCore 上的生产部署，交付了持续达到或超过初始目标的结果。

- 整体成功率：98%（超过原定 95% 的目标）
- 响应时间：从数小时缩短到约 1 分钟（提升 90%）
- 自动化支持量：占工单总量的 66%
- 每月吞吐量：处理 100 多张工单

## 扩展愿景：从单个 agent 到企业平台

随着 AI Support Agent 在生产中交付成果，Mobileye 面临一个新挑战：组织内的大多数开发者缺乏在 AgentCore 上独立部署 agent 所需的 AWS 凭证或基础设施访问权限。为解决这个问题，Mobileye 的 Cloud Infra 团队构建了一个内部 agent 部署平台。

这个内部托管服务让 Mobileye 的开发者无需具备 AWS 专业知识或云凭证，即可部署生产级 AI agent。流程按以下步骤进行：

- 团队提供他们的 agent 代码
- 团队指定所需的 AgentCore 能力——Memory、Browser Tool、Code Interpreter、Observability、Gateway。
- Cloud Infra 团队预置全部基础设施：AWS IAM Roles、Amazon S3 存储、Amazon CloudWatch 监控和 Amazon Cognito 身份验证。
- 开发者获得一个预配置的 `bedrock_agentcore.yaml` 文件，可直接集成到他们的项目中。
- 部署只需一条命令：`agentcore deploy`。

预置的基础设施符合 Mobileye 在安全、成本治理和运营卓越方面的标准。针对代码异常的 CloudWatch Alarms 有助于确认问题能立即暴露出来。

从一个概念验证起步的工作，已经演变为一个全企业范围的平台，团队可以在几分钟而不是几周内，部署安全、受监控、成本可跟踪的 agent。

从手工流程走向智能自动化的路径比你想象的更短，而成果正如 Mobileye 所展示的，可以非常出色。
