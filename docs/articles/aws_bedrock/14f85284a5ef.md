# Iberdrola 使用 Amazon Bedrock AgentCore 增强 IT 运营

[Iberdrola](https://www.iberdrola.com/) 是全球最大的公用事业公司之一，它已经接受了尖端的 AI 技术，以彻底革新其在 [ServiceNow](https://www.servicenow.com/) 中的 IT 运营。通过采用不同的 agentic 架构，Iberdrola 改变了管理数千个变更请求和事件工单的方式，简化了流程并提升了各部门的生产力。

通过与 AWS 的合作，Iberdrola 在一个采用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 的开创性解决方案中实施了这些 agent，聚焦三个关键领域：优化草稿阶段的变更请求验证、用上下文智能丰富事件管理，以及使用对话式 AI 简化变更模型选择。这些创新减少了瓶颈，帮助团队加快工单解决速度，并在整个组织内提供一致且高质量的数据处理。

Amazon Bedrock AgentCore 帮助 Iberdrola 无缝部署可用于生产的 AI agent。凭借 serverless 计算能力、强大的安全性和集成的可观测性，该平台帮助 Iberdrola 在各部门扩展解决方案，同时遵守企业级的可靠性与合规标准。

## 变更与事件管理的挑战

Iberdrola 使用 AI 驱动的验证简化了变更管理的多阶段流程。一组经过编排的 agent 确保请求与预期修改保持一致，同时实时格式化并校验必填字段。这种优化的方法避免了人工重新提交，并大幅缩短了处理时间，帮助团队专注于推动有影响力的成果。

通过使用一群 agent 来执行上下文丰富，Iberdrola 的网络部门现在能更快、更精准地处理事件。这种丰富让技术人员能够访问配置项详情、查阅相关的历史事件，并按环境和告警类型对工单分类，从而缩短响应时间，使团队能够迅速处理关键问题。

## 解决方案概览

Iberdrola 通过分层架构建立其 agentic AI 实践，该架构在分离关注点的同时，实现跨 IT 工作流的无缝集成。ServiceNow 作为主要输入源，MicroGateway 提供智能路由，将请求定向到相关的 agent。一个专门的数据层维护企业信息，通过 extract, transform, and load (ETL) 管道处理原始 ServiceNow 数据，供 agent 使用。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/02/02/image-1.jpg)

该架构包含三层：

- **Agentic AI 资源** – 该层涵盖所有 agent 部署、用于标准化数据访问的 [Model Context Protocol (MCP) servers](https://modelcontextprotocol.io/docs/getting-started/intro)、身份验证机制，以及维护上下文信息的记忆对象。该设计支持特定领域的 agent 开发，同时共享公共基础设施服务。
- **推理层** – 一个精简的抽象层提供来自组织集成模型组合的 [large language model (LLM)](https://aws.amazon.com/what-is/large-language-model/) 推理能力。该层提供一致的模型访问模式，同时支持实验，而无需修改 agent。
- **数据层** – 一个全面的信息基础，包含运营数据、分析数据集和事务记录。该层通过提供对历史模式、实时运营状态以及智能决策所需上下文信息的访问，增强 agent 的能力。

该设计支持三个不同的用例，分别应对不同的运营挑战：

- **增强的变更管理验证 **– 第一个实现通过确定性的 agentic 工作流支持 Iberdrola 变更管理流程的草稿阶段。多个专门的 agent 依次协作，验证变更模型的适用性，并核实必填字段包含格式正确的信息。当检测到验证错误时，系统会在允许进入后续阶段之前向请求者提供清晰的反馈。
- **智能事件丰富 **– 事件管理解决方案为 Iberdrola 的网络部门展示了多 agent 编排。一个主 agent 接收每个事件，并选择性地调用专门的 agent 进行标记、上下文丰富、相似性检测和变更影响分析。这种自适应的方法通过分类事件、识别相关的历史案例以及提取配置项详情来辅助技术人员。
- **对话式变更模型助手 **– 第三个用例通过对话式 AI 助手解决选择合适变更模型的复杂性。该 agent 收集有关技术家族、变更目标和部署环境的信息，以推荐合适的变更模型。系统提供可点击的推荐，打开预填的变更表单，从而简化变更请求流程。

该概念架构通过 Amazon Bedrock AgentCore 转化为可用于生产的实现，后者提供用于构建和部署企业 AI agent 的托管原语。Amazon Bedrock AgentCore 的 serverless 方法使 Iberdrola 能够专注于 agent 逻辑而非基础设施管理，同时提供可扩展性和运营可靠性。

### Amazon Bedrock AgentCore 组件

[AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 是 agent 部署的基础，接受用任何框架构建的容器化 agent——在 Iberdrola 的案例中是使用 [LangGraph](https://www.langchain.com/langgraph)——并通过 [Amazon Elastic Container Registry](https://aws.amazon.com/ecr/) (Amazon ECR) 仓库部署它们。AgentCore Runtime 保持 serverless 特性，根据请求量扩展，同时提供会话隔离。每个 agent 会话对于复杂工作流最多可运行 8 小时。AgentCore Runtime 生成的日志和指标由 AgentCore Observability 自动捕获。此外，Iberdrola 还配置了向其自托管的 [Langfuse](https://langfuse.com/) 实例进行显式日志记录，以实现集中监控。

[AgentCore Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html) 通过为每个 agent 会话维护记忆对象，在 agent 交互之间提供上下文连续性。使用该记忆对象，agent 可以存储和检索会话状态、对话历史以及中间处理结果。这一能力对于 Iberdrola 的多步骤工作流至关重要，因为 agent 必须在验证阶段或事件丰富流程之间保持上下文。

[AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 通过充当 MCP server 来简化工具集成，将外部工具和服务「MCP 化」。AgentCore Gateway 无需为每个数据源编写自定义集成代码，而是提供 agent 可以一致使用的标准化接口。这种方法对 Iberdrola 的 ServiceNow 端点连接尤其有价值。

[AgentCore Identity](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity.html) 管理入站和出站身份验证流程，通过 OAuth 2.0 协议与 [Entra ID](https://www.microsoft.com/en-us/security/business/identity-access/microsoft-entra-id) 集成。对于入站请求，AgentCore Identity 验证 bearer token 并授权访问底层资源。对于出站操作，它处理 token 获取并管理与下游工具的安全通信。

[AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html) 使用 [OpenTelemetry](https://opentelemetry.io/) 标准从 agent 捕获遥测数据，并通过 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 呈现这些信息。这种集成提供了对运营指标的全面监控，而无需额外的插桩。

### 技术实现

该实现使用 [LiteLLM](https://www.litellm.ai/) 作为 proxy 层，通过 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 及其他多种模型，一致地访问 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) 和 Anthropic Claude 模型。这种抽象使 agent 能够使用标准化的 API 调用与不同的模型变体交互，而 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 为模型输出提供安全控制。

该架构通过 [virtual private cloud (VPC) configuration within AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore-control/latest/APIReference/API_CreateAgentRuntime.html#API_CreateAgentRuntime_RequestSyntax) 满足 Iberdrola 的企业安全要求，使 agent 能够安全访问内部资源，同时保持网络隔离。VPC 端点提供与内部数据源的安全通信，而无需将流量暴露到公共互联网。

用户通过 ServiceNow 发起请求，ServiceNow 通过 REST API 与 MicroGateway 通信，由后者将请求路由到相应的用例 agent。数据架构采用混合方法，将实时运营访问与丰富的分析数据集相结合。原始 ServiceNow 数据经由 ETL 流程流入 [Amazon Simple Storage Service](https://aws.amazon.com/s3/) (Amazon S3) 存储，再流入通过 [pgvector](https://github.com/pgvector/pgvector) 扩展增强以支持语义搜索的 [Amazon Relational Database Service](https://aws.amazon.com/rds/) (Amazon RDS) 数据库。

部署在 AgentCore Runtime 中的 agent 生成的日志和指标可使用 AgentCore Observability 进行监控。此外，Iberdrola 在 [Amazon Elastic Kubernetes Service](https://aws.amazon.com/eks/) (Amazon EKS) 上使用自托管的 [Langfuse](https://langfuse.com/)，以全面查看 LLM 和 agent 生成的 span 和 trace。

## 用例详情

在本节中，我们讨论前面提到的两个用例的实现：增强的变更管理和智能事件管理。

### 增强的变更管理

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/02/02/image-3.jpg)第一个用例展示了一个 agentic 工作流，通过在单个 AgentCore Runtime 内按顺序执行 agent，支持 Iberdrola 变更管理流程的草稿阶段。该工作流通过四个专门的 agent——Rule Extractor、Content Validator、AIM Model Analyst 和 Phase Transition——处理变更请求，每个 agent 都接收上一步的上下文。

该实现包含以下关键组件：

- **单一运行时上下文流** – agent 在一个 AgentCore Runtime 实例内运行，在整个验证管道中保持无缝的上下文和会话状态
- **LangGraph 编排** – agent 被定义为图结构，支持可视化的工作流表示、基于验证结果的条件分支以及全面的审计跟踪
- **向量增强的验证** – 启用 Pgvector 的 PostgreSQL 支持语义相似性搜索，使 AIM Model Analyst agent 能够基于技术描述而非关键字匹配来匹配变更模型
- **一致的处理** – 变更请求遵循相同的验证步骤，满足合规要求和质量标准

### 智能事件管理

第二个用例展示了用于事件管理的智能多 agent 编排，其中 Smart Solver Agent 分析传入的事件，并根据上下文需求选择性地调用专门的 agent。该实现根据每个事件的独特特征调整处理步骤，优化资源利用，同时在需要时提供全面的丰富。

该实现包含以下关键组件：![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/02/02/image-4.jpg)

- **智能编排** – Smart Solver Agent 分析事件内容，并根据缺失的上下文和潜在的增值确定要调用哪些专门的 agent
- **专门的 agent 调用** – 五个专门的 agent（Tag Classifier、Incident Similarity、Incident Associator、Change Associator、Context Retriever）可根据事件的详细程度和复杂性提供丰富
- **自适应处理** – 系统根据事件的复杂性调整丰富活动——简单事件可能只需要标记，而复杂问题则接受完整的上下文分析

## 经验教训

在 Iberdrola 实施 AI agent 展示了 Amazon Bedrock AgentCore 的托管原语如何显著加速企业 AI 部署。Amazon Bedrock AgentCore 最小化了 agentic AI 通常需要的基础设施复杂性，帮助团队专注于 agent 逻辑，同时获得可扩展且安全的云资源。"在 Iberdrola，我们正在用 Amazon Bedrock AgentCore 驱动的新 agentic 能力扩展我们的生产 AI 平台，"Iberdrola 的 AI 全球专家工程师 Iñigo Gutierrez 表示，"通过使用带有内置身份、记忆和可观测性的托管 serverless 运行时，我们能够交付基于 LangGraph 的 agent，它们能规划、通过 MCP 风格的网关调用工具，并在我们的 VPC 内安全运行。这一特性使我们从单点自动化迈向可复用的、生产级的 agent——降低工程的认知负担，并加速跨 IT 运营的安全交付。"

### 关键成功因素

该解决方案提供以下关键优势：

- **专用运行时 ** – AgentCore Runtime 提供完全托管的快速入门环境来托管 AI agent，并实现完全的会话隔离。此外，AgentCore Runtime 开箱即用的流式传输能力以及对 MCP 和 A2A 的支持，免去了开发自定义方案和构建对这些协议支持的需要。
- **托管基础设施** – Amazon Bedrock AgentCore 的 serverless 计算运行时、身份和记忆服务，将企业级能力所需的自定义开发开销降至最低。
- **企业安全** – VPC 支持和全面的标记符合严格的 IT 要求，在不牺牲安全标准的前提下加速开发。
- **开放且框架无关** – Amazon Bedrock AgentCore 与开发指南高度契合，因为你可以通过添加简单的装饰器来选择开发框架，例如 LangGraph。此外，它对使用 Langfuse 等第三方或开源解决方案没有任何限制。
- **可扩展的工具发现** – AgentCore Gateway 自动索引工具并提供 serverless 语义搜索，可从数十个目标扩展到数百个目标，且完全托管。
