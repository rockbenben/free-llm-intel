# 使用 Amazon SageMaker 训练会话 API 编写您自己的训练循环（无需管理 GPU）

如今，对大型语言模型 (LLM) 进行微调通常会迫使我们在训练循环控制和操作简单性之间进行权衡。通过完全托管的服务，您可以选择一个基本模型，提供数据和超参数，并且该服务拥有其他一切，当标准的预打包配方适合您的问题时，这种方法可以很好地发挥作用。托管服务越少，您的控制权就越大，但您也可以管理更多的底层基础设施和培训框架。有时标准方法是不够的：您需要用于监督微调（SFT）的自定义损失或数据课程、您自己的偏好优化、强化学习（RL）奖励函数或上周发布的对齐算法。一旦您需要自己制定训练程序，您就可以承担基础设施工作以获得算法自由。

如今，Amazon SageMaker AI 中的无服务器模型定制通过训练会话 API 进行了扩展，通过将抽象边界绘制得低一级来消除这种权衡。他们没有抽象出算法，而是抽象出了计算。 “forward_backward()”、“optim_step()”和“sample()”等操作成为 SageMaker API 调用，您可以将其组合到您的技术所需的任何过程中：SFT、偏好优化、RL 或新的东西。这些调用以实时、有状态的会话为目标，因此模型跨步骤保持在 GPU 上加载，并且您可以根据需要对其进行任意数量的调用。该服务处理运行时设置、分布式执行、梯度同步、故障恢复、租户隔离以及大规模运行 GPU 的操作。您编写训练循环，SageMaker AI 运行基础设施。

除了该服务之外，我们还发布了 [SageMaker 培训课程食谱](https://github.com/aws/sagemaker-training-sessions-cookbook)，这是一组可立即运行的 SFT 和 RL 食谱，您可以将其用作您自己的培训循环的蓝图。

在这篇文章中，我们介绍了编程模型和三个 SDK 客户端，并展示了训练会话 API 在 SageMaker AI 中的模型训练和自定义选项中的适用范围。然后，我们拆解小学数学问题 (GSM8K) 的最小 RL 循环，以展示操作如何组合在一起，并以食谱中的实际工作负载完成：竞争性编程问题的强化学习，其中生成的代码通过针对单元测试运行来进行评分。

## 什么是 SageMaker AI 训练会话 API？

借助 SageMaker AI 训练会话 API，您可以从本地计算机上自己的 Python 进程驱动实时、GPU 支持的会话。您调用这些操作，SageMaker AI 在加载了您选择的基本模型和低阶适应 (LoRA) 适配器的托管加速器上运行它们。没有预先描述整个作业的配置文件，也没有集群创建步骤。您可以通过代码以交互方式控制每个步骤中发生的情况，以便您可以快速迭代和调试。

职责划分如下：

| **您专注于** | **你写** | **SageMaker AI 手柄** |
| --- | --- | --- |
|您的数据、强化学习环境、代理和算法 | Python 训练循环，为需要 GPU 的步骤调用“forward_backward()”、“optim_step()”和“sample()”等操作 | GPU分配、模型和LoRA加载、分布式执行、故障恢复、检查点存储、安全 |

该 API 围绕 [SageMaker Python SDK](https://github.com/aws/sagemaker-python-sdk) 中的三个客户端组织，按顺序创建。 `ServiceClient` 保存平台级设置（执行角色、模型包组、Amazon Simple Storage Service (Amazon S3) 输出位置，以及可选的 AWS Key Management Service (AWS KMS) 密钥和 Virtual Private Cloud (VPC) 配置，您也可以在每个会话中覆盖这些配置）并启动会话。 “ServiceClient”实例化一个“TrainingClient”（训练和检查点操作，例如“forward”、“forward_backward”、“optim_step”和“save_weights_for_sampler”），后者又实例化一个“SamplingClient”（“sample”和“compute_logprobs”，用于在推出和评估期间生成和评分）。每个 API 调用都映射到循环中的一个操作。活动会话还提供与 OpenAI 兼容的聊天完成端点，因此现有的 OpenAI 客户端代码可以从中进行采样。

每个步骤都会加载一批提示和 (1) GPU 上当前模型的样本。然后，您的 Python 代码 (2) 对这些输出进行评分：验证器、奖励模型调用、测试工具以及可以用代码表达的任何内容。 (3) `forward_backward` 和 `optim_step` 将分数转换为 GPU 上的梯度更新，(4) `save_weights_and_get_sampling_client()` 刷新采样器，以便下一步从更新的模型中进行绘制。

你拥有数据、循环控制和奖励； SageMaker AI 运行 GPU 绑定的采样、梯度和检查点操作。相同的原语涵盖**监督微调（SFT）和其他 LLM 训练技术**。对于 SFT，放弃采样和奖励步骤，并在标记示例上调用“forward_backward”，并使用“cross_entropy”损失。

### 这是针对谁的以及它在 Amazon SageMaker AI 中的适用范围？

当您需要快速迭代周期和算法自由度（例如自定义损失、新的 RL 奖励信号或多级管道），但又不想自己配置或操作 GPU 基础设施时，训练会话 API 是正确的起点。

使用量按处理的令牌进行计费，因此您只需为循环消耗的计算付费。如果您的奖励函数需要 10 秒才能在计算机上对批次进行评分，则在运行时不会对 GPU 时间进行计费。与按 GPU 小时计费相比，这有两个实际优势。首先，没有闲置 GPU 成本：奖励计算、数据加载、日志记录和调试都是不定时进行的，并且仅在调用 GPU 绑定操作时才需要付费。其次，成本与数据集和生成量有关，而不是与挂钟时间或集群大小有关，这使得支出更容易预测，实验也更容易比较。对于具有大量本地计算的工作负载（例如复杂的奖励模型、多工具代理部署或人机循环评估），为整个会话保留 GPU 所节省的费用可能非常可观。

训练会话 API 是为团队构建的，这些团队的工作由训练算法定义，而不仅仅是数据集。因为您自己编写循环，所以相同的基元支持对标记数据进行“cross_entropy”损失的监督微调 (SFT)、使用“ppo”、“importance_sampling”或“cispo”（GRPO、PPO 和其他组相关方法）的**强化学习**，以及从相同部分构建的**自定义目标**，例如偏好优化或蒸馏。它们适合：

- 训练后和对齐研究人员实施 RL 方法（GRPO、PPO、重要性采样变体）、自定义优势估计器或新目标。
- 进行监督微调或偏好优化的团队需要非标准损失、数据课程或多阶段管道，而配置驱动的配方无法表达。
- 需要自定义推出逻辑、奖励塑造和课程的代理和多轮强化学习构建者。
- 机器学习 (ML) 工程师已经不再需要配置驱动的微调，但又不想承担 GPU 集群的操作负担。
- 研究人员移植现有的训练循环代码，因为基于操作的编程模型直接映射到针对低级“forward_backward”、“optim_step”和“sample” API 编写的循环。

[训练会话 API 文档](https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-training-sessions.html) 中列出了受支持的基本模型以及每个可用的 AWS 区域。

## 训练循环剖析：数学问题上的 GRPO

本节将分解一个最小的强化学习循环，以展示这些操作如何组合在一起。该任务是 [GSM8K](https://github.com/openai/grade-school-math)，它是大约 8,500 个小学数学应用题的基准，每个问题都有一个数字答案，如下例所示：

> Natalia 在 4 月份向她的 48 位朋友出售了剪辑，然后在 5 月份售出了一半的剪辑。娜塔莉亚在四月和五月总共卖出了多少个视频？ → 72

我们使用组相对策略优化 (GRPO) 为 OpenAI 的 **GPT-OSS 20B** 训练 LoRA 适配器：对于每个问题，模型都会生成多个答案，每个答案都会根据正确性进行评分，并且超过组平均水平的答案会得到强化。完整的可运行示例位于 [Amazon SageMaker 示例存储库](https://github.com/aws/amazon-sagemaker-examples/tree/default/%20%20%20%20%20model_customization/sm-training_sessions_grpo_gsm8k)。

在打开会话之前，请完成文档中的[先决条件](https://docs.aws.amazon.com/sagemaker/latest/dg/training-sessions-prereqs.html)。

### 打开一个会话

创建一个会话，然后从中获取分词器和“SamplingClient”：
```
from sagemaker.train.training_session import ServiceClient, SamplingParams, AdamParams

svc = ServiceClient(role_arn=role, region=REGION)

training_client = svc.create_lora_training_client(
    "openai/gpt-oss-20b",                        # a name from svc.list_base_models()
    training_session_name=SESSION_NAME,
    rank=32, alpha=64,                           # LoRA rank and scaling factor
    model_package_group_arn=MODEL_PACKAGE_GROUP_ARN,
    s3_output_path=OUTPUT_S3_PATH,
)
tokenizer = training_client.get_tokenizer()
sampling_client = training_client.create_sampling_client()
```
### 定义奖励和优势

特定于任务的逻辑是在您的计算机上运行的两个简短函数：
```
def compute_reward(response_text, ground_truth):
    predicted = extract_answer(response_text)      # parse the number after "#### "
    return 1.0 if predicted == ground_truth else 0.0

def compute_advantages(rewards):
    rewards = np.array(rewards)
    advantages = rewards - rewards.mean()          # center within the group (the GRPO baseline)
    return advantages / (rewards.std() + 1e-8)     # normalize
```
### 循环

每个步骤都遵循图 2 中所示的四个阶段。“draw”、“build_prompt”和“build_training_datum”是示例中的简短帮助程序：
```
for step in range(NUM_STEPS):
    datums, pending = [], []
    # (1) sample K responses per question in one request each (GPU); returns a future right away
    for question, ground_truth in draw(PROMPTS_PER_STEP):          # data loading is local
        prompt = tokenizer.encode(build_prompt(question), add_special_tokens=False)
        pending.append((prompt, ground_truth, sampling_client.sample(
            prompt, num_samples=K,
            sampling_params=SamplingParams(max_tokens=512, temperature=0.7, top_p=0.9))))

    for prompt, ground_truth, future in pending:
        result = future.result()                                    # wait once the batch is in flight
        # (2) score each response, then center the rewards within the group (local)
        rewards = [compute_reward(tokenizer.decode(s.tokens), ground_truth) for s in result.sequences]
        advantages = compute_advantages(rewards)
        datums += [build_training_datum(prompt, s, a) for s, a in zip(result.sequences, advantages)]

    # (3) one gradient step over the batch (GPU); the optimizer step is sequenced behind it
    fwd_bwd_op = training_client.forward_backward(datums, loss_fn="ppo")
    optim_op = training_client.optim_step(AdamParams(learning_rate=1e-5))
    fwd_bwd_op.result(), optim_op.result()

    # (4) refresh the sampler so the next step's rollouts come from the updated policy (GPU)
    sampling_client = training_client.save_weights_and_get_sampling_client()

training_client.stop()
```
三个细节使这个循环起作用：

操作回报期货。每个 GPU 绑定调用都会立即返回一个“APIFuture”：请求排队并由后台提交者发送，并且“.result()”等待该值。该循环在等待任何一个步骤的采样请求之前提交所有采样请求，因此整个批次会同时生成。训练操作按照您调用它们的顺序运行，因此可以在“forward_backward”完成之前提交“optim_step”。

该数据包含损失所需的一切。 `build_training_datum` 打包了提示和响应令牌、来自 `sample()` 的每个令牌的 logprobs、优势以及使提示免受损失的 `weights` 掩码。

检查点是模型包。每次保存都会在模型包组中注册一个版本，包括上面循环中的每步采样器刷新。训练后，另外两次保存添加了用于部署的合并模型以及带有权重和优化器的可恢复状态。
```
training_client.save_weights_for_sampler(merge_weights=True).result()   # merged, deployable model
training_client.save_state().result()                                   # resumable state (weights + optimizer)
```
要恢复，请使用“create_training_client_from_state_with_optimizer”从最新的检查点开始一个新会话。

正在运行的会话将计入并发会话配额，直到您调用“stop()”或它过期为止，因此在完成后停止它，包括在错误路径中，或者在“with”块中打开客户端。合并的检查点部署到实时端点。要将检查点作为 LoRA 适配器提供服务，请参阅说明书的[部署笔记本](https://github.com/aws/sagemaker-training-sessions-cookbook/blob/main/notebooks/deploy_to_sagemaker_inference.ipynb)。

在我们的样本运行中，针对 40 个问题的 10 个训练步骤将保留准确度从 56% 提高到了 75%。

## 现实世界的工作负载：竞争性编程的强化学习

GSM8K 使机制保持可见，但生产 RL 工作负载会增加更多：更长的代数、多轮交互、外部分级机以及足够的吞吐量以保持 GPU 繁忙。 [SageMaker 培训课程手册](https://github.com/aws/sagemaker-training-sessions-cookbook) 将其工程打包到基于相同操作构建的可重用培训循环中。对于新的 RL 任务，您需要编写一个环境：模型看到的内容、其答案如何评分以及是否会进行另一轮。该食谱处理批处理、聊天模板、优势估计、重叠采样和训练、验证、简历检查点和每步指标，并记录每次运行的配置，以便可以重复。 “code_rl”配方使用它来训练竞争性编程问题的模型。

任务。问题来自 DeepCoder 数据集（用于训练的 PrimeIntellect、TACO 和 LiveCodeBench；用于测试的 Codeforces 和 LiveCodeBench）。该模型编写了一个 Python 解决方案，该解决方案在计算机上的 [SandboxFusion](https://github.com/bytedance/SandboxFusion) 容器中针对问题的单元测试运行。当所有测试都通过时奖励为 1，否则奖励为 0，当响应不包含代码块时奖励为 0.1。

多回转刀具的使用。经过两轮，模型可以调用“check_solution”工具，读取测试结果，并在最终评分之前修改其答案。工具调用和结果以模型的本机聊天格式呈现，因此模型使用推理时使用的相同标记格式进行训练。

该配方添加到最小循环的内容：

- **重叠采样和训练：** 当训练器运行步骤时，Rollout 工作人员不断生成。如果旧策略最多有 k 步，则使用从旧策略中采样的一组响应，否则重新排队，并且“cispo”损失会纠正策略差异。
- **流式梯度计算：** `forward_backward` 在组完成时分批提交，而不是每步提交一次。
- **保留验证、检查点恢复和每步指标**，可选择发布到 [SageMaker 管理的 MLflow](https://docs.aws.amazon.com/sagemaker/latest/dg/mlflow.html)。

该食谱在同一结构上有更多食谱，包括对聊天数据集（Tulu 3、UltraChat）的监督微调、GSM8K 上的全面强化学习，以及来自二进制反馈的 KTO 偏好对齐。每个配方自述文件都列出了其命令、超参数和预期指标。

## 结论

SageMaker AI 训练会话 API 将抽象边界下移到训练操作：您在自己的计算机上用 Python 编写训练循环，该服务在托管 GPU 上运行它，处理模型和 LoRA 加载、分布式执行、故障恢复和检查点。完整的 GRPO 循环可归结为四个操作：“sample”、“forward_backward”、“optim_step”和“save_weights_and_get_sampling_client”，并在您自己的代码中包含奖励和优势逻辑。相同的操作可扩展到多轮、使用工具的 RL 和沙盒分级，如代码 RL 配方所示。

自定义奖励、代理推出、分步调试和新发布的技术都使用相同的编程模型：算法保留在循环中，SageMaker AI 运行 GPU。

开始使用：

- 从 [SageMaker 培训课程食谱](https://github.com/aws/sagemaker-training-sessions-cookbook) 中选择一个食谱，例如 [Code RL](https://github.com/aws/sagemaker-training-sessions-cookbook/tree/main/training_sessions_cookbook/recipes/code_rl)。
- 从 Amazon SageMaker 示例存储库运行 [GSM8K 示例](https://github.com/aws/amazon-sagemaker-examples/tree/default/%20%20%20%20%20model_customization/sm-training_sessions_grpo_gsm8k) 并交换您自己的奖励函数。
- 阅读[训练会话 API 文档](https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-training-sessions.html)，了解先决条件、配额、区域、支持的模型和 API 参考。
