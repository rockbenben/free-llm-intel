# IskayPet 如何用 Amazon Bedrock 托管知识库统一企业知识

IskayPet 的办公团队曾面临一个知识难题。日常运营问题的答案——比如退货政策、兽医操作规程或入职流程中的某一步——散落在数百份 Microsoft SharePoint 文档中，横跨四种语言和三个国家。在庞大的文档库中查找正确的信息要花很长时间。每新增一家门店、一个国家或一套流程，问题都会变得更大。

检索增强生成（RAG）是解决这一问题的常规做法。但在生产环境中运行 RAG 通常意味着要自己运维向量数据库、embedding 流水线和摄取任务。

本文介绍 IskayPet——伊比利亚半岛领先的宠物护理公司——如何基于 Amazon Bedrock Managed Knowledge Bases 构建企业知识助手。该助手用四种语言、在三个国家回答员工在零售运营、兽医护理、人力与入职以及采购方面的问题，而且无需管理任何 RAG 基础设施。团队使用 Kiro 搭配 Claude Haiku 4.5，完成了从面向门店的前端到 AWS 架构与部署的整套方案。我们将介绍架构、SharePoint 集成、检索配置上的决策，以及生产环境中的成果。

## 关于 IskayPet

IskayPet 是伊比利亚半岛领先的宠物护理公司。它在西班牙、葡萄牙和法国以 Kiwoko、Tiendanimal、Kivet、Clinicanimal 和 Animalis 品牌运营 330 多家门店。IskayPet 拥有 4,500 多名员工和 700 万名客户，业务覆盖零售、兽医诊所、宠物护理、采购以及人力与入职。每个领域都有自己的政策和流程，涉及西班牙语、葡萄牙语、法语和英语。

## 挑战

在每个业务领域，IskayPet 的办公人员都要手工检索数百份 SharePoint 文档，来回答关于流程、政策、合同和入职的运营问题。业务横跨三个国家、四种语言，这确实很费时间，而答案常常过时或错误。

当时没有可靠的方式来查询企业知识，而且每增加一个国家、领域或文档，问题就更严重。IskayPet 需要一个能做到以下各点的解决方案：

- 基于自身企业文档回答自然语言问题。
- 在四种语言下工作，且无需维护多套系统。
- 将每个问题路由到对应的知识范围（某个领域、某个国家），而不发生交叉污染。
- 无需重新设计架构就能扩展到新的领域和国家。
- 引用来源，让员工能够信任并核实答案。
- 复用现有的 SharePoint 存储库，无需代价高昂的数据迁移。

## 为什么选择 Amazon Bedrock Managed Knowledge Bases

IskayPet 选择了 Amazon Bedrock Managed Knowledge Bases 提供的托管 RAG 基础设施，从而不再需要运行向量存储、embedding 或摄取流水线。主要原因是：

- **托管 RAG：** Amazon Bedrock 负责数据摄取、多模态解析、向量存储、embedding 生成和检索。IskayPet 只需为实际存储和检索的内容付费。
- **原生 SharePoint 连接器：** 该连接器直接从 IskayPet 现有的 SharePoint 环境摄取文档，从而避免了数据迁移。启用高级索引后，它还会处理文档中嵌入图片里的内容。
- **内建混合搜索：** 以不额外收费的方式结合语义搜索和关键词（BM25）搜索，能够找回纯语义搜索可能漏掉的精确词项，例如产品编码和编号。
- **托管 reranking：** 检索到的段落会按相关性重新排序，且不额外收费。
- **文档级访问控制：** 知识库可以在检索时执行源系统自身的权限，因此一次查询只会返回请求用户本就有权阅读的文档中的段落。这让 IskayPet 可以复用 SharePoint 权限，而不必重建一套授权模型。
- **模型灵活性：** IskayPet 可以先从成本效益高的模型起步，之后再更换模型，而无需重写基础设施。
- **原生 RAG 评估：** 团队用内建评估工具衡量每一步的质量。

图 1：方案架构

该方案是一个员工可以通过现有渠道访问的助手。当员工提问时，助手会从知识库中检索最相关的段落，范围限于该员工有权阅读的文档。然后它用员工所用的语言生成有依据、带引用的回答。

从高层看，流程如下：

- 员工通过聊天界面提交自然语言问题。
- 应用为所请求的助手调用知识库，并传入员工身份，以便在检索时应用文档级权限。
- 知识库对已索引的内容执行混合搜索（语义与关键词），对结果重新排序，并返回最相关段落及其来源引用。
- 基础模型（FM）根据检索到的段落生成有依据的回答。提示词要求引用来源，并告知模型在答案不在检索内容中时要说明这一点。
- 员工收到回答以及来源文档，并可以留下反馈（点赞或点踩），这些反馈会进入评估集。

### 使用 Kiro 和 Claude Haiku 4.5 构建方案

IskayPet 使用 [Kiro](https://kiro.dev/)——一个运行在 Amazon Bedrock 上 Claude Haiku 4.5 之上的 agentic 开发环境——完成了整套方案，从面向门店的前端到 AWS 架构与服务部署。随着 Amazon Bedrock 上有新的模型可用，IskayPet 计划针对每个用例评估并采用它们。

关于各 AWS 区域的模型可用性，请参阅 [Amazon Bedrock 中按 AWS 区域支持的模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。

- **面向门店的前端 **——团队使用 Kiro 构建门店员工与助手交互所用的前端，并用 Claude Haiku 4.5 生成和迭代 UI 代码。
- **架构与部署 **——Kiro 还协助设计 AWS 架构并配置方案背后的各项服务：知识库配置、数据源、AWS Identity and Access Management（IAM）角色以及应用层。

用 Kiro 搭配 Claude Haiku 4.5 这类快速、成本效益高的模型所构成的 agentic 工作流，帮助一个小团队快速从概念走向生产。它还让应用代码与基础设施保持一致并且易于维护。

### 摄取：带高级索引的 SharePoint 连接器

IskayPet 的文档本来就存放在 SharePoint 中，并按领域和国家组织。团队没有迁移它们，而是使用了 Amazon Bedrock Managed Knowledge Bases 中的原生 SharePoint 连接器。

在数据源的 Advanced configurations 下，即 Content indexing 和 Advanced indexing 处，IskayPet 启用了 Visual content in documents。该设置会从文档（PDF、DOCX、PPTX）中嵌入的图片以及独立图片中提取内容。流程文档中的图表和扫描内容变得可搜索，而无需单独的前处理流水线。

该连接器以增量方式同步，因此新增和更新的文档会在每次同步时被捕获。

### 多国家、多领域架构

一个关键设计决策是如何为四种语言、若干业务领域和三个国家组织知识。IskayPet 权衡了两种做法：

- 单一的共享知识库，为每份文档打上国家和领域标签，并按查询应用检索过滤器。这最大化了共享内容的复用，但把所有域都耦合进一个索引。
- 每个助手一个专用知识库，各自限定在相关的 SharePoint 站点或库。这让每部分知识在端到端上保持隔离，并让每个助手可以独立调优。

IskayPet 选择了每个助手一个知识库。每个助手指向特定的 SharePoint 站点，还可以通过包含路径进一步收窄到特定的文档库或文件夹，因此它只索引预期内容，而不是整个企业站点。新增一个领域或国家意味着新增一个助手并让它指向正确的内容，而不是重新设计系统。

### 访问控制

访问由用户现有的 SharePoint 权限管理。助手不会授予任何新的访问权限：它只是让查询员工本就能打开的文档变得更直接。这在两个层面生效。

- **用户能看到哪些助手——** 员工只会看到其底层文档对自己有权阅读的那些助手，无论这种权限来自直接授权、组成员身份，还是对特定文件夹的访问权。如果无法确认访问权限，该助手会被隐藏而不是显示出来。
- **哪些文档为回答提供依据——** 检索时会按文档再次强制校验访问权限：员工身份被传给知识库，知识库只返回该人员有权查看的文档中的段落。Amazon Bedrock Managed Knowledge Bases 原生支持这种文档级访问控制，因此对同一问题的答案，在权限不同的两名员工之间也可能合理地不同。

由于每次访问检查都会从 SharePoint 读取权限，在 SharePoint 中撤销或授予访问权会反映到助手中，而无需修改应用。

### 检索与生成配置

RAG 系统的质量主要取决于摄取、检索和生成。微调是一种补充性技术。对于这个用例，IskayPet 调整了以下设置：

- **分块——** 由托管知识库处理，因此团队没有构建或调优分块流水线。这去掉了一个在自管理 RAG 中通常需要大量运维投入的组件。
- **混合搜索——** 知识库结合语义检索与关键词检索，能够找回纯语义搜索可能漏掉的精确词项，例如产品编码。
- **结果数量——** 依据评估集进行调优。助手检索 25 个段落，在去除重复项和过短、无法增加上下文的片段后，最多将 15 个注入提示词。这个数字是主要的成本杠杆，因为它会在每个问题上成倍增加输入 token。
- **生成提示词——** 强制统一的企业语气，要求引用来源，并告知模型在答案不在检索内容中时予以说明，从而减少幻觉并增加可追溯性。

作为一项生产控制措施，团队正在加入 [Amazon Bedrock Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)，对生成的回答应用内容过滤和负责任 AI 策略。

- **评估**——采用 Amazon Bedrock 原生 RAG 评估，把真实使用中的点赞和点踩反馈作为评估集，在每次变更前后衡量质量。

### 生成回答

在回答生成方面，IskayPet 使用 Amazon Bedrock 上一个成本效益高的基础模型。由于知识库将检索与生成解耦，IskayPet 可以切换或升级生成模型，而不触及摄取或检索层。这让团队能随着使用量增长在成本与回答质量之间取得平衡。

## 成本效率

知识库包含多模态解析、embedding 生成和 reranking，且不额外收费，因此 IskayPet 的持续成本主要来自索引存储、检索 API 调用和生成模型的 token。在生产环境中，输入 token 主导了这部分成本，因为每个提示词都要注入若干段落。随着使用量增长，团队正在评估进一步的优化，包括针对提示词稳定部分的 prompt caching，以及面向非交互式工作负载的批量推理。

## 成果

在生产环境的大约头两个月里，IskayPet 观察到：

- **更快的回答——** 找到运营答案的时间从 3–5 分钟降到约 7 秒。
- **更高的生产力——** 花在查找流程和政策上的时间减少了约 95%。
- **规模——** 预计该方案能在所有业务领域和国家每月处理约 100,000 次查询。

## 结论

IskayPet 基于 Amazon Bedrock Managed Knowledge Bases 构建了一个生产级企业知识助手，服务三个国家、四种语言和多个业务领域，且无需运行任何 RAG 基础设施。原生 SharePoint 连接器复用了他们现有的存储库。每个助手一个专用知识库，为他们提供了干净的多国家设计，每个域在端到端上相互隔离。托管的解析、embedding 和 reranking 让运维投入和成本都保持在低水平。用 Kiro 和 Claude Haiku 4.5 构建前端与 AWS 架构，让小团队能够快速到达生产环境。

如果你也面临类似的知识检索挑战，可以从 AWS Free Tier 开始，在 Amazon Bedrock 控制台上构建你的第一个知识库。要进一步深入，请参阅以下资源，并用你自己的文档试用 SharePoint 连接器和文档级访问控制。

要了解更多，请参阅 [Amazon Bedrock Managed Knowledge Base](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-build-managed.html) 和 [使用 Amazon Bedrock 评估功能评估 RAG 来源的表现](https://docs.aws.amazon.com/bedrock/latest/userguide/evaluation-kb.html)。
