# IskayPet 如何将企业知识与 Amazon Bedrock 托管知识库统一起来

IskayPet 的办公室团队面临着知识挑战。日常操作问题（例如退货政策、兽医协议或入职步骤）的答案存在于分布在四种语言和三个国家/地区的数百份 Microsoft SharePoint 文档中。在大型文档存储库中查找正确的信息需要很长时间。每一个新的商店、国家或程序都会让问题变得更加严重。

检索增强生成（RAG）是解决这个问题的常用方法。但在生产中运行 RAG 通常意味着您自己操作矢量数据库、嵌入管道和摄取作业。

在这篇文章中，我们将展示伊比利亚领先的宠物护理公司 IskayPet 如何在 Amazon Bedrock 托管知识库上构建企业知识助理。该助理以四种语言在三个国家/地区回答零售运营、兽医护理、人员和入职以及采购方面的员工问题，无需管理 RAG 基础设施。该团队使用 Kiro 和 Claude Haiku 4.5 构建了整个解决方案，从面向商店的前端到 AWS 架构和部署。我们涵盖架构、SharePoint 集成、检索配置决策和生产结果。

## 关于 IskayPet

IskayPet 是伊比利亚地区领先的宠物护理公司。该公司在西班牙、葡萄牙和法国经营着 330 多家商店，品牌包括 Kiwoko、Tiendanimal、Kivet、Clinicanimal 和 Animalis。 IskayPet 拥有超过 4,500 名员工和 700 万客户，业务涵盖零售、兽医诊所、动物护理、采购以及人员和入职培训。每个地区都有自己的政策和程序，包括西班牙语、葡萄牙语、法语和英语。

## 挑战

在每个业务领域，IskayPet 办公室工作人员手动搜索了数百个 SharePoint 文档，以回答有关程序、政策、合同和入职培训的操作问题。由于在三个国家和四种语言中进行操作，这需要实时的时间，而且答案通常是过时的或错误的。

没有可靠的方法来查询公司知识，而且这个问题随着每个国家、地区或文档的添加而变得越来越严重。 IskayPet 需要一个可以执行以下操作的解决方案：

- 回答基于其公司文档的自然语言问题。
- 跨四种语言工作，无需维护单独的系统。
- 将每个问题发送到正确的知识体系（一个地区、一个国家），而不会交叉污染。
- 无需重新架构即可扩展到新的地区和国家。
- 引用其来源，以便员工可以信任并验证答案。
- 重用现有的 SharePoint 存储库，无需进行昂贵的迁移。

## 为什么 Amazon Bedrock 托管知识库

IskayPet 选择 Amazon Bedrock 托管知识库作为其托管 RAG 基础设施，这消除了运行矢量存储、嵌入或摄取管道的需要。主要原因是：

- **托管 RAG：** Amazon Bedrock 处理数据摄取、多模式解析、矢量存储、嵌入生成和检索。 IskayPet 只需为其存储和检索的内容付费。
- **本机 SharePoint 连接器：** 连接器直接从 IskayPet 的现有 SharePoint 环境中提取文档，从而避免了数据迁移。启用高级索引后，它还可以处理文档中嵌入的图像内容。
- **内置混合搜索：** 将语义和关键字 (BM25) 搜索相结合，无需额外成本即可恢复纯语义搜索可能错过的精确术语，例如产品代码和参考。
- **托管重新排名：** 检索到的段落按相关性重新排序，无需额外付费。
- **文档级访问控制：** 知识库可以在检索时强制执行源系统自己的权限，因此查询仅返回请求用户已被允许读取的文档中的段落。这使得 IskayPet 可以重用 SharePoint 权限，而不是重建授权模型。
- **模型灵活性：** IskayPet 可以从具有成本效益的模型开始，然后在无需重写基础设施的情况下进行更改。
- **原生 RAG 评估：** 团队使用内置评估工具测量每个步骤的质量。

## 解决方案概述

下图显示了从员工的问题到权限感知检索再到有根据的引用答案的端到端流程。

![解决方案架构](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/16/ML-21903-1.png)

图 1：解决方案架构

解决方案是员工通过现有渠道联系的助手。当员工提出问题时，助理会从其知识库中检索最相关的段落，仅限于允许员工阅读的文档。然后，它会用员工的语言生成一个有根据的、被引用的答案。

在较高层面上，流程的工作原理如下：

- 员工通过聊天界面提交自然语言问题。
- 应用程序调用所请求助理的知识库，传递员工的身份，以便将文档级权限应用于检索。
- 知识库对索引内容运行混合搜索（语义和关键字），对结果重新排名，并返回最相关的段落及其源参考。
- 基础模型 (FM) 从检索到的段落中生成有根据的答案。该提示需要来源引用，并告诉模型何时答案不在检索到的内容中。
- 员工收到答案以及源文档，并可以留下反馈（赞成或反对）以提供评估集。

### 使用 Kiro 和 Claude Haiku 4.5 构建解决方案

IskayPet 使用在 Amazon Bedrock 上的 Claude Haiku 4.5 上运行的代理开发环境 [Kiro](https://kiro.dev/) 构建了整个解决方案，从面向商店的前端到 AWS 架构和服务部署。随着 Amazon Bedrock 上推出新模型，IskayPet 计划针对每个用例评估并采用它们。

有关 AWS 区域的模型可用性，请参阅 [Amazon Bedrock 中 AWS 区域支持的模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。

- **面向商店的前端 **– 团队使用 Kiro 构建商店员工用来与助理交互的前端，使用 Claude Haiku 4.5 生成和迭代 UI 代码。
- **架构和部署 **– Kiro 还帮助设计了 AWS 架构并配置了解决方案背后的服务：知识库配置、数据源、AWS Identity and Access Management (IAM) 角色以及应用程序层。

Kiro 的代理工作流程以及 Claude Haiku 4.5 等快速、经济高效的模型帮助小团队快速从概念转向生产。它还保持应用程序代码和基础设施的一致性和可维护性。

### 摄取：具有高级索引的 SharePoint 连接器

IskayPet 的文档已存在于 SharePoint 中，按地区和国家/地区组织。该团队没有迁移它们，而是使用了 Amazon Bedrock 托管知识库中的本机 SharePoint 连接器。

在数据源的高级配置中，在内容索引和高级索引下，IskayPet 启用了文档中的可视内容。此设置从文档（PDF、DOCX、PPTX）中嵌入的图像和独立图像中提取内容。程序文档中的图形和扫描内容无需单独的预处理管道即可搜索。

连接器增量同步，因此每次同步时都会拾取新的和更新的文档。

### 多国家、多地区架构

一个关键的设计决策是如何构建四种语言、多个业务领域和三个国家的知识。 IskayPet 权衡了两种方法：

- 单个共享知识库，每个文档都按国家和地区标记，并且每个查询都应用检索过滤器。这最大化了共享内容的重用，但将所有域耦合到一个索引中。
- 每个助理都有一个专用的知识库，每个知识库的范围都涉及相关的 SharePoint 网站或库。这使得每个知识体系端到端隔离，并让每个助手独立调整。

IskayPet 为每个助手选择了一个知识库。每个助手都指向特定的 SharePoint 站点，并且可以通过包含路径进一步缩小到特定的文档库或文件夹，因此它仅索引预期内容，而不是整个公司站点。添加新的地区或国家意味着添加助手并将其指向正确的内容，而不是重新构建系统。

### 访问控制

访问权限由用户现有的 SharePoint 权限控制。助手不会授予对任何新内容的访问权限：它只会使查询员工已经可以打开的文档变得更加简单。这在两个层面上起作用。

- **用户看到哪些助手 –** 员工仅会看到其有权阅读其基础文档的助手，无论该权利来自直接权限、组成员身份还是对特定文件夹的访问权限。如果无法确认访问，助手将被隐藏而不是显示。
- **哪些文档提供答案 –** 在检索时再次强制访问每个文档：员工的身份被传递到知识库，知识库仅返回该人员有权查看的文档中的段落。 Amazon Bedrock 托管知识库本身支持这种文档级访问控制，因此对于同一问题的相同答案在具有不同权限的两名员工之间可能会存在不同的情况。

由于每次访问检查时都会从 SharePoint 读取权限，因此在 SharePoint 中撤销或授予访问权限会反映在助手中，而无需更改应用程序。

### 检索和生成配置

RAG 系统的质量主要取决于摄取、检索和生成。微调是一种补充技术。对于此用例，IskayPet 调整了以下设置：

- **分块 –** 由托管知识库处理，因此团队没有构建或调整分块管道。这消除了在自我管理的 RAG 中通常需要大量运营工作的组件。
- **混合搜索 –** 知识库结合了语义和关键字检索，可以恢复纯语义搜索可能错过的精确术语，例如产品代码。
- **结果数量 –** 根据评估集进行调整。助手检索 25 个段落，并在删除重复项和太短而无法添加上下文的片段后，在提示中注入最多 15 个段落。这个数字是主要的成本杠杆，因为它会乘以每个问题的输入令牌。
- **生成提示 –** 强制采用公司语气，要求来源引用，并告诉模型何时答案不在检索到的内容中，从而减少幻觉并增加可追溯性。

作为生产控制，该团队正在添加 [Amazon Bedrock Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)，以将内容过滤和负责任的 AI 策略应用于生成的答案。

- **评估 –** 原生 Amazon Bedrock RAG 评估，使用实际使用的赞成和反对反馈作为评估集来衡量每次更改之前和之后的质量。

### 生成响应

为了生成答案，IskayPet 在 Amazon Bedrock 上使用经济高效的基础模型。由于知识库将检索与生成解耦，IskayPet 可以切换或升级生成模型，而无需触及摄取或检索层。这使得团队可以随着使用量的增长平衡成本和答案质量。

## 成本效率

知识库包括多模态解析、嵌入生成和重新排名，无需额外付费，因此 IskayPet 的持续成本主要来自索引存储、检索 API 调用和生成模型令牌。在生产中，由于每个提示中都注入了段落，因此输入标记在成本中占主导地位。随着使用量的增长，该团队正在评估进一步的优化，包括提示稳定部分的提示缓存以及非交互式工作负载的批量推理。

## 结果

大约在生产的前两个月，IskayPet 发现：

- **更快的答案 –** 找到可操作答案的时间从 3-5 分钟减少到大约 7 秒。
- **更高的生产力 –** 搜索程序和政策所花费的时间减少约 95%。
- **规模 –** 该解决方案预计每月可处理所有业务领域和国家/地区的大约 100,000 个查询。

＃＃ 结论

IskayPet 在 Amazon Bedrock 托管知识库上构建了一个生产企业知识助理，为三个国家、四种语言和多个业务领域提供服务，无需运行 RAG 基础设施。本机 SharePoint 连接器重用其现有存储库。每个助理都有一个专用的知识库，为他们提供了干净的多国设计，每个领域都是端到端隔离的。托管解析、嵌入和重新排名可降低运营工作量和成本。使用 Kiro 和 Claude Haiku 4.5 构建前端和 AWS 架构可以让小团队快速投入生产。
