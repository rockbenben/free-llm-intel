# 如何使用 Amazon Bedrock Custom Model Import 配置跨账户模型部署

在企业环境中，组织常把 AI 运营拆分为两个专职团队：AI 研究团队与模型托管团队。研究团队专注于使用[模型训练与微调](https://aws.amazon.com/blogs/aws/accelerate-foundation-model-training-and-fine-tuning-with-new-amazon-sagemaker-hyperpod-recipes/)技术开发和改进 AI 模型。与此同时，另一个独立的托管团队负责把这些模型部署到自己的开发、预发布和生产环境中。

借助 [Amazon Bedrock Custom Model Import](https://aws.amazon.com/bedrock/custom-model-import/)，托管团队可以导入并以 [On-Demand](https://aws.amazon.com/bedrock/pricing/) 计费方式提供使用受支持架构的自定义模型，例如 [Meta Llama 2、Llama 3](https://aws.amazon.com/bedrock/llama/) 与 [Mistral](https://aws.amazon.com/bedrock/mistral/)。团队可以从 [Amazon SageMaker](https://aws.amazon.com/sagemaker/) 或 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）导入权重为 [Hugging Face safetensors](https://huggingface.co/docs/safetensors) 格式的模型。这些导入的自定义模型以无服务器方式，通过单一统一的 API 与已有的 [Amazon Bedrock](https://aws.amazon.com/bedrock/) [基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM）协同工作，免去了管理模型部署与伸缩的负担。

然而在这类企业环境中，出于安全与运营考虑，这些团队往往在不同的 AWS 账户中工作。模型开发团队的训练成果（称为模型产物，例如模型权重）通常存放在研究团队 AWS 账户内的 S3 存储桶中，而托管团队需要从另一个账户访问这些产物才能部署模型。这就带来一个挑战：如何在账户之间安全地共享模型产物？

这正是跨账户访问变得重要的地方。借助 Amazon Bedrock Custom Model Import 的跨账户支持，我们可以帮你配置存放模型产物的 S3 存储桶与托管账户之间的直接访问。这在简化运营工作流的同时，维持团队之间的安全边界。我们的一位客户这样评价：

> Bedrock Custom Model Import 的跨账户支持帮助 AI Platform 团队简化了配置、降低了运营开销，并让模型安全地留在原始位置。
>         – Scott Chang，Salesforce AI Platform 首席工程师

本指南将带你逐步完成为 Amazon Bedrock Custom Model Import 配置跨账户访问的操作，既涵盖未加密场景，也涵盖基于 [AWS Key Management Service](https://aws.amazon.com/kms/)（AWS KMS）的加密场景。

## 示例场景

本次演练中，考虑两个 AWS 账户：

- 模型开发账户（`111122223333`）：在名为 `model-artifacts-111122223333` 的 S3 存储桶中存放模型产物（自定义权重与配置）；可选地用 AWS KMS 客户托管密钥 `kms-cmk-111122223333` 加密产物
- 模型托管账户（`777788889999`）：使用 Amazon Bedrock Custom Model Import 托管模型；使用一个新的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）执行角色 `BedrockCMIExecutionRole-777788889999`；可选地用 AWS KMS 密钥 `kms-cmk-777788889999` 加密产物

下图说明了这一设置，展示 S3 存储桶、KMS 密钥与 Amazon Bedrock Custom Model Import 之间的跨账户访问是如何配置的。

![Figure shows how the cross-account access is configured](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/19/ML-18125-figure1.png)

要在遵循最小权限原则的前提下成功实现所述场景，必须执行以下步骤：

- 模型开发账户必须通过基于资源的策略，向模型托管账户的 IAM 角色 `BedrockCMIExecutionRole-777788889999` 授予访问权限，使其能够使用自己的 S3 存储桶，以及（如适用）加密密钥
- 模型托管账户应建立一个 IAM 角色，例如 `BedrockCMIExecutionRole-777788889999`。所需基于身份的策略应针对模型开发账户的 S3 存储桶，以及用于解密模型产物的客户托管密钥，例如使用 `kms-cmk-111122223333`。
- 模型托管账户必须允许 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 服务承担第 2 步创建的 IAM 角色 `BedrockCMIExecutionRole-777788889999`，做法是把 Amazon Bedrock 服务列为可信实体。该 IAM 角色将由模型托管账户用来发起自定义模型导入作业。

## 先决条件

在开始自定义模型导入作业之前，你需要满足以下先决条件：

- 如果你从 S3 存储桶导入模型，请按 Hugging Face 权重格式准备模型文件。更多信息请参阅 [Import source](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-import-model.html#model-customization-import-model-source)。
- （可选）设置额外的安全配置。你可以加密输入与输出数据、导入作业，或对导入模型发起的推理请求。更多信息请参阅 [Encryption of custom model import](https://docs.aws.amazon.com/bedrock/latest/userguide/encryption-import-model.html)。你可以创建虚拟私有云（VPC）来保护定制作业。更多信息请参阅 [(Optional) Protect custom model import jobs using a VPC](https://docs.aws.amazon.com/bedrock/latest/userguide/vpc-custom-model-import.html)。

## 分步执行

下面从管理这两个账户的管理员视角，给出前述高层流程的分步执行过程：

**第 1 步**：在模型开发账户中设置 S3 存储桶策略，以允许模型托管账户的 IAM 角色访问：

- 以账户 `111122223333` 登录 [AWS Management Console](https://aws.amazon.com/console/)，然后访问 [Amazon S3 console](https://console.aws.amazon.com/s3/)。
- 在 **General purpose** 存储桶视图中，找到 `model-artifacts-111122223333`，即模型开发团队用来存放其模型产物的存储桶。
- 在 **Permissions** 标签页上，于 **Bucket policy** 区域选择 **Edit**，并插入以下基于 IAM 资源的策略。请务必把策略中（以 *red* 标出的）AWS 账户 ID 替换为你的信息。  `{ "Version": "2012-10-17", "Id": "AllowCrossAccountS3Access", "Statement": [ { "Sid": "cross-account-list-get", "Effect": "Allow", "Principal": { * "AWS": "arn:aws:iam::777788889999:root" * }, "Action": [ "s3:ListBucket", "s3:GetObject" ], "Resource": [ * "arn:aws:s3:::model-artifacts-111122223333", "arn:aws:s3:::model-artifacts-111122223333/*" * ], "Condition": { "ArnLike": { * "aws:PrincipalArn": "arn:aws:iam::777788889999:role/BedrockCMIExecutionRole-777788889999*" * } } } ] }`

**第 2 步**：在模型托管账户中建立 IAM 角色，并授权 Amazon Bedrock 承担该角色：

- 以账户 `777788889999` 登录 AWS 控制台，并打开 IAM 控制台。
- 在左侧导航窗格中选择 **Policies**，然后选择 **Create policy**。在 **Policy Editor** 中切换到 **JSON** 标签页，插入以下基于身份的策略。该策略面向只读访问，使用户或角色能够列出并下载指定 S3 存储桶中的对象，但仅当该存储桶属于账户 `111122223333` 时成立。请把 AWS 账户 ID 与 S3 存储桶名称/前缀（以 *red* 标出）替换为你的信息。  `{ "Version": "2012-10-17", "Statement": [ { "Sid": "1", "Effect": "Allow", "Action": [ "s3:ListBucket", "s3:GetObject" ], "Resource": [ * "arn:aws:s3:::model-artifacts-111122223333", "arn:aws:s3:::model-artifacts-111122223333/*" * ], "Condition": { "StringEquals": { *  "aws:ResourceAccount": "111122223333" * } } } ] }`

- 选择 **Next**，把策略命名为 `BedrockCMIExecutionPolicy-777788889999`，然后选择 **Create policy** 完成创建。
- 在左侧导航窗格中选择 **Roles**，并把 **Trusted entity type** 设为 **Custom trust policy**。插入以下可信实体策略，它将角色承担限制为 Amazon Bedrock 服务，专门用于账户 `777788889999` 中位于美国东部（弗吉尼亚北部）`us-east-1` 区域的模型导入作业。请把 AWS 账户 ID 与 [Region](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region)（以 *red* 标出）替换为你的信息。  `{ "Version": "2012-10-17", "Statement": [ { "Sid": "1", "Effect": "Allow", "Principal": { "Service": "bedrock.amazonaws.com" }, "Action": "sts:AssumeRole", "Condition": { "StringEquals": { * "aws:SourceAccount": "777788889999" * }, "ArnEquals": { * "aws:SourceArn": "arn:aws:bedrock:us-east-1:777788889999:model-import-job/*" * } } } ] }`

- 选择 **Next**，在 **Add permissions** 区域搜索上一步创建的策略 `BedrockCMIExecutionPolicy-777788889999`，勾选复选框，然后选择 **Next** 继续。
- 把 **Role name** 设为 `BedrockCMIExecutionRole-777788889999`，在 **Description** 中填写“IAM execution role to be used by CMI jobs”，然后选择 **Create role** 完成创建。

**重要：** 如果你在模型开发账户中为模型产物使用了 AWS KMS 加密密钥，或在 Amazon Bedrock 托管的 AWS 账户中为导入的模型产物使用了该密钥，请继续执行**第 3 步**至**第 5 步**。若不然，请跳到**第 6 步**。

**第 3 步：** 调整模型开发账户中的 AWS KMS 密钥策略，允许 Amazon Bedrock CMI 执行 IAM 角色解密模型产物：

- 回到模型开发账户，在 AWS KMS 控制台中找到名为 `kms-cmk-111122223333` 的 AWS KMS 密钥。记下该 AWS KMS 密钥的 Amazon Resource Name（ARN）。
- 在 **Key policy** 标签页中切换到 **Policy view**，加入以下基于资源的策略语句，使模型托管账户的 IAM 角色 `BedrockCMIExecutionRole-777788889999` 能够解密模型产物。请把 *red* 标出的内容替换为你的信息。  `{ "Sid": "Allow use of the key by the destination account", "Effect": "Allow", "Principal": { * "AWS": "arn:aws:iam::777788889999:role/BedrockCMIExecutionRole-777788889999" * }, "Action": [ "kms:Decrypt", "kms:DescribeKey" ], "Resource": "*" }`

**第 4 步：** 在模型托管账户中设置 AWS KMS 密钥策略，让 CMI 执行 IAM 角色能够加密和解密模型产物，从而安全地存放在 Amazon Bedrock 的 AWS 账户中：

- 回到模型托管账户，在 AWS KMS 控制台中找到名为 `kms-cmk-777788889999` 的 AWS KMS 密钥。记下该 AWS KMS 密钥的 ARN。
- 把以下语句插入该 AWS KMS 密钥的基于资源的策略，使 IAM 角色 `BedrockCMIExecutionRole-777788889999` 能够在 Amazon Bedrock 托管的 AWS 账户中加密和解密静态存储的模型产物。请把 *red* 标出的内容替换为你的信息。  `{ "Sid": "Allow use of the key", "Effect": "Allow", "Principal": { * "AWS": "arn:aws:iam::777788889999:role/BedrockCMIExecutionRole-777788889999" * }, "Action": [ "kms:Encrypt", "kms:Decrypt", "kms:ReEncrypt*", "kms:GenerateDataKey*", "kms:DescribeKey" ], "Resource": "*" }`

**第 5 步：** 在模型托管账户中修改 CMI 执行角色的权限，授予对加密密钥的访问：

打开 IAM 控制台，找到 IAM 策略 `BedrockCMIExecutionPolicy-777788889999`。在现有的基于身份的策略中追加以下语句（把 *red* 标出的 ARN 替换为你在**第 4 步**与**第 5 步**中记下的那个）：

```
{
    "Effect": "Allow",
    "Action": [
        "kms:Decrypt",
        "kms:DescribeKey"
    ],
 "Resource": "arn:aws:kms:us-east-1:111122223333:key/b5b6e052-fb27-4dbb-bf0d-daf3375a9fda" },
{
    "Effect": "Allow",
    "Action": [
        "kms:Encrypt",
        "kms:Decrypt",
        "kms:ReEncrypt*",
        "kms:GenerateDataKey*",
        "kms:DescribeKey"
    ],
 "Resource": "arn:aws:kms:us-east-1:777788889999:key/6cd5d3bf-3d9b-4d1c-83d5-8df6284435a1" }
```

**第 6 步：** 在模型托管账户中发起模型导入作业

在这一步，我们使用 [AWS Command Line Interface](https://aws.amazon.com/cli/)（AWS CLI）命令执行模型导入作业。你也可以用 [AWS SDK](https://aws.amazon.com/developer/tools/) 或 API 达到同样目的。请以具备创建自定义模型导入作业所需权限的 IAM 用户或角色，在终端会话中运行以下命令。你无需显式提供模型开发团队所用 CMK 的 ARN 或细节。

```
aws bedrock create-model-import-job \
    --job-name "cmi-job-777788889999-01" \
    --imported-model-name "mistral-777788889999-01" \
    --role-arn "arn:aws:iam::777788889999:role/BedrockCMIExecutionRole-777788889999" \
    --model-data-source "s3DataSource={s3Uri="s3://model-artifacts-111122223333/mistral-model-weights/"}"
```

使用 Amazon Bedrock Custom Model Import 加密模型产物时，请使用 `--imported-model-kms-key-id` 标志，并指定模型托管账户 CMK 密钥的 ARN。

```
aws bedrock create-model-import-job \
    --job-name "cmi-job-777788889999-04" \
    --imported-model-name "mistral-777788889999-01" \
    --role-arn "arn:aws:iam::777788889999:role/BedrockCMIExecutionRole-777788889999" \
    --model-data-source "s3DataSource={s3Uri="s3://model-artifacts-111122223333/mistral-model-weights/"}" \
    --imported-model-kms-key-id "arn:aws:kms:us-east-1:777788889999:key/6cd5d3bf-3d9b-4d1c-83d5-8df6284435a1" 
```

使用自定义模型导入作业跨账户访问 S3 存储桶，目前仅支持通过 AWS CLI、AWS SDK 或 API 实现。控制台支持尚不可用。

## 排查问题

当 IAM 策略配置不当导致自定义模型导入作业无法进行时，你可能会遇到类似这样的错误：

```
Amazon Bedrock does not have access to the S3 location (s3://model-artifacts-111122223333/mistral-model-weights). Update the permissions and try again.
```

要解决这个问题，请在模型托管账户中通过承担 `BedrockCMIExecutionRole-777788889999` 手动验证对模型开发账户 S3 存储桶的访问。请按以下步骤操作：

**第 1 步：** 用以下命令在 CLI 中确认当前的 IAM 角色或用户，并从输出中复制 ARN：

```
aws sts get-caller-identity
```

**第 2 步：** 更新信任关系。在 `BedrockCMIExecutionRole-777788889999` 的信任策略中追加内容，允许当前用户或 IAM 角色承担该角色：

```
{
    "Effect": "Allow",
    "Principal": {
        "AWS": "arn:aws:sts::777788889999:role/current-user-role"
    },
    "Action": "sts:AssumeRole"
}
```

**第 3 步：** 以 Amazon Bedrock Custom Model Import 执行角色的身份列出或复制 S3 存储桶内容

- 承担 CMI 执行角色（把 ARN 替换为你的信息）：  `aws sts assume-role \ --role-arn *"arn:aws:iam::776941257690:role/BedrockCMIExecutionRole-777788889999"* \ --role-session-name "BedrockCMISession"`
- 把返回的临时凭证导出为环境变量：  `export AWS_ACCESS_KEY_ID="ASIA..." export AWS_SECRET_ACCESS_KEY="..." export AWS_SESSION_TOKEN="..."`
- 运行命令排查权限问题：  `aws s3 ls *s3://model-artifacts-111122223333/mistral-model-weights/* aws s3 cp *s3://model-artifacts-111122223333/mistral-model-weights/config.json . *`

若错误仍然存在，可以考虑使用 [Amazon Q Developer](https://aws.amazon.com/q/developer/)，或参阅 [IAM User Guide](https://docs.aws.amazon.com/IAM/latest/UserGuide/troubleshoot.html#troubleshoot_general_resources) 中列出的其他资源。

## 清理

把自定义模型导入 Amazon Bedrock 不额外收费（参见**分步执行**一节的**第 6 步**）。不过，如果你的模型未用于推理，而你想避免支付存储费用（参见 [Amazon Bedrock pricing](https://aws.amazon.com/bedrock/pricing/)），可以使用 [AWS 控制台](https://console.aws.amazon.com/)、[AWS CLI 参考](https://docs.aws.amazon.com/cli/latest/reference/bedrock/delete-imported-model.html) 或 [API Reference](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_DeleteImportedModel.html) 删除该导入模型。例如（把 *red* 标出的文本替换为你的导入模型名称）：

```
aws bedrock delete-imported-model \
    --model-identifier "mistral-777788889999-01"
```

## 结语

借助 Amazon Bedrock Custom Model Import 的跨账户访问，组织可以显著简化其 AI 模型部署工作流。

Amazon Bedrock Custom Model Import 现已在 Amazon Bedrock 中于美国东部（弗吉尼亚北部）`us-east-1` 与美国西部（俄勒冈）`us-west-2` [AWS 区域](https://aws.amazon.com/about-aws/global-infrastructure/regions_az/) 正式可用。未来变更请参阅[完整区域列表](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。了解更多，请参阅 [Amazon Bedrock Custom Model Import](https://aws.amazon.com/bedrock/custom-model-import/) 产品页与 [Amazon Bedrock pricing](https://aws.amazon.com/bedrock/pricing/) 页面。今天就在 [Amazon Bedrock console](https://console.aws.amazon.com/bedrock) 中试用 Amazon Bedrock Custom Model Import，并把反馈发送到 [AWS re:Post for Amazon Bedrock](https://repost.aws/tags/TAQeKlaPaNRQ2tWB6P7KrMag/amazon-bedrock)，或通过你惯常的 AWS Support 联系人反馈。
