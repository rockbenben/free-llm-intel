# Nova Forge SDK 系列第二部分：利用数据混合能力微调 Nova 模型的实战指南

本实战指南逐步讲解使用 Amazon Nova Forge SDK 微调 Amazon Nova 模型的每一个环节，涵盖数据准备、带数据混合的训练以及评估，为你提供一套可套用到自身用例的可重复流程。这是 Nova Forge SDK 系列的第二部分，建立在 [SDK 简介](https://aws.amazon.com/blogs/machine-learning/introducing-nova-forge-sdk-a-seamless-way-to-customize-nova-models-for-enterprise-ai/) 与第一部分的基础之上，后者介绍了如何启动 [定制化实验](https://aws.amazon.com/blogs/machine-learning/kick-off-nova-customization-experiments-using-nova-forge-sdk/)。

本文聚焦数据混合：这项技术让你在领域数据上微调的同时，不必牺牲模型的通用能力。在[上一篇文章](https://aws.amazon.com/blogs/machine-learning/building-specialized-ai-without-sacrificing-intelligence-nova-forge-data-mixing-in-action/)中，我们论证了这件事为何重要——将客户数据与 Amazon 精选数据集混合后，Massive Multitask Language Understanding（MMLU）分数保持在接近基线的水平，同时在覆盖 1,420 个叶子类别的客户之声（Voice of Customer）分类任务上取得 12 个百分点的 F1 提升。相比之下，只用客户数据微调一个开源模型，会导致通用能力几乎完全丧失。现在我们演示如何自行复现这套做法。

## **方案概览**

该工作流包含五个阶段：

- **环境准备** – 安装 Nova Forge SDK 并配置 AWS 资源
- **数据准备** – 加载、清洗、转换、校验并切分你的训练数据
- **训练配置** – 配置 Amazon SageMaker HyperPod 运行时、MLflow 追踪与数据混合比例
- **模型训练** – 使用低秩适配（Low-Rank Adaptation，LoRA）启动并监控监督微调作业
- **模型评估** – 针对微调后的 checkpoint 运行公开基准测试与领域特定评估

## **前置条件**

开始之前，请确认已具备以下条件：

- 一个可访问 [Amazon Nova Forge](https://aws.amazon.com/nova/forge/) 的 AWS 账户
- 一个已置备 GPU 实例的 [SageMaker HyperPod](https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-hyperpod.html) 集群。本演练使用 `ml.p5.48xlarge` 实例。搭建 HyperPod 集群涉及配置 Amazon Elastic Kubernetes Service（Amazon EKS）集群、置备计算节点并创建执行角色。详细步骤请参阅 [SageMaker HyperPod 入门](https://docs.aws.amazon.com/sagemaker/latest/dg/smcluster-getting-started-slurm.html)。
- 一个用于实验追踪的 [Amazon SageMaker MLflow](https://docs.aws.amazon.com/sagemaker/latest/dg/mlflow.html) 应用
- 一个具备 SageMaker、Amazon Simple Storage Service（Amazon S3）和 Amazon CloudWatch 权限的 IAM 角色
- 一个 SageMaker Studio notebook 或类似的 Jupyter 环境

**成本考虑：** 本演练使用 4 台 `ml.p5.48xlarge` 实例进行训练与评估。这些是高端 GPU 实例。我们建议先做一次短时测试运行（max_steps=5）以验证配置，再投入完整训练。当前费率请参见 [Amazon SageMaker 定价页面](https://aws.amazon.com/sagemaker/pricing/)。

## **第 3 步：准备训练数据集**

Nova Forge SDK 支持 JSONL、JSON 和 CSV 输入格式。本演练使用 Hugging Face 上公开可用的 [MedReason](https://huggingface.co/datasets/UCSC-VLAA/MedReason) 数据集。该数据集包含约 32,700 组医疗推理问答对，可用于演示针对领域特定用例的微调。

### **下载并清洗数据**

Nova Forge SDK 会对训练数据执行 token 级校验。某些 token 会与模型内部的 chat template 冲突，具体是 Nova 在训练时用来分隔 system、user 和 assistant 轮次的特殊分隔符。如果你的数据中含有 ``System:`` 或 ``Assistant:`` 这样的字面字符串，模型可能把它们误判为轮次边界，从而污染训练信号。下面的清洗步骤在冒号前插入一个空格（例如 `System:` → `System :`）以打断模式匹配，同时保持可读性，并移除 `[EOS]` 和 `<image>` 这类在模型词表中具有保留含义的特殊 token。

```
from huggingface_hub import hf_hub_download
import pandas as pd
import json
import re

# Download the dataset
jsonl_path = hf_hub_download(
repo_id="UCSC-VLAA/MedReason",
filename="ours_quality_33000.jsonl",
repo_type="dataset",
local_dir="."
)
df = pd.read_json(jsonl_path, lines=True)

# Tokens that conflict with the model's chat template
INVALID_TOKENS = [
"System:", "SYSTEM:", "User:", "USER:", "Bot:", "BOT:",
"Assistant:", "ASSISTANT:", "Thought:", "[EOS]",
"<image>", "<video>", "<unk>",
]

def sanitize_text(text):
for token in INVALID_TOKENS:
if ":" in token:
word = token[:-1]
text = re.sub(rf'\b{word}:', f'{word} :', text, flags=re.IGNORECASE)
else:
text = text.replace(token, "")
return text.strip()

# Write sanitized JSONL
with open("training_data.jsonl", "w") as f:
for _, row in df.iterrows():
f.write(json.dumps({
"question": sanitize_text(row["question"]),
"answer": sanitize_text(row["answer"]),
}) + "\n")

print(f"Dataset saved: training_data.jsonl ({len(df)} examples)")
```

若想校验你的数据是否含有上述任何保留关键词，请运行这个[脚本](https://github.com/aws-samples/amazon-nova-samples/tree/main/customization/bedrock-finetuning/understanding/dataset_validation)。

### **使用 SDK 加载、转换并校验**

SDK 提供 `JSONLDatasetLoader`，负责把你的原始数据格式转换为 Nova 模型所需的结构。当你调用 `transform()` 时，SDK 会把每组问答对包装成 Nova chat template 格式，即 Nova 模型在训练时期待的结构化轮次格式。你的原始数据会从简单的问答对，变成带正确角色标签与分隔符、完整格式化的多轮对话。

**转换前**（你的原始 JSONL）：

```
{ 
    "question": "What are the causes of chest pain in a 45-year-old patient?", 
    "answer": "Chest pain in a 45-year-old can result from cardiac causes such as..."
}
```

**转换后**（Nova chat template 格式）：

```
{ 
    "messages": [ 
        {"role": "user", "content": "What are the causes of chest pain in a 45-year-old patient?"}, 
        {"role": "assistant", "content": "Chest pain in a 45-year-old can result from cardiac causes such as..."} 
    ]
} 
```

随后，`validate()` 方法会检查转换后的数据是否存在问题，核实 chat template 结构正确、没有残留的非法 token，并且数据符合你所选模型与训练方法的要求。

```
# Initialize the loader, mapping your column names
loader = JSONLDatasetLoader( 
    question="question", 
    answer="answer",
)

loader.load("training_data.jsonl")

# Preview raw data
loader.show(n=3)

# Transform into Nova's expected chat template format
loader.transform(method=TrainingMethod.SFT_LORA, model=Model.NOVA_LITE_2)

# Preview transformed data to verify the structure
loader.show(n=3)

# Validate — prints "Validation completed" if successful
loader.validate(method=TrainingMethod.SFT_LORA, model=Model.NOVA_LITE_2)

train_path = loader.save(f"{S3_DATA_PATH}/train.jsonl")
print(f"Training data: {train_path}")
```

## **第 4 步：配置并启动带数据混合的训练**

启用数据混合后，Nova Forge 会在微调过程中自动把你的领域数据与 Amazon 精选数据集混合。这样模型在学习你领域知识的同时，不会遗忘通用能力。

### **关于训练方法的说明：LoRA 与全秩 SFT**

Nova Forge 支持多种微调方式。本演练使用**带 LoRA 的监督微调（SFT）**（`TrainingMethod.SFT_LORA`），这是一种参数高效方法，只更新一小部分低秩适配器权重，而非全部模型参数。LoRA 训练更快、算力成本更低，是大多数用例推荐的起点。

Nova Forge 也支持**全秩 SFT**，它会更新全部模型参数，可注入更多领域知识。但它需要更多算力，也更容易出现灾难性遗忘（因此数据混合更为重要）。[本系列上一篇文章](https://aws.amazon.com/blogs/machine-learning/building-specialized-ai-without-sacrificing-intelligence-nova-forge-data-mixing-in-action/)展示了使用全秩 SFT 的结果。当 LoRA 无法达到足够的领域表现，或你需要更深的模型适配时，再选择全秩。

### **配置运行时与 MLflow**

```
from amzn_nova_forge.trainer import ForgeTrainer
from amzn_nova_forge.evaluator import ForgeEvaluator

from amzn_nova_forge.manager import SMHPRuntimeManager
from amzn_nova_forge.model.model_enums import Model, TrainingMethod
from amzn_nova_forge.monitor import MLflowMonitor

cluster_name = "nova-forge-hyperpod"
instance_type = "ml.p5.48xlarge"
instance_count = 4
namespace = "kubeflow"

runtime = SMHPRuntimeManager( 
    instance_type=instance_type, 
    instance_count=instance_count, 
    cluster_name=cluster_name, 
    namespace=namespace,
)

MLFLOW_APP_ID = "<your-mlflow-app-id>" # e.g., "app-XXXXXXXXXXXX"
mlflow_app_arn = f"arn:aws:sagemaker:{REGION}:{ACCOUNT_ID}:mlflow-app/{MLFLOW_APP_ID}"

mlflow_monitor = MLflowMonitor( 
    tracking_uri=mlflow_app_arn, 
    experiment_name="nova-sft-datamix",
)
```

### **创建启用数据混合的 trainer**

在构造 `ForgeTrainer` 时传入 `data_mixing_enabled=True`：

```
config = ForgeConfig(

)
```

### **理解并调优数据混合配置**

数据混合控制训练批次如何构成。`customer_data_percent` 参数决定每个批次中来自你的领域数据的比例。剩余部分由 Nova 精选数据集填充，每个 `nova_*_percent` 参数控制该能力类别**在 Nova 部分内部**的相对权重。

例如，按下面的配置：

- 每个训练批次中有 **50%** 来自你的领域数据
- **50%** 来自 Nova 精选数据，按各自相对权重分布于各能力类别

Nova 侧的百分比之和必须为 100。每个数值代表该类别在批次中 Nova 精选部分的占比。

```
# View the default mixing ratios
trainer.data_mixing.get_config() 
```

你可以按自身优先级覆盖这些比例：

```
trainer.data_mixing.set_config({ 
    "customer_data_percent": 50, 
    "nova_agents_percent": 1, 
    "nova_baseline_percent": 10, 
    "nova_chat_percent": 0.5, 
    "nova_factuality_percent": 0.1, 
    "nova_identity_percent": 1, 
    "nova_long-context_percent": 1, 
    "nova_math_percent": 2, 
    "nova_rai_percent": 1, 
    "nova_instruction-following_percent": 13, 
    "nova_stem_percent": 10.5, 
    "nova_planning_percent": 10, 
    "nova_reasoning-chat_percent": 0.5, 
    "nova_reasoning-code_percent": 0.5, 
    "nova_reasoning-factuality_percent": 0.5, 
    "nova_reasoning-instruction-following_percent": 45, 
    "nova_reasoning-math_percent": 0.5, 
    "nova_reasoning-planning_percent": 0.5, 
    "nova_reasoning-rag_percent": 0.4, 
    "nova_reasoning-rai_percent": 0.5, 
    "nova_reasoning-stem_percent": 0.4, 
    "nova_rag_percent": 1, 
    "nova_translation_percent": 0.1,
})
```

**如何理解并调整混合比例**

| **参数** | **控制内容** | **建议** |
| --- | --- | --- |
| `customer_data_percent` | 每个训练批次中你的领域数据占比。 | 数值越高，领域专精越强，但遗忘风险也越大。50% 是均衡的起点。 |
| `nova_instruction-following_percent` | Nova 部分中指令遵循样本的权重。 | 若你的模型在生产中需要遵循结构化 prompt 或输出格式，请保持较高值。 |
| `nova_reasoning-*_percent` | 各类推理能力（数学、代码、规划等）的权重。 | 若下游任务需要多步推理，请提高这些值。 |
| `nova_rai_percent` | 负责任 AI 对齐数据。 | 始终保持非零，以保留安全行为。 |
| `nova_baseline_percent` | 核心事实性知识。 | 有助于保留广泛的世界知识。 |

**提示：** 从默认值开始，跑一次训练作业，在领域任务和 MMLU 上同时评估，然后迭代。[在不牺牲智能的前提下构建专用 AI](https://aws.amazon.com/blogs/machine-learning/building-specialized-ai-without-sacrificing-intelligence-nova-forge-data-mixing-in-action/) 一文表明，即使采用 75/25 的客户数据与 Nova 数据配比，MMLU 仍保持在接近基线的水平（0.74 对基线 0.75），同时在复杂分类任务上取得 12 个百分点的 F1 提升。

### **启动训练作业**

overrides 参数让你控制关键训练超参数：

| **参数** | **说明** | **建议** |
| --- | --- | --- |
| `lr` | 学习率 | 1e-5 是 LoRA 微调的合理默认值。 |
| `warmup_steps` | 学习率从 0 线性爬升的步数 | 通常为总步数的 5–10%，按 `max_steps` 等比设置。 |
| `global_batch_size` | 所有 GPU 上每次梯度更新的样本数 | 批次越大梯度越稳定，但占用更多内存。 |
| `max_length` | 以 token 计的最大序列长度 | 依据你的数据设置。65536 支持长上下文用例；数据较短时可调小以省内存并加快训练。 |
| `max_steps` | 训练总步数 | 先用小值（5–10）验证环境，再调大。约 23k 条训练样本、batch size 为 32 时，一个完整 epoch ≈ 720 步。 |

```
training_config = { 
    "lr": 1e-5, 
    "warmup_steps": 2, 
    "global_batch_size": 32, 
    "max_length": 65536, 
    "max_steps": 5, # Start small to validate; increase for production runs
}

training_result = trainer.train( 
    job_name="nova-forge-sft-datamix", 
    overrides=training_config,
)

training_result.dump("training_result.json") 
print("Training result saved")
```

## **第 5 步：评估微调后的模型**

使用数据混合时评估至关重要，因为你需要同时衡量两件事：模型在你的领域任务上是否有所提升，以及它是否保住了通用能力。如果只测一个维度，你就无法判断混合是否奏效。训练完成后，从输出 manifest 中取出模型 checkpoint 的位置：

```
from amzn_nova_forge.util.checkpoint_util import extract_checkpoint_path_from_job_output

checkpoint_path = extract_checkpoint_path_from_job_output( 
    output_s3_path=training_result.model_artifacts.output_s3_path, 
    job_result=training_result,
)
```

### **配置评估基础设施**

评估只需要单台 GPU 实例（训练用了 4 台）：

```
eval_infra = SMHPRuntimeManager( 
    instance_type=instance_type, 
    instance_count=1, 
    cluster_name=cluster_name, 
    namespace=namespace,
)

eval_mlflow = MLflowMonitor( 
    tracking_uri=mlflow_app_arn, 
    experiment_name="nova-forge-eval",
)

eval_config = ForgeConfig(
    output_s3_path=f"s3://{S3_BUCKET}/demo/eval-outputs/",
    mlflow_monitor=eval_mlflow,
)
evaluator = ForgeEvaluator(
    model=Model.NOVA_LITE_2,
    infra=eval_infra,
    config=eval_config,
)
```

### **运行评估**

Nova Forge 支持三种互补的评估方式：

**1. 公开基准测试**（用于衡量通用能力的保留程度）

这些基准告诉你数据混合是否在起作用。若 MMLU 相比基线明显下降，说明混合需要更多 Nova 数据；若 IFEval 下降，则提高指令遵循的权重。

```
# MMLU — broad knowledge and reasoning across 57 subjects
mmlu_result = evaluator.evaluate( 
    job_name="eval-mmlu", 
    eval_task=EvaluationTask.MMLU, 
    model_path=checkpoint_path,
)

# IFEval — ability to follow structured instructions
ifeval_result = evaluator.evaluate( 
    job_name="eval-ifeval", 
    eval_task=EvaluationTask.IFEVAL, 
    model_path=checkpoint_path,
)
```

**2. 自带数据**（衡量领域特定表现）

用你留出的测试集衡量微调是否提升了真实任务上的表现：

```
byod_result = evaluator.evaluate( 
    job_name="eval-byod", 
    eval_task=EvaluationTask.GEN_QA, 
    data_s3_path=f"s3://{S3_DATA_PATH}/eval/gen_qa.jsonl", 
    model_path=checkpoint_path, 
    overrides={"max_new_tokens": 2048},
)
```

**3. 以大语言模型（LLM）作为评判**（在自动化指标力有不逮的领域，你可以用另一个 LLM 评估回复质量）

## **最佳实践**

- **从默认混合比例开始。** 默认值已针对均衡的取舍做过调优。在拿到可对比的基线评估结果后，再自定义。
- **始终在两个维度上评估。** 至少运行一项公开基准（MMLU）并搭配你的领域特定评估。缺少任一维度，你都无法判断混合是否有效。
- **用 MLflow 比较实验。** 迭代混合比例与超参数时，MLflow 让并排比较多次运行、找出最佳配置变得直接。
- **迭代混合比例，而不只是超参数。** 如果模型正在遗忘通用能力，调整数据混合往往比调学习率或 batch size 更有效。
- **先用 LoRA，必要时再转全秩。** LoRA 更快也更便宜。只有当 LoRA 无法为你的用例带来足够的领域适配时，才转向全秩 SFT。
