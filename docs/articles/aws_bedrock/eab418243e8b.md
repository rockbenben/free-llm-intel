# Swisscom 如何借助 Amazon Bedrock AgentCore 为客户支持与销售构建企业级 agentic AI

*本文与来自 Swisscom 的 Arun Sittampalam 和 Maxime Darcot 共同撰写。*

在持续变化的 AI 生态中前行时，企业面临着把 AI 的潜力转化为可扩展、生产就绪解决方案的挑战。[Swisscom](https://www.swisscom.ch/en/about.html?srsltid=AfmBOorpX6-hpVq8kUI4QrFxMkPwJid2KCbgpGAnuESZ-QG4OrToalWl) 是瑞士领先的电信运营商，2025 年营收估计为 $19B，截至 2025 年 6 月市值超过 $37B，它正是组织如何成功应对这种复杂性、同时坚守对可持续发展与卓越的承诺的典范。

Swisscom 连续 3 年被《World Finance》杂志评为电信行业最具可持续发展力的公司，已确立其创新领导者的地位，并承诺与《巴黎气候协定》保持一致，到 2035 年实现温室气体净零排放。这种可持续发展优先的做法也延伸到他们的 AI 战略：他们正在突破所谓的“自动化天花板”——即传统自动化方法无法满足现代业务需求的瓶颈。

本文将展示 Swisscom 如何实施 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/)，为客户支持与销售运营构建并扩展其企业 AI agent。作为 AWS 欧洲区域（苏黎世）中 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的早期采用者，Swisscom 凭借其 Chatbot Builder 系统和多项 AI 计划在企业 AI 实施方面处于领先地位。其成功部署包括由 Rasa 驱动的 Conversational AI、在 [Amazon SageMaker](https://aws.amazon.com/sagemaker) 上微调的 LLM，以及为满足瑞士数据保护标准而构建的 Swisscom [Swisscom myAI ](http://myai.swisscom.ch/)助手。

## 解决方案概览：Swisscom 的 agentic AI 赋能框架

企业范围内扩展 AI agent 的挑战在于：既要管理彼此孤立的 agentic 解决方案，又要促进跨部门协作。Swisscom 通过 [Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro) 服务器和 [Agent2Agent protocol (A2A)](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/) 来应对，实现跨域的无缝 agent 通信。在瑞士严格的数据保护法下运营，他们开发了一套框架，在合规要求与高效扩展能力之间取得平衡，帮助避免重复工作，同时保持高安全标准。

### Swisscom 的多 agent 架构：系统设计与实施挑战

Swisscom 对企业级 agentic AI 的愿景聚焦解决组织在扩展 AI 解决方案时面临的根本挑战。他们认识到，成功实施不仅需要创新技术，还需要对基础设施和运营采取全面的方法。关键挑战之一在于跨不同部门和系统编排 AI agent，同时保持安全与效率。

为了在实践中说明这些挑战，我们来看一个常见的客户服务场景：一个 agent 负责帮助客户恢复其 Internet 路由器的连接。连接中断有三种可能原因：1) 计费问题，2) 网络中断，或 3) 称为配对问题的配置不匹配。这些问题通常位于与所分配 agent 所在部门不同的部门，凸显了无缝跨部门协作的必要性。

下面的架构图展示了一个未使用 Amazon Bedrock AgentCore 的通用客户 agent 的愿景及相关挑战。Swisscom 的共享 VPC 设置在博文 [Swisscom 中基于共享 VPC 的自动化网络](https://aws.amazon.com/blogs/industries/automated-networking-with-shared-vpcs-at-swisscom/) 中有更详细的说明。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/12/AgentCoreSwisscom-VisionWithoutAgentCore.drawio.png)

该架构包含以下组件：

- 一个面客的通用 agent，作为容器化运行时部署在共享 VPC 内，既需要基础模型调用能力，也需要健壮的会话管理。
- 为完成任务，该 agent 需要访问其他 agent 和 MCP 服务器。这些资源通常分布在多个 AWS 账户中，并作为容器化运行时部署在共享 VPC 内。
- 内部应用访问主要通过 SAIL（Service and Interface Library）进行，这是 Swisscom 用于 API 托管和服务集成的中央系统。企业网络资源可通过 [AWS Direct Connect](https://aws.amazon.com/directconnect/) 访问，VPC Transit Gateway 负责促进安全的跨网络通信。
- 安全合规至关重要：每次交互都需要临时访问 token，对 agent 和客户上下文进行身份验证。这种双向验证对系统组件至关重要——agent、MCP 服务器和工具必须验证服务请求传入的 token。
- 从存储的会话中获取长期洞察（例如客户偏好）需要复杂的分析。

为了大规模构建上述解决方案，Swisscom 识别出若干需要解决的关键挑战：

- **安全与身份验证：**  如何实现安全的传递式身份验证和授权，基于交叉权限（客户、agent、部门）强制执行最小权限访问？如何实现跨部门、跨云系统和本地网络的受控资源共享？
- **集成与互操作性：**  如何让 MCP 服务器和其他 agent 集中可供其他用例使用？如何集成并保持与 Swisscom 基础设施中现有 agentic 用例的兼容性？
- **客户智能与运营：**  如何在多次 agentic 交互中有效地捕获和利用客户洞察？如何跨 agent 实施标准化的评估与可观测性实践？

### Amazon Bedrock AgentCore 如何应对这些挑战

Amazon Bedrock AgentCore 为 Swisscom 提供了全面的解决方案，应对其企业级 agentic AI 挑战。

- **AgentCore Runtime：** 让 Swisscom 的开发者专注于构建 agent，而系统通过保持会话级隔离的 Docker 容器部署来处理安全、成本高效的托管和自动扩缩容。托管在共享 VPC 中使其可以访问内部 API。
- **AgentCore Identity：** 与 Swisscom 现有的身份提供商无缝集成，管理入站和出站身份验证，免去自建 token 交换服务器的需要，并简化 agent、工具和数据源之间的安全交互。
- **AgentCore Memory：** 提供健壮的解决方案，通过自定义记忆策略同时管理基于会话的记忆和长期记忆存储。这对 B2C 运营尤其有价值，因为跨交互理解客户上下文至关重要。将每个用户的数据隔离存放也有助于安全和合规工作。
- **Strands Agents Framework：** 由于 agent 构建简化、开发周期更快、与 Bedrock AgentCore 服务无缝集成，以及内置的追踪、评估和 OpenTelemetry 日志记录能力，它在 Swisscom 的开发者中被广泛采用。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/12/AgentCoreSwisscom-Page-4.drawio-1024x851.png)

该解决方案执行以下工作：

- 客户端向运行在 AgentCore Runtime 上的 Strands agent 发送请求，并传入来自 Swisscom IdP 的身份验证 token。
- 客户端的 token 被验证，随后为 agent 的下游工具使用生成新 token，并回传给该 agent。
- agent 调用 Bedrock 上的基础模型，并把会话存储在 AgentCore Memory 中。流量经由 Bedrock 和 Bedrock AgentCore 的 VPC 终端节点传输，保持流量私有。
- agent 访问共享 VPC 内的内部 API、MCP 与 A2A 服务器，并使用来自 AgentCore Identity 的临时 token 进行身份验证。

凭借可以只使用 Amazon Bedrock AgentCore 部分特性以及其 Amazon VPC 集成的灵活性，Swisscom 得以在保持安全的同时灵活地按自身具体需求使用 Bedrock AgentCore 服务，例如与 Amazon EKS 上现有的 agent 集成。Amazon Bedrock AgentCore 与 VPC 集成，以促进 agent 与内部资源之间的安全通信。

## 结果与收益：自助服务用例的真实实施

Swisscom 与 AWS 合作，为两个 B2C 用例实施 Amazon Bedrock AgentCore：1) 生成个性化销售话术，2) 为自助排障等技术问题提供自动化客户支持。两个 agent 都正在集成到 Swisscom 现有的、名为 SAM 的客户生成式 AI 聊天机器人系统中；由于 Swisscom 客户量大且延迟要求严格，这要求高性能的 agent 间通信协议。在整个开发过程中，团队为每个用例各创建一个 agent，并设计为通过 MCP 和 A2A 在整个组织内共享。

Amazon Bedrock AgentCore 在这些实施中发挥了关键作用。借助 Bedrock AgentCore Memory 的长期洞察，Swisscom 可以追踪和分析跨不同触点的客户交互，持续改善跨域客户体验。AgentCore Identity 提供健壮的安全性，实施精确的访问控制，使 agent 只能访问为特定客户交互授权的资源。AgentCore Runtime 的可扩展性让这些 agent 各自每月高效处理数千个请求，在优化成本的同时保持低延迟。

Strands Agents 框架的采用在这段旅程中尤其有价值：

- 开发团队在 3-4 周内就完成了面向业务方的首次演示，尽管此前没有任何 Strands Agents 经验。
- 一个项目团队从他们的 LangGraph 实现迁移到 Strands Agents，理由是复杂度降低、开发周期更快。
- 该框架原生的 OpenTelemetry 集成支持把性能 trace 无缝导出到 Swisscom 现有的可观测性基础设施，与企业范围的监控标准保持一致。
- [Strands evaluation ](https://strandsagents.com/latest/documentation/docs/user-guide/observability-evaluation/evaluation/)测试用例让团队无需额外工具就能快速搭建评估流水线，以便快速验证 PoC。

## 结论：规模化企业 AI——关键洞察与战略影响

Swisscom 对 Amazon Bedrock AgentCore 的实施展示了企业如何成功应对生产就绪 Agentic AI 的复杂性，同时保持法规合规和运营卓越。Swisscom 的旅程提供了 3 项关键洞察：

- **架构基础至关重要**：通过解决安全跨组织身份验证、标准化 agent 编排和全面可观测性等根本挑战，Swisscom 建立了一个可扩展的基础，它加速而非限制了部署。AgentCore Runtime、Identity 和 Memory 服务的集成加速了基础设施搭建，使团队可以专注业务价值。
- **框架选择决定速度**：Strands Agents 框架的采用说明了合适的开发工具如何大幅缩短价值实现时间。团队在 3-4 周内完成面向相关方的演示，加上从其他框架成功迁移，验证了开发者体验在企业 AI 采用中的重要性。
- **合规可以成为赋能因素**：Swisscom 证明法规合规不一定阻碍创新。该系统在扩展的同时保持数据主权和用户隐私的能力，在法规合规至上的瑞士行业尤其有价值。

随着企业日益认识到 AI agent 是竞争优势的根本，Swisscom 的实施提供了一个经过验证的参考架构。他们在大流量 B2C 应用上的成功——从个性化销售协助到自动化技术支持——表明在合适的基础设施之上构建 agentic AI 可以在规模化时带来可衡量的业务成果。该实施为寻求部署企业级 AI 解决方案的组织提供了蓝图，展示了周密的架构规划与正确的技术选择如何在客户服务和销售运营两方面带来成功结果。

**后续步骤与未来展望**

未来路线图聚焦三个关键领域：agent 共享、跨域集成和治理。集中式 agent 注册表将促进整个组织内的发现与复用，并由标准化文档和共享最佳实践提供支撑。跨域集成将实现不同业务单元之间的无缝协作，并为 agent 通信与互操作性制定清晰标准。实施健壮的治理机制，包括版本控制、使用监控和定期安全审计，将促进系统的可持续增长，同时保持符合企业标准。这种全面的方法将帮助基于真实使用模式和反馈推动持续改进。
