# 用 AWS 为帮助难民构建可扩展的 AI 助手

*本文与 Taras Tsarenko、Vitalii Bozadzhy 和 Vladyslav Horbatenko 共同撰写。*

随着世界各地的组织寻求用 AI 推动社会影响，丹麦人道主义组织 [Bevar Ukraine](http://www.bevarukraine.dk/) 开发了一个名为 Victor 的综合性虚拟生成式 AI 助手，旨在解决融入丹麦社会的乌克兰难民最迫切的需求。本文详述我们如何使用 AWS 服务完成技术实现，构建一个可扩展的多语言 AI 助手系统，在提供自动化协助的同时保持数据安全与 GDPR 合规。

Bevar Ukraine 成立于 2014 年，自 2022 年全面战争爆发以来，一直站在支持丹麦境内乌克兰难民的前线，为超过 3 万名乌克兰人提供住房、求职和融入服务方面的帮助。该组织还向乌克兰运送了 200 多吨人道主义援助物资，包括医疗用品、发电机以及受战争影响的平民所需的基本物品。

## 背景与挑战

难民融入收容国面临多重挑战，尤其是在获取公共服务和应对复杂法律程序方面。严重依赖人类社会工作者的传统支持体系，往往受制于可扩展性限制和语言障碍。Bevar Ukraine 的解决方案通过一个持续运行、同时保持高标准服务质量的 AI 系统来应对这些挑战。

## 方案概览

该方案的骨干由多项 AWS 服务构成，为乌克兰难民交付可靠、安全且高效的[生成式 AI](https://aws.amazon.com/generative-ai/) 数字助手。由三名志愿软件开发者组成的团队在数周内完成了该方案。

下图展示了方案架构。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/15/photo_2025-05-14_14-28-29-AG-250515-1.jpg)

[Amazon Elastic Compute Cloud](https://aws.amazon.com/ec2)（Amazon EC2）作为主要计算层，使用 Spot 实例来优化成本。[Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）为对话日志和支持文档提供安全存储，[Amazon Bedrock](https://aws.amazon.com/bedrock/?gclid=Cj0KCQjwkN--BhDkARIsAD_mnIoJd-28iB6ej8XivuwS1tYLJQYb60i4X0Etzu1OLfe7PJulhHIpSvYaAgL2EALw_wcB&trk=819d8502-4d8d-4965-8778-2d59f833c43d&sc_channel=ps&ef_id=Cj0KCQjwkN--BhDkARIsAD_mnIoJd-28iB6ej8XivuwS1tYLJQYb60i4X0Etzu1OLfe7PJulhHIpSvYaAgL2EALw_wcB:G:s&s_kwcid=AL!4422!3!691967591736!e!!g!!amazon%20bedrock!21048268986!164977106811) 则驱动核心的自然语言处理能力。Bevar Ukraine 使用 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 实现实时数据访问和会话管理，即使在高负载下也能提供低延迟响应。

在实施过程中，我们发现 Anthropic 的 Claude 3.5 大语言模型（LLM）最为合适，因为它具备先进的对话逻辑和维持拟人语气的能力。它最适合给出周全、有理有据的回答，以及生成更具创意的内容，这让 Victor 的回复更自然、更吸引人。

Amazon Titan Embeddings G1 – Text v1.2 擅长为多语言文本生成高质量的向量表示，从而实现高效的语义搜索与相似度比较。当 Victor 需要从庞大的知识库中检索相关信息，或把用户查询与以往见过的输入匹配时，这一点尤为宝贵。Amazon Titan Embeddings 还能与 AWS 顺畅集成，简化索引、搜索和检索等任务。

在与 Victor 的真实交互中，有些查询需要简短、具体的回答，另一些则需要创意生成或上下文理解。通过把用于生成的 Anthropic 的 Claude 3.5 与用于语义检索的 Amazon Titan Embeddings G1 结合起来，Victor 能让每个查询走最合适的流水线：通过嵌入检索相关上下文并生成回答，从而得到更准确、更具上下文感知的回答。

Amazon Bedrock 提供了出色的接口，可用于调用 Anthropic 的 Claude 3.5 和 Amazon Titan Embeddings G1（以及其他模型），无需为每个提供商单独构建集成，从而简化了开发与维护。

为支持多语言，我们使用了支持多语言嵌入的嵌入器，并用 [Amazon Translate](https://aws.amazon.com/translate/) 翻译我们的材料。这增强了我们检索增强生成（RAG）系统的韧性。该应用以安全的方式构建，并使用 AWS 服务来实现这一点。[AWS Key Management Service](https://aws.amazon.com/kms)（AWS KMS）简化了应用内数据加密的过程，[Amazon API Gateway](https://aws.amazon.com/api-gateway/) 支持应用的 REST 端点。用户身份验证与授权能力由 [Amazon Cognito](https://aws.amazon.com/cognito/) 提供，它提供安全且可扩展的客户身份与访问管理（CIAM）能力。

该应用运行在 AWS 基础设施上，所用服务在设计上兼顾安全与可扩展，例如 Amazon S3、[AWS Lambda](https://aws.amazon.com/lambda) 和 DynamoDB。

## 提示与建议

使用 Amazon Bedrock 及其他 AWS 服务为难民构建 AI 助手方案，为我们打造有影响力、由 AI 驱动的人道主义方案提供了宝贵洞见。通过这次实现，我们发现了组织在开发类似方案时应牢记的关键考量。这段经历凸显了在技术能力与以人为本的设计之间取得平衡、提供多语言支持、维护数据隐私，以及打造可扩展又高性价比方案的重要性。这些经验可以作为希望用 AI 和云技术支持人道主义事业的组织的基础，尤其是在为流离失所的人群创建可访问且有帮助的数字协助方面。以下是最主要的几点：

- 使用 Amazon Bedrock playground，用同一个 prompt 并排测试多个 LLM。这有助于你找到在质量、风格和语气上最适合具体用例的模型（例如事实准确性还是对话语气）。
- 试验 prompt 和设置以改进回答。
- 把成本放在心上；在 AWS 中设置监控和预算。
- 对于涉及信息检索或语义搜索的任务，选择嵌入模型时要确保挑对相应设置。注意嵌入的维度大小，因为更大的向量能承载更多含义，但可能增加成本。同时确认该模型支持你的应用所需的语言。
- 如果你使用知识库，请用 Amazon Bedrock knowledge base playground 试验内容如何分块，以及每次查询检索多少段落。找到合适的检索段落数会显著影响最终回答的清晰度与聚焦度——有时少量高质量的分块比塞入过多上下文效果更好。
- 为强化安全与隐私，请使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/)。Guardrails 有助于防止模型泄露敏感信息，例如个人数据或内部业务内容，你还可以拦截有害回答，或强制特定的语气与格式风格。
- 从简单的原型开始，在你所在领域测试嵌入质量，然后迭代扩展。

## 集成与增强层

Bevar Ukraine 用若干互补技术扩展了核心 AWS 基础设施：

- [Pinecone](https://www.pinecone.io/) 向量数据库 —— 用于高效存储和检索语义嵌入
- [DSPy 框架](http://dspy.ai) —— 用于结构化 prompt 工程，以及优化 Anthropic 的 Claude 3.5 Sonnet 的回答
- [EasyWeek](https://easyweek.io/) —— 用于预约排期和资源管理
- [Telegram API](https://core.telegram.org/) —— 用于交付 UI
- [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) —— 用于安全策略执行
- [Amazon Rekognition](https://aws.amazon.com/rekognition/) —— 用于文档验证
- 基于 GitHub 的持续集成与持续交付（CI/CD）流水线 —— 用于快速部署功能

## 关键技术洞见

这次实现揭示了若干关键的技术考量。DSPy 框架在优化和增强我们的语言模型 prompt 方面至关重要。通过集成额外的推理层和上下文感知工具，DSPy 显著提升了回答的准确性、一致性和深度。团队发现，设计一个元数据完备的健壮知识库对系统的有效性至关重要。

GDPR 合规需要审慎的架构决策，包括数据最小化、安全存储和清晰的用户同意机制。成本优化通过策略性使用 EC2 Spot 实例和实施 API 请求限流来实现，在未牺牲性能的前提下带来了可观的运营节省。

## 未来增强

我们的路线图包括若干技术改进，以增强系统能力：

- 使用机器学习算法实现先进的上下文分发，以改善跨多个领域的服务协同
- 为需要专家监督的复杂场景开发精细的人在环（human-in-the-loop）验证系统
- 把合适的组件迁移到基于 Lambda 的无服务器架构，以优化资源利用和成本
- 用先进的语义搜索能力和自动化内容更新来增强知识库

## 成果

该方案每天为丹麦数百名乌克兰难民提供服务，展示了 AWS 服务在为创造社会影响而构建可扩展、安全且高效的 AI 系统方面的潜力。由此，Bevar Ukraine 的志愿者和员工节省了数千小时，他们不必再回答难民的重复性问题，而可以支持他们应对更复杂的生活处境。对难民而言，虚拟助手 Victor 是一份救生支持，让用户能在数秒内得到关于丹麦公共服务最迫切问题的回答，以及许多其他问题的答案，而不必等待有空闲的志愿者来帮忙。考虑到 Victor 用于生成回答的庞大知识库，支持质量也得到了提升。

## 结论

通过细致的架构设计和互补技术的集成，我们打造了一个平台，在维持高标准安全与数据保护的同时，有效应对难民所面临的挑战。

这一实现的成功为其他社会服务领域的类似方案提供了蓝图，有可能帮助世界各地的难民和其他需要帮助的人，也凸显了把健壮的云基础设施与周到的系统设计结合起来以创造有意义的社会影响的重要性。
