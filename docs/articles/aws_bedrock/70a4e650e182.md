# 在 Amazon Bedrock 上推出 Kimi K3.1 Pro

[Moonshot AI](https://www.kimi.ai/blog/kimi-k3-1-pro) 的 Kimi K3.1 Pro Highspeed 现已在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上提供。作为 Moonshot AI 新 K3.1 系列的一部分，它是 Kimi K3 的后训练版本，具有相同的 3T 级开放权重架构和 100 万个令牌上下文窗口，并使用更多的后训练计算进行训练。据 Moonshot AI 称，额外的训练目标是长期代理工作和减少事实错误。它还改进了专业任务，例如财务建模和办公文档，以及游戏引擎、3D 场景和计算机辅助设计 (CAD) 脚本的编码。 Kimi K3.1 Pro Highspeed 以更高的速率生成输出令牌，Moonshot AI 报告的速度是 Kimi K3.1 Pro 的 2-3 倍。

Kimi K3.1 Pro Highspeed 使用与 Amazon Bedrock 上的 Kimi K3 相同的终端节点、API 和功能。如果您已经使用 Kimi K3 进行构建，则可以通过更改现有代码中的模型 ID 来尝试。

Kimi K3.1 Pro Highspeed支持工具调用、结构化输出、可配置推理、图像输入和流媒体。您可以采用 Kimi K3.1 Pro Highspeed，而无需改变您的安全状况。您的数据在 AWS 数据边界内进行处理，不会与 Moonshot AI 共享，也不用于训练模型。推理请求始终启用零数据保留，并且通过零操作员访问，AWS 操作员无法在推理期间查看您的提示和完成情况。

在这篇文章中，我们向您展示如何开始在 Amazon Bedrock 上使用 Kimi K3.1 Pro Highspeed。我们还介绍了如何使用 Flex 层降低成本、重复上下文的显式提示缓存，以及如何使用该模型作为 OpenCode 中的编码助手。

## 在 Amazon Bedrock 上开始使用 Kimi K3.1 Pro Highspeed

要在不编写代码的情况下尝试该模型，请打开 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock/)，选择 **Test**，然后选择 **Playground**，然后选择 **Kimi K3.1**。

从代码来看，Kimi K3.1 Pro Highspeed 可通过 OpenAI 兼容的 [Chat Completions](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-completions.html) 和 [Responses](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html) API 在“bedrock-runtime”端点上使用，并通过Amazon Bedrock [Converse](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html) 和 [Invoke](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-invoke.html) API。我们推荐使用聊天完成 API。您可以通过跨区域推理配置文件到达模型：

- `global.moonshotai.kimi-k3.1` 将请求路由到任何受支持的商业 AWS 区域，并且每个令牌的成本低于地理配置文件。我们建议对大多数工作负载使用它。
- 对于具有数据驻留要求的工作负载，“us.moonshotai.kimi-k3.1”继续在美国区域内进行处理，而“in.moonshotai.kimi-k3.1”则将其保留在印度区域内。

### 先决条件

要遵循示例，您需要：

- 有权访问 Amazon Bedrock 的 AWS 账户。
- Python 3.11 或更高版本，安装了 [OpenAI SDK](https://pypi.org/project/openai/)、[aws-bedrock-token-generator](https://pypi.org/project/aws-bedrock-token-generator/) 和 [boto3](https://pypi.org/project/boto3/) (`pip install -U openai aws-bedrock-token-generator博托3`）。
- 允许在 Kimi K3.1 Pro 高速推理配置文件上调用“bedrock:InvokeModel”和“bedrock:InvokeModelWithResponseStream”的 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 身份。如果您使用不记名令牌进行身份验证，请添加“bedrock:CallWithBearerToken”。

### 使用聊天完成 API 调用 Kimi K3.1 Pro Highspeed

如果您的应用程序已使用 OpenAI SDK，请将其指向 Amazon Bedrock 终端节点并更改模型名称。以下示例根据您的 AWS 凭证创建一个短期不记名令牌并发送一个请求：
```
from openai import OpenAI
from aws_bedrock_token_generator import provide_token

REGION = "us-west-2"
MODEL_ID = "global.moonshotai.kimi-k3.1"

# A short-term token derived from your AWS credentials, so no long-lived key is stored in code
client = OpenAI(
    base_url=f"https://bedrock-runtime.{REGION}.amazonaws.com/openai/v1",
    api_key=provide_token(region=REGION),
)

completion = client.chat.completions.create(
    model=MODEL_ID,
    messages=[
        {"role": "system", "content": "You are a concise senior engineer."},
        {"role": "user", "content": "When should I prefer a queue over a stream?"},
    ],
    reasoning_effort="high",
)
print(completion.choices[0].message.content)
```
Kimi K3.1 Pro Highspeed 总是先推理再回答。通过“reasoning_effort”，您可以控制多少：“low”、“high”或“max”。如果不设置它，模型将使用“max”，因此较低的值是减少较简单任务的延迟和输出令牌的最直接方法。

### 使用响应 API 调用 Kimi K3.1 Pro Highspeed

同一个客户端使用 Responses API，它使用 `reasoning.effort` 进行相同的设置：
```
response = client.responses.create(
    model=MODEL_ID,
    input="Summarize the trade-offs between optimistic and pessimistic locking.",
    reasoning={"effort": "low"},
)
print(response.output_text)
```
### 使用 Converse API 调用 Kimi K3.1 Pro Highspeed

如果您已使用 Amazon Bedrock Converse API，则更改为模型 ID：
```
import boto3

bedrock = boto3.client("bedrock-runtime", region_name="us-west-2")
response = bedrock.converse(
    modelId="global.moonshotai.kimi-k3.1",
    messages=[{"role": "user", "content": [{"text": "Explain idempotency keys in two sentences."}]}],
)

# The model can return a reasoning block before the answer, so pick the text block
content = response["output"]["message"]["content"]
print(next(block["text"] for block in content if "text" in block))
```
## 使用 Flex 层降低成本

[Flex 层](https://docs.aws.amazon.com/bedrock/latest/userguide/service-tiers-inference.html) 以标准价格的一半为 Kimi K3.1 Pro Highspeed 提供服务，以换取可能更长的响应时间。它非常适合成本效率比响应时间更重要的工作负载，例如模型评估、内容摘要和代理工作流程中的后台任务。由于您为每个请求选择层，因此一个应用程序可以混合层。例如，同一应用程序可以使用 Priority 处理延迟关键型请求，使用 Standard 处理日常流量，使用 Flex 处理成本敏感的工作。您的按需配额在标准层、优先层和弹性层之间共享。

要使用 Flex，请将“service_tier”设置为“flex”。以下示例重用了之前的聊天完成客户端：
```
completion = client.chat.completions.create(
    model=MODEL_ID,
    messages=[{"role": "user", "content": "List edge cases to test in a function that parses ISO 8601 dates."}],
    service_tier="flex",
)
print(completion.choices[0].message.content)
print(completion.service_tier)  # The tier that served the request
```
在 Converse API 上，将 `serviceTier` 设置为 `{"type": "flex"}`。要查看每个层提供的流量量，请使用 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 中的“ServiceTier”和“ResolvedServiceTier”维度。我们建议您从 Flex 上的一小部分流量开始，比较延迟和成本，然后再移动更多流量。

## 通过显式提示缓存优化推理

代理和编码助手每次都会重新发送相同的大前缀：系统指令、工具定义、存储库约定和参考文档。 Kimi K3.1 Pro Highspeed会自动缓存重复的前缀，并且通过显式提示缓存，您可以标记稳定前缀的结束位置，以提高缓存命中率。稍后的请求会重用该前缀，而不是再次处理它，这会降低长时间重复上下文的延迟和输入成本。

一些规则适用：

- 显式缓存适用于聊天完成、响应和调用 API，但不适用于 Converse。
- `prompt_cache_breakpoint` 必须遵循至少 256 个稳定内容标记。
- 缓存内容至少保留 30 分钟。
- 缓存写入的计费费率高于标准输入的费率。缓存读取按折扣费率计费，并且不计入您的每分钟输入令牌配额。

以下示例缓存较长的系统提示并在用户内容后添加第二个断点，因此同一文档的后续问题可以重用这两个层：
```
from pathlib import Path

LONG_STATIC_PROMPT = Path("repo_guidelines.md").read_text()  # stable content, at least 256 tokens
QUESTION = "Which of these guidelines apply to database migrations?"

def cached_text(text):
    # Marks the end of a cacheable prefix
    return {"type": "input_text", "text": text, "prompt_cache_breakpoint": {"mode": "explicit"}}

response = client.responses.create(
    model=MODEL_ID,
    extra_body={"prompt_cache_options": {"mode": "explicit"}},
    input=[
        {"type": "message", "role": "system", "content": [cached_text(LONG_STATIC_PROMPT)]},
        {"type": "message", "role": "user", "content": [cached_text(QUESTION)]},
    ],
)
details = response.usage.input_tokens_details
print(f"Cache read: {details.cached_tokens} tokens")  # greater than 0 on a cache hit
```
有关更多信息，请参阅[提示缓存以加快模型推理速度](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)。

## Kimi K3.1 Pro Highspeed 实践：使用 OpenCode 进行编码

[OpenCode](https://opencode.ai/) 是一个在您的终端中运行的开源、与模型无关的编码代理。您可以使用 OpenCode 的 [OpenAI 兼容提供商](https://opencode.ai/docs/providers/) 和 [Amazon Bedrock API 密钥](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html)，通过 Amazon Bedrock Chat Completions API 将其连接到 Kimi K3.1 Pro Highspeed。要创建密钥，请在“baseURL”中设置的 AWS 区域中打开 Amazon Bedrock 控制台，然后选择 **API 密钥**。短期密钥可持续长达 12 小时，仅在您生成它们的区域中有效，建议用于生产用途。长期密钥用于探索。

将以下内容添加到 `~/.config/opencode/opencode.json` 中，将 `baseURL` 中的区域替换为您自己的区域：
```
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "amazon-bedrock-chat-completions": {
      "name": "Amazon Bedrock (Chat Completions)",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://bedrock-runtime.us-west-2.amazonaws.com/openai/v1"
      },
      "models": {
        "global.moonshotai.kimi-k3.1": {
          "name": "Kimi K3.1 Pro Highspeed",
          "capabilities": {
            "reasoning": { "supported": true, "effort": ["low", "high", "max"] }
          }
        }
      }
    }
  },
  "model": "amazon-bedrock-chat-completions/global.moonshotai.kimi-k3.1"
}
```
在项目目录中启动 OpenCode，输入 `/connect`，选择 **Amazon Bedrock (Chat Completions)**，然后粘贴您的 API 密钥，如图 1 所示。OpenCode 存储密钥，因此每个密钥连接一次。要在会话期间在 Kimi K3.1 Pro Highspeed 和其他型号之间切换，请输入“/models”。

输出速度在代理编码中最重要。为了完成一项任务，编码代理会连续进行多次模型调用。它读取文件、计划更改、编辑代码、运行测试并修复失败的问题。每个调用都必须在下一个调用开始之前完成，并且大部分时间都花在生成推理和代码上。较高的输出令牌率会缩短每个步骤，因此整个编辑-测试-修复循环会更快完成，并且迭代之间的等待时间也会更少。

## 可用性

Kimi K3.1 Pro Highspeed 可通过“global.moonshotai.kimi-k3.1”、“us.moonshotai.kimi-k3.1”和“in.moonshotai.kimi-k3.1”跨区域推理配置文件在 Amazon Bedrock 上使用。有关支持的区域和型号详细信息，请参阅[Kimi K3.1 Pro Highspeed 型号卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3-1-highspeed.html) 和[区域可用性](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html)。有关定价，请参阅 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。

要开始使用，请在 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock/) 上尝试 Kimi K3.1 Pro Highspeed。要与 Amazon Bedrock 团队讨论您的使用案例，请[与我们联系](https://pages.awscloud.com/Amazon-Bedrock-Contact-Us.html)。
