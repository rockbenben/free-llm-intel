# 用 MCP 把 AWS Quick 连接到企业应用与 agent

组织需要这样的解决方案：让人和 AI agent 通过单一界面安全地协作访问组织数据，并能跨企业应用执行操作，从而提升生产力。AI agent 能否安全、无缝地连接组织知识库、企业应用和其他 AI agent，是推动 AI 解决方案落地使用的基础。[Model Context Protocol (MCP)](https://modelcontextprotocol.io/about) 为这类连接提供了更安全、更标准化且更简单的机制，免去了构建复杂自定义集成的需要。

在本篇博客中，你将了解如何使用 [AWS Quick MCP Actions 集成](https://docs.aws.amazon.com/quicksuite/latest/userguide/mcp-integration.html) 连接到托管式 MCP 服务端，以接入 [Asana](https://developers.asana.com/docs/using-asanas-model-control-protocol-mcp-server)、[Atlassian 的 Jira 和 Confluence](https://www.atlassian.com/platform/remote-mcp-server)、[Box](https://developer.box.com/guides/box-mcp/)、[Canva](https://www.canva.com/help/mcp-agent-setup/)、[HubSpot](https://developers.hubspot.com/mcp)、[HuggingFace](https://huggingface.co/docs/hub/en/hf-mcp-server)、[Intercom](https://www.intercom.com/blog/introducing-model-context-protocol-fin)、[Linear](https://linear.app/docs/mcp)、[Monday](https://monday.com/w/mcp)、[Notion](https://developers.notion.com/docs/mcp)、[PagerDuty](https://support.pagerduty.com/main/docs/pagerduty-mcp-server-integration-guide)、[Workato](https://docs.workato.com/en/mcp.html) 和 [Zapier](https://zapier.com/mcp) 等企业应用，以及使用 [Amazon Bedrock AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 接入你现有的企业解决方案与 AI agent。我们会给出针对 Atlassian Jira 和 Confluence、[AWS Knowledge MCP Server](https://awslabs.github.io/mcp/servers/aws-knowledge-mcp-server/) 以及 [Amazon Bedrock AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 的具体 Actions 配置示例。

## 解决方案概览

借助 [AWS Quick MCP client](https://docs.aws.amazon.com/quicksuite/latest/userguide/mcp-integration.html)，你可以连接到远程托管式 MCP 服务端，或连接你自己托管的 MCP 服务端。AWS Quick 服务包含一个 MCP client，可用于通过 MCP 服务端把 AWS Quick 与 AI agent 和应用安全地连接起来。AWS Quick MCP client 在传输层支持服务器发送事件（SSE）和可流式 HTTP（streamable HTTP），并支持多种认证机制，包括三足 OAuth（3LO）、两足 OAuth（2LO）和无认证（No Auth）模式。AWS Quick 支持 [OAuth 2.0 Dynamic Client Registration](https://modelcontextprotocol.io/specification/2025-03-26/basic/authorization#dynamic-client-registration) 协议，可在无需用户交互的情况下获取 OAuth client ID。

如下面的架构图所示，你可以使用 MCP client 把 AWS Quick 连接到 AWS Knowledge MCP Server 与 Atlassian MCP 服务端，从而创建集成。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image2.jpg)

## 前提条件

在按本篇博客的分步说明于你自己的 AWS 账户中部署该解决方案之前，请确认已满足以下前提条件。开始之前，请确保你已具备：

- 一个 [AWS 账户](https://docs.aws.amazon.com/accounts/latest/reference/welcome-first-time-user.html#getting-started-step1)
- 已配置 AWS Quick，并订阅 Author Pro
- 一个可访问 Jira 和 Confluence 的 Atlassian 账户
- 创建 AWS 资源以及 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam) 角色和策略的权限
- 对 AWS 服务的基本了解
- 若要做 Amazon Bedrock AgentCore 配置：可访问已安装 AWS SDK 与 Python 的命令行环境；了解 AWS CLI 和 Python；Amazon Bedrock 已启用 Anthropic 模型访问权限

## 与 Atlassian MCP server 的 AWS Quick Actions 集成

本节中，你将创建一个与 Atlassian MCP 服务端的 AWS Quick Actions 集成，用来连接你的 Atlassian 云实例，随后使用 AWS Quick Chat Agent 调用该集成定义的操作。

- 在 Web 浏览器中使用具备 Author Pro 角色的凭据登录 [AWS Quick](https://docs.aws.amazon.com/quicksuite/latest/userguide/what-is.html)。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/10/002-Integrations-Actions-MCP.png)

- 在 **Create integration** 界面，为你的 Atlassian 集成填写 **Name** 和 **Description**。在 **MCP server endpoint** 中，输入 [Atlassian 托管的 MCP server](https://www.atlassian.com/blog/announcements/remote-mcp-server) 的 URL，即 `https://mcp.atlassian.com/v1/sse`，如下面的截图所示，然后选择 **Next**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image5.png)

- Atlassian MCP 服务端支持动态客户端注册和三足 OAuth（3LO）。AWS Quick MCP client 会从 Atlassian MCP 服务端获取建立连接所需的更多信息。在下一个界面中选择 **Create and continue**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image7.png)

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image9-1.png)

- 输入你的 Atlassian 凭据。
 你会收到来自 Atlassian MCP 的请求，要求访问你的 Atlassian 账户。
- 选择一个具体实例，然后选择 **Accept**。
 注意：Atlassian 实例的管理员可能需要把该动态 OAuth client 加入允许列表。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image11.png)

AWS Quick MCP client 会建立与 Atlassian MCP 服务端的连接，并获取它支持的操作或工具。这可能需要几分钟。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image13.png)

- 可选地，你可以把该集成共享给其他用户和群组。由于 Atlassian MCP 服务端支持 3LO，与你共享该连接的用户只能调用他们在 Atlassian Confluence 和 Jira 上被授权访问的操作、检索相应内容并执行相应操作。选择 **Done**。

## 使用 Atlassian MCP 连接

为了说明 Atlassian MCP 服务端的 Actions 集成，我们以一个虚构公司 AnyOrgApp Corp 的团队经理为例：他正准备在 AWS Quick 的默认 Chat Agent（My Assistant）帮助下迎接一位新员工加入团队。本例使用的 Atlassian 实例中有一个包含 AnyOrgApp Corp 相关内容的 Confluence space，以及一个属于该团队的 Jira 项目。你也可以基于自己的 Confluence space 和 Jira 项目内容，尝试类似的用例。

- 该经理用下面的 prompt 找到 AnyOrgApp 项目的新团队成员入职清单。该 prompt 的响应中会包含新团队成员的入职活动清单。

```
Find new team member checklist for the AnyOrgApp project from Confluence
```

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image23.png)

- 该经理用下面的 prompt 把清单转换成给新团队成员的任务，在 Jira 项目中创建这些任务，并把它们指派给新团队成员：

```
Make a list of tasks with start date and due date for a new team member Mateo Jackson 
joining the team on Monday October 6th, 2025. Create these tasks in Jira project 
"<replace-with-jira-project-name>" with start date and due date and assign those to 
<replace-with-email-address-for-mateo>
```

- 当 `atlassian-mcp` Actions 集成需要调用可变操作（例如创建 Jira issue）时，它会请求操作复核。Chat Agent 会为每个待创建的 Jira issue 提示进行复核。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image25.png)

- 创建任务后，会显示一条响应，其中包含已指派给新团队成员的新建任务。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image27.png)

- 检查 Jira 项目，确认任务已创建。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image29.png)

- 该经理要求写一封详尽的欢迎邮件，迎接新团队成员，并附上已指派的任务，要求使用对话中的上下文。
 该 prompt 的响应是一封详尽的欢迎邮件，包含按优先级排序的入职任务清单，以及如何向同事求助的信息。

```
Write a detailed email welcoming Mateo Jackson to the team based on this thread. 
Use warm and helpful tone.
```

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image31.png)

## 连接到 AWS Knowledge MCP Server

[AWS Knowledge MCP Server](https://awslabs.github.io/mcp/servers/aws-knowledge-mcp-server/) 是一个完全托管的远程 MCP 服务端，提供最新的文档、代码示例和其他 AWS 官方内容。

- 要把 AWS Knowledge Server 配置为 MCP Actions 集成，请从 Home 界面选择 Integrations，然后选择 Actions。在 Create new integration 中，像上一节配置 Atlassian MCP 服务端那样选择 Model Context Protocol。
- 在 **Create integration** 界面，使用 AWS Knowledge Server 托管式 MCP 服务端的 URL，即 `https://knowledge-mcp.global.api.aws`，然后选择 **Next**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image33.png)

- 该 MCP 服务端不需要认证，因此 MCP Client 已掌握创建集成所需的信息。选择 **Create and continue**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image35.png)

- 当 AWS Knowledge Server 向你提供的操作出现后，选择 **Next,**，完成 Actions 集成的创建。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image37.png)

- 当 aws-knowledge-server-mcp Actions 集成的状态变为 **available** 后，就可以使用默认 Chat Agent（My Assistant）开始询问 AWS 相关信息。你可以使用类似这样的 prompt：。

```
Get details of the AWS Well-Architected framework from AWS Knowledge MCP Server and 
summarize for a CXO presentation in the context of the new SaaS application your 
company is building on AWS. Use 200 words or fewer.
```

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image39.png)

- 你也可以在一个 prompt 中调用多个 Actions 集成，例如下面这个，其中同时使用了与 AWS Knowledge MCP Server 和 Atlassian MCP 服务端的 Actions 集成：

```
Get details of Well-Architected Framework from AWS Knowledge MCP Server and the details 
of the AnyOrgApp project from Confluence. Prepare well-architected tenets for the 
AnyOrgApp project team. Be crisp.
```

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image41.png)

## 使用 Amazon Bedrock AgentCore Gateway 连接解决方案与 agent

[Amazon Bedrock AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 是一个集中式的工具服务器，提供统一界面，agent 可以在其中发现、访问和调用工具，并原生支持 MCP。你可以把企业解决方案和 agent 作为目标连接到 Amazon Bedrock AgentCore Gateway 端点之后。AWS Quick MCP client 可以通过 Actions 集成连接到 Amazon Bedrock AgentCore Gateway，从而让 AWS Quick 上配置的聊天 agent 和自动化工作流可以使用这些工具。

我们以一个例子来说明（如下图所示）：我们需要连接到用 [Amazon Bedrock Agent](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-how.html) 实现、背后是一个含 IT 帮助内容的 [Amazon Kendra](https://docs.aws.amazon.com/kendra/latest/dg/what-is-kendra.html) 索引的 IT agent，同时还需要让 AWS Quick 用户可以使用一个搭建在 OpenAI 上的 HR agent。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/10/030-Quick-MCP-Blog-Page-2.png)

该架构包含一个 Amazon Bedrock AgentCore Gateway，它配置了一个 AWS Lambda 函数作为目标，并带有一份指明其实现哪些工具的 MCP schema。该 AWS Lambda 函数实现 [InvokeAgent API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_InvokeAgent.html) 来调用 Bedrock Agent 执行 Amazon Kendra 索引搜索，随后再触发一个 Lambda 函数调用 [Amazon Kendra Retrieve API](https://docs.aws.amazon.com/kendra/latest/APIReference/API_Retrieve.html)，从含 IT 帮助内容的企业 Amazon Kendra 索引中搜索并检索内容，同时调用 OpenAI [Responses API](https://platform.openai.com/docs/api-reference/responses) 来调用基于 OpenAI 的 HR agent。AgentCore Gateway 使用 Amazon Cognito 作为其入站身份提供方。AWS Quick MCP client 采用 2LO 认证进行配置，允许入站连接到 AgentCore Gateway 端点。

## 创建一个 Amazon Bedrock AgentCore Gateway 实例并连接解决方案

- 参照 [Quick Start with creating and using a gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-quick-start.html)，创建一个带 Amazon Cognito 授权方和默认 AWS Lambda 目标的 Amazon Bedrock AgentCore Gateway 实例。
- 在 AWS Management Console 的一个标签页中打开 Amazon Cognito 用户池，在左侧导航面板中选择 **App clients**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image45.jpg)

- 创建一个新的 App client，供 AWS Quick MCP client 使用。选择 **Create app client**，然后选择 **Machine-to-machine application**，再选择 **Create app client**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image46.png)

- 对于你刚创建的新 App client，记录 **Client ID**、**Client secret** 和 token URL。后续步骤会用到这些参数。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image48.png)

- 在浏览器的新标签页中打开 AWS Management Console 里的 Amazon Bedrock AgentCore。在左侧导航面板中选择 **Gateways**，然后选择你刚创建的 gateway。记录 **Gateway resource URL**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image51.jpg)

- 在 **Edit Gateway** 界面，选择 **Use existing identity provider configurations**，选择 **Add client**，然后把你前面步骤中创建的 Cognito App client 的 Client ID 加入允许的 client 列表。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image52.png)

- 记录 **Lambda ARN**，并检查 **Inline schema editor window** 中的内联 schema。选择 **Save**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image55.jpg)

- 你可以修改 schema 和 Lambda 函数，把你自己的解决方案和 agent 加入 AgentCore gateway。本篇博客示例所用的 schema 见下面的代码片段。在本篇博客的示例中，Lambda 函数还通过 [InvokeAgent API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_InvokeAgent.html) 调用实现 IT agent 的 Bedrock Agent，并通过 OpenAI [Responses API](https://platform.openai.com/docs/api-reference/responses) 调用由 OpenAI 驱动的 HR agent。如果你只是做试验，可以继续使用 [Quick Start with creating and using a Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-quick-start.html) 中创建的示例工具 `get_weather` 和 `get_time`。

Amazon Bedrock AgentCore Gateway 现在已准备好与 AWS Quick MCP client 或其他 MCP client 集成。

## 创建与 Amazon Bedrock AgentCore Gateway 的 AWS Quick MCP Actions 集成

- 与前面的步骤一样，输入 **Name**、**Description** 以及你的 Amazon AgentCore gateway 的 Gateway resource URL（即前面记下的 **MCP server endpoint**）来配置新的 MCP 集成。选择 **Next**。Description 中包含该 Actions 集成所提供功能的详细信息。AWS Quick 依据该描述来决定针对用户 prompt 应调用哪些 Actions。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/10/image56.png)

- 在 **Authentication settings** 中选择 **Service authentication**，即 2LO 认证。与该 Actions 集成共享的用户将使用这些凭据作为 Amazon Bedrock AgentCore Gateway 的入站凭据。你可以使用 Okta 或 Entra ID 等身份提供方创建 3LO 认证。输入你之前创建的 Amazon Cognito 用户池 App client 的 **Client ID**、**Client secret** 和 **Token URL**。选择 **Create and continue**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/09/image58.png)

- 检查 Amazon Bedrock AgentCore Gateway 以 MCP 工具形式提供的 Actions。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/10/image60.png)

- 可选地，把该集成共享给其他用户，然后选择 **Done**。

## 结论

在本篇博客中，你体验了 [AWS Quick MCP client](https://docs.aws.amazon.com/quicksuite/latest/userguide/mcp-integration.html) 如何支持与 Atlassian、Box 和 AWS Knowledge MCP Server 等远程托管式 MCP 服务端建立安全、无缝且广泛的连接。你也看到了 [Amazon Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html) 如何提供一种直接的机制来连接现有的解决方案和 agent，以及 AWS Quick MCP client 如何与 [Amazon Bedrock AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 连接，在 [AWS Quick](https://docs.aws.amazon.com/quicksuite/latest/userguide/what-is.html) 上为用户和 AI agent 营造协作环境。
