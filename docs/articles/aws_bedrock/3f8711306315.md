# Amazon SageMaker JumpStart 模型排行榜简介

Amazon SageMaker JumpStart 为您提供数百个可快速部署的开放式基础模型。这个选择很强大，但它也产生了一个真正的问题：您应该从哪种模型开始？比较模型通常意味着一次阅读一张模型卡并寻找不同来源在不同条件下发布的基准分数。然后，您仍然必须猜测每个模型对于您的用例将如何执行以及其成本是多少。

今天，我们推出 **Amazon SageMaker JumpStart 模型排行榜**，这是一种直接在 Amazon SageMaker Studio 中并排比较 [JumpStart 模型](https://console.aws.amazon.com/sagemaker/home#/launch?source=jumpstart&page=jumpstart) 质量、速度和成本的新方法。在这篇文章中，我们解释了排行榜显示的内容，用通俗易懂的语言定义了关键术语，并逐步介绍了如何从候选列表转为部署模型。

## JumpStart 模型排行榜是什么？

排行榜是 SageMaker Studio 中 JumpStart 基本模型页面的新视图，位于“类别”和“所有模型”视图旁边。它使用您已经知道的相同搜索栏和过滤器，并在大型语言模型 (LLM) 排行榜上打开。您无需先回答设置问题即可立即看到排名。对于每个模型，它显示两种信息：

- AWS 自行运行的三个公共基准（BIG-Bench Hard、GPQA Diamond 和 MMLU-Pro）的**质量得分**，对每个模型使用相同的评估设置，因此数字具有可比性。
- **性能和成本指标**，AWS 通过使用每个 JumpStart 部署配置将标准化测试工作负载发送到端点来衡量，以便您了解模型的响应速度以及运行成本。

由于这两种数字都来自相同的地方和相同的方法，因此您可以进行同类比较，而不是将来自不同网站的数据拼接在一起。发布时，排行榜涵盖了来自 Meta、Google、Qwen、IBM 和 Arcee 等提供商的 **70 多个模型**，并且随着时间的推移还会添加更多模型。

## 关键概念

本节定义了排行榜使用的术语：质量基准、用例配置文件和形成性能数字的优化目标以及性能指标本身。

### 质量基准

基准测试是一种标准化测试：一组具有已知答案的固定问题。通过相同的测试运行每个模型会给您一个可以比较的分数。在发布时，排行榜报告了LLM的三个推理基准：

| **基准** | **简单来说，它衡量的是什么** |
| --- | --- |
| **大硬凳 (BBH)** |一组需要多步骤推理的具有挑战性的任务，例如逻辑演绎、跟踪对象和多步骤算术。 |
| **GPQA 钻石** |通过网络搜索很难回答的研究生水平的科学问题。这是深刻推理的良好信号。 |
| **MMLU-Pro** |使用较难的多项选择题，涵盖科学、法律和工程等许多学科的广泛知识和推理。 |

对这三者来说越高越好。排行榜单独显示每个基准，而不是将它们混合成一个数字。这使结果保持透明：您可以权衡对您的应用程序重要的基准，并根据基准的公开定义检查每个分数。

### 用例概况和优化目标

速度和成本取决于您的工作负载以及模型的部署方式。排行榜上方的两个菜单控制您看到的性能和成本数字：

- **用例配置文件。** 从用例菜单的“查看基准”中选择最接近您的工作负载的配置文件。默认值为最大上下文。该配置文件仅更改性能和成本指标。每个配置文件的质量基准分数都是相同的。
- **优化目标。** 对于每个配置文件，一个模型可以有多个部署配置，排行榜一次显示一个指标。使用“优化”菜单选择哪一项。默认为平衡。

每个优化目标选择不同的配置：

| **优化目标** | **所示配置** |
| --- | --- |
| **平衡** |每个令牌的估计成本最低的配置。由于每个令牌的成本取决于实例价格和吞吐量，因此这会平衡您每小时支付的费用与实例生成令牌的速度。 |
| **成本优化** |每小时实例价格最低的配置。与其他目标相比，延迟可能更高，吞吐量可能更低。 |
| **延迟优化** |第一个令牌时间最短的配置。 |
| **吞吐量优化** |具有最高吞吐量的配置。这些配置可以使用推测解码。 |

### 性能指标

| **公制** | **它告诉你什么** |
| --- | --- |
| **第一个令牌的时间 (TTFT)** |用户在模型开始响应之前等待的时间。越低越好，这对于聊天来说最重要。 |
| **每个请求的吞吐量（令牌/秒）** |模型每秒生成多少个令牌。越高越好，这对于批量和大容量工作负载很重要。 |
| **实例成本（美元/小时）** |给定指定实例类型的每小时估计成本。 |

**关于成本的说明：** 估算成本仅反映 SageMaker 实例成本，基于配置默认实例类型的按需每小时费率。它不包括数据传输、存储、推理组件成本或折扣，例如预留实例或 AWS Savings Plans。您的实际账单会有所不同。使用 [AWS 定价计算器](https://calculator.aws/) 进行账单估算。

## 我们如何进行基准测试

发布的基准分数通常来自不同的团队，使用不同的提示、设置和硬件，这使得它们很难进行比较。我们采取了不同的方法：

- **每个模型都有一种方法。** AWS 在排行榜上的所有模型上使用相同的评估工具和设置运行每个基准。
- **在 SageMaker 上测量。** 性能和成本来自于将标准化测试工作负载发送到使用每个 JumpStart 部署配置（与您可以启动的配置相同）部署的端点。

有关完整详细信息，包括提示、生成设置以及如何测量配置，请参阅 [JumpStart 模型排行榜基准](https://docs.aws.amazon.com/sagemaker/latest/dg/jumpstart-foundation-models-leaderboard-benchmarks.html)。

在 SageMaker Studio 中，打开模型页面，然后选择排行榜视图。排行榜与其他视图保持相同的搜索栏和过滤器，并且有自己的 URL。您可以将其添加为书签或与您的团队共享直接链接。

每列都有一个蓝色热图，因此表现最好的模型一目了然：蓝色越深，该列中的结果越强。对任何基准列进行排序，以按您最关心的指标对模型进行排名。使用列设置（齿轮图标）隐藏不需要的指标，并水平滚动以查看更多。当您滚动时，模型名称列保持冻结状态，并且当有更多列可用时，边缘会淡出显示。

## 示例：为聊天助手选择模型

假设您正在构建一个内部帮助台助理。员工提出问题并期望按照设定的响应格式快速、准确地得到答案。您需要商业许可的模型并希望保持成本可预测。

按许可证过滤并选择延迟优化的类似聊天的用例配置文件后，您的候选列表可能如下所示：

| **型号** | **BBH** | **MMLU-Pro** | **TTFT（s）** | **吞吐量（令牌/秒）** | **实例成本（美元/小时）** |
| --- | --- | --- | --- | --- | --- |
| **A 型（大）** | 95.9 | 95.9 87.2 | 87.2 2.33 | 2.33 37 | 37 37.66 美元 |
| **B 型（中）** | 94.2 | 94.2 84.9 | 84.9 0.98 | 0.98 44 | 44 5.75 美元 |
| **C 型（小）** | 77.4 | 77.4 66.1 | 66.1 0.27 | 0.27 61 | 61 2.61 美元 |

从表中可以看出，模型 A 的知识得分最高，但成本也最高，第一响应最慢。模型 B 的得分几乎一样，支持多步推理，并且在更小、更便宜的实例上运行。对于帮助台来说，推理问题和快速响应比最后几点常识更重要，模型 B 是更好的起点。更大的型号并不总是更好的选择，排行榜让这种权衡在几秒钟内可见。

从那里，您将部署模型 B，使用帮助台提出的实际问题对其进行测试，并在质量保持不变的情况下将模型 C 作为成本较低的选择。

## 提示和须知事项

- **使用排行榜来建立候选名单，而不是做出最终决定。** 基准衡量一般能力。在投入生产之前，始终根据您自己的数据和提示评估前两个或三个模型。
- **首先过滤，然后排名。** 许可证和输入或输出模态规则模型输入或输出等要求。分数只能帮助您订购剩下的东西。
- **比较基准测试中的模型。** 每个基准测试都有其自己的难度，因此一个基准测试的分数不能直接与另一个基准测试的分数进行比较。
- **考虑模型类型。** 推理和非推理模型使用不同的生成参数进行评估，推理模型的 GPQA 钻石分数在 10 遍中取平均值。两种类型之间的比较是近似的。
- **检查部署配置。** 每个指标都适用于其测量的配置。比较您计划部署的配置的模型。
- **将接近的分数视为平局。** 微小的差异可能属于正常的运行变化，并不意味着某个模型明显更好。寻找明显的间隙。
- **覆盖范围正在扩大。** 并非每个 JumpStart 模型都有基准分数，并且启动基准测试主要针对LLM。没有分数的模型并不是弱模型。它根本还没有经过基准测试。

## 下一步是什么

我们正在继续扩大排行榜。我们正在探索的领域包括：

- **私有中心支持，**因此使用策划的 JumpStart 私有中心的组织可以看到其批准模型的排行榜。
- LLM 文本生成之外的**更多任务排行榜**，例如对象检测、文本嵌入和图像理解。
- **随着新模型添加到 JumpStart，更多模型和基准**。

## 结论

SageMaker JumpStart 模型排行榜将质量、速度和成本集中到一处，并在 SageMaker 上进行一致衡量。您无需比较来自不同来源的数字，而是可以筛选出适合您要求的模型，将它们与您计划运行的配置进行比较，然后只需单击几下即可进行部署。

首先，打开 SageMaker Studio 中的模型页面并选择排行榜视图。要了解更多信息，请参阅以下资源：

- [JumpStart 模型排行榜基准](https://docs.aws.amazon.com/sagemaker/latest/dg/jumpstart-foundation-models-leaderboard-benchmarks.html)。
- [Amazon SageMaker JumpStart](https://aws.amazon.com/sagemaker/jumpstart/)。
- [SageMaker JumpStart 文档](https://docs.aws.amazon.com/sagemaker/latest/dg/studio-jumpstart.html)。
- [SageMaker JumpStart 上基于用例的部署](https://aws.amazon.com/blogs/machine-learning/use-case-based-deployments-on-sagemaker-jumpstart/)。

打开排行榜，为您的工作负载选择两到三个模型，并在选择一个模型进行生产之前部署它们以根据您自己的提示进行测试。
