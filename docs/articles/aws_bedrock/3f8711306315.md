# Amazon SageMaker JumpStart 模型排行榜简介

Amazon SageMaker JumpStart 提供数百个可快速部署的开放权重基础模型。选择多是好事，但它也留下一个很现实的问题：该从哪个模型起步？比模型通常意味着逐个翻模型卡，再去不同来源、不同条件下公布的基准分数里翻找。即便如此，你仍得猜每个模型在你的用例下会表现如何、成本多少。

今天我们推出 **Amazon SageMaker JumpStart 模型排行榜**，让你直接在 Amazon SageMaker Studio 里按质量、速度和成本横向比较 [JumpStart 模型](https://console.aws.amazon.com/sagemaker/home#/launch?source=jumpstart&page=jumpstart)。本文说明排行榜展示哪些内容、用平实的语言解释关键术语，并带你走一遍从初选名单到完成部署的流程。

## 什么是 JumpStart 模型排行榜？

排行榜是 SageMaker Studio 中 JumpStart 基础模型页面上的一个新视图，与 Categories 和 All models 两个视图并列。它沿用你已经熟悉的搜索栏和过滤器，默认打开的是大语言模型（LLM）排行榜。无需先回答设置问题，排名即刻可见。对每个模型，它给出两类信息：

- **质量得分**，来自三个公开基准（BIG-Bench Hard、GPQA Diamond 和 MMLU-Pro），由 AWS 自己运行，所有模型使用同一套评测设置，因此数字之间可以比较。
- **性能与成本指标**，AWS 用每个 JumpStart 部署配置把标准化测试负载发到 endpoint 上测得，由此可以看出模型响应有多快、运行要花多少钱。

两类数字同源同法，你可以做真正对等的比较，而不必把不同网站的数据拼接起来。发布时，排行榜覆盖 Meta、Google、Qwen、IBM 和 Arcee 等厂商的 **70 多个模型**，后续还会持续增加。

## 关键概念

本节解释排行榜使用的术语：质量基准、影响性能数字的用例配置与优化目标，以及性能指标本身。

### 质量基准

基准就是标准化测试：一组答案已知的固定题目。让每个模型跑同一套题，得到的分数才有可比性。发布时，排行榜给出三个面向 LLM 的推理基准：

| **基准** | **用大白话说，它衡量什么** |
| --- | --- |
| **BIG-Bench Hard (BBH)** | 一组需要多步推理的挑战性任务，例如逻辑推演、追踪物体和多步算术。 |
| **GPQA Diamond** | 研究生水平的科学问题，靠网页搜索很难答对，是深度推理的良好信号。 |
| **MMLU-Pro** | 覆盖科学、法律、工程等众多学科的广博知识与推理，采用难度更高的多项选择题。 |

三项都是越高越好。排行榜分别展示每个基准，而不是把它们揉成一个总分。这样结果更透明：你可以按应用需要给不同基准加权，也能拿每一项分数去对照该基准的公开定义。

### 用例配置与优化目标

速度和成本取决于你的工作负载，也取决于模型的部署方式。排行榜上方的两个菜单决定你看到的性能与成本数字：

- **用例配置。** 在 View benchmarks for your use case 菜单里选择最接近你工作负载的配置，默认为 Max Context。这个配置只改变性能与成本指标，质量基准得分在任何配置下都相同。
- **优化目标。** 同一配置下，一个模型可能有多种部署配置，排行榜一次只展示其中一种，用 Optimized for 菜单切换，默认为 Balanced。

每个优化目标对应不同的配置：

| **优化目标** | **展示的配置** |
| --- | --- |
| **Balanced** | 每 token 预估成本最低的配置。由于每 token 成本同时取决于实例价格和吞吐量，这一项是在每小时花费与实例生成 token 的速度之间取平衡。 |
| **Cost optimized** | 每小时实例价格最低的配置。相比其他目标，延迟可能更高，吞吐量可能更低。 |
| **Latency optimized** | 首 token 时间最短的配置。 |
| **Throughput optimized** | 吞吐量最高的配置。这类配置可能使用推测解码。 |

### 性能指标

| **指标** | **它说明什么** |
| --- | --- |
| **Time to first token (TTFT)** | 用户要等多久模型才开始响应。越低越好，对聊天场景最关键。 |
| **Throughput per request (tokens/s)** | 模型每秒生成多少 token。越高越好，对批处理和高并发负载很重要。 |
| **Instance cost ($/hr)** | 给定实例类型下的每小时预估成本。 |

**关于成本的说明：** 预估成本只反映 SageMaker 实例成本，按该配置默认实例类型的按需小时费率计算，不含数据传输、存储、推理组件费用，也不含 Reserved Instances 或 AWS Savings Plans 等折扣。你的实际账单会有所不同，计费估算请使用 [AWS Pricing Calculator](https://calculator.aws/)。

## 我们如何进行基准测试

公开发布的基准分数往往出自不同团队，用的提示、设置和硬件各不相同，很难放在一起比较。我们换了一种做法：

- **所有模型同一套方法。** AWS 对排行榜上的每个模型都用相同的评测 harness 和设置运行每一项基准。
- **在 SageMaker 上实测。** 性能与成本来自把标准化测试负载发送到以对应 JumpStart 部署配置（也就是你可以直接启动的那些配置）部署的 endpoint。

完整细节，包括提示、生成设置以及配置的测量方式，请参阅 [JumpStart 模型排行榜基准](https://docs.aws.amazon.com/sagemaker/latest/dg/jumpstart-foundation-models-leaderboard-benchmarks.html)。

## 操作演示：找一个模型

下面几步演示如何从浏览走到完成部署。你需要具备 SageMaker Studio 的访问权限，以及部署 JumpStart 模型的权限。

在 SageMaker Studio 中打开 Models 页面，然后选择 Leaderboard 视图。排行榜保留与其他视图相同的搜索栏和过滤器，并且有自己的 URL。你可以把它加为书签，也可以把直链分享给团队。

## 示例：为聊天助手挑一个模型

假设你在做一个内部帮助台助手。员工提问后，期待按固定答复格式快速拿到准确答案。你需要一个允许商用的模型，同时希望成本可预测。

按许可证过滤，并选用贴近聊天的用例配置加 Latency optimized 之后，你的初选名单可能长这样：

| **模型** | **BBH** | **MMLU-Pro** | **TTFT (s)** | **吞吐量（tokens/s）** | **实例成本（$/hr）** |
| --- | --- | --- | --- | --- | --- |
| **Model A（大）** | 95.9 | 87.2 | 2.33 | 37 | $37.66 |
| **Model B（中）** | 94.2 | 84.9 | 0.98 | 44 | $5.75 |
| **Model C（小）** | 77.4 | 66.1 | 0.27 | 61 | $2.61 |

读表可见，模型 A 的知识得分最高，但成本也最高，首次响应最慢。模型 B 得分几乎持平，多步推理也站得住，而且跑在更小、更便宜的实例上。对帮助台来说，把问题推理清楚并快速响应，比常识题上最后那几分更重要，因此模型 B 是更好的起点。更大的模型不总是更好的选择，排行榜让这个取舍在几秒内就看得见。

接下来你会部署模型 B，用帮助台里的真实问题测试它，同时把模型 C 记作一个低成本备选，前提是质量撑得住。

## 提示与须知

- **排行榜用来建立初选名单，而不是做最终决定。** 基准衡量的是通用能力。上线之前，一定要用你自己的数据和提示评估排名前两三位的模型。
- **先过滤，再排序。** 许可证、输入或输出模态这类要求决定模型是否入围，分数只帮你给剩下的模型排序。
- **只在同一个基准内比较模型。** 每个基准的难度不同，某个基准上的分数不能直接与另一个基准的分数相比。
- **考虑模型类型。** 推理型模型和非推理型模型用不同的生成参数评测，推理型模型在 GPQA Diamond 上的分数是 10 次运行的平均值。两类模型之间的比较只是近似。
- **核对部署配置。** 每个指标只对被测的那个配置成立。请在你计划部署的配置上比较模型。
- **分数接近就当平手。** 微小差异可能落在正常的运行波动范围内，并不意味着某个模型真的更好。要看明显的差距。
- **覆盖面还在扩大。** 并非每个 JumpStart 模型都已有基准分数，首发基准聚焦于 LLM。没有分数不代表模型弱，只是它还没有被基准测过。

## 下一步

我们会继续扩展排行榜，正在探索的方向包括：

- **私有 hub 支持**，让使用精选 JumpStart 私有 hub 的组织能看到自己所批准模型的排行榜。
- **更多任务排行榜**，超出 LLM 文本生成，例如目标检测、文本嵌入和图像理解。
- **更多模型和基准**，随着新模型加入 JumpStart 而不断补充。

## 结语

SageMaker JumpStart 模型排行榜把质量、速度和成本汇到一处，并在 SageMaker 上以一致的方式测量。你不必再去比较不同来源的数字，而是可以筛选出符合要求的模型，在你计划运行的配置上做比较，然后点几下就完成部署。
