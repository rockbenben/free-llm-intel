# 推出 SOCI 索引镜像，加速 SageMaker AI 作业

深度学习容器镜像每多花一分钟下载，你就多付一分钟费用，团队也多等一分钟。容器镜像下载是纯粹的开销：可计费的作业时间，却不产生任何模型进展。对于现代深度学习镜像，这层开销落在每一个作业上都是好几分钟。今天，我们很高兴宣布*为 Amazon SageMaker AI Training 和 Amazon SageMaker AI processing 作业提供 Seekable OCI (SOCI) 索引*，把完整的容器镜像下载从每个作业的关键路径上彻底移除。

借助 SOCI 索引，SageMaker AI 会惰性加载你的容器镜像。它只取启动容器所需的文件，其余部分在你的代码运行的同时于后台流式传入，因此作业在几秒内就能开始，而不是几分钟。采用方式有两种：指向一个预建索引的 AWS Deep Learning Container（DLC），或为你自己的镜像添加索引。两种方式都不需要改动作业定义、入口点或数据通道。结果是作业启动更快、作业成本更低，更多时间用于构建模型，而不是等待基础设施。

SOCI 索引镜像能在几秒内启动 Amazon SageMaker AI 训练容器，且不影响训练性能。正如我们在*我们实测了什么*一节中所展示的，在我们的基准测试中，这把镜像拉取期间的 GPU 空闲时间最多减少了 90%。

本文介绍如何采用 SOCI 索引：它是什么、我们实测到的结果，以及如何为你自己的作业开启它。

# 挑战所在

SageMaker AI 的训练与处理作业运行在存放于 Amazon Elastic Container Registry（Amazon ECR）的容器镜像中。作业在执行你的代码之前，服务会把整个镜像下载到实例上，解压并把每一层写入磁盘。

小镜像只需几秒。但深度学习镜像通常超过 10 GB 甚至更大。这次下载会给每个作业增加数分钟，而你按作业时间为此付费。影响最大的恰恰是最看重迭代速度的场景：涉及数百个作业的超参数调优扫描、快速实验以及短时处理作业——在这些场景里，镜像下载可能占到总运行时间的大头。

# SOCI 索引的工作方式

[Seekable OCI (SOCI)](https://github.com/awslabs/soci-snapshotter) 是一项惰性加载容器镜像的开源技术。运行时不再在启动前下载整个镜像，而是借助 SOCI 索引只取立即启动容器所需的文件，随后在你的代码访问时于后台流式传输其余部分。

SOCI 索引是一份映射镜像内每一个文件的元数据。你把它作为符合 OCI 规范的 artifact 存放在 Amazon ECR 中，并与原始镜像关联。由于索引是独立的 artifact，你的镜像 digest 以及任何已有签名都保持有效。

## SageMaker AI 会自动检查索引

创建训练或处理作业时，SageMaker AI 会检查你指定的镜像是否带有 SOCI 索引，并据此行事：

| **场景** | **会发生什么** |
| --- | --- |
| **镜像包含 SOCI 索引** | SageMaker AI 惰性加载镜像，并在完整下载完成之前就启动你的容器 |
| **镜像没有 SOCI 索引** | 标准下载，行为不变 |
| **索引无法读取，或惰性加载未成功** | 作业回退到标准下载并继续运行 |

由于作业在需要时总会回退到标准下载，添加 SOCI 索引绝不会妨碍你的作业运行。你只会得到更快的启动，绝不会冒破坏现有工作流之险。

# 我们实测了什么

我们在真实的 SageMaker AI 训练作业上，用两种方式拉取同一批容器镜像：标准下载与 SOCI 索引惰性加载。随后我们分别基于两者运行完整训练作业，以衡量对训练速度的影响。

## 实验设置

- **八个镜像**，压缩后 1.8–35.4 GB。
- **GPU 与 CPU 实例** ml.g4dn、ml.g5、ml.g6、ml.g6e、ml.g7、ml.g7e、ml.p4d、ml.p5 和 ml.m7i，规格从 xlarge 到 48xlarge，位于美国西部（俄勒冈）区域（us-west-2）和美国东部（弗吉尼亚北部）区域（us-east-1）。
- **下载时间**，从镜像拉取开始计时，直到容器可运行。所有数据均为多次重复运行的中位数。

## 结果 1：每种镜像大小下，下载时间都从分钟级降到秒级

| **镜像大小（压缩后）** | **标准下载** | **惰性加载** | **提升** |
| --- | --- | --- | --- |
| **1.8 GB** | 48 s | 3-11 s | ~8x |
| **13.2 GB** | 3 min 42 s | ~6 s | ~34x |
| **35.4 GB** | 7 min 17 s | 3-11 s | ~38x |

每一对柱上方的加速倍数标签显示 Docker 时间与 SOCI 时间之比。加速倍数从最小镜像的约 10 倍到最大镜像的 35 倍以上。

## 结果 3：除首个 epoch 的代价外，训练性能不受影响

我们从 Docker 拉取的镜像和 SOCI 索引镜像分别运行了两类完整训练作业，并逐 epoch 比较：

- 大语言模型（LLM）微调：用 Hugging Face Trainer 在 [alpaca-cleaned](https://huggingface.co/datasets/yahma/alpaca-cleaned)（51,760 条样本）上对 [Qwen2.5-0.5B](https://huggingface.co/Qwen/Qwen2.5-0.5B) 做全参数监督微调（SFT）。  容器镜像：9.4 GB Hugging Face PyTorch DLC。实例：ml.p5.48xlarge、ml.p4d.24xlarge、ml.g6.48xlarge。

- 从第二个 epoch 起，两类工作负载在每种实例上每个 epoch 的耗时都相同（在运行间波动范围内）。
- 惰性加载镜像的首个 epoch 要多花 3–16 秒，因为框架首次访问的文件需要现取。这一首 epoch 代价在每种实例规格上都相同。
- 净效果：每个作业提前 1-6 分钟完成。这是下载节省减去一次性首 epoch 代价后的结果，是每个作业固定的节省。

### 在你自己的工作负载上验证

这些数字来自前面描述的两类工作负载。首 epoch 代价取决于你的镜像以及代码在启动时访问的内容：

- 当第一个训练步骤只需要镜像的一小部分时，惰性加载更有优势，其余部分在你训练的同时流式传入。
- 如果你的入口点在训练开始前读取了镜像的大部分内容（例如扫描、计算校验和或预加载其内容），首个 epoch 就要等待大致相当于完整拉取所取字节的数据。净提升会很小。
- 在我们的测试中，前置读取型的启动仍然胜出：  torch.compile 与即时（JIT）构建的 CUDA 扩展给首个 epoch 增加了 7-15 秒（净节省仍有 3 分 25 秒–3 分 56 秒） 烘焙进镜像的 6 GB 模型在加载时流式传输其权重，增加了 2-3.5 分钟，但索引镜像上的整体作业仍提前 2-2.5 分钟完成。

# 开始使用

你可以用两种方式采用 SOCI 索引：使用预建索引的 AWS Deep Learning Container，或为你自己的自定义镜像创建索引。

## 方式 1：使用预建索引的 AWS Deep Learning Container

AWS 发布了若干热门 Deep Learning Container 的 SOCI 索引变体，以镜像 tag 上的 -soci 后缀标识：

```
763104351884.dkr.ecr.us-east-1.amazonaws.com/pytorch-training:2.9-gpu-py312-cu130-ubuntu22.04-sagemaker-v1-soci
```

预建索引的变体可用于 PyTorch Training、TensorFlow Training、vLLM 和 SGLang，部分框架还提供 arm64 变体。要采用惰性加载，把作业定义中的镜像 tag 更新为 -soci 变体即可。完整列表可在 [AWS Deep Learning Containers Gallery](https://gallery.ecr.aws/deep-learning-containers) 中浏览。

**注意：**如果你基于 DLC 基础镜像（FROM）构建自己的镜像，你必须为最终镜像创建 SOCI 索引。基础镜像的索引不会延续到派生镜像上。

## 方式 2：为自己的镜像创建 SOCI 索引

要为自定义镜像建索引，你需要一台 Linux 主机（例如运行 Amazon Linux 2023 的 Amazon Elastic Compute Cloud（Amazon EC2）实例），并安装 [containerd](https://containerd.io/)、[SOCI snapshotter](https://github.com/awslabs/soci-snapshotter) 以及 [Finch](https://runfinch.com/) 或 [nerdctl](https://github.com/containerd/nerdctl) 之一。

- **设置环境变量**。  `ACCOUNT_ID="111122223333" REGION="us-east-1" REPOSITORY_NAME="my-training-image" ORIGINAL_IMAGE_TAG="v1.0" SOCI_IMAGE_TAG="v1.0-soci" REGISTRY="$ACCOUNT_ID.dkr.ecr.$REGION.amazonaws.com"`
- **安装所需工具**。  `sudo dnf install -y containerd fuse soci-snapshotter runfinch-finch sudo systemctl start soci-snapshotter sudo systemctl restart containerd`
- **向 Amazon ECR 认证**。  `aws ecr get-login-password --region "$REGION" \ | sudo nerdctl login -u AWS --password-stdin "$REGISTRY"`
- **拉取原始镜像**。  `sudo nerdctl pull "$REGISTRY/$REPOSITORY_NAME:$ORIGINAL_IMAGE_TAG"`
- **创建 SOCI 索引镜像**。  `sudo nerdctl image convert --soci \ "$REGISTRY/$REPOSITORY_NAME:$ORIGINAL_IMAGE_TAG" \ "$REGISTRY/$REPOSITORY_NAME:$SOCI_IMAGE_TAG"`
- **推送索引镜像**。  `sudo nerdctl push --platform linux/amd64 \ "$REGISTRY/$REPOSITORY_NAME:$SOCI_IMAGE_TAG"`

这会在你的仓库中创建两个 artifact：SOCI 索引，以及一个把你镜像与索引关联起来的符合 OCI 规范的 image index manifest。你的原始镜像及其 digest 保持不变。

## 在 CI/CD 中自动创建索引

要在每次推送时自动生成索引，请部署 [CFN ECR SOCI Index Builder](https://github.com/aws-ia/cfn-ecr-aws-soci-index-builder)。它使用一条 [Amazon EventBridge](https://docs.aws.amazon.com/eventbridge/latest/userguide/eb-what-is.html) 规则来检测 Amazon ECR 镜像推送事件并构建索引。无需改动你的构建流水线。

# 在 SageMaker AI 作业中使用索引镜像

像引用任何其他镜像那样引用你的 SOCI 索引镜像。无需任何 API 改动，只有 tag 不同。

## 训练示例（SageMaker Python SDK）

```
from sagemaker.train import ModelTrainer
from sagemaker.train.configs import Compute

trainer = ModelTrainer(
    training_image="111122223333.dkr.ecr.us-east-1.amazonaws.com/my-training-image:v1.0-soci",
    role="arn:aws:iam::111122223333:role/SageMakerExecutionRole",
    compute=Compute(
        instance_type="ml.g5.12xlarge",
        instance_count=2,
    ),
)

trainer.train()
```

## 确认镜像已包含 SOCI 索引

启动之前，先确认你的 tag 解析到的是带索引的镜像：

```
aws ecr batch-get-image \
  --repository-name "$REPOSITORY_NAME" \
  --image-ids imageTag="$SOCI_IMAGE_TAG" \
  --accepted-media-types \
  "application/vnd.oci.image.index.v1+json" \
  --query 'images[0].imageManifest' --output text \
  | jq '.manifests[] | {mediaType, artifactType}'
```

在同你的平台 manifest 并列的位置，查找一个 artifactType 以 application/vnd.amazon.soci.index. 开头的子 manifest。如果找不到，说明该 tag 指向的不是带索引的镜像。

# 注意事项

- **仅限 Amazon ECR 私有仓库。**位于其他注册表中的镜像，或通过私有 Docker registry 拉取的镜像（TrainingRepositoryAccessMode 设为 Vpc），不具备惰性加载资格。
- **提升幅度随镜像大小变化。**小于约 4 GB 的镜像提升相对较小。
- **检查是否有 Docker 特有的假设。**SOCI 索引镜像运行在基于 containerd 的运行时上。检查入口点和安装脚本中是否有调用 Docker CLI、读取 /var/run/docker.sock 或从 cgroup 路径推导标识符的代码。为向后兼容，SageMaker AI 会挂载一个 /.dockerenv 标记，但请避免新增对它的依赖。
- SageMaker AI 作业的 SOCI 索引在所有 AWS 区域均可用。

# 结论

借助 SOCI 索引，你可以把 SageMaker AI 训练与处理作业的容器镜像下载时间降到最低。为镜像添加 SOCI 索引，或改用预建索引的 AWS Deep Learning Container。无论哪种方式，都能把启动时间从分钟级缩短到秒级、降低作业总成本，并加快你的机器学习（ML）迭代周期。而你现有的作业定义、API 调用和数据管道完全保持不变。

要深入了解 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/) 并开始使用 SOCI 索引，请参阅以下资源：

- **挑选一个 SOCI 索引的 Deep Learning Container。**浏览 [Deep Learning Containers Gallery](https://gallery.ecr.aws/deep-learning-containers)，并在镜像 tag 后追加 -soci。各框架的具体指导见 [SOCI index for AWS Deep Learning Containers](https://aws.github.io/deep-learning-containers/tutorials/SOCI/)。
- **为自己的自定义镜像建索引。**按照 [SageMaker AI 开发者指南](https://docs.aws.amazon.com/sagemaker/latest/dg/soci-indexing.html)中的分步演练操作，或参阅 [SOCI snapshotter 入门指南](https://github.com/awslabs/soci-snapshotter/blob/main/docs/getting-started.md)了解进阶选项。
- **在 CI/CD 流水线中自动化索引。**部署 [CFN ECR SOCI Index Builder](https://github.com/aws-ia/cfn-ecr-aws-soci-index-builder)，在每次镜像推送时自动生成索引。无需改动流水线。
- **用 Finch 在本地测试。**使用 [Finch 惰性加载演练](https://runfinch.com/docs/container-images/lazy-loading/)，在提交作业前于基于 containerd 的运行时上验证你的镜像。
- **深入了解这项技术。**阅读 AWS Machine Learning Blog 上的 [在 DLAMI 和 DLC 上使用 SOCI 索引缩短容器冷启动时间](https://aws.amazon.com/blogs/machine-learning/reducing-container-cold-start-times-using-soci-index-on-dlami-and-dlc/) 了解基准数据，或浏览 AWS Containers Blog 上的 [深入内部：用 Seekable OCI 与 AWS Fargate 惰性加载容器镜像](https://aws.amazon.com/blogs/containers/under-the-hood-lazy-loading-container-images-with-seekable-oci-and-aws-fargate/)，详细了解惰性加载机制。

更快的容器启动只差一个镜像 tag。在你下一个 SageMaker AI 作业上试试，看看差别。
