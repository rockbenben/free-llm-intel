## [人工智能](https://aws.amazon.com/blogs/machine-learning/)

# Taxbit Assist：Amazon Bedrock AgentCore 上的脚踏实地、角色感知的 AI 代理

[Taxbit](https://www.taxbit.com/)是一个数字资产税务和会计合规平台。 Taxbit 成立于 2018 年，帮助交易所、支付服务和经纪商等企业大规模计算损益、收集税务文件并提交信息申报表。现在，一个具有许可意识的人工智能助手可以帮助合规团队在产品仪表板内找到答案。

但使用该仪表板所需的知识分散在公共网站、API 文档和帮助中心文章中，而且根本没有写下有意义的内容。当客户询问“此表单状态意味着什么？”时，他们要么继续挖掘，要么提交支持请求。根据 Taxbit 的内部生产分析，如今，超过 55% 的向 Assist 提问的用户会在 24 小时内返回询问另一个问题。

在这篇文章中，我们分享了如何在 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 上构建 [Taxbit Assist](https://www.taxbit.com/platform/assist)，这是一个现在嵌入 Taxbit 仪表板中的 AI 助手，这是一个使用任何框架或模型大规模构建、连接和优化代理的平台。我们涵盖架构、使答案足够可信以发送给受监管客户的检索工作、我们如何处理安全和数据驻留，以及我们如何持续衡量实时生产流量的答案质量。

## 助理必须做对的事情

通用聊天机器人不是这个领域的选择。四个限制因素塑造了我们的构建：

- **有依据并引用 –** 我们的用户做出归档决定。每个答案都必须追溯到用户可以打开和阅读的来源，当助手不知道什么时，它必须这么说。
- **角色和组织意识 –** 助理不应引导支持用户完成仅限管理员的工作流程并将他们发送到他们无法打开的页面。
- **无税务建议 –** 解释 Taxbit 如何计算成本基础（用于计算收益或损失的会计方法）的是产品文档。告诉用户选择哪种方法是税务建议。两者之间的界限很窄。
- **区域数据驻留 –** 由单一代码库支持，在生产中进行持续的质量测量。
- **在我们的合规计划中 –** Taxbit Assist 的开发和运营符合 AI 管理系统国际标准 ISO/IEC 42001。 Taxbit 还通过了 ISO/IEC 27001 和 ISO/IEC 27701 认证，并持有 SOC 2 Type II 报告。 Taxbit 不会训练或微调任何模型，Amazon Bedrock 不会使用提示或完成来训练模型。

我们也是一个小团队。我们选择 Amazon Bedrock AgentCore 的原因有三个：其托管代理运行时删除了基础设施操作、内置 AgentCore 内存、Amazon Bedrock AgentCore 的功能、消除了单独的会话状态存储以及每个会话隔离保留了每个用户的上下文，而不是自己构建和操作代理循环、会话状态存储和会话隔离。这让我们将大部分精力投入到后续的检索和安全工作中。

## 解决方案概述

Taxbit Assist 是一个在 AgentCore 运行时（Amazon Bedrock AgentCore 的一项功能）上运行的 [Strands Agents SDK](https://strandsagents.com/) 应用程序。下图展示了该解决方案的架构。

![架构图显示了仪表板用户通过 AgentCore Runtime 的请求流，包括护栏筛选、知识库检索、Claude Sonnet 推理、权限检查和响应流CloudWatch。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/03/ML-21532-1.gif)

图 1：从仪表板问题到护栏筛选、知识库检索、模型推理、权限检查和响应流的请求流

工作流程包括以下步骤：

- 用户在 Taxbit 仪表板中提出问题。流式聊天 API 将其与用户经过验证的身份（电子邮件、组织 ID 和仪表板角色）一起转发到 AgentCore 运行时。
- 运行时使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 筛选传入消息。个人身份信息 (PII) 被适当屏蔽。如果消息被阻止，则永远不会调用模型。
- 代理从 [Amazon Bedrock 知识库](https://aws.amazon.com/bedrock/knowledge-bases/) 知识库检索候选段落，然后在服务器端对它们重新排序。该知识库使用 Amazon Bedrock 完全托管的检索增强生成 (RAG) 功能，并由 Amazon Simple Storage Service (Amazon S3) 的一项功能 [Amazon S3 Vectors](https://aws.amazon.com/s3/features/vectors/) 支持。
- [Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-bedrock.html) 对检索到的段落进行建模推理，并在推荐任何工作流程之前验证用户是否有权访问相关功能和角色。有关 AWS 区域的模型可用性，请参阅 [AWS 区域支持的模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。
- 答案通过源链接流回仪表板。 AgentCore 内存可跨轮进行对话。
- 每个请求都会向 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 发出 OpenTelemetry 跟踪，这为我们的评估工具提供数据。

### 代理运行时

该代理是一个小型 Python 应用程序：一个系统提示符、一个模型和八个工具。它作为 ARM64 容器映像提供，AgentCore 运行时从 [Amazon Elastic Container Registry (Amazon ECR)](https://aws.amazon.com/ecr/) 提取并按需扩展。

这些工具被故意缩小：

- 知识库搜索，主要工具。
- 两项访问检查，一项针对组织权利，一项针对用户的仪表板角色。
- 四种支持票证工具，用于创建、列出、更新和关闭呼叫者自己的票证。
- 当前时间，对于需要亚日精度的罕见问题。

在此版本中，代理没有对客户税务数据的读取权限。它根据产品知识进行回答，并且它唯一可以执行的写入是呼叫者自己的支持票证。

一项安全决策支撑着所有这些：该模型从不处理身份。用户的电子邮件、组织 ID 和角色来自可信调用服务，并在模型看到之前通过闭包绑定到每个工具中。模型可以决定是否检查权限，但不能决定检查谁的权限，因为身份不是它可以设置的参数。用户输入在边界处被净化，因此提示注入不能模仿可信上下文行。

该代理通过 Amazon Bedrock 运行基础模型 (FM)，并通过跨区域推理配置文件调用。

地理感知推理处理数据驻留。推理配置文件 ID 带有从部署区域派生的地理前缀，因此欧盟部署将推理保留在欧盟内，而美国部署则保留在美国。除了在正确的地理位置进行推理之外，我们还支持自带密钥 (BYOK) 模型。在 BYOK 账户中，对话历史记录和保存客户数据的其他存储均使用客户自己的 AWS Key Management Service (AWS KMS) 密钥进行加密。

应用程序推理配置文件处理成本可见性。每个部署都将系统推理配置文件包装在标记的应用程序配置文件中，因此每个模型调用都带有成本分配标签，并显示在 AWS Cost Explorer 中，并按工作负载细分。

Amazon Bedrock 提示缓存可降低延迟和令牌成本。系统提示符对于每个请求都是字节相同的，并以缓存检查点结束，因此静态前缀会跨用户缓存。每个请求的上下文都在用户消息上传输。

## 在精心策划的知识库中提供答案

我们的大部分工程工作都投入到知识库中：由 Amazon S3 Vectors 支持的 Amazon Bedrock 知识库，使用 Cohere Embed English v3 进行嵌入，生成按余弦距离进行比较的 1,024 维 float32 向量。全部都是托管的，所以没有矢量数据库可供我们操作。

### 摄入

内容从三种来源流入，每种来源都以自己的前缀登陆到单个 [Amazon S3](https://aws.amazon.com/s3/) 存储桶中。

图 2：通过 Lambda 抓取工具从已发布的、代码派生的和精选的来源到 Amazon S3 和知识库的内容提取管道

首先发布的内容是：我们的公共网站、API 文档和帮助中心文章，由预定的 [AWS Lambda](https://aws.amazon.com/lambda/) 函数进行爬网。使用站点地图 Lastmod 时间戳和内容哈希，典型的运行仅涉及自上一次运行以来发生的更改。范围界定比我们预期的更重要。我们的站点地图大约有 400 多个 URL，但只有大约 70 多个属于答案生成语料库，仅 /blogs/ 就占了 300 多个营销页面。留在其中，该活动内容将与帮助中心竞争，成为合规性问题的引用来源。排除它是我们最有价值的检索更改之一，并且它根本不需要任何模型工作。

第二个来源不太传统：Lambda 函数读取我们的产品源代码并生成 Markdown 文档，涵盖仪表板路由、权限门、表单资格逻辑和报告配置。这捕捉到了散文中其他地方不存在的产品真相，并且它保持最新，因为它是从代码本身重新生成的。第三个来源是精选内容：手写文章和批准的更正，填补了自动化来源无法覆盖的空白。

[Amazon EventBridge](https://aws.amazon.com/eventbridge/) 以交错的每晚和每周节奏安排爬网，并且每个抓取工具仅在某些内容发生更改时才会触发摄取作业。我们将九个爬虫分为三个伞形数据源，并按 S3 子前缀（product-public/、product-internals/、curated/）划分，从而将相关内容放在一起。

### 上下文分块

我们选择了语义分块，它在自然边界处分割文档，并且在我们的检索测试中优于固定大小的分块。但是从文档中间提取的一大块就失去了文档的内容。在税务报告中，上下文通常就是全部答案：如果针对 IRS 表格 1099（用于报告付款的信息申报表）的问题返回一段仅适用于非美国申报制度的段落，则该段落会产生严重误导。

为了解决这个问题，我们使用知识库的自定义转换挂钩来运行 POST_CHUNKING Lambda 函数，该函数在每个块前面加上文档的 H1 标题和引导段落，通常说明内容适用的位置。前缀的上限约为 128 个标记（80 个标题字符和 300 个范围字符）。由于 Cohere Embed English v3 每个输入最多接受 512 个标记，因此块主体的上限为 384，因此标头和主体可以一起容纳在该窗口内。生产探针发现大约 28% 的块位于 385-512 范围内，并且它们的尾部会被悄悄地截断。

这是我们所做的影响最大的检索更改：块现在将其自己的范围带入向量索引中，而不是仅存在于文档的第一个块中。

两个实用注意事项：首先，Amazon Bedrock 要求转换的中间存储是与数据源存储桶分开的存储桶。同一存储桶上的不同前缀将被拒绝。其次，在现有数据源上启用自定义转换会强制进行替换，因此请计划完全重新摄取而不是就地更改。

### 检索

在查询时，管道过度获取然后修剪：
```
question ─► vector search (75 candidates)
─► Cohere Rerank 3.5, server-side in the same Retrieve call
─► top 12 reranked
─► cap of 2 chunks per source document
─► top 5 passed to the model
```
重新排序器作为同一 Retrieve 调用的一部分在 Amazon Bedrock 内部运行，因此没有额外的服务跃点。我们保留 75 个候选池的范围，因为权威文章通常位于矢量排名 20-50，并且只有在进入池后才会重新排名到顶部。每个文档的上限可以防止一个严重分块的页面填满每个插槽。

引用资格是通过代码中的源类型而不是提示指令来强制执行的。只有三个已发布的来源是可引用的，因为只有它们的 URL 才能解析为客户可以打开的内容。代码衍生和策划的内容为答案提供基础，但不会产生客户无法跟踪的链接。

## 安全和数据处理

三个边界将一个租户的数据排除在另一租户的会话之外：

- 知识库不包含特定于租户的内容：仅包含已发布的文档、代码派生的产品参考和精选文章。
- 权利和角色检查工具从已经对他们进行身份验证的服务中获取调用者的组织和电子邮件，因此该模型无法扩大该范围。
- AgentCore 运行时隔离每个会话，对话历史记录按内存、会话和参与者 ID 进行分区。该参与者 ID 必须来自调用服务，而不是来自 AWS 调用者身份，因为运行时在单个服务角色下执行。推断出的身份会将每个用户的历史记录放在一个分区中。

Amazon Bedrock Guardrails 可根据您的应用程序要求提供可配置的保护措施，并在代理运行之前筛选每条传入消息。我们将其作为独立的 ApplyGuardrail 调用应用，范围仅限于当前用户回合，这避免了每次都重新扫描整个对话历史记录。

PII 政策针对税务数据进行调整。与语言模型无关的秘密，例如密码、卡验证码和云访问密钥，将被彻底阻止。窄格式的数字标识符，包括社会保障号、个人纳税人识别号 (ITIN)、银行账户和路由号码以及国际银行帐号 (IBAN)，均已就地匿名化。这使得代理可以在不看到价值的情况下帮助完成工作流程。外部集成的凭证位于 [AWS Secrets Manager](https://aws.amazon.com/secrets-manager/) 中，并在运行时获取，从未烘焙到映像或配置中。

## 衡量实时流量的质量

最有回报的习惯是在生产中持续测量质量，而不会阻止响应。下图说明了跟踪源如何分散到四个独立的消费者，以及专家的纠正如何返回到检索中。

![评估图显示 CloudWatch 跟踪扇形分布到 AgentCore 评估、质量判断、税务建议分类器和 Slack 中的人工审核，并将批准的更正反馈回知识中基础。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/03/ML-21532-3.png)

图 3：评估流程，其中 CloudWatch 跟踪分散到在线评估、质量判断、税务建议分类器和人工审核，并将批准的更正反馈回知识库

AgentCore 在线评估从 CloudWatch 跟踪中对 10% 的实时会话进行采样，并使用六个内置的“LLM-as-a-judge”评估器对其进行评分：有用性、有害性、连贯性、指令遵循性、工具选择准确性和工具参数准确性。结果以指标和每个会话分数的形式出现在 CloudWatch 中，因此质量回归会显示在仪表板上，而不是客户投诉中。

我们将自己的判断放在最上面，通过 CloudWatch 订阅过滤器读取相同的跟踪源。 Lambda 函数根据对检索来源的忠实度和检索文章的相关性对每个采样答案进行评分，并将结果作为 CloudWatch 指标发出。我们将忠实性和相关性分开，因为答案可以忠实于不应该检索的来源。发生这种情况时，问题出在检索管道中，而不是模型中。

基础模型分类器检查每个响应是否存在税务建议漂移。对于主题过滤器来说，产品文档和税务建议之间的界限太细了：“在自己的钱包之间转账不是应税事件”是建议，而解释 Taxbit 如何应用 [FIFO（先进先出）](https://info.taxbit.com/knowledge/disposition-methods#first-in-first-out) 是产品文档。带有说明和示例提示的模型的误报率几乎为零，而主题过滤器的误报率约为 25%。这两个分类器都不会增加延迟。

人类关闭了这个循环。样本答案（从每个问题和答案中删除个人详细信息）将进入内部审核渠道，主题专家可以在其中回复更正。批准的更正将写入知识库的策划前缀中，并触发增量摄取作业，因此专家的修复可以在几分钟内到达下一个用户的答案，而无需部署。

## 部署和操作

整个堆栈在 [AWS 云开发套件 (AWS CDK)](https://aws.amazon.com/cdk/) 中定义，因此建立新环境或具有不同驻留要求的新区域是一项配置更改。每个拉取请求都运行一个离线评估套件：根据预期的工具路径和行为判断的一组黄金场景，因此在发布之前可以对提示和检索更改进行测量。该套件还每晚针对生产环境运行。合并首先部署到暂存阶段，然后通过手动审批门部署到生产环境。

## 结果和影响

Taxbit Assist 自 2026 年 5 月起已在美国和欧盟投入使用，欧盟流量由地理内推断提供服务。答案基于精选的知识库并引用其来源，助手会在推荐工作流程之前检查功能可用性和用户的权限。对于嵌入式支撑表面，重复使用是团队最密切关注的指标。

一个早期的例子很引人注目。一个与 Taxbit 集成来收集税务文件（W-8 和 W-9 表格、IRS 预扣税和身份证明表格）的新客户在构建过程中严重依赖该助手。以前需要与我们团队共享的渠道或支持请求中提出的集成问题都可以当场得到解答。客户无需等待 Taxbit 支持团队即可继续进行集成，而且支持团队也从未看到流量。

每次对话的模型成本平均低于 20 美分。提示缓存完成了大部分工作：大约四分之三的输入令牌是从缓存提供的，这将模型成本降低了一半以上。

### 我们会采取什么不同的做法

- 在调整提示之前先确定语料库的范围。在我们将索引缩小到支持和文档内容并赋予每个块其文档范围后，答案的改进比任何即时修订都要多。
- 根据您自己的流量测量护栏过滤器强度。我们根据自己的流量测量了 Amazon Bedrock Guardrails PII 检测器，并将 PIN 和银行路由检测器设置为仅检测，因此数字形式的标识符（例如 1099）可以通过，而检测器仍然标记真正的敏感值。
- 保持系统提示字节稳定，以便提示缓存可以跨用户运行。
- 在第一个原型的代码中绑定身份。我们早期的测试构建将模型将身份传递给工具作为参数。我们在启动之前将其移至调用服务，因此注入的提示无法扩大其自身的访问范围。

## 下一步是什么

今天小助手就从产品知识来解答。下一步是一个助理可以回答诸如“我的收款人中有多少人缺少税务文件？”之类的问题。通过相同的身份绑定、权限检查工具模式查询客户自己的报告数据。用户提出问题，模型决定使用哪个工具和过滤器，但经过身份验证的调用者确定该工具可以读取谁的数据，因此模型无法更改它。

## 结论

Amazon Bedrock AgentCore 让一个小团队向两个地区的受监管企业客户提供一个引用的、具有权限意识的助手，而无需运行我们自己的编排、矢量搜索、内容安全或评估基础设施。这使我们能够将时间花在重要的事情上：语料库、检索管道以及税务信息报告中什么才是好的答案。
