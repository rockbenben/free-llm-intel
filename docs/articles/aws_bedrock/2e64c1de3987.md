# 用生成式 AI 加速你的营销创意构思 —— 第 2 部分：从历史参考素材生成定制营销图像

在当今的数字环境中，营销团队在创建营销活动时面临巨大挑战。他们必须在复杂的数据分析和快速变化的消费者偏好中穿梭，跨多个渠道产出有吸引力且个性化的内容，同时保持品牌一致性，并在紧迫的截止时间前完成工作。使用生成式 AI 可以简化并加速创意流程，同时保持与业务目标的一致性。的确，根据 [McKinsey 的《2023 年 AI 现状》报告](https://www.mckinsey.com/capabilities/quantumblack/our-insights/the-state-of-ai-in-2023-generative-AIs-breakout-year)，现在有 72% 的组织已将 AI 集成到其运营中，而营销正成为落地的关键领域。

在我们此前[使用 Amazon Nova 基础模型生成营销活动图像](https://aws.amazon.com/blogs/machine-learning/accelerating-your-marketing-ideation-with-generative-ai-part-1-from-idea-to-generation-with-the-amazon-nova-foundation-models/)的工作基础上，本文演示如何通过向以往的营销活动学习来增强图像生成。我们探讨如何集成 [Amazon Bedrock](https://aws.amazon.com/bedrock)、[AWS Lambda](https://aws.amazon.com/lambda) 和 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/)，构建一个先进的图像生成系统，利用参考营销活动来维护品牌指南、交付一致的内容，并提升新营销活动创建的成效与效率。

## 以往营销活动信息的价值

历史营销活动数据是创建有效营销内容的有力基础。通过分析过往营销活动的效果模式，团队可以识别并复制那些持续带来更高互动率和转化率的成功创意元素。这些模式可能包括特定的配色方案、图像构图，或能与目标受众产生共鸣的视觉叙事技巧。以往的营销活动素材也可作为经过验证的参考，用于在各渠道间保持一致的品牌调性与视觉识别。这种一致性对于建立品牌认知和信任至关重要，尤其是在多渠道营销环境中，连贯的信息传递不可或缺。

本文将探讨如何在营销内容创建中使用历史营销活动素材。我们用有价值的元数据丰富参考图像，其中包括营销活动详情和 AI 生成的图像描述，并将它们送入 embedding 模型处理。通过把这些参考素材与 AI 驱动的内容生成相结合，营销团队可以把过去的成功转化为面向未来营销活动的可执行洞察。组织可以用这种数据驱动的方法扩展营销工作，同时保持质量与一致性，从而实现更高效的资源利用和更好的营销活动表现。我们将演示这种系统化使用以往营销活动数据的方法如何显著增强营销策略与成果。

- 系统从基于 Web 的 UI 开始，用户可以访问它来开始创建新的营销活动图像。[Amazon Cognito](https://aws.amazon.com/es/cognito/) 负责用户认证与管理，帮助确保对平台的安全访问。
- 历史营销素材被上传到 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/)，以构建相关的参考库。该上传流程通过 [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 发起。本文使用公开可用的 [COCO（Common Objects in Context）数据集](https://cocodataset.org/#home) 作为参考图像来源。

- 这一步把素材发现与内容生成衔接起来。当用户发起新的营销活动时，一个 Lambda 函数（`GenerateRecommendationsFunction`）会把营销活动需求转换为向量 embedding，并在 OpenSearch Serverless 索引中执行相似性搜索，以找出最相关的参考图像。随后，所选参考图像的描述通过一个 Lambda 函数（`GeneratePromptFunction`）并入增强后的 prompt。这个 prompt 再通过一个 Lambda 函数（`GenerateNewImagesFunction`）驱动使用 Amazon Bedrock 创建新的营销活动图像。有关图像生成流程的详细信息，请参阅我们的[上一篇博文](https://aws.amazon.com/blogs/machine-learning/accelerating-your-marketing-ideation-with-generative-ai-part-1-from-idea-to-generation-with-the-amazon-nova-foundation-models/)。

我们的方案已在 [GitHub](https://github.com/aws-samples/generative-ai-ml-latam-samples/tree/main/blueprints/genai-marketing-campaigns) 上提供。要部署该项目，请按照 [README](https://github.com/aws-samples/generative-ai-ml-latam-samples/blob/main/blueprints/genai-marketing-campaigns/README.md) 文件中提供的说明操作。

### 生成参考图像 embedding

Lambda 函数 `EmbedImgFunction` 使用 [Amazon Titan Multimodal Embeddings](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-multiemb-models.html) 模型把参考图像编码为向量表示。该模型可以把两种模态都嵌入同一个联合空间，在其中文本和图像都表示为同一维度空间里的数值向量。在这种统一表示下，语义相似的对象（无论是文本还是图像）会被放置得更靠近。该模型在模态内部与跨模态之间都保持了语义关系，从而支持对图像与文本的任意组合进行直接比较。这让基于文本的图像搜索、图像相似性搜索以及文本与图像的联合搜索等强大能力成为可能。

下面的代码演示了把图像转换为向量 embedding 的核心逻辑。Lambda 函数的完整实现请参阅我们的 [GitHub 仓库](https://github.com/dlaredo/generative-ai-ml-latam-samples/blob/main/blueprints/genai-marketing-campaigns/backend-img-indexing/pace_backend/index_imgs_workflow/get_img_embeddings_fn/index.py)。

```
with open(image_path, "rb") as image_file:
    input_image = base64.b64encode(image_file.read()).decode('utf8')

response = bedrock_runtime.invoke_model(
    body=json.dumps({
        "inputImage": input_image,
        "embeddingConfig": {
            "outputEmbeddingLength": dimension
        }
    }),
    modelId=model_id
)
json.loads(response.get("body").read())
```

该函数输出包含图像详情及其 embedding 向量的结构化响应，如下例所示。

```

### 使用 Amazon Bedrock 和 OpenSearch Serverless 索引参考图像

我们的方案使用 OpenSearch Serverless 为参考图像提供高效的向量搜索能力。该过程包含两个主要步骤：先搭建搜索基础设施，再用参考图像数据填充它。

#### 创建搜索索引

在为参考图像建立索引之前，我们需要搭建合适的搜索基础设施。当我们的技术栈被部署时，它会在 OpenSearch Serverless 中预置一个向量搜索 collection，由后者自动处理扩缩容与基础设施管理。在该 collection 内，我们使用 Lambda 函数 `CreateOpenSearchIndexFn` 创建一个搜索索引。

下面的代码展示了我们的索引 mappings 配置，它定义了向量相似度算法以及用于过滤的营销活动元数据字段。我们使用分层可导航小世界（HNSW）算法，在搜索速度与准确率之间取得最佳平衡。营销活动元数据包含一个 `objective` 字段，用于记录营销活动目标（例如点击、认知或点赞），还包含一个 `node` 字段，用于标识目标受众（例如关注者、客户或新客户）。通过用这些字段过滤搜索结果，我们可以帮助确保参考图像来自目标与目标受众相匹配的营销活动，从而保持营销方法的一致性。

```
{
    "mappings": {
        "properties": {
            "results": {"type": "float"},
            "node": {"type": "keyword"},
            "objective": {"type": "keyword"},
            "image_s3_uri": {"type": "text"},
            "image_description": {"type": "text"},
            "img_element_list": {"type": "text"},
            "embeddings": {
                "type": "knn_vector",
                "dimension": 1024,
                "method": {
                    "engine": "nmslib",
                    "space_type": "cosinesimil",
                    "name": "hnsw",
                    "parameters": {"ef_construction": 512, "m": 16}
                }
            }
        }
    }
}
```

完整的实现细节（包括索引设置和其他配置）请参阅我们的 [GitHub 仓库](https://github.com/aws-samples/generative-ai-ml-latam-samples/blob/main/blueprints/genai-marketing-campaigns/backend-img-indexing/pace_backend/oss_indexing_db/custom_resources/create_oss_embeddings_index/create_oss_embeddings_index.py)。

#### 索引参考图像

搜索索引就位后，我们现在可以用参考图像数据填充它。Lambda 函数 `IndexDataFunction` 负责该过程：它连接到 OpenSearch Serverless 索引，并把每张图像的向量 embedding 与其元数据（营销活动目标、目标受众、描述以及其他相关信息）一起存储。之后在创建新的营销活动时，我们可以用这些已建立索引的数据快速找到相关的参考图像。下面是一个简化实现，完整代码见我们的 [GitHub 仓库](https://github.com/aws-samples/generative-ai-ml-latam-samples/blob/main/blueprints/genai-marketing-campaigns/backend-img-indexing/pace_backend/index_imgs_workflow/index_data_fn/index.py)：

```
# Initialize the OpenSearch client
oss_client = OpenSearch(
    hosts=[{'host': OSS_HOST, 'port': 443}],
    http_auth=AWSV4SignerAuth(boto3.Session().get_credentials(), region, 'aoss'),
    use_ssl=True,
    verify_certs=True,
    connection_class=RequestsHttpConnection
)
# Prepare document for indexing
document = {
    "id": image_id,
    "node": metadata['node'],
    "objective": metadata['objective'],
    "image_s3_uri": s3_url,
    "image_description": description,
    "img_element_list": elements,
    "embeddings": embedding_vector
}
# Index document in OpenSearch
oss_response = oss_client.index(
    index=OSS_EMBEDDINGS_INDEX_NAME,
    body=document
)
```

### 把搜索引擎集成到营销活动图像生成器

图像生成 workflow 把营销活动需求与来自以往参考图像的洞察结合起来，创建新的营销视觉素材。该过程从用户通过 Web UI 发起新的营销活动开始。用户提供三项关键输入：所需营销活动的文本描述、其目标，以及其 node。利用这些输入，我们在 OpenSearch Serverless 中执行向量相似性搜索，从库中找出最相关的参考图像。对于这些被选中的图像，我们取回它们的描述（此前通过 Lambda 函数 `DescribeImgFunction` 生成），并把它纳入我们的 prompt 工程流程。由此得到的增强 prompt 作为生成新营销活动图像的基础，这些图像同时贴合两点：用户的需求和成功的参考范例。我们下面详细审视该过程的每一步。

#### 获取图像推荐

当用户定义新的营销活动描述时，Lambda 函数 `GetRecommendationsFunction` 使用 Amazon Titan Multimodal Embeddings 模型把它转换为向量 embedding。通过把营销活动描述转换到与图像库相同的向量空间，我们可以执行精确的相似性搜索，找出与营销活动目标和视觉需求高度吻合的参考图像。

该 Lambda 函数配置搜索参数，包括要取回的结果数量，以及 k-NN 算法的 `k` 值。在我们的示例实现中，我们把 `k` 设为 `5`，取回最相似的 5 张图像。可以调整这些参数，以在结果多样性与相关性之间取得平衡。

为帮助确保上下文相关性，我们应用过滤器来同时匹配新营销活动的 `node`（目标受众）和 `objective`。这种方法保证推荐图像不仅在视觉上相似，而且与营销活动的具体目标和目标受众保持一致。我们展示了搜索查询的简化实现，完整代码见我们的 [GitHub 仓库](https://github.com/aws-samples/generative-ai-ml-latam-samples/blob/main/blueprints/genai-marketing-campaigns/backend-img-generation/pace_backend/lambda/generate_recommendations_fn/index.py)。

```
body = {
    "size": k,
    "_source": {"exclude": ["embeddings"]},
    "query":
        {
            "knn":
                {
                    "embeddings": {
                        "vector": embedding,
                        "k": k,
                    }
                }
        },
    "post_filter": {
        "bool": {
            "filter": [
                {"term": {"node": node}},
                {"term": {"objective": objective}}
            ]
        }
    }
}
res = oss_client.search(index=OSS_EMBEDDINGS_INDEX_NAME, body=body)
```

该函数处理搜索结果，结果存储在 [Amazon DynamoDB](https://aws.amazon.com/dynamodb) 中，以维护营销活动与图像关联的持久记录，便于高效取回。用户可以通过 UI 访问这些推荐，并选择在创建新营销活动时使用哪些参考图像。

#### 用参考图像增强 meta-prompting 技术

prompt 生成阶段建立在我们[上一篇博文](https://aws.amazon.com/blogs/machine-learning/accelerating-your-marketing-ideation-with-generative-ai-part-1-from-idea-to-generation-with-the-amazon-nova-foundation-models/)介绍的 meta-prompting 技术之上。在沿用相同方法并使用 [Amazon Nova Pro 1.0](https://docs.aws.amazon.com/nova/latest/userguide/what-is-nova.html) 的同时，我们现在通过纳入用户所选参考图像的描述来增强这一流程。这些描述使用 XML 标签 `(<related_images>)` 整合进模板 prompt，如下例所示。

{json_schema}
```

prompt 生成由 Lambda 函数 `GeneratePromptFunction` 编排。该函数接收营销活动 ID 和所选参考图像的 URL，从 DynamoDB 取回它们的描述，并使用 [Amazon Nova Pro 1.0](https://docs.aws.amazon.com/nova/latest/userguide/what-is-nova.html) 按前面的模板创建优化后的 prompt。该 prompt 用于后续的图像生成阶段。该 Lambda 函数的代码实现见我们的 [GitHub 仓库](https://github.com/dlaredo/generative-ai-ml-latam-samples/tree/main/blueprints/genai-marketing-campaigns/backend-img-generation/pace_backend/lambda/generate_prompt_fn)。

#### 图像生成

在获得参考图像并生成增强 prompt 之后，我们使用 Lambda 函数 `GenerateNewImagesFunction` 创建新的营销活动图像。该函数使用 Amazon Nova Canvas 1.0 生成最终的视觉素材，其中融入了来自成功参考营销活动的洞察。其实现遵循我们在[上一篇博文](https://aws.amazon.com/blogs/machine-learning/accelerating-your-marketing-ideation-with-generative-ai-part-1-from-idea-to-generation-with-the-amazon-nova-foundation-models/)中详述的图像生成流程。完整的 Lambda 函数代码请参阅我们的 [GitHub 仓库](https://github.com/dlaredo/generative-ai-ml-latam-samples/tree/main/blueprints/genai-marketing-campaigns/backend-img-generation/pace_backend/lambda/generate_new_images_fn)。

为避免产生后续费用，你应当删除本方案中使用的所有资源。由于该方案是使用多个 [AWS CDK](https://docs.aws.amazon.com/cdk/v2/guide/home.html) 技术栈部署的，你应当按照部署的相反顺序删除它们，才能正确移除所有资源。请按以下步骤清理你的环境：

- 删除前端技术栈：

```
cd frontend
cdk destroy
```

- 删除图像生成后端技术栈：

```
cd ../backend-img-generation
cdk destroy
```

- 删除图像索引后端技术栈：

```
cd ../backend-img-indexing
cdk destroy
```

- 删除 OpenSearch 角色技术栈：

```
cd ../create-opensearch-roles
cdk destroy
```

`cdk destroy` 命令会自动移除大部分资源，但可能有些资源需要手动删除，例如内容非空的 S3 桶和 OpenSearch collection。请务必检查 AWS Management Console，确认所有资源都已正确移除。有关 `cdk destroy` 命令的更多信息，请参阅 [AWS CDK Command Line Reference](https://docs.aws.amazon.com/cdk/v2/guide/ref-cli-cmd-destroy.html)。
