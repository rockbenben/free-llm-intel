# xAI 的 Grok 4.6 现已在 Amazon Bedrock 中可用

今天，我们宣布 xAI 的 Grok 4.6 已在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 中可用，为 Bedrock 模型目录增添了一个专为长时间运行的 agent、编码与知识工作打造的前沿模型。Grok 4.6 于 2026 年 8 月 18 日在 Bedrock 上线。它提供 500K token 的上下文窗口，并支持四级可配置的 reasoning effort：low、medium、high 和 xhigh。

这是 xAI 在 Amazon Bedrock 中的第二个模型。在 [Grok 4.3 正式可用](https://aws.amazon.com/blogs/machine-learning/introducing-grok-on-amazon-bedrock/)时，xAI 作为模型供应商加入 Amazon Bedrock，该模型可通过 Bedrock Mantle（Amazon Bedrock 中兼容 OpenAI 的推理引擎）访问。Grok 4.6 大幅拓宽了这一接入面：它同时可在 bedrock-mantle 与 bedrock-runtime 端点上使用，并且除 Chat Completions 与 Responses 之外还支持 Converse API。

本文将介绍 xAI 对 Grok 4.6 设计目标的说明、它在 Amazon Bedrock 上的打包方式，以及如何发出第一个请求。

## Grok 4.6 的设计目标

本节的能力与训练细节均来自 xAI 的发布公告 [Introducing Grok 4.6](https://x.ai/news/grok-4-6)。

Grok 4.6 在 Grok 4.5 的基础上构建，特别关注长时间运行的 agent 以及更具雄心的交互与视觉工作。xAI 将该模型描述为能够跨越多个步骤持续处理复杂任务——无论是研究某个主题、分析信息、在代码库中开展工作，还是把一个想法变成打磨完善的应用程序或工作产物。

在训练方面，xAI 报告称本次补充训练运行比 Grok 4.5 更长，使用了为推理与高级技术概念而精选的模型生成数据、高质量工程数据，以及改进的优化器与训练配方。随后它用 Grok 4.5 重新生成了跨不同 reasoning effort、agent harness 以及 STEM、软件工程、知识工作等领域的监督微调轨迹，并通过基于模型的检查过滤掉有问题的轨迹。之后，模型在广泛的 agentic 强化学习任务上接受训练，涵盖知识工作、通用编码，以及内核优化、Web 开发、计算机辅助设计等特定领域环境。

xAI 特别指出的两种行为，对任何构建 agent 的人都值得注意。在更长的轨迹上，模型开始表现出更多的自测与验证行为，在继续推进之前先检查自己的工作。它在视觉与交互项目上的首轮产出也更强，能在一次迭代中就确立应用的结构与视觉语言；当通往好结果的最快路径是先做出一个足够完整的雏形再迭代时，xAI 团队发现这一点尤其有用。

在安全方面，xAI 表示 Grok 4.6 的防护措施已随模型能力提升而改进和校准，其支撑是该公司所称的、史上范围最广的能力与防护校准部署前测试套件，外加部署后测试与第三方测试。该公司将其安全栈定位为：在漏洞修补、加速工程设计周期、增强 AI 研究等领域的正当用例中，最大化效用与安全性。

## Grok 4.6 在 Bedrock 上新增的能力

有几项 Bedrock 能力是该模型新增的，而非沿用此前 Grok 发布时的能力。

**`bedrock-runtime` 端点。** 除 bedrock-mantle 之外，Grok 4.6 也在 bedrock-runtime 上提供服务，因此你可以用 AWS SDK 和标准的 Bedrock 控制面来访问它，而不必只依赖兼容 OpenAI 的客户端。

**Converse API，包括流式传输。** `converse` 与 `converse_stream` 均可用。这正是 runtime 支持带来的实际收益：跨模型统一的 message 结构，以及通过常规 Converse 事件（`messageStart`、`contentBlockDelta`、`contentBlockStop`、`messageStop`、`metadata`）实现流式传输，无需自行手写 server-sent events（SSE）解析。

**`xhigh` reasoning effort 级别。** effort 依次为 low、medium、high、xhigh，在高端扩展了取值范围，适用于那些值得多花 token 做更深一轮处理的问题。在 Converse 上，应通过 `additionalModelRequestFields={"reasoning_effort": "xhigh"}` 设置，而不是用 reasoning 参数。

**跨区域推理（Cross-Region inference）。** 在 bedrock-runtime 上，你通过两个 inference profile 之一进行路由，而不是固定到单一区域。当你有数据驻留要求时，us.xai.grok-4.6 会将流量限制在美国地理范围内；global.xai.grok-4.6 则在全球范围路由，以获得最广的容量池。Global 也是两者中更便宜的，每百万输入 token 为 $2.00，而另一种为 $2.20，因此在没有驻留约束的情况下，它通常是更好的默认选择。

**Amazon Bedrock Guardrails。** Grok 4.6 现在在其各 API 的 bedrock-runtime 上支持 Guardrails，为你提供内容过滤器、被拒绝主题、个人身份信息（PII）脱敏以及词语策略。你在请求中按 ID 与版本挂载 guardrail，策略会同时针对 prompt 与模型响应进行评估。对于 agentic 负载，这一点很重要，因为它为一个可能跨多个步骤无人值守运行的模型划定了统一的策略边界。

**调用日志（Invocation logging）。** 启用 model invocation logging 后，Grok 4.6 的调用会被完整记录为 Amazon CloudWatch 记录：请求体、响应体、包含 reasoning token 在内的 token 计数，以及所使用的 inference profile。在需要查看模型实际收到了什么请求的 agent 运行审计中很有用。

**Prompt caching。** 缓存输入的计费约为标准输入费率的四分之一，这对每一轮都要重发大段 system prompt 或文档的 agent 很重要。缓存作用于重复的前缀，因此要把稳定内容放在请求前部，并在 usage 块中读取缓存 token 数，确认折扣确实生效，再把它纳入成本模型。

此外还提供工具调用、结构化输出、图像输入、响应流式传输和加密 reasoning 内容，但这些能力自 Grok 4.3 发布时即已存在，并在那篇博文中有所介绍。

## Grok 4.6 在 Amazon Bedrock 上的打包方式

Grok 4.6 接受文本与图像输入并返回文本。不支持音频、语音、视频与 embedding 模态，也不生成图像。该模型可通过两个端点访问，且模型 ID 随所用端点不同而不同：

| **端点** | **模型 ID** | **Base URL** |
| --- | --- | --- |
| bedrock-mantle | `xai.grok-4.6` | https://bedrock-mantle.{region}.api.aws/openai/v1 |
| bedrock-runtime | `us.xai.grok-4.6`（Geo）或 `global.xai.grok-4.6`（Global） | https://bedrock-runtime.{region}.amazonaws.com/openai/v1 |

[![Amazon Bedrock 上通过 bedrock-mantle 与 bedrock-runtime 端点访问 Grok 4.6 的架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/09/17/ML-21784-1.png)](https://aws.amazon.com/blogs/machine-learning/xais-grok-4-6-is-now-available-in-amazon-bedrock/images/image1.png)

在 API 方面，Grok 4.6 支持 Responses API、Chat Completions API 与 Converse API。不支持 Invoke API。

各端点支持的功能不同，这一细节最有可能影响你的集成选择：

在 bedrock-mantle 上，受支持的功能包括客户端工具调用、reasoning、结构化输出、prompt caching、响应流式传输、projects 与滥用检测。

在 bedrock-runtime 上，受支持的功能包括 reasoning、prompt caching、响应流式传输、调用日志与 projects（仅默认 project）。该端点不支持结构化输出、服务端工具使用、intelligent prompt routing、count tokens 以及 application inference profile。

工具调用在两个端点上都能工作。模型返回一个结构化的函数请求，由你的代码执行，再把结果传回。在 bedrock-runtime 上，你可以通过 Converse 的 `toolConfig` 或兼容 OpenAI 的 `tools` 参数来驱动这一循环，因此依赖函数调用的 agent 并不局限于 bedrock-mantle。

如果你的应用依赖 JSON Schema 结构化输出，那就指向 bedrock-mantle。如果你需要 Converse API 或调用日志，那就指向 bedrock-runtime。

### 区域与推理选项

可用性因端点而异。在 bedrock-mantle 上，Grok 4.6 可在美国西部（俄勒冈）（us-west-2）进行区域内推理。在 bedrock-runtime 上则不提供区域内推理，而是通过跨区域 inference profile 调用模型。Geo 跨区域推理可从美国各区域（us-east-1、us-east-2、us-west-1 和 us-west-2）使用；Global 跨区域推理则有一份长得多的区域清单，覆盖美国、加拿大、欧洲、亚太、中东、非洲与南美。Geo 跨区域在地理范围内跨区域路由，同时遵守数据驻留要求；Global 跨区域在没有驻留约束时在全球范围任意路由。完整表格超过 30 个区域，因此在固定某个区域之前，请查阅模型卡与 [Regional availability by model](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html) 页面以获取当前清单。

与 Grok 4.3 发布时相比，这是一种形态上的变化：正如 [Grok 4.3 博文](https://aws.amazon.com/blogs/machine-learning/introducing-grok-on-amazon-bedrock/)所述，当时该模型仅使用区域内推理，并未提供 Geo 与 Global 跨区域推理。

### 服务层级与定价

Grok 4.6 支持三个服务层级。Standard 是按 token 付费、无承诺，通过设置 `"service_tier": "default"` 或省略该字段来选择。Priority 以溢价提供更快、优先的处理（`"service_tier": "priority"`）。Flex 为非时间敏感的工作提供更低成本的选择（`"service_tier": "flex"`）。关于各层级的按 token [定价](https://aws.amazon.com/bedrock/pricing/)，请参阅 Amazon Bedrock 定价页面。

另外两个层级按 Standard 费率的倍数定价：Priority 为 1.75 倍，即 75% 的溢价；Flex 为 0.5 倍，即 50% 的折扣。因此，同一负载在 Standard 区域内模式下每百万输入 token 花费 $2.20，在 Priority 下为 $3.85，在 Flex 下为 $1.10；这意味着选择层级比选择区域是更大的成本杠杆。

参考信息：xAI 列出的 Grok 4.6 定价为每百万输入 token 起价 $2、每百万输出 token 起价 $6，另有一个快速变体价格翻倍。请始终在 [Amazon Bedrock 定价页面](https://aws.amazon.com/bedrock/pricing/) 确认当前费率，因为价格与层级会变化。

## 发出你的第一个请求

在首次调用之前，请先在 Bedrock 控制台中确认该模型在你计划使用的区域对你可用。Grok 4.6 是通过 inference profile 而不是以裸模型 ID 的按需吞吐方式提供服务的，这就是在 bedrock-runtime 上的请求要写 `us.xai.grok-4.6` 或 `global.xai.grok-4.6` 的原因。

Grok 4.6 使用兼容 OpenAI 的 API，因此设置好 base URL 之后，OpenAI SDK 对任一端点都可用。安装该 SDK；如果打算使用 Converse API，也请安装 boto3：

```
pip install openai
pip install boto3
```

用于探索时，可在 Amazon Bedrock 控制台生成长期 Amazon Bedrock API key，然后设置环境变量。对于 bedrock-mantle：

```
export OPENAI_API_KEY="<provide your Bedrock API key>"
export OPENAI_BASE_URL="https://bedrock-mantle.us-west-2.api.aws/openai/v1"
```

对于 bedrock-runtime：

```
export OPENAI_API_KEY="<provide your Bedrock API key>"
export OPENAI_BASE_URL="https://bedrock-runtime.us-east-1.amazonaws.com/openai/v1"
```

在 bedrock-mantle 上使用 Chat Completions API 的第一个请求：

```
from openai import OpenAI

client = OpenAI()

response = client.chat.completions.create(
    model="xai.grok-4.6",
    messages=[
        {"role": "user", "content": "Can you explain the features of Amazon Bedrock?"}
    ],
)
print(response)
```

在 bedrock-runtime 上，区别在于模型名：你传入的是跨区域 inference profile，而不是裸模型 ID。本例还改用 Responses API 来展示这种形式：

```
from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="us.xai.grok-4.6",
    input="Can you explain the features of Amazon Bedrock?",
)
print(response)
```

再通过 Converse API 配合 boto3。由于 reasoning 处于激活状态，第一个 content block 承载 reasoning，答案位于更靠后的 block，因此请遍历各 block 查找文本，而不要直接索引 `content[0]`：

```
import boto3

client = boto3.client("bedrock-runtime", region_name="us-east-1")

response = client.converse(
    modelId="us.xai.grok-4.6",
    messages=[
        {"role": "user", "content": [{"text": "Can you explain the features of Amazon Bedrock?"}]}
    ],
    inferenceConfig={"maxTokens": 2048},
)

blocks = response["output"]["message"]["content"]
text = next(b["text"] for b in blocks if "text" in b)
print(text)
```

在 Converse 上，你通过 additionalModelRequestFields 设置 effort 级别，而不是用 reasoning 参数：

```
response = client.converse(
    modelId="us.xai.grok-4.6",
    messages=[{"role": "user", "content": [{"text": "What is 17*23? Number only."}]}],
    inferenceConfig={"maxTokens": 3000},
    additionalModelRequestFields={"reasoning_effort": "xhigh"},
)
```

三点运维提示。第一，在 bedrock-runtime 上，Grok 4.6 不提供区域内推理，因此请求必须指定 `us.xai.grok-4.6` 或 `global.xai.grok-4.6`。

第二，`bedrock:InvokeModel` 会针对三个资源进行评估：你账户的默认 project、你指定的 inference profile，以及底层基础模型。基础模型 ARN 在区域上使用通配符，因为跨区域 profile 会路由到调用区域之外。兼容 OpenAI 端点上的 bearer token 鉴权还额外需要 `bedrock:CallWithBearerToken`，而 boto3 与 Converse 不需要：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": "bedrock:InvokeModel",
            "Resource": [
                "arn:aws:bedrock:{region}:{account-id}:project/default",
                "arn:aws:bedrock:{region}:{account-id}:inference-profile/us.xai.grok-4.6",
                "arn:aws:bedrock:*::foundation-model/xai.grok-4.6"
            ]
        },
        {
            "Effect": "Allow",
            "Action": "bedrock:CallWithBearerToken",
            "Resource": "*"
        }
    ]
}
```

请列出你计划调用的每一个 inference profile。各 profile 单独授权，因此指定 `us.xai.grok-4.6` 的策略并不覆盖 `global.xai.grok-4.6`。

第三，两种鉴权机制覆盖不同的代码路径。`OPENAI_API_KEY` 中的 Amazon Bedrock API key 以 bearer token 形式传递，为两个端点上兼容 OpenAI 的调用提供鉴权。而 boto3 的 Converse 示例改用 SigV4 签名，取用来自环境、profile 或角色的普通 AWS 凭证。如果你打算在使用兼容 OpenAI 的 API 的同时也使用 Converse，请把两者都配置好。

请把长期 API key 只当作探索用途的凭证。生产环境中，Grok 4.3 发布博文建议使用由 IAM 凭证通过 `aws-bedrock-token-generator` 包生成的短期 bearer token，因为它们会自动过期，并使访问权限始终绑定到你的 IAM 身份；这一建议在这里同样适用。

## 使用 reasoning effort

在 Grok 4.6 上 reasoning 默认处于激活状态，你可以通过 reasoning 参数配置模型投入多少推理，取值为 low（默认）、medium、high 或 xhigh。相较于 Grok 4.3 发布博文所记载的内容，xhigh 级别是新增的——当时可用的级别为 none、low、medium 和 high。

reasoning 内容是加密的。你可以在 Responses API 请求中传入 `include: ["reasoning.encrypted_content"]` 让它被返回，然后在后续轮次把该内容传回，从而在多轮对话中把模型自己先前的 reasoning 作为上下文提供给模型。Chat Completions API 不返回 reasoning token。

加密 reasoning 是 Responses API 的特性，因此本例使用 OpenAI 客户端，而非上面 Converse 示例中的 boto3 客户端：

```
from openai import OpenAI

client = OpenAI()  # OPENAI_BASE_URL points at the bedrock-runtime endpoint

response = client.responses.create(
    model="us.xai.grok-4.6",
    reasoning={"effort": "high"},
    include=["reasoning.encrypted_content"],
    input="Explain quantum entanglement simply.",
)
print(response.output_text)
```

由于 reasoning 默认开启、而 effort 按请求设置，effort 级别是真正可用的成本与延迟控制手段。短的抽取与分类调用使用 low，把 high 或 xhigh 留给规划步骤和长时间 agent 轨迹——在那里早期的错误会不断累积。针对你自己的负载对各级 effort 做基准测试，是找出「更高的 reasoning 在哪里不再值得其 token 成本」的最快方法。

## 开始使用

Amazon Bedrock 上的 Grok 4.6 为你提供一个由 xAI 打造、面向长时间运行的 agent 与雄心勃勃的交互式工作的模型：500K token 上下文窗口、四个 reasoning effort 级别、图像输入、prompt caching，并可在兼容 OpenAI 的 bedrock-mantle 端点与支持 Converse API 及跨区域推理的 bedrock-runtime 端点之间选择。

要开始构建，请查阅 [Grok 4.6 模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-xai-grok-4-6.html) 了解当前区域清单、功能矩阵与参数细节，并查看 [Amazon Bedrock 定价页面](https://aws.amazon.com/bedrock/pricing/) 了解 token 费率。如果你为探索生成了长期 Amazon Bedrock API key，完成后请在 Amazon Bedrock 控制台中将其删除。一个你不再需要却仍长期有效的凭证，只会扩大你账户的暴露面。
