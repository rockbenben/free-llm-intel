# AWS SMGS 如何借助 Amazon Bedrock AgentCore 的 AI 对话助手变革业务管理

AWS 领导者要在多个层级上管理复杂数据，同时做出影响全球运营的时效性决策。传统的商业智能依赖静态仪表盘与人工报表，这造成了延迟，也限制了组织的敏捷性。

NarrateAI 是我们打造的智能对话式解决方案，它以对话式 agentic AI 应对这一挑战，而后者由我们的数据湖与 [**Amazon Bedrock AgentCore**](https://aws.amazon.com/bedrock/agentcore/) 共同驱动。NarrateAI 可通过 **[AWS Quick](https://aws.amazon.com/quick/)** 对话界面访问，为 AWS 各级领导者按需提供富含上下文的商业智能，覆盖范围从首席执行官（CEO）一直到一线团队。通过回答关于业务表现的自然语言问题，NarrateAI 提供即时、准确且可执行的洞察，消除领导者与其数据之间的障碍。

在本文中，我们分享如何用 **Amazon Bedrock AgentCore** 构建 NarrateAI，为 AWS SMGS（销售、营销与全球服务）组织大规模交付商业智能。你将了解到：

- 把批处理与实时交互分离的两层架构。
- 支撑智能路由与校验的专用 AI agent。
- 生产部署的关键工程模式。
- 如何用 AWS 服务构建类似的解决方案。

## 规模化的商业智能：主要障碍

AWS 曾面临一些挑战，限制了传统商业智能方法的效果：

**耗时的准备工作**：AWS 领导者过去常常在业务回顾之前花数小时手动汇总数据。准备过程涉及浏览多个仪表盘、对来自不同来源的数据进行核对，并人工综合洞察，留给战略思考与决策的时间所剩无几。

**数据碎片化**：业务洞察分散在多个系统和仪表盘中，领导者需要从碎片化的数据源中拼凑出连贯的叙述。这种碎片化导致指标不一致，也难以在各级组织和数据集之间维持统一的业务表现视图。

**可访问性有限**：复杂的仪表盘需要专业知识才能有效使用，从而形成对中间报表团队的依赖。领导者无法按需获取洞察，只能等待经过整理的报表，这延误了关键业务决策，也限制了组织敏捷性。

## 解决方案概述

NarrateAI 通过两层架构——批量叙述生成与实时交互——来应对让复杂业务数据可对话这一挑战。这种分离既能前置完成全面的数据处理，又能通过自然对话即时给出上下文准确的响应。

Amazon Bedrock AgentCore 免去了自建编排基础设施的需要，提供服务化架构、内置身份验证、记忆管理以及与基础模型的集成。这使我们的部署周期从数月缩短到数周，同时通过原生 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 集成和自动化的会话管理保持生产级的可观测性与安全性。

### 自动化叙述生成层（批处理）

NarrateAI 通过一个三阶段 pipeline 为每位用户批量生成基于 persona 的全面叙述：

- **数据抽取** — 由配置驱动的结构化查询语言（SQL）模板（按每位用户的角色与权限自适应调整的参数化查询）从 [Amazon Redshift](https://aws.amazon.com/redshift/) 中抽取结构化数据。这些模板支持多级细分与时间序列分析，同时强制执行用户特定的访问控制。
- **数据转换** — [AWS Lambda](https://aws.amazon.com/lambda/) 使用按区块类型组织的逻辑（对象、数组、细分与容器），配合字段映射与层级化组织，把抽取出的数据转换为结构化的 JavaScript 对象表示法（JSON）。
- **叙述渲染** — Jinja 模板（一种广泛使用的 Python 模板引擎）从结构化数据渲染出便于人阅读的叙述。一种层级化、能感知业务领域的切分策略可高效处理大数据集。系统把每位用户的叙述以文本文件形式存储在 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/) 中，通过完整的数据隔离支持行级安全。

### 对话式 AI 界面层（实时）

领导者通过由 Amazon Bedrock AgentCore 驱动的自然语言对话与其叙述交互。当问题到达时，AgentCore 编排专用 AI agent，从 Amazon S3 取回相关的 persona 叙述并将其作为知识来源。各 agent 对叙述内容进行推理，借助 Anthropic 的 Claude Sonnet 4 生成有上下文依据的响应。AgentCore 原生的多 agent 协同框架让系统能够即时处理简单查询。对于复杂问题，它会自动拆解为并行子任务，以给出全面的答案。

## 核心能力

这一架构基础支撑三项核心能力，改变了领导者与业务数据的交互方式。

### 基于预生成知识的自然语言业务查询

领导者用日常语言提出复杂的业务问题，并立即从存储在 Amazon S3 中的结构化知识获得响应。系统理解业务术语，并能在区域、产品、客户细分与时间段等维度上开展分析，具备上下文理解能力。

### 通过用户专属叙述内建行级安全

NarrateAI 在叙述生成阶段即应用行级安全，确保每位用户的知识引擎只包含其被授权的数据。用户权限在数据处理阶段即被应用，每位用户在 Amazon S3 中的叙述文件完全隔离，有助于防止组织内跨用户的数据泄露。

### 通过 persona 过滤实现贴合角色的体验

NarrateAI 根据用户角色和组织层级调整响应。CEO 获得覆盖整个组织的高层战略洞察，而区域经理获得其所在区域的详细运营指标。

这些能力由一套模块化架构支撑，该架构将专用 AI agent 与 AWS 服务相结合，以实现可扩展、智能的商业智能交付。

## 架构组件

我们的架构结合多项 AWS 服务与专用 AI agent，通过模块化、可扩展的设计交付智能、具备上下文感知的业务洞察。下图展示了端到端架构。

用户通过两个入口与 NarrateAI 交互：AWS Quick（一个对话界面）与 Web UI，二者都连接到 **Amazon Bedrock AgentCore Runtime** 进行请求处理。该架构有两条主要流程：实时查询路径（左侧）与批量数据处理路径（右侧）。

![NarrateAI 架构示意图，左侧为实时查询路径，右侧为批量数据处理路径，二者通过 Amazon Bedrock AgentCore Runtime 连接](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/26/ML-20454-1.png)

### NarrateAI agent（Strands agent）：查询处理流程

架构的中心是 NarrateAI Agent，它基于 Amazon Bedrock AgentCore 构建，用于多 agent 编排。一个 Supervisor Agent 通过六个专用工具协调端到端的查询工作流：

- **问题分类** — 当问题到达时，该工具分析用户意图并判断查询复杂度。简单查询（例如“我这个团队本季度的收入是多少？”）走快速路径立即得到答复。复杂的多部分问题（例如“比较我前 5 大客户在各产品线上的增长率”）会被自动拆解为并行子任务。
- **persona 知识定位** — 识别用户的角色、组织层级与数据权限，以确定从 Amazon S3 中取回哪个叙述文件。
- **知识抽取器** — 采用基于目录（TOC）的检索方式，只从用户叙述中取出相关章节，而不是扫描整个文件。即使叙述不断增长，检索仍能保持快速。
- **相关性评估器** — 对照用户的问题评估抽取出的内容，判断哪些章节最为相关，并过滤掉旁枝信息。
- **答案生成器** — 基于相关数据综合出连贯的自然语言响应，由通过 Amazon Bedrock 调用的 Anthropic Claude Sonnet 4 提供支持。
- **在线评估器** — 在交付前校验每一次响应：将生成的数字与源数据交叉比对、检查逻辑连贯性，并确认各项论述都能在用户叙述中找到依据。

响应时间因查询复杂度与底层数据源而异。

### 知识引擎：数据处理流程

架构图的右侧展示了业务数据如何为对话层做好准备：

- **数据接入** — 原始业务数据从 Amazon Redshift 及其他企业数据源流入知识引擎服务（Knowledge Engine Service）。
- **数据转换** — AWS Lambda 函数通过配置驱动的模板处理并转换数据，应用用户特定的权限与组织层级。
- **知识产物存储** — 处理后的数据以结构化的、按 persona 定制的叙述文件形式存储在 Amazon S3 中，用户之间数据完全隔离，以实现行级安全。
- **数据刷新** — Data Refresh Scheduler 自动执行周期性更新，使叙述反映最新的业务数据。

批量数据处理与实时查询处理之间的这种分离，让 NarrateAI 既能即时响应，又能保持底层数据最新、准确。

## 基础设施与 AI 基础

NarrateAI 构建在一组紧密集成的 AWS 服务之上，这些服务以可靠性、准确性与规模为目标。

**数据存储与处理** — 系统把业务数据作为结构化知识产物处理并存储在 Amazon S3 中。AWS Lambda 负责无服务器数据转换，Amazon Redshift 则作为底层数据仓库。一套自研检索系统采用目录（TOC）方式，无需扫描整个文件就能快速定位相关文档章节。即使知识引擎不断增长，这也能让响应保持快速。

**基础模型** — Amazon Bedrock 提供对领先基础模型的访问，包括 Anthropic 的 Claude Sonnet 4，它支撑 NarrateAI 的自然语言理解、复杂业务推理与响应生成。该服务的模型灵活性让我们无需改动架构即可测试并升级到更新的模型版本，随着更强模型的出现不断提升查询理解能力并缩短响应时间。

**安全与护栏** — Amazon Bedrock Guardrails 通过三个为 NarrateAI 用例量身定制、可自定义配置的过滤器来落实安全：

- **内容过滤** — 拦截不当或有害的语言。
- **PII 脱敏** — 帮助防止意外暴露敏感的个人可识别信息（PII）。
- **语气护栏** — 确保每一次响应都保持适合 AWS 领导层的专业口吻。

**agent 部署基础设施** — 我们使用 Amazon Bedrock AgentCore 作为基础编排层。AgentCore 提供全面的 agentic 能力，包括高级可观测性、身份提供方集成以及无服务器记忆管理。

**可观测性** — AgentCore Observability 提供对端到端 agent 会话执行的详细洞察，并通过与 Amazon CloudWatch 的集成支持监控与告警所需的完整运营可见性。AgentCore 内置的基于 OpenTelemetry 的可追踪能力提升了我们的调试效率。故障排查时间从数十分钟乃至数小时降至个位数分钟。

**记忆管理** — 我们把会话历史（短期记忆）从基于 Amazon DynamoDB 的自研方案迁移到 AgentCore 原生的记忆能力。这次迁移：

- 省去了维护自研会话管理代码的需要。
- 把记忆管理收敛到 AgentCore 的无服务器基础设施内，简化了我们的架构。
- 借助内置的会话处理，让功能开发更快。

## 面向生产的工程实践

基础设施就绪之后，要在规模上部署 NarrateAI，还需要解决每个生产级 AI 系统都必须应对的四个关键工程挑战。

第一个挑战是准确性与信任。AI 模型可能生成听上去正确但实际包含错误的答案，这对业务决策是严重的风险。为此，每一次响应在交付前都会被校验，检查数字是否准确、指标是否一致、答案在逻辑上是否站得住。该架构限制大语言模型（LLM）参与数值计算，以降低幻觉风险；自动化检查会在响应触达用户之前标记不当语言。

第二个挑战是跨组织层级的上下文感知。不同的领导者需要看到不同的数据。区域经理只应看到本区域的数字，而高管需要公司全局视图。系统会自动识别提问者是谁、他们被允许查看哪些数据，然后把每一次响应限定在其角色与汇报结构之内，无需手工设置过滤器。

第三个挑战是规模下的响应延迟。早期版本在复杂问题上出现明显的响应延迟，导致用户沮丧、采用率下降。系统现在按复杂度对问题分流。直截了当的查询快速作答，复杂的多部分问题通过并行处理完成。响应时间因用例、查询性质以及底层数据源而异。在数据接入阶段预先分析文档结构，进一步降低了每次查询的信息检索延迟。

最后，范围与主题覆盖需要格外注意。商业智能横跨多个领域（销售、财务、营销等），每个领域都有自己的术语和逻辑。团队与领域专家协作，通过标准化模板方法把机构知识编码进去，把过去需要数月定制开发的工作缩短到数周。

这项工作带来的关键经验是：要做到生产就绪，需要在 AI 的灵活性与基于规则的准确性之间取得平衡，在数据源头就落实数据访问控制，并针对最常见的用例做优化，同时可靠地处理复杂用例。

## 成果与影响

自部署以来，NarrateAI 在商业智能的可获取性与决策速度方面带来了可度量的改善：

- **超过 4,000 名活跃用户**，覆盖从 CEO 到区域经理的 AWS 领导层。
- **业务回顾的准备时间从数小时缩短到数分钟**。
- **全面的数据准确性校验**，通过确定性计算与 Online Evaluator Tool 检查实现。

领导者反馈，他们对数据驱动决策的信心增强了，也能通过自然对话而不是浏览仪表盘来探查业务表现。借助 **Amazon Bedrock AgentCore**，我们把工程运营从人工商业智能流程转变为 AI 驱动的自助服务枢纽。这一做法提升了效率，把回顾准备时间从数小时缩短到数分钟，并通过内置护栏与行级访问控制强化了安全与合规管控。

## 未来愿景：从被动响应到主动预判

NarrateAI 将从对话助手演进为自主 agent，在领导者提问之前主动交付洞察、暴露异常并建议行动。它将由业务日历、实时数据变化与组织上下文触发。借助增强的 Amazon Bedrock AgentCore 编排、事件驱动架构以及先进的多 agent 系统（知识 Agent、预测 Agent 与策略 Agent），该系统将交付预测性分析，并在完整的策略与审计层治理下执行安全、可解释的自主行动。这一演进使 NarrateAI 成为智能业务伙伴，能够预判需求并推动整个组织的主动决策。

## 结论

在本文中，我们展示了如何在 Amazon Bedrock AgentCore 上构建 NarrateAI，为整个 AWS SMGS 大规模交付对话式商业智能。我们介绍了把批量叙述生成与实时交互分离的两层架构、对每一次响应进行路由与校验的专用 agent，以及让解决方案达到生产就绪的工程模式。

你可以使用与我们解决方案相同的 AWS 服务来构建自己的对话式商业智能解决方案。[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 提供模块化服务，用于大规模构建、部署与运营 AI agent，并原生支持多 agent 编排、记忆管理与可观测性。[Amazon Redshift](https://aws.amazon.com/redshift/) 则是面向分析型负载的稳健数据仓库。

这里展示的架构模式可跨行业适用。其中包括：把检索准确性与生成灵活性结合起来的定制知识检索、支持在复杂知识库中智能导航的层级化文档处理、支持多租户环境下安全数据访问的基于角色的访问控制，以及在大规模下提供响应性能的并行 agent 处理。
