# 使用 RAG 构建基于生成式 AI 的 text-to-SQL 应用，由 Amazon Bedrock 提供支持（Claude 3 Sonnet 与用于 embedding 的 Amazon Titan）

SQL 是各企业广泛使用的关键语言之一，它要求理解数据库与表元数据。对于缺乏 SQL 熟练度的非技术用户来说，这可能令人无所适从。如今，[生成式 AI](https://aws.amazon.com/generative-ai/) 可以帮助非技术用户弥合这一知识鸿沟，通过 text-to-SQL 应用生成 SQL 查询。该应用允许用户以自然语言提出问题，然后针对用户的请求生成 SQL 查询。

[大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLM）经过训练，可以针对[自然语言指令](https://aws.amazon.com/what-is/nlp/#:~:text=Natural%20language%20processing%20(NLP)%20is,manipulate%2C%20and%20comprehend%20human%20language.)生成准确的 SQL 查询。然而，现成的 LLM 不经一些改造并不能直接使用。首先，LLM 无法访问企业数据库，模型需要经过定制才能理解某个企业的特定数据库。此外，由于列同义词与内部指标的存在，复杂性还会进一步增加。

LLM 在理解企业数据集与人类上下文方面的局限，可以通过[检索增强生成](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）来解决。本文探讨如何使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 借助 RAG 创建一个 text-to-SQL 应用。我们使用 [Anthropic 的 Claude 3.5 Sonnet](https://aws.amazon.com/bedrock/claude/) 模型生成 SQL 查询，使用 [Amazon Bedrock 中的 Amazon Titan](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html) 进行文本 embedding，并使用 Amazon Bedrock 访问这些模型。

Amazon Bedrock 是一项完全托管的服务，通过单一 API 提供来自 AI21 Labs、Anthropic、Cohere、Meta、Mistral AI、Stability AI 与 Amazon 等领先 AI 公司的高性能[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM）供你选择，并提供构建生成式 AI 应用所需的一整套能力，兼顾安全性、隐私与负责任的 AI。

## 方案概览

该方案主要基于以下服务：

- **基础模型** – 我们使用 Amazon Bedrock 上 Anthropic 的 Claude 3.5 Sonnet 作为 LLM，为用户输入生成 SQL 查询。
- **向量 embedding** – 我们使用 Amazon Bedrock 上的 [Amazon Titan Text Embeddings v2](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html) 进行 embedding。Embedding 是指为文本、图像与音频在向量空间中赋予数值表示的过程。Embedding 通常由[机器学习](https://aws.amazon.com/ai/machine-learning/)（ML）模型执行。下图提供了关于 embedding 的更多细节。![vector embeddings](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/10/ML-16850-Vector-Embeddings.png)
- **RAG** – 我们使用 RAG 为 FM 提供关于表 schema、列同义词与示例查询的更多上下文。RAG 是一个用于构建生成式 AI 应用的框架，可利用企业数据源与向量数据库来克服知识局限。RAG 的工作方式是使用检索器模块，针对用户的 prompt 从外部数据存储中找出相关信息。这些检索到的数据被用作上下文，与原始 prompt 结合，形成扩展后的 prompt 并传给 LLM。随后语言模型生成包含企业知识的 SQL 查询。下图展示了 RAG 框架。![RAG Framework](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/10/ML-16850-RAG.png)
- **Streamlit**** –** 这个开源 Python 库让为 ML 与数据科学创建并分享精美的自定义 Web 应用变得简单直接。你只需使用 Python，几分钟内就能构建强大的数据应用。

下图展示了该方案的架构。

![solution architecture](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/10/ML-16850-Solution-architect.jpg)

我们需要为企业专属数据库更新 LLM。这确保模型能够正确理解数据库，并生成贴合企业数据 schema 与表的回答。存储这些信息有多种文件格式可用，例如 JSON、PDF、TXT 与 YAML。在我们的场景中，我们创建 JSON 文件来存储表 schema、表描述、带同义词的列以及示例查询。JSON 天然结构化的格式，使表 schema、列定义、同义词与示例查询等复杂数据得以清晰、有条理地表示。这种结构便于在大多数编程语言中快速解析与操作数据，减少了对自定义解析逻辑的需求。

可能存在多个包含相似信息的表，这会降低模型的准确性。为提高准确性，我们根据 schema 将表归入四种不同类型，并创建四个 JSON 文件来存放不同的表。我们添加了一个包含四个选项的下拉菜单。每个选项代表这四类中的一类，并分别关联到各自的 JSON 文件。用户从下拉菜单中选定值后，相应的 JSON 文件会被传给 Amazon Titan Text Embeddings v2，它可以将文本转换为 embedding。这些 embedding 被存入向量数据库以便更快检索。

我们向 FM 添加了 prompt 模板，以界定模型的角色与职责。你还可以补充其他信息，例如应使用哪种 SQL 引擎来生成 SQL 查询。

当用户通过聊天输入框提供输入时，我们使用[相似度搜索](https://aws.amazon.com/blogs/big-data/amazon-opensearch-services-vector-database-capabilities-explained/)从向量数据库中为用户查询找出相关的表元数据。用户输入与相关的表元数据以及 prompt 模板结合，作为一个整体输入一起传给 FM。FM 基于最终输入生成 SQL 查询。

为了评估模型的准确性并追踪这一机制，我们将每一次用户输入与输出都存储在 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）中。

## 配置 LLM 并使用 Amazon Bedrock 初始化向量索引

按以下步骤创建一个名为 library.py 的 Python 文件：

- 添加以下 import 语句以引入必要的库：  `import boto3 # AWS SDK for Python from langchain_community.document_loaders import JSONLoader # Utility to load JSON files from langchain.llms import Bedrock # Large Language Model (LLM) from Anthropic from langchain_community.chat_models import BedrockChat # Chat interface for Bedrock LLM from langchain.embeddings import BedrockEmbeddings # Embeddings for Titan model from langchain.memory import ConversationBufferWindowMemory # Memory to store chat conversations from langchain.indexes import VectorstoreIndexCreator # Create vector indexes from langchain.vectorstores import FAISS # Vector store using FAISS library from langchain.text_splitter import RecursiveCharacterTextSplitter # Split text into chunks from langchain.chains import ConversationalRetrievalChain # Conversational retrieval chain from langchain.callbacks.manager import CallbackManager`
- 初始化 Amazon Bedrock 客户端并配置 [Anthropic 的 Claude 3.5](https://aws.amazon.com/bedrock/claude/)。你可以限制输出 token 的数量以优化成本：  `# Create a Boto3 client for Bedrock Runtime bedrock_runtime = boto3.client( service_name="bedrock-runtime", region_name="us-east-1" ) # Function to get the LLM (Large Language Model) def get_llm(): model_kwargs = { # Configuration for Anthropic model "max_tokens": 512, # Maximum number of tokens to generate "temperature": 0.2, # Sampling temperature for controlling randomness "top_k": 250, # Consider the top k tokens for sampling "top_p": 1, # Consider the top p probability tokens for sampling "stop_sequences": ["\n\nHuman:"] # Stop sequence for generation } # Create a callback manager with a default callback handler callback_manager = CallbackManager([]) llm = BedrockChat( model_id="anthropic.claude-3-5-sonnet-20240620-v1:0", # Set the foundation model model_kwargs=model_kwargs, # Pass the configuration to the model callback_manager=callback_manager ) return llm`
- 为给定的 schema 类型创建并返回索引。这种做法可以高效地筛选表，并为模型提供相关输入：  `# Function to load the schema file based on the schema type def load_schema_file(schema_type): if schema_type == 'Schema_Type_A': schema_file = "Table_Schema_A.json" # Path to Schema Type A elif schema_type == 'Schema_Type_B': schema_file = "Table_Schema_B.json" # Path to Schema Type B elif schema_type == 'Schema_Type_C': schema_file = "Table_Schema_C.json" # Path to Schema Type C return schema_file # Function to get the vector index for the given schema type def get_index(schema_type): embeddings = BedrockEmbeddings(model_id="amazon.titan-embed-text-v2:0", client=bedrock_runtime) # Initialize embeddings db_schema_loader = JSONLoader( file_path=load_schema_file(schema_type), # Load the schema file # file_path="Table_Schema_RP.json", # Uncomment to use a different file jq_schema='.', # Select the entire JSON content text_content=False) # Treat the content as text db_schema_text_splitter = RecursiveCharacterTextSplitter( # Create a text splitter separators=["separator"], # Split chunks at the "separator" string chunk_size=10000, # Divide into 10,000-character chunks chunk_overlap=100 # Allow 100 characters to overlap with previous chunk ) db_schema_index_creator = VectorstoreIndexCreator( vectorstore_cls=FAISS, # Use FAISS vector store embedding=embeddings, # Use the initialized embeddings text_splitter=db_schema_text_splitter # Use the text splitter ) db_index_from_loader = db_schema_index_creator.from_loaders([db_schema_loader]) # Create index from loader return db_index_from_loader`
- 使用以下函数创建并返回聊天会话的记忆：  `# Function to get the memory for storing chat conversations def get_memory(): memory = ConversationBufferWindowMemory(memory_key="chat_history", return_messages=True) # Create memory return memory`
- 使用以下 prompt 模板基于用户输入生成 SQL 查询：  `# Template for the question prompt template = """ Read table information from the context. Each table contains the following information: - Name: The name of the table - Description: A brief description of the table - Columns: The columns of the table, listed under the 'columns' key. Each column contains: - Name: The name of the column - Description: A brief description of the column - Type: The data type of the column - Synonyms: Optional synonyms for the column name - Sample Queries: Optional sample queries for the table, listed under the 'sample_data' key Given this structure, Your task is to provide the SQL query using Amazon Redshift syntax that would retrieve the data for following question. The produced query should be functional, efficient, and adhere to best practices in SQL query optimization. Question: {} """`
- 使用以下函数从 RAG 聊天模型获取回答：  `# Function to get the response from the conversational retrieval chain def get_rag_chat_response(input_text, memory, index): llm = get_llm() # Get the LLM conversation_with_retrieval = ConversationalRetrievalChain.from_llm( llm, index.vectorstore.as_retriever(), memory=memory, verbose=True) # Create conversational retrieval chain chat_response = conversation_with_retrieval.invoke({"question": template.format(input_text)}) # Invoke the chain return chat_response['answer'] # Return the answer`

## 为前端 UI 配置 Streamlit

- 初始化 S3 客户端：  `s3_client = boto3.client('s3') bucket_name = 'simplesql-logs-****' #replace the 'simplesql-logs-****’ with your S3 bucket name log_file_key = 'logs.xlsx'`
- 为 UI 配置 Streamlit：  `st.set_page_config(page_title="Your App Name") st.title("Your App Name") # Define the available menu items for the sidebar menu_items = ["Home", "How To", "Generate SQL Query"] # Create a sidebar menu using radio buttons selected_menu_item = st.sidebar.radio("Menu", menu_items) # Home page content if selected_menu_item == "Home": # Display introductory information about the application st.write("This application allows you to generate SQL queries from natural language input.") st.write("") st.write("**Get Started** by selecting the button Generate SQL Query !") st.write("") st.write("") st.write("**Disclaimer :**") st.write("- Model's response depends on user's input (prompt). - 生成查询：  `# SQL-AI page content elif selected_menu_item == "Generate SQL Query": # Define the available schema types for selection schema_types = ["Schema_Type_A", "Schema_Type_B", "Schema_Type_C"] schema_type = st.sidebar.selectbox("Select Schema Type", schema_types)`
- 使用以下代码完成 SQL 生成：  `if schema_type: # Initialize or retrieve conversation memory from session state if 'memory' not in st.session_state: st.session_state.memory = lib.get_memory() # Initialize or retrieve chat history from session state if 'chat_history' not in st.session_state: st.session_state.chat_history = [] # Initialize or update vector index based on selected schema type if 'vector_index' not in st.session_state or 'current_schema' not in st.session_state or st.session_state.current_schema != schema_type: with st.spinner("Indexing document..."): # Create a new index for the selected schema type st.session_state.vector_index = lib.get_index(schema_type) # Update the current schema in session state st.session_state.current_schema = schema_type # Display the chat history for message in st.session_state.chat_history: with st.chat_message(message["role"]): st.markdown(message["text"]) # Get user input through the chat interface, set the max limit to control the input tokens. input_text = st.chat_input("Chat with your bot here", max_chars=100) if input_text: # Display user input in the chat interface with st.chat_message("user"): st.markdown(input_text) # Add user input to the chat history st.session_state.chat_history.append({"role": "user", "text": input_text}) # Generate chatbot response using the RAG model chat_response = lib.get_rag_chat_response( input_text=input_text, memory=st.session_state.memory, index=st.session_state.vector_index ) # Display chatbot response in the chat interface with st.chat_message("assistant"): st.markdown(chat_response) # Add chatbot response to the chat history st.session_state.chat_history.append({"role": "assistant", "text": chat_response})`
- 将会话记录到 S3 存储桶：  `timestamp = datetime.now().strftime('%Y-%m-%d %H:%M:%S') try: # Attempt to download the existing log file from S3 log_file_obj = s3_client.get_object(Bucket=bucket_name, Key=log_file_key) log_file_content = log_file_obj['Body'].read() df = pd.read_excel(BytesIO(log_file_content)) except s3_client.exceptions.NoSuchKey: # If the log file doesn't exist, create a new DataFrame df = pd.DataFrame(columns=["User Input", "Model Output", "Timestamp", "Schema Type"]) # Create a new row with the current conversation data new_row = pd.DataFrame({ "User Input": [input_text], "Model Output": [chat_response], "Timestamp": [timestamp], "Schema Type": [schema_type] }) # Append the new row to the existing DataFrame df = pd.concat([df, new_row], ignore_index=True) # Prepare the updated DataFrame for S3 upload output = BytesIO() df.to_excel(output, index=False) output.seek(0) # Upload the updated log file to S3 s3_client.put_object(Body=output.getvalue(), Bucket=bucket_name, Key=log_file_key) `

## 故障排查提示

使用以下解决方案来处理错误：

**Error ** – 由推理端点抛出的错误意味着在调用 InvokeModel 操作时发生了错误（AccessDeniedException）。你没有使用指定模型 ID 访问该模型的权限。
**Solution** – 确保你对 Amazon Bedrock 中的 FM、Amazon Titan Text Embeddings v2 与 Anthropic 的 Claude 3.5 Sonnet 都拥有访问权限。

**Error** – app.py 不存在
**Solution** – 确保你的 JSON 文件与 Python 文件位于同一文件夹，并且你在同一文件夹中执行命令。

**Error** – No module named streamlit
**Solution** – 打开终端，运行以下命令安装 streamlit 模块：`pip install streamlit`

**Error** – 在调用 GetObject 操作时发生错误（NoSuchBucket）。指定的存储桶不存在。
**Solution** – 在 app.py 文件中核验你的存储桶名称，并根据你的 S3 存储桶名称更新该名称。

## 清理

清理你创建的资源以避免产生费用。要清理你的 S3 存储桶，请参阅[清空存储桶](https://docs.aws.amazon.com/AmazonS3/latest/userguide/empty-bucket.html)。
