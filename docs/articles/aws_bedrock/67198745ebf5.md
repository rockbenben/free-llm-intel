在本文中，我们从架构走向实现。我们向你展示如何在 [NVIDIA NeMo Agent Toolkit (NAT)](https://docs.nvidia.com/nemo/agent-toolkit/latest/index.html) 内部，把 Amazon S3 Vectors 用作持久记忆层，并将其部署到 [Amazon Elastic Kubernetes Service (Amazon EKS)](https://aws.amazon.com/eks/) 上以获得完全的运营控制。

读完本文，你会理解 NAT 的记忆子系统如何运作，以及如何把 Amazon S3 Vectors 实现为一个自定义记忆提供方。你还会学到如何在 Amazon EKS 上部署这套技术栈，并以一个多智能体投资研究用例作为贯穿始终的例子。

## 什么是 NVIDIA NeMo Agent Toolkit？

[NVIDIA NeMo Agent Toolkit (NAT)](https://docs.nvidia.com/nemo/agent-toolkit/latest/index.html) 是一个用于构建、剖析和优化 AI 智能体的开源框架。它框架无关，可与 Strands Agents、LangChain、LlamaIndex、CrewAI 及自定义实现协作。NAT 提供四项与生产智能体系统相关的能力：

- **智能体编排** – 把智能体定义为可组合的工作流，带有可配置的大语言模型（LLM）、工具和 prompt。你可以用 `nat run` 在本地运行，或用 `nat serve` 作为持久服务运行。
- **剖析** – 跨智能体和单个工具跟踪 token 用量、延迟、吞吐和运行时长，以识别多智能体工作流中的瓶颈。
- **评估** – 内置评估器，用于答案准确性、上下文相关性、响应接地（groundedness）和智能体轨迹，并支持自定义评估器。
- **优化** – 自动超参数调优（temperature、`top_p`、`max_tokens`），在最大化质量的同时最小化成本和延迟。

### NAT 的记忆模块

NAT 包含一个专门的记忆子系统，用于跨智能体调用存储和检索会话历史、用户偏好和长期知识。记忆模块是可扩展的：你通过实现 NAT 的插件接口来创建自定义记忆提供方（后端）。关键组件包括：

- **`MemoryEditor`** – 所有记忆后端都必须实现的抽象接口。它定义了三个方法：`add_items()`、`search()` 和 `remove_items()`。
- **`MemoryItem`** – 表示一条记忆的数据模型，含有会话历史、标签、元数据、`user_id` 和一个可选的文本记忆字符串等字段。
- **`MemoryBaseConfig`** – 一个 Pydantic 基类，自定义记忆配置继承它。NAT 通过其 YAML 配置中的 `_type` 字段发现提供方。
- **自动记忆包装器** – `auto_memory_agent` 工作流类型，它给智能体包裹上自动记忆捕获与检索，而无需 LLM 显式调用记忆工具。

NAT 目前有以下内置记忆提供方：Mem0、MemMachine、Redis 和 Zep。它们覆盖了常见用例。然而，对于需要弹性向量存储、强写入一致性和向数十亿向量经济扩展的生产多智能体系统，一个由 Amazon S3 Vectors 支撑的自定义提供方才是合适的选择。

## 为什么用 Amazon S3 Vectors 作为持久记忆后端

[Building persistent memory for multi-agent AI systems with Amazon S3 Vectors](https://aws.amazon.com/blogs/storage/building-persistent-memory-for-multi-agent-ai-systems-with-amazon-s3-vectors/) 深入讲解了架构层面的理由。下表总结了使 S3 Vectors 适合 NAT 记忆层的各项属性：

| 需求 | S3 Vectors 能力 |
| --- | --- |
| 语义检索 | 带可配置距离度量（余弦、欧氏）的向量相似度搜索 |
| 作用域查询 | 每个向量上可过滤的元数据（字符串、数字、布尔、列表） |
| 多智能体协调 | 强写入一致性。记忆在插入后立即可见 |
| 规模 | 每个索引最多 20 亿向量，无需容量规划 |
| 成本效率 | 只为存储、写入和查询付费，没有空闲计算 |
| 访问控制 | 每个桶和索引的 AWS Identity and Access Management (IAM) 策略。每租户索引实现硬隔离 |

## 步骤 1. 创建 Amazon S3 Vectors 基础设施

下面的代码创建一个向量桶和一个索引，其元数据架构为智能体记忆而设计。索引使用 1024 维以匹配 Amazon Titan Text Embeddings V2 的输出，并把大内容字段标记为不可过滤的元数据：

```
import boto3

REGION = "us-west-2"
VECTOR_BUCKET = "amzn-s3-demo-research-agent-memory"
INDEX_NAME = "agent-long-term-memory"

s3vectors = boto3.client("s3vectors", region_name=REGION)

# Create the vector bucket
s3vectors.create_vector_bucket(vectorBucketName=VECTOR_BUCKET)

# Create the index (1024 dimensions matches Amazon Titan Text Embeddings V2)
s3vectors.create_index(
    vectorBucketName=VECTOR_BUCKET,
    indexName=INDEX_NAME,
    dataType="float32",
    dimension=1024,
    distanceMetric="cosine",
    metadataConfiguration={"nonFilterableMetadataKeys": ["content"]},
)
```

创建桶和索引后，你就可以实现读写它们的记忆提供方了。

## 步骤 2. 实现一个自定义 MemoryEditor 插件

下面的代码把 `MemoryEditor` 接口实现为一个 Amazon S3 Vectors 后端，并注册它以便 NAT 能发现它：

```
import boto3
import json
import uuid
from datetime import datetime, timezone
from nat.plugin_api import MemoryBaseConfig, MemoryEditor, MemoryItem, register_memory
from nat.builder.builder import Builder


class S3VectorsMemoryConfig(MemoryBaseConfig, name="s3vectors_memory"):
    """NAT memory provider configuration for Amazon S3 Vectors."""
    vector_bucket: str
    index_name: str
    aws_region: str = "us-west-2"
    default_top_k: int = 5


class S3VectorsMemoryEditor(MemoryEditor):
    """NAT MemoryEditor backed by Amazon S3 Vectors."""

    def __init__(self, config: S3VectorsMemoryConfig):
        self._vector_bucket = config.vector_bucket
        self._index_name = config.index_name
        self._default_top_k = config.default_top_k
        self._s3vectors = boto3.client('s3vectors', region_name=config.aws_region)
        self._bedrock = boto3.client('bedrock-runtime', region_name=config.aws_region)

    def _get_embedding(self, text: str) -> list[float]:
        """Generate embeddings using Amazon Titan Text Embeddings V2."""
        response = self._bedrock.invoke_model(
            modelId='amazon.titan-embed-text-v2:0',
            contentType='application/json',
            accept='application/json',
            body=json.dumps({
                'inputText': text,
                'dimensions': 1024,
                'normalize': True
            })
        )
        return json.loads(response['body'].read())['embedding']

    async def add_items(self, items: list[MemoryItem], **kwargs) -> None:
        """Store memory items as vectors in Amazon S3 Vectors."""
        vectors = []
        for item in items:
            # Build the text to embed from the memory content
            text = item.memory or json.dumps(item.conversation)
            embedding = self._get_embedding(text)
            # Use uuid4 to prevent key collisions within the same second
            key = f"mem_{item.user_id}_{uuid.uuid4().hex[:12]}"
            # Note: S3 Vectors metadata values have size limits.
            # Truncate content to 1024 characters for production use.
            content_for_metadata = text[:1024]
            mem_metadata = {
                'user_id': item.user_id,
                'memory_type': item.metadata.get('memory_type', 'episodic'),
                'agent_id': item.metadata.get('agent_id', ''),
                'team_id': item.metadata.get('team_id', ''),
                'task_id': item.metadata.get('task_id', ''),
                'confidence': item.metadata.get('confidence', 0.8),
                'created_at_epoch': int(datetime.now(timezone.utc).timestamp()),
                'is_shared': item.metadata.get('is_shared', True),
                'source': item.metadata.get('source', 'agent'),
                'content': content_for_metadata,
            }
            # Add domain-specific metadata if present
            if 'ticker' in item.metadata:
                mem_metadata['ticker'] = item.metadata['ticker']
            vectors.append({
                'key': key,
                'data': {'float32': embedding},
                'metadata': mem_metadata
            })
        self._s3vectors.put_vectors(
            vectorBucketName=self._vector_bucket,
            indexName=self._index_name,
            vectors=vectors
        )

    async def search(self, query: str, top_k: int = None, **kwargs) -> list[MemoryItem]:
        """Retrieve semantically relevant memories from Amazon S3 Vectors."""
        query_embedding = self._get_embedding(query)
        effective_top_k = top_k or self._default_top_k
        # Build metadata filter from kwargs
        filter_expr = {}
        for field in ('agent_id', 'memory_type', 'ticker', 'team_id', 'user_id'):
            if field in kwargs:
                filter_expr[field] = {'$eq': kwargs[field]}
        # Support boolean filter for is_shared
        if 'is_shared' in kwargs:
            filter_expr['is_shared'] = {'$eq': kwargs['is_shared']}
        response = self._s3vectors.query_vectors(
            vectorBucketName=self._vector_bucket,
            indexName=self._index_name,
            queryVector={'float32': query_embedding},
            topK=effective_top_k,
            filter=filter_expr if filter_expr else None,
            returnMetadata=True
        )
        results = []
        for vec in response.get('vectors', []):
            results.append(MemoryItem(
                conversation=[],
                tags=[vec['metadata'].get('memory_type', '')],
                metadata=vec['metadata'],
                user_id=vec['metadata'].get('user_id', ''),
                memory=vec['metadata'].get('content', '')
            ))
        return results

    async def remove_items(self, **kwargs) -> None:
        """Remove memory items from Amazon S3 Vectors."""
        keys = kwargs.get('keys', [])
        if keys:
            self._s3vectors.delete_vectors(
                vectorBucketName=self._vector_bucket,
                indexName=self._index_name,
                keys=keys
            )


# Register the memory provider so NAT can discover it
@register_memory(config_type=S3VectorsMemoryConfig)
async def build_s3vectors_memory(config: S3VectorsMemoryConfig, builder: Builder):
    yield S3VectorsMemoryEditor(config)
```

该插件用 Amazon Titan Text Embeddings V2 生成嵌入，把每条记忆存储为一个带作用域元数据的向量，并把搜索过滤条件翻译为 Amazon S3 Vectors 的元数据查询。

## 步骤 3. 配置 NAT 智能体工作流

定义好插件后，在 NAT 的 YAML 配置中配置它，并把它接入一个智能体工作流：

```
# config.yml - NAT agent configuration with Amazon S3 Vectors memory
memory:
  agent_memory:
    _type: s3vectors_memory
    vector_bucket: "amzn-s3-demo-research-agent-memory"
    index_name: "agent-long-term-memory"
    aws_region: "us-west-2"

functions:
  add_memory:
    _type: add_memory
    memory: agent_memory
    description: |
      Store important findings, patterns, or facts to long-term memory.
      Use this after discovering new information during research.
  get_memory:
    _type: get_memory
    memory: agent_memory
    description: |
      Retrieve relevant prior knowledge before starting research.
      Query with the current research topic to recall related findings.
  web_search:
    _type: web_search
  financial_data:
    _type: financial_data_api

workflow:
  _type: auto_memory_agent
  inner_agent_name: research_agent
  memory_name: agent_memory
  llm_name: bedrock_llm
  save_user_messages_to_memory: true
  retrieve_memory_for_every_response: true
  save_ai_messages_to_memory: true

llm:
  bedrock_llm:
    _type: bedrock
    model_id: "anthropic.claude-sonnet-4-20250514"
    temperature: 0.3
```

有了 `auto_memory_agent` 包装器，你可以自动捕获和检索记忆。用户消息和智能体响应会被存储，而相关上下文会在每次智能体调用前注入。这一设计免去了 LLM 显式调用记忆工具的需要。

## 负责任的 AI 与数据处理考量

因为这套方案会持久化会话历史和用户记忆，请规划这些数据如何被保留和访问。为存储的记忆设置一个保留策略，并使用本文中的记忆合并与移除路径来让你不再需要的数据过期。避免在记忆元数据中存储可识别个人身份信息（PII），并在嵌入敏感字段前先脱敏或标记化它们。用每租户索引和最小权限 IAM 策略限定访问范围，使每个智能体只读写它自己拥有的记忆。

## 将 Amazon S3 Vectors 付诸实践：多智能体投资研究

下面的用例演示了这一模式在实践中。考虑三个专用智能体在一个投资研究工具上协作：

- **研究智能体** – 收集市场数据、财报和新闻。
- **分析智能体** – 执行定量分析并识别模式。
- **综合智能体** – 产出结合两个智能体发现的报告。

有了持久记忆，每个智能体都在先前工作之上构建。研究智能体回忆先前收集的数据，避免冗余的 API 调用。分析智能体在此前会话中识别的模式之上构建。综合智能体访问累积的发现，以产出逐渐更丰富的报告。

### 多智能体记忆协调

每个智能体使用同一个 S3 Vectors 索引，但在元数据中用自己的 `agent_id` 写入。智能体用元数据过滤来检索共享知识：

```
# Analysis Agent retrieves Research Agent's shared findings
research_findings = await memory_client.search(
    query=f"Recent research findings for {ticker}",
    top_k=10,
    team_id='investment-research',
    is_shared=True
)

# Synthesis Agent queries all team knowledge
all_team_knowledge = await memory_client.search(
    query=f"Complete analysis and research for {ticker} Q2 2026",
    top_k=20,
    team_id='investment-research'
)
```

NAT 内建的多租户记忆隔离用 `user_id` 按用户限定记忆范围。对于多智能体的团队协调，`team_id` 元数据字段在同一个 S3 Vectors 索引内提供一个额外的分组维度。

### 记忆合并

随着时间推移，情景记忆会累积。周期性地把它们合并成语义记忆（泛化的知识）能让检索保持精准高效。你可以通过一个定时的 cron 作业、一个向量计数阈值，或在若干研究周期后一个由智能体发起的信号来触发合并：

```
async def consolidate_memories(ticker: str, memory_client, workflow):
    """Distill episodic memories into durable semantic knowledge."""
    episodes = await memory_client.search(
        query=f"All findings about {ticker}",
        top_k=50,
        memory_type='episodic',
        ticker=ticker
    )
    episode_texts = [e.memory for e in episodes if e.memory]
    consolidation_prompt = f"""Given these {len(episode_texts)} observations
about {ticker}, identify durable patterns and generalized knowledge.

{chr(10).join(episode_texts)}

Return a JSON array of insight strings. Do not include specific dates
or one-time events."""
    response = await workflow.run(consolidation_prompt)
    # Parse the response into a list of insights
    insights = json.loads(response)
    # Store each consolidated insight as semantic memory
    await memory_client.add_items([
        MemoryItem(
            conversation=[],
            tags=['semantic'],
            metadata={
                'memory_type': 'semantic',
                'confidence': 0.9,
                'ticker': ticker,
                'source': 'consolidation',
                'is_shared': True,
                'team_id': 'investment-research'
            },
            user_id='system',
            memory=insight
        )
        for insight in insights
    ])
```

## 在 Amazon EKS 上部署智能体工作负载

对于需要完全运营控制其智能体工作负载的团队，Amazon EKS 是一个刻意的选择。有了 Amazon EKS，你控制伸缩、网络和生命周期管理，并原生地用 AWS Identity and Access Management (IAM) 集成以访问 Amazon S3 Vectors。如果你更偏好完全托管的运行时，Amazon Bedrock AgentCore 提供了一个托管替代方案，消除了这些运营开销。你用 `nat serve` 把 NAT 智能体作为容器化服务运行。每种智能体类型都是一个 Kubernetes Deployment，其 IAM 访问通过 [IAM Roles for Service Accounts (IRSA)](https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html) 授予。

WORKDIR /app
CMD ["nat", "serve", "--config_file", "config.yml"]

### 用于 S3 Vectors 访问的 IAM 策略

下面的 IAM 策略授予对记忆层的限定访问。通过 IRSA 把它附加到与 `agent-sa` service account 关联的 IAM 角色：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "s3vectors:PutVectors",
                "s3vectors:QueryVectors",
                "s3vectors:GetVectors",
                "s3vectors:DeleteVectors"
            ],
            "Resource": "arn:aws:s3vectors:us-west-2:${ACCOUNT_ID}:vector-bucket/amzn-s3-demo-research-agent-memory/*"
        }
    ]
}
```

## 评估记忆的影响

借助 NAT 的评估工具（`nat eval`），你可以量化记忆对智能体性能的影响。配置两个评估运行：一个启用记忆、一个不启用，使用同一数据集：

```
# Evaluate with memory enabled
nat eval --config_file config_with_memory.yml \
  --dataset eval_dataset.jsonl \
  --metrics accuracy,groundedness,token_usage,latency

# Evaluate without memory (baseline)
nat eval --config_file config_no_memory.yml \
  --dataset eval_dataset.jsonl \
  --metrics accuracy,groundedness,token_usage,latency
```

基于这一设计的架构属性，在比较这些运行时你可以期待以下定性结果。这些是方向性的预期，而非经基准测试的测量：

- **接地性提升** – 召回的记忆提供可验证的来源上下文，智能体可以引用它，而不只依赖参数化知识。
- **token 用量下降** – 智能体跳过重新推导那些在先前会话中已确立的事实。下降幅度随你的工作流涉及多少重复上下文而扩展。
- **延迟略微上升** – 每次记忆召回增加一次 S3 Vectors 查询（标准访问模式下为亚秒级），通常只占整体 LLM 推理时间的一小部分。
- **重复工作减少** – 有了共享记忆，智能体避免重复队友已完成的调研或分析。

这些影响的幅度取决于你的工作负载：跨会话复用多少上下文、有多少智能体协调、以及你的检索预算（top-k）有多大。NAT 的超参数优化器能系统地调 `top_k` 和相似度阈值，为你的用例找到最优的成本-质量权衡。

## 结论

本文展示了如何实现一个由 Amazon S3 Vectors 支撑的自定义 NAT 记忆提供方并把它部署到 Amazon EKS 上。关键的构建块：

- **NAT 的 `MemoryEditor` 接口**为自定义记忆后端提供插件契约。
- `auto_memory_agent` 包装器自动处理捕获与检索。
- **Amazon S3 Vectors** 提供持久、可语义查询、带强一致性以供多智能体协调的后端。
- **Amazon EKS** 让你对智能体生命周期、伸缩和网络隔离拥有完全的运营控制。

这些模式适用于智能体能从累积知识中获益的领域，包括把记忆分为情景、语义或程序性来归类、通过元数据过滤在智能体间共享记忆，以及用 LLM 合并记忆。例子包括客户支持、DevOps 自动化、法律研究和科学发现。

要查看贯穿本文所引用的记忆架构基础，参见 [Building persistent memory for multi-agent AI systems with Amazon S3 Vectors](https://aws.amazon.com/blogs/storage/building-persistent-memory-for-multi-agent-ai-systems-with-amazon-s3-vectors/)。要开始使用 NAT，参见 [NVIDIA NeMo Agent Toolkit 文档](https://docs.nvidia.com/nemo/agent-toolkit/latest/)和 [Adding a Memory Provider 指南](https://docs.nvidia.com/nemo/agent-toolkit/latest/)。
