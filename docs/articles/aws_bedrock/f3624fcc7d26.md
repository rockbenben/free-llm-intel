# Amazon Bedrock 宣布多 agent 协作正式可用

今天，我们宣布 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的 [multi-agent collaboration](https://aws.amazon.com/bedrock/agents/)（多 agent 协作）正式可用（GA）。这项能力让开发者能够构建、部署和管理协同工作的 AI agent 网络，从而高效执行复杂的多步骤工作流。

自 2024 年 re:Invent 大会预览发布以来，金融服务、医疗健康、供应链与物流、制造业和客户支持等各行各业的组织都在使用多 agent 协作来编排专用 agent，从而提升效率、准确性和自动化水平。在此次正式可用版本中，我们根据客户反馈引入了一系列增强功能，进一步完善了可扩展性、可观测性和灵活性，让 AI 驱动的工作流更易于管理和优化。

## 什么是多 agent 协作？

生成式 AI 不再只是模型生成回答，而是关乎自动化。下一波创新浪潮由能够在企业各系统之间自主推理、规划和行动的 agent 驱动。生成式 AI 应用不再只是生成内容，它们还会采取行动、解决问题并执行复杂工作流。这一转变的方向很明确：企业需要的 AI 不只是响应 prompt，还要编排整个工作流，端到端地实现流程自动化。

agent 让生成式 AI 应用能够跨企业系统和数据源执行任务，而 Amazon Bedrock 已经简化了构建 agent 的过程。借助 Amazon Bedrock，客户可以快速创建处理销售订单、编制财务报告、分析客户留存率等各种任务的 agent。然而，随着应用能力不断增强，客户希望它们执行的任务可能超出单个 agent 的处理范围——原因可能是任务需要专业化的知识、涉及多个步骤，或者需要长时间持续执行。

在规模上协调可能多达数百个 agent 同样具有挑战性，因为在庞大的专用 agent 网络中管理依赖关系、确保高效的任务分发并维持性能，需要精巧的编排能力。如果没有合适的工具，企业会遭遇效率低下、延迟增加以及难以监控和优化性能等问题。对于希望进阶 agent 能力、处理更复杂多步骤工作流的客户，Amazon Bedrock 支持多 agent 协作，让开发者能够轻松构建、部署和管理多个无缝协作的专用 agent。

[多 agent 协作](https://aws.amazon.com/bedrock/agents/)让开发者能够创建专用 agent 网络，这些 agent 在 supervisor agent 的指导下相互通信与协调。每个 agent 专注于特定任务，从而为更大的工作流贡献自己的专业能力。这种方法把复杂流程拆解为可并行处理的、可管理的子任务。通过促成 agent 之间的无缝交互，[Amazon Bedrock](https://aws.amazon.com/bedrock/) 提升了运营效率与准确性，确保工作流在规模上更有效地运行。由于每个 agent 只访问其角色所需的数据，这种方法在强化安全与治理的同时，把敏感信息的暴露降到最低。这使企业能够扩展其 AI 驱动的工作流，而无需人工介入 agent 协调。随着 agent 数量增加，supervisor 确保它们之间顺畅协作。

通过在 Amazon Bedrock 上使用多 agent 协作，组织可以：

- 通过将工作负载分发到各个专用 agent，精简 AI 驱动的工作流。
- 通过在可能的情况下并行执行任务，提升执行效率。
- 通过将 agent 的访问限制在必要数据范围内，强化安全与治理。
- 通过消除 agent 协调中的人工介入，降低运营复杂性。

构建高效[多 agent 协作](https://aws.amazon.com/bedrock/agents/)系统的一项关键挑战，是管理在规模上协调多个专用 agent 的复杂性与开销。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 简化了构建、部署和编排高效多 agent 协作系统的过程，同时通过若干关键特性与优化来应对效率挑战：

- **快速设置** – 几分钟内即可创建、部署和管理协同工作的 AI agent，无需复杂的编码。
- **可组合性** – 把现有 agent 作为 subagent 集成到更大的 agent 系统中，让它们无缝协作以处理复杂工作流。
- **高效的 agent 间通信** – supervisor agent 可以使用一致的接口与 subagent 交互，并支持并行通信，从而更高效地完成任务。
- **优化的协作模式** – 可在 supervisor 模式和带路由的 supervisor 模式之间选择。在路由模式下，supervisor agent 会把简单请求直接路由给专用 subagent，跳过完整的编排流程。对于复杂查询，或在未检测到明确意图时，它会自动回退到完整的 supervisor 模式，由 supervisor agent 分析并拆解问题，按需协调多个 subagent。
- **集成的跟踪与调试控制台** – 使用集成的 trace 与 debug 控制台，可视化并分析多 agent 交互的背后过程。

## 正式可用版本有哪些新内容？

正式可用版本根据客户反馈引入了若干关键增强，使多 agent 协作更具可扩展性、灵活性和效率：

- **内联 agent 支持** – 能够在运行时动态创建 supervisor agent，从而在无需预定义结构的情况下实现更灵活的 agent 管理。
- [AWS CloudFormation](https://aws.amazon.com/cloudformation)** 与 **[AWS Cloud Development Kit (AWS CDK)](https://aws.amazon.com/cdk)** 支持 **– 使客户能够以代码方式部署 agent 网络，在 AWS 账户之间提供可扩展、可复用的 agent 模板。
- **增强的可追溯性与调试能力** – 提供结构化执行日志、子步骤跟踪以及与 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 的集成，以改进监控和故障排查。
- **提高协作者与步骤数量上限** – 扩大了 agent 协作者与执行步骤的自助服务上限，支持更大规模的工作流。
- **payload 引用** – 允许 supervisor agent 引用外部数据源，而无需把它们嵌入 agent 请求中，从而降低延迟和成本。
- **改进的引用处理** – 在 agent 将外部数据源引入回答时，提升准确性和归属标注。

这些特性共同提升了多 agent 协作框架在应对复杂现实问题时的协调能力、通信速度和整体效果。

## 跨行业的多 agent 协作

多 agent 协作已经在改变各行各业的 AI 自动化：

- **投资顾问** – 一家金融机构使用多个 agent 分析市场趋势、风险因素和投资机会，为客户提供个性化的建议。
- **零售运营** – 一家零售商部署 agent 用于需求预测、库存跟踪、定价优化和订单履行，以提升运营效率。
- **欺诈检测** – 一家银行机构指派 agent 实时监控交易、检测异常、验证客户行为并标记潜在的欺诈风险。
- **客户支持** – 一个企业客户服务平台使用 agent 进行情感分析、工单分类、知识库检索和自动回复，以缩短解决时长。
- **医疗诊断** – 一个医院系统集成 agent 用于病历分析、症状识别、医学影像审阅和治疗方案建议，以协助临床医生。

## 深入剖析：Syngenta 如何使用多 agent 协作

[Syngenta](https://www.syngenta-us.com/) 是农业创新领域的全球领军企业，它把前沿的生成式 AI 集成到其 Cropwise 服务中，由此开发出 [Cropwise AI](https://www.cropwise.com/)。这一先进系统旨在为农艺顾问和种植者提供针对作物管理实践的定制化建议，从而提升他们的效率。

### **业务挑战**

农业领域面临着在保证可持续性与盈利性的同时优化作物产量的复杂任务。农民和农艺顾问必须考虑众多因素，包括天气模式、土壤条件、作物生长阶段以及潜在的病虫害威胁。过去，分析这些变量需要大量的人工投入和专业知识。Syngenta 认识到，需要一种更高效、由数据驱动的方法来支持作物管理中的决策。

### **解决方案：Cropwise AI**

为应对这些挑战，Syngenta 与 AWS 合作开发了 Cropwise AI，使用 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents) 构建了一个集成多种数据源与 AI 能力的多 agent 系统。该系统提供若干关键特性：

- **先进的种子推荐与布局** – 使用预测性机器学习算法，为每位种植者的独特环境提供个性化的种子推荐。
- **精密的预测建模** – 采用最先进的机器学习算法，通过把实时数据与全面的历史信息相结合，预测作物生长模式、产量潜力和潜在风险因素。
- **精准农业优化** – 为投入品施用提供高度本地化、针对具体地块的建议，最大限度地减少浪费并提升资源效率。

### **agent 架构**

Cropwise AI 构建在 AWS 架构之上，在设计上兼顾可扩展性、可维护性和安全性。该系统使用 Amazon Bedrock Agents 编排多个 AI agent，每个 agent 专注于不同的任务：

- **数据聚合 agent** – 收集并整合大量数据集，包括 20 多年的天气历史、土壤条件以及超过 80,000 条作物生长阶段观测记录。
- **推荐 agent** – 分析聚合后的数据，为精准的投入品施用、产品布局以及病虫害防治策略提供定制化建议。
- **对话式 AI agent** – 使用多语言对话大语言模型（LLM）以自然语言与用户交互，并以清晰的形式呈现洞见。

这种多 agent 协作使 Cropwise AI 能够高效处理复杂的农业数据，提供可付诸行动的洞见和个性化建议，以提升作物产量、可持续性和盈利性。

### **成果**

通过实施 Cropwise AI，Syngenta 在农业实践中取得了显著改善：

- **更优的决策：**农艺顾问和种植者获得由数据驱动的建议，从而优化作物管理策略。
- **更高的产量：**借助 Syngenta 的种子推荐模型，Cropwise AI 帮助种植者将产量提升最多 5%。
- **可持续的做法：**该系统推动精准农业，通过优化的投入品施用减少浪费并最大限度地降低环境影响。

在强调这一进展的重要意义时，Syngenta Group 首席信息与数字官 Feroz Sheikh 表示：

> “作为农业创新领军企业的 Syngenta 正在把 Amazon Bedrock Agents 用于其 Cropwise AI 解决方案，该方案为种植者提供深度洞见，帮助他们优化作物产量、提升可持续性并推动盈利。借助多 agent 协作，Syngenta 将能够使用多个 agent 进一步改进向种植者提供的建议，改变最终用户做决策的方式，并为农业社区带来更大的价值。”

Syngenta 与 AWS 的这一合作，体现了生成式 AI 和多 agent 系统在农业领域的变革潜力：驱动创新并支持可持续的耕作实践。

## 多 agent 协作如何运作

Amazon Bedrock 自动完成 agent 协作，包括任务委派、执行跟踪和数据编排。开发者可以通过以下两种协作模式之一来配置自己的系统：

- **Supervisor 模式**  supervisor agent 接收输入，拆解复杂请求，并把任务分配给各个专用 sub-agent。sub-agent 并行或顺序执行任务，把响应返回给 supervisor，由 supervisor 汇总结果。
- **带路由的 Supervisor 模式**  简单查询会被直接路由到相关的 sub-agent。复杂或有歧义的请求会触发 supervisor 协调多个 agent 来完成任务。
