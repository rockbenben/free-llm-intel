# 在 Amazon SageMaker AI 与 Amazon Bedrock AgentCore 上使用 OpenAI GPT OSS 构建 agentic 工作流

OpenAI 发布了两款开放权重模型：`gpt-oss-120b`（1170 亿参数）和 `gpt-oss-20b`（210 亿参数），两者都采用混合专家（Mixture of Experts，MoE）设计，上下文窗口为 128K。根据 [Artificial Analysis 基准测试](https://artificialanalysis.ai/leaderboards/models?open_weights=open_source)，这两款模型是领先的开源模型，并在推理和 agentic 工作流方面[表现突出](https://openai.com/index/introducing-gpt-oss/)。借助 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker-ai)，你可以通过完全托管的服务微调或定制模型，并选用自己喜欢的框架进行部署。[Amazon SageMaker Inference](https://aws.amazon.com/sagemaker/ai/deploy/) 让你可以自带推理代码和框架，而无需自行搭建和维护集群。

尽管大语言模型（LLMs）擅长理解语言和生成内容，但要构建真实场景中的 agentic 应用，还需要复杂的工作流管理、工具调用能力和上下文管理。多 agent 架构通过把复杂系统拆分成专门化的组件来应对这些挑战，但同时也带来了 agent 协调、记忆管理和工作流编排方面的新复杂性。

本文展示如何把 `gpt-oss-20b` 模型部署到 SageMaker 托管端点，并用 [LangGraph](https://www.langchain.com/langgraph) 演示一个实用的股票分析 agent 助手示例——LangGraph 是一个强大的基于图的框架，可处理状态管理、协同工作流和持久记忆系统。随后我们会把 agent 部署到 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/)，这一统一的编排层把基础设施抽象掉，让你能够安全地大规模部署和运行 AI agent。

## 方案概览

在本方案中，我们构建一个 agentic 股票分析器，包含以下关键组件：

- 把 [GPT OSS 20B](https://openai.com/index/introducing-gpt-oss/) 模型部署到 SageMaker 端点，使用的服务框架是面向 LLM 的开源框架 [vLLM,](https://docs.vllm.ai/en/latest/)
- 用 LangGraph 构建多 agent 编排框架
- 用 Amazon Bedrock AgentCore 部署 agent

下图展示了方案架构。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/15/Screenshot-2025-09-15-at-9.37.48 AM-1024x558.png)

该架构展示了托管在 AWS 上运行的 Amazon Bedrock AgentCore Runtime 中的多 agent 工作流。用户提交查询后，由一条由多个专门化 agent 组成的工作流处理——数据采集 agent（Data Gathering Agent）、股票表现分析 agent（Stock Performance Analyzer Agent）和股票报告生成 agent（Stock Report Generation Agent）——它们各自负责股票评估流程中一个不同的环节。

这些 agent 在 Amazon Bedrock AgentCore Runtime 内协作，当需要语言理解或生成时，它们会调用托管在 SageMaker AI 上的 GPT OSS 模型。模型处理输入并返回结构化输出，为 agent 的后续动作提供依据，从而用开源模型构建出一个完全无服务器、模块化且可扩展的 agentic 系统。

## 先决条件

- 确认你拥有部署该模型所需的 G6e 实例配额。如果没有，请在此处[申请配额](https://us-east-1.console.aws.amazon.com/servicequotas/home/dashboard)。
- 如果你是第一次使用 [Amazon SageMaker Studio](https://docs.aws.amazon.com/sagemaker/latest/dg/studio.html)，需要先创建一个 [SageMaker 域](https://docs.aws.amazon.com/sagemaker/latest/dg/onboard-quick-start.html)。

## 将 GPT-OSS 模型部署到 SageMaker Inference

希望定制模型和框架的客户可以采用带服务器的部署方式，但这需要自行获得 GPU、服务框架、负载均衡器和基础设施搭建条件。SageMaker AI 提供一个完全托管的托管平台，负责按所需驱动完成基础设施的准备、下载模型并完成部署。OpenAI 的 GPT-OSS 模型以 4 位量化方案（MXFP4）发布，既能实现快速推理，又能保持较低的资源占用。这些模型可以运行在 P5（H100）、P6（H200）、P4（A100）和 G6e（L40）实例上。GPT-OSS 模型是稀疏 MoE 架构，包含 128 个专家（120B）或 32 个专家（20B），每个 token 会被路由到 4 个专家，且没有共享专家。仅对 MoE 权重使用 MXFP4，就能把模型大小降到 63 GB（120B）和 14 GB（20B），使它们可以在一块 H100 GPU 上运行。

要高效部署这些模型，你需要像 vLLM 这样强大的服务框架。为了部署该模型，我们构建了一个 vLLM 容器，使用支持 SageMaker AI 上 GPT OSS 模型的最新版本。

你可以使用下面的 [Docker 文件](https://github.com/aws-samples/sagemaker-genai-hosting-examples/tree/main/OpenAI/gpt-oss/deploy/docker)和脚本来构建容器，并把它推送到本地的 [Amazon Elastic Container Registry](https://aws.amazon.com/ecr/)（Amazon ECR）。推荐的做法是直接在 [Amazon SageMaker Studio](https://aws.amazon.com/about-aws/whats-new/2023/12/sagemaker-studio-local-mode-docker/) 中完成，它提供带 AWS CLI 访问权限的托管 JupyterLab 环境，你可以在其中构建镜像并推送到 ECR，作为 SageMaker 工作流的一部分。另一种做法是在已安装 Docker 的 [Amazon Elastic Compute Cloud](https://aws.amazon.com/ec2)（Amazon EC2）实例上执行同样的步骤。

构建容器并推送到 Amazon ECR 之后，你可以进入 SageMaker AI 控制台打开 [Amazon SageMaker Studio](https://aws.amazon.com/sagemaker/studio/)，如下面的截图所示。

## 使用 LangGraph 构建股票分析 agent

在我们的股票分析多 agent 系统中，我们使用 LangGraph 来编排工作流。代码对应的 Jupyter notebook 位于这个 [github 仓库](https://github.com/aws-samples/sagemaker-genai-hosting-examples/tree/main/OpenAI/gpt-oss/agents)。系统由三个专门工具组成，它们协同工作，对股票进行全面分析：

- `gather_stock_data` 工具针对给定的股票代码收集全面的股票数据，包括当前价格、历史表现、财务指标和市场数据。它返回经过格式化的信息，涵盖价格历史、公司基本面、交易指标和近期新闻标题。
- `analyze_stock_performance` 工具对股票数据执行详细的技术面与基本面分析，计算价格趋势、波动率和整体投资评分等指标。它会评估市盈率、利润率和股息率等多个因素，从而提供全面的表现分析
- `generate_stock_report`工具根据采集到的股票数据和分析结果生成专业的 PDF 报告，并按日期分文件夹自动上传到 Amazon S3。

本地测试时，你可以从本地脚本导入必要的函数，使用系统的简化版本。例如：

```
from langgraph_stock_local import langgraph_stock_sagemaker
# Test the agent locally
result = langgraph_stock_sagemaker({
    "prompt": "Analyze SIM_STOCK Stock for Investment purposes."
})
print(result)
```

这样，你就可以在把 agent 部署到可扩展平台之前快速迭代其逻辑，确保每个组件都正常工作，并且整个工作流能对不同类型的股票产出预期结果。

## 部署到 Amazon Bedrock AgentCore

在本地开发并测试好 LangGraph 框架后，你可以把它部署到 Amazon Bedrock AgentCore Runtime。Amazon Bedrock AgentCore 承担容器编排、会话管理、可扩展性以及基础设施管理抽象这些繁重工作。它提供持久化的执行环境，可以在多次调用之间保持 agent 的状态。

在把股票分析 agent 部署到 Amazon Bedrock AgentCore Runtime 之前，我们需要创建一个具有相应权限的 [AWS Identity and Access Management](https://aws.amazon.com/iam/) IAM 角色。该角色允许 Amazon Bedrock AgentCore 调用你的 SageMaker 端点进行 GPT-OSS 模型推理、管理用于存放容器镜像的 ECR 仓库、写入供监控和调试使用的 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 日志、访问 Amazon Bedrock AgentCore 工作负载服务以执行运行时操作，并把遥测数据发送到 [AWS X-Ray](https://aws.amazon.com/xray/) 和 CloudWatch 以实现可观测性。参见以下代码：

```
from create_agentcore_role import create_bedrock_agentcore_role
role_arn = create_bedrock_agentcore_role(
    role_name="MyStockAnalyzerRole",
    sagemaker_endpoint_name="your-endpoint-name",
    region="us-west-2"
)
```

创建好角色之后，你可以使用 Amazon Bedrock AgentCore Starter Toolkit 部署 agent。该工具包通过打包代码、创建所需的容器镜像并配置运行时环境来简化部署流程：

```
from bedrock_agentcore_starter_toolkit import Runtime
agentcore_runtime = Runtime()
# Configure the agent
response = agentcore_runtime.configure(
    entrypoint="langgraph_stock_sagemaker_gpt_oss.py",
    execution_role=role_arn,
    auto_create_ecr=True,
    requirements_file="requirements.txt",
    region="us-west-2",
    agent_name="stock_analyzer_agent"
)
# Deploy to the cloud
launch_result = agentcore_runtime.launch(local=False, local_build=False)
```

当你使用 `BedrockAgentCoreApp` 时，它会自动创建一个监听 8080 端口的 HTTP 服务器，实现处理 agent 请求所需的 `/invocations` 端点，实现用于健康检查的 `/ping` 端点（这对异步 agent 非常重要），处理恰当的内容类型和响应格式，并按 AWS 标准管理错误处理。

把 agent 部署到 Amazon Bedrock AgentCore Runtime 之后，你可以在 Amazon Bedrock AgentCore 控制台上看到状态显示为 **Ready**。

## 调用 agent

创建 agent 之后，你必须设置 agent 的调用入口。在 Amazon AgentCore Runtime 中，我们用 `@app.entrypoint` 装饰器修饰 agent 的调用部分，并把它作为运行时的入口点。把 agent 部署到 Amazon AgentCore Runtime 之后，你可以使用 AWS SDK 调用它：

```
import boto3
import json
agentcore_client = boto3.client('bedrock-agentcore', region_name='us-west-2')
response = agentcore_client.invoke_agent_runtime(
    agentRuntimeArn=launch_result.agent_arn,
    qualifier="DEFAULT",
    payload=json.dumps({
        "prompt": "Analyze SIM_STOCK for investment purposes"
    })
)
```

通过 Amazon Bedrock AgentCore Runtime 调用股票分析 agent 之后，你需要解析并格式化响应，以便清晰呈现。响应处理包括以下步骤：

- 把来自 Amazon Bedrock AgentCore 的字节流解码为可读文本。
- 解析包含完整股票分析的 JSON 响应。
- 使用正则模式匹配提取三个主要部分：  **Stock Data Gathering Section**：提取核心股票信息，包括代码、公司详情、当前价格、市场指标、财务比率、交易数据和近期新闻标题。 **Performance Analysis section: **分析技术指标、基本面指标和波动率指标，以生成全面的股票分析。 **Stock Report Generation Section: **生成包含全部股票技术分析的详细 PDF 报告。

系统还包含错误处理：优雅地处理 JSON 解析错误，在结构化解析失败时回退为纯文本展示，并提供调试信息以便排查股票分析响应的解析问题。

```
stock_analysis = parse_bedrock_agentcore_stock_response(invoke_response)
```

格式化后的输出让你可以轻松审视 agent 的决策过程，并向利益相关方呈现专业的股票分析结果，从而完成从模型部署到有实际业务价值的输出的端到端工作流：
