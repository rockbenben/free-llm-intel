语音智能体、交互式学习应用、无障碍工具和客服助手需要在不长时静默的情况下响应。在本教程中，你在 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/) 上部署一个文本转语音（TTS）模型，它可以在还没生成完整个响应之前就开始播放语音。你使用 [AWS vLLM-Omni Deep Learning Container (DLC)](https://aws.github.io/deep-learning-containers/vllm-omni/) 部署 [Qwen3-TTS](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice)，通过一条持久的双向连接流入文本、流出音频，并通过一个 Gradio 应用试用这一工作流。

[AWS Deep Learning Containers](https://github.com/aws/deep-learning-containers) 提供带深度学习框架及依赖的 Docker 镜像，用于在 AWS 上训练和推理。AWS 为广泛采用的服务框架（如 [vLLM](https://github.com/aws/deep-learning-containers/tree/master/docs/vllm) 和 [SGLang](https://github.com/aws/deep-learning-containers/tree/master/docs/sglang)）提供部署指导。本文是关于专用 DLC（包括 [vLLM-Omni](https://github.com/aws/deep-learning-containers/tree/main/docs/vllm-omni)、[WhisperX](https://github.com/aws/deep-learning-containers/tree/main/docs/whisperx) 和 [llama.cpp](https://github.com/aws/deep-learning-containers/tree/main/docs/llama-cpp)）系列的第 1 部分，聚焦于面向实时语音应用的流式语音。[第 2 部分](https://aws.amazon.com/blogs/machine-learning/generate-images-and-video-with-vllm-omni-on-sagemaker-ai-part-2/)将 vLLM-Omni DLC 应用到图像和视频生成。该系列把焦点用例与部署示例，以及在能提供有用证据时的可复现基准配对呈现。

[vLLM-Omni 项目](https://github.com/vllm-project/vllm-omni)把 vLLM 从文本生成扩展到服务那些处理或生成文本、音频、图像和视频的模型。AWS vLLM-Omni DLC 把被跟踪的 vLLM-Omni 发行版打包进 AWS 镜像，并为 SageMaker AI 添加路由中间件。你使用 [SageMaker 双向流式传输](https://docs.aws.amazon.com/sagemaker/latest/dg/realtime-endpoints-test-endpoints.html#realtime-endpoints-test-endpoints-sdk)，通过持久连接发送文本并接收音频块。

早先的文章 [Build real-time voice applications with Amazon SageMaker AI and vLLM](https://aws.amazon.com/blogs/machine-learning/build-real-time-voice-applications-with-amazon-sagemaker-ai-and-vllm/) 演示了语音流水线的输入侧。它把麦克风音频流式传给 `Voxtral-Mini-4B` Realtime 语音转文本（STT）模型并返回转录事件。本文补上输出侧：把文本发送给 Qwen3-TTS，并通过 vLLM-Omni DLC 流式返回生成的语音。

你会克隆[代码示例](https://github.com/aws-samples/sagemaker-genai-hosting-examples/tree/main/03-features/bidirectional-streaming-vLLM-Omni)、部署一个 Qwen3-TTS 模型，并通过一个 Gradio 应用试用流式语音。

## 用于多模态推理的专用 AWS DLC

专用的推理运行时支持那些不同于通用文本生成的模型架构和媒体流水线。AWS DLC 把这些运行时连同其框架依赖和部署配置一起打包，给你一个基于镜像、通往 AWS 计算和托管推理服务的一致路径。

[vLLM-Omni](https://github.com/vllm-project/vllm-omni) 把 vLLM 从以文本为主的自回归生成，扩展到处理并生成多种模态的模型。它的异构流水线抽象协调多阶段模型工作流，包括自回归和扩散阶段。它还提供流式输出和 OpenAI 兼容的 API。

该运行时并不局限于 TTS。它的[受支持模型](https://github.com/vllm-project/vllm-omni/blob/main/docs/models/supported_models.md)包括统一的全模态模型、自动语音识别（ASR）、TTS、音频生成、图像生成和视频生成。本文把 Qwen3-TTS 作为一个焦点示例，因为流式语音提供了演示双向音频输出的直接方式。

[先前的 vLLM 文章](https://aws.amazon.com/blogs/machine-learning/build-real-time-voice-applications-with-amazon-sagemaker-ai-and-vllm/) 覆盖输入路径：麦克风音频进入一个 Voxtral 模型，转录事件返回到应用。一个语音应用可以把那份转录交给它的对话逻辑，然后用本示例把响应文本变成流式语音。两个端点之间的编排不在本演练范围内。

## 方案概览

完整示例位于 [03-features/bidirectional-streaming-vLLM-Omni](https://github.com/aws-samples/sagemaker-genai-hosting-examples/tree/main/03-features/bidirectional-streaming-vLLM-Omni)。克隆仓库，把部署脚本、共享流式传输层和 Gradio 客户端一起使用。

SageMaker 双向流式传输暴露一个经由 HTTP/2 承载的全双工 WebSocket。客户端连接到 SageMaker Runtime 端口的 `8443`。SageMaker 推理 sidecar 把该连接转发到容器内 vLLM-Omni 原生的 WebSocket 路由。

图 1 展示请求和响应路径。客户端发送会话配置和文本事件。Qwen3-TTS 在同一连接上返回音频生命周期和块事件。

图 1：一个 Gradio 应用使用 HTTP/2 WebSocket，把文本事件流经 Amazon SageMaker AI、推理 sidecar 和 vLLM-Omni DLC 流式传给 Qwen3-TTS。音频事件和 24 kHz PCM 块经同一连接返回

vLLM-Omni v1.5 DLC 添加了 SageMaker AI 所需的双向流式传输能力标签和路由中间件。示例使用 `v1/audio/speech/stream`，它是 vLLM-Omni 暴露的原生 WebSocket 路由之一。

端点配置还使用 [SageMaker 实例池](https://docs.aws.amazon.com/sagemaker/latest/dg/realtime-endpoints-heterogeneous.html)。一个实例池为一个 production variant 定义一份按优先级排序的兼容实例类型列表。SageMaker 先尝试 `ml.g6.xlarge`，当容量不足时退回到 `ml.g6e.xlarge`、`ml.g5.xlarge` 或 `ml.g4dn.xlarge`。它仍然只配置一台实例，而不是每池一台。

SageMaker 在创建端点会为每个配置的池条目校验配额，因此你需要对每种被包含的类型都有可用配额。如果 SageMaker 选了一个不同的实例，你的每小时成本也会变。用 `--instance-types` 把池限制到那些满足你配额、价格和性能要求的类型。

## 前提条件

开始前，你需要：

- 一个 AWS 账户，为 AWS Command Line Interface (AWS CLI) 或 AWS SDK 配置好凭证
- Git
- Python 3.12 或更新版本
- 一个 SageMaker AI execution 角色
- 创建和调用 SageMaker AI 端点的权限
- 至少一种池内实例类型的端点配额：`ml.g6.xlarge`、`ml.g6e.xlarge`、`ml.g5.xlarge` 或 `ml.g4dn.xlarge`
- Boto3 版本 1.40.0 或更新
- SageMaker Runtime HTTP/2 Python 客户端版本 0.4.0

演练使用美国东部（弗吉尼亚北部）区域。示例基于 `AWS_REGION` 构建 DLC 镜像 URI 和运行时端点。

## 部署一个流式语音端点

- **克隆 hosting examples 仓库。** 克隆仓库并进入 vLLM-Omni 双向流式传输示例目录。  `git clone https://github.com/aws-samples/sagemaker-genai-hosting-examples.git cd sagemaker-genai-hosting-examples/03-features/bidirectional-streaming-vLLM-Omni`
- **安装所需的 Python 包。** 创建一个虚拟环境并安装示例所定义的版本。  `python3.12 -m venv .venv source .venv/bin/activate python -m pip install -r requirements.txt`
- **配置示例。** 设置你的 SageMaker AI execution 角色。示例默认 `us-east-1`。传 `--region` 以使用另一个受支持的区域。  `export SAGEMAKER_EXECUTION_ROLE_ARN="arn:aws:iam::<account-id>:role/<sagemaker-execution-role>"`  推理 AMI 设置对于处理 HTTP/2 WebSocket 的 SageMaker sidecar 是必需的。模型调用路径必须省略前导斜杠，因为 SageMaker 在转发请求前会加上它。
- **部署并保留模型端点。** 示例从 DLC 创建一个 SageMaker 模型、一个端点配置和一个实时端点。环境变量 `SM_VLLM_MODEL` 告诉容器加载哪个模型。脚本还会运行一次流式冒烟测试，并把结果存为 `validation-output.wav`。  `python deploy_bidi_stream.py \ --endpoint-name vllm-omni-bidi \ --region us-east-1 \ --keep-endpoint`  等到端点达到 `InService`。首次部署耗时较长，因为实例要下载 DLC 镜像和模型产物。
- **启动 Gradio 应用。** 针对端点运行已签入的 Gradio 客户端。  `python sagemaker_bidi_tts_client.py \ --endpoint-name vllm-omni-bidi \ --region us-east-1`  在浏览器打开 `http://127.0.0.1:6006`。`--share` 选项会创建一个 Gradio 公共链接，除非你需要该行为否则保持禁用。
- **生成流式语音。** 输入文本，选择一个音色和语言，然后选择 **Generate speech**。共享客户端打开双向流、配置脉冲编码调制（PCM）输出并发送文本。  `await send_json( stream, { "type": "session.config", "voice": voice, "language": language, "response_format": "pcm", "stream_audio": True, }, ) await send_json(stream, {"type": "input.text", "text": text}) await send_json(stream, {"type": "input.done"})`  Gradio 音频组件在客户端每收到一个 24 kHz PCM 块时就播放它。状态字段报告块数和总音频字节数。
- **删除示例资源。** 停止 Gradio 进程，然后删除端点、端点配置和模型。  `python deploy_bidi_stream.py \ --endpoint-name vllm-omni-bidi \ --region us-east-1 \ --delete-endpoint`

## 清理

确认清理命令报告了端点、端点配置和模型的删除。如果进程在清理完成前停止，请通过 SageMaker AI 控制台或 API 删除这些资源。一个正在运行的 GPU 端点会持续产生费用。

## 结论

通过部署一个文本转语音模型，你在 SageMaker AI 上使用了 AWS vLLM-Omni DLC，在模型还在生成时就流式输出音频。这个示例展示了专用的 AWS DLC 如何支持那些执行和流式模式不同于通用文本生成的多模态模型。与[先前的 vLLM 语音转文本示例](https://aws.amazon.com/blogs/machine-learning/build-real-time-voice-applications-with-amazon-sagemaker-ai-and-vllm/)配对，这些示例展示了互补的路径：把麦克风音频流式传入转录，然后把应用的文本响应流式传回为语音。[第 2 部分](https://aws.amazon.com/blogs/machine-learning/generate-images-and-video-with-vllm-omni-on-sagemaker-ai-part-2/)将展示如何用同一个 DLC 家族做图像和视频生成。
