# 将 Nova 2 Lite 与 Claude 搭配，实现成本优化的文档处理

一张扫描的毕业纪念册页面包含 176 个印刷体姓名、4 张人像照片，以及零个把两者关联起来的机器可读结构。要把这一页数字化，你需要可靠的照片检测（带边界框）和准确的姓名抽取。你还需要一种依据页面版式判断哪个姓名属于哪张面孔的方法。

在本文中，我们展示如何将 Amazon Nova 2 Lite 与 Anthropic 的 Claude Sonnet 4.6 搭配使用，为大规模数字化扫描文档提供高效解决方案。我们在 Amazon Bedrock 上构建了一条双模型 pipeline，用于数字化扫描的毕业纪念册页面。Amazon Nova 2 Lite 通过一次调用完成原生多模态抽取：检测照片、抽取可见姓名及其坐标，并返回页面级元数据。随后由 Claude Sonnet 4.6 进行空间推理，依据页面版式把姓名与面孔对应起来。

我们在 336 个扫描的毕业纪念册页面上运行了这条 pipeline，共生成 3,122 条姓名与人脸的关联，其中 93% 的关联置信度达到或超过 0.95。与把整个任务交给单个视觉语言模型的单模型方案相比，这种双模型方法在每页成本上低约三分之二。详细的成本拆分见「成本考量」一节。

## 方案概览

这条 pipeline 包含两个阶段。每个阶段使用不同的模型，并按该阶段所要执行的具体任务来选定。

![Amazon Bedrock 上两阶段毕业纪念册文档处理 pipeline 的架构图：一张扫描页面图像流入阶段 1（Amazon Nova 2 Lite，负责照片检测与姓名抽取），再流入阶段 2（Claude Sonnet 4.6，负责结合自适应思考的空间推理），最终产出姓名与人脸关联的结构化 JSON。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/19/ML-20681-1.png)

**图 1.** 双模型 pipeline 架构。扫描的页面图像依次流经两个阶段。在阶段 1 中，Amazon Nova 2 Lite 通过一次 API 调用完成原生多模态抽取：它检测并分类照片、给出边界框，读取页面上可见的姓名并返回其大致位置，同时输出页面级元数据。在阶段 2 中，Claude Sonnet 4.6 利用 Nova 输出的组合结果进行空间推理，把姓名与人脸匹配起来。

**Amazon Nova 2 Lite** 首先运行。由于它能原生处理交错排列的文本与图像，一次 Converse 调用即可返回三类信息：

- 检测到的照片，包含边界框与分类。
- 页面上可见的姓名及其大致位置。
- 页面级元数据，例如标题与类别。

我们通过在这条 Converse API 调用中加入 reasoning 配置，把该任务的推理级别设为 **LOW**。相关配置见后文「步骤 1」代码中的 reasoning 块。在全部 336 个页面上的测试表明，对于这种结构化抽取，**LOW**、**MEDIUM** 和 **HIGH** 三个推理级别在准确率上没有显著差异，而 **LOW** 是最便宜的选择。Nova 通过 `reasoning_config` 字段暴露该设置。步骤 2 中的 Claude 使用单独的 `thinking` 字段，因此两个模型以不同名称控制推理。

只要求 *Nova 2 Lite* 返回姓名、而不要求它返回页面上的每一个 OCR token，正是让第一阶段保持低成本的关键。下游的空间推理步骤并不需要班级名册或活动描述的完整文本，它只需要出现在照片附近的姓名。把 Nova 的输出限制为姓名，可以把输出 token 成本维持在每页约 1,000 个 token，而不是完整跑一遍 OCR 大约会产生 4,500 个 token。

Claude Sonnet 4.6 只在阶段 2 的空间推理步骤中介入。拿到 Nova 输出的带位置姓名和照片边界框后，Claude 判断哪些姓名对应哪些人脸。这一步需要处理页面版式的差异，因为毕业纪念册的版式逐页不同。图注可能出现在照片上方或下方，有些页面还会把单人肖像网格与合影混排。Claude 的自适应思考能够处理这种差异，无需针对每种版式类型额外做 prompt 工程。

在本方案中，Nova 2 Lite 通过一次调用原生完成大批量的抽取工作。Claude 则每页调用一次，用于空间推理步骤。

### Nova 2 Lite 固定的按图计价：规模化下可预测的成本

Amazon Nova 2 Lite 对图像输入计费方式的一项近期变更，使规模化下的每页成本变得可预测，这在处理数十万页时至关重要。

**固定的按图计价：** Amazon Nova 2 Lite 按*固定的每图费率*对图像和文档页面输入计费，与分辨率或文件大小无关。

这一变更对文档处理 pipeline 意义重大。此前，图像 token 成本随分辨率变化，如果不先在代表性样本上做概念验证，就很难预估每页成本。采用固定计费后，Nova 2 Lite 处理的每一张图像都按相同的每图费率计费，与分辨率无关。

对于包含 prompt 与输出的整页抽取，每页成本拆分如下：

| **组成部分** | **Tokens/页** | **费率** | **成本/页** |
| --- | --- | --- | --- |
| 图像 token（固定） | 230 | $0.30/M 输入 | $0.000069 |
| Prompt token（估计） | 500 | $0.30/M 输入 | $0.000150 |
| 输出 token（估计） | 1,000 | $2.50/M 输出 | $0.0025 |
| **总计** | **~$0.0027** |  |  |

按已公布的 Nova 2 Lite 输入 token 费率计算，图像输入只占每页总成本的一小部分。当前费率请见 [Amazon Bedrock 定价页面](https://aws.amazon.com/bedrock/pricing/)。

对于毕业纪念册规模的工作负载（每年数十万页），这种固定计价让成本预测变得简单，因为图像输入成本随页数线性增长，且与页面分辨率无关。无需做分辨率归一化。

## 用于空间推理的自适应思考

Amazon Bedrock 上的 Claude 支持自适应思考，该功能让模型根据输入复杂度决定投入多少内部推理。你可以在 Converse API 的 `thinking` 配置中把 `type` 设为 `adaptive` 来启用它：

```
response = bedrock_runtime.converse(
    modelId='us.anthropic.claude-sonnet-4-6',
    messages=[{
        'role': 'user',
        'content': [
            {'image': {'format': 'jpeg', 'source': {'bytes': image_bytes}}},
            {'text': spatial_reasoning_prompt}
        ]
    }],
    additionalModelRequestFields={
        'thinking': {
            'type': 'adaptive'
        }
    }
)
```

启用自适应思考后，Claude 会根据收到的内容调整推理深度。一个简单的人像网格——八个姓名整齐排列在八张人脸之上——会得到几乎不需要推理的直接答复。而某一页上三张合影共用一个图注块、姓名出现在侧栏时，就会触发逐步的空间分析。

在我们 336 页的运行中，Claude 在每一页都使用了扩展推理，推理轨迹长度从 544 到 1,658 个字符不等。即使较简单的页面也从一定程度的空间分析中受益，因为毕业纪念册的版式很少完全统一。推理轨迹显示，Claude 会逐项推演姓名位置与人脸位置之间的列对齐与垂直偏移，并在页面出现合影时检查图注的邻近关系。

对于这类结构化的空间任务，自适应思考能在无需人工调参的情况下为每页提供恰到好处的推理量。你不需要设置固定的 token 预算，也不需要针对版式编写专用 prompt。模型会读取输入并自行决定。

**关于自适应思考的成本提示：** 启用自适应思考时，请留意三个成本因素。

- 推理 token 按输出 token 的标准输出费率计费（Claude Sonnet 4.6 通过跨区域推理为每百万输出 token $15.00）。
- 推理轨迹会以独立的 `thinking` 内容块形式在 API 响应中返回，但不会展示给最终用户。
- 监控响应元数据中的 `inputTokens` 与 `outputTokens` 以跟踪每页的实际成本，因为在复杂页面上推理可能显著增加输出 token 数量。

## 实现步骤详解

完整源代码、示例图像和 Jupyter notebook 可在 [GitHub 上的 AWS Samples 仓库](https://github.com/aws-samples/amazon-nova-samples/tree/main/multimodal-understanding/repeatable-patterns/35-hybrid-vision-spatial-reasoning)中获取。

### 前提条件

在运行这条 pipeline 之前，请确保已具备以下条件：

- 一个 AWS 账户，且可在提供 Amazon Nova 2 Lite 与 Claude Sonnet 4.6 的 AWS 区域访问 Amazon Bedrock。
- 在 Amazon Bedrock 控制台中为 `us.amazon.nova-2-lite-v1:0` 和 `us.anthropic.claude-sonnet-4-6` 启用模型访问权限。
- 一个 AWS Identity and Access Management（IAM）主体，具备对前述两个模型调用 `bedrock:InvokeModel` 与 `bedrock:Converse` 的权限。
- Python 3.10 或更高版本，并已安装 `boto3` SDK。示例 notebook 还使用 `rapidfuzz` 做模糊姓名匹配，使用 Pillow 绘制可视化叠加层。
- 扫描的页面图像（JPEG 或 PNG）。通过 Converse API 输入图像时，图像字节在请求内联传递。

### 步骤 1：使用 Amazon Nova 2 Lite 检测照片并抽取姓名

把扫描页面发送给 Amazon Nova 2 Lite，prompt 中同时要求检测到的照片（带边界框与分类）和可见姓名（带页面上的大致位置）。Nova 的原生多模态理解能力会在一次 Converse 调用中同时返回这两者。

Nova 对照片和姓名都以 0–1000 的坐标尺度返回边界框。把两者直接传入步骤 2。只要在 prompt 中给出，Claude 就能读懂同一坐标空间，因此无需做转换。

```
def extract_photos_and_names(image_bytes):
    """Detect photos and extract visible names with Amazon Nova 2 Lite."""
    # Using the Converse API consistently for all Bedrock calls

    response = bedrock_runtime.converse(
        modelId='us.amazon.nova-2-lite-v1:0',
        # Note: cross-region inference profile (us.amazon.nova-2-lite-v1:0)
        messages=[{
            'role': 'user',
            'content': [
                {
                    'image': {
                        'format': 'jpeg',
                        'source': {'bytes': image_bytes}
                    }
                },
                {'text': PHOTO_AND_NAME_EXTRACTION_PROMPT}
            ]
        }],
        inferenceConfig={
            'maxTokens': 8000,
            'temperature': 0
        },
        additionalModelRequestFields={
            'reasoning_config': {
                'type': 'enabled',
                'level': 'LOW'
            }
        }
    )

    raw = response['output']['message']['content'][0]['text']
    return json.loads(raw)
```

该 prompt 指示 Nova 返回一个 JSON 对象，其中同时包含照片与页面上可见的姓名。

```
{
  "page_title": "Junior Class Officers",
  "photos": [
    {
      "bbox": [245, 180, 410, 520],
      "type": "portrait",
      "category": "class_officers",
      "summary": "Individual portrait photo"
    }
  ],
  "names": [
    {
      "text": "Cecilia Phillips",
      "bbox": [260, 540, 395, 570]
    },
    {
      "text": "John Kolander",
      "bbox": [420, 540, 555, 570]
    }
  ]
}
```

每张照片都会得到一个边界框、一个类型（portrait、group 或 candid）、一个类别标签和一段简短描述。每个姓名都会得到其可见文本和在页面上的边界框。`page_title` 与 `category` 字段还服务于第二个用例：元数据抽取。借助一次 API 调用，Nova 2 Lite 就提供了照片检测、供匹配 pipeline 使用的带位置姓名，以及结构化元数据。你可以把这些元数据用于搜索索引、按活动类型过滤，或在数百页范围内构建目录。

### 步骤 2：使用 Claude 把姓名与人脸匹配起来

现在把 Nova 输出的带位置姓名和照片边界框传给 Claude 做空间推理。两者使用相同的 0–1000 坐标空间，因此无需归一化：

```
spatial_prompt = f"""Given these names with page coordinates:
{json.dumps(ocr_tokens)}

And these detected photos with bounding boxes:
{json.dumps(photo_detections)}

Match each person's name to their photo based on spatial position.
Return JSON: {{"associations": [{{"name": str, "face_idx": int,
"confidence": float, "reasoning": str}}]}}"""

response = bedrock_runtime.converse(
    modelId='us.anthropic.claude-sonnet-4-6',
    messages=[{
        'role': 'user',
        'content': [
            {'image': {'format': 'jpeg', 'source': {'bytes': image_bytes}}},
            {'text': spatial_prompt}
        ]
    }],
    additionalModelRequestFields={
        'thinking': {'type': 'adaptive'}
    }
)
```

在测试集第 50 页上，Nova 返回了 176 条姓名条目和 4 个照片边界框。其中大多数姓名是页面其他位置的名册和正文文本。只有与这 4 张照片相邻的姓名可以匹配，因此 Claude 产出了 5 条关联：

```
{
  "associations": [
    {"name": "Cecilia Phillips", "face_idx": 0, "confidence": 0.95,
     "reasoning": "Row 0, position 1 of 3 - matches caption above photo"},
    {"name": "John Kolander", "face_idx": 1, "confidence": 0.95,
     "reasoning": "Row 0, position 2 of 3 - matches caption above photo"},
    {"name": "Julie Ostrander", "face_idx": 2, "confidence": 0.95,
     "reasoning": "Row 0, position 3 of 3 - matches caption above photo"}
  ]
}
```

每条关联都包含一个解释空间逻辑的 reasoning 字符串。这在调试关联失败的页面时很有用。

### 步骤 3：校验并汇总结果

最后一步应用置信度阈值和模糊姓名匹配（使用 rapidfuzz）来过滤低质量关联。pipeline 会为每页写入两项输出：一个包含关联数据的 JSON 文件，以及一张在匹配到的姓名与人脸之间画连线的可视化图像。

- **人像网格页面**（336 页中的 282 页）平均每页 10.9 条关联。这类页面版式规整，姓名直接出现在对应照片的上方或下方，pipeline 能可靠处理。

### 成本考量

双模型拆分意味着：合并的抽取调用（照片、带位置姓名、元数据）按 Nova 2 Lite 费率付费，而每页一次推理调用按 Claude 费率付费。在 Nova 2 Lite 固定的按图计价下，第一阶段成本可预测且与输入分辨率无关。Claude 的推理步骤在每页成本中占主导。

**每页成本拆分**

| **阶段** | **服务** | **成本驱动因素** | **大致每页成本** |
| --- | --- | --- | --- |
| 照片 + 姓名抽取 | Amazon Nova 2 Lite | 固定的 230 个图像 token + 约 500 个 prompt token + 约 1,000 个输出 token | ~$0.0027 |
| 空间推理 | Claude Sonnet 4.6 | 图像 + Nova JSON + 自适应推理 token | ~$0.030 |
| pipeline 合计 | **~$0.033** |  |  |

下表把这条 pipeline 与单模型方案做对比：后者把每页都发送给 Claude，由一次调用完成全部三项任务（OCR、照片检测和空间匹配）。

| **维度** | **双模型 pipeline** | **单模型 Claude** |
| --- | --- | --- |
| 输入 token | 图像（Nova：固定 230）+ Nova JSON → Claude | 图像 @ ~1,500 个 token + prompt @ ~1,300 = ~2,800 个 token @ $3/M = ~$0.008 |
| 输出 token | Nova：~1,000 个姓名的 JSON；Claude 推理：~1,700 @ $15/M = ~$0.026 | ~6,000 个 token @ $15/M = ~$0.09 |
| 每页成本 | ~$0.033 | ~$0.10 |
| 每 100,000 页成本 | ~$3,300 | ~$9,800 |
| OCR 质量 | Nova 原生多模态（无需单独的 OCR 服务） | 通用视觉语言模型 |
| 可调性 | 可独立替换或调优每个阶段 | 单体 prompt；改动是全部或全无 |

在 100,000 页的规模上，这就是约 $6,500 的差距。除成本之外，拆分式 pipeline 还让你能够独立替换或调优每个阶段而不触碰其他阶段。例如，当更好的 Claude 层级发布时，你可以只升级推理模型。

精确的每页成本取决于三个因素：

- 你的 Amazon Bedrock 定价层级。
- Nova 输出的姓名数量（随页面密度增长）。
- Claude 使用的推理 token 数量（随版式复杂度增长）。

粗略估算时，先算一次 Nova 2 Lite Converse 调用（单个图像输入、一个要求姓名与照片的 prompt），再加上一次 Claude Converse 调用（输入包含图像和 Nova 的 JSON 输出）。当前费率请查阅 Amazon Bedrock 定价。

**我们 336 页测试运行的实际成本**

基于我们的 pipeline 运行（336 页，平均每页 10.9 条关联）：

| **组成部分** | **估计成本** |
| --- | --- |
| Nova 2 Lite 照片 + 姓名抽取（336 页 × $0.0027） | ~$0.91 |
| Claude 空间推理（336 页 × $0.030） | ~$10.08 |
| **总计** | **336 页约 $10.99（约 $0.033/页）** |

**其他成本优化手段**

对于大批量或非实时的工作负载：

- **Amazon Bedrock 批量推理**：对于可以在一夜之间处理完的工作负载，Nova 2 Lite 与 Claude 调用可享 50% 折扣。把请求的 JSONL 文件提交到 Amazon Simple Storage Service（Amazon S3），由 Amazon Bedrock 异步处理，次日早上读取结果。按批量定价，Nova 2 Lite 的组合阶段从每页约 $0.0027 降至约 $0.0014。
- **Prompt 缓存**：如果你在数千页上重复使用同一个照片检测 prompt（这条 pipeline 就是如此），prompt 缓存最多可将缓存 prompt 的 token 成本降低 90%。
- **推理预算控制**：对于 Claude，你可以在 `thinking` 上设置 `budgetTokens` 上限，以限制较简单页面上的推理 token 成本，同时在需要时仍允许更深入的推理。

### 延迟

每页都要经过两次顺序 API 调用，因此每页总延迟是两者之和。在我们的测试运行中，由于图像输入和自适应推理，Claude 空间推理步骤耗时最长，每页大约 20–30 秒。Nova 2 Lite 在几秒内完成。批量处理时，由于各页相互独立，你可以跨页并行。

| **阶段** | **典型延迟** |
| --- | --- |
| Nova 2 Lite（照片 + 姓名抽取） | 2–5 秒 |
| Claude 空间推理（自适应思考） | 20–30 秒 |
| 每页合计 | 约 22–35 秒 |

## 结论

在本文中，我们展示了如何在 Amazon Bedrock 上把文档处理拆分到两个模型，从而在 336 个毕业纪念册页面上产出 3,122 条姓名与人脸的关联，其中 93% 为高置信度。Amazon Nova 2 Lite 通过一次原生多模态调用完成照片检测与姓名抽取。Claude Sonnet 4.6 通过自适应思考完成空间推理，把姓名与正确的面孔匹配起来。
