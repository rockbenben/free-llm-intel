# Amazon Bedrock Guardrails 图像内容过滤器提供业界领先的防护，帮助客户拦截高达 88% 的有害多模态内容：今日正式可用

[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails) 宣布图像内容过滤器正式可用，使你能够对生成式 AI 应用中的图像和文本内容同时进行审核。此前该功能仅限于文本过滤，本次增强现在可为两种模态提供全面的内容审核。这项新能力免去了自行构建图像防护措施的重活，也免去了把时间耗在容易出错且繁琐的人工内容审核上。

[Tero Hottinen](https://www.linkedin.com/in/terohottinen/)，[KONE](http://www.kone.com/) 的战略合作负责人、副总裁，设想了以下用例：

> “在持续评估中，KONE 认为 Amazon Bedrock Guardrails 是保护生成式 AI 应用的关键组件，尤其是在相关性和上下文依据（contextual grounding）检查以及多模态防护方面。公司计划将产品设计图和手册集成到其应用中，而 Amazon Bedrock Guardrails 将在实现对多模态内容更准确的诊断与分析方面发挥关键作用。”

Amazon Bedrock Guardrails 提供可配置的防护措施，帮助客户为其生成式 AI 应用拦截有害或不需要的输入和输出。客户可以通过实施不同的策略来创建针对其具体用例的定制 Guardrails，从输入 prompt 和模型响应中检测并过滤有害或不需要的内容。此外，客户还可以使用 Guardrails 检测模型幻觉，帮助响应有据可依且准确。通过其独立的 [ApplyGuardrail API](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-use-independent-api.html)，Guardrails 使客户能够在任何[基础模型](https://aws.amazon.com/what-is/foundation-models/)上应用一致的策略，包括托管在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的模型、自托管模型和第三方模型。Bedrock Guardrails 支持与 Bedrock Agents 和 Bedrock Knowledge Bases 无缝集成，使开发者能够在各种工作流中落实防护，例如检索增强生成（RAG）系统和 agentic 应用。

Amazon Bedrock Guardrails 提供六种不同的策略，包括：内容过滤器，用于检测并过滤多个类别（包括仇恨、侮辱、性内容、暴力、不当行为）中的有害材料，并防范 prompt 攻击；主题过滤器，用于限制特定主题；敏感信息过滤器，用于拦截个人身份信息（PII）；词过滤器，用于拦截特定词语；上下文依据检查，用于检测幻觉并分析响应相关性；以及自动推理检查（Automated Reasoning checks，目前处于受限预览），用于识别、纠正并解释事实性陈述。借助新增的图像内容审核能力，这些防护措施现已扩展到文本和图像，帮助客户拦截高达 88% 的有害多模态内容。你可以独立配置对图像或文本内容（或两者）的审核，并使用从低到高可调的阈值，从而构建符合组织负责任 AI 政策的生成式 AI 应用。

这项新能力已在 US East (N. Virginia)、US West (Oregon)、Europe (Frankfurt) 和 Asia Pacific (Tokyo) AWS 区域正式可用。

本文讨论如何开始使用 Amazon Bedrock Guardrails 中的图像内容过滤器。

## 解决方案概览

要开始使用，请在 [AWS Management Console](https://aws.amazon.com/console/) 上创建一条 guardrail，并为文本或图像数据（或两者）配置内容过滤器。你也可以使用 [AWS SDK](https://aws.amazon.com/developer/tools/) 把这项能力集成到你的应用中。

## 创建 guardrail

要创建 guardrail，请完成以下步骤：

- 在 Amazon Bedrock 控制台的导航窗格中，在 **Safeguards** 下选择 **Guardrails**。
- 选择 **Create guardrail**。
- 在 **Configure content filters** 部分，在 **Harmful categories** 和 **Prompt attacks** 下，你可以使用现有的内容过滤器，在文本数据之外同时检测并拦截图像数据。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/28/ml-18588-image001.jpg)
- 选定并配置好要使用的内容过滤器后，你可以保存该 guardrail，并开始用它来帮助拦截生成式 AI 应用中有害或不需要的输入和输出。

## 使用文本生成测试 guardrail

要在 Amazon Bedrock 控制台上测试新的 guardrail，请选择该 guardrail 并选择 **Test**。你有两种选择：通过选择并调用一个模型来测试 guardrail，或者使用 Amazon Bedrock Guardrails 独立的 `ApplyGuardail` API 在不调用模型的情况下测试 guardrail。

使用 `ApplyGuardrail` API，你可以在应用流程中的任何位置、在处理结果或将其提供给用户之前校验内容。你也可以使用该 API 评估自管理（自定义）或第三方 FM 的输入和输出，无论其底层基础设施是什么。例如，你可以用该 API 评估一个 [Meta Llama 3.2](https://www.llama.com/) 模型（托管在 [Amazon SageMaker](https://aws.amazon.com/sagemaker/) 上），或一个 [Mistral NeMo](https://mistral.ai/news/mistral-nemo/) 模型（运行在你的笔记本电脑上）。

### 通过选择并调用模型来测试 guardrail

选择一个支持图像输入或输出的模型，例如 Anthropic 的 Claude 3.5 Sonnet。确认 prompt 过滤器和响应过滤器已针对图像内容启用。然后提供 prompt、上传图像文件，并选择 **Run**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/28/ml-18588-image003.jpg)

在此示例中，Amazon Bedrock Guardrails 进行了干预。选择 **View trace** 查看更多详情。

guardrail trace 提供了在一次交互中安全措施如何被应用的记录。它显示 Amazon Bedrock Guardrails 是否进行了干预，以及对输入（prompt）和输出（模型响应）分别做了哪些评估。在此示例中，内容过滤器拦截了输入 prompt，因为它们在图像中检测到暴力内容，置信度为中等。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/28/ml-18588-image005.jpg)

### 在不调用模型的情况下测试 guardrail

在 Amazon Bedrock 控制台上，选择 **Use ApplyGuardail API**，即在不调用模型的情况下测试 guardrail 的独立 API。选择你要校验的是输入 prompt 还是模型生成输出的示例。然后重复上一节的步骤。确认 prompt 过滤器和响应过滤器已针对图像内容启用，提供要校验的内容，并选择 **Run**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/28/ml-18588-image007.jpg)

在此示例中，我们复用了同一张图像和输入 prompt，Amazon Bedrock Guardrails 再次进行了干预。再次选择 **View trace** 查看更多详情。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/28/ml-18588-image009.jpg)

## 使用图像生成测试 guardrail

现在，让我们用图像生成用例来测试 Amazon Bedrock Guardrails 的多模态毒性检测。下面是一个把 Amazon Bedrock Guardrails 图像内容过滤器用于图像生成用例的示例。我们使用 `InvokeModel` API 和该 guardrail，通过 Amazon Bedrock 上的 Stability 模型生成图像：

```
guardrailIdentifier = <<guardrail_id>>
guardrailVersion ="1"

model_id = 'stability.sd3-5-large-v1:0'
output_images_folder = 'images/output'

body = json.dumps(
    {
        "prompt": "A Gun", #  for image generation ("A gun" should get blocked by violence)
        "output_format": "jpeg"
    }
)

bedrock_runtime = boto3.client("bedrock-runtime", region_name=region)
try:
    print("Making a call to InvokeModel API for model: {}".format(model_id))
    response = bedrock_runtime.invoke_model(
        body=body,
        modelId=model_id,
        trace='ENABLED',
        guardrailIdentifier=guardrailIdentifier,
        guardrailVersion=guardrailVersion
    )
    response_body = json.loads(response.get('body').read())
    print("Received response from InvokeModel API (Request Id: {})".format(response['ResponseMetadata']['RequestId']))
    if 'images' in response_body and len(response_body['images']) > 0:
        os.makedirs(output_images_folder, exist_ok=True)
        images = response_body["images"]
        for image in images:
            image_id = ''.join(random.choices(string.ascii_lowercase + string.digits, k=6))
            image_file = os.path.join(output_images_folder, "generated-image-{}.jpg".format(image_id))
            print("Saving generated image {} at {}".format(image_id, image_file))
            with open(image_file, 'wb') as image_file_descriptor:
                image_file_descriptor.write(base64.b64decode(image.encode('utf-8')))
    else:
        print("No images generated from model")
    guardrail_trace = response_body['amazon-bedrock-trace']['guardrail']
    guardrail_trace['modelOutput'] = ['<REDACTED>']
    print(guardrail_trace['outputs'])
    print("\nGuardrail Trace: {}".format(json.dumps(guardrail_trace, indent=2)))
except botocore.exceptions.ClientError as err:
    print("Failed while calling InvokeModel API with RequestId = {}".format(err.response['ResponseMetadata']['RequestId']))
    raise err
```

你可以从 [GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/responsible_ai/bedrock-guardrails/guardrails_image_content_filters_api.ipynb)获取完整示例。

## 结论

本文探讨了 Amazon Bedrock Guardrails 新增的图像内容过滤器如何提供全面的多模态内容审核能力。通过从纯文本过滤扩展出去，该解决方案现在帮助客户在可配置的类别（包括仇恨、侮辱、性内容、暴力、不当行为和 prompt 攻击检测）中拦截高达 88% 的有害或不需要的多模态内容。Guardrails 可以帮助医疗、制造、金融服务、媒体和教育领域的组织提升品牌安全，而无需承担构建自定义防护措施的负担，也不必进行容易出错的人工评估。

了解更多信息，请参阅[使用 Amazon Bedrock Guardrails 拦截模型中的有害内容](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)。
