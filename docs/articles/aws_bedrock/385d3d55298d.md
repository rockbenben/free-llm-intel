## [人工智能](https://aws.amazon.com/blogs/machine-learning/)

# Novo Nordisk 使用 Amazon Bedrock AgentCore 实现制造流程文档的现代化

[诺和诺德](https://www.novonordisk.com/) (Novo) 是世界领先的跨国制药公司之一，生产治疗糖尿病和肥胖症等慢性疾病的药物，并将其提供给许多国家的患者。每件产品的背后都有一个遵守严格质量要求的制造网络。每个与质量相关的流程步骤都必须通过正式文件进行描述、控制和验证。保持该文档的最新性和准确性是平板电脑领域制造技术团队的核心职责，该职责涵盖全球组织内大量且多样化的受控文档组合，包括标准操作程序、工作说明、表格和培训材料。

管理这个投资组合面临着巨大的挑战。在法规变化、流程改进、设备修改和审计结果的推动下，文档更新频繁。每次更新都需要仔细审查、结构化审批工作流程以及与所有受影响的利益相关者的及时沟通。由于数以千计的活动文档分布在多个部门、部门和产品项目中，跟踪哪些文档需要修改、等待批准或需要立即关注变得越来越复杂。目前，这种监督很大程度上依赖于手动流程和分散的跟踪方法，例如电子表格或断开连接的系统。这些方法耗时、容易出错且难以扩展。其结果是存在过时文档仍在流通、更新延迟以及合规可见性方面存在重大差距的风险。

除了文档管理之外，还存在更深层次的知识挑战。有价值的制造知识分布在许多受控文档、版本、站点和产品程序中。在正确的时间找到正确的答案通常取决于有经验的人知道去哪里寻找。这种对部落知识的依赖造成了瓶颈，减慢了决策速度，并最终影响了救生药物到达患者手中的速度。

为了应对这些挑战，平板电脑领域的制造技术团队已着手开发由代理 AI 提供支持并部署在 AWS 上的智能支持系统。目标是缩短交付周期，提高文档可见性，并使关键制造知识更容易获取，最终帮助组织更快地发展并为世界各地的更多患者提供服务。这篇文章深入探讨了为满足受监管的制药环境所需的高准确度和可追溯性标准而做出的架构和关键设计决策。该解决方案帮助主题专家 (SME) 在几分钟内完成了过去需要数小时或数天的工作。

我们还描述了一个人工智能流程智能助手，它可以通过有根据的、引用的答案来回答复杂的流程问题。该解决方案围绕 GraphRAG 架构构建，将知识图与混合搜索相结合，以检索最相关且上下文准确的信息。人工智能代理基于托管代理框架构建，可端到端协调检索和响应过程。 “引导模式”有助于在搜索开始之前澄清模棱两可的问题，从而帮助做出更准确、更站得住脚的回答。

## 挑战

支持制造的团队反复回答同一问题的不同变体：*对于该场地、该产品和该设备，该流程需要什么？* 回答得好需要同时满足四件事：

- 来自大型语料库的正确文档。
- 正确的版本和生命周期状态（已批准且有效，而不是草稿或过时）。
- 正确的范围（它实际上适用于场地、产品生成和设备）。
- 关系（哪些文档引用哪些文档，以及更改会影响什么）。

传统的关键字搜索返回文档，而不是答案，没有范围、版本或关系的概念。基于普通向量的检索增强生成 (RAG) 系统提高了对自然语言问题的召回率，但仍然难以处理准确的标识符（文档编号、设备代码）、多跳关系问题以及（最重要的是对于受监管的领域）相关内容何时不可用的识别。该团队需要一个将结构和关系视为一流的系统，立足于经批准的来源，并澄清而不是猜测。

## 解决方案概述

该助手基于 GraphRAG 架构构建：[Amazon Neptune](https://aws.amazon.com/neptune/) 中的知识图捕获结构和关系，[Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/serverless/) 中的混合搜索索引提供对文档内容的语义和精确匹配调用。这两个存储故意保持分离并在查询时桥接，而不是组合成单个引擎。这是常见的生产 GraphRAG 模式。

推理层在 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 上运行，这是一个使用任何框架或模型大规模构建、连接和优化代理的平台。 AgentCore 因其托管代理运行时而被选中，该运行时具有内置会话隔离、本机工具编排以及集成的 AWS Identity and Access Management (IAM) 和可观察性。这消除了无差异的基础设施工作，因此团队可以专注于领域逻辑。代理运行时是使用 [Strands Agents SDK](https://github.com/strands-agents) 构建的，并由 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的 [Anthropic Claude](https://aws.amazon.com/bedrock/claude/) 模型提供支持。文档通过摄取管道进行处理，该摄取管道使用 [Amazon Bedrock Data Automation](https://aws.amazon.com/bedrock/data-automation/) 进行多模式解析，并通过 [AWS Step Functions](https://aws.amazon.com/step-functions/) 和 [AWS Lambda](https://aws.amazon.com/lambda/) 进行编排。该堆栈通过 [AWS 云开发工具包 (AWS CDK)](https://aws.amazon.com/cdk/) 定义为基础设施即代码。

在较高的层面上，一个问题像这样在系统中流动：

- *查询代理*接收问题，并在引导模式下确定范围是否足够清晰以便能够很好地回答。
- 如果不明确，代理会在搜索之前提出一个简短的、基于图表的澄清问题（例如，适用哪个网站或产品代）。
- 范围明确后，混合搜索会检索候选段落，图表从这些结果扩展以添加结构和关系，并且重新排序步骤可提高精度。
- 代理根据并引用经批准的源文档撰写答案，并且在内容不可用时是明确的。

## 两层分类法：结构加领域细节

该图表围绕两个互补的层进行组织，这使得助手可以考虑文档所在的“位置”以及它的“内容”。

**高级分类：流程树。**组织的官方流程框架被建模为流程节点的层次结构（大约三个级别，从父级到子级）。每个受控文档都附加到最低的适用流程级别，因此每个已加入的文档都有一个已知的位置。这使得助手可以在检索任何内容之前将问题范围限定到流程区域，并自动对新摄取的文档进行分类。

**低级分类：领域实体。** SME 定义在制造过程中使答案正确或不正确的实体：场地、产品代、设备、流程步骤和类似属性。这些被建模为链接到描述它们的文档的一流图节点，使用一小组统一的关系类型而不是不断增长的边名称列表。

对两个层进行建模是真正的 GraphRAG 系统与“并排的两个数据库”的区别。 OpenSearch 段落上的文档编号也是图中的一个节点，因此搜索命中是图结构的直接入口点，无需模糊重新匹配。这种块到图的桥梁是检索路径中的关键设计选择。

## 为什么要采用固定的、精心策划的分类法（以及为什么这是最佳实践）

早期的 GraphRAG 工作倾向于开放式提取，让语言模型发现没有固定模式的实体。这种方法对于对庞大文本进行开放式“意义建构”非常有效，但它噪音大、难以维护且难以审核。在过去的几年里，共识已经转向本体引导的提取，使用预定义的、特定领域的模式来指导模型，这提高了专业语料库的准确性和可靠性。

对于受监管的药品生产来说，这不是妥协，而是正确的默认设置。该领域已经拥有由专家策划的真实本体，以及新实体的人机循环推广流程的固定模式，支持团队在受监管的制药环境中所需的可审核性。该设计与自早期开放模式方法以来许多领域的发展保持一致，同时使设计决策更容易向质量和审计利益相关者解释。

## 检索：混合搜索、图扩展和重新排名

每个商店都覆盖了其他商店的盲点：

- **OpenSearch 提供召回功能 –** 混合搜索将密集向量相似性（Amazon Titan Text Embeddings）与词汇 BM25 匹配相结合，并与倒数排名融合相融合。矢量搜索捕捉意义。词法匹配可以捕获此处重要的确切标记：文档编号、设备代码和多语言术语。
- **海王星提供结构 –** 鉴于实体和文档搜索浮出水面，该图回答“连接的内容、方式和距离”：相邻文档、引用、层次结构中的位置以及更改的影响，而这正是纯向量检索无法做到的。

常见的模式是*向量找到种子，图形从它们扩展，*对于关系优先的问题则相反。 “重新排名”阶段（通过 Amazon Bedrock Rerank 的交叉编码器）位于融合之后：它将问题和每个候选段落一起读取并重新排序，在任何内容到达模型之前在更便宜的召回阶段之上添加精确传递。

## 引导模式：检索前先澄清

该助手的一个独特之处在于它如何处理歧义。像“在造粒机上采集哪些样品？”这样的问题有几个正确答案，具体取决于产品生产、场地、设备和批量大小。立即回答可能会导致自信、错误、超出范围的反应，这是监管环境中最糟糕的结果。

引导模式颠倒了通常的 RAG 顺序：代理不是先检索，而是先通过澄清缩小范围，然后再搜索。这是最近关于在检索之前澄清模糊问题以及使用知识图“提供”澄清选项而不是让模型发明它们的研究的结果。它使用两类范围：

- 针对特定流程的问题，直接且一致地询问一小部分、近乎通用的属性（例如站点和产品生成）。
- 更深入的一切：随着时间的推移添加哪些设备、批量大小以及属性。这都是从查询时的图表得出的。范围解析步骤将用户的术语与真实的图节点进行匹配，根据已知的内容进行过滤，并且，如果剩余多个候选者，则仅使用图中存在的值来提供真正区分它们的属性。

这使得澄清选项以真实数据为基础（旨在帮助降低出现幻觉选项的风险），并且可以扩展：当专家向分类法添加新的区分属性时，助手会自动显示它，而不需要更改提示或代码。

## 在受监管的环境中扎根和信任

这里的准确性被狭隘地定义并刻意强制执行：

- **显式索引状态 –** 文档可以存在于图表中，并具有元数据、关系，并且在其内容可搜索之前位于层次结构中。确定性标志跟踪文档的内容是否被索引，因此助手可以区分“我有这个文档的内容”和“我只有它的元数据”，而不是从空搜索结果中推断可用性。
- **默认批准来源 -** 答案依赖于批准且有效的文件和最新适用版本，除非用户明确要求提供草稿或历史修订。
- **反幻觉规则 –** 澄清选项和引用的声明旨在来自实际的工具结果，而不是模型自己的知识。
- **规定的限制 –** 当检索到的材料丢失或不明确时，助理会在需要 SME、质量或监管审查时进行说明，而不是填补空白并进行标记。

自动评估工具根据以下标准检查响应：相关源选择、有效文档状态、最新适用版本、范围合规性、引用准确性以及忠实保留需求强度（必须、应该或可能），以便可以随着系统的发展来衡量行为。

## 一个可搜索数百万份文档的智能搜索引擎

该解决方案拥有更宽的保险库，可存放约 400 万份文档。在这种规模下，问题不是缺乏信息，而是几乎不可能手动找到完全正确的、范围内的、当前的答案。传统的企业搜索会返回按关键字重叠排名的长列表，并将艰苦的工作留给询问者。这包括决定适用哪个结果、哪个版本有效以及文档如何关联。

该解决方案将金库变成一个智能的、答案优先的搜索引擎，而两层分类法使其易于大规模处理：

- **图表是完整地图，索引是可搜索子集。** 所有注册域中的每个已加入文档及其元数据、关系和层次结构位置都放置在图表中。这意味着助手可以推断文档所在的位置以及它如何连接，即使对于数以百万计的内容尚未建立索引的人也是如此。全文内容针对已加入的域进行索引，增量添加，并且助手可以明确区分哪个是哪个。
- **范围缩小了检索前的搜索空间。** 由于引导模式预先解决了场地、产品生成、流程区域和设备问题，因此问题会被过滤到可以回答问题的一小部分库中。系统搜索范围内的文档很少，而不是数百万。随着语料库的增长，这有助于保持答案的精确性。
- **混合搜索加图形扩展超越了关键字排名**，显示排名列表永远不会显示的相关文档、参考文献和层次结构，并返回一个有根据的引用答案（不是十个蓝色链接），同时指出内容不可用。

该设计的目的是随着金库的增长而扩展，而不是随着它的增长而退化：文档越大、相互关联越多，图表和范围界定的价值就越大。

## 结果

根据中小企业正在执行的任务类型（搜索答案、更新文档或根据新环境调整文档），过去需要数小时或数天的工作可以减少到几分钟。除了节省原始时间之外，该解决方案还改变了实际要做的事情：

- **浏览团队的流程环境 –** 用户可以通过一个助手在流程分类的所有三个级别之间移动，涵盖大约 400 万个文档及其许多子流程，该助手既充当搜索引擎，又充当文档、流程和组织图的指南。
- **整合结构化和非结构化数据 –** 元数据、流程层次结构和文档内容被统一到一个可搜索的知识图谱中，因此可以一起查询曾经存在于不同系统中的信息。
- **理解实体和文档之间的关系 –** 图表帮助用户询问文档、流程、设备、站点和产品如何连接，包括手动搜索无法回答的多跳问题。
- **端到端跟踪和验证引用 –** 该解决方案可以映射文档的完整引用链，并标记文档指向过时或被取代材料的位置，从而在整个语料库中显示完整性问题，而不是一次一个文档。
- **扩展到进一步的人工智能和代理功能 -** 相同的基础为文档生成、影响分析修订以及其他代理工作流程重用相同的图形、检索和护栏等功能打开了大门，而不是从头开始。

在受监管的环境中同样重要的是，助理的设计旨在澄清范围并标记缺失或模糊的内容，有助于降低自信、超出范围的答案的风险，而这正是错误的真正成本所在。

## 协作交付模型

平板电脑领域的 Novo Manufacturing Technology 团队与 AWS 合作构建了此解决方案，主题专家以及数据和 AI 工程师在整个过程中密切合作。使助手准确的分类法直接来自该小组的领域专家。检索和代理架构是使用 AWS 设计和迭代的。

构建原型是解决方案投入使用的关键。该团队并没有抽象地讨论功能，而是尽早将一个工作系统摆在主题专家面前。他们针对真实问题对其进行了测试，并利用所学到的知识来强化分类、检索路径和引导模式行为。该原型将一个雄心勃勃的想法变成了人们可以尝试、批评和信任的东西。它还在更广泛的推广之前降低了架构决策的风险。

＃＃ 结论

通过在 Amazon Bedrock AgentCore 上结合精选知识图、混合搜索和检索前澄清代理，平板电脑领域的 Novo Manufacturing Technology 团队构建了一个流程智能助手，该助手在速度有帮助的情况下快速，在准确性重要的情况下立足。该设计将当前的 GraphRAG 模式应用于受监管的制造：本体引导的提取、桥接的两存储检索路径、基于图形的消歧和重新排名。这将大型文档景观转变为接地气的、引用的答案，并有扩展到新领域的空间。
