# 使用 Amazon OpenSearch ML connector API

在把数据摄取到 [Amazon OpenSearch](https://aws.amazon.com/opensearch-service/) 时，客户往往需要在把数据写入索引之前对其进行增强。例如，你可能在摄取带有 IP 地址的日志文件，并希望获得该 IP 地址的地理位置；或者你正在摄取客户评论，并希望识别这些评论使用的是哪种语言。传统做法需要引入一个外部流程，这会让数据摄取 pipeline 变得复杂，还可能导致 pipeline 失败。OpenSearch 提供了大量[第三方机器学习（ML）connector](https://opensearch.org/docs/latest/ml-commons-plugin/remote-models/connectors/#supported-connectors)来支持这类增强。

本文重点介绍其中两个第三方 ML connector。我们演示的第一个 connector 是 [Amazon Comprehend](https://aws.amazon.com/comprehend/) connector。本文展示如何使用这个 connector 调用 LangDetect API，以检测所摄取文档的语言。

我们演示的第二个 connector 是 [Amazon Bedrock](https://aws.amazon.com/bedrock/) connector，用于调用 Amazon Titan Text Embeddings v2 模型，以便从所摄取的文档创建 embedding 并执行语义搜索。

## 解决方案概览

我们使用 [Amazon OpenSearch](https://aws.amazon.com/opensearch-service/) 配合 [Amazon Comprehend](https://aws.amazon.com/comprehend/) 来演示语言检测功能。为便于你复现这一环境，我们提供了必要的源代码、一个 [Amazon SageMaker](https://aws.amazon.com/sagemaker/) notebook，以及一个 [AWS CloudFormation](https://aws.amazon.com/cloudformation) 模板。你可以在 [https://github.com/aws-samples/sample-opensearch-ml-rest-api](https://github.com/aws-samples/sample-opensearch-ml-rest-api) GitHub 仓库中找到这些资源。

## 第 1 部分：Amazon Comprehend ML connector

### 配置 OpenSearch 以访问 Amazon Comprehend

在使用 Amazon Comprehend 之前，你需要确保 OpenSearch 能够调用 Amazon Comprehend。做法是为 OpenSearch 提供一个有权调用 `DetectDominantLanguage` API 的 IAM 角色。这要求 OpenSearch 集群启用细粒度访问控制（fine grained access control）。CloudFormation 模板为此创建了一个名为 `<Your Region>-<Your Account Id>-SageMaker-OpenSearch-demo-role` 的角色。请按以下步骤将该角色附加到 OpenSearch 集群。

- 打开 OpenSearch Dashboard 控制台——你可以在 CloudFormation 模板的输出中找到该 URL——并使用你设置的用户名和密码登录。![OpenSearch Dashboards 落地页，包含导航侧栏、可视化工具与数据管理选项](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/19/ML-17073_os-dashboard-2.png)

- 在安全菜单中，选择 **Roles** 以管理 OpenSearch 角色。![OpenSearch 角色 dashboard，带有详细权限矩阵，展示安全分析、告警与快照管理访问控制](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/19/ML-17073_os-roles-4.png)

#### 配置指向 Amazon Comprehend 的 OpenSearch ML connector

在这一步中，你配置 ML connector，把 Amazon Comprehend 连接到 OpenSearch。

- 获取一个授权 token，用于从 SageMaker notebook 向 OpenSearch 发起调用。该 token 使用 CloudFormation 模板附加到 notebook 上的 IAM 角色，该角色具有调用 OpenSearch 的权限。同一个角色也以你刚才映射角色以访问 Amazon Comprehend 的相同方式，被映射到 OpenSearch 管理员角色。使用以下代码完成设置：

```
awsauth = AWS4Auth(credentials.access_key,
credentials.secret_key,
region,
'es',
session_token=credentials.token)
```

- 创建 connector。它需要几项信息：它需要协议（protocol）。在本示例中，使用 `aws_sigv4`，它允许 OpenSearch 使用 IAM 角色调用 Amazon Comprehend。提供该角色的 ARN，也就是你用来为 `ml_full_access` 角色设置权限的同一个角色。将 `comprehend` 作为 `service_name`、`DetectDominateLanguage` 作为 `api_name` 提供。提供 Amazon Comprehend 的 URL，并配置如何调用该 API 以及向它传递什么数据。

最终调用如下：

```
comprehend = boto3.client('comprehend', region_name='us-east-1')
path = '/_plugins/_ml/connectors/_create'
url = host + path

payload = {
  "name": "Comprehend lang identification",
  "description": "comprehend model",
  "version": 1,
  "protocol": "aws_sigv4",
  "credential": {
    "roleArn": sageMakerOpenSearchRoleArn
  },
  "parameters": {
    "region": "us-east-1",
    "service_name": "comprehend",
    "api_version": "20171127",
    "api_name": "DetectDominantLanguage",
    "api": "Comprehend_${parameters.api_version}.${parameters.api_name}",
    "response_filter": "$"
  },
  "actions": [
    {
      "action_type": "predict",
      "method": "POST",
      "url": "https://${parameters.service_name}.${parameters.region}.amazonaws.com",
      "headers": {
        "content-type": "application/x-amz-json-1.1",
        "X-Amz-Target": "${parameters.api}"
      },
      "request_body": "{\"Text\": \"${parameters.Text}\"}" 
    }
  ]
}

comprehend_connector_response = requests.post(url, auth=awsauth, json=payload)
comprehend_connector = comprehend_connector_response.json()["connector_id"]
```

payload = {

### 创建一个使用 Amazon Comprehend API 标注语言的 ingest pipeline

下一步是在 OpenSearch 中创建一个 pipeline，调用 Amazon Comprehend API，并把调用结果添加到正在被索引的文档中。为此，你需要同时提供 `input_map` 和 `output_map`。你用它们告诉 OpenSearch：要向 API 发送什么，以及如何处理调用返回的内容。

```
path = '/_ingest/pipeline/comprehend_language_identification_pipeline'
url = host + path

payload = {
  "description": "ingest identify lang with the comprehend API",
  "processors":[
    {
      "ml_inference": {
        "model_id": comprehend_model_id,
        "input_map": [
            {
               "Text": "Text"
            }
        ],
        "output_map": [
            {  
               "detected_language": "response.Languages[0].LanguageCode",
               "language_score": "response.Languages[0].Score"
            }
        ]
      }
    }
  ]
}
headers = {"Content-Type": "application/json"}
response = requests.put(url, auth=awsauth, json=payload, headers=headers)
```

从以上代码可以看到，你从 Amazon Comprehend 取回了得分最高的语言结果及其分数，并把这些字段添加到文档中。

## 第 2 部分：Amazon Bedrock ML connector

在本节中，你通过 ml-commons 插件，使用 Amazon OpenSearch 配合 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 来执行多语言语义搜索。在尝试本节内容之前，请确认解决方案的先决条件已就绪。

在为你部署的 SageMaker 实例中，你可以看到以下文件：`english.json`、`french.json`、`german.json`。

这些文档包含各自语言的句子，讨论 *spring* 一词在不同语境下的用法。这些语境包括 spring 作动词表示突然移动、作名词表示春季，以及最后作名词表示机械部件。在本节中，你使用面向 Amazon Bedrock 的 ml connector 部署 [Amazon Titan Text Embeddings model v2](https://aws.amazon.com/about-aws/whats-new/2024/04/amazon-titan-text-embeddings-v2-amazon-bedrock/)。然后，你通过摄取不同语言的 JSON 文件，用这个 embedding 模型为三种语言的文本创建向量。最后，这些向量存储在 Amazon OpenSearch 中，使语义搜索能够跨这些语言集合使用。

Amazon Bedrock 通过单一的 API 接口，为各类强大的 AI 基础模型提供简化的访问方式。这项托管服务包含来自 Amazon 以及其他领先 AI 公司的模型。你可以测试不同模型，找到最契合自身需求的理想选择，同时保持安全、隐私与负责任的 AI 实践。该服务让你可以通过微调（fine-tuning）和检索增强生成（Retrieval Augmented Generation，RAG）等方法，用自己的数据定制这些模型。此外，你还可以使用 Amazon Bedrock 创建能够与企业系统和数据交互的 AI agent，这使它成为开发生成式 AI 应用的综合解决方案。

![展示 OpenSearch、SageMaker Notebook 与 Bedrock ML 之间文档摄取与处理流程的 AWS 架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/19/ML-17073_arch-diagram-9.png)

上图展示的参考架构给出了本解决方案所使用的组件。

（1）首先，我们必须在 Amazon SageMaker notebook 中运行代码来创建 OpenSearch ML connector。connector 本质上是对任意模型发起 REST API 调用，这里我们特别想创建一个调用 Amazon Bedrock 中 Titan Embeddings 模型的 connector。

（2）接下来，我们必须创建一个索引，以便随后把语言文档索引进去。创建索引时，你可以指定它的 mapping、setting 和 alias。

（3）在 Amazon OpenSearch 中创建索引后，我们希望创建一个 OpenSearch Ingestion pipeline，以便简化索引所需的数据处理与准备工作，让数据更易于管理和使用。（4）现在我们已经创建了索引并设置好 pipeline，可以开始把文档索引到该 pipeline 中。

（5 – 6）我们使用 OpenSearch 中那个调用 Titan Embeddings 模型 API 的 pipeline。我们把语言文档发送给 Titan embeddings 模型，模型返回这些句子的向量 embedding。

（7）我们把向量 embedding 存储在索引中，并执行向量语义搜索。

虽然本文只重点介绍整体解决方案中的部分环节，但 SageMaker notebook 中包含了自行运行完整 demo 所需的代码和说明。

在使用 Amazon Bedrock 之前，你需要确保 OpenSearch 能够调用 Amazon Bedrock。

### 将 JSON 文档中的句子加载到 dataframe

首先把 JSON 文档中的句子加载到 dataframe 中，以获得更结构化的组织方式。每一行可以包含文本、embedding 以及额外的上下文信息：

```
import json
import pandas as pd

def load_sentences(file_name):
    sentences = []
    with open(file_name, 'r', encoding='utf-8') as file:
        for line in file:
            try:
                data = json.loads(line)
                if 'sentence' in data and 'sentence_english' in data:
                    sentences.append({
                        'sentence': data['sentence'],
                        'sentence_english': data['sentence_english']
                    })
            except json.JSONDecodeError:
                # Skip lines that are not valid JSON (like the index lines)
                continue
    
    return pd.DataFrame(sentences)

# Usage
german_df = load_sentences('german.json')
english_df = load_sentences('english.json')
french_df = load_sentences('french.json')
# print(french_df.head())
```

### 创建指向 Amazon Bedrock 的 OpenSearch ML connector

把 JSON 文档加载到 dataframe 之后，你就可以设置 OpenSearch ML connector，把 Amazon Bedrock 连接到 OpenSearch。

- connector 需要以下信息。它需要协议。本解决方案使用 `aws_sigv4`，它允许 OpenSearch 使用 IAM 角色调用 Amazon Bedrock。提供前面用于为 `ml_full_access` 角色设置权限的同一角色。提供 `service_name`、模型、模型维度（dimensions）以及 embedding 类型。

最终调用如下所示：

```
payload = {
  "name": "Amazon Bedrock Connector: embedding",
  "description": "The connector to bedrock Titan embedding model",
  "version": 1,
  "protocol": "aws_sigv4",
  "parameters": {
    "region": "us-east-1",
    "service_name": "bedrock",
    "model": "amazon.titan-embed-text-v2:0",
    "dimensions": 1024,
    "normalize": True,
    "embeddingTypes": ["float"]
  },
  "credential": {
    "roleArn": sageMakerOpenSearchRoleArn
  },
  "actions": [
    {
      "action_type": "predict",
      "method": "POST",
      "url": "https://bedrock-runtime.${parameters.region}.amazonaws.com/model/${parameters.model}/invoke",
      "headers": {
        "content-type": "application/json",
        "x-amz-content-sha256": "required"
      },
      "request_body": "{ \"inputText\": \"${parameters.inputText}\", \"dimensions\": ${parameters.dimensions}, \"normalize\": ${parameters.normalize}, \"embeddingTypes\": ${parameters.embeddingTypes} }",
      "pre_process_function": "connector.pre_process.bedrock.embedding",
      "post_process_function": "connector.post_process.bedrock.embedding"
    }
  ]
}

bedrock_connector_response = requests.post(url, auth=awsauth, json=payload, headers=headers)

bedrock_connector_3 = bedrock_connector_response.json()["connector_id"]
print('Connector id: ' + bedrock_connector_3)
```

### 创建使用 Amazon Titan Embeddings 模型的索引 pipeline

在 OpenSearch 中创建一个 pipeline。你用这个 pipeline 告诉 OpenSearch，把需要生成 embedding 的字段发送给 embedding 模型。

```
pipeline_name = "titan_embedding_pipeline_v2"
url = f"{host}/_ingest/pipeline/{pipeline_name}"

pipeline_body = {
    "description": "Titan embedding pipeline",
    "processors": [
        {
            "text_embedding": {
                "model_id": bedrock_model_id,
                "field_map": {
                    "sentence": "sentence_vector"
                }
            }
        }
    ]
}

response = requests.put(url, auth=awsauth, json=pipeline_body, headers={"Content-Type": "application/json"})
print(response.text)
```

### 创建索引

pipeline 就位后，下一步是创建一个将使用该 pipeline 的索引。索引中有三个字段：

- `sentence_vector` – 这是向量 embedding 从 Amazon Bedrock 返回后存储的位置。
- `sentence` – 这是非英语的原始句子。
- `sentence_english` – 这是该句子的英文翻译。包含这个字段是为了观察模型对原句的翻译效果。

```
index_name = 'bedrock-knn-index-v2'
url = f'{host}/{index_name}'
mapping = {
    "mappings": {
        "properties": {
            "sentence_vector": {
                "type": "knn_vector",
                "dimension": 1024,  
                "method": {
                    "name": "hnsw",
                    "space_type": "l2",
                    "engine": "nmslib"
                },
                "store":True
            },
            "sentence":{
                "type": "text",
                "store": True
            },
            "sentence_english":{
                "type": "text",
                "store": True
            }
        }
    },
    "settings": {
        "index": {
            "knn": True,
            "knn.space_type": "cosinesimil",
            "default_pipeline": pipeline_name
        }
    }
}

response = requests.put(url, auth=awsauth, json=mapping, headers={"Content-Type": "application/json"})
print(f"Index creation response: {response.text}")
```

### 将 dataframe 加载到索引中

在本节前面，你已经把 JSON 文档中的句子加载到了 dataframe 中。现在，你可以索引这些文档，并使用 Amazon Titan Text Embeddings Model v2 为它们生成 embedding。embedding 将存储在 `sentence_vector` 字段中。

```
index_name = "bedrock-knn-index-v2"

def index_documents(df, batch_size=100):
    total = len(df)
    for start in range(0, total, batch_size):
        end = min(start + batch_size, total)
        batch = df.iloc[start:end]

        bulk_data = []
        for _, row in batch.iterrows():
            # Prepare the action metadata
            action = {
                "index": {
                    "_index": index_name
                }
            }
            # Prepare the document data
            doc = {
                "sentence": row['sentence'],
                "sentence_english": row['sentence_english']
            }
            
            # Add the action and document to the bulk data
            bulk_data.append(json.dumps(action))
            bulk_data.append(json.dumps(doc))

        # Join the bulk data with newlines
        bulk_body = "\n".join(bulk_data) + "\n"

        # Send the bulk request
        bulk_url = f"{host}/_bulk"
        response = requests.post(bulk_url, auth=awsauth, data=bulk_body, headers={"Content-Type": "application/x-ndjson"})

        if response.status_code == 200:
            print(f"Successfully indexed batch {start}-{end} of {total}")
        else:
            print(f"Error indexing batch {start}-{end} of {total}: {response.text}")

        # Optional: add a small delay to avoid overwhelming the cluster
        time.sleep(1)

# Index your documents
print("Indexing German documents:")
index_documents(german_df)
print("\nIndexing English documents:")
index_documents(english_df)
print("\nIndexing French documents:")
index_documents(french_df)
```

### 跨文档执行语义 k-NN

最后一步是在文档之间执行 k 近邻（k-NN）搜索。

```
# Define your OpenSearch host and index name
index_name = "bedrock-knn-index-v2"
def semantic_search(query_text, k=5):
    search_url = f"{host}/{index_name}/_search"
    # First, index the query to generate its embedding
    index_doc = {
        "sentence": query_text,
        "sentence_english": query_text  # Assuming the query is in English
    }
    index_url = f"{host}/{index_name}/_doc"
    index_response = requests.post(index_url, auth=awsauth, json=index_doc, headers={"Content-Type": "application/json"})
    
    if index_response.status_code != 201:
        print(f"Failed to index query document: {index_response.text}")
        return []
    
    # Retrieve the indexed query document to get its vector
    doc_id = index_response.json()['_id']
    get_url = f"{host}/{index_name}/_doc/{doc_id}"
    get_response = requests.get(get_url, auth=awsauth)
    query_vector = get_response.json()['_source']['sentence_vector']
    
    # Now perform the KNN search
    search_query = {
        "size": 30,
        "query": {
            "knn": {
                "sentence_vector": {
                    "vector": query_vector,
                    "k": 30
                }
            }
        },
        "_source": ["sentence", "sentence_english"]
    }

    search_response = requests.post(search_url, auth=awsauth, json=search_query, headers={"Content-Type": "application/json"})
    
    if search_response.status_code != 200:
        print(f"Search failed with status code {search_response.status_code}")
        print(search_response.text)
        return []

    # Clean up - delete the temporary query document
    delete_url = f"{host}/{index_name}/_doc/{doc_id}"
    requests.delete(delete_url, auth=awsauth)

    return search_response.json()['hits']['hits']

# Example usage
query = "le soleil brille"
results = semantic_search(query)

if results:
    print(f"Search results for: '{query}'")
    for result in results:
        print(f"Score: {result['_score']}")
        print(f"Sentence: {result['_source']['sentence']}")
        print(f"English: {result['_source']['sentence_english']}")
        print()
else:
    print("No results found or search failed.")
```

## 使用 ML connector 集成机器学习模型与 OpenSearch 的好处

有多种方式可以执行 k-nn 语义向量搜索；一种流行做法是把外部的 Hugging Face sentence transformer 模型部署到 SageMaker endpoint。以下是本文所示 ML connector 方法的优势，以及为什么应当用它而不是把模型部署到 SageMaker endpoint：

- 架构更简单  单一系统统一管理  与 OpenSearch 原生集成  更简单的部署  统一监控

- 运维优势  需要维护的基础设施更少  随 OpenSearch 内置的扩展能力  更简单的安全模型  直接明了的更新与维护

- 成本效率  单一系统的成本  按使用量付费的 Amazon Bedrock 定价  没有 endpoint 管理成本  更简单的计费
