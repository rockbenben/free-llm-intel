# 使用 Amazon Nova Act 构建意图驱动的 UI 测试

为了在其产品团队中扩展意图驱动的 UI 测试，[Epsilon](https://www.epsilon.com/)（一家数据、技术和营销服务公司，也是 [Publicis Groupe](https://www.publicisgroupe.com/) 的一部分）求助于 [Amazon Nova Act](https://aws.amazon.com/nova/act/)。拥有数亿消费者档案和数千个品牌关系，Epsilon 需要能够跟上快速应用程序变化的 UI 测试。该解决方案无法为每个产品团队带来维护费用。

在 Epsilon 内部，Agentic Platform 团队（50 名工程师）构建共享基础设施，以便其他产品团队可以安全地构建、部署、管理和运行 AI 代理。通过这个共享平台，团队可以获得基于技能的代理构建器。他们还获得联合身份和飞行前授权、模型上下文协议 (MCP) 集成以及跨账户配置。当产品团队想要采用人工智能工具时，他们无需额外配置即可获得功能，也无需自行重新解决身份、安全、浏览器基础设施或模型集成问题。

这些托管功能之一是*UI 测试*。借助 [Amazon Nova Act](https://aws.amazon.com/nova/act/) 和 [Amazon Bedrock AgentCore 浏览器](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html)（Amazon Bedrock AgentCore 的一项功能），Epsilon 的平台团队可以向平台上的团队提供弹性、意图驱动的测试服务。

在这篇文章中，我们将介绍 Epsilon 以托管平台服务形式提供 UI 测试的架构，展示核心 Nova Act 和 Amazon Bedrock AgentCore 浏览器工具集成代码，重点介绍具体的 18 步骤测试工作流程，并分享最佳实践和测量结果。

## 挑战：扩大覆盖范围，而不是取代有效的内容

Epsilon 现有的 UI 测试实践并未被打破。该团队维护了一个“基于 Playwright 的回归套件”，用于验证其 Web 应用程序的功能，并且效果良好。今天，剧作家仍然是他们回归的支柱。

Epsilon 发现的机会是附加的，而不是纠正的：

- **脚本化剧作家测试**对于确定性回归检查非常有效。然而，它们与选择器和页面结构紧密耦合。即使底层功能健全，表面的 UI 更改也可能会破坏它们。
- **多个产品团队**需要针对自己的应用程序进行全面的测试。建立浏览器基础设施、管理依赖关系以及与每个团队的身份系统集成会产生重复的工作。
- 平台团队希望 UI 测试成为适合其现有代理模型的**托管功能**，而不是每个入职团队都必须操作的自定义 CLI。

目标：在现有 Playwright 回归套件之上分层**基于意图的测试**。将其作为多租户平台服务提供，以便每个 Epsilon 产品团队都可以通过用于所有其他代理功能的相同 API 界面进行使用。

## 为什么 Epsilon 选择 Amazon Nova Act 和 Amazon Bedrock AgentCore 浏览器工具

Epsilon 根据两个要求评估了选项：自然语言测试编写（以补充基于选择器的 Playwright 测试）和托管浏览器基础设施（以适应其多租户平台模型）。借助 Amazon Nova Act 与 Amazon Bedrock AgentCore 浏览器工具的结合，Epsilon 可以解决这两个问题。

- **自然语言步骤。** 测试步骤是由 Nova Act 执行的简单英语指令。它们能够适应外观 UI 更改，并且可供非工程师阅读。像“确认奖励余额可见”* 这样的步骤比脆弱的 CSS 选择器要好得多。
- **AWS 托管的临时浏览器会话。** 借助 Amazon Bedrock AgentCore 浏览器工具，团队可以获得独立的浏览器实例，无需交付二进制文件，也无需维护显示服务器。 Amazon Bedrock AgentCore 浏览器工具还提供用于人工观察或接管的实时视图（对于验证码或多因素身份验证有用）、将会话记录到 Amazon Simple Storage Service (Amazon S3) 以及 AWS CloudTrail 审计，所有这些都无需额外配置。
- **基于 AWS Identity and Access Management (AWS IAM) 的身份验证。** 借助 Nova Act，您可以通过标准 AWS 凭证链（任务角色）进行身份验证。这符合 Epsilon 现有的安全模型，无需分发单独的 API 密钥。
- **跨账户友好。** 借助 Nova Act 和 Amazon Bedrock AgentCore 浏览器工具，您可以插入现有的 AWS Security Token Service (AWS STS) AssumeRole 配置。每个入职团队都可以在自己的 AWS 账户内以指定的角色运行测试。这可以保持隔离性和可审计性。

Epsilon 特别选择 Amazon Bedrock AgentCore 浏览器工具，因为它消除了管理浏览器二进制文件、显示服务器和会话生命周期的操作负担。 Agentic Platform 团队对拥有该基础设施没有兴趣。

## 解决方案：架构和实现

Epsilon 的解决方案包含三个主要组件：用于创建工作流程的平台 API、用于执行工作流程的后台任务运行程序，以及驱动浏览器的 Nova Act 和 Amazon Bedrock AgentCore 浏览器工具集成。

### 平台架构

Epsilon 的 UI 测试能力遵循清晰的流程：

- 用户通过平台 API 创建工作流程，指定“target_url”和自然语言步骤列表。
- 创建时，平台会在 AWS 上注册 Nova Act 工作流程定义。
- 执行时，后台任务运行程序（[Celery](https://docs.celeryq.dev/)，用于异步作业处理的 Python 框架）会打开 Amazon Bedrock AgentCore 浏览器工具浏览器会话。它通过 Nova Act 通过 [Chrome DevTools Protocol (CDP)](https://chromedevtools.github.io/devtools-protocol/) WebSocket（以编程方式控制 Chromium 浏览器的标准接口）运行每个步骤，包括条件逻辑（例如，*“如果出现旅行盒，则跳过它”*）。
- 系统捕获每个步骤的屏幕截图，跟踪每个步骤的通过/失败，计算总体通过率，并存储所有内容（结果 JSON、Amazon S3 中的屏幕截图、会话 ID）。
- 完成钩子触发，因此结果被记录回平台。

该功能作为标准代理（“ui-test-agent”）公开，具有两种技能：

- **ui-test-recorder**：交互式探索场景并记录自然语言步骤。
- **ui-test-executor**：运行记录的步骤并返回结构化结果。

入职团队使用 UI 测试的方式与使用任何其他平台代理的方式相同。无需管理额外的基础设施。入职流程非常简单。平台团队为新团队提供跨账户 IAM 角色，注册其目标应用程序 URL，并通过现有平台 API 授予对“ui-test-agent”的访问权限。从那时起，团队创建工作流程、触发执行并通过他们已用于其他平台功能的相同界面检索结果。

### 核心集成

Nova Act + Amazon Bedrock AgentCore 浏览器工具集成非常简洁：
```
import boto3
from bedrock_agentcore.tools.browser_client import browser_session
from nova_act import NovaAct

boto_session = boto3.Session(region_name=region)

with browser_session(region) as client:
    ws_url, headers = client.generate_ws_headers()
    with NovaAct(
        cdp_endpoint_url=ws_url,
        cdp_headers=headers,
        boto_session=boto_session,
        starting_page=url
    ) as nova_act:
        result = nova_act.act(instruction)
```
此模式（打开托管浏览器会话、通过 CDP WebSocket 连接并使用自然语言驱动操作）是基础。 Epsilon 将其与其平台的多租户编排、结果捕获和可观察层结合起来。

### 示例：自动化“创建代理”流程

为了说明基于意图的测试，以下是 Epsilon 平台的代表性工作流程。它执行登录、表单输入、条件处理、滚动和验证。以下步骤强调了 Nova Act 的差异化模式：

| **步骤** | **说明** |
| ---| ---|
| 1 |输入用户名并选择 **下一步** |
| 2 |输入密码并选择**验证** |
| 3 |导航至 **创建代理** 并选择 **设计新规范** 卡 |
| 4 |如果出现入门导览框，请选择 **跳过导览**，然后验证加载的页面是否正确 |
| 5 |填写代理名称和描述字段 |
| 6 |向下滚动直到 **目标陈述** 字段可见，然后填写 |
| 7 |如果技能搜索框不可见，请滚动直至出现。然后搜索并添加技能 |
| 8 |选择 **保存**，确认成功提示，导航回来，并验证新代理是否出现在列表中 |

步骤 4 和 7 演示了*条件逻辑*：“如果元素出现，则处理它”和“如果目标不可见，则滚动直到它可见”。这些模式需要在传统框架中进行显式分支。 Nova Act 通过语言理解自然地处理它们。

### 运行时隔离

Epsilon 在*专用运行程序服务*（FastAPI sidecar）中运行 UI 测试，该服务通过工作流和 IAM 身份验证支持固定“nova-act”3.x，以及 Amazon Bedrock AgentCore 浏览器工具客户端。这使得依赖项与主后端分离，这样它们就不会与 Strands 代理堆栈发生冲突。如果运行器被禁用，工作线程将回退到进程内执行，从而在部署期间提供弹性。

## 最佳实践

根据将 UI 测试构建为平台功能的经验，Epsilon 团队建议：

### 1. 将步骤写为意图，而不是机制
```
GOOD: "Confirm the rewards balance is visible"
BAD: await page.locator('#rewards-balance-container > span.amount').toBeVisible()
```
基于意图的步骤在 UI 重新设计中仍然存在。可能不会编写代码的产品经理和质量保证 (QA) 主管可以直接审查它们。

### 2. 隔离 Nova Act 运行时

将 Nova Act 和 Amazon Bedrock AgentCore 浏览器工具依赖项固定在专用服务或容器中。 Epsilon 了解到，Nova Act 的签名端点以“us-east-1”为目标，无论浏览器会话位于哪个区域。在具有自己的依赖项锁定文件的单独服务中运行它可以防止难以调试的冲突。

### 3. 重用记录的轨迹以降低成本

Epsilon 在**草稿状态**使用轨迹重试，保存成功的轨迹，并在**活动状态**重放它。重复运行会跳过冗余的大型语言模型 (LLM)“思考”，从而减少回归式重复执行的延迟和成本。

### 4. 从第一天开始就进行多租户设计

将跨账户 AssumeRole 与限定范围的 IAM 策略结合使用。每个租户的测试都在自己的帐户中以自己的角色运行。这提供了隔离、可审计性和故障范围遏制，无需为每个团队定制基础设施。

### 5. 依靠托管可观察性

借助 Amazon Bedrock AgentCore 浏览器工具，团队可以获取实时视图、会话记录和 AWS CloudTrail 集成。 Epsilon 使用这些内置功能而不是构建自定义可观察性，减少维护并为合规团队提供熟悉的审计界面。

### 6. Amazon Bedrock AgentCore 浏览器工具视口行为的帐户

提示 Nova Act 步骤时，请考虑 Amazon Bedrock AgentCore 浏览器工具的浏览器视口默认值。引用滚动的步骤（例如，“向下滚动直到可见目标陈述文本框”）验证 Nova Act 是否正确处理页面下部的内容。

## 结果和影响

Epsilon 的 UI 测试功能可跨多个团队运行，多租户架构已在生产中得到验证。

| **尺寸** | **亚马逊新星法案** | **剧作家（同等）** |
| ---| ---| ---|
|创作的台词 | 18 个自然语言步骤 |约 80-150 行代码 |
|选择器/DOM 检查 |无 |每个交互步骤都需要 |
|创作时间（每个工作流程）| 〜5-10 分钟 |约 30-90 分钟 |
|努力比|基线| **4-6 倍的努力** |

以下是测量结果：

- **测试创作速度加快 4-6 倍（基于 Epsilon 的内部基准）。** 使用 Nova Act 创作具有代表性的 18 步工作流程需要 5-10 分钟，而同等 Playwright 脚本（80-150 行代码）则需要 30-90 分钟。 Playwright 脚本中的每个交互步骤都需要检查 DOM、选择稳定的选择器，并针对条件情况编写显式等待、断言和分支。 Nova Act 用 18 条自然语言指令和零选择器或 DOM 检查取代了每步开销，并用简单的英语表达了条件逻辑（例如旅行盒和滚动直到可见步骤）。
- **轨迹重放的通过率为 100%（基于 Epsilon 的内部** **基准）。** 工作流程通过初始探索阶段（通常为 4-5 次提示迭代）后，Epsilon 会保存成功的轨迹并确定性地重放。保存的轨迹在重复运行中达到 100% 的通过率。
- **降低测试编写的障碍。** 步骤读起来就像简单的英语。核心测试工程师之外的团队成员可以阅读、审查和提出测试，从而扩大质量所有权。
- **内置审计跟踪。** AWS CloudTrail 集成和 Amazon Bedrock AgentCore 浏览器工具会话记录使调试和合规性对话变得更加容易。这是团队最初并未打算实现的好处。
- **每团队基础设施开销为零。** 入职团队通过与其他平台代理相同的 API 界面进行 UI 测试。没有浏览器二进制文件，没有 Selenium 网格，没有要管理的显示服务器。
- **每个步骤的通过/失败可见性。** 每个步骤的屏幕截图提供了精细的调试上下文，减少了诊断故障的平均时间。
