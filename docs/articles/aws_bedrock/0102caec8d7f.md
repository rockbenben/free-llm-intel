# Amazon Bedrock 上线 Kimi K3 的印度境内推理

Kimi K3 是一个多模态的开放权重基础模型（FM），服务商 Moonshot AI 报告称它在发布时达到了前沿水平的编码能力与通用 agentic 智能。

除全球推理与美国境内推理之外，[Amazon Bedrock](https://aws.amazon.com/bedrock/) 现在还支持 Kimi K3 在印度的境内推理：让那些对数据驻留有严格要求的本地工作负载得以解锁。[Ultrahuman](https://www.ultrahuman.com/) 这样的客户已经在生产环境里尝到了好处：

> “Ultrahuman 应用里的 AI 健康与养生助手 Jade，用每个人自己的 Ring 与血糖数据，以平实的语言回答问题，每天要处理超过 14,000 次对话。Amazon Bedrock 上的 Kimi K3 让我们通过已经在用的 API 就接入了一个领先的开放权重模型，健康数据始终留在 AWS 内部，并把 Mumbai 作为 fallback Region。借助 prompt 缓存，我们把 LLM 成本降低了 80%，多轮对话快了 85%。”
>         — Aditya Patawari, VP Engineering, Ultrahuman

本文会解释可用的各种全球与地理 inference 选项，并给出一个示例用例的代码：对印度语系文档做光学字符识别（OCR）与理解，再用 code-mixed 的 Hinglish 回答追问。

## 选择推理可以运行在哪里

Amazon Bedrock 上的 Kimi K3 通过[跨 Region inference profile](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html) 提供。你可以从非常多的 AWS Region（「源」）之一调用该模型，Amazon Bedrock 随后会在多个可能的「目标」Region 之一安全地处理你的请求。

跨 Region inference 完全由 AWS 托管：数据在 Region 之间传输时会被加密，并始终留在 AWS 网络上，绝不经过公网，也不需要你搭建任何多 Region 虚拟私有云（VPC）基础设施。

你调用的 inference profile ID 决定了哪些目标 Region 有资格接收请求：

| **Profile** | **Model ID** | **什么时候选它** |
| --- | --- | --- |
| Global | `global.moonshotai.kimi-k3` | 多数场景的推荐选择：成本最低、可用性最广 |
| India geographic | `in.moonshotai.kimi-k3` | 推理处理必须留在 Mumbai 与 Hyderabad 这两个 Region 之内 |

关于可用的 inference profile、它们能从哪些 AWS Region 被调用、以及它们能使用哪些目标 Region 做推理的最新信息，请参见 Amazon Bedrock 的 [Kimi K3 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3.html)。

## 示例走查：印度语系文档理解

来看一个示例用例：读取一份扫描的印地语文档，抽取结构化数据，并用印地语与英语混排（Hinglish）回答追问。

这一需求在印度的金融服务与公共部门工作流里很常见，这类场景经常要把了解你的客户（KYC）表单、公用事业账单等文档数字化。Amazon Bedrock 上的 Kimi K3 可以直接读取图像并围绕图像推理，包括含多语种文字的图像。它提供了一种可行的解法，不需要单独的 OCR 或翻译服务。

### 前提条件

这个示例的完整源码在 [GitHub](https://github.com/aws-samples/sample-moonshotai-on-aws/tree/main/Kimi-on-Amazon-Bedrock/Use-Cases/Indic-Document-OCR) 上。

要跟着做，你需要：

- 一个 [AWS 账户](https://aws.amazon.com/resources/create-account/)。
- 已安装 [Python](https://www.python.org/downloads/) 3.11 或更高版本，且能联网，以便安装[所需的 PyPI 包](https://github.com/aws-samples/sample-moonshotai-on-aws/blob/main/pyproject.toml)。
- 已安装 [AWS Command Line Interface (AWS CLI)](https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-getting-started.html)，并配置好[凭证](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html)，其 [AWS Identity and Access Management (IAM) permissions](https://docs.aws.amazon.com/bedrock/latest/userguide/security-iam.html) 足以通过印度的 inference profile 调用 Kimi K3 模型。

例如，若要走 India geographic inference、通过 `ap-south-1` 的 Mumbai Region 使用 Kimi K3，下面这份 IAM policy 提供了足够的访问权限。把 `{ACCOUNT_ID}` 占位符换成你自己的 AWS 账户 ID：

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "BedrockCallWithBearerToken",
      "Effect": "Allow",
      "Action": ["bedrock:CallWithBearerToken"],
      "Resource": ["*"]
    },
    {
      "Sid": "BedrockKimiK3India",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream"
      ],
      "Resource": [
        "arn:aws:bedrock:ap-south-1::foundation-model/moonshotai.kimi-k3",
        "arn:aws:bedrock:ap-south-2::foundation-model/moonshotai.kimi-k3",
        "arn:aws:bedrock:ap-south-1:{ACCOUNT_ID}:inference-profile/in.moonshotai.kimi-k3",
        "arn:aws:bedrock:ap-south-1:{ACCOUNT_ID}:project/default"
      ]
    }
  ]
}
```

有关 permissions 的更多信息，参见 Amazon Bedrock User Guide 中的[运行模型推理的前提条件](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-prereq.html)。如果你的组织限制了 AWS Region，请让管理员查阅 [geographic 跨 Region inference 的 IAM 与 SCP 指引](https://docs.aws.amazon.com/bedrock/latest/userguide/geographic-cross-region-inference.html)。保持源 Region 处于允许状态，并允许路由到印度的两个目的地，必要时使用按 profile 作用域设置的例外。[Responses API 指南](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html) 也说明了所需的 default project 访问权限。

### 开始使用推理 API

如 [model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3.html) 所述，Amazon Bedrock 支持多种调用 Kimi K3 的 API，全部都在 Bedrock Runtime endpoint 之下：

| **API** | **请求与响应格式** |
| --- | --- |
| [Chat Completions](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-completions-mantle.html#inference-chat-completions-runtime-endpoint) | OpenAI 兼容的 messages 输入与 assistant-message 输出。 |
| [Responses](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html#bedrock-mantle-responses-runtime) | OpenAI 兼容的输入与结构化输出项。 |
| [Converse](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.html) | 跨所支持模型的标准化 messages、content blocks 与推理参数。 |
| [InvokeModel](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_InvokeModel.html) | 模型特定的 JSON 请求体与响应体。 |

因为这个模型推荐使用 OpenAI 兼容 API，我们在示例中也用它们，并通过 [openai Python Library](https://github.com/openai/openai-python#readme) 连接。

Amazon Bedrock 支持为需要 API key 的集成[生成 API key](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-generate.html)。不过 AWS 建议在可能的情况下[改用短期凭证](https://docs.aws.amazon.com/IAM/latest/UserGuide/security-creds-programmatic-access.html#security-creds-alternatives-to-long-term-access-keys)。[AWS token generator Python 库](https://github.com/aws/aws-bedrock-token-generator-python) 会从标准的 AWS CLI 凭证链派生出一个短期的、形似 API key 的 token。

如果你的 AWS CLI 用的是[命名 profile](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html#cli-configure-files-using-profiles)，可能需要先设置 `AWS_PROFILE` 环境变量。CLI 凭证配置好之后，就可以用下面的代码调用模型：

```
from aws_bedrock_token_generator import provide_token
from openai import OpenAI

region = "ap-south-1"
model_id = "in.moonshotai.kimi-k3"

client = OpenAI(
    base_url=f"https://bedrock-runtime.{region}.amazonaws.com/openai/v1",
    api_key=provide_token(region=region),
)

response = client.chat.completions.create(
    model=model_id,
    messages=[{
        "role": "user",
        "content": "Classify this ticket as billing, technical, or account: I was charged twice."
    }],
    max_completion_tokens=2048,
)

print(response.choices[0].message.content)
```

这里 `region`（`ap-south-1`，即 Mumbai）指定请求发往的源 Region。inference profile `in.moonshotai.kimi-k3` 确保推理只在印度的 Region 中处理。

Chat Completions 与 Responses 两个 API 都支持大量特性，例如 streaming、tool calling 与 structured outputs。更多示例见 [OpenAI Python API Reference](https://developers.openai.com/api/reference/python)。

### 分析图像

Amazon Bedrock 上的 Kimi K3 除图像外还支持 PDF 以及多种其他文件类型。你可以把输入文件直接做 base64 编码后发给模型。对于 OCR 或其他小细节很重要的场景，可以考虑把图像的 `detail` 参数设为 `high`。这会提升准确率，代价是每张图消耗更多输入 token。

某些情况下，我们发现当图像在文本输入*之前*提供时，Kimi K3 的输出质量更高。建议对请求顺序做些试验。参考下面的示例代码：

```
from base64 import b64encode

image_path = "sample_data/electricity_bill_hi.png"
with open(image_path, "rb") as f:
    image_base64 = b64encode(f.read()).decode("ascii")

response = client.chat.completions.create(
    model=model_id,
    messages=[
        {
            "role": "user",
            "content": [
                # The model card recommends placing images before text:
                {
                    "type": "image_url",
                    "image_url": {
                        "url": f"data:image/png;base64,{image_base64}",
                        "detail": "high"
                    }
                },
                {"type": "text", "text": QUESTION_PROMPT},
            ]
        },
    ],
    max_completion_tokens=16384,
)

print(response.choices[0].message.content)
```

为了演示，我们生成了一张印地语的合成电费单图像。

![用作 OCR 示例文档的合成印地语电费单](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/02/ML-22220-1-1.png)

图 1：示例中使用的合成印地语电费单（所有示例文档均为虚构）

有了这张图像输入，模型可以直接从文档中取数来回答问题，不需要单独的数字化步骤。例如：

Q: Bill kitne ka hai aur last date kab hai? Late hua toh kitna dena padega?

A: Bill ka total ₹2,217.20 hai, aur last date 20/10/2026 hai. Late hua toh ₹2,261.54 dena padega.

### 搭建结构化抽取流水线

除通用问答之外，你还可以用静态 prompt 在大量文档中抽取一组前后一致的期望字段，从而构建结构化的文档处理工作流。

要对输出结构施加硬约束（而不是尽力而为的 prompt 引导生成），Kimi K3 在 Amazon Bedrock 上支持 structured output，可以通过 function calling，也可以提供 JSON Schema 输出格式。这两种方式的详细说明见 [OpenAI 文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)（针对 OpenAI 兼容 API）与 [Amazon Bedrock User Guide](https://docs.aws.amazon.com/bedrock/latest/userguide/structured-output.html#structured-output-examples)（针对原生 Converse/InvokeModel API）。

在完整的示例代码[仓库](https://github.com/aws-samples/sample-moonshotai-on-aws/tree/main/Kimi-on-Amazon-Bedrock/Use-Cases/Indic-Document-OCR)里，我们提供了一条端到端流水线，它会：

- 按文档原有文字转写文档内容（OCR）。
- 用可配置的 schema 把关键字段抽取为 JSON，日期归一化为 ISO 8601（`YYYY-MM-DD`），天城文数字（例如 २८८）转换为西方数字（288），人名转写为英文。
- 写一段简短的英文摘要。
- 针对同一份文档，用 Hinglish（用拉丁字母书写的印地语，与英语混排）回答多轮追问。

对于上图同一张合成印地语电费单，这条流水线会返回如下结构化字段（有删减）：

```
{
  "consumer_name": "श्रीमती सुनीता देवी शर्मा",
  "consumer_name_english": "Smt. Sunita Devi Sharma",
  "consumer_number": "410277893561",
  "billing_period": "2026-09-01 to 2026-09-30",
  "due_date": "2026-10-20",
  "units_consumed_kwh": 288,
  "amount_due_inr": 2217.20,
  "amount_after_due_date_inr": 2261.54
}
```

我们还包含了一个 KYC 表单示例，以及一个开放的 *schema-free* 模式，由模型自己为其他任意文档类型挑选最有用的字段。所有提供的示例文档都是合成的，姓名与地址均为虚构，身份号码也做了掩码处理。

请[从 GitHub 下载示例代码](https://github.com/aws-samples/sample-moonshotai-on-aws/tree/main/Kimi-on-Amazon-Bedrock/Use-Cases/Indic-Document-OCR)进一步探索，并用你自己的图像试跑。

和任何自动抽取一样，在依赖输出做重要决策之前，你应当先验证它对你的具体场景足够可靠。对关键工作流，可以考虑加入事后校验逻辑或人工复核环节。

## 优化性价比、service tier 与缓存

围绕示例文档调好你的 system prompt 与 schema，才能得到可靠的抽取结果。[Amazon Bedrock Advanced Prompt Optimization](https://docs.aws.amazon.com/bedrock/latest/userguide/advanced-prompt-optimization-how.html)（AdvPO）提供了一个全托管的选项，基于参考样例来优化 prompt 模板。

Amazon Bedrock 的 [service tier](https://aws.amazon.com/bedrock/service-tiers/) 让你能按单次请求掌控性价比。对延迟不那么敏感的场景，你可以选 **flex** **tier**，在默认标准价格上享受 50% 折扣。对延迟关键场景，你可以选「priority」，以更高的价格换取更高的队列优先级。细节见[定价页](https://aws.amazon.com/bedrock/pricing/)。

输入 prompt 中含较长且很少变动的内容时，同样可以从 Amazon Bedrock 的 [prompt 缓存](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)中获益。要确保静态内容（system prompt、工具描述等）出现在输入的最前面，*在*当前图像与问题这类动态部分*之前*。

Amazon Bedrock 上的 Kimi K3 既支持对 cache hit 的折扣价格，也支持显式缓存模式。在默认的**隐式缓存模式**下，服务会尝试自动缓存并复用跨请求重复出现的 prompt 前缀，无需用户做任何操作。不过你可以改用显式模式，并在输入中为可缓存内容指定「breakpoints」，从而提升缓存命中率、响应速度与成本节省。

下面的示例演示用 Responses API 做显式 prompt 缓存。更多信息见 Amazon Bedrock User Guide 中的 [prompt 缓存](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)：

```
for call in (1, 2):
    response = client.responses.create(
        model=model_id, max_output_tokens=2048, store=False,
        input=[
            {"type": "message", "role": "system", "content": [{
                "type": "input_text", "text": static_prefix,
                "prompt_cache_breakpoint": {"mode": "explicit"},
            }]},
            {"type": "message", "role": "user", "content": [{
                "type": "input_text", "text": dynamic_prompt,
            }]},
        ],
        extra_body={"prompt_cache_options": {"mode": "explicit"}},
    )
    print(call, response.usage.input_tokens_details.cached_tokens)
```

## 监控用量

Amazon CloudWatch 会为 Kimi K3 在 `AWS/Bedrock` 命名空间下自动生成 [metrics](https://docs.aws.amazon.com/bedrock/latest/userguide/monitoring-runtime-metrics.html)，让你看到调用速率、token 数、缓存用量、延迟、错误与限流。

[模型调用日志](https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html) 需要主动开启，且可以选择包含 prompt 与输出。启用前先检查访问、保留期与存储位置的设置。

日志与 metrics 存储在提交请求的源 Region，不论跨 Region inference 中实际处理它的是哪个目标 Region。你还可以选择[启用 AWS CloudTrail 数据事件日志](https://docs.aws.amazon.com/bedrock/latest/userguide/logging-using-cloudtrail.html)，把模型调用记录进 CloudTrail，它会以 `additionalEventData.inferenceRegion` 字段记录请求的目标 Region。

## 清理

Kimi K3 按 token 计费，所以这些代码示例不会创建任何需要清理的持久 AWS 资源。如果你为了试用新建了 IAM Role 或 User，或在已有的 User/Role 上添加了额外 permissions，记得用完之后删掉。
