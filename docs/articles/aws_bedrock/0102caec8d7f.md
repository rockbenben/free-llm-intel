# 在 Amazon Bedrock 上引入基于印度的 Kimi K3 推理

Kimi K3 是一种多模态、开放权重基础模型 (FM)，供应商 Moonshot AI 报告称，它在发布时就实现了前沿级编码和通用代理智能。

除了全球和美国的推理之外，[Amazon Bedrock](https://aws.amazon.com/bedrock/) 现在还支持 Kimi K3 在印度进行国内推理：通过严格的数据驻留要求解锁本地工作负载。像 [Ultra human](https://www.ultra human.com/) 这样的客户已经看到了生产中的好处：

> “Ultra human 应用程序中的 AI 健康和保健助理 Jade，使用每个人自己的 Ring 和血糖数据以简单的语言回答问题，每天进行超过 14,000 次对话。Amazon Bedrock 上的 Kimi K3 让我们通过我们已经使用的 API 添加领先的开放权重模型，健康数据保留在 AWS 和孟买作为后备区域。通过即时缓存，我们将 LLM 成本削减了 80%，并使多轮聊天成为可能 85快百分之百。”
> — Aditya Patawari，Ultra human 工程副总裁

在这篇文章中，我们解释了可用的不同全球和地理推理选项，并共享示例用例的代码：光学字符识别 (OCR) 和印度语言文档的理解，以及以代码混合的印度英语进行后续问答。

## 选择可以运行推理的位置

Amazon Bedrock 上的 Kimi K3 通过[跨区域推理配置文件](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html) 提供。您可以从任何一个广泛的 AWS 区域（“源”）调用模型。然后，Amazon Bedrock 在多个可能的“目标”区域之一安全地处理您的请求。

跨区域推理完全由 AWS 管理：数据在区域之间传输时经过加密并保留在 AWS 网络上，永远不会遍历公共互联网或要求您设置任何多区域虚拟私有云 (VPC) 基础设施。

您调用的推理配置文件 ID 控制哪些目标区域符合条件：

| **简介** | **型号 ID** | **何时选择它** |
| ---| ---| ---|
|全球| `global.moonshotai.kimi-k3` |推荐用于大多数用例：成本最低且可用性最广泛 |
|印度地理| `in.moonshotai.kimi-k3` |推理处理必须位于孟买和海得拉巴地区 |

请参阅 Amazon Bedrock [Kimi K3 模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3.html)，了解有关可用推理配置文件、可以从哪些 AWS 区域调用以及可以用于推理的目标区域的最新信息。

## 示例演练：印度语言文档理解

让我们考虑一个示例用例：阅读扫描的印地语文档，提取结构化数据，并用印地语和英语（印度英语）混合回答后续问题。

这种需求在印度金融服务和公共部门的工作流程中很常见，其中“了解你的客户”(KYC) 表格、公用事业账单和类似文件通常必须数字化。 Amazon Bedrock 上的 Kimi K3 可以直接读取和推理图像，包括包含多语言文本的图像。它提供了一种潜在的解决方案，无需单独的 OCR 或翻译服务。

### 先决条件

此示例的完整源代码可在 [GitHub](https://github.com/aws-samples/sample-moonshotai-on-aws/tree/main/Kimi-on-Amazon-Bedrock/Use-Cases/Indic-Document-OCR) 上获取。

要继续操作，您需要：

- [AWS 账户](https://aws.amazon.com/resources/create-account/)。
- 安装 [Python](https://www.python.org/downloads/) 3.11 或更高版本，可以访问互联网来安装 [所需的 PyPI 软件包](https://github.com/aws-samples/sample-moonshotai-on-aws/blob/main/pyproject.toml)。
- 安装了 [AWS 命令行界面 (AWS CLI)](https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-getting-started.html)，并配置了足够的 [凭证](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html) [AWS Identity and Access Management (IAM)]权限](https://docs.aws.amazon.com/bedrock/latest/userguide/security-iam.html) 通过印度推理配置文件调用 Kimi K3 模型。

例如，要通过印度地理推断的“ap-south-1”孟买区域使用 Kimi K3，以下 IAM 策略授予足够的访问权限。将“{ACCOUNT_ID}”占位符替换为您的 AWS 账户 ID：
```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "BedrockCallWithBearerToken",
      "Effect": "Allow",
      "Action": ["bedrock:CallWithBearerToken"],
      "Resource": ["*"]
    },
    {
      "Sid": "BedrockKimiK3India",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream"

        "arn:aws:bedrock:ap-south-1::foundation-model/moonshotai.kimi-k3",
        "arn:aws:bedrock:ap-south-2::foundation-model/moonshotai.kimi-k3",
        "arn:aws:bedrock:ap-south-1:{ACCOUNT_ID}:inference-profile/in.moonshotai.kimi-k3",
        "arn:aws:bedrock:ap-south-1:{ACCOUNT_ID}:project/default"
      ]
    }
  ]
}
```
有关权限的更多信息，请参阅 Amazon Bedrock 用户指南中的[运行模型推理的先决条件](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-prereq.html)。如果您的组织限制 AWS 区域，请要求您的管理员查看[地理跨区域推理 IAM 和 SCP 指南](https://docs.aws.amazon.com/bedrock/latest/userguide/geographic-cross-region-inference.html)。保持源区域允许并允许路由到两个印度目的地，在适当的情况下使用配置文件范围的例外。 [Responses API 指南](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html) 还描述了所需的默认项目访问权限。

### 推理 API 入门

正如[模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3.html)中的详细信息，Amazon Bedrock 支持用于调用 Kimi K3 的多个 API，所有这些 API 都在 Bedrock 运行时终端节点下：

| **API** | **请求和响应格式** |
| ---| ---|
| [聊天完成](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-c​​ompletions-mantle.html#inference-chat-c​​ompletions-runtime-endpoint) |兼容 OpenAI 的消息输入和辅助消息输出。 |
| [回复](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html#bedrock-mantle-responses-runtime) | OpenAI 兼容的输入和结构化输出项。 |
| [Converse](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.html) |跨受支持模型的标准化消息、内容块和推理参数。 |
| [InvokeModel](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_InvokeModel.html) |特定于模型的 JSON 请求和响应主体。 |

由于此模型推荐使用与 OpenAI 兼容的 API，因此我们在本示例中使用这些 API，并通过 [openai Python 库](https://github.com/openai/openai-python#readme) 进行连接。

Amazon Bedrock 支持[生成 API 密钥](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-generate.html)，以进行需要它们的集成。但是，AWS 建议尽可能使用[短期凭证](https://docs.aws.amazon.com/IAM/latest/UserGuide/security-creds-programmatic-access.html#security-creds-alternatives-to-long-term-access-keys)。 [AWS 令牌生成器 Python 库](https://github.com/aws/aws-bedrock-token-generator-python) 从标准 AWS CLI 凭证链派生一个类似 API 密钥的短期令牌。

如果您为 AWS CLI 使用[命名配置文件](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html#cli-configure-files-using-profiles)，您可能需要先设置 `AWS_PROFILE` 环境变量。设置 CLI 凭据后，您可以使用以下代码调用模型：
```
from aws_bedrock_token_generator import provide_token
from openai import OpenAI

region = "ap-south-1"
model_id = "in.moonshotai.kimi-k3"

client = OpenAI(
    base_url=f"https://bedrock-runtime.{region}.amazonaws.com/openai/v1",
    api_key=provide_token(region=region),
)

response = client.chat.completions.create(
    model=model_id,
    messages=[{
        "role": "user",
        "content": "Classify this ticket as billing, technical, or account: I was charged twice."
    }],
    max_completion_tokens=2048,
)

print(response.choices[0].message.content)
```
这里，“region”（“ap-south-1”孟买）指定发出请求的源区域。推理配置文件“in.moonshotai.kimi-k3”确保仅在印度地区处理推理。

聊天完成和响应 API 都支持流式传输、工具调用和结构化输出等广泛的功能。有关更多示例，请参阅 [OpenAI Python API 参考](https://developers.openai.com/api/reference/python)。

### 分析图像

Amazon Bedrock 上的 Kimi K3 支持图像以及 PDF 和一系列其他文件类型。您可以通过 base64 编码直接将输入文件发送到模型。对于 OCR 或其他小细节很重要的用例，请考虑将图像“detail”参数设置为“high”。这提高了准确性，但代价是每个图像消耗更多的输入标记。

在某些情况下，当*在*文本输入之前提供图像时，我们发现 Kimi K3 的输出质量更高。我们建议尝试请求排序。考虑以下示例代码：
```
from base64 import b64encode

image_path = "sample_data/electricity_bill_hi.png"
with open(image_path, "rb") as f:
    image_base64 = b64encode(f.read()).decode("ascii")

response = client.chat.completions.create(
    model=model_id,
    messages=[
        {
            "role": "user",
            "content": [
                # The model card recommends placing images before text:
                {
                    "type": "image_url",
                    "image_url": {
                        "url": f"data:image/png;base64,{image_base64}",
                        "detail": "high"
                    }
                },
                {"type": "text", "text": QUESTION_PROMPT},
            ]
        },
    ],
    max_completion_tokens=16384,
)

print(response.choices[0].message.content)
```
为了进行演示，我们生成了一张印地语的合成电费账单图像。

### 构建结构化提取管道

除了一般问答之外，您还可以使用静态提示来创建结构化文档处理工作流程，以跨多个文档提取一组一致的预期字段。

为了对输出结构应用严格的约束（而不是尽力提示引导生成），Kimi K3 通过函数调用或提供 JSON 架构输出格式支持 Amazon Bedrock 上的结构化输出。这些选项在 [OpenAI 文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)（适用于 OpenAI 兼容 API）和 [Amazon Bedrock 用户指南](https://docs.aws.amazon.com/bedrock/latest/userguide/structured-output.html#structured-output-examples)（适用于本机 Converse/InvokeModel API）中进行了更详细的描述。

在完整的示例代码 [存储库](https://github.com/aws-samples/sample-moonshotai-on-aws/tree/main/Kimi-on-Amazon-Bedrock/Use-Cases/Indic-Document-OCR) 中，我们提供了一个端到端管道：

- 以原始脚本 (OCR) 转录文档。
- 使用可配置模式将关键字段提取为 JSON，日期标准化为 ISO 8601 (`YYYY-MM-DD`)，梵文数字（例如 २८८）转换为西方数字 (288)，名称音译为英语。
- 写一个简短的英文摘要。
- 用印度英语（用拉丁字母书写的印地语，与英语混合）回答有关同一文档的多轮后续问题。

## 优化性价比、服务层级和缓存

根据示例文档调整系统提示和架构，以实现可靠的提取。 [Amazon Bedrock 高级提示优化](https://docs.aws.amazon.com/bedrock/latest/userguide/advanced-prompt-optimization-how.html) (AdvPO) 提供了一个完全托管的选项，用于根据参考示例优化提示模板。

Amazon Bedrock [服务层级](https://aws.amazon.com/bedrock/service-tiers/) 让您可以根据每个请求控制性价比。对于对延迟不太敏感的情况，您可以选择 **flex** **等级** 以在默认标准定价的基础上享受 50% 的折扣。对于延迟关键的场景，您可以选择“优先级”以更高的价格请求更高的队列优先级。有关详细信息，请参阅[定价页面](https://aws.amazon.com/bedrock/pricing/)。

输入提示中内容较长且很少更改的用例也可以受益于 Amazon Bedrock 上的[提示缓存](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)。确保静态内容（系统提示、工具描述等）出现在输入的开头，“在”动态部分（例如当前图像和问题）之前。

Amazon Bedrock 上的 Kimi K3 支持缓存命中的折扣定价以及显式缓存模式。在默认的**隐式缓存模式**中，服务尝试自动缓存并重用请求之间的重复提示前缀，无需用户操作。但是，您可以通过选择显式模式并在输入中指定可缓存内容的“断点”来提高性能，从而提高缓存命中率、响应速度并节省成本。

The following example shows explicit prompt caching with the Responses API.有关更多信息，请参阅 Amazon Bedrock 用户指南中的[提示缓存](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)：
```
for call in (1, 2):
    response = client.responses.create(
        model=model_id, max_output_tokens=2048, store=False,
        input=[
            {"type": "message", "role": "system", "content": [{
                "type": "input_text", "text": static_prefix,
                "prompt_cache_breakpoint": {"mode": "explicit"},
            }]},
            {"type": "message", "role": "user", "content": [{
                "type": "input_text", "text": dynamic_prompt,
            }]},
        ],
        extra_body={"prompt_cache_options": {"mode": "explicit"}},
    )
    print(call, response.usage.input_tokens_details.cached_tokens)
```
## 监控使用情况

Amazon CloudWatch [指标](https://docs.aws.amazon.com/bedrock/latest/userguide/monitoring-runtime-metrics.html) 是在 `AWS/Bedrock` 命名空间下为 Kimi K3 自动生成的，可提供调用率、令牌计数、缓存使用情况、延迟、错误和限制的可见性。

[模型调用日志记录](https://docs.aws.amazon.com/bedrock/latest/userguide/model-inspiration-logging.html) 是可选的，并且可以选择包含提示和输出。在启用之前检查访问、保留和存储位置设置。

日志和指标存储在您提交请求的源区域中，无论哪个目标区域可能在跨区域推理中对其进行了处理。您可以选择[启用 AWS CloudTrail 数据事件日志记录](https://docs.aws.amazon.com/bedrock/latest/userguide/logging-using-cloudtrail.html) 在 CloudTrail 中记录模型调用，它将请求的目标区域记录为“additionalEventData.inferenceRegion”字段。
