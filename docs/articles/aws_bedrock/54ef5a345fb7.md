# Amazon SageMaker AI 的新能力持续改变组织开发 AI 模型的方式

随着 AI 模型变得日益复杂和专业化，能否快速训练和定制模型，可能决定一个组织是引领行业还是落后于人。这正是数十万客户使用 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker-ai/) 的完全托管基础设施、工具和 workflow 来扩展并推进 AI 模型开发的原因。自 2017 年推出以来，SageMaker AI 通过降低复杂度同时最大化性能，改变了组织进行 AI 模型开发的方式。此后，我们持续不断地创新，自发布以来新增了 420 多项新能力，为客户提供快速高效构建、训练和部署 AI 模型的最佳工具。今天，我们很高兴宣布一批新创新，它们建立在 SageMaker AI 丰富功能之上，可加速客户构建和训练 AI 模型。

## Amazon SageMaker HyperPod：开发 AI 模型的首选基础设施

AWS 于 2023 年推出 [Amazon SageMaker HyperPod](https://aws.amazon.com/sagemaker-ai/hyperpod/)，目的是在构建 AI 模型时降低复杂度并最大化性能与效率。借助 SageMaker HyperPod，你可以跨数千个 AI 加速器快速扩展生成式 AI 模型开发，并把基础模型（FM）的训练与微调开发成本降低最多 40%。当今许多顶级模型都是在 SageMaker HyperPod 上训练的，包括来自 Hugging Face、Luma AI、Perplexity AI、Salesforce、Thomson Reuters、Writer 和 Amazon 的模型。通过在 SageMaker HyperPod 上训练 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) FM，Amazon 节省了数月的工作量，并把计算资源利用率提升到 90% 以上。

为进一步简化 workflow 并加快模型的开发与部署，新的命令行界面（CLI）和软件开发工具包（SDK）提供了单一、一致的接口，它简化基础设施管理、统一训练与推理的作业提交，并通过集成的监控与控制同时支持基于 recipe 的 workflow 和自定义 workflow。今天，我们还在 SageMaker HyperPod 中新增了两项能力，可帮助你降低训练成本并加速 AI 模型开发。

### 借助 SageMaker HyperPod 可观测性把排查性能问题的时间从天级缩短到分钟级

为了尽快把新的 AI 创新推向市场，组织需要在 AI 模型开发任务和计算资源之间获得可见性，以优化训练效率，并尽快发现和解决中断或性能瓶颈。例如，要排查某次训练或微调作业失败是否由硬件问题导致，数据科学家和机器学习（ML）工程师希望能快速筛选出执行该作业的特定 GPU 的监控数据进行查看，而不是手动浏览整个集群的硬件资源，来建立作业失败与硬件问题之间的关联。

SageMaker HyperPod 中新的[可观测性能力](https://aws.amazon.com/blogs/machine-learning/accelerate-foundation-model-development-with-one-click-observability-in-amazon-sagemaker-hyperpod/)改变了你监控和优化模型开发工作负载的方式。通过预先配置在 [Amazon Managed Grafana](https://aws.amazon.com/grafana/) 中的统一仪表板，并把监控数据自动发布到 [Amazon Managed Service for Prometheus](https://aws.amazon.com/prometheus/) 工作区，你现在可以在单一视图中查看生成式 AI 任务性能指标、资源利用率和集群健康状况。团队现在可以快速发现瓶颈、避免代价高昂的延迟，并优化计算资源。你可以定义自动化告警，指定特定用例的任务指标和事件，只需点击几下就能把它们发布到统一仪表板。

通过把故障排查时间从天级缩短到分钟级，这项能力可以帮助你加快投产进程，并最大化 AI 投资的回报。

### 在 SageMaker HyperPod 上部署 Amazon SageMaker JumpStart 模型，实现快速、可扩展的推理

在 SageMaker HyperPod 上开发生成式 AI 模型之后，许多客户会把这些模型导入 [Amazon Bedrock](https://aws.amazon.com/bedrock/)——一项用于构建和扩展生成式 AI 应用的完全托管服务。不过，有些客户希望利用自己的 SageMaker HyperPod 计算资源来加速评估，并更快地把模型投入生产。

现在，你可以在几分钟内把 Amazon SageMaker JumpStart 的[开放权重模型](https://aws.amazon.com/blogs/machine-learning/amazon-sagemaker-hyperpod-launches-model-deployments-to-accelerate-the-generative-ai-model-development-lifecycle/)以及微调后的自定义模型部署到 SageMaker HyperPod 上，无需手动配置基础设施。数据科学家只需点击一次即可对 SageMaker JumpStart 模型运行推理，从而简化和加速模型评估。这种简单的一次性预置减少了手动基础设施配置，以最小的投入提供可靠、可扩展的推理环境。大模型下载时间从数小时缩短到数分钟，加速模型部署并缩短上市时间。

## 从本地开发环境无缝访问 SageMaker AI 的强大计算资源

如今，许多客户会从 SageMaker AI 提供的多种完全托管集成开发环境（IDE）中选择用于模型开发的工具，包括 JupyterLab、基于 Code-OSS 的 Code Editor 和 RStudio。尽管这些 IDE 能提供安全高效的配置，但有些开发者更喜欢在个人电脑上使用本地 IDE，因为其调试能力和丰富的定制选项。然而，此前使用 Visual Studio Code 等本地 IDE 的客户无法轻松地在 SageMaker AI 上运行模型开发任务。

借助[新增的 SageMaker AI 远程连接](https://aws.amazon.com/blogs/machine-learning/supercharge-your-ai-workflows-by-connecting-to-sagemaker-studio-from-visual-studio-code)，开发者和数据科学家可以从本地 VS Code 快速、无缝地连接到 SageMaker AI，同时保留对自定义工具和熟悉 workflow 的访问，从而以最高效率工作。开发者可以用本地 IDE 构建和训练 AI 模型，而 SageMaker AI 负责远程执行，因此你可以在偏好的环境中工作，同时仍能享受 SageMaker AI 的性能、可扩展性和安全性。你现在可以选择自己偏好的 IDE——无论是完全托管的云 IDE 还是 VS Code——利用 SageMaker AI 强大的基础设施和无缝扩展能力来加速 AI 模型开发。

## 借助完全托管的 MLflow 3.0 更快构建生成式 AI 模型和应用

随着各行各业客户加速生成式 AI 开发，他们需要能够跟踪实验、观察行为并评估模型和 AI 应用性能的能力。Cisco、SonRai 和 Xometry 等客户已经在使用 SageMaker AI 上的托管 MLflow，以大规模高效管理 ML 模型实验。[SageMaker AI 上完全托管的 MLflow 3.0](https://aws.amazon.com/blogs/machine-learning/accelerating-generative-ai-development-with-fully-managed-mlflow-3-0-on-amazon-sagemaker-ai/) 的推出，使你可以用单一工具轻松跟踪实验、监控训练进度，并更深入地了解模型和 AI 应用的行为，从而帮助你加速生成式 AI 开发。
