uniopen 是台湾统一企业集团推出的一套数字沟通与会员平台，通过 Web、平板和移动渠道把客户连接到电商、会员福利和其他零售体验。

在这些渠道上，uniopen 应用一套审核政策，沿两个轴对每个交互分类。第一个是发生了什么行为（九个类别），第二个是该行为指向什么主题（brand、other 或 forbidden）。两者都必须正确，一个审核决定才有用，而两者都是 uniopen 业务特有的，不能指望一个通用模型开箱就学会。

在本文中，我们展示团队如何通过 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker-ai/) 中的监督微调和一次末端的 prompt 级输出优化，把 Amazon Nova 2 Lite 适配到这些业务特有的审核政策。AWS 的做法把纠错数据、托管的训练、评估和部署控制保持在一条可重复的工作流里。模型可用性因 AWS 区域而异，参见 [Amazon Bedrock 中按 AWS 区域支持的模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。

## 方案概览

该架构把生产审核路径与纠错、训练、评估和部署分离。Amazon Nova 2 Lite 处理主要审核请求。Amazon Nova 2 Pro 支持对被报告错误生成候选纠错，但每条纠错在进入训练集前必须经人工审阅者验证。有了这一分离，团队可以改进领域特定的行为，而不把生成的标签当作真值。

Amazon Simple Storage Service ([Amazon S3](https://aws.amazon.com/pm/serv-s3/)) 存储经验证的纠错集和训练数据。[Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 跟踪活跃和候选模型配置。[Amazon Elastic Kubernetes Service (Amazon EKS)](https://aws.amazon.com/eks/) 上的 Argo Workflows 编排 prompt 优化、评估和部署，而 Argo CD 把经批准的配置应用到生产。当一个硬关卡失败或一个候选需要关注时，[Amazon Simple Notification Service (Amazon SNS)](https://aws.amazon.com/sns/) 和 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 通知运维人员。这些托管的 AWS 组件把数据、训练、配置状态和运营控制保持在一个受治理的工作流里。

负责任的 AI 控制补充了模型定制。对模糊案例和被复用为训练数据的纠错，人工审阅仍是强制的。固定的测试集和回归检查在质量下降时防止自动晋级。团队还可以对输入和输出应用 [Amazon Bedrock Guardrails 内容过滤器](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-content-filters.html)，跨行为和主题类别监控错误，最小化保留的客户数据，并在审核政策变化时重新验证阈值。

两类检查控制晋级：硬关卡和软关卡。*硬关卡*是必过的回归测试。*软关卡*是警告信号，如低置信度或某个特定类别的性能下降。

硬关卡失败会停止工作流并发送告警。通过硬关卡的候选接着被检查软关卡指标。若没有检测到警告，候选可以自动晋级。若触发了一个软关卡警告，候选保持待处理，并在部署前需要管理员审阅和批准。

## 评估方法

一个会话窗口是一段客户对话的有界片段，被当作一个训练或评估样本。全部三种配置都在同一个 737 个会话窗口的留出测试集上评估。微调数据集含有 3,391 个训练窗口。团队在这个一致的测试集上比较了基线模型、微调模型和 prompt 优化的微调模型。

Per Behavior Macro F1 衡量模型把九个审核行为作为一个组分类的一致性程度。每个行为对分数的贡献均等，因此在常见或较易类别上的强表现无法掩盖在较难类别上的弱表现。对 uniopen 而言这很重要，因为审核系统需要在整个政策集上工作，而不只是最常见的行为。

Subject Type Macro F1 衡量模型识别所涉主题类型（brand、other 或 forbidden）的一致性程度。每种主题类型对分数的贡献均等。这很重要，因为一个审核决定在系统不仅检测到一个政策相关行为、还正确理解该行为指向哪个实体时更有用。合起来，这两个指标在同一个 0-1 尺度上展示政策检测和主题理解。

## 基线性能

基础模型确立了一个有用的基线，但它在学会 uniopen 特定的审核分类法上仍显示出显著差距。不经微调，Amazon Nova 2 Lite 达到 0.5852 的 Per Behavior Macro F1 和 0.4162 的 Subject Type Macro F1。这些分数表明模型还没把 uniopen 特定的审核分类法学到足以用于生产的程度。

## Amazon SageMaker AI 定制

然后团队在 Amazon SageMaker AI 中用带 Low-Rank Adaptation (LoRA) 的监督微调来定制 Amazon Nova 2 Lite。微调让模型能从任务特定的样本学习，而不只依赖 prompt 指令。图 4 展示已完成的 Amazon SageMaker AI 训练作业，以及为定制运行记录的配置。

图 4：Amazon Nova 2 Lite 的 Amazon SageMaker AI 监督微调作业

训练作业记录捕获了基础模型、定制技术、训练数据位置、运行时长和进度，以做审计和可重复性。微调交付了最大的性能提升。Per Behavior Macro F1 从 0.5852 升到 0.8364，而 Subject Type Macro F1 从 0.4162 升到 0.8302。主题类型指标超过了它的生产目标，而行为分类接近它的目标。

## Prompt 优化

微调后，团队做了一次 prompt 级的改动，把模型输出从 JSON 简化为一种基于行的格式，并澄清应如何返回多个行为。这一改动不需要额外的模型训练。

prompt 优化把 Per Behavior Macro F1 从 0.8364 升到 0.8550，把 Subject Type Macro F1 从 0.8302 升到 0.8491。有了这最后一步，两个指标分别超过了它们 0.8500 和 0.8200 的生产目标。

## 结果

表 1 总结了 Amazon Nova 2 Lite 基线、Amazon SageMaker AI 微调模型，以及 prompt 优化的微调模型的性能。

*表 1：跨优化阶段的分类性能*

| 指标 | 基线 | 微调（JSON） | Prompt 优化（LF） | 生产目标 |
| --- | --- | --- | --- | --- |
| Per Behavior Macro F1 | 0.5852 | 0.8364 | 0.8550 | ≥ 0.8500 |
| Subject Type Macro F1 | 0.4162 | 0.8302 | 0.8491 | ≥ 0.8200 |

这两个指标在每个阶段暴露出不同的弱点。基线在行为检测和主题理解上都需要改进。Amazon SageMaker AI 微调产出了最大的收益，尤其在 Subject Type Macro F1 上，展示了领域特定样本对 uniopen 分类法的价值。然后 prompt 优化在不再次训练的情况下把两个指标都推到生产目标之上。把两个指标同时用作发布关卡，防止了一个维度上的改进掩盖另一个维度上的回归。

在两个指标都清过发布目标之后，uniopen 可以把常规审核导向定制路径，并让人工审阅聚焦于模糊案例。这一运营模式减少不必要的升级，同时为不确定或政策敏感的内容保留一个人工决定点。

## 后续步骤

团队将继续把 Per Behavior Macro F1 和 Subject Type Macro F1 用作生产关卡。它会从真实流量收集新的边界案例，并用那些案例来决定下一次改进应是一次 prompt 改动还是另一轮有针对性的微调。同一套评估模式可以延伸到额外的零售审核场景，而人工审阅者仍聚焦于模糊案例。

## 结论

uniopen 的结果展示了业务相关的评估如何识别一个基础模型需要在何处适配。监督微调解决了领域特定的分类差距，而 prompt 优化在不再次训练的情况下捕获了额外的收益。可重复的模式是：测量、识别较弱的那个维度、施加有针对性的改动，并且只在每个发布关卡都通过时才晋级。
