# 借助经过验证的语义缓存，减少 LLM agent 中的幻觉——基于 Amazon Bedrock Knowledge Bases

大语言模型（LLM）擅长生成类人的文本，但面临一个关键挑战：幻觉——即产出听起来令人信服但事实上不正确的内容。尽管这些模型在大规模通用数据上训练过，但它们往往缺少在业务场景中给出准确回答所需的组织专属上下文和最新信息。检索增强生成（RAG）技术通过在推理期间把 LLM 锚定在相关数据上来帮助缓解这一问题，但即便提供了准确的源材料，这些模型仍可能产生非确定性的输出，并偶尔编造信息。对于在生产应用中部署 LLM 的组织而言——尤其是在医疗、金融或法律服务等关键领域——这些残留的幻觉会带来严重风险，可能导致错误信息、责任问题以及用户信任的流失。

为应对这些挑战，我们提出一套实用方案，把 LLM 的灵活性与经过起草、整理和验证的答案的可靠性结合起来。我们的方案使用两项关键的 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 服务：[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)——一项全托管服务，可用于存储、搜索和检索组织专属信息以供 LLM 使用；以及 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/)——一项全托管服务，可用于构建、测试和部署能够理解用户请求、将其拆解为步骤并执行操作的 AI 助手。就像客服团队维护一批精心编写的常见问题（FAQ）答案一样，我们的方案会先检查用户的问题是否与经过整理和验证的回答相匹配，然后才让 LLM 生成新的回答。这种方法通过尽可能使用可信信息来帮助防止幻觉，同时仍让 LLM 处理新的或独特的问题。通过实施这一技术，组织可以提升回答准确性、缩短响应时间并降低成本。无论你是 AI 开发新手还是经验丰富的从业者，本文都提供了分步指导和代码示例，帮助你构建更可靠的 AI 应用。

## 方案概览

我们的方案使用 [Amazon Bedrock Knowledge Bases Retrieve API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_Retrieve.html) 实现了一个经过验证的语义缓存，以减少 LLM 回答中的幻觉，同时改善延迟并降低成本。这个只读的语义缓存充当用户与 Amazon Bedrock Agents 之间的智能中间层，存储经过整理和验证的问答对。

当用户提交查询时，方案会先评估该查询与知识库中已有验证问题的语义相似度。对于高度相似的查询（匹配度大于 80%），方案完全绕过 LLM，直接返回经过整理和验证的回答。当发现部分匹配（相似度 60–80%）时，方案会把验证过的回答作为 few-shot 示例来引导 LLM 的响应，从而显著提升准确性和一致性。对于相似度较低（低于 60%）或无匹配的查询，方案回退到标准的 LLM 处理，确保用户问题得到恰当的回答。

这种方法带来几项关键收益：

- **降低成本：** 通过减少对高频问题的非必要 LLM 调用，该方案在大规模下显著降低运营成本
- **提升准确性：** 经过整理和验证的回答把已知用户查询出现幻觉的可能性降到最低，而 few-shot prompting 则提升相似问题的准确性。
- **降低延迟：** 直接检索缓存答案可为已知查询提供近乎即时的响应，改善整体用户体验。

语义缓存充当一个不断增长的可信回答库，持续提升方案的可靠性，同时保持处理用户查询的效率。

## 方案架构

![说明方案使用了哪些 AWS 服务的示意图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/11/ML-17986-semantic-cache-diagram.png)

上图中的方案架构由以下组件和工作流组成。我们假设问题“AWS re:invent 2024 将在哪天举行？”已在经过验证的语义缓存中，对应的答案也已录入为“AWS re:Invent 2024 于 2024 年 12 月 2–6 日举行”。下面我们通过一个示例，走一遍该方案会如何处理用户的问题。

1. 查询处理：

a. 用户提交问题“今年 re:Invent 什么时候举行？”，由 Invoke Agent 函数接收。

b. 该函数使用 Retrieve API 检查语义缓存（Amazon Bedrock Knowledge Bases）。

c. Amazon Bedrock Knowledge Bases 执行语义搜索，找到一个相似度为 85% 的相似问题。

2. 响应路径：（基于*步骤 1.c*中 85% 的相似度得分，我们的方案走强匹配路径）

a. 强匹配（相似度得分大于 80%）：

i. Invoke Agent 函数直接从 Amazon Bedrock 知识库返回经过验证的答案“AWS re:Invent 2024 于 2024 年 12 月 2–6 日举行”，给出确定性的响应。

ii. 无需调用 LLM，响应时间不到 1 秒。

b. 部分匹配（相似度得分 60–80%）：

i. Invoke Agent 函数调用 Amazon Bedrock agent，并通过 Amazon Bedrock Agents 的 [promptSessionAttributes](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-session-state.html#prompt-session-attribute-ex)，把缓存的答案作为 few-shot 示例提供给该 agent。

ii. 如果问题是“AWS 12 月的活动安排是怎样的？”，我们的方案会提供经过验证的 re:Invent 日期，以额外的上下文引导 Amazon Bedrock agent 的响应。

iii. 向 Amazon Bedrock agent 提供一个经过整理和验证的示例，可能有助于提升准确性。

c. 无匹配（相似度得分低于 60%）：

i. 如果用户的问题与缓存中任何经过整理和验证的问题都不相似，Invoke Agent 函数就会调用 Amazon Bedrock agent，且不向它提供任何来自缓存的额外上下文。

ii. 例如，如果问题是“re:Invent 附近有哪些酒店？”，我们的方案会直接调用 Amazon Bedrock agent，由该 agent 利用其可用的工具来组织回答。

3. 离线知识管理：

a. 经过验证的问答对存储在注解问答的 Amazon S3 存储桶（[Amazon Simple Storage Service](https://aws.amazon.com/s3/)）中，并且必须定期更新或审查，以确保缓存包含最新、最准确的信息。

b. 该 S3 存储桶会定期与 Amazon Bedrock 知识库同步。这一离线批处理过程确保语义缓存保持最新，且不影响实时操作。

## 方案演练

进行本次演练前，你需要满足以下先决条件：

- 一个 AWS 账户
- 对 Anthropic 的 Claude Sonnet V1 和 Amazon Titan Text Embedding V2 的[模型访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)
- 已安装 [AWS Command Line Interface（AWS CLI）](https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-getting-started.html)，并配置好相应的凭证

先决条件就绪后，请按以下步骤在你的 AWS 账户中部署该方案。

### 步骤 0：搭建必要的基础设施

按照 [Git 仓库](https://github.com/aws-samples/Reducing-Hallucinations-in-LLM-Agents-with-a-Verified-Semantic-Cache/) 的 [README](https://github.com/aws-samples/Reducing-Hallucinations-in-LLM-Agents-with-a-Verified-Semantic-Cache/blob/main/README.md) 中的 *“Getting started”* 说明，为该方案搭建基础设施。以下所有代码示例均取自该仓库中的 Jupyter notebook。

### 步骤 1：创建两个 Amazon Bedrock 知识库

这一步会创建两个 Amazon Bedrock 知识库。agent 知识库存储 Amazon Bedrock 服务文档，而缓存知识库包含经过整理和验证的问答对。该设置使用 [AWS SDK for Python（Boto3）](https://aws.amazon.com/sdk-for-python/) 与 AWS 服务交互。

```
agent_knowledge_base = BedrockKnowledgeBase(
    kb_name=agent_knowledge_base_name,
    kb_description="Knowledge base used by Bedrock Agent",
    data_bucket_name=agent_bucket_name,
    chunking_strategy="FIXED_SIZE",
    suffix=f'{agent_unique_id}-f'
)

cache_knowledge_base = BedrockKnowledgeBase(
    kb_name=cache_knowledge_base_name,
    kb_description="Verified cache for Bedrock Agent System",
    data_bucket_name=cache_bucket_name,
    chunking_strategy="NONE",  # We do not want to chunk our question-answer pairs
    suffix=f'{cache_unique_id}-f'
)
```

这为你的语义缓存方案奠定了基础，搭起了用于存储 agent 知识和验证缓存条目的 AWS 资源。

### 步骤 2：填充 agent 知识库，并将其与 Amazon Bedrock agent 关联

在本次演练中，你将创建一个专门回答 Amazon Bedrock 相关问题的 Amazon Bedrock agent。这个示例会把 User Guide PDF 形式的 Amazon Bedrock 文档导入 Amazon Bedrock 知识库，作为主要数据集。导入数据之后，你会创建一个带有特定指令的 agent：

```
agent_instruction = """You are the Amazon Bedrock Agent. You have access to a 
knowledge base with information about the Amazon Bedrock service on AWS. 
Use it to answer questions."""

agent_id = agents_handler.create_agent(
    agent_name,
    agent_description,
    agent_instruction,
    [agent_foundation_model],
    kb_arns=[agent_kb_arn] # Associate agent with our Agent knowledge base
)
```

该设置使 Amazon Bedrock agent 能够利用已导入的知识来回答关于 Amazon Bedrock 服务的问题。为了测试，你可以提一个 agent 知识库中并不存在的问题，让 LLM 要么拒绝回答，要么产生幻觉。

```
invoke_agent("What are the dates for reinvent 2024?", session_id="test")
# Response: Unfortunately, the dates for the AWS re:Invent 2024 conference have not 
# been announced yet by Amazon. The re:Invent conference is typically held in late 
# November or early December each year, but the specific dates for 2024 are not 
# available at this time. AWS usually announces the dates for their upcoming 
# re:Invent event around 6-9 months in advance.
```

### 步骤 3：创建包含已知问答对的缓存数据集，并填充缓存知识库

这一步你会创建一个原始数据集，收录 agent 知识库中并不存在的、经过验证的问答对。这些经过整理和验证的答案构成我们的语义缓存，用于防止在已知主题上出现幻觉。适合纳入该缓存的候选内容包括：

- **常见问题（FAQ）：** 用户经常提出的通用查询，可以稳定、准确地回答。
- **需要确定性答案的关键问题：** 精确性至关重要的主题，例如定价信息、服务限制或合规细节。
- **时效性强的信息：** 可能尚未反映在主 RAG 知识库中的近期更新、公告或临时变更。

通过用高质量、经过验证的答案精心打理这个缓存，你可以显著提升方案回答的准确性和可靠性。本次演练中，缓存使用以下示例问答对：

`Q: 'What are the dates for reinvent 2024?'`
`A: 'The AWS re:Invent conference was held from December 2-6 in 2024.'`

`Q: 'What was the biggest new feature announcement for Bedrock Agents during reinvent 2024?'`
`A: 'During re:Invent 2024, one of the headline new feature announcements for Bedrock Agents was the custom orchestrator. This key feature allows users to implement their own orchestration strategies through AWS Lambda functions, providing granular control over task planning, completion, and verification while enabling real-time adjustments and reusability across multiple agents.'`

随后，你会把这些问答对格式化为单独的文本文件，配上相应的[元数据 JSON 文件](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-metadata.html)，上传到 S3 存储桶，并导入缓存知识库。这一过程确保语义缓存中填充的是准确、经过整理和验证的信息，可以被快速检索出来回答用户查询或引导 agent 的响应。

### 步骤 4：实现经过验证的语义缓存逻辑

这一步你会实现经过验证的语义缓存方案的核心逻辑。你会创建一个函数，把语义缓存与 Amazon Bedrock agent 集成起来，增强其给出准确、一致回答的能力。

- 在缓存知识库中查询与用户问题相似的条目。
- 如果找到高相似度匹配（大于 80%），就直接返回缓存的答案。
- 对于部分匹配（60–80%），把缓存的答案作为 few-shot 示例提供给 agent。
- 对于低相似度（低于 60%），回退到标准的 agent 处理。

这套简化的逻辑构成了语义缓存方案的核心，高效地利用经过整理和验证的信息来提升回答准确性并减少不必要的 LLM 调用。

### 步骤 5：评估结果与性能

这一步通过在不同场景下测试并比较结果与延迟，来展示经过验证的语义缓存方案的效果。你将用三个测试用例来展示该方案的行为：

- 强语义匹配（相似度大于 80%）
- 部分语义匹配（相似度 60-80%）
- 无语义匹配（相似度低于 60%）

结果如下：

- 强语义匹配（相似度大于 80%）在不到 1 秒内给出完全一致、经过整理和验证的答案。  `%%time invoke_agent_with_verified_cache("What were some new features announced for Bedrock Agents during reinvent 2024?") # Output: # Cache semantic similarity log: Strong match with score 0.9176399 # CPU times: user 20.7 ms, sys: 442 μs, total: 21.1 ms # Wall time: 440 ms # During re:Invent 2024, one of the headline new feature announcements for Bedrock # Agents was the custom orchestrator. This key feature allows users to implement # their own orchestration strategies through AWS Lambda functions, providing # granular control over task planning, completion, and verification while enabling # real-time adjustments and reusability across multiple agents.`
- 部分语义匹配（相似度 60–80%）在调用期间把验证过的答案传给 LLM。即使 agent 知识库中并不存在该信息，Amazon Bedrock agent 也能借助缓存答案正确回答该问题。  `%%time invoke_agent_with_verified_cache("What are the newest features for Bedrock Agents?") # Output: # Cache semantic similarity log: Partial match with score 0.6443664 # CPU times: user 10.4 ms, sys: 0 ns, total: 10.4 ms # Wall time: 12.8 s # One of the newest and most significant features for Amazon Bedrock Agents # announced during re:Invent 2024 was the custom orchestrator. This feature # allows users to implement their own orchestration strategies through AWS # Lambda functions, providing granular control over task planning, completion, # and verification. It enables real-time adjustments and reusability across # multiple agents, enhancing the flexibility and power of Bedrock Agents.`
- 无语义匹配（相似度低于 60%）则照常调用 Amazon Bedrock agent。对于该查询，LLM 要么因为 agent 知识库中没有相关信息而拒绝提供，要么产生幻觉，给出看似合理但并不正确的回答。  `%%time invoke_agent_with_verified_cache("Tell me about a new feature for Amazon Bedrock Agents") # Output: # Cache semantic similarity log: No match with score 0.532105 # CPU times: user 22.3 ms, sys: 579 μs, total: 22.9 ms # Wall time: 13.6 s # Amazon Bedrock is a service that provides secure and scalable compute capacity # for running applications on AWS. As for new features for the Bedrock Agents # component, I do not have any specific information on recent or upcoming new # features. However, AWS services are frequently updated with new capabilities, # so it's possible there could be new agent features released in the future to # enhance security, scalability, or integration with other AWS services. Without # being able to consult the Knowledge Base, I cannot provide details on any # particular new Bedrock Agent features at this time.`

这些结果展示了语义缓存方案的效果：

- 强匹配无需调用 LLM，即可提供近乎即时、准确且确定性的回答。
- 部分匹配引导 LLM agent 给出更相关或更准确的回答。
- 无匹配则回退到标准的 LLM agent 处理，保持灵活性。

语义缓存显著降低了已知问题的延迟，并提升了相似查询的准确性，同时仍允许 agent 在必要时处理独特的问题。

### 步骤 6：清理资源

请确保删除你创建的 Amazon Bedrock 知识库以及底层的 Amazon OpenSearch Serverless 集合，以免产生不必要的费用。

## 生产就绪方面的考量

在生产环境中部署该方案之前，请先处理以下关键考量：

- **相似度阈值优化：** 试验不同的阈值，以在缓存命中率与准确性之间取得平衡。这直接影响方案在防止幻觉的同时保持相关性的效果。
- **反馈闭环实现：** 建立一种机制，用新的、准确的回答持续更新验证缓存。这有助于防止缓存陈旧，并维护方案作为 LLM 事实来源的完整性。
- **缓存管理与更新策略：** 定期用当前的常见问题刷新语义缓存，以保持相关性并提升命中率。建立系统化流程来审查、验证并纳入新条目，帮助确保缓存质量并贴合不断变化的用户需求。
- **持续调优：** 随着数据集演进调整相似度阈值。把语义缓存视为动态组件，需要针对你的具体用例持续优化。

## 结语

这种经过验证的语义缓存方法提供了一套有力方案，可减少 LLM 回答中的幻觉，同时改善延迟并降低成本。借助 Amazon Bedrock Knowledge Bases，你可以实现一套方案：高效地提供经过整理和验证的答案，用 few-shot 示例引导 LLM 的响应，并在需要时优雅地回退到完整的 LLM 处理。
