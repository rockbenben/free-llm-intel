# 在 Amazon Bedrock 上推出面向印度境内推理的 OpenAI 模型

[Amazon Bedrock 现已支持 OpenAI GPT-5.6 模型 Terra 与 Luna 在印度使用，](https://www.aboutamazon.in/news/aws/openai-gpt-terra-luna-available-india-bedrock)并提供印度地理范围的跨区域推理。如果你在印度有本地数据处理要求，包括金融服务、医疗健康与公共部门，你现在可以规模化地使用这些 OpenAI 模型。Amazon Bedrock 在印度境内处理推理请求与数据。

两个模型都提供 100 万 token 的上下文窗口，接受文本与图像输入，并产出文本输出。你的应用可以在单次请求中处理长文档、大型代码库以及文本与图像混合的工作负载。处理过程始终不会离开该国。

在本文中，我们将说明印度地理范围的跨区域推理如何从 Mumbai 与 Hyderabad 区域工作。我们还会展示如何从 Amazon Bedrock console 入手，以及如何用代码入手，分别使用 OpenAI Responses API、OpenAI Chat Completions API 和 Amazon Bedrock Converse API。

## 印度地理范围的跨区域推理

跨区域推理会自动在多个 AWS 区域之间路由推理请求，以帮助提升吞吐量，而你无需自行管理每个区域的容量。它主要是一种容量机制。你的请求不再受限于单个区域的容量，而是从更广的计算资源池中获取资源。这有助于你在负载下维持吞吐量与一致的性能，而这在流量高峰期最为重要。

使用印度地理范围的跨区域推理时，Amazon Bedrock 只在印度地理范围内的区域之间路由请求，例如 Asia Pacific（Mumbai）区域（ap-south-1）与 Asia Pacific（Hyderabad）区域（ap-south-2）。你可以扩展以满足需求，同时把数据处理保持在印度境内，从而满足数据驻留要求。你从任一印度区域作为源发起对配置文件的调用，Amazon Bedrock 会根据容量把请求路由到目标印度区域。有关各区域模型可用性的最新信息，请参阅 Amazon Bedrock 用户指南中的[按模型划分的区域可用性](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html)。

跨区域推理通过推理配置文件（inference profile）工作。你把配置文件 ID 当作模型来调用，它定义了模型以及 Amazon Bedrock 可以路由你的请求的 AWS 区域。印度地理范围的推理配置文件把路由保持在印度境内。共有两个配置文件：

- `in.openai.gpt-5.6-terra`，用于 GPT-5.6 Terra。
- `in.openai.gpt-5.6-luna`，用于 GPT-5.6 Luna。

使用推理配置文件时，无论由哪个后端区域处理请求，计费与配额消耗都记在源区域中你的账户名下。Amazon CloudWatch 与 AWS CloudTrail 只在源区域记录日志条目，因此你的监控集中在一处。

### **在 Amazon Bedrock Mantle 与 Runtime 端点之间做选择**

对于新应用，我们推荐使用 bedrock-runtime 端点。它支持 Bedrock 原生的 [InvokeModel](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-api.html) 与 [Converse](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html) API、与 OpenAI 兼容的 [Responses](https://docs.aws.amazon.com/bedrock/latest/userguide/bedrock-mantle.html#bedrock-mantle-responses) 与 [Chat Completions](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-completions-mantle.html) API，以及 Anthropic 的 [Messages](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-messages-api.html) API，并且是 [Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)、[智能 prompt 路由](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-routing.html)与[跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)等 Amazon Bedrock 功能可用的地方。

### 数据驻留

印度地理范围的配置文件把推理保持在印度境内。请求只在 ap-south-1 与 ap-south-2 之间路由。你的输入 prompt 与输出结果可能在这两个区域之间移动。数据在通过 Amazon 网络传输的过程中被加密。Amazon Bedrock 采用零数据保留（ZDR）的数据安全模型。这意味着默认情况下，Amazon Bedrock 不存储模型输入或输出。不过，对于某些模型（包括 GPT-5.6），被 Amazon Bedrock 自动滥用检测分类器标记的内容会被保留，用于离线滥用检测。详情请参阅 Amazon Bedrock 用户指南中的[滥用检测](https://docs.aws.amazon.com/bedrock/latest/userguide/abuse-detection.html)。

## 全局跨区域推理

Amazon Bedrock 还在印度提供全局跨区域推理与全局推理配置文件（前缀为 `global.`），可路由到全球受支持的商业 AWS 区域，以获得最大容量。你把请求发送到印度区域端点——Asia Pacific（Mumbai）ap-south-1 或 Asia Pacific（Hyderabad）ap-south-2——并使用全局配置文件 ID 作为模型 ID。随后 Amazon Bedrock 决定由哪个目标区域处理该请求。全局跨区域推理支持 OpenAI GPT-5.6 模型，包括 Sol、Terra 与 Luna。不过，如果你的工作负载有本地数据处理要求，请改用印度配置文件（前缀为 `in.`），因为它们把推理保持在境内。要了解更多关于全局跨区域推理的内容，请参阅[在 Amazon Bedrock 上为 OpenAI GPT-5.6 模型引入跨区域推理](https://aws.amazon.com/blogs/machine-learning/introduce-cross-region-inference-for-openai-gpt-5-6-models-on-amazon-bedrock/)。

## 从 Amazon Bedrock console 访问 GPT-5.6 模型

你可以在 Amazon Bedrock console 的文本 playground 中试用 GPT-5.6，无需写代码或配置 SDK。你可以发送 prompt、调整推理参数、在不同变体之间切换，在集成 API 之前先感受每个模型的表现。

- 在模型可用的区域（例如 Asia Pacific（Mumbai）ap-south-1）打开 [Amazon Bedrock console](https://console.aws.amazon.com/bedrock/)。
- 在导航窗格中，于 **Test** 下选择 **Playground**。
- 在页面中部选择 **Select model**。
- 搜索 OpenAI GPT-5.6 Terra，选择 **IN OpenAI GPT-5.6 Terra**，然后选择 **Apply**。
- 输入一个 prompt，选择 **Run** 以生成响应。

## 使用 OpenAI Responses API 调用 GPT-5.6 模型

Amazon Bedrock 上的 GPT-5.6 模型原生支持 OpenAI Responses API 格式。如果你的应用已经在调用 OpenAI 模型，你可以把现有的 OpenAI SDK client 指向任一印度区域（Mumbai 或 Hyderabad）的 Amazon Bedrock 端点，并把印度地理范围的推理配置文件 ID 作为 model 参数传入。

在认证方面，Amazon Bedrock 接受标准 AWS 凭证或 Amazon Bedrock API key。API key 这条路径最适合 OpenAI SDK，因为它把 key 作为 bearer token 传递。在生产环境中，请使用 `aws-bedrock-token-generator` 包以编程方式生成短期 API key。它会从你现有的 AWS 凭证派生出 bearer token，因此无需存储静态 key。

下面的示例使用 Asia Pacific（Mumbai）ap-south-1 端点与印度地理范围的推理配置文件 ID，在 Amazon Bedrock 上调用 OpenAI GPT-5.6 Terra。

```
from aws_bedrock_token_generator import provide_token
from openai import OpenAI

# Point the OpenAI SDK at the Amazon Bedrock OpenAI-compatible
# endpoint in the Asia Pacific (Mumbai) Region.
client = OpenAI(
    base_url="https://bedrock-runtime.ap-south-1.amazonaws.com/openai/v1",
    api_key=provide_token(region="ap-south-1"),  # short-term Amazon Bedrock API key, valid up to 12 hours
)

# Geographic (India) inference profile ID for GPT-5.6 Terra.
model_id = "in.openai.gpt-5.6-terra"  # "in.openai.gpt-5.6-luna" for luna
response = client.responses.create(
    model=model_id,
    input="Extract the payment due date and total amount from the invoice text that follows, and return them as JSON. <invoice text>",
    max_output_tokens=512,
)
print(response.output_text)
```

Responses API 使用单一的 `input` 字段，并在 `output_text` 中返回生成的文本，输出上限通过 `max_output_tokens` 设置。同一个 client 也适用于 Chat Completions API，如果你的应用已经采用这种格式会很有用。

### 控制推理深度

要控制推理深度，请设置可选的 `reasoning` 参数，例如 `reasoning={"effort": "low"}`。Amazon Bedrock 上的 GPT-5.6 模型支持以下推理强度级别：`none`、`low`、`medium`、`high`、`xhigh` 与 `max`。更多信息请参阅相关博文[在 Amazon Bedrock 上开始使用 OpenAI GPT-5.6 Sol、Terra 与 Luna](https://aws.amazon.com/blogs/machine-learning/get-started-with-openai-gpt-5-6-sol-terra-and-luna-on-amazon-bedrock/)。省略该参数则使用模型默认值。

```
response = client.responses.create(
    model="in.openai.gpt-5.6-terra",
    input="Extract the payment due date and total amount from the invoice text that follows, and return them as JSON. <invoice text>",
    reasoning={"effort": "high"},  # none | low | medium | high | xhigh | max
    max_output_tokens=512,
)
```

完整支持参数列表请参阅 [Amazon Bedrock 用户指南中的 OpenAI 模型文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-openai.html)。

### 带服务端状态的多轮对话

设置 `store=True` 可让 Amazon Bedrock 在服务端保留响应，然后在下一轮用 `previous_response_id` 引用它。你只需发送新的这一轮。不必重发此前的对话历史。

```
first = client.responses.create(
    model="in.openai.gpt-5.6-terra",
    input="Remember this: my favorite number is 42. Reply with just 'stored'..",
    max_output_tokens=50,
    store=True,
)

second = client.responses.create(
    model="in.openai.gpt-5.6-terra",
    previous_response_id=first.id,  # the model recalls the earlier turn
    input="what is my favourite number?",
    max_output_tokens=50,
    store=True,
)

print(second.output_text)
```

如果用 `previous_response_id` 进行串联，你所串联自的那条响应必须是以 `store=True` 创建的。从未存储的响应进行串联会返回错误。

### 流式响应

对于流式场景，设置 `stream=True` 并遍历事件：

```
stream = client.responses.create(
    model="in.openai.gpt-5.6-terra",
    input="Draft a short status update for a delayed shipment, in a polite and direct tone.",
    max_output_tokens=512,
    stream=True,
)

for event in stream:
    if event.type == "response.output_text.delta":
        print(event.delta, end="")
```

## 使用 Converse API 调用 GPT-5.6 模型

如果你更愿意使用 AWS SDK 与 SigV4 认证而不是 API key，Amazon Bedrock Converse API 也支持 GPT-5.6 模型，并为其提供与 Amazon Bedrock 上其他模型相同的统一接口。`ConverseStream` 覆盖流式场景。

```
import boto3

# Standard AWS credentials (SigV4), no API key needed.
client = boto3.client("bedrock-runtime", region_name="ap-south-1")
model_id = "in.openai.gpt-5.6-terra"  # India Geo inference profile
response = client.converse(
    modelId=model_id,
    messages=[
        {
            "role": "user",
            "content": [{"text": "Classify this support ticket as billing, technical, or account: <ticket text>"}],
        }
    ],
    inferenceConfig={"maxTokens": 512},
)
print(response["output"]["message"]["content"]
```

## Prompt 缓存

你的 prompt 可能共享一段长而稳定的前缀，例如系统指令、知识库摘录或一组 few-shot 示例。在这种情况下，Amazon Bedrock 上的 GPT-5.6 模型支持 prompt 缓存。与未缓存的输入 token 相比，缓存读取按 90% 的折扣计费。对于在多个轮次中重复相同上下文的检索增强生成（RAG）与 agent 工作负载，这一节省会迅速累积。详情请见 [Amazon Bedrock prompt 缓存文档](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)。

Prompt 缓存可与印度地理范围的推理配置文件配合使用，因此你能在印度数据驻留边界之内保留这份节省。Prompt 缓存有两种模式：显式与隐式。在隐式缓存下，Amazon Bedrock 会为你自动放置缓存断点。请注意，最小前缀长度为 1,024 token。在显式缓存下，你自行标记缓存边界以获得精确控制，并且缓存的前缀至少保持热状态 30 分钟。

```
response = client.responses.create(
    model="in.openai.gpt-5.6-terra",
    prompt_cache_key="ticket-agent-ver123",  # same key across all requests
    input=[
        {
            "type": "message",
            "role": "developer",
            "content": [{
                "type": "input_text",
                "text": SYSTEM_INSTRUCTIONS,  # long, static: guidelines, KB excerpts (>= 1,024 tokens)
                "prompt_cache_breakpoint": {"mode": "explicit"},
            }],
        },
        {
            "type": "message",
            "role": "user",
            "content": [{
                "type": "input_text",
                "text": user_question,  # changes on every request
            }],
        },
    ],
    extra_body={"prompt_cache_options": {"mode": "explicit"}},
)
```

每次响应都会在 `usage.input_tokens_details` 中告诉你缓存做了什么：

```
details = response.usage.input_tokens_details
print(f"cached: {details.cached_tokens}, written: {details.cache_write_tokens}")
```

首次调用时，你会看到 `cache_write_tokens` 有值，因为前缀被存储。后续调用时，同样的 token 会以 `cached_tokens` 返回，按缓存读取费率计费。由于这些计数是 `input_tokens` 的一部分而非额外叠加，一个被缓存的 token 只被计数并收费一次。

## 印度地理范围跨区域推理的 IAM 权限

要让某个 AWS Identity and Access Management（IAM）角色能够通过印度地理范围的推理配置文件调用 GPT-5.6 模型，需为该角色授予对三类资源的访问权限。这三类资源是：印度地理范围的推理配置文件本身、源区域中的基础模型（FM），以及配置文件中列出的每个目标区域（ap-south-1 与 ap-south-2）中的基础模型。你可以使用 [AmazonBedrockLimitedAccess](https://docs.aws.amazon.com/aws-managed-policy/latest/reference/AmazonBedrockLimitedAccess.html) 托管策略，也可以创建自己的策略。

下面的示例授予通过印度地理范围的推理配置文件使用 GPT-5.6 Terra 模型的权限。源区域是 ap-south-1，目标区域是 ap-south-1 与 ap-south-2。请把 `<ACCOUNT>` 替换为你的账户 ID；如果该角色需要两个模型，请为 `in.openai.gpt-5.6-luna` 复制这些资源。如果你从 Hyderabad 作为源，请把第一条语句中的推理配置文件 ARN 改为 ap-south-2 的。第二条语句中的基础模型资源保持不变，因为它们已经列出了两个印度区域。

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "GrantGeoCrisInferenceProfileAccess",
            "Effect": "Allow",
            "Action": [
                "bedrock:InvokeModel*"
            ],
            "Resource": [
                "arn:aws:bedrock:ap-south-1:<ACCOUNT>:inference-profile/in.openai.gpt-5.6-terra",
                "arn:aws:bedrock:ap-south-1:<ACCOUNT>:project/default"
            ]
        },
        {
            "Sid": "GrantGeoCrisModelAccess",
            "Effect": "Allow",
            "Action": [
                "bedrock:InvokeModel*"
            ],
            "Resource": [
                "arn:aws:bedrock:ap-south-1::foundation-model/openai.gpt-5.6-terra",
                "arn:aws:bedrock:ap-south-2::foundation-model/openai.gpt-5.6-terra"
            ],
            "Condition": {
                "StringEquals": {
                    "bedrock:InferenceProfileArn": "arn:aws:bedrock:ap-south-1:<ACCOUNT>:inference-profile/in.openai.gpt-5.6-terra"
                }
            }
        },
        {
            "Sid": "AllowBearerTokenAuth",
            "Effect": "Allow",
            "Action": ["bedrock:CallWithBearerToken"],
            "Resource": "*"
        }
    ]
}
```

第一条语句授予对印度地理范围推理配置文件的访问权限，适用于源自源区域的请求。第二条语句授予对源区域以及配置文件中列出的每个目标区域中基础模型的访问权限。该访问通过 `bedrock:InferenceProfileArn` 条件限定在这一个配置文件上。这些策略在 `project/default` 资源上授予 `bedrock:CallWithBearerToken` 与 `bedrock:InvokeModel`。OpenAI Responses 与 Chat Completions API 使用该资源以 Amazon Bedrock API key 认证并运行推理。

### 服务控制策略（SCP）

如果你的组织使用服务控制策略来阻止未使用的区域，那么你的区域相关 SCP 条件必须允许地理范围推理配置文件中列出的每个目标区域。

对于印度地理范围的推理配置文件，必须同时允许 `ap-south-1` 与 `ap-south-2`。阻止任一目标区域都会导致跨区域推理失败，即使源区域仍然可访问。

### 在 Amazon Bedrock 上配置使用 GPT-5.6 的 Codex

Codex 可以通过 Amazon Bedrock Runtime 使用地理范围的推理配置文件。请安装最新的 Codex CLI（codex-cli 0.149.1 或更高版本）以使用 Amazon Bedrock Runtime 模型提供方。对于身份提供方是 Okta、Auth0、Microsoft Entra ID、Amazon Cognito 或 AWS IAM Identity Center 的组织，[AWS OIDC Auth Helper 仓库](https://github.com/aws-samples/sample-openai-on-aws/tree/main/aws-oidc-auth)提供了一个示例凭证助手。

首先，按照指南配置你的身份提供方、相应的 AWS 联合资源，以及一个带有前文所示 Bedrock 权限的 IAM 角色。然后在 `~/.aws/config` 中添加一个具名 profile，这样该助手就不会替换由 default profile 解析出的凭证。

```
[profile <AWS_OIDC_PROFILE>] 
credential_process = <ABSOLUTE_PATH_TO_CREDENTIAL_PROCESS> --profile <OIDC_HELPER_PROFILE> 
region = ap-south-1
output = json 
```

这个联合助手会把 OIDC token 换成临时 AWS 凭证，Codex 随后通过标准 AWS 凭证链读取，无需进一步配置。接下来，创建或更新 ~/.codex/config.toml 并引用该 AWS profile，其他支持的设置请参阅 [Codex 配置参考](https://developers.openai.com/codex/config-reference/)：

```
model = "in.openai.gpt-5.6-terra" 
model_provider = "amazon-bedrock-runtime" 
model_reasoning_effort = "high" 
 
[model_providers.amazon-bedrock-runtime.aws] 
profile = "<AWS_OIDC_PROFILE>" 
region = "ap-south-1" 
```

如果该助手没有有效的缓存会话，它会在浏览器中打开配置好的登录页面。完成认证后，助手通过 credential_process 返回临时 AWS 凭证。请求使用 AWS SigV4 签名。当该 profile 由 AWS IAM Identity Center 支撑时，凭证本身就是短期的，并随 SSO 会话轮转。要在 Asia Pacific（Hyderabad）区域使用它，请把 AWS profile 与 Codex 配置中的区域设为 ap-south-2。

如果你已在本地配置好 AWS 凭证，Codex 可以直接使用它们。把 Amazon Bedrock Runtime 提供方指向一个 AWS profile 与一个印度区域，并把模型设为印度地理范围的推理配置文件 ID。

创建或更新 `~/.codex/config.toml`：

```
  model = "in.openai.gpt-5.6-terra"
  model_provider = "amazon-bedrock-runtime"
  model_reasoning_effort = "high"

  [model_providers.amazon-bedrock-runtime.aws]
  profile = "default"
  region = "ap-south-1"
```

profile 的值可以是 `~/.aws/config` 或 `~/.aws/credentials` 中的任意 profile。此处显示为 “default”，但如果你维护多个账户，也可以使用自己的具名 profile。

## 监控与日志

印度地理范围的推理配置文件与你已在 Amazon Bedrock 上用于其他模型的账户级控制配合工作。请求会像按需请求一样出现在 [Amazon Bedrock 模型调用日志](https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html)中。你可以把这些日志投递到 Amazon Simple Storage Service（Amazon S3）或 Amazon CloudWatch Logs。调用次数、token 数、延迟、限流与错误的 CloudWatch 指标按推理配置文件发布。你可以在 Mumbai 或 Hyderabad 跟踪 GPT-5.6 模型的使用情况，而无需自行跨区域关联日志。

要查看某个请求由哪个目标区域处理，CloudTrail 事件包含一个 `additionalEventData` 字段，其中有 `inferenceRegion` 键。对于印度配置文件，该值始终是 `ap-south-1` 或 `ap-south-2`，这为你提供了推理留在印度境内的可审计记录。用量在 AWS Cost Explorer 与 AWS Cost and Usage Report 中逐项列出。按模型归集支出的方式与你的其他 Amazon Bedrock 工作负载相同。

## 结语

Amazon Bedrock 把具备 100 万 token 上下文窗口的 OpenAI GPT-5.6 Terra 与 Luna 模型带给在印度构建应用的客户。印度地理范围的推理配置文件在 bedrock-runtime 端点上可用，这也是我们为新应用推荐的端点。借助印度地理范围的跨区域推理，你可以跨 Mumbai 与 Hyderabad 区域扩展，同时把推理保持在境内。你可以通过 OpenAI Responses API、OpenAI Chat Completions API 或 Amazon Bedrock Converse API 调用这些模型。如果你已有工作负载运行在 bedrock-mantle 端点上，它仍完全受支持且无需任何改动；要采用印度地理范围的配置文件，请把该工作负载指向 Mumbai 或 Hyderabad 的 bedrock-runtime 端点。在为生产工作负载规划规模之前，请查阅 [Amazon Bedrock 定价页面](https://aws.amazon.com/bedrock/pricing/)了解当前的 GPT-5.6 费率。

要开始使用，请查阅 GPT-5.6 Terra 与 Luna 的模型卡，以及 Amazon Bedrock 用户指南中的[跨区域推理章节](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)。在 Mumbai 或 Hyderabad 的 [Amazon Bedrock console](https://console.aws.amazon.com/bedrock/) playground 中试一个 prompt，然后接入本文前面分享的代码示例。如果遇到问题或想向社区提问，[AWS re:Post](https://repost.aws/) 是搜索或发布问题的好地方。
