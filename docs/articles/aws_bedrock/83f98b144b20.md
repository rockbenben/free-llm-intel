# 使用直接偏好优化（DPO）在 Amazon SageMaker AI 中定制 Amazon Nova

在[纽约市的 AWS Summit](https://aws.amazon.com/events/summits/new-york/) 上，我们为 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) 基础模型推出了[一整套全面的模型定制能力](https://aws.amazon.com/blogs/aws/announcing-amazon-nova-customization-in-amazon-sagemaker-ai/)。这些能力以开箱即用的 recipe 形式在 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker-ai/) 上提供，你可以用它们在模型训练的整个生命周期内适配 Nova Micro、Nova Lite 和 Nova Pro，包括预训练、监督微调和对齐。

在这个多篇系列中，我们将逐一探索这些定制 recipe，并提供分步实施指南。我们从直接偏好优化（Direct Preference Optimization，DPO）开始——这是一种对齐技术，提供了一种直截了当的方式，按你的偏好来调整模型输出。DPO 使用与两个回答配对的 prompt——其中一个优于另一个——来引导模型产出更贴合你所期望的语气、风格或准则的输出。你可以根据数据量和成本考量，选择参数高效（parameter-efficient）或全参数模型 DPO 来实施这一技术。定制后的模型可以部署到 Amazon Bedrock，使用预置吞吐量（provisioned throughput）进行推理。参数高效版本支持[按需推理](https://aws.amazon.com/blogs/machine-learning/implementing-on-demand-deployment-with-customized-amazon-nova-models-on-amazon-bedrock/)。Nova 定制 recipe 在 [SageMaker 训练作业](https://docs.aws.amazon.com/sagemaker/latest/dg/how-it-works-training.html)和 [SageMaker HyperPod](https://aws.amazon.com/sagemaker-ai/hyperpod/) 中均可用，让你可以灵活选择最贴合自身基础设施与规模需求的环境。

本文介绍一种精简的方法：使用 SageMaker 训练作业来定制 Amazon Nova Micro。

## 方案概览

如图中所示，使用 Amazon Nova recipe 配合 SageMaker 训练作业的工作流包含以下步骤：

- 用户选择一个特定的 Nova 定制 recipe，该 recipe 提供了控制 Amazon Nova 训练参数、模型设置和分布式训练策略的完整配置。你可以使用针对 SageMaker AI 环境优化的默认配置，也可以自行定制，以试验不同的设置。
- 用户向 SageMaker AI 控制平面提交 API 请求，并传入 Amazon Nova recipe 配置。
- SageMaker 使用训练作业启动脚本，在托管计算集群上运行 Nova recipe。
- 根据所选的 recipe，SageMaker AI 预置所需基础设施、编排分布式训练，并在完成后自动下线该集群。

这种精简的架构提供了完全托管的用户体验：你只需通过简单的 recipe 快速定义 Amazon Nova 训练参数并选择偏好的基础设施，端到端的基础设施管理由 SageMaker AI 负责——采用按需付费的定价模式，仅按净训练时间以秒计费。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/13/ML-19030-image-1.gif)

随后，定制后的 Amazon Nova 模型通过 Bedrock 中的 `createcustommodel` API 部署到 Amazon Bedrock，并可与 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)、[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/)和 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 等原生工具集成。

## 业务用例 – 实施过程详解

本文聚焦于适配 Amazon Nova Micro 模型，以针对特定应用的 agent 工作流优化结构化函数调用。我们展示了这种方法如何为特定领域的用例优化 Amazon Nova 模型：F1 分数提升 81%，ROUGE 指标最高提升 42%。这些改进使模型能更高效地应对大量业务应用场景，例如让客户支持 AI 助手智能地升级查询、为日程安排与工作流自动化提供数字助手，以及在电商和金融服务等领域实现决策自动化。

如下图所示，我们的方法使用 DPO 将 Amazon Nova 模型与人类偏好对齐：针对给定的用户查询和可用工具操作，向模型呈现成对的回答——一个由人工标注者偏好，一个不那么受偏好。模型使用 [nvidia/When2Call](https://huggingface.co/datasets/nvidia/When2Call) 数据集训练，以提高给出 `tool_call` 回答的可能性，这契合「在合适时机自动化后端操作」的业务目标。经过大量此类示例的训练，Amazon Nova 模型不仅学会生成正确的函数调用语法，还学会在复杂工作流中就何时以及如何调用工具做出细致判断——从而提升其在客户支持自动化、工作流编排和智能数字助手等业务应用中的实用价值。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/13/ML-19030-image-2.jpg)

训练完成后，我们使用 SageMaker 训练作业并配合相应的评估 recipe 来评估模型。评估 recipe 是一个 YAML 配置文件，用于定义 Amazon Nova 大语言模型（LLM）评估作业的执行方式。借助该评估 recipe，我们既衡量模型在特定任务上的表现，也衡量其与期望 agent 行为的对齐程度，从而可以定量评估定制方法的有效性。下图展示了这些阶段如何实现为两个独立的训练作业步骤。每个步骤我们都使用与 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 的内置集成来访问日志并监控系统指标，从而实现可靠的可观测性。模型完成训练与评估后，我们作为第 3 步使用 Amazon Bedrock Custom Model Import 功能部署模型。

## 使用 SageMaker 训练作业进行 DPO 训练

要使用 DPO 配合带 recipe 的 SageMaker 训练作业微调模型，我们使用 [PyTorch Estimator](https://sagemaker.readthedocs.io/en/stable/frameworks/pytorch/sagemaker.pytorch.html) 类。先通过以下步骤设置微调工作负载：

- 选择训练作业的实例类型和容器镜像：

```
instance_type = "ml.p5.48xlarge" 
instance_count = 2

image_uri = (
    f"708977205387.dkr.ecr.{sagemaker_session.boto_session.region_name}.amazonaws.com/nova-fine-tune-repo:SM-TJ-DPO-latest"
)
```

- 创建 PyTorch Estimator，以从选定的 Amazon Nova recipe 中封装训练设置：

```
from sagemaker.pytorch import PyTorch

# define Training Job Name
job_name = "train-nova-micro-dpo"

recipe_overrides = {
    "training_config": {
        "trainer": {"max_epochs": 1},
        "model": {
            "dpo_cfg": {"beta": 0.1},
            "peft": {
                "peft_scheme": "lora",
                "lora_tuning": {
                    "loraplus_lr_ratio": 16.0,
                    "alpha": 128,
                    "adapter_dropout": 0.01,
                },
            },
        },
    },
}

estimator = PyTorch(
    output_path=f"s3://{bucket_name}/{job_name}",
    base_job_name=job_name,
    role=role,
    instance_count=instance_count,
    instance_type=instance_type,
    training_recipe=recipe,
    recipe_overrides=recipe_overrides,
    max_run=18000,
    sagemaker_session=sess,
    image_uri=image_uri,
    disable_profiler=True,
    debugger_hook_config=False,
)
```

你可以通过 `training_recipe` 参数指向特定的 recipe，并通过以字典形式提供 `recipe_overrides` 参数来覆盖该 recipe。

`PyTorch Estimator` 类直接从所选 recipe 封装代码与训练设置，从而简化了使用体验。

在此示例中，`training_recipe`：`fine-tuning/nova/nova_micro_p5_gpu_lora_dpo` 定义了使用 PEFT 技术的 DPO 微调设置。

- 设置 PyTorch Estimator 的输入通道：使用提供的 S3 桶路径为训练集和测试集创建 [TrainingInput](https://sagemaker.readthedocs.io/en/stable/api/utility/inputs.html) 对象：

```
from sagemaker.inputs import TrainingInput

train_input = TrainingInput(
    s3_data=train_dataset_s3_path,
    distribution="FullyReplicated",
    s3_data_type="Converse",
)
test_input = TrainingInput(
    s3_data=test_dataset_s3_path,
    distribution="FullyReplicated",
    s3_data_type="Converse",
)
```

- 在已创建的 Estimator 上调用 `fit` 函数提交训练作业：

`estimator.fit(inputs={"train": train_input, "validation": test_input}, wait=True)`

你可以直接在 notebook 输出中监控作业。也可以查看 SageMaker AI 控制台，其中显示了作业状态以及相应的 [CloudWatch](https://aws.amazon.com/cloudwatch/) 日志，用于治理与可观测性，如下图所示。

## 使用评估 recipe 评估微调后的模型

要以基准或自定义数据集评估模型表现，我们可以使用 Nova 评估 recipe 和 SageMaker 训练作业来执行评估工作流，并指向上一步训练得到的模型。在 `mmlu`、`math`、`gen_qa` 和 `llm_judge` 等多个受支持的基准中，接下来我们将为 `gen_qa` 和 `llm_judge` 任务提供两种方案，它们让我们可以评估回答的准确率、精确率以及模型推理质量，并可使用自己的数据集与 Amazon Bedrock 上的基础模型对比结果。

### 方案 A：评估 gen_qa 任务

- 使用其中的代码准备数据集，并按评估 recipe 要求的以下格式组织：

```
{
    "system": "(Optional) String containing the system prompt that sets the behavior, role, or personality of the model",
    "query": "String containing the input prompt",
    "response": "String containing the expected model output"
}
```

- 将数据集保存为 `.jsonl` 文件（这是 Amazon Nova 评估 recipe 所要求的），并上传到 Amazon S3 路径：

```
# Save datasets to s3
val_dataset.to_json("./data/val/gen_qa.jsonl")

s3_client.upload_file(
    "./data/val/gen_qa.jsonl", bucket_name, f"{input_path}/val/gen_qa.jsonl"
)
...
```

- 创建评估 recipe，指向训练好的模型、验证数据以及适用于你用例的评估指标：

```
model_path = "<ESCROW_S3_PATH_MODEL_CHECKPOINTS>"

recipe_content = f"""
run:
  name: nova-micro-gen_qa-eval-job
  model_type: amazon.nova-micro-v1:0:128k
  model_name_or_path: {model_path}
  replicas: 1
  data_s3_path: {val_dataset_s3_path} # Required, input data s3 location

evaluation:
  task: gen_qa
  strategy: gen_qa
  metric: all
    
inference:
  max_new_tokens: 4096
  top_p: 0.9
  temperature: 0.1
"""

with open("eval-recipe.yaml", "w") as f:
  f.write(recipe_content)
```

- 选择实例类型、评估作业的容器镜像，并定义模型将要存放的 checkpoint 路径。Amazon Nova 评估 recipe 推荐的实例类型为：Amazon Nova Micro 和 Amazon Nova Lite 使用 `ml.g5.12xlarge`，Amazon Nova Pro 使用 `ml.g5.48xlarge`：

```
instance_type = "ml.g5.12xlarge" 
instance_count = 1

image_uri = (
    f"708977205387.dkr.ecr.{sagemaker_session.boto_session.region_name}.amazonaws.com/nova-evaluation-repo:SM-TJ-Eval-latest"
)
```

- 创建 PyTorch Estimator，以从刚创建的 recipe 封装评估设置：

```
from sagemaker.pytorch import PyTorch

# define Training Job Name
job_name = "train-nova-micro-eval"

estimator = PyTorch(
    output_path=f"s3://{bucket_name}/{job_name}",
    base_job_name=job_name,
    role=role,
    instance_count=instance_count,
    instance_type=instance_type,
    training_recipe="./eval-recipe.yaml",
    max_run=18000,
    sagemaker_session=sagemaker_session,
    image_uri=image_uri,
    disable_profiler=True,
    debugger_hook_config=False,
)
```

- 设置 PyTorch Estimator 的输入通道：使用提供的 S3 桶路径为验证数据集创建 [TrainingInput](https://sagemaker.readthedocs.io/en/stable/api/utility/inputs.html) 对象：

```
from sagemaker.inputs import TrainingInput

eval_input = TrainingInput(
    s3_data=val_dataset_s3_path,
    distribution="FullyReplicated",
    s3_data_type="S3Prefix",
)
```

- 提交训练作业：

`estimator.fit(inputs={"train": eval_input}, wait=False)`

评估指标将由 SageMaker 训练作业存储在你的 S3 桶中指定的 `output_path` 下。

### 方案 B：评估 llm_judge 任务

- 对于 `llm_judge` 任务，按以下格式组织数据集，其中 `response_A` 表示标准答案（ground truth），`response_B` 表示我们定制模型的输出：

```
{
    "prompt": "String containing the input prompt and instructions",
    "response_A": "String containing the ground truth output",
    "response_B": "String containing the customized model output"
}
```

- 沿用为 `gen_qa` 任务描述的相同做法，为 `llm_judge` 任务专门创建评估 recipe，将 `judge` 指定为 **strategy**：

```
recipe_content = f"""
run:
  name: nova-micro-llm-judge-eval-job
  model_type: amazon.nova-micro-v1:0:128k
  model_name_or_path: "nova-micro/prod"
  ...

evaluation:
  task: llm_judge
  strategy: judge
  metric: all

...
"""
```
