# 从冰箱到餐桌：使用 Amazon Rekognition 和 Amazon Bedrock 生成食谱、减少食物浪费

在当今快节奏的世界里，时间至关重要，连采购食品这类基本任务都可能让人感到仓促而棘手。尽管我们满心打算规划好膳食并据此采购，最终却常常叫了外卖，让未使用的易腐食材在冰箱里腐烂。这个看似小小的食物浪费问题，再加上杂货店扔掉的即将过期的食品供应，对全球食物浪费问题影响重大。这表明我们如何利用 [AWS 上的生成式 AI](https://aws.amazon.com/generative-ai/) 的力量来帮助解决这一问题。

通过利用 [Amazon Rekognition](https://aws.amazon.com/rekognition/) 的计算机视觉能力，以及通过 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 提供的基础模型（FM）的内容生成能力，我们开发了一套解决方案，可根据你冰箱里已有的食材和当地超市即将过期商品的库存来推荐食谱，确保你的家中食物和杂货店里的食物都能被使用，既省钱又减少浪费。

在本文中，我们将逐步介绍如何构建 *FoodSavr* 解决方案（本文为说明起见使用的虚构名称）：使用 [Amazon Rekognition Custom Labels](https://aws.amazon.com/rekognition/custom-labels-features/) 检测食材，并使用 Amazon Bedrock 上的 Anthropic Claude 3.0 生成个性化食谱。我们展示了一个端到端架构：用户可以上传冰箱的照片，方案会根据其中发现的食材（由 Amazon Rekognition 检测）给出食谱列表（由 Amazon Bedrock 生成）。该架构还能识别缺失的食材，并向用户提供附近杂货店的列表。

## 方案概览

以下参考架构展示了如何使用 Amazon Bedrock、Amazon Rekognition 及其他 AWS 服务来实现 FoodSavr 解决方案。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/26/Picture1-11-1024x591.png)

如上图所示，该架构包括以下步骤：

- 对于端到端解决方案，我们建议提供一个前端，让你的用户上传希望被检测和标注的物品图片。要了解如何在 AWS 上部署前端，请参阅 [AWS 上的前端 Web 与移动应用](https://aws.amazon.com/products/frontend-web-mobile/)。
- 用户拍摄的照片存储在 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3) 中。该 S3 存储桶应配置生命周期策略，在使用后删除图片。要了解有关 S3 生命周期策略的更多信息，请参阅[管理存储生命周期](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lifecycle-mgmt.html)。
- 该架构使用了不同的 [AWS Lambda](https://aws.amazon.com/lambda) Lambda 是一项 serverless 的 AWS 计算服务，可运行事件驱动的代码并自动管理计算资源。第一个 Lambda 函数 `DetectIngredients` 借助 [Boto3 Python API](https://boto3.amazonaws.com/v1/documentation/api/latest/index.html) 发挥 Amazon Rekognition 的能力。Amazon Rekognition 是一项先进的计算机视觉服务，使用机器学习（ML）模型来分析上传的图片。
- 我们使用 Rekognition Custom Labels，以食材数据集训练模型。你可以采用该架构，将 Rekognition Custom Labels 用于自己的用例。借助经过训练、可识别各种食材的自定义标签，Amazon Rekognition 能够识别图片中的物品。
- 随后，检测到的食材名称被安全存储在 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/)（一项完全托管的 NoSQL 数据库服务）表中，以便检索和修改。系统会向用户展示已检测到的食材列表，并提供添加其他食材，或删除他们不想要或被误识别的食材的选项。
- 用户通过 Web 界面确认食材列表后，只需点击按钮即可启动食谱生成流程。该操作会调用另一个名为 `GenerateRecipes` 的 Lambda 函数，它使用 Amazon Bedrock API 的高级语言能力（本文中使用 [Anthropic 的 Claude v3](https://aws.amazon.com/bedrock/claude/)）。这一先进的 FM 会分析从 DynamoDB 检索到的已确认食材列表，生成针对这些特定食材的相关食谱。此外，模型还会为每道食谱配上图片，带来视觉上引人入胜、激发灵感的烹饪体验。
- Amazon Bedrock 包含本方案示例中使用的两个关键 FM：Anthropic 的 Claude v3（本文撰写以来已发布更新版本）和 Stable Diffusion，分别用于食谱生成和图像生成。对于本方案，你可以使用任何适合自身用例的 FM 组合。生成的内容（本例中为文本形式的食谱和食谱图片）随后可在前端展示给用户。
- 对于这个用例，你还可以设置一个可选的订购流水线，允许用户订购 FM 所描述的食材。该流水线前面会有一个 Lambda 函数 `FindGroceryItems`，它可以在由当地超市贡献的数据库中查找推荐的杂货商品。该数据库包含即将过期的食材及其价格。

在以下各节中，我们将深入探讨如何在你自己的账户中设置该架构。步骤 8 是可选步骤，因此本文不作介绍。

### 使用 Amazon Rekognition 检测图片

### 使用 Amazon Bedrock 的 FM 生成食谱

为了生成食谱，我们使用 Amazon Bedrock——一项提供高性能 FM 的完全托管服务。我们使用 [Amazon Bedrock API](https://docs.aws.amazon.com/bedrock/latest/APIReference/welcome.html) 查询 [Anthropic 的 Claude v3 Sonnet](https://aws.amazon.com/bedrock/claude/) 模型。我们使用以下 prompt 为 FM 提供上下文：

```
You are an expert chef, with expertise in diverse cuisines and recipes. 
I am currently a novice and I require you to write me recipes based on the ingredients provided below. 
The requirements for the recipes are as follows:
- I need 3 recipes from you
- These recipes can only use ingredients listed below, and nothing else
- For each of the recipes, provide detailed step by step methods for cooking. Format it like this:
1. Step 1: <instructions>
2. Step 2: <instructions>
...
n. Step n: <instructions>
Remember, you HAVE to use ONLY the ingredients that are provided to you. DO NOT use any other ingredient. 
This is crucial. For example, if you are given ingredients "Bread" and "Butter", you can ONLY use Bread and Butter, 
and no other ingredient can be added on. 
An example recipe with these two can be:
Recipe 1: Fried Bread
Ingredients:
- Bread
- Butter
1. Step 1: Heat up the pan until it reaches 40 degrees
2. Step 2: Drop in a knob of butter and melt it
3. Step 3: Once butter is melted, add a piece of bread onto pan
4. Step 4: Cook until the bread is browned and crispy
5. Step 5: Repeat on the other side
6. Step 6: You can repeat this for other breads, too
```

以下代码是 Amazon Bedrock API 调用的正文：

```
# master_ingredients_str: Labels retrieved from DynamoDB table
# prompt: Prompt shown above
content = "Here is a list of ingredients that a person currently has." + user_ingredients_str + "\n\n And here are a list of ingredients at a local grocery store " + master_ingredients_str + prompt

body = json.dumps({
"max_tokens": 2047,
"messages": [{"role": "user", "content": content}],
"anthropic_version": "bedrock-2023-05-31"
})

j_body = json.dumps(body)

modelId = "anthropic.claude-3-sonnet-20240229-v1:0"

response = bedrock.invoke_model(body=body, modelId=modelId)
```

结合使用 prompt 和 API 调用，我们利用从 DynamoDB 表中检索到的食材生成三道食谱。你可以在 body 中添加其他参数（如 temperature、`top_p` 和 `top_k`），为 prompt 进一步设置阈值。有关使用 Amazon Bedrock API 从 Anthropic 的 Claude 3 模型获取响应的更多信息，请参阅 [Anthropic Claude Messages API](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-anthropic-claude-messages.html)。我们建议将 temperature 设置为较低值（例如 0.1 或 0.2），以帮助确保食谱生成的确定性和结构性。我们还建议将 `top_p` 值（nucleus sampling）设置为较高值（例如 0.9），将 FM 的预测限制在最可能的 token 上（本例中，模型将考虑占下一步预测总概率质量 90% 的最可能 token）。`top_k` 是另一种采样技术，将模型的预测限制在 top_k 个最可能的 token 内。例如，如果 `top_k` = 10，模型在下一步预测时只会考虑 10 个最可能的 token。使用 Amazon Bedrock 的一个关键优势是能够在同一解决方案中针对不同任务使用多个 FM。除了用 Anthropic 的 Claude 3 生成文本食谱外，我们还可以动态生成视觉上吸引人的图片来搭配这些食谱。对于这项任务，我们选择使用 [Amazon Bedrock 上提供的 Stable Diffusion 模型](https://aws.amazon.com/bedrock/stable-diffusion/)。Amazon Bedrock 还提供其他强大的图像生成模型，例如 [Titan](https://aws.amazon.com/bedrock/titan/)，我们也给出了相应的 API 调用示例。与使用 Amazon Bedrock API 从 Anthropic 的 Claude 3 获取响应类似，我们使用以下代码：

```
modelId = "stability.stable-diffusion-xl-v0" 
accept = "application/json"
contentType = "application/json"

body = json.dumps({
"text_prompts": [
{
"text": recipe_name
}
], 
"cfg_scale": 10,
"seed": 20,
"steps": 50
})

response = brt.invoke_model(
body = body,
modelId = modelId,
accept = accept, 
contentType = contentType
)
```

## 创建用于检测食材的 Lambda 函数

完成以下步骤，创建你的第一个 Lambda 函数（DetectIngredients）：

- 在 Lambda 控制台的导航窗格中选择 **Functions**。
- 选择 **Create Lambda function**。
- 选择 **Author from scratch**。
- 将函数命名为 DetectIngredients，在 **Runtime** 中选择 **Python 3.12**，然后选择 **Create function**。
- 在 Lambda 配置中，为 **Execution role** 选择 lambdaDynamoRole，将 **Timeout **提高到 **8 秒**，检查设置并选择 **Save**。
- 将 Lambda 函数代码中的文本替换为以下示例代码，然后选择 **Save**：

```
import json
import boto3
import inference
import time
s3 = boto3.client('s3') 

dynamodb = boto3.resource('dynamodb')
table = dynamodb.Table('TestDataTable')
table_name = 'TestDataTable'

def lambda_handler(event, context):
    clearTable()

test = inference.main()

labels, label_count = inference.main()

# The names array will contain a list of all the grocery ingredients detected
# in the image
names = []

for label_dic in labels:
name = label_dic['Name']
# Getting rid of unnecessary parts of label string
if "Food" in name:
    # Remove "Food" from name
    name = name.replace("Food", "")
if "In Fridge" in name:
    # Remove "In Fridge" from name
    name = name.replace("In Fridge", "")
    name = name.strip()

names.append(name)

# Loop through the list of grocery ingredients to construct a dictionary called
# items
# the items dict will be used to batch write up to 25 items at a time when
# batch_write_all is called
items=[]
for name in names:
    if (len(items)) < 29:
        items.append({
           'grocery_item': name
        })

# Remove all duplicates from array
seen = set()
unique_grocery_items = []
for item in items:
    val = item['grocery_item'].lower().strip()
    if val not in seen:
        unique_grocery_items.append(item)
        seen.add(val)

batch_write_all(unique_grocery_items)

table.put_item(
Item={
'grocery_item': "DONE"
})

def batch_write_all(items):
    batch_write_requests = [{
        'PutRequest': {
            'Item': item
        }
    } for item in items]

response = dynamodb.batch_write_item(
    RequestItems={
         table_name:batch_write_requests
    }
)

def clearTable():
    response = table.scan()
    with table.batch_writer() as batch:
        for each in response['Items']:
             batch.delete_item(
                 Key={
                         'grocery_item': each['grocery_item'] 
                 }
```

## 创建用于存储食材的 DynamoDB 表

等待表创建完成、状态变为 **Active** 后，再继续下一步。

## 创建用于调用 Amazon Bedrock 的 Lambda 函数

完成以下步骤，创建另一个 Lambda 函数来调用 Amazon Bedrock API 生成食谱：

- 在 Lambda 控制台的导航窗格中选择 **Functions**。
- 选择 **Create function**。
- 选择 **Author from scratch**。
- 将函数命名为 GenerateRecipes，在 **Runtime** 中选择 **Python 3.12**，然后选择 **Create function**。
- 在 Lambda 配置中，为 **Execution role** 选择 lambdaDynamoRole，将 **Timeout **提高到 **8 秒**，检查设置并选择 **Save**。
- 将 Lambda 函数代码中的文本替换为以下示例代码，然后选择 **Save：**

```
import json
import boto3
import re
import base64
import image_gen

dynamodb = boto3.resource('dynamodb')

bedrock = boto3.client(service_name='bedrock-runtime')

def get_ingredients(tableName):
    table = dynamodb.Table(tableName)
    response = table.scan()
    data = response['Items']

    # Support for pagination
    while 'LastEvaluatedKey' in response:
        response = table.scan(ExclusiveStartKey=response['LastEvaluatedKey'])
        data.extend(response['Items'])

    data = [g_i for g_i in data if g_i['grocery_item'] != 'DONE']
    return data
```

## 创建用于存储图片的 S3 存储桶

最后，创建一个 S3 存储桶来存储你上传的图片，每次上传后都会自动调用 DetectIngredients Lambda 函数。完成以下步骤，创建存储桶并配置 Lambda 函数：

- 在 Amazon S3 控制台的导航窗格中选择 **Buckets**。
- 选择 **Create bucket**。
- 输入唯一的存储桶名称，将所需区域设置为 us-east-1，然后选择 **Create bucket**。
- 在 Lambda 控制台中，导航到 DetectIngredients
- 在 **Configuration **选项卡上，选择 **Add trigger**。
- 将触发器类型选择为 **S3**，并选择你创建的存储桶。
- 将 **Event type** 设置为 **All object create events**，然后选择 **Add**。
- 在 Amazon S3 控制台中，导航到你创建的存储桶。
- 在 **Properties** 和 **Event Notifications** 下，选择 **Create event notification**。
- 输入事件名称（例如 Trigger DetectIngredients），并将事件设置为 **All object create events**。
- 对于 **Destination**，选择 **Lambda Function**，并选择 DetectIngredients Lambda 函数。
- 选择 **Save**。
