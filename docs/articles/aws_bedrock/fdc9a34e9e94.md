# Rocket Close 借助 Amazon Bedrock 与 Amazon Textract 变革抵押贷款文档处理

*本文由 Rocket Close 的 Jeremy Little 与 Chris Day 共同撰写。*

[Rocket Close](https://www.rocketclose.com/) 是 Rocket Companies 生态内一家总部位于底特律的产权与估值管理公司，它通过将一项耗时的手工流程转变为高效的自动化方案，提升了抵押贷款文档处理能力。该公司每天处理约 2,000 个 abstract 文档包文件，每个文件平均 75 页，因此面临一项重大运营挑战：人工抽取平均每个文档包需要 10 小时，造成相当大的资源分配负担与工作流瓶颈。

通过与 AWS 生成式 AI 创新中心（GenAIIC）建立战略合作，Rocket Close 开发出一套智能文档处理方案，显著缩短了处理时间，使流程速度提升 15 倍。该方案使用 [Amazon Textract](https://aws.amazon.com/textract/) 完成 OCR 处理、使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 提供基础模型（FM），在文档切分、分类和字段抽取方面达到 90% 的整体准确率。Amazon Bedrock 是一项完全托管的服务，提供无服务器且更安全的方式来构建和扩展生成式 AI 应用；它通过单一 API 访问来自多家 AI 公司的领先 FM。该方案被设计为每年可扩展到 500,000 份以上文档，这一转型使 Rocket Close 站在抵押贷款行业技术创新的前沿，支撑更快的客户服务与可持续的业务增长。

本文探讨该方案是如何开发与实施的，并展示生成式 AI 如何变革抵押贷款行业中大量依赖文档的流程。

## 大规模人工处理的挑战

Rocket Close 在其产权与估值管理服务中需要处理大量复杂文档。Rocket Close 致力于通过技术驱动的解决方案简化复杂流程，帮助客户实现拥有住房与财务自由的梦想。通过分析广泛的数据点，Rocket Close 能够快速、准确地评估与一笔贷款相关的风险，从而做出更有依据的放贷决策，并为客户提供其所需的融资。Rocket Close 面临一个威胁其增长与盈利的关键瓶颈：

- **业务量过载** – 每天 2,000 个 abstract 文档包，每个平均 75 页
- **工作流耗时** – 由于近期业务量激增，每个文档包需 10 小时，而每个包实际的人工处理工作量估计约为 30 分钟
- **财务影响** – 每个文件的成本相当可观，复杂案件的费用更高，每年处理成本合计达数百万
- **可扩展性受限** – 人工流程无法跟上不断增长的需求
- **质量隐患** – 人工错误与数据抽取不一致

由于每天需要约 1,000 小时的人工处理工作量，Rocket Close 需要一个既能保持准确性、又能大幅缩短处理时间的方案。

## 了解 abstract 文档包

abstract 文档包是与房产所有权及交易相关的法律文件的完整集合。这类文档包通常包含 50–100 页、由多种文档类型捆绑而成的内容，往往格式不一致、质量参差且结构复杂。每个文档包都需要彻底查阅，以抽取关于房产所有权、留置权、抵押贷款和法律状态的关键信息。由于内容高度异构，这些文档包给自动化处理带来了独特挑战：同一个包中的文档可能包含打印文本、版面布局、手写批注、表格、表单、签名和印章。此外，特定文档的排列顺序与是否出现，在不同文档包之间也可能差异很大，这要求具备精细的文档切分与分类能力。

该方案可处理 60 多个不同的文档类别，这些类别归属于若干主要类目：

- **抵押贷款文档** – 包括主要抵押贷款工具，如抵押贷款协议、信托契约和担保工具。这些文档确立了以不动产作为担保的贷款条款，并包含关于贷款金额、利率和还款条件的关键信息。
- **产权链文档** – 此类文档涵盖各种契约类型（一般保证契约、放弃权利契约、特殊保证契约），用于记录房产所有权的历史转移。这些文档确立了法律意义上的产权链，对核实产权是否清晰至关重要。
- **判决文档** – 包括民事判决、判决摘要以及可能影响房产所有权的各类留置权通知。这些文档记录了针对房产所有者、可能影响产权状态的法律主张。
- **税务文档** – 此类文档包括与税务相关的申报，例如联邦税务留置权通知和州税务留置权通知，它们代表因欠税而对房产可能形成的主张。
- **法律文档** – 涵盖各类法律申报，包括未决诉讼、止赎起诉书、继承人宣誓书以及其他可能影响房产所有权状态的法院文书。

## 方案架构

AWS GenAIIC 与 Rocket Close 团队协作开发了一套方案，利用生成式 AI 能力来自动化 abstract 文档包的处理工作流。下图展示了这一两阶段流程的整体方案流水线：使用 Amazon Textract 完成 OCR 处理，使用 Amazon Bedrock 完成智能信息抽取。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/06/ML-19763-image-1.jpeg)

流水线的第一阶段使用 Amazon Textract 将文档图像转换为机器可读的文本。系统通过先进的 OCR 功能处理 PDF 文档，可检测版面布局、表格、表单和签名，同时保留文档的结构层级。抽取出的内容随后被转换为 markdown 格式，既保持人类可读性又保持机器可处理性，并被存储到 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）和本地，供后续处理使用。

第二阶段使用 Amazon Bedrock 的基础模型执行全面的文档分析与数据抽取。系统首先借助领域知识资源分析文档内容并生成目录，从而对文档进行分类与切分。然后根据文档类型，使用结合领域知识的专用 prompt 抽取相关数据字段。抽取出的信息被转换为标准化 JSON 格式，以便与其他系统无缝集成。

该方案的有效性依赖于若干创新性的技术方法：

- **先进的 prompt 工程** – 团队开发了专用 prompt，用以策略性地引导大语言模型（LLM）在不同文档处理任务中的行为。文档分析 prompt 将内容与分类指南结合起来，以促进准确的文档切分；信息抽取 prompt 则纳入字段定义与领域知识，以锁定文档中的特定数据元素。这些精心设计的 prompt 包含示例说明与精确的格式指令，使模型能在各种文档类型与格式下产出稳定、结构化的输出。
- **领域特定知识集成** – 系统纳入行业特定知识，通过若干互补方法来提升抽取准确率。数据字段到文档类别的映射确保系统针对每类文档锁定恰当的信息；完善的数据字典提供清晰的字段定义与预期的抽取格式；抵押贷款行业术语表帮助系统准确理解金融领域常见的专业术语与缩写。这些领域知识在处理过程中被动态纳入 prompt，显著提升了系统从复杂文档中抽取准确信息的能力。
- **领域感知的评估框架** – 项目的成功取决于一套并非只依赖基础准确率指标的评估系统。该方案包含一个综合性框架，其中的指标针对不同字段类型量身定制，便于在抵押贷款领域内准确评估抽取质量。

团队实现了多种专门方法，包括精确与模糊字符串匹配、带可配置容差的数值比较，以及针对州代码、契约类型、交易类型和文档引用的抵押贷款专用指标。领域特定的匹配函数可处理专业内容中的差异，字段类型特定的指标则应用相应的比较方法。

## 成果与影响

概念验证取得了超出预期的强劲成果，验证了该方法对 Rocket Close 文档处理需求的有效性。

该方案在多个评估轮次中经历了严格的性能测试。初始验证阶段测试了 28 个随机样本，其中包含 655 个数据字段，整体准确率达到 90.53%。这一早期成功证明了该方法的可行性，并让人们有信心开展更广泛的测试。

第二轮聚焦于有针对性的测试，使用 52 个与基准真值数据 1:1 映射的样本，涵盖 2,249 个数据字段。系统在该阶段达到 91.28% 的准确率，确认了在不同文档类型下性能的一致性，并以经过核实的基线数据验证了抽取方法。这一阶段对于建立对 Amazon Textract 与定制处理流水线处理多种文档格式能力的信心尤为重要。

最终评估涉及大规模验证，处理了 1,792 个样本、包含超过 44,000 个数据字段，整体准确率达到 89.71%。这次广泛测试在 Rocket Close 文档量的代表性样本上验证了方案的可扩展性与可靠性，表明 AWS 基础设施即使在并行处理大批量多样化文档时也能保持高准确率。

该方案由 AWS 提供支持，有助于在多个维度上创造可观的业务价值。自动化系统将处理时间从每个文档包 30 分钟缩短到 2 分钟以内，使处理速度提升 15 倍。这种加速带来了更快的客户服务与更高的吞吐量。从财务角度看，该方案大幅降低处理成本，为每个文件带来显著节省；按每天处理数千个文件（约 2,000 个）计算，这代表着企业级的潜在年度节省。自动化系统还带来更高的质量与一致性，在保持 90% 整体准确率的同时减少人工错误并统一输出格式。这种一致性改善了下游流程与决策，为业务运营提供可靠的数据。此外，基于云的架构通过在不按比例增加人手的情况下应对不断增长的文档量，提升了可扩展性，从而支持业务增长而无需线性增加成本。它被设计为可弹性扩展至每年处理 500,000 份以上文档，并能在处理高峰期自动扩容，使 Rocket Close 为未来扩张做好准备，而不受基础设施制约。

## 经验总结

概念验证合作揭示了若干有价值的洞见，可为 AWS 上类似的文档处理实施提供指引。

prompt 工程被证明至关重要，因为纳入领域知识的精心设计 prompt 能显著提升抽取准确率。团队开发了专用 prompt，把文档内容与分类指南、领域特定知识结合起来。

两阶段流水线架构在此用例中展现出很强的有效性。将 OCR 与 LLM 处理分离，可以更好地优化每个阶段。Amazon Textract 负责从各种文档格式中抽取文本并保留结构信息这一复杂任务，Amazon Bedrock（使用 Anthropic 的 Claude）则专注于理解内容并抽取相关信息。

领域特定知识集成成为另一个关键成功因素。纳入抵押贷款专用术语与文档理解能力可显著改善结果。该方案使用数据字典、术语表和文档类别定义来帮助提升抽取准确率。

此次合作还凸显了评估的复杂性，这是一个重要考量。开发精细的、领域感知的评估指标对于准确衡量性能至关重要。该评估框架采用针对不同字段类型量身定制的专用指标，包括州代码匹配、契约类型匹配和交易类型匹配。

最后，可扩展性方面的考量从初始设计阶段起就被证明至关重要。方案架构必须从一开始就按高效处理海量文档来设计。采用 Amazon Textract 与 Amazon Bedrock 的两阶段流水线方法有助于提供所需的可扩展性。

## 下一步

在概念验证成功之后，Rocket Close 已具备推进生产实施的条件。

下一阶段将从 POC 转向生产部署，采用可处理企业级文档处理的容器化架构。团队计划通过建立反馈循环来构建持续改进流程，以随时间推移提升抽取准确率。这种迭代方式让系统能够从处理结果中学习，并适应不断演变的文档模式。

长期成功的一个重要考量是制定模型更新策略。Rocket Close 将制定一项策略，在 Amazon Bedrock 提供新版本时更新 LLM 模型，确保方案受益于语言模型能力的最新进展。

最后，这套经验证的方法将扩展到初始范围之外的更多工作流。Rocket Close 计划将该方案应用于贷款与抵押贷款清算处理、购房协议处理以及产权清理文档，把自动化文档处理带来的收益扩展到其更多业务中。

## 结论

Rocket Close 与 AWS 生成式 AI 创新中心的合作展示了生成式 AI 在文档密集型行业中的变革潜力。通过自动化 abstract 文档包处理这一复杂任务，Rocket Close 已为实现重大运营效率、成本节省和更好的可扩展性做好准备。该方案 90% 的强劲整体准确率，加上处理时间从数小时大幅缩短到数分钟，展示了生成式 AI 如何解决抵押贷款与产权行业中的真实业务挑战。

随着 Rocket Close 推进生产实施，在此概念验证期间奠定的基础将支撑其文档处理工作流持续创新与流程优化。
