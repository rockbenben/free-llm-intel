# 为 LLM 训练准备自己的数据集入门

大型语言模型（LLM）在各类语言任务中展现出了卓越的能力。然而，这些模型的性能在很大程度上受训练过程中所用数据的影响。

在这篇博文中，我们介绍如何为 LLM 训练准备自己的数据集。无论你的目标是针对特定任务对预训练模型进行 fine-tuning，还是为特定领域的应用继续预训练，精心整理的数据集都是实现最佳性能的关键。

在这篇博文中，我们介绍如何为 LLM 训练准备自己的数据集。无论你的目标是针对特定任务对预训练模型进行 fine-tuning，还是为特定领域的应用继续预训练，精心整理的数据集都是实现最佳性能的关键。

## 数据预处理

文本数据来源多样，格式也五花八门，例如 PDF、HTML、JSON，以及 Word、Excel、PowerPoint 等 Microsoft Office 文档。现成的、可以直接处理并送入 LLM 训练的文本数据并不多见。因此，LLM 数据准备流水线的第一步，就是从这些不同的来源和格式中提取并汇总数据。在这一步中，你会从多个来源读取数据，借助相应工具提取文本：对扫描版 PDF 使用光学字符识别（OCR），对 Web 文档使用 HTML 解析器，对 Microsoft Office 文件等专有格式使用专门的库。HTML 标签、非 UTF-8 字符等非文本元素通常会被移除或规范化。

下一步是过滤低质量或不符合要求的文档。常见的数据过滤方式包括：

- 基于文档名称或 URL 等元数据进行过滤。
- 基于内容的过滤，例如排除任何有毒或有害内容，以及个人身份信息（PII）。
- 使用正则过滤器识别文本中特定的字符模式。
- 过滤含有过多重复句子或 n-gram 的文档。
- 针对特定语言（例如英语）的过滤器。
- 其他质量过滤器，例如文档中的词数、平均词长、由字母字符与非字母字符构成的词所占比例等。
- 基于模型的质量过滤，使用轻量级文本分类器识别低质量文档。例如，[FineWeb-Edu 分类器](https://huggingface.co/HuggingFaceFW/fineweb-edu-classifier)用于评估网页的教育价值。

从各种文件格式中提取文本并非易事。好在有不少高级库可以大幅简化这一过程。我们会用几个示例来演示文本提取，并在后面探讨如何将其扩展到大规模文档集合。

### HTML 预处理

处理 HTML 文档时，要移除文档标记标签、内联 CSS 样式和内联 JavaScript 等非文本数据。此外，还要把列表、表格和示例代码块等结构化对象转换为 Markdown 格式。[trafilatura](https://trafilatura.readthedocs.io/en/latest/) 库提供了命令行界面（CLI）和 Python SDK，可以按这种方式转换 HTML 文档。下面的代码片段演示了该库的用法：从[使用 torchtune 在 Amazon SageMaker 上 fine-tune Meta Llama 3.1 模型](https://aws.amazon.com/blogs/machine-learning/fine-tune-meta-llama-3-1-models-using-torchtune-on-amazon-sagemaker/)这篇博文中提取并预处理 HTML 数据。

### PDF 处理

PDF 是组织内部存储和分发文档的常见格式。从 PDF 中提取干净的文本颇具挑战，原因有多方面。PDF 可能采用复杂的版面，包含文本分栏、图像、表格和图形；其中还可能嵌有标准库无法解析的字体和图形。与 HTML 不同，PDF 没有标题、段落、列表之类的结构信息可供利用，这使得解析 PDF 文档要困难得多。如果文档存在其他格式，例如 HTML、Markdown，甚至 DOCX 文件，应尽可能避免解析 PDF。在没有替代格式的情况下，可以使用 [pdfplumber、](https://github.com/jsvine/pdfplumber) [pypdf](https://pypdf.readthedocs.io/en/stable/) 和 [pdfminer](https://pdfminersix.readthedocs.io/en/latest/) 等库来帮助从 PDF 中提取文本和表格数据。下面的示例演示如何用 pdfplumber 解析 2023 年 Amazon 年度报告 PDF 的第一页。

```
import pdfplumber

pdf_file = "Amazon-com-Inc-2023-Annual-Report.pdf"

with pdfplumber.open(pdf_file) as pdf:
    page = pdf.pages[1]

print(page.extract_text(x_tolerance=1)[:300])
```

pdfplumber 提供边界框信息，可用于移除页眉、页脚等多余文本。不过，该库只适用于本身含有文本的 PDF，例如数字原生生成的 PDF。对于需要 OCR 的 PDF 文档（例如扫描件），可以使用 [Amazon Textract](https://aws.amazon.com/textract/) 等服务。

### Office 文档处理

用 Microsoft Office 或其他兼容办公软件编写的文档，也是组织内常见的格式。这类文档包括 DOCX、PPTX 和 XLSX 文件，也有相应的库可以处理它们。下面的代码片段使用 [python-docx](https://python-docx.readthedocs.io/en/latest/) 库从 Word 文档中提取文本：代码遍历文档中的各个段落，并将它们拼接成一个字符串。

```
from docx import Document
doc_file = "SampleDoc.docx"

doc = Document(doc_file)

full_text = []
for paragraph in doc.paragraphs:
  full_text.append(paragraph.text)

document_text = '\n'.join(full_text)
```

### 去重

完成预处理之后，还需要进一步处理数据，去除重复项（去重）并过滤掉低质量内容。

去重是准备高质量预训练数据集的关键环节。根据 [CCNet](https://aclanthology.org/2020.lrec-1.494.pdf) 的研究，重复的训练样本在常见的自然语言处理（NLP）数据集中普遍存在。这一问题不仅常常给来自互联网等公开领域的数据集带来偏差，在整理自己的训练数据集时也可能成为隐患。组织在构建自有训练数据集时，往往会使用多种数据来源，例如内部邮件、备忘录、员工内部聊天记录、支持工单、对话以及内部 wiki 页面。同一段文本可能出现在多个来源中，也可能在单一来源（例如某个邮件线程）里过度重复。重复数据会延长训练时间，并可能使模型偏向出现频率更高的样本。

一种常用的处理流水线是 [CCNet 流水线](https://aclanthology.org/2020.lrec-1.494.pdf)。下面介绍 CCNet 流水线中采用的去重与过滤方法。

**将文档切分为分片**。在 CCNet 论文中，作者将 30 TB 数据划分为 1,600 个分片。在该示例中，分片就是经过分组的文档集合，每个分片包含 5 GB 数据和 160 万份文档。组织可以根据自身的数据规模和计算环境决定分片数量及每个分片的大小。创建分片的主要目的是让去重过程能够在计算节点集群上并行执行。

**为文档中的每个段落计算哈希码**。每个分片包含许多文档，每份文档又包含多个段落。我们为每个段落计算一个哈希码，并保存到二进制文件中。CCNet 论文的作者使用规范化段落的 SHA-1 值前 64 位作为键，通过比较这些键来完成去重。如果同一个键出现多次，那么这些键所指向的段落就被视为重复段落。你可以只在一个分片内比较键，这种情况下不同分片之间仍可能存在重复段落；如果跨所有分片比较键，则可以确认整个数据集中不存在重复段落。不过，这样做的计算开销可能很大。

[MinHash](https://en.wikipedia.org/wiki/MinHash#:~:text=In%20computer%20science%20and%20data,how%20similar%20two%20sets%20are.) 是另一种估算两个段落相似度的常用方法。这项技术对大型数据集尤为有用，因为它能高效近似计算 [Jaccard 相似度](https://en.wikipedia.org/wiki/Jaccard_index)。段落会被拆解为 [shingle](https://en.wikipedia.org/wiki/W-shingling)，即固定长度、相互重叠的词或字符序列。每个 shingle 会经过多个哈希函数处理。对于每个哈希函数，我们取所有 shingle 中的最小哈希值，并将其作为该段落的签名，称为 *MinHash 签名*。利用 MinHash 签名，就可以计算段落之间的相似度。MinHash 技术同样可以应用于词、句子或整篇文档。这种灵活性使 MinHash 成为各类文本相似度任务的强大工具。下面的示例展示了这项技术的伪代码：

```
function MinHash_similarity(text1, text2, shingle_length, num_hash_functions):
    # Preprocess texts
    shingles1 = create_shingles(text1, shingle_length)
    shingles2 = create_shingles(text2, shingle_length)

    # Initialize MinHash signatures
    minhash_signatures = []

    # Compute MinHash signatures
    for i from 1 to num_hash_functions:
        hash_function = generate_hash_function()
        minhash1 = minimum_hash(shingles1, hash_function)
        minhash2 = minimum_hash(shingles2, hash_function)
        minhash_signatures.append((minhash1, minhash2))

    # Estimate Jaccard similarity
    common_minhashes = count_common_minhashes(minhash_signatures)
    jaccard_similarity = common_minhashes / num_hash_functions
    return jaccard_similarity
```

使用 MinHash 进行去重的完整步骤如下：

- 将文档拆分为段落。
- 按前面示例所示应用 MinHash 算法，计算段落之间的相似度得分。
- 根据段落之间的相似度识别重复对。
- 将重复对合并为簇，并从每个簇中选取一个代表性段落，以最大限度减少重复。

为提高相似度搜索的效率，尤其是在处理大型数据集时，MinHash 常常与[局部敏感哈希](https://en.wikipedia.org/wiki/Locality-sensitive_hashing)（LSH）等技术结合使用。LSH 对 MinHash 形成补充，它通过分桶和哈希技术快速识别潜在匹配项，而不必对数据集中的每一项进行两两比较。这种组合即便面对海量文档或数据点，也能实现高效的相似度搜索，大幅降低此类操作通常带来的计算开销。

需要注意的是，段落级去重并不是唯一的粒度选择。正如 Meta 的 [Llama 3 论文](https://ai.meta.com/research/publications/the-llama-3-herd-of-models/)所示，也可以采用句子级去重。论文作者还使用了文档级去重来移除近似重复的文档。与段落级去重相比，句子级去重的计算成本更高，但它能对重复内容提供更细粒度的控制。与此同时，删除重复句子可能导致段落不完整，进而影响剩余文本的连贯性和上下文。因此，需要根据数据集的性质仔细权衡粒度与上下文保留之间的关系。

## 创建用于模型 fine-tuning 的数据集

对预训练 LLM 进行 fine-tuning，是指通过有监督的方式在带标注的数据集上训练模型，或借助强化学习技术，使其适配特定任务或领域。fine-tuning 的数据集考量至关重要，因为它直接影响模型的性能、准确性和泛化能力。最重要的考量包括：

- **相关性与领域特定性**：数据集应与模型所要 fine-tune 的任务或领域高度匹配。要确保数据集包含模型可能遇到的多样化样本和边缘情况。这有助于提升模型在各种真实场景下的鲁棒性和泛化能力。例如，在为金融情感分析 fine-tune 模型时，数据集应包含财经新闻文章、分析师报告、股市评论以及公司财报公告。
- **标注质量**：数据集必须没有噪声、错误和无关信息。带标注的数据集必须保持标签一致性。数据集应准确反映 fine-tuning 过程所追求的正确答案、人类偏好或其他目标结果。
- **数据集规模与分布**：尽管 fine-tuning 所需的 token 通常少于预训练（数千对数百万），但数据集仍应足够大，以覆盖任务需求的广度。数据集应包含多样化的样本，体现模型预期要处理的语言、上下文和风格上的变化。
- **伦理考量**：分析并缓解数据集中存在的偏差，例如性别、种族或文化偏差。这些偏差可能在 fine-tuning 过程中被放大，导致不公平或带有歧视性的模型输出。要确保数据集符合伦理标准，并公平地代表不同群体和观点。
- **合理的数据截止时间**：准备数据集时，需要考虑的一个问题是为数据选择截止日期。通常，可根据信息变化的速度选择较早或较晚的截止时间。例如，为品牌一致性 fine-tune LLM 时，可以选择较早的截止时间，因为品牌用语多年保持不变；而准备用于生成审计与合规信函的数据集时，则需要较早的截止时间，因为新的合规法规会不断出台和更新。
- **模态**：对于多模态模型，数据集必须包含各种受支持的数据类型。每种数据类型都必须遵循这里提到的其他考量，例如标注质量、伦理考量、相关性和领域特定性等。
- **合成数据增强**：考虑生成合成数据来补充真实世界数据，尤其是填补数据集中的空白，确保其真实且具有代表性。采用这些技术有助于克服数据可用性有限的挑战，增强模型鲁棒性，并在各类任务上实现更好的泛化。

### fine-tuning 的数据集格式

指令微调（instruction tuning）是指用各种以自然语言指令形式表达的任务，对预训练模型做进一步训练。这种方法旨在增强模型理解并遵循明确指令的能力，从而提升其在各类下游任务上的表现，而无需针对具体任务做 fine-tuning。有一种称为 reference tuning 的技术，用于让大型模型与人类的偏好和价值观对齐。该方法通过将人类反馈纳入训练过程，提升 AI 生成输出的质量、安全性和可接受度。这两种技术对数据的要求差异很大，因此我们将在后面的章节中详细展开。

**使用 Self-Instruct 技术生成指令微调格式合成数据的方法**

使用 Self-Instruct 技术生成合成数据，是构建指令微调数据集最知名的方法之一。该方法利用 LLM 的能力，自举出多样且广泛的指令微调样本集合，大幅减少了对人工标注的需求。下图展示了 Self-Instruct 技术的流程，后面几节会对其加以说明。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/14/ML-17661-synthetic-data-gen-image.png)

**种子数据与任务**

种子数据流程从一小组人工编写的指令-输出对开始，这些样本充当种子数据。种子数据集是构建稳健任务集合的基础，这些任务会应用于各个领域，重点在于提升任务多样性。在某些情况下，input 字段会提供支持指令的上下文，尤其是在输出标签有限的分类任务中。另一方面，对于非分类任务，仅指令本身可能就已自足，无需额外输入。该数据集通过不同的数据格式和解法鼓励任务多样化，因此是确定最终任务池的关键一步，而任务池又支撑着各种 AI 应用的开发。

下面是一个种子任务示例，它用于识别金融实体（公司、政府机构或资产），并根据给定句子分配词性标签或实体分类。

```
{
    "id": "finance_task_001",
    "name": "financial_entity_classification",
    "instruction": "Identify the type of financial entity in the given sentence.",
    "instances": [
      {
        "input": "Entity: Federal Reserve\nSentence: The Federal Reserve raised interest rates by 0.25% to combat inflation.",
        "output": "Government Institution, ORG"
      }
    ],
    "is_classification": true
  }
```

下面的示例要求解释一个金融概念；由于它不是分类任务，输出会更加开放。

```
{
    "id": "finance_task_002",
    "name": "explain_financial_concept",
    "instruction": "Explain the concept of compound interest in two sentences.",
    "instances": [
      {
        "input": "",
        "output": "Compound interest is the interest on a loan or deposit calculated based on both the initial principal and the accumulated interest from previous periods. It allows investments to grow at a faster rate compared to simple interest, where interest is only calculated on the principal."
      }
    ],
    "is_classification": false
  }
```

**指令生成**

以种子数据为基础，通过 prompt 让 LLM 生成新的指令。该过程以现有的人工编写指令作为示例，帮助模型（例如 Anthropic 的 Claude 3.5 或 Meta Llama 405B）生成新指令，随后对其进行质量检查和过滤，再添加到最终输出列表中。

```
Come up with a series of tasks:
1. Suggest a diversified investment portfolio for someone with a moderate risk tolerance.
2. What is the relation between the following financial ratios and company performance?
3. Generate a one-sentence description for each of the following economic terms.
4. Describe a situation in which market volatility can negatively impact retirement planning.
```

**样本生成**

对于每一条生成的指令，模型会创建相应的输入-输出对。这一步会给出如何遵循指令的具体示例。针对非分类任务的 **Input-First Approach** 要求模型先生成输入值，再用这些输入值生成对应的输出。这种方法尤其适用于金融计算这类任务，因为其输出直接取决于具体的输入。

```
input_first_template = \
'''Come up with examples for the following tasks.
Try to generate multiple examples when possible.
If the task doesn't require additional input, you can generate the output directly.
Task: Calculate the compound interest for the given principal, rate, and time period.
Example 1
Principal: $10,000, Rate: 5%, Time: 2 years
Output: $1,025 (Compound interest using annual compounding)
Example 2
Principal: $5,000, Rate: 3%, Time: 5 years
Output: $796.25 (Compound interest using annual compounding)
...
Task: {instruction}'''
```

针对分类任务的 **Output-First Approach** 则是先定义输出（类别标签），再基于输出来生成输入。这种方法确保所创建的输入与预先定义的类别标签相对应。

```
output_first_template = \
'''Given the classification task definition and the class labels,
generate an input that corresponds to each of the class labels.
If the task doesn't require input, just generate possible class labels.
Task: Identify whether the following financial transaction is categorized as "Income" or "Expense."
Class Label: Income
Transaction: Payment received from client for consulting services - $5,000.
Class Label: Expense
Transaction: Payment made for office rent - $1,200.
...
Task: {instruction}'''
```

**后处理过滤器**

过滤与质量控制步骤通过多种机制剔除低质量或冗余样本，以验证数据集质量。生成任务之后，会提取并格式化样本实例，再依据规则进行过滤，例如移除输入与输出相同的实例、输出为空的实例，或已存在于任务池中的实例。此外还会应用其他启发式检查，例如生成不完整或格式问题，以维护最终数据集的完整性。

有关 Self-Instruct 合成数据生成的更多细节，请参阅 [Alpaca: A Strong, Replicable Instruction-Following Model](https://crfm.stanford.edu/2023/03/13/alpaca.html)，了解其数据创建方法以及如何使用该数据集进行指令微调。对于包括指令微调和直接偏好优化在内的各种 fine-tuning 任务，都可以采用类似方法。

**针对不同下游任务（例如代码语言、摘要等）的数据标注**

在为 LLM 训练准备数据时，数据标注发挥着关键作用，因为它直接决定并影响模型生成回答的质量。一般来说，训练 LLM 可以采用多种方法，具体取决于手头的任务，因为我们期望 LLM 能应对各种用例。基础模型之所以能在多种指令和任务上表现出色，是因为在预训练过程中，我们向模型提供了相应的指令和示例，使其能够理解指令并执行任务。例如，要求模型生成代码或执行命名实体抽取。针对每种任务训练 LLM，都需要特定任务的标注数据集。下面探讨几种常见的数据标注方法：

- **人工标注员**：最常见的数据标注方法是使用人工标注员。在这种方法中，由一组人工标注员为各类任务标注数据，例如通用问答、情感分析、摘要、比较不同文本的异同等等。对于每一类任务，你要准备好相应的数据集，并请人工标注员给出答案。为减轻个体偏差，可以针对同一个问题从多位人工标注员处收集多个回答，然后将这些回答整合为一个汇总标签。人工标注被视为大规模收集高质量数据的黄金标准。然而，对于涉及数百万数据点的标注任务，手工标注往往繁琐、耗时且成本高昂，这推动了 AI 辅助数据标注工具的研究，例如 [Snapper](https://aws.amazon.com/blogs/machine-learning/snapper-provides-machine-learning-assisted-labeling-for-pixel-perfect-image-object-detection/)，它们能以交互式的方式减轻人工标注的负担。
- **LLM 辅助标注**：另一种常见的标注方法是使用另一个 LLM 来标注数据，以加快标注速度。在这种方法中，你让另一个 LLM 为情感分析、摘要、编码等各种任务生成回答。实现方式可以有多种。在某些情况下，我们可以使用 N-shot learning 方法提升标签质量。为减轻偏差，我们采用 human-in-the-loop（HITL）方式对部分回答进行复核，以确认标签质量。这种方法的好处是比人工标注更快，因为你可以扩展 LLM endpoint 并并行处理多个请求。但缺点在于，你必须不断迭代、调整模型回答置信度的接受阈值。例如，如果你在为金融犯罪场景准备数据集，就必须降低对假阴性的容忍度，并接受略高的假阳性率。
- **基于群组的标注**：基于群组的标注是一种新兴方法，让两个以上的 LLM 为同一份数据生成标签，然后询问这些模型是否同意其他模型的回答。只有当两个模型都认可彼此的回答时，标签才会被接受。这种方法还有另一种变体：不要求模型相互认可，而是使用第三个 LLM 对另外两个模型的输出质量打分。它能产生高质量的输出，但标注成本呈指数级上升，因为每个数据点至少需要三次 LLM 调用才能得出最终标签。这一方法目前正处于积极研究阶段，我们预计近期会出现更多相关编排工具。
- **基于 RLHF 的数据标注**：这一方法受 RLHF fine-tuning 过程的启发。根据手头的任务，你先抽取一部分未标注的数据点，交由人工标注员标注，然后用标注好的数据集对 LLM 进行 fine-tuning。下一步是让 fine-tune 后的 LLM 为另一部分未标注数据点生成多个输出，由人工标注员将这些输出从好到差排序，再用这些数据训练奖励模型。随后，将其余未标注数据点送入通过监督策略初始化的强化学习 [PPO](https://huggingface.co/blog/deep-rl-ppo)。该策略生成标签，然后你让奖励模型为该标签计算奖励，奖励又进一步用于更新 PPO 策略。想深入了解这一主题，请参阅[在 Amazon SageMaker 上用 RLHF 改进 LLM](https://aws.amazon.com/blogs/machine-learning/improving-your-llms-with-rlhf-on-amazon-sagemaker/)。

## 结论

为 LLM 训练准备高质量数据集是一个关键而复杂的过程，需要仔细考量多种因素。从不同来源提取并清洗数据，到内容去重和坚守伦理标准，每一步都对模型性能起着至关重要的作用。遵循本文提出的指导原则，组织可以整理出全面的数据集，捕捉自身领域的细微差别，从而得到更准确、更可靠的 LLM。
