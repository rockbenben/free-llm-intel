## [人工智能](https://aws.amazon.com/blogs/machine-learning/)

# 用 Amazon Bedrock AgentCore 生成演示文稿

一个金融服务团队每周都要花大量时间，手工把季报、合规文件和市场分析做成给客户的 PowerPoint 演示文稿。每份演示文稿都要读几百页材料、抽取关键数据点、组织幻灯片结构，并生成配套的视觉素材。本文带你一步步搭建一个使用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 的 AI agent 系统，把这套工作流自动化——在我们的内部测试中，它在 90 秒内完成。这个方法把生成内容牢牢锚定在源文档上的同时，缩短了演示文稿的制作时间。该方案把 supervisor agent 部署在 AgentCore runtime（Amazon Bedrock AgentCore 的一项能力）上，使用 [Strands Agents](https://strandsagents.com/) 框架来编排文档生成与摘要两类工具。Anthropic Claude Sonnet 4.6（可在 Amazon Bedrock 上使用）负责内容创作，Amazon Titan Text Embeddings v2 支撑向量检索，Stability AI Stable Image Inpaint（可在 Amazon Bedrock 上使用）生成幻灯片图片。本文附带一个公开仓库，里面是代码资产。

## 方案概览

该方案在 Amazon Bedrock AgentCore runtime 上部署单个 supervisor agent，由它根据用户请求在文档生成和摘要工具之间选择。一条检索增强生成（RAG）pipeline 使用 Amazon OpenSearch Serverless 来做多模态内容的向量存储与语义检索。

该方案包含一个用 .NET 8 minimal APIs 构建的 REST API，因此你可以通过标准 HTTP 调用把它集成进现有企业应用。AWS Lambda 提供无服务器计算，包括用于 PowerPoint 生成的容器化函数。该方案用 [Amazon Virtual Private Cloud (Amazon VPC)](https://docs.aws.amazon.com/vpc/) 做隔离、用 [AWS Key Management Service (AWS KMS)](https://docs.aws.amazon.com/kms/) 做加密、用 [AWS Identity and Access Management (IAM)](https://docs.aws.amazon.com/iam/) 做最小权限访问控制来加固整个实现。

## 关键概念

本节讲与本方案相关的 AgentCore runtime、RAG 和内容安全护栏。

### 用 Amazon Bedrock AgentCore 做 agent 编排

一个要从大型知识库生成文档的 AI agent，必须检索内容、组织大纲、生成文本、创建图片并拼装文件。该方案没有把这些彼此冲突的职责实现成一个单体函数，而是采用基于工具的架构：由一个 supervisor agent 把请求路由给专门的工具。

Amazon Bedrock AgentCore runtime 提供一个平台，用来以任意框架或任意模型大规模地构建、连接和优化 agent。agent 代码运行在一个隔离容器里，自带会话管理、内置身份和可观测性。该方案使用 Strands Agents 框架（一个用于构建 AI agent 的开源 SDK）来实现 supervisor 逻辑。

这个 supervisor agent 暴露两个工具：

- **generate_pptx：** 调用 PPTX Generator Lambda 函数来创建 PowerPoint 演示文稿；该函数从知识库检索内容、生成幻灯片大纲、创建 AI 图片，并拼装出最终文档。
- **generate_summary：** 使用 RAG 从知识库中抽取并综合信息，给出准确、有依据的回答。

agent 判断一个请求需要的是文档生成、内容摘要，还是两者都要，然后调用相应的工具。你只要在自己的代码里定义新的工具，就能加入新的能力，而不必改动已有的工具。

### 面向企业知识的检索增强生成（RAG）

RAG 解决的是 AI 系统里一个根本性挑战：给出准确、最新、且锚定在企业数据上的信息，而不是只依赖模型的训练数据。该实现使用 [Amazon Bedrock Knowledge Bases](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base.html)，它把向量检索与大语言模型（LLM）结合起来，在生成回答之前先检索相关上下文。

RAG pipeline 按如下方式工作：

- 你把企业文档上传到 [Amazon Simple Storage Service (Amazon S3)](https://docs.aws.amazon.com/s3/)。
- 系统对文档做切分和解析，并对包括表格、图表和图片在内的多模态内容应用专门处理。
- Amazon Titan Text Embeddings v2 把每个分块转换成捕捉语义的高维向量。
- [Amazon OpenSearch Serverless](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/serverless.html) 存储这些向量，形成一个可检索的向量数据库。
- 查询时，系统把用户请求转换成一个 embedding，并执行相似度检索来取回相关的文档分块。
- 取回的分块为语言模型提供上下文，由它生成锚定在原始材料上的回答。

这一方法的设计目标，是让生成的文档锚定在企业知识库中的源信息，从而帮助减少幻觉内容。

**注意：** Amazon OpenSearch Serverless collection 的数据平面必须保持公开可访问，因为 Amazon Bedrock Knowledge Bases 是从 AWS 托管的基础设施去访问 Amazon OpenSearch Serverless，而不是通过客户的 VPC 端点。IAM 数据访问策略保护这个 collection，而如果只允许 VPC 内访问，Amazon OpenSearch Serverless 的 dashboard 就会受限。

### 用 Amazon Bedrock Guardrails 保障内容安全

企业级 AI 应用需要内容审核来满足组织标准和合规要求。[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 提供内建的内容过滤与安全机制，并贯穿整条文档生成 pipeline 集成。

Guardrails 在多个阶段运行：

- **输入处理：** 过滤用户请求，帮助防止注入问题和不适宜内容。
- **输出生成：** 监控模型输出，确认其符合内容政策。
- **个人身份信息（PII）处理：** 检测 PII 并做匿名化或拦截。

该实现通过 [AWS Cloud Development Kit (AWS CDK)](https://docs.aws.amazon.com/cdk/v2/guide/cli.html) 创建自定义 guardrails，并按照企业文档创作的具体需要配置相应策略。agent 在模型调用这一层应用 guardrails，从而提供一致的内容安全，而不必为每次部署做手工配置。

## 方案架构

下图说明了这套基于 agent 的文档生成系统。

![Amazon Bedrock AgentCore 演示文稿生成系统的架构图，展示请求在 VPC 内经由 Amazon API Gateway 和 AWS Lambda 流向 supervisor agent、知识库与存储](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/09/ML-19250-1.png)

图 1：Amazon Bedrock AgentCore RAG 演示文稿生成系统的架构

数据流始于用户请求经 [Amazon API Gateway](https://docs.aws.amazon.com/apigateway/) 到达，网关把它们路由到运行在 [AWS Lambda](https://docs.aws.amazon.com/lambda/) 上、基于 .NET 的 Chat API。该 API 在 [Amazon DynamoDB](https://docs.aws.amazon.com/dynamodb/) 中维护会话状态。随后它调用托管在 Amazon Bedrock AgentCore runtime 上的 supervisor agent。

supervisor agent 分析请求并选择合适的工具。要做文档生成时，它调用 PPTX Generator Lambda（一个容器化的 Python 函数）。要做摘要时，supervisor 调用 Summary Generator Lambda，后者通过 `retrieve_and_generate` API 查询知识库。

系统对存放在 Amazon S3 的文档做处理与切分，并用 Amazon Titan Text Embeddings v2 生成 embedding。Amazon OpenSearch Serverless 为这些 embedding 建索引以支持快速语义检索。当工具查询知识库时，由 Amazon OpenSearch Serverless 取回相关分块，随后这些分块作为上下文提供给 Anthropic Claude Sonnet 4.6（在 Amazon Bedrock 上），用于生成有依据的回答。

系统把生成的文档存放在 Amazon S3，并返回 presigned URL 供安全下载。安全措施包括：

- [AWS WAF](https://docs.aws.amazon.com/waf/)，在 Amazon API Gateway 上启用托管规则集和基于 IP 的速率限制。
- [Amazon Cognito](https://docs.aws.amazon.com/cognito/)，使用 Plus 功能套餐和高级安全模式做威胁防护。
- 通过 AWS CDK 开通的 Amazon Bedrock Guardrails，用于一致的内容过滤。
- Amazon DynamoDB 启用时间点恢复、删除保护，以及客户自管的 AWS KMS 加密。
- Amazon S3 桶启用版本控制、服务器访问日志，并阻断公开访问。
- [AWS X-Ray](https://docs.aws.amazon.com/xray/) 对 Lambda 函数做追踪，用于分布式调试。
- 输入校验，用基于正则的 tenant ID 与 session ID 核验。
- 租户隔离，按租户通过 [AWS Security Token Service (AWS STS)](https://docs.aws.amazon.com/STS/latest/APIReference/Welcome.html) 假定角色。

## 前置条件

部署前，你的环境中需要配置好以下工具和访问权限：

- **AWS 环境：**  一个处于活跃状态、具备部署基础设施权限的 AWS 账户。配置好凭证的 AWS Command Line Interface (AWS CLI)。带有相应服务访问策略的 IAM 角色。
- **开发工具：**  [.NET SDK 8](https://learn.microsoft.com/en-us/dotnet/core/whats-new/dotnet-8/overview)，并全局安装 Amazon.Lambda.Tools。[Python 3.12 或更高版本](https://docs.python.org/3/)，用于 AWS CDK 和 Lambda 函数。[Node.js](https://nodejs.org/docs/latest/api/) 和 [AWS CDK CLI](https://docs.aws.amazon.com/cdk/v2/guide/cli.html)，用于部署基础设施。[Docker](https://docs.docker.com/) 或 [Finch](https://runfinch.com/)，用于构建容器镜像（需要支持 ARM64）。
- **AWS 服务访问权限：**  Amazon Bedrock，并开通对 Anthropic Claude Sonnet 4.6、Amazon Titan Text Embeddings v2 以及 Stability AI Stable Image Inpaint（均可通过 Amazon Bedrock 获取）的模型访问权限。各区域的模型可用性见 [Amazon Bedrock 中按 AWS 区域划分的受支持模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。在你的账户中启用 Amazon Bedrock AgentCore 访问权限。把 Amazon API Gateway Regional REST API 的集成超时配置为至少 300 秒，默认值是 29 秒。更多信息见 [API Gateway 配额](https://docs.aws.amazon.com/apigateway/latest/developerguide/api-gateway-execution-service-limits-table.html)。一个已有私有子网的 Amazon VPC。一个用于部署产物的 Amazon S3 桶。

## 设置该方案

设置过程包括配置部署参数和初始化 AWS CDK 环境。

- **克隆仓库**并进入项目目录：  `git clone https://github.com/aws-samples/sample-generating-powerpoint-presentations-with-amazon-bedrock.git`
- **在仓库根目录创建配置文件** `pipeline-params.ini`：  `environment=dev awscliprofile= ContainerRegistry=lambda-pptx-gen AgentContainerRegistry=agentcore-supervisor BucketDev=<amzn-s3-demo-bucket> VpcId=<your-vpc-id> ParsingInferenceProfileId=us.anthropic.claude-haiku-4-5-20251001-v1:0 AgentInferenceProfileId=us.anthropic.claude-sonnet-4-6 EmbeddingModelId=amazon.titan-embed-text-v2:0 ImageGenerationModelId=stability.stable-image-inpaint-v1:0 PPTXGenImageTag=latest AgentImageTag=latest`  把 `awscliprofile` 设为你的 AWS CLI profile 名称，或留空以使用环境变量凭证。
- **Bootstrap AWS CDK**（每个账户和区域只需一次）：  `cdk bootstrap`  这会创建 AWS CDK 部署所需的 [AWS CloudFormation](https://docs.aws.amazon.com/cloudformation/) CDKToolkit stack。
- **让构建脚本可执行：**  `chmod +x ./pipeline-build.sh chmod +x ./pipeline-deploy.sh chmod +x ./deploy-agentcore.sh`

## 构建与部署

部署分三个阶段：构建产物、部署基础设施、部署 AgentCore runtime 上的 agent。

### 构建阶段

构建阶段编译应用代码并打包部署产物。运行构建脚本：

```
./pipeline-build.sh
```

这会编译 .NET 项目（Chat API）并把它们打包成 Lambda 部署包。它用 Docker 或 Finch 构建 PPTX Generator 容器镜像，并与 [Amazon Elastic Container Registry (Amazon ECR)](https://docs.aws.amazon.com/ecr/) 完成认证。随后推送容器镜像，并把构建产物存放在 `asset-output` 目录里。

### 基础设施部署阶段

基础设施部署会创建 AWS 资源并配置服务集成。运行部署脚本：

```
./pipeline-deploy.sh
```

部署按依赖顺序创建四个 AWS CloudFormation stack：

- **VPCEndpointsStack：** 为包括 Amazon Bedrock AgentCore 在内的 AWS 服务配置 Amazon VPC 端点。
- **OpensearchStack：** 开通用于向量存储的 Amazon OpenSearch Serverless collection。
- **AgentCoreStack：** 创建 guardrails、Lambda 函数、IAM 角色，并把配置存入 [AWS Systems Manager Parameter Store](https://docs.aws.amazon.com/systems-manager/latest/userguide/systems-manager-parameter-store.html)。
- **ChatApiStack：** 部署 Amazon API Gateway 和 Chat API Lambda。

### AgentCore runtime 部署

基础设施 stack 部署完成后，把 supervisor agent 部署到 AgentCore runtime：

```
./deploy-agentcore.sh
```

这个脚本构建 supervisor agent 容器（ARM64）、把它推送到 Amazon ECR、创建 AgentCore runtime 和 endpoint，并用该 endpoint 的 Amazon Resource Name (ARN) 更新 Systems Manager 参数。Chat API 引用这个 endpoint ARN，把请求路由给 agent。

部署完成后，AWS CloudFormation 的输出里会包含 Amazon API Gateway 的 endpoint URL 和各资源标识符。

## 配置

该方案提供了若干配置点：

### agent 指令

编辑 `agent/app.py` 可以修改 supervisor agent 的 system prompt 和行为。该 agent 使用 Strands Agents，两个工具定义在 `agent/tools.py` 里：

- **generate_pptx：** 调用 PPTX Generator Lambda 做文档创建。
- **generate_summary：** 调用 Summary Generator Lambda 查询知识库。

### 模型选择

在 `pipeline-params.ini` 中调整模型标识符：

- `ParsingInferenceProfileId`：用于知识库文档解析的模型（出于成本效率推荐 Anthropic Claude Haiku 4.5）。
- `AgentInferenceProfileId`：用于 agent 推理的模型（推荐 Anthropic Claude Sonnet 4.6）。
- `EmbeddingModelId`：用于向量检索的 embedding 模型（Amazon Titan Text Embeddings v2）。
- `ImageGenerationModelId`：用于生成幻灯片图片的模型（Stability AI Stable Image Inpaint）。

使用 inference profile 而不是直接使用模型 ID，请求会取自一个更大的多区域容量池，这会提升吞吐，并有助于在负载下保持稳定的性能。

### Lambda 配置

在 stack 文件里调整计算资源：

- **Chat API：** 128 MB 内存、29 秒超时、100 的保留并发（在 `api.py` 中）。
- **PPTX Generator：** 900 MB 内存、300 秒超时、50 的保留并发（在 `pptx_gen.py` 中）。
- **Summary Generator：** 512 MB 内存、300 秒超时、50 的保留并发（在 `sum_gen.py` 中）。

## 结果

在我们的内部测试中，用一份 90 页的 [Amazon 2024 年年报](https://ir.aboutamazon.com/annual-reports-proxies-and-shareholder-letters/default.aspx) PDF，该方案产出以下性能指标：

- **演示文稿生成时间：** 端到端 70–90 秒（包括知识库检索、内容生成、图片创建和文件拼装）。
- **幻灯片数量：** 六页，含标题、要点、图片+文字、纯图片和要点总结几种版式。
- **图片生成：** 每份演示文稿两张由 Stability AI Stable Image Inpaint 生成的 AI 图片。
- **每次生成的成本：** 截至撰写时在 us-east-1 约 $0.04 的模型调用成本（文本与图片生成，其中图片生成占成本大头）。
- **知识库摄取：** 单个 1.3 MB 的 PDF 文档不到 2 分钟。

Chat API 返回：

- 用于给用户实时反馈的流式响应。由于内部测试显示生成一份演示文稿要 70–90 秒（超过 Amazon API Gateway 默认的 29 秒集成超时），Chat API 采用异步调用模式。请用流式或轮询来获取最终结果，而不是等待一个同步的 REST 调用。

## 清理

为避免持续产生费用，请删除已部署的资源：

- **删除 AgentCore runtime** 和 endpoint：  `aws bedrock-agentcore-control delete-agent-runtime-endpoint \ --agent-runtime-id <runtime-id> \ --agent-runtime-endpoint-id <endpoint-id> aws bedrock-agentcore-control delete-agent-runtime \ --agent-runtime-id <runtime-id>`
- **关闭 Amazon DynamoDB 删除保护**（删除 stack 前必须先做）：  `aws dynamodb update-table --table-name chat-sessions-dev --no-deletion-protection-enabled aws dynamodb update-table --table-name tenant-table-dev --no-deletion-protection-enabled`
- **按依赖逆序删除 AWS CloudFormation stack**：  `aws cloudformation delete-stack --stack-name ChatApiStack aws cloudformation delete-stack --stack-name AgentCoreStack aws cloudformation delete-stack --stack-name OpensearchStack aws cloudformation delete-stack --stack-name VPCEndpointsStack`
- **删除前清空 Amazon S3 桶**（AWS CloudFormation 无法删除非空桶）：  `aws s3 rm s3://amzn-s3-demo-bucket --recursive`
- **删除存放容器镜像的 Amazon ECR repository**：  `aws ecr delete-repository --repository-name lambda-pptx-gen --force aws ecr delete-repository --repository-name agentcore-supervisor --force`
- **删除租户知识库子 stack**（由 tenant provisioner 创建）：  `aws cloudformation delete-stack --stack-name bedrock-kb-<tenant-id>`

## 安全考量

该方案用 Lambda 环境变量存放模型 ID、Amazon S3 桶名、guardrail ID 这类配置值。它们是资源标识符，不是密钥。对于生产部署，请用 AWS Secrets Manager 存放 API 密钥、数据库凭证这类敏感配置值。

AgentCore runtime 上的 agent 运行在隔离容器里，并具备会话级隔离。每个用户会话都在自己的专属环境中运行，有助于避免跨会话的数据污染。

## 结论

在本文里，你用 Amazon Bedrock AgentCore 搭建了一个把企业文档生成自动化的 AI agent 系统。部署在 AgentCore runtime 上的 supervisor agent 把请求路由给专门负责文档创建和摘要的工具，在一次内部测试中把演示文稿的制作压缩到约 90 秒。

RAG pipeline 让生成内容锚定在源文档上，Amazon Bedrock Guardrails 则校验内容合规。你可以把这套架构改造用于金融服务的自动化报告生成、工程团队的技术文档，或销售组织的方案建议书创作。
