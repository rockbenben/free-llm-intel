# Amazon Bedrock AgentCore Runtime 现已支持双向流式传输，实现实时 agent 交互

用 AI agent 构建自然的语音对话，需要工程团队投入复杂的基础设施和大量代码。基于文本的 agent 交互遵循轮次模式：用户发送一个完整请求，等待 agent 处理，然后收到完整回复后才能继续。双向流式传输（bi-directional streaming）通过建立一条同时双向传输数据的持久连接，消除了这一限制。

Amazon Bedrock [AgentCore Runtime](https://aws.amazon.com/bedrock/agentcore/) 支持[双向流式传输](https://aws.amazon.com/about-aws/whats-new/2025/12/bedrock-agentcore-runtime-bi-directional-streaming/)，可在用户与 AI agent 之间实现实时的双向通信。借助这一能力，agent 可以在生成回复的同时持续接收用户输入，从而营造更自然的对话流。它尤其适合多模态交互，例如语音与视觉 agent 对话。agent 可以在仍在接收用户输入时就开始回复、处理对话中途的打断，并根据实时反馈调整回复。

双向语音聊天 agent 能以堪比人类对话的流畅度进行语音交流，让用户可以自然地打断、澄清或切换话题。这类 agent 同时处理流式音频的输入与输出，并保持对话状态。构建这套基础设施需要管理低延迟的持久连接、处理并发的音频流、在多次交互之间保留上下文，并扩展多路并发对话。从零实现这些能力需要数月的工程投入和实时系统方面的专门经验。Amazon Bedrock AgentCore Runtime 通过提供安全、无服务器、专为托管和运行 AI agent 而构建的环境来应对这些挑战，开发者无需自行构建和维护复杂的流式基础设施。

本文将介绍 AgentCore Runtime 上的双向流式传输，以及创建 WebSocket 实现所需的前置条件。你还将了解如何使用 Strands Agents 为语音 agent 实现双向流式传输方案。

## **AgentCore Runtime 双向流式传输**

双向流式传输使用 WebSocket 协议。WebSocket 在单条 TCP 连接上提供全双工通信，建立一条数据可持续双向流动的持久通道。该协议在浏览器、移动应用和服务器环境中都有广泛的客户端支持，适用于各种实现场景。

连接建立后，agent 可以以流的方式接收用户输入，同时把回复分块发送回用户。AgentCore Runtime 负责管理底层基础设施，处理连接与消息排序，并在双向交互过程中保持对话状态。这使开发者无需自行构建流式基础设施，也无需应对并发数据流的复杂性。语音对话与基于文本的交互不同，它要求自然的流畅性。与语音 agent 交谈时，用户期待获得和与人交流一样的对话动态：能在需要纠正时打断、在回复中途插入澄清，或在不出现尴尬停顿的情况下改变话题。借助双向流式传输，语音 agent 可以在生成回复的同时处理传入音频、检测打断并实时调整行为。agent 在这些交互中始终保持对话上下文，即使话题转向也能延续对话主线。这一能力还能让语音 agent 从轮次式系统进阶为有响应力的对话伙伴。

除语音对话之外，双向流式传输还支持多种交互模式。交互式调试会话让开发者可以实时引导 agent 解决问题，在 agent 探索方案时持续给予反馈。协作式 agent 可以与用户共同完成共享任务，随着工作推进持续接收输入，而不是等完整指令下达后才开始。多模态 agent 可以在处理流式视频或传感器数据的同时给出分析与建议。长时间运行的异步 agent 操作可以在数分钟甚至数小时内处理任务，并向客户端流式推送增量结果。

## **WebSocket 实现**

要在 AgentCore Runtime 中创建 WebSocket 实现，应遵循几种模式。首先，容器必须在端口 8080 上实现 **/ws** 路径的 WebSocket 端点，这符合标准 WebSocket 服务器的惯例。该 WebSocket 端点将使单个 agent 容器同时服务传统的 *InvokeAgentRuntime *API 和新的 *InvokeAgentRuntimeWithWebsocketStream *API。此外，客户还必须提供用于健康检查的 **/ping** 端点。

AgentCore Runtime 上基于 WebSocket 的双向流式传输支持使用 WebSocket 语言库的应用。客户端必须通过 WebSocket 协议连接服务端点：

```
wss://bedrock-agentcore.<region>.amazonaws.com/runtimes/<agentRuntimeArn>/ws
```

你还需要使用受支持的认证方式之一（SigV4 标头、SigV4 预签名 URL 或 OAuth 2.0），并确保 agent 应用按 [HTTP 协议契约](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-http-protocol-contract.html)的规定实现 WebSocket 服务契约。

## **Strands 双向 agent：简化语音 agent 开发**

Amazon Nova Sonic 将语音理解与生成统一到单个模型中，以低延迟、领先的准确度和出色的性价比提供类人的对话式 AI。其一体化架构在同一个模型内提供富有表现力的语音生成与实时转写，并根据输入语音的语调、语速和音色动态调整回复。

随着双向流式传输现已在 AgentCore Runtime 中可用，你有多种方式来演示如何托管语音 agent：一种是直接实现，需要自行管理 WebSocket 连接、解析协议事件、处理音频分块并编排异步任务；另一种是 Strands 双向 agent 实现，它把这部分复杂性抽象掉，自行完成上述步骤。

### **示例实现**

本文中，你可以参考 [Amazon Bedrock AgentCore 双向](https://github.com/awslabs/amazon-bedrock-agentcore-samples/tree/main/01-tutorials/01-AgentCore-runtime/06-bi-directional-streaming)代码，它实现了与 Amazon Bedrock AgentCore 的双向通信。该代码仓库包含两种实现：一种是使用 [原生 Amazon Nova Sonic Python](https://github.com/awslabs/amazon-bedrock-agentcore-samples/tree/main/01-tutorials/01-AgentCore-runtime/06-bi-directional-streaming/sonic) 实现并直接部署到 AgentCore Runtime；另一种是[高层框架实现](https://github.com/awslabs/amazon-bedrock-agentcore-samples/tree/main/01-tutorials/01-AgentCore-runtime/06-bi-directional-streaming/strands)，使用 Strands 双向 agent 简化实时音频对话。

下图展示了原生 Amazon Nova Sonic Python WebSocket 服务器直接连接 AgentCore。它通过直接的事件处理让你完全掌控 Nova Sonic 协议，可完整查看会话管理、音频流式传输和回复生成的全过程。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/17/ml-20075-image-2.png)

用于与 Amazon Nova Sonic 进行实时音频对话的 Strands 双向 agent 框架提供了高层抽象，简化了双向流式传输、自动会话管理和工具集成。下面的代码片段就是这种简化的示例。

```
from strands.experimental.bidi.agent import BidiAgent
from strands.experimental.bidi.models.nova_sonic import BidiNovaSonicModel
from strands_tools import calculator

@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket, model_name: str):
    # Define a Nova Sonic BidiModel
    model = BidiNovaSonicModel(
        region="us-east-1",
        model_id="amazon.nova-sonic-v1:0",
        provider_config={
            "audio": {
                "input_sample_rate": 16000,
                "output_sample_rate": 24000,
                "voice": "matthew",
            }
        }
    )
    # Create a Strands Agent with tools and system prompt
    agent = BidiAgent(
        model=model,
        tools=[calculator],
        system_prompt="You are a helpful assistant with access to a calculator tool.",
    )

    # Start streaming conversation
    await agent.run(inputs=[receive_and_convert], outputs=[websocket.send_json])
```

该实现展示了 Strands 的简洁性：实例化一个模型，创建带工具和 system prompt 的 agent，然后用输入/输出流运行它。框架在内部处理协议复杂性。

以下是代码中的 agent 声明部分：

```
agent = BidiAgent(
    model=model,
    tools=[calculator, weather_api, database_query],
    system_prompt="You are a helpful assistant..."
)
```

工具直接传给 agent 的构造函数，Strands 会自动处理函数调用的编排。总之，实现同样功能的原生 WebSocket 版本大约需要 150 行代码，而 Strands 实现把它缩减到大约 20 行、且都聚焦于业务逻辑。开发者可以把精力放在定义 agent 行为、集成工具和编写 system prompt 上，而不必管理 WebSocket 连接、解析事件、处理音频分块或编排异步任务。这让不具备实时系统专门经验的开发者也能用上双向流式传输，同时完整保留 Nova Sonic 的音频对话能力。Strands 双向功能目前仅支持 Python SDK。如果你希望语音 agent 的实现更具灵活性，原生 Amazon Nova Sonic 实现可以帮到你。当 agent 与模型之间存在多种不同通信模式时，这一点也很重要。使用 Amazon Nova Sonic 实现，你可以完全掌控流程的每一步。框架方式能更好地控制依赖，因为依赖由 SDK 处理，并能在不同系统之间保持一致。同一套 Strands 双向 agent 代码结构可与 Nova Sonic、OpenAI Realtime API 和 Google Gemini Live 配合使用，开发者只需替换模型实现，其余代码保持不变。

## **结论**

Amazon Bedrock AgentCore Runtime 的双向流式传输能力改变了开发者构建对话式 AI agent 的方式。通过提供基于 WebSocket 的实时通信基础设施，AgentCore 省去了从零实现流式系统所需的数月工程投入。该框架运行时让开发者可以在同一个安全、无服务器的环境中部署多种类型的语音 agent——从使用 Amazon Nova Sonic 的原生协议实现，到像 Strands 双向 agent 这样的高层框架。
