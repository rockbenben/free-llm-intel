# Claude Opus 4.5 现已登陆 Amazon Bedrock

Anthropic 最新的基础模型 [Claude Opus 4.5](https://www.anthropic.com/news/claude-opus-4-5) 现已在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 中可用；后者是一项全托管服务，提供来自领先 AI 公司的高性能基础模型供你选择。Opus 4.5 在 AI 系统能力上迈出了有意义的一步，并在编码、agent、computer use 与办公任务方面树立了新的标准。它同时超越 Sonnet 4.5 与 Opus 4.1，却以三分之一的价格提供 Opus 级别的能力。

本文将展示这个模型为何与众不同，梳理关键的业务应用，并演示如何在 Amazon Bedrock 上使用 Opus 4.5 新的工具使用能力。读完后，你将了解如何把该模型的能力用于生产环境的 agent 部署。

## Claude Opus 4.5：这个模型为何不同

Opus 4.5 是 Anthropic 在 Opus 系列中提供的最先进模型，面向构建复杂 AI agent 的开发者——这类 agent 能在极少监督下推理、规划并执行复杂任务。它在既有用例上以更好的表现升级了 Sonnet 4.5，并为复杂工作流增加了新能力。

该模型在专业软件工程领域表现出色，在 SWE-bench Verified 上达到 80.9%，帮助把耗时数天的开发项目缩短为几小时的任务。它能独立工作，包括更强的多语言编码能力，以及更高效代码、更好测试覆盖率和更清晰的架构选择等增强行为。在办公生产力方面，该模型能端到端处理复杂项目。它驱动 agent 制作具有专业质感的 PowerPoint 演示文稿、Excel 电子表格与 Word 文档，包括为合同与 NDA 做文档修订标记。该模型还能产出更高质量的 React 与 HTML 制品。它保持一致性与准确性——这对金融及其他重视精确性的行业很重要——并在长项目中跨文件维持上下文。

这是 Anthropic 迄今最好的视觉模型，在 MMMU 上达到 80.7%，适用于依赖复杂视觉解读与多步导航的工作流——例如分析设计稿、处理版式复杂的文档，或自动化浏览器端任务——而 computer use 的表现又进一步提升。

该模型为 agent 开发者带来两项关键改进。工具搜索（tool search）工具让 agent 能处理数百个工具：动态发现并只加载所需内容，而不是预先加载所有定义——这可能节省数万个 token，并在扩展到大型工具库时避免 schema 混乱。工具使用示例（tool use examples）让你直接在工具定义中提供示例工具调用，提升含嵌套对象或数组的复杂 schema 的准确率。

## 业务应用与用例

Opus 4.5 在以下用例中表现出色：

- **软件开发**：构建能在整个项目中编写与重构代码、管理全栈架构，或设计把高层目标拆解为可执行步骤的 agentic 系统的 agent。这一代 Claude 覆盖完整开发生命周期：Opus 4.5 用于生产代码与复杂 agent（那些在端到端软件工程、网络安全或金融分析等工作流中使用 10 个以上工具的 agent），Sonnet 4.5 用于快速迭代与规模化的用户体验，Haiku 4.5 用于子 agent 与免费层产品。Opus 4.5 可以分析技术文档、规划软件实现、编写所需代码并迭代改进——同时在整个过程中跟踪需求与架构上下文。
- **企业运营与办公任务**：从头到尾管理复杂项目。Opus 4.5 使用记忆来跨文件维持上下文与一致性，同时在创建电子表格、幻灯片与文档方面有所改进。该模型处理持续进行的企业项目，把人工工作流自动化。
- **金融分析**：在复杂的信息系统中工作——监管申报文件、市场报告、内部数据——支持预测建模与主动合规。该模型的一致性与准确性使其适用于金融及其他重视精确性的行业。
- **网络安全**：为安全工作流带来专业级分析，关联日志、安全问题数据库与安全情报，用于安全事件检测与自动化事件响应。

## 与 Amazon Bedrock AgentCore 的集成

Amazon Bedrock 为在生产环境中部署 Opus 4.5 提供了企业级基础。这项全托管服务为基础模型提供统一 API，并具备企业级安全、合规与治理能力。

Opus 4.5 与 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 集成，后者提供构建生产 agent 所需的基础设施与原语。AgentCore 包含用于跨会话维持上下文的持久记忆、把 API 与 [Lambda 函数](https://aws.amazon.com/lambda/) 转换为 agent 兼容工具的 Tool Gateway，以及用于安全访问资源的内置[身份与访问管理](https://aws.amazon.com/iam/)。你可以用完整的会话隔离、长时间运行的工作流支持（最长 8 小时）与可观测性功能来部署和监控 agent——这样你就能专注于构建 agent，而不是管理基础设施。

Amazon Bedrock AgentCore 为生产部署提供额外能力。Tool Gateway 只需极少代码就能把既有 API 与 Lambda 函数转换为 agent 兼容的工具——并与模型的工具搜索功能配合，编排数百个工具。通过 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 提供的内置可观测性可跟踪 agent 工作流中的 token 用量、延迟与错误率。

## 快速上手

现在即可通过 Amazon Bedrock 使用 Opus 4.5 模型。我将演示该模型的工具搜索能力——这项功能让 agent 能处理数百个工具，而无需预先把所有定义都载入上下文。首先，我导入所需模块并设置 Amazon Bedrock 客户端：

```
# Import required libraries
import boto3
import json
# Create a session and Bedrock client
session = boto3.Session()
bedrock_client = session.client(
    service_name='bedrock-runtime',
    region_name='us-east-1')
```

在本示例中，我将定义多个带 `defer_loading` 的工具以启用工具搜索。这让模型可以只发现并加载所需的工具，而不是预先加载所有定义：

```
# Define tools with tool search enabled
tools = [
    # Enable tool search - allows dynamic tool discovery
    {
        "type": "tool_search_tool_regex",
        "name": "tool_search_tool_regex"
    },
    # Tools marked with defer_loading are discovered on-demand
    {
        "name": "get_weather",
        "description": "Get current weather for a location",
        "input_schema": {
            "type": "object",
            "properties": {
                "location": {"type": "string"},
                "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]}
            },
            "required": ["location"]
        },
        "defer_loading": True,
        # Provide example inputs to improve accuracy for complex schemas
        "input_examples": [
            {"location": "San Francisco, CA", "unit": "fahrenheit"},
            {"location": "Tokyo, Japan", "unit": "celsius"}
        ]
    },
    {
        "name": "search_documentation",
        "description": "Search AWS documentation",
        "input_schema": {
            "type": "object",
            "properties": {
                "query": {"type": "string"},
                "service": {"type": "string"}
            },
            "required": ["query"]
        },
        "defer_loading": True,
        "input_examples": [
            {"query": "Lambda pricing", "service": "lambda"},
            {"query": "S3 bucket policies"}
        ]
    },
    {
        "name": "analyze_logs",
        "description": "Analyze application logs for errors",
        "input_schema": {
            "type": "object",
            "properties": {
                "log_file": {"type": "string"},
                "time_range": {"type": "string"}
            },
            "required": ["log_file"]
        },
        "defer_loading": True,
        "input_examples": [
            {"log_file": "/var/log/app.log", "time_range": "last 24 hours"},
            {"log_file": "/var/log/error.log"}
        ]
    }
]
```

现在我用 `invoke_model` API 调用模型，把 effort 参数设为 `medium`：

```
# Construct the request with beta features enabled
request_body = {
    "anthropic_version": "bedrock-2023-05-31",
    # Enable beta features: tool search, tool examples, and effort parameter
    "anthropic_beta": ["tool-search-tool-2025-10-19", "tool-examples-2025-10-29", "effort-2025-11-24"],
    "max_tokens": 4096,
    "temperature": 0.7,
    # Set effort to "medium" for balanced token usage
    "output_config": {
        "effort": "medium"
    },
    "messages": [
        {
            "role": "user",
            "content": "What's the weather in Seattle?"
        }
    ],
    "tools": tools
}

# Invoke the model
response = bedrock_client.invoke_model(
    modelId="global.anthropic.claude-opus-4-5-20251101-v1:0",
    body=json.dumps(request_body)

# Parse the response
response_body = json.loads(response['body'].read())
```

模型使用工具搜索从工具库中找到相关工具（`get_weather`），而无需预先加载所有工具定义。effort 参数目前处于 beta，它控制模型在思考、工具调用与响应之间分配 token 的宽松程度。你可以把 effort 设为 `high` 以获得最佳结果，设为 `medium` 以获得均衡用量，或设为 `low` 以保守使用 token。

## agent 开发的关键特性

Opus 4.5 具备多项能力，使其非常适合构建生产 agent。该模型在长时间工作流中保持连贯性，从而为运行数小时或数天多步流程的 agent 提供一致的决策。更好的工具处理意味着 agent 与外部系统、API 与软件界面交互得更可靠——模型会选择正确的工具，并更准确地解读结果。Opus 4.5 还能跨对话轮次跟踪信息并保持上下文，帮助 agent 随时间积累知识并基于历史做出决策。

effort 参数目前处于 beta，它让你可以控制 token 用量。质量最关键时你可以设为 `high` 以获得最佳结果，设为 `medium` 以获得均衡表现，或设为 `low` 以保守使用 token。Opus 4.5 会依据该设置调整在思考、工具调用与响应之间的 token 花费。对于生产部署，Amazon Bedrock AgentCore 通过 CloudWatch 集成提供监控与可观测性，实时跟踪 token 用量（在调整 effort 参数时很有用），同时提供延迟指标、会话时长与错误率，帮助你优化 agent 表现并管理成本。

## 定价

该模型的定价为每百万输入 token 5 美元、每百万输出 token 25 美元，让 Opus 级智能以先前产品三分之一的价格即可获得。

## 可用性与访问

该模型今天即可在 Amazon Bedrock 中通过[跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)使用；跨区域推理会自动把请求路由到 AWS 各区域中的可用容量，以便在需求高峰时获得更高吞吐。

用这个模型处理长时间运行的任务、协调多个工具，或跨长会话维持上下文的 agent。

关于可用性、定价与模型规格的详细信息，请访问 [Amazon Bedrock 文档](https://docs.aws.amazon.com/bedrock/)。
