# 通过跨区域推理访问加拿大 Amazon Bedrock 上的 OpenAI GPT 模型

在 Amazon Bedrock 上构建生成式 AI 应用程序的加拿大组织通常需要最新的基础模型 (FM)，例如可从加拿大 AWS 区域访问的 OpenAI GPT-6.1、OpenAI GPT-6 和 GPT-5.6。借助 Amazon Bedrock 跨区域推理 (CRIS)，您现在可以从加拿大访问这些模型。 [OpenAI GPT-5.6 模型（Sol、Terra 和 Luna）、GPT-6（Astra、Sol 和 Luna）和 GPT-6.1 Sol](https://aws.amazon.com/bedrock/openai/) 可从加拿大（中部）和加拿大西部（卡尔加里）区域获取。推理在北美进行处理，数据驻留控制将在本文后面描述。

跨区域推理是一种能力机制。您的应用程序调用源区域中的 Amazon Bedrock 运行时终端节点。然后，Amazon Bedrock 将请求路由到支持的目标区域进行处理。通过这种方法，您可以访问更广泛的容量池，帮助您的应用程序在需求高峰期间维持吞吐量。您不需要在应用程序中管理目标区域路由。

在这篇文章中，我们将介绍加拿大提供的 GPT-5.6、GPT-6 和 GPT-6.1 模型以及为它们提供服务的跨区域推理配置文件。然后，我们展示如何使用 OpenAI Responses API、Chat Completions API 和 Amazon Bedrock Converse API 设置权限并调用模型。对于响应 API，我们提供了流媒体和工具使用示例。最后，我们介绍了如何请求增加配额、查看源区域中可用的可观察性信号以及完成后进行清理。

## 加拿大提供的型号

借助 Amazon Bedrock，您可以通过跨区域推理访问加拿大的三个 OpenAI 模型系列。下表总结了每个模型及其定位。

| **型号** | **定位** |
| --- | --- |
| GPT-6.1 索尔 |针对性能和成本都很重要的任务进行强大的推理和编码 |
| GPT-6 阿斯特拉 |复杂的端到端推理和代理任务 |
| GPT-6 溶胶 |针对重复任务的强大推理和编码，具有适合常规使用的经济性 |
| GPT-6 露娜 |针对大批量重复任务进行快速、低成本推理，并根据请求调整推理工作量 |
| GPT-5.6 溶胶 |高推理、编码和代理工作负载 |
| GPT-5.6 泰拉 |平衡日常生产的性能和成本|
| GPT-5.6 露娜 |快速且经济实惠，适合大容量、延迟敏感的应用程序 |

这些模型接受文本和图像输入，返回文本，并支持 100 万个令牌上下文窗口、推理模式和工具调用。 GPT-6.1 Sol 支持相同的上下文窗口和工具调用，其模型卡中记录了其他输入和输出模式。 GPT-5.6、GPT-6 和 GPT-6.1 还支持 Amazon Bedrock 上的提示缓存（请参阅提示缓存部分）。这些模型可通过“bedrock-runtime”端点上的 OpenAI Responses API、OpenAI Chat Completions API 和 Amazon Bedrock Converse API 获取。

有关定价，请参阅 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。有关每个模型区域的可用性，请参阅 [Amazon Bedrock 用户指南](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-openai.html) 中的模型卡。

## 来自加拿大的跨区域推理配置文件

Amazon Bedrock 推理配置文件是您传递的代替原始模型 ID 的逻辑标识符。每个配置文件都定义一个模型以及 Amazon Bedrock 可以将请求路由到的一组区域。加拿大提供两种配置文件类型：

- **美国地理**（前缀为“us.”）将请求路由到您的加拿大源区域和美国区域。当您的工作负载需要推理处理以保留在北美（加拿大和美国）时，请选择此配置文件。
- **全球**（前缀为“global.”）将请求路由到部署模型的受支持的商业 AWS 区域。这在请求时利用了更广泛的容量池。

端点可用性因型号和源区域而异，如下表所示。

| **型号** | **美国地理概况** | **全球概况** |
| --- | --- | --- |
| GPT-6.1 索尔 | ca-central-1、ca-west-1 | ca-central-1、ca-west-1 |
| GPT-6 阿斯特拉 / 索尔 / 露娜 | ca-central-1、ca-west-1 | ca-central-1、ca-west-1 |
| GPT-5.6 太阳 / 泰拉 / 露娜 | ca-central-1、ca-west-1 | ca-中央-1 |

个人资料会员资格和模型可用性可能会发生变化。 GPT-5.6 型号的全局配置文件仅可从“ca-central-1”获取。在“ca-west-1”中，使用 GPT-5.6 的美国地理配置文件。在部署之前，使用 AWS 命令​​行界面 (AWS CLI) 或在控制台上验证源区域的活动配置文件（请参阅以下部分），或参阅[跨区域推理支持文档](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference-support.html)。

## 开始使用

以下部分将介绍从加拿大源区域调用这些模型所需的设置和代码。

### 先决条件

在开始之前，请确认您具备以下条件：

- 将加拿大（中部）“ca-central-1”或加拿大西部（卡尔加里）“ca-west-1”区域启用为源区域的 AWS 账户。
- 有权调用推理配置文件的 AWS Identity and Access Management (IAM) 角色或用户（请参阅 **设置权限**）。
- 如果您的组织强制执行 SCP，则允许源区域中的推理配置文件的服务控制策略 (SCP)（请参阅 SCP 注意事项）。
- 安装了“openai”、“boto3”和“aws-bedrock-token-generator”软件包的 Python 3.9 或更高版本。

### 设置权限

为了快速探索，请附加 AWS 托管策略“AmazonBedrockLimitedAccess”。对于具有更严格访问控制的已部署工作负载，请使用最小权限自定义策略。以下示例授予从“ca-central-1”访问 GPT-6 Astra 全局配置文件的权限：
```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["bedrock:InvokeModel*"],
      "Resource": [
        "arn:aws:bedrock:ca-central-1::inference-profile/global.openai.gpt-6-astra"
      ]
    },
    {
      "Effect": "Allow",
      "Action": ["bedrock:InvokeModel*"],
      "Resource": ["arn:aws:bedrock:*::foundation-model/openai.gpt-6-astra"],
      "Condition": {
        "StringLike": {
          "bedrock:InferenceProfileArn": "arn:aws:bedrock:ca-central-1::inference-profile/global.openai.gpt-6-astra"
        }
      }
    }
  ]
}
```
如果您通过 API 密钥路径（OpenAI SDK 的不记名令牌）进行身份验证，还需授予“bedrock:CallWithBearerToken”。对于响应 API，在 `arn:aws:bedrock:ca-central-1:*:project/default` 上添加 `bedrock:InvokeModel`。

### SCP 注意事项

如果您的组织通过 SCP 限制区域，请使用“bedrock:InferenceProfileArn”条件键允许 CRIS 流量，同时阻止对未经批准的区域的直接调用。以下 SCP 拒绝在您批准的源区域之外进行 Amazon Bedrock 推理，除非请求使用 CRIS 推理配置文件：
```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyBedrockOutsideCanadaUnlessCris",
      "Effect": "Deny",
      "Action": ["bedrock:InvokeModel*"],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "aws:RequestedRegion": ["ca-central-1", "ca-west-1"]
        },
        "ArnNotLike": {
          "bedrock:InferenceProfileArn": [
            "arn:aws:bedrock:*:*:inference-profile/us.openai.*",
            "arn:aws:bedrock:*:*:inference-profile/global.openai.*"
          ]
        }
      }
    }
  ]
}
```
在这种情况下，Amazon Bedrock 可以路由到配置文件的目标区域，即使这些区域被您的 SCP 拒绝。必须允许您选择的配置文件中的每个目标区域才能使请求成功。有关更多详细信息，请参阅[在多账户环境中设置跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-prereq.html)。

### 验证活动推理配置文件

在调用模型之前，您可以使用 AWS CLI 验证哪些配置文件在源区域中处于活动状态。以下命令列出了“ca-central-1”中的活动 OpenAI 配置文件。要从卡尔加里运行相同的检查，请将“ca-central-1”替换为“ca-west-1”。
```
aws bedrock list-inference-profiles \
    --region ca-central-1 \
    --type-equals SYSTEM_DEFINED \
    --query "inferenceProfileSummaries[?contains(inferenceProfileId, 'openai')].[inferenceProfileId,status]" \
    --output table
```
Amazon Bedrock 控制台提供相同的视图。打开控制台，选择 **加拿大（中部）** 或 **加拿大西部（卡尔加里）** 作为您的区域，选择 **推理** 下的 **跨区域推理**，然后查看可用的配置文件。

## 通过 Amazon Bedrock Runtime 调用模型

GPT-5.6、GPT-6 和 GPT-6.1 在“bedrock-runtime”终端节点上支持三种访问路径：OpenAI Responses API、OpenAI Chat Completions API 和 Amazon Bedrock Converse API。在端点的“/openai/v1”路径上调用与 OpenAI 兼容的 API。该终端节点接受 AWS 签名版本 4 (SigV4) 或 [Amazon Bedrock API 密钥](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html)。

以下示例使用 [适用于 Python 的 Amazon Bedrock 令牌生成器](https://github.com/aws/aws-bedrock-token-generator-python) 根据您当前的 AWS 凭证创建短期 Amazon Bedrock API 密钥，因此您的应用程序不需要存储静态密钥。

### OpenAI 响应 API

对于已将 OpenAI SDK 与响应 API 结合使用的应用程序，请将客户端指向区域 Amazon Bedrock 运行时终端节点并传递推理配置文件 ID 作为模型。
```
from aws_bedrock_token_generator import provide_token
from openai import OpenAI

region = "ca-central-1"  # Use "ca-west-1" for Calgary
client = OpenAI(
    base_url=f"https://bedrock-runtime.{region}.amazonaws.com/openai/v1",
    api_key=provide_token(region=region),
)

response = client.responses.create(
    model="global.openai.gpt-6-astra",
    input="What are the key considerations for AI governance in Canadian financial services?",
    max_output_tokens=1024,
)
print(response.output_text)
```
对于流输出，设置 `stream=True` 并迭代响应事件，在文本到达时打印文本：
```
stream = client.responses.create(
    model="global.openai.gpt-6-luna",
    input="List five generative AI use cases for Canadian healthcare.",
    max_output_tokens=512,
    stream=True,
)
for event in stream:
    if event.type == "response.output_text.delta":
        print(event.delta, end="", flush=True)
```
### OpenAI 聊天完成 API

OpenAI 聊天完成格式通过同一端点工作。
```
response = client.chat.completions.create(
    model="global.openai.gpt-5.6-terra",
    messages=[{"role": "user", "content": "Summarize recent AI regulatory trends in Canada."}],
    max_completion_tokens=1024,
    reasoning_effort="low",
)
print(response.choices[0].message.content)
```
有关受支持参数的完整列表（包括推理工作级别），请参阅 Amazon Bedrock 用户指南中的[模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-openai.html)。

### 亚马逊 Bedrock Converse API

当您的应用程序通过 AWS 开发工具包调用 Amazon Bedrock 时，请使用 Converse API。 Boto3 通过标准 AWS 凭证链解析凭证。
```
import boto3

bedrock = boto3.client("bedrock-runtime", region_name="ca-central-1")
response = bedrock.converse(
    modelId="us.openai.gpt-5.6-terra",
    messages=[{"role": "user", "content": [{"text": "Summarize recent AI regulatory trends in Canada."}]}],
    inferenceConfig={"maxTokens": 1024},
)
# GPT-5.6 and GPT-6 may return a reasoningContent block alongside the text.
# Select the block that contains the text output.
text_output = next(block["text"] for block in response["output"]["message"]["content"] if "text" in block)
print(text_output)
```
通过更改推理配置文件 ID，相同的调用适用于 GPT-6 Sol、GPT-6 Luna 和 GPT-6.1 Sol。以下示例使用 GPT-6 Sol 的美国地理配置文件和 GPT-6 Luna 的全球配置文件。两者均通过“ca-central-1”进行验证。
```
# GPT-6 Sol, GPT-6 Luna, and GPT-6.1 Sol are called the same way. Swap the inference profile ID, and choose a us. (US geographic) or global. profile to match your data boundary.
# For example, GPT-6.1 Sol via the US geographic profile: modelId="us.openai.gpt-6.1-sol"
# GPT-6 Sol via the US geographic profile: strong reasoning and coding for complex work.
response = bedrock.converse(
    modelId="us.openai.gpt-6-sol",
    messages=[{"role": "user", "content": [{"text": "Summarize recent AI regulatory trends in Canada."}]}],
    inferenceConfig={"maxTokens": 512},
)

# GPT-6 Luna via the global profile: fast, low-cost inference for high-volume tasks such as classification.
response = bedrock.converse(
    modelId="global.openai.gpt-6-luna",
    messages=[{"role": "user", "content": [{"text": "Classify this ticket as BILLING, TECHNICAL, or OTHER: ..."}]}],
    inferenceConfig={"maxTokens": 256},
)
```
### 工具使用

这些模型支持[客户端工具使用（函数调用）](https://docs.aws.amazon.com/bedrock/latest/userguide/tool-use-client-side.html)。在“tools”参数中定义工具，模型会返回一个结构化的工具调用请求供您的应用程序执行。
```
response = client.responses.create(
    model="global.openai.gpt-6-astra",
    input="What's the current exchange rate from CAD to USD?",
    tools=[{
        "type": "function",
        "name": "get_exchange_rate",
        "parameters": {
            "type": "object",
            "properties": {
                "from_currency": {"type": "string"},
                "to_currency": {"type": "string"}
            }
        }
    }],
)

# The model returns a tool-call request rather than text.
for item in response.output:
    if item.type == "function_call":
        print(f"Tool: {item.name}, Args: {item.arguments}")
```
## 提示缓存

GPT-5.6、GPT-6 和 GPT-6.1 支持 Amazon Bedrock 上的提示缓存，以减少重复提示前缀的成本和延迟。隐式缓存无需更改您的代码：Amazon Bedrock 自动缓存 1,024 个令牌或更多符合条件的前缀。后续请求中读取的缓存令牌将按折扣费率计费，并且不计入您的每分钟令牌配额。缓存的令牌显示在响应使用对象和 Amazon CloudWatch 指标中，以便您可以跟踪使用情况。有关缓存写入定价、最小前缀大小以及对显式缓存断点的支持，请参阅[提示缓存文档](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html) 和各个[模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-openai.html)。

## 配额管理

“bedrock-runtime”端点上的跨区域推理配额以每个模型每分钟的令牌数 (TPM) 来衡量。每个配额将输入和输出令牌与单个限制结合起来。美国地理和全球推理配置文件具有单独的配额分配，因此在它们之间切换会改变您从中提取的池。

令牌消耗结合了输入令牌、缓存写入输入令牌和输出令牌。输出令牌乘以模型的燃尽率，因此输出密集型工作负载消耗配额的速度比原始令牌计数显示的要快。在生产部署之前，请尽早增加请求配额并监控配额利用率。使用代表性提示、输出长度、流行为、并发性和峰值流量进行测试。

要请求增加配额，请执行以下步骤：

- 打开“ca-central-1”或“ca-west-1”中的[服务配额控制台](https://console.aws.amazon.com/servicequotas/)。
- 选择 **Amazon Bedrock**，然后为您需要的模型选择名为“每分钟跨区域 InvokeModel 令牌”的配额。
- 选择**请求在帐户级别增加**，输入您的目标值，然后提交请求。

有关如何跟踪令牌使用情况和成本的详细信息，请参阅[跟踪 Amazon Bedrock 中的使用情况和成本](https://docs.aws.amazon.com/bedrock/latest/userguide/cost-management.html)。

## 可观察性

由于这些模型通过 Amazon Bedrock Runtime API 运行，因此通过推理配置文件发出的请求会像按需请求一样出现在您的可观察性工具中。调用日志和 Amazon CloudWatch 指标记录在您的源区域中。无论请求在哪里处理，这都成立。您的可观察性停留在一处。

- **AWS CloudTrail** 记录每个请求，并在“additionalEventData.inferenceRegion”字段中记录哪个目标区域为其提供服务。例如： `"additionalEventData": { "inferenceProfileArn": "arn:aws:bedrock:ca-central-1:111122223333:inference-profile/global.openai.gpt-6-astra", "inferenceRegion": "us-west-2" }`
- **Amazon CloudWatch 指标** 按推理配置文件发布，涵盖调用计数、令牌计数、延迟、限制和错误。
- **模型调用日志记录** 将完整的请求和响应负载传送到 Amazon Simple Storage Service (Amazon S3) 或 Amazon CloudWatch Logs。要在 Amazon Bedrock 控制台上激活它，请选择 **设置**，然后选择 **模型调用日志记录**。您还可以调用“PutModelInitationLoggingConfiguration”API。默认情况下它是关闭的。
- **AWS Data Exports** 按模型和配置文件逐项列出支出。

### Amazon CloudWatch 编码代理见解

如果您使用这些模型为 OpenAI Codex 等 AI 编码助手提供支持，[Amazon CloudWatch Coding Agent Insights](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/coding-agents-insights.html) 会提供专用控制面板。它显示了跨部门、团队和环境等维度的令牌使用情况、API 请求计数、活跃用户和成本归因。要激活它，请配置您的编码代理以将遥测数据导出到 Amazon CloudWatch。有关设置步骤，请参阅[为 OpenAI Codex 设置 OpenTelemetry](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/coding-agents-codex.html)。

## 清理

为了避免测试后持续产生费用，请删除您创建的资源：

- 关闭模型调用日志记录。在 Amazon Bedrock 控制台上，选择 **设置**，然后选择 **模型调用日志记录**，或调用 `DeleteModelInitationLoggingConfiguration`。这将停止将日志传输到 Amazon S3 和 Amazon CloudWatch Logs。
- 删除或分离 IAM 策略以及您为测试创建的任何 Amazon Bedrock API 密钥。

推理配置文件本身是系统定义的，在不使用时不会产生任何费用。

## 安全性和合规性

跨区域推理旨在保护传输中和静态的数据。请求通过使用 TLS 1.2+ 加密的 AWS 私有骨干网而不是公共互联网传输。对于加拿大客户，您的静态数据默认保留在源区域中。这包括调用日志、知识库和配置。仅瞬态推理计算发生在目标区域中，并且默认情况下模型提供者无权访问您的提示或完成。

OpenAI 模型有一个特定的考虑因素。自动滥用分类器标记的内容可能会在目标区域保留最多 30 天以供审核。如果您想将处理限制在北美（加拿大和美国），您可以选择美国地理配置文件。我们建议您与合规团队一起查看 [Amazon Bedrock 滥用检测](https://docs.aws.amazon.com/bedrock/latest/userguide/abuse-detection.html)。

有关加拿大数据驻留模式的更详细信息，请参阅[跨区域推理和加拿大数据驻留：技术架构指南](https://builder.aws.com/content/3EuyyJgS9hWozGI9oUJIU6nCfMk/cross-region-inference-and-canadian-data-residency-a-technical-architecture-guide)。
