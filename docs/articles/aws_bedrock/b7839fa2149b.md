# 在加拿大通过跨区域推理从 Amazon Bedrock 访问 OpenAI GPT 模型

在 Amazon Bedrock 上构建生成式 AI 应用的加拿大组织，往往需要从加拿大的 AWS Region 访问最新的基础模型（FM），例如 OpenAI GPT-6.1、OpenAI GPT-6 和 GPT-5.6。借助 Amazon Bedrock 跨区域推理（CRIS），你现在可以从加拿大访问这些模型。[OpenAI GPT-5.6 模型（Sol、Terra 和 Luna）、GPT-6（Astra、Sol 和 Luna）以及 GPT-6.1 Sol](https://aws.amazon.com/bedrock/openai/) 可从 Canada (Central) 和 Canada West (Calgary) Region 使用。推理在北美处理，数据驻留控制见本文后续说明。

跨区域推理是一种容量机制。你的应用调用源 Region 中的 Amazon Bedrock Runtime 端点，Amazon Bedrock 随后把请求路由到一个受支持的目的 Region 进行处理。这样一来，你就能用上更大的容量池，帮助应用在需求高峰期间维持吞吐量。你不需要在应用里管理目的 Region 的路由。

本文将介绍可从加拿大使用的 GPT-5.6、GPT-6 和 GPT-6.1 模型，以及为它们提供服务的跨区域推理配置文件。然后展示如何设置权限，并用 OpenAI Responses API、Chat Completions API 和 Amazon Bedrock Converse API 调用这些模型。对 Responses API，我们给出流式和工具使用示例。最后，我们说明如何申请配额提升、查看源 Region 中可用的可观测性信号，以及收尾时如何清理。

## 可从加拿大使用的模型

借助 Amazon Bedrock，你可以通过跨区域推理在加拿大访问三个 OpenAI 模型系列。下表概述每个模型及其定位。

| **模型** | **定位** |
| --- | --- |
| GPT-6.1 Sol | 兼顾性能与成本的强推理与编码能力，适合两者都重要的任务 |
| GPT-6 Astra | 复杂的端到端推理与 agentic 任务 |
| GPT-6 Sol | 面向重复性任务的强推理与编码能力，经济性适合常规使用 |
| GPT-6 Luna | 面向高量重复任务的快速、低成本推理，可按请求调整推理强度 |
| GPT-5.6 Sol | 高推理、编码与 agentic 工作负载 |
| GPT-5.6 Terra | 面向日常生产的性能与成本均衡 |
| GPT-5.6 Luna | 面向高量、延迟敏感应用的快速低成本选择 |

这些模型接受文本和图片输入、返回文本，并支持 100 万 token 的上下文窗口、推理模式和工具调用。GPT-6.1 Sol 支持同样的上下文窗口和工具调用，并在其模型卡中记录了额外的输入与输出模态。GPT-5.6、GPT-6 和 GPT-6.1 还支持 Amazon Bedrock 上的提示词缓存（见“提示词缓存”一节）。这些模型可通过 OpenAI Responses API、OpenAI Chat Completions API 以及 `bedrock-runtime` 端点上的 Amazon Bedrock Converse API 使用。

价格请见 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。各模型的区域可用性请见 [Amazon Bedrock 用户指南](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-openai.html)中的模型卡。

## 从加拿大可用的跨区域推理配置文件

Amazon Bedrock 推理配置文件是逻辑标识符，你用它替代原始模型 ID 传入。每个配置文件定义一个模型，以及 Amazon Bedrock 可以把请求路由到的一组 Region。从加拿大可以使用两种配置文件类型：

- **US geographic**（前缀 `us.`）把请求路由到你的加拿大源 Region 和美国的 Region。当工作负载要求推理处理留在北美（加拿大和美国）之内时，选择这种配置文件。
- **Global**（前缀 `global.`）把请求路由到该模型已部署的受支持商业 AWS Region。它在请求发起时利用更广的容量池。

端点可用性因模型和源 Region 而异，如下表所示。

| **模型** | **US geographic 配置文件** | **Global 配置文件** |
| --- | --- | --- |
| GPT-6.1 Sol | ca-central-1、ca-west-1 | ca-central-1、ca-west-1 |
| GPT-6 Astra / Sol / Luna | ca-central-1、ca-west-1 | ca-central-1、ca-west-1 |
| GPT-5.6 Sol / Terra / Luna | ca-central-1、ca-west-1 | ca-central-1 |

配置文件成员和模型可用性都可能变化。GPT-5.6 系列的 global 配置文件只能从 `ca-central-1` 使用。从 `ca-west-1` 出发时，请对 GPT-5.6 使用 US geographic 配置文件。部署前请用 AWS Command Line Interface (AWS CLI) 或控制台（见下一节）核实源 Region 中生效的配置文件，或参阅[跨区域推理支持文档](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference-support.html)。

## 开始使用

以下几节介绍从你的加拿大源 Region 调用这些模型所需的设置和代码。

### 先决条件

开始之前，请确认你已具备以下条件：

- 一个已把 Canada (Central) `ca-central-1` 或 Canada West (Calgary) `ca-west-1` Region 启用为源 Region 的 AWS 账户。
- 一个具备调用推理配置文件权限的 AWS Identity and Access Management (IAM) 角色或用户（见**设置权限**）。
- 如果你的组织强制执行 SCP，还需要一条允许源 Region 中推理配置文件的服务控制策略（SCP）（见 SCP 注意事项）。
- Python 3.9 或更高版本，并安装了 `openai`、`boto3` 和 `aws-bedrock-token-generator` 包。

### 设置权限

快速试用时，附加 AWS 托管策略 `AmazonBedrockLimitedAccess`。对于部署后需要更严格控制的工作负载，请使用最小权限的自定义策略。以下示例授予从 `ca-central-1` 访问 GPT-6 Astra global 配置文件的权限：

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["bedrock:InvokeModel*"],
      "Resource": [
        "arn:aws:bedrock:ca-central-1::inference-profile/global.openai.gpt-6-astra"
      ]
    },
    {
      "Effect": "Allow",
      "Action": ["bedrock:InvokeModel*"],
      "Resource": ["arn:aws:bedrock:*::foundation-model/openai.gpt-6-astra"],
      "Condition": {
        "StringLike": {
          "bedrock:InferenceProfileArn": "arn:aws:bedrock:ca-central-1::inference-profile/global.openai.gpt-6-astra"
        }
      }
    }
  ]
}
```

如果你通过 API key 方式认证（为 OpenAI SDK 使用 bearer token），还需授予 `bedrock:CallWithBearerToken`。对 Responses API，还要在 `arn:aws:bedrock:ca-central-1:*:project/default` 上添加 `bedrock:InvokeModel`。

### SCP 注意事项

如果你的组织通过 SCP 限制 Region，请使用 `bedrock:InferenceProfileArn` 条件键，在允许 CRIS 流量的同时封堵对未批准 Region 的直接调用。以下 SCP 会拒绝已批准源 Region 之外的 Amazon Bedrock 推理调用，除非请求使用的是 CRIS 推理配置文件：

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyBedrockOutsideCanadaUnlessCris",
      "Effect": "Deny",
      "Action": ["bedrock:InvokeModel*"],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "aws:RequestedRegion": ["ca-central-1", "ca-west-1"]
        },
        "ArnNotLike": {
          "bedrock:InferenceProfileArn": [
            "arn:aws:bedrock:*:*:inference-profile/us.openai.*",
            "arn:aws:bedrock:*:*:inference-profile/global.openai.*"
          ]
        }
      }
    }
  ]
}
```

有了这个条件，即使某些目的 Region 平时被你的 SCP 拒绝，Amazon Bedrock 仍可路由到配置文件中的这些 Region。所选配置文件里的每一个目的 Region 都必须被允许，请求才会成功。更多细节请见[在多账户环境中设置跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-prereq.html)。

### 核实生效的推理配置文件

调用模型之前，你可以用 AWS CLI 核实源 Region 中哪些配置文件生效。以下命令列出 `ca-central-1` 中生效的 OpenAI 配置文件。要在 Calgary 做同样的检查，把 `ca-central-1` 换成 `ca-west-1`。

```
aws bedrock list-inference-profiles \
    --region ca-central-1 \
    --type-equals SYSTEM_DEFINED \
    --query "inferenceProfileSummaries[?contains(inferenceProfileId, 'openai')].[inferenceProfileId,status]" \
    --output table
```

Amazon Bedrock 控制台提供同样的视图。打开控制台，把 Region 选为 **Canada (Central)** 或 **Canada West (Calgary)**，在 **Inference** 下选择 **Cross-Region inference**，然后查看可用的配置文件。

## 通过 Amazon Bedrock Runtime 调用模型

GPT-5.6、GPT-6 和 GPT-6.1 在 `bedrock-runtime` 端点上支持三条访问路径：OpenAI Responses API、OpenAI Chat Completions API 和 Amazon Bedrock Converse API。OpenAI 兼容 API 通过该端点的 `/openai/v1` 路径调用。端点接受 AWS Signature Version 4 (SigV4) 或 [Amazon Bedrock API key](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html)。

以下示例使用 [Amazon Bedrock token generator for Python](https://github.com/aws/aws-bedrock-token-generator-python) 从你当前的 AWS 凭证创建短期 Amazon Bedrock API key，因此你的应用无需存储静态密钥。

### OpenAI Responses API

对于已经在用 OpenAI SDK 的 Responses API 的应用，把客户端指向区域性的 Amazon Bedrock Runtime 端点，并把推理配置文件 ID 作为 model 传入。

```
from aws_bedrock_token_generator import provide_token
from openai import OpenAI

region = "ca-central-1"  # Use "ca-west-1" for Calgary
client = OpenAI(
    base_url=f"https://bedrock-runtime.{region}.amazonaws.com/openai/v1",
    api_key=provide_token(region=region),
)

response = client.responses.create(
    model="global.openai.gpt-6-astra",
    input="What are the key considerations for AI governance in Canadian financial services?",
    max_output_tokens=1024,
)
print(response.output_text)
```

要输出流式结果，设置 `stream=True`，遍历响应事件，边到边打印文本：

```
stream = client.responses.create(
    model="global.openai.gpt-6-luna",
    input="List five generative AI use cases for Canadian healthcare.",
    max_output_tokens=512,
    stream=True,
)
for event in stream:
    if event.type == "response.output_text.delta":
        print(event.delta, end="", flush=True)
```

### OpenAI Chat Completions API

OpenAI Chat Completions 格式通过同一个端点工作。

```
response = client.chat.completions.create(
    model="global.openai.gpt-5.6-terra",
    messages=[{"role": "user", "content": "Summarize recent AI regulatory trends in Canada."}],
    max_completion_tokens=1024,
    reasoning_effort="low",
)
print(response.choices[0].message.content)
```

受支持参数的完整列表（包括推理强度等级）请见 Amazon Bedrock 用户指南中的[模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-openai.html)。

### Amazon Bedrock Converse API

当你的应用通过 AWS SDK 调用 Amazon Bedrock 时，使用 Converse API。Boto3 通过标准的 AWS 凭证链解析凭证。

```
import boto3

bedrock = boto3.client("bedrock-runtime", region_name="ca-central-1")
response = bedrock.converse(
    modelId="us.openai.gpt-5.6-terra",
    messages=[{"role": "user", "content": [{"text": "Summarize recent AI regulatory trends in Canada."}]}],
    inferenceConfig={"maxTokens": 1024},
)
# GPT-5.6 and GPT-6 may return a reasoningContent block alongside the text.
# Select the block that contains the text output.
text_output = next(block["text"] for block in response["output"]["message"]["content"] if "text" in block)
print(text_output)
```

同样的调用对 GPT-6 Sol、GPT-6 Luna 和 GPT-6.1 Sol 也适用，只需改推理配置文件 ID。以下示例对 GPT-6 Sol 使用 US geographic 配置文件，对 GPT-6 Luna 使用 global 配置文件。两者都已从 `ca-central-1` 验证过。

```
# GPT-6 Sol, GPT-6 Luna, and GPT-6.1 Sol are called the same way. Swap the inference profile ID, and choose a us. (US geographic) or global. profile to match your data boundary.
# For example, GPT-6.1 Sol via the US geographic profile: modelId="us.openai.gpt-6.1-sol"
# GPT-6 Sol via the US geographic profile: strong reasoning and coding for complex work.
response = bedrock.converse(
    modelId="us.openai.gpt-6-sol",
    messages=[{"role": "user", "content": [{"text": "Summarize recent AI regulatory trends in Canada."}]}],
    inferenceConfig={"maxTokens": 512},
)

# GPT-6 Luna via the global profile: fast, low-cost inference for high-volume tasks such as classification.
response = bedrock.converse(
    modelId="global.openai.gpt-6-luna",
    messages=[{"role": "user", "content": [{"text": "Classify this ticket as BILLING, TECHNICAL, or OTHER: ..."}]}],
    inferenceConfig={"maxTokens": 256},
)
```

### 工具使用

这些模型支持[客户端工具使用（函数调用）](https://docs.aws.amazon.com/bedrock/latest/userguide/tool-use-client-side.html)。在 `tools` 参数中定义工具，模型会返回一个结构化的工具调用请求，交由你的应用执行。

```
response = client.responses.create(
    model="global.openai.gpt-6-astra",
    input="What's the current exchange rate from CAD to USD?",
    tools=[{
        "type": "function",
        "name": "get_exchange_rate",
        "parameters": {
            "type": "object",
            "properties": {
                "from_currency": {"type": "string"},
                "to_currency": {"type": "string"}
            }
        }
    }],
)

# The model returns a tool-call request rather than text.
for item in response.output:
    if item.type == "function_call":
        print(f"Tool: {item.name}, Args: {item.arguments}")
```

## 提示词缓存

GPT-5.6、GPT-6 和 GPT-6.1 在 Amazon Bedrock 上支持提示词缓存，以降低重复提示词前缀的成本与延迟。隐式缓存不需要改代码：Amazon Bedrock 会自动缓存 1,024 token 及以上的合格前缀。后续请求中读取的缓存 token 按折扣价计费，并且不计入你的每分钟 token 配额。缓存 token 会出现在响应的 usage 对象和 Amazon CloudWatch 指标中，便于你跟踪用量。缓存写入的定价、最小前缀长度以及对显式缓存断点的支持，请见[提示词缓存文档](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)和各[模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-openai.html)。

## 配额管理

`bedrock-runtime` 端点上的跨区域推理配额按每个模型的每分钟 token 数（TPM）计量。每个配额把输入和输出 token 合并计入同一个上限。US geographic 和 global 推理配置文件有各自独立的配额分配，所以在两者之间切换会改变你取用的池子。

token 消耗合并计算输入 token、缓存写入的输入 token 和输出 token。输出 token 会乘以模型的消耗速率，所以输出密集的工作负载消耗配额的速度比原始 token 数看上去更快。生产上线之前，请尽早申请配额提升并监控配额利用率。请用有代表性的提示词、输出长度、流式行为、并发和峰值流量做测试。

要申请配额提升，请按以下步骤操作：

- 在 `ca-central-1` 或 `ca-west-1` 打开 [Service Quotas 控制台](https://console.aws.amazon.com/servicequotas/)。
- 选择 **Amazon Bedrock**，然后为你需要的模型选择名为“Cross-Region InvokeModel tokens per minute”的配额。
- 选择 **Request increase at account level**，输入目标值并提交请求。

token 用量与成本如何跟踪，请见[在 Amazon Bedrock 中跟踪用量与成本](https://docs.aws.amazon.com/bedrock/latest/userguide/cost-management.html)。

## 可观测性

由于这些模型通过 Amazon Bedrock Runtime API 运行，经推理配置文件发出的请求在你的可观测性工具中与按需请求表现一致。调用日志和 Amazon CloudWatch 指标都记录在你的源 Region，无论请求在哪里处理。你的可观测性数据始终集中在一处。

- **AWS CloudTrail** 记录每一次请求，并在 `additionalEventData.inferenceRegion` 字段中记录是哪个目的 Region 处理了它。例如：  `"additionalEventData": { "inferenceProfileArn": "arn:aws:bedrock:ca-central-1:111122223333:inference-profile/global.openai.gpt-6-astra", "inferenceRegion": "us-west-2" }`
- **Amazon CloudWatch 指标**按推理配置文件发布，覆盖调用次数、token 数、延迟、限流和错误。
- **模型调用日志**把完整的请求和响应载荷投递到 Amazon Simple Storage Service (Amazon S3) 或 Amazon CloudWatch Logs。要在 Amazon Bedrock 控制台中启用，选择 **Settings**，再选择 **Model invocation logging**。你也可以调用 `PutModelInvocationLoggingConfiguration` API。该功能默认关闭。
- **AWS Data Exports** 按模型和配置文件分项列出支出。

### Amazon CloudWatch Coding Agent Insights

如果你用这些模型驱动 OpenAI Codex 之类的 AI 编码助手，[Amazon CloudWatch Coding Agent Insights](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/coding-agents-insights.html) 提供了一个专用仪表板。它呈现 token 用量、API 请求次数、活跃用户，以及按部门、团队、环境等维度切分的成本归属。要启用它，请配置你的编码助手把遥测导出到 Amazon CloudWatch。设置步骤请见[为 OpenAI Codex 设置 OpenTelemetry](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/coding-agents-codex.html)。

## 清理

为避免测试后继续产生费用，请移除你创建的资源：

- 关闭模型调用日志。在 Amazon Bedrock 控制台中选择 **Settings**，再选择 **Model invocation logging**，或者调用 `DeleteModelInvocationLoggingConfiguration`。这会停止向 Amazon S3 和 Amazon CloudWatch Logs 投递日志。
- 删除或解绑你为测试创建的 IAM 策略和任何 Amazon Bedrock API key。

推理配置文件本身是系统定义的，不使用时不会产生费用。

## 安全与合规

跨区域推理在设计上保护传输中和静态的数据。请求经由以 TLS 1.2+ 加密的 AWS 私有骨干网传输，而不是公共互联网。对加拿大客户，静态数据默认留在你的源 Region，包括调用日志、知识库和配置。只有瞬时的推理计算发生在目的 Region，且默认情况下模型提供方无法访问你的提示词或补全结果。

有一点是 OpenAI 模型特有的。被自动化滥用分类器标记的内容可能会在目的 Region 保留最多 30 天以供审查。如果你想把处理限制在北美（加拿大和美国），可以选择 US geographic 配置文件。我们建议与你的合规团队一起审阅 [Amazon Bedrock 滥用检测](https://docs.aws.amazon.com/bedrock/latest/userguide/abuse-detection.html)。

要更详细地了解加拿大的数据驻留模式，请见 [Cross-Region Inference and Canadian Data Residency: A Technical Architecture Guide](https://builder.aws.com/content/3EuyyJgS9hWozGI9oUJIU6nCfMk/cross-region-inference-and-canadian-data-residency-a-technical-architecture-guide)。
