# 使用 AWS PrivateLink 保护企业网络对 Quick 的访问

当企业数据位于公司防火墙之后，或存放在私有的本地数据中心内时，即使 Amazon Quick 中的 AI agent 和仪表板可以查询几乎任何数据源，也不存在一条从 AWS 直达这些数据的网络路径。管理员必须确保敏感的企业数据不会暴露到公网，同时又能被 AI 驱动的洞察与操作所访问。

对许多企业而言，通过公网路由流量会带来不可接受的风险。HIPAA、FedRAMP、PCI-DSS 等监管框架往往要求敏感数据留在受控的网络边界之内。即便合规不是主要驱动力，暴露内部数据路径也会扩大攻击面、让审计跟踪更复杂，并引入可变延迟，从而降低用户体验。

本演练展示如何以私有方式把本地数据源连接到 Amazon Quick，而不让流量穿越公网。它假定你已经有一条 AWS Direct Connect 或 AWS Site-to-Site VPN，将本地环境与你的虚拟私有云（VPC）连通。在这个基础上，我们配置由 AWS PrivateLink 提供支持的 VPC 终端节点，让 Quick 可以经由 AWS 骨干网访问你的私有资源，然后再叠加安全组与 VPC 终端节点策略，实现纵深防御。

最终你将得到一套网络架构：Quick 与本地数据源之间的流量不经过公网，攻击面缩小，连接稳定且低延迟，并且你能获得清晰的审计跟踪以支撑合规。

## Amazon Quick 与私有网络连接的建立

Amazon Quick 是一个 AI 驱动的工作区，把搜索、分析、研究和自动化整合进同一种对话式体验。弄清楚哪些组件会触达你的私有网络、以及以何种方式触达，决定了后续各节中的架构。

Amazon Quick 中的数据访问分为两条路径。**面向用户的流量**涵盖任何人打开 Quick 控制台、与仪表板交互、发起 API 调用或使用 Quick Desktop 所产生的流量。这些流量全部通过 VPC 终端节点路由（参见「面向用户与 API 访问的 VPC 终端节点」），从而使用户会话不经过公网。

**数据获取流量**是指 Quick 自身进入你的网络拉取数据。这部分由 VPC 连接处理（参见「面向数据源访问的 VPC 连接」），也是大部分架构决策所在之处。会发起数据获取连接的功能与集成包括：

- **Amazon Quick Sight** 通过在 VPC 中放置的 ENI 直接查询本地数据库（PostgreSQL、MySQL、SQL Server、Oracle 等）。它是 VPC 连接最大的使用者。
- **Amazon Quick Flows 与 Amazon Quick Automate** 是两个独立的自动化功能。Flows 处理可重复的任务，Automate 处理带 human-in-the-loop 的复杂多系统编排。两者都会调用操作连接器，其中也包括以私有方式托管在你的 VPC 中的 MCP server。任何调用内部 API 的工作流都走这条路径。
- **Quick Agents** 支撑所有对话式交互，并可以直接调用操作连接器。当自定义 agent 调用私有托管的 MCP server 或内部 API 时，流量经 VPC 连接流动。
- **Amazon Quick Index** 在 Confluence、SharePoint、Amazon Simple Storage Service（Amazon S3）等已连接的源之上构建统一的搜索层。对于位于你的 VPC 内或本地的数据，知识库 VPC 连接目前只支持 Amazon Redshift。Confluence、SharePoint、Box、Google Drive、OneDrive、Amazon S3 等源目前都无法使用 Quick VPC 连接（参见[受支持的 VPC 数据源](https://docs.aws.amazon.com/quick/latest/userguide/vpc-connection-supported-data-sources.html)）。你仍然可以通过存储桶策略把 Amazon S3 存储桶的访问限制到某个 VPC 终端节点，但那是另一套机制。
- **Amazon Quick Research** 为生成带引用的报告，会同时访问防火墙后的企业源与公网数据，在访问私有源时使用 VPC 连接。
- **Apps in Quick** 在结构化数据和操作连接器之上构建交互式 Web 应用，继承与 Quick Sight、Flows 相同的 VPC 连通性。
- **Quick Spaces** 用于组织上述各项功能中的内容，但自身不发起数据连接。

这两条流量路径需要两套不同、但相互配合的私有连接机制：

- **VPC 终端节点（AWS PrivateLink）：**处理面向用户的流量，例如访问 Quick 网站、发起 API 调用和管理性访问。它们使用户流量不经过公网。
- **VPC 连接：**处理数据源流量。Amazon Quick 进入你的 VPC（进而进入你的本地网络），从数据库、Amazon Redshift 知识库源和内部 API 获取数据。这些在 Quick 控制台中配置。

## 配置私有连接

本节按顺序介绍四个构建块：面向用户与 API 访问的 VPC 终端节点、面向数据源访问的 VPC 连接、面向 AWS 数据服务的 VPC 终端节点，以及到所需外部域的出站访问。

### 先决条件

在为 Quick 配置私有连接之前，请确保以下事项已就绪：

- 一个有效的 AWS 账户，并带有 Amazon Quick Enterprise 订阅（VPC 连接需要 Enterprise 版）。
- 在部署 Quick 的 AWS Region 中已有 VPC。
- 受支持的 AWS Region。Quick 网站 VPC 终端节点在 AWS 中国区域和 AWS GovCloud（US）区域不可用。
- 在本地网络与 VPC 之间已建立 AWS Direct Connect 连接或 Site-to-Site VPN。这是把流量从数据中心带入 AWS 的私有路径。
- 具备创建和管理 VPC 终端节点、安全组以及执行 Quick 管理所需的 AWS Identity and Access Management（IAM）权限。要创建 VPC 连接，管理员的 IAM 身份还需要 `quicksight:CreateVPCConnection`、`quicksight:DescribeVPCConnection`、`quicksight:ListVPCConnections`、`quicksight:UpdateVPCConnection`、`quicksight:DeleteVPCConnection`、`ec2:DescribeSubnets`、`ec2:DescribeVpcs`、`ec2:DescribeSecurityGroups`、`iam:ListRoles` 和 `iam:PassRole`，并将范围限定到 VPC 连接执行角色。
- 可以访问组织的 DNS 管理（Route 53 私有托管区域或本地 DNS 转发器），因为私有 DNS 解析会让流量经由 VPC 终端节点而不是公网地址。

### 面向用户与 API 访问的 VPC 终端节点（AWS PrivateLink）

由 PrivateLink 提供支持的 VPC 终端节点负责处理所有面向用户的 Amazon Quick 流量，包括网站、API 调用和嵌入内容。它们让用户无需穿越公网即可访问 Amazon Quick 控制台。

#### 规划 VPC 终端节点架构

规划终端节点架构时，先确定你的 Quick 账户部署在哪个 AWS Region，因为 VPC 终端节点必须位于同一 Region。为终端节点 ENI 的放置选择跨多个可用区的子网，并确保这些子网有经 Direct Connect 或 VPN 通往本地网络的路由。

设计安全组，把终端节点 ENI 上的流量限制到仅必需的端口和源地址范围。如果你希望所有流量都走私有路由（包括 Amazon Quick 对 Amazon S3、Amazon Redshift 和 Amazon Athena 发起的调用），也要为这些服务规划 VPC 终端节点（参见「配置数据源 VPC 终端节点」）。

#### 为 Quick 创建 VPC 终端节点

Quick 需要两个接口 VPC 终端节点才能实现完整的私有访问：

- **网站访问终端节点** – 服务名 `com.amazonaws.<region>.quicksight-website`。它承载流向 Quick 控制台的大部分用户流量。Quick 网站的私有 DNS 名称与公开 URL 不同，因此你必须为 `<region>.quicksight.aws.amazon.com` 创建一条指向该 VPC 终端节点的 A 记录。
- **API 访问终端节点** – 服务名 `com.amazonaws.<region>.quicksight`。它处理编程方式的 API 调用。启用私有 DNS 后，对 `quicksight.<region>.amazonaws.com` 的现有 API 调用会自动经 VPC 终端节点路由，无需额外的 DNS 配置。如需满足 FIPS 合规，请使用 `com.amazonaws.<region>.quicksight-fips`。

> 注意：并非每个 Quick API 都能通过 API VPC 终端节点访问。以下 13 个 API 不受支持：操作连接器 API（CreateActionConnector、DeleteActionConnector、DescribeActionConnector、DescribeActionConnectorPermissions、ListActionConnectors、SearchActionConnectors、UpdateActionConnector、UpdateActionConnectorPermissions）与 flow API（GetFlowMetadata、GetFlowPermissions、ListFlows、SearchFlows、UpdateFlowPermissions）。以编程方式管理操作连接器或 flow 的自动化需要一条通往公共 API 终端节点的路径。参见「Quick 与接口 VPC 终端节点」。

如果管理员通过 VPC 以 IAM 用户身份登录 Amazon Quick，还需要创建 AWS Management Console 终端节点：

- `com.amazonaws.<region>.console`。
- `com.amazonaws.<region>.signin`。

#### 配置 DNS 解析

对于网站终端节点，为 `<region>.quicksight.aws.amazon.com` 创建一条 A 记录，并指向该 VPC 终端节点的 DNS 名称。这样，当公司网络上的用户解析 Quick URL 时，流量会经由私有终端节点而不是公网路由。对于 API 终端节点，在 VPC 终端节点上启用私有 DNS 就足够了，因为 API 调用会自动解析到该终端节点的私有 IP 地址。

Route 53 私有托管区域只应答来自与其关联的 VPC 内部的查询。由于你的用户是从公司网络连接的，请把本地 DNS 服务器配置成将 `<region>.quicksight.aws.amazon.com` 的查询转发到 VPC 中的 Route 53 Resolver 入站终端节点（或在本地 DNS 中托管一条等效记录）。最后，从公司网络验证 DNS 解析，确认请求解析到 VPC 内的私有 IP 而不是公网地址。

#### 设置 VPC 终端节点策略

VPC 终端节点策略限制哪些账户或组织可以使用该终端节点。对于 Quick，策略可以按 AWS 账户 ID 或组织 ID 限定范围。要修改策略，在 Amazon VPC 控制台中打开该终端节点，选择 **Policy** 选项卡，然后选择 **Edit Policy**（图 8）。

> 重要限制：对于 Quick 网站终端节点，Principal、Action 和 Resource 字段必须全部设为 *。条件只能针对 aws:PrincipalAccount 或 aws:OrgId 属性指定。更严格的操作级策略仅在 API 终端节点上受支持。

**网站终端节点策略示例：**

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": "*",
            "Action": "*",
            "Resource": "*",
            "Condition": {
                "StringEquals": {
                    "aws:PrincipalAccount": ["012345678901"]
                }
            }
        }
    ]
}
```

### 面向数据源访问的 VPC 连接

VPC 终端节点处理面向用户的流量，而 VPC 连接处理服务器侧的路径，即 Amazon Quick 进入你的 VPC 访问数据库、Amazon Redshift 知识库源和内部 API。

#### VPC 连接的工作方式

Amazon Quick Enterprise 版与 Amazon VPC 完全集成。当你在 Amazon Quick 中创建 VPC 连接时，实际上是在你的 VPC 子网中加入了弹性网络接口（ENI）。这些 ENI 让 Quick 能与 VPC 内的资源交换网络流量，进而也能与从该 VPC 可到达的任何对象通信，包括通过 Direct Connect 或 VPN 连接的本地系统。

所有标准 VPC 安全控制都适用于这部分流量。路由表、网络 ACL、子网和安全组对进出 Quick 流量的管控方式，与它们管控 VPC 中任何其他实例之间流量的方式完全一致。这意味着你可以连接到：

- 未暴露到公网的私有数据库。
- 可通过 Direct Connect 或 VPN 到达的本地数据源。
- 可通过网络内 IP 地址访问的内部 API。

为 VPC 连接的 ENI 创建一个专用安全组（例如 `QuickSight-VPC`）。在每个数据源的安全组上，允许来自该安全组 ID 的、指向数据库端口的入站流量。

> 针对 2023 年 4 月 27 日之前创建的 VPC 连接的注意事项：附加到 Quick 网络接口的安全组不是有状态的。你必须添加一条入站规则，显式允许来自数据源安全组的、所有端口（0–65535）上的返回流量，因为返回数据包使用的是随机分配的目标端口。该日期之后创建的连接使用标准的有状态行为。参见「安全组：入站和出站规则」。

#### 创建执行角色

Amazon Quick 不会替你创建 VPC 连接执行角色。在添加连接之前，创建一个专用的 IAM 角色（推荐），或更新一个已经信任 Quick 的现有角色，例如本文截图中所用的 `aws-quicksight-service-role-v0`。该角色需要：

- 一份权限策略，授予 Amazon Elastic Compute Cloud（Amazon EC2）中 Quick 用于管理其 ENI 的操作（图 10）。
- 一份信任策略，允许 `quicksight.amazonaws.com` 承担该角色。只有具备该信任策略的角色才会出现在 Quick 控制台的 **Execution role** 列表中。

**权限策略：**

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "ec2:CreateNetworkInterface",
                "ec2:DeleteNetworkInterface",
                "ec2:ModifyNetworkInterfaceAttribute",
                "ec2:DescribeSubnets",
                "ec2:DescribeSecurityGroups"
            ],
            "Resource": "*"
        }
    ]
}
```

![IAM 控制台为 VPC 连接执行角色添加 Amazon EC2 网络接口权限](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/19/ML-20213-10-1.jpg)

**信任策略：**

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": { "Service": "quicksight.amazonaws.com" },
            "Action": "sts:AssumeRole"

```

### 配置数据源 VPC 终端节点

VPC 终端节点（PrivateLink，此处用于 AWS 服务 API）与 VPC 连接（放置在 VPC 中的 Quick ENI，参见「面向数据源访问的 VPC 连接」）是两套不同的机制。Quick 在为仪表板和分析检索数据时会访问其他 AWS 服务（Amazon S3、Amazon Redshift、Amazon Athena、AWS Secrets Manager）。如果你希望所有流量都保持私有，包括 Amazon Quick 对这些 AWS 服务的调用，请为每一项创建接口 VPC 终端节点或网关 VPC 终端节点：

| **服务** | **终端节点类型** | **服务名** |
| --- | --- | --- |
| Amazon S3 | 网关 | `com.amazonaws.<region>.s3` |
| Amazon Redshift | 接口 | `com.amazonaws.<region>.redshift` |
| Amazon Athena* | 接口 | `com.amazonaws.<region>.athena` |
| AWS Secrets Manager | 接口 | `com.amazonaws.<region>.secretsmanager` |
| AWS Glue | 接口 | `com.amazonaws.<region>.glue` |

** Athena 不支持作为 VPC 连接的数据源。Athena 终端节点仅在 AWS PrivateLink 上承载 Athena API 流量。*

请在放置 Amazon Quick ENI 的同一个 VPC 中创建这些终端节点。确保路由表和安全组允许 Amazon Quick 子网与终端节点子网之间的流量。

### 启用对所需外部域的访问

虽然 Quick 与本地源之间的数据流量留在私有网络上，但用户的浏览器仍需要访问一组域，以完成登录、加载静态资源、上报客户端指标以及使用集成。即使配置了 VPC 终端节点，不支持 VPC 终端节点的域仍然需要出站连通性，通常要通过公司代理或防火墙。如果你的账户使用 IAM Identity Center，浏览器登录还需要访问公共的 AWS 登录终端节点和 IAM Identity Center 终端节点（参见「安全的用户访问与身份联合」）。

**所需的外部域**

| **域** | **用途** | **VPC 终端节点支持** |
| --- | --- | --- |
| `<region>.quicksight.aws.amazon.com` | Quick 网站的大部分流量 | 是 |
| `quicksight.<region>.amazonaws.com` | Quick 公共 API 调用 | 是 |
| `signin.aws.amazon.com` | 使用 IAM 身份的账户登录 AWS 控制台 | 是 |
| `<region>.signin.aws` | 登录 | 否 |
| `*.cloudfront.net` | 静态资源（CSS、JavaScript） | 否 |
| `*.s3.<region>.amazonaws.com` | 报告与缩略图 | 是 |
| `*.execute-api.<region>.amazonaws.com` | 客户端指标 | 否 |
| `*.kinesisvideo.amazonaws.com` | 自动化工作流的实时流 | 否 |
| `apis.google.com/js/api.js` | Google Drive 文件选择器 | 不适用 |
| `*.officeapps.live.com` | Quick 侧边面板扩展 | 不适用 |
| `outlook.cloud.microsoft` | Quick 侧边面板扩展 | 不适用 |
| `*.sharepoint.com` | Quick 侧边面板扩展 | 不适用 |
| `*.office.com` | Quick 侧边面板扩展 | 不适用 |
| `*.office365.com` | Quick 侧边面板扩展 | 不适用 |

*来源：*[Quick 访问的域](https://docs.aws.amazon.com/quicksight/latest/developerguide/vpc-interface-endpoints.html)*。*

**配置指导：**

- 对于支持 VPC 终端节点的域（Quick 网站与 API、`signin.aws.amazon.com` 以及 Amazon S3），创建相应的 VPC 终端节点和 DNS 记录。
- 对于不支持 VPC 终端节点的域，让它们经公司的互联网出口（出站代理或防火墙）通过。如果用户流量经你的 VPC 出站，请在公有子网中使用 NAT gateway。
- 如果你的安全态势要求 URL 级过滤，请使用出站代理或 AWS Network Firewall 的域过滤规则，仅允许前面列出的域。
- 从公司工作站（或处于同一出口路径的实例）进行测试：对每个域执行 `nslookup` 和 `curl`，以确认 DNS 解析与路由。

## 强制实施 VPC 终端节点限制

终端节点配置并测试完成后，你可以强制要求对 Quick 账户的所有访问都必须经由 VPC 终端节点，从而完全阻断一般的互联网访问。这样一来，用户只能通过你已经建立的私有路径、从公司网络访问 Quick。

Quick 提供 IP 与 VPC 终端节点限制控制，可将账户访问限制在预定义的 IP 地址范围、VPC ID 或 VPC 终端节点 ID 列表之内。例如，你可以创建一条只允许来自用于 Direct Connect 的那个 VPC 终端节点的访问规则，这意味着任何试图从公网访问 Quick 的人都会被拒绝。

通过 Quick 控制台进行配置（只有使用 IAM 凭证登录的管理员才能访问限制页面）：

- 点击个人资料图标，然后选择 **Manage account**。在 **Security** 下选择 **Manage IP/VPC restrictions**。
- 在 **Restriction** 字段中输入 VPC 终端节点 ID（例如 `vpce-001122def`），输入 **Description**，然后选择 **Add**（图 14）。
- 选择 **Save changes** 应用该规则。
- 打开 **Enforce restrictions**。

![Amazon Quick 的 IP 与 VPC 终端节点限制页面，正在添加一条 VPC 终端节点规则](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/19/ML-20213-14-1.jpg)

图 14：在 IP 与 VPC 终端节点限制页面上添加 VPC 终端节点规则

或者通过 AWS Command Line Interface（AWS CLI）配置：

```
aws quicksight update-ip-restriction \
--aws-account-id ACCOUNT_ID \
--region REGION \
--enabled \
--vpc-endpoint-id-restriction-rule-map \
vpce-001122def=CorporateVpcEndpoint
```

> 注意：UpdateIpRestriction 会替换整个规则映射。请先用 aws quicksight describe-ip-restriction 获取当前规则，并在更新时包含所有现有规则。

**关键注意事项：**

- IP 与 VPC 终端节点规则适用于 Quick 的 Web、嵌入和移动访问，也就是说它们并不限制对公共 API 的访问。要限制来自特定源的 API 调用，请使用带 `aws:SourceIp` 或 `aws:SourceVpce` 条件的 IAM 策略。
- 在启用限制之前，确保你自己的 IP 或 VPC 终端节点已包含在规则中，否则你会把自己锁在外面。
- 规则最多可能需要 10 分钟才能完全生效。
- 你可以组合使用 IP 规则与 VPC 终端节点规则，只要流量满足任一类型的规则就允许通过。IP 规则与 VPC 终端节点规则合计最多可添加 100 条。
- IP 与 VPC 终端节点规则会在你账户的所有 AWS Region 中强制执行，但你只能在创建 Quick 账户的那个 AWS Region 中添加或管理它们。
- 如果你有公开嵌入的仪表板，启用限制后它们将只能通过 VPC 终端节点访问。

在强制实施限制之后，只有经由指定 VPC 终端节点（或允许的 IP 地址范围）到达的流量才能访问你的 Quick 账户，其余所有访问都会被拒绝。

## 安全的用户访问与身份联合

私有网络连接让流量不经过公网，但它并没有回答「谁能访问 Quick 中的哪些内容」这个问题。本节介绍如何集成企业身份提供商、控制用户供给，并在 Quick 的各个组件之间实施细粒度的访问分段。

### 与 AWS IAM Identity Center 集成

> 重要提示：对于与 IAM Identity Center 集成的 Quick 账户，基于浏览器的身份验证需要访问公共的 AWS 登录终端节点和 IAM Identity Center 终端节点。VPC 终端节点不提供这条浏览器登录路径。此过程不需要公网 IP 地址。请通过 NAT gateway 或代理提供出站连通性。参见 IAM Identity Center 用户指南中的「私有访问注意事项」。

Amazon Quick 使用 AWS IAM Identity Center 作为员工身份管理的中心点。IAM Identity Center 通过 SAML 2.0 进行身份验证、通过 SCIM 2.0 进行自动的用户与组供给，与你现有的企业身份提供商（IdP）对接。这带来：

- 从你的 IdP 同步的自动用户供给与取消供给。
- 组成员关系同步——当用户被加入或移出某个组时，这一变更会传播到 Quick。
- 使用现有企业凭证的单点登录（SSO）。
- 通过承担的 IAM 角色获取临时凭证——没有长期存在的 Quick 专用密码。

关于如何结合身份提供商设置 IAM Identity Center 的分步指南，参见 [IAM Identity Center 入门](https://docs.aws.amazon.com/singlesignon/latest/userguide/getting-started.html)。

### Quick 中基于角色的访问

Quick 支持三种基础角色，它们决定用户能做什么：

- **Admin** – 完整的管理访问权限，包括数据源配置、VPC 连接、安全设置、用户管理和 SPICE 容量购买。
- **Author** – 可以创建和发布仪表板、构建 agent、配置 Spaces、管理数据源、创建 flow 以及构建应用。
- **Reader** – 可以查看已发布的仪表板、与 agent 交互、使用已被授予访问权限的 Spaces，并阅读 Quick Research 报告。

这些角色会映射到联合用户在登录时所承担的 IAM 角色。通过在 IdP 中管理角色分配，你可以让「谁拥有哪一级访问权限」保持单一事实来源。

此外，Quick 还支持自定义权限配置文件，可以在账户级、角色级或用户级覆盖默认的角色权限。用户级权限覆盖角色级权限，角色级权限又覆盖账户级权限。这让管理员在三种基础角色之外获得更细粒度的控制。

### 使用 Spaces 做用户分段

Quick Spaces 在角色之外提供了又一层访问分段。每个 Space 都可以配置特定的用户和组权限，这意味着：

- 一个包含敏感收入仪表板和财务知识库的财务团队 Space 只对财务组开放。
- 一个包含连接 CRM 的 agent 和销售管道仪表板的销售团队 Space 只对销售人员开放。
- 跨职能的 Space 可以在多个组之间以恰当的权限共享。

Space 级访问由从你的身份提供商同步而来的组控制，因此把新的团队成员加入相应的组，就会自动授予其相关 Spaces 的访问权限。

### Quick Sight 中的行级安全

对于由结构化数据支撑的仪表板，Quick Sight 支持行级安全（RLS），用于限制每个用户或组能看到哪些数据行。RLS 通过数据集规则配置，也就是一个权限数据集，把用户或组映射到他们可以访问的字段值。

例如，一个区域销售仪表板可以配置成：

- EMEA 销售组只能看到 `region = 'EMEA'` 的行。
- NA 销售组只能看到 `region = 'NA'` 的行。
- 销售副总裁可以看到所有行。

RLS 规则依据 IAM Identity Center 确定的用户身份进行评估，这意味着控制登录的同一套身份联合也管着数据级访问。这一点同样适用于传统仪表板视图和 AI 驱动的自然语言查询。同一套安全策略也限制了 AI 在生成答案时可以引用哪些数据。

### 列级安全

除了行级限制之外，Quick Sight 还支持列级安全（CLS），用于对特定用户或组隐藏敏感列。例如，一个包含员工信息的数据集可以把 salary 和 SSN 两列限制为仅 HR 组可见，而其他组仍然可以访问同一数据集中的非敏感列。

### 身份如何与私有连接配合

身份层与网络层协同工作：

- 公司网络上的用户经你的 IdP → IAM Identity Center → Quick 完成身份验证。
- 其请求经 VPC 终端节点（私有网络路径，参见「面向用户与 API 访问的 VPC 终端节点」）到达 Quick。
- Quick 评估其身份，以确定角色、Space 访问权限以及 RLS/CLS 策略。
- 当 Quick 从本地源获取数据时，它使用 VPC 连接（你 VPC 中的 ENI，参见「面向数据源访问的 VPC 连接」）经 Direct Connect 访问数据库。
- 响应经同一条私有路径返回给用户。

除「启用对所需外部域的访问」一节所述的登录流量和静态资源流量之外，没有任何流量穿越公网，并且在每一个环节，用户身份都决定了他们能看到什么、能做什么。

为了持续获得可见性，请在所有终端节点 ENI 和 VPC 连接 ENI 上启用 VPC Flow Logs，以捕获流量元数据。监控 VPC 终端节点上的 CloudWatch 指标（`ActiveConnections`、`BytesProcessed`、`PacketsDropped`），并为连接失败或异常流量来源设置告警。这些日志同时也可作为你在合规文档中引用的审计跟踪。

## 排查常见问题

| **症状** | **可能原因** | **解决办法** |
| --- | --- | --- |
| 无法从公司网络访问 Quick 网站 | DNS 未解析到 VPC 终端节点 | 确认 `<region>.quicksight.aws.amazon.com` 的 A 记录指向该终端节点的 DNS 名称，并确认本地 DNS 把该名称转发到 Route 53 Resolver 入站终端节点。检查终端节点上的私有 DNS 设置。 |
| 启用限制后把自己锁在外面 | 你的 IP/终端节点不在允许列表中 | 使用具备 API 访问权限的 IAM 身份执行 `update-ip-restriction` CLI 命令（该 API 不受 IP/VPC 规则限制）来添加你的终端节点。 |
| API 调用超时 | 安全组阻断了流量 | 确认终端节点安全组允许来自公司 CIDR 的入站 HTTPS（端口 443）。 |
| 数据源连接失败 | VPC 连接 ENI 无法到达目标 | 确认 VPC 连接 ENI 上的安全组允许向数据库端口出站，且数据库安全组允许来自 Quick 安全组的入站。对于 2023 年 4 月 27 日之前创建的连接，验证那条「所有端口」的入站返回流量规则。检查路由表中是否存在通往本地网络的路径。 |
| 静态资源加载不出来（白屏） | 外部域被阻断 | 确认你的代理或 NAT gateway 允许 `*.cloudfront.net`，并且 `*.s3.<region>.amazonaws.com` 可经由 S3 VPC 终端节点或你的代理访问。 |
| SSO 登录失败 | 登录域不可达 | 在防火墙/代理上放行 `signin.aws.amazon.com` 和 `<region>.signin.aws`。对于 IAM Identity Center 账户，还要放行公共的 AWS 登录终端节点和 IAM Identity Center 终端节点（参见「安全的用户访问与身份联合」）。 |
| VPC 连接状态显示 UNAVAILABLE | 执行角色配置有误 | 确认执行角色具备 `ec2:CreateNetworkInterface`、`ec2:DescribeSubnets`、`ec2:DescribeSecurityGroups`、`ec2:ModifyNetworkInterfaceAttribute` 和 `ec2:DeleteNetworkInterface`，并且其信任策略允许 `quicksight.amazonaws.com`。 |
| 公开嵌入的仪表板无法访问 | VPC 终端节点限制阻止了公网流量 | 属于已知行为：启用限制后，公开嵌入也需要经 VPC 终端节点访问。可考虑为公开受众单独配置一个终端节点，或禁用公开嵌入。 |

## 安全最佳实践

仅靠网络隔离或仅靠身份控制都不够。本架构同时依赖两者：网络控制阻断未授权的访问路径，身份控制阻断已授权会话内的未授权数据访问。下列实践用于同时维护这两层。

- **最小权限的终端节点策略：**通过 `aws:PrincipalAccount` 或 `aws:OrgId` 限制网站终端节点。在 API 终端节点上，把策略范围限定到自动化实际需要的具体操作，而不是放行所有 `quicksight:*` 操作。
- **分层安全组：**同时为 VPC 终端节点 ENI（用户流量）和 VPC 连接 ENI（数据流量）应用安全组。在终端节点 ENI 上，把入站 HTTPS 限制到你公司的 CIDR 范围。在 VPC 连接 ENI 上，使用专用安全组，把出站限制到 Quick 仅需的数据库端口和目的地，并在每个数据源的入站规则中引用该安全组。
- **在所有终端节点 ENI 上启用 VPC Flow Logs：**这些日志捕获流量元数据，可用于安全监控、异常检测和合规审计。它们还提供监管框架对受控网络边界所要求的审计跟踪。
- **定期审计终端节点策略：**每季度复查一次终端节点策略。使用 AWS Config 规则检测与你基准配置的偏移。
- **按敏感度隔离 VPC 连接：**如果你有多个数据环境（开发、预发、生产），请创建各自独立的 VPC 连接并配以不同的安全组，以防跨环境访问。
- **使用 CloudWatch 监控：**为 `PacketsDropped` 和 `ActiveConnections` 指标设置告警。异常模式可能意味着配置错误或有人尝试未授权访问。

### 示例需求与 AWS 配置

以下示例展示了本文中的配置如何满足常见的安全网络需求。请与你的安全团队一起，对照你们自己的需求进行评估。

| **需求** | **可支持你评估的 AWS 控制项** |
| --- | --- |
| 敏感数据不得穿越公网 | 用于用户流量的 VPC 终端节点、用于数据流量的 VPC 连接，以及用于网络可见性的 VPC Flow Logs |
| 用户数据隔离 | VPC 连接 ENI 上的安全组，以及面向敏感数据访问的行级安全 |
| 访问仅限于已授权的终端节点 | VPC 终端节点限制（第 4 节）、CloudTrail API 日志和 VPC Flow Logs |

## 成本考量

| **组件** | **成本模型** | **估算** |
| --- | --- | --- |
| VPC 接口终端节点 | 每个可用区 $0.01/小时 + 每 GB 处理数据 $0.01 | 每个可用区内每个终端节点约 $7.20/月（固定）+ 数据传输 |
| VPC 网关终端节点（S3） | 不收费 | 不收费 |
| VPC 连接（Quick ENI） | 随 Quick Enterprise 提供 | 无额外费用 |
| NAT gateway（用于外部域） | $0.045/小时 + 每 GB 处理数据 $0.045 | 约 $32/月（固定）+ 数据传输 |
| VPC Flow Logs | 按 CloudWatch Logs 摄取费率 | 随流量规模变化 |
| Direct Connect | 端口小时费 + 数据传输 | 随线路规格变化 |

**成本优化建议：**

- 尽可能使用 S3 的网关终端节点（不额外收费）而不是接口终端节点。
- 合并终端节点 ENI：每个终端节点只需要在 Amazon Quick VPC 连接子网所在的可用区中放置 ENI。
- 有选择地在终端节点 ENI 上启用 VPC Flow Logs，而不是在整个 VPC 上启用。
- 评估是否所有外部域都需要 NAT gateway 访问，或者对你们的流量模式来说，使用有针对性的代理是否更具成本效益。

## 结论

这套架构建立了四项互补的控制：VPC 终端节点让用户流量保持私有，VPC 连接为 Quick 提供通往数据源的私有路径，身份联合决定谁能访问什么，VPC 终端节点限制则让私有路径成为强制要求。每一层都可以独立审计，并对应到具体的合规要求（参见「合规映射」）。

把这些就位之后，Quick Agents 可以查询你的本地数据库，Quick Research 可以研究防火墙后的企业源，Quick Sight 仪表板可以可视化敏感数据，Quick Flows 可以编排内部系统，而你的数据全程都不穿越公网。AI 能力没有变化，暴露面被消除了。

要实施这套方案，请先做面向用户与 API 访问的 VPC 终端节点，并在推进到面向数据源访问的 VPC 连接之前先验证用户访问。只有确认所有访问模式都能经私有路径正常工作之后，再启用 VPC 终端节点限制。关于身份联合的设置和高级 RLS/CLS 配置，请参考 [IAM Identity Center 文档](https://docs.aws.amazon.com/singlesignon/latest/userguide/getting-started.html)。
