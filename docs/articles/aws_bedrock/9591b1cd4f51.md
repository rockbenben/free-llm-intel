## [人工智能](https://aws.amazon.com/blogs/machine-learning/)

# 使用 AWS PrivateLink 确保从企业网络的快速访问

当企业数据位于公司防火墙后面或私有本地数据中心时，即使 Amazon Quick 中的 AI 代理和仪表板几乎可以查询任何数据源，也没有来自 AWS 的直接网络路径。管理员必须确保其敏感的企业数据不会暴露在公共互联网上，同时可以访问人工智能驱动的见解和操作。

对于许多企业来说，通过公共互联网路由流量会带来不可接受的风险。 HIPAA、FedRAMP 和 PCI-DSS 等监管框架通常要求敏感数据保留在受控网络边界内。即使合规性不是主要驱动因素，暴露内部数据路径也会增加攻击面，使审计跟踪变得复杂，并引入可变延迟，从而降低用户体验。

本演练向您展示如何将本地数据源私下连接到 Amazon Quick，而不需要通过公共互联网进行流量传输。它假设您已经拥有将本地环境链接到 Virtual Private Cloud (VPC) 的 AWS Direct Connect 或 AWS Site-to-Site VPN。在此基础上，我们配置由 AWS PrivateLink 提供支持的 VPC 终端节点，以便 Quick 可以通过 AWS 主干网访问您的私有资源，然后对安全组和 VPC 终端节点策略进行分层以进行深度防御。

最后，您将拥有一个网络架构，使 Quick 与本地数据源之间的流量远离公共互联网，减少攻击面，提供一致的低延迟连接，并为您提供清晰的合规审计跟踪。

## Amazon Quick 并建立专用网络连接

Amazon Quick 是一个由 AI 驱动的工作区，它将搜索、分析、研究和自动化融入单一对话体验中。了解哪些组件到达您的专用网络以及如何到达，可以确定后续部分中的体系结构。

Amazon Quick 中的数据访问分为两种路径。 **面向用户的流量**涵盖打开 Quick 控制台、与仪表板交互、进行 API 调用或使用 Quick Desktop 的任何人。所有这些都通过 VPC 终端节点进行路由（请参阅用于用户和 API 访问的 VPC 终端节点），从而使用户会话远离公共互联网。

**数据获取流量**是指 Quick 本身进入您的网络以获取数据的情况。这是由 VPC 连接处理的（请参阅用于数据源访问的 VPC 连接），并且这是大多数架构决策所在。启动数据获取连接的功能和集成包括：

- **Amazon Quick Sight** 直接通过放置在 VPC 中的 ENI 查询本地数据库（PostgreSQL、MySQL、SQL Server、Oracle 等）。这是 VPC 连接的最大消耗者。
- **Amazon Quick Flows 和 Amazon Quick Automate** 是独立的自动化功能。流程处理可重复的任务。 Automate 通过人机参与来处理复杂的多系统编排。两者都会调用操作连接器，包括在您的 VPC 中私有托管的 MCP 服务器。任何调用内部 API 的工作流都通过此路径路由。
- **快速代理** 支持所有对话交互，并可以直接调用操作连接器。当自定义代理调用私有托管的 MCP 服务器或内部 API 时，流量会流经 VPC 连接。
- **Amazon Quick Index** 跨连接源（例如 Confluence、SharePoint 和 Amazon Simple Storage Service (Amazon S3)）构建统一的搜索层。对于 VPC 内部或本地的数据，目前仅支持 Amazon Redshift 的知识库 VPC 连接。目前，Confluence、SharePoint、Box、Google Drive、OneDrive 和 Amazon S3 等源无法使用 Quick VPC 连接（请参阅[支持的 VPC 数据源](https://docs.aws.amazon.com/quick/latest/userguide/vpc-connection-supported-data-sources.html)）。您仍然可以通过存储桶策略限制 Amazon S3 存储桶对 VPC 终端节点的访问，这是一种单独的机制。
- **Amazon Quick Research** 访问防火墙后面的企业资源以及公共互联网数据以获取其引文支持的报告，在访问私人资源时使用 VPC 连接。
- **Quick 中的应用程序** 在结构化数据和操作连接器之上构建交互式 Web 应用程序，继承与 Quick Sight 和 Flows 相同的 VPC 连接。
- **快速空间** 组织上述功能中的内容，但不启动自己的数据连接。

这两条流量路径需要两种协同工作的不同专用连接机制：

- **VPC 终端节点 (AWS PrivateLink)：** 处理面向用户的流量，例如访问 Quick 网站、进行 API 调用和管理访问。这些措施使用户流量远离公共互联网。
- **VPC 连接：** 处理数据源流量。 Amazon Quick 深入您的 VPC（进而延伸到您的本地网络），从数据库、Amazon Redshift 知识库源和内部 API 获取数据。这些是在快速控制台中配置的。

## 配置专用连接

本部分按顺序介绍四个构建块：用于用户和 API 访问的 VPC 终端节点、用于数据源访问的 VPC 连接、用于 AWS 数据服务的 VPC 终端节点以及对所需外部域的出站访问。

### 先决条件

在为 Quick 配置专用连接之前，请确保满足以下条件：

- 具有 Amazon Quick Enterprise 订阅的有效 AWS 账户（VPC 连接需要企业版）。
- 部署 Quick 的 AWS 区域中的现有 VPC。
- 支持的 AWS 区域。快速网站 VPC 终端节点在 AWS 中国区域或 AWS GovCloud（美国）区域不可用。
- 在您的本地网络和 VPC 之间建立 AWS Direct Connect 连接或站点到站点 VPN。这是将流量从数据中心传输到 AWS 的私有路径。
- 用于创建和管理 VPC 终端节点、安全组和快速管理的 AWS Identity and Access Management (IAM) 权限。要创建 VPC 连接，管理员的 IAM 身份还需要 `quicksight:CreateVPCConnection`、`quicksight:DescribeVPCConnection`、`quicksight:ListVPCConnections`、`quicksight:UpdateVPCConnection`、`quicksight:DeleteVPCConnection`、`ec2:DescribeSubnets`、`ec2:DescribeVpcs`、`ec2:DescribeSecurityGroups`、 `iam:ListRoles` 和 `iam:PassRole` 的作用域为 VPC 连接执行角色。
- 访问组织的 DNS 管理（Route 53 私有托管区域或本地 DNS 转发器），因为私有 DNS 解析通过 VPC 终端节点而不是公共地址路由流量。

### 用于用户和 API 访问的 VPC 终端节点 (AWS PrivateLink)

由 PrivateLink 提供支持的 VPC 终端节点处理所有面向用户的 Amazon Quick 流量，包括网站、API 调用和嵌入内容。它们使用户无需遍历公共互联网即可访问 Amazon Quick 控制台。

#### 规划您的 VPC 终端节点架构

规划终端节点架构时，首先要确定部署您的 Quick 账户的 AWS 区域，因为 VPC 终端节点必须位于同一区域。选择跨多个可用区的子网进行端点 ENI 放置，并确保这些子网具有通过 Direct Connect 或 VPN 到您的本地网络的路由。

设计安全组，将端点 ENI 上的流量限制为仅需要的端口和源范围。如果您希望所有流量私下路由（包括 Amazon Quick 对 Amazon S3、Amazon Redshift 和 Amazon Athena 的调用），请同时规划这些服务的 VPC 终端节点（请参阅配置数据源 VPC 终端节点）。

#### 为 Quick 创建 VPC 终端节点

Quick 需要两个接口 VPC 终端节点才能实现完全私有访问：

- **网站访问端点** – 服务名称 `com.amazonaws.<region>.quicksight-website`。这可以处理快速控制台的大部分用户流量。 Quick 网站的私有 DNS 名称与公共 URL 不同，因此您必须为指向 VPC 终端节点的“<region>.quicksight.aws.amazon.com”创建 A 记录。
- **API 访问端点** – 服务名称 `com.amazonaws.<region>.quicksight`。这处理编程 API 调用。启用私有 DNS 后，对“quicksight.<region>.amazonaws.com”的现有 API 调用会自动通过 VPC 终端节点进行路由，无需额外的 DNS 配置。为了实现 FIPS 合规性，请使用“com.amazonaws.<region>.quicksight-fips”。

> 注意：并非每个 Quick API 都可以通过 API VPC 终端节点使用。不支持以下 13 个 API：操作连接器 API（CreateActionConnector、DeleteActionConnector、DescribeActionConnector、DescribeActionConnectorPermissions、ListActionConnectors、SearchActionConnectors、UpdateActionConnector、UpdateActionConnectorPermissions）和流 API（GetFlowMetadata、GetFlowPermissions、ListFlows、SearchFlows、UpdateFlowPermissions）。以编程方式管理操作连接器或流的自动化需要公共 API 端点的路径。请参阅快速和接口 VPC 终端节点。

如果管理员通过 VPC 以 IAM 用户身份登录 Amazon Quick，还需创建 AWS 管理控制台终端节点：

- `com.amazonaws.<区域>.console`。
- `com.amazonaws.<区域>.signin`。

#### 配置 DNS 解析

对于网站终端节点，为“<region>.quicksight.aws.amazon.com”创建 A 记录并将其指向 VPC 终端节点 DNS 名称。这样，当公司网络上的用户解析快速 URL 时，流量将通过专用端点而不是公共 Internet 进行路由。对于 API 终端节点，在 VPC 终端节点上启用私有 DNS 就足够了，因为 API 调用会自动解析为终端节点的私有 IP 地址。

Route 53 私有托管区域仅应答来自与其关联的 VPC 内部的查询。由于您的用户从公司网络进行连接，因此请配置本地 DNS 服务器以将对“<region>.quicksight.aws.amazon.com”的查询转发到 VPC 中的 Route 53 解析器入站终端节点（或在本地 DNS 中托管等效记录）。最后，验证来自公司网络的 DNS 解析，以确认请求解析为 VPC 内的私有 IP 而不是公共地址。

#### 设置 VPC 终端节点策略

VPC 终端节点策略限制哪些账户或组织可以使用该终端节点。对于 Quick，策略可以按 AWS 账户 ID 或组织 ID 确定范围。要更改策略，请在 Amazon VPC 控制台中打开终端节点，选择 **策略** 选项卡，然后选择 **编辑策略**（图 8）。

> 重要限制：对于 Quick 网站端点，Principal、Action 和 Resource 字段必须全部设置为 *。只能针对 aws:PrincipalAccount 或 aws:OrgId 属性指定条件。仅 API 端点支持更严格的操作级别策略。

**网站端点策略示例：**
```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": "*",
            "Action": "*",
            "Resource": "*",
            "Condition": {
                "StringEquals": {
                    "aws:PrincipalAccount": ["012345678901"]
                }
            }
        }
    ]
}
```

### 用于数据源访问的 VPC 连接

VPC 终端节点处理面向用户的流量，而 VPC 连接则处理服务器端路径，这意味着 Amazon Quick 会进入您的 VPC 来访问数据库、Amazon Redshift 知识库源和内部 API。

#### VPC 连接如何工作

Amazon Quick Enterprise 版与 Amazon VPC 完全集成。当您在 Amazon Quick 中创建 VPC 连接时，您将弹性网络接口 (ENI) 添加到您的 VPC 子网中。这些 ENI 允许 Quick 与 VPC 内的资源交换网络流量，进而与该 VPC 可访问的任何内容交换网络流量，包括通过 Direct Connect 或 VPN 连接的本地系统。

所有标准 VPC 安全控制均适用于该流量。路由表、网络 ACL、子网和安全组管理进出 Quick 的流量，其方式与管理 VPC 中任何其他实例之间的流量相同。这意味着您可以连接到：

- 私有数据库不暴露在公共互联网上。
- 可通过 Direct Connect 或 VPN 访问本地数据源。
- 可通过网络内的 IP 地址访问内部 API。

为 VPC 连接 ENI 创建专用安全组（例如“QuickSight-VPC”）。在每个数据源的安全组上，允许数据库端口上来自该安全组 ID 的入站流量。

> 关于 2023 年 4 月 27 日之前创建的 VPC 连接的注意事项：附加到 Quick 网络接口的安全组没有状态。您必须添加一条入站规则，明确允许所有端口 (0–65535) 上来自数据源安全组的返回流量，因为返回数据包使用随机分配的目标端口。该日期之后创建的连接使用标准有状态行为。请参阅安全组：入站和出站规则。

#### 创建执行角色

Amazon Quick 不会为您创建 VPC 连接执行角色。在添加连接之前，创建一个专用 IAM 角色（推荐），或更新已信任 Quick 的现有角色，例如本文屏幕截图中使用的“aws-quicksight-service-role-v0”。该角色需要：

- 授予 Amazon Elastic Compute Cloud (Amazon EC2) Quick 操作的权限策略，用于管理其 ENI（图 10）。
- 允许“quicksight.amazonaws.com”承担该角色的信任策略。只有具有此信任策略的角色才会出现在快速控制台的**执行角色**列表中。

**权限政策：**
```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "ec2:CreateNetworkInterface",
                "ec2:DeleteNetworkInterface",
                "ec2:ModifyNetworkInterfaceAttribute",
                "ec2:DescribeSubnets",
                "ec2:DescribeSecurityGroups"
            ],
            "Resource": "*"
        }
    ]
}
```
![IAM 控制台将 Amazon EC2 网络接口权限添加到 VPC 连接执行角色](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/19/ML-20213-10-1.jpg)

#### 配置 VPC 连接

### 配置数据源VPC终端节点

VPC 终端节点（PrivateLink，此处用于 AWS 服务 API）和 VPC 连接（放置在 VPC 中的快速 ENI；请参阅用于数据源访问的 VPC 连接）是不同的机制。检索仪表板和分析数据时，快速访问其他 AWS 服务（Amazon S3、Amazon Redshift、Amazon Athena、AWS Secrets Manager）。如果您希望所有流量保持私有，包括 Amazon Quick 对这些 AWS 服务的调用，请为每个流量创建接口或网关 VPC 终端节点：

| **服务** | **端点类型** | **服务名称** |
| --- | --- | --- |
|亚马逊S3 |网关| `com.amazonaws.<区域>.s3` |
|亚马逊红移 |接口 | `com.amazonaws.<区域>.redshift` |
|亚马逊雅典娜* |接口 | `com.amazonaws.<区域>.athena` |
| AWS Secrets Manager | AWS 秘密管理器接口 | `com.amazonaws.<区域>.secretsmanager` |
| AWS胶水|接口 | `com.amazonaws.<区域>.glue` |

** 不支持 Athena 作为 VPC 连接数据源。 Athena 终端节点仅在 AWS PrivateLink 上保留 Athena API 流量。*

在放置 Amazon Quick ENI 的同一 VPC 中创建这些终端节点。确保路由表和安全组允许 Amazon Quick 子网和终端节点子网之间的流量。

### 启用对所需外部域的访问

虽然 Quick 与本地源之间的数据流量保留在专用网络上，但用户的浏览器仍然需要访问一组域才能进行登录、静态资产、客户端指标和集成。即使配置了 VPC 终端节点，不支持 VPC 终端节点的域也需要出站连接，通常是通过公司代理或防火墙。如果您的账户使用 IAM Identity Center，则浏览器登录还需要公共 AWS 登录和 IAM Identity Center 终端节点（请参阅安全用户访问和身份联合）。

**所需的外部域**

| **域名** | **目的** | **VPC 端点支持** |
| --- | --- | --- |
| `<区域>.quicksight.aws.amazon.com` |大量快速网站流量|是的 |
| `quicksight.<区域>.amazonaws.com` |快速公共API调用|是的 |
| `signin.aws.amazon.com` |使用 IAM 身份的账户的 AWS 控制台登录 |是的 |
| `<区域>.signin.aws` |登录 |没有 |

**配置指导：**

- 对于支持 VPC 终端节点的域（Quick 网站和 API、“signin.aws.amazon.com”和 Amazon S3），创建相应的 VPC 终端节点和 DNS 记录。
- 对于没有 VPC 终端节点支持的域，允许它们通过您的公司 Internet 出口（出站代理或防火墙）。如果用户流量通过您的 VPC 传出，请在公有子网中使用 NAT 网关。
- 如果您的安全状况需要 URL 级过滤，请使用出站代理或 AWS 网络防火墙域过滤规则以仅允许前面列出的域。
- 从公司工作站（或同一出口路径中的实例）进行测试：针对每个域的“nslookup”和“curl”确认 DNS 解析和路由。

## 实施 VPC 端点限制

配置和测试终端节点后，您可以强制对 Quick 账户的所有访问都必须通过 VPC 终端节点，从而完全阻止一般互联网访问。因此，用户只能通过您建立的专用路径从您的公司网络访问 Quick。

Quick 提供 IP 和 VPC 终端节点限制控制，将账户访问限制为预定义的 IP 范围、VPC ID 或 VPC 终端节点 ID 列表。例如，您可以创建一条规则，仅允许从用于 Direct Connect 的 VPC 终端节点进行访问，这意味着任何尝试从公共互联网访问 Quick 的人都将被拒绝。

通过快速控制台进行配置（只有使用 IAM 凭证登录的管理员才能访问限制页面）：

- 选择您的个人资料图标，然后选择**管理帐户**。在 **安全性** 下，选择 **管理 IP/VPC 限制**。
- 在 **Restriction** 字段中，输入 VPC 终端节点 ID（例如，`vpce-001122def`），输入 **Description**，然后选择 **Add**（图 14）。
- 选择 **保存更改** 以应用规则。
- 打开**强制限制**。

![添加 VPC 终端节点规则的 Amazon Quick IP 和 VPC 终端节点限制页面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/19/ML-20213-14-1.jpg)

图 14：在 IP 和 VPC 终端节点限制页面上添加 VPC 终端节点规则

或者，通过 AWS 命令行界面 (AWS CLI) 进行配置：
```
aws quicksight update-ip-restriction \
--aws-account-id ACCOUNT_ID \
--region REGION \
--enabled \
--vpc-endpoint-id-restriction-rule-map \
vpce-001122def=CorporateVpcEndpoint
```
> 注意：UpdateIpRestriction 替换整个规则映射。使用 awsquicksightdescribe-ip-restriction 检索当前规则，并在更新中包含任何现有规则。

**关键考虑因素：**

- IP 和 VPC 端点规则适用于 Quick Web、嵌入式和移动访问，这意味着它们不限制对公共 API 的访问。要限制来自特定源的 API 调用，请使用带有 `aws:SourceIp` 或 `aws:SourceVpce` 条件的 IAM 策略。
- 在启用限制之前，请确保您自己的 IP 或 VPC 终端节点已包含在规则中，否则您将被锁定。
- 规则最多可能需要 10 分钟才能完全生效。
- 您可以组合 IP 规则和 VPC 终端节点规则，这样，如果流量满足任一规则类型，则允许流量。您最多可以添加 100 条 IP 和 VPC 终端节点规则。
- IP 和 VPC 终端节点规则在您的账户的所有 AWS 区域中强制执行，但您只能从创建您的 Quick 账户的 AWS 区域添加或管理它们。
- 如果您有公开嵌入的仪表板，则在启用限制后只能通过 VPC 终端节点访问它们。

实施限制后，只有通过指定 VPC 终端节点（或允许的 IP 范围）到达的流量才能到达您的 Quick 账户。所有其他访问均被拒绝。

## 安全用户访问和身份联合

专用网络连接使流量远离公共互联网，但它并不能回答谁可以访问 Quick 中的内容的问题。本节介绍如何集成企业身份提供商、控制用户配置以及跨 Quick 组件实施细粒度的访问分段。

### 与 AWS IAM 身份中心集成

> 重要提示：对于与 IAM Identity Center 集成的 Quick 账户，基于浏览器的身份验证需要访问公共 AWS 登录和 IAM Identity Center 终端节点。 VPC 终端节点不提供此浏览器登录路径。不需要公共 IP 地址。通过 NAT 网关或代理提供出站连接。请参阅 IAM Identity Center 用户指南中的私有访问注意事项。

Amazon Quick 使用 AWS IAM Identity Center 作为员工身份管理的中心点。 IAM Identity Center 使用 SAML 2.0 进行身份验证并使用 SCIM 2.0 进行自动用户和组配置连接到您现有的企业身份提供商 (IdP)。这提供了：

- 自动用户配置和取消配置与您的 IdP 同步。
- 组成员身份同步 – 当用户添加到组或从组中删除时，该更改会传播到 Quick。
- 使用现有公司凭据进行单点登录 (SSO)。
- 通过假定的 IAM 角色提供临时凭证 – 没有长期存在的 Quick 专用密码。

有关通过身份提供商设置 IAM Identity Center 的分步指南，请参阅 [IAM Identity Center 入门](https://docs.aws.amazon.com/singlesignon/latest/userguide/getting-started.html)。

### Quick 中基于角色的访问

Quick 支持三种基本角色，这些角色决定用户可以执行哪些操作：

- **管理员** – 完全管理访问权限，包括数据源配置、VPC 连接、安全设置、用户管理和 SPICE 容量购买。
- **作者** – 可以创建和发布仪表板、构建代理、配置空间、管理数据源、创建流和构建应用程序。
- **读者** – 可以查看已发布的仪表板、与代理交互、使用他们被授予访问权限的空间以及使用快速研究报告。

这些角色映射到联合用户在登录时担任的 IAM 角色。通过管理 IdP 中的角色分配，您可以维护关于谁拥有何种访问级别的单一事实来源。

此外，Quick 支持自定义权限配置文件，可以覆盖帐户、角色或用户级别的默认角色权限。用户级别权限优先于角色级别，角色级别又优先于帐户级别。这使管理员能够在三个基本角色之外进行精细控制。

### 使用空格进行用户细分

Quick Spaces 提供了角色之外的附加访问分段层。每个空间都可以配置特定的用户和组权限，这意味着：

- 包含敏感收入仪表板和财务知识库的财务团队空间仅可供财务团队访问。
- 具有 CRM 连接代理和管道仪表板的销售团队空间仅限销售用户使用。
- 跨职能空间可以在具有适当权限的多个组之间共享。

空间级别的访问由从您的身份提供商同步的组控制，因此将新的团队成员添加到适当的组会自动授予他们对相关空间的访问权限。

### Quick Sight 中的行级安全性

对于结构化数据支持的仪表板，Quick Sight 支持行级安全性 (RLS)，该安全性限制每个用户或组可以查看哪些数据行。 RLS 通过数据集规则进行配置，这些规则是将用户或组映射到他们可以访问的字段值的权限数据集。

例如，可以配置区域销售仪表板，以便：

- EMEA 销售组仅看到“region = 'EMEA'”的行。
- NA 销售组仅看到“region = 'NA'”的行。
- 销售副总裁可以查看所有行。

RLS 规则根据 IAM 身份中心确定的用户身份进行评估，这意味着控制登录的同一身份联合也管理数据级访问。这同样适用于传统的仪表板视图和人工智能驱动的自然语言查询。相同的安全策略限制人工智能在生成答案时可以参考的数据。

### 列级安全性

除了行级限制之外，Quick Sight 还支持列级安全性 (CLS)，以对特定用户或组隐藏敏感列。例如，包含员工信息的数据集可能会将工资和 SSN 列限制为仅限 HR 组，而其他组仍然可以访问同一数据集中的非敏感列。

### 身份如何与私人连接联系起来

身份层和网络层协同工作：

- 公司网络上的用户通过您的 IdP → IAM 身份中心 → Quick 进行身份验证。
- 他们的请求通过 VPC 终端节点（专用网络路径；请参阅 VPC 终端节点了解用户和 API 访问）到达 Quick。
- 快速评估他们的身份以确定角色、空间访问和 RLS/CLS 策略。
- 当 Quick 从本地源获取数据时，它使用 VPC 连接（VPC 中的 ENI；请参阅数据源访问的 VPC 连接）通过 Direct Connect 访问数据库。
- 响应通过相同的私有路径返回给用户。

除了启用对所需外部域的访问中描述的登录和静态资产流量之外，没有任何流量穿过公共互联网，并且在每个点上，用户的身份决定了他们可以看到和执行的操作。

## 安全最佳实践

单独的网络隔离和身份控制都不够。该架构依赖于以下两个方面：网络控制可防止未经授权的访问路径，而身份控制可防止授权会话中未经授权的数据访问。下面的实践保留了这两个层。

- **最低权限端点策略：** 通过 `aws:PrincipalAccount` 或 `aws:OrgId` 限制网站端点。在 API 端点上，将策略范围限制为仅自动化所需的特定操作，而不是允许所有“quicksight:*”操作。
- **分层安全组：** 将安全组应用于 VPC 终端节点 ENI（用户流量）和 VPC 连接 ENI（数据流量）。在端点 ENI 上，将入站 HTTPS 限制在您的公司 CIDR 范围内。在 VPC 连接 ENI 上，使用专用安全组，将出站限制为仅数据库端口和快速需求的目标，并在每个数据源的入站规则中引用该安全组。
- **在所有端点 ENI 上启用 VPC 流日志：** 这些日志捕获流量元数据以进行安全监控、异常检测和合规性审核。它们还提供监管框架所需的受控网络边界的审计跟踪。
- **定期审核端点策略：** 每季度审查端点策略。使用 AWS Config 规则来检测与基准配置的偏差。
- **按敏感度分隔 VPC 连接：** 如果您有多个数据环境（开发、暂存、生产），请使用不同的安全组创建单独的 VPC 连接，以防止跨环境访问。
- **使用 CloudWatch 进行监控：** 针对“PacketsDropped”和“ActiveConnections”指标设置警报。不寻常的模式可能表明配置错误或尝试未经授权的访问。

### 示例要求和 AWS 配置

以下示例展示了本文中的配置如何满足常见的安全网络要求。与您的安全团队根据您自己的要求评估它们。

## 成本考虑

| **组件** | **成本模型** | **估计** |
| --- | --- | --- |
| VPC接口端点|每个可用区 0.01 美元/小时 + 已处理的 0.01 美元/GB |每个可用区每个端点约 7.20 美元/月（固定）+ 数据传输 |
| VPC 网关端点 (S3) |不收费 |不收费 |
| VPC 连接（快速 ENI）|包含在 Quick Enterprise | 中无额外费用 |
| NAT 网关（用于外部域） | $0.045/小时 + $0.045/GB 处理 | ~$32/月（固定）+ 数据传输 |
| VPC 流日志 | CloudWatch Logs 摄取率 |随交通量变化 |
|直接连接 |端口时间 + 数据传输 |随电路尺寸变化|

**成本优化技巧：**

- 尽可能使用 S3 的网关端点（无需额外付费）而不是接口端点。
- 整合终端节点 ENI：每个终端节点仅需要 Amazon Quick VPC 连接子网所在的可用区中的 ENI。
- 有选择地在端点 ENI 上启用 VPC 流日志，而不是在整个 VPC 上。
- 考虑是否所有外部域都需要 NAT 网关访问，或者目标代理是否对您的流量模式更具成本效益。

## 结论

此架构建立了四个互补的控制：VPC 终端节点保持用户流量的私密性，VPC 连接为 Quick 提供通往数据源的私有路径，身份联合确定谁可以访问什么内容，以及 VPC 终端节点限制强制使用私有路径。每个层都是独立可审核的，并映射到特定的合规性要求（请参阅合规性映射）。

完成此操作后，Quick Agents 可以查询您的本地数据库，Quick Research 可以调查防火墙后面的企业来源，Quick Sight 仪表板可以可视化敏感数据，Quick Flows 可以编排内部系统，所有这些都无需您的数据穿越公共互联网。 AI能力不变。曝光被移除。

要实施，请从用于用户和 API 访问的 VPC 终端节点开始，并在进行数据源访问的 VPC 连接之前验证用户访问。仅在确认所有访问模式都通过专用路径工作后才启用 VPC 终端节点限制。有关身份联合设置和高级 RLS/CLS 配置，请参阅 [IAM 身份中心文档](https://docs.aws.amazon.com/singlesignon/latest/userguide/getting-started.html)。
