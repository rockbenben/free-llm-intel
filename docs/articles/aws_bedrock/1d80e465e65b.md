## [人工智能](https://aws.amazon.com/blogs/machine-learning/)

# 将 Kimi Code CLI 与 Amazon Bedrock 上的模型结合使用

[Kimi Code CLI](https://github.com/moonshotai/kimi-code) 是来自 Moonshot AI 的开源编码代理，Moonshot AI 是 Kimi 系列开放权重基础模型的创建者。以前，将 Kimi Code 与 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的模型结合使用意味着使用 Amazon Bedrock API 密钥配置通用连接“提供商”。对于许多 AWS 客户来说，这意味着引入额外的凭证来获取和保护。

在 v2.7.0 中，Moonshot AI 在 CLI 中添加了原生Bedrock提供程序。您现在可以将代理配置为使用标准 AWS 凭证链，包括命名配置文件和单点登录 (SSO)，而不是创建和管理单独的 API 密钥。

在这篇文章中，我们向您展示如何使用现有的 AWS 凭证将 Kimi Code CLI 连接到 Amazon Bedrock 上的模型。我们以【Kimi K3.1 Pro Highspeed】(https://aws.amazon.com/blogs/machine-learning/introducing-kimi-k3-1-pro-on-amazon-bedrock/)为例，支持流式传输、可配置推理、图像输入、客户端工具调用。

＃＃ 什么是新的

Amazon Bedrock 为来自领先提供商的一系列开放和专有模型提供按代币付费推理，可通过 [标准 API](https://docs.aws.amazon.com/bedrock/latest/userguide/apis.html) 获得。处理保持在 AWS 数据边界内，如用户指南的[数据保护](https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html) 部分中详述。 [型号卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html) 详细说明了每个型号支持哪些 API 和功能。

在旧版本的 Kimi Code CLI 中，您可以通过 `type = "openai"` 或 `type = "openai_responses"` 的提供商连接到 Amazon Bedrock。它们分别使用 OpenAI 兼容的 [聊天完成](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-completions.html) 或 [响应](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html) API。此方法要求您设置区域 `base_url` 并提供 [Amazon Bedrock API 密钥](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html)。密钥可以是短期的，也可以是长期的，但它是一个单独的凭证，供您获取和管理。

本机提供商更改了该设置：

- **使用现有的 AWS 身份验证工作流程。** `bedrock` 提供商可以通过标准 [AWS 命令​​行界面 (AWS CLI)](https://aws.amazon.com/cli/) 凭证链解析临时凭证。您可以使用默认链或选择命名配置文件，包括 SSO 支持的配置文件。
- **如果需要，覆盖每个模型的协议。** 提供商从模型 ID 推断 API 格式和区域端点，但您可以按照本文“覆盖端点 URL 和协议”部分中的详细信息更改它们。

AWS 建议使用短期凭证而不是长期凭证。这一新路径减少了对手动管理的 API 密钥的依赖，但它不会改变您适当保护 AWS 凭证和范围权限的责任。

## 它是如何工作的

本机提供程序分四个步骤处理身份验证和请求路由：

- **解析 AWS 凭证。** 除非您配置 Amazon Bedrock API 密钥，否则 bedrock 提供商将在您的环境中使用标准 AWS 凭证链。您可以设置 `AWS_PROFILE` 以选择特定的[命名配置文件](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html#cli-configure-files-using-profiles)。
- **生成短期不记名令牌。** 提供商使用 [@aws/bedrock-token-generator](https://www.npmjs.com/package/@aws/bedrock-token-generator) 创建短期 Amazon Bedrock API 密钥，并在必要时续订。您无需在 Kimi 代码 `config.toml` 中放置任何 AWS 访问密钥或手动生成的 Amazon Bedrock 密钥。但是，如果您提供了通过 `api_key` 或 `api_key_env` 给出的显式密钥，则该密钥优先。
- **构建区域端点。** 提供程序解析 `AWS_REGION` 或 `AWS_DEFAULT_REGION` 并为模型的推断 API 构造适当的 `bedrock-runtime` 端点。对于 Kimi 模型，这会解析为推荐的与 OpenAI 兼容的聊天完成路径。
- **调用选定的推理配置文件。** 模型别名映射到 Amazon Bedrock 模型或 [推理配置文件](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles.html) ID。此示例使用全局推理配置文件 `global.moonshotai.kimi-k3.1`。 `global.` 前缀选择配置文件，而 `AWS_REGION` 确定接收您的请求的区域终端节点。

然后，CLI 流式传输模型响应，并可以在编码任务期间使用模型的客户端工具调用支持。身份验证、授权、模型访问和网络连接都必须成功才能完成请求。提供商生成的临时 API 密钥的有效期最长为 12 小时或您的 AWS 会话长度（以较短者为准）。

## 先决条件

在本演练中，我们使用 Kimi K3.1 Pro Highspeed 作为示例模型，通过[全局跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html) 访问，以获得最广泛的可用性和最低的成本。在使用该模型之前，请查看 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/) 以了解预期成本。

要继续操作，您需要：

- 有权访问受支持的源 AWS 区域中的目标模型和推理配置文件的 AWS 账户。检查 [Kimi K3.1 Pro Highspeed 模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3-1-highspeed.html) 以了解当前区域和推理配置文件支持。
- Kimi Code CLI v2.7.0 或更高版本。按照[Kimi Code CLI 安装指南](https://github.com/MoonshotAI/kimi-code/blob/main/docs/en/guides/getting-started.md) 并运行 `kimi --version` 检查您的安装。
- [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)，遵循本文中的配置文件和身份检查命令。可选的 `aws login` 工作流程需要 AWS CLI v2.32.0 或更高版本。
- [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 身份（用户或代入角色），有权在您选择的 AWS 区域中调用目标模型和推理配置文件。

以下示例 IAM [策略](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies.html) 仅针对 Kimi K3.1 Pro Highspeed 模型和全局推理配置文件授予本演练使用的权限。将 `${AWS_REGION}` 替换为您的源区域（例如，`us-west-2` 表示美国西俄勒冈州），并将 `${AWS_ACCOUNT_ID}` 替换为您的 12 位 AWS 账户 ID：
```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "BedrockShortTermBearerToken",
      "Effect": "Allow",
      "Action": "bedrock:CallWithBearerToken",
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "bedrock:bearerTokenType": "SHORT_TERM"
        }
      }
    },
    {
      "Sid": "BedrockReadKimiK31InferenceProfile",
      "Effect": "Allow",
      "Action": "bedrock:GetInferenceProfile",
      "Resource": "arn:aws:bedrock:${AWS_REGION}:${AWS_ACCOUNT_ID}:inference-profile/global.moonshotai.kimi-k3.1"
    },
    {
      "Sid": "BedrockInvokeKimiK31GlobalProfile",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream"
      ],
      "Resource": "arn:aws:bedrock:${AWS_REGION}:${AWS_ACCOUNT_ID}:inference-profile/global.moonshotai.kimi-k3.1"
    },
    {
      "Sid": "BedrockInvokeKimiK31ModelsThroughGlobalProfile",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream"
      ],
      "Resource": [
        "arn:aws:bedrock:${AWS_REGION}::foundation-model/moonshotai.kimi-k3.1",
        "arn:aws:bedrock:::foundation-model/moonshotai.kimi-k3.1"
      ],
      "Condition": {
        "StringEquals": {
          "bedrock:InferenceProfileArn": "arn:aws:bedrock:${AWS_REGION}:${AWS_ACCOUNT_ID}:inference-profile/global.moonshotai.kimi-k3.1"
        }
      }
    },
    {
      "Sid": "BedrockInvokeKimiK31DefaultProject",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel"
      ],
      "Resource": "arn:aws:bedrock:${AWS_REGION}:${AWS_ACCOUNT_ID}:project/default",
      "Condition": {
        "StringEquals": {
          "bedrock:ModelArn": "arn:aws:bedrock:${AWS_REGION}:${AWS_ACCOUNT_ID}:inference-profile/global.moonshotai.kimi-k3.1"
        }
      }
    }
  ]
}
```
不带区域或账户 ID 的基础模型 ARN 是有意为之的，并且是全局跨区域路由所必需的。仅当使用 `openai_responses` 协议时才需要 `BedrockInvokeKimiK31DefaultProject` 语句，而不是使用默认的 `openai`（聊天完成）。

AWS 环境的安全是[共同责任](https://aws.amazon.com/compliance/shared-responsibility-model/)。根据[最小权限原则](https://docs.aws.amazon.com/IAM/latest/UserGuide/getting-started-reduce-permissions.html)审核并授予 IAM 权限，特别是对于生产环境。考虑为 Kimi Code CLI 使用专用 IAM [角色](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html)，与常规 AWS 活动分开。

## 开始使用 `bedrock` 提供商

先决条件准备就绪后，请按照以下步骤配置 AWS 身份验证、添加提供商和模型并发送测试请求。

### 第 1 步：配置 AWS 凭证

有[使用 AWS CLI 进行身份验证的不同方法](https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-authentication.html)，具体取决于您组织的设置。通过[命名配置文件](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html)，您可以配置多个 AWS 上下文并在它们之间切换。

例如：

- 如果您通过 [AWS IAM Identity Center](https://aws.amazon.com/iam/identity-center/) 使用 SSO，请运行 `aws configure sso --profile YOUR_PROFILE_NAME` 设置配置文件，然后运行 ​​`aws sso login --profile YOUR_PROFILE_NAME` 进行身份验证。
- 要将 AWS 管理控制台凭证与 AWS CLI v2.32.0 或更高版本结合使用，请运行 `aws login --profile YOUR_PROFILE_NAME`。 [控制台凭据登录指南](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sign-in.html) 还描述了不直接支持缓存登录会话的工具的 `credential_process` 配置。
- 省略 `--profile` 参数以使用默认 AWS 配置文件而不是指定的配置文件。

无论您选择哪种方法，您的会话都会解析为需要先决条件中的 Amazon Bedrock 权限的 IAM 身份（用户或角色）。 AWS CLI 配置文件中配置的区域适用于 AWS CLI 命令，但您仍必须在步骤 2 中为 Kimi 代码显式设置区域。

验证 AWS CLI 是否解析您的预期身份。如果使用默认配置文件，请省略 `--profile YOUR_PROFILE_NAME`：
```
aws sts get-caller-identity --profile YOUR_PROFILE_NAME
```
### 第 2 步：添加提供商和模型

- 在文本编辑器中打开或创建 `~/.kimi-code/config.toml`。如果设置 `KIMI_CODE_HOME`，请改用 `$KIMI_CODE_HOME/config.toml`。如果您有现有文件，请对其进行备份并将这些条目与您当前的设置合并，而不是覆盖不相关的提供程序或模型。
- 将 `YOUR_SOURCE_REGION` 替换为您支持的源区域（例如 `us-west-2`）。要使用命名配置文件，请替换 `YOUR_PROFILE_NAME` 并取消注释 `AWS_PROFILE` 行： `default_model = "bedrock-kimi-k3-1" [providers.bedrock] type = "bedrock" [providers.bedrock.env] AWS_REGION = "YOUR_SOURCE_REGION" # AWS_PROFILE = "YOUR_PROFILE_NAME" [models.bedrock-kimi-k3-1] provider = "bedrock" model = "global.moonshotai.kimi-k3.1" max_context_size = 1000000 capabilities = ["always_thinking", "thinking", "image_in", "tool_use"]` 模型别名 `bedrock-kimi-k3-1` 是 Kimi Code CLI 使用的本地名称。模型值是 Amazon Bedrock 全局推理配置文件 ID。该示例声明了一个 100 万个令牌的上下文窗口以及显式推理、图像输入和工具使用功能。它省略了 `api_key`、`api_key_env` 和 `AWS_BEARER_TOKEN_BEDROCK`，因此提供商使用环境 AWS 凭证。配置的 Amazon Bedrock 密钥将优先。
- 保存文件。 `[providers.bedrock.env]` 表向提供者提供配置。它不会将变量导出到您的 shell 中。

### 步骤 3：发送请求并开始编码会话

- 运行一个小的非交互式编码请求：`kimi --model bedrock-kimi-k3-1 --prompt "Write a Python function that checks whether a string is a palindrome. Include a short usage example."`
- 确认 CLI 流式传输响应，而没有身份验证、授权、区域、模型访问或网络错误。该请求提供了比提供商状态指示器更有意义的连接检查。
- 在项目目录中启动交互式会话：`cd /path/to/your/project kimi` 由于您设置了 `default_model`，因此会话会自动选择 `bedrock-kimi-k3-1`。要求代理解释存储库或提出一个小的更改。在批准之前查看其建议的文件修改和 shell 命令。

## 配置最佳实践

在撰写本文时，本机Bedrock提供程序有几个配置注意事项。这些做法可帮助您避免不明确的状态信息和不匹配的设置。

### 使用配置文件设置提供程序

在撰写本文时，Kimi Code 的桌面和 Web 提供程序创建界面并未公开此凭证链设置使用的所有提供程序环境字段。直接编辑 `config.toml` 以设置 Amazon Bedrock 提供商。有关更多详细信息，请参阅 Kimi 代码文档中的[模型提供程序](https://www.kimi.com/code/docs/en/kimi-code-cli/configuration/providers.html)。

### 显式声明模型功能

Kimi Code 不会自动检测 Amazon Bedrock 上大多数模型的功能，包括 Kimi 模型。检查每个目标模型的 Amazon Bedrock 模型卡，并明确声明其功能以便 Kimi Code 使用它们。

例如，[Kimi K3.1 Pro Highspeed](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3-1-highspeed.html) 支持 `always_thinking`、`thinking`、`image_in` 和 `tool_use`，但不支持 `audio_in` 或 `video_in`，如前面所示的 `config.toml` 示例所示。

这些声明描述了客户端行为。您应该仅包含每个目标模型和 Amazon Bedrock API 终端节点支持的功能。验证应用程序的工具和图像工作流程，而不是仅仅依赖功能标签。

### 保持区域设置一致，并尽可能首选跨区域推理

bedrock 提供程序需要在 Kimi Code 的 `config.toml` 或 shell 环境中显式使用 `AWS_REGION` 或 `AWS_DEFAULT_REGION`。它无法推断仅在 `~/.aws/config` 或通过 `aws configure` 配置的区域。

当您使用跨区域推理配置文件（带有 `global.`、`us.` 或 `in.` 等前缀）时，配置的 Kimi 代码区域控制接收请求的源区域。有关更多信息，请参阅 Amazon Bedrock 用户指南中的[跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)。

对于没有数据驻留要求的工作负载，请从全局推理配置文件开始。与许多其他模型一样，该模型进行全局推理的价格比通过地理概况进行推理的价格低 10%。查看 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/) 了解当前费率和地理替代方案。

### 在需要时覆盖端点 URL 和协议

在某些情况下，提供商的自动检测可能会错误地识别您要用于特定模型的 API 协议或目标 URL。例如，您需要设置不同的 URL 才能通过 [VPC 终端节点](https://docs.aws.amazon.com/bedrock/latest/userguide/vpc-interface-endpoints.html) 或 [Mantle 终端节点](https://docs.aws.amazon.com/bedrock/latest/userguide/endpoints.html) 使用 Amazon Bedrock。

在Kimi代码`config.toml`中，您可以：

- 将 `protocol` 字段设置为 `openai`（聊天完成）、`openai_responses` 或 `anthropic`（消息）以将模型配置为使用特定支持的有线协议。请参阅[型号卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html) 了解哪些型号支持哪些 API。
- 设置 `base_url` 字段以更改目标 URL，该 URL 必须包含任何附加的 API 路径，例如 `/openai/v1` 或 `/anthropic`。

在以下示例中，我们展示了连接到同一模型的配置，但通过您设置的 Amazon Bedrock [VPC 终端节点](https://docs.aws.amazon.com/bedrock/latest/userguide/vpc-interface-endpoints.html) 使用 OpenAI Responses API：
```
[models.bedrock-kimi-k3-1]
provider = "bedrock"
model = "global.moonshotai.kimi-k3.1"
max_context_size = 1000000
capabilities = ["always_thinking", "thinking", "image_in", "tool_use"]
protocol = "openai_responses"
base_url = "https://vpce-EXAMPLE-VPCEID.bedrock-runtime.us-west-2.vpce.amazonaws.com/openai/v1"
```
### 将连接状态视为配置指示器

在 Kimi Code 桌面和 Web 应用程序中，提供商列表可以显示Bedrock提供商的 `connected`。该状态不会验证配置的 AWS 凭证、IAM 权限、区域、模型访问或网络路径。不要将其视为模型请求成功的证据。使用非交互式提示来测试完整路径，并在失败时诊断实际响应。

## 清理

如果您创建了新的 AWS IAM 身份或分配了新的权限来在 Amazon Bedrock 上试验 Kimi K3.1 Pro，请记住在完成测试后将其删除。

您可能还想恢复您设置的任何本地 Kimi Code CLI 提供商配置或 AWS CLI 配置文件。如果不再需要 CLI，您甚至可以完全卸载它们。有关详细信息，请参阅 [Kimi Code](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/getting-started.html#upgrade-and-uninstall) 和 [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/uninstall.html) 的卸载指南。请记住，删除本地 AWS 配置或 CLI 本身并不会撤销 IAM 权限或活动的 AWS 会话。

我们展示的模型的 Amazon Bedrock 推理按每个令牌收费，因此无需清理持久的云基础设施部署。

＃＃ 结论

我们展示了 Kimi Code CLI v2.7.0 中 Moonshot AI 的原生 bedrock 提供程序如何通过标准 AWS 凭证链连接到 Amazon Bedrock 上的 Kimi K3.1 Pro Highspeed。您不再需要单独管理的 Amazon Bedrock API 密钥。

Amazon Bedrock 让您可以通过标准 API 访问来自领先提供商的开放和专有 AI 模型。其治理控制和[合规性验证](https://docs.aws.amazon.com/bedrock/latest/userguide/compliance-validation.html) 程序甚至可以支持严格监管的工作负载。

如果您已经在使用 Kimi Code CLI 并希望在 AWS 上运行推理，请立即升级并尝试新的简化身份验证。

有关 Amazon Bedrock 上的 Kimi K3.1 Pro 的更多信息，请参阅我们的[发布博客文章](https://aws.amazon.com/blogs/machine-learning/introducing-kimi-k3-1-pro-on-amazon-bedrock/) 和 [AWS 上的 Moonshot AI 示例存储库](https://github.com/aws-samples/sample-moonshotai-on-aws)。要按型号探索支持的 API 和功能，请参阅 Amazon Bedrock 用户指南中的[型号卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html)。要与 Amazon Bedrock 团队讨论您的使用案例，请[与我们联系](https://pages.awscloud.com/Amazon-Bedrock-Contact-Us.html)。
