# 将 Kimi Code CLI 与 Amazon Bedrock 上的模型结合使用

[Kimi Code CLI](https://github.com/moonshotai/kimi-code) 是 Moonshot AI 开源的编码 agent，而 Moonshot AI 正是 Kimi 系列开放权重基础模型的作者。此前，要让 Kimi Code 用上 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的模型，得用一个 Amazon Bedrock API key 去配一个通用的连接“provider”。对很多 AWS 客户来说，这意味着凭空多出一份要获取、要保管的凭证。

在 v2.7.0 中，Moonshot AI 为 CLI 加入了原生 bedrock provider。现在你可以让 agent 走标准的 AWS 凭证链，包括具名 profile 和单点登录（SSO），不必再单独创建和管理一份 API key。

本文演示如何用现有的 AWS 凭证把 Kimi Code CLI 接到 Amazon Bedrock 上的模型。我们以 [Kimi K3.1 Pro Highspeed](https://aws.amazon.com/blogs/machine-learning/introducing-kimi-k3-1-pro-on-amazon-bedrock/) 为例，它支持流式输出、可配置推理、图像输入和客户端工具调用。

## 新增内容

Amazon Bedrock 通过[标准 API](https://docs.aws.amazon.com/bedrock/latest/userguide/apis.html)，为来自领先厂商的一系列开放与专有模型提供按 token 计费的推理服务。处理过程始终留在 AWS 数据边界之内，具体见用户指南的[数据保护](https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html)一节。[模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html)则详细列出每个模型支持哪些 API 和功能。

在旧版 Kimi Code CLI 中，你可以通过 `type = "openai"` 或 `type = "openai_responses"` 的 provider 连接 Amazon Bedrock。两者分别使用 OpenAI 兼容的 [Chat Completions](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-completions.html) 或 [Responses](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-responses-api.html) API。这种做法要求你设置区域性的 `base_url`，并提供一份 [Amazon Bedrock API key](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys.html)。key 可以是短期或长期的，但终归是一份要你自己去获取、自己管理的独立凭证。

原生 provider 把这套配置彻底改了：

- **沿用你现有的 AWS 认证流程。** `bedrock` provider 可以通过标准 [AWS Command Line Interface（AWS CLI）](https://aws.amazon.com/cli/) 凭证链解析临时凭证。你可以用默认链，也可以选定一个具名 profile，包括由 SSO 支撑的 profile。
- **需要时为每个模型覆盖协议。** provider 会从模型 ID 推断 API 格式和区域 endpoint，你也可以按本文“覆盖 endpoint URL 与协议”一节所述自行修改。

AWS 建议使用短期凭证而非长期凭证。这条新路径减少了对人工管理 API key 的依赖，但你保护 AWS 凭证、合理限定权限的责任并没有改变。

## 工作原理

原生 provider 分四步完成认证和请求路由：

- **解析 AWS 凭证。** 除非你配置了 Amazon Bedrock API key，否则 bedrock provider 会使用你环境中的标准 AWS 凭证链。你可以设置 `AWS_PROFILE` 来选定某个[具名 profile](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html#cli-configure-files-using-profiles)。
- **生成短期 bearer token。** provider 借助 [@aws/bedrock-token-generator](https://www.npmjs.com/package/@aws/bedrock-token-generator) 创建一个短期 Amazon Bedrock API key，并在需要时续期。你无需把任何 AWS access key 或手工生成的 Amazon Bedrock key 写进 Kimi Code 的 `config.toml`。不过，如果你通过 `api_key` 或 `api_key_env` 显式给了 key，则该 key 优先。
- **构建区域 endpoint。** provider 解析 `AWS_REGION` 或 `AWS_DEFAULT_REGION`，并按模型推断出的 API 构造相应的 `bedrock-runtime` endpoint。对 Kimi 模型而言，解析结果是推荐的 OpenAI 兼容 Chat Completions 路径。
- **调用选定的 inference profile。** 模型别名会映射到 Amazon Bedrock 模型或 [inference profile](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles.html) ID。本例使用全局 inference profile `global.moonshotai.kimi-k3.1`。`global.` 前缀用于选择 profile，而 `AWS_REGION` 决定哪个区域 endpoint 接收你的请求。

随后 CLI 以流式返回模型响应，并能在编码任务中利用模型的客户端工具调用能力。认证、授权、模型访问和网络连通性必须全部通过，一个请求才能完成。provider 生成的临时 API key 有效期最长 12 小时，或等于你的 AWS 会话时长，取两者中较短的一个。

## 前提条件

本演练以 Kimi K3.1 Pro Highspeed 作为示例模型，通过[全局跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html)访问，以获得最广的可用性和最低的成本。使用该模型前，请先查看 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/) 了解预期费用。

要跟着做，你需要：

- 一个 AWS 账户，且在受支持的源 AWS 区域中能够访问目标模型和 inference profile。请查看 [Kimi K3.1 Pro Highspeed 模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3-1-highspeed.html) 了解当前支持的区域和 inference profile。
- Kimi Code CLI v2.7.0 或更高版本。请按 [Kimi Code CLI 安装指南](https://github.com/MoonshotAI/kimi-code/blob/main/docs/en/guides/getting-started.md) 操作，并运行 `kimi --version` 检查安装情况。
- [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)，用于执行本文中的 profile 和身份检查命令。可选的 `aws login` 流程要求 AWS CLI v2.32.0 或更高版本。
- 一个 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam/) 身份（用户或代入角色），在你选定的 AWS 区域中拥有调用目标模型和 inference profile 的权限。

下面的 IAM [policy](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies.html) 示例只授予本演练所需的权限，且仅限 Kimi K3.1 Pro Highspeed 模型和全局 inference profile。请把 `${AWS_REGION}` 换成你的源区域（例如美国西部俄勒冈用 `us-west-2`），把 `${AWS_ACCOUNT_ID}` 换成你的 12 位 AWS 账户 ID：

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "BedrockShortTermBearerToken",
      "Effect": "Allow",
      "Action": "bedrock:CallWithBearerToken",
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "bedrock:bearerTokenType": "SHORT_TERM"
        }
      }
    },
    {
      "Sid": "BedrockReadKimiK31InferenceProfile",
      "Effect": "Allow",
      "Action": "bedrock:GetInferenceProfile",
      "Resource": "arn:aws:bedrock:${AWS_REGION}:${AWS_ACCOUNT_ID}:inference-profile/global.moonshotai.kimi-k3.1"
    },
    {
      "Sid": "BedrockInvokeKimiK31GlobalProfile",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream"
      ],
      "Resource": "arn:aws:bedrock:${AWS_REGION}:${AWS_ACCOUNT_ID}:inference-profile/global.moonshotai.kimi-k3.1"
    },
    {
      "Sid": "BedrockInvokeKimiK31ModelsThroughGlobalProfile",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream"
      ],
      "Resource": [
        "arn:aws:bedrock:${AWS_REGION}::foundation-model/moonshotai.kimi-k3.1",
        "arn:aws:bedrock:::foundation-model/moonshotai.kimi-k3.1"
      ],
      "Condition": {
        "StringEquals": {
          "bedrock:InferenceProfileArn": "arn:aws:bedrock:${AWS_REGION}:${AWS_ACCOUNT_ID}:inference-profile/global.moonshotai.kimi-k3.1"
        }
      }
    },
    {
      "Sid": "BedrockInvokeKimiK31DefaultProject",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel"
      ],
      "Resource": "arn:aws:bedrock:${AWS_REGION}:${AWS_ACCOUNT_ID}:project/default",
      "Condition": {
        "StringEquals": {
          "bedrock:ModelArn": "arn:aws:bedrock:${AWS_REGION}:${AWS_ACCOUNT_ID}:inference-profile/global.moonshotai.kimi-k3.1"
        }
      }
    }
  ]
}
```

不带区域和账户 ID 的 foundation-model ARN 是有意为之，也是全局跨区域路由所必需的。`BedrockInvokeKimiK31DefaultProject` 语句只在用 `openai_responses` 协议时才需要，默认的 `openai`（Chat Completions）用不到。

AWS 环境的安全属于[共同责任](https://aws.amazon.com/compliance/shared-responsibility-model/)。请按[最小权限原则](https://docs.aws.amazon.com/IAM/latest/UserGuide/getting-started-reduce-permissions.html)审核并授予 IAM 权限，生产环境尤其如此。可以考虑为 Kimi Code CLI 单独配一个 IAM [角色](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html)，与日常 AWS 操作分开。

## 开始使用 `bedrock` provider

前提条件就绪后，按以下步骤配置 AWS 认证、添加 provider 和模型，然后发一个测试请求。

### 第 1 步：配置 AWS 凭证

[用 AWS CLI 做身份认证有几种不同方式](https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-authentication.html)，取决于你所在组织的设置。借助[具名 profile](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-files.html)，你可以配置多套 AWS 上下文并在其间切换。

例如：

- 如果你通过 [AWS IAM Identity Center](https://aws.amazon.com/iam/identity-center/) 使用 SSO，运行 `aws configure sso --profile YOUR_PROFILE_NAME` 建立 profile，再运行 `aws sso login --profile YOUR_PROFILE_NAME` 完成认证。
- 要用 AWS Management Console 凭证搭配 AWS CLI v2.32.0 或更高版本，运行 `aws login --profile YOUR_PROFILE_NAME`。[控制台凭证登录指南](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sign-in.html)还说明了 `credential_process` 配置，适用于不直接支持缓存登录会话的工具。
- 去掉 `--profile` 参数，就使用默认 AWS profile 而不是具名 profile。

无论选哪种方式，你的会话都会解析成一个 IAM 身份（用户或角色），它需要具备前提条件里那些 Amazon Bedrock 权限。在 AWS CLI profile 里配置的区域只对 AWS CLI 命令生效；对 Kimi Code，你仍必须在第 2 步显式设置区域。

确认 AWS CLI 解析出的是你想要的那个身份。如果你用默认 profile，就去掉 `--profile YOUR_PROFILE_NAME`：

```
aws sts get-caller-identity --profile YOUR_PROFILE_NAME
```

### 第 2 步：添加 provider 和模型

- 用文本编辑器打开或新建 `~/.kimi-code/config.toml`。如果你设置了 `KIMI_CODE_HOME`，则改用 `$KIMI_CODE_HOME/config.toml`。如果文件已存在，先备份，再把这些条目合并进现有设置，不要直接覆盖掉无关的 provider 或模型。
- 把 `YOUR_SOURCE_REGION` 换成你受支持的源区域（例如 `us-west-2`）。要用具名 profile，就把 `YOUR_PROFILE_NAME` 换掉并取消 `AWS_PROFILE` 那一行的注释：  `default_model = "bedrock-kimi-k3-1" [providers.bedrock] type = "bedrock" [providers.bedrock.env] AWS_REGION = "YOUR_SOURCE_REGION" # AWS_PROFILE = "YOUR_PROFILE_NAME" [models.bedrock-kimi-k3-1] provider = "bedrock" model = "global.moonshotai.kimi-k3.1" max_context_size = 1000000 capabilities = ["always_thinking", "thinking", "image_in", "tool_use"]`  模型别名 `bedrock-kimi-k3-1` 是 Kimi Code CLI 使用的本地名称。模型值是 Amazon Bedrock 全局 inference profile ID。该示例声明了 100 万 token 的上下文窗口，以及推理、图像输入和工具调用这几项显式能力。它省略了 `api_key`、`api_key_env` 和 `AWS_BEARER_TOKEN_BEDROCK`，因此 provider 会使用环境中的 AWS 凭证。若另外配置了 Amazon Bedrock key，则该 key 优先。
- 保存文件。`[providers.bedrock.env]` 表只把配置交给 provider，并不会把变量导出到你的 shell。

### 第 3 步：发一个请求，开始编码会话

- 运行一个小型的非交互式编码请求：  `kimi --model bedrock-kimi-k3-1 --prompt "Write a Python function that checks whether a string is a palindrome. Include a short usage example."`
- 确认 CLI 以流式返回响应，且没有认证、授权、区域、模型访问或网络方面的错误。相比 provider 的状态指示灯，这个请求是更有意义的连通性检查。
- 在项目目录里启动交互式会话：  `cd /path/to/your/project kimi`  由于你设置了 `default_model`，会话会自动选中 `bedrock-kimi-k3-1`。让 agent 讲讲这个仓库，或者提一个小改动。在批准它提出的文件修改和 shell 命令之前，先逐一过目。

## 配置最佳实践

截至本文写作时，原生 bedrock provider 有几处配置需要留意。遵循这些做法，可以避免状态信息含糊、设置前后不一致。

### 用配置文件来配置 provider

截至本文写作时，Kimi Code 的桌面端与 Web 端 provider 创建界面并未暴露这套凭证链配置会用到的全部 provider 环境字段。请直接编辑 `config.toml` 来配置 Amazon Bedrock provider。更多细节参见 Kimi Code 文档中的[模型 provider](https://www.kimi.com/code/docs/en/kimi-code-cli/configuration/providers.html)。

### 显式声明模型能力

Kimi Code 不会自动探测 Amazon Bedrock 上大多数模型的能力，Kimi 系列模型也一样。请查看每个目标模型的 Amazon Bedrock 模型卡，并显式声明其能力，Kimi Code 才能用上它们。

例如，[Kimi K3.1 Pro Highspeed](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-moonshot-ai-kimi-k3-1-highspeed.html) 支持 `always_thinking`、`thinking`、`image_in` 和 `tool_use`，但不支持 `audio_in` 或 `video_in`，前面的 `config.toml` 示例正是这么写的。

这些声明描述的是客户端行为。你只应写入每个目标模型和 Amazon Bedrock API endpoint 实际支持的能力。工具与图像相关工作流要在你自己的应用里验证，不要只看能力标签。

### 保持区域设置一致，尽量优先使用跨区域推理

bedrock provider 要求在 Kimi Code 的 `config.toml` 或 shell 环境中显式给出 `AWS_REGION` 或 `AWS_DEFAULT_REGION`。它无法推断只写在 `~/.aws/config` 里、或通过 `aws configure` 配置的区域。

使用跨区域 inference profile 时（前缀如 `global.`、`us.` 或 `in.`），Kimi Code 里配置的区域决定哪个源区域接收你的请求。更多信息参见 Amazon Bedrock 用户指南中的[跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)。

对于没有数据驻留要求的工作负载，建议从全局 inference profile 起步。和许多其他模型一样，这个模型走全局推理的定价比走地理 profile 低 10%。当前费率和其他地理选项请查看 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。

### 按需覆盖 endpoint URL 与协议

有些情况下，provider 的自动探测可能把你对某个模型想用的 API 协议或目标 URL 认错。例如，要通过 [VPC endpoint](https://docs.aws.amazon.com/bedrock/latest/userguide/vpc-interface-endpoints.html) 或 [Mantle endpoint](https://docs.aws.amazon.com/bedrock/latest/userguide/endpoints.html) 使用 Amazon Bedrock，你就需要另设 URL。

在 Kimi Code 的 `config.toml` 里，你可以：

- 把 `protocol` 字段设为 `openai`（Chat Completions）、`openai_responses` 或 `anthropic`（Messages），让模型使用某种受支持的线路协议。哪些模型支持哪些 API，见[模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html)。
- 设置 `base_url` 字段以更换目标 URL，其中必须带上附随的 API 路径，例如 `/openai/v1` 或 `/anthropic`。

下面的示例展示了连接同一个模型、但通过你搭好的 Amazon Bedrock [VPC endpoint](https://docs.aws.amazon.com/bedrock/latest/userguide/vpc-interface-endpoints.html) 走 OpenAI Responses API 的配置：

```
[models.bedrock-kimi-k3-1]
provider = "bedrock"
model = "global.moonshotai.kimi-k3.1"
max_context_size = 1000000
capabilities = ["always_thinking", "thinking", "image_in", "tool_use"]
protocol = "openai_responses"
base_url = "https://vpce-EXAMPLE-VPCEID.bedrock-runtime.us-west-2.vpce.amazonaws.com/openai/v1"
```

### 把连接状态当作配置指示灯

在 Kimi Code 桌面端和 Web 应用中，provider 列表可能给某个 bedrock provider 显示 `connected`。这个状态并不校验已配置的 AWS 凭证、IAM 权限、区域、模型访问或网络路径。不要把它当成模型请求成功的证据。请用非交互式 prompt 测一遍完整链路，失败时再诊断实际响应。

## 清理

如果你为了试用 Amazon Bedrock 上的 Kimi K3.1 Pro 而新建了 AWS IAM 身份或分配了新权限，测试结束后记得删掉。

你可能还想还原本地为 Kimi Code CLI 做的 provider 配置，或为 AWS CLI 建的 profile。如果这些 CLI 不再需要，甚至可以整个卸载。细节见 [Kimi Code](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/getting-started.html#upgrade-and-uninstall) 和 [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/uninstall.html) 的卸载指南。注意，删除本地 AWS 配置或 CLI 本身，并不会撤销 IAM 权限，也不会结束一个仍然有效的 AWS 会话。

我们演示的这些模型在 Amazon Bedrock 上按 token 计费，因此没有常驻的云基础设施部署需要清理。

## 结语

我们演示了 Kimi Code CLI v2.7.0 中 Moonshot AI 的原生 bedrock provider 如何通过标准 AWS 凭证链，连接到 Amazon Bedrock 上的 Kimi K3.1 Pro Highspeed。你不再需要单独管理一份 Amazon Bedrock API key。

Amazon Bedrock 通过标准 API，让你用上来自领先厂商的开放与专有 AI 模型。它的治理控制和[合规验证](https://docs.aws.amazon.com/bedrock/latest/userguide/compliance-validation.html)项目，连监管严格的工作负载也能支撑。

如果你已经在用 Kimi Code CLI，并想在 AWS 上跑推理，现在就可以升级，试试这套精简后的认证方式。

关于 Amazon Bedrock 上的 Kimi K3.1 Pro 的更多信息，见我们的[发布博客文章](https://aws.amazon.com/blogs/machine-learning/introducing-kimi-k3-1-pro-on-amazon-bedrock/)和 [Moonshot AI on AWS 示例仓库](https://github.com/aws-samples/sample-moonshotai-on-aws)。想按模型了解支持的 API 和功能，见 Amazon Bedrock 用户指南里的[模型卡](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html)。想和 Amazon Bedrock 团队讨论你的用例，[联系我们](https://pages.awscloud.com/Amazon-Bedrock-Contact-Us.html)。
