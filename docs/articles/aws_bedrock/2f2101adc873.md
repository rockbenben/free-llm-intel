# 用 Deep Agents 与 Bedrock AgentCore 构建上下文丰富的研究 agent

AI 驱动的研究工作流中一个常见挑战是深度与上下文之间的取舍。如果你的 agent 读了十个网页，它的上下文窗口（大型语言模型（LLM）一次能处理的文本量）就会被原始内容填满。如果它还要运行数据分析代码，生成图表的逻辑就会与战略性推理争夺有限的空间。团队通常用手工串接 prompt（prompt-chaining）或串行处理来规避这个问题。

更好的做法是把深度工作委派给隔离的 subagent，只让它们返回精简结果。[LangChain Deep Agents](https://docs.langchain.com/oss/python/deepagents/overview) 负责这层编排，它会派生专用的临时 subagent 并管理其生命周期。[Amazon Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html) 提供每个 subagent 所需的基础设施，包括用于网页研究的 MicroVM（一种轻量、单一用途的虚拟机）中的真实浏览器，以及用于数据分析的完整 Python 环境。AgentCore 也作为原生 sandbox 提供方集成在 [Deep Agents CLI](https://docs.langchain.com/oss/python/integrations/sandboxes) 中，因此你可以运行 `deepagents --sandbox agentcore` 来试用 AgentCore CodeInterpreter，而无需构建完整的 agent。

在本文中，你将构建一个竞品研究 agent，端到端地演示这一模式。本走查面向正在构建多步 AI 工作流、且需要为 agent 提供隔离执行环境的开发者。在 notebook 的第 2 部分，你可以用 [AgentCore CLI](https://github.com/aws/agentcore-cli/tree/main) 把同一个 agent 部署到 [Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html)，使它作为受管、会话隔离的服务运行。

## 你将构建什么

coordinator agent 收到请求后，先检查 [AgentCore Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html) 中是否有过往的研究洞察。然后它并行派生三个用于研究的浏览器 subagent，每个都在自己的 AgentCore Browser MicroVM 中浏览不同竞品的网站。三个 subagent 返回结构化发现后，analyst subagent 收到合并后的数据，并使用 AgentCore Code Interpreter 生成对比图表与 markdown 报告。最后，关键洞察被保存到 AgentCore Memory 供后续会话使用。你可以用 [Amazon CloudWatch](https://docs.aws.amazon.com/cloudwatch/)，经由 [Amazon Bedrock AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html) 或 [LangSmith](https://docs.langchain.com/langsmith/home) 追踪整个工作流。

每类 subagent 只能访问自己那套工具：研究者用浏览器工具，分析师用解释器工具，coordinator 用记忆工具。

## 构建 agent

要构建这个 agent，你需要配置一个模型、为每类 subagent 创建 toolkit，然后用 LangChain Deep Agents 把它们串起来。

### 前提条件

开始之前，请确认你具备以下条件：

- 一个已启用 Amazon Bedrock AgentCore 访问权限的 AWS 账户

- 已配置好的 AWS 凭证，形式为环境变量（AWS_ACCESS_KEY_ID、AWS_SECRET_ACCESS_KEY、AWS_SESSION_TOKEN、AWS_REGION），或通过 AWS Command Line Interface（AWS CLI）profile 配置。所需的 IAM 权限请参阅 AgentCore 入门指南。

- Python 3.11 或更高版本，并带有用于安装包的 pip 或 uv

- （可选）已[启用 Amazon CloudWatch Transaction Search](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/Enable-TransactionSearch.html)，以便查看 AgentCore Observability 的 traces 与 spans

- （可选）一个用于可观测性的 LangSmith 账户

- （可选）一个已配置至少一种抽取策略的 AgentCore Memory 资源（抽取策略即决定从对话事件中抽取哪些知识的规则）

- （可选）[langchain-aws 示例仓库](https://github.com/langchain-ai/langchain-aws/blob/main/samples/agents/competitive_research_agent.ipynb) 中可直接运行的 Jupyter notebook，包含完整实现

### 步骤 1：配置模型

下面的代码配置用于编排 agent 的 LLM。这个示例通过 Amazon Bedrock 访问 Claude Sonnet：

```
from langchain_aws import ChatBedrockConverse
from langchain_aws.tools import create_browser_toolkit, create_code_interpreter_toolkit
from deepagents import create_deep_agent
from botocore.config import Config as BotoConfig
 
model = ChatBedrockConverse(
    model="us.anthropic.claude-sonnet-4-6",
    region_name="us-west-2",
    config=BotoConfig(read_timeout=300),
)
```

`us.` 前缀使用跨区域推理配置文件，以获得更高可用性。你也可以直接使用基础模型 ID。

### 步骤 2：创建浏览器 toolkit

每个竞品都有自己的 BrowserToolkit，它会预置各自的 AgentCore Browser MicroVM。并行的研究者之间因此完全隔离。当 LLM 在单轮中发出多个浏览器工具调用时，toolkit 会处理并发：

```
COMPETITORS = [
    ("GitHub", "https://github.com/pricing"),
    ("GitLab", "https://about.gitlab.com/pricing"),
    ("Bitbucket", "https://www.atlassian.com/software/bitbucket/pricing"),
]
 
toolkits_to_cleanup = []
research_subagents = []
 
for company_name, company_url in COMPETITORS:
    browser_toolkit, browser_tools = create_browser_toolkit(region="us-west-2")
    browser_toolkit.session_manager.session_wait_timeout = 60.0
    toolkits_to_cleanup.append(browser_toolkit)
 
    research_subagents.append({
        "name": f"research-{company_name.lower()}",
        "description": f"Researches {company_name} by browsing {company_url}.",
        "system_prompt": RESEARCHER_PROMPT,
        "tools": browser_tools,
    })
```

每个 MicroVM 都运行一个真实的 Chromium 浏览器，通过 Playwright（一个开源的浏览器自动化库）基于 WebSocket 连接。会话是临时的，几秒内即可启动。session_wait_timeout 被设为 60 秒（默认 10 秒），以便在多个工具调用并发运行时给浏览器操作留出足够的完成时间。浏览器工具包括 `navigate_browser`、`extract_text`、`click_element`、`type_text`、`scroll_page`、`extract_hyperlinks` 和 `wait_for_element`。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/29/ML-20818-2.png)

**图 2：** 三个不同的 MicroVM 会话 ID 确认每个研究 subagent 都在各自隔离的 Amazon Bedrock AgentCore Browser 环境中运行。

### 步骤 3：创建解释器 toolkit

analyst subagent 使用 AgentCore Code Interpreter，这是一个隔离的 MicroVM，运行着预装 pandas、matplotlib 和 numpy 的完整 Python 环境：

```
ci_toolkit, ci_tools = await create_code_interpreter_toolkit(region="us-west-2")
toolkits_to_cleanup.append(ci_toolkit)
 
analyst_subagent = {
    "name": "data-analyst",
    "description": "Analyzes competitor data, generates charts and reports.",
    "system_prompt": ANALYST_PROMPT,
    "tools": ci_tools,
}
```

解释器工具包括 `execute_code`、`execute_command`、`write_files`、`read_files`、`list_files`、`upload_file` 和 `install_packages`。需要额外的库？用 `install_packages` 工具在运行时安装。

### 步骤 4：加入跨会话记忆（可选）

coordinator agent 可以借助直接与长期记忆 API 交互的 AgentCore Memory 工具，随时间累积专业经验：

```
from bedrock_agentcore.memory import MemoryClient
from langchain_core.tools import tool
 
memory_client = MemoryClient(region_name="us-west-2")
 
@tool
def save_research_insights(insights: str, session_id: str = "default") -> str:
    """Save competitive research insights to AgentCore long-term memory."""
    memory_client.create_event(
        memory_id=memory_id, actor_id=actor_id, session_id=session_id,
        messages=[
            (f"Save these research insights:\n\n{insights}", "USER"),
            ("Insights saved to long-term memory.", "ASSISTANT"),
        ],
    )
    return "Insights saved and are extracted into long-term memory."
```

**重要：** 你的 AgentCore Memory 资源必须配置至少一种抽取策略（例如 semanticMemoryStrategy），长期召回才能生效。没有策略时，create_event 只存储原始事件，不会抽取任何可供检索的洞察。

当 agent 保存洞察时，AgentCore Memory 中配置的策略会在后台自动抽取结构化知识。在后续运行中，agent 使用 recall_past_research 搜索这些已抽取的知识。它无需从头重新研究，就能找到相关事实与过往发现。

### 步骤 5：创建并运行 agent

把各组件串起来并调用 agent：

```
agent = create_deep_agent(
    model=model,
    subagents=[*research_subagents, analyst_subagent],
    tools=memory_tools,
    system_prompt=COORDINATOR_PROMPT,
    name="competitive-research-coordinator",
    checkpointer=None,  # Simplification; use AgentCoreMemorySaver for session resumability
    store=InMemoryStore(),  # Internal storage for Deep Agents (separate from AgentCore Memory)
)
 
result = await agent.ainvoke(
    {"messages": [{"role": "user", "content": "Compare pricing for GitHub, GitLab, and Bitbucket"}]},
    config={"configurable": {"thread_id": "session-1", "actor_id": "research-agent"}},
)
```

带进度指示器和会话展示的可运行 notebook 见[随附 notebook](https://github.com/langchain-ai/langchain-aws/blob/main/samples/agents/competitive_research_agent.ipynb)。使用 Claude Sonnet 时的预期运行时间是 4–6 分钟，这反映了在三个站点上真实浏览所需的时间。同样的研究若串行处理，耗时会最多增加 3 倍。

## 追踪与调试 agent

[AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html) 通过 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 让你看清这一多 agent 架构。AgentCore 以 OpenTelemetry（OTEL）格式发出 traces 与 spans，因此你可以在 CloudWatch 的 GenAI Observability 页面上查看完整的编排层级：顶层是 coordinator 的运行，每个研究 subagent 各有一个子 span，随后是 analyst subagent。在每个 span 内，你可以查看工具调用及其输入、输出、耗时和 token 用量，从实际耗时确认研究 subagent 是并发执行的，并在某次浏览器导航或代码运行未成功时，定位到是哪个 subagent 的哪次工具调用出了问题。作为每个账户的一次性设置，你需要在 traces 与 spans 可用之前[启用 CloudWatch Transaction Search](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-get-started.html#enabling-transaction-search)。当你把 agent 托管在 AgentCore Runtime 上时（第 2 部分），运行时会自动用 OTEL 为你的 agent 插桩，因此无需额外配置。要在运行时之外运行同一个 agent，请为 agent 加入 AWS Distro for OpenTelemetry（ADOT）SDK 和 LangChain 插桩库。更多信息请参阅 [Amazon Bedrock AgentCore Observability 文档。](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability-get-started.html)

你还可以用 Amazon Bedrock AgentCore Evaluations 为这些 traces 的质量打分，它提供目标达成率、工具选择准确率等内置评估器。更多细节请参阅 [AgentCore Evaluations 文档](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/evaluations.html)。

如果你更愿意，也可以用 [LangSmith](https://docs.langchain.com/langsmith/home) 做追踪。借助 LangSmith，你可以获得端到端追踪，帮助调试这一多 agent 架构。设置三个环境变量即可开启自动追踪：

```
export LANGCHAIN_TRACING_V2=true
export LANGCHAIN_API_KEY="your-langsmith-api-key"
export LANGCHAIN_PROJECT="competitive-research-agent"
```

随附的 notebook 中也讲解了这一选项。

## 为什么这个架构重要

现在你已看到各组件如何组合在一起，下面说明这个模式为何有价值。

第一，coordinator 始终专注于高层推理。每个研究 subagent 在内部处理多步浏览，只返回精简摘要，从而让 coordinator 的上下文留给综合归纳，而不是被原始页面内容填满。

第二，各项能力之间有清晰的分离。每类 subagent 只能访问自己的工具，这降低了误用工具的可能性，也让调试更有针对性。

第三，研究跑得更快。三个浏览器研究任务并发运行，各自在自己的 AgentCore MicroVM 中，与串行处理相比减少了实际耗时。

最后，Amazon Bedrock AgentCore 与模型无关，也与框架无关。无论由哪个模型来编排，AgentCore 的工具（Browser、Interpreter、Memory）都以相同方式工作。换模型只需改一行代码：

```
# Default: Amazon Bedrock
from langchain_aws import ChatBedrockConverse
model = ChatBedrockConverse(model="us.anthropic.claude-sonnet-4-6", region_name="us-west-2")
```

## 把 agent 托管到 AgentCore Runtime

你构建的 agent 运行在 notebook 中，这对开发来说很合适。要把它迁移到具备按会话隔离和稳定调用 ARN 的受管端点，你可以把它托管在 [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 上。AgentCore Runtime 把 agent 托管在 ARM64 容器中，并让每个会话在专用 microVM 中运行，最长可达 8 小时。由于它与框架无关，你的 Deep Agents coordinator、并行的浏览器 subagent 以及 analyst subagent 都无需改动即可运行。

[AgentCore CLI](https://github.com/aws/agentcore-cli/tree/main) 用四个步骤完成部署工作流：用 `agentcore create` 搭建项目骨架，把 agent 代码填入模板，用 `agentcore deploy` 部署，用 `agentcore invoke` 调用。部署之后，你可以用 agentcore logs 流式查看日志，用 `agentcore traces` 检查 traces。完工后，先执行 agentcore remove all，再执行 agentcore deploy，即可拆除所有已预置的资源。

notebook 的第 2 部分会带你走查其中每一步，包括前提条件与 IAM 权限。

## 清理

为避免产生费用，请清理你创建的 AgentCore 资源：

```
# Clean up browser sessions
for toolkit in browser_toolkits:
    await toolkit.cleanup()

# Clean up interpreter session
await ci_toolkit.cleanup()
```

浏览器会话在 1 小时后自动过期。解释器会话在 15 分钟后自动过期。随附的 notebook 包含会自动运行的清理代码。如果你创建了 AgentCore Memory 资源且不再需要，可以通过 Amazon Bedrock AgentCore 控制台或 API 删除它。

## 结论与后续步骤

在本文中，你构建了一个研究 agent，它用 LangChain Deep Agents 做编排，用 Amazon Bedrock AgentCore 提供隔离的浏览器自动化、代码解释和持久记忆。你用 [AgentCore CLI](https://github.com/aws/agentcore-cli/tree/main) 把该 agent 部署到 AgentCore Runtime，使其作为受管服务运行，具备按会话隔离、稳定端点与内置可观测性。这种并行取数、专业处理、最后综合的模式，适用于竞品研究之外的许多工作流：

- **尽职调查：** 让 subagent 研究目标公司的财务申报文件、新闻稿和监管文档。例如，把竞品 URL 换成 SEC EDGAR 的申报页面，就能以最小的改动复用同一套浏览器 subagent 模式。

- **内容创作：** 用研究 subagent 收集素材，同时由写作 subagent 起草各章节

- **数据 pipeline 编排：** 让 subagent 从不同来源抽取数据，再把合并后的结果传给 analyst subagent 做 join 与转换
