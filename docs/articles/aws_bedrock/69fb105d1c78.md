# Guidesly 如何在 AWS 上为户外向导构建 AI 生成的行程报告

*本文是由 Guidesly 的 David Lord、Taylor Lord、Shiva Prasad、Anup Banasavalli Hiriyanagowda、Nikhil Chandra 撰写的客座文章。*

[Guidesly 正在重塑户外休闲的预订、组织与体验方式。](https://guidesly.com/)它成立于 2019 年，最初是为了把垂钓者、猎人、潜水员和户外休闲爱好者与可信赖的向导、潜水店和包船服务连接起来。此后它成长为服务整个行业的垂直领域 AI software as a service（SaaS）系统。借助 Guidesly Pro，户外专业人士获得了一套业务解决方案，可支撑其运营的各个环节——预订、支付、网站、客户管理和营销——全部来自同一个系统。

对许多向导来说，最棘手的挑战是如何被客户发现、在网上的噪声中脱颖而出。即便知道该做什么，他们每天也可能要花上八个小时更新网站、在社交媒体发帖、运营电子邮件营销活动。若无法在这些渠道上持续执行，曝光度就会下降，小型经营者有可能落后于拥有完整营销团队的竞争对手——这些错失的机会会直接影响增长与订单。

为应对这个问题，Jack AI 诞生了。从一开始，Guidesly 就把 AI 视为不只是工具，而是一种连接向导日常面对的各个孤岛的方式——把预订、数据、内容、客户互动和营销统一成一条智能流程。这一愿景超越了自动化。它的目标在于打造一个真正的伙伴，与向导并肩工作，默默承担他们没有时间处理的繁重事务。

与需要持续 prompt 和监督的通用 AI 工具不同，Jack AI 自行在后台工作。它在每次行程结束后自动激活，把原始数据、照片和视频转化为可发布到网站、社交媒体和电子邮件的成品内容。它在 AWS 上以无服务器方式运行，可自动伸缩，从而快速交付一致的内容，让向导专注于自己的行程，而不是行政事务。

在本文中，我们将介绍 Jack AI 如何在 AWS 上构建以支撑这种端到端自动化。我们会探讨 AWS Lambda、AWS Step Functions、Amazon Simple Storage Service（Amazon S3）、Amazon Relational Database Service（Amazon RDS）、Amazon SageMaker AI 和 Amazon Bedrock 等服务如何协同工作：接收行程媒体、为其补充上下文、应用计算机视觉与生成式 AI，并把可直接用于营销的内容发布到多个渠道——安全、可靠且可扩展。

## **挑战：让向导从营销运营中解放出来**

对户外向导而言，真正的目标是交付令人难忘的体验，但创作有吸引力的内容仍是一项关键且耗时的任务。每次行程都会产生数十张照片和故事，而把它们变成有说服力的营销内容却是个挑战：

- **识别鱼种与行程细节** – 向导会拍下无数照片，但手动标注鱼种、尺寸、技法和地点极为繁琐。细节缺失会让帖子信息量不足，对潜在客户的吸引力也降低。
- **抓住恰当的语气** – 每位向导都有独特的风格，它由本地行话、个人叙事方式以及多年在水上或野外的经验塑造而成。要写出既真实又不会显得泛泛或错位的内容，几乎无法规模化。
- **跟上 SEO** – 即便是专业营销人员，持续产出富含关键词、针对本地优化的内容也很有挑战。对忙碌的向导来说，错失 SEO 机会意味着更低的可发现性和更少的订单。
- **管理多个渠道** – 行程报告页面、博客、Instagram 配文、Facebook 帖子和电子邮件简报都需要关注。手动更新这些资源意味着每周数小时的写作、编辑与排版。
- **牺牲水上的时间** – 在笔记本电脑前花的每一小时，都是从带队服务客户中抽走的一小时。对小型企业而言，这种取舍同时影响收入与客户体验。

即便向导们已经竭尽全力，人工流程的准确度和速度仍不足以跟上客户需求、现代营销需要，以及通过电子邮件与客户保持联系这一关键需求。这正是 **Guidesly 的 Jack AI** 出手的地方——它自动化内容创作、SEO 优化、电子邮件营销和多渠道分发，让向导专注于他们热爱的事：交付令人难忘的户外体验。

## **方案概览：Jack AI**

为了实现 Jack AI，Guidesly 在 AWS 上实施了一套全自动、无服务器、AI 驱动的营销工作流，旨在把原始行程数据转化为可发布的内容。该系统让向导可以专注于交付卓越的户外体验，同时在网站、社交媒体和电子邮件营销中保持一致、真实的数字形象。

### **行程媒体接收 – Amazon API Gateway：**

- **自动触发：**向导上传的行程照片和视频通过 **Amazon API Gateway** 进入系统，并立即触发编排 pipeline。
- **及时交付内容：**媒体一上传就被处理，使社交帖子和电子邮件营销能在行程还让人记忆犹新时触达受众。

### **Pipeline 编排 **

**AWS Step Functions** 管理工作流，为每个阶段调用 **AWS Lambda** 函数——从数据提取和鱼类检测，到媒体改进、内容生成和发布。

- **媒体数据提取**  **自动采集元数据：**向导一上传照片和视频，系统就提取其中嵌入的 EXIF Metadata，包括 GPS 坐标、时间戳和设备设置。**上下文增强：**提取出的地理空间信息随后与同一时间、同一地点的天气与水文条件数据结合。这样就能捕捉潮位、水温、风速和云量等细节——这些上下文否则就会丢失。**更丰富的叙事：**通过把每次行程锚定在真实的环境条件与收获之上，系统产出的内容更个性化、更真实、也更有吸引力，而无需向导额外付出。**可扩展的一致性：**无论处理一张图片还是数百张，自动化都能确保每份媒体素材都被高质量上下文数据增强，为下游流程提供可靠输入。
- **使用计算机视觉进行鱼种检测**

鱼种识别是 Jack AI 系统的核心能力之一。挑战不仅在于在真实场景的图片中检测到鱼，还在于在船只、码头、湖泊和近海等高度多变的环境中准确分类数百个物种。

为此，我们设计了一套**多层计算机视觉 pipeline**，把自定义训练的计算机视觉模型与通过 **AWS **服务提供的 foundation vision models 结合起来。

### **实验与模型开发**

我们的模型开发工作流主要在 **Amazon SageMaker AI** 内运行，并使用 **JupyterLab** 作为实验环境。

借助这套设置，我们可以：

- 快速为新计算机视觉架构做原型
- 在 GPU 实例上运行大规模训练作业
- 在多个鱼类分类基准上评估模型
- 在模型改进与生产部署之间快速迭代

SageMaker AI 环境充当中心枢纽，数据集、训练脚本和模型实验都在其中管理。

### **数据集与训练挑战**

由于物种数量庞大且数据分布不均，鱼类识别带来了独特的 machine learning（ML）挑战。我们的系统目前支持 400 多个鱼种类别，数据来自以下来源的组合：

- Guidesly 系统内的专有钓鱼报告图像
- 用户提交的渔获照片
- 从合作伙伴来源收集的精选数据集

虽然一些常见物种有数千个训练样本，但许多物种的标注图像有限，这让传统的监督学习方法难以奏效。

为应对这种不平衡，我们采用混合训练策略：

- 对拥有大规模数据集的物种使用标准监督学习
- 对训练数据有限的稀有物种使用 one-shot 与 few-shot 学习技术

这使系统能够扩展分类覆盖范围，而无需为每个物种都准备大规模数据集。

## **多层视觉 pipeline**

我们没有依赖单一模型，而是实现了一个两阶段视觉架构，把目标检测与物种分类分开。

### **检测层**

第一阶段使用基于 YOLO 的目标检测模型，它们经训练可识别钓鱼图像中的相关对象，包括：

- 鱼
- 钓具
- 人物
- 船只及环境背景

检测模型会为每个对象标出边界框（bounding box）。我们没有把整张图传给下一阶段，而是只裁剪出检测到的鱼所在区域。这种做法显著提升了分类准确度，因为它去除了可能干扰分类模型的无关背景元素。

### **分类层**

随后，每张裁剪出的鱼类图像被送入专门的分类模型。在开发过程中，我们试验了多种架构，包括：

- 卷积神经网络（Convolutional neural networks，CNNs）
- 基于 ResNet 的模型，用于获得强劲的基线分类效果
- 面向长尾物种识别的 one-shot 与 few-shot 模型

这些架构的组合让我们能在数百个物种类别上平衡准确度、推理速度与训练效率。

## **混合视觉 + foundation model 方法**

除了自定义训练的模型，我们还集成了通过 **Amazon Bedrock** 提供的多模态 foundation models（基础模型，FMs），以提供额外的推理与上下文理解能力。

不过，原始视觉模型有时会产生幻觉或误读视觉场景。为降低这一风险，我们在把图像发送给 foundation models 之前会做几步预处理：

- **图像预处理**  裁剪出检测到的鱼类区域 归一化图像尺寸 去除不必要的背景
- **上下文增强**  媒体元数据（地点、水域、时间） 已知物种分布 检测模型输出
- **结构化 system prompt**  向模型提供关于图像的上下文信息 限制可能的物种预测范围

借助这种混合方法，我们可以把领域专用分类器的精确度与大型视觉模型的推理能力结合起来。

## **从研究到生产**

模型验证通过后，我们使用 Amazon SageMaker AI 上的托管端点进行部署。这带来：

- 对上传图像进行实时推理
- 针对大量媒体自动伸缩
- 持续监控与模型更新

结果是得到了一个可扩展的视觉系统，能够在 Guidesly 的系统中处理数千张钓鱼图像，即便在复杂的真实环境下也能提供可靠的鱼种检测。

- **媒体改进，实现更快的 Web 就绪发布**

鱼类检测和上下文增强完成后，Jack AI 专注于为实际发布准备媒体。向导上传的高分辨率照片和视频会被自动处理成经过优化、可直接用于 Web 的素材，适配网站、社交网络和电子邮件营销。这条改进 pipeline 在后台完成压缩、缩放和格式转换，确保媒体文件在保持视觉质量的同时保持轻量。通过在工作流早期就统一素材规格，Jack AI 免去了手动修图的需要，并在不同设备和系统之间保持一致呈现。

改进后的媒体以带版本号的产物形式存储在 Amazon S3 存储桶中，并打上标签，便于直接检索与复用。这些素材可以反复用于 SEO 页面、行程报告、简报和社交帖子，而无需重新处理，让发布 pipeline 保持快速高效。除了性能之外，这一步也支持 SEO 目标——快速加载的图像能提升搜索排名、改善用户体验，并降低向导网站的跳出率。

- **语气改进**

为确保生成的行程报告感觉真实、与钓鱼向导的自然语气相符，我们在内容生成 pipeline 中引入了 *Tone Improvement layer*。系统不通过微调改动底层语言模型，而是借助上下文输入和结构化 prompt 来改进语气。这样既保留了向导独特的叙事风格，又维持了可扩展性与运维上的简洁。

这种方法的基础是上下文注入。结构化的行程元数据被直接嵌入模型 prompt，为模型提供生成准确、相关叙述所需的有据可依的上下文。与此同时，历史行程报告和向导特有的措辞模式会被检索出来，作为参考示例一并加入。这有助于模型模仿向导记录行程时自然使用的词汇、节奏和描述风格。我们不训练自定义模型，而是用精心设计的 prompt 引导 foundation model 产出符合预期语气的输出。这样就能在不必承担维护微调模型的运维开销的前提下，动态调整写作风格。为避免编造细节，生成过程被严格限制在所提供的元数据和上下文输入范围内。模型被要求不得推断源数据中并不存在的缺失信息，例如额外的物种、技法、天气或地点，从而让每份报告都与实际的行程记录保持一致。

生成本身由 Amazon Bedrock FMs 执行，它们处理上下文输入和结构化 prompt，以规模化方式产出连贯、契合领域的报告。通过依赖上下文 prompt 而非重新训练模型，系统免去了训练基础设施、降低了运维开销，并能随着新向导报告和领域模式的出现快速迭代。这种方法达成了系统所需的平衡：以可靠、成本高效且可随系统扩展的方式，交付真实的向导风格行程报告。

## **发布 pipeline**

内容生成、改进并完成语气打磨之后，发布 pipeline 会把所有环节汇集起来，跨渠道交付可直接用于营销的素材。这一阶段被设计为以最少的人工投入端到端运行，确保向导掌握进展，而执行工作由后台的自动化完成。

素材生成由 *Assets Generation Step Function* 负责，它编排多次 AWS Lambda 运行。这些函数会基于每次行程存储在 S3 存储桶中的产物生成营销交付物，包括对 SEO 友好的行程报告、新鲜的网站内容、社交媒体帖子和个性化电子邮件营销。产出会自动存入系统并接入下游发布工作流，减少手动起草、撰写文案或排版的需要。素材准备好后，向导会收到推送通知以便审阅，从而在不增加不必要运维开销的情况下随时掌握情况。

处理后的产物——包括改进后的媒体、提取出的行程细节和生成的营销素材——通过 Amazon RDS 和 Amazon S3 集中存储。Amazon S3 为媒体和生成内容提供持久、成本高效的存储，而 Amazon RDS 则让结构化的行程和向导数据可供下游工作流与报表使用。这些服务共同确保素材可以立即在网站、社交渠道和电子邮件营销中复用，无需额外处理。

借助 AI 驱动的自动化，发布控制仍然保持灵活。向导可以审阅并批准生成的内容、要求进一步优化，或者依赖内置的自动发布开关实现全自动。有了这种灵活性，每位向导都能在质量控制与效率之间取得平衡——需要时亲力亲为，或选择*设置后无需过问*（set-and-forget）的方式。在后台，AWS Step Functions 编排多次 AWS Lambda 函数运行，自动伸缩以容纳数百位向导，且只需最少的基础设施管理。

## **成本考量**

尽管该架构被设计为自动伸缩，每份生成报告的相对成本仍然很小。在典型场景下，生成一份完整报告——包括媒体处理、计算机视觉推理和内容生成——约为每份 $0.10 到 $0.50。最终成本取决于所处理图像的数量、是否包含视频媒体以及 AI 推理请求量等因素。由于工作流是无服务器、事件驱动的，向导只在生成报告时产生费用，使其单位经济性随着用量增长保持可预测。

## **对户外休闲营销的影响**

Jack AI 在 AWS 上端到端运行，其影响不止于自动化，还深入到户外休闲营销的日常执行方式。通过把 AI 驱动的自动化与 AWS 服务结合，生成、优化和发布营销内容的整个过程被简化为一条可重复的工作流。户外休闲向导不再需要花数小时起草行程报告、调整图片格式或安排社交帖子发布。这些任务转而由系统自动处理，让向导得以专注于最重要的事：客户以及户外体验本身。

其结果是网站、社交媒体和电子邮件营销中形成一致且高质量的数字形象。向导得以提升曝光度、强化搜索排名、更有效地与客户互动，而无需配备专职营销人员。

## **成果**

自 Jack AI 在 AWS 上线以来，Guidesly 在户外向导社区中看到了快速的采用和可衡量的影响。通过把他们工作中最耗时的环节之一——营销——实现自动化，Jack AI 减少了每次行程后所需的运营投入，同时帮助向导在网上保持曝光度与竞争力。

此前，向导们每周常常要在笔记本电脑前花六个多小时撰写行程报告、排版博客文章、创作社交媒体配文，并尝试改善内容的搜索表现。在 AWS 上运行 Jack AI 之后，这些工作中的大部分现在都由自动化处理。向导上传的行程照片和简短笔记会被转换成一套完整的营销就绪素材，包括行程报告、富含 SEO 的网站内容、社交配文和电子邮件更新，在几分钟内而非数小时内产出。

Jack AI 的采用量稳步攀升，从 2025 年初的略多于 100 份报告增长到 2025 年 7 月的近 340 份。这一增长反映了我们的向导以及户外行业更广泛的转变：曾经对技术和数字营销犹豫不决的向导，如今正依靠 Jack AI 来建立并壮大线上影响力。
