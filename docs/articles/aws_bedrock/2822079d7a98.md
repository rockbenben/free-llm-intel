# 在 AWS 中以 Amazon Bedrock AgentCore 构建高度可扩展的无服务器 LangGraph 多 agent 系统

生成式 AI 已从实验性原型迅速演进为需要在生产环境中稳定运行、具备规模、并满足真实性能约束的系统。随着组织走出 demo 与概念验证阶段，它们越来越多地遇到与推理延迟、可扩展性、状态管理和运维可见性相关的挑战。如今构建高性能 AI agent 不只是要有强大的模型，还要求实现能够提供一致的性能、在多次交互中保留上下文，并对 agent 在生产中如何推理与行为提供深度可观测性。

本文将介绍一种方案：在 AWS 上使用 [LangGraph Agents](https://www.langchain.com/langgraph) 作为编排器，与 [Amazon Bedrock AgentCore Memory](https://aws.amazon.com/bedrock/agentcore/) 和 [Amazon Bedrock AgentCore Observability](https://aws.amazon.com/bedrock/agentcore/) 集成，构建高度可扩展的无服务器多 agent 生成式 AI 系统。

我们构建高度可扩展的无服务器多 agent 编排方案，结合了 [AWS Lambda](https://aws.amazon.com/lambda/) 与 [AWS Step Functions](https://aws.amazon.com/step-functions/) 这类无服务器技术。开发者可以用这些服务构建自动扩缩、实时响应事件、免去基础设施管理的 LangGraph agent。这使它们非常适合动态、突发性的 agent 工作负载。通过这些服务的组合，你可以编排复杂的多工具 agent 工作流，并拥有持久的状态管理、重试与细粒度的成本控制。

LangGraph 显式的基于图的执行模型支持确定性的协调、并行以及 agent 之间的条件路由，使复杂的多 agent 工作流更易推理与调试。通过把编排逻辑与 agent 行为分离，你可以用 LangGraph 独立地增加、移除或演进专用 agent，同时保持一条清晰、可审计的执行路径。这对需要可预测行为、可扩展性以及对多 agent 推理进行结构化控制的生产系统尤其有价值。

AgentCore Observability 通过为每次调用提供细粒度可见性来扩展这些能力，跨分布式无服务器组件捕获模型输入/输出、延迟与工具链指标。AgentCore Memory 集成的记忆服务使 agent 能够跨会话保持短期对话上下文与长期知识。

## 方案概览

我们这套基于无服务器 LangGraph 与 AgentCore 的多 agent 编排系统方案，是一个由生成式 AI 驱动的多 agent 营销活动评审系统：它使用多样化的人设编排人工评审，使营销活动既能真实地打动目标受众，又能保持法律合规与品牌标准。系统由三个专用 AI agent 并行分析营销活动——人设评审 agent 从多样化的人口统计视角评审内容并给出共鸣度评分；校验 agent 核实法律合规性与品牌指南的遵循情况；最后由定稿 agent 将反馈综合为可执行的建议。用户通过 [React](https://react.dev/) 前端上传活动文档，该前端同时轮询结果，并在评审产出后即时展示。

我们用 LangGraph 把系统建模为有状态的执行图，从而实现编排器与专用 agent。每个节点代表一个独立的 agent 功能，具体分别是人设评审、合规校验与反馈综合；边则定义这些步骤之间的控制流。编排器实现为负责路由执行的监督图，为专用 agent 触发并行分支，并收集它们的输出做最终聚合。LangGraph 编排器与专用 agent 一起打包为一个 Docker 容器。

我们使用 AWS Lambda 作为 AWS 中的无服务器托管运行时，让 Strands agent 自动扩缩、实时响应事件并免去基础设施管理。我们的编排 agent 通过 [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 提供的 REST 接口对外呈现其功能。

我们的 Agent 实现使用 AgentCore Observability 为 agent 工作流中的每一步提供详细可视化，使开发者能够检查执行路径、审计中间输出并排查性能瓶颈。在 AgentCore Observability 中，我们在 Amazon CloudWatch 内提供对运营性能仪表板与遥测的实时可见性，覆盖 traces、会话数、延迟、持续时间、token 用量与错误率等关键指标。

我们在 Agent 实现中将 AgentCore Memory 用于两个关键场景，具体是多 agent 共享记忆，以便在相互独立的 agent 运行之间同时提供上下文与共享记忆，并支持多轮对话。你可以扩展这一实现，为 AI 助手提供自然语言界面，因为我们基于 AgentCore Memory 的实现内置支持存储对话状态与历史。下面的架构图展示了本方案的各个组件。

## 前置条件

完成以下前置条件：

- 确认 [Amazon Bedrock 中的模型访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)。本方案中我们使用 Amazon Bedrock 上的 Anthropic Claude 4.5 Sonnet。
- 安装 [AWS Command Line Interface](https://aws.amazon.com/cli)（AWS CLI）。
- 安装 [AWS SAM CLI v1.100.0+](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/install-sam-cli.html)
- 安装 [Docker v20.x+](https://docs.docker.com/engine/install/)。
- 安装 [Node.js v18.x+](https://nodejs.org/)
- 安装 [Docker v20.x+](https://docs.docker.com/get-docker/)
- 安装 [Python v3.11+](https://www.python.org/downloads/)

## 部署方案

你可以从我们的 [GitHub 仓库](https://github.com/aws-samples/sample-agentic-genai-agentcore/tree/main) 下载本方案。以下分步指引也完全按该 GitHub 仓库 README 中的说明列出，用于在你的 AWS 环境中部署并访问本方案：

第 1 步：克隆仓库
`git clone <respository url>`

`cd aws-genai-campaign-review-langgraph`

### 第 2 步：配置 AWS 凭证

*配置 AWS CLI：*

`aws configure`

*校验凭证：*

`aws sts get-caller-identity`

### 第 3 步：创建 Amazon DynamoDB persona 表

*让脚本可执行：*

`chmod +x scripts/setup_persona_table.sh`

*运行初始化脚本：*

`./scripts/setup_persona_table.sh`

### 第 4 步：构建 AWS SAM 应用

`sam build`

### 第 5 步：部署基础设施

*使用引导式部署，并按照提示提供你的 stack 名称、agent 名称、AWS region，其他部分接受默认值。*

`sam deploy --guided`

### 第 6 步：获取部署输出

*获取 API 端点：*

`aws cloudformation describe-stacks --stack-name <your stack name> --query 'Stacks[0].Outputs' --output table`

*保存这些值：*

- ApiEndpoint – API URL
- CampaignOrchestratorApi – Agent API URL
- CloudFrontURL – 前端 URL
- FrontendBucket – 用于前端的 S3 bucket

### 第 8 步：配置前端环境

*从 CloudFormation 输出中获取值：*

`API_URL=$(aws cloudformation describe-stacks --stack-name <your stack name> --query 'Stacks[0].Outputs[?OutputKey==`ApiEndpoint`].OutputValue' --output text)`

`AGENT_API_URL=$(aws cloudformation describe-stacks --stack-name <your stack name> -review --query 'Stacks[0].Outputs[?OutputKey==`CampaignOrchestratorApi`].OutputValue' --output text)`

*创建 .env 文件：*

`cat > .env << EOF`

`VITE_API_URL=$API_URL`

`VITE_AGENT_API_URL=$AGENT_API_URL`

`VITE_AWS_REGION= <your AWS region>`

`EOF`

### 第 9 步：构建并部署前端

*安装依赖：*

`npm install`

*构建前端：*

`npm run build`

*获取前端 bucket 名称：*

`FRONTEND_BUCKET= $(aws cloudformation describe-stacks --stack-name <your stack name> --query 'Stacks[0].Outputs[?OutputKey==`FrontendBucket`].OutputValue' --output text)`

*部署到 S3：*

```
aws s3 sync dist/ s3://$FRONTEND_BUCKET --delete
```

*失效 CloudFront 缓存（可选，用于更新）：*

`DISTRIBUTION_ID=$(aws cloudfront list-distributions --query "DistributionList.Items[?Origins.Items[0].DomainName=='${FRONTEND_BUCKET}.s3.us-west-2.amazonaws.com'].Id" --output text)`

`aws cloudfront create-invalidation --distribution-id $DISTRIBUTION_ID --paths "/*"`

### 第 10 步：访问应用

*获取 CloudFront URL：*

`aws cloudformation describe-stacks --stack-name <your stack name> --query 'Stacks[0].Outputs[?OutputKey==`CloudFrontURL`].OutputValue' --output text`

在浏览器中打开该 URL 即可访问应用。使用这个 [campaign_brief.md](https://github.com/aws-samples/sample-agentic-genai-agentcore/blob/main/aws-genai-campaign-review-strands-agentcore/campaign_brief.md) 文件作为示例活动文档，并在左侧面板上传。随后你就能在右侧面板看到多 agent 编排产出的活动评审结果。进入 [Bedrock AgentCore Observability 控制台](https://us-west-2.console.aws.amazon.com/cloudwatch/home?region=us-west-2#gen-ai-observability/agent-core?region=us-west-2) 并选择你的 agent，即可看到 agent 工作流中每一步的详细可视化，如下图所示

[![agentcore observability dashboard describing the spans, traces and sessions for the agent invocations](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/11/agentcoreobservability-langgraph-1024x547.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/11/agentcoreobservability-langgraph.png)

## 清理

为避免持续产生费用，试用完本方案后请清理你的账户。

- 删除 CloudFormation stack

`sam delete --stack-name <your stack name>`

- 删除 DynamoDB table

`aws dynamodb delete-table --table-name PersonaTable --region <your aws region>`

## 结论

在本文中，我们展示了如何结合 LangGraph、Amazon Bedrock AgentCore 与 AWS 无服务器服务，帮助团队构建高度可扩展、可直接用于生产的多 agent 生成式 AI 系统。通过使用 LangGraph 显式的基于图的执行模型做编排、以基于 AWS Lambda 的运行时负责执行，开发者可以协调复杂的并行 agent 工作流，同时拥有确定性的控制流、自动扩缩与极低的运维开销。集成的 AgentCore Memory 与 Observability 解决了真实 agent 部署中最常见的两大挑战——状态管理与可见性——办法是在多次 agent 运行之间提供共享且持久的上下文，并对 agent 的行为、性能与成本给出深度洞察。

这些能力共同构成在 AWS 上构建企业级 AI agent 的可复用架构模式。无论你是在实现活动评审系统、数字助手，还是其他多 agent 推理解题工作流，这种方式都能让你把编排与执行解耦、随需求弹性扩缩，并保持对 agent 如何推理与交互的完全透明。通过用 LangGraph 做结构化编排、用 Amazon Bedrock AgentCore 提供托管运行时、记忆与可观测性，你可以有把握地从实验性原型走向生产中可靠、可扩展的生成式 AI 系统。
