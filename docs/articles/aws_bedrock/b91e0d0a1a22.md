# 在 Amazon SageMaker HyperPod 中推出增强的基础设施可观测性

大规模模型训练是 GPU 上最昂贵的工作负载之一，只要一块加速器状态异常，就可能拖住整个分布式作业。训练吞吐下降时，最难的一步往往不是发现出了问题，而是弄清原因和位置。团队常常要花上数小时甚至数天翻查日志和彼此割裂的仪表盘，才能判断变慢究竟来自被节流的 GPU、被打满的网络链路，还是主机上停滞的数据管道。

今天我们宣布推出 Amazon SageMaker HyperPod 的增强可观测性，这项新能力可帮助您更快诊断 GPU 训练问题。它把诊断与性能分析能力集中到一处，覆盖运行在 Amazon Elastic Kubernetes Service（Amazon EKS）和 Slurm 编排器上的训练工作负载：

**诊断摘要**借助 Amazon CloudWatch 的 DetectGroupOutliers API，按利用率、内存、温度、功耗和 SM 时钟逐块比较训练作业中的 GPU，并标出偏离同组其他 GPU 的个体。静态诊断规则会揭示常见故障模式，例如 GPU 硬件故障（XID 错误、ECC 内存错误）、EFA 吞吐下降、热节流和过热，让您在性能退化波及训练之前就发现它。

## 为什么需要它

分布式训练开销高昂，一点点低效累积起来就是大量被浪费的 GPU 小时。在此之前，要看清 HyperPod 基础设施，只能把彼此独立的工具拼凑在一起；即便这样，指标也只告诉您性能已经下降，却说不清为什么。

增强可观测性弥补了三个缺口。无论是 XID 错误、ECC 内存故障还是热节流，它都能在数百甚至数千块 GPU 中定位出那一块不良的加速器，让您把时间花在修复上，而不是寻找上。

这些能力合在一起缩短了故障排查时间，也帮助您让昂贵的加速器保持忙碌。

## 工作原理

每项能力针对分布式训练作业的不同层面。

### 默认指标与高级指标

增强可观测性在两个层级采集遥测数据：

**默认指标**（自动启用）覆盖集群健康、CPU/磁盘/操作系统级使用情况、GPU 利用率与温度，以及按作业统计的资源利用率。这些指标每 30 秒采集一次，发送到您选定的指标存储，CPU 开销约为 1–2%，内存占用为 250–300 MB。

**高级指标**（需主动启用）提供更深的可见性：

- **完整 node exporter 套件：**全面的主机级指标。
- **全部 NVIDIA GPU DCGM 与 AWS Neuron 指标：**细粒度的加速器遥测，包括时钟频率、功耗、PCIe 活动和错误指示。
- **Elastic Fabric Adapter（EFA）指标：**网络接口的吞吐、丢包、重传和错误。

高级指标之所以可选，是因为它们会增加发往指标存储的遥测数据量，从而带来成本。多数在小集群上跑小作业的客户可能用不上，但对于大集群上长时间运行的训练作业，它们不可或缺——这类作业的规律要经过一段时间才会显现。

### 指标存储

指标存储有两种可选：

- **Amazon CloudWatch**（新的默认选项）通过 CloudWatch SageMaker Insights 提供原生监控，您无需离开 AWS Management Console 就能查看指标。
- **Amazon Managed Service for Prometheus**，适合已经把 Prometheus 和 Grafana 作为可观测性标准的团队。

此前只支持 Prometheus。现在 CloudWatch 成为默认选项，价格低于 Amazon Managed Service Prometheus，与 SageMaker 控制台的集成也更紧密。

### 诊断摘要

诊断摘要用两种互补的方式呈现 HyperPod 集群中的问题。

**GPU 异常检测**调用 CloudWatch 的 *DetectGroupOutliers* API，在同一个训练作业内按利用率、内存使用、温度、功耗和 SM 时钟频率比较各块 GPU。某块 GPU 明显偏离同组其他 GPU 时，会以异常卡片的形式出现在诊断摘要中。EKS 和 Slurm 作业都适用。

**静态诊断规则**评估已知故障模式，并按类型归类检出的问题：

- **硬件：**GPU ECC 内存错误、XID 故障、加速器失效。
- **网络：**EFA 吞吐下降、丢包、重传。
- **节流：**因散热、板卡或可靠性限制导致的 GPU 时钟降频。
- **过热：**GPU 温度超过配置的上限。

每个检出的问题都会标明受影响的作业、集群、节点、加速器和 rank。

## 如何开始使用

增强可观测性以附加组件的形式提供给 EKS 编排的集群，以扩展的形式提供给 Slurm 编排的集群，因此您可以通过 AWS Identity and Access Management（IAM）控制谁可以安装或改动它。

### 第 1 步：创建 SageMaker HyperPod 集群

如果已有集群，直接使用即可。要新建 SageMaker HyperPod 集群，可以参照[分步指引](https://awslabs.github.io/ai-on-sagemaker-hyperpod/)。大体步骤如下：

- 在 Amazon SageMaker AI 控制台的导航窗格中选择 **HyperPod clusters**。
- 选择 **Create HyperPod** 集群，再选择 **Orchestrated on Amazon EKS** 或 **Orchestrated by Slurm**。
- 在 **Setup options** 中选择 **Custom setup**。
- 在 **Name** 中填写名称。
- 在 **Instance recovery** 中选择 **Automatic**。
- 选择 **Submit**。

以下截图展示了 Create HyperPod cluster 页面。

![在 Amazon EKS 上选择 Custom setup 的 Create HyperPod cluster 页面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/18/ML-22438-1.png)

图 1：在 Amazon EKS 上以 Custom setup 创建 HyperPod 集群

### 第 2 步：配置 HyperPod 可观测性

在 **Custom setup** 工作流中展开 **HyperPod observability** 区域：

- **Enable HyperPod Observability** 默认勾选。只有在不需要可观测性时才取消勾选。
- **Observability metrics** 列出默认指标（集群健康、CPU/磁盘/操作系统、GPU 利用率/温度、按作业资源）以及可选的高级指标。
- 按需选择高级指标：完整 node exporter 套件、全部 NVIDIA GPU DCGM/Neuron 指标和 EFA 指标。
- 勾选 **Enable logging** 可为容器和 Pod 日志创建 CloudWatch 日志组。
- **Metric store** 选择 **Amazon CloudWatch**（默认）或 **Amazon Managed Service for Prometheus**。
- **Grafana workspace** 可选择新建工作区、使用现有工作区或选择 None。
- 配置 IAM 角色，或让控制台自动创建。

### 第 3 步：用 CLI 安装可观测性附加组件（替代方式，EKS）

HyperPod 可观测性附加组件（EKS）或扩展（Slurm）可以从 AWS Management Console 或通过 API 安装。也可以使用 AWS Command Line Interface（AWS CLI）安装该附加组件。

以下命令会创建附加组件，启用基本指标类别，并让需主动启用的性能分析能力保持关闭：

```
aws eks create-addon \
    --cluster-name <cluster-name> \
    --addon-name amazon-sagemaker-hyperpod-observability \
    --region <region> \
    --configuration-values '{
        "metricsDestination": "cloudwatch",
        "metricsProvider": {
            "nodeMetrics": {"level": "BASIC", "scrapeInterval": 30},
            "acceleratedComputeMetrics": {"level": "BASIC", "scrapeInterval": 30}
        },
        "profilesProvider": {
            "hostProfiling": {"enabled": false}
        }
    }'
```

验证附加组件处于 ACTIVE 状态：

```
aws eks describe-addon \
    --cluster-name <cluster-name> \
    --addon-name amazon-sagemaker-hyperpod-observability \
    --region <region> \
    --query 'addon.status'
```

下图展示了集群 Add-ons 选项卡上的可观测性附加组件。

![HyperPod EKS 集群的 Add-ons 选项卡，显示 Amazon SageMaker HyperPod 可观测性附加组件状态为 Active，指标存储为 Amazon CloudWatch](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/18/ML-22438-3.png)

图 3：集群 Add-ons 选项卡上的可观测性附加组件，处于活动状态并向 Amazon CloudWatch 发送指标

### 第 4 步：启用指标（EKS）

任何指标类别或性能分析能力都可以随时启用或停用。对 EKS 集群，用 AWS Command Line Interface（AWS CLI）更新附加组件配置。以下命令开启高级网络（EFA）指标：

```
aws eks update-addon \
    --cluster-name <cluster-name> \
    --addon-name amazon-sagemaker-hyperpod-observability \
    --region <region> \
    --configuration-values '{
        "metricsDestination": "cloudwatch",
        "metricsProvider": {
            "nodeMetrics": {"level": "BASIC", "scrapeInterval": 30},
            "acceleratedComputeMetrics": {"level": "BASIC", "scrapeInterval": 30},
            "networkMetrics": {"level": "ADVANCED", "scrapeInterval": 30}
        }
    }'
```

在控制台中，选择附加组件卡片上的 **Actions**，再选 **Edit**，也能做同样的改动。下图展示了 **Actions** 按钮。

![Observability add-on Actions menu with Edit, Update version, Delete, and View in EKS options](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/18/ML-22438-4-1.png)

图 4：使用 Actions → Edit 启用或停用指标类别与性能分析

### Slurm 集群：安装或编辑可观测性扩展

在 Slurm 编排的集群上，HyperPod 可观测性是一个集群**扩展**。在集群详情页打开 **Extensions** 选项卡。如果扩展已安装，选择 **Actions**，再选 **Edit**。下图展示了 Slurm 集群 **Extensions** 选项卡上的可观测性扩展。

![Slurm 集群 Extensions 选项卡，显示 HyperPod 可观测性扩展状态为 Active](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/18/ML-22438-5.png)

图 5：Slurm 集群 Extensions 选项卡上的可观测性扩展，以及 Actions → Edit

编辑页面会为每个指标类别设置采集级别。

![Slurm 集群的 Edit HyperPod observability 页面，显示带采集级别的指标类别、主机性能分析和指标存储](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/18/ML-22438-6-1.png)

图 6：在 Slurm 集群上编辑可观测性：指标类别、主机性能分析和指标存储

若要改用 AWS CLI 安装扩展：

```
aws sagemaker create-cluster-extension \
    --cluster-arn <cluster-arn> \
    --extension-name sagemaker-observability \
    --region <region> \
    --configuration-values '{
        "metricsProvider": {
            "clusterMetrics": {"level": "ENABLED", "collectionIntervalSeconds": 30},
            "nodeMetrics": {"level": "BASIC", "collectionIntervalSeconds": 30},
            "acceleratedComputeMetrics": {"level": "BASIC", "collectionIntervalSeconds": 30},
            "jobMetrics": {"level": "ENABLED", "collectionIntervalSeconds": 30}
        },
        "profilesProvider": {"hostProfiling": {"enabled": false}}
    }'
```

要开启 EFA 指标，更新扩展：

```
aws sagemaker update-cluster-extension \
    --cluster-arn <cluster-arn> \
    --extension-arn <extension-arn> \
    --region <region> \
    --configuration-values '{
        "metricsProvider": {
            "clusterMetrics": {"level": "ENABLED", "collectionIntervalSeconds": 30},
            "nodeMetrics": {"level": "ADVANCED", "collectionIntervalSeconds": 30},
            "acceleratedComputeMetrics": {"level": "ADVANCED", "collectionIntervalSeconds": 30},
            "networkMetrics": {"level": "ENABLED", "collectionIntervalSeconds": 30},
            "jobMetrics": {"level": "ENABLED", "collectionIntervalSeconds": 30}
        }
    }'
```

用 `aws sagemaker describe-cluster-extension --cluster-arn <cluster-arn> --extension-arn <extension-arn>` 查看状态。

### 第 5 步：确认指标正在流转

集群就绪后，进入集群详情页。新增的 **Observability** 选项卡会显示概览，包括：

- **Nodes：**节点总数（例如 128）。
- **Accelerators：**GPU/加速器总数（例如 1024）。
- **Jobs：**活动中和近期的训练作业数。
- **Avg. GPU utilization：**集群范围平均值（例如 87.3%）。
- **Avg. vCPU utilization：**集群范围平均值（例如 76.8%）。
- **Avg. memory utilization：**集群范围平均值（例如 83.5%）。

## Amazon Managed Grafana 仪表板

在集群 Observability 选项卡或 Add-ons 页面选择 **Open dashboard in Grafana**，即可打开预置的 Amazon Managed Grafana 仪表板。这些仪表板让您对 HyperPod 集群获得全栈可见性，来自 CloudWatch 或 Prometheus 的遥测数据会按集群、节点、GPU、网络和作业维度呈现。

**注意：**首次使用 Grafana 时，必须先配置 AWS IAM Identity Center 并添加 Grafana 用户。在集群创建过程中选择 Grafana 指标存储选项时，会提供相关文档链接。
