# 在 Amazon SageMaker HyperPod 中推出增强的基础设施可观测性

大规模模型训练是可在 GPU 上运行的最昂贵工作负载之一，而单个不健康的加速器就可能拖住整个分布式作业。当训练吞吐量下降时，难点通常不在于注意到出了问题，而在于弄清楚原因和位置。团队常常花费数小时或数天翻查日志和彼此割裂的仪表盘，以判断变慢是源于被节流的 GPU、饱和的网络链路，还是主机上停滞的数据管道。

今天，我们宣布 Amazon SageMaker HyperPod 中的增强可观测性，这是一项新能力，可帮助您更快诊断 GPU 训练问题。它汇集了面向运行在 Amazon Elastic Kubernetes Service（Amazon EKS）和 Slurm 编排器上的训练工作负载的诊断与性能分析能力：

**诊断摘要**使用 Amazon CloudWatch 的 DetectGroupOutliers API，按利用率、内存、温度、功耗和 SM 时钟比较训练作业中的每个 GPU，并标记出偏离同组其他 GPU 的 GPU。静态诊断规则会揭示常见故障模式，例如 GPU 硬件故障（XID 错误、ECC 内存错误）、EFA 吞吐量下降、热节流和过热，让您在性能退化影响训练之前及时发现。

## 为什么需要它

分布式训练成本高昂，微小的低效会累积成大量被浪费的 GPU 小时。到目前为止，要获得对 HyperPod 基础设施的可观测性，意味着要把彼此独立的工具拼接起来，而且即便如此，指标也只能告诉您性能已经下降，却无法说明原因。

增强可观测性弥补了三个缺口。它能在数百或数千个 GPU 中隔离出单个有问题的加速器——无论是通过 XID 错误、ECC 内存故障还是热节流发现——让您把时间花在修复上，而不是查找上。

这些能力共同缩短故障排查时间，并帮助您让昂贵的加速器保持忙碌。

## 工作原理

每项能力针对分布式训练作业的不同层面。

### 默认指标和高级指标

增强可观测性在两个层级收集遥测数据：

**默认指标**（自动启用）涵盖集群健康、CPU/磁盘/操作系统级使用率、GPU 利用率和温度，以及每个作业的资源利用率。这些指标每 30 秒收集一次，并发送到您选择的指标存储，CPU 开销约为 1–2%，内存占用为 250–300 MB。

**高级指标**（选择性启用）提供更深入的可见性：

- **完整 node exporter 套件：**全面的主机级指标。
- **所有 NVIDIA GPU DCGM 和 AWS Neuron 指标：**详细的加速器遥测数据，包括时钟速度、功耗、PCIe 活动和错误指标。
- **Elastic Fabric Adapter（EFA）指标：**网络接口吞吐量、丢包、重传和错误。

高级指标是可选的，因为它们会增加发送到指标存储的遥测数据量，从而带来成本影响。大多数在小集群上运行小作业的客户可能不需要它们，但对于大型集群上长时间运行的训练作业来说，它们是必不可少的，因为模式会随着时间推移而显现。

### 指标存储

您可以在两种指标存储之间选择：

- **Amazon CloudWatch**（新的默认选项）通过 CloudWatch SageMaker Insights 提供原生监控，因此您无需离开 AWS Management Console 即可可视化指标。
- **Amazon Managed Service for Prometheus**，适合将 Prometheus 和 Grafana 标准化用于可观测性的团队。

此前仅支持 Prometheus。CloudWatch 现在是默认选项，与 Amazon Managed Service Prometheus 相比价格更低，并且与 SageMaker 控制台集成更紧密。

### 诊断摘要

诊断摘要使用两种互补方法来揭示 HyperPod 集群中的问题。

**GPU 异常值检测**使用 CloudWatch 的 *DetectGroupOutliers* API，在训练作业内按利用率、内存使用量、温度、功耗和 SM 时钟频率比较 GPU。当某个 GPU 显著偏离同组其他 GPU 时，它会作为异常值卡片出现在诊断摘要中。这适用于 EKS 和 Slurm 作业。

**静态诊断规则**评估已知故障模式，并按类型组织检测到的问题：

- **硬件：**GPU ECC 内存错误、XID 故障、加速器故障。
- **网络：**EFA 吞吐量下降、丢包、重传。
- **节流：**因热量、板卡或可靠性限制导致的 GPU 时钟节流。
- **过热：**GPU 温度超过配置的限制。

每个检测到的问题都会标明受影响的作业、集群、节点、加速器和 rank。

## 如何开始使用

增强可观测性以附加组件形式提供给由 EKS 编排的集群，并以扩展形式提供给由 Slurm 编排的集群，这意味着您可以通过 AWS Identity and Access Management（IAM）控制谁可以安装或更改它。

### 第 1 步：创建 SageMaker HyperPod 集群

如果您已经有集群，可以直接使用。要创建新的 SageMaker HyperPod 集群，可以按照[分步概要](https://awslabs.github.io/ai-on-sagemaker-hyperpod/)操作。一般来说，步骤如下：

- 在 Amazon SageMaker AI 控制台的导航窗格中，选择 **HyperPod clusters**。
- 选择 **Create HyperPod** 集群，并选择 **Orchestrated on Amazon EKS** 或 **Orchestrated by Slurm**。
- 在 **Setup options** 中，选择 **Custom setup**。
- 在 **Name** 中，输入名称。
- 在 **Instance recovery** 中，选择 **Automatic**。
- 选择 **Submit**。

以下截图显示了 Create HyperPod cluster 页面。

![在 Amazon EKS 上选择 Custom setup 的 Create HyperPod cluster 页面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/18/ML-22438-1.png)

图 1：在 Amazon EKS 上使用 Custom setup 创建 HyperPod 集群

### 第 2 步：配置 HyperPod 可观测性

在 **Custom setup** 工作流中，展开 **HyperPod observability** 部分：

- **Enable HyperPod Observability** 默认已勾选。仅在不需要可观测性时取消勾选。
- **Observability metrics** 显示默认指标（集群健康、CPU/磁盘/操作系统、GPU 利用率/温度、每作业资源）以及可选的高级指标。
- 根据需要选择高级指标：完整 node exporter 套件、所有 NVIDIA GPU DCGM/Neuron 指标和 EFA 指标。
- **Enable logging** 用于为容器和 Pod 日志创建 CloudWatch 日志组。
- 对于 **Metric store**，选择 **Amazon CloudWatch**（默认）或 **Amazon Managed Service for Prometheus**。
- 对于 **Grafana workspace**，选择创建新工作区、使用现有工作区或选择 None。
- 配置 IAM 角色，或让控制台自动创建它们。

### 第 3 步：使用 CLI 安装可观测性附加组件（替代方式，EKS）

您可以从 AWS Management Console 或通过 API 安装 HyperPod 可观测性附加组件（EKS）或扩展（Slurm）。或者，您可以使用 AWS Command Line Interface（AWS CLI）安装该附加组件。

以下命令创建附加组件，启用基本指标类别，并保持选择性启用的性能分析能力为关闭状态：

```
aws eks create-addon \
    --cluster-name <cluster-name> \
    --addon-name amazon-sagemaker-hyperpod-observability \
    --region <region> \
    --configuration-values '{
        "metricsDestination": "cloudwatch",
        "metricsProvider": {
            "nodeMetrics": {"level": "BASIC", "scrapeInterval": 30},
            "acceleratedComputeMetrics": {"level": "BASIC", "scrapeInterval": 30}
        },
        "profilesProvider": {
            "hostProfiling": {"enabled": false}
        }
    }'
```

验证附加组件处于 ACTIVE 状态：

```
aws eks describe-addon \
    --cluster-name <cluster-name> \
    --addon-name amazon-sagemaker-hyperpod-observability \
    --region <region> \
    --query 'addon.status'
```

图 3：集群 Add-ons 选项卡上的可观测性附加组件，处于活动状态并向 Amazon CloudWatch 发送指标

### 第 4 步：启用指标（EKS）

您可以随时启用或禁用任何指标类别或性能分析能力。对于 EKS 集群，请使用 AWS Command Line Interface（AWS CLI）更新附加组件配置。以下命令开启高级网络（EFA）指标：

```
aws eks update-addon \
    --cluster-name <cluster-name> \
    --addon-name amazon-sagemaker-hyperpod-observability \
    --region <region> \
    --configuration-values '{
        "metricsDestination": "cloudwatch",
        "metricsProvider": {
            "nodeMetrics": {"level": "BASIC", "scrapeInterval": 30},
            "acceleratedComputeMetrics": {"level": "BASIC", "scrapeInterval": 30},
            "networkMetrics": {"level": "ADVANCED", "scrapeInterval": 30}
        }
    }'
```

在控制台中，选择附加组件卡片上的 **Actions**，然后选择 **Edit**，即可进行相同的更改。下图显示了 **Actions** 按钮。

![可观测性附加组件的 Actions 菜单，包含 Edit、Update version、Delete 和 View in EKS 选项](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/18/ML-22438-4-1.png)

图 4：使用 Actions → Edit 启用或禁用指标类别和性能分析

### Slurm 集群：安装或编辑可观测性扩展

在由 Slurm 编排的集群上，HyperPod 可观测性是一个集群**扩展**。在集群详情页中，打开 **Extensions** 选项卡。如果扩展已安装，请选择 **Actions**，然后选择 **Edit**。下图显示了 Slurm 集群 **Extensions** 选项卡上的可观测性扩展。

编辑页面会为每个指标类别设置收集级别。

![Slurm 集群的 Edit HyperPod observability 页面，显示带收集级别的指标类别、主机性能分析和指标存储](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/18/ML-22438-6-1.png)

图 6：在 Slurm 集群上编辑可观测性：指标类别、主机性能分析和指标存储

若要改用 AWS CLI 安装扩展：

```
aws sagemaker create-cluster-extension \
    --cluster-arn <cluster-arn> \
    --extension-name sagemaker-observability \
    --region <region> \
    --configuration-values '{
        "metricsProvider": {
            "clusterMetrics": {"level": "ENABLED", "collectionIntervalSeconds": 30},
            "nodeMetrics": {"level": "BASIC", "collectionIntervalSeconds": 30},
            "acceleratedComputeMetrics": {"level": "BASIC", "collectionIntervalSeconds": 30},
            "jobMetrics": {"level": "ENABLED", "collectionIntervalSeconds": 30}
        },
        "profilesProvider": {"hostProfiling": {"enabled": false}}
    }'
```

要开启 EFA 指标，请更新扩展：

```
aws sagemaker update-cluster-extension \
    --cluster-arn <cluster-arn> \
    --extension-arn <extension-arn> \
    --region <region> \
    --configuration-values '{
        "metricsProvider": {
            "clusterMetrics": {"level": "ENABLED", "collectionIntervalSeconds": 30},
            "nodeMetrics": {"level": "ADVANCED", "collectionIntervalSeconds": 30},
            "acceleratedComputeMetrics": {"level": "ADVANCED", "collectionIntervalSeconds": 30},
            "networkMetrics": {"level": "ENABLED", "collectionIntervalSeconds": 30},
            "jobMetrics": {"level": "ENABLED", "collectionIntervalSeconds": 30}
        }
    }'
```

使用 `aws sagemaker describe-cluster-extension --cluster-arn <cluster-arn> --extension-arn <extension-arn>` 检查状态。

### 第 5 步：确认指标正在流式传输

集群准备就绪后，导航到集群详情页。新的 **Observability** 选项卡会显示一个概览，其中包括：

- **Nodes：**节点总数（例如 128）。
- **Accelerators：**GPU/加速器总数（例如 1024）。
- **Jobs：**活动和最近的训练作业数量。
- **Avg. GPU utilization：**整个集群范围的平均值（例如 87.3%）。
- **Avg. vCPU utilization：**整个集群范围的平均值（例如 76.8%）。
- **Avg. memory utilization：**整个集群范围的平均值（例如 83.5%）。
