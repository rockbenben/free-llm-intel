## DeepSeek-R1 概览

DeepSeek-R1 是由 [DeepSeek AI](https://www.deepseek.com/) 开发的大语言模型（LLM），它以 DeepSeek-V3-Base 为基础，通过多阶段训练过程使用强化学习来增强推理能力。一个关键的显著特点是其[强化学习（RL）](https://aws.amazon.com/what-is/reinforcement-learning/)步骤，该步骤用于在标准预训练和微调过程之外进一步优化模型的响应。通过引入 RL，DeepSeek-R1 能够更有效地适应用户反馈和目标，最终提升相关性和清晰度。此外，DeepSeek-R1 采用[思维链（CoT）](https://arxiv.org/html/2501.12948v1)方法，这意味着它能够将复杂查询拆解并逐步推理。这种受引导的推理过程使模型能够生成更准确、更透明、更详细的答案。该模型将基于 RL 的微调与 CoT 能力相结合，旨在生成结构化的响应，同时注重可解释性和用户交互。凭借广泛的能力，DeepSeek-R1 作为一种通用文本生成模型吸引了业界的关注，可集成到 agent、逻辑推理和数据解读任务等各种工作流中。

DeepSeek-R1 采用混合专家（MoE）架构，参数规模达 6,710 亿。MoE 架构可激活 370 亿个参数，通过将查询路由到最相关的专家“集群”来实现高效推理。这种方法使模型能够在保持整体效率的同时专精于不同的问题领域。DeepSeek-R1 在 FP8 格式下推理至少需要 800 GB 的 HBM 显存。在本文中，我们将使用 ml.p5e.48xlarge 实例来部署该模型。ml.p5e.48xlarge 配备 8 块 Nvidia H200 GPU，提供 1128 GB 的 GPU 显存。

DeepSeek-R1 蒸馏模型将主 R1 模型的推理能力带到基于 Qwen（1.5B、7B、14B 和 32B）和 Llama（8B 和 70B）等流行开放模型的更高效架构中。蒸馏是指训练更小、更高效的模型来模仿更大的 DeepSeek-R1 模型的行为和推理模式的过程，后者作为教师模型。

你可以通过 [SageMaker JumpStart](https://aws.amazon.com/sagemaker-ai/jumpstart/) 或 [Bedrock Marketplace](https://docs.aws.amazon.com/bedrock/latest/userguide/amazon-bedrock-marketplace.html) 部署 DeepSeek-R1 模型。由于 DeepSeek-R1 是一个新兴模型，我们建议在部署时启用 guardrails。在本文中，我们将使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 引入安全防护、防止有害内容，并依据关键安全标准评估模型。在撰写本文时，对于在 SageMaker JumpStart 和 Bedrock Marketplace 上部署的 DeepSeek-R1，Bedrock Guardrails 仅支持 ApplyGuardrail API。你可以针对不同用例创建多个 guardrails 并应用到 DeepSeek-R1 模型，从而改善用户体验，并在生成式 AI 应用中标准化安全管控。

## 使用 ApplyGuardrail API 实现 guardrails

Amazon Bedrock Guardrails 使你能够引入安全防护、防止有害内容，并依据关键安全标准评估模型。你可以使用 Amazon Bedrock 的 `ApplyGuardrail` API 为 DeepSeek-R1 模型实施安全措施。这使你能够应用 guardrails 来评估部署在 Amazon Bedrock Marketplace 和 SageMaker JumpStart 上的用户输入和模型响应。你可以使用 Amazon Bedrock 控制台或 API 创建 guardrail。有关创建 guardrail 的示例代码，请参阅 [GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/responsible_ai/bedrock-guardrails/guardrails-api.ipynb)。

一般流程包括以下步骤：首先，系统接收模型的输入。该输入随后通过 `ApplyGuardrail` API 处理。如果输入通过 guardrail 检查，就会被发送到模型进行推理。收到模型输出后，会再应用一次 guardrail 检查。如果输出通过这项最终检查，就会作为最终结果返回。但是，如果输入或输出被 guardrail 干预，则返回一条消息，说明干预的性质以及发生在输入阶段还是输出阶段。以下各节展示的示例演示了如何使用该 API 进行推理。

### 使用已部署 DeepSeek-R1 端点的 guardrails 运行推理

以下代码示例演示如何使用 `invoke_model` 和 `ApplyGuardrail` API，通过 Amazon Bedrock 对已部署的 DeepSeek-R1 模型执行推理。你可以使用 Amazon Bedrock 控制台或 API 创建 guardrail。有关创建 guardrail 的示例代码，请参阅 [GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/responsible_ai/bedrock-guardrails/guardrails-api.ipynb)。创建 guardrail 后，使用以下代码实现 guardrails。该脚本会初始化 `bedrock_runtime` 客户端、配置推理参数，并发送请求以根据用户 prompt 生成文本。

```
import boto3
import json
from enum import Enum

# Initialize Bedrock client
bedrock_runtime = boto3.client("bedrock-runtime")

# Configuration
MODEL_ID = "your-model-id"  # Bedrock model ID
GUARDRAIL_ID = "your-guardrail-id"
GUARDRAIL_VERSION = "your-guardrail-version"

class ChatTemplate(Enum):
    LLAMA = "llama"
    QWEN = "qwen"
    DEEPSEEK = "deepseek"

def format_prompt(prompt, template):
    """Format prompt according to model chat template"""
    templates = {
        ChatTemplate.LLAMA: f"""<|begin_of_text|><|start_header_id|>system<|end_header_id|>
You are a helpful assistant<|eot_id|><|start_header_id|>user<|end_header_id|>
{prompt}<|eot_id|><|start_header_id|>assistant<|end_header_id|>""",

        ChatTemplate.QWEN: f"""<|im_start|>user\n{prompt}<|im_end|>\n<|im_start|>assistant""",

        ChatTemplate.DEEPSEEK: f"""You are a helpful assistant <｜User｜>{prompt}<｜Assistant｜>"""
    }
    return templates[template]

def invoke_with_guardrails(prompt, template=ChatTemplate.DEEPSEEK, max_tokens=1000, temperature=0.6, top_p=0.9):
    """
    Invoke Bedrock model with input and output guardrails
    """
    # Apply input guardrails
    input_guardrail = bedrock_runtime.apply_guardrail(
        guardrailIdentifier=GUARDRAIL_ID,
        guardrailVersion=GUARDRAIL_VERSION,
        source='INPUT',
        content=[{"text": {"text": prompt}}]
    )

    if input_guardrail['action'] == 'GUARDRAIL_INTERVENED':
        return f"Input blocked: {input_guardrail['outputs'][0]['text']}"

    # Format prompt with selected template
    formatted_prompt = format_prompt(prompt, template)

    # Prepare model input
    request_body = {
        "inputs": formatted_prompt,
        "parameters": {
            "max_new_tokens": max_tokens,
            "top_p": top_p,
            "temperature": temperature
        }
    }

    # Invoke model
    response = bedrock_runtime.invoke_model(
        modelId=MODEL_ID,
        body=json.dumps(request_body)
    )

    # Parse model response
    model_output = json.loads(response['body'].read())['generated_text']

    # Apply output guardrails
    output_guardrail = bedrock_runtime.apply_guardrail(
        guardrailIdentifier=GUARDRAIL_ID,
        guardrailVersion=GUARDRAIL_VERSION,
        source='OUTPUT',
        content=[{"text": {"text": model_output}}]
    )

    if output_guardrail['action'] == 'GUARDRAIL_INTERVENED':
        return f"Output blocked: {output_guardrail['outputs'][0]['text']}"
    return model_output

# Example usage
if __name__ == "__main__":
    prompt = "What's 1+1?"
    result = invoke_with_guardrails(prompt, template=ChatTemplate.DEEPSEEK)
    print(result)
```

### 结合 SageMaker JumpStart predictor 实现 guardrails 并运行推理

与 Amazon Bedrock 类似，你也可以在 SageMaker JumpStart predictor 中使用 `ApplyGuardrail` API。你可以使用 Amazon Bedrock 控制台或 API 创建 guardrail，并按照以下代码实现：

```
import boto3
import json
bedrock_runtime = boto3.client('bedrock-runtime')
sagemaker_runtime = boto3.client('sagemaker-runtime')

# Add your guardrail identifier and version created from Bedrock Console or AWSCLI
guardrail_id = "" # Your Guardrail ID
guardrail_version = "" # Your Guardrail Version
endpoint_name = "" # Endpoint Name

prompt = "What's 1+1 equal?"

# Apply guardrail to input before sending to model
input_guardrail_response = bedrock_runtime.apply_guardrail(
    guardrailIdentifier=guardrail_id,
    guardrailVersion=guardrail_version,
    source='INPUT',
    content=[{ "text": { "text": prompt }}]
)

# If input guardrail passes, proceed with model inference
if input_guardrail_response['action'] != 'GUARDRAIL_INTERVENED':
    # Prepare the input for the SageMaker endpoint
    template = f"""You are an AI assistant. Do as the user asks.
### Instruction: {prompt}
### Response: <think>"""
    
    input_payload = {
        "inputs": template,
        "parameters": {
            "max_new_tokens": 1000,
            "top_p": 0.9,
            "temperature": 0.6
        }
    }
    
    # Convert the payload to JSON string
    input_payload_json = json.dumps(input_payload)
    
    # Invoke the SageMaker endpoint
    response = sagemaker_runtime.invoke_endpoint(
        EndpointName=endpoint_name,
        ContentType='application/json',
        Body=input_payload_json
    )
    
    # Get the response from the model
    model_response = json.loads(response['Body'].read().decode())
    
    # Apply guardrail to output
    output_guardrail_response = bedrock_runtime.apply_guardrail(
        guardrailIdentifier=guardrail_id,
        guardrailVersion=guardrail_version,
        source='OUTPUT',
        content=[{ "text": { "text": model_response['generated_text'] }}]
    )
    
    # Check if output passes guardrails
    if output_guardrail_response['action'] != 'GUARDRAIL_INTERVENED':
        print(model_response['generated_text'])
    else:
        print("Output blocked: ", output_guardrail_response['outputs'][0]['text'])
else:
```
