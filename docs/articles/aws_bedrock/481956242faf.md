# 使用 Langfuse 实现 Amazon Bedrock AgentCore 可观测性

人工智能（AI）agent 的兴起，标志着软件开发方式以及应用如何决策、如何与用户交互的转变。传统系统沿着可预测的路径运行，而 AI agent 则参与复杂的推理，这些推理始终隐藏在视野之外。这种不可见性给组织带来一个难题：他们如何信任自己看不见的东西？这正是 agent 可观测性登场之处——它提供对 agentic 应用如何运行、如何交互以及如何执行任务的深入洞察。

本文中，我们将说明如何把 [Langfuse](https://langfuse.com/) 可观测性与 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 集成，以深入洞察 AI agent 的性能、更快地排查问题并优化成本。我们通过一个完整实现走一遍流程：使用部署在 [AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 上的 Strands agent，随后给出逐步的代码示例。

Amazon Bedrock AgentCore 是一个全面的 agentic 平台，能够安全、大规模地部署与运行高能力的 AI agent。它为动态 agent 工作负载提供专门构建的基础设施、用于增强 agent 的强大工具，以及面向真实部署的必要控制措施。AgentCore 由完全托管的服务组成，这些服务可以一起使用，也可以独立使用。它们可与任何框架（包括 CrewAI、LangGraph、LlamaIndex 和 Strands Agents）以及 Amazon Bedrock 之内或之外的任何基础模型协作，兼具灵活性与可靠性。AgentCore 以标准化的 OpenTelemetry（OTEL）兼容格式发出遥测数据，便于与现有的监控与可观测性技术栈集成。它提供 agent 工作流中每一步的详细可视化，使你能够检查 agent 的执行路径、审计中间输出，并排查性能瓶颈与故障。

## Langfuse tracing 的工作方式

Langfuse 使用 OpenTelemetry 对部署在 Amazon Bedrock AgentCore 上的 agent 进行追踪与监控。OpenTelemetry 是云原生计算基金会（CNCF）项目，提供一套规范、API 与库，定义了从应用收集分布式追踪与指标的标准方式。用户现在可以跨不同处理阶段跟踪性能指标，包括 token 用量、延迟与执行时长。系统会创建分层的 trace 结构，同时捕获流式与非流式响应，并带有详细的操作属性与错误状态。

通过 `/api/public/otel` 端点，Langfuse 充当 OpenTelemetry 后端，利用生成式 AI 约定把 trace 映射到其数据模型。这对于使用链与带工具 agent 的复杂大语言模型（LLM）应用尤其有价值，因为嵌套的 trace 能帮助开发者快速定位并解决问题。该集成支持系统性调试、性能监控与审计追踪维护，使团队更容易在 Amazon Bedrock AgentCore 上构建并维护可靠的 AI 应用。

除了 agent 可观测性，Langfuse 还提供一套覆盖 LLM 应用开发生命周期全过程的集成工具。这包括运行自动化的 llm-as-a-judge 评估器（在线／离线）、组织数据标注以用于根因分析与评估器对齐、跟踪实验（本地与 CI 内）、在 playground 中以交互方式迭代 prompt，并通过 prompt management 在 UI 中对其进行版本控制。

## 方案概览

本文展示如何在带有 Langfuse 可观测性的情况下，把 Strands agent 部署到 Amazon Bedrock AgentCore Runtime。实现中使用通过 Amazon Bedrock 访问的 Anthropic Claude 模型。遥测数据从 Strands agent 经 OTEL exporter 流向 Langfuse，用于监控与调试。要使用 Langfuse，请在 AgentCore runtime 部署中设置 `disable_otel=True`。这会关闭 AgentCore 的默认可观测性。

图 1：架构总览

方案中使用的关键组件包括：

- **Strands Agents**：用于构建 LLM 驱动 agent 的 Python 框架，内置遥测支持
- **Amazon Bedrock AgentCore Runtime**：托管运行时服务，用于在 Amazon Web Services（AWS）上托管并扩展 agent
- **Langfuse**：面向 LLM 应用的开源可观测性与评估平台，通过 OTEL 接收 trace
- **OpenTelemetry**：用于收集与导出遥测数据的行业标准协议

#### **第 2 步：Agent 实现**

agent 文件（`strands_claude.py`）实现了一个具备网页搜索能力的旅行 agent。

```
%%writefile strands_claude.py
import os
import logging
from bedrock_agentcore.runtime import BedrockAgentCoreApp
from strands import Agent, tool
from strands.models import BedrockModel
from strands.telemetry import StrandsTelemetry
from ddgs import DDGS
logging.basicConfig(level=logging.ERROR, format="[%(levelname)s] %(message)s")
logger = logging.getLogger(__name__)
logger.setLevel(os.getenv("AGENT_RUNTIME_LOG_LEVEL", "INFO").upper())
@tool
def web_search(query: str) -> str:
"""
Search the web for information using DuckDuckGo.
Args:
query: The search query
Returns:
A string containing the search results
"""
try:
ddgs = DDGS()
results = ddgs.text(query, max_results=5)
formatted_results = []
for i, result in enumerate(results, 1):
formatted_results.append(
f"{i}. {result.get('title', 'No title')}\n"
f" {result.get('body', 'No summary')}\n"
f" Source: {result.get('href', 'No URL')}\n"
)
return "\n".join(formatted_results) if formatted_results else "No results found."
except Exception as e:
return f"Error searching the web: {str(e)}"
# Function to initialize Bedrock model
def get_bedrock_model():
region = os.getenv("AWS_DEFAULT_REGION", "us-west-2")
model_id = os.getenv("BEDROCK_MODEL_ID", "us.anthropic.claude-3-7-sonnet-20250219-v1:0")
bedrock_model = BedrockModel(
model_id=model_id,
region_name=region,
temperature=0.0,
max_tokens=1024
)
return bedrock_model
# Initialize the Bedrock model
bedrock_model = get_bedrock_model()
# Define the agent's system prompt
system_prompt = """You are an experienced travel agent specializing in personalized travel recommendations
with access to real-time web information. Your role is to find dream destinations matching user preferences
using web search for current information. You should provide comprehensive recommendations with current
information, brief descriptions, and practical travel details."""
app = BedrockAgentCoreApp()
def initialize_agent():
"""Initialize the agent with proper telemetry configuration."""
# Initialize Strands telemetry with 3P configuration
strands_telemetry = StrandsTelemetry()
strands_telemetry.setup_otlp_exporter()

# Create and cache the agent
agent = Agent(
model=bedrock_model,
system_prompt=system_prompt,
tools=[web_search]
)

return agent
@app.entrypoint
def strands_agent_bedrock(payload, context=None):
"""
Invoke the agent with a payload
"""
user_input = payload.get("prompt")
logger.info("[%s] User input: %s", context.session_id, user_input)

# Initialize agent with proper configuration
agent = initialize_agent()

response = agent(user_input)
return response.message['content'][0]['text']
if __name__ == "__main__":
app.run()
```

#### 第 3 步：配置 AgentCore Runtime 部署

接下来，使用我们的[起始工具包](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-toolkit.html) 配置 AgentCore Runtime 部署，指定入口点、我们创建的执行角色与 requirements 文件。此外，把 starter kit 配置为在启动时自动创建 [Amazon Elastic Container Registry（ECR）](https://aws.amazon.com/ecr/) 仓库。

在配置步骤中，docker 文件会根据应用代码生成。使用 `bedrock_agentcore_starter_toolkit` 配置 agent 时，它默认会配置 AgentCore Observability。因此，要使用 Langfuse，用户应通过把配置标志设为“True”来禁用 OTEL，如下面的代码块所示。

图 2：配置 AgentCore Runtime

```
from bedrock_agentcore_starter_toolkit import Runtime
from boto3.session import Session
boto_session = Session()
region = boto_session.region_name
agentcore_runtime = Runtime()
agent_name = "strands_langfuse_observability"
response = agentcore_runtime.configure(
entrypoint="strands_claude.py",
auto_create_execution_role=True,
auto_create_ecr=True,
requirements_file="requirements.txt",
region=region,
agent_name=agent_name,
disable_otel=True,
)
response
```

#### **第 4 步：部署到 AgentCore Runtime**

现在 docker 文件已生成，把 agent 启动到 AgentCore Runtime，以创建 Amazon ECR 仓库与 AgentCore Runtime。

接着在 AWS Systems Manager Parameter Store 中配置 Langfuse 的 secret key、public key 与 OTEL 端点，它提供用于配置数据管理与密钥管理的安全、分层存储。

```
import base64
# Langfuse configuration
otel_endpoint = "https://us.cloud.langfuse.com/api/public/otel"
langfuse_secret_key = "<Enter your Langfuse secret key>" #For production key should be securely stored
langfuse_public_key = "<Enter your Langfuse public key" #For production key should be securely stored
langfuse_auth_token = base64.b64encode(f"{langfuse_public_key}:{langfuse_secret_key}".encode()).decode()
otel_auth_header = f"Authorization=Basic {langfuse_auth_token}"
launch_result = agentcore_runtime.launch(
env_vars={
"BEDROCK_MODEL_ID": "us.anthropic.claude-3-7-sonnet-20250219-v1:0", # Example model ID
"OTEL_EXPORTER_OTLP_ENDPOINT": otel_endpoint, # Use Langfuse OTEL endpoint
"OTEL_EXPORTER_OTLP_HEADERS": otel_auth_header, # Add Langfuse OTEL auth header
"DISABLE_ADOT_OBSERVABILITY": "true",
}
)
launch_result
```

下表描述了所使用的各项配置参数。

| **参数** | **描述** | **默认值** |
| --- | --- | --- |
| `langfuse_public_key` | OTEL 端点的 API key | 环境变量 |
| `langfuse_secret_key` | OTEL 端点的密钥 | 环境变量 |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | trace 端点 | https://cloud.langfuse.com/api/public/otel/v1/traces |
| `OTEL_EXPORTER_OTLP_HEADERS` | 认证类型 | Basic |
| `DISABLE_ADOT_OBSERVABILITY` | AWS Distro for Open Telemetry（ADOT）。该实现禁用 Agent Core 的默认可观测性，改用 Langfuse。 | True |
| `BEDROCK_MODEL_ID` | AWS Bedrock 模型 ID | us. anthropic.claude-3-7-sonnet-20250219-v1:0 |

- 含延迟与 token 用量的模型交互
- 请求／响应 payload

### Trace 与层级结构

Langfuse 捕获从用户请求到单次模型调用的所有交互。每个 trace 捕获完整的执行路径，包括 API 调用、函数调用与模型响应，形成 agent 活动的完整时间线。trace 的嵌套结构使开发者能够下钻到具体交互，并在执行链的任意层级识别性能瓶颈或错误模式。为进一步增强可观测性能力，Langfuse 提供了可在 agent 工作流中实现的标签（tagging）机制。

图 3：Langfuse 中的 trace

把分层 trace 与策略性标签结合起来，可以洞察 agent 的运作，从而实现数据驱动的优化与更优质的用户体验。如下图所示，开发者可以下钻到 agent 执行流中每项操作的精确耗时。在上一示例中，整个请求耗时 26.57s，其中还细分了事件循环周期、工具调用与其他组件的耗时。利用这些耗时信息来发现性能瓶颈并缩短响应时间。例如，某些 LLM 操作可能比预期更耗时，或者存在把特定操作并行化以降低整体延迟的机会。借助这些洞察，用户可以做数据驱动的决策，提升 agent 性能并交付更好的客户体验。

### 成本监控

成本监控有助于在汇总层面与单次请求层面跟踪开销，从而保持对 AI 基础设施支出的控制。该平台提供按模型、用户与函数调用的详细成本明细，使团队能够识别成本密集的操作并优化其实现。这种细粒度的成本可见性有助于在模型选择、prompt engineering 与资源分配方面做出数据驱动的决策，同时保持预算约束。仪表板中的成本数据仅供估算之用；实际收费应通过官方账单核实。
