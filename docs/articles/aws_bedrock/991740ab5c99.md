# 使用 AWS Step Functions 构建无服务器的 Amazon Bedrock 批处理任务编排工作流

随着组织越来越多地把基础模型（FM）用于其人工智能与机器学习（AI/ML）工作负载，高效管理大规模推理操作变得至关重要。Amazon Bedrock 支持两大类大规模推理模式：实时推理，以及适用于处理海量数据集、不需要即时结果的场景的批量推理。

[Amazon Bedrock 批量推理](https://docs.aws.amazon.com/bedrock/latest/userguide/batch-inference.html)是一种[成本效益高的方案](https://aws.amazon.com/bedrock/pricing/)，与按需处理相比可享受 50% 的折扣，非常适合高吞吐量、对时间不敏感的工作负载。然而，大规模实施批量推理也带来一系列自身挑战，包括管理输入格式与任务配额、编排并发执行，以及处理后处理任务。开发者需要一个稳健的框架来简化这些操作。

本文介绍一个灵活且可扩展的方案，可简化批量推理工作流。该方案提供高度可扩展的方式来管理你的 FM 批量推理需求，例如为数百万份文档生成 embedding，或对大型数据集运行自定义评估或补全任务。

## 解决方案概述

下图给出了该自动化工作流的总体概览，它包含三个主要阶段：输入数据集预处理（例如 prompt 格式化）、并行执行批量推理任务，以及解析模型输出的后处理。

[![Process Flow](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-1.jpeg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-1.jpeg)

该方案提供了灵活可扩展的框架来简化批量编排。只需给出简单的配置输入，这个 [AWS Cloud Development Kit](https://aws.amazon.com/cdk/)（AWS CDK）堆栈中部署的 Step Functions 状态机就会处理数据集预处理、启动并行批量任务，并对输出进行后处理。

在我们的具体用例中，我们使用了开源数据集 [SimpleCoT](https://huggingface.co/datasets/w601sxs/simpleCoT) 的 220 万行数据。Hugging Face 上的 SimpleCoT 数据集汇集了多样化的任务型示例，旨在展示和训练语言模型中的思维链（CoT）推理。该数据集涵盖广泛的问题类型，包括阅读理解、数学推理、逻辑演绎和自然语言处理（NLP）任务。数据集的结构是每条记录包含任务描述、问题、正确答案以及对推理过程的详细解释。

下图说明了该解决方案的架构。

[![Architecture Diagram](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-2.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-2.jpg)

Amazon Bedrock 批量编排模式使用可扩展的无服务器组件，覆盖批处理工作流特有的关键架构考量：

- **文件格式与存储（File format and storage）** – 任务输入必须组织为存储在 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）桶中的 JSONL 文件，每一行代表一条输入记录，并与该 FM 或提供商对应的 API 请求结构相匹配。例如，Anthropic 的 Claude 模型与 Amazon Titan Text Embeddings V2 的 JSON 结构不同。还有配额需要考虑：截至撰写本文时，每批最少 1,000 条、最多 50,000 条记录。你可以根据自己的用例需求，通过 [Service Quotas](https://docs.aws.amazon.com/servicequotas/latest/userguide/intro.html) 申请提高配额。
- **Step Functions 状态机（Step Functions state machine）** – 编排异步、长时间运行的任务需要稳健的控制流系统。我们的架构使用 Step Functions 协调整个过程，并用 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 维护各个任务及其状态的清单。这里同样有重要的配额考量：例如，使用 Amazon Titan Text Embeddings V2 基础模型的进行中与已提交批量推理任务数量之和，目前每个 AWS 区域最多为 20 个。借助 [Map 工作流状态](https://docs.aws.amazon.com/step-functions/latest/dg/state-map.html)，Step Functions 可以通过控制任务提交和监控完成状态来帮助最大化吞吐量。
- **后处理（Postprocessing）** – 最后，你很可能希望对批量输出（同样是 Amazon S3 中的 JSONL 文件）做一些轻量后处理，以解析响应并把输出与原始输入连接起来。例如，在生成文本 embedding 时，你必须有一种机制把输出向量映射回其源文本。这些可配置的 [AWS Lambda](https://aws.amazon.com/lambda) 函数会在批量结果抵达 Amazon S3 之后作为 Step Functions 工作流的一部分被触发。

以下各节我们将逐步介绍如何把 AWS CDK 堆栈部署到你的 AWS 环境。

## 先决条件

请完成以下先决步骤：

- 安装 node 和 npm。
- 安装 AWS CDK：

```
npm install -g aws-cdk
```

- 将 GitHub 仓库克隆到你的本地开发环境：

```
git clone https://github.com/aws-samples/amazon-bedrock-samples
cd poc-to-prod/bedrock-batch-orchestrator
```

## 部署解决方案

使用以下代码安装所需的包：`npm i`

查看 `prompt_templates.py` 文件，并为你的目标用例向 `prompt_id_to_template` 添加新的 prompt 模板。

`prompt_id_to_template` 是一个 dict，键为 `prompt_id`（让你可以把某个任务与特定的 prompt 关联起来）。prompt 字符串模板中的格式化键也必须存在于你的输入文件中。例如，考虑以下 prompt 模板：

```
You are an AI assistant tasked with providing accurate and justified answers to users' questions.
    
You will be given a task, and you should respond with a chain-of-thought surrounded by <thinking> tags, then a final answer in <answer> tags.

For example, given the following task:

<task>
You are given an original reference as well as a system generated reference. Your task is to judge the naturaleness of the system generated reference. If the utterance could have been produced by a native speaker output 1, else output 0. System Reference: may i ask near where? Original Reference: where do you need a hotel near?.
</task>

<thinking>
The utterance "may i ask near where?" is not natural. 
This utterance does not make sense grammatically.
Thus we output 0.
</thinking>

<answer>0</answer>

Your turn. Please respond to the following task:

<task>
{source}
</task>
```

你必须确保输入数据集为每个格式化键都有一列（例如前面示例代码中的 `source`）。

prompt 模板不用于基于 embedding 模型的任务。使用以下代码部署 AWS CDK 堆栈：`npm run cdk deploy`

请记下 [AWS CloudFormation](https://aws.amazon.com/cloudformation) 输出中表示的桶名和 Step Functions 工作流名称：

## 任务输入结构

作为输入数据集，你可以使用 Hugging Face 数据集 ID，也可以直接指向 Amazon S3 中的数据集（截至撰写本文时支持 CSV 或 Parquet 格式）。输入数据集的来源和模型类型（文本生成或 embedding）决定了 Step Functions 输入的结构。

### Hugging Face 数据集

对于 Hugging Face 数据集，引用数据集 ID（例如 `w601sxs/simpleCoT`）和 split（例如 `train`），你的数据集就会直接从 Hugging Face Hub 拉取。

[![Hugging Face Mapping](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-3.jpeg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-3.jpeg)

`prompt_templates.py` 中的 `question_answering` prompt 模板有一个名为 `source` 的格式化键，用于匹配所引用数据集中相应列的名称（见前面的示例）。我们使用该 prompt 为数据集中 220 万行中的每一行生成推理过程和答案。见以下代码：

```
{
  "job_name_prefix": "full-cot-job",
  "model_id": "us.anthropic.claude-3-5-haiku-20241022-v1:0",
  "prompt_id": "question_answering",
  "dataset_id": "w601sxs/simpleCoT",
  "split": "train",
  "max_records_per_job": 50000
}
```

我们还有可选键 `max_num_jobs`（用于限制任务总数，在小规模测试时很有用）和 `max_records_per_batch`。

### Amazon S3 数据集

将输入的 CSV 或 parquet 文件上传到 S3 桶，并复制其 S3 URI。例如：`aws s3 cp topics.csv s3://batch-inference-bucket-<YOUR_ACCOUNT_ID>/inputs/jokes/topics.csv`

在 Step Functions 控制台打开你的 Step Functions 状态机，并提交具有以下结构的输入。对于 S3 数据集，你必须提供 `s3_uri`。

例如，对于使用 Amazon S3 输入的 Anthropic 模型，请使用以下代码：

```
{
"s3_uri": "s3://batch-inference-bucket-<YOUR_ACCOUNT_ID>/inputs/jokes/topics.csv",
"job_name_prefix": "test-joke-job1",
"model_id": "anthropic.claude-3-haiku-20240307-v1:0",
"prompt_id": "joke_about_topic"
}
```

`joke_about_topic` 的 `prompt_id` 映射到 `prompt_templates.py` 中的一个 prompt 模板，该模板有一个用于 `topic` 的格式化键，而 `topic` 必须是输入 CSV 文件中的列之一。

## 生成批量 embedding

要使用 Amazon Titan Text Embeddings V2 之类的模型生成 embedding，你不需要提供 `prompt_id`，但必须确保输入 CSV 文件有一列名为 `input_text`，其中包含你希望转为 embedding 的文本。例如：

```
{
"s3_uri": "s3://batch-inference-bucket-<YOUR_ACCOUNT_ID>/inputs/embeddings/embedding_input.csv",
"job_name_prefix": "test-embeddings-job1",
"model_id": "amazon.titan-embed-text-v2:0",
"prompt_id": null
}
```

## Step Functions 工作流

下图展示了一次成功的 Step Functions 工作流执行示例。

[![Process Flow](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-4.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-4.jpg)

当 Step Functions 状态机被启动时，它会完成以下步骤：

- 预处理输入数据集，为你的特定模型 ID 和 prompt 模板准备批量任务输入。`BaseProcessor` 抽象类可以快速扩展以支持其他模型提供商，例如 Meta Llama 3 或 Amazon Nova。
- 以事件驱动的方式编排批量任务。我们在 DynamoDB 表中维护一份内部任务清单，并在 Amazon Bedrock 发出与任务状态变化相关的事件时更新它。这些更新随后通过 **Wait for Task Token Callback** 集成模式回传给 step function。使用 SFN Map，我们确保在记录处理完成之前始终保持并发任务的最大容量。
- 并发运行批量输出的后处理，执行一些轻量解析，并使用 [recordId](https://docs.aws.amazon.com/bedrock/latest/userguide/batch-inference-data.html) 字段作为连接键把模型响应合并回原始输入数据。输出数据取决于你使用的模型类型。对于基于文本的模型，输出字符串会放在一个名为 `response` 的新列中。

在状态机运行任务的过程中对其进行监控。已提交与进行中任务的最大数量由 `cdk.json` 中的 AWS CDK context 变量控制（键为 `maxSubmittedandInProgressJobs`）。生成的 Parquet 文件路径会汇总在执行的输出中。

输出的 Parquet 文件将包含与输入文件相同的列，以及生成的响应。

对于文本生成模型，输出字符串会放在一个名为 `response` 的新列中，如下图所示为示例输出。

[![Sample Request and Response](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-5.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-5.jpg)

对于 embedding 模型，输出（浮点数列表）会放在一个名为 `embedding` 的新列中，如下图所示。

[![Sample Dataset](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-6.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/22/ML-18183-image-6.jpg)

Batch Inference API 没有保证的 SLA。运行时间会随请求时目标模型的需求而变化。例如，要处理 SimpleCoT 数据集中的 220 万条记录，执行被分配到 45 个独立的处理任务，任一时刻已提交与进行中的任务最多 20 个。在我们使用 Anthropic 的 Claude Haiku 3.5 于 `us-east-1` 区域的实验中，每个独立任务执行平均耗时 9 小时，端到端总处理时间约 27 小时。

## 清理

为避免产生额外费用，你可以运行 `cdk destroy` 来[清理](https://docs.aws.amazon.com/cdk/v2/guide/ref-cli-cmd-destroy.html)堆栈的资源。

## 结论

本文概述了一个使用 Amazon Bedrock 批量推理执行大规模批处理的无服务器架构。我们探讨了该方案在多种用例中的应用，包括大规模数据标注和 embedding 生成。你也可以从 teacher 模型生成大量合成数据，用于训练 student 模型，作为模型蒸馏过程的一部分。

该方案已在 [GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-samples/tree/main/poc-to-prod/bedrock-batch-orchestrator)中公开发布。我们非常期待看到你如何把这一架构用于自己的用例。
