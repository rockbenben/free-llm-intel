# 使用 Strands 与 Exa 构建具备网页搜索能力的 agent

*本文由来自 Exa 的 Ishan Goswami 和 Nitya Sridhar 共同撰写。*

如果你正在为研究、事实核查或竞争情报构建具备网页搜索能力的 AI agent，那么获取及时、可靠的信息至关重要。大多数通用搜索 API 并非为 agent 工作流设计。它们返回的是充满 HTML 的页面和面向人类浏览优化的短摘要，而不是 agent 可以直接消费的结构化数据。因此，开发者往往需要构建额外的层——自定义爬虫、解析器和排序逻辑——才能把这些内容转换成 agent 工作流中可用的形式。

面向 [Strands Agents SDK](https://strandsagents.com/) 的 Exa 集成解决了这一缺口，它把 AI 原生的搜索与检索层直接构建在工具接口中。Exa 交付干净、结构化的内容，其格式可直接用于 LLM 的上下文窗口，无需后处理来剥离标记或重排输出。再结合 Strands Agents SDK 的模型驱动架构——由模型决定何时调用工具以及如何使用工具输出——agent 就能把实时的网页知识引入其推理循环。

在实践中，你的 agent 通过两个工具访问这一集成：`exa_search`，执行语义搜索，并支持新闻、研究论文和代码仓库等类别；以及 `exa_get_contents`，从选定的 URL 检索完整内容。在本文中，你将学习如何在 Strands Agents 中设置 Exa 集成、了解它暴露的两个核心工具，并通过真实用例了解 agent 如何使用网页搜索来完成多步任务。

## Strands Agents

Strands Agents SDK 是 AWS 推出的一个开源框架，用模型驱动的方式构建 AI agent。开发者无需编写规定每一步的硬编码工作流，而是提供一个模型、一个系统提示（system prompt）和一组工具。由模型自己决定接下来做什么：调用哪些工具、以什么顺序调用，以及任务何时完成。Strands Agents 的核心是 agent 循环。每一轮迭代中，模型都会收到完整的对话历史，包括此前每一次工具调用及其结果。如果模型需要更多信息，它会请求调用工具；Strands Agents 执行该工具并把结果回传。循环持续进行，直到模型产出最终答案。这种跨迭代的上下文累积，正是 agent 能够处理超出单次 LLM 调用能力的多步任务的原因。Strands Agents SDK 内置 40 多个预构建工具，涵盖文件 I/O、shell 执行、网页搜索、AWS API、memory、代码执行等。它还支持 Model Context Protocol（MCP），因此 MCP 服务器暴露的工具可以直接供 agent 使用，无需额外的集成工作。添加新工具（包括 Exa 网页搜索工具）遵循同样的模式：把它们放进 `tools=[]` 列表，模型就会从其签名中学会如何使用它们。

## Exa

Exa 是一个专为 LLM 和 AI agent 构建的网页级搜索引擎。Exa 是一个理解查询含义而不仅是关键词的搜索引擎。像“startups building climate solutions”这样的查询会返回真正的气候领域创业公司，即使这些页面从未使用过这个确切短语。模型依据语义相似度而非字符串重叠来匹配。结果以干净、结构化的内容返回，没有广告或 SEO 噪声，可直接供 LLM 消费。

## Strands Agents 与 Exa：集成概览

Exa 集成通过 `strands-agents-tools` 包提供。它为你的 agent 提供两项能力：在网页上搜索相关内容，以及从特定 URL 提取整页文本。下图展示了深度研究助手（deep research assistant）示例，本文后半部分将深入讨论它。

![Strands Agents 深度研究工作流](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/04/ml-19612-image-1-752x1024.png)

两者都为 AI 消费做了优化，返回结构化内容，你的 agent 可以直接在其上推理。

- `exa_search`：使用多种模式搜索网页，包括 auto、fast 和 deep。你的 agent 可以用类别、域名、日期和文本内容等过滤器来细化结果。
- `exa_get_contents`：从 agent 已发现的 URL（无论是来自先前的搜索还是来自它自身的推理）检索整页内容。该工具会先检查缓存结果，以加快重复请求。如果需要最新内容，它可以自动回退到实时抓取（live crawling），以获取页面的最新版本。

### 使用 `exa_search` 搜索网页

`exa_search` 工具让你的 agent 对网页搜索的控制超越基本的查询字符串。该工具支持四种搜索模式。默认模式 `auto` 是大多数用例推荐的起点。

- **Instant（约 200ms）** —— 为自动补全、实时建议和语音 agent 等实时应用而设计。
- **Fast（约 450ms）** —— 在仍能访问 Exa 高质量索引的前提下针对速度优化。适用于 agent 会发起数十次搜索调用的 agentic 工作流。
- **Auto（约 1s）[推荐]** —— 延迟与高质量结果之间的平衡。推荐用于大多数用例。
- **Deep（约 3-6s）** —— 针对查询变体并行执行搜索，以获得最大覆盖。最适合完整性至关重要的研究任务。

除了搜索模式，`exa_search` 还让你的 agent 对结果如何过滤和限定范围拥有细粒度控制。你可以把搜索缩小到特定的内容类别，例如新闻文章、公司网站、GitHub 仓库、PDF、人物简介或财务报告。当 agent 已经知道自己需要哪种来源时，类别过滤最为有效。例如，查询偏技术性时过滤到研究论文，或者优先考虑时效性时过滤到新闻来源。你还可以在搜索结果中一并请求内容和摘要，全部在一次调用中完成：

```
agent.tool.exa_search( query="recent advances in AI safety research", num_results=10, summary={"query": "key research areas and findings"}) .
```

响应包含标题、URL，以及针对你指定查询的每条结果综合摘要。你的 agent 无需通读每个完整页面，就能建立起对某个主题的基础理解。

### 使用 `exa_get_contents` 提取内容

一旦你的 agent 找到了相关 URL（无论是来自先前的搜索还是来自其自身推理），`exa_get_contents` 工具就会检索整页内容。你传入一个 URL 列表，它返回提取出的文本，供 agent 处理。Exa 维护一个内容缓存，对已抓取过的页面即时提供结果。对于不在缓存中的页面，或者当 agent 需要页面的最新版本时，该工具支持实时抓取。你通过 livecrawl 模式控制这一行为。可配置的超时时间控制等待实时抓取完成多久。你还可以控制返回的文本量。例如，要从某个页面检索最多 5,000 个字符的纯文本：

```
agent.tool.exa_get_contents(urls=["https://example.com/blog-post"], highlight={"maxCharacters": 5000})
```

### 前置条件

要跟随本文中的示例，你需要：

- Python 3.10 或更高版本
- 一个拥有 Amazon Bedrock 访问权限的 AWS 账户
- 一个 [Exa API key](https://dashboard.exa.ai/api-keys)

## 设置

Exa 工具与 Strands Agents 框架中的其他任何工具遵循相同的模式，所以如果你用过其他 Strands 工具，体验是一样的。Strands Agents SDK 包含一个预构建工具库，涵盖文件操作、网页搜索、代码执行、AWS 服务、内存管理等等。Exa 工具就是该库的一部分。导入它们，并通过 `tools` 参数传给 Agent 构造函数。agent 底层的 LLM 随后会在其推理循环中决定何时调用每个工具。由于该集成直接与 Exa REST API 通信，你无需安装或管理单独的 SDK。唯一新增的依赖就是 `strands-agents-tools` 包。要将 Exa 与 Strands Agents 一起使用，请按以下步骤操作：

#### 1. 设置你的 Exa API key

Exa 需要 API key 才能通过身份验证访问。在运行 agent 之前，用你的 key 设置 `EXA_API_KEY` 环境变量。你可以从 [Exa dashboard](https://dashboard.exa.ai/api-keys) 获取 key：

`export EXA_API_KEY="your_exa_api_key_here"`

#### 2. 导入并注册工具

在 agent 代码中，从 `strands_tools.exa` 导入 `exa_search` 和 `exa_get_contents`，并把它们加入 agent 的工具列表：

```
from strands import Agent
from strands_tools.exa import exa_search, exa_get_contents
agent = Agent(tools=[exa_search, exa_get_contents])
```

#### 3. 调用你的 agent

工具注册完成后，agent 就可以在推理流程中自然地交错执行搜索和内容提取：

```
response = agent( "Search for the most recent trends in AI agents and provide a concise summary of key developments")
```

agent 设置好之后，你就可以针对不同的搜索场景开始使用 Exa 工具了。

## 示例：用 Exa 构建深度研究 agent

为了看清这两个工具如何协同工作，下面的示例构建了一个[深度研究助手](https://github.com/strands-agents/samples/tree/main/python/03-integrate/tools/exa)，在多步工作流中演示两个 Exa 工具。给定一个研究问题，agent 会针对不同来源类型执行四次有针对性的搜索，从最有希望的结果中提取完整内容，并把所有内容综合成一份结构化的研究报告。整个工作流在一次 agent 调用内完成，多个工具调用作为推理循环的一部分发生。关键设计洞见在于：不同来源类型需要不同的搜索参数，但不需要不同的工具。两个 Exa 工具在整个工作流中被重复使用，每一步采用不同的参数配置：用类别定位新闻、PDF 或代码仓库；用日期过滤保证时效；用 JSON schema 做结构化提取；用实时抓取保证新鲜度。

## 开始使用

- 在 [Exa dashboard](https://dashboard.exa.ai/api-keys) 注册一个 Exa API key
- 克隆[示例仓库](https://github.com/strands-agents/samples/tree/main/python/03-integrate/tools/exa)并运行深度研究助手
- 修改系统提示，使其面向你的领域：替换类别过滤器、日期范围和 JSON schema 以匹配你的用例

### 设置 agent

设置过程需要一个模型、一个系统提示和两个 Exa 工具：

```
from strands import Agent
from strands.models.bedrock import BedrockModel
from strands_tools.exa import exa_search, exa_get_contents

def create_research_agent() -> Agent:
    model = BedrockModel(
        model_id="us.anthropic.claude-sonnet-4-6",
        region_name="us-west-2",
        max_tokens=20000,
    )
    return Agent(
        model=model,
        system_prompt=load_system_prompt(),
        tools=[exa_search, exa_get_contents],
    )
```

系统提示定义了研究工作流，引导 agent 走完六个步骤：针对不同来源类型的四次定向搜索、一次深度内容提取，以及最后一轮综合分析。agent 决定何时以及如何调用每个工具、如何解读结果，以及何时进入下一步，这些都是其推理循环的一部分。六步研究工作流中的每一步都指示 agent 用针对该类内容调优的不同参数调用 Exa 工具。

***Step 1: Overview search*** —— 一次使用 `auto` 模式的广泛扫描，建立基础理解。系统提示指示 agent 用以下参数调用 `exa_search`。

```
- type: "auto"
- num_results: 5
- text: {"maxCharacters": 2000}
- highlights: {"maxCharacters": 4000}
- summary: {"query": "What are the key concepts, main points, and important details?"}
- subpages: 2
- subpage_target: ["overview", "about", "introduction"]
- max_age_hours: 168
```

***Step 2: News search*** —— 关注范围收窄到 30 天日期窗口内的新闻来源。日期边界在 Python 中计算并注入提示。`max_age_hours` 设置缓存内容可接受的最大年龄（以小时计）。

```
- category: "news"
- num_results: 5
- start_published_date: <runtime-injected: today minus 30 days>
- text: {"maxCharacters": 1500}
- summary: {"query": "What are the key announcements, developments, and news?"}
- max_age_hours: 24
```

***Step 3: Research papers*** —— 为了学术深度，搜索以 `research paper` 类别为目标，并通过引导性 `query` 把关键发现、方法和结论提取为简洁摘录。

```
- category: "research paper"
- num_results: 5
- text: {"maxCharacters": 2000}
- summary: {
    "query": "Extract the research findings, methodology, and conclusions",
    "schema": {
      "type": "object",
      "properties": {
        "title": {"type": "string", "description": "Paper title"},
        "main_findings": {"type": "string", "description": "Key findings and results"},
        "methodology": {"type": "string", "description": "Research methodology used"},
        "conclusions": {"type": "string", "description": "Main conclusions"}
      },
      "required": ["main_findings", "conclusions"]
    }
  }
```

***Step 4: GitHub projects*** —— 开源实现通过 `github` 类别浮出水面。

```
- category: "github"
- num_results: 5
- highlights: {"maxCharacters": 4000}
```

***Step 5:*** ***Deep dive*** —— agent 从发现切换到提取。前几步中最有希望的两三个 URL 会通过 `exa_get_contents` 拉取完整内容。这一步使用强制实时抓取（用 `"always"` 而非 `"fallback"`）以获取最新内容，使用更高的字符上限（4000）做全面提取，并通过子页面抓取来跟进指向参考文献、引用和方法论页面的链接。

```
- urls: <2-3 most valuable URLs from previous searches>
- text: {"maxCharacters": 4000}
- highlights: {"maxCharacters": 4000}
- summary: {"query": "Extract all important details, insights, and actionable information"}
- subpages: 3
- subpage_target: ["references", "citations", "bibliography", "methodology"]
- max_age_hours: 0
```

***Step 6: Synthesis*** —— 这最后一步不调用任何工具。此前各步收集到的所有内容汇入一份结构化的研究报告，包含执行摘要、主题概览、最新进展、关键研究与论文、工具与实现、深度洞察，以及带 URL 的完整来源清单。

与单次搜索调用或基础的搜索 API 封装相比，这套多步工作流有几个优势：

- **有据可依的回答** —— 最终报告中的每个论断都可追溯到来源 URL，减少幻觉。
- **高效的 token 使用** —— 在搜索和提取阶段生成摘要让内容保持简洁，因此 LLM 处理的是提炼后的知识，而非原始页面堆砌。
- **自主的深度** —— agent 在新闻、论文、代码仓库、完整页面等来源类型之间迭代，无需人工引导，覆盖单次搜索无法触及的范围。

## 使用 Exa 工具的最佳实践

在你把 Exa 工具集成到 agent 中时，有一些模式可以帮助你针对质量、延迟和成本进行优化。以下建议将帮助你在 agent 工作流中充分发挥 Exa 工具的作用。有关搜索类型、内容模式和高级过滤的更多信息，请参阅 [Exa best practices documentation](https://exa.ai/docs/reference/search-best-practices)。

- **从 `auto` 开始，再按需调整**：`auto` 搜索类型能很好地处理大多数查询。对于漏掉相关来源代价高昂的研究任务，切换到 `deep`；当 agent 进行大量连续搜索、累计延迟比单次查询的完整性更重要时，切换到 `fast` 或 `instant`。
- **控制内容大小以管理 token 预算**：在“highlights”字段上设置 `maxCharacters`（默认 maxCharacters 为 4,000）。

## 结论

[Strands Agents SDK](https://strandsagents.com) 和 [Exa](https://exa.ai/docs) 提供了一条构建 AI agent 的路径，让 agent 建立在最新、准确的网页信息之上。Exa 的搜索提供语义理解，类别过滤把结果缩小到正确的内容类型，带 JSON schema 的 AI 摘要返回的恰好是 agent 所需的结构，而实时抓取带来新鲜度。Strands Agents 集成通过[两个工具和几行设置代码](https://github.com/strands-agents/tools/blob/main/src/strands_tools/exa.py)暴露这些能力。

正如深度研究助手所展示的，你可以构建一个多步研究 agent，在新闻、学术论文和代码仓库之间搜索，从最佳结果中提取整页内容，并把所有内容综合成有据可依的报告，而这一切仅由一个系统提示驱动。该 agent 用[类别过滤器](https://exa.ai/docs/reference/search-best-practices)瞄准来源类型，用日期范围控制时效，用 JSON schema 塑造输出，用实时抓取管理新鲜度。你可以在把搜索、内容和回答端点接入 agent 之前，先从 [Exa dashboard](https://dashboard.exa.ai) 直接测试它们。整个工作流都可以通过 [Amazon Bedrock AgentCore Observability](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html) 追踪，把非确定性的 agent 行为变成可检查、可调试的 span。这一模式不只适用于研究，也适用于竞争情报、技术支持、市场分析以及其他需要 agent 获取实时网页信息的领域。用你自己的研究问题试试[深度研究助手示例](https://github.com/strands-agents/samples/tree/main/python/03-integrate/tools/exa)。[获取你的 Exa API key](https://dashboard.exa.ai/api-keys) 开始构建，浏览 [Amazon Bedrock 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-bedrock.html) 了解更多底层平台信息，并在 [Strands Agents GitHub 仓库](https://github.com/strands-agents/sdk-python) 上分享你的反馈。
