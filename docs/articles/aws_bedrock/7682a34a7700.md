# 在 AWS 上使用 LLM-as-a-judge 评估医疗健康生成式 AI 应用

在之前的博客文章中，我们探索了多种技术，例如微调大语言模型（LLM）、提示词工程，以及使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的检索增强生成（RAG），用生成式 AI 从放射学报告的所见（findings）部分生成印象（impressions）。[第 1 部分](https://aws.amazon.com/blogs/machine-learning/automatically-generate-impressions-from-findings-in-radiology-reports-using-generative-ai-on-aws/)聚焦模型微调。[第 2 部分](https://aws.amazon.com/blogs/machine-learning/evaluation-of-generative-ai-techniques-for-clinical-report-summarization/)介绍了 RAG，它把 LLM 与外部知识库结合，以减少幻觉并提高医疗应用中的准确率。通过实时检索相关医学信息，RAG 系统能够给出更可靠、更贴合上下文的回答，这使得它们在精度至关重要的医疗健康应用中尤其有价值。在之前两篇文章中，我们都使用 ROUGE 分数这类传统指标来评估性能。该指标适合评估普通的摘要任务，但无法有效判断 RAG 系统是否成功整合了检索到的医学知识，或是否保持了临床准确性。

在第 3 部分中，我们介绍一种使用 Amazon Bedrock 的 LLM-as-a-judge 来评估医疗健康 RAG 应用的方法。这一创新的评估框架应对医疗 RAG 系统特有的挑战：检索到的医学知识是否准确，以及生成的医疗内容质量是否达到严格标准[（例如表达清晰简洁、临床准确和语法准确）](https://pubmed.ncbi.nlm.nih.gov/39333958/)。借助 Amazon 的最新模型以及新发布的、用于 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 的 [RAG 评估功能](https://aws.amazon.com/blogs/aws/new-rag-evaluation-and-llm-as-a-judge-capabilities-in-amazon-bedrock/)，我们现在可以全面评估这些系统检索和使用医学信息、进而生成准确且契合上下文的回答的能力。

随着医疗健康 RAG 应用在临床环境中日益普及，评估方法上的这一进步尤为关键。LLM-as-a-judge 方法提供了更细致的评估框架，同时考量信息检索的质量和生成内容的临床准确性，符合医疗健康领域所要求的严格标准。

在本文中，我们演示如何使用 Amazon Bedrock 实现这一评估框架，比较不同生成器模型的性能（包括 Amazon Bedrock 上的 Anthropic Claude 和 Amazon Nova），并展示如何使用新的 RAG 评估功能来优化知识库参数、评估检索质量。这种方法不仅为医疗 RAG 评估建立了新的基准，也为从业者提供了实用工具，用于构建更可靠、更准确、可在临床环境中信赖的医疗健康 AI 应用。

## 解决方案概览

该解决方案使用 Amazon Bedrock Knowledge Bases 的评估能力，专门针对放射学报告的所见与印象来评估和优化 RAG 应用。我们按从左到右的数据流，在下图中审视这一架构的关键组件。

[![Amazon Bedrock LLM-as-a-Judge 流水线](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/17/image001-1.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/17/image001-1.png)

该工作流包含以下阶段：

- **数据准备** – 我们的评估流程从包含成对放射学所见与印象的提示词数据集开始。这些临床数据会经过一个转换过程，被转换为结构化的 JSONL 格式，这是与知识库评估系统兼容所必需的。准备完成后，这份格式化的数据会被安全上传到 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）存储桶，在整个评估过程中兼顾可访问性与数据安全。
- **评估处理** – 解决方案的核心是一个 Amazon Bedrock Knowledge Bases 评估作业。该组件处理已准备好的数据，并与 Amazon Bedrock Knowledge Bases 无缝集成。这一集成至关重要，因为它使系统能够构建专门针对放射学所见与印象的医疗 RAG 能力，确保评估同时考虑医学上下文和准确性。
- **分析** – 最后阶段为医疗健康数据科学家提供详细的分析能力。通过先进的自动化报告生成系统，专业人员可以获取印象生成摘要任务各项性能指标的详细分析。这套全面的报告系统支持对检索质量和生成准确性进行彻底评估，为系统优化和质量保证提供有价值的洞察。

这一架构为评估医疗 RAG 应用提供了系统而彻底的方法，在精度与可靠性至关重要的医疗健康场景中兼顾准确与可靠。

### 数据集与背景

MIMIC Chest X-ray（MIMIC-CXR）数据库 v2.0.0 是一个大型公开数据集，包含 DICOM 格式的胸部 X 光片以及自由文本的放射学报告。我们使用了由 91,544 份报告组成的 [MIMIC CXR 数据集](https://physionet.org/content/mimic-cxr/2.0.0/)，该数据集需通过数据使用协议获取，这要求用户注册并完成资质审核流程。

在常规临床诊疗中，受过影像判读训练的临床医生（放射科医生）会以自由文本笔记的形式总结其对某项检查的所见。这些报告使用基于规则的方法进行了去标识化处理，以移除受保护的健康信息。由于我们只使用放射学报告文本数据，因此仅从 MIMIC-CXR 网站下载了一个压缩的报告文件（mimic-cxr-reports.zip）。在评估中，我们使用了 [MIMIC-CXR 数据集的子集](https://physionet.org/content/mimic-cxr/2.0.0/)中总计 2,000 份报告里的 1,000 份，称为 dev1 数据集。此外还使用了来自印第安纳大学医院网络的[胸部 X 光集合](https://github.com/abachaa/MEDIQA2021/tree/main/Task3)中总计 2,000 份放射学报告里的另外 1,000 份（称为 dev2）。

### 使用 Amazon Bedrock Knowledge Bases 的 RAG

Amazon Bedrock Knowledge Bases 有助于利用 RAG 这一流行技术，即从数据存储中提取信息来增强 LLM 生成的回答。我们使用 Amazon Bedrock Knowledge Bases 从放射学报告的所见部分生成印象：用查询知识库所获得的上下文来丰富提示。该知识库被设置为以 {prompt, completion} 对的形式，包含 91,544 份 MIMIC-CXR 放射学报告的所见部分及对应的印象部分。

### LLM-as-a-judge 与质量指标

LLM-as-a-judge 代表了一种创新的评估方式：用 LLM 作为自动评估器来评价 AI 生成的医疗内容。在传统指标可能无法捕捉医学准确性与临床相关性细微要求的医疗健康应用中，这一方法尤其有价值。借助专门的提示词和评估标准，LLM-as-a-judge 能够从多个维度评估生成的医疗内容，提供与医疗专业人员标准相符的更全面的评估框架。

我们的评估框架涵盖五项关键指标，每项都用于评估生成医疗内容的特定方面：

- **正确性（Correctness）** – 采用 3 点李克特量表评估，该指标通过将生成的回答与标准答案对比来衡量其事实准确性。在医学场景中，它确保临床判读与所见同源材料及公认的医学知识一致。
- **完整性（Completeness）** – 使用 5 点李克特量表，该指标考察生成的回答是否在整体上全面回应了提示，同时兼顾标准答案。它确保回答中不会遗漏关键的医学所见或判读。
- **有用性（Helpfulness）** – 以 7 点李克特量表衡量，该指标评估回答在临床场景中的实际效用，考量所提供医学信息的清晰度、相关性和可执行性等因素。
- **逻辑连贯性（Logical coherence）** – 采用 5 点李克特量表评估，该指标检查回答中的逻辑缺口、不一致或矛盾之处，确保医学推理自然流畅，并在整篇回答中保持临床有效性。
- **忠实性（Faithfulness）** – 按 5 点李克特量表打分，该指标专门评估回答中是否包含提示中未出现、也无法从提示中快速推断的信息，从而帮助识别在临床环境中可能造成危险的潜在幻觉或编造的医学信息。

这些指标在最终输出和作业报告卡中会被归一化，提供标准化分数，从而支持在不同模型和评估场景之间进行一致比较。这一全面的评估框架不仅有助于维持医疗 RAG 系统的可靠性与准确性，也为持续改进和优化提供详细洞察。关于指标和评估提示词的细节，请参阅[知识库评估作业中使用的评估器提示词](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-eval-prompt.html)。

## 将测试数据集转换为 JSONL 以进行 RAG 评估

为评估我们的 RAG 系统在放射学报告上的表现，我们实现了一条数据转换流水线，将测试数据集转换为所需的 JSONL 格式。以下代码展示了原始 dev1 和 dev2 数据集的格式：

```
{
    "prompt": "value of prompt key",
    "completion": "value of completion key"
}
Output Format

{
    "conversationTurns": [{
        "referenceResponses": [{
            "content": [{
                "text": "value from completion key"
            }]
        }],
        "prompt": {
            "content": [{
                "text": "value from prompt key"
            }]
        }
    }]
}
```

借鉴 Wilcox 的开创性论文 [The Written Radiology Report](https://cdn.agilitycms.com/applied-radiology/PDFs/Issues/AR_07-06_Wilcox.pdf)，我们精心设计提示词，加入了生成高质量印象的完整准则：

```
import json
import random
import boto3

# Initialize the S3 client
s3 = boto3.client('s3')

# S3 bucket name
bucket_name = "<BUCKET_NAME>"

# Function to transform a single record
def transform_record(record):
    return {
        "conversationTurns": [
            {
                "referenceResponses": [
                    {
                        "content": [
                            {
                                "text": record["completion"]
                            }
                        ]
                    }
                ],
                "prompt": {
                    "content": [
                        {
                            "text": """You're given a radiology report findings to generate a concise radiology impression from it.

A Radiology Impression is the radiologist's final concise interpretation and conclusion of medical imaging findings, typically appearing at the end of a radiology report.
\n Follow these guidelines when writing the impression:
\n- Use clear, understandable language avoiding obscure terms.
\n- Number each impression.
\n- Order impressions by importance.
\n- Keep impressions concise and shorter than the findings section.
\n- Write for the intended reader's understanding.\n
Findings: \n""" + record["prompt"]
                        }
                    ]
                }
            }
        ]
    }
```

该脚本逐条处理记录，将其重构为包含对话轮次的格式，其中既有原始放射学所见，也有对应的印象，确保每份报告都符合文献中阐述的专业标准。为使该功能使用的数据集规模可控，我们从原始 dev1 和 dev2 数据集中随机抽取了 1,000 条记录，并使用固定的随机种子以保证可复现：

```
# Read from input file and write to output file
def convert_file(input_file_path, output_file_path, sample_size=1000):
    # First, read all records into a list
    records = []
    with open(input_file_path, 'r', encoding='utf-8') as input_file:
        for line in input_file:
            records.append(json.loads(line.strip()))
    
    # Randomly sample 1000 records
    random.seed(42)  # Set the seed first
    sampled_records = random.sample(records, sample_size)
    
    # Write the sampled and transformed records to the output file
    with open(output_file_path, 'w', encoding='utf-8') as output_file:
        for record in sampled_records:
            transformed_record = transform_record(record)
            output_file.write(json.dumps(transformed_record) + '\n')
            
# Usage
input_file_path = '<INPUT_FILE_NAME>.jsonl'  # Replace with your input file path
output_file_path = '<OUTPUT_FILE_NAME>.jsonl'  # Replace with your desired output file path
convert_file(input_file_path, output_file_path)

# File paths and S3 keys for the transformed files
transformed_files = [
    {'local_file': '<OUTPUT_FILE_NAME>.jsonl', 'key': '<FOLDER_NAME>/<OUTPUT_FILE_NAME>.jsonl'},
    {'local_file': '<OUTPUT_FILE_NAME>.jsonl', 'key': '<FOLDER_NAME>/<OUTPUT_FILE_NAME>.jsonl'}
]

# Upload files to S3
for file in transformed_files:
    s3.upload_file(file['local_file'], bucket_name, file['key'])
    print(f"Uploaded {file['local_file']} to s3://{bucket_name}/{file['key']}")
```

## 配置 RAG 评估作业

我们的 RAG 评估配置从为 Amazon Bedrock 评估作业建立核心配置开始，包括选择评估模型和生成模型（分别为 Anthropic 的 Claude 3 Haiku 和 Amazon Nova Micro）。实现中采用了[混合检索](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-knowledge-bases-now-supports-hybrid-search/)策略，检索深度为 10 条结果，从而在评估期间全面覆盖知识库。为保持条理与可追溯性，每个评估作业都会被分配一个带时间戳信息的唯一标识符，输入数据和结果则通过指定的 S3 路径系统地管理。参见以下代码：

```
import boto3
from datetime import datetime

# Generate unique name for the job
job_name = f"rag-eval-{datetime.now().strftime('%Y-%m-%d-%H-%M-%S')}"

# Configure knowledge base and model settings
knowledge_base_id = "<KNOWLEDGE_BASE_ID>"
evaluator_model = "anthropic.claude-3-haiku-20240307-v1:0"
generator_model = "amazon.nova-micro-v1:0"
role_arn = "<IAM_ROLE_ARN>"

# Specify S3 locations
input_data = "<INPUT_S3_PATH>"
output_path = "<OUTPUT_S3_PATH>"

# Configure retrieval settings
num_results = 10
search_type = "HYBRID"

# Create Bedrock client
bedrock_client = boto3.client('bedrock')
```

核心配置就绪后，我们使用 Amazon Bedrock 的 `create_evaluation_job` API 启动评估作业，它负责编排对我们 RAG 系统性能的全面评估。评估配置指定了五项关键指标——正确性、完整性、有用性、逻辑连贯性和忠实性——从而对生成的放射学印象进行多维度分析。该作业被设置为使用知识库完成检索和生成任务，并由指定模型各自承担角色：Amazon Nova Micro 负责生成，Anthropic 的 Claude 3 Haiku 负责评估，结果会被系统地存放在指定的 S3 输出位置，供后续分析使用。参见以下代码：

```
retrieve_generate_job = bedrock_client.create_evaluation_job(
    jobName=job_name,
    jobDescription="Evaluate retrieval and generation",
    roleArn=role_arn,
    applicationType="RagEvaluation",
    inferenceConfig={
        "ragConfigs": [{
            "knowledgeBaseConfig": {
                "retrieveAndGenerateConfig": {
                    "type": "KNOWLEDGE_BASE",
                    "knowledgeBaseConfiguration": {
                        "knowledgeBaseId": knowledge_base_id,
                        "modelArn": generator_model,
                        "retrievalConfiguration": {
                            "vectorSearchConfiguration": {
                                "numberOfResults": num_results,
                                "overrideSearchType": search_type
                            }
                        }
                    }
                }
            }
        }]
    },
    outputDataConfig={
        "s3Uri": output_path
    },
    evaluationConfig={
        "automated": {
            "datasetMetricConfigs": [{
                "taskType": "Custom",
                "dataset": {
                    "name": "RagDataset",
                    "datasetLocation": {
                        "s3Uri": input_data
                    }
                },
                "metricNames": [
                    "Builtin.Correctness",
                    "Builtin.Completeness",
                    "Builtin.Helpfulness",
                    "Builtin.LogicalCoherence",
                    "Builtin.Faithfulness"
                ]
            }],
            "evaluatorModelConfig": {
                "bedrockEvaluatorModels": [{
                    "modelIdentifier": evaluator_model
                }]
            }
        }
    }
)
```

## 指标可解释性

以下截图展示了评估系统详细的指标可解释性界面，显示了示例对话及其对应的指标评估。每条对话条目包含四个关键列：对话输入（Conversation input）、生成输出（Generation output）、检索到的来源（Retrieved sources）和标准答案（Ground truth），另外还有一列分数（Score）。系统提供 1,000 个示例的完整视图，并提供浏览数据集的导航控件。特别值得注意的是，每条对话的检索深度指示符都显示为 10，说明各示例对知识库的使用保持一致。

该评估框架支持详细跟踪生成指标，并让知识库得出输出的过程变得透明。每条示例对话都呈现完整的信息链，从最初的提示一直到最终评估。系统会显示为生成提供依据的检索上下文、实际生成的回答，以及用于对比的标准答案。评分机制会评估每条回答，并可展开界面查看决策过程的详细解释（如截图中弹出的窗口所示）。这种细粒度的细节支持对 RAG 系统的性能进行彻底分析，并有助于找出检索与生成流程中可优化的环节。

使用 LLM-as-a-judge 评估医疗健康 RAG 应用的实现，是在维持 AI 生成医疗内容的可靠性与准确性方面的一项重要进步。借助这套基于 Amazon Bedrock Knowledge Bases 的全面评估框架，我们展示了自动化评估如何从多个关键维度为医疗 RAG 系统的性能提供详细洞察。两个数据集上的高分表明了这一方法的稳健性，不过这些指标只是开始。
