# Condé Nast 如何借助 Amazon Bedrock 加速合同处理与版权分析

*本文与 Condé Nast 的 Bob Boiko、Christopher Donnellan 和 Sarat Tatavarthi 合写。*

一个多世纪以来，[Condé Nast](https://www.condenast.com/) 始终站在全球媒体的前沿，凭借其声名显赫的品牌组合塑造文化与对话。公司创立于 1909 年，已从传统出版商演变为现代媒体巨头。如今，Condé Nast 旗下包括 Vogue、The New Yorker、GQ 和 Vanity Fair 在内的众多有影响力的品牌，触达 7,200 万纸媒读者、3.94 亿数字消费者，以及社交网络上的 4.54 亿关注者，使其成为全球最具影响力的内容创作者与发行商之一。

公司庞大的业务组合横跨多个品牌与地区，需要管理一张日益复杂的合同、版权与授权协议网络。原有流程严重依赖对新接收合同的人工审阅，在品牌收购或扩张等战略举措期间尤其如此。版权管理专家花费无数小时，把新到的合同与现有模板识别匹配、提取授予的权利与元数据，并管理各类创意素材的授权协议，包括来自全球供稿者的图片、视频和文字内容。这种人工的、基于规则的做法造成了严重的运营瓶颈：流程耗时，且容易出错。结果是公司对权利使用采取保守策略，错失了不少收入机会。Condé Nast 需要一套现代高效的方案，在自动化合同处理的同时，仍保持最高水准的准确性与合规性。

本文探讨 Condé Nast 如何使用 [Amazon Bedrock](https://aws.amazon.com/bedrock) 和 Anthropic 的 Claude，加速其合同处理与版权分析工作流。

## 方案概述

AWS 与 Condé Nast 的法务和技术团队合作，开发了一套由 AWS AI 服务驱动的自动化合同处理方案，聚焦于解析、比较和数据可视化——它本身不提供法律意见。该方案使用以下关键服务：

- [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3) – 可扩展的对象存储服务，用于存放新到的合同、参考模板和方案输出。
- [Amazon OpenSearch Serverless](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/serverless-overview.html) – [Amazon OpenSearch Service](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/what-is.html) 的按需无服务器配置，用作向量存储。
- [Amazon Bedrock](https://aws.amazon.com/bedrock) – 一项完全托管的服务，通过单一 API 提供来自领先 AI 公司的一系列高性能基础模型（FM），并附带丰富的能力集，可用于以安全、隐私和负责任 AI 为前提构建生成式 AI 应用。借助 Amazon Bedrock，你可以针对自己的用例试验并评估顶级 FM，用 fine-tuning 和检索增强生成（RAG）等技术以自有数据私有化定制模型，并构建能借助企业系统和数据源执行任务的 agent。
- [AWS Step Functions](https://aws.amazon.com/step-functions/) – 可视化工作流服务，帮助开发者使用 AWS 服务构建分布式应用、自动化流程、编排微服务，以及创建数据和机器学习（ML）pipeline。
- [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/) – 完全托管的 ML 服务。借助 SageMaker AI，数据科学家和开发者可以快速构建、训练 ML 模型并将其部署到可直接用于生产的托管环境。它提供运行 ML 工作流的 UI 体验，让 SageMaker AI 的 ML 工具可在多个集成开发环境（IDE）中使用。

该工作流包含以下步骤：

- 用户把新合同上传到输入 S3 存储桶。新合同的加入会触发 [Amazon EventBridge](https://aws.amazon.com/eventbridge/)，由它启动主 Step Functions 工作流。
- 一个 [Amazon SageMaker Processing](https://sagemaker.readthedocs.io/en/stable/amazon_sagemaker_processing.html) 作业处理这些合同，把它们从 PDF 转成数字文本文件。这一步利用 Amazon Bedrock 中 [Anthropic 的 Claude 3.7 Sonnet](https://aws.amazon.com/blogs/aws/anthropics-claude-3-7-sonnet-the-first-hybrid-reasoning-model-is-now-available-in-amazon-bedrock/) 的视觉推理能力，把 PDF（先转成图像）转写为原始文本文件。评估单份合同的条款时，该操作会把手写批注、删除线和特殊文档排版（例如单栏与多栏）考虑在内。预处理还能处理长达数百页的大文档：把文档切成更小的分块，反复执行上一步。生成的文本文件保存在 S3 存储桶中，作为现有及未来一系列生成式 AI 用例的基础。中间处理数据的输出遵循与原始源数据相同的访问限制。
- 利用这份文本文件输出，第二个 SageMaker Processing 作业运行，使用 Amazon Bedrock 中的 Anthropic Claude 3.7 Sonnet 提取一组预先指定的元数据字段。大语言模型（LLM）通过 prompt 模板获得一个 schema，其中包含所有可能关注的元数据字段，以及每个字段的简短说明，帮助模型完成提取。
- 第三个 SageMaker Processing 作业通过把新到合同的文本与可能模板的文本（存放在 Amazon Bedrock 知识库中）进行比较，找出相似的现有模板。此外，Anthropic 的 Claude 3.7 Sonnet 会判定与最相似模板之间的关键语义差异。结果汇总到一张电子表格中，包含提取出的元数据字段以及最相似的模板和样板条款。这些结果保存到 S3 存储桶，并向相应的业务与法务人员发送通知消息，请其审阅结果。与各模板相似度都较低的新到合同会送到另一个 S3 存储桶，用于另一条下游流程（进一步分析并生成新模板）。
- 人工审阅者验证系统的结果。随后用一个 [AWS Lambda](https://aws.amazon.com/lambda/) 函数把有效结果加载到 Condé Nast 的版权与版税管理系统。系统会发送通知消息，说明前述加载成功还是失败。方案的输出用于一系列下游流程，并与 Condé Nast 其他内部软件方案集成。
- 第 5 步中没有找到接近模板匹配的合同会被路由去做进一步分析。
- 这些低相似度合同被送入聚类算法，依据文本相似度和每份合同授予的权利进行分组。
- 一张包含所分配的聚类标签、相似度分数、合同文本等内容的电子表格，连同配套的交互式可视化一起保存到 Amazon S3。人工审阅者利用这些结果起草新模板，用于未来的交易和该方案的后续运行。随后，对那些在第 4 步可能有新的对应模板上传到知识库的合同，可以重新运行该方案。

## 收益与成果

通过使用 AWS AI 服务，Condé Nast 显著改善了其版权管理运营：

- **多种模型访问** – Amazon Bedrock 可以通过单一 API 提供对多种 FM 的访问。
- **无缝集成** – Amazon Bedrock SDK 与 SageMaker Processing 配合顺畅。
- **效率大幅提升** – 合同分析的处理时间从数周缩短到数小时，使内容部署更快、对行业变化的响应更敏捷。这有助于版权管理专家把精力放在复杂案例和战略举措上。
- **知识可及性与用户赋能增强** – 该方案把合同分析流程系统化，显著提升了全组织对版权管理专业知识的可及性。法务助理和版权专家现在可以把自身专长编码进处理常规查询的 prompt，从而更高效地运用知识，在保持高准确性标准的同时专注于复杂的战略事务。
- **可扩展性与灵活性** – 在大型品牌收购或扩张等高峰期，系统能轻松应对增加的工作量，无需额外人力。即使需求达到峰值，处理时间也更稳定。
- **准确性提升** – 这套生成式 AI 驱动的系统对合同做详尽分析并能识别细微差异，显著降低了权利侵犯和潜在法律挑战的风险。这让 Condé Nast 在内容部署决策上更有信心，也能更好地保护知识产权资产。
- **附带收益** – 该系统的实施产生了超出其主要职能的宝贵副产品与经验。这些洞见支持了其他方案的开发，其中包括一个把复杂的权利可用性信息转成通俗语言、面向非技术用户的系统，从而在全组织扩大了版权管理的用途。

## 经验教训

在 Condé Nast 实施这套方案带来了一些关键洞见，为媒体行业及其他领域类似的数字化转型举措提供了宝贵经验：

- **数据预处理是基础** – 团队发现，元数据提取及后续流程的质量在很大程度上取决于最初的合同处理 pipeline。这促成了一个高级 OCR 系统的开发，它能够处理各类文档，包括带手写批注的、扫描件的和多栏 PDF。此外，系统还需要在文件体积和页数两方面高效处理大文件。没有这套成熟的预处理能力，工作流后续步骤的表现将大打折扣。
- **人工监督仍然关键** – 项目再次印证了人类专业知识的价值，尤其是在复杂的数据处理任务中。团队发现，人工评估对于处理细微案例不可或缺，也为 prompt 工程提供了关键的反馈回路。这种 human-in-the-loop 做法让 AI 模型得以持续改进，随时间推移不断提升准确性与相关性。它凸显了一点：应把 AI 看作增强人类智能的工具，而不是完全取代人类。
- **以业务为中心的技术集成** – 项目成功的一个关键因素是聚焦于解决具体业务问题。团队专注于研究各种生成式 AI/ML 方案如何有效组合，以应对 Condé Nast 在版权管理上的独特挑战。这一做法确保技术方案始终与业务目标紧密对齐，最终落地更实用、价值立现。
- **早期对齐利益相关方** – 事实证明，从项目一开始就让所有相关方（法务团队、版权管理专家和技术人员）参与很重要。这种协作做法确保方案既满足合规要求，又带来运营效率，也让全组织的采用更顺畅。
- **增量实施** – 先针对特定品牌的一部分合同上线、再逐步推进的决定，使快速迭代和打磨成为可能。这种分阶段做法帮助团队在全面部署之前收集真实反馈并做必要调整，最终方案更稳健、更有效。
- **参考数据的质量** – 项目凸显了多样、高质量示例文档的重要性。当提供一套涵盖多品牌、多地区的代表性历史合同全集时，系统准确性显著提升，这体现了维护记录完备的合同档案对上下文与模式匹配的价值。

## 结论

通过与 AWS 的这次合作，Condé Nast 成功实现了版权管理工作流的现代化，构建出更高效、更准确、更具可扩展性的系统。该方案解决了眼前的运营挑战，并通过为 AI 驱动的内容管理打下基础，为 Condé Nast 的未来增长做好准备。这一实施也为传统媒体公司如何拥抱 AI 技术、在精简运营的同时保持最高版权管理标准并符合监管要求，提供了蓝图。该方案的成功部署展示了 AWS AI/ML 服务在现代化传统合同分析业务流程方面的潜力，为媒体版权管理的效率与准确性树立了新标准。

该项目的开发也正在改变 Condé Nast 的软件开发方式，尤其是生成式 AI 应用。通过帮助领域专家借助 prompt 工程推动开发，组织找到了一条更直接、更贴合业务的构建技术方案之路。这一新模式让专家用浅白的英文直接向语言模型表达需求，在提升结果准确性与相关性的同时，大幅降低了传统开发的复杂度。这一转变重新定义了 Condé Nast 推进技术创新的方式：从传统的软件开发周期，转向更动态、由专业经验驱动的过程。
