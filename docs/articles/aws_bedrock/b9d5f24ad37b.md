# ICYMI：2026 年 8 月为 AI 构建者带来了什么

*回顾 2026 年 8 月 Amazon Bedrock、AgentCore 与 Strands 最重要的更新。*

在 AWS，我们长期致力于让基础技术更易获取，并提供让这些技术真正投入使用所需的基础设施。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 拥有 22.5 万多家活跃客户，其中包括超过 80% 的《财富》100 强企业；它正是这一承诺的体现：提供对领先模型的访问，以及一整套用于构建和扩展 AI 的工具，并具备客户在生产环境中所需的安全性、可靠性、性能与成本效率。随着 agentic 应用的扩展，Amazon Bedrock 通过 [AgentCore](https://aws.amazon.com/bedrock/agentcore/) 延伸这一基础，让你可以使用任意框架与模型来构建、连接并优化 agent。AWS 还将 [Strands Agent Harness SDK](https://strandsagents.com/) 以开源方式发布，让你可以灵活地创建 agent，并把它们部署到你所选的位置。二者合力，帮助你把模型智能转化为生产级 agent，同时不限制这些 agent 的构建方式或运行位置。

随着模型能力增强，组织可以提出一个更有雄心的问题：AI 能从始至终承担多少有意义的工作？在各行各业，agent 正进入这样一类工作流：需要它们对企业信息进行推理、在更长的时间跨度内保持产出，并跨越数字系统与物理系统采取行动。随着这类工作的范围扩大，关注点正在转向模型周边的完整系统，包括它能访问什么上下文、能采取什么行动、数据在哪里处理，以及它的决策与成本如何被治理。

我们相信，AI 的下一阶段不仅取决于模型能做什么，还取决于你有多大信心把责任委派给围绕模型构建的系统。这种信心依赖于这样的系统：它能理解眼前的任务，在任务展开过程中持续存在，并在清晰的组织边界内运作。8 月的更新正朝着这个方向推进，为 AI 系统提供更坚实的基础，使其能够理解更多、工作更久，并在企业、受监管与物理环境中承担要求严苛的责任。

## **以更强控制力、更大规模对更多上下文进行推理**

**把完整工作集与最新 Web 上下文带入你在 Amazon Bedrock 上的 OpenAI 应用。**GPT-5.6 Sol、Terra 与 Luna 现在支持带 prompt caching 的[百万 token 上下文窗口](https://aws.amazon.com/about-aws/whats-new/2026/08/gpt-sol-terra-luna-long-context-bedrock/)，有助于在上下文被重复使用时降低成本与延迟。[Web Search](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-bedrock-web/) 让模型能够找到超出训练数据的最新信息、把相关结果纳入回答，并在无需你接入独立搜索供应商的情况下给出引用。对于需要最新细节的用例，例如实时定价或刚刚发布的文档，模型还可以直接从公共网站[获取内容](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-bedrock-web-access-web-search/)。这些能力合在一起，让你可以在单次 API 调用中分析整个代码库或监管文档、把其中内容与最新的公开信息核对，并返回带有引用的响应。

[**在全球范围路由推理**](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-bedrock-cross-region-openai-v2/)**，无需拼接各个区域。**借助跨区域推理，你可以在 25 个以上的 AWS 区域访问 GPT-5.6 Sol、Terra 与 Luna。Global profile 以更低的每 token 价格提供最广的容量，而 Geo profile 让推理处理保持在既定地理范围内。借助这些更新，你可以在需求高峰期间提升吞吐量，同时选择符合你应用数据处理要求的地理边界。

**在模型用量增长时理解并控制推理开销。** [IAM 主体成本分摊](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-bedrock-expands-iam-principal-cost-allocation-bedrock-mantle/)帮助你把推理开销归因到用户、团队、项目、应用或成本中心，而 [AWS Cost Anomaly Detection](https://aws.amazon.com/about-aws/whats-new/2026/08/aws-cost-anomaly-detection-bedrock-3P/) 现在会监控 Amazon Bedrock 上的第三方基础模型开销，并在成本出现意外变化时提供根因分解。OpenAI 还宣布下调 Amazon Bedrock 上 GPT-5.6 系列的价格，包括 [Luna、Terra](https://aws.amazon.com/about-aws/whats-new/2026/07/openai-gpt-terra-luna-pricing-bedrock/) 与 [Sol](https://aws.amazon.com/about-aws/whats-new/2026/08/bedrock-openai-gpt-56-sol-reduced-pricing/)。这让你更清楚地看到哪些团队在推动开销、更早发现异常变化，并在 AI 负载扩张时做出更有依据的决策。

## **从检测到响应，更快的网络防御**

**为安全团队提供同时适用于防御性工作与经授权攻击性工作流的前沿 AI。** 来自 OpenAI 的 [Daybreak Red 与 Daybreak Blue](https://aws.amazon.com/about-aws/whats-new/2026/08/openai-daybreak-red-and-blue-on-amazon-bedrock/) 现已向符合条件的客户在 Amazon Bedrock 上提供。Daybreak Blue 支持漏洞发现、检测工程与事件响应等防御性工作。Daybreak Red 支持漏洞研究、漏洞利用复现与缓解措施开发等高级的、经授权的任务。你现在可以更快地调查并处置漏洞，同时施加更严格的身份验证、监控、访问控制以及零操作员访问的基础设施。

## **让 agent 保持在正轨上，完成更多工作**

**让生产级 agent 运行足够长的时间，以完成持续数天的工作。** [AgentCore runtime 实例](https://aws.amazon.com/about-aws/whats-new/2026/08/aws-bedrock-agentcore-runtime-instances-generally-available/)让你可以在专用的 Amazon EC2 计算上运行 agent，包括 GPU 加速、内存优化与计算优化实例，会话最长可持续 14 天。[AgentCore 还扩展](https://aws.amazon.com/about-aws/whats-new/2026/08/bedrock-agentcore-two-new-regions/)到美国西部（北加利福尼亚）与亚太（海得拉巴）。你现在可以把长时间运行的研究、编码与监控工作交给 agent，为每类负载匹配所需的计算资源，并让它运行在离所服务的用户与系统更近的地方。

**让 agent 更独立地行动，同时把其行为与花费控制在既定边界内。** [Temporal policy](https://aws.amazon.com/about-aws/whats-new/2026/08/temporal-policies-agentcore/)会针对 agent 已执行的操作来评估每一个动作，让你可以强制实施顺序、前置条件、审批关卡、调用之间的取值匹配以及数据新鲜度要求。速率限制按用户或群组控制请求数、推理 token 与并发连接。[AgentCore payments](https://aws.amazon.com/about-aws/whats-new/2026/08/bedrock-agentcore-payments-ga/)让 agent 能够访问并支付 API、MCP 资源与付费内容，由基础设施强制执行花费上限，并提供端到端可观测性。这些更新合在一起，让你可以给 agent 更多独立性，同时控制能发生什么、以什么顺序发生、以多高速率发生，以及在多大预算之内发生。

**为 agent 提供及时的上下文，同时不削弱数据边界。** [AgentCore 中的 Web Search](https://aws.amazon.com/about-aws/whats-new/2026/08/web-search-amazon-bedrock/)允许 agent 纳入或排除特定域名，并按发布日期过滤结果，帮助它们从已批准的来源获取最新信息。[AgentCore memory](https://aws.amazon.com/about-aws/whats-new/2026/08/agentcore-memory-json-payloads) 可以从活动日志、行为事件、系统事件以及其他结构化 JSON 数据中提取长期记忆，而不只限于对话内容。[细粒度访问控制 ](https://aws.amazon.com/about-aws/whats-new/2026/08/agentcorememory-fine-grained-access-control)随后可按用户或租户隔离这些记忆。现在，你可以让 agent 以可信来源为依据、从业务事件中构建记忆，并在不向每个应用添加自定义授权逻辑的情况下隔离这些上下文。

**查找并复用已获批准的 agent 与工具，而不是重建已有的东西**。 [AWS Agent Registry](https://aws.amazon.com/blogs/machine-learning/manage-agents-tools-and-skills-at-scale-with-aws-agent-registry/) 为你提供可搜索、受治理的目录，涵盖 agent、MCP 服务器、skill 与自定义资源。组织范围的发现能力可以跨已连接的 AWS 账户识别 AgentCore Runtime 上的 agent 与 AgentCore Gateway 上的 MCP 服务器，已批准的资源也可以出现在 Amazon Quick 中。你可以按意图或名称查找可信能力，在工作流之间复用它们，并减少 agent 泛滥与重复开发。

## **在受监管环境中拥有更多构建选择**

**把先进模型、agent 能力与跨模态检索带入受监管负载**。 [Claude Opus 5 ](https://aws.amazon.com/about-aws/whats-new/2026/07/claude-opus-5-aws-govcloud/)现已在 AWS GovCloud（美国）区域提供，并默认启用零数据保留。[OpenAI GPT-5.6 Terra 与 Luna](https://aws.amazon.com/about-aws/whats-new/2026/08/openai-gpt-terra-luna-govcloud/) 也已在 AWS GovCloud（美国）区域提供，具备百万 token 上下文窗口与 prompt caching。[Amazon Nova Multimodal Embeddings](https://aws.amazon.com/about-aws/whats-new/2026/08/amazon-nova-mme-govcloud/) 把跨文本、文档、图像、视频与音频的检索带到 AWS GovCloud（美国西部），而 [AgentCore memory、policy 与托管 harness](https://aws.amazon.com/about-aws/whats-new/2026/08/agentcore-memory-policy-harness-govcloud/) 则补充了托管上下文、控制与编排能力。这有助于你在 AWS GovCloud 中构建编码 agent、文档分析系统、多模态检索应用与受治理的 agent 工作流，并使用商业化区域中可用的更多同类能力。

## **把 AI agent 扩展到物理世界**

**通过一条连贯的工作流，从机器人演示走向训练与物理部署**。 [Strands Robots 连接 Strands Agents、LeRobot 与 Hugging Face 存储桶](https://huggingface.co/blog/amazon/strands-lerobot-streaming-data-loop/)，让你可以录制演示、以 LeRobot 格式流式传输数据集、训练策略，并把它们部署到仿真或物理硬件上，而无需转换底层数据。这让你可以用一种数据格式与一套 agent 工作流，从仿真一路迭代到物理部署。

**协调多台机器人与设备，而无需为每种环境重建 agent。**[Strands Robots 支持基于 mesh 的发现与协调](https://strandsagents.com/blog/robots-working-together-model-hardware-standard-strands-robots/)，可跨仿真设备与物理设备工作。Zenoh 连接同一局域网内的机器人，AWS IoT Core 则支持地理上分散的设备集群。Strands Robots 与 AWS 还参与了 Model Hardware Standard 的限量研究预览。这让你更容易在仿真中为多机器人工作流做原型、以更少的代码改动把它们迁移到本地与云连接的集群上，并探索针对物理设备的标准化控制。
