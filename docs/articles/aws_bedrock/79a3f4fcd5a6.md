# Amazon Nova Multimodal Embeddings 实用指南

Embedding 模型支撑着许多现代应用——从语义搜索和检索增强生成（RAG）到推荐系统和内容理解。然而，选择 embedding 模型需要仔细考量：一旦你已摄入数据，迁移到另一个模型就意味着要重新嵌入整个语料库、重建向量索引，并从零开始验证搜索质量。合适的 embedding 模型应当具备强劲的基线性能、能适配你的具体用例，并支持你现在和将来需要的模态。

[Amazon Nova Multimodal Embeddings](https://aws.amazon.com/nova/) 模型能够生成针对你具体用例的 embedding——从单模态的文本或图像搜索，到横跨文档、视频和混合内容的复杂多模态应用。

本文中，你将学习如何针对自己的具体用例使用 Amazon Nova Multimodal Embeddings：

- **简化架构**：通过跨模态搜索和视觉文档检索
- **优化性能**：选择与你的工作负载相匹配的 embedding 参数
- **实现常见模式**：通过媒体搜索、电商发现和智能文档检索的解决方案演练

本指南为在媒体资产搜索系统、商品发现体验和文档检索应用中配置 Amazon Nova Multimodal Embeddings 提供了实用的基础。

## 针对具体用例优化性能

Amazon Nova Multimodal Embeddings 模型通过 `embeddingPurpose` [参数设置](https://docs.aws.amazon.com/nova/latest/userguide/embeddings-schema.html)针对具体用例优化其性能。它具有不同的向量化策略：*检索系统模式*和*ML 任务模式*。

- **检索系统模式**（包括 `GENERIC_INDEX` 以及各种 `*_RETRIEVAL` 参数）面向信息检索场景，区分两个非对称阶段：*存储/INDEX* 和 *查询/RETRIEVAL*。检索系统类别与参数选择见下表。

| **阶段** | **参数选择** | **原因** |
| --- | --- | --- |
| **存储阶段**（所有类型） | `GENERIC_INDEX` | 针对索引和存储优化 |
| **查询阶段**（混合模态仓库） | `GENERIC_RETRIEVAL` | 在混合内容中搜索 |
| **查询阶段**（纯文本仓库） | `TEXT_RETRIEVAL` | 在纯文本内容中搜索 |
| **查询阶段**（纯图像仓库） | `IMAGE_RETRIEVAL` | 在图像中搜索（照片、插画等） |
| **查询阶段**（纯文档图像仓库） | `DOCUMENT_RETRIEVAL` | 在文档图像中搜索（扫描件、PDF 截图等） |
| **查询阶段**（纯视频仓库） | `VIDEO_RETRIEVAL` | 在视频中搜索 |
| **查询阶段**（纯音频仓库） | `AUDIO_RETRIEVAL`/td> | 在音频中搜索 |

- **ML 任务模式**（包括 `CLASSIFICATION` 和 `CLUSTERING` 参数）面向机器学习场景。该参数使模型能够灵活适配不同类型的下游任务需求。
- **CLASSIFICATION：** 生成的向量更适合区分分类边界，便于下游分类器训练或直接分类。
- **CLUSTERING：** 生成的向量更适合形成聚类中心，便于下游聚类算法。

## 构建多模态搜索与检索方案的演练

Amazon Nova Multimodal Embeddings 专为多模态搜索与检索而构建，而多模态搜索与检索正是多模态 agentic RAG 系统的基础。下图展示了如何构建多模态搜索与检索方案。

![使用 Amazon Nova Multimodal Embeddings 的 RAG 方案](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/20/ML-20106-image-1.png)

在前图所示的多模态搜索与检索方案中，原始内容（包括文本、图像、音频和视频）首先通过 embedding 模型转换为向量表示，以封装语义特征。随后，这些向量被存入向量数据库。用户查询同样会在同一向量空间内转换为查询向量。最相关的 top K 项的检索，通过计算查询向量与已索引向量之间的相似度来实现。该多模态搜索与检索方案可以封装为一个 [Model Context Protocol（MCP）](https://modelcontextprotocol.io/docs/getting-started/intro) 工具，从而便于在下图所示的多模态 agentic RAG 方案中访问。

![使用 Amazon Nova Multimodal Embeddings 的 agentic RAG 方案](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/20/ML-20106-image-2.png)

该多模态搜索与检索方案可以分为两个不同的数据流：

- 数据摄入
- 运行时搜索与检索

下文列出每个数据流中的常见模块，以及相关的工具和技术：

| **数据流** | **模块** | **描述** | **常用工具与技术** |
| --- | --- | --- | --- |
| 数据摄入 | 生成 embedding | 把输入（文本、图像、音频、视频等）转换为向量表示 | Embedding 模型。 |
| 将 embedding 存入向量存储 | 把生成的向量存入向量数据库或存储结构，以供后续检索 | 主流向量数据库 |  |
| 运行时搜索与检索 | 相似度检索算法 | 计算查询向量与已索引向量之间的相似度和距离，检索最接近的项 | 常见距离：余弦相似度、内积、欧氏距离；数据库对 k-NN 和 ANN 的支持，例如 Amazon OpenSearch k-NN |
| Top K 检索与投票机制 | 从检索结果中选择 top K 个最近邻，然后可能组合多种策略（投票、重排、融合） | 例如 top K 最近邻、关键词检索与向量检索的融合（混合搜索） |  |
| 集成策略与混合检索 | 组合多种检索机制或模态结果，例如关键词与向量，或文本与图像检索的融合 | 混合搜索（例如 Amazon OpenSearch hybrid） |  |

我们将探讨几个跨模态业务用例，并概要说明如何使用 Amazon Nova Multimodal Embeddings 应对它们。

### 用例：商品检索与分类

电商应用需要能够自动对商品图像进行分类并识别相似商品，而无需人工打标签。下图展示了一个高层方案：

![使用 Amazon Nova Multimodal Embeddings 进行商品分类](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/20/ML-20106-image-3.jpg)

- 使用 Amazon Nova Multimodal Embeddings 把商品图像转换为 embedding
- 把 embedding 和标签作为元数据存入向量数据库
- 查询新商品图像，找出 top K 个相似商品
- 对检索结果使用投票机制来预测类别

关键 embedding 参数：

| **参数** | **取值** | **用途** |
| --- | --- | --- |
| `embeddingPurpose` | `GENERIC_INDEX`（索引）和 `IMAGE_RETRIEVAL`（查询） | 针对商品图像检索优化 |
| `embeddingDimension` | `1024` | 平衡准确率与性能 |
| `detailLevel` | `STANDARD_IMAGE` | 适合商品照片 |

### 用例：智能文档检索

金融分析师、法务团队和研究人员需要在复杂多页文档中快速找到特定信息（表格、图表、条款），而无需人工逐页翻阅。下图展示了一个高层方案：

![使用 Amazon Nova Multimodal Embeddings 生成图形文档 embedding](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/20/ML-20106-image-4.jpg)

- 把每个 PDF 页面转换为高分辨率图像
- 为所有文档页面生成 embedding
- 把 embedding 存入向量数据库
- 接受自然语言查询并转换为 embedding
- 基于语义相似度检索 top K 个最相关页面
- 返回包含金融表格、图表或特定内容的页面

关键 embedding 参数：

| **参数** | **取值** | **用途** |
| --- | --- | --- |
| `embeddingPurpose` | `GENERIC_INDEX`（索引）和 `DOCUMENT_RETRIEVAL`（查询） | 针对文档内容理解优化 |
| `embeddingDimension` | `3072` | 为复杂文档结构提供最高精度 |
| `detailLevel` | `DOCUMENT_IMAGE` | 保留表格、图表和文本版式 |

在处理缺乏视觉元素的纯文本文档时，建议提取文本内容并采用分块（chunking）策略，索引时使用 `GENERIC_INDEX`，查询时使用 `TEXT_RETRIEVAL`。

### 用例：视频片段搜索

媒体应用需要高效的方法，以便用自然语言描述在庞大的视频库中定位特定视频片段。通过把视频和文本查询转换到统一语义空间中的 embedding，就可以用相似度匹配来检索相关视频片段。下图展示了一个高层方案：

![使用 Amazon Nova Multimodal Embeddings 进行视频片段搜索](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/20/ML-20106-image-5.jpg)

- 对短视频使用 `invoke_model` API、对长视频分段使用 `start_async_invoke` API，通过 Amazon Nova Multimodal Embeddings 生成 embedding
- 把 embedding 存入向量数据库
- 接受自然语言查询并转换为 embedding
- 从向量数据库中检索 top K 个视频片段，供复核或进一步剪辑

关键 embedding 参数：

| **参数** | **取值** | **用途** |
| --- | --- | --- |
| `EmbeddingPurpose` | `GENERIC_INDEX`（索引）和 `VIDEO_RETRIEVAL`（查询） | 针对视频索引与检索优化 |
| `embeddingDimension` | `1024` | 平衡精度与成本 |
| `embeddingMode` | `AUDIO_VIDEO_COMBINED` | 融合视觉与音频内容。 |

### 用例：音频指纹

音乐应用和版权管理系统需要识别重复或相似的音频内容，并把音频片段匹配到源音轨，用于版权检测和内容识别。下图展示了一个高层方案：

![使用 Amazon Nova Multimodal Embeddings 进行音频指纹](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/20/ML-20106-image-6.jpg)

- 使用 Amazon Nova Multimodal Embeddings 把音频文件转换为 embedding
- 把 embedding 连同流派和其他元数据存入向量数据库
- 用音频片段查询，找出 top K 个相似音轨
- 比较相似度分数以识别源匹配并检测重复

关键 embedding 参数：

| **参数** | **取值** | **用途** |
| --- | --- | --- |
| `embeddingPurpose` | `GENERIC_INDEX`（索引）和 `AUDIO_RETRIEVAL`（查询） | 针对音频指纹与匹配优化 |
| `embeddingDimension` | `1024` | 在音频相似度上平衡准确率与性能 |

## 结论

你可以使用 Amazon Nova Multimodal Embeddings 在统一的语义空间中处理多样化的数据类型。通过灵活的、面向用途优化的 embedding API 参数来支持文本、图像、文档、视频和音频，你可以构建更有效的检索系统、分类 pipeline 和语义搜索应用。无论你是在实现跨模态搜索、文档智能还是商品分类，Amazon Nova Multimodal Embeddings 都提供了从非结构化数据中大规模提取洞察的基础。现在就开始探索 [Amazon Nova Multimodal Embeddings: State-of-the-art embedding model for agentic RAG and semantic search](https://aws.amazon.com/cn/blogs/aws/amazon-nova-multimodal-embeddings-now-available-in-amazon-bedrock/) 和 [GitHub 示例](https://github.com/aws-samples/amazon-nova-samples/tree/main/multimodal-embeddings)，把 Amazon Nova Multimodal Embeddings 集成到你的应用中。
