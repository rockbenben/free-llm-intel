*GPT-6.1 Sol 现已在 Amazon Bedrock 上正式可用（GA），为频繁运行的编码、计算机使用和专业工作负载带来更强的推理。*

一个 AI 智能体要完成一项任务，可能需要收集信息、使用工具、尝试不同方法、从错误中恢复并验证结果。每一个决策都影响接下来发生什么。一次错误的转向就可能在智能体达到有用结果之前，增加模型交互、工具调用、延迟和人工干预。

AI 智能体的经济性是在整个任务上成形的。Token 价格影响每次交互的成本，而推理质量影响这项工作需要进行多少次交互、以及它们能否导向一个成功的结果。完成一项任务的总成本取决于这两者。

今天，GPT-6.1 Sol 在 Amazon Bedrock 上正式可用，运行在一个为大规模性能、安全和可靠性构建的推理引擎上。作为对 [GPT-6 Sol 的一次重大升级](https://openai.com/index/introducing-gpt-6-1-sol/)，它在智能体式编码、计算机使用和专业工作上带来强劲表现。据 OpenAI 称，它把[接近 Astra](https://aws.amazon.com/blogs/machine-learning/take-on-your-most-ambitious-work-with-gpt-6-astra-on-amazon-bedrock/) 的智能带到日常工作流中。

## 在智能体工作中应用更强的推理

### 更有效地驾驭软件工程工作流

软件工程展示了推理质量如何影响整条工作流。一个智能体可能需要理解一个陌生的仓库、追踪依赖、确定在哪里做改动，并验证实现。据 OpenAI 称，GPT-6.1 Sol 在 DeepSWE v1.1 上追平 GPT-6 Astra，而每任务成本大约只有五分之一。它还比 GPT-6 Sol 的最好成绩高出 6.4 个百分点，同时使用的推理强度低于那个 GPT-6 Sol 的结果。

Codex 把这份推理用于整个开发周期。你可以配置 Codex 在 Amazon Bedrock 上使用 GPT-6.1 Sol，处理跨越调查、实现和测试的工作。Codex 与仓库、本地文件、终端和开发工具协作，以编写功能、修复 bug 和运行测试。你可以通过桌面应用、CLI 和受支持的 IDE 访问 Codex。对于 AWS 开发，[Agent Toolkit for AWS](https://docs.aws.amazon.com/agent-toolkit/latest/userguide/quick-start.html) 通过一条终端命令把 Codex 连接到 AWS 文档、API 和服务。

### 在文档和工具之间把信息转化为行动

当智能体必须解读复杂文档、选择合适的工具并随条件变化而调整时，同样的推理能力也适用。据 OpenAI 称，GPT-6.1 Sol 在复杂文档分析上逼近 GPT-6 Astra，并在跨业务工具完成多步工作流上优于 GPT-6 Sol。

你可以借现成的体验或你自己构建的应用来应用这些能力。在桌面应用中，ChatGPT Work 可以跨文件和应用收集信息，并把它们变成成品交付物。使用受支持的 Amazon Bedrock API，你还可以构建合成文档的内部工具、跨系统协调工作的智能体，以及评估多个输入的面向客户的应用。

### 认清局限并尊重约束

跨工具有效工作还要求智能体认清何时某个工具失败了、某个动作受限了、或信息缺失了。把这些局限传达出来，能让应用或用户在智能体带着不完整信息继续或采取非预期动作之前介入。据 OpenAI 称，GPT-6.1 Sol 在关于透明度、用户意图和显式约束的苛刻评测上优于 GPT-6 Sol。

当使用受支持的 Amazon Bedrock API 构建时，你可以定义模型可用的工具。你还可以决定当某个动作需要批准或无法完成时你的应用如何响应。这些应用层的控制通过帮助你在某条工作流触及一个有重大影响的决策时让人参与其中，从而补充了模型层面的改进。

## 在 Amazon Bedrock 上运行 GPT-6.1 Sol

Amazon Bedrock 提供在生产中运行 GPT-6.1 Sol 所需的基础设施与控制。你可以通过 AWS Identity and Access Management (IAM) 策略管理模型访问，并通过 AWS CloudTrail 审计调用。为帮助把流量保持在你的网络边界内，你可以使用由 AWS PrivateLink 驱动的专有网络（VPC）端点。推理运行在硬件隔离、零运维人员访问（zero-operator access）的基础设施上，因此即使是 AWS 运维人员在推理期间也无法访问你的 prompt 和补全。

你的推理数据不会被用于模型训练，使用 GPT-6.1 Sol 也不要求你选择加入与 OpenAI 共享你的数据。对于[自动滥用检测](https://docs.aws.amazon.com/bedrock/latest/userguide/abuse-detection.html)，被分类器标记的流量会由 AWS 保留最多 30 天并以编程方式处理。你可以通过你的 AWS 账户团队申请零数据保留。详情见[数据保留](https://docs.aws.amazon.com/bedrock/latest/userguide/data-retention.html#data-retention-zdr)。

## 开始上手

GPT-6.1 Sol 以每任务一小部分的成本为智能体工作带来更强的推理，让你的智能体用更少的步骤达到正确答案。你可以在 [Amazon Bedrock 控制台](https://us-east-1.console.aws.amazon.com/bedrock/home?region=us-east-1#/)中开始使用 GPT-6.1 Sol，或通过受支持的 Amazon Bedrock API 以编程方式使用。有关受支持的 [AWS 区域](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html)、端点、API、特性、推理配置和定价的信息，参见 [Amazon Bedrock 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-openai.html)。
