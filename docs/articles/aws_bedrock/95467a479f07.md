# 为 Amazon Bedrock Flows 推出 agent 节点的多轮对话（预览）

[Amazon Bedrock Flows](https://docs.aws.amazon.com/bedrock/latest/userguide/flows.html) 提供直观的可视化构建器和一组 API，可将基础模型（FM）、[Amazon Bedrock](https://aws.amazon.com/bedrock/) 功能和 AWS 服务无缝连接起来，以大规模构建并自动化用户定义的生成式 AI 工作流。[Amazon Bedrock Agents](https://docs.aws.amazon.com/bedrock/latest/userguide/agents.html) 提供完全托管的解决方案，用于在 AWS 上创建、部署和扩展 AI agent。使用 Flows，你可以提供显式声明的、用户定义的决策逻辑来执行工作流，并把 Agents 作为 flow 中的一个节点加入，以便在工作流的某些步骤中利用 FM 基于上下文推理来动态解释和执行任务。

今天，我们很高兴宣布 Flows 中 agent 节点的多轮对话（预览），这是一项强大的新能力。这项新能力增强了 agent 节点的功能，使用户与 flow 之间能够进行动态的往复对话，就像 flow 执行过程中的自然对话一样。

借助这项新功能，当 agent 节点在继续之前需要用户澄清或提供额外上下文时，它可以智能地暂停 flow 的执行并请求用户提供特定信息。用户发送所需信息后，flow 会带着补充后的输入无缝恢复执行，并保持对话的 `executionId` 不变。

这带来了更具交互性、更能感知上下文的体验，因为节点可以根据用户的回复调整自身行为。下面的时序图展示了 flow 的各个步骤。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/15/ML-17916-image001.png)

多轮对话让开发者可以直接创建能够动态适应和推理的 agentic 工作流。对于那些单次交互不足以充分理解并满足用户需求的复杂场景，这一点尤其有价值。

本文讨论如何创建多轮对话，并探讨这项功能如何改变你的 AI 应用。

## 解决方案概览

设想 ACME Corp 是一家领先的虚构在线旅行社，正在使用 Flows 开发 AI 驱动的假日旅行规划器。他们在实施过程中遇到几个挑战：

- 他们的规划器无法进行动态对话，需要用户一次性提供所有行程细节，而不能追问后续问题
- 他们在编排复杂、多步骤的旅行规划流程时面临挑战，这些流程需要跨多个目的地协调航班、住宿、活动和交通，往往导致效率低下和客户体验不佳
- 当用户在规划过程中修改偏好或提出新约束时，他们的应用无法动态调整推荐

我们来看看 Flows 中新的多轮对话能力如何应对这些挑战，并让 ACME Corp 能够构建一个更智能、更能感知上下文、更高效的假日旅行规划器，真正提升客户的旅行规划体验。

该 flow 提供两条不同的交互路径。对于一般性的旅行咨询，用户会得到由 LLM 驱动的即时回答。然而，当用户想要搜索或预订航班与酒店时，他们会被连接到 agent，由 agent 引导他们走完流程，在收集必要信息的同时维持会话直到完成。该工作流如下图所示。

## 先决条件

对于本示例，你需要以下内容：

- 一个 AWS 账户，以及一个拥有获授权使用 Bedrock 的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色的用户。相关指导请参阅 [Amazon Bedrock 入门](https://docs.aws.amazon.com/bedrock/latest/userguide/getting-started.html)。请确保该角色包含使用 Flows 的权限，具体说明见 [Amazon Bedrock Flows 的先决条件](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-prereq.html)，以及使用 Agents 的权限，具体说明见[创建 Amazon Bedrock Agents 的先决条件](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-prereq.html)。
- 获得对用于调用和评估的模型的访问权限。相关指导请参阅[管理对 Amazon Bedrock 基础模型的访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)。
- [创建一个 Amazon Bedrock Agent](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-build-modify.html)，通过编排 FM、API 调用与用户对话之间的交互，为旅行社应用自动化该任务。我们的旅行 agent 提供四项关键预订功能：搜索可用航班、完成航班预订、查找合适的酒店住宿，以及完成酒店预订。有关如何创建旅行 agent 的示例，请参阅 [Agents for Amazon Bedrock 现已支持记忆保留和代码解释（预览）](https://aws.amazon.com/blogs/aws/agents-for-amazon-bedrock-now-support-memory-retention-and-code-interpretation-preview/)。请确保该 agent 已启用[用户输入功能](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-enable-user-input.html)。该设置让 agent 可以通过自然对话收集所有必需细节，即使初始请求并不完整。

## 创建多轮对话 flow

要创建多轮对话 flow，请完成以下步骤：

- 在 Bedrock 控制台的导航窗格中，选择 **Builder tools** 下的 **Flows**。
- 开始创建一个名为 `ACME-Corp-trip-planner` 的新 flow。

有关创建 Flow 的详细说明，请参阅 [Amazon Bedrock Flows 现已正式可用，具备更强的安全性与可追溯性](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-flows-is-now-generally-available-with-enhanced-safety-and-traceability/)。

Bedrock 提供不同的[节点类型](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-nodes.html)来构建你的 prompt flow。

- 选择 prompt 节点来评估输入意图。如果用户想要搜索或预订酒店或航班，它会把意图分类为 `categoryLetter=A`；如果用户在询问目的地信息，则分类为 `categoryLetter=B`。如果你使用 [Amazon Bedrock Prompt Management](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-management.html)，可以从那里选择 prompt。

对于这个节点，我们在 prompt 配置中使用以下消息：

```
You are a query classifier. Analyze the {{input}} and respond with a single letter:

A: Travel planning/booking queries for hotel and flights Example: "Find flights to London"
B: Destination information queries Example: "What's the weather in Paris?"

Return only 'A' or 'B' based on the primary intent.
```

在本示例中，我们选择了 Amazon 的 [Nova Lite](https://docs.aws.amazon.com/nova/latest/userguide/what-is-nova.html) 模型，并把 temperature 推理参数设为 0.1，以尽量减少幻觉并提升输出的可靠性。你也可以选择其他[可用的 Amazon Bedrock 模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/15/ML-17916-image003.png)

- 使用以下信息创建 Condition 节点，并与 Query Classifier 节点连接。对于这个节点，条件值为：  `Name: Booking Condition: categoryLetter=="A"`  ![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/15/ML-17916-image004.png)
- 为 LLM 指南调用创建第二个 prompt 节点。该节点的输入是 Condition 节点输出“If all conditions are false”的结果。要结束该 flow 分支，请添加一个 Flow output 节点，并把 prompt 节点的输出连接到它。  `You are AcmeGuide, an enthusiastic and knowledgeable travel guide. Your task is to provide accurate and comprehensive information about travel destinations to users. When answering a user's query, cover the following key aspects: - Weather and best times to visit - Famous local figures and celebrities - Major attractions and landmarks - Local culture and cuisine - Essential travel tips Answer the user's question {{query}}. Present the information in a clear and engaging manner. If you are unsure about specific details, acknowledge this and provide the most reliable information available. Avoid any hallucinations or fabricated content. Provide your response immediately after these instructions, without any preamble or additional text.`

在本示例中，我们选择了 Amazon 的 Nova Lite 模型，并把 temperature 推理参数设为 0.1，以尽量减少幻觉并提升输出的可靠性。

- 最后，创建 agent 节点并配置它使用此前创建的 agent。该节点的输入是 Condition 节点输出“Conditions Booking”的结果。要结束该 flow 分支，请添加一个 Flow output 节点，并把 agent 节点的输出连接到它。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/15/ML-17916-image005.png)
- 选择 **Save** 保存你的 flow。

## 使用 Amazon Bedrock Flows API

你也可以通过 [InvokeFlow API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_InvokeFlow.html) 以编程方式与 flow 交互，如下面的代码所示。在首次调用时，系统会自动生成一个唯一的 `executionId`，它会维持会话 1 小时。这个 `executionId` 对后续的 `executionId` API 调用至关重要，因为它为 agent 提供了维持对话历史和完成动作所需的上下文信息。

```
{
  "flowIdentifier": " MQM2RM1ORA",
  "flowAliasIdentifier": "T00ZXPGI35",
  "inputs": [
    {
      "content": {
        "document": "Book a flight to paris"
      },
      "nodeName": "FlowInputNode",
      "nodeOutputName": "document"
    }
  ]
}
```

如果 flow 中的 agent 节点判定需要向用户索取更多信息，来自 `InvokeFlow` 的响应流（`responseStream`）会包含一个 `FlowMultiTurnInputRequestEvent` 事件对象。该事件在 content（`FlowMultiTurnInputContent`）字段中带有请求的信息。

下面是一个 `FlowMultiTurnInputRequestEvent` JSON 对象示例：

```
{
  "nodeName": "Trip_planner",
  "nodeType": "AgentNode",
  "content": {
      "document": "Certainly! I'd be happy to help you book a flight to Paris. 
To get started, I need some more information:
1. What is your departure airport (please provide the IATA airport code if possible)?
2. What date would you like to travel (in YYYYMMDD format)?
3. Do you have a preferred time for the flight (in HHMM format)?
Once I have these details, I can search for available flights for you."
  }
}
```

由于在收到更多输入之前 flow 无法继续，flow 还会发出一个 `FlowCompletionEvent` 事件。flow 总是在 `FlowCompletionEvent` 之前发出 `FlowMultiTurnInputRequestEvent`。如果 `FlowCompletionEvent` 事件中 `completionReason` 的值为 `INPUT_REQUIRED`，说明 flow 在继续之前需要更多信息。

下面是一个 `FlowCompletionEvent` JSON 对象示例：

```
{
  "completionReason": "INPUT_REQUIRED"
}
```

再次调用 `InvokeFlow` API，把用户回复发送回 flow。请务必包含该对话的 `executionId`。

下面是一个 `InvokeFlow` API 的 JSON 请求示例，它提供 agent 节点所需的额外信息：

```
{
  "flowIdentifier": "MQM2RM1ORA",
  "flowAliasIdentifier": "T00ZXPGI35",
  "executionId": "b6450554-f8cc-4934-bf46-f66ed89b60a0",
  "inputs": [
    {
      "content": {
        "document": "Madrid on Valentine's day 2025"
      },
      "nodeName": "Trip_planner",
      "nodeInputName": "agentInputText"
    }
  ]
}
```

这种往复会一直持续，直到不再需要更多信息、agent 已具备完成用户请求所需的全部内容。当不再需要更多信息时，flow 会发出 `FlowOutputEvent` 事件，其中包含最终回答。

下面是一个 `FlowOutputEvent` JSON 对象示例：

```
{
  "nodeName": "FlowOutputNode",
  "content": {
      "document": "Great news! I've successfully booked your flight to Paris. Here are the details:

- Date: February 14, 2025 (Valentine's Day)
- Departure: Madrid (MAD) at 20:43 (8:43 PM)
- Arrival: Paris (CDG)

Your flight is confirmed."
  }
}
```

flow 还会发出一个 `FlowCompletionEvent` 事件。`completionReason` 的值为 `SUCCESS`。

下面是一个 `FlowCompletionEvent` JSON 对象示例：

```
{
  "completionReason": "SUCCESS"
}
```

要开始使用多轮调用，请使用以下示例代码。它使用同一个 `executionId` 处理后续交互，并在整个对话中维持上下文。你需要在 `FLOW_ID` 中指定 flow 的 ID，在 `FLOW_ALIAS_ID` 中指定其别名 ID（获取这些 ID 的说明请参阅[查看 Amazon Bedrock 中 flow 的信息](https://docs.aws.amazon.com/bedrock/latest/userguide/flows-view.html)）。

系统会按需提示输入额外内容，使用 `executionId` 在多次交互之间维持上下文，在执行所请求动作的同时提供连贯、连续的对话流。

```
"""
Runs an Amazon Bedrock flow and handles multi-turn interactions
"""
import boto3
import logging

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

def invoke_flow(client, flow_id, flow_alias_id, input_data, execution_id=None):
    """
    Invoke an Amazon Bedrock flow and handle the response stream.

    Args:
        client: Boto3 client for Bedrock
        flow_id: The ID of the flow to invoke
        flow_alias_id: The alias ID of the flow
        input_data: Input data for the flow
        execution_id: Execution ID for continuing a flow. Defaults to None for first run.

    Returns:
        Dict containing flow_complete status, input_required info, and execution_id
    """
    request_params = {
        "flowIdentifier": flow_id,
        "flowAliasIdentifier": flow_alias_id,
        "inputs": [input_data]
    }
    
    if execution_id:
        request_params["executionId"] = execution_id

    response = client.invoke_flow(**request_params)
    execution_id = response.get('executionId', execution_id)
    
    input_required = None
    flow_status = ""

    for event in response['responseStream']:
        if 'flowCompletionEvent' in event:
            flow_status = event['flowCompletionEvent']['completionReason']
        elif 'flowMultiTurnInputRequestEvent' in event:
            input_required = event
        elif 'flowOutputEvent' in event:
            print(event['flowOutputEvent']['content']['document'])
        elif 'flowTraceEvent' in event:
            print("Flow trace:", event['flowTraceEvent'])

    return {
        "flow_status": flow_status,
        "input_required": input_required,
        "execution_id": execution_id
    }

def create_input_data(text, node_name="FlowInputNode", is_initial_input=True):
    """
    Create formatted input data dictionary.
    
    Args:
        text: The input text
        node_name: Name of the node (defaults to "FlowInputNode")
        is_initial_input: Boolean indicating if this is the first input (defaults to True)
    
    Returns:
        Dict containing the formatted input data
    """
    input_data = {
        "content": {"document": text},
        "nodeName": node_name
    }

    if is_initial_input:
        input_data["nodeOutputName"] = "document"
    else:
        input_data["nodeInputName"] = "agentInputText"

    return input_data

def main():
    FLOW_ID = "MQM2RM1ORA"
    FLOW_ALIAS_ID = "T00ZXPGI35"
    
    session = boto3.Session(
        region_name='us-east-1'
    )
    bedrock_agent_client = session.client(
        'bedrock-agent-runtime', 
    )

    execution_id = None

    try:
        # Initial input
        user_input = input("Enter input: ")
        input_data = create_input_data(user_input, is_initial_input=True)

        while True:
            result = invoke_flow(
                bedrock_agent_client, 
                FLOW_ID, 
                FLOW_ALIAS_ID, 
                input_data, 
                execution_id
            )
        
            if result['flow_status'] == "SUCCESS":
                break
            
            if result['flow_status'] == "INPUT_REQUIRED":
                more_input = result['input_required']
                prompt = f"{more_input['flowMultiTurnInputRequestEvent']['content']['document']}: "
                user_input = input(prompt)
                # Subsequent inputs
                input_data = create_input_data(
                    user_input,
                    more_input['flowMultiTurnInputRequestEvent']['nodeName'],
                    is_initial_input=False
                )
            
            execution_id = result['execution_id']

    except Exception as e:
        logger.error(f"Error occurred: {str(e)}", exc_info=True)

if __name__ == "__main__":
    main()
```

## 结论

借助这项新能力，企业可以构建更直观、更易响应的 AI 解决方案，更好地满足客户需求。无论你是在开发旅行预订系统、客户服务还是其他对话式应用，Flows 中的多轮对话都提供了以最小复杂度创建复杂 AI 工作流所需的工具。
