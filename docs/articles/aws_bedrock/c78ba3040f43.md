# 用 Amazon Nova Sonic 让你的 Web 应用解放双手

图形用户界面已经独领风骚数十年，但如今的用户越来越期望能直接与应用对话。[Amazon Nova Sonic](https://aws.amazon.com/ai/generative-ai/nova/speech/) 是 Amazon Bedrock 推出的先进基础模型，它通过简单的流式 API 提供自然、低延迟的双向语音对话，帮助推动这一转变。用户可以借助语音和内嵌的智能与应用协同，而不只是操作它们。

本文展示我们如何为一个参考应用——Smart Todo App——加入真正的语音优先体验，把日常任务管理变成流畅的免手对话。

## 通过协作式 AI 语音 agent 重新思考用户交互

重要的易用性改进常常被排在后面——不是因为它们没有价值，而是因为在传统的鼠标键盘界面里实现起来很困难。智能批量操作、个性化工作流或语音引导辅助这类功能经常被讨论却又被推迟，原因就是 UI 复杂度。这里说的是把语音作为一种额外的通用交互方式——不是取代特定设备的控件，也不只是无障碍专用方案。语音带来了新的交互模式，同时也惠及屏幕阅读器等辅助技术的用户，为他们提供与应用交互的额外且包容的方式。

Amazon Nova Sonic 远不止一次性的语音命令。该模型可以规划多步骤工作流、调用后端工具，并在多轮之间保持上下文，让你的应用能与用户*协作*。

下表展示了来自不同应用领域（如任务管理、CRM 和服务台）的语音交互。

| 语音交互（示例语句） | 意图 / 目标 | 系统动作 / 行为 | 确认 / UX |
| --- | --- | --- | --- |
| 把我所有的任务都标记为完成。 | 批量完成任务 | 查找用户的未完成任务 → 标记为完成  → 若已配置则归档 | 12 个未完成任务已全部标记为完成。 |
| 为准备 Q3 预算制定一个计划：拆成步骤、指派负责人并设定截止日期。 | 创建多步骤工作流 | 生成计划 → 创建任务 → 指派负责人 → 设定截止日期 → 呈现审阅选项 | 已创建含 6 个任务的计划。是否通知负责人？ |
| 找出 APAC 地区 ARR 超过 $1M 的企业线索，并起草个性化外联内容。 | 构建目标潜在客户清单并起草外联内容 | 查询 CRM → 汇总筛选后的清单 → 起草个性化消息供审阅 | 已起草 24 条个性化外联消息。是否审阅并发送？ |
| 给过去 24 小时内开启的所有 P1 工单排定优先级，并指派给值班人员。 | 分诊与指派 | 筛选工单 → 设置优先级 → 指派给值班人员 → 记录变更 | 12 个 P1 工单已排定优先级并指派给值班团队。 |

Amazon Nova Sonic 理解意图、调用所需的 API 并确认结果——不需要表单。这有助于营造一个效率倍增、上下文即界面的环境。重点不是取代传统 UI，而是通过语音解锁新的能力。

## 示例应用一览

在 Smart Todo 参考应用中，用户可以创建待办列表，并管理列表中的笔记。该应用提供了聚焦而灵活的界面，用于任务跟踪与笔记整理。加入语音后，应用变成免手体验，解锁更自然、更高效的交互。在 Smart Todo App 中，用户可以说：

- “添加一条笔记，跟进项目章程。”
- “归档所有已完成的任务。”

每个命令背后都是聚焦的动作——例如新建笔记、整理内容或更新任务状态——通过语音执行，体验自然且高效。

## Amazon Nova Sonic 双向 API 如何工作

Amazon Nova Sonic 实现了实时双向流式架构。用 `InvokeModelWithBidirectionalStream` 发起会话之后，音频输入和模型响应会在一条打开的流上同时流动：

- **会话开始** – 客户端发送一个 `sessionStart` 事件，其中包含模型配置（例如 temperature 和 topP）。
- **prompt 与内容开始** – 客户端发送结构化事件，指明接下来的数据是音频、文本还是工具输入。
- **音频流式传输** – 麦克风音频以 base64 编码的音频输入事件形式流式发送。
- **模型响应** – 模型处理输入时，会异步流式返回以下响应：  自动语音识别（ASR）结果 工具调用 文本响应 用于播放的音频输出
- **会话关闭** – 通过发送 `contentEnd`、`promptEnd` 和 `sessionEnd` 事件显式关闭对话。

Nova Sonic 架构图

你可以用这种事件驱动的方式打断助手（barge-in）、启用多轮对话，并支持实时自适应。

## 方案架构

本方案采用无服务器应用架构模式，其中 UI 是一个 [React 单页](https://react.dev/)应用。该 React 单页应用与服务端容器中运行的后端 Web API 集成。Smart Todo App 部署在一套可扩展且注重安全的 AWS 架构上，专为支持实时语音交互而设计。下图给出架构概览，展示各 AWS 服务如何协同满足语音应用的双向流式需求。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/11/ArchitectureDiagram.png)

关键 AWS 服务包括：

- [Amazon Bedrock](https://aws.amazon.com/bedrock/) – 通过 Amazon Nova Sonic 基础模型支撑实时双向语音交互。
- [Amazon CloudFront](https://aws.amazon.com/cloudfront/) – 一种[内容分发网络（CDN）](https://aws.amazon.com/what-is/cdn/)，以低延迟在全球分发应用。它把 /（根路径）流量路由到托管在 Amazon S3 存储桶上的 React 应用，并把 `/api` 和 `/novasonic` 流量路由到 Application Load Balancer。
- [AWS Fargate for Amazon Amazon Elastic Container Service（Amazon ECS](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/AWS_Fargate.html)) – 运行后端容器化服务，用于处理 WebSocket 与 REST API，能够支撑长时间运行的双向流。
- [Application Load Balancer（ALB）](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/introduction.html) – 把 Web 流量 `/api`（HTTPS REST API 调用）转发到后端 ECS 服务，处理 Smart Todo App 的 API；并把 `/novasonic`（[WebSocket 连接](https://en.wikipedia.org/wiki/WebSocket)）转发到负责用 Amazon Nova Sonic 管理实时语音流的 ECS 服务。
- [Amazon Virtual Private Cloud（Amazon VPC）](https://docs.aws.amazon.com/vpc/) – 为后端服务提供网络隔离与安全。公有子网承载 Application Load Balancer（ALB），私有子网承载运行 WebSocket 和 REST API 的 ECS Fargate 任务。
- [NAT Gateway](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-nat-gateway.html) 让私有子网中的 Amazon ECS 任务能更安全地连接互联网，以完成诸如 Cognito JWT token 校验端点之类的操作。
- [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/) – 托管用于用户交互的 React 前端
- [AWS WAF](https://aws.amazon.com/waf/) – 帮助保护 Application Load Balancer（ALB）免受恶意流量影响，并在应用层执行安全规则。
- [Amazon Cognito](https://aws.amazon.com/cognito/) – 管理身份认证并签发 token。
- [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) – 存储应用数据，例如待办列表和笔记。

## 部署方案

为便于评估该方案，我们提供了 Smart Todo App 的示例代码，位于 [GitHub 仓库](https://github.com/aws-samples/sample-amazon-q-developer-vibe-coded-projects/tree/main/NovaSonicVoiceAssistant)。

Smart Todo App 由多个独立的 Node.js 项目组成，包括一个 CDK 基础设施项目、一个 React 前端应用以及后端 API 服务。部署工作流会确保各组件被正确构建，并与 Amazon Cognito、Amazon DynamoDB 和 Amazon Bedrock 等 AWS 服务集成。

### 前提条件

- [AWS 账户](https://signin.aws.amazon.com/signup?request_type=register)，具备有助于落实安全最佳实践的适当权限，包括[最小权限](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html#grant-least-privilege)。
- 本地已安装并运行 [Docker Engine](https://docs.docker.com/engine/)，以便在本地构建容器镜像。
- 已使用 AWS 管理员凭证配置好 [AWS CLI](https://aws.amazon.com/cli/)。
- 已安装 [Node.js](https://nodejs.org) >= 20.x 和 npm。
- 已在 Amazon Bedrock 中启用 Amazon Nova Sonic。更多信息，请参阅[添加或移除对 Amazon Bedrock 基础模型的访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access-modify.html)。

### 部署步骤

- 克隆以下仓库：

```
git clone https://github.com/aws-samples/sample-amazon-q-developer-vibe-coded-projects.git
cd NovaSonicVoiceAssistant
```

- 首次部署时，使用以下自动化脚本：

```
npm run deploy:first-time
```

该脚本会：

- 使用 npm（node package manager）安装依赖
- 使用本地已安装的 docker engine 构建组件和容器镜像
- 使用 CDK 部署基础设施（CDK BootStrap ==> CDK Synth ==> CDK Deploy）
- 用 Amazon Cognito 的设置更新环境变量
- 用更新后的环境变量重新构建 UI
- 部署最终基础设施（CDK Deploy）
