# 使用 Amazon Quick 和 Amazon Bedrock 重新思考 RAG 的访问控制

企业组织正在采用检索增强生成 (RAG) 来从 Microsoft SharePoint、Google Drive 和 Atlassian Confluence 等公司知识源中获取见解。然而，这些知识源包含受复杂权限结构控制的敏感信息。确保人工智能生成的答案尊重这些权限是企业人工智能中最困难的挑战之一。

在本文中，我们将探讨 [Amazon Quick](https://aws.amazon.com/quick/) 和 [Amazon Bedrock 知识库](https://aws.amazon.com/bedrock/knowledge-bases/) 如何通过实时访问控制列表 (ACL) 强制执行、在查询时直接向权威来源验证权限来解决这一挑战。

## 业务问题

考虑以下场景：SharePoint 网站所有者为其组织创建知识库。跨多个部门的团队成员使用人工智能助手从这个知识库中获取答案。关键要求是每个团队成员只能从他们有权访问的文档中接收人工智能生成的见解。

这是一个普遍的企业挑战。组织希望在不损害现有安全状况的情况下，实现对人工智能驱动的见解的民主化访问。人工智能响应中出现的单个未经授权的文档可能会泄露机密战略文档、未发布的财务数据或敏感的人力资源信息。

## 为什么现有方法存在不足

RAG 访问控制的常见方法是使用复制和过滤方法来强制执行文档级权限。它通常是这样工作的：

- 数据源连接器（例如 SharePoint 连接器）将 ACL 拉取作为定期同步作业的一部分。
- ACL 从数据源复制并作为属性存储在索引中。
- 在查询时，AI 系统将登录用户映射到存储的 ACL 属性并相应地过滤结果。

虽然这种方法表面上看起来合理，但它存在三个根本弱点。

## 问题 1：人工智能系统不是事实的来源

在这个模型中，人工智能系统单独负责执行，而不是权限的权威来源。这需要数据连接器跨各种数据源准确复制复杂的、特定于源的 ACL 逻辑。每个数据源都有自己独特的权限模型。跨数十个连接器映射继承层次结构、组成员资格、条件访问策略和拒绝规则是一项容易出错的工作。

## 问题 2：过时的权限会造成安全漏洞

一般来说，数据连接器支持按需或按客户定义的计划运行的基于拉取的同步。这些 AI 解决方案中的 ACL 是上次同步运行时的快照。一些解决方案使用基于事件的更新，但这并不普遍适用。例如，当组成员身份发生更改时，像 Confluence 这样的数据源不会发出事件。在同步之间，访问权限被撤销的用户可能仍会从他们不应再看到的文档中收到 AI 答案。

## 问题 3：不断发展的数据源功能

数据源定期更改或引入新机制来控制对内容的访问。 SharePoint 中的新权限功能或对 Google Drive 共享模型的更改可能会在 ACL 映射逻辑中造成间隙。这可能会暴露内容，直到连接器更新为止。

## AWS 如何解决这个问题：实时 ACL 实施

为了应对这些挑战，我们实施了实时 ACL 检查，作为 Amazon Quick 和 Amazon Bedrock 知识库现有预检索 ACL 过滤之上的额外安全层。这确保系统通过在查询时直接与权威来源检查权限来强制执行最新的访问控制。这可以避免依赖可能过时或错误映射的 ACL 数据。

## 工作原理：Google Drive 示例

当用户向使用 Google Drive 知识库的 Amazon Quick 代理提交查询时，系统会分两个阶段强制执行访问控制：

### 第 1 阶段：预检索过滤

Amazon Quick 针对向量索引执行语义搜索，以查找最相关的文档段落。系统应用已存储在索引中的访问控制列表。这将产生一组初步的候选文件。此阶段是必要的，因为对索引中每个文档的实时 API 调用在规模上成本太高。

### 第二阶段：实时验证

Amazon Quick 通过调用 Google Drive API 实时验证候选文档。它使用管理员提供的服务帐户凭据通过模拟生成用户特定的访问令牌。 Google Drive 维护与每个文档关联的访问控制列表的真实来源。用户无权访问的文档将从检索的结果集中排除。只有经过验证和授权的文档段落才会作为上下文传递到大语言模型 (LLM)。该模型使用这些知识来生成响应。

这种两阶段方法平衡了性能与安全性。它使用缓存的 ACL 来提高效率，同时通过实时检查促进正确性。除了 ACL 执行之外，Amazon Bedrock 还提供负责任的 AI 控制。其中包括用于内容过滤的 Amazon Bedrock Guardrails、用于减少幻觉的接地检查，以及用于帮助组织负责任地部署生成式 AI 应用程序的可配置安全策略。

## 为什么这对您的组织很重要

这种方法具有三个主要优点：

- **始终有效的权限** – 使用 RAG 产品时，同步周期之间不再存在安全间隙。如果员工的访问权限被撤销，这种变化会在几分钟内（而不是几小时或几天）反映在人工智能响应中。
- **扩展的信心** – 组织可以扩展其知识库覆盖范围，因为知道实时 ACL 检查会验证每个查询的权威来源的权限，无论数据源如何。
- **减少操作负担** – 您无需担心同步频率。
