# 使用 Amazon Bedrock、LangChain 和 Streamlit 构建医疗报告分析 dashboard

在医疗健康领域，快速分析和解读医疗报告的能力对医疗服务提供者和患者都至关重要。医疗报告虽然包含有价值的信息，但由于其复杂性以及分析过程耗时，往往未被充分利用。这种复杂性体现在几个方面：解读多个参数及其之间的关系（例如各种血细胞计数）、将检测结果与标准参考范围进行对比，以及需要分析健康参数随时间变化的趋势。为应对这一挑战，我们构想了一个医疗报告分析 dashboard，通过一套示例实现来展示医疗服务提供者可以如何增强与医疗数据的交互。

在本文中，所创建的 dashboard 是一个汇聚式解决方案，把 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 先进的 AI 能力、[LangChain](https://www.langchain.com/) 的文档处理能力和 [Streamlit](https://github.com/streamlit/streamlit) 直观的用户界面结合在一起。借助这些技术，我们构建了一个系统，它不仅能够存储和展示医疗报告，还能通过自然语言交互和动态可视化主动帮助解读这些报告。

## 解决方案概览

该解决方案的基础是通过 Amazon Bedrock 可用的多种大语言模型，包括 [Anthropic 的 Claude](https://aws.amazon.com/bedrock/claude/) 系列和 [Amazon Nova Foundation Models](https://aws.amazon.com/ai/generative-ai/nova/)。你可以从 Claude Opus 4.1、Claude 3.7 Sonnet、Amazon Nova Pro 等选项中选择，每个模型都针对不同的性能与能力需求做了优化。所选模型在具备医疗上下文感知的情况下处理自然语言查询，从而能够对医疗数据做详细解读。借助这种灵活性，你可以根据具体需求在准确性、速度和成本等因素之间取得平衡。LangChain 的文档处理能力进一步增强了这一点，它负责管理检索系统并保持对话上下文，促成准确且相关的响应。

该解决方案的数据流始于安全存储在 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/)中的医疗报告，随后通过 LangChain 的文档处理系统进行处理。当你与 Streamlit 前端交互时，你的查询由 Amazon Bedrock 分析，同时 LangChain 维护对话上下文并管理文档检索。系统处理这些信息，并通过一个带有交互式可视化的直观界面呈现结果。

这些可视化由 [Plotly](https://plotly.com/) 驱动，包括清晰展示正常值与实际值对比的范围对比图、用于参数比较的柱状图，以及用于跟踪随时间变化趋势的趋势线。Streamlit 界面把一切串联起来，在管理用户会话状态和对话历史的同时，提供与 AI 系统的实时交互。这种全面的方式有助于确保医疗专业人员能够通过自然语言查询快速访问、分析和解读其医疗报告，同时查看辅助的可视化数据。

下面给出该解决方案的架构图，共分为四层：

- 用户界面层：Streamlit Web App、聊天界面、Plotly 数据可视化
- 处理层：LangChain 文档处理、对话检索链、数据解析
- AI/ML 层：Amazon Bedrock、Amazon Bedrock embeddings、内存向量存储
- 存储层：用于存储医疗报告的 Amazon S3、对话缓冲区记忆（conversation buffer memory）

## 前置条件

在部署医疗报告分析 dashboard 之前，你需要：

- 一个已启用 [Amazon Bedrock 访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)的 [AWS 账户](https://www.google.com/search?client=firefox-b-d&channel=entpr&q=aws+account+create+account)
- 具备 [Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/security-iam.html) 和 [Amazon S3](https://docs.aws.amazon.com/AmazonS3/latest/userguide/security-iam.html) 的 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam/)权限
- [已安装并配置好 AWS Command Line Interface（AWS CLI）](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)
- 一个用于存储 csv 格式医疗报告的 [Amazon S3](https://aws.amazon.com/pm/serv-s3/) 桶。请按照[创建通用存储桶](https://docs.aws.amazon.com/AmazonS3/latest/userguide/create-bucket-overview.html)的说明创建桶。提供的示例报告位于以下 [repository](https://github.com/aws-samples/sample-medical-analysis-dashboard)。上传报告所需的命令见部署章节。
- Python 3.9 或更高版本，并带有 pip
- [Amazon Bedrock 模型的访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)。该解决方案支持多种模型，包括：[Anthropic 的 Claude](https://aws.amazon.com/bedrock/anthropic/) 系列（Opus 4.1、3.7 Sonnet、Sonnet 4 等）[Amazon Nova foundation model](https://aws.amazon.com/ai/generative-ai/nova/) 系列（Nova Pro 和 Nova Lite）

本项目我们将使用 Python 虚拟环境（venv），以提供干净、隔离的环境。虚拟环境有助于避免项目之间的包冲突，并让依赖管理更加直接。虽然我们使用的是 Python 内置的 venv，但你也可以改用 [miniconda](https://www.anaconda.com/docs/getting-started/miniconda/main) 或其他环境管理器。

## 部署

要开始部署，请在本地机器上安装必要的包。

- 克隆仓库：

```
git clone https://github.com/aws-samples/sample-medical-analysis-dashboard.git
```

- 进入项目目录。
- 创建并激活虚拟环境（推荐）：

在 Mac/Linux 上：

```
python3 -m venv venv
source venv/bin/activate
```

在 Windows 上：

```
python3 -m venv venv
venv\Scripts\activate
```

- 将 pip 更新到最新版本：

```
python3 -m pip install --upgrade pip
```

- 安装所需的包：

```
pip install -r requirements.txt
```

项目依赖列在 `requirements.txt` 中：

- boto3
- streamlit
- unstructured
- langchain-aws
- langchain-community
- pandas
- plotly
- numpy
- docarray

这些包将处理 AWS 集成、Web 界面、数据处理和可视化。它们会在部署过程中安装到我们的虚拟环境中。这样的设置有助于确保各组件在虚拟环境中被正确安装并相互隔离，以获得最佳性能。

- 按照[为 AWS CLI 配置环境变量](https://docs.aws.amazon.com/cli/v1/userguide/cli-configure-envvars.html)来配置 AWS 凭证。

```
export AWS_ACCESS_KEY_ID='your-access-key'
export AWS_SECRET_ACCESS_KEY='your-secret-key'
```

- 将示例 CSV 文件上传到前置条件章节中创建的 S3 桶：

我们的仓库包含两个示例文件：

- `basic_test.csv`：包含 15 个参数的完整血液检测
- `blood_test.csv`：包含基本参数

`basic_test.csv` 的内容如下：

```
Parameter,Value,Reference_Range,Unit
Hemoglobin,13.8,13.5-17.5,g/dL
RBC,4.8,4.5-5.9,million/µL
WBC,8500,4000-11000,cells/µL
Glucose,92,70-100,mg/dL
Creatinine,1.0,0.7-1.3,mg/dL
```

运行以下命令将示例文件上传到 S3 桶：

```
aws s3 cp basic_test.csv s3://BUCKET_NAME/

aws s3 cp blood_test.csv s3://BUCKET_NAME/
```

转到 app.py 第 68 行，将 app.py 中的 S3 桶名称改为与你实际的 S3 桶名称一致。

```
BUCKET_NAME = "your-bucket-name"
```

- 运行应用：

```
streamlit run app.py
```

dashboard 将在 `http://localhost:8501` 上可用。现在你就可以通过 Web 界面与你的医疗报告进行交互了。

## 安全考量

虽然我们当前的部署使用虚拟医疗数据用于演示，但对于真实的医疗健康应用，考虑安全与合规措施至关重要。以下是在生产环境中增强安全性的建议：

**数据隐私：**

- **HIPAA 合规**：实施[符合 HIPAA](https://aws.amazon.com/compliance/hipaa-compliance/) 的做法，包括访问控制和审计跟踪。
- **加密**：对静态数据使用 [Amazon S3 服务端加密](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingServerSideEncryption.html)（SSE-S3），对传输中的数据使用 TLS。
- **个人可识别信息（PII）保护**：对 PII 字段应用[数据脱敏](https://aws.amazon.com/what-is/data-masking/)。通过[基于角色的权限](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies.html)控制数据访问。[使用 CloudWatch Logs 和 Amazon S3 监控模型调用](https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html)。配置 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/)。你还可以使用 guardrails 限制模型提供医疗建议、处方或诊断，把响应限定在数据分析和解读范围内。
- **Amazon S3 配置**：用以下 S3 桶设置保护你的医疗数据存储 启用[版本控制](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html)以维护完整的审计跟踪，并防止意外删除或修改 在桶和账户两个层级[阻止公共访问](https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-control-block-public-access.html) 实施严格的[桶策略](https://docs.aws.amazon.com/AmazonS3/latest/userguide/example-bucket-policies.html)，限制仅特定 IAM 角色可以访问，并强制传输加密 为上传到桶的所有对象配置[加密](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingEncryption.html)（AES-256 或 KMS）

**推荐的 AWS 安全实施方式：**

- [IAM 角色](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html)：按照最小权限原则为每项服务创建特定的 IAM 角色
- [S3 桶加密](https://docs.aws.amazon.com/AmazonS3/latest/userguide/bucket-encryption.html)：为所有对象启用默认的 AES-256 加密
- [Amazon Bedrock API 访问](https://docs.aws.amazon.com/bedrock/latest/userguide/getting-started-api.html)：使用 IAM 角色和恰当的 API 密钥管理来保护访问
- **审计日志**：启用 [AWS CloudTrail](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-user-guide.html) 以全面记录 API 调用。[记录 S3 桶上的数据访问事件](https://docs.aws.amazon.com/AmazonS3/latest/userguide/enable-cloudtrail-logging-for-s3.html)、[Amazon Bedrock API 调用](https://docs.aws.amazon.com/bedrock/latest/userguide/logging-using-cloudtrail.html)以及 IAM 用户和角色的活动 [监控并记录](https://docs.aws.amazon.com/AmazonS3/latest/userguide/monitoring-overview.html) S3 桶配置变更和策略更新等管理事件

以上为通用建议。对于生产级医疗健康应用，请咨询安全专家并进行风险评估，以确保满足所有相关合规标准。

- [删除创建的 Amazon S3 桶](https://docs.aws.amazon.com/AmazonS3/latest/userguide/delete-bucket.html)
- 删除创建的本地资源：

```
# Deactivate virtual environment
deactivate
# Remove project directory and virtual environment
rm -rf medical-analysis-dashboard/
```

## 结论

在本文中，我们演示了一个概念性的医疗报告分析 dashboard 的开发过程，它结合了 Amazon Bedrock 的 AI 能力、LangChain 的文档处理能力和 Streamlit 的交互式可视化功能。该解决方案通过由 Amazon Bedrock 提供的大语言模型驱动的上下文感知聊天系统，以及健康参数的动态可视化，把复杂的医疗数据转化为易于理解的洞察。

本项目展示了云与 AI 技术如何应用于医疗健康分析，使医疗报告的解读更加直观和高效。虽然我们的实现使用虚拟数据用于演示，但该架构为构建安全、符合合规要求的医疗健康应用提供了基础，这些应用可以进一步增强以满足医疗健康组织的要求和安全规程。
