# Amazon Bedrock 如何为 AWS 下一代客户计划提供支持

在 AWS，我们的销售团队会创建以客户为中心、称为*客户计划（account plan）*的文档，以深入了解每个 AWS 客户的独特目标与挑战，帮助客户团队提供量身定制的指导与支持，加速客户在 AWS 上取得成功。随着业务扩展，客户计划流程变得更加复杂，需要详细的分析、评审和跨团队对齐，才能为客户交付有意义的价值。这种复杂性，加上其中涉及的人工评审工作，带来了显著的运营开销。为应对这一挑战，我们于 2025 年 1 月推出了 Account Plan Pulse，这是一款旨在简化和增强客户计划流程的生成式 AI 工具。实施 Pulse 后，计划质量同比提升 37%，而完成、评审和批准计划的总体时间减少了 52%。

本文分享我们如何使用 [Amazon Bedrock](https://aws.amazon.com/bedrock) 构建 Pulse，以减少评审时间并提供可执行的客户计划摘要，便于协作与阅读，从而帮助 AWS 销售团队更好地服务客户。Amazon Bedrock 是一项全面、安全且灵活的服务，用于构建生成式 AI 应用和 agent。它将你连接到领先的基础模型（FM）、用于部署和运营 agent 的服务、用于微调、防护和优化模型的工具，以及将应用连接到最新数据的知识库，让你拥有从实验快速迈向真实部署所需的一切。

## 规模与复杂性不断上升带来的挑战

随着 AWS 持续增长和演进，我们的客户计划流程需要做出调整，以应对不断上升的规模与复杂性。在可通过 Amazon Bedrock 获得企业级大语言模型（LLM）之前，我们曾探索用基于规则的文档处理来评估客户计划，但事实证明它不足以处理细微的内容和不断增长的文档量。到 2024 年，三个关键挑战浮现出来：

- **计划质量与格式参差不齐** – 由于团队遍布众多 AWS 区域并服务不同行业的客户，客户计划在结构、细节和格式上自然出现了差异。这种不一致使得难以确保关键客户需求被有效且一致地描述。此外，客户计划质量的评估本质上带有主观性，严重依赖人工判断来评估每份计划的深度、战略对齐和客户关注度。
- **资源密集的评审流程** – 质量评估过程依赖销售领导层的人工评审。虽然细致，但这些评审占用了本可用于战略性客户投入的宝贵时间。随着业务规模扩大，这种做法在计划审批和实施上造成瓶颈。
- **知识孤岛** – 我们发现了跨团队协作中尚未发掘的潜力。开发用于提取和共享知识的方法，可以把单个客户计划转化为集体最佳实践，从而更好地服务客户。

## 解决方案概述

为应对这些挑战，我们设计了 Pulse——一个使用 Amazon Bedrock 分析和改进客户计划的生成式 AI 解决方案。下图展示了该解决方案的工作流。

[![解决方案概述](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/01/ML-19090_solution_overview.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/01/ML-19090_solution_overview.png)

该工作流包含以下步骤：

- 客户计划的叙述性内容通过异步批处理 pipeline 按计划从我们的 CRM 系统中拉取。
- 数据流经一系列处理阶段：预处理以结构化和规范化数据并生成元数据。LLM 推理以分析内容并生成洞见。验证以确认质量与合规性。
- 结果被安全存储，用于报告和仪表板可视化。

我们已将 Pulse 直接与现有销售工作流集成，以最大化用户采用率，并建立了持续优化性能的反馈回路。下图展示了解决方案架构。

[![解决方案架构](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/01/ML-19090_solution-architecture.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/01/ML-19090_solution-architecture.png)

在以下各节中，我们将更详细地探讨该解决方案的关键组件。

### 数据摄取

我们实现了一个批处理 pipeline，将客户计划从我们的 CRM 系统抽取到 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）存储桶中。调度器按固定节奏触发该 pipeline，便于对最新信息进行持续分析。

### 预处理

考虑到客户计划的动态特性，它们按每日快照处理，每次运行只包含有更新的计划。预处理在两个层面进行：一个 ETL（抽取、转换、加载）流程层，用于组织需要处理的文件；以及在模型调用之前作为输入验证的一部分。这种使用计划最后修改日期的方法，对于避免对相同内容重复运行至关重要。预处理 pipeline 负责每日调度作业，读取以 Parquet 文件形式存储在 Amazon S3 中的客户计划数据，从 HTML 字段中抽取文本内容，并为每份文档生成结构化元数据。为优化处理效率，系统会比较文档时间戳，仅处理最近修改过的计划，从而显著降低计算开销和成本。随后，处理后的文本内容和元数据被转换为标准化格式，并以 Parquet 文件形式写回 Amazon S3，形成一个可供 LLM 分析的干净数据集。

### 使用 Amazon Bedrock 进行分析

我们解决方案的核心使用 Amazon Bedrock，它提供多样的模型选择与控制、数据定制、安全与 guardrail、成本优化以及编排能力。我们使用 Amazon Bedrock 的 FM 执行两项关键功能：

- **客户计划评估** – Pulse 依据 10 个业务关键类别评估计划，生成标准化的 Account Plan Readiness Index。这种自动评估会识别改进领域，并给出具体的改进建议。
- **可执行的洞见** – Amazon Bedrock 提取并综合跨计划的模式，识别客户的战略重点和市场趋势，而这些信息原本可能孤立地停留在单份文档中。

我们通过异步批处理实现这些能力，其中评估和摘要工作负载独立运行。评估流程让每个客户账户经过 27 个特定问题，并配有定制的控制 prompt；摘要流程则生成主题概览，便于阅读和知识共享。

在此实现中，我们使用带 [schema 约束](https://docs.anthropic.com/en/docs/test-and-evaluate/strengthen-guardrails/increase-consistency#example-generating-consistent-market-intelligence)的结构化输出 prompt，以提供与我们的报告工具集成的一致格式。

### 验证

我们的验证框架包含以下组件：

- 输入与输出验证作为 [OWASP 大语言模型应用十大风险](https://owasp.org/www-project-top-10-for-large-language-model-applications/)的一部分至关重要。通过引入必要的 guardrail 和 prompt 验证，输入验证必不可少；输出验证则确保结果是结构化的，并被约束在预期的响应范围内。
- 依据既定业务规则进行自动化质量与合规检查。
- 对未达到质量阈值的输出进行额外评审。
- 随时间推移提升系统准确性的反馈机制。

### 存储与可视化

该解决方案包含以下存储与可视化组件：

- Amazon S3 为所有已处理的客户计划和洞见提供安全存储。
- 每日运行节奏刷新洞见，并支持进度跟踪。
- 交互式仪表板同时提供高管摘要和详细的计划视图。

## 为生产而工程化：构建可靠的 AI 评估

在将 Pulse 从原型推向生产时，我们实施了一套稳健的工程框架，以应对三个 AI 特有的关键挑战。首先，LLM 的非确定性意味着相同的输入可能产生不同的输出，这可能损害评估的一致性。其次，客户计划会随客户关系在一年中自然演变，使得静态评估方法不够充分。第三，不同 AWS 团队会依据具体客户的行业和业务需求，优先关注客户计划的不同方面，因此需要灵活的评估标准。为保持评估的可靠性，我们开发了一个统计框架，对客户计划输入进行多次模型运行并做变异系数（CoV）分析。目标是使用 CoV 作为校正因子来处理数据离散度，我们通过在所评估的问题层面计算整体 CoV 实现了这一点。借助这种方法，我们可以科学地度量并稳定输出的变异性，为选择性人工评审建立清晰的阈值，并检测需要重新校准的性能漂移。落在置信阈值内的客户计划会在系统中自动推进，超出既定阈值的则被标记为需人工评审。我们在此基础上补充了动态阈值加权系统，通过依据业务影响为各标准分配不同权重，使评估与组织优先级保持一致。这会针对不同账户类型定制阈值——例如，对企业账户与中端市场账户应用不同的评估参数。这些业务阈值会定期与销售领导层一起评审，并根据反馈调整，因此我们的 AI 评估既能保持相关性，又能维持质量并节省宝贵时间。

## 结论

本文分享了对由 Amazon Bedrock 驱动的 Pulse 如何改变 AWS 销售团队客户计划流程的说明。通过自动化评审和结构化验证，Pulse 简化了质量评估，并通过在我们在全球的组织中呈现可执行的客户情报来打破知识孤岛。这帮助我们的销售团队减少评审时间，把更多时间用于为战略性客户投入做出数据驱动的决策。

展望未来，我们很高兴进一步提升 Pulse 的能力，通过将战略规划与销售活动和客户成果相连接来衡量客户计划的执行情况。通过分析客户计划的叙述内容，我们旨在识别并把握新机会，更深入地洞见战略规划如何驱动客户在 AWS 上取得成功。

我们计划继续利用 Amazon Bedrock 的新能力，为我们的流程带来更强、更稳健的改进。通过为工作流编排构建 [flows](https://aws.amazon.com/bedrock/flows/)、使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/)、引入 [agentic 框架](https://aws.amazon.com/ai/agentic-ai/?nc2=h_l1_f)，以及使用 [Strands Agents](https://strandsagents.com/latest/) 和 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/)，我们可以在未来实现更动态的流程。
