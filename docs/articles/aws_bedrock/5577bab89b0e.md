# 使用 Biomni 工具与 Amazon Bedrock AgentCore Gateway 构建生物医学研究 agent

*本文与[斯坦福 Biomni 团队](https://biomni.stanford.edu/)共同撰写。*

生物医学研究人员大约有 90% 的时间花在手工处理海量而分散的信息上。这一点可由 [Genentech 的挑战](https://aws.amazon.com/solutions/case-studies/genentech-generativeai-case-study/) 佐证：需要处理 PubMed 中的 3800 万篇生物医学论文、Human Protein Atlas 等公共数据库，以及其内部覆盖数百种疾病、数亿个细胞的数据库。横跨基因组学、蛋白质组学与病理学等不同模态的专用数据库和分析工具正在迅速激增。研究人员必须紧跟庞大的工具版图，留给假设驱动型工作的时间因此更少，而正是这类工作推动着突破性发现。

由基础模型驱动的 AI agent 提供了有前景的解决方案：它们能够自主规划、执行并调整复杂的研究任务。斯坦福研究人员构建的 [Biomni](https://biomni.stanford.edu/about) 正是这种潜力的范例。Biomni 是一个通用型生物医学 AI agent，集成了 150 个专用工具、105 个软件包和 59 个数据库，可执行基因优先级排序、药物重定位和罕见病诊断等复杂分析。

然而，要在生产环境中部署这类 agent，需要稳健的基础设施，既能处理计算密集型 workflow 和多个并发用户，又要维持安全与性能标准。[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 是一整套全面的服务，可用任意框架或模型部署和运行能力强大的 agent，并具备企业级的安全性与可扩展性。

本文将展示如何使用 AgentCore 实现一个研究 agent，使其能够访问 Biomni 中 30 多个专用生物医学数据库工具，从而在保持企业级安全性与生产规模的同时加速科学发现。该解决方案的代码位于 [开源工具包](https://github.com/aws-samples/amazon-bedrock-agents-healthcare-lifesciences) 仓库中，该仓库收录了 Amazon Web Services（AWS）上面向生命科学的起步 agent。[分步说明](https://github.com/aws-samples/amazon-bedrock-agents-healthcare-lifesciences/blob/main/agents_catalog/28-Research-agent-biomni-gateway-tools/README.md#deploy) 可帮助你部署自己的工具与基础设施，以及 AgentCore 组件和示例。

## 从原型到生产的复杂度鸿沟

要把本地的生物医学研究原型变成多个研究团队都能访问的生产系统，需要解决复杂的基础设施挑战。

### 具备企业级安全的 agent 部署

企业级安全挑战包括基于 OAuth 的身份认证、通过可扩展 gateway 安全共享工具、面向研究审计轨迹的全面可观测性，以及为处理并发研究负载而做的自动伸缩。许多有前景的原型之所以无法进入生产，正是因为既要实现这些企业级要求、又要保持准确生物医学分析所需的领域专业能力，其复杂度太高。

### 会话感知的研究上下文管理

生物医学研究 workflow 往往跨越多次对话，需要在长时间的研究会话中持久记住先前的分析、实验参数和研究偏好。研究 agent 必须对进行中的项目保持上下文感知，记住具体的蛋白靶点、实验条件和分析偏好。而这一切还必须在一个多租户生产环境中，为不同研究人员和研究项目之间提供恰当的会话隔离。

### 可扩展的工具 gateway

在大规模场景下，实现一个可复用的工具 gateway 变得至关重要：它要能处理来自研究 agent 的并发请求、提供恰当的身份认证并保持一致的性能。该 gateway 必须让 agent 能够通过安全端点发现并使用工具，通过上下文搜索能力帮助 agent 找到正确的工具，并在同一个统一服务中同时管理入站认证（验证 agent 身份）与出站认证（连接外部生物医学数据库）。缺少这样的架构，研究团队就会遭遇认证复杂性和可靠性问题，难以有效扩展。

## 解决方案概览

我们使用开源 agent 框架 [Strands Agents](https://strandsagents.com/1.x/) 构建了一个研究 agent，并为 PubMed 生物医学文献检索实现了本地工具。我们通过集成 Biomni 数据库工具扩展了该 agent 的能力，使其能够访问 30 多个专用生物医学数据库。

AgentCore Gateway 服务把 Biomni 数据库工具集中为更安全、可复用的端点，并具备语义搜索能力。AgentCore Memory 服务使用面向研究上下文的专用策略，在多次研究会话之间维持上下文感知。安全由 AgentCore Identity 服务负责，它同时管理用户身份认证与工具访问控制。部署则通过 AgentCore Runtime 服务得以简化，提供具备会话隔离的可扩展托管部署。最后，AgentCore Observability 服务可对研究 workflow 进行全面监控与审计，这对科学可复现性至关重要。

### 第 1 步 – 使用 AgentCore Gateway 创建 Biomni 数据库工具等各类工具

在真实用例中，我们需要把 agent 连接到不同的数据源。每个 agent 都可能重复实现同样的工具，导致代码臃肿、行为不一致和维护噩梦。AgentCore Gateway 服务通过把工具集中为 agent 可访问的可复用安全端点，简化了这一过程。配合负责认证的 AgentCore Identity 服务，AgentCore Gateway 构建出企业级的工具共享基础设施。为了让 agent 借助可复用工具获得更多上下文，我们通过注册在 gateway 上的 Biomni 工具提供了 30 多个专用公共数据库 API 的访问能力。该 gateway 通过 [Model Context Protocol（MCP）](https://modelcontextprotocol.io/docs/getting-started/intro) 暴露 Biomni 的数据库工具，使研究 agent 能够发现并调用这些工具，与 PubMed 等本地工具并列使用。它负责认证、限流和错误处理，提供无缝的研究体验。

```
def create_gateway(gateway_name: str, api_spec: list) -> dict:
    # JWT authentication with Cognito
    auth_config = {
        "customJWTAuthorizer": {
            "allowedClients": [
                get_ssm_parameter("/app/researchapp/agentcore/machine_client_id")
            ],
            "discoveryUrl": 
                get_ssm_parameter("/app/researchapp/agentcore/cognito_discovery_url"),
        }
    }
    
    # Enable semantic search for BioImm tools
    search_config = {"hcp": {"searchType": "SEMANTIC"}}
    
    # Create the gateway
    gateway = bedrock_agent_client.create_gateway(
        name=gateway_name,
        collectionexecution_role_arn,
        protocolType="MCP",
        authorizerType="CUSTOM_JWT",
        authorizerConfiguration=auth_config,
        protocolConfiguration=search_config,
        description="My App Template AgentCore Gateway",
    )
```

### 第 2 步 - 带本地工具的 Strands 研究 agent

以下代码片段展示了模型初始化，并实现了用 Strands `@tool` 装饰器声明的 PubMed 本地工具。我们在 [research_tools.py](https://github.com/aws-samples/amazon-bedrock-agents-healthcare-lifesciences/blob/main/agents_catalog/28-Research-agent-biomni-gateway-tools/agent/agent_config/tools/research_tools.py) 中实现了该 PubMed 工具，它调用 PubMed API，使 agent 的执行上下文中具备生物医学文献检索能力。

```
from agent.agent_config.tools.PubMed import PubMed

@tool(
    name="Query_pubmed",
    description=(
        "Query PubMed for relevant biomedical literature based on the user's query. "
        "This tool searches PubMed abstracts and returns relevant studies with "
        "titles, links, and summaries."
    ),
)
def query_pubmed(query: str) -> str:
    """
    Query PubMed for relevant biomedical literature based on the user's query.
    
    This tool searches PubMed abstracts and returns relevant studies with 
    titles, links, and summaries.
    
    Args:
        query: The search query for PubMed literature
        
    Returns:
        str: Formatted results from PubMed search
    """
    pubmed = PubMed()
    
    print(f"\nPubMed Query: {query}\n")
    result = pubmed.run(query)
    print(f"\nPubMed Results: {result}\n")
    
    return result
```

### 第 3 步 - 添加持久记忆以提供上下文研究协助

该研究 agent 实现了 [AgentCore Memory](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-agentcore-memory-building-context-aware-agents/) 服务，并采用三种策略：*semantic* 用于事实性研究上下文，*user_preference* 用于研究方法论，*summary* 用于会话连续性。AgentCore Memory 的会话管理器与 [Strands 会话管理](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/agents/session-management/) 集成，在查询前检索相关上下文，并在响应后保存交互记录。这使 agent 能够跨会话记住研究偏好、进行中的项目和领域专业知识，无需手动重建上下文。

### 第 4 步 - 使用 AgentCore Runtime 部署

为了部署 agent，我们使用 AgentCore Runtime 把该研究 agent 配置并启动为托管服务。部署过程会用 agent 的主入口（[agent/main.py](https://github.com/aws-samples/amazon-bedrock-agents-healthcare-lifesciences/blob/main/agents_catalog/28-Research-agent-biomni-gateway-tools/agent/main.py)）配置 runtime，为其分配用于访问 AWS 服务的 IAM 执行角色，并同时支持 OAuth 与 IAM 两种认证模式。部署完成后，该 runtime 会变成一个可伸缩的无服务器 agent，可通过 API 调用。该 agent 自动处理会话管理、记忆持久化和工具编排，同时提供对 Biomni gateway 与本地研究工具的安全访问。

```
agentcore configure --entrypoint agent/main.py -er arn:aws:iam::&lt;Account-Id&gt;:role/&lt;Role&gt; --name researchapp&lt;AgentName&gt;
```

有关使用 AgentCore Runtime 部署的更多信息，请参阅 *Amazon Bedrock AgentCore Developer Guide* 中的 [AgentCore Runtime 入门](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-getting-started.html)。

### **Agent 实战**

以下三个具有代表性的研究场景展示了该 agent 在不同领域的能力：药物机制分析、遗传变异研究和通路探索。对于每个查询，agent 都会自主判断应使用哪些工具组合、构造合适的子查询、分析返回的数据，并综合出一份带有恰当引用的完整研究报告。随附的演示视频展示了完整的 agent workflow，包括工具选择、推理和响应生成。

- 对曲妥珠单抗（trastuzumab，Herceptin）的作用机制与耐药机制进行全面分析，你需要：HER2 蛋白结构与结合位点、受影响的下游信号通路、来自临床数据的已知耐药机制、正在研究联合疗法的当前临床试验、用于预测治疗反应的生物标志物。查询相关数据库以提供一份全面的研究报告。
- 分析 BRCA1 变异在乳腺癌风险与治疗反应中的临床意义。请调查：致病性 BRCA1 变异的群体频率、临床意义与致病性分类、相关癌症风险与外显率估计、治疗意义（PARP 抑制剂、铂类药物）、针对 BRCA1 阳性患者的当前临床试验

### 可扩展性与可观测性

部署复杂 AI agent 时最关键的挑战之一，是确保它们能够可靠地扩展，同时对运行状况保持全面的可见性。生物医学研究 workflow 本质上难以预测——单次基因组分析可能处理成千上万个文件，而一篇文献综述可能横跨数百万篇出版物。传统基础设施难以应对这种动态负载，尤其是在处理需要在不同研究项目之间严格隔离的敏感研究数据时。在本次部署中，我们使用 Amazon Bedrock AgentCore Observability 可视化 agent workflow 的每一步。你可以使用该服务检查 agent 的执行路径、审计中间输出，并调试性能瓶颈与故障。对于生物医学研究而言，这种透明度不仅是有帮助的——它对法规合规与科学可复现性是必需的。

在可观测性框架中，session、trace 和 span 构成三层层级关系。一个 session 包含多个 trace，每个 trace 代表该 session 更广上下文中的一次独立交互。每个 trace 包含多个 span，用于捕获细粒度操作。以下截图展示了一个 agent 的使用情况：生产环境中的会话数、token 使用量和错误率

## 未来方向

虽然本次实现只聚焦于一部分工具，但 AgentCore Gateway 的架构在设计上就考虑了可扩展性。研究团队使用 MCP 协议即可无缝添加新工具，无需改动代码。新注册的工具可被 agent 自动发现，使你的研究基础设施能够与快速变化的工具集一同演进。

对于需要执行代码的计算分析，可以把 [AgentCore Code Interpreter](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/code-interpreter-tool.html) 服务集成到研究 workflow 中。借助 AgentCore Code Interpreter，研究 agent 可以获取数据，并使用 BioPython、scikit-learn 或自定义基因组学包等领域专用库执行基于 Python 的分析。

未来的扩展可以支持多个研究 agent 在复杂项目上协作：分别负责文献综述、实验设计、数据分析和结果解读的专用 agent 通过多 agent 协作共同工作。各组织也可以针对特定治疗领域、疾病领域或研究方法开发专用研究 agent，让它们共享同一套企业基础设施与工具 gateway。

## 与 Biomni 一起展望未来

*“Biomni 今天已经可用于学术研究和开放式探索。但要实现真正的发现——比如推进药物开发——我们需要超越原型，让系统达到企业级可用。把 Biomni 嵌入生物技术和制药企业的 workflow，对于把研究潜力转化为切实影响至关重要。

*这正是我们乐于把这个开源环境与 Amazon Bedrock AgentCore 集成的原因——它弥合了从研究到生产的差距。展望未来，我们也期待用 Biomni A1 agent 架构和 Biomni-R0 模型扩展这些能力，它们将解锁更复杂的生物医学推理与分析。* *与此同时，Biomni 将继续保持蓬勃发展的开源环境，研究人员与产业团队都可以贡献工具、共享 workflow，并与 AgentCore 一起推动生物医学 AI 的边界。”*

## 结论

本次实现展示了各组织如何使用 Amazon Bedrock AgentCore 把生物医学研究原型转变为可用于生产环境的系统。通过 AgentCore Gateway 服务集成 Biomni 由 150 多个专用工具构成的完整工具集，我们说明了团队如何构建企业级工具共享基础设施，并能跨多个研究领域扩展。把 Biomni 的生物医学工具与 Bedrock AgentCore 的企业级基础设施相结合，组织就能构建出既保持科学严谨性、又满足生产环境在安全性、可扩展性和可观测性方面要求的研究 agent。Biomni 多样的工具集合——覆盖基因组学、蛋白质组学和临床数据库——例证了专用研究能力如何通过安全的 gateway 架构被集中管理并在研究团队之间共享。

要开始用 Biomni 工具构建你自己的生物医学研究 agent，可访问我们的 [GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-agents-healthcare-lifesciences/tree/main/agents_catalog/28-Research-agent-biomni-gateway-tools) 查看完整代码与文档，了解该实现。你可以按照分步实施指南，配置带本地工具、gateway 集成和 Bedorck AgentCore 部署的研究 agent。随着需求演进，你还可以用所在组织的专有数据库和分析工具扩展该系统。我们鼓励你分享自己的扩展与改进，加入不断壮大的生命科学 AI agent 与工具生态。
