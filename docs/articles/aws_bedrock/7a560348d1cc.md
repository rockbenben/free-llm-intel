# 将 AgentCore Runtime 托管的 MCP server 连接到 AWS Quick

[Model Context Protocol（MCP）](https://docs.aws.amazon.com/quicksuite/latest/userguide/mcp-integration.html) server 让基础模型能够访问外部数据和工具，为文件、数据库与 API 提供标准化且安全的访问方式。它们让 AI agent 能够与真实应用交互，以准确的上下文减少幻觉，并提供有状态的多轮能力。业界标准架构迅速演进并采纳 MCP 来驱动 agentic AI 工作流。

[AWS Quick](https://aws.amazon.com/quick/) 支持 MCP 集成，用于自主执行、实时数据访问以及专门的 AI 子 agent 集成。如果你已经有 MCP server，可以参照这份[集成指南](https://docs.aws.amazon.com/quick/latest/userguide/mcp-integration.html)把它与 AWS Quick 集成。如果还没有 MCP server，可以使用 AWS 提供的[在 AWS 上部署 MCP server 的指导](https://aws.amazon.com/solutions/guidance/deploying-model-context-protocol-servers-on-aws/)，它遵循 AWS Well-Architected 支柱。视你的使用场景不同，有几种选择：

- 如果你有自己的 REST API，或有一个运行在 [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 上的 REST API，可以使用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) Gateway 让 AWS Quick 直接与你的 API 集成。
- 如果你偏好无服务器架构，且只需要为 AI agent 提供最低限度的执行能力，可以编写一个 AWS Lambda 函数，并使用 AgentCore Gateway 与 AWS Quick 集成。
- 如果你想要一个全托管的无服务器 MCP server 方案，具备会话隔离、更长的执行时间、持久文件系统、内置身份认证、可观测性、增强载荷、双向流式传输和评估能力，可以使用 [AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 托管 MCP server，并借助 AgentCore Gateway 与 AWS Quick 连接。

本文将介绍如何在 AgentCore Runtime 中部署并托管你的 MCP server、如何把它与 AWS Quick 集成，以及所需的前提条件。采用这种模式，你可以提升 AI 工具的可复用性、避免重复建设，让客户端复用通过 MCP server 暴露的常用工具与 agent，而不必从头再写一遍。你的客户也因此能在 AWS Quick（聊天 agent 与工作流）中使用你的产品，而无需为每个场景构建定制连接器。

### 方案概览

截至本文撰写时，你可以在 Web 浏览器或桌面应用中使用 [AWS Quick](https://aws.amazon.com/quick/)，与提供 AI agent 能力的[聊天 agent](https://aws.amazon.com/quick/chat-agents/)或 [Flows](https://aws.amazon.com/quick/flows/) 协作。要让 AI agent 与 MCP server 连接、从而获得额外的工具和子 agent 能力，你需要把 MCP server 与 AWS Quick 集成。集成通过 AWS Quick 一侧的连接器和 AgentCore 一侧的 AgentCore Gateway 完成。AgentCore Gateway 与 Runtime 都在 Amazon Bedrock AgentCore 中提供，这是一个用于构建生成式 AI 应用的全托管服务。从 AWS Quick 到 AgentCore Gateway 的授权流程称为 Inbound Auth，从 AgentCore Gateway 到 AgentCore Runtime 的流程称为 Outbound Auth。Inbound Auth 负责身份认证，并授权用户访问 MCP server。Inbound Auth 我们使用 Amazon Cognito 满足授权需求，你也可以改用其他身份提供方。Outbound Auth 负责机器对机器的认证与授权，我们使用 [AgentCore Identity](https://aws.amazon.com/blogs/machine-learning/introducing-amazon-bedrock-agentcore-identity-securing-agentic-ai-at-scale/)，一项专为 AI agent 打造的综合身份与访问管理服务。MCP 协议目前要求以 OAuth 2.0 作为认证协议，因此 Outbound Auth 使用 OAuth 2.0。

![AWS Quick 经由 AgentCore Gateway 连接到运行在 AgentCore Runtime 上的 MCP server 的架构图，其中使用 Amazon Cognito 与 AgentCore Identity 完成身份认证](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-1.png)

### 前提条件

开始之前，请确认你满足以下前提条件，以便按照本文的分步说明在自己的 AWS 账户中部署该方案。

- 一个 [AWS 账户](https://docs.aws.amazon.com/accounts/latest/reference/welcome-first-time-user.html#getting-started-step1)。
- 已配置 AWS Quick，且订阅级别为 Author 或更高。
- 具备创建 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam) 角色与策略，以及创建 AgentCore、Amazon Cognito 和 Amazon CloudWatch 资源的权限。
- 具备 AWS 服务的基础知识。
- 对于 Amazon Bedrock AgentCore 的配置：可访问已安装 AWS SDK 与 Python 的命令行环境；熟悉 AWS CLI 与 Python；已为 Anthropic 模型开通 Amazon Bedrock 访问权限。
- 对于运行本教程：Python 3.10+；已配置 AWS 凭证；Amazon Bedrock AgentCore SDK；MCP（Model Context Protocol）库；运行中的 Docker daemon。

### 实施步骤

按以下步骤，把一个在本地编写的 MCP server 变成在 AWS Quick 聊天 agent 内可用、且已完成集成与认证的工具。

- 在 AgentCore Runtime 上实现并部署一个示例远程 MCP server。
- 为 MCP server 与 AgentCore Gateway 配置入站与出站认证并完成集成。
- 在 AWS Quick 中注册该 MCP 集成，并与你的聊天 agent 对接。
- 在 AWS Quick 中测试该 MCP server 集成。
- 清理资源。

### 步骤 1：在 AgentCore Runtime 上实现并部署远程 MCP server

在这一步，我们在 AgentCore Runtime 上部署一个带有基础占位工具的示例 MCP server。详细的分步代码见 GitHub 上的 [AgentCore 示例 notebook](https://github.com/awslabs/agentcore-samples/blob/main/06-workshops/01-AgentCore-runtime/02-hosting-MCP-server/hosting_mcp_server.ipynb)，这里只做概要讲解。

按如下方式创建项目结构与文件：

**项目结构**

```
mcp_server_project/
├── mcp_server.py          # Main MCP server code
├── requirements.txt       # Dependencies
└── __init__.py            # Python package marker
```

文件：requirements.txt

```
mcp>=1.10.0
boto3
bedrock-agentcore
bedrock-agentcore-starter-toolkit>=0.1.21
strands-agents
```

使用以下命令在你的 Python 解释器中安装这些依赖：

```
uv venv sample-venv                   # Create Virtual Environment
source sample-venv/bin/activate       # Activate Virtual Environment
uv pip install -r requirements.txt    # Install the dependencies
```

以下是最小化的示例代码。关于安全认证配置的更多细节，请参阅[使用 AgentCore Gateway 与 MCP 客户端构建安全的认证码流程](https://aws.amazon.com/blogs/machine-learning/building-a-secure-auth-code-flow-setup-using-agentcore-gateway-with-mcp-clients/)。当你以 MCP 协议配置 AgentCore Runtime 时，该服务要求 MCP server 容器在路径 `0.0.0.0:8000/mcp` 上可用，这也是大多数官方 MCP server SDK 支持的默认路径。

文件：sample_mcp_server.py

```
from mcp.server.fastmcp import FastMCP

mcp = FastMCP(host="0.0.0.0", stateless_http=True)

@mcp.tool()
def getOrder() -> int:
    """Get an order"""
    return 123

@mcp.tool()
def updateOrder(orderId: int) -> int:
    """Update existing order"""
    return 456

if __name__ == "__main__":
    mcp.run(transport="streamable-http")
```

该 server 使用 `FastMCP` 并设置 `stateless_http=True`，这是兼容 AgentCore Runtime 所必需的。这段代码做了以下事情：

- `FastMCP`：创建一个可以托管你的工具的 MCP server。
- `@mcp.tool()`：把你的 Python 函数转成 MCP 工具的装饰器。
- `stateless_http=True`：兼容 AgentCore Runtime 所必需。

你可以参照 notebook 中的「Creating Local Testing Client」与「Testing Locally」两节，用本地 MCP server 客户端在本地测试你的 MCP server。

现在可以部署到 AgentCore Runtime 了。你可以在终端中使用 Bedrock starter kit 部署（如下文步骤所述），也可以按 notebook 中「Launching MCP Server to AgentCore Runtime」一节的说明改用 Python 脚本部署。本教程使用 AgentCore starter kit。

打开终端，把当前工作目录切到你的项目目录，然后为部署配置项目。`configure` 命令是交互式的，各步骤都有清楚的提示。本教程中可以选择默认值。

```
# Configure your AgentCore project
agentcore configure --entrypoint mcp_server.py --name simple_mcp_server
```

`configure` 命令会自动完成几项关键配置工作。它生成 `Dockerfile` 和 `.dockerignore` 文件，用于把你的 agent 容器化，使你的 Python 应用在不同环境中一致运行。最重要的是，它会创建一个 `.bedrock_agentcore.yaml` 配置文件，用来保存 agent 的运行时设置和部署参数。

`--entrypoint` 参数指定包含 agent 主逻辑的 Python 文件，也就是包含你用 `@app.entrypoint` 装饰的那个函数的文件。`--name` 参数为你的 agent 在你的 AWS 账户内指定一个唯一标识符，用于跨 AWS 服务的资源命名与管理。

配置完项目后，可以运行以下命令启动部署。

```
agentcore launch
```

此时你应该能在 Runtime 中看到这个 MCP server 了。

![AgentCore Runtime 控制台，显示已部署的 MCP server](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-2.png)

### 步骤 2：为 MCP server 与 AgentCore Gateway 配置入站与出站认证并完成集成

在这一步，我们配置 AgentCore Gateway，使其成为 AWS Quick 与你已部署的 MCP server 之间的安全桥梁。入站与出站流程都按推荐的安全最佳实践搭建，包括开箱即用的端到端 TLS。如需定制，可参阅相应服务的文档。这包括为 Gateway 设置 IAM 角色、配置两个 Amazon Cognito 用户池分别处理 **Inbound Auth**（授权来自 AWS Quick 的请求）与 **Outbound Auth**（通过 OAuth 2.0 认证对 MCP server 的调用），以及创建 Gateway 端点。若要以编程方式配置，请参阅 GitHub 上的[以 MCP server 作为目标的教程](https://github.com/awslabs/agentcore-samples/blob/main/01-tutorials/02-AgentCore-gateway/05-mcp-server-as-a-target/01-mcp-server-target.ipynb)。

![AgentCore Gateway 作为桥梁连接 AWS Quick 与 MCP server，并包含入站与出站认证的示意图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-3.png)

#### 步骤 2a：创建供 AgentCore Gateway 承担的 IAM 角色

进入 AWS 管理控制台，选择 IAM，然后选择 Create role。把 Amazon Bedrock AgentCore 选为使用场景。

![IAM 创建角色页面，使用场景已选中 Amazon Bedrock AgentCore](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-4.png)

你可以在 Permissions 中附加以下内联 IAM 策略：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "MCPServerRuntimePermissions",
            "Effect": "Allow",
            "Action": [
                "bedrock-agentcore:InvokeAgentRuntime",
                "bedrock-agentcore:InvokeRegistryMcp",
                "secretsmanager:GetSecretValue"
            ],
            "Resource": [
                "arn:aws:bedrock-agentcore:<REGION>:<ACCOUNT_ID>:runtime/<RUNTIME_ID>",
                "arn:aws:bedrock-agentcore:<REGION>:<ACCOUNT_ID>:runtime/<RUNTIME_ID>/runtime-endpoint/*"
        }
        ]
}
```

使用示例角色名 `agentcore-sample-mcpgateway-role`（也可以自选）。Resource 填入部署在 AgentCore Runtime 上的 MCP server 的 runtime ARN。

#### 步骤 2b：创建用于 Gateway 入站授权的 Amazon Cognito 用户池

转到 Amazon Cognito，创建一个新用户池充当入站授权层，在来自 AWS Quick 的请求到达 Gateway 之前对其进行校验。

进入 Amazon Cognito，选择 Create user pool。

![Amazon Cognito 的 Create user pool 页面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-5.png)

接下来，为该用户池配置资源服务器。在导航窗格中选择 Branding 下的 Domain，然后新建一个资源服务器，定义 Gateway 在授权时校验的受保护自定义 scope `invoke`。

![Amazon Cognito 资源服务器配置，包含 invoke 自定义 scope](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-6.png)

请记录先前创建的用户池中的以下 Inbound Auth 信息，后续步骤会引用它们：

- **Client ID 与 Client Secret**：在导航窗格中选择 App Clients，然后选中你的 app client 查看凭证。
- **Discovery URL**：`https://cognito-idp.{REGION}.amazonaws.com/{gw_user_pool_id}/.well-known/openid-configuration`

#### 步骤 2c：创建用于出站授权的 Amazon Cognito 用户池

转到 Amazon Cognito，创建第二个用户池充当出站授权层，使 Gateway 在调用托管于 AgentCore Runtime 的 MCP server 时能够自行完成认证。

进入 Amazon Cognito，选择 Create user pool。

![Amazon Cognito 的 Create user pool 页面，用于出站授权层](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-7.png)

与入站授权类似，为出站授权创建一个资源服务器，并取得 client ID、secret 以及带受保护自定义 scope `invoke` 的 discovery URL。

![用于出站授权的 Amazon Cognito 资源服务器，包含 invoke 自定义 scope](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-8.png)

请记录该用户池为 Outbound Auth 提供的以下信息，后续会用到：

- **Client ID 与 Client Secret**：在导航窗格中选择 App Clients，然后选中你的 app client 查看凭证。
- **Discovery URL**：`https://cognito-idp.{REGION}.amazonaws.com/{gw_user_pool_id}/.well-known/openid-configuration`

接下来，在 AgentCore Identity 中创建 OAuth 凭证提供方。转到 Amazon Bedrock AgentCore，选择 Identity，然后选择 Add Outbound Auth 和 Create OAuth Client。在表单中填入上一步在 Outbound Auth 的 Amazon Cognito 用户池中创建的 app client 的 Discovery URL、Client ID 与 Client Secret。

![AgentCore Identity 的 Create OAuth Client 表单，已填入出站 Cognito app client 的信息](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-9.png)

#### 步骤 2d：创建 AgentCore Gateway

转到 Amazon Bedrock AgentCore，选择 Gateway，然后选择 Create Gateway。本次演练中我们将其命名为 `ac-gateway-mcp-server`。在 **Inbound Auth** 处，把认证类型选为 **JWT**，选择 Use Existing Identity Provider Configuration，并填入步骤 2b 中创建的 Inbound Auth Amazon Cognito 用户池的 **Discovery URL** 与 **Client ID**。

![AgentCore Gateway 创建页面，已配置 JWT 入站认证](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-10.png)

![AgentCore Gateway 入站认证详情，包含 Cognito 的 discovery URL 与 client ID](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-11.png)

在 Permissions 部分，使用我们在步骤 2a 中创建的 IAM 角色。

![AgentCore Gateway 的 Permissions 部分，已选中 IAM 角色](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-12.png)

在 Target 部分，把你的 MCP server 注册为一个 target。请确认授权类型选择 OAuth Client，因为 MCP 协议目前不支持其他授权方式。要构造 MCP 端点 URL，请使用下面的模板，并把 `encoded_agentcore_runtime_mcp_server_arn` 替换为部署在 AgentCore Runtime 上的 MCP server 的 ARN 的 URL 编码形式。

```
https://bedrock-agentcore.us-east-1.amazonaws.com/runtimes/{encoded_agentcore_runtime_mcp_server_arn}/invocations?qualifier=DEFAULT
```

在 Outbound Auth 配置中，使用我们在 Outbound Auth 部分创建的 OAuth 客户端。

![AgentCore Gateway 的 Target 部分，已配置 MCP server 端点与 OAuth 客户端](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-13.png)

信息填写完成后，选择 Create Gateway，并等待 Gateway 及其 Target 都进入 Ready 状态，再继续下一步。

![AgentCore Gateway 处于 Ready 状态](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-14.png)

![AgentCore Gateway 的 Target 处于 Ready 状态](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-15.png)

### 步骤 3：在 AWS Quick 中注册 MCP 集成

转到 AWS Quick，选择 Connectors，然后为你的团队选择 Create。把集成类型选为 Model Context Protocol（MCP），开始把刚创建的 Gateway 注册为一个 MCP 集成。

![AWS Quick 的 Connectors 页面，集成类型已选中 Model Context Protocol](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-16.png)

为集成填写名称和描述，以及 MCP Server Endpoint，即步骤 2d 中创建的 AgentCore Gateway 的 Resource URL。在连接类型上，你还可以选择私有 [VPC 连接](https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-quick-vpc-mcp/)，以限制 MCP server 在网络上的可见性，从而提升安全性。

![AWS Quick 集成配置，包含 MCP server 端点](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-17.png)

在 Authenticate 页面，填入步骤 2d 中在 AgentCore Gateway 上配置的 Inbound Auth 信息。你可以按使用场景选择认证类型：如果场景是认证单个用户，选择 User authentication；如果是更系统化的集成，则选择 Service authentication。本教程使用基于 Amazon Cognito 的 User authentication，你也可以接入自己偏好的身份提供方。根据所选身份提供方填写 Client ID、Client Secret、Token URL 和 Authorization URL。

Token URL 请使用下面的模板。注意用户池 ID 中的下划线必须去掉（例如 `us-west-2_qNBcTlLbR` 变成 `us-west-2qNBcTlLbR`）。Authorize URL 使用同一个 URL，但要把 `token` 换成 `authorize`。

Token URL 模板：

```
https://{user_pool_id_without_underscore}.auth.{REGION}.amazoncognito.com/oauth2/token
```

![AWS Quick 的 Authenticate 页面，包含 Cognito 的 token URL 与 authorize URL](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-18.png)

信息填写完成后，选择 Create and Continue 并检查你的配置。此时页面只显示 listTools，并会与 MCP server 同步工具。当 Action 进入 Available 状态后，同步即完成。

![AWS Quick 的集成检查页面，同步完成前只显示 listTools](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-19.png)

当 Action 处于 Available 或 Ready 状态后，你应该能看到工具已刷新。

![AWS Quick 集成页面，显示已同步的 MCP 工具处于 Available 状态](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-20742-20.png)

### 步骤 4：在 AWS Quick 中测试 MCP server 集成

你可以选择 Test Action APIs 来验证 MCP 工具可访问且按预期工作。

### 结论

本文介绍了 AWS Quick 如何与托管在 Amazon Bedrock AgentCore Runtime 上的自定义 MCP server 集成。你走完了这样的流程：在 AgentCore Runtime 上部署远程 MCP server，用 Amazon Cognito 与 AgentCore Identity 通过入站和出站认证为其加固，借助 AgentCore Gateway 把它接到 AWS Quick，并在 AWS Quick 中把它注册为 Action 集成。这种模式提升了 AI 工具与 agent 在组织内的可复用性，团队可以通过标准化的 MCP 接口暴露专门能力，并在 AWS Quick 聊天 agent 与 Flows 中直接使用，而无需为每个场景构建定制连接器。
