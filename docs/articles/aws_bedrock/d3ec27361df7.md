# 借助 Strands Agents、Amazon Bedrock AgentCore 与 LibreChat 构建教育领域的 AI agent 并扩大其采用

对于大多数企业应用来说，基础的 AI 聊天并不够用。机构需要能够从自有数据库中取数、与现有工具集成、处理多步流程并独立做出决策的 AI。

本文演示如何用 [Strands](https://strandsagents.com/latest/) Agents 快速构建成熟的 AI agent，用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 可靠地扩展它们，并通过 [LibreChat](https://www.librechat.ai/) 熟悉的界面让用户使用，从而在你的机构内推动用户立即采用。

## 基础 AI 聊天界面面临的挑战

虽然基础的 AI 聊天界面可以回答问题并生成内容，但教育机构需要的是简单聊天无法提供的能力：

- **上下文决策（Contextual decision-making）** – 当学生问“我该选哪些课？”时，需要 agent 能访问其成绩单、检查先修课程、核实毕业要求并考虑时间冲突，而不只是给出通用课程介绍
- **多步工作流（Multi-step workflows）** – 学位规划需要分析当前进度、识别尚缺的要求、建议课程顺序，并随着学生做出决定而更新建议
- **机构数据集成（Institutional data integration）** – 有效的教育 AI 必须连接学生信息系统、学习管理服务、学术数据库和机构知识库，以提供相关且个性化的指导
- **持久记忆与学习（Persistent memory and learning）** – agent 需要记住与学生的以往交互、跨学期跟踪其学业进程，并逐步理解个体学习模式与需求

## 将开源灵活性与企业基础设施结合

本文介绍的集成展示了三种技术如何协同工作来应对这些挑战：

- **Strands Agents** – 仅用几行代码就能构建成熟的多 agent 工作流
- **Amazon Bedrock AgentCore** – 通过无服务器、按使用付费的部署方式可靠地扩展 agent
- **LibreChat** – 为用户提供熟悉的聊天界面，推动即时采用

### Strands Agents 概述

Strands Agents 是一个开源 SDK，采用模型驱动的方式，仅用几行代码就能构建和运行 AI agent。与 [LibreChat 简单的 agent 实现](https://www.librechat.ai/docs/features/agents)不同，Strands 支持多种成熟模式，包括通过 workflow、graph 和 swarm 工具实现的[多 agent 编排](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/multi-agent/agents-as-tools/)、用于管理数千个工具的语义搜索，以及带深度分析思考循环的高级推理能力。该框架充分利用最先进模型在规划、串联思路、调用工具和反思方面的能力来简化 agent 开发，同时以灵活的架构和全面的可观测性，支持从本地开发扩展到生产部署。

### Amazon Bedrock AgentCore 概述

Amazon Bedrock AgentCore 是一组全面的企业级服务，帮助开发者使用你选择的框架和模型，快速、安全地大规模部署和运行 AI agent，这些 agent 可以托管在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上或其他地方。这些服务可组合使用，并可与流行的开源框架和众多模型配合，因此你不必在开源灵活性与企业级安全性和可靠性之间做取舍。

Amazon Bedrock AgentCore 包含可一起使用或独立使用的模块化服务：Runtime（用于部署和扩展动态 agent 的安全无服务器运行时）、Gateway（把 API 和 [AWS Lambda](https://aws.amazon.com/lambda) 函数转换为与 agent 兼容的工具）、Memory（同时管理短期和长期记忆）、Identity（提供安全的访问管理）以及 Observability（对 agent 性能提供实时可见性）。

本集成中使用的关键 Amazon Bedrock AgentCore 服务是 Amazon Bedrock AgentCore Runtime，这是一个专为部署和扩展动态 AI agent 与工具而构建的安全无服务器运行时，支持包括 LangGraph、CrewAI 和 Strands Agents 在内的开源框架、一种协议以及你选择的模型。Amazon Bedrock AgentCore Runtime 专为 agentic 工作负载打造，具备业界领先的延长运行时支持、快速冷启动、真正的会话隔离、内置身份识别，以及对多模态负载的支持。与典型的无服务器模型（函数被启动、执行后立即终止）不同，Amazon Bedrock AgentCore Runtime 预置专用 microVM，可持久运行最长 8 小时，从而支持成熟的多步 agentic 工作流：在同一会话内，每一次后续调用都基于之前交互累积的上下文和状态。

### LibreChat 概述

LibreChat 已成为商业 AI 聊天界面的领先开源替代品，为教育机构大规模部署对话式 AI 提供了有力方案。LibreChat 以灵活性和可扩展性为核心设计，为高等教育提供多项关键优势：

- **多模型支持（Multi-model support）** – LibreChat 支持接入多个 AI 提供商，机构可以针对不同用例选择最合适的模型，同时避免厂商锁定
- **用户管理（User management）** – 稳健的认证与授权系统帮助机构以恰当的权限和使用控制，管理学生、教师和职员的访问
- **对话管理（Conversation management）** – 学生和教师可以把 AI 交互组织到项目和主题中，营造更有结构的学习环境
- **可定制界面（Customizable interface）** – 该方案可以换标并定制，以匹配机构形象和具体的教学需求

## 集成收益

将 Strands Agents 与 Amazon Bedrock AgentCore 和 LibreChat 集成，会带来独特的收益，使这两项服务的能力远超各自单独所能达到的水平：

- **通过熟悉的界面获得无缝的 agent 体验（Seamless agent experience through familiar interface）** – LibreChat 直观的聊天界面成为通往成熟 agentic 工作流的入口。用户通过自然对话即可触发复杂的多步流程、数据分析和外部系统集成，无需学习新界面或复杂 API。
- **动态加载与管理 agent（Dynamic agent loading and management）** – 与静态的 AI 聊天实现不同，此集成支持带访问管理的动态 agent 加载。新的 agentic 应用可以独立部署并对用户开放，无需更新 LibreChat 或停机，从而实现 agent 的快速开发。
- **企业级安全与扩展（Enterprise-grade security and scaling）** – Amazon Bedrock AgentCore Runtime 为每个用户会话提供完全的会话隔离，每个会话运行时使用隔离的 CPU、内存和文件系统资源。这在用户会话之间形成完全分隔，保护有状态的 agent 推理过程，并有助于防止跨会话数据污染。该服务可在数秒内扩展到数千个 agent 会话，而开发者只需为实际用量付费，非常适合需要支持大量学生且使用模式各异的教育机构。
- **内置 AWS 资源集成（Built-in AWS resource integration）** – 已在 AWS 上运行基础设施的组织，可以将其现有资源——数据库、数据湖、Lambda 函数和应用——无缝连接到 Strands Agents，无需复杂的集成或数据迁移。agent 可以直接访问这些资源并通过 LibreChat 界面呈现洞见，把现有的 AWS 投入转化为智能的对话体验，例如查询 [Amazon Relational Database Service](https://aws.amazon.com/rds/)（Amazon RDS）数据库、分析 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）中的数据，或与现有微服务集成。
- **高性价比的 agentic 计算（Cost-effective agentic computing）** – 通过将 LibreChat 高效的架构与 Amazon Bedrock AgentCore 的按使用付费模式结合，组织可以部署成熟的 agentic 应用，而无需承担企业 AI 系统通常伴随的高额固定成本。用户只需为实际的 agent 计算和工具使用付费。

## 高等教育场景中的 agent 用例

LibreChat 与 Strands Agents 的集成支持众多教育应用，体现了该方案的多功能性与强大能力：

- 课程推荐 agent 可以分析学生的学业记录、当前选课情况和职业兴趣，推荐相关课程。通过与学生信息系统集成，该 agent 可以确保推荐时考虑先修课程、时间冲突和毕业要求。
- 学位进度跟踪 agent 可以与学生交互，帮助他们理解自己的具体学位要求，并就剩余课程、选修课选项和时间线优化提供指导。
- 可以将 agent 配置为可访问学术数据库和机构知识库，帮助学生和教师发现相关研究论文与资源，并就各学科特定的学术写作、引用格式和研究方法提供指导。
- agent 可以处理学生关于注册、截止日期和校园资源的日常咨询，把教职工的时间释放出来用于更复杂的学生支持需求。

教育用例的 Strands Agent 代码示例请参阅以下 [GitHub 仓库](https://github.com/aws-samples/AI-Agents-for-Education)。

## 解决方案概述

下面的架构图展示了部署带 Strands Agents 集成的 LibreChat 的整体系统设计。Strands Agents 使用 Amazon Bedrock AgentCore Runtime 部署，这是一个专为使用包括 Strands Agents 在内的开源框架部署和扩展动态 AI agent 与工具而构建的安全无服务器运行时。

![AgentCore 与 LibreChat 集成的架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/04/ML-18949-arch-diag.png)

该解决方案架构包含几个关键组件：

- **LibreChat 核心服务（LibreChat core services）** – 核心聊天界面运行在 [Amazon Elastic Container Service](https://aws.amazon.com/ecs)（Amazon ECS）配合 [AWS Fargate](https://aws.amazon.com/fargate) 集群中，包括面向用户体验的 LibreChat、用于增强搜索能力的 Meilisearch，以及用于文档检索的检索增强生成（RAG）API 服务。
- **LibreChat 支撑基础设施（LibreChat supporting infrastructure）** – 该方案使用 [Amazon Elastic File System](https://aws.amazon.com/efs/)（Amazon EFS）存储 Meilisearch 的索引和用户上传的文件；使用 [Amazon Aurora PostgreSQL-Compatible Edition](https://aws.amazon.com/rds/aurora/postgresql-features/) 作为 RAG API 使用的向量数据库；使用 Amazon S3 存储 LibreChat 配置；使用 [Amazon DocumentDB](https://aws.amazon.com/documentdb/) 管理用户、会话和对话数据；并使用 [AWS Secrets Manager](https://aws.amazon.com/secrets-manager/) 管理对资源的访问。
- **Strands Agents 集成（Strands Agents integration）** – 该方案通过 [custom endpoints](https://www.librechat.ai/docs/quick_start/custom_endpoints)，使用 Lambda 和 [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 把由 Amazon Bedrock AgentCore Runtime 托管的 Strands Agents 与 LibreChat 集成。这种集成模式支持在 LibreChat 中动态加载 agent，以获得高级生成式 AI 能力。具体而言，该方案展示了一个用户活动分析 agent，它从 LibreChat 日志中提取洞见。
- **认证与安全（Authentication and security）** – LibreChat 与 Strands Agents 之间的集成实现多层认证方式，在不牺牲用户体验或管理简便性的前提下保持安全。当学生或教师从 LibreChat 界面选择一个 Strands Agent 时，认证流程通过若干协同层次在后台无缝运行：**用户认证** – LibreChat 通过你所在机构现有的认证系统处理用户登录，提供包括 OAuth、LDAP/AD 或本地账户在内的多种选项，详见 LibreChat 认证[文档](https://www.librechat.ai/docs/configuration/authentication)。**API Gateway 安全** – 用户通过 LibreChat 认证后，系统使用预配置的 API key 对每个请求进行认证，自动处理 API Gateway 的安全问题。**服务间认证** – 底层 Lambda 函数使用 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色安全地调用部署 Strands Agent 的 Amazon Bedrock AgentCore Runtime。**资源访问控制** – Strands Agents 在已定义的权限范围内运行，只能访问已获授权的资源。

## 部署过程

该方案使用 [AWS Cloud Development Kit](https://aws.amazon.com/cdk/)（AWS CDK）和 [AWS CloudFormation](https://aws.amazon.com/cloudformation/) 通过若干自动化阶段完成部署。我们以日志分析 agent 为例演示部署过程。该 agent 让管理员可以通过自然语言查询对 LibreChat 日志进行分析。

LibreChat 以容器化服务形式部署在 ECS Fargate 集群上，并与支撑服务集成，包括虚拟私有云（VPC）网络、[Application Load Balancer](https://aws.amazon.com/elasticloadbalancing/application-load-balancer/)（ALB），以及由 Aurora PostgreSQL-Compatible、DocumentDB、Amazon EFS 和 Amazon S3 存储构成的完整数据层。安全性内建于其中：恰当的 IAM 角色、安全组和 secrets 管理。

用户活动分析 agent 能提供关于学生如何与 AI 工具交互的有价值洞见，识别使用高峰时段、热门话题以及学生可能需要额外支持的潜在领域。该 agent 通过以下 [CloudFormation 模板](https://github.com/aws-samples/AI-Agents-for-Education/blob/main/Librechat_log_analysis_agent/librechat-log-analysis-agent-stack.yaml)自动预置，该模板使用 Amazon Bedrock AgentCore Runtime 部署 Strands Agents，预置一个调用该 agent 的 Lambda 函数、一个让 agent 成为 URL 端点的 API Gateway，以及第二个访问存储在 DocumentDB 中的 LibreChat 日志的 Lambda 函数。第二个 Lambda 用作该 agent 的工具。

以下代码展示如何配置 LibreChat，使该 agent 成为一个 custom endpoint：

```
custom:
    - name: 'log-analysis-assitant'
      apiKey: '{AWS_API_GATEWAY_KEY}'
      baseURL: '{AWS_API_GATEWAY_URL}'
      models:
        default: ['Strands Agent']
        fetch: false
      headers:
        x-api-key: '{AWS_API_GATEWAY_KEY}'
      titleConvo: true
      titleModel: 'us.amazon.nova-lite-v1:0'
      modelDisplayLabel: 'log-analysis-assitant'
      forcePrompt: false
      stream: false
      iconURL: 'https://d1.awsstatic.com/onedam/marketing-channels/website/aws/en_US/
             product-categories/ai-ml/machine-learning/approved/images/256f3da1-3193-
             441c-b2641f33fdd6.a045b9b4c4f34545e1c79a405140ac0146699835.jpeg'
```

堆栈成功部署后，你可以登录 LibreChat、选择该 agent 并开始聊天。下面的截图展示了一个用户活动分析 agent 可以帮助回答的示例问题，它从 DocumentDB 读取 LibreChat 用户活动并生成答案。

## 部署注意事项与最佳实践

部署此 LibreChat 与 Strands Agents 集成时，组织应仔细考虑几个关键因素，它们会显著影响实施的成功以及长期可持续性。

安全与合规是任何成功部署的基础，在教育环境中数据保护尤为重要。组织必须实施稳健的数据分类方案，以保证敏感信息得到恰当处理；基于角色的访问控制确保用户只能访问与其角色相称的 AI 能力和数据。除传统边界安全之外，当部署可能访问多个不同敏感级别数据源的 AI 系统时，[分层授权](https://aws.amazon.com/blogs/security/enhancing-data-privacy-with-layered-authorization-for-amazon-bedrock-agents/)方式变得至关重要。这包括在应用栈中实施多重授权检查，包括服务间授权、在系统各组件中传递最终用户身份的受信身份传播，以及在每个数据访问点评估权限的细粒度访问控制，而不是仅依赖宽泛的服务级权限。此类分层安全架构有助于缓解 prompt 注入漏洞和未授权的跨租户数据访问等风险，确保即使某一安全层被攻破，仍有其他控制措施在保护敏感的教育数据。定期合规监控变得必不可少，自动化审计与检查在整个系统生命周期内维持对相关数据保护法规的持续遵循，同时验证分层授权策略在系统演进过程中始终有效。

成本管理需要一种在功能与财务可持续性之间取得平衡的战略方式。组织必须根据业务影响和关键程度安排生成式 AI 支出优先级，同时在客户与用户细分之间保持成本透明。实施全面的用量监控，可以帮助组织跟踪 AI 服务的消耗模式，并在成本成为问题之前发现优化机会。部署中人的因素往往比技术实现更具挑战性。教师培训项目应就如何把 AI 工具融入教学提供全面指导，不仅关注如何使用工具，还要关注如何有效地使用它们以取得教育成果。学生引导需要清晰的指南和教程，既促进有效的 AI 交互，也维护学术诚信。也许最重要的是，建立持续的反馈闭环，确保系统依据真实的用户体验和可衡量的教育成果演进，而不是依据对用户需求的假设。成功的部署还需要仔细关注 AI 技术的动态特性。该架构对动态 agent 加载的支持，使组织能够为新院系或用例添加专用 agent 而不中断现有服务。版本控制系统应维护不同的 agent 版本，以便测试和逐步推出改进；性能监控则同时跟踪技术指标和用户满意度，指导持续改进工作。

## 结论

LibreChat 与 Strands Agents 的集成标志着在高等教育中普及先进 AI 能力方面迈出的重要一步。通过把开源系统的可及性与可定制性，同企业级 AI 服务的成熟度与可靠性结合起来，机构可以为学生和教师提供强大工具，提升学习、研究和学业成就。该架构表明，教育机构不必在强大的 AI 能力与机构控制之间做选择。相反，它们可以同时利用开源方案的创新性与灵活性，以及云端 AI 服务的可扩展性与可靠性。本文展示的集成示例说明了该方案的多功能性与定制潜力，可供机构在扩展和调整方案以满足不断变化的教育需求时借鉴。

在后续工作中，LibreChat 系统的 [Model Context Protocol (MCP)](https://www.librechat.ai/docs/features/mcp) 服务器集成能力为增强 agent 架构提供了令人期待的可能。一条特别有前景的路径是把 [agent 包装为 MCP 服务器](https://aws.amazon.com/blogs/opensource/open-protocols-for-agent-interoperability-part-1-inter-agent-communication-on-mcp/)，将它们转换为可以与其他支持 MCP 的 agent 无缝集成的标准化工具。这种方式将使教育者能够组合出成熟的多 agent 工作流，打造针对个体学习风格量身定制的高度个性化教育体验。

教育的未来在于拥有正确的 AI 工具——经过恰当集成、合乎伦理地部署——通过可随教育需求演进的灵活、可互操作、可扩展的方案，增强人类的学习与成就。

**![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/04/smanubol-100x100.png)Sudheer Manubolu** 是 Amazon Web Services（AWS）的解决方案架构师。他专长于云架构、企业解决方案和 AI/ML 实施。他为在 AWS 上构建变革性解决方案的客户提供技术与架构指导，尤其侧重于利用 AWS 的 AI/ML 和容器服务推动创新与卓越运营。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/04/thallaab-100x96.png)**Abhilash Thallapally** 是 AWS 的解决方案架构师，帮助公共部门客户使用 Amazon SageMaker 设计和构建可扩展的 AI/ML 解决方案。他的工作覆盖广泛的 ML 用例，主要兴趣包括计算机视觉、生成式 AI、IoT，以及在 AWS 上部署成本优化的解决方案。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/04/straimar-100x102.png)**Mary Strain** 在 AWS 负责美国教育领域的人工智能与机器学习战略。Mary 的职业生涯始于纽约布朗克斯的一所中学教师。此后，她在教育和公共部门技术组织中担任领导职务。Mary 曾就基于能力的评估、课程设计、微证书和劳动力发展计划等方面的创新政策与实践，为 K12、高等教育以及州和地方政府提供咨询。作为宾夕法尼亚大学教育设计工作室（The Education Design Studio）、有色人种男孩教育学校联盟（The Coalition of Schools Educating Boys of Color）以及新泽西州 AI 工作组（The State of NJ AI Task Force）的顾问，Mary 二十年来一直处于为教育带来创新方案的前沿。
