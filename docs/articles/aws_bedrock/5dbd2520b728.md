## [Artificial Intelligence](https://aws.amazon.com/blogs/machine-learning/)

# TwelveLabs 的 Pegasus 1.5 现已在 Amazon Bedrock 中提供

2026 年 10 月 9 日，我们宣布 [TwelveLabs 的 Pegasus 1.5 已在 Amazon Bedrock 上提供](https://aws.amazon.com/about-aws/whats-new/2026/10/twelve-labs-pegasus-1-5-aws/)。Pegasus 1.5 是一个视频语言模型，可将长视频转换为结构化、带时间戳的元数据。你描述对工作流重要的那些时刻，模型就会把每一个匹配的片段以 JSON 返回。

视频是非结构化数据中一个重要而复杂的类别，然而其中大部分内容仍然无法被搜索、也未被充分利用。要从这些内容中提取结构化、可执行的洞察，过去需要耗费大量人力的人工审阅或碎片化的工具链。

使用 Pegasus 的早期版本，你可以把模型指向一段视频、提出一个问题，然后得到一个答案。现在，Pegasus 1.5 会分析整个视频，找出所有匹配用户自定义条件的片段，并返回结构化、带时间戳的元数据。它还引入了视频分段、带参考图像的多模态提示，以及即时处理。

借助 Amazon Bedrock 上的 Pegasus 1.5，你可以直接从 Amazon Simple Storage Service（Amazon S3）URI 或 base64 字符串分析视频，无需任何预索引，并且你的数据始终留在 AWS 数据边界之内。

在本文中，我们介绍 Pegasus 1.5 的新特性、该模型在 Amazon Bedrock 上的打包方式，以及如何发送你的第一个请求。随后我们会逐步讲解视频分段、结构化 JSON 输出和多模态提示。

## Pegasus 1.5 的新特性

与之前的版本相比，Pegasus 1.5 有以下变化：

- **基于时间的元数据生成。** 由你定义对工作流重要的分段、事件或领域特定的线索，例如编辑段落、体育比赛中的回合、讲话人变化或品牌出现。Pegasus 1.5 会把每一个匹配的片段以 JSON 返回，其中包含开始和结束时间以及所请求的字段。
- **多模态提示。** 一个分段定义可以把文本描述与视觉参考结合起来。这样就可以定位特定的产品、logo 或人物，以及他们在画面中正在做什么。
- **即时处理。** 无需摄取管道或预索引步骤。视频直接从 Amazon S3 发送，结果在响应中返回。
- **扩展的处理能力。** Pegasus 1.5 可在单次请求中分析长达两小时的视频，而 Pegasus 1.2 为一小时。

Pegasus 1.5 保留并增强了使 Pegasus 1.2 成为强大视频理解工具的核心能力，包括：

- **视频到文本生成**：根据视频内容生成详细的文本描述。
- **细粒度视觉理解**：分析视频帧中的对象、屏幕上的文字和数值内容。
- **时间定位**：准确识别视频中特定事件的时间戳。
- **多模态理解**：结合视觉、音频和文本信息进行综合分析。
- **多语言支持**：完全支持英语，并部分支持阿拉伯语、中文、法语、德语、意大利语、日语、韩语、葡萄牙语、俄语、西班牙语、泰语和越南语。

## Pegasus 1.5 在 Amazon Bedrock 上的工作方式

Pegasus 1.5 接收一个视频，以及一个文本提示或一组分段定义，并返回文本或 JSON。你可以通过 `bedrock-runtime` 端点使用 `InvokeModel` API 调用它，或者在希望响应在生成过程中流式返回时使用 `InvokeModelWithResponseStream`。

| **设置** | **值** |
| --- | --- |
| Model ID | `twelvelabs.pegasus-1-5-v1:0` |
| AWS Region | US West (Oregon)，`us-west-2` |
| 推理 | On-demand |
| API | `InvokeModel`、`InvokeModelWithResponseStream` |

每个请求都会以两种分析模式之一运行，通过 `analysisMode` 字段选择：

| **分析模式** | **analysisMode** | **你发送** | **你得到** |
| --- | --- | --- | --- |
| 通用 | `general`（默认） | `inputPrompt` 中的文本提示 | `message` 中的文本答案，或在你提供 schema 时返回 JSON |
| 基于时间的元数据 | `time_based_metadata` | `responseFormat` 中的分段定义 | 一个 `segments` 列表，包含开始和结束时间以及你请求的字段 |

你可以通过两种方式把模型指向视频。S3 位置（`s3Location`）接收对象的 `uri` 和 `bucketOwner` 账户 ID，适合长视频。base64 字符串（`base64String`）把视频嵌入请求体，最大 25 MB，适合短片。

要按应用追踪成本，可以从 Pegasus 1.5 模型创建 application inference profile，为其打上标签，并在调用时用其 Amazon Resource Name（ARN）代替模型 ID。

## Pegasus 1.5 入门

以下部分概述如何开始使用 Pegasus 1.5。

### 先决条件

在开始之前，请确保你具备：

- 一个拥有 Amazon Bedrock 访问权限的有效 AWS 账户。
- Python 3.10 或更高版本，并已安装 AWS SDK for Python（Boto3）。
- 针对 `bedrock:InvokeModel` 和 `bedrock:InvokeModelWithResponseStream` 的 AWS Identity and Access Management（IAM）权限。
- 在 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock/)中为 TwelveLabs Pegasus 1.5 启用了模型访问权限。
- 存储在 Amazon S3 存储桶中的视频，或可以内联发送的短片。

以下策略授予对 Pegasus 1.5 的两个调用操作。

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "bedrock:InvokeModel",
                "bedrock:InvokeModelWithResponseStream"
            ],
            "Resource": [
                "arn:aws:bedrock:us-west-2::foundation-model/twelvelabs.pegasus-1-5-v1:0"
            ]
        }
    ]
}
```

Boto3 使用你常用的 AWS 凭证对请求进行签名。你也可以通过 Amazon Bedrock API key 进行身份验证，方法是把它设置在 `AWS_BEARER_TOKEN_BEDROCK` 环境变量中。在生产环境中，建议使用由 IAM 凭证通过 `aws-bedrock-token-generator` 包生成的短期密钥，因为它会自动过期。使用 bearer token 身份验证还需要 `bedrock:CallWithBearerToken` 权限。

### 发送你的第一个请求

安装 Boto3：

```
pip install boto3
```

以下示例以通用模式分析存储在 Amazon S3 中的视频。该示例使用全局 Cross Region Inference（CRIS）端点。如果要以美国地理端点为目标，请把端点 URL 中的“global.”替换为“us.”。

```
import boto3
import json
from botocore.config import Config

AWS_REGION = "us-west-2"
MODEL_ID = "global.twelvelabs.pegasus-1-5-v1:0"

bedrock_runtime = boto3.client(
    service_name="bedrock-runtime",
    region_name=AWS_REGION,
    config=Config(
        # keep a longer read_timeout for lengthier invocations such as video segmentation
        read_timeout=900,
        retries={"max_attempts": 0},
        connect_timeout=10,
    ),
)

# Analyze a video stored in Amazon S3
payload = {
    "inputPrompt": "Summarize this video and identify the key topics discussed.",
    "mediaSource": {
        "s3Location": {
            "uri": "s3://amzn-s3-demo-pegasus-15/your-video.mp4",
            "bucketOwner": "your-account-id"
        }
    },
    "temperature": 0.2,
    "maxOutputTokens": 4096,
    "includeMetering": True
}

response = bedrock_runtime.invoke_model(
    modelId=MODEL_ID,
    body=json.dumps(payload)
)
result = json.loads(response["body"].read())
print(result["message"])
```

响应在 `message` 中携带答案，在 `input_tokens` 和 `output_tokens` 中携带 token 数，并在 `stopReason` 中给出生成结束的原因。`stopReason` 为 `length` 表示答案在完成之前就达到了 `maxOutputTokens`，所以在依赖输出之前请检查这一项：

```
if result["stopReason"] == "length":
    print("The answer was cut off. Raise maxOutputTokens and try again.")
print("Tokens in:", result["input_tokens"], "out:", result["output_tokens"])
```

通用模式的请求字段：

| **字段** | **必填** | **描述** |
| --- | --- | --- |
| `inputPrompt` | 是 | 关于该视频的问题或指令 |
| `mediaSource.s3Location.uri` | 需要一个视频来源 | 视频的 S3 URI |
| `mediaSource.s3Location.bucketOwner` | 与 `uri` 一起使用 | 拥有该存储桶的 AWS 账户 ID |
| `mediaSource.base64String` | 需要一个视频来源 | Base64 编码的视频，最大 25 MB |
| `temperature` | 否 | 输出的随机性，从 0 到 1。默认 0.2 |
| `maxOutputTokens` | 否 | 要生成的最大 token 数，从 512 到 98,304 |
| `responseFormat` | 否 | 答案必须遵循的 JSON Schema |
| `analysisMode` | 否 | `general`（默认）或 `time_based_metadata` |

对于短片，你可以内联发送视频，而不是从 S3 读取：

```
import base64

with open("your-video.mp4", "rb") as f:
    video_b64 = base64.b64encode(f.read()).decode("utf-8")

payload["mediaSource"] = {"base64String": video_b64}
response = bedrock_runtime.invoke_model(modelId=MODEL_ID, body=json.dumps(payload))
print(json.loads(response["body"].read())["message"])
```

请注意，前面的示例使用了可选的 `includeMetering` 属性。`includeMetering: True` 会让 Pegasus 1.5 在非流式响应中额外添加两个计费用量字段：`outputTokenCount` 和 `inputVideoSecond`（被分析视频的时长，以秒为单位）。

### 流式返回响应

对于交互式应用，`InvokeModelWithResponseStream` 会在答案生成过程中分块返回。每个块在 `message` 中携带下一段文本：

```
response = bedrock_runtime.invoke_model_with_response_stream(
    modelId=MODEL_ID,
    body=json.dumps(payload)
)
for event in response["body"]:
    chunk = json.loads(event["chunk"]["bytes"])
    print(chunk.get("message", ""), end="", flush=True)
print()
```

### 返回结构化 JSON

在通用模式下，你可以把答案约束到某个 JSON Schema，以便下游代码直接解析。把 `responseFormat.type` 设为 `json_schema`，并把 schema 放在 `jsonSchema` 下。答案会以 JSON 字符串的形式出现在 `message` 中：

```
payload = {
    "inputPrompt": "Analyze this video and return a structured summary.",
    "mediaSource": {
        "s3Location": {
            "uri": "s3://amzn-s3-demo-pegasus-15/your-video.mp4",
            "bucketOwner": "your-account-id"
        }
    },
    "temperature": 0,
    "maxOutputTokens": 2048,
    "includeMetering": True,
    "responseFormat": {
        "type": "json_schema",
        "jsonSchema": {
            "type": "object",
            "properties": {
                "summary": {"type": "string"},
                "key_scenes": {"type": "array", "items": {"type": "string"}},
                "setting": {"type": "string"}
            },
            "required": ["summary", "key_scenes", "setting"]
        }
    }
}
response = bedrock_runtime.invoke_model(modelId=MODEL_ID, body=json.dumps(payload))
summary = json.loads(json.loads(response["body"].read())["message"])
print(summary["summary"])
for scene in summary["key_scenes"]:
    print(" -", scene)
```

### 视频分段：把视频转换为结构化数据

基于时间的元数据生成是 Pegasus 1.5 与早期版本差异最大的地方。你发送的不是一个提示，而是一个或多个分段定义，模型会返回视频中匹配每个定义的每一个片段。

把 `analysisMode` 设为 `time_based_metadata`，把 `responseFormat.type` 设为 `segment_definitions`。这些定义取代了 `inputPrompt`，因此请省略该字段。每个定义包含：

- `id`：定义的名称，会在其匹配的每个片段上返回。
- `description`：匹配的片段是什么样子。
- `fields`：要为每个片段提取的值，每项包含 `name`、`type`（`string`、`boolean`、`number`、`integer`、`array` 或 `timestamp`）和 `description`。

以下示例识别新闻广播中的每个编辑段落，并为每一段返回标题、摘要和关键话题：

```
payload = {
    "analysisMode": "time_based_metadata",
    "mediaSource": {
        "s3Location": {
            "uri": "s3://amzn-s3-demo-pegasus-15/news-broadcast.mp4",
            "bucketOwner": "your-account-id"
        }
    },
    "responseFormat": {
        "type": "segment_definitions",
        "segmentTimeFormat": "hh:mm:ss",
        "segmentDefinitions": [
            {
                "id": "editorial_section",
                "description": "A distinct editorial section of the broadcast, "
                "such as a new story, topic, or segment of the program.",
                "fields": [
                    {"name": "segment_title", "type": "string",
                     "description": "A descriptive title"},
                    {"name": "summary", "type": "string",
                     "description": "A brief summary of the segment content"},
                    {"name": "key_topics", "type": "array", "items": {"type": "string"},
                     "description": "Main topics discussed"}
                ]
            }
        ]
    },
    "temperature": 0,
    "maxOutputTokens": 32768,
    "includeMetering": True
}
response = bedrock_runtime.invoke_model(
    modelId=MODEL_ID,
    contentType="application/json",
    accept="application/json",
    body=json.dumps(payload)
)
result = json.loads(response["body"].read())
for segment in result["segments"]:
    print(segment["start_sec"], "-", segment["end_sec"], segment["segment_title"])
    print(" ", segment["summary"])
    print(" topics:", ", ".join(segment["key_topics"]))
```

每个片段都携带 `start_sec`、`end_sec` 以及你定义的 `fields`。`segmentTimeFormat` 控制时间的书写方式：`seconds` 返回可进行算术运算的数字，而 `hh:mm:ss` 和 `hh:mm:ss.fff` 以字符串形式返回可读的时间戳。响应中还包含一个 `definition_errors` 列表，当所有定义都被处理时该列表为空。

单个请求可以包含多个分段定义，例如一个用于编辑段落，另一个用于屏幕上出现的品牌。Pegasus 1.5 会在一个 `segments` 列表中返回所有定义的匹配结果，并用 `_definition_id` 标记每个片段，以便区分。以下示例为前一个请求添加第二个定义，并对结果进行分组：

```
from collections import defaultdict

payload["responseFormat"]["segmentDefinitions"].append({
    "id": "brand_appearance",
    "description": "A shot where a company logo or branded product "
    "is clearly visible on screen.",
    "fields": [
        {"name": "brand", "type": "string", "description": "The brand shown"},
        {"name": "is_prominent", "type": "boolean",
         "description": "Whether the brand is the main focus of the shot"}
    ]
})
response = bedrock_runtime.invoke_model(modelId=MODEL_ID, body=json.dumps(payload))
result = json.loads(response["body"].read())
by_definition = defaultdict(list)
for segment in result["segments"]:
    by_definition[segment["_definition_id"]].append(segment)
for definition_id, segments in by_definition.items():
    print(definition_id, len(segments), "segments")
```

由于 schema 只定义一次，同一组定义可以应用于整个视频库，为每个资产生成一致的元数据。

### 多模态提示：为查询添加上下文视觉信息

Pegasus 1.5 引入了多模态提示，因此你可以在文本提示之外附带参考图像。当你想要询问模型关于特定对象、人物或场景的问题，而展示比描述更容易时，这很有用。

例如，你可以提供一张产品图片，并要求模型找出该产品在视频中出现的每一个时刻。或者，你可以提供某个特定 logo 的参考图像，让模型检测品牌出现的位置及其时间戳。这一能力提升了视频分析的精确度，并开辟了视觉品牌监测、产品植入分析和图像引导的内容搜索等用例。

参考图像的附加方式因模式而异。在通用模式下，把它们放在 `promptV2.mediaSources` 中，问题放在 `promptV2.inputText` 中。在分段模式下（`analysisMode: time_based_metadata`），把它们附加到 `responseFormat.segmentDefinitions` 内每个分段定义的 `mediaSources` 上。这样，一个定义就能同时匹配视觉参考和文本描述。每张图像需要一个 `name`、一个值为 `image` 的 `media_type`，以及恰好一个来源：要么是内联的 `base64String`，要么是带 `uri` 和 `bucketOwner` 的 `s3Location`。单个请求最多可携带 30 张参考图像。

通用模式的请求会就参考图像中展示的对象向模型提问。以下示例负载和响应给出了通用模式下的一个示例。

### 监控用量

Pegasus 1.5 在其模型 ID 下的 `AWS/Bedrock` 命名空间中发布 Amazon CloudWatch 指标，包括 `Invocations`、`OutputTokenCount`、`InvocationLatency` 和 `InvocationClientErrors`。用它们来跟踪调用量和延迟。当你需要按应用拆分用量时，可将其与 application inference profile 搭配使用。

## 用例

Pegasus 1.5 面向管理大量长视频的组织：

- **新闻和广播档案**：团队可以一次性定义编辑段落、话题和讲话人变化，然后对数以年计、此前只能通过转录文本关键词搜索的素材进行编目。
- **体育广播机构和联盟**：在完整比赛素材中检测回合、得分事件和其他关键时刻，加快集锦制作。
- **流媒体应用**：场景级元数据支持基于时刻的推荐、上下文相关的广告投放，以及分段级的品牌安全检查。

在每种情况下，人仍然是工作流的一部分。他们的工作从手工查找并标记每一个时刻，转变为审阅和优化模型生成的元数据。

## 输入要求

Pegasus 1.5 支持以下视频规格：

- **时长**：最长 2 小时。
- **文件大小**：从 Amazon S3 读取时最大 2 GB，作为 base64 字符串时最大 25 MB。
- **分辨率**：360×360 至 5184×2160。
- **宽高比**：介于 1:1 与 2.4:1 之间，或它们的倒数。
- **格式**：FFmpeg 支持的格式。
