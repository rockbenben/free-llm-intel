# 在 Amazon Bedrock 上使用 Coveo Passage Retrieval 提升 LLM 准确性

*本文由 Coveo 的 Keith Beaudoin 和 Nicolas Bordeleau 共同撰写。*

随着生成式 AI 改变业务运营，企业面临一个关键挑战：如何帮助大语言模型（LLM）给出准确且可信的回答？如果缺乏可靠的数据基础，这些 AI 模型可能生成误导性或不准确的回答，从而可能降低用户信任和组织信誉。

作为 AWS 合作伙伴，[Coveo](https://www.coveo.com/en) 通过其 [Passage Retrieval API](https://docs.coveo.com/en/oaie5277/leverage-machine-learning/about-coveo-passage-retrieval-cpr) 应对这一挑战。该解决方案为 LLM 驱动的应用提供相关且能感知上下文的企业知识，为其生成的回答提供依据，从而提升可靠性。在检索增强生成（RAG）系统中，检索过程是最复杂的组成部分，需要从企业数据源中提取最相关、最精确的信息。通过将 [Coveo AI-Relevance Platform](https://www.coveo.com/en/platform) 与 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 集成，组织可以获得业界领先的企业搜索服务，它具备安全、统一的混合索引，遵循企业权限模型，并提供强大的连接能力。Coveo AI-Relevance Platform 利用机器学习（ML）和深入的使用分析持续优化相关性。这使 Amazon Bedrock Agents 能够针对复杂的企业内容提供有依据、贴合上下文的回答。

Coveo AI-Relevance Platform 是一项业界领先的服务，它将云上和本地仓库的内容连接并统一到单一索引中，让快速找到相关内容变得简单高效。其 ML 算法会分析用户行为、应用内上下文以及档案与权限数据，以检索个性化的搜索结果和建议，随后将洞察汇总并回传给内容与体验管理者。通过与企业的各类系统（如网站、知识库和 CRM）无缝集成并强制执行安全权限，Coveo 帮助用户在保护数据的同时获得最相关的信息。

在本文中，我们展示如何将 Coveo 的 [Passage Retrieval API](https://docs.coveo.com/en/oaie5277/leverage-machine-learning/about-coveo-passage-retrieval-cpr) 部署为 Amazon Bedrock Agents 操作组，以提升回答准确性，让 Coveo 用户能够利用现有索引在全组织范围内快速部署新的生成式体验。

## Coveo 的 Passage Retrieval API

[Coveo Passage Retrieval API](https://docs.coveo.com/en/oaie5277/leverage-machine-learning/about-coveo-passage-retrieval-cpr) 通过传入从统一索引中检索到的排序文本段落（或称*分块*），以及适当的元数据（例如用于引用的来源 URL），为 LLM 应用提供增强，使生成的答案扎根于组织的专有知识。Passage Retrieval API 构建于 Coveo 的统一混合索引之上，采用两阶段检索流程，从结构化和非结构化内容源中提取最相关的段落，提供准确性、安全性和实时相关性。下图展示了这些阶段。

![Coveo 的两阶段内容检索](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/19/Coveo-Passage-Retrieval-API.jpeg)

该过程包含以下关键组件：

- **使用两阶段检索流程提取相关段落** – 在第一个检索阶段，使用 Coveo 的混合搜索系统识别最相关的文档。随后，它从这些文档中提取最相关的文本段落，并附带排名分数、引用链接和其他关键元数据。这种两阶段方法让 Coveo 能够先从各来源中识别可访问且相关的文档，再更精确地定位最相关的段落。
- **通过混合排名增强搜索结果** – 结合语义（向量）搜索与词法（关键词）匹配，帮助 Coveo 在正确的上下文中检索到正确的信息。
- **ML 相关性** – AI 持续从用户交互中学习，针对每个用户的旅程、行为和档案来定制检索，从而提供贴合上下文的回答。
- **通过统一索引跨源连接内容** – 一个集中式的混合索引连接各来源的结构化和非结构化内容。与联邦搜索方式相比，这种统一混合索引通过跨来源应用排名函数，提供了更好的多源相关性。Coveo 还提供丰富的预构建连接器库，以保持与第三方服务（如 Salesforce、SharePoint 和 Google Drive）的无缝集成，并通过自动更新实现数据新鲜度，支持实时检索。
- **用于跟踪性能的分析与洞察** – 通过数据平台和 Knowledge Hub 进行事件跟踪，你可以准确看到生成的答案表现如何、哪些信息缺失或未被充分利用，以及哪些内容需要调优。借助这些洞察，你可以提升答案质量并带来可衡量的业务影响。
- **企业级安全** – Coveo 通过早期绑定方式在抓取时导入条目级权限，从而提供每个所连接内容源的原生权限模型。在建立索引前解析访问权限有助于防止数据泄漏，并通过在查询执行前过滤掉用户看不到的条目来提升搜索性能。
- **重新定义企业级就绪的 RAG** – Coveo 超越基础向量搜索，重新构想 RAG 系统所能实现的能力，提供面向企业需求设计的动态、智能检索流水线。其核心是一个统一混合索引，可无缝连接结构化、非结构化和权限敏感的数据。这一基础再加上实时的 ML 驱动调优，有助于确保传递给 LLM 的每个响应都是相关的，并安全地扎根于正确的上下文。

通过原生访问控制执行、基于行为的相关性调整，以及对内容使用情况和性能的深入分析，Coveo 让组织能够持续优化其生成式 AI 体验。凭借来自 Gartner、Forrester 和 IDC 等领先分析机构的持续认可，Coveo 为企业级生成式 AI 提供了可靠、安全且可扩展的基础。

## 解决方案概览

该解决方案展示了如何将 Coveo 的 Passage Retrieval API 与 Amazon Bedrock Agents 集成，构建能够提供准确、贴合上下文且有依据的回答的 LLM 驱动助手。它广泛适用于 agent 需要访问专有知识的各类用例，无论是支持客户、协助员工，还是赋能销售与服务团队。这种方法有助于让 AI 回答扎根于跨结构化与非结构化内容中最相关、最可信的信息。Amazon Bedrock Agents 充当该解决方案的智能骨干，负责解读自然语言查询并编排检索过程，以交付有依据、贴合上下文的洞察。在此用例中，该 agent 被配置为回答用户关于 Coveo 服务能力、API 文档和集成指南的问题。该 agent 旨在针对用户问题从企业内容中获取精确段落，从而支撑虚拟助手、支持 copilot 或内部知识机器人等应用。通过结构化的定义和指令，该 agent 理解何时以及如何触发 Coveo 的 Passage Retrieval API，确保 LLM 生成的回答有准确、可信的内容支撑。

操作组定义了 Amazon Bedrock agent 可以调用的结构化 API 操作。它使用 OpenAPI 规范定义 agent 与 [AWS Lambda](https://aws.amazon.com/lambda) 函数之间的接口。在此用例中，根据用户的搜索意图获取相关段落是唯一可用的操作。

下图展示了解决方案架构。

![Coveo's-Passage-Retrieval-API-in-Amazon-Bedrock-Agent-Solution-Overview](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/19/Solution-overview.png)

在此演示中，该 agent 在创建时被设置了以下指令：

```
You will act as an expert on Coveo documentation, platform, APIs, analytics, and integration guides.
        Use the CoveoPRAPI Action Group to retrieve relevant information on Coveo documentation, platform, APIs, analytics, and integration guides.
        Summarize the information retrieved from the Action Group response clearly and accurately.
        OuputFormatting guidelines:
        - Provide clear, direct answers without introductory phrases such as “As an expert,” “Sure,” or “Here is...”
        - When appropriate, organize content using:
          - Numbered or bulleted lists
        - Structured sections (e.g., features, steps, key points)
        Keep answers concise, informative, and free of conversational filler.
```

操作组中定义的 Lambda 函数对于使 Amazon Bedrock agent 能够调用 Coveo Passage Retrieval API 至关重要。该 Lambda 函数执行以下任务：

- 接收来自 Amazon Bedrock agent 的传入请求
- 使用用户的输入查询 Coveo Passage Retrieval API
- 将相关搜索结果返回给 Amazon Bedrock agent

最后，Coveo AI-Relevance Platform 通过 Passage Retrieval API 提供已建立索引的结构化搜索结果。

## 先决条件

在开始之前，你必须具备以下先决条件：

- 一个 [AWS 账户](https://aws.amazon.com/resources/create-account/)，并具备 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）权限，可部署 [AWS CloudFormation](https://aws.amazon.com/cloudformation) 堆栈
- 可访问 Amazon Bedrock 中的模型
- 已创建并准备就绪的 Coveo 索引
- 以下 Coveo 信息：Coveo organization ID、Coveo search hub、Coveo API key

## 使用 AWS CloudFormation 部署解决方案

要部署你的 agent，请完成以下步骤：

- 启动 CloudFormation 堆栈：
[![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/19/launchStack-logo.jpeg)](https://console.aws.amazon.com/cloudformation/home?region=us-east-1#/stacks/create/review?templateURL=https://aws-blogs-artifacts-public.s3.us-east-1.amazonaws.com/ml-18821/TemplateBedrockCoveoPRAPI-vF.yaml)
- 输入堆栈名称，以及 **AgentModelID**、**AgentName**、**CoveoApiKey**、**CoveoOrgID** 和 **CoveoSearchHub** 的值。
- 在 **Capabilities** 部分，勾选确认复选框。
- 选择 **Create stack**。
- 等待堆栈创建完成。
- 在堆栈详情页面上确认所有资源均已创建。

## 测试解决方案

要测试该解决方案，请完成以下步骤：

- 在 Amazon Bedrock 控制台的导航窗格中，选择 **Agents**。
- 选择由 CloudFormation 堆栈创建的 agent。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/19/agent-overview-screenshot.jpeg)

- 在 **Test** 下，在消息框中输入你的问题。

在此演示中，Coveo 的技术文档（来自其网站）已被摄取到现有的 Coveo 搜索索引中。让我们从查询“What is the difference between Coveo Atomic and Headless?”开始。

以下是当使用 Claude 3 Haiku v1 作为 LLM 时，agent 对该问题的回答。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/29/agent-builder-answer-screenshot-1.png)

- 在右侧窗格中选择 **Show trace**，并展开 **Trace step 1** 查看 agent 的推理依据。

以下截图展示了 Amazon Bedrock Agents 如何处理并回答该问题。首先，它形成了一段推理依据：

```
To understand the difference between Coveo Atomic and Headless, I will need to retrieve relevant information from the Coveo technical documentation using the CoveoPRAPI Action Group.
```

然后它调用 `CoveoPRAP` 操作组，该操作组专门用于检索相关段落，并通过 Lambda 函数对 `/rest/search/v3/passages/retrieve` 发起 API 调用。

此示例展示了该 agent 通过 CoveoPRAP1 操作组规划和执行必要操作的系统化方式，并在形成最终回答之前检索相关的文档分块。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/19/agent-orchestration-trace-screenshot.png)

该 Lambda 函数代码包含一个调试功能，会记录从 Passage Retrieval API 检索到的每一段内容。该日志机制会遍历返回的 chunk，依次编号以便快速查阅。这些日志可在 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 中查看，因此你可以准确看到每个用户查询检索到了哪些段落，以及它们如何促成最终回答。要查看这些日志，请打开 CloudWatch 控制台，在 **Log groups** 页面中找到该 Lambda 函数的名称。

以下截图展示了 CloudWatch 中 agent 的详细日志。在日志中，Coveo Passage Retrieval API 向 LLM 返回了最相关的五个分块。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/19/agent-cloudwatch-log-screenshot.png)

## 清理

为避免持续产生费用，请删除作为 CloudFormation 堆栈一部分部署的资源：

- 在 AWS CloudFormation 控制台的导航窗格中，选择 **Stacks**。
- 选择你创建的堆栈，然后选择 **Delete**。
- 出现提示时，选择 **Delete** stack。

更多信息请参阅 [Deleting a stack on the AWS CloudFormation console](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/cfn-console-delete-stack.html)。

## 结论

通过将 Amazon Bedrock 的能力与 Coveo 的 AI 驱动检索相结合，组织可以开发出基于其企业内容提供经过验证的回答的 AI 应用。这种方法有助于减少不准确之处，同时提供实时、安全的响应。

我们鼓励你探索 [GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-samples) 中的预构建示例，以帮助你开始使用 Amazon Bedrock。
