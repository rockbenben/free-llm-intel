# 从学习到排行榜：Cisco 如何借助 AWS AI League 让 1,200 名工程师掌握 agentic AI 技能

Cisco 与许多大型工程组织一样，正在采用生成式 AI 和 agentic AI 来改变工程师构建软件的方式。难点已不再是获取技术，而是帮助数千名工程师从观看演示，走向有信心地亲手构建。录制课程和幻灯片很少能弥合这一差距。工程师学得最快的方式，是构建真实的东西、看到它失败、修复它，然后再试一次。

AWS 正是为此设计了 [AWS AI League](https://aws.amazon.com/ai/aileague/)。它把动手实践的 AI 学习变成一场游戏化竞赛：参与者在 AWS 上定制模型、构建 agent，在实时排行榜上获得即时反馈，并在游戏节目式的总决赛中同台竞技。

Cisco 是这一模式在规模化落地方面最清晰的示例之一。2025 年，Cisco 软件工程师 Hemanth V 从 Cisco 内部活动一路走到在 AWS re:Invent 2025 上被加冕为首位 AWS AI League 冠军。2026 年，1,200 名 Cisco 工程师在 Cisco Transformation Fest 4.0 的 AWS AI League 锦标赛中同场竞技。获胜者 Nishanth Aluhonnu 赢得了 AWS re:Invent 2026（拉斯维加斯）的全场通行证。

本文分享 Cisco 和 AWS 如何借助 Cisco Transformation Fest 和 AWS AI League，构建持久的“边做边学”文化。我们此前在 [From theory to delivery: How Atos upskilled 400 engineers in agentic AI](https://aws.amazon.com/blogs/machine-learning/from-theory-to-delivery-how-atos-upskilled-400-engineers-in-agentic-ai/) 中介绍过这一项目，本文则聚焦 Cisco 的经验。我们会梳理 Cisco 的历程，分享 2026 年获胜 agent 的技术经验，并说明你的组织如何举办自己的 AWS AI League。

# 什么是 AWS AI League？

AWS AI League 帮助组织通过竞赛培养高级 AI 技能。每一季联赛都遵循三个步骤：

- **Learn（学习）——** 由 AWS 专家主持的 2 小时动手实践工作坊，介绍相关工具和挑战内容。
- **Build（构建）——** 参与者按自己的节奏实验，并提交到实时排行榜；自动评估器在每次提交后给出实时反馈。
- **Compete（竞赛）——** 顶尖入围者登上舞台，参加现场游戏节目式的总决赛。

尽管 AWS AI League 提供多种用例，在 Cisco 它提供了以下两项挑战：

- **Agentic AI 挑战——** 参与者使用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 构建 agent，该平台可用任意框架或模型大规模构建、连接和优化 agent。agent 在迷宫式网格中移动，沿途解决挑战，最终抵达宝箱。这些挑战对应现实任务，例如处理不当内容、运行代码、从 Web 检索信息以及提取结构化数据。构建者可为 supervisor agent 和 sub-agent 选择模型，并添加工具，例如 [AgentCore memory（Amazon Bedrock AgentCore 的一项能力）](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html)和 [AWS Lambda Event Functions](https://aws.amazon.com/lambda/lambda-functions/)。构建者使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 为 agent 应用安全控制。
- **模型定制挑战——** 参与者使用最新训练配方在 [Amazon SageMaker Studio](https://aws.amazon.com/sagemaker/ai/studio/) 中微调模型。当自动评估器判定参与者定制的模型在竞赛特定任务上比参考模型更准确、更全面时，挑战会为其加分。

入围者按时间效率、准确性、agent 规划和 token 消耗效率评分。

- **Cisco Cloud Control**，一款与 AWS 服务集成的云原生、AI 驱动的应用，整合安全、网络、可观测性和协作。
- **Cisco AI Defense**，Cisco 安全团队在此使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/)，在 Cisco 产品组合中嵌入 AI 治理和 guardrails。

两家公司还发布了跨网络和 AWS 的联合部署指南与 Cisco Validated Designs。近期联合创新的一个例子是跨 AWS 骨干网的按需 SD-WAN fabric，旨在提供客户所期望的韧性和正常运行时间。

# 剖析赢得 agentic AI 挑战需要什么

2026 年的获胜 agent 提供了远超游戏本身的经验。每个设计选择都对应团队在生产中运行 agent 时面临的决策。

## 输出 token 才是真正的成本

Agentic AI 挑战按挑战得分、宝箱奖励、剩余生命和 token 奖励来给 agent 评分，计算方式为 `tokenBonus = 1000 - (totalOutputTokens / challengesVisited)`。

在资格赛中，前四名 agent 都解出了地图。第一名 agent 输出 1,220 个 token，第二名输出 1,430 个，最终差距仅是近 16,000 分中的 16 分。当每个 agent 都能解决问题后，效率决定胜负。

为了解哪些 token 重要，Nishanth 构建了同一 agent 的九个变体，每次只改变一个因素。结果很明确：工具结果和系统提示词不计入评分，但 agent 写出的所有内容，包括工具调用参数，都计入。每次工具调用除参数外，还有约 52 个 token 的固定开销。

这与现实成本相呼应。生成输出是顺序进行的，价格通常比输入高数倍，而在 agent 循环中，这一成本会在每一步累积。冗长且结构良好的系统提示词（也可以缓存）很便宜。话多的 agent 则不然。

## 一个 agent，而非五个

应对这一挑战的常见架构是：在 Amazon Bedrock AgentCore 上设置 supervisor agent，将任务委派给负责导航、计算和 Web 检索的专门 sub-agent。对许多生产系统而言，这是合理的模式。获胜设计使用单个 agent，没有 sub-agent。取而代之的是，提示词开头有一个简短的分发表，将每种挑战类型匹配到单轮中的正确方法。

理由很简单：agent 之间的每次交接都是模型必须写的一条消息，而在这场挑战中，每个写出的 token 都计分。这并不意味着 sub-agent 不好，而是要根据协调成本来选择架构。当协调成本高昂时，更扁平的设计可能胜出。

下图展示了 agentic AI 挑战的 AWS 参考架构：带专门 sub-agent 的 supervisor agent。获胜设计有意没有使用这种多 agent 模式。

![AWS AI League 参考架构：supervisor agent 和三个 sub-agent](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/03/ML-22161-5.png)

图 5：AWS AI League 参考架构

在此参考架构中，supervisor agent 运行在 Amazon Bedrock AgentCore runtime（Amazon Bedrock AgentCore 的一项能力）中，协调三个 sub-agent，Amazon Bedrock Guardrails 和 AgentCore memory 连接到该 runtime。supervisor 和 sub-agent 通过 Amazon Bedrock AgentCore Gateway（Amazon Bedrock AgentCore 的一项能力）路由到四个工具：导航工具、浏览器工具、代码执行工具以及使用 AWS Lambda 函数的自定义工具。

## 将确定性逻辑放入工具

路线规划没有交给模型。它在 AWS Lambda 函数中运行，将棋盘视为优化问题。每个格子都有预期价值：它能带来的分数，减去它可能消耗的生命，再减去 agent 解决它所需的 token。规划器遵守约束（例如先收集钥匙再开门），并在时间预算内优化路线。

这是对大多数 agent 都有用的模式：让模型处理语言和判断，把搜索、数学和规则移到工具中，在那里更快、更便宜且可重复。

## 基于价值而非习惯做决策

第二轮总决赛被设计成一个陷阱。一个 7×7 的棋盘几乎布满每枚价值 25 分的硬币，而单个调度挑战格价值 1,500 分。习惯告诉人们去收集硬币。规划器的价值表表明，硬币是噪音。agent 选择高价值挑战，在该轮得到 7,537 分，而下一名入围者为 5,953 分。那一轮建立了领先优势，并最终帮助该 agent 赢得总冠军。
