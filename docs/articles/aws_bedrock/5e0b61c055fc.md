# 从学习到上榜：Cisco 如何用 AWS AI League 让 1,200 名工程师掌握 agentic AI

Cisco 与许多大型工程组织一样，正在引入生成式 AI 和 agentic AI，改变工程师构建软件的方式。难点已不再是能不能拿到技术，而是如何让数千名工程师从看演示，走到有把握地亲手构建。录播课程和幻灯片很少能弥合这道差距。工程师学得最快的路径，是自己做出点真东西，看它失败，修好，再试一次。

AWS 设计 [AWS AI League](https://aws.amazon.com/ai/aileague/) 正是为了这件事。它把动手式 AI 学习变成一场游戏化竞赛：参与者在 AWS 上定制模型、构建 agent，在实时排行榜上拿到即时反馈，最后在游戏节目式的总决赛中同台竞技。

Cisco 是这套模式规模化落地最清晰的例子之一。2025 年，Cisco 软件工程师 Hemanth V 从 Cisco 内部活动一路走到 AWS re:Invent 2025，成为首位 AWS AI League 冠军。2026 年，1,200 名 Cisco 工程师在 Cisco Transformation Fest 4.0 的 AWS AI League 锦标赛中同场竞技，冠军 Nishanth Aluhonnu 拿到了 AWS re:Invent 2026（拉斯维加斯）的全场通行证。

本文介绍 Cisco 与 AWS 如何借助 Cisco Transformation Fest 和 AWS AI League，培育一种持久的「边做边学」文化。我们此前在 [From theory to delivery: How Atos upskilled 400 engineers in agentic AI](https://aws.amazon.com/blogs/machine-learning/from-theory-to-delivery-how-atos-upskilled-400-engineers-in-agentic-ai/) 中写过这一项目，这次聚焦 Cisco 的经历：梳理 Cisco 的历程，分享 2026 年获胜 agent 的技术经验，并说明你的组织如何举办自己的 AWS AI League。

# 什么是 AWS AI League？

AWS AI League 帮助组织通过竞赛培养进阶 AI skill。每一季联赛都按三步推进：

- **Learn（学习）——** 由 AWS 专家带领的 2 小时动手工作坊，介绍工具和挑战内容。
- **Build（构建）——** 参与者按自己的节奏试验，并提交到实时排行榜，自动评估器在每次提交后即时反馈。
- **Compete（竞赛）——** 顶尖入围者登台，进行现场游戏节目式的总决赛。

AWS AI League 提供多种用例，在 Cisco 落地的是以下两项挑战：

- **Agentic AI 挑战——** 参与者用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 构建 agent，这个平台可以用任意框架或模型大规模构建、连接和优化 agent。agent 在迷宫式网格中穿行，沿途解开挑战，最终抵达宝箱。这些挑战对应现实任务，例如处理不当内容、执行代码、从 Web 检索信息、提取结构化数据。构建者可以为 supervisor agent 和 sub-agent 选择模型，并挂接工具，例如 [AgentCore memory（Amazon Bedrock AgentCore 的一项能力）](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html)和 [AWS Lambda Event Functions](https://aws.amazon.com/lambda/lambda-functions/)。构建者用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 给 agent 加上安全控制。
- **模型定制挑战——** 参与者在 [Amazon SageMaker Studio](https://aws.amazon.com/sagemaker/ai/studio/) 中用最新的训练配方微调模型。当自动评估器判定参与者定制的模型在竞赛特定任务上比参考模型更准确、更全面时，挑战即给予加分。

入围者按时间效率、准确性、agent 规划和 token 消耗效率评分。

# Cisco 与 AWS 的合作

Cisco 的 AWS AI League 故事，根植于一段深厚的工程合作。Cisco 与 AWS 为共同客户把网络、云、安全和可观测性结合起来，其中包括：

- **Cisco SD-WAN**，其控制器架构运行在 AWS 上，作为软件即服务（SaaS）应用服务全球客户。
- **Cisco Meraki**、**Cisco Spaces**，以及 Cisco 的 IoT 和智能建筑团队。
- **Cisco Cloud Control**，一款与 AWS 服务集成的云原生 AI 应用，把安全、网络、可观测性和协作汇到一处。
- **Cisco AI Defense**，Cisco 安全团队在这里用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/)，在整个 Cisco 产品组合中嵌入 AI 治理和 guardrails。

两家公司还发布了覆盖网络与 AWS 的联合部署指南和 Cisco Validated Designs。近期的一项联合创新是跨 AWS 骨干网按需提供的 SD-WAN fabric，目标是交付客户期待的韧性和正常运行时间。

> “当你看到那么多业务部门各自独立地选择在 AWS 上原生构建下一代平台，这就不是供应商关系了。这是真正的工程合作伙伴关系。”

Cisco 工程副总裁 Kumaril Kapoor 与 AWS Industries India 负责人 Chandra Balani 坐下来聊了 AWS 与 Cisco 的合作故事：从跨网络、云和 AI 的联合创新，到通过一年一度的 Cisco AWS Transformation Fest 赋能数千名工程师。

# 拆解赢得 agentic AI 挑战的关键

2026 年的获胜 agent 给出的经验，远不止于这场游戏。它的每个设计选择，都对应团队在生产环境运行 agent 时要做的决定。

## 输出 token 才是真正的成本

agentic AI 挑战按挑战得分、宝箱奖励、剩余生命和 token 奖励给 agent 打分，token 奖励的计算方式是 `tokenBonus = 1000 - (totalOutputTokens / challengesVisited)`。

资格赛中，前四名 agent 都解出了地图。第一名输出 1,220 个 token，第二名输出 1,430 个，最终差距只是近 16,000 分里的 16 分。当所有 agent 都能解出问题时，效率决定胜负。

为了弄清哪些 token 真正起作用，Nishanth 做了同一 agent 的九个变体，每次只改一处。结果很清楚：工具返回结果和系统 prompt 不计入评分，agent 写出的所有内容——包括工具调用参数——都计入。每次工具调用在参数之外，还带着约 52 个 token 的固定开销。

这与真实世界的成本结构一致。输出生成是串行的，定价通常比输入高出数倍，而在 agent 循环里，这笔开销会在每一步上叠加。冗长但结构良好的系统 prompt（还可以缓存）很便宜，话多的 agent 则不便宜。

## 一个 agent，而不是五个

这类挑战的常见架构，是在 Amazon Bedrock AgentCore 上放一个 supervisor agent，把导航、计算和 Web 检索分派给专门的 sub-agent。对许多生产系统来说，这是站得住的模式。获胜设计只用一个 agent，没有 sub-agent，而是在 prompt 开头放了一张简短的分发表，把每种挑战类型对应到单轮之内应采取的做法。

理由很简单：agent 之间的每次交接，都是模型必须写下的一条消息，而在这场挑战里，写出的每个 token 都计分。这并不是说 sub-agent 不好，而是要根据协调的代价来选架构。协调很贵时，更扁平的设计反而能赢。

下图是 agentic AI 挑战的 AWS 参考架构：一个 supervisor agent 搭配若干专门 sub-agent。获胜设计有意没有采用这种多 agent 模式。

![AWS AI League 参考架构，含一个 supervisor agent 和三个 sub-agent](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/03/ML-22161-5.png)

图 5：AWS AI League 参考架构

在这套参考架构里，supervisor agent 运行在 Amazon Bedrock AgentCore runtime（Amazon Bedrock AgentCore 的一项能力）中，协调三个 sub-agent，Amazon Bedrock Guardrails 和 AgentCore memory 接入该 runtime。supervisor 和 sub-agent 经由 Amazon Bedrock AgentCore Gateway（Amazon Bedrock AgentCore 的一项能力）路由到四个工具：导航工具、浏览器工具、代码执行工具，以及基于 AWS Lambda 函数的自定义工具。

## 把确定性逻辑放进工具

路线规划没有交给模型。它跑在一个 AWS Lambda 函数里，把棋盘当作优化问题来处理。每个格子都有一个期望值：它能带来的分数，减去它可能消耗的生命，再减去 agent 解开它要花的 token。规划器遵守约束，比如先拿到钥匙才能开门，并在时间预算内优化路线。

这对大多数 agent 都是有用的模式：让模型负责语言和判断，把搜索、计算和规则挪进工具，在那里更快、更便宜，也可重复。

## 按价值决策，而不是按习惯

总决赛第二轮被设计成一个陷阱。一块 7×7 的棋盘几乎铺满了每枚 25 分的硬币，而只有一个调度挑战格价值 1,500 分。习惯告诉你去收硬币，规划器的价值表却说这些硬币是噪音。agent 奔着高价值挑战去，那一轮拿到 7,537 分，下一名入围者是 5,953 分。正是那一轮建立的领先，把它一路带到总冠军。

# 对 Cisco 的影响

在 Cisco 办 AWS AI League 的两年里，影响体现在 skill、文化和认可三个方面：

- **规模化的动手 AI skill。** 1,200 名工程师参加了 2026 年锦标赛，在 Amazon Bedrock AgentCore 上构建 agent，其中很多人此前没有 agentic AI 经验。
- **跨业务部门的连接。** 原本永远不会碰面的工程师在同一场锦标赛里竞争、交流做法、互相学习。
- **持久的学习文化。** Transformation Fest 已经办到第四年，成了年度承诺，而不是一次性的黑客松。
- **连续两年获得认可。** 一位 Cisco 工程师拿下 2025 AWS AI League 全球冠军，2026 年的 Cisco 冠军将出席 AWS re:Invent 2026。
- **领导层可见度。** 2026 年总决赛在 Cisco 和 AWS 高层领导面前举行，给工程师一个真正展示工作的舞台。

对 Hemanth 来说，最大的收获是信心。开始之前不需要把一切都学会，动手去做，自然就学会了。

> “只有技术还不够，还需要有被赋予空间去尝试它的人。Transformation Fest 造出了这样的赋能环境，AWS AI League 造出了执行的机会。”
>         — Kumaril Kapoor，Cisco 工程副总裁
