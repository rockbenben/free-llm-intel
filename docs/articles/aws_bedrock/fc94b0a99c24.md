# Meta 的 Muse Spark Open 现已在 Amazon SageMaker JumpStart 上线

Meta 针对编码优化的开放权重模型 Muse Spark Open，现已在 [Amazon SageMaker JumpStart](https://aws.amazon.com/sagemaker/ai/jumpstart/) 上线，它是 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/) 的机器学习（ML）中心。该模型基于真实的开发者工作流训练，例如多文件重构和漫长的调试会话，并支持 100 万 tokens 的上下文窗口。只需几个步骤，你就能把它部署到自己 AWS 账户里的一个 SageMaker AI endpoint 上，而不必自己管理 serving 基础设施。SageMaker JumpStart 提供两种变体：BF16（`Muse-Spark-Open-816B-A42B`）和 NVFP4 量化（`Muse-Spark-Open-816B-A42B-NVFP4`）。

在这篇文章中，我们介绍 Muse Spark Open，并演示如何用 [Amazon SageMaker Studio](https://aws.amazon.com/sagemaker/ai/studio/) 和 [SageMaker Python SDK](https://sagemaker.readthedocs.io/en/stable/) 部署该模型、向它发送第一个推理请求，以及完成清理。

## Muse Spark Open 概览

Meta 把 Muse Spark Open 描述为一个针对编码优化的模型，为 agentic 编码工作流而训练，重点放在首次尝试准确率、tool calling 以及对大型代码库的理解上。它是一个推理模型，输入接受文本、图像、文档、音频和音视频，返回文本。

Muse Spark Open 采用 mixture-of-experts (MoE) 架构，总参数量 8160 亿，其中每个 token 激活 420 亿。该模型承载着一个极大网络的容量，而它在每个 token 上花费的计算量更接近一个小得多的 dense 模型。Meta 以 Muse Model License 发布权重，该许可证包含 Muse Spark Usage Policy。

下表总结了该模型。

| **属性** | **Muse Spark Open** |
| --- | --- |
| 提供方 | Meta |
| 架构 | Mixture of experts (MoE)，推理模型 |
| 参数 | 总计 816B，激活 42B |
| 上下文长度 | 1M tokens |
| 输入模态 | 文本、图像、文档、音频、音视频 |
| 输出模态 | 文本 |
| SageMaker JumpStart 中的变体 | BF16 和 NVFP4 |
| 许可证 | Muse Model License，包含 Muse Spark Usage Policy |

## 为长时间运行的编码 agent 而建

Meta 按开发者在真实仓库里的工作方式来训练 Muse Spark Open：代码生成、调试、多文件重构，以及运行很久才结束的任务。借助 100 万 tokens 的上下文窗口，该模型可以吞下整个项目，包括它的依赖、遗留代码和成千上万个文件。你不需要把一个任务拆成更小的块去迁就上下文。

Meta 从一开始就把 Muse Spark Open 设计成一个 agentic 模型。Meta 表示，该模型会在很长的跨度上规划、行动、观察结果并自我纠正，而不是发起单次 tool call。作为推理模型，它在行动前先把任务推演清楚，而 SageMaker AI endpoint 会把这段推理和答案一起返回，于是你能跟进一个 agent 正在做什么、以及为什么这么做。Meta 训练该模型浏览网页、为可拆分的工作协调 subagents，并在桌面、移动和浏览器环境中操作计算机。这些是模型自身的能力。在 SageMaker AI 上，由你的应用或 agent 框架来提供模型所调用的工具、浏览器和 computer-use 环境。除代码之外，Meta 还称 Muse Spark Open 能够跨图像、文档、音频和视频进行推理。

模型的两个特性决定了它该怎么被服务。第一，稀疏激活让每个 token 的计算量保持很低，但服务时仍需要足够的 GPU 显存来容纳全部 8160 亿参数，所以实例选择最终取决于显存容量。第二，NVFP4 变体用 NVIDIA 的 4-bit 浮点格式存储权重，所需显存大约只有 BF16 权重的四分之一。在 SageMaker AI 上，这个差别决定了实例：NVFP4 变体运行在 `ml.p5e.48xlarge` 上，BF16 变体运行在 `ml.p6-b300.48xlarge` 上。因此当你按成本来定规模时，NVFP4 是应当先试的变体。在你自己的工作负载上评估它，以确认质量符合你的用例。

在 SageMaker AI 上拿到开放权重，也意味着部署由你掌控。endpoint 运行在你的 AWS 账户内，所以你的源代码和 prompts 是在由你配置、由你控制的基础设施上处理的。你可以把 endpoint 接入你自己的 [Amazon Virtual Private Cloud (Amazon VPC)](https://aws.amazon.com/vpc/)，用来自 [AWS Key Management Service (AWS KMS)](https://aws.amazon.com/kms/) 的密钥加密它的存储卷，并为容器开启网络隔离。实例类型和扩缩上限也由你选，你还可以锁定模型版本，于是模型只在你重新部署时才改变。

## 用例

你可以把 Muse Spark Open 用于广泛应用场景。Meta 对编码与 agentic 工作流的聚焦，使它适合下列用例：

- **面向私有仓库的编码助手**：在把整个项目都放进上下文的情况下回答关于大型代码库的问题、重构它们并调试它们，而代码是在你账户内的 endpoint 上处理的。
- **长时间运行的编码 agent**：运行这样的 agent——它规划一次改动、跨多个文件编辑、在你自己的沙箱里执行测试，并依据结果纠正方向。
- **多模态工程工作流**：把截图、设计文档，或一段带音频和视频的缺陷录屏，变成一份复现方案或一版修复草稿。

## 开始使用 SageMaker JumpStart

你可以从 SageMaker Studio 部署 Muse Spark Open，也可以用 SageMaker Python SDK。两条路径都会在你的账户里创建一个实时的 SageMaker AI endpoint。

### 前置条件

开始之前，请确认你已经具备以下条件：

- 一个 AWS 账户，并拥有创建 SageMaker AI 模型与 endpoint 的权限。
- 一个供 SageMaker AI 使用的 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 执行角色。就本次演练而言，`AmazonSageMakerFullAccess` 托管策略已经足够。用于生产时，请把角色限定到你的部署所需要的操作和资源。细节参见[如何使用 SageMaker AI 执行角色](https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-roles.html)。
- 一个可访问 SageMaker Studio 的 SageMaker AI domain，用于 Studio 路径。搭建步骤参见[使用快速设置上手 Amazon SageMaker AI](https://docs.aws.amazon.com/sagemaker/latest/dg/onboard-quick-start.html)。
- endpoint 实例类型的服务配额：NVFP4 变体对应 **ml.p5e.48xlarge for endpoint usage**，BF16 变体对应 **ml.p6-b300.48xlarge for endpoint usage**。要提升配额，参见[请求提升配额](https://docs.aws.amazon.com/servicequotas/latest/userguide/request-quota-increase.html)。
- 对于 SDK 路径：Python 3.10 或更高版本，以及 SageMaker Python SDK v3（`pip install --upgrade sagemaker`）。
- 一个 Muse Spark Open 在 SageMaker JumpStart 中可用的 AWS Region。上线时，Muse Spark Open 可在 US East (N. Virginia) 和 US East (Ohio) 使用。要查看其他 Region 的可用性，请在你的 Region 打开 SageMaker JumpStart。

承载 Muse Spark Open 的是多 GPU 实例，只要 endpoint 在运行你就需要付费，无论它是否在处理请求。用完后请删除 endpoint，做法见本文的清理章节。费率参见 [Amazon SageMaker AI 定价](https://aws.amazon.com/sagemaker/ai/pricing/)。

### 使用 SageMaker Python SDK 部署

SageMaker JumpStart 用模型 ID 标识每个变体：

- BF16：`meta-vlm-muse-spark-open-816b-a42b`。
- NVFP4：`meta-vlm-muse-spark-open-816b-a42b-nvfp4`。

下面的代码使用 SageMaker Python SDK v3 部署 NVFP4 变体。你可以在 SageMaker Studio 的 notebook 里运行它，它会使用你所在 domain 的执行角色。在任何其他已配置 AWS 凭证的 Python 环境中，请用 `role_arn` 参数传入你的 SageMaker AI 执行角色。Muse Spark Open 是 gated 模型，因此你必须设置 `accept_eula=True` 才能部署它。要锁定特定的模型版本，请把 `model_version` 加入 `JumpStartConfig`。

```
from sagemaker.core.jumpstart.configs import JumpStartConfig
from sagemaker.serve import ModelBuilder
from sagemaker.train.configs import Compute

# NVFP4 variant; for BF16, use "meta-vlm-muse-spark-open-816b-a42b" with ml.p6-b300.48xlarge
model_id = "meta-vlm-muse-spark-open-816b-a42b-nvfp4"

jumpstart_config = JumpStartConfig(
    model_id=model_id,
    accept_eula=True,  # Confirms that you accept Meta's license terms
)

model_builder = ModelBuilder.from_jumpstart_config(
    jumpstart_config=jumpstart_config,
    compute=Compute(instance_type="ml.p5e.48xlarge"),
    # role_arn="<your-sagemaker-execution-role-arn>",  # Required outside SageMaker Studio
)

model = model_builder.build(model_name="muse-spark-open-nvfp4")
endpoint = model_builder.deploy(endpoint_name="muse-spark-open-nvfp4")
```

### 运行推理

endpoint 处于服务状态后，用 `invoke` 方法向它发送请求。该 endpoint 接受一个 OpenAI 兼容的 chat 请求体，其中带有 `messages` 列表，并返回一个 chat completion。最终答案在 `message.content` 中，模型的推理过程在 `message.reasoning_content` 中，而 `usage.reasoning_tokens` 报告这段推理用掉了多少 tokens。由于 Muse Spark Open 是推理模型，请在 `max_tokens` 里为它的推理和最终答案留出足够余量。

```
import json

payload = {
    "messages": [
        {
            "role": "user",
            "content": "Write a Python function that validates ISO 8601 dates, and add pytest unit tests for it.",
        }
    ],
    "max_tokens": 4096,
}

response = endpoint.invoke(
    body=json.dumps(payload),
    content_type="application/json",
)

result = json.loads(response.body.read().decode("utf-8"))
message = result["choices"][0]["message"]
print("Reasoning:", message.get("reasoning_content"))
print("Answer:", message["content"])
```

该 endpoint 还支持流式传输。要在 tokens 生成的同时接收它们，请在请求体中加上 `"stream": true`，并改为调用 `endpoint.invoke_with_response_stream` 而不是 `invoke`。

## 清理

要停止继续产生费用，请在不再需要时删除 endpoint。如果你是用 SDK 部署的，请删除模型、endpoint 以及 endpoint 配置：

```
from sagemaker.core.resources import EndpointConfig

endpoint_config = EndpointConfig.get(endpoint_config_name=endpoint.endpoint_name)
model.delete()
endpoint.delete()
endpoint_config.delete()
```

如果你是从 SageMaker Studio 部署的，请在 SageMaker AI 控制台中删除 endpoint：选择 **Inference**，然后选择 **Endpoints**，选中该 endpoint，再选择 **Actions**、**Delete**。
