在本文中，你在 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/) 上把一个文本 prompt 变成一张图像，再把那张图像动画化为一段短视频。你从同一个 AWS vLLM-Omni Deep Learning Container (DLC) 部署两个端点：一个用于 [FLUX.2-klein-4B](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B) 图像生成的实时端点，一个用于 [Wan2.1-VACE-1.3B](https://huggingface.co/Wan-AI/Wan2.1-VACE-1.3B-diffusers) 视频生成的异步端点。工作流发送一个文本 prompt 生成一张静态图，然后把图像和一个运动 prompt 传给视频端点。它从 Amazon Simple Storage Service (Amazon S3) 取回 MP4，并提供一个可选的 Streamlit 界面。

[AWS Deep Learning Containers](https://github.com/aws/deep-learning-containers) 为在 AWS 上的训练和推理打包框架和依赖。[AWS vLLM-Omni DLC](https://aws.github.io/deep-learning-containers/vllm-omni/) 打包被跟踪的 vLLM-Omni 发行版，并为 SageMaker AI 添加路由中间件。[vLLM-Omni](https://github.com/vllm-project/vllm-omni) 把 vLLM 从文本生成扩展到通过 OpenAI 兼容 API 处理或生成文本、音频、图像和视频的模型。

本文延续一个关于专用 AWS DLC 的系列。[第 1 部分](https://aws.amazon.com/blogs/machine-learning/build-real-time-voice-applications-with-vllm-omni-on-sagemaker-ai-part-1/) 用 vLLM-Omni 和 SageMaker AI 双向流式传输做实时语音。第 2 部分涵盖实时与异步推理：图像模型内联返回其结果，而运行更久的视频模型把其输出写入 [Amazon S3](https://aws.amazon.com/s3/)。把图像和视频生成与文本转语音演练分开，也让不同的模型、载荷和响应模式更清晰。

你克隆[代码示例](https://github.com/aws-samples/sagemaker-genai-hosting-examples/tree/main/03-features/vllm-omni-image-video)、为图像生成部署 FLUX.2-klein-4B，并把其输出传给 Wan2.1-VACE-1.3B 做图像条件化的视频生成。示例包含一个命令行工作流和一个 Streamlit 应用。

## 方案概览

该方案把同一个被固定的 AWS vLLM-Omni DLC 镜像部署到两个 SageMaker AI 端点。[部署脚本](https://github.com/aws-samples/sagemaker-genai-hosting-examples/blob/main/03-features/vllm-omni-image-video/deploy.py) 改动 `SM_VLLM_MODEL`，在一个端点加载 FLUX.2-klein，在另一个加载 Wan VACE。保留一个公共容器镜像减少了服务栈的差异，而分开的端点让每个模型使用适合其工作负载的实例类型和推理选项。

- 一个 SageMaker AI 实时端点运行 FLUX.2-klein，并把请求路由到 `/v1/images/generations`。
- 一个 [SageMaker Asynchronous Inference](https://docs.aws.amazon.com/sagemaker/latest/dg/async-inference.html) 端点运行 Wan VACE，并把请求路由到 `/v1/videos/sync`。
- Amazon S3 存储多部分视频请求和生成的 MP4。

图 1 展示请求路径。应用把图像 prompt 发给 FLUX.2-klein 并收到一个 base64 编码的 PNG。它把图像缩放到视频尺寸、转成一个紧凑的 JPEG data URL，并把那个引用插入 Wan VACE 请求。SageMaker Asynchronous Inference 从 Amazon S3 读取多部分请求，并把 MP4 写到返回的输出位置。

图 1：一个 CLI 或 Streamlit 应用调用一个 FLUX.2-klein 实时端点，把生成的 PNG 经 Amazon S3 传给一个 Wan VACE 异步端点，并从 Amazon S3 取回生成的 MP4

图 2 把同一流程显示为一个编号的请求-响应序列。图像调用直接返回给应用。视频调用返回一个异步输出位置，应用在生成结束时从 Amazon S3 取回 MP4。

图 2：一个六步序列展示应用调用图像端点、收到 PNG、向 Amazon S3 上传一个视频请求、调用异步视频端点，并取回生成的 MP4

SageMaker AI 把推理流量发送到 `/invocations`。DLC 读取 `CustomAttributes` 头并把请求转发到选定的 vLLM-Omni 路由。示例在上传到 Amazon S3 之前预先构建多部分视频体，因此发送给 vLLM-Omni Videos API 的确切请求保持显式。它把成功的响应和调用失败分别存放在不同的 Amazon S3 前缀下。

示例对图像使用实时推理，因为应用在能构造下一个请求之前期待一个直接响应。视频生成是一个运行更久的操作，携带一个图像条件化的多部分载荷。[SageMaker Asynchronous Inference](https://docs.aws.amazon.com/sagemaker/latest/dg/async-inference.html) 把请求排入队列并用 Amazon S3 做输入和输出，因此客户端可以轮询结果位置而不必一直吊着一个同步请求。这是一个工作负载选择，而非对每个视频模型的规则。使用与你模型延迟、载荷和客户端交互相匹配的推理选项。

示例使用固定的 `ml.g6.xlarge` 和 `ml.g6e.xlarge` 实例类型。对于实时图像端点，[SageMaker 容量感知实例池](https://docs.aws.amazon.com/sagemaker/latest/dg/realtime-endpoints-heterogeneous.html) 可按优先级列出兼容实例类型。只在你为图像模型的 GPU 显存和性能要求验证了每个候选类型之后再添加一个池。本示例把异步视频端点保持在一个固定实例类型上。

## 前提条件

开始前，你需要：

- 一个 AWS 账户，为 AWS Command Line Interface (AWS CLI) 或 AWS SDK 配置好凭证。
- 一个有样本 Amazon S3 桶访问权限的 SageMaker AI execution 角色。
- 创建和调用 SageMaker AI 端点的权限。
- 在你选定 AWS 区域中对 `ml.g6.xlarge` 和 `ml.g6e.xlarge` 的端点配额。
- Git。
- Python 3.11 或更新版本。

本演练使用美国东部（弗吉尼亚北部）AWS 区域。在部署 GPU 端点前审阅 [SageMaker AI 定价](https://aws.amazon.com/sagemaker/ai/pricing/)。

## 生成一张图像并动画化

- **克隆 hosting examples 仓库。** 克隆仓库并进入 vLLM-Omni 图像与视频示例目录。  `git clone https://github.com/aws-samples/sagemaker-genai-hosting-examples.git cd sagemaker-genai-hosting-examples/03-features/vllm-omni-image-video`
- **安装 Python 依赖。** 创建一个虚拟环境并安装示例 requirements。  `python -m venv .venv source .venv/bin/activate python -m pip install -r requirements.txt`
- **部署图像和视频端点。** 设置你的 SageMaker AI execution 角色并运行[部署脚本](https://github.com/aws-samples/sagemaker-genai-hosting-examples/blob/main/03-features/vllm-omni-image-video/deploy.py)。脚本固定 `omni-sagemaker-cuda-v1.6`、创建一个实时图像端点、创建一个异步视频端点，并把它们的资源名写入 `.vllm_omni_media_state.json`。  `export SAGEMAKER_ROLE_ARN=<your-sagemaker-execution-role-arn> python deploy.py \ --role-arn "$SAGEMAKER_ROLE_ARN" \ --region us-east-1`  环境变量 `SM_VLLM_MODEL` 告诉每个容器加载哪个模型。视频端点开启变分自编码器（VAE）分块（tiling）以降低视频解码期间的峰值内存。如果你的本地 AWS 凭证在端点启动时过期，刷新它们并用 `--resume` 重跑命令。脚本会复用保存的资源。
- **生成一张图像并动画化。** 带一个图像 prompt 和一个运动 prompt 运行[端到端命令行工作流](https://github.com/aws-samples/sagemaker-genai-hosting-examples/blob/main/03-features/vllm-omni-image-video/generate.py)。  `python generate.py \ --image-prompt "Cinematic photograph of a coastal observatory at sunrise" \ --video-prompt "Slow camera push-in toward the coastal observatory; preserve the building and coastline"`  FLUX.2-klein 返回一个 OpenAI 兼容的 JSON 响应，其中把 PNG 作为 base64 数据。[共享请求辅助函数](https://github.com/aws-samples/sagemaker-genai-hosting-examples/blob/main/03-features/vllm-omni-image-video/vllm_omni_media.py) 在构造 Wan VACE 请求之前，把该图像缩放到目标视频尺寸并编码成 JPEG：  `reference_image = prepare_video_reference( image_bytes, width=480, height=320, ) fields = { "prompt": video_prompt, "image_reference": json.dumps( {"image_url": image_data_url(reference_image, "image/jpeg")} ), "num_frames": "17", "num_inference_steps": "30", } body, content_type = encode_multipart_formdata(fields)`  这一转换把 JSON 安全的图像引用保持在 Videos API 多部分解析器的每部分大小限制之下。示例把完整请求上传到 Amazon S3 并用 `route=/v1/videos/sync` 提交给异步端点。SageMaker AI 返回输出和失败位置。脚本在验证并保存 `outputs/` 中的 MP4 之前轮询它们。对于较小的请求，[InvokeEndpointAsync](https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_runtime_InvokeEndpointAsync.html) 也通过 `Body` 接受最大 128,000 字节的内联请求数据。用 `Body` 或 `InputLocation` 之一，不要两者都用。这一工作流用 `InputLocation`，因为它的图像条件化多部分请求大于为 `InvokeEndpointAsync` 所记录文档的 128,000 字节内联 `Body` 设计参数。默认视频设置使用 17 帧和 30 个扩散步。仅对快速端点冒烟测试使用四步，因为在我们审阅时更低设置在保留源构图方面不奏效。在美国东部（弗吉尼亚北部）区域的一次验证运行中，`ml.g6.xlarge` 图像端点在 9 分 30 秒内达到 `InService`。`ml.g6e.xlarge` 视频端点在 8 分 40 秒内达到 `InService`。一次预热后的默认调用在 4.7 秒返回图像。Wan VACE 报告了 8.9 秒的模型延迟，CLI 在 11.8 秒取回 MP4。这些单次运行的数值是复现检查点，而非性能基准。
- **运行 Streamlit 应用。** 在两个端点都达到 `InService` 后启动 [Streamlit 应用](https://github.com/wirjo/sagemaker-genai-hosting-examples/blob/feat/vllm-omni-image-video/03-features/vllm-omni-image-video/app_streamlit.py)。  `streamlit run app.py`  图 3 展示完整的应用流程。更新图像 prompt、图像尺寸或种子，然后选择 **Generate image**。在审阅 FLUX.2-klein 的结果后，输入一个运动 prompt 并调整帧数、每秒帧数或推理步数，然后选择 **Generate video**。演示重放经那次验证运行的产物。已发布的应用调用已部署的端点。      *图 3：在 Streamlit 中配置图像和运动 prompt，生成一张 FLUX.2-klein 图像，然后创建 Wan VACE 视频* 图 4 展示生成的 Wan VACE MP4，不带应用界面。应用显示并下载两个产物，同时使用与命令行工作流相同的请求辅助函数。      *图 4：Wan VACE 用所请求的镜头和环境运动动画化 FLUX.2-klein 的海岸天文台图像*

## 清理

完成时删除端点、端点配置和模型：

```
python cleanup.py
```

[清理脚本](https://github.com/wirjo/sagemaker-genai-hosting-examples/blob/feat/vllm-omni-image-video/03-features/vllm-omni-image-video/cleanup.py) 为审阅在 Amazon S3 输出前缀下保留生成的对象。当你不再需要那些产物时删除该前缀。一个正在运行的 GPU 端点会持续产生费用。

## 结论

你为两个生成式媒体模型部署了一个 AWS vLLM-Omni DLC 发行版，通过实时推理返回 FLUX.2-klein 图像，并通过异步推理取回 Wan VACE 视频。这一工作流展示了共享的服务运行时如何支持不同的模型家族，同时 SageMaker AI 对每个工作负载施加适合的响应模式。

试试[代码示例](https://github.com/wirjo/sagemaker-genai-hosting-examples/tree/feat/vllm-omni-image-video/03-features/vllm-omni-image-video)，然后审阅 [vLLM-Omni DLC 文档](https://aws.github.io/deep-learning-containers/vllm-omni/) 和 [SageMaker Asynchronous Inference 开发者指南](https://docs.aws.amazon.com/sagemaker/latest/dg/async-inference.html)，把这一模式适配到其他受支持的图像和视频模型。
