# 宣布用 SageMaker AI 自定义模型的新方式，无需管理 GPU

真正从 AI 中取得成果的公司并不只是使用现成的基础模型（FM）。它们用强化学习等训练后技术来定制开放权重模型。一个基于你的业务上下文、产品目录或临床词汇训练过的模型，对你的任务会更准确，运行成本也更低。当你构建 agent 时，你的数据、工作流、评估方式和成功标准同样会影响模型的行为。

然而，模型定制并不容易。你必须选择合适的技术、搭建并管理 GPU 基础设施，而且对 agent 来说还要构建用于多轮强化学习的运行环境。我们推出了 Amazon SageMaker AI 无服务器模型定制来应对这些挑战，今天我们通过正式发布（general availability）的 training sessions 进一步扩展它。

借助 [training sessions](https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-training-sessions.html)，你可以掌控训练后的逻辑，而无需管理底层基础设施。你编写并编排训练循环，包括自定义损失函数或奖励信号。SageMaker AI 负责 GPU 分配、分布式执行、故障恢复和检查点存储。

## 定制模型，不必操心基础设施管理

使用 SageMaker AI 无服务器模型定制，你无需选择实例类型、管理集群或编写分布式训练配置。

**我们不想限制你**。你可以使用 SFT、DPO、RLVR、RLAIF 或多轮 RL 等技术。你可以通过 Low-Rank Adaptation（LoRA）或全量微调来决定更新模型的多少部分，并通过持续定制把多种技术串联起来。

**我们不想让你浪费时间**。我们的 SageMaker AI training sessions cookbook 提供了示例和用例，以及模型定制 agent skill。你描述自己的用例，agent 负责数据处理、技术选型、训练、评估和部署。agent 就在你工作的地方工作：SageMaker Studio、Kiro、Claude Code、Codex 或 GitHub Copilot。

## 编写你自己的训练后循环

agent 训练中一个重要转变是转向多轮强化学习。例如，一个负责预订差旅、分诊支持工单或执行多步研究任务的 agent，需要经过若干轮交互，你才能判断它是否达成了正确结果。

然而，训练循环很快就会变得复杂。你可能在一套基础设施上训练模型，在另一套上运行推理来生成响应，对这些响应打分，再把结果送进下一次更新。每个阶段需要不同的算力，而跨不同工具和集群把它们连起来又增加了工作量。

SageMaker AI 已经以托管、无服务器的方式提供多轮 RL。但我们听到客户希望在一个循环里自行定义损失函数、设计奖励信号或 RL 阶段。training sessions 给了你这种灵活性。

> “借助 SageMaker AI Serverless Training Sessions，我们针对 Amazon Neptune 知识图谱微调了 gpt-oss-20b，让它能够进行 agentic 的多轮工具调用，而平台替我们处理了基础设施。配置一次就成功了，无需手动调参，也没有和内存不足较劲。检查点与恢复尤其出彩：从精确的步数恢复完全可靠。它给了我们开发人员想要的灵活性，同时把运维负担从他们肩上卸了下来。”
>         — Nitin Wagh，Karini AI 首席执行官

## 工作原理

你的代码在你的环境中运行训练循环和奖励函数，并把 agent 连接到它的工具或模拟器。training session 承担 GPU 密集型的工作：sampler 生成响应，trainer 计算梯度并更新模型权重。具体顺序取决于你编写的算法。

例如，我们来看 Group Relative Policy Optimization（GRPO）的实现。GRPO 是一种强化学习方法，它针对同一个 prompt 生成多个响应、对它们打分，并利用它们的相对表现来更新模型。循环一次完整的执行过程如下：

- **采样响应 –** 你的循环要求 sampler 用当前模型为每个 prompt 生成多个响应。
- **为响应打分 –** 你的奖励函数在你的环境中使用验证器、奖励模型或测试工具对每个响应打分。
- **更新模型 –** 你的循环把分数送回 trainer。`forward_backward()` 用这些分数计算梯度，`optim_step()` 把更新应用到模型权重。
- **刷新并重复 –** 你的循环要求 session 用更新后的权重刷新 sampler，然后开始下一批。你的代码重复这些步骤，直到训练完成。

你按 SageMaker AI 处理的 token 付费。当你的奖励函数在你的环境中为一批数据打分时，计量会暂停，而且无需预留任何容量。

## 掌控你的数据与模型

每个 session 都使用你创建的 AWS Identity and Access Management（IAM）执行角色，你还可以添加自己的 AWS Key Management Service（AWS KMS）密钥和虚拟私有云（VPC）配置。你的数据留在你所选 AWS 区域中你自己的 Amazon Simple Storage Service（Amazon S3）存储桶里，你的检查点也存放在那里。

我们不会用你的数据或你定制后的权重去训练另一个模型。部署之前，你可以评估模型的准确性、偏差和安全性。部署之后，你可以应用护栏（guardrails），并用 Amazon CloudWatch 监控它。

你可以继续使用团队现有的治理流程。

## 立即开始

在 SageMaker AI 无服务器模型定制的 training sessions 上编写你自己的训练循环，现已推出，支持 `gpt-oss-20b`、`gemma-4-31B-it`、`Qwen3.6-27B` 和 `Qwen3.8-27B`。

两种上手方式：

- **在你的 IDE 中：** 安装 SageMaker Python SDK（在 Python 3.10 至 3.12 的 Linux 或 macOS 上），克隆 cookbook，然后开始开发。
- **在 SageMaker Studio 中：** 在 20 秒内启动一个即用型 AI 开发环境。登录、打开 notebook、连接你的编码 agent（Kiro、Claude Code、Codex 或 Copilot）、下载 agent skill 和 cookbook，就可以开始了。
