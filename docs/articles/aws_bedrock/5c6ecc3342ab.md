# 使用 Jamf 的 AI Governance 与 Amazon Bedrock 在 Mac 上管理 AI 应用

随着组织在全体员工中扩大 AI 的应用，IT 管理员需要一种可扩展的方式来管理 AI 应用在员工设备上的配置与使用。这些应用包括 Claude Code、Claude Desktop 与 OpenAI Codex。与此同时，用户可以打开已批准的应用直接开始工作，无需手动配置。

受到 78,000 多家组织信任、用于大规模管理与保护 Apple 设备的 [Jamf](https://www.jamf.com/)，如今把这一管理模式延伸到 AI 治理。借助对 Amazon Bedrock 的支持，[Jamf 的 AI Governance](https://www.jamf.com/solutions/ai-governance/) 帮助组织在受管理的 Mac 上集中配置与管理这些应用。

在本文中，我们展示如何把 Jamf 的 AI Governance 与 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 结合使用，在整批 Mac 设备上为 AI 应用配置、部署并校验受管设置。

## Jamf 的 AI Governance 如何与 Amazon Bedrock 协同工作

Claude Code、Claude Desktop 与 OpenAI Codex 等 AI 应用在用户设备的本地运行。每个应用都通过本地配置文件来设置推理提供商的身份验证、Model Context Protocol（MCP）server 连接以及可观测性配置等。要在企业规模上治理这些应用，你需要同时控制推理在哪里运行，以及每个应用在设备上如何配置。

Amazon Bedrock 通过你的 AWS 账户为这些应用提供模型推理，推理在你所选的 AWS 区域中运行。借助 Jamf 的 AI Governance，你可以定义把每个应用连接到 Amazon Bedrock 的设置，并通过[声明式设备管理](https://www.jamf.com/blog/getting-to-know-declarative-management/)（DDM）把它们下发到你的全部设备。Amazon Bedrock 与 Jamf 的 AI Governance 共同提供了一种可扩展的方式，在治理 AI 应用的同时把推理保持在你 AWS 的安全边界之内。

你可以在 Jamf 的 AI Governance 中定义应用配置，并通过 Jamf Blueprints 部署它。Jamf 通过 DDM 把配置下发到各个设备的操作系统，帮助受管设置抵御本地篡改。随后用户可以打开应用而无需编辑本地配置文件，你也可以在 Jamf AI Governance 中查看策略范围与部署状态。

## Jamf 的 AI Governance 与 Amazon Bedrock 的实践

本节我们以 Claude Code 配合 Amazon Bedrock 为例，完整走一遍部署过程。工作流分为三部分：创建受管策略、将其部署到受管理的 Mac，以及校验策略已生效。同样的模式也适用于其他受支持的应用，包括 Claude Desktop 与 OpenAI Codex。

在开始之前，请先完成 [Jamf 的 AI Governance 前提条件](https://learn.jamf.com/r/en-US/ai-governance-configuration-guide/Requiremements)。

### 为 Amazon Bedrock 上的 Claude Code 创建策略

你可以在 Jamf 账户的 **AI Governance > AI Policies** 下创建策略。在[策略构建器](https://learn.jamf.com/r/en-US/ai-governance-configuration-guide/AI_Policies)中，你配置 Amazon Bedrock 的提供商设置，包括身份验证方式、AWS 区域与模型访问权限。

该策略定义了整个组织中用户使用 Claude Code 时如何借助 Amazon Bedrock。例如，你可以在 Claude Code 中启用 Amazon Bedrock 的 [prompt caching](https://aws.amazon.com/bedrock/prompt-caching/)。在迭代式编码工作流中，对受支持的模型，prompt caching 可以把成本降低最多 90%、把延迟降低最多 85%。你还可以配置 Claude Code 的行为，包括努力程度（effort level）、MCP server 访问、本地文件夹权限、沙箱设置与遥测。

![Jamf 策略构建器为 Amazon Bedrock 配置 Claude Code 的提供商设置](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-21256-2.png)

*图 2：在 Amazon Bedrock 上设置 Claude Code*

### 使用 Jamf Blueprints 部署策略

然后你可以通过 [Jamf Blueprints](https://learn.jamf.com/r/en-US/ai-governance-configuration-guide/Deploying_a_Policy_with_Blueprints) 把该策略部署到目标 Mac 组。Jamf 通过 DDM 以受管配置的形式下发配置。Jamf 会在用户打开 Claude Code 之前把配置放置在他们的设备上。用户无需手动配置即可开始使用 Claude Code。

![在已应用 Jamf 配置的受管理 Mac 上打开 Claude Code](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-21256-3.png)

*图 3：在已应用受管配置的情况下打开 Claude Code*

### 校验并监控部署

部署完成后，你可以使用 Jamf 的 AI Governance 查看策略范围与部署状态。你还可以使用 AI Visibility 查看整个设备群中的 AI 应用与活动，并生成用于治理留证的报表。

![Jamf AI Governance 中的 AI Visibility 控制面板，展示 AI 应用活动与治理报表](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/07/07/ML-21256-4.png)

*图 4：Jamf 的 AI Governance 中的 AI Visibility 与治理报表*

## 结语

借助 Jamf 的 AI Governance 与 Amazon Bedrock，你可以为用户提供对 AI 应用的受管访问，同时把推理留在你的 AWS 环境中。Jamf 通过 DDM 下发应用配置，因此 IT 团队可以在整批 Mac 设备上部署提供商设置与应用管控，然后校验策略覆盖面，而无需依赖手动配置。
