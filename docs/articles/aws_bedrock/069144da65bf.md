# Oldcastle 借助 Amazon Bedrock 加速文档处理

*本文与 Oldcastle APG 的 Avdhesh Paliwal 共同撰写。*

[Oldcastle APG](https://www.oldcastleapg.com/) 是建筑产品行业全球最大的制造商网络之一，当时正苦于处理交付证明（proof of delivery，POD）文档——即 ship tickets——的流程效率低下且耗费人力。该公司在 200 多个站点每月处理 10 万–30 万张 ship tickets。他们现有的光学字符识别（optical character recognition，OCR）系统并不可靠，需要持续维护和人工干预，只能准确读取 30–40% 的文档，导致大量时间与资源消耗。

本文探讨 Oldcastle 如何与 AWS 合作，利用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和 [Amazon Textract](https://aws.amazon.com/textract/) 改造其文档处理工作流。我们将讨论 Oldcastle 如何克服此前 OCR 方案的局限，实现每月数十万份 POD 文档的自动化处理，在大幅提高准确性的同时减少人工投入。该解决方案展示了一种实用、可扩展的方法，可根据你的具体需求加以调整，用于应对文档处理或运用生成式 AI 优化业务流程等类似挑战。

## 文档处理的挑战

Oldcastle 的首要挑战是找到一款能够完成以下工作的解决方案：

- 在极少人工干预下准确处理大量 ship tickets（POD）
- 可扩展至每月处理 20 万–30 万份文档
- 处理页面旋转、格式多变等不一致的输入
- 将数据提取准确率从当前的 30–40% 提升到更高的水平
- 增加新能力，如 POD 上的签名验证
- 提供对未结 POD 和交付情况的实时可见性

此外，Oldcastle 还需要一个处理供应商发票并将其与采购订单匹配的解决方案，由于文档格式各异，这同样带来了类似的挑战。现有流程要求 200 多个站点的调度员每天花 4–5 小时手动处理 ship tickets。这消耗了宝贵的人力资源，导致处理延迟，并可能在数据录入时出现错误。IT 团队也不堪重负，需要不断维护和开发，以维持这套不可靠的 OCR 系统运转。

## 解决方案概览

AWS 解决方案架构师与 Oldcastle 的工程师紧密合作，构建了一套应对这些挑战的解决方案。端到端工作流使用 [Amazon Simple Email Service](https://aws.amazon.com/ses/)（Amazon SES）接收 ship tickets，这些单据由现场司机直接发送。系统采用以 [Amazon S3 Event Notifications](https://docs.aws.amazon.com/AmazonS3/latest/userguide/EventNotifications.html) 为核心的基于事件的架构，大规模处理邮件。工作流将 ship ticket 文档发送给自动扩缩的计算任务编排器。文档按以下步骤处理：

- 系统使用 Start Document Analysis API 并启用 Layout 和 Signature 功能，将 PDF 文件发送给 Amazon Textract。
- Amazon Textract 的结果由一个 [AWS Lambda](https://aws.amazon.com/lambda/) 微服务处理。该微服务解决页面文本的旋转问题，并生成一组以 markdown 表示文本的页面。
- markdown 被传递给 Amazon Bedrock，由后者高效提取 markdown 文本中的关键值。
- 编排器将结果保存到他们的 [Amazon Relational Database Service (Amazon RDS) for PostgreSQL](https://aws.amazon.com/rds/postgresql/) 数据库中。

在这一架构中，Amazon Textract 是大规模处理大型 PDF 文件的有效方案。Amazon Textract 的输出包含必要的几何信息，用于在生成 markdown 之前计算旋转角度并修正版面问题。高质量的 markdown 版面对于 Amazon Bedrock 从内容中识别正确的键值对至关重要。我们通过只提取所需数据来限制输出 token，并使用 Amazon Bedrock 批处理以获得最低的 token 成本，从而进一步优化了成本。选用 Amazon Bedrock，是因为它具备成本效益，且擅长处理格式固定、需提取字段相同的 ship tickets。

## 成果

在 AWS 上采用该架构的实施为 Oldcastle 带来诸多收益：

- **业务流程改进** – 该解决方案实现了以下成果：  减轻了各站点手动处理 ship tickets 的需求 以极少人工干预实现文档处理自动化 提升了数据提取的准确性与可靠性 增强了签名验证和拒收不完整文档的能力 提供了对未结 POD 和交付情况的实时可见性
- **生产力提升 **– Oldcastle 获得了以下收益：  人工录入数据和文档处理所花费的工时显著减少 员工有更多时间投入到更高价值的活动中 IT 团队受益于开发与维护工作量的降低
- **可扩展性与性能 **– 团队体验到以下性能提升：  他们从每月处理数千份文档无缝扩展到 20 万–30 万份 团队未发现数据量增加带来任何性能问题
- **用户满意度 **– 该解决方案在多个方面改善了用户感受：  由于新系统准确可靠，用户对其高度信任 业务用户对其易用性和有效性给予了正面反馈
- **成本效益 **– 采用这种方法，Oldcastle 处理文档的成本可低至每页不到 $0.04

## 结论

在 AWS 实施取得成功后，Oldcastle 正在探索向其他用例扩展的可能性，例如 AP 发票处理、W9 表单验证和自动化文档审批工作流。这一向 AI 驱动文档处理转型的战略举措，正使 Oldcastle 的运营具备更高的效率与可扩展性。
