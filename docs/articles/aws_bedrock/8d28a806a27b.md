# 将令牌化与 Amazon Bedrock Guardrails 集成，实现安全的数据处理

*本文由 Thales 网络安全产品部门首席解决方案架构师 Mark Warner 共同撰写。*

随着生成式 AI 应用进入生产环境，它们集成到越来越多处理敏感客户数据的业务系统之中。这种集成在保护个人可识别信息（PII）方面带来了新的挑战，同时还要保留下游应用在确有正当需要时恢复原始数据的能力。设想一家在多个部门推行生成式 AI 的金融服务公司。客服团队需要一个能访问客户档案并提供个性化响应的 AI 助手，响应中会包含联系信息，例如：“我们会把您的新卡寄到您位于 123 Main Street 的地址。”与此同时，欺诈分析团队需要同样的客户数据，但必须在不暴露真实 PII 的前提下分析模式，只能使用敏感信息的受保护表示形式。

[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 有助于检测输入提示词或模型响应中标准格式的敏感信息，例如 PII。[敏感信息过滤器](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-sensitive-filters.html)让组织可以控制敏感数据的处理方式，可以选择阻止包含 PII 的请求，或用 `{NAME}`、`{EMAIL}` 之类的通用占位符掩码敏感信息。这项能力帮助组织在遵守数据保护法规的同时，仍然利用大语言模型（LLM）的强大能力。

尽管掩码能有效保护敏感信息，但它带来一个新挑战：数据可逆性的丧失。当 guardrail 用通用掩码替换敏感数据时，原始信息对下游应用就变得不可访问，而这些应用可能出于合法的业务流程需要它。这种局限会影响既需要安全性又需要功能性数据的工作流。

[Tokenization](https://aws.amazon.com/solutions/guidance/tokenization-to-improve-data-security-and-reduce-audit-scope-on-aws/)（令牌化）为这一挑战提供了互补的方法。与掩码不同，令牌化用格式保持的 token 替换敏感数据，这些 token 与原始信息在数学上无关，但保持其结构和可用性。当授权系统需要时，这些 token 可以被安全地还原为原始值，从而在整个组织环境中开辟安全数据流动的路径。

本文介绍如何将 Amazon Bedrock Guardrails 与第三方令牌化服务集成，在保护敏感数据的同时保持数据可逆性。通过结合这些技术，组织可以实施更强的隐私控制，同时保留其生成式 AI 应用及相关系统的功能。本文描述的方案演示了如何将 Amazon Bedrock Guardrails 与 [Thales CipherTrust Data Security Platform](https://aws.amazon.com/blogs/apn/how-thales-enables-pci-dss-compliance-with-a-tokenization-solution-on-aws/) 的令牌化服务结合起来，构建一种在不牺牲按需安全处理数据能力的前提下保护敏感数据的架构。这种方法对需要平衡创新与合规要求的高度受监管行业组织尤其有价值。

## Amazon Bedrock Guardrails API

本节介绍 Amazon Bedrock Guardrails 与第三方令牌化服务集成的关键组件和工作流。

Amazon Bedrock Guardrails 提供两种不同的内容安全控制实现方式：

- 通过 [InvokeModel](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_InvokeModel.html) 和 [Converse](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.html) 等 API 与模型调用直接集成，其中 guardrail 作为模型推理过程的一部分自动评估输入和输出。
- 通过 [ApplyGuardrail](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_ApplyGuardrail.html) API 进行独立评估，它把 guardrail 评估与模型调用解耦，允许依据已定义的策略评估文本。

本文使用 ApplyGuardrail API 进行令牌化集成，因为它将内容评估与模型调用分离，允许在这两个步骤之间插入令牌化处理。这种分离在工作流中创造出必要的空间，以便在模型调用之前、或在模型响应交给流程下游的目标应用之后，用格式保持的 token 替换 guardrail 掩码。

该方案通过在 guardrail 评估与模型调用之间插入令牌化处理，扩展了典型的 ApplyGuardrail API 实现，如下所示：

- 应用调用 ApplyGuardrail API 评估用户输入中是否含有敏感信息。
- 如果未检测到敏感信息（[action = "NONE"](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_GuardrailPiiEntityFilter.html#bedrock-Type-runtime_GuardrailPiiEntityFilter-action)），应用则通过 InvokeModel API 继续调用模型。
- 如果检测到敏感信息（[action = "ANONYMIZED"](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_GuardrailPiiEntityFilter.html#bedrock-Type-runtime_GuardrailPiiEntityFilter-action)）：应用捕获检测到的 PII 及其位置。它调用令牌化服务把这些实体转换为格式保持的 token。它用这些 token 替换通用 guardrail 掩码。应用随后用令牌化后的内容调用基础模型。
- 对于模型响应：应用对模型输出施加 guardrail，检查是否含有敏感信息。它在把响应传递给下游系统之前，对检测到的 PII 进行令牌化。

## 方案概览

为了说明这一工作流在实践中如何创造价值，设想一个财务顾问应用，它帮助客户理解自己的消费模式并获得个性化的财务建议。在这个示例中，三个不同的应用组件协同工作，提供安全、AI 驱动的财务洞察：

- **客户网关服务** – 这个受信任的前端编排器接收客户查询，而这些查询往往包含敏感信息。例如，客户可能会问：“你好，我是 j.smith@example.com。基于我最近在 acme.com 上的五笔交易，以及我当前 2,342.18 美元的余额，我应该考虑他们的新信用卡优惠吗？”
- **财务分析引擎** – 这个 AI 驱动的组件分析财务模式并生成建议，但不需要访问真实的客户 PII。它使用匿名化或令牌化后的信息工作。
- **响应处理服务** – 这个受信任的服务负责最终的客户沟通，包括在向客户呈现结果之前对敏感信息进行去令牌化。

下图展示了在这个财务顾问应用中，将 Amazon Bedrock Guardrails 与令牌化服务集成的工作流。[AWS Step Functions](https://aws.amazon.com/step-functions/) 使用 [AWS Lambda](https://aws.amazon.com/lambda) 函数，跨越三个关键组件（客户网关服务、财务分析引擎和响应处理服务）编排 PII 检测、令牌化、AI 模型调用和去令牌化的顺序流程。

![AWS Step Functions 按顺序编排安全检查、数据令牌化和 Bedrock 模型调用](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/09/07/ML-19297-arch-diag.png)

该工作流运行如下：

- 客户网关服务（在本示例中通过 [Amazon API Gateway](https://aws.amazon.com/api-gateway)）接收包含敏感信息的用户输入。
- 它调用 ApplyGuardrail API 识别应当被匿名化或阻止的 PII 或其他敏感信息。
- 对于检测到的敏感元素（例如用户名或商户名），它调用令牌化服务生成格式保持的 token。
- 带有令牌化值的输入被传递给财务分析引擎进行处理。（例如：“你好，我是 [[TOKEN_123]]。基于我最近在 [[TOKEN_456]] 上的五笔交易以及我当前 2,342.18 美元的余额，我应该考虑他们的新信用卡优惠吗？”）
- 财务分析引擎在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上调用 LLM，使用令牌化数据生成财务建议。
- 模型响应（可能包含令牌化值）被发送到响应处理服务。
- 该服务调用令牌化服务对 token 进行去令牌化，恢复原始敏感值。
- 最终去令牌化后的响应被交付给客户。

这种架构在整个处理流程中保持数据机密性，同时保留信息的效用。财务分析引擎处理结构有效但受密码学保护的数据，使其能够生成有意义的建议而不暴露敏感的客户信息。与此同时，工作流入口和出口处的受信任组件在必要时可以访问真实数据，从而构成安全的端到端方案。

在接下来的章节中，我们详细讲解 Amazon Bedrock Guardrails 与令牌化服务集成的实现过程。

## 先决条件

要实现本文描述的方案，你的环境中必须配置以下组件：

- 一个已在目标 AWS Region 中启用 Amazon Bedrock 的 AWS 账户。
- 按最小权限原则配置的适当 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）权限，并启用特定操作：`bedrock:CreateGuardrail`、`bedrock:ApplyGuardrail` 和 `bedrock-runtime:InvokeModel`。
- 对于 [AWS Organizations](https://aws.amazon.com/organizations)，验证 [service control policy](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps.html) 是否允许访问 Amazon Bedrock。
- 安装了 boto3 库的 Python 3.7+ 环境。关于安装 boto3 库的信息，请参阅 [AWS SDK for Python (Boto3)](https://aws.amazon.com/sdk-for-python/)。
- 使用 [AWS Command Line Interface](https://aws.amazon.com/cli)（AWS CLI）为程序化访问配置的 AWS 凭证。更多细节请参阅[配置 AWS CLI 设置](https://docs.aws.amazon.com/cli/v1/userguide/cli-chap-configure.html)。
- 此实现需要一个可通过 REST API 端点访问的已部署令牌化服务。尽管本演练演示了与 Thales CipherTrust 的集成，但该模式同样适用于提供 protect 和 unprotect API 操作的令牌化提供商。请确保你的应用环境与 AWS API 及令牌化服务端点之间存在网络连通性，并具备访问所选令牌化服务的有效认证凭证。关于专门设置 Thales CipherTrust 的信息，请参阅[Thales 如何借助 AWS 上的令牌化方案实现 PCI DSS 合规](https://aws.amazon.com/blogs/apn/how-thales-enables-pci-dss-compliance-with-a-tokenization-solution-on-aws/)。

## 配置 Amazon Bedrock Guardrails

通过 Amazon Bedrock 控制台或使用 AWS SDK 以编程方式配置 Amazon Bedrock Guardrails，以进行 PII 检测和掩码。[敏感信息过滤器策略](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-sensitive-filters.html#guardrails-sensitive-information-policy-configure)可以对模型请求或响应中的信息进行匿名化或隐去：

```
import boto3
def create_bedrock_guardrail():
    """
    Create a guardrail in Amazon Bedrock for financial applications with PII protection.
    """
    bedrock = boto3.client('bedrock')
    
    response = bedrock.create_guardrail(
        name="FinancialServiceGuardrail",
        description="Guardrail for financial applications with PII protection",
        sensitiveInformationPolicyConfig={
            'piiEntitiesConfig': [
                {
                    'type': 'URL',
                    'action': 'ANONYMIZE',
                    'inputAction': 'ANONYMIZE',
                    'outputAction': 'ANONYMIZE',
                    'inputEnabled': True,
                    'outputEnabled': True
                },
                {
                    'type': 'EMAIL',
                    'action': 'ANONYMIZE',
                    'inputAction': 'ANONYMIZE',
                    'outputAction': 'ANONYMIZE',
                    'inputEnabled': True,
                    'outputEnabled': True
                },
                {
                    'type': 'NAME',
                    'action': 'ANONYMIZE',
                    'inputAction': 'ANONYMIZE',
                    'outputAction': 'ANONYMIZE',
                    'inputEnabled': True,
                    'outputEnabled': True
                }
            ]
        },
        blockedInputMessaging="I can't provide information with PII data.",
        blockedOutputsMessaging="I can't generate content with PII data."
    )
    
    return response
```

## 集成令牌化工作流

本节实现令牌化工作流：首先用 ApplyGuardrail API 检测 PII 实体，然后用来自你的令牌化服务的格式保持 token 替换通用掩码。

### 应用 guardrail 检测 PII 实体

使用 ApplyGuardrail API 校验用户的输入文本并检测 PII 实体：

```
import boto3
from botocore.exceptions import ClientError
def invoke_guardrail(user_query):
    """
    Apply Amazon Bedrock Guardrails to validate input text and detect PII entities.
    
    Args:
        user_query (str): The user's input text to be checked.
    
    Returns:
        dict: The response from the ApplyGuardrail API.
    
    Raises:
        ClientError: If there's an error applying the guardrail.
    """
    try:
        bedrock_runtime = boto3.client('bedrock-runtime')
        
        response = bedrock_runtime.apply_guardrail(
            guardrailIdentifier='your-guardrail-id', # Replace with your actual guardrail ID
            guardrailVersion='your-guardrail-version', # Replace with your actual version
            source="INPUT",
            content=[{"text": {"text": user_query}}]
        )
        
        return response
    except ClientError as e:
        print(f"Error applying guardrail: {e}")
        raise
```

### 调用令牌化服务

[ApplyGuardrail API 的响应](https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/bedrock-runtime/client/apply_guardrail.html)包含与敏感信息策略匹配的 PII 实体列表。解析这些实体并调用令牌化服务生成 token。

下面的示例代码使用 Thales CipherTrust 令牌化服务：

```
import json
import requests
from botocore.exceptions import ClientError
def thales_ciphertrust_tokenizer(guardrail_response):
  """
  Process PII entities detected by the guardrail and tokenize them using Thales CipherTrust
    
  Args:
      guardrail_response (dict): The response from the ApplyGuardrail API
    
  Returns:
      list: List of dictionaries containing original values, types, and tokenized responses
    
  Raises:
      ClientError: If there's an error invoking Thales CipherTrust.
  """
  try:
    protected_results = []
      
    for assessment in guardrail_response.get("assessments", []):
      pii_entities = assessment.get("sensitiveInformationPolicy", {}).get("piiEntities", [])
            
      for entity in pii_entities:
          sensitive_value = entity.get("match")
          entity_type = entity.get("type")
                
          if sensitive_value:
              # Prepare payload for Thales CipherTrust tokenization service
              crdp_payload = {
                  "protection_policy_name": "plain-alpha-internal",
                  "DATA_KEY": sensitive_value,
              }
                    
              url_str = "http://your-ciphertrust-cname:8090/v1/protect"  # Replace with your actual CipherTrust URL
              headers = {"Content-Type": "application/json"}
                    
              # Invoke the Thales CipherTrust tokenization service
              response = requests.post(url_str, headers=headers, data=json.dumps(crdp_payload))
              response.raise_for_status()
              response_json = response.json()
                    
              protected_results.append({
                   "original_value": sensitive_value,
                   "type": entity_type,
                   "protection_response": response_json
              })
        
    return protected_results
  except requests.RequestException as e:
    print(f"Error invoking Thales CipherTrust: {e}")
    raise ClientError(f"Error invoking Thales CipherTrust: {e}", "TokenizationError")
```

### 用 token 替换 guardrail 掩码

接下来，用 Thales CipherTrust 令牌化服务生成的 token 替换通用 guardrail 掩码。这使下游应用能够处理结构有效的数据，同时保持安全性和可逆性。

```
def process_guardrail_output(protected_results, guardrail_response):
    """
    Process guardrail output by replacing placeholders with protected values.
    
    Args:
        protected_results (list): List of protected data tokenized by Thales CipherTrust.
        guardrail_response (dict): Guardrail response dictionary.
        
    Returns:
        list: List of modified output items with placeholders replaced by tokens.
    
    Raises:
        ValueError: If input parameters are invalid.
        Exception: For any unexpected errors during processing.
    """
    try:
        # Validate input types
        if not isinstance(protected_results, list) or not isinstance(guardrail_response, dict):
            raise ValueError("Invalid input parameters")
            
        # Extract protection map
        protection_map = {res['type'].upper(): res['protection_response']['protected_data'] 
                          for res in protected_results}
        # Process outputs 
        modified_outputs = []
        for output_item in guardrail_response.get('outputs', []):
            if 'text' in output_item:
                modified_text = output_item['text']
                
                # Replace all placeholders in one pass
                for pii_type, protected_value in protection_map.items():
                    modified_text = modified_text.replace(f"{{{pii_type}}}", protected_value)
                
                modified_outputs.append({"text": modified_text})
        return modified_outputs
    except (ValueError, KeyError) as e:
        print(f"Error processing guardrail output: {e}")
        raise
    except Exception as e:
        print(f"Unexpected error while processing guardrail output: {e}")
        raise
```

此过程的结果是把包含符合所用 Amazon Bedrock Guardrails 敏感信息策略信息的用户输入，转换为唯一且可逆的令牌化版本。

以下示例输入包含 PII 元素：

```
"Hi, this is john.smith@example.com. Based on my last five transactions on acme.com, and my current balance of $2,342.18, should I consider their new credit card offer?"
```


### 下游应用处理

清洗后的输入已可供生成式 AI 应用使用，包括在 Amazon Bedrock 上的模型调用。针对令牌化输入，由财务分析引擎调用的 LLM 会生成相关分析，并保持安全的 token 格式：

```
"Based on your recent transactions at 1001000WcFzawG.Jc9Tfc and your current account status, I can confirm that the new credit card offer would provide approximately $33 in monthly rewards based on your spending patterns. With annual benefits of around $394 against the $55 annual fee, this card would be beneficial for your profile, 1001000GC5gDh1.D8eK71@EjaWV.lhC."
```

当授权系统需要恢复原始值时，token 会被去令牌化。使用 Thales CipherTrust 时，这通过 [Detokenize API](https://thalesdocs.com/ctp/con/crdp/latest/admin/crdp-examples/crdp-reveal-example/index.html) 完成，它需要与先前令牌化操作相同的参数。这完成了安全的数据流，同时在需要时保留恢复原始信息的能力。

## 清理资源

按照本文描述的方法操作时，你会在账户中创建新的 AWS 资源。为避免产生额外费用，请在不再需要时删除这些资源。

要清理资源，请完成以下步骤：

- 删除你创建的 guardrail。相关说明请参阅[删除你的 guardrail](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-delete.html)。
- 如果你按本文所述使用 Lambda、API Gateway 或 Step Functions 实现了令牌化工作流，请删除你创建的资源。
- 本文假定你的账户中已有可用的令牌化方案。如果你部署了第三方令牌化方案（例如 Thales CipherTrust）来测试此实现，请参阅该方案的文档，了解正确停用这些资源并停止产生费用的说明。

## 结论

本文演示了如何将 Amazon Bedrock Guardrails 与令牌化结合，以增强生成式 AI 工作流中敏感信息的处理。通过集成这些技术，组织可以在处理过程中保护 PII，同时为授权的下游应用保留数据效用和可逆性。
