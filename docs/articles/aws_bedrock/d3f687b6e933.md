# Amazon Bedrock 代币经济学数据湖

如果您需要为您的 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 工作负载提供可观测性数据湖，那么您并不孤单。当您每天在多个帐户中运行数千次模型调用时，发送请求后您可能会想，发生了什么？您可以看到总账单，但无法查看每个通话中发生的情况。

您可能会开始问问题：发送了什么提示，模型返回什么，使用了多少令牌，哪个模型处理了它，以及响应是否良好！如果您是一名平台或机器学习 (ML) 工程师，需要跨团队管理一组 Amazon Bedrock 工作负载，那么这确实是一个问题。您无法调试尖峰，无法发现浪费的提示，也无法区分一个团队和另一个团队的使用情况。

我们构建了一些可以提供帮助的东西：用于您的 Amazon Bedrock 调用的集中式可观测性数据湖。在这篇文章中，我将介绍您拥有的本地数据以及我们如何设计该湖。我还展示了如何使用它来查看提示并得出每次调用的成本。 [AWS CloudFormation](https://docs.aws.amazon.com/cloudformation/) 模板、[AWS Lambda](https://aws.amazon.com/lambda/) 代码和 SQL 查询均位于 [AWS 示例 Bedrock 调用数据湖 GitHub 存储库](https://github.com/aws-samples/sample-bedrock-token-cost-allocation)。这篇文章将介绍架构和部署步骤。该存储库包含部署它所需的一切。

## 您今天的 Amazon Bedrock 可见度如何？

Amazon Bedrock 提供[模型调用日志记录](https://docs.aws.amazon.com/bedrock/latest/userguide/model-inspiration-logging.html)，而且它确实非常强大。您可以在[您使用 Bedrock 的每个 AWS 账户中的设置](https://us-east-1.console.aws.amazon.com/bedrock/home?region=us-east-1#/settings) 中打开调用日志。它向 [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/pm/serv-s3/) 或 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 提供请求和响应的完整记录。

数据存在，但被锁定在个人账户内。您真正想要的是整个组织中每次调用的单一、快速、可查询的视图。这就是数据湖为您提供的。

## 什么是 Amazon Bedrock 可观测性数据湖？

集中式 [Amazon Bedrock 调用日志](https://docs.aws.amazon.com/bedrock/latest/userguide/model-inspiration-logging.html) 数据湖将原始模型调用日志从链接账户提取到 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/)。订阅日志过滤器然后将这些记录转发到您的中央帐户。中央账户通过 [Amazon Data Firehose](https://aws.amazon.com/firehose/) 处理数据，并通过 [Amazon Athena](https://aws.amazon.com/athena/) 将它们公开为一张干净的表，您可以在整个组织中查询。

所有内容均使用两个 [AWS CloudFormation](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/Welcome.html) 模板部署为基础设施即代码，因此您可以在组织中的每个账户中重复部署。这可以在 [AWS 示例 Bedrock 调用数据湖 GitHub 存储库](https://github.com/aws-samples/sample-bedrock-token-cost-allocation) 中找到。

## 每个 Amazon Bedrock 调用日志捕获什么？

运行此解决方案后，您将在部署到的链接帐户中获得一组组合数据，以便您可以使用 Athena 进行查询。将日志平铺到处理后的表中后，每次调用会得到什么：

- **用户或应用程序发送的提示**。
- **返回的模型响应**。
- **输入和输出令牌计数**，因此您可以测量每次调用的真实权重。
- **使用的模型**，因此您可以了解跨团队的模型利用率。
- **停止原因**（例如，`max_tokens`），它告诉您响应何时被切断。
- **帐户和时间戳**，因此您可以对所有内容进行属性和时间切片。

## Amazon Bedrock 数据湖是如何设计的？

数据湖将每次调用经历五个阶段，从 Amazon Bedrock 写入日志到您可以在 Athena 中查询日志。

### 1. Amazon Bedrock 写入调用日志

每次应用程序调用 Amazon Bedrock 模型时，Amazon Bedrock 都可以记录发生的情况：哪个模型、哪个账户、哪个 IAM 身份进行了调用、使用了多少个输入和输出令牌以及提示和响应文本。您可以通过单个 API 调用为每个账户启用一次此功能，将 Amazon Bedrock 指向 CloudWatch 日志组并为其赋予可以在其中写入的角色。

### 2. CloudWatch 将日志转发到中央账户

每个源账户都会在其 Amazon Bedrock 日志组上获得一个订阅过滤器。将其视为永久转发规则，即“将每个新事件发送到此地址”。该地址是您中央账户中的 Amazon CloudWatch Logs 目标。源帐户没有获得中央管道的权限。他们将事件传递到目的地，中央帐户自己的角色从那里接收事件。

### 3. 一个小的 Lambda 整理每条记录

CloudWatch 不会移交干净的 JSON。它将事件捆绑成批次，并对它们进行压缩和编码，因此到达的内容看起来像是乱码，直到您打开它。一个小型 Lambda 函数可以完成三项工作：

- 将批次解包回单独的日志记录。
- 消除噪音。 CloudWatch 偶尔会发送内务消息和简单的英语通知，例如“Amazon Bedrock 日志的权限已正确设置”。这些不是调用数据，让它们通过下一阶段的中断。
- 平整一个尴尬的领域。调用者的身份到达下一层嵌套。 Lambda 将其提升到顶部，以便稍后查询。

### 4. Amazon Data Firehose 转换为 Parquet 并写入 S3

Amazon Data Firehose 缓冲记录并将其写入 Amazon S3 存储桶，并在此过程中从 JSON 转换为 Parquet。 Firehose 还将每个对象归档在日期路径下 (`year=2026/month=08/day=27/`)。

### 5.使用Athena查询数据并连接成本数据

[AWS Glue](https://aws.amazon.com/glue/) 表告诉 Athena 如何读取这些文件，以便您可以使用普通 SQL 查询数据湖。您可以看到哪些用户使用最多的代币、哪些模型被普遍选择以及人们在提示什么。如果需要，您还可以将其连接到 [AWS 成本和使用情况报告](https://aws.amazon.com/aws-cost-management/aws-cost-and-usage-reporting/) (CUR) 以获取每日用户提示的支出。

## 开始之前您需要什么？

部署之前需要做好以下几件事：

- [AWS 命令​​行界面 (AWS CLI)](https://aws.amazon.com/cli/) 配置了每个账户的凭证。
- **CloudFormation** `CAPABILITY_IAM` 和 `CAPABILITY_NAMED_IAM` 权限。
- **至少一个链接账户**（运行 Amazon Bedrock 工作负载的账户）和**一个中央账户**用于接收复制日志（这些账户可以是同一账户）。
- **Python 3 with Boto3** (`pip install boto3`)，用于端到端测试脚本。
- [克隆存储库](https://github.com/aws-samples/sample-bedrock-token-cost-allocation) 及其中的所有资源。

## 你如何部署它？

**这里的顺序很重要。** 中央帐户堆栈必须先存在，然后链接的帐户堆栈才能引用它。

### 第 1 阶段：部署中央数据湖堆栈

首先将中央 CloudFormation 堆栈部署到将拥有管道的帐户中。在继续之前，请注意堆栈输出中的两个值：CloudWatch Logs 目标 ARN（每个源账户都需要）和 [AWS Quick视线](https://aws.amazon.com/quick/?trk=cb69a790-31b4-4f3f-ab38-8c131506ae2b&sc_channel=ps&ef_id=Cj0KCQjw2OnUBhC2ARIsACKyfaHOyr I2BSqC3eo7DZbbj0Ks030dwANVC-ITwsJaw_YzyJqknqgei6IaAm3WEALw_wcB:G:s&gads_camp=23528573981&gads_ag=191423962694&gads_ad=8069675641 54&gads_kw=amazon%20quick&gads_matchtype=e&gads_network=g&gads_device=c&gads_geo=1006993&gad_campaignid=23528573981&gbraid=0AAAA ADjHtp_o1ijSErUcY81biixQPaoFW&gclid=Cj0KCQjw2OnUBhC2ARISACKyfaHOyrI2BSqC3eo7DZbbj0Ks030dwANVC-ITwsJaw_YzyJqknqgei6IaAm3WEALw_wcB)角色 ARN（如果您部署仪表板，稍后需要）。

### 第 2 阶段：在每个源帐户中部署日志记录堆栈

部署关联帐户 CloudFormation。对运行 Amazon Bedrock 工作负载的每个账户重复此操作。源堆栈很小，并且采用单个输入：来自阶段 1 的目标 ARN。

### 第 3 阶段：打开 Amazon Bedrock 模型调用日志记录

部署堆栈不会启动日志记录。 Amazon Bedrock 日志记录是账户级别设置，而不是 CloudFormation 资源。每个源账户激活一次，将 Amazon Bedrock 指向日志组和第 2 阶段的日志记录角色。仅启用 CloudWatch 传输。

### 第 4 阶段：验证数据是否到达

在源账户中运行测试调用，等待 Amazon Data Firehose 刷新其缓冲区（[大约一分钟，有时更长](https://docs.aws.amazon.com/firehose/latest/dev/basic-deliver.html#Frequency)），然后确认 Parquet 对象已出现在数据湖的“data/”前缀下。最后，检查您的 S3 存储桶以查看数据。

### 第 5 阶段：创建 Athena 视图并查询数据

中央堆栈将视图定义保存为命名的 Athena 查询，但不运行它。执行一次保存的查询以创建平面视图。在专用 Athena 工作组中针对原始表或扁平视图运行查询。该视图很简单：令牌计数、缓存令牌、停止原因和提示/响应预览已经是平面列。

## 什么是代币经济学以及为什么这个数据湖对其很重要？

Tokenomics 是管理人工智能 (AI) 代币消费经济的实践，在 2026 年 FinOps 基金会会议上宣布为正式的 FinOps 领域。它建立在与云财务管理相同的“查看”、“保存”、“运行”和“计划”支柱之上，但应用于代币而不是基础设施。挑战在于您无法优化无法衡量的内容。如今，大多数组织都缺乏回答基本代币经济学问题所需的精细数据：哪些团队消耗的代币最多，哪些提示是浪费的。通过每次调用令牌和成本可见性，团队可以将每个工作负载与适合它的模型相匹配。这正是这个数据湖为您提供的。通过对每次调用的提示、响应、令牌计数、模型和 IAM 身份的可见性，您可以为开始运行令牌经济学实践而不仅仅是跟踪 Amazon Bedrock 账单奠定基础。

## 您现在可以使用 Amazon Bedrock 调用日志做什么？

通过在一个快速、可查询的表中进行每次调用，您终于可以回答曾经很痛苦的问题：

- **调试和审核调用 –** 在帐户中提取特定调用的准确提示和响应，而无需挖掘原始日志文件。
- **衡量代币效率 –** 将“input_tokens”与“output_tokens”进行比较，并跨团队选择模型，以找出您无缘无故燃烧代币的地方。
- **发现提示工程机会 –** 查找响应被切断的请求（`stop_reason = max_tokens`），这是提示或配置需要工作的好迹象。
- **查看模型系列 –** 数据显示哪个模型服务于每种模式，以便团队可以确认每个模型与其工作负载相匹配。
- **管理跨团队的使用情况 –** 每次调用都与一个帐户绑定，以便您知道谁在运行什么。

## 数据治理

由于该解决方案将每个团队的完整提示和完成情况集中到单个 Amazon S3 存储桶中，因此安全性和治理从一开始就内置于该架构中。该存储桶受 AWS Key Management Service (AWS KMS) 的服务器端加密保护，因此默认情况下数据会进行静态加密。对存储桶和 Amazon Athena 查询结果的访问是通过 AWS Identity and Access Management (IAM) 策略控制的。您可以将权限范围限定到需要它们的团队和角色。提示可能包含个人身份信息 (PII)，具体取决于您的用户与 Amazon Bedrock 交互的方式。我们建议检查您的 IAM 策略和 Amazon S3 存储桶策略，以确认只有授权委托人才能访问数据。

## 清理

如果您希望删除创建的资源，请清空对象存储桶，然后删除 CloudFormation 模板。请注意在删除之前清空 S3 存储桶并手动删除 Athena Workgroup。

## 总结

现在，您可以将来自 Amazon Bedrock 的原始调用日志转换为单个、快速、组织范围内的可观察层。您可以清楚地了解帐户中的每个提示、响应、代币计数和模型选择，而不是封闭的系统。当您需要时，您还可以直接了解每件产品的成本。

与任何系统项目一样，不要试图让海洋沸腾。从一两个链接帐户开始，舒适地查询调用表，然后扩展到整个组织。您的 Amazon Bedrock 使用量只会增加，因此您越早建立这种可见性，未来的每次调试、效率和成本对话就会变得越简单。
