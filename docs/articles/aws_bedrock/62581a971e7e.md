# AI 在 Snoonu 驱动个性化商品发现的力量

*本文由 Snoonu 的 Felipe Monroy、Ana Jaime 与 Nikita Gordeev 共同撰写。*

在电商领域管理庞大的商品目录，给那些试图高效地把顾客与他们真正想要的商品连接起来的零售商带来了新的障碍。传统的“一刀切”做法往往导致机会流失与客户参与度下降。对 Snoonu 这类 marketplace 应用而言，个性化对于提升客户参与度、提高转化率、最大化单用户收入，并同时建立长久的客户忠诚度至关重要。

从顾客视角看，Snoonu 的用户期待无缝的商品发现体验：既节省时间，又能呈现符合其偏好的商品。他们希望推荐在具体情境下恰当，并能随其不断变化的需求调整。这使个性化不仅是一项业务上的必须，更成为客户满意度的必备条件。

在本文中，我们分享中东领先的电商平台 Snoonu 如何借助 AI 驱动的个性化改造其商品发现体验。

## 排序与推荐面临的挑战

在 Snoonu，创新与卓越是指导原则，他们力求在卡塔尔提供最佳的购物与配送体验。随着规模扩大，优化排序、向顾客推荐商品与商家，对于提升用户体验和推动业务增长至关重要。起初，Snoonu 依赖基于热度的排序等基础规则，这导致推荐系统缺乏个性化与深度。为突破这一瓶颈，Snoonu 在 2024 年转向 [Amazon Personalize](https://aws.amazon.com/personalize/)。他们先从整个平台共用一个统一的全球模型提供实时推荐开始，再逐步演进到按垂直业务划分的推荐模型。这一演进体现了以持续交付增量价值为核心的创业心态所具有的敏捷与迭代方式。结果，Snoonu 通过更智能、数据驱动的体验取得了可衡量的成效，客户参与度与转化率大幅提升。

## Snoonu 个性化的演进

Snoonu 的个性化之旅始于静态规则，主要依赖基于热度的排序。这种方法虽然实施简单，却向所有用户展示同样的热门商品，忽略了个人偏好，导致推荐商品的参与度偏低。或许最重要的是，它无法帮助发现那些本可能与特定顾客完美匹配的长尾商品。

为解决这些局限，Snoonu 通过构建横跨所有垂直业务（Marketplace、Food 和 Groceries）的统一全球模型，实现了[实时推荐](https://docs.aws.amazon.com/personalize/latest/dg/getting-recommendations.html)。系统为用户生成每日推荐列表。尽管这种方法相比静态规则提升了相关性，却也有自身的问题。推荐会很快过时，既无法捕捉用户行为的细微差别，也无法对库存变化做出反应。此外，由于推荐在整周内保持不变，系统无法动态适应用户行为与库存更新，这限制了它推动转化的效果。

真正的突破来自这样一个决定：为每个垂直业务分别实现模型，而不是维持单一统一的全球模型。这一战略转变认可了客户行为与决策过程在不同垂直业务间存在显著差异——例如，点午餐的顾客与规划每周杂货采购的人呈现出不同的模式。通过为外卖配送、杂货购物和 marketplace 购买分别开发专门模型，Snoonu 能够更好地捕捉各垂直业务客户旅程的独特细微之处，尽管这些行为存在部分重叠。这种按垂直业务划分的做法带来了更精准的推荐，最终提升了客户体验与满意度。此外，Snoonu 把训练策略从 3 周一个周期转变为每日更新——这一关键变化我们会在本文后面探讨。

系统进一步借助精密的[过滤表达式](https://docs.aws.amazon.com/personalize/latest/dg/filter-expressions.html)得到增强，以提升推荐的相关性。该特性的一项关键应用是排除已加入购物篮的商品，以缩小探索列表。此外，过滤表达式还支持针对用户当前浏览类别的推荐。例如，当用户搜索笔记本电脑时，系统会智能地推荐相关的电子产品。

为优化性能与可扩展性，Snoonu 通过 [Amazon ElastiCache](https://aws.amazon.com/elasticache/) 实现了 Redis 缓存。这一增补显著降低了 API 延迟、提升了系统可扩展性并优化了成本，同时改善了整体用户体验。

## 解决方案概览

Snoonu 的架构使用 Amazon Personalize 交付实时推荐：无缝捕获用户交互、持续更新其个性化模型，并按对顾客可供的商品进行过滤。下图展示了该解决方案的架构。

该技术解决方案架构由若干关键阶段组成，使用 AWS 服务与外部工具：数据准备与收集、模型训练，以及实时推荐。在接下来的小节中，我们将更详细地讨论这些阶段。

## 数据准备与收集

Snoonu 为其推荐系统实现了双 pipeline 的数据收集策略。Amplitude 捕获应用内所有用户交互，这些数据进入 Snoonu 的主 pipeline，每日导出到 BigQuery，用于历史存储与模型重训。历史存储包含用户-商品交互、商品元数据和用户元数据的结构化数据集，每日在 Databricks 中处理。经过校验与特征变换后，数据导出到 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3），并通过 Amazon Personalize 每日用于重训模型。关于所用不同数据类型的更多细节及其如何支撑个性化，请参阅 [Preparing training data for Amazon Personalize](https://docs.aws.amazon.com/personalize/latest/dg/preparing-training-data.html)。

由这一数据准备与收集 pipeline 每日收集的数据集更新，支撑了新鲜的商品目录与更新后的业务规则。

## 模型训练与更新

Snoonu 为不同用例实现了多个 [Amazon Personalize recipe](https://docs.aws.amazon.com/personalize/latest/dg/use-case-recipe-features.html)。aws-user-personalization recipe 驱动首页排序以及购物车和商品详情页的推荐。aws-similar-items recipe 负责“经常一起购买”类推荐，aws-personalized-ranking recipe 则增强类别与子类别页面的排序。

尽管 Amazon Personalize 通常建议每周训练一次，但通过大量实验，Snoonu 发现他们的用例需要更频繁的更新。他们从 3 周的训练周期改为每周一次，最终定为每日训练，以在所有垂直业务中保持相关性。

每个垂直业务都使用针对其特定需求优化的不同 Amazon Personalize recipe。例如，Snoonu 的 Marketplace 同时实现用户个性化与重排序能力，以有效应对庞大的商品目录。其杂货垂直业务主要使用 similar items，推荐“经常一起购买”的商品以促进购物篮构建；外卖配送服务则依赖用户个性化来捕捉下单模式。想进一步了解如何选择合适的 Amazon Personalize recipe，请参阅 [Choosing a recipe](https://docs.aws.amazon.com/personalize/latest/dg/working-with-predefined-recipes.html)。

为与此互补并更新实时推荐系统，他们把按业务垂直线过滤后的 Amplitude 事件通过 [Amazon Kinesis Data Streams](https://aws.amazon.com/kinesis/data-streams) 流式传输，随后进入 [AWS Lambda](https://aws.amazon.com/lambda)。Lambda 函数承担三项关键任务：校验 schema，确保传入的 Kinesis Data Streams 数据格式正确；在处理这些事件后使用 PutEvents API 发送到 Amazon Personalize，以更新 event tracker；并通过向其中介服务发送携带 userId 的 HTTP POST 请求来触发推荐更新。这使系统能够基于即时的用户行为持续更新并改进推荐。

## 实时推荐

由于 Snoonu 使用的是自定义 recipe，他们构建了一个 campaign 来托管 solution version，以返回实时推荐。想进一步了解这一过程，请参阅 [Custom resources for training and deploying Amazon Personalize models](https://docs.aws.amazon.com/personalize/latest/dg/create-custom-resources.html)。

为大规模高效地提供这些推荐，Snoonu 开发了一个中介服务，充当前端与其 campaign 解决方案之间的智能桥梁。该服务解决了在即时响应用户行为的同时，大规模高效管理缓存、API 用量与响应时间的挑战。为此，他们使用 [Amazon ElastiCache](https://aws.amazon.com/elasticache/) 缓存推荐，并实现由实时触发驱动的缓存失效策略，而非传统的 Time to Live（TTL）逻辑。当用户发生交互时，Lambda 函数会触发推荐服务，只有在动作很可能改变用户偏好时才可能清除缓存并获取新的推荐。

该服务还负责 Amazon Personalize 结果的后处理，按原生不支持的因素进行过滤，例如地理可售性与实时库存状态。该架构确保系统能够即时响应用户行为，同时大规模高效管理缓存、API 用量与响应时间，提供对用户始终新鲜且相关的个性化推荐。

最后，所有推荐请求都通过 [Amazon MQ](https://aws.amazon.com/amazon-mq/)（使用 [RabbitMQ](https://docs.aws.amazon.com/amazon-mq/latest/developer-guide/working-with-rabbitmq.html)）记录日志，使 Snoonu 可以比较过滤前后的推荐并监控系统性能。

## 业务成果

Amazon Personalize 的实施为 Snoonu 带来了显著的业务成果，展示了电商中个性化推荐的强大影响。在 Groceries 垂直业务中，来自购物车推荐的加购事件增长了惊人的 1,600%，表明客户参与度与商品发现显著改善。这一个性化策略证明极具成本效益：在 6 个月期间产生的商品交易总额（GMV）是模型总投资的 47 倍。这相当于 QR 2.6 million（715,000 美元）的累计增量 GMV，直接归因于推荐驱动的转化。最值得注意的是，在至少包含一件推荐商品的订单中，个性化推荐对客户购物篮大小的贡献为 30%。这些结果还展示了个性化如何有效地产生乘数效应，推动即时销售并鼓励顾客探索更广泛的商品类别、做出更明智的购买决策。marketplace 业务的成功为 Snoonu 把这一个性化策略扩展到其他垂直业务铺平了道路，用客户洞见打造更具吸引力、更相关的购物体验。

## 关键经验

实现 AI 驱动个性化的旅程带来了有价值的洞见。从小处着手、快速扩展被证明至关重要，它帮助 Snoonu 在扩展到更复杂用例之前验证成效。数据质量成为关键的成功因素，需要在准备与维护一致的 schema 上投入大量资源。

Snoonu 的个性化之旅始于横跨所有垂直业务的单一统一模型，这为理解客户行为模式奠定了基础。随着平台成熟，团队战略性地演进了其做法：为不同垂直业务开发专门模型，并实现针对各类用例的特定推荐 recipe。

## 结论

Snoonu 与 Amazon Personalize 的旅程展示了 AI 驱动个性化在电商中的变革力量。Snoonu 分阶段推进个性化的做法对客户行为产生了实质性影响。该解决方案在特定垂直业务内优化了性能，并创造了乘数效应，提升客户参与度并鼓励跨类别探索。Amazon Personalize 帮助 Snoonu 取得了可观的业务价值，同时显著提升了客户满意度。这一成功故事为探索更具创新性的 AI 驱动能力打开了大门，例如在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上使用生成式 AI 模型，以进一步改进其个性化与发现体验。
