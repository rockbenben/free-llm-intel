# 使用 Amazon Bedrock AgentCore Browser 和 Amazon Nova Act 实现 agentic QA 自动化

质量保证（QA）测试长期以来是软件开发的支柱，但传统 QA 方法未能跟上现代开发周期和复杂 UI 的步伐。大多数组织仍依赖手动测试与 Selenium、Cypress、Playwright 等基于脚本的自动化框架相结合的混合方式——而团队把大量时间花在维护现有测试自动化上，而不是创建新测试。问题在于传统自动化很脆弱。测试脚本会因 UI 变更而失效，需要专门的编程知识，并且往往在跨浏览器和跨设备覆盖上不完整。在众多组织正积极探索 AI 驱动测试工作流的当下，现有方法仍显不足。

本文探讨 agentic QA 自动化如何应对这些挑战，并通过一个使用 [Amazon Bedrock AgentCore Browser](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html) 和 [Amazon Nova Act](https://nova.amazon.com/act) 为示例零售应用自动化测试的实例来逐步讲解。

## agentic QA 测试的优势

agentic AI 把 QA 测试从基于规则的自动化转向智能、自主的测试系统。与遵循预编程脚本的传统自动化不同，agentic AI 能够观察、学习、适应并实时做出决策。主要优势包括通过 UI 观察自主生成测试，以及随着 UI 元素变化而动态适应——从而把消耗 QA 团队时间的维护开销降到最低。这些系统模仿人类交互模式，确保测试从真实的用户视角进行，而不是走僵化的脚本化路径。

## 用于大规模 agentic QA 测试的 AgentCore Browser

要在企业规模上实现 agentic AI 测试的潜力，组织需要能支撑智能、自主测试 agent 的健壮基础设施。AgentCore Browser 是 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 的内置工具，它通过提供专为 AI agent 与网站和应用交互而设计的安全、基于云的浏览器环境来满足这一需求。

AgentCore Browser 包含必要的企业安全特性，例如会话隔离、通过实时查看实现的内置可观测性、[AWS CloudTrail](https://aws.amazon.com/cloudtrail) 日志记录和会话回放能力。每个浏览器实例在容器化的临时环境中运行，使用后即可关闭，从而提供干净的测试状态和最优的资源管理。对于大规模 QA 运营，AgentCore Browser 可以并发运行多个浏览器会话，因此组织能够同时在不同场景、环境和用户旅程上并行测试。

## 使用 Amazon Nova Act SDK 进行 agentic QA

当与 Amazon Nova Act 这类 agentic SDK 结合时，AgentCore Browser 的基础设施能力才真正发挥威力。Amazon Nova Act 是一项 AWS 服务，帮助开发者构建、部署和管理可靠的 AI agent 集群，用于自动化生产环境的 UI 工作流。借助该 SDK，开发者可以把复杂的测试工作流拆解成更小、更可靠的命令，同时保留按需调用 API 和直接操作浏览器的能力。这种方法在整个测试过程中实现了 Python 代码的无缝集成。开发者可以在 agentic 工作流中直接穿插测试、断点和断言，获得前所未有的控制与调试能力。AgentCore Browser 云基础设施与 Amazon Nova Act agentic SDK 的这种结合，构建了一个全面的测试生态，改变了组织处理质量保证的方式。

## 实践实现：零售应用测试

为了在实践中说明这种转变，我们设想为一家零售公司开发新应用。我们创建了一个模拟零售 Web 应用来演示 agentic QA 流程，并假设该应用在开发和测试阶段托管在企业私有网络内的 AWS 基础设施上。

为简化测试创建过程，我们使用 [Kiro](https://kiro.dev/) 这一 AI 驱动的编码助手，通过分析我们的应用代码库自动生成 UI 测试用例。Kiro 检查应用结构、审阅现有测试模式，并按 Amazon Nova Act 要求的 JSON schema 格式创建完整的测试用例。通过理解应用的功能——包括导航、搜索、筛选和表单提交——Kiro 生成带有操作和预期结果的详细测试步骤，这些步骤可立即通过 AgentCore Browser 执行。这种 AI 辅助的方法大幅加快测试创建，同时提供全面覆盖。下面的演示展示了 Kiro 为我们的 QA 测试演示应用生成 15 个可直接使用的测试用例。

[![Kiro 生成测试用例](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/15/video1_12_12.gif)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/15/video1_12_12.gif)

测试用例生成后会被放入[测试数据目录](https://github.com/aws-samples/amazon-nova-samples/tree/main/nova-act/usecases/qa-testing/tests/src/test_data)，由 [pytest](https://docs.pytest.org/en/stable/) 自动发现并执行。每个 JSON 测试文件都会成为一个独立测试，pytest 可以并行运行它们。该框架使用 [pytest-xdist](https://pypi.org/project/pytest-xdist/) 把测试分发到多个工作进程，自动利用可用的系统资源以获得最佳性能。

执行期间，每个测试都通过 Amazon Nova Act SDK 获得自己独立的 AgentCore Browser 会话。Amazon Nova Act agent 从 JSON 文件中读取测试步骤并执行——完成点击按钮或填写表单等操作，然后验证预期结果是否出现。这种数据驱动的方法意味着团队只需编写 JSON 文件就能创建完整的测试套件，无需为每个测试场景编写 Python 代码。并行执行架构显著缩短测试时间。原本需要顺序运行的测试现在可以在多个浏览器会话中同时执行，由 pytest 管理分发和结果聚合。使用 pytest-html 和 pytest-html-nova-act 插件会自动生成 HTML 报告，提供测试结果、截图和执行日志，让整个测试过程完全可见。

![](https://d2908q01vomqb2.cloudfront.net/artifacts/DBSBlogs/ML-19972/ML-19972-video2.gif)

AgentCore Browser 最强大的能力之一是并发运行多个浏览器会话，从而在规模化时实现真正的并行测试执行。当 pytest 把测试分发到各工作进程时，每个测试都会在云中启动自己独立的浏览器会话。这意味着整个测试套件可以同时执行，而不必等待每个测试顺序完成。

[AWS Management Console](https://aws.amazon.com/console) 提供了对这些并行会话的完整可见性。如下面视频所示，你可以查看并发运行的活跃浏览器会话、监控其状态，并实时跟踪资源利用率。这种可观测性对于理解测试执行模式和优化测试基础设施至关重要。

![](https://d2908q01vomqb2.cloudfront.net/artifacts/DBSBlogs/ML-19972/ML-19972-video3.gif)

除了监控会话状态，AgentCore Browser 还提供实时查看和会话回放功能，可以准确观察 Amazon Nova Act 在测试执行期间和执行之后做了什么。对于活跃的浏览器会话，你可以打开实时查看，实时观察 agent 与应用交互——点击按钮、填写表单、浏览页面并验证结果。启用会话回放后，你可以通过回放录制的会话来查看记录的事件。这让你即使在测试执行完成后也能验证测试结果。这些能力对于调试测试失败、理解 agent 行为以及对自动化测试过程建立信心都极有价值。

有关完整的部署说明，以及示例零售应用代码、[AWS CloudFormation](https://aws.amazon.com/cloudformation) 模板和 pytest 测试框架的获取方式，请参阅配套的 [GitHub 仓库](https://github.com/aws-samples/amazon-nova-samples/tree/main/nova-act/usecases/qa-testing)。该仓库包含在你自己的 AWS 环境中部署和测试该应用所需的组件。

## 结论

本文讲解了 AgentCore Browser 如何帮助并行化 Web 应用的 agentic QA 测试。像 Amazon Nova Act 这样的 agent 能够以高可靠性执行自动化的 agentic QA 测试。
