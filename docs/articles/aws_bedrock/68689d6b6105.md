# 在 AWS 上为你的机器翻译任务评估大型语言模型

大型语言模型（LLM）在机器翻译（MT）任务中展现出了令人期待的能力。视用例而定，它们能够与 [Amazon Translate](https://aws.amazon.com/translate/) 等神经翻译模型相竞争。LLM 尤其突出的是它们学习输入文本上下文的天然能力，这使它们能够捕捉文化线索并产出更自然的译文。例如，“Did you perform well?” 这句话译为法语，可能被翻译成“Avez-vous bien performé?” 具体译文可能因上下文而大相径庭。如果这个问题是在体育语境下提出的，例如“Did you perform well at the soccer tournament?”，那么自然的法语译文就会完全不同。对 AI 模型而言，要产出更自然的译文，不仅捕捉上下文、还要把握文化特性至关重要。LLM 最令人着迷的优势之一，就是它们理解上下文的内在能力。

我们的许多全球客户希望利用这一能力来提升其译文内容的质量。本地化既依赖自动化，也依赖被称为机器翻译后编辑（MTPE）流程中的“人在环中”。构建有助于提升译文质量的解决方案带来多重收益：

- 在 MTPE 活动上可能节省的成本
- 本地化项目的交付周期更快
- 借助提升后的质量，为内容消费者与读者带来更好的整体体验

LLM 在 MT 任务上也表现出了差距，例如：

- 某些语言对之间的质量不稳定
- 没有集成既有翻译知识（也称为翻译记忆库，TM）的标准模式
- 固有的幻觉风险

把 MT 工作负载从神经翻译切换为 LLM 驱动的翻译，应当按个案评估。不过，业界已经看到了足够的潜力，值得把 LLM 视为一个有价值的选项。

这篇附带代码的博客文章提出了一个解决方案，用于借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 中可用的基础模型（FM）试验实时机器翻译。它有助于你为自身内容翻译用例收集更多关于 LLM 价值的数据。

## 引导 LLM 的输出

翻译记忆库和 [TMX 文件](https://help.transifex.com/en/articles/6838724-tmx-files-and-format)是计算机辅助翻译（CAT）工具和翻译管理系统（TMS）领域中重要的概念与文件格式。

### 翻译记忆库

翻译记忆库是一个数据库，用于存储此前已翻译的文本片段（通常是句子或短语）及其对应的译文。TM 的主要目的是通过为已翻译过的片段提供建议来辅助人工或机器译者。这可以显著提升翻译效率与一致性，尤其是对于涉及重复内容或类似主题的项目。

翻译记忆库交换格式（TMX）是用于表示和交换 TM 数据的一种被广泛采用、开放的标准。它是一种基于 XML 的文件格式，允许在不同的 CAT 工具和 TMS 之间交换 TM。一个典型的 TMX 文件包含翻译单元的结构化表示，翻译单元即同一文本被译为多种语言后的分组。

### 把 TM 与 LLM 集成

把 TM 与 LLM 结合使用，是提升机器翻译质量与效率的一种强有力方法。以下是一些潜在收益：

- **提升准确率与一致性** – LLM 可以从 TM 中存储的高质量译文中获益，这有助于改善 LLM 所产出译文的整体准确率与一致性。TM 可以为 LLM 提供特定片段的可靠参考译文，降低出错或不一致的可能性。
- **领域适配** – TM 往往包含特定领域或主题的译文。通过使用领域特定的 TM，LLM 可以更好地适配该领域的术语、风格与上下文，从而产出更准确、更自然的译文。
- **高效复用人工译文** – TM 存储的是人工翻译的片段，其质量通常高于机器翻译片段。通过把这些人工译文纳入 LLM 的训练或推理过程，LLM 可以学习并复用这些高质量译文，从而有可能提升其整体表现。
- **减少后编辑工作量** – 当 LLM 能够准确使用 TM 中存储的译文时，对人工后编辑的需求就会减少，从而提升生产力并节省成本。

另一种把 TM 数据与 LLM 集成的方法，是像为业务领域内容生成微调模型那样使用 fine-tuning。对于在全球性行业运营、可能需要与 10 多种语言互译的客户来说，这种方法在操作上可能既复杂又昂贵。本文提出的解决方案依托 LLM 的上下文学习能力和 prompt engineering。它让你可以直接使用现成的模型，而无需涉及机器学习运维（MLOps）活动。

## 解决方案概览

LLM 翻译 playground 是一个示例应用，提供以下能力：

- 使用 Amazon Bedrock 中可用的模型试验 LLM 的翻译能力
- 创建并比较各种推理配置
- 评估 prompt engineering 与检索增强生成（RAG）对 LLM 翻译的影响
- 配置受支持的语言对
- 使用你现有的 TMX 文件与多个 LLM 一起导入、处理并测试翻译
- 自定义术语转换
- 性能、质量与用量指标，包括 BLEU、BERT、METEOR 和 CHRF

### TM 知识库的策略

LLM 翻译 playground 提供两种把翻译记忆库纳入 prompt 的选项。每个选项都通过应用内的独立页面提供：

- **使用 FAISS 的向量存储** – 在该模式下，应用会处理用户上传的 .tmx 文件、为其建立索引，并在本地存储到向量存储（FAISS）中。
- **使用 Amazon OpenSearch Serverless 的文档存储** – 仅支持使用 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/) 的标准文档检索。要测试向量检索，请使用向量存储选项（使用 FAISS）。

在向量存储模式下，翻译片段的处理方式如下：

- 对源片段进行嵌入。
- 提取元数据：片段语言、系统生成的 `<tu>` 片段唯一标识符
- 把源片段向量连同元数据和片段本身的纯文本一起作为文档存储

翻译自定义部分允许你选择嵌入模型。你可以选择 Amazon Titan Embeddings Text V2 或 Cohere Embed Multilingual v3。Amazon Titan Text Embeddings V2 在预训练中包含对 100 多种语言的多语言支持。Cohere Embed 支持 108 种语言。

在文档存储模式下，语言片段不会被嵌入，而是按照扁平结构存储。文档之间会保留两个元数据属性：

- 片段语言
- 系统生成的 `<tu>` 片段唯一标识符

[![Translation Memory Chunking](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/31/ML-17172-chunking-003.jpg)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/31/ML-17172-chunking-003.jpg)

### Prompt engineering

该应用使用 prompt engineering 技术，为推理纳入多种类型的输入。以下示例 XML 展示了 prompt 的模板结构：

```
<prompt>
<system_prompt>…</system_prompt>
<source_language>EN</source_language>
<target_language>FR</target_language>
<translation_memory_pairs>
<source_language>…</source_language>
<target_language>…</target_language>
</translation_memory_pairs>
<custom_terminology_pairs>
<source_language>…</source_language>
<target_language>…</target_language>
</custom_terminology_pairs ><user_prompt>…</user_prompt>
</prompt>
```

项目代码使用 Python 版本的 [AWS Cloud Development Kit](https://aws.amazon.com/cdk/)（AWS CDK）。要运行项目代码，请确保你已满足 [Python 的 AWS CDK 先决条件](https://docs.aws.amazon.com/cdk/latest/guide/work-with-cdk-python.html)。

## 安装 UI

要部署该解决方案，请先安装 UI（Streamlit 应用）：

- 使用以下命令克隆 GitHub 仓库：

```
git clone https://github.com/aws-samples/llm-translation-playground.git
```

- 进入部署目录：

```
cd llm-translation-playground
```

- 安装并激活 Python 虚拟环境：

```
python3 -m venv .venv
source .venv/bin/activate
```

- 安装 Python 库：

```
python -m pip install -r requirements.txt
```

## 部署 AWS CDK 堆栈

请完成以下步骤来部署 AWS CDK 堆栈：

- 进入部署文件夹：

```
cd deployment/cdk
```

- 配置 AWS CDK 上下文参数文件 `context.json`。对于 `collection_name`，使用 OpenSearch Serverless 集合名称。例如：

`"collection_name": "search-subtitles"`

- 部署 AWS CDK 堆栈：

```
cdk deploy
```

- 在 [AWS CloudFormation](https://aws.amazon.com/cloudformation) 上查看 `OpsServerlessSearchStack` 堆栈，验证部署是否成功。状态应显示为 **CREATE_COMPLETE**。
- 在 **Outputs** 选项卡中，记下 `OpenSearchEndpoint` 属性的值。

[![Cloudformation Stack Output](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/31/ML-17172-cfn-stack-004.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/31/ML-17172-cfn-stack-004.png)

**配置解决方案**

该堆栈会创建一个 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色，具备运行该应用所需的恰当权限级别。LLM 翻译 playground 会代表你自动代入该角色。为此，请修改你打算运行该应用所依据的角色或主体，使其被允许代入新建的角色。你可以使用预先创建好的策略并将其附加到你的角色上。策略的 Amazon Resource Name（ARN）可以从名为 `LLMTranslationPlaygroundAppRoleAssumePolicyArn` 的堆栈输出中获取，如上一张截图所示。你也可以在 IAM 控制台中选择你的角色并选择 **Add permissions** 来完成这一操作。如果你更倾向使用 [AWS Command Line Interface](https://aws.amazon.com/cli)（AWS CLI），请参考以下示例命令行：

```
aws iam attach-role-policy --role-name &lt;role-name&gt;  --policy-arn &lt;policy-arn&gt;
```

最后，按下述方式配置 `utils` 文件夹中的 `.env` 文件：

- **APP_ROLE_ARN** – 由该堆栈创建的角色的 ARN（堆栈输出 `LLMTranslationPlaygroundAppRoleArn`）
- **HOST** – OpenSearch Serverless 集合端点（不带 https）
- **REGION** – 部署该集合所在的 AWS 区域
- **INGESTION_LIMIT** – 你上传的每个 TMX 文件被索引的翻译单元（`<tu>` 标签）最大数量

### 用语义相似度为翻译记忆库挑选片段

在向量存储模式下，应用允许你上传 TMX 并创建本地索引，利用语义相似度来选择翻译记忆库片段。首先，我们基于待翻译文本和源语言，检索出相似度得分最高的片段。然后，我们检索出目标语言和父翻译单元 ID 与之匹配的对应片段。

要试用它，按前面所示的方式上传文件即可。视文件大小而定，这可能需要几分钟。最大限制为 200 MB。你可以使用前一示例中的示例文件，也可以使用代码仓库中提供的其他示例之一。

这种方法与静态索引检索不同，因为它假定源文本在语义上足够接近那些能够代表预期风格与语气特征的片段。

## 进一步考量

把现有 TMX 文件用于基于生成式 AI 的翻译系统，有可能提升译文的质量与一致性。以下是使用 TMX 文件进行生成式 AI 翻译的一些步骤：

- **TMX 数据管道** – TMX 文件包含结构化的翻译单元，但其格式可能需要预处理，以便以生成式 AI 模型可消费的格式提取源文本和目标文本片段。这涉及能够解析 XML 结构、处理编码问题并添加元数据的抽取、转换、加载（ETL）管道。
- **纳入质量评估与人工复核** – 尽管生成式 AI 模型可以产出高质量译文，仍建议纳入质量评估技术和人工复核流程。你可以使用自动化的质量评估模型来标记可能质量较低的译文，随后由人工译者复核并修改。
- **迭代与改进** – 翻译项目往往涉及翻译、复核和改进的迭代循环。你可以定期用更新后的 TMX 文件重新训练或微调生成式 AI 模型，形成持续改进的良性循环。
