# 使用 managed entitlements 简化对 Amazon Bedrock 模型的多账户访问

跨数十个甚至数百个 AWS 账户管理 AI 模型访问权限会带来两难。要么你在每个账户中配置 [AWS Marketplace](https://docs.aws.amazon.com/marketplace/) 访问权限，要么手动逐个启用订阅。对于使用第三方模型（如 Anthropic Claude 或 Cohere）的组织来说，这种运营开销会拖慢 AI 的采用。

在本文中，我们向你展示如何使用 [Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html) 的 managed entitlements，从一个中央账户订阅一次，然后在整个组织内分发模型访问权限。这种方法让工作负载账户无需在每个账户中单独配置 AWS Marketplace 即可访问模型。Managed entitlements 通过确保你的团队能够访问所需模型，同时维持集中治理，补充了 Amazon Bedrock 的其他能力，如模型评估和 guardrails。

在本文中，我们解释 managed entitlements 何时是你的组织的合适解决方案，逐步介绍四步工作流，演示真实场景，并涵盖关于 private offer 和区域行为的重要注意事项。

理解不同模型的分发方式是判断何时需要 managed entitlements 的关键。下表展示了三个类别：

| **模型类别** | **示例** | **访问方式** |
| --- | --- | --- |
| Amazon 模型 | Amazon Nova | 拥有 Amazon Bedrock 权限即可立即使用 |
| Amazon 销售的模型 | Meta、Mistral、DeepSeek | 拥有 Amazon Bedrock 权限即可立即使用 |
| AWS Marketplace 模型 | Anthropic Claude、Cohere、Stability AI | 需要 AWS Marketplace 订阅 |

对于 Amazon 模型和由 Amazon 销售的模型，最近推出的[简化访问](https://aws.amazon.com/blogs/security/simplified-amazon-bedrock-model-access/)意味着你可以立即开始调用它们，无需任何额外设置。通过 AWS Marketplace 分发的第三方模型则有所不同。每个账户在调用这些模型前都需要订阅，这意味着每个账户都需要 AWS Marketplace 权限。对于管理许多账户的组织来说，这会造成运营开销。要么你广泛授予 AWS Marketplace 权限，要么安排人员在每个账户中手动启用模型。

Amazon Bedrock 的 *managed entitlements* 弥合了这一缺口。从一个中央账户订阅一次，然后使用 [AWS License Manager](https://docs.aws.amazon.com/license-manager/) 在整个组织内分发访问权限。成员账户中无需 AWS Marketplace 权限。

## 何时需要 managed entitlements？

Managed entitlements 适用于以下组织：跨多个 AWS 账户运行工作负载；希望将 AWS Marketplace 订阅管理集中到单一账户；已谈妥 private offer 定价并希望各账户采用一致费率；或需要对整个组织的模型访问拥有集中可见性。它仅在需要使用第三方 AWS Marketplace 模型（如 Claude 或 Cohere）时适用。

如果你只使用 Amazon 和合作伙伴模型（例如 Amazon Titan、Llama、Mistral 或 DeepSeek），只在单一 AWS 账户中运营，或每个账户团队已经各自独立管理其 AWS Marketplace 订阅，那么你可能不需要 managed entitlements。

## 前提条件

在实施 managed entitlements 之前，请确认你已具备以下条件：

- **启用了所有功能的 AWS Organizations：** Managed entitlements 需要配置了所有功能的 [AWS Organizations](https://docs.aws.amazon.com/organizations/)。
- **管理账户访问权限：** 你需要访问你的管理账户，并同时拥有 AWS Marketplace 和 AWS License Manager 的权限。
- **成员账户：** 你希望向其分发模型访问权限的账户。
- **服务关联角色（service-linked roles，SLR）：** 直接链接到 AWS 服务的预定义 AWS Identity and Access Management (IAM) 角色。对于 Managed Entitlements，你必须为 AWS License Manager 和 AWS Marketplace 都创建 SLR。这些角色包含这些服务代表你调用其他 AWS 服务所需的全部权限。

## 工作原理

可以把 license 想象成你的组织使用某个模型的权利，而 grant 则是与特定账户分享这一权利的机制。一个 license 可以有多个 grant，因此你可以从单一订阅向许多账户分发访问权限。

Managed entitlements 的工作流包含四个主要步骤，如下图所示：

![Managed entitlements 工作流，展示四个步骤：订阅、验证 license、创建 grant 和激活](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/18/ML-20435-1.png)

**要实施 managed entitlements：**

- **订阅模型：** 从你的管理账户，通过 AWS Marketplace 订阅第三方 Amazon Bedrock 模型。当你通过 AWS Marketplace 订阅该模型时，就会发生这一步。你可以通过 AWS Marketplace 控制台或接受 private offer 来订阅。订阅后，AWS License Manager 会自动创建一个 license。
- **验证 license 创建：** AWS License Manager 会为你的订阅自动创建一个 license。这个 license 代表你使用该模型的权利，并作为向其他账户分发的基础。
- **创建 grant：** 使用 AWS License Manager，你创建 grant，与你的 [AWS Organizations](https://docs.aws.amazon.com/organizations/) 中的特定成员账户分享该 license。你可以精确控制哪些账户获得每个模型的访问权限。
- **激活并使用：** 成员账户会收到其 grant 的通知。激活 grant 后，它们即可立即开始调用该模型。成员账户无需任何额外设置即可立即开始调用模型。

成员账户即使没有订阅 private offer 或激活的 grant，仍然可以调用模型，但会按公开价格计费。

## 真实场景

### 场景 1：在整个组织中启用某个模型

**情况：** 你的团队需要在 50 个工作负载账户中访问一个新的 Anthropic Claude 模型。你不想为每个账户授予 `aws-marketplace:Subscribe` 权限，也不想逐个账户手动启用模型。

**解决方案：** 从你的管理账户（拥有 AWS Marketplace 权限），订阅 AWS Marketplace private offer。AWS License Manager 会自动创建一个 license。为你的 50 个工作负载账户创建 grant，并将它们分发到单个账户、整个组织或某个组织单元（organizational unit，OU）。每个账户可以单独激活其 grant，也可以在组织层面激活 grant。随后，团队无需在其账户中拥有 AWS Marketplace 权限即可调用模型。

**结果：** 集中订阅与分发访问，订阅管理整合在你的管理账户中。

### 场景 2：分阶段推出模型

**情况：** 你希望先让选定团队试用一个新模型，再向整个组织开放。你需要了解谁在使用什么，并能够逐步扩大访问范围。

**解决方案：** 从管理账户订阅，然后仅为试点账户创建 grant。随着试点成功，将 grant 扩展到其他账户。AWS License Manager 提供整个组织中 grant 状态的可见性。

**结果：** 受控的推出过程，并带有清晰的审计轨迹，记录哪些账户拥有访问权限以及它们何时激活。

### 场景 3：private offer 分发

**情况：** 你已通过 AWS Marketplace 与模型供应商谈妥定制价格。你需要每个账户都使用这一价格，而不是各自创建订阅。

**解决方案：** 请供应商将 private offer 扩展到管理账户。从管理账户接受该 private offer。所创建的 license 体现了你谈妥的条款。通过 grant 分发访问权限，以确保成员账户的使用量都计入你的协议。

**结果：** 整个组织采用一致的价格，并简化成本分摊。

### 场景 4：快速的全组织部署

**情况：** 你的组织已将某个模型标准化用于 AI 工作负载。你希望 AWS Organizations 中的每个账户都能立即获得访问权限。

**解决方案：** 从管理账户订阅，然后一步分发到整个组织：将整个 AWS Organizations 作为目标来分发 grant（而非选定账户）。

就是这样。成员账户会自动收到 grant。对于启用了所有功能的组织，组织会自动接受 grant，但在账户管理员显式激活它们之前，它们会处于 *Disabled* 状态。这为模型使用开始之前提供了最后一道控制点。

**结果：** 通过单个 grant，你组织中的每个账户都获得模型访问权限。加入组织的新账户会自动继承访问权限，无需额外创建 grant。

## 注意事项

在实施 managed entitlements 之前，请牢记以下事项，以确保部署顺利。

### 成本分摊

模型使用费用会账单到持有订阅的管理账户。使用 AWS Cost Allocation Tags 按成员账户或团队跟踪使用情况。

### Private offer

在处理通过 AWS Marketplace 谈妥的 private offer 时，managed entitlements 工作流保持不变。从管理账户接受 private offer，license 会自动创建。然后你可以通过 grant 向成员账户分发访问权限。

Private offer 通常包含定制价格、付款条件或额外支持协议。无论哪个成员账户调用模型，这些条款都适用于你组织对该模型的使用。在接受和分发访问权限之前，请仔细查看 offer 条款。

### 现有订阅

当成员账户已有活动的 Amazon Bedrock 模型，且其付款账户向他们分发了同一模型的订阅时，首个订阅的 entitlements 会被禁用，他们现在拥有新分发 grant 上的 entitlements。

### 区域行为

虽然你可以在受支持的 AWS 区域中调用模型，但 AWS License Manager 会在 us-east-1 中创建 license。即便你的工作负载运行在其他区域，grant 的创建和激活也会通过 AWS License Manager 的 us-east-1 端点进行。

## 清理资源

如果你不再需要某个模型订阅：

- 在 AWS License Manager 中删除成员账户的 grant。
- 从管理账户取消 AWS Marketplace 订阅。
- 确认成员账户不再按 private 价格计费。

注意：取消订阅不会自动移除 grant。你必须单独删除 grant 才能撤销 private 定价。

## 结论

在本文中，我们向你展示了如何使用 Amazon Bedrock 的 managed entitlements，从单一管理账户集中第三方模型订阅，并在整个组织内分发访问权限。Amazon Bedrock 的 managed entitlements 代表了组织大规模管理第三方模型访问方式的重大改进。你现有的订阅会继续正常运行而不受干扰，并且你可以立即对新的订阅使用集中分发工作流，同时维持组织的治理控制。通过将订阅管理整合到一处并简化所有账户的访问权限，你可以专注于构建 AI 应用，而非管理访问基础设施。

### 后续步骤

准备好实施 managed entitlements 了吗？从以下方面开始：

- 确定你的组织使用哪些第三方模型。
- 审视你当前跨账户的订阅方式。
- 以一个模型作为试点实施 managed entitlements。
- 根据结果扩展到其他模型和账户。

你还可以探索将 managed entitlements 与 AWS Service Catalog 结合使用，为你的团队创建自助式模型访问工作流。
