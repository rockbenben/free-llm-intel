# 使用 Crawl4AI 为 Amazon Bedrock 知识库准备 Web 内容

当您构建检索增强生成 (RAG) 应用程序时，答案质量取决于您摄取的数据。 [Amazon Bedrock 知识库](https://aws.amazon.com/bedrock/knowledge-bases/) 是 Amazon Bedrock 的完全托管 RAG 功能。借助 [Amazon Bedrock 托管知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-build-management.html)，您可以连接数据源，Amazon Bedrock 会为您管理提取、存储、索引和检索。您无需配置或扩展矢量存储，嵌入和重新排名默认使用服务管理模型。

对于 Web 内容，请从托管知识库的 [Amazon Bedrock Web Crawler](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-management-ds-webcrawler.html) 数据源连接器开始。您向其提供您有权抓取的种子网址或站点地图，它就会在您设置的范围和速率限制内进行抓取。计划同步可在页面更改时使您的知识库保持最新状态，并且连接器可以等待使用 JavaScript 加载的内容。没有可供您构建、托管或操作的爬网程序，因此此连接器是大多数公共网站内容的起点。

有些来源需要对到达知识库的内容进行更多控制。您可能只想对每个页面的主要内容区域建立索引，删除导航和其他样板文件，或者将您自己的元数据属性附加到每个文档。对于此类源材料，您可以通过使用开源 Python 爬虫程序 [Crawl4AI](https://github.com/unclecode/crawl4ai) 构建的准备步骤来扩展知识库的范围。该步骤将每个页面的 Markdown 和元数据 sidecar 写入 Amazon Simple Storage Service (Amazon S3)，知识库通过其 Amazon S3 数据源提取这两者。

在这篇文章中，我们将向您展示如何选择适当的网络摄取路径并为需要额外处理的内容实施自定义准备。然后，您开始摄取托管知识库并验证检索质量。配套的 [aws-samples 存储库](https://github.com/aws-samples/sample-crawl4ai-bedrock-knowledge-base) 提供了完整的工作流程作为示例实现。

这是对已知 Web 属性的批量摄取，而不是在推理时进行实时 Web 访问，例如使用 Amazon Nova 的 [Web Grounding](https://docs.aws.amazon.com/nova/latest/nova2-userguide/web-grounding.html)。

## 解决方案概述

当 Amazon Bedrock Web Crawler 能够到达并索引您需要的页面时，开始使用它。它尊重“robots.txt”，并且在第一次完全抓取后，每次同步仅捕获添加、更新和删除的内容。

当公共源材料在摄取之前需要以下一项或多项时，请使用 Crawl4AI 准备路径：

- **结构化 Markdown 准备**：使用带有修剪内容过滤器的“DefaultMarkdownGenerator”来减少导航和其他样板文件，同时保留标题、列表和表格。由于修剪是启发式的，因此请检查站点的代表性输出。
- **有界、有针对性的提取**：仅提取可选 CSS 选择器匹配的页面区域。通过种子来源、页面/路径/主机范围、深度和页面上限以及 URL 模式来约束广度优先遍历。
- **自定义元数据**：将源 URL、抓取时间戳、内容类型和您自己的属性附加到每个文档，以便您可以过滤它们的检索结果。

由于托管知识库和客户管理知识库均支持 Amazon S3 数据源，因此 Crawl4AI 路径适用于任一类型。本文使用托管知识库，并指出客户管理知识库的不同之处。

本文的其余部分遵循配套示例。将其架构和默认设置作为起点，而不是作为 Amazon Bedrock 知识库的要求。

默认情况下，该示例在公有子网中运行 AWS Fargate 任务，并通过 Internet 网关访问您配置的网站。一旦准备好源文档和元数据 sidecar，Crawl4AI 的角色就结束了。从摄取开始，Amazon Bedrock 知识库就会处理解析、分块、嵌入、索引和检索。下图显示了 Crawl4AI 从计划到检索的路径。

图中的编号步骤映射到以下工作流程：

- Amazon EventBridge 按照配置的计划在 AWS Fargate 上启动 Amazon Elastic Container Service (Amazon ECS) 任务。
- 该任务会抓取您配置的公共网站，并为每个页面准备带有元数据 sidecar 的 Markdown。
- 该任务将准备好的文件上传到支持知识库数据源的 Amazon S3 存储桶。
- 该任务启动 Amazon Bedrock 知识库摄取作业。
- Amazon Bedrock 知识库读取新的和更改的对象，解析它们，并应用您选择的分块策略。
- 它创建嵌入并在知识库的向量存储中对它们进行索引，Amazon Bedrock 为托管知识库管理该向量存储。
- 您的生成式人工智能应用程序在知识库中查询相关块或生成的带有引文的响应。

该任务在启动时从 AWS Systems Manager Parameter Store 读取其非秘密管道配置。

该工作流仅处理公共页面，不实现经过身份验证的会话。对于需要登录的站点，请首先评估 [Amazon Bedrock Web Crawler 身份验证选项](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-management-ds-webcrawler.html)，其中包括基本身份验证、基于表单的身份验证和 SAML 身份验证。使用身份验证扩展示例需要会话处理、AWS Secrets Manager 中的凭证以及安全审查。

## 工作流程如何运作

AWS 云开发工具包 (AWS CDK) 应用程序在部署期间将实施打包在容器映像中。当计划触发时，容器运行“scripts/container_entrypoint.py”并按顺序执行爬网、上传和摄取。下面三个步骤解释了核心逻辑。

### 第 1 步：抓取并提取内容

爬网步骤执行有界爬网，并为每个成功准备的页面写入带有元数据 sidecar 的 Markdown 文件。以下摘录经过简化。模块 `src/crawl4ai_bedrock_kb/crawl.py` 包含完整的种子节奏、URL 过滤和范围、页面限制和重定向检查：
```
async def crawl_and_prepare(config: PipelineConfig, output_dir: str) -> list[str]:
    written, seen = [], set()
    pages_crawled = 0
    browser_config = BrowserConfig(headless=True, java_script_enabled=True)

    async with AsyncWebCrawler(config=browser_config) as crawler:
        for seed in config.seed_urls:
            remaining = config.crawl.max_pages - pages_crawled
            if remaining <= 0:
                break

            strategy = BFSDeepCrawlStrategy(
                max_depth=config.crawl.max_depth,
                max_pages=remaining,
                filter_chain=FilterChain([
                    SeedScopeFilter(seed, config.crawl.scope),
                    # Optional include/exclude URLPatternFilter objects are added here.
                ]),
            )
            run_config = CrawlerRunConfig(
                deep_crawl_strategy=strategy,
                markdown_generator=DefaultMarkdownGenerator(
                    content_filter=PruningContentFilter()
                ),
                css_selector=config.crawl.css_selector,  # Optional page region.
                check_robots_txt=config.crawl.check_robots_txt,
                mean_delay=config.crawl.request_delay_seconds,
                max_range=0,
                semaphore_count=1,
            )

            results = await crawler.arun(url=seed, config=run_config)
            for result in results:
                if pages_crawled >= config.crawl.max_pages:
                    break
                pages_crawled += 1
                requested_url = result.url
                source_url = getattr(result, "redirected_url", None) or requested_url
                if not SeedScopeFilter(seed, config.crawl.scope).apply(source_url):
                    continue  # Recheck the effective destination after redirects.
                canonical = _canonical_url(source_url)
                if canonical in seen:
                    continue
                seen.add(canonical)
                if not result.success or not result.markdown:
                    continue

                md_result = result.markdown
                markdown = (
                    getattr(md_result, "fit_markdown", None)
                    or getattr(md_result, "raw_markdown", None)
                    or (md_result if isinstance(md_result, str) else "")
                )
                if not markdown:
                    continue

                # The complete implementation adds title, crawl timestamps, content
                # type, and configured custom attributes to this metadata.
                written.extend(
                    _write_document(
                        output_dir,
                        _base_name(source_url),
                        markdown,
                        {"source_url": source_url},
                    )
                )
    return written
```
Amazon Bedrock 知识库支持 Amazon S3 数据源的[多种文档格式](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-ds.html)，包括纯文本、HTML、Markdown、PDF 和 DOCX。该工作流程编写 Markdown 是因为它保留了标题、列表和表格，而无需将所有原始 HTML 引入到摄取中。

### 第 2 步：上传到 Amazon S3

上传步骤将每个准备好的 Markdown 文档及其匹配的元数据 sidecar 发送到工作流程的“s3Prefix”下配置的 S3 存储桶。对于“page.md”，sidecar 必须命名为“page.md.metadata.json”，即附加“.metadata.json”的完整源文件名。该工作流程将每个 sidecar 存储在与其文档相同的 S3 位置。 Amazon Bedrock 将每个元数据 sidecar 限制为 10 KB。如果 sidecar 超出该限制，则运行会在写入任一文件之前停止并出现错误。

sidecar 中的每个属性都使用托管知识库和客户管理知识库都接受 Amazon S3 数据源的类型化格式。以下缩写的 sidecar（为了便于阅读而进行了格式化）显示了工作流写入的三个属性：
```
{
  "metadataAttributes": {
    "source_url": {
      "value": {"type": "STRING", "stringValue": "https://www.example.com/services/permits"}
    },
    "crawled_at_epoch": {
      "value": {"type": "NUMBER", "numberValue": 1790640000}
    },
    "content_category": {
      "value": {"type": "STRING", "stringValue": "web"}
    }
  }
}
```
管道仅上传当前爬网生成的路径，因此不会发送过时的本地文件。

### 步骤 3：让 Amazon Bedrock 知识库进行分块、嵌入和索引

内容进入 S3 后，摄取作业将每个文档交给数据源的摄取管道。默认情况下，托管知识库使用其托管解析器解析每个文件，该解析器会自动为您的内容选择解析方法。您在连接数据源时选择分块策略。您之后无法更改它，因此请在创建生产数据源之前评估选项。托管知识库提供以下分块策略：

- **默认分块**使用 300 个标记的固定大小块，重叠率为 20%。
- **固定大小分块**按照最大标记计数和您设置的重叠百分比来拆分内容。
- **无分块**将每个文件视为单个块，对于您已分割的内容。

块边界和检索结果取决于内容和所选策略，因此将选项与代表性页面和评估问题进行比较。要稍后更改策略，请创建新的数据源。有关更多信息，请参阅[自定义数据源的提取](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-management-customize-ingestion.html)。客户管理的知识库还提供语义和分层分块以及其他解析选项。有关详细信息，请参阅[内容分块如何适用于知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-chunking.html)。

然后，工作流程启动摄取作业，以便知识库处理新文档。以下来自“src/crawl4ai_bedrock_kb/ingest.py”的简化摘录显示了该调用：
```
def start_ingestion_job(config: PipelineConfig) -> str:
    # Start an Amazon Bedrock knowledge base ingestion job and return its ID.
    client = boto3.client("bedrock-agent", region_name=config.region)
    response = client.start_ingestion_job(
        knowledgeBaseId=config.knowledge_base_id,
        dataSourceId=config.data_source_id,
    )
    return response["ingestionJob"]["ingestionJobId"]
```
相同的“StartIngestionJob”和“GetIngestionJob”调用适用于两种知识库类型，您还可以在控制台上监控进度。

## 部署解决方案

在本部分中，您将使用 AWS CDK 将工作流程部署到您的 AWS 账户中。这两种知识库类型之间只有知识库先决条件不同。完成后，请按照清理部分中的步骤删除资源。

### 先决条件

在开始之前，请确保您拥有：

- AWS 账户。
- 以下知识库之一：**托管知识库**，本文使用的托管知识库位于[可用托管知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-management-regions.html) 的 AWS 区域。有关说明，请参阅[创建托管知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-management-create.html) 和 [Amazon S3 连接器](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-management-ds-s3.html)。在数据源上，将**元数据文件前缀**留空，因为工作流将每个元数据 sidecar 与其文档一起写入。 **现有客户管理的知识库。** 要添加 Amazon S3 数据源，请参阅[连接到您的知识库的 Amazon S3](https://docs.aws.amazon.com/bedrock/latest/userguide/s3-data-source-connector.html)。该工作流程为每个文档编写一个元数据 sidecar，因此请确认您的矢量存储可以存储和过滤这些属性，如[元数据和过滤](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-config.html)中所述。例如，Amazon OpenSearch Serverless 矢量索引必须使用“faiss”引擎。 Amazon Aurora 矢量索引需要自定义元数据列或每个元数据属性的列。借助 Amazon S3 矢量（Amazon S3 的一项功能），您可以将最多 1 KB 的自定义元数据附加到每个矢量，因此请保持您添加的属性简短。
- 该知识库中状态为“可用”的 Amazon S3 数据源。它可以是新的数据源，也可以是您已经使用的数据源。它必须使用您为此工作流程配置的 S3 存储桶。如果数据源按前缀或文件模式过滤内容，则过滤器必须允许工作流在其“s3Prefix”（默认“web-content/”）下写入的文件。
- 知识库、S3 存储桶和您在一个区域中部署的堆栈。
- 授权抓取您配置的公共网站。
- 部署工作站，配备 Git、Python 3.10 或更高版本、Node.js、AWS 命令​​行界面 (AWS CLI) 版本 2、AWS CDK CLI v2 以及正在运行的 Docker 兼容容器引擎。 [部署指南](https://github.com/aws-samples/sample-crawl4ai-bedrock-knowledge-base/blob/main/deploy/README.md)列出了最低 AWS CDK CLI 版本。
- 在部署工作站上配置的 AWS 凭证，有权引导目标环境并部署 CDK 堆栈。
- 目标账户和区域中的引导 CDK 环境。部署步骤包括 bootstrap 命令。

您仅需要工作站来构建和部署。部署后，计划在 AWS 中运行任务。

### 部署预定的工作流程

克隆配套存储库并安装部署依赖项：
```
git clone https://github.com/aws-samples/sample-crawl4ai-bedrock-knowledge-base.git
cd sample-crawl4ai-bedrock-knowledge-base/deploy
python -m venv .venv
source .venv/bin/activate  # Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```
保持 Docker 运行。首先将“AWS_DEFAULT_REGION”设置为您的知识库的区域，因为“cdk部署”使用您的环境或AWS配置文件中的区域，而不是引导命令中的区域。如果需要，引导一次目标账户和区域。然后使用您的知识库、数据源、S3 存储桶和授权种子 URL 部署堆栈：
```
export AWS_DEFAULT_REGION=REGION  # Windows PowerShell: $env:AWS_DEFAULT_REGION = "REGION"
cdk bootstrap aws://ACCOUNT_ID/REGION

cdk deploy \
  -c knowledgeBaseId=ABCDEFGHIJ \
  -c dataSourceId=KLMNOPQRST \
  -c s3Bucket=amzn-s3-demo-bucket \
  -c 'seedUrls=["https://www.example.com/services"]' \
  -c maxDepth=1 \
  -c maxPages=25
```
将每个示例值（包括“ACCOUNT_ID”、“REGION”和四个必需的上下文键）替换为您自己的值。示例值在语法上是有效的，因此未经编辑的命令会部署一个指向您不拥有的存储桶的堆栈。您还可以在“cdk.json”中设置这些键。

`maxDepth` 和 `maxPages` 值将第一次爬网限制为一个链接级别和 25 个页面。在检查准备好的输出后提高它们。要预览爬网准备的页面，您还可以使用“--dry-run”在本地运行管道，如 [README](https://github.com/aws-samples/sample-crawl4ai-bedrock-knowledge-base#quick-start) 中所述。堆栈名称是固定的，因此同一帐户和区域中的另一个“cdk部署”会更新此堆栈。

该示例默认构建 ARM64 容器映像。如果 x86_64 工作站上的 Docker 无法构建 ARM64 映像，请将“-c cpuArchitecture=X86_64”添加到“cdk deploy”命令中。

如果您的账户开启了 VPC 阻止公共访问，则任务无法从默认公共子网访问 Internet。要检查模式，请运行“aws ec2 describe-vpc-block-public-access-options”。在仅入口模式下，使用“-c egressMode=nat”进行部署，这会添加按小时收费的 NAT 网关。双向模式也需要排除，如部署指南所述。

该堆栈不会创建或更改您的知识库或数据源。

使用默认的“速率（24 小时）”计划，首次运行将在部署创建 Amazon EventBridge 规则时开始。要跟踪该运行，请使用“TailLogsCommand”输出中的命令，“cdk deploy”完成时将打印该命令。成功运行会记录“job_status: COMPLETE”。要在计划之外启动另一次运行，请在当前运行完成后使用“RunTaskCommand”输出中的命令。要稍后列出输出，请运行“aws cloudformation describe-stacks --stack-name Crawl4aiBedrockKbCrawler --region REGION --query "Stacks[0].Outputs"”。

[部署指南](https://github.com/aws-samples/sample-crawl4ai-bedrock-knowledge-base/blob/main/deploy/README.md)涵盖了其余配置，包括爬网边界、计划、网络、容器架构、监控和按需运行。

## 验证检索质量

摄取后，在添加生成之前使用“检索”测试代表性问题。托管知识库使用混合搜索。当它使用默认的托管嵌入模型时，它还会使用其托管重新排序器对结果进行重新排序。您可以使用 sidecar 中的元数据来缩小结果范围。该示例的默认配置将设置为“web”的“content_category”添加到每个页面。以下示例从过去 7 天内爬网的页面中返回最多 5 个块。它需要适用于 Python (Boto3) 1.43.32 或更高版本的 AWS 开发工具包，您可以使用“python -m pip install "boto3>=1.43.32"”进行安装。将区域和知识库 ID 替换为您自己的值：
```
import time

import boto3

client = boto3.client("bedrock-agent-runtime", region_name="us-east-1")
week_ago = int(time.time()) - 7 * 24 * 60 * 60

response = client.retrieve(
    knowledgeBaseId="ABCDEFGHIJ",
    retrievalQuery={"text": "How do I apply for a building permit?"},
    retrievalConfiguration={
        "managedSearchConfiguration": {
            "numberOfResults": 5,
            "filter": {
                "andAll": [
                    {"equals": {"key": "content_category", "value": "web"}},
                    {"greaterThan": {"key": "crawled_at_epoch", "value": week_ago}},
                ]
            },
        }
    },
)

for result in response["retrievalResults"]:
    print(result.get("metadata", {}).get("source_url"), result["content"]["text"][:200])
```
该示例传递一个整数时间戳，两种知识库类型都在数字过滤器中接受该整数时间戳。托管知识库不支持“startsWith”和“stringContains”过滤器。对于客户管理的知识库，请在“vectorSearchConfiguration”而不是“drivenSearchConfiguration”中传递相同的过滤器。它支持的运算符取决于其向量存储。

元数据过滤可以提高检索精度，但不是授权边界。如果不同的用户应该看到不同的页面，则托管知识库的 Amazon S3 连接器支持使用您提供的访问控制列表 (ACL) 文件进行文档级访问控制。该示例不创建 ACL 文件。

要从托管知识库生成响应，请使用[代理检索](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-test-agentic-retrieve.html)。 “AgenticRetrieveStream”操作返回检索到的结果以及生成的响应以及对这些结果的引用。对于客户管理的知识库，请使用“RetrieveAndGenerate”。在这两种情况下，每个引用的结果都包含来自其 sidecar 的“source_url”元数据，您的应用程序可以将其呈现为面向用户的源。

每当您更改内容准备、分块或检索设置时，都要评估检索相关性、源页面覆盖率和引文质量。有关可以调整的检索设置，请参阅[配置和自定义托管知识库的查询](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-management-test-config.html)。

## 重复运行

每个计划的事件都会启动一个独立的 Fargate 任务。堆栈不会阻止重叠运行，因此请选择比预期抓取和摄取持续时间更长的间隔。不会宣布失败的运行，因为该示例未添加重试策略、死信队列或警报。当某些文档无法摄取时，摄取作业还可以报告“COMPLETE”，然后任务以代码 0 退出。该任务会记录作业的失败原因。在您依赖计划之前，添加您需要的监控，包括针对这些故障原因发出警报。

每次运行都会根据配置的任务大小（默认为 2 vCPU 和 4 GB）产生 Fargate 费用。该任务在轮询摄取作业时保持运行长达 30 分钟，因此缓慢的摄取作业会延长计费任务时间。如果摄取时间较长，任务会以非零代码退出，并且摄取作业将继续运行。该堆栈打开集群的 Container Insights 以及它创建的 Amazon Virtual Private Cloud (Amazon VPC) 的流日志。两者都会增加 Amazon CloudWatch 费用。堆栈的 AWS KMS 密钥按月收费，并且任务的公共 IPv4 地址在任务运行时计费。使用“egressMode=nat”或“privateEndpoints=true”，NAT 网关和接口端点按小时计费，即使没有任务运行也是如此。知识库的使用单独计费。有关详细信息，请参阅 [Amazon VPC 定价](https://aws.amazon.com/vpc/pricing/) 和 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。

上传是附加的：在以后的抓取过程中删除 URL 或丢失页面不会删除其现有的 S3 对象。要删除陈旧内容，请删除已配置前缀下的过时文档和匹配的 sidecar，然后再次开始提取。如果您为托管知识库数据源打开文档删除保护（删除保护），请检查其阈值。删除超过该百分比的文档的同步会跳过其删除阶段，因此这些文档会保留索引。要在存储桶中的对象发生更改时自动开始提取，请参阅[为 Amazon Bedrock 知识库构建和部署自动同步解决方案](https://aws.amazon.com/blogs/machine-learning/build-and-deploy-an-automatic-sync-solution-for-amazon-bedrock-knowledge-bases/)。

## 负责任的人工智能考虑因素

检索到的段落成为基础模型用来生成响应的上下文。在生产中运行此工作流程之前应用以下控制：

- **Amazon Bedrock Guardrails**：将 [guardrail](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html) 附加到您的代理检索或“RetrieveAndGenerate”请求，以应用内容过滤器、拒绝的主题、单词过滤器和敏感信息过滤器。代理检索仅支持护栏“BLOCK”操作，不支持“MASK”。
- **上下文接地检查**：打开 Guardrails [上下文接地检查](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-contextual-grounding-check.html)，根据检索到的段落的接地情况以及与查询的相关性对每个响应进行评分。护栏会阻止分数低于您设置的阈值的响应。对于代理检索，您可以使用“ApplyGuardrail” API 对生成的答案运行检查。该检查支持问题回答和总结，而不是对话式聊天机器人用例。
- **将爬网内容视为不可信输入**：准备好的网页成为模型上下文，因此公共页面上的文本可以通过检索尝试提示注入。不要仅依靠护栏来抓住它。将种子 URL 限制为您信任的站点，并在内容到达知识库之前应用下一节中描述的摄取过滤模式。
- **引文和人工审核**：在每个生成的响应中返回引文，以便用户可以根据源页面验证声明。对于风险较高的用例，请让人工审核员随时了解情况。

## 安全性和合规性考虑

在针对生产内容运行此工作流程之前，请查看以下注意事项：

- **使用受信任的公共爬网目标**：种子 URL 和爬网设置是部署配置，Fargate 任务允许出站访问，以便它可以到达公共网站。在示例的默认网络模式下，任务在具有公共 IP 的公共子网中运行。仅配置授权的公共站点。请勿使用此示例来爬网私有或内部端点。在针对其他信任模型调整工作流程之前，请检查网络出口和目的地控制。
- **尊重抓取指令**：工作流程默认打开 Crawl4AI 的“robots.txt”检查，并且 CDK 路径将其固定，没有上下文键来禁用它。验证您是否有权抓取目标网站，且符合 [AWS 可接受使用政策](https://aws.amazon.com/aup/)。
- **速率限制**：配置请求之间的延迟，以避免源网站不堪重负。
- **静态加密**：堆栈创建具有自动密钥轮换功能的 AWS Key Management Service (AWS KMS) 客户托管密钥，并用它加密其 CloudWatch 日志组。默认情况下，Amazon S3 使用 Amazon S3 托管密钥 (SSE-S3) 进行服务器端加密来加密新对象。如果您的数据分类需要存储桶的客户管理密钥，请配置存储桶以使用它。然后在 AWS Identity and Access Management (IAM) 和密钥策略中向上传者和知识库服务角色授予所需的 AWS KMS 权限。堆栈的任务角色不包括 AWS KMS 权限。默认情况下，托管知识库使用 AWS 拥有的密钥或您在创建知识库时指定的客户托管密钥对其数据进行加密。对于客户管理的知识库，请检查其矢量存储的加密。
- **最低权限 IAM**：CDK 堆栈在配置的存储桶前缀上授予 Fargate 任务角色“s3:PutObject”。它还在目标知识库上授予“bedrock:StartIngestionJob”和“bedrock:GetIngestionJob”，以及其单个配置参数的“ssm:GetParameter”。单独的角色涵盖 Amazon EventBridge 任务启动以及标准容器映像拉取和日志传输。管道不会读取或列出 S3，也不会调用“InvokeModel”或“Retrieve”。
- **容器和模板检查**：容器以非 root 用户身份运行，CDK 应用程序通过资源范围的抑制对每个合成运行 cdk-nag AWS 解决方案检查。
- **保护部署配置**：CDK 应用程序将非秘密管道设置存储在纯文本 Parameter Store“String”参数中。仅参数名称放置在任务定义中。不要将密码、cookie、令牌或其他机密放入 CDK 上下文或此参数中。
- **摄取管道安全性**：请参阅[保护 RAG 摄取管道：过滤机制](https://aws.amazon.com/blogs/security/securing-the-rag-ingestion-pipeline-filtering-mechanisms/)，了解在内容到达知识库之前要应用的过滤和验证模式。

## 清理

为了避免持续产生费用，请删除本演练期间创建的资源：

- 从存储库的“deploy/”目录中，在同一区域中运行“cdk destroy”，并使用传递给“cdk deploy”的四个必需“-c”值。该应用程序会在每个命令上检查它们。这将删除堆栈的 Amazon EventBridge 规则、ECS 集群、任务定义、日志组、IAM 角色、Parameter Store 参数和安全组以及 VPC（如果堆栈创建了它）。它还安排堆栈的 AWS KMS 密钥在 30 天的等待期后删除。它不会删除导入的 VPC、您的知识库、S3 存储桶或工作流程上传的对象。 CDK 还将容器映像和模板保留在其引导资源中。它还保留集群的 Container Insights 日志组，其名称以“/aws/ecs/containerinsights/Crawl4aiBedrockKbCrawler-”开头。
- 要删除提取的 Web 内容，请删除 `s3://<bucket>/<prefix>` 下准备好的对象，然后再次同步数据源。如果托管知识库数据源启用了文档删除保护措施，则删除超过其阈值百分比的文档的同步将跳过其删除阶段。
- 仅当您仅为本演练创建托管知识库时才将其删除。托管知识库没有单独的矢量存储可供删除。
- 对于客户管理的知识库，仅删除您为本演练创建的 Amazon S3 数据源。其数据删除策略决定 Amazon Bedrock 是否也从矢量存储中删除数据源的矢量嵌入。

## 结论

在本文中，您了解了如何将 Amazon Bedrock 知识库扩展到需要在摄取前进行准备的授权公共 Web 内容。计划的 Fargate 任务使用 Crawl4AI 进行有界爬行，使用“page.md.metadata.json” sidecar 准备 Markdown，将它们上传到 Amazon S3 数据源，然后开始摄取。然后，知识库处理解析、分块、嵌入、索引、检索和引用的基础响应。

从大多数公共网站的托管知识库中的 Amazon Bedrock Web Crawler 开始。当您需要控制每个页面的哪些部分被索引或哪些元数据随页面传输时，请使用 Crawl4AI 路径。首先，从配套的 [sample-crawl4ai-bedrock-knowledge-base](https://github.com/aws-samples/sample-crawl4ai-bedrock-knowledge-base) 存储库部署预定的 Fargate 工作流程，然后在扩展之前使用代表性内容验证检索质量和引用。
