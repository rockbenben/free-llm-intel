# 使用 Amazon Nova 为生成式 AI 构建数据一致性的 Text-to-SQL 方案

企业依赖精确、实时的洞察来做出关键决策。然而，让非技术用户在没有技术专长的情况下访问专有数据或组织内部数据，依然是一大挑战。Text-to-SQL 通过生成精确的、与 schema 相关的查询来弥合这一差距，从而支持更快的决策并培育数据驱动的文化。真正的难点在于从专有数据或组织内部数据中得到确定性的答案——也就是生成精确计数或详细报告这类操作所需的精确、一致的结果。生成式 AI 提供了多种查询数据的方法，但选对方法对于实现准确性与可靠性至关重要。

本文评估使用生成式 AI 查询数据的主要方案，讨论各自的优势与局限，并说明为什么 Text-to-SQL 是确定性、与 schema 相关任务的最佳选择。我们演示如何有效地使用 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/)——一款可通过 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 使用的基础模型（FM）——来从数据中获得精确而可靠的答案。

## 查询数据的可选方案

组织在查询数据方面有多种选择，具体取决于数据的性质与期望的结果。本节评估以下方法，以明确各自的适用场景，以及为什么 Text-to-SQL 对确定性的、基于 schema 的任务最为理想：

- **Retrieval Augmented Generation（RAG）：**  **用例 **– 适合从文档或文章这类非结构化或半结构化来源中提取洞察。**优势 **– 能处理多种数据格式，并给出叙述式响应。**局限 **– 概率性答案可能各不相同，因此不适合确定性查询，例如获取精确计数或匹配特定 schema 约束。**示例 **– “总结产品评论中的反馈。”
- **生成式商业智能（BI）：**  **用例 **– 适合基于结构化与非结构化数据产出高层次洞察与摘要。**优势 **– 为决策与趋势提供叙述式洞察。**局限 **– 缺少与 schema 相关的查询或运营查询所需的精确性，结果在措辞与关注点上往往会有差异。**示例 **– “上季度销售增长的关键驱动因素是什么？”
- **Text-to-SQL：**  **用例 **– 擅长直接从关系型 schema 查询结构化的组织数据。**优势 **– 针对特定的、依赖 schema 的查询给出确定性、可复现的结果，非常适合过滤、计数或聚合数据这类精确操作。**局限 **– 需要结构化数据与预定义 schema。**示例 **– “上个月纽约市有多少确诊糖尿病的患者到访了诊所？”

在要求精确性与一致性的场景中，Text-to-SQL 凭借准确的、由 schema 驱动的结果胜过 RAG 与生成式 BI。这些特性使它成为运营查询与结构化数据查询的理想方案。

## 解决方案概览

本方案使用 Amazon Nova Lite 与 Amazon Nova Pro 大语言模型（LLM）来简化用自然语言查询专有数据的过程，使非技术用户也能使用。

Amazon Bedrock 是一项全托管服务，通过单一 API 提供对领先 FM 的访问，从而简化生成式 AI 应用的构建与扩展。它让开发者能够安全、私密地试验并定制这些模型，把生成式 AI 能力集成到应用中，而无需自行管理基础设施。

在该体系中，Amazon Nova 代表新一代 FM，带来更强的智能与业界领先的性价比。包括 Amazon Nova Lite 与 Amazon Nova Pro 在内的这些模型旨在处理文本、图像与视频理解等多种任务，因而成为适用于各类应用的多面工具。

部署代码与详细说明可在我们的 [GitHub 仓库](https://github.com/aws-samples/sample-data-consistency-with-genai-text-to-sql-amazon-nova) 中找到。

该方案包含以下关键特性：

- **动态 schema 上下文 **– 动态获取数据库 schema，以生成精确的查询
- **SQL 查询生成 **– 使用 Amazon Nova Pro LLM 把自然语言转换为 SQL 查询
- **查询执行 **– 在组织数据库中运行查询并获取结果
- **格式化响应 **– 使用 Amazon Nova Lite LLM 把原始查询结果处理为易读的格式

本方案中，我们使用 Amazon Nova Pro 与 Amazon Nova Lite，发挥各自所长，让每个阶段都能高效、有效地处理：

- **动态 schema 获取与 SQL 查询生成** – 我们使用 Amazon Nova Pro 把自然语言输入转换为 SQL 查询。它在复杂推理与理解方面的先进能力，使其非常适合准确解读用户意图并生成精确的 SQL 语句。
- **格式化响应生成** – 在运行 SQL 查询之后，原始结果会交由 Amazon Nova Lite 处理。该模型能高效地把数据格式化为易读的输出，使信息对非技术用户也可访问。它的速度与成本效益在这个阶段很有优势，因为这一阶段的关键在于快速处理与简明呈现。

通过以这种方式有策略地部署 Amazon Nova Pro 与 Amazon Nova Lite，该方案确保每个组件都能以最优状态运行，在性能、准确性与成本效益之间取得平衡。

## 代码执行流程

本节我们来看代码执行流程。代码参考自 [GitHub 仓库](https://github.com/aws-samples/sample-data-consistency-with-genai-text-to-sql-amazon-nova)。请勿单独运行代码中的各个部分。

### 动态获取 schema

使用 `INFORMATION_SCHEMA` 视图动态提取 schema 细节（代码参考自 `app.py`）：

```
def get_schema_context(db_name, db_view_name):
    conn = connect_to_db()
    cursor = conn.cursor()
    cursor.execute(f"USE {db_name}")
    query = f"SELECT COLUMN_NAME, DATA_TYPE FROM INFORMATION_SCHEMA.COLUMNS WHERE TABLE_NAME = '{db_view_name}'"
    cursor.execute(query)
    schema = cursor.fetchall()
    print("Schema:", schema)
    return '\n'.join([f"- {row[0]}: {row[1]}" for row in schema])
```

动态 schema 获取通过查询元数据表来获得更新后的 schema 细节（例如表名与列类型），从而自动适应变化。这让 schema 更新能够无缝融入 Text-to-SQL 系统，减少人工投入并提升可扩展性。

请测试该函数，以验证 schema 发生变化时它能自动适应。

在生成 SQL 之前，先获取相关表的 schema 细节，以便准确地构造查询。

### 使用 Amazon Nova Pro 生成 SQL 查询

把用户查询与 schema 上下文发送给 Amazon Nova Pro（代码参考自 `sql_generator.py`）：

```
def generate_sql_query(question: str, schema_context: str, db_name: str, db_view_name: str = None) -> str:
    
    nova_client = NovaClient()
       
    # Base prompt with SQL generation rules
    base_prompt = """
    MS SQL DB {db_name} has one view names '{db_view_name}'. 
    Always use '{db_view_name}' as table name to generate your query.
    Create a MS SQL query by carefully understanding the question and generate the query between tags <begin sql> and </end sql>.
    The MS SQL query should selects all columns from a view named '{db_view_name}'
    In your SQL query always use like condition in where clasue.
    if a question is asked about product stock then always use 'distinct' in your SQL query.
    Never Generate an SQL query which gives error upon execution.
      
    
    Question: {question}
    
    Database Schema : {schema_context}
    
    Generate SQL query:
    """
    
    # Format the prompt with the question and schema context
    formatted_prompt = base_prompt.format(
        question=question,
        db_name=db_name,
        db_view_name=db_view_name if db_view_name else "No view name provided",
        schema_context=schema_context if schema_context else "No additional context provided"
    )
        
    # Invoke Nova model
    response = nova_client.invoke_model(
        model_id='amazon.nova-pro-v1:0',
        prompt=formatted_prompt,
        temperature=0.1  # Lower temperature for more deterministic SQL generation
    )
    
    # Extract SQL query from response using regex
    sql_match = extract_sql_from_nova_response(response)
    if sql_match:
        return sql_match
    else:
        raise ValueError("No SQL query found in the response")
    
def extract_sql_from_nova_response(response):
    try:
        # Navigate the nested dictionary structure
        content = response['output']['message']['content']
        # Get the text from the first content item
        text = content[0]['text']
        
        # Find the positions of begin and end tags
        begin_tag = "<begin sql>"
        end_tag = "</end sql>"
        start_pos = text.find(begin_tag)
        end_pos = text.find(end_tag)
        
        # If both tags are found, extract the SQL between them
        if start_pos != -1 and end_pos != -1:
            # Add length of begin tag to start position to skip the tag itself
            sql_query = text[start_pos + len(begin_tag):end_pos].strip()
            return sql_query
            
        return None
        
    except (KeyError, IndexError):
        # Return None if the expected structure is not found
        return None
```

这段代码为 text-to-SQL 用例建立了结构化的上下文，引导 Amazon Nova Pro 基于预定义的数据库 schema 生成 SQL 查询。它通过定义静态的数据库上下文来保证一致性：明确表名、列与关系，有助于避免查询构造中的歧义。查询必须引用 `vw_sales` 视图，从而使分析报表的数据提取保持统一。此外，在适用的情况下，生成的查询必须包含与数量相关的字段，以确保业务用户能得到关于产品销售、库存水平或交易计数的关键洞察。为增强搜索灵活性，LLM 被要求使用 LIKE 运算符，而不是在 WHERE 条件中进行精确匹配，从而支持部分匹配并兼容用户输入的差异。通过施加这些约束，这段代码优化了 Text-to-SQL 的交互，为销售数据分析提供结构化、相关且贴合业务需求的查询生成。

### 使用 Amazon Nova Lite 格式化查询结果

把 SQL 查询得到的数据库结果发送给 Amazon Nova Lite，将其格式化为易读的形式，并打印在 Streamlit UI 上（代码参考自 `app.py`）：

```
def interact_with_nova(user_input, llm_query, query_response, model="nova"):
    session = boto3.session.Session()
    region = session.region_name
    
    nova_client = NovaClient(region_name=region)
    
    final_prompt = f"""Human: You are a expert chatbot who is happy to assist the users. User questions in given in <Question> tag and results in <query_response> tag. Understand the question and use information from <query_response> to generate an answer. If there are more than one entery, give a numbered list. Never retrun <question> and <query_response> in your response.
    for example : question - "How many mouse were sold?"
                  llm response : 
                                " There were 3 mouse sold in total. 
                                - 1 mouse sold to Mia Perez on October 2nd, 2023. 
                                - 2 mouse sold to Jack Hernandez on October 1st 2023."
    <Question>
    {user_input}
    </Question>
    <query_response>
    {query_response}
    </query_response>"""
    
    try:
        
            response = nova_client.invoke_model(
                model_id='amazon.nova-lite-v1:0',
                prompt=final_prompt,
                max_tokens=4096,
                temperature=0.7
            )
            
            content = response['output']['message']['content']
            text = content[0]['text']
            return text
            
            return "Sorry, I couldn't process your request."
    
    except Exception as e:
        print(f"Error in LLM interaction: {str(e)}")
        return "Sorry, an error occurred while processing your request."
```
