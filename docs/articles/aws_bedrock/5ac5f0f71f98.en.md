# How LoanPro built an agentic AI loan servicing assistant with Amazon Bedrock AgentCore

*This post is co-written with Mariah Miller from AWS and Colin Terry from LoanPro*

Have you ever wondered what the experience is like for the person on the other end of the phone when you call your bank for support? When a borrower calls a lender, the answering agent must pull account data from dozens of fields, transaction histories, and workflow queues to orient themselves before they can help the borrower. All the while, the clock runs. Assembling that context by hand means longer calls, inconsistent service quality, and agent frustration. A loan servicing assistant built on agentic AI changes that.

[LoanPro](https://www.loanpro.io/), the operating system for modern lenders, set out to change that. Working with AWS Partner [AllCloud](https://allcloud.io/) and the [AWS Generative AI Innovation Center](https://aws.amazon.com/ai/generative-ai/innovation-center/), LoanPro built a multi-agent AI assistant that gives servicing agents immediate access to synthesized borrower context and actionable next-step recommendations. Early results show customer call times reduced by up to 15 percent, according to AllCloud’s published case study.

In this post, we walk through the business challenge, the agentic AI architecture built on [Amazon Bedrock](https://aws.amazon.com/bedrock/) and [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/), and the outcomes LoanPro achieved. Amazon Bedrock is a fully managed service that offers a choice of high-performing foundation models from leading AI companies through a single API, along with the capabilities you need to build generative AI applications with security, privacy, and responsible AI.

## About LoanPro

LoanPro is a modern, API-first lending and credit platform that automates the entire loan lifecycle from origination to payoff. Founded in 2015, LoanPro serves as the system of record for lenders of every type: fintechs, banks and credit unions, and corporates that offer lending as a value-added service. According to LoanPro, the platform serves over 450 lenders, with loans managed on its platform reaching about 31 percent of US households. The platform powers loan management at enterprise scale across the financial services industry.

LoanPro isn’t a lender. It’s the operating system that lenders run on. That distinction matters because LoanPro’s AI strategy is designed to benefit the institutions it serves across the platform, not a single lending operation.

## The challenge

One of LoanPro’s core user groups is servicing agents: the people who manage borrower accounts, handle inbound calls, process payments, and resolve issues. During a live customer interaction, an agent might need to review:

- The borrower’s complete payment history, including missed and returned payments.
- Active loan terms, fees, and current balance.
- Prior interactions and open support tickets.
- Available workflow actions such as payment plans, deferrals, or escalations.

Before the AI assistant, agents navigated this information manually, moving through multiple screens and tabs to assemble the full picture. Less experienced agents took longer, and outcomes varied depending on who picked up the phone. LoanPro needed a solution that could:

- Instantly synthesize account data into a coherent summary.
- Recommend the right next action based on account context.
- Deliver more consistent servicing quality across agents of different experience levels.

## Solution overview

With the AWS Generative AI Innovation Center, LoanPro partnered with AllCloud to design and build a multi-agent AI assistant using [Amazon Bedrock](https://aws.amazon.com/bedrock/). The assistant runs on Anthropic’s [Claude Sonnet 5.5](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-sonnet-5-5.html), [Claude Haiku 5.5](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-haiku-5-5.html), and [Claude Opus 5.5](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-opus-5-5.html) on Amazon Bedrock (see [Models at a glance in Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards.html)). Model availability varies by AWS Region. For model availability by Region, refer to [Regional availability by models in Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html). It’s orchestrated with [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/), a platform to build, connect, and optimize agents at scale, with any framework or model. Agent logic is built with the [Strands Agents SDK](https://strandsagents.com/), an open source framework for building AI agents with tool use. The system coordinates specialized agents through a composer that routes each request to the right specialist, so each agent handles a focused task and can be evaluated and improved independently. The team chose these managed services over building the agent runtime and model access in-house. Amazon Bedrock provides access to leading foundation models through a single API, giving the team flexibility to adopt new models without managing separate endpoints. Amazon Bedrock AgentCore provides a managed agent runtime that removes the operational overhead of running agents in production.

Figure 1 shows this flow in implementation terms. A user request enters through LoanPro API v2 on [Amazon API Gateway](https://docs.aws.amazon.com/apigateway/). An [AWS Lambda](https://docs.aws.amazon.com/lambda/) handler places the request on an [Amazon Simple Queue Service (Amazon SQS)](https://docs.aws.amazon.com/sqs/) queue. The Agent Interceptor Lambda function then invokes the Loan Summary Agent. The agent runs on Amazon Bedrock AgentCore runtime, a capability of Amazon Bedrock AgentCore, and uses Anthropic’s Claude models on Amazon Bedrock. It reaches its tools through a [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) server on Amazon Bedrock AgentCore Gateway, a capability of Amazon Bedrock AgentCore. The gateway finds the right tool in a catalog that the Loan Summary Service registers in AWS Systems Manager [Parameter Store](https://docs.aws.amazon.com/systems-manager/latest/userguide/systems-manager-parameter-store.html). The Loan Summary Tool Lambda function validates the caller’s signature against LoanPro’s single sign-on (SSO) service. It then retrieves account data from LoanPro’s loan management system, which runs on [Amazon Elastic Compute Cloud (Amazon EC2)](https://docs.aws.amazon.com/ec2/) behind a [Network Load Balancer](https://docs.aws.amazon.com/elasticloadbalancing/latest/network/introduction.html). The system’s role-based access controls validate the same signature. LoanPro also checks each request against the user’s permissions and compliance controls, then writes the action to its audit trail. The sections that follow describe these pieces: the multi-agent system, the tools it calls, and the gateway.

The architecture has four key components, which combine the pieces in Figure 1 with the composer agent and Invoke API Tool that coordinate and act on them:

### Multi-agent architecture with Strands Agents SDK

The solution uses a multi-agent architecture built with the Strands Agents SDK. Rather than a single monolithic model handling every task, specialized agents collaborate to serve different parts of the servicing workflow. One agent focuses on data retrieval and account summarization. Another handles action selection and workflow recommendations. A composer agent routes each request to the right specialist and composes the final response. This separation of concerns makes each agent more straightforward to evaluate, tune, and extend independently.

### Tool use: Data Retrieval and Invoke API

The agents retrieve borrower data from LoanPro’s internal systems through **tool use**, a capability in Amazon Bedrock for calling external functions and APIs. Two primary tools power the assistant:

- **Data Retrieval Tool:** Fetches account details, payment histories, loan terms, and borrower metadata from LoanPro’s data layer, shown in Figure 1 as the Loan Summary Tool. It spans eight distinct API endpoints, synthesizing around 1,400 fields per account.
- **Invoke API Tool:** Triggers workflow actions within LoanPro’s platform, such as presenting informational panels to the agent or initiating a predefined automation sequence.

By connecting to LoanPro’s existing APIs, the assistant works with live production data without requiring a separate data pipeline or data warehouse.

### Amazon Bedrock AgentCore Gateway with AWS Lambda

AgentCore Gateway is the secure access layer between the agents and the tools they call. It exposes LoanPro’s APIs to the agents as tools over the Model Context Protocol (MCP), handles authentication, and manages those connections. [AWS Lambda](https://aws.amazon.com/lambda/), a serverless compute service that runs code without provisioning or managing servers, provides the integration layer between the gateway and LoanPro’s APIs. The team chose AgentCore Gateway with Lambda over a direct integration for three reasons. It centralizes authentication at a managed entry point, isolates LoanPro’s APIs behind a managed boundary, and lets new tools be added without redeploying the agents. This serverless approach keeps the infrastructure lightweight and scales automatically with request volume. In Figure 1, the Agent Interceptor (an AWS Lambda function) invokes the agent on AgentCore runtime. AgentCore Gateway enforces this access control, screening each request before it reaches the Loan Summary Tool. Because the assistant operates in a regulated lending context, the production deployment pairs these components with additional controls. LoanPro’s role-based access controls and compliance guardrails apply to each request, and AI actions are written to LoanPro’s audit trail and attributed to a named, responsible person.

### Integration into LoanPro’s existing web portal

The assistant is embedded directly into LoanPro’s existing web portal, the same interface servicing agents already use. Agents interact with the AI assistant through two components:

- **Account summary view:** When an agent opens a borrower account, the assistant automatically generates a narrative summary of the account’s health, recent activity, and outstanding issues. Raw data becomes a coherent story about the borrower’s situation.
- **Conversational chat interface:** Agents can ask follow-up questions in natural language to dig deeper into specific account details. The team describes this as allowing agents to “talk to the loan.” Every agent interaction with the chat interface is logged, maintaining an auditable record of actions taken during a borrower conversation.

## Implementation approach

LoanPro built the assistant with the [AWS Generative AI Innovation Center](https://aws.amazon.com/ai/generative-ai/innovation-center/), which pairs AWS applied scientists with customers and partners to accelerate generative AI initiatives, and AllCloud, an AWS Premier Consulting Partner. The three teams designed and built the solution together. What began as a focused engagement now runs in production, serving LoanPro’s servicing agents.

The work was organized into two parallel workstreams:

### Workstream 1: Servicing agent assistant

The primary workstream built the AI assistant that is now running in production. Key activities included:

- Selecting and mapping the data sources (application data, loan histories, borrower records) the agent would need to retrieve.
- Developing agent functionality for autonomous data retrieval and intelligent action selection.
- Iterating on prompts to improve retrieval accuracy and output quality.
- Documenting LoanPro’s security model and integration patterns to inform the production roadmap.

### Workstream 2: LLM account rule automation advisory

LoanPro had an existing proof of concept (POC) that used a large language model (LLM) to convert natural language into rule automation code for their Clojure rules engine. The core functionality worked, but the solution had known limitations: frequent timeouts, no monitoring, and no deployment strategy. AllCloud conducted architectural reviews and provided recommendations to bring this existing POC to a production-ready state, including a documented production architecture and risk assessment.

## Evaluation pipeline

A structured evaluation pipeline validated agent accuracy against benchmarks established by LoanPro’s subject-matter experts (SMEs). The team assembled a benchmark of 150 SME-labeled accounts. Against that benchmark, they measured the agent’s ability to retrieve data, summarize findings, and select appropriate actions, holding it to a 99 percent accuracy target that the agent met. This framework carries forward into production, giving LoanPro a repeatable process for measuring and improving agent performance over time.

## Results

Deploying the AI assistant delivered measurable operational impact:

- **Up to 15 percent reduction in customer call times** (source: AllCloud case study). Across over 800 servicing professionals at LoanPro’s early launch lender partners, agents previously spent 18–20 percent of every call (1–2.5 minutes across 5–7 clicks) orienting to accounts. The AI assistant consolidates that context into a single click, saving 1 to nearly 2 minutes per call. Across those agents, that reclaims up to 9 minutes per operating hour per agent, roughly 120 hours of agent capacity every operating hour.
- **Decreased internal ticket volumes by nearly 8 percent** (source: LoanPro). Lenders on the platform report fewer support escalations as agents resolve more cases during the initial call.
- **Account summaries in under 15 seconds** (source: LoanPro internal benchmarks). The narrative summary transforms raw borrower data into a coherent account story within 15 seconds of opening an account, replacing what previously took agents 3–5 minutes of manual navigation.
- **Consistent servicing quality**. The assistant provides the same level of account context and action recommendations to agents across the platform, reducing variability tied to individual experience levels.
- **Compliance-aligned interaction logging**. Every action and query the agent makes through the AI assistant is logged, providing an auditable record of interactions during borrower conversations.
- **Responsible AI controls**. [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) apply content filtering and grounding validation to agent responses alongside LoanPro’s compliance guardrails and role-based access controls (RBAC), keeping outputs within policy before they reach a servicing agent and the borrower.

That time savings compounds across thousands of calls.”

## Looking ahead

Building on the success of the servicing agent assistant, LoanPro and AllCloud are expanding their collaboration. The teams are developing additional AI agents to extend intelligent capabilities across more parts of the lending workflow, moving beyond servicing into areas such as collections and origination support.

The modular, multi-agent architecture makes this expansion practical. New agents can be built and deployed independently using the same Amazon Bedrock AgentCore infrastructure, without redesigning the core system. As the Strands Agents SDK and Amazon Bedrock AgentCore continue to evolve, LoanPro plans to incorporate new capabilities as they become available.
