# New Relic 用 AWS 上的生成式 AI 变革生产力

[New Relic Inc.](https://newrelic.com/) 是一家总部位于旧金山的技术公司，开创了应用性能监控（APM），并提供全面的可观测性解决方案。New Relic 服务于全球领先客户，其中包括 Ryanair 等知名品牌，帮助各类组织监控并优化其数字系统，从而交付更好的客户体验。

New Relic 面临的挑战在很多快速成长的企业中都很常见。他们的工程师把宝贵的时间花在跨多个系统的碎片化文档中搜索信息上，查询内部系统有时甚至要耗费一天以上。作为一个服务全球数千客户的可观测性平台，New Relic 清楚需要一种更高效的方式来访问并利用组织知识。

这一挑战促成了 New Relic NOVA（New Relic Omnipresence Virtual Assistant）的诞生：一个构建在 Amazon Web Services（AWS）上的创新人工智能（AI）工具。New Relic NOVA 改变了 New Relic 员工访问公司知识与系统并与之交互的方式。

New Relic 与[生成式 AI 创新中心](https://aws.amazon.com/ai/generative-ai/innovation-center/)合作，让 New Relic NOVA 从知识助手演进为一个综合性的生产力引擎。New Relic NOVA 构建在多项 AWS 服务之上，包括 [Amazon Bedrock](https://aws.amazon.com/bedrock/?trk=978e13b6-fa37-4872-9001-1825f3ca3367&sc_channel=ps&ef_id=Cj0KCQjwqqDFBhDhARIsAIHTlksXVp8TxKBJXH08wI1JYInb3fWk7zigz7Kq5sY3m20eKR1uU_HJqe8aAvHtEALw_wcB:G:s&s_kwcid=AL!4422!3!692006004850!e!!g!!amazon%20bedrock!21048268689!159639953975&gad_campaignid=21048268689&gbraid=0AAAAADjHtp9Gy6epvq3Izt29Nbow0MeA2&gclid=Cj0KCQjwqqDFBhDhARIsAIHTlksXVp8TxKBJXH08wI1JYInb3fWk7zigz7Kq5sY3m20eKR1uU_HJqe8aAvHtEALw_wcB)、[Amazon Kendra](https://aws.amazon.com/pm/kendra/?trk=0fab6fc5-a1b5-4c90-95ba-9d9de1e9b574&sc_channel=ps&ef_id=Cj0KCQjwqqDFBhDhARIsAIHTlkun2FtxEiybZOQHqil9j4fPFnp3D1S1W3yoYO-HB3r7xpTlSKdEAbkaAuE0EALw_wcB:G:s&s_kwcid=AL!4422!3!652240143532!e!!g!!amazon%20kendra!19870609809!147151599973&gad_campaignid=19870609809&gbraid=0AAAAADjHtp_i9i101B7MEZ1nxtfa93Eeb&gclid=Cj0KCQjwqqDFBhDhARIsAIHTlkun2FtxEiybZOQHqil9j4fPFnp3D1S1W3yoYO-HB3r7xpTlSKdEAbkaAuE0EALw_wcB)、[Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/pm/serv-s3/?refid=59968c08-333e-424a-b5a8-4fd08af5af4d) 和 [Amazon DynamoDB](https://aws.amazon.com/pm/dynamodb/?trk=8a8dfafe-2566-4dd7-a0a4-880dd910dfa0&sc_channel=ps&ef_id=Cj0KCQjwqqDFBhDhARIsAIHTlkvsykUJtH_pWN6Chzcpg3ufj-QMQrttBzCuKRj3x8D_URBwnp-C598aAvz_EALw_wcB:G:s&s_kwcid=AL!4422!3!651751059996!e!!g!!amazon%20dynamodb!19852662209!145019198137&gad_campaignid=19852662209&gbraid=0AAAAADjHtp8esdSqMfYOpx8fDFZWgHJma&gclid=Cj0KCQjwqqDFBhDhARIsAIHTlkvsykUJtH_pWN6Chzcpg3ufj-QMQrttBzCuKRj3x8D_URBwnp-C598aAvz_EALw_wcB)。通过 [Strands Agents](https://strandsagents.com/latest/)，New Relic NOVA 提供智能代码评审、AI 治理以及托管的 Model Context Protocol（MCP）服务。

Amazon Bedrock 是一项完全托管的服务，提供对领先基础模型的访问，用于构建生成式 AI 应用；它免去了管理基础设施的负担，同时让团队能够针对具体用例定制模型。通过单一 API，开发者可以试验并评估不同的基础模型，将其与企业系统集成，并大规模构建安全的 AI 应用。

该解决方案缩短了信息检索时间，同时把复杂的运维工作流自动化。通过与该生成式 AI 创新中心合作，New Relic NOVA 已发展为一套解决方案，如今在整个组织内每天处理超过 1,000 次查询。New Relic NOVA 与 Confluence、GitHub、Salesforce、Slack 以及各类内部系统无缝集成，在知识型查询和事务型任务上的回答均保持 80% 的准确率。

我们将展示 New Relic NOVA 如何利用 AWS 服务进行架构设计，构建出一个可扩展的智能助手；它不仅限于文档检索，还能处理自动化团队权限申请、速率限制管理等复杂任务。我们会探讨技术架构、开发历程，以及构建一套能大规模交付可衡量生产力提升的企业级 AI 解决方案过程中的关键经验。

## 解决方案

New Relic NOVA 在八周内开发完成，由内部工程、安全、法务与合规团队同 AWS 生成式 AI 创新中心协作推进。这一合作加速了快速开发与迭代，充分利用了 AWS 在大规模 AI 实施方面的专长。

## Agent 架构

New Relic NOVA 的架构由三个关键层次组成：

- **主 agent 层 –** 它充当可控的编排者，通过识别用户意图并把工作下派给以下各下游层来执行不同工作流：基于从 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 或 [Amazon Kendra](https://aws.amazon.com/kendra/) 摄取的自定义知识进行检索增强生成（RAG）。用于直接与第三方平台交互的 agent。用于处理 New Relic 内部任务的自定义 agent。在无法判定用户诉求时的兜底处理。
- **数据源层（向量数据库、enrich、数据源）** – 这些层代表用于检索或 RAG 目的而摄取内部知识（例如 New Relic 标准文档和代码仓库文档）的资源。这些自定义资源的价值在于提升用于信息请求的信息与搜索性能。
- **agent 层 **– 由两种不同的 agent 类型组成：**使用 MCP 的 Strands Agents：**处理第三方服务的多步流程，利用 MCP 实现标准化的服务交互。**自定义操作 agent：**执行权限申请、服务限额修改等 New Relic 特定任务，对内部系统提供精确控制。

中心 agent 充当编排者，把查询路由给专用子 agent，采用委派模型，响应直接返回给用户，而无需 agent 之间互相推理或调整。同时，Strands Agents 被用于借助 MCP 高效管理第三方服务集成。这种做法让 New Relic NOVA 兼得两者之长：编排模型为内部流程保持灵活性，同时通过 MCP 统一外部服务，为 New Relic 未来的自动化需求构建了可扩展的基础。

## 数据集成策略

其威力在于 New Relic NOVA 能够无缝集成多个数据源，为知识检索提供统一接口。这种做法包括：

- **面向 Confluence 的 Amazon Bedrock Knowledge Bases：**确认与 Confluence 空间直接同步，并保持信息最新。
- **面向 GitHub Enterprise 的 Amazon Kendra：**为 GitHub 仓库建立索引并执行搜索，提供对代码文档的快速访问。
- **面向 Salesforce 和 Jira 的 Strands Agents：**自定义 agent 分别执行 SOQL 和 JQL 查询，从各自平台（Salesforce 和 Jira）获取相关数据。
- [**Amazon Q Index**](https://docs.aws.amazon.com/amazonq/latest/qbusiness-ug/isv.html) **用于 Slack：**利用 Amazon Q Index 的能力为 Slack 频道历史记录实现 RAG 解决方案，之所以选择它是因为其快速开发的潜力。

New Relic NOVA 数据集成的一个独特之处在于自定义的文档丰富化流程。在摄取过程中，文档会补充元数据、关键词和摘要，从而显著提升检索的相关性和准确性。

## 使用 Amazon Nova 模型

[Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/?trk=978e13b6-fa37-4872-9001-1825f3ca3367&sc_channel=ps&ef_id=Cj0KCQjwqqDFBhDhARIsAIHTlkta_DaBLkax4Von5Dsx9Yho8yEf5tBf8_CYHq9cNjTxDiXJDJQBdnAaApSGEALw_wcB:G:s&s_kwcid=AL!4422!3!692006004844!e!!g!!amazon%20nova!21048268689!159639953895&gad_campaignid=21048268689&gbraid=0AAAAADjHtp9Gy6epvq3Izt29Nbow0MeA2&gclid=Cj0KCQjwqqDFBhDhARIsAIHTlkta_DaBLkax4Von5Dsx9Yho8yEf5tBf8_CYHq9cNjTxDiXJDJQBdnAaApSGEALw_wcB) 是 AWS 新一代基础模型，旨在为企业用例提供前沿智能与业界领先的性价比。Amazon Nova 模型家族可以处理文本、图像和视频等多种输入，在交互式聊天到文档分析等任务上表现出色，同时支持 RAG 系统和 AI agent 工作流等高级能力。

为了优化性能与成本效益，New Relic NOVA 通过 Amazon Bedrock 使用 Amazon Nova Lite 和 Pro 模型。这些模型经过精心选择，以在回答质量与延迟之间取得平衡，使 New Relic NOVA 在处理复杂查询的同时维持 20 秒以内的响应时间。Amazon Bedrock 提供对多样化[基础模型家族](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)的访问。其标准化框架和 prompt 优化支持在无需改动代码的情况下无缝切换模型。这使 New Relic NOVA 可以用 Amazon Nova Lite 优化速度，或面对高复杂度时切换到 Amazon Nova Pro，同时保持一致性能与成本效率。

## 高级 RAG 实现

New Relic NOVA 采用精细的 RAG 方法，利用 Amazon Bedrock Knowledge Bases、Amazon Kendra 和 Amazon Q Index。为最大化检索准确性，New Relic NOVA 实施了若干关键优化技术：

- [**分层分块**](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-chunking.html#kb-hiearchical-chunking)**：**Amazon Bedrock Knowledge Bases 采用分层分块，在针对多种分块方法进行大量实验后，这一方法被证明最为有效。
- **上下文丰富化：**一个自定义 [AWS Lambda](https://aws.amazon.com/lambda/) 函数在知识库摄取期间增强各个分块，注入相关关键词和上下文信息。这一流程对代码相关内容尤其有价值，因为结构和语义线索会显著影响检索性能。
- **元数据集成：**在知识库文档摄取期间，摘要、标题、作者、创建日期和最后修改日期等额外上下文会作为文档元数据附加。这些丰富后的元数据提升了检索信息的质量与相关性。
- **自定义文档处理：**对于 GitHub 仓库等特定数据源，采用针对性的文档处理技术，以保留代码结构并提升搜索相关性。

这些技术协同作用，优化了 New Relic NOVA 中的 RAG 系统，在各类文档类型上交付高准确度的检索，同时借助现有连接器把开发工作量降到最低。分层分块、上下文丰富化、元数据集成和自定义文档处理的组合，使 New Relic NOVA 无论面对何种数据源或文档格式，都能提供精确、具备上下文感知的回答。

## 评估框架

New Relic NOVA 实施了一套全面的评估框架，利用 Amazon Bedrock 基础模型实现其[以大语言模型（LLM）作为评判者](https://aws.amazon.com/blogs/machine-learning/llm-as-a-judge-on-amazon-bedrock-model-evaluation/)的方法，并结合由问题、[基准事实](https://aws.amazon.com/blogs/machine-learning/ground-truth-curation-and-metric-interpretation-best-practices-for-evaluating-generative-ai-question-answering-using-fmeval/)答案和源文档 URL 组成的验证数据集。该评估框架可以在开发环境中按需执行，涵盖三项用于系统验证的关键指标：

- 回答准确性测量采用 1–5 的离散量表评分体系，由 LLM 评估所生成回答与既定基准事实数据之间的事实一致性。
- 上下文相关性评估采用 1–5 的量表，分析检索到的上下文与用户查询之间的相关性。
- 响应延迟跟踪衡量工作流性能，从最初输入查询到最终生成答案，通过完整的计时分析确保最佳用户体验。

这种三指标评估方法支撑 New Relic NOVA 解决方案核心功能上的细致性能优化。

## 可观测性与持续改进

该解决方案包含一套全面的可观测性框架，用于收集指标并分析用户反馈。指标与反馈的收集通过 New Relic AI 监控解决方案实现。反馈通过 Slack 的表情回应功能（emoji 反应）实现，用户可以快速对 New Relic NOVA 的回答给出反馈。这些表情回应会被 New Relic 的 python agent 捕获，并发送到 https://one.newrelic.com/ 域。反馈收集系统为以下方面提供有价值的洞察：

- 衡量用户对回答的满意度。
- 识别准确性可改进的领域。
- 理解不同团队的使用模式。
- 跟踪不同类型查询的有效性。
- 监控各数据源的性能。
- 追踪每次 LLM 调用及其延迟。

收集到的反馈数据可以使用 AWS 分析服务进行分析，例如用于 ETL 处理的 [AWS Glue](https://aws.amazon.com/glue/)、用于查询的 [Amazon Athena](https://aws.amazon.com/athena/)，以及用于可视化的 [AWS Quick Sight](https://aws.amazon.com/quicksight/)。这种数据驱动的方法使 New Relic NOVA 得以持续改进，并帮助依据真实用户交互来排定未来增强的优先级。

## 考量与后续步骤

New Relic NOVA 的成功为有意实施类似解决方案的组织凸显了几条关键经验：

- 从清晰理解用户痛点和可衡量的成功标准开始。
- 实施稳健的数据集成策略并配合自定义文档丰富化。
- 使用最契合自身用例的生成式 AI 服务和基础模型，以取得最佳效果。
- 从一开始就内置反馈机制，以实现持续改进。
