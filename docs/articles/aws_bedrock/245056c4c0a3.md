# 构建能够使用 Amazon Bedrock AgentCore payments 完成交易的 OpenClaw agent

*本文是 AWS 与 [OpenClaw Foundation](https://www.openclaw.org/) 合作的成果。*

浏览网页、调用 API、查询 Model Context Protocol（MCP）服务器的自主 agent，可能遇到这样的服务：需要先结清一个 HTTP 402 Payment Required 响应，访问才能继续。要在不必每笔交易都停下来等人批准的情况下使用这些服务，agent 需要一条在事先批准的限额内运作的支付通路。安全的设计会把钱包提供方的凭证，以及创建或扩大支付会话的权限，都放在面向模型的运行时之外。运行时仍然可以在这些限额内发起已获批准的支付。

[AgentCore payments](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments.html) 是 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 的一项能力，它提供钱包集成、支出限额，以及一个在 agent 支付协议不断演进时保持一致的支付层。[x402](https://github.com/coinbase/x402) 与 [Machine Payments Protocol（MPP）](https://mpp.dev/) 等协议支持 agent 与服务之间的程序化支付流程。本文将带你把 OpenClaw 连接到一个由人工经可信管理路径预置的钱包与有界支付会话，然后使用 [OpenClaw](https://openclaw.ai) 的 `aws-agents-pay` 插件发起已获批准的测试网支付。

## 为什么 agent 需要支付能力

自主 agent 可以跨多个步骤与服务行动，而无需人对每个动作逐一审阅。长时间运行的研究或工作流 agent，可能在无人值守时遇到付费 API 或内容端点。有界支付层让 agent 能够继续，但须落在人工事先设定的收款方、资产、网络、单笔支付、累计预算与过期时间限制之内。

一些 API、内容服务、计算服务与 MCP 工具采用按使用付费的定价。单笔交易可能不到一美元，甚至只有几分钱的一小部分。银行卡处理的最低手续费会让这个量级的交易变得不划算，而稳定币支付可以支持小额支付与近乎实时的结算。这让 x402 这类 HTTP 原生协议适合程序化、由 agent 发起的支付。

直接实现这一切，需要钱包提供方集成、受保护的凭证处理、支付授权、确定性限额与支付可观测性。你还需要考虑到模型可能被不可信输入操控。该设计并不能阻止 prompt 注入；相反，它假设不可信输入可以操控模型，因此按收款方、资产、网络、单笔支付金额、会话预算与过期时间，来限定运行时的权限边界。

## 方案概览

在 agent 支付协议不断演进的过程中，AgentCore payments 提供一个一致的支付层。这个 OpenClaw 集成用 x402 v2 演示了该模式：它通过已配置的钱包提供方处理商户的 HTTP 402 挑战，并返回一份签名授权，客户端用它重放原请求。[AgentCore Identity，Amazon Bedrock AgentCore 的一项能力，](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity.html) 负责存储钱包提供方凭证。在配置了遥测投递后，[AgentCore Observability，同样是 Amazon Bedrock AgentCore 的一项能力，](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/observability.html) 可以通过 Amazon CloudWatch 与 AWS X-Ray 提供日志、指标与 trace。

AgentCore payments 支持以 Coinbase 钱包或 Stripe Privy 钱包作为支付连接。两者都提供嵌入式稳定币钱包。视提供方与地域可用性而定，你或你的最终用户可以通过稳定币，或用借记卡以法币为钱包充值。两家提供方都使用 AgentCore Identity 的凭证存储与按会话的支出限额。

本演练使用 [OpenClaw](https://openclaw.ai/)——一个运行在你设备上、通过本地 Gateway 连接模型、工具与消息渠道的 AI 助手。项目由 [OpenClaw Foundation](https://www.openclaw.org/) 维护，插件则扩展该助手的能力。本演练把由人执行的支付管理与面向模型的运行时分离开：人在可信终端中预置钱包、创建支付会话、批准收款方并设定预算。`aws-agents-pay` 插件只向模型暴露两个工具：`get_payment_session_status` 用于检查已配置的支付会话，`get_paid_content` 用于请求一个已获批准的付费 URL，并在配置的策略内完成支付。运行时可以在已批准的会话内发起支付，但不能创建、延长或替换会话。

*图 1：演示展示在 OpenClaw gateway 应用中与一个名为“Bob”的 AI 助手对话。用户问“西雅图现在的天气怎么样？”，随后 Bob 为一个付费天气 API 在 Base Sepolia 上执行了一笔 0.001 USDC 的测试支付*

典型的支付流程是：

- agent 调用 `get_payment_session_status`，确认运维人员预置的会话可用。
- agent 针对一个已获批准的 URL 调用 `get_paid_content`。插件先执行一次有界网络探测，收到包含 x402 v2 挑战的 HTTP 402 响应。
- 收到挑战后，插件校验挑战中的资源与所请求的 URL 具有相同的源（origin）与路径。随后在调用 `ProcessPayment` 之前，按运维人员的策略校验网络、资产、收款方与金额。
- 对同一支付请求重试时，插件复用同一个幂等 token，而不是创建第二笔支付。并发的重复请求仍可能造成竞态，因此应避免并发发起同一笔支付。
- 插件等到签名授权的 `validAfter` 时间，然后带上支付签名重放原请求。
- 本演练启用了 `returnBody`，插件会返回付费响应的正文，将其限制在 10 KiB 以内，并标记为 `untrusted: true`。插件不会把签名后的支付凭证返回给模型。

Agent Toolkit for AWS 中当前的 OpenClaw 设置流程提供了测试用的 Base Sepolia 与生产用的 Base 示例，并支持针对其他链的定制，包括 Ethereum、其他 EVM 兼容链与 Solana。

## 实施步骤：配置 OpenClaw 完成有界支付

以下各节将带你走完前置条件、在 agent 循环之外预置钱包与支付会话、配置显式支付策略，以及完成一笔有界支付。

### 前置条件

请确认你具备以下前置条件。

- OpenClaw 2026.3.24 或更高版本：`npm install -g openclaw`。
- Node.js 与 npm。
- 一个可访问 AgentCore payments 的 AWS 账户。
- 按 [AgentCore payments IAM 角色指南](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments-iam-roles.html)为管理与运行时分别准备独立的 AWS Identity and Access Management（IAM）角色。OpenClaw 的运行时角色只需要查询状态所需的读操作以及 `ProcessPayment`，不得拥有会话写入权限。
- Coinbase CDP 或带 Privy 的 Stripe 凭证，且仅可在交互式 AgentCore CLI 中输入。
- 一个由你控制或经过独立批准的 Base Sepolia x402 v2 端点。你可以用 [Coinbase x402 Bazaar](https://docs.cdp.coinbase.com/x402/buyer/discover-services) 发现候选服务，但在把它们加入支付策略之前，请先核实端点、收款方、网络、资产与价格。
- 商户收款方地址与 USDC 资产合约，须独立于 HTTP 402 响应，从商户文档或其他已知可信来源核实。

**免责声明：** 本方案的安全性遵循 [AWS 共担责任模型](https://aws.amazon.com/compliance/shared-responsibility-model/)。AWS 负责云本身的安全，你负责云中的安全。对本方案而言，你的职责包括配置 IAM 权限、保护钱包提供方凭证，以及定义支付策略。请遵循 [AgentCore payments IAM 角色指引](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments-iam-roles.html)，把管理、管控、agent 执行与服务操作分离开。

以下步骤将带你从安装插件，到看着 agent 为它的第一份付费内容付款。

### 1. 从 ClawHub 安装插件

继续之前，请确认 `@aws/aws-agents-pay` 包在 ClawHub 上可用。然后安装它：

```
openclaw plugins install clawhub:@aws/aws-agents-pay
```

Bash

包名为 `@aws/aws-agents-pay`，安装后的插件 ID 为 `aws-agents-pay`，随包附带的 skill 名称为 `agents-pay`。

要查看随包附带的上手指引，运行：

```
openclaw skills info agents-pay
```

Bash

检查已安装的插件：

```
openclaw plugins inspect aws-agents-pay
```

Bash

面向模型的运行时只应暴露 `get_payment_session_status` 与 `get_paid_content`。如果出现了设置、会话创建、shell 或其他面向模型的工具，请立即停止。意外的工具可能意味着这是另一个、过期的或被修改过的包。

### 2. 完成人工监督下的支付设置

安装插件并不会创建 payment manager、connector、instrument 或支付会话。请从以下预置方式中选择一种。两种方式都在你 AWS 凭证下的可信终端中执行，且创建会话要求你在交互式 TTY 中键入 `approve`。

**方式 A——OpenClaw 辅助设置。** 对 OpenClaw 说：`Help me set up the agents-pay skill.` OpenClaw 可以解释每一步，但管理命令必须由你自己执行，会话创建也必须由你批准。OpenClaw 的引导并不会取消交互式审批环节。

**方式 B——完全手动设置。** 直接按 [OpenClaw 设置指南](https://github.com/aws/agent-toolkit-for-aws/blob/main/plugins/aws-agents/skills/agents-pay/references/openclaw-setup.md) 操作，不借助 OpenClaw。

无论选择哪种方式，都要在可信、有人监督的终端中按 [OpenClaw 设置指南](https://github.com/aws/agent-toolkit-for-aws/blob/main/plugins/aws-agents/skills/agents-pay/references/openclaw-setup.md) 操作。该指南涵盖创建 AgentCore 项目、预置支付资源、运行设置向导，以及把生成的配置加入 OpenClaw。凭证必须由你输入，`approve` 也必须由你键入。

### 3. 用显式策略配置插件

在启用插件之前，先审阅生成的配置。它必须包含 payment manager ARN、instrument ID、session ID、user ID、网络、确切的资产合约、已批准的收款方，以及一个正的每笔支付上限。

本沙盒演练请使用[配套代码示例](https://github.com/awslabs/agentcore-samples/tree/main/01-features/08-agents-that-transact/01-payments-skills-and-cli/converse-with-openclaw-agent/#3-configure-trusted-policy)第 3 步中的支付策略。其中的 Base Sepolia 网络、源（origin）、收款方、USDC 资产、支付限额与 `returnBody` 设置，都与下一步使用的测试端点相匹配。

这个沙盒端点已列在 Coinbase x402 Bazaar 中，但本演练直接调用一个已知 URL。若要走发现驱动的流程，请参阅 [Coinbase Bazaar 教程](https://github.com/awslabs/agentcore-samples/tree/main/01-features/08-agents-that-transact/00-getting-started/04-agent-with-coinbase-bazaar-via-gateway/)。

对于固定的商户集合，请用商户文档或其他已知可信来源在带外核实 `allowedRecipients` 中的每个地址。不要仅因为某个收款方出现在 HTTP 402 响应中就予以批准。对于更宽泛的发现场景，可设置 `allowAnyRecipient: true`，让发布方自行选择收款方。这个选项用收款方白名单换取了灵活性；源、网络、资产、单笔支付与会话预算等控制仍然生效。本演练请把 `networkPreferences` 保持在 Base Sepolia（`eip155:84532`），并使用设置向导选定的确切 Base Sepolia USDC 合约。

`maxPaymentAmountAtomic` 以资产的最小单位限制单笔支付。对于六位小数的 USDC 资产，`100000` 表示 0.10 USDC。支付会话预算则另行限制累计支出，直到会话过期或被用尽。本演练请把 `returnBody` 设为 `true`，好让 agent 能使用付费响应。插件会把响应限制在 10 KiB 以内并标记为 `untrusted: true`。由发布方控制的内容可能包含 prompt 注入指令，因此当 agent 只需要响应元数据与摘要时，请将 `returnBody` 留空或设为 `false`。该设置不会暴露签名后的支付凭证。

钱包提供方的密钥不应出现在 OpenClaw 配置中。请把支付会话 ID、资源标识符、收款方策略与其他配置值视为敏感运维数据，因为它们描述并授权了运行时的支付路径。

保存 `~/.openclaw/openclaw.json` 后重启 gateway：

```
openclaw gateway restart
```

Bash

如果你使用受保护的 `~/.x402/config.json` 路径而不是内联的插件配置，插件会检查该目录与文件的所有者与权限，并拒绝加载不安全的配置。

### 4. 检查会话状态并为内容付费

让你的 OpenClaw agent 检查已配置的会话是否可用：

```
What's the status of my payment session?
```

Plain text

如果会话不可用、已过期或已用尽，请停止。使用可信的管理路径审视情况并创建替代会话。面向模型的运行时无法创建或扩大自己的预算。

配套示例把它的支付策略固定到本演练所用的 Base Sepolia 端点上。让 agent 去取它：

```
Fetch https://sandbox.node4all.com/v1/x402-test
```

Plain text

插件执行一次有界探测，按运维人员的策略校验返回的挑战，调用 AgentCore payments，等到签名授权生效，然后重放该请求。本演练启用了 `returnBody`，因此工具会返回付费响应正文，并带上 `content_returned: true`，将其限制在 10 KiB 以内，并标记为 `untrusted: true`。它不会返回签名后的支付凭证。

请把商户响应与所有取回的内容视为不可信。该设计并不阻止 prompt 注入；它假设模型可能被操控，并通过 IAM 隔离、已批准的收款方与资产、单笔支付上限、累计会话预算与过期时间，来限定支付权限。只在 agent 需要付费响应时才启用 `returnBody`，并把该响应当作数据而非指令。

再次查询会话状态：

```
What's my payment session status now?
```

Plain text

确认报告的剩余预算已反映这笔支付。

### 清理

从 OpenClaw 移除插件并重启 gateway：

```
openclaw plugins uninstall aws-agents-pay
openclaw gateway restart
```

Bash

用同一条可信管理路径移除 AWS 上的支付资源。不要把基础设施删除或会话创建暴露给面向模型的运行时，并让运行时 IAM 角色不持有这些权限。

## 结论

借助 AgentCore payments，agent 可以在人工事先设定的限额内访问付费墙后的 API、按使用付费的数据源与按量计费的 MCP 工具。AgentCore payments 负责钱包集成、支出限额与支付编排。在这个 OpenClaw 模式中，人工把钱包提供方凭证，以及对收款方、资产、单笔支付限额、累计会话预算与过期时间的权限，都保持在面向模型的运行时之外。agent 只能在这些已批准的边界内发起支付。

[从 ClawHub 安装 `aws-agents-pay` 插件](https://clawhub.ai/aws/plugins/aws-agents-pay)，然后按 [带 AgentCore payments 的 OpenClaw agent 示例](https://github.com/awslabs/agentcore-samples/tree/main/01-features/08-agents-that-transact/01-payments-skills-and-cli/converse-with-openclaw-agent/) 预置支付资源并完成一次端到端 x402 支付。
