# 使用 Amazon Bedrock 简化资助提案评审

评估资助提案的政府和非营利组织面临一个重大挑战：从数百份内容详尽的提交材料中筛选出最有前景的项目，而每份材料各有其独特价值。这项艰巨、耗时的流程通常是资助管理流程的第一步，而该流程对于产生有意义的社会影响至关重要。

AWS Social Responsibility & Impact (SRI) 团队意识到有机会用[生成式 AI](https://aws.amazon.com/generative-ai/) 来增强这一职能。该团队开发了一个创新解决方案，利用 [Amazon Bedrock](https://aws.amazon.com/ai/generative-ai/?gclid=EAIaIQobChMI84fJ1ZbSiAMVTUtHAR2s6QA6EAAYASAAEgLqXvD_BwE&trk=8f1c8b7a-7d88-4fec-9624-839fb8e22c8f&sc_channel=ps&ef_id=EAIaIQobChMI84fJ1ZbSiAMVTUtHAR2s6QA6EAAYASAAEgLqXvD_BwE:G:s&s_kwcid=AL!4422!3!686079219969!p!!g!!amazon%20generative%20ai!20901655904!158309132298) 的 natural language processing (NLP) 能力来简化资助提案的评审与评估。Amazon Bedrock 是一项完全托管的服务，让你可以通过单一 API 使用你选择的高性能 foundation models (FMs)，这些模型来自 AI21 Labs、Anthropic、Cohere、Meta、Mistral AI、Stability AI 和 Amazon 等领先 AI 公司，同时还提供广泛的能力，帮助你构建具备安全性、隐私保护和负责任 AI 的生成式 AI 应用。

过去，AWS Health Equity Initiative 的申请由评审委员会人工审核。每个周期需要 14 天或更长时间才能完成所有申请的评审。该计划平均每周期收到 90 份申请。2024 年 6 月的 AWS Health Equity Initiative 申请周期收到了 139 份申请，是该计划迄今为止最大的一次申请涌入。评审委员会人工处理这么多申请估计需要 21 天。以 Amazon Bedrock 为中心的方法将评审时间缩短到 2 天（减少 90%）。

目标是提高评审流程的效率和一致性，使客户能够更快地构建有影响力的解决方案。通过将 Amazon Bedrock 先进的 NLP 能力与精心设计的 prompt engineering 相结合，团队创建了一个动态、数据驱动且公平的解决方案，展示了 large language models (LLMs) 在社会影响领域的变革潜力。

在本文中，我们探讨团队基于 Amazon Bedrock 的资助提案评审方案的技术实现细节和关键经验，为希望优化资助管理流程的组织提供蓝图。

## 使用生成式 AI 构建有效的资助提案评审 prompt

Prompt engineering 是精心构建有效 prompt 的艺术，用以指示和引导 LLMs 等生成式 AI 模型产生期望的输出。通过深思熟虑地设计 prompt，实践者可以释放生成式 AI 系统的全部潜力，并将其应用于广泛的真实场景。

在为我们的 Amazon Bedrock 模型构建用于评审资助提案的 prompt 时，我们使用了多种 prompt engineering 技巧，以确保模型的响应是有针对性的、结构化的且可执行的。这包括为模型分配特定的 persona、提供分步骤指令，以及指定期望的输出格式。

首先，我们为模型分配了公共卫生专家的 persona，重点是改善服务不足人群的医疗结果。这一背景有助于引导模型从 subject matter expert (SME) 的视角评估提案，该专家会全面思考全球挑战和社区层面的影响。通过清晰定义 persona，我们确保模型的响应符合期望的评估视角。

```
Your task is to review a proposal document from the perspective of a given persona, and assess it based on dimensions defined in a rubric. Here are the steps to follow:

1. Review the provided proposal document: {PROPOSAL}

2. Adopt the perspective of the given persona: {PERSONA}
```

可以针对同一 rubric 分配多个 persona，以涵盖各种视角。例如，当分配 “Public Health Subject Matter Expert” 这个 persona 时，模型对项目的影响潜力和证据基础给出了敏锐的见解。当分配 “Venture Capitalist” persona 时，模型对该组织明确提出的里程碑和资金到位后的可持续性计划给出了更有力的反馈。同样，当分配 “Software Development Engineer” persona 时，模型就拟议的 AWS 技术使用给出了专业领域的专门见解。

接下来，我们将评审流程分解为一组结构化的指令供模型遵循。这包括审阅提案、在特定维度（影响潜力、创新性、可行性、可持续性）上进行评估，然后给出总体摘要和分数。列出这些分步骤指令为模型提供了关于所需任务要素的清晰指导，并有助于产生全面且一致的评估。

```
3. Assess the proposal based on each dimension in the provided rubric: {RUBRIC}

For each dimension, follow this structure:
<Dimension Name>
 <Summary> Provide a brief summary (2-3 sentences) of your assessment of how well the proposal meets the criteria for this dimension from the perspective of the given persona. </Summary>
 <Score> Provide a score from 0 to 100 for this dimension. Start with a default score of 0 and increase it based on the information in the proposal. </Score>
 <Recommendations> Provide 2-3 specific recommendations for how the author could improve the proposal in this dimension. </Recommendations>
</Dimension Name>

4. After assessing each dimension, provide an <Overall Summary> section with:
 - An overall assessment summary (3-4 sentences) of the proposal's strengths and weaknesses across all dimensions from the persona's perspective
 - Any additional feedback beyond the rubric dimensions
 - Identification of any potential risks or biases in the proposal or your assessment

5. Finally, calculate the <Overall Weighted Score> by applying the weightings specified in the rubric to your scores for each dimension.
```

最后，我们将期望的输出格式指定为 JSON，其中为各维度评估、总体摘要和总体分数设置了不同的板块。规定这种结构化响应格式确保模型的输出能够被我们的资助评审团队摄取、存储和分析，而不是以自由文本形式交付。这种对输出的控制程度有助于简化对模型评估结果的下游使用。

```
6. Return your assessment in JSON format with the following structure:

{{ "dimensions": [ {{ "name": "<Dimension Name>", "summary": "<Summary>", "score": <Score>, "recommendations": [ "<Recommendation 1>", "<Recommendation 2>", ... ] }}, ... ], "overall_summary": "<Overall Summary>","overall_score": <Overall Weighted Score> }}

Do not include any other commentary beyond following the specified structure. Focus solely on providing the assessment based on the given inputs.
```

通过结合这些 prompt engineering 技巧——角色分配、分步骤指令和输出格式化——我们得以构建出一个 prompt，能从生成式 AI 模型引出全面、客观且可执行的资助提案评估。这种结构化方法使我们能够有效利用模型的能力，以可扩展且高效的方式支持资助评审流程。

## 使用 Streamlit 和生成式 AI 构建动态提案评审应用

为了演示和测试动态提案评审方案的能力，我们使用 [Streamlit](https://streamlit.io/)、Amazon Bedrock 和 [Amazon DynamoDB](https://aws.amazon.com/dynamodb) 构建了一个快速原型实现。需要注意的是，该实现并非用于生产，而是作为概念验证和进一步开发的起点。该应用允许用户定义并保存各种 persona 和评估 rubric，然后在评审提案提交材料时动态应用它们。这种方法能够基于指定的标准对每份提案进行有针对性且相关的评估。

该应用的架构由几个关键组件构成，我们将在本节中讨论。

团队使用 DynamoDB（一个 NoSQL 数据库）来存储 persona、rubric 和提交的提案。存储在 DynamoDB 中的数据被发送到 Streamlit（一个 Web 应用界面）。在 Streamlit 上，团队将 persona 和 rubric 添加到 prompt 中，再将 prompt 发送给 Amazon Bedrock。

```
import boto3
import json

from api.personas import Persona
from api.rubrics import Rubric
from api.submissions import Submission

bedrock = boto3.client("bedrock-runtime", region_name="us-east-1")

def _construct_prompt(persona: Persona, rubric: Rubric, submission: Submission):
    rubric_dimensions = [
        f"{dimension['name']}|{dimension['description']}|{dimension['weight']}"
        for dimension in rubric.dimensions
    ]

    # add the table headers the prompt is expecting to the front of the dimensions list
    rubric_dimensions[:0] = ["dimension_name|dimension_description|dimension_weight"]
    rubric_string = "\n".join(rubric_dimensions)
    print(rubric_string)

    with open("prompt/prompt_template.txt", "r") as prompt:
        prompt = prompt.read()
        print(prompt)
        return prompt.format(
            PROPOSAL=submission.content,
            PERSONA=persona.description,
            RUBRIC=rubric_string,
        )
```

Amazon Bedrock 使用 Anthropic 的 Claude 3 Sonnet FM 根据 prompt 评估提交的提案。模型的 prompt 根据所选的 persona 和 rubric 动态生成。Amazon Bedrock 会将评估结果发回 Streamlit 供团队审阅。

```
def get_assessment(submission: Submission, persona: Persona, rubric: Rubric):
    prompt = _construct_prompt(persona, rubric, submission)

    body = json.dumps(
        {
            "anthropic_version": "",
            "max_tokens": 2000,
            "temperature": 0.5,
            "top_p": 1,
            "messages": [{"role": "user", "content": prompt}],
        }
    )
    response = bedrock.invoke_model(
        body=body, modelId="anthropic.claude-3-haiku-20240307-v1:0"
    )
    response_body = json.loads(response.get("body").read())
    return response_body.get("content")[0].get("text")
```

## 影响

这个快速原型展示了可扩展、灵活的提案评审流程的潜力，使组织能够：

- 将申请处理时间最多缩短 90%
- 通过自动化评估任务简化评审流程
- 捕获有关提案和评估的结构化数据以供进一步分析
- 通过支持使用多个 persona 和 rubric 来纳入多元视角

在整个实施过程中，AWS SRI 团队专注于打造交互式且用户友好的体验。通过实际操作 Streamlit 应用并观察动态选择 persona 和 rubric 的影响，用户可以获得构建应对真实挑战的 AI 驱动应用的实践经验。

## 生产级实施的考量

尽管快速原型展示了该方案的潜力，但生产级实施需要额外的考量以及使用更多 AWS 服务。一些关键考量包括：

- **可扩展性与性能** – 为处理大量提案和并发用户，使用 [AWS Lambda](https://aws.amazon.com/lambda/)、[Amazon API Gateway](https://aws.amazon.com/api-gateway/)、DynamoDB 和 [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/s3/) 的 serverless 架构将提供更好的可扩展性、可用性和可靠性。
- **安全与合规** – 根据所涉数据的敏感性，需要加密、身份验证与访问控制以及审计等额外安全措施。[AWS Key Management Service (KMS)](https://aws.amazon.com/kms/)、[Amazon Cognito](https://aws.amazon.com/cognito/)、[AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 和 [AWS CloudTrail](https://aws.amazon.com/cloudtrail/) 等服务可以帮助满足这些要求。
- **监控与日志 ** – 使用 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 和 [AWS X-Ray](https://aws.amazon.com/xray/) 等服务实施稳健的监控和日志机制，可以跟踪性能、识别问题并维持合规。
- **自动化测试与部署** – 使用 [AWS CodePipeline](https://aws.amazon.com/codepipeline/)、[AWS CodeBuild](https://aws.amazon.com/codebuild/) 和 [AWS CodeDeploy](https://aws.amazon.com/codedeploy/) 等服务实施自动化测试与部署流水线，有助于提供一致且可靠的部署，降低错误和停机的风险。
- **成本优化** – 实施成本优化策略，例如使用 [AWS Cost Explorer](https://aws.amazon.com/aws-cost-management/aws-cost-explorer/) 和 [AWS Budgets](https://aws.amazon.com/aws-cost-management/aws-budgets/)，可以帮助管理成本并保持高效的资源利用率。
- **负责任 AI 考量** – 实施保障措施（如 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails)）和监控机制，有助于确保生成式 AI 模型得到负责任且合乎伦理的使用，包括偏差检测、内容审核和人工监督。尽管 AWS Health Equity Initiative 申请表收集了客户信息（如姓名、电子邮件地址和运营国家/地区），但在发送给启用 Amazon Bedrock 的工具时，这些信息被系统性地省略，以避免模型产生偏差并保护客户数据。

通过使用全套 AWS 服务并遵循安全性、可扩展性和负责任 AI 的最佳实践，组织可以构建满足其特定要求的生产就绪方案，同时实现合规、可靠和成本效益。

## 结论

Amazon Bedrock 结合有效的 prompt engineering，使 AWS SRI 能够在数天而非数周内完成资助提案评审并向客户发放资助。本项目所培养的技能——例如使用 Streamlit 构建 Web 应用、与 DynamoDB 等 NoSQL 数据库集成，以及定制生成式 AI prompt——具有高度可迁移性，适用于广泛的行业和用例。
