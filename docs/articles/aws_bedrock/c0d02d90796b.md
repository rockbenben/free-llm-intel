# 使用 Amazon Bedrock AgentCore 构建设备管理 agent

物联网（Internet of Things，IoT）设备的激增，改变了我们与周围环境交互的方式，从家庭到工业场景皆是如此。然而，随着联网设备数量的增长，管理这些设备的复杂度也随之上升。传统的设备管理界面往往要求用户在多个应用之间来回切换，每个应用都有各自的 UI 和学习曲线。这种割裂给试图监控和控制自身 IoT 环境的用户带来了摩擦。

本文介绍如何使用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 构建一套对话式设备管理系统。借助该方案，用户可以通过自然语言管理自己的 IoT 设备，并通过一个 UI 完成查看设备状态、配置 WiFi 网络、监控用户活动等任务。若要进一步了解 Amazon Bedrock AgentCore 如何借助多种框架和模型，安全地大规模部署和运行高效的 agent，请参阅[帮助客户大规模交付生产级 AI agent](https://aws.amazon.com/blogs/machine-learning/enabling-customers-to-deliver-production-ready-ai-agents-at-scale/)。

## 设备管理的挑战

管理现代化的 IoT 环境需要应对诸多挑战，而这些挑战会阻碍用户体验和技术落地。界面割裂迫使用户在不同设备的多款应用和管理工具之间来回周旋，技术复杂度则可能让即便是基础的配置任务，对非专业人士来说也显得令人生畏。此外还有可见性受限的问题——无法全面监控设备状态，以及用户管理能力不足——难以追踪设备的使用模式。

这些痛点叠加在一起，给想要有效实施和维护 IoT 方案的用户造成了显著的摩擦。

## 方案概览

这套使用 agent 的对话式 AI 方案，通过统一的对话界面把设备管理任务集中到单一入口，从而为 IoT 的复杂性提供了一种全面的应对方式。用户无需在技术菜单中层层导航，而是通过自然语言交互完成复杂操作，同时获得对已联网设备的全面可见性，并把复杂的配置任务转化为直截了当的对话。系统提供以下核心能力：用于库存控制和状态监控的设备管理、用于简化网络配置的 WiFi 网络管理、用于访问控制的用户管理，以及用于按时间分析用户交互的活动追踪。这种无缝的管理体验把监控盲区降到最低，并就使用模式和潜在安全问题提供有价值的洞察，在有效消除 IoT 落地常见障碍的同时，保持整个网络中恰当的系统授权。

## 架构概览

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/02/device-management-architecture-5.png)

设备管理系统采用模块化架构，使用了多项 AWS 服务。该架构由以下组件构成：

- **用户与应用界面** – 用户通过一个作为前端界面的 Web 应用与系统交互。
- **基础模型** – 本系统使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 中的多种基础模型（foundation models，FMs）来支撑自然语言理解与生成能力。
- **Amazon Bedrock AgentCore Gateway** – 该特性作为已认证请求的安全入口，在把请求路由到相应目标之前先校验 bearer token。
- **Amazon Bedrock AgentCore Identity** – 该特性管理 agent 的身份与权限，控制 agent 可以代表用户执行哪些操作。
- **Amazon Bedrock AgentCore Memory** – 该特性同时支持短期记忆和长期记忆，在单次会话内维持即时的对话上下文，并跨会话存储持久的洞察与偏好。这使得 agent 能够提供一致且具备上下文感知的回复，而开发者无需管理复杂的记忆基础设施。
- **Amazon Bedrock AgentCore Observability** – 该特性监控 agent 性能、追踪指标，并就系统使用情况和行为提供洞察，用于调试与优化。
- **Amazon Bedrock AgentCore Runtime** – 这一安全、无服务器的环境支持用开源框架构建的 AI agent。它为每个用户会话分配隔离容器，从而保持完全的会话隔离，使长时间运行的有状态交互也能被可扩展且安全地管理。
- **Amazon Cognito** – [Amazon Cognito](https://aws.amazon.com/cognito/) 通过 bearer token 的生成与校验来处理用户认证，为系统的安全访问提供便利。
- **Amazon DynamoDB** – [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 将系统数据存放在五张表中。
- **AWS Lambda** – 该方案把网关连接到执行具体设备管理操作的 [AWS Lambda](https://aws.amazon.com/lambda) 函数。Lambda 承载设备管理的业务逻辑，实现了七个核心工具。

该架构实现了从用户提问到返回响应的无缝流转：用户通过应用提交自然语言请求，请求经 Amazon Cognito 认证后由 Amazon Bedrock AgentCore Runtime 处理。运行时确定应当调用哪个工具，并把请求经网关发送给 Lambda 函数，由后者按需查询或更新 DynamoDB。结果沿同一条路径返回，运行时基于检索到的数据生成自然语言响应。

详细的部署说明请参阅 [GitHub 仓库](https://github.com/awslabs/agentcore-samples/tree/main/02-use-cases/01-conversational-agents/device-management-agent)。

## 设备管理 agent 的核心功能

设备管理系统使用 Lambda 实现了七个设备管理必备工具，包括列出设备、获取设置、管理 WiFi 网络和监控用户活动，全部由 agent 按需调用。这些功能由我们在 DynamoDB 中灵活的非关系型数据库架构支撑，该架构包含五张不同的表——Devices、DeviceSettings、WifiNetworks、Users 和 UserActivities——分别存储专门的数据，以维护完整的系统记录。这些组件共同构成坚实的基础，既能实现高效的设备管理，又能保留系统活动的详细审计轨迹。

## 性能与安全考量

该方案在强大的并发处理能力与全面的保护措施之间取得平衡。设备管理系统通过自动扩缩的 Lambda 函数、不随数据量变化而波动的 DynamoDB 性能，以及遇到限流时采用指数退避的智能重试逻辑，高效处理多个并发请求。为了在数百个工具之间横向扩展，Amazon Bedrock AgentCore Gateway 的语义搜索能力可按含义高效且相关地发现工具，即使在大规模场景下也能促成快速准确的响应。

系统实施了业界领先的安全实践，包括 Amazon Cognito 认证、Amazon Bedrock AgentCore Identity、通过网关与 Lambda 两级权限校验实现的分层访问控制、对静态数据和传输中数据的全面加密，以及用于帮助防范 prompt 注入攻击并保持交互安全的 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/)。

## 结语

本文介绍的设备管理系统使用 Amazon Bedrock AgentCore，通过对话式 AI 改造 IoT 管理，打造出一个直观的界面，让复杂的设备操作变成简单的对话。其可组合、可复用、解耦的 agentic 架构通过内建的安全、可扩展部署与无缝集成能力，减轻了「无差别的重体力活」。通过把大语言模型与 AWS 基础设施结合，该方案提供了企业级能力，又不让开发者背上基础设施管理的负担。主要收益包括：通过自然语言交互简化用户体验、以统一界面提升运营效率、获得全面的设备可见性，以及与 AI 进展同步演进、经得起未来考验的架构。系统与模型无关的做法使其能够随着新基础模型的出现而持续改进，而稳健的安全与可观测性特性帮助组织放心部署可扩展的新一代设备管理方案，并贴合各自特定的 IoT 环境。
