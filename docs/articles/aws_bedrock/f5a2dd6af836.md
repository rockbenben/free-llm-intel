# 用 Amazon Nova Sonic 与动态菜单显示实现语音 AI 驱动的 drive-thru 点餐

人工智能（[AI](https://aws.amazon.com/ai/)）正在改变快餐服务（QSR）行业，尤其是在效率与客户满意度交汇的 drive-thru 场景。传统系统在服务交付上造成显著障碍，从人员配置受限、订单准确性问题，到不同门店之间客户体验不一致。这些挑战叠加劳动力成本上升和需求波动，促使行业寻求创新方案。

在本文中，我们将演示如何使用 [Amazon Nova Sonic](https://aws.amazon.com/ai/generative-ai/nova/speech/) 和各项 AWS 服务实现一套快餐店（QSR）drive-thru 方案。我们会走一遍构建智能系统的过程，该系统把语音 AI 与交互式菜单显示结合起来，并提供技术洞察与实施指导，帮助餐厅将其 drive-thru 运营现代化。

对快餐店而言，高峰时段的赌注尤其高：漫长的等待时间和顾客与员工之间的沟通失误会显著影响经营表现。常见痛点包括订单准确性问题、不同班次之间服务质量波动，以及应对顾客需求突增的能力有限。现代消费者期待与数字点餐系统一样的无缝、高效服务，这为语音 AI 技术带来了前所未有的机会，可支撑 7×24 小时可用性和一致的服务质量。

Amazon Nova Sonic 是 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) 家族中的[基础模型（FM）](https://aws.amazon.com/what-is/foundation-models/)，专为语音应用而设计。它通过 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 提供，开发者可以使用 Nova Sonic 构建这样的应用：理解口语、处理复杂的会话式交互，并生成恰当的回复以实现实时客户互动。这一创新的语音到语音（speech-to-speech）模型通过以下方式应对传统语音应用的挑战：

- 准确识别带各种口音的流式语音，并对背景噪声具备鲁棒性
- 根据用户的语调和情绪调整语音回复
- 双向流式语音 I/O，用户感知延迟低
- 优雅的中断处理与对话中自然的轮流发言
- 业界领先的性价比

与 AWS 无服务器服务集成后，Nova Sonic 可提供自然、类人的语音交互，帮助改善 drive-thru 体验。该架构构建了一个具成本效益的系统，通过智能自动化同时提升服务一致性和运营效率。

## **解决方案概述**

我们的语音 AI drive-thru 方案构建了一套智能点餐系统，把实时语音交互与健壮的后端基础设施结合起来，带来自然的客户体验。系统实时处理语音，理解各种口音和说话风格，并能应对 drive-thru 环境中常见的背景噪声。将语音指令与交互式菜单显示集成，既增强了用户反馈，又通过减少口头交互来简化点餐流程。

系统构建在 AWS 无服务器架构之上，集成了以下关键组件：[Amazon Cognito](https://aws.amazon.com/cognito/) 用于身份验证并支持[基于角色的访问控制](https://docs.aws.amazon.com/cognito/latest/developerguide/role-based-access-control.html)，[AWS Amplify](https://aws.amazon.com/amplify/) 用于数字菜单板，[Amazon API Gateway](https://aws.amazon.com/api-gateway/) 用于打通对 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 表的访问，[AWS Lambda](https://aws.amazon.com/lambda/) 函数配合 [Amazon Nova Canvas](https://aws.amazon.com/ai/generative-ai/nova/creative/) 生成菜单图片，以及 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）配合 [Amazon CloudFront](https://aws.amazon.com/cloudfront/) 用于图片存储与分发。

下面的架构图展示了这些服务如何互连，以支撑顾客与数字菜单板之间的自然对话，并编排从驶入 drive-thru 到完成下单的整个顾客旅程。

下面我们逐一考察每个组件如何协同工作，为这套智能点餐系统提供动力。

## **使用 AWS CloudFormation 部署方案资源**

请在 Amazon Bedrock [可用](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)且支持以下模型的 AWS Region 中部署 CloudFormation 模板：Amazon Nova Sonic 与 Amazon Nova Canvas。

本方案由两个 CloudFormation 模板组成，它们协同创建一个完整的餐厅 drive-thru 点餐系统。`nova-sonic-infrastructure-drivethru.yaml` 模板建立基础 AWS 基础设施，包括 Cognito 用户身份验证、带 CloudFront CDN 用于菜单图片的 S3 存储、用于菜单项和客户数据的 DynamoDB 表，以及配置了正确 CORS 的 API Gateway 端点。`nova-sonic-application-drivethru.yaml` 模板在此基础上部署一个 Lambda 函数：它向系统填充一套完整内置的 drive-thru 菜单（含汉堡、鸡翅、薯条、饮品、酱料和套餐），同时使用 Amazon Nova Canvas AI 模型为每个菜单项自动生成专业的食物摄影图片，并存入 S3 存储桶，通过 CloudFront 分发。

在部署第一个 CloudFormation 模板 `nova-sonic-infrastructure-drivethru.yaml` 时，你需要指定以下参数：

- 堆栈名称
- Environment – 部署环境：dev、staging 或 prod（默认 dev）
- UserEmail – 用户账户的有效电子邮箱地址（必填）

重要：部署前，你必须先在 Amazon Bedrock 控制台中启用对所选 Amazon Nova Sonic 模型和 Amazon Nova Canvas 模型的访问。

使用 AWS 资源会产生费用。部署完成后，将部署以下资源：

- Amazon Cognito 资源：[用户池](https://docs.aws.amazon.com/cognito/latest/developerguide/cognito-user-pools.html) – `CognitoUserPool` [应用客户端](https://docs.aws.amazon.com/cognito/latest/developerguide/user-pool-settings-client-apps.html) – `AppClient` [身份池](https://docs.aws.amazon.com/cognito/latest/developerguide/identity-pools.html) – `CognitoIdentityPool` [组](https://docs.aws.amazon.com/cognito/latest/developerguide/cognito-user-pools-user-groups.html) – `AppUserGroup` [用户](https://docs.aws.amazon.com/cognito/latest/developerguide/managing-users.html) – `AppUser`

- [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）资源：[IAM 角色](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html)：`AuthenticatedRole` `DefaultAuthenticatedRole` `ApiGatewayDynamoDBRole` `LambdaExecutionRole` `S3BucketCleanupRole`

- Amazon DynamoDB 表：`MenuTable` – 存储菜单项、定价和定制选项 `LoyaltyTable` – 存储客户忠诚度信息与积分 `CartTable` – 存储进行中会话的购物车数据 `OrderTable` – 存储已完成和待处理的订单 `ChatTable` – 存储已完成的聊天详情

- Amazon S3、CloudFront 和 AWS WAF 资源：`MenuImagesBucket` – 用于存储菜单项图片的 S3 存储桶 `MenuImageCloudFrontDistribution` – 用于全球内容分发的 CloudFront distribution `CloudFrontOriginAccessIdentity` – CloudFront 与 S3 之间的安全访问 `CloudFrontWebACL` – 为 CloudFront distribution 提供带安全规则的 WAF 防护

- Amazon API Gateway 资源：REST API – `app-api`，带 Cognito 授权的 API 资源与方法：`/menu`（GET、OPTIONS） `/loyalty`（GET、OPTIONS） `/cart`（POST、DELETE、OPTIONS） `/order`（POST、OPTIONS） `/chat`（POST、OPTIONS） API 部署到指定的环境阶段

- AWS Lambda 函数：`S3BucketCleanupLambda` – 在堆栈删除时清理 S3 存储桶

- CloudFormation 自定义资源：`S3BucketCleanup` – 触发 `S3BucketCleanupLambda`

部署 CloudFormation 模板后，请从 AWS CloudFormation 控制台的 Outputs 标签页复制以下内容，供配置前端应用时使用：

- `cartApiUrl`
- `loyaltyApiUrl`
- `menuApiUrl`
- `orderApiUrl`
- `chatApiUrl`
- `UserPoolClientId`
- `UserPoolId`
- `IdentityPoolId`

下面的截图展示了 **Outputs** 标签页的样子。

![Nova Sonic Drive Thru 方案 CFN 输出](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/08/2.CFN-Output.jpg)

在部署第二个 CloudFormation 模板 `nova-sonic-application-drivethru.yaml` 时，你需要指定以下参数：

- InfrastructureStackName – 该堆栈名称与你此前用 `nova-sonic-infrastructure-drivethru.yaml` 部署的堆栈名称一致

## **用户身份验证**

该方案使用 Amazon Cognito 的用户池和身份池，为餐厅的数字菜单板实现安全的、基于角色的访问控制。用户池通过 `AppUserGroup` 处理身份验证和组管理，身份池则提供映射到特定 IAM 角色（包括 `AuthenticatedRole`）的临时 AWS 凭证。系统确保只有经过验证的数字菜单板用户才能访问应用，并与菜单 API、购物车管理、订单处理和忠诚度服务交互，同时还提供对 Amazon Bedrock 的安全访问。这为顾客和餐厅运营方同时带来了健壮的安全性和直观的点餐体验。

## **无服务器数据管理**

该方案实现了无服务器 API 架构，使用 Amazon API Gateway 创建单一的 REST API `(app-api)`，打通前端界面与后端服务之间的通信。该 API 包含五个资源端点 `(/menu, /loyalty, /cart, /chat,/order)`，具备基于 Cognito 的身份验证，并直接集成 DynamoDB 完成数据操作。后端使用五张 DynamoDB 表：`MenuTable` 用于菜单项与定价，`LoyaltyTable` 用于客户画像与忠诚度积分，`CartTable` 用于进行中的购物会话，`ChatTable` 用于捕获聊天历史，`OrderTable` 用于订单跟踪与历史。该架构在规模化下提供快速一致的性能，全局二级索引可按客户 ID 和订单状态高效查询，从而优化 drive-thru 运营。

## **菜单与图片的生成和分发**

该方案使用 Amazon S3 和 CloudFront 实现菜单项图片的安全全球内容分发。CloudFormation 模板创建 `MenuImagesBucket`，并通过 CloudFront Origin Access Identity 限制访问，确保图片经 CloudFront distribution 安全提供、在世界各地快速加载。AWS Lambda 通过 `DriveThruMenuLambda` 函数支撑 AI 驱动的内容生成，该函数自动填充示例菜单数据，并使用 Amazon Nova Canvas 生成高质量的菜单项图片。这个无服务器函数在堆栈部署期间执行，为菜单项（从经典汉堡到特色鸡翅）生成专业的食物摄影图片，使整个菜单的视觉呈现保持一致。该 Lambda 函数与 DynamoDB 集成以存储生成的图片 URL，并使用 S3 做持久化存储，形成了一套完整的自动化工作流，可按需扩展，同时通过按使用量付费优化成本。

## **语音 AI 处理**

该方案使用 Amazon Nova Sonic 作为核心语音 AI 引擎。数字菜单板通过安全的 WebSocket 连接与 Amazon Nova Sonic 建立直接集成，从而即时处理顾客的语音输入并转换为结构化的点餐数据。CloudFormation 模板为 `AuthenticatedRole` 配置了访问 amazon.nova-sonic-v1:0 基础模型的 IAM 权限，使已通过身份验证的用户能够与语音 AI 服务交互。Nova Sonic 处理复杂的自然语言理解和意图识别，处理菜单询问、订单修改和项目定制等顾客请求，并在整个点餐过程中保持会话上下文。这种直接集成把延迟问题降到最低，为顾客带来可与人工交互媲美的自然会话式点餐体验，同时在各个 drive-thru 门店保持可靠服务。

## **托管数字菜单板**

AWS Amplify 以可扩展的前端应用形式托管并交付数字菜单板界面。该界面通过 CloudFront 显示 AI 生成的菜单图片，并从 DynamoDB 获取实时定价，针对 drive-thru 环境做了优化。这个基于 React 的应用在高峰时段自动扩展，利用 CloudFront 提供的全球内容分发网络实现快速加载。它与 Amazon Cognito 集成完成身份验证，与 Amazon Nova Sonic 建立 WebSocket 连接以进行语音处理，并使用 API Gateway 端点进行菜单和订单管理。这套无服务器方案在保持高可用的同时，随着顾客通过语音指令交互提供实时的视觉更新。

## **清理**

如果你决定不再使用该方案，可以按以下步骤移除它、它通过 AWS CloudFormation 部署的相关资源，以及 Amplify 部署：

- 删除 CloudFormation 堆栈：在 AWS CloudFormation 控制台中，在导航窗格选择 Stacks。找到你在部署 `nova-sonic-application-drivethru.yaml` 过程中创建的堆栈（你为它指定了名称）。选择该堆栈并选择 Delete。对 `nova-sonic-infrastructure-drivethru.yaml` 重复此操作

- 删除 Amplify 应用及其资源。相关说明请参阅[清理资源](https://aws.amazon.com/getting-started/hands-on/build-web-app-s3-lambda-api-gateway-dynamodb/module-six/)。

## **结语**

使用 Amazon Nova Sonic 的语音 AI drive-thru 点餐系统，为餐厅提供了一个应对常见运营挑战的实用方案，包括人员配置受限、订单准确性问题和高峰时段瓶颈。构建在 AWS 服务之上的无服务器架构——Amazon Cognito 负责身份验证、API Gateway 负责数据通信、DynamoDB 负责存储、AWS Amplify 负责托管——创造了一个可扩展的系统，能应对需求波动并保持一致性能。该系统通过 API Gateway 与 DynamoDB 的直接集成，支持菜单管理、购物车功能、忠诚度计划和订单处理等餐厅核心运营。对于希望把 drive-thru 运营现代化的餐厅，该方案带来可衡量的收益，包括缩短等待时间、提升订单准确性和运营效率。按使用量付费的定价模式和自动扩展有助于控制成本，同时支撑业务增长。随着客户期望转向更高效的服务体验，落地语音 AI 技术为餐厅带来竞争优势，并使其在餐饮服务行业未来的技术发展中占据有利位置。
