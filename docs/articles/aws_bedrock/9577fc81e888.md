# 借助 Amazon Bedrock AgentCore Runtime 直接代码部署实现更快迭代

[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 是一个 agentic 平台，用于安全地大规模构建、部署与运营高效的 agent。[Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 是 Bedrock AgentCore 的一项完全托管服务，提供低延迟的无服务器环境来部署 agent 与工具。它提供会话隔离，支持包括流行开源框架在内的多种 agent 框架，并能处理多模态工作负载与长时间运行的 agent。

AgentCore Runtime 支持[基于容器的部署](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-toolkit.html)，其中容器定义写在 Dockerfile 里，agent 被打包为容器镜像。已经具备容器构建与部署流水线的客户能从中受益，因为 agent 部署可以集成到现有流水线中。

如今，AgentCore Runtime 推出了第二种部署 agent 的方法——直接代码部署（面向 Python）。agent 代码及其依赖可以打包为 zip 归档，从而不再需要 Docker 定义与 ECR 依赖。这让开发者能够轻松地进行原型验证并加快迭代。对于在部署 agent 时不想操心 Docker 专业知识与容器基础设施的客户，这种方式非常合适。

本文演示如何使用直接代码部署（面向 Python）。

## 认识 AgentCore Runtime 直接代码部署

在容器部署方式下，开发者需要编写 Dockerfile、构建兼容 ARM 的容器、管理 ECR 仓库，并在代码变更时上传容器。在已经建立容器 DevOps 流水线来自动化部署的场景中，这种方式效果很好。

不过，希望获得完全托管部署的客户可以从直接代码部署中受益，它能显著提升开发者的时间效率与生产力。直接代码部署为从快速原型验证 agent 能力到大规模部署生产工作负载，提供了一条安全且可扩展的前进路径。

我们将讨论每种部署选项的优势，帮助你为自己的用例选择合适的方式。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/04/Screenshot-2025-11-04-at-10.15.09 AM.png)

采用直接代码部署时，开发者将代码与依赖打成 zip 归档，上传至 [Amazon S3](https://aws.amazon.com/s3/)，并在 agent 配置中配置该存储桶。使用 [AgentCore 起始工具包](https://github.com/aws/bedrock-agentcore-starter-toolkit)时，工具包会处理依赖检测、打包与上传，带来大为简化的开发者体验。直接代码部署同样支持通过 API 使用。

下面从高层对比两种方式的部署步骤：

### 基于容器的部署

基于容器的部署方式包含以下步骤：

- 创建 Dockerfile
- 构建兼容 ARM 的容器
- 创建 ECR 仓库
- 上传至 ECR
- 部署到 AgentCore Runtime

### 直接代码部署

直接代码部署方式包含以下步骤：

- 将代码与依赖打包为 zip 归档
- 上传至 S3
- 在 agent 配置中配置该存储桶
- 部署到 AgentCore Runtime

## 如何使用直接代码部署

下面用一个通过 [Strands Agents SDK](https://strandsagents.com/latest/) 创建、并使用 [AgentCore 起始工具包](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-toolkit.html)部署的 agent，来说明直接代码部署如何运作。

### 前提条件

开始之前，请确保已具备以下条件：

- Python 3.10 至 3.13 中的任一版本
- 已安装你惯用的包管理器。例如，我们使用 [uv](https://github.com/astral-sh/uv) 包管理器。
- 用于创建与部署 agent 的 AWS 账户
- 对 Anthropic Claude Sonnet 4.0 的 [Amazon Bedrock 模型访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)

**第 1 步：初始化项目**

使用 uv 包管理器创建一个新的 Python 项目，然后进入项目目录：

```
uv init <project> --python 3.13
cd <project>
```

**第 2 步：为项目添加依赖**

安装项目所需的 Bedrock AgentCore 库与开发工具。在本例中，依赖通过 `.toml` 文件添加，也可以改为在 `requirements.txt` 文件中指定：

```
uv add bedrock-agentcore strands-agents strands-agents-tools
uv add --dev bedrock-agentcore-starter-toolkit
source .venv/bin/activate
```

**第 3 步：创建 agent.py 文件**

创建定义 AI agent 行为的主实现文件：

```
from bedrock_agentcore import BedrockAgentCoreApp 
from strands import Agent, tool 
from strands_tools import calculator  
from strands.models import BedrockModel 
import logging 

app = BedrockAgentCoreApp(debug=True) 

# Logging setup 
logging.basicConfig(level=logging.INFO) 
logger = logging.getLogger(__name__) 

# Create a custom tool  
@tool 
def weather(): 
     """ Get weather """  
     return "sunny" 

model_id = "us.anthropic.claude-sonnet-4-20250514-v1:0" 
model = BedrockModel( 
     model_id=model_id, 
) 

agent = Agent( 
     model=model, 
     tools=[calculator, weather], 
     system_prompt="You're a helpful assistant. You can do simple math calculation, and tell the weather." 
) 

@app.entrypoint 
def invoke(payload): 
     """Your AI agent function""" 
     user_input = payload.get("prompt", "Hello! How can I help you today?") 
     logger.info("\n User input: %s", user_input) 
     response = agent(user_input) 
     logger.info("\n Agent result: %s ", response.message) 
     return response.message['content'][0]['text'] 

if __name__ == "__main__": 
     app.run() 
```

**第 4 步：部署到 AgentCore Runtime**

配置并将 agent 部署到 AgentCore Runtime 环境：

```
agentcore configure --entrypoint agent.py --name <agent-name>
```

这会启动一个交互式会话，在其中配置用于上传 zip 部署包的 S3 存储桶，并选择部署配置类型（如下方配置所示）。要选择直接代码部署，请选择选项 1——Code Zip。

**部署配置**

选择部署类型：

- Code Zip（推荐）——简单、无服务器、无需 Docker
- Container——用于自定义运行时或复杂依赖

```
agentcore launch
```

该命令会创建 zip 部署包，将其上传到指定的 S3 存储桶，并在 AgentCore Runtime 环境中启动 agent，使其准备好接收并处理请求。

为了测试该解决方案，我们向 agent 询问天气情况：

```
agentcore invoke '{"prompt":"How is the weather today?"}'
```

首次部署大约需要 30 秒完成，但后续对 agent 的更新可以受益于精简的直接代码部署流程，耗时应当不到一半，从而支持开发期间更快的迭代周期。

### 何时选择直接代码而非基于容器的部署

我们来看看几个维度上直接代码与基于容器部署有何不同。这有助于你选择适合自己的选项：

- **部署流程**：直接代码将 agent 以 zip 文件部署，无需 Docker、ECR 或 CodeBuild。基于容器的部署使用 Docker 与 ECR，可完全掌控 Dockerfile。
- **部署时间：**尽管首次部署 agent 时差别不大，但后续更新在使用直接代码部署时要快得多（从容器平均 30 秒缩短到直接代码部署约 10 秒）。
- **产物存储：**直接代码将 ZIP 包存储在 S3 存储桶中。基于容器的部署将 Docker 镜像存储在 Amazon ECR 中。由于产物存储在服务账户中，直接代码部署会按 [标准 S3 存储费率](https://aws.amazon.com/s3/pricing/)产生存储费用（自 2026 年 2 月 27 日起）。基于容器的部署则在你自己的账户中产生 Amazon ECR 费用。
- **自定义能力**：直接代码部署通过基于 ZIP 的打包支持自定义依赖，而基于容器的方式依赖 Dockerfile。
- **包体积**：直接代码部署将包体积限制为 250MB，而基于容器的包最大可达 2GB。
- **语言支持：**直接代码目前支持 Python 3.10、3.11、3.12 与 3.13。基于容器的部署支持多种语言与运行时。

我们的总体建议是：

**基于容器的部署是正确选择**——当你的包超过 250MB、已有容器 CI/CD 流水线，或需要高度专用的依赖与自定义打包要求时。如果需要多语言支持、自定义系统依赖，或希望在自己的账户中直接掌控产物存储与版本管理，请选择容器。

**直接代码部署是正确选择**——当你的包小于 250MB、使用 Python 3.10-3.13 与 LangGraph、Strands 或 CrewAI 等常见框架，并且需要快速原型验证与快速迭代周期时。如果你的构建流程简单、没有复杂依赖，并且希望去掉 Docker/ECR/CodeBuild 的配置，请选择直接代码。

**混合方式对许多团队都很有效**——用直接代码进行快速原型验证与实验，在快速迭代与简单配置能加速开发的地方发挥作用；随后当包体积、多语言要求或专用构建流程提出要求时，再升级到容器用于生产。

## 结语

Amazon Bedrock AgentCore Runtime 直接代码部署让 agent 的迭代开发周期更进一步加快，同时仍可享受企业级安全与部署规模。开发者现在可以直接部署代码来快速原型验证与迭代，无需创建容器。要开始使用 AgentCore Runtime 直接代码部署，请访问 [AWS 文档](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-code-deploy.html)。
