# 第 3 部分：使用 Amazon Bedrock 与 Amazon Bedrock Data Automation 的多 agent 协作构建面向投资研究的 AI 助手

在金融服务行业，分析师需要在结构化数据（例如时间序列的价格信息）、非结构化文本（例如 SEC 文件和卖方研究报告）以及音视频内容（财报电话会和演示文稿）之间来回切换。每种格式都需要不同的分析方法和专用工具，造成工作流效率低下。在此之上，行业状况快速演变、决策窗口狭窄，还带来了巨大的时间压力。分析延迟可能意味着错失机会，或未能识别正在出现的风险，并可能造成重大的财务后果。

AI 助手可以通过自动化例行的数据收集与处理任务、呈现相关洞察，让分析师专注于更高价值的活动，从而提升生产力。然而，单个 AI agent 难以应对复杂、多步骤的投资研究工作流，无法有效处理全部专业化任务。这正是多 agent 协作带来的进步之处。通过创建在特定任务与功能上表现卓越的专用 AI 子 agent，并在 AI supervisor agent 的协调框架下把它们组合使用，我们就可以应对投资研究工作流的全部复杂性。supervisor agent 能够智能地拆解复杂查询、把专门任务分派给子 agent，并把它们的输出综合成完整答案——这与现实世界中的研究团队运作方式类似。这种方法的好处相当可观，源于分布式问题求解与专业化分工：借助专业知识提升准确性，通过增加新的 agent 能力而不必重建整个系统来增强可扩展性，并因每个专用 agent 的推理过程都可以被追踪和验证而获得更高的透明度。

[Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 利用[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM）、API 和数据的推理能力来拆解用户请求、收集相关信息并高效完成任务。借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的[多 agent 协作](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-announces-general-availability-of-multi-agent-collaboration/)能力，你可以构建、部署和管理多个 AI agent，让它们协同处理需要专业技能的各种复杂多步骤任务。[Amazon Bedrock Data Automation](https://aws.amazon.com/bedrock/bda/)（BDA）能够为你的 AI 应用从文档、图像、音频和视频等非结构化多模态内容中生成有价值的洞察，并且可以在为[检索增强生成](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）工作流设置知识库时用作解析器（parser）。

本文介绍如何使用 Amazon Bedrock 的多 agent 协作能力构建一个多 agent 投资研究助手。我们的解决方案展示了如何让一组专用 AI agent 协同分析财经新闻、评估股票表现、优化投资组合配置，并交付全面的投资洞察——所有这些都通过统一的自然语言界面进行编排。在多模态数据的 RAG 工作流中设置知识库时，我们使用 BDA 作为解析器。Amazon Bedrock 中的 Anthropic Claude 模型被用作与 supervisor agent 和各子 agent 关联的[大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLM）。

## 解决方案概览

该多 agent 投资研究助手由一个 supervisor agent 和三个子 agent（定量分析 agent、新闻 agent 和智能摘要 agent）组成，它们在同一协调框架中协同工作，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/19/multi-agent-1.jpg)

supervisor agent 使用你提供的说明来理解每个协作者 agent 的结构与角色。supervisor agent 通过拆解用户 prompt、把子任务分派给专用子 agent，并汇总它们的输出以生成最终回答，来编排整个投资研究流程。每个子 agent 都被配置为执行如下专门任务：

- **定量分析 agent **  **功能** – 由 stock-query 和 portfolio-optimization 两个 action group 支撑。**职责** – 查询并分析历史股票数据，并基于用户输入（例如股票代码或投资金额）构建优化的投资组合配置。
- **新闻 agent**  **功能** – 由 `web_search` action group 和 `financial_analysis_KB` 知识库支撑。**职责** – 从知识库中搜索并检索相关财务数据（例如财报和监管申报文件）作为上下文。如果知识库中不存在所需信息，则构造 Web 查询。处理与公司财务分析、业绩驱动因素和管理层评论相关的查询。
- **智能摘要 agent**  **功能** – 使用 LLM 能力并配合特定的 prompt 说明，没有自定义 action group。**职责** – 接收其他子 agent 的输出（例如最新新闻和财务数据），并把信息综合成结构化的投资洞察。将财报等长文本或文档摘要为简明的洞察。

多 agent 协作的工作方式如下：

- 用户向多 agent 投资研究助手提出一个高层次的研究查询。
- supervisor agent 把查询拆解为子任务，并按需并行或顺序地编排和调用相关子 agent：  新闻 agent 用于检索财务报告或数据  定量分析 agent 用于股票数据分析  智能摘要 agent 用于摘要冗长文本
- supervisor agent 结合原始查询上下文，汇总各子 agent 的输出。
- supervisor agent 把汇总后的信息传给 LLM，以生成最终的研究洞察。

该架构利用不同专用 agent 的优势，全面覆盖投资研究的各个方面，并由 supervisor agent 提供智能编排。

## 技术架构

下图是技术架构。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/15/technical.jpg)

技术架构的部分关键组件及相关代码如下：

- **使用 Amazon Bedrock Data Automation (BDA) 处理数据** – 以下代码通过 `boto3` 中的 `bda-runtime` 客户端，使用 `invoke_data_automation_async()` 方法异步调用一个 BDA 作业：  `bda_response = bda_runtime_client.invoke_data_automation_async( inputConfiguration={ "s3Uri": s3_uri_input }, outputConfiguration={ "s3Uri": s3_uri_output }, )`
- **使用工具定义并构建子 agent** – 以下代码使用 `Agent.create.` 创建一个子 agent。它定义了两个 Lambda 工具——一个用于获取历史股票数据，另一个用于运行投资组合优化——然后把它们与该子 agent 的角色、目标、说明以及底层 FM 一并注册。  `quantitative_analysis_agent = Agent.create( name="quantitative_analysis_agent", role="Financial Data Collector", goal="Retrieve real-time and historic stock prices as well as optimizing a portfolio given tickers.", instructions="""Specialist in real-time financial data extraction and portfolio optimization. ...""", tools=[ # Stock Data Lookup Tool { "code": stock_data_lookup_arn, "definition": { "name": "stock_data_lookup", "description": "Gets the 1-month stock price history for a given stock ticker, formatted as JSON.", "parameters": { "ticker": {"description": "The ticker to retrieve price history for", "type": "string", "required": True} }, }, }, ], llm=LLM, )`

- **定义并构建 supervisor agent（多 agent 投资研究助手）** – 以下代码使用 `SupervisorAgent.create` 创建一个 supervisor agent。它定义了协作 agent（子 agent），并把它们与该 supervisor agent 的角色、目标、说明以及底层 FM 一并注册。  `investment_research_assistant = SupervisorAgent.create( "investment_research_assistant", role="Investment Research Assistant", goal="A seasoned investment research expert responsible for orchestrating subagents ...", collaboration_type="SUPERVISOR", instructions=f"""You are a Investment Research Assistant, a financial research supervisor overseeing multiple specialized agents. Your goal is to coordinate and synthesize their outputs to create a structured stock investment analysis. ...""", collaborator_agents=[ { "agent": "news_agent", "instructions": f"Always check the knowledge base (ID: {kb_id}) first. Use this collaborator for finding news and analyzing specific documents." }, { "agent": "quantitative_analysis_agent", "instructions": "Use this collaborator for retrieving stock price history and performing portfolio optimization." }, { "agent": "smart_summarizer_agent", "instructions": "Use this collaborator for synthesizing stock trends, financial data, and generating structured investment insights." } ], collaborator_objects=[news_agent, quantitative_analysis_agent, smart_summarizer_agent], llm=LLM, )`
- **调用 supervisor agent（多 agent 投资研究助手）** – 以下代码使用 `invoke` 方法，把定义好的请求作为 prompt 传入，并使用多 agent 协作架构从 supervisor agent 获取回答。  `request = """What's AMZN stock price doing over the last week and relate that to recent news""" print(f"Request:\n{request}\n") result = investment_research_assistant.invoke( request, enable_trace=True, trace_level="core", ) print(f"Final answer:\n{result}")`

## 结论

使用 Amazon Bedrock Agents 及其多 agent 协作功能构建的多 agent 投资研究助手，展示了金融专业人士如何利用 AI 增强分析能力。通过由 supervisor agent 编排、各专注于财务分析不同方面的专用 agent，我们构建了一个系统，它能够处理多样的数据类型、应用合适的分析技术，并针对复杂的投资查询综合出全面的洞察。其成果是一个 AI 助手，能够处理那些会让单 agent 系统不堪重负的多步骤财务分析工作流。

多 agent 协作的应用广泛延伸到整个金融行业，从股票研究、投资组合管理到风险评估与合规监控。需要多种专业技能和数据源的复杂财务工作流，都能从这种架构方法中受益。

该实现使用了关键的 AWS 服务，包括用于基础模型的 Amazon Bedrock、Amazon Bedrock Agents 的多 agent 协作能力、用于文档存储的 Amazon S3、用于向量搜索能力的 Amazon OpenSearch Serverless，以及用于专门操作的 Lambda 函数。这种无服务器架构提供了可扩展性，而知识库集成则提供来自财务文档的上下文，使 AI 的回答立足于事实数据。
