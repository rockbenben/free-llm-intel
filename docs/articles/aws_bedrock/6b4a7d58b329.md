# 访问 Amazon Bedrock 上的 OpenAI GPT 模型，并在泰国、马来西亚、新加坡、印度尼西亚和台湾进行全球跨区域推理

当需求超过本地容量时，单区域推理可能会受到限制。泰国、马来西亚、新加坡、印度尼西亚和台湾的团队需要访问超出该容量的最新 OpenAI 模型。 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 通过来自所有五个 AWS 区域的全球跨区域推理提供 OpenAI GPT-6 Sol 和 GPT-6 Luna，以及来自亚太地区（新加坡）的 GPT-6 Astra。本文向您展示如何配置调用、设置权限以及监控来自源区域的推理。

GPT-6 Sol、GPT-6 Luna 和 GPT-6 Astra 均可通过前面区域的全局跨区域推理在“bedrock-runtime”端点上使用。请参阅 Amazon Bedrock 用户指南中的[跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)。有关每个配置文件中源区域和目标区域的完整列表，请参阅[推理配置文件支持的区域和模型](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)。

在这篇文章中，我们介绍了全球跨区域推理配置文件，并使用 Converse API、OpenAI 兼容 API 和编码客户端从亚太地区（新加坡）调用它们。然后，我们介绍 [AWS Identity and Access Management](https://aws.amazon.com/iam/) (IAM) 和服务控制策略 (SCP) 配置、配额管理和监控。

## OpenAI GPT-6 的全局跨区域推理配置文件

GPT-6 系列提供三种模型，每种模型都可通过全局跨区域推理获得。

- GPT-6 Sol 为一周执行的复杂任务带来强大的推理和编码能力。
- GPT-6 Luna 使集中、可重复的大批量任务变得实用。
- GPT-6 Astra 处理复杂的推理、编码和长文档工作。

所有这三个都接受文本和图像输入、客户端工具使用和提示缓存。他们在推理努力上有所不同。 GPT-6 Sol 和 GPT-6 Luna 接受无、低、中、高、xhigh 和 max。 GPT-6 Astra 接受相同的级别，但没有。对于 GPT-6 Sol 和 GPT-6 Luna，请参阅[在 Amazon Bedrock 上使用 GPT-6 Sol 和 GPT-6 Luna 为日常工作带来更多智能](https://aws.amazon.com/blogs/machine-learning/bring-more-intelligence-to-everyday-work-with-gpt-6-sol-and-gpt-6-luna-on-amazon-bedrock/)。对于 GPT-6 Astra，请参阅[在 Amazon Bedrock 上使用 GPT-6 Astra 开展您最雄心勃勃的工作](https://aws.amazon.com/blogs/machine-learning/take-on-your-most-ambitious-work-with-gpt-6-astra-on-amazon-bedrock/)。

Global cross-Region inference routes requests across supported commercial AWS Regions where the model is deployed, giving you broad access to Amazon Bedrock capacity.您可以通过传递全局跨区域推理配置文件 ID 代替模型 ID 来调用它。您的源区域是您进行 API 调用的位置。 Amazon Bedrock 选择要处理的目标区域。账单、配额跟踪、AWS CloudTrail 和 Amazon CloudWatch 均保留在您的源区域中。

## Amazon Bedrock 上的 OpenAI 模型入门

Start with the prerequisites, then invoke any of the three profiles through the Converse API, the OpenAI-compatible APIs, or your existing coding client.

### 先决条件

- 有权调用配置文件的 IAM 身份。安全和权限部分中的 IAM 策略仅授予这些示例所需的内容。
- 您的源区域已激活。只有您呼叫的区域需要激活。您无需激活在 Amazon Bedrock 托管容量上运行的目标区域。新加坡 (`ap-southeast-1`) 是默认启用的区域。雅加达 (`ap-southeast-3`)、马来西亚 (`ap-southeast-5`)、泰国 (`ap-southeast-7`) 和台北 (`ap-east-2`) 是您必须首先激活的选择加入区域。有关更多信息，请参阅[在您的账户中启用或禁用 AWS 区域](https://docs.aws.amazon.com/accounts/latest/reference/manage-acct-regions.html)。
- 当前的 AWS 开发工具包或 CLI。 OpenAI 兼容示例还需要 OpenAI SDK 和 Amazon Bedrock 令牌生成器。使用“pip install boto3 openai aws-bedrock-token-generator”安装它们。

### 通过 Amazon Bedrock Runtime 调用 GPT-6 模型

每个模型在此终端节点上支持三种访问路径：Amazon Bedrock Converse API、OpenAI Responses API 和 OpenAI Chat Completions API。 OpenAI 兼容的 API 在“/openai/v1”路径上调用，而不是通过 AWS 开发工具包，并且终端节点接受签名版本 4 (SigV4) 或 Amazon Bedrock API 密钥。 Pass the global cross-Region inference profile ID as the `model` in every case.

**Converse API.** This example calls GPT-6 Sol from Asia Pacific (Singapore) and logs the response. Set `BEDROCK_PROFILE_ID` to `global.openai.gpt-6-luna` or `global.openai.gpt-6-astra` to switch models, or call `converse_stream` for streaming.
```
import logging
import os
import boto3

# AWS_REGION overrides this default, so set it to your source Region or unset it.
REGION = os.environ.get("AWS_REGION", "ap-southeast-1")
PROFILE_ID = os.environ.get("BEDROCK_PROFILE_ID", "global.openai.gpt-6-sol")
PROMPT = (
    "In three bullet points, explain when a workload should use "
    "cross-Region inference instead of calling a model in a single Region."
)

logging.basicConfig(format="%(levelname)s %(message)s")
log = logging.getLogger("bedrock-cris")
log.setLevel(logging.INFO)

client = boto3.client("bedrock-runtime", region_name=REGION)

# AccessDeniedException points at the IAM policy. ValidationException usually
# means the model ID is not a global cross-Region inference profile.
response = client.converse(
    modelId=PROFILE_ID,
    messages=[{"role": "user", "content": [{"text": PROMPT}]}],
    inferenceConfig={"maxTokens": 1024},
    # GPT-6 Sol and Luna accept none through max. GPT-6 Astra rejects none.
    additionalModelRequestFields={"reasoning": {"effort": "low"}},
)

# Any effort above none can prepend a reasoningContent block, so pick the text
# block by key rather than by position.
text = "".join(b["text"] for b in response["output"]["message"]["content"] if "text" in b)

log.info("Called %s from %s", PROFILE_ID, REGION)
log.info("Stop reason: %s", response["stopReason"])
log.info("Response:\n%s", text)
```
**OpenAI 聊天完成 API。** 将 OpenAI SDK 指向区域端点并传递相同的配置文件 ID。
```
import logging
import os
from aws_bedrock_token_generator import provide_token
from openai import OpenAI

REGION = os.environ.get("AWS_REGION", "ap-southeast-1")
PROFILE_ID = os.environ.get("BEDROCK_PROFILE_ID", "global.openai.gpt-6-sol")
PROMPT = "List three uses for a message queue."

logging.basicConfig(format="%(levelname)s %(message)s")
log = logging.getLogger("bedrock-cris")
log.setLevel(logging.INFO)

# provide_token mints a short-term key from your AWS credentials, valid up to 12 hours.
client = OpenAI(
    base_url=f"https://bedrock-runtime.{REGION}.amazonaws.com/openai/v1",
    api_key=provide_token(region=REGION),
)

response = client.chat.completions.create(
    model=PROFILE_ID,
    messages=[{"role": "user", "content": PROMPT}],
    max_completion_tokens=256,
)

log.info("Called %s from %s", PROFILE_ID, REGION)
log.info("Response:\n%s", response.choices[0].message.content)
```
迁移现有 OpenAI 客户端时：

- 在每个请求上设置模型参数，包括那些引用先前响应的请求。
- 使用支持的工具类型：“function”、“mcp”、“custom”、“namespace”和“tool_search”。
- 直接在客户端中配置推理配置文件 ID，而不是查询模型端点。

### 设置 ChatGPT 桌面应用程序和 Codex CLI

ChatGPT 桌面应用程序和 Codex CLI 共享 `~/.codex/config.toml`，因此一项更改涵盖了两者。在两个内置 Amazon Bedrock 提供程序中，只有“amazon-bedrock-runtime”接受推理配置文件。
```
model = "global.openai.gpt-6-astra"
model_provider = "amazon-bedrock-runtime"
[model_providers.amazon-bedrock-runtime.aws]
region = "ap-southeast-1"
```
SigV4 签名意味着没有密钥可以轮换。为非默认配置文件添加 `profile = "<your-profile>"`，并显式设置 `region`，因为否则客户端会回退到 `AWS_REGION`。用另一个配置文件 ID 替换“型号”以更改型号。

Codex 报告了这些配置文件的 272,000 个令牌窗口，这是其自己的捆绑数字，而不是服务限制。使用“model_context_window”提升它。此配置需要 Codex CLI 0.148 或更高版本。

## 安全和权限

Amazon Bedrock 提供一系列推理控制。其中两个在这里很重要。 AWS Identity and Access Management (IAM) 策略控制哪些角色可以调用哪些配置文件，服务控制策略 (SCP) 应用组织范围的控制，包括区域范围。本节涵盖了两者以及请求数据所在的位置。

### 全局跨区域推理的 IAM 权限

要通过全局跨区域推理配置文件调用任何这些模型，您的 IAM 策略需要四个语句：

- 访问源区域中的推理配置文件和项目/默认资源。
- 访问源区域中的基础模型，范围仅限于推理配置文件。
- 基础模型的与区域无关的 Amazon 资源名称 (ARN)“arn:aws:bedrock:::foundation-model/openai.gpt-6-sol”，其中“aws:RequestedRegion”设置为“unspecified”以允许跨区域路由。
- 用于 API 密钥身份验证的“bedrock:CallWithBearerToken”。

此 IAM 策略授予通过来自“ap-southeast-1”的全局跨区域推理调用 GPT-6 Sol 的权限。替换为您的 AWS 账户 ID，并将“ap-southeast-1”替换为您的源区域。
```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "GrantGlobalCrisProfileAndProjectAccess",
      "Effect": "Allow",
      "Action": ["bedrock:InvokeModel"],
      "Resource": [
        "arn:aws:bedrock:ap-southeast-1:<ACCOUNT>:inference-profile/global.openai.gpt-6-sol",
        "arn:aws:bedrock:ap-southeast-1:<ACCOUNT>:project/default"
      ],
      "Condition": {
        "StringEquals": { "aws:RequestedRegion": "ap-southeast-1" }
      }
    },
    {
      "Sid": "GrantGlobalCrisInRegionModelAccess",
      "Effect": "Allow",
      "Action": ["bedrock:InvokeModel"],
      "Resource": ["arn:aws:bedrock:ap-southeast-1::foundation-model/openai.gpt-6-sol"],
      "Condition": {
        "StringEquals": {
          "aws:RequestedRegion": "ap-southeast-1",
          "bedrock:InferenceProfileArn": "arn:aws:bedrock:ap-southeast-1:<ACCOUNT>:inference-profile/global.openai.gpt-6-sol"
        }
      }
    },
    {
      "Sid": "GrantGlobalCrisGlobalModelAccess",
      "Effect": "Allow",
      "Action": ["bedrock:InvokeModel"],
      "Resource": ["arn:aws:bedrock:::foundation-model/openai.gpt-6-sol"],
      "Condition": {
        "StringEquals": {
          "aws:RequestedRegion": "unspecified",
          "bedrock:InferenceProfileArn": "arn:aws:bedrock:ap-southeast-1:<ACCOUNT>:inference-profile/global.openai.gpt-6-sol"
        }
      }
    },
    {
      "Sid": "AllowBearerTokenAuth",
      "Effect": "Allow",
      "Action": ["bedrock:CallWithBearerToken"],
      "Resource": "*"
    }
  ]
}
```
如果您使用流式传输（“converse_stream”或“stream=True”），请将“bedrock:InvokeModelWithResponseStream”添加到前三个语句中的操作中。 Converse 授权为“bedrock:InvokeModel”。如果您仅使用 SigV4 凭据调用 Converse，请删除第四条语句。

要切换模型，请将“openai.gpt-6-sol”替换为“openai.gpt-6-luna”或“openai.gpt-6-astra”。有关完整参考，请参阅[全局跨区域推理的 IAM 策略要求](https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html)。

### 全局跨区域推理的服务控制策略注意事项

全局跨Region推理请求不携带Region名称。 Amazon Bedrock 将 `aws:RequestedRegion` 设置为 `unspecified`，因此 SCP 中的区域白名单会拒绝调用，并且错误仅指定策略类型，而不指定哪个策略。这是企业帐户中首次调用失败的常见原因。

不要扩大允许名单，而是限制例外范围。 Amazon Bedrock 在授权期间填充“bedrock:InferenceProfileArn”条件键，因此 SCP 可以允许这些配置文件，同时保持区域对其他所有内容的控制。下面的 SCP 就是这么做的。
```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyOutsideApprovedRegionsExceptBedrockInvoke",
      "Effect": "Deny",
      "NotAction": [
        "iam:*", "sts:*", "organizations:*", "account:*",
        "route53:*", "cloudfront:*", "waf:*", "wafv2:*", "shield:*",
        "support:*", "trustedadvisor:*", "health:*",
        "budgets:*", "ce:*", "cur:*", "tax:*", "billing:*",
        "bedrock:Invoke*"
      ],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": { "aws:RequestedRegion": ["ap-southeast-1"] }
      }
    },
    {
      "Sid": "DenyBedrockInferenceOutsideApprovedRegionsUnlessCris",
      "Effect": "Deny",
      "Action": ["bedrock:Invoke*"],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": { "aws:RequestedRegion": ["ap-southeast-1"] },
        "ArnNotLike": {
          "bedrock:InferenceProfileArn": [
            "arn:aws:bedrock:*:*:inference-profile/global.*"
          ]
        }
      }
    }
  ]
}
```
第一条语句对除 Amazon Bedrock 推理之外的所有服务强制实施区域许可名单。第二个拒绝在这些区域之外进行推理，除非它通过全局跨区域推理配置文件进行路由。对于地理配置文件，请将其前缀（例如“inference-profile/us.*”）添加到“ArnNotLike”列表中，因为地理请求携带真实的区域名称。将您的源区域保留在允许列表中，并将您的组织使用的全局服务添加到“NotAction”。

一个更粗鲁的替代方案是将“未指定”添加到现有的允许列表中，这可以工作，但会对所有其他服务打开相同的异常。有关即用型策略文件，请参阅 [aws-samples service-control-policy-examples 存储库](https://github.com/aws-samples/service-control-policy-examples/blob/main/Region-controls/Deny-access-to-AWS-based-on-the-requested-AWS-region-with-Bedrock-CRIS.json)。

### 数据保留和滥用检测

对于自动离线滥用检测，AWS 将分类器标记的流量保留最多 30 天并以编程方式进行处理。在跨区域推断下，保留发生在目标区域，对于全局配置文件来说，目标区域是部署模型的任何受支持的商业 AWS 区域。符合条件的客户可以通过其 AWS 客户团队请求完全零数据保留。有关更多信息，请参阅[Amazon Bedrock 滥用检测](https://docs.aws.amazon.com/bedrock/latest/userguide/abuse-detection.html) 和[数据保留](https://docs.aws.amazon.com/bedrock/latest/userguide/data-retention.html)。

如果您的组织有数据驻留要求，请尽早将其提交给您的风险和合规团队。请参阅这五个国家/地区的 [AWS 金融服务合规中心](https://aws.amazon.com/financial-services/security-compliance/compliance-center/) 国家/地区页面。我们建议您就遵守与您的业务相关的要求获取自己的建议。

## 配额管理

“bedrock-runtime”上的 GPT-6 配额以每分钟令牌 (TPM) 为单位，根据您调用的源区域进行跟踪。输入和缓存写入令牌计数为 1:1，每个输出令牌消耗 10 个配额令牌。例如，包含 2,000 个输入令牌和 1,000 个输出令牌的请求会耗尽配额中的 12,000 个令牌。

Amazon Bedrock 预先保留完整的“max_tokens”，因此请将其设置为接近您期望的完成情况。一项配额涵盖“InvokeModel”、Converse、响应和聊天完成。在源区域的 [服务配额控制台](https://console.aws.amazon.com/servicequotas/) 上查看并提出它。在生产之前，请求会提前增加，并在“AWS/Bedrock”命名空间中的“EstimatedTPMQuotaUsage”达到分配的 70-80% 时发出警报。请参阅 [Amazon Bedrock 中的令牌计数方式](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-token-burndown.html) 和 [Amazon Bedrock 终端节点和配额](https://docs.aws.amazon.com/general/latest/gr/bedrock.html) 了解当前值。

## 监控和记录

**您的操作界面保留在您的源区域中。** Amazon CloudWatch 指标、AWS CloudTrail 事件、模型调用日志、配额核算和账单都保留在您调用的区域中。您支付该区域的费率，而不是处理区域的费率。

**CloudTrail 记录每个请求的处理位置。** AWS 将全球跨区域推理配置文件的目的地记录为其商业区域，而不是枚举它们。 `GetInferenceProfile` 返回与区域无关和源区域模型 ARN，而不是目标列表。您的每个请求记录是源区域 CloudTrail 中的“additionalEventData.inferenceRegion”。此端点上的推理是一个管理事件，默认情况下会记录，无需额外费用。 CloudTrail 事件历史记录保留 90 天，因此更长的时间范围需要跟踪或模型调用日志记录。使用此命令检索 CloudTrail 事件。
```
aws cloudtrail lookup-events \
  --region ap-southeast-1 \
  --lookup-attributes AttributeKey=EventSource,AttributeValue=bedrock.amazonaws.com \
  --start-time <START> \
  --end-time <END> \
  --max-results 1 \
  --query 'Events[0].CloudTrailEvent' --output text | python3 -m json.tool
```
设置您刚刚拨打的电话的窗口，因为 CloudTrail 传输会延迟几分钟。如果最近的事件是失败的调用，则它带有“errorCode”并且不带有“inferenceRegion”。引发 `--max-results` 并选择一个没有 `errorCode` 的事件。
```
{
  "eventName": "Converse",
  "eventSource": "bedrock.amazonaws.com",
```

＃＃ 结论

这篇文章展示了如何通过“基岩运行时”的全球跨区域推理来调用来自五个亚太源区域的 GPT-6 Sol 和 GPT-6 Luna，以及来自亚太地区（新加坡）的 GPT-6 Astra。将全局跨区域推理配置文件 ID 作为“model”参数传递，并配置本文中的 IAM 策略和 SCP 例外。同一端点为 OpenAI 兼容的 API 提供服务，因此现有的 OpenAI 集成可以通过更改基本 URL 和密钥来实现跨越。
