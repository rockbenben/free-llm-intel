## [人工智能](https://aws.amazon.com/blogs/machine-learning/)

# 在泰国、马来西亚、新加坡、印度尼西亚和台湾，用全球跨区域推理访问 Amazon Bedrock 上的 OpenAI GPT 模型

需求超出本地容量时，单区域推理会被限流。泰国、马来西亚、新加坡、印度尼西亚和台湾的团队还需要在本地容量之外用上最新的 OpenAI 模型。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 通过全球跨区域推理在这五个 AWS 区域都提供 OpenAI GPT-6 Sol 和 GPT-6 Luna，并在亚太地区（新加坡）提供 GPT-6 Astra。本文说明如何配置调用、设置权限，以及如何从你的源区域监控推理。

GPT-6 Sol、GPT-6 Luna 和 GPT-6 Astra 都可以从上述区域通过全球跨区域推理调用，走的是 `bedrock-runtime` 端点。参见 Amazon Bedrock User Guide 中的[跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)。每个配置文件涵盖的源区域与目标区域完整列表，见[推理配置文件支持的区域与模型](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)。

本文先介绍全球跨区域推理配置文件，再从亚太地区（新加坡）分别用 Converse API、OpenAI 兼容 API 和编码客户端调用它们。随后讲 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）与服务控制策略（SCP）的配置、配额管理和监控。

## OpenAI GPT-6 的全球跨区域推理配置文件

GPT-6 系列提供三个模型，每一个都支持全球跨区域推理。

- GPT-6 Sol 为贯穿整周执行的复杂任务提供很强的推理与编码能力。
- GPT-6 Luna 让目标集中、可重复的任务在大批量下同样实用。
- GPT-6 Astra 处理复杂推理、编码和长文档工作。

三个模型都接受文本和图像输入，支持客户端侧工具调用和 prompt 缓存。差别在推理强度：GPT-6 Sol 和 GPT-6 Luna 支持 none、low、medium、high、xhigh、max；GPT-6 Astra 支持的档位与它们相同，只是不含 none。关于 GPT-6 Sol 和 GPT-6 Luna，见[在 Amazon Bedrock 上用 GPT-6 Sol 和 GPT-6 Luna 给日常工作带来更多智能](https://aws.amazon.com/blogs/machine-learning/bring-more-intelligence-to-everyday-work-with-gpt-6-sol-and-gpt-6-luna-on-amazon-bedrock/)。关于 GPT-6 Astra，见[用 Amazon Bedrock 上的 GPT-6 Astra 承接最有野心的工作](https://aws.amazon.com/blogs/machine-learning/take-on-your-most-ambitious-work-with-gpt-6-astra-on-amazon-bedrock/)。

全球跨区域推理会把请求路由到部署了该模型的所有受支持商业 AWS 区域，让你用上更大范围的 Amazon Bedrock 容量。调用方式是用全球跨区域推理配置文件 ID 代替 model ID。你发起 API 调用的那个区域就是源区域，由 Amazon Bedrock 选定处理请求的目标区域。计费、配额统计、AWS CloudTrail 和 Amazon CloudWatch 全都留在源区域。

下表列出本文涵盖的全球跨区域推理配置文件 ID 及其源区域。

| **全球跨区域推理配置文件** | **源区域** | **目标区域** |
| --- | --- | --- |
| global.openai.gpt-6-sol global.openai.gpt-6-luna | 亚太地区（新加坡） ap-southeast-1 亚太地区（雅加达） ap-southeast-3 亚太地区（马来西亚） ap-southeast-5 亚太地区（泰国） ap-southeast-7 亚太地区（台北） ap-east-2 | 部署了该模型的受支持商业 AWS 区域 |
| global.openai.gpt-6-astra | 亚太地区（新加坡） ap-southeast-1 | 部署了该模型的受支持商业 AWS 区域 |

AWS 会持续新增区域和配置文件，推理配置文件的可用性与区域支持也随之变化，因此动手开发前请在模型卡片上确认这两项：[GPT-6 Sol](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-openai-gpt-6-sol.html)、[GPT-6 Luna](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-openai-gpt-6-luna.html) 和 [GPT-6 Astra](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-openai-gpt-6-astra.html)。每 token 单价见 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。

## 在 Amazon Bedrock 上开始使用 OpenAI 模型

先看前置条件，之后就能通过 Converse API、OpenAI 兼容 API 或你现有的编码客户端调用三个配置文件中的任意一个。

### 前置条件

- 一个有权调用该配置文件的 IAM 身份。「安全与权限」一节给出的 IAM 策略只授予这些示例所需的内容。
- 已启用你的源区域。只有发起调用的区域需要启用；目标区域不用你启用，它们跑在 Amazon Bedrock 托管的容量上。新加坡（`ap-southeast-1`）是默认启用的区域。雅加达（`ap-southeast-3`）、马来西亚（`ap-southeast-5`）、泰国（`ap-southeast-7`）和台北（`ap-east-2`）属于 opt-in 区域，必须先启用。详见[在账户中启用或停用 AWS 区域](https://docs.aws.amazon.com/accounts/latest/reference/manage-acct-regions.html)。
- 较新的 AWS SDK 或 CLI。OpenAI 兼容的示例还需要 OpenAI SDK 和 Amazon Bedrock token 生成器，用 `pip install boto3 openai aws-bedrock-token-generator` 安装。

### 通过 Amazon Bedrock Runtime 调用 GPT-6 模型

在这一个端点上，每个模型都支持三条访问路径：Amazon Bedrock Converse API、OpenAI Responses API 和 OpenAI Chat Completions API。OpenAI 兼容 API 走 `/openai/v1` 路径调用，不经由 AWS SDK，而端点同时接受 Signature Version 4（SigV4）签名或 Amazon Bedrock API key。三种路径都把全球跨区域推理配置文件 ID 作为 `model` 传入。

**Converse API。** 这个示例从亚太地区（新加坡）调用 GPT-6 Sol 并记录响应。把 `BEDROCK_PROFILE_ID` 设为 `global.openai.gpt-6-luna` 或 `global.openai.gpt-6-astra` 即可换模型，要流式输出就调用 `converse_stream`。

```
import logging
import os
import boto3

# AWS_REGION overrides this default, so set it to your source Region or unset it.
REGION = os.environ.get("AWS_REGION", "ap-southeast-1")
PROFILE_ID = os.environ.get("BEDROCK_PROFILE_ID", "global.openai.gpt-6-sol")
PROMPT = (
    "In three bullet points, explain when a workload should use "
    "cross-Region inference instead of calling a model in a single Region."
)

logging.basicConfig(format="%(levelname)s %(message)s")
log = logging.getLogger("bedrock-cris")
log.setLevel(logging.INFO)

client = boto3.client("bedrock-runtime", region_name=REGION)

# AccessDeniedException points at the IAM policy. ValidationException usually
# means the model ID is not a global cross-Region inference profile.
response = client.converse(
    modelId=PROFILE_ID,
    messages=[{"role": "user", "content": [{"text": PROMPT}]}],
    inferenceConfig={"maxTokens": 1024},
    # GPT-6 Sol and Luna accept none through max. GPT-6 Astra rejects none.
    additionalModelRequestFields={"reasoning": {"effort": "low"}},
)

# Any effort above none can prepend a reasoningContent block, so pick the text
# block by key rather than by position.
text = "".join(b["text"] for b in response["output"]["message"]["content"] if "text" in b)

log.info("Called %s from %s", PROFILE_ID, REGION)
log.info("Stop reason: %s", response["stopReason"])
log.info("Response:\n%s", text)
```

**OpenAI Chat Completions API。** 把 OpenAI SDK 指向该区域的端点，传入同一个配置文件 ID。

```
import logging
import os
from aws_bedrock_token_generator import provide_token
from openai import OpenAI

REGION = os.environ.get("AWS_REGION", "ap-southeast-1")
PROFILE_ID = os.environ.get("BEDROCK_PROFILE_ID", "global.openai.gpt-6-sol")
PROMPT = "List three uses for a message queue."

logging.basicConfig(format="%(levelname)s %(message)s")
log = logging.getLogger("bedrock-cris")
log.setLevel(logging.INFO)

# provide_token mints a short-term key from your AWS credentials, valid up to 12 hours.
client = OpenAI(
    base_url=f"https://bedrock-runtime.{REGION}.amazonaws.com/openai/v1",
    api_key=provide_token(region=REGION),
)

response = client.chat.completions.create(
    model=PROFILE_ID,
    messages=[{"role": "user", "content": PROMPT}],
    max_completion_tokens=256,
)

log.info("Called %s from %s", PROFILE_ID, REGION)
log.info("Response:\n%s", response.choices[0].message.content)
```

迁移现有的 OpenAI 客户端时：

- 每个请求都要设置 model 参数，引用上一轮响应的请求也不例外。
- 只使用受支持的工具类型：`function`、`mcp`、`custom`、`namespace` 和 `tool_search`。
- 直接在你的客户端里配置推理配置文件 ID，而不是去查询 models 端点。

### 配置 ChatGPT 桌面应用和 Codex CLI

ChatGPT 桌面应用和 Codex CLI 共用 `~/.codex/config.toml`，改一处两边都生效。两个内置的 Amazon Bedrock provider 中，只有 `amazon-bedrock-runtime` 接受推理配置文件。

```
model = "global.openai.gpt-6-astra"
model_provider = "amazon-bedrock-runtime"
[model_providers.amazon-bedrock-runtime.aws]
region = "ap-southeast-1"
```

走 SigV4 签名就不存在要轮换的密钥。若不是默认 profile，加上 `profile = "<your-profile>"`；`region` 要显式设置，否则客户端会退回去读 `AWS_REGION`。换模型时把 `model` 换成另一个配置文件 ID。

Codex 对这几个配置文件报出 272,000 token 的上下文窗口，这是它自带的数值，不是服务上限，可以用 `model_context_window` 调高。这项配置需要 Codex CLI 0.148 或更高版本。

## 安全与权限

Amazon Bedrock 提供多种针对推理的管控，这里涉及两项：AWS Identity and Access Management（IAM）策略决定哪些角色能调用哪些配置文件；服务控制策略（SCP）施加覆盖整个组织的管控，其中包含区域范围。本节讲清这两项，并说明请求数据会落在哪里。

### 全球跨区域推理的 IAM 权限

要通过全球跨区域推理配置文件调用这些模型中的任意一个，你的 IAM 策略需要四条 statement：

- 在源区域访问该推理配置文件以及 project/default 资源。
- 在源区域访问该基础模型，范围限定到这个推理配置文件。
- 该基础模型不绑定区域的 Amazon Resource Name（ARN），即 `arn:aws:bedrock:::foundation-model/openai.gpt-6-sol`，并把 `aws:RequestedRegion` 设为 `unspecified`，以放行跨区域路由。
- `bedrock:CallWithBearerToken`，用于 API key 鉴权。

下面这份 IAM 策略授予从 `ap-southeast-1` 通过全球跨区域推理调用 GPT-6 Sol 的权限。请把策略里的账户 ID 占位符换成你自己的 AWS 账户 ID，把 `ap-southeast-1` 换成你的源区域。

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "GrantGlobalCrisProfileAndProjectAccess",
      "Effect": "Allow",
      "Action": ["bedrock:InvokeModel"],
      "Resource": [
        "arn:aws:bedrock:ap-southeast-1:<ACCOUNT>:inference-profile/global.openai.gpt-6-sol",
        "arn:aws:bedrock:ap-southeast-1:<ACCOUNT>:project/default"
      ],
      "Condition": {
        "StringEquals": { "aws:RequestedRegion": "ap-southeast-1" }
      }
    },
    {
      "Sid": "GrantGlobalCrisInRegionModelAccess",
      "Effect": "Allow",
      "Action": ["bedrock:InvokeModel"],
      "Resource": ["arn:aws:bedrock:ap-southeast-1::foundation-model/openai.gpt-6-sol"],
      "Condition": {
        "StringEquals": {
          "aws:RequestedRegion": "ap-southeast-1",
          "bedrock:InferenceProfileArn": "arn:aws:bedrock:ap-southeast-1:<ACCOUNT>:inference-profile/global.openai.gpt-6-sol"
        }
      }
    },
    {
      "Sid": "GrantGlobalCrisGlobalModelAccess",
      "Effect": "Allow",
      "Action": ["bedrock:InvokeModel"],
      "Resource": ["arn:aws:bedrock:::foundation-model/openai.gpt-6-sol"],
      "Condition": {
        "StringEquals": {
          "aws:RequestedRegion": "unspecified",
          "bedrock:InferenceProfileArn": "arn:aws:bedrock:ap-southeast-1:<ACCOUNT>:inference-profile/global.openai.gpt-6-sol"
        }
      }
    },
    {
      "Sid": "AllowBearerTokenAuth",
      "Effect": "Allow",
      "Action": ["bedrock:CallWithBearerToken"],
      "Resource": "*"
    }
  ]
}
```

如果你使用流式输出（`converse_stream` 或 `stream=True`），在前三条 statement 的 Action 里补上 `bedrock:InvokeModelWithResponseStream`。Converse 按 `bedrock:InvokeModel` 鉴权。若你只用 SigV4 凭证调用 Converse，可以去掉第四条 statement。

换模型时，把全文的 `openai.gpt-6-sol` 替换为 `openai.gpt-6-luna` 或 `openai.gpt-6-astra`。完整说明见[全球跨区域推理的 IAM 策略要求](https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html)。

### 全球跨区域推理的服务控制策略注意事项

全球跨区域推理的请求不带区域名。Amazon Bedrock 会把 `aws:RequestedRegion` 置为 `unspecified`，于是 SCP 里的区域允许列表会拒绝这类调用，而报错只点出策略类型，不说是哪一条策略。企业账户首次调用失败，原因常常在这里。

做法不是放宽允许列表，而是把例外范围收窄。Amazon Bedrock 在鉴权时会填充 `bedrock:InferenceProfileArn` 条件键，因此 SCP 可以放行这几个配置文件，同时对其他所有调用保留区域管控。下面这条 SCP 就是这么做的。

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyOutsideApprovedRegionsExceptBedrockInvoke",
      "Effect": "Deny",
      "NotAction": [
        "iam:*", "sts:*", "organizations:*", "account:*",
        "route53:*", "cloudfront:*", "waf:*", "wafv2:*", "shield:*",
        "support:*", "trustedadvisor:*", "health:*",
        "budgets:*", "ce:*", "cur:*", "tax:*", "billing:*",
        "bedrock:Invoke*"
      ],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": { "aws:RequestedRegion": ["ap-southeast-1"] }
      }
    },
    {
      "Sid": "DenyBedrockInferenceOutsideApprovedRegionsUnlessCris",
      "Effect": "Deny",
      "Action": ["bedrock:Invoke*"],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": { "aws:RequestedRegion": ["ap-southeast-1"] },
        "ArnNotLike": {
          "bedrock:InferenceProfileArn": [
            "arn:aws:bedrock:*:*:inference-profile/global.*"
          ]
        }
      }
    }
  ]
}
```

第一条 statement 对除 Amazon Bedrock 推理之外的所有服务强制执行你的区域允许列表。第二条在那些区域之外拒绝这项推理，除非请求走的是全球跨区域推理配置文件。地理区域配置文件（geographic profile）要把它们的前缀（例如 `inference-profile/us.*`）也加进 `ArnNotLike` 列表，因为地理区域的请求带着真实区域名。源区域要留在允许列表里，你所在组织用到的全局服务则加进 `NotAction`。

更简单粗暴的替代办法是把 `unspecified` 加进现有允许列表，这行得通，但等于给所有其他服务开了同一个例外。现成的策略文件见 [aws-samples 的 service-control-policy-examples 仓库](https://github.com/aws-samples/service-control-policy-examples/blob/main/Region-controls/Deny-access-to-AWS-based-on-the-requested-AWS-region-with-Bedrock-CRIS.json)。

### 数据保留与滥用检测

在自动化离线滥用检测中，被分类器标记的流量由 AWS 保留至多 30 天，并以程序方式处理。走跨区域推理时，这份保留发生在目标区域；对全球配置文件而言，目标区域就是部署该模型的任意受支持商业 AWS 区域。符合条件的客户可以通过自己的 AWS 客户团队申请完全的零数据保留。详见 [Amazon Bedrock 滥用检测](https://docs.aws.amazon.com/bedrock/latest/userguide/abuse-detection.html)和[数据保留](https://docs.aws.amazon.com/bedrock/latest/userguide/data-retention.html)。

如果你的组织有数据驻留要求，请尽早和风险与合规团队沟通这件事。这五个国家的对应页面见 [AWS 金融服务合规中心](https://aws.amazon.com/financial-services/security-compliance/compliance-center/)。与你的业务相关的要求该如何满足，建议另行获取你自己的合规意见。

## 配额管理

`bedrock-runtime` 上的 GPT-6 配额以每分钟 token 数（TPM）计量，按你发起调用的源区域统计。输入 token 与缓存写入 token 按 1:1 计入，每个输出 token 消耗 10 个 token 的配额。例如一个 2,000 输入 token、1,000 输出 token 的请求，会从你的配额里扣掉 12,000 个 token。

Amazon Bedrock 会预先按完整的 `max_tokens` 预留，所以要把 `max_tokens` 设得接近你预期的补全长度。同一份配额覆盖 `InvokeModel`、Converse、Responses 和 Chat Completions。请在源区域到 [Service Quotas 控制台](https://console.aws.amazon.com/servicequotas/)查看并上调。上线生产环境前提前申请提额，并对 `AWS/Bedrock` 命名空间下的 `EstimatedTPMQuotaUsage` 设告警，阈值取你所分配额度的 70–80%。当前数值见 [Amazon Bedrock 中 token 如何计数](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-token-burndown.html)和 [Amazon Bedrock 端点与配额](https://docs.aws.amazon.com/general/latest/gr/bedrock.html)。

## 监控与日志

**你的运维面始终留在源区域。** Amazon CloudWatch 指标、AWS CloudTrail 事件、模型调用日志、配额核算和计费都留在你发起调用的区域。你按这个区域的费率付费，而不是处理请求的那个区域。

**CloudTrail 记录每个请求在哪里被处理。** 关于全球跨区域推理配置文件的目的地，AWS 文档给的是它的商业区域，并不逐一列举。`GetInferenceProfile` 返回的是不绑定区域的模型 ARN 和源区域的模型 ARN，而不是目的地列表。逐个请求的记录在源区域 CloudTrail 的 `additionalEventData.inferenceRegion` 里。该端点上的推理属于管理事件，默认就记录日志，不额外收费。CloudTrail 事件历史保留 90 天，要覆盖更长的时间就得建 trail 或启用模型调用日志。用下面这条命令取回 CloudTrail 事件。

```
aws cloudtrail lookup-events \
  --region ap-southeast-1 \
  --lookup-attributes AttributeKey=EventSource,AttributeValue=bedrock.amazonaws.com \
  --start-time <START> \
  --end-time <END> \
  --max-results 1 \
  --query 'Events[0].CloudTrailEvent' --output text | python3 -m json.tool
```

时间窗口要框在你刚发起的那次调用附近，因为 CloudTrail 投递有几分钟延迟。如果最近一条事件是失败的调用，它会带 `errorCode` 而没有 `inferenceRegion`。这时把 `--max-results` 调大，挑一条不含 `errorCode` 的事件。

```
{
  "eventName": "Converse",
  "eventSource": "bedrock.amazonaws.com",
  "awsRegion": "ap-southeast-1",
  "managementEvent": true,
  "requestParameters": {
    "modelId": "global.openai.gpt-6-sol",
    "inferenceConfig": { "maxTokens": 1024 }
  },
  "additionalEventData": {
    "inferenceRegion": "us-east-1"
  }
}
```

**指标与编码智能体用量都留在 CloudWatch。** 开发者通过编码智能体使用 GPT-6 时，CloudWatch 的 [Coding Agent Insights](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/coding-agents-insights.html) 会在 GenAI Observability 下提供现成的看板，按用户、团队和成本中心拆分 token 用量。这些智能体原生上报 OpenTelemetry 指标。Codex 的配置见[为 OpenAI Codex 设置 OpenTelemetry](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/coding-agents-codex.html)。

## 清理

本文新增了一份 IAM 策略，另视你的选择可能加了一条 SCP statement 和一个日志目的地。把你附加的 IAM 策略解除关联或删除；如果加了 SCP 条目，把它还原。如果你在 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）或 Amazon CloudWatch Logs 里创建了模型调用日志目的地，也要删掉，以免产生存储费用。全球跨区域推理配置文件是系统定义的，没有需要删除的东西。

## 总结

本文演示了如何在 `bedrock-runtime` 上通过全球跨区域推理，从五个亚太源区域调用 GPT-6 Sol 和 GPT-6 Luna，以及从亚太地区（新加坡）调用 GPT-6 Astra。把全球跨区域推理配置文件 ID 作为 `model` 参数传入，再按本文配好 IAM 策略和 SCP 例外即可。同一个端点也承载 OpenAI 兼容 API，已有的 OpenAI 集成改一个 base URL 和一把密钥就能迁过来。

上手做法是附加本文的 IAM 策略，通过 `global.openai.gpt-6-sol` 发出第一个请求。按 10 倍消耗速率估算你的每分钟 token 配额，并在 CloudTrail 里确认调用记录中出现了 `additionalEventData.inferenceRegion`。

更多信息见 [Amazon Bedrock User Guide](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-bedrock.html)、[用跨区域推理把模型推理请求路由到各个 AWS 区域](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)和 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。
