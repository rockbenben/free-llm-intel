# AWS 上使用 Smartsheet MCP 的 AI 代理的工作管理上下文

当人工智能代理能够对整个组织中发生的实际工作采取行动时，它们是最有用的。工作管理涉及复杂的跨职能任务，例如更新项目时间表、重新分配任务和显示状态。人工智能代理可以为您提供这些支持，而无需任何人切换工具。 [Smartsheet](https://www.smartsheet.com/) 是一个用于管理项目、项目组合和运营的工作管理平台，已推出通用的模型上下文协议 (MCP) 服务器。

借助 [Smartsheet MCP 服务器](https://developers.smartsheet.com/ai-mcp/smartsheet/mcp-server)，AI 助手可以通过标准化协议读取、写入和管理 Smartsheet 数据。该协议涵盖 40 多种用于探索、创建和管理工作表、行、列和自动化的工具。您可以直接通过自然语言更新任务状态、创建行以及修改项目结构。

在这篇文章中，我们将介绍两种将其连接到现有工作流程的方法。 [Amazon Quick](https://aws.amazon.com/quick/) 是一个为业务用户、项目经理和运营团队构建的代理 AI 工作区。他们可以通过自然语言提出问题、更新工作表并构建仪表板，而无需编写代码。 [Kiro](https://kiro.dev/) 是一个代理 IDE，开发人员可以通过 MCP 连接到 Smartsheet，以参考项目规范、更新任务状态并跟踪依赖项，而无需离开编码工作流程。

## 使用 Amazon Quick 和 Kiro 进行 Sprint 管理

考虑一个在 Smartsheet 中跟踪他们的冲刺的软件工程团队。任务、所有者、状态和阻止者都位于项目表中。以下是同一团队的每条路径：

当项目经理等用户想要检查本周哪些冲刺任务被阻止时，他们可以通过自然语言询问 Amazon Quick。 Amazon Quick 聊天代理查询 Smartsheet MCP 服务器、提取相关行并显示包含所有者姓名和截止日期的摘要。响应是根据实时 Smartsheet 数据生成的，无需构建报告或仪表板。

对于正在修复错误或开发功能的开发人员，他们可以要求 Kiro 拉出当前的冲刺表并向他们展示分配给他们的开放后端任务。 Kiro 通过 MCP 查询 Smartsheet 并内联显示列表。提交修复后，Kiro 挂钩会自动将相应的行状态更新为“完成”。

## 先决条件

Smartsheet MCP 服务器提供精确结构化的上下文，包括行关系、列类型、单元格历史记录和注释。这会产生令牌有效的有效负载大小，而不是返回原始 API 有效负载。在整个项目组合中运行数百个人工智能辅助查询时，这种工程决策可以大规模降低成本并改善延迟。要了解 Smartsheet 如何在 AWS 上构建远程 MCP 服务器，请参阅[Smartsheet 如何在 AWS 上构建远程 MCP 服务器](https://aws.amazon.com/blogs/machine-learning/how-smartsheet-built-a-remote-mcp-server-on-aws/)。

在将 Smartsheet MCP 服务器连接到 Amazon Quick 和 Kiro 之前，请验证您是否已准备好以下各项：

- 一个活跃的 AWS 账户，对您要连接的服务（Amazon Quick 或 Kiro）具有适当的 AWS Identity and Access Management (IAM) 权限
- 商业、企业或 AWM 计划中的 Smartsheet 帐户。
- Smartsheet 个人访问令牌或 OAuth 凭据（如果您的客户端支持 OAuth 流程）。
- 对于 Amazon Quick：您的 Amazon Quick 帐户中的作者或更高权限。
- 对于 Kiro：从 [kiro.dev](https://kiro.dev) 安装 Kiro IDE，并在您的环境中提供“Node.js”。

Smartsheet MCP 服务器可在三个区域端点使用。它使用 Streamable HTTP 传输（MCP 规范版本 2025-06-18 和 2025-03-26），并使用 OAuth 2.0 或个人访问令牌进行身份验证。

- 美国商业：https://mcp.smartsheet.com。
- 欧盟：https://mcp.smartsheet.eu。
- 澳大利亚：https://mcp.smartsheet.au。

这两个选项都公开相同的 Smartsheet 工具集。正确的选择取决于您的工作完成地点：

如果您需要整个团队都可以使用的完全托管的组织范围解决方案，请选择 Amazon Quick：无需应用程序注册，只需预构建 OAuth，并且它可以在企业中的知识工作者中扩展。

如果您是一名想要轻量级的开发人员，请选择 Kiro：没有基础设施，只有配置文件和个人访问令牌，范围仅限于您自己的工作流程。

## Kiro 集成

当开发人员希望 Smartsheet 项目上下文与代码一起直接在其开发环境中可用而无需上下文切换时，[Kiro](https://kiro.dev/docs/mcp/) 是正确的路径。

Kiro 是围绕规范驱动的开发而构建的。它将高级提示转化为结构化规范，然后转化为工作代码、文档和测试。 MCP 服务器是 Kiro 通过连接到文档、数据库、API 和企业系统来获取真实世界上下文的方式，使其代理基于实时数据而不是训练时的知识。

Kiro 的一项名为 powers 的功能是一个一键安装的捆绑包，它将精心设计的 MCP 服务器与控制文件和挂钩打包在一起。它为 Kiro 编码代理提供了开箱即用的新功能。对于 Smartsheet，配置连接需要一个 JSON 配置块，从那时起，Kiro 代理可以引用实时项目数据作为开发工作流程的一部分。

要将 Smartsheet MCP 服务器连接到 Kiro，请将其添加到您的 Kiro MCP 配置（工作区范围为“.kiro/settings/mcp.json”）。有关完整演练，请参阅[Kiro 和 MCP 服务器入门](https://repost.aws/articles/ARuX8rkojgSx-TYCc65JyAOw/getting-started-with-kiro-and-mcp-servers-connect-your-ai-ide-to-real-world-tools)：
```
{
  "mcpServers": {
    "smartsheet-us": {
      "type": "http",
      "url": "https://mcp.smartsheet.com",
      "headers": {
        "Authorization": "Bearer <SMARTSHEET_API_TOKEN>"
      }
    }
  }
}
```
此配置使用个人访问令牌（API 密钥）方法。对于生产部署，建议使用 OAuth。

将“SMARTSHEET_API_TOKEN”设置为您环境中的 Smartsheet 个人访问令牌。 Kiro 在启动时将 MCP 服务器加载为后台进程。初始化后，Kiro 代理可以在所有模式下使用 Smartsheet 工具：聊天、规格规划和基于挂钩的自动化。完整详细信息请参见 [Smartsheet MCP 服务器文档](https://developers.smartsheet.com/api/smartsheet/ai-integration/mcp-server)。

从那里，Kiro 可以引用 Smartsheet 数据作为开发工作流程的一部分：

## 企业治理

对于在受监管或企业环境中部署的构建者来说，Smartsheet MCP 服务器安全模型构建在与 Smartsheet REST API 相同的基础设施和权限层上。这不是一个新的信任边界：

- **OAuth 2.0 和个人访问令牌身份验证**：选择 MCP 客户端支持的身份验证方法。
- **用户级权限强制**：代理只能访问经过身份验证的用户有权查看的数据。不会通过自然语言提示进行权限升级。
- **组织级人工智能控制**：系统管理员可以全局打开或关闭人工智能功能。写入工具访问权限可由用户组配置。
- **流式 HTTP 传输**：防火墙白名单是通过完全限定域名 (FQDN) (mcp.smartsheet.com) 而不是 IP 地址完成的。

对于合规架构师来说，MCP 服务器不存储提示，提示内容保留在 AI 客户端和模型之间。 Smartsheet 只能看到结构化工具调用及其结果。

## 清理

如果您按照本演练操作并希望随后删除集成，请按以下步骤撤消每条路径：

### 亚马逊快速

- 在 Amazon Quick 控制台中，导航至 **连接器**。
- 选择您的 Smartsheet 连接器。
- 选择 **删除** 以删除连接。这将撤销 OAuth 令牌并停止代理访问 Smartsheet 数据。

### 基罗

- 打开 MCP 配置文件 (`.kiro/settings/mcp.json`)。
- 从“mcpServers”对象中删除“smartsheet-us”条目。
- 重新启动 Kiro 以卸载服务器。

## 后续步骤

有关服务器工作原理的背景信息，请参阅[Smartsheet 如何在 AWS 上构建远程 MCP 服务器](https://aws.amazon.com/blogs/machine-learning/how-smartsheet-built-a-remote-mcp-server-on-aws/)。将 Smartsheet MCP 服务器连接到您选择的系统后，我们建议尝试以下四项操作：

您可以要求聊天代理监控您的活动项目表，识别标记为“已阻止”或“有风险”的行。您还可以要求使用讨论评论来注释项目，并通过您喜欢的渠道向您的团队提供结构化摘要。这将是一个链接“get_sheet_summary”、“search”和“create_discussion_on_row”的示例工作流程。

代理还可以通过 Smartsheet MCP 服务器检索数据，以协调问题跟踪器和 Smartsheet 项目计划之间的任务状态。它可以标记两者之间的偏差，并依次使用“get_sheet_summary”、“get_columns”、“update_rows”和“create_discussion_on_row”更新受影响的行。

您还可以尝试跨报告和仪表板聚合项目运行状况信号。您可以使用它生成结构化简报，无需手动收集数据，利用“list_reports”、“get_report”、“list_dashboards”、“get_dashboard”和“search”。

最后，您可以使用代理跟踪每次写入，并通过讨论评论解释更改的内容和原因。这通过“update_rows”和“create_discussion_on_row”的组合在 Smartsheet 中创建了一个人类可读的审计跟踪。

所有四种模式都适用于上述路径：Amazon Quick 适用于面向业务用户的工作流程，Kiro 适用于开发人员发起的操作。
