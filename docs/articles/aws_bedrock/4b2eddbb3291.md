# 使用 Multi-Provider Generative AI Gateway 参考架构简化 AI 运营

随着各类组织在其应用中越来越多地采用 AI 能力，对 AI 模型访问进行集中管理、安全防护与成本控制，已成为扩展 AI 解决方案的必要一步。[AWS 上的 Generative AI Gateway](https://aws.amazon.com/solutions/guidance/multi-provider-generative-ai-gateway-on-aws/) 指南通过提供一个统一的网关来应对这些挑战：它支持多个 AI 提供商，同时提供全面的治理与监控能力。

Generative AI Gateway 是一套参考架构，面向希望以自托管方式实现端到端生成式 AI 解决方案的企业——这些方案包含多种模型、数据增强的响应以及 agent 能力。该指南结合了 Amazon Bedrock 广泛的模型访问能力、Amazon SageMaker AI 统一的开发者体验，以及 [LiteLLM](https://www.litellm.ai/) 强大的管理能力，同时以更安全可靠的方式支持客户访问来自外部模型提供商的模型。

LiteLLM 是一个开源项目，用于应对客户在部署生成式 AI 工作负载时面临的常见挑战。LiteLLM 简化了多提供商模型访问，同时把成本追踪、可观测性、prompt 管理等生产运营要求标准化。在本文中，我们将介绍 Multi-Provider Generative AI Gateway 参考架构如何指导把 LiteLLM 部署到 AWS 环境中，用于生产级生成式 AI 工作负载的管理与治理。

## 挑战：管理多提供商 AI 基础设施

使用生成式 AI 进行构建的组织在扩展其 AI 举措时面临若干复杂挑战：

- **提供商碎片化**：团队往往需要访问来自不同提供商的不同 AI 模型——[Amazon Bedrock](https://aws.amazon.com/bedrock/)、[Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/)、OpenAI、Anthropic 等——每个提供商都有不同的 API、认证方式与计费模式。
- **治理模式分散**：没有统一的访问入口，组织很难在不同的 AI 服务之间实施一致的安全策略、使用监控与成本控制。
- **运维复杂性**：管理从 [AWS Identity and Access Management](https://aws.amazon.com/iam/) 角色到 API key 的多种访问范式、模型专属的速率限制，以及跨提供商的故障转移策略，会带来运维开销并增加服务中断的风险。
- **成本管理**：跨多个提供商与团队理解并控制 AI 支出变得越来越困难，尤其是在用量扩大时。
- **安全与合规**：在不同 AI 提供商之间实现一致的安全策略与审计轨迹，对企业治理构成重大挑战。

## Multi-Provider Generative AI Gateway 参考架构

该指南通过提供一个集中式网关来应对这些常见的客户挑战：把多个 AI 提供商的复杂性抽象在单一受管接口之后。

![multi-provider-solution-reference-architecture](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/21/ML-19752-image-1.png)

该解决方案构建在 AWS 服务之上并使用开源的 LiteLLM 项目，组织可以用它来集成 AI 提供商，同时保持集中的控制、安全与可观测性。

### AWS 上的灵活部署选项

Multi-Provider Generative AI Gateway 支持多种部署模式，以满足组织的多样化需求：

[**Amazon ECS**](https://aws.amazon.com/ecs/)** 部署**
 对于偏好以托管基础设施运行容器化应用的团队，ECS 部署提供无服务器容器编排，具备自动扩缩容与集成负载均衡。

[**Amazon EKS**](https://aws.amazon.com/eks/)** 部署**
 已具备 Kubernetes 专业能力的组织可以使用 EKS 部署选项，它提供对容器编排的完全控制，同时可受益于托管的 Kubernetes 控制平面。客户可以部署新集群，也可以复用现有集群进行部署。

为这些部署选项提供的参考架构，需要根据你组织的具体安全要求接受额外的安全测试。在把任何内容部署到生产环境之前，请按需执行额外的安全测试与评审。

### 网络架构选项

Multi-Provider Generative AI Gateway 支持多种网络架构选项：

**全球公网部署**
 对于拥有全球用户群的 AI 服务，可以把网关与 [Amazon CloudFront](https://aws.amazon.com/cloudfront/)（CloudFront）和 [Amazon Route 53](https://aws.amazon.com/route53/) 结合使用。该配置提供：

- 借助 [AWS Shield](https://aws.amazon.com/shield/) DDoS 防护增强的安全性
- 使用 Amazon CloudFront 默认证书简化 HTTPS 管理
- 全球边缘缓存，改善延迟
- 跨区域的智能流量路由

**区域直连访问**
 对于优先考虑低延迟与成本优化的单区域部署，直接访问 [Application Load Balancer（ALB）](https://aws.amazon.com/elasticloadbalancing/application-load-balancer/) 可以省去 CloudFront 层，同时通过正确配置的安全组与网络 ACL 保持安全性。

**私有内部访问**
 需要完全隔离的组织可以把网关部署在私有 VPC 内，不暴露于互联网。该配置确保 AI 模型访问始终位于你的安全网络边界之内，并通过 ALB 安全组把流量限制在已授权的私有子网 CIDR 范围内。

## 全面的 AI 治理与管理

Multi-Provider Generative AI Gateway 的设计目标是从简洁的管理界面出发，实现稳健的 AI 治理标准。除基于 policy 的配置与访问管理之外，用户还可以配置负载均衡、prompt caching 等高级能力。

### 集中式管理界面

Generative AI Gateway 在 LiteLLM 中包含一个基于 Web 的管理界面，支持在整个组织范围内全面管理 LLM 的使用。

关键能力包括：

**用户与团队管理**：在细粒度层面配置访问控制，从单个用户到整个团队，并按与组织结构一致的基于角色的权限进行授权。

**API key 管理**：集中管理与轮换所连接 AI 提供商的 API key，同时保留 key 使用情况与访问模式的审计轨迹。

**预算控制与告警**：在提供商、团队与单个用户层面设置支出上限，并在接近或超过阈值时自动告警。

**全面的成本控制：**成本受 AWS 基础设施与 LLM 提供商影响。虽然客户有责任配置该解决方案以满足自身成本要求，但[客户可以查看现有的成本设置](https://github.com/aws-solutions-library-samples/guidance-for-multi-provider-generative-ai-gateway-on-aws?tab=readme-ov-file#cost) 以获得更多指导。

**支持多个模型提供商：**兼容 Boto3、OpenAI 与 LangGraph SDK，让客户无论提供商是谁，都能为工作负载选用最合适的模型。

**支持 Amazon Bedrock Guardrails：**客户可以为其生成式 AI 工作负载使用在 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 上创建的 guardrails，无论模型来自哪个提供商。

### 智能路由与韧性

围绕模型部署的常见考量包括模型与 prompt 的韧性。这些因素对于理解在响应 prompt 或访问数据存储时如何处理故障十分重要。

**负载均衡与故障转移**：网关实现了精细的路由逻辑，把请求分发到多个模型部署，并在检测到问题时自动故障转移到备用提供商。

**重试逻辑**：内置带指数退避的重试机制，即使个别提供商出现瞬时问题，也有助于保持可靠的服务交付。

**Prompt caching**：智能缓存通过避免对昂贵 AI 模型的重复请求来帮助降低成本，同时保持响应的准确性。

### 高级 policy 管理

模型部署架构的复杂度可以从简单到高度复杂。Multi-Provider Generative AI Gateway 提供维持强健治理态势所需的高级 policy 管理工具。

**速率限制**：配置精细的速率限制 policy，可按用户、API key、模型类型或一天中的时段而不同，以促进资源的公平分配并帮助防止滥用。

**模型访问控制**：依据用户角色限制对特定 AI 模型的访问，确保敏感或昂贵的模型只有获授权人员才能访问。

**自定义路由规则**：实现业务逻辑，依据请求类型、用户位置或成本优化要求等条件把请求路由到特定提供商。

## 监控与可观测性

随着 AI 工作负载包含越来越多的组件，可观测性需求也随之增长。Multi-Provider Generative AI Gateway 架构与 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 集成。这一集成使用户能够配置多种监控与可观测性方案，包括 [Langfuse](https://langfuse.com/) 等开源工具。

### 全面的日志与分析

网关交互会自动记录到 CloudWatch，提供以下方面的详细洞察：

- 跨提供商与团队的请求模式与使用趋势
- 延迟、错误率与吞吐量等性能指标
- 按用户、团队与模型类型划分的成本分摊与支出模式
- 用于合规报告的安全事件与访问模式

### 内置故障排查

管理界面提供实时日志查看能力，使管理员无需直接访问 CloudWatch 就能快速诊断并解决使用问题。

## 通过 Amazon SageMaker 集成扩展模型访问

Amazon SageMaker 通过提供一个能够与网关架构无缝集成的完整机器学习系统，帮助增强 Multi-Provider Generative AI Gateway 指南。通过使用 Amazon SageMaker 的托管基础设施进行模型训练、部署与托管，组织可以开发自定义 foundation model，或对现有模型进行微调，并通过网关与其他提供商的模型一起访问它们。这一集成消除了单独管理基础设施的需要，同时促进在自定义模型与第三方模型之间保持一致的治理。SageMaker AI 的模型托管能力把网关的模型访问扩展到自托管模型，以及 Amazon Bedrock、OpenAI 和其他提供商上可用的模型。

该代码仓库描述了若干可直接上手的灵活部署选项。

### 带全球 CloudFront 分发的公有网关

使用 CloudFront 为你的生成式 AI 服务提供一个全球分布、低延迟的访问点。CloudFront 边缘站点把内容快速送达世界各地的用户，同时 AWS Shield Standard 帮助防御 DDoS 攻击。这是面向拥有全球用户群的公网 AI 服务所推荐的配置。

### 使用 CloudFront 的自定义域名

若想要更具品牌感的体验，你可以把网关配置为使用自己的自定义域名，同时仍可享受 CloudFront 的性能与安全特性。如果你希望与公司的线上形象保持一致，这个选项非常理想。

### 通过公有 Application Load Balancer 直连

更看重低延迟而非全球分发的客户可以选择直连 ALB 的部署方式，省去 CloudFront 层。这种简化架构可以带来成本节省，但需要额外考虑 Web 应用防火墙防护。

### 仅私有 VPC 访问

为了获得高等级的安全性，你可以把网关完全部署在私有 VPC 内，与公共互联网隔离。该配置非常适合处理敏感数据，或部署面向内部的生成式 AI 服务。访问仅限于 VPN、Direct Connect、VPC peering 或 [AWS Transit Gateway](https://aws.amazon.com/transit-gateway/) 等可信网络。

## 结论

Multi-Provider Generative AI Gateway 是一份解决方案指南，旨在帮助客户以架构良好的方式开始构建生成式 AI 解决方案，同时充分利用 AWS 的服务环境与配套的开源软件包。客户可以使用来自 Amazon Bedrock、Amazon SageMaker JumpStart 或第三方模型提供商的模型。工作负载的运营与管理通过 LiteLLM 管理界面进行，客户可以按自己的偏好选择托管在 ECS 或 EKS 上。

此外，我们还发布了一个[示例](https://github.com/aws-samples/sample-agentic-ai-foundation)，把该网关集成到 agentic 客户服务应用中。该 agentic 系统使用 [LangGraph](https://www.langchain.com/langgraph) 编排，并部署在 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 上。LLM 调用通过网关路由，从而可以灵活地用不同模型测试 agent——无论这些模型托管在 AWS 还是其他提供商。

这份指南只是 AWS 上成熟生成式 AI 基础的一部分。要深入了解 AWS 上生成式 AI 系统的各个组成部分，请参阅 [Architect a mature generative AI foundation on AWS](https://aws.amazon.com/blogs/machine-learning/architect-a-mature-generative-ai-foundation-on-aws/)，其中描述了生成式 AI 系统的更多组件。
