# 使用 Kiro 构建可重复的 PHP 到 Java 迁移引擎

当您的团队将成熟的 PHP 应用程序迁移到 Java 时，您将获得更强的类型安全性、更广泛的库支持和更可预测的扩展。多年来使用 Laravel、Symfony 或 Doctrine 构建的 PHP 代码库在不明显的地方（从 Eloquent 特征到 XML 映射文件）携带业务规则，因此结构相似的 Java 端口可以干净地编译，但行为仍然不同。

这篇文章展示了如何使用 [Kiro](https://kiro.dev/) 将 PHP 到 Java 的迁移从一次性的信念转变为可测量、可重复的过程。 Kiro 是一个 AI 集成开发环境 (IDE)，它将 AI 代理与您的代码库配对，以便您在循环中运行多步骤工程任务。该方法以可重用引擎为中心：共享方法、机械发现扫描仪和八阶段工作流程。该引擎将原始 PHP 应用程序视为规范，并拒绝声明 Java 端口正确，直到奇偶校验工具验证它为止。

## 先决条件

在开始之前，您需要：

- 熟悉 PHP（Laravel/Eloquent 或 Symfony/Doctrine）。 Java 知识（Spring Boot、JPA）可帮助您查看生成的输出，但引擎会为您生成惯用的 Java，因此您无需自己用 Java 重写应用程序。
- Kiro 工作区，可以访问 [Skills](https://kiro.dev/docs/skills/) 和 [Steering](https://kiro.dev/docs/steering/) 文件。
- 运行发现扫描器的计算机上的 PHP 8.0 或更高版本，以及用于生成的 Spring Boot 项目的带有 Maven 的 Java 21。
- 对迁移规划（发现、翻译和验证）的基本了解。

## 您将在这篇文章中学到什么

您从一个开放的存储库开始，因此您可以自己运行引擎而不是阅读它。引擎知道的所有内容都存在于一小组技能文件中，通过这些文件，您可以以多种方式运行相同的方法。

## 运行引擎的两种方式：Kiro 和 AWS Transform

这里的所有内容都打包为技能文件：版本化的 Markdown 功能包，对迁移方法 (php-to-java-migration) 和发现扫描器工作流程 (php-model-discovery) 进行编码。由于这些知识存在于文件中而不是任何一种工具中，因此您可以通过两种方式运行相同的方法。

### 方法 1：Kiro、交互式和开发人员参与

Kiro 将人工智能代理引入您的编辑器中以逐步推动迁移。将存储库根目录作为 Kiro 工作区打开，当您要求 Kiro 迁移 PHP 应用程序时，技能会自动激活。然后，Kiro 使用明确的批准门来执行八阶段工作流程，因此您可以查看发现清单、批准规则手册，并在下一阶段开始之前签署每个阶段。这是本文中每个示例都使用的模式。

### 方法 2：AWS Transform、代理和组合规模

[AWS Transform](https://aws.amazon.com/transform/) 是用于大规模迁移和现代化的 AWS 代理 AI 服务，现在与 Kiro 进行了本地集成。通过这种集成，您可以向 AWS Transform 提供管理交互式 Kiro 会话的相同技能文件，因此翻译前的发现、作为裁判的奇偶校验工具以及“*修复循环，而不是代码*”适用于自主运行。

### 当每条路径都适合时

- **控制和自治：** 首先使用 Kiro 完成代码：在一个应用程序上运行技能，读取生成的 Java，然后运行测试。当您想要迁移更多内容时，AWS Transform 会以代理方式运行相同的方法，并在技能定义的检查点进行审查。
- **规模和新颖性：** Kiro 一次处理一个应用程序，适合首个框架。 AWS Transform 将许多应用程序作为并行作业运行。
- **共享反馈循环：** 两条路径读取相同的技能文件，因此 Kiro 中进行的每个规则手册修复都会改进下一次 AWS Transform 运行，反之亦然。

## 翻译前的发现

最重要的一条规则先于其他规则触发：在扫描仪运行之前，不要阅读、猜测或手动翻译模型或实体文件。

扫描仪单次运行，没有依赖关系，如下图所示。它对源令牌应用三种发现策略，并发出一个 JSON 清单，将任何不明确的内容路由到审查标志队列，供人工解决。

![php-model-discovery，三种策略，一种清单。发现扫描器的图表，discover-models.php。左侧，PHP 代码库输入到扫描器中，扫描器按顺序运行三种策略：Eloquent 模型发现、Doctrine 属性检测和 ORM XML 映射。然后，箭头将结果传送到右侧的 model-manifest.json，其中包含字段、转换和关系的模型数组，以及用作人工审核的标志数组队列。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/28/ML-21579-3.png)

图 3：扫描器对源令牌运行三种发现策略，并发出带有审查标记队列的单个 JSON 清单

扫描器是discover-models.php，一个单文件、无依赖的PHP命令行工具，不执行目标代码。它仅将源文本读取为令牌，因此无论是否安装了依赖项，它都会针对您选择的应用程序运行。它在每次扫描时运行三种策略：Eloquent 模型发现（沿着类继承链走到 Illuminate\Database\Eloquent\Model）、Doctrine 属性检测（#[ORM\Entity] 属性）和 ORM XML 映射（外部 `*.orm.xml` 文件）。输出是单个 JSON 清单。 “models[]”数组包含每个字段、转换、关系和可见性规则，并且“flags[]”数组出现在每个条目上。扫描仪会标记歧义而不是猜测。例如，从运行时表达式构建的“$fillable”列表成为简单的英语标志，并且该标志列表是人工审核队列。

## 奇偶校验优先管道

第 0 阶段是准备阶段：它运行扫描仪并组装库存。前三个阶段集中了人类的专业知识。第 1 阶段在编写 Java 之前构建奇偶校验工具，针对 PHP 原始版本和 Java 端口重放请求/响应对。该安全带必须通过正常运行的 PHP，并且当您故意破坏它时会失败，因为错过注入破坏的安全带是不可信的。第 2 阶段播种规则手册和差距清单（RULEBOOK.md、GAP_INVENTORY.md），第 3 阶段根据代表性文件对其进行压力测试，然后再将其提交到应用程序中。

这些映射是机械的并且可追溯到清单：PHP 命名空间变为 Java 包，Eloquent 模型变为 JP​​A @Entity，具有 Many 和所属关系变为 @OneToMany 和 @ManyToOne，Eloquent 查询范围变为 Spring Data 存储库方法。该规则在序列化中表现出来：html、markdown 和文本都带有 @JsonIgnore，因为清单将它们记录在 Page 的 $hidden 列表中，而 Book 的描述故意没有记录。

## 开始使用

完整的迁移引擎可在[示例 PHP 到 Java 迁移存储库](https://github.com/aws-samples/sample-php-to-java-migration) 中找到。

使用方法：

- 克隆存储库并打开其根目录作为 Kiro 工作区（打开文件夹并选择包含 .kiro/ 的文件夹）。除了用于扫描程序的 PHP 8.0+ 和带有 Maven 的 Java 21 之外，无需安装任何内容。
- 将 PHP 源代码提取到项目的 source-php/ 文件夹中。自述文件固定了用于奇偶校验的确切上游提交，以便任何人都可以重现基线。
- 要求 Kiro 迁移应用程序。 php-to-java-migration 技能会自动激活，首先运行扫描程序，在 .kiro/specs/ 下生成新的规范，然后引导您通过批准大门。
- 对于代理运行，请将 AWS Transform 指向相同的技能文件，以便其代理在您的产品组合中执行相同的方法。

该方法自动检测 Laravel、Symfony、CodeIgniter 和纯 PHP，并且扩展是附加的：为新框架添加检测行和 `references/<framework>-to-spring.md` 指南。由于 Kiro 和 AWS Transform 读取相同的文件，因此在升级两个引擎后对其进行优化。

## 清理

如果您在此演练期间部署了示例 Spring Boot 应用程序：

- 停止正在运行的 Spring Boot 应用程序（内存中的 H2 数据库是短暂的，不需要单独清理）。
- 如果不再需要，请从工作区中删除生成的 Java 项目文件夹。
- 发现扫描器仅生成 JSON 清单文件。如果您不打算引用发现扫描器的 JSON 清单，请从工作目录中删除它。
- 迁移引擎本身不配置任何 AWS 资源，因此无需取消配置云资源。

## 结论

我们展示了如何使用 Kiro 构建可重复的 PHP 到 Java 迁移引擎，将大规模重写转变为可测量的复合过程。主要原则是：

- **翻译前的发现：** 机械扫描仪会清点每个模型、字段和关系，因此您无需猜测结构。
- **在代码之前构建判断：**奇偶校验工具在编写第一行 Java 之前定义“完成”。
- **修复循环，而不是代码：** 当文件中出现相同的错误时，修改规则手册并重新生成，而不是手动修补。
- **同一个大脑：** 该方法编写一次，跨项目共享，并随着每次迁移而改进。

这些都不是特定于 PHP 或 Java 的。相同的形状适用于其他迁移，其中旧系统是唯一完整的规范。克隆[示例 PHP 到 Java 迁移存储库](https://github.com/aws-samples/sample-php-to-java-migration)，将其作为 Kiro 工作区打开，并探索为其提供支持的技能和指导功能，或将相同的技能文件引入 AWS Transform。有关 AWS 上的语言迁移模式的更多信息，请参阅 [AWS Prescriptive Guidance](https://aws.amazon.com/prescriptive-guidance/) 文档。
