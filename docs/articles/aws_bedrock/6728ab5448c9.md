# Amazon Textract Insights 发布：面向文档的可验证生成式 AI

金融服务、保险、医疗健康以及公共部门的各类组织都依赖文档处理。它们把扫描文件和纸质表单，转成系统可以直接据以处理的结构化数据。随着生成式 AI 成熟，这些组织想要的不再只是准确的文本提取，而是用自己的话描述需要哪些信息，就能从复杂文档中得到可靠、可审计的答案。

今天我们宣布 [Amazon Textract Insights](https://aws.amazon.com/textract/) 正式可用。这是 Amazon Textract 的生成式 AI 新功能，通过 Amazon Textract 内的一个新 API 提供。使用时，您用自然语言描述想要的字段，提交一份文档，或一个混合了多种文档的文档包；返回的结构化结果里，每个值都带有置信度分数和页面级溯源信息，全程不需要训练模型。

## 从混合文档包中提取数据的挑战

许多高价值的文档工作负载，处理的不是干净、单一用途的文件，而是内容混杂的文档包。比如一份抵押贷款档案，常常是一次扫描里同时夹着 W-2 表、工资单、银行对账单和一页手写笔记；每份材料版式各异，出现顺序也不固定。理赔档案和入职材料包也类似：打印表单、密集表格、扫描收据和自由文本信函交错在同一个文件里。

面对这类文件，团队通常走两条路之一，而每条路都有自己的取舍。第一条是自建流水线，把光学字符识别、文档拆分、分类、基础模型 prompt 和人工审核串起来，集成、扩容、运维全得自己扛。第二条是直接套用通用大语言模型，答案读起来通顺，却无法可靠地标出来源页面，也给不出置信度分数。没有可追溯的来源和经过校准的分数，就很难判断哪些值可以自动采纳、哪些需要人工复核，自动化能做到哪一步往往就卡在这里。

Amazon Textract Insights 是为可靠的文档处理而建的，它把整套流程收进 Amazon Textract 上的一个异步请求。团队不必再拼装和运维自建流水线，只需通过一个托管 API，直接拿到需要的数据。

## Amazon Textract Insights 的工作方式

使用 Amazon Textract Insights，您在 blueprint 中定义要提取什么。blueprint 是一份 JSON Schema，每个字段都附有自然语言描述，说明要找什么；每个字段还有推理类型，决定该值是逐字从页面读取，还是根据文档内容推断。您可以从常见文档类型的 AWS 公共 blueprint 起步，例如 W-2 表、1040 表、1098 表、护照或出生证明；也可以针对业务特有的文档自行编写 blueprint。

处理混合文档包时，把预期出现的每种文档类型的 blueprint 加到同一个项目里，再从自己的 Amazon Simple Storage Service（Amazon S3）存储桶提交一个最多 3,000 页的单一文件，并开启拆分。Amazon Textract Insights 会把文档包拆成逻辑子文档，为每份子文档匹配最合适的 blueprint，提取所请求的字段，并为每个值返回置信度分数和溯源信息。

例如，假设您收到一份抵押贷款申请，是 26 页的单一 PDF，里面有 W-2 表、工资单、银行对账单，还有信贷员的手写笔记。您创建一个 Amazon Textract Insights 项目，选用 AWS 公共的 W-2、工资单和银行对账单 blueprint，为信贷员笔记另加一个自定义 blueprint，并开启拆分。随后通过一次 StartDocumentInsights 调用，从 Amazon S3 存储桶提交该文件。Amazon Textract Insights 会把文件拆成一份份独立文档，逐一匹配 blueprint，再把结果写回您的 S3 存储桶。每个值都带有置信度分数，以及它取自哪一页、哪个边界框。

## 面向可审计自动化的置信度与溯源

Amazon Textract Insights 返回两类字段：一类是直接从页面读取的显式字段，另一类是从文档内容推断出的字段。两类都附带置信度分数和溯源信息，标明该值取自哪一页、哪个坐标。

每个值都能追到来源，审核人员或审计人员可以对照原始文档核实任一结果。您可以把自动化延伸到过去只能送去人工审核的文档，同时在需要判断的环节保留人的参与。

>         借助 Amazon Textract Insights，我们可以用平实的语言描述所需字段，服务会识别并提取相应数据。每个提取出的值都会返回置信度分数，团队因此可以把审核精力只放在置信度较低的字段上。我们也很期待探索文档拆分能力，它有望自动把多文档文件拆成独立文档，进一步简化我们的文档处理流程。”

## 基于 Amazon Textract 引擎构建

我们更新了 [Amazon Textract 的读取引擎](https://aws.amazon.com/about-aws/whats-new/2026/11/textract-text-detection-model/) Amazon Textract Core：准确性提升，对密集表格和手写内容的处理更强，DetectDocumentText 和 AnalyzeDocument API 的语言覆盖也扩展到 40 种。Amazon Textract 客户今天就能直接享受这些改进，无需任何改动，现有的 Amazon Textract API 保持不变。

Amazon Textract Core 现已在[另外两个 AWS 区域正式可用](https://aws.amazon.com/about-aws/whats-new/2026/11/textract-tokyo-zurich/)：亚太地区（东京）和欧洲（苏黎世），提供区域内处理的 AWS 区域总数达到 18 个。Amazon Textract Insights 尚未在这些 AWS 区域提供。

## 安全与数据处理

### 项目和 blueprint

Amazon Textract Insights 用 AWS 自有密钥对静态存储的项目和 blueprint 加密。若要使用自己的 AWS Key Management Service（AWS KMS）客户管理密钥，请在调用 CreateProject 或 CreateBlueprint 时通过 EncryptionConfiguration 指定。

### Insight 分析作业

Amazon Textract Insights 从您在 StartDocumentInsights 请求中指定的 Amazon S3 存储桶读取文档，并把结果写回其中。作业的中间数据以 AWS 自有密钥静态加密。如果您在请求的 EncryptionConfiguration 中指定了客户管理密钥，Amazon Textract Insights 会用它加密该作业的中间数据。所有中间数据都是临时的，作业完成即删除。作业完成后写入您的存储桶的结果，适用输出存储桶的默认加密设置。项目的密钥不适用于其作业。

如果您禁用自己的密钥，或撤销 Amazon Textract 对它的访问权限，Amazon Textract Insights 就无法再使用以该密钥加密的数据。

### 跨区域推理

Amazon Textract Insights 会在您所在的地理范围内自动选择最优的 AWS 区域来处理推理请求。这样可以最大化可用计算资源和模型可用性，并力求给出一致的客户体验。所有数据都在 Amazon 的安全网络中加密传输。Amazon Textract Insights 会把您的推理请求安全地路由到请求发起地所在地理范围内的可用计算资源。例如，源自美国的推理请求会在美国境内处理。Amazon Textract Core API 保持不变，仍在您调用的 AWS 区域处理请求。目标 AWS 区域列表见 [Amazon Textract 文档指南](https://docs.aws.amazon.com/general/latest/gr/textract.html)。

## 开始使用

上手 Amazon Textract Insights 只需四个步骤。

**定义所需内容：**从 AWS 公共 blueprint 起步，或用自然语言描述自己的字段。

**创建项目：**把 blueprint 加进去。

**提交文档：**通过一次 API 调用，从您的 Amazon S3 存储桶发送一份文档或一个混合文档包。

**审核结果：**接受达到置信度阈值的值，其余转交人工审核。阈值请用自己文档的代表性样本调校。

Amazon Textract Insights 支持 PDF、PNG、JPEG 和 TIFF 输入，可处理英语、法语、德语、意大利语、葡萄牙语和西班牙语文档。它按页计费而非按 token 计费，没有最低用量承诺。Amazon Textract 各功能的当前费率见 [Amazon Textract 定价页面](https://aws.amazon.com/textract/pricing/)。
