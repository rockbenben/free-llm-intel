# Amazon Textract Insights 发布：面向文档的可验证生成式 AI

金融服务、保险、医疗健康以及公共部门等各行业的组织都依赖文档处理。它们将扫描文件和纸质表单转换为系统可据以操作的结构化数据。随着生成式 AI 日趋成熟，这些组织想要的不只是准确的文本提取。它们希望用自己的语言描述所需信息，并从复杂文档中获得可靠、可审计的答案。

今天，我们宣布 [Amazon Textract Insights](https://aws.amazon.com/textract/) 正式可用。这是 Amazon Textract 的一项全新生成式 AI 功能，可通过 Amazon Textract 内的一个新 API 使用。借助 Amazon Textract Insights，你可以用自然语言描述所需字段，并提交一份文档或一个混合的多文档包。你会收到结构化结果，其中每个值都带有置信度分数和页面级溯源信息，且无需进行模型训练。

## 从混合文档包中提取数据的挑战

许多高价值的文档工作负载涉及的是多样化的混合文档包，而非单纯的单一用途文件。例如，一份抵押贷款文件通常以单次扫描的形式送达，其中包含 W-2 表、工资单、银行对账单以及一页手写笔记。每份文档都有自己的版式，且出现顺序并不固定。理赔文件和入职材料包可能非常相似：打印表单、密集表格、扫描收据和自由文本信函交错在同一个文件中。

团队通常采取两种方法之一，而每种方法都有取舍。第一种是自定义流水线，将光学字符识别、文档拆分、分类、基础模型提示以及审核步骤组合在一起。团队必须自行集成、扩展和运维全部环节。第二种是默认使用通用大语言模型。它能给出流畅的答案，但无法可靠地标注来源页面或给出置信度分数。没有可追溯的来源和经过校准的分数，就很难判断哪些值可以自动接受、哪些需要人工审核。这种不确定性往往限制了团队能够实现自动化的程度。

Amazon Textract Insights 专为可靠的文档处理而构建，将整个工作流整合为 Amazon Textract 上的单次异步请求。你的团队无需组装和运维自定义流水线，而是通过一个托管 API 完成工作，直接获得所需数据。

## Amazon Textract Insights 的工作方式

使用 Amazon Textract Insights 时，你在 blueprint 中定义要提取的内容。blueprint 是一个 JSON Schema，其中每个字段都带有自然语言描述，说明要查找什么。每个字段还具有一种推理类型，用于决定该值是逐字从页面读取，还是根据文档内容推断得出。你可以从针对常见文档类型（如 W-2 表、1040 表、1098 表、护照或出生证明）的 AWS 公共 blueprint 开始，也可以针对自身业务特有的文档自行编写 blueprint。

对于混合文档包，你将预期出现的每种文档类型的 blueprint 添加到同一个项目中。然后，你从自己的 Amazon Simple Storage Service（Amazon S3）存储桶提交一个最多 3,000 页的单一文件，并启用拆分。Amazon Textract Insights 会将文档包拆分为逻辑子文档，将每份子文档与适合它的 blueprint 匹配，提取所请求的字段，并为每个值返回置信度分数和溯源信息。

例如，假设你收到一份抵押贷款申请，它是一个 26 页的单一 PDF，其中包含 W-2 表、工资单、银行对账单以及信贷员的手写笔记。你创建一个 Amazon Textract Insights 项目，使用 AWS 公共的 W-2、工资单和银行对账单 blueprint，为信贷员笔记添加一个自定义 blueprint，并启用拆分。然后，你通过一次 StartDocumentInsights 调用从 Amazon S3 存储桶提交该文件。Amazon Textract Insights 会将文件拆分为各个独立文档，将每份文档与其 blueprint 匹配，并将结果写入你的 S3 存储桶。每个值都包含置信度分数以及其来源页面和边界框。

## 面向可审计自动化的置信度与溯源

Amazon Textract Insights 返回两类字段：第一类是直接从页面读取的显式字段。第二类是根据文档内容推断得出的字段。两者都会随附置信度分数以及溯源信息，标明该值来自哪一页以及相应坐标。

由于每个值都可追溯到其来源，审核人员或审计人员可以对照原始文档确认任何结果。你可以将自动化扩展到以前需要人工审核的文档，同时在需要判断的环节保留人工参与。

>         借助 Amazon Textract Insights，我们可以用平实的语言描述所需字段，该服务会识别并提取相应数据。每个提取出的值都会返回置信度分数，使我们的团队能够仅将审核精力集中在服务置信度较低的字段上。我们还很高兴探索文档拆分功能，这可能有助于自动将多文档文件拆分为独立文档，并进一步简化我们的文档处理工作流。”

## 基于 Amazon Textract 引擎构建

我们更新了 [Amazon Textract 的读取引擎](https://aws.amazon.com/about-aws/whats-new/2026/11/textract-text-detection-model/) Amazon Textract Core，提升了准确性，加强了对密集表格和手写内容的处理，并将 DetectDocumentText 和 AnalyzeDocument API 的语言覆盖范围扩展至 40 种语言。Amazon Textract 客户今天即可在无需任何更改的情况下享受所有这些优势。你的 Amazon Textract API 保持不变。

Amazon Textract Core 现已在[另外两个 AWS 区域正式可用](https://aws.amazon.com/about-aws/whats-new/2026/11/textract-tokyo-zurich/)：亚太地区（东京）和欧洲（苏黎世），使区域内处理所覆盖的 AWS 区域总数达到 18 个。Amazon Textract Insights 尚未在这些 AWS 区域提供。

## 安全与数据处理

### 项目和 blueprint

Amazon Textract Insights 使用 AWS 自有密钥对静态存储的项目和 blueprint 进行加密。如需使用你自己的 AWS Key Management Service（AWS KMS）客户管理密钥，请在调用 CreateProject 或 CreateBlueprint 时于 EncryptionConfiguration 中指定该密钥。

### Insight 分析作业

Amazon Textract Insights 从你在 StartDocumentInsights 请求中指定的 Amazon S3 存储桶读取文档，并将结果写入其中。作业的中间数据使用 AWS 自有密钥进行静态加密。如果你在请求的 EncryptionConfiguration 中指定客户管理密钥，Amazon Textract Insights 会使用该密钥加密作业的中间数据。所有中间数据都是临时的，并在作业完成时删除。作业完成后写入你的存储桶的结果，适用你的输出存储桶的默认加密设置。项目的密钥不适用于其作业。

如果你禁用密钥或移除 Amazon Textract 对该密钥的访问权限，Amazon Textract Insights 将无法再使用以其加密的数据。

### 跨区域推理

Amazon Textract Insights 会自动选择你所在地理范围内的最优 AWS 区域来处理推理请求。这可以最大化可用计算资源和模型可用性，旨在提供一致的客户体验。所有数据都通过 Amazon 的安全网络加密传输。Amazon Textract Insights 会将你的推理请求安全地路由到请求发起所在地理范围内的可用计算资源。例如，源自美国的推理请求将在美国境内处理。Amazon Textract Core API 保持不变，并继续在你调用的 AWS 区域处理请求。有关目标 AWS 区域的列表，请参阅 [Amazon Textract 文档指南](https://docs.aws.amazon.com/general/latest/gr/textract.html)。

## 开始使用

开始使用 Amazon Textract Insights 只需四个步骤。

**定义所需内容：** 从 AWS 公共 blueprint 开始，或用自然语言描述你自己的字段。

**创建项目：** 将你的 blueprint 添加到其中。

**提交文档：** 通过一次 API 调用，从你的 Amazon S3 存储桶发送一份文档或一个混合文档包。

**审核结果：** 接受达到你置信度阈值的值，并将其余值转交审核。使用你自己文档的代表性样本调整阈值。

Amazon Textract Insights 支持 PDF、PNG、JPEG 和 TIFF 输入，并可处理英语、法语、德语、意大利语、葡萄牙语和西班牙语文档。它按页计费，而不是按 token 计费，且无最低承诺用量。有关 Amazon Textract 各功能的当前费率，请参阅 [Amazon Textract 定价页面](https://aws.amazon.com/textract/pricing/)。
