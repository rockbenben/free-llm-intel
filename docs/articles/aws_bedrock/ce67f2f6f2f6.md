# Amazon Bedrock AgentCore harness 新增 Strands harness 默认配置、内置工具与生命周期钩子

构建 AI 智能体时，选择模型只是第一步。智能体仍然需要工具、完成任务的指令、在长会话中管理上下文增长的方法，以及在执行任何会产生后果的操作（例如发放退款）之前提供防护机制。

我们正在升级 Amazon Bedrock AgentCore harness，使其使用 Strands harness——这是我们今年早些时候发布的开源智能体 harness，采用 Apache 2.0 许可证。AgentCore harness 还引入了生命周期钩子，因此你可以在智能体循环的指定节点应用自己的确定性检查与通知。

通过此升级，依赖托管默认配置的智能体会获得推荐模型、面向任务的系统提示词、自动提示缓存（最初面向 Amazon Bedrock 上的 Anthropic 模型）以及主动上下文管理。它们还会获得用于规划、Web 检索、文件系统访问、上下文卸载和任务委派的其他内置工具。这让智能体在长时间任务中具备更强的能力，使其能够跟踪子任务、减少上下文窗口占用并委派工作。借助钩子，你可以通过在特定生命周期检查点运行确定性代码，将非确定性的 AI 行为转化为可预测、安全且受治理的工作流。

无需采用新的资源类型或集成。你已在使用的 AgentCore harness 会自动获得这两项更新。

## 在 AWS 上使用 Strands 能力

[Strands harness](https://strandsagents.com/docs/user-guide/harness/) 提供了一套组装好的智能体基础，包含推荐指令、工具和上下文管理。[Amazon Bedrock AgentCore harness](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness.html) 将该基础作为托管 AWS 服务运行。其结果是得到一个生产级默认智能体，你无需自行组装和运行 harness 或其基础设施。

你无需预置计算资源、打包并托管智能体循环、管理会话扩缩容，或运维工具执行基础设施。每个会话都在 AgentCore runtime（Amazon Bedrock AgentCore 的一项能力）中一个安全、内核隔离的 microVM 中运行，并具备托管计算、扩缩容和高可用性。

AgentCore 通过将 harness 连接到生产智能体所需的各种服务来实现这一点，包括会话持久化、流式响应、使用量元数据、可观测性、AgentCore memory、Identity、Gateway、Browser、Code Interpreter 以及客户提供的容器。你仍然控制模型、指令、工具、权限和生命周期策略，而 AgentCore 管理底层执行环境。

## 能力更强的托管 harness

当你使用 harness 的托管默认配置时，它现在提供更强的体验：

- **当前推荐模型。** 当你省略模型时，Harness 会使用一个推荐默认模型，该模型会随着新模型的发布而演进，始终让你的 harness 保持最新。显式的 harness 级和每次调用级模型配置仍然优先。
- **面向任务的指令。** 托管系统提示词鼓励智能体收集相关上下文、使用合适的工具、持续执行直到任务解决、适应失败或被拒绝的操作，并在报告完成前验证其工作。默认系统提示词会随时间改进，以支持最新的 harness 行为。
- **自动提示缓存。** 对于在 Amazon Bedrock 上使用 Converse 的受支持模型，Harness 会缓存系统提示词、工具定义和对话历史。使用相同提示词和工具集重复调用时，可以使用价格更低的缓存读取 token，从而降低输入处理延迟和成本。
- **主动上下文管理。** 默认情况下，一旦上下文窗口达到可配置阈值，Harness 会总结较早的对话轮次，同时保留近期上下文。通过这种方式保持上下文精简，有助于 Harness 以[比其他领先 harness 低约 34% 的 token 成本](https://strandsagents.com/blog/we-ran-94000-trials-to-measure-the-cost-of-harness-choice/)运行。
- **上下文卸载。** 大型工具结果可以从即时模型上下文中移出。智能体会收到预览，并可在需要时检索完整结果，从而减少重复的上下文占用，同时不失去对数据的访问。
- **跨调用规划。** `todo_write` 工具维护结构化任务计划，该计划可在同一会话的后续调用中恢复，包括在对话总结之后。
- **聚焦式委派。** `subagent` 工具将自包含任务委派给新的 worker，并将结果返回给父智能体。该 worker 是调用内部的，不是单独管理的 harness 资源，并共享调用限制和你的工具调用生命周期钩子。
- **Web 检索。** `web_fetch` 工具从指定网页检索内容，为 harness 提供最新的外部上下文。
- **细粒度文件系统访问。** 借助独立的 `read`、`write` 和 `edit` 工具，你可以仅授予智能体所需的细粒度文件系统能力。

客户提供的 Model Context Protocol (MCP) 服务器、AgentCore Gateway（Amazon Bedrock AgentCore 的一项能力）、Browser、Code Interpreter、内联函数、技能、记忆以及客户提供的容器，继续通过现有 harness 接口工作。

## 默认推荐，需要时可配置

Harness 管理其默认配置，以便在模型、指令、上下文管理和内置能力改进时，使用这些默认配置的智能体能够获得当前 AgentCore 推荐体验。

显式配置始终优先：

- 配置模型 ID 以继续使用特定模型。
- 配置 `systemPrompt` 以完全替换托管系统提示词。
- 配置 `truncation` 以保留特定的上下文管理策略。
- 列出单独的 `allowedTools` 选择器，以维持固定的工具集。

当省略 `allowedTools` 或将其设置为 `["*"]` 时，Harness 会提供当前推荐的内置工具集。由于该工具集可能随时间增加能力，具有固定安全或能力边界的应用程序应仅列出其所需的工具。

例如，以下配置允许只读文件系统访问和 Web 检索，而不授予 shell 访问或文件修改权限：

```
{
    "allowedTools": [
        "read",
        "web_fetch"
    ]
}
```

## 使用生命周期钩子管控会产生后果的操作

借助生命周期钩子，你可以在智能体循环的指定节点运行自己的确定性代码。例如，AWS Lambda 函数可以允许或拒绝请求或工具调用，Amazon Simple Notification Service (Amazon SNS) 主题或 Amazon EventBridge 事件总线可以接收通知，以记录活动或启动异步工作流。

Harness 支持四种生命周期事件：

| **事件** | **运行时机** | **Lambda 拒绝的影响** |
| --- | --- | --- |
| `before_invocation` | 智能体处理请求之前 | 使用 `hook_stopped` 停止调用 |
| `before_tool_call` | 模型提出工具调用之后、执行之前 | 跳过该工具调用。智能体循环继续 |
| `after_tool_call` | 工具结果产生之后 | 保留结果，并在进一步推理之前停止 |
| `after_invocation` | 调用完成之后 | 报告决策。已经流式输出的内容无法撤回 |

只有 Lambda 钩子可以改变智能体循环。它们同步运行并返回 allow 或 deny，可附带可选原因。SNS 和 Amazon EventBridge 钩子是通知，不会阻塞智能体循环。

例如，客户支持智能体可以自行调查订单，同时 `before_tool_call` 钩子在退款工具运行之前，根据审批限额检查每笔退款。以下配置将该 Lambda 函数附加到 harness：

```
[
    {
        "beforeToolCall": {
            "name": "refund_policy",
            "target": {
                "lambda": {
                    "arn": "arn:aws:lambda:us-west-2:123456789012:function:refund-policy",
                    "timeoutSeconds": 10,
                    "failureMode": "deny"
                }
            }
        }
    }
]
```

该函数在钩子负载中接收建议的工具调用，并返回决策：

```
def lambda_handler(event, _context):
    tool = event["context"]
    if tool["toolName"] == "issue_refund" and tool["toolInput"]["amount"] > 500:
        return {"decision": "deny", "reason": "Refund exceeds the $500 auto-approval limit."}
    return {"decision": "allow"}
```

当函数拒绝该调用时，harness 会跳过退款，智能体继续运行，因此它可以告诉客户该请求已升级。每个决策还会作为 `hookEvent` 出现在 `InvokeHarness` 响应流中：

```
{
    "hookEvent": {
        "name": "refund_policy",
        "type": "before_tool_call",
        "decision": "deny",
        "reason": "Refund exceeds the $500 auto-approval limit."
    }
}
```

钩子同样适用于子智能体。当智能体委派任务时，子智能体进行的每次工具调用都会经过相同的 `beforeToolCall` 和 `afterToolCall` 钩子，因此委派无法绕过你的退款策略。调用级钩子（`beforeInvocation`、`afterInvocation`）针对整个调用运行一次。

你通过 `CreateHarness` 或 `UpdateHarness` 配置钩子。如果 Lambda 函数超时或返回错误，钩子会应用其 `failureMode`，默认值为 deny。有关超时、负载字段和上下文限制，请参阅 [Amazon Bedrock AgentCore 开发人员指南](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-lifecycle-hooks.html)中的 Lifecycle hooks。

要查看所有事件和目标类型协同工作，请尝试 Amazon Bedrock AgentCore [GitHub 上的示例仓库](https://github.com/awslabs/agentcore-samples/tree/main/01-features/01-harness/02-use-cases/05-refund-desk-hooks)中的 Refund Desk 示例。六步引导式演示展示了全部四种生命周期事件以及 AWS Lambda、Amazon SNS 和 Amazon EventBridge 目标。它还展示了对客户端提供的内联函数结果的验证，以及 `failureMode` 为 deny 和 allow 时的区别。

## 使用 AgentCore CLI 运行多智能体研究协调器

创建 harness 只需一条命令。你为其命名，并设置所需的指令、上下文策略和限制。此示例创建一个 Research Coordinator：一个带有面向任务的系统提示词和基于总结的截断策略的 harness。在一次调用中，它运行 researcher、synthesizer 和 reviewer 作为子智能体，并返回一份汇总报告。你无需预置基础设施或自行连接委派逻辑，即可获得多智能体编排和上下文管理。

`agentcore harness` 命令直接调用 harness API，因此你不需要 CLI 项目或部署步骤。使用 npm 安装 AgentCore CLI（Amazon Bedrock AgentCore 的一项能力）：

```
npm install -g @aws/agentcore
```

CLI 使用你的默认 AWS 凭证。它没有 `--profile` 标志，因此如果要使用特定配置文件，请设置 `AWS_PROFILE` 环境变量。将示例中协调器的指令保存为工作目录中的 `system_prompt.md`。

### 创建 harness

此命令传入协调器的系统提示词、一个在对话增长时保留最近 30 条消息不变的总结策略，以及足够完成整个工作流的限制。由于省略了模型、记忆和执行角色，harness 使用当前 AgentCore 推荐模型和托管记忆，CLI 会为你创建一个 IAM 执行角色。

```
HARNESS_ID=$(agentcore harness create --region us-west-2 --json \
--name ResearchCoordinator \
--system-prompt "$(cat system_prompt.md)" \
--truncation '{"strategy":"summarization","config":{"summarization":{"summaryRatio":0.3,"preserveRecentMessages":30}}}' \
--max-iterations 100 \
--timeout-seconds 3600 \
| jq -r '.harness.harnessId')
```

创建是异步的。等待创建完成。最后一条命令应输出 `READY`：

```
while [ "$(agentcore harness get --region us-west-2 --id "$HARNESS_ID" --json | jq -r '.harness.status')" = CREATING ]; do sleep 10; done

agentcore harness get --region us-west-2 --id "$HARNESS_ID" --json | jq -r '.harness.status'
```

### 发送提示词

使用新的会话 ID 调用 harness。先从一个基本问题开始。协调器会直接回答，而不调用其子智能体：

```
SESSION_ID=$(uuidgen)
agentcore harness invoke --region us-west-2 \
--id "$HARNESS_ID" \
--session-id "$SESSION_ID" \
--prompt "What is the current trending topic in AI?"
```

然后在同一会话中请求一份完整的研究报告。协调器规划工作，并按顺序委派给 researcher、synthesizer 和 reviewer。如果 reviewer 要求，它最多运行一个修订周期，并交付最终报告。复用会话 ID 会在同一环境中继续对话。

```
agentcore harness invoke --region us-west-2 \
--id "$HARNESS_ID" \
--session-id "$SESSION_ID" \
--prompt "Perform a full research report on how data shapes innovations in the tech industry. Use specialized subagents to complete this task. In the final output, clearly state which part each subagent was responsible for, followed by their specific findings."
```

使用 `--prompt` 时，CLI 会在该轮结束时以 JSON 打印完成的对话记录。研究运行大约需要 10 到 15 分钟。要在其运行时跟进，请省略 `--prompt`，CLI 会打开交互式聊天。

包含完整系统提示词的同一 Python (boto3) 示例可在 GitHub 上的 AgentCore 示例仓库中获取。

### 清理

完成后删除 harness。除非传入 `--delete-managed-memory false`，否则这也会删除其托管记忆。CLI 创建的执行角色会保留在你的账户中，因此如果不再需要，请在 IAM 控制台中删除它。

```
agentcore harness delete --region us-west-2 --id "$HARNESS_ID"
```

## 推出与兼容性

11 月 11 日，AgentCore harness 开始向新的和现有 harness 推出由 Strands harness 提供支持的体验。客户无需采取任何操作。

你显式提供的配置保持不变。省略模型、系统提示词或 `truncation` 配置，或使用 `allowedTools: ["*"]` 的 harness，会获得升级后的托管默认配置。

如果你的应用程序需要固定行为或固定能力边界，请显式配置这些设置。
