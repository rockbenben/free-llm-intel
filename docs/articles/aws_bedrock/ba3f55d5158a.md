# Amazon Bedrock AgentCore 的 Spring AI SDK 现已正式可用

Agentic AI 正在改变组织使用生成式 AI 的方式：从 prompt 与响应的交互，转向能够规划、执行并完成复杂多步骤任务的自主系统。虽然 Agentic AI 领域的早期概念验证让业务相关方感到振奋，但要扩到生产环境，就必须解决可扩展性、治理与安全方面的挑战。[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 是一个 Agentic AI 平台，可用任意框架、任意模型大规模构建、部署和运营 agent。

Java 开发者希望用熟悉的 Spring 模式来构建 AI agent，但生产部署所需的基础设施从零实现起来相当复杂。Amazon Bedrock AgentCore 提供了托管运行基础设施（可扩展性、可靠性、安全性、可观测性）、短期与长期记忆、浏览器自动化、沙箱化代码执行以及评估等构建模块。目前把这些能力集成到一个 Spring 应用中，需要编写自定义 controller 来满足 AgentCore Runtime 的契约、处理 Server-Side Events（SSE）流式传输、实现健康检查、管理速率限制，还要把 Spring advisor、memory repository 和工具定义接线好。这些是写好任何 AI Agent 逻辑之前就要花数周的基础设施工作。

借助全新的 [Spring AI AgentCore SDK](https://github.com/spring-ai-community/spring-ai-agentcore)，你可以构建生产就绪的 AI agent，并让它们在高度可扩展的 AgentCore Runtime 上运行。Spring AI AgentCore SDK 是一个开源库，通过注解、自动配置和可组合的 advisor 这些熟悉的模式，把 Amazon Bedrock AgentCore 的能力带入 [Spring AI](https://spring.io/projects/spring-ai)。Spring 开发者只需添加一个依赖、在一个方法上打注解，剩下的交给 SDK。

## 理解 AgentCore Runtime 契约

[AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 按用量计费来管理 agent 的生命周期与伸缩，意味着你不为空闲算力付费。runtime 把传入请求路由给你的 agent 并监控它的健康状况，但这要求你的 agent 遵守一份契约。该契约要求实现方暴露两个端点。**/invocations** 端点接收请求，并以 JSON 或 SSE 流式方式返回响应。**/ping** 健康端点报告 Healthy 或 HealthyBusy 状态。长时间运行的任务必须表明自己正忙，否则 runtime 可能为了节省成本把它们缩容掉。SDK 自动实现了这份契约，包括异步任务检测——当 agent 正在处理时，它会报告[忙碌状态](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-long-run.html)。

除契约之外，SDK 还为生产负载提供了额外能力，例如以正确的分帧处理 SSE 响应、处理背压，以及针对大响应的连接生命周期管理。它还提供速率限制，对请求进行限流，以保护你的 agent 免受流量尖峰冲击，并限制单用户消耗。你只需专注于 agent 逻辑，runtime 集成由 SDK 处理。

本文中，我们从 chat 端点开始构建一个生产就绪的 AI agent，然后逐步加入流式响应、对话记忆，以及用于网页浏览和代码执行的工具。读到最后，你将拥有一个功能完整的 agent，既可部署到 AgentCore Runtime，也可在你现有的基础设施上独立运行。

## 前置条件

为了跟做本文，你需要：

- Java 17 或更高版本（推荐 Java 25）
- [Spring Boot](https://spring.io/projects/spring-boot) 3.5 或更高版本
- 一个 AWS 账户
- [Maven](https://maven.apache.org/) 或 [Gradle](https://gradle.org/)

## 方案概述

Spring AI AgentCore SDK 基于三条设计原则：

- **约定优于配置** —— 合理的默认值与 AgentCore 的预期一致（端口 8080、端点路径、content-type 处理），无需显式配置。
- **注解驱动开发** —— 单个 @AgentCoreInvocation 注解就能把任意 [Spring bean](https://docs.spring.io/spring-framework/reference/core/beans/definition.html) 方法变成一个与 AgentCore 兼容的端点，并自动完成序列化、流式检测和响应格式化。
- **部署灵活性** —— SDK 支持 [AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 做全托管部署，但你也可以把各个独立 module（[Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html)、[Browser](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html)、[Code Interpreter](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/code-interpreter-tool.html)）用在运行于 [Amazon EKS](https://aws.amazon.com/eks/)、[Amazon ECS](https://aws.amazon.com/ecs/) 或任何其他基础设施上的应用里。

下图展示了 SDK 各组件如何交互。@AgentCoreInvocation 注解负责处理 runtime 契约，而 ChatClient 组合 Memory advisor、Browser 工具和 Code Interpreter。部署到 AgentCore Runtime 是可选的，你可以把 SDK 的各个 module 当作独立功能使用。

## 创建你的第一个 AI agent

下面这一节带你一步步创建一个功能完整的 agent：

### 步骤 1：添加 SDK 依赖

把 Spring AI AgentCore BOM 加入你的 Maven 项目，然后引入 runtime starter：

```
<dependencyManagement>
     <dependencies>
         <dependency>
             <groupId>org.springaicommunity</groupId>
             <artifactId>spring-ai-agentcore-bom</artifactId>
             <version>1.0.0</version>
             <type>pom</type>
             <scope>import</scope>
         </dependency>
     </dependencies>
 </dependencyManagement>
 
<dependencies>
     <dependency>
         <groupId>org.springaicommunity</groupId>
         <artifactId>spring-ai-agentcore-runtime-starter</artifactId>
     </dependency>
 </dependencies>
```

### 步骤 2：创建 agent

@AgentCoreInvocation 注解告诉 SDK，这个方法负责处理传入的 agent 请求。SDK 会自动配置 POST /invocations 和 GET /ping 端点、处理 JSON 序列化，并自动报告健康状态。

```
@Service
 public class MyAgent {
 
    private final ChatClient chatClient;
 
    public MyAgent(ChatClient.Builder builder) {
         this.chatClient = builder.build();
     }
 
    @AgentCoreInvocation
     public String chat(PromptRequest request) {
         return chatClient.prompt()
             .user(request.prompt())
             .call()
             .content();
     }
 }
 
record PromptRequest(String prompt) {}
```

### 步骤 3：配置 Amazon Bedrock

在 application.properties 中设置模型和 AWS Region：

```
spring.ai.bedrock.aws.region=us-east-1                                
spring.ai.bedrock.converse.chat.options.model=global.anthropic.claude-sonnet-4-5-20250929-v1:0
```

### 步骤 4：本地测试

启动应用并发送一个请求：

```
mvn spring-boot:run
 
curl -X POST http://localhost:8080/invocations \
   -H "Content-Type: application/json" \
   -d '{"prompt": "What is Spring AI?"}' 
```

这就是一个完整的、与 AgentCore 兼容的 AI agent。没有自定义 controller，没有协议处理，也没有健康检查实现。

### 步骤 5：添加流式输出

若要在响应生成时即时流式输出，把返回类型改成 Flux<String>。SDK 会自动切换到 SSE 输出：

```
@AgentCoreInvocation
 public Flux<String> streamingChat(PromptRequest request) {
     return chatClient.prompt()
         .user(request.prompt())
         .stream()
         .content();
 }
```

SDK 负责 SSE 分帧、Content-Type 头、换行保留和连接生命周期。你的代码始终聚焦于 AI 交互本身。

### 步骤 6：为 agent 添加记忆

现实中的 agent 必须记住用户在一段对话中先前说过什么（短期记忆），以及随着时间积累学到的东西（长期记忆）。SDK 通过 Spring AI 的 advisor 模式与 [AgentCore Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html) 集成——advisor 是一种拦截器，在 prompt 到达模型之前为其补充上下文。

短期记忆（STM）用滑动窗口保留最近的消息。长期记忆（LTM）用四种策略跨会话持久化知识：

| **策略** | **用途** | **示例** |
| --- | --- | --- |
| Semantic | 关于用户的事实性信息 | “用户在金融行业工作” |
| User preference | 显式设置与选择 | “偏好公制单位” |
| Summary | 压缩后的对话历史 | 用于保持连贯性的会话摘要 |
| Episodic | 过往交互与经验教训 | “用户上周在 X 上遇到了麻烦” |

AgentCore 会异步整合这些策略，在无需开发者显式干预的情况下提取相关信息。添加 memory 依赖并启用自动发现。在自动发现模式下，SDK 会自动探测可用的长期记忆策略和 namespace，无需手工配置：

```
agentcore.memory.memory-id=${AGENTCORE_MEMORY_ID}
agentcore.memory.long-term.auto-discovery=true
```

然后注入 AgentCoreMemory 并把它组合进你的 chat client：

```
// Add to MyAgent constructor
 private final AgentCoreMemory agentCoreMemory;
 
public MyAgent(ChatClient.Builder builder, AgentCoreMemory agentCoreMemory) {
     this.agentCoreMemory = agentCoreMemory;
     this.chatClient = builder.build();
 }
 
// Update the chat method to include memory advisors
 @AgentCoreInvocation
 public String chat(PromptRequest request, AgentCoreContext context) {
     String sessionId = context.getHeader(AgentCoreHeaders.SESSION_ID);
 
    return chatClient.prompt()
         .user(request.prompt())
         .advisors(agentCoreMemory.advisors)
         .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, "user:" + sessionId))
         .call()
         .content();
 }
```

`agentCoreMemory.advisors` 列表同时包含 STM 与所有已配置的 LTM advisor。有关详细配置选项，见 [Memory 文档](https://github.com/spring-ai-community/spring-ai-agentcore)。

### 步骤 7：用工具扩展 agent

AgentCore 提供专门的工具，SDK 通过 ToolCallbackProvider 接口把它们暴露为 Spring AI 的 tool callback。

**浏览器自动化** —— agent 可以用 [AgentCore Browser](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-tool.html) 浏览网站、提取内容、截图，并与页面元素交互：

```
<dependency>
     <groupId>org.springaicommunity</groupId>
     <artifactId>spring-ai-agentcore-browser</artifactId>
 </dependency>
```

**代码解释器** —— agent 可以用 [AgentCore Code Interpreter](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/code-interpreter-tool.html) 在安全沙箱中编写并运行 Python、JavaScript 或 TypeScript。沙箱内置 numpy、pandas 和 matplotlib。生成的文件通过 artifact store 捕获。

```
<dependency>
     <groupId>org.springaicommunity</groupId>
     <artifactId>spring-ai-agentcore-code-interpreter</artifactId>
 </dependency>
```

两个工具都通过 Spring AI 的 `ToolCallbackProvider` 接口集成。下面是把记忆、浏览器和代码解释器组合在一起的最终版 MyAgent：

```
@Service
 public class MyAgent {
 
    private final ChatClient chatClient;
    private final AgentCoreMemory agentCoreMemory;
 
    public MyAgent(
             ChatClient.Builder builder,
             AgentCoreMemory agentCoreMemory,
             @Qualifier("browserToolCallbackProvider") ToolCallbackProvider browserTools,
             @Qualifier("codeInterpreterToolCallbackProvider") ToolCallbackProvider codeInterpreterTools) {
         this.agentCoreMemory = agentCoreMemory;
         this.chatClient = builder
             .defaultToolCallbacks(browserTools, codeInterpreterTools)
             .build();
     }
 
    @AgentCoreInvocation
    public Flux<String> chat(PromptRequest request, AgentCoreContext context) {
         String sessionId = context.getHeader(AgentCoreHeaders.SESSION_ID);
 
        return chatClient.prompt()
             .user(request.prompt())
             .advisors(agentCoreMemory.advisors)
             .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, "user:" + sessionId))
             .stream()
             .content();
     }
 }
```

模型平等地看到所有工具，并根据用户请求决定调用哪一个。虽然本文聚焦于用 Amazon Bedrock 访问基础模型（FM），Spring AI 支持包括 OpenAI 和 Anthropic 在内的多家大语言模型（LLM）提供商，因此你可以挑选适合自己的模型。举例来说，一个差旅与费用管理 agent 可以在同一段对话中，用 browser 工具查询航班选项，用代码解释器分析支出模式并生成图表：

## 部署你的 agent

SDK 支持两种部署模型：

**AgentCore Runtime** —— 若需要全托管基础设施，把应用打包成 ARM64 容器，推送到 [Amazon Elastic Container Registry (Amazon ECR)](https://aws.amazon.com/ecr/)，再创建一个引用该镜像的 AgentCore Runtime。runtime 负责伸缩与健康监控。[examples/terraform](https://github.com/spring-ai-community/spring-ai-agentcore/tree/main/examples/terraform) 目录提供了基础设施即代码（IaC），包含 IAM 与 OAuth 认证选项。

**独立运行** —— 在运行于 Amazon Elastic Kubernetes Service（Amazon EKS）、Amazon Elastic Container Service（Amazon ECS）、Amazon Elastic Compute Cloud（Amazon EC2）或本地环境的应用中，使用 AgentCore Memory、Browser 或 Code Interpreter。采用这种方式，团队可以逐步引入 AgentCore 的能力。例如，先在现有的 Spring Boot 服务里加入记忆，之后再迁移到 AgentCore Runtime。

## 认证与授权

AgentCore Runtime 支持两种认证方式：用于 AWS 服务间调用的基于 IAM 的 SigV4，以及面向用户侧应用的 OAuth2。当你的 Spring AI agent 部署到 AgentCore Runtime 时，认证在基础设施层完成。你的应用通过 `AgentCoreContext` 获得已认证用户的身份。之后可以在 Spring 应用里用标准的 Spring Security 模式，按这些原则实现细粒度授权。对于独立部署，你的 Spring 应用负责用 Spring Security 提供认证与授权。此时，对 AgentCore 服务（Memory、Browser、Code Interpreter）的调用使用标准 AWS SDK 的凭证机制来保护。

## 通过 AgentCore Gateway 连接 MCP 工具

Spring AI agent 可以通过 AgentCore Gateway 访问企业工具，后者提供 Model Context Protocol（MCP）支持、出站认证和语义化工具注册表。要使用 Gateway，把 Spring AI MCP client 端点配置为指向 AgentCore Gateway，并用 IAM SigV4 或 OAuth2 认证：

```
spring.ai.mcp.client.toolcallback.enabled=true
spring.ai.mcp.client.initialized=false
spring.ai.mcp.client.streamable-http.connections.gateway.url=${GATEWAY_URL}
```

这样 agent 就能发现并调用企业工具，而 Gateway 负责对下游服务的凭证管理。想看动手示例，见 [Building Java AI agents with Spring AI and Amazon Bedrock AgentCore](https://catalog.workshops.aws/java-spring-ai-agents) 工作坊，其中演示了与 AgentCore Gateway 的 MCP 集成。

## 下一步

SDK 会持续演进。即将推出的集成包括：

- *可观测性* —— 把 Spring AI 的 tracing、metrics 和 logging 集成起来，通过 OpenTelemetry 支持 Amazon CloudWatch 以及 LangFuse、Datadog、Dynatrace 等外部可观测性工具。基础的 AgentCore 可观测性今天已经可用。
- *评估* —— 面向 agent 响应的测试与质量评估框架。
- *高级身份管理* —— 为 Spring AI Agent 简化安全上下文获取。

## 结论

本文中，我们展示了如何用 Spring AI AgentCore SDK 在 Java 中构建生产就绪的 AI agent。从一个打了注解的方法出发，我们加入了流式响应、持久记忆、浏览器自动化和代码执行——全部通过熟悉的 Spring 模式完成。SDK 是 Apache 2.0 许可下的开源项目。开始使用：

- 在 GitHub 上探索 [Spring AI AgentCore SDK](https://github.com/spring-ai-community/spring-ai-agentcore)。仓库中包含可作为起点的示例应用： `simple-spring-boot-app` —— 具备基本请求处理的最小 agent `spring-ai-sse-chat-client` —— 使用 Server-Sent Events 的流式响应 `spring-ai-memory-integration` —— 短期与长期记忆用法 `spring-ai-extended-chat-client` —— 带按用户记忆隔离的 OAuth 认证 `spring-ai-browser` —— 网页浏览与截图能力
- 阅读 [Amazon AgentCore 文档](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-agentcore.html)，了解 Runtime、Memory、Browser 和 Code Interpreter 服务的细节。
- 试用 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock/) 启用模型访问，并探索可用的基础模型。
- 想动手深入，试试 [Building Java AI agents with Spring AI and Amazon AgentCore](https://catalog.workshops.aws/java-spring-ai-agents) 工作坊。在大约四小时里，你会搭建一个完整的差旅与费用管理助手——逐步加入 persona、记忆、知识检索、网页浏览、代码执行、MCP 工具集成，并以无服务器方式部署到 AgentCore Runtime，带认证与可观测性。不需要人工智能与机器学习（AI/ML）经验。
