# 使用 Amazon Bedrock Knowledge Bases 构建 GraphRAG 应用

如今，企业采用 AI-first 战略以保持竞争力并提升效率已愈发普遍。随着生成式 AI 的采用不断增长，这项技术解决问题的能力也在提升（一个例子是生成全面市场报告的用例）。简化待解决问题日益增长的复杂度的一种方式是通过图（graph），图擅长对关系建模，并能从相互连接的数据与实体中提炼出有意义的洞察。

在本文中，我们探讨如何在 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 中使用基于图的检索增强生成（GraphRAG）来构建智能应用。与基于相似度分数检索文档的传统向量搜索不同，knowledge graph 编码实体之间的关系，使大语言模型（LLM）能够以具备上下文感知的推理来检索信息。这意味着系统不再只是找到最相关的文档，而是可以推断实体与概念之间的连接，从而提升响应准确性并减少幻觉。要检视所构建的图，[Graph Explorer ](https://docs.aws.amazon.com/neptune/latest/userguide/visualization-graph-explorer.html)是一个很好的工具。

## GraphRAG 简介

传统的检索增强生成（RAG）方法通过从知识源获取相关文档来改进生成式 AI，但当相关信息分散在多份文档或来源中时，它们常常受困于上下文碎片化。

这正是 GraphRAG 的用武之地。GraphRAG 的诞生是为了借助 knowledge graph 来增强知识检索与推理，它把信息组织为实体及其关系。与仅依赖向量搜索或关键词匹配的传统 RAG 方法不同，GraphRAG 支持多跳推理（不同上下文片段之间的逻辑连接）、更好的实体链接以及上下文检索。这使它对于复杂的文档解读尤其有价值，例如法律合同、研究论文、合规指南和技术文档。

## Amazon Bedrock Knowledge Bases GraphRAG

**Amazon Bedrock Knowledge Bases** 是一项用于存储、检索和组织企业知识的托管服务。它与通过 Amazon Bedrock 提供的 foundation model 无缝集成，使 AI 应用能够生成更有依据、更可信的响应。Amazon Bedrock Knowledge Bases [现已支持 GraphRAG，](https://aws.amazon.com/about-aws/whats-new/2025/03/amazon-bedrock-knowledge-bases-graphrag-generally-available/) 这一高级特性通过整合基于图的检索来增强传统 RAG。它让 LLM 能够理解实体、事实和概念之间的关系，使响应在上下文上更贴切、更可解释。

### Amazon Bedrock Knowledge Bases GraphRAG 的工作原理

图是通过把数据表示为节点（实体）以及节点之间的边（关系）的结构化表示来生成的。这个过程通常包括：识别数据中的关键实体，确定这些实体彼此如何关联，然后把这些关系建模为图中的连接。在传统 RAG 流程之后，Amazon Bedrock Knowledge Bases GraphRAG 会执行额外步骤来提升生成响应的质量：

- 它识别并检索与初次检索到的文档 chunk 相关联的图节点或 chunk 标识符。
- 随后系统通过遍历图结构扩展这些信息，从向量库中检索这些相关 chunk 的更多细节。
- 借助这种包含相关实体及关键连接的更丰富上下文，GraphRAG 可以生成更全面的响应。

### 图是如何构建的

设想从 PDF 文件这类非结构化数据中抽取信息。在 Amazon Bedrock Knowledge Bases 中，图是通过一个扩展传统 PDF 摄取流程的过程来构建的。系统会创建三类节点：chunk、document 和 entity。摄取 pipeline 首先使用可自定义的方法，把来自 Amazon Simple Storage Service（Amazon S3）文件夹的文档切分为 chunk（你可以从基础的固定大小切分，一直选到更复杂的基于 LLM 的切分机制）。随后每个 chunk 被嵌入，一个 `ExtractChunkEntity` 步骤使用 LLM 识别 chunk 中的关键实体。这些信息连同 chunk 的 embedding、文本和文档 ID 一起发送到 [Amazon Neptune Analytics](https://docs.aws.amazon.com/neptune-analytics/latest/userguide/what-is-neptune-analytics.html) 存储。插入过程通过 [Amazon Neptune 中的批量加载 API](https://docs.aws.amazon.com/neptune/latest/userguide/bulk-load.html) 创建相互连接的节点与边，把 chunk 链接到其源文档和抽取出的实体。下图展示了这一过程。

### 用例

设想一家公司需要分析大批文档，并且需要把分散在这些文档中的实体关联起来以回答一些问题（例如，Amazon 近年来投资或收购了哪些公司？）。从这类非结构化数据中提炼有意义的洞察，并将其与其他内部和外部信息连接起来，是一项重大挑战。为应对这一点，该公司决定使用 [Amazon Bedrock Knowledge Bases](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base.html) 构建一个 GraphRAG 应用，利用图数据库来表示数据中的复杂关系。

该公司的一项业务需求是生成一份全面的市场报告，详细分析内部与外部信息如何与行业趋势、公司行动和绩效指标相关联。通过使用 Amazon Bedrock Knowledge Bases，该公司可以构建一个 knowledge graph，表示新闻稿、产品、公司、人物、财务数据、外部文档和行业事件之间错综复杂的连接。在这一过程中，Graph Explorer 工具变得极为重要，它帮助数据科学家和分析师可视化这些连接、导出相关子图，并把它们与 Amazon Bedrock 中的 LLM 无缝集成。图结构整理完善之后，公司里的任何人都可以用自然语言向 Amazon Bedrock LLM 提问，并从跨多份文档和实体、信息彼此关联的 knowledge base 中生成更深入的洞察。

## 方案概述

在这个使用 Amazon Bedrock Knowledge Bases 的 GraphRAG 应用中，我们设计了一套简明的流程，把原始文档转化为丰富且相互连接的知识图谱。其工作方式如下：

- **文档摄取**：用户可以手动把文档上传到 Amazon S3，或设置自动摄取 pipeline。
- **切分、实体抽取与 embedding 生成**：在 knowledge base 中，文档首先通过固定大小切分或可自定义方法切分为 chunk，然后为每个 chunk 计算 embedding。最后，提示 LLM 从每个 chunk 中抽取关键实体，生成一个 GraphDocument，其中包含实体列表、chunk embedding、切分后的文本和文档 ID。
- **图构建**：embedding 连同抽取出的实体及其关系一起用于构建 knowledge graph。构建出的图数据（包括节点（实体）和边（关系））会自动插入 Amazon Neptune。
- **数据探索**：图数据库填充完成后，用户可以使用 [Graph Explorer](https://github.com/aws/graph-explorer) 快速探索数据。这个直观的界面支持对 knowledge graph 进行可视化导航，帮助用户理解数据中的关系与连接。
- **LLM 驱动的应用：** 最后，用户可以通过 Amazon Bedrock 利用 LLM 查询图，并跨文档检索关联信息。这能实现强大的、具备上下文感知的响应，从已摄取文档的整个语料中提炼洞察。

## 先决条件

本文的示例方案使用以下网站的数据集：

- [ Amazon Press Center 归档](https://press.aboutamazon.com/press-release-archive)
- [ Amazon 投资者关系季度报告](https://ir.aboutamazon.com/quarterly-results/default.aspx)

此外，你需要：

- 在 AWS 上创建一个 S3 bucket 来存放文件。在本例中，我们把该 bucket 命名为：blog-graphrag-s3。
- 从上述网站下载 PDF 和 XLS 文件，并上传到该 S3 bucket。

## 构建 Graph RAG 应用

- 打开 [Amazon Bedrock 的 AWS Management Console](https://console.aws.amazon.com/bedrock/)。
- 在导航窗格中，在 **Knowledge Bases** 下选择 **Create**。
- 选择 **Knowledge Base with vector store**，然后选择 **Create**。
![Amazon Bedrock Knowledge Bases 界面，展示创建与测试选项](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/19/ML-18340_003_kb.png)
- 为 **Knowledge Base name** 输入名称（例如：`knowledge-base-graphrag-demo`）以及可选描述。
- 选择 **Create and use a new service role**。
- 选择 **Data source as Amazon S3**。
- 其余保持默认，选择 **Next** 继续。
- 输入 **Data source name**（例如：`knowledge-base-graphrag-data-source`）。
- 通过选择 **Browse S3** 选择一个 S3 bucket。（如果你的账户中没有 S3 bucket，请创建一个。务必上传所有必要文件。）
- S3 bucket 创建、文件上传完成后，选择 `blog-graphrag-s3` bucket。
- 其余保持默认，选择 **Next**。
- 选择 **Select model **，然后选择一个 embeddings 模型（在本例中，我们选择了 **Titan Text Embeddings V2 model**）。
- 在 **Vector database** 部分，在 **Vector store creation method** 下选择 **Quick create a new vector store**，在 **Vector store** 中选择 **Amazon Neptune Analytics (GraphRAG)**，然后选择 **Next** 继续。
- 复核所有细节。
- 复核完所有细节后选择 **Create Knowledge Base**。
- 在 Amazon Bedrock 上创建 knowledge base 可能需要几分钟，具体取决于数据源中的数据量。创建成功后，你应该能看到 knowledge base 的状态为 **Available**。

![填写 knowledge base 详情与数据源配置](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/22/ML-18340_004_create_kb.gif)

## 结论

将 Graph Explorer 与 Amazon Neptune 和 Amazon Bedrock LLM 结合使用，为构建复杂的 GraphRAG 应用提供了方案。Graph Explorer 提供对数据中复杂关系的直观可视化与探索，让理解和分析公司之间的连接与投资变得简单。你可以利用 Amazon Neptune 图数据库的能力，对相互连接的数据建立高效查询，从而在各种实体与关系之间快速关联信息。

通过用这种方法分析 Amazon 的投资与收购历史，我们可以快速识别出原本可能被忽视的模式与洞察。例如，在考察“Which companies has Amazon invested in or acquired in recent years?”或“How is AWS increasing energy efficiency?”这些问题时，GraphRAG 应用可以遍历 knowledge graph，把新闻稿、投资者关系信息、实体和财务数据关联起来，全面呈现 Amazon 的战略动作。

集成 Amazon Bedrock LLM 进一步提升了生成结果的准确性与相关性。这些模型可以为图数据提供语境，帮助你理解公司关系与投资趋势中的细微差别，并有助于生成全面的市场报告。基于图的知识与自然语言处理的这种结合，带来更精确的答案与数据解读，超越基本的事实检索，提供对 Amazon 投资战略的分析。

总而言之，Graph Explorer、Amazon Neptune 和 Amazon Bedrock LLM 之间的协同，为构建能从复杂数据集中提炼有意义洞察的 GraphRAG 应用搭好了框架。这种方法简化了分析企业投资的过程，并创造出在各行各业与各种用例中分析非结构化数据的新方式。
