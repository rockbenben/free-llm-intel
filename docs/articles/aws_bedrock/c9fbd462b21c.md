# 构建 AI 驱动的合规证据采集系统

合规审计需要完整的证据链，往往涉及跨多个系统的数百张截图。你的合规团队很可能要花数小时手动浏览 [GitHub](https://github.com/) 仓库、AWS 控制台和内部应用，在每一步都截取屏幕截图。这一手工过程耗时、易错，并且难以在多个审计周期中稳定复现。本文演示我们如何借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和浏览器自动化来自动化审计工作流。

本文展示如何为你的组织构建一套类似的系统。你将了解架构决策、实现细节和部署流程，这些内容可以帮助你自动化自己的合规工作流。我们构建了一个浏览器扩展，使用 Amazon Bedrock 与 [Amazon Nova 2 Lite](https://aws.amazon.com/nova/) 模型来自动完成这一证据采集过程。该扩展会执行预定义的合规工作流，自动截取带时间戳的截图，并把整理好的证据存入 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/)。它还能分析合规文档，并利用自然语言处理（natural language processing，NLP）生成新的工作流。

你将了解我们如何设计这套方案的架构、如何集成 Amazon Nova 2 Lite 实现智能自动化，以及如何实现应对现代 Web 应用复杂性的浏览器自动化工具。我们会介绍技术实现细节、部署流程和真实使用模式。

## 方案概览

我们选择浏览器自动化加 AI 的组合，有几个关键原因：它可以配合任何 Web 应用工作而无需 API 访问；它能截取审计人员所需的可视证据；它还能通过智能自动化适应 UI 变化。

该方案以面向 Chrome 和 Firefox 的浏览器扩展作为主要界面，提供三项主要能力：证据采集器、AI 驱动的工作流设计器和报告投递。证据采集器执行预定义工作流，在 Web 应用中导航，并把带时间戳的截图存入 Amazon S3 存储桶。AI 驱动的工作流设计器使用 Amazon Nova 2 Lite 模型与 Amazon Bedrock 通信。当你上传一份合规文本文件时，Amazon Nova 2 Lite 会分析它，并生成扩展可以执行的工作流 JSON。在报告投递方面，工作流完成后，[Amazon Simple Email Service（Amazon SES）](https://aws.amazon.com/ses/) 会生成合规报告并发送到指定邮箱。

在基础设施方面，有两个 [AWS Lambda](https://aws.amazon.com/lambda/) 函数为该方案提供支持：一个在部署期间把初始系统提示词上传到 S3 存储桶，另一个负责清理存储桶。在身份验证与授权方面，扩展使用 [Amazon Cognito](https://aws.amazon.com/cognito/) 管理用户登录。Cognito 与 [AWS Security Token Service（AWS STS）](https://docs.aws.amazon.com/STS/latest/APIReference/welcome.html) 和 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam/) 协作，为扩展提供访问 Amazon Bedrock、Amazon S3 和 Amazon SES 所需的、范围受限的最小权限凭证。AWS 对静态存储的证据加密，按日期和工作流组织，并保留完整的审计日志。

## 架构

了解了系统能做什么，接下来看看它的结构。浏览器扩展采用模块化架构，分为四个不同的层：

### [![证据采集器示意图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/18/1.EvidenceCollectorDiagram.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/18/1.EvidenceCollectorDiagram.png)

### A. UI 层

侧边面板是主要界面，包含三个组件。聊天界面用于与 Amazon Nova 2 Lite 进行自然语言交互，处理合规问题和一次性自动化任务。工作流管理面板列出可用工作流、显示执行状态，并提供编辑能力。身份验证 UI 负责 Amazon Cognito 登录和配置管理。下图展示了该 UI 及其功能。

### [![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/23/0.1.UILayerOverview-620x1024-1.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/18/0.1.UILayerOverview.png)

### B. AI Agent 层

Amazon Nova 2 Lite 作为智能层，提供三种运行模式：

- **聊天模式：**例如提出临时性问题，它会回答合规问题，并依据自然语言指令执行浏览器自动化工具。当你需要快速采集证据、又不想创建完整工作流时，这种模式最有用。

- **设计器模式**（用于创建新工作流）：分析上传的 `.txt` 文档，抽取工作流步骤并生成自动化脚本。当你有合规文档并需要创建可重复使用的工作流时，就用这种模式。

- **报告生成模式**（在工作流完成后使用）：工作流完成后分析已采集的截图，生成一份完整的合规报告，包含证据摘要、发现项和合规状态评估。随后 Amazon SES 会把完成的报告通过电子邮件发送到你指定的邮箱。

### C. 工作流引擎

工作流执行引擎会逐步处理以 JSON 定义的工作流。JSON 是一种用于定义分步指令的文本格式。暂时不必纠结技术细节，我们会展示 AI 如何自动生成这些内容。引擎负责导航、等待页面加载、结合上下文截取屏幕截图，并管理需要人工操作（例如身份验证）的用户确认步骤。引擎还包含智能错误恢复：当某一步失败时，它会用 Amazon Nova 2 Lite 给出替代方案。

工作流设计器使用 Amazon Nova 2 Lite 分析合规文档，抽取所需的证据点，并生成工作流 JSON。你可以在保存前测试工作流、编辑已有工作流，并在 Amazon S3 中管理工作流版本。

### D. 存储与服务

Amazon S3 以结构化的文件夹层级存储证据，按截图、合规文档、AI 提示词、工作流及其备份、聊天日志和生成的报告分别组织，如下例所示：

```
evidence-collector-bucket-{AccountId}-{Region}/
|
|--- evidence/
     |--- README.txt → Explains the evidence folder structure and organization
     |--- YYYY/MM/DD/
          |--- screenshot-*.png → Captured screenshots during workflow execution for compliance evidence
|
|--- workflow-documents/
     |--- README.txt → Explains the workflow documents folder purpose
     |--- {timestamp}-{filename}.txt → User-uploaded compliance documents analyzed by AI to generate workflows
|
|--- config/
     |--- prompts/
     |    |--- compliance-assistant-prompt.txt → Defines AI assistant's compliance knowledge and response guidelines
     |    |--- workflow-designer-prompt.txt → Instructs AI on generating workflows from compliance documents
     |    |--- report-analysis-prompt.txt → Guides AI in analyzing workflow execution results for reports
|    |
|    |--- workflows/
          |--- README.txt → Explains the workflows folder and backup strategy
          |--- user-workflows.json → Current active workflows available to users
          |--- backups/
               |--- user-workflows-{timestamp}.json → Timestamped backup created before each workflow update
|
|--- chat-logs/
     |--- README.txt → Explains the chat logs folder purpose
     |--- chat-log-{timestamp}.json → Conversation logs between users and AI for audit trail
|
|--- reports/
     |--- README.txt → Explains the reports folder structure and organization
     |--- YYYY/MM/DD/
          |--- report-{workflow-name}-{timestamp}.html → Generated HTML evidence report documenting workflow execution
```

## AI 驱动的工作流设计器

下图展示前端发生了什么，以及你会与哪些 AWS 服务交互。

[![AI 驱动的工作流设计器](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/18/2.AI-PoweredWorkflowDesigner.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/18/2.AI-PoweredWorkflowDesigner.png)

工作流设计器解决了一个关键难题：从合规文档快速、准确地创建工作流。你可以上传包含合规要求的文本文件，Amazon Nova 2 Lite 会分析它并生成可执行的工作流。

该过程分三步：**(1)** 文档上传——上传包含合规要求的文本文件；**(2)** AI 分析——Amazon Nova 2 Lite 抽取所需证据点、确定要检查的系统，并判断可自动化的机会；**(3)** 工作流生成——AI 生成完整的工作流 JSON，包含导航步骤、截图点，以及需要时的用户确认步骤。

例如，给定一份文档写道：“*要取得证据，我们需要从 GitHub.com 截取一些屏幕截图。登录后，前往仓库 “https://github.com/aws-samples”。确认 main 分支已启用分支保护并配置了必需的评审。登录后截一张图，然后在验证步骤之后再截一张。*” Nova 2 Lite 分析这份文档并生成如下工作流：

```
{
  "workflows": [
    {
      "name": "GitHub Branch Protection Verification",
      "description": "Verify branch protection is enabled on the main branch with required reviews",
      "steps": [
        {
          "action": "navigate",
          "url": "https://github.com",
          "description": "Navigate to GitHub homepage"
        },
        {
          "action": "wait_for_user",
          "description": "Please log in with your GitHub credentials, then click Continue"
        },
        {
          "action": "screenshot",
          "description": "Capture the page after login for evidence"
        },
        {
          "action": "navigate",
          "url": "https://github.com/YOUR_REPO”,
          "description": "Navigate to the repository where you want to verify branch protection"
        },
        {
          "action": "click",
          "element": "Settings",
          "description": "Click on the Settings tab"
        },
        {
          "action": "click",
          "element": "Branches",
          "description": "Click on the Branches option under Settings"
        },
        {
          "action": "screenshot",
          "description": "Capture the branch protection settings page for evidence"
        }
      ]
    }
  ]
}
```

工作流设计器提供测试模式，你可以立即执行生成的工作流，验证它是否正常工作。如果步骤需要调整，编辑模式支持带语法高亮和校验的 JSON 修改。

## 部署与配置

克隆该 [GitHub](https://github.com/aws-samples/sample-ai-powered-compliance-evidence-collector) 仓库，并进入你所用浏览器对应的项目目录。主目录中包含 chrome-extension 和 firefox-extension 两个文件夹。

```
git clone https://github.com/aws-samples/sample-ai-powered-compliance-evidence-collector

cd sample-ai-powered-compliance-evidence-collector
```

我们提供一个统一的 [AWS CloudFormation](https://aws.amazon.com/cloudformation/) 模板，可部署完整的 AWS 基础设施，并支持 Chrome、Firefox 或两者。你必须把 `AdminEmail` 更新为 Amazon SES 用于发送所生成报告的邮箱地址，把 `UserEmail` 更新为接收临时 Amazon Cognito 密码和合规报告的邮箱地址。

可以用 `BrowserType` 参数选择要支持哪些浏览器扩展：

- `Chrome`——仅配置 Chrome 扩展
- `Firefox`——仅配置 Firefox 扩展
- `Both`——同时配置 Chrome 和 Firefox 扩展（默认）

```
aws cloudformation create-stack \
  --stack-name evidence-collector \
  --template-body file://deployment/evidence-collector-cfn.yaml \
  --parameters \
    ParameterKey=BrowserType,ParameterValue=Both \
    ParameterKey=AdminEmail,ParameterValue=admin@example.com \
    ParameterKey=UserEmail,ParameterValue=user@example.com \
    ParameterKey=BucketName,ParameterValue=my-evidence-bucket \
  --capabilities CAPABILITY_IAM \
  --region us-east-1
```

该模板会创建：

- 采用强密码策略的 Amazon Cognito 用户池
- 用于访问 AWS 服务、带基于角色权限的 Amazon Cognito 身份池
- 启用加密、版本控制和阻止公有访问的 S3 存储桶
- 具备访问 Amazon Bedrock、S3 和 SES 最小权限策略的 IAM 角色
- 把初始系统提示词上传到 S3 的 AWS Lambda 函数
- 一个初始用户，并发出包含临时密码的电子邮件邀请

部署完成后，CloudFormation 的输出会提供配置浏览器扩展所需的值：

- `EvidenceBucketName`
- `IdentityPoolId`
- `Region`
- `UserPoolClientId`
- `UserPoolId`

你需要把这些数据填入浏览器扩展，完成一次性配置。CloudFormation 屏幕的输出如下图所示。

[![CloudFormation 输出（证据采集器）。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/18/3.CloudFormationOutputEvidenceCollector.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/18/3.CloudFormationOutputEvidenceCollector.png)

## 自动化工作流执行

了解架构之后，我们看看工作流实际如何执行。这个例子展示一个 IAM 审计工作流：

```
{
  "workflows": [
    {
      "description": "Review AWS IAM users and roles for compliance",
      "name": "AWS IAM Access Review",
      "steps": [
        {
          "action": "navigate",
          "description": "Navigate to AWS IAM console",
          "url": "https://console.aws.amazon.com/iam/home#/users"
        },
        {
          "action": "wait_for_user",
          "description": "Please log into AWS Console, then select Continue"
        },
        {
          "action": "navigate",
          "description": "Navigate to IAM Users page",
          "url": "https://console.aws.amazon.com/iam/home#/users"
        },
        {
          "action": "screenshot",
          "description": "Capture IAM Users page for evidence"
        },
        {
          "action": "navigate",
          "description": "Navigate to IAM Roles page",
          "url": "https://console.aws.amazon.com/iam/home#/roles"
        },
        {
          "action": "screenshot",
          "description": "Capture IAM Roles page for evidence"
        }
      ]
    }
  ]
}
```

工作流引擎按顺序执行每一步，等待页面加载并处理异步操作。对于截图步骤，引擎会先确认页面已完全渲染再截取，添加时间戳叠加层，然后以规范化的命名上传到 Amazon S3。

用户确认步骤（`wait_for_user`）会暂停执行，并在聊天界面中显示“继续”按钮。这用于处理身份验证这类无法自动化或不宜自动化的场景。你确认完成后，工作流继续运行。

## 清理

删除 CloudFormation 堆栈：

```
aws cloudformation delete-stack --stack-name evidence-collector –-region us-east-1
```

删除堆栈会移除 Amazon Cognito 用户池、身份池、IAM 角色、Lambda 函数和 S3 存储桶。

## 结语

本文展示了如何构建一套 AI 驱动的系统，用于自动化合规证据采集。你了解了如何结合 Amazon Bedrock 中的 Amazon Nova 2 Lite 与浏览器扩展能力，打造一套适配现代 Web 应用、并能适应需求变化的方案。该方案支持与页面加载同步的工作流执行，可从合规文档生成工作流，并连同审计日志一起存储证据。CloudFormation 部署能在几分钟内搭好完整的基础设施。要开始使用，请部署 CloudFormation 堆栈，用你的 AWS 凭证配置浏览器扩展，并运行其中一个示例工作流；然后用工作流设计器为你的合规要求创建自定义工作流。
