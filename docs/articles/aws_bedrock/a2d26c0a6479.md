# 在 Amazon Bedrock 上使用 Amazon Nova Model Distillation 优化视频语义搜索意图

为视频语义搜索优化模型需要在准确率、成本和延迟之间取得平衡。更快、更小的模型缺乏路由智能，而更大、更准确的模型则会带来显著的延迟开销。在[本系列第 1 部分](https://aws.amazon.com/blogs/machine-learning/power-video-semantic-search-with-amazon-nova-multimodal-embeddings/)中，我们展示了如何在 AWS 上构建多模态视频语义搜索系统，并使用 Amazon Bedrock 中的 Anthropic Claude Haiku 模型实现智能意图路由。虽然 Haiku 模型对用户搜索意图具有很高的准确率，但它会把端到端搜索时间增加到 2-4 秒。这占整体延迟的 75%。

图 1：一个端到端查询延迟分解的示例

现在考虑一下，当路由逻辑变得更复杂时会发生什么。企业元数据可能比我们示例中的五个属性（title、caption、people、genre 和 timestamp）复杂得多。客户可能会把镜头角度、情绪与情感、授权与版权窗口，以及更多领域特定的分类体系纳入考量。更细致的逻辑意味着更严苛的 prompt，而更严苛的 prompt 会带来更昂贵、更慢的响应。这正是模型定制发挥作用的地方。与其在“快但过于简单”的模型和“准确但过于昂贵或过慢”的模型之间二选一，我们可以训练一个小模型，让它以低得多的延迟和成本准确完成该任务，从而同时实现这三点。

在本文中，我们展示如何使用 [Model Distillation](https://docs.aws.amazon.com/bedrock/latest/userguide/model-distillation.html)——[Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的一种模型定制技术——把路由智能从大型 teacher 模型（Amazon Nova Premier）迁移到小得多的 student 模型（Amazon Nova Micro）中。该方法将推理成本降低 95% 以上，延迟降低 50%，同时保持任务所需的细致路由质量。

## 解决方案概览

我们将在 Jupyter notebook 中端到端地走完整套蒸馏管线。从高层来看，该 notebook 包含以下步骤：

- **准备训练数据**——使用 Nova Premier 生成 10,000 条合成标注示例，并以 Bedrock distillation 格式将数据集上传到 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/)
- **运行蒸馏训练作业**——使用 teacher 和 student 模型标识符配置作业，并通过 Amazon Bedrock 提交
- **部署蒸馏后的模型**——使用[按需推理](https://docs.aws.amazon.com/bedrock/latest/userguide/deploy-custom-model-on-demand.html)部署自定义模型，以获得灵活的按用量付费访问
- **评估蒸馏后的模型**——使用 [Amazon Bedrock Model Evaluation](https://aws.amazon.com/bedrock/evaluations/) 将路由质量与基础版 Nova Micro 以及原始 Claude Haiku 基线进行比较

完整的 notebook、训练数据生成脚本和评估工具都可在 [GitHub repository.](https://github.com/aws-samples/sample-video-semantic-search-multimodal-embeddings/tree/main/optimized-video-seach-intent-w-bedrock-model-distillations) 中获取。

## 准备训练数据

我们选择模型蒸馏而非[监督微调（SFT）](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-model-fine-tuning.html)等其他定制技术的关键原因之一，是它不需要完全标注的数据集。使用 SFT 时，每个训练示例都需要人工生成的回答作为标准答案。使用蒸馏时，你只需要 prompts。Amazon Bedrock 会自动调用 teacher 模型生成高质量回答。它在后台应用数据合成与增强技术，生成多达 15,000 组 prompt-response 对的多样化训练数据集。

话虽如此，如果你希望更好地控制训练信号，也可以选择提供带标注的数据集。JSONL 文件中的每条记录都遵循 bedrock-conversation-2024 schema，其中 user 角色（输入 prompt）是必需的，assistant 角色（期望的回答）是可选的。请参见以下示例，更多细节可参考 [Prepare your training datasets for distillation](https://docs.aws.amazon.com/bedrock/latest/userguide/distillation-prepare-datasets.html)：

```
{
    "schemaVersion": "bedrock-conversation-2024",
    "system": [{ "text": "Return JSON with visual, audio, transcription, metadata weights (sum=1.0) and reasoning for the given video search query." }],
    "messages": [
        {
            "role": "user",
            "content": [{ "text": "Olivia talking about growing up in poverty" }]
        },
        {
            "role": "assistant",
            "content": [{ "text": " {"visual": 0.2, "audio": 0.1, "transcription": 0.6, "metadata": 0.1, "reasoning": "The query focuses on spoken content ('talking about'), making transcription most important. Visual and audio elements are secondary since they support the context, while metadata is minimal."}"}]
        }
    ]
}
```

为撰写本文，我们使用 [Nova Premier](https://aws.amazon.com/nova/?trk=23e2e049-0266-487a-b670-77ae5e9000a3&sc_channel=ps&ef_id=CjwKCAjwvqjOBhAGEiwAngeQnX0g3nvWLEDEtx2niXi2JuMSSpQPQWeayL37ensXqKlZlZLzXt24wRoCGRYQAvD_BwE:G:s&s_kwcid=AL!4422!3!795877020884!p!!g!!amazon%20foundation%20model!23532472786!195602671671&gclid=CjwKCAjwvqjOBhAGEiwAngeQnX0g3nvWLEDEtx2niXi2JuMSSpQPQWeayL37ensXqKlZlZLzXt24wRoCGRYQAvD_BwE) 准备了 10,000 条合成标注示例，它是 Nova 系列中最大、能力最强的模型。这些数据在视觉、音频、转写和元数据信号查询之间以均衡的分布生成。示例覆盖了预期搜索输入的全部范围，代表不同的难度层级，包含边界情况和变体，并防止对狭窄的查询模式过拟合。下图展示了四个模态通道上的权重分布。

如果你需要更多示例，或希望把查询分布适配到你自己的内容领域，可以使用提供的 `generate_training_data.py` 脚本，借助 Nova Premier 合成生成更多训练数据。

## 运行蒸馏训练作业

训练数据上传到 Amazon S3 后，下一步是提交蒸馏作业。模型蒸馏的工作方式是：先用你的 prompts 从 **teacher 模型**生成回答，再用这些 prompt-response 对微调 **student 模型**。在本项目中，teacher 是 [**Amazon Nova Premier**](https://docs.aws.amazon.com/ai/responsible-ai/nova-micro-lite-pro/overview.html)，student 是 [**Amazon Nova Micro**](https://docs.aws.amazon.com/ai/responsible-ai/nova-micro-lite-pro/overview.html)，后者是一个为高吞吐推理优化的快速、高性价比模型。teacher 的路由决策成为塑造 student 行为的训练信号。

Amazon Bedrock 会自动管理整个训练编排和基础设施。无需预置集群、无需调参，也无需搭建 teacher 到 student 的模型管线。你只需指定 teacher 模型、student 模型、训练数据的 S3 路径，以及具有必要权限的 AWS Identity and Access Management（IAM）角色。其余由 Bedrock 处理。以下是触发蒸馏训练作业的示例代码片段：

```
import boto3
from datetime import datetime

bedrock_client = boto3.client(service_name="bedrock")

teacher_model = "us.amazon.nova-premier-v1:0"
student_model  = "amazon.nova-micro-v1:0:128k"

job_name   = f"video-search-distillation-{datetime.now().strftime('%Y-%m-%d-%H-%M-%S')}"
model_name = "nova-micro-video-router-v1"

response = bedrock_client.create_model_customization_job(
    jobName=job_name,
    customModelName=model_name,
    roleArn=distillation_role_arn,
    baseModelIdentifier=student_model,
    customizationType="DISTILLATION",
    trainingDataConfig={"s3Uri": training_s3_uri},
    outputDataConfig={"s3Uri": output_s3_uri},
    customizationConfig={
        "distillationConfig": {
            "teacherModelConfig": {
                "teacherModelIdentifier": teacher_model,
                "maxResponseLengthForInference": 1000
            }
        }
    }
)

job_arn = response['jobArn']
```

该作业以异步方式运行。你可以在 Amazon Bedrock 控制台的 **Foundation models > Custom models** 下监控进度，或以编程方式监控：

```
status = bedrock_client.get_model_customization_job(
    jobIdentifier=job_arn)['status']
print(f"Job status: {status}")  # Training, Complete, or Failed
```

训练时间因数据集大小和所选的 student 模型而异。对于 10,000 条标注示例和 Nova Micro，作业预计在数小时内完成。

## 部署蒸馏后的模型

蒸馏作业完成后，自定义模型即在你的 Amazon Bedrock 账户中可用，并可以部署。Amazon Bedrock 为自定义模型提供两种部署选项：[**Provisioned Throughput**](https://docs.aws.amazon.com/bedrock/latest/userguide/prov-throughput.html) 适用于可预测的高流量工作负载，**On-Demand Inference** 适用于无需前期承诺、灵活的按用量付费访问。

对于大多数刚起步的团队，按需推理是推荐路径。无需预置端点，没有按小时承诺，也没有最低使用量要求。以下是部署代码：

```
import uuid

deployment_name = f"nova-micro-video-router-{datetime.now().strftime('%Y-%m-%d')}"

response = bedrock_client.create_custom_model_deployment(
    modelDeploymentName=deployment_name,
    modelArn=custom_model_arn,
    description="Distilled Nova Micro for video search modality weight prediction (4 weights)",
    tags=[
        {"key": "UseCase", "value": "VideoSearch"},
        {"key": "Version", "value": "v2-4weights"},
    ],
    clientRequestToken=f"deployment-{uuid.uuid4()}",
)

deployment_arn = response['modelDeploymentArn']
print(f"Deployment ARN: {deployment_arn}")
```

一旦状态显示为 **InService**，你就可以像调用任何其他基础模型一样，使用标准的 InvokeModel 或 [Converse API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.html) 调用蒸馏后的模型。你只需按 Nova Micro 的推理费率为你消耗的 token 付费：**每 1,000 个输入 token $0.000035，每 1,000 个输出 token $0.000140。**

```
import boto3
import json

bedrock_runtime = boto3.client(service_name="bedrock-runtime")

custom_model_arn = bedrock_client.get_model_customization_job(
    jobIdentifier=job_arn
)['outputModelArn']

response = bedrock_runtime.converse(
    modelId=custom_model_arn,
    messages=[
        {
            "role": "user",
            "content": [{"text": query}]
        }
    ]
)

routing_weights = json.loads(
    response['output']['message']['content']['text']
)
print(routing_weights)
# {"visual": 0.7, "audio": 0.1, "transcription": 0.1, "metadata": 0.1}
```

基础模型在遵循指令和保持输出格式一致这两方面都很吃力。它会产生自由文本回答、不完整的 JSON 和非数值的权重值。蒸馏后的模型则始终返回格式良好、包含四个数值权重且总和为 1.0 的 JSON，符合路由管线所需的 schema。

在与原始 Claude Haiku router 比较时，两个模型都在由 Nova Premier 生成的 100 条标注示例的留出集上评估。我们使用 **Amazon Bedrock Model Evaluation **在结构化、托管的工作流中执行比较。为了在标准指标之外评估路由质量，我们定义了一个自定义的 OverallQuality 评分量表（见以下代码块），指示 Claude Sonnet 从两个维度为每个预测打分：相对于标准答案的权重准确度，以及推理质量。每个维度都映射到具体的 5 分阈值，因此该量表既会惩罚数值漂移，也会惩罚套话式的通用推理。

```
 "rating_scale": [
        {"definition": "Weights within 0.05 of reference. Reasoning is specific and consistent.",
         "value": {"floatValue": 5.0}},
        {"definition": "Weights within 0.10 of reference. Reasoning is clear and mostly consistent.",
         "value": {"floatValue": 4.0}},
        {"definition": "Dominant modality matches. Avg error < 0.15. Reasoning is present but generic.",
         "value": {"floatValue": 3.0}},
        {"definition": "Dominant modality wrong OR avg error > 0.15. Reasoning vague or inconsistent.",
         "value": {"floatValue": 2.0}},
        {"definition": "Unparseable JSON, missing keys, or error > 0.30. No useful reasoning.",
         "value": {"floatValue": 1.0}},
    ]
```

蒸馏后的 Nova Micro 模型在大型语言模型（LLM）作为评判者的评估中获得了 **4.0 分（满分 5 分）**，路由质量与 Claude 4.5 Haiku 几乎相同，而延迟约为其一半（833ms 对 1,741ms）。成本优势同样显著。切换到蒸馏后的 Nova Micro 模型可使输入和输出 token 的推理成本降低 **95% 以上**，且在按需定价下无需任何前期承诺。**注意：**LLM-as-judge 评估是非确定性的。不同运行之间分数可能略有差异。
