# 使用 Amazon Bedrock 将生成式 AI 能力集成到 Microsoft Office

[生成式 AI](https://aws.amazon.com/generative-ai/)正在迅速改变现代职场，提供了前所未有的能力，增强我们与文本和数据交互的方式。在 Amazon Web Services（AWS），我们深知许多客户把熟悉的 Microsoft Office 应用套件（包括 Word、Excel 和 Outlook）作为日常工作流的骨干。本文展示一套强大的方案，把以基于 Amazon Bedrock 的大型语言模型（LLM）形式存在的 AWS 生成式 AI 能力无缝集成到 Office 体验之中。通过利用生成式 AI 的最新进展，我们让员工能在每天已经使用的工具中释放新的效率与创造力水平。无论是撰写有吸引力的文字、分析复杂数据集，还是从信息中获得更深入的洞察，把生成式 AI 与 Office 套件集成都会改变团队开展其核心工作的方式。请与我们一起探索你的组织如何利用这项变革性技术推动创新、提升员工生产力。

## 组件深入解析

### Office Add-ins

[Office Add-ins](https://learn.microsoft.com/en-us/office/dev/add-ins/overview/office-add-ins)允许用基于标准 Web 技术构建的自定义扩展来扩展 Office 产品。借助 AWS，组织可以以极低的基础设施开销为全球用户托管并提供 Office Add-ins。

一个 Office Add-in 由两个元素组成：

- **Manifest**：一个领域特定的 XML 文件，规定 Office Add-in 如何与应用集成。Manifest 必须装载在 Office 安装环境中。请参阅[推荐的发布方式](https://learn.microsoft.com/en-us/office/dev/add-ins/publish/publish#production-deployment-methods)。测试时，可以[旁加载（sideload）Office Add-in](https://learn.microsoft.com/en-us/office/dev/add-ins/testing/test-debug-office-add-ins#sideload-an-office-add-in-for-testing)。
- **用户界面**：一个集成到 Microsoft Office 体验中的自定义 Web 应用。你可以在 AWS 云上快速托管这类应用而无需管理底层基础设施，例如[使用 Amazon Simple Storage Service（S3）和 Amazon CloudFront](https://docs.aws.amazon.com/prescriptive-guidance/latest/patterns/deploy-a-react-based-single-page-application-to-amazon-s3-and-cloudfront.html)。

下面的代码片段演示了用户调用插件时可能运行的函数的一部分，它执行以下操作：

- 向生成式 AI 后端发起请求，在请求体中提供用户 prompt 和可用上下文
- 使用 [Microsoft 的 Office JavaScript API](https://learn.microsoft.com/en-us/office/dev/add-ins/develop/understanding-the-javascript-api-for-office#accessing-the-office-javascript-api-library) 把后端响应中的结果集成到 Word 文档中。请注意，这些 API 把对象用作命名空间，从而无需显式导入。我们改用全局可用的命名空间（例如 `Word`）来直接访问相关 API，如下面的示例片段所示。

```
// Initiate backend request (optional context)
const response = await sendPrompt({ user_message: prompt, context: selectedContext });

// Modify Word content with responses from the Backend
await Word.run(async (context) => {
  let documentBody;

  // Target for the document modifications
  if (response.location === 'Replace') {
    documentBody = context.document.getSelection(); // active text selection
  } else {
    documentBody = context.document.body; // entire document body
  }

  // Markdown support for preserving original content layout
  // Dependencies used: React markdown
  const content = renderToString(<Markdown>{ response.content } < /Markdown>);
  const operation = documentBody.insertHtml(content, response.location);

  // set properties for the output content (font, size, color, etc.)
  operation.font.set({ name: 'Arial' });

  // flush changes to the Word document
  await context.sync();
});
```

### 生成式 AI 后端基础设施

AWS 云后端由三个组件组成：

- [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 作为入口，接收来自 Office 应用 Add-in 的请求。API Gateway 支持[多种控制和管理 API 访问的机制](https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-control-access-to-api.html)。
- [AWS Lambda](https://aws.amazon.com/lambda/) 负责 REST API 集成，处理请求并调用相应的 AWS 服务。
- [Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项全托管服务，通过 API 提供来自领先 AI 初创公司和 Amazon 的基础模型（FM），你可以从广泛的 FM 中挑选最适合自己用例的模型。借助 Bedrock 的 serverless 体验，你可以快速上手、用自己的数据私有化定制 FM，并使用 AWS 工具快速集成和部署到应用中，而无需管理基础设施。

#### LLM prompt 编写

Amazon Bedrock 允许你从[广泛的基础模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)中选择用于 prompt 的模型。这里，我们使用 Amazon Bedrock 上 [Anthropic 的 Claude 3.5 Sonnet](https://aws.amazon.com/bedrock/claude/) 来做补全。本示例中使用的 system prompt 如下：

```
You are an office assistant helping humans to write text for their documents.

[When preparing the answer, take into account the following text: <text>{context}</text>]
Before answering the question, think through it step-by-step within the <thinking></thinking> tags.
Then, detect the user's language from their question and store it in the form of an ISO 639-1 code within the <user_language></user_language> tags.
Then, develop your answer in the user’s language within the <response></response> tags.
```

在 prompt 中，我们首先给 LLM 设定一个人设，指明它是帮助人们写作的办公助手。第二行是可选的，包含用户在文档中选中的文本，作为上下文提供给 LLM。我们特意指示 LLM 先模拟逐步思考以得出答案的过程（思维链推理），这是 [prompt 工程](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-prompt-engineering.html)中提升输出质量的有效手段。接着，我们指示它从问题中识别用户语言，以便后续引用。最后，我们指示 LLM 使用先前识别出的用户语言在 response 标签内给出答案，这些标签内容用作最终回复。在这里我们使用 temperature 等推理参数的默认配置，这些参数可以随每次 LLM prompt 快速[配置](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-parameters.html)。随后把用户输入作为 user message 添加到 prompt 中，并通过 Amazon Bedrock 的 [Messages API](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-anthropic-claude-messages.html) 发送给 LLM。

#### AWS 账户中的实现细节与演示环境搭建

作为前提条件，我们需要确保工作在[支持该基础模型的](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html) AWS 区域（这里我们使用 Anthropic 的 Claude 3.5 Sonnet）。此外，还需要[添加对所需相关 Amazon Bedrock 基础模型的访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)。对于本次演示搭建，我们描述在 AWS 控制台中执行的手动步骤。如有需要，这套环境也可以用[基础设施即代码](https://docs.aws.amazon.com/whitepapers/latest/introduction-devops-aws/infrastructure-as-code.html)来定义。

要完成集成，请按以下步骤操作：

- 创建一个使用 Python 运行时的 AWS Lambda 函数，并用下面的代码作为 API 的后端。确保运行时中可用 [Powertools for AWS Lambda (Python)](https://docs.powertools.aws.dev/lambda/python/latest/)，例如为函数挂载[Lambda layer](https://docs.powertools.aws.dev/lambda/python/latest/#lambda-layer)。确保 Lambda 函数的 IAM 角色提供对所需 FM 的访问权限，例如：  `{ "Version": "2012-10-17", "Statement": [ { "Effect": "Allow", "Action": "bedrock:InvokeModel", "Resource": [ "arn:aws:bedrock:*::foundation-model/anthropic.claude-3-5-sonnet-20240620-v1:0" ] } ] } `  下面的代码块展示了基于 [Powertools for AWS Lambda (Python) REST API 事件处理器](https://docs.powertools.aws.dev/lambda/python/latest/core/event_handler/api_gateway/)的 REST API Lambda 集成示例实现：  `import json import re from typing import Optional import boto3 from aws_lambda_powertools import Logger from aws_lambda_powertools.event_handler import APIGatewayRestResolver, CORSConfig from aws_lambda_powertools.logging import correlation_paths from aws_lambda_powertools.utilities.typing import LambdaContext from pydantic import BaseModel logger = Logger() app = APIGatewayRestResolver( enable_validation=True, cors=CORSConfig(allow_origin="http://localhost:3000"), # for testing purposes ) bedrock_runtime_client = boto3.client("bedrock-runtime") SYSTEM_PROMPT = """ You are an office assistant helping humans to write text for their documents. {context} Before answering the question, think through it step-by-step within the <thinking></thinking> tags. Then, detect the user's language from their question and store it in the form of an ISO 639-1 code within the <user_language></user_language> tags. Then, develop your answer in the user's language in markdown format within the <response></response> tags. """ class Query(BaseModel): user_message: str # required context: Optional[str] = None # optional max_tokens: int = 1000 # default value model_id: str = "anthropic.claude-3-5-sonnet-20240620-v1:0" # default value def wrap_context(context: Optional[str]) -> str: if context is None: return "" else: return f"When preparing the answer take into account the following text: <text>{context}</text>" def parse_completion(completion: str) -> dict: response = {"completion": completion} try: tags = ["thinking", "user_language", "response"] tag_matches = re.finditer( f"<(?P<tag>{'|'.join(tags)})>(?P<content>.*?)</(?P=tag)>", completion, re.MULTILINE | re.DOTALL, ) for match in tag_matches: response[match.group("tag")] = match.group("content").strip() except Exception: logger.exception("Unable to parse LLM response") response["response"] = completion return response @app.post("/query") def query(query: Query): bedrock_response = bedrock_runtime_client.invoke_model( modelId=query.model_id, body=json.dumps( { "anthropic_version": "bedrock-2023-05-31", "max_tokens": query.max_tokens, "system": SYSTEM_PROMPT.format(context=wrap_context(query.context)), "messages": [{"role": "user", "content": query.user_message}], } ), ) response_body = json.loads(bedrock_response.get("body").read()) logger.info("Received LLM response", response_body=response_body) response_text = response_body.get("content", [{}])[0].get( "text", "LLM did not respond with text" ) return parse_completion(response_text) @logger.inject_lambda_context(correlation_id_path=correlation_paths.API_GATEWAY_REST) def lambda_handler(event: dict, context: LambdaContext) -> dict: return app.resolve(event, context) `
- 创建一个带 Lambda 代理集成的 API Gateway REST API，通过 REST API 对外暴露该 Lambda 函数。你可以参考[本教程](https://docs.aws.amazon.com/apigateway/latest/developerguide/api-gateway-create-api-as-simple-proxy-for-lambda.html)，使用 API Gateway 控制台为该 Lambda 函数创建 REST API。通过[配合代理资源创建 Lambda 代理集成](https://docs.aws.amazon.com/apigateway/latest/developerguide/api-gateway-set-up-simple-proxy.html#lambda-proxy-integration-with-proxy-resource)，我们就可以把对资源的请求路由到 Lambda 函数。按教程[部署 API](https://docs.aws.amazon.com/apigateway/latest/developerguide/how-to-deploy-api.html)，并记下该 API 的调用 URL。请确保为 REST API [配置适当的访问控制](https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-control-access-to-api.html)。

## 结论

本文展示了生成式 AI 的变革力量如何融入 Office 流程。我们描述了一个端到端示例，演示如何用 Add-in 把 Office 产品与 LLM 的文本生成和操作能力集成起来。在我们的示例中，我们使用 Amazon Bedrock 上的托管 LLM 进行文本生成。后端作为完全 serverless 的应用托管在 AWS 云上。
