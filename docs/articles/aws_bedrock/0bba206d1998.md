# 使用 Amazon Bedrock AgentCore Memory 扩展 Kiro CLI 的对话记忆

会忘记你在之前会话中告诉它内容的 agentic IDE 并没有多大用处。你花了数天或数周时间在庞大代码库上处理复杂业务需求。然而，你的 IDE 只在当前会话中记得你，无法回想对话历史、从对话中得出的偏好，或其他洞见。结果你不得不在每个新会话中反复提供相同的上下文信息。这种重复设置上下文的需求会影响你的生产力。

在这篇博文中，我们演示如何通过实现一个与 [Amazon Bedrock AgentCore Memory](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory.html) 集成的自定义 [Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro)（MCP）server，来扩展 [Kiro CLI](https://kiro.dev/cli/) 的对话记忆。你可以使用 Kiro CLI 直接从终端与 Kiro 的 AI agent 交互。Amazon Bedrock AgentCore Memory 是一项全托管服务，让 AI agent 能够保留过去交互中的信息，从而创建更智能、更具上下文感知的对话。通过实现自定义 MCP server，你可以为 Kiro CLI 提供工具，用于存储和检索对话上下文、监控记忆使用情况，以及管理底层的 Bedrock Agent Core Memory 基础设施。

## 方案概览

该方案由三个协同工作的主要组件构成：

- **[Amazon Bedrock AgentCore Memory](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-agentcore-memory-building-context-aware-agents/)** 是一项全托管服务，用于存储和检索对话上下文，提供带有内置语义搜索的持久记忆能力。AgentCore Memory 提供了强大的能力，可同时维护短期工作记忆和长期智能记忆，使 AI agent 能够保留上下文、从交互中学习，并提供真正个性化的体验。
- **自定义 MCP Server **通过 MCP 暴露 Amazon Bedrock AgentCore Memory 的能力，使记忆操作可供兼容 MCP 的客户端使用。
- **Kiro CLI c**onnects 通过 STDIO 协议连接到 MCP server，以存储和检索对话历史。

[![架构图：展示 Kiro CLI 与 Amazon Bedrock AgentCore Memory 及 MCP Server 的集成](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/02/ML-19844-image-1.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/02/ML-19844-image-1.png)

MCP server 充当 Kiro CLI 与 Amazon Bedrock AgentCore Memory 之间的桥梁，让 Kiro CLI 能够跨会话维护对话历史和上下文。MCP server 提供的工具分为三类。

- **对话工具** – 你可以按主题或时间范围搜索对话历史，以一致的会话跟踪存储对话，检索完整对话内容，并列出此前存储的会话。
- **监控工具** – 你可以查看记忆使用统计和 MCP server 配置
- **管理工具** – 你可以删除特定会话，并在需要时删除已存储的数据。

该方案采用两阶段检索策略：首先使用 retrieve_memory_records Bedrock AgentCore Memory API 尝试语义搜索以进行概念匹配，随后回退到直接的事件级内容匹配，扫描存储在 AgentCore Memory 会话中的原始对话载荷。这种级联方法确保无论语义策略是否已完成处理，对话都可被检索。你可以在 prompt 中使用*最近*、*昨晚*或*昨天*等时间范围来查找相关对话。

这一架构让 Kiro CLI 具备上下文感知能力。它跨会话记住你的偏好、项目细节和工作流，因此你无需反复提供相同信息。

## 操作演练

对于本演示，你需要具备以下先决条件：

- 通过 AWS Management Console 和 [AWS Command Line Interface（AWS CLI）](https://aws.amazon.com/cli) 访问 [AWS 账户](https://signup.aws.amazon.com/gp/aws/developer/registration/index.html)。

你使用的 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam) 用户必须具备权限，能够进行必要的 AWS 服务调用并管理本文提及的 AWS 资源。在为该 IAM 用户授予权限时，请遵循[最小权限原则](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html#grant-least-privilege)。

- 一个 [AWS Builder ID](https://docs.aws.amazon.com/signin/latest/userguide/create-builder-id.html)。
- 在你的台式机/笔记本上[安装](https://kiro.dev/docs/cli/installation/)并[配置](https://kiro.dev/docs/cli/authentication/#sign-in-to-kiro-cli)了 Kiro CLI。

在终端中执行以下步骤：

- 运行以下命令克隆仓库：  `git clone https://github.com/aws-samples/sample-amazon-bedrock-agentcore-memory-mcp-server.git`
- 运行以下命令创建 Python 虚拟环境并安装依赖：  `cd sample-amazon-bedrock-agentcore-memory-mcp-server python3 -m venv venv; source venv/bin/activate; pip3 install -r requirements.txt;`
- 运行以下命令创建 Amazon Bedrock AgentCore Memory 资源并生成 Kiro agent 配置。请注意，完成此步骤可能需要几分钟：  `python3 setup_bedrock_agentcore_memory.py`

出现提示时，为 actor 标识符选择以下选项之一。这些转换会按该标识符存储。

- 选项 1：User ID（默认）——推荐用于个人使用。它使用 USER 环境变量中的系统用户名。上述命令会设置 `ACTOR_ID_TYPE=userid in agent/kiro_memory.json`
- 选项 2：Project ID——推荐用于团队或基于项目的记忆隔离。出现提示时，你必须提供 `projectid` 和 `your-project-id`。上述命令会在 `agent/kiro_memory.json` 中设置 `ACTOR_ID_TYPE=projectid` 和 `PROJECT_ID=your-project-id`

使用的命名空间策略是：`/strategy/semanticMemoryStrategy/actor/{actorId}/session/{sessionId}`

- 设置 kiro agent 配置  `mkdir -p ~/.kiro/agents/ mkdir -p ~/.kiro/hooks/ cp -p agent/kiro_memory.json ~/.kiro/agents/ cp -p hooks/cache-prompt.sh ~/.kiro/hooks/ cp -p hooks/load-preferences.sh ~/.kiro/hooks/ cp -p hooks/store-conversation.sh ~/.kiro/hooks/ chmod 755 ~/.kiro/hooks/*`
- 将 kiro_memory agent 配置为默认 agent。

将以下内容添加到 `~/.kiro/settings/` 目录中的 `cli.json` 文件，以默认使用 `kiro_memory` agent：`{"chat.defaultAgent": "kiro_memory"}`

- 登录 Kiro CLI

要登录 Kiro CLI，你需要拥有 AWS Builder ID，或来自你所在组织的有效 Kiro 订阅。

如果两者都没有，你可以按照[创建 AWS Builder ID](https://docs.aws.amazon.com/signin/latest/userguide/create-builder-id.html)中的步骤创建一个。

`kiro-cli login --use-device-flow`

请注意，通过 `agentcore-memory-mcp-server`，会话可使用以下工具。

- `clear_all_data` – 删除记忆中特定命名空间的信息
- `delete_session` – 删除特定会话
- `get_direct_conversation_history` – 访问特定会话的完整对话内容
- `get_memory_stats` – 使用 list_memory_records 提供记忆概览
- `get_server_config` – 提供 MCP server 的配置
- `get_session_details` – 提供特定会话的信息
- `list_sessions` – 列出此前存储的会话
- `search_conversation_history` – 按主题或时间范围搜索对话历史的工具
- `search_memories` – 另一个用于搜索长期记忆的工具
- `store_conversation` – 以一致的会话 ID 存储对话

## 测试方案

Kiro CLI 会根据响应或执行你的 prompt 所需的功能来调用 MCP server。Kiro CLI 的 hook 会在每次对话后触发并存储对话。以下是一些使用示例：

`What is AWS DevOps agent? Is it GA yet?`

允许 Kiro 可能请求批准使用的工具访问。获得响应后，输入 `/quit` 退出 Kiro CLI。

重新登录 Kiro CLI 并提问：

`What have we discussed about AWS DevOps agent?`

允许来自 Kiro CLI 的工具使用请求。Kiro 将使用 `agentcore-memory-mcp-server` 从 Bedrock AgentCore memory 中获取相关信息。

你可以追问类似这样的问题：

```
Can I integrate GitHub with AWS DevOps agent?
What is the pricing for AWS DevOps agent?
```

再次用 `/quit` 退出 Kiro CLI 会话，过一段时间重新登录。用自然语言让 Kiro CLI 检索之前关于 AWS DevOps Agent 的讨论。Kiro 会向你展示此前讨论的摘要。

## 结语

在这篇博文中，我们演示了如何使用与 Amazon Bedrock AgentCore Memory 集成的自定义 MCP server，增强 Kiro CLI 的上下文持久性。该自定义 MCP server 提供全面的工具，用于存储和检索对话上下文、监控记忆使用情况，以及管理持久记忆基础设施。借助智能检索、自然语言时间范围和级联回退策略等功能，你可以可靠地访问对话历史，而无需反复提供相同的上下文信息。
