# 用 Amazon Bedrock AgentCore 加速并购尽职调查

并购（M&A）团队面临一个长期存在的挑战：在保持速度和分析严谨性的同时，对多个收购标的开展全面的尽职调查。团队往往要花数周时间手工审查标的，才能识别出可行的机会。Amazon Bedrock AgentCore 是一个用于大规模构建、连接和优化 agent 的平台，支持任何框架或模型。它可以通过编排 AI agent 来加速这一过程，让这些 agent 在既定的 guardrails 内自主处理数据收集、分析和合规检查。

在本文中，我们展示如何在 Amazon Bedrock AgentCore 上构建多 agent 尽职调查系统。我们给出一个参考架构，它结合了 agent 编排、知识检索和治理控制，然后借助完整的示例仓库逐步演示如何部署和运行该方案。

## 并购尽职调查的挑战

以运输与物流行业为例，分析师需要从金融数据库、市场研究应用、监管申报文件和内部知识库中提取数据，然后手工核对这些信息。这一过程缓慢且耗费资源。

当团队重复劳动时，问题会进一步加剧。行业研究、估值模型和竞争分析在每笔新交易中都被重新做一遍，而不是在以往交易的机构知识基础上继续积累。与此同时，治理方面的顾虑拖慢了 AI 的采用，因为法务和合规团队需要确信 AI 生成的洞察准确、可追溯，并有来源引用作为支撑。

这四重压力（周期漫长、数据碎片化、重复劳动和治理要求）为 AI agent 从根本上改变尽职调查的运作方式创造了机会。

## AI agent 如何变革尽职调查

AI agent 通过自主数据收集、智能路由、持久记忆和内置可审计性的组合，逐一应对这些挑战。

在数据收集方面，agent 自主查询多个来源（金融数据库、知识库、市场数据 API），并将结果综合为初步评估。在我们的测试中，原本需要分析师数周时间完成的工作在数小时内就完成了，因为 agent 无需人工干预即可处理重复的搜索与汇总循环。

在优先级排序方面，agent 依据战略标准评估机会，并将高优先级交易路由给合适的专家。系统不会逐个顺序审查每个标的，而是优先呈现最有前景的候选者，并标出值得深入分析的具体维度（财务表现、战略契合度、合规风险）。

agent 还会随着时间积累机构知识。每一次完成的分析都会丰富共享记忆层，使未来的交易能够受益于先前的研究、估值假设和整合经验。团队不再需要从零开始重建上下文。

治理从一开始就被内置到 agent 工作流中，而非事后补充。系统经过配置，使 agent 输出的每一项论断都有引用作为依据，并由引用检查评估器加以验证。每次 agent 调用都会产生审计轨迹，guardrails 在运行时执行组织策略。合规团队可以将每一条被引用的论断追溯回其来源文档。

## 架构决策：集成套件还是自定义构建

我们给出两条实现路径，各自适合不同的组织需求。

### 选项 1：Amazon Quick（集成方案）

Amazon Quick 提供现成的 AI 能力，专为商业智能和研究工作流量身打造。如果你的需求符合标准分析模式，它提供了一条快速上线的路径。Amazon Quick Research 可生成专业、可导出的深度报告。Amazon Quick Flows 通过预置工作流实现重复任务的自动化。Amazon Quick Index 提供跨已连接数据源的统一搜索。

如果你希望快速部署、工作流符合标准商业智能模式，并且相比自定义开发更倾向于完全托管服务，就选择 Amazon Quick。更多信息和参考架构请参阅[Announcing Amazon Quick](https://aws.amazon.com/quicksight/)。

你还可以用自定义 Amazon Bedrock AgentCore agent 扩展 Quick，以满足专有估值模型或战略契合框架等特殊需求。有关这一模式的实际示例，请参阅[使用 Quick 和 AgentCore 构建智能合同管理](https://aws.amazon.com/blogs/machine-learning/build-an-intelligent-contract-management-solution-with-amazon-quick-suite-and-bedrock-agentcore/)。那篇文章演示了 Amazon Quick 如何处理文档管理和用户界面，而 Amazon Bedrock AgentCore 如何支撑专用 agent 之间的协作。

### 选项 2：基于 Amazon Bedrock AgentCore 的自定义架构

[Amazon Bedrock AgentCore](https://docs.aws.amazon.com/bedrock-agentcore/)让你对 agent 行为、记忆和协调拥有细粒度的控制。这一方法适合拥有专有方法论、复杂多 agent 协调需求、需要与专用内部系统集成，或需要完全掌控 agent 行为和模型选择的 M&A 团队。

本文余下部分将以运输与物流尽职调查场景为背景，详细探讨这一自定义架构。我们部署一个可运行的多 agent 系统，针对合成标的调用它，并通过自动化的引用检查评估器验证输出。

## 参考架构

对于选择自定义路径的 M&A 团队，以下参考架构展示了各组件如何端到端地组合在一起。

图 1：基于 Amazon Bedrock AgentCore 的多 agent M&A 尽职调查架构

该架构使用 Amazon Bedrock AgentCore 编排多 agent 尽职调查工作流。一个 supervisor agent 协调四个 specialist agent，每个负责尽职调查流程中一个不同的阶段。用户通过 Jupyter notebook 或终端界面进行交互，而 AgentCore runtime 管理 agent 的执行与协作。系统结合了检索增强生成（RAG）、结构化财务分析、外部工具集成、记忆和基于策略的治理，以支撑可用于生产环境的尽职调查工作流。

### Agent 编排层

Amazon Bedrock AgentCore runtime 通过 [Strands Agents SDK](https://strandsagents.com/)协调多个专用 agent。supervisor agent 采用 agents-as-tools 模式，根据任务需求将请求路由给特定领域的 specialist agent。

**Target Screening Agent** 通过将自然语言查询转换为 SQL 并针对 [Amazon Aurora](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/CHAP_AuroraOverview.html) PostgreSQL 执行，来识别收购候选者。当分析师提出「mid-market logistics companies with revenue between 100M and 500M USD and EBITDA margins above 12 percent」时，agent 会将其转换为参数化查询。随后它检索匹配的行，并用知识库中的叙述性上下文丰富结果。

**Financial Analysis Agent** 使用结构化和非结构化数据源执行估值分析。它采用标准估值方法，包括贴现现金流（DCF）分析和可比公司分析，并通过 AgentCore Gateway 支撑的工具获取市场倍数。该 agent 生成初步估值，并内联记录支持性假设，同时标记与历史表现背离的管理层预测。

**Strategic Fit Agent** 评估整合风险、协同效应和组织一致性。它从存储在 AgentCore memory 中的历史交易检索上下文（使用专用的 `prior_deals` 命名空间）。然后它将当前标的的特征与已完成的收购进行比较，识别整合风险并引用来源备忘录。

**Compliance Validation Agent** 依据 M&A 治理清单审计响应。它调用自定义引用检查评估器（以 AWS Lambda 函数实现），后者检查响应中的每一项事实性论断，并标记缺乏来源引用支撑的断言。

### 关键架构组件

该架构结合结构化和非结构化企业数据，使 agent 的响应有据可查、扎根于已验证的来源。

- [Amazon Aurora](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/CHAP_AuroraOverview.html) PostgreSQL Serverless v2 存储结构化的财务和运营数据集。Target Screening Agent 从自然语言生成 SQL，并通过 RDS Data API 执行查询，无需分析师自己编写 SQL 即可快速访问目标公司的指标。
- [Amazon Bedrock Knowledge Bases](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base.html)是 Amazon Bedrock 中完全托管的 RAG 能力，对尽职调查文档建立索引，包括保密信息备忘录（CIMs）、财务报表、宣传资料和内部治理清单。agent 检索相关段落并内联引用。
- **AgentCore Gateway** 是 Amazon Bedrock AgentCore 的一项能力，让 agent 通过兼容 Model Context Protocol (MCP)的集成方式安全地与外部工具和服务交互。在该架构中，agent 通过 gateway 调用基于 [AWS Lambda](https://docs.aws.amazon.com/lambda/latest/dg/welcome.html)的市场数据服务，并由 Cedar 策略对工具使用和 agent 交互执行确定性访问控制。
- **AgentCore memory** 跨交互维护上下文状态和可复用的机构知识。会话记忆保持对话的连续性，而长期 `prior_deals` 命名空间存储已完成收购的经验教训，为未来分析提供参考。
- **AgentCore Evaluations** 是 Amazon Bedrock AgentCore 的一项能力，使用基于 Lambda 的评估器自动验证输出质量、引用准确性和特定领域的标准。引用检查评估器返回结构化的通过/失败结果，并给出有支撑和无支撑的论断数量。
- [Amazon Bedrock Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)在整个工作流中执行安全和响应控制，在 supervisor 层级应用，使 specialist 的输出经过组织策略检查。

每次调用都会产生一个 [Amazon CloudWatch](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/WhatIsCloudWatch.html) 日志流和一条 [AWS X-Ray](https://docs.aws.amazon.com/xray/latest/devguide/aws-xray.html) 追踪，捕获从 supervisor 到 specialist 再到工具的完整调用层级，提供端到端的可观测性。

### 安全性

M&A 尽职调查涉及公司处理的一些最敏感数据：未公开的财务数据、交易条款和整合计划。因此，安全性是架构中的一等公民。agent 可以调用的每一项 IAM 权限都限定到特定的 Amazon Resource Name (ARN)，而非通配符。AgentCore Gateway 的市场数据工具更进一步，采用 Cedar 策略引擎执行默认拒绝的基于属性的授权。只有当请求的行业代码与批准的垂直领域匹配时，该工具才会运行，其他一切情况在运行前即被拒绝。数据库层位于私有、与互联网隔离的子网中，并处于 virtual private cloud (VPC) 端点之后。数据存储通过 KMS 进行静态加密，Amazon Bedrock Guardrails 会筛查每条 supervisor 响应中的有害内容和个性化财务建议。这种由 IAM、Cedar、网络隔离和加密构成的分层模型，覆盖了处理机密交易数据的系统的不同失效模式。

## 部署并运行示例

完整的参考实现可在 [M&A Due Diligence Multi-Agent Sample](https://github.com/aws-samples/sample-ma-due-diligence-agentcore)仓库中获取。它附带合成数据（不含真实公司、财务数据或个人身份信息）、一键式部署和 Jupyter notebook 演练。完整的部署—运行—清理周期预估成本低于 USD $5.00。

### 先决条件

在部署之前，请确认你具备：

- 一个已为 Anthropic Claude 和 Amazon Nova 启用 Amazon Bedrock 模型访问权限的 AWS 账户。有关各 AWS Region 的模型可用性，请参阅[Amazon Bedrock 中各 AWS Region 支持的模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。
- AWS Command Line Interface (AWS CLI) v2.15 或更高版本。
- Python 3.11 或更高版本。
- Node.js 20 或更高版本。
- AWS Cloud Development Kit (AWS CDK) v2（`npm install -g aws-cdk`）。
- 无需在本地安装 Docker。agent 容器镜像在 AWS CodeBuild 上构建。

部署到以下受支持的 Region 之一：`us-east-1`、`us-west-2`、`ap-southeast-2` 或 `eu-central-1`。

### 步骤 1：部署堆栈

克隆仓库并运行部署脚本。首次部署需要 20–25 分钟。

```
# macOS / Linux
git clone https://github.com/aws-samples/sample-ma-due-diligence-agentcore.git
cd sample-ma-due-diligence-agentcore
./deploy.sh
```

```
# Windows
git clone https://github.com/aws-samples/sample-ma-due-diligence-agentcore.git
cd sample-ma-due-diligence-agentcore
.\deploy.ps1
```

部署脚本会验证你的 Region 和模型访问权限、创建虚拟环境、运行 `cdk deploy --all`、植入合成数据，并执行部署后的冒烟测试。它还会以可编辑模式安装项目，从而注册 `mna` 命令行工具，供你在下一步中调用 agent。

### 步骤 2：调用 agent

使用 mna CLI 向各个 specialist agent 发送 prompt，或让 supervisor 在它们之间进行路由：

```
# Let the supervisor orchestrate across specialists
mna invoke supervisor "Screen the mid-market logistics targets with revenue 100M-500M, then run a DCF on the top hit." --session-id walkthrough-session-00000000-0001

# Target Screening: text-to-SQL on Aurora + KB narrative enrichment
mna invoke target_screening "Screen the target pipeline for transportation companies with revenue between 100M and 500M USD, EBITDA margin above 12%, and fleet size above 200. Surface the top three and tell me what the CIM says about the leader's growth trajectory." --session-id walkthrough-session-00000000-0001

# Financial Analysis: KB retrieval + Gateway-backed market data tool
mna invoke financial_analysis "Run a DCF on Example Corp using the CIM in the knowledge base. Flag any management projection that diverges from historical performance by more than 20% and pull comparable multiples for transportation-logistics mid-market." --session-id walkthrough-session-00000000-0001

# Strategic Fit: AgentCore Memory long-term retrieval
mna invoke strategic_fit "Compare Example Corp' integration profile against our three most recent completed acquisitions. Identify the top three integration risks and cite the source memos." --session-id walkthrough-session-00000000-0001
```

每次调用都会在其末尾打印一个 `trace_id`。使用 `mna trace <trace_id>` 可查看该调用的完整 X-Ray 追踪。

### 步骤 3：用评估器验证输出

mna evaluate 子命令针对 specialist 的输出运行引用检查评估器：

```
# Capture a response in JSON format
mna --json invoke financial_analysis "Run a DCF on Example Corp using the CIM." --session-id blog-demo-session-00000000-000002 > run.json

# --session-id accepts any string between 33 and 256 characters --- AgentCore Runtime enforces this length range for runtimeSessionId. The value above is just an example; use a unique string per session (a UUID works well) if you want to keep invocations isolated or omit --session-id entirely to let the client generate one for you.

# Extract response text and citations
python -c "import json,pathlib;d=json.loads(pathlib.Path('run.json').read_text());pathlib.Path('response.txt').write_text(d['text'])"

python -c "import json,pathlib;
d=json.loads(pathlib.Path('run.json').read_text());
pathlib.Path('citations.json').write_text(json.dumps(d['citations']))"

# Run the citation-check evaluator
mna evaluate --response-file response.txt --citations-file citations.json
```

评估器返回结构化结果，指示通过或失败，并给出论断总数、有支撑的论断数以及任何无支撑的断言数。通过时退出码为 0，失败时为 1，因此可在 CI 流水线中组合使用。

### 步骤 4：浏览 notebook

如需对同一工作流进行逐单元格的引导式浏览：

```
jupyter lab notebooks/walkthrough.ipynb
```

notebook 依次介绍环境验证、数据概览、每个 specialist agent 一个单元格（附带渲染后的响应和引用），以及追踪检查。

## 清理

为避免持续产生费用，请在浏览完成后立即销毁所有已部署的资源：

```
# macOS / Linux
./cleanup.sh
```

```
# Windows
.\cleanup.ps1
```

清理脚本运行 `cdk destroy --all --force`，按依赖关系的逆序拆除所有堆栈。随后它执行一次验证扫描，检查是否存在孤立资源：

- 匹配 `mna-*` 的 S3 存储桶。
- 匹配 mna-* 的 ECR 仓库。
- 名称中包含 `mna` 的 Amazon Bedrock Knowledge Bases。
- AgentCore runtime、memory 和 gateway。
- 以 `Mna` 开头的 AWS CloudFormation 堆栈。

验证脚本会为找到的资源打印可直接复制粘贴的命令，以便你确认最终达到零成本状态。如果每次扫描的脚本输出均为空，说明所有计费资源都已移除。有关 CDK 资源清理的更多详情，请参阅 [AWS CDK 文档](https://docs.aws.amazon.com/cdk/v2/guide/ref-cli-cmd-destroy.html)。
