# 在 Amazon Bedrock 上使用定制的 Amazon Nova 模型实现按需部署

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 提供模型定制能力，客户可以通过 fine-tuning 和模型蒸馏等功能，将[基础模型](https://aws.amazon.com/what-is/foundation-models/)（foundation model，FM）的版本调整到契合自身特定需求。今天，我们宣布推出按需部署功能，可用于在 Amazon Bedrock 上部署定制模型。

定制模型的按需部署提供了一个随使用模式扩展的额外部署选项。这种方式允许只在需要时调用定制模型，请求会实时处理，无需预先配置计算资源。

按需部署选项包含一种按 token 计费的定价模式，根据推理过程中处理的 token 数量收费。这种按量付费的方式是对现有 Provisioned Throughput 选项的补充，让用户可以灵活选择最契合其特定工作负载需求和成本目标的部署方式。

在本文中，我们将梳理 Amazon Bedrock 定制模型按需部署的工作流，并提供使用 [AWS Management Console](https://aws.amazon.com/console/) 以及 API 或 [AWS SDK](https://aws.amazon.com/developer/tools/) 的分步实施指南。我们还将讨论在 Amazon Bedrock 上部署定制 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) 模型的最佳实践和注意事项。

## 理解定制模型按需部署工作流

模型定制生命周期代表了从概念化到部署的端到端历程。这个过程始于定义你的具体用例、准备并格式化合适的数据，然后通过 Amazon Bedrock fine-tuning 或 [Amazon Bedrock 模型蒸馏](https://aws.amazon.com/bedrock/model-distillation/)等功能进行模型定制。每个阶段都建立在前一个阶段之上，形成一条通向部署生产就绪的[生成式 AI](https://aws.amazon.com/what-is/generative-ai/)能力的路径，而这些能力可以按你的需求量身定制。下图展示了这一工作流。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ML-19210-image-1.png)

定制模型之后，评估和部署阶段决定了模型将以何种方式提供推理服务。这正是定制模型按需部署的价值所在：它提供了一个契合可变工作负载和注重成本的实现方案的部署选项。使用按需部署时，你可以通过 AWS 控制台或标准 API 操作、借助模型标识符来调用定制模型，计算资源只在需要时自动分配。按需部署在保持预期性能的同时提供了灵活性，因此你可以用 Amazon Bedrock 提供的同样 serverless 体验，将定制模型无缝集成到应用中——所有计算资源都会根据你的实际使用情况自动为你管理。由于该工作流支持迭代改进，你可以根据评估结果和不断变化的业务需求来优化模型。

## 前提条件

本文假设你在用按需部署之前已经拥有一个定制的 Amazon Nova 模型。按需部署要求使用在此功能发布之后新定制的 Amazon Nova 模型。此前定制的模型与该部署选项不兼容。关于通过 fine-tuning 或模型蒸馏创建或定制 Nova 模型的说明，请参阅以下资源：

- [fine-tuning Amazon Nova 模型](https://docs.aws.amazon.com/nova/latest/userguide/customize-fine-tune.html)
- [Amazon Bedrock 模型蒸馏指南](https://aws.amazon.com/blogs/machine-learning/a-guide-to-amazon-bedrock-model-distillation-preview/)

成功定制 Amazon Nova 模型后，你可以按照以下各节所述，使用按需部署选项继续部署该模型。

## 按需部署实施指南

在 Amazon Bedrock 上为定制的 Amazon Nova 模型实现按需部署主要有两种方式：使用 Amazon Bedrock 控制台，或使用 API 或 SDK。首先，我们探讨如何通过 Amazon Bedrock 控制台部署模型，它提供了一个用户友好的界面来设置和管理部署。

### 使用 Amazon Bedrock 控制台的分步实施

要使用控制台在 Amazon Bedrock 上为定制的 Amazon Nova 模型实现按需部署，请按以下步骤操作：

- 在 Amazon Bedrock 控制台上，选择要部署的定制模型（fine-tuning 或模型蒸馏）。选择 **Set up inference **，然后选中 **Deploy for on-demand**，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ML-19210-image-2.png)

- 在 **Deployment details** 下，输入 **Name** 和 **Description**。你可以选择添加 **Tags**，如下图所示。选择 **Create** 开始定制模型的按需部署。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ML-19210-image-3.png)

在 **Custom model deployments** 下，部署状态应为 InProgress、Active 或 Failed，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ML-19210-image-4.png)

你可以选择一个部署，查看所选定制模型的 **Deployment ARN**、**Creation time**、**Last updated** 和 **Status**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ML-19210-image-5.png)

定制模型已通过按需部署完成部署并就绪。你可以在测试 playground 中试用，或前往 **Chat/Text playground**，在 **Categories** 下选择 **Custom models**。选中你的模型，在 **Inference** 下选择 **On demand**，然后按部署名称选择，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/17/ML-19210-image-6.png)

### 使用 API 或 SDK 的分步实施

成功训练模型后，你可以部署它来评估响应质量和延迟，或者将该模型用作你用例中的生产模型。你需要使用 `CreateCustomModelDeployment` API 为训练好的模型创建模型部署。以下步骤展示了如何使用这些 API 来部署和删除用于按需推理的定制模型部署。

```
import boto3
import json

# First, create and configure an Amazon Bedrock client:
bedrock_client = boto3.client(
service_name="bedrock",region_name="<region-info>")

# create custom model deployment 
response = bedrock_client.create_custom_model_deployment(
                        modelDeploymentName="<model-deployment-name>",
                        modelArn="<trained-model-arn>",
                        description="<model-deployment-description>",
                        tags=[
{"key":"<your-key>",
 "value":"<your-value>"},
   ])
```

成功创建模型部署后，你可以按如下方式使用 `GetCustomModelDeployment` API 检查部署状态：

```
response = bedrock_client.get_custom_model_deployment( 
			customModelDeploymentIdentifier="<custom-deployment-arn>")
```

`GetCustomModelDeployment` 支持三种状态：`Creating`、`Active` 和 `Failed`。当响应中的状态为 `Active` 时，你应该能够通过按需部署、使用 `InvokeModel` 或 `Converse` API 来使用该定制模型，如下例所示：

```
# Define Runtime Client
bedrock_runtime = boto3.client(service_name="bedrock-runtime", region_name="<region-info>") 
# invoke a deployed custom model using Converse API
response = bedrock_runtime.converse(
                    modelId="<custom-deployment-arn>",
                    messages=[
                        {
                            "role": "user",
                            "content": [
                                {
                                    "text": "<your-prompt-for-custom-model>",
                                }
                            ]
                        }
                    ]
                )

result = response.get('output')
print(result)

# invoke a deployed custom model using InvokeModel API
request_body = {
    "schemaVersion": "messages-v1",
    "messages": [{"role": "user", 
                  "content": [{"text": "<your-prompt-for-custom-model>"}]}],
    "system": [{"text": "<system prompt>"}],
    "inferenceConfig": {"maxTokens": 500, 
                        "topP": 0.9, 
                        "temperature": 0.0
                        }
}
body = json.dumps(request_body)
response = bedrock_runtime.invoke_model(
        modelId="<custom-deployment-arn>",
        body=body
    )

# Extract and print the response text
model_response = json.loads(response["body"].read())
response_text = model_response["output"]["message"]["content"][0]["text"]
print(response_text)
```

按照这些步骤，你可以通过 Amazon Bedrock API 部署和使用定制模型，并立即通过按需部署使用为你的用例量身定制的高效、高性能模型。

## 最佳实践与注意事项

成功实施定制模型的按需部署，取决于对若干运营因素的理解。这些注意事项——包括延迟、区域可用性、配额限制、部署选项选择以及成本管理策略——会直接影响你在优化资源利用率的同时部署有效解决方案的能力。以下指南有助于你在制定推理策略时做出明智决策：

- **冷启动延迟** – 使用按需部署时，你可能会遇到初始冷启动延迟，通常持续数秒，具体取决于模型大小。这通常发生在部署近期没有流量、需要重新初始化计算资源时。
- **区域可用性** – 发布时，Amazon Nova 模型的定制模型部署将在美国东部（弗吉尼亚北部）区域提供。
- **配额管理** – 每个定制模型部署都有特定配额：  每分钟 token 数（Tokens per minute，TPM） 每分钟请求数（Requests per minute，RPM） 处于 `Creating` 状态的部署数量 单个账户中的按需部署总数

每个部署在其分配的配额内独立运行。如果某个部署超过其 TPM 或 RPM 配额，传入请求将被限流。你可以通过提交工单或联系 AWS 账户团队来申请提高配额。

- **在定制模型部署与 Provisioned Throughput 之间选择** – 你可以通过创建定制模型部署（用于按需使用）或购买 Provisioned Throughput 来为定制模型设置推理。选择取决于每个推理选项所支持的区域和模型、吞吐量需求以及成本考量。这两个选项相互独立，可以同时用于同一个定制模型。
- **成本管理** – 按需部署采用按量付费的定价模式，基于推理期间处理的 token 数量计费。你可以在按需部署上使用成本分配标签来跟踪和管理推理成本，从而借助 [AWS Cost Explorer](https://aws.amazon.com/aws-cost-management/aws-cost-explorer/) 更好地进行预算跟踪和成本优化。

## 清理

如果你一直在测试按需部署功能且不打算继续使用它，请务必清理资源以避免产生不必要的费用。以下是使用 Amazon Bedrock 控制台进行删除的方法：

- 导航到你的定制模型部署
- 选择要删除的部署
- 删除该部署

以下是使用 API 或 SDK 进行删除的方法：

要删除定制模型部署，你可以使用 `DeleteCustomModelDeployment` API。以下示例演示如何删除定制模型部署：

```
# delete deployed custom model deployment
response = bedrock_client.delete_custom_model_deployment(
              customModelDeploymentIdentifier="<trained-model-arn>"
                        )
```

## 结语

Amazon Bedrock 推出定制模型按需部署，是在让各种规模的企业都能更便捷、更具成本效益、更灵活地部署 AI 模型方面迈出的重要一步。按需部署具有以下优势：

- **成本优化** – 按量付费定价让你可以只为自己实际使用的计算资源付费
- **运维简便** – 自动资源管理无需手动配置基础设施
- **可扩展性** – 无缝处理可变工作负载，无需预先规划容量
- **灵活性** – 可以根据你的具体需求在按需部署和 Provisioned Throughput 之间自由选择

上手非常简单。首先通过 fine-tuning 或模型蒸馏完成模型定制，然后使用 AWS Management Console 或 API 选择按需部署。配置部署详情，在测试环境中验证模型性能，再无缝集成到生产工作流中。
