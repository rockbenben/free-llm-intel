# 使用面向 GenAI IDP Accelerator 的 Strands AI Agents 增强文档分析

从非结构化数据中提取结构化信息，是释放业务价值的关键第一步。我们的 [Generative AI Intelligent Document Processing (GenAI IDP) Accelerator](http://www.amazon.com/genai-idp-accelerator) 一直处于这一变革的前沿，已为数百家客户处理了数千万份文档。

尽管组织可以使用智能文档处理（IDP）解决方案，通过提取结构化数据来让文档数字化，但如何高效分析这些已处理数据的方法仍然难以捉摸。文档被处理并结构化之后，新的挑战随之出现：企业如何才能快速分析这些海量信息并释放可付诸行动的洞察？

为满足这一需求，我们推出 Analytics Agent，这是一项无缝集成到 GenAI IDP Accelerator 中的新功能。借助该功能，用户无需具备 SQL 或数据分析专长，即可使用自然语言查询执行高级搜索和复杂分析。

本文讨论非技术用户如何借助自然语言，使用这一工具来分析并理解他们已大规模处理的文档。

## GenAI IDP Accelerator

[GenAI IDP Accelerator](https://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws) 是一个开源解决方案，帮助组织利用生成式 AI 从各类文档中自动提取信息。该加速器结合 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 与其他 AWS 服务（包括 [AWS Lambda](https://aws.amazon.com/lambda)、[AWS Step Functions](https://aws.amazon.com/step-functions/)、[Amazon Simple Queue Service](https://aws.amazon.com/sqs/)（Amazon SQS）和 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/)），构建出一套无服务器系统。GenAI IDP Accelerator 按规模化设计，每天可处理数千份文档。它提供三种处理模式，供用户为复杂的文档处理工作流构建自定义解决方案。该加速器可以使用 [AWS CloudFormation](https://aws.amazon.com/cloudformation) 模板部署，用户既可以通过 Web 界面，也可以直接把文件上传到 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）来立即开始处理文档。该加速器由文档分类、数据提取、评估、摘要和评测等多个模块组成。如需进一步了解 GenAI IDP Accelerator，请参阅[在 AWS 上使用生成式 AI 加速智能文档处理](https://aws.amazon.com/blogs/machine-learning/accelerate-intelligent-document-processing-with-generative-ai-on-aws/)。

现在，通过 Analytics Agent 功能使用自然语言查询，你就可以提取有价值的信息，以了解该方案的运行表现。要使用该功能，只需部署最新版本的 GenAI IDP Accelerator，并在导航窗格中选择 **Agent Companion Chat**，如下面的截图所示（来自加速器 [0.4.7 版本](https://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws/releases/tag/v0.4.7)）。与分析相关的查询会自动路由到 Analytics Agent。

![显示导航菜单、示例查询按钮和可用 AI agents 面板的 IDP Agent Companion Chat 欢迎界面](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/15/image-1-7.png)

Analytics Agent 充当业务用户与其已处理文档数据之间的智能接口。它能够处理通常需要资深数据科学家才能应对的复杂查询，让普通业务用户也能用上高级分析。例如，一家医疗服务机构可以问：“上个月有多少比例的保险理赔被拒？其中有多少是因材料不完整导致的？给我看一下过去六个月拒赔原因的趋势。”或者，一家税务会计公司可以问：“我的哪些客户在 W2 表格上向不止一个州缴纳州税？”

下面的截图是通过 Agent Companion Chat 界面使用 Analytics Agent 功能进行分析的一个示例。一位会计行业的用户查询：“对过去 180 天内所有已上传 W2 的总收入做直方图，在 0 到 300,000 美元之间分 25 个区间”，该 agent 在不到一分钟内分析了从 1,000 多份 W2 表格中提取的数据。

## Analytics Agent

Analytics Agent 使用 [Strands Agents](https://aws.amazon.com/blogs/opensource/introducing-strands-agents-an-open-source-ai-agents-sdk/) 构建，后者是一个开源 SDK，采用模型驱动的方式来构建 AI agent。该 agent 借助多种工具，通过把自然语言转换为数据和可视化，让处理企业数据变得更直观。Analytics Agent 的工作流包括以下步骤：

- 该 agent 在需要时使用数据库探索工具，以了解存放在 IDP 解决方案内 [Amazon Athena](https://aws.amazon.com/athena) 表中的数据结构。这是必要的，因为 IDP 解决方案内的表可能因用户配置处理流水线的方式不同而具有不同的 schema。
- 该 agent 把自然语言查询转换为与可用数据库和表兼容的优化 SQL 查询。这些查询可以扩展到任意大小的表。
- 该 agent 对 Athena 执行 SQL，并把查询结果存储到 Amazon S3。这些结果可能长达数千行。它会根据 Athena 生成的错误消息，自动修复并重新运行可能失败的查询。
- 该 agent 把查询结果从 Amazon S3 安全地传输到 [AWS Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) Code Interpreter 沙箱中。
- 该 agent 编写 Python 代码，用于分析查询结果，并以与界面兼容的结构化输出生成图表或表格。该代码会被复制到沙箱中，并在其中安全执行。
- 最后，最终的可视化结果在 Web 界面中呈现，便于直接解读。

## 方案概览

下面的架构图展示了无服务器版 Analytics Agent 的部署，以及它如何通过 [AWS AppSync](https://aws.amazon.com/appsync/) API 与现有 IDP 解决方案集成。

![GenAI IDP Agent Analysis 功能的 AWS 架构图，展示代码执行、API 集成和身份验证服务](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/15/image-7.jpg)

Analytics Agent 主要部署在 Lambda 函数中。当用户从 IDP 前端向 AppSync API 提交查询时，一个临时的请求处理 Lambda 函数会在 DynamoDB 中创建并存储唯一的作业 ID 以跟踪异步处理流程，并启动一个长时间运行的 agent 请求处理 Lambda 函数，该函数会实例化一个 Strands agent 并启动它。前端轮询作业状态，并从 DynamoDB 中获取最终结果（包括此前作业的结果）。agent 请求处理 Lambda 函数具有 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）权限，可以访问 Athena 中的 IDP 表，并可以启动和运行 AgentCore Code Interpreter 沙箱，以实现更安全的 Python 代码执行。

该架构遵循安全优先的设计：

- **沙箱化执行** – Python 代码在 AgentCore Code Interpreter 中运行，与 AWS 环境的其余部分以及互联网完全隔离
- **安全的数据传输** – 查询结果通过 Amazon S3 和 AgentCore API 传输，而不经过 LLM 的上下文窗口
- **会话管理** – AgentCore Code Interpreter 会话得到妥善管理，并在使用后清理
- **最小权限** – 每个组件只请求必要的 AWS 权限
- **审计轨迹** – 该方案提供全面的日志记录与监控，以支持安全审查

## 借助 Analytics Agent 获得智能文档洞察

为了演示 Analytics Agent 的能力，我们使用 GenAI IDP Accelerator 处理了 [RVL-CDIP](https://huggingface.co/datasets/chainyo/rvl-cdip) 数据集中的 10,000 份文档。该数据集包含备忘录、信函、表单和报告等多种文档类型，我们使用[模式 2 配置](https://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws/blob/main/config_library/pattern-2/rvl-cdip-package-sample/config.yaml)进行处理，以提取文档类型、发件人、收件人和部门详情等结构化信息。在下面的各节中，我们将逐一介绍一个示例用户查询的细节。

### 真实场景查询：部门备忘录分析

一位业务用户用自然语言提出了一个直截了当的问题：“哪些部门产生的备忘录最多？”这个看似简单的查询，在传统做法下需要数据分析师完成以下步骤：

- 获取凭证并连接内部数据库
- 通过执行探索性查询或阅读内部文档来了解数据库 schema
- 使用正确的 Athena 语法编写复杂的 SQL
- 执行并校验查询
- 处理结果并创建可视化
- 为汇报整理结论

Analytics Agent 在 60 秒内自主完成了整个工作流。

下图展示了该 agent 基于单条自然语言查询生成的可视化。

### Agent 能力

这个示例展示了三项具有变革意义的能力：

- **自主问题求解** – 该 agent 独立发现了数据库 schema，识别出正确的表和列，并在无需人工干预的情况下处理了数据质量问题（空值）。这意味着无论文档类型或 IDP 处理配置如何，该 agent 都能处理由 IDP 解决方案分析的不同文档。
- **自适应推理** – 当该 agent 在初次可视化中发现空值时，它通过筛选数据并重新生成图表自动纠正了问题，展现出自我纠错能力。
- **端到端可解释性** – 整个工作流从自然语言查询到精致的可视化，在 90 秒内完成，且完全透明。用户可以通过详细的思考过程日志复盘该 agent 做出的每一项决策。

Analytics Agent 把已处理的文档数据转化为可付诸行动的洞察，帮助业务用户像向同事提问一样轻松地探索自己的文档语料。这种数据分析的大众化确保有价值的洞察不会被技术壁垒锁住，而是能被组织内各层级的决策者即时获取。

## 客户如何使用该功能

这项功能的强大之处在于它能够实现数据分析的大众化，仅凭对话这一简单力量就把业务用户变成数据分析师。客户可以在以下用例中使用该功能：

- **即时业务洞察：**  用通俗语言提出复杂问题，例如“上个季度有多少比例的发票金额超过 50,000 美元？”通过“过去 12 个月发票的平均金额走势如何？”之类的查询，立即获得趋势与模式的可视化。借助“给我看看西雅图办公室的员工中谁提交的发票最多”之类的查询，无需等待 IT 或数据科学团队即可做出数据驱动的决策。
- **风险与合规监控：**  通过“给我看看所有缺少必备条款的合同”之类的查询实时检测异常。跟踪各类文档的合规率。识别需要立即关注的高风险文档。
- **运营卓越：**  通过“哪些文档类型的处理时间最长？”之类的查询监控处理瓶颈。跟踪不同文档类别的准确率。依据量级模式优化资源分配。
- **客户体验提升：**  通过“我们本月距离用尽 100 美元的月度处理配额预算还有多远？”之类的查询分析特定客户的处理指标。识别流程自动化的机会。通过“哪些已处理的发票还没有关联的已处理工资单？”之类的查询实时跟踪 SLA 合规情况。
- **战略规划：**  通过“我们预计上传文档数量将逐年增长 20%。未来五年我们预计要处理多少份文档？”之类的查询，基于历史模式预测处理量。识别季节性趋势并据此规划。跟踪文档处理投资的 ROI 指标。为系统扩容做出有数据支撑的决策。

## 最佳实践

使用 Analytics Agent 时，请考虑以下最佳实践：

- **先宽后窄** – 先提出概括性问题，再深入具体细节。
- **保持具体** – 清楚说明你要找什么信息。如有必要，不必犹豫用一整段话来描述你的需求。
- **使用追问** – 在先前问题所得的基础上深入探索主题。在 Agent Companion Chat 中发送的聊天消息是有状态的，因此你可以提出追问。
- **核对结果** – 确认可视化对你的数据是合理的，并通读所显示的 agent 思考过程，以校验它做出的决策。

## 与外部 agentic AI 系统集成

Analytics Agent 可以通过 IDP Accelerator 新增的 Model Context Protocol（MCP）Server 轻松集成到其他 agentic AI 系统中，例如 [AWS Quick](https://aws.amazon.com/quicksuite/)。借助这一集成，组织可以把文档分析能力纳入更广泛的 AI 工作流和自动化平台。有关实施指导和技术细节，请参阅 [MCP 集成文档](https://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws/blob/main/docs/mcp-integration.md)。

## 清理

当你完成对 Agent Analysis 功能的试验后，可以根据需要选择两种清理方式：

- **删除单条分析查询** – 在 Web 界面中进入 Agent Analysis 部分，使用“load previous chat”面板删除特定查询。或者，你也可以直接从与你的堆栈关联的 DynamoDB 分析作业表中删除查询条目。
- **删除整个 IDP 部署** – 使用 CloudFormation 控制台删除 IDP 堆栈。如需在清空 S3 存储桶的同时自动清理，可以使用 IDP CLI：

`idp-cli delete --stack-name my-idp-stack --empty-buckets --force`

有关更详细的清理流程和选项，请参阅 [IDP CLI 文档](https://github.com/aws-solutions-library-samples/accelerated-intelligent-document-processing-on-aws/blob/main/docs/idp-cli.md#delete)。
