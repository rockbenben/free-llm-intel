# 为 Amazon Bedrock AgentCore Runtime agent 设置自定义域名

在将 [AI agent](https://aws.amazon.com/what-is/ai-agents/) 部署到 [Amazon Bedrock AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html)（目前处于预览阶段）时，客户往往希望使用自定义域名，以营造专业且无缝的体验。

默认情况下，AgentCore Runtime 的 agent 使用的端点形如 `https://bedrock-agentcore.{region}.amazonaws.com/runtimes/{EncodedAgentARN}/invocations`。

本文讨论如何使用 [Amazon CloudFront](https://aws.amazon.com/cloudfront/) 作为反向代理，把这些端点转换为易用的自定义域名（例如 `https://agent.yourcompany.com`）。该方案结合 CloudFront、[Amazon Route 53](https://aws.amazon.com/route53/) 和 [AWS Certificate Manager](https://aws.amazon.com/certificate-manager/)（ACM），创建安全、可扩展的自定义域名设置，并可与你现有的 agent 无缝配合。

## Amazon Bedrock AgentCore Runtime 的优势

如果你正在构建 AI agent，很可能已经为托管难题头疼过：管理基础设施、处理认证、扩展以及维护安全。Amazon Bedrock AgentCore Runtime 有助于解决这些问题。

Amazon Bedrock AgentCore Runtime 与框架无关；你可以将其与 [LangGraph](https://www.langchain.com/langgraph)、[CrewAI](https://www.crewai.com/)、[Strands Agents](https://strandsagents.com/) 或你从零构建的自定义 agent 一起使用。它支持最长 [8 小时](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html#runtime-service-limits)的延长执行时间，非常适合传统无服务器函数无法处理的复杂推理任务。每个用户会话都在自己独立的 microVM 中运行，提供对企业应用至关重要的安全性。

基于用量的定价模式意味着你只需为实际使用付费，而不必为预置的资源付费。与其他托管方案不同，Amazon Bedrock AgentCore Runtime 开箱即可提供内置认证和专为 AI agent 设计的可观测性。

## 自定义域名的优势

使用带 [Open Authorization (OAuth)](https://en.wikipedia.org/wiki/OAuth) 认证的 Amazon Bedrock AgentCore Runtime 时，你的应用会向服务端点直接发起 HTTPS 请求。这样做虽然可行，但自定义域名能带来若干优势：

- **自定义品牌（Custom branding）** – 客户端应用（网页浏览器、移动应用）在网络请求中展示你品牌的域名，而不是 AWS 基础设施细节
- **更佳的开发者体验（Better developer experience）** – 开发团队可以使用易于记忆的品牌域名，而不必在代码库和配置中复制粘贴冗长的 AWS 端点
- **简化维护（Simplified maintenance）** – 自定义域名让部署多个 agent 或跨环境更新配置时的端点管理变得简单直接

## 解决方案概述

在本方案中，我们使用 CloudFront 作为反向代理，把来自你自定义域名的请求转换为 Amazon Bedrock AgentCore Runtime 的 API 调用。你的应用无需使用默认端点，而是可以向 `https://agent.yourcompany.com/` 这样的易用 URL 发起请求。

下图说明了该解决方案的架构。

![AgentCore-Diagram](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/20/Screenshot-2025-08-20-at-11.41.18 AM-1024x483.png)

该工作流包含以下步骤：

- 客户端应用向 [Amazon Cognito](https://aws.amazon.com/cognito/) 进行认证，并获取 bearer token。
- 客户端向你自定义域名发起 HTTPS 请求。
- Route 53 把 DNS 请求解析到 CloudFront。
- CloudFront 把已认证的请求转发到 Amazon Bedrock Runtime 的 agent。
- agent 处理请求，并沿同一路径返回响应。

你可以使用同一个 CloudFront 分配同时服务前端应用和后端 agent 端点，从而避免[跨源资源共享（CORS）](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)问题，因为一切都源自同一个域名。

## 先决条件

要跟随本演练，你需要准备好以下内容：

- 一个具有相应权限的 AWS 账户
- [AWS Cloud Development Kit](https://aws.amazon.com/cdk/)（AWS CDK）2.x 或更高版本
- 一个具备 Amazon Bedrock AgentCore Runtime [相应权限](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-permissions.html)的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）执行角色

虽然 Amazon Bedrock AgentCore Runtime 可以部署在其他[受支持的 AWS 区域](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html)，但 CloudFront 要求 SSL 证书位于 `us-east-1` 区域。

你可以从以下域名方案中选择：

- **使用现有域名（Use an existing domain）** – 添加一个子域名，例如 `agent.yourcompany.com`
- **注册新域名（Register a new domain）** – 如果你没有域名，可以使用 Route 53 注册
- **使用 CloudFront 的默认 URL（Use the default URL from CloudFront）** – 无需注册或配置域名

如果你想在设置自定义域名之前快速测试该方案，请选择第三种方案。

## 创建带入站认证的 agent

如果你已经部署了使用 OAuth 认证的 agent，可以跳到下一节设置自定义域名。否则，请按以下步骤使用 Amazon Cognito 作为 OAuth 提供方创建新 agent：

- 为你的 agent 创建一个具有以下结构的新目录：

```
your_project_directory/
├── agent_example.py # Your main agent code
├── requirements.txt # Dependencies for your agent
└── __init__.py # Makes the directory a Python package
```

- 在 `agent_example.py` 中编写主 agent 代码：

```
# agent_example.py
from strands import Agent
from bedrock_agentcore.runtime import BedrockAgentCoreApp

agent = Agent()
app = BedrockAgentCoreApp()
@app.entrypoint
def invoke(payload):
    """Process user input and return a response"""
    user_message = payload.get("prompt", "Hello")
    response = agent(user_message)
    return str(response) # response should be json serializable
if __name__ == "__main__":
    app.run()
```

- 在 `requirements.txt` 中添加依赖：

```
# requirements.txt
strands-agents
bedrock-agentcore
```

- 运行以下命令创建 Amazon Cognito 用户池和测试用户：

```
# Create User Pool and capture Pool ID
export POOL_ID=$(aws cognito-idp create-user-pool \
  --pool-name "MyUserPool" \
  --policies '{"PasswordPolicy":{"MinimumLength":8}}' \
  --region us-east-1 | jq -r '.UserPool.Id')

# Create App Client and capture Client ID
export CLIENT_ID=$(aws cognito-idp create-user-pool-client \
  --user-pool-id $POOL_ID \
  --client-name "MyClient" \
  --no-generate-secret \
  --explicit-auth-flows "ALLOW_USER_PASSWORD_AUTH" "ALLOW_REFRESH_TOKEN_AUTH" \
  --region us-east-1 | jq -r '.UserPoolClient.ClientId')

# Create and configure a test user
aws cognito-idp admin-create-user \
  --user-pool-id $POOL_ID \
  --username "testuser" \
  --temporary-password "Temp1234" \
  --region us-east-1 \
  --message-action SUPPRESS

aws cognito-idp admin-set-user-password \
  --user-pool-id $POOL_ID \
  --username "testuser" \
  --password "MyPassword123" \
  --region us-east-1 \
  --permanent

echo "Pool ID: $POOL_ID"
echo "Discovery URL: https://cognito-idp.us-east-1.amazonaws.com/$POOL_ID/.well-known/openid-configuration"
echo "Client ID: $CLIENT_ID"
```

- 使用 starter toolkit 提供的 Amazon Bedrock AgentCore 命令行界面（CLI）部署 agent：

```
pip install bedrock-agentcore-starter-toolkit #install the starter toolkit

agentcore configure --entrypoint agent_example.py \
--name my_agent \
--execution-role your-execution-role-arn \
--requirements-file requirements.txt \
--authorizer-config "{\"customJWTAuthorizer\":{\"discoveryUrl\":\"https://cognito-idp.us-east-1.amazonaws.com/$POOL_ID/.well-known/openid-configuration\",\"allowedClients\":[\"$CLIENT_ID\"]}}"

agentcore launch
```

部署后请记下你的 agent runtime 的 Amazon Resource Name（ARN）。配置自定义域名时你需要用到它。

更多示例和细节，请参阅[使用 Inbound Auth 与 Outbound Auth 进行认证和授权](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-oauth.html)。

## 设置自定义域名解决方案

现在我们用 AWS CDK 实现自定义域名方案。本节展示如何创建 CloudFront 分配，把自定义域名的请求代理到 Amazon Bedrock AgentCore Runtime 端点。

- 创建一个新目录并初始化 AWS CDK 项目：

```
mkdir agentcore-custom-domain
cd agentcore-custom-domain
cdk init app --language python
source .venv/bin/activate
pip install aws-cdk-lib constructs
```

- 对 agent ARN 进行编码，并准备 CloudFront 源配置：

```
# agentcore_custom_domain_stack.py 
import urllib.parse

agent_runtime_arn = "arn:aws:bedrock-agentcore:us-east-1:accountId:runtime/my_agent-xbcDkz4FR9"
encoded_arn = urllib.parse.quote(agent_runtime_arn, safe='') # URL-encode the ARN
region = agent_runtime_arn.split(':')[3]  # Extract region from ARN
```

如果你的前端应用与 agent 端点运行在不同的域名上，你必须配置 CORS 头。当前端托管在另一个域名（例如 `https://app.yourcompany.com` 调用 `https://agent.yourcompany.com`），或者你在本地开发（例如 `http://localhost:3000` 调用你的生产 agent 端点）时，这种情况很常见。

- 为满足 CORS 需求，创建一个 CloudFront [响应头策略](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/understanding-response-headers-policies.html)：

```
# agentcore_custom_domain_stack.py 
from aws_cdk.aws_cloudfront import ResponseHeadersPolicy, ResponseHeadersCorsBehavior

# Create CORS response headers policy
cors_policy = ResponseHeadersPolicy(self, 'CorsPolicy',
    cors_behavior=ResponseHeadersCorsBehavior(
        access_control_allow_origins=['*'], # Or specify your frontend domains
        access_control_allow_headers=[
            'Authorization',
            'Content-Type', 
            'X-Amzn-*',
            'X-Requested-With'
        ],
        access_control_allow_methods=['GET', 'POST', 'OPTIONS'],
        access_control_allow_credentials=False,
        access_control_expose_headers=['*'],
        origin_override=True # Overrides CORS headers from origin
    )
)
```

- 创建一个 CloudFront 分配，作为 agent 端点的反向代理：

```
# agentcore_custom_domain_stack.py
 from aws_cdk.aws_cloudfront import (
    Distribution, BehaviorOptions, CachePolicy, 
    AllowedMethods, ViewerProtocolPolicy,
    OriginProtocolPolicy, OriginRequestPolicy
)
from aws_cdk.aws_cloudfront_origins import HttpOrigin

bedrock_agentcore_hostname = f"bedrock-agentcore.{region}.amazonaws.com"
origin_path = f"/runtimes/{encoded_arn}/invocations"

distribution = Distribution(self, 'Distribution',
    default_behavior=BehaviorOptions(
        origin=HttpOrigin(
            bedrock_agentcore_hostname,
            origin_path=origin_path, 
            protocol_policy=OriginProtocolPolicy.HTTPS_ONLY,
            read_timeout=Duration.seconds(120) # Optional: for responses >30s, adjust as needed
        ),
        viewer_protocol_policy=ViewerProtocolPolicy.REDIRECT_TO_HTTPS,
        cache_policy=CachePolicy.CACHING_DISABLED,  # Critical for dynamic APIs
        allowed_methods=AllowedMethods.ALLOW_ALL,
        response_headers_policy=cors_policy,  # Add CORS policy if created
        origin_request_policy=OriginRequestPolicy.ALL_VIEWER,  # Forward headers for MCP
    ),
    # Add domain configuration if using custom domains
    domain_names=[domain_name] if domain_name else None,
    certificate=certificate if domain_name else None,
)
```

设置 `cache_policy=CachePolicy.CACHING_DISABLED`，以确保 agent 的响应保持动态、不被 CloudFront 缓存。

- 如果你使用自定义域名，请向堆栈添加 SSL 证书和 DNS 配置：

```
# agentcore_custom_domain_stack.py 
from aws_cdk.aws_certificatemanager import Certificate, CertificateValidation
from aws_cdk.aws_route53 import HostedZone, ARecord, RecordTarget
from aws_cdk.aws_route53_targets import CloudFrontTarget

# For existing domains
hosted_zone = HostedZone.from_lookup(self, 'HostedZone',
    domain_name='yourcompany.com'
)
# SSL certificate with automatic DNS validation
certificate = Certificate(self, 'Certificate',
    domain_name='my-agent.yourcompany.com',
    validation=CertificateValidation.from_dns(hosted_zone),
)
# DNS record pointing to CloudFront
ARecord(self, 'AliasRecord',
    zone=hosted_zone,
    record_name='my-agent.yourcompany.com',
    target=RecordTarget.from_alias(CloudFrontTarget(distribution)),
)
```

以下代码是组合了所有组件的完整 AWS CDK 堆栈：

```
# agentcore_custom_domain_stack.py
import urllib.parse
from aws_cdk import Stack, CfnOutput, Duration
from aws_cdk.aws_cloudfront import (
    Distribution, BehaviorOptions,
    CachePolicy, AllowedMethods,
    ViewerProtocolPolicy, OriginProtocolPolicy,
    ResponseHeadersPolicy, ResponseHeadersCorsBehavior,
    OriginRequestPolicy
)
from aws_cdk.aws_cloudfront_origins import HttpOrigin
from aws_cdk.aws_certificatemanager import Certificate, CertificateValidation
from aws_cdk.aws_route53 import HostedZone, ARecord, RecordTarget
from aws_cdk.aws_route53_targets import CloudFrontTarget
from constructs import Construct

class AgentcoreCustomDomainStack(Stack):
    def __init__(self, scope: Construct, construct_id: str, **kwargs) -> None:
        super().__init__(scope, construct_id, **kwargs)

        # Configuration - Update these for your setup
        agent_runtime_arn = "arn:aws:bedrock-agentcore:us-east-1:accountId:runtime/my_agent-xbcDkz4FR9"
        region = agent_runtime_arn.split(':')[3]  # Extract region from ARN
        domain_name = "agent.yourcompany.com"  # Using your hosted zone
        hosted_zone_id = "Z1234567890ABC"  # Your hosted zone ID
        enable_cors = True  # Set to False if serving frontend and backend from same domain

        # Encode the agent ARN for the origin path
        encoded_arn = urllib.parse.quote(agent_runtime_arn, safe='')
        bedrock_agentcore_hostname = f"bedrock-agentcore.{region}.amazonaws.com"
        origin_path = f"/runtimes/{encoded_arn}/invocations"

        # Create CORS response headers policy if needed
        cors_policy = None
        if enable_cors:
            cors_policy = ResponseHeadersPolicy(self, 'CorsPolicy',
                cors_behavior=ResponseHeadersCorsBehavior(
                    access_control_allow_origins=['*'],  # Or specify your frontend domains
                    access_control_allow_headers=[
                        'Authorization',
                        'Content-Type', 
                        'X-Amzn-*',
                        'X-Requested-With'
                    ],
                    access_control_allow_methods=['GET', 'POST', 'OPTIONS'],
                    access_control_expose_headers=['*'],
                    access_control_allow_credentials=False,
                    origin_override=True  # Overrides CORS headers from origin
                )
            )

        # Base distribution configuration
        distribution_props = {
            "default_behavior": BehaviorOptions(
                origin=HttpOrigin(
                    bedrock_agentcore_hostname,
                    origin_path=origin_path,  # Direct path to agent endpoint
                    protocol_policy=OriginProtocolPolicy.HTTPS_ONLY,
                    read_timeout=Duration.seconds(120) # Optional: for responses >30s, adjust as needed
                ),
                viewer_protocol_policy=ViewerProtocolPolicy.REDIRECT_TO_HTTPS,
                cache_policy=CachePolicy.CACHING_DISABLED,
                allowed_methods=AllowedMethods.ALLOW_ALL,
                response_headers_policy=cors_policy,  # Add CORS policy if enabled
                origin_request_policy=OriginRequestPolicy.ALL_VIEWER,  # Forward headers for MCP
            )
        }

        # Optional: Add custom domain
        if domain_name:
            # Use from_hosted_zone_attributes for specific zone
            hosted_zone = HostedZone.from_hosted_zone_attributes(self, 'HostedZone',
                                                                 zone_name='yourcompany.com',  # Your root domain
                                                                 hosted_zone_id=hosted_zone_id
                                                                 )

            certificate = Certificate(self, 'Certificate',
                                      domain_name=domain_name,
                                      validation=CertificateValidation.from_dns(
                                          hosted_zone),
                                      )

            # Add custom domain to distribution
            distribution_props["domain_names"] = [domain_name]
            distribution_props["certificate"] = certificate

        distribution = Distribution(self, 'Distribution', **distribution_props)

        # Create DNS record if using custom domain
        if domain_name:
            ARecord(self, 'AliasRecord',
                    zone=hosted_zone,
                    record_name=domain_name,
                    target=RecordTarget.from_alias(
                        CloudFrontTarget(distribution)),
                    )

        # Outputs
        if domain_name:
            domain_url = f"https://{domain_name}/"
            CfnOutput(self, "AgentEndpoint",
                      value=domain_url,
                      description="Your custom domain endpoint"
                      )

        CfnOutput(self, "CloudFrontDistribution",
                  value=f"https://{distribution.distribution_domain_name}/",
                  description="CloudFront default domain (works without custom domain)"
                  )
```

- 配置 AWS CDK 的 `app` 入口：

```
# app.py
#!/usr/bin/env python3
import aws_cdk as cdk
from agentcore_custom_domain.agentcore_custom_domain_stack import AgentCoreCustomDomainStack

app = cdk.App()
AgentcoreCustomDomainStack(app, "AgentCoreCustomDomainStack",
    # CloudFront requires certificates in us-east-1
    env=cdk.Environment(region='us-east-1'),
)
app.synth()
```

## 部署自定义域名

现在你可以部署该方案，并验证它在自定义域名和默认域名下都能正常工作。请完成以下步骤：

- 更新 `agentcore_custom_domain_stack.py` 中的以下值：你的 Amazon Bedrock AgentCore Runtime ARN、你的域名（如果使用自定义域名）、你的托管区 ID（如果使用自定义域名）
- 使用 AWS CDK 部署：

```
cdk deploy
```

## 测试你的端点

部署自定义域名后，你可以使用自定义域名或 CloudFront 默认域名测试端点。首先，从 Amazon Cognito 获取 JWT token：

```
export TOKEN=$(aws cognito-idp initiate-auth \
  --client-id "your-client-id" \
  --auth-flow USER_PASSWORD_AUTH \
  --auth-parameters USERNAME='testuser',PASSWORD='MyPassword123' \
  --region us-east-1 | jq -r '.AuthenticationResult.AccessToken')
```

使用以下代码通过自定义域名进行测试：

```
curl -X POST "https://my-agent.yourcompany.com/" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -H "X-Amzn-Bedrock-AgentCore-Runtime-Session-Id: session-12345678901234567890123456789012345" \
  -d '{"prompt": "Hello, how can you help me today?"}'
```

或者，使用以下代码通过 CloudFront 默认域名进行测试：

```
curl -X POST "https://d1234567890123.cloudfront.net/" \

```

如果一切正常，你会通过任一端点收到来自 agent 的响应。你已成功为 Amazon Bedrock AgentCore Runtime 的 agent 创建了自定义域名！

## 注意事项

在生产环境中实施该方案时，以下是一些重要注意事项：

- **成本影响（Cost implications）** – CloudFront 会产生数据传输和请求费用。请查看 [Amazon CloudFront 定价](https://aws.amazon.com/cloudfront/pricing/)以了解对你使用模式的影响。
- **安全增强（Security enhancements）** – 考虑实施以下安全措施：[AWS WAF](https://aws.amazon.com/waf/) 规则，帮助防御常见的 Web 攻击。速率限制，帮助防止滥用。地理位置限制，如果你的 agent 只应从特定区域访问。
- **监控（Monitoring）** – 启用 CloudFront [访问日志](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/AccessLogs.html)，并设置 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 告警，以监控错误率、延迟和请求量。

## 清理

为避免持续产生费用，请在不再需要这些资源时将其删除：

```
cdk destroy
```

你可能需要从各自的服务控制台手动删除 Route 53 托管区和 ACM 证书。
