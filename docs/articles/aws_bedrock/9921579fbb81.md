# 在亚太地区（新西兰）使用 Amazon Bedrock 运行生成式 AI 推理

*Kia ora！*

新西兰的客户一直希望能从本地 AWS Region 访问 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的基础模型（FM）。

今天，我们很高兴宣布 Amazon Bedrock 现已在亚太地区（新西兰）Region（ap-southeast-6）推出。新西兰的客户现在可以在奥克兰 Region 通过跨区域推理直接访问 [Anthropic Claude](https://aws.amazon.com/bedrock/claude/) 模型（Claude Opus 4.5、Opus 4.6、Sonnet 4.5、Sonnet 4.6 和 Haiku 4.5）以及 Amazon（Nova 2 Lite）模型。

本文将探讨从新西兰 Region 发起跨区域推理的工作方式、可通过地理路由与全球路由使用的模型，以及如何完成第一次 API 调用。我们涵盖三个关键方面：

- Amazon Bedrock 在 ap-southeast-6 如何利用跨区域推理让你访问基础模型，以及跨奥克兰、悉尼和墨尔本的 ANZ 地理路由配置
- 支持的模型、IAM 权限，以及如何从奥克兰 Region 发起第一次推理调用
- 配额管理、安全考量，以及如何为你的工作负载在地理与全球跨区域推理之间选择

## 理解跨区域推理

跨区域推理是 Amazon Bedrock 的一项能力，它把推理处理分布到多个 AWS Region，帮助你在规模化时获得更高吞吐。

当你调用跨区域[推理配置（inference profile）](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)时，Amazon Bedrock 会把你的请求从**源 Region**（你发起 API 调用的地方）路由到**目标 Region**（执行推理处理的地方）。跨区域操作期间传输的所有数据都留在 AWS 网络上，不经过公网，并且在 AWS Region 之间传输时加密。所有跨区域推理请求都会记录在源 Region 的 [AWS CloudTrail](https://aws.amazon.com/cloudtrail/) 中。如果你配置了[模型调用日志](https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html)，日志会发布到同一 Region 的 [Amazon CloudWatch Logs](https://aws.amazon.com/cloudwatch/) 或 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/)。

Amazon Bedrock 提供两类跨区域推理配置：

- **地理跨区域推理** – 在特定地理边界内路由请求。例如，使用 AU 配置、以奥克兰为源 Region 时，请求会路由到奥克兰、悉尼和墨尔本。适用于有数据驻留要求、需要推理处理留在澳大利亚与新西兰境内的组织。
- **全球跨区域推理** – 把请求路由到全球受支持的商业 AWS Region，提供最高可用吞吐。适用于没有严格数据驻留要求的组织。

## 新变化：新西兰成为跨区域推理的源 Region

随着本次发布，奥克兰（`ap-southeast-6`）成为 Amazon Bedrock 上 AU 地理与全球跨区域推理的新源 Region。这意味着你现在可以从新西兰 Region 发起 Amazon Bedrock API 调用，跨区域推理会把请求路由到由基础模型执行推理的目标 Region。

### AU 地理跨区域推理配置

AU 跨区域配置现在横跨澳大利亚与新西兰的三个 Region。下表详列源 Region 与目标 Region 的路由关系。

| **源 Region** | **目标 Region** | **说明** |
| --- | --- | --- |
| **奥克兰（`ap-southeast-6`）** | `ap-southeast-6`, `ap-southeast-2`, `ap-southeast-4` | 新增 – 来自奥克兰的请求可路由到悉尼、墨尔本或奥克兰 |
| **悉尼（`ap-southeast-2`）** | `ap-southeast-2`, `ap-southeast-4` | 来自悉尼的请求可路由到悉尼或墨尔本 |
| **墨尔本（`ap-southeast-4`）** | `ap-southeast-2`, `ap-southeast-4` | 来自墨尔本的请求可路由到悉尼或墨尔本 |

有两点重要细节需要注意：

- 悉尼与墨尔本的 AU 跨区域推理配置仍只在悉尼与墨尔本之间路由。新增奥克兰不会改变现有澳大利亚源 Region 配置的目标 Region。
- 源自奥克兰的请求既可在本地处理，也可路由到任一澳大利亚 Region，从而有三个目标 Region 用于分摊容量。

### 从新西兰发起全球跨区域推理

对于没有严格数据驻留要求的组织，从奥克兰 Region 发起全球跨区域推理可访问全球所有受支持 AWS 商业 Region 的推理容量。全球跨区域推理带来两项关键优势：

- **更高吞吐** —— 智能路由会把流量动态分布到所有受支持商业 Region，降低流量高峰时被限流的可能性
- **内置韧性** —— 请求会自动路由到有余量的 Region，帮助你的应用在需求模式变化时保持业务连续性

## 快速开始

### 支持的模型与推理配置 ID

从新西兰 Region 发起的跨区域推理，在 AU 地理与全球两类推理配置下均支持来自多家提供商的基础模型。下表列出发布时可用最新模型的示例。

| **跨区域推理类型** | **示例模型** |
| --- | --- |
| **AU 地理跨区域推理** | Anthropic Claude Opus 4.6、Claude Sonnet 4.6、Claude Sonnet 4.5、Claude Haiku 4.5 |
| **全球跨区域推理** | Anthropic Claude Opus 4.6、Claude Sonnet 4.6、Claude Opus 4.5、Claude Sonnet 4.5、Claude Haiku 4.5 |

AU 地理跨区域推理目前支持 Anthropic Claude 模型，使推理处理保持在 ANZ 地理范围内。全球跨区域推理则可访问来自多家提供商的更广泛基础模型集合。要使用跨区域推理配置，请把基础模型 ID 替换为带地理（au.）或全球（global.）前缀的形式——例如，`anthropic.claude-sonnet-4-6` 变为 `au.anthropic.claude-sonnet-4-6` 或 `global.anthropic.claude-sonnet-4-6`。

关于受支持模型与推理配置 ID 的完整且最新的清单，请参阅[推理配置支持的 Region 与模型](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)。

跨区域推理配置可与 `InvokeModel`、`InvokeModelWithResponseStream`、`Converse` 和 `ConverseStream` API 配合使用。`Converse` API 在不同基础模型之间提供一致的请求与响应格式，因此无需改写集成代码即可在模型之间切换。

### 配置 IAM 权限

要从奥克兰 Region 通过 AU 地理跨区域推理调用基础模型，你的 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam/)策略需要两条语句：

- 授予对源 Region 中推理配置的访问权限
- 授予对 AU 跨区域推理配置中列出的所有目标 Region 内基础模型的访问权限。

下面的 IAM 策略示例授予从奥克兰通过 AU 地理跨区域推理调用 Anthropic Claude Sonnet 4.6 的权限。请把 `<ACCOUNT_ID>` 替换为你的 AWS 账户 ID。

```
{ 
     "Version": "2012-10-17", 
     "Statement": [ 
         { 
             "Sid": "AllowAuCrisInferenceProfile", 
             "Effect": "Allow", 
             "Action": [ 
                 "bedrock:InvokeModel", 
                 "bedrock:InvokeModelWithResponseStream" 
             ], 
             "Resource": "arn:aws:bedrock:ap-southeast-6:<ACCOUNT_ID>:inference-profile/au.anthropic.claude-sonnet-4-6" 
         }, 
         { 
             "Sid": "AllowFoundationModelViaAuCris", 
             "Effect": "Allow", 
             "Action": [ 
                 "bedrock:InvokeModel", 
                 "bedrock:InvokeModelWithResponseStream" 
             ], 
             "Resource": [ 
                 "arn:aws:bedrock:ap-southeast-2::foundation-model/anthropic.claude-sonnet-4-6", 
                 "arn:aws:bedrock:ap-southeast-4::foundation-model/anthropic.claude-sonnet-4-6", 
                 "arn:aws:bedrock:ap-southeast-6::foundation-model/anthropic.claude-sonnet-4-6" 
             ], 
             "Condition": { 
                 "StringLike": { 
                     "bedrock:InferenceProfileArn": "arn:aws:bedrock:ap-southeast-6:<ACCOUNT_ID>:inference-profile/au.anthropic.claude-sonnet-4-6" 
                 } 
             } 
         } 
     ] 
} 
```

第一条语句允许从奥克兰源 Region 调用 AU 推理配置。第二条语句允许在三个目标 Region 中调用该基础模型，但仅当请求经 AU 推理配置路由时才允许。这遵循最小权限原则，阻止在这些 Region 中直接调用模型。

同样的两条语句模式适用于 AU 跨区域推理配置中的任何模型——只需替换资源 ARN 中的模型 ID。关于全球跨区域推理的 IAM 策略、[服务控制策略（SCP）](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps.html)配置以及进阶安全模式，请参阅[保护 Amazon Bedrock 跨区域推理：地理与全球](https://aws.amazon.com/blogs/machine-learning/securing-amazon-bedrock-cross-region-inference-geographic-and-global/)。

## 安全与合规考量

跨区域推理的设计以安全为核心。所有请求仅经由 AWS 全球网络传输并端到端加密，你的静态数据仍留在源 Region。

对于使用 SCP 限制访问特定 AWS Region 的组织，从奥克兰源 Region（`ap-southeast-6`）发起调用时请注意：

- **AU 地理跨区域推理**要求在 SCP 中为 Amazon Bedrock 操作允许 `ap-southeast-2`、`ap-southeast-4` 和 `ap-southeast-6`，因为奥克兰的 AU 配置会路由到全部三个 ANZ Region。
- **全球跨区域推理**还要求为 Amazon Bedrock 操作允许以 *unspecified* 作为 Region 值，因为目标 Region 是动态确定的。

下面的示例 SCP 把服务限制在奥克兰 Region，但对 Amazon Bedrock 与 IAM 等全球性服务作例外处理。它把 Amazon Bedrock 限制在三个 ANZ Region，并要求在悉尼与墨尔本的 Amazon Bedrock 访问必须经过跨区域推理配置，而非直接调用模型：

```
{ 
     "Version": "2012-10-17", 
     "Statement": [ 
         { 
             "Sid": "DenyNonBedrockServicesOutsideAuckland", 
             "Effect": "Deny", 
             "NotAction": [ 
                 "bedrock:*", 
                 "iam:*", 
                 "organizations:*", 
                 "support:*" 
             ], 
             "Resource": "*", 
             "Condition": { 
                 "StringNotEquals": { 
                     "aws:RequestedRegion": ["ap-southeast-6"] 
                 } 
             } 
         }, 
         { 
             "Sid": "DenyBedrockOutsideANZRegions", 
             "Effect": "Deny", 
             "Action": "bedrock:*", 
             "Resource": "*", 
             "Condition": { 
                 "StringNotEquals": { 
                     "aws:RequestedRegion": [ 
                         "ap-southeast-2", 
                         "ap-southeast-4", 
                         "ap-southeast-6" 
                     ] 
                 } 
             } 
         }, 
         { 
             "Sid": "DenyDirectBedrockInDestinationRegions", 
             "Effect": "Deny", 
             "Action": "bedrock:*", 
             "Resource": "*", 
             "Condition": { 
                 "StringEquals": { 
                     "aws:RequestedRegion": [ 
                         "ap-southeast-2", 
                         "ap-southeast-4" 
                     ] 
                 }, 
                 "Null": { 
                     "bedrock:InferenceProfileArn": "true" 
                 } 
             } 
         } 
     ] 
} 
```

在上面的策略中：

- 第一条语句把所有服务限制在奥克兰 Region，但对 Amazon Bedrock 以及 IAM、AWS Organizations、AWS Support 这类不受 Region 限制、独立运行的全球性服务作例外。
- 第二条语句把 Amazon Bedrock 限制在三个 ANZ Region，这是 AU 跨区域推理把请求从奥克兰路由到悉尼与墨尔本所必需的。
- 第三条语句对 **bedrock:InferenceProfileArn** 使用 Null 条件，拒绝悉尼或墨尔本中任何未经跨区域推理配置路由的 Amazon Bedrock 请求。这样既阻止在目标 Region 直接调用模型，又允许跨区域推理正常运行。

关于详细的 SCP 配置示例、全球跨区域推理 IAM 策略、禁用特定跨区域推理类型，以及 [AWS Control Tower](https://aws.amazon.com/controltower/) 集成指引，请参阅[保护 Amazon Bedrock 跨区域推理：地理与全球](https://aws.amazon.com/blogs/machine-learning/securing-amazon-bedrock-cross-region-inference-geographic-and-global/)。

## 审计与监控

[AWS CloudTrail](https://aws.amazon.com/cloudtrail/) 在源 Region 记录所有跨区域推理调用。`additionalEventData.inferenceRegion` 字段记录每个请求在何处处理，因此你可以精确审计推理发生的位置：

```
{ 
     "eventSource": "bedrock.amazonaws.com", 
     "eventName": "InvokeModel", 
     "awsRegion": "ap-southeast-6", 
     "requestParameters": { 
         "modelId": "au.anthropic.claude-sonnet-4-6" 
     }, 
     "additionalEventData": { 
         "inferenceRegion": "ap-southeast-2" 
     } 
} 
```

要做实时运行监控，[Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 在源 Region 提供跨区域推理请求的指标。关键指标包括：

- **InvocationCount** — 推理请求总数
- **InvocationLatency** — 包含跨区域路由的端到端响应时间
- **InvocationClientErrors** — 失败请求，包括限流（出现尖峰说明你正接近配额上限）
- **InputTokenCount** 与 **OutputTokenCount** — 用于配额追踪的 token 消耗量

## 配额管理

[Amazon Bedrock 服务配额](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas.html)在源 Region 层面管理。从奥克兰 Region（ap-southeast-6）申请的配额提升仅适用于源自奥克兰的请求。

配额从两个维度衡量：

- **每分钟 token 数（TPM）** — 每分钟可处理的最大 token 数（输入 + 输出）
- **每分钟请求数（RPM）** — 每分钟最大推理请求数

计算所需配额时，请计入 **token 消耗率（burndown rate）**。对于 Anthropic Claude Opus 4.6、Sonnet 4.6 和 Sonnet 4.5，输出 token 消耗的配额是输入 token 的五倍（5:1 消耗率）。对于 Claude Haiku 4.5 和 Amazon Nova 模型，消耗率为 1:1。

**配额消耗公式：**

*配额消耗 = 输入 token + 缓存写入 token +（输出 token x 消耗率）*

要申请配额提升，请在源 Region 打开 [AWS Service Quotas 控制台](https://console.aws.amazon.com/servicequotas/)，选择 Amazon Bedrock，并搜索该模型相关的跨区域推理配额。

## 结语

本文介绍了 Amazon Bedrock 从新西兰 Region 提供的跨区域推理支持。新西兰的客户现在可以从奥克兰发起 API 调用，并通过地理与全球跨区域推理配置访问基础模型。关键要点：

- **奥克兰现已成为跨区域推理的源 Region** — 新西兰客户可从本地 Region 发起 Amazon Bedrock API 调用，日志与配置都留在奥克兰。
- **AU 地理跨区域推理把数据留在 ANZ 境内** — 来自奥克兰的推理请求路由到三个目标（奥克兰、悉尼和墨尔本），在 ANZ 地理边界内提供 Anthropic Claude 模型。
- **全球跨区域推理扩大模型访问范围** — 通过把请求路由到全球受支持的商业 AWS Region，提供最高可用吞吐。
- **既有澳大利亚路由不变** — 悉尼与墨尔本这两个源 Region 仍只在彼此之间路由。

你可以按以下步骤开始使用新西兰 Region 的跨区域推理：

- 在奥克兰 Region（`ap-southeast-6`）登录 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock/)。
- 使用本文的策略示例配置 IAM 与 SCP 权限。
- 使用 au. 推理配置 ID 发起第一次 API 调用。
- 依据预期工作负载，通过 [Service Quotas 控制台](https://console.aws.amazon.com/servicequotas/)申请配额提升。
