# 使用 Amazon Bedrock Agents 加速 IaC 故障排查

排查[基础设施即代码（IaC）](https://aws.amazon.com/what-is/iac/)错误往往会消耗宝贵的时间和资源。开发者可能要经历多轮循环，在各类论坛中寻找解决方案、反复处理重复出现的问题，或者努力定位根本原因。这些延误可能导致安全错误或合规违规被忽略，在复杂的多账户环境中尤其如此。

本文演示如何使用 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 构建一个智能解决方案，通过上下文感知的故障排查来简化 Terraform 和 [AWS CloudFormation](https://aws.amazon.com/cloudformation) 代码问题的解决。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项完全托管的服务，通过单一 API 提供来自 AI21 Labs、Anthropic、Cohere、Meta、Stability AI 和 Amazon 等领先 AI 公司的高性能基础模型（FM）选择，并提供一整套能力，让你以安全、隐私和负责任 AI 的方式构建生成式 AI 应用。Amazon Bedrock Agents 是一项完全托管的服务，帮助开发者创建能够把复杂任务分解为步骤、并使用 FM 和 API 执行这些步骤以达成特定业务目标的 AI agent。

我们的解决方案使用 Amazon Bedrock Agents 分析错误消息和代码上下文，为 IaC 错误生成详细的排查步骤。在拥有[多账户 AWS 环境](https://docs.aws.amazon.com/whitepapers/latest/organizing-your-aws-environment/organizing-your-aws-environment.html)的组织中，团队通常会维护一个集中式的 AWS 环境供开发者部署应用。这种设置确保使用 IaC 进行的 AWS 基础设施部署符合[组织的安全与合规措施](https://docs.aws.amazon.com/organizations/latest/userguide/security.html)。对于与这些合规措施相关的特定 IaC 错误，例如涉及[服务控制策略](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps.html)（SCP）或[基于资源的策略](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_identity-vs-resource.html)的错误，我们的解决方案会智能地引导开发者联系相应的团队，如安全团队或赋能团队。这种有针对性的指引维护了安全协议，并确保敏感问题由合适的专家处理。该解决方案很灵活，可以适配这些示例之外的类似用例。

尽管在本示例中我们聚焦于 [Terraform Cloud 工作区](https://developer.hashicorp.com/terraform/cloud-docs/workspaces)，但同样的原则也适用于 [GitLab CI/CD pipeline](https://docs.aws.amazon.com/prescriptive-guidance/latest/devops-pipeline-accelerator/using-gitlab-cicd.html)或其他执行 IaC 代码的持续集成与交付（CI/CD）方式。通过自动化初步的错误分析并提供有针对性的解决方案或指引，你可以提升运营效率，并在组织的合规框架内专注于解决复杂的基础设施挑战。

## 解决方案概览

在深入部署过程之前，让我们先梳理下图所示架构的关键步骤。

![Terraform-troubleshooting](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/11/Terraform-troubleshooting.png)

Terraform 解决方案的工作流如下：

- **通过 Amazon Bedrock Agents 聊天控制台进行初始输入** – 用户首先在 Amazon Bedrock Agents 的聊天控制台中输入其 Terraform 错误的详细信息。这通常包括发生错误的 Terraform Cloud 工作区 URL，以及（可选）在需要更多上下文时提供的 Git 仓库 URL 和分支名称。
- **错误检索与上下文收集** – Amazon Bedrock agent 把这些详细信息转发给一个 action group，由该 action group 调用第一个 [AWS Lambda](https://aws.amazon.com/lambda) 函数（参见下面的 [Lambda 函数代码](https://github.com/aws-samples/sample-iac-troubleshooting-amazon-bedrock/blob/main/terraform-troubleshooting.py)）。该函数会调用另一个 Lambda 函数（参见下面的 [Lambda 函数代码](https://github.com/aws-samples/sample-iac-troubleshooting-amazon-bedrock/blob/main/fetch-error-code-details.py)），后者从指定的 Terraform Cloud 工作区检索最新的错误消息。如果提供了 Git 仓库 URL，它还会从该仓库检索相关的 Terraform 文件。这些上下文信息随后会被送回第一个 Lambda 函数。
- **错误分析与响应生成** – 随后，Lambda 函数会构造一个详细的 prompt，其中包含错误消息、仓库文件（如果可用）以及特定的用例指令。然后它使用 Amazon Bedrock 模型来分析错误，并生成排查步骤或联系特定团队的指引。
- **交互与用户引导** – agent 向用户显示生成的响应。对于大多数 Terraform 错误，响应中包含详细的排查步骤。对于与组织策略相关的特定情况（例如服务控制策略或基于资源的策略），响应会引导用户联系相应的团队，如安全团队或赋能团队。
- **持续改进** – 该解决方案可以不断更新新的特定用例和组织准则，确保排查建议与组织不断演进的基础设施和合规要求保持同步。例如： **SCP 或 IAM 策略违规** – 当开发者因 SCP 或严格的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）边界而遇到权限问题时予以引导，提供替代方案或升级路径。 **VPC 与网络限制** – 标记不符合要求的虚拟私有云（VPC）或子网配置（例如公有子网），并建议符合安全要求的调整。 **加密要求** – 检测 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）或 [Amazon Elastic Block Store](https://aws.amazon.com/ebs)（Amazon EBS）资源缺失或不正确的加密配置，并推荐符合合规标准的适当配置。

该解决方案简化了 Terraform 错误的解决过程，为开发者提供即时的上下文感知指引，同时确保敏感或复杂的问题被引导至相应的团队。通过利用 Amazon Bedrock Agents 的能力，它为在大型多账户 AWS 环境中管理 IaC 挑战提供了一种可扩展且智能的方法。

## 先决条件

要实施该解决方案，你需要具备以下条件：

- 了解 Amazon Bedrock Agents、[prompt 工程](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-prompt-engineering.html)、[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)、Lambda 函数和 IAM
- 一个 [AWS 账户](https://aws.amazon.com/resources/create-account/)，具备相应的 [IAM 权限](https://docs.aws.amazon.com/accounts/latest/reference/security-iam.html)，可在 Amazon Bedrock 中创建 agent 和知识库，并创建 Lambda 函数和 IAM 角色
- 为 Amazon Bedrock Agents 创建的[服务角色](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-permissions.html)
- 为 Amazon Bedrock 启用的[模型访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)
- 一个 GitLab 账户，其中包含一个仓库，并有一个用于访问该仓库的[个人访问令牌](https://docs.gitlab.com/ee/user/profile/personal_access_tokens.html)

## 创建 Amazon Bedrock agent

要[创建并配置 Amazon Bedrock agent](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-create.html)，请完成以下步骤：

- 在 Amazon Bedrock 控制台的导航窗格中，选择 **Agents**。
- 选择 **Create agent**。
- 提供 agent 的详细信息，包括 agent 名称和描述（可选）。
- 通过 IAM 服务角色授予 agent 访问 AWS 服务的权限。这样你的 agent 就能访问所需的服务，例如 [Lambda](https://aws.amazon.com/lambda/)。
- 从 Amazon Bedrock 中选择一个 FM（例如 Anthropic 的 Claude 3 Sonnet）。
- 要通过 Amazon Bedrock Agents 排查 Terraform 错误，请将以下指令附加到 agent。该指令确保 agent 从用户那里收集所需的输入，并执行 action group 以提供详细的排查步骤。

*“你是 Terraform 代码错误专家。向用户打招呼并询问 Terraform 工作区 URL、分支名称、代码仓库 URL。收到后，触发故障排查 action group。向用户提供排查步骤。”*

## 为 action group 配置 Lambda 函数

在配置好初始 agent 并向其添加上述指令后，你需要创建两个 Lambda 函数：

- 第一个 [Lambda 函数](https://docs.aws.amazon.com/lambda/latest/dg/getting-started.html)会被添加到 action group 中，由 Amazon Bedrock agent 调用，并随后通过 invoke 方法触发第二个 Lambda 函数。更多详细信息请参阅 [Lambda 函数代码](https://github.com/aws-samples/sample-iac-troubleshooting-amazon-bedrock/blob/main/terraform-troubleshooting.py)。请确保已设置 LAMBDA_2_FUNCTION_NAME 环境变量。
- 第二个 Lambda 函数将负责从 GitLab 获取 Terraform 工作区错误以及相关的 Terraform 代码。请参阅 [Lambda 函数代码](https://github.com/aws-samples/sample-iac-troubleshooting-amazon-bedrock/blob/main/fetch-error-code-details.py)。请确保已设置 TERRAFORM_API_URL、TERRAFORM_SECRET_NAME 和 VCS_SECRET_NAME 环境变量。

在检索到 Terraform 工作区错误和代码详细信息后，这些详细信息会被传回第一个 Lambda 函数，该函数会使用 Amazon Bedrock API 配合 FM，根据错误和代码信息生成并提供适当的排查步骤。

## 将 action group 添加到 Amazon Bedrock agent

请完成以下步骤，把 action group 添加到 Amazon Bedrock agent：

- 向 Amazon Bedrock agent [添加 action group](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-action-add.html)。
- 为 action group 指定一个描述性名称（例如 troubleshooting），并提供描述。这有助于明确该 action group 在工作流中的用途。
- 对于 **Action group type**，选择 **Define with function details**。

更多详细信息，请参阅[在 Amazon Bedrock 中为你的 agent 的 action group 定义函数详细信息](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-action-function.html)。

- 对于 **Action group invocation**，选择你先前创建的第一个 Lambda 函数。

当某个 action 被调用时，该函数会运行所需的业务逻辑。请确保选择第一个 Lambda 函数的正确版本。有关如何为 action group 配置 Lambda 函数的更多详细信息，请参阅[配置 Lambda 函数以发送 Amazon Bedrock agent 从用户处获取的信息](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-lambda.html)。

- 对于 **Action group function 1**，提供名称和描述。
- 添加以下参数。

| **名称** | **说明** | **类型** | **必填** |
| --- | --- | --- | --- |
| workspace_url | Terraform 工作区 URL | string | True |
| repo_url | 代码仓库 URL | string | True |
| branch_name | 代码仓库分支名称 | string | True |

## 结论

IaC 为管理云环境提供了灵活性，但排查代码错误可能非常耗时，在具有严格组织护栏的环境中尤其如此。本文演示了 Amazon Bedrock Agents 结合 action group 和生成式 AI 模型，如何简化并加速 Terraform 错误的解决，同时保持与环境安全和运营准则的合规性。

借助 Amazon Bedrock Agents 的能力，开发者可以获得针对 SCP 或 IAM 违规、VPC 限制以及加密策略等环境相关问题的、上下文感知的排查步骤。该解决方案会根据错误的上下文提供具体的指引，并针对需要进一步升级的问题将用户引导至相应的团队。这减少了花在 IaC 错误上的时间，提升了开发者生产力，并保持组织的合规性。
