# 使用 LangChain 为 Amazon Bedrock Knowledge Bases 实现动态元数据过滤

[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 提供全托管的[检索增强生成（RAG）](https://aws.amazon.com/what-is/retrieval-augmented-generation/)功能，可将大语言模型（LLM）连接到内部数据源。这是一种颇具成本效益的方法，可提升 LLM 的输出质量，使其在各种场景中保持相关、准确和有用。它还为开发者提供了对 LLM 输出更强的控制能力，包括加入引用和管理敏感信息。

Amazon Bedrock Knowledge Bases 具备[元数据过滤能力](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-knowledge-bases-now-supports-metadata-filtering-to-improve-retrieval-accuracy/)，可让你根据文档的特定属性精炼搜索结果，从而提高检索准确率和回答的相关性。这些元数据过滤器可以与常规的语义（或混合）相似度检索结合使用。改进文档检索结果有助于为每位用户生成个性化的回答。动态元数据过滤器让你能够根据变化的用户画像或用户输入的答复即时创建自定义查询，使检索到的文档只包含与你需求相关的信息。

在本文中，我们讨论如何在 Amazon Bedrock Knowledge Bases 中使用元数据过滤器。

## 解决方案概览

以下代码是 Amazon Bedrock Knowledge Bases 的一个元数据过滤器示例。逻辑运算符（如 AND 或 OR）可以嵌套，以组合其他逻辑运算符和过滤条件。更多信息请参阅 [Retrieve API](https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/bedrock-agent-runtime/client/retrieve.html)。

```
{
    "andAll": [
        {
            "equals": {
                "key": "desired_destination",
                "value": "<UNKNOWN>"  # This will be overwritten with appropriate values at runtime
            }
        },
        {
            "equals": {
                "key": "travelling_with_children",
                "value": "<UNKNOWN>"  # This will be overwritten with appropriate values at runtime
            }
        }
    ]
}
```

在我们的用例中，我们以一个旅行网站为例：用户回答几个关于其旅行偏好的问题（包括期望目的地、偏好活动和同行伙伴），随后系统检索相关文档。

本文只聚焦 RAG 中的检索部分。上游组件（包括文档摄取和查询格式化）我们以静态数据而非代码的形式提供。下游的生成组件不在本文讨论范围内。

## 创建动态过滤器

过滤器中的 `"value"` 字段需要在请求时更新。这意味着要覆盖 `retrieval_config` 对象，如下图所示。过滤器中的占位值会在运行时被用户数据覆盖。

![键的占位值如何被用户数据中的实际值更新的示意图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/11/kva.png)

由于 `retrieval_config` 对象是逻辑条件的嵌套层级结构（一棵树），你可以实现广度优先搜索，找出所有 `"value"` 字段值（其中 `"value"` 是键、`"<UNKNOWN>"` 是占位值），并用用户数据中对应的值替换它们。参见以下代码：

```
def setup_retrieval_config(inputs):

    # Make a copy because the filter is updated dynamically based on the user_data, this allows you to start from the default each time
    local_retrieval_config = copy.deepcopy(retrieval_config)

    updated_vector_search_config = replace_values(local_retrieval_config["vectorSearchConfiguration"], inputs["user_data"])
    local_retrieval_config["vectorSearchConfiguration"] = updated_vector_search_config

    return local_retrieval_config

def replace_values(vector_search_config: Dict, user_data: Dict):
    # Replace the value fields in the filter with the correct value according to the user_data
    # Uses breadth first search to find all of the value fields

    # Filter is not a required key, if you do not want any filters get rid of the key
    if "filter" in vector_search_config and not vector_search_config["filter"]:
        del vector_search_config["filter"]

    # Recursively traverse from the root
    elif 'filter' in vector_search_config:
        vector_search_config['filter'] = replace_values(vector_search_config['filter'], user_data)

    # At a node that is not the root
    else:
        for key, value in vector_search_config.items():
            if isinstance(value, dict):

                # At a leaf e.g. {"key": "age", "value": ""}}
                if 'key' in value and 'value' in value:

                    # Only overwrite value['value'] that are not unknown
                    if value['key'] in user_data and not (value["value"] == "unknown" or value["value"] == ["unknown"]):

                        # Primitive data type
                        if type(value["value"]) in [str, int, float, bool]:
                            value['value'] = user_data[value['key']]

                        # List data type
                        elif isinstance(value["value"], list):
                            value['value'] = [user_data[value['key']]]
                        else:
                            raise ValueError(f"Unsupported value['value'] type {type(value['value'])}")
                else:
                    vector_search_config[key] = replace_values(value, user_data)

            # Recurse on each item in the list
            elif isinstance(value, list):
                vector_search_config[key] = [replace_values(item, user_data) for item in value]
            else:
                raise ValueError(f"Unsupported value type {type(value)}")

    return vector_search_config
```

### 选项 1：每次都创建检索器

要动态定义 `retrieval_config` 参数，你可以每次都实例化 [AmazonKnowledgeBasesRetriever](https://python.langchain.com/v0.2/docs/integrations/retrievers/bedrock/)。这样可以融入更大的、以 [LangChain](https://www.langchain.com/) 为中心的代码库。参见以下代码：

```
def create_retrieval_chain() -> Runnable:
        """
        Creates a retrieval chain for the retriever.

        Returns:
            Runnable: The retrieval chain.
        """

        query = create_query_for_retrieval()

        def create_retriever(inputs):
            # This wrapper is necessary because if you return a callable object LangChain will automatically call it immediately, which is not the desired behavior
            # instead we want to call the retriever on the next step of the chain
            retriever_wrapper = {"retriever": AmazonKnowledgeBasesRetriever(knowledge_base_id=knowledge_base_id, retrieval_config=inputs["retrieval_config"])}
            return retriever_wrapper

        # Retrieval chain has three steps: (1) create the filter based off of the user data, (2) create the retriever, and (3) invoke the retriever
        retrieval_chain = (
            {
                "user_data" : itemgetter("user_data"),
                "retrieval_config" : lambda inputs: setup_retrieval_config(inputs)
            } |
            {
                "query" : query,
                "retriever" : lambda inputs: create_retriever(inputs)
            } |
            RunnableLambda(lambda inputs: inputs["retriever"]["retriever"].invoke(inputs["query"]))
        )
        return retrieval_chain
```

### 选项 2：直接访问底层 Boto3 API

[Boto3 API](https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/bedrock-agent-runtime/client/retrieve.html) 能够使用动态的 `retrieval_config` 直接检索。你可以通过访问 `AmazonKnowledgeBasesRetriever` 所包装的对象来利用这一点。这种方式略快一些，但不够 pythonic，因为它依赖 LangChain 的实现细节，而这些细节可能在不通知的情况下发生变化。这还需要额外的代码来把输出适配成 LangChain 检索器所需的格式。参见以下代码：

```
retriever = AmazonKnowledgeBasesRetriever(
    knowledge_base_id=knowledge_base_id,
    retrieval_config=retrieval_config
)

def create_retrieval_chain() -> Runnable:
        """
        Creates a retrieval chain for the retriever.

        Returns:
            Runnable: The retrieval chain.
        """

        query = create_query_for_retrieval()
        
        def retrieve_and_format(inputs):
            results = retriever.client.retrieve(
                retrievalQuery={"text": inputs["query"]}, 
                knowledgeBaseId=knowledge_base_id, 
                retrievalConfiguration=inputs["retrieval_config"]
            )
        
            documents = []
            for result in results["retrievalResults"]:
                metadata = {
                    "location": result["location"],
                    "source_metadata": result["metadata"],
                    "score": result["score"],
                }

                document = Document(
                    page_content=result["content"]["text"],
                    metadata=metadata
                )
                documents.append(document)
            
            return documents

        retrieval_chain = (
            {
                "query" : query,
                "retrieval_config" : lambda inputs: setup_retrieval_config(inputs)
            } |
            RunnableLambda(lambda inputs: retrieve_and_format(inputs))
            # RunnableLambda(lambda inputs: retriever.client.retrieve(retrievalQuery={"text": inputs["query"]}, knowledgeBaseId=knowledge_base_id, retrievalConfiguration=inputs["retrieval_config"]))
        )
        return retrieval_chain

retrieval_chain_2 = create_retrieval_chain()
```

```
retrieval_chains = [retrieval_chain_1, retrieval_chain_2]

    logger.info(retrieval_chain_id)
    # Loop through each filter options

        retrieval_config["vectorSearchConfiguration"]["filter"] = filter
        # Loop through each user data entry
        for user_entry in user_data:
            inputs = {
                    "user_data": user_entry,
                    "retrieval_config": retrieval_config

            # Run the retrieval chain with the current user entry
            try:
                result = retrieval_chain.invoke(inputs)
                # print(f"Result for user entry {user_entry['trip_id']}: {result}")
```

## 结论

通过 Knowledge Base 的元数据过滤启用动态过滤，能够按用户特定需求调整输出，从而增强 RAG 系统中的文档检索，显著提升 LLM 生成回答的相关性与准确性。在旅行网站的例子中，过滤器确保检索到的文档与用户偏好高度匹配。

这种方法也可应用于其他用例，例如客户支持、个性化推荐和内容策展，这些场景都需要对上下文敏感的信息检索。配置得当的过滤器对于在不同应用中保持准确性至关重要，这使该功能成为在多种场景下精炼 LLM 输出的强大工具。

请务必在你的应用中利用这一强大而灵活的解决方案。关于 Amazon Bedrock Knowledge Bases 中元数据的更多信息，请参阅 [Amazon Bedrock Knowledge Bases now supports metadata filtering to improve retrieval accuracy](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-knowledge-bases-now-supports-metadata-filtering-to-improve-retrieval-accuracy/)。另外，[Amazon Bedrock Knowledge Bases now provides autogenerated query filters](https://aws.amazon.com/about-aws/whats-new/2024/12/amazon-bedrock-knowledge-bases-auto-generated-query-filters-improved-retrieval/)。

## 安全最佳实践

对于 AWS IAM 策略：

- 遵循最小权限原则：明确写出 IAM 操作，只列出所需的权限，而不是使用通配符
- 为工作负载使用 IAM 角色的临时凭证
- 避免在 Action 元素中使用通配符（*），因为这会授予对特定 AWS 服务所有操作的访问权限
- 从 Resource 元素中移除通配符，并明确列出 IAM 实体应访问的具体资源
- 使用前仔细审查 AWS 托管策略；如果 AWS 托管策略授予的权限超出所需，可考虑改用客户托管策略

关于 AWS IAM 更详细的安全最佳实践，请参阅 [IAM 中的安全最佳实践](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html)。

对于 Amazon S3：

- 除非明确需要，否则阻止公开访问；通过使用 S3 Block Public Access 功能并实施适当的存储桶策略，确保 S3 存储桶不可公开访问
- 为静态数据启用加密（所有 S3 存储桶默认已加密），并使用 HTTPS/TLS 强制传输中的数据加密
- 通过 IAM 策略和存储桶策略仅授予所需的最小权限，并禁用 ACL（访问控制列表），因为对大多数现代用例已不再推荐使用 ACL
- 启用服务器访问日志、AWS CloudTrail，并使用 GuardDuty、Macie 和 IAM Access Analyzer 等 AWS 安全服务来监控和发现潜在安全问题

关于 Amazon S3 更详细的安全最佳实践，请参阅 [Amazon S3 安全最佳实践](https://docs.aws.amazon.com/AmazonS3/latest/userguide/security-best-practices.html)。

对于 Amazon Bedrock：

- 使用 IAM 角色和策略来控制对 Bedrock 资源和 API 的访问。
- 实施 VPC 终端节点，以便从你的 VPC 内部安全访问 Bedrock。
- 在使用 Bedrock 时对静态数据和传输中数据进行加密，以保护敏感信息。
- 使用 AWS CloudTrail 监控 Bedrock 的使用情况和访问模式，以满足审计需要。

关于 Amazon Bedrock 中安全性的更多信息，请参阅 [Amazon Bedrock 中的安全性](https://docs.aws.amazon.com/bedrock/latest/userguide/security.html)。

对于 Amazon SageMaker：

- 使用 IAM 角色控制对 SageMaker 资源的访问，并根据岗位职责限制权限。
- 使用 AWS KMS 密钥加密 SageMaker notebook、训练作业和端点，以保护数据。
- 为 SageMaker 资源配置 VPC，以限制网络访问并增强安全性。
- 使用 SageMaker 私有端点访问 API，无需经过公共互联网。
