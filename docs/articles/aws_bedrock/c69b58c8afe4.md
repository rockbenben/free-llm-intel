# 通过 AWS Batch 的 SageMaker 培训作业配额管理跨团队借出和借用资源

随着对 Amazon SageMaker 训练作业的 [AWS Batch](https://aws.amazon.com/batch/) 支持的推出，客户获得了一种新的完全托管方式来排队、安排和重试机器学习 (ML) 训练工作负载，而无需构建自己的基础设施。相反，他们使用 AWS Batch 的排队和调度功能。随着组织扩展其人工智能和机器学习 (AI/ML) 运营并加入更多团队，协调对共享图形处理单元 (GPU) 容量的访问可能会给管理员带来额外的通信、协调和配置开销。这种开销包括设置单独的队列、调整容量限制以及仔细编排正确的工作负载以在正确的时间获取正确的资源。 AWS Batch 的核心价值主张是帮助客户提高计算利用率，并且随着培训环境的发展，利用现有容量做更多事情的机会也在增加。

从管理多团队培训环境的客户开始，我们听到了一个一致的要求：为我们提供一种方法来定义每个团队或项目的分配，自动共享闲置容量，并首先运行我们最高优先级的工作负载。此请求促使我们构建了[配额管理](https://docs.aws.amazon.com/batch/latest/userguide/quota-management.html)，这是 AWS Batch 的一种新调度功能。管理员可以使用它将计算容量划分为按团队、项目或工作负载组织的配额份额。每个配额份额都使用可配置的资源共享策略，最大限度地提高 GPU 利用率，同时在最重要的时候尊重每个团队的分配。

本文介绍了配额管理的工作原理，包括如何通过借贷策略配置配额份额、为优先工作负载设置份额内抢占，以及开始使用 SageMaker Python SDK。

## 配额份额及抢占

管理员可以通过为单独的实体（例如单个团队或项目）定义配额份额来分配和共享受限的 GPU 资源。每个配额共享包括计算配额（容量限制）和空闲计算的资源共享策略。这些策略确定是否保留空闲计算直到作业到达（“RESERVE”）、借给具有可用工作的其他配额共享（“LEND”），或者在空闲时借出并在共享有可能受益的工作时借用（“LEND_AND_BORROW”）。

配额共享作为虚拟队列运行，分层嵌套在关联的作业队列中。为作业队列安排作业时，AWS Batch 在迭代关联的配额份额时会优先考虑低于其容量限制的配额份额。如果作业到达已借出其容量的配额共享，则 AWS Batch 会执行跨共享抢占。这会回收贷款配额份额的资源，因此管理员无需追踪职位借用能力并自行终止它们。如果作业到达的配额份额达到或超过其容量限制，AWS Batch 将检查是否有可用容量可从另一个配额份额借用。如果是这样，工作负载可以使用空闲容量运行。

您可以在配置配额共享时启用基于优先级的共享内抢占。当作业到达借出配额份额时，交叉共享抢占会回收借出的容量，而共享抢占会抢占处于 SCHEDULED、STARTING 或 RUNNING 状态的较低优先级作业。这使得队列前面的优先级较高的作业能够更快地开始运行。

## 配置配额管理资源

使用新的配额管理功能需要创建一个包含“quotaSharePolicy”的[调度策略](https://docs.aws.amazon.com/batch/latest/APIReference/API_CreateSchedulingPolicy.html)、一个根据特定实例指定其容量限制的[服务环境](https://docs.aws.amazon.com/batch/latest/APIReference/API_CreateServiceEnvironment.html)，以及[a连接到两者的 SageMaker Training 作业队列](https://docs.aws.amazon.com/batch/latest/APIReference/API_CreateJobQueue.html)。之后，您可以将配额份额关联到作业队列。用户指南包含用于[配置配额管理资源](https://docs.aws.amazon.com/batch/latest/userguide/create-quota-management-resources.html) 和[配额份额](https://docs.aws.amazon.com/batch/latest/userguide/create-quota-shares.html) 的 AWS 命令​​行界面 (AWS CLI) 和控制台示例。与 SageMaker Python SDK v3 中的 [aws_batch](https://github.com/aws/sagemaker-python-sdk/tree/master/sagemaker-train/src/sagemaker/train/aws_batch) 模块集成的配额管理端到端示例包含在 [示例中]笔记本](https://github.com/aws/sagemaker-python-sdk/blob/master/v3-examples/training-examples/aws_batch/sm-training-queues_quota-management.ipynb)。在此示例中，我们逐步完成总结关键组件的代码片段，并使用笔记本中的辅助函数来创建调度策略、服务环境、作业队列和三个配额共享。

此处配置的三个配额份额代表三个不同的项目。每个都有相同的容量限制集：单个“ml.g5.xlarge”实例。 QS1 配额份额代表后台作业。对于此项目，您希望首先运行最重要的后台作业，并借用尽可能多的可用闲置容量。在此配额份额内，没有紧急作业，并且抢占是可以接受的，因为所有作业都使用检查点。此配额共享使用“LEND_AND_BORROW”资源共享策略，并开启了共享内抢占。同一配额份额内的较高优先级作业可以抢占正在运行的较低优先级作业。
```
from sagemaker.train.aws_batch.boto_client import get_batch_boto_client
from utils.aws_batch_resource_management import AwsBatchResourceManager, QuotaShareConfig, create_quota_management_resources

INSTANCE_TYPE = "ml.g5.xlarge"

# Create SchedulingPolicy, ServiceEnvironment, JobQueue, and QuotaShares
resource_manager = AwsBatchResourceManager(get_batch_boto_client())
qs1 = QuotaShareConfig(
    name="QS1",
    capacity_unit=INSTANCE_TYPE,
    max_capacity=1,
    in_share_preemption=True,
    sharing_strategy="LEND_AND_BORROW",
    borrow_limit=200
)
```
QS2 代表中等优先级工作负载。选择此配置的团队宁愿等待容量可用，也不愿忍受额外的抢占。这些抢占来自于借用容量的回收或由于更高优先级的作业提交而导致的共享抢占。这适用于较短的作业，或者当大多数提交的作业具有相似的优先级时。配额份额仍然受益于在工作派遣时考虑工作优先级。提交的作业会触发 AWS Batch 回收运行作业所需的任何借出容量。
```
qs2 = QuotaShareConfig(
    name="QS2",
    capacity_unit=INSTANCE_TYPE,
    max_capacity=1,
    in_share_preemption=False,
    sharing_strategy="LEND"
)
```
QS3 代表需要尽快启动且中断最少的工作负载。它配置为保留容量，既不借出也不借入其他配额份额。它不会经历交叉共享抢占，因为它的工作负载不会超出其容量限制。通过关闭共享抢占，只要容量限制不变，提交到此配额份额的工作负载就不会被 AWS Batch 抢占。
```
qs3 = QuotaShareConfig(
    name="QS3",
    capacity_unit=INSTANCE_TYPE,
    max_capacity=1,
    in_share_preemption=False,
    sharing_strategy="RESERVE"
)
```
这些配额共享配置是示例笔记本中“create_quota_management_resources”函数的输入，该函数还使用所选常量名称配置相应的调度策略、服务环境和作业队列。
```
SCHEDULING_POLICY_NAME = "my-qm-scheduling-policy"
JOB_QUEUE_NAME = "my-sm-training-qm-jq"
SERVICE_ENVIRONMENT_NAME = "my-sm-training-qm-se"

resources = create_quota_management_resources(
    resource_manager=resource_manager,
    scheduling_policy_name=SCHEDULING_POLICY_NAME,
    job_queue_name=JOB_QUEUE_NAME,
    service_environment_name=SERVICE_ENVIRONMENT_NAME,
    capacity_unit=INSTANCE_TYPE,
    max_capacity=3,
    quota_share_configs=[qs1, qs2, qs3]
)
```
## 将 SageMaker 培训作业提交到 QS1

SageMaker Python SDK 中的 [aws_batch](https://github.com/aws/sagemaker-python-sdk/tree/master/sagemaker-train/src/sagemaker/train/aws_batch) 模块已进行扩展，允许以编程方式将 SageMaker Training 作业提交到支持配额管理的 AWS Batch 作业队列。为了演示这些新功能，我们使用提交到作业队列的 Hello World“ModelTrainer”。以下代码片段根据所选区域和实例类型标识要使用的图像 URI。
```
import logging

logging.basicConfig(
    level=logging.INFO, format="%(asctime)s - %(name)s - %(levelname)s - %(message)s"
)
logging.getLogger("botocore.client").setLevel(level=logging.WARN)
logger = logging.getLogger(__name__)

from sagemaker.core.helper.session_helper import Session
from sagemaker.core import image_uris

session = Session()

image_uri = image_uris.retrieve(
    framework="pytorch",
    region=session.boto_session.region_name,
    version="2.5",
    instance_type=INSTANCE_TYPE,
    image_scope="training",
)
```
我们在基本的 hello world 模型训练器示例中使用此图像 URI：
```
from sagemaker.train.model_trainer import ModelTrainer
from sagemaker.train.configs import SourceCode, Compute, StoppingCondition

TRAINING_JOB_NAME = "hello-world-simple-job"
MAX_RUN_TIME = 300

source_code = SourceCode(command="echo 'Hello World'")

model_trainer = ModelTrainer(
    training_image=image_uri,
    source_code=source_code,
    base_job_name=TRAINING_JOB_NAME,
    compute=Compute(instance_type=INSTANCE_TYPE, instance_count=INSTANCE_COUNT),
    stopping_condition=StoppingCondition(max_runtime_in_seconds=MAX_RUN_TIME),
)
```
要在 SageMaker Python SDK 中使用作业队列，请向“aws_batch”模块中的“TrainingQueue”构造函数提供队列名称。
```
from sagemaker.train.aws_batch.training_queue import TrainingQueue, TrainingQueuedJob

# Construct the queue object using the SageMaker Python SDK
queue = TrainingQueue(JOB_QUEUE_NAME)
logger.info(f"Using queue: {queue.queue_name}")
```
然后，我们可以向 QS1（我们的后台作业配额份额）提交三个作业。第一个提交的作业具有最高优先级，其次是中等优先级作业，然后是最低优先级作业。由于 QS1 或 QS2 当前没有任何运行，因此应该启动两个实例的作业，对应于提交的第一个和第二个作业（因为它们具有最高的相对优先级）。请注意，因为这只是一个 hello world 训练作业，所以它不需要数据，但通常“ModelTrainer”需要数据来执行训练。
```
from utils.aws_batch_resource_management import JobStatus, await_jobs, list_jobs_by_quota_share

# Submit three jobs to QS1, all with different priorities to guarantee dispatch ordering.
qs1_job_high: TrainingQueuedJob = queue.submit(job_name="qs1_job_high", training_job=model_trainer, quota_share_name=qs1.name, priority=3, inputs=None)
qs1_job_med: TrainingQueuedJob = queue.submit(job_name="qs1_job_med", training_job=model_trainer, quota_share_name=qs1.name, priority=2, inputs=None)
qs1_job_low: TrainingQueuedJob = queue.submit(job_name="qs1_job_low", training_job=model_trainer, quota_share_name=qs1.name, priority=1, inputs=None)

logger.info(f"Submitted jobs: {qs1_job_high.job_name}, {qs1_job_med.job_name}, {qs1_job_low.job_name}")
logger.info(f"Waiting for jobs to transition...")

# qs1_job_high is dispatched first using capacity from QS1, and qs1_job_med is dispatched second borrowing idle capacity from QS2
await_jobs([([qs1_job_high, qs1_job_med], JobStatus.dispatched() | JobStatus.terminal())])
list_jobs_by_quota_share(queue, [qs1.name, qs2.name, qs3.name], JobStatus.active())
```
## 向 QS2 提交作业会触发交叉共享抢占以回收借出的容量

拥有 QS2 的团队可能会发现他们有工作需要执行，并向 QS2 提交作业。这样做会触发从 QS1 抢回容量，QS1 当前正在借用该容量（QS3 的容量未配置为借用）。这是一种交叉共享抢占。
```
# When a job is submitted to QS2, it will preempt its capacity back from QS1
qs2_job_1: TrainingQueuedJob = queue.submit(job_name="qs2_job_1", training_job=model_trainer, quota_share_name=qs2.name, priority=1, inputs=None)

logger.info(f"Submitted job {qs2_job_1.job_name}")
logger.info(f"Waiting for jobs to transition...")

await_jobs([
    ([qs2_job_1], JobStatus.dispatched() | JobStatus.terminal()),
    ([qs1_job_med], {JobStatus.RUNNABLE}) # Lowest priority QS1 job will be preempted
])
list_jobs_by_quota_share(queue, [qs1.name, qs2.name, qs3.name], JobStatus.active())
```
## 在 QS1 中更新作业优先级会触发共享抢占以运行最高优先级作业

如果科学家意识到 QS1 中仍处于 RUNNABLE 状态的“qs1_job_low”作业由于优先级更改而需要立即开始运行，他们可以使用新的 [UpdateServiceJob](https://docs.aws.amazon.com/batch/latest/APIReference/API_UpdateServiceJob.html) API 来提高 QS1 中已提交作业的优先级。由于没有可用容量可供借用，因此这会启动共享抢占，以便当前正在运行的作业被抢占，并且“qs1_job_low”可以开始。
```
# Updating qs1_job_low to be the highest priority job in QS1
qs1_job_low.update(scheduling_priority=4)

logger.info(f"Updated job {qs1_job_low.job_name} to increase its priority")
logger.info(f"Waiting for jobs to transition...")

await_jobs([
    ([qs1_job_low], JobStatus.dispatched() | JobStatus.terminal()),
    ([qs1_job_high], {JobStatus.RUNNABLE}) # High priority job will preempt lower priority jobs within the same quota share
])
list_jobs_by_quota_share(queue, [qs1.name, qs2.name, qs3.name], JobStatus.active())
```
