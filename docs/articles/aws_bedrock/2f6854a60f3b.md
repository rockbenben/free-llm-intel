# 在 AWS Quick 中运营您的整个销售业务

大多数卖家不需要另一种人工智能产品来学习。他们需要将已经使用的工具和信息整合在一起，以便他们能够了解业务中发生的情况并采取行动。

AWS Quick 和亚马逊销售合作伙伴插件一起完成此任务。 Quick 将亚马逊卖家的销售数据、库存信号和市场情报整合到一个地方，问题变成答案，答案变成行动。它了解卖家的完整业务背景，因此卖家无需在每次对话中重新解释他们的目录、利润或竞争格局。它建立在 AWS 之上，亚马逊也用同样的基础设施来运行自己的市场。

在 2026 年 9 月 23 日的 Amazon Accelerate 上，亚马逊宣布推出销售合作伙伴插件，并在 AWS Quick 中推出测试版。这篇文章介绍了推出的内容、如何申请免费的 AWS Quick 优惠以及日常体验。它还涵盖了卖家使用技能和连接器时如何发挥作用。

# 1. 为什么 Quick 适合亚马逊卖家

Quick 具有四个特点，适合亚马逊卖家已有的工作方式：它了解业务、超越亚马逊商店、将数据转化为决策，以及保护卖家已经信任的基础设施上的卖家数据。

## Quick 了解您的业务，而不仅仅是您的提示

Quick 和销售合作伙伴插件连接到卖家的库存源、销售数据和运营文档。通过这些，Quick 对目录结构、利润阈值、季节性和竞争地位有了生动的了解。要求 Quick 审核您第四季度的 ASIN，它会返回基于卖家的实际利润数据、历史转化率和库存可用性的排名推荐。卖家使用它的次数越多，它的推荐就越清晰。

## Quick 不仅仅停留在您的亚马逊商店

卖家的业务涉及许多工具：另一个渠道上的店面、电子邮件收件箱、会计系统、电子表格、供应商门户。快速连接到卖方已经工作的地方，并从整个操作中提取背景信息。它是一个业务助手，恰好对亚马逊有深入的了解，所以卖家是整体增长的，而不是单独在一个渠道上增长的。

## 它将数据转化为您可以采取行动的决策

卖家并不缺乏数据。他们拥有品牌分析、搜索查询性能、广告报告、库存健康状况和列表质量数据。问题是将这些信号转化为一项明确的行动。快速进行合成。它观察变化，标记重要事项，进行分析，并提出决策及其背后的证据。

## 您的数据在您已销售的基础设施上受到保护

Quick 在 AWS 上运行，不使用卖家数据来训练模型，不用于一般改进，也不用于其他任何目的。卖家数据保留在卖家的环境中，永远不会通知其他任何人的模型。对于已经在亚马逊市场上运营的卖家来说，没有新的安全状况需要评估。基础设施与目前保护卖家账户的基础设施相同，并且卖家选择的 AWS 区域负责管理数据的存储位置。

# 亚马逊销售合作伙伴插件

销售合作伙伴插件将 AWS Quick 直接连接到实时卖家中心数据。使用卖家中心帐户登录一次后，该插件可以通过对话方式访问产品列表、库存和销售数据，实时提取而不是手​​动导出和重新组装。它像应用程序一样安装，无需编码。它配备了精选的亚马逊技能，并与亚马逊广告 MCP 配合使用，因此广告活动绩效和支出与销售数据并存。该插件在美国商店处于测试阶段。

# 3. 体验是什么样的

连接插件后，工作将在对话中进行。您用简单的语言询问，Quick 会提取相关的实时数据，然后返回答案和建议的下一步。您无需检查仪表板、导出报告并在电子表格中对其进行协调，而是可以在一个地方从问题转移到操作的答案。在发送任何内容之前，您先查看 Quick 建议的内容。

# 4. 卖家可以构建的两个用例

在加速研讨会上，我们让卖家在几分钟内通过简单的语言描述实时构建真正的代理。快速将描述转化为工作代理，然后卖方在对话中对其进行完善。

## 用例 A：库存启动准备

卖家正在亚马逊上投放新产品，并希望总到岸成本最低。代理读取供应商数据，并根据入库成本、存储和销售速度权衡每个 SKU 的履行选项。它会遍历放置选择并返回卖家选择的输出：运输计划、成本比较或组合包。它在创造任何东西之前解释其推理并确认。

图 4：库存启动准备代理比较每个因素的 FBA 和 AWD 履行情况并推荐混合方法

## 用例 B：发布后的产品健康状况

发布后，代理通过销售合作伙伴插件读取四个信号系列：列表健康状况、库存、销售和流量。它将他们联系起来以查找原因，而不仅仅是报告数字。销量持平但客流量良好表明存在转化问题。销量持平且流量下降表明了可发现性。良好的转换与下降的单位指向供应。它返回每个 ASIN 的健康摘要、带有证据的诊断以及排名修复列表，标记任何低置信度呼叫。

图 5：发布后产品健康代理的每周摘要，以及每周的销售证据

一个诚实的限制，诚实地处理：销售数据不包括商品成本，因此代理商在亚马逊收费后报告利润并以此方式标记。当卖家想要真实的毛利率时，代理商会要求他们将成本数据纳入谈话中。它从来不会像毛利率一样呈现费用后利润。

# 5. 实际运用的技能和连接器

销售合作伙伴插件和亚马逊广告 MCP 将亚马逊销售和广告数据引入 Quick。 AWS Quick 中的其他连接器引入了按角色组织的业务运营的其余部分。其中包括第二个店面（来自另一个渠道的订单和产品）、电子邮件和日历（起草供应商说明、跟踪应付款）、团队消息传递（共享更新）以及会计和库存系统（销售数据不包含成本和库存背景）。由于各个部分是组合在一起的，因此卖家可以提出一个涉及亚马逊数据及其相关工具的问题。
