# 利用 Amazon Bedrock 能力增强地理空间分析与 GIS 工作流

随着数据日益丰富、信息系统日趋复杂，利益相关方需要能够揭示高质量洞见的解决方案。将新兴技术应用到地理空间领域，为打造具有变革性的用户体验、为用户和组织提供直观的工作流带来了独特机遇，帮助他们履行自身的使命与职责。

在本文中，我们探讨如何将现有系统与 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 集成，以创建新的工作流，释放效率与洞见。这种集成能让技术、非技术以及领导角色同等受益。

## 地理空间数据简介

地理空间数据与相对于地球的位置相关（纬度、经度、海拔）。数值型和结构化的地理空间数据格式可分类如下：

- **矢量数据（Vector data）** – 地理要素，例如道路、建筑或城市边界，以点、线或多边形表示
- **栅格数据（Raster data）** – 地理信息，例如卫星影像、温度或高程图，以网格单元表示
- **表格数据（Tabular data）** – 基于位置的数据，例如描述和指标（平均降雨量、人口、所有权），以行列形式的表格表示

地理空间数据源还可能包含自然语言文本元素，用以描述非结构化属性，以及用于对相关记录进行分类和描述的元数据。地理空间信息系统（GIS）提供了存储、分析和展示地理空间信息的方式。在 GIS 应用中，这些信息通常与地图一同呈现，用以可视化街道、建筑和植被。

## LLM 与 Amazon Bedrock

大语言模型（LLM）是基础模型（FM）的一个子集，它通过称为*生成*（generation）的过程，把输入（通常是文本或图像，取决于模型模态）转换为输出（通常是文本）。Amazon Bedrock 是一项全面、安全且灵活的服务，用于构建[生成式 AI](https://aws.amazon.com/generative-ai/) 应用和 agent。

LLM 可胜任许多涉及自然语言的通用任务。一些常见的 LLM 用例包括：

- **摘要（Summarization）** – 使用模型对文本或文档进行摘要。
- **问答（Q&A）** – 使用模型回答问题，依据的是训练时或推理时提供的上下文中的数据或事实，后者使用检索增强生成（RAG）。
- **推理（Reasoning）** – 使用模型提供思维链推理，辅助人类进行决策和假设评估。
- **数据生成（Data generation）** – 使用模型生成合成数据，用于测试仿真或假设场景。
- **内容生成（Content generation）** – 使用模型，基于从 Amazon Bedrock 知识库或用户 prompt 中获得的洞见起草报告。
- **AI agent 与工具编排（AI agent and tool orchestration）** – 使用模型规划对其他系统和流程的调用。在 agent 调用其他系统之后，agent 的输出又可以作为上下文，供 LLM 进一步生成。

GIS 可以实现这些能力，从而创造价值并改善用户体验。收益包括：

- **实时决策（Live decision-making）** – 利用实时洞见支持即时决策，例如应急响应协调和交通管理
- **研究与分析（Research and analysis）** – 由人或系统识别出的深入分析，例如趋势分析、模式与关系、环境监测
- **规划（Planning）** – 利用研究与分析进行有依据的长期决策，例如基础设施建设、资源配置和环境监管

用 LLM 能力增强 GIS 及其工作流，能让数据分析和探索更简单、发现新洞见并改进决策。Amazon Bedrock 提供了托管和调用模型的方式，也能把 AI 模型与周边基础设施集成，我们将在本文中详细说明。

## 通过 RAG 与 agentic 工作流将 GIS 与 AI 结合

LLM 使用海量通用信息训练，以发现语言产出方式中的模式。为提升 LLM 在特定用例上的表现，人们提出了 RAG 和 agentic 工作流等方法。地理空间用例中检索政策与通用知识可用 RAG 完成，而计算和分析 GIS 数据则需要 agentic 工作流。本节我们结合地理空间用例，展开说明 RAG 与 agentic 工作流。

### 检索增强生成

借助 RAG，你可以在调用模型时动态注入来自知识库的上下文信息。

RAG 用来自知识库（文档集合）的数据补充用户提供的 prompt。Amazon Bedrock 为 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）和 SharePoint 等数据源提供托管知识库，因此当你的 AI 助手为用户生成回复时，你可以提供补充信息，例如城市发展规划、情报报告或政策法规。

知识库非常适合以自然语言存储信息的非结构化文档。当 AI 模型用源自 RAG 的信息回复用户时，它可以提供对来源材料的引用与出处。下图展示了这些系统如何连接在一起。

由于地理空间数据通常是结构化的并且存放在 GIS 中，你可以用工具和 agent 而不是知识库把 GIS 连接到 LLM。

### 工具与 agent（用于控制 UI 和系统）

许多 LLM，例如 Amazon Bedrock 上的 [Anthropic 的 Claude](https://aws.amazon.com/bedrock/claude/)，都可以提供可用工具的描述，让你的 AI 模型生成文本来调用外部流程。这些流程可能检索实时信息，例如某地当前的天气或查询结构化数据存储，也可能控制外部系统，例如启动工作流或往地图上添加图层。你可能希望通过工具与 LLM 集成的一些常见地理空间功能包括：

- 执行数学计算，例如坐标之间的距离、按数值筛选数据集或计算派生字段
- 从预测分析模型中提取信息
- 在结构化数据存储中查找兴趣点
- 在非结构化数据存储中搜索内容和元数据
- 检索实时地理空间数据，例如交通、路线或预计到达时间
- 可视化距离、兴趣点或路径
- 提交工作产出，例如分析报告
- 启动工作流，例如订购物资或调整供应链

工具通常以 [AWS Lambda](https://aws.amazon.com/lambda/) 函数实现。Lambda 无需运行服务器的复杂性和开销即可运行代码。它负责基础设施管理，从而实现更快的开发、更好的性能、更强的安全性和更低的成本。

## 转换地理空间数据

使用以下代码转换地理空间数据：

```
INPUT_FILE="california-counties.json"
OUTPUT_FILE="california-counties.csv"

# Create CSV header
echo "OBJECTID,AREA,PERIMETER,CO06_D00_,CO06_D00_I,STATE,COUNTY,NAME,LSAD,LSAD_TRANS,Shape_Length,Shape_Area,WKT" > "$OUTPUT_FILE"

# Function to convert ESRI rings to WKT POLYGON format
esri_to_wkt() {
    local rings=$1
    
    # Extract the first ring (exterior ring)
    local exterior_ring=$(echo "$rings" | jq -c '.[0]')
    
    if [ "$exterior_ring" = "null" ] || [ -z "$exterior_ring" ]; then
        echo "POLYGON EMPTY"
        return
    fi
    
    # Start building the WKT string
    local wkt="POLYGON (("
    
    # Process each coordinate pair in the ring
    local coords=$(echo "$exterior_ring" | jq -r '.[] | "\(.[0]) \(.[1])"')
    local first_coord=""
    local result=""
    
    while IFS= read -r coord; do
        if [ -z "$result" ]; then
            result="$coord"
            first_coord="$coord"
        else
            result="$result, $coord"
        fi
    done <<< "$coords"
    
    # Close the ring by adding the first coordinate again if needed
    if [ "$first_coord" != "$(echo "$coords" | tail -1)" ]; then
        result="$result, $first_coord"
    fi
    
    wkt="${wkt}${result}))"
    echo "$wkt"
}

# Process each feature in the JSON file
jq -c '.features[]' "$INPUT_FILE" | while read -r feature; do
    # Extract attributes
    OBJECTID=$(echo "$feature" | jq -r '.attributes.OBJECTID // empty')
    AREA=$(echo "$feature" | jq -r '.attributes.AREA // empty')
    PERIMETER=$(echo "$feature" | jq -r '.attributes.PERIMETER // empty')
    CO06_D00_=$(echo "$feature" | jq -r '.attributes.CO06_D00_ // empty')
    CO06_D00_I=$(echo "$feature" | jq -r '.attributes.CO06_D00_I // empty')
    STATE=$(echo "$feature" | jq -r '.attributes.STATE // empty')
    COUNTY=$(echo "$feature" | jq -r '.attributes.COUNTY // empty')
    NAME=$(echo "$feature" | jq -r '.attributes.NAME // empty')
    LSAD=$(echo "$feature" | jq -r '.attributes.LSAD // empty')
    LSAD_TRANS=$(echo "$feature" | jq -r '.attributes.LSAD_TRANS // empty')
    Shape_Length=$(echo "$feature" | jq -r '.attributes.Shape_Length // empty')
    Shape_Area=$(echo "$feature" | jq -r '.attributes.Shape_Area // empty')
    
    # Extract geometry and convert to WKT
    if echo "$feature" | jq -e '.geometry.rings' > /dev/null 2>&1; then
        rings=$(echo "$feature" | jq -c '.geometry.rings')
        WKT=$(esri_to_wkt "$rings")
    else
        WKT="POLYGON EMPTY"
    fi
    
    # Escape any commas in the fields
    NAME=$(echo "$NAME" | sed 's/,/\\,/g')
    LSAD=$(echo "$LSAD" | sed 's/,/\\,/g')
    LSAD_TRANS=$(echo "$LSAD_TRANS" | sed 's/,/\\,/g')
    
     # Write to CSV - wrap WKT field in quotes
    echo "$OBJECTID,$AREA,$PERIMETER,$CO06_D00_,$CO06_D00_I,$STATE,$COUNTY,$NAME,$LSAD,$LSAD_TRANS,$Shape_Length,$Shape_Area,\"$WKT\"" >> "$OUTPUT_FILE"
done

echo "Conversion complete. Output saved to $OUTPUT_FILE"

# Upload data files to S3
aws s3 cp earthquakes.csv s3://$DATA_BUCKET/earthquakes/
aws s3 cp california-counties.csv s3://$DATA_BUCKET/counties/
```

这段代码执行以下操作来转换地理空间数据格式：

- 将 ESRI JSON 转换为 WKT 格式
- 将县边界处理为 CSV 格式
- 为 Amazon Redshift 保留空间信息

### 示例 2：生成报告草稿

接下来，我们输入 prompt“写一份报告，说明如何利用各类区域及相关住房数据来规划新的住房开发，以满足高需求。”

本例展示了 LLM 在 prompt 模板、RAG 和摘要方面的能力。

### 示例 3：在地图上显示地点

### 示例 4：把 UI 作为上下文

LLM 根据所选标记理解“这里”的上下文，执行检索以查看土地开发政策，然后用简单的自然语言回复用户：“不能，原因如下……”

## 结论

LLM 与 GIS 的集成创造了直观的系统，帮助不同技术水平的用户通过自然语言交互完成复杂的空间分析。借助 RAG 和基于 agent 的工作流，组织可以在保持数据准确性的同时，把 AI 模型无缝接入现有的知识库和结构化数据系统。Amazon Bedrock 通过为模型调用、知识检索和系统控制提供稳健的平台，促进了 AI 与 GIS 技术的融合，最终改变用户可视化、分析和与地理数据交互的方式。

如需进一步探索，[Earth on AWS](https://aws.amazon.com/earth/) 提供了视频和文章，你可以借此了解 AWS 如何帮助在云上构建 GIS 应用。
