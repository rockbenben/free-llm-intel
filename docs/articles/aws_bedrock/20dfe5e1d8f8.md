# 使用 Amazon Bedrock inline agents 构建动态的、基于角色的 AI agent

AI agent 的势头持续增强，企业正借助生成式 AI 的能力重塑客户体验并自动化复杂工作流。我们看到 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 被应用于投资研究、保险理赔处理、根因分析、广告活动等众多场景。Agent 利用基础模型（FM）的推理能力，把用户请求的任务拆解为多个步骤。它们依据开发者提供的指令创建编排计划，并通过安全地调用公司 API、使用检索增强生成（RAG）访问知识库来执行该计划，从而准确处理用户的请求。

尽管各组织已经认识到以托管资源方式定义、配置和测试 agent 所带来的好处，我们也越来越多地看到对另一种更动态的调用 agent 的方式的需求。组织需要能够即时调整的方案——无论是测试新方法、响应变化的业务规则，还是为不同客户定制方案。这正是 Amazon Bedrock Agents 中新增的 [inline agents](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-create-inline.html) 能力带来变革性影响的地方。它允许你在运行时动态调整 agent 的行为，方式是修改其指令、工具、guardrail、知识库、prompt，甚至它使用的 FM——而无需重新部署应用。

在本文中，我们探讨如何使用 Amazon Bedrock inline agents 构建一个应用，并演示单个 AI 助手如何根据用户角色动态调整其能力。

## Amazon Bedrock Agents 中的 inline agents

inline agents 带来的这种运行时灵活性开启了一些强大的新可能，例如：

- **快速原型验证** – inline agents 最大限度压缩了传统上修改 agent 配置所需的创建／更新／准备（create/update/prepare）周期，减少了耗时。开发者可以即时测试模型、工具和知识库的不同组合，大幅加快开发进程。
- **A/B 测试与实验** – 数据科学团队可以在受控环境中系统地评估不同的模型—工具组合、测量性能指标并分析回答模式。这种实证方法使团队能够在上生产前对各类配置做定量比较。
- **基于订阅层级的个性化** – 软件公司可以根据每个客户的订阅等级调整功能，为高级版用户提供更先进的工具。
- **基于画像的数据源集成** – 机构可以根据用户画像调整内容的复杂度和语气，通过即时更换与 agent 关联的知识库，提供契合其画像的解释与资源。
- **动态工具选择** – 开发者可以构建包含数百个 API 的应用，通过为给定请求动态挑选一小部分 API 供 agent 考虑，从而快速、准确地完成任务。这对需要多租户扩展的大型软件即服务（SaaS）平台尤其有用。

inline agents 扩展了你使用 Amazon Bedrock Agents 构建和部署 agentic 方案的选择。对于需要以托管、带版本的方式管理 agent 资源，且配置预先确定并经过测试（特定模型、指令、工具等）的工作负载，开发者可以继续对用 CreateAgent 创建的资源使用 InvokeAgent。对于每次调用 agent 都需要在运行时动态改变行为的工作负载，你可以使用新的 [InvokeInlineAgent API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_InvokeInlineAgent.html)。无论采用哪种方式，你的 agent 都具备安全性与可扩展性，并提供可配置的 guardrail、灵活的模型推理选项、对知识库的原生访问、代码解释、会话记忆等能力。

## 解决方案概述

我们的 HR 助手示例展示了如何使用 Amazon Bedrock Agents 中新的 inline agent 能力，构建一个能适配不同用户角色的单一 AI 助手。当用户与助手交互时，助手会根据用户的角色及其具体选择，动态配置 agent 的能力（例如模型、指令、知识库、action group 和 guardrail）。这种做法构建出一个实时调整功能的灵活系统，比为每个用户角色或工具组合分别创建 agent 更高效。该 HR 助手示例的完整代码可在我们的 [GitHub 仓库](https://github.com/awslabs/amazon-bedrock-agent-samples/tree/main/examples/agents_ux/inline-agent-hr-assistant)中找到。

这种动态工具选择带来个性化的体验。当一名没有直接下属的员工登录时，会看到一组基于其角色可用的工具。他们可以从申请休假、使用知识库查询公司政策、使用代码解释器做数据分析，或提交费用报告等选项中选择。随后，inline agent 助手只会用这些选中的工具进行配置，从而帮助员工完成其选择的任务。在真实场景中，用户不需要做这些选择，因为应用会替他们决定，并在运行时自动配置 agent 的调用。在本应用中我们把它显式呈现出来，以便你看到这种影响。

同样地，当经理登录同一系统时，会看到反映其额外权限的扩展工具集。除员工级工具外，经理还可以使用执行绩效评估等能力。他们可以选择本次会话要使用的工具，即时用所选内容配置 inline agent。

知识库的纳入范围也会根据用户角色调整。员工和经理看到不同层级的公司政策信息，经理还能额外访问绩效评估和薪酬明细等机密数据。在本演示中，我们实现了[元数据过滤](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-knowledge-bases-now-supports-metadata-filtering-to-improve-retrieval-accuracy/)，只根据用户的访问级别检索相应层级的文档，进一步提升效率与安全性。

我们来看看界面如何适配不同的用户角色。

员工视图提供对基本 HR 功能的访问，例如休假申请、费用提交和公司政策查询。用户可以选择本次会话要使用其中哪些工具。

经理视图则把这些选项扩展到薪酬管理等监督类功能，展示了 inline agent 如何根据用户权限获得更广泛的工具集。

如前面截图所示，同一个 HR 助手会根据用户角色提供不同的工具选项。员工看到 Knowledge Base、Apply Vacation Tool 和 Submit Expense 等选项，而经理还有 Performance Evaluation 等额外选项。用户可以选择为当前交互向 agent 添加哪些工具。

这种灵活性使得快速适应用户需求和偏好成为可能。例如，如果公司为创建商务差旅申请推出新政策，工具目录可以很快加入一个 Create Business Travel Reservation 工具。员工在需要规划商务旅行时可以选择把这个新工具加入 agent 配置，或者应用也可以根据其角色自动完成这一操作。

借助 Amazon Bedrock inline agents，你可以创建一个 action 目录，由应用或应用的使用者动态选择。这提升了方案的灵活性与适应性，使其非常适合应对现代业务运营中复杂且不断变化的格局。用户对 AI 助手的能力拥有更多控制权，而系统只加载每次交互所需的工具，从而保持高效。

## 技术基础：动态配置与 action 选择

inline agents 允许在运行时做动态配置，使单个 agent 能有效承担许多 agent 的工作。通过指定 action group 并即时修改指令——甚至在同一会话内完成——你可以构建出无需多次部署 agent 就能适配各种场景的多用途 AI 应用。

关于 inline agents，有以下要点：

- **运行时配置** – 在运行时更改 agent 的配置，包括其使用的 FM。这使得无需重新部署应用即可快速实验和调整，缩短开发周期。
- **工具级治理** – 在工具级别实施治理和访问控制。当 agent 在运行时动态变化时，工具级治理有助于无论 agent 如何配置都能维持安全性与合规性。
- **Agent 效率** – 在运行时只提供必要的工具和指令，以减少 token 用量并提升 agent 的准确性。可选工具更少，agent 选出正确工具的过程就更简单，从而减少工具选择过程中的幻觉。与静态 agent 相比，这种做法还可能带来更低的成本和更好的延迟，因为移除不必要的工具、知识库和指令会减少 agent 的大语言模型（LLM）所处理的输入和输出 token 数量。
- **灵活的 action 目录** – 创建可复用的 action，以便根据具体需求动态选择。这种模块化做法简化了 AI 应用的维护、更新和扩展。

以下是可复用 action 的示例：

- **企业系统集成** – 与 Salesforce、GitHub 或数据库等系统连接
- **实用工具** – 执行发送电子邮件或管理日历等常见任务
- **团队专属 API 访问** – 与专门的内部工具和服务交互
- **数据处理** – 分析文本、结构化数据或其他信息
- **外部服务** – 获取天气更新、股价，或执行网页搜索
- **专用 ML 模型** – 使用特定的机器学习（ML）模型处理针对性任务

使用 inline agents 时，你可以为以下方面配置参数：

- 基于用户意图或对话流程的上下文化工具选择
- 适配不同的用户角色与权限
- 在沟通风格或画像之间切换
- 基于任务复杂度的模型选择

inline agent 会使用你在运行时提供的配置，从而实现高度灵活的 AI 助手，高效处理不同业务场景中的各种任务。

## 使用 inline agents 构建 HR 助手

我们来看看如何使用 Amazon Bedrock inline agents 构建我们的 HR 助手：

- **创建工具目录** – 我们开发了一个 HR 相关工具的演示目录，包括：  **Knowledge Base** – 使用 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)根据应用用户的角色访问公司政策与指引。为了按用户角色过滤知识库内容，你还需要提供一个元数据文件，指明哪些员工角色类型可以访问每个文件  **Apply Vacation **– 用于申请和跟踪休假。  **Expense Report **– 用于提交和管理费用报告。  **Code Interpreter** – 用于执行计算和数据分析。  **Compensation Management **– 用于开展和审阅员工薪酬评估（仅经理可访问）。
- **设定对话语气** – 我们定义了多种对话语气以适配不同的交互风格：  **Professional** – 用于正式、商务化的交互。  **Casual** – 用于友好、日常的支持。  **Enthusiastic** – 用于积极、鼓励式的协助。
- **实施访问控制** – 我们实施了基于角色的访问控制。应用后端会检查用户角色（员工或经理），提供对相应工具和信息的访问权限，并将这些信息传给 inline agent。角色信息还用于配置知识库中的元数据过滤，以生成相关的回答。系统支持在运行时动态使用工具。用户可以在会话期间切换画像或增删工具，使 agent 实时适配不同的对话需求。
- **将 agent 与其他服务和工具集成** – 我们把 inline agent 连接到：  用于公司政策的 Amazon Bedrock Knowledge Bases，并启用基于角色访问的元数据过滤。  用于执行具体 action（例如提交休假申请或费用报告）的 [AWS Lambda](https://aws.amazon.com/lambda) 函数。  用于执行计算和数据分析的代码解释器工具。
- **创建 UI** – 我们创建了一个基于 Flask 的 UI，它执行以下操作：  根据用户角色显示可用工具。  允许用户选择不同的画像。  提供一个聊天窗口用于与 HR 助手交互。

要了解这种基于角色的动态功能在底层如何运作，我们来看下面的系统架构图。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/09/ML-17894-image003.jpg)

如上面的架构图所示，系统的工作方式如下：

- 最终用户登录，并被识别为经理或员工。
- 用户选择其有权访问的工具，并向 HR 助手发出请求。
- agent 会拆解问题，并使用可用工具分步解答查询，可能包括：  带基于角色访问的元数据过滤的 Amazon Bedrock Knowledge Bases。  用于特定 action 的 Lambda 函数。  用于计算的代码解释器工具。  薪酬工具（仅经理可访问，用于提交基本工资上调申请）。
- 应用使用 Amazon Bedrock inline agent，根据用户角色和请求动态传入相应工具。
- agent 使用选定的工具处理请求并向用户给出回答。

这种做法提供了灵活、可扩展的方案，能够快速适配不同的用户角色和不断变化的业务需求。

## 结论

在本文中，我们介绍了 Amazon Bedrock inline agent 功能，并展示了它在 HR 用例中的应用。我们基于用户角色和权限动态选择工具，调整指令以设定对话语气，并在运行时选择不同的模型。借助 inline agents，你可以改变构建和部署 AI 助手的方式。通过在运行时动态调整工具、指令和模型，你可以：

- 为不同用户角色打造个性化体验
- 通过让模型能力与任务复杂度相匹配来优化成本
- 简化开发与维护
- 无需管理多套 agent 配置即可高效扩展

对于需要高度动态行为的组织——无论你是 AI 初创公司、SaaS 提供商还是企业解决方案团队——inline agents 都提供了一种可扩展的方式来构建随需求成长的智能助手。要开始使用，请浏览我们的 [GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/agents-and-function-calling/bedrock-agents/features-examples/15-invoke-inline-agents/inline-agent-api-usage.ipynb)和 [HR 助手演示应用](https://github.com/awslabs/amazon-bedrock-agent-samples/tree/main/examples/agents_ux/inline-agent-hr-assistant)，它们演示了关键实现模式和最佳实践。
