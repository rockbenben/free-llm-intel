# 使用 Stream Vision Agents 和 Amazon Nova 2 Sonic 构建实时语音 agent

*本文与 Neevash Ramdial（*[*Stream*](https://getstream.io/) 的技术营销负责人）共同撰写

构建感觉自然、响应迅速的生产级语音 agent 是一项复杂的工程挑战。你必须编排 speech-to-speech 模型、管理低延迟音频流，并处理连接生命周期。你还需要在 Web、移动端和桌面应用之间提供一致的体验。

在本文中，你将学习如何将 Stream 的 Vision Agents 开源框架与 Amazon Bedrock 和 Amazon Nova 2 Sonic 结合，构建几分钟内即可投入生产的实时语音 agent。你将了解该集成的底层工作原理，逐步浏览代码示例，并探索函数调用、自动重连和多语言语音支持等高级能力。

## 挑战

构建支持语音的 AI 应用需要编排多个必须可靠协同工作的复杂系统。你面临如下挑战：管理实时音频流基础设施，同时集成语音识别、语言模型和 text-to-speech 服务。每一个环节都有其自身的延迟特性和故障模式。一次典型的语音交互包括：从用户麦克风采集音频、将其流式传输到 speech-to-text 服务、通过语言模型处理转录文本、生成响应、将响应转换回语音，再传递给用户。所有这一切都必须在几百毫秒的窗口内完成，才能让人感觉自然。这条流水线中的延迟会破坏对话流程，让用户感到沮丧。除了核心 AI 流水线之外，生产级语音应用还必须应对真实世界部署中那些杂乱的现实问题：不可靠的网络连接、浏览器兼容性问题、会话超时，以及服务不可用时的优雅降级。你往往要花更多时间构建重连逻辑、管理 WebRTC 连接和处理边缘情况，而不是花在真正的 AI 能力上。这种基础设施负担意味着团队要么投入数月构建定制方案，要么退而求其次，采用无法满足其特定需求的现成产品。Vision Agents 抽象掉了基础设施的复杂性，同时提供了定制 AI 体验的灵活性。

## 方案概览

该方案整合了三个关键组件：

- [Amazon Nova 2 Sonic](https://aws.amazon.com/nova/models/) 是通过 Amazon Bedrock 提供的 speech-to-speech 基础模型，具备实时双向音频流、原生轮次检测和函数调用能力。Nova 2 Sonic 负责完整的 speech-to-speech 流水线，接收音频输入并产生音频输出。这避免了对独立 STT 和 TTS 服务的需求。
- [Stream 的 Vision Agents ](https://visionagents.ai/)一个用于构建实时语音和视频 AI agent 的开源 Python 框架。它提供基于插件的架构，包含 25 个以上的集成、生产部署工具，以及面向 React、iOS、Android、Flutter 和 React Native 的客户端 SDK。该系统的核心设计是灵活性。你可以使用 Stream 的全球边缘网络获得高效性能，也可以集成你偏好的实时通信（RTC）提供商。Vision Agents 通过简洁的装饰器接口处理提供商特有的规格，使客服 agent、工作流自动化和 API 驱动的操作等用例只需极少的样板代码即可实现。借助 Vision Agents，你可以使用开源框架、第三方模型提供商和电话服务来构建 AI 应用。
- Stream 的 Edge Network 是一个全球分布的边缘网络，通常可实现低于 500 毫秒的加入时间和低于 30 毫秒的音频延迟，在客户端与你的 agent 后端之间提供实时传输层。

这些组件共同构成了一个完整的栈：Stream 负责实时媒体传输和客户端体验，Amazon Nova 2 Sonic 提供 AI 智能，Vision Agents 提供将它们粘合在一起的胶水代码。

## 架构概览

该系统围绕清晰的职责分离而设计：Stream 的基础设施负责实时媒体传输和客户端连接，而 Amazon Nova Sonic 运行在客户自己的 AWS 账户中，提供 AI 智能。这种分离有助于让敏感数据和业务逻辑始终处于客户的掌控之中，同时 Stream 全球分布的边缘网络提供用户所期望的低延迟媒体体验。Stream 的边缘网络充当终端用户设备与 Vision Agent 工作进程之间的媒体中介。当用户说话时，音频被采集、加密，并以 RTP over UDP 的形式传输到最近的 Stream SFU（Selective Forwarding Unit）。SFU 终止 WebRTC 连接，处理 NAT 穿越和带宽估计，并将音频轨道转发给 Vision Agent 工作进程，就像它是另一个通话参与者一样。这意味着 agent 自然地集成到通话模型中。agent 就是另一个 peer，通过人类参与者使用的同一基础设施接收和发送音频。

音频数据在系统中双向流动：来自用户的语音由 Vision Agent 工作进程解码为原始 PCM，通过 Bedrock real-time API 流式传输到 Amazon Nova Sonic；来自 Nova Sonic 的响应音频帧被重新编码、封装为 RTP，再通过 SFU 回传到客户端设备。端到端延迟通常低于 500 毫秒。语音活动检测（VAD）在工作进程中运行，用于检测语音边界和打断（barge-in）事件，而浏览器中的回声消除有助于防止 agent 自身的输出再次触发 VAD 环路。

## 账户边界

- 客户 AWS 账户  业务逻辑与编排（agent 策略、工具、数据访问）。通过 Amazon Bedrock 集成访问 Amazon Nova 模型。
- Stream AWS 账户  全球 WebRTC/SFU 媒体面、TURN/STUN 和信令。Vision Agent 运行时（工作进程）以机器人 peer 的身份终止 WebRTC，并桥接客户的 Amazon Bedrock 集成。

## 端到端媒体流

- 用户从 Web 或移动端加入。  应用嵌入 Stream 的音频客户端 SDK，请求麦克风（以及可选的摄像头），并加入配置为 AI 参与的通话类型。媒体以 RTP over UDP 形式发送，以获得可预测的低延迟和无队头阻塞的传输。2. 区域 SFU 终止
- 区域 SFU 终止  最近区域中的 Stream SFU 节点终止用户的 WebRTC 连接，处理带宽估计、simulcast 和 NAT 穿越。SFU 将相关音频轨道转发给 Vision Agent 工作进程，就像它是另一个参与者一样。
- Vision Agent 工作进程  一个专用的 Vision Agent 工作进程持有该会话的 PeerConnection 状态。它将音频解码为原始 PCM，并通过工作进程将 PCM 帧流式传输到 Amazon Bedrock 服务，再作为客户 AWS 账户中的实时会话转发给 Amazon Nova 2 Sonic。
- 通过 Amazon Bedrock 将 Amazon Nova 2 Sonic 与 Vision Agents 集成  Amazon Nova 2 Sonic 检测语音边界，并执行 speech-to-speech 建模（理解、推理和 TTS），还可选择调用客户系统（RDS、API、知识库）中的工具。它优雅地处理打断（barge-in），并维持完整的对话上下文，使对话保持自然连贯。
- 将响应流式回传给用户  当 Amazon Nova Sonic 产生响应音频帧时，Vision Agent 工作进程会：  将其切片并封装为 RTP，使用单调递增的时间戳以避免间隙/漂移  通过 SFU 在同一 WebRTC 会话中发送 RTP 数据包。浏览器的 WebRTC 栈以低于 500 毫秒的延迟解码并播放音频。
- 打断、转录文本和旁路数据  浏览器中的回声消除有助于防止 agent 自身的输出再次触发 VAD。当用户打断时，新的语音会通过 RTCDataChannel 触发中断信号，使工作进程停止转发 Amazon Nova Sonic 的输出并重置其本地缓冲区。

## 前置条件

开始之前，请确保你已具备以下条件：

- 通过环境变量、IAM 角色或 AWS Command Line Interface（AWS CLI）配置文件配置的 AWS 凭证。对于生产环境，请使用附加到计算资源上的 IAM 角色，而不是长期凭证。对于本地开发，请使用 AWS CLI 配置文件（aws configure）或 AWS SSO。不要将包含凭证的 .env 文件提交到版本控制系统。
- 一个 Stream 账户，带有 Audio API key 和 secret（预计你每月可免费获得 333,000 分钟的参与者时长）。
- 已安装 Python 3.12 或更高版本。
- 已安装 [uv 包](https://docs.astral.sh/uv/)管理器（`pip install uv`）。
- 已安装 Vision Agents（`uv add vision-agents`）

### 步骤 2：配置环境变量

在项目根目录创建一个“.env”文件来管理配置。对于 AWS 凭证，我们建议在该文件中指向你的 `AWS_PROFILE`，以便应用程序在与 AWS 资源交互时访问你的凭证。我们不建议将 AWS access key 直接存储在此文件中。

对于 Stream API 凭证，你可以使用 HashiCorp Vault 或 AWS Secrets Manager 等第三方库，但安全方面的考量不在本文讨论范围之内。

```
# Stream API credentials
STREAM_API_KEY=test/geststream/api_key
STREAM_API_SECRET=test/getstream/api_secret
# AWS credentials
AWS_PROFILE=your_aws_profile_name
AWS_REGION=us-east-1
```

Vision Agents 会在启动时自动发现这些环境变量，因此你无需将它们显式传递给每个客户端。

### 步骤 3：构建你的第一个语音 agent

创建一个 `main.py` 文件，代码如下：

```
import asyncio
from dotenv import load_dotenv

from vision_agents.core import Agent, User, Runner
from vision_agents.core.agents import AgentLauncher
from vision_agents.plugins import aws, getstream

load_dotenv()

async def create_agent(**kwargs) -> Agent:
    agent = Agent(
        edge=getstream.Edge(),
        agent_user=User(name="Helpful Assistant", id="agent"),
        instructions="You are a helpful voice assistant. Be concise and friendly.",
        llm=aws.Realtime(
            model="amazon.nova-2-sonic-v1:0",
            region_name="us-east-1",
            voice_id="matthew",
        ),
    )
    return agent

async def join_call(agent: Agent, call_type: str, call_id: str, **kwargs) -> None:
    call = await agent.create_call(call_type, call_id)

    async with agent.join(call):
        await asyncio.sleep(2)
        await agent.llm.simple_response(
            text="Greet the user warmly and ask how you can help."
        )
        await agent.finish()  # Run until the call ends

if __name__ == "__main__":
    Runner(AgentLauncher(create_agent=create_agent, join_call=join_call)).cli()
```

### 步骤 4：运行语音 agent

运行 agent：

```
uv run main.py run
```

用不到 30 行代码，你就获得了一个功能完备、由 Amazon Nova Sonic 驱动的实时语音 agent，可从 Stream 客户端 SDK 访问。

## 理解 Amazon Bedrock 集成

让我们更仔细地看看 `aws.Realtime` 插件的底层工作原理。

### 使用 Amazon Nova 2 Sonic 进行双向流式传输

Amazon Nova 2 Sonic 使用事件驱动的双向流式 API。这种方法不使用请求-响应模式，而是允许近乎连续的音频同时双向流动。Vision Agents 的 AWS 插件通过结构化的事件序列来管理这种复杂性：

- 会话初始化 – 发送 `sessionStart` 事件，携带推理配置（temperature、max tokens、top-p）。
- Prompt 设置 – `promptStart` 事件配置音频输出格式（24kHz PCM）、语音选择和工具定义。
- 系统指令 – 系统指令以文本内容块的形式发送，角色为 `SYSTEM`。
- 音频流 – 麦克风音频帧（每帧约 32 毫秒）以 `audioInput` 事件的形式流式传输。
- 响应流 – Nova Sonic 以 `audioOutput` 事件的形式回传生成的语音。
- 会话拆除 – `promptEnd` 和 `sessionEnd` 事件干净地关闭连接。

每个内容块都遵循三部分模式：`contentStart` → 内容载荷 → `contentEnd`。这种层次结构使模型能够在整个交互过程中保持恰当的上下文。

下面是插件中会话开始事件的样子：

```
def _create_session_start_event(self) -> Dict[str, Any]:
    return {
        "event": {
            "sessionStart": {
                "inferenceConfiguration": {
                    "maxTokens": 1024,
                    "topP": 0.9,
                    "temperature": 0.7,
                }
            },
            "turnDetectionConfiguration": {
                "endpointingSensitivity": "MEDIUM"
            },
        }
    }
```

### 添加函数调用

Amazon Nova 2 Sonic 的关键能力之一是在实时对话中原生支持函数调用。这使你的语音 agent 能够在保持自然口语对话的同时执行查询数据库、调用 API 和触发工作流等操作。使用 `@llm.register_function` 装饰器来定义模型可以调用的函数：

```
import asyncio
from dotenv import load_dotenv
from typing import Dict, Any

from vision_agents.core import Agent, User, Runner
from vision_agents.core.agents import AgentLauncher
from vision_agents.plugins import aws, getstream

load_dotenv()

async def create_agent(**kwargs) -> Agent:
    agent = Agent(
        edge=getstream.Edge(),
        agent_user=User(name="Weather Assistant", id="agent"),
        instructions="""You are a helpful weather assistant. When users ask
        about weather, use the get_weather function to fetch current conditions.
        You can also help with simple calculations.""",
        llm=aws.Realtime(
            model="amazon.nova-2-sonic-v1:0",
            region_name="us-east-1",
        ),
    )

    @agent.llm.register_function(
        name="get_weather",
        description="Get the current weather for a given city"
    )
    async def get_weather(location: str) -> Dict[str, Any]:
        # In production, call a real weather API
        return {
            "city": location,
            "temperature": 72,
            "condition": "Sunny",
            "humidity": "45%"
        }

    @agent.llm.register_function(
        name="calculate",
        description="Perform a mathematical calculation"
    )
    def calculate(operation: str, a: float, b: float) -> dict:
        operations = {
            "add": lambda x, y: x + y,
            "subtract": lambda x, y: x - y,
            "multiply": lambda x, y: x * y,
            "divide": lambda x, y: x / y if y != 0 else None,
        }
        result = operations.get(operation, lambda x, y: None)(a, b)
        return {"operation": operation, "a": a, "b": b, "result": result}

    return agent

async def join_call(agent: Agent, call_type: str, call_id: str, **kwargs) -> None:
    await agent.create_user()
    call = await agent.create_call(call_type, call_id)

    async with agent.join(call):
        await asyncio.sleep(2)
        await agent.llm.simple_response(
            text="Greet the user and let them know you can check the weather."
        )
        await agent.finish()

if __name__ == "__main__":
    Runner(AgentLauncher(create_agent=create_agent, join_call=join_call)).cli()
```

### 函数调用在 Amazon Nova 2 Sonic 中如何工作

当模型决定调用函数时，会发生以下序列：

- Nova 2 Sonic 发出一个 `toolUse` 事件，其中包含函数名和参数。
- Vision Agents 插件拦截该事件，反序列化参数，并运行已注册的 Python 函数。
- 结果通过 `toolResult` 事件回传给 Nova，并按照标准的 `contentStart` → `toolResult` → `contentEnd` 模式封装。
- Nova 2 Sonic 将函数结果纳入其响应，并自然地继续口语对话。

使用这种方法，你可以构建复杂的多步骤工作流。例如，语音 agent 可以在一次自然对话中查询客户记录、检查库存并下单。

### 通过 Amazon Bedrock 使用标准 LLM

除了实时 speech-to-speech 之外，AWS 插件还通过 `aws.LLM` 提供标准 LLM 集成。这适用于自定义流水线架构：你希望将 Amazon Bedrock 模型与独立的 STT 和 TTS 提供商配对：

```
from vision_agents.core import Agent, User
from vision_agents.plugins import aws, getstream, cartesia, deepgram, smart_turn

agent = Agent(
    edge=getstream.Edge(),
    agent_user=User(name="Custom Pipeline Agent"),
    instructions="Be helpful and concise.",
    llm=aws.LLM(
        model="anthropic.claude-3-haiku-20240307-v1:0",
        region_name="us-east-1"
    ),
    tts=cartesia.TTS(),
    stt=deepgram.STT(),
    turn_detection=smart_turn.TurnDetection(
        buffer_duration=2.0,
        confidence_threshold=0.5
    ),
)
```

标准 LLM 支持通过 `converse_stream()` 进行流式响应、完整的对话历史管理、面向 Claude 等模型的视觉输入，以及多轮工具调用——每次请求最多执行 3 轮函数。

### 使用 Amazon Polly 进行 text-to-speech

对于自定义流水线架构，AWS 插件还包含 Amazon Polly TTS 集成。当你使用非实时 LLM（例如 Amazon Bedrock 上的 Claude 或其他提供商的模型）并需要高质量语音合成时，这很有用：

```
from vision_agents.plugins import aws

tts = aws.TTS(
    region_name="us-east-1",
    voice_id="Joanna",
    engine="neural",        # 'standard' or 'neural'
    language_code="en-US"
)
```

Amazon Polly TTS 同时支持 standard 和 neural 引擎、用于精细控制语音的 SSML 输入，以及多种语言和声音。neural 引擎产生的语音听起来更自然，是你在 AWS 基础设施上构建自定义 STT → LLM → TTS 流水线时的理想选择。

### 清理资源

要删除 Stream 通话并终止正在运行的 Vision Agent 进程：

```
uv run main.py stop
```

重要提示：对 Amazon Nova 2 Sonic 的所有 API 调用都会产生 Amazon Bedrock 费用。你可以运行清理命令来终止会话，避免持续计费。活动会话在显式终止之前可能会继续产生费用。

## 用例

有了技术基础之后，值得探索这些能力在哪些地方能转化为有意义的现实影响。低延迟语音、对话管理和工具集成的组合，为各行各业开辟了广泛的应用场景——在这些场景中，自然的口语交互可以替代或增强传统界面。

### 用例 1：面向无屏幕和低注意力环境的语音界面

Vision Agents 与 Amazon Nova 2 Sonic 结合，非常适合用户无法可靠地与屏幕交互的环境，例如驾驶、现场服务、物流、医疗或现场作业。在这些场景中，语音成为主要界面，而非锦上添花的功能。

- 借助 Amazon Nova 2 Sonic，你可以获得低延迟、自然轮次的实时 speech-to-speech 交互，使用户能够自由表达、打断响应并自我纠正，而不会中断对话流程。
- Vision Agents 跨轮次管理对话状态和任务逻辑，将语音输入转化为结构化操作，例如检索下一个工作分配、更新任务状态、记录备注或请求人工协助。

由于 agent 在整个交互过程中保持上下文，用户可以直接发出后续命令或澄清，而无需重复信息。例如，送货司机可以问“我的下一站是哪里？”，收到语音导航，说“将上一次配送标记为完成”，接着说“呼叫调度中心”——全程无需触碰屏幕，而 agent 会实时更新后端系统。

### 用例 2：大规模高并发呼入电话支持

Vision Agents 与 Amazon Nova 2 Sonic 结合，专为处理大量呼入支持电话而设计——在这些场景中，人工客服会成为瓶颈。这个用例的核心在于规模：减少排队时间、分流重复性请求，并把人工客服留给需要他们介入的案例。

- 借助 Amazon Nova 2 Sonic，来电者可以进行低延迟的实时 speech-to-speech 对话，自然地说明问题，而无需在预设脚本的 IVR 菜单中层层导航。
- Vision Agents 编排意图检测、对话状态和后端集成（例如订单系统、账户记录或工单服务），使常见请求能在通话中自动解决。

当问题超出预定义的置信度阈值或需要人工干预时，agent 会升级给人工，并附上结构化的上下文，从而免去来电者重复陈述的麻烦。在高峰时段，可能有数百名客户来电询问配送延误。来电者无需排队，而是立即由语音 agent 接待：它检查订单状态、解释延误原因、提供后续步骤，只有在检测到异常时才转接人工客服。这将电话系统从基于排队模式的成本中心，转变为持续运行的一线解决层。
