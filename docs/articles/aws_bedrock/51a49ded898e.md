Amazon Bedrock 现在支持 Anthropic Claude 模型：在首尔支持 [Claude Opus 5](https://aws.amazon.com/blogs/machine-learning/introducing-claude-opus-5-on-aws-anthropics-most-capable-opus-model/) 和 [Claude Sonnet 5](https://aws.amazon.com/blogs/machine-learning/introducing-claude-sonnet-5-on-aws-anthropics-most-capable-sonnet-model/)，在新加坡支持 [Claude Sonnet 5](https://aws.amazon.com/blogs/machine-learning/introducing-claude-sonnet-5-on-aws-anthropics-most-capable-sonnet-model/)——在 `bedrock-runtime` 端点上做区域内推理。如果你在韩国或新加坡有本地数据处理要求，例如在金融服务、医疗和公共部门，你现在可以大规模使用这些 Anthropic 模型。Amazon Bedrock 在你调用的区域内处理推理请求和数据。处理不会离开该区域。

在本文中，我们演练区域内推理如何从亚太（首尔）区域（`ap-northeast-2`）和亚太（新加坡）区域（`ap-southeast-1`）用 `bedrock-runtime` 端点工作。我们还演示如何从 Amazon Bedrock 控制台以及用代码上手——分别使用 Amazon Bedrock Converse API、InvokeModel API 和 Anthropic Messages API。

## 区域内推理

为帮助你满足 AI 应用严格的数据驻留要求，Amazon Bedrock 提供区域内推理。你的请求完全在你指定的单个 AWS 区域内处理，且不会离开该区域。当你有严格的单区域数据处理需求时使用它。

与跨区域推理配置不同，这里没有路由层。你发送到首尔（`ap-northeast-2`）或新加坡（`ap-southeast-1`）区域的请求只由那个区域服务。你的输入 prompt 和输出结果在请求的整个生命周期内都留在其中。作为交换，你的吞吐受该区域容量限制。请求受每区域服务配额约束。计费遵循你所调用区域的标准按需定价。配额消费、Amazon CloudWatch 指标和 AWS CloudTrail 日志条目都限定在同一个区域。在你的监控中没有源与目的之分要考虑。首尔的 Claude Sonnet 5 和 Claude Opus 5、新加坡的 Claude Sonnet 5 的区域内推理在 `bedrock-runtime` 端点上可用。对于新应用，我们推荐 `bedrock-runtime` 端点。你用直接 model ID 调用它，例如 `anthropic.claude-opus-5` 或 `anthropic.claude-sonnet-5`。它支持 Anthropic 的 [Messages](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-messages-api.html) API，以及 Amazon Bedrock 的 [InvokeModel](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-api.html) 和 [Converse](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html) API，并支持诸如 [Amazon Bedrock Guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html) 和[智能 prompt 路由](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-routing.html)等 Amazon Bedrock 特性。

## 从 Amazon Bedrock 控制台访问 Claude 模型

你可以在 Amazon Bedrock 控制台的文本 playground 中访问 Claude 模型，无需编码或 SDK 设置。你可以发送 prompt、调整推理参数并在变体之间切换，以便在集成 API 之前先感受每个模型。

- 在你希望作为源的区域打开 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock/)。
- 在导航窗格的 **Test** 下，选择 **Playground**。
- 选择页面中间的 **Select model**。
- 搜索 `anthropic.claude-opus-5`，在 **Inference** 下选择 **On-Demand**，然后选择 **Apply**。
- 输入一个 prompt 并选择 **Run** 以生成响应。

## 用 Anthropic Messages API 及 Amazon Bedrock InvokeModel 和 Converse API 调用 Claude 模型

你可以用首尔的区域内推理以编程方式访问 Anthropic 的 Claude Opus 5 或 Claude Sonnet 5——通过 Anthropic SDK 在 `bedrock-runtime` 上用 [Anthropic Messages API](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-anthropic-claude-messages.html)，或继续在 `bedrock-runtime` 上用 [Invoke](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-api.html) 和 [Converse API](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html)，通过 [AWS Command Line Interface (AWS CLI)](https://aws.amazon.com/cli/) 和 [AWS SDK](https://aws.amazon.com/developer/tools/)。

### 前提条件

- 拥有 Amazon Bedrock 访问权限的有效 AWS 账户。
- 已安装并配置 AWS CLI。
- Python 3.8+。
- 已安装 Boto3：`pip install boto3`。
- 已安装 Anthropic SDK：`pip install anthropic`。
- 已安装用于 Amazon Bedrock 认证的 Amazon Bedrock Token Generator：`pip install aws_bedrock_token_generator`。

下面是使用 AWS SDK for Python (Boto3) 配合 InvokeModel API 的一个简短示例：

```
import boto3
import json

# Create a Bedrock Runtime client with in-region inference in Singapore
bedrock_runtime = boto3.client(
    service_name="bedrock-runtime",
    region_name="ap-southeast-1")

# Invoke Claude Sonnet 5
response = bedrock_runtime.invoke_model(
    modelId="anthropic.claude-sonnet-5",
    contentType="application/json",
    accept="application/json",
    body=json.dumps({
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 4096,
        "messages": [
            {
                "role": "user",
                "content": " Can you explain the features of Amazon Bedrock? "
            }
        ]
    })
)

result = json.loads(response["body"].read())
print(result["content"][0]["text"])
```

你也可以使用 Amazon Bedrock Converse API 获得统一的多模型体验：

```
import boto3

# Create a Bedrock Runtime client with in-region inference in Seoul
bedrock_runtime = boto3.client(
    service_name="bedrock-runtime",
    region_name="ap-northeast-2"
)

# Invoke Claude Opus 5
response = bedrock_runtime.converse(
    modelId="anthropic.claude-opus-5",
    messages=[
        { "role": "user",
          "content": [
              { "text": " Can you explain the features of Amazon Bedrock?"
              }
          ]
        }
    ],
    inferenceConfig={
        "maxTokens": 4096
    }
)

if 'output' in response:
    blocks = response['output']['message']['content']
    print('\n'.join(b.get('text', '') for b in blocks if 'text' in b))
```

你也可以通过 `anthropic` SDK 包使用 Anthropic Messages API 获得更简洁的体验：

```
from anthropic import Anthropic
from aws_bedrock_token_generator import provide_token

token = provide_token(region="ap-northeast-2")

client = Anthropic(
    base_url="https://bedrock-runtime.ap-northeast-2.amazonaws.com/anthropic",
    api_key=token,
)

response = client.messages.create(
    model="anthropic.claude-sonnet-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Can you explain the features of Amazon Bedrock?"}],
)

print(response)
```

你可以通过 [CloudWatch](https://docs.aws.amazon.com/bedrock/latest/userguide/monitoring.html) 和 [AWS Cost Explorer](https://aws.amazon.com/aws-cost-management/aws-cost-explorer/) 监控用量、性能和成本，随需求增长扩展应用。

## 结论

随着 Anthropic 的 Claude Opus 5 和 Claude Sonnet 5 在 Amazon Bedrock 上、在首尔带区域内推理上线，以及 Claude Sonnet 5 在新加坡带区域内推理上线，你现在可以构建那些有严格数据驻留要求的生成式 AI 应用。这把推理保持在你要的那个区域内。我们对这次上线感到兴奋，并期待看到你如何用这些能力在整个区域加速创新并交付有影响力的 AI 驱动体验。要获取每个区域模型可用性的最新信息，参见 Amazon Bedrock 用户指南中的[按模型的区域可用性](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html#model-regions-anthropic)。
