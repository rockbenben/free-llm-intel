# Amazon Bedrock 推出面向生成式 AI 应用的 Session Management APIs（预览版）

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 宣布推出 Session Management APIs 的预览版，这项新能力使开发者能够为使用 LangGraph、LlamaIndex 等流行开源框架构建的生成式 AI 应用简化状态与上下文管理。Session Management APIs 提供开箱即用的方案，使开发者能够在多步骤生成式 AI 工作流中安全管理状态与对话上下文，免去构建、维护或扩展自定义后端方案的需要。本文讨论新的 Session Management APIs，以及如何在你的生成式 AI 应用中处理会话状态。

通过在多次交互之间保留会话状态，Session Management APIs 增强了工作流的连续性，使虚拟助手、多 agent 研究流程等需要在长时间交互中保持上下文的生成式 AI 应用成为可能。开发者可以利用这项能力为工作流阶段创建检查点、保存中间状态，并从失败或中断处恢复任务。此外，他们还可以暂停并重放会话，并利用详细的 trace 来调试和改进其生成式 AI 应用。通过将会话视为一等资源，这项能力使开发者能够通过 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）实施细粒度访问控制，并使用 [AWS Key Management Service](https://aws.amazon.com/kms)（AWS KMS）加密数据，确保来自不同用户会话的数据被安全隔离，并以强隐私保护支持多租户应用。

构建生成式 AI 应用需要的不仅仅是模型 API 调用。你的应用必须处理对话历史、用户偏好、状态跟踪与上下文变化。随着这些应用复杂度提升，稳健的状态管理变得至关重要。主要原因包括：

- **上下文一致性** – 维护状态确保应用能够跟踪信息流向，从而产出更连贯、更贴合上下文的输出。
- **用户交互跟踪** – 在交互式应用中，状态管理使系统能够记住用户输入与偏好，促成个性化体验。
- **资源优化** – 高效的状态管理有助于有效分配计算资源，确保应用平稳运行且没有不必要的冗余。
- **错误处理与恢复** – 开发者可以利用这项能力为工作流阶段创建检查点、保存中间状态，并从失败或中断处恢复任务。

本文讨论新的 Session Management APIs，以及如何在你的生成式 AI 应用中处理会话状态。

## 背景

生成式 AI 应用中的*状态持久化*指的是在多次交互之间维护并回忆信息的能力。这对于创造连贯且贴合上下文的体验至关重要。你可能需要持久化的信息包括：

- **用户信息** – 关于用户的基本细节，例如 ID、偏好或历史记录
- **对话历史** – 当前会话内既往交互的记录
- **上下文标记** – 多轮对话中当前主题、意图或阶段的指示
- **应用状态** – 进行中的流程或工作流的当前状态

有效利用会话属性可以实现个性化——基于正在进行的对话量身定制回答；实现连续性——即使发生中断，对话也能从上次停下的地方继续；并实现复杂任务处理——有效管理多步骤流程或决策树。这些能力增强了用户体验以及生成式 AI 应用的整体功能。

## 挑战

在生成式 AI 应用中实现稳健的状态管理会带来若干相互关联的挑战。系统必须在毫秒级完成状态持久化与检索，以维持流畅的对话。随着流量增长与上下文数据扩展，状态管理还需要具备高效的扩展能力。

当你构建自己的状态管理系统时，需要实现处理后端服务与基础设施，以支持持久化、检查点与检索操作。本文以 LangGraph 为例讨论短期记忆的概念与可用选项。短期记忆在单个对话线程内存储信息，它作为 agent 状态的一部分被管理，并通过线程范围的检查点持久化。你可以使用同步或异步连接把短期记忆持久化到 PostgreSQL 之类的数据库中。然而，你还需要搭建基础设施、实施数据治理，并启用安全与监控。

## 方案概览

Amazon Bedrock 中的 Session Management APIs 提供了一套完整方案，通过免去自定义基础设施的搭建与维护，简化生成式 AI 应用的开发与部署。这项能力不仅降低了处理数据持久化、检索与检查点的复杂性，还通过内置的租户隔离能力提供企业级安全特性。你可以把 DIY 生成式 AI 方案中管理状态与上下文的繁重工作卸载给 Session Management APIs，同时继续使用你偏好的 OSS 工具。这将加速你部署安全且可扩展的生成式 AI 方案的过程。

Session Management APIs 还支持 human-in-the-loop 场景，即在自动化工作流中需要人工干预的情况。此外，它还提供完善的调试与可追溯性功能，为故障排查与合规目的保留详细的执行日志。能够快速检索并分析会话数据，使开发者可以基于真实使用模式与性能指标优化其应用。

## 搭建 Session Management APIs

我们使用以下代码集成 Session Management APIs：

```
# Initialize session saver
session_saver = BedrockSessionSaver(
    region_name="<aws_region>",
   )

# Compile graph with session management
graph = graph_builder.compile(checkpointer=session_saver)
 
# Create a new session
session_id = session_saver.session_client.client.create_session()[“sessionId”]
```

## 运行对话

现在我们可以运行有状态对话：

```
config = {"configurable": {"thread_id": session_id}}

while True:
    user_input = input("User: ")
    if user_input.lower() in ["quit", "exit", "q"]:
        print("Goodbye!")
        break
    for event in graph.stream(
        {"messages": [("user", user_input)]}, 
        config
    ):
        for value in event.values():
            if isinstance(value["messages"][-1], BaseMessage):
                print("Assistant:", value["messages"][-1].content)
```

## 访问会话历史

你可以使用 graph 实例快速检索对话历史：

```
for i in graph.get_state_history(config, limit=5):
    print(i)
```

尽管在 LangGraph 中使用 `BedrockSessionSaver` 访问数据很简单，但有时你可能需要直接访问会话数据——无论是出于审计目的还是外部处理。Session Management APIs 提供了这一功能，不过需要注意，检索到的数据是序列化格式。要有意义地处理这些数据，你需要先执行反序列化：

```
# List all invocation steps
steps = client.list_invocation_steps(
    sessionIdentifier=session_id,
)
 
# Get specific step details
step_details = client.get_invocation_step(
    sessionIdentifier=session_id,
    invocationIdentifier="your-invocation-id",
    invocationStepId="your-step-id",
)
```

## 重放与分叉操作

你可能希望分析这些步骤以理解推理过程、进行调试或尝试不同路径。你可以带着检查点调用 graph，从该点重放特定操作：

```
config_replay = {
    "configurable": {
        "thread_id": session_id,
        "checkpoint_id": "<checkpoint_id>",
    }
}
for event in graph.stream(None, config_replay, stream_mode="values"):
    print(event)
```

在所提供的 `checkpoint_id` 之前，graph 会重放此前已执行的步骤，并执行 `checkpoint_id` 之后的步骤。

你也可以尝试分叉，以重新审视 agent 过去的操作，并在 graph 中探索其他路径：

```
config = {
    "configurable": {
        "thread_id": session_id,
        "checkpoint_id": "<checkpoint_id>",
    }
}
graph.update_state(config, {"state": "updated state"})
```

## Human-in-the-loop

Human-in-the-loop（HITL）交互模式允许 graph 在特定步骤停止，并在继续之前寻求人工批准。如果你需要评审特定的工具调用，这一点很重要。在 LangGraph 中，断点构建于检查点之上，检查点在每个节点执行后保存 graph 的状态。你可以使用 Session Management APIs 在 graph 中有效实现 HITL。

本示例演示了 Session Management APIs 如何与 LangGraph 无缝集成，创建在交互之间保持上下文的有状态对话。Session Management APIs 承担了状态持久化的复杂性，使你能够专注于构建对话逻辑。

## 注意事项与最佳实践

在实施 Session Management APIs 时，请考虑以下关键实践以获得最佳效果：

- **会话生命周期管理 **– 请仔细规划会话生命周期，从创建到终止。在对话开始时使用 CreateSession 初始化会话，并在完成后使用 EndSession 正确关闭。这种做法促进高效的资源利用，并在交互之间维持清晰的状态边界。
- **安全与合规 **– 对于处理敏感信息的应用，请使用 Session Management APIs 的内置安全特性实施适当的数据保护措施。默认情况下，会话加密使用 AWS 托管密钥。若有额外的安全需求，你可以使用客户托管密钥加密会话数据。利用该服务的数据保留与删除能力，在维持适当数据治理的同时保持符合相关法规。

## 结论

Amazon Bedrock 中的 Session Management APIs 为处理生成式 AI 应用中的状态提供了强大方案。通过使用这一完全托管的能力，开发者可以专注于打造创新的 AI 体验，而不必陷入基础设施管理的复杂细节。与 LangGraph 的无缝集成增强了其实用性，使复杂的有状态 AI 应用能够快速开发与部署。

随着生成式 AI 领域持续演进，稳健的状态管理将变得愈发关键。Session Management APIs 提供了满足这些不断增长的需求所需的可扩展性、安全性与灵活性，使开发者能够构建更具上下文感知、更个性化且更可靠的 AI 驱动应用。

采用 Session Management APIs，开发者可以加速走向生产，通过一致且连贯的交互提供更好的用户体验，并专注于其 AI 应用独特的价值主张，而非底层基础设施的挑战。
