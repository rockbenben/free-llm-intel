# 在 AWS 上使用 PwC 的 AI 驱动标注提取合同洞察

*本文由 PwC 的 Yash Munsadwala、Adam Hood、Justin Guse 与 Hector Hernandez 共同撰写。*

合同分析往往耗费法务、合规与采购团队大量时间，尤其是当重要洞察埋藏在冗长、非结构化的协议中时。随着合同数量增长，查找特定条款并评估已提取的条款会越来越难以扩展。

如今许多团队主要依赖关键词与模式匹配抽取，或依赖合同管理系统来分析合同。这些方法虽然可行，但往往无法在规模化场景下提供一致的洞察。因此，许多团队正在探索基于 AI 的方法，把[大语言模型（LLM）](https://aws.amazon.com/what-is/large-language-model/)与自动化抽取工作流结合起来。

构建在 AWS 上的 PwC AI 驱动标注（AIDA）解决方案，可以通过基于规则的抽取与自然语言查询从合同中提取结构化洞察。借助 LLM，AIDA 能解读复杂的法律语言，并依据既定规则提取洞察。用户可以就单份合同、或在项目内跨多份文档提出自然语言问题，并获得带链接引用的、针对上下文的答案。这些能力减少了对合同语言的手工检索与解读，有助于精简审查工作流。在客户实施中，AIDA 已帮助把人工合同审查时间最多减少 90%，帮助团队更快获取关键信息、缩短审查周期。本文中你将看到 AIDA 如何应对这些挑战。我们会走一遍 AIDA 背后的架构，并演示三项核心能力：基于模板的抽取、文档级 chat 以及跨文档的 global chat。

## 方案概览

AIDA 旨在把非结构化文档转化为结构化、可搜索的洞察，精简跨系统访问与复用关键合同信息的过程。AIDA 使用 LLM，并结合 AWS 云原生服务与集成服务，帮助更有效地从合同中提取洞察。该方案提供的能力可支持组织的安全、合规与风险管理要求，但客户仍需自行负责配置与运营该方案以满足其具体合规义务。由于 AIDA 处理的可能是敏感的合同数据，在对 AI 生成结果作业务或法律上的依赖之前，应施加适当的保障措施与人工审查流程。AIDA 提供了一套全面的能力来应对既有挑战。以下关键特性突出了核心功能，我们会在后续章节中详细探讨：

- **定制化数据抽取：** 借助用户定义的规则与自定义模板实现可扩展的数据抽取。按文档使用自定义抽取字段与逻辑，并行从数千份合同中以一致的准确率提取洞察。
- **跨文档的自然语言问答**：提出自然语言问题，获得针对上下文的回答，并带有指向源文档的链接引用。
- **与模型系统集成：** 与模型系统（例如合同管理系统与文档仓库）集成，你可以用它们检索源数据并交付已提取的洞察。

AIDA 可支持跨众多行业可扩展的合同分析，包括媒体与娱乐（M&E）以及房地产，也适用于采购、法务与合规等能力领域。例如在 M&E 行业，AIDA 通过从许可协议中提取并分析权利信息，帮助内容制作方与发行方释放其知识产权的整体价值。它会归纳广播、流媒体、院线与衍生权利，让有关衍生作品、续集与全球发行的决策更快、更有依据。一家大型电影与电视工作室把权利研究时间缩短了 [90%](https://www.pwc.com/us/en/technology/alliances/library/aws-ai-driven-annotation.html)。

### AIDA 的架构概览![AIDA 的 PWC 解决方案架构](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/24/ML-19434-image-1.png)

该架构展示了 AIDA 各组件如何协同工作，利用 AWS 可扩展的云原生服务安全地处理、分析并交付来自复杂合同的洞察。每个组件都旨在帮助在规模化处理合同时保持安全、可追溯性与性能。

### **1. 边缘安全与访问**

AIDA 的边缘层为用户流量提供已认证的访问与受控路由。请求先经过 [AWS WAF](https://aws.amazon.com/waf/) 做威胁过滤，再经 Network Load Balancer 到达反向代理服务器（NGINX），由它管理 SSL 终止、路由与策略执行，然后转发到 Amazon Elastic Container Service（[Amazon ECS](https://aws.amazon.com/pm/ecs/)）。传输中的数据使用 TLS 1.2 或更高版本加密，包括用户经 HTTPS 的连接，以及 Amazon ECS、Amazon Relational Database Service（[Amazon RDS](https://aws.amazon.com/rds/)）、Amazon Simple Storage Service（[Amazon S3](https://aws.amazon.com/s3/)）、[Amazon Bedrock](https://aws.amazon.com/bedrock/) 与其他 AWS 服务之间的内部服务间通信。

认证由 [Amazon Cognito](https://aws.amazon.com/cognito/) 处理，并与 Microsoft Entra ID、Okta 等企业身份提供商集成，以在规模化场景下保护访问安全。AIDA 通过应用级与项目级角色实施细粒度访问控制，使管理员可以集中管理用户访问与权限。项目级角色帮助管理员控制用户权限并定义每个用户在项目内可执行的操作，从而为数据与功能提供安全且受治理的访问。

### **2. 数据存储**

认证之后，AIDA 把上传的文档、[光学字符识别（OCR）](https://aws.amazon.com/what-is/ocr/)输出与相关元数据存放在 Amazon S3 中，为管理大量合同数据提供持久且成本高效的方式。结构化数据、配置与已提取的洞察持久保存在 Amazon RDS 中，用户可以有效地查询与检索洞察，用于分析与集成。

Amazon S3 存储桶在静态存储时使用 Amazon S3 托管的加密密钥（SSE-S3）加密，Amazon RDS 实例在静态存储时使用 AWS KMS 托管的密钥加密。此外，S3 存储桶的设置遵循 [Amazon S3 最佳实践](https://docs.aws.amazon.com/AmazonS3/latest/userguide/security-best-practices.html)，包括：在存储桶层面启用 Block Public Access，以及启用访问日志以用于安全分析与审计。

### **3. OCR 与预测处理**

OCR 与抽取工作流在 Amazon ECS 上使用 [AWS Fargate](https://aws.amazon.com/fargate/) 异步运行，任务通过 Amazon Simple Queue Service（[Amazon SQS](https://aws.amazon.com/sqs/)）协调。采用这种方式，用户可并行处理大量合同，而不会阻塞用户交互。

抽取规则决定如何识别相关内容并把它发送到托管在 Amazon Bedrock 上的基础模型（FM），由 LLM 解读合同文本并提取结构化取值。结果回写到 Amazon RDS，可供审查、仪表板与集成使用。

### **4. 检索增强生成（RAG）**

分析合同时，答案准确且能追溯到原始源文本至关重要。RAG 通过把模型响应建立在底层合同内容之上、而不是仅依赖模型知识，来帮助做到这一点。AIDA 使用 RAG 帮助验证响应确实以合同文本为依据。存放在 Amazon S3 中的文档使用 Amazon Bedrock Embeddings Models 生成 embedding，向量索引在 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/) 中用于语义搜索。在推理时，相关数据从 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 检索并与用户输入结合，产出准确、上下文感知且可解释的结果。

此外，AIDA 使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 实施内容过滤、敏感信息（PII）保护与 prompt 安全控制，进一步确认响应保持安全并符合企业与法律标准。

### **5. 可视化**

为展示合同的处理情况，AIDA 与 [AWS Quick Sight](https://aws.amazon.com/quicksuite/quicksight/) 集成，对文档数量、OCR 准确率、抽取吞吐量与处理状态等指标做可视化。

该仪表板可提供系统性能的可见性，并帮助随时间推移识别瓶颈或提升效率的机会。

### **6. 跨内部、供应商与第三方系统的系统集成**

AIDA 使用 [AWS Lambda](https://aws.amazon.com/pm/lambda/)、[Amazon EventBridge](https://aws.amazon.com/eventbridge/) 与 Amazon SQS 与下游系统集成。这些集成把已提取的洞察交付到合同生命周期管理工具、数据系统或其他运营系统。可配置的人在回路（human-in-the-loop）审查队列可以在结果向下游转发之前校验并批准抽出的输出。

通过把结构化合同数据推送到正在使用的工具中，组织可以减少手工数据处理，并在合规、报告与分析工作流中复用合同洞察。

### **7. 辅助与系统服务**

一系列辅助 AWS 服务为 AIDA 的核心系统提供安全、可观测性与自动化支持。AWS Identity and Access Management（[AWS IAM](https://aws.amazon.com/iam/)）与 AWS Key Management Service（[AWS KMS](https://aws.amazon.com/kms/)）管理访问与加密，其中 IAM 策略按最小权限原则实现；[Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 与 [AWS X-Ray](https://docs.aws.amazon.com/xray/latest/devguide/aws-xray.html) 提供监控；而 [AWS CodeBuild](https://aws.amazon.com/codebuild/)、[AWS CodePipeline](https://aws.amazon.com/codepipeline/) 与 [AWS CloudTrail](https://aws.amazon.com/cloudtrail/) 通过为数据操作启用访问日志，支持持续部署与可审计性。

接下来我们深入看 Amazon Bedrock 具体如何支撑这些带来效率提升的智能特性。

## Amazon Bedrock 如何支撑 AIDA 的智能特性

Amazon Bedrock 支撑 AIDA 的智能洞察、抽取与对话能力。通过把先进的 FM 集成到 AIDA 的处理 pipeline 中，Amazon Bedrock 实现了上下文感知的数据抽取、语义检索与交互式 chat 功能。AIDA 在统一工作流中编排文档处理、OCR、语义检索与 LLM 推理：依据查询或预定义规则检索相关章节，并使用 Amazon Bedrock 支撑 RAG、给出带明确源文档引用的回答。

为展示这些关键特性，我们向 AIDA 上传了来自[合同理解 Atticus 数据集（CUAD）](https://zenodo.org/records/4595826#.YEu3V-1Kh8o)的样例合同，这是由 The Atticus Project 的数十位法律专家创建的开放法律合同审查数据集。CUAD 数据集依据 Creative Commons Attribution 4.0（CC BY 4.0）许可公开提供，允许为研究与评估目的使用与分发。

### **1. 通过可复用模板实现更智能、更快速的洞察抽取**

*可复用模板*让用户只需定义一次抽取逻辑并在多份文档上应用，从而在规模化场景下抽取一致的合同属性。每个模板把代表关键合同要素的标签归为一组，例如终止通知期、续约条款或法律与合规团队经常审阅的权利条款。

当模板被应用到一组合同时，相同的抽取规则在各文档间被一致地使用。这有助于减少人工审查工作，同时提升准确性与一致性，尤其是在处理大量合同时。在背后，AIDA 使用保留页面与章节上下文的结构化表示来处理每份合同。抽取规则决定如何识别相关内容，LLM 则解读该上下文以提取正确的取值。结果返回时带有指向原始合同文本的引用，使你能够核实每条洞察从何而来。

例如，**Termination Notice Period** 标签会从下图中所示的合同里直接提取时间期限，而右侧面板显示抽出的答案（以绿色高亮），并带有可点击的引用，指向合同内的确切源文本。

![展示已抽取答案的 AIDA 示例](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/24/ML-19434-image-2.png)

### **2. 文档级 chat**

你可以使用*文档级 chat* 就单份合同提出自然语言问题，并获得直接基于该文档的回答。当需要就特定条款、日期或义务快速澄清时，这一能力尤其有用，可避免你手工浏览冗长复杂的协议。

提交问题时，AIDA 通过把查询与文档内容的语义表示做比对，识别出合同中最相关的章节。这些章节随后作为上下文提供给托管在 Amazon Bedrock 上的 LLM，由它依据合同文本生成回答。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/28/ML-19434-image-3.png)

### **3. Global chat **

*Global chat* 把文档级 chat 能力扩展为支持在项目内跨多份合同提问。当需要更宏观的视角时，例如识别通用条款、比较义务或总结一组相关协议的条款，这一特性很有用。

Global chat 有两种使用方式。一种场景是把问题放到项目内所有合同上评估，给出统一的、项目级的视角。另一种场景可以把问题限定在选定的一组合同上，因此用户可以在使用同一对话界面的同时聚焦于特定协议。

![AIDA Global Chat 示例](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/24/ML-19434-image-4.png)
 AIDA 帮助使用 Amazon Bedrock 从底层合同构建语义知识库，通过抽取并 embedding 文档内容以供搜索。这些 embedding 索引在 Amazon OpenSearch Serverless 中，形成一个可扩展的语义层，支持在庞大且多样的合同集合上查询。

提交问题时，AIDA 可以通过隐式与显式过滤相结合的方式检索相关段落。隐式过滤依赖查询与合同内容之间的语义相似度来找出上下文相关的章节。显式过滤施加元数据约束，例如合同类型、创建日期、业务单元或司法辖区，把结果缩小到最相关的子集。选定的上下文随后提供给托管在 Amazon Bedrock 上的 LLM，由它生成带有指回原始源文档引用的统一回答。

## 构建在 AIDA 系统之上的支撑能力

下一节介绍构建在 AIDA 系统之上的支撑能力：运营仪表板与外部系统集成。

### 运营仪表板

运营仪表板提供项目层面合同审查绩效的统一视图，跟踪文件数量、OCR 与洞察抽取的完成率、错误以及抽取准确率。它帮助团队快速发现瓶颈并监控审查人员的工作效率。

![AIDA 运营仪表板](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/24/ML-19434-image-5.png)

### 外部系统集成

AIDA 生成的结构化已抽取洞察可被快速推送到下游系统，例如合同生命周期管理（CLM）工具、ERP 系统、CRM 或数据仓库。这种集成帮助用高质量的、机器可读的合同数据丰富内部或外部系统，减少跨系统的手工数据重复录入与核对。通过把这些洞察直接嵌入这些系统，组织可以改进合规监控并支持更快、由数据驱动的决策。

# 结论

PwC 的 AI 驱动标注（AIDA）解决方案由 AWS 支撑，帮助组织从人工合同审查迈向更快、更可靠且可扩展的方式。通过把 OCR、用户定义的抽取规则与经由 Amazon Bedrock 的检索增强生成结合起来，AIDA 帮助快速识别埋在复杂合同中的关键条款、义务与洞察。

该方案帮助精简法务与运营工作流、缩短审查时间，并在大量文档上提升一致性。该方案构建在 AWS 的云原生服务之上，并像 Amazon ECS、Amazon S3、Amazon RDS 与 Amazon OpenSearch Serverless 那样按安全要求设计。AIDA 可以提供企业部署所需的灵活性与韧性。PwC 与 AWS 携手可以把合同数据转化为可行动的智能，让决策更明智、运营更高效。
