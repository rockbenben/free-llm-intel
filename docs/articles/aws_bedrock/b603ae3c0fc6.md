# 使用下一代 AgentCore runtime 安全高效地运行 agent

AI agent 早已不局限于一次性的 prompt。它们现在可以连续数小时运行多步骤工作负载。前沿 agent 能独立完成的 task 长度大约每四个月翻一番（[METR](https://metr.org/time-horizons/)），40% 的大型企业正在规模化使用 AI agent，高于一年前的 27%（[McKinsey](https://www.mckinsey.com/capabilities/quantumblack/our-insights/the-state-of-ai)）。随着 agent 运行时间更长、自主性更强，关注点从 agent 能做什么，转向它们能否在规模化下安全、可靠、经济地运行。agent 做的事比传统软件更多：执行代码、操作浏览器、访问敏感数据，并代表用户采取行动。这些能力带来了新的安全与基础设施要求，使强隔离成为生产部署的关键。

每个 agent 会话都需要一个安全、隔离的环境。但要在规模化下提供这种隔离，会带来一个根本性挑战：在性能、成本与效率之间取得平衡。预置环境即便空闲也在消耗资源，推高成本。按需环境减少了闲置容量，却带来冷启动延迟，拖慢 agent 的执行。两种方式都无法在不做取舍的前提下高效扩展。当组织从部署少量 agent 转向运行数千个并发会话时，构建和管理自定义沙盒会变得越来越复杂、昂贵且不可预测。

这一挑战显而易见。只有 15% 的组织实现了编排式多 agent 系统的规模化，70% 表示还无法信任并治理自己的 agent（[Deloitte](https://www.deloitte.com/us/en/about/press-room/deloitte-survey-examines-ai-readiness-agentic-ai-success.html)）。规模化 agent 不应意味着要在安全、速度和成本之间做取舍。下一代 agent 基础设施必须在提供强隔离的同时，具备快速启动、弹性扩展和按用量计费的经济性。因为随着 AI agent 进入生产，安全执行不应成为瓶颈，它应当成为让规模化成为可能的基石。通往生产的最快路径，也应当是最安全的那条。

## 下一代 AgentCore runtime

我们构建 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 是为了帮助开发者在规模化下安全地构建、连接和优化 agent。AgentCore runtime 是 Amazon Bedrock AgentCore 的一项能力，即托管计算层。它为开发者提供一个全托管环境，无需构建或维护基础设施即可部署和运行 agent。自发布以来，客户不断把 agent 推向越来越复杂的工作负载。随着这些工作负载增长，对执行环境的要求也在提高：更多算力、更灵活的计费，以及延伸到数据（而不只是计算）的信任边界。只有底层基础设施同时为规模和速度而建，agent 才能大规模进入生产。

今天，我们宣布 AgentCore runtime 的更新，以满足这些要求。核心保证不变：每个会话都运行在自己硬件隔离的 Firecracker micro virtual machine (MicroVM) 中，拥有自己的身份、策略和审计轨迹。这些更新在这一保证之下拓展了可能性。现在会话启动最快提升 15 倍，算力可扩展到 4 倍，运行效率最高提升 68%，且隔离边界完好无损。

下面是这次的新变化。

## 运行更大的工作负载，无需更长的启动等待

构建越来越先进 agent 的团队希望获得更大灵活性：能够在隔离会话内扩展内存和算力，以匹配工作负载的需求。从大型代码库编译、浏览器驱动的工作流，到本地模型推理，执行环境都需要跟得上。

与上一版本相比，会话现在可扩展 4 倍，最高 8 vCPU 和 32 GB，并支持最大 10 GB 的容器镜像。会话启动时间低于 2 秒，且不受镜像大小和并发数影响。你不再需要预热池和预置集群来应对冷启动。

## 不再为空闲的 agent 付费

随着团队把 agent 推向生产，他们希望计费方式能反映 agent 实际的工作方式。agent 大部分时间都在等待模型响应、工具调用或人的决策。agent 应当按实际做的工作计费，而不是按等待的时间计费。

现在，runtime 会在 agent 释放内存后几分钟内回收，空闲的 agent 则缩容到零。对于交互之间天然存在停顿的多轮 agent，这意味着每个会话的内存消耗最多降低 68%。对于常驻 agent，承诺基线定价为每个会话设定一个内存基线，按最低量计费，并允许按需突发到该基线的四倍。这让稳定工作负载能以 AWS Lambda MicroVM 费率获得可预期的价格。runtime 更高效地使用算力，因此同样的工作你付得更少。这也让常常卡住生产上线的财务对话更容易谈成。

## 隔离现在延伸到你的数据

许多企业的 agent 安全模型存在一道长期缺口。agent 运行在隔离会话内，但它所需的数据却位于该边界之外。长时间运行的 agent 会一路积累上下文：文件、凭证、工具输出等等。团队最终不得不自行制定数据进出的规则，每新增一个 agent 就多一分复杂性和风险。

只停留在计算层的隔离，只是半道边界。下一代 AgentCore runtime 补上了这道缺口。每个会话仍运行在自己硬件隔离的环境中，拥有自己的身份、访问策略和审计轨迹。agent 现在可以动态挂载文件系统并把工作成果保存其中，例如支持 FUSE 的 Amazon Simple Storage Service (Amazon S3) bucket。你的数据在整个任务期间都留在信任边界内，由你一次性定义的统一控制策略来治理。

## 我们的承诺

能进入生产的 agent，是那些你放心让它们代表你行动的 agent——面对真实数据、真实利害、真实责任。信任不是事后补上的功能，而是你赖以构建的 runtime。这次发布是朝那个未来迈出的一步：更大的会话、更高效的资源利用、位于信任边界内的存储，同时不放松让工作值得信赖的隔离。到 re:Invent 时，会话级作用域将通过带会话标签的凭证，把每个会话绑定到自己的存储文件夹，我们也会在此基础上继续构建。
