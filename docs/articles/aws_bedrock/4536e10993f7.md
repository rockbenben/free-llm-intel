# 使用 Amazon SageMaker Canvas 在 GS Caltex 进行生产 MLOps，第 1 部分

[GS Caltex](https://www.gscaltex.com/en) 使用 [Amazon SageMaker Canvas](https://aws.amazon.com/sagemaker/canvas/) 和 [Amazon SageMaker Pipelines](https://aws.amazon.com/sagemaker/ai/pipelines/) 将流程工程师的模型连接到生产工作流程。这家韩国能源和化工公司将模型开发和运营分给了技能互补的工程师。

流程工程师无需编写代码，即可利用其流程知识在 SageMaker Canvas 中构建和验证模型。机器学习 (ML) 工程师配置 SageMaker Pipelines 工作流程以进行部署和计划推理。

将资产从 SageMaker Canvas 转移到 SageMaker Pipelines 仍然需要集成工作。机器学习工程师必须设置生产数据路径、提供模型配置并连接预处理和推理作业。 GS Caltex 自动执行此交接，同时重用在 SageMaker Canvas 中创建的资产。

GS Caltex 报告称，其 ML 工程师现在可以在几个小时内部署模型，而之前需要大约一周的时间。该公司每 30 分钟运行一次批量推理，减少了对连续运行端点的需求。 GS Caltex 报告称，这显着降低了推理成本。

这篇文章介绍了 GS Caltex 如何将 SageMaker Canvas 连接到 SageMaker Pipelines，并在生产中重用经过验证的预处理流程和模型。

## 解决方案概述

机器学习操作 (MLOps) 工作流有两个路径：准备新的模型版本以进行部署，以及使用已部署的模型运行批量推理。

### 从经过验证的模型到可重复的工作流程

您可以使用 SageMaker Canvas 直观地准备数据、构建模型并生成批量预测。您还可以通过 SageMaker Canvas 在 Amazon SageMaker 模型注册表中注册经过验证的模型。 GS Caltex 构建了一个单独的移交流程，将这些资产转化为可执行的 SageMaker Pipelines 步骤。

流程工程师了解流程背后的变量和数据，并评估模型的预测是否有用。机器学习工程师将生成的资产转化为生产作业并管理模型版本和执行历史记录。

| **面积** | **SageMaker Canvas 中准备了什么** | **生产工作流程中管理什么** |
| --- | --- | --- |
|数据准备 |使用 Data Wrangler 构建的预处理流程 | Amazon SageMaker 处理中的预处理作业 |
|模型开发|训练好的模型和评估结果 |模型注册表中的模型版本和批准状态 |
|预测|模型预测的验证 |使用批准的模型每 30 分钟进行一次批量推理 |
|运营|单个模型的开发和验证 |步骤执行历史记录、存储结果和故障处理 |

ML 工程师从 SageMaker Canvas 接收预处理流程和模型，并检查数据格式和预测结果。审核后，他们在模型注册表中批准该模型并进行部署。此准备工作在部署新模型版本时进行。后续推理运行将重用已部署的模型。

Amazon EventBridge 启动每个计划的运行。 SageMaker Pipelines 准备来自 Amazon Simple Storage Service (Amazon S3) 的输入数据，运行预处理和 [SageMaker 批量转换](https://docs.aws.amazon.com/sagemaker/latest/dg/batch-transform.html)，并将结果存储在 S3 中。 ML 工程师可以检查步骤状态和 Amazon CloudWatch 日志来监控工作流程。

生产管道重用在 SageMaker Canvas 中创建的预处理逻辑和经过训练的模型。 ML 工程师配置输入和输出路径，设置执行顺序，并编写将审批和调度连接到工作流程的代码。

## 先决条件

在开始之前，请准备以下内容：

- [在 SageMaker Canvas 中构建和评估的模型](https://docs.aws.amazon.com/sagemaker/latest/dg/canvas-custom-models.html) 及其 [Data Wrangler 预处理流程](https://docs.aws.amazon.com/sagemaker/latest/dg/canvas-data-prep.html)
- 用于推理的 CSV 数据和用于存储文件的 S3 存储桶。
- [SageMaker 执行角色](https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-roles.html) 和 [具有启动管道权限的 Amazon EventBridge 角色](https://docs.aws.amazon.com/sagemaker/latest/dg/pipeline-eventbridge.html)
- 安装了 Boto3 和 SageMaker Python SDK 2.x 的 Python 环境。

完整的参考实现可在 [GitHub 存储库](https://github.com/aws-samples/sample-canvas-to-pipelines-mlops) 中找到。本文中的代码示例重点关注组件之间的连接。该存储库使用示例贷款分类模型，因此请调整配置以匹配模型的输入和输出格式。

## 技术实现

以下步骤涵盖预处理重用、模型批准和部署、管道构建和计划推理。

### 1. 使用 SageMaker Processing 运行 SageMaker Canvas 预处理流程

在 SageMaker Canvas 中使用 Data Wrangler 创建的预处理流程记录数据源和转换步骤。要设置参考实现，请使用 SageMaker Processing 将数据导出到 Amazon S3，然后检索作业设置和该作业使用的“.flow”文件。

在导出设置中，关闭 **自动作业配置** 并选择 **SageMaker 处理**。导出开始后，在 Amazon SageMaker AI 控制台上打开处理作业详细信息。记录容器映像 URI、名为“flow”的输入的 S3 URI、执行角色和输出设置。使用这些值来配置运行“.flow”文件的管道步骤。

SageMaker 执行角色必须有权读取所需的 S3 数据、写入结果以及访问容器映像。根据您需要处理的数据量选择实例类型和计数。

保持工艺工程师验证预处理逻辑，并调整生产环境的数据源、路径和其他设置。根据原始作业配置检查容器映像和输出节点。

| **要检查的项目** | **做什么** |
| --- | --- |
|输入位置 |检查“.flow”文件中数据源引用的 S3 URI。将原始数据上传到另一个位置不会更新此引用。 |
|容器镜像|使用 S3 导出期间创建的处理作业中的图像，并固定可重现已验证转换的版本。 |
|输出 ID |使用导出配置中的输出节点和输出名称。如果所需格式为“{node_id}.{output_name}”，请完全匹配。 |
|学习转型价值观 |保留训练期间学到的值，例如缩放和编码参数。不要在每个推理批次上重新安装它们。 |
|验证 |比较 SageMaker Canvas 和处理针对相同输入生成的列、数据类型和转换值。 |

某些“.flow”文件包含执行元数据，例如“internal_metadata.dw_job.container_uri”。检查实际的处理作业设置，而不是假设每个导出都包含此字段。如果您将工作流程移动到另一个 AWS 区域，请验证容器映像在该区域是否可用。

参考实现通过在“runs/<execution-id>/”下执行来分离中间输出和最终输出。其“PrepareInput”步骤将数据写入“.flow”文件引用的固定 S3 位置。防止共享该输入路径的执行重叠。

为了隔离每次执行的输入数据，请添加一个准备步骤，更新“.flow”文件副本中的源 URI。声明 SageMaker Pipelines 参数不会自动替换文件内的 URI。

### 2. 处理训练和推理输入之间的差异

目标列是训练数据和推理数据之间的区别之一。使用训练数据构建的流可以包含期望输入模式中的目标列的转换。推理数据不包含该已知结果。

参考实现在预处理之前添加了“PrepareInput”步骤。如果目标列缺失，此步骤将为其添加占位符值。预处理后，“DropTargetColumn”会删除该列。将占位符的数据类型和列位置与训练模式相匹配，并仅按原始顺序将预期特征传递给模型。
```
PrepareInput -> PreprocessNewData -> DropTargetColumn
             -> BatchPredict -> AssembleResults
```
仅当占位符目标不影响特征值时才使用此方法。按目标过滤行、从中派生特征或应用目标编码的流需要额外处理。在这些情况下，将推理所需的转换和学习状态分开。

验证应涵盖列顺序和计数、数据类型、缺失值处理和行计数。删除目标后，检查剩余列是否与训练期间使用的特征顺序匹配。

### 3. 注册、批准和部署模型

在 [模型注册表](https://docs.aws.amazon.com/sagemaker/latest/dg/canvas-register-model.html) 中注册经过验证的 SageMaker Canvas 模型版本。注册版本可以包括模型文件、推理配置和评估结果。 ML 工程师在更改批准状态之前会审查此信息。

模型文件（例如“model.tar.gz”）必须与正确的推理容器和环境设置一起使用。模型注册表中的模型包将这些信息组合在一起。在此批处理架构中，部署从批准的包中创建 SageMaker 模型资源以供批量转换引用。

以下示例检查已批准的包，然后创建模型资源。在部署期间提供 `model_package_arn`、`model_name` 和 `sagemaker_role_arn`。此示例为每个版本使用唯一的型号名称。
```
import boto3

sm_client = boto3.client("sagemaker")
package = sm_client.describe_model_package(
    ModelPackageName=model_package_arn
)

if package["ModelPackageStatus"] != "Completed":
    raise RuntimeError("Model package is not ready")
if package["ModelApprovalStatus"] != "Approved":
    raise RuntimeError("Model package is not approved")

sm_client.create_model(
    ModelName=model_name,
    ExecutionRoleArn=sagemaker_role_arn,
    PrimaryContainer={"ModelPackageName": model_package_arn},
)
```
模型注册表记录批准状态，但它不会对每个推理请求强制执行批准检查。检查部署代码中的状态并在管道配置中保留选定的包 ARN 和模型名称。如果批准被撤销，请更新使用该模型的计划和执行配置。

模型版本发布时进行注册和部署。每 30 分钟运行一次的管道使用该模型创建批量转换作业，因此不需要在每次运行时再次注册模型。

### 4. 连接预处理、推理和结果组装

推理管道有五个步骤。

| **步骤** | **功能** | **输入和输出** |
| --- | --- | --- |
| `准备输入` |如果需要，添加占位符目标列 |新的推理数据 -> 提供目标列的数据 |
| `预处理新数据` |运行 SageMaker Canvas 预处理流程 |准备好的输入和 `.flow` -> 转换后的数据 |
| `DropTargetColumn` |删除目标列和 CSV 标题 |转换后的数据 -> 没有标题的 CSV |
| `批量预测` |使用批准的模型运行批量推理 |特征 CSV -> 预测文件 |
| `组装结果` |将预处理数据与预测相结合 |预处理数据和预测文件 -> 最终结果 CSV |

在连接步骤之前配置每个作业。在以下示例中，“prepare_args”、“preprocess_args”、“drop_target_args”和“assemble_args”保存使用“PipelineSession”的处理器上的“run()”调用返回的步骤参数。处理器和“transformer”共享“pipeline_session”对象。使用之前部署的“model_name”配置“transformer”。
```
from sagemaker.workflow.pipeline import Pipeline
from sagemaker.workflow.steps import ProcessingStep, TransformStep

prepare = ProcessingStep(
    name="PrepareInput", step_args=prepare_args
)
preprocess = ProcessingStep(
    name="PreprocessNewData",
    step_args=preprocess_args,
    depends_on=[prepare],
)
drop_target = ProcessingStep(
    name="DropTargetColumn",
    step_args=drop_target_args,
    depends_on=[preprocess],
)

# The DropTargetColumn job defines an output named "features".
features_uri = (
    drop_target.properties.ProcessingOutputConfig
    .Outputs["features"].S3Output.S3Uri
)
predict = TransformStep(
    name="BatchPredict",
    step_args=transformer.transform(
        data=features_uri,
        content_type="text/csv",
        split_type="Line",
    ),
)
assemble = ProcessingStep(
    name="AssembleResults",
    step_args=assemble_args,
    depends_on=[predict],
)

pipeline = Pipeline(
    name="canvas-process-inference",
    steps=[prepare, preprocess, drop_target, predict, assemble],
    sagemaker_session=pipeline_session,
)
pipeline_arn = pipeline.upsert(role_arn=sagemaker_role_arn)["PipelineArn"]
```

使用“depends_on”控制执行顺序，并通过步骤输出属性传递数据。例如，“assemble_args”必须接收预处理数据的位置和“predict.properties.TransformOutput.S3OutputPath”。输出名称“features”属于“DropTargetColumn”。 Data Wrangler 步骤使用在其预处理流程中定义的输出 ID。

在参考实现中，“AssembleResults”将预处理的数据和按行位置的预测结合起来。在生产中使用它之前，添加检查文件顺序和行计数是否匹配，如果不匹配则停止结果生成。如果预处理对行进行排序或删除，请维护源记录 ID 和预测之间的显式映射。

### 5. 每 30 分钟安排一次推理

GS Caltex 每 30 分钟运行一次推理。以下示例使用 [Amazon EventBridge 规则来安排 SageMaker Pipelines 执行](https://docs.aws.amazon.com/sagemaker/latest/dg/pipeline-eventbridge.html)。创建管道并在附加计划之前通过手动运行对其进行验证。
```
import boto3

events_client = boto3.client("events")
rule_name = "canvas-process-inference-every-30-minutes"

events_client.put_rule(
    Name=rule_name,
    ScheduleExpression="rate(30 minutes)",
    State="ENABLED",
)

result = events_client.put_targets(
    Rule=rule_name,
    Targets=[{
        "Id": "canvas-process-inference",
        "Arn": pipeline_arn,
        "RoleArn": eventbridge_role_arn,
    }],
)
if result["FailedEntryCount"]:
    raise RuntimeError(result["FailedEntries"])
```
将 `eventbridge_role_arn` 设置为信任 Amazon EventBridge 服务委托人 `events.amazonaws.com` 的角色，并具有目标管道的 `sagemaker:StartPipelineExecution` 权限。 `pipeline_arn` 值标识在上一步中创建的管道。

表达式“rate(30 分钟)”计划以 30 分钟的间隔运行。要按整点和半点运行，请使用“cron(0/30 * * * ? *)”。决定每个运行在输入准备步骤中处理哪个数据窗口，并在执行时记录它。

## 操作注意事项

在启用计划运行之前，请检查总成本、执行时间以及无效或不匹配数据的处理。

### 评估整个工作流程中的批次成本

[Amazon SageMaker Pipelines](https://aws.amazon.com/sagemaker/ai/pipelines/) 是一种无服务器工作流程编排服务。它可以管理执行顺序和依赖关系，而无需您配置或维护工作流服务器。处理和批量转换作业使用单独的计算资源，并根据实例类型和持续时间计费。

预配置的实时端点非常适合需要持续低延迟响应的请求。批量转换适合可以一起处理一组记录的工作负载。它会在作业完成时释放作业的计算资源，因此您可以运行预测，而无需为每个模型保持推理端点持续运行。

| **考虑** | **配置的实时端点** | **具有批量转换功能的 SageMaker 管道** |
| --- | --- | --- |
|资源生命周期|实例仍可用于服务请求 |为每个作业配置和释放资源 |
|成本驱动因素|端点正常运行时间和容量|作业持续时间、频率、实例计数和支持服务 |
|适合的工作负载 |立即响应和持续的在线请求 |按预定时间间隔处理累积数据 |
|添加模型 |端点容量和持续托管成本|附加处理、作业持续时间和并发限制 |

30 分钟的时间表每天产生 48 次预定跑步。估计总运行时间时包括预处理、实例启动、推理和后处理。成本比较还应考虑处理、S3、CloudWatch 以及工作流使用的其他服务。

使用测量的使用情况评估每个工作负载的成本，包括支持服务和每个计划作业的完整运行时间。

### 检查运行时和重叠执行

每 30 分钟开始一次跑步的计划并不能保证每次跑步都能在该时间间隔内完成。使用代表性数据测量完整管道运行时间，包括实例启动和重试失败作业所需的时间。

决定如何处理在上一个执行完成之前到达的计划运行。控制管道内的并行步骤不会阻止单独的管道执行重叠。检查活动执行，防止同一输入窗口的重复处理，并分隔每次运行的输出路径。

记录每次运行的输入数据窗口、预处理流程版本、模型包 ARN、管道执行 ARN 和输出位置。这些详细信息有助于重现结果并调查错误。

### 验证输出和失败行为

在启用计划之前完成以下检查：

- 通过 SageMaker Canvas 和处理运行验证数据集。比较输出列、数据类型、行计数和键转换值。
- 检查添加占位符目标是否不会更改特征值，并且目标是否已从模型输入中删除。
- 使用批准的模型版本运行批量转换并验证源记录和预测之间的关联。
- 确认无效的输入模式或预处理失败会阻止下游推理和结果发布。
- 测量运行时间和成本，测试同一输入窗口的重叠执行和重新处理，然后启用 30 分钟计划。

添加针对作业失败和处理延迟的 CloudWatch 警报，以及根据需要的数据质量或模型监控。根据测量的运行时间和数据特征设置初始阈值，并在模型或数据量发生变化时查看它们。

## 采用方法和结果

通过分阶段推出，团队可以在跨模型标准化切换之前验证切换。以下部分描述了采用方法和 GS Caltex 报告的结果。

### 从模型开发转向常规运营

首先验证一个模型的生产路径，然后标准化跨部署重复的步骤。以下顺序是根据 GS Caltex 经验建议的采用方法。

| **舞台** | **目标** | **范围** |
| --- | --- | --- |
|爬行|在生产中重现开发成果 |验证 SageMaker Canvas 模型，将其注册到模型注册表中，然后手动运行管道 |
|步行|建立可靠的计划运行 |检查批准、按要求的时间间隔安排运行、添加故障警报并通过执行管理输出 |
|运行|跨模型复用操作流程|引入通用模板、持续集成和持续交付 (CI/CD)、变更验证以及转移运营责任的程序 |

随着自动化的扩展，过程工程师继续评估预测是否对过程有用。机器学习工程师管理管道的执行和变更。

GS Caltex 减少了将 SageMaker Canvas 模型连接到生产所需的重复工作。机器学习工程师现在可以在几个小时内部署模型，而之前需要大约一周的时间。他们还重复使用流程工程师在 SageMaker Canvas 中验证的资产。

工艺工程师在看到他们的模型在生产中使用后，开始建议在其他工艺中的应用。机器学习工程师花更少的时间重复集成工作，可以专注于操作和监控管道。

## 清理测试资源

对于测试部署，请禁用 Amazon EventBridge 规则并首先删除其目标。活动管道执行和作业完成后，删除测试管道及其 SageMaker 模型资源。

如果您创建了用于测试的实时端点，请将其也删除。从 S3 中删除输入、中间和预测文件，并根据您的保留策略清理 CloudWatch 日志。在删除它们之前，检查其他执行或审计要求是否仍然依赖于模型文件和模型注册表版本。

＃＃ 结论

在 GS Caltex，流程工程师在 SageMaker Canvas 中创建和验证模型，ML 工程师使用这些资产在 SageMaker Pipelines 中运行生产工作流程。这种切换减少了重复的集成工作。 GS Caltex 报告称，机器学习工程师现在可以在几个小时内完成模型部署，而之前需要大约一周的时间。

移交需要包括预处理流程、输入模式、推理配置和批准流程以及模型文件。验证工作流程是否重现了预期结果，并且可以按要求的计划可靠地运行。

要尝试此方法，请从您在 SageMaker Canvas 中验证的一个模型开始，并使用 [GitHub 存储库](https://github.com/aws-samples/sample-canvas-to-pipelines-mlops)。有关定义和运行工作流程的详细信息，请参阅 [SageMaker Pipelines 开发人员指南](https://docs.aws.amazon.com/sagemaker/latest/dg/pipelines.html)。通过手动执行检查预处理和批量预测结果，然后安排按照应用程序需要的时间间隔运行。
