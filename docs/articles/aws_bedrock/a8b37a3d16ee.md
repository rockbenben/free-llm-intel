# 使用 Amazon Bedrock Agents 构建虚拟气象学家

[生成式 AI](https://aws.amazon.com/ai/generative-ai/) 能力的集成正在推动许多行业的变革。尽管天气信息可以通过多种渠道获取，但高度依赖气象数据的企业需要稳健且可扩展的解决方案，以有效管理和利用这些关键洞察并减少人工流程。本解决方案演示如何创建一个 AI 驱动的虚拟气象学家，它能够用自然语言回答复杂的天气相关问题。我们使用多种 AWS 服务部署一套完整解决方案，让你可以与提供实时天气信息的 API 交互。在本解决方案中，我们使用 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/)。

Amazon Bedrock Agents 有助于精简 workflow 并自动化重复性任务。Amazon Bedrock Agents 可以安全地连接到公司的数据源，并用准确的响应增强用户的请求。你可以使用 Amazon Bedrock Agents 设计符合自身要求的 action schema，从而在 agent 发起指定动作时保持控制。这种灵活的方式让你能够在偏好的后端服务中无缝集成并执行业务逻辑，形成功能与灵活性的紧密结合。交互过程中还会保留记忆，从而带来更个性化的用户体验。

本文介绍一种精简的方式：把 Amazon Bedrock Agents 与[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM）结合，部署一个 AI 驱动的 agent。我们会带你完成 agent 的配置过程，并实现虚拟气象学家提供准确天气相关响应所需的特定逻辑。此外，我们还使用了多种 AWS 服务，包括用于托管前端的 [AWS Amplify](https://aws.amazon.com/amplify/)、用于处理请求逻辑的 [AWS Lambda](https://aws.amazon.com/lambda/) 函数、用于用户认证的 [Amazon Cognito](https://aws.amazon.com/cognito/)，以及用于控制 agent 访问权限的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）。

## 解决方案概览

下图给出总体概览并突出关键组件。该架构使用 Amazon Cognito 进行用户认证，使用 Amplify 作为前端应用的托管环境。Amazon Bedrock Agents 会把用户查询中的细节转发给 action group，后者再调用自定义 Lambda 函数。每个 action group 和 Lambda 函数负责一项特定任务：

- **geo-coordinates** —— 处理地理坐标（geo-coordinates），获取特定位置的详细信息
- **weather** —— 收集所提供位置的天气信息
- **date-time** —— 获取当前日期和时间

## 先决条件

要完成本文的解决方案，你必须先具备以下条件：

- 一个 [AWS 账户](https://signin.aws.amazon.com/signup?request_type=builderId)
- 在部署本解决方案的同一 [AWS 区域](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region)中，具备在 Amazon Bedrock 中访问 Anthropic 的 Claude 3.5 Sonnet 的 FM [访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)

## 部署 AWS Amplify 应用

你需要使用 GitHub 上的前端代码手动部署 Amplify 应用。请完成以下步骤：

- 从 [GitHub](https://github.com/aws-samples/virtual-meteorologist-using-amazon-bedrock-agents) 下载前端代码 AWS-Amplify-Frontend.zip。
- 使用该 .zip 文件在 Amplify 中手动[部署](https://docs.aws.amazon.com/amplify/latest/userguide/manual-deploys.html)应用。
- 返回 Amplify 页面，使用它自动生成的域名访问应用。

### 使用 Amazon Cognito 进行用户认证

Amazon Cognito 是一项身份服务，可用于对用户进行认证和授权。在我们的解决方案中，我们使用 Amazon Cognito 在用户使用应用前验证其身份。我们还使用身份池，在用户与 Amazon Bedrock API 交互期间为其提供临时 AWS 凭证。

### 使用 Amazon Bedrock Agents 自动化应用任务

借助 Amazon Bedrock Agents，你可以在应用中构建和配置自主 agent。agent 帮助最终用户基于组织数据和用户输入完成各种动作。agent 编排 FM、数据源、软件应用与用户对话之间的交互。

### 使用 action group 定义 Amazon Bedrock agent 执行的动作

action group 定义了一组相关动作，Amazon Bedrock agent 可以执行这些动作来帮助用户。配置 action group 时，你有多种方式处理用户提供的信息，包括把用户输入添加到 agent 的 action group、把数据传给 Lambda 函数以执行自定义业务逻辑，或直接通过 InvokeAgent 响应返回控制权。在我们的应用中，我们创建了三个 action group，为 Amazon Bedrock agent 提供这些必要功能：检索特定位置的坐标、获取当前日期与时间信息，以及获取给定位置的天气数据。这些 action group 让 agent 能够访问并处理关键信息，增强其准确、全面回答与位置服务和天气状况相关用户查询的能力。

### 为 Amazon Bedrock action group 使用 Lambda

作为该解决方案的一部分，部署了三个 Lambda 函数，以支持为 Amazon Bedrock agent 定义的 action group：

- **位置坐标 Lambda 函数** —— 该函数由 `obtain-latitude-longitude-from-place-name` action group 触发。它接收地名作为输入，并返回相应的经纬度坐标。该函数使用地理编码服务或数据库执行这一查询。
- **日期与时间 Lambda 函数** —— 该函数由 `get-current-date-time-from-timezone` action group 调用，提供当前的日期与时间信息。
- **天气信息 Lambda 函数** —— 该函数由 `obtain-weather-information-with-coordinates` action group 调用。它接收来自第一个 Lambda 函数的地理坐标，并返回指定区域的当前天气状况和预报。该 Lambda 函数使用天气 API 获取最新的气象数据。

这些 Lambda 函数各自接收一个输入事件，其中包含来自 Amazon Bedrock agent 的 API 操作或函数参数的相关元数据和已填充字段。这些函数处理该输入、执行各自的特定任务，并返回包含所需信息的响应。随后，Amazon Bedrock agent 使用该响应来组织对用户查询的回复。通过使用这些 Lambda 函数，我们的 Amazon Bedrock agent 获得了访问外部数据源并执行复杂计算的能力，显著增强其处理与位置、时间和天气信息相关用户请求的能力。

### 使用 AWS Amplify 托管前端代码

Amplify 提供用于构建安全、可扩展的移动和 Web 应用的开发环境。开发者可以专注于代码，而不必担心底层基础设施。Amplify 还与许多 Git 提供商集成。对于本解决方案，我们使用本文前面介绍的方法手动上传前端代码。

## 示例用例

以下是几个示例查询，用于演示你的虚拟气象学家的能力：

- “纽约市今天天气怎么样？”
- “下周末我该在迈阿密安排一场户外生日派对吗？”
- “丹佛圣诞节当天下雪吗？”
- “今天我能去芝加哥的海滩游泳吗？

这些查询展示了 agent 提供当前天气信息、基于天气预报给出建议以及预测未来天气状况的能力。你甚至可以问一个与游泳之类的活动相关的问题，它会根据天气状况回答该活动是否适合进行。

## 清理

如果你决定不再使用虚拟气象学家，可以按以下步骤删除它、通过 AWS CloudFormation 部署的相关资源以及 Amplify 部署：

- 删除 CloudFormation 堆栈：在 AWS CloudFormation 控制台的导航窗格中选择 **Stacks**。找到你在部署过程中创建的堆栈（你为它指定了名称）。选中该堆栈，然后选择 **Delete**。
- 删除 Amplify 应用及其资源。相关说明请参阅[清理资源](https://aws.amazon.com/getting-started/hands-on/build-web-app-s3-lambda-api-gateway-dynamodb/module-six/)。
