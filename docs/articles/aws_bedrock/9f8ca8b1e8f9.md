# 如何借助 AWS Lambda 为 Amazon Nova 模型定制构建有效的奖励函数

构建有效的奖励函数可以帮助你针对自身需求定制 [Amazon Nova](https://aws.amazon.com/nova/) 模型，而 [AWS Lambda](https://aws.amazon.com/pm/lambda/) 提供了可扩展、成本低廉的基础。Lambda 的无服务器架构让你可以专注于定义质量标准，而由它来处理计算基础设施。

Amazon Nova 提供多种定制方法，其中[强化微调](https://docs.aws.amazon.com/bedrock/latest/userguide/reinforcement-fine-tuning.html)（Reinforcement fine-tuning，RFT）尤为突出，它能通过迭代反馈教会模型期望的行为。与需要数千个带标注推理路径的样本的[监督微调](https://docs.aws.amazon.com/bedrock/latest/userguide/nova-2-sft-data-prep.html#nova-2-dataset-preparation)（Supervised fine-tuning，SFT）不同，RFT 从针对最终输出的评估信号中学习。RFT 的核心是奖励函数——一种引导模型产出更好响应的评分机制。

本文演示 Lambda 如何为 Amazon Nova 定制提供可扩展、成本低廉的奖励函数。你将学会在面向可客观验证任务的[基于可验证奖励的强化学习（RLVR）](https://docs.aws.amazon.com/bedrock/latest/userguide/reward-functions.html#rft-rlvr)与面向主观评估的[基于 AI 反馈的强化学习（RLAIF）](https://docs.aws.amazon.com/bedrock/latest/userguide/reward-functions.html#rft-rlaif)之间做出选择，设计多维度的奖励系统以帮助防止 reward hacking，针对训练规模优化 Lambda 函数，并用 [Amazon CloudWatch](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/WhatIsCloudWatch.html) 监控奖励分布。文中还包含可运行的代码示例与部署指引，帮助你立即开始实验。

## **使用 AWS Lambda 构建基于代码的奖励**

定制基础模型有多种路径，各自适合不同的场景。当你拥有清晰的输入输出示例、想教会模型特定的响应模式时，SFT 表现出色——它对分类、命名实体识别，或让模型适配领域特有的术语与格式约定等任务尤其有效。当期望行为可以通过示例演示出来时，SFT 效果很好，因此它非常适合教会模型一致的风格、结构或事实性知识迁移。不过，有些定制挑战需要不同的思路。当应用需要模型同时平衡多个质量维度时——比如客服回复必须同时做到准确、有同理心、简洁且符合品牌调性——或者当构建数千条带标注的推理路径并不现实时，基于强化学习的方法提供了更好的替代方案。RFT 通过从评估信号中学习来应对这些场景，而无需穷尽式地标注演示正确的推理过程。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/08/ML-204191.jpeg)

基于 AWS Lambda 的奖励函数通过基于反馈的学习简化了这一过程。你不需要向模型展示数千个有效示例，而是提供 prompt 并定义对响应进行评分的评估逻辑——模型随后通过迭代反馈学会改进。这种方法需要的标注样本更少，同时让你对期望行为有精确的控制。多维度评分能够捕捉细微的质量标准，防止模型钻空子走捷径；而 Lambda 的无服务器架构可以处理波动变化的训练负载，无需管理基础设施。最终结果是：不具备深厚机器学习专业知识的开发者也能上手 Nova 定制，同时它又足够灵活，可以支撑复杂的生产用例。

## **基于 AWS Lambda 的奖励机制如何工作**

RFT 架构把 AWS Lambda 用作无服务器的奖励评估器，与 Amazon Nova 训练 pipeline 集成，形成一个引导模型学习的反馈闭环。流程开始于你的训练任务针对每个训练 prompt 从 Nova 模型生成候选响应。这些响应流入你的 Lambda 函数，由它在正确性、安全性、格式和简洁性等维度上评估其质量。函数随后返回标量数值分数——作为最佳实践，通常取 -1 到 1 的区间。较高的分数引导模型强化产生该响应的行为，较低的分数则引导它远离导致糟糕响应的模式。这个循环在整个训练过程中重复数千次，逐步把模型塑造成能持续获得更高奖励的响应。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/08/ML-204192.jpeg)

该架构把若干 AWS 服务整合为一个紧密协作的定制方案。Lambda 执行你的奖励评估逻辑，并自动伸缩以应对波动的训练需求，你无需预置或管理基础设施。Amazon Bedrock 提供完全托管的 RFT 体验并内建对 Lambda 的支持，通过简单的应用程序编程接口（API）为 RLAIF 实现提供 AI 评判模型。对于需要高级训练控制的团队，[Amazon SageMaker AI](https://docs.aws.amazon.com/sagemaker/latest/dg/whatis.html) 通过 [Amazon SageMaker AI 训练作业](https://docs.aws.amazon.com/nova/latest/userguide/nova-model-training-job.html)和 [Amazon SageMaker AI HyperPod](https://docs.aws.amazon.com/nova/latest/userguide/nova-hp.html) 提供选项，两者都支持同样的基于 Lambda 的奖励函数。Amazon CloudWatch 实时监控 Lambda 的性能，记录关于奖励分布与训练进度的详细调试信息，并在出现问题时触发告警。最底层是 Amazon Nova 本身——它在大量用例上优化过定制配方，能有效响应你的奖励函数所提供的反馈信号。

这种无服务器方式让 Nova 定制具备成本效益。Lambda 可以自动伸缩，从初期实验阶段每秒处理 10 次并发评估，扩展到生产训练期间的 400 次以上评估，而无需调优基础设施或做容量规划。你的单个 Lambda 函数可以同时评估多个质量标准，提供细致、多维度的反馈，防止模型利用过于简单的评分捷径。该架构既支持通过 RLVR 做客观验证——对测试用例运行代码或校验结构化输出——也支持通过 RLAIF 做主观判断，由 AI 模型评估语气、有用性等特质。你只需为评估期间实际消耗的计算时间付费，计费粒度为毫秒，因此实验成本低廉，而生产成本与训练强度成正比。对于迭代式开发来说最有价值的一点或许是：Lambda 函数会作为可复用的“Evaluator”资产保存在 Amazon SageMaker AI Studio 中，让你在多次训练运行中调整定制策略时保持质量度量的一致性。

## **选择合适的奖励机制**

成功的 RFT 的基础是选择合适的反馈机制。两种互补的方法服务于不同的用例：**RLVR** 与 **RLAIF** 是[两种技术](https://docs.aws.amazon.com/bedrock/latest/userguide/reward-functions.html)，用于在初始训练之后微调大语言模型（LLM）。它们的主要差别在于向模型提供反馈的方式。

### **RLVR（基于可验证奖励的强化学习）**

RLVR 使用确定性代码来验证客观正确性。RLVR 面向“正确答案”可以被数学或逻辑验证的领域，例如解一道数学题。RLVR 使用确定性函数为输出评分，而不是使用学习得到的奖励模型。对于创意写作或品牌语调这类不存在绝对基准真值的任务，RLVR 会失效。

- **最适合：** 代码生成、数学推理、结构化输出任务
- **示例：** 让生成的代码跑测试用例、校验 API 响应、检查计算准确性
- **优势：** 可靠、可审计、确定性的评分

RLVR 函数以程序化方式对照基准真值验证正确性。下面这个示例做的是情感分析。

```
from typing import List
import json
import random

from dataclasses import asdict, dataclass

import re
from typing import Optional


def extract_answer_nova(solution_str: str) -> Optional[str]:
    """Extract sentiment polarity from Nova-formatted response for chABSA."""
    # First try to extract from solution block
    solution_match = re.search(r'<\|begin_of_solution\|>(.*?)<\|end_of_solution\|>', solution_str, re.DOTALL)
    if solution_match:
        solution_content = solution_match.group(1)
        # Look for boxed format in solution block
        boxed_matches = re.findall(r'\\boxed\{([^}]+)\}', solution_content)
        if boxed_matches:
            return boxed_matches[-1].strip()
    
    # Fallback: look for boxed format anywhere
    boxed_matches = re.findall(r'\\boxed\{([^}]+)\}', solution_str)
    if boxed_matches:
        return boxed_matches[-1].strip()
    
    # Last resort: look for sentiment keywords
    solution_lower = solution_str.lower()
    for sentiment in ['positive', 'negative', 'neutral']:
        if sentiment in solution_lower:
            return sentiment
    
    return None


def normalize_answer(answer: str) -> str:
    """Normalize answer for comparison."""
    return answer.strip().lower()


def compute_score(
    solution_str: str,
    ground_truth: str,
    format_score: float = 0.0,
    score: float = 1.0,
    data_source: str = 'chabsa',
    extra_info: Optional[dict] = None
) -> float:
    """chABSA scoring function with VeRL-compatible signature."""
    answer = extract_answer_nova(solution_str)
    if answer is None:
        return 0.0
    
    # Parse ground_truth JSON to get the answer
    gt_answer = ground_truth.get("answer", ground_truth)
    
    clean_answer = normalize_answer(answer)
    clean_ground_truth = normalize_answer(gt_answer)
    
    return score if clean_answer == clean_ground_truth else format_score

@dataclass
class RewardOutput:
    """Reward service."""

    id: str
    aggregate_reward_score: float

def lambda_handler(event, context):

    scores: List[RewardOutput] = []

    samples = event

    for sample in samples:
        # Extract the ground truth key. In the current dataset it's answer
        print("Sample: ", json.dumps(sample, indent=2))
        ground_truth = sample["reference_answer"]
        
        idx = "no id"
        # print(sample)
        if not "id" in sample:
            print(f"ID is None/empty for sample: {sample}")
        else:
            idx = sample["id"]

        ro = RewardOutput(id=idx, aggregate_reward_score=0.0)

        if not "messages" in sample:
            print(f"Messages is None/empty for id: {idx}")
            scores.append(RewardOutput(id="0", aggregate_reward_score=0.0))
            continue
        
        # Extract answer from ground truth dict
        if ground_truth is None:
            print(f"No answer found in ground truth for id: {idx}")
            scores.append(RewardOutput(id="0", aggregate_reward_score=0.0))
            continue
        
        # Get completion from last message (assistant message)
        last_message = sample["messages"][-1]
        completion_text = last_message["content"]
        
        if last_message["role"] not in ["assistant", "nova_assistant"]:
            print(f"Last message is not from assistant for id: {idx}")
            scores.append(RewardOutput(id="0", aggregate_reward_score=0.0))
            continue

        if not "content" in last_message:
            print(f"Completion text is empty for id: {idx}")
            scores.append(RewardOutput(id="0", aggregate_reward_score=0.0))
            continue

        random_score = compute_score(solution_str=completion_text, ground_truth=ground_truth)
        ro = RewardOutput(id=idx, aggregate_reward_score=random_score)

        print(f"Response for id: {idx} is {ro}")
        scores.append(ro)

    return [asdict(score) for score in scores]
```

你的 RLVR 函数应包含三个关键设计要素，才能实现有效训练。第一，通过给予部分分数来创造平滑的奖励地形——例如，即使最终答案错误，只要响应结构正确也给出 format_score 对应的分数。这可以避免让学习变得困难的二值评分断崖。第二，实现良好的抽取逻辑，具备多种解析策略，能优雅地处理各种响应格式。第三，在每一步都校验输入，使用防御式编程实践来防止畸形输入导致崩溃。

### **RLAIF（基于 AI 反馈的强化学习）**

RLAIF 使用 AI 模型作为评判者来做主观评估。RLAIF 能达到与 RLHF（Reinforcement Learning via Human Feedback，基于人类反馈的强化学习）相当的表现，同时速度显著更快、成本更低。下面是一个用于情感分类的示例 RLVR lambda 函数代码。

- **最适合：** 创意写作、摘要、品牌语调对齐、有用性
- **示例：** 评估响应语气、判断内容质量、评判与用户意图的对齐程度
- **优势：** 无需人工标注成本即可获得可扩展的、类人的判断

RLAIF 函数把判断工作交给能力强的 AI 模型，如下面的示例代码所示

```
import json
import re
import time
import boto3
from typing import List, Dict, Any, Optional

bedrock_runtime = boto3.client('bedrock-runtime', region_name='us-east-1')
JUDGE_MODEL_ID = "<jude_model_id>" #Replace with judge model id of your interest
SYSTEM_PROMPT = "You must output ONLY a number between 0.0 and 1.0. No explanations, no text, just the number."

JUDGE_PROMPT_TEMPLATE = """Compare the following two responses and rate how similar they are on a scale of 0.0 to 1.0, where:
- 1.0 means the responses are semantically equivalent (same meaning, even if worded differently)
- 0.5 means the responses are partially similar
- 0.0 means the responses are completely different or contradictory

Response A: {response_a}

Response B: {response_b}

Output ONLY a number between 0.0 and 1.0. No explanations."""

def extract_solution_nova(solution_str: str, method: str = "strict") -> Optional[str]:
    """Extract solution from Nova-formatted response."""
    assert method in ["strict", "flexible"]
    
    if method == "strict":
        boxed_matches = re.findall(r'\\boxed\{([^}]+)\}', solution_str)
        if boxed_matches:
            final_answer = boxed_matches[-1].replace(",", "").replace("$", "")
            return final_answer
        return None
        
    elif method == "flexible":
        boxed_matches = re.findall(r'\\boxed\{([^}]+)\}', solution_str)
        if boxed_matches:
            numbers = re.findall(r"(\\-?[0-9\\.\\,]+)", boxed_matches[-1])
            if numbers:
                return numbers[-1].replace(",", "").replace("$", "")
        
        answer = re.findall(r"(\\-?[0-9\\.\\,]+)", solution_str)
        if len(answer) == 0:
            return None
        else:
            invalid_str = ["", "."]
            for final_answer in reversed(answer):
                if final_answer not in invalid_str:
                    break
        return final_answer

def lambda_graded(id: str, response_a: str, response_b: str, max_retries: int = 50) -> float:
    """Call Bedrock to compare responses and return similarity score."""
    prompt = JUDGE_PROMPT_TEMPLATE.format(response_a=response_a, response_b=response_b)
    
    for attempt in range(max_retries):
        try:
            response = bedrock_runtime.converse(
                modelId=JUDGE_MODEL_ID,
                messages=[{"role": "user", "content": [{"text": prompt}]}],
                system=[{"text": SYSTEM_PROMPT}],
                inferenceConfig={"temperature": 0.0, "maxTokens": 10}
            )
            
            output = response['output']['message']['content'][0]['text'].strip()
            score = float(output)
            return max(0.0, min(1.0, score))

        except Exception as e:
            if "ThrottlingException" in str(e) and attempt < max_retries - 1:
                time.sleep(2 ** attempt)
            else:
                return 0.0
    return 0.0

def compute_score(id: str, solution_str: str, ground_truth: str) -> float:
    """Compute score for train.jsonl format."""
    answer = extract_solution_nova(solution_str=solution_str, method="flexible")
    if answer is None:
        return 0.0
    
    clean_answer = str(answer)
    clean_ground_truth = str(ground_truth)
    
    score = lambda_graded(id, response_a=clean_answer, response_b=clean_ground_truth)
    return score

def lambda_grader(samples: List[Dict[str, Any]]) -> List[Dict[str, Any]]:
    """
    Process samples from train.jsonl format and return scores.
    
    Args:
        samples: List of dictionaries with messages and metadata
        
    Returns:
        List of dictionaries with reward scores
    """
    results = []
    
    for sample in samples:
        sample_id = sample.get("id", "unknown")
        
        # Extract reference answer from metadata or top level
        metadata = sample.get("metadata", {})
        reference_answer = metadata.get("reference_answer", sample.get("reference_answer", {}))
        
        if isinstance(reference_answer, dict):
            ground_truth = reference_answer.get("answer", "")
        else:
            ground_truth = str(reference_answer)
        
        # Get assistant response from messages
        messages = sample.get("messages", [])
        assistant_response = ""
        
        for message in reversed(messages):
            if message.get("role") in ["assistant", "nova_assistant"]:
                assistant_response = message.get("content", "")
                break
        
        if not assistant_response or not ground_truth:
            results.append({
                "id": sample_id,
                "aggregate_reward_score": 0.0
            })
            continue
        
        # Compute score
        score = compute_score(
            id=sample_id,
            solution_str=assistant_response,
            ground_truth=ground_truth
        )
        
        results.append({
            "id": sample_id,
            "aggregate_reward_score": score,
            "metrics_list": [
                {
                    "name": "semantic_similarity",
                    "value": score,
                    "type": "Reward"
                }
            ]
        })
    
    return results

def lambda_handler(event, context):
    return lambda_grader(event)
```

在实现 RLAIF 函数时，考虑用全局变量初始化客户端以降低整体调用延迟。优雅地处理限流异常，避免训练中断。使用 temperature 0.0 以获得确定性的评判分数，这有助于模型的一致性。并且提供清晰的评分细则（rubric），这有助于评判者给出校准良好的分数。

## **编写优质奖励函数的注意事项**

要为 RFT 编写好的奖励函数，应从现在开始保持简单、创造平滑的奖励地形（而不是二值断崖）、确保奖励与真实目标一致（避免被 hack）、对复杂任务使用稠密/塑形奖励、提供清晰的信号，并让它们可验证且一致。

- **清晰定义目标：** 明确知道对你的模型而言成功是什么样子。
- **平滑的奖励地形：** 不要用简单的通过/失败（0 或 1），而是使用平滑、稠密

奖励信号，对“方向正确”给予部分分数。这种细粒度的反馈帮助模型从渐进式改进中学习，而不是等待一个完美的响应。对于复杂的多步任务，为中间进展（塑形）提供奖励，而不只是为最终结果（稀疏）提供奖励。

- **让奖励多维度：** 单一的标量奖励太容易被 hack。奖励

应从多个维度评估模型表现：例如正确性、对输入的忠实度、安全性/策略对齐、格式和简洁性等。

- **防止 reward hacking：** 确保模型无法通过捷径获得高奖励

（例如侥幸猜中、重复性动作）；让任务无法被猜中。

- **使用可验证的评分细则：** 对于代码生成或数学这类客观任务，使用自动

评分器来执行代码或解析特定的答案标签（例如 <answer>），从而在无需人工介入的情况下验证正确性。

- **为主观任务引入 LLM 评判者：** 当程序化代码无法评判

答案时（例如摘要），使用一个独立的、能力强的模型作为“LLM Judge”。你必须先评估这个评判者，确保其评分稳定且与人类偏好一致。

## **在训练循环中优化奖励函数的执行**

一旦你的奖励函数正确工作，优化有助于你更快地训练并控制成本。本节涵盖针对你的工作负载可以考虑的技术。优化技术的效果会叠加——一个配置得当的 Lambda 函数，配合合适的批大小、并发设置、冷启动缓解与错误处理，评估响应的速度可以比朴素实现快十倍，同时成本显著更低、训练可靠性更好。在定制流程早期就投入优化，会在整个训练过程中带来回报：缩短迭代时间、降低计算成本，并在问题变得需要昂贵重训之前就发现它们。

- **在开始训练之前确保 IAM 权限已正确配置**

依赖管理与权限

- 如何添加依赖：你可以把依赖直接和代码打包进一个部署包（.zip 文件），也可以使用 Lambda 层（layer）把依赖与核心逻辑分开管理。创建 .zip 部署包（参见[此处](https://docs.aws.amazon.com/lambda/latest/dg/python-package.html#python-package-dependencies)的说明）使用 Lambda 层（参见[此处](https://docs.aws.amazon.com/lambda/latest/dg/python-layers.html)的说明）
- RLAIF 所需的 Amazon Bedrock 访问权限：Lambda 函数的执行角色应具备访问 Amazon Bedrock 以进行 LLM API 调用的权限。

对多个函数共享的依赖使用层。对特定函数的逻辑使用部署包。为 RLAIF 实现给 Lambda 执行角色附加 AWS Identity and Access Management（IAM）权限。遵循最小权限原则，把 Resource ARN 限定为你用作评判者的那个具体基础模型，而不是使用通配符。

- **理解平台差异，以及哪个平台更适合你的需求**

优化基于 Lambda 的奖励函数，需要理解不同训练环境如何与无服务器评估交互，以及架构选择如何影响吞吐、延迟和成本。优化空间在同步与异步处理模型之间差别很大，因此针对环境的调优对生产规模的定制至关重要。

Amazon SageMaker AI 训练作业采用同步处理：首先生成 rollout，然后并行分批评估。这种架构在批大小和并发管理方面带来独特的优化机会。`lambda_batch_size` 参数默认为 64，它决定 Lambda 在单次调用中评估多少个样本——对于毫秒级完成的快速奖励函数，可以把它调高；对于接近超时阈值的复杂评估，则应调低。`lambda_concurrency` 参数控制并行执行，默认的 12 次并发调用对生产工作负载往往偏保守。快速的奖励函数可以从显著更高的并发中受益，有时可达到 50 次甚至更多同时执行，但你必须监控账户级 Lambda 并发限制，它会在一个区域内封顶你所有函数的总并发执行数。

Amazon SageMaker AI HyperPod 则通过异步处理采取了根本不同的方式，逐个生成并评估样本，而不是大批量处理。这种逐样本架构天然支持更高吞吐，默认配置下无需特殊调优即可每秒通过 Lambda 处理 400 个事务。要扩展到这一基线以上，需要协调调整 HyperPod 配方（recipe）参数——具体是控制 worker 并行度的 `proc_num` 与 `rollout_worker_replicas`。在激进扩展 worker 时，考虑按比例增加 `generation_replicas`，以防止生成成为瓶颈而评估能力闲置。

- **利用 Lambda 的并发优化奖励函数**

Lambda 配置直接影响训练速度与可靠性：

- 超时配置：把超时设为 60 秒（默认只有 3 秒），为 RLAIF 评判调用或复杂的 RLVR 逻辑留出余量 内存分配：把内存设为 512 MB（默认是 128 MB），加速的 CPU 能提升响应时间的表现

- **冷启动缓解**

冷启动缓解可以避免拖慢训练并抬高成本的延迟尖峰。让部署包保持在 50MB 以内以最小化初始化时间——这通常意味着排除不必要的依赖，并对大型共享库使用 Lambda 层。通过在全局作用域而不是在 handler 函数内部初始化 Amazon Bedrock runtime 客户端这类客户端，在多次调用之间复用连接，让 Lambda 执行环境在调用之间保持这些连接。使用 Lambda Insights 对函数做性能剖析，找出性能瓶颈。把频繁访问的数据，例如评估评分细则、校验规则或配置参数，缓存在全局作用域，这样 Lambda 每个容器只加载一次，而不是每次调用都加载。这种“全局初始化 + handler 级执行”的模式，对于训练期间要处理数千次评估的 Lambda 函数尤其有效。

```
# Keep deployment package under 50MB
# Reuse connections across invocations
bedrock_client = boto3.client('bedrock-runtime')  # Global scope

# Cache frequently accessed data
EVALUATION_RUBRICS = {...}  # Load once

def lambda_handler(event, context):
    # Clients and cached data persist across invocations
    return evaluate_responses(event, bedrock_client, EVALUATION_RUBRICS)
```

- **优化 RLAIF 评判模型**

对于使用 Amazon Bedrock 模型作为评判者的 RLAIF 实现，有一个重要的权衡需要考虑。较大的模型给出更可靠的判断，但吞吐更低；较小的模型吞吐更好，但能力可能较弱——选择足以完成你任务的最小评判模型，以最大化吞吐。在扩展到完整训练之前，先对评判者的一致性做剖析。

**吞吐管理：**

- 在区域级别监控 Amazon Bedrock 的限流上限 考虑为评判模型使用 Amazon SageMaker AI 端点。它提供更高吞吐，但目前只支持开放权重模型和 Nova 模型 在可能时把多次评估批量放进一次 API 调用 考虑共享 Amazon Bedrock 配额的并发训练作业

- **确保你的 Lambda 奖励函数能容错并自我纠正**

现实世界的系统会遇到故障——网络抖动、服务暂时不可用，或偶发的 Lambda 超时。与其让一次失败毁掉整个训练作业，我们构建了健壮的重试机制，自动处理超时、Lambda 失败和瞬时错误。系统会以指数退避智能重试失败的奖励计算，给临时问题留出恢复的时间。如果某次调用在三次重试后仍然失败，你会收到清晰、可操作的错误消息，指出具体问题——无论是超时、权限问题，还是奖励逻辑中的 bug。这种透明性让你可以快速定位并修复问题，而不必在晦涩的日志里翻找。

```
def robust_evaluation(sample, max_retries=3):
    """Evaluation with comprehensive error handling."""
    for attempt in range(max_retries):
        try:
            score = compute_score(sample)
            return score
        except ValueError as e:
            # Parsing errors - return 0 and log
            print(f"Parse error for {sample['id']}: {str(e)}")
            return 0.0
        except Exception as e:
            # Transient errors - retry with backoff
            if attempt < max_retries - 1:
                time.sleep(2 ** attempt)
            else:
                print(f"Failed after {max_retries} attempts: {str(e)}")
                return 0.0
    return 0.0
```

- **用 CloudWatch 迭代调试，尽早捕捉任何错误迹象**

对训练过程的可观测性，对监控进度和排查问题都至关重要。我们会自动把训练 pipeline 每个阶段的详尽信息记录到 CloudWatch：每个训练步的指标——包括逐步的训练奖励分数，以及每个 pipeline 组件的详细执行轨迹。这种细粒度日志让实时跟踪训练进度、确认奖励函数是否按预期为响应评分、以及在问题出现时快速诊断都变得简单直接。例如，如果你发现训练没有改善，可以在 CloudWatch 中查看奖励分布，看你的函数是否大多返回零，或者信号是否不足。

CloudWatch 为奖励函数的性能提供全面的可观测性。以下是几个对该方案有用的 [Amazon CloudWatch Insights 查询](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/CWL_QuerySyntax-examples.html)。

```
-- Find samples with zero rewards
SOURCE '/aws/lambda/my-reward-function'
| fields @timestamp, id, aggregate_reward_score
| filter aggregate_reward_score = 0.0
| sort @timestamp desc

-- Calculate reward distribution
SOURCE '/aws/lambda/my-reward-function'
| fields aggregate_reward_score
| stats count() by bin(aggregate_reward_score, 0.1)

-- Identify slow evaluations
SOURCE '/aws/lambda/my-reward-function'
| fields @duration, id
| filter @duration > 5000
| sort @duration desc

-- Track multi-dimensional metrics
SOURCE '/aws/lambda/my-reward-function'
| fields @timestamp, correctness, format, safety, conciseness
| stats avg(correctness) as avg_correctness, 
        avg(format) as avg_format,
        avg(safety) as avg_safety,
        avg(conciseness) as avg_conciseness 
  by bin(5m)
```

## 结论

基于 Lambda 的奖励函数为需要精确行为控制、但不想依赖海量标注数据集的组织解锁了 Amazon Nova 定制，并带来更强的推理能力。这种方法通过灵活性、可扩展性和成本效益带来显著优势，简化了你的模型定制流程。该架构让 RLVR 负责客观验证任务，而 RLAIF 帮助完成主观判断，以实现细致入微的质量评估。组织可以单独使用它们，也可以组合起来做全面评估，既涵盖事实准确性，也涵盖风格偏好。可扩展性从无服务器基础中自然产生，自动处理从早期实验到生产规模定制的各种训练负载波动。成本效益直接源于这一设计——组织只为实际发生的评估计算付费，训练作业因优化的 Lambda 并发和高效的奖励计算而更快完成。Amazon Nova 基础模型、Lambda 的无服务器可扩展性，以及 Amazon Bedrock 托管式定制基础设施的组合，让强化微调无论组织规模大小都更易上手。从本文中的示例代码开始实验，着手定制能交付你的应用所需确切行为的 Amazon Nova 模型。
