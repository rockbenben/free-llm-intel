# Gen Digital 如何用 Amazon Bedrock AgentCore Web Search 为 Norton Revamp 搭建 AI 精选新闻引擎

你的职业声誉如今首先存在于线上。招聘人员会在回电话之前先查 LinkedIn，客户在约第一次会议之前会审视你的数字形象。对有野心的专业人士来说，这种转变是一个机会：一个精心打磨的线上声音，能打开单凭简历永远打不开的门。

但要脱颖而出，光靠内容生成还不够，它需要对*当下此刻*正在发生什么保持实时的感知。一位想要建立生成式 AI 思想领袖声誉的专业人士，需要对今天的突破做出反应，而不是上周的头条。而在被 AI 生成的噪声淹没的信息流里，受众对真实与及时的回报胜过以往任何时候。

*Web Search on Amazon Bedrock AgentCore* 让这件事成为可能。我们构建了 [*Norton Revamp*](https://revamp.norton.com/)，一个由生成式 AI 驱动的专业声誉管理平台。它的核心是一个 AI 精选新闻引擎，由 AgentCore Web Search 驱动，把每一条内容建议、目标推荐和新闻条目都锚定在当前、带引用的 web 知识上。这个平台于 2026 年 3 月上线，由一小群工程师搭建。

在这篇文章里，我们向你展示 [Gen](https://www.gendigital.com/us/en/) 团队如何用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) Web Search 在 Norton Revamp 里搭出一个 AI 精选新闻引擎，帮客户把想法变成有吸引力的社交媒体帖子。

## 挑战：为专业内容提供实时 grounding

不同于依赖静态知识库的聊天机器人，Norton Revamp 需要理解每个用户的专业领域里*此刻*正在流行什么。网络安全专家需要当天的威胁情报，营销负责人需要本周的行业变化。传统做法（自建 web 爬虫、第三方新闻 API、静态内容数据库）各有各的取舍：基础设施开销、数据陈旧、供应商复杂度，或者数据出境风险。

在选定 AgentCore Web Search 之前，我们评估了三种替代方案。自建爬虫需要持续维护，而且跟不上实时。第三方新闻 API 带来了供应商合同、API key 管理，还有数据离开我们 AWS 环境的问题。静态知识库则永远处于陈旧状态。AgentCore Web Search 消除了这些顾虑：它是全托管的、零基础设施开销，完全在 AWS 内运行、零数据出境，并且返回带 URL 和发表日期的引用来源。这让个性化、实时的新闻流在规模化下变得可行。

## AgentCore Web Search 如何驱动 Norton Revamp

Web Search on Amazon Bedrock AgentCore 是一项全托管的 web 搜索能力，符合 Model Context Protocol（MCP）。它作为 AgentCore Gateway 上的一个托管连接器提供，而 AgentCore Gateway 是 Amazon Bedrock AgentCore 的一项能力。我们的 agent 发出一条自然语言查询，Web Search 返回相关摘要、来源 URL、标题和发表日期，模型用它们产出有依据的回答。

这项能力支撑着三个核心功能：

**AI 精选新闻流**

每个用户都会得到一条个性化的内容流，把与其目标相关的最新文章和热门话题呈现出来。如果你正在打造生成式 AI 思想领袖的声誉，你的新闻流就会优先展示 AI 突破、行业分析和新兴用例，并通过 AgentCore Web Search 实时取源。它不像静态的 RSS 聚合器，而是一个能感知目标的发现引擎，每一次会话都会刷新。

**智能内容建议**

用户会收到 AI 生成的内容点子，按其所在领域的热门话题定制，用他们自己的真实语气写就，还可以选配 AI 生成的视觉素材。AgentCore Web Search 把每一条建议都锚定在*今天*正在发生的事情上。一套三步教练流程（Analyze、Refine、Post）带着用户从最初的想法一路走到在 LinkedIn 和 X 上发布内容，中间带有反馈回路，所以 AI 每一轮迭代都更准。

**感知趋势的目标设定**

用户定义一个目标，AI 就构建一份带每周主题和里程碑的个性化路线图。AgentCore Web Search 把实时趋势数据喂进目标生成，让每周主题反映当前的行业动态。系统会从过去四周的活动里学习，并随着用户的成长刷新推荐。

## 架构与技术栈

![事件驱动的新闻引擎架构，展示 Amazon Nova、AgentCore Web Search 和 AI Learning System 如何为内容生成提供 grounding](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/29/c-ml-22210-arch-diagram.png)

图 1：Norton Revamp 新闻引擎的事件驱动架构

这套集成遵循事件驱动架构。当用户设置或更新自己的职业目标时，Amazon Nova（经由 Amazon Bedrock）会基于该目标、近期活动和互动模式生成有针对性的搜索查询。agent 把这些查询发给 AgentCore Web Search，后者完全在我们的 AWS 环境内返回带引用的结果。我们的 AI Learning System 按相关性、时效和来源可信度给结果排序。排好序的结果随后作为 Amazon Nova Lite 的 grounding 上下文，用来以用户的真实语气生成内容建议。互动数据再回灌到查询生成环节，让新闻引擎越来越聪明。

**生成式 AI 与机器学习技术栈：**

- **Amazon Bedrock** – 核心生成式 AI 引擎，用于内容生成、个性化、帖子分析（批处理模式）与内容教练。
- **Amazon Nova (Nova Lite)** – 主力大语言模型（LLM），驱动内容生成、目标创建与趋势分析。
- **Web Search on Amazon Bedrock AgentCore** – 通过一个符合 MCP 的托管连接器提供实时 web 检索，支撑新闻引擎、内容 grounding 与趋势发现。
- **Stability AI** – 图像生成。
- **Claude（经由 Amazon Bedrock）** – 面向复杂推理任务的额外 LLM 能力。

**基础设施：** 前端是 React、TypeScript 和 Tailwind CSS。后端是 Node.js、Amazon Elastic Container Service (Amazon ECS)、AWS Lambda、Amazon DynamoDB（多表，采用复合键模式）、Amazon API Gateway、Amazon Simple Storage Service (Amazon S3)、Amazon Simple Queue Service (Amazon SQS)、Amazon EventBridge、Amazon CloudFront、Amazon CloudWatch 和 AWS Secrets Manager。基础设施通过 Terraform 管理，并用蓝绿部署实现零停机发布。

**处理流水线：** 这个平台跑四个流水线阶段：

- **Full Scan** – 拉取最多 1,000 条历史帖子，存入 Amazon S3，运行 Amazon Bedrock 批量分析以评估声誉影响。
- **Daily Scan** – 由 Amazon EventBridge 触发的增量分析。
- **Weekly Goal Generation** – 由 Lambda 生成目标，综合考虑历史互动数据加上来自 AgentCore Web Search 的实时趋势数据。
- **Content Coaching** – 在 Analyze、Refine、Post 流程中进行同步的 Amazon Bedrock 调用，每一步都用 AgentCore Web Search 的结果做锚定。

我们从第一天起就把生成式 AI 嵌了进来——它既是产品，也是开发方法。人与 AI 的职责划分是刻意设计的：架构决策、安全评审、业务逻辑和个性化算法归人负责；代码生成、文档、测试脚手架、重构和 UI 组件创建交给 AI。

借助 Claude，我们每个概念产出 10 个以上的设计变体，把从设计到原型的时间从数周压缩到数小时，并且 70% 的 UI 代码由 AI 生成。我们在原本只够试一种定价模型的时间里测了五种定价模型。游戏化系统在上线前经历了八轮迭代。

可衡量的影响是：功能实现快 3 倍，样板代码生成提速 90%，文档提速 80%，测试创建提速 70%，UI 组件生成提速 65%。代价是：评审 AI 的产出占用了我们 20–30% 的时间。

AI 在个性化算法、DynamoDB 多表架构（这需要基于经验的判断）、安全实现以及 Amazon Bedrock 批处理优化上都提供了帮助。关键的洞察是：AI 加快了实现，但由人设计了 AI Learning System 应该如何适应用户目标。产品侧的生成式 AI（Amazon Bedrock、Amazon Nova、AgentCore Web Search）与开发侧的生成式 AI 服务的是不同目的，我们把两者严格分开。

## 集成 AgentCore Web Search 的最佳实践

对于正在考虑用 AgentCore Web Search 做实时 grounding 的团队：

- **在查询生成上投入——** 结构良好的查询比开放式查询带来更好的结果，所以我们的 prompt 工程重点放在了这里。
- **有策略地缓存——** 实时新鲜度正是它的价值所在，但有些查询不必每一次会话都重新执行。我们会缓存结果，并设置与新鲜度要求相匹配的 time-to-live（TTL）值。
- **建立反馈回路——** 追踪用户点开了哪些 web 搜索结果，并把这个信号回灌给查询生成。我们的新闻引擎在头 90 天里的相关性持续提升。
- **校验来源质量——** AgentCore Web Search 会返回来源 URL 和发表日期。我们搭了一个轻量的可信度打分层，用来优先呈现权威来源。
