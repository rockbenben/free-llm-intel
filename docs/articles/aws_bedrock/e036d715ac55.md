# Rufus 如何借助 Amazon Bedrock 把对话式购物体验扩展到数百万亚马逊客户

我们亚马逊的团队构建了 [Rufus](https://www.aboutamazon.com/news/retail/amazon-rufus-ai-assistant-personalized-shopping-features)，这是一款 AI 驱动的购物助手，通过智能的对话式体验让我们的客户感到愉悦。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/19/ml-19594-2.jpeg)

今年已有超过 2.5 亿客户使用过 Rufus。月活跃用户同比增长 140%，交互量同比增长 210%。此外，在购物过程中使用 Rufus 的客户完成购买的可能性高出 60%。为了实现这一切，我们的团队会仔细评估每一个决策，力求聚焦于最重要的事情：打造最好的 agentic 购物助手体验。通过专注于客户驱动的功能，Rufus 如今更聪明、更快速、更有用。

本文将分享我们采用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 如何加速了 Rufus 的演进。

## 构建客户驱动的架构

定义清晰的用例是塑造需求与实现的基础，构建 AI 驱动的购物助手也不例外。对于 Rufus 这样的购物助手，我们的用例与客户会提出的各类问题相对应，我们希望用每一个回答超越他们的期望。例如，客户可能想了解自己在考虑的那双鞋的某个事实，于是问「这双鞋防水吗？」另一位客户可能想请 Rufus 给出推荐，于是问「给我几个适合跑马拉松的鞋子选项」。这些例子只代表我们从客户用例反推设计、让 Rufus 支持的多样问题类型中的一小部分。

定义好客户用例后，我们在设计 Rufus 时会通盘考虑整个技术栈，使其为客户无缝工作。从首次发布到后续迭代，我们都会收集指标来了解 Rufus 的表现，目标是持续改进。这意味着不仅要用 LLM-as-a-judge 等工具衡量答案的准确程度，还要分析延迟、客户重复参与度以及每次交互的对话轮数等因素，以更深入地洞察客户参与情况。

## 从自研 LLM 向外扩展

Rufus 最初发布时，我们构建了自研的大语言模型（LLM）。之所以决定自研 LLM，是因为需要使用一个专门针对购物领域问题训练的模型。起初我们考虑过现成模型，但其中大多数在我们的购物评估（evals）中表现不佳。另一些模型的代价是体积更大，因此更慢、成本更高。我们并不需要一个在众多领域都表现良好的模型，我们需要的是在购物领域表现良好、同时保持高准确率、低延迟和成本效益的模型。通过构建自研 LLM 并用 AWS 芯片部署，我们得以在全球范围内投入生产，支撑 Prime Day 之类的大规模活动——当时我们[使用了 80,000 颗 AWS Inferentia 和 Trainium 芯片](https://aws.amazon.com/blogs/machine-learning/scaling-rufus-the-amazon-generative-ai-powered-conversational-shopping-assistant-with-over-80000-aws-inferentia-and-aws-trainium-chips-for-prime-day/)。

Rufus 初步成功后，我们希望扩展到需要高级推理、更大上下文窗口和多步推理的用例。然而，训练 LLM 面临一个重大挑战：迭代可能需要数周甚至数月才能完成。随着更强的新模型以更快的节奏发布，我们希望尽可能快地改进 Rufus，并开始快速评估和采用最先进的模型。要发布这些新功能并打造真正出色的购物助手，Amazon Bedrock 是自然的选择。

## 用 Amazon Bedrock 加速 Rufus

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一个全面、安全且灵活的平台，用于构建生成式 AI 应用与 agent。Amazon Bedrock 将你连接到领先的基础模型（FM）、用于部署和运行 agent 的服务，以及用于微调、防护和优化模型的工具，还有能把应用连接到最新数据的 knowledge base，让你拥有一切所需，快速从实验走向真实部署。Amazon Bedrock 让你可以访问来自领先 AI 公司的数百个基础模型，并提供评估工具，帮助你根据自身独特的性能与成本需求挑选最佳模型。

Amazon Bedrock 通过以下方式为我们带来巨大价值：

- **管理来自不同提供方的领先基础模型（FM）的托管**，并通过 [converse API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.html) 等与模型无关的接口提供访问。通过提供对前沿模型的访问，我们能够以对现有系统最小的改动快速评估并集成它们。这提升了我们的速度。我们可以为任务使用最佳模型，同时平衡成本、延迟和准确性等特性。
- **消除大量运营开销**，例如 Rufus 团队原本要管理模型托管基础设施、应对伸缩挑战，或维护亚马逊各运营地区遍布全球的模型服务 pipeline。Bedrock 承担了这些繁重工作，让客户可以专注于为自己的独特需求构建创新解决方案。
- **提供全球可用性**，支持跨多个地理区域的一致部署。借助 Amazon Bedrock，我们以极少的投入快速在新的商城站点上线。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/19/ml-19594-3.jpeg)

由 Amazon Bedrock 托管的模型还帮助 Rufus 支持跨模态的多种体验，包括文本和图像。即便是在文本到文本这样的单一模态内，用例在复杂度、流量和延迟要求上也可能各不相同。像「规划一次露营旅行」「给我妈妈推荐礼物」或风格建议这类场景，需要更深入的推理、多轮对话，以及使用 *web search* 等工具的能力，才能给出上下文丰富、个性化的答案。而「这把电钻的功率是多少？」这样直接的产品询问，可以由更小、更快的模型高效处理。

我们的策略是组合多个模型来驱动 Rufus，包括 Amazon Nova、Anthropic 的 Claude Sonnet 以及我们的自研模型，从而交付尽可能可靠、快速且直观的客户体验。

## 将 Amazon Bedrock 与 Rufus 集成

借助 Amazon Bedrock，我们可以为每种查询类型评估并选择最优模型，在答案质量、延迟和参与度之间取得平衡。使用 Amazon Bedrock 带来的收益使我们的开发速度提升了 6 倍以上。使用多个模型让我们能够把一次对话拆解成细粒度的片段。这样一来，我们就能更有效地回答问题，并已看到切实的收益。在确定计划使用的模型之后，我们还采用混合方式，为模型提供恰当的上下文，使其有效完成任务。在某些情况下，我们可能已经拥有 Rufus 回答问题所需的上下文。例如，如果我们知道客户在询问此前的订单，就可以把其订单历史放进模型的首次推理请求中。这优化了需要发起的推理调用次数，也带来更强的确定性，有助于避免下游错误。在另一些情况下，我们可以把决定权交给模型，当它认为需要更多信息时，可以使用工具检索额外上下文。

我们发现，用恰当的信息为模型做 grounding 非常重要。我们采用的方式之一是使用 [Amazon Nova Web Grounding](https://aws.amazon.com/blogs/aws/build-more-accurate-ai-applications-with-amazon-nova-web-grounding/)，因为它可以与 Web 浏览器交互，检索并引用权威的互联网来源，从而显著减少答案缺陷、提升准确性并增强客户信任。除了优化模型准确性，我们还配合 Amazon Bedrock 的各项功能，尽可能降低延迟。通过使用 [prompt caching](https://aws.amazon.com/bedrock/prompt-caching/) 和并行工具调用，我们进一步降低了延迟。这些从模型响应到服务延迟的优化，意味着使用 Rufus 的客户完成购买的可能性高出 60%。

## 通过工具集成实现 agentic 功能

更重要的是，Amazon Bedrock 的架构支持 agentic 能力，通过[工具使用](https://docs.aws.amazon.com/bedrock/latest/userguide/tool-use.html)让 Rufus 对购物者更有用。借助 Bedrock 上的模型，Rufus 可以把服务作为工具动态调用，以提供个性化、实时、准确的信息，或代表用户执行操作。当客户向 Rufus 询问产品的可用性、价格或规格时，Rufus 远远超越了其内置知识。它会检索你的订单历史等相关信息，并在推理时使用集成的工具查询实时数据库、查看最新的产品目录并访问实时数据。为了更个性化，Rufus 现在具备账户记忆，能够根据客户的个人购物活动理解他们。Rufus 可以利用你此前可能分享过的信息，例如你喜欢的爱好，或之前提到过的宠物，提供更加个性化和有效的体验。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/19/ml-19594-5.jpeg)

在构建这些 agentic 能力时，可能有必要为 agent 构建一个可与之交互的服务，以提升效果。例如，Rufus 在产品详情页有一个 **Price history** 功能，让客户即时查看历史价格，判断自己是否拿到了好价。购物者可以在浏览时直接向 Rufus 询问价格历史（例如「这件商品在过去三十天里打过折吗？」），也可以设置 **agentic 价格提醒**，在产品达到目标价格时收到通知（「这副耳机降到七折时帮我买」）。借助 **auto-buy** 功能，Rufus 可以在达到期望价格后的 30 分钟内代你完成购买，并使用你的默认支付和配送信息完成下单。auto-buy 请求会保持有效六个月，目前使用该功能的客户平均每次购买可节省 20%。agent 本身可以在价格提醒与 auto-buy 服务中创建持久记录，随后系统使用传统软件管理该记录并据此执行操作。模型、工具与服务的这种紧密集成，把 Rufus 变成了一个真正动态的个性化购物 agent。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/19/ml-19594-6.jpeg)

除价格跟踪之外，Rufus 还支持自然、对话式的复购。客户只需说「把我们上周做南瓜派用的东西重新下单」，或「下单我昨天浏览过的登山靴和登山杖」。Rufus 会把过去的活动与当前意图联系起来，并在商品缺货时给出替代建议。Rufus 使用 agentic AI 能力自动把商品加入购物车，便于快速查看与结账。在这些场景中，Rufus 能够判断何时需要收集信息以给出更好的回答，或执行客户指示的操作。这只是我们已上线的众多 agentic 功能中的两个例子。

## 结果：亚马逊规模的 AI 驱动购物

借助 Amazon Bedrock，Rufus 展示了组织如何构建能够扩展到服务数百万用户的复杂 AI 应用。灵活的模型选择、托管的基础设施与 agentic 能力的结合，使亚马逊能够交付一个既智能又实用的购物助手，同时对准确性、延迟和成本保持严格控制。如果你正在考虑自己的 AI 计划，Rufus 展示了 Bedrock 在简化从 AI 实验到生产部署之路上的潜力，让你可以专注于客户价值而不是基础设施的复杂性。我们鼓励你试用 Bedrock，见证我们看到的同样收益，并把注意力放在自己的 agentic 解决方案及其核心能力上。
