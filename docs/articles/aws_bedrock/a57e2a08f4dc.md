# AgentWatch：用 ambient agent 实现主动式 AWS 监控

AgentWatch 为你的 DevOps 团队提供针对 AWS 资源的 ambient 监控，超越跨多个账户管理 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 告警的被动循环。CloudWatch 告警触发得太晚，[AWS Lambda](https://aws.amazon.com/pm/lambda/) 错误在无人察觉中累积，[Amazon Elastic Compute Cloud (Amazon EC2)](https://aws.amazon.com/pm/ec2) 性能下降直到客户报告问题才被发现。这让你的团队不断救火，而不是预防问题。每天，你都要手动检查仪表盘、分诊 CloudWatch 告警，并调查已经影响用户的问题。指标源源不断涌入，日志在数十个服务中不断累积，告警持续触发，但知道什么重要、何时重要以及该怎么做，才是真正的挑战。

这种被动的监控方式给你的团队带来运营挑战。你在不同工具之间来回切换，从碎片化的数据源中拼凑事件经过，并花数小时为本来可以预防的问题做事后复盘。等到你弄清楚出了什么问题时，你的客户已经经历了性能下降或服务中断。你的值班工程师因告警疲劳而精疲力竭，而团队的效率也因日常监控任务占用了本应用于创新的时间而受损。这些挑战会导致服务水平协议（SLA）目标未达成、客户升级投诉，以及技术债不断累积——因为你的团队专注于救火，而没有实施预防措施。当前的监控工具要求你不停地查询、分析并判断哪些内容值得关注。你需要一种不同的方法。这正是 AgentWatch 的用武之地：它是一个 ambient 的 AWS 资源监控 agent，为基础设施监督提供了另一种思路。该 agent 与你的团队持续协同工作，观察你的基础设施、分析模式并呈现洞察，而无需持续的人工干预。它监控你的系统，只有真正需要你的判断或行动时，才会把你拉进流程。

在本文中，我们通过实际实现来演示 AgentWatch 的能力。你将看到该解决方案如何每 15 分钟执行一次基础设施检查，汇总跨多个 AWS 账户的 CloudWatch 指标、日志和告警。该 agent 把可操作的报告直接发送到 Slack，并回答关于你基础设施状态的自然语言查询。全文中，我们探讨三种 human-in-the-loop 模式，它们既能保持适当的监督，又能最大限度地实现自动化。

## 什么是 ambient agent？

[Ambient agent](https://blog.langchain.com/introducing-ambient-agents/) 代表着向事件驱动、自主 AI 系统的转变。这类 agent 监听事件流并动态响应，可同时处理多个事件，从而减轻人的运营负担。它们无需持续的人工干预即可提供持续监控，同时通过在关键决策点引入人来保持适当的监督。

ambient agent 可以以事件驱动的方式动态触发，并行处理多个任务，因此非常适合条件快速变化、需要持续关注的监控场景。ambient agent 在特定场景中效果最佳。将它们引入你的工作流时，需要审慎考虑这些 agent 何时以及如何与人交互，以及当 agent 执行任务并通知最终用户时，人对工作流拥有何种控制权。

## **这如何适用于你的 AWS 基础设施？**

对于你的 AWS 基础设施，这意味着 AgentWatch 可以持续监控你的资源、识别趋势，并交付可操作的情报，而无需你手动查询仪表盘或翻查日志。既然你已经理解了 ambient agent 的概念，接下来我们看看 AgentWatch 如何为 AWS 基础设施监控落实这些原则。

## 认识 AgentWatch

我们把 AgentWatch 构建为基于 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 大语言模型（LLM）的 ambient AWS 监控 agent，并使用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) Runtime 进行部署——这是一个专为大规模运行 AI agent 而构建的安全无服务器托管环境。借助 [AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-getting-started.html)，你可以把 agent 部署为可通过编程方式调用的 HTTP 端点。AgentCore Runtime 会**自动处理**身份认证、扩缩容和基础设施管理，因此你可以专注于 agent 的能力，而不是运维问题。

AgentWatch 演示了你如何实现智能基础设施监控，在自动化与人工控制之间取得平衡。我们正在构建一个混合型 ambient agent：它执行的某些任务完全自主（例如监控资源利用率和提供信息等低风险活动），而其他操作则需要用户配置和批准，例如分析告警原因和实施修复。

你的组织可能使用不同的沟通工具进行协作。随着 AI 能力的进步，你将通过 Slack 等各种通信服务，以不同的方式与自主工作者（或 agent）协作。这些 agent 能更快、更高效地完成任务，同时与最终用户保持更紧密的反馈闭环。在本解决方案中，我们使用 Slack 作为最终用户界面，ambient agent 在这里发布消息，你也可以在这里按需与 agent 交互。

有了这个基础，我们来看看 AgentWatch 如何通过三种核心模式保持适当的人工监督。

## human-in-the-loop 模式

human-in-the-loop（HITL）是构建可信 ambient agent 的基础。ambient agent 虽然自主运行，但必须知道何时在决策过程中引入人类。AgentWatch 实现了三种核心 HITL 模式，在自主性与适当的人工监督之间取得平衡：

- **通知（Notify）模式：** 通知模式在重要事件发生时向你告警，但不采取任何行动。这适用于标记你应该知晓、但 agent 无权处理的事件。  **实现方式：** 每 15 分钟（该间隔可参数化，由 MonitoringSchedule 的速率控制；也可以选择 5、10、30、60 分钟的间隔），AgentWatch 会生成一份监控报告，涵盖跨 AWS 服务的 CloudWatch 告警、关键问题和资源健康状况。该 agent 把这些报告发布到 Slack 频道，让你的团队随时了解情况，而无需立即采取行动或批准。我们选择 15 分钟间隔，是为了在及时发现问题和合理的 API 使用量、通知频率之间取得平衡。这个间隔短到足以快速捕捉问题，又长到足以避免告警疲劳。
- **询问（Question）模式：** 当 agent 遇到如何继续推进的不确定性时，询问模式允许它向你请求澄清。这有助于防止 agent 在面临模糊情况时做出错误假设或采取不当行动。  **实现方式**：如果 AgentWatch 检测到严重告警，但不清楚应该进行自动修复还是升级给值班工程师，它会向 Slack 发布一个问题以请求指导。这模拟了站点可靠性工程师（SRE）在对生产系统做出重大变更之前，先咨询资深管理员的做法。
- **审核（Review）模式：** 借助审核模式，你可以在 agent 执行操作之前批准、拒绝或编辑这些操作。这对于需要人工判断的敏感操作尤为重要。  **实现方式**：当 AgentWatch 想要执行可能产生重大影响的操作（例如修改 AWS 资源、调整扩缩容策略或更改告警阈值）时，它会通过 Slack 向你呈现拟议的操作，并附上相关背景和推理过程。随后，你可以批准该操作继续执行、完全拒绝，或在执行前编辑参数。这些 HITL 模式为你的团队带来多重好处。它们通过在关键时刻确保适当的人工监督来降低实施风险。这些模式模仿了工程团队中自然的人际沟通方式，使其易于被采纳。随着时间推移，agent 会从你的反馈中学习，不断改进其决策。

现在，我们来探讨让这些能力得以实现的技术架构。

## 架构与实现

AgentWatch 实现了一个定时监控系统，每 15 分钟自主收集并汇总 AWS 基础设施数据。这种监控方式使用由 AI 驱动的 agent 来收集当前系统信息，并通过 Slack 通知交付结构化的状态报告。

图 1：AgentWatch 架构图

AgentWatch 的监控循环始于 [Amazon EventBridge](https://aws.amazon.com/eventbridge/) 通过基于 cron 的规则每 15 分钟触发一个 [AWS Lambda](https://aws.amazon.com/lambda/) 函数。该 Lambda 函数使用 Open Authorization 2.0（OAuth 2.0）客户端凭证向 [Amazon Cognito](https://aws.amazon.com/pm/cognito/?refid=de90528c-2450-48d7-9981-bc556d44c9ab#Learn-more-about-building-with-Amazon-Cognito) 进行身份认证，获取 bearer token，然后带着监控 prompt 调用 AgentCore Runtime。AgentCore 会实例化一个 LangChain agent——这是一个用于构建由语言模型驱动的应用的框架，这类应用可以使用工具并维护对话上下文——该 agent 可以访问七个专用于 AWS 基础设施的监控工具，这些工具配备了专门的 CloudWatch 监控能力，可系统性地收集基础设施数据，包括仪表盘、日志组、服务日志、错误模式、告警状态和跨账户指标，从而为你整个 AWS 环境提供全面的可见性。

数据收集完成后，LangChain agent 会把聚合后的 CloudWatch 数据发送给 [Amazon Bedrock 的 Claude Sonnet 模型](https://aws.amazon.com/bedrock/anthropic/)，由该模型处理原始监控信息，并把它转换为有上下文、人类可读的洞察。智能摘要会经由该 agent 流回 AgentCore Runtime，再返回 Lambda 函数；Lambda 函数把分析结果格式化为结构化的 Slack block，其中包含日志分析和告警状态等条理清晰的章节。随后，AgentWatch 通过 webhook 把格式化后的监控报告投递到你指定的 Slack 频道，在你的协作工作区内定期提供关于 AWS 基础设施的自动化健康更新——这些监控任务全程无需人工干预。

我们把 AgentWatch 构建为一个 LangChain agent，它可以访问七个专用于 AWS 基础设施的监控工具。该 agent 使用 Amazon Bedrock 的 Claude 模型进行自然语言理解，能够分析 CloudWatch 仪表盘、获取日志、检查告警，并执行跨账户监控。该架构遵循混合型 ambient 模式，同时具备定时监控和按需交互能力。借助 LLM 的自然语言理解能力，AgentWatch 可以分析复杂的 AWS 监控场景。它会判断哪些工具组合能提供监控覆盖，然后生成包含可操作洞察、人类可读的报告。该 agent 会在多次交互之间保持对话上下文，从而支持后续提问和对监控策略的逐步细化。

把 agent 部署到 AgentCore Runtime 上，它提供了安全、无服务器且专为大规模运行 AI agent 而构建的托管环境。AgentCore Runtime 支持多种 agent 框架和模型提供商。部署 agent 之后，它就会成为一个可通过编程方式调用的 HTTP 端点。AgentCore Identity 使用 OAuth 2 进行身份认证，并以 Cognito 作为身份提供商，不过你也可以使用**其他**符合 OpenID Connect（OIDC）的身份提供商（IdP）。

部署基础设施由三个协同工作的主要组件构成。首先，一个 Lambda 函数充当编排层。它向 Cognito 进行身份认证以获取 bearer token，带着适当的 prompt 调用 AgentCore Runtime 端点，并为 Slack 格式化响应。

```
@app.entrypoint
def agent_handler(payload: Dict[str, Any]) -> str:
	# Extract prompt and session context
	user_prompt = payload.get("prompt")
	thread_id = payload.get("session_id", "default-session")
   # Invoke agent with conversation memory
   result = monitoring_agent.invoke(
		{"messages": [{"role": "user", "content": user_prompt}]},
		{"configurable": {"thread_id": thread_id}}
)
return result['messages'][-1].content
```

其次，EventBridge 通过一条配置为每 15 分钟触发的规则提供定时调用能力。规则触发时，Lambda 会使用预先配置的监控 prompt，请求汇总 CloudWatch 告警、关键问题和资源健康状况。

第三，[Amazon API Gateway](https://aws.amazon.com/api-gateway/) 把 Lambda 函数暴露为 HTTP 端点，并通过 slash 命令与 Slack 应用集成。你在 Slack 中输入的问题会路由到 API Gateway，后者以你的问题作为 prompt 触发 Lambda。

这种双触发架构让 AgentWatch 可以在两种模式下运行。在*定时模式*下，agent 每 15 分钟自主运行一次，主动监控 AWS 基础设施并发布报告，无需人工干预即可让你的团队了解情况。在*按需模式*下，你可以通过 Slack 提出具体问题并立即收到响应，从而在需要时进行交互式故障排查和调查。

## 用例与收益

AgentWatch 在多种运营场景中创造价值。该解决方案通过持续分析你 AWS 基础设施中的 CloudWatch 指标、日志和告警，在潜在问题影响用户之前识别它们。这种主动式方法降低了运营开销，让你的团队减少日常监控任务的耗时，同时通过自动化报告和智能告警保持对系统健康状况的可见性。

## 开始使用

要开始使用 AgentWatch，请访问 [GitHub 仓库](https://github.com/aws-samples/sample-ambient-agents-on-agentcore)，获取完整的部署说明和实现细节。

### 前提条件

在部署 AgentWatch 之前，请确认你拥有一个具备 CloudWatch、Lambda 和 EventBridge 权限的 AWS 账户。你还需要一个为 OAuth 2.0 身份认证配置好的 Cognito 用户池，以及一个你拥有应用创建权限的 Slack 工作区。本地开发和定制需要 Python 3.11 或更高版本。

### 快速设置

使用以下命令进行快速设置。

- 配置身份提供商  `python idp_setup/setup_cognito.py`
- 部署 Agent 到 AgentCore Runtime  `# Install the latest AgentCore CLI npm install -g @aws/agentcore # Create an AgentCore project and bring your existing agent code agentcore create --name AgentWatch --no-agent agentcore add agent \ --name AgentWatch \ --type byo \ --code-location . \ --entrypoint ambient_agent.py \ --language Python # Deploy to AgentCore Runtime agentcore deploy`
- 部署基础设施。  `cd deployment ./deploy.sh`
- 配置 Slack 集成——使用部署输出中的 API Gateway 端点更新你的 Slack 应用。

部署脚本会自动完成整个设置流程。它会配置你的身份提供商（Cognito）、把 agent 部署到 AgentCore Runtime，并设置 Lambda 函数、EventBridge 规则和 API Gateway。完成后，脚本会提供 Slack webhook URL，你在配置应用时需要用到它。

### 测试部署

- 定时监控：AgentWatch 每 15 分钟自动发布报告。
- 按需查询：使用 Slack slash 命令提出具体问题：  `/ask What is the status of my CloudWatch alarms? /ask Show me recent errors in my Lambda functions /ask Analyze log patterns for the last hour`

部署完成后，请确保你的实现遵循以下安全和运维最佳实践。

## 安全与最佳实践

AgentWatch 实现了多层安全机制来保护你的基础设施。基于 Cognito 的 OAuth 2.0 支持安全的 API 访问，而 AWS Identity and Access Management（IAM）角色代入可提供细粒度的跨账户权限。AgentCore Runtime 增加了企业级的安全与合规能力。为保障运营安全，HITL 模式有助于防止不当的自主操作。该 agent 的对话记忆在保持上下文的同时遵守会话边界，而日志记录则提供审计轨迹和故障排查能力。

## 扩展 AgentWatch

我们为监控构建的 ambient agent 架构可以扩展到其他运营领域。

## 结论

在本文中，我们展示了 AgentWatch 如何通过把自主运行与适当的人工监督相结合来改进基础设施监控。你看到了该解决方案如何每 15 分钟执行基础设施检查、把可操作的报告交付到 Slack，并回答关于你 AWS 环境的自然语言查询。三种 human-in-the-loop 模式——通知、询问和审核——确保你在受益于持续智能监控的同时，始终知情且保持控制。

该架构使用 [AWS Managed Services (AMS)](https://aws.amazon.com/managed-services/) 和 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) Runtime，为 ambient agent 部署提供可扩展、安全的基础。你可以把这种方法从 AWS 监控推广到其他需要持续观察并有选择地引入人工参与的领域，包括成本优化、安全监控、合规报告和性能分析。

随着 AI agent 变得更加精密，像 AgentWatch 这样的 ambient 架构将帮助你在提高运营效率的同时，保留关键基础设施决策所必需的人类判断。要开始使用 AgentWatch，请访问 [AgentWatch – GitHub](https://github.com/aws-samples/sample-ambient-agents-on-agentcore)，获取完整的部署说明和实现细节。
