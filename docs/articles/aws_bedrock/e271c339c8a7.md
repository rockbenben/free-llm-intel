# 使用生成式 AI 为金融合规生成可疑交易报告草稿

金融法规与合规要求不断变化，合规报告的自动化已成为金融行业的变革力量。[Amazon Web Services](https://aws.amazon.com/)（AWS）的[生成式 AI](https://aws.amazon.com/generative-ai/) 解决方案提供了一条无缝、高效的方式来把这套报告流程自动化。把 AWS 生成式 AI 集成到合规框架中，不仅提升了效率，还通过促进合规报告的精确性和及时交付，为金融行业注入更强的信心与信任。这些解决方案帮助金融机构避免不合规带来的高昂代价与声誉后果。这反过来又有助于金融生态的整体稳定与健全，使行业及其服务的消费者共同受益。

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 是一项托管的生成式 AI 服务，可访问各类先进[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM）。它包含的功能便于高效构建生成式 AI 应用，并高度重视隐私与安全。要从 FM 得到好的响应，很大程度上依赖于采用高效的技术向 FM 提供 prompt。[Retrieval Augmented Generation](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）是一种关键方法，用来自外部源的上下文相关信息来增强 FM 的 prompt。它使用 [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 等向量数据库，对上下文信息进行语义搜索。

[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 由 [Amazon OpenSearch Serverless](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/serverless-overview.html) 等向量数据库支撑，有助于实现 RAG，用来自事实性资源的相关信息补充模型输入，从而减少潜在的幻觉并提升响应准确性。

[Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 让生成式 AI 应用能够借助 action group 执行多步骤任务，并实现与 API、知识库和 FM 的交互。使用 agent，你可以设计出直观、可适应的生成式 AI 应用，它们能够理解自然语言查询，并营造有吸引力的对话来收集有效使用 FM 所需的细节。

可疑交易报告（STR）或可疑活动报告（SAR）是一类报告，当金融机构有合理理由怀疑其业务活动中已经发生或试图发生任何金融交易时，必须向金融监管机构提交。提交这些报告有规定的时限，而为一个客户账户生成一份报告通常需要数小时的人工工作。

本文中，我们探讨一套利用 Amazon Bedrock 中可用 FM 生成 STR 草稿的解决方案。我们介绍如何用生成式 AI 把草稿生成的人工流程自动化——使用账户信息、交易明细和往来函件摘要，并为此类交易涉及的欺诈实体信息建立知识库。

## 解决方案概览

该解决方案使用 Amazon Bedrock Knowledge Bases、Amazon Bedrock Agents、[AWS Lambda](https://aws.amazon.com/lambda/)、[Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）和 OpenSearch Service。工作流如下：

- 用户通过业务应用请求创建 STR 报告草稿。
- 应用调用 Amazon Bedrock Agents，该 agent 已预配置了详细指令，用于与用户进行对话式交互。agent 遵循这些指令从用户处收集所需信息，通过 action group 调用 Lambda 函数补齐缺失信息，并按指定格式生成报告。
- 按照其指令，agent 调用 Amazon Bedrock Knowledge Bases，查找可疑交易涉及的欺诈实体的详细信息。
- Amazon Bedrock Knowledge Bases 查询 OpenSearch Service，对报告所需的实体执行语义搜索。如果 Amazon Bedrock Knowledge Bases 中存在欺诈实体的信息，agent 就遵循其指令为用户生成报告。
- 如果在知识库中找不到信息，agent 就通过聊天界面提示用户提供包含相关信息的网站 URL。用户也可以在聊天界面中提供对欺诈实体的描述。
- 如果用户提供了可公开访问网站的 URL，agent 就遵循其指令调用 action group 来调用 Lambda 函数抓取该网站 URL。Lambda 函数从网站抓取信息并返回给 agent，供报告使用。
- Lambda 函数还会把抓取到的内容存入 S3 存储桶，供搜索索引后续使用。
- 可以设置 Amazon Bedrock Knowledge Bases 定期扫描 S3 存储桶，把新内容索引到 OpenSearch Service。

### 创建网站抓取 Lambda 函数

使用 Python 3.13 运行时创建一个名为 `Url-Scraper` 的新 Lambda 函数，用于抓取 Amazon Bedrock Agents 提供的网站 URL 并提取内容。该函数会抓取内容、把信息发送给 agent，并把内容存入 S3 存储桶以便日后参考。

[![Lambda 函数设置页面，包含运行时和架构选项](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/08/ML-16279-image-5.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/08/ML-16279-image-5.png)

为简洁起见，此代码片段中省略了错误处理。完整代码可在 [GitHub](https://github.com/aws-samples/suspicious-financial-transactions-reporting) 中获取。

新建一个名为 `search_suspicious_party.py` 的文件，写入以下代码片段：

```
import boto3
from bs4 import BeautifulSoup
import os
import re
import urllib.request
BUCKET_NAME = os.getenv('S3_BUCKET')
s3 = boto3.client('s3')
def get_receiving_entity_from_url(start_url):
    response = urllib.request.urlopen(
        urllib.request.Request(url=start_url, method='GET'),
        timeout=5)
    soup = BeautifulSoup(response.read(), 'html.parser')
    # Extract page title
    title = soup.title.string if soup.title else 'Untitled'
    # Extract page content for specific HTML elements
    content = ' '.join(p.get_text() for p in soup.find_all(['p', 'h1', 'h2', 'h3', 'h4', 'h5', 'h6']))
    content = re.sub(r'\s+', ' ', content).strip()
    s3.put_object(Body=content, Bucket=BUCKET_NAME, Key=f"docs/{title}.txt")
return content
```

把 `lambda_function.py` 中默认生成的代码替换为以下代码：

```
import json
from search-suspicious-party import *
def lambda_handler(event, context):
    # apiPath should match the path specified in action group schema
    if event['apiPath'] == '/get-receiving-entity-details':
        # Extract the property from request data
        start_url = get_named_property(event, 'start_url')
        scraped_text = get_receiving_entity_from_url(start_url)
        action_response = {
            'actionGroup': event['actionGroup'],
            'apiPath': event['apiPath'],
            'httpMethod': event['httpMethod'],
            'httpStatusCode': 200,
            'responseBody': {
                'application/json': {
                    'body': json.dumps({'scraped_text': scraped_text})
                }
            }
        }
        return {'response': action_response}
    # Return an error if apiPath is not recognized
    return {
        'statusCode': 400,
        'body': json.dumps({'error': 'Invalid API path'})
    }
def get_named_property(event, name):
    return next(
        item for item in
        event['requestBody']['content']['application/json']['properties']
        if item['name'] == name
    )['value']
```

### 设置 Amazon Bedrock Agents

要在 Amazon Bedrock 中创建新 agent，请完成以下步骤。了解更多信息，请参考[手动创建并配置 agent](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-create.html)。

- 在 Amazon Bedrock 控制台的导航窗格中选择 **Agents**，然后选择 **Create Agent**。
- 在 **Name** 中填入名称（例如 `agent-str`）。
- 选择 **Create**。

- 在 **Select model** 中选择模型提供商和模型名称（例如 Anthropic 的 Claude 3.5 Haiku）
- 在 **Instructions for the Agent** 中提供指令，让 agent 能够调用[大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLM）。

- 在 **Action groups** 下选择 **Add**，创建一个新的 action group。

action 是 agent 通过发起 API 调用可以执行的任务。一组 action 构成一个 action group。

- 提供一份 API schema，定义该 action group 中的所有 API。
- 在 **Action group** 详情中填入 action group 名称（例如 `agent-group-str-url-scraper`）。
- 在 **Action group type** 中选择 **Define with API schemas**。
- 在 **Action group invocation** 中选择 **Select an existing Lambda function**，即你之前创建的那个 Lambda 函数。

[![Action group 配置界面，包含 Lambda 函数选择与 API schema 选项](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/08/ML-16279-image-17.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/08/ML-16279-image-17.png)

- 在 **Action group schema** 中选择 **Define via in-line schema editor**。
- 把默认示例代码替换为以下示例，以定义 [schema](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-api-schema.html)，指定带有默认值和必填值的输入参数：

```
openapi: 3.0.0
info:
  title: Gather suspicious receiving entity details from website
  version: 1.0.0
paths:
  /:
    post:
      description: Get details about suspicious receiving entity from the URL
      operationId: getReceivingEntityDetails
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: "#/components/schemas/ScrapeRequest"
      responses:
        "200":
          description: Receiving entity details gathered successfully
components:
  schemas:
    ScrapeRequest:
      type: object
      properties:
        :
          type: string
          description: The URL to start scraping from
      required:
        - start_url
```

### Agent 指令

Amazon Bedrock Agents 的 agent 指令为多步骤用户交互提供了机制，用来收集 agent 调用 LLM 所需的输入，并以丰富的 prompt 生成符合所需格式的响应。请用平实的英语提供合乎逻辑的指令。这些指令没有预定义的格式。

- 提供任务概览，包括角色：

```
You are a financial user creating Suspicious Transaction Report (STR) draft for a financial compliance use case.
```

- 提供 agent 可用于发起用户交互的消息：

```
Greet the user with the message “Hi <name>. Welcome to STR report drafting. How can I help?”
Ask the user to provide the transactions details. From the transaction details, capture the response in the <answer> tag and include the <thinking> tag to understand the rationale behind the response.
```

- 说明需要对从 LLM 收到的输出做哪些处理：

```
For the transaction input provided by user, create a narrative description for financial risk reporting of the provided bank account and transaction details.
1. Add a summary of correspondence logs that includes title, summary, correspondence history, and analysis in the narrative description.
2. Add the details about the receiving entity in the narrative description. You can get details about receiving entities from the agent action group.
```

- 提供可选消息，供 agent 在多步骤交互中按需收集缺失输入时使用：

```
If you don't have knowledge about Receiving entity, you should ask the Human for more details about it with a message “Unfortunately I do not have enough context or details about the receiving entity <entity name> to provide an accurate risk assessment or summary. Can you please provide some additional background information about <entity name>? What is the URL of the <entity name> or the description?”
```

- 说明 agent 可以通过 action group 采取哪些动作来处理用户输入：

```
If user provides the URL of <entity name>, call the action group <add action group name> to get the details. If user provides the description of <entity name>, then summarize and add it to the narrative description as a receiving entity.
```

- 说明 agent 应如何给出响应，包括格式细节：

```
Once you have all the necessary input (financial transaction details and receiving entity details), create a detailed well-formatted draft report for financial risk reporting of the provided bank account and transaction details containing the following sections:
1. Title
2. Summary of transactions
3. Correspondence History & Analysis
4. Receiving entity summary
```

## 结论

本文中，我们展示了 Amazon Bedrock 如何为构建生成式 AI 应用提供稳健的环境，其中包含一系列先进的 FM。这项完全托管的服务以隐私和安全为先，同时帮助开发者高效构建 AI 驱动的应用。RAG 是一项突出功能，它使用外部知识库，以相关信息丰富 AI 生成的内容，并由 OpenSearch Service 作为其向量数据库提供支撑。此外，你还可以把元数据字段加入知识库和 agent 会话上下文，配合 [Amazon Verified Permissions](https://aws.amazon.com/verified-permissions/) 传递细粒度的访问上下文用于授权。

通过精心的 prompt engineering，Amazon Bedrock 能最大限度地减少不准确之处，并确保 AI 响应以事实性文档为依据。先进技术与数据完整性的这种结合，使 Amazon Bedrock 成为任何想要开发可靠生成式 AI 解决方案的人的理想之选。你现在可以探索扩展这份示例代码，用 Amazon Bedrock 和 RAG 可靠地为合规报告生成文档草稿。
