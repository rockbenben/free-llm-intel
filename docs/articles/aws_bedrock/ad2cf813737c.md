# 在 Amazon Bedrock 中使用生成式 AI 增强设备维护中的建议生成

在制造业中，来自服务报告的有价值洞察往往在文档存储系统里未被充分利用。本文探讨 [Amazon Web Services](https://aws.amazon.com/)（AWS）客户如何构建一套方案，使用[生成式 AI](https://aws.amazon.com/generative-ai/)自动化地从大量报告中数字化并提取关键信息。

该方案使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的 [Amazon Nova Pro](https://aws.amazon.com/ai/generative-ai/nova/)，并结合 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)，利用已有的专家建议知识库，生成与所观察到的设备状态相一致的建议操作。随着方案被使用，知识库会随时间不断扩展。

Amazon Bedrock 是一项完全托管的服务，通过单一 API 提供来自 AI21 Labs、Anthropic、Cohere、Meta、Stability AI、Mistral 和 Amazon 等领先 AI 公司的高性能基础模型（FM）供你选择，并提供广泛的能力，让你能够以安全、隐私和负责任 AI 的方式构建生成式 AI 应用。

[Amazon Bedrock Knowledge Base](https://aws.amazon.com/bedrock/knowledge-bases/) 提供完全托管的端到端检索增强生成（RAG）工作流，通过纳入来自公司数据源的上下文信息，创建高度准确、低延迟且定制化的生成式 AI 应用，因此非常适合存储工程师从过往报告中得出的专家建议，并让 FM 能够准确地定制其回答。

传统的服务与维护周期依赖具备专家知识的工程师手动提交报告。花费在查阅过往报告上的时间可能导致运营延迟和业务中断。该方案让设备维护团队能够：

- 摄取（多语言的）检查与维护报告，并提取设备状态和待办操作，提升可见性与可执行性
- 借助经验丰富的工程师的专业知识生成稳健、可信的建议
- 将专家工程师构建的初始知识库扩展，纳入经确认有效的生成建议
- 通过一个在 AWS 上精简设备维护流程的集中式、AI 驱动的工具，加快维护时间并防止计划外停机

为帮助你实施该方案，我们提供了一个 GitHub 仓库，其中包含可部署的代码和基础设施即代码（IaC）模板。你可以使用该 [GitHub 仓库](https://github.com/aws-samples/sample-bedrock-equipment-maintenance) 在你自己的 AWS 环境中快速搭建并定制该方案。

## 方案概览

下图是本文所述方案的架构表示，展示了所用到的各项 AWS 服务。使用这个 GitHub 仓库，你可以将方案部署到自己的 AWS 账户中进行测试。

![Architecture Diagram of Solution](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/10/abb-drawio.png)

以下是该方案的关键工作流：

- **使用 Amazon Textract 自动摄取服务报告** – 报告摄取工作流会处理服务报告并将其转换为标准化格式。该工作流使用 [Amazon Textract](https://aws.amazon.com/textract/) 进行光学字符识别（OCR），使用 [Amazon Translate](https://aws.amazon.com/translate/) 进行语言翻译，使用 [Amazon Comprehend](https://aws.amazon.com/comprehend/) 进行语言检测。无论报告原本是什么格式或语言，这些服务都能提供经过准确处理、可用于元数据提取的报告。
- **使用 RAG 智能生成建议** – 摄取完成之后，元数据提取与标准化流程使用 RAG 架构，并结合 [Amazon Bedrock 中的 Amazon Nova Pro](https://aws.amazon.com/ai/generative-ai/nova/) 与 Amazon Bedrock Knowledge Bases。该工作流从报告中提取关键元数据，并使用 RAG 流程生成精确且可执行的维护建议。元数据经过标准化以保证一致性与可靠性，为建议提供坚实基础。
- **使用 Amazon SageMaker Ground Truth 进行专家验证** – 为验证并完善生成的建议，方案纳入了使用 [Amazon SageMaker Ground Truth](https://aws.amazon.com/sagemaker/groundtruth/) 的专家审阅流程。该工作流涉及创建定制标注作业，由专家审阅并验证建议的准确性和可靠性。这一反馈回路有助于持续提升模型表现，使维护建议更加可信。
- **为后续处理扩展知识库** – 该工具的知识库需要针对每种设备类型补充新规则，主要来自两个来源：分析过往设备与维护报告，以获得关于建议操作的标注数据；强化工具生成并经人类专家核验的有效建议。

这套汇编而成的规则集由专家审阅、划定关键性等级，然后自动同步到 Amazon Bedrock Knowledge Bases，以持续提升方案在生成下一条建议操作时的信心。这些工作流共同构成从报告摄取到可执行建议的无缝高效流程，为维护运营产出高质量洞察。该方案可通过 Terraform 以 IaC 方式部署和扩展，便于在各种环境中实施与推广。团队可以灵活地向全球客户高效推广该方案，提升维护运营水平并减少计划外停机。以下几节中，我们将逐步介绍定制和部署该方案的步骤。

## 先决条件

要部署该方案，你必须拥有一个具有相应权限、并且能够访问 Amazon Bedrock 上 Amazon Nova FM 的 AWS 账户。这可以在 Amazon Bedrock 控制台页面上启用。

## 克隆 GitHub 仓库

将包含该方案 IaC 的 [GitHub 仓库](https://github.com/aws-samples/sample-bedrock-equipment-maintenance) 克隆到本地机器。

## 定制 ReportsProcessing 函数

要定制 `ReportsProcessing` [AWS Lambda](https://aws.amazon.com/lambda) 函数，请按以下步骤操作：

- 打开 `lambdas/python/ReportsProcessing/extract_observations.py` 文件。该文件包含 `ReportsProcessing` Lambda 函数的逻辑。
- 修改该文件中的代码，加入你根据报告特定文档样式处理报告的自定义逻辑。例如，你可能需要修改 `extract_metadata` 函数以处理不同的报告格式，或调整 `standardize_metadata` 函数中的逻辑以符合你所在组织的标准。

## 定制 RecommendationGeneration 函数

要定制 `RecommendationGeneration` Lambda，请按以下步骤操作：

- 打开 `lambdas/python/RecommendationGeneration/generate_recommendations.py` 文件。该文件包含 `RecommendationGeneration` Lambda 函数的逻辑，它使用 RAG 架构。
- 修改该文件中的代码，加入你根据具体需求生成建议的自定义逻辑。例如，你可能需要调整 `query_formulation()` 函数以修改发送给 Anthropic Claude 3 Sonnet 的 prompt，或更新 `retrieve_rules` 函数以定制从知识库中的检索过程。

## 更新 Terraform 配置

如果你更改了 Lambda 函数名称、角色或其他 AWS 资源，请更新 `terraform` 目录中相应的 Terraform 配置文件以反映这些更改。

## 初始化 Terraform 工作目录

打开终端或命令提示符，切换到已克隆仓库中的 `terraform` 目录。输入以下命令以初始化 Terraform 工作目录：

```
terraform init
```

## 预览 Terraform 变更

在应用变更之前，输入以下命令预览 Terraform 运行计划：

```
terraform plan
```

该命令会显示 Terraform 计划对你的 AWS 基础设施所做的变更。

## 部署 Terraform 栈

如果你对计划中的变更满意，输入以下命令将 Terraform 栈部署到你的 AWS 账户：

```
terraform apply
```

输入 `yes` 并按 **Enter** 继续部署。

## 创建 Amazon Bedrock 知识库

部署 Terraform 栈之后，创建一个 Amazon Bedrock 知识库，用以存储和检索维护规则与建议：

```
aws bedrock-agent create-knowledge-base \
--knowledge-base-name "EquipmentMaintenanceKB" \
--description "Knowledge base for equipment maintenance recommendations" \
--storage-configuration '{ "type": "VECTOR_STORE", "vectorStore": { "embeddingModelArn": "arn:aws:bedrock:{aws-region}::foundation-model/amazon.titan-embed-text-v1" } }'
```

知识库创建完成后，不要忘记用相应的知识库 ID 更新 Generate Recommendations lambda 函数的环境变量。

## 上传测试报告并验证方案生成的建议

要测试该方案，请将一份示例维护报告上传到指定的 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）桶：

```
aws s3 cp sample_report.pdf s3://iac-created-reports-bucket/incoming
```

文件上传后，导航到已创建的 [AWS Step Functions](https://aws.amazon.com/step-functions/) 状态机，并确认发生了成功的执行。成功执行的输出必须包含从输入文档中提取的观察结果，以及从知识库中拉取的新生成的建议。

## 清理

当你用完该方案后，请清理你创建的资源以避免持续产生费用。

## 结论

本文概述了如何实施一套基于风险的维护方案，以预先防范潜在故障并避免维护团队的设备停机。该方案凸显了 Amazon Bedrock 的优势。通过将 Amazon Nova Pro 与 RAG 用于你的设备维护报告，工程师和科学家可以专注于提升建议的准确度并提高开发速度。该方案的关键能力包括：

- 使用 Amazon Textract、Amazon Comprehend 和 Amazon Translate 自动摄取并标准化维护报告
- 由 RAG 和 Amazon Bedrock 上的 Amazon Nova Pro 驱动的智能建议生成
- 使用 SageMaker Ground Truth 持续进行专家验证并扩展知识库
- 使用 Terraform 以 IaC 方式实现可扩展、可用于生产的部署

借助 AWS 服务的广度与 Amazon Bedrock 的灵活性，设备维护团队可以精简运营并减少计划外停机。
