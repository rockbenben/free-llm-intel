# 由 Amazon Bedrock 驱动的 DIVA 物流 agent

[DTDC](https://dtdc.in/) 是印度领先的综合快递物流服务商，运营着该国最大的客户接触点网络。DTDC 以技术驱动的物流解决方案服务于横跨多个行业领域的广泛客户，使其成为提供卓越交付的值得信赖的合作伙伴。

DTDC Express Limited 每月收到超过 400,000 次客户查询，涵盖从运单追踪请求到可服务性核查与运费查询。面对如此巨大的货量，他们原有的物流 agent DIVA 运行在僵化的引导式 workflow 上，迫使用户沿固定路径操作，而无法进行自然、动态的对话。这种灵活性缺失加重了客户支持团队的负担、延长了问题解决时间，并带来糟糕的客户体验。

DTDC 在寻找一个更灵活、更智能的助手——它能够理解上下文、处理复杂查询，并在减少对人工坐席依赖的同时提升效率。为了获得更好的客户体验，DTDC 决定使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 为 DIVA 增强生成式 AI 能力。

[ShellKode](https://www.shellkode.com/) 是 AWS 合作伙伴，一家云生云长（born-in-the-cloud）的公司，专注于现代化、安全、数据、生成式 AI 与机器学习（ML）。ShellKode 以推动变革性增长为使命，通过最先进的技术解决方案赋能企业，应对复杂挑战并开启新机遇。凭借深厚的行业专长，他们提供量身定制的战略，在不断演进的数字格局中孕育创新、效率与长期成功。

本文中，我们讨论 DTDC 与 ShellKode 如何借助 Amazon Bedrock 构建 DIVA 2.0——一个由生成式 AI 驱动的物流 agent。

## 解决方案概述

为解决现有物流 agent 的局限，ShellKode 使用 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/)、[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 与一个 API 集成层，构建了一个先进的 agentic 助手。

当客户与 DIVA 2.0 交互时，他们体验到的是一个无缝的对话式界面，能够自然地理解并回应他们的查询。无论是追踪包裹、查询运费，还是询问服务可用性，用户都可以用自己的话提问，无需遵循僵化的脚本。DIVA 2.0 增强的 AI 能力使其能够理解上下文、处理复杂请求并给出准确、个性化的回答，显著改善整体客户体验并减少对人工介入的需求。下面的高层架构图展示了应用流程以及使用 AWS 服务的解决方案架构。

[![](https://d2908q01vomqb2.cloudfront.net/fc074d501302eb2b93e2554793fcaf50b3bf7291/2025/07/23/ML-17898_DTDC-Chatbot-17Apr2025.jpg)](https://d2908q01vomqb2.cloudfront.net/fc074d501302eb2b93e2554793fcaf50b3bf7291/2025/07/23/ML-17898_DTDC-Chatbot-17Apr2025.jpg)

DTDC 物流 agent 采用模块化、可扩展的架构设计，以实现无缝集成与高性能。这一精简的 workflow 展示了这样一个生成式 AI 驱动的 serverless 物流 agent：它使用 [AWS App Runner](https://aws.amazon.com/apprunner/)、Amazon Bedrock Agents、[AWS Lambda](https://aws.amazon.com/lambda) 与一个基于向量的知识库，智能且高效地处理从运单追踪请求到可服务性核查与运费的各类用户查询。

该物流 agent 使用 [Amazon CloudFront](https://aws.amazon.com/cloudfront/) 与 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）以静态网站方式托管。物流 agent 与 [DTDC 网站](https://dtdc.in/) 集成，为最终用户交互提供直观、易用的界面（见下面的截图）。

[![](https://d2908q01vomqb2.cloudfront.net/fc074d501302eb2b93e2554793fcaf50b3bf7291/2025/07/23/ML-17898_DTDC-Website.png)](https://d2908q01vomqb2.cloudfront.net/fc074d501302eb2b93e2554793fcaf50b3bf7291/2025/07/23/ML-17898_DTDC-Website.png)

最终用户通过 DTDC 网站访问该物流 agent，并用自然语言提交诸如追踪货件、检查服务可用性、计算运费、常见问题等查询。用户请求由 App Runner 处理，它帮助在 AWS 上运行 Web 应用（包括 API 服务、后端 Web 服务与网站）。App Runner 上托管了多个 API 服务，例如 Amazon Bedrock Agents API 与 Dashboard API。App Runner 根据用户请求发起对 Amazon Bedrock Agents API 的调用。

Amazon Bedrock 是一项完全托管的服务，提供多种业界领先的基础模型（FM）以及一整套构建生成式 AI 应用的能力，并通过安全性、隐私保护与负责任 AI 简化开发。使用 Amazon Bedrock 时，你的内容不会被用来改进基础模型，也不会与任何模型提供方共享。[Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 提供可配置的防护措施，帮助大规模安全地构建生成式 AI 应用。要了解更多，请参阅[使用 guardrails 构建安全、负责任的生成式 AI 应用](https://aws.amazon.com/blogs/machine-learning/build-safe-and-responsible-generative-ai-applications-with-guardrails/)。[AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）帮助管理员安全地控制谁可以通过身份验证并被授权使用 Amazon Bedrock 资源。

Amazon Bedrock agent 在 Amazon Bedrock 中配置。Amazon Bedrock agent 接收请求，并利用其自然语言理解能力解读用户意图。根据所解读的意图，agent 触发相应的 Lambda 函数，例如：

- 追踪货运单
- 价格信息
- 地点可服务性核查
- 创建支持工单

被触发的 Lambda 函数调用以下客户端 API，检索相关数据，并把响应返回给 agent：

- **Tracking System API** —— 检索实时状态并提供货运单运输追踪的更新
- **Delivery Franchise Location API** —— 检查在地点之间投递包裹的服务可用性
- **Pricing System API** —— 根据用户提供的货运详情计算运费
- **Customer Care API** —— 为最终用户创建支持工单

agent 把响应传给大语言模型（LLM）——此处为 Amazon Bedrock 上的 Anthropic Claude 3.0，由它理解所检索数据的上下文、进行处理，并为用户生成有意义的回答。

知识库包含从 DTDC 网站抓取的网页内容、内部支持文档、常见问题与运营数据，支持实时更新与准确的回答。知识库内容以向量嵌入（vector embedding）形式存储在 [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 中，从而提供快速且相关的回答。对于一般性查询，物流 agent 从 Amazon Bedrock Knowledge Bases 获取信息，以保证准确性与相关性。通过语义相似度搜索，系统依据用户查询从知识库中检索相关的信息片段，Amazon Bedrock 随后用这些内容生成结合上下文的回答。如果在知识库中找不到相关数据，则返回一个回退回答（已在 Amazon Bedrock prompt 中预配置），说明系统无法处理该请求。

物流 agent 的查询及关联响应存储在 [Amazon Relational Database Service（Amazon RDS）for PostgreSQL](https://aws.amazon.com/rds/postgresql/) 中，以获得更强的可扩展性与关系型数据处理能力。App Runner 发起 Dashboard API 调用，以更新 Amazon RDS 中的查询与关联响应。我们将在下一节更详细地讨论这一点。

在整个过程中，[Amazon CloudWatch Logs](https://aws.amazon.com/cloudwatch) 捕获意图识别、Lambda 调用、API 响应与回退触发等关键事件，用于审计与系统监控。[AWS CloudTrail](https://aws.amazon.com/cloudtrail) 记录并监控 AWS 账户中的活动，包括用户、角色或 AWS 服务执行的操作。它记录这些事件，可用于运营审计、治理与合规。

[Amazon GuardDuty](https://aws.amazon.com/guardduty/) 是一项威胁检测服务，持续监控、分析并处理你 AWS 环境中的 AWS 数据源与日志。GuardDuty 使用威胁情报源——例如恶意 IP 地址与域名列表、文件哈希以及 ML 模型——来识别 AWS 环境中可疑且可能恶意的活动。

## 解决方案的挑战与收益

在实施 DIVA 2.0 时，DTDC 与 ShellKode 面临若干重大挑战。从多个遗留系统集成实时数据，对于在追踪、费率与可服务性方面提供准确、最新的信息至关重要；这一点很可能是通过 Amazon Bedrock Agents 稳健的 API 集成能力来解决的。另一个主要障碍是训练 AI 理解复杂的物流术语与多步查询，这一问题通过使用 Amazon Bedrock LLM 与 Amazon Bedrock Knowledge Bases 并以行业特定数据进行微调而得以克服。团队还必须谨慎处理从僵化的旧 DIVA 系统迁移的过程，同时保持服务连续性并保留历史数据，可能采用了并行系统分阶段推进的方式。最后，扩展解决方案以处理每月超过 400,000 次查询并同时保持性能也是一项重大挑战，这一问题通过使用 Amazon Bedrock Agents 的云基础设施来获得最佳可扩展性与性能而得到解决。这些挑战凸显了在物流这类高流量、数据密集型行业中升级到 AI 驱动系统的复杂性，也说明 AWS 解决方案如何提供了克服这些障碍所需的工具。通过使用 Amazon Bedrock 为物流 agent 注入生成式 AI 能力，DTDC 获得了以下收益：

- **增强的对话与实时数据访问（配合客户支持坐席）** —— 在 Amazon Bedrock Agents 的驱动下，该方案提升了自然语言理解能力，带来更流畅、更有吸引力的对话。凭借多步推理，它能以更高准确率处理更广泛的查询。此外，通过与 DTDC 的 API 层无缝集成，物流 agent 可实时访问追踪货件、服务可用性与计算运费等关键信息。先进的对话能力与实时数据相结合，提供快速、准确且与上下文相关的回答。
- **智能数据处理与准确的 FAQ 回答** —— 对于复杂查询，物流 agent 使用 LLM 技术处理原始数据并给出结构化、贴合需求的回答。这确保用户获得清晰、可据以行动的洞察。对于常见问题，物流 agent 使用 Amazon Bedrock Knowledge Bases 提供精确回答而无需人工支持，从而缩短等待时间并提升整体用户体验。
- **降低对在线人工坐席的依赖并持续改进** —— 尽管该物流 agent 并未消除对客户支持的需求，但由客户支持团队处理的查询数量已减少 51.4%。系统通过集成的实时分析，提供关于查询高峰时段、未解决问题与整体参与度等关键性能指标的有价值洞察，帮助随时间推移不断打磨并提升助手的能力。

## 成果

这一由生成式 AI 驱动的物流 agent 减轻了客户支持团队的负担并缩短了问题解决时间，带来更好的客户体验：

- 在 Amazon Bedrock 的驱动下，DIVA 2.0 能理解自然语言查询并支持动态对话，响应准确率达到 93%
- 基于看板最近 3 个月的指标数据，他们观察到以下情况：71% 的咨询与货运单相关（256,048 次），而 29.5% 为一般性咨询（107,132 次）；51.4% 的货运单咨询（131,530 次）未生成支持工单，而 48.6%（124,518 次）产生了新的支持工单；在最终生成工单的咨询中，40% 是先经过客户支持中心再转交 AI 助手，而 60% 是先从 AI 助手开始、之后才涉及客户支持中心

DIVA 2.0 使客户支持团队处理的查询数量减少了 51.4%。DTDC 的支持团队现在可以专注于更关键的问题，从而提升整体效率。
