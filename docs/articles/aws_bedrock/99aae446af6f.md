# 使用 Amazon Bedrock Custom Model Import 部署 GPT-OSS 模型

[Amazon Bedrock Custom Model Import](https://aws.amazon.com/bedrock/custom-model-import/) 现在支持[开放权重的 OpenAI 模型](https://aws.amazon.com/bedrock/openai/)，包括参数量为 [200 亿和 1200 亿](https://openai.com/index/introducing-gpt-oss/) 的 GPT-OSS 变体。GPT-OSS 模型具备推理能力，可与 [OpenAI Chat Completions API](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-completions.html) 配合使用。由于完整保留了 OpenAI API 兼容性，组织可以把现有应用迁移到 AWS，从而获得企业级的安全性、扩展能力与成本管控。

本文中，我们演示如何在 Amazon Bedrock 上使用 Custom Model Import 部署 GPT-OSS-20B 模型，同时与你现有的应用保持完全的 API 兼容性。

## Amazon Bedrock Custom Model Import 概述

Amazon Bedrock Custom Model Import 让你可以把自定义模型带入与你访问基础模型（FM）相同的无服务器环境。所有模型共用一套统一的 API；你无需在多个端点之间来回切换，也不必管理独立的基础设施。

要使用这项功能，请先把模型文件上传到 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3)，然后通过 Amazon Bedrock 控制台发起导入。繁重的工作都由 AWS 承担，包括预置 GPU、配置推理服务器以及按需自动扩展。你可以专注于自己的应用，基础设施交给 AWS 管理。

GPT-OSS 模型支持 [OpenAI Chat Completion API](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-chat-completions.html)，包括消息数组、角色定义（system、user 或 assistant）以及带有 token 用量指标的标准响应结构。你只需把应用指向 Amazon Bedrock 端点，代码库几乎不用改动即可工作。

## GPT-OSS 模型概述

GPT-OSS 模型是 OpenAI 自 GPT-2 以来首批开放权重的语言模型，以 Apache 2.0 许可发布。你可以免费下载、修改和使用它们，包括用于商业应用。这些模型专注于推理、工具使用和高效部署。请根据你的需求选择合适的模型：

- **GPT-OSS-20B（210 亿参数）** – 该模型非常适合对速度和效率要求最高的应用。尽管拥有 210 亿参数，它每个 token 只激活 36 亿，因此在仅有 16 GB 内存的边缘设备上也能平稳运行。它拥有 24 层、32 个专家（每个 token 激活 4 个）和 128k 上下文窗口，性能与 OpenAI 的 o3-mini 相当，同时还能本地部署以获得更快的响应。
- **GPT-OSS-120B（1170 亿参数）** – 它为编码、数学和 agent 式工具使用等复杂推理任务而构建，每个 token 激活 51 亿参数。它拥有 36 层、128 个专家（每个 token 激活 4 个）和 128k 上下文窗口，性能与 OpenAI 的 o4-mini 相当，同时能在单块 80GB GPU 上高效运行。

两个模型都采用混合专家（MoE）架构——模型组件的子集（专家）处理不同类型的任务，每次请求只激活最相关的专家。这种方式在带来强大性能的同时，让计算成本保持可控。

## 了解 GPT-OSS 模型的文件格式

当你从 Hugging Face 下载 GPT-OSS 模型时，会得到几种协同工作的文件类型：

- **权重文件（.safetensors）** – 实际的模型参数
- **配置文件（config.json）** – 定义模型行为的设置
- **Tokenizer 文件** – 负责文本处理
- **索引文件（model.safetensors.index.json）** – 把权重数据映射到具体文件

索引文件需要具备特定的结构才能与 Amazon Bedrock 配合工作。它必须在根层级包含 `metadata` 字段。该字段可以为空（`{}`），也可以包含模型总大小（对于文本模型必须小于 200 GB）。

来自 Hugging Face 的模型有时会包含 `total_parameters` 之类的额外元数据字段，而 Amazon Bedrock 并不支持它们。你必须在导入前删除这些字段。正确的结构应类似下面的代码：

```
{
"metadata": {},
"weight_map": {
"lm_head.weight": "model-00009-of-00009.safetensors",
    ...
  }
}
```

在上传到 Amazon S3 之前，请确保排除 `metal` 目录。

## 解决方案概述

本文中，我们完整走一遍使用 Amazon Bedrock Custom Model Import 的部署流程。我们使用 [Tonic/med-gpt-oss-20b](https://huggingface.co/Tonic/med-gpt-oss-20b) 模型，它是 OpenAI GPT-OSS-20B 的微调版本，专门针对医疗推理和指令遵循做了优化。

部署流程包括四个主要步骤：

- 从 Hugging Face 下载模型文件，并为 AWS 做好准备。
- 把模型文件上传到 Amazon S3。
- 使用 Amazon Bedrock Custom Model Import 把模型导入 Amazon Bedrock。
- 用 OpenAI 兼容的 API 调用测试你的部署。

## 前提条件

开始部署 GPT-OSS 模型之前，请确保你具备以下条件：

- 一个有效且具备相应权限的 AWS 账户
- 以下事项所需的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）[权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-import-iam-role.html)：在 Amazon Bedrock 中创建模型导入作业；把文件上传到 Amazon S3；在部署后调用模型；使用 Custom Model Import 服务角色
- 目标 AWS 区域中的一个 S3 存储桶
- 约 40 GB 的本地磁盘空间用于下载模型
- 访问美国东部（弗吉尼亚北部，us-east-1）区域的权限（基于 GPT-OSS 的自定义模型需要）
- 已安装 2.x 版本的 [AWS Command Line Interface](https://aws.amazon.com/cli/)（AWS CLI）
- Hugging Face CLI（用 `pip install -U "huggingface_hub[cli]"` 安装）

## 把模型文件上传到 Amazon S3

在导入模型之前，你必须把模型文件存放到 Amazon Bedrock 可以访问的 S3 存储桶中。请完成以下步骤：

- 在 Amazon S3 控制台的导航窗格中选择 **Buckets**。
- 创建一个新存储桶，或打开一个已有的存储桶。
- 上传你的模型文件。

或者，使用 AWS CLI 把文件上传到目标 Amazon Bedrock 区域中的 S3 存储桶：

```
aws s3 sync ./med-gpt-oss-20b/ s3://amzn-s3-demo-bucket/med-gpt-oss-20b/
```

40 GB 的上传通常需要 5–10 分钟完成。请验证文件已上传：

```
aws s3 ls s3://amzn-s3-demo-bucket/med-gpt-oss-20b/ --human-readable
```

请记下你的 S3 URI（例如 `s3://amzn-s3-demo-bucket/med-gpt-oss-20b/`），供导入作业使用。

输出文件会按照 S3 存储桶的加密配置进行加密。取决于你如何设置 S3 存储桶，这些文件会使用 [SSE-S3 服务端加密](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingServerSideEncryption.html) 或 [AWS Key Management Service](https://aws.amazon.com/kms)（AWS KMS）的 [SSE-KMS 加密](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingKMSEncryption.html)。

## 使用 Amazon Bedrock Custom Import 导入模型

模型文件已上传到 Amazon S3，现在你可以把模型导入 Amazon Bedrock，它将在那里被处理并可用于推理。请完成以下步骤：

- 在 Amazon Bedrock 控制台的导航窗格中选择 **Imported models**。
- 选择 **Import model**。
- 在 **Model name** 中输入 `gpt-oss-20b`。
- 在 **Model import source** 中选择 **Amazon S3 bucket**。
- 在 **S3 location** 中输入 `s3://amzn-s3-demo-bucket/med-gpt-oss-20b/`。
- 在 **Service access** 中选择 **Create and use a new service role**。Amazon Bedrock 控制台会自动生成一个具有正确信任关系和 Amazon S3 读取权限的角色。
- 选择 **Import** **model** 以启动导入作业。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/11/21/ML-20109-image-5-new.png)

如需使用 AWS CLI，请使用以下代码：

```
aws bedrock create-model-import-job \
  --job-name "gpt-oss-20b-import-$(date +%Y%m%d-%H%M%S)" \
  --imported-model-name "gpt-oss-20b" \
  --role-arn "arn:aws:iam::YOUR-ACCOUNT-ID:role/YOUR-ROLE-NAME" \
  --model-data-source "s3DataSource={s3Uri=s3://amzn-s3-demo-bucket/med-gpt-oss-20b/}"
```

对于 20B 参数规模的模型，模型导入通常需要 10–15 分钟完成。你可以在 Amazon Bedrock 控制台上或使用 AWS CLI 监控进度。完成后请记下 `importedModelArn`，调用模型时会用到它。

## 使用 OpenAI 兼容 API 调用模型

模型导入完成后，你可以用熟悉的 OpenAI Chat Completions API 格式测试它，验证是否按预期工作：

- 创建一个名为 `test-request.json` 的文件，内容如下：

```
{
  "messages": [
    {
      "role": "system",
      "content": "You are a helpful AI assistant."
    },
    {
      "role": "user",
      "content": "What are the common symptoms of Type 2 Diabetes?"
    }
  ],
  "max_tokens": 500,
  "temperature": 0.7
}
```

- 使用 AWS CLI 把请求发送到你导入的模型端点：

```
aws bedrock-runtime invoke-model \
  --model-id "arn:aws:bedrock:us-east-1:YOUR-ACCOUNT-ID:imported-model/MODEL-ID" \
  --body file://test-request.json \
  --cli-binary-format raw-in-base64-out \
  response.json
cat response.json | jq '.'
```

响应以标准 OpenAI 格式返回：

```
{
  "id": "chatcmpl-f06adcc78daa49ce9dd2c58f616bad0c",
  "object": "chat.completion",
  "created": 1762807959,
  "model": "YOUR-ACCOUNT-ID-MODEL-ID",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Type 2 Diabetes often presents with a range of symptoms...",
        "refusal": null,
        "function_call": null,
        "tool_calls": []
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 98,
    "completion_tokens": 499,
    "total_tokens": 597
  }
}
```

响应结构与 OpenAI 的格式完全一致——`choices` 包含响应内容，`usage` 提供 token 计数，`finish_reason` 表示完成状态。现有的 OpenAI 响应解析代码无需修改即可工作。

这类模型的一大优势是透明性。`reasoning_content` 字段会提供模型在生成最终响应之前内部推理过程的信息。这种程度的透明度在闭源 API 中是无法获得的。

## 清理资源

完成后请清理你的资源，以避免不必要的费用：

```
aws bedrock delete-imported-model --model-identifier "arn:aws:bedrock:us-east-1:ACCOUNT:imported-model/MODEL-ID"

aws s3 rm s3://amzn-s3-demo-bucket/med-gpt-oss-20b/ --recursive
```

如果你不再需要该 IAM 角色，请使用 IAM 控制台将其删除。

## 从 OpenAI 迁移到 Amazon Bedrock

从 OpenAI 迁移只需极少的代码改动——只有调用方式发生变化，消息结构完全保持一致。

对 OpenAI，使用以下代码：

```
import openai
response = openai.ChatCompletion.create(model="....", messages=[...])
```

对 Amazon Bedrock，使用以下代码：

```
import boto3, json
bedrock = boto3.client('bedrock-runtime')
response = bedrock.invoke_model(
    modelId='arn:aws:bedrock:us-east-1:ACCOUNT:imported-model/MODEL-ID',
    body=json.dumps({"messages": [...]})
)
```

迁移过程很直接，并且你将获得可预测的成本、更好的数据隐私，以及针对自身需求微调模型的能力。

## 最佳实践

请考虑以下最佳实践：

- **文件校验** – 上传前请验证 `model.safetensors.index.json` 具有正确的 metadata 结构、被引用的 safetensors 文件存在且 tokenizer 受支持。本地校验可以节省导入重试的时间。
- **安全** – 在 Amazon Bedrock 控制台上自动创建具有最小权限的 IAM 角色。对于多个模型，请使用不同的 S3 前缀以保持隔离。
- **版本管理** – 使用有描述性的 S3 路径（`gpt-oss-20b-v1.0/`）或带日期的导入作业名称来跟踪部署。

## 定价

使用导入到 Amazon Bedrock 的自定义模型进行推理会产生费用。更多细节请参阅[计算运行自定义模型的成本](https://docs.aws.amazon.com/bedrock/latest/userguide/import-model-calculate-cost.html)和 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。

本文中，我们展示了如何在 Amazon Bedrock 上使用 Custom Model Import 部署 GPT-OSS 模型，同时保持完全的 OpenAI API 兼容性。你现在可以用极少的代码改动把现有应用迁移到 AWS，并获得企业级收益，包括对模型的完全掌控、微调能力、可预测的定价以及更强的数据隐私。
