# 使用 Amazon Nova 自动对图像中的 PII 进行脱敏

在团队之间共享数据、与外部合作伙伴共享数据，或把数据用于机器学习（ML）模型训练等工作负载，都是现代业务运营的基础。然而，当这些数据包含个人可识别信息（PII）时，组织就要承担《通用数据保护条例》（GDPR）与《支付卡行业数据安全标准》（PCI DSS）等法规带来的重大法律与合规义务。如果在共享或处理数据之前没有妥善脱敏 PII，结果可能是监管处罚、声誉受损以及客户信任的流失。

在真实世界的图像数据集中，PII 脱敏尤其具有挑战性。与结构化文本不同，图像中的 PII 可能出现在意想不到的位置和形态：画面边缘被拍到的半张脸、映在汽车光亮漆面上的脸、只露出一部分但与其它视觉线索结合后就能识别身份的街道标牌，或者广角照片里摊在桌上、泄漏了姓名、地址或证件号码的文件。这些边缘情况常常让单一用途的遮蔽工具失效。

[Amazon Nova](https://aws.amazon.com/nova/models/?trk=33dc490e-0fb2-4cb1-a521-3941c13b64c0&sc_channel=ps) 是一组具备先进视觉理解能力的基础模型，因此非常适合充当复杂图像分析工作流的智能协调者。Nova 会整体理解图像内容，结合上下文判断某个对象是否构成 PII——包括前文描述的细微与罕见情况——并从始至终指挥整条脱敏 pipeline。通过理解 PII 的「是什么」，Nova 协调各类专用工具，在脱敏时达到像素级精度，同时保留图像的整体价值。

在本文中，我们介绍一条由 Amazon Nova 指挥的多步 pipeline，它利用上下文视觉推理来协调互补的工具，包括部署在 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/?trk=047fc009-5bd4-4337-800d-8b880665cece&sc_channel=ps&trk=c3974822-373e-499b-9739-834a50722377&sc_channel=ps&ef_id=CjwKCAjwuO_QBhAWEiwAIkVhU_SEPtv0f-b7rSZQYrxPl_-56NFn16ZJoiNS46JpT4hYCiMKhkwu2xoCNY0QAvD_BwE:G:s&s_kwcid=AL!4422!3!795877020716!e!!g!!sagemaker%20ai!23532472972!194311071804&gad_campaignid=23532472972&gclid=CjwKCAjwuO_QBhAWEiwAIkVhU_SEPtv0f-b7rSZQYrxPl_-56NFn16ZJoiNS46JpT4hYCiMKhkwu2xoCNY0QAvD_BwE) 上、用于像素级分割的 Meta 开源 Segment Anything Model（SAM 3），以及用于光学字符识别（OCR）的 [Amazon Textract](https://aws.amazon.com/textract/)。这条 pipeline 旨在提供全面、合规的 PII 脱敏，即使面对指纹、证件卡片或任意朝向的车牌这类棘手边缘情况也不例外。

## 解决方案概览

本方案使用以下关键服务来实现全面的 PII 脱敏：

### Nova 2 Lite

Amazon Nova 2 Lite 是一个快速、经济高效的多模态基础模型，可处理文本、图像、视频与文档。该模型在 [Amazon Bedrock](https://aws.amazon.com/bedrock) 中提供，具有出色的性价比，帮助企业和开发者构建能力强、可靠且高效的应用。它在本方案中担任中央协调者，协调整个 PII 检测与脱敏工作流，在每个阶段做出决策，并协调各项专用服务以达成全面结果。

### Segment Anything Model（SAM 3）

SAM 3 是一个开源分割模型，能够根据文本与视觉提示检测、分割并跟踪图像中的对象。在本方案中，SAM 3 充当由 Nova 指挥的精密仪器。当 Nova 识别出视觉类 PII 元素时，它会把分割任务交给 SAM 3，以产出用于脱敏的精确边界。

在 model playground 上以「flower」一词作为提示时，SAM 3 的分割掩码叠加在原图上的效果（https://ai.meta.com/research/sam3/）

### Amazon Textract

Amazon Textract 是一项 ML 服务，可从 PDF、图像、表格和表单等格式中自动提取文本、手写内容、版面元素与数据。在这条 pipeline 中，Amazon Textract 充当 Nova 的 OCR 能力。当 Nova 判定某张图像包含文本类 PII 时，它会指示 Amazon Textract 提取全部文本内容及其坐标，随后 Nova 结合整张图像的上下文来评估哪些内容属于敏感信息。

### PII 检测

图像中常见的 PII 项包括但不限于：

- 姓名。
- 证件号码，例如驾驶证号码。
- 地址。
- 电话号码。
- 资产信息，例如媒体访问控制（MAC）地址。
- 财产识别号码，例如车辆识别号码（VIN）。
- 个人特征，例如人脸图像。
- 生物识别数据，例如指纹。

这些项可以归为 2 种模态：文本类（姓名、证件号码、地址、电话号码、资产信息与财产识别号码）与视觉类（个人特征与生物识别数据）。

Nova 指挥的工作流可以访问两个子流程，分别定位文本类或视觉类 PII 项的像素坐标。Nova 首先对图像做一次初步评估，确定存在哪些类型的 PII，然后把图像智能地路由到相应的子流程。随后由一个 AWS Lambda 函数在 Nova 指示下识别出的坐标处遮蔽内容。

本方案非常适合对脱敏准确率要求较高的一次性或批量图像预处理场景。Nova 2 Lite 出色的性价比、低延迟与先进的多模态推理能力，使其很适合协调这条工作流，在既不需要组织具备深厚的机器学习专业能力、也不需要微调专用模型的情况下，交付准确的 PII 脱敏。

## 解决方案架构

本节介绍一套架构指导：由 Nova 驱动图像处理工作流，并指挥并行的文本类与视觉类分析，以识别并脱敏敏感信息。

![由 Amazon Nova 指挥的 PII 检测与脱敏 pipeline 架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/25/ml-20185-arch.png)

### 1. 文档上传与工作流触发

当你把图像上传到 S3 的 `input/` 文件夹时，一条 S3 事件通知会触发 EventBridge 规则，从而启动 AWS Step Functions 工作流。

![第 1 步：上传到 Amazon S3 originals 文件夹的图像会触发 Step Functions 工作流](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/23/20185-1.png)

### 2. 文件校验与 PII 初筛

工作流首先校验你上传的文件类型是否与 Amazon Bedrock 支持的图像格式兼容。校验通过后，Nova 2 Lite 会对图像做初步评估，作为第一道智能防线判断是否存在 PII。如果 Nova 判定不存在 PII，工作流会提前退出，图像立即被移动到 S3 的 noPII/ 文件夹，无需进一步处理即可供下游使用。大多数业务图像都不含 PII。Nova 的这一提前退出决策会在第一个、也是成本最低的步骤上分流掉大量图像。它避免了对 Amazon Textract、SageMaker AI 上的 SAM 3 等下游服务的不必要调用，从而显著降低整条 pipeline 的成本。

![第 2 步：Nova 2 Lite 在进一步处理前校验文件并筛查 PII](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/23/20185-2.png)

### 3. 并行 PII 检测：视觉流程

当 Nova 2 Lite 识别出潜在 PII 时，它会按类型（文本类、视觉类或两者兼有）对检测到的 PII 进行分类，并为下游处理做出路由决策。基于 Nova 的分类结果，Step Functions 工作流会有选择地调用其中一个或两个专用流程：如果 Nova 检测到文本类 PII 就调用文本流程，检测到视觉类 PII 就调用视觉流程，两类都识别到则并行调用两个流程。

视觉流程专注于检测图像中的视觉类 PII 元素，例如人脸与车牌。在 Nova 的指挥下，部署在 SageMaker AI 上的 SAM 3 会收到提示，定位视觉类 PII 元素并产出逐像素的分割掩码。分割掩码是一种像素级轮廓，勾勒出图像中某个对象的精确形状。它把每个像素标记为属于该对象或不属于该对象，类似一张精确的数字镂空模板。与简单的 bounding box（围绕对象的粗略矩形）不同，分割掩码沿着被检测目标的真实轮廓走，因此可以只脱敏敏感像素而不遮蔽周围内容。这种在 Nova 初始 PII 分类引导下的精确做法，有助于在只移除敏感区域的同时保住图像的价值。例如，在大型图像数据集上训练 ML 模型时，这种方法有助于阻止 PII 传入模型，同时保留你的数据集规模与非敏感的视觉信息。

![第 3 步：SageMaker AI 上的 SAM 3 为视觉类 PII 生成分割掩码](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/23/20185-3.png)

### 4. 并行 PII 检测：文本流程

文本流程借助 Amazon Textract，利用 Nova 的多模态推理来分析嵌入图像中的文本。首先，Amazon Textract 定位图像中文本的像素级位置并提取其内容。它会为每个检测到的文本元素同时给出轴对齐 bounding box 与多边形坐标，你可以选择最适合自己脱敏需求的坐标类型。随后，Nova 2 Lite 会把每个提取出的文本元素与原始图像一起评估，判断哪些元素包含姓名、地址或证件号码等 PII。这正是 Nova 上下文智能的关键之处：有些文本元素孤立来看似乎并不构成 PII，但 Nova 可以推理图像中周围的视觉上下文，从而识别出其敏感性质。例如，街道名与街道号被拆到 2 个位置时，单独来看都不构成 PII，但由于它们出现在同一张图像中，完整地址是可见的，就应当作为 PII 予以遮蔽。作为多模态模型，Nova 可以同时处理文本与图像，做出这类细微的 PII 判定。最后，Amazon Textract 返回被 Nova 判定为 PII 的文本坐标，供下一步使用。

### 5. PII 脱敏与最终校验

在这些子流程于 Nova 指挥下完成分析之后，它们输出的坐标会传给下一阶段用于脱敏。请记住，视觉流程的输出是来自 SAM 3 的分割掩码坐标，而文本流程的输出是来自 Amazon Textract 的 bounding box 或多边形坐标。

一个 Lambda 函数会把各流程返回的坐标合并为图像中统一的 PII 位置集合。随后，`RedactPII` Lambda 函数使用 Python 中的 `Pillow`（`PIL`）库遮蔽原图中识别出的区域，并把脱敏后的图像存入 S3 的 redacted/ 文件夹。

作为最后的质量保证步骤，Nova 2 Lite 会对脱敏后的图像做一次全面复核，判断所有检测到的 PII 是否都已移除。这项最终校验利用 Nova 的整体视觉理解能力，捕捉任何残留的敏感内容。如果 Nova 判定图像已经干净，就把它移动到 S3 的 noPII/ 文件夹供下游使用。如果 Nova 仍然检测到 PII，图像会被移动到隔离文件夹进行人工复核，这一设计有助于防止 PII 漏过。

![第 5 步：Lambda 函数脱敏识别出的区域，并由 Nova 校验结果](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/25/ml-20185-p5.png)

### 6. 测试方案

要验证该方案是否正常工作，请按以下步骤操作：

- 准备一张包含 PII 的测试样图。你可以使用 AI 生成的图像。
- 使用 AWS Command Line Interface（AWS CLI）或 Amazon S3 控制台把图像上传到 S3 originals/ 存储桶。
- 在 AWS Step Functions 控制台上监控 Step Functions 执行，跟踪工作流进度。
- 验证脱敏后的图像出现在 S3 的 redacted/ 或 humanreview/ 文件夹中。
- 从 S3 的 redacted/ 或 humanreview/ 文件夹下载输出图像。
- 检查图像，确认 PII 是否已成功移除，或找出需要人工复核的 PII 元素（例如「PII 检测」一节所列举之外的冷门元素）。

## 清理

当你不再需要本方案时，请完成以下步骤清理资源。在执行清理之前，请确保已备份你希望从 S3 存储桶中保留的任何数据。以下步骤将永久删除所有资源与数据。

- 从 S3 存储桶备份任何必要的数据。
- 删除这些 S3 存储桶（`originals/`、`noPII/`、`redacted/` 与 `humanreview/`）
- 删除托管 SAM 3 模型的 SageMaker AI 端点。
- 删除 Step Functions 状态机。
- 删除这些 Lambda 函数（PII 检测、脱敏与最终校验）。
- 删除为 S3 事件通知配置的 EventBridge 规则。

## 结论

在本文中，我们演示了 Amazon Nova 2 Lite 如何充当一条无服务器、自动化 pipeline 的智能协调者，在图像中检测并脱敏 PII，而无需自定义模型训练或微调。Nova 的多模态推理驱动着工作流中的每一项决策：从最初的 PII 检测与分类，到智能路由至 Amazon Textract、Amazon SageMaker AI 上的 SAM 3 这类专用工具，再到对脱敏输出做最终质量校验。凭借 Nova 2 Lite 出色的性价比与先进的视觉能力，组织可以大规模部署 PII 脱敏，同时保持对数据保护法规的完全合规。

本文提供的架构指导可以按你具体的合规要求进行调整，并部署在你自己的 AWS 账户中。要开始使用，请在 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock/)中探索 Amazon Nova 模型，并参阅 [Amazon Nova 文档](https://docs.aws.amazon.com/nova/)、[Amazon Textract 文档](https://docs.aws.amazon.com/textract/) 与 [Amazon SageMaker AI 文档](https://docs.aws.amazon.com/sagemaker/)，以部署本 pipeline 中使用的各项互补服务。
