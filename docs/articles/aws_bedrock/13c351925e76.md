# 基于 Amazon Nova Sonic 的可扩展语音 agent 设计：多 agent、工具与 session segmentation

对于需要提供快速、自然且可靠的语音体验的组织来说，可扩展语音 agent 的设计模式至关重要。许多团队都面临高延迟、实时音频管理，以及在复杂工作流中协调多个 agent 等挑战。

在本文中，你将学习如何使用 [Amazon Nova Sonic](https://docs.aws.amazon.com/ai/responsible-ai/nova-2-sonic/overview.html)、[Amazon Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/securely-launch-and-scale-your-agents-and-tools-on-amazon-bedrock-agentcore-runtime/) 和 [Strands BidiAgent](https://strandsagents.com/docs/user-guide/concepts/bidirectional-streaming/agent/) 来构建可扩展、易维护的语音 agent，高效应对这些挑战，从而带来响应更快、更智能的客户交互。

我们将探讨三种流行的语音 agent 架构模式，说明它们的权衡取舍，以及最大限度降低延迟的最佳实践。

## 基础构件

在深入探讨架构模式之前，先简要概览本文示例方案所使用的三个关键组件。

![展示基于 Amazon Nova Sonic、AgentCore Runtime 和 Strands Agents 的语音 agent 方案基础构件的架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/08/ML-20826-1.png)

Amazon Nova Sonic 是一个基础模型，为生成式 AI 应用打造自然、类似人类的语音到语音对话。用户可以通过语音与 AI 实时交互，具备理解语气、自然对话流程以及执行动作的能力。

Amazon Bedrock AgentCore Runtime 是面向 AI agent 的 serverless 托管环境。你把 agent 打包为容器，部署到 AgentCore Runtime，它会负责扩缩容、会话隔离和计费。对于语音 agent，它提供带 SigV4 认证的[双向 WebSocket streaming](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-bidirectional-streaming.html)、microVM 级别的会话隔离以避免 noisy-neighbor 造成的延迟尖峰、[AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-websocket.html)（使用 Model Context Protocol（MCP）开源协议共享托管工具）、跨会话的持久记忆，以及针对 time-to-first-audio 等语音专属指标的遥测能力。

[Strands Agents](https://strandsagents.com/) 是一个用于构建 AI agent 的开源框架。它的 [BidiAgent](https://strandsagents.com/docs/user-guide/concepts/bidirectional-streaming/quickstart/) 类是 Nova Sonic 与你的应用之间的一种集成选项。它管理双向流生命周期、路由工具调用并处理会话管理，通过模型 SDK 接口简化语音 agent 应用。

## 三种集成模式：工具、agent-as-tool（sub-agent）与 session segmentation

现代语音系统不再构建一个大而全的 agent，而是越来越倾向于由**工具驱动的 agent**、**充当工具的 sub-agent** 以及**隔离 prompt、记忆和权限的 session segmentation 策略**组成。这些模式让团队可以把庞大的助手拆解为更小、更专业、可复用的组件，同时保持清晰的安全边界。

在运行以下各节的示例之前，请安装 Python 及所需依赖（包括 strands-agents 和 boto3），并确保你的 IAM 配置具备所需服务的相应权限。完整示例请参考 [GitHub 仓库](https://github.com/awslabs/agentcore-samples/tree/main/01-tutorials/01-AgentCore-runtime/06-bi-directional-streaming/02-strands-ws)。

### 模式 1：AgentCore Gateway——面向低延迟的工具选择

工具调用指的是语音 agent 把输入发送给外部函数或服务，由其处理后返回结果。它让 agent 能够快速、安全地执行查询数据库或触发服务等任务，而无需额外的推理步骤。

借助 [AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-get-started-websocket.html)，你可以把现有业务逻辑暴露为**工具**——Nova Sonic 在对话中可以直接调用的独立函数。语音模型选择要调用的工具、传入参数、获得结果，再把结果说出来。模型与工具之间没有中间的推理层。

![展示 AgentCore Gateway 工具选择模式的架构图：Nova Sonic 直接调用 MCP 工具](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/08/ML-20826-2.png)

AgentCore Gateway 将 MCP server 托管为托管 endpoint。MCP 是协议，AgentCore Gateway 是运行这些协议的 AWS 功能。语音 agent 通过 Gateway ARN 建立连接。

```
# Nova Sonic calls tools directly via AgentCore Gateway
model = BidiNovaSonicModel(
    model_id="amazon.nova-2-sonic-v1:0",
    mcp_gateway_arn=[
        "arn:aws:bedrock-agentcore:us-east-1:123456789012:gateway/auth-tools",
        "arn:aws:bedrock-agentcore:us-east-1:123456789012:gateway/banking-tools",
        "arn:aws:bedrock-agentcore:us-east-1:123456789012:gateway/mortgage-tools",
    ],
)
```

当用户说“我的账户余额是多少？”时，Nova Sonic 会：

- 从语音中理解意图。
- 从可用的 MCP 工具中选择 `get_account_balance`。
- 用正确的参数调用该工具。
- 把结果说出来。

**权衡：** Nova Sonic 负责所有决策。如果一次工具调用需要多步校验、条件逻辑，或把多个操作串联起来，那么这些推理负担就完全落在语音模型的 system prompt 上。对简单工具来说这没问题；对于复杂工作流，就会变得脆弱。

### 模式 2：Sub-agent——通过解耦的 agent 增加推理能力

采用 sub-agent 或 agent-as-tool 模式时，你现有的业务逻辑运行在各个自主 agent 中，每个 agent 都有自己的模型、system prompt、工具和推理能力。语音编排器把整个任务交给这些 sub-agent，而不是调用单个工具。

从语音 agent 连接 sub-agent 有很多种方式。Agent-to-Agent（A2A）和 Strands Agent-as-Tool 是两种常见做法：

- **本地 agent-as-tool：** sub-agent 在进程内运行，使用 Strands 中的 [Agents as Tools 模式](https://aws.amazon.com/blogs/machine-learning/multi-agent-collaboration-patterns-with-strands-agents-and-amazon-nova/)包装为 `@tool` 函数。这是最直接的方式，没有网络跳转，也不需要单独部署。代价是 sub-agent 与编排器共享同一进程，并随之一起扩缩容。
- **通过 A2A 协议的远程 agent：** sub-agent 部署为独立的 [AgentCore Runtime 上的 A2A server](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-a2a.html)（或远程服务器），通过网络调用。A2A 是用于 agent 间通信的开放协议。正如 MCP 把 agent 连接到工具，A2A 把 agent 连接到其他 agent。正如 AWS 关于 [AgentCore Runtime 中的 A2A 协议支持](https://aws.amazon.com/blogs/machine-learning/introducing-agent-to-agent-protocol-support-in-amazon-bedrock-agentcore-runtime/)的博客所解释的，用不同框架（Strands、OpenAI、LangGraph、Google ADK）构建的 agent 可以用统一格式共享上下文和推理。这提供了完全的部署独立性和跨框架互操作性。

![展示 sub-agent 模式的架构图：Nova Sonic 分派给专业 agent](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/08/ML-20826-3.png)

Strands Agents 对这两种协议都提供内置支持：MCP 用于工具访问，A2A 用于 agent 间通信。想动手实践，请参阅社区指南 [Agent Collaboration: Strands Agents, MCP, and the Agent2Agent Protocol](https://community.aws/content/2xu47bH8LZYPr11tDN2eTDiEL95/agent-collaboration-strands-agents-mcp-and-the-agent2agent-protocol)。

下面是本地 agent-as-tool 的做法，每个 sub-agent 都是一个 `@tool`，内部包装了一个完整的 Strands `Agent`：

```
# sub_agents.py — Define sub-agents as Strands tools using the Agents-as-Tools pattern
from strands import Agent, tool
from strands.models import BedrockModel

# Each sub-agent is a full Strands Agent wrapped as a @tool
# The BidiAgent orchestrator calls these via Nova Sonic's tool use

@tool
def authenticate_customer(account_id: str, date_of_birth: str) -> str:
    """Authenticate a customer using their account ID and date of birth.
    Handles the full verification flow including identity checks and retry logic.
    Returns authentication status and token."""
    auth_agent = Agent(
        model=BedrockModel(model_id="amazon.nova-lite-v1:0"),
        system_prompt="""You are an authentication agent. Verify the customer's identity
        using the provided account ID and date of birth. Call verify_identity to check
        credentials. Return a clear auth status in 1-2 sentences.""",
        tools=[verify_identity, check_account_exists],  # Sub-agent's own tools
    )
    result = auth_agent(f"Authenticate account {account_id}, DOB: {date_of_birth}")
    return str(result)


@tool
def handle_banking_inquiry(query: str, auth_token: str) -> str:
    """Handle banking questions — balances, transactions, transfers.
    Validates permissions and returns a conversational summary."""
    banking_agent = Agent(
        model=BedrockModel(model_id="amazon.nova-lite-v1:0"),
        system_prompt="""You are a banking agent. Use the provided tools to answer
        the customer's query. Summarize results in 2-3 natural sentences.
        Do not return raw JSON.""",
        tools=[get_account_balance, get_recent_transactions, transfer_funds],
    )
    result = banking_agent(query)
    return str(result)


@tool
def handle_mortgage_inquiry(query: str) -> str:
    """Handle mortgage questions — rates, calculations, eligibility, application status.
    Performs its own calculations and reasoning."""
    mortgage_agent = Agent(
        model=BedrockModel(model_id="amazon.nova-lite-v1:0"),
        system_prompt="""You are a mortgage specialist. Help with rate inquiries,
        payment calculations, and eligibility assessments. Keep responses concise
        and conversational — this will be spoken aloud.""",
        tools=[get_mortgage_rates, calculate_payment, check_eligibility],
    )
    result = mortgage_agent(query)
    return str(result)
```

然后，语音编排器使用 BidiAgent 配合这些 sub-agent 工具：

```
# voice_orchestrator.py — BidiAgent with sub-agents as tools
from strands.experimental.bidi.agent import BidiAgent
from strands.experimental.bidi.models.nova_sonic import BidiNovaSonicModel
from sub_agents import authenticate_customer, handle_banking_inquiry, handle_mortgage_inquiry

model = BidiNovaSonicModel(
    region="us-east-1",
    model_id="amazon.nova-2-sonic-v1:0",
    provider_config={"audio": {"voice": "tiffany", "input_sample_rate": 16000, "output_sample_rate": 16000}},
)

agent = BidiAgent(
    model=model,
    tools=[authenticate_customer, handle_banking_inquiry, handle_mortgage_inquiry],
    system_prompt="""You are a banking voice assistant. Route customer requests to the
    appropriate specialist. Always authenticate before accessing account data.
    Keep your own responses brief — the sub-agents handle the details.""",
)

await agent.run(inputs=[ws_input], outputs=[ws_output])
```

sub-agent 自行思考。Nova Sonic 不需要编排各个步骤，只需分派任务并说出结果。

**权衡：** 每次 sub-agent 调用都会增加延迟：sub-agent 自身的模型推理加上它的工具调用。在语音对话中，这意味着 sub-agent 推理时沉默时间更长。AWS 关于[多 agent 语音助手](https://aws.amazon.com/blogs/machine-learning/building-a-multi-agent-voice-assistant-with-amazon-nova-sonic-and-amazon-bedrock-agentcore/)的博客建议，sub-agent 先从 Amazon Nova 2 Lite 这类小而高效的模型入手，在有效处理专业任务的同时降低延迟。

Amazon Nova 2 Sonic 支持[异步工具调用](https://docs.aws.amazon.com/nova/latest/nova2-userguide/sonic-async-tools.html)，因此工具在后台运行时对话仍能自然继续。它会持续接收输入，可以并行运行多个工具，如果用户中途改变请求也能从容适配——在交付所有结果的同时，聚焦于仍然相关的内容。

## 模式 3：面向超低延迟的 session segmentation

还有第三种方法值得考虑。它不能整齐地归入 MCP 或 sub-agent 模式，而是专门为延迟压倒一切的语音场景打造。

你不必把外部工具或 sub-agent 委托出去，而是**把对话切分为若干逻辑阶段**，每个阶段都有自己的 Nova Sonic 会话、system prompt 和工具集。当对话从一个阶段过渡到下一个阶段（例如从身份验证转到账户查询）时，你在同一个 WebSocket 连接内关闭当前会话，用不同的 prompt 和工具开启一个新会话。每个 sub-voice-agent 都可以使用自己的 MCP gateway、工具，甚至 sub-agent——不同之处在于它以聚焦的 prompt 和极简的工具面运行，从而减少推理开销和延迟。

![展示 session segmentation 模式的架构图：每个对话阶段使用独立的 Nova Sonic 会话](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/05/08/ML-20826-4.png)

设想一个包含三个对话阶段的银行语音助手：身份验证、账户管理和按揭咨询。你不必加载一个塞满所有工具的大 system prompt，而是把每个阶段作为聚焦的 Nova Sonic 会话来运行：

```
# Phase 1: Authentication
auth_session = BidiNovaSonicModel(
    model_id="amazon.nova-2-sonic-v1:0",
    mcp_gateway_arn=["arn:...gateway/auth-tools"],  # Only auth tools
)
auth_agent = BidiAgent(
    model=auth_session,
    tools=[],
    system_prompt="""You are an authentication assistant. 
    Collect the user's account ID and date of birth. 
    Call verify_identity to authenticate. 
    Once verified, say 'You're all set' and stop.""",
)
# Run until authentication completes
await auth_agent.run(inputs=[ws_input], outputs=[ws_output])

# Phase 2: Account management (new session, new prompt, new tools)
banking_session = BidiNovaSonicModel(
    model_id="amazon.nova-2-sonic-v1:0",
    mcp_gateway_arn=["arn:...gateway/banking-tools"],  # Only banking tools
)
banking_agent = BidiAgent(
    model=banking_session,
    tools=[],
    system_prompt="""You are a banking assistant. The user is already authenticated.
    Help with balance inquiries, transactions, and transfers.
    Keep responses to one or two sentences.""",
)
await banking_agent.run(inputs=[ws_input], outputs=[ws_output])
```

每个阶段都获得一个干净的 Nova Sonic 会话，具备：

- 聚焦的 system prompt：更短、更具体，模型混淆的空间更小。
- 仅保留相关工具：通过 MCP gateway、本地工具，或两者兼用。当模型只需要 3 个工具时，就不会把推理周期浪费在 15 个工具之间做选择。
- 可选地拥有自己的 sub-agent：需要更深度推理的阶段可以在内部采用模式 2，而较简单的阶段只保留工具。
- 可以把上一个会话的上下文作为聊天历史传入新会话，让整个对话保持连续性。

### 与工具、sub-agent 和 session segmentation 模式的对比

| **因素** | **工具** | **Sub-Agent（Agent-as-Tool）** | **Session Segmentation** |
| --- | --- | --- | --- |
| 延迟 | 低 | 较高（sub-agent 推理） | 最低（会话切换时会产生延迟） |
| 每轮工具集 | 已加载的工具 | Sub-agent 的工具 | 仅阶段相关工具 |
| System prompt | 一个大的 prompt | 编排器 + sub-agent 的 prompt | 小型、阶段专属的 prompt |
| 推理深度 | 仅语音模型 | 语音模型 + sub-agent | 仅语音模型（按阶段） |
| 现有 agent 的复用 | 高（相同的 MCP 工具） | 最高（相同的 sub-agent） | 中（按阶段组合工具/sub-agent） |
| 对话连续性 | 无缝 | 无缝 | 需要阶段间的交接逻辑 |

## 语音 agent 的延迟最佳实践

构建语音 agent 而非文本 agent 时，延迟是关键考量。以下是一些实用技巧，可让响应时间保持快速、灵敏：

**sub-agent 从小模型起步。** 你的语音编排器用 Nova Sonic 处理对话，但 sub-agent 并不需要大模型。先从 Amazon Nova 2 Lite 或 Nova 2 Micro 开始。它们速度快、成本优化，能够很好地处理大多数专业任务。如果质量要求，你随时可以把某个 sub-agent 升级为更大的模型，但默认应从小型模型开始。

**设计带缓存的有状态 sub-agent。** 无状态 sub-agent 每次调用都访问数据库或 API，每次都会增加延迟。更好的做法是让 sub-agent 在一个会话内缓存来自数据源（API、AWS Lambda 函数、数据库）的结果。如果银行 sub-agent 已经获取过一次账户详情，就应该把数据保存在内存中，后续问题（余额、交易、汇总）直接从缓存读取，而不是反复调用后端。

**身份验证后预取数据。** 这对呼叫中心场景尤其有价值。客户完成身份验证后，你已经知道他们是谁。不要等他们开口才去拉取数据。应立刻在后台获取账户余额、近期交易、待处理提醒和按揭状态。当客户问“我的余额是多少？”时，答案已经在内存中了。

**并行执行独立的工具调用。** 如果用户说“给我看一下我所有账户的概览”，不要依次调用 `get_checking_balance`、`get_savings_balance`、`get_credit_card_balance`。应采用并发执行，让三个调用同时进行。Strands 原生支持这一点：agent 的工具执行器默认就会并行运行独立的调用。

**用填充语掩盖工具延迟。** 当工具调用或 sub-agent 分派不可避免时，可以指示语音模型在等待时说一句简短的填充语：“让我帮你查一下……”或“稍等，我查一查……”。这样对话就不会陷入沉默，而是一直有回应。

**减少每个会话的工具数量。** 可用工具越多，工具选择就越慢。如果你的 agent 有 15 个工具，但典型对话只用到 3 到 4 个，可以考虑 session segmentation 模式，按阶段只加载相关工具。

## 结论

把文本聊天机器人迁移为语音助手并不是简单地套一层外壳。交互模型根本不同——从响应设计、延迟预算到轮次转换行为都是如此。但有了结构良好的多 agent 架构和 Amazon Bedrock AgentCore，业务逻辑层可以保持不变。

你已经构建好的 sub-agent 是最大的资产。好好复用它们。
