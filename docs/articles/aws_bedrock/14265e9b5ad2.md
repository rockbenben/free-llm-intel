# Aetion 如何利用生成式 AI 和 Amazon Bedrock 将科学意图转化为结果

*本文与来自 Aetion 的 Javier Beltrán、Ornela Xhelili 和 Prasidh Chhabri 共同撰写。 *

对于医疗健康领域的决策者来说，全面理解患者历程和随时间变化的健康结果至关重要。科学家、流行病学家和生物统计学家会实施大量查询，从真实世界数据中提取复杂的、具有临床意义的患者变量。这些变量往往涉及复杂的事件序列、发生与未发生的组合，以及详尽的计算或分类，以准确反映患者经历和病史的多样性。把这些变量表达为自然语言查询，让用户得以表达科学意图，并探索患者时间线的全部复杂性。

[Aetion](https://aetion.com/) 是面向生物制药企业、支付方和监管机构的领先决策级真实世界证据软件提供商。该公司为医疗健康和生命科学客户提供全面的解决方案，快速、透明地把真实世界数据转化为真实世界证据。

Aetion Evidence Platform（AEP）的核心是 Measure——用于灵活捕获复杂患者变量的逻辑构件，使科学家能够定制分析，以应对其研究问题带来的细微差别和挑战。AEP 用户可以使用 Measure 构建患者队列，并分析其结果和特征。

用户提出科学问题，目的是把科学意图（例如“我想找出被诊断为糖尿病、随后开具过二甲双胍的患者”）转换为能在真实世界数据中提取这些变量的算法。为便于完成这种转换，Aetion 开发了 Measures Assistant，把用户以自然语言表达的科学意图转化为 Measure。

在本文中，我们回顾 Aetion 如何使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 来简化分析流程，产出决策级真实世界证据，并让不具备数据科学专业背景的用户也能与复杂的真实世界数据集交互。

Amazon Bedrock 是一项完全托管的服务，通过统一 API 提供来自领先 AI 初创公司和 Amazon 的高性能[基础模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)（FM）。它提供多种多样的 FM，让你可以选择最适合自己特定用例的模型。

## Aetion 的技术

Aetion 是一家医疗健康软件与服务公司，运用因果推断科学，生成关于药物和临床干预的安全性、有效性和价值的真实世界证据。Aetion 已与大多数前 20 大生物制药企业、领先支付方和监管机构建立合作。

Aetion 为美国、加拿大、欧洲和日本的生命科学企业、监管机构（包括 FDA 和 EMA）、支付方以及卫生技术评估（HTA）客户带来深厚的科学专业知识和技术，其分析能够实现以下目标：

- 通过识别目标人群、创建外部对照臂，以及对受控环境中代表性不足的场景和人群进行情境化，来优化临床试验
- 通过标签变更、定价、报销覆盖和处方集决策来扩大行业准入
- 针对药物、疗法和诊断开展安全性与有效性研究

Aetion 的应用（包括 Discover 和 Substantiate）由 AEP 驱动。AEP 是一个核心的纵向分析引擎，能够对数亿条患者历程应用严格的因果推断和统计方法。

AetionAI 是 Aetion 的一组生成式 AI 能力，嵌入在 AEP 和各个应用中。Measures Assistant 是 Substantiate 中的一项 AetionAI 功能。

## 方案概览

患者数据集被摄取到 AEP 中，并转换为纵向（时间线）格式。AEP 引用这些数据来生成队列并运行分析。Measure 是决定队列进入条件、纳入或排除标准以及研究特征的变量。

下图展示了方案架构。

![架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/21/ML-17579-arch.png)

Measures Assistant 是部署在 [Kubernetes on AWS](https://aws.amazon.com/kubernetes/) 环境中的微服务，通过 REST API 访问。传输到该服务的数据使用 Transport Layer Security 1.2（TLS）加密。当用户通过助手 UI 提问时，Substantiate 会发起一个请求，其中包含该问题以及此前的消息历史（如有）。Measures Assistant 把问题纳入 prompt 模板，并调用 Amazon Bedrock API 来调用 [Anthropic 的 Claude 3 Haiku](https://www.anthropic.com/news/claude-3-haiku)。用户提供的 prompt 和发送到 Amazon Bedrock API 的请求均使用 TLS 1.2 加密。

Aetion 选择使用 Amazon Bedrock 来处理大语言模型（LLM），是因为它提供来自多个提供商的丰富模型选择、安全态势、可扩展性和易用性。人们发现 Anthropic 的 Claude 3 Haiku LLM 在运行时和成本方面都优于其他可选方案。

Measures Assistant 维护着一个关于 AEP Measure 的本地知识库，内容来自 Aetion 的科学专家，并把这些信息作为 guardrail 纳入响应。这些 guardrail 确保服务向用户返回有效的指引，并弥补核心模型可能出现的逻辑推理错误。

Measures Assistant 的 prompt 模板包含以下信息：

- 对 LLM 所执行任务的总体定义。
- AEP 文档的摘录，描述所涵盖的每种 Measure 类型、其输入和输出类型以及使用方法。
- 一种 in-context learning 技术，在 prompt 中包含语义相关的已解答问题及答案。
- 用于约束 LLM 以特定方式表现的规则。例如，如何应对无关问题、保障敏感数据安全，或限制其在生成无效 AEP 设置时的“创造力”。

为简化流程，Measures Assistant 使用由两部分组成的模板：

- **Static**——与用户问题配合使用的固定指令。这些指令涵盖了 Measures Assistant 的大量明确定义的指引。
- **Dynamic**——根据用户问题的语义接近度，从本地知识库中动态选取问题和答案。这些示例把此前类似问答纳入 prompt，从而提升生成答案的质量。这种技术为 Retrieval Augmented Generation（RAG）模式建模了一个小规模、经过优化、进程内的知识库。

Mixedbread 的 [mxbai-embed-large-v1](https://www.mixedbread.ai/blog/mxbai-embed-large-v1) Sentence Transformer 经过微调，为一个问答本地知识库和用户问题生成句向量嵌入（sentence embedding）。句子与问题的相似度通过嵌入向量之间的余弦相似度来计算。

问答池的生成与维护采用人工参与（human in the loop）。领域专家持续测试 Measures Assistant，并利用问答对不断对其加以改进，以优化用户体验。

## 成果

我们实现的 AetionAI 能力，让用户能够用自然语言查询和句子描述科学意图，并转化为在真实世界数据中提取这些变量的算法。现在，用户只需几分钟就能把自然语言表达的问题变成 Measure，而过去需要数天，并且无需支持人员和专业培训。

## 结论

在本文中，我们介绍了 Aetion 如何使用 AWS 服务，简化用户从定义科学意图到运行研究并获取结果的路径。Measures Assistant 使科学家能够实施复杂研究并迭代研究设计，通过对简短自然语言查询的响应即时获得指引。

Aetion 正在持续优化 Measures Assistant 可用的知识库，并在整个产品套件中扩展创新的生成式 AI 能力，以改善用户体验，并最终加快把真实世界数据转化为真实世界证据的过程。
