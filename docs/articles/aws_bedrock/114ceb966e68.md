# Boomi Scribe 如何使用 AWS 简化文档工作

Boomi Scribe 缓解了文档工作这一企业开发团队最长期存在的技术债来源之一。企业开发人员常常难以创建和维护文档，尤其是当工作流（自动化业务流程）涉及与多个企业应用和数据源的集成时。Boomi 认识到了这一挑战，构建了 *Boomi Scribe*——一个运行在 AWS 上的 AI 驱动 agent，可自动化并简化整个文档流程。Boomi Scribe 会在开发人员工作的同时，自动为整个集成流程生成详细的文档。

Boomi Scribe 通过多步骤方法生成准确、详细且易用的文档，由 AWS 人工智能和机器学习（AI/ML）服务提供支持，包括 [Amazon Bedrock](https://aws.amazon.com/bedrock/?trk=ee99e8dd-e2f5-475d-bf70-086a096c69e4&sc_channel=ps&ef_id=CjwKCAjw1N7NBhAoEiwAcPchp1AaU8Z41HWSXXOxOz_vUPgXkOxv2vFG8jE4Pib1Dc-FGOeC3ESFYhoCPQcQAvD_BwE:G:s&s_kwcid=AL!4422!3!798517281048!e!!g!!amazon%20bedrock!23606216570!196197897280&gad_campaignid=23606216570&gclid=CjwKCAjw1N7NBhAoEiwAcPchp1AaU8Z41HWSXXOxOz_vUPgXkOxv2vFG8jE4Pib1Dc-FGOeC3ESFYhoCPQcQAvD_BwE) 和 [Claude models](https://aws.amazon.com/bedrock/anthropic/)。Boomi Scribe 不止于自动文档。它提供具体的洞察和版本比较，开发人员可将其用于规划和更广泛的沟通。完整的文档还有助于避免业务和合规需求的审计出现缺口。

在本文中，你将了解 Boomi Scribe 如何自动化集成流程文档、比较组件版本以呈现有意义的变更，并提升开发人员生产力。这一切都由为 AWS 云端构建的可扩展架构所支撑。

### 为工作流编写文档

Boomi 集成流程可以表示为有向无环图（DAGs），每个节点对应工作流中的一个特定步骤。这些工作流决定了数据如何在源系统和目标系统之间检索、处理、路由和交付。如果没有准确的文档，这些工作流对于非构建者来说可能无法阅读。这会给调试、交接和合规带来重大问题。

### 手工文档陷阱

为这些工作流编写文档是一项耗时的人工任务，导致不一致和低效。但为了可维护性和让利益相关者放心，必须记录每个步骤的关键逻辑和技术细节。版本管理以及比较流程版本之间的变更同样繁琐且容易出错。遗漏的更新、不完整的功能描述或不准确之处会造成误解，可能导致返工和时间损失。为了能够高效处理大量流程并保持准确性，自动化势在必行。

### Boomi Scribe 的方案

Boomi Scribe 自动化整个文档流程。Boomi 将集成流程存储为 XML 文件，其中包含有关流程的元数据，包括每个步骤如何连接以及其他相关信息。Boomi Scribe agent 首先解析这些复杂的集成流程 XML 表示，以提取相关特征。随后将这些特征转换为有向无环图（DAG）的 dot 表示格式，作为模型可消费的结构化输入。然后 agent 将该输入传递给由 Amazon Bedrock 和 Anthropic 的 Claude Haiku 4.5 驱动的 AI 模型，生成文档。最后，agent 比较 DAG 的各个版本，突出显示组件的差异和变更。

通过解析和提取每个集成步骤及其特征的数据，并在每次修订时将其组织成 DAG，准确而完整的数据被传递给模型，以创建或更新现有文档。开发人员不再需要为流程的每个步骤手工创建或分析文档，即可准确反映他们的新增和变更。

### 方案概览与架构

Boomi Scribe 的架构必须可靠，并且必须能够扩展到超过 3.3 万家 Boomi 客户的开发人员使用。Boomi 使用 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/)中的机器学习（ML）服务来构建和维护用于用户意图分类的模型。Boomi 在 Amazon Bedrock 中使用基础大语言模型（LLM）（包括 Claude Haiku 4.5）来生成自然语言文档。Haiku 是一个 few-shot 学习模型，Boomi 用它处理 DAG 并生成详细的描述。Boomi 将 DAG 文件、生成的文档和元数据存储在 [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/s3/)中。[Amazon DynamoDB](https://aws.amazon.com/dynamodb)作为内部后端数据存储，支撑系统功能并维持服务运行。最后，Boomi 使用 [AWS Lambda](https://aws.amazon.com/lambda/)编排整个流水线，从 DAG 解析到文档生成与比较。

### Boomi Scribe 的工作流

agent 解析 DAG 以捕获集成流程的细节。随后生成全面的文档，包括突出显示与前一版本比较得出的变更和洞察。最后，它将结果存储在 Amazon S3 中。

#### DAG 解析

集成流程 DAG 被上传到 Amazon S3，一个 AWS Lambda 函数触发对节点和边的解析，以表示集成步骤。以下示例 DAG 展示了从更复杂的集成流程 XML 表示和 dot 表示格式中提取的相关特征。这些特征和格式与 AI 模型理解工作流和集成细节、进而生成文档所需的输入特征保持一致。

```
digraph G {
    # Process-level attributes
    version="2";
    created_date="2023-09-14T02:15:26Z";
    modified_date="2024-10-28T23:30:06Z";
    process_name="Send Exception Mail";
    folder_full_path="/path/to/folder";
    number_of_connected_shapes="8";
    number_of_subprocess_components="0";
    sub_process_component_names="";
    number_of_map_components="0";
    map_component_names_info="";
    # Node definitions
    start[shapenumber="shape1", shapetype="start", shapename="Start", label="Main_NoData"];
    documentproperties[shapenumber="documentproperties", shapetype="documentproperties", shapename="Document Properties", label="Document Properties", name="NA"];
    message[shapenumber="message", shapetype="message", shapename="Message", label="Message"];
    dataprocess[shapenumber="dataprocess", shapetype="dataprocess", shapename="Data Process", label="Data Process"];
    catcherrors[shapenumber="catcherrors", shapetype="catcherrors", shapename="Try/Catch", label="Try/Catch", error="exception", default="connectoraction"];
    exception[shapenumber="exception", shapetype="exception", shapename="Exception", label="Exception"];
    connectoraction[shapenumber="connectoraction", shapetype="connectoraction", shapename="Connector", label="mail", actionType="GET", connectorname="Mail", connectorType="mail", objectName="NA", operationName="NA", operationType="NA", requestProfileName="NA", responseProfileName="NA"];
    stop[shapenumber="stop", shapetype="stop", shapename="Stop", label="Stop"];
    # DAG
    start -> documentproperties documentproperties -> message message -> dataprocess dataprocess -> catcherrors catcherrors -> exception catcherrors -> connectoraction connectoraction -> stop;
}
```

#### 文档生成

agent 通过 Amazon Bedrock 将解析后的 DAG 传递给 Claude Haiku 4.5，模型生成一份摘要，其中包含面向利益相关者的工作流高层概览以及流程图。随后是一节流程元数据，包括名称、版本、日期、路径以及步骤和组件的数量。再下一节提供流程的业务背景。最后生成流程步骤与功能一节，对工作流中的每个步骤逐一描述，提供关于流程的简明细节，以及针对 Boomi 集成流程量身定制的上下文相关描述。

### 收益

已部署的流程平均有 42 个记录版本，中位数为 16。这有力地表明团队可以生成多个文档版本。版本控制提供了在需要时参考先前版本的灵活性。Boomi Scribe 确保文档在整个流程生命周期中保持一致、准确且及时更新，无需人工投入（也不会出现人工错误），并能扩展到每天为每位客户处理数百个流程而不出现性能瓶颈。多项案例研究表明，Boomi Scribe 带来了显著的时间节省，将文档工作所花时间减少了最多 85%。

### 结论

组织希望通过减少不必要的苦差事来降低成本、提高生产力。维护软件文档，尤其是漫长而复杂的工作流的文档，一直是一个长期存在、问题重重的负担和技术债来源。Boomi Scribe 使用来自 AWS 的 AI/ML 工具，为一个经过验证、可扩展且可靠的方案，实现了复杂工作流的文档和版本管理自动化。
