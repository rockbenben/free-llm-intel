# Amazon Bedrock AgentCore Identity 中的私有证书颁发机构支持

许多构建应用的团队会把身份提供方（IdP）——例如 Keycloak 或 PingFederate——自托管在私有网络内。这些 IdP 通常会出示由私有证书颁发机构（CA）签发的 TLS 服务器证书。借助 [AgentCore Identity](https://aws.amazon.com/bedrock/agentcore/)（Amazon Bedrock AgentCore 的一项能力）中的私有 CA 支持，你的 agent 现在可以在信任组织已有私有 CA 的同时连接到这些 IdP。

AgentCore Identity 现在为私有身份提供方提供私有 CA 证书支持。你把 PEM 编码的 CA 证书存储在 AWS Secrets Manager 或 Amazon Simple Storage Service（Amazon S3）中，并[从凭证提供方中引用它](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity-outbound-credential-provider.html)。CA 证书只包含公开证书，不包含其私钥。AgentCore Identity 用它来验证你的 IdP 的发现端点、JSON Web Key Set（JWKS）端点和 token 端点所出示的服务器证书。CA 证书必须是根 CA 证书或中间 CA 证书。

在本文中，我们将展示如何用 AWS Private Certificate Authority 为 IdP 签发证书。然后我们配置一个 [AgentCore Identity 凭证提供方](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity-outbound-credential-provider.html)，使其信任该证书，并在尽量减少停机的情况下轮换 CA。我们还会展示如何保护 CA 证书，使只有你的 IdP 团队能够修改它。尽管 AgentCore Identity 支持任何私有 CA，包括企业 CA、第三方 CA 和自签名根 CA，但本文的演练使用 AWS Private CA，并以 Keycloak 作为 IdP。

## 解决方案概览

设想一个 agent 需要调用由你的 Keycloak IdP 保护的内部 wiki API。该 agent 运行在 [AgentCore Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 上——这是 Amazon Bedrock AgentCore 的一项能力，用于托管你的 agent 代码。为了从 Keycloak 获取 OAuth 2.0 访问 token，该 agent 使用一个 AgentCore Identity 凭证提供方，其中保存着 IdP 连接详情和客户端凭证。

下图展示了这一设置。Keycloak 运行在你的虚拟私有云（VPC）中，位于一个内部 Application Load Balancer 之后。该负载均衡器出示由 AWS Private CA 签发的 [AWS Certificate Manager（ACM）](https://aws.amazon.com/certificate-manager/) 私有证书。AgentCore Identity 所信任的 CA 证书存储在 Secrets Manager 或 Amazon S3 中。

AgentCore Identity 通过 [Amazon VPC Lattice](https://aws.amazon.com/vpc/lattice/) 以私有方式访问 IdP，后者通过[资源网关](https://docs.aws.amazon.com/vpc-lattice/latest/ug/resource-gateway.html)连接到你的 VPC——资源网关是 VPC Lattice 流量进入你的 VPC 的入口点。私有 CA 支持需要 VPC Lattice。如果你选择托管选项，AgentCore Identity 会为你创建并管理 VPC Lattice 资源。

![AgentCore Identity 通过 VPC Lattice 访问 Keycloak IdP，并依据私有 CA 验证其服务器证书。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/18/ML-22407-1.png)

图 1：将 AgentCore Identity 连接到使用私有 CA 的自托管 IdP

流程如下：

- 你在 Secrets Manager 或 Amazon S3 中存储 CA 证书。
- 你创建一个凭证提供方，指向你的 IdP 和该 CA 证书。
- AgentCore Identity 读取该 CA 证书，并检查它是否为有效的 CA 证书。
- 你的 agent 向 AgentCore Identity 请求访问 token。
- AgentCore Identity 通过 VPC Lattice 连接到 IdP，并依据你的 CA 校验负载均衡器证书。
- IdP 签发 token，AgentCore Identity 将其返回给你的 agent。

使用机器对机器（machine-to-machine）、代为执行（on-behalf-of）和用户委托（user-delegated）流程的 agent 也可以在不修改代码的情况下使用私有 CA。

## 先决条件

要跟随本演练操作，你需要：

- 一个 [AWS 账户](https://aws.amazon.com/resources/create-account/)，可访问 [AgentCore 控制台](https://console.aws.amazon.com/bedrock-agentcore)，并位于 AgentCore Identity 支持私有 IdP 的[受支持 AWS 区域](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html)。
- 一个运行在你的 VPC 中、符合 OpenID Connect（OIDC）的自托管 IdP，并已为你的 agent 注册 OAuth 客户端。网络要求（包括子网、安全组以及为 IdP 主机名准备的私有托管区）在[连接到私有身份提供方](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity-private-idp.html#private-idp-prerequisites)中有描述。
- 最新版本的 [AWS Command Line Interface（AWS CLI）](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) 和 [OpenSSL](https://openssl-library.org/)。
- 创建凭证提供方的权限，以及对 CA 证书的读取权限。AgentCore Identity 使用调用 `CreateOauth2CredentialProvider` 的主体的凭证来读取证书，因此该主体需要对相应 secret 拥有 `secretsmanager:GetSecretValue`，或对相应对象拥有 `s3:GetObject`。如果 secret 或对象使用客户管理的 AWS Key Management Service（AWS KMS）密钥加密，该主体还需要对该密钥拥有 `kms:Decrypt`。

## 注意事项

规划部署时请注意以下事项：

- **仅限私有 IdP**：凭证提供方或授权方必须带有 `privateEndpoint` 才能使用私有 CA。否则请求会失败，并返回消息 `The private certificate authority feature can only be used with private IdP`。
- **PEM 格式的 CA 证书**：文件必须为 PEM 编码，且不超过 16 KB。它只能包含处于有效期内的根 CA 或中间 CA 证书。
- **每个提供方只有一个证书来源**：每个凭证提供方引用一个 secret 或一个 S3 对象。要信任多个 CA，请把这些证书放进同一个 PEM 文件。
- **存储位置**：secret 或 S3 对象必须与凭证提供方位于同一个 AWS 区域。Secrets Manager 的 secret 还必须与凭证提供方位于同一个账户。当你提供 `bucketOwnerAccountId` 且桶策略授予访问权限时，S3 对象可以位于另一个账户。
- **区域**：私有 CA 支持依赖 VPC Lattice，在 AgentCore Identity 支持私有 IdP 的 AWS 区域中可用。

## 演练

本演练包含四个步骤。如果你的 IdP 已经出示企业 CA 签发的证书，请跳至第 2 步。

### 第 1 步：为你的 IdP 签发服务器证书

首先在 AWS Private CA 中创建一个根 CA。相关说明请参阅[创建私有 CA](https://docs.aws.amazon.com/privateca/latest/userguide/create-CA.html) 和[安装 CA 证书](https://docs.aws.amazon.com/privateca/latest/userguide/PCACertInstall.html)。请选择通用（general-purpose）模式，因为短有效期证书模式签发的证书仅在 7 天或更短时间内有效。创建 CA 时，请授权 ACM 续期证书，这样 ACM 就能在 IdP 的服务器证书过期之前完成续期。

接下来，请求服务器证书。AgentCore Identity 会检查证书是否与 IdP 主机名匹配，因此请把 IdP 发现文档中出现的每个主机名都作为主题备用名称（SAN）加入。在多数 Keycloak 部署中，发现端点、JWKS 端点和 token 端点共用一个主机名。例如，如果你的发现 URL 是 `https://keycloak.example.local/realms/agents/.well-known/openid-configuration`，请把 `keycloak.example.local` 添加为 SAN。

为 IdP 请求私有证书（控制台）

- 打开 [ACM 控制台](https://console.aws.amazon.com/acm/home) 并选择 Request。
- 选择 Request a private certificate，然后选择 Next。
- 在 Certificate authority 中，选择你创建的 CA。
- 在 Fully qualified domain name 中，输入 IdP 主机名，例如 `keycloak.example.local`。
- 选择 Request。
- 将该证书附加到 IdP 前面的内部负载均衡器的 HTTPS 侦听器上。相关说明请参阅[更新 HTTPS 侦听器](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/listener-update-certificates.html)。

### 第 2 步：存储 CA 证书

AgentCore Identity 需要信任该 CA 证书才能验证 IdP 的服务器证书。由于它信任的是 CA 而不是服务器证书本身，你无需在服务器证书每次续期时更新凭证提供方。

从 AWS Private CA 以 PEM 格式导出 CA 证书：

```
aws acm-pca get-certificate-authority-certificate \
  --certificate-authority-arn arn:aws:acm-pca:us-east-1:111122223333:certificate-authority/11223344-1234-1122-2233-112233445566 \
  --query Certificate \
  --output text > idp-root-ca.pem
```

上传文件之前，请[对照要求](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity-private-idp.html#identity-private-certificate-requirements)检查它。文件必须为 PEM 编码并满足大小要求，且只能包含处于有效期内的 CA 证书。以下命令会显示 CA 标志、到期日期和文件大小。最后一条命令用于确认 IdP 的证书链可以追溯到该 CA。请从能够访问 IdP 的主机上运行它。当证书链有效时，它会返回 Verify return code: 0 (ok)。

```
openssl x509 -in idp-root-ca.pem -noout -subject -enddate
openssl x509 -in idp-root-ca.pem -noout -text | grep "CA:TRUE"
wc -c < idp-root-ca.pem
openssl s_client -connect keycloak.example.local:443 -servername keycloak.example.local \
  -CAfile idp-root-ca.pem </dev/null 2>/dev/null | grep "Verify return code"
```

输出大致如下：

```
subject=CN=Example Corp Root CA
notAfter=Nov 10 00:00:00 2035 GMT
                CA:TRUE
    1489
Verify return code: 0 (ok)
```

把该文件存储在 Secrets Manager 或 Amazon S3 中。Secrets Manager 的 secret 必须是与凭证提供方位于同一账户的字符串 secret。S3 对象可以位于另一个账户，这适合把 IdP 运行在中央账户中的组织。

```
# Option A: AWS Secrets Manager
aws secretsmanager create-secret \
  --name agentcore/keycloak-root-ca \
  --secret-string file://idp-root-ca.pem
# Option B: Amazon S3
aws s3 cp idp-root-ca.pem s3://amzn-s3-demo-bucket/trust-anchors/keycloak-root-ca.pem
```

只把对 secret 或对象的写权限授予运维你的 IdP 的团队。示例策略请参阅本文后面的「保护 CA 证书」一节。

### 第 3 步：创建凭证提供方

你可以在 AgentCore 控制台或使用 AWS CLI 创建凭证提供方。只有在把 OAuth 客户端连接到 VPC 之后，控制台上才会出现私有 CA 设置，因为私有 CA 支持仅适用于私有 IdP。

创建信任你的私有 CA 的凭证提供方（控制台）

- [打开 AgentCore 控制台](https://console.aws.amazon.com/bedrock-agentcore)，在导航窗格的 Connections 下选择 **Outbound Auth**。然后选择 **Add OAuth client**。
- 在 **Provider** 中选择 **Customized provider**。在 **Configuration type** 中选择 **Discovery URL**，并输入你的 IdP 的发现 URL，例如 `https://keycloak.example.local/realms/agents/.well-known/openid-configuration`。然后输入客户端 ID 和客户端 secret。
- 展开 Additional configurations。在 **VPC security** 下选择 **Managed**，并选择能够访问该 IdP 的 VPC、子网和安全组。如果你自行管理 VPC Lattice 资源，请选择 **Self-managed**，并改为选择资源配置。
- 在 **Root certificate authority** 下选择 **Add root certificate**。
- 在 **Add root certificate** 面板中，为 **Certificate source** 选择 **AWS Secrets Manager**，并选择你在第 2 步创建的 secret。要使用 Amazon S3，请选择 **Amazon S3** 并输入 S3 URI。对于位于另一个账户的对象，还需输入 Bucket owner account ID。
- 选择 **Apply**。
- 选择 **Add OAuth client**。

Root certificate authority 字段接受根 CA 证书或中间 CA 证书。

![AgentCore 控制台的 Add root certificate 面板，已选择 AWS Secrets Manager 作为证书来源。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/11/18/ML-22407-2.png)

图 2：从 AWS Secrets Manager 添加根证书

要用 AWS CLI 创建同样的凭证提供方，请在自定义 OAuth 2.0 提供方配置中添加 certificateConfigurations：

```
aws bedrock-agentcore-control create-oauth2-credential-provider \
  --name keycloak-private-ca \
  --credential-provider-vendor CustomOauth2 \
  --oauth2-provider-config-input '{
    "customOauth2ProviderConfig": {
      "oauthDiscovery": {
        "discoveryUrl": "https://keycloak.example.local/realms/agents/.well-known/openid-configuration"
      },
      "clientId": "agentcore-client",
      "clientSecret": "<client-secret>",
      "privateEndpoint": {
        "managedVpcResource": {
          "vpcIdentifier": "vpc-0abc123def456",
          "subnetIds": ["subnet-0abc123", "subnet-0def456"],
          "securityGroupIds": ["sg-0abc123def456"],
          "endpointIpAddressType": "IPV4"
        }
      },
      "certificateConfigurations": [
        {
          "secretsManager": {
            "secretArn": "arn:aws:secretsmanager:us-east-1:111122223333:secret:agentcore/keycloak-root-ca-AbCdEf"
          }
        }
      ]
    }
  }'
```

若要改用 Amazon S3，请把 `certificateConfigurations` 条目替换为 `{"s3": {"uri": "s3://amzn-s3-demo-bucket/trust-anchors/keycloak-root-ca.pem", "bucketOwnerAccountId": "444455556666"}}`。如果省略 bucketOwnerAccountId，AgentCore Identity 会认为该桶位于你自己的账户中。为了让客户端 secret 不出现在 shell 历史记录中，你可以[引用存储在 Secrets Manager 中的客户端 secret](https://aws.amazon.com/blogs/machine-learning/reference-your-own-aws-secrets-manager-secrets-in-amazon-bedrock-agentcore-identity/)。

### 第 4 步：验证凭证提供方

AgentCore Identity 会在后台验证证书并建立私有连接，因此新建的凭证提供方会从 `CREATING` 状态开始。几分钟后检查状态：

```
aws bedrock-agentcore-control get-oauth2-credential-provider \
  --name keycloak-private-ca \
  --query '{status: status, failureReason: failureReason}'
```

在控制台上，凭证提供方的详情页会在 **Root certificates** 下显示所配置的证书。当状态为 READY 时，你的 agent 就可以向 IdP 请求 token。如果状态是 `CREATE_FAILED`，`failureReason` 字段会说明原因。例如，`Leaf certificates are not allowed, must provide CA certificates only` 表示你上传的是服务器证书而非 CA 证书。如果看到 `Unable to access S3 object` 或 `Secrets Manager can't find the specified secret`，请检查 URI 或 Amazon Resource Name（ARN）是否正确，并确认你的身份能够读取该对象或 secret。如果提供方为 `READY` 但 token 请求失败，请确认 IdP 的服务器证书由所配置的 CA 签发，且其 SAN 与 IdP 主机名匹配。

## 监控并轮换 CA 证书

在确认凭证提供方信任该私有 CA 之后，请监控 CA 证书的到期时间，并在到期前轮换它，以避免 token 请求失败。当你的 agent 通过使用私有 CA 的凭证提供方请求 token 时，AgentCore Identity 会把 `EarliestCertificateDaysToExpiry` 指标发布到 `AWS/Bedrock-AgentCore` 命名空间下的 Amazon CloudWatch。该指标报告 PEM 文件中最早到期的证书还剩多少天。它具有 `ProviderName`、`ProviderArn` 和 `TokenVault` 三个维度。创建告警时请指定全部三个维度。我们建议使用 [CloudWatch 告警](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/AlarmThatSendsEmail.html)，在数值降到零之前就提前通知你，因为 CA 证书过期后，发往 IdP 的 token 请求就会失效。

> 注意：AgentCore Identity 仅在你创建或更新凭证提供方时读取证书。如果你更改了 secret 或 S3 对象，之后请调用 UpdateOauth2CredentialProvider，以便 AgentCore Identity 读取新内容。请在更新请求中包含 certificateConfigurations。如果省略它，凭证提供方将不再信任你的私有 CA。

一个 PEM 文件可以包含多张 CA 证书，AgentCore Identity 会信任其中每一张。你可以借此在尽量减少停机的情况下轮换到新 CA：

- 把当前 CA 证书和新 CA 证书合并到一个文件中，例如使用 `cat current-ca.pem new-ca.pem > rotation.pem`。把该文件上传到你的 secret 或 S3 对象。
- 调用 `UpdateOauth2CredentialProvider` 并等待状态恢复为 `READY`。
- 用由新 CA 签发的证书替换 IdP 的服务器证书。
- token 请求成功后，上传一个只包含新 CA 证书的文件，并再次调用 `UpdateOauth2CredentialProvider`。

AgentCore Identity 不检查证书吊销列表（CRL），也不使用在线证书状态协议（OCSP）。这意味着，如果未授权方获得了某个 IdP 服务器证书的私钥，AgentCore Identity 仍会继续信任该证书。这种信任会持续到证书过期，或直到你停止信任签发它的 CA。要停止信任某个 CA，请把它从 PEM 文件中移除，并更新凭证提供方。

## 保护 CA 证书

CA 证书不包含私钥，按设计就是公开的，因为你要把它交给每一个必须信任你的 IdP 的客户端。你需要保护的是信任存储的数据完整性，也就是保存该证书的 secret 或 S3 对象。如果有人替换了证书，或向信任存储中加入了另一张 CA 证书，那么下一次更新就可能让一个能够重定向流量的未授权方冒充你的 IdP。

我们建议把权限范围限定在写操作上，而不是读操作上。只把写权限（例如 `s3:PutObject` 或 `secretsmanager:PutSecretValue`）授予运维 IdP 的团队或流水线。把读权限授予调用 `CreateOauth2CredentialProvider` 或 `UpdateOauth2CredentialProvider` 的主体。在这些操作期间，AgentCore Identity 会使用调用方的 IAM 权限读取 CA 证书。以下面向中央身份账户（444455556666）的桶策略，只允许工作负载账户（111122223333）中管理凭证提供方的角色读取 CA 证书。它还要求该角色属于 AWS Organizations 中你的组织，并拒绝除 IdP 管理员角色之外的主体进行写操作：

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCredentialProviderAdminRead",
      "Effect": "Allow",
      "Principal": { "AWS": "arn:aws:iam::111122223333:role/AgentCoreCredentialProviderAdmin" },
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::amzn-s3-demo-bucket/trust-anchors/*",
      "Condition": {
        "StringEquals": { "aws:PrincipalOrgID": "o-exampleorgid" }
      }
    },
    {
      "Sid": "DenyWritesExceptIdpAdmin",
      "Effect": "Deny",
      "Principal": "*",
      "Action": ["s3:PutObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::amzn-s3-demo-bucket/trust-anchors/*",
      "Condition": {
        "ArnNotLike": { "aws:PrincipalArn": "arn:aws:iam::444455556666:role/IdpAdmin" }
      }
    }
  ]
}
```

工作负载账户中的主体还需要在自己的 IAM 策略中拥有 `s3:GetObject`。对于必须位于同一账户的 Secrets Manager，请在 secret 上使用[基于资源的策略](https://docs.aws.amazon.com/secretsmanager/latest/userguide/auth-and-access_resource-policies.html)，把写操作限制为只有 IdP 管理员角色可执行。

由于 secret 位于同一账户，IAM 策略可以授予读权限，因此资源策略只需拒绝变更：

```
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DenyChangesExceptIdpAdmin",
      "Effect": "Deny",
      "Principal": "*",
      "Action": [
        "secretsmanager:PutSecretValue",
        "secretsmanager:UpdateSecret",
        "secretsmanager:UpdateSecretVersionStage",
        "secretsmanager:RotateSecret",
        "secretsmanager:DeleteSecret",
        "secretsmanager:RestoreSecret",
        "secretsmanager:PutResourcePolicy",
        "secretsmanager:DeleteResourcePolicy"
      ],
      "Resource": "*",
      "Condition": {
        "ArnNotLike": { "aws:PrincipalArn": "arn:aws:iam::111122223333:role/IdpAdmin" }
      }
    }
  ]
}
```

启用 [S3 版本控制](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html)以便恢复被覆盖的文件，并启用 [AWS CloudTrail 数据事件](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/logging-data-events-with-cloudtrail.html)以记录每一次变更。由于 CA 证书并非机密，SSE-S3 加密已经足够，这样可以避免客户管理密钥所需的跨账户 AWS KMS 权限。

让每个凭证提供方的信任范围保持狭窄。只上传签发你的 IdP 服务器证书的那个 CA，而不是组织的完整信任包。如果你的多个 IdP 使用不同的 CA，请把每张 CA 证书存储在各自的 secret 或 S3 对象中，使每个凭证提供方只信任它所需的 CA。

## 为入站授权使用私有 CA

你也可以为入站授权使用私有 CA。当 AgentCore Runtime 或 AgentCore Gateway（Amazon Bedrock AgentCore 的一项能力）验证由私有 IdP 签发的 JSON Web Token（JWT）时，它会从 JWKS 端点获取该 IdP 的发现文档及其签名密钥。AgentCore Gateway 会在你创建网关时验证发现 URL。如果 CA 证书缺失或与 IdP 的证书链不匹配，网关状态会变为 `FAILED`，原因显示为 `Failed to validate discovery url`。要为该连接信任私有 CA，请在 `customJWTAuthorizer` 配置中、紧邻现有 `privateEndpoint` 的位置添加 `certificateConfigurations`：

```
"customJWTAuthorizer": {
  "discoveryUrl": "https://keycloak.example.local/realms/agents/.well-known/openid-configuration",
  "allowedClients": ["agentcore-client"],
  "privateEndpoint": {
    "managedVpcResource": {
      "vpcIdentifier": "vpc-0abc123def456",
      "subnetIds": ["subnet-0abc123", "subnet-0def456"],
      "securityGroupIds": ["sg-0abc123def456"],
      "endpointIpAddressType": "IPV4"
    }
  },
  "certificateConfigurations": [
    { "s3": { "uri": "s3://amzn-s3-demo-bucket/trust-anchors/keycloak-root-ca.pem", "bucketOwnerAccountId": "444455556666" } }
  ]
}
```

## 清理

为避免持续产生费用，请删除你创建的资源：

- 在 AgentCore 控制台中删除凭证提供方，或运行 `aws bedrock-agentcore-control delete-oauth2-credential-provider --name keycloak-private-ca`。
- 删除 Secrets Manager 中的 secret 或 Amazon S3 中的对象。
- 从负载均衡器侦听器中移除该证书，然后在 ACM 中删除它。
- 在 AWS Private CA 控制台中停用然后删除该私有 CA。在你删除之前，AWS Private CA 会对每个 CA 收取月度费用。详情请参阅 [AWS Private CA 定价](https://aws.amazon.com/private-ca/pricing/)。

## 结论

在本文中，我们展示了如何把 AgentCore Identity 连接到一个使用自有 CA 证书的自托管 IdP。你用 AWS Private CA 签发了服务器证书，把 CA 证书存储在 Secrets Manager 或 Amazon S3 中，并从凭证提供方引用它。你还了解了如何用合并的 PEM 文件轮换 CA，以及如何限制谁能够更改你的 agent 所信任的证书。

要了解更多信息，请参阅 [Amazon Bedrock AgentCore 开发人员指南中的「连接到私有身份提供方」](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity-private-idp.html)。使用 Keycloak 的示例请参阅 [GitHub 上的 Amazon Bedrock AgentCore 示例仓库](https://github.com/awslabs/agentcore-samples/tree/main/01-features/05-authenticate-and-authorize/01-inbound-auth/05-inbound-auth-keycloak)。如果你有疑问或反馈，请在本文下留言。
