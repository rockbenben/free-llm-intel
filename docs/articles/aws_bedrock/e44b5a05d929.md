# 在 Amazon Bedrock 中以 Amazon Neptune 与 Mem0 实现按公司划分的记忆

*本文由 TrendMicro 的 Shawn Tsai 共同撰写。*

提供相关且具备上下文感知的回复，对客户满意度至关重要。对企业级 AI chatbot 而言，不仅要理解当前查询，还要理解其背后的组织上下文，这才是关键。借助 [Amazon Neptune](https://aws.amazon.com/neptune/) 与 [Mem0](https://github.com/mem0ai/mem0) 实现的 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 按公司划分的记忆，为 AI agent 提供持久的、公司专属的上下文，使其能够在多次交互中学习、适应并智能应答。TrendMicro 是全球最大的杀毒软件公司之一，他们开发了 Trend’s Companion chatbot，让客户可以通过自然的对话式交互探索信息（[了解更多](https://www.trendmicro.com/zh_tw/business/ai/companion.html)）。

TrendMicro 希望增强其 AI chatbot 服务，为企业客户提供个性化、具备上下文感知的支持。该 chatbot 需要保留对话历史以保证连贯性，大规模引用公司专属知识，并确保记忆保持准确、安全且及时更新。难点在于把面向组织知识的长期记忆与面向进行中对话的短期记忆整合起来，同时支持全公司范围的知识共享。TrendMicro 与 AWS 团队（包括 AWS 的 Generative AI Innovation Center）合作，使用 Amazon Neptune、Amazon OpenSearch 和 Amazon Bedrock 解决了这一挑战，具体细节我们在本篇博客中展开。

## 方案概览

TrendMicro 通过组合多项 AWS 服务，在 Amazon Bedrock 中实现了按公司划分的记忆。Amazon Neptune 存储公司专属的知识图谱，表示组织中的关系、流程与数据，以支持精确且结构化的检索。Mem0 管理用于即时上下文的短期对话记忆，以及跨会话持久保存知识的长期记忆。Amazon Bedrock 编排 AI agent 工作流，与 Neptune 和 Mem0 集成，在推理过程中检索并应用上下文知识。该架构让 chatbot 能够回忆相关历史、检索结构化的公司知识，并以量身定制、上下文丰富的答案作答，从而显著改善用户体验。

### 记忆的创建与更新

该架构首先捕获用户消息，并通过 Amazon Bedrock 上的 Claude 模型抽取实体、关系与潜在记忆。随后用 Amazon Bedrock Titan Text Embed 对这些内容做 embedding，并在 Amazon OpenSearch Service 与 Amazon Neptune 中同时检索。相关实体与记忆被检索出来，先经模型更新，再重新 embedding 并索引回 OpenSearch 与 Neptune。这一闭环流程确保与实体相关的记忆可以持续刷新，Neptune 中的知识图谱也始终与对话中获得的洞察保持一致。

### 记忆检索

处理用户查询时，系统采用类似的 Bedrock Titan embedding 流水线，同时检索 OpenSearch Service 中的向量 embedding 与 Neptune 中的实体三元组。然后用 Amazon Bedrock Rerank 或 Cohere Rerank 模型对相关记忆重排序，以确保交付的是上下文最准确的信息。这种双重检索策略既提供了 OpenSearch 的语义灵活性，也提供了 Neptune 的结构化精确性，使 chatbot 能够给出高度相关且具备上下文感知的答案。

### 响应与记忆的映射，以及 human-in-the-loop 反馈

对每条 AI 回复，系统会把句子映射到所引用的具体记忆，并生成记忆评估报告。随后用户有机会批准或拒绝这些映射。被批准的记忆保留在知识库中，被拒绝的则从 OpenSearch Service 与 Neptune 中一并移除。这确保只有经过验证且可信的知识被保留下来。这种 human-in-the-loop 机制增强了信任，有助于持续提升记忆准确度，并让企业客户能够直接影响其 AI 知识的精炼过程。

## Amazon Neptune 实战

![Graph](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/13/Picture1-3-1024x507.png)

为了说明 Amazon Neptune 如何丰富 chatbot 的记忆，设想一位客户问道：“谁承认 Kublai 为统治者？”没有知识图谱时，AI 可能给出诸如“Kublai 是一位蒙古统治者，得到了不同群体的承认”这样的模糊回复。这类答案笼统而缺乏精确性。

当提出同样的问题，但改为查询 Neptune 实体图谱并将其放入大型语言模型（LLM）的上下文窗口时，模型可以依据（Ilkhans, recognized, Kublai）这样的结构化三元组进行推理。这样 chatbot 就能更准确地回复：“根据组织知识库，Kublai 被 Ilkhans 承认为统治者。”这个前后对比示例展示了 Neptune 中结构化的实体关系如何让模型给出既切合上下文又可验证的答案。

## 结论与下一步

正如 [AWS Trend Micro 案例研究](https://aws.amazon.com/solutions/case-studies/trendmicro/) 所述，Trend Micro 使用 AWS 来帮助交付更安全、更具扩展性且更智能的客户体验。在此基础之上，Trend Micro 结合 Amazon Bedrock、Amazon Neptune、Amazon OpenSearch Service 与 Mem0，打造出具备持久、组织专属记忆的 AI chatbot，可大规模提供智能且具备上下文感知的对话。通过将基于图谱的知识与生成式 AI 结合，Trend Micro 有望提升答案质量，交付更清晰、更准确的回复，同时为能够持续适应组织知识演进的 AI 系统奠定基础；这项工作仍在评估与调优中，以进一步增强终端用户体验。

展望未来，TrendMicro 正在探索更广的图谱覆盖范围、更多更新流水线以及多语言支持等后续增强。希望深入了解的读者，我们建议查看 [GitHub 示例实现](https://github.com/aws-samples/sample-company-wise-memory-in-bedrock)，其中包含我们实现的源代码，以及 [Amazon Neptune 文档](https://docs.aws.amazon.com/neptune/) 以获取更多技术细节与灵感。
