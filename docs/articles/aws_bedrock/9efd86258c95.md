# 在 Amazon Bedrock 中微调模型时应考虑的安全最佳实践

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 已成为数以万计希望构建自身生成式 AI 战略的客户的首选。它提供了一条直接、快速且安全的方式来开发先进的 [生成式 AI 应用](https://aws.amazon.com/generative-ai/) 与体验，以推动创新。

借助 Amazon Bedrock 的全面能力，你可以使用各类高性能基础模型（FM），从而能够针对具体需求挑选最合适的选项、用微调与检索增强生成（RAG）等技术以自有数据私密地定制模型，并创建运行复杂业务任务的托管 agent。

微调预训练语言模型让组织能够针对其特定用例定制和优化模型，带来更好的表现，以及贴合其独特数据与需求的更准确输出。借助微调能力，企业可以释放生成式 AI 的全部潜力，同时保持对模型行为的控制，并使之与自身目标与价值观对齐。

本文深入探讨组织在微调生成式 AI 模型时应考虑的关键安全最佳实践。

## Amazon Bedrock 中的安全

云安全是 AWS 的最高优先级。Amazon Bedrock 通过全面的方法来优先保障安全，以保护客户数据与 AI 工作负载。

Amazon Bedrock 以安全为核心构建，提供多项功能来保护你的数据与模型。其安全框架的主要方面包括：

- **访问控制** – 包括这些功能：使用 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）基于资源的策略进行细粒度访问控制，以管控对特定 Amazon Bedrock 资源的访问
- **数据加密** – Amazon Bedrock 提供如下加密：静态数据使用 [AWS Key Management Service](https://aws.amazon.com/kms/)（AWS KMS）加密；传输中的数据使用 TLS 1.2 或更高版本加密
- **网络安全** – Amazon Bedrock 提供多种安全选项，包括：支持 [AWS PrivateLink](https://aws.amazon.com/privatelink/)，在你的虚拟私有云（VPC）与 Amazon Bedrock 之间建立私有连接；VPC 端点用于在 AWS 环境内安全通信
- **合规** – Amazon Bedrock 符合多项行业标准与法规，包括 HIPAA、SOC 与 PCI DSS

## 解决方案概述

模型定制是向模型提供训练数据、以提升其在特定用例上表现的过程。Amazon Bedrock 目前提供以下定制方法：

- **持续预训练** – 通过用无标签的专有数据微调 FM 的参数，使其能力贴合特定领域，并随着更多相关数据的出现持续改进。
- **微调** – 向模型提供有标签的数据以在特定任务上训练，使其学会针对给定输入产出恰当的输出。该过程会调整模型参数，提升其在有标签训练数据集所代表任务上的表现。
- **蒸馏** – 把知识从更大、更聪明的模型（称为 teacher）迁移到更小、更快、更省成本的模型（称为 student）的过程。

Amazon Bedrock 中的模型定制涉及以下操作：

- 创建训练数据集与验证数据集。
- 为数据访问设置 IAM 权限。
- 配置 KMS 密钥与 VPC。
- 创建带超参数调优的微调或预训练作业。
- 通过指标与评估分析结果。
- 为定制模型购买预置吞吐量。
- 把定制模型用于推理等任务。

本文围绕微调来讲解这些步骤。不过，这些概念同样可以用于持续预训练。

下面的架构图说明了 Amazon Bedrock 模型微调的工作流。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-arch-diagram.png)

工作流步骤如下：

- 用户在自己的 AWS 账户内提交 Amazon Bedrock 微调作业，并使用 IAM 进行资源访问。
- 该微调作业在模型部署账户中发起一个训练作业。
- 为访问你 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）存储桶中的训练数据，该作业使用 [Amazon Security Token Service](https://docs.aws.amazon.com/STS/latest/APIReference/welcome.html)（AWS STS）来承担角色权限，以进行身份验证与授权。
- 对 S3 数据的网络访问通过 VPC 网络接口完成，使用提交作业时提供的 VPC 与子网信息。
- 该 VPC 配有用于访问 Amazon S3 与 AWS KMS 的私有端点，从而增强整体安全性。
- 微调过程会生成模型产物（model artifacts），它们存储在模型提供方的 AWS 账户中，并使用客户提供的 KMS 密钥加密。

该工作流在多个 AWS 账户之间提供安全的数据处理，同时通过客户托管的加密密钥维持客户对敏感信息的控制。

数据由客户掌控；模型提供方无法访问这些数据，也无法访问客户的推理数据或其定制训练数据集。因此，模型提供方拿不到数据来改进其基础模型。你的数据同样不会提供给 Amazon Bedrock 服务团队。

下面几节中，我们将走一遍使用 Amazon Bedrock 控制台在 Amazon Bedrock 中微调并部署 Meta Llama 3.1 8B Instruct 模型的步骤。

## 先决条件

开始之前，请确认你具备以下先决条件：

- 一个 [AWS 账户](https://signup.aws.amazon.com/billing/signup#/start/email)
- 一个具备以下操作权限的 IAM 联合角色：创建、编辑、查看和删除 VPC 网络与安全资源；创建、编辑、查看和删除 KMS 密钥；创建、编辑、查看和删除用于 [模型定制](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-iam-role.html) 的 IAM 角色与策略；创建、上传、查看和删除 S3 存储桶以访问训练与验证数据，并具备把输出数据写入 Amazon S3 的权限；列出将用于微调的基础模型上的 FM；为 Amazon Bedrock FM 创建定制训练作业；预置模型吞吐量；列出定制模型，并在微调后的模型上具备调用模型的权限
- [模型访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)，你可以通过 Amazon Bedrock 控制台申请

本文使用 `us-west-2` AWS 区域。关于为 IAM 角色分配权限的说明，请参阅 [Identity-based policy examples for Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/security_iam_id-based-policy-examples.html) 与 [How Amazon Bedrock works with IAM](https://docs.aws.amazon.com/bedrock/latest/userguide/security_iam_service-with-iam.html)。

## 准备数据

要微调像 Meta Llama 3.1 8B Instruct 这样的文本到文本模型，请创建一个包含多条 JSON 行的 JSONL 文件，作为训练数据集以及可选的验证数据集。

每条 JSON 行是一个样本，包含 prompt 与 completion 字段。格式如下：

```
{"prompt": "<prompt1>", "completion": "<expected generated text>"}
{"prompt": "<prompt2>", "completion": "<expected generated text>"}
```

以下是一条来自示例数据集的样例，用作在 Amazon Bedrock 中微调 Meta Llama 3.1 8B Instruct 的单行输入。在 JSONL 格式中，每条记录就是一行文本。

```
{"prompt": "consumer complaints and resolutions for financial products", "completion": "{'Date received': '01/01/24', 'Product': 'Credit card', 'Sub-product': 'Store credit card', 'Issue': 'Other features, terms, or problems', 'Sub-issue': 'Other problem', 'Consumer complaint narrative': None, 'Company public response': None, 'Company': 'Bread Financial Holdings, Inc.', 'State': 'MD', 'ZIP code': '21060', 'Tags': 'Servicemember', 'Consumer consent provided?': 'Consent not provided', 'Submitted via': 'Web', 'Date sent to company': '01/01/24', 'Company response to consumer': 'Closed with non-monetary relief', 'Timely response?': 'Yes', 'Consumer disputed?': None, 'Complaint ID': 8087806}"}
```

## 创建 KMS 对称密钥

把训练数据上传到 Amazon S3 时，你可以使用 AWS KMS 的服务器端加密。你可以在 [AWS Management Console](https://aws.amazon.com/console)、[AWS Command Line Interface](https://aws.amazon.com/cli)（AWS CLI）与 SDK，或 [AWS CloudFormation](https://aws.amazon.com/cloudformation/) 模板中创建 KMS 密钥。在控制台中创建 KMS 密钥请完成以下步骤：

- 在 AWS KMS 控制台的导航窗格中选择 **Customer managed keys**。
- 选择 **Create key**。
- 创建一个对称密钥。有关说明，见 [Create a KMS key](https://docs.aws.amazon.com/kms/latest/developerguide/create-keys.html#create-keys-console)。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-create-kms-key.png)

## 创建 S3 存储桶并配置加密

创建 S3 存储桶并配置加密请完成以下步骤：

- 在 Amazon S3 控制台的导航窗格中选择 **Buckets**。
- 选择 **Create bucket**。
- 在 **Bucket name** 中为存储桶输入唯一名称。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/24/ml-16438-create-s3-bucket-masked.png)

- 在 **Encryption type**¸ 中选择 **Server-side encryption with AWS Key Management Service keys**。
- 在 **AWS KMS key** 中选择 **Choose from your AWS KMS keys**，并选择你创建的密钥。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-bucket-enc.png)

- 用默认设置完成存储桶创建，或按需自定义。

## 创建 Amazon S3 VPC 网关端点

你还可以通过设置 Amazon S3 VPC 端点，并使用基于资源的 IAM 策略限制对存放模型定制数据的 S3 存储桶的访问，进一步加固 VPC。

我们来创建一个 Amazon S3 网关端点，并用自定义 IAM [基于资源的策略](https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_identity-vs-resource.html) 将其挂载到 VPC，以更严格地控制对 Amazon S3 文件的访问。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-s3-gtw-ep.png)

以下代码是一个示例资源策略。请使用你先前创建的存储桶名称。

```
{
	"Version": "2012-10-17",
	"Statement": [
		{
			"Sid": "RestrictAccessToTrainingBucket",
			"Effect": "Allow",
			"Principal": "*",
			"Action": [
				"s3:GetObject",
				"s3:PutObject",
				"s3:ListBucket"
			],
			"Resource": [
				"arn:aws:s3:::$your-bucket",
				"arn:aws:s3:::$your-bucket/*"
			]
		}
	]
}
```

## 为 AWS KMS VPC 接口端点创建安全组

安全组充当实例的虚拟防火墙，用于控制入站与出站流量。该 VPC 端点安全组只允许来自挂载到你 VPC 私有子网的安全组的流量，从而增加一层保护。创建该安全组请完成以下步骤：

- 在 Amazon VPC 控制台的导航窗格中选择 **Security groups**。
- 选择 **Create security group**。
- 在 **Security group name** 中输入名称（例如 `bedrock-kms-interface-sg`）。
- 在 **Description** 中输入描述。
- 在 **VPC** 中选择你的 VPC。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-kms-ep-sg.png)

- 添加一条允许来自 VPC CIDR 块的 HTTPS 流量的入站规则。

## 创建 AWS KMS VPC 接口端点

现在你可以创建一个接口 VPC 端点（PrivateLink），在 VPC 与 AWS KMS 之间建立私有连接。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-kms-ep.png)

安全组使用你上一步创建的那个。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-kms-ep-subnets.png)

挂载一个 VPC 端点策略，控制通过该 VPC 端点对资源的访问。以下代码是一个示例资源策略。请使用你先前创建的 KMS 密钥的 Amazon Resource Name（ARN）。

```
{
	"Statement": [
		{
			"Sid": "AllowDecryptAndView",
			"Principal": {
				"AWS": "*"
			},
			"Effect": "Allow",
			"Action": [
				"kms:Decrypt",
				"kms:DescribeKey",
				"kms:ListAliases",
				"kms:ListKeys"
			],
			"Resource": "$Your-KMS-KEY-ARN"
		}
	]
}
```

至此，你已成功创建私有通信所需的端点。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-ep-list.png)

## 为模型定制创建服务角色

我们来创建一个用于模型定制的服务角色，具备以下权限：

- 一个 [信任关系](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-iam-role.html#model-customization-iam-role-trust)，供 Amazon Bedrock 承担并执行模型定制作业
- 访问 Amazon S3 中训练与验证数据、以及把输出数据写入 Amazon S3 的 [权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-iam-role.html#model-customization-iam-role-s3)
- 若你用 KMS 密钥加密了以下任一资源，则需要解密该密钥的权限（见 [Encryption of model customization jobs and artifacts](https://docs.aws.amazon.com/bedrock/latest/userguide/encryption-custom-job.html)）
- 模型定制作业或由此产生的定制模型
- 模型定制作业的训练、验证或输出数据
- 访问 VPC 的 [权限](https://docs.aws.amazon.com/bedrock/latest/userguide/vpc-model-customization.html#vpc-data-access-role)

我们先创建所需的 IAM 策略：

- 在 IAM 控制台的导航窗格中选择 **Policies**。
- 选择 **Create policy**。
- 在 **Specify permissions**¸ 下，使用以下 JSON 授予对 S3 存储桶、VPC 与 KMS 密钥的访问权限。请填入你的账户、存储桶名称与 VPC 设置。

你可以把以下 IAM 权限策略作为 VPC 权限的模板：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "ec2:DescribeNetworkInterfaces",
                "ec2:DescribeVpcs",
                "ec2:DescribeDhcpOptions",
                "ec2:DescribeSubnets",
                "ec2:DescribeSecurityGroups"
            ],
            "Resource": "*"
        }, 
        {
            "Effect": "Allow",
            "Action": [
                "ec2:CreateNetworkInterface",
            ],
            "Resource":[
               "arn:aws:ec2:${{region}}:${{account-id}}:network-interface/*"
            ],
            "Condition": {
               "StringEquals": { 
                   "aws:RequestTag/BedrockManaged": ["true"]
                },
                "ArnEquals": {
                   "aws:RequestTag/BedrockModelCustomizationJobArn": ["arn:aws:bedrock:${{region}}:${{account-id}}:model-customization-job/*"]
               }
            }
        }, 
        {
            "Effect": "Allow",
            "Action": [
                "ec2:CreateNetworkInterface",
            ],
            "Resource":[
               "arn:aws:ec2:${{region}}:${{account-id}}:subnet/${{subnet-id}}",
               "arn:aws:ec2:${{region}}:${{account-id}}:subnet/${{subnet-id2}}",
               "arn:aws:ec2:${{region}}:${{account-id}}:security-group/security-group-id"
            ]
        }, 
        {
            "Effect": "Allow",
            "Action": [
                "ec2:CreateNetworkInterfacePermission",
                "ec2:DeleteNetworkInterface",
                "ec2:DeleteNetworkInterfacePermission",
            ],
            "Resource": "*",
            "Condition": {
               "ArnEquals": {
                   "ec2:Subnet": [
                       "arn:aws:ec2:${{region}}:${{account-id}}:subnet/${{subnet-id}}",
                       "arn:aws:ec2:${{region}}:${{account-id}}:subnet/${{subnet-id2}}"
                   ],
                   "ec2:ResourceTag/BedrockModelCustomizationJobArn": ["arn:aws:bedrock:${{region}}:${{account-id}}:model-customization-job/*"]
               },
               "StringEquals": { 
                   "ec2:ResourceTag/BedrockManaged": "true"
               }
            }
        }, 
        {
            "Effect": "Allow",
            "Action": [
                "ec2:CreateTags"
            ],
            "Resource": "arn:aws:ec2:${{region}}:${{account-id}}:network-interface/*",
            "Condition": {
                "StringEquals": {
                    "ec2:CreateAction": [
                        "CreateNetworkInterface"
                    ]    
                },
                "ForAllValues:StringEquals": {
                    "aws:TagKeys": [
                        "BedrockManaged",
                        "BedrockModelCustomizationJobArn"
                    ]
                }
            }
        }
    ]
}
```

你可以把以下 IAM 权限策略作为 Amazon S3 权限的模板：

```

        {

            "Resource": [
                "arn:aws:s3:::output-bucket",
                "arn:aws:s3:::output-bucket/*"

```

现在我们来创建 IAM 角色。

- 在 IAM 控制台的导航窗格中选择 **Roles**。
- 选择 **Create roles**。
- 用以下信任策略创建角色（请填入你的 AWS 账户 ID）：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": {
                "Service": "bedrock.amazonaws.com"
            },
            "Action": "sts:AssumeRole",
            "Condition": {
                "StringEquals": {
                    "aws:SourceAccount": "account-id"
                },
                "ArnEquals": {
                    "aws:SourceArn": "arn:aws:bedrock:us-west-2:account-id:model-customization-job/*"
                }
            }
        }
    ] 
}
```

- 挂载你自定义的 VPC 与 S3 存储桶访问策略。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-iam-policies.png)

- 为角色命名，然后选择 **Create role**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-iam-role.png)

## 用 IAM 角色更新 KMS 密钥策略

在你前几步创建的 KMS 密钥中，需要更新密钥策略以加入该 IAM 角色的 ARN。以下代码是一个示例密钥策略：

```
{
    "Version": "2012-10-17",
    "Id": "key-consolepolicy-3",
    "Statement": [
        {
            "Sid": "BedrockFineTuneJobPermissions",
            "Effect": "Allow",
            "Principal": {
                "AWS": "$IAM Role ARN"
            },
            "Action": [
                "kms:Decrypt",
                "kms:GenerateDataKey",
                "kms:Encrypt",
                "kms:DescribeKey",
                "kms:CreateGrant",
                "kms:RevokeGrant"
            ],
            "Resource": "$ARN of the KMS key"
        }
     ]
}
```

更多细节请参阅 [Encryption of model customization jobs and artifacts](https://docs.aws.amazon.com/bedrock/latest/userguide/encryption-custom-job.html)。

## 发起微调作业

设置微调作业请完成以下步骤：

- 在 Amazon Bedrock 控制台的导航窗格中选择 **Custom models **。
- 在 **Models** 区域中选择 **Customize model** 与 **Create fine-tuning job**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-create-ft-main-view.jpg)

- 在 **Model details** 下选择 **Select model**。
- 选择 **Llama 3.1 8B Instruct** 作为基础模型，然后选择 **Apply**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-select-model.png)

- 在 **Fine-tuned model name,** 中为你的定制模型输入名称。
- 选择 **Model encryption** 添加 KMS 密钥，并选择你先前创建的 KMS 密钥。
- 在 **Job name** 中为训练作业输入名称。
- 可选：展开 **Tags** 区域添加用于追踪的标签。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-create-ft-job-kms.png)

- 在 **VPC Settings** 下，选择你在前面步骤中创建的 VPC、子网与安全组。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-create-ft-job-vpc.png)

当你为作业指定 VPC 子网与安全组时，Amazon Bedrock 会在其中一个子网中创建与你的安全组关联的弹性网络接口（ENI）。ENI 使 Amazon Bedrock 作业能够连接到你 VPC 中的资源。

我们建议你在每个可用区中至少提供一个子网。

- 在 **Input data** 下，指定训练与验证数据集的 S3 位置。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/24/ml-16438-create-ft-job-input-masked.png)

- 在 **Hyperparameters,** 下，为你的微调作业设置 **Epochs**、**Batch size**、**Learning rate** 与 **Learning rate warm up steps ** 的值。

更多细节请参阅 [Custom model hyperparameters](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-models-hp.html)。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-job-parameters.png)

- 在 **Output data** 下，为** S3 location** 输入存放微调指标的存储桶的 S3 路径。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/24/ml-16438-ft-job-output-masked.png)
- 在 **Service access** 下，选择为 Amazon Bedrock 授权的方式。你可以选择 **Use an existing service role**，使用你先前创建的角色。
- 选择 **Create Fine-tuning job**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-ft-iam-role.png)

## 购买预置吞吐量

微调完成后（如下方截图所示），你就可以用这个定制模型做推理。不过在能使用定制模型之前，你需要为它购买预置吞吐量。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-ft-job-monitor3.png)

请完成以下步骤：

- 在 Amazon Bedrock 控制台的导航窗格中，于 **Foundation models** 下选择 **Custom models**。
- 在 **Models tab** 上选择你的模型，然后选择 **Purchase provisioned throughput**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-purchase-pt1.png)

- 在 **Provisioned throughput name** 中输入名称。
- 在 **Select model** 下，确认模型与你先前选择的定制模型一致。
- 在 **Commitment term & model units** 下配置你的承诺期与模型单元。更多见解请参阅 [Increase model invocation capacity with Provisioned Throughput in Amazon Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/prov-throughput.html)。本文中我们选择 **No commitment ** 并使用 1 个模型单元。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-purchase-pt2.png)

- 在 **Estimated purchase summary** 下查看预估费用，然后选择 **Purchase provisioned throughput**。

预置吞吐量上线后，你就可以用该模型做推理。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/23/ml-16438-purchase-pt3.png)
