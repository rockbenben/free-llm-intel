# 借助 Lexbe 与 Amazon Bedrock 提升法律文档审阅体验

*本文与 Lexbe 的 Karsten Weber 和 Rosary Wang 合著。*

法律专业人士经常需要在海量文档中筛出诉讼所需的关键证据。这一过程耗时、容易出错，而且成本高昂——尤其在截止期限逼近时。法律文档审阅软件的领先者 Lexbe 直面这些挑战，采用了 [Amazon Bedrock](https://aws.amazon.com/bedrock/)。通过集成 Amazon 提供的高级 AI 与机器学习服务，[Lexbe](https://lexbe.com/) 简化了其文档审阅流程，同时提升了效率与准确度。本文探讨 Lexbe 如何使用 Amazon Bedrock 及其他 AWS 服务克服业务挑战，为法律文档分析交付可扩展的高性能方案。

## 业务挑战及其重要性

法律专业人士日常要面对管理与分析海量案件文档的艰巨任务，文档数量可以从 100,000 份一直到超过一百万份。在这些大型数据集中快速识别相关信息，往往对构建有力的案件——或避免代价高昂的疏漏——至关重要。Lexbe 在其自定义应用 Lexbe Pilot 中使用 Amazon Bedrock 来应对这一挑战。

Lexbe Pilot 是集成在 Lexbe eDiscovery 平台中的 AI 驱动问答助手。它让法律团队可以借助生成式 AI，即时查询整个案件的全部文档并从中提取洞见——无需再做耗时的人工检索与分析。借助 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases)，用户可以查询整个数据集，并取回有依据、上下文相关的结果。这种做法远超传统关键词搜索，能帮助法律团队找出原本可能被埋没的关键文档或*确凿证据*。随着案件规模增长，过去只返回少量文档的关键词搜索，现在可能产生数百甚至数千条结果。Lexbe Pilot 把这些庞大的结果集提炼为简洁、有意义的回答——为法律团队提供做出明智决策所需的洞见。

若不解决这些挑战，就可能遗漏证据，进而导致不利结果。借助 Amazon Bedrock 及其相关服务，Lexbe 提供了一套可扩展的高性能方案，让法律专业人士能够高效、准确地穿行于不断扩张的电子发现领域。

## 方案概览：以 Amazon Bedrock 为基础

Lexbe 通过集成 Amazon Bedrock 改造了其文档审阅流程。Amazon Bedrock 是一套强大的 AI 与机器学习（ML）服务。凭借与 AWS 生态系统的深度集成，Amazon Bedrock 提供了满足 Lexbe 法律行业客户严苛要求所需的性能与可扩展性。

**使用的关键 AWS 服务：**

- **Amazon Bedrock. **一项全托管服务，提供高性能基础模型（FM）用于大规模语言任务。借助这些模型，Lexbe 能以极高的准确率快速分析海量法律文档。
- **Amazon Bedrock Knowledge Bases. **为端到端的检索增强生成（RAG）工作流提供全托管支持，使 Lexbe 能够摄取文档、执行语义搜索，并检索上下文相关的信息。
- [Amazon OpenSearch](https://aws.amazon.com/what-is/opensearch/)**. **为所有文档文本及相应元数据建立索引，同时使用 Vector 与 Text 两种模式。这使 Lexbe 能按向量或按关键词在海量数据集中快速定位特定文档或关键信息。
- [AWS Fargate](https://aws.amazon.com/fargate)**.** 在无服务器容器环境中编排大规模负载的分析与处理，使 Lexbe 无需管理底层服务器基础设施即可横向扩展。

## Amazon Bedrock Knowledge Bases 的架构与工作流

下图展示了 Amazon Bedrock 在 Lexbe 平台中的集成方式。该架构旨在同时处理法律文档的大规模摄取与检索。![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/04/image-1-5.png)

- **用户访问：** 用户通过 Web 浏览器访问前端应用。
- **请求路由：** 请求经 [Amazon CloudFront](https://aws.amazon.com/cloudfront) 路由，再通过 [Application Load Balancer](https://aws.amazon.com/elasticloadbalancing/application-load-balancer/) 连接到后端。
- **后端处理：** 运行在 Fargate 上的后端服务处理该请求，并与系统各组件交互。
- **文档处理：** 法律文档存放在 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3) 桶中，由 Apache Tika 从这些文档中抽取文本。抽取出的文本以单个文本文件的形式存放在另一个 S3 桶中。该桶被用作 Amazon Bedrock 的源仓库。
- **生成 embedding：** 抽取出的文本经 Titan Text v2 处理以生成 embedding。Lexbe 试验了多种 embedding 模型——包括 [Amazon Titan](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html) 和 Cohere——并测试了不同 token 大小的配置（例如 512 与 1024 token 的对比）。
- **存储 embedding：** 生成的 embedding 存储在向量数据库中，以便快速检索。
- **执行查询：** Amazon Bedrock Knowledge Bases 针对给定查询从向量数据库中检索相关数据。
- **集成 LLM：** Amazon Bedrock Sonnet 3.5 大语言模型（LLM）处理检索到的数据，生成连贯且准确的回答。
- **返回响应：** 最终回答经 CloudFront 通过前端应用返回给用户。

## Amazon 与 Lexbe 的合作

在八个月的时间里，Lexbe 与 Amazon Bedrock Knowledge Bases 团队携手合作，提升其 Pilot 特性的性能与准确度。这次合作包括两个组织的高层团队每周召开策略会议，从而实现快速迭代。从一开始，Lexbe 就确立了明确的验收标准，聚焦于达到特定的召回率。这些指标成为该特性何时可用于生产的基准。如下图所示，系统性能经历了五个重要里程碑，每一个都标志着向生产迈进的一次跨越。我们之所以聚焦 Recall Rate，是因为识别出正确的文档对于得到正确回答至关重要。与检索增强生成（RAG）的某些用例不同——那些用例中用户有具体问题，往往几份文档就能回答——我们的目标是生成事实认定报告，需要大量源文档。因此，我们聚焦 Recall Rate，以帮助确保 Amazon Bedrock Knowledge Bases 没有遗漏重要信息。

**第一轮迭代： **2024 年 1 月。最初的系统 Recall Rate 只有 5%，说明要达到生产可用还有大量工作要做。

**第二轮迭代： **2024 年 4 月。Amazon Bedrock Knowledge Bases 增加了新特性，准确率明显提升。此时 Recall Rate 达到 36%。

**第三轮迭代：** 2024 年 6 月。参数调整（尤其是 token 大小）带来了又一次性能跃升，Recall Rate 提升到 60%。

**第四轮迭代： **2024 年 8 月。使用 Titan Embed text-v2 模型使 Recall Rate 达到 66%。

**第五轮迭代： **2024 年 12 月**。**引入 Reranker 技术带来了巨大价值，使 Recall Rate 最高达到 90%。

## 最终成果令人印象深刻

- **广泛、类人的报告能力。** 在一起工业事故案件中，Pilot 被要求完成一份完整的事实认定分析。它产出了一份精炼的五页报告，包含清晰的章节标题，并带有指向每份源文档的超链接——无论这些文档是英文、西班牙文还是其他任何语言。
- **深度、自动化的推理。** 在一起涉及数万份文档的案件中，我们问：“Bob 的儿子是谁？”，但文中任何地方都没有明确提到他的孩子。然而 Pilot 锁定了一封邮件：它以“Dear Fam,”开头，以“Love, Mom/Linda,”结尾，元数据中还包含孩子们的名和姓。通过把这些线索连起来，它准确识别出了 Bob 的儿子，并引用了做出该推断的那封邮件。

eDiscovery 中的传统技术无法做到上述任何一项。借助 Pilot，法律团队可以：

- **生成可执行的报告**，律师可以快速迭代以做更深入的分析。
- **简化 eDiscovery**，揭示远超简单文本匹配的关键关联。
- **即刻释放战略洞见**，即便是多语言数据也能做到。

无论你需要一份完整、易读的报告，还是需要针对数据中潜藏关系的聚焦洞察，由 Amazon Bedrock Knowledge Bases 驱动的 Lexbe Pilot 都能快速交付你所需的精确信息。

## 集成 Amazon Bedrock 与 AWS 服务的收益

通过把 Amazon Bedrock 与其他 AWS 服务集成，Lexbe 在其文档审阅流程中获得了若干战略优势：

**可扩展性。** 借助 [Amazon Elastic Container Service（Amazon ECS）](https://aws.amazon.com/ecs) 和 AWS Fargate，Lexbe 可以动态扩展其处理基础设施。

**成本效率。** 在 Amazon ECS Linux Spot Market 中处理带来了显著的成本优势。

**安全性。** AWS 稳健的安全框架（包括加密与基于角色的访问控制）保护敏感的法律文档。这对 Lexbe 的客户至关重要，因为他们必须遵守严格的保密要求。

## 结论：可扩展、准确且高性价比的方案

通过集成 Amazon Bedrock，Lexbe 把其文档审阅平台转变为高效、可扩展且准确的方案。结合 Amazon Bedrock、Amazon OpenSearch 和 AWS Fargate，他们在检索准确度与处理速度上都取得了显著提升——同时把成本控制住。Lexbe 的成功印证了 AWS AI/ML 服务应对复杂现实挑战的能力。借助 AWS 灵活、可扩展且高性价比的产品，Lexbe 完全有能力满足法律行业不断变化的需求——无论现在还是未来。如果你的组织正面临可从 AI/ML 驱动的方案中受益的复杂挑战，请与 AWS 一起迈出下一步。首先与你的 AWS Solutions Architect 紧密合作，设计契合你独特需求的定制策略。与 AWS 产品团队接触，探索前沿服务，确保你的方案可扩展、安全且面向未来。我们可以携手帮助你更快创新、降低成本，并交付变革性的成果。
