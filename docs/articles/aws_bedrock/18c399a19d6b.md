# 在 Amazon SageMaker JumpStart 上使用 OpenTSLM 对时间序列数据进行推理

在各个行业中，决策首先要了解正在发生的变化及其原因。工业组织收集为其运营决策提供信息的数据。这些数据有助于防止生产中断、诊断车辆故障、解释数据中心性能下降以及根据供需变化调整定价。然而，解释这些数据仍然需要专业时间，收集更多数据并不意味着团队可以据此采取行动。 Claude 或 ChatGPT 等通用语言模型可以帮助分析数据。然而，以文本或图像形式处理数百个操作指标的长历史记录可能会消耗大量令牌，从而增加成本。

为了帮助组织根据这些数据采取行动，[Aionic Labs](https://www.aioniclabs.ai/) 正在开发时间基础模型，包括 [OpenTSLM](https://github.com/OpenTSLM/OpenTSLM)，这是一个开源的时间序列语言模型 (TSLM) 系列。这些模型解释从设备传感器数据到供应和需求的运营测量结果，以及维护记录、市场新闻和工程师的观察等背景信息。在此过程中，TSLM 帮助系统识别最近测量中出现的问题。然后，专家可以提出后续问题，以了解发生了什么变化并评估如何应对。 [TimeNet](https://docs.timenet.ai/) 是时间序列数据的共享数据基础设施，提供一种格式和 API 来查找、构建和加载用于训练和评估这些模型的数据集。它们共同帮助组织在问题变得代价高昂之前了解其系统如何变化和采取行动。

OpenTSLM 现已在 [Amazon SageMaker JumpStart](https://aws.amazon.com/sagemaker/ai/jumpstart/) 中提供，因此您可以在自己的 AWS 环境中部署模型。本文探讨了 Nexthink 和 Aionic Labs 如何将此功能引入主动 IT 协助，然后展示如何部署 OpenTSLM 并使用 TimeNet 将其适应您自己的数据。

## 客户示例：Nextthink 的主动 IT 支持

[Nexthink](https://nexthink.com/platform) 和 Aionic Labs 正在建设数字化工作场所，让员工“在”需要请求之前获得帮助。中心是 Nexthink 的个人 IT 代理 [Spark](https://nexthink.com/platform/spark)，它通过时间序列语言模型进行了增强，该模型将设备遥测和上下文与员工遇到的问题联系起来。 Spark 将这种理解转化为行动：它检查可能的问题，指导员工进行适当的修复，并对结果进行跟踪。主动协助成为保持工作顺利进行的一部分。

该工作流程将最近的设备时间序列（例如 CPU 活动、内存使用情况、可用磁盘空间、应用程序稳定性和连接性）与带时间戳的事件以及设备和软件上下文相结合。 TSLM 接收数值测量值以及文本上下文，并解释信号在观察窗口中如何变化。

TSLM 为 Spark 提供了三个输出：

- **状态摘要：** 解释可能的问题和支持信号模式，将设备行为与员工的体验联系起来。
- **建议的操作：** 指定检查以确认问题以及 Spark 为员工提供的实际操作。
- **预期结果：** 描述预期的改进以及 Spark 如何检查结果。

设备遥测和上下文支持调查一系列问题，包括高 CPU 或内存负载下的性能降低、反复出现的应用程序冻结或崩溃以及无法同步的文件。资源使用情况、应用程序事件、存储测量和连接活动提供了不同的证据。与设备配置和软件版本相结合，它们为 TSLM 提供了更广泛的基础来解释员工的经历并指导 Spark 的下一步检查。

在图 2 所示的低磁盘示例中，TSLM 将不断减少的可用空间、不断增加的磁盘队列以及更频繁的应用程序挂起与可能的员工症状（例如计算机速度缓慢或保存文件困难）联系起来。 Spark 检查剩余空间以及是否可以使用 IT 批准的清理来删除临时文件。如果检查确认清理是适当的，Spark 会向员工显示建议删除的内容并要求确认。员工确认后，Spark 会运行清理工作，检查现有可用空间，并询问问题是否有所改善。如果问题仍然存在，Spark 会将调查结果传递给 IT 支持。

TSLM 了解系统如何变化并帮助人们根据这种理解采取行动。对于 Spark 来说，这意味着识别新出现的 IT 问题并指导员工找到解决方案。同样的方法将时间序列智能引入制造、能源和互联产品，将测量和背景转化为解释和智能决策。

- 预构建的推理容器 – [AWS 深度学习容器](https://docs.aws.amazon.com/sagemaker/latest/dg/pre-built-containers-frameworks-deep-learning.html) 具有 GPU 加速功能，因此您无需构建自己的映像即可提供模型服务。

- 企业安全 – 具有 IAM 访问控制和网络隔离选项的 Amazon Virtual Private Cloud (VPC) 部署。

SageMaker JumpStart 中的模型是 [OpenTSLM-Flamingo](https://arxiv.org/html/2510.02410v3#S3.SS3)。它将 Gemma 3 4B 语言模型与时间序列编码器和交叉注意力层相结合，让语言模型关注编码序列。该模型共有 52.4 亿个参数，存储在 bfloat16 中，因此其权重占用约 10.5 GB 的 GPU 内存。

应用程序准备数字时间序列和文本上下文，调用 SageMaker 端点并接收模型的响应。应用程序可以将该响应呈现给专家或将其用作另一个工作流程的输入。

这种分离允许应用程序控制观察窗口、选择相关信号并在使用之前验证响应。它还使模型具有独立的适应性：在应用程序切换到新的检查点之前，可以根据代表性案例对其进行评估。

您还可以使用 SageMaker Python SDK v3 从 Python 创建部署。以下示例使用模型构建器。该模型是门控的：设置 `accept_eula=True` 接受其许可，即 Gemma 使用条款。在部署之前查看条款。 SDK 在构建模型时会打印指向它们的链接。

```
MODEL_ID = "pytorch-reasoning-opentslm-flamingo-gemma3-4b"

builder = ModelBuilder.from_jumpstart_config(

builder.build(model_name="opentslm-blog-demo")
endpoint = builder.deploy(endpoint_name="opentslm-blog-demo")
```
### 问一个关于时间序列的问题

端点接受带有一个或多个实例的 JSON 请求。每个实例都包含一个问题、一个或多个数字系列以及可选的上下文行。每个系列都有其值、名称和信号的简短描述，例如其单位和采样间隔。一个系列最多可以容纳 32,768 个值。端点将每个系列缩放为均值 0 和标准差 1，并将原始均值和标准差作为文本传递给模型，以便模型接收信号的形状和尺度。使用 `None` 作为缺失值。模型掩盖了它。

使用 SageMaker 运行时 [InvokeEndpoint](https://docs.aws.amazon.com/sagemaker/latest/APIReference/API_runtime_InvokeEndpoint.html) API 发送请求。设置 ENDPOINT_NAME 以匹配您的部署。主叫身份需要`sagemaker:InvokeEndpoint`权限。以下合成 CPU 示例显示了一个请求。
```
import json

import boto3

ENDPOINT_NAME = "opentslm-blog-demo"
runtime = boto3.client("sagemaker-runtime")

# One hour of CPU utilization, one sample per minute, with a five-minute spike.
cpu = [21, 20, 22, 19, 21, 20, 23, 21, 20, 19, 22, 21, 20, 21, 19, 22, 20, 21, 23, 20,
       21, 19, 20, 22, 21, 20, 19, 21, 78, 85, 82, 80, 79, 22, 20, 21, 19, 20, 22, 21,
       20, 21, 23, 19, 20, 21, 22, 20, 19, 21, 20, 22, 21, 20, 19, 21, 22, 20, 21, 20]

request = {
    "instances": [{
        "question": "Summarize the pattern and suggest what to check.",
        "series": [{
            "values": cpu,  # use None for a missing value
            "name": "CPU utilization (%)",
            "text": "CPU utilization (%), 1 sample/minute:",
        }],
        "context": ["The series covers 10:00 to 10:59 on a web server."],  # optional
    }],
    "parameters": {"max_new_tokens": 128},
}

response = runtime.invoke_endpoint(
    EndpointName=ENDPOINT_NAME,
    ContentType="application/json",
    Body=json.dumps(request),
)
print(json.loads(response["Body"].read())["generated_text"][0])
```
一个请求最多可以容纳四个实例，每个实例有 1 到 32 个系列，并且响应在 `generated_text` 中为每个实例包含一个答案。 `max_new_tokens` 接受 1 到 512 之间的值。该模型使用贪婪解码，因此相同的请求通常会返回相同的答案。实时调用必须在 60 秒内完成，请求正文最大为 6 MB。在 `ml.g6.2xlarge` 上，模型每秒生成约 20 个代币。端点按顺序处理请求的实例，因此响应时间随着实例的数量和答案的长度而增长：512 个令牌的答案大约需要 30 秒。要保持在 60 秒之内，请在一个请求中仅发送多个实例并提供简短的答案，例如 `max_new_tokens` 为 128。6 MB 限制还限制了请求可以携带的系列数据量。对于长时间运行的请求，您可以使用[异步推理](https://docs.aws.amazon.com/sagemaker/latest/dg/async-inference.html)。

您可以使用 AWS 命令​​行界面 (AWS CLI) 发送相同的请求。将请求保存为 JSON，例如使用 `json.dump(request, open("request.json", "w"))`，然后运行：
```
aws sagemaker-runtime invoke-endpoint \
    --endpoint-name opentslm-blog-demo \
    --content-type application/json \
    --body fileb://request.json \
    response.json
cat response.json
```
### 选择一个保留相关事件的输入窗口

[OpenTSLM-Flamingo](https://arxiv.org/html/2510.02410v3#S3.SS3) 在语言模型使用编码时间序列之前将其压缩为固定大小的表示集。这限制了传递给语言模型的表示，但它并没有使整个系统在内存中不受限制，也不能保证在很长的记录中仍然可以轻松识别简短的事件。

长背景研究使这种区别具体化。 [TS-Haystack](https://arxiv.org/html/2602.14200v6) 评估不同长度记录的事件检索，发现评估的 TSLM 变体通常会随着历史记录的增长而失去准确性，特别是在定位事件开始和结束时间时。这些结果促使您测试窗口上所选的检查点以及应用程序使用的问题。

选择一个包含事件和足够的周围上下文来解释它的窗口。对于长录音，请比较重叠的窗口。保留短暂事件的采样分辨率并及时调整相关通道。在文本上下文中包括单位、采样间隔和观察期。以预期长度验证正常和异常示例。端点可接受的有效负载大小和模型的有用分析窗口是单独的约束。

### 什么时候应该进行微调？

首先在应用程序中的代表性示例上测试预训练的 OpenTSLM 模型，并评估它回答您的问题的效果。

- **当答案正确并且其解释与信号匹配时使用预训练模型**。
- **当重要信息丢失时，例如测量单位、采样率、系统上下文或相关时间窗口，改进输入**。
- **当模型始终错过特定于您的领域的模式或难以完成您的任务时，即使有足够的上下文，也可以对模型进行微调。使用代表性信号与审阅的答案配对。

[TimeNet](https://docs.timenet.ai/) 提供了一种一致的方式来加载数据以进行训练和评估。微调后，在未用于训练的示例上将调整后的模型与原始模型进行比较。

### 使用 TimeNet 准备微调数据

[ARFBench](https://www.datadoghq.com/blog/ai/introducing-arfbench/) 是有关 Datadog 软件事件遥测异常的多项选择题的公共基准。我们使用ARFBench是因为它的选择题答案可以自动评分，这使得微调的效果可衡量。相同的工作流程适用于具有开放式答案的任务，例如 Nexthink 示例中的摘要和建议操作。 TimeNet 将 ARFBench 作为版本化数据集：每个问题都存储其答案选项、正确答案和度量信号。训练作业通过 TimeNet 加载 ARFBench 以及来自 Hugging Face 的模型检查点。

### 提交 SageMaker 训练作业并部署微调后的模型

SageMaker 训练作业在 GPU 实例上运行 OpenTSLM 训练脚本。该工作对时间序列编码器、感知器重采样器、交叉注意力层和语言模型的标记嵌入进行微调，并保持 Gemma 3 语言模型的其余部分冻结。该作业将微调后的模型保存到 Hugging Face 模型存储库布局中的 Amazon S3，并将训练前后的测试准确度写入 `metrics.json` 文件。如果您的 SageMaker Studio 域有默认的 MLflow 应用程序，该作业还会记录训练和验证损失以及测试准确性，以便您可以在 [MLflow UI](https://docs.aws.amazon.com/sagemaker/latest/dg/mlflow-launch-ui.html) 中比较运行。在我们对一个 `ml.g7e.2xlarge` 实例的运行中，135 个 ARFBench 问题的准确率从 5.0% 上升到 45.9%。根据 [ARFBench 论文](https://arxiv.org/abs/2604.21199)，这远远高于随机选择在完整基准上达到的 24.5%。在微调之前，模型将大多数答案留空。然后，它用给定的选项之一回答了每一个问题。 ARFBench 在此作为示例应用程序：它展示了如何使用公共数据集使模型适应新的任务和答案格式。结果并非与其他模型或官方 ARFBench 排行榜结果进行比较。

以下摘录自随附笔记本，开始使用 `ModelTrainer` 进行训练作业。 `scripts/train.py` 加载 ARFBench，评估和微调模型，并将其保存到 `FINETUNED_PREFIX`。
```
trainer = ModelTrainer(
    training_image=TRAINING_IMAGE,  # the SageMaker PyTorch 2.9 training image
    source_code=SourceCode(
        source_dir="scripts", entry_script="train.py", requirements="requirements.txt"
    ),
    compute=Compute(instance_type="ml.g7e.2xlarge", volume_size_in_gb=100),
    stopping_condition=StoppingCondition(max_runtime_in_seconds=24 * 60 * 60),
    hyperparameters={"base-model": BASE_MODEL, "output": FINETUNED_PREFIX, "epochs": 3},
    role=ROLE_ARN,
)
trainer.train()
```
要部署微调模型，请在 `ml.g6.2xlarge` 或 JumpStart 模型支持的其他实例类型上创建新的实时端点，并使用与 JumpStart 模型相同的容器映像和环境变量以及随附笔记本提供的推理脚本。将其模型数据指向微调模型文件的 S3 位置。请求格式保持不变，因此您可以向其发送上一节中的请求。随附的笔记本包含代码。

### 根据您的领域调整工作流程

通过将信号窗口与相关问题和审阅的答案配对，可以使相同的工作流程适应其他时间序列任务。潜在的示例包括通过维护环境解释设备行为、通过操作条件解释能耗模式以及通过可穿戴测量来描述活动。数据、监督和评估应反映应用程序旨在支持的领域和决策。

在准备过程中保留测量的时间和意义，并以反映部署的方式分离训练和评估数据。对于预测任务，只有在预测时可用的信息才属于输入。领域专家应评估答案是否以信号为基础并且对预期工作流程有用。对于自由文本答案，将其与经过审阅的参考答案进行比较，例如通过专家评级或LLM法官，其中语言模型根据标题对每个答案进行评分。

## 清理

已部署的端点将继续产生费用，直到您将其删除。完成后，删除端点、其端点配置及其模型。如果您从 SageMaker Studio 部署，请运行以下命令，而不是在端点页面上选择 **删除**，这只会删除端点。这些命令从端点名称查找配置和型号名称并删除所有三个。将 `ENDPOINT_NAME` 设置为端点的名称，例如对于 Studio 部署，以 `jumpstart-dft-` 开头的默认名称：
```
ENDPOINT_NAME=opentslm-blog-demo
CONFIG_NAME=$(aws sagemaker describe-endpoint --endpoint-name "$ENDPOINT_NAME" \
    --query EndpointConfigName --output text)
MODEL_NAME=$(aws sagemaker describe-endpoint-config --endpoint-config-name "$CONFIG_NAME" \
    --query 'ProductionVariants[0].ModelName' --output text)

aws sagemaker delete-endpoint --endpoint-name "$ENDPOINT_NAME"
aws sagemaker delete-endpoint-config --endpoint-config-name "$CONFIG_NAME"
aws sagemaker delete-model --model-name "$MODEL_NAME"
```
使用微调端点的名称重复这些命令。停止笔记本应用程序并删除您不打算保留的特定于教程的 S3 数据和工件。训练作业完成后停止。

时间序列语言模型将数值测量与人们用来做出决策的问题、背景和专业知识联系起来。在制造、能源、可穿戴设备和数字基础设施领域，它们为人们和应用程序提供了一种解释系统如何变化的通用方法。更广泛的机会是将运营历史与语言联系起来，使过去的观察在当前决策中更有用。

OpenTSLM 现已在 [Amazon SageMaker JumpStart](https://aws.amazon.com/sagemaker/ai/jumpstart/) 中提供，因此您可以通过 SageMaker Studio 或 SageMaker SDK 将其部署到您自己的 AWS 环境中的实时推理终端节点。 TimeNet 和 SageMaker 训练作业提供了一种使模型适应您领域的信号和问题的途径。

要开始使用，请探索 [Amazon SageMaker JumpStart](https://aws.amazon.com/sagemaker/ai/jumpstart/)，按照 [AWS 示例存储库](https://github.com/aws-samples/generative-ai-on-amazon-sagemaker) 中的示例进行操作，并查阅 [OpenTSLM 存储库](https://github.com/OpenTSLM/OpenTSLM) 和 [TimeNet 文档](https://docs.timenet.ai/)。从公共 ARFBench 示例开始，根据代表性案例对其进行评估，然后引入来自您自己领域的信号、问题和专业知识。
