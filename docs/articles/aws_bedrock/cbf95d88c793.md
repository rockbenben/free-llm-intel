# Heurist Finance 如何在 Amazon Bedrock AgentCore 上构建 AI 原生的投资工作台

[Heurist](https://www.heurist.ai/) 使用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 为散户投资者构建 AI 驱动的金融智能。其旗舰产品 Heurist Finance 把若干机构级工作流汇入一个聊天体验：它收集市场数据、阅读申报文件与新闻、执行深度研究、构建并对投资组合做压力测试，以及监控持仓。每个回答都反映用户自己的投资组合与偏好。Heurist 的目标是让统一的风险与收益视图、整体组合构建、情景分析这类工具，任何有市场问题的人都能用上。

本文讲解 Heurist 如何在 Amazon Bedrock AgentCore 上构建 Heurist Finance 背后的系统，并利用 [AgentCore payments](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments.html)（Amazon Bedrock AgentCore 的一项能力）按查询购买优质数据。文章展示付费数据访问、沙箱化分析、身份、记忆与可观测性如何汇聚成一个可审计的回答。

## 业务挑战

Heurist 让散户投资者获得建立在优质市场、宏观经济、基本面与另类数据之上的研究。这些数据源位于付费墙与定制 API 之后。没有单一供应商能覆盖全部，而在产品拥有庞大用户群之前，企业合同很难说得过去。只购买每个问题所需的数据是一种更好的经济模型，但它带来了另一个问题：agent 需要代表用户花钱，同时还要落实托管、支出限额与审计要求。

这带来了一个更广泛的生产挑战。每个动作都必须映射到具体的用户、会话与请求，因此身份需要贯穿整个工作流。团队还需要跨会话状态、隔离的代码执行、支付编排与端到端追踪。自行构建这套基础设施可能要花上几个月，并让团队从那些使 Heurist Finance 与众不同的研究工作流与个性化上分心。

## 解决方案概览

Heurist 把它的 agent 部署在 Amazon Bedrock AgentCore 上——这是一个可用任意框架或模型大规模构建、连接与优化 agent 的平台。Heurist 用 [Strands](https://strandsagents.com/) 编排其 agent，并使用 Amazon Bedrock 上可用的 [Anthropic Claude](https://aws.amazon.com/bedrock/anthropic/)。图 1 展示了周边 AgentCore 服务如何为每个请求提供支撑。

## 跨付费数据回答一个问题

单次用户回合就可能把价格、宏观经济指标、申报文件、基本面与新闻组合起来，再对结果做相关性分析、情景分析、绘图或回测。AgentCore Code Interpreter（Amazon Bedrock AgentCore 的一项能力）在一个不允许任意网络出口的隔离沙箱中完成这些工作。沙箱在 AWS Cloud 中运行，分析结束即被销毁。

其中有些数据是要花钱的，Heurist Finance 通过 Amazon Bedrock AgentCore payments 按查询购买。一个 Payment Manager 协调一个 `CoinbaseCDP` Payment Connector。每次交互都会获得一个 Payment Session，带有一个 `maxSpendAmount` 值以限定该次运行的支出上限，以及一个作用域限定在 Base 上的 Payment Instrument（一个嵌入式加密钱包）。

每个付费请求都遵循 x402 协议：

- Heurist Finance 向商户请求一个付费数据源。
- 商户返回 HTTP 402，并附上 x402 支付条款：金额、收款方、资产（USDC）与网络（Base）。
- AgentCore payments 依据 Payment Session 的 `maxSpendAmount` 值检查该载荷。如果这笔费用会超出上限，Heurist Finance 会告知用户并给出替代方案。
- 在预算之内，Heurist Finance 调用 Process Payment API，该 API 通过 Payment Instrument 对支付签名。凭证在运行时从 AWS Secrets Manager 取回。
- Heurist Finance 带着 `X-PAYMENT` 头中的证明重试该请求，商户随即返回数据。

有了 x402，Heurist Finance 只购买某个问题所需的数据，无需供应商合同或预付款。Heurist 通过 AgentCore payments、Payment Manager、Payment Connector 与 SDK 集成实现了该流程。

## 了解投资者的研究

当用户提出一个宽泛的问题，比如某只股票是否被高估时，Heurist Finance 会把研究建立在该用户的持仓、自选清单、时间跨度与风险偏好之上。答案在既有上下文之上继续构建，而不是从零开始，并随着画像逐渐清晰而变得更具体。

AgentCore memory（Amazon Bedrock AgentCore 的一项能力）跨会话存储用户的偏好、论点状态与对话历史。AgentCore Identity（Amazon Bedrock AgentCore 的一项能力）把该存储限定到单个用户，因此 Heurist 无需自建独立的偏好存储与访问控制层。

## 隔离、安全与审计

用户的画像与对话历史可能暴露其信念、风险承受能力、时间跨度与持仓。因此 Heurist 把身份、访问与审计视为每个请求的一部分。

AgentCore Identity 在每次服务调用中携带已通过身份验证的用户。每次工具调用、支付与记忆操作都会记录用户 ID、工作负载身份、请求 ID 与 trace ID，从而在各项服务之间形成一条统一的审计轨迹。

每项服务还各自执行边界。AgentCore Identity 接受 OAuth 并签发有作用域的凭证。AgentCore payments 按用户限定 Payment Session 与 Payment Instrument 的作用域，AgentCore memory 把画像与对话数据绑定到单个用户，AgentCore Code Interpreter 则隔离分析运行时。

Amazon Bedrock Guardrails 对输入与输出都做过滤。输入过滤有助于阻断针对支付与数据工具的 prompt 注入尝试，输出过滤则有助于执行 Heurist 的政策——不得推荐未对冲的单一股票。支付凭证保留在 AWS Secrets Manager 中，由 Payment Credential Provider 在运行时为 Payment Connector 取回。

## 请求流：一个用户问题

以这个问题为例：“今天的 PCE 数据发布对我的投资组合有何影响？”编排器从 Amazon Aurora PostgreSQL 加载用户的组合，AgentCore Identity 把这次读取限定到该用户。编排器随后调用一个付费的共识预测端点。收到 HTTP 402 后，AgentCore payments 检查 Payment Session 的支出上限，并通过 Payment Instrument 对支付签名。编排器带着 `X-PAYMENT` 头中的证明重试请求。

AgentCore Code Interpreter 计算组合影响，并在其沙箱内把一张图表写入 Amazon S3。Amazon Bedrock 结合用户的持仓、时间跨度与风险偏好综合出答案，回答以流式返回并附上图表。图 2 端到端地描摹了这一序列。

## 成果

Heurist 估计，相比自建的大语言模型（LLM）编排栈，agent 系统工程量减少约 80%，因为 AgentCore 管理身份、跨会话记忆、沙箱与支付基础设施。它还为 Heurist 提供了可预测的每用户边际成本，支撑其面向散户的定价。

该架构还带来两项运行特性：

- AgentCore Observability 的 trace 让 agent 的决策可复现，使合规问题能在一次查询中解决，从而提升合规就绪度并缩短排障时间。
- 支付凭证保留在 AWS Secrets Manager 中，由 Payment Connector 在运行时取回，提升了终端用户的安全性。

> “AgentCore 承担了平台方面的工作，让我们能把精力加倍投入到产品上。托管基础设施为我们节省了数月时间。”

— JW Wang，Heurist 创始人

## 结论

Heurist 的经历表明，托管 agent 基础设施如何让一个小团队专注于差异化的金融研究，而不是其底层的系统。AgentCore payments 是该模式的核心：它让产品以受治理、可审计的方式访问付费数据，而无需 Heurist 从零构建支付基础设施。

## 接下来

在这个基础之上，Heurist 正在三个方向扩展产品：与财报日历挂钩的事件驱动研究、对市场事件的组合感知分析，以及基于相近时间跨度的交易者正在研究什么而给出的推荐。
