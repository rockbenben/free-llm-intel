# 使用 Amazon Bedrock 构建 AI 驱动的课程内容生成系统

教育行业需要高效、高质量的课程材料开发，以跟上快速演变的知识领域。教师投入数天时间为即将在几周内讲授的主题创建内容和测验。教师更多参与手工内容创作，会挤压教学创新的时间，造成课程材料不一致，并给教师和学生带来糟糕的体验。

[生成式 AI](https://aws.amazon.com/generative-ai/)驱动的系统可以显著减少教师花在课程材料开发上的时间和精力，同时提升教育质量。把内容创建任务自动化，能让教育者有更多时间用于互动式教学和更具创意的课堂策略。

本文中的解决方案通过使用[大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLM），具体是借助 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 使用 Anthropic 的 Claude 3.5，来应对这一挑战，用于教育内容创作。这种 AI 驱动的方式支持自动生成结构化的课程大纲和详细内容，把开发周期从数天缩短到数小时，同时确保材料保持最新且全面。这次技术探索展示了机构如何利用先进的 AI 能力来变革教育内容开发流程，使其更高效、更可扩展，并更能响应现代学习需求。

该解决方案使用 [Amazon Simple Queue Service](https://aws.amazon.com/sqs/)（Amazon SQS）、[AWS Lambda](https://aws.amazon.com/lambda/)、Amazon Bedrock、[Amazon API Gateway](https://aws.amazon.com/api-gateway) WebSocket API、[Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）、[Amazon CloudFront](https://aws.amazon.com/cloudfront)、[Amazon DynamoDB](https://aws.amazon.com/dynamodb)、[Amazon Cognito](https://aws.amazon.com/cognito) 和 [AWS WAF](https://aws.amazon.com/waf/)。架构按照 [AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html) 设计，具备稳健性、可扩展性、成本优化、高性能和更强的安全性。

本文中，我们详细探讨每个组件，以及两个核心模块的技术实现：课程大纲生成和课程内容生成。课程大纲按周为一个学科生成包含模块和子模块的课程结构。主要成果和次要成果按周、按学期以层次化结构生成。内容生成是为内容大纲中生成的模块和子模块生成内容。生成的内容包括文本和视频脚本，以及相应的多项选择题。

## 解决方案概览

解决方案架构通过 WebSocket API 整合这两个核心模块。这一设计以使用 AWS Lambda 函数做无服务器计算、使用 Amazon Bedrock 做 AI 模型集成、使用 Amazon SQS 做可靠的消息排队为基础。

系统的安全采用多层方式，结合 Amazon Cognito 做用户认证、AWS WAF 做威胁缓解、一个 Lambda [authorizer](https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-use-lambda-authorizer.html) 函数做细粒度访问控制。为优化性能并提升用户体验，部署了 AWS WAF 来过滤恶意流量，并帮助防御常见的 Web 漏洞。此外，还实施了 Amazon CloudFront 作为 WebSocket 分发层，以显著提升内容交付速度并降低最终用户的延迟。这一综合架构构建出一个安全、可扩展、高性能的系统，用于生成和交付教育内容。

## WebSocket API 与认证机制

**Course WebSocket API** 管理课程大纲生成和内容生成的实时交互。与传统 REST API 相比，WebSocket 支持流式 AI 响应和实时交互，降低延迟并改善用户响应性。它还支持可扩展的并发，允许多个请求并行处理而不会压垮系统资源。**AWS WAF** 提供基于规则的过滤，在流量到达 API Gateway 之前帮助防御基于 Web 的威胁。**Amazon CloudFront** 通过在全球范围分发 WebSocket 流量来提升性能与安全性。**Amazon Cognito 与 JWT Lambda authorizer 函数**负责认证，在允许访问之前校验用户身份。

每个 WebSocket 实现三条主要路由：

- **$connect** – 触发一个 Lambda 函数，把 `connection_id` 记录到 DynamoDB。这样可以跟踪活跃连接、定向发送消息并高效管理连接，支持实时通信以及跨多个服务器实例的扩展。
- **$disconnect** – 在 DynamoDB 中记录断开连接，从 DynamoDB 表中移除 `connection_id` 记录。这便于正确清理非活跃连接、帮助避免资源浪费、维护准确的活跃客户端列表，并有助于优化系统性能和资源分配。
- **$default** – 处理意外或无效流量。

## 使用 Amazon Cognito 进行 WebSocket 认证

WebSocket API 集成 Amazon Cognito 做认证，并使用基于 JWT 的 Lambda authorizer 函数做 token 校验。认证流程如下：

- 用户认证  课程设计者使用 Amazon Cognito 登录，认证成功后 Cognito 签发 JWT 访问 token。Amazon Cognito 支持多种认证方式，包括用户名密码登录、社交身份提供商（如 Google 或 Facebook）以及基于 SAML 的联邦身份。
- WebSocket 连接请求  当用户尝试连接 WebSocket API 时，客户端会在 WebSocket 请求头中包含 JWT 访问 token。
- JWT token 校验（Lambda authorizer 函数）  该 JWT token authorizer Lambda 函数提取 token，并对照 Amazon Cognito 公钥进行校验。如果 token 有效，请求继续；如果 token 无效，连接被拒绝。
- 维护用户会话  认证成功后，$connect 路由的 Lambda 函数把 `connection_id` 和用户详情存入 DynamoDB，从而支持定向发送消息。当用户断开连接时，$disconnect Lambda 函数会移除 `connection_id`，以维护准确的会话记录。

## 课程大纲生成

课程大纲生成模块帮助课程设计者创建结构化的课程大纲。在这个概念验证中，默认结构跨 4 周，每周包含三个主要学习成果以及若干辅助的次要成果，但可以根据每门课程或每个机构的实际情况调整。该模块遵循以下工作流：

- 课程设计者通过课程 WebSocket（`courseOutline` 路由）提交 prompt。
- `CourseOutlineWSLambda` 把请求发送到 SQS 队列做异步处理。
- SQS 队列触发 `CourseOutlineLLMLambda`，后者在 Amazon Bedrock 中调用 Anthropic 的 Claude 3.5 Sonnet 生成大纲。
- 响应使用 Pydantic 模型结构化，并以 JSON 返回。
- 结构化的大纲存入 S3 的 `OutputBucket`，最终版本则存入门户存储桶供教师审阅。

以下代码示例是 `courseOutline` 路由的示例 payload，可以按机构要求定制。各字段定义如下：

- **action** – 指定要执行的操作（`courseOutline`）。
- **is_streaming** – 表示响应是否应流式返回（`yes` 为实时流式，`no` 为一次性输出）。
- **s3_input_uri_list** – 包含参考材料的 S3 URI 列表（如果没有可以留空）。
- **course_title** – 正在为其生成大纲的课程标题。
- **course_duration** – 课程的总周数。
- **user_prompt** – 一段结构化 prompt，引导 AI 依据教学大纲信息生成详细的课程大纲，给出组织良好的每周学习结构。如果使用其他 LLM，请针对该模型优化 `user_prompt` 以获得最佳效果。

```
{
    "action": "courseOutline", 
    "is_streaming": "yes",
    "s3_input_uri_list": [],
    "course_title": "Fundamental of Machine Learning",
    "course_duration": 2,
    "user_prompt": "I need help developing a {course_duration}-week course content for a {course_title} course. Please use the following syllabus to:\n\n1. If provided, refer to the syllabus text from <syllabus> tags to extract the course learning outcomes.\n2. Design each week to focus on 3 main learning outcomes.\n3. For each main learning outcome, provide 3 supporting sub-learning outcomes.\n\n<syllabus>\n\n{syllabus_text}\n\n</syllabus>\n\nEnsure that each week has 3 main learning outcomes and each of those has 3 supporting sub-learning outcomes."
}
```

# Read the syllabus text from uploaded doc

        pdf_text = extract_text_from_pdf(bucket, key)

# Initialize the Pydantic model

course_outline = {}

You have expertise in curriculum design. Your role is to analyze the provided syllabus, extract learning outcomes,

Format your response in valid JSON for easy parsing and integration.
Respond only with the requested content, without any preamble or explanation."""

user_msg_prompt = PromptTemplate.from_template(user_prompt)

messages = [{"role": "user","content": [{"text": user_msg}]}]

converse_response = bedrock_runtime_client.converse(
        system=[{ "text": system_prompt}],
        modelId=model_id,
        messages=messages,
        inferenceConfig=inference_config,
        toolConfig=tool_config,
    )

# Parse the LLM response into JSON format
course_outline = parse_bedrock_tool_response(converse_response)
        
send_message_to_ws_client(apigatewaymanagementapi_client, connection_id, response=course_outline)

return {'statusCode': 200,
         'body': json.dumps({'course_outline': course_outline})
        }
    
```

## 课程内容生成

课程内容生成模块基于课程大纲创建逐周的详细内容。虽然默认配置为每个主要学习成果生成以下产出，但这些产出完全可以定制，以满足具体课程需求和机构偏好：

- 一套阅读材料
- 三个视频脚本（每个 3 分钟）
- 一个测验，每个视频配一道多项选择题

该模块遵循以下工作流：

- 课程设计者通过 `courseContent` 路由提交学习成果。
- `CourseContentWSLambda` 函数把请求发送到 SQS 队列。
- SQS 队列触发 `CourseContentLLMLambda` 函数，后者调用 Amazon Bedrock 生成内容。
- 生成的内容被结构化并存入 Amazon S3。

以下是 `courseContent` 路由的示例 payload，可以按机构要求定制。各字段定义如下：

- **action** – 指定要执行的操作（`courseContent`）。
- **is_streaming** – 决定响应模式（`yes` 为实时流式，`no` 为一次性输出）。
- **s3_input_uri_list** – 包含额外课程材料的 S3 URI 数组，这些材料将用于生成课程内容（可选）。
- **week_number** – 表示正在为其生成内容的周次。
- **course_title** – 课程标题。
- **main_learning_outcome** – 指定周次的主要学习目标。
- **sub_learning_outcome_list** – 将要覆盖的辅助学习成果列表。
- **user_prompt** – 一段结构化指令，引导 LLM 生成特定周次的课程内容，促成全面覆盖。如果要切换到其他 LLM，请针对最佳表现优化 `user_prompt`。

    "week_number":1,
    "course_title": "Fundamental of Machine Learning",
    "main_learning_outcome" : "Understand the basics of machine learning and its applications",

"Identify real-world applications of machine learning",

    bucket, key = get_s3_bucket_and_key(s3_input_uri)
    if key.endswith('.pdf'):
        pdf_text = extract_text_from_pdf(bucket, key)
        additional_context = additional_context + pdf_text

# Initialize the Pydantic model
pydantic_classes = [CourseContent]

course_content={}    

system_prompt =f"""You are an AI assistant specialized in educational content creation.
Your task is to generate course materials based on given learning outcomes.
Produce concise, accurate, and engaging content suitable for college-level courses.
You may refer to additional context provided within <additional_context> tags if present.
Format your response in valid JSON for easy parsing and integration.
Respond only with the requested content, without any preamble or explanation."""

user_msg_prompt = PromptTemplate.from_template(user_prompt)

user_msg = user_msg_prompt.format(course_title=course_title, 
                                    week_number=week_number,
                                    main_learning_outcome=main_learning_outcome,
                                    sub_learning_outcome_list=sub_learning_outcome_list,
                                    additional_context=additional_context)

messages = [{"role": "user","content": [{"text": user_msg}]}]

tools = []
for class_ in pydantic_classes:
    tools.append(convert_pydantic_to_bedrock_converse_function(class_))
tool_config = { "tools": tools }

converse_response = bedrock_runtime_client.converse(
                            system=[{ "text": system_prompt}],
                            modelId=model_id,
                            messages=messages,
                            toolConfig=tool_config,
                            )

# Parse the LLM response into JSON format
course_content = parse_bedrock_tool_response(converse_response)

send_message_to_ws_client(apigatewaymanagementapi_client, connection_id, response=course_content)
   
return {'statusCode': 200,
         'body': json.dumps({'course_content': json.dumps(course_content)})
        }
```

## 前提条件

要实施本文提供的解决方案，你应当具备以下条件：

- 一个可用的 [AWS 账户](https://signin.aws.amazon.com/signup?request_type=builderId)，并熟悉[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM）和 [Amazon Bedrock](https://aws.amazon.com/bedrock/)。为 [Anthropic 的 Claude](https://aws.amazon.com/bedrock/anthropic/) 3.5v2 Sonnet 和 Anthropic 的 Claude 3.5 Haiku [启用模型访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access-modify.html)
- 已设置好 [AWS Cloud Development Kit](https://aws.amazon.com/cdk/)（AWS CDK）。关于安装说明，请参考 [AWS CDK 工作坊](https://cdkworkshop.com/15-prerequisites.html)。
- 部署 CDK 堆栈时，选择一个可以使用 Amazon Bedrock 中 Anthropic 的 Claude 模型的 [Region](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region)。虽然本解决方案使用美国西部（俄勒冈）`us-west-2` Region，你也可以选择其他 Region，但在继续之前需要确认它支持 Amazon Bedrock 中 Anthropic 的 Claude 模型。你用于访问模型的 Region 必须与部署堆栈的 Region 一致。

## 可扩展性与安全考量

该解决方案以可扩展性和安全性为核心原则设计。由于用于 WebSocket 的 Amazon API Gateway 本身并不支持 AWS WAF，我们集成了 Amazon CloudFront 作为分发层，并应用 AWS WAF 来增强安全性。

通过使用 Amazon SQS 和 AWS Lambda，系统实现异步处理、支持高并发，并动态伸缩以应对变化的负载。AWS WAF 有助于防御恶意流量和常见的 Web 威胁。Amazon CloudFront 可以改善全球性能、降低延迟，并提供内置的 DDoS 防护。Amazon Cognito 负责认证，使只有授权用户才能访问 WebSocket API。AWS IAM 策略实施严格的访问控制，保护 Amazon Bedrock、Amazon S3、AWS Lambda 和 Amazon DynamoDB 等资源。
