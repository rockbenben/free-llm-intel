# 用 Amazon Bedrock 多模态 RAG 能力革新药物数据分析

在制药行业，生物技术和医疗健康公司面临前所未有的挑战：如何高效管理和分析来自多种来源的海量药物相关数据。传统数据分析方法在处理包含文本、图像、图表和表格混合的复杂医学文档时显得力不从心。[Amazon Bedrock](https://aws.amazon.com/bedrock/) 提供[多模态](https://aws.amazon.com/about-aws/whats-new/2024/12/amazon-bedrock-knowledge-bases-processes-multimodal-data/)检索、先进的 chunking 能力以及引用等功能，帮助组织获得高准确度的回答。

制药与医疗健康组织要处理大量复杂的文档格式和非结构化数据，这给分析带来挑战。临床研究文档及与之相关的研究论文通常呈现技术性文本、详细表格和复杂统计图表的交织混合，使自动化数据提取尤为困难。临床研究文档还带来额外挑战：多个研究机构的格式不统一、数据呈现风格各异。本文通过一个能给出高准确度回答的示例应用，展示从复杂研究文档中提取数据驱动洞察的解决方案。它会分析研究文档中的临床试验数据、患者结局、分子结构图和安全报告。这可以帮助制药公司加速研究进程。该方案从源文档中提供引用，减少幻觉并提升回答的准确度。

## 方案概览

该示例应用使用 Amazon Bedrock 构建智能 AI 助手，用于分析和总结包含文本、图表和非结构化数据的研究文档。Amazon Bedrock 是一项全托管服务，提供多种业界领先的基础模型（FM）以及一整套构建生成式 AI 应用的能力，并通过安全性、隐私保护和负责任 AI 简化开发。

为了让 FM 掌握最新且专有的信息，组织会使用[检索增强生成](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）——一种从公司数据源获取数据并充实 prompt 的技术，从而给出相关且准确的回答。

[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 是 Amazon Bedrock 内一项全托管的 RAG 能力，内置会话上下文管理和来源归属，帮助你实现从数据摄取到检索、再到 prompt 增强的完整 RAG 工作流，而无需为数据源构建自定义集成或管理数据流。

Amazon Bedrock Knowledge Bases 引入了强大的文档解析能力，包括由 [Amazon Bedrock Data Automation](https://aws.amazon.com/bedrock/bda/) 驱动的解析和 FM 解析，彻底改变了我们处理复杂文档的方式。Amazon Bedrock Data Automation 是一项全托管服务，能有效处理多模态数据，而无需提供额外的 prompt。FM 选项则使用 FM 解析多模态数据。该解析器提供自定义数据提取所用默认 prompt 的选项。这一高级特性超越了基础文本提取，它智能地把文档拆分为不同组成部分——文本、表格、图像和元数据——同时保留文档结构和上下文。在处理 PDF 等受支持格式时，专用 FM 会解释并提取表格数据、图表和复杂的文档版式。此外，该服务还提供语义 chunking 等高级 chunking 策略，它基于嵌入模型计算出的语义相似度，智能地把文本划分为有意义的片段。与传统的句法 chunking 方法不同，这种方式保留了内容的上下文和含义，从而提升信息检索的质量和相关性。

该方案架构通过一套顺畅的工作流实现上述能力：首先由管理员以安全方式把知识库文档上传到 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）存储桶。这些文档随后被摄取到 Amazon Bedrock Knowledge Bases，由大语言模型（LLM）处理并解析摄取的数据。方案采用[语义 chunking](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-chunking.html)，把文档嵌入高效存储在 [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 中以优化检索。方案包含一个用 [Streamlit](https://streamlit.io/) 构建的易用界面，为最终用户提供直观的聊天体验。当用户与 Streamlit 应用交互时，会触发 [AWS Lambda](https://aws.amazon.com/lambda) 函数来处理请求，从知识库检索相关上下文并生成恰当的回答。该架构通过 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）实现安全防护，在整个工作流中维持恰当的访问控制。Amazon Bedrock 使用 [AWS Key Management Service](https://aws.amazon.com/kms/)（AWS KMS）加密与你的知识库相关的资源。默认情况下，Amazon Bedrock 使用 AWS 托管密钥加密这些数据。你还可以选择使用[客户托管密钥](https://docs.aws.amazon.com/kms/latest/developerguide/concepts.html#customer-cmk)加密模型构件。这一端到端方案提供高效的文档处理、上下文感知的信息检索和安全交互，通过顺畅的聊天界面给出准确而全面的回答。

该方案还使用了以下服务和特性：

- [Anthropic Claude 3 系列](https://aws.amazon.com/bedrock/claude/)提供 Opus、Sonnet 和 Haiku 模型，可接受文本、图像和视频输入并生成文本输出。它们在能力、准确度、速度和成本上提供了广泛的选择空间。这些模型能够理解包含图表、图形、表格、示意图和报告的复杂研究文档。
- [AWS Lambda](https://aws.amazon.com/lambda) 是一项无服务器计算服务，让你无需预置或管理服务器即可经济高效地运行代码。
- [Amazon S3](https://aws.amazon.com/s3/) 是一项高度可扩展、持久且安全的对象存储服务。
- [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 是一个全托管的搜索与分析引擎，用于高效检索文档。OpenSearch Service 的向量数据库能力支持语义搜索、基于 LLM 的 RAG、推荐引擎以及对富媒体内容的搜索。
- [Streamlit](https://streamlit.io/) 是一种更快的构建和分享数据应用的方式，用纯 Python 就能创建交互式 Web 数据应用。

## 先决条件

推进本方案需要以下先决条件。本文使用 us-east-1 AWS Region。关于可用 Region 的详细信息，请参阅 [Amazon Bedrock endpoints and quotas](https://docs.aws.amazon.com/general/latest/gr/bedrock.html)。

## 测试示例应用

设想你是某生物技术公司研发部门的成员，你的工作需要从研究论文、药物规格和行业论文等多种来源中，获取与药物和疫苗相关的信息洞察。你正在研究癌症疫苗，并希望基于癌症研究出版物获得洞察。你可以把“参考资料”一节中给出的文档上传到 S3 存储桶并同步知识库。下面我们来探索一些示例交互，以展示该应用的能力。AI 助手生成的回答基于上传到与知识库相连的 S3 存储桶中的文档。由于机器学习（ML）的非确定性，你的回答可能与本文呈现的略有不同。

## 结论

本文展示了利用 Amazon Bedrock Knowledge Bases 的[高级解析与 chunking 特性](https://community.aws/content/2jU5zpqh4cal0Lm47MBdRmKLLJ5/a-developer-s-guide-to-advanced-chunking-and-parsing-with-amazon-bedrock?lang=en)，实现强大的多模态文档分析（文本、图表、图像）。通过把 Amazon Bedrock FM 的强大能力、OpenSearch Service 与智能 chunking 策略结合在 Amazon Bedrock Knowledge Bases 之中，组织可以把复杂的研究文档转化为可搜索、可据以行动的洞察。语义 chunking 的引入确保文档上下文与关联关系得以保留，而易用的 Streamlit 界面则通过直观的聊天体验让最终用户可以使用该系统。该方案不仅简化了分析研究文档的过程，还展示了 AI/ML 技术在增强知识发现和信息检索方面的实际应用。随着组织持续应对不断增长的复杂文档数量，这一可扩展的智能系统为从其文档库中挖掘最大价值提供了稳固框架。

虽然我们的演示聚焦于医疗健康行业，但这项技术的适用性远不止单一行业。Amazon Bedrock 上的 RAG 已在多个行业证明其价值。知名采用者包括零售业的 [Adidas](https://aws.amazon.com/solutions/case-studies/georgia-pacific-optimizes-operator-efficiency-case-study/?did=cr_card&trk=cr_card)、信息管理领域的 [Empolis](https://aws.amazon.com/solutions/case-studies/empolis/?did=cr_card&trk=cr_card)、AI 解决方案领域的 [Fractal Analytics](https://aws.amazon.com/solutions/case-studies/fractal-analytics-case-study/?did=cr_card&trk=cr_card)、制造业的 [Georgia Pacific](https://aws.amazon.com/solutions/case-studies/georgia-pacific-optimizes-operator-efficiency-case-study/?did=cr_card&trk=cr_card) 以及金融服务业的 [Nasdaq](https://aws.amazon.com/solutions/case-studies/nasdaq-video-case-study/?did=cr_card&trk=cr_card)。这些例子说明了 RAG 技术在各类业务领域的广泛适用性和变革潜力，凸显了它在多个行业推动创新与效率的能力。
