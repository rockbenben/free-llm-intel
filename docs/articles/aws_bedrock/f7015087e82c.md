# 用 Amazon Nova Act 自动化竞争对手价格情报

监控竞争对手的价格对电商团队保持市场优势至关重要。然而，许多团队仍困在人工跟踪里，每天浪费数小时逐个查看网站。这种低效的做法拖延决策、抬高运营成本，并带来人为失误的风险，最终导致收入流失和机会丧失。

[Amazon Nova Act](https://nova.amazon.com/act) 是一个开源的浏览器自动化 SDK，用于构建能够浏览网站并用自然语言指令提取数据的智能 agent。本文演示如何构建一个自动化的竞争对手价格情报系统，把人工工作流精简掉，帮助团队基于实时市场洞察做出数据驱动的定价决策。

## 人工竞争对手价格情报的隐性成本

电商团队需要及时、准确的市场数据才能保持竞争力。传统工作流依靠人工、容易出错：在多个竞争对手网站上搜索特定商品，记录价格与促销数据，再把这些数据汇总到电子表格中做分析。这一过程带来几个关键挑战：

- **时间和资源消耗：** 人工价格监控每天占用员工数小时的时间，构成一笔可观的运营成本，而且随着商品目录增长，这种成本的可扩展性很差。
- **数据质量问题：** 人工录入数据会带来不一致和人为错误，可能导致基于有缺陷的信息做出错误的定价决策。
- **可扩展性受限：** 随着商品目录扩大，人工流程越来越难以为继，在竞品分析中形成瓶颈。
- **洞察延迟：** 最关键的问题是时效性。竞争对手的价格在一天之内可能快速变化，基于过时数据做出的决策会造成收入损失或错失机会。

这些挑战远不止于电商。保险公司会定期审阅竞争对手的保单、承保范围、除外责任和保费结构，以维持市场竞争力。金融服务机构通过耗时的人工核查来分析贷款利率、信用卡优惠和费用结构。旅游与酒店企业监控机票、住宿和套餐的波动价格，以便动态调整自己的产品。无论在哪个行业，困境都是一样的。人工调研缓慢、劳动密集且容易出错。在价格按小时变化的市场中，这些延迟让人几乎无法保持竞争力。

## 用 Amazon Nova Act 实现自动化

Amazon Nova Act 是一项 AWS 服务，附带一个 SDK，旨在帮助开发者构建能够在网页浏览器中行动的 agent。开发者用 Python 编写更小、更有针对性的命令来组装自动化流程，把用于浏览器交互的自然语言指令与程序化逻辑结合起来，例如测试、断点、断言，或用线程池实现并行化。借助工具调用能力，开发者还可以让 API 调用与浏览器操作同时进行。这让团队能完全掌控自动化的运行与扩展方式。Nova Act 支持 agentic commerce 场景，由自动化 agent 处理竞品监控、内容校验、目录更新和多步浏览工作流等任务。竞争对手价格情报是非常契合的场景，因为该 SDK 的设计目标就是应对真实世界的网站行为，包括布局变化和动态内容。

电商网站经常更改布局、开展短期促销，或轮换横幅和组件。这些变动常常会让依赖固定元素选择器或僵硬导航路径的传统规则式脚本失效。Nova Act 灵活、由自然语言命令驱动的方式，帮助 agent 在页面演进时继续工作，为生产级竞争情报系统提供了所需的韧性。

## 常用构建模块

Nova Act 包含一组简化浏览器自动化的构建模块。电商公司可以用它从网站上收集并记录商品价格，无需人工介入。实现这一点的构建模块包括：

### 从网页中提取信息

借助 Nova Act 的提取能力，agent 可以直接从渲染后的网页中收集结构化数据。你可以定义一个 Pydantic 模型来表示希望返回的 schema，然后让 `act_get()` 调用按该 schema 回答关于当前浏览器页面的问题。这样提取出的数据保持强类型、经过校验，并且可以直接供下游使用。

```
Nova.act_get("Search for 'iPad Pro 13-inch (M4 chip), 256GB Wi-Fi'.", schema=ProductData.model_json_schema())
```

### 导航到网页

这一步把 agent 重定向到某个特定网页作为起点。新的浏览器会话在期望的起点打开，使 agent 能够执行操作或提取数据。

```
nova.go_to_url(website_url)
```

### 并行运行多个会话

价格情报工作负载通常需要在短时间内检查数十个竞争对手页面。单个 Nova Act 实例一次只能调用一个浏览器，但多个实例可以并发运行。每个实例都很轻量，因此并行启动若干个并把工作分摊到它们之上是可行的。这使得浏览器自动化可以采用 map-reduce 风格的做法：不同的 Nova Act 实例同时处理各自的任务。通过把搜索或提取工作并行分布到许多实例上，组织可以缩短总执行时间，并以最低延迟监控大型商品目录。

```
from concurrent.futures import ThreadPoolExecutor, as_completed

from nova_act import ActError, NovaAct

# Accumulate the complete list here.
all_prices = []

# Set max workers to the max number of active browser sessions.
with ThreadPoolExecutor(max_workers=10) as executor:
    # Get all prices in parallel.
    future_to_source = {
        executor.submit(
            check_source_price, product_name, source_name, source_url, headless
        ): source_name
        for source_name, source_url in sources
    }
    # Collect the results in all_books.
    for future in as_completed(future_to_source.keys()):
        try:
            source = future_to_source[future]
            source_price = future.result()
            if source_price is not None:
                all_prices.extend(source_price.source)
        except ActError as exc:
            print(f"Skipping source price due to error: {exc}")

print(f"Found {len(all_prices)} source prices:\n{all_books}")
```

### 验证码

有些网站会在自动化浏览期间弹出验证码。出于伦理考虑，我们建议让人工参与解决验证码，而不是尝试自动化方案。Nova Act 不会代替用户破解验证码。

在本地运行 Nova Act 时，你的工作流可以用 `act_get()` 调用来检测是否存在验证码。如果检测到，工作流可以暂停并提示用户手动完成，例如在终端启动的进程里调用 `input()`。为此，请以有头模式（headed）运行工作流（设置 `headless=False`，这也是默认值），让用户可以直接与浏览器窗口交互。

用 AgentCore Browser Tool（ACBT）部署 Nova Act 工作流时，你可以使用它内建的[人在回路（HITL）能力](https://github.com/aws/nova-act?tab=readme-ov-file#use-nova-act-sdk-with-amazon-bedrock-agentcore-browser-tool)。ACBT 提供无服务器的浏览器基础设施，并能从 AgentCore AWS Console 实时串流画面。遇到验证码时，人工操作员可以通过 UI 接管（takeover）功能实时接管浏览器会话，解决挑战后把控制权交还给 Nova Act 工作流。

```
result = nova.act("Is there a captcha on the screen?", schema=BOOL_SCHEMA) if result.matches_schema and result.parsed_response:
    input("Please solve the captcha and hit return when done")
...
```

### 处理错误

Nova Act 客户端启动之后，`act()` 调用期间可能会遇到错误。这些问题可能源于动态布局、元素缺失或意外的页面变化。Nova Act 把这些情况以 ActError 的形式暴露出来，让开发者可以捕获它们、重试操作、应用回退逻辑，或记录细节以便进一步分析。这帮助价格情报 agent 避免静默失败，即使网站行为不可预测也能继续运行。

## 构建与监控 Nova Act 工作流

### 使用 AI 驱动的 IDE 构建

构建 Nova Act 自动化工作流的开发者，可以使用带 Nova Act IDE 扩展的 AI 驱动开发环境来加速实验和原型开发。该扩展支持 Kiro、Visual Studio Code 和 Cursor 等主流 IDE，把智能代码生成和上下文感知辅助直接带进你偏好的开发环境。Amazon Nova Act 的 IDE 扩展通过把自然语言提示转化为可投产的代码来加快开发。你无需翻阅文档或编写重复的样板代码，只需描述自动化目标即可。这对竞争对手价格情报这类复杂任务很有帮助：扩展可以帮你快速组织 ThreadPoolExecutor 逻辑、设计 Pydantic schema，并构建健壮的错误处理。

### 在 Nova Act 控制台中观察工作流

Nova Act 的 AWS 控制台让你通过 AWS Management Console 查看工作流执行的详细轨迹与产物。它提供一个集中位置来实时管理和监控自动化工作流。你可以从[工作流运行](https://docs.aws.amazon.com/nova-act/latest/userguide/step-4-review-workflow-runs.html)的总体视图下钻到单个会话、act 和步骤的具体细节。这种可见性通过精确展示 agent 如何做决定、如何执行循环，帮助你调试和分析性能。借助直接访问存储在 Amazon S3 中的截图、日志和数据，你可以快速排查问题，而无需在多个工具之间切换。这精简了排查过程，并缩短了从实验到生产部署的迭代周期。

## 运行该方案

为帮助你上手自动化市场调研，我们发布了一个基于 Python 的示例项目，承担价格监控的繁重工作。该方案使用 Amazon Nova Act 一次启动多个浏览器会话，同时在各竞争对手站点搜索商品。你不必自己逐个打开标签页，脚本会浏览网页找出价格和促销信息，然后把所有内容汇集成干净的结构化格式，方便你用于自己的定价模型。以下各节将介绍如何开始构建竞争对手价格情报 agent。探索之后，你可以部署到 AWS 并在 AWS Management Console 中监控工作流。

竞争对手价格情报 agent 作为 Price Comparison 用例的一部分，已在 Amazon Nova Samples GitHub 仓库中作为 AWS Samples 方案提供。

### 1. 前提条件

你的开发环境必须包含：Python 3.10 或更高版本，以及 [Nova Act SDK](https://pypi.org/project/nova-act/)。

### 2. 获取 Nova Act API key：

导航到 `https://nova.amazon.com/act` 并生成一个 API key。使用 Nova Act Playground，或选择以 API key 认证的 Nova Act 开发者工具时，访问与使用受 [nova.amazon.com 使用条款](https://www.amazon.com/gp/help/customer/display.html?nodeId=Tsn7s47ytlgjRBHozK)约束。

### 3. 克隆仓库、设置 API key 并安装依赖：

开始之前，克隆仓库、设置 API key 以便应用通过认证，并安装所需的 Python 依赖。这样你的环境就准备好了，可以在本地顺利运行项目。API Key 可以在 Nova Act 上生成。

```
# Clone the repo 
https://github.com/aws-samples/amazon-nova-samples.git 
cd nova-act/usecases/price_comparison 

# Create and activate a virtual environment (optional but recommended) 
python3 -m venv .venv 
source .venv/bin/activate 

# Windows:
.venv\Scripts\activate 

# Install Python dependencies 
pip install -r requirements.txt 

# Set the Nova Act API Key export NOVA_ACT_API_KEY="your_api_key"
```

### 4. 运行脚本

环境搭好之后，你就可以运行 agent 来执行竞争对手价格情报。脚本接受商品名（可选）和竞争对手网站列表（可选），启动并发的 Nova Act 浏览器会话，搜索每个站点，提取价格与促销细节，并返回结构化的聚合结果。

上例使用的是脚本默认的竞争对手列表，其中包含 Amazon、Target、Best Buy 和 Costco 等大型零售商。你可以在运行脚本时提供自己的竞争对手 URL 列表来覆盖这些默认值。

```
python -m main.py \
    --product_name "iPad Pro 13-inch, 256GB Wi-Fi" \
    --product_sku "MVX23LL/A" \
    --headless
```

agent 会并行启动多个 Nova Act 浏览器会话，每个竞争对手站点一个。每个会话加载零售商的网站，检查是否存在验证码，若需要解决则暂停等待用户输入。确认无阻碍后，agent 搜索商品、查看返回结果、点击最相关的条目，并提取价格与促销信息。并发运行这些流程，使 agent 能够高效完成多站点比价。

例如，面向 Amazon 时，agent 会打开一个新的浏览器会话，导航到 amazon.com，并对该站点执行针对该商品的搜索。它检查返回的结果，找出与查询最匹配的商品条目，并提取价格、促销、库存状态及相关元数据等关键细节。这一过程体现在下面的终端输出中，其中反映了每个推理步骤（本示例中的价格为示意，不代表真实市场价格）：
