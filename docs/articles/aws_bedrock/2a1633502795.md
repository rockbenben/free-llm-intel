# 使用 Amazon Bedrock 构建由生成式 AI 驱动的业务报告解决方案

传统的业务报告流程往往耗时且低效。专员通常每月花费约两小时准备报告，而经理则每月最多花费 10 小时汇总、审阅和格式化提交的内容。这种人工做法常常导致格式和质量上的不一致，需要多轮审阅。此外，报告分散在各个系统中，使整合与分析更加困难。

生成式人工智能（AI）为这些报告挑战提供了一种颇具吸引力的解决方案。根据一项 [Gartner 调查](https://www.gartner.com/en/newsroom/press-releases/2024-05-07-gartner-survey-finds-generative-ai-is-now-the-most-frequently-deployed-ai-solution-in-organizations)，生成式 AI 已成为组织中被最广泛采用的 AI 技术，其中 29% 的组织已将其投入实际使用。

本文介绍由生成式 AI 引导的业务报告——聚焦于撰写关于业务的成果与挑战——提供了一套智能而实用的解决方案，帮助简化并加速内部沟通与报告。该方案遵循 Amazon Web Services（AWS）最佳实践构建，采用之后，你将把更少的时间用于撰写报告，而把更多时间用于推动业务成果。该方案应对三项现实世界的挑战：

- 从海量数据中发掘有价值的洞察
- 管理 AI 实施相关的风险
- 通过提升效率与决策来推动增长

完整的方案代码可在我们的 [GitHub 仓库](https://github.com/aws-samples/sample-genai-enterprise-report-writing-assistant/)中获取，让你能在自己的 AWS 环境中部署并测试该方案。

该生成式 AI 方案通过自动化增强报告流程。借助大语言模型（LLM）处理，报告系统能够生成人类可读的报告、回答追问，并让非技术背景的相关方也能获取洞察。这种自动化降低了成本和对大量人力资源的需求，同时减少人为错误与偏见。其结果是人工流程难以达到的准确度和客观性，最终带来更高效、更有效的业务报告。

## 方案概览

这个由生成式 AI 驱动的 Enterprise Writing Assistant 展示了一套现代的无服务器架构，利用 AWS 强大的服务组合交付智能写作解决方案。该系统在设计上兼顾可扩展性与安全性，把 [AWS Lambda](https://aws.amazon.com/lambda/) 函数、提供 AI 能力的 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 以及各种 AWS 服务结合起来，打造出健壮的企业级写作助手，帮助组织在保持高质量与一致性标准的同时精简内容创作流程。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/22/image-1-1024x573.jpeg)

该方案采用基于 AWS 服务的无服务器、可扩展设计。下面我们来了解各组件是如何协同工作的：

### 用户交互层

- 用户通过浏览器访问该方案，浏览器连接到托管在 [Amazon S3](https://aws.amazon.com/s3/) 上、并通过 [Amazon CloudFront](https://aws.amazon.com/cloudfront/) 全球分发的前端 Web 应用，以获得最佳性能
- [Amazon Cognito](https://aws.amazon.com/cognito/) 用户池负责身份验证和安全的用户管理

### API 层

- [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 中的两类 API 管理前端与后端之间的通信：  **WebSocket API** 为报告撰写和编辑提供实时的双向通信  **REST API** 处理提交和检索报告等事务性操作
- [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 监控这两类 API，以提供运维可见性
- 专用的 [AWS Lambda](https://aws.amazon.com/lambda/) 授权器通过校验用户凭证来保护这两类 API

### 编排层

- 专门的 AWS Lambda 函数编排核心业务逻辑：  **Business Report Writing Lambda** 负责报告起草与用户协助  **Rephrase Lambda** 提升报告的清晰度与专业性  **Submission Lambda** 处理最终报告提交  **View Submission Lambda** 检索此前提交的报告

### AI 与存储层

- [Amazon Bedrock](https://aws.amazon.com/bedrock/) 提供报告撰写与改写所需的 LLM 能力
- 两张 [Amazon DynamoDB](https://aws.amazon.com/dynamodb/) 表存储不同类型的数据：  **Session Management** 表在活动会话期间维护对话上下文  **Business Report Store** 表永久归档已完成的报告

该架构通过使用仅在运行时才产生费用的无服务器组件，实现了高可用、自动扩缩容和成本优化。组件之间的通信遵循 AWS 最佳实践加以保护。

你可以按照 [GitHub 仓库](https://github.com/aws-samples/sample-genai-enterprise-report-writing-assistant/tree/main)中的分步说明，在你自己的 AWS 账户中部署该架构。

## 真实工作流：报告生成与改写

该系统的工作流先通过分类过程对每一条用户输入进行分析和归类。这一分类决定了系统如何处理并响应输入。系统依据三种不同的分类采用特定的处理路径：

- **问题或指令**：当系统把输入归类为问题或指令时，它会以恰当的 prompt 激活 LLM，生成相关回复。系统把这些交互存入对话记忆，从而为后续相关查询保持上下文。这种上下文感知能力提供连贯一致的回复，并在先前交互的基础上继续构建。
- **校验提交内容**：对于需要校验的输入，系统会启用其评估协议，对你的提交内容给出详细反馈。系统会把这些交互存入对话记忆，但在校验过程中刻意跳过记忆检索。这一设计选择使校验过程仅基于当前提交内容本身的价值，而不受此前对话影响。这种做法降低了系统延迟，并有助于得到更准确、更客观的校验结果。
- **超出范围**：当输入落在系统定义的参数之外时，它会以标准化的消息回应：“Sorry, I can only answer writing-related questions.”这为系统的能力维持清晰的边界，有助于避免混淆或不恰当的回复。

这些分类既支持高效处理，又只在必要时维护恰当的上下文，从而在不同交互场景中同时优化性能与准确率。

## 先决条件

要在你的 AWS 账户中部署该方案，需要以下内容：

- 一个具有管理访问权限的 AWS 账户
- 已安装并配置好的 [AWS CLI (2.22.8)](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-version.html)
- 对 Amazon Bedrock 模型（Claude 或 Anthropic Claude）的访问权限
- Node.js（20.12.7），用于前端组件
- 用于克隆代码仓库的 Git

## 部署方案

生成式 AI Enterprise Report Writing Assistant 使用 AWS CDK 进行基础设施部署，使在 AWS 环境中搭建变得简单直接：

- 克隆 GitHub 仓库：

```
git clone https://github.com/aws-samples/sample-generative AI-enterprise-report-writing-assistant.git && cd sample-generative AI- enterprise-report-writing-assistant
```

- 安装依赖项：

```
npm install
```

- 将应用部署到 AWS：

```
cdk deploy
```

- 部署完成后，等待 1-2 分钟让 [AWS CodeBuild](https://aws.amazon.com/codebuild/) 流程结束。
- 使用 CDK/CloudFormation 输出中的 `VueAppUrl` 访问该应用。

部署过程会创建必要的资源，包括 Lambda 函数、API Gateway、DynamoDB 表，以及托管在 S3 和 CloudFront 上的前端应用。

有关详细的配置选项和自定义方式，请参阅 GitHub 仓库中的 [README](https://github.com/genai-enterprise-report-writing-assistant/blob/main/README.md)。

## 清理资源

为避免产生后续费用，请在不再需要时删除该方案创建的资源：

```
cdk destroy
```

该命令会删除由 CDK 堆栈预置的 AWS 资源，包括：

- Lambda 函数
- API Gateway 端点
- DynamoDB 表
- S3 存储桶
- CloudFront 分发
- Cognito 用户池

请注意，某些资源（例如包含部署构件的 S3 存储桶）可能需要先清空内容才能删除。

## 结论

传统的业务报告耗时且依赖人工，导致整体效率低下。生成式 AI Enterprise Report Writing Assistant 在组织处理内部报告流程的方式上代表了重大跃升。借助生成式 AI 技术，该方案解决了业务报告的传统痛点，同时引入了此前无法实现的能力。通过具备实时反馈的智能报告撰写辅助、为提升清晰度与专业性而做的自动改写、精简的提交与审阅流程，以及健壮的校验系统，该方案为现代业务报告需求提供全面的支持。该架构有助于安全、高效的处理，在自动化与人工监督之间取得关键平衡。随着组织持续应对日益复杂的业务问题，快速生成清晰、准确且有洞察力的报告的能力已不仅是一种优势，而是必需品。生成式 AI Enterprise Report Writing Assistant 提供的框架可以随组织的需求扩展，同时在各层级报告中保持一致性与质量。
