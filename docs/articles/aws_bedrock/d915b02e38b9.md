# 使用开源 Model Profiler 简化 Amazon Bedrock 中的模型选择

生成式 AI 在各行业的采用正在加速，而 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 提供了一个受管服务，用于构建生产就绪的 AI 应用。借助来自 Anthropic、OpenAI、Meta、Mistral AI、Cohere 和 Amazon 等提供方的 100 多个基础模型，团队可以灵活地为每个用例选择正确的模型。

但选择也带来了复杂性。跨能力、定价、区域可用性、上下文窗口上限和吞吐量来比较模型并不简单。这些信息散落在控制台页面、文档以及各区域的 API 调用之中。对于为新工作负载评估模型、优化成本与性能，或从其他 AI 系统迁移的组织来说，这种碎片化的发现过程会拖慢试验、延迟生产决策。

[Amazon Bedrock Model Profiler](https://github.com/aws-samples/sample-bedrock-migration-and-modernization-tools/tree/main/bedrock-model-profiler) 填补了这一缺口。这个开源工具把来自多个 AWS API 和外部来源的模型 metadata 聚合到一个可搜索的界面中。借助高级筛选、并排比较和详细的模型卡片，团队可以浏览完整的 Amazon Bedrock 目录，并通过减轻在各种文档和模型卡片之间手工查找的负担，做出有依据的、数据驱动的决策。

在本文中，你将了解 Model Profiler 提供了什么、它支持哪些真实场景，以及如何在五分钟内把它部署到你自己的环境中。

## 解决方案概览

Model Profiler 是一个 Web 应用，让你在一处浏览、筛选和比较 Amazon Bedrock 上可用的每一个基础模型。你不必在多个控制台页面和文档站点之间来回跳转，而是得到一个统一界面，其中包含模型卡片、并排比较、区域可用性地图以及每日更新的定价明细。

Model Profiler 展示 Model Explorer 界面

在这个界面背后，一条完全自动化的 serverless pipeline 从七个不同的来源收集并处理数据：五个 AWS API 和两个公开 URL。这让目录无需人工干预即可保持准确。

| **来源** | **类型** | **认证** | **收集的数据** |
| --- | --- | --- | --- |
| Amazon Bedrock ListFoundationModels API | AWS API | IAM (Sigv4) | 模型规格、能力、模态，以及跨 33 个区域的可用性 |
| AWS Price List API | AWS API | IAM (Sigv4) | 跨三个服务代码的按需、批量和预留档定价 |
| AWS Service Quotas API | AWS API | IAM (Sigv4) | 每分钟 token 数（TPM）上限、每分钟请求数（RPM）配额，以及吞吐量约束 |
| Amazon Bedrock ListInferenceProfiles API | AWS API | IAM (Sigv4) | 跨区域推理配置与地理范围 |
| Amazon Bedrock Mantle API | AWS API | IAM (Sigv4) | 跨区域的 Mantle 推理可用性 |
| LiteLLM Model Database | 公开 URL | 无 | token 规格，包括上下文窗口大小和最大输出 token |
| AWS Documentation | 公开 URL | 无 | 模型生命周期状态（active、legacy、end-of-life） |

在评估模型时，理解关键配额指标至关重要。每分钟 token 数（TPM）衡量你每分钟能处理多少 token。可以把它看作你的吞吐量上限，其中 1,000 个 token 大约相当于 750 个单词的文本。每分钟请求数（RPM）限制你能发出多少次 API 调用，与请求大小无关。两项配额都随模型和区域而异。

Model Profiler 数据 pipeline 的架构图

Model Profiler 运行一条由 AWS Step Functions 编排的完全自动化数据 pipeline。十七个 AWS Lambda 函数分四个阶段处理数据，并利用 Lambda 之间的 S3 缓存把每次执行的 API 调用从约 480 次减少到 29 次。这相当于 97% 的缓存命中率。一个由 Amazon Bedrock 驱动的自愈式 agentic 系统会检测数据缺口，并自动应用安全的配置修复。整条 pipeline 在 8–12 分钟内完成，每天 UTC 上午 6 点运行。

运行计划可通过 AWS CloudFormation 模板中的 Amazon EventBridge 规则进行配置。你可以根据自己的需求调整 cron 表达式，以不同的时间或频率运行。

### 阶段 0：初始化

这条 pipeline 首先动态发现当前哪些 AWS 区域支持 Amazon Bedrock。没有任何区域列表是硬编码的，因此新上线的区域会被自动纳入。随后它初始化执行上下文（S3 路径、缓存键），并在后端与 React 前端之间同步配置，确保两侧无需人工干预即可保持一致。

### 阶段 1：并行收集

三条独立的收集分支同时运行。Pricing 分支跨三个服务代码查询 AWS Price List API，并按提供方和模型聚合结果。Models 分支向已启用 Amazon Bedrock 的各区域扇出，在每个区域调用 ListFoundationModels，并对结果去重，汇总为一份规范模型列表。Quotas 分支并行收集每分钟 token 数和每分钟请求数的服务限额。

### 阶段 2：并行丰富

原始数据收集完成后，六个丰富化步骤并发运行，从缓存数据中读取而不是重新调用 API，以把定价记录关联到模型、计算区域可用性、确定跨区域推理支持情况、获取上下文窗口大小、探测 Mantle API，并确定每个模型的生命周期状态。

### 阶段 3：聚合与智能

最终的聚合器把丰富化数据合并成两个生产就绪的 JSON 文件：bedrock_models.json（包含规格、配额、可用性和生命周期状态的完整模型目录）和 bedrock_pricing.json（按提供方和模型组织的定价）。两个文件都会被复制到 Amazon Simple Storage Service（Amazon S3），并通过 Amazon CloudFront 提供访问。

在发布之前，一个缺口检测系统会扫描输出，查找七类数据质量问题。当缺口超过配置的阈值时，一个自愈 agent 会分析缺口报告并自动应用安全的修复。变更会被版本化并备份，而不满足安全标准的建议会被记录以供人工审核，而不是自动应用。

### 部署选项

该解决方案提供两种部署选项。本地模式完全在你的机器上运行，使用你现有的 AWS 凭证。运行数据收集器、启动前端，凭借对 Amazon Bedrock 和 Pricing API 的读取权限即可开始探索。不需要任何云基础设施。

AWS 部署提供完全 serverless 的架构，并带有每日自动数据刷新。一个 AWS Step Functions workflow 编排 AWS Lambda 函数，每天 UTC 上午 6 点收集最新数据，把结果存储在 Amazon S3 中，并通过 Amazon CloudFront 提供访问。本地收集器导入与 Lambda 代码相同的转换函数，因此无论你在本地还是在生产环境运行，输出都保持一致。

## 核心功能

Model Profiler 提供四项核心能力，简化模型选择流程：从发现与比较，到区域规划以及跟踪你的候选清单。

### Model Explorer

Model Explorer 是你发现 Amazon Bedrock 模型的起点。在一个可搜索、可筛选的界面中浏览 120 多个基础模型。你可以按提供方（Anthropic、Meta、Amazon、Mistral AI、Cohere 以及另外 14 家）、按能力（例如视觉、代码生成、函数调用或 embedding），以及按输入与输出模态来缩小结果范围。模态描述模型能处理的数据类型：纯文本模型处理书面内容，而多模态模型可能接受文本和图像作为输入，并生成文本、图像或两者作为输出。区域筛选只显示目标区域中可用的模型，状态筛选则让你专注于 active 模型，或把 legacy 选项一并纳入。

Model Explorer 界面，展示筛选选项和模型卡片

消费选项筛选让你按使用模型的方式进一步收窄结果。In Region 在特定的 AWS 区域中提供按需推理，并按 token 计费。跨区域推理服务（CRIS）跨区域路由请求以获得更高吞吐量。Batch 以更低成本异步处理大批量数据，结果交付到 Amazon S3。Mantle 提供带有专属容量和自定义配置的受管推理端点。

Model Explorer 支持两种视图模式。卡片视图提供可视化浏览，让关键规格一览无余。表格视图支持跨多个模型进行密集比较。全文搜索可在模型名称、描述和提供方信息中检索。

每个模型都有一个全面的详情视图，汇总可用的信息：技术规格（模态、上下文窗口、推理类型）、按区域和消费类型划分的定价明细、带跨区域推理细节的区域可用性、各区域的服务配额（TPM 与 RPM 上限），以及指向官方文档和提供方信息的链接。

模型卡片，展示技术规格信息

### 模型比较

当你确定了候选模型之后，比较视图让你在每一个重要维度上对它们进行分析。

Model Comparison 视图，并排展示四个模型，并提供 Overview 与 Availability 选项卡

最多可同时比较 25 个模型的四个维度。定价涵盖各区域的输入与输出 token 成本，包括按需、批量和预置档。区域可用性显示每个模型在哪些地方可用，包括跨区域推理支持。规格包括上下文窗口大小、最大输出 token 和受支持的功能。能力矩阵则并排展示每个模型支持什么。

Amazon Bedrock 提供多种定价选项，以匹配不同的工作负载模式。按需档包括 standard、flex 和 priority 选项，按 token 计价且无需承诺。Batch 定价为在 24 小时内处理的非时间敏感作业提供 30-50% 的折扣，具体取决于模型和模态。预留档以固定的每小时费率为持续的高容量工作负载提供专属容量。按模型划分的详细定价，请参阅 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/) 页面。

### 区域可用性矩阵

对于规划多区域部署的团队，Regional Availability 视图提供覆盖全部 33 个已启用 Amazon Bedrock 区域的完整“模型 × 区域”矩阵。区域按地理区域分组（NAMER、EMEA、APAC、LATAM），每个单元格显示某个模型在该区域的可用方式：按需（In Region）、跨区域推理（CRIS）或 Mantle。

你可以按可用性类型筛选该矩阵，从而快速回答诸如“哪些模型在欧洲支持 CRIS？”或“ap-southeast-2 中按需可用的是什么？”这类问题。展开某个模型行会显示推理配置 ID、CRIS 源区域和地理范围。该矩阵还会呈现模型生命周期状态（active、legacy 或 end-of-life），因此你可以识别即将弃用的模型并提前规划迁移。对于跨多个地理区域运营的组织，这个视图替代了原本需要数十次单独 API 调用并手工交叉比对生命周期文档的工作。

Regional Availability 矩阵，展示每个区域的模型可用性，并用颜色编码的单元格表示模型状态

### 收藏

在浏览模型的过程中，你可以给模型加星标，把它们加入 Favorites 列表——一份在你多次浏览器会话之间保留的个人候选清单。Favorites 选项卡提供与 Model Explorer 主界面相同的筛选、排序和详情视图，只是范围限于你保存的模型。这在评估期间跟踪一组工作用的候选模型时很有用，也便于快速访问你团队最常用的模型。

## 用例

让我们看看不同团队如何基于各自独特的需求来处理模型选择。以下场景中的组织均为虚构。它们结合真实的 AWS 定价与配额数据，以及贴近现实的工作负载假设，来展示该解决方案的能力。

### 跨欧洲区域选择符合合规要求的模型

Octank Financial Services 需要构建一个由 AI 驱动的文档分析系统，用于监管合规。该团队需要具备视觉能力的模型来处理扫描文档，但为满足数据驻留要求，运营必须完全保持在 EU 区域之内。面对 Amazon Bedrock 上数十个多模态模型以及各区域不同的定价，团队估计光是把候选模型列出来就要花 6 到 8 小时的人工调研。

使用 Model Profiler，团队按“vision”能力和 EU 区域筛选，立刻看到符合条件的模型。他们用 Regional Availability 矩阵确认 eu-west-1 和 eu-central-1 中的按需可用性，然后并排比较定价，找出最具成本效益的选项。服务配额也确认吞吐量能满足他们预计的每日 50,000 次文档审查。

结果是：模型评估从估计的 8 小时缩短到 25 分钟。团队还发现，他们首选的模型在 eu-west-1 比在 eu-central-1 便宜 18%，并且找到了一款上下文窗口更大的新模型，这减轻了把冗长的监管文档拆到多次调用中的必要性。

### 从第三方 AI 提供方迁移

Octank Health 运营着一个构建在第三方 AI 提供方之上的临床文档助手，需要迁移到 Amazon Bedrock，以获得更紧密的 AWS 集成和更好的成本控制。他们的要求很具体：128K token 或更大的上下文窗口、低延迟，以及至少在美国三个区域可用以实现冗余。要把当前提供方的能力在不同区域间手工映射到 Amazon Bedrock 目录，需要在多个文档来源上进行大量调研。

团队使用能力筛选找出符合要求的模型，然后打开比较视图，评估候选模型的上下文窗口、输出上限和定价。Regional Availability 视图确认了哪些模型支持美国范围的跨区域推理，从而无需改动应用即可获得自动故障转移。生命周期状态标记帮助他们避开了一款即将进入 legacy 状态的模型。

评估在 45 分钟内完成。团队选择了一款上下文窗口为 200K 的模型（相比此前 128K 的上限是一次显著升级），每 token 成本低 15%。跨区域推理可用性检查帮助他们避免选择一款不支持跨区域的模型——那将迫使他们重新设计故障转移策略。

### 多区域部署：规划全球扩张

Octank Media 正在把他们由 AI 驱动的内容推荐引擎从美国扩展到欧洲和亚太。在确定架构之前，他们需要确认当前模型在目标区域的可用性、了解各区域支持哪些消费选项，并核实服务配额能否承受预计的流量。

Regional Availability 矩阵让团队在一处就能看到他们的模型在全部 33 个区域的情况，并按 In Region、CRIS 和 Mantle 分列。按 APAC 和 EMEA 区域筛选，清楚地揭示了他们的模型在哪些地方可用以及以何种方式可用。生命周期状态列确认该模型在目标区域处于 active 状态，且没有即将到来的弃用。跨区域配额比较发现 ap-northeast-1 是一个潜在瓶颈，需要在发布前提交配额提升申请。

多区域可行性分析在 20 分钟内完成。此前，同样的工作需要通过 AWS Command Line Interface（AWS CLI）逐个查询区域并交叉比对文档。在生产之前就识别出东京的配额约束，有助于避免一次服务中断；而确认 CRIS 在欧洲的可用性，则为流量尖峰建立了可靠的回落策略。

## 先决条件

在部署 Model Profiler 之前，请确认你已具备以下条件。

**用于本地部署：**

- Python 3.11 或更高版本。
- Node.js 18 或更高版本。
- 已配置 AWS 凭证，并对以下服务具备读取权限：

```
bedrock:ListFoundationModels, bedrock:ListInferenceProfiles
bedrock-mantle:*
pricing:GetProducts, pricing:DescribeServices
servicequotas:ListServiceQuotas, servicequotas:GetServiceQuota
ec2:DescribeRegions
```

**用于 AWS 部署（额外要求）：**

- 已安装 AWS Serverless Application Model（AWS SAM）CLI。
- 具备部署 CloudFormation 栈、Lambda 函数、S3 桶、Step Functions 和 CloudFront 分发的权限的 AWS 凭证。AWS SAM 模板会自动创建必要的 IAM 策略，因此你只需要有部署该栈本身的权限。

## 部署演练

Model Profiler 提供两条部署路径。选择本地部署，在你自己的机器上快速探索；或者选择 AWS serverless 部署，获得一个自动刷新、托管的界面。

### 选项 1：本地部署

在五分钟内本地部署 Model Profiler，无需任何云基础设施。

#### 步骤 1：克隆代码仓库

```
git clone https://github.com/aws-samples/bedrock-model-profiler.git
cd bedrock-model-profiler
```

#### 步骤 2：设置 Python 环境

```
python -m venv .venv
source .venv/bin/activate # On Windows: .venv\Scripts\activate
pip install -r local/requirements.txt
```

#### 步骤 3：收集模型数据

使用你的 AWS profile 运行数据收集器。它会查询跨 25 个区域的 API，通常 1-2 分钟完成。

```
python -m local collect --profile your-aws-profile
```

随着每个阶段完成，你会看到进度输出：

```
[1/8] Collecting pricing data...
Found 9562 pricing products
[2/8] Aggregating pricing data...
Aggregated into 18 providers
...
[8/8] Building final output...
Wrote data/bedrock_models.json
Wrote data/bedrock_pricing.json

Collection Complete!
Duration: 81.3 seconds
Models collected: 117
```

#### 步骤 4：启动前端

```
cd frontend
npm install
cp template.env .env
npm run dev
```

在浏览器中访问 [http://localhost:5173](http://localhost:5173/)。应用会直接从本地 data/ 目录加载数据。

### 选项 2：AWS 部署

部署完整的 serverless 解决方案，并带有每日自动刷新。

#### 步骤 1：验证你的 AWS 账户

```
aws sts get-caller-identity
```

如果你有多个 profile，请设置要使用的那一个：

```
export AWS_PROFILE=your-profile-name
```

#### 步骤 2：部署后端栈

必须先使用 AWS SAM 部署后端。这会创建 Lambda 函数、Step Functions workflow、S3 数据桶和 EventBridge 计划。

```
cd infra
sam build -t backend-template.yaml
sam deploy --guided
```

引导式部署会提示你输入栈名称、区域和参数。标准部署可使用默认值，或按需自定义。

#### 步骤 3：部署前端并链接基础设施

后端栈运行起来之后，setup 脚本会部署剩余的基础设施并把一切连接起来。

```
./setup-infrastructure.sh
```

该脚本执行五个步骤：

- 校验后端栈存在，并获取数据桶名称。
- 部署前端基础设施（S3 托管桶和 CloudFront 分发）。
- 用 CloudFront ARN 更新后端栈，使数据桶向 CDN 授予读取权限。
- 如果在 frontend/.env 中配置了 Amazon Cognito 凭证，则可选地部署分析栈。
- 构建 React 前端并上传到 S3。

完成后，你会收到一个 CloudFront URL，通过它即可访问该应用。数据每天 UTC 上午 6 点自动刷新。如需更多帮助，请参阅代码仓库中的部署指南 [https://github.com/aws-samples/bedrock-model-profiler](https://github.com/aws-samples/bedrock-model-profiler#troubleshooting)，或在 [https://github.com/aws-samples/bedrock-model-profiler/issues](https://github.com/aws-samples/bedrock-model-profiler/issues) 提交 issue

## 清理

如果你是为了评估而部署了 AWS 基础设施，请在完成模型选择后移除这些资源，以避免持续产生费用。

让未使用的基础设施持续部署，时间一长可能累积意外成本，尤其是在多个区域或多个账户中运行 profiler 进行测试时。此外，删除评估栈有助于保持 AWS 环境整洁，并有助于避免在管理生产资源时产生混淆。

**用于本地部署：** 删除克隆下来的代码仓库目录。没有创建任何云资源。**用于 AWS 部署：** 删除 CloudFormation 栈以移除所有资源：

```
aws cloudformation delete-stack --stack-name bedrock-profiler
```

这会移除 S3 桶、Lambda 函数、Step Functions workflow 和 CloudFront 分发。
