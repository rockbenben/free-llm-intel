# 使用 Amazon Nova 进行会议摘要与行动项提取

会议在决策、项目协调与协作中发挥着关键作用，远程会议在许多组织中也已十分常见。然而，从这些对话中捕捉并结构化关键要点往往效率低下且前后不一。人工总结会议或提取行动项不仅耗时费力，还容易出现遗漏或误解。

[大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLMs）通过将非结构化的会议记录转化为结构化的摘要和行动项，提供了更为可靠的解决方案。这一能力尤其适用于项目管理、客户支持与销售通话、法律与合规，以及企业知识管理等场景。

在本文中，我们对 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) 系列中可在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上使用的不同理解模型进行了基准测试，就如何为会议摘要任务选择最合适的模型提供洞见。

## 用 LLMs 生成会议洞见

现代 LLMs 凭借理解上下文、推断主题关系以及生成结构化输出的能力，在摘要和行动项提取方面表现出色。在这类用例中，与传统的模型 fine-tuning 或定制相比，prompt engineering 提供了一种更高效、更可扩展的方法。prompt engineering 无需修改底层模型架构，也无需在大规模标注数据集上训练，而是借助精心设计的输入查询来引导模型行为，直接影响输出的格式与内容。这种方法无需资源密集的重新训练过程，即可实现快速的、特定领域的定制。对于会议摘要和行动项提取这类任务，prompt engineering 能够精确控制生成结果，确保其满足特定的业务需求。它还可以灵活调整 prompts 以适应不断演变的用例，因此非常适合那些需要在没有模型 fine-tuning 开销的情况下快速调整模型行为的动态环境。

## Amazon Nova 模型与 Amazon Bedrock

[Amazon Nova 模型](https://docs.aws.amazon.com/nova/latest/userguide/what-is-nova.html)于 2024 年 12 月在 AWS re:Invent 上亮相，旨在以行业领先的价格性能提供前沿智能。它们是各自智能层级中速度最快、最具成本效益的模型之一，并经过优化，能够以可靠、安全且经济高效的方式支撑企业级[生成式 AI](https://aws.amazon.com/generative-ai/)应用。

理解模型系列包含四个层级的模型：Nova Micro（仅文本，超高效，适用于边缘场景）、Nova Lite（多模态，兼顾通用性的均衡之选）、Nova Pro（多模态，速度与智能兼备，非常适合大多数企业需求）以及 Nova Premier（多模态，是处理复杂任务能力最强的 Nova 模型，也是模型蒸馏中的教师模型）。Amazon Nova 模型可用于多种任务，从摘要到结构化文本生成均可胜任。借助 [Amazon Bedrock Model Distillation](https://aws.amazon.com/bedrock/model-distillation/)，客户还可以将 Nova Premier 的智能能力迁移到更快、更具成本效益的模型（如 Nova Pro 或 Nova Lite），以适配自身的用例或领域。这可以通过 [Amazon Bedrock console](https://docs.aws.amazon.com/nova/latest/userguide/getting-started-console.html) 以及 [Converse API](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference-call.html) 和 [Invoke API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_InvokeModel.html) 等 API 来实现。

## 解决方案概览

本文演示如何使用通过 Amazon Bedrock 提供的 Amazon Nova 理解模型，借助 prompt engineering 实现自动化的洞见提取。我们重点关注两项关键输出：

- **会议摘要**——一种高层级的抽象式摘要，从会议记录中提炼关键讨论点、作出的决策与重要更新
- **行动项**——一份结构化的可执行任务清单，源自会议对话，适用于整个团队或项目

## 解决方案组件

我们利用 Amazon Bedrock 上提供的常用模型，开发了该解决方案的两项核心功能——会议摘要与行动项提取。在接下来的小节中，我们将介绍用于这些关键任务的 prompts。

对于会议摘要任务，我们使用了[角色设定](https://docs.aws.amazon.com/nova/latest/userguide/prompting-system-role.html)，提示 LLM 在 `<summary>` 标签中生成摘要，以减少冗余的开头和结尾语句；同时采用 one-shot 方法，即给 LLM 提供一个示例，确保 LLM 始终按照正确的格式生成摘要。作为系统 prompt 的一部分，我们给出清晰简洁的规则，强调正确的语气、风格、长度以及对所提供会议记录的忠实度。

对于行动项提取任务，我们在 prompts 中给出了关于生成行动项的具体指令，并使用 [chain-of-thought](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/chain-of-thought#example-writing-donor-emails-basic-cot) 来提升生成行动项的质量。在 assistant 消息中，前缀 `<action_items>` 标签作为[预填充](https://docs.aws.amazon.com/nova/latest/userguide/prompting-structured-output.html)提供，用于引导模型朝正确方向生成，并避免冗余的开头和结尾语句。

不同模型系列对相同 prompts 的响应各不相同，遵循针对特定模型定义的 prompting 指南十分重要。有关 Amazon Nova prompting 最佳实践的更多信息，请参阅[Amazon Nova 理解模型的 prompting 最佳实践](https://docs.aws.amazon.com/nova/latest/userguide/prompting.html)。

## 数据集

为评估该解决方案，我们使用了公开 [QMSum 数据集](https://github.com/Yale-LILY/QMSum)中的样本。QMSum 数据集是会议摘要领域的基准数据集，包含来自学术、商业和治理讨论的英文会议记录，并配有人工标注的摘要。它评估 LLMs 从复杂的多说话人对话中生成结构化、连贯摘要的能力，是抽象式摘要与语篇理解的宝贵资源。在测试中，我们从 QMSum 数据集中随机抽取了 30 场会议。每场会议包含 2–5 个按主题划分的文字记录，平均每段记录约含 8,600 个 token。

## 评估框架

让 LLMs 在会议摘要和行动项提取任务中生成高质量输出并非易事。ROUGE、BLEU 和 METEOR 等传统评估指标侧重于生成文本与参考摘要之间的表层相似度，但往往无法捕捉事实正确性、连贯性和可操作性等细微之处。人工评估是金标准，但成本高、耗时长，且难以规模化。为应对这些挑战，可以采用 LLM-as-a-judge，即使用另一个 LLM 依据明确定义的准则系统地评估生成输出的质量。这种方法提供了一种可扩展且经济高效的方式来实现评估自动化，同时保持较高的准确性。在本示例中，我们选用 Anthropic 的 Claude 3.5 Sonnet v1 作为评判模型，因为我们发现它与人类判断最为一致。我们使用 LLM 评判者从三个主要指标对生成的响应进行评分：忠实度、摘要和问答（QA）。

[忠实度](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/faithfulness/)评分通过衡量摘要中被解析出的陈述里、由给定上下文（例如会议记录）所支持的部分占陈述总数的比例，来衡量生成摘要的忠实程度。

[摘要](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/summarization_score/#summarization-score)评分是 QA 评分与简洁度评分按相同权重（0.5）组合而成。QA 评分衡量生成摘要对会议记录的覆盖程度。它首先根据会议记录生成一组问答对，然后在以摘要（而非会议记录）作为上下文时，衡量其中被正确回答的问题所占比例。QA 评分与忠实度评分互为补充，因为忠实度评分并不衡量生成摘要的覆盖程度。我们只使用 QA 评分来衡量生成摘要的质量，因为行动项本就不应覆盖会议记录的方方面面。简洁度评分衡量生成摘要长度与会议记录总长度之比。

我们使用了忠实度评分和摘要评分的改进版本，其延迟远低于原始实现。

## 结果

我们对 Amazon Nova 模型在会议摘要和行动项提取任务上的评估，揭示出清晰的性能—延迟规律。在摘要方面，Nova Premier 取得了最高的忠实度评分（1.0），处理时间为 5.34 秒；Nova Pro 在 2.9 秒内达到 0.94 的忠实度。更小的 Nova Lite 和 Nova Micro 模型忠实度评分分别为 0.86 和 0.83，处理时间更快，分别为 2.13 秒和 1.52 秒。在行动项提取方面，Nova Premier 再次以 0.83 的忠实度领先，处理时间为 4.94 秒，其次是 Nova Pro（忠实度 0.8，2.03 秒）。有趣的是，尽管 Nova Micro 体量更小，但在这项特定任务上（忠实度 0.7，1.43 秒）却优于 Nova Lite（忠实度 0.63，1.53 秒）。这些测量结果为文本处理应用中 Amazon Nova 模型系列的性能—速度特征提供了有价值的洞见。下图展示了这些结果。以下截图展示了我们摘要任务的一个示例输出，包括 LLM 生成的会议摘要和行动项列表。

## 结论

在本文中，我们展示了如何使用 prompting，借助通过 Amazon Bedrock 提供的 Amazon Nova 模型生成会议摘要和行动项等会议洞见。对于大规模 AI 驱动的会议摘要，优化延迟、成本和准确性至关重要。Amazon Nova 理解模型系列（Nova Micro、Nova Lite、Nova Pro 和 Nova Premier）为高端模型提供了一种实用的替代方案，在显著降低运营成本的同时大幅提升了 inference 速度。这些因素使 Amazon Nova 成为企业大规模处理海量会议数据的理想选择。
