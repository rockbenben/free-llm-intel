# 借助 Amazon Nova Multimodal Embeddings 的统一向量检索，规模化实现创意素材发现

游戏公司在管理其广告创意素材方面面临着前所未有的挑战。现代游戏公司会为 A/B 测试活动制作数千条视频广告，一些组织维护着超过 100,000 个视频素材的素材库，且每月还以数千个素材的速度增长。这些素材对用户获取活动至关重要——能否找到合适的创意素材，往往决定一次投放是成功上线还是代价高昂的失败。

本文介绍如何使用 [Amazon Nova Multimodal Embeddings](https://docs.aws.amazon.com/nova/latest/userguide/nova-embeddings.html) 检索特定的视频片段。我们还会回顾一个真实用例：在针对 170 个游戏创意素材库的测试中，Nova Multimodal Embeddings 取得了 96.7% 的召回成功率，以及 73.3% 的高精度召回（即目标内容出现在前两条结果中）。该模型还展现出强大的跨语言能力，在多种语言之间的性能下降极小。

传统用于整理、存储和检索创意素材的方法，无法满足创意团队的动态需求。传统做法是给创意素材手动打标签以支持关键词检索，再按文件夹层级组织，人工在其中查找所需素材。基于关键词的检索系统需要手动打标签，既耗费人力又前后不一致。虽然大语言模型（LLM）方案——例如基于 LLM 的自动打标签——提供了强大的多模态理解能力，但它们无法扩缩到满足创意团队在庞大素材库中执行多样化实时检索的需求。

核心挑战在于创意素材发现中的语义检索。检索需要支持无法用固定 prompt 或预定义标签预先组织的、不可预测的检索需求。当创意专业人员检索 `the character is pinched away by hand` 或 `A finger taps a card in the game` 时，系统必须理解的不只是关键词，还有跨不同媒体类型的语义含义。

这正是 [Nova Multimodal Embeddings](https://docs.aws.amazon.com/nova/latest/userguide/nova-embeddings.html) 改变格局之处。Nova Multimodal Embeddings 是一款先进的多模态嵌入模型，面向 agentic [检索增强生成（RAG）](https://aws.amazon.com/what-is/retrieval-augmented-generation/) 与语义检索应用，采用统一向量空间架构，可在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 中使用。更重要的是，该模型可直接从视频素材生成嵌入，无需中间转换步骤或手动打标签。

Nova Multimodal Embeddings 的视频嵌入生成能力实现了对视频内容的真正语义理解。Nova Multimodal Embeddings 可以分析视频中的视觉场景、动作、物体与上下文，从而创建丰富的语义表示。当你检索 `the character is pinched away by hand` 时，模型理解的是所描述的具体动作、视觉元素与上下文——而不只是关键词匹配。这种语义能力规避了基于关键词的检索系统的根本局限，使创意团队能够用自然语言描述找到相关视频内容，而这些描述用传统方法是无法预先打标签或组织的。

## 解决方案概览

本节介绍 Nova Multimodal Embeddings 及其关键能力、优势，以及它与 AWS 服务的集成，从而构建一套完整的多模态检索架构。本文描述的多模态检索架构提供：

- **输入灵活**：接受文本查询、上传的图片、视频和音频文件作为检索输入
- **跨模态检索**：用户可以用文本描述查找视频、图片与音频内容，也可以用上传的图片在多种媒体类型中发现相似的视觉内容
- **输出精确**：返回带相似度分数、视频片段精确时间戳以及详细元数据的排序结果
- **同步检索与取回**：通过预计算的嵌入和高效的向量相似度匹配，即时提供检索结果
- **统一的异步架构**：检索查询以异步方式处理，以应对不同的处理时长并提供一致的用户体验

## Nova Multimodal Embeddings

[Nova Multimodal Embeddings](https://aws.amazon.com/ai/generative-ai/nova/) 是首个统一嵌入模型，通过单一模型支持文本、文档、图片、视频与音频，以业界领先的准确率实现跨模态检索。它提供以下关键能力与优势：

- **统一向量空间架构**：传统基于标签的系统，或需要在不同向量空间之间建立复杂映射的「多模态转文本」pipeline，都与它不同——Nova Multimodal Embeddings 生成的嵌入无论输入模态为何，都存在于同一个语义空间中。这意味着 `racing car` 的文本描述在空间上会靠近包含赛车的图片与视频，从而实现直观的跨模态检索。
- **灵活的嵌入维度**：Nova Multimodal Embeddings 提供四种嵌入维度选项（256、384、1024 和 3072），使用 Matryoshka Representation Learning（MRL）训练，可在不同维度下实现低延迟检索且准确率损失极小。1024 维选项为多数企业应用提供了最佳平衡，而 3072 维则为关键用例提供最高精度。
- **同步与异步 API**：该模型既支持针对较小内容的实时嵌入生成，也支持对大型文件进行带自动分段的异步处理。这种灵活性使系统能够处理从快速文本查询检索到数小时视频内容索引的各类任务。
- **先进的视频理解**：对于视频内容，Nova Multimodal Embeddings 提供精细的分段能力，把长视频拆分为有意义的片段（1–30 秒）并为每个片段生成嵌入。对于广告创意管理而言，这种分段方式与典型的生产工作流完美契合——创意团队需要管理和检索的是特定视频片段，而非整段视频。

### 与 AWS 服务的集成

### 系统执行流程

内容摄取工作流通过一系列自动化步骤，把原始媒体文件转化为可检索的向量嵌入。该过程始于用户上传内容，终于把嵌入存入向量数据库，使内容可通过语义检索被发现。

- **用户交互**：用户通过 [Amazon CloudFront](https://aws.amazon.com/cloudfront) 访问 Web 界面，使用拖拽或文件选择上传媒体文件（图片、视频和音频）。
- **API 处理**：文件被转换为 base64 格式，经 API Gateway 发送到主 Lambda 函数，进行文件类型与大小限制校验（最大文件大小为 10 MB）。
- **Amazon S3 存储**：Lambda 解码 base64 数据，并把原始文件上传到 Amazon S3 进行持久存储。
- **Amazon S3 事件触发**：新文件上传时，Amazon S3 会自动触发一个专用的嵌入 Lambda 函数，启动嵌入生成过程。
- **调用 Amazon Bedrock**：嵌入 Lambda 函数异步调用 Amazon Bedrock 的 Nova Multimodal Embeddings 模型，为多种媒体类型生成统一嵌入向量。
- **向量存储**：嵌入 Lambda 函数把生成的嵌入向量连同元数据存入 OpenSearch Service，形成一个可检索的向量数据库。

### 检索与取回工作流

通过检索与取回工作流，用户可以使用多模态查询找到相关内容。该过程把用户查询转换为嵌入，并在预先构建的向量数据库上执行相似度检索，返回基于跨媒体类型语义相似度的排序结果。

- **检索请求**：用户通过 Web 界面使用上传的文件或文本查询发起检索，并可选不同的检索模式（视觉、语义或音频）。
- **API 处理**：检索请求经 API Gateway 发送到检索 API Lambda 函数进行初步处理。
- **任务创建**：检索 API Lambda 函数在 [Amazon DynamoDB](https://aws.amazon.com/dynamodb) 中创建检索任务记录，并把消息发送到 [Amazon Simple Queue Service (Amazon SQS)](https://aws.amazon.com/sqs/) 队列以进行异步处理。
- **队列处理**：检索 API Lambda 函数把消息发送到 Amazon SQS 队列以进行异步处理。这种统一的异步架构满足了 Nova Multimodal Embeddings 的 API 要求（视频分段需异步调用），避免 API Gateway 超时，并有助于确保对多种查询类型的可扩缩处理。
- **worker 激活**：检索 worker Lambda 函数由 Amazon SQS 消息触发，从中提取检索参数并准备生成嵌入。
- **查询嵌入**：worker Lambda 函数调用 Amazon Bedrock 的 Nova Multimodal Embeddings 模型，为检索查询（文本或上传的文件）生成嵌入向量。
- **向量检索**：worker Lambda 函数在 OpenSearch Service 中使用余弦相似度执行相似度检索，随后把结果更新到 DynamoDB 供前端轮询。

### 工作流集成

上一节描述的两条工作流共享通用的基础设施组件，但用途不同：

- **上传工作流（1–6）**：专注于摄取和处理媒体文件，以构建可检索的向量数据库
- **检索工作流（A–G）**：处理用户查询并从预先构建的向量数据库中取回相关结果
- **共享组件**：两条工作流使用相同的 Amazon Bedrock 模型、OpenSearch Service 索引以及核心 AWS 服务

### 关键技术特性

- **统一向量空间**：所有媒体类型（图片、视频、音频和文本）都被嵌入到同一个维度空间中，实现真正的跨模态检索。
- **异步处理**：统一的异步架构满足 Amazon Nova Multimodal Embedding API 的要求，并通过 Amazon SQS 队列与 worker Lambda 函数确保可扩缩的处理。
- **多模态检索**：支持文本到图片、文本到视频、文本到音频以及文件到文件的相似度检索。
- **可扩缩架构**：无服务器设计会根据需求自动扩缩。
- **状态跟踪**：轮询机制提供异步处理状态与检索结果的更新。

### 跨模态检索实现

系统的核心在于其借助 OpenSearch k 近邻（KNN）检索实现的智能跨模态检索能力，如下代码所示：

```
def search_similar(self, query_vector: List[float], embedding_field: str, 
                  top_k: int = 20, filters: Dict[str, Any] = None) -> List[Dict[str, Any]]:
    """Search for similar vectors using OpenSearch KNN"""
    query = {
        "size": top_k,
        "query": {
            "knn": {
                embedding_field: {
                    "vector": query_vector,
                    "k": top_k
                }
            }
        },
        "_source": [
            "s3_uri", "file_type", "timestamp", "media_type", 
            "segment_index", "start_time", "end_time", "duration"
        ]
    }
    
    # Add filters for media type or other criteria
    if filters:
        query["query"] = {
            "bool": {
                "must": [query["query"]],
                "filter": [{"terms": {k: v}} for k, v in filters.items()]
            }
        }
    
    response = self.client.search(index=self.index, body=query)
    
    # Process and return results with metadata
    results = []
    for hit in response['hits']['hits']:
        source = hit['_source']
        results.append({
            'score': hit['_score'],
            's3_uri': source['s3_uri'],
            'file_type': source['file_type'],
            'media_type': source.get('media_type', 'unknown'),
            'segment_info': {
                'segment_index': source.get('segment_index'),
                'start_time': source.get('start_time'),
                'end_time': source.get('end_time')
            }
        })
    
    return results
```

## 真实应用与性能

以游戏行业的一个用例为例，我们来考察这样一个场景：一位创意专业人员需要为一次新投放找出展示 `characters celebrating victory with bright visual effects` 的视频片段。

传统做法需要：

- 对数以千计的视频手动打标签，既耗费人力又可能不一致
- 会漏掉语义细微之处的基于关键词的检索
- 对实时查询而言过慢且过贵的基于 LLM 的分析

借助 Nova Multimodal Embeddings，同样的查询变成一次直接的文本检索，它会：

- 生成查询的语义嵌入
- 在统一向量空间中检索所有视频片段
- 返回基于语义相似度的排序结果
- 为相关视频片段提供精确时间戳

### 性能指标与验证

基于与游戏行业合作伙伴使用包含 170 个素材（130 个视频和 40 张图片）的素材库开展的全面测试，Nova Multimodal Embeddings 在 30 个测试用例中表现出色：

- **召回成功率**：96.7% 的测试用例成功取回到目标内容
- **高精度召回**：73.3% 的测试用例把目标内容返回在前两条结果中
- **跨模态准确率**：相比传统方法，在文本到视频检索中具有更高的准确率

### 关键发现

以下是我们从测试结果中得到的发现：

- **分段策略**：对于广告创意工作流，我们推荐使用 `SEGMENTED_EMBEDDING` 并采用 5 秒视频片段，因为它契合典型的生产需求。创意团队通常需要把原始广告素材分段以便管理，并在生产工作流中取回特定片段，这使 Nova Multimodal Embeddings 的分段功能在这些用例中尤其有价值。
- **评估框架**：要评估 Nova Multimodal Embeddings 在你的用例中的效果，请重点测试以下核心能力：
- **物体与实体识别**：使用 `red sports car` 或 `character with sword` 之类的查询，评估跨模态的物体识别能力
- 场景与上下文理解：评估 `outdoor celebration scene` 或 `indoor meeting environment` 之类的上下文检索
- **活动与动作**：验证 `running character` 或 `clicking interface elements` 之类的基于动作的查询
- **视觉属性**：测试针对具体属性的检索，包括颜色、风格与视觉特征
- **抽象语义**：用 `victory celebration` 或 `tense atmosphere` 之类的查询评估概念理解能力
- **测试方法**：从你的内容库构建一个有代表性的测试数据集，创建契合真实用户需求的多样化查询类型，并同时衡量召回成功率（能否找到相关内容）与精确率（排序质量）。重点关注能反映你团队实际检索模式的查询，而非通用测试用例。
- **多语言表现**：Nova Multimodal Embeddings 展现出强大的跨语言能力，在中文查询上表现尤为突出，得分为 78.2，而英文查询为 89.3（3072 维）。这意味着语言差距仅为 11.1，明显优于另一个在不同语言之间性能大幅下降的领先多模态模型。

## 可扩缩性与成本优势

该无服务器架构在优化成本的同时提供自动扩缩。在设计你的多模态素材发现系统时，请留意以下维度性能细节与成本优化策略。

**维度性能：**

- **3072 维**：准确率最高（英文 89.3、中文 78.2），存储成本也更高
- **1024 维**：性能均衡（英文 85.7、中文 68.3），推荐用于大多数用例
- **384/256 维**：面向大规模部署的成本优化选项

**成本优化策略：**

- 根据准确率需求与存储成本的权衡选择维度
- 对大型文件使用异步处理，以避免超时带来的成本
- 使用预计算的嵌入，减少反复发生的 LLM 推理成本
- 采用按需付费的无服务器架构，以降低低使用量时期的成本

```
def search_by_image(self, image_s3_uri: str) -> Dict:
    """Find similar content using image as query"""
    query_embedding = self.nova_service.get_image_embedding(image_s3_uri)
    
    # Search across all media types using visual similarity
    return self.opensearch_manager.search_similar(
        query_embedding=query_embedding,
        embedding_field='visual_embedding',
        size=10
    )
```
