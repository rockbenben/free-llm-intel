# 宣布 Amazon Bedrock Knowledge Bases GraphRAG 搭配 Amazon Neptune Analytics 正式可用

今天，Amazon Web Services（AWS）宣布 Amazon Bedrock Knowledge Bases GraphRAG（GraphRAG）正式可用。这是 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 中的一项能力，用 [Amazon Neptune Analytics](https://docs.aws.amazon.com/neptune-analytics/latest/userguide/what-is-neptune-analytics.html) 中的图数据增强检索增强生成（RAG）。该能力会自动为语义搜索创建 embedding，并生成从已摄取文档中抽取的实体与关系图，从而增强生成式 AI 应用的响应。这张图存储在 Amazon Neptune Analytics 中，在检索阶段提供更丰富的上下文，交付更全面、更相关、更可解释且贴合客户需求的响应。开发者只需在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 控制台上点几下就能启用 GraphRAG，无需任何图建模专业知识即可提升生成式 AI 应用的准确度。

本文讨论 GraphRAG 的益处，以及在 Amazon Bedrock Knowledge Bases 中如何上手使用它。

## 用图为 RAG 增强，构建更全面、更可解释的生成式 AI 应用

生成式 AI 通过能给出有帮助、细致且富有洞见的响应的自然对话，正在改变人与技术的交互方式。然而，当前生成式 AI 系统面临的一个关键挑战是：由于数据分散存放在多份文档中，要给出全面、相关且可解释的响应并不容易。如果不能有效地把输入数据源之间共享的上下文映射起来，响应就可能不完整、不准确。

为解决这一问题，AWS 在 re:Invent 2024 上宣布了 GraphRAG 的公开预览，如今宣布其正式可用。这一新能力把图数据建模的能力与先进的自然语言处理（NLP）结合起来。GraphRAG 会自动创建图，捕捉相关实体与跨文档各章节之间的连接。更具体地说，所创建的图会把块与文档、实体与块连接起来。

在生成响应时，GraphRAG 先做语义搜索，找出最相关的前 k 个块，然后遍历这些块的邻近邻域以检索最相关的内容。通过把这份上下文信息连接起来，生成式 AI 系统可以给出更完整、更精确、且以源数据为依据的响应。无论是回答跨主题的复杂问题，还是总结冗长报告的关键细节，GraphRAG 都能交付所需的全面且可解释的响应，从而实现更有帮助、更可靠的 AI 对话。

当相关信息分散在多个来源或文档中时，GraphRAG 能提升相关性与准确度，这从下面三个用例中可以看出。

### 精简市场研究，加速业务决策

一家领先的全球金融机构希望加强从其专有研究中提取洞见的能力。该机构拥有庞大的经济与市场研究报告库，想探索 GraphRAG 能否改善复杂金融查询的信息检索与推理。为做评估，他们加入了自家专有研究论文，重点覆盖关键市场趋势与经济预测。

为评估 GraphRAG 的效果，该机构与 AWS 合作，使用 Amazon Bedrock Knowledge Bases 与 Amazon Neptune Analytics 构建了概念验证。目标是判断 GraphRAG 相比传统检索方法能否更有效地呈现洞见。GraphRAG 把知识组织成相互连接的实体与关系，从而实现跨文档的多跳推理。这一能力对于回答诸如*“未来几年资本支出增长有哪些逆风与顺风？”*或*“ILA 罢工对国际贸易有何影响？”*这类复杂问题至关重要。GraphRAG 不是仅依赖关键词匹配，而是让模型追踪经济指标、政策变化与行业影响之间的关系，确保响应上下文丰富且有数据支撑。

在比较 GraphRAG 与其他检索方法的响应质量时，在全面性、清晰度与相关性上出现了明显差异。其他检索方法给出的是直白的响应，往往缺少更深的洞见与更宽的上下文。而 GraphRAG 通过纳入相关因素、提供额外的相关信息，给出更细致的答案，使响应比其他检索方法更全面。

### 改善汽车制造中的数据驱动决策

一家国际汽车公司管理着一个大型数据集，支撑工程、制造与客户服务领域的数千个用例。每天有数千名用户查询不同的数据集，确保洞见准确且跨来源连通一直是个持久的挑战。

为解决这一问题，该公司与 AWS 合作，原型化了一张图，映射车辆性能、供应链物流与客户反馈等关键数据点之间的关系。这种结构能在各数据集之间给出更精确的结果，而不是依赖彼此割裂的查询结果。

由于 Amazon Bedrock Knowledge Bases GraphRAG 搭配 Amazon Neptune Analytics 会自动从已摄取文档构建图，该公司可以在其 RAG 应用中更高效地呈现相关洞见。这种做法帮助各团队识别制造质量中的模式、预测维护需求并提升供应链韧性，使数据分析在整个组织内更有效、更可扩展。

### 加强网络安全事件分析

一家网络安全公司正在使用 GraphRAG 来改进其 AI 驱动的助手分析安全事件的方式。传统检测方法依赖孤立告警，常常遗漏攻击的更广上下文。

通过使用图，该公司把登录异常、恶意软件特征码与网络流量模式等互不相干的安全信号连接成威胁活动的结构化表示。这样可以更快做根因分析，并产出更全面的安全报告。

Amazon Bedrock Knowledge Bases 与 Neptune Analytics 使该系统在保持严格安全控制的同时可扩展，并实现资源隔离。借助这种做法，该公司的安全团队可以快速解读威胁、确定响应优先级并减少误报，从而更高效地处理事件。

## 解决方案概述

本文提供一份演练，教你用 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）存储桶中的文件构建 Amazon Bedrock Knowledge Bases GraphRAG 搭配 Amazon Neptune Analytics。运行此示例会在 Amazon Neptune Analytics、Amazon S3 与 Amazon Bedrock 上产生费用。本示例的 Amazon Neptune Analytics 费用约为每小时 $0.48。Amazon S3 费用随数据集大小而变，更多 Amazon S3 定价细节见[此处](https://aws.amazon.com/s3/pricing/)。Amazon Bedrock 费用随你所选的 embedding 模型与切块策略而变，Bedrock 定价的更多细节见[此处](https://aws.amazon.com/bedrock/pricing/)。

## 先决条件

要跟随本文操作，你需要一个具备访问 Amazon Bedrock 所需权限的 AWS 账户，以及一个存放数据、用作知识库的 Amazon S3 存储桶。还要确认你已启用对 Claude 3 Haiku（anthropic.claude-3-haiku-20240307-v1:0）以及你希望用作 embedding 模型的任何其他模型的模型访问权限。关于如何启用模型访问的更多细节，请参阅[此处](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access-modify.html)的文档。

## 构建 Amazon Bedrock Knowledge Bases GraphRAG 搭配 Amazon Neptune Analytics

要开始使用，请完成以下步骤：

- 在 Amazon Bedrock 控制台的导航窗格中，于 **Builder tools** 下选择 **Knowledge Bases**。
- 在 **Knowledge Bases** 区域中，选择 **Create**，然后选择 **Knowledge Base with vector store**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-18468-img1-1024x877.png)
- 在 **Knowledge Base details** 中输入名称与可选描述。
- 在 **IAM permissions** 中选择 **Create and use a new service role**，以创建新的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-18468-img2-1024x926.png)
- 在 **Data source details** 中选择 **Amazon S3 ** 作为数据源。
- 选择 **Next**。
- 在 **S3 URI** 中选择 **Browse S3**，并选择相应的 S3 存储桶。
- 在 **Parsing strategy** 中选择 **Amazon Bedrock default parser**。
- 在 **Chunking strategy** 中选择 **Default chunking **（GraphRAG 推荐），或按你的意愿选择任何其他策略。
- 选择 **Next**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-18468-img3-1024x926.png)
- 在 **Embeddings model** 中选择一个 embedding 模型，例如 [Amazon Titan Text Embeddings v2](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-embedding-models.html)。
- 在 **Vector database** 中选择 **Quick create a new vector store**，然后选择 **Amazon Neptune Analytics (GraphRAG)**。
- 选择 **Next**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-18468-img4-1024x771.png)
- 查看配置详情，然后选择 **Create Knowledge Base**。

## 同步数据源

- 知识库创建完成后，在 **Data source** 区域点击 **Sync **。数据同步可能需要几分钟到几小时，取决于你拥有的源文档数量以及每份文档的大小。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-18468-img5-1024x318.png)

## 测试知识库

数据同步完成后：

- 选择展开图标，展开测试区域的完整视图。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-18468-img6-1024x515.png)
- 通过添加[过滤器](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-content-filters.html)或[护栏](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails.html)来配置你的知识库。
- 我们建议你启用[重排序](https://docs.aws.amazon.com/bedrock/latest/userguide/rerank.html)（关于重排序模型的定价信息，见 [Amazon Bedrock Pricing](https://aws.amazon.com/bedrock/pricing/)），以充分利用 GraphRAG 的能力。重排序让 GraphRAG 能够细化和优化搜索结果。
- 你也可以为知识库中的每份文档提供[自定义元数据文件](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-metadata.html)（每份最大 10 KB）。你可以对检索施加过滤器，指示向量存储先基于文档元数据做预过滤，再搜索相关文档。这样你就能控制检索到的文档，尤其是在查询含义不明时。请注意不支持 `list` 类型。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-18468-img7-1024x722.png)
- 使用右侧窗格中的对话区域，就你 Amazon S3 存储桶中的文档提问。

响应将使用 GraphRAG，并在回答中提供对块与文档的引用。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/06/ML-18468-img8-1024x729.png)

既然你已启用 GraphRAG，就来测试一下：查询你的生成式 AI 应用，观察响应相比基线 RAG 方法有何改善。你可以查看 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 日志，了解索引、查询延迟与准确度的性能指标。

## 清理

探索完该方案后，请务必通过删除你创建的所有资源来清理。需要清理的资源包括 [Amazon Bedrock 知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-delete.html)、该知识库使用的关联 [AWS IAM 角色](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_manage_delete.html)，以及用于存放源文档的 [Amazon S3 存储桶](https://docs.aws.amazon.com/AmazonS3/latest/userguide/delete-bucket.html)。

你还需要单独删除由 Amazon Bedrock Knowledge Bases 代你创建的 [Amazon Neptune Analytics 图](https://docs.aws.amazon.com/neptune-analytics/latest/userguide/managing-deleting.html)。

## 结语

本文讨论了如何上手 Amazon Bedrock Knowledge Bases GraphRAG 搭配 Amazon Neptune。若想进一步实验，可以看看 Amazon Bedrock Knowledge Bases 的[检索 API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_RetrieveAndGenerate.html)，在你自己的应用中发挥 GraphRAG 的能力。代码示例与最佳实践请参阅我们的[文档](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-build-graphs.html)。
