# 使用 Amazon Nova Act headless 模式实施自动化冒烟测试

使用 [Amazon Nova Act](https://nova.amazon.com/act) headless 模式进行自动化冒烟测试，可帮助开发团队在持续集成与持续交付（CI/CD）流水线中验证核心功能。开发团队常常每天多次部署代码，因此快速测试有助于保持应用质量。传统的端到端测试可能需要数小时才能完成，从而造成 CI/CD 流水线的延迟。

冒烟测试是测试的一个子集，用于验证应用最关键的功能在部署后能正常工作。这些测试聚焦用户登录、核心导航和关键交易等关键工作流，而不是穷尽式的功能覆盖。冒烟测试通常几分钟而非几小时就能完成，因此非常适合对代码变更快速反馈至关重要的 CI/CD 流水线。

Amazon Nova Act 使用 AI 驱动的 UI 理解和自然语言处理与 Web 应用交互，取代传统的 CSS 选择器。你无需维护脆弱的 CSS 选择器和复杂的测试脚本，而是可以用简单的英文命令编写测试，这些命令能适应 UI 变化。

本文展示如何在 CI/CD 流水线中使用 Amazon Nova Act headless 模式实施自动化冒烟测试。我们使用示例电商应用 [SauceDemo](https://www.saucedemo.com/) 作为演示目标。我们演示如何在 CI/CD 环境中为无头浏览器自动化设置 Amazon Nova Act，并创建验证关键用户工作流的冒烟测试。接着展示如何实施并行执行以最大化测试效率、为每次部署配置 GitLab CI/CD 自动执行测试，以及应用可维护、可扩展的测试自动化最佳实践。

- 通过自动化脚本或日历提醒每 90 天轮换一次密钥
- 通过日志监控 API key 的使用，以检测未授权访问

```
import os
from nova_act import NovaAct

SAUCEDEMO_URL = "https://www.saucedemo.com/"

def test_login_flow():
    """Test complete login flow and product page verification"""
    with NovaAct(starting_page=SAUCEDEMO_URL) as nova:
        nova.act("Enter 'standard_user' in the username field")
        nova.act("Enter 'secret_sauce' in the password field")
        nova.act("Click the login button")
        nova.act("Verify Products appear on the page")

def test_ecommerce_workflow():
    """Test complete e-commerce workflow: login → shop → checkout → logout"""
    with NovaAct(starting_page=SAUCEDEMO_URL) as nova:
        # Login
        nova.act("Enter 'standard_user' in the username field")
        nova.act("Enter 'secret_sauce' in the password field")
        nova.act("Click the login button")
        nova.act("Verify Products appear on the page")
        
        # Shopping
        nova.act("Select Sauce Labs Backpack")
        nova.act("Add Sauce Labs Backpack to the cart")
        nova.act("Navigate back to products page")
        nova.act("Select Sauce Labs Onesie")
        nova.act("Add Sauce Labs Onesie to the cart")
        nova.act("Navigate back to products page")
        
        # Cart verification
        nova.act("Click cart and Navigate to the cart page")
        nova.act("Verify 2 items are in the cart")
        
        # Checkout process
        nova.act("Click the Checkout button")
        nova.act("Enter 'John' in the First Name field")
        nova.act("Enter 'Doe' in the Last Name field")
        nova.act("Enter '12345' in the Zip/Postal Code field")
        nova.act("Click the Continue button")
        
        # Order completion
        nova.act("Verify Checkout:Overview page appears")
        nova.act("Click the Finish button")
        nova.act("Verify 'THANK YOU FOR YOUR ORDER' appears on the page")
        
        # Return and logout
        nova.act("Click the Back Home button")
        nova.act("Click the hamburger menu on the left")
        nova.act("Click the Logout link")
        nova.act("Verify the user is on the login page")
def main():
    # Check API key
    if not os.getenv("NOVA_ACT_API_KEY"):
        exit("❌ Set NOVA_ACT_API_KEY environment variable")
    
    print("🚀 Starting Nova Act E-commerce Tests")
    
    tests = [
        ("Login Flow", test_login_flow),
        ("E-commerce Workflow", test_ecommerce_workflow)
    ]
    
    passed = 0
    for test_name, test_func in tests:
        try:
            test_func()
            print(f"✅ {test_name}: PASS")
            passed += 1
        except Exception as e:
            print(f"❌ {test_name}: FAIL - {e}")
    
    print(f"\n📊 Results: {passed}/{len(tests)} tests passed")
    
    if passed == len(tests):
        print("🎉 All tests passed!")
    else:
        exit(1)

if __name__ == "__main__":
    main()
```

### 创建 GitHub Actions 工作流

GitLab CI/CD 是 GitLab 内置的 CI 系统，在代码变更时自动运行流水线。流水线在 YAML 文件中定义，用于指定何时运行测试以及执行哪些步骤。

创建 `.gitlab-ci.yml`：

```
stages:
  - test

smoke-tests:
  stage: test
  image: mcr.microsoft.com/playwright/python:v1.40.0-jammy
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
    - if: $CI_COMMIT_BRANCH == "develop"
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_PIPELINE_SOURCE == "web"
  before_script:
    - pip install uv
    - uv sync
    - uv run playwright install chromium  
  script:
    - uv run python smoke_tests.py
  variables:
    HEADLESS: 'true'
    NOVA_ACT_SKIP_PLAYWRIGHT_INSTALL: 'true'
```

### 配置 GitLab CI/CD 变量

GitLab CI/CD 变量为 API key 等敏感信息提供安全存储。这些值经过加密，仅你的 GitLab CI/CD 流水线可访问。按以下步骤添加变量：

- 在你的项目中依次选择 **Settings**、**CI/CD** 和 **Variables**。
- 选择 **Add variable**。
- 在 key 处输入 `NOVA_ACT_API_KEY`。
- 在 value 处输入你的 Amazon Nova Act API key。
- 选择 **Mask variable** 以在作业日志中隐藏该值。
- 选择 **Add variable**。

## 配置并行执行

在你的 CI/CD 流水线已能成功验证各个测试用例之后，下一项优化聚焦通过并行执行提升性能。并发测试执行通过同时运行多个浏览器实例来减少总测试时间，在保持测试可靠性与隔离性的同时最大化 CI/CD 资源的效率。

### 添加并行执行框架

更新 `smoke_tests.py` 以支持并发测试：

```
import os
from concurrent.futures import ThreadPoolExecutor, as_completed
from nova_act import NovaAct

SAUCEDEMO_URL = "https://www.saucedemo.com/"
headless = os.getenv("HEADLESS", "false").lower() == "true"


def test_login_flow():
    """Test complete login flow and product page verification"""
    
    with NovaAct(starting_page=SAUCEDEMO_URL, headless=headless) as nova:
        nova.act("Enter 'standard_user' in the username field")
        nova.act("Enter 'secret_sauce' in the password field")
        nova.act("Click the login button")
        # nova.act("In case of error, make sure the username and password are correct, if required re-enter the username and password")
        nova.act("Verify Products appear on the page")

def test_ecommerce_workflow():
    """Test complete e-commerce workflow: login → shop → checkout → logout"""    
    with NovaAct(starting_page=SAUCEDEMO_URL, headless=headless) as nova:
        # Login
        nova.act("Enter 'standard_user' in the username field")
        nova.act("Enter 'secret_sauce' in the password field")
        nova.act("Click the login button")
        nova.act("Verify Products appear on the page")
        
        # Shopping
        nova.act("Select Sauce Labs Backpack")
        nova.act("Add Sauce Labs Backpack to the cart")
        nova.act("Navigate back to products page")
        nova.act("Select Sauce Labs Onesie")
        nova.act("Add Sauce Labs Onesie to the cart")
        nova.act("Navigate back to products page")
        
        # Cart verification
        nova.act("Click cart and Navigate to the cart page")
        nova.act("Verify 2 items are in the cart")
        
        # Checkout process
        nova.act("Click the Checkout button")
        nova.act("Enter 'John' in the First Name field")
        nova.act("Enter 'Doe' in the Last Name field")
        nova.act("Enter '12345' in the Zip/Postal Code field")
        nova.act("Click the Continue button")
        
        # Order completion
        nova.act("Verify Checkout:Overview page appears")
        nova.act("Click the Finish button")
        nova.act("Verify 'THANK YOU FOR YOUR ORDER' appears on the page")
        
        # Return and logout
        nova.act("Click the Back Home button")
        nova.act("Click the hamburger menu on the left")
        nova.act("Click the Logout link")
        nova.act("Verify the user is on the login page")

def run_test(test_name, test_func):
    """Execute a single test and return result"""
    try:
        test_func()
        print(f"✅ {test_name}: PASS")
        return True
    except Exception as e:
        print(f"❌ {test_name}: FAIL - {e}")
        return False

def main():
    # Check API key
    if not os.getenv("NOVA_ACT_API_KEY"):
        exit("❌ Set NOVA_ACT_API_KEY environment variable")
    
    print("🚀 Starting Nova Act Tests (Parallel)")
    
    tests = [
        ("Login Flow", test_login_flow),
        ("E-commerce Workflow", test_ecommerce_workflow)
    ]
    
    # Configure parallel execution
    max_workers = int(os.getenv("MAX_WORKERS", "2"))
    
    # Run tests in parallel
    results = []
    with ThreadPoolExecutor(max_workers=max_workers) as executor:
        future_to_test = {
            executor.submit(run_test, name, func): name 
            for name, func in tests
        }
        
        for future in as_completed(future_to_test):
            results.append(future.result())
    
    # Report results
    passed = sum(results)
    total = len(results)
    
    print(f"\n📊 Results: {passed}/{total} tests passed")
    
    if passed == total:
        print("🎉 All tests passed!")
    else:
        exit(1)

if __name__ == "__main__":
    main()
```

### 为并行执行更新 GitLab CI/CD

并行执行已经在你的 `.gitlab-ci.yml` 中通过 `MAX_WORKERS= "2"` 变量配置好了。运行冒烟测试时，流水线会自动使用该并行框架。

### 理解并行执行

`ThreadPoolExecutor` 是一个管理工作线程池的 Python 类，允许多个任务同时运行。在这里，每个线程运行一个独立的浏览器测试，从而减少总执行时间。

```
# Configure worker count
max_workers = int(os.getenv("MAX_WORKERS", "2"))

# Execute tests concurrently
with ThreadPoolExecutor(max_workers=max_workers) as executor:
    future_to_test = {
        executor.submit(run_test, name, func): name 
        for name, func in tests
    }
```

并行执行带来多项好处：更快的执行（因为测试同时运行而非顺序运行）、可根据系统资源调整的可配置工作线程数、优化 CI/CD 计算时间的资源效率，以及让新增更多测试而不增加总运行时间变得简单的可扩展性。

不过，有几项重要考量需要注意。每个测试都会打开一个浏览器实例（这会增加资源占用），测试之间必须相互独立以保持适当隔离，并且你必须在 CI 环境中权衡工作线程数与可用的 CPU 和内存限制。

每个并行测试都会消耗系统资源并产生 API 用量。先从两个工作线程开始，再根据你的环境容量和成本要求调整。监控你的 Amazon Nova Act 用量，以优化测试速度与费用之间的平衡。

比较顺序执行与并行执行，性能提升十分显著。在顺序执行中，测试一个接一个运行，总时间为所有单个测试时长之和。采用并行执行时，多个测试同时运行，大约以最长测试的时长完成，从而节省大量时间；随着测试套件增长，这种收益会更有价值。

你的冒烟测试现在具备并发执行能力，在保持完整测试隔离与可靠性的同时显著减少总测试时间。`ThreadPoolExecutor` 实现允许多个浏览器实例同时运行，把你的顺序测试套件转变为完成速度快得多的并行执行。随着测试套件增长，这种性能提升会越来越有价值，从而使全面验证不会成为部署流水线的瓶颈。

通过 `MAX_WORKERS` 环境变量可配置工作线程数，为根据可用系统资源优化性能提供了灵活性。在 CI/CD 环境中，这让你能在测试执行速度与资源约束之间取得平衡，而本地开发则可用满系统能力以获得更快的反馈循环。该架构保持测试完全独立，确保并行执行不会引入可能损害可靠性的不稳定或跨测试依赖。作为最佳实践，请保持测试独立——每个测试都应无论执行顺序如何、无论其他测试是否同时运行，都能正确工作。

## 最佳实践

在性能优化的测试框架完成后，请考虑以下实践以达到生产就绪：

- 保持测试独立。测试不受执行顺序或同时运行的其他测试影响。
- 添加重试逻辑：把测试函数包在带重试机制的 try-catch 块中，以处理瞬时网络问题。
- 为 GitLab CI/CD 流水线配置合理的超时，并考虑添加定时运行以每日验证生产环境。
- 在日常维护方面，为 Amazon Nova Act API key 制定轮换计划，并监控测试执行时间以及早发现性能回退。随着应用增长，你可以向并行执行框架添加新的测试函数而不影响整体运行时间，使该方案对未来需求具有很高的可扩展性。
