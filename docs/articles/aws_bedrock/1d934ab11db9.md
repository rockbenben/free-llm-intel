# 简化 AI agent 工具交互：通过 MCP 将 API Gateway 连接到 AgentCore Gateway

AgentCore Gateway 现在支持 API Gateway。随着组织探索 agentic 应用的可能性，它们持续面对这样一个挑战：如何以安全且符合企业政策的方式，把企业数据用作大语言模型（LLM）调用请求中的上下文。为帮助标准化并保障这些交互的安全，许多组织采用了 [Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro)（MCP）规范，它定义了 agentic 应用如何安全地连接数据源与工具。

虽然 MCP 对全新用例很有优势，但组织也要应对把既有 API 资产带入 agent 时代的挑战。MCP 当然可以包装现有 API，但这需要额外工作：把请求从 MCP 翻译成 RESTful API、确保安全在整个请求流程中得到维持，并施加生产部署所需的标准可观测性。

[Amazon Bedrock AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 现在支持把 [Amazon API Gateway](https://aws.amazon.com/api-gateway/) 作为目标，把发往 AgentCore Gateway 的 MCP 请求翻译为发往 API Gateway 的 RESTful 请求。你现在可以用 MCP 把新增和既有的 API 端点都暴露给 agentic 应用，并自带安全与可观测性。本文介绍这些新能力，并展示如何实现它们。

## 新特性：AgentCore Gateway 对 API Gateway 的支持

AgentCore Gateway 现在除了[既有的目标类型](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-supported-targets.html)（[Lambda](https://aws.amazon.com/lambda/) 函数、[OpenAPI](https://swagger.io/specification/) schema、[Smithy](https://smithy.io/) 模型与 [MCP](https://modelcontextprotocol.io/docs/getting-started/intro) 服务器）之外，还支持 API Gateway 目标。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/04/ML-20114-image-1.png)

我们的客户已经用 API Gateway 成功构建了广泛的 API 生态，连接了众多应用的后端。随着企业迈向下一代 agentic 应用，自然的演进就是把既有 API 与后端工具暴露给 AI 驱动的系统，让成熟基础设施与现代智能 agent 之间实现无缝集成。

AgentCore Gateway 与 API Gateway 的这项集成简化了 API Gateway 与 AgentCore Gateway 之间的连接。它允许你直接以 API Gateway 为目标，因此你无需把 API Gateway API 导出为 OpenAPI 3 规范，再把它作为 OpenAPI 目标加入 AgentCore Gateway。

借助这项集成，AgentCore Gateway 将新增一种 API_GATEWAY 目标类型，免去手动导出与导入的过程。REST API 拥有者只需几次控制台操作或一条 CLI 命令，就能把 API 添加为 AgentCore Gateway 目标，用 AgentCore Gateway 把既有 REST API 暴露为 MCP 工具。API 使用者随后可以通过 Model Context Protocol（MCP）把 AI agent 与这些 REST API 连接起来，用 AI 集成驱动自己的工作流。你的 agentic 应用现在可以连接新增或既有的 API Gateway API。AgentCore Gateway 与 API Gateway 的这项集成支持 IAM 与 API key 授权。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/04/ML-20114-image-2.png)

AgentCore Gateway 与 API Gateway 都与 [Amazon CloudWatch Logs](https://docs.aws.amazon.com/apigateway/latest/developerguide/set-up-logging.html)、[AWS CloudTrail](https://docs.aws.amazon.com/apigateway/latest/developerguide/cloudtrail.html) 与 [AWS X-Ray](https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-enabling-xray.html) 集成以实现可观测性。使用 AgentCore Gateway 与 API Gateway 之间这项新能力的 agent 开发者，可以利用这些可观测性工具。

## 演练

本文展示如何把一个既有的、位于 API Gateway 上的 REST API 设置为 AgentCore Gateway 的目标。借助这项集成，你可以把既有 REST API 作为暴露在 AgentCore Gateway 中的工具，供 agentic 应用使用。

### 先决条件

本示例需要以下条件：

- 一个 AWS 账户，且在 API Gateway 中已有 REST API。
- 一个 [Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色或用户，具备创建 AgentCore Gateway 与设置 API Gateway 目标的足够权限。

你可以用多种方式创建 gateway 并添加目标：

- [AWS Management Console](https://aws.amazon.com/console/)
- [AWS SDK for Python (Boto3)](https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/bedrock-agentcore-control.html)
- [AWS Command Line Interface](https://docs.aws.amazon.com/cli/latest/reference/bedrock-agentcore-control/create-gateway.html)（AWS CLI）
- [AgentCore starter toolkit](https://aws.github.io/bedrock-agentcore-starter-toolkit/user-guide/gateway/quickstart.html)，用于快速、直接地完成设置

本文使用 Boto3 来设置 AgentCore Gateway 与 API Gateway 之间的集成。若需交互式演练，你可以使用 [GitHub](https://github.com/awslabs/amazon-bedrock-agentcore-samples/tree/main/01-tutorials/02-AgentCore-gateway/11-api-gateway-as-a-target) 上的 Jupyter Notebook 示例。

### 设置入站与出站授权的先决条件。

入站授权对传入的用户请求进行认证。出站授权帮助 AgentCore Gateway 代表已认证的用户安全地连接 gateway 目标（例如 API Gateway）。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/04/ML-20114-image-3.png)

当以 API Gateway 为目标时，AgentCore Gateway 支持以下出站授权类型：

- **无授权（不推荐）**——某些目标类型提供绕过出站授权的选项。我们不推荐这种安全性较低的做法。
- **基于 IAM 的出站授权**——使用 [gateway 服务角色](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-prerequisites-permissions.html#gateway-service-role-permissions)，以 [AWS Signature Version 4（Sig V4）](https://docs.aws.amazon.com/AmazonS3/latest/API/sig-v4-authenticating-requests.html)授权访问 gateway 目标。
- **API key**——使用通过 AgentCore Identity 设置的 API key 来授权访问 API Gateway 目标。使用与 API Gateway 用量计划关联映射而创建的 API key，有助于你监控和控制 API 使用量。更多细节请参阅这份[文档](https://docs.aws.amazon.com/apigateway/latest/developerguide/api-gateway-api-usage-plans.html)。

使用[文档](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_create_for-service.html)中的信任策略[创建 IAM 角色](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-prerequisites-permissions.html#gateway-service-role-permissions)。

- 对于基于 IAM 的出站授权，策略应包含 `execute-api:Invoke` 权限。示例内联策略：

```
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Action": [
                "execute-api:Invoke", 
            ],
            "Resource": " "arn:aws:execute-api:{AWS_Region}:{AWS_Account_ID}:api-id/stage/METHOD_HTTP_VERB/resource-path",
            "Effect": "Allow"
        }
    ]
}
```

- 对于 API key 授权，你可以创建 API key（参见 API Gateway [文档](https://docs.aws.amazon.com/apigateway/latest/developerguide/api-gateway-setup-api-keys.html)），并[把它与你的 API Gateway 用量计划关联](https://docs.aws.amazon.com/apigateway/latest/developerguide/api-gateway-create-usage-plans.html)。然后用 AgentCore Identity [创建一个 API key 凭证提供方](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/resource-providers.html#api-key-management)。

完成后，按 AgentCore Gateway [文档](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-outbound-auth.html#gateway-outbound-auth-api-key)的说明更新策略。

### 创建 AgentCore Gateway

使用 AgentCore starter toolkit 时，你可以用[默认授权配置](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-inbound-auth.html#gateway-inbound-auth-jwt)创建 gateway，通过 [Amazon Cognito](https://aws.amazon.com/cognito/) 实现基于 JWT 的入站授权。

```
import boto3
gateway_client = boto3.client('bedrock-agentcore-control')
auth_config = {
    "customJWTAuthorizer": { 
        "allowedClients": ['<cognito_client_id>'],  # Client MUST match with the ClientId configured in Cognito. Example: 7rfbikfsm51j2fpaggacgng84g
        "discoveryUrl": <cognito_oauth_discovery_url>
    }
}
create_response = gateway_client.create_gateway(
name='sample-ac-gateway',
    	roleArn='<IAM_Role_ARN>', # The IAM Role must have permissions to create/list/get/delete Gateway
    protocolType='MCP',
    protocolConfiguration={
        'mcp': {
            'supportedVersions': ['2025-03-26'],
            'searchType': 'SEMANTIC'
        }
    },
    authorizerType='CUSTOM_JWT',
    authorizerConfiguration=auth_config,
    description='AgentCore Gateway with API Gateway target'
)
print(create_response)
# Retrieve the GatewayID used for GatewayTarget creation
gatewayID = create_response["gatewayId"]
gatewayURL = create_response["gatewayUrl"]
print(gatewayID)
```

这会返回你在创建 gateway 目标时需要用到的 `GATEWAY_ID`。

### 创建 AgentCore Gateway 目标

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/12/04/ML-20114-image-4.png)

### 创建目标配置

要创建 API gateway 目标，你需要在目标配置中指定以下内容：

- **toolFilters**：用于决定 REST API 上的哪些资源将作为工具暴露在 gateway 上。过滤器还支持在 filterPath 中使用通配符。
- **toolOverrides **（可选）：用于允许用户覆盖工具名称与描述。你必须显式指定路径与方法。
- **restApiId**：用于传入 API Gateway ID。

以下是目标配置的几个示例：

**示例 1**

这会把 **GET 与 POST /pets**、**GET /pets/{petId}** 暴露给 gateway，并覆盖它们的工具名称与描述。

```
{
  "mcp": {
    "apiGateway": {
      "restApiId": "<api-id>",
      "stage": "<stage>",
      "apiGatewayToolConfiguration": {
        "toolFilters": [
          {
            "filterPath": "/pets",
            "methods": ["GET","POST"]
          },
          {
            "filterPath": "/pets/{petId}",
            "methods": ["GET"]
          }
        ],
	  "toolOverrides" : [
          {
             "name": "ListPets",
             "path": "/pets",
             "method": "GET",
             "description":"Retrieves all the available Pets."
         },
         {
              "name": "AddPet",
              "path": "/pets",
              "method": "POST",
               "description":"Add a new pet to the available Pets."
          },
          {
             "path": "/pets/{petId}",
             "method": "GET",
             "name": "GetPetById",
             "description": "Retrieve a specific pet by its ID"
         }
         ]	
      }
    }
  }
}
```

**示例 2**

这会暴露 **GET /pets**，同时也会暴露 **GET /pets/{petId}** 或 **/pets** 下的任何内容。由于未指定 **toolOverrides**，它将使用 API Gateway 中的资源描述。

```
{
  "mcp": {
    "apiGateway": {
      "restApiId": "<api-id>",
      "stage": "<stage>",
      "apiGatewayToolConfiguration": {
        "toolFilters": [
          {
            "filterPath": "/pets/*",
            "methods": ["GET"]
          }
        ]
      }
    }
  }
}
```

### 凭证提供方配置

创建目标时，你还需要通过凭证提供方配置来指定目标的出站授权。如上所述，共有三种凭证提供方：

**GATEWAY_IAM_ROLE**

这会使用你在创建 gateway 时指定的 `ROLE_ARN`。按如下方式定义凭证提供方配置：

```
[
    {
        "credentialProviderType": "GATEWAY_IAM_ROLE"
    }
]
```

**API_KEY**

这需要用 AgentCore Identity [创建 API key 凭证提供方](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/identity-add-api-key.html)。

```
[
    {
        "credentialProviderType": "API_KEY",
        "credentialProvider": {
            "apiKeyCredentialProvider": {
                "providerArn": "<provider-arn>",
                "credentialParameterName": "x-api-key", // optional
                "credentialPrefix": "abc",              // optional, prefix is added to the API key when sending it to the target endpoint
                "credentialLocation": "HEADER"          //optional, specifies where in the request the API key should be placed
            }
        }
    }
]
```

**NO_AUTH**

`NO_AUTH` 可以通过在创建 AgentCore Gateway 目标时不指定凭证提供方配置来实现。不推荐这样做。

### 创建 AgentCore Gateway 目标

现在把你的 REST API 配置为 gateway 目标：

```
import boto3
gateway_client = boto3.client('bedrock-agentcore-control')
create_gateway_target_response = gateway_client.create_gateway_target(
    name='api-gateway-target',
    gatewayIdentifier='<gateway_ID>',
    targetConfiguration=[< your_target_configuration>],
    credentialProviderConfigurations=[<your_credential_config>]
)
print(create_gateway_target_response)
gateway_target_id=create_gateway_target_2_response['targetId']
```

### 用 Strands Agent 框架测试 gateway

用 [Strands Agents](https://strandsagents.com/latest/) 框架测试 gateway，列出并调用 MCP 服务器上可用的工具。你也可以使用基于其他 agentic 框架构建的、兼容 MCP 的其他 agent。

```
def create_streamable_http_transport():
    return streamablehttp_client(
        gatewayURL, headers={"Authorization": f"Bearer {<Bearer_Token>}"}
    )
client = MCPClient(create_streamable_http_transport)
with client:
    # Call the listTools
    tools = client.list_tools_sync()
    # Create an Agent with the model and tools
    agent = Agent(model=yourModel, tools=tools)  ## you can replace with any model you like
    # Invoke the agent with the sample prompt. This will only invoke MCP listTools and retrieve the list of tools the LLM has access to. The below does not actually call any tool.
    agent("Hi, can you list all tools available to you")
    # Tool calling
    agent("List all the available pets")
    agent("Tell me about the pet with petId 3 ")
    agent("When my order will be delivered? My order id is 2")
```
