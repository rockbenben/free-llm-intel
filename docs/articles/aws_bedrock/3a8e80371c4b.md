# Skello 如何在多租户环境中使用 Amazon Bedrock 查询数据并保持逻辑边界

*本文是与 Skello 共同撰写的客座文章。*

[Skello](https://www.skello.co/) 是一款领先的人力资源（HR）软件即服务（SaaS）解决方案，专注于员工排班与劳动力管理。Skello 服务于酒店、零售、医疗健康、建筑与工业等多元行业，提供排班创建、工时追踪与薪资准备等功能。截至 2024 年，Skello 在欧洲拥有约 20,000 家客户与 400,000 名日活用户，并持续创新以满足客户不断演变的需求。

其中一项创新是实现一个 AI 驱动的助手，以提升用户体验与数据可访问性。在本文中，我们说明 Skello 如何用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 为终端用户打造这一 AI 助手，同时在多租户环境中保障客户数据安全。Amazon Bedrock 是一项完全托管的服务，通过单一 API 提供多种高性能基座模型（FM）供选择，并附带一整套能力，帮助你以安全、隐私与负责任的 AI 方式构建生成式 AI 应用。

我们深入探讨用大语言模型（LLM）进行数据查询所面临的挑战，尤其是在一家受[《通用数据保护条例》（GDPR）](https://commission.europa.eu/publications/publications-general-data-protection-regulation-gdpr_en)约束的法国公司的语境下。我们的解决方案展示了如何在强大的 AI 能力与严格的数据保护要求之间取得平衡。

## 多租户数据访问的挑战

随着 Skello 平台成长到服务数千家企业，我们发现了一项关键需求：用户需要更好的方式来访问并理解他们的劳动力数据。我们的许多客户——尤其是担任 HR 与运营角色的人——觉得传统数据库查询工具过于技术化、过于耗时。这促使我们确定了两个关键的改进方向：

- **快速访问非结构化数据** – 用户需要在各类数据中查找特定信息——员工记录、排班数据、考勤日志与绩效指标。当用户提出复杂问题时，例如“上个月所有工时超过 30 小时的兼职员工有哪些”或“零售部门的平均病假时长是多少？”，传统搜索方法往往力不从心。
- **通过图表可视化数据以支持分析** – 尽管我们的平台收集了全面的劳动力数据，用户仍难以把这些原始信息转化为可执行的洞察。他们需要一种直观的方式，无需编写复杂的 SQL 查询或学习专门的商业智能工具，就能创建趋势与模式的视觉呈现。

为应对这些挑战，我们需要一套解决方案，它能够：

- 理解关于复杂劳动力数据的自然语言问题
- 正确解读用户查询中的上下文与意图
- 在遵守数据访问规则的前提下生成合适的数据库查询
- 以用户友好的格式返回结果，包括可视化图表
- 处理用户表达相似问题的不同方式
- 处理关于基于时间的数据与趋势的查询

LLM 成为这项任务的理想解决方案。它们理解自然语言与上下文的能力，加上生成结构化输出的能力，使其非常适合把用户问题转换为精确的数据库查询。然而，在业务关键型应用中实施 LLM 需要审慎考量安全、准确性与性能方面的要求。

## 解决方案概述

用 LLM 从自然语言输入生成结构化查询是一个新兴的探索方向。该过程可以把用户请求转换为有组织的数据结构，进而用来自动查询数据库。

- 通过无服务器架构获得可扩展性
- 借助按需付费的定价实现高性价比处理
- 低延迟性能
- 可使用 Anthropic 的 Claude 3.5 Sonnet 等先进语言模型
- 快速部署能力
- 灵活的集成选项

## 处理复杂查询

对于更复杂的请求，例如“给我过去 3 个月按职位、按周统计的工作工时”，我们的系统会完成以下步骤：

- 提取查询组成部分：  目标指标：工作工时 聚合层级：周、职位 时间范围：3 个月
- 生成时间计算：  使用相对时间表达而非硬编码日期 实施标准化的日期处理模式

## 数据 schema 优化

为了让系统尽可能高效且对用户友好，我们精心组织了数据结构——可以把它想象成给一间大办公室建立一套井然有序的档案系统。

我们创建了标准化的 schema 定义，为存储相似类型的信息建立了一致的方式。例如，与日期相关的字段（入职日期、班次时间、假期时段）都遵循相同的格式。这有助于避免用户在提出“显示上周的所有事件”这类问题时产生混淆。这就好比让办公室里所有日历都使用相同的日期格式，而不是有的用 MM/DD/YY、有的用 DD/MM/YY。

我们的系统采用一致的命名规范，为所有数据字段使用清晰、可预测的名称。我们不用 `emp_typ_cd` 这类技术缩写，而是使用 `employee_type` 这样清晰的术语。这让 AI 在用户提出“显示所有全职员工”这类问题时，能够直接理解其含义。

为优化搜索模式，我们有策略地组织数据，让常见搜索快速高效。这一点尤为重要，因为它直接影响用户体验与系统性能。我们分析使用模式以找出被请求最频繁的信息，并据此设计数据库索引。此外，我们创建了专门的数据视图，对常见的报表请求进行预聚合。这种全面的做法意味着“今天谁在上班？”这类问题几乎可以瞬时得到回答。

我们还通过梳理不同信息之间的关系，建立了清晰的数据关联。例如，我们把员工与所属部门、班次和经理明确连接起来。这有助于回答“显示下周有团队成员休假的所有部门经理”这类复杂问题。

这些优化为用户带来了实实在在的好处：

- 提问时响应更快
- 查询答案更准确
- 指代特定类型数据时混淆更少
- 能够就不同类型信息之间的关系提出更复杂的问题
- 以不同方式提出相似问题时结果一致

例如，无论用户问的是“显示所有人的休假时间”还是“展示所有假期安排”，系统都明白他们在寻找同一类信息。这种可靠性让系统更值得信赖，也让无论技术背景如何的所有人都更容易使用。

## 图表生成与展示

我们系统最强大的功能之一，是能够自动把数据转换为有意义的可视化图表。这包括以下操作：

- **智能标签创建** – 系统理解你的数据含义，并创建清晰易读的标签。例如，如果你问“显示过去 6 个月的员工出勤情况”，横轴会自动标注月份（1 月到 6 月），纵轴以易读的间隔显示出勤数字，标题则清楚说明你正在看的内容：“Employee Attendance Trends.”
- **自动图例创建** – 系统会生成有用的图例，说明图表各部分代表什么。例如，如果你问“比较不同部门的销售额”，不同部门会获得不同颜色，清晰的图例会说明哪种颜色代表哪个部门，并在需要时自动添加“虚线表示上一年”之类的附加信息。
- **选择合适的图表类型** – 系统能聪明地挑选最佳方式展示你的信息。例如，比较不同类别时使用柱状图（“显示各部门的销售额”），展示随时间变化的趋势时使用折线图（“今年出勤情况如何变化？”），展示整体构成时使用饼图（“全职与兼职员工的构成如何？”），呈现复杂模式时使用热力图（“显示一周中每天最忙的时段”）。
- **智能尺寸与刻度调整** – 系统会自动调整图表的尺寸与刻度，使其易于阅读。例如，如果数值范围是 1–100，它可能以 10 为间隔显示；如果你看的是百万级数据，它可能以更易读的方式呈现（1M、2M 等）；图表会自动重设尺寸以清晰呈现模式；重要细节绝不会小到看不清。

这一切都自动完成——你提出问题，系统负责创建清晰、专业可视化的技术细节。例如，下图是针对“过去 7 周我的员工工作了多少小时？”这一问题的示例。

## 安全优先的架构

我们的实现遵循 [OWASP](https://owasp.org/) 最佳实践（具体是 [LLM06](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/)），在安全控制与 LLM 之间保持完全隔离。

通过专门的安全服务，用户认证与授权检查在与 LLM 交互之前完成，用户上下文与权限通过 Amazon Bedrock 的 `SessionParameters` 管理，使安全信息完全处于 LLM 处理之外。

我们的校验层使用 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 来防御 prompt 注入、不当内容以及种族主义、性别歧视或非法内容等禁止话题。

系统架构通过细致的权限矩阵实现严格的基于角色的访问控制，因此用户只能访问其授权范围内的数据。认证方面，我们使用业界标准的 JWT 与 SAML 协议，我们的授权服务对数据访问权限保持细粒度管控。

这种多层方法可防止通过 prompt 操纵或其他 LLM 特定攻击造成的潜在安全绕过。系统在数据库与 API 两个层面自动强制执行数据边界，有效防止不同客户账户之间的数据串扰。例如，部门经理只能访问其团队的数据，这些限制通过数据库分区（compartmentalization）强制执行。

此外，我们全面的审计系统维护所有操作的不可变日志，包括时间戳、用户标识符与所访问的资源，并将其单独存储以保护其完整性。该安全框架在后台无缝运行，在不干扰用户体验或合法工作流的前提下，为敏感信息提供稳固保护。

## 收益

创建数据可视化从未如此容易。即使没有专门技能，你现在也能制作专业水准的图表，有效传达你的洞察。这一精简的流程确保你的可视化始终保持清晰直观，从而让你专注于探索数据问题，而不必把时间花在呈现细节上。

该解决方案通过简单的对话式请求工作，无需技术知识或专门软件。你只需用日常语言描述想要可视化的内容，系统便会解读你的请求并创建合适的可视化。无需学习复杂的软件界面、记住特定命令或理解数据格式要求。底层技术会自动处理数据处理、图表选择与专业排版，把你的口头或书面请求在片刻之间转换为精致的可视化呈现。

你的具体信息需求决定了数据的展示方式，使洞察更具相关性与可执行性。当需要分享发现时，这些可视化会以精致的排版无缝融入你的报告与演示，增强整体信息的效果。这种数据可视化的民主化，让每个人都能讲述有说服力的数据故事。
