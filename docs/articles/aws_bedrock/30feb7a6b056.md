# 在 AWS GovCloud（美国）中使用 Amazon Bedrock 配置 ChatGPT 桌面应用程序

ChatGPT 桌面应用程序现已在 [AWS GovCloud（美国）](https://aws.amazon.com/govcloud-us/) 中的 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上提供，通过两个组件提供对 OpenAI 前沿模型的访问。 Work 完成复杂的多步骤任务并提供可供审查的结果，Codex 是用于开发、测试和审查软件的编码代理。

本演练适用于其安全架构需要模型推理才能使用 AWS GovCloud（美国）身份、终端节点和区域控制的组织。它将 Codex 配置为通过“us-gov-west-1”中的 Amazon Bedrock Mantle 路由模型请求，其中可以使用 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 和现有 AWS GovCloud (US) 网络控制来管理访问。

Codex 是用于人工智能驱动的软件开发的 OpenAI 编码代理。借助 GPT 模型支持推理，Codex 引入了针对复杂、长期的开发人员工作流程进行优化的新型智能。您可以使用 ChatGPT 桌面应用程序、Codex CLI 以及与 Visual Studio Code、JetBrains 和 Xcode 集成的 IDE。模型推理通过 Amazon Bedrock 上的响应 API 进行路由。

对于有数据驻留要求的客户，处理将在您选择的 Amazon Bedrock AWS 区域内进行。您按代币付费，无需席位许可证，也无需按开发者做出承诺。还支持零数据保留 (ZDR)。在此可配置模式下，系统会处理提示和响应，而不会由 AWS 写入持久存储或与模型提供商共享。这有助于您保护敏感信息并满足严格的数据治理、隐私和安全要求。

本文将介绍 ChatGPT 桌面应用程序的受控本地部署，该应用程序将模型推理发送到 AWS GovCloud（美国西部）中的 Amazon Bedrock。该配置使用 API 模式登录、托管设备策略、命名 AWS 配置文件和网络限制。这些限制仅允许访问经批准的 Amazon Bedrock 终端节点，同时禁用其他外部连接和网络支持的功能。结果是机构安全团队可以在批准更广泛的使用之前测试和记录部署。

使用 AWS GovCloud（美国）并遵循本指南本身并不授权您的工作负载。您的组织仍然负责根据其系统安全计划和授权流程检查所选模型、AWS 服务、区域、终端节点、工作站控制、存储库、凭证和数据流。

## 解决方案概述

您可以通过两种方式使用 ChatGPT 桌面应用程序：

- 处理需要规划、研究、归档和最终结果的大型任务。
- 用于技术工作的 Codex，例如编辑代码、运行测试和审查拉取请求。

ChatGPT 桌面应用程序通过桌面应用程序或 CLI 在组织管理的计算机上运行。它使用配置的 AWS 凭证将请求安全地发送到“us-gov-west-1”中的 Amazon Bedrock Mantle 终端节点。由于此设置直接使用 AWS，因此 ChatGPT 工作区规则和用户角色无法控制它。主要的安全控制是计算机的策略以及所使用的 AWS 身份和权限。

## 演练

配置包含三个主要步骤：设置身份验证、设置 ChatGPT 桌面应用程序配置文件，然后启动、初始化和验证部署。

### 先决条件

在使用 AWS GovCloud（美国）设置 ChatGPT 桌面应用程序之前，请确保 ChatGPT 桌面应用程序的[您的版本](https://learn.chatgpt.com/docs/changelog) 支持 AWS GovCloud（美国）中的 Amazon Bedrock。您需要一个经批准的 AWS GovCloud（美国）账户、一个 IAM 身份和经批准的凭证、对经批准的模型、AWS 区域和终端节点的访问权限以及使用它们的权限。您还需要设置“requirements.toml”和“config.toml”文件。

### 第 1 步：设置身份验证

选择已批准的 AWS GovCloud（美国）账户和 IAM 身份或角色，可以访问“us-gov-west-1”中已批准的模型。通过您组织的批准机制获取凭证。本演练使用命名的配置文件“codex-il5”。将凭证、不记名令牌、会话令牌和其他机密保留在 TOML 文件之外。

保护配置文件配置、凭证源、SSO 令牌缓存以及 ChatGPT 桌面应用程序任务写入的任何凭证助手，同时允许批准的身份验证工具维护和刷新凭证。

ChatGPT 桌面应用程序支持两种 Amazon Bedrock 身份验证途径：[Amazon Bedrock API 密钥](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-generate.html) 或 [AWS 开发工具包凭证链](https://docs.aws.amazon.com/sdkref/latest/guide/standardized-credentials.html)。凭证链路径支持通过 AWS IAM Identity Center 的 AWS SSO。

该应用程序首先检查其环境中的“AWS_BEARER_TOKEN_BEDROCK”。对于桌面使用，可以通过 Windows 上的“%USERPROFILE%\.codex\.env”或 Linux 和 macOS 上的“~/.codex/.env”提供此变量。如果存在，承载令牌优先于基于配置文件的身份验证。

如果没有可用的不记名令牌，应用程序将回退到标准 AWS SDK 凭证链。该链可以从“~/.aws/credentials”读取AWS凭证，并从“~/.aws/config”读取相关配置文件设置。在 Windows 上，相应的默认路径为“%USERPROFILE%\.aws\credentials”和“%USERPROFILE%\.aws\config”。该链还支持 SSO 配置文件。对于 SSO，它使用 AWS 配置文件中的配置文件设置和缓存的 SSO 会话来获取临时角色凭证。这些凭证不需要手动存储在 AWS 凭证文件中。请参阅 [OpenAI 的 Bedrock 身份验证文档](https://learn.chatgpt.com/docs/amazon-bedrock) 和 [AWS IAM Identity Center 凭证提供程序文档](https://docs.aws.amazon.com/sdkref/latest/guide/feature-sso-credentials.html)。

### 步骤 2：设置 ChatGPT 桌面应用程序配置文件

您必须创建两个 ChatGPT 桌面应用程序配置文件：“config.toml”和“requirements.toml”。

重要提示：需要在启动应用程序之前设置配置文件。下表显示了文件位置。

| **操作系统** | **用户 `config.toml`** | **管理员`requirements.toml`** |

|窗户| `%USERPROFILE%\.codex\config.toml` | `%ProgramData%\OpenAI\Codex\requirements.toml` |
| Linux | `~/.codex/config.toml` | `/etc/codex/requirements.toml` |
| macOS | `~/.codex/config.toml` | `/etc/codex/requirements.toml` |

从“requirements.toml”文件开始。 `requirements.toml` 是管理员控制的规则文件。它设置用户无法覆盖的安全限制，例如，限制允许 ChatGPT 桌面应用程序使用哪些权限级别、工具或设置。

## 故障排除

**应用程序提示输入 OpenAI 帐户。** 验证“requirements.toml”和“config.toml”是否使用上表中显示的确切位置和文件名，终止所有 ChatGPT 和 Codex 进程，然后重新启动。这些文件必须在应用程序启动之前。

**AWS GovCloud（美国）端点据报告不受支持。** 使用 OpenAI 确认确切的桌面或应用程序服务器版本、端点和型号。仅更改 URL 并不能建立支持。

**使用了错误的 AWS 身份。** 检查有效的凭证来源和命名配置文件。检查 Amazon Bedrock API 密钥是否优先于配置文件。

**缺少能力限制。** 重新启动后检查完整的有效要求。仅 API 登录设置不应用功能策略。

## 回滚和清理

如果验证检查失败，请停止推出。将受影响的设备恢复为之前批准的策略和提供商设置，然后重新启动 ChatGPT 桌面应用程序。撤销任何临时 AWS 凭证或 API 密钥，并确认这些设备无法再连接到 Amazon Bedrock。保留测试记录，并在重试之前清楚地记录失败的原因。
