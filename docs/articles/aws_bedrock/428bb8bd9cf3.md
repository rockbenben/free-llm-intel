# 以生成式 AI 之力为高端审计能力加速：Verisk 打造精密对话式聊天平台以提升客户支持水平的历程

*本文由 Verisk 的 Sajin Jacob、Jerry Chen、Siddarth Mohanram、Luis Barbier、Kristen Chenowith 与 Michelle Stahl 共同撰写。*

[Verisk](https://www.verisk.com/)（Nasdaq: VRSK）是全球保险行业领先的数据分析与技术合作伙伴。凭借先进的分析、软件、研究以及在 20 多个国家的行业专长，Verisk 帮助个人、社区和企业构建韧性。公司致力于在人类监督与透明度之下开展合乎伦理、负责任的 AI 开发。Verisk 正在使用[生成式 AI](https://aws.amazon.com/generative-ai/) 提升保险客户的运营效率与盈利能力，同时坚守其 AI 伦理原则。

Verisk 的 Premium Audit Advisory Service（PAAS®）是为保费审计师与核保人员提供技术信息与培训的领先来源。PAAS 帮助用户对商业意外险业务的风险暴露进行分类，涵盖一般责任险、商业车险和工伤补偿险。PAAS 提供广泛的核心服务，包括 40,000 多份分类指南和 500 多份公告。PAAS 现在还纳入了 PAAS AI——首个专为保费审计开发的商用交互式生成式 AI 聊天工具，它通过回答问题并快速检索、汇总分类指南、公告、费率卡等多份 PAAS 文档，缩短研究时间，并让用户能够做出有依据的决策。

本文将介绍 PAAS 客户支持流程的开发过程，涵盖生成式 AI 的引入、数据、架构以及结果的评估。对话式 AI 助手正在迅速改变面向客户与员工的支持方式。Verisk 采纳了这项技术并开发了自己的 PAAS AI，为 PAAS 平台提供了更强的自助服务能力。

## 契机

Verisk PAAS 平台收录了海量文档——包括分类指南、咨询内容和公告——帮助 Verisk 的客户确定工伤补偿险、一般责任险和商业车险业务适用的规则与分类。当保费审计师需要在这个庞大的文档库中获得准确的答案时，他们面临的挑战是：

- **数量庞大**——文档（咨询、公告等）的数量之大，使人工检索既耗时又低效
- **响应缓慢**——在这个庞大的文档库中查找准确信息可能很慢，妨碍及时决策
- **答复质量不稳定**——人工检索可能得到不相关或不完整的结果，从而导致不确定性和潜在错误

为解决这一问题，Verisk PAAS AI 旨在通过为业务处理提供全天候支持，并对客户查询给出精确、快速的回答，来减轻这一负担。该技术深度集成到 Verisk 全新重构的 PAAS 平台中，利用 Verisk 的全部文档、培训材料和集体专业知识。它采用检索增强生成（RAG）方法，并结合多种 AWS 服务与自研的评估机制，及时回答用户关于 Verisk PAAS 平台能力的大多数问题。

在规模化部署后，PAAS AI 将使 Verisk 的员工能够把更多时间投入到复杂问题、关键项目和创新上，从而提升整体客户体验。在整个开发过程中，Verisk 遇到了一系列需要权衡的考量、关键发现和决策，这些都为任何希望探索生成式 AI 潜力的企业提供了宝贵洞见。

## 方法

在使用大语言模型（LLM）构建交互式 agent 时，两种常见方法是 RAG 与模型微调。二者之间的选择取决于具体用例和可用数据。Verisk PAAS 最初为 PAAS AI 开发了一条 RAG pipeline，并逐步改进该方案。以下是继续采用 RAG 架构对 Verisk 有益的若干原因：

- **动态数据访问**——PAAS 平台不断演进，持续增加新的业务功能和技术能力。Verisk 需要确保其回答基于最新信息。RAG 方法可以访问持续更新的数据，无需频繁重新训练模型即可给出包含最新信息的回答。
- **多数据源**——除数据新鲜度之外，另一个关键方面是能够从多个 PAAS 资源中获取相关上下文。无需为新数据源进行微调即可轻松扩展知识库，使该方案具备良好的适应性。
- **减少幻觉**——与自由生成文本相比，检索降低了幻觉风险，因为回答直接来自所提供的摘录。Verisk 还开发了一个评估工具来提升回答质量。
- **LLM 的语言能力**——虽然可以从企业数据源中检索到恰当的上下文，但语言组织与流畅度仍由底层 LLM 负责。
- **透明度**——Verisk 希望持续提升 PAAS AI 的回答生成能力。RAG 架构在上下文检索过程中提供了所需的透明度，而检索到的上下文最终将用于生成用户回答。这种透明度帮助 Verisk 找出了需要重构文档的地方。
- **数据治理**——由于访问平台的用户多样、数据访问权限各不相同，数据治理与隔离至关重要。Verisk 在 RAG pipeline 中实施了控制措施，依据用户权限限制数据访问，帮助确保回答只传递给获得授权的用户。

尽管 RAG 与微调各有优劣，但鉴于 Verisk 对实时准确性、可解释性和可配置性的需求，RAG 是在 PAAS 平台上构建 PAAS AI 的最佳方法。随着 Verisk PAAS 平台用例的发展，该 pipeline 架构支持迭代式增强。

### Amazon ElastiCache

Verisk 的 PAAS 团队认定 ElastiCache 是存储全部聊天历史的理想方案。这种存储方式可以在对话式聊天中实现无缝集成，并支持在网站上显示最近的对话，从而提供高效、响应迅速的用户体验。

### Amazon Bedrock

在 Amazon Bedrock 中提供的 [Anthropic 的 Claude](https://aws.amazon.com/bedrock/claude/)，在 Verisk 的方案中承担了多种角色：

- **回答生成**——在构建 PAAS AI 时，Verisk 对领先的 LLM 进行了全面评估，用其庞大的数据集测试每个模型的能力。通过 Amazon Bedrock，Verisk 得以便捷地访问多个一流的基座模型（FM），从而能够就关键性能指标进行高效测试与比较。Amazon Bedrock 统一的 API 与稳健的基础设施，为大规模开发、测试和部署 LLM 方案提供了理想平台。经过这番广泛测试，Verisk 发现 Anthropic 的 Claude 模型在各项关键指标上始终表现更优。Anthropic 的 Claude 在 Verisk 复杂的业务领域中展现出更出色的语言理解能力，能够对用户问题给出更贴切的回答。鉴于该模型在 Verisk PAAS 平台各用例中的突出表现，它显然是驱动 PAAS AI 自然语言能力的明确选择。
- **对话摘要**——当用户提出追问时，PAAS AI 能够延续对话线索。为此，Verisk 使用 Claude 对对话进行摘要，以更新来自 ElastiCache 的上下文。完整的对话摘要与新的摘录会作为输入提供给 LLM，用于生成下一次回答。这种对话流程使 PAAS AI 能够回答用户的追问，并开展更自然、更具上下文的对话，让 Verisk PAAS 更接近于拥有一个真正能与用户进行有用往复交流的 AI 助手。
- **关键词提取**——从用户问题和此前的对话中提取关键词，用于构建新的摘要化 prompt，并作为输入传给 Verisk 的知识库检索器以执行向量相似度搜索。

### Amazon OpenSearch Service

OpenSearch 主要用于存储文本 embedding，通过对索引数据的快速访问来促进高效的文档检索。这些 embedding 充当文档的语义表示，使搜索能力超越简单的关键词匹配。这种语义搜索功能增强了系统检索与查询在上下文上相似的相关文档的能力，从而提升数据查询的整体准确性和速度。此外，OpenSearch 还充当相似度搜索的语义缓存，通过降低计算负载、缩短数据检索操作中的响应时间来优化性能。在快速、精确的信息访问至关重要的更大的 PAAS 生态中，这使它成为不可或缺的工具。

### Snowflake in Amazon

在 PAAS AI 生态中集成 Snowflake，有助于提供可扩展的实时数据访问，使 Verisk 能够及时回应客户关切并改进服务。借助 Snowflake 的能力，Verisk 可以执行包括情感分析和预测建模在内的先进分析，从而更好地理解客户需求并提升用户体验。这个持续运行的反馈闭环对于打磨 PAAS AI、确保其始终响应迅速并贴合用户需求至关重要。

## 数据结构化与检索

构建 PAAS AI 知识库的一个关键要素，是恰当地组织数据并有效地查询数据，以给出准确的回答。Verisk 探索了多种技术，既优化内容的组织方式，也优化提取最相关信息的方法：

- **分块**——准备累积问答数据的关键一步，是把数据切分为单个文档，以便建立索引并导入 OpenSearch Service。与其上传包含多页内容的大文件，Verisk 按文档章节和字符长度把数据切分成更小的片段。通过把数据拆分为聚焦于文档某一章节的小型模块化分块，Verisk 可以更轻松地为每个文档建立索引，也更成功地取回正确的上下文。对数据分块还使知识库能够随时间推移简单直接地更新和重建索引。
- **混合查询**——在查询知识库时，Verisk 发现仅使用标准的向量搜索不足以检索到与某个问题相关的全部上下文。因此，他们实现了一种方案，把稀疏的 bm25 搜索与稠密向量搜索结合起来，形成混合搜索方法，取得了好得多的上下文检索效果。
- **数据分离与过滤**——Verisk 遇到的另一个问题是：由于文档数量庞大且某些主题内部内容相互重叠，对于一些询问在多个来源中都出现的特定主题的问题，系统检索到了错误的文档——其中有些在用户问题的语境下并不需要或不合适。因此，他们实施了数据分离，按文档类型拆分文档，并按业务线过滤，以改善应用内的上下文检索。

通过对驱动 PAAS AI 的知识库以及从中提取答案的查询方式都进行充分实验与优化，Verisk 在概念验证阶段就实现了很高的回答准确率，为进一步开发铺平了道路。所探索的技术——混合查询、HTML 章节分块和索引过滤——成为 Verisk 提取高质量上下文方法的核心要素。

## LLM 参数与模型

在 prompt 的结构、长度、temperature、角色设定和上下文方面进行实验，是提升 PAAS AI 由 Claude 驱动的回答质量与准确性的关键。Anthropic 提供的 [prompt 设计指南](https://docs.anthropic.com/claude/docs/prompt-engineering) 非常有帮助。

Verisk 精心设计了 prompt，为 Anthropic 的 Claude 提供清晰的上下文并设定回答用户问题的角色。把 temperature 设为 0，有助于减少 LLM 生成回答的随机性和不确定性。

Verisk 还尝试了不同的模型以提升整体方案的效率。对于更看重延迟、所需推理较少的场景，Anthropic 的 Claude Haiku 是完美的选择。而对于其他场景，例如基于所提供上下文的问答，此时 LLM 能否理解 prompt 中给出的每一个细节更为重要，Anthropic 的 Claude Sonnet 是更好的选择，可以在延迟、性能和成本之间取得平衡。

## 护栏

PAAS AI 项目中的 LLM 护栏既使用了 Amazon Bedrock 提供的 guardrails，也在 prompt 中设置了专门的段落，用来识别无关问题和 prompt 攻击尝试。Amazon Bedrock guardrails 可附加到任何 Amazon Bedrock 模型调用上，并自动检测给定的模型输入和输出是否违反了所设定的语言过滤器（暴力、不当行为、色情等），有助于筛查用户输入。这些专门的 prompt 则进一步通过构建第二道网来提升 LLM 的安全性，借助 LLM 自身的能力捕捉用户的任何不当输入。

这使 Verisk 有信心认为，模型只会围绕保费审计服务这一既定用途作答，不会被威胁行为者滥用。

![PAAS Evaluation API pipeline](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/13/ML-17110_arch_diag_002.png)

在验证了 [Deepeval](https://github.com/confident-ai/deepeval)、[Ragas](https://github.com/explodinggradients/ragas)、[Trulens](https://github.com/truera/trulens) 等多个评估工具之后，Verisk PAAS 团队意识到，将这些工具用于他们的具体用例存在一定的局限。因此，团队决定开发自己的评估 API，如上图所示。

这个自研 API 基于三项主要指标评估回答：

- **回答相关性得分**——该流程使用 LLM 评估所给出的回答是否与客户的 prompt 相关。这有助于确保回答直接针对所提出的问题。
- **上下文相关性得分**——该流程使用 LLM 评估所检索到的上下文是否恰当、是否与问题良好契合。这有助于确保 LLM 拥有恰当且准确的上下文来生成回答。
- **忠实度得分**——该流程使用 LLM 检查回答是基于所检索到的上下文生成的，还是属于幻觉。这对于维护所提供信息的完整性和可靠性至关重要。

这种自研的评估方法有助于确保生成的回答不仅相关、上下文恰当，而且忠实于既定的生成式 AI 知识库，从而把错误信息的风险降到最低。通过引入这些指标，Verisk 提升了 PAAS AI 的稳健性和可靠性，为客户提供准确、可信的回答。

![PAAS AI 平台的反馈闭环](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/13/ML-17110_arch_diag_003.png)

Verisk PAAS 团队实施了如上图所示的全面反馈闭环机制，以支持持续改进并处理可能出现的任何问题。

该反馈闭环围绕以下关键组件构建：

- **客户反馈分析**——团队主动收集并分析客户反馈，以识别潜在的数据问题或生成式 AI 回答中的问题。这种分析有助于精确定位需要改进的具体领域。
- **问题分类**——问题被识别后，会按其性质分类。如果属于数据相关问题，就指派给内部业务团队解决；如果属于应用问题，则自动创建 Jira 工单，交由 PAAS IT 团队处理并修复。
- **QA 测试用例更新**——系统提供选项，可根据收到的反馈更新 QA 测试用例。这有助于确保测试场景始终切题且全面，覆盖各类潜在问题。
- **ground truth 约定**——作为评估 LLM 回答质量基准的 ground truth 约定会被定期审查和更新。这有助于确保评估指标保持准确，并能反映期望的标准。
- **持续评估**——使用更新后的 QA 测试用例和 ground truth 约定对 LLM 回答进行定期评估。这有助于维持高质量的回答，并快速处理任何偏离预期标准的情况。

这一稳健的反馈闭环机制使 Verisk 能够持续打磨 PAAS AI，确保它为客户查询提供精确、相关且上下文恰当的回答。通过整合客户反馈、高效分类问题、更新测试场景并遵循严格的评估规程，Verisk 保持了高标准的服务，并推动其生成式 AI 能力持续改进。

## 业务影响

Verisk 最初把 PAAS AI 推给一家 beta 客户，以展示其真实场景下的性能和影响。以这种方式支持客户，与 Verisk 过去的客户接洽和支持方式形成鲜明对比——过去，Verisk 通常会安排一个团队直接与客户互动。Verisk 的 PAAS AI 彻底改变了领域专家（SME）的工作方式，并且能够以低成本实现规模化，同时仍提供高质量的协助。过去需要数小时人工审阅的工作，现在几分钟就能完成，使每位专家的处理时间惊人地缩短了 96–98%。这种效率的大幅提升不仅精简了运营，也让 Verisk 的专家能够专注于更具战略意义、能为组织带来更大价值的举措。

在分析这些早期使用数据时，Verisk 还发现了其他可以为客户创造商业价值的领域。随着 Verisk 收集更多信息，这些数据将有助于揭示改进结果所需的条件，并为推广到约 15,000 名用户的更大客户群做好准备。

持续的开发将聚焦于扩展这些能力，并根据所收集的问题确定优先级。不过，最令人兴奋的是生成式 AI 在地平线上带来的新可能。Verisk 深知这项技术正在快速进步，并渴望利用各种创新为客户带来更多价值。随着新模型和新技术的出现，Verisk 计划对 PAAS AI 进行调整，以利用最新的能力。尽管 PAAS AI 目前专注于回答用户问题，但这只是起点。Verisk 计划迅速提升其能力，使其能够主动给出建议，并直接在系统本身中配置功能。Verisk PAAS 团队为突破生成式 AI 可能性边界的挑战而备受鼓舞，也乐于去检验这些边界。

## 结语

Verisk 为其 PAAS 平台开发 PAAS AI 的实践，展示了生成式 AI 在客户支持与运营效率方面的变革力量。通过细致的数据采集、组织与检索，以及对 LLM、语义搜索功能和严格评估规程的运用，Verisk 打造了一个稳健的系统，能够对用户问题给出准确、实时的回答。通过在坚持合乎伦理、负责任的 AI 实践的同时持续增强 PAAS AI 的功能，Verisk 将为客户提供更大的价值，让员工能够专注于创新，并为保险行业的客户服务树立新的标杆。
