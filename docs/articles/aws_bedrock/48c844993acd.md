# Trinity：由 agentic AI 驱动的残障学生转衔规划

*本文与 University Startups 的 Marc Steren、Odina Salihbaeva 和 Aashrit Surapaneni 共同撰写；University Startups 是 University Startups、g/d/n/a 与 AWS 之间的合作项目。*

Trinity 是一个对话式 AI 解决方案，帮助残障学生为自己的高等教育后规划（postsecondary planning）负起责任。它由 University Startups 开发，该组织于 2020 年基于一个朴素的信念成立：残障学生理应拥有一条清晰、个性化的前进道路。该组织与美国各地的初中与高中学生合作，把 AI 驱动的转衔规划（transition planning）与面向职业的课程结合起来，帮助年轻人把自身优势转化为真实的未来。

本文探讨 University Startups 如何高效地扩展 Trinity 的历程——随着数十个学区接入，复杂度超出了最初架构的承载能力。

为了让 Trinity 投入生产，University Startups 与 g/d/n/a（gdna.io）合作。后者是一家以生成式 AI 为先的 AWS 合作伙伴，工作在 AWS 原生基础设施与 agentic AI 的交汇处。g/d/n/a 专长于帮助初创企业快速上线、安全扩展与正确构建，业务涵盖 agentic SaaS 交付、生成式 AI 咨询与 CloudOps 优化。

Trinity 专注于构建个别化教育计划（IEP）。IEP 是一份法律强制要求的文件，由学生的家长、教师与专家共同制定，用于支持满足该学生的教育需求。学生不是去填静态的 IEP 表格，而是与 Trinity 对话，探索自己的兴趣、优势与目标，离开时带走一份个性化、符合《残障人士教育法案》（IDEA）的转衔规划。

更多内容请阅读[*University Startups 如何在 Amazon Bedrock 上构建 Trinity*](https://aws.amazon.com/blogs/machine-learning/empowering-students-with-disabilities-university-startups-generative-ai-solution-for-personalized-student-pathways/)。在第一年里，Trinity 触达了美国十几个州的教育工作者与学生。向沙特阿拉伯与科威特的国际扩展正在进行中。

## 扩展 Trinity 面临的挑战

面向残障学生的转衔规划是一个受联邦监管的流程，由《残障人士教育法案》（IDEA）管辖。它涉及跨越高等教育后教育、就业、独立生活与社区参与等各方面的细致目标设定。支持这一流程的 AI 系统需要准确、具备上下文意识、符合法律，并且对能力差异很大的学生都可用。在 Trinity 能够规模化运行之前，必须先解决三个核心挑战。

### 单一模型承载不了整个工作流

早期的原型把学生信息采集、职业探索、合规检查与计划撰写全都放在一个 prompt 里。到了生产环境，检索质量、教学语气与监管要求在同一个上下文窗口中相互竞争。这意味着任何一个领域的失败都可能破坏整个学生会话，导致幻觉或不准确的信息。

### 通用建议不够好

为残障学生推荐大学、职业与培训项目，需要同时按地理位置、残障支持服务、项目费用、教育层次与职业契合度做筛选。没有现成的检索工具能以低延迟可靠地做到这一点。

### 合规与数据保护不容妥协

特殊教育中的学生记录必须按《健康保险便携性与责任法案》（HIPAA）标准以及《家庭教育权利与隐私法案》（FERPA）的残障相关数据保护要求加以保护。随着 Trinity 架构的演进，字段级加密、严格的基于角色的访问控制与自动化数据保留控制必须从第一天起就内建到基础之中。

## 解决方案概览

University Startups 定义了产品设计规范与通用学习设计（UDL）标准。g/d/n/a 在 AWS 上交付了完整的工程构建，从基础设施与 AI 编排到合规控制与教育工作者仪表盘，最终形成一个完全无服务器的架构，可随 University Startups 服务的学区规模扩展。

### 架构概览

该架构展示了一个由 Amazon Bedrock 驱动的多 agent 解决方案，配有工具与数据以提供有针对性的指引，并具备额外的无障碍特性。

图 1：Trinity 在 AWS 上的无服务器多 agent 架构

学生通过一个 Web 客户端访问 Trinity，该客户端经 REST 与 WebSocket 连接 Amazon API Gateway，计算在 AWS Lambda 上无服务器运行。由 Claude 3.5 Sonnet 驱动的 Amazon Bedrock 提供 AI 交互能力，会话状态存放在 Amazon DynamoDB 中。Amazon Polly 为更能受益于音频的学生朗读回答，Amazon Transcribe 把学生的语音输入转换为文本，从而在不改动后端逻辑的前提下实现完整的无障碍体验。身份验证经由 Amazon Cognito 完成，并通过 Canvas LTI 1.3 联邦实现学校单点登录。

整个架构中都有负责任 AI 的措施，包括用于内容过滤与减少幻觉的 Amazon Bedrock Guardrails。关于 Amazon Bedrock 上各 AWS 区域的模型可用性，请参阅 Amazon Bedrock 中的[各 AWS 区域支持的模型](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html)。

### 多 agent 架构

关键的架构决策是从单个大语言模型（LLM）迁移到分层的六 agent 系统。这些 agent 通过与工具和数据集交互来处理专门任务，以提供贴合上下文的建议。

g/d/n/a 设计了一个系统：各具明确职责的专门 agent 在单一编排器下协作：

- Orchestrator Agent：读取学生对话，选择正确路径，为各 agent 排定顺序，并汇总最终输出。
- College Agent：从超过 30,000 条记录的 Knowledge Base 中推荐 4 年制大学与社区学院。
- Employment Agent：从超过 1,000 个职业的 Knowledge Base 中匹配工作与职业路径。
- Training Agent：从超过 5,000 条记录的 Knowledge Base 中推荐职业培训项目与认证。
- Community Agent：为学生补充社交活动与志愿机会，与所选路径无关。
- Independent Living Agent：为学生补充生活技能与日常生活目标。

这一架构带来了领域聚焦、更好的检索依据，以及路径感知的排序。一个专门的汇总步骤把各 agent 的输出组装成一份内部一致的转衔规划，因为所有 agent 都基于同一份共享的学生画像工作，并由贯穿全程的 DynamoDB 会话记录提供支撑。

### 两阶段 pipeline

Trinity 的工作流把推荐与计划生成分开。在第一阶段，学生完成四段式信息采集对话后，Orchestrator 会路由到合适的主 agent，由后者返回五到十个排序后的选项，并已按该学生的上下文筛选。在第二阶段，选择确认后，所有 agent 各自贡献计划中属于自己的部分。Orchestrator 把输出汇总为一份结构化、符合 IDEA 的 IEP 转衔规划，可在五到十秒内导出为排版好的 PDF。实时 WebSocket 层让教育工作者的界面始终保持响应。

### 混合知识检索

g/d/n/a 构建并维护三个专用的 Amazon Bedrock Knowledge Bases，即全托管的检索增强生成（RAG）能力。agent 发出检索并生成的请求，因此答案绑定到真实记录，而不只是模型的参数化知识。检索使用四因子混合评分模型：语义相似度（30%）、关键词匹配（25%）、位置偏好（20%），以及项目属性如残障支持可用性、费用与教育层次（25%）。查询在检索前会做 AI 扩展，相关性低于 25% 阈值的结果会被完全过滤掉。

## 合规内建于设计

g/d/n/a 从一开始就把 Trinity 的合规层构建到基础之中。该系统通过 AWS Key Management Service（AWS KMS）的字段级加密与每年轮换的密钥，帮助保护敏感的学生信息。该加密覆盖个人可识别信息（PII），包括姓名、残障类型、便利措施与学校联系方式。

安全性进一步延伸到遵循最小权限原则的 AWS Identity and Access Management（IAM）策略。每个 Lambda 函数只获得必要的权限。基于角色的访问控制（RBAC）在服务端强制执行数据边界：Super Admin 可访问跨学区的全系统指标，协调员只能看到本学区的数据，学校教职员查看本校的学生信息，学生只能访问自己的会话与计划。

在身份验证方面，g/d/n/a 通过 LTI 1.3 把 Trinity 直接集成到 Canvas 中，而不是创建单独的登录凭证。Canvas 作为身份源，AWS 则通过一个由 Lambda 支撑的自定义 OpenID Connect（OIDC）提供程序、API Gateway 与 Cognito 管理身份验证流程，在学校既有基础设施内营造顺畅的登录体验。

## 成效

在各学区，Trinity 在学生自主性、教育工作者效率与 IEP 合规方面带来了可衡量的提升。

### 学生自主性

通过 Trinity 的体验，学生对自己的未来目标获得了自主性。学生不是被交给一份关于自己的计划，而是在引导式对话中自行形成目标。该对话通过技能矩阵梳理相关支持，并把它们与超过 30,000 个大学选项、超过 1,000 种职业以及超过 5,000 个培训项目连接起来，使这些目标具体且可达。

> “它帮助学生聚焦长期目标与职业方面的可执行步骤。”

— Temieka Brown，P10X

> “Trinity 帮助学生把职业路径可视化。”

— Marna Dale，Plaquemines

### 教育工作者效能

借助 Trinity，教育工作者可以提供更高效的 IEP 规划流程，把时间集中在学生的具体需求上。通过把学生问卷、职业探索与合规文档自动化到一次引导式会话中，Trinity 在十分钟以内交付有意义的学生参与与 IEP 转衔合规，无需分散的资源或人工协调。

> “合规、易用与面向职业的课程——三者兼得，而不是彼此取舍。”

— Mary Ellen，Plaquemines

### 经现场验证

在任何学校上线之前，特殊教育教师与转衔协调员都用真实的 IEP 场景对 Trinity 做了压力测试。他们的反馈印证了核心架构决策：多 agent 设计能为学生提供准确、低延迟的结果。

## 结论

Trinity 是三项能力共同作用的成果：University Startups 在特殊教育转衔规划上的领域专长、g/d/n/a 对多 agent 架构的工程实现，以及 AWS 提供的可扩展性、安全性与托管 agentic AI 服务。

这一合作产出了一个生产级应用：为真实的 IEP 规划而构建，为能力差异很大的学生而设计，并且在架构上能够扩展到新的监管环境而无需重建。Trinity 目前正更深入地拓展 Transition Planning Management 网络，为沙特阿拉伯与科威特启动本地化，并扩展学习管理系统（LMS）连接，让更多学区可以在他们已经在用的工具中访问 Trinity。

*每个学生都理应拥有一条清晰、个性化的前进道路。Trinity 就是让这件事规模化的方式。*
