# Skai 借助 Amazon Bedrock Agents 革新数据访问与分析，显著提升客户洞察

*本文由 Skai 的 Lior Heber 和 Yarden Ron 共同撰写。*

[Skai](https://skai.io/)（前身为 Kenshoo）是一个由 AI 驱动的全渠道广告与分析平台，专为品牌和代理商设计，让他们可以在单一界面中跨搜索、社交、零售媒体市场以及其他“围墙花园”渠道规划、投放、优化和衡量付费媒体。通过整合来自 100 多个发布商和零售网络的数据，Skai 应用实时分析、预测建模和增量测试来提供预算与出价建议，把媒体支出与销售成果关联起来，并减少渠道孤岛，让营销人员在规模化运营中获得全漏斗可见性和更高的广告支出回报率。

Skai 意识到，我们的客户要花数天（有时是数周）手工准备报告，在查询复杂数据集时苦苦挣扎，并且缺乏直观的可视化工具。传统分析平台需要专业技术能力，让许多用户面对未被挖掘的数据潜力而感到无所适从。但通过与 AWS 合作并采用 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) —— 这类 AI 助手能够通过编排对 API 的调用来自主执行复杂的多步骤任务 —— 我们重新定义了可能性。现在，客户可以用自然语言分析数据，在几分钟而不是几天内生成报告，并通过自然语言对话将洞察可视化。

在本文中，我们分享 Skai 如何使用 Amazon Bedrock Agents 改善数据访问与分析，并提升客户洞察。

## 数据分析面临的挑战

在采用 Amazon Bedrock Agents 之前，Skai 的客户通过表格、图表和预定义业务问题来访问数据。希望深入研究数据的广告活动经理团队每周要花大约 1.5 天准备静态报告，而单个用户则难以在大量数据点之间建立关联。诸如“客户应该把时间花在优化哪些广告活动上、以及如何优化”这类关键业务问题，仍然隐藏在非结构化知识和彼此割裂的数据点中。

我们识别出三项系统性挑战：

- **报告生成耗时** – 表格在特定实体层级（如广告活动、广告、产品和关键词）展示扁平数据和分组数据。然而，通过连接这些不同实体并确定相关时间范围来获得全面理解是耗时的。用户必须手动处理原始数据，才能构建完整的叙述。
- **摘要** – 分析提取出的原始数据在理解、识别关键模式、汇总复杂数据集和得出有洞察力的结论方面带来了重大挑战。用户缺乏能够动态探索数据维度的直观工具，阻碍了他们获得整体视图并为明智决策提取关键洞察的能力。
- **建议** – 向理解程度各异的利益相关者呈现数据驱动的建议，需要深入的数据分析、对各方视角的预判，以及清晰且有说服力的沟通，以展示 ROI 并促成明智决策。

## Celeste 如何驱动转型

为应对报告生成耗时、复杂数据难以汇总、以及需要数据驱动建议这几项挑战，Skai 使用 AWS 构建了 Celeste，一个生成式 AI agent。借助 AI agent，用户可以用自然语言提问，agent 会自动从多个来源收集数据，将其综合为带有可执行洞察的连贯叙述，并提供面向数据的建议。

Skai 平台吸纳了海量关于众多零售商和传统搜索引擎上产品搜索的数据。梳理这些数据可能很耗时，但 Celeste 中的能力可以让这类探索性研究变得容易得多。

Skai 的解决方案利用 Amazon Bedrock Agents 打造了一个由 AI 驱动的分析助手，改变了用户与复杂广告数据交互的方式。该系统处理诸如“比较第一季度表现不佳的广告活动中各广告组的成效”这样的自然语言查询，无需数据库专家介入。agent 会自动联接 Skai 来自多个广告发布商的数据集，涵盖 profiles、campaigns、ads、products、keywords 和 search terms。除了简单的数据检索，该助手还会生成全面的洞察和案例研究，同时就广告活动提供可执行的建议，并附上详细的分析方法和可直接呈现给利益相关者的材料。

例如，考虑以下问题：“我正在推出一款新的家庭安防产品，想在 Amazon 上启用 3 个新的 Sponsored Product 广告活动和 2 个新的 Sponsored Brand 广告活动。其他广告活动中已经在投放的哪些高效果关键词及其匹配类型，适合纳入这些新的投放？”

当使用真实的客户数据提出这个问题时，Celeste 迅速给出了回答，找出了品牌词与通用品类词的组合，供该厂商在新品发布时参考。仅通过几个追问，Celeste 就能为这些假设的广告活动给出估算的 CPC、预算和高层级测试计划，并附上可用于减少与现有广告活动不必要 **冲突** 的否定关键词。

这是一个很好的探索性问题示例，它需要摘要分析、趋势与洞察识别，以及建议。Skai 的数据直接支持这类分析，而 Celeste 内的能力让该 agent 具备提供智能建议的智慧。Amazon Bedrock 之所以能实现这一点，是因为它让 Celeste 可以访问强大的基础模型（FM），同时不会让客户面临这样的风险：这些模型的供应商将敏感问题用于直接支持客户之外的目的。Celeste 平均将构建客户案例研究所需的时间减少 75%，把通常需要数周的过程变成只需几分钟。

## 借助 Amazon Bedrock 的托管 AI 加速实现价值

Skai 成功故事中的一个关键因素，是我们有意选择 Amazon Bedrock 作为基础 AI 服务。与需要大量基础设施搭建和模型管理的替代方案不同，Amazon Bedrock 提供了一条从概念到生产的顺畅路径。

这段旅程始于一个简单的问题：在不从零构建 AI 基础设施的前提下，我们如何利用生成式 AI 为客户提供全新且更好的体验？借助 Amazon Bedrock，Skai 可以在数小时内开始试验，并在数天内交付可用的概念验证。团队可以测试多个 FM（Anthropic 的 Claude、Meta 的 Llama 和 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/)），无需管理多套独立环境，并通过 Amazon Bedrock Agents 快速迭代。

一位开发者表示：“我们在一个冲刺内就从白板走到了可运行的原型。用传统方式，我们现在还在配置基础设施。”

借助 Amazon Bedrock Agents，Skai 可以把客户价值和快速迭代放在基础设施复杂性之前。该托管服务将模型部署与扩缩容的 DevOps 开销降到最低，同时免去了对 FM 调优方面专业 ML 能力的需求。这帮助团队专注于数据集成和客户特定的分析模式，在规模化使用经济高效的按需模型的同时，确保客户数据保持私密与安全。借助 Amazon Bedrock Agents，领域专家可以完全专注于最重要的事情：把客户的数据挑战转化为可执行的洞察。

## Amazon Bedrock Agents 的优势

Amazon Bedrock Agents 的引入大幅简化了 Skai 的架构，同时减少了对自定义代码的需求。内置操作组取代了原本需要数周开发时间的数千行自定义集成代码。该平台原生的记忆和会话管理能力意味着团队可以专注于业务逻辑，而不是基础设施层面的问题。声明式 API 定义将集成时间从数周缩短到数小时。此外，集成的代码解释器简化了数学问题的处理，并有助于应对准确性和规模方面的问题。

作为服务众多客户的解决方案提供商，安全与合规是不容妥协的。Amazon Bedrock 通过继承 AWS 全面的合规认证（包括 HIPAA、SOC2 和 ISO27001）满足了这些安全要求。不保留数据用于模型训练的承诺，对保护敏感客户信息至关重要，而其与现有 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）策略和 VPC 配置的无缝集成则简化了部署。

在每一次向客户演示 Celeste 时，最初的询问总是围绕隐私、安全和专有数据的保护。借助 AWS 基础设施，Skai 能够自信地向客户保证其数据不会被用于训练任何模型，这有效地让 Skai 与竞争对手区分开来。得益于按用量付费的模式，Skai 无需在 AI 基础设施上投资即可经济地扩展。团队避免了为 GPU 集群或专用实例做出昂贵的前期承诺，转而利用基于实际使用模式的自动扩缩容。这种方法可以按具体 agent 细化成本归因，让 Skai 能在细粒度层面理解并优化支出。为每项具体任务选择最合适模型的灵活性进一步优化了性能与成本，确保资源与业务需求精准匹配。

## 解决方案概览

下图展示了解决方案架构。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/29/ML-19118-image-1.png)

我们的 Amazon Bedrock Agent 由几个核心组件构成。

首先，一个自定义层包含以下内容：

- **客户体验 UI（CX UI）** – 用户交互以提交问题并查看响应的前端界面
- **Chat Manager** – 编排对话流程、管理会话状态，并处理 UI 与处理层之间的通信
- **Chat Executor** – 接收来自 Chat Manager 的处理后请求，与 Amazon Bedrock Agent 对接，处理判断何时以及如何调用该 agent 的业务逻辑，并管理整体对话工作流和短期记忆

其次，我们结合 Amazon Bedrock 使用了以下内容：

- **Amazon Bedrock Agent** – 一个编排器，接收来自 Chat Executor 的查询，根据查询确定要调用哪些工具，并管理工具调用过程。
- **Anthropic 的 Claude 3.5 Sonnet V2** – 生成自然语言响应的 FM。该模型为 API 生成查询，并处理工具返回的结构化数据。它为用户生成连贯、贴合上下文的回答。

最后，数据层包含以下内容：

- **Tool API** – 一个自定义 API，接收来自 Amazon Bedrock Agent 的工具调用请求并查询客户数据
- **客户数据** – 存放敏感客户信息的数据存储，且与 Amazon Bedrock 保持隔离

该解决方案还包括以下关键安全措施：

- 在 Tool API 与 Amazon Bedrock Agent 之间强制实施数据隔离
- 原始客户数据绝不共享
- Skai 能够维持数据隐私与合规要求

## 克服关键挑战

实施该解决方案带来了一些关键挑战。

首先，早期原型在串联多个 agent 和 API 时出现 90 秒（甚至更长）的响应时间。通过采用自定义编排器和流式传输，我们将中位延迟降低了 30%，如下表所示。

| **方法** | **平均延迟（秒）** | **P90** | **P99** |
| --- | --- | --- | --- |
| 基线 | 136 | 194 | 215 |
| 优化后工作流 | 44 | 102 | 102 |

其次，客户经常分析跨越多年的数据集，超出了 Anthropic Claude 的 50,000 token 窗口。我们的解决方案使用动态会话分块来拆分对话，同时保留关键上下文，并采用基于检索增强生成（RAG）的记忆检索。

最后，我们在规模化场景下实施了以下错误处理措施：

- 使用 WatchDog 配合 [Amazon CloudWatch Logs Insights](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/AnalyzingLogData.html) 进行实时追踪，监控 230 多项 agent 指标
- 重试机制：带有 500 错误“BEDROCK_MODEL_INVOCATION_SERVICE_UNAVAILABLE”的失败 API 调用会自动重试
- [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 监控与告警
