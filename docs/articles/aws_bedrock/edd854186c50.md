# Clario 使用 Amazon Bedrock 简化临床试验软件配置

*本文由 Clario 的 Kim Nguyen 与 Shyam Banuprakash 共同撰写。*

Clario 是 endpoint 数据解决方案的领先提供商，用于系统性地采集、管理与分析特定的预定义结局（endpoint），以评估治疗方案在临床试验行业中的安全性与有效性，为希望把新疗法带给患者的生命科学公司生成高质量的临床证据。自 50 多年前成立以来，Clario 的 endpoint 数据解决方案已支持临床试验超过 30,000 次，并在 100 多个国家获得 700 多项监管批准。

本文建立在我们此前的[文章](https://aws.amazon.com/blogs/machine-learning/clario-enhances-the-quality-of-the-clinical-trial-documentation-process-with-amazon-bedrock/)之上，那篇文章讨论了 Clario 如何开发由 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 驱动的 AI 解决方案来加速临床试验。此后，Clario 进一步增强其 AI 能力，专注于创新解决方案，简化临床试验软件配置与相关制品的生成，同时交付高质量的临床证据。

## 业务挑战

在临床试验中，设计与定制各类软件系统配置，以高效地管理与优化临床试验的不同阶段，至关重要。这些配置的范围从基本的研究设置，到数据采集定制、与其他系统集成等更高级的功能。Clario 使用来自多个来源的数据为临床试验构建特定的软件配置。传统 workflow 需要从各个表单中人工提取所需数据。这些表单包含关于检查、访视、病情与干预的重要信息。此外，该流程还需要纳入与研究相关的信息，例如研究计划、参与标准、申办方、合作方，以及来自多个企业数据提供方的标准化检查方案。

这一流程的人工性质带来了若干挑战：

- **手动提取数据** – 团队成员需人工审阅 PDF 文档以提取结构化数据。
- **转录挑战** – 把数据从源表单人工转移到配置文档的过程存在改进空间，尤其是在减少转录不一致、增强标准化方面。
- **版本控制挑战** – 当研究需要迭代或更新时，在文档与系统之间保持一致变得越来越复杂。
- **信息流割裂** – 数据存在于彼此孤立的孤岛中，包括 PDF、研究详情数据库记录以及其他独立文档。
- **软件构建时间线** – 配置流程直接影响生成所需软件构建的时间线。

对于时间至关重要、准确性不容妥协的临床试验，Clario 已实施严格的质量控制措施，以尽量降低人工流程带来的风险。这些投入虽然可观，却也凸显出一个业务挑战：如何在复杂的研究配置中确保精确性与一致性。

## 解决方案概述

为应对这一业务挑战，Clario 开发了一个由生成式 AI 驱动的解决方案，称为 AWS 上的 Clario Genie AI Service。该解决方案利用大语言模型（LLM）的能力，具体是使用 [Anthropic 的 Claude 3.7 Sonnet](https://aws.amazon.com/bedrock/anthropic/)，运行在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上。整个流程由 [Amazon Elastic Container Service](https://aws.amazon.com/ecs)（Amazon ECS）编排，从而改变了 Clario 处理临床试验软件配置的方式。

Clario 的方法使用基于 Amazon Bedrock 的定制数据解析器，自动把 PDF 传递表单中的信息结构化成经过验证的表格。Genie AI Service 集中来自多个来源的数据，包括传递表单、研究详情、标准化检查方案以及额外的配置参数。交互式审核仪表盘帮助利益相关方核验 AI 提取的信息，并在最终确定验证后的配置之前进行必要的修正。验证完成后，系统会自动生成软件配置规范（SCS）文档，作为软件配置的完整记录。流程的最后一步是由生成式 AI 驱动的 XML 生成，生成的 XML 随后被发布到 Clario 专有的医学影像软件中用于研究构建，从而形成端到端解决方案，大幅减少人工投入，同时提升临床试验软件配置的准确性。

Genie AI Service 的架构由若干相互连接的组件构成，它们以清晰的 workflow 顺序协同工作，如下图所示。

![架构图，展示企业数据中心与 AWS 云服务之间的临床数据 workflow](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/02/image-1-2.png)

该 workflow 包含以下步骤：

- 启动研究并采集数据。
- 使用 Amazon Bedrock 提取数据。
- 审核并验证 AI 生成的输出。
- 生成必要的文档与代码制品。

下面几节我们将更详细地讨论 workflow 的各个步骤。

### 研究启动与数据采集

workflow 从通过多个集成步骤采集关键研究信息开始：

- **研究代码查询** – 用户首先输入唯一标识该临床试验的研究代码。
- **与研究数据库的 API 集成** – 研究查询操作通过调用 API，从研究数据库获取研究计划、参与标准、申办方、合作方等研究详情，为配置奠定基础。
- **传递表单处理** – 用户通过安全的 [AWS Direct Connect](https://aws.amazon.com/directconnect/) 网络，使用 Web UI 把包含检查、访视、病情与干预等研究参数的传递表单上传到 Genie AI Service。
- **数据结构化** – 系统按关键类别组织信息：访视信息（排期、操作）检查规范（方案、要求）研究专用的自定义字段（生命体征、给药信息等）

### 数据提取

该解决方案通过 API 调用，在 Amazon Bedrock 上使用 Anthropic 的 Claude Sonnet 执行以下操作：

- 解析并提取传递表单中的结构化数据
- 识别文档中的关键字段与表格
- 把信息组织成标准化格式
- 应用领域专用规则，正确归类临床试验访视
- 提取并验证人口学字段，同时保持正确的数据类型与格式
- 处理医学影像参数的专用格式规则
- 处理文档特有的适配（例如对体模扫描与受试者扫描采用不同的处理方式）

### 审核与验证

该解决方案提供完整的审核界面，供利益相关方通过以下步骤验证并精修 AI 生成的配置：

- **交互式审核流程** – 审核人员访问 Genie AI Service 界面执行以下操作：检查 AI 生成的输出；按需对数据进行修正或调整；添加评论并高亮所做调整，作为反馈机制；验证配置的准确性
- **数据存储** – 经审核并批准的软件配置会保存到 Clario 的 Genie 数据库，形成集中、权威且可审计的配置数据源

### 文档与代码生成

配置数据验证通过后，该解决方案通过结构化 workflow 自动生成必要的文档与代码制品：

- **SCS 文档创建** – 审核人员访问 Genie AI Service 界面，使用已验证的数据生成 SCS 文档，从而最终确定软件配置。
- **XML 生成 workflow** – SCS 文档定稿后，workflow 完成以下步骤：workflow 从 Genie 数据库获取配置详情。SCSXMLConverter 是 Genie AI Service 的内部微服务，负责处理 SCS 文档与研究配置。该微服务通过 API 调用调用 Anthropic 的 Claude 3.7 Sonnet，生成标准化的 SCS XML 文件。对生成的 XML 执行验证检查，以确保其满足 Clario 临床研究软件在结构与内容上的要求。最终生成的 XML 输出用于软件构建流程，并附有转换过程的详细日志。

## 收益与成果

该解决方案提升了数据提取质量，同时为团队提供精简的仪表盘，加速验证流程。

通过实现一致的提取逻辑并尽量减少人工数据录入，该解决方案降低了潜在的转录错误。此外，内置的验证保障机制现在能在流程早期识别潜在问题，防止问题向下游传导。

该解决方案也改变了团队的协作方式。通过提供集中式审核能力，并让跨职能团队访问同一个解决方案，沟通变得更透明、更高效。标准化后的 workflow 为信息共享与决策建立了更清晰的渠道。

从运营角度看，新方法在各项研究之间具备更强的可扩展性，同时支持研究演进过程中的迭代。这种标准化为把这些能力扩展到组织内其他运营领域奠定了坚实基础。

重要的是，该解决方案通过完整的审计轨迹与可复现的流程，保持了很强的合规性与可审计性。关键成果包括：

- 研究配置的执行时间已缩短，同时整体质量有所提升
- 团队可以把更多精力放在研究设计优化等增值活动上。

## 经验教训

Clario 通过生成式 AI 改造软件配置的历程带来了宝贵的经验，将指导未来的举措。

### 生成式 AI 实施洞察

以下是围绕使用生成式 AI 技术浮现出的关键经验：

- **prompt 工程是基础** – 结合领域知识的 few-shot prompting 至关重要。团队发现，在 prompt 中提供详细示例与明确的业务规则是成功的必要条件。Clario 的 prompt 并非简单指令，而是包含完整的业务逻辑、边界情况处理以及精确的输出格式要求，以引导 AI 理解临床试验配置。
- **prompt 工程需要迭代** – 数据提取的质量在很大程度上取决于精心编写、编码了领域专业知识的 prompt。Clario 团队花费了大量时间，通过多轮迭代与尝试不同方法来精修这些 prompt，以捕获关于访视顺序、人口学要求与字段格式的复杂业务规则。
- **验证 workflow 中的人为监督** – 尽管生成式 AI 大幅加速了提取，但在结构化的验证 workflow 中人工审核仍然必不可少。Genie AI Service 界面专门设计用来突出潜在的不一致，并为审核人员提供便捷的编辑能力，使其高效运用专业经验。

### 集成挑战

系统集成过程中浮现出一些重要挑战：

- **双系统同步** – 最大的挑战之一是核实 SCS 文档中的改动是否在解决方案中得到体现。这种双向集成的优化仍在进行中。
- **系统切换策略** – 从概念验证脚本过渡到完整集成的解决方案功能，需要周密规划以避免中断。

### 流程适配

团队识别出以下成功推动流程变革的关键因素：

- **分阶段实施** – Clario 分批推出该解决方案，先从试点团队开始，由他们验证功能并作为内部倡导者，帮助其他团队从熟悉的以文档为中心的 workflow 过渡到新解决方案。
- **workflow 优化是迭代的** – 最初的 workflow 设计已根据用户反馈与实际使用模式演进。
- **培训需求** – 即使界面直观，恰当的培训仍能确保用户充分利用该解决方案的各项能力。

### 技术考量

实施过程揭示了几项需要考虑的重要技术层面：

- **数据格式的多样性** – 传递表单在不同治疗领域（肿瘤、神经等）之间差异显著，甚至同一领域内不同研究之间也不相同。当 AI 模型遇到此前未见过的表单结构或术语时，这种多样性会带来挑战。Clario 的 prompt 工程需要持续迭代，因为他们会不断在传递表单中发现新的模式与边界情况，形成一条反馈回路：由人类专家指出被漏掉或误解的数据点，再据此改进后续的 prompt。
- **性能优化** – 较大文档的处理时间需要优化，以维持流畅的用户体验。
- **错误处理的健壮性** – 在生成式 AI 处理流程中构建有韧性的错误处理，对生产可靠性至关重要。

### 战略洞察

该项目产出了宝贵的战略经验，将指导未来的举措：

- **从定义清晰的用例开始** – 从软件配置流程入手，为 Clario 提供了具体且高价值的目标，用以展示生成式 AI 的收益。
- **为可扩展性而设计** – 在架构设计时考虑未来扩展，使他们处于有利位置，可以把这些能力扩展到其他领域。
- **衡量具体成果** – 追踪处理时间与错误率等具体指标，有助于量化生成式 AI 投入的回报。

这些经验对于精修当前解决方案、并为组织内未来的生成式 AI 实施提供指引，都极具价值。

## 结论

对 Clario 而言，通过生成式 AI 改造软件配置流程不仅仅是一项技术成就——它反映了公司在临床试验中处理数据与知识工作的根本性转变。通过把 Amazon Bedrock 中可用的 LLM 的模式识别与处理能力，与人类在验证和决策方面的专业经验结合起来，Clario 打造了一个兼具两者优势的混合 workflow，并由 Amazon ECS 编排，实现可靠、可扩展的执行。

该举措的成功表明，AWS 上的生成式 AI 是一种能够带来切实收益的实用工具。通过聚焦痛点明确、定义清晰的具体流程，Clario 实施的由 Amazon Bedrock 驱动的 Genie AI Service 解决方案既创造了即时价值，也为更广泛的转型奠定了基础。

对于正在考虑类似转型的组织，这段经验凸显了从具体用例入手、为人类与 AI 协作而设计、并持续关注可衡量的业务成果的重要性。秉持这些原则，生成式 AI 可以成为组织演进的真正催化剂。
