# 使用 Amazon Nova 对文档信息定位进行基准测试

每天，企业都要处理成千上万份包含关键业务信息的文档。从发票、采购订单到表单与合同，准确定位并提取特定字段，历来是文档处理流水线中最复杂的挑战之一。虽然光学字符识别（OCR）能告诉我们文档里有哪些文本，但要判断特定信息位于何处，一直需要复杂的计算机视觉方案。

这一领域的演进恰好说明了该挑战的复杂性。早期的目标检测方法（如 [YOLO（You Only Look Once）](https://arxiv.org/abs/1506.02640)）把目标检测重新表述为回归问题，实现了实时检测，从而彻底改变了这一领域。[RetinaNet](https://arxiv.org/abs/1708.02002v2) 通过 Focal Loss 解决类别不平衡问题，把这一方向又推进一步；[DETR](https://arxiv.org/abs/2005.12872) 则引入基于 Transformer 的架构，以尽量减少手工设计的组件。然而这些方法有着共同的局限：它们都需要大量训练数据、复杂的模型架构，以及相当的专业能力来实施和维护。

多模态大语言模型（LLM）的出现，代表着文档处理领域的一次范式转变。这些模型把先进的视觉理解与自然语言处理能力结合起来，带来了几项突破性优势：

- 尽量减少专用计算机视觉架构的使用
- 无需监督学习即可具备零样本（zero-shot）能力
- 用自然语言界面来指定定位任务
- 灵活适应不同文档类型

本文演示如何在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 中使用基础模型（FM），具体来说是 [Amazon Nova Pro](https://aws.amazon.com/ai/generative-ai/nova/)，在极大简化实现的同时实现高精度的文档字段定位。我们会展示这些模型如何以最小的前端工作量精确定位并解读文档字段，从而减少处理错误与人工干预。通过在 [FATURA 数据集](https://arxiv.org/abs/2311.11856) 上开展全面的基准测试，我们给出了性能基准与落地的实施指南。

## 理解文档信息定位

文档信息定位超越了传统的文本抽取，它要识别信息在文档内部的精确空间位置。虽然 OCR 告诉我们存在哪些文本，但定位告诉我们特定信息位于何处——对现代文档处理工作流来说，这是一个关键区别。这项能力支撑着从自动化质量检查、敏感数据脱敏，到智能文档比对与校验的一系列关键业务操作。

应对这一挑战的传统做法，依赖基于规则的系统与专用计算机视觉模型的组合。这类方案往往需要大量训练数据、细致的模板匹配，以及持续的维护来应对文档差异。以金融机构为例，它们针对所处理的每一类发票或表单，都需要单独的模型与规则，这让可扩展性成为一大难题。Amazon Bedrock 上具备定位能力的多模态模型从根本上改变了这一范式。这些多模态 LLM 不需要复杂的计算机视觉架构或大量训练数据，通过自然语言交互就能同时理解文档的视觉版式与语义含义。借助具备定位能力的模型，组织可以以显著更低的技术开销、更强的新文档类型适应能力，实现稳健的文档定位。

像 Amazon Bedrock 上提供的这类具备定位能力的多模态模型，从根本上改变了这一范式。这些多模态 LLM 不需要复杂的计算机视觉架构或大量训练数据，通过自然语言交互就能同时理解文档的视觉版式与语义含义。借助具备定位能力的模型，组织可以以显著更低的技术开销、更强的新文档类型适应能力，实现稳健的文档定位。

## 解决方案概览

我们设计了一个简单的定位方案：它以文档图像和文本 prompt 作为输入，经 Amazon Bedrock 上选定的 FM 处理，并用绝对坐标或归一化坐标返回字段位置。该方案实现了两种不同的文档字段定位 prompt 策略：

- **图像尺寸策略（image dimension）** – 基于绝对像素坐标工作，显式提供图像尺寸，并依据文档的实际大小请求边界框位置
- **缩放坐标策略（scaled coordinate）** – 使用归一化的 0–1000 坐标系，在不同文档尺寸与格式之间更为灵活

该方案采用模块化设计，可以通过更新配置而不是改动代码，直接扩展以支持自定义字段 schema。这种灵活性加上 Amazon Bedrock 的可扩展性，使该方案既适合小规模文档处理，也适合企业级部署。在接下来的章节中，我们演示该方案中基于 Amazon Bedrock FM 进行文档字段定位的设置与实现策略。更多细节可参见我们的 [GitHub 仓库](https://github.com/aws-samples/sample-document-information-localization)。

### 初始设置

完成以下设置步骤：

- 配置 Amazon Bedrock runtime 客户端，并设置合适的重试逻辑与超时：

```
import boto3
from botocore.config import Config

# Configure Bedrock client with retry logic
BEDROCK_CONFIG = Config(
    region_name='us-west-2',
    signature_version='v4',
    read_timeout=500,
    retries={
        'max_attempts': 10,
        'mode': 'adaptive'
    }
)

# Initialize Bedrock runtime client
bedrock_runtime = boto3.client("bedrock-runtime", config=BEDROCK_CONFIG)
```

- 定义字段配置，以指定需要在文档中定位哪些元素：

```
# sample config
field_config = {
    "invoice_number": {"type": "string", "required": True},
    "total_amount": {"type": "currency", "required": True},
    "date": {"type": "date", "required": True}
}
```

- 用选定的模型与策略初始化 `BoundingBoxExtractor`：

```
extractor = BoundingBoxExtractor(
    model_id=NOVA_PRO_MODEL_ID,  # or other FMs on Amazon Bedrock
    prompt_template_path="path/to/prompt/template",
    field_config=field_config,
    norm=None  # Set to 1000 for scaled coordinate strategy
)

# Process a document    
bboxes, metadata = extractor.get_bboxes(
    document_image=document_image,
    document_key="invoice_001" # Optional tracking key
)
```

## 实现 prompt 策略

在这个工作流中，我们测试两种 prompt 策略：图像尺寸与缩放坐标。

下面是图像尺寸策略的示例 prompt 模板：

```
"""
Your task is to detect and localize objects in images with high precision.
Analyze each provided image (width = {w} pixels, height = {h} pixels) and return only a JSON object with bounding box data for detected objects.

Output Requirements:
1. Use absolute pixel coordinates based on provided width and height.
2. Ensure high accuracy and tight-fitting bounding boxes.

Detected Object Structure:
- "element": Use one of these labels exactly: {elements}
- "bbox": Array with coordinates [x1, y1, x2, y2] in absolute pixel values.

JSON Structure:
```json
{schema}
```

Provide only the specified JSON format without extra information.
"""
```

The following is a sample prompt template for the scaled coordinate strategy:

```
"""
Your task is to detect and localize objects in images with high precision.
Analyze each provided image and return only a JSON object with bounding box data for detected objects.

Output Requirements:
Use (x1, y1, x2, y2) format for bounding box coordinates, scaled between 0 and 1000.

Detected Object Structure:
- "element": Use one of these labels exactly: {elements}
- "bbox": Array [x1, y1, x2, y2] scaled between 0 and 1000.

JSON Structure:
```json
{schema}
```

Provide only the specified JSON format without extra information.
"""
```

## Benchmarking results

We conducted our benchmarking study using FATURA, a public invoice dataset specifically designed for document understanding tasks. The dataset comprises 10,000 single-page invoices saved as JPEG images, representing 50 distinct layout templates with 200 invoices per template. Each document is annotated with 24 key fields, including invoice numbers, dates, line items, and total amounts. The annotations provide both the text values and precise bounding box coordinates in JSON format, making it ideal for evaluating field localization tasks. The dataset has the following key characteristics:

- Documents: 10,000 invoices (JPEG format)
- Templates: 50 distinct layouts (200 documents each)
- Fields per document: 24 annotated fields
- Annotation format: JSON with bounding boxes and text values
- Field types: Invoice numbers, dates, addresses, line items, amounts, taxes, totals
- Image resolution: Standard A4 size at 300 DPI
- Language: English

- Scaled coordinate:  Method: Uses normalized 0-1000 coordinate system Input: Image bytes, output schema
- Added gridlines:  Method: Enhances image with visual gridlines at fixed intervals Input: Modified image with gridlines bytes, image dimensions, output schema

## 结论

这项基准测试研究展示了多模态 FM 在文档字段定位方面取得的显著进步。通过在 FATURA 数据集上的全面测试，我们证明这些模型只需极少的设置工作就能有效定位并抽取文档字段，从而大幅简化传统的计算机视觉工作流。Amazon Nova Pro 成为企业文档处理的极佳选择，取得 0.8305 的 mAP，并在多样化的文档类型上表现一致。展望未来，我们看到若干值得进一步优化的方向。后续工作可以探索把该方案延伸到 agentic 工作流中，以支持更复杂的文档类型和字段关系。
