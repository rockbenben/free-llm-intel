运行在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的 [Claude Desktop](https://claude.com/docs/third-party/claude-desktop/overview) 提供了强大的 AI 辅助，但没有集成的网络搜索，其回答受限于模型的训练知识截止日期。当你需要最新信息，例如近期文档更新、实时定价或天气更新时，模型无法自行检索。

[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 是一个以任意框架或模型大规模构建、连接并优化智能体的平台。借助 AgentCore 的一项能力 [AgentCore Gateway](https://aws.amazon.com/blogs/machine-learning/introducing-amazon-bedrock-agentcore-gateway-transforming-enterprise-ai-agent-tool-development/)，你可以通过将 Claude Desktop 连接到 [Web Search](https://aws.amazon.com/blogs/machine-learning/introducing-web-search-on-amazon-bedrock-agentcore/) 来弥合这一知识截止差距。Web Search 是一项完全托管、兼容 Model Context Protocol（MCP）的网络搜索能力，其背后是一个覆盖数百亿文档的 Amazon 网页索引。所有查询流量都留在 AWS 基础设施内，无需管理外部 API key，也没有查询离开你的边界。

在 Claude Desktop 中，你可以使用[受管 MCP server](https://claude.com/docs/third-party/claude-desktop/extensions#managed-mcp-servers-admin) 连接一个启用了 Web Search 目标的 AgentCore Gateway。在本文中，我们逐步演示如何设置这一集成，并使用基于 JSON Web Token（JWT）的入站认证来保护通信。

## 架构

许多在 AWS 上运行的企业使用 [AWS IAM Identity Center](https://aws.amazon.com/iam/identity-center/) 来对其 AWS 账户进行单点登录（SSO）访问。在本次演练中，我们把 AWS IAM Identity Center 作为 AgentCore Gateway 的认证源。在这种设置下，运行在 Amazon Bedrock 上的 Claude Desktop 可以通过一个受信任的、企业托管的身份认证流程调用 Web Search。这种方式与组织现有的身份治理保持一致，无需单独的凭证或第三方身份提供方。

要把 AWS IAM Identity Center 与 AgentCore Gateway 基于 JWT 的认证打通，我们使用 [Amazon Cognito](https://aws.amazon.com/pm/cognito/) 作为联邦层，采用 OAuth 2.0 授权码模式（authorization code grant flow）。IAM Identity Center 通过 [Security Assertion Markup Language (SAML)](https://en.wikipedia.org/wiki/SAML) 处理用户认证；Amazon Cognito 签发 JWT；AgentCore Gateway 在每个请求上验证这些 JWT。整条认证链都留在 AWS 内部。

## 前提条件

要跟随本文的步骤，你需要以下内容：

- 一个 AWS 账户，具备创建 [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam/) 角色和 Amazon Bedrock AgentCore 资源的权限。
- 对 AWS Organizations 中管理账户的管理员访问权限（用于 AWS IAM Identity Center 配置）。
- 已为访问 AWS 账户的 SSO 预先配置好的 AWS IAM Identity Center。
- 以 Amazon Bedrock 作为推理提供方设置好的 Claude Desktop。
- 已安装并配置好 AWS Command Line Interface（AWS CLI）v2。
- Python 3.10 或更高版本。
- Boto3 SDK 已更新到最新版本。

Amazon Bedrock AgentCore 上的 Web Search 目前可在美国东部（弗吉尼亚北部）AWS 区域（us-east-1）、欧洲（爱尔兰）区域（eu-west-1）和亚太地区（东京）区域（ap-northeast-1）使用。请确认你的 Gateway 创建在这些区域之一。

## 配置

配置包括建立认证链（AWS IAM Identity Center → Amazon Cognito → JWT），然后把 AgentCore Gateway 接入 Claude Desktop。我们在下一节逐步演示每个步骤。

### 步骤 1：创建 Amazon Cognito 用户池

在你的目标 AWS 账户中，创建一个 Amazon Cognito 用户池，它将作为 AgentCore Gateway 的 OpenID Connect（OIDC）令牌签发方。

```
export AWS_REGION=<your-region>

# Create User Pool
aws cognito-idp create-user-pool \
  --pool-name "agentcore-websearch-pool" \
  --region $AWS_REGION \
  --auto-verified-attributes email \
  --schema '[{"Name":"email","Required":true,"Mutable":true,"AttributeDataType":"String"}]' \
  --username-attributes email \
  --username-configuration "CaseSensitive=false" \
  --mfa-configuration "OFF"

# Note the Pool ID
export USER_POOL_ID=$(aws cognito-idp list-user-pools --max-results 10 \
  --region $AWS_REGION \
  --query "UserPools[?Name=='agentcore-websearch-pool'].Id" --output text)
echo "User Pool ID: $USER_POOL_ID"

# Create a domain (must be globally unique)
aws cognito-idp create-user-pool-domain \
  --domain "<your-unique-prefix>" \
  --user-pool-id $USER_POOL_ID \
  --region $AWS_REGION
```

记下这些值以便后续步骤使用：

- **User Pool ID：** `$USER_POOL_ID`。
- **Domain（域）**：`<your-unique-prefix>.auth.<region>.amazoncognito.com`。
- **Audience（受众）**：`urn:amazon:cognito:sp:<user-pool-id>`。
- **ACS URL：** `https://<your-unique-prefix>.auth.<region>.amazoncognito.com/saml2/idpresponse`。

### 步骤 2：配置 IAM Identity Center 的 SAML 应用

在你的 AWS Organizations 管理账户中，创建一个与 Cognito 联邦的 SAML 应用：

- 打开 IAM Identity Center 控制台。
- 依次选择 **Applications**、**Add application**、**I have an application I want to set up**、**SAML 2.0**，然后 **Next**。
- 填写以下详细信息：**Display name**：AgentCore Web Search。选择 **Manually type your metadata value**。**ACS URL**：`https://<your-unique-prefix>.auth.<region>.amazoncognito.com/saml2/idpresponse`。**Audience**：`urn:amazon:cognito:sp:<user-pool-id>`。下载 SAML metadata XML 文件并选择 **Submit**。应用创建完成后，编辑属性映射并插入以下值：Subject、${user:subject}，Format：Persistent。Email、${user:email}，Format：Basic。分配有权访问 Web Search 的用户或用户组。

### 步骤 3：将 SAML IdP 接入 Cognito

回到目标账户，在你的 Cognito 用户池中把 IAM Identity Center 注册为一个 SAML 身份提供方：

```
# Add IAM Identity Center as SAML IdP
METADATA=$(cat /path/to/downloaded-metadata.xml)

aws cognito-idp create-identity-provider \
  --user-pool-id $USER_POOL_ID \
  --provider-name "IAMIdentityCenterIdP" \
  --provider-type SAML \
  --provider-details "{\"MetadataFile\": $(echo "$METADATA" | python3 -c 'import sys,json; print(json.dumps(sys.stdin.read()))')}" \
  --attribute-mapping '{"email": "email"}' \
  --region $AWS_REGION
```

### 步骤 4：为 Amazon Bedrock AgentCore 创建 Cognito 应用客户端

创建一个带 client secret 的应用客户端。Claude Desktop 使用这个 client 来发起 OAuth 流程，该流程通过 IAM Identity Center 认证用户并为 AgentCore Gateway 获取一个 JWT：

```
aws cognito-idp create-user-pool-client \
  --user-pool-id $USER_POOL_ID \
  --client-name "agentcore-websearch-client" \
  --generate-secret \
  --supported-identity-providers "IAMIdentityCenterIdP" \
  --callback-urls '["http://localhost:53280/callback"]' \
  --allowed-o-auth-flows code \
  --allowed-o-auth-scopes "openid" "email" "profile" \
  --allowed-o-auth-flows-user-pool-client \
  --region $AWS_REGION
```

记下输出中的 **Client ID** 和 **Client Secret**。它们就是你的应用客户端 ID 和密钥。

### 步骤 5：为 AgentCore Gateway 配置 Web Search 工具

在这一步，我们创建一个新的 AgentCore Gateway，其[**Inbound Auth Type**](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-inbound-auth.html#gateway-inbound-auth-jwt) 设为 **JSON Web Tokens (JWT)**。对于该配置，我们使用前面步骤中创建的 Cognito 用户池 ID 和应用客户端 ID。

运行以下 Python 脚本，用所需配置创建 Gateway，并将所有占位符替换为你环境中的实际值。

```
import boto3
import json
import time

session = boto3.Session(region_name="your-region")
iam_client = session.client("iam")
gateway_client = session.client("bedrock-agentcore-control")

ACCOUNT_ID = "your-target-aws-account-id"
ROLE_NAME = "websearch-gateway-role"
GATEWAY_NAME = "websearch-gateway"
COGNITO_DISCOVERY_URL = "https://cognito-idp.<your-region>.amazonaws.com/<user-pool-id>/.well-known/openid-configuration"
COGNITO_CLIENT_ID = "<cognito-application-client-id>"

# --- Step 1: Create IAM execution role ---
trust_policy = {
    "Version": "2012-10-17",
    "Statement": [{
        "Effect": "Allow",
        "Principal": {"Service": "bedrock-agentcore.amazonaws.com"},
        "Action": "sts:AssumeRole",
        "Condition": {
            "StringEquals": {"aws:SourceAccount": ACCOUNT_ID}
        }
    }]
}

permissions_policy = {
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "GetGateway",
            "Effect": "Allow",
            "Action": "bedrock-agentcore:GetGateway",
            "Resource": f"arn:aws:bedrock-agentcore:us-east-1:{ACCOUNT_ID}:gateway/*"
        },
        {
            "Sid": "GetConfigBundle",
            "Effect": "Allow",
            "Action": "bedrock-agentcore:GetConfigurationBundleVersion",
            "Resource": f"arn:aws:bedrock-agentcore:us-east-1:{ACCOUNT_ID}:configuration-bundle/*"
        },
        {
            "Sid": "InvokeWebSearch",
            "Effect": "Allow",
            "Action": "bedrock-agentcore:InvokeWebSearch",
            "Resource": "arn:aws:bedrock-agentcore:us-east-1:aws:tool/web-search.v1"
        }
    ]
}

try:
    iam_client.create_role(
        RoleName=ROLE_NAME,
        AssumeRolePolicyDocument=json.dumps(trust_policy),
        Description="Execution role for web search AgentCore gateway",
    )
    print(f"✓ Role '{ROLE_NAME}' created.")
except iam_client.exceptions.EntityAlreadyExistsException:
    print(f"✓ Role '{ROLE_NAME}' already exists, reusing.")

iam_client.put_role_policy(
    RoleName=ROLE_NAME,
    PolicyName="websearch-gateway-policy",
    PolicyDocument=json.dumps(permissions_policy),
)
print(f"✓ Inline policy attached to '{ROLE_NAME}'.")

# --- Step 2: Create the gateway ---
response = gateway_client.create_gateway(
    name=GATEWAY_NAME,
    description="AgentCore gateway with managed Web Search connector",
    roleArn=f"arn:aws:iam::{ACCOUNT_ID}:role/{ROLE_NAME}",
    protocolType="MCP",
    protocolConfiguration={
        "mcp": {
            "supportedVersions": ["2025-03-26"],
        }
    },
    authorizerType="CUSTOM_JWT",
    authorizerConfiguration={
        "customJWTAuthorizer": {
            "discoveryUrl": COGNITO_DISCOVERY_URL,
            "allowedClients": [COGNITO_CLIENT_ID],
        }
    },
)
gateway_id = response["gatewayId"]
gateway_url = response.get("gatewayUrl")
print(f"✓ Gateway created: {gateway_id}")
print(f" URL: {gateway_url}")

# --- Step 3: Wait for gateway to become READY ---
print(" Waiting for gateway to reach READY status...", end="", flush=True)
for i in range(40):  # up to ~10 minutes
    resp = gateway_client.get_gateway(gatewayIdentifier=gateway_id)
    status = resp.get("status")
    if status == "READY":
        print(f" READY (after {(i+1)*15}s)")
        break
    elif status == "FAILED":
        print(f"\n✗ Gateway entered FAILED status.")
        reasons = resp.get("statusReasons", [])
        for r in reasons:
            print(f" Reason: {r}")
        exit(1)
    print(".", end="", flush=True)
    time.sleep(15)
else:
    print(f"\n✗ Gateway did not reach READY within 10 minutes (last status: {status})")
    exit(1)

# --- Step 4: Attach the managed Web Search connector target ---
gateway_client.create_gateway_target(
    gatewayIdentifier=gateway_id,
    name="web-search-tool",
    description="Managed Web Search connector",
    targetConfiguration={
        "mcp": {
            "connector": {
                "source": {"connectorId": "web-search"},
                "configurations": [{"name": "WebSearch", "parameterValues": {}}],
            }
        }
    },
    credentialProviderConfigurations=[
        {"credentialProviderType": "GATEWAY_IAM_ROLE"}
    ],
)
print("✓ Web search target attached.")
print()
print("=" * 60)
print(f" Gateway ID: {gateway_id}")
print(f" Gateway URL: {gateway_url}")
print(f" Auth: CUSTOM_JWT (Cognito)")
print(f" Target: web-search (managed connector)")
print("=" * 60)
```

现在你拥有了一个带 Web Search 工具、具备基于 JWT 的入站授权的 AgentCore Gateway。

### 步骤 6：配置 Claude Desktop

使用 Claude Desktop 配置文档中的步骤，打开针对 Amazon Bedrock 的 Claude Desktop 配置窗口。打开后，选择 **Connectors and Extensions**，然后选择 **Add server**，再选择 **Blank**。

下面的截图展示了带有这些选项的配置窗口。

图 2：Claude Desktop connector 配置窗口

输入以下详细信息：

- **Name**：websearchtool。
- **Transport**：Streamable HTTP。
- **URL**：输入步骤 5 中创建的 AgentCore Gateway 的 gateway resource URL。
- **OAuth**：Bring your own client。
- **Client ID**：输入步骤 4 中创建的应用客户端的 client ID。
- **Client Secret**：输入步骤 4 中创建的应用客户端的 client secret。
- **Authorization Server**：输入 `["https://<your-unique-prefix>.auth.<region>.amazoncognito.com/oauth2/authorize"]`。
- **Scope**：openid。
- **Callback host**：`localhost`。
- **Callback port**：53280。

完成后，选择 **sign in and test**。这会打开一个浏览器供你认证，并把你重定向到 AWS IAM Identity Center 的 SSO 登录页。输入你的凭证进行认证。若成功，你会看到一条类似“Authorization complete. You can close this tab and return to Claude.”（授权完成。你可以关闭此标签页并返回 Claude。）的消息。

回到 Claude Desktop，你会看到一条类似下图的成功 MCP 注册消息。

图 3：Claude Desktop 中成功的 MCP server 注册

Claude Desktop 现在会通过 MCP 的 tools/list 调用发现 WebSearchTool。每当模型需要来自网络的最新信息时，它会自动调用该工具。

图 4：Web Search 工具执行审批对话框

## 清理

如果你跟随操作时创建了资源，请执行以下步骤删除它们：

```
# Delete the gateway target
aws bedrock-agentcore-control delete-gateway-target --gateway-identifier <gateway-id> --target-id <target-id> --region $AWS_REGION

# Delete the gateway (only if it was created for this walkthrough)
aws bedrock-agentcore-control delete-gateway --gateway-identifier <gateway-id> --region $AWS_REGION

# Delete the IAM policy (only if it was created for this walkthrough)
aws iam delete-role-policy --role-name websearch-gateway-role --policy-name websearch-gateway-policy

# Delete the IAM role (only if it was created for this walkthrough)
aws iam delete-role --role-name websearch-gateway-role

# Delete the Cognito application client
aws cognito-idp delete-user-pool-client --user-pool-id $USER_POOL_ID --client-id <client-id> --region $AWS_REGION

# Delete the Cognito identity provider
aws cognito-idp delete-identity-provider --user-pool-id $USER_POOL_ID --provider-name IAMIdentityCenterIdP --region $AWS_REGION

# Delete the Cognito pool domain
aws cognito-idp delete-user-pool-domain --user-pool-id $USER_POOL_ID --domain <your-unique-prefix> --region $AWS_REGION

# Delete the cognito pool
aws cognito-idp delete-user-pool --user-pool-id $USER_POOL_ID --region $AWS_REGION
```

最后，在管理账户的 IAM Identity Center 控制台中，删除你在步骤 2 创建的 SAML 应用。

## 结论

在本文中，我们演练了将 AgentCore 上的 Web Search 与 Claude Desktop 集成。虽然本次演练以 AWS IAM Identity Center 作为身份提供方，但同样的模式适用于任何兼容 SAML 或 OIDC 的身份提供方。你可以通过在 Amazon Cognito 中把你现有的 IdP 配置为联邦源来替换它。这种方式在不引入第三方依赖的情况下填补了网络搜索的空白，并且所有查询都留在你的 AWS 边界内。

要开始上手，请按照上述步骤在你自己的环境中设置这一集成。有关高级 Gateway 配置，参见 [AgentCore Gateway 开发者指南](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-using.html)。要了解更多关于 Web Search 的信息，参见 [Web Search](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway-target-connector-web-search-tool.html) 文档。
