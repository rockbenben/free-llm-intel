# 使用 torchtitan 在 AWS Trainium 上训练 Qwen3

在 [AWS Trainium](https://aws.amazon.com/ai/machine-learning/trainium/) 上使用 torchtitan 意味着按照您一贯的方式使用它。 TorchNeuron 将 Trainium 注册为原生 PyTorch 设备，这使得 torchtitan 通过标准 PyTorch 接口使用它。您可以使用这些配置从随机初始化进行预训练或微调已发布的权重。您还可以为您的工作负载自定义模型实现和内核。在这篇文章中，您将在单个“trn2.48xlarge”上以三种方式训练 Qwen3。

第一种方法使用 Transformers v5 作为 torchtitan 中的建模后端。它通过“AutoModelForCausalLM”运行 Hub 模型，并直接读取和写入已发布的安全张量。第二种方法通过更改 config.model_spec 切换到 torchtitan 的原生 Qwen3。第三个添加来自 torchtitan-neuron 配方的神经元内核接口 (NKI) 专家混合 (MoE) 内核，然后使用 torchtitan 的覆盖注册表来附加您自己的内核。所有三种配置都使用相同的“torchrun”启动模式和配置结构。

## 先决条件

要完成本演练，请将单个“trn2.48xlarge”与适用于 Neuron 的 AWS Deep Learning AMI 或 Neuron PyTorch 训练容器结合使用。这两种环境都提供在 Trainium 上训练所需的 Neuron 驱动程序、运行时和编译器。

在安装 [torchtitan-neuron](https://github.com/aws-neuron/torchtitan-neuron) 之前，请检查您的环境是否已包含它。以下命令打印已安装的版本和包路径：
```
python3 -c "import torchtitan, torchtitan_neuron; print(torchtitan.__version__, torchtitan_neuron.__file__)"
```
本演练使用下表中的版本。要重现示例，请固定这些版本。 Transformers v5 集成和 Trainium 特定覆盖模块可以在 torchtitan 版本之间发生变化。

| **组件** | **版本** |
| --- | --- |
|实例| trn2.48xlarge、16 个 Trainium2 加速器、128 个物理 NeuronCore |
|逻辑神经元核心 | 64 在 LNC=2 |
|火炬，torch_neuronx | 2.14.0、2.14.3 |
|变压器| 5.16.0 |
|火炬泰坦神经元 |版本 2.33 (0.2.2+neuron.1) |

安装“torch_neuronx”后，TorchNeuron 将 Trainium 注册为“neuron”设备，并且 torchtitan 在启动时检测到它。在 Eager 模式下，Neuron 在执行操作时对其进行编译。使用“torch.compile”，Neuron 编译捕获的图。同样的启动模式适用于所有三种配置。

对于本演练中使用的版本，请使用“--no-deps”安装 torchtitan-neuron 和 torchtitan 的剩余依赖项，以保留 torchtitan 的 Neuron 版本：
```
git clone https://github.com/aws-neuron/torchtitan-neuron
cd torchtitan-neuron
pip install -r requirements.txt
```
在开始训练之前，请从 Hugging Face Hub 获取 Qwen3 模型工件。将它们存储在本地目录中，您可以将其传递给训练配置：
```
hf download Qwen/Qwen3-4B-Instruct-2507 \
  --local-dir "$PWD/assets/hf/Qwen3-4B-Instruct-2507"
```
每个训练配置都是一个 Python 配置函数。这三个示例从您为每个步骤更新的基本配置开始。

## 使用 Hugging Face Transformers v5 进行训练

在第一个配置中，Transformers v5 通过“AutoModelForCausalLM”构建 Qwen3。 Hub 模型定义提供了用于前向和后向传递的实现。您可以通过在配置中设置其 Hub ID 来选择模型。

从“transformers_modeling_backend_full()”开始。它保留映射到 Hugging Face 配置键的字段未设置，因此“AutoConfig.from_pretrained()”从 Hub 加载模型架构。

在 torchtitan-neuron 存储库根目录中创建“neuron_qwen3.py”，您可以在其中运行训练命令。添加导入、模型工件路径和基本配置：
```
import os
from torchtitan.experiments.transformers_modeling_backend.config_registry import (
    transformers_modeling_backend_full,
)
from torchtitan.experiments.transformers_modeling_backend.configs import (
    TransformersBackendConfig,
)

ASSETS = os.path.abspath("./assets/hf/Qwen3-4B-Instruct-2507")

def v5_qwen3_4b() -> TransformersBackendConfig:
    config = transformers_modeling_backend_full()
    config.hf_model = "Qwen/Qwen3-4B-Instruct-2507"
    config.hf_assets_path = ASSETS
    config.dataloader.dataset = "c4_test"
    config.training.steps = 10
    config.training.local_batch_size = 1
    config.parallelism.data_parallel_shard_degree = -1
    return config
```

```
torchrun --nproc_per_node=64 --rdzv_backend c10d --rdzv_endpoint localhost:0 \
  --local-ranks-filter 0 --role rank --tee 3 \
  -m torchtitan.train --module neuron_qwen3 --config v5_qwen3_4b
```
此命令启动 64 个训练过程，每个逻辑 NeuronCore 一个。 `--moduleneuron_qwen3` 导入本地配置模块。 `--config v5_qwen3_4b` 选择配置功能。数据并行设置将模型划分为所有 64 个等级。

### 加载并保存拥抱脸部检查点

要根据已发布的权重进行微调，请启用检查点加载并将“initial_load_path”指向“ASSETS”。状态字典适配器调整前导的“model.”前缀并处理绑定嵌入。它将最终检查点保存为拥抱面部安全张量。
```
def v5_qwen3_4b_finetune() -> TransformersBackendConfig:
    config = v5_qwen3_4b()
    config.checkpoint.enable = True
    config.checkpoint.folder = "checkpoint_qwen3_4b_ft"
    config.checkpoint.initial_load_path = ASSETS # absolute path required
    config.checkpoint.initial_load_in_hf = True
    config.checkpoint.initial_load_model_only = True
    config.checkpoint.last_save_in_hf = True
    config.checkpoint.last_save_model_only = True
    return config
```
使用第一个训练步骤损失来快速检查 torchtitan 是否加载了已发布的权重。对于“Qwen/Qwen3-4B-Instruct-2507”，经过验证的运行在公布的权重中产生了 6.54 的步骤 1 损失，在随机初始化中产生了 12.43 的步骤 1 损失。

训练后，使用 AutoModelForCausalLM 和 load_state_dict 加载导出的检查点。成功的往返报告除了“lm_head.weight”之外没有丢失或意外的键，Qwen3-4B 与令牌嵌入相关。这证实了这些文件仍然是标准的 Hugging Face 检查点。

## 使用 torchtitan 的原生模型进行训练

在第二个配置中，torchtitan 构建其原生“Qwen3Model”。将本机 Qwen3 导入和配置函数添加到“neuron_qwen3.py”：

此示例从“qwen3_32b()”开始，因为测试的 torchtitan 版本不提供通用的“qwen3_4b()”配置生成器。下一行将 32B 型号规格替换为 4B 规格。其余字段重现测试运行。
```
from torchtitan.models.qwen3 import model_registry
from torchtitan.models.qwen3.config_registry import qwen3_32b
from torchtitan.trainer import Trainer

def native_qwen3_4b() -> Trainer.Config:
    config = qwen3_32b()
    config.model_spec = model_registry("4B", attn_backend="sdpa")
    config.hf_assets_path = ASSETS
    config.dataloader.dataset = "c4_test"
    config.training.steps = 10
    config.training.local_batch_size = 1
    config.training.global_batch_size = 64
    config.parallelism.data_parallel_shard_degree = -1
    return config
```

```
torchrun --nproc_per_node=64 --rdzv_backend c10d --rdzv_endpoint localhost:0 \
  --local-ranks-filter 0 --role rank --tee 3 \
  -m torchtitan.train --module neuron_qwen3 --config native_qwen3_4b
```
`config.model_spec` 选择模型类并定义 torchtitan 如何对模型进行分片并映射其检查点键。这里，`model_registry("4B", attn_backend="sdpa")` 选择了 torchtitan 的原生 Qwen3 实现，具有缩放点积注意力 (SDPA)。

## 添加 NKI 内核以供专家混合

在第三种配置中，torchtitan 运行专家混合层，其内核是用 NKI（Neuron 内核语言）编写的。将所需的导入和 Qwen3 MoE 配置函数添加到“neuron_qwen3.py”：
```
from torchtitan.config import CompileConfig
from torchtitan_neuron.models.qwen3.config_registry import qwen3_nki_moe_config

def nki_qwen3_30b_a3b() -> Trainer.Config:
    config = qwen3_nki_moe_config(
        "30B-A3B",
        compile_config=CompileConfig(enable=False, backend="neuron"),
        n_layers=4,
        num_experts=64,
        top_k=4,
    )
    config.hf_assets_path = ASSETS
    return config
```

```
torchrun --nproc_per_node=64 --rdzv_backend c10d --rdzv_endpoint localhost:0 \
  --local-ranks-filter 0 --role rank --tee 3 \
  -m torchtitan.train --module neuron_qwen3 --config nki_qwen3_30b_a3b
```
此配置使用跨 64 个等级的数据并行分片，张量并行度为 1。它不使用专家并行性。 `num_experts=64` 设置模型中专家的数量，而不是专家并行度。

设置“CompileConfig(enable=False)”以急切模式运行此示例。 TorchNeuron 支持在急切执行和“torch.compile”中注册的 NKI 运算符。

在本演练使用的 torchtitan 版本中，“qwen3_nki_moe_config()”用 NKI 分组专家实现替换了 MoE 块。它还选择SDPA和无聚集旋转嵌入。当启用“torch.compile”时，将“grad_clip”添加到“CompileConfig.components”以编译梯度范数裁剪。

NKI 内核作为 PyTorch 操作员进入训练。 `wrap_nki` 使 NKI 内核可从 PyTorch 调用，而 `nki_op` 则注册该运算符。 `register_autograd` 使用前向传递期间保存的路由元数据附加其后向传递。

该示例将 Qwen3-30B-A3B 减少到 4 层和 64 个专家，因此它适合一个“trn2.48xlarge”。它将每个令牌路由到 4 位具有“top_k=4”的专家。

### 附上你自己的NKI内核

在某些情况下，您可能希望优化模型中张量形状的操作。专门的内核可以根据这些形状定制其平铺和数据移动。它还可以用一个优化的运算符替换对性能至关重要的 PyTorch 操作序列。您可以自己编写内核，也可以从“nkilib”中的内核开始。此示例使用“nkilib.core.embeddings”中的“rope_hf”，它需要 Hugging Face 张量布局并支持其自己的向后模式。此示例演示了内核注册和 autograd 集成，而不是性能改进。

在存储库根目录中创建“my_neuron_kernels.py”，您可以在其中启动训练。 torchtitan 将查询和密钥存储为“[batch，seq，heads，head_dim]”，而“rope_hf”则需要“[batch，heads，seq，head_dim]”。转换运算符内部的布局并使用 torch.empty_like() 分配输出张量：
```
import torch
from nkilib.core.embeddings.rope_hf import rope_hf
from torch_neuronx import nki_op
from torch_neuronx.nki_hop import wrap_nki
from torch_neuronx.utils import get_logical_neuron_cores

LNC = (int(get_logical_neuron_cores()),)
wrapped_rope = wrap_nki(rope_hf)

@nki_op("my_kernels::rope_fwd")
def rope_fwd(query, key, rope_cache):
    q = query.permute(0, 2, 1, 3).contiguous()
    k = key.permute(0, 2, 1, 3).contiguous()
    cache = rope_cache.reshape(-1, rope_cache.shape[-1])
    q_out, k_out = wrapped_rope[LNC](
        q,
        k,
        torch.empty_like(q),
        torch.empty_like(k),
        rope_cache=cache,
    )
    return (
        q_out.permute(0, 2, 1, 3).contiguous(),
        k_out.permute(0, 2, 1, 3).contiguous(),
    )
```
当您使用“backward=True”调用“rope_hf”时，它会计算梯度。为该模式注册第二个操作员。在前向传递期间保存旋转缓存，以便后向传递可以重用它。对于缓存梯度返回“None”，因为缓存是不可微分的。
```
@nki_op("my_kernels::rope_bwd")
def rope_bwd(grad_query, grad_key, rope_cache):
    gq = grad_query.permute(0, 2, 1, 3).contiguous()
    gk = grad_key.permute(0, 2, 1, 3).contiguous()
    cache = rope_cache.reshape(-1, rope_cache.shape[-1])
    out_q, out_k = wrapped_rope[LNC](
        gq,
        gk,
        torch.empty_like(gq),
        torch.empty_like(gk),
        rope_cache=cache,
        backward=True,
    )
    return (
        out_q.permute(0, 2, 1, 3).contiguous(),
        out_k.permute(0, 2, 1, 3).contiguous(),
    )
```

```
def _setup_context(ctx, inputs, output):
    ctx.save_for_backward(inputs[2])

def _backward(ctx, grad_query, grad_key):
    (rope_cache,) = ctx.saved_tensors
    grad_q, grad_k = rope_bwd(grad_query, grad_key, rope_cache)
    return grad_q, grad_k, None

rope_fwd.register_autograd(_backward, setup_context=_setup_context)
```
由于“rope_hf”需要受支持的序列长度，因此在调用内核之前验证该约束。子类 `CosSinRoPE` 并从 `apply_rotary_emb` 调用 `rope_fwd`：
```
from dataclasses import dataclass
from torchtitan.config import derive, override
from torchtitan.models.common.rope import CosSinRoPE

class NKIRoPE(CosSinRoPE):
    @dataclass(kw_only=True, slots=True)
    class Config(CosSinRoPE.Config):
        pass

    @staticmethod
    def apply_rotary_emb(query, key, rope_cache):
        stride = 128 * LNC[0]
        if query.shape[1] % stride:
            raise ValueError(
                f"rope_hf requires a sequence length that is a multiple of "
                f"128 * LNC={stride}, got {query.shape[1]}"
            )
        q_out, k_out = rope_fwd(query, key, rope_cache)
        return q_out.type_as(query), k_out.type_as(key)
```
注册“NKIRoPE”作为“CosSinRoPE”的替代品。 `derive()` 将共享配置字段复制到替换配置中：
```
@override(
    "nki_rope",
    target=CosSinRoPE.Config,
    exact=True,
    description="nkilib rope_hf kernel in place of the PyTorch rotation",
)
def _nki_rope(cfg: CosSinRoPE.Config) -> NKIRoPE.Config:
    return derive(cfg, NKIRoPE.Config)
```
要加载自定义覆盖，请将其模块名称传递给“--override.imports”。 torchtitan 在构建模型之前导入注册表项：
```
torchrun --nproc_per_node=64 --rdzv_backend c10d --rdzv_endpoint localhost:0 \
  --local-ranks-filter 0 --role rank --tee 3 \
  -m torchtitan.train --module neuron_qwen3 --config native_qwen3_4b \
  --override.imports my_neuron_kernels
```
在训练开始之前，torchtitan 会记录覆盖替换的每个配置节点。确认输出包含每个 Qwen3 层的一个“nki_rope”条目：
```
[Override] nki_rope: model_spec.model.layers.0.attention.rope CosSinRoPEConfig -> NKIRoPE.Config
[Override] nki_rope: model_spec.model.layers.1.attention.rope CosSinRoPEConfig -> NKIRoPE.Config
```
将序列长度设置为“128 * LNC”的倍数，当 LNC 为 2 时，该长度为 256。将旋转缓存重塑为“[seq, head_dim * 2]”，前半部分为余弦值，后半部分为正弦值。内核在训练开始之前验证这些约束。

有关完整的 torchtitan 示例，请参阅“torchtitan_neuron/models/gpt_oss/nki_attention.py”。它通过相同的运算符和覆盖机制连接“nkilib”闪存注意力内核。它还处理“DTensor”输入以实现张量并行性。

在使用自定义内核进行训练之前，请将其输出与其替换的实现进行比较。在使用 float32 输入的数值测试中，“rope_hf”和 torchtitan 的 PyTorch 旋转嵌入对于查询和密钥产生的最大绝对差为 0.0。

当您注册多个覆盖时，请使用“fqns”将每个覆盖限制为预期的模块实例。例如，`fqns=["layers.1[0-9].attention.rope"]`的目标是第10层到第19层中的旋转嵌入。当两个覆盖声明同一节点时，torchtitan会停止，并在覆盖不匹配任何节点时发出警告。

## 查看训练输出

启动时，确认 torchtitan 报告 64 个排名和预期模型。第一步包括编译，并且比后面的步骤花费更长的时间。每个训练步骤都会报告损失、梯度范数、高带宽内存 (HBM) 使用情况、吞吐量和模型 FLOP 利用率 (MFU)。对于检查点运行，确认第一步损失接近 6.54。对于自定义内核运行，请确认“nki_rope”覆盖对于每个 Qwen3 层都出现一次。

## 跨实例扩展

相同的并行设置适用于 Transformer 和本机模型配置。 “trn2.48xlarge”在 LNC=2 时公开 64 个逻辑 NeuronCore。设置“data_parallel_shard_ Degree = -1”以在“torchrun”启动的每个等级上对模型参数、梯度和优化器状态进行分片。

设置“config.parallelism.tensor_parallel_ Degree”以将每个层的权重分片到一组等级上。每个等级计算每个矩阵乘法的一个切片。默认情况下启用序列并行性，标准化层在沿序列维度分片的激活上运行。 torchtitan 将张量并行性与多维“DeviceMesh”上的完全分片数据并行（FSDP）相结合。

当您增加模型大小、序列长度或本地批量大小时，请观察每个等级的 HBM。这些值决定每个等级需要多少内存。

## 结论

[AWS Trainium](https://aws.amazon.com/ai/machine-learning/trainium/) 在本演练的所有三种配置中充当受支持的 torchtitan 设备。您可以通过 Hugging Face Transformers v5 训练 Qwen3，并直接加载或保存已发布的安全张量。您还可以通过设置 config.model_spec 使用 torchtitan 的原生 Qwen3 实现进行训练。对于混合专家模型，请使用 torchtitan-neuron NKI 配方。对于自定义内核，请使用覆盖注册表通过相同的启动流程附加 NKI 操作符。

有关设置指南，请参阅 [AWS Neuron 文档](https://awsdocs-neuron.readthedocs-hosted.com/)。有关当前源和培训食谱，请参阅 torchtitan 存储库。
