# 使用 torchtitan 在 AWS Trainium 上训练 Qwen3

在 [AWS Trainium](https://aws.amazon.com/ai/machine-learning/trainium/) 上使用 torchtitan，意味着按你一贯的方式使用它。TorchNeuron 把 Trainium 注册为原生 PyTorch 设备，使 torchtitan 可以通过标准 PyTorch 接口使用它。你可以用这些配置从随机初始化开始预训练，或微调已发布的权重。你还可以针对自己的工作负载自定义模型实现和 kernel。本文将在单台 `trn2.48xlarge` 上用三种方式训练 Qwen3。

第一种方法把 Transformers v5 作为 torchtitan 中的建模后端。它通过 `AutoModelForCausalLM` 运行 Hub 模型，并直接读写已发布的 safetensors。第二种方法通过修改 `config.model_spec` 切换到 torchtitan 原生的 Qwen3。第三种方法引入 torchtitan-neuron recipes 中的 Neuron Kernel Interface (NKI) 混合专家（MoE）kernel，然后用 torchtitan 的 override registry 挂载你自己的 kernel。三种配置都使用相同的 `torchrun` 启动方式和配置结构。

## 先决条件

要跟随本演练，请使用单台 `trn2.48xlarge`，搭配 AWS Deep Learning AMI for Neuron 或 Neuron PyTorch 训练容器。两种环境都提供在 Trainium 上训练所需的 Neuron 驱动、运行时和编译器。

在安装 [torchtitan-neuron](https://github.com/aws-neuron/torchtitan-neuron) 之前，请检查你的环境是否已包含它。以下命令会打印已安装的版本和包路径：

```
python3 -c "import torchtitan, torchtitan_neuron; print(torchtitan.__version__, torchtitan_neuron.__file__)"
```

本演练使用下表中的版本。要复现这些示例，请固定这些版本。Transformers v5 集成和 Trainium 专用 override 模块可能在不同 torchtitan 版本之间发生变化。

| **组件** | **版本** |
| --- | --- |
| 实例 | trn2.48xlarge，16 个 Trainium2 加速器，128 个物理 NeuronCore |
| 逻辑 NeuronCore | LNC=2 时为 64 个 |
| torch、torch_neuronx | 2.14.0、2.14.3 |
| transformers | 5.16.0 |
| torchtitan-neuron | release-2.33 (0.2.2+neuron.1) |

安装 `torch_neuronx` 后，TorchNeuron 会把 Trainium 注册为 `neuron` 设备，torchtitan 会在启动时检测到它。在 eager 模式下，Neuron 在执行时编译操作。使用 `torch.compile` 时，Neuron 编译捕获到的计算图。同样的启动方式适用于全部三种配置。

对于本演练使用的版本，请用 `--no-deps` 安装 torchtitan-neuron 和 torchtitan 的其余依赖，以保留 Neuron 构建的 torch：

```
git clone https://github.com/aws-neuron/torchtitan-neuron
cd torchtitan-neuron
pip install -r requirements.txt
```

开始训练之前，请从 Hugging Face Hub 获取 Qwen3 模型产物，并存放在一个可以传给训练配置的本地目录中：

```
hf download Qwen/Qwen3-4B-Instruct-2507 \
  --local-dir "$PWD/assets/hf/Qwen3-4B-Instruct-2507"
```

每个训练配置都是一个 Python 配置函数。三个示例都从一份基础配置出发，你在每一步对它做修改。

## 使用 Hugging Face Transformers v5 训练

在第一种配置中，Transformers v5 通过 `AutoModelForCausalLM` 构建 Qwen3。Hub 中的模型定义提供前向和反向传播所使用的实现。你在配置中设置 Hub ID 来选择模型。

从 `transformers_modeling_backend_full()` 开始。它把映射到 Hugging Face 配置键的字段留空，因此 `AutoConfig.from_pretrained()` 会从 Hub 加载模型架构。

在 torchtitan-neuron 仓库根目录（也就是你运行训练命令的位置）创建 `neuron_qwen3.py`。添加导入、模型产物路径和基础配置：

```
import os
from torchtitan.experiments.transformers_modeling_backend.config_registry import (
    transformers_modeling_backend_full,
)
from torchtitan.experiments.transformers_modeling_backend.configs import (
    TransformersBackendConfig,
)

ASSETS = os.path.abspath("./assets/hf/Qwen3-4B-Instruct-2507")

def v5_qwen3_4b() -> TransformersBackendConfig:
    config = transformers_modeling_backend_full()
    config.hf_model = "Qwen/Qwen3-4B-Instruct-2507"
    config.hf_assets_path = ASSETS
    config.dataloader.dataset = "c4_test"
    config.training.steps = 10
    config.training.local_batch_size = 1
    config.parallelism.data_parallel_shard_degree = -1
    return config
```

```
torchrun --nproc_per_node=64 --rdzv_backend c10d --rdzv_endpoint localhost:0 \
  --local-ranks-filter 0 --role rank --tee 3 \
  -m torchtitan.train --module neuron_qwen3 --config v5_qwen3_4b
```

该命令启动 64 个训练进程，每个逻辑 NeuronCore 一个。`--module neuron_qwen3` 导入本地的配置模块。`--config v5_qwen3_4b` 选择配置函数。数据并行设置会把模型分片到全部 64 个 rank 上。

### 加载并保存 Hugging Face 检查点

要从已发布的权重微调，请启用检查点加载，并把 `initial_load_path` 指向 `ASSETS`。state-dictionary 适配器会调整开头的 `model.` 前缀，并处理绑定嵌入（tied embeddings）。它把最终检查点保存为 Hugging Face safetensors。

```
def v5_qwen3_4b_finetune() -> TransformersBackendConfig:
    config = v5_qwen3_4b()
    config.checkpoint.enable = True
    config.checkpoint.folder = "checkpoint_qwen3_4b_ft"
    config.checkpoint.initial_load_path = ASSETS # absolute path required
    config.checkpoint.initial_load_in_hf = True
    config.checkpoint.initial_load_model_only = True
    config.checkpoint.last_save_in_hf = True
    config.checkpoint.last_save_model_only = True
    return config
```

用第一个训练步的 loss 快速检查 torchtitan 是否加载了已发布的权重。对于 `Qwen/Qwen3-4B-Instruct-2507`，验证过的运行从已发布权重得到第 1 步 loss 为 6.54，从随机初始化得到 12.43。

训练结束后，用 `AutoModelForCausalLM` 和 `load_state_dict` 加载导出的检查点。一次成功的往返除了 `lm_head.weight` 之外不会报告任何缺失或意外的键，Qwen3-4B 把该权重与 token 嵌入绑定。这确认这些文件仍然是标准的 Hugging Face 检查点。

## 使用 torchtitan 的原生模型训练

在第二种配置中，torchtitan 构建其原生的 `Qwen3Model`。把原生 Qwen3 的导入和配置函数加入 `neuron_qwen3.py`：

这个示例从 `qwen3_32b()` 出发，因为测试所用的 torchtitan 构建没有提供通用的 `qwen3_4b()` 配置构造函数。下一行把 32B 的模型规格替换为 4B 规格。其余字段复现了测试过的运行。

```
from torchtitan.models.qwen3 import model_registry
from torchtitan.models.qwen3.config_registry import qwen3_32b
from torchtitan.trainer import Trainer

def native_qwen3_4b() -> Trainer.Config:
    config = qwen3_32b()
    config.model_spec = model_registry("4B", attn_backend="sdpa")
    config.hf_assets_path = ASSETS
    config.dataloader.dataset = "c4_test"
    config.training.steps = 10
    config.training.local_batch_size = 1
    config.training.global_batch_size = 64
    config.parallelism.data_parallel_shard_degree = -1
    return config
```

```
torchrun --nproc_per_node=64 --rdzv_backend c10d --rdzv_endpoint localhost:0 \
  --local-ranks-filter 0 --role rank --tee 3 \
  -m torchtitan.train --module neuron_qwen3 --config native_qwen3_4b
```

`config.model_spec` 选择模型类，并定义 torchtitan 如何分片模型以及映射其检查点键。这里，`model_registry("4B", attn_backend="sdpa")` 选择使用缩放点积注意力（SDPA）的 torchtitan 原生 Qwen3 实现。

## 为混合专家添加 NKI kernel

在第三种配置中，torchtitan 使用以 NKI（Neuron kernel 语言）编写的 kernel 运行混合专家层。把所需的导入和 Qwen3 MoE 配置函数加入 `neuron_qwen3.py`：

```
from torchtitan.config import CompileConfig
from torchtitan_neuron.models.qwen3.config_registry import qwen3_nki_moe_config

def nki_qwen3_30b_a3b() -> Trainer.Config:
    config = qwen3_nki_moe_config(
        "30B-A3B",
        compile_config=CompileConfig(enable=False, backend="neuron"),
        n_layers=4,
        num_experts=64,
        top_k=4,
    )
    config.hf_assets_path = ASSETS
    return config
```

```
torchrun --nproc_per_node=64 --rdzv_backend c10d --rdzv_endpoint localhost:0 \
  --local-ranks-filter 0 --role rank --tee 3 \
  -m torchtitan.train --module neuron_qwen3 --config nki_qwen3_30b_a3b
```

该配置在 64 个 rank 上使用数据并行分片，张量并行度为 1。它不使用专家并行。`num_experts=64` 设置模型中的专家数量，而不是专家并行度。

设置 `CompileConfig(enable=False)` 会让该示例以 eager 模式运行。TorchNeuron 在 eager 执行和 `torch.compile` 中都支持已注册的 NKI 算子。

在本演练使用的 torchtitan 构建中，`qwen3_nki_moe_config()` 用 NKI grouped-experts 实现替换 MoE 块。它还会选择 SDPA 和不做 gather 的旋转嵌入（rotary embedding）。启用 `torch.compile` 时，请把 `"grad_clip"` 加入 `CompileConfig.components`，以编译梯度范数裁剪。

NKI kernel 以 PyTorch 算子的形式进入训练。`wrap_nki` 让 NKI kernel 可以从 PyTorch 调用，`nki_op` 注册该算子。`register_autograd` 使用前向传播期间保存的路由元数据挂载其反向传播。

该示例把 Qwen3-30B-A3B 缩减为 4 层和 64 个专家，以便在一台 `trn2.48xlarge` 上运行。它用 `top_k=4` 把每个 token 路由到 4 个专家。

### 挂载你自己的 NKI kernel

在某些情况下，你可能想针对模型中的张量形状优化某个操作。专用 kernel 可以让自己的分块和数据移动方式适配这些形状。它还可以用一个优化后的算子替换一段性能关键的 PyTorch 操作序列。你可以自己编写 kernel，也可以从 `nkilib` 中选一个作为起点。本示例使用 `nkilib.core.embeddings` 中的 `rope_hf`，它期望 Hugging Face 的张量布局，并支持自己的反向模式。本示例演示的是 kernel 注册和 autograd 集成，而不是性能提升。

在启动训练的仓库根目录创建 `my_neuron_kernels.py`。torchtitan 把 query 和 key 存为 `[batch, seq, heads, head_dim]`，而 `rope_hf` 期望 `[batch, heads, seq, head_dim]`。在算子内部转换布局，并用 `torch.empty_like()` 分配输出张量：

```
import torch
from nkilib.core.embeddings.rope_hf import rope_hf
from torch_neuronx import nki_op
from torch_neuronx.nki_hop import wrap_nki
from torch_neuronx.utils import get_logical_neuron_cores

LNC = (int(get_logical_neuron_cores()),)
wrapped_rope = wrap_nki(rope_hf)

@nki_op("my_kernels::rope_fwd")
def rope_fwd(query, key, rope_cache):
    q = query.permute(0, 2, 1, 3).contiguous()
    k = key.permute(0, 2, 1, 3).contiguous()
    cache = rope_cache.reshape(-1, rope_cache.shape[-1])
    q_out, k_out = wrapped_rope[LNC](
        q,
        k,
        torch.empty_like(q),
        torch.empty_like(k),
        rope_cache=cache,
    )
    return (
        q_out.permute(0, 2, 1, 3).contiguous(),
        k_out.permute(0, 2, 1, 3).contiguous(),
    )
```

当以 `backward=True` 调用时，`rope_hf` 会计算梯度。为该模式注册第二个算子。在前向传播期间保存旋转缓存，以便反向传播复用它。为缓存梯度返回 `None`，因为缓存不可微。

```
@nki_op("my_kernels::rope_bwd")
def rope_bwd(grad_query, grad_key, rope_cache):
    gq = grad_query.permute(0, 2, 1, 3).contiguous()
    gk = grad_key.permute(0, 2, 1, 3).contiguous()
    cache = rope_cache.reshape(-1, rope_cache.shape[-1])
    out_q, out_k = wrapped_rope[LNC](
        gq,
        gk,
        torch.empty_like(gq),
        torch.empty_like(gk),
        rope_cache=cache,
        backward=True,
    )
    return (
        out_q.permute(0, 2, 1, 3).contiguous(),
        out_k.permute(0, 2, 1, 3).contiguous(),
    )
```

```
def _setup_context(ctx, inputs, output):
    ctx.save_for_backward(inputs[2])

def _backward(ctx, grad_query, grad_key):
    (rope_cache,) = ctx.saved_tensors
    grad_q, grad_k = rope_bwd(grad_query, grad_key, rope_cache)
    return grad_q, grad_k, None

rope_fwd.register_autograd(_backward, setup_context=_setup_context)
```

由于 `rope_hf` 要求受支持的序列长度，请在调用该 kernel 之前校验这一约束。继承 `CosSinRoPE`，并从 `apply_rotary_emb` 调用 `rope_fwd`：

```
from dataclasses import dataclass
from torchtitan.config import derive, override
from torchtitan.models.common.rope import CosSinRoPE

class NKIRoPE(CosSinRoPE):
    @dataclass(kw_only=True, slots=True)
    class Config(CosSinRoPE.Config):
        pass

    @staticmethod
    def apply_rotary_emb(query, key, rope_cache):
        stride = 128 * LNC[0]
        if query.shape[1] % stride:
            raise ValueError(
                f"rope_hf requires a sequence length that is a multiple of "
                f"128 * LNC={stride}, got {query.shape[1]}"
            )
        q_out, k_out = rope_fwd(query, key, rope_cache)
        return q_out.type_as(query), k_out.type_as(key)
```

把 `NKIRoPE` 注册为 `CosSinRoPE` 的替代实现。`derive()` 会把共享的配置字段复制到替代配置中：

```
@override(
    "nki_rope",
    target=CosSinRoPE.Config,
    exact=True,
    description="nkilib rope_hf kernel in place of the PyTorch rotation",
)
def _nki_rope(cfg: CosSinRoPE.Config) -> NKIRoPE.Config:
    return derive(cfg, NKIRoPE.Config)
```

要加载自定义 override，请把它的模块名传给 `--override.imports`。torchtitan 会在构建模型之前导入该注册表条目：

```
torchrun --nproc_per_node=64 --rdzv_backend c10d --rdzv_endpoint localhost:0 \
  --local-ranks-filter 0 --role rank --tee 3 \
  -m torchtitan.train --module neuron_qwen3 --config native_qwen3_4b \
  --override.imports my_neuron_kernels
```

训练开始之前，torchtitan 会记录 override 替换的每个配置节点。确认输出中每个 Qwen3 层都有一条 `nki_rope` 条目：

```
[Override] nki_rope: model_spec.model.layers.0.attention.rope CosSinRoPEConfig -> NKIRoPE.Config
[Override] nki_rope: model_spec.model.layers.1.attention.rope CosSinRoPEConfig -> NKIRoPE.Config
```

把序列长度设为 `128 * LNC` 的倍数，当 LNC 为 2 时是 256。把旋转缓存重塑为 `[seq, head_dim * 2]`，余弦值放在前半部分，正弦值放在后半部分。kernel 会在训练开始前校验这些约束。

完整的 torchtitan 示例见 `torchtitan_neuron/models/gpt_oss/nki_attention.py`。它通过相同的算子和 override 机制接入 `nkilib` flash-attention kernel。它还处理张量并行所需的 `DTensor` 输入。

在使用自定义 kernel 训练之前，请把它与它所替换的实现比较输出。在使用 float32 输入的数值测试中，`rope_hf` 与 torchtitan 的 PyTorch 旋转嵌入在 query 和 key 上的最大绝对差都是 0.0。

注册多个 override 时，请用 `fqns` 把每一个限制在预期的模块实例上。例如，`fqns=["layers.1[0-9].attention.rope"]` 针对第 10 到 19 层的旋转嵌入。当两个 override 声明同一个节点时 torchtitan 会停止，当某个 override 没有匹配任何节点时会发出警告。

## 检查训练输出

启动时，确认 torchtitan 报告 64 个 rank 和预期的模型。第一步包含编译，耗时比后续步骤更长。每个训练步都会报告 loss、梯度范数、高带宽内存（HBM）使用量、吞吐量和模型 FLOPs 利用率（MFU）。对于检查点运行，确认第一步 loss 接近 6.54。对于自定义 kernel 运行，确认 `nki_rope` override 在每个 Qwen3 层都出现一次。

## 跨整台实例扩展

相同的并行设置适用于 Transformers 和原生模型配置。在 LNC=2 时，`trn2.48xlarge` 暴露 64 个逻辑 NeuronCore。设置 `data_parallel_shard_degree = -1`，把模型参数、梯度和优化器状态分片到 `torchrun` 启动的每个 rank 上。

设置 `config.parallelism.tensor_parallel_degree`，把每一层的权重分片到一组 rank 上。每个 rank 计算每次矩阵乘法的一个切片。由于序列并行默认启用，归一化层在按序列维度分片的激活上运行。torchtitan 在多维 `DeviceMesh` 上把张量并行与 Fully Sharded Data Parallel (FSDP) 结合。

当你增大模型规模、序列长度或本地批大小时，请关注每个 rank 的 HBM。这些值决定每个 rank 需要多少内存。

## 结论

[AWS Trainium](https://aws.amazon.com/ai/machine-learning/trainium/) 在本演练的全部三种配置中都能作为受支持的 torchtitan 设备使用。你可以通过 Hugging Face Transformers v5 训练 Qwen3，并直接加载或保存已发布的 safetensors。你也可以通过设置 `config.model_spec` 使用 torchtitan 原生的 Qwen3 实现训练。对于混合专家模型，请使用 torchtitan-neuron 的 NKI recipes。对于自定义 kernel，请使用 override registry，通过同样的启动流程挂载 NKI 算子。

关于环境搭建指导，请参阅 [AWS Neuron 文档](https://awsdocs-neuron.readthedocs-hosted.com/)。关于最新的源码和训练 recipes，请参阅 torchtitan 仓库。
