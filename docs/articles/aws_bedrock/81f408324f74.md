# 用 Amazon Nova Micro 与 Amazon Nova Lite 提升理赔数据处理的成本效益与速度

Amazon 的运营遍布全球，每天影响着数百万客户、员工和供应商的生活。从庞大的物流网络到前沿的技术基础设施，这种规模印证了公司创新与服务客户的能力。伴随这种规模而来的是管理风险和处理理赔的责任——无论涉及工伤赔偿、运输事故还是其他保险相关事项。风险经理负责监督针对 Amazon 的理赔的全生命周期。来自不同来源的理赔文件随着理赔成熟而不断增多，单笔理赔平均包含 75 份文件。风险经理必须严格遵循相关的标准作业程序（SOP），审视数十个理赔方面的演变以评估严重程度并采取恰当措施，公平而高效地审阅与处理每笔理赔。但随着 Amazon 持续增长，风险经理如何才能跟上不断增加的理赔数量？

2024 年 12 月，Amazon 内部的一个技术团队针对与公司相关理赔的数据构建并实施了一套 AI 驱动的方案。该方案生成不超过 500 词、覆盖多个类别的结构化理赔摘要，在保持理赔审阅流程准确性的同时提升效率。然而，团队在高推理成本和处理时间（每笔理赔 3–5 分钟）上面临挑战，尤其是在新增文件时。由于团队计划把这项技术扩展到其他业务线，他们探索了 [Amazon Nova Foundation Models](https://aws.amazon.com/ai/generative-ai/nova/) 作为潜在替代方案，以解决成本与延迟问题。

下图展示了在理赔数据集上，多种基础模型在性能与延迟、性能与成本方面的对比。

![Sonnet 与 Nova 等语言模型的性能对比图，以 BERT-F1 分数对运营指标作图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/10/ML-18438-model-comparison.png)

针对理赔摘要用例的评估证明，Amazon Nova 基础模型（FM）是其他前沿大语言模型（LLM）的有力替代方案，在实现相当性能的同时成本显著更低、整体速度更快。Amazon Nova Lite 模型在处理冗长、多样且杂乱的文档时展现出强大的摘要能力。

## 方案概览

摘要流水线首先使用 [AWS Glue](https://aws.amazon.com/glue/) 作业处理原始理赔数据。它把数据存入中间 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/) 存储桶，并使用 [Amazon Simple Queue Service（Amazon SQS）](https://aws.amazon.com/sqs/) 管理摘要作业。理赔摘要由 [AWS Lambda](https://aws.amazon.com/lambda/) 使用托管在 Amazon Bedrock 中的基础模型生成。我们首先用基于 Nova Lite 的 LLM 分类模型过滤无关的理赔数据，只对相关的理赔数据做摘要，以缩小上下文窗口。考虑到相关性判断与摘要所需的智能水平不同，我们选择恰当的模型，在保持性能的同时优化成本。由于理赔会在新信息到达时生成摘要，我们还使用 [Amazon DynamoDB](https://aws.amazon.com/dynamo/) 缓存中间结果与摘要，以减少重复推理并降低成本。下图展示了理赔摘要用例方案的高层架构。

![AWS 理赔摘要工作流图，集成数据预处理、排队、AI 处理与存储服务](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/10/ML-18438-arch.png)

尽管 Amazon Nova 团队已发布覆盖多个不同类别的[性能基准](https://aws.amazon.com/ai/generative-ai/nova/understanding/)，但理赔摘要因其输入多样、上下文窗口长而是一个独特的用例。这促使负责理赔方案的技术团队用自己的基准研究进一步考察。为了评估 Amazon Nova 模型在其特定用例中的性能、速度和成本，团队策划了一个由 95 对理赔文件与经核验的各方面摘要组成的基准数据集。理赔文件长度从 1,000 词到 60,000 词不等，多数约为 13,000 词（中位数 10,100）。这些文件的经核验摘要通常很短，不足 100 词。模型的输入包含多种类型的文档和摘要，覆盖生产环境中的各个方面。

根据基准测试，团队观察到 Amazon Nova Lite 比他们当前使用的模型快一倍，成本低 98%。Amazon Nova Micro 更为高效，运行速度快四倍，成本低 99%。成本效益与延迟的大幅改善，为设计更精密的模型和扩大测试算力以提升摘要质量提供了更大的灵活性。此外，团队还观察到，在长上下文窗口和长输出场景下，Amazon Nova 模型与次优模型之间的延迟差距进一步拉大，这使得在需要优化延迟的长文档场景中，Amazon Nova 成为更有力的替代方案。另外，团队在开展这项基准研究时使用了与当前生产方案相同的 prompt，实现了 prompt 的无缝迁移。即便如此，Amazon Nova 模型仍成功遵循指令并生成后处理所需的格式。基于基准测试与评估结果，团队把 Amazon Nova Lite 用于分类和摘要用例。

## 结论

本文分享了 Amazon 内部技术团队如何评估 Amazon Nova 模型，并因此在推理速度和成本效益上取得显著改善。回顾这项举措，团队总结出若干带来关键优势的重要因素：

- **可访问多样化的模型组合** —— 提供包括 Amazon Nova Micro 和 Amazon Nova Lite 这类紧凑而强大的选项在内的广泛模型，使团队能够快速试验并集成最符合自身需求的模型。
- **可扩展性与灵活性** —— Amazon Nova 模型在成本与延迟上的改善，为设计更精密的模型和扩大测试算力以提升摘要质量带来了更大灵活性。这种可扩展性对于处理海量数据或复杂工作流的组织尤其宝贵。
- **易于集成与迁移** —— 模型能够遵循指令并按所需格式生成输出，简化了后处理以及集成到现有系统的过程。

如果你的组织也有类似的大规模文档处理用例，且成本高昂、耗时漫长，上述评估实践表明 Amazon Nova Lite 和 Amazon Nova Micro 可能带来颠覆性改变。这些模型擅长处理海量多样文档和长上下文窗口——非常适合复杂的数据处理环境。尤其有说服力的是，这些模型能在显著降低运营成本的同时保持高性能。重要的是要针对质量、成本、速度这三大支柱不断迭代并尝试新模型。请用你自己的用例和数据集对这些模型做基准测试。
