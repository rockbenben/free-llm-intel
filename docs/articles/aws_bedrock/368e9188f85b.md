# 几分钟内跑通你的第一个 agent：Amazon Bedrock AgentCore 推出新功能

让一个 agent 跑起来，历来意味着先解决一长串基础设施问题，然后才有机会测试 agent 本身到底好不好用。你要接好框架、存储、身份验证和部署流水线；等到 agent 处理第一个真实任务时，你已经把几天时间花在了基础设施上，而不是 agent 逻辑上。

我们从零构建 AgentCore，就是为了让开发者专注于 agent 逻辑而不是后端管道，并且能配合他们已经在用的框架和模型，包括 LangGraph、LlamaIndex、CrewAI、Strands Agents 等。今天，我们推出了一些新能力，进一步简化 agent 的构建体验，消除那些在 agent 开发每个阶段——从最初原型到生产部署——都在拖慢团队的基础设施障碍。

## **三步从想法走到可运行的 agent**

每个 agent 都有一个编排层，其中包含这样的循环：调用模型、决定调用哪个工具、把结果传回去、管理上下文窗口、处理失败。要运行这个循环，底下需要一套基础设施：托管 agent 的计算资源、安全执行代码的沙箱、连接工具的安全通道、持久化存储，以及错误恢复能力。这套基础设施构成了 agent harness（智能体运行框架），让 agent 真正跑得起来。

到目前为止，搭建这套 harness 是每个团队都必须从零开始做的第一件事。这意味着挑选框架、编写编排代码、把它接到工具和记忆上、确保身份验证到位，这一切都要在 agent 处理哪怕一个请求之前完成。这些工作是必要的，但它并不能告诉你 agent 是否有用。我们合作过的大多数团队，都要在这套基础设施上花上几天，才能跑通第一次真实测试。

AgentCore 新增的托管 agent harness 功能，用一份直白的配置取代了所有这些前期搭建工作。你只需三次 API 调用就能声明并运行 agent，无需编写编排代码。你定义 agent 做什么：使用哪个模型、可以调用哪些工具、遵循什么指令。AgentCore 的 harness 会把计算、工具、记忆、身份和安全缝合在一起，生成一个几分钟内就能测试的可运行 agent。换一个模型或添加一个工具只是改配置，不必重写代码。你可以在几分钟内即时修改 API 参数，测试 agent 的若干变体。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/21/AgentCore-DevEx-Capabilities_Screenshot_HarnessInvokeDemo_Blog_1200w_REVIEW.jpg)

这种速度并不以牺牲灵活性为代价。AgentCore 中的 harness 由 Strands Agents 驱动，这是 AWS 提供的开源框架。当你需要自定义编排逻辑、专门的路由或多 agent 协同，可以从配置方式切换到代码定义的 harness，平台相同、microVM 隔离相同、部署流水线也相同。AgentCore 会把会话状态持久化到持久（durable）文件系统，因此 agent 可以在任务中途挂起，然后从断开之处原样继续。这让 human-in-the-loop（人在回路）模式变得实用，无需自建管道，也不必在日后需求出现时重新设计 agent。你可以几分钟内上手，然后在需求演进时增加更多能力和控制，而无需任何架构重构。

> “我们正在构建将颠覆电商的 AI agent。”VTEX 工程副总裁 Rodrigo Moreira 表示。“此前，为每个新 agent 做原型验证，都要先写几天的编排代码、搭好基础设施，才能验证一个想法。AgentCore 的 harness 功能将改变这一点：换模型、加工具、改写 agent 指令，如今都是一次配置变更，而不是一次重建。我们现在能在几分钟而不是几天内验证 agent 的想法，也期待借助这些新能力进一步加速 agent 开发。”

## **在同一个终端里构建、部署、运维 agent**

agent 已经能跑了，现在你想把它放到生产环境运行。这通常意味着离开编辑器、搭一条部署流水线、配置环境，再把一个和当初构建 agent 时完全不像的流程拼凑起来。

新的 [AgentCore CLI](https://github.com/aws/agentcore-cli) 让你在整个生命周期内保持同一套工作流：原型、部署、运维，都在你已经使用的那个终端里完成。你在本地迭代 agent，准备好后直接部署，无需切换工具，也不必另建一条流水线。AgentCore 通过基础设施即代码（IaC）驱动部署，支持 CDK 和 Terraform（即将推出），因此你的 agent 配置可复现、可版本控制。你在本地测试的内容，就是在生产环境运行的内容。

## **为你的编码 agent 提供正确的上下文**

在整个 agent 开发过程中，大多数开发者身边都有一位编码助手，例如 Claude Code 或 Kiro。但编码助手的效力取决于它掌握的上下文。通用 MCP server 可以让它访问 API 和文档，却无法编码那些真正重要的判断：该用哪些模式、各项能力如何组合、常见任务的推荐路径长什么样。AgentCore 新增的预构建 skills 超越了原始的 API 访问。它们为编码 agent 提供经过整理、保持最新的 AgentCore 最佳实践知识，因此你得到的建议反映的是这个平台应当如何被使用，而不只是有哪些端点存在。Kiro 今天已经把这项能力作为内置 Power 提供，面向 Claude Code、Codex 和 Cursor 的 Plugins 即将推出。在一个快速演进的平台上，让编码 agent 拥有准确的上下文，意味着从写第一行代码开始就能少走弯路。

## **开始使用**

AgentCore 中的托管 agent harness 今天已在四个 AWS Region 以预览形式提供：美国西部（俄勒冈）、美国东部（弗吉尼亚北部）、亚太地区（悉尼）和欧洲（法兰克福）。AgentCore CLI 与持久化 agent 文件系统已在所有提供 AgentCore 的 [AWS 商业区域](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-regions.html) 可用。关于编码 agent skills 的更多信息见[此处](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/harness-environment.html)。你只为实际使用的资源付费，CLI、harness 和 skills 不额外收费（详见 [AgentCore 定价页](https://aws.amazon.com/bedrock/agentcore/pricing/)）。访问 [AgentCore 文档](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agentcore-get-started-cli.html) 开始使用。

你可以借助这些能力专注于 agent 逻辑，不必为基础设施搭建操心。随着 agent 演进，你可以在不重构架构的前提下加上评估、记忆、工具连接和策略强制执行。你用来做原型的平台，就是你在生产环境运行的平台。
