# 借助 Amazon Bedrock Agents 加速癌症生物标志物的分析与发现

根据美国国家癌症研究所的定义，[癌症生物标志物](https://pmc.ncbi.nlm.nih.gov/articles/PMC5528374/)是“在血液、其他体液或组织中发现的生物分子，是正常或异常过程、或癌症等疾病状态的标志”。生物标志物通常能将患病患者与健康人区分开来。众所周知的癌症生物标志物包括用于肺癌的 EGFR、用于乳腺癌的 HER2、用于前列腺癌的 PSA 等等。[BEST](https://pubmed.ncbi.nlm.nih.gov/27010052/)（Biomarkers, EndpointS, and other Tools，即生物标志物、终点及其他工具）资源将生物标志物分为若干类型，例如诊断性、预后性和预测性生物标志物，可通过分子、影像和生理测量等多种技术进行检测。

发表在 Nature Reviews Drug Discovery 上的一项[研究](https://www.nature.com/articles/nrd.2016.136)指出，肿瘤药物从 I 期临床到获批的总体成功率仅约 5%。生物标志物通过改善试验的患者分层、加快药物开发、降低成本和风险以及实现个性化医疗，在提高临床开发成功率方面发挥着关键作用。例如，一项针对 1,079 种肿瘤药物的[研究](https://ascopubs.org/doi/10.1200/jco.2015.33.15_suppl.e17804)发现，使用生物标志物开发的药物成功率为 24%，而未使用生物标志物开发的化合物成功率仅为 6%。

研究科学家和真实世界证据（RWE）专家在使用现有工具分析生物标志物、验证生物标志物发现相关假设时面临诸多挑战。最值得注意的是，这包括跨各种生物医学文献（例如 PubMed）、公共科学数据库（例如 Protein Data Bank）、商业数据库和企业内部专有数据进行搜索、总结和洞见生成的繁琐且耗时的步骤。他们希望快速使用、修改或开发必要的工具，用于生物标志物的识别，以及跨模态、适应症、药物暴露和治疗、以及相关的终点结果（如生存期）的关联分析。每项实验可能采用数据、工具和可视化的不同组合。科学文献中的证据应当易于识别，并能结合相关上下文进行引用。

[Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 通过与公司系统、API 和数据源无缝连接，使生成式 AI 应用能够自动化多步骤任务。Bedrock 的[多 agent 协作](https://aws.amazon.com/about-aws/whats-new/2024/12/amazon-bedrock-multi-agent-collaboration/)使开发者能够构建、部署和管理多个协同工作的专用 agent，以应对日益复杂的业务工作流。在本文中，我们向你展示如何通过自然语言界面，利用 Amazon Bedrock Agents 的 agentic 工作流帮助研究科学家加速这一进程。我们定义了一个示例分析流程，专门针对临床、基因组和影像模态生物标志物的肺癌生存分析。我们展示了一系列专用 agent，包括生物标志物数据库分析师、统计学家、临床证据研究员和医学影像专家，它们与一个主管 agent 协作。我们展示了 agent 在自我审查和规划方面的高级能力，通过将复杂任务分解为一系列步骤并展示生成最终答案的思维链，帮助与最终用户建立信任。该解决方案的代码可在 [GitHub](https://github.com/aws-samples/amazon-bedrock-agents-cancer-biomarker-discovery) 上获取。

## 多模态生物标志物分析工作流

研究科学家在分析多模态患者生物标志物时提出的一些示例科研需求包括：

- 与总生存期相关的前五个生物标志物是哪些？请给我看一张高风险和低风险患者的 Kaplan Meier 图。
- 根据文献证据，肿瘤的哪些特性与 metagene X 活性和 EGFR 通路相关？
- 你能计算基因 X 低表达患者队列的影像生物标志物吗？请给我看肿瘤分割结果以及球形度和伸长率数值。

为了回答上述问题，研究科学家通常会使用多模态数据（包括临床、基因组和计算机断层扫描（CT）影像数据）运行生存分析流程（如下图所示）。

他们可能需要：

- 以编程方式预处理多样化的结构化和非结构化输入数据，并提取生物标志物（影像组学/基因组学/临床等）。
- 进行统计生存分析，例如 Cox** 比例风险模型**，并生成 Kaplan**-Meier 曲线**等可视化结果用于解读。
- 进行基因集富集分析（GSEA）以识别显著基因。
- 研究相关文献以验证初步发现。
- 将发现与影像基因组学生物标志物关联起来。

## 解决方案概述

我们提出一个基于大语言模型（LLM）agent 的框架，以增强并加速上述分析流程。正如 Andrew Ng 在 [Agentic Design Patterns Part 1](https://www.deeplearning.ai/the-batch/how-agents-can-improve-llm-performance/?ref=dl-staging-website.ghost.io) 中所述，LLM agent 的设计模式包括反思、工具使用、规划和多 agent 协作等能力。agent 基于专有和公开数据以及用户输入帮助用户完成操作。agent 负责编排基础模型（FM）、数据源、软件应用和用户对话之间的交互。此外，agent 会自动调用 API 来执行操作，并搜索知识库为这些操作补充信息。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/11/ML-16901-image2.png)

如上图所示，我们将解决方案定义为包含规划与推理，并包含多个子 agent，包括：

- **生物标志物数据库分析师**：将自然语言问题转换为 SQL 语句，并在存储生物标志物的 [Amazon Redshift](https://aws.amazon.com/redshift/) 数据库上执行。
- **统计学家**：使用带有 [lifelines 库](https://lifelines.readthedocs.io/en/latest/index.html) 的自定义容器构建生存回归模型，并生成 Kaplan Meier 图等可视化结果用于生存分析。
- **临床证据研究员**：使用 [PubMed](https://pubmed.ncbi.nlm.nih.gov/) API 搜索生物医学文献以获取外部证据。使用 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 进行检索增强生成（RAG），基于内部文献证据给出回答。
- **临床试验分析师**：使用 [Clinicaltrials.gov](https://clinicaltrials.gov/) API 搜索过往临床试验研究。
- **医学影像专家**：使用 [Amazon SageMaker jobs](https://docs.aws.amazon.com/sagemaker/latest/dg/distributed-training-options.html) 增强 agent 的能力，使其能够用临时集群触发异步作业来处理 CT 扫描图像。

## Amazon Bedrock Agents 深度解析

下图描述了通过 Web 应用与用户交互的 agent 的关键组件。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/11/ML-16901-image4.png)

### 大语言模型

LLM（例如 Anthropic 的 Claude 或 [Amazon Titan](https://aws.amazon.com/bedrock/titan) 模型）具备理解和生成类人文本的能力。它们使 agent 能够理解用户查询、生成恰当的响应并执行复杂的推理任务。在本次部署中，我们使用 [Anthropic 的 Claude 3 Sonnet](https://aws.amazon.com/bedrock/claude/) 模型。

### Prompt 模板

Prompt 模板是预设计的结构，用于引导 LLM 的响应和行为。这些模板有助于塑造 agent 的个性、语气以及理解科学术语的特定能力。通过精心设计 prompt 模板，你可以帮助确保 agent 在交互中保持一致性，并遵循特定准则或品牌调性。Amazon [Bedrock Agents 提供了默认的 prompt 模板](https://docs.aws.amazon.com/bedrock/latest/userguide/advanced-prompts.html)s，用于预处理用户查询、编排、知识库以及后处理模板。

### 指令

除 prompt 模板外，指令还描述 agent 的设计用途以及它可以如何与用户交互。你可以使用指令定义特定 agent 的角色，以及它在不同条件下如何使用可用的操作集。指令会与 prompt 模板一起作为每次调用 agent 时的上下文进行补充。你可以在 [agent_build.yaml](https://github.com/aws-samples/amazon-bedrock-agents-cancer-biomarker-discovery/blob/f8b431fb9f03f2f16a0c6243f3114e94790158ff/agent_build.yaml#L841) 中查看我们如何定义 agent 指令。

### 用户输入

用户输入是与 agent 交互的起点。agent 处理该输入，理解用户的意图和上下文，然后构建合适的思维链。agent 将判断自己是否拥有回答用户问题所需的信息，或者是否需要[向用户请求更多信息](https://docs.aws.amazon.com/bedrock/latest/userguide/the%20agent%0dagents-the%20user%0duser-input.html)。如果需要用户提供更多信息，agent 会组织问题以请求补充信息。Amazon Bedrock Agents 设计为可处理各种用户输入，从简单查询到复杂的多轮对话。

### Amazon Bedrock Knowledge Bases

Amazon Bedrock 知识库是一个信息存储库，其中的信息已从源数据向量化，agent 可以访问这些信息来补充其响应。通过集成 Amazon Bedrock 知识库，agent 能够提供更准确、更符合上下文的答案，特别是对于 LLM 通用知识可能未覆盖的领域特定查询。在该解决方案中，我们纳入了非小细胞肺癌相关文献，用以表示属于客户的内部证据。

### 操作组

[操作组](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-action-create.html)是 Amazon Bedrock Agents 可执行的特定函数或 API 调用集合。通过定义操作组，你可以将 agent 的能力扩展到单纯的对话之外，使其能够执行实际的任务。该解决方案通过操作组为 agent 提供以下工具。源代码可在仓库的 [ActionGroups](https://github.com/aws-samples/amazon-bedrock-agents-cancer-biomarker-discovery/tree/main/ActionGroups) 文件夹中找到。

- **Text2SQL 与 Redshift 数据库调用**：Text2SQL 操作组使 agent 能够获取 Redshift 数据库的相关 schema，针对特定子问题生成 SQL 查询，通过额外调用 LLM 来审查和优化 SQL 查询，最后执行 SQL 查询从 Redshift 数据库检索相关结果。该操作组包含这些操作的 OpenAPI schema。如果查询执行返回的结果超过[可接受的 Lambda 返回载荷大小](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas.html)，该操作组会改为将数据写入一个中间的 [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/s3) 位置。
- **使用自定义容器进行科学分析：** 科学分析操作组使 agent 能够使用自定义容器，借助特定的库和 API 执行科学分析。在该解决方案中，这些任务包括拟合生存回归模型和生成用于生存分析的 Kaplan Meier 图。自定义容器使用户能够验证结果可重复，且库版本或算法逻辑不会出现偏差。该操作组为每项所需任务定义了带特定参数的函数。Kaplan Meier 图会输出到 Amazon S3。
- **使用 PubMed 获取生物医学文献证据**：PubMed 操作组使 agent 能够与 PubMed [Entrez Programming Utilities](https://www.ncbi.nlm.nih.gov/books/NBK25501/)（E-utilities）API 交互以获取生物医学文献。该操作组包含 OpenAPI schema，可接受用户查询以在 PubMed 中搜索文章。Lambda 函数提供了一种便捷的方式，用于从 PubMed 数据库搜索和检索科学文章。它允许用户使用特定查询进行搜索、检索文章元数据，并处理 API 交互的复杂性。总体而言，agent 使用该操作组，充当研究人员查询与 PubMed 数据库之间的桥梁，简化访问和处理生物医学研究信息的过程。
- **使用 SageMaker 作业进行医学影像处理**：医学影像操作组使 agent 能够通过触发 SageMaker 处理作业来处理特定患者群体的 CT 扫描图像。我们复用了这篇[之前的博文](https://aws.amazon.com/blogs/machine-learning/predict-lung-cancer-survival-status-using-multimodal-data-on-amazon-sagemaker-jumpstart/)中的医学影像组件。

该操作组创建患者级别的三维影像组学特征，用于解释 CT 扫描中观察到的肿瘤的大小、形状和视觉属性，并将其存储在 Amazon S3 中。如下图所示，每次患者研究都会执行以下步骤：

- 读取 CT 扫描和肿瘤分割的 2D DICOM 切片文件，将它们组合成 3D 体数据，并以 NIfTI 格式保存。
- 对齐 CT 体数据与肿瘤分割结果，以便将计算聚焦在肿瘤内部。
- 使用 [pyradiomics](https://www.radiomics.io/pyradiomics.html) 库计算描述肿瘤区域的影像组学特征。它提取八类共 120 个影像组学[特征](https://pyradiomics.readthedocs.io/en/latest/features.html)，例如肿瘤感兴趣区域内强度分布与共现的统计表征，以及从形态学角度描述肿瘤的基于形状的测量值。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/12/11/ML-16901-image5.jpg)

### 思维链推理与响应

我们来看几个与主管 agent 一起进行思维链推理和执行的示例。主管 agent 解读用户问题，生成一系列步骤，并与相关子 agent 一起执行这些步骤。

为回答以下问题，agent 使用可用的子 agent 设置了以下编排工作流。

**问题**：对于接受过化疗的患者，与总生存期相关的最佳基因表达生物标志物（p 值最低）是什么？请给我看一张列出前五个生物标志物的条形图。

- 我将生成一个计划  查询生物标志物数据库中患者的数据 运行生存分析以找出 p 值 获取 p 值最低的前 5 个生物标志物并创建可视化图表
- 我将请求生物标志物数据库分析师  获取数据库 schema 并生成 SQL 通过自我评估审查并优化 SQL 执行 SQL 查询并将结果存储在 Amazon S3 中
- 我将请求统计学家  从数据库分析师处检索生成的数据集 使用自定义容器 API 拟合生存回归模型 检索模型拟合汇总结果并按最低 p 值对前五个生物标志物排序 生成包含前五个生物标志物的条形图

**主管 agent 响应**：基因生物标志物 ‘gdf15’ 的 p 值最低，为 0.02，因此 gdf15 是最佳基因生物标志物。条形图显示了前 5 个生物标志物及其对应的 p 值。

**问题**：根据文献证据，肿瘤的哪些特性与 metagene X 活性和 EGFR 通路相关？

- 我将生成一个计划  将请求路由给临床证据研究员
- 我将请求临床证据研究员  查询内部知识库以获取内部证据 查询 PubMed 以获取外部文献 汇总结果并附上引用

**主管 agent 响应**：根据内部和外部证据，影像特性、分子特征、耐药性与治疗方法、信号通路与机制、新兴治疗策略 ，以及细胞特性与 EGFR 通路相关。

**问题**：你能计算基因 X 低表达患者队列的影像生物标志物吗？请给我看肿瘤分割结果以及球形度和伸长率数值。

- 我将生成一个计划  查询生物标志物数据库以找到 gdf15 值最低的患者队列 触发医学影像分析作业以处理该队列的 CT 扫描图像 汇总影像作业的结果。
- 我将请求生物标志物数据库分析师  获取数据库 schema 并生成 SQL 通过自我评估审查并优化 SQL 执行 SQL 查询并检索患者 id
- 我将请求医学影像专家  从数据库分析师处获取患者队列 使用 SageMaker 医学影像作业为队列中每名患者计算影像生物标志物 在作业完成通知后检索并分析结果 提取所需生物标志物并可视化肿瘤分割输出图像

**主管 agent 响应**：用于处理患者医学影像的计算影像生物标志物作业已触发，现已完成。根据患者的基因 X 表达值筛选出了以下患者。患者肿瘤的伸长率和球形度数值连同相应的肿瘤分割图像一并显示。

# 结论

研究科学家在识别和验证特定于癌症亚型、且与干预措施和患者结局相关的生物标志物方面面临重大挑战。现有工具往往需要大量人工步骤，才能跨不同数据源进行搜索、总结和生成洞见。本文展示了 Amazon Bedrock Agents 如何通过多 agent 协作和相关工具提供灵活的框架，帮助加速这一关键的发现过程。

通过提供肺癌生存的示例分析流程，我们展示了这些 agentic 工作流如何利用自然语言界面、数据库检索、统计建模、文献检索和医学图像处理，将复杂的研究查询转化为可付诸行动的洞见。该 agent 使用了自我审查和规划等高级智能能力，将任务分解为逐步分析，并透明地展示最终答案背后的思维链。尽管这项技术对药物研究和临床试验结局的潜在影响仍有待充分实现，但类似的解决方案有助于自动化数据分析和假设验证任务。

该解决方案的代码可在 [GitHub](https://github.com/aws-samples/amazon-bedrock-agents-cancer-biomarker-discovery) 上获取，我们鼓励你探索并在此基础上构建。有关 Amazon Bedrock Agents 的入门示例，请查看 [Amazon Bedrock Agents GitHub 仓库](https://github.com/aws-samples/amazon-bedrock-samples/tree/main/agents-and-function-calling/bedrock-agents)。
