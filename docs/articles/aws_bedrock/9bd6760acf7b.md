# 构建更聪明的 AI agent：AgentCore 长期记忆深度解析

构建能够记住用户交互的 AI agent，需要的远不止存储原始对话。虽然 Amazon Bedrock AgentCore 的短期记忆能够捕捉即时上下文，但真正的挑战在于把这些交互转化为跨越会话的、持久且可付诸行动的知识。正是这些信息，把转瞬即逝的交互变为用户与 AI agent 之间有意义的、持续的关系。在本文中，我们将揭开 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) Memory 长期记忆系统如何运作的面纱。

如果你刚接触 AgentCore Memory，我们建议先阅读介绍性博客文章：[Amazon Bedrock AgentCore Memory：构建上下文感知的 agent](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-agentcore-memory-building-context-aware-agents/)。简而言之，AgentCore Memory 是一项全托管服务，它通过同时提供短期工作记忆和长期智能记忆能力，让开发者能够构建上下文感知的 AI agent。

## 持久记忆的挑战

人类在交互时并不只是记住确切的对话内容——我们会提取含义、识别模式，并随着时间建立理解。要让 AI agent 以同样的方式响应，需要解决若干复杂挑战：

- agent 记忆系统必须区分有意义的洞察与日常闲聊，判断哪些话语值得长期存储、哪些只需临时处理。用户说“我是素食者”应当被记住，而“嗯，让我想想”则不必。
- 记忆系统需要跨时间识别相关信息并加以合并，同时不产生重复或矛盾。当用户在 1 月提到自己对贝类过敏、在 3 月又提到“不能吃虾”时，这些内容需要被识别为相关事实，并与已有知识整合，而不产生重复或矛盾。
- 记忆必须按时间上下文的顺序处理。随时间变化的偏好（例如用户去年喜欢某家餐厅的辣味鸡肉，但今天偏好温和口味）需要谨慎处理，确保在保留历史上下文的同时，尊重最新的偏好。
- 当记忆存储增长到包含数千乃至数百万条记录时，快速找到相关记忆会成为一项重大挑战。系统必须在全面保留记忆与高效检索之间取得平衡。

解决这些问题需要精密的提取、整合与检索机制，远超简单的存储。Amazon Bedrock AgentCore Memory 通过实现一条有研究支撑的长期记忆 pipeline 来应对这些复杂性，该 pipeline 模拟人类的认知过程，同时保持企业级应用所需的精度与规模。

## AgentCore 长期记忆的工作方式

当 agentic 应用向 AgentCore Memory 发送对话事件时，会启动一条 pipeline，通过多阶段流程把原始对话数据转化为结构化、可检索的知识。让我们逐一了解该系统的各个组件。 ![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/13/ML-19668-2.png)

### 1. 记忆提取：从对话到洞察

当新事件被存入短期记忆后，一个异步提取流程会分析对话内容，识别出有意义的信息。该流程借助大语言模型（LLM）理解上下文，并提取应当保留在长期记忆中的相关细节。提取引擎会结合先前的上下文处理传入消息，按预定义的 schema 生成记忆记录。作为开发者，你可以配置一个或多个 Memory 策略，只提取与应用需求相关的信息类型。提取流程支持三种内置记忆策略：

- **语义记忆**：提取事实与知识。示例：  `"The customer's company has 500 employees across Seattle, Austin, and Boston"`
- **用户偏好**：结合上下文捕捉显性与隐性偏好。示例：  `{“preference”: "Prefers Python for development work", “categories”: [“programming”, ”code-style”], “context”: “User wants to write a student enrollment website”}`
- **摘要记忆**：按会话范围，为不同主题下的对话创建持续的叙述，并以结构化 XML 格式保留关键信息。示例：  `<topic=“Material-UI TextareaAutosize inputRef Warning Fix Implementation”> A developer successfully implemented a fix for the issue in Material-UI where the TextareaAutosize component gives a "Does not recognize the 'inputRef' prop" warning when provided to OutlinedInput through the 'inputComponent' prop. </topic>`

对每种策略，系统都会结合时间戳处理事件，以保持上下文的连续性并支持冲突消解。单个事件可以提取出多条记忆，且每种记忆策略独立运行，从而支持并行处理。

### 2. 记忆整合

系统并非简单地把新记忆追加到现有存储中，而是执行智能整合，合并相关信息、解决冲突并将冗余降到最低。随着新信息的到来，这种整合确保 agent 的记忆保持一致且始终最新。

整合流程如下：

- **检索**：对每条新提取的记忆，系统从同一 namespace 和同一策略中检索语义上最相似的前若干条已有记忆。
- **智能处理**：新记忆与检索到的记忆会连同整合 prompt 一起发送给 LLM。该 prompt 保留语义上下文，从而避免不必要的更新（例如“loves pizza”和“likes pizza”被视为基本相同的信息）。在保持这些核心原则的前提下，该 prompt 被设计为处理各种场景：  `You are an expert in managing data. Your job is to manage memory store. Whenever a new input is given, your job is to decide which operation to perform. Here is the new input text. TEXT: {query} Here is the relevant and existing memories MEMORY: {memory} You can call multiple tools to manage the memory stores...`  基于该 prompt，LLM 决定应采取的操作：  **ADD**：当新信息与已有记忆不同时  **UPDATE**：当新知识补充或更新已有记忆时，增强已有记忆  **NO-OP**：当信息冗余时
- **向量存储更新**：系统执行确定的操作，并把过时的记忆标记为 INVALID 而不是立即删除，从而维护不可变的审计轨迹。

这种方式确保矛盾信息得到消解（优先采用较新的信息）、重复被降到最低，并且相关记忆得到恰当的合并。

### 处理边界情况

整合流程能够优雅地处理若干棘手场景：

- **乱序事件**：虽然系统在会话内按时间顺序处理事件，但通过细致的时间戳跟踪与整合逻辑，它也能处理迟到的事件。
- **信息冲突**：当新信息与已有记忆矛盾时，系统优先考虑新近性，同时保留先前状态的记录：  `Existing: "Customer budget is \$500" New: "Customer mentioned budget increased to \$750" Result: New active memory with \$750, previous memory marked inactive`
- **记忆失败**：如果某条记忆的整合失败，不会影响其他记忆。系统使用指数退避与重试机制来处理瞬时故障。如果整合最终仍然失败，该记忆仍会被加入系统，以帮助避免潜在的信息丢失。

## 高级自定义 memory 策略配置

虽然内置记忆策略覆盖了常见用例，但 AgentCore Memory 认识到不同领域需要量身定制的记忆提取与整合方式。系统支持[带覆盖项的内置策略](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-custom-strategy.html)，通过自定义 prompt 扩展内置的提取与整合逻辑，让团队能够按自身特定需求调整记忆处理方式。为保持系统兼容性，并聚焦于判据与逻辑而非输出格式，自定义 prompt 帮助开发者定制提取或过滤哪些信息、记忆应如何整合，以及如何消解矛盾信息之间的冲突。

AgentCore Memory 还支持为记忆提取和整合选择自定义模型。这种灵活性帮助开发者根据自身需求在准确率与延迟之间取得平衡。你可以在创建 *memory_resource* 时通过 API 将其定义为策略覆盖项，也可以通过控制台操作（如下方的控制台截图所示）。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/14/ML-19668-4.png)

除了覆盖功能之外，我们还提供[自管理策略](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-self-managed-strategies.html)，让你完全掌控自己的记忆处理 pipeline。使用自管理策略，你可以用任意模型或 prompt 实现自定义的提取与整合算法，同时借助 AgentCore Memory 完成存储与检索。此外，通过 Batch API，你可以把提取出的记录直接导入 AgentCore Memory，同时完全保有自己的处理逻辑所有权。

### 性能特征

我们在三个公开基准数据集上评估了内置记忆策略，以考察长期对话记忆的不同方面：

- **LoCoMo**：通过机器-人工 pipeline 生成的、包含基于人设的交互与时间事件图的多会话对话。用于检验在贴近真实的对话模式下的长期记忆能力。
- **LongMemEval**：评估跨多个会话和较长时间跨度下，长对话中的记忆保持能力。为提升评估效率，我们随机采样了 200 个问答对。
- **PrefEval**：使用 21 个会话的实例，在 20 个主题上检验偏好记忆，评估系统随时间记住并一致应用用户偏好的能力。
- **PolyBench-QA：** 一个问答数据集，包含 80 条轨迹中的 807 个问答（QA）对，采集自一个在 PolyBench 中解题的编码 agent。

我们使用两个标准指标：***正确性*** 与 ***压缩率***。基于 LLM 的正确性评估系统在需要时能否正确回忆并使用已存储的信息。压缩率定义为输出记忆的 token 数 / 完整上下文的 token 数，用于评估记忆系统存储信息的效率。压缩率越高，说明系统在保留关键信息的同时降低了存储开销。这一压缩率直接带来更快的推理速度和更低的 token 消耗——这是大规模部署 agent 时最关键的考量，因为它能更高效地处理大量对话历史并降低运营成本。

| **记忆类型** | **数据集** | **正确性** | **压缩率** |
| --- | --- | --- | --- |
| **RAG 基线（完整对话历史）** | LoCoMo | 77.73% | 0% |
| LongMemEval-S | 75.2% | 0% |  |
| PrefEval | 51% | 0% |  |
| **语义记忆** | LoCoMo | 70.58% | 89% |
| LongMemEval-S | 73.60% | 94% |  |
| **偏好记忆** | PrefEval | 79% | 68% |
| **摘要** | PolyBench-QA | 83.02% | 95% |

检索增强生成（RAG）基线由于可以访问完整的对话历史，在事实类问答任务上表现良好，但在偏好推断上较为吃力。记忆系统取得了很好的实用权衡：虽然信息压缩会使某些事实类任务的正确性略有下降，但它为实现可扩展部署提供了 89-95% 的压缩率，使上下文规模保持有界，并在各自的专门用例中表现有效。

对于需要推断的更复杂任务（理解用户偏好或行为模式），记忆在性能准确率和存储效率两方面都展现出明显优势——在这些用例中，提取出的洞察比原始对话数据更有价值。

除准确率指标之外，AgentCore Memory 还提供了生产部署所需的性能特征。

- 对标准对话而言，在触发提取后，提取与整合操作会在 20-40 秒内完成。
- 语义搜索检索（`retrieve_memory_records` API）约在 200 毫秒内返回结果。
- 并行处理架构使多个记忆策略能够独立处理；因此，不同记忆类型可以同时处理而互不阻塞。

这些延迟特性与高压缩率相结合，使系统在大规模部署中高效管理海量对话历史的同时，保持响应灵敏的用户体验。

## 长期记忆最佳实践

要最大化 agent 中长期记忆的效果：

- **选择合适的记忆策略**：选择与你的用例相符的内置策略，或为领域特定需求创建自定义策略。语义记忆捕捉事实性知识，偏好记忆面向个人偏好，摘要记忆则提炼复杂信息以更好地管理上下文。例如，客服 agent 可能使用语义记忆记录客户的交易历史和过往问题，而摘要记忆则针对不同主题为当前的客服对话和故障排查工作流生成简短叙述。
- **设计有意义的 namespace**：让 namespace 的结构反映应用的层级。这同时也能实现精确的记忆隔离与高效检索。例如，用 `customer-support/user/john-doe` 存放单个 agent 的记忆，用 `customer-support/shared/product-knowledge` 存放团队共享信息。
- **监控整合模式**：定期查看正在创建（使用 `list_memories` 或 `retrieve_memory_records` API）、更新或跳过了哪些记忆。这有助于改进提取策略，也帮助系统捕捉更贴合你用例的相关信息。
- **为异步处理做规划：** 记住长期记忆的提取是异步的。设计应用时要处理事件摄入与记忆可用之间的延迟。可以考虑在长期记忆于后台处理和整合期间，用短期记忆满足即时检索需求。你可能还需要实现回退机制或加载状态，以在处理的延迟期间管理用户预期。

## 结论

Amazon Bedrock AgentCore Memory 的长期记忆系统代表了构建 AI agent 方面的一项重大进步。它结合了精密的提取算法、智能的整合流程和不可变的存储设计，为那些能够随时间学习、适应并改进的 agent 提供了稳健的基础。

该系统背后的科学——从有研究支撑的 prompt 到创新的整合工作流——确保你的 agent 不只是记住，而是理解。这把一次性交互转化为持续的学习体验，创造出随着每次对话而更有帮助、更个性化的 AI agent。
