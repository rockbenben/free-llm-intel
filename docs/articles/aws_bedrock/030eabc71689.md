# 使用 LLMPerf 和 LiteLLM 对 Amazon Bedrock 上的定制模型进行基准测试

开放的基础模型（FM）让组织能够针对自身特定领域或任务进行 fine-tuning，从而构建定制化的 AI 应用，同时保留对成本和部署的控制权。然而，部署可能占去相当大的一部分工作量，往往需要消耗项目 30% 的时间，因为工程师必须通过反复测试仔细优化实例类型并配置服务参数。这一过程既复杂又耗时，需要专业知识并经过多轮迭代测试才能达到预期的性能。

[Amazon Bedrock Custom Model Import](https://aws.amazon.com/bedrock/custom-model-import/) 通过提供简洁的 API 来部署和调用模型，简化了自定义模型的部署。你可以上传模型权重，让 AWS 负责最优的全托管部署。这确保部署具备高性能和成本效益。Amazon Bedrock Custom Model Import 还支持自动扩缩容，包括缩容至零。当模型闲置且 5 分钟内没有调用时，它会缩容至零，你只需按 5 分钟为增量支付实际用量。它同样支持扩容：当需要更高并发时，会自动增加活跃模型副本的数量。这些特性使 Amazon Bedrock Custom Model Import 成为希望在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上使用自定义模型的组织的一个有吸引力的方案，既简单又经济高效。

在将这些模型部署到生产环境之前，使用基准测试工具评估其性能至关重要。这些工具有助于主动发现潜在的生产问题（例如限流），并验证部署能否承受预期的生产负载。

本文开启了一个博客系列，探讨 Amazon Bedrock Custom Model Import 上的 DeepSeek 与开放 FM。文中介绍如何使用流行的开源工具 LLMPerf 和 LiteLLM，对 Amazon Bedrock 中的自定义模型进行性能基准测试。文中附带一个 [notebook](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/custom-models/import_models/llama-3/benchmark-deepseek-r1-distill-llama-llmperf.ipynb)，其中包含部署 [DeepSeek-R1-Distill-Llama-8B](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Llama-8B/tree/main) 模型的分步说明，但同样的步骤也适用于 Amazon Bedrock Custom Model Import 支持的任何其他模型。

## 前提条件

本文需要有一个 Amazon Bedrock 自定义模型。如果你的 AWS 账户中还没有，请按照[使用 Amazon Bedrock Custom Model Import 部署 DeepSeek-R1 蒸馏版 Llama 模型](https://aws.amazon.com/blogs/machine-learning/deploy-deepseek-r1-distilled-llama-models-with-amazon-bedrock-custom-model-import/)中的说明操作。

## 使用开源工具 LLMPerf 和 LiteLLM 进行性能基准测试

要进行性能基准测试，你将使用 [LLMPerf](https://github.com/ray-project/llmperf)，这是一个广受欢迎的基础模型基准测试开源库。LLMPerf 通过创建并发的 Ray Client 并分析其响应，在模型调用 API 上模拟负载测试。LLMPerf 的一大优势是对基础模型 API 的广泛支持，其中包括 [LiteLLM](https://docs.litellm.ai/docs/)，后者支持 Amazon Bedrock 上[所有可用模型](https://docs.litellm.ai/docs/providers/bedrock)。

## 使用 LiteLLM 设置自定义模型调用

LiteLLM 是一个多用途的开源工具，既可用作 Python SDK，也可用作proxy 服务器（AI 网关），通过标准化格式访问 100 多种不同的 FM。LiteLLM 会对输入进行标准化，以匹配各 FM 提供商特定的 endpoint 要求。它支持 Amazon Bedrock API，包括 `InvokeModel` 和 Converse API，也支持 Amazon Bedrock 上可用的 FM，包括导入的自定义模型。

要用 LiteLLM 调用自定义模型，需要使用 model 参数（请参阅[有关 LiteLLM 的 Amazon Bedrock 文档](https://docs.litellm.ai/docs/providers/bedrock)）。这是一个遵循 `bedrock/provider_route/model_arn` 格式的字符串。

`provider_route` 指明要使用的请求/响应规范的 LiteLLM 实现。DeepSeek R1 模型可以通过 [DeepSeek R1 provider route](https://docs.litellm.ai/docs/providers/bedrock#deepseek-r1) 使用其自定义 chat template 来调用，也可以通过 [Llama provider route](https://docs.litellm.ai/docs/providers/bedrock#deepseek-not-r1) 使用 Llama chat template 来调用。

`model_arn` 是所导入模型的 Amazon Resource Name（ARN）。你可以在控制台中获取导入模型的 ARN，也可以通过发送 [ListImportedModels](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_ListImportedModels.html) 请求来获取。

例如，下面的脚本使用 DeepSeek R1 chat template 调用自定义模型。

```
import time
from litellm import completion

while True:
    try:
        response = completion(
            model=f"bedrock/deepseek_r1/{model_id}",
            messages=[{"role": "user", "content": """Given the following financial data:
        - Company A's revenue grew from $10M to $15M in 2023
        - Operating costs increased by 20%
        - Initial operating costs were $7M
        
        Calculate the company's operating margin for 2023. Please reason step by step."""},
                      {"role": "assistant", "content": "<think>"}],
            max_tokens=4096,
        )
        print(response['choices'][0]['message']['content'])
        break
    except:
        time.sleep(60)
```

确认导入模型的调用参数无误后，就可以配置 LLMPerf 进行基准测试。

## 使用 LLMPerf 配置 token 基准测试

为了对性能进行基准测试，LLMPerf 使用分布式计算框架 [Ray](https://github.com/ray-project/ray) 来模拟真实负载。它会派生出多个远程客户端，每个客户端都能向模型调用 API 发送并发请求。这些客户端以实现为并行执行的 [actor](https://docs.ray.io/en/latest/ray-core/actors.html)。`llmperf.requests_launcher` 负责在多个 Ray Client 之间分配请求，并支持模拟各种负载场景和并发请求模式。与此同时，每个客户端都会在请求过程中收集性能指标，包括延迟、吞吐量和错误率。

两个关键的性能指标是 *延迟*（latency）和 *吞吐量*（throughput）：

- 延迟指处理单个请求所需的时间。
- 吞吐量衡量每秒生成的 token 数量。

为 FM 选择合适的服务配置，通常需要尝试不同的 batch size，同时密切监控 GPU 利用率，并考虑可用内存、模型规模和工作负载的特定要求等因素。要了解更多信息，请参阅[优化 AI 响应速度：Amazon Bedrock 低延迟推理实用指南](https://aws.amazon.com/blogs/machine-learning/optimizing-ai-responsiveness-a-practical-guide-to-amazon-bedrock-latency-optimized-inference/)。尽管 Amazon Bedrock Custom Model Import 通过提供预优化的服务配置简化了这一过程，但验证部署的延迟和吞吐量仍然至关重要。

首先配置 `token_benchmark.py`，这是一个便于配置基准测试的示例脚本。在脚本中，你可以定义以下参数：

- **LLM API**：使用 LiteLLM 调用 Amazon Bedrock 自定义导入的模型。
- **Model**：与上一节类似，定义要调用的 route、API 和模型 ARN。
- **输入 token 的均值/标准差**：用于概率分布的参数，输入 token 数量将从该分布中采样。
- **输出 token 的均值/标准差**：用于概率分布的参数，输出 token 数量将从该分布中采样。
- **并发请求数**：应用在使用时可能需要支持的用户数量。
- **完成的请求数**：测试中要发送到 LLM API 的请求总数。

下面的脚本展示了调用模型的示例。有关导入自定义模型并运行基准测试的分步说明，请参阅[这个 notebook](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/custom-models/import_models/llama-3/benchmark-deepseek-r1-distill-llama-llmperf.ipynb)。

```
python3 ${{LLM_PERF_SCRIPT_DIR}}/token_benchmark_ray.py \\
--model "bedrock/llama/{model_id}" \\
--mean-input-tokens {mean_input_tokens} \\
--stddev-input-tokens {stddev_input_tokens} \\
--mean-output-tokens {mean_output_tokens} \\
--stddev-output-tokens {stddev_output_tokens} \\
--max-num-completed-requests ${{LLM_PERF_MAX_REQUESTS}} \\
--timeout 1800 \\
--num-concurrent-requests ${{LLM_PERF_CONCURRENT}} \\
--results-dir "${{LLM_PERF_OUTPUT}}" \\
--llm-api litellm \\
--additional-sampling-params '{{}}'
```

测试结束时，LLMPerf 会输出两个 JSON 文件：一个包含聚合指标，另一个为每次调用分别记录条目。

### 缩容至零与冷启动延迟

需要记住的一点是：由于 Amazon Bedrock Custom Model Import 在模型闲置时会缩容至零，你需要先发起一次请求，以确保至少有一个活跃的模型副本。如果收到模型尚未就绪的错误，需要等待大约 10 秒、最长 1 分钟，让 Amazon Bedrock 准备好至少一个活跃的模型副本。就绪后，再次运行测试调用，然后继续基准测试。

## DeepSeek-R1-Distill-Llama-8B 的示例场景

假设有一个托管在 Amazon Bedrock Custom Model Import 上的 `DeepSeek-R1-Distill-Llama-8B` 模型，支撑一个并发请求不超过 2 个的低流量 AI 应用。为考虑波动，你可以调整 prompt 和 completion 的 token 数量参数。例如：

- 客户端数量：2
- 输入 token 平均数量：500
- 输入 token 数量的标准差：25
- 输出 token 平均数量：1000
- 输出 token 数量的标准差：100
- 每个客户端的请求数：50

## 分析 LLMPerf 的性能结果并使用 Amazon CloudWatch 估算成本

借助 LLMPerf，你可以对在 Amazon Bedrock 中提供服务的自定义模型进行性能基准测试，而无需深入检查 Amazon Bedrock Custom Model Import 部署的服务属性和配置细节。这些信息很有价值，因为它们代表了应用最终用户的预期体验。

此外，基准测试还可以作为成本估算的有用工具。通过 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/)，你可以观察到 Amazon Bedrock Custom Model Import 为响应负载测试而扩展到的活跃模型副本数量。ModelCopy 作为 CloudWatch 指标暴露在 AWS/Bedrock 命名空间中，并以导入模型的 ARN 作为标签上报。`ModelCopy` 指标的图表如下图所示。这些数据有助于估算成本，因为计费依据是给定时刻活跃模型副本的数量。

## 结论

尽管 Amazon Bedrock Custom Model Import 简化了模型部署和扩缩容，但性能基准测试对于预测生产性能，以及在成本、延迟和吞吐量等关键指标上比较模型仍然必不可少。
