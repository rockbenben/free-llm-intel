# 用 AWS 生成式 AI 服务变革零售

线上零售商长期面临一个难题：顾客在线下单时难以判断服装是否合身、穿上效果如何，这导致退货率上升、购买信心下降。代价是什么？收入流失、运营开销增加以及客户不满。与此同时，消费者越来越期待沉浸式、可交互的购物体验，以弥合线上零售与线下零售之间的差距。采用虚拟试穿技术的零售商可以提升购买信心、降低退货率，并直接转化为盈利能力与客户满意度的改善。本文演示如何在 AWS 上使用 Amazon Nova Canvas、Amazon Rekognition 和 Amazon OpenSearch Serverless 构建虚拟试穿与推荐解决方案。无论你是开发零售解决方案的 AWS Partner，还是正在探索生成式 AI 转型的零售商，你都将了解该解决方案的架构、实现方法以及部署时的关键考量。

你可以在 [GitHub repo](https://github.com/aws-samples/sample-genai-virtual-tryon) 中找到用于在你的 AWS 账户中部署该解决方案的代码库。

## **解决方案概览**

该解决方案演示如何构建一个 AI 驱动的无服务器零售解决方案。该服务提供四项集成能力：

- 虚拟试穿：通过 [Amazon Nova Canvas](https://aws.amazon.com/nova/models/) 和 [Amazon Rekognition](https://aws.amazon.com/rekognition/) 生成顾客穿着或使用产品的逼真视觉呈现
- 智能推荐：使用 Amazon [Titan Multimodal Embeddings](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-multiemb-models.html) 提供具备视觉感知能力的商品建议，从而理解风格关联与视觉相似度
- 智能搜索：通过理解客户意图的目标导向智能，实现自然语言的商品发现。使用 [OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/) 进行向量相似度匹配
- 分析与洞察：使用 Amazon [DynamoDB](https://aws.amazon.com/dynamodb/?trk=292f3097-d805-46ec-9150-f185787f6c21&trk=292f3097-d805-46ec-9150-f185787f6c21&sc_channel=ps&sc_channel=ps&ef_id=EAIaIQobChMIrMzin-e9kgMVWW5HAR2gBgjIEAAYASAAEgLgSfD_BwE:G:s&s_kwcid=AL!4422!3!651751059996!e!!g!!dynamodb!19852662209!145019198137&gclid=EAIaIQobChMIrMzin-e9kgMVWW5HAR2gBgjIEAAYASAAEgLgSfD_BwE) 跟踪客户交互、偏好与趋势，以优化库存与商品陈列决策

该架构使用无服务器 AWS 服务以获得可扩展性，并采用模块化设计，让你既可以实现单项能力，也可以部署完整解决方案。

## **预构建的架构组件**

该解决方案运行在 AWS 无服务器基础设施之上，包含五个专用 AWS Lambda 函数，每个都针对特定任务进行优化：Web 前端（chatbot 界面）、虚拟试穿处理、推荐生成、数据集摄取和智能搜索。该架构使用 S3 存储桶进行安全存储，使用 Amazon OpenSearch Serverless 进行向量相似度搜索，并使用 DynamoDB 进行实时分析跟踪。

### **可扩展性与部署**

该解决方案使用 AWS Serverless Application Model（AWS SAM）构建，只需一条命令即可部署整套方案，并根据需求自动扩展。预留并发限制有助于防止资源争用，而 Amazon API Gateway 缓存和预签名 URL 则可优化性能。微服务方式允许各个组件独立扩展和更新。

## **先决条件**

在开始部署流程之前，请确认已配置以下先决条件：

**AWS 账户设置**

- 一个具备管理员权限的有效 AWS 账户
- 已安装 AWS Command Line Interface（AWS CLI），并配置了相应凭证
- 该解决方案要求 Amazon Nova Canvas、Amazon Titan Multimodal Embeddings、Amazon Rekognition 和 Amazon OpenSearch Serverless 位于同一 Region。建议部署在 US East (N. Virginia) – us-east-1。

Amazon Bedrock 模型的区域可用性会随时间变化。在 us-east-1 以外的 Region 部署之前，请查阅 [Amazon Bedrock model support by Region](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html) 页面和 [AWS Regional Services List](https://aws.amazon.com/about-aws/global-infrastructure/regional-product-services/)，确认所有所需模型均受支持。

[Amazon Bedrock foundation models](https://aws.amazon.com/about-aws/whats-new/2025/10/amazon-bedrock-automatic-enablement-serverless-foundation-models/) 现在会在你的账户中首次调用时自动启用，覆盖所有 AWS 商业区域。该解决方案所需的模型（Amazon Nova Canvas 和 Amazon Titan Embeddings）将在应用程序首次调用时自动激活——无需手动启用。

**注意：**对于首次使用 Amazon Bedrock 的用户，由于服务需要预置访问权限，首次模型调用可能会多花几秒钟。

**AWS 服务权限**

**开发环境**

## **部署 SAM 模板**

部署流程使用 AWS SAM 定义并部署所有基础设施组件。请按以下步骤构建并部署应用程序。

### **步骤 1：仓库设置**

首先[克隆仓库](https://github.com/aws-samples/sample-genai-virtual-tryon)并进入项目目录：

```
git clone https://github.com/aws-samples/sample-genai-virtual-tryon.git

cd VirtualTryOne-GenAI
```

查看项目结构以了解代码库的组织方式：

- `template.yaml`：定义所有 AWS 资源的 SAM 模板
- `requirements.txt`：Lambda 函数的 Python 依赖
- Lambda 函数源文件（*.py）
- 时尚数据集与示例图像

### **步骤 2：安装依赖**

```
pip install -r requirements.txt
```

该命令会安装图像处理、AWS SDK 交互、OpenSearch 连接及其他核心功能所需的软件包。

### **步骤 3：SAM 构建流程**

构建 SAM 应用程序，它会打包 Lambda 函数并准备部署产物：

```
sam build
```

构建过程会：

- 为每个 Lambda 函数创建部署包
- 解析依赖并创建层（layer）包
- 校验 SAM 模板语法
- 准备用于部署的 CloudFormation 模板

### **步骤 4：引导式部署**

首次部署时，请使用引导式部署选项：

```
sam deploy --guided
```

引导式部署会提示你输入：

- 堆栈名称（选择唯一的名称）
- 用于部署的 AWS Region
- 用于定制的参数值
- 资源创建的确认
- IAM 角色创建权限

该过程会创建一个 `samconfig.toml` 文件，保存你的部署偏好以供后续部署使用。

### **步骤 5：后续部署**

完成初始设置后，使用简化后的部署命令：

```
sam deploy
```

该命令会使用 `samconfig.toml` 中保存的配置，以确保部署一致。

**安全警告**：基础部署的 API Gateway 端点没有身份验证。我们不建议在未实现身份验证的情况下将其部署到生产环境（例如 *Amazon Cognito* 或 *API Gateway authorizers*）。

此外，请在处理之前对所有用户上传的图像实施图像校验和内容审核。使用 [Amazon Rekognition Content Moderation](https://docs.aws.amazon.com/rekognition/latest/dg/procedure-moderate-images.html) 检测不当或不安全的内容，并在 API Gateway 或 Lambda 层校验文件类型、大小和尺寸。在图像进入 S3 存储或 Nova Canvas 管线之前，拒绝未通过审核检查的图像。这有助于防止恶意文件和不当内容被处理、存储或返回给其他用户。

### **步骤 6：查找你的堆栈名称与函数 ID**

运行 `sam deploy` 之后，你需要找到 `YourStackName` 和 ID 的正确值，以便调用 Lambda 函数。

**方法 1：查看 SAM 部署输出**

`DataIngestionFunctionName: my-fashion-stack-DataIngestionFunction-abc123xyz`

**方法 2：查看 CloudFormation 输出**

从 CloudFormation 获取函数名：

```

--stack-name my-fashion-stack \
--query 'Stacks[0].Outputs[?OutputKey==`DataIngestionFunctionName`].OutputValue' \
--output text;
```

**方法 3：查看 samconfig.toml**

运行以下命令后，你的堆栈名称会保存在 samconfig.toml 中

```

```

```

```

`# Output: stack_name = "my-fashion-stack`

**方法 4：查看 AWS 管理控制台**

- 在 AWS 管理控制台中进入 **AWS CloudFormation**。
- 选择你的堆栈（例如 **my-fashion-stack**）。
- 单击 **Outputs** 选项卡。
- 找到 **DataIngestionFunctionName**。这就是要使用的完整函数名。

### **步骤 7：设置时尚数据集**

## AI 驱动的核心功能

### **虚拟试穿流程**

虚拟试穿功能是本应用的核心能力，它使用 Amazon Nova Canvas 生成用户穿着所选服装单品的逼真图像。流程始于用户通过拖拽式界面上传照片，该界面支持 JPEG、PNG 和 JPG 等常见图像格式，文件大小上限为 6 MB。该解决方案使用多模态内容生成模型 Amazon Nova Canvas，并与 Amazon Rekognition 集成，以生成逼真的商品视觉效果。虚拟试穿流程使用带有 taskType: “VIRTUAL_TRY_ON” 的 payload 结构，将源图像（客户照片）与参考图像（服装单品）相结合，并进行智能遮罩。系统采用 maskType: “GARMENT” 的基于服装的遮罩方式，根据检测到的服装类别自动识别并替换服装区域。系统会自动校验并预处理上传的图像，使用光线充足、正面朝向且清晰展示用户身体的照片可获得最佳效果。对于生产部署，请在处理前对所有用户上传的图像进行校验和审核，以帮助防止恶意或不当内容被存储和处理。有关实现指导，请参阅下文的安全警告部分。用户照片处理完成后，服装选择通过两种主要方式进行：

- 上传个人服装图像，获得自定义试穿体验
- 浏览并搜索精选时尚数据集，其中包含 60 多件专业拍摄的单品

AI 处理阶段涉及计算机视觉和生成式 AI 技术。Amazon Rekognition 首先分析用户照片和服装单品，检测服装类型、身体区域和用户性别，以实现个性化匹配。随后 Nova Canvas 生成逼真的试穿图像，将所选服装真实地套用到用户照片上，处理通常可在 15 秒内完成。之后用户可以通过多种方式与其生成的试穿结果交互：

- 下载高质量图像供个人使用
- 基于试穿的单品请求相似商品推荐
- 收藏喜欢的单品以备日后参考

### **个性化推荐**

推荐引擎是本应用最先进的部分之一，它使用多模态 AI embeddings 来理解视觉与文本层面的时尚偏好。推荐引擎使用 Amazon Titan Multimodal Embeddings 将服装图像和文本转换为 1024 维向量表示。这些 embeddings 被索引到 Amazon OpenSearch Serverless 中，并使用 k 最近邻（kNN）搜索实现亚秒级相似度匹配。系统分析用户行为、照片特征和交互模式，生成符合个人风格偏好与实际需求的个性化服装建议。影响推荐的关键因素包括：

- 使用 Amazon Titan 多模态 embeddings 进行视觉相似度分析，找出颜色、图案和风格相近的单品
- 根据照片分析和搜索历史检测用户性别并推断风格偏好
- 类别匹配，帮助确保推荐符合用户偏好的服装类型（上身、下身、全身、鞋类）

### **智能时尚搜索**

我们的智能搜索系统超越了传统的关键词匹配，能够理解自然语言查询和用户意图。时尚搜索 agent 会自动将用户搜索归入三类主要意图：搭配规划（寻找可搭配的单品）、比价选购（注重预算的购物）和风格探索（探索新的时尚趋势）。用户可以使用这样的口语化短语进行搜索：

- “Show me blue dresses under $100”，获得按价格筛选的结果
- “Show me casual tshirt”，按颜色和风格偏好筛选
- “Affordable jeans for women”，按性别和预算进行针对性搜索

该搜索引擎集成了多项高级功能以改善搜索体验：

- 为常见拼写错误自动纠错
- 目标导向的结果排序，根据检测到的用户意图对单品排定优先级
- 多条件筛选，支持颜色、价格区间、类别和性别偏好
- 模糊匹配，可处理服装类型的变体与同义词

## **分析与监控**

`python quick_analytics.py`

分析洞察包括：

- 虚拟试穿总会话数与独立用户数
- 最热门的服装类别与单品
- 上传与数据集两种使用方式的对比
- 每日活跃趋势
- 用户参与度指标

## **示例工作负载假设**

以下估算基于典型的 workshop 场景：

– **数据集**：已索引 60 件时尚单品
 – **每日用量**：50 次虚拟试穿、100 次搜索、75 次推荐
 – **存储**：约 500MB 图像、约 100MB 处理结果
 – **时长**：运行一个月

**成本明细 **
**AI 与机器学习服务**

- **Amazon Bedrock – Nova Canvas：$**60.00/月  1,500 张虚拟试穿图像，每张 $0.04

*这是最大的成本驱动因素*

- **Amazon Bedrock – Titan Embeddings**：$0.50 – $1.00/月  已索引 60 件单品 + 每天约 100 次搜索查询

**基础设施服务**

- **OpenSearch Serverless**：$7.00 – $12.00/月  索引和搜索操作至少需要 2 个 OpenSearch Compute Units（OCU）
- **NAT Gateway**：$3.50 – $5.00/月  约 5GB 数据用于 Lambda 的互联网访问
- **AWS Key Management Service（AWS KMS）加密**：$3.00/月  启用自动轮换的 3 个密钥

**计算与存储**

- **Lambda**：免费额度  约 50,000 次调用由免费额度覆盖
- **S3 Storage：**$0.02 – $0.05/月  约 600MB 用于图像和处理结果
- **DynamoDB**：$0.50 – $1.00/月  5,000 次读写操作用于分析

## **清理资源**

为避免持续的 AWS 费用，请在不再需要应用程序时妥善清理所有已部署的资源：

**Step 1：删除 CloudFormation 堆栈**

删除 SAM 创建的所有 AWS 资源：

```
sam delete --stack-name <your-stack-name>
```

该命令会：

- 删除 Lambda 函数及相关资源
- 移除 API Gateway 端点
- 删除 DynamoDB 表（数据将丢失）
- 移除模板创建的 IAM 角色和策略

**Step 2：手动清理资源**

某些资源可能需要手动删除：S3 buckets：# Empty and delete S3 buckets

```
aws s3 rm s3://<upload-bucket-name> --recursive
aws s3 rm s3://<processed-bucket-name> --recursive
aws s3 rm s3://<dataset-bucket-name> --recursive
aws s3 rb s3://<upload-bucket-name>
aws s3 rb s3://<processed-bucket-name>
aws s3 rb s3://<dataset-bucket-name>
```

**Amazon OpenSearch Serverless collection：**

# 删除 OpenSearch collection

```
aws opensearchserverless delete-collection --id <collection-id>
```

**Step 3：验证清理结果**

确认所有资源均已删除：

- 检查 CloudFormation 控制台以确认堆栈删除完成
- 确认 S3 存储桶已移除
- 确认 OpenSearch collections 已删除
- 查看账单仪表板是否有任何剩余费用

**Step 4：清理本地环境**

移除本地部署产物：# Remove SAM build artifacts

```
rm -rf .aws-sam/
rm samconfig.toml
rm response.json
```
