# 使用 Amazon Bedrock 中的 Amazon Nova 构建角色一致的故事板——第 2 部分

尽管精心打磨 prompt 可以带来不错的效果，但要达到专业级的视觉一致性，往往需要调整底层模型本身。在本两篇系列文章的[第 1 部分](https://aws.amazon.com/blogs/machine-learning/build-character-consistent-storyboards-using-amazon-nova-in-amazon-bedrock-part-1/)所介绍的 prompt 工程和角色塑造方法基础上，我们通过对 [Amazon Nova Canvas](https://aws.amazon.com/ai/generative-ai/nova/creative/) 基础模型（FM）进行微调，进一步提升特定角色的一致性。借助微调技术，创作者可以指示模型在多个场景中对角色外观、表情和风格元素保持精确控制。

在本文中，我们以 Amazon Web Services (AWS) 旗下 FuzzyPixel 制作的动画短片[《Picchu》](https://www.youtube.com/watch?v=vKSaF8NvMiQ)为例，通过提取关键角色帧来准备训练数据，并为主角 Mayu 和她的母亲微调一个角色一致的模型，这样我们就能像下图所示，快速为新的续集生成故事板概念。

## 方案概览

为实现自动化工作流，我们提出以下综合方案架构，使用 AWS 服务进行端到端实现。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/18/arch-1024x660.png)

该工作流包含以下步骤：

- 用户将视频素材上传到 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）存储桶。
- 触发 [Amazon Elastic Container Service](https://aws.amazon.com/ecs)（Amazon ECS）来处理视频素材。
- Amazon ECS 对帧进行降采样，挑选出包含角色的帧，然后居中裁剪以生成最终的角色图像。
- Amazon ECS 从 [Amazon Bedrock](https://aws.amazon.com/bedrock/)调用 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/)模型（Amazon Nova Pro），为图像生成描述文字。
- Amazon ECS 将图像描述和元数据写入 S3 存储桶。
- 用户使用 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker-ai)中的 notebook 环境调用模型训练任务。
- 用户通过调用 Amazon Bedrock 的 `create_model_customization_job` 和 `create_model_provisioned_throughput` API 来微调自定义 Amazon Nova Canvas 模型，创建可用于推理的自定义模型。

该工作流分为两个不同阶段。初始阶段（步骤 1–5）专注于准备训练数据。在本文中，我们将演示一条自动化流水线：从输入视频中提取图像，然后生成带标签的训练数据。第二阶段（步骤 6–7）专注于微调 Amazon Nova Canvas 模型，并使用自定义训练的模型执行测试推理。对于后几个步骤，我们在以下 [GitHub 仓库](https://github.com/aws-samples/sample-character-consistent-storyboard/tree/main/02-character-consistent-fine-tuning-with-amazon-nova-canvas)中提供了预处理图像数据和详尽的示例代码，以指导你完成整个流程。

## 准备训练数据

我们从工作流的第一阶段开始。在我们的示例中，构建了一条自动化的视频对象/角色提取流水线，通过以下步骤提取带有准确描述标签的高分辨率图像。

### 创意角色提取

我们建议首先以固定间隔对视频帧采样（例如每秒 1 帧）。然后应用 [Amazon Rekognition](https://aws.amazon.com/rekognition/)标签检测和人脸集合搜索，以识别感兴趣的帧和角色。标签检测可以识别 2,000 多个不同的标签，并定位它们在帧中的位置，非常适合初步检测一般角色类别或非人类角色。为了区分不同角色，我们随后使用 Amazon Rekognition 的[在集合中搜索人脸](https://docs.aws.amazon.com/rekognition/latest/dg/collections.html)功能。该功能通过将人脸与预先填充的人脸集合进行匹配来识别和跟踪角色。如果这两种方法不够精确，我们可以使用 [Amazon Rekognition Custom Labels](https://aws.amazon.com/rekognition/custom-labels-features/)训练自定义模型来检测特定角色。下图展示了这一工作流。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/18/image-5-1024x408.jpeg)

检测完成后，我们为每个角色添加适当的像素留白并进行居中裁剪，然后使用 [Amazon Titan Multimodal Embeddings](https://docs.aws.amazon.com/bedrock/latest/userguide/titan-multiemb-models.html)模型运行去重算法，移除相似度超过阈值的图像。这样做有助于构建多样化的数据集，因为冗余或几乎相同的帧可能导致模型过拟合（即模型过于精确地学习训练数据，包括其中的噪声和波动，从而在新数据上表现不佳）。我们可以校准相似度阈值，以微调对「相同图像」的判定，从而更好地控制数据集多样性与冗余消除之间的平衡。

### 数据标注

我们使用 Amazon Bedrock 中的 Amazon Nova Pro 为每张图像生成描述文字，然后将图像和标签清单文件上传到 Amazon S3 位置。这一过程聚焦于 prompt 工程的两个关键方面：角色描述，帮助 FM 根据角色的独特属性识别并命名角色；以及多样化的描述生成，避免描述中出现重复模式（例如「an animated character」）。以下是我们在数据标注过程中使用的 prompt 模板示例：

```
system_prompt = """ 
    You are an expert image description specialist who creates concise, natural alt
    text that makes visual content accessible while maintaining clarity and focus.
    Your task is to analyze the provided image and provide a creative description
    (20-30 words) that emphasizes the Three main characters, capturing the essential
    elements of their interaction while avoiding unnecessary details.
"""

prompt = """
    
    1. Identify the main characters in the image: Character 1, Character 2, and
        Character 3 at least one will be in the picture so provide at a minimum a
        description with at least one character name.
      - "Character 1" describe the first character, key traits, background, attributes.
      - "Character 2" describe the second character, key traits, background, attributes.
      - "Character 3" describe the third character, key traits, background, attributes. 
    2. Just state their name WITHOUT adding any standard characteristics.
    3. Only capture visual element outside the standard characteristics
    4. Capture the core interaction between them
    5. Include only contextual details that are crucial for understanding the scene
    6. Create a natural, flowing description using everyday language
    
    Here are some examples
    
       ...
    
    
    
    [Identify the main characters]
    [Assessment of their primary interaction]
    [Selection of crucial contextual elements]
    [Crafting of concise, natural description]
    
    
    {
        "alt_text": "[Concise, natural description focusing on the main characters]"
    }
    
    
    Note: Provide only the JSON object as the final response.
```

数据标注输出的格式为 JSONL 文件，其中每一行将图像引用的 Amazon S3 路径与 Amazon Nova Pro 生成的描述配对。随后将该 JSONL 文件上传到 Amazon S3 用于训练。以下是该文件的一个示例：

```
{"image_ref": "s3://media-ip-dataset/characters/blue_character_01.jpg", "alt_text": "This
    animated character features a round face with large expressive eyes. The character
    has a distinctive blue color scheme with a small tuft of hair on top. The design is
    stylized with clean lines and a minimalist approach typical of modern animation."}
{"image_ref": "s3://media-ip-dataset/props/iconic_prop_series1.jpg", "alt_text": "This
    object appears to be an iconic prop from the franchise. It has a metallic appearance
    with distinctive engravings and a unique shape that fans would immediately recognize.
    The lighting highlights its dimensional qualities and fine details that make it
    instantly identifiable."}
```

### 人工验证

对于企业级用例，我们建议在继续模型训练之前引入 human-in-the-loop 流程来验证标注数据。这种验证可以通过 [Amazon Augmented AI](https://aws.amazon.com/augmented-ai/)（Amazon A2I）来实现，这是一项帮助标注人员验证图像和描述质量的服务。更多详情请参阅 [Amazon Augmented AI 入门](https://docs.aws.amazon.com/sagemaker/latest/dg/a2i-getting-started.html)。

## 微调 Amazon Nova Canvas

有了训练数据后，我们就可以在 Amazon Bedrock 中微调 Amazon Nova Canvas 模型。Amazon Bedrock 需要一个 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）服务角色来访问存储模型定制训练数据的 S3 存储桶。更多详情请参阅[模型定制的访问与安全](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-model-job-access-security.html)。你可以直接在 Amazon Bedrock 控制台上执行微调任务，也可以使用 Boto3 API。我们在本文中介绍这两种方法，你可以在 [picchu-finetuning.ipynb](https://github.com/aws-samples/sample-character-consistent-storyboard/blob/main/02-character-consistent-fine-tuning-with-amazon-nova-canvas/picchu-finetuning.ipynb)中找到端到端的代码示例。

### 在 Amazon Bedrock 控制台上创建微调任务

首先在 Amazon Bedrock 控制台上创建一个 Amazon Nova Canvas 微调任务：

- 在 Amazon Bedrock 控制台的导航窗格中，选择 **Foundation models** 下的 **Custom models**。
- 选择 **Customize model**，然后选择 **Create Fine-tuning job**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/18/image-8-1024x453.jpg)

- 在 **Create Fine-tuning job details** 页面上，选择要定制的模型，并为微调后的模型输入名称。
- 在 **Job configuration** 部分，为任务输入名称，并可选择添加要关联的标签。
- 在 **Input data** 部分，输入训练数据集文件的 Amazon S3 位置。
- 在 **Hyperparameters** 部分，输入超参数的值，如下图所示。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/18/image-7-1.jpg)

- 在 **Output data** 部分，输入 Amazon Bedrock 保存任务输出的 Amazon S3 位置。
- 选择 **Fine-tune model job** 以开始微调过程。

在我们的实验中，这组超参数组合取得了不错的效果。一般来说，提高学习率会让模型训练得更激进，这往往会带来一个有趣的权衡：我们可能更快实现角色一致性，但可能影响整体图像质量。我们建议采用系统的方法来调整超参数。从建议的 batch size 和学习率开始，先尝试增加或减少训练步数。如果模型即使训练了 20,000 步（Amazon Bedrock 允许的最大值）仍难以学习你的数据集，那么我们建议增大 batch size 或上调学习率。尽管这些调整很细微，却可能显著改善模型性能。有关超参数的更多详情，请参阅[创意内容生成模型的超参数](https://docs.aws.amazon.com/nova/latest/userguide/fine-tune-hyperparameters-content-generation-models.html)。

### 使用 Python SDK 创建微调任务

以下 Python 代码片段使用 [create_model_customization_job API](https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/bedrock/client/create_model_customization_job.html)创建同样的微调任务：

```
bedrock = boto3.client('bedrock')
jobName = "picchu-canvas-v0"
# Set parameters
hyperParameters = {
        "stepCount": "14000",
        "batchSize": "64",
        "learningRate": "0.000001",
    }

# Create job
response_ft = bedrock.create_model_customization_job(
    jobName=jobName,
    customModelName=jobName,
    roleArn=roleArn,
    baseModelIdentifier="amazon.nova-canvas-v1:0",
    hyperParameters=hyperParameters,
    trainingDataConfig={"s3Uri": training_path},
    outputDataConfig={"s3Uri": f"s3://{bucket}/{prefix}"}
)

jobArn = response_ft.get('jobArn')
print(jobArn)
```

任务完成后，你可以使用以下代码获取新的 `customModelARN`：

```
custom_model_arn = bedrock.list_model_customization_jobs(
    nameContains=jobName
)["modelCustomizationJobSummaries"][0]["customModelArn"]
```

## 部署微调后的模型

采用上述超参数配置，该微调任务可能需要长达 12 小时才能完成。完成后，你应该会在自定义模型列表中看到一个新模型。随后你可以创建预配置吞吐量来托管该模型。有关预配置吞吐量和不同承诺计划的更多详情，请参阅[通过 Amazon Bedrock 中的预配置吞吐量提高模型调用容量](https://docs.aws.amazon.com/bedrock/latest/userguide/prov-throughput.html)。

### 在 Amazon Bedrock 控制台上部署模型

要从 Amazon Bedrock 控制台部署模型，请完成以下步骤：

- 在 Amazon Bedrock 控制台的导航窗格中，选择 **Foundation models **下的 **Custom models **。
- 选择新的自定义模型，然后选择 **Purchase provisioned throughput**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/18/image-8-1024x453.jpg)

- 在 **Provisioned Throughput details** 部分，为预配置吞吐量输入名称。
- 在 **Select model** 下，选择你刚刚创建的自定义模型。
- 然后指定承诺期限和模型单元数。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/18/image-9.jpg)

购买预配置吞吐量后，会创建一个新的模型 Amazon Resource Name (ARN)。当预配置吞吐量投入服务后，你就可以调用这个 ARN。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/18/image-10-1-1024x257.jpg)

### 使用 Python SDK 部署模型

以下 Python 代码片段使用 [create_provisioned_model_throughput API](https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/bedrock/client/create_provisioned_model_throughput.html)创建预配置吞吐量：

```
custom_model_name = "picchu-canvas-v0"

# Create the provision throughput job and retrieve the provisioned model id
provisioned_model_id = bedrock.create_provisioned_model_throughput(

```
