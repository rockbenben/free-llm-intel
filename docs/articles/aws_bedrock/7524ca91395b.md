# 从数小时到几分钟：Agentic AI 如何把时间还给营销人员，去做真正重要的事

你的营销团队把大量时间耗在页面组装、协调邮件和评审循环上。这些手工流程让团队无法投入最重要的工作：识别客户面临什么问题、打磨能引起共鸣的信息，以及打造能带来有意义参与的营销活动。

本文分享 AWS Marketing 的技术、AI 与分析（Technology, AI, and Analytics，TAA）团队如何与 [Gradial](https://www.gradial.com/) 合作，在 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上构建一套 agentic AI 方案，以加速内容发布工作流。该方案把网页组装时间从最长四小时缩短到约十分钟（降幅超过 95%），同时在各类企业内容管理系统（CMS）上维持质量标准。我们的营销团队如今可以更快、更一致地发布内容，从而腾出精力，去寻找更有效的方式触达并服务客户。该方案能够减少人工投入、缩短评审周期，并提升我们各个数字资产上的内容质量。

营销团队面临一个瓶颈：网页发布要耗上数小时的手工组装、协调和评审循环。TAA 团队负责构建和运营 AWS 的数字内容基础设施、营销技术工作流，以及各团队用于大规模交付个性化、连贯体验的工具，以此改造面向客户的 Web 体验。TAA 需要一套方案，既能应对 CMS 工作流的复杂性，又能协调多个利益相关方、执行品牌与无障碍标准，并在发布前确认合规要求已满足。

营销团队可以用这套 agentic AI 方案缩短生产时间，同时通过把从活动简报到上线、跨数字渠道的协调工作自动化来维持质量。它连接企业内容管理系统，编排页面组装、理解自然语言请求、确定所需组件，并在内置校验的前提下执行页面创建。借助通过 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 提供的多种基础模型（foundation model，FM），包括 [Anthropic Claude](https://aws.amazon.com/bedrock/anthropic/) 和 [Amazon Nova](https://aws.amazon.com/nova/)，[Gradial](https://www.gradial.com/) Agents 承接了过去需要数小时人工配置的复杂编排，从而让营销组织的运作方式现代化。

我们将逐一介绍传统内容发布工作流面临的挑战、我们这套 agentic AI 方案的架构、包括用于实时校验的 Model Context Protocol（MCP）服务器在内的关键组件，以及所取得的可量化成果。

## **内容发布的挑战**

对 AWS 的数字营销经理（Digital Marketing Manager，DMM）和产品营销经理（Product Marketing Manager，PMM）来说，发布一个网页远不止把它搭出来。一个典型页面始于源自活动简报的需求，经过与数字团队和运营团队的启动会议，再进入待办列表等待排期。此后是来回沟通，直到这份请求可以开工。营销人员要在传统内容管理系统里花上最多四小时配置页面。文案评审、创意评审、链接测试、后端校验和利益相关方签核，又会在上线前累积更多耗时。瓶颈并不在某一个步骤，而在于这些步骤如何层层叠加。DMM 或 PMM 可能花好几个小时配置组件、组装页面，结果只因一张图片未达到无障碍标准而返工。页面被打回修改，又一圈评审重新开始。工作本身并不复杂，但协调与返工让它变得昂贵。在这个工作流里，有四个具体挑战造成的摩擦最大：

- 页面组装耗时——页面创建涉及配置组件、组织布局，以及把内容放进预定义框架。这项工作需要熟悉结构化的 CMS 工作流和可用的组件集。
- 跨团队协调延迟——各团队通常在页面组装完成后才评审文案、素材、链接和集成。在这一阶段发现的问题需要修改，并带来额外的评审循环。
- 技术依赖——当需求超出既有组件的能力时，团队要与工程团队协作实现更新，这会拉长交付时间并增加依赖。
- 被动式质量控制——内容健康检查、无障碍合规、品牌标准和 SEO 要求都在流程末端才评估，而不是在组装过程中评估。当问题在页面完全组装之后才被发现时，团队就要面对代价高昂的重写和协调延误，时间可能被拖上数小时甚至数天。

AWS TAA 团队意识到，这些并不是可以逐个解决的孤立问题，而是一个根本性工作流问题的表征：花在机械式组装上的时间太多，留给推动业务前进的策略性工作的时间太少。方案必须先解决页面组装，因为时间主要耗在这里，协调、依赖和校验要求也都是在这里引入的。

## **方案概览**

这套 agentic AI 方案提供三项能力：自然语言页面组装、实时内容校验，以及在单个会话中端到端执行工作流。[Gradial](https://www.gradial.com/) 与 AWS MCP 集成，负责与企业内容系统建立实时连接。

**通过 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 实现自然语言页面组装：**

营销人员可以用自然语言描述内容并请求相应动作，从而组装页面。[Gradial](https://www.gradial.com/) 使用 Amazon Bedrock 上的模型，包括 Anthropic Claude 和 [Amazon Nova](https://aws.amazon.com/nova/)，理解这一请求，判断需要哪些组件、确定正确的布局结构，并生成配置。系统通过传给 [Gradial](https://www.gradial.com/) Agents 的结构化指令，自动完成组件选择与配置，把过去需要专门 CMS 知识的布局决策变成流水线化操作。这让内容管理团队无需深厚的技术专长也能更快组装页面。

**通过 MCP 服务器实现实时内容质量校验：**

质量检查不再要等到最后。MCP 是一种开放协议，允许 AI 系统直接连接外部工具和数据源。在本方案中，MCP 服务器连接内容质量系统，在组装过程中而不是组装之后校验内容。随着内容被创建，系统会依据 SEO、无障碍和品牌标准对它进行评估（见图 1）。作者可以在同一会话中立即发现并解决问题，而不必等上几天之后的排期评审会议，与创意团队、营销运营或其他利益相关方再走一遍。

图 1：Gradial 调用 AWS 的健康检查服务，依据专有的合规与质量准则、SEO、无障碍和品牌标准校验内容。这种实时校验确保问题在流程早期被发现并纠正，让用户可以在继续组装页面之前先处理问题。

**通过代理层直接执行 CMS 操作：**

代理层以编程方式把 [Gradial](https://www.gradial.com/) 连接到 CMS，让组装好的页面可以在内容模型和发布工作流中被创建和配置。[Gradial](https://www.gradial.com/) 通过代理层发送结构化指令，CMS 则照常处理页面创建、组件渲染和发布治理。代理层保住了 CMS 作为发布系统的角色，同时减少了发布前手动授权的工作量。由此，组装、配置和交接被合并成一条自动化工作流，协调开销随之降低。

这条流水线通过四个自动化阶段，把自然语言页面组装指令转换成可上线的页面资产。首先，[Gradial](https://www.gradial.com/) 使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的模型理解自然语言输入并确定所需组件。接着，[Gradial](https://www.gradial.com/) Agents 编排页面结构、组件选择和布局配置。与此同时，MCP 服务器实时依据质量标准校验内容。最后，代理层在 CMS 中创建并配置页面。

## **成果与影响**

该方案投入生产后，对比实施前后，AWS Marketing 看到了可量化的改善：

| **指标** | **实施前** | **实施后** |
| --- | --- | --- |
| 页面组装时间 | 最多四小时的手工搭建 | 借助自然语言指令降至约十分钟（降幅 95%） |
| 质量校验 | 被动、滞后的质量评审 | 主动的实时质量评审 |
| 用户体验 | 多步骤的手工操作，配置复杂 | 直观的自然语言界面与指令 |

营销团队如今可以把时间投入内容策略与优化，而不是技术性组装，从而加速高影响力活动的上市时间。内容校验现在发生在内容创建过程中，而不是之后。MCP 服务器在组件组装的同时识别问题，因此可以在同一会话内解决，减少反复的评审循环，加快发布速度。

## **结语**

通过把 [Gradial’s](https://www.gradial.com/) 的 agentic AI 方案与 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 集成，组织可以让自己的内容发布工作流现代化，并获得可量化的业务影响。该方案交付三项关键成果。第一，它通过自动化的组件配置和布局生成缩短页面组装时间，从而实现更快的内容生产。第二，它通过组装期间的实时校验在源头保证质量，在发布前确认内容符合标准，并在利益相关方评审之前解决问题。第三，它带来无障碍的创作体验，用自然语言输入取代复杂的 CMS 交互，让更多团队成员无需专门培训就能搭建和发布页面。这种速度、质量与易用性的结合表明，[Amazon Bedrock](https://aws.amazon.com/bedrock/) 上的 agentic AI 能够在维持营销组织所要求的治理与合规标准的同时，让企业内容运营现代化。
