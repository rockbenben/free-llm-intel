# 在 Amazon SageMaker AI 上通过知识蒸馏构建高效的代理

您在前沿模型上构建了一个购物助手，并且它有效。一位购物者要求“从一家至少 4.5 星的商店购买一款低于 20 美元的黑色腰包”，代理商会搜索目录、检查候选人、检查限制条件并做出推荐。但这种互动的实际成本是多少？代理助手不是一个模型调用，而是一个循环：搜索、读取结果、细化、验证、决定。一项已完成的任务可以多次调用该前沿模型，并且您需要为每个购物者的每一次调用付费。在生产规模上，每项任务的成本会增加，侵蚀项目的投资回报率，并阻止项目交付。

提高代理应用程序效率的一种方法是使用更小的模型，这样响应速度更快并且托管成本效益更高。问题在于质量：较小的模型通常无法完成任务，这就是为什么首先选择较大的模型。知识蒸馏通过将较大“教师”模型的行为转移到较小的“学生”中，训练学生重现教师的输出，从而缩小了这一差距，从而以较小模型的速度和成本保持了大部分质量。

在本文中，您将学习如何使用知识蒸馏，特别是序列级知识蒸馏 (SeqKD)，来微调 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/) 上的购物代理。我们涵盖了如何与前沿教师一起生成高质量的多步骤轨迹并保留解决任务的轨迹，如何对它们进行编码以进行监督微调，如何在无服务器基础设施上运行培训，以及如何根据保留的基准来评估学生。

## 什么是序列级知识蒸馏（SeqKD）？

最简单的蒸馏应用形式是序列级知识蒸馏（SeqKD）。它使用教师模型生成高质量的响应，然后通过监督微调 (SFT) 根据这些响应训练学生模型。 SeqKD 仅需要教师的*文本*，无法访问教师的逻辑，也没有强化学习基础设施，因此即使是封闭的或仅使用 API 的教师也能工作。与基于 logit 或 on-policy 等其他方法相比，它处于蒸馏谱中最具成本效益和可移植性的一端。老师写下答案，学生根据答案进行微调。由于这些答案作为数据集保留，因此您可以重复使用它们来训练或测试不同的学生，而无需重新生成数据。

原则上，您希望学生在可能的输出上匹配教师的完整分布。这里需要注意的是你不能。可能序列的空间非常大，因此精确匹配它是不可行的。 SeqKD 通过使用教师实际产生的样本来近似它，从而回避了这一点。

对于智能体来说，老师产生的序列不是一段散文，而是一条轨迹、推理的有序运行、工具调用以及它们返回的观察结果，其中每一步都以之前的所有内容为条件。对学生进行整个序列的培训，教会他们导致每个行动的推理以及行动本身的多步骤过程，而不是单个答案文本段落。这使得代理任务成为序列级 KD 最清晰的例证之一，因为被复制的序列就是行为本身。

图 2：SeqKD 仅通过教师的文本输出来传输行为：教师生成轨迹，学生对其进行训练，结果以小模型的速度和成本保持了教师的大部分质量。训练期间不需要教师权重、逻辑或梯度，因此它像普通的监督微调一样运行

## 当 SeqKD 是正确的选择时

SeqKD 适合一组特定的情况：

**您有输入，但没有高质量的目标输出**

这是 SeqKD 的核心案例，本质上是数据生成。您提供输入，教师编写目标，这样您就可以对没有现有高质量标签的任务或领域进行微调。目标可以像单一答案一样简单，也可以像多轮工具使用轨迹一样复杂。这篇文章采用的是该光谱中最苛刻的一端，即代理轨迹，这是特别难以获取的。一项任务会分成许多部分正确的运行，并且需要可靠的评分者才能区分已解决的运行和失败的运行。程序化评分器的基准测试恰好满足了这一要求，因此您可以让老师生成轨迹并仅保留解决任务的轨迹。

**你的老师是一个前沿模型，你只能通过API联系**

这是前沿模型的正常情况。您无法自行访问权重来托管它，无法读取其逻辑，也无法对其进行微调。这就排除了基于逻辑的蒸馏和基于策略的方法，这些方法都需要内部访问。 SeqKD 只需要老师的文本回复，因此这是一种仍然有效的方法，并且它使您无需在学生接管后为每个请求支付前沿价格。

**您想要一个强有力的、具有成本效益的第一步**

一些最强大的小型推理模型在很大程度上是通过 SeqKD（对教师推理轨迹进行监督微调）构建的，因此当设置正确时，它是推理迁移的有效起点。 [DeepSeek-R1 蒸馏模型](https://arxiv.org/abs/2501.12948) 是一个众所周知的例子：通过在教师生成的推理轨迹上进行微调，将大老师的推理提炼成较小的 Qwen 和 Llama 学生。

## 解决方案概述

本节从头到尾遍历管道。 Amazon Bedrock 上的前沿教师 GLM-5.3 充当 ShoppingBench 代理来生成轨迹。该基准测试自己的评分器仅保留解决任务的那些，并且这些解决的轨迹通过对 SageMaker AI 模型定制进行无服务器监督微调来微调 Qwen3.5-4B 学生。然后，在保留的 ShoppingBench 拆分上对经过筛选的学生进行评估，并在运行工具循环的 SageMaker AI Inference 实时端点后面提供服务。

### 准备数据集

寻找值得模仿的轨迹是最困难的部分，而 ShoppingBench 评分器则是区分成功与失败的关键。 ShoppingBench 发布了 750 个综合购物问题，其中每个问题针对产品、商店和优惠券意图 250 个，每个问题都有一个隐藏的黄金答案和定义成功的约束条件。我们将它们分为 426 个训练问题和 324 个保留评估问题（产品 103、商店 105、优惠券 116），作为固定索引，因此两组不重叠。

对于每个训练问题，前沿教师（Amazon Bedrock 上的 GLM-5.3，推理开启，温度 1.0）充当 ShoppingBench 代理。它搜索约 270 万种产品的目录，检查候选产品，并推荐符合限制的产品。我们对每个问题对老师进行两次采样，给出 850 个轨迹，然后让 ShoppingBench 自己的记分器只保留解决任务的轨迹。温度 1.0 是故意的。采样而不是贪婪解码使这两种尝试探索不同的查询和推理路径，这为更多问题提供了至少一个已解决的轨迹和更多样化的学习集。这种拒绝抽样步骤将一个有能力但不完美的教师变成了一个干净的训练集，因为教师只需足够正确的次数就可以让解决的运行值得模仿。

每个解决的轨迹都是一个完整的情节：购物者的请求、教师的推理和每一步的工具调用（搜索、检查、推荐、终止）以及环境返回的观察结果。我们将推理与行动结合起来，结果表明，正是行动将学生带到了老师的身边。

### 编码训练轨迹

序列级蒸馏是对已经存在的轨迹进行监督学习，因此在训练期间没有任何东西称为工具，并且应用程序只能看到文本。因为这些轨迹是多步骤的工具使用对话，所以我们将每个轨迹编码为聊天轮流的“消息”列表，并让学生自己的聊天模板呈现它，因此培训师看到的标记与代理在推理时生成的标记相匹配。

每条轨迹成为每一步的一个训练行。 ‘用户’轮到系统提示和对话为止。 “助理”回合承载该步骤的推理，工具调用它导致，一个…块，后跟一个线束原生形式的[{…}]。损失仅发生在“辅助”回合，因此模型学习产生下一个推理和行动，而不是预测环境返回的观察结果。具有多个步骤的轨迹扩展为多行。这里，解决的轨迹在过滤后扩展到大约 2,600 个训练行和 130 个验证行。

单行将到目前为止的对话（用户）与下一步要学习的内容（助理）配对：
```
{
  "messages": [
    {"role": "user", "content": "You are a shopping assistant. ...\n# Task\nFind a black waist bag under $20 from a shop rated 4.5 or higher.\n# Observations so far\n(none yet)"},
    {"role": "assistant", "content": "<think>Start with a broad search and let the price filter work before I narrow by shop rating.</think>\n<tool_call>[{\"name\": \"find_product\", \"parameters\": {\"q\": \"black waist bag\", \"price\": \"0-20\"}}]</tool_call>"}
  ]
}
```
后面的每个步骤都成为自己的行，新的观察结果附加到用户内容中，下一个推理和工具调用作为“助理”目标，直到最终的“推荐产品”和“终止”调用。使用模型的精确聊天模板渲染每一行。

按问题而不是按行拆分数据。教师对每个问题进行两次采样，并且每个轨迹扩展为多个步骤，因此许多行共享一个问题，并且行级拆分会在训练和验证中泄漏几乎相同的上下文。保留整个问题（大约百分之五）可以保持验证集的诚实。

每步编码的成本是重复上下文，因为每一行都重申了不断增长的对话，并且无服务器微调会截断“dataset_max_len”之后的任何内容，因此超过限制的行会丢失其所需的部分内容。不要让限制决定削减什么，而是将行数保持在预算范围内。最有效的解决方法是压缩工具观察结果，这在令牌计数中占主导地位。对于产品搜索结果，仅保留下一个决策所依赖的字段（id、价格、评级和正在检查的约束），删除原始列表文本，并限制每次搜索保留的结果数量。如果轨迹仍然超出预算，请限制每个轨迹的步数。这里“dataset_max_len”是 16,384 个标记，它适合修剪观察值后的大多数轨迹。

每个分割的 JSONL 位于 S3 中后，使用 SageMaker Python SDK v3 中的“DataSet.create”将每个分割注册为自定义数据集资产，该资产会返回训练作业使用的“train_dataset”和“val_dataset”。

### 微调学生

训练使用 [SageMaker AI 模型自定义](https://aws.amazon.com/sagemaker/ai/model-customization/) 和无服务器 SFT。您从 [模型中心](https://docs.aws.amazon.com/sagemaker/latest/dg/studio-jumpstart.html) 选择一个基本模型，将作业指向编码的数据集，托管服务会配置计算、运行作业并返回自定义模型，并在 [Amazon SageMaker with MLflow](https://docs.aws.amazon.com/sagemaker/latest/dg/mlflow.html) 中跟踪指标。由于数据已经采用受支持的格式，因此无需管理训练脚本、容器映像或实例。

该作业将其输出写入[模型包组](https://docs.aws.amazon.com/sagemaker/latest/dg/model-registry-model-group.html)，该组对它生成的每个模型进行版本控制，因此首先使用“ModelPackageGroup.create”创建该组（如果名称已存在，则重用它）并将其传递给训练器。然后配置[自定义作业](https://docs.aws.amazon.com/sagemaker/latest/dg/model-customize-open-weight-job.html)。选择基本模型和训练类型，将其指向训练和验证数据集以及模型包组，然后命名一个 MLflow 实验，以便在作业运行时指标流式传输到 MLflow。
```
from sagemaker.train.sft_trainer import SFTTrainer
from sagemaker.train.common import TrainingType

sft_trainer = SFTTrainer(
    model="huggingface-vlm-qwen3-5-4b",  # Qwen3.5-4B from the JumpStart model hub
    training_type=TrainingType.LORA,  # TrainingType.FULL for full fine-tuning
    training_dataset=train_dataset.arn,
    validation_dataset=val_dataset.arn,
    model_package_group=model_package_group,
    mlflow_experiment_name="seqkd-shopping-exp",
    s3_output_path="s3://<amzn-s3-demo-bucket>/seqkd/output/",
    accept_eula=True,
)
```
训练器从一组记录的默认超参数开始，您可以使用“sft_trainer.hyperparameters.to_dict()”进行检查并在启动之前覆盖它们。对于这次运行，我们提高序列长度以适应多步轨迹，使用 64 的低秩适应 (LoRA) 等级，并在小数据集上训练三个时期：
```
sft_trainer.hyperparameters.dataset_max_len = 16384
sft_trainer.hyperparameters.max_epochs = 3
sft_trainer.hyperparameters.global_batch_size = 64
sft_trainer.hyperparameters.learning_rate = 0.0001
sft_trainer.hyperparameters.lora_rank = 64
sft_trainer.hyperparameters.lora_alpha = 256  # alpha / rank = 4
sft_trainer.hyperparameters.lr_warmup_steps_ratio = 0.1
sft_trainer.hyperparameters.train_val_split_ratio = 0.95
```
通过试运行验证配置，然后启动托管作业并在完成时读取注册的模型包 ARN。该 ARN 是评估和服务步骤使用的部署就绪工件：
```
from sagemaker.core.resources import TrainingJob

sft_trainer.train(dry_run=True)  # checks the config without launching
training_job = sft_trainer.train(wait=True)  # launch and wait
model_package_arn = TrainingJob.get(
    training_job_name=training_job.training_job_name
).output_model_package_arn
```
### 评估学生

分两个阶段进行评估，首先是成本最低的。完整的端到端评估既耗费时间又耗费资源。它在数百万个产品上建立了一个搜索服务器，部署端点，并对每个悬而未决的问题运行多步骤代理循环。在运行完整评估之前，使用 SageMaker AI 模型评估运行一项低成本托管预检查，该模型会根据教师的真实操作一次对一个生成的步骤进行评分。

预检查需要评分功能。模型评估支持您提供的 [自定义评分器](https://docs.aws.amazon.com/sagemaker/latest/dg/model-customize-evaluation-preset-custom-scorers.html) 奖励函数，该函数每个样本运行一次，将学生生成的操作与教师生成的操作进行比较。对于工具调用蒸馏，对工具选择进行分级（模型是否按顺序调用了正确的工具，忽略参数格式），因为这是最需要转移的行为蒸馏。为了将重点放在选择而不是语法上，奖励函数从学生的操作和教师的参考中读取工具名称，而不需要精确的格式匹配。
```
def reward_function(sample, index):
    pred = sample.get("model_response", "")
    ref = sample.get("reference_answer", "") or sample.get("response", "")

    ref_names = tool_names(ref)  # tool names from the teacher's <tool_call>[...]</tool_call>
    pred_names = tool_names(pred)  # tool names the student emitted, parsed leniently
    toolset = 1.0 if (pred_names and pred_names == ref_names) else 0.0

    return {
        "id": str(sample.get("id", f"sample-{index:03d}")),
        "aggregate_reward_score": toolset,  # the gate metric: tool selection
        "metrics_list": [
            {"name": "toolset_match", "value": toolset, "type": "Reward"},
        ],
    }
```
使用 Evaluator.create() 将该函数注册为版本化的 Evaluator，然后调用 evaluate() 为每个任务运行一个自定义评分器作业，与学生一起对基本模型进行评分，以便每个结果都有比较。

决策规则很简单。学生必须在这项低成本预检查中击败基本模型。如果是这样，那么蒸馏就完成了，值得进行更全面的端到端评估。如果没有，请先修复训练。

### 服务蒸馏剂

精炼模型本身并不运行工具。微调教会它在正确的时刻以文本形式发出正确的工具调用，但仍然需要执行该调用并反馈结果。在推理时，您将模型包装在一个小的确定性工具中，该工具提示模型，解析它发出的工具调用，运行工具，附加观察结果，然后再次提示，循环直到模型产生最终答案。这是普通的应用程序代码，或者是现成的服务框架，不是强化学习，也不是策略训练循环。

学生是一个基于开放权重基础的低阶适应 (LoRA) 适配器，这决定了您的部署方式。不要合并适配器并提供权重的第二个完整副本，而是提供一次基本模型并将学生作为适配器附加到顶部，作为一个实时端点上的两个推理组件。在调用时命名推理组件可以选择哪个答案，因此同一端点可以同时为基础学生和经过精炼的学生提供服务，以进行并排比较。

我们通过 Deep Java Library Large Model Inference (DJL LMI) 容器为开放权重模型提供服务，该容器捆绑了用于高吞吐量生成的 vLLM 引擎，固定到特定版本而不是“最新”，因此重新部署是可重现的。随附的笔记本将推理组件调用包装在一个小的“kd_serve”帮助程序中，因此部署启用 LoRA 服务的基本组件，然后附加学生适配器可简化为：
```
from sagemaker.core import image_uris
import kd_serve

# DJL LMI container (vLLM engine bundled in); pin the version for reproducible redeploys
image_uri = image_uris.retrieve("djl-lmi", region=region, version="0.36.0")

# 1. Deploy the base model as an inference component, with LoRA serving enabled.
endpoint_name, base_ic = kd_serve.deploy_base_endpoint(
    endpoint_name="seqkd-shopping-agent",
    role=role,
    region=region,
    image_uri=image_uri,
    base_model_id="Qwen/Qwen3.5-4B",
    instance_types=["ml.g5.2xlarge", "ml.g6.2xlarge", "ml.g6e.2xlarge"],
    max_lora_rank=64,
    max_loras=4,
    max_model_len=131072,
)

# 2. Resolve the student's adapter artifacts from its Model Package and attach them
# as a second inference component on the same base.
adapter_uri = kd_serve.resolve_adapter_uri(model_package_arn, region)
student_ic = kd_serve.attach_adapter(
    endpoint_name=endpoint_name,
    base_ic_name=base_ic,
    adapter_component_name=f"{endpoint_name}-student",
    adapter_s3_uri=adapter_uri,
    region=region,
)
```
`instance_types` 列表是一个有序的首选项。 SageMaker AI Inference 部署在具有可用容量的第一种类型上，然后回退到列表中，因此学生根据可用性使用“ml.g5.2xlarge”、“ml.g6.2xlarge”或“ml.g6e.2xlarge”。基本权重加载一次，并且两个推理组件共享它们，因此添加适配器会消耗适配器大小的内存，而不是模型的第二个副本。

## 结果

我们根据一组参考点，在 ShoppingBench 测试中对经过精炼的学生进行评估，这些参考点包含了良好的外观：

- **基础 Qwen3.5-4B：** 现成的学生，无需微调。这是地板。
- **蒸馏学生 (SeqKD)：** 在教师轨迹上微调的相同 4B 模型，即本文描述的方法。这才是重要的结果。
- **GLM-5.3 教师：** 在 Bedrock 上生成训练数据的前沿模型。我们报告采样（温度 1.0，生成数据的设置）和贪婪（温度 0）。
- **中型前沿模型：** 作为代理运行的强大专有模型，包括作为实用上限。

每个模型都针对三个购物者意图（产品、​​商店和优惠券）运行相同的未经修改的 ShoppingBench 代理循环。我们报告绝对成功率（ASR），即代理解决的未解决问题的比例，对三个意图进行平均，缺少轨迹被视为失败。当推荐的产品满足每个规定的约束时，问题就被视为已解决。以下数字来自 LoRA 学生的单次运行，因此预计运行之间会有一些变化。

学生从老师的推理及其工具调用中学习，而这种选择对结果负有很大一部分责任。在相同的轨迹上训练同一个学生，并剥离推理，只留下裸露的工具调用，平均 ASR 从 0.541 下降到 0.415：

### 保持一般能力

ASR 衡量我们提炼出来的技能。平衡点是学生是否保持了一般的遵循指令的能力，还是过度适应了购物任务。我们使用 [IFEval](https://github.com/google-research/google-research/tree/master/instruction_following_eval) 进行检查，这是一个通用的指令跟踪基准，可以对可验证的格式指令进行评分，例如“以三个要点回答”。将其视为回归检查，而不是排行榜。学生的提示严格分数从基础模型的 0.819 下降到 0.741，其教学严格分数从 0.872 下降到 0.813，下降了大约 6 到 8 分（图 6）。这就是专业化的预期成本。这位学生用一些一般性的指导来换取购物任务的巨大收获。大幅下降将是一个警告信号，表明蒸馏将模型缩小得太窄。

### 优点和权衡

成功率本身并不能证明这种转变是合理的。进行蒸馏的原因是，您可以以小模型的成本和速度获得大部分较强模型的质量。这里最明显的证据是，4B 学生达到了其前沿教师和中型前沿模型的任务质量，同时足够小，可以在单个 G 系列实例（本例中为 NVIDIA A10G/L40/L40S）上运行。

成本差异与形状和尺寸一样重要。通过 API 达到的前沿模型是按令牌在每个任务的每个步骤上计费的，因此成本随着使用而增长并且不会停止，并且每次引入的代理循环都会支付该费用。精炼的学生在您托管的端点上运行，该端点按小时计费，无论它服务于一项任务还是数千项任务，因此在横向扩展之前，增加的流量不会产生更多费用。您正在将可变的每次请求费用换成固定的每小时费用，并且您可以使用的模型越小，固定成本就越小。

我们在这里不会发布每个任务的成本或延迟数字，因为它取决于您的流量：G 系列实例维持的吞吐量以及因此每个任务摊销的成本是您的请求模式、序列长度和并发性的函数。根据当前的 [SageMaker AI 定价](https://aws.amazon.com/sagemaker/ai/pricing/) 和前沿提供商的代币定价，根据您自己的工作负载进行衡量，而不是依赖单一的标题数字。

## 限制和最佳实践

### 该任务适合学生吗（能力墙）

蒸馏传递的是学生已经可以表示的分布，而不是它所缺乏的原始能力。差距太大，学生就抄袭老师的格式，却没有学会解决。在大型教师的思想链上训练的小型模型会产生长而结构良好的推理，其答案仍然是错误的，而以相同方式训练的智能体会发出格式良好的工具调用，但没有取得任何进展，用重新措辞的查询重新搜索，并在不满足约束的情况下运行到其步数限制。两者的症状是相同的，迹线变长，而精度保持不变。当你看到它时，停止添加数据，要么培养学生，要么降低任务难度。

决定这一点的差距是任务和学生之间的差距，而不是学生和老师之间的差距。只要任务本身在他力所能及的范围内，一个小学生就可以恢复大老师的素质。这就是这里的代购员工作的原因。教师是一个混合专家模型，大约有 400 亿个活跃参数，大约是学生 40 亿个的十倍，但购物任务完全在 4B 模型的能力范围内，因此学生恢复了教师的质量，而不仅仅是延长了其轨迹。

### SeqKD 不再有帮助的地方

SeqKD 解决了简单和中等难度的问题，但在最难的问题上却停滞不前，学生必须从自己的错误中恢复过来。对于代理来说，这比单步任务更清晰。在多步骤循环中，早期错误会复合，因为学生看不到自己的错误导致的状态。缩小这一差距是政策方法的目标，这就是为什么 SeqKD 通常是第一阶段而不是终点线的原因。 SeqKD 对基础设施的要求也最少，因为它仅使用教师的文本，而 Logit 蒸馏需要教师的每个令牌分配，并且策略方法对学生自己的部署进行评分。纯文本 SeqKD 热启动，然后是政策阶段是常见的做法，因此这篇文章涵盖了第一阶段，突破平台期是自然的下一步。

### 带有结果的两个选择

首先，将培训目标与您想要的行为相匹配。这里，这意味着在每个工具调用中保留教师的推理，而不是压缩为最终答案，因为推理是解决任务的一部分（结果量化差距），并使用代理在服务时使用的聊天模板渲染每个目标。第二，诚实评价。对模型未见过的数据进行测量，因为泄露的基准会夸大分数，并与学生必然击败的未经训练的基础模型进行比较，将其设置在教师和独立前沿模型旁边，以便数字显示学生与提取结果的接近程度。

## 清理

实时推理端点只要运行就会计费，因此在获得结果后拆除您支持服务的端点。由于学生充当基本推理组件之上的适配器推理组件，因此各个部分必须按依赖顺序排列：首先是适配器组件，然后是基本组件，然后是端点及其配置。随附的“kd_serve”帮助程序会为您执行此操作，从结构上查找适配器，以便无论确切的组件名称如何，它都会进行清理：
```
import kd_serve

# Deletes the adapter IC, then the base IC, then the endpoint and its configuration
kd_serve.teardown_endpoint(endpoint_name, region=region)
```
训练作业本身不需要清理。无服务器训练会自动计算、运行和发布它，因此完成的作业不是持续的费用。注册的模型包及其组也没有计算成本，因此您可以保留它们以进行沿袭并稍后重新部署。确实会持续增加成本的一件事是 S3 中的数据（编码轨迹和输出工件），只要您保留它，就会产生存储成本，因此请删除不再需要的数据或将其移至成本较低的存储类别。

＃＃ 结论

在这篇文章中，我们展示了如何通过序列级知识蒸馏（SeqKD）将代理购物助理提炼为更小、成本更低的学生。我们与 Bedrock 上的前沿教师一起生成了高质量的单轮、多步轨迹，并仅保留使用 ShoppingBench 自己的记分器解决任务的轨迹，将每个步骤编码为聊天格式的消息，以保留教师的推理及其工具调用，使用 SageMaker AI 模型定制在无服务器基础设施上对学生进行微调，使用 MLflow 跟踪训练，使用 SageMaker AI 模型评估运行质量门检查，并将结果提供给运行工具循环。回报是一名 4B 学生基本上恢复了其前沿教师的所有任务质量。由于 SeqKD 仅需要教师的文本输出，因此即使教师是通过 API 访问的封闭前沿模型，它也能发挥作用，并且在学生接管后，您可以停止为每一步支付前沿价格。

SeqKD 是一个强有力的第一步，但也存在真正的局限性。将学生规模与任务相匹配，根据强参考点而不是仅使用未经训练的基础模型来评估保留套件，并且当问题的最难尾部难以模仿时，遵循 SeqKD，使用此处未涵盖的 on-policy 方法，让学生从自己的部署中学习。

要亲自尝试此操作，请参阅[随附的代码存储库](https://github.com/aws/sagemaker-hyperpod-recipes/tree/main/examples/sequence-distillation) 和 [SageMaker AI 文档](https://docs.aws.amazon.com/sagemaker/latest/dg/customizing-models-distillation.html)。
