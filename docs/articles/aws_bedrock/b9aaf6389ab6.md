# 为最佳性价比而设计 prompt

为了保持竞争力，如今的企业正转向 AI，以帮助自身压缩成本、提升效率。找到最合适的 AI 模型——那个能帮它们花得更少、做得更多的模型——已成为企业的当务之急。对许多企业而言，从 OpenAI 的模型家族迁移到 [Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) 不只是换一个模型，更是一次朝着可扩展性、效率与更广泛多模态能力迈进的战略选择。

本文讨论如何在 Amazon Nova 中优化 prompting，以获得最佳的性价比。

## 为什么要从 OpenAI 迁移到 Amazon Nova？

OpenAI 的模型依然强大，但规模上去之后，其运营成本可能高得令人望而却步。请看 [Artificial Analysis](https://artificialanalysis.ai/) 给出的这些数据：

| **模型** | **输入 token 成本（每百万 token）** | **输出 token 成本（每百万 token）** | **上下文窗口** | **输出速度（token/秒）** | **延迟（首 token 秒数）** |
| --- | --- | --- | --- | --- | --- |
| **GPT-4o** | ~$2.50 | ~$10.00 | 最高 128K token | ~63 | ~0.49 |
| **GPT-4o Mini** | ~$0.15 | ~$0.60 | 最高 128K token | ~90 | ~0.43 |
| **Nova Micro** | ~$0.035 | ~$0.14 | 最高 128K token | ~195 | ~0.29 |
| **Nova Lite** | ~$0.06 | ~$0.24 | 最高 300K token | ~146 | ~0.29 |
| **Nova Pro** | ~$0.80 | ~$3.20 | 最高 300K token | ~90 | ~0.34 |

对于高并发量的应用——例如全球客户支持或大规模文档分析——这些成本差异具有颠覆性。Amazon Nova Pro 不仅提供三倍以上的成本效率，其更长的上下文窗口也使它能够处理更广泛、更复杂的输入。

## 拆解 Amazon Nova 套件

Amazon Nova 并不是单一模型，而是一个面向多种需求设计的套件：

- **Amazon Nova Pro** – 一款强大的多模态模型，可处理文本、图像与视频。它擅长文档分析和深度数据可视化等任务。[根据 Nova 技术报告与模型卡的第 2.1.1 节](https://www.amazon.science/publications/the-amazon-nova-family-of-models-technical-report-and-model-card)，基准对比显示 Amazon Nova Pro 在复杂推理任务上与 GPT-4o 相当甚至超越。
- **Amazon Nova Lite** – 在多模态处理与速度之间取得平衡。Amazon Nova Lite 非常适合文档摘要、翻译乃至基础视觉搜索这类应用，与 GPT-4o Mini 相比能以更低的延迟和成本交付高质量输出。你可以在 [Nova 技术报告与模型卡的第 2.1.2 节](https://www.amazon.science/publications/the-amazon-nova-family-of-models-technical-report-and-model-card) 中找到这些基准测试结果。
- **Amazon Nova Micro** – 一款为超低延迟而打造的纯文本模型。输出速度最高可达每秒 195 个 token，Amazon Nova Micro 非常适合聊天助手和自动化 FAQ 这类实时应用。其 token 成本远低于 GPT-4o Mini——按每个 token 计算大约便宜 4.3 倍。

Amazon Nova 更低的每 token 成本与更高的每秒输出，让你可以灵活地为实时应用简化 prompt，从而在你的用例中平衡质量、速度与成本。

## 理解基础

要最好地判断哪个模型家族适合你的需求，理解 OpenAI 与 Amazon Nova 在 prompt engineering 最佳实践上的差异很重要。每个模型家族都有自己的长处，但也有一些做法对两者都适用。无论用哪个模型家族，要获得高质量的准确性，都离不开清晰的指令、结构化的 prompt 与迭代式的精修。无论你使用的是强力的输出指令，还是明确定义的用例，目标都是减少歧义、提升回复质量。

### OpenAI 的做法

OpenAI 使用分层消息系统来做 prompt engineering，system、developer、user 三类 prompt 协同作用，以控制语气、安全性与输出格式。其做法强调：

- **分层消息角色** – 用 system 消息设定模型的角色与行为，确保（在 system prompt 中设定的）总体安全与风格准则得到保持
- **指令位置与分隔符** – 把指示放在开头，并在上下文、示例与查询之间做清晰分隔
- **有选择地使用 chain-of-thought** – 在复杂任务上确有收益时，才使用细致的逐步推理
- **格式与结构** – 使用 DO、MUST、DO NOT 这类强力指令来保证输出一致（例如以 JSON 输出）

### Amazon Nova 的做法

- **定义 prompt 用例 **  **任务** – 模型究竟应该做什么 **角色** – 模型应当扮演哪种角色 **回复风格** – 输出的结构或语气 **指令** – 模型必须遵循的准则
- **Chain-of-thought**  **显式声明回复** – 提供清晰而强力的指令来约束模型的回复 **结构化思考 **– 逐步思考有助于培养结构化思维
- **格式与结构 **  用分隔符把 prompt 分节，例如 ##Task##、##Context## 或 ##Example## 指定输出格式，例如 JSON、YAML 或 Markdown 使用 DO、DO NOT 或 MUST 这类强指令与大写 预填回复以引导模型，例如以“{“或“json…”开头

## 演进你的 prompt 策略：从 OpenAI 迁移到 Amazon Nova

迁移到 Amazon Nova 并不只是换一下 API 端点——它要求你重做 prompt engineering，以契合 Amazon Nova 的长处。你需要重新组织用例定义。先把你现有的 GPT-4o 或 GPT-4o Mini prompt 拆解为任务、角色、回复风格、指令与成功标准这些核心要素。务必把这些要素清晰地结构化，为模型提供一份蓝图。

为理解如何把现有的 OpenAI prompt 迁移到在 Amazon Nova Pro 上表现最佳，请看下面这个使用会议纪要摘要器的示例。以下是 GPT-4o 的 system prompt：

```
You will be provided with meeting notes, and your task is to summarize the meeting 
as follows: 
-Overall summary of discussion 
-Action items (what needs to be done and who is doing it) 
-If applicable, a list of topics that need to be discussed more fully in the next meeting.
```

```
Meeting Date: March 5th, 2050
```

```
You are an experienced executive assistant skilled in meeting note analysis and 
summarization. Your primary responsibilities include distilling complex discussions
into clear, actionable summaries.
Follow these instructions:

##INSTRUCTIONS##
1. Read understand the meeting notes found in ##NOTES##

3. Summarize the meeting notes in 5 sentences or less. Put this in a section called 
"Overall Summary".
4. Numerically list any action items for specific people and what needs to be completed. 
Put this list in a section called "Action Items".
5. If applicable, list the topics that need to be discussed more fully in the next meeting. 
Put this in a section called "Topics for Next Meeting".
```

### 利用 Amazon Nova 的扩展上下文

Amazon Nova Lite 与 Amazon Nova Pro 最多支持 300,000 个输入 token，这意味着如有需要，你可以在 prompt 中放入更多上下文。相应地扩充你的背景数据与详细指令——如果你原来的 OpenAI prompt 是针对 128,000 个 token 优化的，就把它调整为使用 Amazon Nova 的扩展窗口。

### 量身定制输出约束

如果你的 GPT prompt 要求严格格式（例如“只用 JSON 回复”），务必让 Amazon Nova 的 prompt 也包含这些指令。此外，如果你的任务涉及多模态输入，要明确说明何时需要包含图像或视频引用。

### 函数调用

[生成式 AI](https://aws.amazon.com/generative-ai/) agent 的兴起，使函数调用（也称工具调用）成为[大语言模型](https://aws.amazon.com/what-is/large-language-model/)（LLM）最重要的能力之一。模型能否以低延迟正确挑出适合任务的工具，往往决定了一个 agentic 系统是成功还是失败。

OpenAI 与 Amazon Nova 的模型在函数调用上有相似之处，尤其是都支持结构化 API 调用。两个模型家族都支持通过定义好的工具 schema 来选择工具，我们会在本文后面讨论这一点。它们也都提供了决定何时调用、何时不调用这些工具的机制。

OpenAI 的函数调用使用灵活的 JSON schema 来定义和构建 API 交互。这些模型支持范围很广的 schema 配置，使开发者能够通过与 API 端点绑定的简明 JSON 定义，快速实现外部函数调用。

以下是一个函数的示例：

```
tools = [{
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get current temperature for a given location.",
            "parameters": {
                    "type": "object",
                    "properties": {
                        "location": {
                            "type": "string",
                            "description": "City and country e.g. Montevideo, Uruguay"
                        }            
                },            
                "required": [                
                    "location"
        ],
        "additionalProperties": False
    },
    "strict": True
    }
}]

completion = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "What is the weather like in Punta del Este today?"}],
    tools=tools
```

与 OpenAI 的做法类似，Amazon Nova 在传入配置 schema 时也能调用工具，如下面的代码示例所示。Amazon Nova 在调用工具时大量使用 [Greedy Decoding](https://docs.aws.amazon.com/nova/latest/userguide/prompting-tools-function.html)，建议把 temperature、topP 与 topK 都设为 1。这样可以确保模型在工具选择上达到最高准确度。这些 Greedy Decoding 参数以及其他优秀的工具使用示例，在 [Tool use (function calling) with Amazon Nova](https://docs.aws.amazon.com/nova/latest/userguide/tool-use.html) 中有非常详细的介绍。

以下是不使用 ***additionalModelRequestFields*** 进行函数调用的示例：

```
tool_config = {
    "tools": [{
        "toolSpec": {
            "name": "get_recipe",
            "description": "Structured recipe generation system",
            "inputSchema": {
                "json": {
                    "type": "object",
                    "properties": {
                        "recipe": {
                            "type": "object",
                            "properties": {
                                "name": {"type": "string"},
                                "ingredients": {
                                    "type": "array",
                                    "items": {
                                        "type": "object",
                                        "properties": {
                                            "item": {"type": "string"},
                                            "amount": {"type": "number"},
                                            "unit": {"type": "string"}
                                        }
                                    }
                                },
                                "instructions": {
                                    "type": "array",
                                    "items": {"type": "string"}
                                }
                            },
                            "required": ["name", "ingredients", "instructions"]
                        }
                    }
                }
            }
        }
    }]
}

# Base configuration without topK=1
input_text = "I need a recipe for chocolate lava cake"
messages = [{
    "role": "user",
    "content": [{"text": input_text}]
}]

# Inference parameters
inf_params = {"topP": 1, "temperature": 1}

response = client.converse(
    modelId="us.amazon.nova-lite-v1:0",
    messages=messages,
    toolConfig=tool_config,
    inferenceConfig=inf_params
)
# Typically produces less structured or incomplete output
 
```

下面的示例显示，通过使用

***additionalModelRequestFields*** 可以提升函数调用的准确性：

```
# Enhanced configuration with topK=1
response = client.converse(
    modelId="us.amazon.nova-lite-v1:0",
    messages=messages,
    toolConfig=tool_config,
    inferenceConfig=inf_params,
    additionalModelRequestFields={"inferenceConfig": {"topK": 1}}
)
# Produces more accurate and structured function call
```

要最大化 Amazon Nova 的函数调用潜力并提升准确性，请始终配合 ***topk=1*** 使用 ***additionalModelRequestFields***。这会强制模型选出概率最高的那一个 token，避免随机选取 token。它提高了输出的确定性，并把函数调用的精度提升约 30–40%。

下面的代码示例进一步说明如何成功地做工具调用。第一个场景展示在没有显式工具的情况下生成食谱。该示例没有使用 topK，通常会导致回复结构较差：

```
input_text = """
I'm looking for a decadent chocolate dessert that's quick to prepare. 
Something that looks fancy but isn't complicated to make.
"""

messages = [{
    "role": "user",
    "content": [{"text": input_text}]
}]

response = client.converse(
    modelId="us.amazon.nova-lite-v1:0",
    messages=messages,
    inferenceConfig={"topP": 1, "temperature": 1}
)
# Generates a conversational recipe description
# Less structured, more narrative-driven response
```

在这个示例中，场景展示在有结构化工具的情况下生成食谱。我们把 topK 设为 1，从而产出更结构化的输出：

```
response = client.converse(
    modelId="us.amazon.nova-lite-v1:0",
    messages=messages,
    toolConfig=tool_config,
    inferenceConfig={"topP": 1, "temperature": 1},
    additionalModelRequestFields={"inferenceConfig": {"topK": 1}}
)
# Generates a highly structured, JSON-compliant recipe
# Includes precise ingredient measurements
# Provides step-by-step instructions
```

总体而言，OpenAI 提供更灵活、更广泛的 schema 支持。Amazon Nova 提供更精确、更可控的输出生成，在处理高风险的结构化数据场景时是最佳选择——正如技术报告与模型卡第 2.1.1 节中讨论的 Amazon Nova 在 IFEval 基准上的表现所示。对于需要可预测、结构化回复的应用，我们推荐使用 Amazon Nova，因为其函数调用方法提供了更优的控制力与准确性。

## 结论

从 OpenAI 的模型演进到 Amazon Nova，代表了 AI 使用方式上的一次重大转变。它显示出一种过渡：转向以很低的成本交付相当甚至更优表现的模型，同时在多模态处理与扩展上下文处理方面具备更强的能力。

无论你使用的是稳健、面向企业就绪的 Amazon Nova Pro，敏捷经济的 Amazon Nova Lite，还是多面手的 Amazon Nova Micro，收益都很明确：

- **成本节省** – token 成本最多低至四分之一，企业可以更经济地扩展应用
- **更强的回复性能** – 更快的响应时间（最高每秒 190 个 token）让实时应用更可行
- **能力扩展** – 更大的上下文窗口与多模态支持解锁新的应用，从细致的文档分析到整合视觉内容

通过演进你的 prompt 策略——重新定义用例、充分利用扩展上下文、迭代精修指令——你可以把现有工作流从 OpenAI 的 o4 与 o4-mini 模型平滑迁移到 Amazon Nova 的创新世界。
