# 使用 Amazon Bedrock Guardrails 保护你的 DeepSeek 模型部署

生成式 AI 的快速进步，把 [DeepSeek-R1](https://aws.amazon.com/blogs/aws/deepseek-r1-models-now-available-on-aws/) 等强大的公开可用大语言模型（LLM）推到了创新前沿。DeepSeek-R1 模型现已可通过 [Amazon Bedrock Marketplace](https://aws.amazon.com/bedrock/marketplace/) 和 [Amazon SageMaker JumpStart](https://aws.amazon.com/sagemaker-ai/jumpstart/) 访问，蒸馏变体则可通过 [Amazon Bedrock Custom Model Import](https://aws.amazon.com/bedrock/custom-model-import/) 获得。根据 [DeepSeek AI](https://www.deepseek.com/) 的说法，这些模型在推理、编码和自然语言理解方面能力强劲。然而，与所有模型一样，将它们部署到生产环境时，需要审慎考虑数据隐私要求、妥善管理输出中的偏见，以及建立健壮的监控与控制机制。

采用 DeepSeek-R1 这类开源、开放权重模型的组织，有重要机会来应对以下几项关键考量：

- 参照 [OWASP LLM Top 10](https://genai.owasp.org/llm-top-10/) 和 [MITRE Atlas](https://atlas.mitre.org/) 等资源，加强安全措施以防止潜在滥用
- 确保保护敏感信息
- 培养负责任的内容生成实践
- 努力符合相关行业法规

在医疗、金融和政府服务等高度受监管的行业，这些顾虑尤为关键，因为数据隐私和内容准确性至关重要。

本文提供一份全面指南，介绍如何使用 Amazon Bedrock Guardrails 为 DeepSeek-R1 及其他开放权重模型实施健壮的安全防护。我们将探讨：

- 如何使用 Amazon Bedrock 提供的安全功能保护你的数据和应用
- guardrail 的实际实施，以防范 prompt 攻击并过滤有害内容
- 实施健壮的纵深防御策略

按照本指南操作，你将学会如何在保持强安全控制、促进合乎伦理的 AI 实践的同时，使用 DeepSeek 模型的先进能力。无论你是在开发面向客户的生成式 AI 应用还是内部工具，这些实施模式都能帮助你满足安全且负责任的 AI 要求。通过这套分步方法，组织可以按照 AI 安全最佳实践来部署 DeepSeek-R1 等开放权重 LLM。

## DeepSeek 模型及其在 Amazon Bedrock 上的部署

DeepSeek AI 是一家专注于开放权重基础 AI 模型的公司，最近发布了其 [DeepSeek-R1 模型](https://github.com/deepseek-ai/DeepSeek-R1/blob/main/DeepSeek_R1.pdf)，根据其[论文](https://arxiv.org/pdf/2501.12948)，这些模型在行业基准中展现出卓越的推理能力和性能。根据第三方评估，这些模型在质量指数、科学推理与知识、定量推理以及编码（HumanEval）等各项指标上持续位列前三。

该公司进一步丰富其产品组合，发布了六个基于 DeepSeek-R1 衍生的 dense 模型，构建在 Llama 和 Qwen 架构之上，并已将其作为开放权重模型公开。这些模型现可通过 AWS 生成式 AI 解决方案访问：DeepSeek-R1 可通过 [Amazon Bedrock Marketplace 和 SageMaker Jumpstart](https://aws.amazon.com/blogs/machine-learning/deepseek-r1-model-now-available-in-amazon-bedrock-marketplace-and-amazon-sagemaker-jumpstart/) 获得，而基于 Llama 的蒸馏版本可通过 [Amazon Bedrock Custom Model Import](https://aws.amazon.com/blogs/machine-learning/deploy-deepseek-r1-distilled-llama-models-with-amazon-bedrock-custom-model-import/) 部署。

Amazon Bedrock 提供全面的[安全功能](https://docs.aws.amazon.com/bedrock/latest/userguide/security.html)，帮助在保持数据隐私与法规合规的同时，安全地托管和运行开源及开放权重模型。关键功能包括静态和传输中数据加密、细粒度访问控制、安全连接选项，以及多种[合规](https://aws.amazon.com/compliance/services-in-scope/)认证。此外，Amazon Bedrock 还提供用于内容过滤和敏感信息保护的 guardrail，以支持负责任的 AI 使用。AWS 通过平台范围内广泛的安全与合规措施强化这些能力：

- 使用 [AWS Key Management Service (AWS KMS)](https://docs.aws.amazon.com/kms/latest/developerguide/overview.html) 对静态和传输中数据加密
- 通过 [AWS Identity and Access Management (IAM)](https://docs.aws.amazon.com/IAM/latest/UserGuide/introduction.html) 进行访问管理
- 通过 [Amazon Virtual Private Cloud (Amazon VPC)](https://aws.amazon.con/vpc) 部署、[VPC 端点](https://docs.aws.amazon.com/bedrock/latest/userguide/vpc-interface-endpoints.html)和 [AWS Network Firewall](https://aws.amazon.com/network-firewall/) 实现网络安全，用于 TLS 检查与严格策略规则
- [服务控制策略（SCP）](https://docs.aws.amazon.com/organizations/latest/userguide/orgs_manage_policies_scps.html)用于 AWS 账户级治理
- [安全组](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html)和[网络访问控制列表](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-network-acls.html)（NACL）用于访问限制
- [合规认证](https://aws.amazon.com/compliance/programs/)，包括 HIPAA、SOC、ISO 和 GDPR
- [AWS GovCloud (US-West) 中的 Amazon Bedrock](https://aws.amazon.com/govcloud-us/?whats-new.sort-by=item.additionalFields.postDateTime&whats-new.sort-order=desc) 获得 FedRAMP High 授权
- 通过 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) 和 [AWS CloudTrail](https://docs.aws.amazon.com/bedrock/latest/userguide/logging-using-cloudtrail.html) 进行监控与日志记录

部署到生产环境时，组织应根据自身具体的合规与安全需求定制这些安全设置。作为安全流程的一部分，AWS 会对所有模型容器进行漏洞扫描，并且只接受 [Safetensors](https://github.com/huggingface/safetensors) 格式的模型，以帮助防止不安全的代码执行。

## Amazon Bedrock Guardrails

Amazon Bedrock Guardrails 提供可配置的防护措施，帮助大规模安全地构建生成式 AI 应用。Amazon Bedrock Guardrails 还可以与 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 和 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 等其他 Amazon Bedrock 工具集成，以构建更安全、更符合负责任 AI 政策的生成式 AI 应用。了解更多请参阅 [AWS Responsible AI](https://aws.amazon.com/ai/responsible-ai/) 页面。

### 核心功能

Amazon Bedrock Guardrails 有两种使用方式。第一种是直接与 InvokeModel 和 Converse API 调用集成，在推理过程中对输入 prompt 和模型输出都应用 guardrail。这种方式适用于通过 Amazon Bedrock Marketplace 和 Amazon Bedrock Custom Model Import 托管在 Amazon Bedrock 上的模型。另一种是 ApplyGuardrail API，它提供更灵活的方式，允许在不调用模型的情况下[独立评估内容](https://aws.amazon.com/blogs/machine-learning/implement-model-independent-safety-measures-with-amazon-bedrock-guardrails/)。第二种方式适用于在应用的不同阶段评估输入或输出，以及处理 Amazon Bedrock 之外的定制或第三方模型。两种方式都让开发者能够实施针对自身用例定制、且符合负责任 AI 政策的防护措施，确保生成式 AI 应用中的交互安全合规。

#### 关键的 Amazon Bedrock Guardrails 策略

Amazon Bedrock Guardrails 提供以下可配置的 guardrail 策略，帮助大规模安全地构建生成式 AI 应用：

- 内容过滤器 可调节有害内容的过滤强度 预定义类别：仇恨、侮辱、性内容、暴力、不当行为以及 prompt 攻击 多模态内容，包括文本和图像（预览）
- 主题过滤器 能够限制特定主题 在查询和回复中阻止未经授权的主题
- 词语过滤器 屏蔽特定词语、短语和脏话 针对冒犯性语言或竞品引用的自定义过滤器
- 敏感信息过滤器 阻断或掩码个人可识别信息（PII） 支持自定义正则表达式模式 对标准格式（如 SSN、DOB 和地址）进行概率性检测
- 上下文 grounding 检查 通过来源 grounding 检测幻觉 查询相关性校验
- 用于防幻觉的自动推理检查（受限预览，gated preview）

#### 其他能力

与模型无关的实现：

- 兼容所有 Amazon Bedrock 基础模型
- 支持微调模型
- 通过 ApplyGuardrail API 扩展到外部的定制和第三方模型

这一全面框架帮助客户实施负责任的 AI，在多样化的生成式 AI 应用中维持内容安全和用户隐私。

## 解决方案概览

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/07/ml-18238-deepseek-guardrails.jpg)

- **Guardrail 配置** 创建带有针对你的用例定制策略的 guardrail，并配置这些策略。

- **与 InvokeModel API 集成** 在请求中带上 guardrail 标识符调用 Amazon Bedrock InvokeModel API。发起 API 调用时，Amazon Bedrock 会把指定的 guardrail 同时应用到输入和输出。

- **Guardrail 评估过程**

- **输入评估**：在把 prompt 发给模型之前，guardrail 会按已配置的策略评估用户输入。**并行策略检查**：为改善延迟，会针对每项已配置策略并行评估输入。**输入干预**：如果输入违反任何 guardrail 策略，会返回预先配置的拦截消息，并丢弃模型推理。**模型推理**：如果输入通过 guardrail 检查，prompt 会被发送到指定模型进行推理。**输出评估**：模型生成回复后，guardrail 按已配置的策略评估输出。**输出干预**：如果模型回复违反任何 guardrail 策略，会根据策略以预先配置的消息拦截，或对敏感信息进行掩码。**回复交付**：如果输出通过所有 guardrail 检查，回复会未经修改地返回给应用

## 前提条件

在为通过 Amazon Bedrock Custom Model Import 功能导入的模型设置 guardrail 之前，请确保满足以下前提条件：

- 一个可访问 Amazon Bedrock 的 AWS 账户，以及具有所需权限的 IAM 角色。为实现集中式访问管理，我们建议使用 [AWS IAM Identity Center](https://aws.amazon.com/iam/identity-center/)。
- 确保已使用 Amazon Bedrock Custom Model Import 服务导入自定义模型。作为示例，我们将使用 DeepSeek-R1-Distill-Llama-8B，它可以通过 [Amazon Bedrock Custom Model Import](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-import-model.html) 导入。部署该模型有两种选择：按照[部署 DeepSeek-R1 蒸馏 Llama 模型](https://aws.amazon.com/blogs/machine-learning/deploy-deepseek-r1-distilled-llama-models-with-amazon-bedrock-custom-model-import/)中的说明部署 DeepSeek 的蒸馏 Llama 模型。使用 [aws-samples](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/custom-models/import_models/llama-3/DeepSeek-R1-Distill-Llama-Noteb.ipynb) 中提供的 notebook 进行部署。

你可以按这篇[博文](https://aws.amazon.com/blogs/machine-learning/safeguard-a-generative-ai-travel-agent-with-prompt-engineering-and-amazon-bedrock-guardrails/)所述使用 AWS Management Console 创建 guardrail。或者，你也可以参照这个 [notebook](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/responsible_ai/bedrock-guardrails/guardrails_custom_model_import.ipynb)，了解如何以编程方式创建本解决方案中的 guardrail。该 notebook 会完成以下操作：

- 安装所需依赖
- 使用 boto3 API 和过滤器创建 guardrail，以满足前面提到的用例
- 为导入的模型配置 tokenizer
- 使用能展示各种 Amazon Bedrock guardrail 过滤器实际效果的 prompt 测试 Amazon Bedrock Guardrails

这种方式把 guardrail 同时集成到用户输入和模型输出中。这确保任何潜在有害或不恰当的内容在交互的两个阶段都会被拦截。对于通过 Amazon Bedrock Custom Model Import、Amazon Bedrock Marketplace 和 Amazon SageMaker JumpStart 导入的开放权重蒸馏模型，需要实施的关键过滤器包括针对 prompt 攻击、内容审核、主题限制和敏感信息保护的过滤器。

## 使用 AWS 服务实施纵深防御策略

虽然 Amazon Bedrock Guardrails 提供了必要的内容与 prompt 安全控制，但在部署任何基础模型（尤其是 DeepSeek-R1 这类开放权重模型）时，实施全面的纵深防御策略至关重要。关于符合 OWASP LLM Top 10 的纵深防御方法的详细指导，请参阅我们此前关于架构安全生成式 AI 应用的[博文](https://aws.amazon.com/blogs/machine-learning/architect-defense-in-depth-security-for-generative-ai-applications-using-the-owasp-top-10-for-llms/)。

要点包括：

- 以安全为先来构建组织韧性
- 使用 AWS 服务构建在安全的云基础之上
- 跨多个信任边界应用分层防御策略
- 应对 LLM 应用的 OWASP Top 10 风险
- 在整个 AI/ML 生命周期实施安全最佳实践
- 将 AWS 安全服务与 AI 和机器学习（AI/ML）专用功能结合使用
- 考虑多元视角并使安全与业务目标保持一致
- 为 prompt 注入和数据投毒等风险做好准备并加以缓解

模型级控制（guardrail）与纵深防御策略的结合，形成强健的安全态势，有助于防范：

- 数据外泄企图
- 对微调模型或训练数据的未授权访问
- 模型实现中的潜在漏洞
- AI agent 和集成的恶意使用

我们建议在部署任何新的 AI/ML 解决方案之前，使用 [AWS 针对生成式 AI 工作负载的指导](https://aws.amazon.com/blogs/security/threat-modeling-your-generative-ai-workload-to-evaluate-security-risk/)开展全面的威胁建模演练。这有助于让安全控制与具体风险场景和业务需求对齐。

## 结论

为 LLM（包括 DeepSeek-R1 模型）实施安全防护，对于维持安全、合乎伦理的 AI 环境至关重要。通过把 Amazon Bedrock Guardrails 与 Amazon Bedrock InvokeModel API 和 ApplyGuardrails API 配合使用，你可以帮助缓解先进语言模型带来的相关风险，同时仍然利用其强大能力。不过，需要认识到模型级防护只是全面安全策略的一个组成部分。

本文概述的策略应对了若干关键安全问题，这些问题在通过 Amazon Bedrock Custom Model Import、Amazon Bedrock Marketplace 以及 Amazon SageMaker JumpStart 托管在 Amazon Bedrock 上的各类开放权重模型中普遍存在。其中包括对 prompt 注入攻击的潜在脆弱性、有害内容的生成，以及近期评估中发现的其他风险。通过把这些 guardrail 与纵深防御方法结合实施，组织可以显著降低滥用风险，并使其 AI 应用更好地符合伦理标准和法规要求。

随着 AI 技术不断演进，优先考虑生成式 AI 的安全与负责任使用至关重要。Amazon Bedrock Guardrails 提供了一个可配置且健壮的框架来实施这些防护，让开发者能根据自身用例和组织政策定制保护措施。我们强烈建议使用 AWS 指导对你的 AI 工作负载开展全面的威胁建模，以评估安全风险，并在整个技术栈中实施适当的控制。

请记得定期审查并更新你的 guardrail 以及所有安全控制，以应对新的潜在漏洞，并帮助在快速演变的 AI 安全格局中维持对新兴威胁的防护。虽然今天我们聚焦 DeepSeek-R1 模型，但 AI 格局在持续演变，新模型不断涌现。Amazon Bedrock Guardrails 与 AWS 安全服务和最佳实践相结合，提供了一个一致的安全框架，能够适配保护你在各类开放权重模型（当前和未来）上的生成式 AI 应用。通过把安全视为评估、改进和适配的持续过程，组织可以放心地部署创新的 AI 解决方案，同时维持强健的安全控制。
