# Agentic Resource Discovery（ARD）：一份面向 agent 发现的开放规范

### AWS Agent Registry 与 Agentic Resource Discovery（ARD）规范如何为你的 agent 实现跨环境发现

随着组织扩大对人工智能（AI）agent 与工具的使用，找到合适的资源成了困难的那部分。团队会构建 Model Context Protocol（MCP）服务器、部署 agent、创建专用工具，但缺少一个集中式目录，这些资源就会各自孤立。开发者要自己去定位资源、评估它、连接它，并手工维护这条连接。更糟的是，为某一个 AI 客户端配置好的 agent，并不会因此对另一个客户端可用。

当团队只接上少数几个工具时，这还可以应付。但当 agent、MCP 服务器、skill 与 API 的数量不断增长，并且分散在公共注册表与企业私有资产中时，这种做法就无法扩展了。

## AWS Agent Registry：一个集中、可搜索的目录

AWS Agent Registry 为你的组织提供一个集中式目录，涵盖 agent、MCP 服务器、工具、agent skill 和自定义资源。它围绕两个核心概念构建：

- Registries（注册表）。一个注册表是你在自己的 AWS 账户中创建的目录，带有它自己的授权配置与审批设置。你可以运行一个组织级的注册表，也可以按资源类型、阶段或团队拆分成多个注册表。借助跨账户共享，一个注册表可以服务你整个 AWS Organization。
- Registry Records（注册表记录）。一条记录代表一个单独的资源，捕获描述它是什么、做什么以及如何访问它的元数据。

## 工作流很直接

- **创建注册表**：管理员创建一个注册表、配置审批设置，并使用 AWS Identity and Access Management（IAM）或来自企业身份提供商的 JSON Web Token（JWT）配置授权。
- **发布记录**：发布者把他们的 MCP 服务器、agent 或工具描述为记录，并提交审批。
- **策展记录并审批**：策展人审阅待处理的记录，批准或拒绝它们，并把不再使用的记录标记为弃用。
- **发现已批准的资源：** 消费者，无论人类用户还是 AI agent，都在注册表中搜索自己需要的资源。

## 为什么它达到企业级要求

- **策展：** 审批工作流确保只有满足你的安全、合规与质量标准的记录才能被发现。管理员可以随时把某条记录移出发现范围。
- **混合搜索：** 语义理解与关键词匹配相结合，因此自然语言查询和精确名称查找都能返回相关结果。
- **MCP 原生访问：** 注册表在远程 MCP 端点上提供，因此任何兼容 MCP 的客户端都能直接搜索并使用它。
- **灵活的授权：** 用 IAM 凭证或来自企业身份提供商的 JWT 控制访问。

## 多环境带来的挑战

AWS Agent Registry 解决了你的 AWS 环境内部的发现问题。但大多数企业并不只在一个地方运营。agent 和工具被部署在多个云、本地基础设施、SaaS 平台和企业应用中，每个环境都有自己的注册表、命名约定和元数据 schema。

当每个环境都用自己的一套格式来描述 agentic 资源时，要把它们整合起来，就需要为每一对需要互操作的注册表定制连接器。一份共享规范改变了这个等式：如果每个注册表都以相同的格式描述资源，并通过一个通用协议暴露发现能力，那么发布者只需描述一次，消费者就能在任何地方发现。

## 登场：Agentic Resource Discovery（ARD）

ARD 是一个开放标准，而不是某个产品或某一个注册表。它基于 Apache License 2.0 发布，托管在 [agenticresourcediscovery.org](https://agenticresourcediscovery.org/) 和 [GitHub](https://github.com/ards-project) 上。AWS 在该规范制定过程中提供了反馈。

可以把 ARD 理解为让注册表之间能够联邦，类似于域名系统（DNS）让名称解析能够跨网络进行。一个组织可以在多个环境中部署 agent，每个环境的目录都通过一个通用协议、在一个端点之后呈现这些资源。为了组合式发现，任何注册表都可以基于对这份共享通用协议的理解，去跨这些注册表建立索引。因此，本地注册表可以通过 ARD 实现联邦，而无需双边协议或专有连接器。

## ARD 如何与 AWS Agent Registry 互补

我们认为 ARD 是 AWS Agent Registry 模式的自然补充：

- **无需迁移即可联邦：** agentic 基础设施分散在云、本地和 SaaS 上的组织，可以用一种一致的格式暴露这些资源。我们期望 ARD 在把控制权留在本地的同时实现跨环境发现。
- **全局发现，本地控制：** ARD 的设计映射了 AWS 客户所期望的控制模型：发布目录的组织控制其中有什么、谁能看到，以及何时撤销访问。我们期望 AWS Agent Registry 现有的访问控制继续留在执行点，而由 ARD 充当互操作性层。
- **支持公开发现：** 以 ARD 作为共享协议，任何组织都可以在自己的域上发布目录，让任何兼容 ARD 的客户端都能发现它。我们期望 ARD 为 Agent Registry 客户打开跨组织的发现路径。
