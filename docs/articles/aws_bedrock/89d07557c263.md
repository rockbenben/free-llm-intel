# 使用 Amazon Nova 为 Amazon Athena 查询构建对话式自然语言界面

对于不熟悉 [SQL](https://aws.amazon.com/what-is/sql/) 的业务用户来说，数据分析往往带来不小的挑战。传统方法需要技术专长才能查询数据库，导致洞察滞后并依赖数据团队。许多组织在让业务用户能访问数据的同时，又希望保留 [Amazon Athena](https://aws.amazon.com/athena/) 的分析能力，这两者之间很难兼顾。

现代 AI agent 通过在人与机器之间建立自然对话，正在改变企业使用数据的方式。用户无需学习复杂的 SQL 命令，只需用自然语言提问即可。[Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 通过使用[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM）让这一切成为可能，这些模型能够理解人类语言、对接各类数据来源，并自动执行特定任务。借助这些工具，业务用户可以直接从数据中得到所需答案，无需等待技术支持。

Amazon Bedrock 提供一系列 FM，每种都针对特定用例设计。其中，[Amazon Nova](https://aws.amazon.com/ai/generative-ai/nova/) 作为 Amazon 的新一代 FM 脱颖而出，提供前沿智能与业界领先的性价比。Amazon Nova 家族的核心由四类不同的模型组成，各自满足独特的业务需求。理解类模型（提供 Micro、Lite、Pro 和 Premier 变体）充当人类语言的高水平解读者，其中 Amazon Nova Premier 为复杂数据分析提供最强的能力。与之互补的是内容生成模型 [Amazon Nova Canvas](https://aws.amazon.com/ai/generative-ai/nova/creative/) 和 [Amazon Nova Reel](https://aws.amazon.com/ai/generative-ai/nova/creative/)，它们负责创意与内容生产任务。此外还有语音到语音模型 [Amazon Nova Sonic](https://aws.amazon.com/ai/generative-ai/nova/speech/)。最后，Amazon Nova 家族还提供 Amazon Nova Act，这是一个经过训练可在 Web 浏览器中执行动作的模型。

Amazon Nova 对我们的 Athena 查询解决方案之所以特别强大，在于它在处理复杂推理任务、生成精确文本以及提供准确摘要方面的出众能力。在把自然语言问题翻译成 SQL 查询、并用清晰易懂的表述向用户解释结果时，这些能力至关重要。

Amazon Nova 家族兼具精致功能与有竞争力的价格，对于希望弥合技术数据系统与非技术用户之间鸿沟的企业而言，是理想之选。

在本文中，我们探讨一个创新解决方案：使用由 Amazon Nova Lite 驱动的 Amazon Bedrock Agents，为 Athena 查询打造对话式界面。我们以 [AWS Cost and Usage Reports](https://docs.aws.amazon.com/cur/latest/userguide/what-is-cur.html)（AWS CUR）为例，但该解决方案可以改造用于你通过 Athena 查询的其他数据库。这种方法让数据访问更平民化，同时保留 Athena 强大的分析能力，使你能用自然语言与数据交互。

## 解决方案概览

该架构组合了多项 AWS 服务，把自然语言问题转换为针对 AWS CUR 的精确 Athena 查询。用户可以用日常语言与数据交互，系统会自动生成并执行相应的 SQL 查询。以 Amazon Nova Lite 作为 FM 的 Amazon Bedrock Agents 充当智能层，在整段对话中维护上下文、处理查询的细化调整，并促成准确的数据检索。该解决方案的一个关键组件是对话式查询 agent——一个由 Amazon Nova Lite 驱动、把自然语言翻译为 Athena SQL 查询的 Amazon Bedrock agent。

agent 与 Athena 的集成通过自然对话支持无缝的数据探索，其精简的架构支撑高效的查询处理。该解决方案的其他关键特性包括：

- 通过 [Amazon Cognito](https://aws.amazon.com/cognito/) 与[基于角色的访问控制](https://docs.aws.amazon.com/cognito/latest/developerguide/role-based-access-control.html)实现安全的用户身份认证
- 前端应用托管在 [AWS Amplify](https://aws.amazon.com/amplify/) 上
- 实时查询处理与结果可视化
- 自然语言到 SQL 查询的转换
- 上下文感知的对话管理

下图所示的架构展示了我们如何使用包括 [AWS Lambda](https://aws.amazon.com/lambda/) 函数在内的多项 AWS 服务，构建一个安全、可扩展的对话式数据查询系统。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/08/05/build_conversational_query_architecture_diagram_nova.png)

该工作流包含以下步骤：

- 用户在由 HTML、CSS 和 JavaScript 构建、托管在 Amplify 上的 Web 界面中操作。
- 身份认证通过 Amazon Cognito 处理，它验证用户身份，并从其身份池（identity pool）提供临时 AWS 凭证。
- 用户通过认证后，即可通过该界面向系统发送自然语言查询。
- 我们的对话式查询 agent 由 Amazon Bedrock 与 Amazon Nova Lite 驱动，在两个关键 action group 的支持下处理这些查询：一个提供时间上下文的 Clock and Calendar action group，以及一个负责查询执行的 Build and Run Athena Query action group。
- 用户提交查询后，Amazon Nova Lite 将其转换为 SQL，随后传给相应的 Lambda 函数。
- Lambda 函数以所需的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色运行，在 Athena 中执行该 SQL 查询。
- Athena 针对在 [AWS Glue](https://aws.amazon.com/glue) 中编目的数据执行查询，取回结果，再经格式化后通过同一个对话式界面返回给用户。

该架构在提供安全、高效查询处理的同时，为用户保持简单、类似对话的体验。系统可自动伸缩，并通过基于角色的访问控制与安全的凭证管理来保障安全性。

## 使用 Amazon Cognito 实现安全访问

该应用的安全与访问管理构建在 Amazon Cognito 身份认证框架之上。通过实现 Amazon Cognito 用户池，系统管理用户认证与分组组织；Amazon Cognito 身份池则分发与指定 IAM 角色相匹配的临时 AWS 凭证。该架构确保 Amazon Bedrock Agents API 以及整个应用仅对已认证的团队成员开放，在提供强安全控制的同时不损害用户体验。

## 用于对话式 Athena 查询的 Amazon Bedrock Agents

Amazon Bedrock Agents 架构通过对存储在 [AWS Glue Data Catalog](https://docs.aws.amazon.com/prescriptive-guidance/latest/serverless-etl-aws-glue/aws-glue-data-catalog.html) 中、经 Athena 访问的 AWS CUR 数据进行自然语言交互，来支持数据分析。该 agent 使用 Amazon Nova Lite 等 Amazon 的 FM 解读复杂的成本分析请求，将它们转换为精确的 SQL 查询，并以用户友好的格式呈现结果。该 agent 与专门的 action group 协同：`ClockandCalendarActionGroup` 负责准确的日期计算，`BuildandRunAthenaQueryActionGroup` 负责针对 AWS CUR 数据执行优化后的 Athena 查询。凭借对 AWS 服务命名规范与 AWS CUR schema 细节的全面掌握，该 agent 能够处理复杂的日期范围、成本计算和特定服务的查询，同时通过 Amazon Cognito 认证保障安全性。该架构展示了 Amazon Bedrock Agents 如何弥合自然语言请求与技术性数据库查询之间的鸿沟，帮助用户通过简单的对话获得财务洞见，而无需具备 SQL 专长或对底层数据结构的深入了解。

## 用于 Amazon Bedrock action group 的 Lambda 函数

作为该解决方案的一部分，系统部署 Lambda 函数来支持为 `ConversationalQueryAgent` 定义的 action group。这些函数使该 agent 能够对 AWS CUR 数据执行复杂查询，并为准确的分析提供时间上下文。

action group `ConversationalQueryAgent` 使用两个不同的、由 Lambda 支撑的 action group 来提供全面的成本分析能力。`ClockandCalendar` Lambda 函数提供当前日期与时间的功能。这一能力确保该 agent 能获取准确的时间信息，这对于生成对时间敏感的报告，以及把成本分析与特定账单周期或自定义时间范围对齐至关重要。

`BuildandRunAthenaQuery` Lambda 函数是该 agent 分析能力的核心。该函数直接连接 Athena，针对 AWS CUR 数据执行 SQL 查询。为便于演示，我们使用一个名为 `cid-cur` 的数据库，其中有一张包含 AWS CUR 2.0 信息的 `data` 表。该函数处理这些查询，返回便于解读与分析的格式化结果。

## 将该解决方案适配到其他以 Amazon S3 为后端的 Athena 数据库

尽管该解决方案专门为 AWS CUR 2.0 数据设计，你仍可以通过修改 Amazon Bedrock agent 指令中的关键小节，把它适配到其他以 Amazon S3 为后端的 Athena 数据库：

- 用你自己表的列名与描述替换整个 **CUR Query Column List** 小节（该小节包含所有 AWS CUR 专有的列定义，例如 `bill_payer_account_id`、`line_item_unblended_cost` 等）。
- 修改 **AWS Service Names** 小节，以反映与你的数据领域相关的特定服务或类别；若不适用，可整节删除。
- 更新 **Sample Query** 小节，展示适合你的数据结构与用例的查询。
- 如果你的数据不涉及财务计算，请调整 **Cost Types** 与 **Amortized Cost Calculation** 小节，把它们替换为与你的数据集相关的领域特定计算逻辑。

关于查询构造原则、日期处理、错误预防与响应格式化的核心小节可以基本保持不变，因为它们提供了通过对话式 AI 查询 Athena 的通用最佳实践。

## 清理

如果你决定停止使用 `ConversationalQueryAgent` 应用，可以按以下步骤移除该应用、它通过 AWS CloudFormation 部署的关联资源，以及 Amplify 部署：

- 删除 CloudFormation 堆栈：在 AWS CloudFormation 控制台的导航窗格中选择 **Stacks**。找到你在部署过程中创建的堆栈（你曾为它指定名称）。选中该堆栈并选择 **Delete**。
- 删除 Amplify 应用及其资源。具体说明请参阅 [Clean Up Resources](https://aws.amazon.com/getting-started/hands-on/build-web-app-s3-lambda-api-gateway-dynamodb/module-six/)。

## 注意事项

为在整个组织内获得最佳可见性，请在你的 AWS 付款人账户（payer account）中部署这套由 Amazon Bedrock agent 驱动的 Athena 查询解决方案，以便无缝访问并分析来自 AWS CUR 数据库的成本数据。这一集成展示了 Amazon Bedrock agent 如何针对 Athena 数据库执行复杂的分析查询，为组织数据提供对话式访问，同时保持对所有关联账户的全面可见性。

在部署到生产环境之前，应实施额外的防护措施来增强安全性。你可以通过在 [Amazon Bedrock Guardrails](https://aws.amazon.com/bedrock/guardrails/) 中为 agent [关联 guardrails](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-guardrail.html) 来实现。

## 结论

Amazon Bedrock Agents 与 Athena 的集成展示了对话式 AI 在数据分析与成本管理方面的变革潜力。我们的 `ConversationalQueryAgent` 解决方案由 Amazon Nova Lite 驱动，展示了自然语言处理如何简化复杂的数据库查询，帮助用户通过简单的对话式 prompt 从 AWS CUR 数据中提取有价值的洞见。这一实现不仅解决了成本分析中构造 SQL 查询的难题，还提供了一个灵活的框架，可扩展用于在整个组织内通过 Athena 查询不同的 SQL 数据库。通过把 Amazon Bedrock 的语言能力与 Athena 的分析能力结合起来，这一方法为数据访问的平民化树立了新标准，帮助技术与非技术用户都能从组织数据中得出可付诸行动的洞见。随着 AI 与分析技术持续演进，该解决方案为组织提供了通往其数据仓库的直观界面，改变团队与 AWS 成本数据（以及更多数据）交互并从中提取价值的方式。
