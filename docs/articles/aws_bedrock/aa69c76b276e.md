# AI 智能体的按次推理付费：BlockRun 与 Incarna 如何使用 Amazon Bedrock AgentCore payments

AI 智能体在运行时，往往需要买点东西才能完成任务：一次模型推理、一个 API 响应、访问网页内容的权限，或者调用另一个智能体。这些购买金额小、频次高，有时每笔只有几分之一美分，而且发生在智能体的循环内部，旁边没有可供审批的人。

[Amazon Bedrock AgentCore payments](https://aws.amazon.com/blogs/machine-learning/agents-that-transact-introducing-amazon-bedrock-agentcore-payments-built-with-coinbase-and-stripe/) 免掉了这重负担。它给智能体一条托管的按需付费路径，消费上限由基础设施来强制执行，而不是交给模型自己。本文中，我们来看 Incarna 如何用 AgentCore payments 让它的智能体按请求逐个向 BlockRun 支付模型推理费用。BlockRun 是一个按用量付费的推理 router，通过 [x402](https://aws.amazon.com/blogs/industries/x402-and-agentic-commerce-redefining-autonomous-payments-in-financial-services/) 服务 15 多家提供商的 90 多个模型，每次调用独立报价、独立结算。AgentCore payments 可与兼容 x402 的端点配合，包括 Amazon Bedrock 推理端点。借助这项服务，Incarna 团队把接入 x402 支付支持的工作量从数月压缩到数天，并把端到端的按次推理付费流程推上了生产。

## 挑战：按请求为推理付费

按推理付费是一种高频、低额的消费模式。一个智能体在单次会话里可能做出上百笔小额购买，每笔只值几分之一美分。卡组织网络并不是为低于一美分的支付而建的。自建支付通道意味着要同时解决好几个难题：你得决定资金存放在哪里、每笔支付如何签名，要支持 x402 这类新兴支付协议，还要防止自主智能体过度消费。

## AgentCore payments 提供什么

Amazon Bedrock AgentCore 是一个平台，用任意框架或模型都能大规模地构建、连接和优化智能体。AgentCore payments 是 Amazon Bedrock AgentCore 的一项托管能力，构建者可以用几行代码为自己的智能体加上支付。它处理支付协议、连接钱包、对交易签名，并强制执行消费上限。构建者通过一个托管服务完成集成，而不必自己把各个部件拼装起来。有几方面让它很适合按次推理付费：

- **托管钱包。** Incarna 用 Coinbase CDP connector 为每个智能体的钱包完成开通。钱包归客户所有，客户授予 Incarna 一项使用它的委托授权。
- **原生协议处理。** 当付费端点返回 HTTP 402（「Payment Required」）时，智能体通过 AgentCore payments 走 x402 完成支付。它用配置好的钱包对交易签名，并把密码学证明返回给商家。
- **基础设施层的消费治理。** AgentCore payments 在模型之外强制执行上限，所以即便智能体的 prompt 被操纵，它也无法超出。
- **可审计的结算。** 支付以稳定币结算。Incarna 使用 Base 网络上的 USDC，每笔交易都可在链上验证。

### 前提条件

Incarna 走过的这条路对其他团队同样开放，而 AgentCore payments 会替你把各个部件开通好。你可以通过 Agent Toolkit for AWS 里的 AgentCore payments skill，在一次有引导的对话中把它们配置好（在 Claude Code、Kiro 或 Codex 中）。也可以自己用 AgentCore CLI、AgentCore SDK 或 AWS SDK 逐个创建。

先把 Coinbase CDP 或 Stripe Privy 的凭证存为一个 payment credential provider，这样密钥就留在 AWS Secrets Manager 里，而不是留在你的代码里。接着创建一个 Payment Manager 和 connector，围绕这些凭证来协调支付，同时顺手设好默认消费上限。然后创建 payment instrument，也就是智能体付款所用的嵌入式钱包。最终用户为它注入资金，并通过一个重定向 URL 授予签名权限；在测试网络上，你可以用 testnet USDC 来充值。

## 流程：一次推理的买与卖

在这套集成里，BlockRun 是卖方。BlockRun 从一个实时目录中提供计量的模型推理，每次调用都各自报价、各自付款、各自结算。单次推理的流程很直接：

- 智能体需要一次模型调用。它对接 BlockRun，由 BlockRun 负责提供商选择与交付。不需要按家订阅。
- BlockRun 以一个 PaymentRequired 挑战回应，并给出这一次具体调用的价格。
- 它开启一个 payment session 并调用 `ProcessPayment`。AgentCore payments 把报价与该会话设定的消费上限做核对，并从智能体自己的钱包地址为授权签名。
- 卖方验证支付签名。
- BlockRun 提供这次推理，并记录一笔费用，即每次调用的那一小笔金额。

由于结算按请求发生，智能体只为自己用到的东西付费；它决定不发起的调用，不产生任何费用。

AgentCore payments 支持两种 x402 支付方案：`exact` 和 `upto`。价格事先确定的情况下一般用 `exact`。定价动态变化的资源适合 `upto`：智能体授权一个上限金额，推理提供商最后按实际用量结算，不超过那个上限。

## 把消费控制在范围内

让构建者放心把真金白银交给智能体的，是 payment session 这一环。一个 session 设定一个上限，也就是智能体最多能花多少，而 AgentCore payments 在基础设施层强制执行这个上限。智能体自己的代码和 prompt 改不了它。每个 session 还带一个过期时间，Incarna 把自己的 session 规模定为一天的预算。即便智能体的逻辑出了问题，它仍然花不过客户设下的额度。今天没有用到会话级预算的集成，将来也能不改代码就把它接上。这些控制如何生效的细节，见[用内置护栏启用安全的智能体支付](https://aws.amazon.com/blogs/machine-learning/enable-safe-agentic-payments-with-built-in-guardrails-using-amazon-bedrock-agentcore-payments/)。

## 结论

AgentCore payments 给智能体提供了一条受治理的、按需的付费方式，让它为自己使用的服务买单。BlockRun 与 Incarna 展示了端到端是怎么拼起来的：一个为推理付费的智能体，一个负责计量并结算的提供商，以及一个拥有这笔交易的身份。如果你正在构建需要在运行过程中购买服务的智能体，通过 AgentCore payments 这一个受治理的集成点就能加上这项能力。

## 开始使用

准备给你的智能体加上按次推理付费了？可以这样开始：

- **配置 AgentCore payments。** 创建一个 Payment Manager，配上你的钱包连接和消费策略。把一个 Coinbase CDP 钱包接为你的凭证提供商。逐步说明见 [AgentCore payments 开发者指南](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/payments.html)。
- **按你的预算开启一个 payment session。** 在智能体开始任务之前，开启一个带消费上限的 session，上限要与负载相称。智能体就在那个上限之内交易，由基础设施强制执行。
- **调用付费端点。** 把你的智能体指向一个兼容 x402 的服务（比如 BlockRun）。当端点返回 HTTP 402 时，带上支付详情调用 `ProcessPayment`。AgentCore payments 处理签名，并返回一份凭证，智能体出示它即可获得该服务。

想研究代码，见 [GitHub 上的 AgentCore payments 示例](https://github.com/awslabs/agentcore-samples/tree/main/01-features/08-agents-that-transact)。

## 关于 BlockRun 与 Incarna

**BlockRun** 是一个按用量付费的推理 router，通过 x402 支付协议提供模型推理。智能体经由单个计量端点访问一个实时的模型目录。每次调用都在 Base（USDC）上独立报价、独立授权、独立付款、独立结算。BlockRun 负责提供商的选择与交付，因此智能体通过一次集成就能访问众多模型，不必逐家订阅，也不必与各提供商建立计费关系。

**Incarna** 由 SpreadX 打造，给 AI 智能体一个能跨会话、跨模型、跨运行时存续的持久身份。每个身份都带着自己的钱包、邮箱地址、社交账号，以及一份在多次运行之间始终挂在同一个 ID 上的行动记录。当智能体为一项服务付费时，链上的付款方是智能体自己的身份，而不是一个共享的平台密钥，这让每笔交易都能归属于同一个长久的实体。Incarna 已在 Base 主网上线，进行真实结算。
