# AI 代理按推理付费：BlockRun 和 Incarna 如何使用 Amazon Bedrock AgentCore 付款

当 AI 代理运行时，它通常需要购买一些东西来完成任务：模型推理、API 响应、访问 Web 内容或调用另一个代理。这些购买规模小且频繁，有时每次只花费一小部分，而且它们发生在代理商的循环内，没有人可以批准它们。

[Amazon Bedrock AgentCore 付款](https://aws.amazon.com/blogs/machine-learning/agents-that-transact-introducing-amazon-bedrock-agentcore- payments-built-with-coinbase-and-stripe/) 消除了这一负担。它为代理提供了一种按需支付服务的托管方式，支出限制由基础设施而不是模型强制执行。在这篇文章中，我们将了解 Incarna 如何使用 AgentCore 付款方式让其代理向 BlockRun 支付一次一个请求的模型推理费用。 BlockRun 是一种即用即付推理路由器，为来自超过 15 个提供商的 90 多个模型提供服务，每个模型独立报价和结算。 AgentCore 付款可与 x402 兼容的终端节点配合使用，包括 Amazon Bedrock 推理终端节点。借助这项服务，Incarna 团队将添加 x402 支付支持的工作从几个月缩短到几天，并将端到端按推理付费流程投入生产。

## 挑战：按请求支付推理费用

按推理付费是一种高频、低价值的模式。代理商可能会在一次会话中进行数百笔小额采购，每笔价值不到一美分。卡网络并不是为低于美分的支付而建立的。建造自己的轨道意味着同时解决几个难题。您必须决定资金存放在哪里以及如何签署每笔付款，支持 x402 等新兴支付协议，并防止自治代理超支。

## AgentCore 支付提供什么

Amazon Bedrock AgentCore 是一个使用任何框架或模型大规模构建、连接和优化代理的平台。 AgentCore 付款是 Amazon Bedrock AgentCore 的一项托管功能，构建者可以使用它通过几行代码向其代理添加付款。它处理支付协议、连接到钱包、签署交易并强制执行支出限制。建筑商通过一项托管服务进行集成，而不是自行组装零件。有几点使它非常适合按推理付费：

- **托管钱包。** Incarna 使用 Coinbase CDP 连接器配置每个代理的钱包。客户拥有该钱包并授予 Incarna 使用该钱包的委托授权。
- **本机协议处理。** 当付费端点以 HTTP 402（“需要付款”）应答时，代理使用 AgentCore 付款通过 x402 进行付款。它使用配置的钱包签署交易并向商家返回加密证明。
- **基础设施层的支出治理。** AgentCore 支付强制执行模型之外的限制，因此即使代理的提示被操纵，代理也无法超出这些限制。
- **您可以审核的结算。** 付款以稳定币结算。 Incarna 在 Base 网络上使用 USDC，每笔交易都可以在链上验证。

### 先决条件

Incarna 遵循的道路向其他团队开放，AgentCore 支付为您提供了各个部分。您可以通过 Agent Toolkit for AWS（在 Claude Code、Kiro 或 Codex 中）中的 AgentCore 支付技能进行引导式对话来设置它们。您还可以使用 AgentCore CLI、AgentCore SDK 或 AWS SDK 自行创建每一项。

首先将您的 Coinbase CDP 或 Stripe Privy 凭证存储为支​​付凭证提供商，这将秘密保存在 AWS Secrets Manager 中而不是您的代码中。创建付款管理器和连接器以根据这些凭证协调付款，并在现场设置默认支出限额。然后创建一个支付工具，即代理付款的嵌入式钱包。最终用户为其提供资金并通过重定向 URL 授予签名权限，在测试网络上，您可以使用测试网 USDC 为其提供资金。

## 流程：买入和卖出一个推论

在这次整合中，BlockRun 是卖方。 BlockRun 从实时目录中提供计量模型推理服务，每次调用均自行报价、支付和结算。单个推理的流程很简单：

- 代理需要模型调用。它与 BlockRun 集成，后者处理提供商选择和交付。无需按提供商订阅。
- BlockRun 回答 PaymentRequired 质询以及该特定呼叫的价格。
- 它打开支付会话并调用“ProcessPayment”。 AgentCore 付款根据为会话设置的支出限额检查报价，并从代理自己的钱包地址签署授权。
- 卖家验证付款签名。
- BlockRun 提供推理服务并记录费用（每次调用的少量金额）。

由于结算是根据请求进行的，因此代理只需为其使用的内容付费，而代理选择不拨打的电话则无需支付任何费用。

AgentCore 支付支持两种 x402 支付方案：“exact”和“upto”。当预先知道价格时，通常会使用“精确”方案。 “upto”方案适合具有动态定价的资源。代理授权上限金额，推理提供者最终确定实际使用量，直至达到该上限。

## 控制支出

让建筑商放心让代理商转移真实资金的部分是支付会话。会话设置了一个上限，即代理可以花费的最高限额，而 AgentCore 支付在基础设施层强制执行该上限。代理自己的代码和提示无法更改它。每个会话还带有到期时间，Incarna 根据一天的预算调整其会话大小。如果代理的逻辑出现问题，它的支出仍然不能超过客户设置的限额。即使现在不使用会话级预算的集成也可以采用它，而无需更改代码。有关这些控件如何工作的更多信息，请参阅[使用内置护栏启用安全代理付款](https://aws.amazon.com/blogs/machine-learning/enable-safe-agentic- payments-with-built-in-guardrails-using-amazon-bedrock-agentcore- payments/)。

## 结论

AgentCore 支付为代理商提供了一种受管控的、按需的方式来支付他们使用的服务的费用。 BlockRun 和 Incarna 展示了它如何端到端地组合在一起：为推理付费的代理、计量和结算推理的提供商以及拥有交易的身份。如果您正在构建需要在运行时购买服务的代理，您可以通过 AgentCore 支付的单一受管理集成点添加该功能。

## 开始使用

准备好为您的代理添加按推理付费了吗？开始方法如下：

- **设置 AgentCore 付款。** 使用您的钱包连接和支出政策创建付款管理器。连接 Coinbase CDP 钱包作为您的凭证提供商。请参阅 [AgentCore 付款开发人员指南](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/ payments.html) 了解分步说明。
- **根据您的预算打开付款会话。** 在客服人员开始任务之前，打开一个具有适合工作负载的支出上限的会话。代理在该上限内进行交易，并且基础设施强制执行。
- **调用付费端点。** 将您的代理指向 x402 兼容的服务（如 BlockRun）。当端点返回 HTTP 402 时，使用付款详细信息调用“ProcessPayment”。 AgentCore 付款处理签名并返回代理可以出示以访问服务的证明。

要探索代码，请参阅 [GitHub 上的 AgentCore 付款示例](https://github.com/awslabs/agentcore-samples/tree/main/01-features/08-agents-that-transact)。

## 关于 BlockRun 和 Incarna

**BlockRun** 是一种即用即付推理路由器，通过 x402 支付协议提供模型推理服务。代理通过单个计量端点访问模型的实时目录。每次看涨期权均在 Base (USDC) 上独立报价、授权、支付和结算。 BlockRun 处理提供商的选择和交付，因此代理可以通过一次集成访问许多模型，而无需针对每个提供商的订阅或计费关系。

**Incarna** 由 SpreadX 构建，为 AI 代理提供了在会话、模型和运行时中持续存在的持久身份。每个身份都带有自己的钱包、电子邮件地址、社交帐户以及在运行过程中始终附加到一个 ID 的操作历史记录。当代理人为服务付费时，链上付款人是代理人自己的身份，而不是共享平台密钥，使得每笔交易都归属于单个持久实体。 Incarna已上线Base主网并进行真实结算。
