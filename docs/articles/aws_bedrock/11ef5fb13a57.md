# 使用生成式 AI 加速威胁建模

本文探讨 [生成式 AI](https://aws.amazon.com/ai/generative-ai/) 如何通过自动化漏洞识别、生成全面的攻击场景以及提供情境化的缓解策略，来革新威胁建模实践。以往的自动化尝试难以应对威胁分析中创造性和情境化的方面，而生成式 AI 凭借理解复杂系统关系、推理新型攻击向量以及适配独特架构模式的能力，克服了这些局限。传统自动化工具依赖僵化的规则集和预定义模板，而如今的 AI 模型能够解读细微的系统设计、推断跨组件的安全影响，并生成人工分析师可能忽略的威胁场景，使有效的自动化威胁建模成为现实。

## 威胁建模及其重要性

威胁建模是一种结构化方法，用于识别、量化并应对与某个应用或系统相关的安全风险。它从攻击者的视角分析架构，以发现潜在漏洞、确定其影响并实施适当的缓解措施。有效的威胁建模会审视数据流、信任边界和潜在攻击向量，从而针对特定系统制定全面的安全策略。

在安全的 shift-left（左移）方法中，威胁建模是一项关键的早期干预手段。通过在设计阶段——在写出第一行代码之前——实施威胁建模，组织能够在潜在漏洞的初始阶段就识别并解决它们。下图展示了这一工作流。

[![Shift-left 中的威胁建模](https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2025/05/17/ML-18677-shift-left.png)](https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2025/05/17/ML-18677-shift-left.png)

这种主动策略显著减少了安全债务的累积，并将安全从瓶颈转变为创新的推动力。当从一开始就纳入安全考量时，团队能够在整个开发生命周期中实施适当的控制，从而从一开始就构建出更具韧性的系统。

尽管有这些明显的好处，威胁建模在软件开发行业中仍未得到充分利用。这种有限的采用源于传统威胁建模方法固有的若干重大挑战：

- **时间要求** – 该过程需要 1–8 天才能完成，要实现全面覆盖还需多次迭代。这与现代软件环境中紧张的开发时间表相冲突。
- **评估不一致** – 威胁建模存在主观性。安全专家在威胁识别和风险等级判定上往往各不相同，导致项目和团队之间出现不一致。
- **扩展局限** – 人工威胁建模无法有效应对现代系统的复杂性。微服务、云部署和系统依赖的增长超出了安全团队识别漏洞的能力。

## 生成式 AI 如何提供帮助

生成式 AI 通过自动化那些传统上需要人类判断、推理和专长的复杂分析任务，革新了威胁建模。生成式 AI 将自然语言处理与视觉分析相结合，为威胁建模带来强大能力，可同时评估系统架构、图表和文档。借助 [MITRE ATT&CK](https://attack.mitre.org) 和 [OWASP](https://owasp.org) 等广泛的安全数据库，这些模型能够快速识别复杂系统中的潜在漏洞。这种同时处理文本和视觉内容、并参照全面安全框架的双能力，使得威胁评估比传统人工方法更快、更彻底。

我们的解决方案 [Threat Designer](https://github.com/awslabs/threat-designer/tree/main) 使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 中提供的企业级基础模型（foundation model，FM）来变革威胁建模。借助 [Anthropic’s Claude Sonnet 3.7](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-anthropic-claude-37.html) 先进的多模态能力，我们大规模创建全面的威胁评估。你也可以使用 [model catalog](https://docs.aws.amazon.com/bedrock/latest/userguide/bedrock-marketplace-discover-a-model.html) 中的其他可用模型，或使用你自己的 [fine-tuned](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-models.html) 模型，从而最大限度地灵活使用预训练的专业知识，或针对你的安全领域和组织需求量身定制能力。这种适应性确保你的威胁建模解决方案能够提供与你所处独特安全态势相一致的精准洞察。

## 解决方案概览

Threat Designer 是一个用户友好的 Web 应用，让开发与安全团队也能使用高级威胁建模。Threat Designer 使用大语言模型（large language model，LLM）来简化威胁建模流程，并以最少的人工投入识别漏洞。

主要功能包括：

- **架构图分析** – 用户可以提交系统架构图，应用会使用多模态 AI 能力对其进行处理，以理解系统组件及其关系
- **交互式威胁目录** – 系统生成一份全面的潜在威胁目录，用户可以通过直观的界面对其进行浏览、筛选和提炼
- **迭代式优化** – 借助回放功能，团队可以在设计改进或修改后重新运行威胁建模流程，查看变更如何影响系统的安全态势
- **标准化导出** – 结果可以导出为 PDF 或 DOCX 格式，便于与现有安全文档和合规流程集成
- **Serverless 架构** – 该解决方案运行在基于云的 serverless 基础设施上，无需专用服务器，并根据需求提供自动扩展

## Agent 服务工作流

agent 服务基于 LangChain 的 [LangGraph](https://www.langchain.com/langgraph) 构建，通过它我们可以用基于图的结构编排复杂工作流。这种方法包含两种关键设计模式：

- **关注点分离** – 威胁建模流程被分解为离散的、专门化的步骤，这些步骤可以独立且迭代地执行。图中的每个节点代表一个特定功能，例如图像处理、资产识别、数据流分析或威胁枚举。
- **结构化输出** – 工作流中的每个组件都会生成标准化、定义明确的输出，作为后续步骤的输入，从而提供一致性并促进下游集成，实现一致的表示。

agent 工作流遵循有向图，处理从 Start 节点开始，经过若干专门化阶段，如下图所示。

[![Agent 剖析](https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2025/05/17/ML-18677-agent-anatomy.png)](https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2025/05/17/ML-18677-agent-anatomy.png)

工作流包含以下节点：

- **图像处理** – Image processing 节点处理架构图图像，并将其转换为适合 LLM 使用的格式
- **资产** – 这些信息连同文本描述输入 Assets 节点，该节点识别并编目系统组件
- **流** – 工作流随后进入 Flows 节点，映射组件之间的数据移动和信任边界
- **威胁** – 最后，Threats 节点利用这些信息识别潜在漏洞和攻击向量

我们 agent 架构中的一项关键创新是通过图中的条件边实现的自适应迭代机制。这一特性解决了基于 LLM 的威胁建模中的根本挑战之一：控制分析的全面性和深度。

Threats 节点之后的条件边支持两种强大的操作模式：

- **用户控制的迭代** – 在此模式下，用户指定 agent 应执行的迭代次数。每经过一次循环，agent 都会通过分析之前迭代中可能忽略的边缘案例来丰富威胁目录。这种方法让安全专业人员能够直接控制分析的彻底程度。
- **自主差距分析** – 在完全 agentic 模式下，一个专门的差距分析组件会评估当前的威胁目录。该组件识别威胁模型中潜在的盲区或欠发达领域，并触发额外的迭代，直到它判定威胁目录已足够全面。agent 本质上是在执行自身的质量保证，持续优化其输出，直到满足预定义的完整性标准。

## 开始使用 Threat Designer

要开始使用 Threat Designer，请按照 GitHub 上项目 [README](https://github.com/awslabs/threat-designer/blob/main/README.md) 中的分步部署说明操作。部署解决方案后，你就可以创建第一个威胁模型了。登录并完成以下步骤：

- 选择 **Submit threat model** 以发起一个新的威胁模型。
- 填写提交表单，提供你的系统详情：  必填字段：提供标题和架构图图像。  推荐字段：提供解决方案描述和假设（这些能显著提高威胁模型的质量）。
- 配置分析参数：  选择你的迭代模式：  Auto（默认）：agent 智能判断威胁目录何时已全面。  Manual：指定最多 15 次迭代以获得更多控制。  配置你的推理增强，以指定模型在分析上花费的时间（使用 Anthropic’s Claude Sonnet 3.7 时可用）。
- 选择 **Start threat modeling** 以启动分析。

[![向导](https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2025/05/17/ML-18677-wizard.png)](https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2025/05/17/ML-18677-wizard.png)

你可以通过直观的界面监控进度，它会实时显示每个执行步骤。完整的分析通常需要 5–15 分钟，具体取决于系统复杂度和所选参数。

[![工作流](https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2025/05/17/ML-18677-workflow.png)](https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2025/05/17/ML-18677-workflow.png)

分析完成后，你将获得一个全面的威胁模型，可以对其进行探索、优化和导出。

[![威胁建模结果](https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2025/05/17/ML-18677-results.png)](https://d2908q01vomqb2.cloudfront.net/b6692ea5df920cad691c20319a6fffd7a4a766b8/2025/05/17/ML-18677-results.png)

## 结论

在本文中，我们展示了生成式 AI 如何将威胁建模从一项专属的、专家驱动的流程，转变为所有开发团队都能使用的安全实践。通过我们的 Threat Designer 解决方案使用 FM，我们使复杂的安全分析变得大众化，让组织能够更早、更一致地识别漏洞。这种 AI 驱动的方法消除了时间、专业知识和可扩展性方面的传统障碍，使 shift-left 安全成为现实而不仅仅是愿景——最终在不牺牲开发速度的前提下构建更具韧性的系统。

按照 [README](https://github.com/awslabs/threat-designer/blob/main/README.md) 中的说明部署 Threat Designer，上传你的架构图，即可快速获得 AI 生成的安全洞察。这种精简的方法帮助你将主动的安全措施集成到开发流程中，而不影响速度或创新——让全面威胁建模适用于不同规模的团队。
