# Amazon Bedrock 如何识别 AI 生成的钓鱼邮件

通过钓鱼邮件实施的社会工程学攻击仍然是发动网络攻击最常见的手段之一。AI 生成的钓鱼邮件如今给管理邮件系统的安全团队带来了新的挑战，其高度复杂性显著提升了风险。现代社会工程师利用生成式 AI 和开源情报（OSINT）炮制出成千上万封各不相同的邮件，语法完美、上下文恰当、细节个性化。如今，一封钓鱼邮件的特征可能反而是写得完美、格式专业。

## 钓鱼攻击的演变

对于 John 这样一家中型公司的 IT 安全工程师来说，钓鱼检测的规则曾经很简单：标出拼写错误、识别泛泛的称呼、隔离任何发件人域名不匹配的邮件。这是早期钓鱼攻击的典型特征——攻击者大规模发送数以百万计、错误百出的通用邮件，靠数量而非精准度来寻找受害者。安全过滤器正是为这些威胁而构建的，多年来一直行之有效。糟糕的语法、笼统的问候语和不匹配的 logo 都是暴露攻击者的指标。

John 如今所监控的威胁态势，与那些过滤器当初设计要捕捉的情形截然不同。生成式 AI 改变了钓鱼攻击的运作方式。现在的攻击语法正确、上下文准确，并且针对目标进行了个性化处理。这些邮件不会触发传统过滤器，因为那些过滤器本来就不是为捕捉它们而设计的。

如今识别威胁不再靠它长什么样，而是靠它知道什么。现代 AI 系统会执行 OSINT 操作，从职业社交网络、公司网站和公开的数字足迹中拉取数据，勾勒出组织层级和人际关系。有了这些情报，社会工程师就能大规模处理海量数据集，生成上下文准确、针对你所在组织量身定制的邮件。这些通信甚至能根据你的回复实时调整，改变语气或修改细节，以与对话保持一致。

Amazon Bedrock 是一项全托管服务，通过统一的 API 提供来自领先 AI 公司的高性能基础模型（foundation model，FM），同时提供构建具备安全性、隐私和负责任 AI 能力的生成式 AI 应用所需的能力。Amazon Bedrock 在您现有的安全基础设施之上增加了一层额外的分析，超越了传统的表层过滤。它理解上下文，并基于行为模式而非语法质量或格式来检测钓鱼企图。为了将这一点落到实处，让我们来拆解一下 Amazon Bedrock 从邮件进入收件箱的那一刻起是如何对其进行分析的。

Amazon Bedrock 使用在海量数据上预训练的大规模通用 AI 模型。基础模型可以分析邮件内容中的行为模式、理解上下文关系，并识别出表明某封邮件可能是钓鱼企图的异常之处。在实践中，这些能力可以组织成一个多阶段的分析流水线。每封邮件在到达用户收件箱之前，都会经过身份验证、行为分析和风险评分。

Amazon Bedrock 提供两项集成能力来支撑您的 AI 驱动钓鱼防御。预训练的基础模型带来复杂的自然语言理解能力，能够察觉基于规则的系统看不见的细微操纵、上下文异常和冒充模式。第二项能力是 Amazon Bedrock Guardrails，它提供可配置的防护措施，帮助基础模型的交互与您组织的负责任 AI 政策和应用要求保持一致，而无需编写自定义检测逻辑。这两项能力可以一起集成到一个多阶段的邮件分析流水线中。

## 用于智能钓鱼防御的 Amazon Bedrock 工作流

在该工作流方案中，每封邮件首先经过标准的身份验证检查（Sender Policy Framework（SPF）、DomainKeys Identified Mail（DKIM）、Domain-based Message Authentication, Reporting and Conformance（DMARC））。这些协议用于确认发送服务器是否有权代表该域名发送邮件，以及邮件在传输过程中是否被篡改。由 Amazon Bedrock 基础模型驱动的钓鱼检测工作流会从三个关键因素分析邮件：用词选择、沟通风格偏差，以及请求的上下文适当性。检测写作风格中这些细微的不一致以及不相称的请求，在传统安全控制之上增加了一层更深入的分析。AI 分析同样需要谨慎治理，以确认其负责任地运行、并且不超出您界定的边界。Amazon Bedrock Guardrails 帮助过滤输入的 prompt 和模型的输出。它们可以阻止可能无意中泄露机密数据的响应，并检查分析结果是否遵守您设定的政策。请记住，guardrails 需要仔细配置和校准，才能满足您的应用要求。

## 实施 Amazon Bedrock Guardrails 进行分析

Amazon Bedrock Guardrails 通过内容过滤器、禁用主题、词语过滤器和敏感信息过滤器，让您可以精细控制基础模型处理邮件内容的方式。例如，安全工程师 John 可以配置 guardrails，自动编辑在邮件分析过程中发现的敏感个人身份信息（PII），从而帮助防止基础模型生成可能无意中泄露机密数据的响应。

不过，用于安全分析的 guardrail 配置需要仔细校准。内容过滤器虽然能防范不适当的输入和输出，但设置过于严格可能会阻止模型分析那些确实需要评估的可疑内容。如果社会工程师在邮件中加入冒犯性语言以绕过过滤器，您的 guardrails 必须允许安全系统分析该内容。与此同时，guardrails 在其他情境下仍须防范不适当的输入和输出。Guardrails 还提供上下文依据检查，使模型的响应在事实上锚定于正在分析的邮件内容，减少由模型幻觉导致的误报。这让 AI 驱动的分析能够在界定的边界内运行，同时仍能检测出错综复杂的模式。

在本文中，您将学习如何使用 Amazon Bedrock 基础模型实现一个多阶段邮件分析流水线，该模型会评估发件人的行为模式、上下文适当性和沟通异常，以便在 AI 生成的钓鱼企图到达用户之前将其识别出来。

## 实施框架

以下框架展示了如何在您现有的邮件安全基础设施中落地这一方案，让处于 John 这样职位的人能够从被动过滤转向主动检测。在标准身份验证检查（SPF、DKIM、DMARC）确认邮件来自合法邮件服务器之后，钓鱼检测工作流会再进一步，叠加行为分析。您的系统从检查服务器是否获得授权，转变为评估一封邮件是否符合同事平时的沟通方式。

在深入实施之前，我们先来厘清各个组件的作用。行为分析从发件人基线跟踪器开始，它是为每位向您发送邮件的人建立的一份画像。发件人基线跟踪器记录员工的日常写作方式，使 Amazon Bedrock 分析流水线有一个可供比对的参照点。

随着持续使用，钓鱼检测工作流会逐渐了解员工使用的词语、他们有多正式或多随意、通常提出什么请求，以及平时和谁通信。以 John 的环境为例：一位平时只发简短一两句的同事，突然写了一封正式邮件，要求紧急电汇。分析流水线捕捉到这一变化，并将其标记出来，供 John 的团队进一步查看。

这有助于减少误报，并节省 John 的团队原本可能花在梳理那些被标记、但最终并非真实威胁的邮件上的时间。

以下粗略勾勒了当一封邮件进入钓鱼检测工作流时，这些组件是如何协同工作的：

### 第 1 步：输入 guardrails 与预处理

```
INITIALIZE EmailSecurityAnalyzer:
    - Set up Amazon Bedrock client (Claude Sonnet 4.5 model)
    - Configure Amazon Bedrock Guardrails for PII protection and content filtering
    - Initialize knowledge base for phishing examples
    - Initialize sender baseline tracker
    - Set risk thresholds (safe < 30, suspicious < 70, dangerous >= 70)

FUNCTION analyze_email(email):
    // Step 1: Pre-process with guardrails
    processed_email = apply_input_guardrails(email)
    IF content_blocked:
        RETURN manual_review_required
```

钓鱼检测工作流首先让收到的邮件经过 Amazon Bedrock Guardrails，后者会筛查敏感内容，并在分析开始前将任何需要人工复核的内容标记出来。

### 第 2 步：结合上下文构建 prompt

```
// Step 2: Build analysis prompt
prompt = construct_prompt(
    email_content,
    sender_baseline_patterns,
    organizational_context,
    known_phishing_examples
)
```

邮件通过该检查后，工作流会借助 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/)，将邮件内容与发件人的基线沟通模式、组织上下文和已知钓鱼样本相结合，构建出一个分析 prompt。这样一来，模型是在完整的全景下评估邮件，而不是在真空中做判断。

### 第 3 步：带 guardrails 的 AI 驱动分析

```
// Step 3: Invoke AI model with guardrails
analysis = bedrock_invoke_with_guardrails(prompt)
IF guardrail_intervened:
    RETURN blocked_with_reasons
```

基础模型使用构建好的 prompt 处理邮件，同时 guardrails 将分析限制在您界定的安全边界内。基础模型可以彻底检查可疑内容，而 guardrails 则防止它在此过程中生成暴露敏感信息的输出。

### 第 4 步：多因素风险评分

```
// Step 4: Calculate risk scores
risk_score = weighted_average(
    content_anomaly_score,
    behavioral_deviation_score,
    context_alignment_score
)
```

基于该分析，Amazon Bedrock 流水线会生成三个分数：内容异常分、行为偏差分和上下文契合分。流水线将它们合并为一个 0–100 的风险分数，由此决定邮件的路由去向。

### 第 5 步：分类与自动路由

```
// Step 5: Classify and route
risk_level = classify_risk(risk_score)
action = route_email(risk_level) // DELIVER, QUARANTINE, or BLOCK
RETURN analysis_result

FUNCTION route_email(risk_level):
    IF risk_level == SAFE: deliver_to_inbox
    IF risk_level == SUSPICIOUS: quarantine_for_review
    IF risk_level == DANGEROUS: block_and_alert_security
```

安全的邮件照常进入员工的收件箱。可疑邮件会被隔离，交由安全团队复核。危险邮件则被直接拦截。

### 通过反馈持续学习

```
FUNCTION process_feedback(email, is_phishing):
    IF is_phishing:
        add_to_phishing_knowledge_base(email)
    ELSE:
        update_sender_baseline(email)
        add_to_legitimate_examples(email)
```

当邮件在路由系统中流转时，这些步骤在毫秒级内完成。您现有的基础设施仍然负责邮件路由和投递。分析作为一层并行的检查层运行，在邮件到达用户收件箱之前评估行为风险。

随着持续使用，钓鱼检测工作流会通过几种互补技术提升做出这些判断的准确性。动态 prompt 工程是指根据真实世界的结果不断迭代优化发送给基础模型的指令，它把安全团队的反馈直接纳入分析 prompt，逐步微调模型评估潜在问题的方式。该反馈回路还会汇入一个不断增长的、经过验证的样本知识库，已确认的钓鱼企图和合法邮件在这里被编目，随后作为 few-shot learning 示例用于未来的 prompt。因此，当新邮件进来时，模型并非从零开始。它会参考您真实的、此前已验证且与类似模式相符的样本，从而做出更有依据的判断。

## 示例：AI 生成的钓鱼邮件分析

下面这封 AI 生成的钓鱼邮件展示了现代钓鱼攻击的复杂程度。请注意其完美的语法、合理的业务背景，以及对真实采购订单（PO）格式的引用。这些都不会触发传统的垃圾邮件过滤器。邮件之后是一个简化的 prompt 结构，展示 Amazon Bedrock 如何对照发件人基线和已知钓鱼模式来分析邮件。该 prompt 将邮件内容与历史上下文相结合，以支持超越表层过滤的行为分析。最后是示例风险评估输出，识别出一次供应商冒充企图。Amazon Bedrock 流水线标记出了行为异常，包括首次出现的付款变更请求，以及传统身份验证检查未能发现的域名不一致。

### 钓鱼邮件样本

```
Hi Sarah,

Following up on our last call Tuesday about the Q3 reconciliation.

Our finance team has updated our banking details as part of our transition to Example Banking Inc.

Could you update the payment info for PO-2024-089? Before the November 15th deadline? New details attached.

Best,
Michael Chen | Example Inc.
```

### Prompt 结构与风险评估输出

```
=== EMAIL CONTENT ===
{email_content}

=== SENDER BASELINE ===
- Domain: example.com (verified vendor)
- History: 2-3 emails/month, never requested payment changes
- Tone: Professional, invoice/contract discussions

=== KNOWN EVENT PATTERNS ===
- Vendor impersonation with lookalike domains
- Payment detail change requests referencing valid POs risk assessment

=== Task ===
Score (0-100): content anomalies, behavioral deviation, context alignment

{
    "risk_score": 78,
    "risk_level": "DANGEROUS",
    "key_findings": [
        "Domain mismatch: 'example-website.com' vs 'example.com'",
        "First-ever payment change request from this sender",
        "Phone number doesn't match vendor records"
    ]
}
```

## 持续反馈回路

在这些示例背后，钓鱼检测系统在数据库中维护着动态的发件人基线，跟踪每位发件人典型的沟通模式、词汇、语气和请求类型。John 的安全团队标记出的误报会被反馈回钓鱼检测流水线，更新基线以涵盖发件人沟通方式中合理的差异。已确认的钓鱼模式与这些基线一起被编目，用最新的情报丰富未来的 prompt 上下文。其结果是一个反馈回路：每一次纠正、每一个确认的威胁都会让分析更加准确。

![持续反馈回路示意图，展示以循环形式排列的五个阶段：分析、评分、复核、学习和增强，各阶段之间有箭头依次连接](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/06/22/ML-19725-2-2.png)

持续反馈流水线包含五个阶段：

> 1. 分析 – 基础模型使用由累积的钓鱼企图情报和发件人上下文构建的动态 prompt，评估您收到的邮件。
>         2. 评分 – 基于该分析，给出一个 0–100 的风险分数，可疑邮件会被隔离，交由您的安全团队复核。
>         3. 复核 – 被标记的邮件会被归类为已确认的钓鱼企图或误报。
>         4. 学习 – 这些分类结果反馈回您的系统，更新样本库、发件人行为基线和新出现的模式目录。
>         5. 增强 – 新的样本和已确认的钓鱼企图模式被纳入分析 prompt，提升下一轮循环的检测准确率。

在您的系统建立基线认知的早期阶段，需要更多人工介入的复核。对 John 来说，这意味着他的团队起初要花更多时间对被标记的邮件进行分类，但这项投入很快就会见到回报。随着样本库和发件人画像不断扩充，模型在区分合法通信与钓鱼企图方面会越来越准确。John 始终参与其中，但他的注意力从筛选噪音转向聚焦真正可疑的邮件。

每经历一次这样的循环，都会形成更强大、更具适应性的防御，并与它所要捕捉的钓鱼企图一同演进。正是这种持续改进，使这种反馈驱动的检测模型区别于静态的、基于特征码的检测。

## 结论

钓鱼检测不能再依赖拼写错误和蹩脚措辞这类表层指标。本文中的框架通过将 Amazon Bedrock 基础模型与行为分析、上下文依据以及持续反馈回路相结合，来应对这一转变，从而随时间推移不断提升准确率。Amazon Bedrock 能捕捉到训练有素的肉眼也可能错过的细微操纵企图，而您现有的基础设施则继续做它本来该做的事。

将这些防御措施与扎实的验证流程、对意外请求的合理怀疑，以及让团队从容前行的安全文化结合起来。员工意识依然重要，但如今生成式 AI 与您并肩工作，共同识别并帮助阻止冒充企图。AI 让钓鱼邮件更难被察觉；而同样的技术若用于防御，则会让钓鱼攻击更难得逞。

要开始实施这些防御，请先访问 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock/)。您可以为邮件流程配置 Amazon Bedrock Guardrails，并按照本教程构建自己的邮件钓鱼检测流水线。欢迎在评论中分享您使用 AI 驱动安全的经验。
