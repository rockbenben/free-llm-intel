# 在 AWS 上使用 Hugging Face smolagents 构建多模型框架的 Agentic AI

*本文由 Hugging Face 的 Jeff Boudier、Simon Pagezy 和 Florent Gbelidji 合著。*

Agentic AI 系统代表着从对话式 AI 向能够进行复杂推理、使用工具和执行代码的自主 agent 的演进。企业应用受益于针对具体需求量身定制的战略部署方式。这些需求包括：提供自动扩缩容能力的托管端点、用于支撑复杂推理的基础模型 API，以及支持自定义集成需求的容器化部署选项。

[Hugging Face smolagents](https://huggingface.co/docs/smolagents/en/index) 是一个开源的 Python 库，旨在让开发者用几行代码就能轻松构建并运行 agent。我们将展示如何通过把 Hugging Face smolagents 与 [Amazon Web Services (AWS)](https://aws.amazon.com/) 托管服务集成来构建一个 agentic AI 解决方案。你将了解到如何部署一个医疗健康 AI agent，它会演示多模型部署选项、向量增强的知识检索以及临床决策支持能力。

虽然我们以医疗健康作为示例，但该架构同样适用于多个对领域特定智能与可靠性要求严苛的行业。该解决方案利用 smolagents 模型无关、模态无关、工具无关的设计，在 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/) 端点、[Amazon Bedrock](https://aws.amazon.com/bedrock/) API 和容器化模型服务器之间进行编排。

## 解决方案概览

许多 AI 系统受限于单一模型方案，无法适应多样化的企业需求。这些系统通常部署选项僵化、不同 AI 服务之间的 API 不一致，并且缺少可用于择优选择模型的多模型部署选项。

本解决方案展示了组织如何构建能解决这些局限的 AI 系统。该解决方案允许按运营需求选择部署方式，并在不同的 AI 后端与部署方式之间提供一致的请求和响应格式。它通过医学知识集成与向量搜索生成带上下文的响应，并借助容器化架构支持从开发环境到生产环境的部署。

这个医疗健康用例说明该 AI agent 如何借助临床决策支持以及 AWS 的安全与合规能力，处理涉及六种药物的复杂医疗查询。

## 架构

该解决方案由以下服务和功能组成，用以提供 agentic AI 能力：

- SageMaker AI 搭配 [BioM-ELECTRA-Large-SQuAD2](https://huggingface.co/sultan/BioM-ELECTRA-Large-SQuAD2) 模型，用于专业医学查询和托管自动扩缩容。
- Amazon Bedrock 搭配 [Claude 3.5 Sonnet V2 by Anthropic](https://aws.amazon.com/bedrock/anthropic/)，用于复杂推理和基础模型访问。
- [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 用于向量相似度匹配，以及基于医学知识索引的上下文知识检索。
- [Amazon Elastic Container Service (Amazon ECS)](https://aws.amazon.com/ecs/) 搭配 [AWS Fargate](https://aws.amazon.com/fargate/)，用于对使用 smolagents 库的 Python 应用进行无服务器容器编排和可扩展部署。
- [AWS Identity and Access Management (IAM)](https://aws.amazon.com/iam) 用于安全和访问控制。
- 带 BioM-ELECTRA-Large-SQuAD2 的容器化模型服务器，用于自托管模型部署。

下图展示了解决方案架构。

![架构工作流在下面的博文正文中有描述。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/24/ml-19944-1.png)

该架构将 Hugging Face smolagents 框架与 AWS 服务完整集成。客户端 Web 界面连接到一个医疗健康 agent 容器，该容器在三个模型后端之间进行编排：带 BioM-ELECTRA 的 SageMaker AI、带 Claude 3.5 Sonnet V2 的 Amazon Bedrock，以及带 BioM-ELECTRA 的容器化模型服务器。该解决方案包含由 OpenSearch Service 提供支持的向量存储，以及一个具备静态与传输中数据加密的安全层。该安全层还负责 IAM 访问控制与身份验证，以及为满足监管合规所需的各项医疗免责声明。

该解决方案通过 smolagents 支持多种部署选项，每个后端都针对不同场景做了优化：

- SageMaker AI：面向带自动扩缩容的托管端点，以及使用 [Hugging Face Hub](https://huggingface.co/models) 模型的生产工作负载。
- Amazon Bedrock：通过 AWS API 以无服务器方式访问基础模型并完成复杂推理。
- 容器化模型服务器：用于自托管模型部署，以及集成来自 Hugging Face Hub 的工具。

三个后端都实现了 [Hugging Face Messages API 兼容性](https://huggingface.co/docs/text-generation-inference/en/messages_api)，确保无论选用哪种模型服务，请求和响应格式都保持一致。用户根据自己的需求选择相应的后端——该解决方案提供的是部署选项，而不是自动路由。

完整实现可在 sample-healthcare-agent-with-smolagents-on-aws 的 [GitHub 仓库](https://github.com/aws-samples/sample-healthcare-agent-with-smolagents-on-aws) 中获取。

## 关键优势

将 Hugging Face smolagents 与 AWS 托管服务集成，为企业级 agentic AI 部署带来显著优势。

### 部署选择

组织可以为每个用例选择最优部署方式：用 Amazon Bedrock 以无服务器方式访问基础模型，用自托管容器化部署做自定义工具集成，或用 SageMaker AI 运行专门的领域模型。这些选项有助于贴合具体工作负载的要求，而不是采用一刀切的做法。

### 多模型部署选项

组织可以在不改动 agent 逻辑的前提下优化其基础设施选型。你无需修改应用代码，就能在容器化模型服务器、SageMaker AI 和 Amazon Bedrock 之间切换。这既提供了部署选项，又保持了 agent 行为的一致性。

### 代码生成能力

smolagents 的 CodeAgent 方式通过直接生成并执行 Python 代码来简化多步操作。下面的对比展示了 smolagents 的多步操作方式：

#### 多步 JSON 方式：

```
{
  "action": "search",
  "parameters": {"query": "drug interactions"},
  "next_action": {
    "action": "filter",
    "parameters": {"criteria": "severity > moderate"}
  }
}
```

#### smolagents CodeAgent：

```
# Search and filter in single code block
results = search_tool("drug interactions")
filtered_results = [r for r in results if r.severity > "moderate"]
final_answer(f"Found {len(filtered_results)} severe interactions: {filtered_results}")
```

smolagents CodeAgent 支持用单个代码块处理多步操作，从而减少大语言模型（LLM）调用次数，同时简化 agent 开发。它在各类 AWS 服务部署中都提供对 agent 逻辑的完全控制。

### 可扩展架构

在 AWS 上部署该应用，你可以获得安全功能与自动扩缩容能力，从而满足组织的安全要求并保持监管合规。使用 Amazon ECS 和 Fargate 运行容器化工作负载，有助于实现可靠运维，并通过自动化的资源扩缩容来优化成本。

## 先决条件

在部署该解决方案之前，你需要准备以下内容：

- 一个具有相应权限的 AWS 账户，可用于创建 [IAM 角色](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles.html)、[Amazon ECS 集群](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/clusters.html) 和 [Amazon OpenSearch Service 域](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/createupdatedomains.html)。
- 已安装并配置 [AWS Command Line Interface (AWS CLI)](https://aws.amazon.com/cli) 2.0 或更高版本。
- 用于运行部署脚本的 Python 3.10 或更高版本。
- 已安装并运行 [Docker](https://docs.docker.com/get-docker/)（生产环境需要它来提供安全的代码执行沙箱）。
- 在你的 AWS 区域中可访问 Amazon Bedrock、SageMaker AI 和 OpenSearch Service，并具备创建和管理资源所需的相应 IAM 权限。
- 本次实现使用 [Python 3.10+](https://www.python.org/downloads/)、[smolagents 框架](https://huggingface.co/docs/smolagents/en/index)、[transformers 4.28.1+](https://pypi.org/project/transformers/)、[PyTorch 2.0.0+](https://pytorch.org/get-started/locally/) 和 [boto3](https://pypi.org/project/boto3/)。

运行以下命令安装所需的 Python 包：

```
pip install -r healthcare_ai_agent/phase_00_installation/requirements.txt
```

## 配置环境变量

在部署基础设施之前，先为你的 AWS 区域和资源名称设置所需的环境变量。

- 在终端中设置以下环境变量：

```
export AWS_REGION=us-west-2
export SAGEMAKER_ENDPOINT_NAME=healthcare-qa-endpoint-1
export OPENSEARCH_DOMAIN=healthcare-vector-store
export OPENSEARCH_INDEX=medical-knowledge
export BEDROCK_MODEL_ID=anthropic.claude-3-5-sonnet-20241022-v2:0
export SAGEMAKER_MODEL_ID=sultan/BioM-ELECTRA-Large-SQuAD2
export CONTAINERIZED_MODEL_ID=sultan/BioM-ELECTRA-Large-SQuAD2
```

- 验证这些变量已设置：

```
echo $AWS_REGION
echo $SAGEMAKER_ENDPOINT_NAME
```

这些环境变量会在整个部署和测试过程中使用。在进入下一步之前，请确认它们已设置。

## 搭建 AWS 基础设施

首先使用 `Smolagents_SageMaker_Bedrock_Opensearch.py` 实现中的 `SampleAWSInfrastructureManager` 类，创建基础的 AWS 基础设施组件。

### 部署完整基础设施（自动化方式）

要自动化部署 AWS 基础设施组件，可以使用增强版 main 函数。

- 启动 **增强版 main 函数：**

```
from Smolagents_SageMaker_Bedrock_Opensearch import enhanced_main
enhanced_main()
# Select option 1 for complete AWS infrastructure deployment
```

- 部署过程会自动创建 Amazon ECS 集群、IAM 角色和一个 OpenSearch Service 域。
- 等待部署完成（大约 15–20 分钟）。

### 单独创建各项 AWS 组件（替代方式）

如果你更希望逐个创建组件，可以为用于向量增强知识检索的 OpenSearch Service 域和用于容器化部署的 Amazon ECS 集群分别进行设置。

作为完整 AWS 基础设施部署（`enhanced_main` 中的选项 1）的一部分，OpenSearch Service 域和 Amazon ECS 集群都会被自动创建。如果你已经部署了完整基础设施，这两个组件就已就绪，可以跳到 **部署 Amazon SageMaker AI 端点** 一节。

### 部署 Amazon SageMaker AI 端点

将 BioM-ELECTRA-Large-SQuAD2 模型部署到 SageMaker AI，以进行专业的医学查询处理。这里提供了自动化方式（通过增强版 main 部署）和手动方式（通过 SageMaker AI 端点部署）。

## 实现医疗健康 agent

使用 `SampleTripleHealthcareAgent` 类部署核心医疗健康 agent，该类演示了 smolagents 的集成以及跨三个后端的部署能力。

### 初始化三后端医疗健康 agent

搭建主医疗健康 agent，它通过 smolagents 框架集成，在 SageMaker AI、Amazon Bedrock 和容器化模型服务器之间进行编排。

- 创建向量存储实例：

```
from Smolagents_SageMaker_Bedrock_Opensearch import SampleOpenSearchVectorStore
vector_store = SampleOpenSearchVectorStore()
vector_store_available = vector_store.initialize_client()
```

- 初始化三后端医疗健康 agent：

```
from Smolagents_SageMaker_Bedrock_Opensearch import SampleTripleHealthcareAgent
import os
agent = SampleTripleHealthcareAgent(
endpoint_name=os.getenv('SAGEMAKER_ENDPOINT_NAME'),
vector_store=vector_store if vector_store_available else None
)
```

- 该 agent 初始化三个模型后端：  `SampleSageMakerEndpointModel` 集成 BioM-ELECTRA  `SampleBedrockClaudeModel` 使用 Claude 3.5 Sonnet V2 API  `SampleContainerizedModel` 带回退机制
- 每个后端都由 `SampleHealthcareCodeAgent` 包装，以便接入 smolagents。
- 这些 agent 配置了 `max_steps=3`，并集成了 `DuckDuckGoSearchTool`。

### 配置部署选项

系统根据运营需求展示了三种部署选项。

#### 了解这些部署选项：

- **SageMaker AI 部署**：有关药物信息、副作用和监测要求的专业医学查询。
- **Amazon Bedrock 部署：** 需要详细医学分析和多步推理的复杂推理任务。
- **容器化部署：** 使用专门工具进行自定义模型集成，以及自托管模型访问。

每个后端都包含针对六种药物的医学知识数据库回退，而 Amazon OpenSearch Service 通过相似度匹配，在各模型后端之间提供上下文信息。

### 测试交互式系统

使用 `sample_interactive_healthcare_assistant` 函数测试多模型部署。

- 启动交互式医疗健康助手：

```

```

- 系统提供用于切换模型的命令：  **1** 对应 SageMaker Endpoint  **2** 对应容器化模型服务器  **3** 对应 Amazon Bedrock Claude API  **compare <question>** 可查看三个后端的响应
- 为获得最佳性能，测试查询限制在 100 个字符以内。
- 响应会在可用时包含向量上下文，以及数据库回退信息。
