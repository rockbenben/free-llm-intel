# 使用 Amazon Nova Micro 与 Amazon Bedrock 按需推理实现高性价比的自定义 text-to-SQL

在企业 AI 应用中，text-to-SQL 生成始终是一项长期挑战，尤其是在处理自定义 SQL 方言或领域特定的数据库 schema 时。尽管 foundation models（基础模型，FMs）在标准 SQL 上表现强劲，但要让专用方言达到生产级准确度，仍需微调。然而微调带来一个运维层面的权衡：把自定义模型托管在常驻基础设施上会产生持续成本，即使在不使用的时候也是如此。

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 的按需推理配合微调后的 Amazon Nova Micro 模型提供了另一种选择。通过把 [LoRA](https://arxiv.org/abs/2106.09685)（Low-Rank Adaptation）微调的效率与无服务器、按 token 计费的推理结合起来，组织无需承担常驻模型托管带来的额外成本，就能获得自定义 text-to-SQL 能力。尽管应用 LoRA adapter 会增加推理时间开销，但测试表明其延迟仍适合交互式 text-to-SQL 应用，而且成本随用量而非预置容量伸缩。

在本文中，我们演示两种微调 [Amazon Nova Micro](https://aws.amazon.com/nova/?trk=572ae9ee-3a0d-4258-a24e-f5396ba81e9b&trk=572ae9ee-3a0d-4258-a24e-f5396ba81e9b&sc_channel=ps&sc_channel=ps&ef_id=CjwKCAiAmp3LBhAkEiwAJM2JUEchOgB31omdwAIRFchCmeMiZ9CkhuMEOtR0BgMYVzFfoGnxANCRRhoCAsMQAvD_BwE:G:s&s_kwcid=AL!4422!3!692006004844!e!!g!!amazon%20nova!21048268689!159639953895&gclid=CjwKCAiAmp3LBhAkEiwAJM2JUEchOgB31omdwAIRFchCmeMiZ9CkhuMEOtR0BgMYVzFfoGnxANCRRhoCAsMQAvD_BwE) 的方法，用于自定义 SQL 方言生成，兼顾成本效率与生产就绪的性能。我们的示例工作负载在每月 22,000 次查询的样本流量下，月度成本维持在 $0.80，与常驻托管的模型基础设施相比实现了成本节省。

## **方案总览**

该方案包含以下高层步骤：

- 准备自定义 SQL 训练数据集，其中的 I/O 对针对贵组织的 SQL 方言与业务需求。
- 使用准备好的数据集和选定的微调方式，在 Amazon Nova Micro 模型上启动微调过程。Amazon Bedrock model customization 用于简化部署，Amazon SageMaker AI 用于细粒度的训练定制与控制
- 在 Amazon Bedrock 上部署自定义模型以使用按需推理，免去基础设施管理，只为 token 用量付费。
- 用针对你的自定义 SQL 方言与业务用例的测试查询来验证模型表现。

为了在实践中演示这一方法，我们提供了两条完整的实现路径，分别满足不同的组织需求。第一条使用 Amazon Bedrock 的托管 model customization，适合优先考虑简单性和快速部署的团队。第二条使用 Amazon SageMaker AI 训练作业，适合需要对超参数和训练基础设施做更细粒度控制的组织。两种实现共用同一套数据准备 pipeline，并都部署到 Amazon Bedrock 以使用按需推理。以下是两份 GitHub 代码示例的链接：

## **1. 数据集准备**

我们的演示使用 [sql-create-context](https://huggingface.co/datasets/b-mc2/sql-create-context) 数据集。该数据集是 [WikiSQL](https://github.com/salesforce/WikiSQL) 与 [Spider 数据集](https://yale-lily.github.io/spider)的精选组合，包含超过 78,000 个自然语言问题与 SQL 查询配对的示例，覆盖多样化的数据库 schema。由于其在查询复杂度上的多样性——从简单的 SELECT 语句到带聚合的复杂多表 join——这个数据集为 text-to-SQL 微调提供了理想基础。

### **数据格式化与结构**

训练数据的组织方式如[文档](https://docs.aws.amazon.com/bedrock/latest/userguide/distillation-data-prep-option-1.html)所述。这涉及创建 JSONL 文件，其中包含 system prompt 指令，以及与之配对的用户查询和复杂度各异的对应 SQL 响应。格式化后的训练数据集随后被划分为训练集和验证集，以 JSONL 文件存储，并上传到 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）以进行微调。

## **Amazon Bedrock 微调方法**

Amazon Bedrock 的 model customization 提供了一种精简、全托管的 Amazon Nova 模型微调方式，无需预置或管理训练基础设施。对于希望在获得针对自身 text-to-SQL 用例的定制模型性能的同时，追求快速迭代和最少运维开销的团队，这种方法非常理想。

借助 Amazon Bedrock 的定制能力，训练数据上传到 Amazon S3，微调作业通过 AWS 控制台或 API 配置。随后由 AWS 负责底层的训练基础设施。产出的自定义模型可以用按需推理部署，并保持与基础 Nova Micro 模型相同的按 token 计费价格、不额外加价，因此对波动的工作负载而言是一种高性价比的方案。当你需要在不管理 ML 基础设施的前提下为自定义 SQL 方言快速定制模型、希望把运维复杂度降到最低，或者需要具备自动伸缩能力的无服务器推理时，这种方法都很合适。

## **2a. 使用 Amazon Bedrock 创建微调作业**

Amazon Bedrock 同时支持通过 AWS 控制台和 [AWS SDK for Python (Boto3)](https://aws.amazon.com/sdk-for-python/) 进行微调。[AWS 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/model-customization-submit.html)包含关于如何用这两种方式提交训练作业的通用指导。在我们的实现中，我们使用了 AWS SDK for Python (Boto3)。请参阅我们 GitHub 示例仓库中的[示例 notebook](https://github.com/aws-samples/amazon-nova-samples/tree/main/customization/bedrock-finetuning/text-to-sql)，查看我们的分步实现。

### **配置超参数**

选定要微调的模型后，我们接着为自身用例配置超参数。对于 Amazon Bedrock 上的 Amazon Nova Micro 微调，可以定制以下[超参数](http://docs.aws.amazon.com/bedrock/latest/userguide/cm-hp-nova-mm.html)来优化我们的 text-to-SQL 模型：

| 参数 | 范围/约束 | 用途 | 我们采用的取值 |
| --- | --- | --- | --- |
| Epochs | 1–5 | 遍历训练数据集的完整轮数 | 5 个 epoch |
| Batch Size | 固定为 1 | 更新模型权重前处理的样本数 | 1（Nova Micro 固定值） |
| Learning Rate | 0.000001–0.0001 | 梯度下降优化的步长 | 0.00001，以获得稳定收敛 |
| Learning Rate Warmup Steps | 0–100 | 逐步提高学习率的步数 | 10 |

注：这些超参数是针对我们的特定数据集和用例优化过的。最优取值可能因数据集规模和复杂度而异。在示例数据集上，该配置在模型准确度与训练时间之间取得了更好的平衡，训练约 2-3 小时完成。

### **分析训练指标**

Amazon Bedrock 会自动生成训练和验证指标，并存储在指定的 S3 输出位置。这些指标包括：

- **Training loss：**衡量模型对训练数据的拟合程度
- **Validation loss：**反映在未见数据上的泛化表现

## **3a. 使用按需推理部署**

微调作业成功完成后，你可以用按需推理部署自定义 Nova Micro 模型。这种部署方式提供自动伸缩和按 token 计费，非常适合波动的工作负载，且无需预置专用计算资源。

### **调用自定义 Nova Micro 模型**

部署完成后，你可以在 Amazon Bedrock Converse API 中把 deployment ARN 作为模型 ID，以此调用自定义的 text-to-SQL 模型。

```
# Use the deployment ARN as the model ID
deployment_arn = "arn:aws:bedrock:us-east-1:<account-id>:deployment/<deployment-id>"
# Prepare the inference request
response = bedrock_runtime.converse(
    modelId=deployment_arn,
    messages=[
        {
            "role": "user",
            "content": [
                {
                    "text": """Database schema:
CREATE TABLE sales (
    id INT,
    product_name VARCHAR(100),
    category VARCHAR(50),
    revenue DECIMAL(10,2),
    sale_date DATE
);
Question: What are the top 5 products by revenue in the Electronics category?"""
                }
            ]
        }
    ],
    inferenceConfig={
        "maxTokens": 512,
        "temperature": 0.1,  # Low temperature for deterministic SQL generation
        "topP": 0.9
    }
)
# Extract the generated SQL query
sql_query = response['output']['message']['content']['text']
print(f"Generated SQL:
{sql_query}")
```

## **Amazon SageMaker AI 微调方法**

虽然 Amazon Bedrock 方法通过托管训练体验简化了模型定制，但寻求更深入优化控制的组织可能从 SageMaker AI 方法中获益。SageMaker AI 对训练参数提供广泛控制，而这些参数能显著影响效率与模型性能。你可以调整 **batch size** 以优化速度与内存，跨层微调 **dropout 设置**以防止过拟合，并配置 **learning rate 调度**以保证训练稳定性。具体到 LoRA 微调，你可以用 SageMaker AI 定制缩放因子和正则化参数，并针对多模态与纯文本数据集采用不同的优化设置。此外，你还可以调整**上下文窗口大小**和**优化器设置**，以匹配你的具体用例需求。完整代码示例请参阅下面的 [notebook](https://github.com/aws-samples/amazon-nova-samples/tree/main/customization/Nova_1.0/SageMakerTrainingJobs/Amazon-Nova-Text-to-SQL-Sagemaker-Training)。

**配置自定义训练 recipe**

使用 Amazon SageMaker AI 微调 Nova 模型时的一个关键差异点，是能够定制训练 recipe。Recipe 是 AWS 提供的预配置训练栈，帮助你快速开始训练与微调。在保持与 Amazon Bedrock 的标准超参数集（epochs、batch size、learning rate 和 warmup steps）兼容的同时，recipe 通过以下方面扩展了超参数选项：

- **正则化参数**：hidden_dropout、attention_dropout 和 ffn_dropout，用于防止过拟合。
- **优化器设置**：可定制的 beta 系数和 weight decay 设置。
- **架构控制**：面向 LoRA 训练的 adapter rank 与缩放因子。
- **高级调度**：自定义的 learning rate 调度和 warmup 策略。

推荐做法是先以默认设置建立基线，再根据你的具体需求进行优化。下面列出一些你可以进一步优化的附加参数。

| 参数 | 范围/约束 | 用途 |
| --- | --- | --- |
| `max_length` | 1024–8192 | 控制输入序列的最大上下文窗口大小 |
| `global_batch_size` | 16,32,64 | 更新模型权重前处理的样本数 |
| `hidden_dropout` | 0.0–1.0 | 对隐藏层状态做正则化，防止过拟合 |
| `attention_dropout` | 0.0–1.0 | 对注意力机制权重做正则化 |
| `ffn_dropout` | 0.0–1.0 | 对前馈网络层做正则化 |
| `weight_decay` | 0.0–1.0 | 模型权重的 L2 正则化强度 |
| `Adapter_dropout` | 0.0–1.0 | 对 LoRA adapter 参数做正则化 |

我们使用的完整 recipe 可以在[这里](https://github.com/aws/sagemaker-hyperpod-recipes/blob/main/recipes_collection/recipes/fine-tuning/nova/nova_1_0/nova_micro/SFT/nova_micro_1_0_g5_g6_48x_gpu_lora_sft.yaml)找到。

**创建并执行 SageMaker AI 训练作业**

配置好模型和 recipe 后，初始化 `ModelTrainer` 对象并开始训练：

```
from sagemaker.train import ModelTrainer

trainer = ModelTrainer.from_recipe(
    training_recipe=recipe,
    recipe_overrides=recipe_overrides,
    compute=compute_config,
    stopping_condition=stopping_condition,
    output_data_config=output_config,
    role=role,
    base_job_name=job_name,
    sagemaker_session=sess,
    training_image=image_uri
)

# Configure data channels
from sagemaker.train.configs import InputData, S3DataSource

train_input = InputData(
    channel_name="train",
    data_source=S3DataSource(
        s3_uri=train_s3_path,
        s3_data_type="Converse",
        s3_data_distribution_type="FullyReplicated"
    )
)

val_input = InputData(
    channel_name="val",
    data_source=S3DataSource(
        s3_uri=test_s3_path,
        s3_data_type="Converse",
        s3_data_distribution_type="FullyReplicated"
    )
)

# Begin training
training_job = trainer.train(
    input_data_config=[train_input,val_input],
    wait=False
)
```

训练完成后，我们通过 Amazon Bedrock 的 [create_custom_model_deployment](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_CreateCustomModelDeployment.html) API 把模型注册到 Amazon Bedrock，从而可以使用部署后的模型 ARN、system prompt 和用户消息，通过 [converse](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.html) API 进行按需推理。

在我们的 SageMaker AI 训练作业中，我们使用默认的 recipe 参数，包括 2 个 epoch 和 batch size 64；我们的数据包含 20,000 行，因此整个训练作业持续了 4 小时。使用 [ml.g5.48xlarge](https://aws.amazon.com/ec2/instance-types/g5/) 实例，微调 Nova Micro 模型的总成本为 $65。

## **4. 测试与评估**

为了评估模型，我们同时做了运行测试和准确性测试。在准确性方面，我们实现了 LLM-as-a-Judge 方法：收集微调模型给出的问题和 SQL 响应，再用一个 judge 模型对照真实答案给它们打分。

```
def get_score(system, user, assistant, generated):
    formatted_prompt = (
        "You are a data science teacher that is introducing students to SQL. "
        f"Consider the following question and schema:"
        f"<question>{user}</question>"
        f"<schema>{system}</schema>"
        "Here is the correct answer:"
        f"<correct_answer>{assistant}</correct_answer>"
        f"Here is the student's answer:"
        f"<student_answer>{generated}</student_answer>"
        "Please provide a numeric score from 0 to 100 on how well the student's "
        "answer matches the correct answer. Put the score in <SCORE> XML tags."
    )

    _, result = ask_claude(formatted_prompt)
    pattern = r'<SCORE>(.*?)</SCORE>'
    match = re.search(pattern, result)
    return match.group(1) if match else "0"
```

在运行测试方面，我们收集了 TTFT（Time to First Token，首 token 时间）和 OTPS（Output Tokens Per Second，每秒输出 token 数）等指标。与基础 Nova Micro 模型相比，我们在 5 次运行中首次产生 token 的冷启动时间平均为 639 ms（增加 34%）。这一延迟增加源于在推理时应用 LoRA adapter，而不是把它们烘焙进模型权重。不过，这一架构选择带来了可观的成本收益：微调后的 Nova Micro 模型与基础模型价格相同，可按需付费、灵活使用，且没有最低承诺量。在正常运行中，我们在 50 次调用里首 token 时间平均为 380 ms（增加 7%）。端到端延迟合计约 477 ms 即可完成整段响应生成。token 生成速率保持在约每秒 183 个 token，仅比基础模型下降 27%，仍然非常适合交互式应用。

## **成本汇总**

**一次性成本：**

- **Amazon Bedrock 模型训练成本：**每 1,000 个 token $0.001 × epoch 数　对于 2,000 个示例、5 个 epoch、每个约 800 个 token 的情况 = $8.00
- **SageMaker AI 模型训练成本：**我们使用了 ml.g5.48xlarge 实例，价格为 $16.288/小时　使用 20,000 行数据集训练 4 小时 = $65.15
- **持续成本**　**存储：**每个自定义模型每月 $1.95
- **按需推理：**与基础 Nova Micro 相同的按 token 价格　输入 token：每 1,000 个 token $0.000035（Amazon Nova Micro）输出 token：每 1,000 个 token $0.00014（Amazon Nova Micro）

**生产工作负载的示例计算：**

每月 22,000 次查询（100 用户 × 每天 10 次查询 × 22 个工作日）：

- 平均每次查询 800 个输入 token + 60 个输出 token
- 输入成本：(22,000 × 800 / 1,000) × 0.000035 = 0.616
- 输出成本：(22,000 × 60 / 1,000) × 0.00014 = 0.184
- **每月推理总成本**：0.80 USD

这一分析验证了：对于自定义方言的 text-to-SQL 用例，在 Amazon Bedrock 上使用 PEFT LoRA 微调 Nova 模型，比在常驻基础设施上自托管自定义模型更具成本效益。自托管方式可能适合需要对基础设施、安全配置或集成要求做最大程度控制的用例，但 Amazon Bedrock 的按需成本模型能为大多数生产级 text-to-SQL 工作负载带来可观的成本节省。

## **结论**

这些实现选项表明，Amazon Nova 微调可以按组织需求和技术要求进行量身定制。我们探讨了两种不同的方法，分别服务不同的受众和用例。无论你选择 Amazon Bedrock 的托管式简单性，还是通过 SageMaker AI 训练获得更多控制，无服务器部署模型和按需定价都意味着你只需为实际用量付费，同时免去基础设施管理。

**Amazon Bedrock model customization** 方法提供精简的托管方案，消除基础设施的复杂性。数据科学家可以专注于数据准备和模型评估，无需管理训练基础设施，因此非常适合快速实验和开发。

**SageMaker AI training **方法对微调流程的每个方面提供更强的控制。machine learning（ML）工程师可以对训练参数、基础设施选择以及与现有 MLOps 工作流的集成进行细粒度控制，从而按所需的性能、成本和运维要求进行优化。例如，你可以调整 batch size 和实例类型来优化训练速度，或修改 learning rate 和 LoRA 参数，根据具体的运维需求在模型质量与训练时间之间取得平衡

**在以下情况选择 Amazon Bedrock model customization**：你需要快速迭代、ML 基础设施方面的专业知识有限，或者希望在仍能获得定制模型性能的同时把运维开销降到最低。

**在以下情况选择 SageMaker AI training**：你需要细粒度的参数控制、有特定的基础设施或合规要求、需要与现有 MLOps pipeline 集成，或者希望优化训练过程的每一个方面。
