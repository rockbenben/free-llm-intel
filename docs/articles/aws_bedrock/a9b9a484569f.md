# 使用 Amazon EKS 和 SageMaker HyperPod EKS 上的 NVIDIA Nemotron 模型加速代理 AI

NVIDIA [Nemotron 3.5 Super VL](https://aws.amazon.com/about-aws/whats-new/2026/01/nvidia-nemotron-3.5-super-vl-on-sagemaker-jumpstart/) 加入 NVIDIA Nemotron 3 [纳米](https://aws.amazon.com/blogs/machine-learning/run-nvidia-nemotron-3-nano-as-a-complete-management-serverless-model-on-amazon-bedrock/)，[纳米Omni]（https://aws.amazon.com/blogs/machine-learning/nvidia-nemotron-3-nano-omni-model-now-available-on-amazon-sagemaker-jumpstart/），[超级]（https://aws.amazon.com/blogs/machine-learning/run-nvidia-nemotron-3-super-on-amazon-bedrock/）， [Ultra](https://aws.amazon.com/blogs/machine-learning/nvidia-nemotron-3-ultra-now-available-on-amazon-sagemaker-jumpstart/) 和 [Nemotron 3.5 Lightning](https://aws.amazon.com/blogs/machine-learning/nvidia-nemotron-3-5-lightning-now-available-in-amazon-sagemaker-jumpstart/) 模型已在 AWS 上提供。它是一个 120B 参数专家混合 (MoE) 模型，每个代币激活 12B 参数。它将推理和工具使用与文本、图像、文档和视频理解结合起来，因此一种模型可以同时服务于文本和视觉任务。本文探讨了其架构和使用案例，然后展示了如何将其部署在 [Amazon Elastic Kubernetes Service (Amazon EKS)](https://aws.amazon.com/eks/)、[Amazon EKS 自动模式](https://aws.amazon.com/eks/auto-mode/) 和 [Amazon SageMaker HyperPod] 上EKS](https://docs.aws.amazon.com/sagemaker/latest/dg/sagemaker-hyperpod-eks.html)。

## 关于 Nemotron 3.5 Super VL

NVIDIA Nemotron 3.5 Super VL 是从 Nemotron 3 Ultra 中提炼出来的开放式多模式模型。 NVIDIA 发布了权重、训练数据集和训练后配方，因此您可以针对特定领域的工作负载自定义模型，并在您控制的基础设施上运行它。型号详情：

- 总参数 120B，每个令牌 12B 活跃。
- Hybrid Mamba-2、[MoE](https://www.nvidia.com/en-us/glossary/mixture-of-experts/) 以及带有 RADIO 视觉编码器的注意力层。
- 上下文长度最多 1M 个令牌。
- 输入：文本、图像、文档和视频。
- 输出：文本。
- BF16 和 NVFP4 检查点。

NVIDIA 在 [Hermes Bench](https://portal.nousresearch.com/bench) 上的得分为 63.44%，在 LangChain 代理评估上的得分为 87.05%，在 CharXiv 图表推理基准上的得分为 80.8%。 （[技术报告](https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3.5-Super-and-Lightning-Technical-Report.pdf)）

### 模型架构

Nemotron 3.5 Super VL 使用混合 Mamba-Transformer MoE 架构，交错 Mamba-2、注意力层和专家层。稀疏路由会激活每个 token 120B 参数中的 12B，因此每个 token 的计算匹配一个小得多的模型，而 GPU 内存仍然保留完整的权重。 Mamba-2 层在生成过程中携带恒定大小的状态，因此它们的内存不会像 KV 缓存那样随着序列长度而增长，这使得长上下文可以承受。递归共享的多令牌预测 (MTP) 头支持本机推测解码。

### 用例

Nemotron 3.5 Super VL 支持将推理与视觉理解相结合的代理工作流程：

- **编码：**测试和验证代码，分析错误，建议修复。
- **网络研究：**交叉引用并验证搜索工具返回的来源。
- **文档智能：** 阅读表格、图表和页面布局以生成摘要。
- **网络安全：**识别漏洞并分类威胁。
- **视频理解：**搜索、内容、评论和事件分析。

Nemotron 3.5 Super VL 通过 NVIDIA 参考实现、说明书和 [NVIDIA Agent Toolkit](https://blogs.nvidia.com/blog/nvidia-agent-toolkit-open-models-tools-skills-secure-runtime-ai-agents/) 与主要开放代理框架和编排系统集成。有关受支持框架的完整列表，请参阅 [NVIDIA 开发人员博客](https://developer.nvidia.com/blog/nvidia-nemotron-3-5-super-vl-powers-specialized-agents-with-multimodal-reasoning/)。

## 在 AWS 上部署

本节概述架构、验证和性能评估方法。 [aws-do-eks](https://bit.ly/do-eks) 项目中提供了在 AWS 上部署 Nemotron 3.5 Super VL 和 Nemotron 3 Ultra 的详细[演练](https://github.com/aws-samples/aws-do-eks/tree/main/Container-Root/eks/deployment/inference/agentic-ai/nemotron)，包括先决条件、集群创建、模型权重下载、部署、测试、基准测试和清理。同样的模式也适用于 NVIDIA Nemotron 系列中的其他型号。

### 部署架构

[参考实现](https://bit.ly/aws-do-nemotron) 在标准 Amazon EKS、EKS 自动模式和 SageMaker HyperPod EKS 上运行。借助 EKS 自动模式，AWS 可以代表您管理集群中的扩展、GPU 和 EFA 支持。对于每个协调器选项，模型部署的 Kubernetes 清单都是相同的。每个集群都有一个托管 Kubernetes API 的控制平面以及一个 CPU 和 GPU 节点的数据平面。 CPU 节点运行系统和测试 Pod，而 GPU 节点运行模型。 Amazon Elastic Container Registry (Amazon ECR) 存储容器映像，共享的 Amazon FSx for Lustre 卷保存模型权重，Elastic Fabric Adapter (EFA) 连接 GPU 节点。下图显示了标准 Amazon EKS 集群。

图 1：用于服务 NVIDIA Nemotron 模型的标准 Amazon EKS 集群架构

NVIDIA Dynamo 提供在单个节点上聚合的模型，或在不同节点上通过预填充和解码进行分解的模型。对于视觉语言模型，图像/视频编码阶段还可以在其自己的节点上分解运行。

图 3：已部署模型的 aiperf 性能指标

左上方窗格中的 aiperf 输出显示关键性能指标 (KPI)，例如首次令牌时间 (TTFT)、令牌间延迟 (ITL) 和每秒令牌吞吐量 (TPS)。通过在不同的并发级别进行这些测量，我们可以研究延迟和吞吐量如何依赖于并发请求的数量。此信息对于仔细规划容量和模型部署拓扑至关重要。 [aws-do-eks 容器](https://gallery.ecr.aws/hpc-cloud/aws-do-eks) 提供自动化功能，用于可视化 GPU 和 EFA 利用率以及使用单个命令运行 aiperf 和并发扫描。

![比较 TTFT 和 ITL 跨并发级别的聚合与分解部署的并发扫描图表](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/28/ML-21105-4.png)

图 4：比较聚合和分解部署的并发扫描

前面的并发扫描图显示，Nemotron 3.5 Super VL 的推理具有较低的 TTFT，并且两个节点上的聚合和分解部署之间的 ITL 大致相同。

在做出部署决策时，这样的图表非常有用。将延迟预算绘制为水平线，例如每个令牌的 TTFT 低于 600 毫秒（约 1 秒），ITL 低于 100 毫秒。两条线下方最右边的点是该拓扑的一个副本可以在服务级别目标 (SLO) 内提供的吞吐量，此处为 c32，或每秒大约 320 个令牌。要规划容量，请将每秒目标令牌除以每个副本的吞吐量，并找到要部署的预填充解码对的数量。更改后重新运行相同的扫描（精度、TP/PP 形状、聚合与分解、新的 Dynamo 或 vLLM 版本）可以立即看到权衡。向右和向下移动的曲线是胜利。由于 TTFT 和 ITL 是分开绘制的，因此它还告诉您要缩放哪一侧：ITL 上升表示增加解码容量，TTFT 上升表示增加预填充容量。
