# 借助 Amazon Bedrock AgentCore 和 Amazon Nova Sonic 2.0，用 agentic AI 电影助手交付高度个性化的观众体验

用基于 Amazon Nova Sonic 2.0 的 agentic AI 电影助手交付高度个性化的观众体验。推荐系统是现代媒体流媒体服务的支柱，塑造着用户如何发现内容。传统机器学习（ML）系统用协同过滤或基于内容的过滤来预测内容偏好，但它们常常抓不住依赖情境的需求，例如一天中的时间、心情或社交场合。举例来说，看完《The Shawshank Redemption》之后，系统可能会再推荐几部监狱题材的剧情片，却忽略了用户其实想看点轻松的来放松。混合式做法弥合了这一缺口：它把传统机器学习的模式识别能力，与生成式 AI 的上下文理解和对话能力结合起来。Agentic AI 更进一步，通过动态对话围绕观看情境进行推理，与用户互动。这些推荐 agent 综合来自多个来源的信息——剧情简介、影评、观看历史——并纳入用户的实时反馈。用户可以询问具体场景或主题，agent 会给出带上下文的解释。这样的体验就像在咨询一位既懂内容、又懂个人偏好的博学策展人。

本文中，我们逐一介绍两个有助于提升用户观看体验的用例。第一个：想象你告诉 AI agent，忙完一天后想看点好玩的，然后拿到匹配你当下心情、而不只是匹配你过去观看记录的推荐。第二个：想象你在看电影途中暂停，问一句“那个演员是谁？”或者“把刚才发生的事总结一下？”，然后立刻得到答案。构建这样一个对话式助手，需要编排实时语音处理、上下文管理、工具调用和经过筛选的响应。这是一项复杂的挑战，而我们可以借助 agentic AI 的工具与框架来简化它，包括 [Strands Agents SDK,](https://strandsagents.com/latest/) [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 和 [Amazon Nova Sonic 2.0](https://nova.amazon.com/sonic)。这套 agentic AI 系统使用 [Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro)（MCP），交付一位通过自然对话理解用户偏好的私人娱乐礼宾。我们在 [GitHub](https://github.com/aws-samples/sample-hyper-personalized-agentic-ai-media-assistant) 仓库中分享了该应用的代码示例。

## 架构

方案架构聚焦两件事：1/ 电影推荐，2/ 电影场景分析。我们会在本文后续章节中更详细地展开这两条流程。

![超个性化 agentic AI 助手的端到端架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/23/architecture-diagram-1024x574-1.jpg)

**用户交互工作流**

- 用户在 Web UI 上完成身份验证；该 UI 作为静态网站托管在 Amazon Simple Storage Service（Amazon S3）上，并通过 [Amazon CloudFront](https://aws.amazon.com/cloudfront/) 配合 [Amazon Cognito](https://aws.amazon.com/cognito/) 提供服务。
- 客户端向部署在 [AWS Fargate](https://aws.amazon.com/fargate/) 上的服务器建立 WebSocket 连接，该服务器通过 Amazon CloudFront 端点对外暴露。客户端与服务器之间的会话通信都走这条连接。WebSocket 连接要求在建立时校验 JWT token。
- AWS Fargate 服务器校验传入连接，并与 [Amazon Nova Sonic 2.0](https://aws.amazon.com/nova/speech/) 建立会话，用于与服务器之间的双向流式通信。
- 用户的语音指令通过已建立的 WebSocket 连接发送给 Amazon Nova Sonic 模型。Fargate 容器使用双向的 Smithy 流式 RPC 协议与 Nova Sonic 模型通信。模型返回的响应由容器处理。
- AWS Fargate 容器管理来自 Nova Sonic 的工具事件，并通过 MCP server 处理用户请求，从而发起 agentic 工作流。[Amazon Bedrock AgentCore Gateway](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/gateway.html) 帮助把 [AWS Lambda](https://aws.amazon.com/lambda/) 函数转换成供 agent 使用的 MCP 兼容工具。
- AWS Lambda 使用 Amazon Nova 理解模型（micro、lite、pro）进行处理，并由 [OpenSearch 和 S3 Vector](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-opensearch.html) 承担语义搜索与存储层。结果通过 Amazon Bedrock AgentCore Gateway 返回给服务器。
- AWS Fargate 把响应发给 Amazon Nova Sonic，由其完成最终语音回复的组织。语音回复通过 WebSocket 连接流式传输到 Web UI。

### **自然语音用户界面**

我们使用 Amazon Nova Sonic 2.0——我们最新的语音到语音模型，能以低延迟提供实时、类人的语音对话。它带来的用户体验是流畅的交流，感觉确实像在对话，帮助把 AI 交互从僵硬的问答环节转变为动态、有产出的对话。借助[异步支持](https://docs.aws.amazon.com/nova/latest/nova2-userguide/sonic-async-tools.html)来完成的任务，你可以在活跃对话期间把复杂任务放到后台处理，同时保持对话流畅。最后，Nova Sonic 2.0 原生支持文本输入和流式语音输入，让你在与 AI 助手交互的方式上拥有灵活性。你还可以在对话开始时提供 system prompt 来定义 AI 助手的个性。能够控制助手个性，可以确保响应始终与品牌一致、不越界，从而帮助保护你的服务声誉。我们分享了一些[最佳实践](https://docs.aws.amazon.com/nova/latest/userguide/prompting-speech-best-practices.html)，讲如何用 Nova Sonic 编写有效的 system prompt，以尽可能提升效果。我们方案中定义的完整 system prompt 可以在[这个 module](https://github.com/aws-samples/sample-hyper-personalized-agentic-ai-media-assistant/blob/main/react-client/src/helper/s2sEvents.js) 中找到。

### **预处理工作流**

下图展示了从影片目录数据、电影场景和电影剧本中生成关键洞察的离线流程。这些洞察支撑我们方案中的电影个性化与场景分析工作流，并作为电影助手 agent 的基础知识。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/20/ds-offline-flow-scaled.jpg)

为展示电影个性化功能，我们创建了 500 部示例电影来代表片库。电影的元数据（包括片名、类型和简介）被转换成 embedding，也就是一种捕捉其含义的数值表示。这使语义搜索成为可能：查询按含义而不是按精确关键词来匹配。其他元数据（包括演员阵容和上映日期）作为属性存储在同一个索引中，该索引位于一个 Amazon OpenSearch Service 集群内，由 Amazon Simple Storage Service（Amazon S3）Vector 作为存储层。这个索引被用来支撑上一节所述的混合式电影推荐搜索工作流。

为了让场景分析功能达到高精度，我们把媒体内容的处理拆成两步。第一步，我们使用 [ Amazon Bedrock Data Automation ](https://aws.amazon.com/bedrock/bda/) 从视频内容中提取关键洞察。这些洞察包括章节级摘要及对应的时间码、转录文本、音频片段等。此外，我们使用 [Amazon Rekognition 中的名人识别功能](https://docs.aws.amazon.com/rekognition/latest/dg/celebrities.html) 来识别章节中出现的名人。第二步，我们使用由 Amazon Bedrock Data Automation 提取的电影剧本所生成的 embedding 做语义相似度搜索。这些 embedding 是 agent 用以在剧本中找到与给定电影场景摘要语义最相似时刻的基础。我们会在后文提供更多细节。

### **电影推荐流程**

下面的用户交互更详细地演示了内容个性化工作流：

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/19/ML-19121-3.gif)

参考上图的流程：当用户请求电影推荐时，Amazon Nova Sonic 识别出用户意图，并触发相应的工具来处理电影推荐请求。一个 Lambda 函数通过 AgentCore Gateway 被触发来处理该请求。该函数先从 DynamoDB 表中检索用户的亲和度（affinity），以更好地理解用户画像。这张表刻画了每个用户在偏好、品味和观看模式上的个性化档案。举例来说，如果用户过去看过** Harry Potter **系列，系统就可能给奇幻和冒险类型分配更高的亲和度。把用户亲和度与用户查询结合起来，我们通过多个按顺序串联的大语言模型（LLM）调用处理该请求。首先，一个 LLM 根据查询意图对搜索类型进行分类。这一分类有助于确定应该使用哪种搜索查询，比如一般性电影推荐、直接检索某部电影、电影台词，或者与电影完全无关的内容。考虑到性价比，我们为此 prompt 使用 Amazon Nova Micro。提取意图分类及其他元数据的 prompt 可以在[这份代码示例](https://github.com/aws-samples/sample-hyper-personalized-agentic-ai-media-assistant)中找到。

接下来，我们把用户查询发给另一个 LLM 进行改写，得出更丰富、更相关的搜索查询，用于对电影目录数据做语义搜索。举例来说，下面这条用户查询：

`我想找几部好玩的电影，你有什么推荐？`

会被改写成：

`有趣、好玩的电影，具备幽默感、刺激感或令人愉快的叙事`

通过内部测试，我们发现使用 Amazon Nova Lite 能以最具成本优化的方式产出结构化响应。完整的查询改写 prompt 片段见[这份代码示例](https://github.com/aws-samples/sample-hyper-personalized-agentic-ai-media-assistant/blob/main/backend/stack/stack_constructs/prompts/rewrite_prompt.txt)。

查询改写与意图分类这两个 prompt 的输出，被用作 Amazon OpenSearch Service 搜索查询的参数。我们用 [Nova embeddings](https://docs.aws.amazon.com/nova/latest/nova2-userguide/embeddings.html) 把改写后的查询转换成 1024 维向量，用于语义搜索。此外，我们的搜索查询还加入了时效性和热度加权，把更新、表现更好的剧集在推荐排序中往前提。一个搜索查询的示例片段可以在下面这个 [OpenSearch module](https://github.com/aws-samples/sample-hyper-personalized-agentic-ai-media-assistant/blob/main/backend/stack/lambdas/create_update_conversation/opensearch_helper.py) 的 `_get_titles_from_query_v2` 函数中找到。

示例搜索查询返回了 30 部相关电影。最后，我们使用 Amazon Rerank 模型，基于搜索结果和改写后的用户查询对推荐电影重新排序，返回最相关的三部。该过程在整个用户会话中反复执行，对话历史作为上下文的一部分传入前一个 LLM 链，进一步帮助丰富用户体验。下面是电影推荐查询的一个示例截图：

**电影场景分析流程**

与推荐流程类似，这里我们概述一条通过相同组件实现的场景分析工作流。设想你不得不休息一下，错过了最爱剧集的几分钟，这位助手会给你一份摘要。它还能给出某个场景的详细分析，包括出场的演员以及场景里发生了什么。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/03/19/ML-19121-7.gif)

当用户暂停电影来提问时，应用会抓取相关元数据，例如当前时间码和电影片名，然后把这些信息存入 Amazon DynamoDB 表以供后续使用。举例来说，如果用户问：“**你能不能告诉我这个场景里发生了什么？”**，应用会参考用户观看日志来定位最新状态以及用户正在观看的电影。场景分析由 Amazon Nova Sonic 基于对用户对话的上下文理解所触发的工具来处理。我们通过多个按顺序串联的 LLM 调用处理场景分析请求。首先，我们用 Amazon Nova Micro 配合一段 prompt，根据用户查询对场景分析的意图进行分类。这项任务所用的 prompt 可以在 [movie scene assistant](https://github.com/aws-samples/sample-hyper-personalized-agentic-ai-media-assistant/blob/main/backend/python-server/movie_scene_assistant.py) 模块的 `movieScene_classfier` 函数中找到。

基于意图分类功能，我们触发相应的工作流来处理场景细节。本节我们聚焦场景级细节。利用检索到的用户观看日志，我们提取与给定时间码匹配的章节摘要、转录文本以及已知名人。包括场景细节和电影剧本在内的电影洞察，由 Amazon Bedrock Data Automation 处理，并存放在一个 Amazon OpenSearch Serverless collection 中，用于语义搜索与过滤。当用户观看日志落在某个章节的开头时，我们会选择性地带上上一章的信息，以便提供更好的上下文、帮助丰富场景分析。接下来，我们用提取到的场景细节在电影剧本中寻找语义最相似的片段，并用剧本细节来提供更丰富的场景理解。为演示这一过程，我们以从 [Tears of Steel](https://mango.blender.org/) 中提取的 5:15–5:40 之间的一场戏为例：

根据 Amazon Bedrock Data Automation 生成的洞察，上一场景的章节摘要如下：

> 在一座历史悠久的欧洲城市里，一个巨型机器人撞穿屋顶，造成破坏。一名装着机械眼的男子从阳台上观察机器人的动作。他对着画面外的人说：“让她进来”，并说“还有两分钟”。接着他催促道：“快一点，哥们”，表明这是一次时间紧迫的行动。另一名持步枪的男子出现，位置便于与机器人交战。这场戏显示一场军事或战术行动正在进行，机器人是主要威胁。机械眼男子盯着倒计时器，表明他们正准备与机器人正面对抗。\n[spk_0]：让她进来。还有两分钟。两分钟。快一点，哥们。

我们使用上一场景的摘要，对由 Amazon Bedrock Knowledge Bases 管理的 Amazon OpenSearch 索引执行语义搜索。数据源包含经过预处理的电影剧本，chunk 大小为 300 token，重叠 10%。我们用 [Amazon Rerank ](https://docs.aws.amazon.com/bedrock/latest/userguide/rerank.html)模型对检索到的文档重新排序，选出最佳片段作为场景描述的最终表示。下面是从重排过程中得到的一段剧本示例：

> 它环顾四周，然后发现了塔里的 Barley。BARLEY：（对着无线电）好，他们来了。还有两分钟！14. 内景 教堂/掩体 清晨。导演通过无线电听着 Barley 说话。BARLEY：（续）（通过无线电）两分钟。DIRECTOR：（通过无线电对扩音器）快一点，Thom！Vivacissimo！15. 外景 街道 白天。Thom 和 Celia 分手的重演继续，Celia 现在比原先更具威胁性，不再那么难过，而是更具威慑。CELIA：你为什么不干脆承认，你是被我的机械手吓到了？天空中又出现一些字让 Thom 读：“Celia，我爱你的机械手”，不过他决定不予理会。6. THOM：听着，Celia，我那时还年轻。但这不是毁灭世界的理由。Celia 继续威胁地盯着 Thom，开合她的机械手。16. 内景 教堂/掩体 清晨。导演和助理在办公室里看着这一幕展开。ASSISTANT：他为什么要这么做？DIRECTOR：那一招我们已经试过了！17. 外景 街道 白天。

最后，我们用 Amazon Nova Micro 总结上一场景的信息。响应由 Amazon Nova Sonic 转换为自然语音，再流式回传给用户，完成这次交互。下面是 Amazon Nova Sonic 产出的最终叙述：

> 在这个场景中，Barley 在塔顶倒数计时，制造出紧迫感。下方掩体里，导演正在下令加快动作。街道上，Thom 和 Celia 紧张对峙。Celia 有一只骇人的机械手，Thom 承认了自己过去的错误。导演和助理看着这一幕展开，尽管助理满心困惑，导演仍保持专注。

## **结论**

本文中，我们展示了一个会话式 AI agent：它以**自然语音交互**理解并回应，帮助用户以个性化方式**发现****电影和电视节目**，并在观看过程中提供**实时洞察**。系统分析用户的个人观看模式和观看历史，构建个性化档案，用以驱动相关推荐。举例来说，一位常看动作片的用户，在问“好玩的电影”这类泛泛的主题问题时，可以得到与动作片相关的推荐。你可以通过语音指令与 AI 交互，获得量身定制的内容建议、获取演员的详细信息，以及对正在观看的电影中特定场景的即时解释。该方案展示了 Nova Sonic 2.0 理解自然语言、执行语义知识库搜索、管理播放列表以及在多轮对话中保持上下文的能力。这一做法相比基于隐式反馈的推荐是一次显著跃升，转向显式的、对话式的偏好收集。这最终有助于打造更具吸引力、更直观的内容发现体验，从而提升用户参与度和服务留存率。
