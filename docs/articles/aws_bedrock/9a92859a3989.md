# 释放生成式 AI 的力量：Druva 用于简化数据保护的多 agent copilot

*本文与 Druva 的 David Gildea 和 Tom Nijs 共同撰写。*

生成式 AI 正在改变企业与客户互动的方式，也在重塑复杂 IT 运维的对话式交互界面。[Druva](https://www.druva.com/) 是数据安全解决方案的领先提供商，正站在这场变革的前沿。Druva 与 Amazon Web Services（AWS）合作，正在开发一款前沿的、由生成式 AI 驱动的多 agent copilot，目标是重新定义数据安全与网络韧性领域的客户体验。

该方案由 [Amazon Bedrock](https://aws.amazon.com/bedrock/?trk=36201f68-a9b0-45cc-849b-8ab260660e1c&sc_channel=ps&ef_id=Cj0KCQjwoZbBBhDCARIsAOqMEZUWjL8nfrIzig0l53TU6ydK3_zcySLwF8Gmcn_p--d43t31eiS9eR4aArKdEALw_wcB:G:s&s_kwcid=AL!4422!3!692006004850!e!!g!!amazon%20bedrock!21048268689!159639953975&gad_campaignid=21048268689&gbraid=0AAAAADjHtp94HJQ-CX-VlbQXMG7OUjKlX&gclid=Cj0KCQjwoZbBBhDCARIsAOqMEZUWjL8nfrIzig0l53TU6ydK3_zcySLwF8Gmcn_p--d43t31eiS9eR4aArKdEALw_wcB) 提供支撑，并使用先进的大语言模型（LLM），将为 Druva 的客户提供一个直观的对话式界面，以便在产品套件中获取数据管理、安全洞察和运维支持。通过发挥生成式 AI 与 agentic AI 的力量，Druva 希望简化运营、提升客户满意度，并增强其数据安全与网络韧性解决方案的整体价值主张。

本文将剖析这款 AI copilot 背后的技术架构，探讨它如何处理自然语言查询、如何在复杂 workflow 中保持上下文，以及如何给出安全、准确的响应以简化数据保护运维。

## 挑战与机遇

Druva 希望有效服务于那些正在超越传统基于查询的 AI、迈向 agentic 系统的企业，并以更快的速度、更简单的方式和更强的信心满足其复杂的数据管理与安全需求。

全面的数据安全需要跟踪大量数据与指标，以识别潜在的网络威胁。随着威胁不断演变，客户很难及时掌握组织数据中需要排查的新数据异常，而漏掉任何威胁信号都可能导致敏感信息被未授权访问。例如，一家在多个区域管理 500 多台服务器的全球金融服务公司，目前在备份失败时要花数小时人工检查数十个系统的日志。有了 AI copilot，他们只需问一句「为什么我的备份昨晚失败了？」，就能立刻得到分析结果：某次策略更新在其欧洲数据中心引发了冲突，并附带分步修复步骤，从而把排查时间从数小时缩短到几分钟。该解决方案不仅减少了支持请求的数量、加快了解决时间，还为最终用户带来了更高的运营效率。

通过重新构想用户与系统交互的方式——从 AI 驱动的 workflow 到更智能的自动化——Druva 看到了一个明确的机会：提供更无缝的客户体验，从而增强客户满意度、忠诚度与长期成功。

Druva 在实施生成式 AI 驱动的多 agent copilot 方面的关键机会包括：

- **简化的用户体验**：通过提供自然语言界面，copilot 可以简化复杂的数据保护任务，帮助用户快速获取所需信息。
- **智能故障排查**：copilot 可以利用 AI 能力分析来自不同来源的数据，定位备份失败的根本原因，并提供个性化的解决建议。
- **简化的策略管理**：多 agent copilot 可以引导用户完成数据保护策略的创建、修改和实施过程，降低人为出错的可能性并改善合规性。
- **主动支持**：通过持续监控数据保护环境，copilot 可以主动识别潜在问题并提供指导，帮助预防故障或优化性能。
- **可扩展且高效的运营**：该 AI 驱动的解决方案可以同时处理大量客户咨询与任务，减轻 Druva 支持团队的负担，使他们能够专注于更复杂、更具战略性的工作。

## 解决方案概览

为 Druva copilot 提出的解决方案采用了一套精巧的架构，结合 [Amazon Bedrock](https://aws.amazon.com/bedrock/?trk=36201f68-a9b0-45cc-849b-8ab260660e1c&sc_channel=ps&ef_id=Cj0KCQjwoZbBBhDCARIsAOqMEZUWjL8nfrIzig0l53TU6ydK3_zcySLwF8Gmcn_p--d43t31eiS9eR4aArKdEALw_wcB:G:s&s_kwcid=AL!4422!3!692006004850!e!!g!!amazon%20bedrock!21048268689!159639953975&gad_campaignid=21048268689&gbraid=0AAAAADjHtp94HJQ-CX-VlbQXMG7OUjKlX&gclid=Cj0KCQjwoZbBBhDCARIsAOqMEZUWjL8nfrIzig0l53TU6ydK3_zcySLwF8Gmcn_p--d43t31eiS9eR4aArKdEALw_wcB)（包括 Amazon Bedrock Knowledge Bases）、LLM 以及动态 API 选择流程的力量，提供智能且高效的用户体验。下图展示了端到端架构及各个子组件。

![解决方案架构](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/21/image-1-ML-17621.png)

系统的核心是 *supervisor agent*，它作为多 agent 系统的中央协调组件。该 agent 负责统筹整个对话流程、把任务委派给专用子 agent，并在各组件之间维持无缝通信。

用户通过用户界面与 supervisor agent 交互，提交与数据保护、备份管理和故障排查相关的自然语言查询。supervisor agent 分析用户的输入，并根据查询的性质把请求路由到合适的子 agent。

*data agent* 负责通过与 GET API 交互，从 Druva 的系统中检索相关信息。该 agent 获取计划中的备份作业、备份状态及其他相关细节，为用户提供准确、最新的信息。

help agent 通过提供最佳实践指导、分步说明和排查建议来帮助用户。该 agent 依托一个内容丰富的知识库（包括详细的 API 文档、用户手册和常见问题），为用户提供贴合具体情境的协助。

当用户需要执行关键操作时，例如发起备份作业或修改数据保护策略，*action agent* 就会登场。该 agent 与 POST API 端点交互以执行必要的操作，确保及时、准确地满足用户需求。

为确保多 agent copilot 以最合适的 API 和参数运行，该方案引入了动态 API 选择流程。下图展示了用于实现动态 API 选择的各项 AWS 服务，data agent 与 action agent 都具备这一能力。Bedrock Knowledge Bases 包含关于可用 API、其功能以及最佳使用模式的全面信息。收到输入查询后，我们使用语义搜索检索 top K 个相关 API。这种语义搜索能力使系统能够适应每个用户请求的具体上下文，提升 copilot 的准确性、效率和可扩展性。确定合适的 API 后，agent 会提示 LLM 解析 top K 个相关 API，并最终确定 API 选择及其所需参数。这一步确保 copilot 具备有效执行用户请求的完整能力。

![动态 API 选择](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/10/21/image-2-ML-17621.png)

最后，被选中的 API 会被调用，多 agent copilot 执行目标操作或检索所需信息。用户通过用户界面收到清晰简洁的响应，以及相关的建议或指导。

在整个交互过程中，用户可以在 copilot 执行关键操作之前，通过 user feedback 节点提供补充信息或明确批准。借助这种 human-in-the-loop 方式，系统在运行时具备必要的防护措施，并让用户对敏感操作保持控制。

## 评估

Druva 这款生成式 AI 驱动的多 agent copilot 的评估过程，着眼于评估系统各个关键组件的性能与有效性。通过对动态 API 选择等单个组件、对各 agent 的隔离测试以及端到端功能进行充分测试，copilot 才能为用户交付准确、可靠且高效的结果。

评估方法：

- **单元测试**：对每个组件（单个 agent、数据抽取、API 选择）执行隔离测试，以验证其功能、性能和错误处理能力。
- **集成测试**：执行测试以验证多 agent copilot 各组件之间的无缝集成与通信，保持数据流与控制流的完整性。
- **系统测试**：在完整系统上执行端到端测试，模拟真实世界的用户场景与 workflow，以评估整体功能、性能和用户体验。

## 评估结果

为合适的任务选择正确的模型，对系统性能至关重要。动态工具选择是系统中最关键的环节之一——调用正确的 API 是端到端方案成功的关键。一次错误的 API 调用就可能导致取到错误的数据，并在整个多 agent 系统中级联出错误结果。为优化动态工具选择组件，我们测试了多种 Nova 与 Anthropic 模型，并对照使用 Sonnet 3.7 创建的基准真值进行了评测。

结果表明，即使是 Nova Lite 和 Haiku 3 这样较小的模型，也每次都选对了 API。但这些小模型在参数解析上表现吃力，例如相对输入问题调用 API 时给出正确的参数。把参数解析准确率纳入考虑后，整体 API 选择准确率下降到：Nova Micro 81%、Nova Lite 88%、Nova Pro 93%。Haiku 3、Haiku 3.5 和 Sonnet 3.5 的表现相当，在 91% 到 92% 之间。Nova Pro 在准确率与延迟之间提供了最优权衡，平均响应时间略超过一秒。相比之下，Sonnet 3.5 的延迟为 8 秒，不过这可能归因于 Sonnet 3.5 的输出更冗长——平均生成 291 个 token，而 Nova Pro 为 86 个。prompt 还有优化空间，可以让 Sonnet 3.5 的输出更简洁，从而降低延迟。

针对真实世界场景的端到端测试，必须邀请熟悉该系统的人类领域专家评估者，依据解决方案的完整性、准确性和相关性来评估性能。在初期开发阶段的 11 个高难度问题上，系统在这些维度上的平均得分为 5 分制下的 3.3 分。考虑到评估是在开发的早期阶段进行的，这已经是不错的表现，为后续改进奠定了坚实基础。

通过聚焦于评估每个关键组件并开展严格的端到端测试，Druva 确保这款生成式 AI 驱动的多 agent copilot 达到准确性、可靠性和效率的最高标准。评估过程中获得的洞察，指导了 copilot 的持续改进与优化。

## 结论

Druva 这款生成式 AI 驱动的多 agent copilot 展示了结合结构化与非结构化数据源、用 AI 打造下一代虚拟 copilot 的巨大潜力。这一创新做法使 Druva 区别于传统数据保护厂商：把耗时数小时的人工调查转变为即时的、AI 驱动的对话式洞察，90% 的常规数据保护任务都能通过自然语言交互完成，从根本上重新定义了客户在数据安全领域的期望。对于数据安全与数据保护领域的组织而言，这项技术能带来更高效的运营、更强的客户互动以及数据驱动的决策。copilot 提供的洞察与智能，让 Druva 的各类相关方——包括客户、支持团队、合作伙伴和高管——能够更快做出明智决策，把数据安全问题的平均解决时间缩短最多 70%，并将备份排查从数小时加速到数分钟。虽然本项目聚焦于数据保护行业，但其底层原则与方法可以应用于各个领域。通过精心的设计、测试和持续改进，任何行业的组织都能受益于 AI 驱动的 copilot，让它们的数据、文档和内容获得上下文化处理，从而提供智能且个性化的体验。

本实现借助 Amazon Bedrock AgentCore Runtime 和 Amazon Bedrock AgentCore Gateway，提供稳健的 agent 编排与管理能力。这一方式有望通过可定制的 agent 提供智能自动化与数据搜索能力，让用户与应用的交互变得更自然、更高效、更有效。如果你有兴趣实现类似功能，可以探索 [Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/)、[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 和 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/)，作为完全托管的 AWS 解决方案。
