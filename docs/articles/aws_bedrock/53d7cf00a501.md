# 使用 Amazon Bedrock Data Automation 和 Amazon SageMaker AI 处理多页文档并引入人工审核

各行各业的组织都在面对大量多页文档带来的挑战，这些文档需要经过智能处理才能提取出准确的信息。尽管自动化已经改善了这一流程，但在特定场景下仍然需要人的专业判断来核实数据的准确性与质量。

2025 年 3 月，AWS 推出 [Amazon Bedrock Data Automation](https://aws.amazon.com/bedrock/bda/)，让开发者能够从文档、图像、视频和音频等非结构化多模态内容中自动生成有价值的洞察。Amazon Bedrock Data Automation 通过自动化地从未结构化内容中提取、转换并生成洞察，简化了文档处理工作流。它借助统一的、多模态的推理 API，把数据准备、模型管理、微调、prompt engineering 与编排等耗时工作降到最低，以低于其他方案的成本交付业界领先的准确率。

Amazon Bedrock Data Automation 简化了复杂的文档处理任务，包括文档拆分、分类、提取、归一化和校验，同时提供带置信度分数的视觉定位（visual grounding）以增强可解释性，并内置幻觉缓解能力，因此能从非结构化数据源中给出可信的洞察。然而，尽管 Amazon Bedrock Data Automation 的先进能力带来了出色的自动化，仍然存在需要人的判断、且这种判断极为宝贵的场景。这正是它与 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker-ai) 集成、构成强大端到端方案的意义所在。把人工审核循环引入文档处理工作流之后，组织既能保持最高水平的准确度，又能保持处理效率。借助人工审核循环，组织可以：

- 在置信度低时校验 AI 的预测结果
- 有效处理边缘情况与异常
- 通过恰当的监督维持监管合规
- 在最大化自动化的同时保持高准确度
- 建立反馈循环，随时间推移持续改进模型表现

通过有策略地部署人工循环，组织可以把人的注意力集中在文档中不确定的部分，让自动化系统处理常规提取，从而在效率与准确度之间取得最优平衡。在本篇博文中，我们将展示如何结合 Amazon Bedrock Data Automation 与 SageMaker AI，在引入人工审核循环的情况下处理多页文档。

## 理解置信度分数

置信度分数对于判断何时触发人工审核至关重要。置信度分数表示 Amazon Bedrock Data Automation 对你这次提取结果准确性的确定程度百分比。

我们的目标是简化智能文档处理（intelligent document processing，IDP）：把准确度计算这类重活都在 Amazon Bedrock Data Automation 内部处理掉。这样客户可以专注于用 Amazon Bedrock Data Automation 解决自己的业务难题，而不必应付复杂的评分机制。Amazon Bedrock Data Automation 针对 Expected Calibration Error（[ECE](https://towardsdatascience.com/expected-calibration-error-ece-a-step-by-step-visual-explanation-with-python-code-c3e9aa12937d/)）来优化其模型，这一指标有助于实现更好的校准，从而得到更可靠、更准确的置信度分数。

在文档处理工作流中，置信度分数通常这样解读：

- **高置信度（90–100%）** – 对提取结果的确定性很高
- **中等置信度（70–89%）** – 有合理的把握，但仍可能存在错误
- **低置信度（<70%）** – 不确定性很高，很可能需要人工核实

我们建议在你自己的具体数据集上测试 Amazon Bedrock Data Automation，以确定触发人工审核工作流的置信度阈值。

## 方案概览

下面的架构提供了一个无服务器方案，使用 Amazon Bedrock Data Automation 和 SageMaker AI 在带人工审核循环的情况下处理多页文档。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/24/ML-18583-arch-diagram.png)

该工作流包含以下步骤：

- 文档被上传到 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）输入桶，该桶是文档进入 Amazon Bedrock Data Automation 处理的入口。
- 一条 [Amazon EventBridge](https://aws.amazon.com/eventbridge/) 规则会自动检测 S3 桶中的新对象，并触发负责编排文档处理流水线的 [AWS Step Functions](https://aws.amazon.com/step-functions/) 工作流。
- 在 Step Functions 工作流内部，会执行 `bda-document-processor` [AWS Lambda](https://aws.amazon.com/lambda) 函数，该函数带着合适的 blueprint 调用 Amazon Bedrock Data Automation。Amazon Bedrock Data Automation 使用这些预先配置好的指令来提取并处理文档中的信息。
- Amazon Bedrock Data Automation 分析文档，提取带有关联置信度分数的关键字段，并把处理后的输出存放到另一个 S3 桶中。该输出包含提取到的信息以及相应的置信度水平。
- Step Functions 工作流调用 `bda-classifier` Lambda 函数，该函数从 Amazon S3 取回 Amazon Bedrock Data Automation 的输出。这个函数会针对已提取的字段，把置信度分数与预定义的阈值进行比较评估。
- 对于置信度分数低于阈值的字段，工作流会把文档转送到 SageMaker AI 进行人工审核。审核者通过自定义 UI 查看任务并校验页面上的字段。审核者可以更正自动化流程提取错误的字段。
- 人工审核后经校验和更正的表格数据存放在一个 S3 桶中。
- Sagemaker AI 的输出写入 Amazon S3 后，会执行 `bda-a2i-aggregator` AWS Lambda，用经人工审核的新值更新 Amazon Bedrock Data Automation 输出的 payload。这份聚合后的输出存放在 Amazon S3 中，从而提供可供下游系统使用的、最终的高置信度输出。

## 前提条件

要部署这个方案，你需要在部署机器上安装 [AWS Cloud Development Kit](https://aws.amazon.com/cdk/)（AWS CDK）、Node.js 和 Docker。构建脚本会完成方案的打包与部署。

## 部署方案

按以下步骤部署该方案：

- 把方案仓库克隆到你的部署机器上。
- 进入项目目录并运行构建脚本：

`./build.sh`

部署会在你的 AWS 账户中创建以下资源：

- 两个新的 S3 桶：一个用于文档的初始上传，一个用于文档的输出
- 一个 Amazon Bedrock Data Automation 项目，以及五个用于处理测试文档的 blueprint
- 一个 [Amazon Cognito](https://aws.amazon.com/cognito/) 用户池，供 [Amazon SageMaker Ground Truth](https://aws.amazon.com/sagemaker/groundtruth/) 为 SageMaker AI 提供私有劳动力（private workforce），用于处理置信度分数低于阈值的数据
- 两个 Lambda 函数和一个用于处理测试文档的 Step Function 工作流
- 两个用于 Lambda 函数处理测试文档的 [Amazon Elastic Container Registry](https://aws.amazon.com/ecr/)（Amazon ECR）容器镜像

## 向私有劳动力中添加一名工作人员

构建完成后，你必须在 SageMaker Ground Truth 中向私有劳动力添加一名工作人员。请按以下步骤操作：

- 在 SageMaker AI 控制台的导航窗格中，展开 **Ground Truth**，选择 **Labeling workforces**，然后选择 **Private** 选项卡。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/25/ML-18583-labeling-workforce.jpeg)

- 在 **Workers** 区域中，选择 **Invite new workers**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/25/ML-18583-Invite-workers.jpeg)

- 在 **Email addresses** 中，输入你要邀请的工作人员的电子邮件地址。本示例中，请使用你能够访问的邮箱。
- 选择 **Invite new workers**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/24/ML-18583-add-new-workers.jpg)

工作人员添加完成后，会收到一封包含临时密码的电子邮件。收到该邮件可能需要最长 5 分钟。

- 在 **Labeling workforces** 页面上的 **Private workforce summary** 区域中，选择 **Labeling portal sign-in URL** 对应的链接。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/25/ML-18583-labelling-portal-1.jpeg)

- 在弹出的提示中，输入你之前用于设置工作人员的电子邮件地址，并填入邮件中的临时密码，然后选择 **Sign In**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/24/ML-18583-sagemaker-private-workforce.jpg)

- 按提示设置新密码。

你将被重定向到私有标注劳动力的作业队列页面。页面顶部会提示你目前还不是任一工作团队的成员。你必须在下一步完成该流程，以确保作业被正确分配。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/24/ML-18583-Sagemaker-AI-jobs.jpg)

- 在 **Labeling workforces** 页面上，打开私有团队（本文中为 `bda-workforce`）。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/25/ML-18583-Sagemaker-AI-private-team-1.jpeg)

- 在 **Workers** 选项卡上，选择 **Add workers to team**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/25/ML-18583-Sagemaker-AI-add-new-workers.jpeg)

- 把刚刚通过验证的工作人员添加到该团队。

## 测试方案

要测试该方案，请把项目 `assets` 文件夹中的测试文档上传到用于接收文档的 S3 桶。你可以在 Step Functions 控制台监控系统进度，也可以通过 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 查看日志。文档处理完成后，你可以在 SageMaker AI 中看到一个新的作业已为该用户排队。要查看这个作业，请返回 **Labeling workforces** 页面并选择 **Labeling portal sign-in URL** 对应的链接。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/25/ML-18583-Sagemaker-AI-labeling-portal-sign-in-1.jpeg)

使用之前记录的电子邮件地址和更新后的密码登录。你会看到一个显示待审核作业的页面。选中该作业并选择 **Start working**。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/25/ML-18583-Sagemaker-AI-available-jobs.jpeg)

在 UI 中，你可以针对已处理的文档，逐条审核置信度分数低于阈值（默认 70%）的条目。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/24/ML-18583-Sagemaker-AI-input-document.jpg)

在这个页面上，你可以把数据修改为更正后的值。更新后的数据会保存在 S3 输出桶中的 `a2i-output/bda-review-flow-definition/<date>/review-loop-<date time stamp>/output.json` 文件里。随后可以处理这些数据，用它们为从文档中取回的信息提供更正后的值。
