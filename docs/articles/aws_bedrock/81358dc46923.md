# 使用 Amazon Nova Sonic 构建语音驱动的 AWS 助手

随着云基础设施变得日益复杂，对直观且高效的管理界面的需求从未如此迫切。传统的命令行界面（CLI）和 Web 控制台虽然功能强大，却可能成为快速决策与运维效率的障碍。如果你能直接对 AWS 基础设施说话，并立即得到智能的回应，会怎样？

在本篇博文中，我们探讨如何用 [Amazon Nova Sonic](https://docs.aws.amazon.com/nova/latest/userguide/speech.html) 处理语音、用 [Strands Agents](https://strandsagents.com/latest/documentation/docs/) 进行多 agent 编排，构建一个精密的语音驱动 AWS 运维助手。该方案展示了自然语言语音交互如何改变云上运维，让 AWS 服务更易使用、运维更高效。

我们演示的多 agent 架构超越了基础的 AWS 运维，可支持多种用例，包括客户服务自动化、物联网（IoT）设备管理、财务数据分析和企业工作流编排。这一基础模式可以适配任何需要智能任务路由与自然语言交互的领域。

## 核心组件

多 agent 架构由若干专门化组件组成，它们协同工作，处理语音命令并执行 AWS 操作：

- **Supervisor Agent**：充当中央协调者，分析传入的语音查询，并根据上下文与意图将其路由到相应的专门化 agent。
- **Specialized Agents**：**EC2 Agent**：处理实例管理、状态监控与计算操作 **SSM Agent**：管理 Systems Manager 操作、命令执行与补丁管理 **Backup Agent**：监管 [AWS Backup](https://aws.amazon.com/backup/) 的配置、作业监控与恢复操作
- **Voice Integration Layer**：使用 [Amazon Nova Sonic](https://docs.aws.amazon.com/nova/latest/userguide/speech.html) 进行双向语音处理，把语音转换为文本以便处理，再把文本转换回语音用于回应。

## 方案概览

Strands Agents Nova Voice Assistant 通过对话式人工智能（AI）展示了 AWS 基础设施管理的一种新范式。用户无需在复杂的 Web 控制台中层层导航，也无需记住 CLI 命令，只需说出自己的意图即可获得即时回应。该方案弥合了自然的人类沟通与 AWS 技术操作之间的差距，让技术人员与非技术人员都能轻松管理云资源。

## 技术栈

该方案采用现代化的云原生技术，提供稳健且可扩展的语音界面：

- **后端**：Python 3.12+，使用 [Strands Agents](https://strandsagents.com/latest/documentation/docs/) 框架进行 agent 编排
- **前端**：React，配合 [AWS Cloudscape Design System](https://cloudscape.design/) 提供一致的 AWS UI/UX
- **AI 模型**：[Amazon Bedrock](https://aws.amazon.com/bedrock) 与 Claude 3 Haiku，用于自然语言理解与生成
- **语音处理**：[Amazon Nova Sonic](https://docs.aws.amazon.com/nova/latest/userguide/speech.html) 用于高质量语音合成与识别
- **通信**：WebSocket 服务器，用于实时双向通信

## 主要特性与能力

我们的语音驱动助手提供多项高级特性，让 AWS 运维更加直观高效。系统能够理解自然语音查询，并将其转换为相应的 AWS API 调用。例如：

- “列出我在 us-east-1 中所有运行中的 EC2 实例”
- “在我的 Dev 实例上使用 SSM 安装 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/) agent”
- “检查昨晚备份作业的状态”

这些回应专门针对语音播报做了优化：摘要精炼，限制在 800 个字符以内；信息以清晰的结构化方式呈现；措辞为对话式，读出来自然流畅（避免技术术语，并使用适合语音合成的完整句子）。

## 实现概览

上手使用语音驱动的 AWS 助手包括三个主要步骤：

### 环境搭建

- 配置可访问 Bedrock、Nova Sonic 以及目标 AWS 服务的 AWS 凭证
- 搭建 Python 3.12+ 后端环境与 React 前端
- 确保具备适用于多 agent 操作的 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam/) 权限

### 启动应用

- 启动用于语音处理的 Python WebSocket 服务器
- 使用 AWS Cloudscape 组件启动 React 前端
- 配置语音设置与 WebSocket 连接

### 开始语音交互

- 授予浏览器麦克风权限以进行语音输入
- 用“列出我的 EC2 实例”或“检查备份状态”之类的示例命令进行测试
- 通过 [Amazon Nova Sonic](https://docs.aws.amazon.com/nova/latest/userguide/speech.html) 体验实时语音回应

准备好构建你自己的助手了吗？完整的部署说明、代码示例与故障排查指南都可在 [GitHub 仓库](https://github.com/aws-samples/sample-aws-strands-nova-voice-assistant) 中获取。

## AWS Strands Agents 设置

该实现采用带专门化 agent 的多 agent 编排器模式：

```
from strands import Agent
from config.conversation_config import ConversationConfig
from config.config import create_bedrock_model

class SupervisorAgent(Agent):
    def __init__(self, specialized_agents, config=None):
        bedrock_model = create_bedrock_model(config)
        conversation_manager = ConversationConfig.create_conversation_manager("supervisor")
        
        super().__init__(
            model=bedrock_model,
            system_prompt=self._get_routing_instructions(),
            tools=[],  # No tools for pure router
            conversation_manager=conversation_manager,
        )
        self.specialized_agents = specialized_agents
```

## 生产环境考量

尽管该方案以面向开发的部署方式展示了 Strands Agents 的能力，规划生产落地的组织应考虑使用 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) [Runtime](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/agents-tools-runtime.html) 来实现企业级托管与管理。[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 在生产部署中的优势：

- 无服务器运行时：专为部署和扩展动态 AI agent 而打造，无需管理基础设施
- 会话隔离：为每个用户会话提供专属 microVM 的完整会话隔离，这对执行特权操作的 agent 至关重要
- 自动扩缩：可在数秒内扩展到数千个 agent 会话，按使用量计费
- 企业级安全：内置安全控制，并与身份提供商（[Amazon Cognito](https://aws.amazon.com/cognito/)、Microsoft Entra ID、Okta）无缝集成
- 可观测性：通过 CloudWatch 集成提供内置的分布式追踪、指标与调试能力
- 会话持久性：高度可靠，为长时间运行的 agent 交互提供会话持久化

对于准备走出开发与测试阶段的组织，[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) Runtime 提供了以企业规模部署语音驱动 AWS 助手所需的生产就绪基础。
