# 用 Amazon Quick 打通结构化与非结构化数据

组织以多种形式收集数据。结构化数据存放在数据库和电子表格里，非结构化数据则躺在文档、报告以及分散在各文件系统的文件中。要把两者放在一起分析，通常得在多个工具之间来回切换、分别运行查询，再手工关联结果。

[Amazon Quick](https://docs.aws.amazon.com/quick/latest/userguide/welcome.html) 用一套统一的体验来应对这一点。你可以通过[富化过的数据集](https://docs.aws.amazon.com/quick/latest/userguide/working-with-datasets.html)接入结构化数据，通过[由 S3 支撑的知识库](https://docs.aws.amazon.com/quick/latest/userguide/s3-integration.html)接入非结构化数据，随后用同一个对话式 AI agent 查询这两类数据。

在这篇文章中，你将学会如何：

- 把 Amazon Simple Storage Service（Amazon S3）接成数据源，并创建一个知识库。
- 搭建一个把结构化与非结构化数据合在一起的 Space。
- 创建并配置一个能跨这两类数据查询的自定义 chat agent。
- 在一次对话里提出横跨结构化与非结构化来源的问题。

## 方案架构

下面的架构图说明各个组件如何连接，通过 Amazon Quick 交付统一的数据体验。

![https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026-10-27/ML-22035-1.png](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-1.png)

图 1：在 Amazon Quick 中合并结构化与非结构化数据的方案架构

架构分为三层：

- **数据层：** 你的数据以两种形态存在。非结构化内容（文档、PDF、报告）存放在 Amazon S3，并通过知识库建立索引。结构化数据（指标、销售数字和运营关键绩效指标）以富化数据集的形式加载，附带语义描述，agent 用这些描述把问题翻译成 SQL。
- **工作空间层：** 一个 Space 把两类数据汇聚进同一个工作空间。这个 Space 引用你的知识库来应答非结构化查询、引用你的数据集来应答结构化查询，也可以包含 dashboard、文件上传和 action 连接器。来自不同来源的数据正是在这一层汇聚成统一的上下文。
- **agent 层：** 自定义 chat agent 关联到这个 Space，并把该 Space 作为自己的知识来源。用户提出问题时，agent 自行判断是查知识库、查数据集，还是两者都查，然后返回一份合并起来、带引用的回答。Amazon Quick 还会把内置的 [AI guardrails](https://docs.aws.amazon.com/quick/latest/userguide/guardrails.html)（例如内容安全筛查）应用到聊天交互上。

采用这种分层做法，你可以随时间扩展这套方案。当你往 Space 里新增一个数据源，关联到该 Space 的 agent 就能用上它，而回答会遵循提问用户本人的权限。

## 前提条件

要跟着完成这次演练，你需要：

- 一个 Amazon Quick 账户，并且跟随本演练的用户要有 Enterprise 订阅（创建数据集需要 Enterprise）。细节见 [Amazon Quick 定价](https://aws.amazon.com/quick/pricing/)。
- 一个存放业务文档的 Amazon S3 bucket。创建方法见 [Amazon S3 User Guide](https://docs.aws.amazon.com/AmazonS3/latest/userguide/create-bucket-overview.html)。
- 由 Amazon Quick 管理员授予的 [Amazon Quick 对你 S3 bucket 的访问权限](https://docs.aws.amazon.com/quick/latest/userguide/s3-admin-setup.html#s3-grant-bucket-access)。在管理员控制台中，管理员依次选择 Permissions、AWS resources，勾选 Amazon S3，再选择 Select S3 buckets。被选中的 bucket 默认只有只读权限。
- 在 Amazon Quick 中创建集成、知识库、数据集、Space 和 chat agent 的权限。

## 步骤 1：创建一个 Amazon S3 集成

先把 Amazon Quick 连到你的 S3 bucket。在 Amazon Quick 控制台的左侧导航面板中选择 **Knowledge**。

knowledge 页面会列出可用的连接器类型，包括 Amazon Q Business、Web Crawler、Amazon S3，以及 Google Drive、OneDrive、Microsoft SharePoint 这类第三方选项。

在 Amazon S3 下选择 **Add**。在 Create S3 knowledge base 对话框的 Connect S3 bucket 页面，填写以下内容：

- **Name：** 给你的集成起一个有描述性的名字（例如 “My Data Access Integration”）。
- **S3 bucket location：** 如果要用与 Amazon Quick 同一 AWS 账户里的 bucket，选择 **Quick Suite instance account**；如果要用另一个账户里的 bucket，选择 **Other AWS account**。
- **S3 bucket URL：** 存放你数据的那个 bucket 的 S3 URI。该 bucket 必须与 Amazon Quick 处于同一个 Region。

选择 **Next**。

## 步骤 2：创建一个知识库

S3 集成创建完成后，Amazon Quick 会提示你创建一个知识库。知识库会为 AI 搜索对 S3 内容建立索引。

配置知识库：

- **Name：** “Business Knowledge Base”。
- **Description（可选）：** 说明这个知识库将怎么使用。
- **Content：** 选择 “Add all content” 为所连 S3 bucket 里的全部内容建立索引，或选择 “Add specific content” 来指定要纳入的文件夹与文件的 S3 前缀（前缀筛选区分大小写）。

**Next：** Additional settings 会打开文档级访问控制列表（ACL）以及元数据文件夹这几项可选设置。请在创建知识库之前决定是否使用 ACL，因为这个选择之后无法更改。本次演练用的是示例数据，默认设置就够用。细节见 [Set up and manage Amazon S3 integration](https://docs.aws.amazon.com/quick/latest/userguide/s3-setup-manage.html)。

选择 **Create**。一条成功横幅确认 S3 集成已就绪，知识库随即在后台开始建立索引。

## 步骤 3：创建并富化一个数据集

[数据集](https://docs.aws.amazon.com/quick/latest/userguide/working-with-datasets.html)就是被加载进 Amazon Quick 的结构化数据文件。用语义描述、自定义指令和正确的数据类型把它富化之后，AI agent 能更准确地解读你的数据，进而把自然语言问题翻译成 SQL 查询。

### 创建数据集

- 从 Amazon Quick 首页进入左侧导航中的 **Data**。
- 选择 **Create dataset**，再选 **Upload file**。
- 选中你先前下载的 **Product_Sales.csv** 文件，然后选择 **Open**。
- 在确认页面核对列名与数据类型，选择 **Next** 创建数据集。

Amazon Quick 会把该文件摄取进 SPICE（内存计算引擎），数据集随后出现在你的数据集列表中。

数据集的名称取自上传的文件，所以它在你的账户里显示为 Product_Sales.csv。

### 富化数据集

用语义信息富化数据集，能帮助 AI 在业务语境下理解你的数据。agent 会利用这份上下文把自然语言问题翻译成更准确的 SQL 查询。在数据集页面选择 **Edit dataset**，进入数据准备视图。

### Transform：修正数据类型

在 **Transform** 标签页中，更新那些自动识别出错的列的数据类型。就这个数据集而言：

- 把 **Order Date** 和 **Date Key** 从 String 改为 Date。
- 把 **Customer ID** 从 String 改为 Integer。
- 把 **Sales**、**Discount** 和 **Profit** 从 String 改为 Decimal。
- 把 **Quantity** 和 **Unit Price** 从 String 改为 Integer。

![https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026-10-27/ML-22035-4.png](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-4.png)

图 4：Transform 视图，展示对 Product_Sales.csv 数据集所做的数据类型修改

### Output：补充语义上下文

选择 **Output** 标签页即可访问数据集级的富化字段。在这里你提供的上下文，能帮助 AI 明白你的数据代表什么、该如何使用。

**Description：** 写一段数据集级的描述：

“Product sales transaction data for AnyCompany, covering orders from FY2024-FY2025 across North America, EMEA, Asia Pacific, and Latin America. Includes order details, customer information, product lines, and revenue metrics.”

**Custom instructions：** 就 AI 应当如何查询这些数据给出指引：

**USAGE GUIDELINES:**

- Revenue values are in USD.
- When comparing performance, group by Region (North America, EMEA, Asia Pacific, Latin America).
- Order Date should be used for time-based trend analysis. The fiscal year matches the calendar year.
- Date Key is a numeric YYYYMMDD representation of Order Date.
- Sales = Quantity x Unit Price x (1 – Discount)

**COMMON USE CASES:**

- Regional sales performance comparison.
- Product line revenue analysis.
- Quarterly trend identification.
- Customer segmentation by industry and segment.

**TAGS：** Sales, revenue, orders, regional performance, product analytics

**Column descriptions：** 在左侧面板中逐个选中列并添加描述。例如：

- Order ID: “Unique identifier for each sales transaction (format: `REGION-YYYY-NNNNNN`)”
- Region: “Geographic sales region: North America, EMEA, Asia Pacific, or Latin America”
- Product: “AnyCompany product name: Analytics Pro, Connect, Automate, AI Assistant, Data Catalog, or Integration Hub”
- Sales: “Order revenue in USD after discount”
- Segment: “Customer size segment: Enterprise, Mid-Market, or SMB”

图 5：Output 视图，展示配置了 Description 与 Custom instructions 的数据集详情

选择 **Save & publish** 保存改动。此后数据集概览会以正确的数据类型列出各列，并带上你添加的描述。

![https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026-10-27/ML-22035-6.png](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-6.png)

这个富化后的数据集为你的方案提供了结构化数据层。当 agent 收到一个关于销售数据的自然语言问题时，它会用这些描述和指令生成更准确的 SQL 查询。再加上步骤 2 的那个知识库，你现在已经有结构化与非结构化两类数据，可以把它们放进一个 Space 了。

## 步骤 4：创建一个 Space

Amazon Quick 里的 [Space](https://docs.aws.amazon.com/quick/latest/userguide/working-with-spaces.html) 充当统一的数据工作空间。一个 Space 可以容纳文件上传、dashboard、知识库、actions 和数据集，给你的 chat agent 提供一个能跨数据类型查询的位置。

在左侧导航选择 **Spaces**，新建一个 Space，命名为 “Business Intelligence Hub”。

把知识库和数据集加进这个 Space：

- 选择 **Add knowledge**，再在列表中选中 **Knowledge bases**，然后从列表里挑 “Business Knowledge Base”。
- 再次选择 **Add knowledge**，在列表中选中 **Datasets**，然后从列表里挑 “Product_Sales.csv”。

现在这个 Space 会把你的知识库（非结构化文档）和你富化后的数据集（结构化销售数据）都作为数据源关联起来。两类数据就在这个中枢汇合，你的 chat agent 由此获得一个能跨全部内容查询的位置。图 7 展示了这两项资源都处于 Ready 状态的这个 Space。

![https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026-10-27/ML-22035-7.png](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-7.png)

进入左侧导航的 **Chat agents**，选择 **Create chat agent**。Amazon Quick 会给出一个 prompt 构建器，你可以用自然语言描述你的 agent，也可以从 Training Guide、Project Coordinator、Onboarding Helper 这类模板中挑选。

本次演练选择 **Skip**，改为手动配置 agent。

### 配置 agent 人格

配置面板分成几个部分。先从 Agent Persona 开始：

- **Agent identity：** “Business Intelligence Assistant”
- **Description：** “An AI assistant that breaks down information silos by analyzing business data from your knowledge base”

在 Agent Persona instructions 中输入：

```
You are a Business Intelligence Assistant designed to help organizations break down information silos. Your primary functions are:

1. Analyze business data stored in S3
2. Retrieve relevant findings from the reports and memos in the knowledge base
3. Provide comprehensive insights that connect internal data with external trends
4. Generate clear, actionable recommendations based on data analysis

When answering questions, always cite your sources and explain how you arrived at your conclusions. Focus on delivering practical business value and highlighting patterns across different information sources.
```

页面会出现一条提示，确认你的 chat agent 已配备企业级 guardrails。

### 设定沟通风格

在 Communication style 下选一个回答风格预设，可选项包括 Executive、Technical 和 Creative。就商业智能这个用例而言，选择 **Executive**。

### 关联知识来源

在 **Knowledge Sources** 下选择 **Link spaces**，选中你先前创建的 “Business Intelligence Hub” Space。这样 agent 就能访问你的 S3 知识库以及那个 Space 里的其他数据源。关联一个 Space 之后，agent 只会基于大语言模型（LLM）的知识和被关联的资源来回答。

你也可以直接把参考文档（PDF、TXT、HTML、MD、CSV、DOC、DOCX）挂到 agent 上作为额外上下文。对你上传的参考文档，Amazon Quick 最多抽取 100,000 个字符的文本。

## 最佳实践

当你从这次演练转向自己的数据时，可以参考下面这些做法：

- **组织好你的 S3 数据：** 使用清晰的文件夹结构和文件命名约定。结构清晰之后，把知识库的范围限定到特定 S3 前缀也更容易。
- **写出具体的 persona 指令：** 指令越具体，agent 的回答越一致。要写清该如何标注来源、如何处理含义模糊的查询。
- **用 Space 控制范围：** 与其让 agent 能访问所有东西，不如建立若干聚焦的 Space，只放与该 agent 用途相关的数据源。
- **从建议 prompt 入手：** 建议 prompt 能帮助用户理解 agent 能做什么。挑选那些能展示 agent 在结构化与非结构化数据两方面能力范围的 prompt。
- **分享之前先测试：** 在分享给团队之前，用预览面板以有代表性的问题测一遍你的 agent。

## 安全考量

按照 [AWS 共享责任模型](https://aws.amazon.com/compliance/shared-responsibility-model/)，配置你的数据、知识库和 agent 的访问权限属于你的责任。在你把这套方案改造到自己的场景时，请考虑以下几点：

- **只授予最小权限的 S3 访问：** 只把知识库确实需要的 bucket 授权给 Amazon Quick。管理员选中的 bucket 默认只有只读权限。如果你通过 API 创建知识库，可以为单个 S3 数据源指定一个自定义的 AWS Identity and Access Management（IAM）角色，而不必授予账户级的 S3 访问权限。
- **控制文档访问：** 如果文档需要按用户或按组授权，请在创建知识库时启用文档级 ACL。这个选择之后无法更改。
- **加密的 bucket：** 如果你的 bucket 使用 AWS Key Management Service（AWS KMS）密钥，请按照[管理员设置指南](https://docs.aws.amazon.com/quick/latest/userguide/s3-admin-setup.html)中的 AWS KMS 步骤操作。
- **只加入可信内容：** agent 会用你知识库中的文档来组织回答，因此只纳入来自你信任来源的内容。
- **有选择地分享：** chat agent 和知识库默认是私有的。只把它们分享给确实需要的用户和组。
- **把 guardrails 当作其中一层：** Amazon Quick 内置内容安全筛查，管理员还可以添加最多 50 个被屏蔽的词或短语。这些控制有助于降低风险，但不能替代你在访问与权限配置上的责任。细节见 [Amazon Quick 中的 AI guardrails](https://docs.aws.amazon.com/quick/latest/userguide/guardrails.html)。
