# 使用 Amazon Quick 将结构化和非结构化数据整合在一起

组织以多种形式收集数据。结构化数据存在于数据库和电子表格中，而非结构化数据则存在于跨文件系统存储的文档、报告和文件中。一起分析两者通常需要在多个工具之间切换、运行单独的查询以及手动关联结果。

[Amazon Quick](https://docs.aws.amazon.com/quick/latest/userguide/welcome.html) 通过统一的体验解决了这个问题。您可以通过[丰富的数据集](https://docs.aws.amazon.com/quick/latest/userguide/working-with-datasets.html)连接结构化数据，并通过[S3支持的知识库](https://docs.aws.amazon.com/quick/latest/userguide/s3-integration.html)连接非结构化数据。然后，您可以通过单个对话式 AI 代理来查询两者。

在这篇文章中，您将学习如何：

- 连接 Amazon Simple Storage Service (Amazon S3) 作为数据源并创建知识库。
- 构建一个结合结构化和非结构化数据的空间。
- 创建和配置跨两种数据类型进行查询的自定义聊天代理。
- 在一次对话中提出跨越结构化和非结构化来源的问题。

## 解决方案架构

下图说明了每个组件如何连接以通过 Amazon Quick 提供统一的数据体验。

![显示将结构化数据集和 Amazon S3 知识库连接到 Amazon Quick 中的聊天代理的数据、工作区和代理层的架构图](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-1.png)

图 1：在 Amazon Quick 中组合结构化和非结构化数据的解决方案架构

该架构分为三层：

- **数据层：** 您的数据以两种形式存在。非结构化内容（文档、PDF、报告）存储在 Amazon S3 中并通过知识库建立索引。结构化数据（指标、销售数字和运营关键绩效指标）作为丰富的数据集加载，其中包含代理用于将问题转换为 SQL 的语义描述。
- **工作空间层：** 空间将两种数据类型组合到一个工作空间中。该空间引用您的非结构化查询知识库和结构化查询数据集。它还可以包括仪表板、文件上传和操作连接器。在这一层，来自不同来源的数据汇聚到统一的上下文中。
- **代理层：** 自定义聊天代理链接到空间并将其用作其知识源。当用户提出问题时，代理确定是否查询知识库、数据集或两者，并返回带有引用的组合响应。 Amazon Quick 还将内置的 [AI 护栏](https://docs.aws.amazon.com/quick/latest/userguide/guardrails.html)（例如内容安全筛选）应用于聊天交互。

通过这种分层方法，您可以随着时间的推移扩展解决方案。当您向空间添加新数据源时，链接到该空间的代理可以使用它，并且响应会尊重发出请求的用户的权限。

## 先决条件

要完成本演练，您需要：

- 为遵循本演练的用户提供具有 Enterprise 订阅的 Amazon Quick 账户（创建数据集需要 Enterprise）。有关详细信息，请参阅[亚马逊快速定价](https://aws.amazon.com/quick/pricing/)。
- 用于存放您的业务文档的 Amazon S3 存储桶。要创建一个，请参阅 [Amazon S3 用户指南](https://docs.aws.amazon.com/AmazonS3/latest/userguide/create-bucket-overview.html)。
- [Amazon Quick 访问您的 S3 存储桶](https://docs.aws.amazon.com/quick/latest/userguide/s3-admin-setup.html#s3-grant-bucket-access)，由 Amazon Quick 管理员授予。在管理控制台中，管理员选择权限，然后选择 AWS 资源，选择 Amazon S3，然后选择选择 S3 存储桶。所选存储桶默认具有只读权限。
- 在 Amazon Quick 中创建集成、知识库、数据集、空间和聊天代理的权限。

## 步骤 1：创建 Amazon S3 集成

首先将 Amazon Quick 连接到您的 S3 存储桶。在 Amazon Quick 控制台中，选择左侧导航面板中的 **知识**。

知识页面显示可用的连接器类型，包括 Amazon Q Business、Web Crawler、Amazon S3 以及 Google Drive、OneDrive 和 Microsoft SharePoint 等第三方选项。

在 Amazon S3 下，选择 **添加**。在创建 S3 知识库对话框的连接 S3 存储桶页面上，提供以下详细信息：

- **名称：** 集成的描述性名称（例如“我的数据访问集成”）。
- **S3 存储桶位置：** 选择 **Quick Suite 实例账户** 以使用与 Amazon Quick 相同的 AWS 账户中的存储桶，或选择 **其他 AWS 账户** 以使用不同账户中的存储桶。
- **S3 存储桶 URL：** 包含您的数据的存储桶的 S3 URI。该存储桶必须与 Amazon Quick 位于同一区域。

选择**下一步**。

![创建 S3 知识库对话框，显示连接 S3 存储桶字段的名称、存储桶位置和存储桶 URL](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-2.png)

图 2：创建集成对话框，显示 S3 连接字段

## 步骤 2：创建知识库

创建 S3 集成后，Amazon Quick 会提示您创建知识库。知识库对您的 S3 内容进行索引，以进行 AI 驱动的搜索。

配置知识库：

- **名称：**“商业知识库”。
- **描述（可选）：** 有关如何使用知识库的注释。
- **内容：** 选择“添加所有内容”以索引连接的 S3 存储桶中的所有内容，或选择“添加特定内容”以指定要包含的文件夹和文件的 S3 前缀（前缀过滤器区分大小写）。

**下一步：** 其他设置可打开文档级访问控制列表 (ACL) 和元数据文件夹的可选设置。在创建知识库之前决定是否使用 ACL，因为以后无法更改该选择。本演练使用示例数据，因此默认设置就足够了。有关详细信息，请参阅[设置和管理 Amazon S3 集成](https://docs.aws.amazon.com/quick/latest/userguide/s3-setup-manage.html)。

选择**创建**。成功横幅确认 S3 集成，知识库开始在后台建立索引。

![使用业务知识库名称和内容选择选项创建知识库对话框](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-3.png)

## 步骤 3：创建并丰富数据集

[数据集](https://docs.aws.amazon.com/quick/latest/userguide/working-with-datasets.html) 是加载到 Amazon Quick 中的结构化数据文件。通过使用语义描述、自定义指令和正确的数据类型丰富数据集，AI 代理可以更准确地解释您的数据。然后它可以将自然语言问题转换为 SQL 查询。

### 创建数据集

- 从 Amazon Quick 主页，导航至左侧导航栏中的 **数据**。
- 选择**创建数据集**，然后选择**上传文件**。
- 选择您之前下载的 **Product_Sales.csv** 文件，然后选择 **打开**。
- 在确认屏幕上，检查列名称和数据类型。选择 **下一步** 创建数据集。

Amazon Quick 将文件提取到 SPICE（内存计算引擎）中，数据集将显示在您的数据集列表中。

该数据集的名称取自上传的文件，因此它在您的帐户中显示为 Product_Sales.csv。

### 丰富数据集

使用语义信息丰富数据集有助于人工智能理解业务环境中的数据。代理使用此上下文将自然语言问题转换为更准确的 SQL 查询。在数据集页面中，选择“**编辑数据集**”进入数据准备视图。

### 转换：修复数据类型

在 **转换** 选项卡中，更新自动检测到错误的列的数据类型。对于这个数据集：

- 将**订单日期**和**日期键**从字符串更改为日期。
- 将**客户 ID** 从字符串更改为整数。
- 将**销售额**、**折扣**和**利润**从字符串更改为小数。
- 将**数量**和**单价**从字符串更改为整数。

![显示应用于 Product_Sales.csv 数据集中的列的数据类型更改的转换选项卡](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-4.png)

### 输出：添加语义上下文

选择 **输出** 选项卡以访问数据集级别的丰富字段。在这里，您提供上下文，帮助人工智能理解您的数据代表什么以及如何使用它。

**描述：** 添加数据集级别的描述：

“AnyCompany 的产品销售交易数据，涵盖 2024 财年至 2025 财年北美、欧洲、中东和非洲、亚太地区和拉丁美洲的订单。包括订单详细信息、客户信息、产品线和收入指标。”

**自定义说明：** 添加有关 AI 应如何查询此数据的指导：

**使用指南：**

- 收入值以美元为单位。
- 比较性能时，按区域（北美、欧洲、中东和非洲、亚太地区、拉丁美洲）分组。
- 订单日期应用于基于时间的趋势分析。财政年度与日历年一致。
- 日期键是订单日期的数字 YYYYMMDD 表示形式。
- 销售额 = 数量 x 单价 x (1 – 折扣)

**常见用例：**

- 区域销售业绩比较。
- 产品线收入分析。
- 季度趋势识别。
- 按行业和细分市场进行客户细分。

**标签：** 销售、收入、订单、区域绩效、产品分析

**列说明：** 选择左侧面板中的每一列并添加说明。例如：

- 订单 ID：“每笔销售交易的唯一标识符（格式：`REGION-YYYY-NNNNNN`）”
- 区域：“销售地理区域：北美、欧洲、中东和非洲、亚太地区或拉丁美洲”
- 产品：“AnyCompany 产品名称：Analytics Pro、Connect、Automate、AI Assistant、Data Catalog 或 Integration Hub”
- 销售：“折扣后美元订单收入”
- 细分：“客户规模细分：企业、中端市场或中小企业”

## 步骤 4：创建空间

Amazon Quick 中的 [Spaces](https://docs.aws.amazon.com/quick/latest/userguide/working-with-spaces.html) 充当统一数据工作区。空间可以保存文件上传、仪表板、知识库、操作和数据集，为您的聊天代理提供一个跨数据类型查询的位置。

从左侧导航中，选择 **Spaces** 并创建一个新空间。将其命名为“商业智能中心”。

将您的知识库和数据集添加到空间：

- 选择 **添加知识** 并从列表中选择 **知识库**。从列表中选择“业务知识库”。
- 再次选择“**添加知识**”，然后从列表中选择“**数据集**”。从列表中选择“Product_Sales.csv”。

该空间现在显示作为数据源链接的知识库（非结构化文档）和丰富的数据集（结构化销售数据）。这是两种数据类型汇集在一起​​的中心枢纽，为您的聊天代理提供了一个可以查询所有内容的地方。图 7 显示了两个资源均处于就绪状态的空间。

![商业智能中心空间显示 Product_Sales.csv 数据集和业务知识库链接为就绪状态下的数据源](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/10/27/ML-22035-7.png)

配置面板有几个部分。从代理角色开始：

You are a Business Intelligence Assistant designed to help organizations break down information silos. Your primary functions are:

2. Retrieve relevant findings from the reports and memos in the knowledge base
3. Provide comprehensive insights that connect internal data with external trends
4. Generate clear, actionable recommendations based on data analysis

When answering questions, always cite your sources and explain how you arrived at your conclusions. Focus on delivering practical business value and highlighting patterns across different information sources.

## 最佳实践

当您从本演练转到您自己的数据时，请使用以下实践：

- **组织您的 S3 数据：** 使用清晰的文件夹结构和文件命名约定。清晰的结构还可以更直接地将知识库范围限定到特定的 S3 前缀。
- **写下具体的人物指令：** 您的指令越具体，客服人员的反应就越一致。包括有关如何引用来源和处理模棱两可的查询的指导。
- **使用空间来控制范围：** 不要让代理访问所有内容，而是创建仅包含与该代理目的相关的数据源的集中空间。
- **从建议提示开始：** 建议提示可帮助用户了解代理可以执行的操作。选择能够展示代理在结构化和非结构化数据方面的范围的提示。
- **共享前测试：** 在与您的团队共享之前，使用预览面板通过代表性问题测试您的代理。

## 安全考虑

在 [AWS 责任共担模型](https://aws.amazon.com/compliance/shared-responsibility-model/) 下，您负责配置对您的数据、知识库和代理的访问权限。调整此解决方案时请考虑以下事项：

- **授予最低权限的 S3 访问权限：** 仅向 Amazon Quick 授予对您的知识库需要的存储桶的访问权限。管理员选择的存储桶默认具有只读权限。如果您通过 API 创建知识库，则可以为单个 S3 数据源提供自定义 AWS Identity and Access Management (IAM) 角色，而不是授予账户范围的 S3 访问权限。
- **控制文档访问：** 如果文档需要按用户或按组访问，请在创建知识库时启用文档级 ACL。您以后无法更改此选择。
- **加密存储桶：** 如果您的存储桶使用 AWS Key Management Service (AWS KMS) 密钥，请按照 [管理员设置指南](https://docs.aws.amazon.com/quick/latest/userguide/s3-admin-setup.html) 中的 AWS KMS 步骤操作。
- **仅添加受信任的内容：** 代理使用您的知识库中的文档来形成响应，因此仅包含来自您信任的来源的内容。
- **选择性共享：** 聊天代理和知识库默认是私有的。仅与需要它们的用户和组共享它们。
- **使用护栏作为一层：** Amazon Quick 包含内置内容安全筛选，管理员最多可以添加 50 个阻止的单词或短语。这些控制有助于降低风险，但不能取代您配置访问和权限的责任。有关详细信息，请参阅 [Amazon Quick 中的 AI 护栏](https://docs.aws.amazon.com/quick/latest/userguide/guardrails.html)。
