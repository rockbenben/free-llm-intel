# 构建多界面 AI 助手：使用 Amazon Q 与 Slack，并由 Amazon CloudFront 提供来自 Amazon S3 存储桶的可点击引用

客户反馈一致表明，当用户能在日常使用的生产力工具内与 AI 助手交互、无需切换应用和上下文时，AI 助手最有用。[Amazon Q Business](https://aws.amazon.com/q/business/) 和 [Slack](https://slack.com/) 这类 Web 应用已成为现代 AI 助手部署的关键环境。本文探讨多样化界面如何增强用户交互、改善可访问性，并照顾不同偏好。

通过跨环境提供无缝体验，组织可以提升用户满意度和采用率。该助手采用[检索增强生成（RAG）](https://aws.amazon.com/what-is/retrieval-augmented-generation/)，这一技术在这些界面的回复中整合可信、权威的来源，增强可信度与教育价值。这种多界面、由 RAG 驱动的方式不仅力求满足现代用户的灵活性需求，也培育出更有见识、更投入的用户群体，最终最大化助手的效能与触达。通过把 RAG 与多种界面结合，无论用户偏好哪种环境和生产力工具，助手都能提供一致、准确且贴合上下文的信息。

## 解决方案组件

本节我们讨论该解决方案的两个关键组件：数据源和向量数据库。

### 数据源

我们使用上传到 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）存储桶中的 [Spack 文档](https://github.com/spack/spack/tree/develop/lib/spack/docs) RST（ReStructured Text）文件。每当助手将其作为来源返回时，链接会指向 Spack 文档中的具体位置，而不是[来源页面的顶部](https://spack.readthedocs.io/en/latest/containers.html)。例如，[Docker Hub 上的 Spack 镜像](https://spack.readthedocs.io/en/latest/containers.html#spack-images-on-docker-hub)。

[Spack](https://spack.io/) 是一款适用于超级计算机、Linux 和 macOS 的多功能包管理器，它通过允许同一台机器上共存多个版本、配置、环境和编译器，彻底改变了科学软件的安装方式。Spack 由 Todd Gamblin 于 2013 年在[劳伦斯利弗莫尔国家实验室](https://www.llnl.gov/)（LLNL）开发，解决了传统包管理器在高性能计算（HPC）环境中的局限。LLNL 任务科学云转型项目负责人 Brian Weston 为该助手的开发提供了咨询。

此外，我们还使用通过 [Amazon CloudFront](https://aws.amazon.com/cloudfront/) 链接访问的、上传到 S3 存储桶的文本文件。还有一个由 [AWS Lambda](https://aws.amazon.com/pm/lambda/?gclid=EAIaIQobChMIzZTBtdXViQMV6mBHAR1hhgAzEAAYASAAEgLWN_D_BwE&trk=73f686c8-9606-40ad-852f-7b2bcafa68fe&sc_channel=ps&ef_id=EAIaIQobChMIzZTBtdXViQMV6mBHAR1hhgAzEAAYASAAEgLWN_D_BwE:G:s&s_kwcid=AL!4422!3!651212652666!e!!g!!lambda!909122559!45462427876) 函数驱动的自动化摄取作业，把 Slack 会话数据写入该 S3 存储桶。这使助手还能利用用户此前的会话来回答问题并引用来源。我们选择使用 CloudFront 链接而不是 Slack 链接，是因为当该来源在 Amazon Q 中被引用时，用户可能无权访问 Slack 数据。还有一种替代方法，即使用 [Amazon Kendra](https://aws.amazon.com/kendra/) 的 [Slack 连接器](https://docs.aws.amazon.com/kendra/latest/dg/data-source-slack.html)。

只要文本能被提取并写入向量数据库（需要一些代码改动），该解决方案还可以支持 PDF、Word 文档等其他数据类型。它们的原始文件可以由 CloudFront 分发提供。

### 向量数据库

该解决方案使用 Amazon Kendra 作为[向量数据库](https://aws.amazon.com/what-is/vector-databases/)，在简单性和成本效益方面具有显著优势。作为一项全托管的 AWS 服务，Amazon Kendra 同时降低了开发和维护成本。支持两类检索器（原生检索器和 Amazon Kendra）的 Amazon Q 被无缝集成到这一架构中。通过使用 Amazon Kendra，该方案让 Amazon Q 和 Slack 两个界面高效地使用同一个检索器。这种方式不仅简化了整体架构，也在两个环境中提供更一致的用户体验。最终形成一个连贯、高性价比的系统，无论用户选择哪个界面，信息检索与呈现都保持统一。

Amazon Kendra 还支持为每个源文件使用[元数据](https://docs.aws.amazon.com/kendra/latest/dg/s3-metadata.html)，这使两个 UI 都能为其来源提供链接，无论是 Spack 文档网站还是 CloudFront 链接。此外，Amazon Kendra 支持[相关性调优](https://docs.aws.amazon.com/kendra/latest/dg/tuning.html)，可以为特定数据源加权。在本方案中，我们提高了 Spack 文档结果的权重。

## 结论

使用 RAG 实现多界面 AI 助手，代表着 AI 驱动的组织沟通的一次飞跃。通过把 Amazon Q Business 和 Slack 界面与由 Amazon Kendra 驱动的健壮后端集成，该解决方案提供无缝、不依赖具体环境的准确且贴合上下文的信息访问。该架构的优势在于跨环境的一致性、自动化的数据摄取流程以及全面的监控能力。这种方式不仅提升了用户参与度和生产力，也让组织能够在日益以 AI 为中心的格局中快速适应不断变化的沟通需求，标志着迈向更高效、更智能的信息管理系统的重要一步。
