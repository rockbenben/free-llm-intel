# 使用 Amazon Bedrock Knowledge Bases 为结构化数据构建对话式界面

组织在数据库和数据仓库中管理着大量结构化数据。大语言模型（LLM）已经改变了自然语言处理（NLP），但把对话式查询转化为结构化数据分析仍然复杂。数据分析师必须把业务问题转换为 SQL 查询，这造成了工作流瓶颈。

[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 支持直接与结构化数据源进行自然语言交互。该系统会解释数据库 schema 与上下文，在维持数据可靠性标准的同时把自然语言问题转换为准确的查询。借助 Amazon Bedrock Knowledge Bases 结构化数据检索的能力，你只需几个步骤，就能从 [AWS Glue Data Catalog](https://docs.aws.amazon.com/prescriptive-guidance/latest/serverless-etl-aws-glue/aws-glue-data-catalog.html) 表和 [Amazon Redshift](https://aws.amazon.com/redshift) 集群设置结构化数据摄取，与你的结构化数据对话。

本文提供配置结构化数据检索解决方案的说明，并附带实用的代码示例与模板。文中涵盖实现示例与额外注意事项，让你能够快速构建并扩展对话式数据接口。借助清晰的示例与经过验证的方法论，组织可以转变其数据访问能力并加速决策流程。

## 解决方案概述

该解决方案演示如何使用 Amazon Bedrock Knowledge Bases 结构化数据检索构建对话式应用。开发者在把结构化数据集成到生成式 AI 应用时常常面临挑战。这包括难以训练 LLM 基于复杂的数据库 schema 把自然语言查询转换为 SQL 查询，以及确保适当的数据治理与安全控制到位。Amazon Bedrock Knowledge Bases 通过提供托管的自然语言到 SQL（NL2SQL）模块来缓解这些复杂性。Amazon Bedrock Knowledge Bases 提供端到端的托管工作流，让你可以构建自定义生成式 AI 应用，这些应用能够访问并纳入来自各种结构化与非结构化数据源的上下文信息。借助先进的 NLP，Amazon Bedrock Knowledge Bases 可以把自然语言查询转换为 SQL 查询，因此你可以直接从源中检索数据，而无需移动或预处理数据。

该解决方案包含 Amazon Bedrock Knowledge Bases、[Amazon Redshift](https://aws.amazon.com/redshift/)、[AWS Glue](https://aws.amazon.com/glue) 和 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）。解决方案架构由两部分组成：数据摄取管道，以及使用 Amazon Bedrock Knowledge Bases 的结构化数据检索应用。

Amazon Bedrock Knowledge Bases 结构化数据检索支持把 Amazon Redshift 作为查询引擎，并支持多种数据摄取选项。数据摄取管道是一次性设置，并支持多种摄取选项。本文讨论一个使用 Amazon S3、AWS Glue 和 Amazon Redshift 的常见数据摄取用例。

你可以配置 Amazon Bedrock Knowledge Bases 结构化数据检索，从 AWS Glue 数据库和 S3 数据集检索数据。此设置使用 [Amazon Redshift 中 Data Catalog 的自动挂载](https://aws.amazon.com/blogs/big-data/simplify-external-object-access-in-amazon-redshift-using-automatic-mounting-of-the-aws-glue-data-catalog/)。通过这种摄取选项，你可以把现有的 S3 数据集和 Data Catalog 表无缝集成到你的检索增强生成（RAG）应用中，并采用通过 Lake Formation 配置的访问权限。下图展示了该管道。

数据摄取配置完成、知识库数据源同步任务结束之后，用户即可提出自然语言问题，Amazon Bedrock Knowledge Bases 会生成 SQL，对查询引擎执行该 SQL，再交由 LLM 处理，从而给出对用户友好的回答。下图展示了结构化数据检索工作流的示例架构。

[![Amazon Bedrock Knowledge Bases 结构化数据检索的对话流程](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/06/ML-18134-SRAG-KB-Sync-Process.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/06/06/ML-18134-SRAG-KB-Sync-Process.png)

数据检索工作流包含以下步骤：

- 在 RAG 应用中，用户可以通过聊天界面提出自然语言的数据分析问题，例如“2025 年 2 月的销售收入是多少？”
- 该自然语言查询被发送到 Amazon Bedrock Knowledge Bases 进行数据检索与处理。
- Amazon Bedrock Knowledge Bases 根据知识库创建时配置的底层数据 schema 生成 SQL 查询。
- 该 SQL 查询在查询引擎（Amazon Redshift）上执行，从结构化数据存储（AWS Glue 表）中检索数据。查询可以包含多个 join 和聚合。
- 生成的 SQL 响应连同额外上下文一起被发送到 LLM，以生成自然语言形式的回答。
- 回答被返回给用户。用户可以基于检索到的回答追问，例如“这一期间带来最高收入的产品是什么？”

Amazon Bedrock Knowledge Bases 结构化数据检索支持三种不同的 API，以满足你的数据检索需求：

- **检索与响应生成** – 检索与响应生成 API 与我们前面讨论的解决方案工作流类似，它会生成 SQL 查询、通过查询引擎检索数据，再交由 LLM 处理以生成自然语言回答
- **仅检索** – 仅检索 API 会生成 SQL 查询、通过查询引擎检索数据，并直接返回数据，不经过 LLM 处理
- **生成 SQL 查询** – 生成 SQL 查询 API 会返回由 Amazon Bedrock Knowledge Bases 生成的原始 SQL 查询，可用于审查以及由应用进一步处理

## 先决条件

要实现本文提供的解决方案，你必须拥有一个 [AWS 账户](https://signin.aws.amazon.com/signup?request_type=builderId)。此外，必须在 Amazon Bedrock 中启用对所需基础模型的访问权限。

## 设置数据摄取管道

为设置数据摄取管道，我们把示例数据集加载到 S3 存储桶中，并配置 AWS Glue 作为数据存储、Redshift Serverless 工作组作为查询引擎。请在数据摄取 notebook 中完成以下步骤：

- 数据摄取方面，下载以下[示例电商数据集](https://www.kaggle.com/datasets/steve1215rogg/e-commerce-dataset)，将其转换为 pandas data frame，并使用 [Amazon SageMaker Data Wrangler](https://aws.amazon.com/sagemaker-ai/data-wrangler/) 上传到 S3 存储桶。
- 使用 [AWS Glue crawler](https://docs.aws.amazon.com/glue/latest/dg/add-crawler.html) 爬取存放该数据集的源 S3 存储桶，从而创建 AWS Glue 数据库和表。你可以修改这一步，改为爬取你自己的 S3 存储桶，或把现有的 Data Catalog 表用作存储元数据。
- 使用数据摄取 notebook 在[默认 VPC](https://docs.aws.amazon.com/vpc/latest/userguide/default-vpc.html) 中创建 Redshift Serverless 命名空间和工作组。如果你计划使用自己的 Redshift Serverless 工作组或 Amazon Redshift 预置集群，可以跳过这一步。

## 设置结构化数据检索解决方案

本节我们详细说明设置解决方案中结构化数据检索组件的步骤。

Amazon Bedrock Knowledge Bases 支持多种数据访问模式，包括 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）、[AWS Secrets Manager](https://aws.amazon.com/secrets-manager/) 和数据库用户。本文演示采用 IAM 访问的设置方式。你可以把 IAM 访问与作为摄取工作流一部分配置的 Redshift Serverless 工作组配合使用，也可以配合现有的 Redshift Serverless 或预置集群，来完成这些步骤。

请在结构化数据检索 notebook 中完成以下步骤：

- 创建一个执行角色，并为其配置从 Amazon Redshift、AWS Glue 和 S3 存储桶访问数据所需的策略。
- 调用 [CreateKnowledgeBase API](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent_CreateKnowledgeBase.html)，使用该执行角色和知识库配置创建知识库。在知识库配置中，AWS Glue 数据库和表被用作存储元数据，Amazon Redshift 作为查询引擎。
- 创建知识库之后，你必须[完成额外步骤](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-prereq-structured.html)，以确保 IAM 执行角色具备在 Amazon Redshift 中执行查询并从 AWS Glue 检索数据所需的权限。该 notebook 包含必要说明，用于为执行角色创建并授予数据库访问权限，以及授予 [AWS Lake Formation](https://aws.amazon.com/lake-formation/) 权限。
- 摄取任务会把 AWS Glue 数据库和表的数据存储 schema 元数据同步到 NL2SQL 模块。这些 schema 元数据将在结构化数据检索期间生成 SQL 查询时使用。
- 知识库同步任务完成后，你可以使用三种数据检索 API——检索并生成响应、仅检索、生成 SQL 查询——来查询并验证该结构化数据检索解决方案。

更多细节请参阅[通过连接结构化数据存储创建知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-structured-create.html)。

## 结论

Amazon Bedrock Knowledge Bases 通过把自然语言问题转换为 SQL 查询来简化数据分析，无需专业的数据库技能。该服务与 Amazon Redshift、AWS Glue 和 Amazon S3 集成，让业务分析师、数据科学家和运营团队可以使用对话式问题直接查询数据。它通过内置的治理控制与访问权限维持数据安全。客户可以部署这一托管服务，让用户用自然语言问题分析数据，同时保持数据完整性与安全标准。

要了解更多信息，请参阅[通过连接结构化数据存储构建知识库](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-build-structured.html)和 [Amazon Bedrock Knowledge Bases 现已支持结构化数据检索](https://aws.amazon.com/about-aws/whats-new/2024/12/amazon-bedrock-knowledge-bases-structured-data-retrieval/)。
