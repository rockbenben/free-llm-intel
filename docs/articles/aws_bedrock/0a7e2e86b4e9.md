# 借助 Amazon Bedrock Agents 发挥 MCP servers 的强大能力

*2025 年 6 月：本文已更新。*

AI agents 通过与外部系统交互、执行复杂工作流并在各项操作之间保持上下文感知，扩展了 large language models（LLMs）的能力。[Amazon Bedrock Agents](https://aws.amazon.com/bedrock/agents/) 通过将 foundation models（FMs）与数据源、应用程序和用户输入编排起来，经由 API 集成和 knowledge base 增强来完成面向目标的任务，从而实现这一功能。然而，过去将这些 agents 连接到各类企业系统会造成开发瓶颈——每一次集成都需要定制代码和持续维护，这种标准化难题拖慢了在整个组织数字生态系统中交付情境化 AI 助手的进度。你可以通过使用 [Model Context Protocol (MCP)](https://modelcontextprotocol.io/introduction) 来解决这个问题，它为 LLMs 连接数据源和工具提供了一种标准化的方式。

如今，MCP 正在为 agents 提供对不断扩展的可用工具列表的标准访问能力，你可以用这些工具完成各种任务。随着时间推移，MCP 可以通过市场促进 agents 和工具的可发现性，使 agents 能够共享上下文并拥有共同的工作空间以更好地交互，并在整个行业内扩展 agent 互操作性。

在本文中，我们将展示如何构建一个使用 MCP 访问数据源的 Amazon Bedrock agent，以快速构建生成式 AI 应用程序。借助 Amazon Bedrock Agents，你的 agent 可以像本例中那样，用基于 MCP 的工具即时组装而成：

```
InlineAgent(
    foundation_model="us.anthropic.claude-3-5-sonnet-20241022-v2:0",
    instruction="You are a friendly assistant for resolving user queries",
    agent_name="SampleAgent",
    action_groups=[
        ActionGroup(
            name="SampleActionGroup",
            mcp_clients=[mcp_client_1, mcp_client_2],
        )
    ],
).invoke(input_text=”Convert 11am from NYC time to London time”)
```

我们展示了一个构建 agent 的示例，该 agent 通过 MCP 连接到 [AWS Cost Explorer](https://aws.amazon.com/aws-cost-management/aws-cost-explorer/)、[Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 和 Perplexity AI，以帮助你了解自己的 [Amazon Web Service (AWS)](https://aws.amazon.com/) 支出。你可以使用本文引用的代码，将你的 agents 连接到其他 [MCP servers](https://github.com/modelcontextprotocol/servers?tab=readme-ov-file#-reference-servers)，以应对你的业务挑战。我们设想这样一个世界：agents 可以访问不断增长的 MCP servers 列表，并用它们完成各种各样的任务。

## Model Context Protocol

MCP 由 Anthropic 开发，是一个开放协议，为将 AI 模型连接到几乎任何数据源或工具提供了标准化方式。借助 client-server 架构，MCP 使开发者能够通过轻量级 MCP servers 暴露自己的数据，同时将 AI 应用程序构建为连接到这些 servers 的 MCP clients。通过这一架构，MCP 使用户能够构建更强大、具备上下文感知能力的 AI agents，无缝访问所需的信息和工具。无论你要连接的是外部系统、内部数据存储还是工具，现在都可以用 MCP 以同一种方式与它们对接。MCP 的 client-server 架构使你的 agent 能够随着 MCP server 的更新获得新能力，而无需对应用程序代码做任何改动。

### MCP 架构

MCP 使用一种[client-server 架构](https://modelcontextprotocol.io/introduction#general-architecture)，其中包含以下组件，如下图所示：

- **Host**：MCP host 是需要通过 MCP 协议访问数据的程序或 AI 工具，例如 Claude Desktop、集成开发环境（IDE）或任何其他 AI 应用程序。
- **Client**：与 servers 保持一对一连接的协议客户端。
- **Server**：通过标准化 MCP 暴露能力的轻量级程序。
- **Local data sources**：你的数据库、本地数据源以及 MCP servers 可以安全访问的服务。
- **Remote services**：通过互联网以 API 形式提供、MCP servers 可以连接的外部系统。

## 在 Amazon Bedrock agents 中使用 MCP

在本文中，我们提供了一份分步指南，介绍如何将你喜爱的 MCP servers 作为 [Action Groups](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-action-create.html) 连接到 Amazon Bedrock agents，使 agent 能够用它来完成用户交代的任务。我们还介绍 Amazon Bedrock [Inline Agent SDK](https://github.com/awslabs/amazon-bedrock-agent-samples/tree/main/src/InlineAgent)，它通过管理复杂的工作流编排，简化了调用 [inline agents](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-create-inline.html) 的过程。该 SDK 还内置了 MCP client 实现，使你可以直接访问 MCP server 提供的工具。如果没有这个 SDK，开发者必须编写并维护用于以下用途的定制代码：

- 解析响应流
- 处理 [return control](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-returncontrol.html) 流程
- 管理 agent 各次交互之间的状态
- 协调 API 调用

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/04/04/sdk.png)

在创建 agent 的过程中，开发者会为每一个需要与 agent 通信的 MCP server 创建对应的 MCP client。当被调用时，agent 会判断用户任务需要哪些工具；如果需要 MCP server 的工具，它就会使用相应的 MCP client 向该 server 请求执行工具。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/04/04/mcp.png)

为了编排这一工作流，你可以利用 Amazon Bedrock Agents 的 [return control](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-returncontrol.html) 能力。下图展示了一个 agent 处理使用两个工具的请求时端到端的流程。在第一个流程中，执行的是基于 Lambda 的 action；在第二个流程中，agent 使用 MCP server。

## 用例：改变你在包括 Amazon Bedrock 在内的各项 AWS 服务中管理 AWS 支出的方式

为了展示 Amazon Bedrock agent 如何使用 MCP servers，让我们来看一个示例用例。试想提出这样的问题：*“帮我理解过去几周我在 Bedrock 上的支出”* 或 *“上个月我在各个区域和实例类型上的 EC2 成本是多少？”*，然后得到一份人类可读的数据分析，而不是仪表盘上的原始数字。系统会解读你的意图，并精准地交付你需要的内容——无论是详细的明细、趋势分析、可视化图表，还是节省成本的建议。这很有用，因为你关心的是洞察，而不是数据。你可以使用两个 MCP servers 来实现这一点：一个自建的 MCP server 用于检索 AWS 支出数据，另一个是开源的[来自 Perplexity AI 的 MCP server](https://docs.perplexity.ai/guides/mcp-server)，用于解读数据。你把这两个 MCP servers 作为 action groups 添加到一个 *inline* Amazon Bedrock agent 中。这样你就得到了一个能够改变你管理 AWS 支出方式的 AI agent。本文的全部代码都可以在 [GitHub](https://github.com/awslabs/amazon-bedrock-agent-samples/tree/main/src/InlineAgent) 仓库中找到。

让我们逐步了解如何使用 [inline agents](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-create-inline.html) 创建这个 agent。你可以使用 inline agents 在运行时动态定义和配置 Amazon Bedrock agents。它们为 agent 能力提供了更大的灵活性和控制力，使用户能够按需指定 FMs、指令、action groups、guardrails 和 knowledge bases，而无需依赖预先配置的控制平面设置。值得注意的是，你也可以不使用 inline agents，而是通过在 [InvokeAgent](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_agent-runtime_InvokeAgent.html) API 中使用 `RETURN_CONTROL` 来编排这一行为。

## Amazon Bedrock Agents 中的 MCP 组件

- **Host**：这就是 Amazon Bedrock inline agent。该 agent 将 MCP clients 添加为 action groups，当用户提出与 AWS 支出相关的问题时，可以通过 [RETURN_CONTROL](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-returncontrol.html) 调用这些 action groups。
- **Client**：你创建两个 client，各自与对应的 server 建立一对一连接：一个 cost explorer client 带有特定的 cost server 参数，一个 Perplexity AI client 带有 Perplexity server 参数。
- **Servers**：你创建两个 MCP servers，每个都在你的机器上本地运行，并通过[标准输入/输出](https://modelcontextprotocol.io/docs/concepts/transports#standard-input%2Foutput-stdio)与你的应用程序通信（或者，你也可以将 client 配置为与远程 MCP servers 对话）。  Cost Explorer 和 [Amazon CloudWatch Logs](https://docs.aws.amazon.com/AmazonCloudWatch/latest/logs/WhatIsCloudWatchLogs.html)（用于 Amazon Bedrock 模型调用日志数据）以及一个用于检索 AWS 支出数据的 MCP server。Perplexity AI MCP server 用于解读 AWS 支出数据。
- **Data sources**：MCP servers 与远程数据源通信，例如 Cost Explorer API、CloudWatch Logs 和 Perplexity AI search API。

要开始实施本文中的解决方案，你需要满足以下前置条件：

## 实现细节

既然你已经了解了 agent 产生的输出，让我们揭开帷幕，看看产生这些输出的一些关键代码片段。

- **创建 MCP clients**：[config.py](https://github.com/awslabs/amazon-bedrock-agent-samples/blob/main/src/InlineAgent/examples/mcp/cost_explorer_agent/config.py) 定义了与你的两个 MCP servers 通信的两个 MCP clients。其中定义了 cost explorer 和 Perplexity clients 的 server 参数。该解决方案使用 `StdioServerParameters`，它配置 client 应如何通过标准输入/输出（stdio）流进行通信。其中包含 server 通过 API 访问所需数据所需的参数。  `# Cost server parameters cost_server_params = StdioServerParameters( command="docker", args=[ "run", "-i", "--rm", "-e", "AWS_PROFILE", "-e", "AWS_REGION", "-e", "BEDROCK_LOG_GROUP_NAME", "-v", f"{str(Path.home())}:/root/.aws/", "-e", "stdio", "aws-cost-explorer-mcp:latest", ], env={ "AWS_PROFILE": config.AWS_PROFILE, "AWS_REGION": config.AWS_REGION, "BEDROCK_LOG_GROUP_NAME": config.BEDROCK_LOG_GROUP_NAME, }, ) # Perplexity server parameters perplexity_server_params = StdioServerParameters( command="docker", args=["run", "-i", "--rm", "-e", "PERPLEXITY_API_KEY", "mcp/perplexity-ask"], env={"PERPLEXITY_API_KEY": config.PERPLEXITY_API_KEY}, )`  在 `main.py` 中，MCP server 参数被导入并用于创建你的两个 MCP clients。  `cost_explorer_mcp_client = await MCPStdio.create(server_params=cost_server_params) perplexity_mcp_client = await MCPStdio.create(server_params=perplexity_server_params)`

- **配置 agent action group**：`main.py` 创建了 action group，将 MCP clients 组合成 agent 可以访问的单一接口。这使 agent 能够通过 return of control 按需请求你的应用程序调用其中任一 MCP server。  `# Create action group with both MCP clients cost_action_group = ActionGroup( name="CostActionGroup", mcp_clients=[cost_explorer_mcp_client, perplexity_mcp_client] )`
- **创建 inline agent**：inline agent 可以按以下规格创建：  **Foundation model:** 选择你想要的 FM 来驱动 agent。它可以是 Amazon Bedrock 提供的任何模型。本例使用 Anthropic 的 Claude 3.5 Sonnet 模型。**Agent instruction：**向你的 agent 提供指令，其中包含用于编排对用户查询的响应的指导和步骤。这些指令确立了 agent 处理各类查询的方式。**Agent name**：你的 agent 的名称。**Action groups:** 定义 agent 可以访问的 action groups。它们可以包含单个或多个 action group，每个 group 可以访问多个 MCP clients 或 [AWS Lambda](https://aws.amazon.com/lambda)。作为可选项，你可以将 agent 配置为使用 [Code Interpreter](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-code-interpretation.html) 为应用程序生成、运行和测试代码。

```
# Create and invoke the inline agent
await InlineAgent(
    foundation_model="us.anthropic.claude-3-5-sonnet-20241022-v2:0",
    instruction="""You are a friendly assistant that is responsible for resolving user queries.
    
    You have access to search, cost tool and code interpreter. 
    
    """,
    agent_name="cost_agent",
    action_groups=[
        cost_action_group,
        {
            "name": "CodeInterpreter",
            "builtin_tools": {
                "parentActionGroupSignature": "AMAZON.CodeInterpreter"
            },
        },
    ],
).invoke(
    input_text="<user-query-here>"
)
```

你可以用这个示例在 Amazon Bedrock 上构建一个 inline agent，它与不同的 MCP servers 建立连接，并将它们的 clients 归组为单一的 action group 供 agent 访问。

## 结论

Anthropic MCP 协议为将 FMs 连接到数据源提供了一种标准化方式，现在你可以在 Amazon Bedrock Agents 中使用这一能力。在本文中，你看到了一个结合 Amazon Bedrock 与 MCP 强大能力的示例，构建出一个为理解和管理 AWS 支出提供全新视角的应用程序。

组织现在可以为其团队提供对复杂财务数据的自然对话式访问，同时利用来自 Perplexity 等来源的情境化智能增强响应。随着 AI 持续演进，将模型安全连接到组织关键系统的能力将变得越来越有价值。无论你是想改变客户服务、精简运营，还是获得更深入的业务洞察，Amazon Bedrock 与 MCP 的集成都为你的下一次 AI 创新提供了灵活的基础。你可以通过浏览我们的[代码示例](https://github.com/awslabs/amazon-bedrock-agent-samples/tree/main/src/InlineAgent/examples/mcp)深入了解这一 MCP 集成。

**![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/03/11/eashank.png)Eashan Kaushik **是 Amazon Web Services 的 AI/ML 专业解决方案架构师。他热衷于打造前沿的生成式 AI 解决方案，同时在工作中坚持以客户为中心的方式。在担任现职之前，他获得了纽约大学坦登工程学院的计算机科学硕士学位。工作之余，他喜欢运动、举重和跑马拉松。

**![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/06/03/madhur.jpg)Madhur Prashant ** 是 Amazon Web Services 的 AI 与 ML 解决方案架构师。他对人类思维与生成式 AI 的交汇点充满热情。他的兴趣在于生成式 AI，具体来说是构建有用、无害，且对客户而言最优的解决方案。工作之余，他喜欢做瑜伽、徒步、陪伴他的双胞胎，以及弹吉他。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/11/20/ML-16951-Amit.jpg)**Amit Arora** 是 Amazon Web Services 的 AI 与 ML 专业架构师，帮助企业客户使用基于云的机器学习服务快速扩展其创新成果。他还是华盛顿特区乔治城大学数据科学与分析硕士项目的兼职讲师。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/04/01/plmera.jpeg)**Andy Palmer** 是 AWS 战略客户的技术总监。他的团队在多个专业领域提供专业解决方案架构技能，包括 AIML、生成式 AI、数据与分析、安全、网络和开源软件。Andy 及其团队始终走在最前沿，指导我们最先进的客户走完他们的生成式 AI 之旅，并帮助寻找将这类新工具应用于现有问题领域以及全新创新与产品体验的方法。
