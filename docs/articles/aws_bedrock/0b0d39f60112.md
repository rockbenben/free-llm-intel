# 在中东地区（阿联酋与巴林）推出面向 Anthropic Claude 模型的 Amazon Bedrock 全球跨区域推理

*本文由 Anthropic 的 Gareth Jones 合著。*

我们很高兴宣布，面向在中东运营的客户，现已通过 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 的[全球跨区域推理](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)提供 Anthropic 的 [Claude Opus 4.6](https://www.anthropic.com/news/claude-opus-4-6)、[Claude Sonnet 4.6](https://www.anthropic.com/news/claude-sonnet-4-6)、[Claude Opus 4.5](https://www.anthropic.com/news/claude-opus-4-5)、[Claude Sonnet 4.5](https://www.anthropic.com/news/claude-sonnet-4-5) 和 [Claude Haiku 4.5](https://www.anthropic.com/news/claude-haiku-4-5)。此次上线支持中东地区的组织在 Amazon Bedrock 上访问 Anthropic 最新的 Claude 模型，同时受益于跨越 AWS 网络的全球高可用推理路由。借助全球跨区域推理，你可以无缝扩展推理工作负载、提升弹性并降低运维复杂度。

为帮助你实现 AI 应用的规模化，Amazon Bedrock 提供了跨区域推理配置文件（cross-Region inference profiles），这是组织可以用来将推理处理无缝分布到多个 AWS 区域的一项强大功能。这一能力帮助你在大规模构建时获得更高的吞吐量，并使你的生成式 AI 应用即使在高负载下也能保持响应迅速和可靠。当你在 Amazon Bedrock 中调用跨区域推理配置文件时，你的请求会遵循一条智能路由路径。请求从你发起 API 调用的源区域出发，并自动路由到该推理配置文件中定义的目标区域之一。跨区域推理通过安全的 AWS 网络运行，对传输中的数据进行端到端加密。

关键区别在于，跨区域推理不会改变数据的存储位置——使用跨区域推理时，客户数据不会存储在目标区域；客户管理的日志（例如模型调用日志）、knowledge bases 和存储的配置都完全保留在源区域内。推理请求经由 Amazon Bedrock 管理的 AWS Global Network 传输，响应以加密形式返回到你在源区域的应用程序。

在本文中，我们讨论如何在 Amazon Bedrock 中针对中东地区使用 Anthropic Claude 模型的全球跨区域推理。我们将带你了解每个 Anthropic Claude 模型变体的能力、全球跨区域推理的关键优势（包括提升的弹性）、你可以落地的真实用例，以及一个帮助你立即开始构建生成式 AI 应用程序的代码示例。

## 全球跨区域推理的优势

随着生成式 AI 的加速普及，客户越来越需要能够可靠地扩展推理工作负载，同时保持一致的性能。部署大规模生成式 AI 应用程序往往涉及管理区域容量限制、流量峰值和可用性要求。Amazon Bedrock 全球跨区域推理通过让推理请求自动路由到预定义全局推理配置文件中的最优区域来应对这些挑战，带来多项优势：

- **在需求高峰期间提升吞吐量**——对于中东地区的组织，全球跨区域推理在区域高峰时段（例如斋月、大型购物活动或高流量营业时段）提供关键的弹性保障。系统会自动将请求路由到全球基础设施中有可用容量的区域，确保你的应用程序即使在意外的流量激增期间也能保持性能。这种动态路由无缝发生，流量路由完全由 Amazon Bedrock 管理。对于服务 GCC 及更广泛 MENAT 区域客户的关键业务应用程序，这意味着可以避免代价高昂的停机或性能下降，以免影响收入和客户信任。
- **安全的数据传输**——跨区域操作期间传输的数据由 Amazon Bedrock 管理。数据在区域之间传输时经过加密，有助于满足中东地区组织所重视的严格安全与数据保护要求。
- **简化的多区域策略**——组织不再需要手动设计复杂的多区域部署。全球跨区域推理有助于提供企业级的弹性，而无需承担管理多个区域 endpoint 的运维开销。
- **支持快速数字化转型**——随着中东地区组织加快其契合国家愿景（如 Saudi Vision 2030 和 UAE's AI Strategy）的数字化转型举措，全球跨区域推理提供了支持雄心勃勃的 AI 项目所需的可扩展性，且不受容量限制。
- **简化的监控**——[Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 和 [AWS CloudTrail](https://aws.amazon.com/cloudtrail) 继续在你的中东源区域记录日志条目，提供应用程序性能的集中视图。这种简化的可观测性意味着你的团队可以使用熟悉的 AWS 工具来监控和管理生成式 AI 应用程序，无论请求在全球何处处理，都让合规和运维管理更加直接。
- **按需配额灵活性**——全球跨区域推理有助于消除单个区域容量限制带来的约束。你的工作负载可以动态访问 AWS 全球基础设施中的资源，从而无缝处理高容量应用程序以及该地区快速增长的数字经济中常见的突发流量峰值。

随着这项能力现已在中东地区面向 Anthropic 的 Claude Opus 4.6、Claude Sonnet 4.6、Claude Opus 4.5、Claude Sonnet 4.5 和 Claude Haiku 4.5 提供，整个地区的组织都可以更有信心地构建和扩展生成式 AI 应用程序，因为他们知道自己能够获得企业级的弹性和性能。

## 配额管理

要查看使用全局推理配置文件时跨区域吞吐量的默认配额，请参阅 [Amazon Bedrock service quotas](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-increase.html) 中的 global cross-Region model inference requests per minute 和 global cross-Region model inference tokens per minute 数值。

你可以在源区域通过 [Service Quotas console](https://me-central-1.console.aws.amazon.com/servicequotas/home/services/bedrock/quotas) 或使用 [AWS Command Line Interface](https://aws.amazon.com/cli)（AWS CLI）命令来申请、查看和管理全局跨区域推理配置文件的配额。

## 开始使用

要开始结合全球跨区域推理使用 Anthropic 的 Claude Opus 4.6、Claude Sonnet 4.6、Claude Opus 4.5、Claude Sonnet 4.5 或 Claude Haiku 4.5（例如 `me-central-1` 区域），请完成以下步骤：

- 确认你的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色或用户具备使用跨区域推理配置文件调用 Amazon Bedrock 模型的[必要权限](https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html#global-cris-iam-setup)。
- 使用 Amazon Bedrock API 或 AWS SDK 调用模型：

```
import boto3
import json
bedrock = boto3.client('bedrock-runtime', region_name='me-central-1')
model_id = "global.anthropic.claude-sonnet-4-6"
response = bedrock.converse(
    messages=[{"role": "user", "content": [{"text": "Explain cloud computing in 2 sentences."}]}],
    modelId=model_id,
)

print("Response:", response['output']['message']['content'][0]['text'])
print("Token usage:", response['usage'])
print("Total tokens:", response['usage']['totalTokens'])
```

你可以通过 [CloudWatch](https://docs.aws.amazon.com/bedrock/latest/userguide/monitoring.html) 和 [AWS Cost Explorer](https://aws.amazon.com/aws-cost-management/aws-cost-explorer/) 监控用量、性能和成本，以便随着需求增长扩展应用程序。
