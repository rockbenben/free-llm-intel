# Ring 如何借助 Amazon Bedrock Knowledge Bases 支撑全球客户支持

*本文由 Ring 的 David Kim 与 Premjit Singh 共同撰写。*

在全球范围内扩展自助服务支持，其挑战远不止翻译。本文介绍 [Ring](https://ring.com/)——Amazon 旗下的家庭安防子公司——如何借助 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 构建一个可投产、面向多语言区域（multi-locale）的[检索增强生成（RAG）](https://aws.amazon.com/what-is/retrieval-augmented-generation/)支持聊天机器人。通过去除按 Region 分别部署基础设施，Ring 把扩展到每个新增语言区域的成本降低了 21%，同时在 10 个国际 Region 中保持一致客户体验。

本文将介绍 Ring 如何实现针对 Region 特定内容的[元数据驱动（metadata-driven）](https://aws.amazon.com/blogs/machine-learning/amazon-bedrock-knowledge-bases-now-supports-metadata-filtering-to-improve-retrieval-accuracy/)过滤，如何把内容管理拆分为摄取、评估与发布几类工作流，以及在扩展过程中实现成本节省。本文描述的架构使用 Amazon Bedrock Knowledge Bases、[Amazon Bedrock](https://aws.amazon.com/bedrock/)、[AWS Lambda](https://aws.amazon.com/lambda/)、[AWS Step Functions](https://aws.amazon.com/step-functions/) 与 [Amazon Simple Storage Service（Amazon S3）](https://aws.amazon.com/s3/)。无论你是在向国际扩展支持运营，还是想优化现有的 RAG 架构，该实现都提供了可应用到自家多语言区域支持系统的实用模式。

## Ring 的支持体系演进历程

Ring 的客户支持最初依赖基于 [Amazon Lex](https://aws.amazon.com/lex/) 构建的规则式聊天机器人。虽然可用，但该系统受限于预设对话模式，无法处理多样化的客户咨询。在高峰期，16% 的交互会升级给人工客服，支持工程师则要把 10% 的时间用于维护这套规则系统。随着 Ring 向国际语言区域扩张，这种做法变得难以持续。

### 基于 RAG 的支持系统需求

Ring 面临一个挑战：如何在不给每个 Region 单独搭建基础设施的前提下，为多个国际语言区域提供准确、贴合上下文的支持。团队确定了四项需求，用以指导架构选择。

- **全球内容本地化**

Ring 的国际布局所需的远不止翻译。每个地区都需要 Region 特定的产品信息——从电压规格到法规合规细节——并通过统一系统提供。在英国、德国以及其他八个语言区域，Ring 需要应对每个 Region 各自不同的产品配置与支持场景。

- **无服务器、托管式架构**

Ring 希望工程团队专注于改善客户体验，而不是管理基础设施。团队需要一套全托管、无服务器的方案。

- **可扩展的知识管理**

面对数百份不断更新的产品指南、故障排查文档与支持文章，Ring 需要能从统一存储库中精确检索信息的[向量搜索](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/vector-search.html)技术。系统还必须支持自动化的内容摄取 pipeline，使 Ring 内容团队发布的更新无需人工干预即可在多个语言区域生效。

- **性能与成本优化**

Ring 的端到端平均延迟要求为 7–8 秒，性能分析显示跨 Region 延迟在总响应时间中占不到 10%。这一发现让 Ring 可以采用集中式架构，而不必在每个 Region 部署独立基础设施，从而降低了运维复杂度与成本。

为满足这些需求，Ring 使用带内容语言标签的元数据驱动过滤。该方式从单一集中式系统提供 Region 特定内容。针对无服务器需求，Ring 选择了 Amazon Bedrock Knowledge Bases 与 Lambda，既免去基础设施管理，又能自动扩缩容。

## 方案概览

Ring 将其 RAG 聊天机器人架构设计为把内容管理拆分成两个核心流程：摄取与评估、发布。这种两阶段方式让 Ring 在保持生产系统稳定的同时持续改进内容。

- **每日数据复制与 Knowledge Base 创建**

Ring 使用 AWS Step Functions 编排每日工作流，该工作流会：

- 把内容与元数据从 Knowledge Base Source 桶复制到 Data Source（Version）
- 以每日桶作为数据源建立索引，创建一个新的 Knowledge Base（Version），用于向量嵌入

每个版本各自维护一个独立的 Knowledge Base，使 Ring 具备独立的评估能力与简洁的回滚选项。

- **每日评估流程**

AWS Step Functions 工作流继续使用评估数据集来：

- 在各 Knowledge Base 版本上运行查询
- 测试检索准确率与回复质量，以比较各版本之间的表现
- 把性能指标发布到 Tableau 仪表板，并按 `contentLocale` 组织结果

- **质量校验与 Golden 数据集创建**

Ring 使用 **Anthropic Claude Sonnet 4** 大语言模型（LLM）作为评判者来：

- 评估各 Knowledge Base 版本上的指标，识别表现最佳的版本
- 比较按 `contentLocale` 组织的检索准确率、回复质量与性能指标
- 把表现最好的版本发布到 Data Source（Golden）供生产使用

该架构支持回退到最多 30 天前的版本。由于内容每周约更新 200 次，Ring 决定不保留 30 天以上的版本。

- **客户交互 – **客户通过聊天机器人界面发起支持查询。例如，电池更换场景下的客户查询如下：

```
{
	"text": "How can I replace the doorbell battery?",
	"market": "en-GB"
}
```

- **查询编排与知识检索**

Ring 配置 Lambda 处理客户查询，并从 Amazon Bedrock Knowledge Bases 检索相关内容。该函数会：

- 为 RAG 系统转换传入的查询
- 使用 equals 运算符按 `contentLocale` 标签施加元数据过滤，以精确指向特定区域的内容
- 查询经过校验的 Golden Data Source，以检索上下文相关的内容

下面是 Ring 在 AWS Lambda 中使用的示例代码：

```
## Metadata Filtering for Regional Content Targeting

num_results = 10
market = "en-GB"
knowledge_base_id = "A2BCDEFGHI"
user_text = "How can I replace the doorbell battery?"

# Configure Regional content filtering
vector_search_config = {"numberOfResults": num_results}
vector_search_config["filter"] = {
	"equals": {
		"key": "contentLocale",
		"value": market
	}
}

# Run Amazon Bedrock Knowledge Base search
response = boto3.client("bedrock-agent-runtime").retrieve(
	knowledgeBaseId=knowledge_base_id,
	retrievalQuery={"text": user_text},
	retrievalConfiguration={
		"vectorSearchConfiguration": vector_search_config,
	},
)
```

- **回复生成**

在该 Lambda 函数中，系统会：

- 根据相关性分数对检索到的内容排序，选取分数最高的上下文
- 把排名最高的上下文与原始客户查询组合，构造增强后的 prompt
- 把增强后的 prompt 发送到 Amazon Bedrock 上的 LLM
- 为每个 `contentLocale` 配置对应语言区域的 prompt
- 生成上下文相关的回复，并通过聊天机器人界面返回

## 实现时的其他考量

在你自行大规模构建基于 RAG 的系统时，除核心实现之外，还应考虑以下架构方式与运维要求：

### 向量存储选型

Ring 的实现使用 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/) 作为其 knowledge base 的向量存储。不过，Amazon Bedrock Knowledge Bases 也支持把 [Amazon S3 Vectors](https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-bedrock-kb.html) 作为向量存储选项。在这两者之间选择时，请考虑：

- **Amazon OpenSearch Serverless**：提供高级搜索能力、实时索引与灵活的查询选项。最适合需要复杂搜索模式的应用，或当你在向量搜索之外还需要其他 OpenSearch 功能时。
- **Amazon S3 vectors**：为简单的向量搜索用例提供更具成本效益的选项。S3 向量存储提供自动扩缩容、内置持久性，对访问模式可预测的大规模部署可能更经济。

除这两个选项外，AWS 还支持与[其他数据存储选项](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-setup.html)集成，包括 [Amazon Kendra](https://aws.amazon.com/pm/kendra)、[Amazon Neptune Analytics](https://docs.aws.amazon.com/neptune-analytics/latest/userguide/what-is-neptune-analytics.html) 和 [Amazon Aurora PostgreSQL](https://aws.amazon.com/rds/aurora/)。选择向量存储时，请评估你在查询复杂度、成本优化与运维需求方面的具体要求。[规范性指引](https://docs.aws.amazon.com/prescriptive-guidance/latest/choosing-an-aws-vector-database-for-rag-use-cases/introduction.html)为评估适合自身 RAG 用例的向量存储提供了不错的起点。

### 版本化架构的考量

Ring 为每个版本实施独立的 Knowledge Base，而你也可以考虑另一种做法：在单个 knowledge base 内为每个版本使用独立的数据源。该方法利用 **x-amz-bedrock-kb-data-source-id** 过滤参数，在检索时定位特定数据源：

```
vector_search_config["filter"] = {
	"equals": {
		"key": "x-amz-bedrock-kb-data-source-id",
		"value": '<data source Id>'
		}
	}
# Execute Bedrock Knowledge Base search
response = boto3.client("bedrock-agent-runtime").retrieve(
	knowledgeBaseId=knowledge_base_id,
	retrievalQuery={"text": user_text},
	retrievalConfiguration={
		"vectorSearchConfiguration": vector_search_config,
	},
)
```

在这两种做法之间选择时，请权衡以下具体取舍：

- **每个版本独立的知识库**（Ring 采用的做法）：数据源管理更清晰，回滚能力更干净，但需要管理更多的 knowledge base 实例。
- **单个知识库配多个数据源**：需要维护的 knowledge base 实例更少，但数据源路由逻辑与过滤机制会带来复杂度，并且需要为每个数据源 ID 维护独立的数据存储。

### 灾难恢复：多 Region 部署

设计 RAG 架构时，请考虑你的灾难恢复要求。Amazon Bedrock Knowledge Bases 是 Regional 资源。为实现稳健的灾难恢复，请把完整架构部署到多个 Region：

- **Knowledge Bases**：在多个 Region 创建 Knowledge Base 实例
- **Amazon S3 桶**：为 Golden Data Source 维护跨 Region 副本
- **Lambda 函数与 Step Functions 工作流**：在每个 Region 部署你的编排逻辑
- **数据同步**：实施跨 Region 保持内容同步的流程

该集中式架构从单一 Region 承接其流量，优先考虑成本优化而非多 Region 部署。请评估你自己的恢复时间目标（Recovery Time Objective，RTO）与恢复点目标（Recovery Point Objective，RPO）要求，以判断你的用例是否需要多 Region 部署。

### 基础模型吞吐：跨 Region 推理

Amazon Bedrock 的基础模型是带有 Region 配额的 Regional 资源。为应对流量突发并突破单 Region 配额扩展，Amazon Bedrock 支持[跨 Region 推理（cross-Region inference，CRIS）](https://aws.amazon.com/about-aws/whats-new/2024/08/amazon-bedrock-cross-region-inference/)。CRIS 会自动把推理请求路由到多个 AWS Region，以提升吞吐：

CRIS：只在特定地理边界内路由请求（例如美国境内或欧盟境内），以满足数据驻留要求。这可将 Region 内默认配额提升至多一倍。

[Global CRIS](https://aws.amazon.com/about-aws/whats-new/2025/09/amazon-bedrock-global-cross-region-inference-anthropic-claude-sonnet-4/)：在全球多个商业 Region 之间路由请求，优化可用资源，并提供超出地理性 CRIS 能力的更高模型吞吐。Global CRIS 会自动为每个请求选择最优 Region 进行处理。

CRIS 的运行独立于你的 Knowledge Base 部署策略。即使在单 Region 部署 Knowledge Base 的情况下，你也可以配置 CRIS 在流量突发时扩展基础模型吞吐。请注意，CRIS 只作用于推理层——你的 Knowledge Bases、S3 桶与编排逻辑仍是 Regional 资源，需要单独做多 Region 部署以实现灾难恢复。

### 嵌入模型选择与分块策略

选择合适的嵌入模型与分块策略对 RAG 系统的表现很重要，因为它直接影响检索准确率与回复质量。Ring 使用 **Amazon Titan Embeddings 模型**搭配**默认分块策略**，这套组合对其支持文档效果良好。

Amazon Bedrock 在[多种选项](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)上提供灵活性：

**嵌入模型：**

- **Amazon Titan embeddings**：针对文本内容优化
- **Amazon Nova multimodal embeddings**：支持“Text”“Image”“Audio”“Video”多种模态

**分块策略：**

摄取数据时，Amazon Bedrock 使用四种策略把文档切分为便于高效检索的可管理分块：

- **标准分块**：固定大小的分块，适用于格式统一的文档
- **分层分块**：适用于层级结构清晰的文档
- **语义分块**：依据主题边界切分内容
- **多模态内容分块**：适用于混合内容类型（文本、图片、表格）的文档

请评估你的内容特征，为具体用例选出最优组合。

## 结语

本文介绍了 Ring 如何借助 Amazon Bedrock Knowledge Bases 构建一个可投产、面向多语言区域的 RAG 支持聊天机器人。该架构结合了自动化内容摄取、使用 LLM 作为评判者的系统性每日评估，以及元数据驱动的内容定位，使每新增一个语言区域的基础设施与运营成本降低 21%，同时在 10 个国际 Region 中保持一致客户体验。

在核心 RAG 架构之外，我们还讨论了生产部署的关键设计考量：向量存储选型、版本化策略、用于灾难恢复的多 Region 部署、用于扩展基础模型吞吐的跨 Region 推理，以及嵌入模型选择与分块策略。这些模式广泛适用于任何在 AWS 上构建多语言区域或高可用 RAG 系统的团队。Ring 正继续把其聊天机器人架构演进为 agentic 模式，具备动态 agent 选择与多个专用 agent 的集成。这一 agentic 方式将让 Ring 能把客户咨询路由到负责设备故障排查、订单管理与产品推荐的专用 agent，展示了基于 Amazon Bedrock 构建的 RAG 支持系统的可扩展性。

要进一步了解 Amazon Bedrock Knowledge Bases，请访问 [Amazon Bedrock 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base.html)。
