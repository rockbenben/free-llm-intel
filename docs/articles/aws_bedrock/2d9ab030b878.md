# 对比级联架构：用 Amazon Nova Sonic 构建实时语音助手

语音 AI agent 正在重塑我们与技术交互的方式。从客户服务、医疗辅助到家庭自动化和个人生产力，这些智能虚拟助手在各行各业迅速普及。它们的自然语言能力、全天候可用性以及日益增强的复杂程度，使其成为追求效率的企业和渴望无缝数字体验的个人手中的宝贵工具。

[Amazon Nova Sonic](https://docs.aws.amazon.com/ai/responsible-ai/nova-2-sonic/overview.html) 通过双向流式接口提供实时、类人的语音对话。它能理解不同的说话风格，并生成富有表现力的回应，既适应所说的内容，也适应说话的方式。该模型支持多种语言，提供男声和女声，非常适合客户支持、营销外呼、语音助手和教育类应用。

与 Amazon Nova Sonic 这类把语音理解和生成合并到单个端到端模型的新架构相比，经典的 AI 语音对话系统采用顺序处理的级联架构。这些系统通过一条分立的 pipeline 处理用户语音：级联模型的做法把语音 AI 处理拆解为若干独立组件：

- **语音活动检测（VAD）**：需要前置的 VAD 来检测用户何时停顿或停止说话。
- **语音转文本（STT）**：用户的语音通过自动语音识别（ASR）模型转换为书面文本格式。
- **大语言模型（LLM）处理**：转写出的文本随后送入 LLM 或对话管理器，由它分析输入并基于对话上下文生成相关的文本回复。
- **文本转语音（TTS）**：AI 的文本回复随后由 TTS 模型转换回听起来自然的语音音频，再播放给用户。

## 级联架构的核心挑战

级联架构带来了模块化设计、组件专用和可调试等好处，但累积延迟和交互性下降是它的缺点。

### 级联效应

设想一个语音助手处理简单的天气查询。在级联 pipeline 中，每个处理步骤都会引入延迟和潜在错误。客户的实施案例显示，最初的误解会在 pipeline 中层层放大，往往导致答非所问。这种级联效应让故障排查变得复杂，并对整体用户体验造成负面影响。

### 时间就是一切

真实对话需要自然的节奏。顺序处理会在响应时间上造成可感知的延迟。这些对话流中的中断会给用户带来摩擦感。

### 集成挑战

语音 AI 需要的不仅是语音处理——它需要自然的交互模式。客户反馈指出，编排多个组件使得处理打断、快速往返等动态对话要素变得困难。工程资源往往更多花在 pipeline 管理上。

### 资源现实

级联架构需要为每个组件投入独立的计算资源、监控和维护。这种架构复杂度同时影响开发速度和运营效率。随着对话量增长，扩展难题会加剧，进而影响系统可靠性和成本优化。

### 对语音助手开发的影响

这些洞见驱动了 Nova Sonic 开发中的关键架构决策，回应了一个根本需求：统一的一体化语音到语音处理，无需应对多组件管理的复杂度，就能实现自然、响应迅速的语音体验。

## 两种方案对比

要比较构建语音 AI agent 的语音到语音方案与级联方案，请考虑以下几点：

| **考虑维度** | **语音到语音（Nova Sonic）** | **级联模型** |
| --- | --- | --- |
| **延迟** | **优化的延迟表现与 TTFA** 我们使用首字节音频时间（Time to First Audio，TTFA 1.09）指标评估 Nova Sonic 模型的延迟表现。TTFA 衡量从用户说完查询到收到响应音频第一个字节所经过的时间。参见[技术报告与模型卡](https://assets.amazon.science/86/bb/4316d28940bd9a719abb28f45aaf/amazon-nova-sonic-technical-report-and-model-card-6-12.pdf)。 | **潜在的额外延迟与错误** 级联模型可以在语音识别、语言理解和语音生成上使用多个模型，但受制于额外延迟以及阶段之间的误差传播。通过使用 Pipecat、LiveKit 这类现代异步编排框架，你可以把延迟降到最低。使用流式组件和 TTS 填充语有助于保持自然的对话节奏并减少延迟 |
| **架构与开发复杂度** | **简化的架构** Nova Sonic 把语音转文本、自然语言理解和文本转语音合入一个模型，内置[工具调用](https://docs.aws.amazon.com/nova/latest/userguide/speech-tools.html)和打断（barge-in）检测，提供面向[关键输入](https://docs.aws.amazon.com/nova/latest/userguide/input-events.html)和[输出事件](https://docs.aws.amazon.com/nova/latest/userguide/output-events.html)的事件驱动架构，以及[双向流式 API](https://docs.aws.amazon.com/nova/latest/userguide/speech-bidirection.html)，带来简化的开发者体验。 | **架构上可能的复杂度** 开发者需要为 pipeline 的每个阶段挑选同类最佳的模型，同时还要编排额外组件，例如用于委派 agent 和工具调用的异步 pipeline、TTS 填充语以及（VAD）。 |
| **模型选择与定制** | **对单个组件的控制较少** Amazon Nova Sonic 允许定制[音色](https://docs.aws.amazon.com/nova/latest/userguide/available-voices.html)、内置工具调用，并可与 [Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases) 和 [Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore) 集成。不过，与完全模块化的级联系统相比，它对单个模型组件提供的细粒度控制更少。 | **对每一步可能有细粒度控制** 级联模型通过允许独立调优、替换和优化每个模型组件（如 STT、语言理解和 TTS），对每一步提供更多控制。这包括来自 [Amazon Bedrock Marketplace](https://aws.amazon.com/bedrock/model-marketplace/)、[Amazon SageMaker AI](https://aws.amazon.com/blogs/machine-learning/introducing-bidirectional-streaming-for-real-time-inference-on-amazon-sagemaker-ai/) 的模型以及微调模型。这种模块化带来了模型的选择自由和灵活性，非常契合需要量身定制表现的复杂或专门能力。 |
| **成本结构** | **通过集成方案简化成本结构** Amazon Nova Sonic 按基于 token 的用量模型计费。 | **多组件相关的成本可能复杂** 级联模型由多个组件构成，它们的成本都需要估算。在规模化和高并发场景下，这一点尤为重要。 |
| **语言与口音支持** | Nova Sonic 支持的[语言](https://docs.aws.amazon.com/nova/latest/nova2-userguide/sonic-language-support.html) | 通过专用模型可能获得更广的语言支持，包括在对话中途切换语言的能力 |
| **区域可用性** | Nova Sonic 支持的[区域](https://docs.aws.amazon.com/bedrock/latest/userguide/models-regions.html) | 由于模型选择范围广，并且可以在 [Amazon Elastic Kubernetes Service (Amazon EKS)](https://aws.amazon.com/eks) 或 [Amazon SageMaker](https://aws.amazon.com/sagemaker) 上自托管模型，可能获得更广的区域支持。 |

两种方案也有一些共同特征。

| **电话与传输选项** | 级联方案和语音到语音方案都支持多种[电话](https://aws.amazon.com/blogs/machine-learning/building-ai-powered-voice-applications-amazon-nova-sonic-telephony-integration-guide/)与传输协议，例如 WebRTC 和 WebSocket，可在 Web 和电话网络上实现实时、低延迟的音频流。这些协议促成了无缝的双向音频交换，这对自然的对话体验至关重要，使语音 AI 系统能轻松接入现有通信基础设施，同时保持响应性和音质。 |
| --- | --- |
| **评估、可观测性与测试** | 级联方案和语音到语音方案都可以被系统化地评估、观测和测试，以便进行可靠比较。建议投入建设一套语音 AI 评估与可观测性系统，以对生产环境的准确性和性能建立信心。这样的系统应能追踪从输入到输出的整条 pipeline，端到端捕获指标和对话数据，从而随着时间推移全面评估质量、延迟和对话健壮性。 |
| **开发者框架** | 级联方案和语音到语音方案都得到 Pipecat、LiveKit 等主流开源语音 AI 框架的良好支持。这些框架提供模块化、灵活的 pipeline 和实时处理能力，开发者可以借助它们高效地在不同组件和交互风格之间构建、定制和编排语音 AI 模型。 |

## 何时使用哪种方案

下图给出了一个实用框架，用于指导你的架构决策：

[![决策树](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/26/ml-19206-image-3.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/01/26/ml-19206-image-3.png)

在以下情况使用语音到语音：

- 实现的简洁性很重要
- 用例处于 Nova Sonic 的能力范围之内
- 你想要一种类人、低延迟的实时对话体验

在以下情况使用级联模型：

- 需要对单个组件做定制
- 你需要使用来自 [Amazon Bedrock Marketplace](https://aws.amazon.com/bedrock/model-marketplace/)、[Amazon SageMaker AI，](https://aws.amazon.com/blogs/machine-learning/introducing-bidirectional-streaming-for-real-time-inference-on-amazon-sagemaker-ai/)的模型，或为你特定领域微调的模型
- 你需要支持 Nova Sonic 未覆盖的语言或口音
- 用例需要在特定环节做专门处理
