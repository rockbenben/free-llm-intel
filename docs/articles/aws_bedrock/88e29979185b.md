# 使用 Amazon Lex、Amazon Bedrock 和 ServiceNow 实现生成式 AI 自助服务

基于聊天的助手已成为提供自动化客户服务与支持的重要工具。本文建立在此前一篇文章 [Integrate QnABot on AWS with ServiceNow](https://aws.amazon.com/blogs/machine-learning/integrate-qnabot-on-aws-with-servicenow/) 的基础上，探讨如何借助 [Amazon Lex](https://aws.amazon.com/lex/)、[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 以及自定义的 [ServiceNow](https://www.servicenow.com/) 集成，构建一个智能助手，打造自动化的事件管理支持体验。

Amazon Lex 由与 Alexa 相同的深度学习技术驱动。借助它，开发者可以快速构建能够理解自然语言、进行真实对话并满足客户请求的会话式界面。你可以配置 Amazon Lex，让它使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 基础模型（FM）来搜索并概括常见问题（FAQ）的回答，从而回应客户提问。Amazon Bedrock Knowledge Bases 提供了把数据源汇聚成信息仓库的能力。使用知识库，你可以毫不费力地创建一个采用[检索增强生成](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）的应用——RAG 是一种从数据源检索信息来增强模型回答生成的技术。

ServiceNow 是一个基于云的平台，用于 IT 工作流管理与自动化。凭借在工单、知识管理、人力资源（HR）服务等方面强大的能力，ServiceNow 已经在为众多企业服务台提供支持。

通过把 Amazon Lex 聊天助手与 Amazon Bedrock Knowledge Bases 和 ServiceNow 连接起来，企业可以为客户和员工提供 7×24 小时的自动化支持与自助服务选项。在本文中，我们演示如何把 Amazon Lex 与 Amazon Bedrock Knowledge Bases 和 ServiceNow 集成。

## 解决方案概览

下图展示了该解决方案的架构。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-architecture.png)

该工作流包含以下步骤：

- ServiceNow 知识库被导出到 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3），它将作为 Amazon Bedrock Knowledge Bases 的数据源。Amazon S3 中的数据默认会被加密。你还可以通过[使用 AWS KMS 密钥进行服务器端加密](https://docs.aws.amazon.com/AmazonS3/latest/userguide/UsingKMSEncryption.html)（SSE-KMS）进一步增强安全性。
- 可以使用 [Amazon AppFlow](https://aws.amazon.com/appflow/) 在 ServiceNow 与 Amazon S3 之间同步。也可以使用 [AWS Glue](https://aws.amazon.com/glue/) 等其他方案从 ServiceNow 摄取数据。
- 创建 Amazon Bedrock Knowledge Bases，以 Amazon S3 作为数据源，并以 [Amazon Titan](https://aws.amazon.com/bedrock/titan/)（或你选择的其他模型）作为嵌入模型。
- 当 Amazon Lex 聊天助手的用户提问时，Amazon Lex 会从 Amazon Bedrock Knowledge Bases 获取答案。
- 如果用户请求创建一个 ServiceNow 工单，则会调用 [AWS Lambda](https://aws.amazon.com/lambda/)
- Lambda 函数从 [AWS Secrets Manager](https://aws.amazon.com/secrets-manager/) 获取密钥，并发起 HTTP 调用以创建 ServiceNow 工单。
- 在 AWS Lambda 上启用了 [Application Auto Scaling](https://docs.aws.amazon.com/autoscaling/application/userguide/what-is-application-auto-scaling.html)，以便根据用户交互自动扩缩 Lambda。
- 该解决方案将遵循负责任 AI 政策，并由 [Guardrails for Amazon Bedrock ](https://aws.amazon.com/bedrock/guardrails/)强制执行组织的负责任 AI 政策。
- 该解决方案使用 [Amazon CloudWatch](https://aws.amazon.com/cloudwatch/)、[AWS CloudTrail](https://aws.amazon.com/cloudtrail/) 和 [Amazon GuardDuty](https://aws.amazon.com/guardduty/) 进行监控。

在授予任何系统资源访问权限时，务必遵循最小权限访问策略。

## 先决条件

在构建解决方案之前，需要完成以下先决条件。

- 在 [Amazon Bedrock 控制台](https://console.aws.amazon.com/bedrock)上，按照[管理对 Amazon Bedrock 基础模型的访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)中的说明，申请访问你选择的 Anthropic Claude 模型。有关使用 Amazon Bedrock 的定价信息，请参阅 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。
- 如果你还没有 ServiceNow 账户，请[注册一个](https://signon.service-now.com/x_snc_sso_auth.do?pageId=sign-up)。保存好你的用户名和密码。在本演练的后续步骤中，你需要把它们存入 AWS Secrets Manager。
- 按照 [Integrate QnABot on AWS ServiceNow](https://aws.amazon.com/blogs/machine-learning/integrate-qnabot-on-aws-with-servicenow/) 中的说明创建一个 ServiceNow 实例。
- 按照[创建用户](https://docs.servicenow.com/bundle/washingtondc-platform-administration/page/administer/users-and-groups/task/t_CreateAUser.html)中的说明，创建一个在 ServiceNow 中拥有创建事件权限的用户。记下这些凭证，供本演练后续步骤使用。

本演练中提供的说明仅用于演示目的。请遵循 [ServiceNow 文档](https://docs.servicenow.com/bundle/washingtondc-customer-service-management/page/product/customer-communities/reference/servicenow-communities.html)创建社区实例，并遵循其最佳实践。

## 解决方案概览

要把 Amazon Lex 与 Amazon Bedrock Knowledge Bases 和 ServiceNow 集成，请按照后续各节中的步骤操作。

## 使用 AWS CloudFormation 控制台部署

在这一步中，你首先创建解决方案概览中讨论的解决方案架构，但不包括 Amazon Lex 助手——后者会在本演练稍后创建。请完成以下步骤：

- 在 [CloudFormation 控制台](https://console.aws.amazon.com/cloudformation/)上，确认你处于正确的 [AWS 区域](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region)，并选择 **Create stack** 来创建 CloudFormation 堆栈。
- 下载 [CloudFormation 模板](https://aws-blogs-artifacts-public.s3.amazonaws.com/ML-16345/GenAI-Blog-CFN.yaml)，并在 **Specify template** 中上传它。选择 **Next**。
- 对于 **Stack name**，输入一个名称，例如 `ServiceNowBedrockStack`。
- 在 **Parameters** 部分，针对 ServiceNow 相关信息，填写此前创建的 **ServiceNow host** 和 **ServiceNow username** 的值。
- 其他值保留默认设置。在最后一页的 **Capabilities** 下，选择 **I acknowledge that AWS CloudFormation might create IAM resources**。选择 **Submit** 创建 CloudFormation 堆栈。
- 整个堆栈成功部署后，在 **Outputs** 选项卡中记下输出键值 `BedrockKnowledgeBaseId`，因为在稍后创建 Amazon Lex 助手时会用到它。

把 Lambda 与 Application Auto Scaling 集成超出了本文的范围。相关指引请参阅 [AWS Lambda and Application Auto Scaling](https://docs.aws.amazon.com/autoscaling/application/userguide/services-that-can-integrate-lambda.html) 中的说明。

## 在 AWS Secrets Manager 中存储密钥

请按以下步骤把 ServiceNow 用户名和密码存入 AWS Secrets Manager：

- 在 [CloudFormation 控制台](https://console.aws.amazon.com/cloudformation/)上，进入 **Resources** 选项卡，输入“secrets”来筛选搜索结果。在 **Physical ID** 下，选择你通过 CloudFormation 堆栈创建的 AWS Secrets Manager 密钥的控制台 URL。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-cloudformation-secrets-manager.png)
- 在 AWS Secrets Manager 控制台的 **Overview** 选项卡上，在 **Secret value** 下选择 **Retrieve secret value**。
- 选择 **Edit**，输入你此前创建的 ServiceNow 实例的用户名和密码。请确保用户名和密码都正确。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-edit-secret.png)

## 下载知识文章

你需要能够访问 ServiceNow 知识文章。请按以下步骤操作：

- 如果你还没有知识库，请[创建一个](https://docs.servicenow.com/bundle/washingtondc-servicenow-platform/page/product/knowledge-management/task/create-a-knowledgebase.html)。你可能需要定期同步知识库以保持其内容最新。
- 按照 [ServiceNow](https://docs.aws.amazon.com/appflow/latest/userguide/servicenow.html) 中的说明，使用 Amazon AppFlow 把数据从 ServiceNow 同步到 Amazon S3。或者，你也可以按照博客文章[在 Amazon S3 数据湖中使用 AWS Glue Studio 提取 ServiceNow 数据并用 Amazon Athena 进行分析](https://aws.amazon.com/blogs/big-data/extract-servicenow-data-using-aws-glue-studio-in-an-amazon-s3-data-lake-and-analyze-using-amazon-athena/)中的说明，使用 AWS Glue 把数据从 ServiceNow 摄取到 Amazon S3。
- 下载一篇[示例文章](https://aws-blogs-artifacts-public.s3.amazonaws.com/ML-16345/HR+Policies+and+Procedures.pdf)。

## 同步 Amazon Bedrock Knowledge Bases：

该解决方案使用 Amazon Bedrock 的全托管 Knowledge Base 来无缝驱动 RAG 工作流，从而无需自定义集成和数据流管理。作为知识库的数据源，该解决方案使用 Amazon S3。以下步骤概述了如何把 ServiceNow 文章上传到由 CloudFormation 模板创建的 S3 存储桶。

- 在 [CloudFormation 控制台](https://console.aws.amazon.com/cloudformation/)上，进入 **Resources** 选项卡，输入“S3”来筛选搜索结果。在 **Physical ID** 下，选择通过 CloudFormation 堆栈创建的 S3 存储桶的 URL。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-cloudformation-s3.png)
- 把此前下载的知识文章[上传](https://docs.aws.amazon.com/AmazonS3/latest/userguide/upload-objects.html)到这个 S3 存储桶。

接下来你需要同步数据源。

- 在 [CloudFormation 控制台](https://console.aws.amazon.com/cloudformation)上，进入 **Outputs** 选项卡，输入“Knowledge”来筛选搜索结果。在 **Value** 下，选择你通过 CloudFormation 堆栈创建的知识库的控制台 URL。在新的浏览器标签页中打开该 URL。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-cf-knowledge-base.png)
- 向下滚动到 **Data source**，选择该数据源。选择 **Sync**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-data-source-sync.png)

你可以在 **Test the knowledge base** 部分选择模型并向其提问，以此测试知识库。

## 使用 Guardrails for Amazon Bedrock 实现负责任 AI

会话式 AI 应用需要稳健的 guardrails，以保护敏感用户数据、遵守隐私法规、落实伦理原则并缓解幻觉，从而促进负责任的开发与部署。Guardrails for Amazon Bedrock 允许你针对知识库配置组织策略。它们通过同时评估用户输入和模型响应来帮助保障生成式 AI 应用的安全

要设置 guardrails，请按以下步骤操作：

- 按照 Amazon Bedrock 用户指南中的说明[创建 guardrail](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-create.html)。

你可以通过启用 grounding 检查和相关性检查并调整阈值，来减少模型回答中的幻觉

- [创建 guardrail 的版本](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-versions-create-manage.html#guardrails-versions-create)。
- 选择刚创建的 guardrail，并复制 guardrail ID。稍后在创建 intent 时会用到该 ID。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-gaurdrails-in-bedrock.png)

## Amazon Lex 设置

在本节中，你将为 Amazon Lex 聊天助手配置用于调用 Amazon Bedrock 的 intent。本演练使用 [Amazon Lex V2](https://docs.aws.amazon.com/lexv2/latest/dg/what-is.html)。

- 在 [CloudFormation 控制台](https://console.aws.amazon.com/cloudformation/)上，进入 **Outputs** 选项卡，复制 `BedrockKnowledgeBaseId` 的值。本节稍后会用到该 ID。
- 在 **Outputs** 选项卡的 **Outputs** 下，输入“bot”来筛选搜索结果。选择你通过 CloudFormation 堆栈创建的 Amazon Lex 助手的控制台 URL。在新的浏览器标签页中打开该 URL。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-cf-knoweldge-base-id-1.png)
- 在 Amazon Lex 的 **Intents** 页面上，选择 **Create another intent**。在 **Add intent** 下拉菜单中，选择 **Use built-in intent**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-buitin-Inent.png)
- 在 **Use built-in intent** 屏幕上，在 **Built-in intent** 下选择 **QnAIntent- Gen AI feature**。
- 对于 **Intent name**，输入 `BedrockKb` 并选择 **Add**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-QnaIntnent.png)
- 在 QnA 配置部分的 **Select model** 下，选择 **Anthropic** 和 **Claude 3 Haiku**，或你选择的模型。
- 展开 **Additional Model Settings**，输入你此前创建的 guardrails 的 **Guardrail ID**。在 **Guardrail Version** 下，输入与你已创建版本数对应的编号。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-add-guardrails.png)
- 输入你此前在 CloudFormation 输出部分记录的 **Knowledge base for Amazon Bedrock Id**。在页面底部选择 **Save intent**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2024/08/17/ML-16345-choose-model.png)

## 监控

你可以使用 CloudWatch 日志查看助手的性能，并排查对话中的问题。在你部署的 CloudFormation 堆栈中，已经以适当的权限配置好了 Amazon Lex 助手的 CloudWatch 日志组。

要查看 Amazon Lex 助手的对话日志，请按以下指引操作。

在 CloudFormation 控制台的 **Outputs** 选项卡中，输入“Log”来筛选搜索结果。在 **Value** 下，选择你通过 CloudFormation 堆栈创建的 CloudWatch 日志组的控制台 URL。在新的浏览器标签页中打开该 URL。

为保护敏感数据，Amazon Lex 会在对话日志中遮蔽槽位值。作为安全最佳实践，不要在请求属性或会话属性中存储任何槽位值。Amazon Lex V2 不会在音频中遮蔽槽位值。你可以按照[选择性对话日志捕获](https://docs.aws.amazon.com/lexv2/latest/dg/monitoring-selective-logging.html)中的说明，仅选择性地捕获文本。

### 为 Amazon Bedrock 摄取作业启用日志记录

你可以使用 CloudWatch 监控 Amazon Bedrock 摄取作业。要为摄取作业配置日志记录，请按照[知识库日志记录](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-bases-logging.html)中的说明操作。

### AWS CloudTrail 日志

AWS CloudTrail 是一项 AWS 服务，用于跟踪用户、角色或 AWS 服务所执行的操作。当你创建 AWS 账户时，CloudTrail 就会在你的账户上启用。当该账户中发生活动时，该活动会连同其他 AWS 服务事件一起记录在 **Event history** 中的 CloudTrail 事件里。你可以在自己的 AWS 账户中查看、搜索和下载近期事件。更多信息，请参阅[使用 CloudTrail Event history](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/view-cloudtrail-events.html)。

作为安全最佳实践，你应当监控对环境的任何访问。你可以配置 [Amazon GuardDuty](https://docs.aws.amazon.com/guardduty/latest/ug/what-is-guardduty.html)，以识别 AWS 环境中任何意外且可能未经授权的活动。

## 清理

为避免产生未来的费用，请删除你创建的资源。要清理 AWS 环境，请使用以下步骤：

- [清空 S3 存储桶的内容](https://docs.aws.amazon.com/AmazonS3/latest/userguide/empty-bucket.html)，即你作为 CloudFormation 堆栈一部分创建的那个存储桶。
- [删除 CloudFormation 堆栈](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/cfn-console-delete-stack.html)，即你创建的那个堆栈。
