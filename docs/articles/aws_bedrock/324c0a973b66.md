# 使用 Amazon Bedrock 微调定制 Amazon Nova 模型

今天，我们来分享 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 如何让针对特定业务需求定制 [Amazon Nova models](https://aws.amazon.com/nova/) 变得简单直接。随着客户扩大 AI 部署，他们需要能够体现专有知识与工作流的模型——无论是在客户沟通中保持一致品牌语调、处理复杂的行业特定工作流，还是在高并发的航空订票系统中准确分类意图。prompt engineering 和检索增强生成（RAG）之类的技术为模型提供额外上下文以提升任务表现，但这些技术并不能给模型灌输原生理解。

Amazon Bedrock 为 Nova 模型支持三种定制方式：有监督微调（SFT），用带标注的输入-输出示例训练模型；强化微调（RFT），用奖励函数引导学习走向目标行为；以及模型蒸馏，把知识从更大的教师模型迁移到更小、更快的学生模型。每种技术都把新知识直接嵌入模型权重，而不是在推理时通过 prompt 或检索到的上下文提供。借助这些方式，你能获得更快的推理、更低的 token 成本，以及在对你业务最重要的任务上更高的准确率。Amazon Bedrock 自动管理训练过程，你只需把数据上传到 [Amazon Simple Storage Service (Amazon S3)](https://aws.amazon.com/s3/) 并通过 AWS Management Console、CLI 或 API 发起作业。无需深厚的机器学习专业知识。Nova 模型支持在 Amazon Bedrock 中以按需方式调用定制模型。这意味着你只需按标准费率按调用付费，而无需购买更昂贵的预置容量（Provisioned Throughput）。

本文中，我们将带你完整走一遍在 Amazon Bedrock 中用 Amazon Nova 模型做模型微调的实现，并通过一个意图分类器示例逐步演示每一步，该示例在一个领域特定任务上取得了更优表现。通读本指南，你将学会：准备能带来实质模型提升的高质量训练数据，配置超参数以优化学习而不至于过拟合，以及部署你微调后的模型以获得更高准确率和更低延迟。我们还会展示如何用训练指标和 loss 曲线评估结果。

## **理解微调以及何时使用它**

prompt engineering 或检索增强生成（RAG）这类上下文工程技术把信息放进模型的 prompt。这些方法有明显优势：立即生效、无需训练，允许动态更新信息，且无需修改就能配合多个基础模型使用。然而，这些技术在每次调用时都消耗上下文窗口的 token，随着时间推移会抬高累计成本与延迟。更重要的是，它们的泛化能力不佳。模型每次只是读一遍指令，而不是把知识内化，所以遇到新奇的表述、边缘情况，或需要超出 prompt 中显式提供的信息进行推理的任务时，就可能吃力。相比之下，定制技术通过添加一个额外权重的 adapter 矩阵并对其做定制（“参数高效微调”，又称“PEFT”），把新知识直接纳入模型。由此得到的定制模型获得了新的领域特定技能。借助定制，更快、更高效的小模型可以在特定训练领域达到与更大模型相当的表现。

**何时微调：** 当你有一个高并发、定义明确的任务，且能够汇总出高质量带标注的示例或一个奖励函数时，就应考虑微调。用例包括：训练模型正确渲染公司 logo、把品牌语调和公司政策嵌入模型，或用一个小 LLM 替换传统 ML 分类器。

像 Nova Micro 这样的微调小 LLM 正越来越多地取代传统 ML 分类器来完成意图检测这类任务。它们以轻量级模型的速度和成本，提供 LLM 的灵活性和世界知识。与传统分类器不同，LLM 无需重新训练就能应对措辞、俚语和上下文方面的自然变化，而微调会针对特定任务进一步锐化其准确率。我们在本文后面用意图分类器示例来演示这一点。

**何时不要微调：** 微调需要汇总高质量带标注的数据或一个奖励函数，并执行一次训练作业，这涉及前期时间与成本。不过，对于高并发应用，这笔前期投入可以降低每次请求的推理成本和延迟。

## **定制方式**

Amazon Bedrock 为 Nova 模型提供三种定制方式：

- **有监督微调（SFT）** 利用你提供的带标注数据来定制模型，让它学习其中的模式。本文演示这一技术的实际应用。
- **强化微调（RFT）** 走的是另一条路，用训练数据配合奖励函数——可以是自定义代码，也可以是充当评判者的 LLM——来引导学习过程。
- **模型蒸馏** 适用于需要知识迁移的场景，让你把大型教师模型中的洞察压缩到更小、更高效、适合资源受限设备的学生模型中。

Amazon Bedrock 会自动使用适合该模型的参数高效微调（PEFT）技术来定制 Nova 模型。与全量微调相比，这降低了显存需求、加速了训练，同时保持模型质量。既然已经明确了何时以及为何使用微调，接下来我们看看 Amazon Bedrock 如何简化实现过程，以及哪些 Nova 模型支持这种定制方式。

## **了解 Amazon Bedrock 上的 Amazon Nova 模型**

Amazon Bedrock 全自动完成基础设施预置、算力管理与训练编排。你把数据上传到 S3，用一次 API 调用就能开始训练，无需管理集群与 GPU，也无需配置分布式训练 pipeline。它提供了清晰的数据准备文档（包括格式规范和 schema 要求）、合理的超参数默认值（例如 `epochCount`、`learningRateMultiplier`），以及通过 loss 曲线提供的训练可见性，帮你实时监控收敛情况。

**Nova 模型：** 有若干 Nova 模型支持微调（见[文档](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-model-supported.html)）。训练完成后，你可以选择用成本效益高的按需推理在 Amazon Bedrock 上托管定制后的 Nova 模型，推理价格与未定制模型一样低。

以 Nova 2 Lite 为例，它是一个快速、高性价比的推理模型。作为多模态基础模型，它能在 100 万 token 的上下文窗口内处理文本、图像和视频。这个上下文窗口支持在单个 prompt 中分析超过 400 页的文档或 90 分钟的视频。它擅长文档处理、视频理解、代码生成和 agentic 工作流。Nova 2 Lite 同时支持 SFT 和 RFT。

最小的 Nova 模型 Nova Micro 也特别有用，因为它以 LLM 的智能水平提供快速、低成本的推理。Nova Micro 非常适合作为更大系统一部分的 pipeline 处理任务，例如修正地址或从文本中抽取数据字段。本文中，我们展示一个为分割任务定制 Nova Micro、而不是自建数据科学模型的示例。下表列出 Nova 1 和 Nova 2 推理模型及其在本文发布时的可用情况，以及哪些模型当前允许 RFT 或 SFT。这些能力可能变化；最新模型可用性与[定制](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-model-supported.html)请见[在线文档](https://docs.aws.amazon.com/bedrock/latest/userguide/models-supported.html)，模型详情请见 [Nova Users Guide](https://docs.aws.amazon.com/nova/latest/userguide/what-is-nova.html)。

## **用例示例——意图检测（替换传统 ML 模型）**

意图检测从输入案例中判定用户意图交互的类别。例如，在航空出行助手系统中，用户可能是在查询先前预订的航班信息，也可能是在问航空公司服务的问题，比如如何托运宠物。系统通常希望按意图把咨询路由给特定的 agent。意图检测系统必须高并发地快速、经济地运行。

这类系统传统的方案是训练一个机器学习模型。这虽然有效，开发者却越来越多地转向小 LLM 来做这些任务。LLM 更灵活，可以通过改 prompt 快速调整，还自带广泛的世界知识。它们对缩写、短信式俚语、同义表达和上下文的理解可以带来更好的用户体验，而且 LLM 的开发体验对 AI 工程师来说也很熟悉。

在我们的示例中，我们会在开源数据集 [Airline Travel Information System (ATIS)](https://www.kaggle.com/datasets/hassanamin/atis-airlinetravelinformationsystem) 上定制 Nova Micro 模型，这是意图类系统的行业标准基准。Nova Micro 在未定制时于 ATIS 上达到 41.4%，而我们可以针对该特定任务定制它，通过一次简单的训练作业把准确率提高到 97%。

## **技术实现：微调过程**

决定模型微调成功的两个关键因素是**数据质量**和**超参数选择**。把这两者做对，决定了你的模型是高效收敛，还是需要昂贵的重新训练。我们逐一走过实现过程的每个环节，先从如何准备训练数据开始。

### **数据准备**

Amazon Bedrock 要求 JSONL（JavaScript Object Notation Lines）格式，因为它在训练期间支持大数据集的高效流式读取，使你可以增量处理数据而不受内存限制。这种格式也简化了校验：每一行都可以独立检查错误。请确认 JSONL 文件中的每一行都是合法 JSON。如果文件格式不合法，Amazon Bedrock 的模型创建作业会报错失败。更多细节见 [Nova 模型微调文档](https://docs.aws.amazon.com/nova/latest/userguide/fine-tune-prepare-data-understanding.html)。我们用一个脚本把 ATIS 数据集格式化成 JSONL。Nova Micro 接受单独的验证集，所以我们随后把 10% 的数据切分为验证集（Nova 2 模型在定制时会自动这么做）。我们还保留了一个记录测试集，模型未在其上训练，以便得到干净的测试结果。

在我们的意图分类器示例中，输入数据只有文本。不过，在微调多模态模型时，也要确保只使用受支持的图像格式（PNG、JPEG 和 GIF）。确保训练样本覆盖重要情形。在微调之前，与团队一起校验数据集，并移除含糊或自相矛盾的答案。

### **数据隐私方面的考虑：**

在使用敏感数据做微调时：

- 在上传到 Amazon S3 之前，对 PII（姓名、邮箱地址、电话号码、支付信息）做匿名化或掩码处理。
- 考虑合规所需的属地化数据存储要求。
- Amazon Bedrock 不会使用你的训练数据来改进基础模型。
- 为增强安全性，可考虑使用 Amazon Virtual Private Cloud（VPC）端点，在 S3 与 Amazon Bedrock 之间建立私有连接，避免暴露在公共互联网上。

### **关键超参数**

超参数控制训练作业。Amazon Bedrock 设置了合理的默认值，通常不改也能用，但你可能需要为你的微调作业调整它们以达到目标准确率。以下是 Nova 理解模型的超参数——其他模型请参考[文档](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-models-hp.html)：

有三个超参数控制训练作业的行为，虽然 Amazon Bedrock 设置了合理的默认值，理解它们有助于你优化结果。**把这些设置调对，可以为你省下数小时训练时间，并尽量减少算力成本。**

第一个超参数 `epochCount` 指定模型对数据集做多少遍完整遍历。可以把它想象成反复读一本书以提升理解。第一遍读下来你可能记住 60% 的内容；第二遍把理解提升到 80%。但当你已经理解 100% 的内容后，再读只会浪费训练时间而不再有收益。Amazon Nova 模型支持 1 到 5 个 epoch，默认 2。更大的数据集通常用更少的 epoch 就能收敛，而更小的数据集则受益于更多迭代。在我们的 ATIS 意图分类器示例中，合并样本约 5000 条，我们把 `epochCount` 设为 3。

`learningRateMultiplier` 控制模型从错误中学习的力度，本质上就是修正的步长。如果学习率过高，你可能漏掉细节、跳到错误结论；如果学习率过低，结论形成得很慢。ATIS 示例中我们使用 1e-5（0.00001），这能提供稳定、渐进的学习。`learningRateWarmupSteps` 参数会在设定的迭代次数内把学习率逐步提升到指定值，缓解训练初期的不稳定。我们的示例使用默认值 10。

**这对你意味着什么：** 设置合适的 epoch 数可以避免浪费训练时间与成本。每个 epoch 都代表对完整训练数据再做一遍遍历，这会增加处理的 token 数（这是模型训练中的主要成本——见本文后面的“成本与训练时间”）。epoch 太少意味着模型可能没把训练数据学到足够有效的程度。早点找到这个平衡能同时省下时间和预算。学习率直接影响模型的准确率与训练效率，可能意味着一小时内收敛的模型与始终达不到可接受表现的模型之间的差别。

## **启动微调作业**

微调的前提是创建一个存放训练数据的 S3 桶。

### **S3 桶设置**

在与你的 Amazon Bedrock 作业相同的区域创建一个 S3 桶，并采用以下安全配置：

- **启用服务端加密**（SSE-S3 或 SSE-KMS），保护静态存储的训练数据。
- **阻止公共访问**，防止未授权的暴露。
- **启用 S3 版本控制**，保护训练数据免受意外覆盖，并跟踪各轮训练迭代的变化。

对你的输出 S3 桶施加相同的加密与访问控制。把你的 JSONL 文件上传到新的 S3 桶，然后用 /training-data 前缀组织它。S3 版本控制有助于保护训练数据免受意外覆盖，并让你跟踪各轮训练迭代的变化。当你试验不同数据集版本以优化结果时，这一点至关重要。

创建有监督微调作业

- 在 [AWS Management Console](https://console.aws.amazon.com/) 中选择 **Amazon Bedrock**。
- 选择 **Test, Chat/Text playground**，确认模型选择下拉列表中出现 Nova Micro。
- 在 Custom model 下选择 **Create**，然后选择 **Supervised fine-tuning job**。

- 将“**Nova Micro**”模型指定为源模型。
- 在 Training data 部分，输入 JSONL 训练文件的 S3 URI 路径（例如 `s3://amzn-s3-demo-bucket/training-data/focused-training-data-v2.jsonl)`）。

- 展开 Hyperparameters 部分并配置以下值：`epochCount: 3`、`learningRateMultiplier: 1e-5`、`learningRateWarmupSteps: 10`
- 选择具备最小权限 S3 访问策略的 IAM 角色，或者创建一个。该角色应具备：权限范围限定在特定桶路径上的特定操作（`s3:GetObject` 和 `s3:PutObject`）（例如 ` arn:aws:s3:::your-bucket-name/training-data/*` 和 `arn:aws:s3:::your-bucket-name/output-data/*`）。避免过度授权，并包含 IAM condition key。关于 S3 权限最佳实践与安全配置的详细指导，请参阅 [AWS IAM Best Practices 文档](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html)。
- 选择 Create job。

### **监控作业状态**

要监控训练作业的状态与收敛情况：

- 在 **Custom models** 仪表板中监控作业状态。
- 等待 **Data validation** 阶段完成，随后是 **Training** 阶段（完成时间从几分钟到几小时不等，取决于数据集大小与模态）。
- 训练完成后，选择你的作业名称，查看 **Training metrics** 标签页，确认 loss 曲线呈现正常的收敛。
- 训练完成后，若作业成功，就会创建一个可用于推理的定制模型。你可以部署定制后的 Nova 模型用于按需推理。

### **评估训练是否成功**

借助 Amazon Bedrock，你可以通过训练指标和 loss 曲线评估微调作业的效果。分析训练 loss 在各 step 和各 epoch 上的走势，就能判断模型是否在有效学习，并确定是否需要调整超参数以取得最佳表现。Amazon Bedrock 定制会自动把训练产物（包括验证结果、指标、日志和训练数据）存到你指定的 S3 桶，让你对训练过程拥有完整的可见性。训练指标数据让你能追踪模型在特定超参数下的表现，做出有依据的调参决策。

***图 4：** 从训练指标分析 loss 曲线***

这条 loss 曲线表明模型表现良好。指标中向下走的 loss 曲线证实模型成功地从你的训练数据中学到了东西。理想情况下，在模型学习过程中，训练 loss 与验证 loss 曲线应走势相近。配置得当的模型表现出平稳收敛——loss 平滑下降，没有剧烈波动。如果你在 loss 曲线中看到振荡模式（上下大幅摆动），把 `learningRateMultiplier` 降低 50% 并重新开始训练。如果你的 loss 下降太慢（曲线平或几乎不降），把 `learningRateMultiplier` 提高 2 倍。如果你的 loss 过早进入平台期（在达到良好准确率之前就变平），把 `epochCount` 增加 1-2 个 epoch。

![机器学习训练 loss 曲线，展示三种情形：收敛过慢、振荡以及最优收敛模式](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/04/06/ML-20219-5.png)

***图 5：*** ***理解 loss 曲线***

**关键要点：** 你的 loss 曲线讲述了完整的故事。平滑的下降趋势意味着成功。剧烈振荡意味着学习率过高。平线意味着你需要更多 epoch 或更好的数据。盯住这一个指标，就能避免昂贵的重新训练。

## **定制最佳实践**

**最大化微调成功率** 始于数据质量。小而精的数据集一贯优于大而噪的数据集。把精力放在精挑细选能准确代表目标领域的带标注示例上，而不是收集大量平庸数据。每个训练样本在使用前都应正确格式化并通过校验，因为干净的数据会直接转化为更好的模型表现。记得指定合适的 system prompt。

**要避免的常见坑** 包括过度训练（在收敛后仍跑太多 epoch）、次优的数据格式化（JSON/JSONL 结构不一致），以及需要调整的超参数设置。我们建议在开始前校验训练数据格式，并在训练期间主动监控 loss 曲线。留意模型已经收敛的信号。越过这一点继续训练只会浪费资源而不会改进结果。

**成本与训练时间**

在我们的 ATIS 示例中，用 4,978 条合并示例、3 个训练 epoch（约 175 万 token）训练定制后的 Nova Micro 模型，用时约 1.5 小时，仅花费 $2.18，外加每月 $1.75 的模型存储经常性费用。使用定制后的 Amazon Nova 模型做按需推理，费率与未定制模型相同。参考 [Bedrock 定价](https://aws.amazon.com/bedrock/pricing/) 页面。Amazon Bedrock 提供的托管微调加上 Amazon Nova 模型，把微调成本稳稳拉进大多数组织的可接受阈值之内。易用性与成本效益开辟了新的可能：定制模型以更好、更快的结果产出，而无需维护冗长的 prompt 或本组织专属的知识库。

**部署与测试微调后的模型**

对于不可预测或低并发的工作负载，考虑按需推理。当需要一致、高并发的生产负载，并且要求有保证的性能与更低的每 token 成本时，再使用更昂贵的预置吞吐。

**模型安全方面的考虑：**

- 使用 IAM 资源策略限制模型调用，控制哪些用户和应用可以调用你的定制模型。
- 通过 IAM 角色与策略，为访问按需推理端点的 API 调用方实现认证/授权。

**网络安全：**

- 为 Amazon Bedrock [配置 VPC 端点](https://docs.aws.amazon.com/bedrock/latest/userguide/vpc-interface-endpoints.html)，让流量留在你的 AWS 网络内。
- 使用安全组和网络 ACL 限制对训练与推理 pipeline 的网络访问。
- 考虑把资源部署在 VPC 内，以获得额外的网络层控制。

## **超越 Amazon Bedrock 的定制能力**

Amazon Bedrock 简化的定制体验能满足许多客户需求。如果你需要对定制做更全面的控制，Amazon SageMaker AI 提供更丰富的定制类型以及对超参数更细致的控制——详见博文 [Announcing Amazon Nova customization in Amazon SageMaker AI](https://aws.amazon.com/blogs/aws/announcing-amazon-nova-customization-in-amazon-sagemaker-ai/)。

对于需要更进一步定制的场景，[Amazon Nova Forge](https://aws.amazon.com/nova/forge/) 提供了从零构建基础模型的战略替代方案。微调通过带标注的示例教会模型特定任务行为，而 Nova Forge 使用持续预训练，把模型沉浸在数百万到数十亿 token 的无标注专有数据中，从而建立全面的领域知识。这种方式非常适合拥有海量专有数据集的组织、需要深厚专业知识的极度专门化领域，或者那些构建将作为组织资产的长期战略基础模型的组织。

Nova Forge 通过提供高级能力超越标准微调，包括在全秩有监督微调期间缓解灾难性遗忘的数据混合、为取得最佳模型表现而做的 checkpoint 选择，以及用于多轮强化微调的 bring-your-own-optimizer（BYOO）。虽然它需要通过年度订阅和更长的训练周期做更大投入，但 Forge 能提供比从零训练基础模型显著更具成本效益的路径。这种方式非常适合构建作为长期竞争优势的战略 AI 资产。Nova Forge 的定制示例见 GitHub 上的 [Amazon Nova Customization Hub](https://github.com/aws-samples/amazon-nova-samples/tree/main/customization)。

## **结论**

正如我们通过意图分类器示例所展示的，Amazon Bedrock 的托管微调能力，加上 Nova 和 Nova 2 模型，让 AI 定制变得低成本、低门槛。这条简化的路径只需最少的数据准备与超参数管理，最大限度地减少了对专职数据科学技能的需求。你可以通过减少模型必须处理的上下文信息 token 来定制模型，从而改善延迟、降低推理成本。在 Amazon Bedrock 上微调 Nova 模型，能把通用基础模型转化为强大的领域专用工具，以低训练成本提供更高准确率和更低延迟。Amazon Bedrock 能够用[按需推理](https://docs.aws.amazon.com/nova/latest/nova2-userguide/on-demand-inference.html)托管 Nova 模型，使你以与基础 Nova 模型相同的每 token 价格运行模型。当前费率请见 [Bedrock 定价页面](https://aws.amazon.com/bedrock/pricing/)。

要开始你自己的 Amazon Bedrock 微调项目，请浏览 [Amazon Bedrock 微调文档](https://docs.aws.amazon.com/bedrock/latest/userguide/custom-models.html)，并在 [AWS Samples GitHub 仓库](https://github.com/aws-samples/amazon-nova-samples/tree/main/customization) 中查看示例 notebook。
