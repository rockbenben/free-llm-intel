# Amazon Bedrock Knowledge Bases 现在支持将 Amazon OpenSearch Service 托管集群用作向量存储

[Amazon Bedrock Knowledge Bases](https://aws.amazon.com/bedrock/knowledge-bases/) 通过支持 [Amazon OpenSearch Service](https://aws.amazon.com/opensearch-service/) 托管集群，扩展了其向量存储选项，进一步强化了它作为全托管 [Retrieval Augmented Generation](https://aws.amazon.com/what-is/retrieval-augmented-generation/)（RAG）解决方案的能力。这一增强建立在 Amazon Bedrock Knowledge Bases 的核心功能之上——该功能旨在将 [foundation models](https://aws.amazon.com/what-is/foundation-models/)（FM，基础模型）与内部数据源无缝连接。Amazon Bedrock Knowledge Bases 自动完成数据摄取、分块、向量嵌入生成与向量存储等关键流程，并应用先进的索引算法与检索技术，让用户以极少的投入构建智能应用。

最新更新拓宽了用户可用的向量数据库选项。除了此前支持的向量存储，例如 [Amazon OpenSearch Serverless](https://aws.amazon.com/opensearch-service/features/serverless/)、[Amazon Aurora PostgreSQL-Compatible Edition](https://aws.amazon.com/rds/aurora/features/)、[Amazon Neptune Analytics](https://docs.aws.amazon.com/neptune-analytics/latest/userguide/what-is-neptune-analytics.html)、Pinecone、MongoDB 和 Redis Enterprise Cloud，用户现在还可以使用 OpenSearch Service 托管集群。这一集成使 OpenSearch Service 域可作为存储与检索向量嵌入的稳健后端，在向量存储方案上提供了更大的灵活性与更多选择。

为帮助用户充分利用这一新集成，本文提供一份全面、分步的指南，介绍如何将 Amazon Bedrock 知识库与作为其向量存储的 OpenSearch Service 托管集群集成。

## 为什么要把 OpenSearch Service 托管集群用作向量存储？

OpenSearch Service 为向量工作负载提供两种互补的部署选项：托管集群和 serverless 集合。两者都能发挥 OpenSearch Service 强大的向量搜索与检索能力，但各自在不同场景中更胜一筹。托管集群提供广泛的配置灵活性、性能调优选项和可扩展性，因此特别适合企业级 AI 应用。那些希望对集群配置、计算实例拥有更多控制权，希望调优性能与成本，并需要支持更广泛的 OpenSearch 功能和 API 操作的组织，会发现托管集群正好契合其用例。另一方面，OpenSearch Serverless 擅长需要自动扩缩容与容量管理、无需管理集群或节点即可简化运维、自动软件更新以及内置高可用与冗余的用例。最佳选择完全取决于具体用例、运维模式和技术要求。以下是 OpenSearch Service 托管集群为何能为组织提供有吸引力的选择的几个关键原因：

- **灵活配置** —— 托管集群提供灵活而丰富的配置选项，可针对特定工作负载进行精细调优。这包括选择实例类型、调整资源分配、配置集群拓扑以及实施专门的性能优化。对于有特定性能要求或独特工作负载特征的组织，这种级别的定制极具价值。
- **满足设计标准的性能与成本优化** —— 向量数据库的性能是准确性、延迟和成本这三个关键维度之间的权衡。托管集群提供细粒度的控制能力，可沿其中一个维度或几个维度的组合进行优化，以满足特定的设计标准。
- **抢先使用高级 ML 功能** —— OpenSearch Service 遵循结构化的发布周期，新能力通常先出现在开源项目中，随后进入托管集群，之后才进入 serverless 产品。优先考虑尽早采用高级向量搜索能力的组织，可能会从选择托管集群中获益，因为托管集群往往能更早接触到新的创新。不过，对于使用 Amazon Bedrock Knowledge Bases 的客户，这些功能只有在完全集成进知识库之后才会带来实际价值。这意味着，即使某项功能已在托管 OpenSearch Service 集群中可用，它也可能不会立即在 Amazon Bedrock Knowledge Bases 中可用。尽管如此，选择托管集群仍能让组织在这些能力于 Bedrock Knowledge Bases 中获得支持后，更快地利用最新的 OpenSearch 进展。

## 先决条件

在深入具体设置之前，请确保已具备以下先决条件：

- **数据源** —— 一个 [Amazon S3](https://aws.amazon.com/s3/) 存储桶（或自定义源），其中包含用于知识库摄取的文档。我们假设你的存储桶包含可供检索的[受支持文档](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-ds.html#kb-ds-supported-doc-formats-limits)类型（PDF、TXT 等）。
- **OpenSearch Service 域（可选）** —— 对于现有域，请确保它与你要创建 Amazon Bedrock 知识库的 [Region](https://docs.aws.amazon.com/glossary/latest/reference/glos-chap.html#region) 和账户相同。截至本文撰写时，Bedrock Knowledge Bases 要求 OpenSearch Service 域具备公有访问权限；仅限虚拟私有云（VPC）内的域尚不受支持。请确保你拥有创建或配置域所需的[必要权限](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/ac.html)。本指南同时涵盖新建域与现有域的设置。

## 解决方案概览

本节介绍将 OpenSearch Service 托管集群与 Amazon Bedrock Knowledge Bases 集成的以下高层步骤：

- **创建 OpenSearch Service 域** —— 设置一个具备公有访问权限、合适引擎版本和安全设置的新 OpenSearch Service 托管集群，其中包括 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）主用户角色和细粒度访问控制。此步骤还包括通过创建专用 IAM 资源建立管理访问权限，并为安全访问仪表板配置 [Amazon Cognito](https://aws.amazon.com/cognito/) 身份验证。
- **在 OpenSearch Service 中配置向量索引** —— 在域上创建一个启用 k 最近邻（k-NN）的索引，并为向量、文本块和元数据字段设置合适的映射，以兼容 Amazon Bedrock Knowledge Bases。
- **配置 Amazon Bedrock 知识库** —— 开始创建 Amazon Bedrock 知识库，启用你的 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）数据源，并将其配置为使用你的 OpenSearch Service 域作为向量存储，同时填入所有相关的域信息。
- **在 OpenSearch Service 中配置细粒度访问控制权限** —— 通过创建一个具有特定权限的角色并将其映射到 [Amazon Bedrock](https://aws.amazon.com/bedrock/) IAM 服务角色，在 OpenSearch Service 中配置细粒度访问控制，从而为知识库提供安全且受控的访问。
- **完成知识库创建并摄取数据** —— 在 Amazon Bedrock 控制台中发起同步操作，以处理 S3 文档、生成嵌入并将其存储到你的 OpenSearch Service 索引中。

## 解决方案演练

以下是在 AWS 控制台中集成 Amazon Bedrock Knowledge Bases 与 OpenSearch Service 托管集群需要遵循的步骤。

### 通过 IAM 主用户和角色建立管理访问权限

在创建 OpenSearch Service 域之前，你需要创建两项关键 IAM 资源：一个专用的 IAM 管理员用户和一个主角色。这种做法有助于对你的 OpenSearch Service 域进行妥善的访问管理，尤其是在实施细粒度访问控制时——生产环境强烈建议启用该控制。此用户和角色将拥有创建、配置和管理 OpenSearch Service 域及其与 Amazon Bedrock Knowledge Bases 集成所需的权限。

#### 创建 IAM 管理员用户

管理用户是管理 OpenSearch Service 配置的主体账户。要创建 IAM 管理员用户，请按以下步骤操作：

- 在 AWS 账户中打开 IAM 控制台
- 在左侧导航窗格中选择 **Users**，然后选择 **Create user**
- 输入一个描述性的用户名，例如 `<opensearch-admin>`
- 在权限配置页面上，选择 **Attach policies directly**
- 搜索并附加 `AmazonOpenSearchServiceFullAccess` 托管策略，该策略授予 OpenSearch Service 操作的完整权限
- 检查你的设置并选择 **Create user**

创建用户后，复制并保存该用户的 Amazon Resource Name（ARN），以便稍后在域配置中使用，并将 `<ACCOUNT_ID>` 替换为你的 AWS 账户 ID。

该 ARN 大致如下所示：

`arn:aws:iam::<ACCOUNT_ID>:user/opensearch-admin`

#### 创建充当 OpenSearch Service 主用户的 IAM 角色

借助 OpenSearch Service，你可以为启用了细粒度访问控制的域指定一位主用户。通过将 IAM 角色配置为主用户，你可以使用可信主体管理访问，避免使用静态用户名和密码。要创建该 IAM 角色，请按以下步骤操作：

- 在 IAM 控制台的左侧导航窗格中，选择 **Roles**，然后选择 **Create role**
- 选择 **Custom trust policy** 作为可信实体类型，以便精确控制哪些主体可以担任该角色
- 在 JSON 编辑器中，粘贴以下信任策略，它允许诸如你的 `opensearch-admin` 用户之类的主体担任该角色

```
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Effect": "Allow",
         "Principal": {
           "AWS": "arn:aws:iam::<ACCOUNT_ID>:user/opensearch-admin"
         },
         "Action": "sts:AssumeRole"
       }
     ]
   }
```

- 继续前往 **Add permissions** 页面，附加你为管理员用户使用的同一个 `AmazonOpenSearchServiceFullAccess` 托管策略
- 提供一个描述性名称，例如 `OpenSearchMasterRole`，然后选择 **Create role**

角色创建完成后，导航到其摘要页面并复制该角色的 ARN。在配置 OpenSearch Service 域的主用户时，你将需要这个 ARN。

`arn:aws:iam:: <ACCOUNT_ID>:role/OpenSearchMasterRole`

### 为向量搜索创建 OpenSearch Service 域

管理 IAM 角色建立后，下一步是创建将作为 Amazon Bedrock 知识库向量存储的 OpenSearch Service 域。这涉及配置域的引擎、网络访问，以及最重要的一点——使用细粒度访问控制配置其安全设置。

- 在 OpenSearch Service 控制台中，选择 **Managed clusters** 作为部署类型，然后选择 **Create domain**。
- 配置域详细信息：提供一个域名称，例如 `bedrock-kb-domain`。为了快速、直接地完成设置，请选择 **Easy create**，如下图所示。该选项会自动选择适合开发或小规模工作负载的实例类型和默认配置。这样，你无需手动配置即可快速部署一个可用的 OpenSearch Service 域。这些设置中有许多可以在需求变化后修改，因此这种方式非常适合实验或非生产用例，同时仍能提供坚实的基础。

![Amazon OpenSearch 域创建](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18695-domain-creation.jpeg)

如果你的工作负载需要更高的每秒输入/输出操作数（IOPS）或吞吐量，或者涉及管理大量数据，建议选择 **Standard create**。启用该选项后，你可以自定义实例类型、存储配置和高级安全设置，以优化数据存储与检索操作的速度和效率，因此它非常适合生产环境。例如，你可以将每个数据节点上每预置 3 TiB 存储的 GP3 卷基准性能从 3,000 IOPS 和 125 MiB/s 吞吐量提升到 16,000 IOPS 和 1,000 MiB/s 吞吐量。这种灵活性意味着你可以让 OpenSearch Service 域的性能与特定的工作负载需求相匹配，从而为高吞吐或大规模应用实现高效的索引与检索操作。应依据 OpenSearch Service 工作负载的规模和复杂度对这些设置进行微调，以同时优化性能与成本。

不过，尽管提高域的吞吐量与存储设置有助于改善域性能，也可能有助于缓解由存储或节点级瓶颈导致的摄取错误，但截至本文撰写时，它并不会提高向 Amazon Bedrock Knowledge Bases 摄取的速度。无论底层域配置如何，知识库摄取对客户和向量数据库都按固定吞吐率运行。AWS 会持续投入扩展和改进 Bedrock Knowledge Bases 的摄取能力，未来的改进可能带来更大的灵活性。

- 对于引擎版本，选择 OpenSearch 2.13 或更高版本。如果你计划存储二进制嵌入，请选择 2.16 或以上版本，因为二进制向量索引需要该版本。建议使用最新的可用版本，以获得性能改进和功能更新。
- 对于网络配置，在 **Network** 下选择 **Public access**，如下图所示。这一点至关重要，因为截至本文撰写时，Amazon Bedrock Knowledge Bases 不支持连接到位于 VPC 之后的 OpenSearch Service 域。为维护安全，我们实施 IAM 策略和细粒度访问控制，以细粒度的方式管理访问。借助这些控制，你可以定义谁可以访问你的资源以及可以执行哪些操作，遵循最小权限原则。如果提示选择网络设置，请选择 **Dual-stack mode**。这样可同时支持 IPv4 和 IPv6，提供更好的兼容性与可访问性。

![Amazon OpenSearch 域网络访问配置](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18695-opensearch-network.jpeg)

- 在安全方面，启用 **Fine-grained access control**，通过在索引、文档和字段级别定义详细的、基于角色的权限来保护你的域。与仅在域级别生效的基于资源的策略相比，该功能提供更精确的控制。

在细粒度访问控制的实施部分，我们将引导你创建一个具有特定索引和集群权限的自定义 OpenSearch Service 角色，然后通过将 Amazon Bedrock Knowledge Bases 的服务角色与该自定义角色关联来为其授权。这种映射建立了一种信任关系，使 Bedrock Knowledge Bases 在使用其服务凭证访问你的 OpenSearch Service 域时，只能执行你明确允许的操作，从而实现安全且受控的集成。

启用细粒度访问控制时，你必须选择一位主用户来管理域。你有两个选项：

- **创建主用户（用户名和密码）** —— 该选项在 OpenSearch Service 内部用户数据库中建立凭证，可快速完成设置并通过基本身份验证直接访问 OpenSearch Dashboards。虽然对初始配置或开发环境很方便，但它要求你谨慎管理这些凭证，并将其视为独立于 AWS 基础设施的身份。**将 IAM ARN 设置为主用户** —— 该选项与 AWS 身份体系集成，允许基于 IAM 的身份验证。对于应用和服务已依赖 IAM 进行安全访问、且你需要可审计性并与现有 AWS 安全态势集成的生产环境，强烈建议采用此选项。

在本演练中，我们选择 **Set IAM ARN as master user**。这是生产环境推荐的做法，因为它与你现有的 AWS 身份框架集成，提供更好的可审计性和安全管理。

在文本框中，粘贴你在第一步创建的 `OpenSearchMasterRole` 的 ARN，如下图所示。这将把该 IAM 角色指定为 OpenSearch Service 域的超级用户（superuser），授予其在 OpenSearch Dashboards 中管理用户、角色和权限的完整权限。

![Amazon OpenSearch 域 FGAC](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18695-opensearch-fgac.png)

虽然设置 IAM 主用户对于程序化访问很理想，但并不便于让用户登录 OpenSearch Dashboards。在后续步骤中，域创建完成并且我们配置好 Cognito 资源之后，我们会回到这一安全配置，启用 Amazon Cognito 身份验证。届时你就能为 OpenSearch Dashboards 提供用户友好的登录体验，用户可以登录托管 UI 并自动映射到 IAM 角色（例如 `MasterUserRole` 或权限更受限的角色），把易用性与稳健的、基于角色的安全性结合起来。目前，请先以 IAM ARN 作为主用户完成初始域设置。

- 检查你的设置并选择 **Create** 以启动域。初始化过程通常需要约 10–15 分钟。在此期间，OpenSearch Service 将创建域并应用你的配置。

域变为活动状态后，导航到其详情页以获取以下信息：

- **域端点** —— 这是访问 OpenSearch Service 的 HTTPS URL，通常遵循以下格式：`https://search``-<domain-name>-<unique-identifier>.<region>.es.amazonaws.com`
- **域 ARN** —— 它唯一标识你的域，结构如下：`arn:aws:es:<region>:<account-id>:domain/<domain-name>`

请务必复制并妥善保存这两项信息，因为在后续步骤中配置 Amazon Bedrock 知识库时你会用到它们。至此 OpenSearch Service 域已启动并运行，你现在拥有一个可用于存储向量嵌入的空集群。接下来，我们继续在该域中配置向量索引。

### 创建 Amazon Cognito 用户池

创建 OpenSearch Service 域之后，下一步是配置 Amazon Cognito 用户池。该用户池将为访问 OpenSearch Dashboards 提供安全且用户友好的身份验证层。请按以下步骤操作：

- 导航到 Amazon Cognito 控制台，从主仪表板选择 **User pools**。选择 **Create user pool** 开始配置流程。最新的、面向开发者的控制台体验提供统一的应用设置界面，而非传统的分步向导。
- 对于 OpenSearch Dashboards 集成，选择 **Traditional web application**。该应用类型支持仪表板访问所需的身份验证流程，并能安全地处理集成所需的 OAuth 流程。
- 在 **Name your application** 字段中输入描述性名称，例如 `opensearch-kb-app`。该名称将自动成为你的应用客户端名称。
- 配置用户如何对你的系统进行身份验证。对于 OpenSearch 集成，请选择 **Email** 作为主要登录选项。这允许用户使用电子邮件地址注册和登录，提供一种熟悉的身份验证方式。如果你的用例需要其他登录方式，还可选择 **Phone number** 和 **Username**。
- 指定注册期间必须收集的用户信息。至少确保将 **Email** 选为必填属性。这对账户验证和恢复流程至关重要。
- 此步骤是一项关键的安全配置，用于指定 Cognito 在身份验证成功后可以将用户重定向到哪里。在 **Add a return URL** 字段中，按以下格式输入你的 OpenSearch Dashboards URL：`https://search-<domain-name>-<unique-identifier>.aos.<region>.on.aws/_dashboards`。
- 选择 **Create user directory**，以预置你的用户池及其关联的应用客户端。

简化界面会针对你选择的应用类型自动配置最佳设置，包括适当的安全策略、OAuth 流程和托管 UI 域生成。复制并保存 **User pool ID** 和 **App client ID** 的值。配置 Cognito 身份池并更新 OpenSearch Service 域的安全设置时，你会用到它们。

### 向用户池添加管理员用户

创建 Amazon Cognito 用户池后，你需要添加一个将有权访问 OpenSearch Dashboards 的管理员用户。请按以下步骤操作：

- 在 Amazon Cognito 控制台中，选择你刚创建的用户池
- 在左侧导航窗格中，选择 **Users**
- 选择 **Create user**
- 选择 **Send an email invitation**
- 为管理员输入 **Email address**，例如 `admin@example.com`
- 选择是设置 **Temporary password**，还是让 Cognito 生成一个
- 选择 **Create user**

![Amazon Cognito 用户创建](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18695-cognito-userpool.png)

管理员首次登录时，系统会提示其创建永久密码。当所有后续设置步骤完成后，该管理员用户即可通过身份验证访问 OpenSearch Dashboards。

### 配置应用客户端设置

### 在 OpenSearch Service 中创建 k-NN 向量索引

此步骤涉及在你的 OpenSearch Service 域中创建一个启用向量搜索的索引，供 Amazon Bedrock 存储文档嵌入向量、文本块和元数据。索引必须包含三个关键字段：一个用于存储内容数值表示的嵌入向量字段（浮点或二进制格式）、一个用于保存原始文本块的文本字段，以及一个用于 Amazon Bedrock 托管元数据的字段——Amazon Bedrock 会在其中跟踪文档 ID 和来源归因等关键信息。通过合适的索引映射，Amazon Bedrock Knowledge Bases 可以高效地存储和检索文档数据的各个组成部分。

你使用 OpenSearch Dashboards 中的 Dev Tools 功能创建该索引。要访问 OpenSearch Dashboards 中的 Dev Tools，请按以下步骤操作：

- 登录你的 OpenSearch Dashboards 账户
- 导航到你的 OpenSearch Dashboards URL
- 你会被重定向到 Cognito 登录页
- 使用你在 **Add an admin user to the user pool** 部分创建的管理员用户凭证登录
- 输入你提供的电子邮件地址（`admin@example.com`）
- 输入你的密码（如果这是首次登录，系统会提示你创建永久密码）
- 身份验证成功后，你将被带到 OpenSearch Dashboards 主页
- 在左侧导航窗格的 **Management group** 下，选择 **Dev Tools**
- 确认你位于 **Console** 页面，如下图所示，你将在其中输入 API 命令

![Amazon OpenSearch 仪表板](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18695-opensearch-dashboard.jpeg)

要定义并创建索引，请将以下命令复制到 Dev Tools 控制台，如有需要，可将 `bedrock-kb-index` 替换为你偏好的索引名。如果你要设置二进制向量索引（例如，配合 [Amazon Titan](https://aws.amazon.com/bedrock/amazon-models/titan/) Text Embeddings V2 使用二进制嵌入），请在索引映射中包含额外的必需字段：

- 将“`data_type`”设为“`binary`”
- 将“`space_type`”设为“`hamming`”（而不是浮点嵌入所用的“l2”）

更多详细信息，请参阅 [Amazon Bedrock Knowledge Bases 设置文档](https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base-setup.html)。

```
PUT /bedrock-kb-index
{
  "settings": {
    "index": {
      "knn": true
    }
  },
  "mappings": {
    "properties": {
      "embeddings": {
        "type": "knn_vector",
        "dimension": <<embeddings size depending on embedding model used>>,
        "space_type": "l2",
        "method": {
          "name": "hnsw",
          "engine": "faiss",
          "parameters": {
            "ef_construction": 128,
            "m": 24
          }
        }
      },
      "AMAZON_BEDROCK_TEXT_CHUNK": {
        "type": "text",
        "index": true
      },
      "AMAZON_BEDROCK_METADATA": {
        "type": "text",
        "index": false
      }
    }
  }
}
```

该索引映射的关键组成部分包括：

- **启用 k-NN** —— 在索引设置中启用 k-NN 功能，从而可以使用 `knn_vector` 字段类型。
- **向量字段配置** —— 定义用于存储向量数据的 `embeddings` 字段，并根据所选的嵌入模型指定维度、空间类型和数据类型。维度必须与嵌入模型的输出匹配，这一点至关重要。Amazon Bedrock Knowledge Bases 提供 Amazon Titan Embeddings V2（256、512 或 1,024 维）和 Cohere Embed（1,024 维）等模型。例如，使用 1,024 维的 Amazon Titan Embeddings V2 时，需要在映射中设置 dimension: 1024。模型向量大小与索引映射不匹配会导致摄取失败，因此务必核实该值。
- **向量方法设置** —— 使用 Faiss 引擎配置分层可导航小世界（HNSW）算法，并设置用于平衡索引构建速度与准确性的参数。Amazon Bedrock Knowledge Bases 集成特别要求 OpenSearch Service k-NN 索引使用 Faiss 引擎。
- **文本块存储** —— 建立一个用于存储文档原始文本块的字段，从而支持可能的全文查询。
- **元数据字段** —— 创建一个用于 Amazon Bedrock 托管元数据的字段，在不建立索引的情况下存储关键信息，以便直接搜索。

将命令粘贴到 Dev Tools 控制台后，选择 **Run**。如果成功，你将收到与下图类似的响应。

![Amazon OpenSearch 仪表板索引创建](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18695-opensearch-index-cr.jpeg)

现在，你的域上应该有一个带有上述映射的新索引（例如名为 `bedrock-kb-index`）。请记下你创建的索引名、向量字段名（`embeddings`）、文本字段名（`AMAZON_BEDROCK_TEXT_CHUNK`）和元数据字段名（`AMAZON_BEDROCK_METADATA`）。在接下来的步骤中，你将授予 Amazon Bedrock 使用此索引的权限，然后把这些详细信息填入 Amazon Bedrock Knowledge Bases 的设置中。

向量索引已成功创建，你的 OpenSearch Service 域现在已准备好存储和检索嵌入向量。接下来，你将配置 IAM 角色和访问策略，以便 Amazon Bedrock 与你的 OpenSearch Service 域之间进行安全交互。

## 理解访问策略

在将 OpenSearch Service 托管集群与 Amazon Bedrock Knowledge Bases 集成时，理解访问控制如何跨不同层次运作很重要。

对于同账户设置配置（知识库与 OpenSearch Service 域位于同一 AWS 账户，这也是目前唯一受支持的配置），只要启用了细粒度访问控制且你的 IAM 角色已正确映射，就无需更新 OpenSearch Service 域的基于资源的策略。在这种情况下，IAM 权限与细粒度访问控制映射已足以授权访问。然而，如果该域的基于资源的策略包含针对你的知识库服务角色或主体的 deny 语句，访问将被阻止——无论 IAM 或细粒度访问控制设置如何。为避免意外失败，请确保该策略没有显式限制对 Amazon Bedrock Knowledge Bases 服务角色的访问。

![Bedrock 知识库同步作业](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/07/01/ML-18695-kb-data-sync.jpeg)

要开始使用你的知识库，请选择已配置的数据源并发起同步流程。此操作将启动 Amazon S3 数据的摄取。同步完成后，你的知识库即可用于信息检索。

将 Amazon Bedrock Knowledge Bases 与 OpenSearch Service 托管集群集成，为 AI 应用中的向量存储与检索提供了强大的解决方案。本文中，我们带你走完了设置 OpenSearch Service 域、配置向量索引并将其连接到 Amazon Bedrock 知识库的全过程。完成此设置后，你现在可以在 AI 驱动的应用中充分发挥向量搜索能力的潜力，更高效地处理和检索大型数据集中的信息。
