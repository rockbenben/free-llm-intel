# 使用 Strands Agents 结合 Meta 的 Llama 4 与 Amazon Bedrock 构建多 agent 方案

多 agent 方案让网络化的 agent 群体协作、协调并共同推理，正在改变我们应对现实问题的方式。企业要管理拥有多种数据源、目标不断变化且受各种约束的环境。这正是多 agent 架构大显身手之处。通过让多个各自拥有专用工具、记忆或视角的 agent 作为一个集体去交互和推理，组织可以解锁强大的新能力：

- **可伸缩性** – 多 agent 框架能处理复杂度不断增长的任务，智能地分摊工作负载，并实时按规模调整。
- **韧性** – 当 agent 协同工作时，单个 agent 的失败可以由其他 agent 补偿或缓解，从而形成健壮、容错的系统。
- **专业化** – 单个 agent 在特定领域（如金融、数据转换和用户支持）表现出色，同时又能无缝协作，解决跨学科问题。
- **动态问题求解** – 多 agent 系统可以快速重组、转向并响应变化，这在动荡的业务、安全和运维环境中至关重要。

agentic AI 框架近期的一些发布，例如 [Strands Agents](https://strandsagents.com/latest/)，让开发者更容易参与创建和部署由模型驱动的多 agent 方案。你可以定义 prompt 并集成工具集，让能力强大的语言模型自主推理、规划和调用工具，而不是依赖手工编写、易碎的 workflow。

在生产环境中，[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore) 这类服务通过持久记忆、身份集成和企业级可观测性等特性，支持安全、可扩展的部署。这种向协作式多 agent AI 方案的转变正在革新软件架构，使其更自主、更有韧性、更易适应。从云基础设施的实时故障排查，到金融服务中的跨团队自动化，再到协调复杂多步业务流程的对话式助手，采用多 agent 方案的组织正在为更高的敏捷性和创新力做好准备。现在，借助 Strands 这类开放框架，任何人都可以开始构建能够共同思考、交互和演进的智能系统。

本文探讨如何使用 Strands Agents、Meta 的 Llama 4 模型和 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 构建一个多 agent 视频处理工作流，通过多个各司其职的 AI agent 协同工作，自动分析和理解视频内容。为展示这一方案，我们将用 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/?trk=8d6208e0-d44a-43ff-b272-99d77e5686ba&sc_channel=ps&ef_id=Cj0KCQiA9OnJBhD-ARIsAPV51xNoT7JZG7As6erHs2W1NjBtz_01YqYg-iZ49v7w6MEGWEXprHoPWtkaAvnZEALw_wcB:G:s&s_kwcid=AL!4422!3!724218586019!e!!g!!amazon%20sagemaker%20ai!19852662230!170020191325&gad_campaignid=19852662230&gbraid=0AAAAADjHtp_gJXWgoW0NCfoG_UDRlrMLP&gclid=Cj0KCQiA9OnJBhD-ARIsAPV51xNoT7JZG7As6erHs2W1NjBtz_01YqYg-iZ49v7w6MEGWEXprHoPWtkaAvnZEALw_wcB) 带你走一遍代码。

## Meta 的 Llama 4：释放 1M+ 上下文窗口的价值

[Llama 4](https://ai.meta.com/blog/llama-4-multimodal-intelligence/) 是 Meta 最新的[大语言模型（LLM）](https://aws.amazon.com/what-is/large-language-model/)家族，以上下文窗口能力和多模态智能见长。两个模型都采用[混合专家（MoE）](https://en.wikipedia.org/wiki/Mixture_of_experts)架构以提升效率，面向多模态输入设计，并针对驱动 agentic 系统和复杂工作流做了优化。其中的旗舰型号 Meta Llama 4 Scout 支持 1000 万 token 的上下文窗口——行业首创——使模型能在单个 prompt 内处理和推理大量数据。

这支撑了诸如总结整座图书馆的书籍、分析庞大的代码库、跨数千份文档做整体性研究，以及在长交互中保持深而持久的对话上下文等应用。Llama 4 Maverick 型号同样提供 100 万 token 的窗口，适合要求严苛的语言、视觉和跨文档任务。这些超长上下文窗口为高级摘要、记忆保持以及复杂多步工作流打开了新的可能性，使 Meta 的 Llama 4 成为同时适用于研究和企业级 AI 应用的多面手方案

| **模型名称** | **上下文窗口** | **关键能力与用例** |
| --- | --- | --- |
| **Meta 的** **Llama 4 Scout** | 10M token（在 Amazon Bedrock 上最多 3.5M） | 超长文档处理、整本书或整个代码库的摄入、大规模摘要、长对话记忆、高级研究 |
| **Meta 的** **Llama 4 Maverick** | 1M token | 大上下文多模态任务、高级文档与图像理解、代码分析、全面问答、稳健摘要 |

## 使用 Strands Agents 的 agentic 工作流简介

本文演示的视频处理方案用六个专用 agent 实现了一套 agent 工作流。每个 agent 承担特定角色，把输出交给下一个 agent，从而完成流程中的多步任务。这与深度研究架构采用同样的分析方式：其中有一个 orchestrator agent 负责协调其他 agent 协同工作的过程。这一概念在 Strands Agents 中称为 *[Agents as Tools](https://strandsagents.com/latest/documentation/docs/user-guide/concepts/multi-agent/agents-as-tools/)*。

这种 AI 系统中的架构模式，可以把专用的 AI agent 包装成可被其他 agent 调用的函数（工具）。这套 agentic 工作流包含以下专用 agent：

- `Llama4_coordinator_agent` – 可以访问其他 agent，并启动从帧提取 agent 到摘要生成的整个流程
- `s3_frame_extraction_agent` – 使用 OpenCV 库从视频中提取有意义的帧，处理视频文件操作的复杂性
- `s3_visual_analysis_agent` – 具备必需的工具，通过分析每张图像来处理帧，并把结果作为 JSON 文件存到指定的 [Amazon Simple Storage Service](https://aws.amazon.com/s3/)（Amazon S3）存储桶
- `retrieve_json_agent` – 以 JSON 文件的形式取回对帧的分析结果
- `c_temporal_analysis_agent` – 通过按时间顺序分析图像，专门处理视频帧中时序的 AI agent
- `summary_generation_agent` – 专门为图像时序分析生成摘要

## 用 Agents as Tools 把视频分析方案模块化

流程从 orchestrator agent 开始，它使用 Meta 的 Llama 4 实现，负责在专用 agent 之间协调沟通和任务分派。这个中心 agent 启动并监控视频处理 pipeline 的每一步。利用 Strands Agents 中的 Agents as Tools 模式，每个专用 agent 都被包装成可调用的函数（工具），从而实现 agent 之间的无缝通信和模块化编排。这种层级化的分派模式让 coordinator agent 能动态调用各领域专用的 agent，与人协作团队运作的方式如出一辙。

- **可定制性** – 每个 agent 的 system prompt 都可以单独调优，以便在其专门任务上达到最佳表现。
- **关注点分离** – 每个 agent 专注于自己最擅长的事，使系统更易于开发和维护。
- **工作流灵活性** – coordinator agent 可以为不同的用例按不同顺序编排各个组件。
- **可扩展性** – 各组件可以按各自具体的性能需求单独优化。
- **可扩展性** – 引入新的专用 agent 即可增加新能力，而不干扰已有的 agent。

通过把 agent 变成工具，我们得到了可以组合起来解决复杂视频理解任务的积木，也展示了如何用 Strands Agents 支撑具备专用 LLM 推理能力的多 agent 系统。我们来仔细看看 `coordinator_agent`：

@tool
def process_s3_analysis_json(s3_uri: str) -> str:
    """Retrieve JSON from S3 and extract only the analysis text"""
    try:
        # Parse S3 URI and download JSON
        s3_parts = s3_uri.replace('s3://', '').split('/', 1)
        bucket = s3_parts[0]
        key = s3_parts[1]
       
        s3_client = boto3.client('s3')
        response = s3_client.get_object(Bucket=bucket, Key=key)
        json_content = response['Body'].read().decode('utf-8')
        
        # Parse and extract text
        data = json.loads(json_content)
        
        # Handle both formats
        if 'analyses' in data:
            analyses = data['analyses']
        elif 'sessions' in data:
            analyses = [session['data'] for session in data['sessions'] if 'data' in session]
		else:
            return "Error: No 'analyses' or 'sessions' field found"
        
        # Extract text only
        text_only = []
        for analysis in analyses:
            if 'analysis' in analysis:
                text = analysis['analysis']
                if not text.startswith("Failed:"):
                    text_only.append(text)
        
        # Clean up local file
        local_file = "visual_analysis_results.json"
		if os.path.exists(local_file):
            os.remove(local_file)
        
        return "\n".join(text_only)
    except Exception as e:
        return f"Error processing {s3_uri}: {str(e)}"

为避免将来产生不必要的费用，请清理你作为本方案一部分创建的资源：要删除 Amazon S3 文件：

- 打开 [AWS Management Console](https://console.aws.amazon.com/)
- 导航到 Amazon S3
- 找到并选择你的 [Amazon SageMaker](https://aws.amazon.com/sagemaker/) 存储桶
- 选择你上传的视频文件
- 选择 **Delete** 并确认

要停止并移除 SageMaker notebook：

- 在 AWS Management Console 中进入 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/ai/)
- 选择 **Notebook instances**
- 选择你的 notebook
- 如果它正在运行，选择 **Stop**
- 停止之后，选择 **Delete**

## 结论

本文说明了把 Strands Agents SDK 与 Meta 的 Llama 4 模型和 Amazon Bedrock 基础设施结合起来，如何支撑构建高级的多 agent 视频处理工作流。通过使用高度专用的 agent，并让它们借助 Agents as Tools 模式通信协作，开发者可以把帧提取、视觉分析、时序推理和摘要这类复杂任务模块化。这种关注点分离提升了可维护性、可定制性和可扩展性，同时让跨 AWS 服务的集成变得无缝。我们鼓励开发者探索并扩展这一架构：增加新的专用 agent，把工作流适配到更多样的用例——从智慧城市、工业自动化到媒体内容管理。Strands Agents、Meta 的 Llama 4 与 Amazon Bedrock 的组合，为打造能应对现代业务环境复杂性的自主、有韧性的 AI 方案奠定了坚实基础。

要开始上手，请访问 [Meta-Llama-on-AWS agents 项目的官方 GitHub 仓库](https://github.com/aws-samples/Meta-Llama-on-AWS/tree/main/agents/strands)查看代码示例和部署说明。要进一步了解如何用 Strands Agents 构建，请参阅 [Strands Agents 文档](https://strandsagents.com/latest/documentation/docs/)，它以代码优先的方式介绍了如何集成模块化的 AI agent。关于多 agent AI 架构与编排的更多背景，AWS 关于 [agent 互操作](https://aws.amazon.com/blogs/opensource/open-protocols-for-agent-interoperability-part-1-inter-agent-communication-on-mcp/)和[自主 agent 框架](https://aws.amazon.com/blogs/industries/agentic-ai-for-ran-optimization-pathway-to-autonomous-network-level-5/)的博文提供了有价值的指引，塑造着智能系统的未来。
