# Amazon Nova Act SDK（预览版）：浏览器自动化 agent 走向生产之路

2025 年初，我们以研究预览的形式推出了 [Amazon Nova Act SDK](https://labs.amazon.science/blog/nova-act)，帮助开发者构建能够在网页浏览器中可靠完成任务的 agent。现在，我们很高兴能与客户一起，在受限预览（limited preview）中把他们的 agent 推向生产环境：借助新的 AWS 集成，包括用于安全凭证管理的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）、用于数据存储与策略控制的 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3），以及用于可扩展的云端浏览器执行的新 [Amazon Bedrock AgentCore Browser Tool](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-sandbox-tool.html)。

在本篇博文中，我们将介绍 Amazon Nova Act SDK 的独特之处、它的工作方式，以及各行各业的团队如何已经在用它大规模自动化基于浏览器的工作流。

## 传统自动化业务流程的挑战

许多日常业务操作都需要浏览器，例如提交休假申请、处理发票、访问供应商门户，或查看仪表盘。API 覆盖不足往往意味着这些工作流只能靠人工完成：团队在多个标签页之间复制粘贴数据、沿着多步流程操作、在无数界面里一路点击，才能把活干完。

传统的基于规则的浏览器自动化框架在动态的 Web 环境中常常遇到麻烦。团队花在持续维护上的时间可能比新建自动化还多，因为页面结构的变化（例如新增了表单字段或下拉选项）就会让脆弱的 selector 失效。最重要的是，这类框架难以规模化。如果同一个用例要在 50 个不同网站上执行（例如在各州网站上进行专业执照核验），团队就必须构建 50 套针对具体站点的自动化，因为基于规则的框架无法泛化。

作为人类，我们执行任务的能力可以跨不同工具和界面迁移。例如，一旦你会用 Outlook 起草邮件，在 Gmail 里做同样的事也很轻松——即便你以前从未用过 Gmail。大语言模型（LLM）在数百万个 UI 示例上训练过，因此有望为 AI agent 建立类似的模式识别能力。它们通过理解语言、遵循指令和跨领域推理，把我们带到了今天这一步——驱动了聊天、摘要、编码 copilot 等等。现在，我们正进入生成式 AI 的下一阶段：一个以行动为中心的阶段。Agentic AI 建立在 LLM 的基础之上，从理解走向执行。这类系统被设计用来完成动态的、多步的工作流——比如填写复杂表单、与不断变化的 UI 元素交互，或大规模执行真实世界的业务任务。Agentic AI 并不取代 LLM——它是对 LLM 的延伸，释放出新的自动化能力，让我们在企业环境中离真正把任务做完更近一步。

## 借助 Amazon Nova Act SDK 实现 Agentic AI

借助 Amazon Nova Act SDK，你可以构建并部署由 Amazon Nova Act 模型驱动的可靠浏览器 agent，该模型专为 agentic AI 打造并做了微调。它通过强化学习和大量领域内的浏览器交互数据训练而成，能够精确地执行逐步式工作流。在最新版本中，我们通过 AWS 集成扩展了这些能力，让你可以把 agent 从原型带到生产环境。你只需一条命令即可安装 SDK，用 Python 与自然语言编写 agent，实时调试，并直接集成到持续集成与持续交付（CI/CD）流水线中。凭借现已通过 AWS 提供的企业级安全性、可观测性与基础设施，Amazon Nova Act SDK 为希望构建能大规模行动并交付成果的 agent 的团队，提供了一条快速、灵活的路径。你可以用 Amazon Nova Act SDK 自动化那些传统脚本或通用模型不够可靠、不够可扩展的真实工作流。你可以用一条命令安装它，用 Python 与自然语言的组合编写 agent，在工作流运行时调试，并通过 CI/CD 流水线部署。

Amazon Nova Act SDK 还可与新的 Amazon Bedrock AgentCore Browser Tool 集成，后者是一个快速、安全的云端浏览器，让 AI agent 能够大规模地与网站交互。它包含企业级的安全特性，包括虚拟机级别的隔离和联邦身份集成。该工具通过实时查看、[AWS CloudTrail](https://aws.amazon.com/cloudtrail) 日志记录和会话回放提供内置的可观测性，用于排障、保持质量并支撑合规。

## Amazon Nova Act SDK 的优势

Amazon Nova Act SDK 可靠、部署快，并且是为安全的大规模浏览器自动化用例而构建的。本节将更详细地讨论该 SDK 的部分优势。

### 可靠性：以高准确率与可重复性构建稳健的浏览器自动化

借助 Amazon Nova Act SDK，开发者可以把复杂工作流拆解成可靠的原子命令（例如收集某个网页上的所有表单元素，并返回一个包含该表单全部必填字段的字符串）。它支持在需要时为这些命令补充详细指令（例如关掉所有弹窗横幅）、支持调用 API，还可以选择通过 Playwright 交替进行直接的浏览器操作以提升可靠性（例如输入密码时）。开发者可以穿插 Python 代码——比如测试、断点、断言，或用于并行的线程池——来优化性能，尤其因为即便最快的 agent 也受网页加载时间制约。在最新版本中，Amazon Nova Act SDK 在早期企业工作流中已经展现出超过 90% 的可靠性，涵盖自动化质量保证、复杂表单处理和流程执行。推理与恢复能力的改进，帮助 agent 适应不断变化的 UI，并以一致、准确的方式完成复杂序列。

### 上市速度：以天而非周为单位从原型走向生产

Amazon Nova Act SDK 旨在帮助你快速构建自动化，而不必依赖脆弱的脚本。你可以用一条命令安装 SDK。你可以用 Python、自然语言或两者兼用来定义 agent。你可以一边运行流程一边调试、检查 DOM、在步骤之间暂停，并快速迭代。Amazon Nova Act SDK 支持以下特性：

- 基于 Git 的 CI/CD 流水线
- 可复用的 agent 模块
- 面向敏感任务（例如密码输入）的 Playwright 回退
- 用于快速执行的线程与并行化

你不必改造基础设施，也不必重建内部工具。用 Amazon Nova Act 构建的 agent 可以融入现有的开发工作流，让你快速从试验走向生产。

### 安全性：由 AWS 支撑，部署值得信赖的自动化

Amazon Nova Act SDK 与 IAM 集成以实现访问控制，对模型的访问与其他 AWS 服务的访问一样进行管理。它支持在 macOS、Linux、Windows 和 WSL2 上执行。运行环境相互隔离，并且对敏感输入与输出支持加密。Amazon Nova Act SDK 的设计目标就是在企业环境中工作——具备生产系统所要求的可靠性、可观测性与安全性。

## Amazon Nova Act SDK 能在哪些地方带来影响

### 自动化数据录入与表单填写

Amazon Nova Act SDK 通过自动化表单提交、上传和更新，减少在 CRM、HR 工具和财务平台等基于 Web 的系统中的重复性人工输入。在医疗健康领域，工作人员要协助参保人处理复杂的、各州不同的福利申请。公共部门的个案工作者也要在多个系统之间反复录入家庭数据。Amazon Nova Act SDK 能可靠地处理这些动态流程——无需脆弱的脚本或定制代码，就能穿行于不断变化的字段、下拉框和弹窗之间。
