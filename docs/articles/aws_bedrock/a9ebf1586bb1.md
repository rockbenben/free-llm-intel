# 使用 Amazon Bedrock Custom Model Import 部署 DeepSeek-R1 蒸馏版 Llama 模型

开放的基础模型（FM）已成为[生成式 AI](https://aws.amazon.com/ai/generative-ai/)创新的基石，使组织能够构建和定制 AI 应用，同时保持对成本和部署策略的控制。通过提供高质量、公开可用的模型，AI 社区促进了快速迭代、知识共享以及兼具成本效益的解决方案，让开发者和终端用户共同受益。[DeepSeek AI](https://www.deepseek.com/) 是一家专注于推进 AI 技术的研究公司，已成为这一生态的重要贡献者。其 [DeepSeek-R1](https://github.com/deepseek-ai/DeepSeek-R1) 模型代表了一个大语言模型（LLM）系列，旨在处理从代码生成到通用推理的广泛任务，同时保持颇具竞争力的性能和效率。

[Amazon Bedrock Custom Model Import](https://aws.amazon.com/bedrock/custom-model-import/) 让你可以通过单一的无服务器统一 API，把自定义模型与现有 FM 一并导入和使用。你可以按需访问导入的自定义模型，无需管理底层基础设施。将受支持的自定义模型与 Knowledge Bases、Guardrails 和 Agents 等 Bedrock 原生工具和功能集成，可加速你的生成式 AI 应用开发。

在本文中，我们探讨如何使用 Amazon Bedrock Custom Model Import 部署 DeepSeek-R1 的蒸馏版本，让希望在安全、可扩展的 AWS 基础设施上以高性价比获得最先进 AI 能力的组织能够使用它们。

## DeepSeek-R1 的蒸馏变体

DeepSeek AI 以 DeepSeek-R1 为基础，基于 Meta 的 Llama 和 Qwen 两种架构创建了一系列蒸馏模型，参数量从 1.5B 到 70B 不等。蒸馏过程是把更大的 DeepSeek-R1 模型当作教师，训练更小、更高效的模型来模仿它的行为和推理模式，也就是把 671B 参数模型的知识与能力迁移到更紧凑的架构中。由此得到的蒸馏模型，例如 DeepSeek-R1-Distill-Llama-8B（基座模型为 [Llama-3.1-8B](https://huggingface.co/meta-llama/Llama-3.1-8B)）和 DeepSeek-R1-Distill-Llama-70B（基座模型为 [Llama-3.3-70B-Instruct](https://huggingface.co/meta-llama/Llama-3.3-70B-Instruct)），在性能与资源需求之间提供了不同的权衡。虽然与原始 671B 模型相比，蒸馏模型在推理能力上可能有所下降，但它们显著提升了推理速度并降低了计算成本。例如，8B 版本这类较小的蒸馏模型能更快处理请求、消耗更少资源，在生产部署中更具成本效益；而 70B 模型这类较大的蒸馏版本则保持更接近原始模型的性能，同时仍带来可观的效率提升。

## 解决方案概览

在本文中，我们演示如何使用 Amazon Bedrock Custom Model Import 部署 DeepSeek-R1 模型的蒸馏版本。我们重点导入当前受支持的变体 DeepSeek-R1-Distill-Llama-8B 和 DeepSeek-R1-Distill-Llama-70B，它们在性能与资源效率之间达到了较优平衡。你可以从 [Amazon Simple Storage Service](https://aws.amazon.com/s3)（Amazon S3）或 [Amazon SageMaker AI](https://aws.amazon.com/sagemaker/) 模型仓库导入这些模型，并通过 Amazon Bedrock 在完全托管、无服务器的环境中完成部署。下图展示了端到端流程。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/29/ML18202-image001.png)

在这一工作流中，存放在 Amazon S3 中的模型产物被导入 Amazon Bedrock，随后由后者自动处理模型的部署与扩缩容。这种无服务器方式免去了基础设施管理，同时提供企业级的安全性与可扩展性。

你可以使用 Amazon Bedrock 控制台，通过图形界面并按照本文的说明进行部署；也可以改用[以下 notebook](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/custom-models/import_models/llama-3/DeepSeek-R1-Distill-Llama-Noteb.ipynb)，借助 Amazon Bedrock SDK 以编程方式部署。

## 先决条件

你应当具备以下先决条件：

- 一个可访问 Amazon Bedrock 的 AWS 账户。
- 适用于 Amazon Bedrock 和 Amazon S3 的 [AWS Identity and Access Management](https://aws.amazon.com/iam/)（IAM）角色与权限。更多信息请参阅[为模型导入创建服务角色](https://docs.aws.amazon.com/bedrock/latest/userguide/model-import-iam-role.html)。
- 一个准备好的 S3 存储桶，用于存放自定义模型。更多信息请参阅[创建存储桶](https://docs.aws.amazon.com/AmazonS3/latest/userguide/create-bucket-overview.html)。
- 充足的本地存储空间：8B 模型至少需要 17 GB，70B 模型至少需要 135 GB。

## 准备模型包

请按以下步骤准备模型包：

- 从 Hugging Face 下载 DeepSeek-R1-Distill-Llama 模型产物：根据你要部署的模型，从以下链接之一下载：  [https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Llama-8B/tree/main](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Llama-8B/tree/main) [https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Llama-70B/tree/main](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Llama-70B/tree/main)

更多信息，可参考 Hugging Face 的[下载模型](https://huggingface.co/docs/hub/en/models-downloading#faster-downloads)或[从 hub 下载文件](https://huggingface.co/docs/huggingface_hub/en/guides/download)说明。

通常你需要以下文件：

- 模型配置文件：`config.json`；tokenizer 文件：`tokenizer.json` 和 `tokenizer_config.json`；`.safetensors` 格式的模型权重文件

- 将这些文件上传到 S3 存储桶中的一个文件夹，且该存储桶位于你计划使用 Amazon Bedrock 的同一 AWS 区域。请记下你所使用的 S3 路径。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/29/ML18202-image003.png)

## 导入模型

请按以下步骤导入模型：

- 在 Amazon Bedrock 控制台中，在导航窗格的 **Foundation models** 下选择 **Imported models**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/29/ML18202-image005.png)

- 选择 **Import model**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/29/ML18202-image007.png)

- 在 **Model name** 中，为你的模型输入名称（建议在名称中采用版本方案，以便跟踪导入的模型）。
- 在 **Import job name** 中，为你的导入作业输入名称。
- 在 **Model import settings** 中，选择 **Amazon S3 bucket** 作为导入源，并输入你之前记下的 S3 路径（以 `s3://<your-bucket>/folder-with-model-artifacts/` 的形式提供完整路径）。
- 在 **Encryption** 中，可选择自定义加密设置。
- 在 **Service access role** 中，选择创建新的 IAM 角色或提供你自己的角色。
- 选择 **Import model**。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/29/ML18202-image009.png)

导入模型需要几分钟时间，具体取决于所导入的模型（例如，Distill-Llama-8B 模型可能需要 5–20 分钟完成）。

![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/29/ML18202-image013-1.png)

## 测试导入的模型

导入模型后，你可以使用 Amazon Bedrock Playground 或直接通过 Amazon Bedrock 的调用 API 来测试它。要使用 Playground，请按以下步骤操作：

- 在 Amazon Bedrock 控制台中，在导航窗格的 **Playgrounds** 下选择 **Chat / Text**。
- 在模型选择器中，选择你导入的模型名称。
- 按需调整推理参数，并写下你的测试提示词。例如：
`<｜begin▁of▁sentence｜><｜User｜>Given the following financial data: - Company A's revenue grew from $10M to $15M in 2023 - Operating costs increased by 20% - Initial operating costs were $7M Calculate the company's operating margin for 2023. Please reason step by step, and put your final answer within \\boxed{}<｜Assistant｜>`

由于我们在 playground 中使用的是导入的模型，必须包含 “beginning_of_sentence” 和 “user/assistant” 标签，才能为 DeepSeek 模型正确格式化上下文；这些标签帮助模型理解对话结构并给出更准确的回答。如果你采用[以下 notebook](https://github.com/aws-samples/amazon-bedrock-samples/blob/main/custom-models/import_models/llama-3/DeepSeek-R1-Distill-Llama-Noteb.ipynb)中的编程方式，那么在配置模型时会自动处理这一点。

- 查看提供的模型响应和指标。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/01/30/ML18202-updated.jpg)

**注意**：首次调用模型时，如果遇到 `ModelNotReadyException` 错误，SDK 会自动以指数退避重试请求。恢复时间取决于按需资源池规模和模型大小。你可以使用 [AWS SDK for Python (Boto3)](https://aws.amazon.com/sdk-for-python/) 的 Config 对象自定义重试行为。更多信息请参阅[处理 ModelNotReadyException](https://docs.aws.amazon.com/bedrock/latest/userguide/invoke-imported-model.html#handle-model-not-ready-exception)。

## 定价

Custom Model Import 让你可以在 Amazon Bedrock 中针对受支持的架构使用自己的自定义模型权重，并通过 On-Demand 模式在完全托管的方式下与 Amazon Bedrock 托管的 FM 一并提供服务。Custom Model Import 不对模型导入收费，推理费用按两个因素计费：活跃模型副本的数量及其活跃时长。

计费以 5 分钟为一个窗口，从每个模型副本首次成功调用开始计算。每个模型副本每分钟的价格取决于架构、上下文长度、区域和计算单元版本等因素，并按模型副本规模分级。托管所需的 Custom Model Units 取决于模型的架构、参数数量和上下文长度，例如 Llama 3.1 8B 128K 模型需要 2 个 Unit，而 Llama 3.1 70B 128K 模型需要 8 个 Unit。

Amazon Bedrock 会自动管理扩缩容，默认根据你的使用模式维持 0 到 3 个模型副本（可通过 Service Quotas 调整）。如果 5 分钟内没有调用，它会缩容到 0，并在需要时再扩容，不过这可能会带来数十秒的冷启动延迟。如果推理量持续超过单副本的并发上限，就会增加额外副本。每个副本的最大吞吐量和并发数在导入时确定，取决于输入/输出 token 配比、硬件类型、模型大小、架构和推理优化等因素。

考虑以下定价示例：一位应用开发者在 us-east-1 区域导入了一个 8B 参数规模、序列长度 128K 的定制 Llama 3.1 类型模型，并在 1 个月后删除该模型。这需要 2 个 Custom Model Units。因此，每分钟价格为 $0.1570，当月模型存储费用为 $3.90。

更多信息请参阅 [Amazon Bedrock 定价](https://aws.amazon.com/bedrock/pricing/)。

## 基准测试

DeepSeek [公布了基准测试](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Llama-8B#4-evaluation-results)，将其蒸馏模型与原始 DeepSeek-R1 及基础 Llama 模型进行对比，这些结果可在模型仓库中获取。基准测试显示，视任务不同，DeepSeek-R1-Distill-Llama-70B 保持了原始模型 80-90% 的推理能力，而 8B 版本在资源需求显著降低的情况下达到 59-92% 的性能。两个蒸馏版本在特定推理任务上都表现出相对于对应基础 Llama 模型的提升。

## 其他注意事项

在 Amazon Bedrock 中部署 DeepSeek 模型时，请考虑以下几个方面：

- 模型版本管理至关重要。由于 Custom Model Import 每次导入都会创建唯一的模型，请在模型名称中实施清晰的版本策略，以跟踪不同版本和变体。
- 当前支持的模型格式以基于 Llama 的架构为主。尽管 DeepSeek-R1 蒸馏版本表现出色，AI 生态仍在快速演进。请关注 Amazon Bedrock 模型目录，因为平台上会不断出现新架构和更大的模型。
- 请仔细评估你的用例需求。尽管 DeepSeek-R1-Distill-Llama-70B 这类更大的模型性能更好，但对许多应用而言，8B 版本可能以更低的成本提供足够的能力。
- 考虑实施监控与可观测性。[Amazon CloudWatch](https://aws.amazon.com/cloudwatch) 为导入的模型提供指标，帮助你跟踪使用模式和性能。你可以使用 [AWS Cost Explorer](https://aws.amazon.com/aws-cost-management/aws-cost-explorer/) 监控成本。
- 从较低的并发配额起步，并根据实际使用模式逐步提升。每个账户默认三个并发模型副本的限制适合大多数初期部署。

## 结论

Amazon Bedrock Custom Model Import 让组织能够使用 DeepSeek-R1 蒸馏版本等强大的公开可用模型，同时享受企业级基础设施。Amazon Bedrock 的无服务器特性消除了管理模型部署与运维的复杂性，让团队可以专注于构建应用而非基础设施。借助自动扩缩容、按使用量付费以及与 AWS 服务的无缝集成等功能，Amazon Bedrock 为 AI 工作负载提供了可用于生产的环境。DeepSeek 创新的蒸馏方法与 Amazon Bedrock 托管基础设施的结合，在性能、成本和运营效率之间实现了较优平衡。组织可以从小模型起步并按需扩展，同时保持对模型部署的完全控制，并享受 AWS 的安全与合规能力。

能够在专有 FM 与开放 FM 之间选择，使组织可以根据自身具体需求灵活优化。开放模型支持高性价比的部署，并可完全控制模型产物，因此非常适合定制化、成本优化或模型透明度至关重要的场景。这种灵活性结合 Amazon Bedrock 的统一 API 和企业级基础设施，让组织能够构建可随需求演进而调整的弹性 AI 策略。

更多信息请参阅 [Amazon Bedrock 用户指南](https://docs.aws.amazon.com/bedrock/latest/userguide/what-is-bedrock.html)。
