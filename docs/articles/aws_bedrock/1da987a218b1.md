# 在 AWS 上通过 Smartsheet MCP 为 AI 代理提供工作流上下文

只有当 AI 代理能够对组织内真实开展的工作采取行动时，它才最有用。运行项目与运营涉及复杂的跨职能任务，例如更新项目时间线、重新分配任务、呈现状态。AI 代理可以在不让任何人切换工具的情况下帮你完成这些工作。[Smartsheet](https://www.smartsheet.com/) 已推出一款正式可用（generally available）的 Model Context Protocol（MCP）Server。

借助 [Smartsheet MCP Server](https://developers.smartsheet.com/ai-mcp/smartsheet/mcp-server)，AI 助手可以通过标准化协议读取、写入和管理 Smartsheet 数据。该协议涵盖 40 多个工具，用于浏览、创建和管理 sheet、行、列与自动化流程。你可以直接用自然语言更新任务状态、创建行、修改项目结构。

本文介绍把它接入既有工作流的两种方式。[Amazon Quick](https://aws.amazon.com/quick/) 是面向业务用户、项目经理和运营团队的代理式 AI 工作空间。他们可以用自然语言提问、更新 sheet、构建仪表盘，而无需编写代码。[Kiro](https://kiro.dev/) 是一款代理式 IDE，开发者可通过 MCP 连接 Smartsheet，在不离开编码工作流的情况下查阅项目规格、更新任务状态、跟踪依赖关系。

## 使用 Amazon Quick 与 Kiro 管理 Sprint

设想一个在 Smartsheet 中跟踪 sprint 的软件工程团队。任务、负责人、状态和阻塞项都存放在一张项目 sheet 里。对同一个团队来说，两条路径分别如下：

当项目经理这样的用户想查看本周有哪些 sprint 任务被阻塞时，可以用自然语言询问 Amazon Quick。Amazon Quick 的对话代理会查询 Smartsheet MCP Server，取出相关行，并给出包含负责人姓名和截止日期的摘要。该响应直接基于 Smartsheet 的实时数据生成，无需另外构建报表或仪表盘。

对于正在修复 bug 或推进功能的开发者，他们可以让 Kiro 拉取当前的 sprint sheet，并显示分配给自己的、处于打开状态的 backend 任务。Kiro 通过 MCP 查询 Smartsheet，并就地列出清单。修复提交后，Kiro 的 hook 会自动把对应行的状态更新为 Complete。

## 前提条件

Smartsheet MCP Server 提供精确结构化的上下文，包括行关系、列类型、单元格历史和评论。由此得到的负载体积对 token 更友好，而不是直接返回原始 API 负载。当你在一个项目组合上运行数百次 AI 辅助查询时，这一工程决策会累积为更低的成本和更好的延迟。想了解 Smartsheet 如何在 AWS 上构建其远程 MCP server，参见[Smartsheet 如何在 AWS 上构建远程 MCP server](https://aws.amazon.com/blogs/machine-learning/how-smartsheet-built-a-remote-mcp-server-on-aws/)。

在把 Smartsheet MCP Server 连接到 Amazon Quick 与 Kiro 之前，请确认已具备以下条件：

- 一个处于活跃状态的 AWS 账户，并拥有针对所连接服务（Amazon Quick 或 Kiro）的相应 AWS Identity and Access Management（IAM）权限
- 一个 Business、Enterprise 或 AWM 方案下的 Smartsheet 账户。
- 一个 Smartsheet Personal Access Token；如果你的客户端支持 OAuth 流程，也可以使用 OAuth 凭证。
- 对于 Amazon Quick：在你的 Amazon Quick 账户中拥有 Author 或更高权限。
- 对于 Kiro：从 [kiro.dev](https://kiro.dev) 安装 Kiro IDE，且环境中可用 `Node.js`。

Smartsheet MCP Server 在三个区域端点提供服务。它使用 Streamable HTTP 传输（MCP 规范版本 2025-06-18 和 2025-03-26），并通过 OAuth 2.0 或 Personal Access Token 进行认证。

- 美国商用区：https://mcp.smartsheet.com。
- 欧盟：https://mcp.smartsheet.eu。
- 澳大利亚：https://mcp.smartsheet.au。

两种方案暴露相同的 Smartsheet 工具集。该选哪个，取决于你的工作在哪里完成：

如果你需要一个完全托管、全组织可用、整个团队都能使用的方案，就选 Amazon Quick：无需注册应用，只有预置好的 OAuth，并且能在企业内的知识工作者之间扩展。

如果你是开发者、想要轻量的方案，就选 Kiro：不需要基础设施，只需一个配置文件和一份 personal access token，且范围限定在你自己的工作流内。

Amazon Quick 让该集成在整个组织内可用，从项目经理、运营团队一直到在 Smartsheet 中管理工作的业务用户。

## Kiro 集成

当开发者希望 Smartsheet 的项目上下文直接出现在开发环境中、与代码并列、不必切换上下文时，[Kiro](https://kiro.dev/docs/mcp/) 就是合适的选择。

Kiro 围绕规格驱动开发（spec-driven development）构建。它把高层提示转化为结构化规格，再转化为可工作的代码、文档和测试。MCP server 是 Kiro 获取现实世界上下文的途径：它连接到文档、数据库、API 和企业系统，让代理扎根于实时数据，而不是训练时的知识。

Kiro 有一项名为 powers 的功能，是一键安装的打包件，把精选的 MCP server 与 steering 文件和 hooks 打包在一起。它让 Kiro 编码代理开箱即获得一项新能力。对于 Smartsheet，配置连接只需一个 JSON 配置块，此后 Kiro 代理就能在开发工作流中引用实时的项目数据。

要把 Smartsheet MCP Server 连接到 Kiro，把它加入你的 Kiro MCP 配置（工作区范围对应 `.kiro/settings/mcp.json`）。完整演练参见 [Kiro 与 MCP Server 入门](https://repost.aws/articles/ARuX8rkojgSx-TYCc65JyAOw/getting-started-with-kiro-and-mcp-servers-connect-your-ai-ide-to-real-world-tools)：

```
{
  "mcpServers": {
    "smartsheet-us": {
      "type": "http",
      "url": "https://mcp.smartsheet.com",
      "headers": {
        "Authorization": "Bearer <SMARTSHEET_API_TOKEN>"
      }
    }
  }
}
```

该配置使用 Personal Access Token（API key）方式。生产部署建议使用 OAuth。

在环境中把 `SMARTSHEET_API_TOKEN` 设为你的 Smartsheet Personal Access Token。Kiro 在启动时会把 MCP server 作为后台进程加载。初始化完成后，Smartsheet 工具在 Kiro 代理的所有模式下都可用：对话、规格规划，以及基于 hooks 的自动化。完整细节见 [Smartsheet MCP Server 文档](https://developers.smartsheet.com/api/smartsheet/ai-integration/mcp-server)。

此后，Kiro 就能在开发工作流中引用 Smartsheet 数据：

## 企业治理

对于在受监管或企业环境中部署的构建者来说，Smartsheet MCP Server 的安全模型建立在与 Smartsheet REST API 相同的基础设施和权限层之上。它并不是一个新的信任边界：

- **OAuth 2.0 与 Personal Access Token 认证**：选择你的 MCP 客户端支持的认证方式。
- **用户级权限约束**：代理只能访问通过认证的用户有权查看的数据。无法通过自然语言提示进行权限提升。
- **组织级 AI 管控**：系统管理员可以全局开启或关闭 AI 功能。写入类工具的访问权限可按用户组配置。
- **Streamable HTTP 传输**：防火墙白名单按完全限定域名（FQDN）（mcp.smartsheet.com）配置，而不是按 IP 地址。

对合规架构师而言，MCP Server 不存储提示，提示内容始终留在 AI 客户端与模型之间。Smartsheet 只能看到结构化的工具调用及其结果。

## 清理

如果你照着本文演练过，之后想移除该集成，可以按下面的方法撤销每条路径：

### Amazon Quick

- 在 Amazon Quick 控制台中，进入 **Connectors**。
- 选择你的 Smartsheet 连接器。
- 选择 **Delete** 移除该连接。这会吊销 OAuth token，并停止代理对 Smartsheet 数据的访问。

### Kiro

- 打开你的 MCP 配置文件（`.kiro/settings/mcp.json`）。
- 从 `mcpServers` 对象中删除 `smartsheet-us` 条目。
- 重启 Kiro 以卸载该 server。

## 后续步骤

关于该 server 如何工作的背景，参见[Smartsheet 如何在 AWS 上构建远程 MCP server](https://aws.amazon.com/blogs/machine-learning/how-smartsheet-built-a-remote-mcp-server-on-aws/)。把 Smartsheet MCP Server 连接到你所选的系统之后，我们建议尝试以下四项操作：

你可以让对话代理监控你的活跃项目 sheet，找出标记为 Blocked 或 At Risk 的行。你也可以让它用一条讨论评论给项目添加标注，并通过你惯用的渠道向团队交付结构化摘要。这会是一个把 `get_sheet_summary`、`search` 和 `create_discussion_on_row` 串联起来的示例工作流。

代理还可以通过 Smartsheet MCP Server 取回数据，在你的事项跟踪器与 Smartsheet 项目计划之间核对任务状态。它可以标出两者之间的偏差，并更新受影响的行，依次使用 `get_sheet_summary`、`get_columns`、`update_rows` 和 `create_discussion_on_row`。

你也可以尝试把报表和仪表盘中的项目健康信号汇总起来。借助 `list_reports`、`get_report`、`list_dashboards`、`get_dashboard` 和 `search`，它可以无需人工收集数据就生成结构化简报。

最后，你可以让代理在每次写入之后都跟一条讨论评论，说明改了什么、为什么改。通过 `update_rows` 与 `create_discussion_on_row` 的组合，这在 Smartsheet 内部形成一条人类可读的审计轨迹。

这四种模式在前面两条路径上都适用：Amazon Quick 面向业务用户的工作流，Kiro 面向由开发者发起的操作。
