# 使用语言 embedding 在 Amazon Bedrock 上实现零样本分类与语义搜索

在本文中，我们讨论什么是 embedding，演示如何实际使用语言 embedding，并探讨如何用它们添加零样本分类和语义搜索等功能。随后我们会使用 [Amazon Bedrock](https://aws.amazon.com/bedrock/) 和语言 embedding，把这些功能加入一个[简易信息聚合（RSS）](https://en.wikipedia.org/wiki/RSS)聚合器应用。

Amazon Bedrock 是一项完全托管的服务，通过 API 提供来自领先 AI 初创公司和 Amazon 的[基础模型](https://aws.amazon.com/what-is/foundation-models/)（FM），因此你可以从广泛的 FM 中挑选最适合自己用例的那一个。Amazon Bedrock 提供无服务器体验，你可以快速上手、用自己的数据私下定制 FM，并使用 [Amazon Web Services](https://aws.amazon.com/)（AWS）服务将它们集成并部署到应用中，而无需管理基础设施。本文中，我们使用 Amazon Bedrock 上的 [Cohere v3 Embed](https://aws.amazon.com/bedrock/cohere-command-embed/) 模型来创建语言 embedding。

## 用例：RSS 聚合器

- **零样本分类** – 文章会在不同主题之间进行分类。有一些默认主题，例如 Technology、Politics 和 Health & Wellbeing，如下图所示。用户也可以创建自己的主题。

## 什么是 embedding？

本节简要介绍什么是 embedding，以及它们可以怎么用。

Embedding 是概念或对象（例如语言或图像）的数值表示。本文讨论的是语言 embedding。通过把这些概念归约为数值表示，我们就可以以计算机能够理解和运算的方式来使用它们。

以 Berlin 和 Paris 为例。作为人类，我们理解这两个词之间的概念联系。Berlin 和 Paris 都是城市，都是各自国家的首都，而且都在欧洲。我们几乎是本能地理解它们的概念相似性，因为我们能在头脑中建立世界模型。然而，计算机并没有内置的方式来表示这些概念。

为了以计算机能理解的方式表示这些概念，我们把它们转换为语言 embedding。语言 embedding 是高维向量，通过神经网络训练来学习彼此之间的关系。在训练过程中，神经网络会接触大量文本，并根据词语在不同上下文中如何共现和关联来学习模式。

Embedding 向量让计算机能够从语言中对世界建模。例如，如果我们把 “Berlin” 和 “Paris” 做 embedding，现在就可以对这些 embedding 做数学运算。我们随后能观察到一些相当有趣的关系。例如，我们可以做下面这件事：Paris – France + Germany ~= Berlin。这是因为这些 embedding 捕捉到了 “Paris” 与 “France” 之间、以及 “Germany” 与 “Berlin” 之间的关系——具体来说，就是 Paris 和 Berlin 都是各自国家的首都。

下图展示了各国与其首都之间的词向量距离。

[![国家与首都的 embedding 表示。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-04-distance-embeddings.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-04-distance-embeddings.png)

从 “Paris” 中减去 “France” 会剥离国家语义，留下一个表示“首都”这一概念的向量。再把这个向量与 “Germany” 相加，我们得到的东西就与 “Berlin”（德国的首都）非常接近。这一关系的向量如下图所示。

[![演示如何操纵这些 embedding 来展示概念相似性。](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-05-embedding-manipulation.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-05-embedding-manipulation.png)

在我们的用例中，我们使用 Amazon Bedrock 中预训练的 Cohere Embeddings 模型，它对整段文本而非单个词做 embedding。这些 embedding 表示文本的含义，可以用数学运算来处理。这一特性有助于映射文本之间的相似性等关系。

## 零样本分类

我们使用语言 embedding 的一种方式，是利用其特性计算一篇文章与某个主题的相似程度。

为此，我们先把一个主题拆解为一系列互不相同又相互关联的 embedding。例如，对于文化，我们有一组关于体育、电视节目、音乐、书籍等的 embedding。然后我们对 RSS 文章的标题和描述做 embedding，并计算它们与主题 embedding 的相似度。由此，我们就可以为文章分配主题标签。

下图展示了这一机制如何运作。Cohere 生成的 embedding 维度很高，包含 1,024 个值（即维度）。不过为了演示这个系统如何工作，我们使用一种旨在降低 embedding 维度的算法——[t 分布随机邻域嵌入（t-SNE）](https://en.wikipedia.org/wiki/T-distributed_stochastic_neighbor_embedding)，以便在二维中查看它们。下图使用这些 embedding 直观展示了主题如何按相似性和含义聚集。

[![不同主题的聚类](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-06-topic-clustering.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-06-topic-clustering.png)

你可以用一篇文章的 embedding，检查它与上述各 embedding 的相似度。然后就可以说：如果某篇文章与其中某个 embedding 聚得很近，它就可以归入与之关联的主题。

这就是 [k 近邻（k-NN）算法](https://en.wikipedia.org/wiki/K-nearest_neighbors_algorithm)。该算法用于执行分类和回归任务。在 k-NN 中，你可以基于某个数据点与其他数据点的邻近程度做出推断。例如，你可以说，一篇文章如果与上图所示音乐主题邻近，就可以打上文化主题的标签。

下图以一篇 [ArsTechnica 文章](https://arstechnica.com/science/2024/07/the-climate-is-changing-so-fast-that-we-havent-seen-how-bad-extreme-weather-could-get/)为例作了演示。我们把该文章的标题和描述做 embedding 后进行绘制：（气候的变化如此之快，以至于我们还没看到极端天气能糟糕到什么程度：几十年前的统计数据已不再能代表当下可能出现的情形）。

[![ars-technica 文章相对于不同主题的聚类展示](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-07-topic-cluster-article.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-07-topic-cluster-article.png)

这种做法的优势在于，你可以添加由用户生成的自定义主题。你可以先为一系列概念上相关的条目创建 embedding，从而构成一个主题。例如，一个 AI 主题会与 AI、Generative AI、LLM 和 Anthropic 的 embedding 相近，如下图所示。

[![向应用添加自定义主题](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-08-add-new-topic.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-08-add-new-topic.png)

在传统分类系统中，我们必须训练一个分类器——这是一项监督学习任务，需要提供一系列示例来判定文章是否属于相应主题。这样做可能相当费力，需要标注数据和训练模型。而在我们的用例中，我们只需提供示例、创建聚类并给文章打标签，无需提供标注示例或训练额外模型。下图是我们网站结果页的截图，展示了这一点。

在我们的应用中，我们按计划摄取新文章。我们使用 EventBridge 调度定期调用一个 Lambda 函数，由它检查是否有新文章。如果有，就使用 Amazon Bedrock 和 Cohere 为它们创建 embedding。

我们计算文章与各个主题 embedding 之间的距离，从而判定文章是否属于该类别。这一步由带 pgvector 的 Aurora PostgreSQL 完成。我们存储主题的 embedding，然后用以下 SQL 查询计算它们的距离：

```
const topics = await sqlClient.then(it=> it.query(
    `SELECT name, embedding_description, similarity
     FROM (SELECT topic_id as name, embedding_description, (1- ABS( 1 –(embed.embedding <-> $1))) AS "similarity" FROM topic_embedding_link embed)  topics
     ORDER BY similarity desc`,
    [toSql(articleEmbedding)]
  ))
```

上面代码中的 <-> 运算符计算文章与主题 embedding 之间的欧氏距离。这个数值让我们了解文章与某个主题有多接近。随后我们可以基于这一排名判断主题是否恰当。

接着我们给文章打上主题标签。这样做是为了让后续的主题请求在计算上尽可能轻量：我们只做一次简单的 join，而不是计算欧氏距离。

```
const formattedTopicInsert = pgformat(
    `INSERT INTO feed_article_topic_link(topic_id, feed_article_id) VALUES %L ON CONFLICT DO NOTHING`,
    topicLinks
  )
```

我们还会缓存特定的主题／订阅源组合，因为这些组合按小时计算，并且在此期间预计不会变化。

## 语义搜索

如前所述，Cohere 生成的 embedding 包含大量特征；它们编码了词或短语的含义与语义。我们还发现，可以对这些 embedding 做数学运算，从而实现计算两个短语或词语之间相似度等操作。

我们可以使用这些 embedding，借助 k-NN 算法计算搜索词与文章 embedding 之间的相似度，从而找到与所提供搜索词在语义和含义上相近的文章。

例如，在我们的某个 RSS 源中，有很多评测不同产品的文章。在传统搜索系统中，我们会依赖关键词匹配来提供相关结果。虽然查找某篇具体文章可能很简单（例如搜索“最佳数字笔记本”），但要涵盖多篇产品清单类文章，我们就需要另一种方法。

在语义搜索系统中，我们先把 “Product list” 这个词转换为 embedding，然后利用该 embedding 的特性在 embedding 空间中执行搜索。借助 k-NN 算法，我们可以找到语义上相似的文章。如下图所示，尽管标题或描述中都没有 “Product list” 这段文字，我们仍然找到了包含产品清单的文章。这是因为我们能够捕捉查询的语义，并把它与每篇文章已有的 embedding 相匹配。

[![语义搜索示例](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-02-example-search.png)](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/02/06/ML-17434-02-example-search.png)

在我们的应用中，我们使用 Aurora PostgreSQL 上的 pgvector 存储这些 embedding。pgvector 是一个开源扩展，可在 PostgreSQL 中实现向量相似度搜索。我们使用 Amazon Bedrock 和 Cohere v3 Embed 把搜索词转换为 embedding。

把搜索词转换为 embedding 之后，我们可以把它与摄取过程中已保存的文章 embedding 进行比较。然后就可以使用 pgvector 找到聚在一起的文章。相应的 SQL 代码如下：

```
SELECT *
FROM (
    SELECT feed_articles.id as id, title, feed_articles.feed_id as feed, feedName, slug, description, url, author, image, published_at as published, 1 - ABS(1 - (embedding <-> $2)) AS "similarity"
    FROM feed_articles
    INNER JOIN (select feed_id, name as feedName from feed_user_subscription fus where fus.user_id=$1) sub on feed_articles.feed_id=sub.feed_id
    ${feedId != undefined ? `WHERE feed_articles.feed_id = $4` : ""}
)
WHERE similarity > 0.95
ORDER BY similarity desc
LIMIT $3;
```

这段代码计算主题与该文章 embedding 之间的距离，作为 “similarity”。如果距离很近，我们就可以认为文章的主题与之相关，于是把该主题附加到文章上。
