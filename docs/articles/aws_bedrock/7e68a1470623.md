# 用 Claude Code 与 Amazon Bedrock prompt caching 为你的开发提速

***2025 年 9 月：新增 [Guidance for Claude Code with Amazon Bedrock](https://aws.amazon.com/solutions/guidance/claude-code-with-amazon-bedrock/)，作为把 Claude Code 部署到组织时的一项考量。***

[Amazon Bedrock](https://aws.amazon.com/bedrock/) 中的 prompt caching 现已正式可用，为 agentic AI 应用带来性能与成本上的收益。需要处理大型代码库的编程助手是 prompt caching 的理想用例。

本文中，我们将探讨如何把 Amazon Bedrock [prompt caching](https://aws.amazon.com/bedrock/prompt-caching/) 与 [Claude Code](https://www.anthropic.com/claude-code) 结合使用——后者是 Anthropic 发布的编程 agent，现已[正式可用](https://www.anthropic.com/news/claude-4)。这一强大的组合会改变你的开发工作流：它通过降低推理响应延迟带来极快的响应，同时降低输入 token 成本。你将看到，这如何让 AI 辅助编程不仅更高效，而且在日常开发任务中也更具经济可行性。

## Claude Code 是什么？

![Claude Code](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/24/6826a6227b1fbd47034d1936_claude-code.png)

Claude Code 是 Anthropic 的 AI 编程助手，由 [Claude Sonnet 4](https://aws.amazon.com/bedrock/anthropic/) 驱动。它可以直接在你的终端、你常用的 [IDE](https://docs.anthropic.com/en/docs/claude-code/ide-integrations)（例如 VS Code 和 Jetbrains）中运行，也可以通过 [Claude Code SDK](https://docs.anthropic.com/en/docs/claude-code/sdk) 在后台运行，理解你的项目上下文并执行操作，而无需你手动操作或把生成的代码添加到项目中。与传统编程助手不同，Claude Code 可以：

- 编写代码并修复跨代码库中多个文件的 bug
- 回答关于代码架构与逻辑的问题
- 运行并修复测试、linting 以及其他命令
- 检索 git 历史、解决合并冲突，并创建 commit 和 PR
- 操作你其他所有命令行工具，例如 AWS CLI、Terraform 和 k8s

Claude Code 最吸引人的地方在于它如何融入你现有的工作流。你只需把它指向项目目录，然后用自然语言命令与它交互。Claude Code 还支持 [Model Context Protocol（MCP）](https://docs.anthropic.com/en/docs/agents-and-tools/mcp)，让你可以把外部工具和数据源直接连接到终端，并用你的上下文定制它的 AI 能力。

要了解更多，请参阅 [Claude Code 教程](https://docs.anthropic.com/en/docs/claude-code/tutorials)和 [Claude Code：agentic 编程最佳实践](https://www.anthropic.com/engineering/claude-code-best-practices)。

## 面向 AI 辅助开发的 Amazon Bedrock prompt caching

在处理大上下文时，Amazon Bedrock 的 prompt caching 功能会大幅降低响应时间和成本。它的工作方式如下：启用 prompt caching 后，你的 agentic AI 应用（例如 Claude Code）会在 prompt 的特定位置插入缓存检查点标记。Amazon Bedrock 随后解释这些由应用定义的标记并创建缓存检查点，在处理完前面的文本后保存整个模型状态。在后续请求中，如果你的 prompt 复用相同的前缀，模型就会加载缓存状态，而不是重新计算。

具体到 Claude Code，这意味着该应用在处理你的代码库时会智能地管理这些缓存点，让 Claude 能够“记住”之前分析过的代码，而无需承担重新处理它的全部计算与资金成本。当你针对同一段代码提出多个问题，或迭代优化解决方案时，Claude Code 会利用这些缓存检查点提供更快的响应，同时大幅降低 token 消耗与相关成本。

要了解更多，请参阅 [Amazon Bedrock prompt caching 文档](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html)。

## 解决方案概述：试用结合 Amazon Bedrock prompt caching 的 Claude Code

### 先决条件

- 拥有可访问 Amazon Bedrock 的 AWS 账户。
- 适用于 Amazon Bedrock 的相应 [AWS Identity and Access Management（IAM）](https://aws.amazon.com/iam/) 角色与权限。
- 在目前支持 prompt caching 的 AWS 区域（例如 us-east-1 和 us-west-2）中，具备对 Anthropic Claude Sonnet 4 的 Amazon Bedrock [模型访问权限](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)。
- 已使用你的 AWS 凭证配置好的 [AWS 命令行界面（AWS CLI）](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)。

对于[受支持的模型和 AWS 区域](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html#prompt-caching-models)，prompt caching 会自动开启。

### 在 Amazon Bedrock 上使用 Claude Sonnet 4 设置 Claude Code

用你的凭证配置好 AWS CLI 之后，请按以下步骤操作：

- 在你的终端中运行以下命令：`# Install Claude Code npm install -g @anthropic-ai/claude-code # Configure for Amazon Bedrock export CLAUDE_CODE_USE_BEDROCK=1 export ANTHROPIC_MODEL='us.anthropic.claude-sonnet-4-20250514-v1:0' export ANTHROPIC_SMALL_FAST_MODEL='us.anthropic.claude-3-5-haiku-20241022-v1:0' # Launch Claude Code claude`
- 检查终端中是否出现 **Welcome to Claude Code!** 提示，以确认 Claude Code 正在运行。
![终端 - 欢迎使用 Claude Code](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/24/image-24-2.png)

要了解更多关于为 Amazon Bedrock 配置 Claude Code 的信息，请参阅[连接到 Amazon Bedrock](https://docs.anthropic.com/en/docs/claude-code/overview#connect-to-amazon-bedrock)。

### prompt caching 入门

为入门起见，我们先来试验一个简单的 prompt。

- 在 Claude Code 中运行 prompt：`build a basic text-based calculator`
- 审查并回应 Claude Code 的请求：  当出现类似 `Do you want to create calculator.py?` 的问题时，选择 `1. Yes` 继续。
*示例问题：*  `Do you want to create calculator.py? 1. Yes 2. Yes, and don't ask again for this session (shift+tab) 3. No, and tell Claude what to do differently (esc)` 批准前请仔细审查每个请求，以维护安全。
- Claude Code 生成计算器应用后，会显示类似这样的说明：`Run the calculator with: python3 calculator.py`
- 通过运行上面指示的命令来测试该应用。然后按屏幕提示进行计算。

Claude Code 会自动启用 prompt caching 以优化性能和成本。要监控 token 使用量与成本，请使用 `/cost` 命令。你将得到类似下面这样的详细明细：

```
/cost 
  ⎿  Total cost:            $0.0827
  ⎿  Total duration (API):  26.3s
  ⎿  Total duration (wall): 42.3s
  ⎿  Total code changes:    62 lines added, 0 lines removed
```

该输出为你本次会话的资源消耗提供了有价值的信息，包括总成本、API 处理时间、实际耗时，以及代码改动。

### prompt caching 入门

为了解 prompt caching 的收益，我们用同样的 prompt 在不启用 prompt caching 的情况下试一次，以便对比：

- 在终端中按 `Ctrl+C` 退出 **Claude Code**。
- 要创建新的项目目录，请运行命令：`mkdir test-disable-prompt-caching; cd test-disable-prompt-caching `
- 通过设置环境变量来禁用 prompt caching：`export DISABLE_PROMPT_CACHING=1`
- 运行 `claude` 以启动 Claude Code。
- 检查终端输出，确认 prompt caching 已禁用。你应该会在 **Overrides (via env)** 部分看到 `Prompt caching: off`。
![](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2025/05/24/Claude-Code-Prompt-Caching-Off.png)
- 运行 prompt：`build a basic text-based calculator`
- 完成后，运行 `/cost` 查看资源使用情况。

你会看到，即使 prompt 很简单，资源消耗也高于启用 prompt caching 时的水平：

```
/cost 
  ⎿  Total cost:            $0.1029
  ⎿  Total duration (API):  32s
  ⎿  Total duration (wall): 1m 17.5s
  ⎿  Total code changes:    57 lines added, 0 lines removed
```

不启用 prompt caching 时，每次交互都要承担处理你上下文的全部成本。

### 清理

要重新启用 prompt caching，请退出 Claude Code，并在重启 Claude 之前运行 unset `DISABLE_PROMPT_CACHING`。你不使用 Claude Code 时不会产生成本。

## 面向复杂代码库与高效迭代的 prompt caching

在处理复杂代码库时，prompt caching 带来的收益远高于简单 prompt 的情形。举个示意性的例子，假设初始 prompt 是：`Develop a game similar to Pac-Man`。这个初始 prompt 会生成项目的基础结构和文件。当你用诸如 `Implement unique chase patterns for different ghosts` 这样的 prompt 继续完善应用时，编程 agent 必须理解你的整个代码库，才能做出有针对性修改。

如果不使用 prompt caching，你就迫使模型在每一次迭代中重新处理代表代码结构、类关系和现有实现的数千个 token。

prompt caching 通过保留你的复杂上下文来缓解这种重复处理，从而以下列方式改变你的软件开发工作流：

- 与同一批文件反复交互时 token 成本大幅降低
- 响应时间更快，因为 Claude Code 无需重新处理你整个代码库
- 开发周期更高效，因为迭代时不必每次都承担全部成本

## 结合 Model Context Protocol（MCP）的 prompt caching

[Model Context Protocol（MCP）](https://modelcontextprotocol.io/introduction) 通过把编程 agent 连接到你的特定工具和信息源，改变你的编程体验。你可以把 Claude Code 连接到[各类 MCP server](https://modelcontextprotocol.io/examples)，与你的文件系统、数据库、开发工具和其他生产力工具集成。这会把一个通用的编程助手变成个性化的助手，使其能够在代码库之外与你的数据和工具交互、遵循你组织的最佳实践，从而加速你特有的开发流程与工作流。

在 AWS 上构建时，你还能通过使用[面向代码助手的 AWS 开源 MCP server](https://aws.amazon.com/blogs/machine-learning/introducing-aws-mcp-servers-for-code-assistants-part-1/) 获得额外优势：它们提供智能的 AWS 文档搜索、最佳实践建议，以及实时的成本可见性、分析与洞察——而无需离开你的软件开发工作流。

在使用 MCP 时，Amazon Bedrock prompt caching 变得至关重要，因为它在多次交互之间保留复杂的上下文。由于 MCP 会持续用外部知识和工具丰富你的 prompt，prompt caching 免除了反复处理这些扩展上下文的需要，可将成本削减最高 90%、将延迟降低最高 85%。随着你的 MCP server 提供关于你独特开发环境日益复杂的上下文，这一优化尤其有价值：你可以在最长 5 分钟内保留相关上下文而不出现性能损失或额外成本，从而快速迭代复杂的编程挑战。

## 把 Claude Code 部署到组织时的注意事项

Claude Code 现已正式可用，许多客户正在考虑在 AWS 上的部署方案，以利用其编程能力。对于部署，请考虑你用于安全与治理的基础架构：

**考虑利用 [AWS IAM Identity Center](https://aws.amazon.com/iam/identity-center/)（原 AWS Single Sign On，SSO）来集中治理 Claude Code 的身份与访问。** 这会验证只有获得授权的开发者才能访问。此外，它还允许开发者使用[临时的、基于角色的凭证](https://docs.aws.amazon.com/singlesignon/latest/userguide/howtogetcredentials.html)访问资源，从而免除对静态访问密钥的需求并增强安全性。在打开 Claude Code 之前，请确保使用 `aws configure sso --profile <PROFILE_NAME>` 把 AWS CLI 配置为使用 IAM Identity Center profile。然后，使用所创建的 profile 登录：`aws sso login --profile <PROFILE_NAME>`。

**对于大型企业部署，考虑实施 [Guidance for Claude Code with Amazon Bedrock](https://aws.amazon.com/solutions/guidance/claude-code-with-amazon-bedrock/)。** 该指南帮助组织部署 Claude Code，同时对 AI 资源访问保持严格控制，无缝接入现有的身份基础设施，并针对开发者生产力与使用模式提供可观测性。

**查看[服务配额](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas.html)，并根据活跃开发者数量设置合适的 Token Per Minute（TPM）与 Request Per Minute（RPM）。** 请确保你拥有足够的 TPM 与 RPM 配额来支撑团队的使用量。作为参考，请遵循[速率限制建议](https://docs.anthropic.com/en/docs/claude-code/costs#rate-limit-recommendations)。例如，如果你有 200 名开发者，你可以为每位开发者申请 20,000 TPM，即总计 4,000,000 TPM。

**考虑自动配置默认环境变量。** 这包括本文列出的环境变量，例如 `CLAUDE_CODE_USE_BEDROCK`、`ANTHROPIC_MODEL` 和 `ANTHROPIC_FAST_MODEL`。这样会配置 Claude Code 自动连接 Bedrock，为各团队的开发提供一致的基线。作为起步，组织可以先向开发者提供自助式说明。

**为你的组织考虑权限、memory 和 MCP server。** 安全团队可以为 Claude Code 允许与不允许执行的操作配置受管[权限](https://docs.anthropic.com/en/docs/claude-code/security)，这些权限无法被本地配置覆盖。此外，你可以为所有项目配置 [memory](https://docs.anthropic.com/en/docs/claude-code/memory)，从而自动把常用的 bash 命令、文件、工作流和风格约定加入其中，以符合组织的偏好。要做到这一点，可以把你的 `CLAUDE.md` 文件部署到企业目录 `/<enterprise root>/CLAUDE.md` 或用户主目录 `~/.claude/CLAUDE.md`。最后，我们建议由一个中央团队配置 MCP server，并把 `.mcp.json` 配置提交到代码库，让所有用户都能受益。

要了解更多，请联系你的 AWS 客户团队，或参阅以下资源：

- [工作坊：Amazon Bedrock 上的 Claude Code](https://catalog.workshops.aws/claude-code-on-amazon-bedrock)
- [Claude Code 部署概览](https://docs.claude.com/en/docs/claude-code/third-party-integrations)

## 结论

本文中，你了解了 Amazon Bedrock prompt caching 如何显著增强 AI 应用， Claude Code 这一 agentic AI 助手就是有力的示范。借助 prompt caching，你可以更高效地处理大型代码库，从而大幅降低成本和响应时间。有了这项技术，你可以与自己的代码进行更快、更自然的交互，用生成式 AI 快速迭代。你还了解了 Model Context Protocol（MCP），以及外部工具的无缝集成如何让你用文档、Web 资源等特定上下文定制 AI 助手。无论你是在处理复杂的调试、重构遗留系统，还是开发新功能，Amazon Bedrock prompt caching 与 Claude Code 这类 AI 编程 agent 的组合都为软件开发提供了更迅捷、更具成本效益且更智能的方法。

Amazon Bedrock prompt caching 已随 Claude 4 Sonnet 和 Claude 3.5 Haiku 正式可用。要了解更多，请参阅 [prompt caching](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html) 和 [Amazon Bedrock](https://aws.amazon.com/bedrock/)。

Anthropic Claude Code 现已正式可用。要了解更多，请参阅 [Claude Code 概览](https://docs.anthropic.com/en/docs/claude-code/overview)，并联系你的 AWS 客户团队获取部署指导。
