Jina-VLM: Small Multilingual Vision Language Model

## [*tag*](https://jina.ai/news/jina-vlm-small-multilingual-vision-language-model/#architecture)架构

jina-vlm 的架构。图像会被缩放到适配一个最多 12 个重叠图块（tile）的网格，外加一张全局缩略图。每个图块是一个 378x378 的正方形裁剪；相邻图块重叠 112 像素，图块原点之间的步长为 266 像素。因此 4x3 的网格覆盖 1176x910 像素，超过这一有效分辨率的图像会被缩小以适应图块预算。每个图块通过 SigLIP2 产出 729 个 patch。VL 连接器拼接第 24 层和第 18 层（即倒数第三层和倒数第九层）的特征，然后施加 2x2 注意力池化，把 729 个 token 缩减到 182，再投影到解码器维度。视觉 token 与文本 embedding 一起送入 Qwen3 解码器。

有两个难题一直制约着 VLM 的实际部署：多语言能力在视觉适配过程中往往会退化，而高质量 VLM 的计算开销依然昂贵。[jina-vlm](https://jina.ai/models/jina-vlm) 通过审慎的架构选择——我们的注意力池化连接器把视觉 token 减少 4 倍、对性能影响极小——以及一套明确保留多语言能力的训练方案，同时解决了这两个问题。

关键的架构创新是我们的视觉-语言连接器。我们并不把每个图块的 729 个视觉 token 全部传给语言模型，而是施加 2×2 注意力池化，将其缩减到 182 个 token——4 倍的缩减，信息损失却极小。连接器的工作方式如下：

- **多层特征融合**：我们拼接 ViT 第 18 层和第 24 层（倒数第三层与倒数第九层）的特征，同时捕捉细粒度空间细节和高层语义。
- **注意力池化**：对每个 2×2 的 patch 邻域，我们把邻域特征的均值作为 query，然后施加交叉注意力，产出单个池化后的表示。
- **SwiGLU 投影**：池化后的特征通过一个门控线性单元（gated linear unit）投影到语言模型维度。

这一效率提升如下表所示：

| 指标 | 无池化 | 有池化 | 缩减倍数 |
| --- | --- | --- | --- |
| 视觉 token（12 图块 + 缩略图） | 9,477 | 2,366 | 4.0× |
| LLM prefill FLOPs | 27.2 TFLOPs | 6.9 TFLOPs | 3.9× |
| KV-cache 显存 | 2.12 GB | 0.53 GB | 4.0× |

由于 ViT 对每个图块的处理与是否池化无关、完全相同，这些节省只体现在语言模型上，而语言模型正是推理期间的最主要开销。

### [*tag*](https://jina.ai/news/jina-vlm-small-multilingual-vision-language-model/#training-procedure)训练流程

VLM 训练中一个常见的失败模式是灾难性遗忘：语言模型在适配视觉输入时，会丧失其纯文本能力。这对多语言模型尤其尖锐，因为视觉适配会拖累非英语语言上的表现。

我们通过一个两阶段训练流程来解决这个问题，其中显式使用多语言数据并保留纯文本能力。

#### 阶段 1：对齐训练

第一阶段侧重跨语言语义对齐（grounding），使用覆盖多种视觉领域的描述数据集：自然场景、文档、信息图和示意图。关键在于，我们加入了 15% 的纯文本数据，以维持主干的语言理解能力。相比编码器和解码器，连接器使用更高的学习率（2e-4）和更短的预热（warmup），使其能快速适配，而预训练组件则缓慢变化。

#### 阶段 2：指令微调

第二阶段训练面向 VQA 和推理任务的指令跟随能力。我们把覆盖学术 VQA、文档理解、OCR、数学和推理的公开数据集，与纯文本指令数据结合起来，以维持语言能力。

合并后的数据约包含 500 万多模态样本和 120 亿文本 token，横跨 29 种语言，其中大约一半为英语，其余涵盖中文、阿拉伯语、德语、西班牙语、法语、意大利语、日语、韩语、葡萄牙语、俄语、土耳其语、越南语、泰语、印尼语、印地语、孟加拉语等。

### [*tag*](https://jina.ai/news/jina-vlm-small-multilingual-vision-language-model/#via-transformers)通过 Transformers

```
from transformers import AutoModelForCausalLM, AutoProcessor
import torch
from PIL import Image

# Load model and processor
model = AutoModelForCausalLM.from_pretrained(
    "jinaai/jina-vlm",
    torch_dtype=torch.bfloat16,
    trust_remote_code=True,
    device_map="auto"
)
processor = AutoProcessor.from_pretrained(
    "jinaai/jina-vlm",
    trust_remote_code=True
)

# Load an image
image = Image.open("document.png")

# Create the conversation
messages = [
    {
        "role": "user",
        "content": [
            {"type": "image", "image": image},
            {"type": "text", "text": "What is the main topic of this document?"}
        ]
    }
]

# Process and generate
inputs = processor.apply_chat_template(
    messages,
    add_generation_prompt=True,
    tokenize=True,
    return_dict=True,
    return_tensors="pt"
).to(model.device)

outputs = model.generate(**inputs, max_new_tokens=256, do_sample=False)
response = processor.decode(outputs[0], skip_special_tokens=True)
print(response)
```

## [*tag*](https://jina.ai/news/jina-vlm-small-multilingual-vision-language-model/#conclusion)结论

[jina-vlm](https://jina.ai/models/jina-vlm) 表明，小 VLM 通过审慎的架构和训练选择，也能实现强劲的跨语言视觉理解。注意力池化连接器提供 4 倍的 token 缩减而几乎不影响性能，而在多模态训练中掺入纯文本数据，则保住了原本会退化的语言能力。

我们指出当前方法的若干局限：

- **图块开销**：处理耗时随图块数量线性增长。对于极高分辨率的图像，这会变得可观。此外，图块化会损害需要整体场景理解的任务，比如物体计数或跨图块边界的空间推理。全局缩略图能部分缓解这一点，但对这类任务而言，原生分辨率的方法可能更合适。
- **多图推理**：由于该情形下的训练数据有限，多图基准上的表现较弱。对简洁视觉回答的优化，似乎与长时间的多步推理相冲突，MMLU-Pro 的退化就说明了这一点。

未来的工作可以探索更高效的分辨率处理、针对计数和空间任务的定向改进，并研究我们的多语言训练方案能否迁移到更大的模型规模。
