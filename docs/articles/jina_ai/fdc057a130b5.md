# 从原始数值识别 Embedding 模型

一个只需读取原始数字位就能为 embedding 模型「指纹识别」的小型 transformer，无需特征工程。

作者：Han Xiao · 6 分钟阅读

Embedding 模型是黑箱。你输入文本，拿到一个向量——一串浮点数，没有标签、没有水印、没有任何能告诉你它来源的元数据。如果有人递给你一个 1024 维向量，你能分辨它是 BGE-M3、[jina-embeddings-v5-text-small](https://jina.ai/?sui&model=jina-embeddings-v5-text-small) 还是 Qwen3-Embedding 产出的吗？即便两个向量来自同一个模型，你能判断它们分别是用检索指令还是分类指令生成的吗？

结果是可以。embedding 向量里的数值模式，携带着产出它的模型、乃至推理时所用指令提示词的、出人意料地强的指纹。我们训练了一个小型 transformer 分类器（80 万参数），仅靠读取原始浮点数字位，就能从 25+ 个 embedding 模型中识别 68 种「模型-任务」组合，准确率达 87%。你可以亲自试试这个[在线 Demo](https://embedding-inversion-demo.jina.ai)：粘贴任意一个 embedding 向量，看看分类器认为它是哪个模型、哪种任务产出的。

## [分词：把数字当作文本](https://jina.ai/news/identifying-embedding-models-from-raw-numerical-values/#tokenization-treating-numbers-as-text)

一个 1024 维 embedding 向量就是 1024 个浮点数的序列。要把它喂进分类器，我们需要一种对这些数值结构不做任何假设的表示方式。

我们采取了一个大胆的做法：把每个浮点数当作一串数字字符，逐字符分词。相比[更紧凑的替代方案](https://jina.ai/news/identifying-embedding-models-from-raw-numerical-values/#alternative-approaches)这听起来浪费，但事实证明这是正确的取舍。对于 `-0.1234` 这样的值，token 序列是：

```
- 0 . 1 2 3 4
```

各维度之间用 `[SEP]` token 分隔，整个序列以 `[CLS]` 开头。完整词表只有 15 个 token（对浮点值做数字级分词，词表大小为 15）：

| Token ID | 含义 |
| --- | --- |
| 0-9 | 数字 |
| 10 | 负号 |
| 11 | 小数点 |
| 12 | [SEP] |
| 13 | [CLS] |
| 14 | [PAD] |

在保留 4 位小数精度时，一个 1024 维向量大约产生 7,700 个 token，一个 384 维向量约产生 2,900 个 token。序列长度随 embedding 维度自然变化，跨维度无需 padding 或截断。由于该分词器是一个不含任何可学习组件的直接整数映射，它极其高效。

## [模型结构](https://jina.ai/news/identifying-embedding-models-from-raw-numerical-values/#model-architecture)

4 层 encoder-only transformer，80 万参数，词表 15，序列长度最多 7,700 token。

这个分类器是一个小型 encoder-only transformer，4 层、128 维、4 个带 RoPE 的注意力头，配合 SwiGLU FFN 与 RMSNorm。CLS token 经池化后投影到 68 类的输出空间，总参数量约 80 万。

尽管词表只有 15 个 token，这从根本上仍是一个长序列任务。单个 1024 维 embedding 会变成一条 7,700 token 的序列，比典型的 NLP 输入更长。模型必须在数千个数字 token 上做注意力，以捕捉区分不同模型输出的统计模式。这使得高效的注意力与位置编码（RoPE）即便在这个极小规模下也必不可少。

### [数据](https://jina.ai/news/identifying-embedding-models-from-raw-numerical-values/#data)

我们使用了 10,000 条多语言文本样本，每条都由 25+ 个模型、配合各种任务前缀（如 `retrieval.query`、`retrieval.document`、`classification`、`clustering`）嵌入，共产生 68 个不同的类别。重要的是，这 68 类不仅包含不同的模型，也包含对同一模型施加的不同指令提示词。例如，带检索指令的 [jina-embeddings-v5-text-small](https://jina.ai/?sui&model=jina-embeddings-v5-text-small) 与带分类指令的同一模型，被视为不同的类别。目标是从纯原始输出中同时检测出模型身份与任务特定行为。

每个类别划分为 7,000 条训练样本与 3,000 条验证样本。这些模型跨越五种输出维度。

| 维度 | 类别数 | 示例模型 |
| --- | --- | --- |
| 384 | 8 | BGE-small, E5-small, MiniLM, GTE-small |
| 512 | 2 | BGE-small-zh |
| 768 | 24 | BGE-base, E5-base, [jina-embeddings-v5-text-nano](https://jina.ai/?sui&model=jina-embeddings-v5-text-nano), Nomic, INSTRUCTOR, LaBSE |
| 1024 | 32 | BGE-M3, E5-large, [jina-embeddings-v3](https://jina.ai/?sui&model=jina-embeddings-v3), [jina-embeddings-v5-text-small](https://jina.ai/?sui&model=jina-embeddings-v5-text-small), Qwen3-0.6B, Snowflake, mxbai |
| 1536 | 2 | GTE-Qwen2-1.5B |

仅 1024 维这一组就有 32 个类别要区分，其中还包括来自同一模型家族、但任务前缀不同的模型。在这种情况下分类器无法依赖序列长度，只能纯粹学习数值模式。

### [训练](https://jina.ai/news/identifying-embedding-models-from-raw-numerical-values/#training)

训练在一块 A100 40GB 上进行，采用混合精度、按长度分桶的批次，以及带余弦调度的 AdamW，速率约 34 万 token/秒，每轮约 23,800 步。

## [实验结果](https://jina.ai/news/identifying-embedding-models-from-raw-numerical-values/#experimental-results)

14 个 epoch（约 430 亿 token）上的训练与验证曲线：训练准确率 87.3%，验证准确率 86.0%。

训练/验证差距之小以及持续提升，说明这是可泛化的学习而非记忆。在 80 万参数下，模型已接近其容量上限，更大的模型很可能会把准确率推得更高。

### [混淆矩阵](https://jina.ai/news/identifying-embedding-models-from-raw-numerical-values/#confusion-matrix)

在整个验证集上的 68 类混淆矩阵（每类 3,000 样本，共 204,000），总体准确率 87.0%。

总体准确率 87.0%，相比 1.5% 的随机水平高出 59 倍。若干模型被完美分类，包括 GTE-large、[jina-embeddings-v3](https://jina.ai/?sui&model=jina-embeddings-v3)/[jina-embeddings-v5-text-small](https://jina.ai/?sui&model=jina-embeddings-v5-text-small) 的分类变体、LaBSE 与 Paraphrase MiniLM。最难的案例是同一基础模型的不同任务前缀变体。Qwen3-0.6B 在其 4 种任务类型间表现出最强的同家族混淆，而 [jina-embeddings-v5-text-small](https://jina.ai/?sui&model=jina-embeddings-v5-text-small) 在 5 种任务间取得了 92% 的同家族准确率。同一模型上不同指令提示词会产生可区分的输出模式，这本身就是一个值得注意的发现——它表明即使基础权重完全相同，任务适配也会留下可测量的数值痕迹。

来自不同家族（BGE vs. Jina vs. E5 vs. Nomic）的模型，要比同一模型的任务变体容易区分得多。核心架构与训练方法留下的签名，比任务特定的适配器更强。真正的难点在 1024 维组（32 类）和 768 维组（24 类），分类器在这里必须纯粹依赖数值模式而非序列长度。

## [替代方案](https://jina.ai/news/identifying-embedding-models-from-raw-numerical-values/#alternative-approaches)

### [分桶分词器](https://jina.ai/news/identifying-embedding-models-from-raw-numerical-values/#bucket-tokenizer)

把每个维度量化到 K 个桶之一（比如 256），产生长度为 D 的紧凑序列，每个维度一个 token。这正是 Embedding-Converter（ICLR 2025）采用的方法。对 1024 维向量，你得到 1024 个 token 而非 7,700 个。

分桶会给值的分布强加一个先验：你必须在看到数据之前就决定桶边界。但不同模型分布其值的方式根本不同——有的把质量集中在零附近一个窄区间，有的在 [-1, 1] 上均匀铺开，而且分布随同一模型内的维度而异。任何固定的分桶方案，要么在值聚集处浪费分辨率，要么在值分散处分辨不足。按模型自适应分桶又违背了初衷，因为它需要先知道模型身份。

### [定长 MLP](https://jina.ai/news/identifying-embedding-models-from-raw-numerical-values/#fixed-length-mlp)

把原始 embedding 向量直接喂进一个 MLP 分类器。根本问题不止于可变维度问题（我们的模型产出 384 到 1536 维不等的向量）。即便你把一切都 pad 到固定长度，也隐含假设了维度索引在各模型间语义对齐——即 BGE-M3 的第 1 维对应 [jina-embeddings-v5-text-small](https://jina.ai/?sui&model=jina-embeddings-v5-text-small) 的第 1 维。这个假设是错的。不同的架构、训练数据与训练目标会产生截然不同的内部表示。

上述两种替代方案都强加了模型必须绕过的结构性假设。而数字级分词避开了所有这些问题，它是我们能找到的最「无假设」的表示：这里就是每个数字的精确数位、按序排列、用标记分隔，剩下的你自己想办法。

## [结论](https://jina.ai/news/identifying-embedding-models-from-raw-numerical-values/#conclusion)

Embedding 模型被训练成把语义相似的文本映射到相近的向量。训练目标从未涉及让向量可被识别，也没说要编码任何模型签名。然而签名就在那里，强到足以让一个极小的分类器探测出来。一个 embedding 模型的「风格」——它用来表示语义的特定数值模式——如同笔迹一样独特。甚至连指令提示词的选择都会留下可检测的痕迹。

这对若干实际场景有价值：在来源模型未知时审计向量数据库、核实某个 API 是否真的用了它声称的模型、检测模型版本变更。更根本地，它告诉我们：embedding 模型以结构上互不相同的方式编码语义，即使产出相同维度的向量也是如此。
