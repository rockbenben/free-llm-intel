jina-embeddings-v5-text：任务目标嵌入蒸馏

文本嵌入模型广泛用于语义相似性任务，包括信息检索、聚类和分类。通用模型通常使用对比损失函数通过单阶段或多阶段过程进行训练。我们引入了一种新颖的训练方案，它将模型蒸馏技术与特定任务的对比损失相结合，以生成紧凑的高性能嵌入模型。我们的研究结果表明，这种方法对于训练小型模型比纯粹的对比或基于蒸馏的训练范例更有效。所得模型 jina-embeddings-v5-text-small 和 jina-embeddings-v5-text-nano 的基准分数超过或匹配类似大小模型的最新水平。 jina-embeddings-v5-text 模型还支持多种语言的长文本（small 最多 32K token，nano 最多 8K），并生成在截断和二进制量化下保持稳健的嵌入。模型权重是公开的，希望能够激发嵌入模型开发的进一步进步。

我们的第五代嵌入：两个轻量级多语言模型，在检索、匹配、聚类和分类方面具有 SOTA 性能。

我们正在发布“jina-embeddings-v5-text”，这是我们嵌入模型系列的第五代，推动了 1B 以下多语言嵌入的质量效率前沿：

- [jina-embeddings-v5-text-small](https://jina.ai/?sui&model=jina-embeddings-v5-text-small) (**677M** 参数): **67.0** 在 MMTEB 上，**71.7** 在 MTEB 英语上
- [jina-embeddings-v5-text-nano](https://jina.ai/?sui&model=jina-embeddings-v5-text-nano)（**239M**参数）：MMTEB 上**65.5**，MTEB 英语**71.0**

小模型支持 **32K 令牌上下文（nano 为 8K）**、**4 个特定于任务的 LoRA 适配器**（检索、文本匹配、分类、聚类）以及 **Matryoshka 维度截断**（从 1024 降至 32）。在 239M 参数下，nano 模型的检索质量与参数数量是其两倍的模型相当。

与我们的前几代相比：v5-text-small 在检索方面与 [jina-embeddings-v4](https://jina.ai/?sui&model=jina-embeddings-v4) (3.8B) 匹配，同时小 5.6 倍，并且在所有方面优于 [jina-embeddings-v3](https://jina.ai/?sui&model=jina-embeddings-v3) (572M)具有相似参数数量的任务。

`v5-text-small` 在 MMTEB 上达到****67.0****（在 9 种任务类型的 131 个任务中平均），比次佳的 sub-1B 模型（Qwen3-0.6B，指令为 64.3）高出****+2.7 分****。具有 239M 个参数的纳米模型得分为 65.5，击败了具有两倍参数的模型。

在纯英语评估中，“v5-text-small”以 ****71.7**** 领先所有 sub-1B 多语言模型（7 种任务类型的 41 个任务的平均值），紧随其后的是“KaLM-mini-v2.5”（71.3）和“v5-text-nano”（71.0）。 239M 纳米模型在不到一半的尺寸下实现了与 494M KaLM 的同等性能。

`v5-text-small` 在 sub-4B 模型中的五个检索基准（MTEB Multilingual、MTEB English、RTEB、BEIR 和 LongEmbed）中实现了最高的任务级别平均值 (****63.28****)，与 [jina-embeddings-v4](https://jina.ai/?sui&model=jina-embeddings-v4) (3.8B, 63.62) 匹配，同时****小 5.6 倍****。

根据 2026 年 2 月 21 日的 [MTEB 排行榜](https://huggingface.co/spaces/mteb/leaderboard)，“jina-embeddings-v5-small”（0.6B 参数，排名第 8）是 MTEB Multilingual v2 上 1B 参数下最强的嵌入模型，在每个指标上都优于 Qwen3-Embedding-0.6b。 “jina-embeddings-v5-nano”（0.2B 参数，排名第 11）以一小部分大小提供了前 11 名的性能，此参数类中没有其他模型可以与之相媲美。

## [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#architecture)架构

![<code>jina-embeddings-v5-text</code> 架构](https://cms.jina.ai/content/images/2026/02/v5_architecture_1771470917.png)

v5-text 使用仅解码器主干和最后令牌池而不是均值池。每个变压器层注入四个轻量级 LoRA 适配器，独立处理检索、文本匹配、分类和聚类。用户在推理时选择适当的适配器。对于检索，查询将获得“查询：”前缀，文档将获得“文档：”。 Small 的上下文长度为 32K token（nano 为 8K），比 v3 增加了 4 倍。

### [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#elastic-inference-service)弹性推理服务

在生产中使用 v5-text 的最快方法。 Elastic 推理服务 (EIS) 提供具有内置扩展功能的托管嵌入推理，因此您可以直接在 Elastic 部署中生成嵌入，而无需管理基础设施。
```
PUT _inference/text_embedding/jina-v5
{
  "service": "elastic",
  "service_settings": {
    "model_id": "jina-embeddings-v5-text-small"
  }
}
```
有关设置详细信息，请参阅 [EIS 文档](https://www.elastic.co/docs/explore-analyze/elastic-inference/eis)。

### [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#jina-embedding-api)Jina 嵌入 API

我们的托管 API 具有按代币付费的定价。支持开箱即用的任务选择、维度截断和批处理。无需 GPU。
```
curl https://api.jina.ai/v1/embeddings \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "jina-embeddings-v5-text-small",
    "task": "retrieval.query",
    "dimensions": 1024,
    "input": ["What is knowledge distillation?"]
  }'
```
在 [jina.ai/embeddings](https://jina.ai/embeddings) 获取 API 密钥。

### [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#hugging-face-sentence-transformers)Hugging Face + 句子转换器

在本地运行并完全控制推理。 Hugging Face 上提供了权重，并具有开箱即用的句子转换器集成。
```
from sentence_transformers import SentenceTransformer
import torch

model = SentenceTransformer(
    "jinaai/jina-embeddings-v5-text-small-retrieval",
    model_kwargs={"dtype": torch.bfloat16},
)

query_emb = model.encode("What is knowledge distillation?", prompt_name="query")
doc_embs = model.encode(["Knowledge distillation transfers...", "Venus is..."], prompt_name="document")
similarity = model.similarity(query_emb, doc_embs)
```
### [*标签*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#vllm)vLLM

为生产工作负载提供高吞吐量服务。 vLLM 原生支持带有最后令牌池的 v5-text。
```
from vllm import LLM
from vllm.config.pooler import PoolerConfig

model = LLM(
    model="jinaai/jina-embeddings-v5-text-small-retrieval",
    dtype="float16",
    runner="pooling",
    pooler_config=PoolerConfig(seq_pooling_type="LAST", normalize=True),
)
outputs = model.encode(["Query: climate change impacts"], pooling_task="embed")
```
为了通过 llama.cpp 和 MLX 优化本地推理，每个任务适配器的 LoRA 权重都会合并到基本模型中以生成独立的权重文件。这就是为什么您会看到每个任务都有单独的存储库（检索、文本匹配、分类、聚类）——每个存储库都包含可供直接加载的完整合并权重，在推理时没有 LoRA 开销。

### [*标签*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#llamacpp-gguf)llama.cpp (GGUF)

在 CPU 或边缘设备上运行量化模型。我们为每个模型提供 14 种 GGUF 量化变体，从 F16 到 IQ1_S。
```
llama-server -hf jinaai/jina-embeddings-v5-text-small-retrieval-GGUF:Q4_K_M \
  --embedding --pooling last -ub 32768
```
### [*标签*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#mlx)MLX

通过 MLX 进行原生 Apple Silicon 推理。可为所有任务适配器提供全精度、4 位和 8 位量化。
```
import mlx.core as mx
from tokenizers import Tokenizer
from model import JinaEmbeddingModel
import json

with open("config.json") as f:
    config = json.load(f)

model = JinaEmbeddingModel(config)
weights = mx.load("model-4bit.safetensors")  # or model.safetensors, model-8bit.safetensors
model.load_weights(list(weights.items()))

tokenizer = Tokenizer.from_file("tokenizer.json")
texts = ["Query: What is machine learning?"]
embeddings = model.encode(texts, tokenizer)
```
从 Hugging Face 下载：“jinaai/jina-embeddings-v5-text-small-retrieval-mlx”（也可用于文本匹配、分类和聚类适配器）。

## [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#training)训练

这两个模型都是从“**Qwen3-Embedding-4B**”中提炼出来的，这是一个更大的经过训练的嵌入模型。小型变体使用“Qwen3-0.6B-Base”作为其主干，而 Nano 使用 EuroBERT-210m。我们的训练结合了两个互补的信号：

- **嵌入蒸馏**来自 4B 老师通过余弦相似性损失。学生无需指令式提示即可学习近似教师的嵌入空间。这对于标记数据稀缺的语言和任务特别有效。
- **特定于任务的对比损失**（`InfoNCE`）在带有硬负挖掘和批内负的标记查询文档对上。冻结蒸馏后的骨干网后，我们为每个任务类别训练单独的 LoRA 适配器。

我们的消融研究表明，这种组合方法始终优于单独使用任何一种方法。在 MTEB 英语检索中，组合方法在同一主干上实现了**60.1 `nDCG@10`**，而仅蒸馏的结果为 58.6，仅对比的结果为 54.3。

我们还在训练期间应用**GOR（广义正交正则化）**，这鼓励嵌入组件更加均匀地分布。这不会显着提高标准基准测试分数，但它使二进制量化几乎无损，这是内存受限部署的关键属性。

训练中的一些值得注意的观察结果：

- 蒸馏和对比学习以我们最初没有想到的方式互补。
- 从我们的损耗混合物中删除任何单个组件都会降低整体性能。
- 特定于任务的 LoRA 适配器在参数开销可以忽略不计的情况下优于多任务训练。
- GOR 正则化使二进制量化几乎无损，这对于部署来说比边际全精度增益更重要。

## [*标签*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#conclusion)结论

嵌入模型越来越多地用作大型系统中的工具链组件。 LLM 代理调用嵌入 API 来进行检索、记忆和分类，作为代理工作流程的一部分。 OpenClaw 和 OpenViking 等项目将嵌入视为代理上下文管理的核心基础设施层，而不是独立的搜索端点。在这种情况下，每次调用的推理成本和延迟与基准分数一样重要，紧凑模型成为自然选择。

更小的嵌入模型的趋势反映了更广泛的转变。设备上检索、基于浏览器的搜索和边缘部署都需要适合有限内存预算的模型。 Matryoshka 维度支持让单个模型无需重新训练即可服务于高精度和超快速近似搜索。与低至 1-2 位的 GGUF 量化相结合，生产嵌入服务的有效内存占用量下降了一个数量级。

我们正在研究“jina-embeddings-v5-multimodal”，将相同的架构扩展到视觉和跨模态检索。早期结果表明，将视觉编码器与微调的文本嵌入模型对齐是可能的，而不会降低文本性能。敬请关注。
