# jina-embeddings-v5-text：新的 SOTA 小型多语言 embedding

两款 sub-1B 多语言 embedding，具备同类最佳性能，可在 Elastic Inference Service、Llama.cpp 和 MLX 上使用。

jina-embeddings-v5-text：面向任务的 embedding 蒸馏

文本 embedding 模型被广泛用于语义相似度任务，包括信息检索、聚类和分类。通用模型通常采用单阶段或多阶段流程、使用对比损失函数进行训练。我们提出一种新的训练方案，将模型蒸馏技术与任务特定的对比损失相结合，以产出紧凑、高性能的 embedding 模型。我们的发现表明，相比纯对比式或纯蒸馏式的训练范式，这种方法在训练小模型时更为有效。所得模型 jina-embeddings-v5-text-small 和 jina-embeddings-v5-text-nano 的基准分数，超过或持平同等规模模型的最先进水平。jina-embeddings-v5-text 模型还支持多种语言的长文本（small 最高 32K token，nano 为 8K），并生成在截断和二值量化下仍保持稳健的 embedding。模型权重已公开，希望能激励 embedding 模型开发的进一步进展。

我们的第 5 代 embedding：两款轻量级多语言模型，在检索、匹配、聚类和分类上具备 SOTA 性能。

![](https://cms.jina.ai/content/images/icon/favicon-50.ico)jinaai 合集

![](https://cms.jina.ai/content/images/thumbnail/jina-embeddings-v5-text-698a0a5b809aa96a2ff39cdd.png)

我们发布 `jina-embeddings-v5-text`，这是我们 embedding 模型家族的第五代，推进了 sub-1B 多语言 embedding 的质量-效率前沿：

- [jina-embeddings-v5-text-small](https://jina.ai/?sui&model=jina-embeddings-v5-text-small)（**677M** 参数）：MMTEB 上 **67.0**，MTEB English 上 **71.7**
- [jina-embeddings-v5-text-nano](https://jina.ai/?sui&model=jina-embeddings-v5-text-nano)（**239M** 参数）：MMTEB 上 **65.5**，MTEB English 上 **71.0**

small 模型支持 **32K token 上下文（nano 为 8K）**、**4 个任务特定 LoRA adapter**（检索、文本匹配、分类、聚类），以及从 1024 到 32 的 **Matryoshka 维度截断**。在 239M 参数下，nano 模型的检索质量可与参数量两倍的模型相匹敌。

与我们前几代相比：v5-text-small 在检索上持平 [jina-embeddings-v4](https://jina.ai/?sui&model=jina-embeddings-v4)（3.8B），同时体积小 5.6 倍；并在参数量相近的情况下，于所有任务上超越 [jina-embeddings-v3](https://jina.ai/?sui&model=jina-embeddings-v3)（572M）。

| 特性 | v5-text-small | v5-text-nano |
| --- | --- | --- |
| 基座模型 | `Qwen3-0.6B-Base` | `EuroBERT-210m` |
| 参数 | **677M** | **239M** |
| embedding 维度 | 1024 | 768 |
| 上下文长度 | 32,768 | 8,192 |
| 语言 | 119（Qwen3 tokenizer） | 15+（EuroBERT tokenizer） |
| 池化 | Last-token | Last-token |
| LoRA adapter | 4（检索、文本匹配、分类、聚类） |  |
| Matryoshka 维度 | 32-1024 | 32-768 |
| MMTEB 分数 | **67.0** | **65.5** |
| MTEB English | **71.7** | **71.0** |

`v5-text-small` 在 MMTEB 上取得 ****67.0****（在 9 种任务类型的 131 个任务上取平均），比次优的 sub-1B 模型（带指令的 Qwen3-0.6B，64.3）高出 ****+2.7 分****。239M 参数的 nano 模型得分 65.5，击败参数量两倍的模型。

在纯英文评测上，`v5-text-small` 以 ****71.7****（在 7 种任务类型的 41 个任务上取平均）领先所有 sub-1B 多语言模型，紧随其后的是 `KaLM-mini-v2.5`（71.3）和 `v5-text-nano`（71.0）。239M 的 nano 模型以不到一半的体积，达到与 494M 的 KaLM 相当的水平。

在 sub-4B 模型中，`v5-text-small` 在五个检索基准（MTEB Multilingual、MTEB English、RTEB、BEIR 和 LongEmbed）上取得最高的任务级平均（****63.28****），持平 [jina-embeddings-v4](https://jina.ai/?sui&model=jina-embeddings-v4)（3.8B，63.62），同时体积 ****小 5.6 倍****。

根据 2026/02/21 的 [MTEB Leaderboard](https://huggingface.co/spaces/mteb/leaderboard)，`jina-embeddings-v5-small`（0.6B 参数，排名第 8）是 MTEB Multilingual v2 上 1B 参数以下最强的 embedding 模型，在每项指标上都超越 Qwen3-Embedding-0.6b。`jina-embeddings-v5-nano`（0.2B 参数，排名第 11）以极小的体积提供前 11 的性能，该参数级别中没有其他模型能接近。

## [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#architecture)架构

![<code>jina-embeddings-v5-text</code> 架构](https://cms.jina.ai/content/images/2026/02/v5_architecture_1771470917.png)

v5-text 使用 decoder-only 基座，采用 last-token 池化而非 mean 池化。每个 transformer 层注入四个轻量级 LoRA adapter，分别独立处理检索、文本匹配、分类和聚类。用户在推理时选择合适的 adapter。对于检索，查询加上 "Query:" 前缀，文档加上 "Document:"。上下文长度 small 为 32K token（nano 为 8K），相比 v3 提升 4 倍。

## [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#getting-started)快速开始

### [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#elastic-inference-service)Elastic Inference Service

在生产环境中使用 v5-text 的最快方式。Elastic Inference Service（EIS）提供托管的 embedding 推理并内置扩缩容，因此你可以直接在自己的 Elastic 部署中生成 embedding，而无需管理基础设施。

```
PUT _inference/text_embedding/jina-v5
{
  "service": "elastic",
  "service_settings": {
    "model_id": "jina-embeddings-v5-text-small"
  }
}
```

设置细节参见 [EIS 文档](https://www.elastic.co/docs/explore-analyze/elastic-inference/eis)。

### [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#jina-embedding-api)Jina Embedding API

我们的托管 API，采用按 token 计费。开箱即支持任务选择、维度截断和批处理。无需 GPU。

```
curl https://api.jina.ai/v1/embeddings \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "model": "jina-embeddings-v5-text-small",
    "task": "retrieval.query",
    "dimensions": 1024,
    "input": ["What is knowledge distillation?"]
  }'
```

在 [jina.ai/embeddings](https://jina.ai/embeddings) 获取 API key。

### [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#hugging-face-sentence-transformers)Hugging Face + sentence-transformers

在本地运行，完全掌控推理。权重已在 Hugging Face 上提供，并开箱即集成 sentence-transformers。

```
from sentence_transformers import SentenceTransformer
import torch

model = SentenceTransformer(
    "jinaai/jina-embeddings-v5-text-small-retrieval",
    model_kwargs={"dtype": torch.bfloat16},
)

query_emb = model.encode("What is knowledge distillation?", prompt_name="query")
doc_embs = model.encode(["Knowledge distillation transfers...", "Venus is..."], prompt_name="document")
similarity = model.similarity(query_emb, doc_embs)
```

### [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#vllm)vLLM

面向生产工作负载的高吞吐服务。vLLM 原生支持 v5-text，采用 last-token 池化。

```
from vllm import LLM
from vllm.config.pooler import PoolerConfig

model = LLM(
    model="jinaai/jina-embeddings-v5-text-small-retrieval",
    dtype="float16",
    runner="pooling",
    pooler_config=PoolerConfig(seq_pooling_type="LAST", normalize=True),
)
outputs = model.encode(["Query: climate change impacts"], pooling_task="embed")
```

为通过 llama.cpp 和 MLX 优化本地推理，每个任务 adapter 的 LoRA 权重都被合并进基座模型，以产出独立的权重文件。这就是为什么你会看到每个任务（检索、文本匹配、分类、聚类）都有单独的仓库——每个仓库都包含完整的合并权重，可直接加载，推理时没有 LoRA 开销。

### [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#llamacpp-gguf)llama.cpp (GGUF)

在 CPU 或边缘设备上运行量化模型。我们为每个模型提供 14 种 GGUF 量化变体，从 F16 到 IQ1_S。

```
llama-server -hf jinaai/jina-embeddings-v5-text-small-retrieval-GGUF:Q4_K_M \
  --embedding --pooling last -ub 32768
```

### [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#mlx)MLX

通过 MLX 实现原生 Apple Silicon 推理。为所有任务 adapter 提供全精度、4-bit 和 8-bit 量化。

```
import mlx.core as mx
from tokenizers import Tokenizer
from model import JinaEmbeddingModel
import json

with open("config.json") as f:
    config = json.load(f)

model = JinaEmbeddingModel(config)
weights = mx.load("model-4bit.safetensors")  # or model.safetensors, model-8bit.safetensors
model.load_weights(list(weights.items()))

tokenizer = Tokenizer.from_file("tokenizer.json")
texts = ["Query: What is machine learning?"]
embeddings = model.encode(texts, tokenizer)
```

从 Hugging Face 下载：`jinaai/jina-embeddings-v5-text-small-retrieval-mlx`（也提供文本匹配、分类和聚类 adapter）。

## [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#training)训练

两个模型都从 `**Qwen3-Embedding-4B**`（一个大得多的已训练 embedding 模型）蒸馏而来。small 变体使用 `Qwen3-0.6B-Base` 作为基座，而 nano 使用 EuroBERT-210m。我们的训练结合了两种互补信号：

- 通过余弦相似度损失，从 4B teacher 进行 **embedding 蒸馏**。student 学习逼近 teacher 的 embedding 空间，而无需指令式 prompt。这对于标注数据稀缺的语言和任务尤其有效。
- 在标注的查询-文档对上使用 **任务特定对比损失**（`InfoNCE`），配合难负例挖掘和批内负例。冻结蒸馏后的基座之后，我们为每个任务类别训练单独的 LoRA adapter。

我们的消融研究表明，这种组合方法持续优于任一单独方法。在 MTEB English 检索上，组合方法在同一基座上取得 **60.1 `nDCG@10`**，而仅蒸馏为 58.6、仅对比为 54.3。

我们还在训练中应用 **GOR（Generalized Orthogonal Regularization）**，它促使 embedding 各分量分布更均匀。这不会显著提升标准基准分数，但能让二值量化几乎无损——这是内存受限部署的关键特性。

训练中值得注意的几点观察：

- 蒸馏与对比学习以我们起初未曾预料的方式互补。
- 从我们的损失组合中移除任何单一组件，都会全面降低性能。
- 任务特定 LoRA adapter 以可忽略的参数开销优于多任务训练。
- GOR 正则化让二值量化几乎无损，这对部署的意义大于全精度上的边际收益。

## [*tag*](https://jina.ai/news/jina-embeddings-v5-text-distilling-4b-quality-into-sub-1b-multilingual-embeddings/#conclusion)结论

embedding 模型越来越多地被用作更大系统内部的工具链组件。LLM agent 在 agentic 工作流中调用 embedding API 来进行检索、记忆和分类。OpenClaw 和 OpenViking 等项目把 embedding 视为 agent 上下文管理的核心基础设施层，而非独立的搜索 endpoint。在这种格局下，每次调用的推理成本和延迟与基准分数同样重要，紧凑模型成为自然之选。

向更小 embedding 模型发展的趋势反映了更广泛的转变。设备端检索、基于浏览器的搜索和边缘部署，都要求模型能装进受限的内存预算。Matryoshka 维度支持让单个模型无需重训即可同时服务高精度和超快近似搜索。结合低至 1-2 bit 的 GGUF 量化，生产级 embedding 服务的有效内存占用下降一个数量级。

我们正在开发 `jina-embeddings-v5-multimodal`，把同一架构扩展到视觉和跨模态检索。早期结果表明，将视觉 encoder 与经过 fine-tuning 的文本 embedding 模型对齐是可行的，且不会降低文本性能。敬请期待。
