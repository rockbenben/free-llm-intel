下一波个人计算的关键不是更好的应用，而是代表你打理日常的 agents：管理你的日历、分类处理你的收件箱、跟踪你的财务、把你的笔记整理得井井有条。

要让 agent 在生产环境中工作，三件事必须同时成立：模型要准确，要快，还要便宜到可以持续运行。大多数模型只优化其中一两项。Mercury 2 三者兼顾。

我们在 [PinchBench](https://pinchbench.com/) 上评估了 Mercury 2——这个开源基准构建在 OpenClaw 之上，OpenClaw 是 GitHub 历史上增长最快的开源项目，60 天内获得超过 25 万 star。以下是我们的发现。

Mercury 2 定义了 Pareto 前沿：有竞争力的任务表现、业界领先的速度，以及一个让 agent 持续运行在经济上可行的价位。

## PinchBench 是什么？

PinchBench 衡量的是 LLM 作为 [OpenClaw](https://github.com/openclaw) agent「大脑」的表现。它不测孤立能力，而是评估真实的 agent 工作流：安排会议、处理邮件、调研主题、管理文件、编写代码。

它测的正是生产 agent 真正重要的东西：

- **工具使用**——模型能否用正确的参数调用正确的工具？
- **多步推理**——它能否串联多个动作完成复杂任务？
- **真实世界的混乱**——它能否处理含糊的指令和不完整的信息？
- **实际结果**——文件到底创建没有、邮件发送没有、会议排上没有？

关键在于，PinchBench 评估的是质量、成本与延迟的联合权衡——明确揭示一个模型能否用于持续的、真实世界的 agent 部署。

## 为什么这对 Agent 重要

Agent 每个任务要跑几十次推理调用。延迟在每一步上叠加，成本在每一小时上叠加。一个准确但慢的模型只能做演示；一个快但贵的模型无法扩展到持续运行。

Mercury 2 的速度来自一种根本不同的技术路径——并行精化，而非逐 token 生成。速度优势是模型与生俱来的，不依赖专用硬件或压缩。推理级的质量、实时的延迟、标准的 GPU。
