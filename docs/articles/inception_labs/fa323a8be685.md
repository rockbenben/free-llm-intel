今天，我们发布 Mercury 2.5，这是我们迄今能力最强的生产模型。相比 Mercury 2，它的质量显著提升，同时保持同样低延迟、低成本的服务特性。

自 Mercury 2 发布以来，已有数千名开发者用它构建应用，数十家企业将其投入生产，使用量增长了一个数量级以上。如今它服务于搜索、语音和编程产品中对延迟敏感的工作负载。

这些工作负载给出的信号比单靠基准测试更清晰。我们利用客户反馈和生产中的失败案例来改进 evals、聚焦训练。Mercury 2.5 就是这一闭环的首个成果。

## 有哪些变化

Mercury 2.5 是市面上能力最强的 diffusion LLM。据我们所知，它是迄今训练过的规模最大的 diffusion 语言模型。

- **质量：** 相比 Mercury 2，智能提升 40%。可与 GPT-5.6 Luna (Low)、Gemini 3.5 Flash-Lite 和 Claude Haiku 4.5 等成本优化的前沿模型相媲美。
- **速度：** 在广泛可用的 NVIDIA GPU 上达到每秒 1,107 个 token。
- **上下文：** 260K token。
- **价格：** 每百万输入 token $0.20、每百万输出 token $0.75。发布时，Mercury 2.5 降价 80%，为每百万输入 token $0.04、每百万输出 token $0.15。
- **能力：** 可调的推理、并行工具调用，以及与 schema 对齐的 JSON。

自 Mercury 2 发布以来，我们看到 Inception 在 NVIDIA AI 基础设施上进一步推进了基于 diffusion 的语言模型。Mercury 2.5 在智能上的跃升，加上持续保持的速度与低成本，反映出新架构在 NVIDIA 平台上能多快成熟为可投入生产的系统。

Shruti Koparkar，NVIDIA 加速计算事业部产品高级经理

## Mercury 在生产环境中

### 搜索 Agent 与 RAG 流水线

一次搜索请求可能触发数十次模型调用：规划搜索、重写查询、重排结果、结构化事实、总结来源、核对答案。Mercury 让这些调用足够快，能控制在一次用户交互之内。目前已有数家领先的搜索基础设施公司在生产环境中运行它。

### 语音 Agent 与交互式应用

在语音场景中，延迟不是基础设施细节，而是来电者听到的那一段停顿。

OpenCall 构建处理实时客户来电的 AI 电话 Agent。在其生产工作负载上，Mercury 把模型响应延迟的中位数压到了接近 170 毫秒。

![](https://i.ytimg.com/vi_webp/9_58fpiCIOI/sddefault.webp)

改用 Mercury 后，我们的 P99 响应时间从几分钟降到了仅 1 秒，P50 从 0.4 秒降到了 0.2 秒以内——比我们见过的任何其他提供商都快得多，而且这还包含了推理。

Oliver Silverstein，OpenCall 联合创始人兼 CEO

- **阅读更多： **[**第一个快到足以接起电话的推理模型**](https://www.inceptionlabs.ai/blog/mercury-2-the-first-reasoning-model-fast-enough-to-pick-up-the-phone)

### 编程 subagent 与助手

编程 Agent 已经会把工作分摊到多个模型上。一个模型可能负责规划或写代码，另一些负责搜索、运行工具、路由请求、总结状态，或压缩较长的会话。这些辅助调用会反复发生，因此延迟和成本会迅速累加。

Augment Code 把 Mercury 用于上下文压缩、模型路由和 MCP 工具搜索。把压缩环节迁到 Mercury 后，延迟降低了 82%，从约 150 秒降到 27 秒，成本降低了 90%，同时质量保持不变。工具搜索的摘要在 1 秒内即可返回。

同样的速度也适用于 Web 应用开发。在下面的演示中，可以看到 Mercury 2.5 仅凭几条 prompt 就生成一个可运行的音乐发现日志 Web 应用。

## Mercury Voice 与 Mercury Router 预览版

除 Mercury 2.5 之外，我们还宣布 [Mercury Voice](https://www.inceptionlabs.ai/models) 和 [Mercury Router](https://www.inceptionlabs.ai/models) 的预览版。

- Mercury Voice 的首 token 时间 (TTFT) 低于 170 毫秒，是一款为延迟预算最紧的语音 Agent 优化的 dLLM。
- Mercury Router 用 dLLM 理解传入的 prompt，并把它们路由到在质量、速度和成本上组合最优的模型（开放模型和闭源模型）。
