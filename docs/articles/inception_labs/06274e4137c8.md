[SearchBlox](about:blank) 正在为电商、客户服务、知识管理、法务和数字平台等各行业的企业提供快速、懂上下文的搜索与 RAG。为在企业规模下支撑 AI，企业需要同时具备速度、准确率和可预期成本的方案。

SearchBlox SearchAI 现已集成 **Inception 的 Mercury dLLM**，解锁超低延迟、低成本的规模化 GenAI。这一合作让 SearchBlox 客户即便在企业级负载上也能获得亚秒级的 GenAI 响应。

## 挑战：生产规模下的速度与成本

部署 GenAI 搜索的企业面对一个根本性的张力：传统自回归 LLM 有质量，但其延迟和成本让实时应用既慢又贵。对电商产品问答、客户支持、员工知识助手之类的用例，响应时间直接影响满意度。

SearchBlox 需要一个既能处理实时查询、又不牺牲准确率、也不让基础设施成本失控的方案。

> “速度如今是企业 AI 的决定性差异点。我们与 Inception 的合作让实时 GenAI 成为可行的现实。无论是客户支持、合规、风控、分析还是电商，每一位 SearchAI 客户都能从覆盖其全部数据的亚秒级智能中受益。”——Timo Selvaraj，SearchBlox 首席产品官

## 方案：Mercury 进入 SearchAI 的 RAG 流水线

在非结构化文本上实现快速、准确的大规模推理，正是 SearchAI 流水线采用 Mercury 的原因。Diffusion 生成给了 Mercury 一条并行精化的路径，使企业搜索能以一致的亚秒延迟运行。

SearchBlox 也评估过其他轻量模型，但它们要么延迟更高，要么无法在 SearchAI 处理的任务范围内保持质量。Mercury 的架构即使在突发式的企业负载下也能提供可预期的性能——这对响应时间不稳定就会损害用户体验的面向客户的应用至关重要。

SearchBlox 把 Mercury 集成进 SearchAI 架构，作为其 LLM 抽象层内的一个模型端点。集成过程无需重构，也无需重写流水线。

Mercury 与以下组件并排接入现有的 RAG 流水线：

- 混合搜索
- 上下文构建器与元数据增强
- 查询改写
- SearchAI PreText NLP
- 向量与关键词融合
- SmartFAQs
- 电商搜索体验

这次集成保留了 SearchAI 客户已经依赖的一切，同时大幅改善了速度和成本。

## 企业搜索的成果

**能规模化的速度。**即使在高负载的企业工作负载下，Mercury 也能提供亚秒级推理。对 SearchBlox 客户来说，这意味着产品问答、智能 FAQ 和知识检索都近乎即时——无论处理十个查询还是上万个。

**推理成本降低 60% 到 90%。**与使用自回归 LLM 相比，Mercury 大幅降低了 SearchBlox 的计算成本。结合 SearchBlox 的固定成本授权模式，企业获得可持续的 GenAI 搜索经济性。

**安全的部署。**SearchAI 客户可以在 AWS Bedrock 或 Azure Foundry 上部署 Mercury，确保数据从不离开他们的私有云实例，并继承 AWS 或 Azure 完整的安全、合规与治理框架。

**靠上下文换来的更好质量。**借助 SearchAI 的 RAG 与元数据自动化，Mercury 获得更高的 grounding 准确率、更好的领域感知摘要、针对每个用户和工作流的个性化输出、多语言支持，以及对嘈杂企业数据更高的容错。结果是每次交互都高度相关。
