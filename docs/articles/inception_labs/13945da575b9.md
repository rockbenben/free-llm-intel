今天，TIME 把 Mercury 2 列入其 2026 年度最佳发明榜单的人工智能类别。Mercury 2 是第一个为推理而构建的 diffusion LLM，我们很高兴看到自己在语言模型架构上的这套新做法，能与今年其他入选者一同获得认可。[查看完整榜单](https://time.com/collection/best-inventions/2026/inception-mercury-2/?filters=AI)。

感谢我们的客户、我们的投资人，以及那支多年来一直押注「语言模型不必一个字一个字地写」的团队。

## 一个新的根基

AI 如今运行在 coding 助手、voice agent、搜索系统、copilot，以及在更大循环里反复执行动作的 agentic 工作流之中。每一步都会增加延迟，而推理增加得更多。

原因在于架构。今天几乎所有在生产环境里运行的 LLM 都是自回归的。它一次生成一个 token，所以模型想得越多，用户等得就越久，每完成一项任务的成本也就越高。这个行业已经花了数十亿美元绕开这个限制，靠的是专用芯片、优化过的 serving 技术栈以及模型压缩。这些权宜之计确实有用，但它们把底层架构原样留了下来。

## 把 diffusion 用到语言上

Mercury 2 构建在 diffusion 之上——也就是现代图像与视频生成背后的那套方法——如今被应用于语言。它不像打字机那样一次敲定一个 token，而是像一位编辑：并行生成大量 token，并在若干轮 passes 中不断打磨它们。

Mercury 2 每秒生成超过 1,000 个 token，比领先的 speed-optimized LLM 快 5 倍以上。

速度只是故事的一部分。随着 AI 基础设施成本攀升、数据中心为满足需求而吃力支撑，每一个 token 都要付出算力、电力和冷却水的代价。自回归生成让 GPU 大部分时间都在等内存。Mercury 2 给了它们与生俱来擅长的那种密集并行工作，在随处可得的 NVIDIA GPU 上，每个 GPU 周期、每单位能耗都能产出更多输出。

## 此后：Mercury 2.5、Mercury Voice、Mercury Router、Mercury Decide

Mercury 2 于二月发布。九月，我们随后推出了 Mercury 2.5，这是我们迄今能力最强的生产模型。它在质量上相比 Mercury 2 是一次显著提升，同时保持同样的低延迟、低成本 serving 特征。Mercury Voice 是我们为 voice agent 优化的 dLLM，首个 token 时间（time-to-first-token）低于 170ms；Mercury Router 理解用户 prompt，并按质量、速度和成本把任务路由到最合适的模型；Mercury Decide 则是一个 System One 决策模型，被 [ValsAI ](https://www.vals.ai/blogs/evaluation-of-mercury-decide)评为比 Jev 更准确、也更便宜。
