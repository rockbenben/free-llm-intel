# Vibe 中的远程 Agent，由 Mistral Medium 3.5 驱动

Mistral 把编码 Agent 搬上了云端，通过 Mistral Medium 3.5——一款为长周期编码与生产力工作优化的全新 128B 开放权重模型——实现并行、异步的任务执行。此次更新在 Mistral Vibe 和 Le Chat 中引入远程 Agent，并为研究、跨工具工作流等多步任务推出全新的 Work 模式，同时全程为敏感操作保留人工监督。Mistral Medium 3.5 今天在 Pro、Team 与 Enterprise 计划上可用，定价为每百万输入 token $1.5、每百万输出 token $7.5。

编码 Agent 大多一直住在你笔记本上。今天我们把它们搬上云端：它们自主运行、并行工作，完成后通知你。你可以从 [Mistral Vibe CLI](https://mistral.ai/products/vibe) 或直接在 Le Chat 里启动它们，在不离开对话的情况下卸载一个编码任务。

为这一切提供动力的是处于公开预览的 Mistral Medium 3.5——我们在 Mistral Vibe 和 Le Chat 中的新默认模型，为编码与生产力工作的长时间运行而造。Le Chat 中的新 Work 模式（预览）在此基础上扩展出一个强大 Agent，处理研究、分析与跨工具操作等复杂多步任务。

## 亮点。

- Mistral Medium 3.5，一款新旗舰模型，把指令遵循、推理与编码融合进单个 128B dense 模型。以开放权重、修改版 MIT 许可证发布。
- 真实场景表现强劲，而其体量足以在少至 4 块 GPU 上自托管运行。
- 用于异步编码的 Mistral Vibe 远程 Agent：会话运行在云端，可从 CLI 或 Le Chat 派出，本地 CLI 会话还可以"传送"上云。
- 在 Le Chat 中启动 Mistral Vibe 编码任务。会话运行在同一个远程运行时上，你走开也继续推进。
- Le Chat 的 Work 模式由一个新 Agent 驱动，基于 Mistral Medium 3.5，逐步处理多步任务，并行调用工具直至完成。

## Mistral Medium 3.5。

Mistral Medium 3.5 是我们首个融合的旗舰模型，现已公开预览。它是一个 128B dense 模型，上下文窗口 256k，用一整套权重同时处理指令遵循、推理与编码。它在真实使用中表现强劲，最少 4 块 GPU 即可自托管。推理强度（reasoning effort）现在可按请求配置，同一模型既能秒回闲聊，也能攻坚复杂的 Agent 长跑。我们从零训练了视觉编码器，以支持可变图像尺寸与宽高比。

Mistral Medium 3.5 在 SWE-Bench Verified 上得分 77.6%，领先 [Devstral 2](https://mistral.ai/news/devstral-2-vibe-cli) 以及 Qwen3.5 397B A17B 等模型。它的 Agent 能力同样出色，在 τ³-Telecom 上得分 91.4。

这个模型为长周期任务而生：可靠地调用多个工具，产出下游代码可消费的结构化输出。正是它，让 Vibe 中的异步云端 Agent 具备了可交付的实用性。

Mistral Medium 3.5 成为 Le Chat 的默认模型，并在我们的编码 Agent Vibe CLI 中接替 Devstral 2。

## Vibe 远程 Agent。

从今天起，编码会话可以在你离开时继续攻坚长任务。许多会话可以并行运行，你不再充当 Agent 每一步的瓶颈。

你可以从 Mistral Vibe CLI 或 Le Chat 启动云端 Agent。运行期间，你可以查看 Agent 在做什么——文件 diff、工具调用、进度状态，以及随时冒出的提问。进行中的本地 CLI 会话，在你希望让它继续运行时可以传送到云端，会话历史、任务状态与审批都会随之迁移。

![None](https://mistral.ai/_astro/schema_Z1wpYoe.webp?dpl=6abbd11780b53c00082eea6f)

Vibe 位于工程团队现有系统之间，在需要人的环节保留人在环。它接入 GitHub 处理代码与 pull request，接入 Linear 和 Jira 处理 issue，接入 Sentry 处理事故，并接入 Slack 或 Teams 等应用做汇报。

每个编码会话都运行在隔离沙箱中，包括大范围编辑与安装。工作完成后，Agent 可以在 GitHub 上开一个 pull request 并通知你——于是你审阅的是结果，而不是产生结果的每一次按键。

它契合那些耗时但不需要开发者判断力的高量、定义清晰的工作：模块重构、测试生成、依赖升级、CI 排查以及 bug 修复。

我们使用在 [Mistral Studio](https://mistral.ai/products/studio) 中编排的 [Workflows](https://mistral.ai/news/workflows)，把 Mistral Vibe 带进 Le Chat。我们最初为自家内部编码环境构建这套东西，然后服务于我们的[企业客户](https://mistral.ai/customers)。今天这一能力向所有人开放，大家现在可以从网页启动编码任务。而且，不必绑定本地终端，开发者可以并行运行多个任务。

你可以直接在 Le Chat 中启动编码会话：对话里描述的任务会运行在与 CLI 和网页相同的远程运行时上，稍后以一个完成的分支或 PR 草稿回到你面前。

## Le Chat 全新 Work 模式（预览）。

Work 模式是 Le Chat 中面向复杂任务的强大 Agent 模式，由全新 harness 与 Mistral Medium 3.5 驱动。Agent 成为助手本身的执行后端，于是 Le Chat 能够读写、同时使用多个工具，并推进多步项目直到完成你交代的事。

以下是 Work 模式今天就能让你做的事。

- 跨工具工作流：在一次运行中同步邮件、消息与日历；结合与会者上下文、从你的数据源拉取的最新新闻与谈话要点，为会议做准备。
- 研究与综合：跨网页、内部文档与已连接工具深挖一个主题，产出结构化的简报或报告，你可以编辑后再导出或发送。
- 整理收件箱并起草回复；从团队和客户的讨论中在 Jira 里建 issue；把摘要发到你的 Slack 团队。

会话的存续时间比典型的聊天回复长得多，因此 Agent 能跨越许多轮次、经历反复试错、一路走到完成。在 Work 模式中，连接器默认开启而非手动选择，这让 Agent 能伸入文档、邮箱、日历及其他系统，获取正确行动所需的丰富上下文。

Agent 的每个动作都可见：你能看到每次工具调用及其推理依据。对发消息、写文档、修改数据等敏感任务，Le Chat 会（依据你的权限设置）先请求明确批准再执行。
