# 发布 Mistral OCR 4

今天我们发布 Mistral OCR 4，它在提取文本之外，还提供边界框（bounding box）、区块分类（block classification）和内联置信度分数。模型支持 10 个语系下的 170 种语言，可在单一容器中运行以支撑完全自托管部署，并作为[企业搜索、RAG 与领域定制检索管线](https://mistral.ai/news/search-toolkit/)的摄取组件。OCR 4 是一个小而专注的模型。本文将介绍新特性、它在公开与内部基准上的表现、这些基准的已知局限，以及何时该用模型 API、何时该用 Document AI 的指引。

## **亮点**

- **突破性性能。**独立标注员在所有参测的 OCR 与文档 AI 系统中更偏好 OCR 4，平均胜率 72%；同时在 OlmOCRBench 上取得最高综合分（85.20）。方法论与已知评分局限见下文"基准"部分。
- **是分割理解，不只是文本。**在提取文本之外，OCR 4 还返回边界框、类型化区块分类（标题、表格、公式、签名等）以及内联置信度分数。边界框是我们被请求最多的能力，可为上下文内高亮和可靠数据管线定位文本。同时，区块类型与置信度分数可支撑引用溯源、脱敏（redaction）与人在环验证。
- **与 Mistral Search Toolkit 集成（公开预览）。**OCR 4 是 [Search Toolkit](https://mistral.ai/news/search-toolkit/) 的摄取组件——这是 Mistral 在 AI Now Summit 上发布的开源、可组合搜索框架。其结构化输出为该工具包的摄取、检索与评估工作流提供可直接引用的输入，服务 RAG 与企业搜索。
- **多语言覆盖。**支持 10 个语系下的 170 种语言，并在多个竞品系统性能下滑的专业与低资源语言上取得可度量的提升。
- **跑在你自己的基础设施上。**OCR 4 足够紧凑，可在单容器部署，让文档数据留在你的环境中以满足驻留、主权与合规要求，同时支持高性价比的高吞吐批处理。自管部署面向企业客户开放。

## **总览**

Mistral OCR 4 从各类文档中抽取并结构化内容。此前几代专注于把页面转换为干净的文本和表格，而 OCR 4 返回的是文档的结构化表示。每个区块都有边界框定位、按类型分类，并逐页、逐词生成内联置信度分数。因此，下游系统不仅知道文档*说了什么*，还知道每个元素*在哪里*、扮演*什么角色*，以及模型对每个区域的*把握有多大*。

这一结构支撑多种下游负载：

- **面向 RAG 的语义分块**：干净、已分类的区块成为更好的检索单元。
- **Agent 的结构原语**：Agent 从阅读文档升级为对文档采取行动（表单填写、发票处理、合规检查）。
- **面向连接器的结构化内容**：为摄取与索引管线提供一致的、类型化的输出。

OCR 4 接受常见企业格式，包括 PDF、DOC、PPT 与 OpenDocument，并支持 10 个语系下的 170 种语言，涵盖许多系统处理不佳的专业与低资源语言。作为可单容器部署的紧凑模型，它既适合成本敏感部署，也适合大批量部署。它可以完全自托管运行，让有数据主权要求的组织把文档数据留在自己的基础设施内。

开发者可通过 API 集成模型；团队也可以在 Mistral Studio 中使用 [Document AI](https://mistral.ai/solutions/document-ai/)，以应用级、无代码的方式访问同一引擎。通过 API 的 Mistral OCR 4 定价为每 1,000 页 $4，使用 Batch API 可享 50% 折扣，成本降至每 1,000 页 $2。Document AI 定价为每 1,000 页 $5。

## **基准**

> "我们在一个图表密集的金融 QA 数据集上，把 Mistral OCR 4 与领先的 Agent 化文档解析器做了对比，结果以约 1/8 的成本和 1/17 的延迟达到了相当的准确率。对于规模化的生产用例，这个差距会迅速复利放大。" —— Aidan Donohue，Rogo AI 工程师

为评估 OCR 4，我们将其与领先的 AI 原生 OCR 模型、前沿通用模型、企业文档服务以及我们自家的 Mistral OCR 3 进行了对比。

### **人类偏好评估**

自动化基准带有上文所述的评分缺陷，因此我们补充了一场以真实使用场景文档为素材的一对一人评。我们收集了 12+ 种语言的 600+ 份文档，来源为第三方供应商，用以代表真实行业用例，并请独立标注员在盲测条件下逐文档把每个竞品的输出与 OCR 4 的输出对比排序。

在所有参测系统中，标注员在大多数文档上更偏好 OCR 4。由于这些是针对真实文档的人类判断，而非对固定参考文本的字符串比对，它们绕开了影响自动化评分的大部分标注与格式噪声。

### **总体表现**

> "Mistral OCR 的每页速度约为我们现有供应商的 4 倍——对于速度直接影响客户 IP 时限管理的批量案件登记（docketing）工作流来说，这是了不起的结果。" —— Ivan Mihailov，Anaqua AI 工程师

除了在人评中位列第一，OCR 4 还在公开基准 **OlmOCRBench（85.20）**上取得我们参测模型中的最高综合分，并在内部 **Crawl Multilingual 评估（.98）**上领先——超过 AI 原生与企业方案。

在 **OmniDocBench** 上，OCR 4 得分 **93.07**。我们报告这个数字时附带提醒：**OlmOCRBench** 和 **OmniDocBench** 对某些输出的评分方式存在已知局限，单一综合数字既可能低估也可能高估真实性能。

当我们审计造成失分的差异时，发现多数不是模型错误，而是基准比对输出方式的产物。反复出现的类别有：

- **标准答案（ground truth）本身错误。**一些参考标注就是错的：缺失或多出的文本、对脱敏区域的转写、或错别字（例如参考文献里引用作者姓名拼错了，而模型从页面上读对了）。输出与源文档一致，却仍被判错。
- **等价的数学记法。**渲染结果完全相同的不同 LaTeX 写法被计为不匹配——渲染出的公式是对的，字符串比对不是。
- **公式切分方式。**一个表达式是作为单个公式输出还是拆成若干行内片段，会影响匹配——即便渲染内容完全相同，因为匹配器无法把碎片对齐。
- **多栏阅读顺序。**跨栏边界被拆开的单词（例如 "certifi-cates"）以及栏序假设，会让正确的提取被判为阅读顺序失败。
- **区块类型归属。**基准不期望输出中包含页眉/页脚。为消解这一点，我们在评分前从输出中剥离页眉页脚。但测试随后会检查一个恰好也是页面标题的字符串——它本应存在——从而误报。

这些产物集中在数学、科学与多栏文档上，而且它们惩罚正确输出的次数多于奖励错误输出。因此我们把综合分数视作方向性参考而非定论。

这些基准只是方向性的。所有竞品分数均为我们的内部复现。我们建议在你自己的文档上做评估。

### **性能细节**

**Crawl Multilingual 细分。**在我们的内部多语言评估中，OCR 4 在全部八个语系上领先——英语、西欧、东欧、中东、中文、东亚、东南亚及专业语言（印地语、日语、格鲁吉亚语、孟加拉语、亚美尼亚语、希伯来语、希腊语、古吉拉特语、泰米尔语、马拉雅拉姆语、卡纳达语、泰卢固语）。差距在专业与低资源语言上最大：许多竞品系统在这些语言上急剧退化，而 OCR 4 保持高精度。

## **推荐用例**

OCR 4 同时支撑高吞吐管线和交互式文档工作流，包括：

- **文档解析与抽取：**复杂、多语言文档。
- **检索增强生成（RAG）：**为语义分块和溯源回答提供结构化、已分类、可直接引用的内容。配合 [Search Toolkit](https://mistral.ai/news/search-toolkit/)，OCR 4 的输出可直接喂入检索管线。
- **Agent 工作流：**为 Agent 提供完成表单填写、发票处理、合规检查等任务的结构原语，尤其适用于法律、金融服务与医疗。
- **利用置信度分数的结构化数据管线，让人工校验者高效发挥作用：**表单/发票抽取、脱敏与合规驱动流程。
- **企业搜索与知识库：**OCR 作为自定义摄取与实体抽取的数据源组件。

早期用户正把 OCR 4 用于把发票转成结构化字段、归档公司资料数字化、从技术与科学报告中提取干净文本，以及驱动企业搜索。

**关于超出适用范围的说明。**OCR 4 是一个文档理解模型，不是决策者。它**不**适用于医疗诊断、法律建议或裁决、高风险金融决策、安全关键系统、实时/延迟敏感处理，或非文档输入（原始音频、视频等）。

### **OCR 4 API：理解你的选项**

Mistral 的 OCR 4 通过单一 API endpoint 提供。每个请求都运行同一个底层 OCR 模型，并且始终返回抽取内容、边界框、区块类型、置信度分数和 markdown 结构的文本。变量在于你在其上叠加多少功能。

**当你希望达成以下目标时，使用 OCR 4 的纯抽取模式：**

- 把快速准确的文档抽取直接嵌入你的应用、Agent 或数据管线。
- 直接处理原始响应——边界框、区块类型与置信度分数——驱动自定义下游逻辑。
- 借助 Batch API 运行大批量或批处理摄取，完全掌控吞吐与成本。
- 为满足严格的数据隐私、主权或合规要求而自托管。

**当你希望获得以下能力时，启用 Document AI（同一 endpoint，附加参数）：**

- 按你定义的 schema 返回结构化 JSON——把 JSON schema 与文档一同传入，OCR 输出会交给 `mistral-small-2603` 生成符合你规范的内容。
- 传入图像标注 schema，为检测到的图像加上结构化 JSON 标注——这会为每张图像触发额外的视觉-语言模型调用。
- 在 JSON schema 之外使用自定义 prompt，引导如何解释或总结整篇文档的抽取内容。
- 让业务人员、解决方案团队或试点项目在不写下游解析逻辑的情况下产出结构化结果。

实用决策规则：如果你需要原始抽取内容，直接用 OCR 4 即可。如果你需要把输出重塑为结构化格式、加注领域字段，或用自定义指令进一步处理，就在同一次调用中加入 Document AI 参数。无论如何你都会拿到 OCR 结果；Document AI 只是在其上叠加结构化层。
