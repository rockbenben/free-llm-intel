今天，我们发布 Workflows 的公开预览。Workflows 是企业 AI 的编排层。它带来把 AI 驱动的流程从概念验证可靠地推向生产所需的持久性、可观测性与容错能力。**ASML、ABANCA、CMA-CGM、France Travail、La Banque Postale、Moeve** 等组织已经在用 Workflows 自动化关键流程。

如今的企业团队用得上强大的模型，缺的是让它们在生产中可靠运行的方法。这在我们合作的每个行业都看得到。故障模式高度一致：在 notebook 里能跑、一进生产就静默失败且无迹可查的流水线；扛不住一次网络超时的长时流程；执行中需要人工审批、却没有任何暂停/恢复机制的多步操作；以及部署后无从验证"是否还在做该做的事"的系统。

要自建解决这些挑战的全部能力，对企业来说是数月的复杂工程：编排层得从零拼装，而它连接的那些组件——推理、agents、连接器、可观测性——各自来自不同工具，有不同的接口和格式。

Workflows 是 Studio 的一部分，因此编排层与被编排的组件天然为一体。一旦确定了业务流程，开发者用 Python 编写工作流。每个工作流随后可发布到 Le Chat，让组织里的任何人触发。每一步都在 Studio 中被追踪、可审计。把这一切聚在一起，Workflows 让你的组织能在几天内从识别用例走到生产运行。

## 真实世界中的 Workflows

如前所述，Mistral AI 的客户已经在用 Workflows 自动化业务流程并投入生产。以下例子展示持久性、可观测性和人工审批在实践中如何运作。

**货物放行自动化。**

全球航运靠单证运转。一次货物放行可能涉及海关申报、危险品分类、安全检查和跨多个司法辖区的监管核查。漏掉一步就可能导致货物在港口延误，甚至违反合规。

这类用例的运营要求是：系统必须扛得住间歇性超时、执行中途能为人工审查暂停，并且在出错时给出确切的"哪里出错、为何出错"的记录。

借助 Workflows，一位客户端到端地自动化了这一切。工作流按海关规则校验每一份进线单证、检查异常、标记需要人工签核的事项、等待批准后放行货物。在 Workflows 中，人工审批步骤只是一行代码：wait_for_input()。工作流暂停、不限时地等待且不消耗算力、通知审查人，然后从暂停处精确恢复。Studio 记录完整的执行历史。

**文档合规检查。**

KYC 审查手工、重复且耗时。一次客户开户可能需要提取身份证件、对照制裁名单和 PEP 数据库核验、交叉参照多个辖区的监管要求，并产出一份带证据支撑的结构化风险评估。手工完成时，每件案例要消耗分析师数小时。

这里的运营要求是速度与可审计性。自动化这类流程的系统既要快，又要为满足监管要求记录步骤及其背后的推理。

借助 Workflows，整个审查流程只需几分钟，而 Studio 把每一步呈现为结构化时间线，可下钻到任意细节层级，并原生支持 OpenTelemetry 追溯到具体 trace。

**客服工单分诊。**

支持团队面对的是吞吐量：退款请求、技术问题、计费纠纷、账户升级。快速一致地路由到正确的团队，决定了问题解决时长。

这里的运营要求是可纠正性。自动化路由必然有错。出错时，团队需要看到工单为何被这样路由，并在不重新训练模型的前提下修正。

借助 Workflows，进线工单会被分析、按意图和紧急度分类，并自动路由到正确的下游流程。每个路由决策在 Studio 中都可见、可追溯。分类错了，团队在工作流层面直接修正。

## 为什么选 Workflows

- **持久执行。**Workflows 在每一步追踪状态。流程失败后从断点恢复。于是开发者可以把精力放在业务逻辑而非恢复逻辑上。
- **可观测性。**每个分支、重试和状态变化都记录在 Studio 中。若某决策数月后需要追查，完整时间线就在那里展示它如何达成。
- **人在回路（human-in-the-loop）。**一行代码即可让工作流暂停等待审批。审查人通过 Le Chat、webhook 或任何已接入界面响应，工作流从停止处继续。
- **Studio 原生。**Workflows 与 Studio 其余部分共用同样的 agents 和连接器，无需单独的集成工作。
- **企业就绪。**Studio 内的 Workspace 隔离团队与项目，基于角色的访问控制（RBAC）确保规则被一致执行。
- **为开发者与业务团队而建。**工程师以代码编写工作流，业务团队在 Le Chat 中运行它们。
- **部署灵活性。**控制平面运行在 Mistral。Worker 与数据处理运行在你的环境里，就在你的关键服务所在处：云、本地或混合。

## 底层实现

Workflows 构建在 Temporal 的持久执行引擎之上——正是驱动 Netflix、Stripe 和 Salesforce 编排的同一套基础设施。我们针对 AI 负载做了扩展：加入流式传输、payload 处理、多租户，以及核心引擎开箱不具备的可观测性。

部署模型在 Mistral 与你的环境之间分工，并把控制平面与数据平面分离。Mistral 托管编排基础设施：Temporal 集群、Workflows API 和 Studio。你用独立的 Helm chart 在自己的 Kubernetes 环境部署 worker，它们通过安全凭证连回中心集群。你的数据和业务逻辑留在你的边界之内。

Mistral SDK 通过装饰器和单行配置处理重试策略、链路追踪、超时、限流和人在回路，你要写的只剩业务逻辑本身。

## 开始使用

Python SDK 是开发者编写和运行工作流的方式。v3.0 现已公开可用，一条命令即可安装：

```
uv add mistralai-workflows
```
