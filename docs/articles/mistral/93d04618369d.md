# Leanstral 1.5：让丰饶的证明人人可用

自发布以来，Leanstral 为 [Lean 4](https://leanprover.github.io/) 中的证明工程提供了一条开放、务实的路径。今天我们发布 **Leanstral 1.5**——一款免费、Apache-2.0 许可的模型，总参数 119B、激活参数仅 6B，带来一次性能升级，让形式化验证比以往更强大、更易得。

Leanstral 1.5 **在 miniF2F 上饱和**，**解出 587/672 道 PutnamBench 题目**，并在 **FATE-H 上取得 87%**、**FATE-X 上取得 34%** 的最新 SOTA。超越基准之外，它还能验证复杂代码性质，**并在开源仓库中发现此前未知的 bug**——证明严格的正式方法既有效又实用，可以落地到真实世界。

## **训练 Leanstral**

Leanstral 1.5 经历三阶段流程：mid-training、监督微调，以及使用 CISPO 的强化学习。Leanstral 1.5 在两个 RL 环境中进行了大量训练：

在**多轮环境**中，模型拿到一个定理陈述，必须证明或证伪它。模型提交证明、接收 Lean 编译器反馈，并在每次尝试中改进方法。证明能通过编译即成功；否则循环继续，直到模型解题或耗尽预算。

在**代码 Agent 环境**中，Leanstral 像一名在裸文件系统中工作的开发者：编辑文件、运行 bash 命令，并使用 Lean 语言服务器实时查看目标、错误和类型信息。这使它足以处理长周期任务，如补全仓库中的部分证明、构建辅助引理，并在多轮上下文压缩中坚持不懈。模型学会驾驭完整的证明工程工作流，最终由 [我们对 SafeVerify 的 fork](https://github.com/mistralai/LeanstralSafeVerify) 在给定目标定理列表时校验其正确性。

## **评测**

我们在以下基准上评测 Leanstral：

- **miniF2F** 是跨系统的形式化数学基准，题目从初等问题到 IMO 级挑战，考察代数、组合与数论中的多样证明能力。
- **PutnamBench** 由 672 道 Putnam 数学竞赛题组成，需要深度推理和长证明链才能解决具有挑战性的数学问题。
- **FATE-H 与 FATE-X** 分别是硕士与博士级难度的抽象代数基准，考察群论、环论、模论等领域的 advanced 推理。
- **FLTEval** 基于费马大定理仓库的真实 pull request，以真实复杂度检验实用证明工程。

我们在 miniF2F 上完全饱和，验证集与测试集均达 100%。在 PutnamBench 与 FATE-H/X 上，我们将 Leanstral 1.5 与不带自然语言引导的 Goedel-Architect、high 设置下的 Seed-Prover 1.5 以及 AxProverBase 比较。Leanstral 在 FATE-H/X 上创下新 SOTA，分别解出 87 和 34 题。在 PutnamBench 上，它以远低于对手的代价超过 Seed-Prover 1.5 high 共 7 题：每道题约 $4，而 Seed-Prover 估计每道题 $300 以上——其 high 设置按每题 10 个 H20-天的预算运行。排名更高的证明器都是在不同条件下运行的——有的获得自然语言证明引导，有的运行成本高得多，如每题 $54–68 的 Aleph Prover。

Leanstral 1.5 展现出我们见过的主流形式推理模型中最强的测试时扩展能力。下图跟踪了当每题尝试的 token 预算从 25k 提升到 4M 时 PutnamBench 上的 Pass@8：性能全程平滑且单调爬升，从 50k 时的 44 题，到 200k 时的 244 题、1M 时的 493 题、4M 时的 587 题。Leanstral 没有在证明变长时放弃，而是在数百万 token 中持续推理、编辑文件、反复修订，把预算直接转化为解题数——这正是下文 AVL 树证明背后的同一行为：它运行了超过 270 万 token，历经 22 次压缩。

随本次发布，我们还完全开源了 [FLTEval](https://github.com/mistralai/FLTEval)。Leanstral 1.5 把该基准的 pass@1 从 21.9 提升到 28.9，pass@8 从 31.9 提升到 43.2，以七分之一的成本超越了 Opus 4.6 的 39.6。它相对规模为其 3–10 倍的开源模型的领先优势也进一步扩大，如下图所示。

## **代码验证案例研究**

尽管主要面向数学训练，Leanstral 1.5 在代码验证上展现出强大能力。我们呈现两个关键案例以说明其影响。

### **AVL 树：证明时间复杂度**

AVL 树是自平衡二叉搜索树，通过插入和删除时的再平衡维持 O(log n) 的高度。Leanstral 1.5 为一个真实实现证明了这些时间复杂度保证——任务要求用结构归纳镜像树的递归结构、小心处理 monadic 的时间追踪，并对再平衡路径做穷尽案例分析。在 270 万 token 和 22 次压缩中，Leanstral 系统地逐层展开 TimeM monad，暴露出与控制流交织在一起的底层计算。它为插入建立了几乎紧的界：每单位高度 48 步加一个常数项，然后通过是对数关系把高度与树规模连接起来，交付了完整、经过验证的证明：插入与删除确实是 O(log n)。

### **Bug 发现：找出隐藏缺陷**

为测试 Leanstral 的抓 bug 能力，我们搭建了一条自动化管线：Aeneas 把 Rust 代码翻译成 Lean，Leanstral 则从代码推断用户意图并生成正确性性质。随后 Leanstral 尝试四次证明每条性质。若全部失败，它再尝试四次证明其否定。在测试的 57 个仓库中，该流程标记出 47 条被违反的性质，其中 11 条指向真实 bug——5 个此前从未在 GitHub 上报过。

其中一个 bug 位于 [datrs/varinteger](https://github.com/datrs/varinteger) 库 zigzag 解码的符号函数中。在输入 Std.U64.MAX 时，表达式 (value + 1) 发生溢出，导致 debug 模式崩溃、release 模式静默损坏——这是测试和模糊测试通常会漏掉的边缘情况。Leanstral 的管线自动捕获了它，表明形式化验证已可应用于真实代码库，并找出一些传统方法忽视的 bug。

## **开始使用**

Leanstral 1.5 采用 **Apache-2.0** 许可。权重可在 [Huggingface](https://huggingface.co/mistralai/Leanstral-1.5-119B-A6B) 获取，同时也已作为[免费 API endpoint](https://docs.mistral.ai/models/model-cards/leanstral-1-5) 提供，名为 `leanstral-1-5`。我们推荐在 Mistral Vibe 中使用。要开始你的旅程，领取一个 API Key，然后：

**1. 配置 Mistral Vibe**

```
uv tool install mistral-vibeuv tool update mistral-vibevibe --setup
```

**2. 安装 Leanstral 1.5**

```
/leanstallexit
```

**3. 启动 Agent**

```
vibe --agent lean
```

**4. 安装 Lean LSP MCP（可选）**

强烈建议安装 [Lean LSP MCP](https://github.com/oOo0oOo/lean-lsp-mcp)，在 `~/.vibe/config.toml` 中加入以下内容：

```
[[mcp_servers]]name = "lean-lsp"transport = "stdio"command = "uvx"args = ["lean-lsp-mcp"]tool_timeout_sec = 600
```

如果此前没有已有的 MCP 服务器，你可能需要移除 `mcp_servers = []`。

**5. 开始证明**

让 Leanstral 处理一个定理、调试一个证明，或为某个仓库做出贡献。就是这么简单。
