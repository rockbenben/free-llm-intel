今天，我们发布 Search Toolkit 的公开预览。Search Toolkit 是一个可组合的框架，用于为 AI 应用构建生产级搜索流水线。我们打造它，是因为构建搜索基础设施的团队仍把太多工程时间花在"管道衔接"上。多数人把摄取、检索、评估的分立工具拼在一起，每个工具有自己的接口、自己对数据的假设。Search Toolkit 把这三者收进单一框架、共享同一接口，让团队把时间花在提升搜索质量上，而不是维护集成。Search Toolkit 开源，并可运行在你的基础设施所在之处：云、本地、边缘。

## **搜索基础设施仍然比它该有的难度更难。**

多数构建检索系统的团队，花在拼装基础设施上的时间比改进搜索质量还多。摄取需要一套工具，检索需要另一套。评估（如果做的话）则用又一个独立框架硬接上去，还带着另一套数据形态假设。

团队反馈：在对自己的数据跑出第一条查询之前，要先花数周做集成工作。而要衡量检索器是否返回了正确结果，往往还得再上另一条工具链。对构建 RAG 工作流或内部知识系统的组织来说，这种开销层层放大。

## **它的位置。**

**企业搜索。**多数组织面对的不是"一个"搜索问题，而是十几个：内部 wiki、工单系统、文档库、文件存储、代码库。每个源结构不同、元数据不同，要做好索引就需要不同处理。团队通常最终为每个源各建一条摄取流水线，各有各的解析逻辑、分块策略，以及各自对"文档长什么样"的假设。结果是一堆无法一起搜索的孤立索引，或一个试图统一它们、却自成新维护负担的脆弱定制层。Search Toolkit 在单一框架内为各类数据源提供一致的处理与索引模式，团队新增数据源时无需每次重建流水线。

**RAG 与检索质量。**当 RAG 系统返回糟糕的结果，第一个问题是：毛病出在检索还是生成？实践中多数团队没有干净的办法回答。他们改提示词、调分块策略、换模型，却始终不知道检索器是否一开始就找对了上下文。即使聚焦检索的团队，也常缺乏工具在自己的数据、用自己的相关性判断严格对比策略。替代方案是每个实验写一套自定义评估脚本。Search Toolkit 内置评估，可独立衡量检索器性能，让你把检索质量与生成质量分离，并随语料演化对比各配置。

**领域定制检索。**法律文件、医疗病历、代码库、财务披露。现成检索器在通用文本上训练，遇到与网页搜索不同的专业术语、文档结构和相关性标准往往吃力。需要领域调优检索的团队，常常不得不从零搭建定制检索基础设施，维护昂贵且难以评估。

## **agentic 世界的搜索**

处理企业任务的 agents 需要访问企业上下文。它们自主、大量地做检索决策，所以底层搜索基础设施的质量直接影响每个下游步骤。在大文档语料中搜索时，agents 对索引执行语义搜索，以低延迟获得精确结果。

agents 也需要实时数据。借助[连接器（Connectors）](https://docs.mistral.ai/studio-api/knowledge-rag/connectors)，它们通过 MCP 集成直接从 CRM、代码仓库、生产力工具等源系统拉取。需要跨大量内容搜索时，agent 可以查询已索引语料；需要最新状态时，可以从源系统拉实时数据。Search Toolkit 让你的 agents 在与实时检索并行之时，还有一条高质量的索引搜索路径可调用。

## **内部构成。**

**摄取。**用可配置流水线从多数据源索引和处理数据。Search Toolkit 负责文档解析、分块和嵌入生成。自定义文档格式和预处理步骤可通过标准适配器接口插入。

**检索。**Search Toolkit 自带 BM25 稀疏检索、稠密嵌入检索，以及将两者结合的混合配置。每一项都可按你的数据和用例配置。

**评估。**用内置指标衡量搜索质量：recall、precision、MRR 和 NDCG。对你自己的测试集运行评估、并排比较检索器配置、追踪各版本的质量变化。

所有模块共享同一配置接口。换掉你的索引器、切换你的检索器、加一个评估器——流水线其余部分自动适配。

Search Toolkit 为企业的高级用例而设计，并在金融服务、制造、公共部门、媒体与娱乐等行业实战检验。CMA CGM 把 Search Toolkit 与 Voxtral 配合使用，帮助记者识别假新闻。该流水线处理来自三个不同数据源的音频，端到端 15 秒内返回告警。

## **开始使用。**

尝试 Search Toolkit 最快的方式是我们的[**starter app 模板**](https://github.com/mistralai/search-starter-app)。

**前置条件**

安装 [Docker](https://docs.docker.com/get-docker/)。生成的项目中还需要 [uv](https://docs.astral.sh/uv/)。

**搭建新项目**

```
uvx copier copy gh:mistralai/search-starter-app my-search-projectcd my-search-project
```

**运行**

```
# Start Vespa locally with Dockermake setup-vespa# Index sample datamake ingest path=sample_data/hello.txt# Run a querymake search query="hello world"
```

模板包含：

- 预配置的 Vespa 索引
- 混合检索（BM25 + 向量）
- 示例数据与摄取流水线

完整细节见[starter app README](https://github.com/mistralai/search-starter-app)。
