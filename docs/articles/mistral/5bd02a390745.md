## **面向业务流程的 agents、工作流与应用**

agents、工作流和应用分别服务于业务流程的不同环节。agent 负责调查并采取行动，工作流负责协调执行与审批，应用则给员工提供使用这些系统的入口。

Studio 把这三者放在同一套基础设施上聚到一起。你从 Le Chonk 这样的模型开始，通过连接器和 MCP server 把它接到你的企业数据与系统上。有了这个底座，你可以轻松构建 agents、工作流和应用，让它们拿到自己需要的上下文。Studio 负责它们怎么跑起来，同时让团队可以查看发生过什么。

借助新的 Mistral MCP server，开发者可以用 Mistral Vibe 或他们已经在用的编程 agent 来构建，在本地测试，然后用一条命令部署到自己的 Studio 环境。托管与执行由 Studio 承担，所以团队可以在这个底座上继续往上搭，把每一个新用例更快推进生产。

### **构建能调查、能行动的托管 agents**

在 Studio 里，开发者现在可以构建执行复杂多步任务的 agents。开发者可以给它们装配沉淀团队流程的 skills、让它们可以跑代码的沙箱、以及把任务的一部分委派出去的 subagents。Hooks 让开发者在执行的关键节点插入自定义逻辑，塑造 agent 怎么工作、怎么和现有系统集成。

Studio 打理着这一切背后的运行时，用的是每周支撑数百万 Mistral Vibe 会话的那套已被验证的基础设施。开发者专注于 agent 的能力与行为，同时给它可以访问的工具、数据和动作划定边界。这意味着可以更快地把有能力的 agents 送进生产，要自己搭的基础设施更少，对 agents 如何运行的掌控更多。

我们的工程团队在 Studio 里造了一个 agent 来调查生产事故。告警一响，工程师就要弄清楚发生了什么，而且通常还背着尽快解决问题的压力。这个 agent 会把调查先跑起来：按团队的 runbook 一步步走，做敏感动作之前先申请审批，然后把它的发现发到 Slack 里。工程师接手时已经拿到有用的上下文，团队每月省下几百小时。

### **用工作流自动化流程**

工作流定义一个流程怎么跑：哪些步骤按固定规则执行、哪里交给 agent 推理、什么时候由人来决策。被打断的运行可以从中断处继续。团队可以在 Mistral Vibe 里描述一个流程，用它来生成、测试、部署一条工作流，产出的代码可以查看和编辑。本次发布还新增了来自企业系统的事件触发器，以及一张可视化 graph，让每条工作流的逻辑更容易被查看。

我们的产品运营团队在 Studio 里搭了一条工作流，用来分拣内部团队的想法和客户反馈。把每一条提交路由给合适的人，是这个团队日常工作之一，但也费时间。模型先识别 bug 和功能请求，然后路由规则把它们送到对应的团队。这为产品运营团队每周省下约 35 小时。

### **构建可直接用于企业的应用**

编程 agent 让构建一个应用变得容易，但要让整个企业都用起来，就得满足安全、访问与可靠性上的要求。Studio 提供托管、身份认证和访问控制，帮开发者更快地把应用变成企业可用状态。团队可以基于已经预先批准、可复用的组件来构建，减少需要过安全审查的新代码量。

这些应用可以使用 agents 和工作流，通过搜索索引检索企业文档，并访问 Studio 里的共享上下文。开发者可以在本地测试，然后用一条命令部署，让应用通过自己的链接可用，或者直接在 Mistral Vibe 里面被使用。

我们的 Applied AI 团队——负责帮客户构建 AI 方案的团队——在 Studio 里造了一个人员调配应用。以前给项目配人，要靠人工把团队画像和过往经历跟散落在文档与工具里的需求一项项对上。

这个应用用一个 agent 来推荐人选，并解释他们的经历如何匹配项目。人员调配负责人拿到一份自带佐证、随时可以评审的候选名单，帮助 Mistral 在为复杂的客户 AI 项目配人时更快组起团队、把平时容易被漏掉的专业能力挖出来。

每一个用例都让企业为构建下一个用例积攒了更多装备。更多的工程精力被投进改进运营本身，花在反复重建其外围基础设施上的时间就更少。

## **让 AI 保持主权**

Studio 让你掌控 AI 跑在哪里、怎么运行、以及你打造出了什么智能。模型和平台都可以部署在你自己的云、VPC 或本地环境里。你也可以选择 Mistral 托管的部署，或者把多种环境组合起来满足自己的要求。敏感数据以及围绕它建立起来的流程，都可以留在你自己的边界之内。

模型你自己挑，数据和工具的访问权限你来治理，哪些动作必须人来审批也由你决定。OpenTelemetry trace 会显示一次运行的每一步，包括模型调用、工具使用与审批，让团队能看到流程在哪里变慢、在哪里失败。Evaluations 让团队在发布之前，用自己的数据集来测对 prompts、模型或工具所做的改动。这些 trace 和 evaluation 都留在他们手里，把他们在日常使用中沉淀下来的运营知识保下来。

客户已经在把它落到实践里，用的是和我们的 Solutions 团队一起搭起来的系统。从渗透测试到 KYC onboarding，他们正在把 [AI 带进关键业务](https://www.youtube.com/watch?v=6_eHHtB7Q2I)，同时把敏感数据与专业知识都留在自己的掌控之下。
