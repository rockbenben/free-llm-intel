摘要

全新的管理员控制让你按工作区或组织管理连接器访问，带作用域权限的 API key 与多账号连接器增强了自动化 AI 作业的安全性。Connectors Debugger 为中断的连接提供详细的根因分析，而 Workflows 和 Vibe Code 中的集成确保对企业工具无缝、受治理的访问。目前有 60 多个预置连接器可用，并为更多平台提供自定义 MCP 选项。

## 治理哪些工具在哪里运行、为单个连接器连接多个账号、追踪任何中断的连接。

今天，我们在 Connectors 中引入多项新能力，为对接外部企业平台带来更安全的体验。即日起，你可以使用：

- **增强的管理员控制**（GA）：按工作区设置连接器访问，并在组织或工作区内逐个开启或关闭工具
- **带连接器作用域的 API key**（GA）：在对接第三方系统的自动化 AI 作业中防止身份冒用
- **多账号连接器**（GA）：允许用户用多个账号认证同一个连接器
- **Connectors Debugger**（公开预览）：为 MCP 连接器提供端到端根因分析
- **Vibe Code 中的连接器**（GA）：在开发者界面中复用你的连接器
- **Workflows 中的连接器**（公开预览）：用你所需的全部工具支撑不间断的长时运行任务

异步 agents 正走向日常工作。一个 agent 要在组织内可靠、有用，就需要真实的企业数据：CRM 记录、代码仓库、邮箱、知识库。在演示中把 agent 连上这些数据很容易。难的是在生产环境中运行——多数方案正是在这里卡壳。

生产级连接有几条不可妥协的原则。连接器应同时遵守两套规则：源平台已设置的权限，以及你的管理员在 Mistral Studio 或 Vibe 中设置的控制。自动化工作应代表某个用户或服务账号运行，绝不能冒充编写它的人。当连接中断，你应该能查明原因。管理员应该能精确到单个工具，决定组织各部分可用什么。

## 更多控制：连接器能做什么

**增强的管理员控制**在两个层面起作用：横跨你的团队，以及深入每个连接器。

- **工作区与组织控制**让每个团队拥有自己的连接器访问。你的财务工作区可以访问内部数据源但不开公网，而工程团队拿到开发者工具和互联网。同一目录，各团队不同规则。
- **工具级控制**更深一层。在任何连接器内部，为整个组织或单个工作区开启或关闭个别工具。屏蔽所有会写数据的操作，或屏蔽知识库上的某个具体动作如 `delete_file`。连接器保持连接；只有你批准的工具能运行。

**带连接器作用域的 API key** 负责身份。创建 key 时，你选择它只能触达工作区的共享连接器，还是也能触达你的私有连接器，让自动化作业恰好拥有它需要的访问。配合服务账号使用，自动化工作以一个明确的身份运行，而不是以编写它的人的身份。

**多账号连接器**让一个连接器持有多个登录。把个人账号与工作账号连到同一个连接器，设置默认，按任务切换。每个账号独立存储和刷新，所以 agent 能在正确的账号上行动，而不必再立第二个连接器。

## 看清连接为何失败

**Connectors Debugger** 确切告诉你连接在哪一步断裂。指向一个 MCP server URL，如服务器需要就加上 OAuth 凭证，然后运行检查。它把连接走一遍 11 个步骤——从触达服务器到打开 MCP 会话——并逐步记录。过去只能靠猜的故障，比如 OAuth token 交换失败，现在会精确显示在它发生的那一步。

## **Workflows 与 Vibe Code **里的连接器

**Workflows 中的连接器**让长时与定时运行不再因认证中断。你在 Workflow 定义里直接声明它需要哪些连接器、应以哪些账号运行；Studio 在启动运行时解析这些依赖。个人凭证不进入自动化工作，任务也不会因为 token 过期而中途失败。一次夜间运行可以全程从 CRM 拉取、更新跟踪表、读知识库，而不掉任何一个连接。

**Vibe Code 中的连接器**为编码 agent 带来同样的受治理访问。输入 `/connectors`，从本地 MCP server 和管理员批准的工作区连接器中挑选，选择启用哪些工具，开始任务。异步 agents 在你全局统一的规则下就能访问 Outlook、Jira、Notion、Linear 和 Confluence。

我们在持续添加连接器。目录现已覆盖 60 多个集成，而你需要的平台若未列出，自定义 MCP 连接器可以补位。
