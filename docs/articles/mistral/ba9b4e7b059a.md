# 用 LLM as a Judge 评估 RAG

大语言模型（LLM）正迅速成为构建广泛应用的必备工具。但要确保这些模型表现符合预期，说起来容易做起来难。评估 LLM 系统不只是验证输出是否连贯，还要确保答案相关并满足必要要求。

## RAG 系统的兴起

检索增强生成（RAG）系统已成为增强 LLM 能力的流行方式。把 LLM 与数据检索系统配对后，LLM 生成的回答不仅连贯，还扎根于相关且最新的信息。这有助于减少模型听起来自信、实际却在产生幻觉的情况。

然而，评估这些 RAG 系统是否高性能并不简单。不仅要看 LLM 生成的输出听起来是否正确，还要追溯源头，验证检索到的信息是否相关、准确。传统方法往往忽略这些细微之处，因此一套全面的评估框架必不可少。

退一步看，许多领域都面临同样的问题：可能缺乏清晰的量化指标或评估数据来衡量表现，而成功的标准可能更偏定性与细腻。

### LLM As A Judge：用 LLM 评估 LLM

在需要规模化运行评估、又缺乏人工评审员的情况下，"LLM As A Judge" 已成为评估 LLM 系统回答的流行解法。

"LLM As A Judge" 的典型做法是创建一个"judge LLM"：给定"generator LLM"的回答后，按指定量表为该回答打分。量表可以是数值的（如 1-10 或 0-3）、二元的（如 True 或 False）或定性的（如"Excellent""Good""Okay""Bad"）。随后把分数在整个评估数据集的所有问题上取平均，得到总体加权得分。

对于"LLM as A Judge"的指令 prompt，你可以为 LLM 创建自定义的评估标准。例如，制定具体的评分标准，检查回答是否准确、相关、有据可依。Mistral 的模型可以高效地用于 LLM 系统的 generator 和 judge 两侧。

### RAG Triad：更整体的评估框架

RAG Triad 是一个评估 RAG 系统的流行框架，旨在检查 LLM 回答相对于数据源的可靠性与上下文完整性。它由 [TruLens](https://www.trulens.org/getting_started/core_concepts/rag_triad/) 提出，随后也出现了多个类似框架，如 [RAGAS](https://docs.ragas.io/en/latest/concepts/metrics/overview/)，以便对 RAG 系统做更定性的评估。

RAG Triad 聚焦三个关键维度：

1. **Context Relevance（上下文相关性）**：该指标检查检索到的文档是否与用户查询高度契合，确保用于生成回答的信息相关且恰当，为连贯有用的回答奠定基础。

2. **Groundedness（有据性）**：该指标验证生成的回答是否准确基于检索到的上下文，确保 LLM 输出符合事实、可靠，减少那些恼人的幻觉风险。

3. **Answer Relevance（答案相关性）**：该指标评估最终回答对用户原始查询的响应程度，确保生成的答案有帮助、切题，与用户意图对齐并提供有价值的洞见。

借助 RAG Triad，评估者可以获得 LLM 表现的全景视图、发现潜在问题，并确保回答准确、可靠、上下文健全。这个框架有助于在人类、AI 与知识库之间建立可信的交互。

这在端到端评估一个 RAG LLM 系统时尤其有用，因为它同时评估检索与生成两个环节。这样不仅评估 LLM 的答案，也评估它相对于所检索源数据的正确性。

### Structured Outputs：一个务实的解法

自定义结构化输出（structured outputs）是我们 API 中的一项新功能，让你控制 LLM 的输出格式，以结构化的机器可读方式给出取值，从而获得更高的可靠性。

Mistral 的模型配合结构化输出，为实现 RAG Triad、应对常见评估挑战提供了务实的路径。通过为取值设定明确的标准和 schema，结构化输出能帮你构建更可靠的"LLM As A Judge"，用于评估 LLM 系统。

结构化输出为定义新的、可复用的评估标准提供了理想的框架，并强制一种易于机器读取、可用于评估的格式。


## 结论

评估 LLM 系统对开发可靠的 AI 应用至关重要。RAG Triad 配合 Mistral 的结构化输出，为"以 LLM 评估 LLM"提供了稳健的框架。通过聚焦上下文相关性、有据性与答案相关性，我们可以确保 LLM 的回答更准确、更有意义。这种方式提升了用户体验和 AI 驱动应用的可靠性，让与 AI 系统的交互更加可信。
