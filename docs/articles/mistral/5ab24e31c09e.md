今天我们在 Studio 中发布 Connectors（连接器），为构建扎根企业数据的高度定制 AI 应用的开发者扫清障碍。所有内置连接器以及自定义 MCP，现在都可以通过 API/SDK 用于所有模型与 agent 调用。

我们还引入直接工具调用（direct tool calling），让开发者精确控制工具以何种方式、在何时被调用，测试和迭代不再被认证门槛挡住。此外，你现在可以实现人在回路（human-in-the-loop）审批流程，在工具执行前进行安全审查与确认，兼顾灵活与治理。

- 程序化访问：创建、修改、列出和删除你的连接器，也能列出它们的工具并直接运行。
- 所有连接器集中注册，横跨 Mistral 应用可用：Le Chat 和 AI Studio（Vibe 即将到来）。
- 通过 Conversation API、Completions API 和 Agent SDK 使用，可以支撑复杂工作流，以及与 CRM、知识库和生产力工具等企业系统的集成。

## 集成活在平台里，而不是你的代码里

构建企业 AI agent 越来越容易。更难的是它周围的一切：找对 API 文档、编写并维护工具函数、做集成、配置 OAuth、处理 token 刷新，以及调试分页失效这类边缘情况。

正因如此，各团队反复重建同一层集成。即使在同一家公司内，相似的集成也常常在不同代码里被各自实现多次，带来安全风险、流量不可观测和重复劳动。

![None](https://mistral.ai/_astro/connector-1_1XsRpe.webp?dpl=6abbd11780b53c00082eea6f)

连接器用 MCP 协议把一个集成封装成单一、可复用的实体，从而解决这个问题。

```
my_connector = client.beta.connectors.create(    name="salesforce-crm",    description="Salesforce CRM — accounts, contacts, opportunities",    server="https://your-mcp-server.internal/salesforce",    visibility="shared_workspace",    oauth_config={        "client_id": os.environ["SALESFORCE_CLIENT_ID"],        "scopes": ["read_accounts", "read_contacts"],        "redirect_uri": "https://your-app.internal/oauth/callback",    },)
```

注册之后，这个自定义 MCP 连接器在 Studio 中可被发现、受治理、被监控，并成为任何对话、agent 或工作流的原生工具——无需重写集成逻辑、无需重新实现认证、无需在各团队间重复。一次配置，处处常跑。把连接器挂到任意对话只需一行：

```
response = client.beta.conversations.start_async(    model="mistral-medium-latest",    inputs="Which enterprise accounts renewed last quarter?",    tools=[{"type": "connector", "connector_id": "salesforce-crm"}],)
```

## 一条可运行的黄金路径

我们来基于多源推理构建一个多步工作流 agent，前提是它与 GitHub、公开仓库内容与文档、以及网络实时数据的安全连接。该 agent 可以理解意图、分析代码并提议修改，也能胜任生成测试、重构、识别低效之处、bug 或漏洞等常见用例。

### 前置条件

```
pip install mistralaiexport MISTRAL_API_KEY="your-api-key"client = Mistral(api_key=os.environ["MISTRAL_API_KEY"])
```

### 1 - 为公开远程 MCP 创建连接器

为了查询和探索代码库，我们将利用 DeepWiki 远程服务器，它提供通往 API/工具端点的 MCP 接口。这样 agent 就能探索内容和文档，而不必手动爬文档或加载整个仓库。

```
my_custom_mcp = client.beta.connectors.create_async(    name="my_deepwiki",    description="DeepWiki MCP for code repository exploration",    server="https://mcp.deepwiki.com/mcp",    visibility="shared_workspace",)
```

MCP server 注册一次，用户便可在对话、agent 或直接工具调用中复用它。这是任何自定义 MCP 流程的入口。关于如何管理内置与自定义连接器的完整示例，见 [cookbook：Connectors Management](https://docs.mistral.ai/cookbooks/mistral-connectors-01-connectors-management)。

### 2 - 创建 agent

该 agent 还需要能连接 GitHub 和网络；用户无需创建这些连接器，因为它们已内置在 Mistral 中。

注意，一个连接器可能暴露数十个工具。如果用户想排除潜在破坏性的操作，`tool_configuration` 可以在不修改连接器本身的情况下控制工具可用性。更多细节见 Cookbook：[Using Connectors in Conversations](https://docs.mistral.ai/cookbooks/mistral-connectors-02-connectors-in-conversations-and-agents)。

```
my_agent = client.beta.agents.create_async(    name="deepwiki_agent",    description="Agent for code repository exploration",    model="mistral-small-latest",    instructions="""\ You are an Open-Source Software Auditor. \
```

当被要求审查一个库或仓库时，你必须执行以下全部任务：

```
## Final verdictBased on all three analyses, give a clear recommendation:- **SAFE TO ADOPT** — no major concerns- **ADOPT WITH CAUTION** — some concerns to be aware of- **AVOID** — significant risks identified
Always be thorough and cite your sources.\""",    tools=[        {"type": "web_search"},        {            "type": "connector",            "connector_id": "github",            "tool_configuration": {"exclude": ["delete_file"]},        },        {"type": "connector", "connector_id": "my_custom_mcp.name"},    ],)
response = await client.beta.conversations.start_async(    agent_id=my_agent.id,    inputs=[        {            "role": "user",            "content": "Please perform full audit on repo pallets/flask",        }    ],)
```

## 直接工具调用

并非每个工作流都需要模型来决定何时、如何调用工具。为了更确定的体验，用户现在可以直接调用连接器。

```
result = await client.beta.connectors.call_tool_async(        connector_id="my_deepwiki",        tool_name="read_wiki_structure",        arguments={"repoName": "sqlite/sqlite"},    ) print(f"Tool output:\n{result.content}")
```

这对调试和流水线式自动化尤其有用——后者要求尽量消除歧义。完整模式见 [cookbook：Connector tool calling](https://docs.mistral.ai/cookbooks/mistral-connectors-03-connectors-tool-calling)。

## 当需要人在回路时

有些操作不该在没有明确批准的情况下执行。`requires_confirmation` 会暂停执行，在工具运行前把控制权交还你的应用：

```
{   "type": "connector",   "connector_id": "gmail",   "tool_configuration": {       "include": ["gmail_search"],       "requires_confirmation": ["gmail_search"]   }}
```

模型提出建议，用户的应用决定是否继续。AI 判断与人类判断之间的边界是显式的、写在代码里的。完整审批流程（包括待处理工具调用与恢复步骤）见 [cookbook：Human-in-the-loop Confirmation](https://docs.mistral.ai/cookbooks/mistral-connectors-04-human-in-the-loop-confirmation)。
