# MAX 25.1——推出 MAX Builds

今天，我们很高兴宣布 MAX 25.1 发布，这标志着我们向社区交付前沿 AI 开发工具的方式发生重大演进。本次发布大幅改进了 Agentic 与 LLM 工作流的开发者体验，引入了包含全新 GPU 编程接口的 nightly 发布模式，并上线了 [MAX Builds](https://builds.modular.com/)——你的 GenAI 开发一站式目的地。

## MAX 25.1

MAX 25.1 在多个关键领域带来多项突破性改进：

### 增强的 Agent 与 RAG 能力

本次发布带来大量提升开发体验的改进：

- **新的 GPU 加速 mpnet2 模型**：通过 `/v1/embeddings` API endpoint，[为你的 RAG 与 agent 应用快速生成 embeddings](https://builds.modular.com/recipes/max-serve-openai-embeddings)。
- **OpenAI 兼容的 function calling API**：采用业界标准方式让 MAX 模型与外部服务交互。
- **结构化输出生成**：[保证 LLM 生成的响应符合任意 API 规范](https://docs.modular.com/max/serve/structured-output/)，非常适合 agent 工作负载。

### 高性能 LLM 工作流

我们实现了两项重要的性能增强：

- **支持 paged attention**：通过在 token 生成期间启用更大的 cache 容量，用户可以看到最高 5% 的 token 生成性能提升。此外，paged attention 还提升了内存效率，允许更长的上下文长度。
- **prefix caching 预览**：通过缓存已有推理请求的 key-value (KV) 计算，新查询可以复用 KV cache 中编码的上下文，消除重复计算，提升具有重复前缀的工作负载性能。在输入重复的工作负载中，prefix caching 通常可将吞吐量提升 30%。

关于如何启用 paged attention 和 prefix caching，可阅读[文档](https://docs.modular.com/max/serve/prefix-caching/)了解更多。

### 离线批量推理

MAX 25.1 支持 LLM 工作流的离线批量推理，[允许你加载模型并直接从 Python 运行推理](https://builds.modular.com/recipes/max-offline-inference)。离线批量推理通过把请求分组并消除 HTTP 请求带来的延迟来提升性能。预期性能取决于具体工作负载，由于延迟与模型加载时间的改善，较小批次的作业相比 vLLM 展现出高 12% 的吞吐量。

### 通过 MAX Graphs 用 Mojo 做 GPU 编程

MAX 构建在一个令人兴奋的 GPU 编程接口之上，它抽象掉了底层硬件。MAX 25.1 引入新的 Custom Ops API，允许你用 Mojo 编写新的图操作来扩展 MAX Engine，并可运行在 CPU 或 GPU 上，为你的模型提供完整的可组合性与可扩展性。深入探索最新的 [GitHub GPU 编程示例！](https://github.com/modular/max/tree/main/examples/custom_ops)

## 用 MAX Nightlies 加速创新

MAX 25.1 不仅仅是功能改进——它标志着我们交付方式的根本转变。我们转向强调持续创新的 nightly 优先模式：

- **即时获取新功能**：新能力一旦就绪就会进入 MAX nightlies。新模型、流水线优化和 API 都会最先登陆 nightlies，并配有文档和配方帮你上手新功能。
- **社区驱动开发**：早期访问让社区可以实时反馈，在开发过程中塑造功能。跟随 MAX nightlies 一起见证 GPU 编程等新 API 的开发历程！

[MAX GitHub 仓库](https://github.com/modular/max)、[发布包](https://docs.modular.com/magic/)和 [Docker 镜像](https://hub.docker.com/u/modular)现在默认使用 nightly 构建，确保你始终能获取最新改进。
