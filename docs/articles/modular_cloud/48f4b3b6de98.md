# ModCon 2026：开源、开放云、开放硅

四年半前，Modular 下了一次注：AI 不会永远运行在单一类型的硅片上，而软件栈需要为异构硬件、AI 工作负载日益复杂的世界重新架构。

在今天上午的 ModCon 主题演讲上，我们展示了这次押注结出的果实。Modular Platform 如今已生产就绪，每分钟服务数十亿 token，支撑着真实的企业级部署。我们把平台的更多部分向生态开放，把它扩展到全新的硬件门类，并携一批重量级行业伙伴同行。

更具体地说，Modular 与 Qualcomm 宣布了：

- [**Mojo 1.0 现已完全开源**](https://modular.com/blog/mojo-open-source)[，采用 Apache 2.0 许可证。](https://modular.com/blog/mojo-open-source)
- **Modular Cloud 正式公开发布**，服务 MiniMax 等旗舰客户。
- Modular Platform 现在**支持 AWS Trainium、Google TPU，以及 **[**Qualcomm Cloud AI 100 与 Qualcomm Dragonfly**](https://modular.com/blog/modcon-qualcomm) 加速器，与 CPU 和 GPU 并列。关于 Qualcomm Dragonfly 适配工作，详见我们的博客。
- **Mojo 即将原生支持 Windows**，得益于与 Microsoft Windows 团队的合作。
- MAX 许可证不再包含设备使用限制，MAX 将**开放源码并提供一个开放联盟计划**，让更广泛的生态与我们一起构建平台。

异构计算已经到来，它拥有一个单一的、开放的软件平台。

## Mojo 🔥 现已开源

上周，[我们宣布 Mojo 达到 1.0](https://www.modular.com/blog/modular-26-5-mojo-1-0-is-here)，为开发者提供一个稳定的、可长期构建的生产就绪基础。伴随一系列新特性，1.0 最重要的部分是稳定性保证：你今天写的代码不会在某天突然被抽掉地基。

今天更进一步。整个 Mojo 语言已在无附加限制的 Apache 2.0 许可证下开源，这意味着编译器和全部工具链完全开源。你可以扩展这门语言、把它带到新平台、在其上构建任何你想要的应用。这延续了我们技术栈的渐进开放——从 2024 年的 Mojo 标准库到 2025 年的 MAX kernels——并将从此继续。想了解 Mojo 并参与贡献，请访问 [mojolang.org](https://mojolang.org/)。

### Mojo 的 Windows 支持

Mojo 多年来一直支持 macOS 和 Linux，Windows 开发者此前可以通过 WSL 使用它。原生 Windows 支持一直是我们收到最多的开发者请求之一。

每天有数百万开发者在 Windows 上构建，覆盖极其广泛的应用与工作负载。我们相信 Mojo 能在整个生态中产生有意义的影响。把 Mojo 以正确的方式带上 Windows 需要对该平台的深厚专长，因此我们很高兴 Microsoft Windows 团队看到了与我们相同的机会——我们正在携手让它成真。

> "我们很高兴看到 Mojo 来到 Windows，以及它为跨系统与 AI 工作的开发者创造的机会。每天有数百万开发者在 Windows 上构建，我们致力于帮助他们在自己选择的平台上获取所需的工具与技术。"

– Logan Iyer，Windows 平台 + 开发者部门企业副总裁

## 介绍 Modular Cloud

Modular Cloud 是整个 Modular 技术栈汇聚成生产服务的地方。它让开发者直接获得 Modular 业界领先的推理性能，同时抽象掉在异构基础设施上部署、优化和运维模型的复杂性。

Modular Cloud 已在 [console.modular.com](https://console.modular.com/) 正式可用，通过共享 endpoint 和专属部署在 Modular 技术栈上服务流行的开源模型。共享 endpoint 兼容 OpenAI、按 token 计费；专属部署运行在我们的算力或你自己的算力上，使用预留的隔离实例。

过去几个月，Modular Cloud 一直悄悄以 ModelRun 的名义服务 OpenRouter 流量，其 endpoint 在平台的生产流量延迟与吞吐量排名中始终位居前列。独立基准机构 [Artificial Analysis](https://artificialanalysis.ai/) 讲出了同样的故事。

### MiniMax

MiniMax 是 Modular Cloud 的旗舰企业客户，在专属 Modular 部署上运行 M3，以每分钟数十亿 token 的规模服务其生产流量。

在规模下高效服务 M3 是一项独特的系统挑战。它结合了 1M token 上下文窗口、原生多模态，以及 MiniMax Sparse Attention（MSA）——一种新颖的稀疏注意力架构，有选择地关注相关的 KV block，在上下文扩展时降低所需计算。

交付业界领先性能需要全栈优化：在 MAX 中原生实现 M3、构建并调优专门的 MSA kernel，并围绕 MiniMax 真实世界的流量模式优化部署。

## GPU 之外：Trainium、TPU 与 Dragonfly

Modular Cloud 已在 NVIDIA 和 AMD GPU 上服务生产工作负载。今天，我们把硬件支持扩展到 GPU 之外、进入定制 AI 加速器——这是对平台可移植性更严苛的考验。

我们新增支持 AWS Trainium、Google TPU、Qualcomm Cloud AI 100 Ultra 和 Qualcomm Dragonfly。每一个都通过同一个 Modular Platform 运行，使用相同的建模 API、服务工作流、编程语言和核心抽象。开发者一次编写模型，就能把它带到完全不同的硬件架构，而无需围绕硬件重建软件栈。

同样重要的是，我们启用这些平台所花的工程投入只有传统新 AI 硬件启用所需的一小部分——工程投入减少超过 10 倍。

未来几个月，我们将把这些新硬件平台带入生产，并通过 Modular Cloud 提供。

## MAX：与生态共建的共同基石

AI 硬件创新在加速，但出色的硬件只有开发者能用才有意义。太多创新仍被锁在为单一架构编写的软件栈之后。业界需要一个共同的软件根基：一次编写模型触及所有加速器，依据性能与经济性而非"哪个栈恰好支持它"来选择硬件，让厂商凭硅片本身的价值竞争。这正是我们构建 Modular Platform 的目标。

加入 Qualcomm 强化了这一目标。Modular Platform 将继续支持并优化广泛的硬件，包括与高通技术公司产品直接竞争的硬件。摆在生态面前的机遇远比任何单一厂商的路线图更大，而一块基石只有所有人都能站在上面才算成立。

为打造这块基石，我们推进两项重要计划：

**我们正在开放 MAX。**我们演进 MAX 的许可模式、扩大源码访问，让开发者、企业、硬件厂商和合作伙伴能在平台上构建、扩展并回馈。

**我们正在为生态筹建一个联盟计划。**我们正推动一个覆盖硬件厂商、模型提供商、云公司和数据中心运营商的行业联盟计划。目标是让合作伙伴直接参与集成 MAX、为其平台优化，并帮助塑造 Modular Platform 的下一步走向。

HTEC 已经演示了这在实践中是什么样子。他们的工程师仅用几个月、仅几名工程师，就自己在 Modular Platform 上跑通了 Google TPU 支持，我们只起支持作用而非主导集成。这是我们构建之物的有力验证：一块生态可以独立扩展的基石。

其他初创硬件厂商也看到了市场上同样的需求。d-Matrix 就是其中之一：

> "d-Matrix 与 Modular 对异构计算的共同承诺，建立在对开放标准的相互支持之上。当我们进入解耦异构计算的时代，开放标准能加速 GPU、CPU 和 XPU 协同部署、在规模上驱动效率，这也是我们的合作如此天然契合的原因。"

> Sid Sheth，d-Matrix 创始人兼 CEO
