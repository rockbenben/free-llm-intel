# 模块26.7：开放MAX

模块化团队

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a82c/6ada2f7b9f71f84fdcd7ddf1_image.png)

产品展示

Modular 26.7 的标题是我们长期以来一直想写的标题：此版本**为所有人开放 MAX 图形编译器、MAX 运行时和设备可扩展性挂钩**。这意味着 MAX 现在完全可用源代码，并且可以由硬件创新者、研究人员以及所有喜欢让加速器“brr”使用的其他人构建和修改。此版本还带来了急切模式，让您可以在很短的时间内调试自定义操作、决策模型支持以及 Mojo 发展为系统编程语言的下一步。

## **MAX 现已完全提供源代码**

在我们的[最近的 ModCon 会议](https://youtu.be/4Hw7PeIsFPo?si=e2hSCEGJQU1kLHrg&t=4806) 上，我们承诺开放 MAX，并且我们正在兑现这一承诺。

MAX 的完整源代码现已提供：硬件后端、图形编译器、运行时等等。我们新的 MAX 许可证是特意允许的：您可以使用 MAX 使用、修改、扩展和构建商业产品，而无需支付许可费或版税。如果您想在自己的加速器上启动 MAX，可以从这里开始，您可以查看 NVIDIA、AMD、Apple Silicon 和 CPU 的现有实现作为参考点。我们计划在未来几个月内发布其他芯片（包括 Qualcomm Dragonfly 和 Google TPU）的 MAX 插件源代码。

### 为什么不是 Apache 2.0？

MAX 许可证几乎允许 Apache 2.0 所做的一切：使用、修改、扩展和使用 MAX 构建商业产品，无需任何费用或版税。差异归结为碎片化。我们花了几十年的时间维护主要的开源项目，并且[看到了他们面临的挑战](https://www.modular.com/blog/democratizing-ai-compute-part-8-what-about-the-mlir-compiler-infrastruct)。 MAX 的目标是统一跨硬件的编程模型，不兼容的特定平台版本将破坏这一目标。 Modular [联盟计划](https://www.modular.com/alliance) 是我们解决此问题的方法，它为硬件供应商和合作伙伴提供了在 MAX 上进行构建的共享路径，而不会破坏生态系统。与 Mojo 一样，我们希望随着技术的成熟以及社区的反馈，我们的方法会不断发展。

MAX 源代码中包含的内容远远超出我们在此介绍的内容，因此我们撰写了 [a](https://www.modular.com/blog/max-license)[单独的帖子](https://www.modular.com/blog/max-license)，介绍其中包含的内容以及可以使用它构建的内容。

## **MAX 的新功能**

### **Eager 模式可加快开发速度**

MAX 长期以来一直拥有先进的图形编译器，可以执行自动融合和其他优化以获得最佳性能。但在开发过程中，快速迭代通常比峰值性能更重要。 MAX 现在拥有完整的 eager 模式支持，包括您的自定义操作，并且它与图形编译器共享单个代码路径，因此您在 eager 模式下运行的代码与您编译和发布的代码相同。

声明一次操作，直接在张量上调用它，然后在编译的模块中不加修改地重用它。这使得开发循环变得更快：在 Gemma 4 31B 的切片上，Eager 模式在大约 30 秒内到达第一个令牌，而编译时间约为 110 秒。

以下是 eager 模式如何与自定义操作配合使用的示例：

蟒蛇
```
n, w, c = custom.Symbols("n", "w", "c")
downsample = custom.declare(
    "downsample",
    inputs={"x": custom.TemplateType(DType.float32, [n, w, c])},
    outputs=[custom.TemplateType(DType.float32, [n, w // 2, c])],
    custom_extensions=["path/to/kernels"],
)

# Eager: runs immediately.
y = downsample(Tensor.ones([2, 8, 3]))        # shape (2, 4, 3)

# Compiled: same op inside a Module.
class Encoder(Module):
    def forward(self, x: Tensor) -> Tensor:
        return downsample(x) * 2.0

model = Encoder().compile(TensorType(DType.float32, ["batch", 8, 3], device=Encoder().device))
y = model(Tensor.ones([2, 8, 3]))             # same op, now compiled
```
### **支持系统一/决策模型、新模式和更多模型**

最近，人们对系统一/决策模型的新模式感到非常兴奋，因为它们能够以非常便宜的方式实现零样本分类。 MAX 通过新的 v1/decisions 和 v1/systemone API 端点增加了对这些决策模型（包括 Decider 2B）的初步支持。

MAX 还增加了对 MiMo-V2.6-Flash、GLM-5.3-Flash 和 Muse-Glimmer 的支持，以及 KDA 和稀疏 MLA。

除了新功能外，我们还继续改进现有的型号系列。过去需要在 CPU 中往返的多个操作现在完全在 GPU 上运行，这为 Qwen 和 GLM 模型提供了 2.6 倍的预填充加速。

## **Mojo 1.2：成长为一种系统语言**

通过 1.0，Mojo 证明了自己是一种跨异构硬件高性能代码的语言。现在我们正在研究 [Mojo 路线图的下一阶段](https://mojolang.org/docs/roadmap/#phase-2)：Mojo 作为一种系统编程语言。

### **模式匹配**

Mojo 1.2 的旗舰新功能是模式匹配。 “match”语句可让您用清晰、结构化的情况替换一长串条件，并且编译器可以检查您是否已处理其中的每一个条件。

Python
```
def classify_point(p: Tuple[Int, Int]) -> String:
    match p:
        case 0, 0:
            return "origin"
        case x, 0 if x < 0:
            return String("negative x-axis:", x)
        case x, 0:
            return String("x-axis:", x)
        case 0, y:
            return String("y-axis:", y)
        case x, y:
            return String("point:", x, ",", y)
```
作为奖励，它也可以在编译时运行：

蟒蛇
```
def classify_type[T: AnyType]() -> String:
    comptime match T:
        case == Int:
            return "integer"
        case == String:
            return "string"
        case _:
            return "other"
```
### **更具表现力的特征和约束**

结构现在可以显式选择退出特征一致性（例如，通过声明自己为“不可移动”），并且“where”子句接受“else”分支，以便您可以准确说明约束失败的原因。两者都使通用代码更易于阅读和调试。

有关 1.2 中更改的完整列表，请参阅 [Mojo 变更日志](https://mojolang.org/releases/v1.2.0/)。
