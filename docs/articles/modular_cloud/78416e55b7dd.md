# Modular：Modular 26.7 开放 MAX

Modular 团队

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a82c/6ada2f7b9f71f84fdcd7ddf1_image.png)

产品

Modular 26.7 的重头戏，是我们很久以来一直想写下的那句话：本次发布**向所有人开放了 MAX graph compiler、MAX runtime 和 device extensibility hooks**。这意味着 MAX 现在完整 source-available，硬件创新者、研究人员，以及所有喜欢把加速器跑出一声 "brr" 的人，都可以自行构建和修改它。本次发布还带来一个 eager mode，让你调试 custom ops 所花的时间只剩一小截；同时带来 decision model 支持，以及 Mojo 朝 systems programming language 成长的下一步。

## **MAX 现在完整 source-available**

在[最近的 ModCon 大会](https://youtu.be/4Hw7PeIsFPo?si=e2hSCEGJQU1kLHrg&t=4806)上，我们承诺把 MAX 开放出来，现在我们兑现了这个承诺。

MAX 的全部源码现已可用：hardware backend、graph compiler、runtime，还有更多。我们的新 MAX License 刻意保持宽松：你可以使用、修改、扩展 MAX，也可以用它构建商业产品，没有授权费也没有版税。如果你一直想在自己的加速器上把 MAX 拉起来，这里就是起点，而且你可以拿现有的 NVIDIA、AMD、Apple Silicon 和 CPU 实现作为参照。我们计划在接下来几个月里发布其他芯片的 MAX plugin 源码，包括 Qualcomm Dragonfly 和 Google TPU。

### 为什么不是 Apache 2.0？

MAX License 允许的事情几乎覆盖了 Apache 2.0 能做的一切：使用、修改、扩展 MAX，并用它构建商业产品，没有费用也没有版税。差别归结到 fragmentation 上。我们维护大型 open source 项目已经几十年，也[见过它们面对的那些挑战](https://www.modular.com/blog/democratizing-ai-compute-part-8-what-about-the-mlir-compiler-infrastructure)。MAX 的目标是统一跨硬件的编程模型，而互不兼容的平台专属版本会破坏这个目标。Modular 的 [alliance program](https://www.modular.com/alliance) 就是我们解决这件事的方式：给硬件厂商和合作伙伴一条共同的路径在 MAX 上构建，而不把生态撕成碎片。和 Mojo 一样，我们预计自己的做法会随着技术成熟、随着我们听到社区的声音而演进。

MAX 源码里的东西远不是这里能讲完的，所以我们专门写了[一篇](https://www.modular.com/blog/max-license)[独立的文章](https://www.modular.com/blog/max-license)，讲里面有什么、你能用它构建什么。

## **MAX 的新内容**

### **eager mode 让开发更快**

MAX 很早就有一个先进的 graph compiler，会自动做 fusion 和其他优化以逼近峰值性能。但在开发阶段，快速迭代往往比峰值性能更要紧。MAX 现在完整支持 eager mode，你的 custom ops 也算在内，而且它和 graph compiler 共用同一条 code path，所以你在 eager mode 下跑的代码，就是你编译并上线的那一份。

一个 op 只声明一次，就能直接在 Tensor 上调用它，之后原封不动地复用在编译好的 Module 里。这让开发循环快得多：在 Gemma 4 31B 的一个切片上，eager mode 大约 30 秒就能出第一个 token，而编译模式大约要 110 秒。

这是一个 eager mode 配合 custom ops 工作的例子：

python

```
n, w, c = custom.Symbols("n", "w", "c")
downsample = custom.declare(
    "downsample",
    inputs={"x": custom.TemplateType(DType.float32, [n, w, c])},
    outputs=[custom.TemplateType(DType.float32, [n, w // 2, c])],
    custom_extensions=["path/to/kernels"],
)

# Eager: runs immediately.
y = downsample(Tensor.ones([2, 8, 3]))        # shape (2, 4, 3)

# Compiled: same op inside a Module.
class Encoder(Module):
    def forward(self, x: Tensor) -> Tensor:
        return downsample(x) * 2.0

model = Encoder().compile(TensorType(DType.float32, ["batch", 8, 3], device=Encoder().device))
y = model(Tensor.ones([2, 8, 3]))             # same op, now compiled
```

### **支持 System One/decision model、新 modality，以及更多模型**

最近大家对 System One/decision model 这种新 modality 热情很高，因为它们能用极低的成本实现 zero-shot 分类。MAX 已经加入对这些 decision model 的初步支持，包括 Decider 2B，通过新的 v1/decisions 和 v1/systemone API endpoint 提供。

MAX 还加入了对 MiMo-V2.6-Flash、GLM-5.3-Flash 和 Muse-Glimmer 的支持，带有 KDA 和 sparse MLA。

除了新能力，我们也在持续改进已有的模型家族。几个过去要在 CPU 上绕一趟的 op 现在完全跑在 GPU 上，这给 Qwen 和 GLM 系列模型带来 2.6 倍的 prefill 提速。

## **Mojo 1.2：朝 systems language 成长**

1.0 让 Mojo 证明了自己是一门在异构硬件上写高性能代码的语言。现在我们正在投入 [Mojo roadmap 的下一阶段](https://mojolang.org/docs/roadmap/#phase-2)：把 Mojo 做成一门 systems programming language。

### **pattern matching**

Mojo 1.2 的旗舰新特性是 pattern matching。`match` 语句让你用清晰、结构化的 case 取代冗长的条件分支链，而且 compiler 还能检查你是否把每一种情况都处理了。

python

```
def classify_point(p: Tuple[Int, Int]) -> String:
    match p:
        case 0, 0:
            return "origin"
        case x, 0 if x < 0:
            return String("negative x-axis:", x)
        case x, 0:
            return String("x-axis:", x)
        case 0, y:
            return String("y-axis:", y)
        case x, y:
            return String("point:", x, ",", y)
```

作为额外的好处，它在 compile-time 同样可用：

python

```
def classify_type[T: AnyType]() -> String:
    comptime match T:
        case == Int:
            return "integer"
        case == String:
            return "string"
        case _:
            return "other"
```

### **更具表达力的 trait 与 constraint**

struct 现在可以显式退出 trait conformance（例如把自己声明为 `not Movable`），`where` clause 也接受一个 `else` 分支，好让你准确说明一个 constraint 为什么失败。这两点都让 generic 代码更好读，也更好调试。

1.2 的完整变更列表见 [the Mojo changelog](https://mojolang.org/releases/v1.2.0/)。
