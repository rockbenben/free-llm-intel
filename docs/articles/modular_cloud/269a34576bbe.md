# 重新介绍 MAX 的模块

吴凯西

阿利斯特·伯特

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a82c/6aff3d96149fad6867cf98f0_ReleaseBlogPost-Option_%25281%2529.jpeg)

工程

MAX 专为以最快速度进行生产推理而构建。我们最近重新设计了 `Module` API，以帮助开发人员更快地构建快速模型。 `Module` 是机器学习框架中的标准构建块，这篇文章解释了我们如何以及为何重建此 API，深入探讨了几个关键方面：

- 新设计如何加速开发
- 使用新的 `Module` 进行生产推理
- 支持分布式计算
- `Module` API 的简化
- 熟悉的类似 PyTorch 的语法
- 与前代产品相比，新的 `Module` 在堆栈中的位置

## 重建MAX的AI框架

Modular 专注于具有最先进性能的生产推理。 MAX 的优势在于其编译堆栈：跨架构、优化的 Mojo 内核，以及积极融合内核和规划内存的图形编译和执行。

旧版 `Module` 直接构建在我们的图形堆栈上。图前向方法提供了出色的性能，但开发人员体验仍有改进的空间。我们通过在图堆栈顶部引入一个新的 Eager 层，然后在其顶部重建 `Module` 来缩小差距。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d35cf2b4cc97a204c52_stack_diagram_1.png)

## 熟悉的、类似 PyTorch 的语法

如果您编写过 PyTorch 模型，那么新的 `Module` 应该会感到熟悉。这是 MAX 和 PyTorch 中的同一层：

蟒蛇
```
# MAX
from max.nn import Module
from max.tensor import Tensor

class MyLayer(Module):
    def __init__(self, in_dim, out_dim):
        self.weight = Tensor.zeros([out_dim, in_dim])
        self.bias = Tensor.zeros([out_dim])

    def forward(self, x):
        return x @ self.weight.T + self.bias
```
Python
```
# PyTorch
import torch
from torch import nn

class MyLayer(nn.Module):
    def __init__(self, in_dim, out_dim):
        super().__init__()
        self.weight = nn.Parameter(torch.zeros(out_dim, in_dim))
        self.bias = nn.Parameter(torch.zeros(out_dim))

    def forward(self, x):
        return x @ self.weight.T + self.bias
```
差异在于设计的有意简化：没有 `super().__init__()` 调用，并且使用简单的 `Tensor` 代替 `nn.Parameter`。

## 热切执行可以加快开发速度

代理从根本上改变了开发周期。虽然模型性能对于生产工作负载仍然至关重要，但在开发过程中实现快速迭代可以说比以往任何时候都更加重要。为每个单元测试和调试日志支付编译成本是痛苦的。

急切执行避免了昂贵的图形编译，而是立即开始计算结果。当您第一次使用新的 `Module` 运行 Gemma 4 时，您的第一个令牌出现得更快。

## 使用新的 `Module` 进行生产推理

重新设计的 `Module` 仍然服务于我们的主要用例，生产推理。内置的 `compile` 方法跟踪模型并将其编译为图形，这让 MAX 使用有关整个模型的知识来优化计算。我们的图形编译器执行：

- 操作融合，以减少发射开销。
- 常量折叠和其他初始化时间提升，以避免在每个循环上重复相同的常量计算。
- 执行和内存规划，因此 MAX 可以规划存储并重用缓冲区，而不是分配新缓冲区。
- 形状推断和动态形状推理，支持上述所有内容。

`Module` 直接支持急切执行和编译执行，因此模型作者可以两全其美：

蟒蛇
```
model = DeepSeekV3(config)

# Option 1: Call eagerly
model.load_state_dict(state_dict)
model(inputs)

# Option 2: Compile, then call
compiled = model.compile(*input_types, weights=state_dict)
compiled(inputs)
```
## 分布式计算：将工作分散到多个设备上

重新设计是一个重新思考我们如何编写分布式模型的机会。该框架的作用是构建从单个 GPU 到多个 GPU 的计算扩展。

没有单一的正确方法可以做到这一点。由于 GPU 的计算和内存限制不同、模型的层数和维度不同以及输入的形状不同，因此存在许多并行策略。以下是分发模型的几种方法：

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d36d840e29bf1ddffd2_tensor_parallelism.gif)

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d368798806989f4456e_pipeline_parallelism.gif)

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d36a98f5293499a160d_data_parallelism.gif)

MAX 中的较低级别抽象现在可以表达数据并行性、管道并行性或张量并行性。 `Tensor` 仍然是一个逻辑 N 维数组，但它现在可以存在于多个设备上。分布式张量上的操作根据特定的分片规则进行。

## 树实用程序

`Module` 现在是 `Tree`，这是 MAX 中受 [JAX 的 Pytrees](https://docs.jax.dev/en/latest/pytrees.html) 启发的新 API。 `Tree` 由 `Module` 和 `Tensor` 组成，这简化了两件事：

- `Module.parameters` 和 `Module.descendants` 使用树遍历来收集连接的 `Module` 和 `Tensor`。
- `Module.trace` 和 `Module.compile` 使用 `tree.map` 将 `Tensor` 转换为图权重。

这些 API 还间接帮助序列化：树 `flatten` 生成展平的叶子和存储树结构的 `TreeDef` 对象。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff414aa964ec05b8c4675a_tree_diagram_white.png)

例如，我们使用 `Tree.map` 仅量化专家混合模型中的专家层。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff402560bbdcb52d503671_tree_map_quantize_experts_5.gif)

## 用于处理图形、权重张量和数据类型的更简单的 API

我们还删除了不再需要的抽象和样板。

**没有符号 **`**Weight**`** 类。** `Weight` 的存在是为了在图中跟踪和创建权重。现在您可以直接在 `Module` 中使用 `Tensor`。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d3777e8487f07c00742_code_diff_example_1_1.png)

**默认 **`**dtype**`** 和 **`**device**`**。** 本文顶部的图层均未定义。默认的 `dtype` 和 `device` 上下文管理器意味着到处使用一种设备或数据类型的模型不需要将它们传递到每一层。您仍然可以在需要时按层设置它们。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d37beb5520f17172f9e_code_diff_example_2_1.png)

**内置**`**compile**`**。**图形构建样板已消失。每个 `Module` 现在都有一个 `compile` 方法，在上面的产生式推理部分中进行了介绍。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d3743de88213eee0959_code_diff_example_3_1.png)

## 最后的想法

旧版 `Module` 实现现在位于 `max.nn.legacy` 中，并将于 2027 年第一季度删除，因此现在是迁移现有模型的好时机。我们还围绕新的 `max.tensor` 和 `max.functional libraries.` 重组 `max.nn`

最好的起点是[模型启动工作流程教程](https://max.modular.com/develop/model-bringup-workflow/)，它逐步介绍如何使用新 API 端到端地构建模型。

展望未来，2027 年将带来量化、训练和多节点支持。本系列的下一篇是框架概述，展示了 MAX 在 ML 框架领域的适用范围，随后是有关即时执行、分布式张量、序列化等的帖子。
