# 重新引入 MAX 的 Module

Kathy Wu

Alister Burt

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a82c/6aff3d96149fad6867cf98f0_ReleaseBlogPost-Option_%25281%2529.jpeg)

工程

MAX 为以最高速度做生产推理而生。我们最近重新设计了 `Module` API，帮助开发者把本来就要做快的模型做得更快。`Module` 是机器学习框架中的标准构件，本文说明我们为何重建、如何重建这套 API，并深入几处关键细节：

- 新设计如何加快开发
- 用新的 `Module` 做生产推理
- 对分布式计算的支持
- `Module` API 的简化
- 熟悉的、类似 PyTorch 的语法
- 新的 `Module` 相较前代在技术栈中的位置

## 重建 MAX 的 AI 框架

Modular 一直专注于业界领先性能的生产推理。MAX 的优势在它的编译栈：跨架构、经过优化的 Mojo kernel，以及会激进融合 kernel、规划内存的图编译与执行。

旧版 `Module` 直接构建在我们的图栈之上。以图为中心的做法带来了出色性能，但开发者体验仍有改进空间。我们先在图栈之上引入一个新的 Eager 层，再基于它重建 `Module`，从而补上了这块短板。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d35cf2b4cc97a204c52_stack_diagram_1.png)

## 熟悉、类似 PyTorch 的语法

如果你写过 PyTorch 模型，新的 `Module` 应该会让你觉得眼熟。下面是同一个层在 MAX 和 PyTorch 里的写法：

python

```
# MAX
from max.nn import Module
from max.tensor import Tensor

class MyLayer(Module):
    def __init__(self, in_dim, out_dim):
        self.weight = Tensor.zeros([out_dim, in_dim])
        self.bias = Tensor.zeros([out_dim])

    def forward(self, x):
        return x @ self.weight.T + self.bias
```

python

```
# PyTorch
import torch
from torch import nn

class MyLayer(nn.Module):
    def __init__(self, in_dim, out_dim):
        super().__init__()
        self.weight = nn.Parameter(torch.zeros(out_dim, in_dim))
        self.bias = nn.Parameter(torch.zeros(out_dim))

    def forward(self, x):
        return x @ self.weight.T + self.bias
```

这些差异是有意为之的设计简化：不再调用 `super().__init__()`，并用普通的 `Tensor` 取代 `nn.Parameter`。

## Eager 执行让开发更快

agent 从根本上改变了开发周期。模型性能对生产负载仍然关键，但让开发阶段能快速迭代，可以说比以往任何时候都更重要。每跑一次单元测试、每看一条调试日志都要付一次编译代价，实在难受。

## 用新的 `Module` 做生产推理

重新设计后的 `Module` 依然服务于我们的主要场景——生产推理。内置的 `compile` 方法会 trace 模型并把它编译成图，MAX 因此可以借助对整个模型的了解来优化计算。我们的图编译器会做这几件事：

- 算子融合，减少 launch 开销。
- 常量折叠以及其他初始化期提升，避免每轮循环都重复相同的常量计算。
- 执行与内存规划，让 MAX 能规划存储、复用 buffer，而不是不断分配新的。
- 形状推断与动态形状推导，为上述能力提供支撑。

`Module` 同时直接支持 eager 执行与编译执行，模型作者可以两头都占：

python

```
model = DeepSeekV3(config)

# Option 1: Call eagerly
model.load_state_dict(state_dict)
model(inputs)

# Option 2: Compile, then call
compiled = model.compile(*input_types, weights=state_dict)
compiled(inputs)
```

## 分布式计算：把工作拆到多台设备

这次重设计也是重新思考分布式模型写法的机会。框架的职责，是把一个计算从单块 GPU 扩展到多块 GPU 的过程组织起来。

这件事没有唯一正确的做法。并行策略之所以有这么多，是因为 GPU 的算力与内存上限各不相同，模型的层数与维度各不相同，输入的形状也各不相同。下面是几种切分模型的方式：

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d36d840e29bf1ddffd2_tensor_parallelism.gif)

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d368798806989f4456e_pipeline_parallelism.gif)

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d36a98f5293499a160d_data_parallelism.gif)

MAX 的底层抽象现在可以表达数据并行、流水线并行或张量并行。`Tensor` 仍然是逻辑上的 N 维数组，但现在可以分布在不止一台设备上。分布式张量上的运算按特定的分片规则进行。

## Tree 工具

`Module` 现在是一个 `Tree`——MAX 中受 [JAX 的 Pytrees](https://docs.jax.dev/en/latest/pytrees.html) 启发的新 API。`Tree` 由 `Module` 与 `Tensor` 组成，这让两件事变简单了：

- `Module.parameters` 和 `Module.descendants` 借助树遍历收集相连的 `Module` 与 `Tensor`。
- `Module.trace` 和 `Module.compile` 借助 `tree.map` 把 `Tensor` 转换成图权重。

这些 API 也间接帮到了序列化：树的 `flatten` 同时产出展平后的叶子，以及一个保存树结构的 `TreeDef` 对象。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff414aa964ec05b8c4675a_tree_diagram_white.png)

举个例子，我们用 `Tree.map` 只量化混合专家模型里的专家层。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff402560bbdcb52d503671_tree_map_quantize_experts_5.gif)

## 处理图、权重张量与 dtype 的更简单 API

我们还删掉了一些不再需要的抽象与样板代码。

**不再有符号化的 **`**Weight**`** 类。** `Weight` 原本用来在图中跟踪和创建权重。现在你直接在 `Module` 里使用 `Tensor`。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d3777e8487f07c00742_code_diff_example_1_1.png)

**默认的 **`**dtype**`** 与 **`**device**`**。** 本文开头那个层两者都没有定义。默认的 `dtype` 与 `device` 上下文管理器意味着：如果一个模型处处只用一种设备或一种 dtype，就无需把它们传进每一层。需要时你仍可以按层单独设置。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d37beb5520f17172f9e_code_diff_example_2_1.png)

**内置 **`**compile**`**。** 图构建的样板代码已经消失。每个 `Module` 现在都有 `compile` 方法，前文的生产推理一节已经介绍过。

![](https://cdn.prod.website-files.com/68c9c3107effc2ea46e1a81f/6aff3d3743de88213eee0959_code_diff_example_3_1.png)

## 结语

旧版 `Module` 实现现在位于 `max.nn.legacy`，将在 2027 年第一季度移除，所以现在正是迁移既有模型的好时机。我们也在围绕新的 `max.tensor` 与 `max.functional libraries.` 重新组织 `max.nn`。

最好的起点是 [Model Bringup Workflow 教程](https://max.modular.com/develop/model-bringup-workflow/)，它带你用新 API 端到端地构建一个模型。

往前看，2027 年会带来量化、训练与多节点支持。本系列的下一篇是框架概览，说明 MAX 在 ML 框架版图中的位置，随后还有 eager 执行、分布式张量、序列化等文章。
