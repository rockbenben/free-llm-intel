# Modular Platform 25.5：引入大规模批量推理

Modular Platform 25.5 [来了](https://hub.docker.com/u/modular)，带来了大规模批量推理（Large Scale Batch Inference）：一个高度异步、规模化的批量 API，基于开放标准构建，由 [Mammoth](https://www.modular.com/mammoth) 驱动。我们通过与合作伙伴 [SF Compute](https://www.modular.com/blog/sf-compute) 推出这一新能力，用一个快速、精准、高效、可跨任意硬件无缝扩展工作负载的平台，实现高吞吐量的 AI 性能。

本次发布还包括 MAX Graph API 的开源，以及扩展了对在 MAX 中直接用 PyTorch 编写自定义算子的支持。此外，我们通过优化的 Docker 容器和新的独立 Mojo Conda 包，让 Modular Platform 的开发与部署更加轻松。

## 由 Mammoth 驱动的大规模批量推理

随着 AI 工作负载在复杂度和规模上不断增长，基础设施需要更智能、更快、更高效。这就是我们与 [SF Compute](https://sfcompute.com/inference) 合作构建大规模批量推理 API 的原因——这是一款高吞吐量服务产品，[由 Mammoth 驱动](https://www.modular.com/mammoth)，即 Modular 的智能 Kubernetes 原生集群编排层。为最大化吞吐量和效率，Mammoth 使用优化的调度器持续在 GPU 集群间分配作业，使集群资源利用率保持在 90% 以上。

这一服务支持语言、视觉和多模态领域的 20 多个业界领先模型，运行在 NVIDIA 和 AMD 硬件上，并包含一个 OpenAI 兼容的 API。[观看我们的联合发布视频](https://www.youtube.com/watch?v=PZIqVuvaJgE)并[查看博客文章](https://www.modular.com/blog/sf-compute)，了解更多关于 SF Compute 大规模推理 API 的信息。[注册获取访问](https://sfcompute.com/inference)，通过 SF Compute 使用大规模批量推理。

## 轻量、模块化的打包

#### 独立的 Mojo 包

Mojo 赋能了一代新的 GPU 开发者，让他们编写摆脱厂商锁定的、可移植且高性能的代码。在 25.5 中，我们通过两个新的独立 Conda 包，让用 Mojo 做 GPU 编程更易得。

`mojo` 包提供与 AI 无关的 CPU 和 GPU kernel 开发所需的一切：编译器、运行时、调试器和 LSP，无需额外的 MAX 包。为简化纯 Mojo 或 Python/Mojo 混合包的分发，`mojo-compiler` 包只包含核心组件：编译器和运行时。这个轻量选项为通过官方 [Modular 社区包仓库](https://builds.modular.com/?category=packages)分发 Mojo 应用和库提供了坚实基础。一个 Python wheel 发行版正在筹备中，以进一步简化集成工作流。

无论你是 GPU 开发新手，还是想优化现有系统的性能，我们的 [Mojo GPU Puzzles](https://puzzles.modular.com) 和 [GPU 编程文档](https://docs.modular.com/mojo/manual/gpu/architecture)都会带你从编写基础操作一路进阶到高性能矩阵乘法。

#### 更轻量的 MAX 服务包

为进一步降低部署开销并大幅缩短生产环境的冷启动时间，我们从容器中移除了 PyTorch 依赖，让 MAX 服务包比以往更精简。在 NVIDIA GPU 上不到 700 MB，你可以更快地部署和扩展生产工作负载——容器比等效的 vLLM 小 90% 以上。

## 开源 MAX Graph API

本次发布还包含 MAX Graph API 的开源——这是我们业界领先模型背后基于 Python 的引擎，由 Mojo kernel 库驱动。有了它，你现在可以直接用 Python 构建开放、可移植、GPU 加速的图。

代码自由可用意味着 AI 编码助手可以把完整源码作为参考，从而更快、更容易地把你最关键的模型移植到 Modular Platform。我们还增强了 Graph API，使其在编译时对自定义图进行验证，减少开发周期并确保模型正确性。

今年早些时候，我们开源了所有 MAX kernel。现在，你可以亲自探索模型构建接口本身——附带支撑代码和单元测试，用小型、明确定义的示例演示每一个 kernel。

想了解更多？加入我们在 [Modular 社区论坛](https://forum.modular.com)上不断壮大的 AI 开发者社区，分享你的突破，获取专家帮助。

## MAX 与 PyTorch 无缝集成

25.5 的新特性：MAX 图现在可以无缝集成为 PyTorch 工作流中的自定义算子。

通过新的 `@graph_op` 装饰器，任意 MAX 图都可以自动包装为一个自定义 PyTorch 算子——极大地拓展了你用 MAX 扩展 PyTorch 的方式。这让你可以轻松地把缓慢、平台专用的 PyTorch kernel 替换为高性能的 MAX 实现，甚至用更快、可移植的 MAX 图替换掉模型的整个部分。

最重要的是，你可以在保留现有 PyTorch 代码库的同时做到这一点，确保最小扰动、最大性能收益。

## 探索完整更新

查看 25.5 的全部更新，见完整的 [MAX](https://docs.modular.com/max/changelog/#v255-2025-08-05) 和 [Mojo changelog](https://docs.modular.com/mojo/changelog/#v255-2025-08-05)。Mojo 新增参数化别名、改进的字符串处理、Iterator trait，以及自定义 GPU 函数更强的类型检查。MAX 改进包括用 Mojo 实现更快的 prefix caching、对 OpenAI API 的 `logprobs` 和 `echo` 请求参数最高 12 倍的加速支持，以及 Idefics3 模型支持。
