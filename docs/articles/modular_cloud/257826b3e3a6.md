# Modular 26.2：业界领先的图像生成与升级的 Mojo AI 编码

今天的 26.2 版本把 Modular Platform 的模态支持扩展到图像生成与图像编辑工作流，延续我们已有的文本和音频生成支持。在 26.2 中，Black Forest Labs 的 FLUX.2 模型各变体获得支持，相比业界最优（SOTA）实现有超过 4 倍加速。

Mojo 26.2 让这门语言在 AI 辅助的 GPU kernel 开发上显著更高效。本版本引入了简化语言的特性，同时带来[全新 AI 编码 skills](https://github.com/modular/skills)——专为编写高性能、可移植 GPU kernel 而打造。加上超过 75 万行开源 Mojo kernel 代码，Claude、Cursor、Codex 这类编码 agent 现在可以轻松地在任意硬件目标上编写、移植和优化 kernel。Mojo 类 Python 的可读性让生成的代码既正确又易懂。

## MAX：内建于你现有技术栈的 FLUX 图像生成

Modular Platform 用单一框架统一 AI。我们从文本起步，快速扩展到[音频](https://inworld.ai/blog/how-we-made-state-of-the-art-speech-synthesis-scalable-with-modular)，今天再加上图像生成与图像编辑——全都带有 Modular 一贯的业界领先性能。

如果你已在生产中运行 Modular Platform，添加图像生成无需任何改动，只需换一个 endpoint。你会在 FLUX.2 系列模型上获得约 4 倍的延迟加速（相比使用 torch.compile 的 PyTorch Diffusers）。结果因图像分辨率而异：

| 图像分辨率 | Diffusers 相比 MAX 的加速 |
| --- | --- |
| 1024x1024 | 4.1x |
| 1360x768 | 3.4x |
| 768x1360 | 4.0x |

这些来自 MAX 的性能提升没有可察觉的质量损失。下图展示了 torch.compile（左）与 MAX（右）的结果。图像质量几乎完全一致，而 MAX 的性能肉眼可感——是 torch.compile 的 4 倍。图像质量的容差可配置，我们能在亚秒内获得高质量图像。这打开了大量此前因缺乏准实时图像生成而被阻塞的工作流。

FLUX.2-dev 的性能同样体现在 AMD MI355X 上：MAX 超过 torch.compile 性能 1.25 倍，生成耗时仅比 B200 慢 4%。

从 TCO（总拥有成本）视角看，这意味着 Modular Platform 用户立刻就能获得 TCO 节省。为估算 TCO 节省，我们调研了 GPU 市场，发现 MI355X 的价格通常约为 B200 的 70-80%。将其套用到我们的基准生成时间上，相当于在 AMD 硬件上部署模型时节省 25% 的 TCO，而生成速度没有明显牺牲。

[MAX 图像生成](https://www.modular.com/solutions/image-generation)现已在我们的云和企业方案中提供。我们在持续提升图像生成工作流的性能，预计未来几周内将达到对 SOTA 最高 7 倍的加速。如果你的工作流用到图像生成，并对 TCO 与性能收益感兴趣，请[联系我们](https://www.modular.com/request-demo)。

## Mojo：为 AI 编码时代而设计

AI 编码 agent 需要正确的基础才能构建好的软件。在[我们最近的分析](https://www.modular.com/blog/the-claude-c-compiler-what-it-reveals-about-the-future-of-software)中——Anthropic 用一个 agent 团队复刻 C 编译器的实验——Modular CEO Chris Lattner 点出一个关键洞察：agent 的有效性取决于它所构建的基础系统。Mojo 是面向未来 AI 系统的新一代基础。

其类 Python 语法、最多样板代码和强类型安全使它非常适合 agent：常见错误在编译期就被抓住，迭代周期更短，清晰的错误消息意味着更少的调试 token。同时，其独有的元编程能力实现了零成本抽象——包括可读的内存布局和可组合的 kernel 设计模式——却仍能在广泛硬件上交付裸机性能。

为帮助 agent 写出更好的 Mojo 代码，我们开源了 Modular 的 Mojo kernel 实现，并通过仓库各处的 `CLAUDE.md` 文件和 README 持续打磨 agent 引导。在 26.2 中，我们更进一步，推出一整套可直接接入 AI 编码助手的 [Mojo 编码 agent skills](https://github.com/modular/skills)，纠正过时模式、强制 idiomatic 代码。

用这条命令安装我们的 Mojo skills：

python

```
npx skills add modular/skills
```

这些 skills 对把现有 CUDA 或 Triton kernel 移植到 Mojo 尤其有用——把你的 agent 指向一个 kernel，skill 负责结构化翻译，你专注于 Mojo 特有的优化。

我们最初的 skills 只是开始。我们正努力将其扩展，覆盖硬件特定优化、PyTorch 到 MAX 的模型转换，以及 kernel 性能分析与调试。我们会持续演进这些 skills，并欢迎未来的外部贡献来扩展其能力。

此外，随着[《Programming Massively Parallel Processors》](https://www.amazon.com/Programming-Massively-Parallel-Processors-Hands-ebook/dp/B0DRCSRMXC)第五版出版，我们开源了书中所有例题的 Mojo 版本。这既是一份从 CUDA 到 Mojo 的极佳学习资源，也为把现有 CUDA kernel 移植到 Mojo 提供了优秀的示例素材。你也可以探索我们的 [Mojo GPU puzzles](https://puzzles.modular.com/) 深入练习。

## 其他亮点

- **新模型架构**：本版本还发布了 Kimi-K2.5、Kimi-VL、OlMo3、Qwen3-30B-A3B-Instruct-2507（一个开箱即用多 GPU 张量并行的 mixture-of-experts 模型），并为 Qwen3、Qwen3-MoE 和 GPT-OSS 扩展了张量并行覆盖。
- **扩展硬件支持。**MAX 和 Mojo 现在运行在 AMD RDNA 消费级 GPU（包括 AMD 780M 等集成 GPU）、NVIDIA B300、Jetson Thor 和 DGX Spark 上。这让开发者能在许多人已拥有的硬件上进行本地开发与测试。
- **简化 Mojo 语言。**Mojo 正稳步朝着今年晚些时候的稳定 1.0 发布前进。在这个 0.26.2 版本中，语言更一致、更符合人体工学：围绕 `comptime` 作为所有编译期表达式的唯一关键字对齐，用 `comptime if` 和 `comptime for` 取代 `@parameter if` 和 `@parameter for`。Mojo 还支持了条件式 trait 遵循、t-strings、显式 struct 对齐等众多特性。

完整变更列表见 [MAX](https://docs.modular.com/max/changelog/#v262-2026-03-19) 和 [Mojo changelog](https://docs.modular.com/mojo/changelog/#v0262-2026-03-19)。
