# 社区聚焦：用 Cursor 编写 Mojo

作为一名编程自学新手，复杂的语法从来不是我的朋友。Python 是我最早尝试的语言之一，我立刻就爱上了它可读、简单的语法——几乎就像用英语写作。当我偶然发现 Mojo 时，它看起来像是两全其美：把 Python 直白的语法与 Rust、C 这类编译型语言的性能结合在一起。不过，我还是在寻找能加快学习速度的方法，让我能少在语法上费心、多专注于构建。

发现 Mojo 后不久，我在一篇 LinkedIn 帖子中看到 [Cursor——一款 AI 驱动的代码编辑器](https://www.cursor.com/)，它是从 Visual Studio Code fork 出来的。当不再受限于我对语法的生疏、不再需要在代码编辑器和浏览器之间来回切换去用 ChatGPT 时，我的构建速度快得让我震惊。

生成的代码完美吗？不，但它是一个很好的迭代起点，Cursor 从根本上改变了我学习新编程语言的方式。这种范式转变并非 Cursor 独有；GitHub Copilot 和其他 AI 驱动的 IDE 插件已经改变了人们编程和学习编程的方式。我很兴奋能用 Cursor 写 Mojo，但很快就意识到这会很难——因为 Mojo 是一门全新的、仍在演进的语言，大多数大语言模型很难写出能编译、能在最新发布版本上运行的正确 Mojo。

我没有放弃、回到传统方式手写 Mojo，而是决定把这个挑战当作一次学习经历。我的使命很简单：帮 AI 写出更好的 Mojo。

## 我第一次尝试用 AI 写 Mojo

第一次尝试用 Cursor 写 Mojo 时，我用了他们的默认模型之一：Anthropic 的 Claude 3.5 Sonnet。这个模型的训练数据截止到 2024 年 4 月，意味着它的训练集里缺少五个月的 Mojo 更新。为了测试模型写 Mojo 的能力，我给 Cursor 一个简单任务："Write a Mojo script to output the sum of two values"（写一个输出两值之和的 Mojo 脚本）：

Mojo

fn main():
   let a: Int = 5
   let b: Int = 7
   let sum = a + b
   print("The sum of", a, "and", b, "is:", sum)

main()

关于这段生成的代码，我注意到两点：

- 它使用了 `let` 语句。在演进早期，Mojo 同时支持 `let` 和 `var` 语句。在某段时间里这算是正确的 Mojo，但今年早些时候对 `let` 语句的支持已被移除。
- 尽管每个 Mojo 程序都必须包含一个名为 `main()` 的函数作为入口点，但 `main()` 函数中的代码无需显式调用 `main()` 就会运行，所以生成代码的最后一行是多余的。

总体而言，这次的发挥还可以，但不算好。如果给 Cursor 加 Sonnet 的 Mojo 写作水平打分，此时我只会给 C。

## 向 ChatGPT 求教

我需要提升 Cursor 的 Mojo 写作能力，而网上满是让 AI 更精准的推荐技术——从 RAG（以及 graph RAG）到微调，到提示工程。我被这些选择淹没了，于是转向 ChatGPT 求建议：把生成的那份半正确的 Mojo 代码示例发给它，问如何提高表现。ChatGPT 的建议是？用 Mojo 标准库专属数据微调一个模型。

考虑到这是我第一次涉足微调，我把事情简化，使用 OpenAI 的控制台。我再次让 ChatGPT 干活：把 Mojo 文档喂给它，请它生成训练数据。

OpenAI 的微调控制台

用这些数据微调模型、并让 Cursor 使用微调后的模型后，我给 Cursor 同样的提示："Write a Mojo script to output the sum of two values"：

Mojo

fn sum(a: Int, b: Int) -> Int:
   return a + b

print(sum(3, 5))

这个回答有进步，但我注意到生成代码有一个明显问题：`print(sum(3, 5))` 的调用不在 `main()` 函数里，所以运行这段代码会报如下错误：

Mojo

error: TODO: expressions are not yet supported at the file scope level
print(sum(3, 5))
^
mojo: error: failed to parse the provided Mojo source module

代码其他地方是正确的。当我把 `print(sum(3, 5))` 放进 `main()` 函数后，脚本运行了，返回 3 加 5 的和 8。我还想测试微调后的 GPT-4o 对 Mojo 变量语法的了解是否比 Claude 3.5 Sonnet 更好，于是给 Cursor 另一条命令："Use variables."（使用变量）。Cursor 随即将脚本更新为：

Mojo

fn sum(a: Int, b: Int) -> Int:
   return a + b

fn main():
   var num1: Int = 3
   var num2: Int = 5
   print(sum(num1, num2))

这个语法是正确的！总体来看，Cursor 加上我微调的 GPT-4o 写 Mojo 的能力，我会给 B。

我还想测试未微调的 GPT-4o 是否知道 `let` 已不再被 Mojo 支持。为此我切换到基础模型，让 Cursor "write a Mojo script to output the sum of two values"：

Mojo

struct Adder:
   fn add(a: Int, b: Int) -> Int:
      return a + b

fn main()
   let adder = Adder()
   let result = adder.add(5, 7)
   print("The sum is: \(result)")

main()

这个结果明显比微调后的 GPT-4o 更差：它退回到过时的 `let` 语法、在末尾加了不必要的 `main()` 调用，还把解法过度复杂化——把 `add()` 函数做成 struct 的一部分。这让我确信：用 Mojo 文档生成的数据微调 GPT-4o，显著提升了模型的 Mojo 能力。**‍**

## 我的收获与下一步

尽管经过 Mojo 文档微调后的 GPT-4o 在 Cursor 里写出了勉强可用的 Mojo，我仍在持续实验各种技术以提升表现。在我的最新迭代里，我创建了一个 JSON 文件，收录我在网上能找到的全部 Mojo 相关资源，包括文档、博客、代码片段和教程。我写了[一个脚本](https://github.com/Julz19/DataGen/tree/main)，把这个文件喂给 GPT-4o，让模型以一个正在学习 Mojo 的用户身份生成一组与 Mojo 相关的问题。然后我的脚本再用 OpenAI 新的 o1-preview 模型，基于 JSON 文件里的资源回答 GPT-4o 生成的问题。o1-preview 在多步推理和避免答案幻觉方面似乎做得更好。

我计划继续扩展这个数据集，然后用更大的数据集再次微调 GPT-4o。我期望用这个微调后的模型创建更庞大的 Mojo 问答数据集。最后，我会在得到的 Mojo 数据集上微调一个开源模型（如 Llama 3），释放终极模型，让我自己和其他 Mojicians 都能写出更好的 Mojo。这只是我在 Mojo 与 AI 之旅的开始，我迫不及待想看看未来会带来什么。
