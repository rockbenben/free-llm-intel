# 仅用 14 天在 AMD MI355 上实现最先进性能

八月底，AMD 和 TensorWave 联系我们希望为 AMD 媒体技术日（Media Tech Day）联合准备一场演示——他们询问我们能否在 9 月 16 日演示 AMD Instinct™ MI355 上运行的 MAX。只有一个问题：Modular 没有人能接触到 MI355。

从我们首次能接触硬件算起，只有两周时间。我们视其为一个机会：能否在短短 2 周内在 MI355 上达到最先进（SOTA）性能？我们有信心做到，因为多年来我们一直在构建一个技术平台，以实现 AI 硬件的快速启用（bringup）。

# **为什么 AI 硬件启用如此困难**

新的 AI 硬件上线本不应只花两周。

为什么？现代 AI 软件生态是碎片化的。不同公司掌控着不同的层——硬件厂商追逐芯片销量，研究人员在验证最前沿的想法，应用开发者则把这些东西拼凑起来。结果呢？复杂脆弱的技术栈，难以扩展，更难优化。

正因如此，我们从第一天起就构建了 **Modular 技术栈**，让 AI 硬件启用变得快速、一致且可维护。

我们常开玩笑说*硬件已不再是难点*——拖慢所有人的是软件。

## **为可移植性而生的基础**

Modular 软件栈——从 **Mojo**（我们的编程语言），到 **MAX**（我们的推理框架）和 **Mammoth**（我们的分布式服务系统）——在架构上以**可移植性**为核心，这意味着它能快速迁移到最新的硬件架构并取得 SOTA 性能。

我们的设计优势体现在：

- **架构无关的设计。** Mojo 和 MAX 不硬编码 GPU 知识与优化，而是把所有硬件相关的细节委托给库。
- **库驱动的执行。** 卸载（offloading）、调度和指令选择通过抽象层控制，而不是编译器中硬编码的路径。
- **参数化操作。** 我们不使用“魔法常量”（如 SIMD 宽度或 tile 形状），而是使用可为新硬件重新调参的参数化 kernel。

由于**技术栈 99.9% 与架构无关**，添加对新 GPU 的支持大多只需更新少数几个 kernel。MAX 和 Mammoth 开箱即用。

正是这一设计让我们在 MI355 硬件到位后能够如此迅速地行动。事实上，我们只需修改硬件本身发生变化的部分。这些都存在于特定的 kernel 中——那我们来看看 MI355 的新特性。

### **AMD MI355 的新变化**

要理解为什么 MI355 只需要增量式的 kernel 更新，我们先来看看 MI355 架构提供了什么，以及 Modular 的 kernel 如何应对这些特性：

| MI355 feature | Impact | Our adjustment |
| --- | --- | --- |
| New FP32→BF16 conversion instructions | Faster casting between data types | Updated cast dispatch in Mojo’s standard library |
| Larger tensor-core tile sizes | Higher arithmetic intensity | Expanded matmul tile selection space |
| Increased shared memory (64KB→160KB) | Larger tiles, less memory pressure | Tuned tile-size parameters |
| Transposed DRAM→shared-memory loads | Removes extra in-place transpositions | Updated LayoutTensor load logic |
| Larger HBM capacity | Allows larger dynamic batch sizes | Nothing — handled automatically by MAX’s scheduler |

MI355 的这些新硬件特性专门用于优化类 matmul 操作，因此在 Modular 技术栈中，这也是唯一需要更改的类别。

# **两周达到 SOTA：逐日实录**

得益于上文所述的技术栈设计，我们在获得硬件访问权限之前很久就已开始在 AMD 的 MI355 上开展工作——我们只需将 Modular 技术栈按支持快速硬件启用来架构即可。

距离演示只有 2 周，我们必须有选择地确定在合理时间内能开发什么。Modular 虽然行动迅速，但我们也以保持良好的工作与生活平衡为荣——所以我们希望在不进入极限加班模式的情况下达成目标。

## **第 0 天：没有硬件也要准备**

在我们还没摸到 MI355 之前，我们就已开始离线测试代码生成。Mojo 与硬件无关的后端让我们能模拟指令路径——验证生成的汇编符合预期。你也可以[借助 Compiler Explorer](https://mojo.godbo.lt/z/4cr1en9K6)亲自试试。

通过理解新硬件提供的特性并确保发出正确的指令，我们无需真正在新硬件上运行程序就能对优化做原型验证 🤯。

有了硬件和初步验证，我们现在可以制定计划了。

## **第一周：寻找发力点**

我们把 MI355 GPU 与 B200 GPU 做了基准对比，运行了 Llama、Gemma 和 Mistral 等模型。我们对照理论上限分析结果以寻找优化机会——我们开发了工具来自动化其中大部分分析工作。工具指出 matmul 优化是通往显著性能提升和 SOTA 结果的路径。

matmul 实现——仅约 500 行注释良好的代码——很容易调整到能在 MI355 硬件上高效运行。我们还希望跨 AMD 硬件保持可移植性——同一份代码在 MI300、MI325 和 MI355 上都能达到 SOTA——因为即便工期紧张，我们依然重视良好的软件设计。

在 matmul 代码上工作了几小时并修正 M=N=K=8192 的情况后，我们证明了微小的参数化改动就能带来接近 AMD [hipBLASLt](https://rocm.docs.amd.com/projects/hipBLASLt/en/latest/what-is-hipBLASLt.html) 库的性能（我们实测它是 SOTA，且快于 hipBLAS）。

| Matmul kernel | GFlop/s |
| --- | --- |
| Mojo (day 0) | 1202302.79 |
| hipblaslt | 1561446.68 |
| Mojo (day 1) | 1610514.29 |

当天再做几处微调后，Mojo matmul kernel 已经**比 SOTA 快 3%**。这一首日实验证明我们的目标是可实现的。

第一周剩余工作包括：

- 将我们的实现泛化到模型中出现的各种形状
- 完善用于选择最优 kernel 参数的启发式规则
- 搭建基准测试自动化
- 配置远程登录系统，使计算资源易于访问和共享

当然，第一周也并非没有问题。由于硬件配置错误和 Kubernetes 集成中缺少 GPU 算子，我们遭遇了一些延误。尽管有挫折，到周末我们已取得亮眼的性能数字，并安心享受了周末。

## **第二周：从优化到演示**

还剩一周——演示定于下周二。

我们继续优化 matmul kernel，并开始探索其他机会，例如优化 Attention kernel 的性能。到第二周中期，我们已有足够好的数字可以与合作伙伴分享。

演示准备工作也在全面展开。这项工作需要 IT 部门确保我们能现场展示基准测试结果，设计部门把演示做得专业，产品团队帮助打磨信息表达。

与此同时，我们的工程团队继续针对新硬件优化技术栈，利用第一周建好的自动化向其他团队提供实时数据。

到周五，[MAX nightlies](https://x.com/Modular/status/1968071169837613217) 已在 MI355 上平稳运行，我们的基准测试持续领先于 AMD 定制的 vLLM 分支。带着这些结果，我们已准备好周二演示！

**💡 趣事：** MI355 的启用不仅快，而且仅由两位工程师在正常工作时间内完成，没有熬夜、零赶工。事实证明，出色的架构能同时提升性能*与*心智健康。

# **结果：超越业界**

两周结束时，**MAX 在多种工作负载上最多超出 AMD 优化的 vLLM 分支 2.2×**——同时保持了对 **MI300**、**MI325** 和 **MI355** 的**完全可移植性**。这些收益部分来自 kernel，但也来自整个技术栈的协同，兼顾了性能与可移植性。

更了不起的是，整个启用工作只涉及两位工程师，在 MI355 启用上各投入两周，其中一人还有预先安排的假期，所以实际上相当于 1.5 位工程师工作两周。总计产出 20 个小 PR、零熬夜。这是软件架构成就交付速度的教科书案例。

性能结果不言自明。

在 AMD 媒体技术日上，与 **NVIDIA 旗舰 Blackwell 架构**相比，MAX 是[**唯一**](https://tensorwave.com/blog/save-up-to-70-with-max-the-fastest-inference-engine-on-amd-compute)展示出明显 **TCO 优势**的推理方案。

这次两周冲刺只是开始。自那次演示以来，我们扩展了 MI355 支持，加入了早期 **Apple silicon** 支持，并在 **NVIDIA Blackwell** 和 **AMD MI355X** 上都达到了**最先进性能**。看看我们[近期的 25.6 版本](https://www.modular.com/blog/modular-25-6-unifying-the-latest-gpus-from-nvidia-amd-and-apple)。
