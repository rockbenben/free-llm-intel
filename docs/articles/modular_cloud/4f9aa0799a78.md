# 借助 AI 智能体翻译到 Mojo

在 Modular，我们一直在尝试最新的智能体编程工具，把最好的整合进工作流，也一路上学到不少教训。我们意识到的一点是：Mojo 语言天生契合现代 AI 编码智能体的需求。

Mojo 语法熟悉、样板极少，对智能体来说读写都很省 token。它的类型系统与约束模型能在编译期抓住许多常见错误。与其让智能体狂烧 token 构建一个可能行也可能不行的东西、不行再花几小时调试，Mojo 早早发现问题，并给智能体提供清晰的错误信息。这种更紧的反馈回路，正是[强类型语言在智能体工作流中日益受青睐](https://github.blog/ai-and-ml/llms/why-ai-is-pushing-developers-toward-typed-languages/)的原因之一。

Mojo 也不用人机工程换取性能。同一份读起来干净利落的代码，可以瞄准 [Mojo 支持的完整硬件谱系](https://mojolang.org/docs/requirements/#gpu-compatibility)，包括 NVIDIA、AMD 与 Apple silicon GPU。

### 帮助 AI 智能体处理 Mojo

唯一的挑战是 Mojo 仍是年轻语言，LLM 没在大量 Mojo 代码上训练过。因此我们创建了工具，帮助智能体从一开始就产出正确、地道的 Mojo。这始于[把 Modular 写过的所有 Mojo 代码开源](https://github.com/modular/modular)，连同我们面向 MAX 的全部 Python API。

再进一步，Mojo 现在有了[编码智能体 skills](https://github.com/modular/skills)，可接入大多数 AI 编码助手。这些 skills 像一个轻量适配层，纠正 AI 模型可能产出的误解、过时模式与非地道代码。

要开始使用 skills，用一条命令即可把它装进任何受支持的编码智能体：

bash

```
npx skills add modular/skills
```

### 演示：把 CUDA 代码翻译为 Mojo

今天 Mojo 的杀手级应用，是编写高性能且可移植的 GPU kernels。然而世界上现有 kernel 代码大多用 CUDA 和 Triton 写成（主要面向 NVIDIA GPU）。借助我们的 AI 智能体 skills，你可以快速把这些既有 kernel 翻译成 Mojo。

看一个实战例子。

我们从 [Szymon Ożóg 对 CUDA Softmax 优化的探索](https://github.com/SzymonOzog/FastSoftmax)出发。本地 clone 这个仓库，在家也能跟着做：

bash

```
git clone git@github.com:SzymonOzog/FastSoftmax.git
```

本教程使用 Claude Code 搭配 Opus 4.7 模型，但同样的步骤适用于任何前沿编码智能体。

首先创建一个新的 Mojo 项目。我们的 `new-modular-project` skill 负责项目搭建，引导你选择正确的配置。

在 AI 智能体里开个新会话，先给它这个 prompt：

bash

```
I'd like to start a new Mojo project named mojo_softmax using a quick uv
environment and the nightly build of Mojo.
```

你的智能体应当激活 `new-modular-project` skill 并替你完成项目设置：

bash

```
⏺ Skill(new-modular-project)                                                    
  ⎿  Successfully loaded skill                                                                                
⏺ All options specified. Creating a quick uv environment with nightly Mojo.
                                                                                
  Listed 1 directory (ctrl+o to expand)                                         
                                                                               
⏺ Bash(mkdir mojo_softmax && cd mojo_softmax && uv venv && uv pip install mojo  
      --index https://whl.modular.com/nightly/simple/ --prerelease allow)     
  ⎿  Running…                                                                   
```

然后在新项目就绪时回报：

bash

```
⏺ Bash(source .venv/bin/activate && mojo --version)                             
  ⎿  Mojo 0.26.3.0.dev2026042105 (cfe16c5b)                                                                                
⏺ Project mojo_softmax is set up at ./mojo_softmax with a quick uv venv and nightly Mojo  
  0.26.3.0.dev2026042105 installed.                                                                                
  To work in it:                                                                
  cd mojo_softmax                                                               
  source .venv/bin/activate   
```

项目配置好 Mojo 编译器与工具后，就可以开始把 CUDA 参考代码翻译成 Mojo。用类似下面的 prompt，把路径改成你 clone FastSoftmax 的位置：

bash

```
In the directory ./FastSoftmax, there's a CUDA example of a fast softmax
I'd like to port to Mojo. When done, build it and test it to verify
that it works correctly.
```

不同智能体的输出会有差异，我本地运行时看到的是：

bash

```
⏺ I've read all the CUDA kernels. The file contains 10 progressive optimizations, with
 `softmax_kernel8` as the default - it uses online normalization (single-pass max+sum), float4
 vectorized loads, warp shuffles, and shared-memory cross-warp reduction.
 
 I'll port this to Mojo using shared-memory tree reductions (universal across GPU backends
 including Apple silicon) with coalesced strided access, matching the algorithm of kernels 3-8.                                                                                                                            
```

接着智能体会激活 `mojo-syntax` 与 `mojo-gpu-fundamentals` skills，写出 `fast_softmax.mojo` 文件：

bash

```
⏺ Now I'll load the Mojo skills to guide the port.                                                                                
⏺ Skill(mojo-gpu-fundamentals)                                                  
  ⎿  Successfully loaded skill                                                                                
⏺ Skill(mojo-syntax)                                                            
  ⎿  Successfully loaded skill                            
⏺ Now I have enough understanding to write the Mojo port. I'll implement the    
  softmax kernel, plus a test harness that verifies against a CPU       
  reference.                                                                                
⏺ Write(fast_softmax.mojo)                                                           
```

完成后，智能体会构建并测试 Mojo 实现以验证其正确运行：

bash

```
⏺ Bash(source .venv/bin/activate && mojo build fast_softmax.mojo 2>&1 | head -80)
  ⎿  (No output)                                          
                                  
⏺ Build succeeded. Running the test now.                                                          
⏺ Bash(source .venv/bin/activate && ./fast_softmax 2>&1 | head -40)                  
  ⎿  row 0 sum = 0.9999997 drift from 1.0 = 2.9802322e-07 
     row 1 sum = 0.99999994 drift from 1.0 = 5.9604645e-08                      
     row 2 sum = 1.0000001 drift from 1.0 = 1.1920929e-07                       
     … +8 lines (ctrl+o to expand)                                                                                
⏺ The port is complete and verified working on the local GPU.                
```

虽然你的具体项目格式可能与我不同，但你的 `mojo_softmax` 项目现在应当包含一个正确的 Mojo kernel 和检验它的测试（我这里就是 `fast_softmax.mojo`）。

一个关键点值得注意：这个示例的原始 CUDA 代码只能跑在 NVIDIA GPU 上，而新的 Mojo 版本能跑在 NVIDIA、AMD 与 Apple silicon GPU 上，以及 Mojo 未来支持的其他加速器。这是为新硬件引导 kernel、算法乃至模型的极快方式。

新翻译的 Mojo 版本在功能上应与源头一致，你可以通读代码理解概念如何从 CUDA 映射到 Mojo。下一步，你还可以对这份代码做更进一步的 Mojo 专属优化，或为你手头的具体硬件调优。而且参考源不限于 CUDA——同样的流程适用于 Python 里的 Triton kernels 以及各种其他语言的代码。

### 加速你的 Mojo 之旅

如你所见，你可以把散落在 Python、CUDA 及众多来源的既有参考代码快速翻译成 Mojo。开箱即用就能带来实打实的改进。例如 Automatika Robotics 把用于自主导航的一些 CUDA 与 SYCL kernels 移植到 Mojo 时，立刻收获了性能提升。按[他们自己的话](https://forum.modular.com/t/project-mojo-for-robotics-porting-gpu-navigation-kernels-jetson-strix-halo/2952/2)说：

*“同样的负载，我们用在我们 EMOS kompass-core：5,001 条轨迹 × 1,000 个点，10 秒时域，启用 4 个代价函数。*

- ***kompass-core SYCL（AdaptiveCpp / CUDA）：*** *16.358 ms (±0.12)*
- ***kompass-mojo（Mojo 0.26.1 / CUDA）：* *15.973 ms (±0.09)***

*需要说明：我是用 Claude 结合官方 skills 翻译的我的 Mojo kernels，Mojo 侧还没做任何优化工作。所以这个初始结果相当亮眼。”*

[Mojo 1.0 beta 1](https://www.modular.com/blog/modular-26-3-mojo-1-0-beta-max-video-gen-and-more)刚刚发布，用前沿 AI 编码智能体配合这些 skills，是把老 Mojo 项目升级到今年晚些时候正式发布 1.0 的好方法。我们深知 LLM 受益于变化不大的语言，这也是我们[为 1.0 稳定 Mojo](https://www.modular.com/blog/the-path-to-mojo-1-0)的原因之一。

事实上，我们随机抽了五个社区项目，安装这些 skills，然后对 Claude Opus 4.7 说：

> 我想把这个项目更新到最新版 Mojo。

五个案例全部成功：智能体在没有其他协助的情况下，把整个项目正确更新到可在最新 Mojo 1.0 beta 1 上构建。

### **自己试试**

这些 Mojo 编码 skills 现已可用。三种用法：

**给你的 Python 提速。** 如果某个 Python 函数成了瓶颈，装了 Mojo skills 的智能体可以把它翻译成 Mojo。指向慢代码，它产出一个可直接替换、可 profile、可调优的初版 Mojo 移植。想更进一步，稍作改动同一份代码就能瞄准 GPU。

**用 Mojo 取代 CUDA 或 Triton。** 如 softmax 演示所示，skills 能处理从 CUDA 到 Mojo 的结构性翻译。同样流程适用于 Triton kernels 及其他 kernel 领域特定语言。你得到一个可移植的起点，跑在 NVIDIA、AMD 与 Apple silicon GPU 上，无需从零重写。

**参与进来。** skills 本身是[开源的](https://github.com/modular/skills)。如果遇到当前 skills 处理不好的模式，开个 issue 或贡献修复。智能体在真实世界里见到的 Mojo 代码越多，写得就越好。

用 `npx skills add modular/skills` 安装 skills，并在 [Modular 论坛](https://forum.modular.com/)告诉我们你构建了什么。
