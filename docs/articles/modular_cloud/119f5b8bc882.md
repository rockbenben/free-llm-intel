# Modular 亮相 NVIDIA GTC 2026：Blackwell 上的 MAX、Mojo Kernel 移植与 B200 上的 DeepSeek V3

每年春天，圣何塞都会挤满对 GPU 有强烈见解的人，我们也很高兴是其中一员。本周来 NVIDIA GTC 找我们，展位 #3004，我们将整周在 Blackwell 上运行演示。

以下是我们会展示的内容预览：

## 用 MAX 服务的 DGX Spark 上的 FLUX 图像生成

我们在展位上用 [MAX 框架](https://docs.modular.com/max/get-started/)在一台 NVIDIA DGX Spark 上运行 Black Forest Labs 的开源 FLUX.2-klein 扩散模型。你选一个提示词，看它现场生成，然后远程扩展：同一份代码在 B200 上驱动 FLUX.2-dev 模型。

MAX 负责整条流水线：图编译、kernel 调度和服务，从底层用 Mojo 写成，而非用第三方零件拼装。如果图像或视频生成在你团队的路线图上，欢迎来展位亲自看看 MAX 如何处理完整扩散流水线。

## 借助 AI 辅助开发把一个 CUTLASS Blackwell conv2d kernel 移植到 Mojo

去年的 GTC，人们在展位上说得最多的是："你们是真正教我们怎么给 GPU 编程的展位。"今年，我们继续这么做。

这个演示会带你走一遍把 NVIDIA 的 CUTLASS Blackwell conv2d kernel（`76_blackwell_conv_fprop`）从 CUDA C++ 移植到 Mojo 的过程。成果：在 B200 上达到 130.7 TFLOPS（与 CUTLASS 吞吐量持平），Mojo 代码约 770 行，而 CUTLASS 约 3k 行。

Mojo 的结构化 kernel 架构让我们复用了约 90% 的现有 matmul 基础设施：warp specialization、TMA 流水线、TMEM 管理、CLC 调度。唯一的新代码是 `im2col` tile 加载器。性能优势来自 Mojo 内置的自动调优和直接硬件访问——没有黑盒库，没有隐藏的翻译层。

整个移植在单次会话中用 Cursor 和 Claude 完成。agent 分析了 CUTLASS 源码、实现了 barrier 同步、调试了 GPU kernel 挂起，并从 0.16 TFLOPS 一路迭代到 130.7 TFLOPS。我们会展示 git 历史，让你看到每一个优化步骤。

这也预示了 Mojo 的方向：Mojo 1.0 计划在今年晚些时候发布，带来语义化版本和稳定的 API 面。所有 kernel 代码都在我们的 [modular/max](https://github.com/modular/max) GitHub 仓库开源。

## 通过 Modular Cloud 在 B200 上运行 DeepSeek V3

我们在云端 NVIDIA B200 GPU 上通过 [Modular Cloud](https://www.modular.com/request-demo) 服务 DeepSeek V3。你发送一个提示（文本或代码），看 token 实时流回，并附带实时指标：每秒 token 数、首 token 时间、负载下的延迟。

在生产规模部署 DeepSeek V3 意味着要应对缓慢的首 token 延迟、不稳定的尾延迟和低效的 GPU 利用率。Modular Cloud 是一个全托管 endpoint，用 MAX 和 Mojo kernel 端到端优化。它随你的用量伸缩，让你不必自己管理部署。

与其他推理平台不同，我们通过 MAX 和 Mojo 控制全栈，这意味着我们可以在每一层调优性能。有意评估专用 endpoint 的企业团队，欢迎到展位与我们交流。
