# Modverse #47: MAX 25.2 and an evening of GPU programming at Modular HQ

Caroline Frasca

Community

MAX 25.2 is turning heads — and for good reason. This powerful update delivers industry-leading performance for large language models on NVIDIA GPUs, all without CUDA. MAX 25.2 builds on the momentum of 25.1 and introduces major upgrades to help you build GenAI systems that are faster, leaner, and easier to scale. Highlights include:

- State-of-the-art performance on H100 and H200 GPUs
- Multi-GPU support
- Enhanced LLM serving
- Ultra-slim containers for rapid deployment
- Mojo-powered GPU programming
- Advanced features like GPTQ quantization

Curious to see it in action? Join us at **Modular HQ** on **April 24** for an evening dedicated to GPU programming with Mojo and MAX: [**Next-Gen GPU Programming: Hands-On with Mojo & MAX**](https://lu.ma/modular-meetup?utm_source=modverse). Hear from Chris Lattner and Jack Clayton, meet fellow developers, and explore how these tools are reshaping what’s possible in AI.

And if you haven’t already, check out [the latest community meeting recording](https://www.youtube.com/watch?v=lJkHv0juxUE)—featuring critical updates to the MAX and Mojo license, a live demo of Kelvin, a typesafe dimensional analysis library for Mojo, and Q&A with the team.

# Blogs, Tutorials, and Videos

- MAX 25.2 delivers industry-leading performance on NVIDIA GPUs, built from the ground up without CUDA, to power faster, more responsive, and more customizable GenAI deployments at scale. Dive into [**the release blog post**](https://www.modular.com/blog/max-25-2-unleash-the-power-of-your-h200s-without-cuda?utm_source=modverse).
- Catch up on the latest installments in Chris Lattner’s Democratizing AI Compute blog post series:In part 5, [**What about CUDA C++ alternatives like OpenCL?**](https://www.modular.com/blog/democratizing-ai-compute-part-5-what-about-cuda-c-alternatives?utm_source=modverse), we explore why C++ alternatives to CUDA failed to gain traction in AI, challenges faced, and key lessons for the future of GPU programming.Part 6, [**What about AI compilers (TVM and XLA)?**](https://www.modular.com/blog/democratizing-ai-compute-part-6-what-about-ai-compilers?utm_source=modverse), breaks down how kernel fusion boosts performance, why AI compilers struggle with GenAI workloads, and what prevented TVM and XLA from fully unlocking GPU performance or democratizing AI compute.Part 7, [**What about Triton and Python eDSLs?**](https://www.modular.com/blog/democratizing-ai-compute-part-7-what-about-triton-and-python-edsls?utm_source=modverse), examines Python eDSLs and takes a closer look at Triton–one of the most popular approaches in this space–as well as a few others.In part 8, [**What about the MLIR compiler infrastructure?**](https://www.modular.com/blog/democratizing-ai-compute-part-8-what-about-the-mlir-compiler-infrastructure?utm_source=modverse), Chris Lattner shares the origin story of the MLIR compiler framework: how it started, what it changed, and the power struggles along the way.

- Missed Chris Lattner’s lightning talk at Modular’s NVIDIA GTC booth? [**The recording**](https://www.youtube.com/watch?v=d89mHSeN_QE) is available on YouTube. In just a few minutes, Chris breaks down what’s holding GPU programming back—and how MAX and Mojo are making it fast, scalable, and developer-friendly again.

- During [**community meeting #15**](https://www.youtube.com/watch?v=lJkHv0juxUE), we announced key updates to the MAX and Mojo license, and enjoyed a live demo of Kelvin, a new typesafe dimensional analysis library for Mojo.

# Awesome MAX + Mojo

- [jake-danton](https://forum.modular.com/u/jake_danton/summary) created a [Mojo Gameboy emulator](https://forum.modular.com/t/gameboy-emulator/684).
- [forfudan](https://forum.modular.com/u/forfudan/summary) launched [DeciMojo](https://forum.modular.com/t/decimojo-fixed-point-decimal-arithmetic-implemented-in-mojo/682), a correctly-rounded, fixed-point decimal arithmetic library in Mojo.
- [bgreni](https://forum.modular.com/u/bgreni/summary) shared [ChronoFlare](https://forum.modular.com/t/chronoflare-a-type-safe-time-interval-library/1155), a library for representing time intervals in a type-safe way, inspired by [std::chrono::duration](https://en.cppreference.com/w/cpp/chrono/duration). bgreni also shared [Kelvin](https://forum.modular.com/t/kelvin-typesafe-dimensional-analysis/1198), a typesafe dimensional analysis library for scientific computing.
- [Samufi](https://forum.modular.com/u/samufi/summary) developed [Larecs](https://forum.modular.com/t/larecs-lightweight-archetype-based-ecs/558), a performance-oriented archetype-based ECS for Mojo, based on the Go ECS [Arche](https://github.com/mlange-42/arche).
