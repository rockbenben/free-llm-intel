# Modular 25.4：一个容器，兼顾 AMD 与 NVIDIA GPU，没有锁定

我们很高兴宣布 Modular Platform 25.4——一次重大发布，把 AMD GPU 的全部威力带入我们的整个平台。这次发布标志着向普惠化高性能 AI 迈出的关键一步：无缝移植到 AMD GPU。**开发者现在可以构建和部署针对峰值性能优化的模型，完全不依赖任何单一硬件厂商**——解锁更大的灵活性、更低的成本和更广泛的算力获取。

## **🚀 现正式支持 AMD GPU**

**25.4 的头条特性是对 AMD GPU 的官方支持，由我们[新宣布的 AMD 合作](https://www.modular.com/blog/modular-x-amd-unleashing-ai-performance-on-amd-gpus)背书。**你现在可以在 AMD MI300X 和 MI325X GPU 上部署完整加速的 Modular，用的是与 NVIDIA[完全相同的代码和容器](https://hub.docker.com/r/modular/max-full)，零改动、零工作流调整。企业第一次可以构建可移植、高性能的 GenAI 部署，在任何平台上运行，没有厂商锁定，也不需要平台专用优化。

相比现有基础设施，**Modular 在 AMD GPU 上对主流 LLM 工作负载带来可观的性能收益**——即便与在 NVIDIA GPU 上运行相同工作负载相比也极具竞争力：

- **最高 53% 更高的吞吐量**，在 [Llama-3.1-8B](https://builds.modular.com/models/Llama-3.1-Instruct/8B)、[Gemma-3-12B](https://builds.modular.com/models/gemma-3-it/1B)、[Mistral-Small-24B](https://builds.modular.com/models/Mistral-Small-Instruct-2501/24B) 等业界领先语言模型的 prefill 密集型 BF16 工作负载上，对比 AMD MI300X 上的 vLLM。
- **最高 32% 更高的吞吐量**，在 decode 密集型 BF16 工作负载上，对比 AMD MI300X 上的 vLLM。
- **吞吐量持平或更优**，在 MI325X 上运行 ShareGPT 工作负载，对比 NVIDIA H200 上的 vLLM。

AMD MI300X 和 MI325X GPU 往往在诸多 AI 工作负载上提供更优的性价比，让你能够基于真实世界经济性来优化总拥有成本，而不是被锁进单一厂商的定价结构。关于这些性能基准的更深入分析，见我们最近的 AMD 合作[公告](https://www.modular.com/blog/modular-x-amd-unleashing-ai-performance-on-amd-gpus)。

除头条的 AMD GPU 支持外，我们还引入：

- **AMD 消费级 GPU 的初步支持**，包括面向[全系列 RDNA3 和 RDNA4 GPU](https://docs.modular.com/mojo/stdlib/gpu/host/info/#radeon7600)的基础调优。
- **扩展的消费级硬件兼容性**，支持从 [NVIDIA RTX 20xx](https://docs.modular.com/mojo/stdlib/gpu/host/info/#rtx2060) 到 [50xx GPU](https://docs.modular.com/mojo/stdlib/gpu/host/info/#rtx5090)。
- **一份 GPU 支持矩阵**，用单一代码库涵盖[AMD 与 NVIDIA 众多最强大的企业级 GPU](https://docs.modular.com/mojo/stdlib/gpu/host/info/)。

虽然部分架构的 AI 模型支持仍在开发中，但 GPU 编程能力在整个扩展的硬件生态中已完全可用——并且是[开源](https://github.com/modular/modular/)的。你今天就可以借助不断扩充的 [Mojo GPU Puzzles](https://builds.modular.com/puzzles/introduction.html) 用 Mojo 学习为这一整排 GPU 编程。

## **🤖 扩展的模型支持**

Modular 25.4 显著扩展了我们的模型生态，包括：

- [**GGUF 量化的 Llama**](https://builds.modular.com/models/Llama-3.2-Instruct/1B-Q4_K_M)，使用 paged KVCache 策略支持 q4_0、q4_k 和 q6_k 量化。
- [**Qwen3 家族**](https://builds.modular.com/models/Qwen3/1.7B)模型，具备先进推理与多语言能力。
- [**OLMo2 家族**](https://builds.modular.com/models/OLMo-2-0425/1B-Instruct)模型，面向研究和常见任务设计。
- [**Gemma3 多模态**](https://builds.modular.com/models/gemma-3-it/1B)模型，提供优化性能与更强的安全性。

前往 [Code with Modular](https://builds.modular.com/)，你可以找到这些发布，以及另外 500 多个生成式 AI 模型。

## 🐍 **Python–Mojo 绑定**

Mojo 的简洁易用一直从 Python 汲取灵感，而 Mojo 25.4 通过全新 Python–Mojo 绑定的开发者预览版让两门语言走得更近。你现在可以直接从 Python 代码调用 Mojo 函数，无需管理复杂的构建系统或依赖链。用 Python 开发，然后把你性能热点无缝替换为飞快的 Mojo 等价实现。这就像给你的 Python 应用装了一个涡轮按钮！在 [Modular 论坛](https://forum.modular.com/t/initial-support-for-calling-mojo-from-python/1514/)了解更多，并试试 [GitHub 上的代码示例](https://github.com/modular/modular/tree/main/examples/mojo/python-interop)。
