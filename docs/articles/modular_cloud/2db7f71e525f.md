# Mojo 24.5 上手实践

Mojo 24.5 发布了，这是我们迄今最大的一次版本。它现已通过新的 Magic 包管理器提供，并随 MAX 24.5 版本一起打包。请[安装 Magic](https://docs.modular.com/magic/#install-magic) 以便跟随本文实践。

本次版本包含若干核心语言变更和标准库增强。在这篇博文中，我们将通过代码示例深入其中许多新特性与语言改进。我们的例子聚焦于统一的指针类型 `UnsafePointer`，并逐步引入其他值得关注的特性。读完本文，你将全面理解这些增强，并能在你的 Mojo 代码中自如运用它们。

本次版本最大的亮点之一是社区的巨大贡献。我们收到了来自 11 位社区贡献者的众多 pull request，涵盖新特性、bug 修复、文档改进和代码重构。特别感谢 🙏🏼 我们的社区贡献者：

> @jjvraw, @artemiogr97, @martinvuyk, @jayzhan211, @bgreni, @mzaks, @msaelices, @rd4com, @jiex-liu, @kszucs, @thatstoasty.

完整变更列表请参阅 [24.5 版 changelog](https://docs.modular.com/mojo/changelog#v245-2024-09-13)。

本文所有代码都可在我们的 [GitHub 仓库](https://github.com/modularml/devrel-extras/tree/main/blogs/hands_on_with_mojo_24_5)中找到。

### 大幅减少自动导入的模块

Mojo v24.5 大幅减少了自动导入用户程序的实体集合。此前，*memory*、*sys*、*os*、*utils*、*python*、*bit*、*random*、*math*、*builtin* 和 *collections* 等模块会自动可用。现在，只有 *prelude/__init__.mojo* 中明确列举的实体会被自动导入。这一变化要求开发者**显式导入**他们使用的实体，避免意外的命名空间污染，提升代码清晰度。

### *fn* 中不再需要 *var*

Mojo 24.5 放宽了在 *fn* 函数中使用 *var* 的要求，使 *fn* 更接近 *def* 函数，同时仍保留其独特能力。不过，*fn* 与 *def* 的区别仍在于它允许对内存进行更强的控制——在通过 Foreign Function Interface（FFI）对接底层 C 代码时这一点尤其重要。另一个区别是 *def* 会隐式抛出异常。

### 通过 *UnsafePointer* 统一指针数据结构

在 24.5 中，我们通过把所有先前的指针类型并入单一类型 [UnsafePointer](https://docs.modular.com/mojo/stdlib/memory/unsafe_pointer/UnsafePointer) 来统一指针数据结构。以前的类型——*DTypePointer*、*LegacyPointer* 和 *Pointer*——已被移除。它们的功能已并入 *UnsafePointer*，在保留全部必要能力的同时简化了指针系统。这一统一让 Mojo 中的指针使用更顺畅，减少了开发者的困惑。

下一节将温习 *UnsafePointer* 及其正确用法。你可以跳过本节直接看示例。

### *UnsafePointer* 温习

#### 理解未初始化内存的未定义行为（UB）

[UnsafePointer](https://docs.modular.com/mojo/stdlib/memory/unsafe_pointer/UnsafePointer) 类型创建对内存位置的间接引用。你可以用 *UnsafePointer* 动态分配和释放内存，或指向由别处代码分配的内存。你可以用这些指针编写与底层接口交互的代码、对接其他编程语言，或构建某些数据结构。但正如其名，它们天生不安全。例如，使用 unsafe 指针时，你要为正确分配和释放内存负责。

当我们在 Mojo 中用 *UnsafePointer* 分配内存时，所分配的内存是未初始化的。在不正确初始化的情况下访问这段未初始化内存，属于**未定义行为**（UB）。在未初始化的指针上使用 [*__getitem__*](https://docs.modular.com/mojo/stdlib/memory/unsafe_pointer/UnsafePointer#__getitem__) 操作（即方括号 *[]*）时就可能发生：

Mojo

ptr = UnsafePointer[Int].alloc(1)
ptr[0] = 42 <-- Undefined Behavior

上例中 *ptr[0]* 试图提供一个有效引用，但由于内存未初始化，该引用的有效性与生命期是不明确的。与 C 不同——C 不作区分，并因此长期受内存漏洞困扰——Mojo 要求对 unsafe 指针进行显式初始化以保证内存安全。

#### 用 *init_pointee_copy/move* 正确初始化

为确保内存被正确初始化，Mojo 提供了诸如 *UnsafePointer* 的 [*init_pointee_copy*](https://docs.modular.com/mojo/stdlib/memory/unsafe_pointer/UnsafePointer#init_pointee_copy) 之类的方法，适用于 *Int* 这样的数值类型。该方法允许安全地初始化内存，我们正是应该用它来安全地初始化 *ptr*。

Mojo

ptr = UnsafePointer[Int].alloc(1)
ptr.init_pointee_copy(42)

在前面的代码片段中，用 *ptr[0] = 42* 初始化 *ptr* 被认定为有问题，因为它直接对未初始化内存赋值。使用 *init_pointee_copy* 解决了这个问题，确保内存在使用前被正确、安全地初始化。

关于如何分配和初始化指针的更多讨论，请阅读 [UnsafePointer 文档](https://docs.modular.com/mojo/manual/pointers)。

有了这份入门，我们开始使用 *UnsafePointer*，并逐步介绍 Mojo 24.5 的其他特性，最终看到把这些新特性全部串起来的端到端示例。

### 示例 1：*UnsafeBuffer*

下面是用 *UnsafePointer* 在 Mojo 中实现缓冲区数据结构的一种方式。你能看出这个缓冲区为何不安全吗？

Mojo

from memory import memset_zero

struct UnsafeBuffer:
    var data: UnsafePointer[UInt8]
    var size: Int

    fn __init__(inout self, size: Int):
        self.data = UnsafePointer[UInt8].alloc(size)
        memset_zero(self.data, size)
        self.size = size

    fn __del__(owned self):
        self.data.free()

如果我们运行 *magic run mojo unsafe_buffer.mojo*：

Mojo

def main():
    ub = UnsafeBuffer(10)
    print("initial value at index 0:")
    print(ub.data[0])
    ub.data[0] = 255
    print("value at index 0 after getting set to 255:")
    print(ub.data[0])

我们得到输出：

Output

initial value at index 0:
0
value at index 0 after getting set to 255:
0

但为什么？哪里出了问题？

正如[安全部分](https://docs.modular.com/mojo/manual/pointers#safety)所述，*UnsafePointer* 不携带任何生命期信息，这意味着 *UnsafeBuffer* 中 *data* 的生命期与 *ub* 实例的生命期没有关联。在最后一条 *print(ub.data[0])* 中，编译器认为在 *ub.data[0] 计算出元素指针之后、读取该指针之前，*ub* 就已不再使用。结果，[Mojo 的（ASAP）析构器](https://docs.modular.com/mojo/manual/lifecycle/death#default-destruction-behavior)被激活，释放了 *data* 指针。任何后续调用都变成未定义行为（UB），因为它们访问的是已释放的内存。这就是我们（还算幸运地）看到意外输出的原因。

在下一个示例中，我们尝试把缓冲区实现做安全。

### 示例 2：*SafeBuffer*

下面的实现通过 *write* 和 *read* 方法，把（私有的）*_data* 指针的生命期绑定到 *SafeBuffer* 实例上。此外，我们在 *write* 和 *read* 方法中用 [debug_assert](https://docs.modular.com/mojo/stdlib/builtin/debug_assert/) 检查边界，它通过编译选项 *-D MOJO_ENABLE_ASSERTIONS* 激活。我们马上会看到怎么用。

Mojo

from memory import memset_zero

struct SafeBuffer:
   var _data: UnsafePointer[UInt8]
   var size: Int

   fn __init__(inout self, size: Int):
       debug_assert(size > 0, "size must be greater than zero")
       self._data = UnsafePointer[UInt8].alloc(size)
       memset_zero(self._data, size)
       self.size = size

   fn __del__(owned self):
       self._data.free()

   fn write(inout self, index: Int, value: UInt8):
       debug_assert(0 <= index < self.size, "index must be within the buffer")
       self._data[index] = value

   fn read(self, index: Int) -> UInt8:
       debug_assert(0 <= index < self.size, "index must be within the buffer")
       return self._data[index]

现在如果通过以下命令运行应用代码

Mojo

def main():
    sb = SafeBuffer(10)
    sb.write(0, 255)
    print("value at index 0 after getting set to 255:")
    print(sb.read(0))

Bash

magic run mojo -D MOJO_ENABLE_ASSERTIONS safe_buffer.mojo

我们看到输出符合预期：

Output

value at index 0 after getting set to 255:
255

注意，关键在于不要直接访问 *_data*，而要通过 *write* 和 *read* 方法来把 *_data* 指针的生命期绑定到底层实例。

#### 具名结果绑定

Mojo 现在支持具名结果绑定（named result bindings）。具名结果绑定可把函数结果直接就地构造（emplace）到函数的输出槽位中。相比“保证”的具名返回值优化，此特性为函数结果的就地构造提供了更多灵活性与保证。

要看到它如何简化应用代码，我们接着看下面基于 *SafeBuffer* 的代码：

Mojo

struct SafeBuffer:
    ...

    @staticmethod
    fn initialize_with_value(size: Int, value: UInt8) -> Self as output:
        output = SafeBuffer(size)
        for i in range(size):
            output.write(i, value)

        return

def main():
    buffer = SafeBuffer.initialize_with_value(size=10, value=128)

在这段代码中，我们定义了一个静态方法 *initialize_with_value*，返回一个 *SafeBuffer* 实例。方法把 *output* 声明为 *Self* 类型的返回变量。方法内我们创建一个指定大小的新 *SafeBuffer* 来初始化 *output*，然后向每个索引写入给定值来填充缓冲区。

通过使用具名返回变量 *output*，编译器会直接在返回值最终驻留的内存位置构造并修改它。这省去了对 *SafeBuffer* 实例不必要的复制或移动——对于既不可移动也不可复制的类型这一点很重要。函数签名中的 *as output* 语法表明 *output* 是返回变量；最后的 return 语句不带值地返回控制权，因为 *output* 本身就是返回值。

#### 参数排他性检查

Mojo 24.5 现在会在编译期检查可变参数引用不与其他引用别名。这意味着 Mojo 要求可变的引用（包括因 *borrow*ed/*inout* 参数产生的隐式引用）必须是被唯一引用（无别名）的。这对代码安全很重要，因为它让编译器（和代码读者）能理解一个值在何处、何时被修改。它对性能优化也有用，因为编译器由此可以确信：通过不可变引用的访问不会在背后发生变化。

要看到参数排他性如何帮助写出安全代码并在编译期捕获错误，我们看看下面的 *process_buffers* 函数——它用我们的 *SafeBuffer* 把借用缓冲区的值覆写进一个可变缓冲区：

Mojo

fn process_buffers(buffer1: SafeBuffer, inout buffer2: SafeBuffer):
   debug_assert(buffer1.size == buffer2.size, "buffer sizes much match")
   for i in range(buffer1.size):
       buffer2.write(i, buffer1.read(i))

现在假设应用代码中我们有：

Mojo

def main():
    buffer1 = SafeBuffer.initialize_with_value(size=10, value=128)
    buffer2 = SafeBuffer(10)
    process_buffers(buffer1, buffer1)

我们在应用代码中不小心把 *buffer1* 同时传给了 *process_buffers* 的两个参数，而第二个参数本意是可变的（*inout*）。这意味着我们试图在持有 *buffer1* 借用引用的同时修改它。Mojo 的参数排他性规则要求可变引用（*inout* 参数）必须唯一且无别名。编译器在编译期检测到这一违规，对潜在 bug 发出警告，并通过强制执行无别名规则保障代码安全。这也让编译器可以把参数引用视为无别名，从而更激进地优化。

运行代码时，编译器会警告此类问题：

Output

warning: call argument allows writing a memory location previously readable through another aliased argument
    process_buffers(buffer1, buffer1)
                    ^~~~~~~~  ~~~~~~~
note: 'buffer1' value is passed through aliasing 'inout' argument
    process_buffers(buffer1, buffer1)
                    ^          ~~~~~~~

#### Formattable trait

从 Mojo 24.5 起，[print](https://docs.modular.com/mojo/stdlib/builtin/io/print) 函数要求其参数符合 [Formattable](https://docs.modular.com/mojo/stdlib/utils/format/Formattable) trait。这默认实现了高效的流式写入，避免不必要的中间 *String* 堆分配。

让我们用这个新 trait 实现 *format_to* 和 *__str__ *，以便轻松打印缓冲区值。其他一切不变，只是加上 *Formattable* 和 *Stringable*：

Mojo

struct SafeBuffer(Stringable, Formattable):
   ...

   fn __str__(self) -> String:
       return String.format_sequence(self)

   fn format_to(self, inout writer: Formatter):
      debug_assert(self.size > 0, "size must be greater than zero")
       writer.write("[")
       for i in range(self.size - 1):
           writer.write(self._data[i], ", ")

       writer.write(self._data[self.size - 1])
       writer.write("]")

现在通过 *magic run mojo safe_buffer.mojo* 在应用代码中测试：

Mojo

def main():
    buffer1 = SafeBuffer.initialize_with_value(size=10, value=128)
    buffer2 = SafeBuffer(10)
    process_buffers(buffer1, buffer2)
    print("buffer2:", buffer2)

产生预期输出：

Output

buffer2: [128, 128, 128, 128, 128, 128, 128, 128, 128, 128]

为完整起见，这里是 *safe_buffer.mojo* 的全部代码：

Mojo

from memory import memset_zero

struct SafeBuffer(Stringable, Formattable):
    var _data: UnsafePointer[UInt8]
    var size: Int

    fn __init__(inout self, size: Int):
        debug_assert(size > 0, "size must be greater than zero")
        self._data = UnsafePointer[UInt8].alloc(size)
        memset_zero(self._data, size)
        self.size = size

    @staticmethod
    fn initialize_with_value(size: Int, value: UInt8) -> Self as output:
        output = SafeBuffer(size)
        for i in range(size):
            output.write(i, value)

        return

    fn __del__(owned self):
        self._data.free()

    fn write(inout self, index: Int, value: UInt8):
        debug_assert(0 <= index < self.size, "index must be within the buffer")
        self._data[index] = value

    fn read(self, index: Int) -> UInt8:
        debug_assert(0 <= index < self.size, "index must be within the buffer")
        return self._data[index]

    fn __str__(self) -> String:
        return String.format_sequence(self)

    fn format_to(self, inout writer: Formatter):
        debug_assert(self.size > 0, "size must be greater than zero")
        writer.write("[")
        for i in range(self.size - 1):
            writer.write(self._data[i], ", ")

        writer.write(self._data[self.size - 1])
        writer.write("]")


fn process_buffers(buffer1: SafeBuffer, inout buffer2: SafeBuffer):
    debug_assert(buffer1.size == buffer2.size, "buffer sizes much match")
    for i in range(buffer1.size):
        buffer2.write(i, buffer1.read(i))


def main():
    sb = SafeBuffer(10)
    sb.write(0, 255)
    print("safe buffer outputs:")
    print(sb.read(0))

    buffer1 = SafeBuffer.initialize_with_value(size=10, value=128)
    buffer2 = SafeBuffer(10)
    # process_buffers(buffer1, buffer1) # <-- argument exclusivity detects such errors at compile time
    process_buffers(buffer1, buffer2)
    print("buffer2:", buffer2)

### 示例 3：泛型 *SafeBuffer[T]*

在这个示例中，我们要把 *SafeBuffer* 实现做成泛型，让它能处理不同的数据类型。为此，我们用带 *Optional[T]* 的 *UnsafePointer*，以便能用 *NoneType* 初始化指针。把 *SafeBuffer* 泛型化后，我们可以为各种数据类型创建缓冲区，同时保持安全与正确的初始化。

Mojo

from collections import Optional

struct SafeBuffer[T: CollectionElement]:
   var _data: UnsafePointer[Optional[T]]
   var size: Int

   fn __init__(inout self, size: Int):
       debug_assert(size > 0, "size must be greater than zero")
       self._data = UnsafePointer[Optional[T]].alloc(size)
       for i in range(size):
           (self.data + i).init_pointee_copy(NoneType())

       self.size = size

   @staticmethod
   fn initialize_with_value(size: Int, value: T) -> Self as output:
       output = SafeBuffer[T](size)
       for i in range(size):
           output.write(i, value)

       return

   fn __copyinit__(inout self, existing: Self):
       self._data = existing._data
       self.size = existing.size

   fn __moveinit__(inout self, owned existing: Self):
       self._data = existing._data
       self.size = existing.size

   fn __del__(owned self):
       self._data.free()

   fn write(inout self, index: Int, value: Optional[T]):
       debug_assert(0 <= index < self.size, "index must be within the buffer")
       self._data[index] = value

   fn read(self, index: Int) -> Optional[T]:
       debug_assert(0 <= index < self.size, "index must be within the buffer")
       return self._data[index]
   
   fn take(inout self, index: Int) -> Optional[T] as output:
        output = self.read(index)
        self.write(index, Optional[T](None))
        return

#### 条件符合

Mojo 24.5 允许类型“条件符合”（conditionally conform）trait，即泛型 struct 只有当其类型参数满足特定条件时才符合某个 trait。在我们的例子中，只要 *T* 自身符合 *Stringable*（即 *T: Stringable*），就可以让 *SafeBuffer[T: CollectionElement]* 符合 *Stringable*。条件符合的关键要求是：泛型参数上使用的 trait 必须包含 struct 定义中使用的 trait。

为此，我们使用 *StringableFormattableCollectionElement*，它被定义为同时包含 *Formattable* 和 [StringableCollectionElement](https://docs.modular.com/mojo/stdlib/builtin/value/StringableCollectionElement) traits：

Mojo

trait StringableFormattableCollectionElement(Formattable, StringableCollectionElement):
   ...

然后我们定义 *__str__* 方法，其类型参数 *U* 必须符合 *StringableFormattableCollectionElement*：

Mojo

fn __str__[U: StringableFormattableCollectionElement](self: SafeBuffer[U]) -> String:
    ...

注意 *self* 参数的类型写作 *SafeBuffer[U]*，重复了类型参数 *U*。这确保 * __str__* 方法只有在 *U* 符合必要 trait 时才可用，让编译器能在我们试图用不满足要求的类型使用 *SafeBuffer* 时在编译期捕获类型错误。

现在我们可以把这种 trait 纳入 *__str__* 和 *format_to*，只需对代码做最小调整：

Mojo

struct SafeBuffer[T: CollectionElement]:
   ...

   fn __str__[U: StringableFormattableCollectionElement](self: SafeBuffer[U]) -> String:
       ret = String()
       writer = ret._unsafe_to_formatter()
       self.format_to(writer)
       _ = writer^
       return ret^

   fn format_to[
       U: StringableFormattableCollectionElement
   ](self: SafeBuffer[U], inout writer: Formatter):
       debug_assert(self.size > 0, "size must be greater than zero")
       writer.write("[")
       for i in range(self.size - 1):
           if self._data[i]:
               writer.write(self._data[i].value(), ", ")
           else:
               writer.write("None", ", ")

       if self._data[self.size - 1]:
           writer.write(self._data[self.size - 1].value())
       else:
           writer.write("None")

       writer.write("]")

要测试条件符合如何在编译期捕获类型错误，我们定义一个既非 *Stringable* 也非 *Formattable*、但仍满足 *CollectionElement* 要求的哑类型：

Mojo

struct NotStringableNorFormattable(CollectionElement):
   fn __init__(inout self): ...
   fn __copyinit__(inout self, existing: Self): ...
   fn __moveinit__(inout self, owned existing: Self): ...

如果我们尝试在应用代码中使用它：

Mojo

def main():
    buf = SafeBuffer[NotStringableNorFormattable](10)
    buf.__str__()

我们会得到如下编译期错误，指出该类型不符合所需的 trait *StringableFormattableCollectionElement*：

Output

    buf.__str__()
    ~~~~~~~~~~~^~

note: failed to infer parameter 'U', argument type 'NotStringableNorFormattable' does not conform to trait 'StringableFormattableCollectionElement'
       buf.__str__()
       ^~~

note: function declared here

#### *mojo test*

Mojo 24.5 还带来了 [mojo test](https://docs.modular.com/mojo/cli/test) 选项，使用 Mojo 编译器运行单元测试。我们在 *test_generic_safe_buffer.mojo* 下添加如下测试用例：

   assert_equal(val, String("hi"))

        self._data = UnsafePointer[Optional[T]].alloc(size)
        for i in range(size):
            (self._data + i).init_pointee_copy(NoneType())

        self.size = size

    @staticmethod
    fn initialize_with_value(size: Int, value: T) -> Self as output:
        output = SafeBuffer[T](size)
        for i in range(size):
            output.write(i, value)

        return

    fn __copyinit__(inout self, existing: Self):
        self._data = existing._data
        self.size = existing.size

    fn __moveinit__(inout self, owned existing: Self):
        self._data = existing._data
        self.size = existing.size

    fn __del__(owned self):
        self._data.free()

    fn write(inout self, index: Int, value: Optional[T]):
        debug_assert(0 <= index < self.size, "index must be within the buffer")
        self._data[index] = value

    fn read(self, index: Int) -> Optional[T]:
        debug_assert(0 <= index < self.size, "index must be within the buffer")
        return self._data[index]

    fn __str__[U: StringableFormattableCollectionElement](self: SafeBuffer[U]) -> String:
        ret = String()
        writer = ret._unsafe_to_formatter()
        self.format_to(writer)
        _ = writer^
        return ret^

    fn format_to[
        U: StringableFormattableCollectionElement
    ](self: SafeBuffer[U], inout writer: Formatter):
        debug_assert(self.size > 0, "size must be greater than zero")
        writer.write("[")
        for i in range(self.size - 1):
            if self._data[i]:
                writer.write(self._data[i].value(), ", ")
            else:
                writer.write("None", ", ")

        if self._data[self.size - 1]:
            writer.write(self._data[self.size - 1].value())
        else:
            writer.write("None")

        writer.write("]")

    fn take(inout self, index: Int) -> Optional[T] as output:
        output = self.read(index)
        self.write(index, Optional[T](None))
        return


fn process_buffers[T: CollectionElement](buffer1: SafeBuffer[T], inout buffer2: SafeBuffer[T]):
    debug_assert(buffer1.size == buffer2.size, "buffer sizes much match")
    for i in range(buffer1.size):
        buffer2.write(i, buffer1.read(i))
