# Modular 26.4：SOTA MoE 服务、通过 Agent Skills 做模型 bring-up、Mojo 1.0 Beta 2 等

Modular 26.4 把业界领先的 mixture-of-experts（MoE）服务带到 Modular Cloud，扩展了 MAX 对最新开放权重模型的支持，并向 Mojo 1.0 再迈一步。

Modular Cloud 正在扩展，现已支持 [MiniMax M3](https://www.modular.com/blog/day-zero-minimax-m3-open-weights-on-modular-cloud)、[GLM 5.2](https://www.modular.com/models/glm-5-2) 和 [Kimi 2.7](https://www.modular.com/models/kimi-k2-6) 等最新前沿模型。Modular Cloud 构建在 26.4 版本之上——该版本新增对多种模型架构的支持、增强量化与投机解码能力、改进 OpenAI API 兼容性、扩展 Apple 芯片 GPU 支持，并通过 `modular/skills` 让智能体化的模型 bring-up 更易得。

## **在 Modular Cloud 上服务 SOTA MoE**

今天所有前沿模型都是基于 MoE 的。MoE 架构意味着，尽管模型很大（数千亿甚至上万亿参数），任意时刻只有一小部分参数被激活。这种稀疏激活进一步借助 KVCache block 的稀疏激活来扩展。庞大的规模加上稀疏性，让这些模型更难服务——因为它需要从上云到 kernel 的跨栈优化。在 Modular Cloud 中，我们精心调优了 Gemma 4、Deepseek、GLM、MiniMax 和 Kimi 等模块，以确保这些模型的峰值性能。

通过 Modular Cloud 可获取的新 MoE 模型包括：

- [MiniMax M3](https://www.modular.com/blog/day-zero-minimax-m3-open-weights-on-modular-cloud)
- [GLM 5.2](https://www.modular.com/models/glm-5-2)
- [Gemma 4](https://www.modular.com/blog/day-zero-launch-fastest-performance-for-gemma-4-on-nvidia-and-amd)
- 以及更多

Modular Cloud 为你提供 [500 多种模型架构](https://www.modular.com/models)的访问，覆盖从智能体编码、多轮对话到视觉与视频生成的不同用例。[今天就申请访问](https://console.modular.com/signup?utm_source=26.4releaseBlog) Modular Cloud。

## MAX：新模型、更多能力、更快的 bring-up

在上一个 [26.3](https://www.modular.com/blog/modular-26-3-mojo-1-0-beta-max-video-gen-and-more?utm_source=26.4releaseBlog) 版本中，我们引入了分布式感知张量和 Modular 原生智能体工具的初步组件。在 MAX 26.4 中，我们持续投入以扩展 MAX 框架的能力、改善开发体验。

MAX 是 Modular Cloud 能力的底座，而在 MAX 26.4 中，我们新增了模型覆盖与服务机制。包括：

- MAX 现在支持新的模型架构，如 `GlmMoeDsaForCausalLM`、`LFM2ForCausalLM` 和 `HYV3ForCausalLM`。
- `KimiK25ForConditionalGeneration` 扩展为同时支持 Kimi 2.6 和 2.7，并支持 Eagle3、DFlash 等不同的投机解码器。
- **改进 OpenAI API 兼容性：**MAX 26.4 新增对 `developer` 角色的支持，使推理输出与 Responses API 对齐，改进结构化输出的处理，并添加兼容性标志，使真实世界的请求更少因细微的请求差异而失败。
- **更广的量化覆盖：**Gemma4 和 FLUX.2-Klein 等模型现在可用 FP8 或 FP4 权重运行。
- **Apple 芯片 GPU：**MAX 现在在 M3 及更新的 Apple 芯片 GPU 上支持许多常见模型架构，包括 Qwen 3.6 和 Gemma 4。我们在 Mojo 和 MAX 上持续改进对 Apple 芯片的支持，请关注 nightly 以获取最新能力和最佳性能。
- **更清爽的 MAX API 与迁移说明：**26.4 把 [MAX 模块](https://docs.modular.com/max/api/python/)移入更清晰的归属，并移除了一些旧的传统类型。多数变更都带有弃用垫片（deprecation shim），迁移期间现有代码应能继续工作。

完整列表见 [MAX changelog](https://docs.modular.com/max/changelog/#v264-2026-06-18)。

### 用 `modular/skills` 做智能体化模型 bring-up

开发者常问我们如何把自己的模型带进 MAX 来享用这些能力。在 26.4 中，我们发布了 [import-model](https://github.com/modular/skills/tree/main/import-model) 和 [debug-model](https://github.com/modular/skills/blob/main/debug-model/SKILL.md) skills，让你能用 agent 把模型导入 MAX。可通过以下方式安装该 skill：

mojo

```
npx skills add modular/skills
```

这些 skills 引导 AI 编码 agent 走一遍可复现的模型 bring-up 工作流：

- **决策与规划**：检查 Hugging Face 的 config 和 modeling 代码。
- **实现模型**：以最接近的现有 MAX 架构为脚手架搭建。
- **验证其输出**：与参考实现逐层运行 logit 分歧排查，直到输出匹配。

结果是一条从 Hugging Face 模型 ID 到可部署的、可用的 MAX 架构的快速务实路径。为演示这一点，我们用这些 agent skills 把腾讯的 [Hunyuan Hy3-preview](https://huggingface.co/tencent/Hy3-preview) 模型带进了 MAX。该模型使用 192 个路由专家、sigmoid 加 correction-bias 路由，并在 MAX 上以多 GPU 张量并行注意力和专家并行 MoE 运行。

在我们的新 [指南](https://www.modular.com/p/2ff1044d37bb80759de3f913b30984d7)中阅读更多关于用智能体 skills 做模型 bring-up 的内容。

## Mojo 1.0 beta 2：在通往发布的路上趋于稳定

作为我们 [通往 Mojo 1.0 之路](https://www.modular.com/blog/the-path-to-mojo-1-0)的又一步，本版本包含 Mojo 1.0 beta 2。这次更新聚焦精修与稳定。你很快会在 nightlies 中看到 Mojo 标准库里标注哪些接口是稳定的，并且随着接近 1.0 发布，我们会不断扩大这一范围。

自 beta 1 以来还有若干语言改进：

- 许多常见集合类型如 `List[T]` 不再要求其内容必须是 `Copyable`。这让集合成为在更广元素类型上更通用的容器。
- 我们移除了 `enqueue_function` 中冗余的函数参数。这让加速器编程更简洁，因为 kernel 只需指定一次。
- 我们持续投入 Python -> Mojo 互操作，其中一部分是在许多常见用例中降低 Python 调用进入 Mojo 的开销。
- Mojo 的反射（reflections）现在更顺手，与标准库的整合也更紧密。
