# Mojo 24.6 上手实践

**Mojo 24.6** 到来了，它在参数约定与生命期管理上带来了重大变化。这个版本是 Mojo 演进中的重要一步：让内存与所有权模型更直观，同时保持强安全保证。这些变更现已可用，并随 [MAX 24.6 版本](https://www.modular.com/blog/introducing-max-24-6-a-gpu-native-generative-ai-platform)一起打包发布。

## 关键变更概览

本次版本的亮点之一是对若干核心概念的更名，以更好反映其用途：

- **`inout` → `mut` 用于可变参数：** 更能体现这些参数可以被修改。
- **“lifetime” → “origin” 用于引用追踪：** 更准确地描述“引用从哪里来”这一概念。

这些命名变更让 Mojo 代码更直观，同时保留了开发者期待的强安全保证。让我们通过实践示例逐一深入了解。

## 新的参数约定

Mojo 24.6 最显眼的变化是参数约定的更名。`inout` 关键字被 **`mut`** 取代。这一改动让代码意图更清晰——`mut` 明确表示参数可以被修改。

看一个实际例子：

#### 24.6 之前

Mojo

@value
struct Task:
    var description: String

    fn __init__(inout self, desc: String):
        self.description = desc

struct TaskManager:
    var tasks: List[Task]

    fn __init__(inout self):
        self.tasks = List[Task]()

    fn add_task(inout self, task: Task):
        self.tasks.append(task)
    
    fn show_tasks(self):
        for t in self.tasks:
            print("- ", t[].description)

#### 24.6 之后

Mojo

@value
struct Task:
    var description: String

    # Notice: `inout` -> `out`
    fn __init__(out self, desc: String):
        # 'out self' indicates we are constructing a fresh Task
        self.description = desc

struct TaskManager:
    var tasks: List[Task]

    fn __init__(out self):
        # Another 'out self' constructor,
        # sets up an empty list of tasks
        self.tasks = List[Task]()

    # Notice: `inout` -> `mut`
    fn add_task(mut self, task: Task):
        self.tasks.append(task)

    fn show_tasks(self):
        for t in self.tasks:
            print("- ", t[].description)

def main():
    # Create a new TaskManager
    manager = TaskManager()

    # Add tasks
    manager.add_task(Task("Walk the dog"))
    manager.add_task(Task("Write Mojo 24.6 blog post"))

    manager.show_tasks()

## 隐式转换

24.6 的另一项重要变化是隐式转换的处理方式。单参数构造函数现在需要 [`@implicit`](https://docs.modular.com/mojo/manual/decorators/implicit/) 装饰器才允许隐式转换。这让类型转换更明确、更安全——开发者必须显式选择启用隐式转换行为。

其工作方式如下：

Mojo

struct Task:
    var description: String

    @implicit  # Explicitly opt-in to implicit conversion
    fn __init__(out self, desc: String):
        self.description = desc

    @implicit  # Also allow conversion from string literals
    fn __init__(out self, desc: StringLiteral):
        self.description = desc

这一改动在保持类型安全的同时允许更便捷的用法：

Mojo

def main():
    manager = TaskManager()
    # These now work because we opted into implicit conversion
    # String → Task
    manager.add_task(String("Walk the dog"))
    # StringLiteral → Task
    manager.add_task("Write Mojo 24.6 blog post")

如果没有 `@implicit` 装饰器，你就必须显式创建 `Task` 对象：

Mojo

# Explicit conversion required
manager.add_task(Task("Walk the dog"))

这种新方法把隐式转换从“自动”变为“选择启用”，在便利与类型安全之间取得平衡。

Bash

magic run example2

## `Origins`：更直观的引用模型

Mojo 24.6 最重要的变化之一是把 **“lifetimes”更名为“origins”**，并大幅充实了引用模型。这一变化更准确地反映了这些注解实际所做的事——追踪引用从何而来，而非其完整生命周期。别忘了查阅 [Mojo 手册](https://docs.modular.com/mojo/manual/values/lifetimes)。

通过几个实践示例来探索这一概念：

Mojo

struct TaskManager:
    var tasks: List[Task]

    fn get_task(ref self, index: Int) -> ref [self.tasks] Task:
        # The [self.tasks] annotation shows
        # this reference originates from the tasks list
        return self.tasks[index]

def main():
    manager = TaskManager()
    manager.add_task("Initial task")

    # Get a reference to the first task
    first_task = manager.get_task(0)
    first_task.description = "Modified task"  # Safe modification

origin 注解 `[self.tasks]` 清楚表明返回的引用来自 tasks 列表。这让代码中的引用关系更易理解和追踪。

Bash

magic run example3

### 使用多个 origins

当涉及多个引用时，origins 显得尤为强大：

Mojo

fn pick_longer(ref t1: Task, ref t2: Task) -> ref [t1, t2] Task:
    # The [t1, t2] annotation shows this reference
    # could come from either t1 or t2
    return t1 if len(t1.description) >= len(t2.description) else t2

def main():
    manager = TaskManager()
    manager.add_task("Short task")
    manager.add_task("This is a longer task")
    
    # copies so a new origin is detected
    first_task = manager.get_task(0)
    first_task.description = "Walk the dog ASAP and then write the blog post!"

    # Compare tasks by length
    longer = pick_longer(first_task, manager.get_task(1))
    print("Longer task: ", longer.description)

这个函数演示了 `ref [t1, t2]` 如何允许返回的引用源自 `t1` 或 `t2`，实现更灵活、更具表达力的引用管理。

运行示例：

Bash

magic run example4

**注意：** Mojo 24.6 **在编译期**强制执行严格的参数排他性。例如下面的调用：

Mojo

pick_longer(manager.get_task(0), manager.get_task(1))

会产生编译器错误：

Output

# error: argument of 'pick_longer' call allows writing
# a memory location previously writable through another aliased argument

该错误的发生是因为函数试图修改一个已经可通过另一引用写入的内存位置，从而确保内存安全、防止潜在的数据竞争。

## 用 `out` 实现具名结果

Mojo 24.6 通过直接使用 `out` 约定，为具名结果引入了更简洁的语法。它取代了之前的 `Type as out` 语法，与语言中其他地方 `out` 的用法保持一致。

看一个演示新语法的例子：

Mojo

struct TaskManager:
    var tasks: List[Task]

    fn __init__(out self):
        self.tasks = List[Task]()

    # Named result using the new 'out' convention
    @staticmethod
    fn bootstrap_example(out manager: TaskManager):
        manager = TaskManager()
        manager.add_task("Default Task #0")
        manager.add_task("Default Task #1")
        return  # 'manager' is implicitly returned

def main():
    # Create a TaskManager with default tasks
    mgr = TaskManager.bootstrap_example()
    mgr.show_tasks()

`bootstrap_example` 方法演示了具名结果的工作方式：

- 我们用 `out manager: TaskManager` 声明结果参数。
- 在函数内初始化并填充 manager。
- `return` 语句隐式返回具名结果。

## 新的集合类型

Mojo 24.6 为标准库带来两个重要新增：**`Deque`** 和 **`OwnedPointer`**。逐一了解：

### Deque：双端队列

新的 `Deque` 集合类型在序列两端都提供**高效的 O(1)** 操作。当需要从集合任一端添加或删除元素时——例如实现带优先级的工作队列——它特别有用。

Mojo

from collections import Deque

struct TaskManager:
    # Using Deque instead of List
    var tasks: Deque[Task]

    fn __init__(out self):
        self.tasks = Deque[Task]()

    fn add_task(mut self, task: Task):
        # Add to back (normal priority)
        self.tasks.append(task)

    fn add_urgent_task(mut self, task: Task):
        # Add to front (high priority)
        self.tasks.appendleft(task)

### OwnedPointer：安全的内存管理

`OwnedPointer` 类型提供**安全的**、单一所有权、非空的智能指针功能。当处理需要确定性清理的资源——如文件句柄或网络连接——时特别有用。

**`OwnedPointer` 的关键特性：**

- **单一所有权语义**
- **自动清理**：离开作用域时
- **移动语义**：使用 `^` 运算符
- **非空**（始终指向有效数据）

一个展示概念的基础例子：

Mojo

from memory import OwnedPointer

@value
struct HeavyResource:
    var data: String

    fn __init__(out self, data: String):
        self.data = data

    fn do_work(self):
        print("Processing:", self.data)

struct Task:
    var description: String
    var heavy_resource: OwnedPointer[HeavyResource]

    # We keep the @implicit for description
    @implicit
    fn __init__(out self, desc: StringLiteral):
        self.description = desc
        self.heavy_resource = OwnedPointer[HeavyResource](HeavyResource("Heavy resource with description: " + desc))

    fn __moveinit__(out self, owned other: Task):
        self.description = other.description^
        self.resource = other.resource^

## 把一切串起来

我们来看一个**完整示例**，融合所有新特性——参数约定、origins 和集合类型。这个例子展示 Mojo 24.6 的各项改进如何协同工作，产出更干净、更安全、更高效的代码：

Mojo

from collections import Deque
from memory import OwnedPointer
from os import abort


@value
struct HeavyResource:
    var data: String

    fn __init__(out self, data: String):
        self.data = data

    fn do_work(self):
        print("Heavy work:", self.data)

struct Task:
    var description: String
    var heavy_resource: OwnedPointer[HeavyResource]

    # We keep the @implicit for description
    @implicit
    fn __init__(out self, desc: StringLiteral):
        self.description = desc
        self.heavy_resource = OwnedPointer[HeavyResource](HeavyResource("Heavy resource with description: " + desc))

    fn __moveinit__(out self, owned other: Task):
        self.description = other.description^
        self.heavy_resource = other.heavy_resource^

    # Workaround `CollectionElement` requirement for `Deque`
    fn __copyinit__(out self, other: Task):
        abort("__copyinit__ should never be called")
        while True:
            pass

    fn do_work(self):
        self.heavy_resource[].do_work()


struct TaskManager:
    var tasks: Deque[Task]

    fn __init__(out self):
        self.tasks = Deque[Task]()

    # Need to use `owned` to avoid Copy
    fn add_task(mut self, owned task: Task):
        self.tasks.append(task^)

    fn add_urgent_task(mut self, owned task: Task):
        # or to the front
        self.tasks.appendleft(task)

    fn show_tasks(self):
        for t in self.tasks:
            print("- ", t[].description)

    @staticmethod
    fn bootstrap_example(out manager: TaskManager):
        manager = TaskManager()
        manager.add_task("Deque-based Task #1")
        manager.add_urgent_task("Deque-based Task #0")
        return

    fn do_work(owned self):
        for t in self.tasks:
            t[].do_work()

def main():
    mgr = TaskManager.bootstrap_example()
    print("Tasks:")
    mgr.show_tasks()
    print("Do work:")
    mgr^.do_work()
    # When 'mgr' goes out of scope, OwnedPointer cleans up all HeavyResources
    # so no need for explicit cleanup

这个例子展示了：

- **新的 `out`、`mut`、`read` 参数约定：** 清楚表明每个方法如何与 struct 状态交互。
- **`@implicit` 单参数构造转换：** 用字符串字面量方便地添加任务，无需显式构造 `Task`。
- **带 `ref [a, b]` 的 origins：** 管理可源自多个来源的引用，增强灵活性。
- **`Deque` 集合类型：** 双端高效管理任务。
- **`OwnedPointer` 安全管理资源：** 确保重量级资源无需手动清理即可妥善管理。
- **用 `out` 实现具名结果：** 简化函数返回约定，提升可读性与一致性。

## 使用 Mojo LLDB 调试器与 VS Code 增强功能进行调试

Mojo 24.6 还为**工具生态**带来显著改进，以更好的调试能力和编辑器集成提升开发者体验。在这方面，

`mojo debug --rpc` 改为 `mojo debug --vscode`。请务必查看 [24.6 版 changelog 的工具部分](https://docs.modular.com/mojo/changelog#24-6-tooling-changes)。

- **符号断点：** 现在可以在代码中的特定符号上设置断点。例如：

Bash

- **改进的错误信息：** 错误信息现在更清晰简洁，去掉了不必要的类型展开，聚焦核心问题。

VS Code 扩展增强

- **数据断点：** 在执行期间监视特定变量或 struct 字段的变化。
- **函数断点：** 当特定函数被调用时中断执行。
- **运行与调试面板自动化：** 调试会话开始时扩展会自动打开“运行和调试”面板。
- **增强的 LSP 与文档显示：** origins 和参数化类型在语言服务协议及生成的 API 文档中展示得更清楚。

## 总结

**Mojo 24.6** 显著提升了语言易用性，同时保留其强安全保证。新的参数约定（`mut`、`out`）澄清了代码意图，**“lifetimes”更名为“origins”**更好地传达其用途。**`Deque`** 和 **`OwnedPointer`** 的引入拓宽了标准库能力，**选择启用的隐式转换**规则强化了工作流中的类型安全。

这些更新让 Mojo 更**直观**、更**高效**，同时坚守语言对性能与安全的承诺。无论你是 Mojo 新手还是资深开发者，这些改进都带来更精致、更强大的编程体验。

要尝试这些新特性，请更新到 Mojo 24.6 并查看 [完整 changelog](https://docs.modular.com/mojo/changelog#v246-2024-12-17)。
