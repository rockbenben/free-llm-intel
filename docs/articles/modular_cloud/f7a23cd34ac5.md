# “CUDA”到底是什么？（AI 算力民主化，第 2 篇）

过去一年，似乎**所有人**都开始谈论 [CUDA](https://en.wikipedia.org/wiki/CUDA)：它是**深度学习的脊梁**，是**新型硬件难以竞争**的原因，也是 **NVIDIA 护城河**与**飙升市值**的核心。DeepSeek 给了我们一个惊人的启示：它的**突破之所以可能，是因为“绕过”了 CUDA**，[直通 PTX 层](https://www.tomshardware.com/tech-industry/artificial-intelligence/deepseeks-ai-breakthrough-bypasses-industry-standard-cuda-uses-assembly-like-ptx-programming-instead)…但这到底意味着什么？人人似乎都想冲破锁定，但在制定作战计划之前，我们必须**理解对手到底是什么**。

CUDA 在 AI 中的统治地位不容否认——但**大多数人不真正理解 CUDA 是什么**。有人以为它是编程语言，有人称它为框架，许多人笼统地认为它就是“**NVIDIA 用来让 GPU 变快的那个东西**”。这些说法都不算全错——许多[聪明人正试图解释清楚](https://x.com/IanCutress/status/1884374138787357068)——但没有一个抓住了**“CUDA 平台”的全貌**。

CUDA 不只是单一事物。它是一个**庞大的、分层的技术栈**——由技术、软件库和底层优化共同组成的**巨大并行计算生态**。它包括：

- **一个底层并行编程模型**，让开发者用类 C++ 的语法驾驭 GPU 的原始算力。
- **一套复杂的库与框架**——支撑 AI 等关键垂直用例的中间件（例如服务于 PyTorch 和 TensorFlow 的 cuDNN）。
- **一组高层解决方案**，如 TensorRT-LLM 和 Triton，无需深厚 CUDA 功底也能运行 AI 工作负载（如 LLM 服务）。

……而这只是冰山一角。

本文将拆解 **CUDA 平台的关键层**，梳理它的**历史演进**，并解释**为什么它对当今 AI 计算如此不可或缺**。这也为系列的下一篇铺垫——我们将深入**CUDA 为何如此成功**。提示：它更多关乎市场激励，而非技术本身。

让我们开始。🚀

## CUDA 之路：从图形到通用计算

在 GPU 成为 AI 与科学计算的重镇之前，它们是**图形处理器——专为渲染图像而生的处理器**。早期 GPU 把图像渲染**硬连线**进硅片，意味着渲染的每一步（变换、光照、光栅化）都是固定的。对图形而言很高效，但这些芯片**不灵活**——无法改作其他类型的计算。

一切在 **2001 年**改变：NVIDIA 发布了 **GeForce3**，第一颗带**可编程着色器**的 GPU。这是计算领域的一次**剧变**：

- 🎨 **之前**：固定功能 GPU 只能应用预定义效果。
- 🖥️ **之后**：开发者可以**编写自己的着色器程序**，解锁**可编程图形流水线**。

这一进步随 **Shader Model 1.0** 而来，让开发者能编写在 GPU 上执行的**小型程序**处理顶点与像素。NVIDIA 看清了**未来的方向**：GPU 不只是提升图形性能，还能成为**可编程的并行计算引擎**。

与此同时，研究人员很快就提出了问题：

> “🤔 如果 GPU 能跑图形小程序，我们能不能用它做非图形的任务？”

最早的认真尝试之一，是斯坦福的 [**BrookGPU 项目**](http://graphics.stanford.edu/projects/brookgpu/)。Brook 提出了一种让 **CPU 把计算任务卸载到 GPU** 的编程模型——这个关键想法[为 CUDA 铺平了道路](https://www.nvidia.com/content/GTC/documents/1001_GTC09.pdf)。

这一步**既有战略意义又是脱胎换骨的**。NVIDIA 没有把通用计算当作**副业实验**，而是**把它提到一等优先级的位置**，将 CUDA 深植于**硬件、软件与开发者生态**之中。

## CUDA 并行编程模型

**2006 年**，NVIDIA 发布 **CUDA（“Compute Unified Device Architecture”）**——第一个面向 GPU 的**通用编程平台**。CUDA 编程模型由两部分组成：“CUDA 编程语言”和“NVIDIA 驱动”。

CUDA 是一个从驱动到 kernel 需要深度整合的分层技术栈

CUDA 语言源自 C++，并做了增强以直接暴露 GPU 的底层特性——例如它的“GPU 线程”与内存概念。程序员可以用这门语言定义一个“CUDA Kernel”——在 GPU 上运行的独立计算。一个非常简单的例子：

注意，这一切都非常底层——充满琐碎细节（指针、“魔法数字”）。一旦出错，等待你的通常是难以理解的崩溃。此外，CUDA 暴露了大量 NVIDIA 硬件专属的细节——比如“一个 warp 里的线程数”（这里不展开）。

尽管有这些困难，这些组件让一整代硬核程序员得以使用 GPU 在数值问题上展现的巨大肌肉。例如，[**AlexNET**](https://en.wikipedia.org/wiki/AlexNet) 在 2012 年点燃了现代深度学习。它之所以可能，靠的是为卷积、激活、池化、归一化等 AI 操作编写的自定义 CUDA kernel，以及 GPU 能提供的马力。

虽然 CUDA 语言和驱动是人们听到“CUDA”时**通常想到的东西**，但这远非全部——它只是**馅儿**。随着时间推移，**CUDA 平台**扩展到更多内容，原有缩写作为描述 CUDA 的方式也失去了实用意义。

## 高层 CUDA 库：让 GPU 编程更亲民

CUDA 编程模型打开了**通用 GPU 计算**的大门且威力强大，但它带来两个挑战：

- CUDA **难用**，而且更糟的是……
- CUDA 帮不了**性能可移植性**

为第 N 代写的 kernel 大多能在第 N+1 代上“继续工作”，但性能往往很差——离 N+1 代能达到的峰值很远，尽管 GPU 的全部意义就在性能。这让 CUDA 成为**专家工程师的利器**，但对多数开发者是**陡峭的学习曲线**。这也意味着每当新一代 GPU（比如正在崛起的 Blackwell）问世，都需要大规模重写。

随着 NVIDIA 成长，它希望 GPU 能服务于那些在各自问题域是专家、但并非 GPU 专家的人。NVIDIA 的解法是开始构建丰富而复杂的**闭源高层库**，把底层 CUDA 细节抽象掉。这些库包括：

- **cuDNN**（2014）– 加速深度学习（如卷积、激活函数）。
- **cuBLAS** – 优化的线性代数例程。
- **cuFFT** – GPU 上的快速傅里叶变换（FFT）。
- ……以及[许多其他库](https://developer.nvidia.com/gpu-accelerated-libraries)。

有了这些库，开发者**不必编写自定义 GPU 代码也能用上 CUDA 的威力**，而 NVIDIA 承担起**为每一代硬件重写它们**的重担。这是 NVIDIA 的一大投入，**但它奏效了**。

**cuDNN 库**在这个故事里尤为重要——它为 Google 的 **TensorFlow**（2015）和 Meta 的 **PyTorch**（2016）铺了路，使深度学习框架得以起飞。此前也有 AI 框架，但真正能规模化的框架是从它们开始的——现代 AI 框架如今拥有***数千个***这类 CUDA kernel，每一个都极难编写。随着 AI 研究爆炸式发展，NVIDIA 大力扩张这些库以覆盖重要的新用例。

CUDA 上的 PyTorch 建立在多层依赖之上

NVIDIA 对这些**强大 GPU 库**的投入，让全世界得以专注于构建 PyTorch 这样的高层 AI 框架和 HuggingFace 这样的开发者生态。它的下一步是打造可以**开箱即用**的完整**解决方案**——完全不需要理解 CUDA 编程模型。

## 全垂直解决方案，纾解 AI 与 GenAI 的快速增长

AI 热潮远超研究实验室——**AI 如今无处不在**。从**图像生成**到**聊天机器人**，从**科学发现**到**代码助手**，**生成式 AI（GenAI）在全行业爆发**，为这个领域带来洪流般的新应用和新开发者。

与此同时，**新一代 AI 开发者出现了，需求截然不同**。早期，深度学习需要**高度专精的工程师**，懂 CUDA、HPC 和底层 GPU 编程。如今，一类新的开发者——常被称为 **AI 工程师**——在不触碰底层 GPU 代码的情况下构建和部署 AI 模型。

为满足这一需求，NVIDIA 超越了仅提供库的层面，开始交付把底层**一切**都抽象掉的**交钥匙方案**。这些框架让 AI 开发者无需**深厚的 CUDA 功底**，也能以最小的努力**优化和部署模型**。

- **Triton Serving** – 面向 AI 模型的高性能服务系统，让团队跨多 GPU 与 CPU 高效运行推理。
- **TensorRT** – 深度学习推理优化器，**自动调校模型**以在 NVIDIA 硬件上高效运行。
- **TensorRT-LLM** – 更专门的方案，为**大规模语言模型（LLM）推理而生**。
- ……外加很多（真的很多）其他东西。

NVIDIA 驱动与 TensorRT-LLM 之间存在多层

这些工具**让 AI 工程师与 CUDA 的底层复杂性完全隔绝**，让他们**专注 AI 模型与应用，而非硬件细节**。这些系统提供了巨大杠杆，支撑了 AI 应用横向上的规模化。

## 整体观之的“CUDA 平台”

CUDA 常被认为是一个**编程模型**、一套**库**，甚至只是“**NVIDIA GPU 跑 AI 的那个东西**”。但实际上，**CUDA 远不止于此**——它是一个**统一品牌、一个真正庞大的软件集合、一个高度调校过的生态**，全部与 NVIDIA 硬件深度整合。正因如此，“CUDA”一词是含糊的——我们更愿意用“CUDA 平台”这个说法，以澄清我们谈论的对象在精神上更接近 Java 生态、甚至一个操作系统，而非仅仅一门编程语言加运行时库。

CUDA 不断膨胀的复杂性：一个横跨驱动、语言、库与框架的多层生态

CUDA 平台的核心构成：

- **庞大的代码库** – 数十年积累的优化 GPU 软件，从矩阵运算到 AI 推理无所不包。
- **广阔的工具体系与库生态** – 从**用于深度学习的 cuDNN** 到**用于推理的 TensorRT**，CUDA 覆盖**极其多样的工作负载**。
- **硬件调校的性能** – 每次 CUDA 发布都针对 **NVIDIA 最新 GPU 架构**深度优化，确保顶级效率。
- **专有且不透明** – 当开发者调用 CUDA 的**库 API**时，底层发生的事情大多是**闭源的、与 NVIDIA 生态深度绑定的**。

CUDA 是一套强大但庞杂的技术——**一整个坐在现代 GPU 计算地基上的软件平台**，甚至超出了 AI 的范畴。

现在我们知道“CUDA”是什么了，接下来要理解它为何如此成功。提示：CUDA 的成功其实不在于**性能**——而在于**战略、生态与势能**。下一篇我们将探讨是什么让 NVIDIA 的 CUDA 软件塑造并固化了现代 AI 时代。
