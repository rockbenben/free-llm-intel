# stack-pr 发布：一个管理 GitHub 堆叠式 PR 的开源工具

我们很高兴发布一款旨在简化管理 GitHub 堆叠式 pull request（PR）的新工具——[*stack-pr*](https://github.com/modularml/stack-pr)。这个工具还处于早期开发阶段，但我们很兴奋能把它分享给社区，并欢迎你的贡献。

### 什么是堆叠式 PR？

堆叠式 PR 是一种组织 pull request 的方式：一个 PR 按顺序依赖于另一个 PR。你不必提交一个庞大的 PR，而是可以把改动拆分成更小、更易管理、彼此层层递进的 PR。随着堆栈中的每个 PR 被评审并合并，其余 PR 会自动更新，确保集成过程顺畅。

### 使用堆叠式 PR 有什么好处？

堆叠式 PR 为管理代码库中多个相互依赖的改动提供了结构化的方式。把大型改动拆分成更小、更聚焦的 PR，开发者可以获得：

- **更好的代码评审**：每个 PR 都可以独立评审，更容易发现问题、理解改动。
- **并行工作**：你可以在某个前置改动完成评审和合并之前，就先着手下一个改动。
- **更干净的历史**：提交历史保持更有条理，真实反映改动的逻辑演进。

### *stack-pr* 是什么？怎么使用？

*stack-pr* 是一个 CLI 工具，让你在终端里从容地管理堆叠式 PR。它的接口很简单，支持创建、更新和合并堆叠式 PR。

*stack-pr* 提供了一个管理 PR 堆栈的简单心智模型：本地 git 分支中的每个 commit 都会变成一个独立的 PR，依赖于上一个 commit 对应的 PR。当你想更新堆栈时——无论是给已有 PR 加入改动、重新排序、丢弃某些 PR，还是新增 PR——只需在本地 git 分支中做相应修改（通常会用 *git rebase -i*），然后运行一条命令 *stack-pr export*，GitHub 上的 PR 就会相应更新。准备好合并时，可以使用 *stack-pr land* 命令，它会先合入最底层的 PR，再 rebase 堆栈中其余的部分。

更详细的使用手册见 [`README.md`](https://github.com/modularml/stack-pr/blob/main/README.md)。

### 致敬同类工具

*stack-pr* 并不是这个领域的第一款工具，我们想向其他现有工具致敬——特别是给了 *stack-pr* 很多启发的 [*ghstack*](https://github.com/ezyang/ghstack)。*ghstack* 同样是一款处理 PR 堆栈的优秀工具，但它有一些限制，而我们在 *stack-pr* 中绕开了这些限制。例如，*ghstack* 要求你允许对仓库强制推送，而且构建堆栈时生成的分支数量是我们的工具的 3 倍。尽管如此，我们也非常推荐你试一试它！

### 我们为什么开源 *stack-pr*？

我们公司相信回馈社区。开源这个工具，我们希望对生态做出贡献，促进协作与改进。我们邀请开发者、团队和开源爱好者试用我们的工具、提供反馈并参与其开发。*stack-pr* 还很年轻，有很多可以改进的地方；你现在就可以直接使用它，同时我们也欢迎为它贡献代码，让它对所有人都更好用！
