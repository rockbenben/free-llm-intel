# 通往 Mojo 1.0 之路

大约三年前的此刻，Mojo 语言从还只是一个念头的状态踏上了旅程。自[那时](https://docs.modular.com/mojo/changelog)[以来](https://docs.modular.com/mojo/changelog)，Mojo 确实长大了许多：推动[当今最新加速器](https://www.modular.com/blog/achieving-state-of-the-art-performance-on-amd-mi355----in-just-14-days)的性能边界、驱动 MAX（而 MAX 又支撑着[世界领先的 AI 模型](https://www.modular.com/blog/tts-1-max-ranked-1-speech-model-on-artificial-analysis)），并被无数开发者采用，应用于从[音频处理](https://github.com/spluta/MMMAudio)到[生物信息学](https://academic.oup.com/bioinformaticsadvances/article/5/1/vbaf292/8325233)的广泛场景。今天，我们很高兴谈谈 Mojo 旅程中的下一步大事：**Mojo 1.0！**

## 我们对 Mojo 1.0 的愿景

我们不久前发布了 [Mojo 作为一门语言的愿景](https://docs.modular.com/mojo/vision)，以及 Modular 最初为何打造它。引用那份文档中的一段话：

> 我们对 Mojo 的愿景，是成为开发者所需的那一门编程语言——用它面向多样硬件（CPU、GPU 及其他加速器），以 Python 直观语法结合现代系统编程能力进行开发。

同时，我们给出了 [Mojo 的开发路线图](https://docs.modular.com/mojo/roadmap)，把语言的发展分为若干概念阶段。[Phase 1](https://docs.modular.com/mojo/roadmap#phase-1-high-performance-cpu--gpu-coding) 聚焦 Mojo 最初的杀手级应用：用一门强大、富有表达力的语言为 GPU 和 CPU 编写高性能 kernel。越来越多人在我们的 [Mojo GPU puzzles](https://puzzles.modular.com/) 上第一次学习 GPU 编程，正是 Mojo 在这一领域价值的证明之一。Mojo 让 Modular 得以[快速榨取市面上最新加速器的极限性能](https://www.modular.com/blog/achieving-state-of-the-art-performance-on-amd-mi355----in-just-14-days)，并为[Modular 的所有 AI 工作负载](https://www.modular.com/customers)提供动力。

虽然我们期望 Mojo 随着时间充分实现整条路线图的潜力，我们也希望为 Mojo 开发体验带来一段稳定的纪元，因此就有了 1.0 版本。也就是说，**当我们完成路线图中为 Phase 1 列出的目标时，Mojo 就会迎来 1.0**，为寻求高性能 CPU 与 GPU 编程语言的开发者提供稳定性。

本阶段还需完成的功能与质量工作已在全力推进，我们有信心 Mojo 将在 2026 年的某个时刻达到 1.0。这也将让我们能[如约](https://docs.modular.com/mojo/faq/#will-mojo-be-open-sourced)**开源 Mojo 编译器**。

虽然我们对这个里程碑感到兴奋，但这当然不会是 Mojo 开发的终点！一些常被要求的、面向更通用系统编程的能力不会在 1.0 完成，比如健壮的异步编程模型和私有成员的支持。更多信息请看下文！

## 为什么是现在要 1.0？

Mojo 的 1.0 版本此刻推出有多个理由：首先，我们希望确立 Mojo 生态内的稳定纪元。一个充满活力的成长型社区已经围绕 Mojo 形成，越来越多人想用它构建更大的项目。到目前为止，Mojo 及其库的快速变化一直是个挑战。

我们希望通过让开发者确信"今天写的东西明天不会坏"，使维护 Mojo 项目容易得多。语义化版本控制、稳定与不稳定接口的标记，以及对语言变更的整体刻意规划，将为基于 Mojo 1.x 开发的开发者提供更坚实的基础。

使用已稳定 API 的 Mojo 包，应当在整个 1.x 系列中保持可构建，即便我们继续添加不进入 1.0 的新特性。这让不断增多的社区 Mojo 库可以互相操作，解锁日益复杂的 Mojo 项目。

我们很高兴有更多 Mojicians 来到这个平台。宣布语言 1.0，是向外界发出信号：来试试 Mojo，或者回来看看自上次尝鲜以来它已成长为何模样。正因如此，为新老开发者提供出色的文档与工具链体验对我们非常重要。

对 Mojo 1.0 的规划对 Modular 团队也极具价值，因为它是一个聚焦与优先级的强制机制。开发一门语言时可做的事情太多，识别出我们在 1.0 之前**不会**去做什么反而很有帮助。这让我们把精力投向把 Mojo 今天擅长的部分做成更扎实的体验，先打磨好初始的一组特性，再添加更多。

关于 Mojo 标准库，我们计划给每个新语言特性留出足够的时间在库中走一遍。这让我们在把特性称为"完成"之前发现 bug 或改进点。我们也预期 1.0 会有相对较少的库特性被"稳定化"，并随时间渐进地扩大这个范围。

## 1.0 之后是什么？

Mojo 1.0 将是一个值得庆祝的里程碑，但它只是一段更长旅程中的一步。有许多特性赶不上 1.0 首发，其中一些我们计划在 1.x 版本中渐进推出。这些特性大多（例如 "match" 语句和 enum）向后兼容、不会破坏现有代码，所以我们可以把它们加进 1.x。

话虽如此，我们知道 Mojo 1.0 不会完美！Mojo 语言路线图 Phase 2 里有一些重要语言特性会引入对语言和标准库的破坏性变更。例如，把字段标记为 "private" 的能力，对提供内存安全至关重要。

在 Mojo 1.x 的开发期间，我们会公布一次源码破坏性的 Mojo 2.0 的计划，并在一个 "experimental" 标志下构建对它的支持，允许选择启用这一语言模式。这意味着 Mojo 编译器会同时支持 1.x 和 2.0 的包，我们目标是让它们链接兼容——就像 C++'20 与 C++'98 源码不兼容，但开发者可以构建混合生态一样。之后当 2.0 收敛发布时，我们会促成逐包从 1.x 向 2.x 的迁移。

眼下我们全神贯注于把 1.0 交付出去，但我们非常确信能够平稳地走完这次未来的过渡。Mojo 从 Python 学到了很多好的东西，也从那些做得不那么好的地方学到了经验：我们会尽力避免一场像 Python 2 到 3 那样的过渡！

## 加入社区，一起跟进！

我们迈向 Mojo 1.0 的工作将公开进行，我们欢迎反馈和 pull request 帮助这门语言更进一步。有一些很好的参与方式：

- 在我们开源的 [`modular`](https://github.com/modular/modular) 仓库里，以 nightly 方式体验陆续推出的新语言与库特性。
- 在 [Modular 论坛](https://forum.modular.com/)对语言和接口设计展开深入讨论。
- 访问[我们的新社区页面](https://www.modular.com/community)获取更多资源。

在未来一年，Mojo 1.0 将是这门语言的一大步！
