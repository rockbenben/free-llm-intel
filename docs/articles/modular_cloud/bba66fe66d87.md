# 问题

[Hippocratic AI](https://hippocraticai.com/) 打造以安全为核心的 AI 健康 agent，与患者对话，帮助弥合全球 1500 万医疗工作者的缺口。其 Polaris 系统并行编排数十个专用模型，确保每一次交互在临床上都是安全的，错误率低于人类临床医生。Hippocratic AI 的系统可扩展到每天联系数万名患者，并建立起人们对 AI 产品可用于高度监管行业的信任。

在实时语音中每一毫秒都很重要，而在 Hippocratic AI 的规模下，延迟上的收益会直接复利式转化为更好的患者体验和单机效率。其生产部署横跨多个框架，包括 SGLang 和 vLLM，并持续评估新兴框架以获取额外的延迟余量，硬件路线图覆盖 NVIDIA、AMD 及未来一代加速器。

# 解决方案

我们与 Hippocratic AI 的合作是一项联合工程：两个团队协同把 Modular 的 [MAX 框架](https://www.modular.com/open-source/max)集成进 Hippocratic AI 使用 NVIDIA B300 GPU 的推理流水线。评估基准将 MAX 与现有 SGLang 部署在 400B+ 参数模型上对比，特别关注尾延迟以及底层架构向异构硬件的未来可移植性。

Modular 已从头重建 AI 基础设施栈：从用 Mojo 编写的高度优化的可移植 kernel，到以 MAX 为核心的模型服务基础设施，再到可部署在 Modular 云或你自己云上的编排系统。这种多年深厚基础设施投入形成的垂直整合方式，让 Modular 在从现有框架中榨取性能方面拥有独特优势。

MAX 在每个关键维度都交出了答卷：

- **让每一次对话都即时。** MAX 平均首 token 时间（TTFT）低于 500ms，即便在高并发下也把总生成时间控制得很紧，支持响应灵敏、自然的交互。
- **消除破坏信任的延迟尖峰。** 在医疗领域，最坏情况的交互与平均情况同样重要。评估中，对一个关键的稠密生产模型，MAX 实现了约快 30% 的 P99 端到端延迟，解决了会在对话中途造成明显停顿的尾延迟尖峰。
- **单节点服务更多患者。** 针对特定工作负载，MAX 在规模下实现了平均端到端延迟约快 22%，为 Hippocratic AI 生产栈的单机效率目标做出贡献。

# 成果

通过把 MAX 加入推理栈，Hippocratic AI 打开了一条跨厂商硬件的异构部署策略。Hippocratic AI 与 Modular 的协作仍在持续。由于 MAX 的可移植性来自其优化的 kernel 库与调度架构而非厂商专用胶水代码，同样的收益延伸到正在成为生产 AI 部署核心的大型推理模型：为生产中使用的前沿 LLM 提供灵活、硬件无关的部署。

| 指标 | 结果 |
| --- | --- |
| 首 token 时间（TTFT） | 平均低于 500ms |
| 端到端延迟 - P99 | 快 30% |
| 端到端延迟 - 平均 | 快约 22% |
