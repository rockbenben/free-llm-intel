# 与客户共同开发企业级前沿防护

2026 年 9 月 1 日

今天我们宣布企业级前沿防护（Enterprise Frontier Safeguards，EFS）——一个把零数据保留（ZDR）的隐私性与检测滥用的最先进防护结合起来的方案。EFS 的运作方式是把数据存储在由客户而非 Anthropic 控制的云基础设施里。EFS 将分阶段向客户推出，今年晚些时候开始。为了让过渡平滑，在 EFS 就绪之前，符合条件的客户将在 Fable 5 和 Fable 5.1 上获得 ZDR。

我们与金融服务、医疗、制造、电信、法律、零售和公共部门等行业超过 100 家客户、以及我们在亚马逊云科技、Google Cloud 和 Microsoft Azure 的云伙伴密切合作，开发了 EFS。

EFS 将在 Claude Code、Claude Enterprise、Claude Platform、Amazon Bedrock、AWS 上的 Claude Platform、Google 的 Agent Platform 和 Microsoft Foundry 上得到支持。

## 解决前沿安全的两难

Mythos 级的模型，如 [Claude Fable 5.1](https://www.anthropic.com/claude-fable-and-mythos-5-1)，代表了智能和 agentic 能力的一次重大跃升。然而，随着这种提升而来的，既有滥用的可能，也有自主失当行为的可能。

过去几个月，我们看到了试图滥用 AI 模型的大量证据。这些从欺诈这类典型滥用，到复杂的网络攻击——后者可能包含 agent 自主地从事破坏性行为。其中一些案例涉及对企业客户凭证的窃取或盗用，而若没有监控流量、检测异常行为的能力，这些很难被发现。

此外，因为[最老练的滥用](https://www.anthropic.com/news/disrupting-AI-espionage)可能涉及分散在多个会话和账户上的许多任务，仅对每次交互单独跑自动化分析、然后即刻丢弃数据是不够的。有效的检测需要把数据存储一段有意义的时间，以便能跨时间和账户做关联。

出于这个原因，我们从 Fable 5 起引入了 30 天数据保留。这一政策的动机并非想要用企业数据做训练：Anthropic 从未在未经明确许可的情况下用企业数据训练，也永远不会。

与我们合作的企业普遍理解数据保留在安全和安保上的价值，但许多——尤其是受监管行业里的——发现很难使用带数据保留的模型。于是我们与客户坐下来，设计一个能兼得两全其美的方案：既有 ZDR 的隐私性，又有跨时间和账户监控所能带来的安全性。

## 与客户共同设计

我们带着将每天使用它的那些专家——安全、产品、合规和交付团队——的反馈，构建了企业级前沿防护。我们合作的团体之一是系统性风险分析与韧性中心（ARC），其成员包括美国最大银行的首席信息安全官，如高盛、摩根士丹利、花旗、美国银行和富国银行。

我们还与康卡斯特（Comcast）、毕马威（KPMG）、Visa 等公司的领导者合作，以确保该设计能跨行业站得住。我们的对话覆盖了财富 100 强的四分之一、每一家美国全球系统重要性银行、以及几乎每一个受监管行业。

以下是我们从这一广泛客户群处听到的，以及我们为应对这些共同关切而构建进 EFS 的东西：

### 关于监控

企业长久以来一直把监控用于内部人员风险，如今希望在为 agent 升级监控上得到帮助。他们的关切是关于 Anthropic 的自动化监控系统能否满足他们的监管标准。

**在 EFS 中，客户控制数据如何被审阅。** 当监控检测到一个需要注意的模式时，那些信号会被直接发给客户，让他们能审阅自动化系统检测到了什么。

### 关于数据存储

对企业而言，增加另一家「受信任的数据供应商」是件麻烦事，原因有很多。他们必须通知自己所有客户这些供应商是谁、并更新合同。鉴于数据极高的敏感性，他们也有安全存储和审计数据的要求。出于这些关切，我们把 EFS 架构设计成客户能在其现有云基础设施上存储数据。

**在 EFS 中，客户能控制他们的数据存储与管理。** 客户希望有能力让数据栖身于他们自己控制的基础设施里，在他们自己的加密密钥、访问策略和审计日志之下。用于监控的活动数据可以存储在客户自己的云账户里（如 Amazon S3、Azure Blob Storage 或 Google Cloud Storage）。

### 关于自动化与人工审阅

即便自动化审阅越来越有效，一个人去查看一条标记，仍能通过确认真正的滥用、清除误报来增添价值。但我们从许多客户——尤其是受监管行业里的——那里听到的是，做那项审阅的人必须是他们自己的人。许多团队在严格规定谁可以查看某些信息的规则下运作——特权的法律材料、非公开信息、药物安全报告。他们的团队已经为此项工作受过培训、获过审批。

**EFS 有自动化的安全监控，无需 Anthropic 的人工审阅。** 客户想要对网络攻击的防护，并理解若攻击在多个会话和账户上展开，会很难检测。在 EFS 中，自动化系统分析一个滚动的流量窗口，寻找严重滥用的信号，包括试图开发攻击性网络或生物能力的企图，以及凭证被盗或泄漏的迹象。那些标记直接发给客户，由他们的人接手处理——无需 Anthropic 员工的人工审阅。

> AI 控制的设计必须能保护敏感信息，而模型防护是这一过程中的重要组成部分。Anthropic 在开发企业级前沿防护时征询了我们，以确保与我们的要求和标准对齐。

> 企业级前沿防护给了我们恰恰所要求的：我们的日志留在一个由 Wells 管理的环境里、在 Wells 管理的密钥之下。我们在 Anthropic 运作检测的同时保管我们数据的主导权。正是这种分工，让我们的团队能安全地让前沿模型工作，并履行我们对客户、员工和监管方的义务。我们的行业需要这些防护，所以我们帮助塑造了它们。

> 作为一家运营关键基础设施的公司，模型的能力很重要。同样重要的是那些让我们能把数据留在自己账户里的方案，而企业级前沿防护解决了这一点。

> 我们的八位成员与 Anthropic 合作，定义了在一个系统重要性银行内部运行最强前沿模型需要什么：谁持有数据、谁持有密钥、自动化审阅能看到和不能看到什么、以及在什么条件下才允许人类去查看。这次协作正在促成改进的防护与标准的开发和交付，它们能在我们行业内外规模化。

> 防护架构的一个关键信条，是我们能保留数据、并把它置于模型本身之外、在我们环境内受保护地保管。公司里、以及客户工作里的一些领域是受监管、高度敏感的。那些防护实际上让我们能把 AI 应用到我们此前无法涉足的业务部分。——服务伙伴

> 二十多年来客户一直把他们的数据托付给我们。正是这份经验，让我们想帮 Anthropic 一起把这件事想透，而不是在场外等待。我们得以在架构层面——而不仅仅是政策层面——协作打造新的安全与隐私能力。

> 我们的客户想让前沿模型工作，而他们安全团队希望数据留在他们控制的基础设施里。Anthropic 与一百多家企业一起构建企业级前沿防护，正是为此。——服务伙伴

> 随着 AI 模型承担更多受监管、敏感的工作负载，负责任地扩展也归结到架构，而不仅是政策承诺。对数据环境的直接掌控，配上基于模式的自动化安全监控，给了企业真正监督、问责和信心地部署所需的具体、结构性能力。——服务伙伴

> 防护及其设计——显然，你们听到了我们的反馈。他们让我们坐上驾驶座。日志由我们掌控；除非我们愿意，它们哪儿都不去。它让我们掌控数据、掌控信息，并掌控在某个可能超出防护的东西被检测到之后该怎么做。

> 随着 AI 更深地嵌入企业各处，安全和信任正是让组织从实验走向规模化部署的东西。企业级前沿防护从一开始就把这些内建进去：监控数据留在客户控制的基础设施里，由他们自己的团队决定谁能访问它。——服务伙伴

> 让客户数据保密是 Snowflake 对每一位客户做出的承诺。我们一直飞速地把前沿模型送到他们手中。难的是在最严格的数据保证下安全地做到。我们与 Anthropic 合作设计企业级前沿防护，好让我们两者兼得：数据留在客户的环境里、在他们掌控的密钥之下，从第一天起就跑 Anthropic 最强的模型。这就是当以平台为念构建时，负责任的前沿 AI 应有的样子。

> 在 Stripe，保护客户数据是我们运作方式的根基。Anthropic 的企业级前沿防护将让我们能使用覆盖的前沿模型、同时把会话日志保留在 Stripe 的 AWS 环境里，其访问和审阅由 Stripe 的安全控制治理。

> Rogo 的客户期望获得可得的最好智能，但绝不在其数据的安全和护栏之外付出代价。企业级前沿防护会把最强的模型带给金融机构，同时满足它们所要求的机构级数据要求。前沿智能与企业级控制的这种结合，对在整个金融服务领域部署 AI 至关重要。

> FIS 支撑着资金如何流转、金融机构如何运作背后的基础设施，因此我们部署的任何 AI 防护都必须达到那种规模和信任标准。我们与 Anthropic 的合作已包含通过 Project Glasswing 用我们自己的系统测试他们最前沿的模型。Claude 企业级前沿防护扩展了这项工作，把保留的数据留在我们自己的账户里、并把标记直接路由给我们的安全团队。

> 企业把真实的生产工作交给 Cognition 的自主工程师，而这份信任取决于他们的工作保持私密。有了企业级前沿防护，客户数据和身份从不出我们这一侧。它将让我们把前沿 AI 带入生产工作，无需隐私上的权衡。

> 我们客户的代码和数据是他们最有价值的知识产权的一些。保护那些信息是我们在 Factory 构建方式的根基。我们与 Anthropic 一起，让客户能在把专有数据掌控权留在自己手中的同时，使用 Claude 最强的模型。企业级前沿防护给企业提供了前沿智能的访问，同时具备他们安全团队所要求的数据保护。

> 我们一直保持对客户机密性和安全坚定不移的承诺。我们所服务的顶尖法律和专业团队视这些原则为不可谈判，我们也以同样的标准要求自己。企业级前沿防护映照了这份承诺，让有着最严苛保密要求的客户能访问前沿模型，而模型提供方不保留他们的数据。

## EFS 如何运作

这些控制被设计成，无论你从 Anthropic 直接访问 Claude、还是通过云伙伴访问，都以同样的方式运作。在亚马逊云科技、Google Cloud 和 Microsoft Azure 上的客户会得到同等的控制，把他们的活动数据存储在云账户里、在他们已经信任的环境中。我们也在努力支持那些服务符合企业级前沿防护资格客户的第三方产品。

客户自有存储、客户管理的加密密钥，以及完全自动化审阅，各自都是选择启用的，所以你启用你组织所需的那些。它们都不改变模型行为、API 价格或速率限制。

Anthropic 不向企业级前沿防护收费。如果客户选择把数据存储在他们的云账户里，其云提供商会像对任何其他资源那样，就存储以及读取、写入和数据出站费用向他们计费。
