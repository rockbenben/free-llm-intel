# 推出生命科学验证计划

2026 年 9 月 17 日

今天，我们推出生命科学验证计划（Life Sciences Verification Program，LSVP），它让生命科学专业人士以一套对生物学相关工作更宽容的改良防护，访问我们的 Mythos、Opus 和 Sonnet 模型。我们已经通过一个早期访问计划纳入了数十家组织，如今正向更广泛的生命科学社区开放申请（[在此加入候补名单](https://claude.com/form/life-sciences-verification-program)）。该计划以 beta 启动，最初面向团队和机构。我们会持续改进该计划，并随时间把访问扩展到个人的 Pro 和 Max 套餐。

LSVP 旨在让生命科学专业人士把我们的模型用于一系列目前在我们普遍可用的 Fable 模型里被屏蔽的任务，如药物发现、研究生物学、临床开发和制造。它为各类团队而构建——从学术实验室到初创公司、药企等等。

## **验证与访问类型**

要符合这些授权的资格，每位申请者都要经历一个验证流程，其中包括对其研究资质、安全标准和伦理研究监督的审阅。一旦验证，团队可按其访问需求申请两种 LSVP 授权：「标准使用（Standard Use）」或「高风险使用（High-risk Use）」。这些授权可以通过我们所有产品界面使用，包括 [Claude Science](https://claude.com/product/claude-science)、[Claude.ai](http://claude.ai/redirect/website.v1.a11d29d6-cf23-40c2-95fb-1b1bdb0d6600)、Claude Code 和 API。

**标准使用**授权适合多数生命科学工作，包括多数生物研究与开发工作流。这些授权可延展到整个团队以应对多样的日常工作负载，且每年续期一次。它们给那些团队提供对我们 Mythos、Opus 和 Sonnet 模型的访问，配有比我们普遍可用模型对科学任务更宽容的改良分类器。标准使用授权今天适用于 Mythos 5.1、Opus 5 和 Sonnet 5，未来模型发布时也适用。它们被专门设计用来支撑生命科学活动的全谱系，领域涵盖基础科学、研发、供应链与制造、临床开发、质量保证、监管事务、投资与尽调等等。

虽然我们预计标准使用会覆盖多数访问需求，但某些工作带有更高的滥用可能、因而需要额外的审查。

**高风险使用**是针对那些在标准使用下被屏蔽的领域工作的团队的一项附加授权。它移除所有屏蔽生命科学请求的防护。该授权适用于单个研究项目而非整个团队，且必须每六个月续期一次。通常，一位做军民两用工作的研究者会有一个标准使用授权用于多样的日常活动，以及一个或多个高风险使用授权——后者只适用于特定项目上的工作（例如，刻画某一个特定的病毒载体家族如何被人类免疫通路识别）。

针对 Claude Opus 5 和 Claude Sonnet 5 的高风险授权今天即可用。我们正与美国政府合作，让高风险授权能更广泛地用于 Claude Mythos，但在本次发布之时，它们仍限于一小批经额外审查的实体。

所有其他防护，例如网络分类器，在 LSVP 授权下仍保持不变。

## 通过共同责任实现可信访问

正如我们最近在[威胁报告](https://www.anthropic.com/threat-intelligence-report-september-2026)中展示的，我们平台上正发生日益老练的滥用尝试，包括可能支持生物武器开发的尝试。在生物学里，往往无法区分一个用户是在做正当工作（例如研究一种病毒病原体以开发针对它的疫苗）还是在追求伤害（例如恶意地设法增强一种病毒的传播性），因此最令人担忧的威胁模型，是正当访问被一个居心不良的行为者转移或夺取的那种。事实上，内部威胁和作乱使用一直是重大生物安全事件和恐慌的主要因素。在开发 LSVP 的防护时，我们特别旨在防范三种令人担忧的威胁模型：

- *访问被夺：* 恶意软件或账户接管把访问转移给一个作恶者
- *内部威胁：* 作乱或被迫的员工蓄意采取恶意行动、或把其访问转移给一个作恶者
- *agent 滥用：* agent——尤其是在群体中或长时段任务上工作的——采取非预期的危险动作

为了防范这些威胁、并与企业 CISO 密切协作，我们围绕「共同责任」的概念设计了新的 LSVP 防护，通过对照模型访问的*预期用例*来监控使用。因为我们为 LSVP 组织的生命科学信誉和监督做过审查，我们可以赋能它们自行指定什么构成其计划内团队或项目的安全使用。

每个实体的访问都绑定到它在授权申请中所指定的用例，而我们持续监控 LSVP 流量，以识别处于声明安全范围之外的使用或模式。若发生未经授权的活动，我们能把这些案例标记给组织管理员，让其在事先商定的时限内对事件进行分类和整改。这些用例应包含对预期工作的高层描述，就像一份招聘启事里会给出的那样，而不包含任何敏感信息或知识产权。

## LSVP 中的监控如何运作

严重滥用往往分散在许多请求和会话中，以显得互不关联、从而逃避检测。在 LSVP 中，我们把防护从实时拦截——我们在每次请求时拒绝潜在有害的访问——转向离线监控，这让我们能更清晰地跨行为模式识别潜在滥用。把执法从实时拦截转向离线监控，让正当工作以更少的打断继续，但这要求我们保留与被标记活动相关的数据以供审阅。对 LSVP 流量，我们要求保留数据 30 天，以便有效做到这种监控。

这些数据被严格隔离，不能用于模型训练、也不得被 Anthropic 生命科学研究团队的成员访问。对于合格组织，我们也在努力理解 LSVP 如何能与我们[企业级前沿防护](https://www.anthropic.com/news/enterprise-frontier-safeguards)（EFS）系统的功能集成。

## 申请与可用性

有兴趣加入 LSVP 的组织可[在此登记意向](https://claude.com/form/life-sciences-verification-program)。我们预计在第一周内纳入数百家组织，并在未来几周进一步扩展该计划，以支持多数生命科学社区。

今天，LSVP 在我们第一方控制台中支持 API 使用，也在 Claude for Enterprise 和 Team 套餐中可用。我们尚不支持个人套餐，但正努力扩大对这些用户的访问。它在第三方平台上也尚不可用。

作为一个 beta，LSVP 对启用了 BAA 的组织不可用。这意味着有 PHI 数据的客户应使用带非 BAA、非 HIPAA 的独立组织。

在 API 和 Claude Science 中，用户能原生地在各授权之间切换。在 [Claude.ai](http://claude.ai/redirect/website.v1.a11d29d6-cf23-40c2-95fb-1b1bdb0d6600) 和 Claude Code 中，最初只有一个预选的默认授权适用（除非使用带 API 认证的 Claude Code）。这对绝大多数只需要标准使用授权的用户来说应该没问题。不过，我们会随时间改进这些 LSVP 功能的支持与可移植性。
