# 超越许可提示：让 Claude Code 更安全、更自主

发布于 2025 年 10 月 20 日

Claude Code 全新的沙箱功能——一个 bash 工具和网页版 Claude Code——通过启用两道边界（文件系统和网络隔离），减少了许可提示、提升了用户安全。

在 [Claude Code](https://www.claude.com/product/claude-code) 里，Claude 与你并肩编写、测试和调试代码，浏览你的代码库、编辑多个文件、并运行命令来验证它的工作。给 Claude 这么多对你代码库和文件的访问可能带来风险，尤其在 prompt 注入的情形里。

为帮助应对这一点，我们在 Claude Code 中推出了两项构建于沙箱之上的新功能，它们都旨在为开发者提供一个更安全的工作场所，同时允许 Claude 以更少许可提示、更自主地运行。在我们的内部使用中，我们发现沙箱安全地把许可提示减少了 84%。通过界定 Claude 能自由工作的一组边界，它们提升了安全性与能动性。

### **在 Claude Code 上保障用户安全**

Claude Code 运行在一个基于许可的模式上：默认只读，意味着它在进行修改或运行任何命令之前会请求许可。这有一些例外：我们自动允许像 echo 或 cat 这样安全的命令，但多数操作仍需明确批准。

不断点击「批准」会拖慢开发周期、并导致「批准疲劳」，用户可能不会密切关注自己批准的是什么，进而让开发变得更不安全。

为解决这一点，我们为 Claude Code 推出了沙箱。

## **沙箱：一种更安全、更自主的方法**

沙箱创建预定义的边界，Claude 在其中可以更自由地工作，而不是为每个动作请求许可。启用沙箱后，你得到的许可提示大大减少、安全性提升。

我们的沙箱方法构建在操作系统级特性之上，以实现两道边界：

- **文件系统隔离**，确保 Claude 只能访问或修改特定的目录。这对防止一个被 prompt 注入的 Claude 修改敏感的系统文件尤其重要。
- **网络隔离**，确保 Claude 只能连接到获批准的服务器。这防止了一个被 prompt 注入的 Claude 泄漏敏感信息或下载恶意软件。

值得一提的是，有效的沙箱需要*同时*具备文件系统和网络隔离。没有网络隔离，一个被攻陷的 agent 可能外泄 SSH 密钥这类敏感文件；没有文件系统隔离，一个被攻陷的 agent 很容易逃出沙箱并获得网络访问。正是通过同时使用这两项技术，我们能为 Claude Code 用户提供更安全、更快速的 agentic 体验。

### Claude Code 中两项新的沙箱功能

#### **沙箱化 bash 工具：无需许可提示的安全 bash 执行**

我们推出[一个新的沙箱运行时](https://docs.claude.com/en/docs/claude-code/sandboxing)，作为研究预览以 beta 提供，它让你确切定义你的 agent 能访问哪些目录和网络主机，而不必像容器那样拉起和管理。它可用于对任意进程、agent 和 MCP 服务器做沙箱化。它也作为[一个开源研究预览](https://github.com/anthropic-experimental/sandbox-runtime)提供。

在 Claude Code 中，我们用这个运行时对 bash 工具做沙箱化，允许 Claude 在你设定的限定范围内运行命令。在安全的沙箱内，Claude 能更自主地运行、并安全地执行命令而无需许可提示。如果 Claude 试图访问沙箱*之外*的东西，你会立刻收到通知，并可以选择是否允许。

我们构建在像 [Linux bubblewrap](https://github.com/containers/bubblewrap) 和 macOS seatbelt 这样的操作系统级原语之上，在 OS 层强制这些限制。它们不仅覆盖 Claude Code 的直接交互，也覆盖命令派生的任何脚本、程序或子进程。如上所述，这个沙箱同时强制：

- **文件系统隔离，** 通过允许对当前工作目录的读写访问，但阻止修改其外的任何文件。
- **网络隔离，** 通过只允许互联网访问经由一个连到沙箱外运行的代理服务器的 unix 域套接字。这个代理服务器强制限制进程能连接到的域名，并为新请求的域名处理用户确认。如果你想进一步提升安全性，我们也支持定制这个代理，对出站流量施加任意规则。

两个组件都可配置：你可以轻松选择允许或不允许特定的文件路径或域名。

Claude Code 的沙箱架构用文件系统和网络控制隔离代码执行，自动允许安全的操作、阻止恶意的操作，只在需要时请求许可。

沙箱确保即便一次成功的 prompt 注入也被完全隔离、无法影响用户的整体安全。这样，一个被攻陷的 Claude Code 无法窃取你的 SSH 密钥，也无法向攻击者的服务器打电话回家（phone home）。

要开始使用这个功能，在 Claude Code 里运行 /sandbox，并查看关于我们安全模型的[更多技术细节](https://docs.claude.com/en/docs/claude-code/sandboxing)。

为让其他团队更容易构建更安全的 agent，我们[开源](https://github.com/anthropic-experimental/sandbox-runtime)了这个功能。我们相信其他人应当考虑为自己的 agent 采纳这项技术，以增强其 agent 的安全态势。

#### **网页版 Claude Code：在云端安全地运行 Claude Code**

今天，我们也发布 [Claude Code on the web](https://docs.claude.com/en/docs/claude-code/claude-code-on-the-web)，让用户能在云端一个隔离的沙箱里运行 Claude Code。网页版 Claude Code 在隔离的沙箱里执行每次 Claude Code 会话，在其中它以安全、稳妥的方式对其服务器拥有完全访问。我们把沙箱设计成确保敏感凭证（如 git 凭证或签名密钥）从不与 Claude Code 同处沙箱之内。这样，即便沙箱内运行的代码被攻陷，用户也能免于进一步的伤害。

网页版 Claude Code 用一个自定义代理服务透明地处理所有 git 交互。在沙箱内，git 客户端用一个专门构建的作用域受限的凭证向该服务认证。代理验证这个凭证以及 git 交互的内容（例如确保它只推送到配置的分支），然后在把请求发到 GitHub 之前附上正确的认证 token。

Claude Code 的 Git 集成把命令经由一个安全代理路由，该代理验证认证 token、分支名和仓库目标——在允许安全版本控制工作流的同时，防止未授权的推送。

## 如何开始

我们新的沙箱化 bash 工具和网页版 Claude Code，为用 Claude 做工程工作的开发者在安全和生产力上都带来显著提升。

要开始使用这些工具：

- 在 Claude 里运行 `/sandbox`，并查看[我们的文档](https://docs.claude.com/en/docs/claude-code/sandboxing)了解如何配置这个沙箱。
- 前往 [claude.com/code](http://claude.ai/redirect/website.v1.96e5891a-4883-4e39-9424-66cbc1393bf0/code) 试用网页版 Claude Code。

或者，如果你在构建自己的 agent，看看我们[开源的沙箱代码](https://github.com/anthropic-experimental/sandbox-runtime)，并考虑把它集成进你的工作。我们期待看到你所造之物。

要了解更多关于网页版 Claude Code 的信息，查看我们的[发布博客文章](https://www.anthropic.com/news/claude-code-on-the-web)。
