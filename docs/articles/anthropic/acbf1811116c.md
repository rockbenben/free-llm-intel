作为一名销售主管，我很痛苦地承认，不久前，那些想为公司购买Claude的人并没有足够快地得到他们需要的答案。他们已经填写了我们的联系销售表格，但等了很长时间才收到回复，有时甚至要等好几天。他们的大多数问题都很简单：计划的费用是多少，是否有最低座位数，或者我们是否可以满足 HIPAA 的合同要求。答案就在我们的文档和支持文章中，但客户希望有人能够快速引导他们完成这些任务。

因此，我们在 Claude Managed Agents（测试版）上建立了一个采购代理，将潜在客户从“我希望 Claude 加入我的公司”到完成购买。采购代理现在每天进行数千次对话，回答客户最紧迫的问题，并帮助他们完成结帐。它升级给我们团队的客户受到了教育，并且更愿意做出购买决策：他们转化为机会的频率是旧表单中潜在客户的两倍多，并且成交速度要快大约五天。我们特意将这种体验保留为选择加入，这意味着我们的客户一开始就可以根据自己的喜好选择是否愿意与代理商或销售代表交谈。

![](https://assets.claude.com/b67a0e1a023590767c2fd9b4cbb9a94aba1cc82d.png)

## **为什么旧的入站流程会崩溃**

在建立采购代理之前，我们的入库流程相当简单。买家填写了一份表格。该线索被发送给业务开发代表，后者对其进行资格鉴定并将其传递给客户经理。当团队可以与每个对产品感兴趣的人交谈时，这仍然很有效。

我们每个月都会收到数以万计的入站请求，而我们的入站 BDR 团队却无法跟上。销售代表每天都在回答文档中已经涵盖的问题，而我们没有有效的方法来联系队列中的所有客户。这不是我们想要为客户提供的体验。

我们希望每位客户都能在任何时间以任何语言获得专业的答案，并且能够按照自己的喜好进行购买，这通常意味着无需与销售代表交谈。我们希望我们的代表将时间花在可以改变结果轨迹的对话上。

## **缩小差距的采购代理**

我们在客户已经提出问题的地方部署了代理：在我们的[联系销售](https://claude.com/contact-sales)和[定价](https://claude.com/pricing#team-&-enterprise)页面、产品内部以及我们的电子邮件中。任何客户都可以在我们的 [Claude.ai](http://claude.ai) 产品中找到采购代理，这是一种简单的聊天体验，可以帮助客户了解什么计划最适合他们。客户描述他们的团队的需求，代理提出一些后续问题，然后回答有关定价、安全和数据的问题，然后推荐计划和座位数。每次对话以以下三种方式之一结束：

- **购买。** 买家直接结账。
- **交接。** 对于较大或更复杂的交易，代理会将买家以及完整的对话详细信息传递给代表。
- **快速回答。** 有时这就是客户的全部需求。

我们构建代理程序是为了遵循销售代表的相同工作，这意味着了解客户正在尝试解决什么问题，他们当前的 Claude 使用情况如何，以及我们如何最好地帮助他们。

![](https://assets.claude.com/7c281bb3ea8a03950ee0130275034a17b32b111a.png)

## **我们为什么使用 Claude Managed Agents？**

在幕后，购买代理很简单：一个提示、一些工具和在 Claude Managed Agents 上运行的 Claude。由于该平台负责托管、会话管理和工具编排，因此我们的工程师将时间花在销售设计购买体验上，而不是构建基础设施。

我们最终选择了托管代理，原因如下：

- **快速投入生产。** 一名工程师在短短几周内就在托管代理上构建了初始购买代理。
- **技术和非技术贡献者。 **工程部门拥有代码，但销售和内容主管直接在控制台中审查和编辑系统提示。更改首先发送给我们的临时代理，因此任何人都可以在到达客户之前尝试进行调整。
- **专注于域，而不是线束。** 托管代理运行代理循环、会话和托管。我们把时间花在提示、工具和知识库上——这三件事是销售特有的。
- **版本控制使迭代成本更低。** 对代理的每次更改都会保存为其自己的版本。我们在 v7 上进行了大约一周的内部测试，并且在发布后每周都会发布及时的更改。当需要时，我们可以轻松地将新会话指向以前的版本。
- **支持更多用例的灵活性。** 如今，客户在我们的网站上发现了该代理。托管代理支持计划运行，这为我们提供了探索其他类型的客户参与的途径。

## **我们在构建采购代理时学到了什么**

**给Claude一个目标，而不是规则。**解释代理的目标比详细的指令列表更有效。例如，像“您的目标是了解客户需求、确定潜在客户资格并推荐最佳计划”这样简单的内容比在流程图中列出每项资格要求更有效。

**少即是多。 **我们尝试了不同长度、复杂性和结构的提示，发现“少即是多”的格言最有效。如今的模型可以理解复杂、细致入微的目标，并据此进行逆向工作。在实践中，这意味着通过向 Claude 提供成功所需的知识和背景来摆脱 Claude 的阻碍，例如基于席位的定价涵盖哪些内容或计费周期何时运行。

**在开发循环中使用中小企业。 **在代理编码加快开发周期的世界中，这一点变得越来越有价值。通过使用托管代理和 Claude Code 节省时间，我们的工程师能够将更多时间与销售团队一起打造以客户为中心的体验。我们能够尽早且经常地测试代理，从而实现快速迭代。

**专注于对客户有利的事情。** 代理经常将小型团队指向我们的团队计划而不是企业计划，因为在某些情况下这对他们来说是正确的答案。我们决定这是一个功能。找到正确的计划而不是被追加销售的买家更有可能留下来并获得更好的体验。

**将每个代理升级视为反馈。** 每次代理将买家传递给代表时，都会解释原因。早期，大部分原因是客户无法使用我们的自助服务产品自行完成的事情。这些原因决定了我们如何改善体验，需要专人帮助完成交易的对话比例下降了大约一半。

## **对客户来说发生了什么变化**

该代理现在每天全天候进行数千次对话。客户的问题可以立即得到解答，而不必等待预定的电话或在多天内交换电子邮件。我们的许多客户实际上更喜欢与客服人员交谈而不是与人交谈，因为这样可以在出现问题时为他们提供快速、明智的答案。我们的许多新的自助服务企业客户在购买前都会与采购代理进行交谈，我们发现那些事先与代理交谈过的人对他们所购买的产品有更好的了解。

## **代理商如何改变我们的销售组织**

该座席改变了我们的代表度过一天的方式。现在，我们已经能够将团队的大部分时间和精力集中在客户购买过程的早期教育、进行更多现场客户对话以及花时间亲自参加活动。

最有影响力的变化是，我们的销售代表现在获得了更明智的潜在客户，比旧的联系表格更频繁地将潜在客户转化为销售机会，并且结案速度加快了大约五天。销售代表在开始对话时就已经知道客户的需求、他们被告知的内容以及我们如何才能最好地帮助他们。

例如，我们的一位内部销售代表 Ojas 过去常常交换大约 10 封电子邮件来完成一笔交易；现在大约需要六个。自从推出采购代理以来，他已经将已完成的赢得交易的产出提高了 2.5 倍，因为这使他能够专注于受过高等教育且准备就绪的客户，这些客户只需要帮助就可以完成交易。

不久前，我们的团队还无法跟上入站队列。现在，任何买家都可以随时开始对话，我们的代表可以更有效地利用时间。采购代理是我们迈向整个客户关系代理的第一步。
