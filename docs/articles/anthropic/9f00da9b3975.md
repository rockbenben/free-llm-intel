# 项目重新设计：从文件夹到对话

Claude projects 的全新体验，现已在 Claude Code 中以 beta 形式提供

- 类别：[产品公告](https://claude.com/blog/category/announcements)、[Claude Code](https://claude.com/blog/category/claude-code)
- 产品：[Claude Code](https://claude.com/product/claude-code)
- 日期：2026 年 9 月 17 日
- 阅读时长：5 分钟
- 分享：[复制链接](https://claude.com/blog/projects-redesigned#)https://claude.com/blog/projects-redesigned

过去，在一次构建中管理多个会话，需要你去拆分工作、腾挪交接、再把结果缝回一起。如今在一个 Claude Code 项目里，你只需描述需要完成什么，Claude 来管理工作。

Claude 界定请求范围、分派工作、协调并行线程、审阅输出，并组装最终成品。你可以在全程引导进度，甚至从手机上；而你离开电脑之后，它仍在继续工作。

例如，配置一个项目，设定一个目标：降低你应用的结账 p75 延迟。然后请 Claude 剖析每个端点、测试优化方案，并在并行线程里开 PR。或者连接你的 API、web 和移动端仓库，设定一个目标：退役一个已弃用的 v1 端点。Claude 会为每个仓库开一个线程来迁移调用方、跑测试、开 PR，然后告诉你哪些需要先行合并。

从今天起，更新后的项目以 beta 形式向部分使用 Claude Code 云端会话、且在网上或桌面上没有现存项目的 Claude Pro 和 Max 订阅者开放。

接下来一周，我们会把这些套餐上更多 Claude Code 用户的访问权限扩大。随后是整个 Claude 各套餐以及 Team 和 Enterprise 套餐上的更新项目。如果你在 Pro 或 Max 上、还没有获得访问权，可以加入[候补名单](https://claude.com/form/projects)。

Pro 和 Max 套餐上的现有项目会像今天一样继续工作。随着推广扩展到 chat 和 Cowork，我们会逐步升级它们。

## 线程干活，Claude 指挥

项目里有干活的线程，也有指挥它们的协调器。

当你启动一个项目时，你选择一个目标，以及仓库或上下文。Claude 一开始会建议它可以马上接手的工作。你可以配置项目的云端环境、连接器、插件、指令和模型。

你可以在主项目聊天里监控并引导进度，或者钻进每个单独的线程里检视并引导细节。像给一位幕僚长做交代那样向项目里的 Claude 简要说明，它就会把工作路由到新线程或已有线程。

Claude 也会主动跟进、把事情办到底。连上代码仓库后，一个线程会开 pull request 并跑你的测试；有文档时，它会阅读并起草。

在底层，每个线程都是一个 Claude Code 云端会话，在它自己的分支和仓库副本上工作。协调器让工作保持条理，但如果任何线程在处理同一份代码，重叠会像任何普通 PR 一样作为合并冲突来解决。

每个线程在需要时还能用 subagents、循环和工作流把它分派的工作进一步拆分成若干块，从而让大任务更快完成。

## 上下文随时间积累

项目是为长时间运行或 agentic 的工作流设计的：那些耗时超过一次回复、且包含多个部分的工作。

随着时间推移，Claude 会更了解项目细节并把它们应用到它的工作中。现在每个线程都会写入并从一份共享记忆中汲取，减少了复杂 prompt 工程的需要。

例如，Claude 能记住发布改到了周五、导出为什么被砍掉，或在动计费服务之前该和谁确认。

一个跨越一周的项目。每个请求在右侧开一个线程；记忆、决策和成果在下方逐层累积。

Claude 也记得你的工作和沟通风格。你可以要求它调整自己多久向你确认一次、多频繁地开新线程、或每条更新写多详细。

除了记忆，项目现在还包含一个库，收集你添加的文件和 Claude 产出的成果物。这让查找相关材料、让新工作在过往成果之上构建都更容易。

## 接下来

项目可以同时运行多个线程，而每个线程都是一次完整的 Claude Code 会话。正因如此，项目可能更快触及用量上限。你可以查看项目专属的用量，并选择协调器聊天以及工作线程所使用的模型和努力（effort）级别。

线程如今在云端运行；在你自己的机器上、与你本地的工具和代码一起、并在你的网络之内运行，很快就会到来。

开始使用[项目](https://claude.com/projects)。
