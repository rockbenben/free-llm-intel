现在，你可以把 Claude Managed Agents、Messages API 以及 Claude SDK 的 OpenTelemetry（OTel）trace 发送到任意 OTel 工具，并跟上你的 agent 走过的每一步。如果你已经在把 Claude Code 或 Cowork 的 trace 送进你的可观测性工具，那么你在 Claude Platform 上构建的 agent 也可以出现在同一个地方。

## 用 OpenTelemetry 追踪 agent

要把更多的访问权限交给一个 agent，起点是追踪它的模型调用、工具调用以及 MCP server 调用。审阅它的 trace，然后随着它证明了自己的可靠，再逐步放宽它的访问权限。

在 Claude Console 里添加一个目的地，之后每一次 agent turn、每一次模型调用和每一次工具调用，都会以一条标准 OpenTelemetry trace 的形式抵达你的可观测性工具，并带上延迟、token 与 ID。

![OpenTelemetry 的 trace 如何工作](https://assets.claude.com/28fe34519808d40faa51162351234a3790230860.png)

## 与你的可观测性工具协同

Claude 的 trace 遵循 [OpenTelemetry GenAI 语义约定](https://github.com/open-telemetry/semantic-conventions-genai/)，因此来自 Claude 与其他提供商的数据可以在同一批工具和仪表盘里使用。

- **把 agent 与你技术栈的其他部分放在一起调试**。在 [Grafana Cloud](https://grafana.com/docs/grafana-cloud/observe-and-act/agent-observability/guides/send-claude-platform-traces/)、[Honeycomb](https://docs.honeycomb.io/send-data/use-cases/claude-platform)、[Sentry](https://sentry.io/cookbook/trace-claude-platform-with-opentelemetry/) 和 [Splunk](https://agent-observability-docs.splunk.com/sdk-api/third-party-integrations/claude) 里，agent 的 trace 与你的日志和指标并列，于是你能看出某个变慢或失败的步骤来自哪个服务。
- **用生产数据改进 agent**。借助 [Arize AI](https://arize.com/docs/ax/integrations/platforms/claude-managed-agents/claude-managed-agents-tracing)、[Braintrust](https://www.braintrust.dev/docs/integrations/ai-providers/anthropic#export-opentelemetry-traces-from-the-claude-api)、[Datadog](https://docs.datadoghq.com/llm_observability/instrument/otel_instrumentation/?tab=python#using-claude-managed-agents)、[Langfuse](https://langfuse.com/integrations/model-providers/claude-platform)、[LangSmith by LangChain](https://docs.langchain.com/langsmith/trace-anthropic)、[New Relic](https://newrelic.com/blog/news/anthropic-otel-ai-observability) 和 [PostHog](https://posthog.com/docs/ai-observability/installation/anthropic?tab=Claude+Platform&utm_source=anthropic&utm_campaign=anthropic-otel)，你可以把真实的 trace 变成 eval，捕捉质量问题，并衡量某项改动是否起了作用。
- **跟踪整个组织的用量**。把 trace 发送到 [Databricks Unity Gateway](https://docs.databricks.com/aws/en/ai-gateway/unified-trace-table)，让平台团队与安全团队能看到按团队划分的 token 用量，并标记异常活动。

Claude 的 trace 同样适用于任何接受标准 OTLP endpoint 的其他 OpenTelemetry 工具。

## 开始使用

Claude Platform 上的 OpenTelemetry trace 已进入公测。Managed Agents 与 Messages API 需要在 Claude Console 里设置一个目的地，而 Claude SDK 会自动导出 trace。

参见[文档](https://platform.claude.com/docs/en/manage-claude/opentelemetry)开始上手。

![Foxglove](https://assets.claude.com/59150536fe838e40bd470d19ad4ab74ec3fa2d61.svg)

> “在 Foxglove，我们正在构建帮助机器人团队调试其机器人的 agent。Claude Platform 原生的 OpenTelemetry 导出让我们能在 PostHog 里把 agent 的交互与产品使用数据放在一起分析。这帮助我们评估 agent 在实际中的表现、识别它们的短板，并为机器人团队排定改进的优先级。”

Roman Shtylman，联合创始人兼 CTO

![Ramp](https://assets.claude.com/6db782273272dd89f11df7b54089328994fe718e.svg)

> “Claude 支撑着 Ramp 一些能力最强的内部与面向客户的 agent。我们构建了 Reflect，一套 agentic 系统，为它们的 Langfuse trace 打分、找出反复出现的故障并提出修复方案。在某些 agent 上，我们已经把 token 用量削减了 10–20%，并让会话快了 30%。但 Reflect 只能改进它观察得到的东西。Claude API 原生的 OpenTelemetry 导出可以把高保真的 instrumentation 直接喂进这个改进循环，不需要任何额外步骤。”

David Traina，高级软件工程师

![Sterling Labs](https://assets.claude.com/0e7434aa92b7dbc6ea6bd4109a0b3602bcb2a22c.svg)

> “在 Sterling Labs，我们像赛车队调校引擎那样调校自己的系统。对于全天候分析实时市场的 agent，Langfuse 就是我们的维修区围墙。Claude Platform 原生的 OpenTelemetry 导出把每一条 trace 直接灌进来，无需自定义 instrumentation，所以我的团队能专注于前沿，而不是布线。”

Hyon Lee，CTO

![FloQast](https://assets.claude.com/37eab59899ee1b3f95d9bd8106e2708f2db42680.svg)

> “动到公司账目的 agent 必须展示自己的工作，就像会计师那样。我们的 agent 运行在 Claude Platform 上，我们的遥测存放在 Grafana Cloud 里，而 Claude 原生的 OpenTelemetry 导出会把每一次模型调用放进它所在的那条对账或分录工作流的同一条 trace 中。我们与技术栈里的其余部分一起看到 prompt 版本、工具调用、延迟与 token 开销，所以当审计师问某个 agent 做了什么、为什么这么做时，我们能从同一条时间线上给出答案。”

Ankush Sharma，基础设施负责人
