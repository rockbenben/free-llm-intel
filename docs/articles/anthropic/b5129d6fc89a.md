任何开过 pull request 的人都知道这是怎么回事。他们刚开始做下一件事，评审结果就回来了。于是他们停下来，重新翻回旧代码，推送一个修复，再等待评审重新运行。然后他们再去找人批准。

这种做法有其充分理由。大多数团队希望每项变更都由人批准，而当每一行代码都由人编写时，这很容易跟上。但现在很多开发者用 agent 构建。在 Claude Code 团队，[Claude 编写了我们的大部分代码](https://claude.dev/blog/solving-code-review-at-anthropic/)，我们也希望 PR 之后的一切都能同样快速地推进。

这就是我们构建 [Claude Ship](https://claude.com/product/claude-ship) 的原因，它今天以 beta 版推出。它可以评审 PR、修复 PR，并根据每个团队制定的策略决定哪些已准备好合并。团队仍然掌控它在哪里运行，以及哪些变更需要人工处理。目标：以团队编写代码的速度交付代码。

> 符合条件的 Claude Enterprise 组织可申领至少 $10,000 的 Claude Ship 额度，并在申领后 30 天内使用。申领截止日期为 January 15, 2027。适用条款。

### Claude Ship 如何运作：评审、修复和批准

Claude Ship 由已经全面可用的 [Code Review](https://claude.com/resources/articles/code-review-is-now-generally-available) 以及两个处于 beta 版的新 agent 组成：PR Steward 和 Claude Approvals。它们共同将 pull request 推进完成评审、修复和批准决策，让团队不必手动管理每一步。

![Claude Ship 帮助团队评审 PR、修复 PR，并决定什么可以合并。Claude Ship 使用 AI，可能漏掉缺陷、安全漏洞或其他问题。](https://assets.claude.com/2a72b687af32e0d798bd2859b12576be1f607f13.png)

**Code Review** 会通过多个视角，对照代码库对 pull request 进行深入评审。它收集发现，以对抗性方式验证这些发现，对它们进行分类，并发布到 PR 上。在 Claude Code 团队，Claude 的评审是更广泛流程中的一层；从 June 到 September，合并的 PR [增长了一倍多](https://claude.dev/blog/solving-code-review-at-anthropic/)，而回退的比例下降了 40% 以上。Code Review 为团队提供快速评审、清晰的发现，并可为每个仓库选择 Quick、Standard 或 Deep 评审级别。

![Code Review 在 pull request 上发布发现的示例。](https://assets.claude.com/a30243fe61e4cc224ebfdcdb8d693b69c125b060.png)

**PR Steward** 致力于让 PR 保持通过状态，但它的设计目标不是批准或合并 pull request。它会介入失败的 CI 检查、合并冲突，以及来自 Code Review、其他评审工具或团队成员的评审反馈。每次推送后，它会评论说明自己改了什么以及如何撤销。开发者可以评论 `@claude` 并附上指令来引导工作，或评论 `@claude stop` 让它退出。

![PR Steward 在 pull request 上处理修复的示例。](https://assets.claude.com/c6832086d36407567641b1b4de4d705f79ef3fca.png)

接下来，**Claude Approvals** 会应用团队写成仓库文件的批准策略。如果策略允许，Claude 可以自行批准常规变更，也可以针对某些场景要求更深入的人工签核。它就像一个更智能的 CODEOWNERS 文件。团队可以让 Claude Approvals 在决策过程中考虑多种信号，包括 Code Review 的发现，或使用自然语言的自定义分类器。对大多数客户，我们建议先以仅观察模式启用，以建立信心，然后再配置分支保护，要求获得 Claude Approvals 的放行。

![Claude Approvals 策略文件示例。](https://assets.claude.com/6beae6085c1dc6bb43a62e6acf1f5563a14f4238.png)

![满足其批准策略的 pull request 示例。](https://assets.claude.com/635a1675ea125007f1d5f686db25959d8485d5fc.png)

## 两种上手方式

### 面向开发者：在 Claude Code 中运行 `/ship`

开发者可以通过 Claude Code 中新的 `/ship` 命令，在自己的 pull request 上试用 Claude Ship。当变更准备好后，他们运行 `/ship`。Claude 会推送变更、打开 PR、评审变更，并处理反馈和失败的检查，帮助其准备好合并。哪些内容可以合并取决于开发者的权限和仓库的分支规则。

![在 Claude Code 中运行 /ship 的示例。](https://assets.claude.com/3b5fa6d188937030373792607c2cc73fc01e52b1.png)

### 面向管理员和工程负责人：逐个仓库设置规则

为整个仓库启用 Claude Ship 后，它会在团队控制的设置和批准策略下，自动处理团队的 pull request。开发者无需手动调用 `/ship` 命令。

- **管理员选择它在哪里运行。** 管理员为每个仓库开启 Code Review 和 PR Steward。当已连接的仓库在其默认分支上有策略文件时，Claude Approvals 就会启动，管理员可以将其关闭。
- **每个仓库都会获得所需的设置。** 管理员选择评审级别（Quick、Standard 或 Deep）、选择评审运行时机，并配置支出限额。
- **团队保留现有工具。** Claude Ship 可与现有的分支保护和必需检查配合使用。

团队决定推进节奏。他们可以从一个仓库开始，选择评审级别和评审运行时机，设置每月支出限额，并让批准策略以观察模式运行，直到建立信任。

### Claude Code 团队如何交付

我们在自己的许多 pull request 上运行 Claude Ship。最大的变化之一是谁能够处理客户反馈。例如，Claude Code 团队的产品经理现在可以阅读一条反馈，与 [Claude Tag](https://claude.com/product/tag) 讨论想法和权衡，让它打开一个 PR，然后继续做下一件事，而 Claude Ship 会将其推进完成评审、修复和批准决策。

最近，一位客户感到困惑，因为我们的 Analytics API 文档暗示 Admin 密钥可以拉取 Pro 和 Team 的用量。产品经理问 Claude Tag 是否已有修复正在进行，它便打开了一个修复。Code Review 没有发现阻塞项，一位文档评审者签核，Claude Approvals 通过，修复在当晚就合并了。

### 可用性

Claude Ship 已在 Claude Team 和 Enterprise 计划中可用，适用于 GitHub 上的仓库。Code Review [已全面可用](https://claude.com/resources/articles/code-review-is-now-generally-available)，PR Steward 和 Claude Approvals 处于 beta 版。

Claude Ship 的使用按 token 计费，因此启用它会增加组织成本。金额取决于所覆盖 pull request 的数量和大小、评审级别、评审运行频率，以及 PR Steward 完成的工作量。管理员可以为 Code Review 和 PR Steward 设置支出限额。Claude Approvals 没有基础费用，但策略中的分类器按其使用的 token 计费，而使用 Claude 评审的策略会触发一次计费的 Code Review，即使在观察模式下也是如此。运行 `/ship` 会计入常规 Claude Code 使用量。

Claude Ship 不适用于启用 Zero Data Retention、HIPAA 配置或客户管理加密密钥的组织。

### 开始使用

开发者可以更新 Claude Code，并在下一次变更时运行 `/ship`。从今天起，`/ship` 正在 Claude Code 和桌面应用中逐步推出。

已经在使用 Code Review 的团队可以在某个仓库上添加 PR Steward，并添加观察模式下的批准策略。

初次使用 Code Review 的团队可以阅读[设置指南](https://code.claude.com/docs/en/code-review-setup)，连接 GitHub 并开启他们的第一个仓库。

在[文档](https://code.claude.com/docs/en/claude-ship)中了解更多。
