开过 pull request 的人都熟悉这个过程。刚开始做下一件事，审查反馈就回来了。于是停下手头的工作，重新翻出之前的代码，推送修复，再等审查重跑，最后还要找人审批。

这么做有充分的理由。多数团队希望每项变更都由人审批。当每行代码都由人编写时，审批速度容易跟得上。如今，很多开发者借助 agent 开发。在 Claude Code 团队，[我们的大部分代码由 Claude 编写](https://claude.dev/blog/solving-code-review-at-anthropic/)。我们希望 PR 提交后的各个环节也能达到同样的速度。

为此，我们构建了 [Claude Ship](https://claude.com/product/claude-ship)，今天开始提供测试版。它可以审查并修复 PR，依据各团队制定的策略判断哪些变更已达到合并要求。团队仍可决定它在哪些地方运行、哪些变更需要人工审批。我们希望让代码交付跟上编写速度。

> 符合资格的 Claude Enterprise 组织可领取至少 10,000 美元的 Claude Ship 额度，并在领取后的 30 天内使用。领取截止日期为 2027 年 1 月 15 日。适用相关条款。

### Claude Ship 如何审查、修复和审批

Claude Ship 包含已正式推出的 [Code Review](https://claude.com/resources/articles/code-review-is-now-generally-available)，以及处于测试阶段的两个新 agent，PR Steward 和 Claude Approvals。三者协同完成 pull request 的审查、修复与审批判断，团队无需手动协调每一步。

![Claude Ship 帮助团队审查和修复 PR，并判断哪些变更已可合并。Claude Ship 使用 AI，可能遗漏 bug、安全漏洞或其他问题。](https://assets.claude.com/2a72b687af32e0d798bd2859b12576be1f607f13.png)

**Code Review** 结合代码库，从多个角度深入审查 pull request。它汇集发现的问题，以对抗方式逐项验证，再分类并发布到 PR。Claude Code 团队把 Claude 的审查作为整套流程中的一环。从 6 月到 9 月，合并的 PR 数量[增加了一倍以上](https://claude.dev/blog/solving-code-review-at-anthropic/)，回滚比例下降了 40% 以上。Code Review 提供快速审查和明确的问题说明，每个仓库可在 Quick、Standard 和 Deep 三个审查级别中选择。

![Code Review 在 pull request 上发布审查结果的示例。](https://assets.claude.com/a30243fe61e4cc224ebfdcdb8d693b69c125b060.png)

**PR Steward** 负责让 PR 保持检查通过，它的设计职责不包含审批或合并 pull request。CI 检查失败、出现合并冲突，或收到 Code Review、其他审查工具或团队成员的反馈时，它都会着手处理。每次推送后，它会发表评论，说明改了什么以及如何撤销。开发者可在评论中用 `@claude` 加指令来引导它，也可发送 `@claude stop` 让它停止处理。

![PR Steward 在 pull request 上处理修复的示例。](https://assets.claude.com/c6832086d36407567641b1b4de4d705f79ef3fca.png)

接下来，**Claude Approvals** 会应用团队写入仓库文件的审批策略。如果策略允许，Claude 可以自行批准常规变更，也可以在特定情况下要求人工进一步签核。它的作用类似于更智能的 CODEOWNERS 文件。团队可以让 Claude Approvals 在决策时参考多种信号，包括 Code Review 的发现，或用自然语言定义的自有分类器。对多数客户，我们建议先以仅观察模式启用，验证效果后再配置分支保护，要求通过 Claude Approvals 检查。

![Claude Approvals 策略文件示例。](https://assets.claude.com/6beae6085c1dc6bb43a62e6acf1f5563a14f4238.png)

![符合审批策略的 pull request 示例。](https://assets.claude.com/635a1675ea125007f1d5f686db25959d8485d5fc.png)

## 两种上手方式

### 开发者可在 Claude Code 中运行 `/ship`

开发者可以通过 Claude Code 的新命令 `/ship`，在自己的 pull request 上试用 Claude Ship。变更准备好后，运行 `/ship`。Claude 会推送代码、打开 PR、审查变更，并处理反馈和失败的检查，协助 PR 达到合并要求。哪些变更可以合并，取决于开发者的权限和仓库的分支规则。

![在 Claude Code 中运行 /ship 的示例。](https://assets.claude.com/3b5fa6d188937030373792607c2cc73fc01e52b1.png)

### 管理员和工程负责人可逐个仓库设置规则

为整个仓库启用 Claude Ship 后，它会自动处理团队的 pull request，并遵循团队掌控的配置与审批策略。开发者无需手动运行 `/ship` 命令。

- **管理员决定在哪些仓库运行。** 管理员逐个仓库启用 Code Review 和 PR Steward。已连接仓库的默认分支中有策略文件时，Claude Approvals 会启动，管理员可以将其关闭。
- **各仓库可按需设置。** 管理员会选择审查级别（Quick、Standard 或 Deep）、审查运行时机，并设置支出上限。
- **团队可继续使用原有工具。** Claude Ship 兼容现有的分支保护和必需检查。

团队可以自行决定推进节奏。可以先选一个仓库，设定审查级别、运行时机和月度支出上限，并以观察模式运行审批策略，直到对它的表现有把握。

### Claude Code 团队如何交付代码

我们在自己的许多 pull request 上运行 Claude Ship。其中一项最大的变化是能直接处理客户反馈的人更多了。例如，Claude Code 团队的产品经理现在可以阅读一条反馈，与 [Claude Tag](https://claude.com/product/tag) 讨论思路和取舍，让它打开 PR，然后继续下一项工作。Claude Ship 会接手审查、修复和审批判断。

最近有位客户感到困惑，因为我们的 Analytics API 文档暗示 Admin 密钥可以查询 Pro 和 Team 的用量。产品经理问 Claude Tag 这项修正是否已经在做，Claude Tag 随即创建了修复 PR。Code Review 没有发现阻断问题，文档审查人员签核，Claude Approvals 也通过了检查。修复当晚就合并了。

### 可用范围

Claude Ship 面向 Claude Team 和 Enterprise 方案，在 GitHub 仓库上使用。Code Review 已[正式推出](https://claude.com/resources/articles/code-review-is-now-generally-available)，PR Steward 和 Claude Approvals 仍处于测试阶段。

Claude Ship 按 token 计费，启用后可能增加组织的支出。费用取决于纳入的 pull request 数量及规模、审查级别、审查频次，以及 PR Steward 的工作量。管理员可以为 Code Review 和 PR Steward 设置支出上限。Claude Approvals 不收基础费用，但策略中的分类器按实际使用的 token 计费。策略使用 Claude 的审查结果时，即使处于观察模式，也会触发付费的 Code Review。运行 `/ship` 计入常规 Claude Code 用量。

启用了 Zero Data Retention、HIPAA 配置或客户管理加密密钥的组织无法使用 Claude Ship。

### 开始使用

开发者可以更新 Claude Code，在下一项变更上运行 `/ship`。`/ship` 从今天起陆续在 Claude Code 和桌面应用中推出。

已在使用 Code Review 的团队，可以在仓库中添加 PR Steward，并在观察模式下配置审批策略。

初次使用 Code Review 的团队，可以阅读[设置指南](https://code.claude.com/docs/en/code-review-setup)，连接 GitHub 并在第一个仓库中启用。

详见[文档](https://code.claude.com/docs/en/claude-ship)。
