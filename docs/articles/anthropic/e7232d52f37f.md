# 发布 Claude Mythos 与 Claude Fable 5.1

我们推出 Claude Fable 5.1 与 Claude Mythos 5.1。它们是面向编程与知识工作的全球最先进的模型——而它们的科研能力也让我们提前看到 AI 模型将如何推动科学进步。

Claude Fable 5.1 与 Claude Mythos 5.1 是同一个模型，只是安全护栏的强度不同。Fable 5.1 全面开放，而 Mythos 5.1 只通过我们的可信访问计划提供；它的护栏专为支持网络安全与生命科学领域的工作而设计。

在能力增强的同时，Fable 5.1 针对我们收到的客户关于价格、数据留存与护栏的反馈，迈出了重要一步。

**价格*.***凡按 token 计费的地方，Fable 5.1 在典型工作负载上的成本预计比 Fable 5 低 25%。这是因为我们下调了 cache reads 的价格（即模型读取已经被处理并存储过的输入）。对于高度 agentic 的工作，节省往往大得多——最高可达约 45%。

**数据留存*. ***我们全新的 Enterprise Frontier Safeguards（EFS）体系，既能在防范对抗性滥用方面保持最先进水平，又为客户提供完整隐私（等同于零数据留存政策）。EFS 的做法是把数据存储在完全由客户而非 Anthropic 控制的云基础设施上。它将分阶段向企业客户开放，从今年秋天晚些时候开始。在 EFS 就绪之前，符合条件的客户可以以零数据留存方式使用 Fable 5.1。

**护栏*. ***我们改进了护栏，以减少误报（即系统把良性内容标记出来的情况）。在网络安全领域，我们最新的护栏拦下的误报比以前少 60%。这部分是因为 Fable 5.1 现在可以用于发现软件漏洞——但不能用于为其开发 exploit。在生物学领域，我们与美国政府合作建立了一个访问计划，让使用者能够获得 Claude Mythos 5.1 的先进生物学能力。我们预计很快会向科学家开放报名。

## 科学研究

我们在广泛的领域中测试了 Claude Fable 5.1 与 Claude Mythos 5.1 的科学研究能力。我们的发现——其中包括下面分享的早期示例——进一步印证了 AI 模型很快会对科学发现作出重要贡献。

**分子设计*.* **许多现代药物的作用方式是结合到体内的靶点上，以阻断靶点、激活靶点或向靶点递送某些东西。要让药物在更低剂量下起效，就需要高亲和力的结合物；对许多常见药物形式而言，设计出一个结合物就是研发流程的第一步。为了看 Claude Mythos 5.1 在这项任务上能做到什么程度，我们让模型可以调用开源的蛋白质设计与折叠工具，并把它的设计送到两家外部机构做实验验证。Mythos 5.1 证明自己能够设计亲和力极高的结合物。在三个靶点上，[3] 它的结合亲和力比提交给 [Adaptyv Bio 的蛋白质设计竞赛](https://proteinbase.com/competitions) 的最佳设计高 10 倍。它的命中率（也就是设计中确实是可用结合物的数量）是我们迄今测到最强的：在 12 个靶点上达到接近 50%。（当今蛋白质设计领域的命中率通常为 10–15%。）

Claude 设计的蛋白质结合物（橙色），分别对应 12 个靶点（灰色）。视频中每一个设计都在实验室中被确认能够结合。图中展示的结构是 ESMFold2 的预测结果。

**计算分析与建模**。Claude Fable 5.1 训练了一个神经网络，为金星三分之一的地表制作了一张全新的高分辨率高程图。它的工作依据是 30 多年前 NASA 的 Magellan 任务拍摄的雷达图像，以及一份已经覆盖该行星五分之一区域的[地图](https://agupubs.onlinelibrary.wiley.com/doi/full/10.1029/2012EO120002)。Claude 的新地图如今能呈现小至两到三公里的细节，而不是 10 到 20 公里，并且高程的准确度比之前最高提升 25%。

我们正以 Creative Commons 许可[发布这张地图](https://zenodo.org/records/22164484)，赶在即将开展的 NASA VERITAS 与 ESA EnVision 任务之前，希望它能帮助这些任务确定未来观测应当瞄准哪些地质特征。

**计算生物学*.***在计算生物学中，在 GPU 上运行任务专用的机器学习模型是常态。因此这些模型的速度成为科研进展的瓶颈。Mythos 5.1 给出了这个问题的一种解法：通过编写自定义 GPU kernel 并缓存它们的中间结果，它把七个开源深度学习模型最高加速了 2.5 倍（输出完全一致）。

## 安全、防护与对齐

过去两年里，AI 模型的 agentic 能力已经强大得多。但正如我们[记录过的](https://www.anthropic.com/news/investigating-incidents-cybersecurity-evals)，更强的自主性伴随着新的风险。安全、防护与对齐方面的工作需要与 AI 能力以同样的速度推进。昨天，我们[发布了一份报告](https://www.anthropic.com/news/improving-alignment-security-efforts)，说明我们如何改进自身在对齐与安全方面的工作

在发布 Claude Fable 5.1 与 Claude Mythos 5.1 之前，我们（某些情况下还有外部研究者）对模型做了大量测试，覆盖许多领域的风险。我们在 [System Card](https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card) 中完整描述了这些工作；下面是简要总结。

**化学与生物风险**。我们测试了 Claude Mythos 5.1 在多大程度上能够帮助制造化学或生物武器。测试包括专家 red-teaming、自动化评估，以及一次让博士级生物学家与 AI 专家配对的桌面推演，用以检验模型能否达到人类专家的表现水平。Mythos 5.1 的能力强于 Mythos 5。但我们的评估显示，它仍未达到我们 [Responsible Scaling Policy](https://www.anthropic.com/responsible-scaling-policy) 所定义的下一个风险等级。因此我们部署 Mythos 5.1 时使用的[护栏](https://www.anthropic.com/news/improving-fable-5-s-biology-safeguards)与我们施加在 Mythos 5 上的一致，即限制对研究性生物学能力的访问。

**网络风险**。我们运行了一套评估来考察 Claude Mythos 5.1 的网络安全能力（关闭网络安全护栏）。总体而言，该模型展现出我们发布过的所有模型中最强的网络能力，但它仍处于我们 [Frontier Compliance Framework](https://www.anthropic.com/news/compliance-framework-SB53) 中较低的风险类别。我们还对 Fable 5.1 的网络安全护栏做了大量压力测试：除了我们自身对其稳健性的动态评估，我们还委托两家机构进行外部测试，并由 [Gray Swan](https://www.grayswan.ai/) 做自动化测试。与 Fable 5 和 Opus 5 一样，我们没有发现这些护栏存在[严重级别为 critical 的 jailbreak](https://www.anthropic.com/news/fable-safeguards-jailbreak-framework)的证据。

**Agentic 安全**。我们评估了 Claude Mythos 5.1 对恶意请求与 prompt injection（藏在 AI 模型所处理内容中的对抗性指令）的回应。它拒绝恶意 agentic 编码与计算机使用请求的比例与 Mythos 5、Sonnet 5 和 Opus 5 相当；在一项外部 [prompt injection benchmark](https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card)上，它是我们迄今最稳健的模型。

**对齐*.***我们通过静态与交互式行为评估、用[自然语言 autoencoder](https://www.anthropic.com/research/natural-language-autoencoders)分析其内部思考、与未对齐相关的能力评估、对我们训练数据的审查，以及对内部试点使用的分析，来测试模型的行为。我们还收到了来自外部测试的报告。

我们的自动化行为审计发现，Claude Mythos 5.1 在多数指标上比它的前代 Mythos 5 对齐得更好。当被分配一项原本不可能完成的任务时，它试图访问测试环境之外资源的可能性显著低于 Mythos 5。它也比 Mythos 5 更少用带有动机的推理来为自己的行为辩护（例如推理说当前情形只是模拟或评测），而且更少在追求用户目标的过程中无视明确约束。从我们对训练数据的审查来看，Mythos 5.1 无论尝试 reward hacking（也就是作弊）还是作弊成功，整体比率都低于 Mythos 5。

尽管我们的对齐评估总体上显示出改进，测试也发现模型有时仍然能绕过审批和 auto-mode 分类器（我们在 [System Card](https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card) 中有更详细的讨论）。我们的对齐评估在覆盖范围上也有局限。目前，我们的自动化行为审计对超长上下文工作和多 agent 场景的可见度较低。对不可能任务的覆盖也少于我们的期望（这类任务会引发更异常、更未对齐的行为），不过我们近期在这方面做出了改进，正在努力继续推进。

我们还改进了护栏，使它们能让模型在不牺牲安全的前提下更有用。下面说明这些变化。

**面向企业的自动化护栏*.***[Enterprise Frontier Safeguards](https://www.anthropic.com/news/enterprise-frontier-safeguards)（EFS）让我们能够检测并响应对我们模型的滥用，同时仍为企业客户提供零数据留存协议那样的隐私。有了 EFS，客户把自己的数据存储在自有云基础设施上，而不是 Anthropic 的系统上；任何人工审查默认都由客户自己完成，而不是 Anthropic。我们是在与 100 多家客户的密切协作中开发 EFS 的，这些客户来自金融服务、医疗健康、制造、电信、法律、零售和公共部门等行业，协作对象还包括我们在 Amazon Web Services、Google Cloud 和 Microsoft Azure 的云合作伙伴。

EFS 将支持 Claude Code、Claude Enterprise、Claude Platform、Amazon Bedrock、AWS 上的 Claude Platform、Google 的 Agent Platform 以及 Microsoft Foundry。它从今年秋天起分阶段推出。如上文所述，具备 EFS 资格的客户在 EFS 就绪之前，可以以零数据留存方式使用 Fable 5.1（以及 Fable 5）。你可以在[这里](https://www.anthropic.com/news/enterprise-frontier-safeguards)阅读更多关于 EFS 的内容；如需申请访问，请填写[这张表单](https://claude.com/form/enterprise-frontier-safeguards)。

**面向生物学与网络安全更精准的护栏*. ***过去几个月里，我们在让 Fable 5.1 的护栏更精准方面取得了进展：让它们更不容易标记良性内容（比如关于医疗问题的提问，或是网络防御者用模型来让自己的系统更安全），同时仍然确保它们对真实威胁提供可靠防护。

正如我们[最近分享的](https://www.anthropic.com/news/improving-fable-5-s-biology-safeguards)，针对与基础生物学和医学问题相关的良性请求，我们为 Fable 5.1 与 Fable 5 准备的最新生物学护栏触发频率降低了 85%（相比随 Fable 5 上线的那一版）。不过，与生命科学研究和开发相关的查询仍会被引导到我们的 Opus 模型。我们正通过一个与美国政府合作开发的 Claude Mythos 5.1 访问计划，把该模型的生命科学能力开放给专业人士，下文会详细讨论。

借助 Fable 5.1，我们正在更新网络安全护栏使其更精准。同时我们现在允许 Fable 5.1 用于识别软件漏洞——也就是开展那类能提升软件安全性的防御性工作。由于这些变化，Claude Code 用户预计每个 session 来自我们网络安全护栏的介入平均会减少约 60%（相对于 Fable 5 上的此前护栏）。不过，我们的护栏仍然会把若干类双用途的网络安全任务（可能有助益*或*可能造成危害的任务）引导给我们的 Opus 模型，这包括渗透测试、exploit 生成以及基于二进制文件的漏洞扫描。

**抗蒸馏机制*.***蒸馏是一种用于提取先进模型能力的方法，通常以工业规模实施，动用数千个虚假账号。蒸馏是一种安全风险，因为蒸馏出的能力随后可能在缺乏充分护栏的情况下被发布。Fable 5.1 配备了强化的机制，让蒸馏攻击更难奏效。例如，新的 API 账号（从今天起创建的账号）已经不可能在多轮对话中手动编辑 Claude 的先前上下文、同时保留 Claude 先前思考的记录。这就堵住了一种常见且有公开文档的蒸馏技术，此前蒸馏者用它来非法提取 Claude 的思考内容。我们会逐步推出这一变化以尽量减少干扰：现有账号目前不受此变化影响，但在未来的模型发布中它会适用于所有用户，届时少数客户的自定义集成会受到影响。我们的[帮助中心文章](https://support.claude.com/en/articles/16761192)更详细地说明了这一变化以及开发者可以做出的调整。

## Claude Mythos 5.1 的可信访问

Claude Mythos 5.1 与 Fable 5.1 完全相同，但它为工作受上文所述网络安全与生命科学限制影响的、经审核的个人与机构提供更宽松的护栏。它将通过两个可信访问计划提供：

- **Cyber Verification Program：**CVP 目前为防御性安全工作提供对某些 Opus 级与 Sonnet 级模型的访问，其网络安全护栏有所放宽。不久之后，该计划也将包括对 Claude Mythos 级模型的访问。[在此申请加入 CVP](https://portal.anthropic.com/programs/cvp)。
- **Life Sciences Verification Program：**LSVP 的设计让生命科学专业人士可以使用 Claude Mythos 5.1，并配备专为专业研发活动设计的护栏（其他所有护栏仍然保持）。我们与美国政府合作，已经纳入了首批参与者，并计划把这一计划的访问范围扩大到更广泛的生命科学界。

除了这些可信访问计划，[Claude Security](https://claude.com/product/claude-security)——我们用于扫描代码库漏洞并建议补丁供人工审阅的产品——现在也由 Claude Mythos 5.1 提供支持。

## 符合 EU AI Act 的要求

2026 年 7 月，Anthropic（与 [190 个其他签署方](https://digital-strategy.ec.europa.eu/en/news/strong-backing-code-practice-transparency-ai-generated-content)一起，其中也包括若干其他主要 AI 模型提供商）签署了 EU AI Act 的《AI 生成内容透明度实践准则》。

这要求我们为 2026 年 8 月 2 日之后发布的模型的输出加上水印——一种用数字方式判断某段文字有多大概率出自 Claude 的手段。正如我们[最近解释的](https://www.anthropic.com/news/claude-text-watermark)，这个水印对没有检测 API 的人不可见。它对 Claude 输出的质量与内容没有实际影响，也不包含任何关于用户、用户所在机构或用户与 Claude 对话内容的信息。

该法案还要求我们提供一种途径，让用户能够判断一段文本是否可能含有水印。因此我们正在私密预览中推出一个检测 API。按照欧盟法律的要求，它目前向符合条件的组织开放（例如监管机构、执法部门、媒体、事实核查机构、独立研究者、教育组织以及欧盟公民社会团体）。它同样向那些为自身遵守该法案而负有验证水印义务的企业开放。我们计划随着时间推移扩大检测 API 的访问范围。你可以在[这里](https://forms.gle/9tGA33hPJJwtHsMk9)登记获取访问的意向。
