我们正在介绍克劳德寓言 5.1 和克劳德神话 5.1。它们是世界上最先进的编码和知识工作模型，它们的研究能力让人们能够初步了解人工智能模型将如何促进科学进步。

Claude Fable 5.1 和 Claude Mythos 5.1 是同一型号，但防护级别不同。 《神鬼寓言》5.1 是普遍可用的，而《神话 5.1》只能通过我们的可信访问程序获得；其保障措施是专门为支持网络安全和生命科学领域的工作而设计的。

除了功能的增强之外，《神鬼寓言 5.1》还采取了重要措施来解决我们从客户那里收到的有关价格、数据保留和安全措施的反馈。

**价格*.*** 对于典型工作负载，无论使用情况如何按代币计费，《神鬼寓言》 5.1 的成本预计比《神鬼寓言 5》低 25%。这是因为我们正在降低缓存读取（模型读取已处理和存储的输入）的定价。对于高度代理的工作，节省的费用通常要大得多，高达约 45%。

**数据保留*。 ***我们的新企业前沿保障 (EFS) 系统为客户提供完全的隐私（与零数据保留政策相同），同时在防止敌对性使用方面仍然保持最先进的水平。 EFS 的工作原理是将数据存储在完全由客户而非 Anthropic 控制的云基础设施中。它将从今年秋季晚些时候开始分阶段向企业客户提供。在 EFS 推出之前，符合条件的客户将能够以零数据保留的方式使用 Fable 5.1。

**保障措施*。 ***我们改进了保护措施，以减少误报（系统标记良性内容）。在网络安全方面，我们最新的防护措施阻止的误报比以前减少了 60%。部分原因是《神鬼寓言 5.1》现在可用于发现软件漏洞，但不能用于开发漏洞利用程序。在生物学方面，我们与美国政府合作开发了一项访问计划，以便能够访问 Claude Mythos 5.1 的高级生物学功能。我们预计很快就会向科学家开放报名。

## 科学研究

我们测试了克劳德寓言5.1和克劳德神话5.1在广泛领域的科学研究能力。我们的发现（包括我们下面分享的早期例子）进一步证明人工智能模型很快将为科学发现做出重要贡献。

**分子设计*.* **许多现代药物通过与体内的靶点结合来阻断、激活或输送某些物质来发挥作用。高亲和力粘合剂对于药物在较低剂量下发挥作用是必需的；设计一个药物是许多常见药物模式开发过程的第一步。为了了解 Claude Mythos 5.1 在这项任务上的表现如何，我们为模型提供了开源蛋白质设计和折叠工具的访问权限，并将其设计发送给两个外部组织进行实验验证。 Mythos 5.1 被证明能够设计非常高亲和力的粘合剂。在三个靶标上，[3] 其结合亲和力比 [Adaptyv Bio 蛋白质设计竞赛](https:// Proteinbase.com/competitions) 提交的最佳设计高 10 倍。它的命中率（即可行的绑定设计的数量）是我们迄今为止测量到的最高的：它在 12 个目标中达到了近 50%。 （当今蛋白质设计中 10-15% 的命中率是典型的。）

Claude 为 12 个目标（灰色）中的每一个设计了蛋白质结合剂（橙色）。视频中的每一个设计都被证实可以在实验室中绑定。显示的结构是 ESMFold2 预测。

**计算分析和建模**。克劳德寓言 5.1 训练了一个神经网络来创建金星三分之一的新高分辨率高程图。它的工作基于 NASA 麦哲伦任务 30 多年前拍摄的雷达图像以及已经存在于地球五分之一面积的[地图](https://agupubs.onlinelibrary.wiley.com/doi/full/10.1029/2012EO120002)。克劳德的新地图现在可以显示小至两到三公里的细节，而不是 10 到 20 公里，并且显示高度的准确度比以前提高了 25%。

在即将到来的 NASA VERITAS 和 ESA EnVision 任务之前，我们根据知识共享许可[发布了这张地图](https://zenodo.org/records/22164484)，希望它可以帮助他们确定未来观测的目标地质特征。

## 安全、保障和协调

过去两年，人工智能模型的代理能力变得更加强大。但正如我们[记录](https://www.anthropic.com/news/investigating-incidents-cybersecurity-evals)，更大的自主权伴随着新的风险。安全、保障和一致性方面的工作需要与人工智能能力同步发展。昨天，我们[发布了一份报告](https://www.anthropic.com/news/improving-alignment-security-efforts) 描述了我们如何改进我们自己的一致性和安全工作

在发布 Claude Fable 5.1 和 Claude Mythos 5.1 之前，我们（在某些情况下还有外部研究人员）对模型进行了跨多个领域的广泛风险测试。我们在[系统卡](https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card)中详细描述了这些努力；下面是一个简短的总结。

**化学和生物风险**。我们测试了克劳德神话 5.1 可以在多大程度上帮助制造化学或生物武器。这涉及专家红队、自动评估以及将博士级生物学家与人工智能专家配对的桌面练习，以测试模型是否可以与人类专家的表现相匹配。 Mythos 5.1 的功能比 Mythos 5 更强。但是，我们的评估表明它仍然达不到我们的[负责任的扩展政策](https://www.anthropic.com/responsible-scaling-policy) 中定义的下一个风险等级。因此，我们在部署 Mythos 5.1 时采用了与 Mythos 5 相同的保障措施，这些保障措施限制了对研究生物学功能的访问。

**网络风险**。我们进行了一系列评估来评估 Claude Mythos 5.1 的网络功能（关闭网络安全保障措施）。总体而言，该模型展示了我们发布的所有模型中最强大的网络功能，尽管它仍然属于我们的[前沿合规框架](https://www.anthropic.com/news/compliance-framework-SB5​​3)中较低的风险类别。我们还对《神鬼寓言 5.1》的网络安全保障措施进行了广泛的压力测试：除了我们自己对其稳健性进行动态评估之外，我们还委托两个组织进行外部测试，以及 [Gray Swan](https://www.grayswan.ai/) 的自动化测试。与《神鬼寓言 5》和《作品 5》一样，我们尚未发现这些保障措施的[严重越狱](https://www.anthropic.com/news/fable-safeguards-jailbreak-framework)的证据。

**代理安全**。我们对 Claude Mythos 5.1 如何响应恶意请求和提示注入（隐藏在人工智能模型处理的内容中的对抗指令）进行了评估。它拒绝恶意代理编码和计算机使用请求的速度与 Mythos 5、Sonnet 5 和 Opus 5 相当，并且它是我们迄今为止在外部[提示注入基准](https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card)上最强大的模型。

**对齐*.*** 我们通过静态和交互式行为评估、使用[自然语言自动编码器](https://www.anthropic.com/research/natural-language-autoencoders)分析其内部思维、与未对齐相关的能力评估、对我们的训练数据的审查以及对我们内部飞行员使用的分析来测试模型的行为。我们还收到了外部测试的报告。

我们的自动行为审计发现，Claude Mythos 5.1 在大多数指标上比其前身 Mythos 5 更好。与 Mythos 5 相比，该模型在分配不可能的任务时尝试访问其测试环境之外的资源的可能性要小得多。与神话 5 相比，它也不太可能使用动机推理来证明其行为的合理性（例如，通过推理情况是模拟或评估），并且在追求用户目标时不太可能忽略明确的约束。根据我们对其训练数据的审查，Mythos 5.1 都尝试奖励黑客（或作弊），并取得了成功，但总体比率低于 Mythos 5。

虽然我们的对齐评估总体上显示出改进，但我们的测试发现该模型有时仍然可以绕过批准和自动模式分类器（正如我们在[系统卡](https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card)中更详细讨论的那样）。我们的一致性评估提供的覆盖范围也存在限制。目前，我们的自动化行为审计对超长上下文工作和多代理设置的可见性较低。尽管我们最近在这一领域做出了改进，并且正在努力继续这样做，但我们对不可能任务（这可能会引发更多异常和失调行为）的覆盖范围也比我们希望的要少。

我们还改进了我们的保障措施，使我们的模型在不影响安全性的情况下更加有用。我们在下面描述这些变化。

**企业的自动化保障措施*.*** [企业前沿保障措施](https://www.anthropic.com/news/enterprise-frontier-safeguards) (EFS) 使我们能够检测和响应模型的滥用，同时仍然为我们的企业客户提供零数据保留协议的隐私。通过 EFS，客户将数据存储在自己的云基础设施上，而不是 Anthropic 的系统上；默认情况下，任何人工审核都是由客户自己完成，而不是由人为完成。我们与金融服务、医疗保健、制造、电信、法律、零售和公共部门等行业的 100 多家客户以及 Amazon Web Services、Google Cloud 和 Microsoft Azure 等云合作伙伴密切合作开发了 EFS。

Claude Code、Claude Enterprise、Claude Platform、Amazon Bedrock、AWS 上的 Claude Platform、Google 代理平台和 Microsoft Foundry 将支持 EFS。从今年秋天开始，它正在分阶段推出。如上所述，在 EFS 准备就绪之前，有资格使用 EFS 的客户可以使用零数据保留的 Fable 5.1（和 Fable 5）。您可以在[此处](https://www.anthropic.com/news/enterprise-frontier-safeguards)阅读有关 EFS 的更多信息；要请求访问，请填写[此表格](https://claude.com/form/enterprise-frontier-safeguards)。

**更精确的生物学和网络安全保障*。 ***在过去的几个月里，我们在使《神鬼寓言 5.1》的防护措施更加精确方面取得了进展：确保它们不太可能标记良性内容（例如有关医疗问题的查询或网络防御者使用该模型使系统更安全），但仍然确保它们提供针对真正威胁的强大保护。

正如我们[最近分享的](https://www.anthropic.com/news/improving-fable-5-s-biology-safeguards)，我们针对《神鬼寓言 5.1》和《神鬼寓言 5》的最新生物学保障措施，对于与基本生物学和医学问题相关的良性请求（相对于《神鬼寓言 5》中推出的那些），触发频率减少了 85%。然而，与生命科学研究和开发相关的查询仍将针对我们的 Opus 模型。我们正在通过与美国政府合作开发的 Claude Mythos 5.1 访问计划向专业人士提供该模型的生命科学功能，我们将在下面讨论。

在《神鬼寓言 5.1》中，我们正在更新我们的网络安全保障措施，使其更加精确。我们现在还允许使用《神鬼寓言 5.1》来识别软件漏洞，即进行可提高软件安全性的防御工作。由于这些变化，相对于《神鬼寓言 5》之前的安全措施，Claude Code 用户每次会话的网络安全措施干预平均减少约 60%。但是，我们的安全措施仍然将几种双用途网络安全任务（可能有帮助或*有害应用程序的任务）重定向到我们的 Opus 模型。这包括渗透测试、漏洞利用生成和基于二进制的漏洞扫描。

**反蒸馏机制*.*** 蒸馏是一种用于提取高级模型能力的方法。它通常以工业规模使用，使用数千个虚假账户。蒸馏存在安全风险，因为蒸馏后的能力随后可能在没有足够保障措施的情况下释放。 《神鬼寓言 5.1》配备了强化机制，使蒸馏攻击变得更加困难。例如，新的 API 帐户（从今天开始创建的帐户）不再可能在多轮对话中手动编辑 Claude 先前的上下文，同时保留 Claude 先前思维的记录。这关闭了一种常见的、公开记录的蒸馏技术，该技术允许蒸馏者非法提取克劳德的想法。我们正在逐步推出此更改，以最大程度地减少干扰：现有帐户目前不受此更改的影响，但它将适用于未来模型版本的所有用户。少数客户的定制集成将会受到影响。我们的[帮助中心文章](https://support.claude.com/en/articles/16761192)详细介绍了此更改以及开发人员可以进行的调整。

- **生命科学验证计划：** LSVP 的设计使生命科学专业人员可以使用 Claude Mythos 5.1 以及专为专业研究和开发活动设计的保障措施（同时所有其他保障措施仍然存在）。我们与美国政府合作，招募了第一批参与者，并计划将这个项目的参与范围扩大到更广泛的生命科学界。

## 遵守欧盟人工智能法案

2026 年 7 月，Anthropic（与[190 个其他签署方](https://digital-strategy.ec.europa.eu/en/news/strong-backing-code-practice-transparency-ai- generated-content)，包括其他几家主要 AI 模型提供商）签署了《欧盟 AI 法案》关于 AI 生成内容透明度的实践准则。

这要求我们在 2026 年 8 月 2 日之后发布的模型的输出中添加水印（一种确定 Claude 参与撰写文本的可能性的数字方式）。正如我们[最近解释的](https://www.anthropic.com/news/claude-text-watermark)，任何没有检测 API 的人都看不到该水印。它对 Claude 输出的质量或内容没有实际影响，并且不包含有关用户、他们的组织或他们与 Claude 的对话的信息。

该法案还要求我们为用户提供一种方法来判断文本是否可能包含水印。因此，我们在私人预览版中推出了检测 API。目前，根据欧盟法律的要求，符合资格的组织（例如监管机构、执法机构、媒体、事实核查人员、独立研究人员、教育组织和欧盟民间社会团体）可以使用它。它也适用于有类似义务验证水印以确保自身遵守该法案的企业。我们计划随着时间的推移扩大对检测 API 的访问。您可以在[此处](https://forms.gle/9tGA33hPJJwtHsMk9)登记访问兴趣。
