# Anthropic 员工如何使用 Claude Tag

*产出可用于客户的材料、汇编每周问题报告、进行法务审阅——全都在工作本已发生的地方完成。*

[Claude Tag](https://www.anthropic.com/news/introducing-claude-tag) 把 Claude 带入 Slack 这样的聊天工具，你可以在一个讨论串里像 @ 同事一样 @Claude，它会承接对话的上下文、完成任务，并把答案或结果发回到该讨论串。它还能[跟踪对话](https://claude.com/blog/claude-tag-now-reads-even-more-of-the-room)，利用可用的上下文、它的记忆，以及所收到的常设指令来决定何时参与聊天。过去几个月里，Anthropic 的各个团队一直用 Claude Tag 在共享频道里[自助做数据分析](https://claude.com/blog/self-service-data-analytics-in-slack-how-anthropic-deploys-claude-tag-for-ad-hoc-questions)、处理支持工单，或帮助[定位](https://www.anthropic.com/news/introducing-claude-tag)疑难 bug 的根因。

我们受自身在 Anthropic 工作的启发，整理了十几个 [Claude Tag 用例示例](https://claude.com/docs/claude-tag/users/use-cases)，并附上具体的 prompt 和设置说明。在本文里，我们重点介绍 Anthropic 员工用 Claude Tag 让工作流和流程更高效的三种方式，并给出他们用过的 prompt，方便你借用或改造最契合自己工作的那些。

## 把一个 Slack 讨论串打磨成一份精美文档

在最近一次功能发布期间，一位销售要求提供一份非技术性的材料，向客户和潜在客户解释这个功能如何运作；产品市场团队的 Hema Thanki 在 45 分钟内，把随后展开的那个 Slack 讨论串变成了一份可送审的文档。

那个 Slack 讨论串有 15 条以上的消息，多人陆续插话提建议或追加要求，其中对「到底需要什么」以及「现有技术材料是否足够」还带着一点张力。Hema 没有去澄清这些模糊之处，而是在讨论串里 @ 了 Claude：

‍`@Claude，通读这个 Slack 讨论串，做出[请求者]所要的那份一页纸。`


请求 Claude 基于一个 Slack 讨论串生成市场材料。此图为说明用例而生成，不含真实信息。

Claude 大约两分钟就生成了一份两页的草稿，用平实的语言讲清功能做什么、它的商业理由、实施涉及什么，并附了一个含更详细信息的附录。

随后，Hema 让 Claude 核验它的回复：

‍`@Claude，这份文档里的一切都是符合事实且正确的吗？`

Claude 把文档里的论断分成「已对照公开文档验证」的和「属于它自己的措辞」两类，并把后者标记出来提请产品负责人签核。Hema 提供了两份含相关信息的官方资源，Claude 就改写了一节以匹配这些资源里获批的措辞。

给 Claude 的后续指令同样在 Slack 里进行。此图为说明用例而生成，不含真实信息。

到那时，Hema 注意到被截断的讨论串使表述的基调产生了偏差，于是她粘贴进更完整的上下文。她与 Claude 来回共打磨了四个版本。在第一次请求约 45 分钟后，她把文档发给该功能的产品负责人审阅。Hema 没有花数小时去研究和起草文档，而是把时间用在了质疑准确性、提供来源、决定收录哪些信息上——这些都是需要人类判断的任务，也让这份客户资产更加扎实。

除了从 Slack 讨论串生成简报，Hema 还在日常工作中处处使用 Claude Tag。她保留着一个与 Claude 的私有 Slack 频道，在其中用一条条独立的讨论串提要求，像 @ 同事一样 @-提及 Claude。在那个频道里，Claude 会读取她粘贴或附加的任何内容、搜索 Slack 工作区和公开文档，并在后台工作，发布一份随进度更新的清单。Claude 的访问权限被刻意收窄：它只在被授予[访问权限](https://claude.com/blog/agent-identity-access-model)的频道和文档中工作，并在没有这些资源访问权时告知她。

## 整合并跟进散落在各 Slack 频道中的请求

当新功能发布时，销售通常要跟踪它，并把它传达给那些提出过该功能请求的、他们所服务的客户。这些请求通过 Slack 或一个产品反馈中心传达，可能散落在数月之久的历史里。产品战略与运营团队的 Steph Soderborg 在约 26 分钟内，就整合了所有与某个即将发布功能相关的诉求，并直接通知了每一位代表客户提出该诉求的销售。

起初，Steph 给 Claude 发消息，给出搜索目标、一句「什么算匹配」的定义，以及一份她想要的输出示例——上次发布时的一个七条条目列表：

‍`@Claude 我们即将 GA [一个新功能]。你能搜 Slack 吗……帮我找出任何曾为其客户提出这一功能需求的人……附上他们的 Slack 昵称和团队、提出该请求的客户，并从 Slack 链接到那次诉求。`


Claude 在若干频道和整个工作区跑了约 20 个搜索变体。产品反馈中心挡住了它的直接访问，于是它改从 Slack 交叉引用中浮现出中心里的条目，并把另一个内部助手先前发布的一份初版列表折入其中、对两者去重。整合后的列表在约 26 分钟后返回，包含约 24 个客户，每位提出者一行，含其 Slack 昵称、团队、客户，以及一个指向原始诉求的链接。

请求 Claude 生成一份在 Slack 里提出过某特定功能需求的所有人列表。此图为说明用例而生成，不含真实信息。

随后，Steph 交给 Claude 一项更大、她凭一己之力本没有余力去做的整合任务：她想要一幅全貌——企业客户在上一周报告的所有产品问题，包括哪些坏掉了、哪些已经修好，以及其中哪些报告指向同一个底层问题。她告诉 Claude 阅读所有涵盖事故、升级、支持和产品反馈的 Slack 频道，大约 50 分钟后，Claude 发布了一份按产品领域组织、把约 120 条原始发现浓缩为 23 个仍未解决的问题和 14 个已解决问题的报告。每个问题都附摘要和一个指向源讨论串的链接。Steph 随后让 Claude 复查它的工作，它又找出了 15 个问题。

Steph 估计，梳理、分析并综合这么多信息，至少会占用她一周的全职工作，或者干脆永远做不完。而借助 Claude Tag，她只花几分钟把诉求理清，Claude 就在后台干了起来。

Steph 也在一个私有频道里与 Claude 合作，一开始就发出完整指令，包括去哪些地方搜索、什么算匹配，通常还附上一份输出格式示例。Claude 搜索工作区、阅读它受邀进入的频道，并在工作中发布进度更新。当反馈中心挡住访问时，Claude 会试图通过可访问的文档和频道收集相关的或有关联的信息，甚至请求进入这些频道的访问权。

## 加快法律文档审阅

Anthropic 的法务团队会在每篇博客、落地页、邮件或任何其他材料公开发布前审阅它。在临近产品发布的日子里，市场团队可能排入数十份不同的资产待审，且期限紧迫。而这还只是流经审阅队列的所有市场材料之外的部分——从一段话的社交文案，到 2,500 字的博客草稿、十几个标签页的规划文档，再到跨多个触点含多个变体的邮件系列。法务团队的产品法律顾问 Molly Villagra 建了一个专用 Slack 频道，让 Claude Tag 先行审阅每一份市场资产，把市场法务审阅的周转时间从一天（或更久）压缩到每份资产 30 分钟。

要请求法务审阅，市场人员在 Slack 频道里贴出文档链接。没有工程背景的 Molly 在该频道为 Claude 设置了具体的规则和指令。Claude 不仅能替法务发现问题（如无凭据的市场宣称），还能帮忙核查市场内容里的事实性陈述，因为它能访问公司 Slack、一个内部知识索引和公开网络。如果有标记项，Claude 会列出它们并附上如何处理的具体指令，并直接与提出者合作解决。对于仍需法务签核的遗留问题，Claude 会 @ 相应的产品法律顾问，他们能迅速审阅那些被标记的陈述。

市场人员在专用 Slack 频道里贴出文档链接来请求法务审阅。此图为说明用例而生成，不含真实信息。

例如，在最近一次新闻通讯审阅中，Claude 标记了三个关键条目，而仅仅几分钟后，在未受提示的情况下，它在内部文档里找到了所需信息并解决了其中一条。Molly 在市场法务审阅频道里 @Claude，要求把它变成默认做法：

‍`你那三个要点抓得很好，但它们都能由你亲自验证。今后当你要标记这些问题时，会不会试着实时验证它们？`

应 Molly 的要求，Claude Tag 把这条新指令加入了它今后所有审阅要遵循的指令集，从而能够实时根据频道反馈改进自己。

这个反馈回路启发 Molly 建立了一个新的例程：指示 Claude 每周五回顾当周法律顾问的反馈，并提议更新共享指令供她批准。

我们上面分享的每一个工作流，都在为 Anthropic 员工省下数小时乃至数天的工作，并让一些换作从前根本不会发生的项目得以进行。你的团队会最先把工作流或项目交给 Claude 处理？

Claude Tag 目前处于公开 beta 阶段，在 Anthropic 自营服务上向 Team 和 Enterprise 套餐开放。可在 [claude.ai/admin-settings/claude-tag](https://claude.ai/admin-settings/claude-tag) 为你的工作区配置，或访问 [claude.com/docs/claude-tag](https://claude.com/docs/claude-tag) 了解更多。
