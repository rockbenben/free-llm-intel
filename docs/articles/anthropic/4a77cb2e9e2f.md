## 蓝图里有什么

该仓库包含购物 agent 和商家 agent 完整、可运行的实现，可以用 [Messages API](https://platform.claude.com/docs/en/intro)、[Agent SDK](https://code.claude.com/docs/en/agent-sdk) 或 [Claude Managed Agents](https://platform.claude.com/docs/en/managed-agents/overview)（beta）构建。你可以在写任何代码之前，在一个自助导览的演示里看到它们运行，然后用 Claude Code 把它们定制到你的目录、政策、品牌等等。

### 购物 agent

购物 agent 栖身于你的应用或网站内。这份蓝图包含了目录、购物车、结账、客户偏好和订单历史的集成点，并把支付留给你自己——无论那是你现有的结账流程，还是一家 agentic 支付服务商。

顾客可以说「我需要一顶帐篷、一个睡袋和一个炉子，用来带两个孩子过周末」，agent 就能从那里接手。以下是它能做的：

- 搜索目录并组装出正确的一组商品，包括多件商品的请求。
- 记住顾客的偏好，并据此定制它的建议。
- 直接在对话里展示产品、比较和购物车，而不只是文本。
- 构建购物车并交给结账。
- 在同一对话里回答客服问题，例如订单在哪、如何退货或换货、退款政策怎么说的——而不是把顾客甩到一个支持页面。

这个 agent 具备专为把价格和商品约束到真实目录数据、并避免操纵性追加销售（upsell）模式而设计的护栏。在仓库里，这些是用于目录搜索、多件商品规划、深度研究、个性化、客户关怀和对话内 UI 的 skills 和工具。

### 商家 agent

商家 agent 支持经营店铺的人。用户可以问「我们该打折清掉哪一季的库存？」并基于他们自己的数据得到答案。以下是它能做的：

- 回答关于销售表现的问题，例如什么好卖、什么不好卖。
- 跟踪库存并主动标记问题，例如一件商品在促销开始前就要售罄。
- 基于店铺自身的销售历史推荐定价和促销。
- 起草营销活动来推动那些需要被推动的产品。

当 agent 主动建议一项改动时，一个人在任何东西上线前先批准它，意味着用户握有最终决定权，而他们的 agent 在照看着店铺。在仓库里，这些能力以用于销售分析、目录与库存管理、营销与促销、以及门户内 UI（如图表和仪表盘）的 skills 交付。
