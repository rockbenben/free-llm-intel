# monday.com 如何把平台改造成人与 agent 协作的 agent 优先产品

*在附加式 AI 功能上撞墙之后，monday 围绕 Claude 重建了它的平台。两个月、五百万次 agent 交互之后，其团队分享了这次向 agent 优先产品转型的五条教训。*

超过 250,000 家公司，从中小企业到财富 500 强组织，都在用 [monday.com](http://monday.com) 管理它们的工作。十多年前公司刚成立时，其核心产品是一个帮助团队自动化工作流和管理项目的可视化界面。如今，它已从底层重新架构其产品，围绕一种人机协作模式，把 AI 编织进各个层面的工作中。以 Claude 为核心，monday 的新平台承担技术复杂性，让客户能在他们已经熟悉的工作流内部，站在 AI 前沿工作。

monday.com 首席产品与技术官 Daniel Lereya 表示：「向 agent 优先产品的转变，是我们作为公司所做的最重要的决定之一。它意味着从根本上重新设想平台应该做什么，而不仅仅是在现有工作流上加装 AI。我们的愿景是让 monday 成为人与 AI agent 无缝协作的地方，而 Anthropic 和 Claude 一直是帮助我们实现这一愿景的可信伙伴。」

## 撞上「AI 尘埃」的天花板

monday 的重建分三个阶段展开。第一阶段，随着前沿 LLM 技术成熟、客户热情高涨，monday 各团队致力于把 AI 能力嵌入其原有平台。这一努力在 2025 年 5 月达到高潮，公司内部办了「AI 月」，用四周时间在全公司范围交付 AI 功能或产品。

采用强劲并引发了热情，但很快团队就撞了墙。monday.com AI Works Platform 产品副总裁 Orly Stern Izhaki 说：「我们在做『AI 尘埃』——把自动化撒到现有工作流上，却没有把它们嵌入产品之内、也没有改变产品的根本价值主张。我们的功能帮助用户总结文本、归类信息，但它们并没有创造持续的使用模式。」

公司需要把重心从「给产品功能添加 AI」转向「把 AI 原生地构建进平台」。Izhaki 说：「采用 AI 功能，并不等于成为一家 AI 公司。一旦我们理解了这一点，一切都变了。」

就这样，Izhaki 的团队着手彻底重新想象 monday：从一个工作管理工具，变成一个人与 agent 共同完成工作的地方。虽然转型产品的指令来自高层，但把那颗北极星翻译成具体的产品决策、并构建他们自己的 agent，则落在每个团队、每位员工身上。

经过数月的高强度工作，公司宣布了其历史上最重大的变革——围绕人与 agent 协同工作重建整个产品体验，利用已经内建的上下文、工作流、看板、权限和治理。自 2026 年 5 月发布以来，monday 的客户已在其平台上与 agent 产生了超过 500 万次交互。

## **把 agent 当队友**

除了访问权限和限制，monday 的每个 agent 都被赋予一个名字和一个头像，同事们可以在 monday 平台里通过触发器和 @-提及把工作安排给 agent。

这一设计是刻意为之，针对的是 monday 在其客户群中注意到的一个模式：许多企业想让 AI 干活，却常常停滞在一个与它们实际工作场所平行运行的 AI 聊天框上。把 agent 直接嵌入工作流、让人们像与同事一样与它们互动，把 agentic AI 从一个抽象概念变成了一个具体、可执行的东西。

monday 为 agent 规划的工作，范围从 IT 工单分类和知识库维护，到候选人寻源和面试排期、面向销售和市场的竞争情报简报，以及诸如会议准备、把决策转化为可跟踪任务的「幕僚长」式工作。

## **在 monday 中运行 Claude 的四种方式**

客户通过四种能力在 monday 平台内部使用 Claude：

借助 **monday Agents**，团队可以用 prompt 构建自定义 agent，并选择 Claude 作为其模型。平台会给 agent 一个名字、一张脸，以及看板上一块人人都能给它派活的位置。

**自带 agent（Bring Your Own Agent，BYOA）** 让 Claude Managed Agents 能够加入平台。一旦进入 monday 平台，一个人构建的 agent 就能成为整个团队都能 @-提及、都能派活的队友。

**预置 Agent（Pre-built Agents）** 在 monday Agents Store 中提供，把 Claude 插件变成专门的队友：法务团队可以在自己的工作流内部作为一个 agent 运行一个法务插件，财务团队也能对各自的插件照此办理。

**Claude Coding 集成** 让团队在 monday 控制面板里连接 Claude，然后规划并把任务指派给 agent。Claude Managed Agents 在客户自己的环境中执行，结果和更新在任务移交给下一个 agent 或移交给人类审阅之前，落回到工单上。工作从业务需求一直跑到可用的代码，再回到业务用户手中。

## **不离开看板，从简报做到落地页**

一个端到端的例子：一个市场团队在单个看板条目内运营一条活动生产线。市场人员和内容负责人在该条目上打磨简报，就目标、受众、关键信息和渠道达成一致。一个用 monday Agents 构建的策略师 Agent 把这份原始输入转成一份结构化简报，涵盖活动目标、信息支柱、渠道拆解和成功指标。

随后，一个落地页构建器接手。它作为 Claude Managed Agents 运行在公司自己的环境中，拉取获批的简报，生成一份现有落地页的新变体，其文案、结构和信息都适配该活动。输出自动落回 monday 条目上。在页面进入审批之前，一个品牌审阅者——一个 Claude Managed Agent——对照品牌指南和法律标准检查它，并标记任何需要注意力的地方。市场经理随后只需做一个决定：发布还是打磨。

## **一家站在 AI 前沿的家族企业**

[Cooke](https://cookeseafood.com/) 是一家 1985 年创立于新不伦瑞克省布莱克斯港的家族海产企业，它已从一个只有 5,000 条三文鱼的单一养殖场，成长为全球最大家族拥有的海产公司，在 16 个国家运营。如今，Cooke 在 Claude 和 monday 之上共同运行项目交付、资源管理和合同管理。产品经理用 Claude 把获批的章程和需求转成初步项目计划、生成状态报告、并暴露会直接馈入其 monday RAID 日志的风险和问题，覆盖约 200 个进行中和拟议中的项目。Claude 自动化了那些维系跨 130 份合同全生命周期工作流准确性的报告和数据处理——这些是过去繁琐的手工维护工作。

Cooke 战略总监 Patti Stevens 表示：「monday 和 Claude 一起，帮助我们读懂团队产能、做出更聪明的分配决策。monday 过去是一个我们不得不去更新的平台。如今我们从中开展运营。」

## **monday.com 学到了什么**

对于计划类似重建的公司，monday 团队分享了它们把平台改造成 AI 优先产品时学到的五条教训：

- **心智模式比技术更难改变。** 人们天然想保护质量、持续改进已经管用的东西。让团队从「我们如何负责任地改进当前产品」转向「我们如何为一个不同的未来负责任地重建它」，比技术工作花了更长时间。
- **当一切都同时变化时，小团队走得更快。** 方向、UX、技术、定价、信任模型，以及公司对「好」自身的定义，全都同时处于变动之中。层层利益相关者会丢失那么多细节，但拥有清晰归属和快速决策权的小团队能紧贴这些细节。
- **采用与否，取决于信任，一如取决于能力。** 产品-市场契合取决于用户的信心，以及让 agent 进入工作实际完成方式的意愿。治理、权限、透明度和可靠性，决定了 agent 是止步于试点项目，还是迈入生产。
- **能力需要匹配的基础设施。** 当 agent 扎根于实时项目数据、团队历史和结构化工作流时，它们的表现会处于另一个层级；而在企业规模下，后端必须撑得住。在 agent 层之外，monday 还投资于 monday DB，让数据基础设施能够支撑跨组织运行的 agent 的数量、速度和复杂性。
- **建立在已经管用的东西之上。** monday 一直把自己描述为「人们组队推动业务成果的地方」，而 agent 优先的重建把这一承诺延伸给了新一类团队成员。人们仍然来到 monday 实现目标，不同的是，与他们并肩工作的某些成员如今是 agent。
