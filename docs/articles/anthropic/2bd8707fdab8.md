# 扩展 Cyber Verification Program

2026 年 10 月 6 日

我们推出 Cyber Verification Program（CVP）的一个全新扩展版本，它把更高级的网络攻击能力以及降低拦截强度的 classifier 开放给符合条件的安全从业者。该计划如今由三个访问层级构成，安全团队可以按自己的工作性质申请最合适的那一档。每一档都包含对我们最强模型的使用权限，包括 Claude Opus 5.5、Claude Sonnet 5.5、Claude Mythos 5.1，以及此后发布的新模型。有兴趣的客户可以在[这里申请](https://portal.anthropic.com/programs/cvp)。

网络安全天然具有双重用途：让安全团队发现并修复一个漏洞的同一套能力，也能帮助恶意攻击者去利用它。正因如此，我们的通用可得模型——例如 [Claude Opus 5.5](https://www.anthropic.com/claude-opus-5-5)、[Claude Fable 5.1](https://www.anthropic.com/claude-fable-and-mythos-5-1) 和 [Claude Sonnet 5.5](https://www.anthropic.com/claude-sonnet-5-5)——带有保守的网络安全防护，会拦截绝大多数网络类工作。这样做是为了限制恶意攻击者能用我们的模型造成的危害，同时我们也在持续努力降低安全编码场景里的误报。

但防守方同样需要拿到最好的工具和最强大的能力来保护自己的系统。过去六个月，我们通过两个项目提供受信任的访问：[Project Glasswing](https://www.anthropic.com/glasswing) 和 [CVP](https://support.claude.com/en/articles/14604842-real-time-cyber-safeguards-on-claude-opus-and-sonnet)。前者让一批负责保护最关键软件的组织用上了 Claude Mythos；后者让经过审核的安全团队在 Claude Opus 和 Claude Sonnet 模型上享有降低后的安全防护。

如今，我们把这两个项目合并为一个扩展后的方案，旨在让更多安全组织拿到保护自身系统所需的能力。

### 新的访问层级

更新后的访问层级按安全从业者网络工作的范围，向他们开放特定的模型能力。每一档都有不同的审核要求和安全控制。

**Defense Access** 面向防御性工作，包括安全运营中心（SOC）与事件响应任务、逆向分析恶意软件，以及分析和验证漏洞。符合条件的组织示例包括：正在守护自己拥有或维护的系统的企业、非营利组织、大学和政府机构的安全团队；任意规模的关键基础设施运营者，例如区域医院或市政公用事业；规模较小的安全公司；开源维护者；以及有漏洞报告记录的独立研究者。

我们预计许多从事防御性网络安全工作的组织都能符合这一档。我们力求在几天内回复申请。

**Red Team Access** 在上述防御用途之外，增加了经授权的渗透测试与红队演练。符合条件的组织示例包括：企业内部红队、政府红队，以及安全与渗透测试公司。这一档的组织只能对自己获得授权测试的系统开展对抗性测试，包括关键行业的 IT 系统。用户仍会对可能造成人身伤害或大规模混乱的操作遇到实时拦截，例如部署勒索软件、破坏物理系统，或对高风险安全系统做渗透测试。

由于更高的准入门槛和更严的安全控制，我们预计这一档的申请需要几周时间审核。在审核 Red Team Access 申请期间，符合条件的组织会先被纳入 Defense Access 档。目前这一档只面向组织；独立研究者不具备申请资格。

**Specialized Access** 的网络拦截最少，仅保留给一小批经过验证、且获准测试可能影响人们生命或扰乱市场的安全系统的组织，例如飞行运行系统、电网、电信网络、银行间转账基础设施和政府行政网络。

这一档目前由我们与美国政府协作，对每一个组织做深入审核。Project Glasswing 的现有成员将转入这一档，且无需为当前模型重新审批。

我们的通用可得模型仍可以继续用于代码审查、修复已知问题、在自有源码中查找漏洞以及安全告警的分诊等任务。

加入该计划的组织必须接受数据保留，以便我们监测网络滥用行为。当 [Enterprise Frontier Safeguards](https://www.anthropic.com/news/enterprise-frontier-safeguards)（EFS）——一套把零数据保留的隐私性与强安全防护结合起来的新方案——在今年晚些时候的秋季上线后，符合条件的组织将可以把数据存储在自己控制的云基础设施中。在 EFS 可用之前，已拥有 Claude Fable 5.1 或 Claude Mythos 5.1 零数据保留访问权限的组织，同样可以在 CVP 中使用零数据保留。要登记对 EFS 的兴趣，请[填写这份表单](https://claude.com/form/enterprise-frontier-safeguards)。

### 检验我们各层级的有效性

为了评估 CVP 防护的实际效果，我们把 Claude Opus 5.5 跑了一遍 CyScenarioBench——一项衡量模型能否在现实约束下规划并执行多阶段网络作战行动的评估——并针对不同的 CVP 层级调校了安全防护。由于这项评估涉及复杂的、交互式的进攻场景，我们预期 Claude 在通用可得模型和 Defense Access 档都会遇到大量拦截，而在 Red Team Access 与 Specialized Access 档不会遇到拦截。

在每个访问层级中，对 10 道 CyScenarioBench 题目各尝试五次，我们发现：

- 没有 CVP 访问权限时，每个任务在第一条 prompt 上就被拦截；
- 在 Defense Access 档，50 次试验中有 46 次在挑战过程中的某个节点被拦截，其余四个任务成功完成；
- 在 Red Team Access 档，没有发生任何拦截，Claude Opus 5.5 成功完成了 50 个任务中的 34 个——实际上等同于该模型在这项评估上不加任何安全防护时 67.6% 的成功率（可代表 Specialized Access）。

这些评估让我们有信心把更高级的网络能力安全地开放给更广泛的防守者，把我们从 Project Glasswing 开始的防御性工作进一步扩展。我们会持续打磨基于层级的 classifier。

在 CyScenarioBench 上，我们的防护在 Defense Access 档拦截了 Claude Opus 5.5 的 50 个任务中的 46 个；而 Claude Opus 5.5 的 Red Team Access 档没有拦截任何任务，并完成了 50 个中的 34 个——与不施加任何安全防护时的完成率相同。

## 把优势交给防守方

通过 Project Glasswing，我们发现 Claude Mythos 系列模型显著提升了组织识别自身系统漏洞的速度。通过该计划，我们的合作伙伴在 2026 年 4 月至 7 月间发现了至少 129,000 个已验证的软件漏洞。而通过我们自己的开源扫描工作，在 2026 年 4 月至 10 月间又发现了 5,500 个已验证的软件漏洞。在这些已验证的漏洞中，迄今有超过 33,000 个被评为 critical 或 high 严重级别。这很可能还是低估，因为它只基于 Glasswing 合作伙伴中一部分的调研数据。因此，我们预计真实影响至少还要高出五倍。

当被问到如果没有 Claude Mythos 系列模型、要找到同样数量的漏洞需要多久时，多家合作伙伴告诉我们，这些模型让他们发现漏洞的速度提前了数月乃至数年。阅读我们的合作伙伴 [Booz Allen 和 Comcast](https://claude.com/blog/how-comcast-booz-allen-use-claude-mythos-to-secure-their-codebases) 的经验分享。

这些结果代表该计划对第三方代码影响的下限，因为它们来自 33 份合作伙伴报告和 Anthropic 开源合作的部分数据。数据的局限在于各组织采取的分诊方式不同，且不到 50% 的合作伙伴披露了已修复的数量，通常是因为他们的修复仍在进行中，因此修复率被显著低估。

我们今天对 Cyber Verification Program 所做的改动，意在把 Project Glasswing 的影响扩展到多得多的网络防守者。我们也在继续开展保护开源软件和关键基础设施的工作。未来几周，我们会分享更多关于这项工作的内容，以及我们在持续为防守方建立持久优势过程中学到的东西。

## 申请访问

有兴趣的组织可以[在此申请 CVP](https://portal.anthropic.com/programs/cvp)。作为申请流程的一部分，我们会核验所有申请人，并要求提供相应访问层级所要求的安全控制证明。现有 CVP 成员在此前的模型上保持其当前设置，并会在更新后的计划中自动接受对 Claude Opus 5.5、Claude Sonnet 5.5 和 Claude Mythos 5.1 访问权限的评估。管理员需要按照[这些步骤](https://support.claude.com/en/articles/16764810-assign-a-program-to-workspaces-in-claude-console)把访问权限分配给具体的 workspace。

CVP 可在 Claude Platform、Google Cloud 的 Vertex AI 以及 Microsoft Foundry 上使用。在 Amazon Bedrock 上，CVP 仅对符合 [Enterprise Frontier Safeguards](https://www.anthropic.com/news/enterprise-frontier-safeguards) 条件的客户开放。

如果你的工作被拦截了，而你认为自己所在的层级本该允许，你可以[在此报告](https://claude.com/form/cyber-block-false-positive-report-cvp-rejection-appeal)。每个层级的完整详情见我们的 [Help Center](https://support.claude.com/en/articles/14604842-real-time-cyber-safeguards-on-claude-opus-and-sonnet)。
