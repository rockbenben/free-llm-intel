## 标记 Claude 的热门频道

我们采访的八家初创公司在 Slack 上使用 Claude Tag，但少数渠道一次又一次被认为是最佳起点。

## 01 Claude待命

设置示例：

渠道

`#on-call` `#alerts-ci` `#deploy-watch` `#support-escalations`

连接器

GitHub、GitLab、Sentry、dbt、PagerDuty、Linear、Datadog、Jira、Grafana、incident.io

线程和例程

事件响应、早上事件摘要、周一值班交接、每日健康状况摘要、每小时事件回顾

入门说明

@Claude 请记住此频道：监视警报并立即在其自己的线程中对每个警报进行分类。检查现有票证。首先查询数据，然后进行推理，并将验证的内容与推断的内容分开。如果是真的，请使用链接命名可能的根本原因，标记所有者，并仅在包含修复程序的情况下打开草稿 PR。如果不需要采取任何行动，请直接说出来。每次事件发生后，将您学到的内容添加到[课程文件]中。

分类渠道是出了名的吵闹。 Sentry 错误、Datadog 警报、客户错误报告和支持请求会不断造成干扰，因此很难从噪音中找到信号。这通常是团队交给Claude的第一个任务。

由于Claude在频道中作为第一响应者，第一遍通常是在值班工程师打开笔记本电脑之前完成的。Claude会在每个项目落地时阅读它，调查其代码库和它可以访问的工具，并分享它的发现。如果包含修复程序，则会打开 PR 草稿；如果没有，它会将问题转给合适的人并附上调查结果。在这些设置中，一个人会在合并之前检查每个修复，只有真正的新问题才需要有人自己开始调查。

在为财务团队构建人工智能原生 ERP 的 Campfire，一名工程师在一份报告中给 Claude 贴上了标签，称其人工智能代理的一些最终答案尚未到达用户手中。 21 分钟后，Claude 开了一个 PR，当天下午就合并了。

### Kikoff：每个分诊渠道的第一响应者

Kikoff 是一家金融科技初创公司，致力于帮助消费者建立信用、解决流动性需求并实现财务安全。 Claude Tag 是整个公司分诊渠道的第一响应者，包括：

- `#deploys`：Claude 决定每次发布后要观看的内容，并标记任何损坏的内容。
- `#alerts-ci`：当构建失败时，Claude 会找出原因并提出修复方案作为 PR 草案。
- `#alerts-sentry-backend`：Claude 首先处理 Sentry 异常和崩溃问题。
- `#dog-fooding`：Claude 调查员工在进行dogfooding 时标记的内容，并标记正确的所有者。
- `#support`：Claude率先获得支持票。

基科夫一开始就让Claude只在被提及时才参与对话，而当团队让它自己加入时，最大的胜利就来了。当注册失败时，Claude将其追溯到后端更改，评估了影响，指定了负责修复的团队，并创建了一份 PR 草案，以便应用程序在此期间会轻微失败。

Claude 标记注册已损坏，将其追溯到后端更改，评估影响，指定负责修复的团队，并打开草稿 PR，以便应用程序温和地失败。基科夫重现的对话。名称和图像已被修改。经 Kikoff 许可使用。

> “当 Claude 在监视器或人类之前发现问题时，我总是很兴奋。一个人只能亲自管理这么多的上下文，Claude Tag 帮助我们组织和拥有一些上下文，然后我们管理结果。”

Alex Dejeu，Kikoff 工程经理

### NavigateAI：修复碎片化上下文的错误

NavigateAI 为建筑现场团队打造人工智能副驾驶。他们在大约 90 个渠道中运行 Claude Tag，用于警报分类、错误修复、快速功能构建和支持升级。自 6 月以来，Claude 直接从 Slack 线程打开了大约 223 个 PR，并合并了 134 个 PR，从打开到合并的平均时间为两个小时。

分类是 NavigateAI 一个特别有价值的用例。因为 Claude 有如此多的背景信息，所以它可以找到乍一看可能被忽略的问题的不直观的根本原因。

> “我们与 Claude Tag 最大的‘哇！’时刻是当我们尝试调试负载问题时，该问题似乎是由客户引起的（因为他们的呼叫失败）。正常人的反应是继续追查该客户。但由于 Claude 可以访问许多其他数据源，它实际上发现它来自同一时间运行的未经检测的内部 cron 作业。”

Mike Chen，NavigateAI 工程主管

有了Claude，解决问题的平均时间得到了改善。在一个案例中，Claude 在 Sentry 警报发出 8 分钟后找到了根本原因，并在警报发出 93 分钟后合并了修复程序。

“快速发展的初创公司通常必须选择速度而不是结构。Claude·塔格为我们提供了两者。它是连接我们所有工具上的点的大脑，因此我们无需自己构建即可获得结构，”迈克说。

## 02 话题转公关

设置示例：

渠道

`#quick-wins` `#bug-bash` `#product-feedback` `#feature-requests` `#ux-papercuts` `#tech-debt` `#design-polish`

连接器

GitHub、GitLab、Linear、Jira、Confluence、Notion、Figma、Sentry

线程和例程

每个线程一个请求，每周积压清理，每日公关综述，每周发货回顾

入门说明

@Claude 请记住这个频道：当有人描述错误或小功能时，请在自己的线程中处理它。首先检查现有票证并阅读相关代码。如果缺少细节，请询问它们或提供真实的示例，而不是猜测。如果更改很小且包含在内，请打开一份 PR 草案，其中包含更改内容以及测试方式的简短摘要。绝不合并；一个人审查并批准。如果规模太大或风险太大，请说明原因并建议门票。

速度是初创公司最大的优势之一，但往往取悦用户的小请求可能会在混乱中迷失。情报通常由面向客户的团队收集，在 Slack 中提交，如果不被忽视，最终会到达 Linear 或 Jira，在那里它会优先于数百个其他票证。

有了 Claude Tag，任何人都可以起草 PR，无论是技术性的还是非技术性的。在线索中提出一个想法，在同一个地方获得来自产品、工程和 GTM 的实时反馈，Claude 将线索转化为反映每个人意见的 PR 草案。

我们采访的许多初创公司都使用 Claude Tag 来实现“轻松愉快”的功能，或者删除那些可以快速审查但不会被优先考虑的剪纸。

### 有序：两天内从 Slack 交换到生产功能

Orderful 是一个 EDI 平台，可通过 API 或直接通过浏览器将公司与其贸易伙伴连接起来。其客户通过该平台与其合作伙伴交易标准文件。

Orderful 的 Web 应用程序不支持一种文档类型 753。该请求已积压，一家大型零售商的发货被推迟。

当一位客户经理在 Slack 中跟进时，PM 给 Claude 加上了标签：“@Claude，你应该建立一个。” Claude 要求提供该文档的真实示例，以便它可以构建为实际格式，然后打开了一份 PR 草案，添加了 753 支持。

Claude 确认修复程序适用于真实的 753 交易。名称和图像已更改。经 Orderful 许可使用。

第二天早上，Claude为随附的 754 提交了一张罚单，这是零售商的回应，并开设了第二个 PR。两者都在 Slack 交换后大约两天投入生产。

Orderful 首席技术官 Piers MacDonald 表示：“之前需要花费数周或数月的时间才能完成 Slack 对话。” “过去，难以证明其价值的轻量级功能常常被积压。现在他们有了出路。”

### 价：从功能请求到推出

Valence 与全球最大的雇主合作，将企业人才和绩效与人工智能教练 Nadia 连接起来。当 Valence 工程师在 Slack 中解释如何解决重要客户要求的紧急产品变更时，Claude 不仅仅遵循指示，还确定了需要进行的其他更改，因为相同的配置存在于两个位置。如果没有Claude，最初的改变就不完整。

Claude指出，所请求的改变实际上是两个改变。经 Valence 许可使用。

> “它不仅同意专家的观点。它还发现了重复的配置，这是人类无法追踪的东西。”

Sameer Bansal，Valence 首席人工智能工程师

还有一个案例，客户紧急要求定制。Claude检查了代码，并与工程师合作，确认无需更改代码即可发货。不到一个小时，队友就为客户准备好了解决方案。

## 03 公司大脑

设置示例：

渠道

`#ask-anything` `#company-wiki` `#product-questions`

连接器

GitHub、Notion、Google Drive、Linear、Jira、Confluence、Granola、Metabase

线程和例程

每个线程一个问题、决策日志更新、每周陈旧文档检查、重复问题回顾

入门说明

@Claude 请记住此频道：回答我们的代码、文档和过去的线程中的问题，并链接您的来源。如果来源不同意，请检查代码，给出当前答案，并标记过时的文档。如果您不确定，请说出来并标记所有者。当线程做出决定时，将其记录在[文档位置]中。任何交给客户的东西都需要先进行人工检查。

在初创公司，机构知识通常存在于人们的头脑中，从复杂的产品计费代码到入职文档的托管位置。

对于我们采访过的许多初创公司来说，Claude·塔格（Claude Tag）已经成为公司的大脑。Claude回答了消息来源，并在不确定时标记了所有者。它还可以使知识保持最新状态：当线程做出决定时，Claude 可以在同一天将其记录在您的文档中，并标记已经过时的文档。

示例交换。

### Moritz：从招生到人员配置的实时真相来源

莫里茨是一家人工智能本土律师事务所，承诺当天就可以处理合同，而莫里茨所说的行业标准至少需要三周。与法律工作相关的一切，从接收和报价到人员配备和后续工作，都在 Slack 中进行，每个事务有一个线程，每个客户有一个渠道。

现在，从首席执行官到律师助理，每个人都会首先询问Claude。在 Slack 中搜索长达 30 分钟的问题只需不到两分钟即可得到解答。轮班结束时的更新现在是根据当天的线程起草的，从大约一个小时的组装变成了五分钟的编辑。

那时间又回到了法律工作。Claude·塔格（Claude Tag）处理案件周围的行政工作，例如后续问题、提醒和状态更新。它无法访问客户文件或与莫里茨律师的特权对话。

> “一家在 44 个国家/地区开展业务的公司每月会产生数百个一次性问题，而没有人会为其构建功能。Claude Tag 根据我们自己在 Slack 中的历史记录来回答这些问题。每个答案都是一条带有链接的线索，因此机构记忆会复合。”

Stefan Mandaric，Moritz 联合创始人兼首席技术官

### Campfire：按需客户体验

Slack 的一个渠道特别“受欢迎”：他们的 CX（或客户体验）渠道。销售人员使用此渠道“在潜在客户对话期间验证某些功能”，而不必“联系 10 个不同的人”。

这种类型的渠道特别有效，因为销售人员可以在客户关注的同时立即做出答复，并且可以在早期客户对话中更加独立和自信地运作。

> “Claude Tag 基本上充当了我们的中心知识库。”

Nancy Jin，Campfire 人工智能工程经理

## 04 自助数据

设置示例：

渠道

`#data-requests` `#ask-revops` `#metric-definitions`

连接器

dbt、GitHub、元数据库、BigQuery、雪花、Databricks、概念

线程和例程

每个线程一个问题、每周站立前读数、启动和实验读数、管道故障分类、新问题分类

入门说明

@Claude 请记住这个频道：来自我们的治理模型的答案以及[数据技能存储库]中的定义。如果那里没有涵盖数据，请说它未经验证，而不是猜测。先给出答案，然后给出数字、驱动因素以及任何注意事项。在解释更改之前，请检查最近的事件、版本和 Slack 讨论。如果某个指标的定义不清楚，请询问我们指的是哪一个。对于任何重要的事情，请在运行之前共享您的计划或 SQL。将您验证的内容与您假设的内容分开，并在答案末尾列出所有开放数据质量警告。如果有人发现错误，请起草修复方案供数据团队成员审核。如果一个问题出现两次，建议安排时间。

在快速发展的初创公司中，每个职能部门都需要数据，而数据团队必须决定谁的要求优先。通过 Claude Tag 连接到您的数据，任何人都可以用简单的英语提问，而无需在数据团队的队列中等待。

这也是我们采用的一个用例。 [在我们一个多月的数据渠道中，Claude Tag 回答了人们发布的超过 75% 的问题，通常在一两分钟内](https://claude.com/resources/articles/self-service-data-analytics-in-slack-how-anthropic-deploys-claude-tag-for-ad-hoc-questions)。它基于受监管的数据和分析师使用的相同定义，这些定义存在于Claude在每次对话中重新阅读的版本化存储库中。

来自 Slack 中的自助数据分析：Anthropic 如何部署 Claude Tag 来解决临时问题。

### 描述：响应临时数据请求

Descript 是一个人工智能驱动的视频编辑平台。 Claude Tag 现在是数据请求和初步分析的第一线支持者。产品、增长、RevOps 和财务在 Slack 中提出问题，并根据 Descript 的 dbt 模型获得答案。

> “我曾经编写复杂的 SQL，并每周或每月手动刷新数字。现在我已经用我自己的 Claude 工件替换了几个数据团队仪表板，并且我不再手动刷新它们。”

Daisy 张，Descript 增长营销主管

黛西的定期报告准备时间从几天缩短到几个小时。

例如，增长团队会询问生命周期订阅量下降的原因、付费搜索是否正在失去对其他渠道的最后接触信用，或者自助帐户需要多长时间才能成为企业机会。数据团队跟踪 Claude 生成的工件，以了解哪些数据资产在团队中最重要，并将自己的时间花在战略问题和构建使自助服务工作的环境上。

> “商业智能的承诺对于商业用户来说一直是自助式的。直到我们为 Claude Tag 建立了庞大的数据上下文之前，我从未见过它真正实现。”

Jen Huhn，Descript 货币化项目经理

### 有序：从问题到仪表板

在 Orderful，自助分析涵盖对话式分析和完整数据构建：任何人都可以从 Slack 中的问题转到合并到生产中的仪表板。关键是语义层对商定的定义和指标进行编码，因此每个答案和每个构建都使用相同的定义。

> “我们信任输出，因为语义层限制了 SQL，CI 控制了构建，并且有一个就定义达成一致的流程。如果没有这些，你就会得到看似自信的错误答案。一旦这些护栏就位，连接 Claude Tag 需要不到 30 分钟。现在，团队成员在共享 Slack 线程中一起构建，而不是单独会话。”

Piers MacDonald，Orderful 首席技术官

入门说明

@Claude 请记住此频道：从我们的线程、文档和数据中起草每个定期报告，并链接您的来源。领导改变的事情和需要做出决定的事情。将您验证的内容与您假设的内容分开，并标记任何缺失的内容，而不是填补空白。将草稿发布到其自己的线程中以供[所有者]编辑。在一个人批准之前什么都不会发生。如果报告不断得到相同的编辑，建议更新这些说明。

我们介绍的许多例子都是反应性的：Claude回应说，发生了一些事情。例行报告是Claude按计划负责的工作，就像队友负责重复交付的工作一样。

在 Claude Tag 中使用例程的示例。

您描述一次结果； Claude 每次都会运行它并在团队已经工作的地方发布结果。

### Valence：交易审核和交接

Valence 安排 Claude 在每次季度业务审查之前向团队通报客户健康状况、未完成的交易、阻碍因素和后续步骤。他们还致力于在交易完成时使从销售到客户成功的交接更加无缝。Claude通过帮助汇总整个参与过程中的详细信息来节省团队时间，并且经常找到他们可能错过的关键项目。

Sameer 表示：“当交易完成时，Tag 会根据交易历史记录、通话和合同进行交接：谁是谁、承诺了什么、定制内容以及尚未完成的内容。然后，客户成功部门会在开始之前对其进行审核。”

## 06 入门清单

下面的清单汇总了这些初创团队的最佳实践，以便您可以将它们应用到您自己的工作流程中。

发布前

检查先决条件。

Claude Tag 在 Claude Team 和 Enterprise 计划中处于公开测试版，并且不适用于 Free、Pro 或 Max。您需要一个 Claude 组织所有者和一个 Slack 工作区管理员来连接两者。管理员还必须打开例程，并且团队计划需要使用积分才能让 Claude 做出响应。

使用捆绑包设置Claude的访问权限。

在渠道中，Claude 以自己的[代理身份](https://claude.com/docs/claude-tag/concepts/agent-identity) 工作，使用服务帐户而不是任何人的个人登录。将所需的连接器、存储库和说明分组到[捆绑包](https://claude.com/docs/claude-tag/admins/add-connections)中，并将它们附加到组织范围内、每个工作区或每个通道。这设定了Claude在每个地方可以到达的范围，并且频道中的每个人都获得相同的访问权限。开始范围狭窄：仅满足第一个渠道的工作需要。

在私人频道中进行实验。

我们采访的初创公司中，近一半是通过在私人渠道中进行小型跨职能团队实验来开始他们的 Claude Tag 之旅的。 Sameer 说：“从混合角色的私人渠道开始，然后转向群组渠道。”

确定边界。

默认情况下，Slack 工作区中的任何人都可以使用 Claude，即使没有 Claude 帐户也是如此。您可以[限制对您的组织的访问](https://claude.com/docs/claude-tag/admins/restrict-access)，并将搜索限制为 Claude 所在的频道。在 Enterprise 上，您还可以限制对特定角色或所选频道的访问。

对Claude能做什么和不能做什么设定明确的期望。我们采访过的几个团队让 Claude 打开 PR 草案，但人们会进行审查和合并。对于 Orderful，[Claude Code](https://claude.com/resources/articles/claude-code-guide-for-startups)，而不是 Tag，处理“基础设施变更、审计、敏感数据”。对于“艰难的决定”，例如“涉及多个服务的公关”，Claude会获得第二意见。莫里茨不允许Claude·塔格查阅客户文件或与其律师进行特权对话。

尽早开始安全审查。

通常的问题是数据保留和 Claude 可以达到什么目的，[安全](https://claude.com/docs/claude-tag/concepts/security-and-data) 和 [数据生命周期](https://claude.com/docs/claude-tag/concepts/data-lifecycle) 页面回答了这两个问题。 Claude Tag 不适用于启用了零数据保留、客户管理加密 (CMEK) 策略或 HIPAA 配置的组织，并且它不在我们的业务伙伴协议的涵盖范围内，因此请在计划推出之前进行检查。

设置预算和警报。

Claude Tag 按使用量计费，因此随着使用量的增长，尽早进行对话可以避免出现意外。您可以使用 Enterprise Analytics API 按用户[设置总体支出限额](https://claude.com/docs/claude-tag/admins/set-spend-limit)、选择每个渠道的模型以及[属性成本](https://claude.com/docs/claude-tag/admins/attribute-costs)。 Orderful 运行组织范围内的警报上限，分别为 75% 和 90%。 “我们对渠道成本拥有极端的所有权。所有者证明，‘是的，这笔支出对于产出/结果来说是合理的，’”Kikoff 工程经理 Alex Dejeu 说道。使用第一个渠道的实际成本来确定下一个渠道的规模。

部署

在您的团队已使用的渠道中选择一项明确的任务，例如待命警报或错误分类。

“我们在某些团队中进行实验，看看哪些方法有效，然后一旦确信我们已经解决了问题，我们就会将这个想法推广给其他团队，以将其添加到他们自己的类似渠道中。我们希望避免与那些对人工智能错误容忍度较低的人发生信任破裂的经历，”Kikoff 的工程经理 Alex Dejeu 说。

培养您的专家和文化传承者。

让您的团队已经信任的人首先公开使用 Claude。

“与 Claude 公开交流非常高效且有趣。一些销售和客户成功部门的人员观看了专家 [与 Claude Tag 的互动]，然后开始询问 Claude 自己，并快速获得了价值，”Valence 首席人工智能工程师 Sameer Bansal 说道。

调整噪音。

多家初创公司告诉我们，他们需要调整Claude的健谈。太健谈是一种风险。

“临时请求中的对话有时会变得吵闹。我们一直在努力降低这里的响应能力，并且对我们在临时请求中使用 Claude 的内容更加有原则，”NavigateAI 工程主管 Mike Chen 说。

然而，闲聊太少也是一个风险。 Flagler Health 联合创始人 Will Hu 表示，在繁忙的频道中，“你要么每次都必须@，要么起不了多大作用。”而且“如果没有人密切关注某个频道或与其互动，它就会闲置。”

让队友连接他们自己的帐户。

Claude 可以为频道中的每个人提供设置中的管理捆绑包。 [个人连接器](https://claude.com/docs/claude-tag/concepts/personal-connectors) 的工作方式有所不同：Claude 会根据请求者的权限进行操作，因此一旦他们批准，它就可以从他们的文档、收件箱或 CRM 中提取（所有者首先为组织添加连接器，在 Enterprise 上由管理员管理个人连接器）。答案仍然发布在频道中，因此对于敏感内容请选择“允许审核”。

编写渠道说明，就像您在入职新员工一样：

首先检查什么，何时打开 PR，何时询问，以及“无需采取任何行动”是有效的答案。

在频道中而不是在私信中向Claude提供反馈。

在线程中更正它。它[记住每个频道](https://claude.com/docs/claude-tag/users/memory)，团队成员可以通过观看来学习如何使用它。要获得持久修复，请要求 Claude 更新该频道的内存。

两名 Valence 员工在看到一位同事与 Claude 公开讨论问题后向他们表示感谢。经 Valence 许可使用。

不确定下一步该去哪里？标记 Claude 并询问它对您的组织了解了什么以及它将扩展到哪些用例。

Moritz 的联合创始人兼首席技术官 Stefan Mandaric 请 Claude 为每个团队推荐用例。十五分钟后，它阅读了公司的 Slack 频道、线性问题、Notion SOP、Drive 和 Metabase 仪表板，并发布了 25 个。“25 个中的 18 个无需进一步设置即可工作。这成为我们的推出计划。”

## 最后一句话：我们从令人惊叹的时刻学到了什么

令人惊叹的时刻并不总是与速度有关。Claude经常发现一些没有人要求它寻找的东西。有时惊喜就是克制。有时令人惊讶的是意想不到的交流。 Orderful 首席技术官皮尔斯·麦克唐纳 (Piers MacDonald) 表示：“最终，你会习惯Claude插嘴讲笑话，并且你很快就会意识到，观众很轻松，而且是第一个发笑的人。”

在 Slack 中重新创建有序的对话。经 Orderful 许可使用。
