# Claude Sonnet 5.5

2026 年 9 月 28 日

我们推出 Claude Sonnet 5.5，这是 Claude 5.5 家族中的第二个模型。它相对 Claude Sonnet 5 是一次清晰的升级，运行速度快 30% 以上，而在多数工作上的成本低最多 30%。

Sonnet 5.5 是 Claude Opus 5.5 的更快、更低成本的补充。Opus 5.5 为需要审慎判断的复杂工作而生，Sonnet 5.5 则最擅长范围明确的日常任务、修 bug，以及制作精良的文档、幻灯片和电子表格。它对设计也有敏锐的眼光。为高吞吐、成本敏感的应用打造的 Claude Haiku 5.5 将在未来几周内加入 Claude 5.5 家族。

Sonnet 5.5 相比 Sonnet 5 在以下方面有所提升：

**性能。** Sonnet 5.5 在 Terminal-Bench 4.0（一项智能体编程评测）上得到 70.6%，而 Sonnet 5 是 10.3%。在 GDPval-AA——一项考察多种职业真实工作的测试——上，它比 Opus 5.5 低两分。它在长周期工作和图像理解上都很强，是第一个仅凭截图就打通《Pokémon Red》的 Sonnet 模型。

**协作。** 和 Opus 5.5 一样，Sonnet 5.5 的写作比我们上一代模型更清晰；早期测试者称它是比 Sonnet 5 更好的协作伙伴。它的速度也让它非常适合在复杂度较低的任务上做快速迭代。

**成本。** Sonnet 5.5 的定价与 Sonnet 5 相同：每百万输入 token 2 美元、每百万输出 token 10 美元，缓存读取每百万 token 0.20 美元，但完成同样的工作通常需要少得多的 token。在我们的测试中，它每个任务的成本比前代低最多 30%。

**速度。** Sonnet 5.5 生成输出的速度比 Sonnet 5 快 30% 以上，是我们迄今为止最快的 Sonnet 模型。

**对齐与安全。** 在我们的自动化行为审计中，Sonnet 5.5 在多数对齐指标上优于或持平 Sonnet 5。由于它的网络安全能力与 Opus 5 相当，它是第一个带着我们为能力最强的模型所开发的那类网络安全防护与回退机制上线的 Sonnet 模型。它的生物学防护与 Sonnet 5 相同。两类防护都只针对一小类高风险请求；常规软件开发和多数生命科学工作不受影响。

## 编程

Sonnet 5.5 的性能跃升在编程上尤其明显。在 FrontierCode 的 High effort 档位上，它比同一设置下的 Sonnet 5 高出 10 分，而每任务成本约为后者的十五分之一。在 CursorBench（用取自真实 Cursor 编程会话的任务来测试模型）上，它的最好成绩与 Opus 5.5 相差在约两分以内。

早期测试者很欣赏 Sonnet 5.5 理解一个代码库的速度。他们也对它的效率印象深刻：在一对一的对比运行中，它比 Sonnet 5 更多地把 tool call 批量合在一起，从而带来更少的步骤和更低的成本。

## 知识工作

Sonnet 5.5 在知识工作的多个领域都有提升。在 GDPval-AA（用横跨 44 种职业、九大行业的真实世界任务来测试模型）上，Sonnet 5.5 的得分几乎与 Opus 5.5 持平，比 Sonnet 5 高约 400 分。它在计算机使用和图表识别上接近 Opus 5.5，在长周期知识工作上明显胜过 Sonnet 5 和 GPT-6 Sol。

早期测试者强调了那些不易量化的改进。他们觉得它是更自然的对话伙伴，并提到它对设计的天分，指出它会给用户界面增添打磨，也能照着幻灯片模板做出几乎不需要修改的演示文稿。在一次内部测试中，我们把一家上市公司的季度财报材料和电话会纪要，连同一份幻灯片模板交给它，要求做一份 10 页的经营复盘。两位专家评审它的初稿可以直接原样发出。

## 安全

### 对齐

Sonnet 5.5 并没有推进我们模型能力的边界，所以我们的对齐评估聚焦在一组适用于任何能力层级模型的针对性风险上，包括违背用户利益行事、误导用户，以及配合高风险的滥用行为。

在我们的自动化行为审计（在约 1,850 个场景下测试 Claude）中，Sonnet 5.5 在对齐、抗滥用与诚实的多数指标上优于或持平 Sonnet 5。在我们更新的 containment 评测中，Sonnet 5.5 尝试逃出沙盒的频率之低接近 Opus 5.5——那是我们测过的最好的模型——而它探测自己容器边界的倾向是我们所有模型里最低的。就整场审计而言，Opus 5.5 总体仍略好一点，但我们没有发现 Sonnet 5.5 追求与用户意图相冲突的目标的证据。

正如我们在[最近的对齐评估](https://www.anthropic.com/research/alignment-assessment-cybersecurity-incidents)中所说，没有任何一套评测能可靠地抓住每一次失效，Sonnet 5.5 也可能带着我们尚未发现的倾向，这正是我们把自身的对齐工作与下面所述防护配套使用的原因。

### 防护

**网络安全。** Sonnet 5.5 的网络能力比 Sonnet 5 有大步提升，所以我们为它部署了与 Opus 5.5 类似的防护。用户仍然可以在常规软件开发中发现并修复自己代码里的 bug，但更高风险的网络安全任务会明显回退到 Sonnet 5。很快，网络安全防御者可以申请加入我们扩容后的 [Cyber Verification Program](https://support.claude.com/en/articles/14604842-real-time-cyber-safeguards-on-claude-opus-and-sonnet)，为 Sonnet 5.5、Opus 5.5 和 Claude Mythos 模型分级获取更高级的能力。

**生物学。** Sonnet 5.5 使用与 Sonnet 5 相同的一套生物学防护。这些防护针对有害请求；多数研究、教育与临床工作不受影响，尽管某些微生物学与病毒学的请求可能被误判拦截。机构可以申请加入我们的 [Life Sciences Verification Program](https://www.anthropic.com/news/life-sciences-verification-program)，获得为生物学相关工作全部范围所设计的防护。

**蒸馏。** 蒸馏攻击指攻击者用数千个虚假账号以工业规模抽取一个模型的能力，让不良行为者能在缺少我们为 Claude 内建那些防护的情况下造出高能力模型。由于 Sonnet 5.5 比它的前代能力强得多，它是第一个带着阻止推理抽取的安全分类器上线的 Sonnet 模型。Sonnet 5.5 还扩展了 [preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking)，因此 Claude 的思考无法与创建它的账号解绑。多数开发者不会察觉变化。如果你在账号之间搬移对话，包括在 Claude Code 里中途切换账号，我们的[文档文章](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking)解释了这一变化。

## 开始使用

与 Opus 5.5 和 Sonnet 5 一样，Claude Sonnet 5.5 可以零数据保留地提供服务。

Claude Sonnet 5.5 现已在所有平台可用，包括 Amazon Web Services、Google Cloud 和 Microsoft Azure。开发者可以在 Claude Platform 上用 `claude-sonnet-5-5` 开始。如果你以 thinking 关闭的方式运行 Sonnet，需要先切换到新的 `between_tools` 设置——它会让前置思考保持关闭——然后再迁到 Sonnet 5.5。细节见我们的[迁移指南](https://platform.claude.com/docs/en/models/sonnet-5-5/migration-guide#turn-thinking-off)。
