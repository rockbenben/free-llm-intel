# 推出 Claude Opus 5

2026 年 7 月 24 日

Claude Opus 5 今天可用。它是一个深思熟虑、主动积极的模型，以一半的价格逼近 Claude Fable 5 的前沿智能。

在像 [Frontier-Bench](https://www.frontierbench.ai/) 和 [GDPval-AA](https://artificialanalysis.ai/evaluations/gdpval-aa) 这样的编程与知识工作评测上，Opus 5 是新的 state-of-the-art，不过在网络安全任务上它仍落后于 Mythos 5。

Opus 5 是为每天使用而设计的：它比其他模型更高效地工作。它是 Claude Max 上新的默认模型，也是 Claude Pro 上最强的模型。

## 性能与成本效益

Claude Opus 5 在与前代 Opus 4.8 相同的成本下，提供了大幅改进的性能。本节的图表展示性能如何随模型的 effort 设置变化，客户可以用它来为智能做优化，或为更快更便宜的结果而节省 token。

Opus 5 在高价值的软件工程任务上表现出色。例如，在 **Frontier-Bench v0.1** 上，Opus 5 超越所有其他模型，并在更低每任务成本下把 Opus 4.8 的性能翻了一倍多。在 **CursorBench 3.2** 上、max effort 下，该模型的表现落在 Fable 5 峰值分数的 0.5% 之内，而每任务成本只有一半；它在 high、xhigh 和 max effort 上，也在给定成本下取得了比所有其他模型更高的性能。

我们在知识工作和问题求解任务上看到类似结果。例如：

- 在 **ARC-AGI 3** 上——一个模型必须解决新颖问题的评测——Opus 5 的分数是次优模型的三倍高。
- 在 **Zapier AutomationBench** 上——它衡量模型能否从头到尾完成业务任务——Opus 5 在相同每任务成本下的通过率约为次优模型的 1.5×。即便在最低的 effort 设置下，Opus 5 通过的任务也比任何其他模型多。
- 在 **OSWorld 2.0** 上——一个计算机使用基准——Opus 5 在任何给定成本下都胜过每一个其他模型，以仅略超三分之一的成本超越了 Fable 5 的最佳结果。

它在若干相关评测上也是我们最好、最省成本的模型：

Opus 5 相对 Opus 4.8 在科学研究上是一次有意义的改进。在我们每一项生命科学评测上——涵盖结构生物学、有机化学和生物信息学等主题——它都比 Opus 4.8 表现更好。它的改进在有机化学任务上最显著，比如从光谱数据推断分子结构（在我们的内部基准上它比 Opus 4.8 高 10.2 个百分点），以及在蛋白质相关任务上，比如预测蛋白质序列的变化如何影响它的功能（这里它高 7.7 个百分点）。

## 与 Claude Opus 5 协作

Claude Opus 5 在验证自己的工作、并仔细迭代直到成功这方面强得多。在评测和早期访问测试中，我们和我们的用户发现了许多 Opus 5 自主性与细致度的例子：

- 在一个 Frontier-Bench 任务上，Opus 5 得到一张机器零件的图，被要求写代码把它重建为 3D FreeCAD 模型。然而在这个任务里，模型被刻意地不给直接 *查看* 那张图的办法。Opus 5 的回应是写它自己的计算机视觉流水线，从原始像素里抽出几何、然后重建出整个机器零件。它反复做到了这点；配备同样设置的竞争模型在五次尝试后没有一个能解决它。
- 给定一个流行开源包管理器里的真实 bug，Opus 5 找到根本原因、并修了一个社区的补丁漏掉的边界情形。一个竞争模型只修了表面症状（而非底层原因），然后报告 bug 已解决。
- 一家交易公司的工程师用 Opus 5 在单个会话里为一个新交易所构建了一个市场数据源。先前的模型根本无法完成这个任务，哪怕给了工程师详尽的计划。在找不到可对照验证的实时数据源时，Opus 5 甚至构建了它自己的测试装置，来检查它的代码是否正确解析了交易所的数据。

下面是我们早期访问客户关于与 Opus 5 协作体验的更多反馈：

> 在 FrontierCode 1.1 上，Claude Opus 5 以一半的成本逼近 Fable 级的性能。在 Devin 内部，它在困难的调试和根因分析任务上也展现出特别的强项。

> Claude Opus 5 以 Opus 的速度和成本交付接近 Fable 5 的智能。在 CursorBench 上它仅次于 Fable 5，并带有许多同样的行为。我们很兴奋看到开发者在 Cursor 里如何使用它。

> Claude Opus 5 登顶 Zapier 的 AutomationBench 排行榜，且没有比先前的 Claude 模型花更多 token。它拿一份原始的账户健康工作簿、端到端跑完了一个完整的客户流失预防序列：标记有风险的账户、提醒正确的 owner、并为留存运营做总结。先前的模型没过；Opus 5 达到了 100%。

> 在我们的基因组学分析工作上，Claude Opus 5 表现得更像一个谨慎的科学家，胜过我们跑过的任何模型。它会伸手取用正确的统计检验来排除混淆因素、用独立方法交叉核对它自己的结果，并在长长的多步分析中保持在正轨上。

> Claude Opus 5 在我们内部评测上领先于它那个系列里的每一个模型。它不只是在我们最难的智能体编程任务上更好——比 Opus 4.7 高 22%——它更稳，逐次运行之间的方差小得多。对 Lovable 上数以百万计的构建者来说，这种一致性就是全部的关键。可靠的产出，一次构建接一次构建。

> Claude Opus 5 是 Opus 系列自 4.5 以来最大的飞跃。在同样的全栈应用构建上，前端最先显示出它：这是我们见过 Opus 模型里最好的动画、游戏和 3D 作品。

> 我们很喜欢 Claude Opus 5。对我们智能体处理的那种开放式分析工作，它相对 Opus 4.8 是一次严格升级，而收益恰恰在最重要的地方最大：更难、更模糊的任务。响应更清晰、更简洁，我们也在更高的 effort 级别上看到效率提升。

> Claude Opus 5 对我们分析师每天运行的金融研究工作流，是一次相对 Opus 4.8 显著的改进。它在数值推理、表格处理，以及在精确要紧之处更锐利的批判性思维上脱颖而出。

> Claude Opus 5 交付了分析专业化企业内容所必需的行业智能与准确性。Box 发现 Opus 5 比 Opus 4.8 高出 8%，并在数据分析（改进 11%）和尽职调查（改进 17%）工作流上带来显著的性能收益——这些正是技术、医疗和公共部门组织每天依赖的。

> Claude Opus 5 是相对 Opus 4.8 一次清晰的代际跨越。一个周末，我给了它一个对我开发环境行使幕僚长职责的角色：它自己建了一个监控器、驱动每一台机器，只在需要判断时把我拉进来。

> Claude Opus 5 在我们的基础研究助手代码库上做了大规模改动，在整个智能体工作流中适应反馈，并比我们使用过的任何模型都更清楚地解释它的推理。它承接了我们通常会拆成更小块的工作。

> 在我们一些最难的金融建模任务上，Claude Opus 5 相对 Opus 4.8 在准确性和效率上都是清晰的一步提升。它的表现底线实质更高，尤其在深度金融领域逻辑上。跨各 effort 级别，它平均准确率高 9 个百分点，而少三分之一的轮次和工具调用、少 60% 的时间。

> Claude Opus 5 像一个真正的前端开发者那样检查自己的工作。在我们的基准上，它在桌面和手机宽度下于浏览器里打开它的页面，抓到一个藏在移动端首屏之下的产品和一个屏幕外的结账按钮，并在交回工作前把两者都修好。

> Claude Opus 5 在法律智能体工作上相对先前的 Opus 模型是一次清晰的性能提升，我们在公司治理和仲裁这样的实践领域看到了最大的收益。我们也对 Opus 5 在更低推理级别保持质量的能力印象深刻——它达到相似性能，而相比在 max reasoning 下的 Opus 4.8 平均少生成 26% 的 token。

> Claude Opus 5 对我们最大的收益在更长时段的工作上：构建一整份 deck，然后修订它。产物的质量是决定我们上线哪个模型的东西，而这是我们见过的最清晰的一步提升——更好的视觉理解、更干净的格式、更少的幻灯片问题。

> Claude Opus 5 的判断力是它的出众之处。交接一个 PR 时，它不急着发布：它验证分支、检查模板、并想清楚测试的含义，好让交接干净。较旧的模型倾向抢跑、结果被我们的检查逮住。

> 在一次重构会话中，Claude Opus 5 反驳了我提出的一个设计，而在我坚持时它也没有屈服。相反，它准确解释了我在想法里有价值的地方、把它的反对收窄到一个单一的设计问题、并提出了一个既保留好的部分、又修掉缺陷的折中方案。这种判断力正是让我们能少些监督地信任它的那种。

> 在首轮红线批注上，Claude Opus 5 在我们测试的模型里得分最高，几乎是 Opus 4.8 的两倍。评论也更好：在 NDA 上，它用更少时间和更少的趟次到达红线，而准确性保持或更好。

> Claude Opus 5 写干净、紧凑的 diff、没有死代码，而且在微妙的、代码库特定的问题上它是更强的危险发现者。我们要为生产工作负载采用它。

> 我们一定要把一系列用例迁移到我们统一的智能体平台 Cosmos 上。我们期待越来越多地用 Claude Opus 5 做代码评审，而我有信心说：我们更希望大家用 Opus 5 而非 Opus 4.8。

> Claude Opus 5 出众的是判断力。它在下笔一行代码之前想得更深、在规划阶段而非事后就逮住它自己的逻辑漏洞、并推理一个答案为什么对、而不只是它管不管用。这是我们见过的从一个 Claude 模型到下一个最清晰的一次问题求解飞跃，我们期待看到它在 JetBrains IDE 里被采用。

> Claude Opus 5 是我们在我们交易基准上测试过的最强 Opus 模型，而它达到那里大约只用 Opus 4.8 七分之一的推理 token 和不到一半的延迟。用一小部分算力换来更好的答案。

> Claude Opus 5 让监控智能体在生产中管理它们自己的部分记忆，使它们在更长的时段上更自主、更可靠。这个智能体把它的上下文当作一份活文档：在我们某项服务里标记出一个潜在异常后，它把它的假设对照生产重新核对了一遍、发现那个信号是无害的、把这个纠正写进了它的记忆，并自己撤销了它的监控查询。

> Claude Opus 5 是一个为长时间、多步工作而构建的强大智能体编程模型。它深入理解你的代码库、在复杂任务中保持主线，并比 Opus 4.8 更有效果地为功能开发和 bug 修复确定需求。开发者如今可以在 Kiro 里用 Opus 5 构建，访问它的先进能力来攻克雄心勃勃的项目。

## 对齐与安全

*对齐。* 在部署前测试中，我们的自动化行为审计发现 Opus 5 是我们迄今对齐最好的模型（如下方图表所示）。它比 Opus 4.8、Sonnet 5 或 Fable 5 更贴合 [Claude 宪法](https://www.anthropic.com/constitution)；表现出的欺骗行为率最低；也最不容易被诱骗去滥用。在避免可能有难以逆转副作用的鲁莽行动方面，它也是我们迄今最安全的模型。

在我们的自动化行为审计上，Opus 5 在整体失对齐行为上得分 2.3，是我们近期模型里最低的。

*安全。* Opus 5 没有推进危险、双用途能力的前沿。在与私营部门和政府伙伴一起进行的严格评估中，我们发现它在生物学研究和攻击性网络安全两方面都仍落后于 Mythos 5。关于这些评估的更多信息见我们的 [System Card](https://www.anthropic.com/claude-opus-5-system-card)。

和它的前代 Opus 4.8 一样，我们有意避免在网络任务上训练 Opus 5。模型因变得普遍更能干，在这些任务上仍然有实质改进，并在 *发现* 网络安全漏洞上逼近 Mythos 5。然而它在那些漏洞的 *利用* 上——也就是把漏洞变成实质性网络威胁——仍大幅落后于 Mythos 5。

Opus 5 在 OSS-Fuzz 上的表现说明了这点，这是我们开发来评估模型能在多大程度上不经大量人类指导就找到、然后利用漏洞的一项评测。尽管 Mythos 5 和 Opus 5 以相近的成功识别漏洞，Opus 5 在开发利用程序上的分数远落后于 Mythos 5。

在我们的网络安全评测之一 OSS-Fuzz 上，Opus 5 在识别软件漏洞上接近 Mythos 5（左），但在为它们开发利用程序上要明显不那么成功（右）。

## **Opus 5 的保障措施**

Claude Opus 5 的保障措辞被设计为允许模型在网络安全和生物学两方面的有益用途。它们与我们应用到 Opus 4.8 的相似，只除了在一小窄范围网络任务上更强的护栏。

*网络安全。* Opus 5 的网络分类器比 Fable 5 上的按比例不那么限制性的。它们允许 Opus 5 在源代码里发现漏洞，但阻止"基于二进制"的漏洞扫描（一个更可能与恶意行为者相关联的方法）、渗透测试和利用程序生成。

基于我们的测试，我们预计这些分类器干预的频率比它们对 Fable 5 少约 85%。在 [Claude.ai](http://claude.ai/redirect/website.v1.5d872901-4bfc-4fc1-8c50-421524a24eb3)、Claude Code 和 Claude Cowork 里，任何被标记的请求默认会回退到 Opus 4.8。对 Opus 4.8 的回退也能在 API 上启用。

我们的 [Cyber Verification Program](https://support.claude.com/en/articles/14604842-real-time-cyber-safeguards-on-claude-opus-and-sonnet)（CVP）促成本否则会被模型保障措施阻碍的网络安全工作。已经在 CVP 中的企业和研究人员，可即时访问一个安全限制更少的 Opus 5 版本。

*生物学。* 由于 Opus 5 有一整套与 Opus 4.8 相似的保障措施，它如今是我们面向普遍可用的、最强的科学研究模型。尽管如此，模型在长时间、自主的研究任务上仍显示出重要的局限，而这正是我们预期 AI 模型带来最实质性生物学风险的地方。（对这类生物学工作，Mythos 5 仍是更强的模型。）作为本次发布的一部分，在 Fable 5 上被阻止的生物学相关请求，现在会路由到 Opus 5 而非 Opus 4.8。

## **开始上手**

Claude Opus 5 今天在所有平台上可用，定价为每百万输入 token $5、每百万输出 token $25（与 Opus 4.8 相同）。开发者可以在 Claude API 上开始使用 claude-opus-5。

它以 Fast 模式提供，在该模式下它跑得约两倍默认速度的 2.5 倍。和 Opus 4.8 一样，Fast 模式在 Claude Platform 上以 Opus 5 基础价的两倍提供、也通过 Claude Code 里的额度使用。

伴随 Opus 5，我们发布两项 beta 更新：

- **[Claude Platform 上的会话中途工具变更](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-system-messages)。** 在一次会话内，开发者现在可以改变 Claude 能使用哪些工具，而不使 prompt 缓存失效。
- **[API 上的自动回退](https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback#server-side-fallback)。** 用户现在可以选择让那些在 Opus 5（或 Fable 5）上被我们安全分类器标记的请求自动路由到另一个模型。开启自动回退后，API 请求默认总是路由到最佳可用模型，而不是被阻止。

与先前的 Opus 模型一致，Opus 5 对普遍访问没有数据保留要求。

关于如何把 Opus 5 用到最好的更多指导，见我们的 [提示词指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5)。
