Claude Opus 5.5 现在是 Claude 在 Pro、Max、Ultra 和 Team 计划中的默认模型。我们建议把它作为知识工作的日常主力模型，也就是当你用 Claude 做研究、分析，以及撰写或制作备忘录、报告、电子表格和演示文稿时，一直选着的那个模型。

如果你或团队一直用 Sonnet 干日常活、把 Opus 留给繁重的分析或复杂项目，现在值得重新掂量：更强的模型能用更少的功夫把任务做完，这[往往能抵掉它每 token 更高的一大半价格](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)。

当前几款模型的对比如下：

| **模型** | **适用场景** | **每百万 token 价格（输入 / 输出）*** | **相对速度** |
| --- | --- | --- | --- |
| Claude Haiku 5.5 | 快速查询，以及速度优先的大批量工作 | $0.10 / $0.50 | 最快 |
| Claude Sonnet 5.5 | 范围明确、要求清晰的任务，以及据明确要求产出的精修文档、幻灯片和电子表格 | $2 / $10 | 快 |
| Claude Opus 5.5 | 大多数知识工作：研究、分析，以及需要判断力的成品文档、演示文稿和电子表格 | $4 / $20 | 中等 |
| Claude Fable 5.2 | 最宏大、开放式的技术工作，如编程、金融和科学等领域 | $8 / $40 | 中等 |

**价格针对按 token 计费的用量（[模型对比](https://platform.claude.com/docs/en/models/opus-5-5/overview)）。Haiku 5.5 的价格适用于不超过 100k token 的 prompt，更长的 prompt 按 $0.50 / $2.50 计费。在 Pro、Max、Ultra 和 Team 计划中，价格更高的模型会更快消耗额度。除限时首发优惠外，Pro 计划以及 Team 和按席位计费的 Enterprise 计划的标准席位，其额度不包含 Fable 5.2，因此它按用量积分计费。*

[**Haiku 5.5**](https://www.anthropic.com/claude-haiku-5-5) 是我们最快、也最便宜的模型，专为快速查询和撰写摘要、整理数据这类大批量工作打造。这是首款带 effort 控制的 Haiku 模型，因此你可以在切换到更大模型之前，先要求它更仔细地过一遍。它最适合短小、范围窄的任务；需要更长的分析，就换用 Opus 5.5。

[**Sonnet 5.5**](https://www.anthropic.com/claude-sonnet-5-5) 在范围明确、要求清晰的任务上比 Opus 5.5 更快也更便宜，比如让 Claude 把定稿的笔记整理成精修文档，或套用幻灯片模板做一份演示文稿。不过在更高的 effort 档位下，Sonnet 5.5 的单任务成本会逼近 Opus 5.5；所以如果你发现自己在把 Sonnet 推到 Extra high 或 Max effort，不妨换用 Opus 5.5。

**[Opus 5.5](https://www.anthropic.com/claude-opus-5-5) **专为需要审慎判断的复杂工作打造，比如研究、财务分析，以及产出成品文档、演示文稿和电子表格。后文会详细说明我们为何推荐用 Opus 5.5 承担日常知识工作。

[**Fable 5.2**](https://www.anthropic.com/claude-fable-and-mythos-5-2) 最适合最吃力的推理和长时间运行的任务，比如深入的多步研究，或可以交给一大群连续跑上数小时的 subagent 去做的编程。大多数知识工作，先用 Opus 5.5；等项目的范围和复杂度确实需要时，再转到 Fable 5.2。Fable 5.2 在所有付费计划中都可用，不过[它如何计入你的用量](https://support.claude.com/en/articles/15424964-claude-fable-models-on-your-plan)取决于具体计划。

无论当前用的是哪个模型，如果 Claude 表现不如预期，先试更高的 effort，再考虑换更大的模型。如果它已掌握上下文、明显认真做过，却仍然做错，那就换更大的模型。

## **Opus 5.5 在文档、研究、财务和图表上表现最出色**

Opus 5.5 精确遵循指令、不越出范围，因此它产出的电子表格、幻灯片和文档往往几乎不用再改。它对待数字和来源也很谨慎。在一项内部研究测试中，Opus 5.5 仅凭一份存档的网页快照，撰写某公司的季度业绩报告，而快照里该公司的财报发布很难找到。自动评分器逐一核对报告里每个数字和引文与快照页面的对应关系，规则是：只要凭空捏造哪怕一个数字或一句引文，报告即判不合格。跨各 effort 档位，18 份报告有 16 份通过。

它的文笔也比早期模型更清晰：把最重要的信息放在最前面，少用行话，遵守你给的写作规范；在较长的任务里，还会直说它做了什么、发现了什么、还需要你提供什么。这也让它的成果更容易核查，我们既把这看作实用上的好处，也看作安全上的好处。

Ramp 的资深软件工程师 John Ruelas [说](https://www.anthropic.com/claude-opus-5-5)："它写起来像一位靠谱的同事，也遵守我们的写作规范。一份设计说明书出来后几乎不用改就能用；它重写我们的一条 prompt 时，我甚至更喜欢它的版本，胜过我自己写的。"

财务分析是它的另一项强项。Opus 5.5 能准确读取信息密集的申报文件、财务模型和图表，并在整个项目或交易中保持上下文连贯。在另一项内部测试里，它分析两家虚构 HR 软件公司之间的拟议合并：先在 Excel 里搭出财务模型，再据此做成一份给高管看的演示文稿，判断按该价格这笔交易是否划算。整个任务用时 63 分钟，而 Opus 5 做同一任务要 93 分钟；成本只有一半，模型却更完整，演示文稿也更好读。

投资公司 Walleye Capital 中央股票量化研究工程负责人 Frank Corrao [表示](https://www.anthropic.com/claude-opus-5-5)，在较高的 effort 档位下，Opus 5.5"发现我们自己指令里的分钟索引差了一位，主动做了修正，还指出这会让它在评分器那里丢分。它是对的，此前我们测过的模型没有一个发现并处理过这个问题。"

Opus 5.5 是我们在视觉能力上最强的 Opus 模型。它能准确读取信息密集的文档、图表、截图和示意图，因此从文档里提取数据很可靠。即便设在最低 effort 档，它从密集图表中读数的准确度也高于 Opus 5 设在最高档时。

## **充分发挥 Opus 5.5**

每出一个新模型，都值得重新试一遍你交给 Claude 的东西，并丢掉为旧模型养成的提示习惯。

### **先试这些任务**

- **直接要成品文件。** 想要电子表格或文档，就直说要电子表格或文档，别只要一份供展开的大纲。多数情况下，Opus 5.5 能从你的请求一步做到成品文件。
- **让它核查长文档。** 丢给它一份长计划、报告或演示文稿，让它找错和前后矛盾。长文档里容易漏看的细节，Opus 5.5 能揪出来，比如演示文稿里某张图表与源数据对不上。
- **交给它一个研究问题。** 提一个没有标准答案的问题，让它汇集资料、啃完长文档，再把发现写成备忘录、报告或演示文稿。
- **试试视觉类工作。** 视觉能力上的提升也延续到了设计，不妨用它做界面原型、搭网站，或把一个概念画出来。

![Claude Opus 5.5 的任务示意](https://assets.claude.com/43af7ca2d9f20a0722825b0c207cd80af4d3fdab.png)

### **改掉这些提示习惯**

- **把 Claude 接到你的工作文件和系统。** 想让产出贴合你的工作，这是最有用的一步：Claude 能通过 connector 触达你的文件和系统时，就可以自己去取任务所需的东西，而不只依赖你粘贴进去的内容。在 Team 和 Enterprise 计划中，必须先由所有者开启 connector，成员才能使用。
- **在第一条消息里就说清"做完"是什么样。** 别一条一条地给 Claude 下指令，而是一次讲清目标、最终产出，以及希望它何时停下来问你。把又长又分多块的工作一路做到底，Opus 5.5 比 Opus 5 更稳。
- **删掉"think hard"和"think carefully"。** Opus 5.5 的思考始终开启，会根据你的请求和 effort 档位决定想多少。在我们的测试里，去掉这两行后回复起步更快，质量也没有明显下降。
- **从 Medium 档开始。** Medium 是 Opus 5.5 的默认档；在我们的编程和知识工作评测中，Medium 档的 Opus 5.5 追平或超过了 High 档的 Opus 5。更高的档位想得更久、花钱更多，却不一定产出更好，所以等 Medium 卡住了再升到 High。要改档位，点发送按钮旁边的模型名称，选择 Effort。
- **直接附上图表，别重敲一遍。** 把图表、截图或示意图本身发过去，而不是把里面的数字抄进 prompt。为早期模型准备的变通办法，比如把图表数值誊写出来，可能已经用不上了。
- **点名你不想要的风格。** 做设计工作时，"避免千篇一律的外观"这类笼统指令，往往只是把一种默认风格换成另一种。点出具体要避开的样式更管用，比如米色背景或药丸形按钮。
- **把自家规范给它。** 把品牌或写作规范贴进请求里，或让 Claude 去看你做得最好的几份现成演示文稿——比如放在它能通过 connector 访问的 Google Drive 文件夹里——再让它照着来。要做好几轮才完全到位的准备。

![Claude Opus 5.5 提示习惯示意](https://assets.claude.com/d61fa79e1e1a38bd6ad4547ddb66c993ef569705.png)

这一关于 effort 的结论，在早期测试者那里也成立。Factory 的技术团队成员 Zimu Li [说](https://www.anthropic.com/claude-opus-5-5)："Claude Opus 5.5 是我们第一个会默认设在 medium effort 的模型。在我们的测试中，它追平了设在 high effort 的 Opus 5，而输出 token 少了 20% 到 25%。"

## **在一个演示项目上测试 Opus 5.5**

上面这些，放到我们在一次演示里走完的项目中是什么样子？设想一家零售公司，过去一年营收增长放缓，管理层对原因有四种猜测，分析师手里有一文件夹材料：各门店销售电子表格、最近一次管理层外出会议的 PDF，以及其他文件。用设在 Medium 档的 Opus 5.5 时，prompt 大致是：

`Growth slowed a lot this year. Leadership has a couple of theories about why; they're in [my manager's] note. Everything I have is in the uploaded folder. Please test each of the four theories against the data and tell me which ones hold up.`

这段 prompt 没叫 Claude "think hard"，也没说查哪种理论该看哪个文件。它只讲清目标和最终产出的样子，把做法留给 Claude。

Claude 发现数据并不支持这四种猜测中的任何一种，不过有一种无法完全排除。接着它提出了一个没人提过的解释：新店开得离老店太近，把老店的生意分走了。按城市列门店时，这个规律还不太看得清；一旦按与新店的距离筛选，就清楚了。Claude 用销售影响对该距离做回归，为这一发现提供了依据。

随后，Claude 把分析整理成一份文档，正文之外还带图表和交互元素，其中有一个滑块，展示销售额随新店与老店之间距离变化的走势。一位同事同时审阅了这份文档。

接着，经理让 Claude 把文档做成董事会幻灯片，开头就给出结论。对于不用 Claude 的同事，文档可导出为 Word、PDF 或 Google Docs，演示文稿可导出为 PowerPoint、PDF 或 Google Slides。

想看完整项目（含问答），可[点播观看 Opus 5.5 for Work 场次](https://claude.com/resources/webinars/opus-5-5-for-work)。

## **用自己的工作试试 Opus 5.5**

挑一件你平时会拆成好几次请求来做的事，比如研究备忘录、差异分析，或根据现成文档做一份演示文稿。把文件和最终成果的描述放在一条消息里交给 Opus 5.5，档位留在 Medium，再把结果和你习惯从其他模型拿到的作个对比。
