# 预告模型硬件标准

2026 年 8 月 27 日

我们正为第一批科研实验室和先进制造商，开放模型硬件标准（Model Hardware Standard，MHS）的研究预览——这是一份让 AI agent 安全操作物理设备的共享规范。MHS 让 AI agent 能并行操作多台实验室和制造仪器，例如显微镜、液体处理机和机械臂，并执行从常规药物发现实验、到量子计算机激光校准等各类精细任务。MHS 的开发始于 Anthropic 与 [HHMI Janelia 研究园区](https://www.hhmi.org/research/janelia) 之间的合作。

一个实验室或制造车间，通常要花数周乃至数月来设置并集成它们的硬件。多数设备彼此不通信，反而需要专家去构建定制的集成。MHS 把这项集成工作缩减到几小时或几分钟。而且通过把这些工具与 AI 结合，MHS 还能帮助研究者和工程师更从容地编排自主、全天候的实验与工作流——agent 能对实验的每一步进行推理、实时更新参数，在某些情况下还能在无人干预下从硬件错误中恢复。

我们正在与横跨科学、机器人、电子和制造领域的伙伴分享 MHS 的一个早期版本，以便我们协作构建安全评测、并为操作物理设备的 AI 系统制定最佳实践——赶在把这个标准开源之前。MHS 适用于任何有可编程接口的设备。它也是模型无关的，任何 agent harness 都能用标准协议访问它，比如 [Model Context Protocol](https://www.anthropic.com/news/model-context-protocol)。要申请研究预览的访问权，[请到此处](https://www.modelhardwarestandard.com/)。

## MHS 如何运作

模型硬件标准（MHS）之前与之后的对比。

让实验室里或工厂车间上的多台设备彼此通信可能很有挑战，即便暂且不提把 AI 集成进这套配置的额外难度。每台设备往往有它自己的编程接口，而到目前为止还没有集成它们的标准方法。而且一旦设备*被*连起来，也没有一种通用方式让它们与一个 AI agent 共享数据，或让 agent 安全地操作它们。

MHS 通过引入一个标准化的驱动来解决这些挑战：驱动是在计算机操作系统和一个硬件设备之间做翻译的软件。MHS 驱动使用一组简单的原语——像「read」（例如「获取温度」）或「write」（例如「设置温度」）这样的指令——任何硬件设备都能理解并据此行动。它还让每台设备以一个标准格式可被发现，从而使设备和 agent 能通过网络找到彼此、相互通信，而不需要在中间夹一个定制的「翻译器」程序。

MHS 驱动还帮助一个 AI agent 理解如何使用一台它从未见过的设备，给出那些单靠代码或许无法从代码中辨明的机器特性信息（例如一台机械臂的重量——这对知道如何安全地操纵它很重要）。迄今为止，其中很多信息一直保存在纸质手册里、在用户的计算机上，或作为默会知识。但 MHS 驱动含有标签，让用户能直接用自然语言写下这些信息（用户可以亲自动手，或通过和一个 agent 聊天、让它就其硬件配置访谈他们）。有了这些标签的信息，MHS 驱动随后会自动生成一份参考文件，里面有关于设备一般特性的信息，例如它能测量什么、能调整什么、以及会强制执行哪些安全限制。这份文件给出 agent 操作设备所需知道的一切。

在设备连接好、agent 知道如何使用每一台之后，agent 需要一种方法来控制硬件。对 MHS 来说，有三种这样的机制：MCP、命令行界面，和代码文件（API）。它们协同工作，通过一行代码就实现跨多台设备的编排。

一旦 agent 能控制设备，它就能从每台设备接收运行数据，并在高层监督和指挥工作。agent 能在各仪器间排布步骤的顺序、监控结果，并随着条件实时变化调整参数。当 agent 需要执行长时间运行的任务、或以超出其在线推理所允许的速度操作设备时，它可以在代码文件里把一个或多个设备的驱动指令串接起来。这让设备自己执行操作，而 agent 无需在每一步都推理。

在我们测试 MHS 的过程中，我们发现 Claude 以一种探索性的方式与实验和硬件交互，就像一位科学家那样。例如，我们观察到 Claude 对一台激光器做一处调整、通过相机观察结果以评估它的调整如何让激光束移动，并重复这一过程、寻求理解事件发生的顺序。随后 Claude 把它学到的东西打包成代码文件，写了一个确定性的脚本，让它无需在每一步推理就能对准激光，从而整个过程能作为单条命令运行。

## 来自 MHS 的早期范例

我们才刚刚开始看到人们能用前沿模型和 MHS 做什么，但我们的希望是：这份标准能在任何使用可编程接口设备的领域，帮助研究者、工程师和其他从业者加速发现与实验的过程。

在我们开发 MHS 的过程中，我们与生物科技、机器人、量子计算和其他领域的一小批实验室和硬件制造商分享了它。在这些早期项目中，我们目睹 MHS 缩短了集成设备所需的时间、使在各种实验环境中更快迭代成为可能，并协助机器的实时运行和实时故障检测。下面，我们的伙伴分享了他们一些涉及 MHS 的早期项目细节。

### Genentech：为实验室自动化实施 MHS

*Genentech 的研究者把 MHS 作为概念验证实施并测试，用来自动化 BCA 蛋白测定——一种测量样品总蛋白浓度的标准流程，它需要协调一台液体处理机、一台机械臂和一块酶标仪。*

### 华盛顿大学 Baker 与 Pinglay 实验室：把 AI agent 带到实验台

*华盛顿大学 Baker 与 Pinglay 实验室的博士生 Zihao Song 用 MHS 构建了一个仪表盘来远程监控他的仪器；一个由 AI agent 监督的 qPCR（通过反复的加热和冷却循环来复制目标 DNA 序列），它会观察扩增曲线并在恰当时机中止流程；以及一个机械臂与液体处理机之间、用于无碰撞板转移的集成。*

### 卡内基梅隆大学：通过快速自动化测定剂量-反应曲线

*卡内基梅隆大学的研究者用 MHS 运行系列稀释的剂量-反应实验，比之前大约快三倍——一个 AI agent 编排着一台液体处理机、一块酶标仪、一台机械臂，以及分布在接口根本互不兼容的三台计算机上的监控相机。*

### HHMI Janelia：用 MHS 加速显微镜研究

*在 HHMI Janelia 研究园区，研究者正用 MHS 加速一系列显微镜相关项目。这里，Ahrens 实验室研究睡眠如何帮助身体从压力中恢复的科学家 Virginie Ruetten，分享了她如何用 MHS 统一并编排一套原先涉及七个不同厂商程序、却没有共享接口的装置。*

### QuEra Computing：在量子激光稳频中使用 MHS

*QuEra——一家用中性原子构建量子计算机的公司——用 MHS 让一个 AI agent 控制其量子机器内部激光系统的部分。该 agent 开发了一个控制器，能在 99.3% 的情况下在无人干预时恢复激光的「锁定」——激光为与原子相互作用而必须保持的超高精确频率。*

### Tetsuwan Scientific：用 MHS 运行 qPCR 以剖析局部污染

*Tetsuwan 的研究者把 MHS 与其自动化生物实验室平台 ResearchOS 集成。MHS 帮助编排了一个 qPCR 工作流，以参与为加利福尼亚州圣佩德罗溪表征污染的公民科学努力。*

硬件厂商以及支持它们的软件公司，也在把它们设备中的 MHS 支持构建起来，好让 AI agent 更容易发现和操作它们的设备。例如：

- 亚马逊云科技（AWS）将通过 Strands Robots——那款把 AI agent 连到物理设备的库——支持 MHS。在 MHS 研究预览期间，AWS 会为参与者提供 Strands Robots 包的一个私有的、预发布版本。
- Automata 正在其实验室自动化平台 LINQ 中添加 MHS 支持，以对自主实验室里的仪器执行智能错误处理。
- 丹纳赫（Danaher）与 Anthropic 正积极探讨 MHS 支持的能力如何能让其智能仪器和自主实验室规模化生物医学研究与开发。
- 斗山机器人（Doosan Robotics）正在其机械臂上测试 MHS，包括用于执行自动化质量保证、以及协调跨多台机器人的任务。
- MBF Bioscience 正在为 ScanImage——这款在全球数百神经科学实验室运行激光扫描显微镜的软件——构建一个 MHS 驱动，以把 AI agent 集成进实时数据分析和实验。
- 凯杰（QIAGEN）正在通过一个其核酸纯化平台 QIAsymphony Connect 上工作着的概念验证来试验 MHS，展示 AI agent 如何能帮助实验室更快排查仪器问题、引导操作员完成恢复、并在降低生物样品风险的同时提升仪器在线率。
- 帝肯（Tecan）正在其 Fluent 液体处理平台上添加 MHS 支持，好让 AI agent 能直接发现并操作它们。
- 优傲机器人（Universal Robots）已获得 MHS 的早期访问，并计划在其机器人平台上添加支持。

## 加入研究预览

我们伙伴的这些早期成果令人鼓舞，但在我们把这份标准开源之前，还有更多工作要做。作为一个大语言模型，Claude 通过文本和图像了解物理世界，这意味着它的空间和物理推理存在仍需要专家监督的局限。例如在处理蛋白样品时，Genentech 的研究者不得不引导 Claude 认识到：由样品起泡造成的错误是物理故障，而非软件 bug，只能通过恰当的物理纠正来缓解。

MHS 目前也还无法与那些缺乏编程接口的硬件协作，因此我们正与此类设备的制造商合作、把 MHS 驱动构建进去。许多开发者已经用 Claude Code 与单台物理设备打交道；对 MHS 的下一阶段，我们希望把这份标准扩展到覆盖开发者赖以构建的更多设备。早期采用者包括 Hugging Face，他们正在其机器人库 LeRobot 中添加 MHS 支持；以及树莓派（Raspberry Pi），在使用其摄像头 MHS 驱动成功测试后，他们正跨多款产品启用 MHS 集成。

我们也会用研究预览来与发布伙伴构建额外的安全评测，并加强对物理世界中 AI 使用的保护。我们正在制定一份物理安全路线图，以进一步加固我们的防护政策，和针对滥用风险的执法覆盖。当我们开源 MHS 时，会发布研究预览的发现，作为我们安全部署这份标准指南的一部分。

我们邀请跨行业的利益相关者加入我们 MHS 研究预览的候补名单。如果你想参与，[在此提交你的意向](https://www.modelhardwarestandard.com/)。
