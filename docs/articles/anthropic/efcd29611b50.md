摩根大通正在全公司推广 Claude，把使用范围从工程师扩大到更多员工。在商业与投资银行部门，各项工作更快进入生产，腾出的产能被重新投向业务优先事项。

各团队在对其余遗留系统做现代化改造，工程师也在搭建自己的 agent，包括 pull request 审查 agent 和自愈 agent，并把行之有效的方法分享出来。

基础设施与运维团队用 [Claude Code](https://claude.com/product/claude-code) 做监控、告警和根因分析。公司的安全团队则借助我们的前沿模型更快地发现并修复漏洞——这项工作我们最早在 [Project Glasswing](https://www.anthropic.com/glasswing) 中介绍过。

## **触达产品团队与顾问**

离业务最近的人也在用 Claude 构建东西。产品团队把需求直接转成工程 backlog，其他团队用 Claude Code 做风险与控制评估、项目规划。

知识类工作已经展开。产品开发生命周期里很大一部分发生在代码之外：调研、需求、设计和规划。

在资产与财富管理业务中，摩根大通把业务洞察最深、想法最大胆的人，与技术专家、产品专家编进规模不大却充分授权的小团队。这让他们更容易大规模构建并交付定制化的客户投资方案。Claude Code 如今已是他们工程工作流的一部分，团队推进得更快，同时每一项变更在交付客户前都要经过更严格的测试。

上个月，J.P. Morgan Asset Management 发布了一款 connector，把 55ip 的 ActiveTax Technology® 接入 [Claude for Financial Advisors](https://claude.com/resources/articles/claude-for-financial-advisors)，让兼顾税务因素的组合迁移分析进入顾问的日常工作。

## **为受监管的机构而建**

Claude Code 运行在受控环境中，包括公司自有基础设施上的容器化开发平台 Devspace。这样设计是为了防止 agent 直接接触员工凭据或内部系统。使用范围分阶段放开，新的 Claude 模型必须先通过公司自己的审批流程，员工才用得上。

代码上线也守同一套规矩。数千项自动化测试和审批关卡会检查每一次变更，自动化关卡给出非此即彼的「放行」或「中止」，由流水线强制执行，因此 Claude 没法给自己的工作签字放行。每一次生产变更仍由人负责。

过去一年，摩根大通对 Claude 的使用从软件工程延伸到网络防御，再到面向财务顾问的工具；他们向我们提出的需求，也正在塑造我们为其他受监管机构构建的产品。让 Claude 在全球最大金融机构之一既有的管控框架内运转，正是我们努力的方向。
