# 桌面扩展：为 Claude Desktop 一键安装 MCP 服务器

发布于 2025 年 6 月 26 日

桌面扩展让安装 MCP 服务器简单到只需点一个按钮。我们分享技术架构和创建优质扩展的技巧。

- 文件扩展名更新 2025 年 9 月 11 日：Claude Desktop 扩展现在使用 .mcpb（MCP Bundle）文件扩展名，而非 .dxt。现有的 .dxt 扩展会继续工作，但我们建议开发者今后对新扩展使用 .mcpb。所有功能保持不变——这纯粹是一次命名约定的更新。

—

去年我们发布 Model Context Protocol（MCP）时，我们看到开发者构建了出色的本地服务器，让 Claude 能访问从文件系统到数据库的一切。但我们不断听到同样的反馈：安装太复杂。用户需要开发工具、得手动编辑配置文件，还常常卡在依赖问题上。

今天，我们推出桌面扩展——一种新的打包格式，让安装 MCP 服务器简单到只需点一个按钮。

### 应对 MCP 安装难题

本地 MCP 服务器为 Claude Desktop 用户解锁强大能力。它们能与本地应用交互、访问私有数据、并与开发工具集成——同时把数据留在用户机器上。然而，当前的安装流程制造了重大障碍：

- **需要开发工具**：用户需要装 Node.js、Python 或其他运行时
- **手动配置**：每个服务器都要编辑 JSON 配置文件
- **依赖管理**：用户必须解决包冲突和版本不匹配
- **没有发现机制**：找有用的 MCP 服务器需要去 GitHub 上搜
- **更新复杂**：让服务器保持最新意味着手动重装

这些摩擦点意味着，MCP 服务器尽管强大，对非技术用户仍基本不可及。

### 推出桌面扩展

桌面扩展（`.mcpb` 文件）通过把整个 MCP 服务器——连同所有依赖——打包进单个可安装包，来解决这些问题。对用户而言，变化如下：

**之前：**

```
# Install Node.js first 
npm install -g @example/mcp-server 
# Edit ~/.claude/claude_desktop_config.json manually 
# Restart Claude Desktop 
# Hope it works
```

**之后：**

- 下载一个 `.mcpb` 文件
- 双击用 Claude Desktop 打开
- 点「Install」

就这样。没有终端、没有配置文件、没有依赖冲突。

## 架构概览

一个桌面扩展是一个 zip 归档，包含本地 MCP 服务器以及一个 `manifest.json`，后者描述 Claude Desktop 和其他支持桌面扩展的应用所需要知道的一切。

```
extension.mcpb (ZIP archive)
├── manifest.json         # Extension metadata and configuration
├── server/               # MCP server implementation
│   └── [server files]    
├── dependencies/         # All required packages/libraries
└── icon.png             # Optional: Extension icon

# Example: Node.js Extension
extension.mcpb
├── manifest.json         # Required: Extension metadata and configuration
├── server/               # Server files
│   └── index.js          # Main entry point
├── node_modules/         # Bundled dependencies
├── package.json          # Optional: NPM package definition
└── icon.png              # Optional: Extension icon

# Example: Python Extension
extension.mcpb (ZIP file)
├── manifest.json         # Required: Extension metadata and configuration
├── server/               # Server files
│   ├── main.py           # Main entry point
│   └── utils.py          # Additional modules
├── lib/                  # Bundled Python packages
├── requirements.txt      # Optional: Python dependencies list
└── icon.png              # Optional: Extension icon
```

桌面扩展里唯一必需的文件是一个 manifest.json。Claude Desktop 处理所有复杂性：

- **内建运行时**：我们随 Claude Desktop 附带 Node.js，消除外部依赖
- **自动更新**：扩展在新版本可用时自动更新
- **安全的密钥**：像 API 密钥这样的敏感配置存在 OS 钥匙串里

manifest 包含人类可读的信息（如名称、描述或作者）、一份功能声明（工具、prompt）、用户配置，以及运行时要求。多数字段是可选的，所以最简版本相当短，尽管在实践中我们预期所有三种受支持的扩展类型（Node.js、Python 和经典二进制/可执行文件）都会包含文件：

```
{
  "mcpb_version": "0.1",                    // MCPB spec version this manifest conforms to
  "name": "my-extension",                   // Machine-readable name (used for CLI, APIs)
  "version": "1.0.0",                       // Semantic version of your extension
  "description": "A simple MCP extension",  // Brief description of what the extension does
  "author": {                               // Author information (required)
    "name": "Extension Author"              // Author's name (required field)
  },
  "server": {                               // Server configuration (required)
    "type": "node",                         // Server type: "node", "python", or "binary"
    "entry_point": "server/index.js",       // Path to the main server file
    "mcp_config": {                         // MCP server configuration
      "command": "node",                    // Command to run the server
      "args": [                             // Arguments passed to the command
        "${__dirname}/server/index.js"      // ${__dirname} is replaced with the extension's directory
      ]                              
    }
  }
}
```

[manifest 规范里](https://github.com/anthropics/dxt/blob/main/MANIFEST.md)有若干便利选项，旨在让本地 MCP 服务器的安装和配置更容易。服务器配置对象的定义方式，既为以模板字面量形式的用户自定义配置留出空间，也为按平台的覆盖留出空间。扩展开发者可以详细地定义他们想从用户那里收集什么样的配置。

我们看一个 manifest 如何协助配置的具体例子。在下面的 manifest 里，开发者声明用户需要提供一个 `api_key`。Claude 在用户供应该值之前不会启用扩展、会自动把它操作系统的秘密库里、并在启动服务器时透明地把 `${user_config.api_key}` 替换成用户提供的值。类似地，`${__dirname}` 会被替换成扩展解包目录的完整路径。

```
{
  "mcpb_version": "0.1",
  "name": "my-extension",
  "version": "1.0.0",
  "description": "A simple MCP extension",
  "author": {
    "name": "Extension Author"
  },
  "server": {
    "type": "node",
    "entry_point": "server/index.js",
    "mcp_config": {
      "command": "node",
      "args": ["${__dirname}/server/index.js"],
      "env": {
        "API_KEY": "${user_config.api_key}"
      }
    }
  },
  "user_config": {
    "api_key": {
      "type": "string",
      "title": "API Key",
      "description": "Your API key for authentication",
      "sensitive": true,
      "required": true
    }
  }
}
```

### 构建你的第一个扩展

我们走一遍把一个现有 MCP 服务器打包成桌面扩展。我们用一个简单的文件系统服务器作示例。

#### 第 1 步：创建 manifest

首先，为你的服务器初始化一个 manifest：

```
npx @anthropic-ai/mcpb init
```

这个交互式工具就你的服务器提问，并生成一个完整的 manifest.json。如果你想快速抵达最基本的 manifest.json，可以带一个 --yes 参数运行该命令。

#### 第 2 步：处理用户配置

如果你的服务器需要用户输入（如 API 密钥或允许的目录），在 manifest 里声明它：

```
"user_config": {
  "allowed_directories": {
    "type": "directory",
    "title": "Allowed Directories",
    "description": "Directories the server can access",
    "multiple": true,
    "required": true,
    "default": ["${HOME}/Documents"]
  }
}
```

Claude Desktop 会：

- 展示一个用户友好的配置界面
- 在启用扩展前校验输入
- 安全地存储敏感值
- 根据你的开发者配置，作为参数或环境变量把配置传给服务器

在下面的例子中，我们把用户配置作为环境变量传入，但它也可以是一个参数。

```
"server": {
   "type": "node",
   "entry_point": "server/index.js",
   "mcp_config": {
   "command": "node",
   "args": ["${__dirname}/server/index.js"],
   "env": {
      "ALLOWED_DIRECTORIES": "${user_config.allowed_directories}"
   }
   }
}
```

#### 第 3 步：打包扩展

把一切打包进一个 `.mcpb` 文件：

```
npx @anthropic-ai/mcpb pack
```

这条命令：

- 校验你的 manifest
- 生成 `.mcpb` 归档

#### 第 4 步：本地测试

把你的 `.mcpb` 文件拖进 Claude Desktop 的设置窗口。你会看到：

- 关于你扩展的人类可读信息
- 所需的权限和配置
- 一个简单的「Install」按钮

### 高级特性

#### 跨平台支持

扩展能适应不同的操作系统：

```
"server": {
  "type": "node",
  "entry_point": "server/index.js",
  "mcp_config": {
    "command": "node",
    "args": ["${__dirname}/server/index.js"],
    "platforms": {
      "win32": {
        "command": "node.exe",
        "env": {
          "TEMP_DIR": "${TEMP}"
        }
      },
      "darwin": {
        "env": {
          "TEMP_DIR": "${TMPDIR}"
        }
      }
    }
  }
}
```

#### 动态配置

用模板字面量表示运行时值：

- `${__dirname}`：扩展的安装目录
- `${user_config.key}`：用户提供的配置
- `${HOME}, ${TEMP}`：系统环境变量

#### 功能声明

帮助用户事先理解能力：

```
"tools": [
  {
    "name": "read_file",
    "description": "Read contents of a file"
  }
],
"prompts": [
  {
    "name": "code_review",
    "description": "Review code for best practices",
    "arguments": ["file_path"]
  }
]
```

### 构建一个开放的生态

我们致力于围绕 MCP 服务器的开放生态，并相信它被多个应用和服务普遍采纳的能力惠及了社区。本着这一承诺，我们把桌面扩展规范、工具链、以及 macOS 和 Windows 版 Claude 用来实现其自身桌面扩展支持的 schema 和关键函数开源。我们希望 MCPB 格式不只是让本地 MCP 服务器对 Claude 更可移植，也对其他 AI 桌面应用如此。

我们开源：

- 完整的 MCPB 规范
- 打包与校验工具
- 参考实现代码
- TypeScript 类型和 schema

这意味着：

- **对 MCP 服务器开发者**：打包一次，在任何支持 MCPB 的地方运行
- **对应用开发者**：添加扩展支持，而无需从零构建
- **对用户**：在所有支持 MCP 的应用上一致的体验

规范和工具链刻意以 0.1 版本发布，因为我们期待与更广泛的社区一起演进和更改这一格式。我们期待你的声音。

### 安全与企业考量

我们理解扩展引入了新的安全考量，对企业尤甚。我们在桌面扩展的预览版里内建了若干防护：

#### 对用户

- 敏感数据留在 OS 钥匙串
- 自动更新
- 能够审计装了哪些扩展

#### 对企业

- 支持组策略（Windows）和 MDM（macOS）
- 能够预装获批准的扩展
- 把特定扩展或发布者列入黑名单
- 完全禁用扩展目录
- 部署私有的扩展目录

关于如何在你的组织内管理扩展的更多信息，见我们的[文档](https://support.anthropic.com/en/articles/10949351-getting-started-with-model-context-protocol-mcp-on-claude-for-desktop)。

### 如何开始

准备好构建你自己的扩展了吗？以下是起步方式：

**对 MCP 服务器开发者**：查看我们的[开发者文档](https://github.com/anthropics/dxt)——或干脆在你本地 MCP 服务器的目录里运行以下命令直接上手：

```
npm install -g @anthropic-ai/mcpb
mcpb init
mcpb pack
```

**对 Claude Desktop 用户**：更新到最新版，并在设置里找到扩展（Extensions）板块

**对企业**：查看我们的企业文档了解部署选项

### 用 Claude Code 构建

在 Anthropic 内部，我们发现 Claude 很擅长以极少的干预来构建扩展。如果你也想用 Claude Code，我们建议你简要说明你想让你的扩展做什么，然后把以下上下文加进 prompt：

```
I want to build this as a Desktop Extension, abbreviated as "MCPB". Please follow these steps:

1. **Read the specifications thoroughly:**
   - https://github.com/anthropics/mcpb/blob/main/README.md - MCPB architecture overview, capabilities, and integration patterns
   - https://github.com/anthropics/mcpb/blob/main/MANIFEST.md - Complete extension manifest structure and field definitions
   - https://github.com/anthropics/mcpb/tree/main/examples - Reference implementations including a "Hello World" example

2. **Create a proper extension structure:**
   - Generate a valid manifest.json following the MANIFEST.md spec
   - Implement an MCP server using @modelcontextprotocol/sdk with proper tool definitions
   - Include proper error handling and timeout management

3. **Follow best development practices:**
   - Implement proper MCP protocol communication via stdio transport
   - Structure tools with clear schemas, validation, and consistent JSON responses
   - Make use of the fact that this extension will be running locally
   - Add appropriate logging and debugging capabilities
   - Include proper documentation and setup instructions

4. **Test considerations:**
   - Validate that all tool calls return properly structured responses
   - Verify manifest loads correctly and host integration works

Generate complete, production-ready code that can be immediately tested. Focus on defensive programming, clear error messages, and following the exact
MCPB specifications to ensure compatibility with the ecosystem.
```

### 结论

桌面扩展代表着用户与本地 AI 工具交互方式的一次根本转变。通过移除安装摩擦，我们让强大的 MCP 服务器对所有人——而不仅是开发者——变得可及。

在内部，我们用桌面扩展来分享高度实验性的 MCP 服务器——有的有趣、有的有用。有一个团队做了实验，看我们的模型在被直接连到一台 GameBoy 时能走多远，类似我们的[「Claude 玩宝可梦」研究](https://www.anthropic.com/news/visible-extended-thinking)。我们用桌面扩展打包了一个扩展，它打开流行的 [PyBoy](https://github.com/Baekalfen/PyBoy) GameBoy 模拟器、让 Claude 接管操控。我们相信，把模型的能力与用户本地机器上已有的工具、数据和应用连接起来，存在着数不尽的机会。
