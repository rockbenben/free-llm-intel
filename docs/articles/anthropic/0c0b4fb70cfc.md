[Claude Duet](https://claude.com/resources/articles/claude-duet) 是一个智能体，目前处于研究预览阶段，它使用一台基于云端的计算机替你完成工作。它可以调用你选择接入 Claude 的所有应用与服务，而且即使你关闭应用，它仍会持续运行。它能在你离开时读取你的收件箱、起草回复、预订事务并运行例程。我们团队在自己的账户上运行 Claude Duet，每天都在用它工作。

我们基于三项原则构建 Claude Duet，用来指导这个智能体的行为：

- 你的信息，以及他人在你所连接的应用中分享的内容，都会被审慎处理——我们用一个全新的分类器，在 Claude Duet 起草的消息发出之前对其进行检查。
- 你始终掌控它代你执行的操作。
- Claude Duet 永远不会看到你的密码、浏览器 cookie、登录 token 或其他凭据。

Claude Duet 是新的，但它背后的思考并不新。2025 年，我们[发布了关于安全可信智能体的框架](https://www.anthropic.com/news/our-framework-for-developing-safe-and-trustworthy-agents)，该框架让人处于掌控位置，并将隐私与安全交互视为基本要求。此后，我们撰文说明了为什么[单一防御并不足够](https://www.anthropic.com/research/trustworthy-agents)，以及为什么[模型内部的防护无法独立成立](https://www.anthropic.com/engineering/how-we-contain-claude)。我们还通过 [Claude Managed Agents](https://www.anthropic.com/engineering/managed-agents) 构建并运营企业用来在生产环境中运行智能体的基础设施，而 Claude Duet 以同样的方式让凭据与智能体保持分离。它建立在这项工作之上，并补充了一个替你行动的智能体所需的防护。本文会逐一说明我们新增了什么，以及我们仍在努力解决的问题。

## 你批准重要操作

在你离开时行动的智能体，必须知道何时停下来征求许可，并以恰当的节奏这么做。在 Claude Duet 执行发送潜在敏感消息、付款或删除任何内容这类操作之前，它会向你展示该操作、目标位置和内容，包括每一位收件人。然后它会等待你批准该操作。

每一项操作旁边都会运行一项独立的自动检查，它基于 [Claude Code 的 auto mode 分类器](https://www.anthropic.com/engineering/claude-code-auto-mode) 构建，并为 Claude Duet 做了扩展。该检查会评估这项操作是否符合你的意图。检查在负责执行的模型之外运行，因此藏在页面里的指令无法影响结果。

有些操作即使得到你的批准也仍然被禁止，比如证券交易、在账户之间转移资金这类银行操作，以及访问他人的账户。另一些步骤则不受「别再问我」规则的覆盖，无论你批准过多少次，比如付款或汇款、删除订单、创建账户。你不在时运行的例程也遵循同样的防护。

我们花了大量时间校准 Claude Duet 请求批准的频率。审批疲劳是一个严重问题，因为请求太多会让人养成随手点过的习惯，有时并没有经过充分考虑。我们会随时间继续调整这一校准。

在购物场景中，Claude Duet 使用来自 Stripe 的 Link 这类钱包的一次性卡付款，且仅限该商户和该金额。你会看到商品和总额，并在 Link 应用里批准这笔购买。你的真实卡号不会共享给 Claude Duet 或商户。

图 1. 审批流程：审批卡与独立的检查都位于模型之外，因此智能体读取到的任何内容都无法替它对审批卡作答。

## 你的信息会被审慎处理

一个替你读取邮件并发送消息的智能体，无时无刻不在判断不同类型的信息该发往哪里。如果你让 Claude Duet 给团队发一份每周回顾，它应当只包含团队里每个人本来就有权访问的内容，而绝不应包含私人细节，比如你的绩效评估对话。

为解决这个问题，我们构建了一个新的安全分类器，它独立于主模型运行，检查 Claude Duet 即将发送的每条消息是否包含潜在敏感信息。我们把这类信息分为两个层级：

- **绝不共享：**我们对登录凭据、完整的卡号与银行账号、政府证件号码等信息给予最高级别的保护。Claude Duet 被要求绝不与任何人分享这些信息，即使你开口要求也不例外。
- **共享需经同意：**对于健康、财务等其他私密信息，只有在得到你明确批准后 Claude Duet 才会分享。你本人的请求即视为同意，因此「给我的牙医发条消息，说说我的牙疼」通常不需要额外批准。

图 2. 你的信息可以流向何处：在任何内容发出之前，检查都会权衡该信息的敏感程度，以及你是否已给出同意。

如果 Claude Duet 因上述任一原因被拦下，它可以决定改写这条消息、去掉敏感信息，再交给你批准后分享。

Claude Duet 仍处于研究预览阶段，这些防护偶尔会漏掉一些东西，或把一条无害的消息标记出来。正因如此，它们要与上面的审批机制配合工作——这些机制的设计目的，是让你掌控 Claude Duet 代你发送的内容。随着我们对人们如何使用 Claude Duet 的了解加深，我们会继续迭代这个分类器。

## 你可以看清任务与已连接的应用

你可以在任务列表里看到 Claude Duet 做过什么、正在做什么，每个任务都有自己的页面，你也可以在任务进行中引导它。Claude Duet 会保留你的对话历史和它的记忆，以便在不同任务之间携带上下文，直到你删除或重置历史记录。删除账户会清除 Claude Duet 存储的所有内容。

![Claude Duet 任务列表的截图](https://assets.claude.com/2ea9a7ae6dfe5a96c7e3e0fb759df5a0703704b1.png)

你连接到 Claude 的应用会延续到 Claude Duet，在一处关闭某个应用，两处都会关闭。断开某个应用的连接会从那一刻起停止新的访问，但 Claude Duet 已经从中了解到的东西会保留下来，直到你重置它的记忆——你随时可以在该应用的设置里重置。Claude Duet 还会使用你 Claude 账户中的记忆，因此 Claude 从你早前聊天中记住的细节是可见的。

## 凭据和浏览器与模型隔离

Claude Duet 永远看不到你的密码、浏览器 cookie，也看不到你已连接应用的登录 token，并且无法把它们保存进记忆。它们只会经过模型无法访问的独立机器，而约束 Claude Duet 行为的审批与安全检查也在那里运行。

**密码**

当某个网站要求输入密码时，你在 Claude 应用内的表单里键入它。该表单用一个一次性密钥加密它，这个密钥只存在于我们安全的云浏览器机器上，且仅用于这一次。它把加密后的密码以未解密状态交给浏览器，由浏览器把它键入网站。模型看不到这个密码，也无法保存或重复使用它。很快你还可以用 1Password 登录；Claude Duet 会请求一份凭据，你在 1Password 中批准该请求，凭据便会送到浏览器，全程不经过模型。

一个替你登录的智能体会以两种方式改变网络钓鱼的格局。一方面，Claude Duet 并不替你持有凭据，因此无法被钓走密码，任何隐藏指令也无法让它泄露一个它根本没有的秘密。另一方面，登录表单本身就是一个攻击目标，因为任何索要密码的东西都可以被仿冒。所以 Claude Duet 的登录表单只会在你主动发起登录时、出现在应用内部。它绝不会以链接、短信、邮件或 claude.ai 以外网站的形式出现。如果有看似 Claude Duet 的东西在别处索要你的密码，那它不是正当的。

**登录 token**

当 Claude Duet 在已连接的应用中工作时，它遵循[我们的 Claude Managed Agents 设计](https://www.anthropic.com/engineering/managed-agents)，让凭据始终处于智能体工作范围之外。智能体代你使用的凭据，例如某个已连接服务的登录 token，永远不会进入智能体工作的那台机器。取而代之，那台机器上放的是凭据的占位符，由机器之外的代理在发出请求时才填入真实值。

**浏览器**

Claude Duet 中的浏览器运行在云端一台专属虚拟机里，与模型、以及与智能体工作的云计算机都相互隔离。智能体只通过一组固定的命令驱动浏览器：*打开这个页面、点击这里、输入这些*。网站运行的任何东西[都留在浏览器机器上](https://www.anthropic.com/engineering/managed-agents)。网站代码和 cookie 不会进入 Claude Duet 的记忆或你连接的应用，智能体的任何命令也都无法从浏览器里读出 cookie。真正返回的是页面文本和下载内容，因为智能体必须读取它们才能完成工作。这正是其他检查存在的原因，也是 Claude Duet 还采用我们[浏览器使用研究](https://www.anthropic.com/research/prompt-injection-defenses)中所述 prompt injection 防护的原因。它通过浏览器上传的文件，会接受与它发出的消息相同的敏感信息检查。

图 3. 浏览器边界：固定命令向外发出，页面文本返回，而网站代码、cookie 与下载内容都留在浏览器机器上。

Claude Duet 还被设计为会表明自己是智能体。目前，它的网页浏览器发出的请求会带上一个独特的 User-Agent 头，我们也会公布它浏览时使用的公网 IP 地址，好让网站能识别它并决定如何对待它。在发布之前，我们还联系了几家大型网站，让它们可以选择阻止 Claude Duet 访问其站点，其中一些确实这样做了。随着我们从研究预览中学到更多，我们会持续改进 Claude Duet 表明自身身份的方式。

图 4. 凭据路径：密码在你的手机上加密，只在浏览器机器上解密，且从不经过模型。

## 我们如何测试 Claude Duet

测试早在研究预览之前就开始了，并且仍在继续。我们的 Safeguards 团队依据日常任务形态构建了评测集，每个任务都有三个变体：一个无害版本、一个注入了指令的版本，以及一个诱使智能体做超出要求之事的版本。这些评测与来自真实使用的影子流量一并运行。

红队进一步测试了 Claude Duet 是否会泄露信息、未经批准就行动，或遵循恶意 prompt。我们为整个系统建立了威胁模型，覆盖它所触及的各个仓库与信任边界。一家外部渗透测试公司在我们开放源代码访问权限的情况下测试了 Claude Duet，而一项覆盖云浏览器与登录表单的后续工作正在进行中。每一项新的凭据功能在交付给任何人之前，都会在隔离的测试台上接受红队测试。

Claude Duet 也在 Anthropic 公开漏洞赏金计划的范围内，该计划依据我们的负责任披露政策，对有效报告给予奖励，并为善意研究提供安全港。如果你发现了安全漏洞，我们希望听到它：请通过 [HackerOne](https://hackerone.com/anthropic) 上的 Anthropic 漏洞赏金计划提交报告。

## 与你一起构建这一切

我们以研究预览的形式发布 Claude Duet，是因为我们想了解你在个人智能体上最看重什么，包括你希望接下来看到哪些防护与控制。这里描述的部分内容仍在变化：它请求批准的频率、你如何登录，以及敏感信息检查区分私密与无害内容的准确程度。用平实的语言告诉 Claude Duet 你希望看到什么、或哪里出了问题，它会为我们的团队提交一份报告。
