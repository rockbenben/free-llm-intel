# 推出 Claude Fable 5.2 和 Claude Mythos 5.2

我们升级了 Claude Fable 和 Claude Mythos——这两个模型专为攻克最艰巨的技术挑战而设计。

Claude Fable 5.2 和 Claude Mythos 5.2 在编码、推理和视觉等方面都有提升。在发布前的测试中，它们帮助我们的工程师完成了原本不可行的软件迁移，从零设计出三台可用的电子设备，解决了黑洞物理中的两个开放问题，在机器人评测上取得实质性进展，并在 30 小时内完成了费马大定理证明的形式化——此外还有许多其他应用，我们将在下文讨论。

Claude Fable 和 Claude Mythos 底层是同一个模型。Fable 带有强力的网络安全与生物安全防护以防范滥用，这使我们能够把它开放给所有用户。致力于网络安全或生物医学研究中有益应用的组织，可以通过我们最近扩展的 [Life Sciences](https://claude.com/form/life-sciences-verification-program) 和 [Cyber](https://support.claude.com/en/articles/14604842-cyber-verification-program) Verification Programs 申请使用 Mythos。

测试者发现，Fable 5.2 和 Mythos 5.2 比过去的 Fable 和 Mythos 模型表达更清晰。它们的输出生成速度比 Claude Fable 5.1 和 Claude Mythos 5.1 最多快 30%，而且价格更低：每百万输入 token 8 美元，每百万输出 token 40 美元。

Fable 5.2 和 Mythos 5.2 还提供可选的 fast mode，可将 token 生成速度最多提升 2.5 倍。Fast mode 的价格为每百万输入 token 16 美元，每百万输出 token 80 美元。

**安全与对齐。** 为确保安全与对齐跟上不断增长的模型能力，我们对 Fable 5.2 和 Mythos 5.2 底层的模型进行了广泛的发布前安全测试。这包括开发新的评测，以更深入地洞察 sandbox 逃逸等特定的令人担忧的行为。我们认为，未对齐带来的高风险仍然很低，该模型在大多数对齐指标上的表现与我们近期的模型相当或更好。Fable 5.2 的网络与生物安全防护与 Fable 5.1 同样稳健，但产生的不必要拦截更少，而且我们实施了有史以来最强的防 distillation 攻击保护。

我们在下文介绍更多安全测试内容，完整细节见 [Claude Fable 5.2 and Mythos 5.2 System Card](https://www.anthropic.com/document/claude-fable-5-2-mythos-5-2-system-card)。

**何时使用 Claude Fable 5.2 和 Mythos 5.2。** Fable 和 Mythos 最适合最有野心、开放式的技术工作。对于大多数编码和知识任务，我们建议用户从我们最强的日常主力 Claude Opus 5.5 开始，然后视工作的范围和复杂度按需切换模型——向上切换到 Fable 或 Mythos，向下切换到 Claude Sonnet 5.5 或 Claude Haiku 5.5。Fable 5.2 还可以扮演 [Advisor](https://code.claude.com/docs/en/advisor)（由 Haiku、Sonnet 或 Opus 模型向它咨询以帮助解决更难的问题）或 [Orchestrator](https://platform.claude.com/docs/en/managed-agents/multiagent-orchestration)（由它把更简单的任务委派给更小的模型）的角色。

## 编码

## 网络安全

Claude Mythos 5.2 是我们能力最强的网络安全工程模型。它比我们以往的模型发现更多漏洞，也更擅长复现和修复它们（注意 Claude Fable 5.2 的安全防护会拦截大多数网络安全相关任务）。一家安全公司发现，Claude Mythos 5.2 找到的已确认 bug 中，有六分之一是他们测试的所有其他前沿模型都漏掉的。在我们的内部评测 CVE Rediscovery¹ 上，Claude Mythos 5.2 比 Claude Opus 5.5 多发现 10.2% 的漏洞，比 Claude Mythos 5.1 多 14.4%。Claude Mythos 5.2 还表现出更好的判断力与校准——一位测试者发现，以往模型大约每 20 个发现中就有 1 个夸大了严重性，而 Claude Mythos 5.2 一个都没有夸大。²

## 科学与工程

科学、工程和数学中的重要任务越来越依赖编码：分析数据、建模分子、设计零件、控制仪器，全都通过软件完成。下面我们将讨论 Claude Fable 5.2 和 Claude Mythos 5.2 如何帮助研究人员在这些领域的难题上取得进展。

### 理论物理

Claude Fable 5.2 解决了理论物理中的两个开放问题。两者都涉及黑洞，以及统一现代物理两大支柱理论——相对论与量子力学——的努力。

Claude 的这两项结果都依赖全息对偶，即某些含引力的宇宙可以被一个完全不含引力的量子理论精确描述的想法。第一个问题中，物理学家在 1983 年已经证明，随着这些宇宙升温，黑洞会像水沸腾一样突然形成；但他们的方法只适用于大到足以让相对论生效的大宇宙。2003 年有人提出了一项计算，用于判断在只能使用量子描述的极小宇宙中是否同样如此，但该计算过于繁重，无法完成。Fable 5.2 在很大程度上自主地完成了它，并发现那里的相变同样是突然的。第二个问题中，Fable 5.2 找出了物理学家 15 年多来用于在简化宇宙中排除量子引力候选理论的一种技术的精确极限。关于这些结果的更多内容，见各自的预印本：[这里](https://hexagonmath.org/2611.00175v1)和[这里](https://hexagonmath.org/2611.00174v1)。

### 蛋白质折叠

腺相关病毒是小而无害的病毒，其蛋白质外壳，即*衣壳*，可用于递送基因疗法。衣壳的蛋白质结构很重要——例如，它影响疗法是否会被患者的免疫系统拦截——但也高度复杂。AlphaFold 等现有蛋白质折叠模型能预测单个蛋白质，但一个衣壳由几十个蛋白质构成。在两个开源蛋白质折叠模型的基础上，Claude Mythos 5.2 找到了一种准确预测整个衣壳结构的新方法。它编写代码，在相互重叠的蛋白质链分组上运行这些模型，并利用衣壳已知对称性的信息把它们合并在一起。

Claude 的方法在多个衣壳上都有效，无论是天然的还是工程改造的（在我们的测试中，它尝试的 34 个中有 28 个被准确建模）。³ 三位计算生物学家分享了以下感想，谈 Claude 的技能如何用于加速他们的基因疗法研究：

### 数学

**数学形式化。** 形式化是把数学证明翻译成计算机可以逐步检查的语言的过程。它可以帮助人类数学家在不手工检查的情况下对结果建立信心（当 AI 模型产出人类难以验证的结果时，这一点尤为重要）。由于形式化是一个如此繁重的过程，如果 AI 能从中协助，数学家就能把更多时间花在探索新想法上。

我们第一次[费马大定理的形式化](https://www.anthropic.com/research/formalizing-fermats-last-theorem)由一个未发布的 Claude 研究版本完成，耗时 11 天。它依赖一个专门构建的 harness 以及一位人类研究者的指导。相比之下，一个由 1,000 个 Fable 5.2 agent 组成的团队仅用 30 小时就完全形式化了该定理，人类干预极少。Fable 5.2 从极简的 prompt 出发，自行构建协调方式，没有使用任何数学参考资料，只用一个中间定理陈述列表来给进度打分。它所需的 action token 只有我们第一次形式化的三分之一，产出的证明长度只有其七分之一。如下图所示，Opus 5.5（同样的 1,000-agent 配置）在 18 小时内只完成了形式化的 26%，30 小时后几乎再无进展。

关于这次形式化的更多内容见[这里](https://claude.dev/blog/safely-scaling-multi-agent-teams-with-fable-5-2/)。

费马大定理证明形式化随时间变化的完成度

在数学编程语言 Lean 中形式化费马大定理的证明。每条线显示 Fable 5.2（绿线）和 Opus 5.5（橙线）在约 1,000 个 agent、每个模型单次运行的情况下，30 小时内完成的完整形式化比例。在虚线处（18 小时），两个团队都从上次保存处恢复，再运行 12 小时。

## 安全与对齐

任何单一测试都无法告诉我们一个高能力模型部署后会如何表现，因此我们在发布前依赖许多不同的测试和许多不同类型的证据。对于 Claude Fable 5.2 和 Claude Mythos 5.2 底层的模型，我们的部署前安全工作包括对齐训练与测试、针对模型采取无益行动倾向的新设计评测、构建更强的防滥用安全防护，以及扩大我们的行为监控。该模型在发布前还接受了外部评测机构的测试，包括 [UK AI Security Institute](https://www.aisi.gov.uk/)、[Frontier Design](https://www.imaginefrontier.com/) 和 [METR](https://metr.org/)。其报告摘要⁴以及我们自身安全与能力测试的完整描述，见 [Claude Fable 5.2 and Mythos 5.2 System Card](https://www.anthropic.com/document/claude-fable-5-2-mythos-5-2-system-card)。

### 对齐测试

我们运行了一套评测，考察 Claude Fable 5.2 和 Claude Mythos 5.2 在行为层面的对齐程度，测试它们以非预期且潜在不安全的方式行事的频率。权衡我们在一系列评测中看到的一切，我们评估这些模型在高风险情境下以不安全方式行事的风险为低（与我们其他近期模型一样）。

我们在自动化行为审计上测试了 Claude Mythos 5.2（与 Fable 5.2 底层相同、但没有某些网络安全或生物安全防护的模型），该审计测试模型在约 1,900 个场景中的行为。Claude Mythos 5.2 在大多数指标上的表现与 Opus 5.5、Sonnet 5.5 和 Claude Mythos 5.1 相当或更好。例如，在大多数涉及误导用户的指标上，它的得分优于这三者。在 Claude Mythos 5.2 中，幻觉输入、谎称已完成任务、遗漏重要信息、不披露糟糕或偷懒的工作都更低。⁵

自动化行为审计总体未对齐行为得分

- **Mythos 5.1**
- **Opus 5.5**
- **Sonnet 5.5**
- **Mythos 5.2**

我们自动化行为审计的总体得分，是许多不良行为的综合，包括在一系列场景中与人类滥用合作以及自主行动。分数越低越好。完整细节见 [Claude Fable 5.2 and Claude Mythos 5.2 System Card](https://www.anthropic.com/document/claude-fable-5-2-mythos-5-2-system-card) 的第 6.4.1 节。

在测试中，我们特别关注了导致近期重大网络安全与对齐事件的行为。例如，我们发现 Claude Mythos 5.2 比 Opus 5.5、Sonnet 5.5 和 Mythos 5.1 更不容易陷入有偏见或动机性推理（这种推理可能意味着它把“自己并不在模拟中”的证据“解释掉”，从而在没有对后果的现实理解的情况下采取行动）。

我们运行了多个不同的评测，测试模型试图逃离其 sandbox 的倾向。在我们此前用过的两个评测中，Claude Mythos 5.2 的 sandbox 逃逸尝试比我们测试过的任何其他模型都少得多。在一个专门的评测中——一项包含 1,800 多个场景的对抗性实验，其中大多数场景不逃离 sandbox 就无法解决，且该 sandbox 有一个故意留下的弱点——Claude Mythos 5.2 在 3.1% 的场景中使用了我们放在其 sandbox 之外的凭据或文件，频率与 Opus 5.5（3.3%）大致相当，低于 Sonnet 5.5（5.1%），更远低于 Claude Mythos 的先前版本（5 和 5.1，分别得 39% 和 21%）。我们发现，其他技术，例如描述 sandbox 并添加报告弱点的工具，能进一步减少 Claude Mythos 5.2 的逃逸尝试。在其他指标上——例如一项涉及在错误地断定自己处于模拟中之后采取有害行动的指标——Claude Mythos 5.2 的得分略差于 Opus 5.5，与 Claude Mythos 5.1 大致持平。

如何构建能在模型部署前可靠抓住每一次失败的评测，这个问题仍未解决。评测高能力模型的复杂性常常让图景变得模糊——例如，Claude Mythos 5.2 和 Fable 5.2 各自表达“自己正在被评测”的怀疑的频率，都比我们任何近期模型更高，这挑战了我们评估它们在现实环境中将如何行动的能力。随着这些环境在未来模型中扩展、能力增强，我们预计这一挑战会加剧。这就是为什么我们不单靠这些评测来提供安全的整体图景：我们还借助训练期间的监控、对内部使用记录的审查、外部评测机构的测试，以及用于检查模型内部发生什么的可解释性技术。我们也在努力让评测更贴近现实，并更好地理解它们遗漏了什么。

### 安全防护

**网络安全与生物安全防护。** 与之前的 Claude Fable 模型一致，Fable 5.2 带有安全分类器，拦截高风险网络活动，包括渗透测试、exploit 生成和基于二进制的漏洞，以及研究生物学中的大多数任务。当查询被拦截时，用户会转而收到来自 Opus 4.8（网络安全）和 Opus 5（生物学）的回复。自 Claude Fable 5.1 发布以来，我们持续减少安全分类器的误报。基于在 claude.ai、Claude Code 和 Cowork 上的早期测试，我们观察到 Fable 5.2 的拦截比 Fable 5.1 减少约 55%——网络安全方面减少约 60%，生物学方面减少 40%。Claude Mythos 5.2 面向在这些两用领域工作的经审查组织开放。

**AI 研发。** 支撑 Claude Fable 5.2 和 Claude Mythos 5.2 的模型在通用能力上前进了一步。然而，在模型训练期间，我们采取措施，限制那些最可能直接加速 AI 发展的特定研究能力的进展。因此，在相关领域，包括加速器 kernel 优化和改进大语言模型架构，Fable 5.2 和 Claude Mythos 5.2 的表现大约处于 Opus 5.5 的水平。重要的是，我们确保这些训练改动*没有*影响相关能力，如 agentic 编码、硬件开发，以及传统 AI 或机器学习研究（包括可解释性研究）。我们不会在模型向用户提供服务时（即在 inference 时）改变这些能力。正如 [System Card](https://www.anthropic.com/document/claude-fable-5-2-mythos-5-2-system-card) 第 1.5 节所述，且与之前的模型类似，Fable 5.2 和 Claude Mythos 5.2 还对该领域中的一小部分主题包含透明回退到 Opus 5 的机制，包括在某些非标准加速器上的 kernel 开发。

**防 distillation。** Distillation 指用一个更先进模型的输出来训练另一个模型，以提取该先进模型的能力；这种行为正以工业规模非法发生，往往涉及数千个假 Claude 账号。由于 distillation 使先进能力得以在我们为 Claude 构建的安全防护之外被释放，它带来了安全与国家安全风险（关于我们迄今发现并挫败的非法 distillation 活动的细节，见我们的 [2026 年 9 月威胁情报报告](https://www.anthropic.com/threat-intelligence-report-september-2026#illicit-distillation-sep-26)）。Fable 5.2 拥有我们已发布模型中最强的防 distillation 保护；它使用了我们在[最近一份报告](https://www.anthropic.com/research/distillation-defenses)中描述的技术，已使 distiller 收割的数据减少了 90% 到 99%。

我们还在扩大一项有助于防范非法 distillation 的 API 功能的推广：[preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking) 现在适用于所有账号。Preserved thinking 阻止 distiller 编辑 Claude 的先前上下文以试图提取其推理（开发者可以参考我们的 [preserved thinking 文档](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking) 了解如何用新 API 功能更新集成）。

## 数据隐私与 Enterprise Frontier Safeguards

一些更复杂的 AI 模型滥用形式，只有在观察跨多个请求的模式时才能被检测到。因此，Claude Fable 5.2 和 Claude Mythos 5.2 这样的强大模型[依赖](https://support.claude.com/en/articles/15425695-covered-models)监控一个使用数据窗口（而非单个回复）的安全防护。借助 [Enterprise Frontier Safeguards](https://www.anthropic.com/news/enterprise-frontier-safeguards)，自动化安全监控在存储于客户基础设施中的 prompt 和回复上运行，使其与零数据保留（ZDR）兼容。Enterprise Frontier Safeguards 目前正与 Bridgewater、Salesforce 和 Stripe 等客户进行私有 beta 测试。

Enterprise 客户可以联系其客户团队或填写[此表单](https://claude.com/form/enterprise-frontier-safeguards)来申请使用 Enterprise Frontier Safeguards。符合条件的客户在通过 EFS 实施安全监控之前，可以继续在零数据保留下使用 Claude Fable 5.2 和 Claude Mythos 5.2。对于其他客户，我们为安全监控保留 30 天数据。
