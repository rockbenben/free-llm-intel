# Claude寓言 5.2 和神话 5.2

我们升级了Claude寓言和Claude神话，这些模型旨在解决最艰巨的技术挑战。

Claude Fable 5.2 和 Claude Mythos 5.2 显示了编码、推理和视觉等领域的改进。在预发布测试期间，他们帮助我们的工程师完成了原本不可行的软件迁移，从头开始设计了三种工作电子设备，解决了黑洞物理学中的两个开放问题，在机器人评估方面取得了实质性进展，并在 30 小时内正式证明了费马大定理，以及我们将在下面讨论的许多其他应用。

Claude寓言和Claude神话是相同的底层模型。 《神鬼寓言》拥有强大的网络安全和生物学保障措施来防止滥用，这使我们能够将其提供给所有用户。在网络安全或生物医学研究中寻求有益应用的组织可以通过我们最近扩展的[生命科学](https://claude.com/form/life-sciences-verification-program)和[网络](https://support.claude.com/en/articles/14604842-cyber-verification-program)验证计划申请访问Mythos。

测试人员发现，Fable 5.2 和 Mythos 5.2 比过去的 Fable 和 Mythos 模型的沟通更加清晰。它们生成输出的速度比 Claude Fable 5.1 和 Claude Mythos 5.1 快 30%，并且价格更低：每百万输入代币 8 美元，每百万输出代币 40 美元。

Fable 5.2 和 Mythos 5.2 还配备了可选的快速模式，可将代币生成速度提高高达 2.5 倍。快速模式的价格为每百万输入代币 16 美元，每百万输出代币 80 美元。

**安全性和一致性。** 为了帮助确保安全性和一致性与不断增长的模型功能保持同步，我们对 Fable 5.2 和 Mythos 5.2 的基础模型进行了广泛的预发布安全测试。这包括开发新颖的评估，以更深入地了解沙箱逃逸等特定相关行为。我们认为，错位带来的高风险仍然很低，并且该模型在大多数对齐措施上的表现与我们最近的模型一样好，甚至更好。 《神鬼寓言 5.2》的网络和生物防护措施与《神鬼寓言 5.1》一样强大，但产生的不必要的区块更少，而且我们已经实施了有史以来最强大的蒸馏攻击保护措施。

我们在下面描述了有关安全测试的更多信息，完整的详细信息可以在 [Claude Fable 5.2 和 Mythos 5.2 系统卡](https://www.anthropic.com/document/claude-fable-5-2-mythos-5-2-system-card) 中找到。

**何时使用 Claude Fable 5.2 和 Mythos 5.2。** Fable 和 Mythos 最适合最雄心勃勃、开放式的技术工作。对于大多数编码和知识任务，我们建议用户从我们最强的日常驱动程序 Claude Opus 5.5 开始，然后根据工作的范围和复杂性根据需要切换到不同的模型 - 向上到 Fable 或 Mythos，或向下到 Claude Sonnet 5.5 或 Claude Haiku 5.5。 Fable 5.2 还可以扮演 [Advisor](https://code.claude.com/docs/en/advisor)（Haiku、Sonnet 或 Opus 模型参考它来帮助解决更困难的问题）或 [Orchestrator](https://platform.claude.com/docs/en/driven-agents/multiagent-orchestration)（它将更简单的任务委托给更小的模型）的角色。

## 网络安全

Claude Mythos 5.2 是我们最有能力的网络安全工程模型。它比我们以前的模型捕获更多的漏洞，并且更擅长重现和修复它们（请注意，Claude Fable 5.2 的防护措施将阻止大多数与网络安全相关的任务）。一家安全公司发现，他们测试的所有其他前沿模型都漏掉了 Claude Mythos 5.2 发现的六分之一的已确认错误。在我们的内部评估 CVE Rediscovery 中，1 Claude Mythos 5.2 发现的漏洞比 Claude Opus 5.5 多 10.2%，比 Claude Mythos 5.1 多 14.4%。 Claude Mythos 5.2 还表现出更好的判断力和校准能力——一位测试人员发现，以前的模型夸大了大约二十分之一的发现的严重性，而 Claude Mythos 5.2 并没有夸大任何发现。²

## 科学与工程

科学、工程和数学中的重要任务越来越依赖于编码：分析数据、建模分子、设计零件和控制仪器都是通过软件完成的。下面，我们讨论Claude寓言 5.2 和Claude神话 5.2 如何帮助研究人员在这些领域的难题上取得进展。

### 理论物理

Claude寓言 5.2 解决了理论物理中的两个悬而未决的问题。两者都涉及黑洞，以及统一现代物理学、相对论和量子力学这两个关键理论的努力。

Claude的两个结果都依赖于全息对偶性，即某些包含引力的宇宙可以通过根本不包含引力的量子理论来精确描述。在第一个问题中，物理学家在 1983 年表明，随着这些宇宙升温，黑洞会突然形成，就像水沸腾一样；但他们的方法只适用于大到足以应用相对论的宇宙。 2003 年，人们提出了一项计算，以确定在只能使用量子描述的非常小的宇宙中是否也存在同样的情况，但完成起来太费力了。 《神鬼寓言 5.2》在很大程度上是自主工作的，完成了它，但发现过渡也很突然。在第二个问题中，《寓言 5.2》发现了物理学家 15 年多以来用来排除简化宇宙中量子引力候选理论的技术的确切极限。请在[此处](https://hexagonmath.org/2611.00175v1) 和[此处](https://hexagonmath.org/2611.00174v1) 中了解有关这些结果的更多信息。

### 蛋白质折叠

### 数学

**数学形式化。** 形式化是将数学证明翻译成计算机可以逐步检查的语言的过程。它可以帮助人类数学家获得对结果的信心，而无需手动检查结果（当人工智能模型生成人类难以验证的结果时，这一点更加重要）。由于形式化是一个非常费力的过程，如果人工智能能够协助它，数学家就可以花更多的时间探索新奇的想法。

我们的第一个[费马大定理的形式化](https://www.anthropic.com/research/formalizing-fermats-last-theorem)由 Claude 的未发布研究版本完成，花了 11 天。它依赖于专门设计的安全带以及人类研究人员的指导。相比之下，由 1,000 名 Fable 5.2 智能体组成的团队在短短 30 小时内就完全形式化了该定理，并且几乎没有人为干预。 《神鬼寓言 5.2》从最少的提示开始，构建了自己的协调方式，并且不使用任何数学参考资料，仅使用中间定理陈述列表来评分进度。它需要的操作令牌数量是我们第一次形式化的三分之一，并且生成的证明时间缩短了七倍。如下图所示，Opus 5.5（同样有 1000 个智能体设置）在 18 小时内仅完成了 26% 的形式化，并且在 30 小时后几乎没有取得任何进展。

## 安全和对齐

没有任何一项测试可以告诉我们一个高性能模型在部署后将如何表现，因此我们在发布之前依赖许多不同的测试和许多不同类型的证据。对于 Claude Fable 5.2 和 Claude Mythos 5.2 的基础模型，我们的部署前安全工作包括对齐训练和测试、新设计的对模型采取无益行动倾向的评估、建立更强有力的防止滥用的保障措施以及扩大我们的行为监控。该模型在发布前还经过了外部评估机构的测试，包括[英国人工智能安全研究所](https://www.aisi.gov.uk/)、[Frontier Design](https://www.imaginefrontier.com/)和[METR](https://metr.org/)。请参阅 [Claude Fable 5.2 和 Mythos 5.2 系统卡](https://www.anthropic.com/document/claude-fable-5-2-mythos-5-2-system-card) 了解他们的报告摘要⁴以及我们自己的安全和功能测试的完整描述。

### 对齐测试

我们对《Claude寓言 5.2》和《Claude神话 5.2》在行为方面的一致性进行了一系列评估，测试它们以非预期和潜在不安全方式行为的频率。权衡我们在一系列评估中看到的一切，我们将这些模型在高风险情况下以不安全方式行为的风险评估为较低（与我们最近的其他模型一样）。

我们在自动行为审计中测试了 Claude Mythos 5.2（与《神鬼寓言 5.2》相同的基础模型，但没有某些网络安全或生物学保障措施），该审计测试模型在大约 1,900 个场景中的行为方式。在大多数指标上，Claude Mythos 5.2 的表现与 Opus 5.5、Sonnet 5.5 和 Claude Mythos 5.1 一样好，甚至更好。例如，在大多数涉及误导用户的指标上，它的得分高于所有三个指标。在 Claude Mythos 5.2.⁵ 中，幻觉输入、谎称已完成任务、遗漏重要信息以及未能披露糟糕或懒惰的工作的情况均较低

我们在测试过程中特别关注导致最近值得注意的网络安全和对齐事件的行为。例如，我们发现 Claude Mythos 5.2 比 Opus 5.5、Sonnet 5.5 和 Mythos 5.1 更倾向于进行有偏见或有动机的推理（这种推理可能意味着它“解释掉”了它不在模拟中的证据，从而在没有对后果有现实了解的情况下采取行动）。

我们进行了多次不同的评估来测试模型尝试逃离沙箱的倾向。在我们之前使用的两次评估中，Claude Mythos 5.2 的沙箱逃逸尝试比我们测试过的任何其他模型都要少得多。在一项专门的评估中（包括超过 1,800 个场景的对抗性实验，其中大多数场景在不逃离沙箱的情况下无法解决，并且沙箱有故意的弱点），Claude Mythos 5.2 在 3.1% 的场景中使用了我们放置在沙箱之外的凭据或文件，大约与 Opus 5.5 (3.3%) 一样频繁，比 Sonnet 5.5 (5.1%) 少，而且很好低于 Claude Mythos 之前的版本（5 和 5.1，得分分别为 39% 和 21%）。我们发现其他技术，例如描述沙箱和添加报告弱点的工具，进一步减少了 Claude Mythos 5.2 的逃脱尝试。在其他衡量标准上（例如，在模拟中错误地得出结论后采取有害行动），Claude Mythos 5.2 的得分略低于 Opus 5.5，与 Claude Mythos 5.1 持平。

在部署模型之前建立可靠地捕获每个故障的评估问题仍未解决。评估高性能模型的复杂性常常使情况变得混乱——例如，《Claude神话 5.2》和《寓言 5.2》都让人怀疑它们比我们最近的任何模型都更频繁地被评估，这挑战了我们评估它们在现实世界中的行为方式的能力。随着这些设置的扩展和未来模型功能的增强，我们预计这一挑战将会加剧。这就是为什么我们不仅仅依靠这些评估来提供安全性的整体情况：我们利用培训期间的监控、内部使用的记录审查、外部评估人员的测试以及可解释性技术来检查模型内部发生的情况。我们还在努力使我们的评估更加现实，并更好地了解他们错过了什么。

### 保障措施

**网络安全和生物学保障措施。** 与之前的 Claude Fable 模型一致，Fable 5.2 配备了安全分类器，可以阻止高风险网络活动，包括渗透测试、漏洞利用生成和基于二进制的漏洞，以及研究生物学中的大多数任务。当查询被阻止时，用户将收到来自网络安全 Opus 4.8 和生物学 Opus 5 的响应。自 Claude Fable 5.1 发布以来，我们不断减少安全分类器的误报。根据 claude.ai、Claude Code 和 Cowork 的早期测试，我们发现与 Fable 5.1 相比，Fable 5.2 的区块减少了约 55%，网络安全方面的区块减少了约 60%，生物学方面的区块减少了 40%。 Claude Mythos 5.2 可供在这些双重用途领域工作的经过审查的组织使用。

**人工智能研究和开发。** Claude Fable 5.2 和 Claude Mythos 5.2 的基础模型是通用能力的一个进步。然而，在模型的训练过程中，我们采取了一些措施来限制最能直接加速人工智能发展的特定研究能力的进步。因此，在相关领域，包括加速器内核优化和改进大型语言模型架构，Fable 5.2和Claude Mythos 5.2的表现大约与Opus 5.5水平相同。重要的是，我们确保训练变化不会影响代理编码、硬件开发和传统人工智能或机器学习研究（包括可解释性研究）等相关功能。当模型被提供给用户时（即在推理时），我们不会改变这些功能。如 [系统卡](https://www.anthropic.com/document/claude-fable-5-2-mythos-5-2-system-card) 第 1.5 节所述，与之前的模型类似，Fable 5.2 和 Claude Mythos 5.2 还包括针对该领域的一小部分主题的 Opus 5 的透明回退，包括某些非标准加速器上的内核开发。

**反蒸馏。** 蒸馏是根据更高级模型的输出来训练模型以提取高级模型的功能，这种方法在工业规模上非法发生，通常涉及数千个虚假的Claude帐户。由于蒸馏允许在没有我们为 Claude 内置的保障措施的情况下释放高级功能，因此它会带来安全和国家安全风险（请参阅我们的 [2026 年 9 月威胁情报报告](https://www.anthropic.com/threat-intelligence-report-september-2026#illicit-distillation-sep-26)，了解有关我们迄今为止检测和破坏的非法蒸馏活动的详细信息）。 《神鬼寓言 5.2》拥有我们发布的所有模型中最强大的防蒸馏保护；它使用了我们在[最近的报告](https://www.anthropic.com/research/distillation-defenses)中描述的技术，这些技术将蒸馏器收集的数据减少了 90% 到 99%。

我们还扩大了 API 功能的推出，以帮助防止非法蒸馏：[保留思维](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking) 现在适用于所有帐户。保留思维可防止蒸馏者编辑 Claude 先前的上下文以试图提取其推理（开发人员可以参考我们的[保留思维文档](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking)以了解如何更新与新 API 功能的集成）。

## 数据隐私和企业前沿保障

只有在观察多个请求的模式时才能检测到一些更复杂形式的人工智能模型滥用。因此，像 Claude Fable 5.2 和 Claude Mythos 5.2 这样的强大模型[依赖](https://support.claude.com/en/articles/15425695-covered-models) 来监控使用数据窗口（而不是个人响应）。借助 [Enterprise Frontier Safeguards](https://www.anthropic.com/news/enterprise-frontier-safeguards)，可以根据存储在客户基础设施中的提示和响应运行自动安全监控，使其与零数据保留 (ZDR) 兼容。 Enterprise Frontier Safeguards 现已与 Bridgewater、Salesforce 和 Stripe 等客户进行内测。

企业客户可以联系其客户团队或填写[此表格](https://claude.com/form/enterprise-frontier-safeguards)来请求访问 Enterprise Frontier Safeguards。符合条件的客户可以在使用 EFS 实施安全监控之前，继续使用零数据保留的 Claude Fable 5.2 和 Claude Mythos 5.2。对于其他客户，我们保留 30 天以进行安全监控。

网络安全专业人员可以通过[网络验证计划](https://support.claude.com/en/articles/14604842-cyber-verification-program)申请访问Claude Mythos 5.2。 Claude Enterprise 客户还可以使用由我们全系列型号（包括 Claude Mythos 5.2）提供支持的 [Claude Security](https://claude.com/product/claude-security)。生命科学研究人员还可以[申请](https://claude.com/form/life-sciences-verification-program)通过[生命科学验证计划](https://claude.com/form/life-sciences-verification-program)进行访问。
