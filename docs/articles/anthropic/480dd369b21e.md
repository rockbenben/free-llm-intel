# 为安全团队提供对 Claude Enterprise 的更多可见性和控制

Claude Enterprise 新增了安全与管理功能，包括 security center、全面可用的 inference hooks、centralized management，以及更多访问控制。

想了解 Claude 是如何配置的，security center 会展示你组织的 Claude 设置与 Anthropic 推荐配置之间的对比。想落实你的策略，inference hooks 会把 prompt 和工具调用发送到你的数据安全工具进行检查。想管理访问，centralized management 为你的公司提供一个统一的管理控制台来管理全公司范围的设置；新的访问控制则让你能通过 Admin API 将成员登出、自行管理 IP allowlist，并在受管电脑上的 Claude Desktop 中屏蔽个人账号及其他外部 Claude 账号，从而帮助防范 shadow IT。

我们最近还宣布了一项端点检测与响应（EDR）集成，它会在用户电脑上的 [unified Claude](https://claude.com/resources/articles/unified-claude-enterprise) 与 Cowork 虚拟机内运行你组织的传感器。

安全团队需要看清 Claude 是如何配置的、它在公司设备上做些什么，以及人们工作时数据是如何被处理的。这些功能正是为他们提供这种可见性与控制力。

## Security center：在一处审查你的 Claude 安全设置

![Claude Organization settings 中的安全态势仪表板，16 项控制中有 13 项通过。](https://assets.claude.com/893acaa9f8b564cda630ed280d69e5c7d2bca5f7.png)

安全团队可以在一个页面上审查 Claude 在 chat、Cowork 和 Claude Code 上的安全设置，而不必逐项查看。security center 是 Organization settings 中的一个新页面，它将设置与 Anthropic 的推荐配置进行对比，让你的团队一眼看出需要改什么、去哪里改。

对于每一项控制，security center 会显示当前值、推荐值（如果有），以及一个指向相应设置（可在其中修改）的链接。它还会标明哪些设置是新增的或最近变更的。security center 在每次页面加载时都会检查你的配置，因此自动检查的控制项反映的是你当前的设置。拥有 Compliance API 的组织可以通过它读取相同的结果。

Attestations 为你的管理员提供了一个用于安全审查的共享工作区。他们可以一起一次性走完整个流程，在同一处记录每项控制的当前状态、接受风险并标记问题。

你可以将 security center 页面下载为报告，分享给审计人员和相关利益相关方。报告会标明哪些控制项由页面自动检查、哪些由 Owner 确认。security center 是基于 Anthropic 推荐给出的指引，而非认证，也不保证符合任何法律或标准。

## Inference hooks

Inference hooks 将 Claude 与你组织已在使用的数据安全工具连接起来，让你的数据丢失防护（DLP）与安全策略能够在人们工作时作用于 prompt 和工具调用。

hooks 有两种，现在都已全面可用：

- Prompt hooks 将来自受支持 Claude 产品的 prompt 发送到你的安全工具进行检查。
- Pre-tool-call hooks 在受支持 Claude 产品中的工具调用运行之前对其进行检查。

Hooks 与安全厂商协同工作。你的团队可以保留已经写好的策略，并将其应用到 Claude 上。

## Centralized management：一个控制台统管整个组织的身份与访问

Centralized management 为你的父组织提供一个位于 admin.claude.com 的专属管理控制台；父组织代表你的公司，统辖其下的各个 Claude Enterprise 与 Claude Platform 组织。管理员可以在那里一次性为父组织旗下的各组织管理全公司范围的设置，而不必从各个组织各自的设置里分别管理。这些设置包括 single sign-on、目录同步（SCIM）、域验证、群组，以及 Compliance API 密钥。

该控制台在一处展示父组织旗下的每一个组织，并新增两个角色。父组织的 owner 可以管理父级层面的一切，包括由谁担任 owner 和 admin 角色。父组织的 admin 可以管理除这些角色任命之外的一切。

公司还可以连接多个身份提供商，每个都有自己的 single sign-on 与 SCIM 配置。被收购的公司可以保留其现有的提供商，你的团队也可以逐个域名地迁移到新的提供商。

每个组织保留自己的成员、角色、设置，以及组织级安全控制，例如 IP allowlisting、租户限制和会话时长。父级角色默认不授予组织内部的访问权限，但在父级创建的 Compliance API 密钥可以跨组织读取数据。

## Access controls：成员登出与 shadow IT 防范

安全团队现在只需一次 Admin API 调用，就能将某位成员登出 Claude，而无需将其从组织中移除。该调用会结束这位成员在所有浏览器和设备上的登录会话，Claude Code 等应用也必须重新登录。它不会终止 API 密钥、已在运行的云端会话或定时例行任务，该成员之后仍可重新登录。

Enterprise 管理员现在可以自行设置和管理自己的 IP allowlist，而无需经过 Anthropic。IP allowlist 将大多数 Claude 产品的访问限制在你组织批准的 IP 地址范围内。

管理员现在可以设置最常用的 Claude Desktop 设置，无需通过设备管理推送。为帮助防范 shadow IT，管理员还可以在受管电脑上的 Claude Desktop 中屏蔽个人账号及其他外部 Claude 账号。Owner 还可以限制人们可以将哪些工作区文件夹与 Claude 配合使用。

## Cowork 与 unified Claude 中的端点检测与响应（EDR）

当 Cowork 与 unified Claude 在本地工作时，它们会在用户电脑上一个隔离的虚拟机中运行 shell 命令和代码，以提供额外保护。这种隔离有助于保护设备，而安全团队一直要求对虚拟机拥有与 endpoint 上其他各处相同的可见性。

管理员现在可以在 Cowork 虚拟机内运行其组织的 EDR 传感器。该传感器会把其中的活动上报到安全团队已在监控的同一个控制台。这覆盖的是用户电脑上的虚拟机，而非云端的 Cowork 会话。

管理员通过 macOS 和 Windows 上的设备管理来设置该集成。每次虚拟机启动时，Claude 都会先验证来自你的 EDR 厂商的传感器包签名，然后再安装。传感器以检测模式运行：它们向你的安全团队上报活动，而不会加以拦截。该集成适用于受支持的 EDR 厂商，具体名单见 [Help Center](https://support.claude.com/en/articles/17828685-run-your-endpoint-detection-and-response-edr-sensor-in-claude-cowork-on-claude-desktop)。

## 开始使用

这些功能适用于 Claude Enterprise，beta 期间的一些例外情况列于 [Help Center](https://support.claude.com/en)。

[security center](https://support.claude.com/en/articles/18246629-review-your-organization-s-security-posture-with-the-security-center) 处于 beta 阶段。[Inference hooks](https://support.claude.com/en/articles/16059458-inference-hooks-overview)（包括 prompt hooks 和 pre-tool-call hooks）已全面可用。管理员可以在 Organization settings 中管理 inference hooks 和 security center。

[Centralized management](https://support.claude.com/en/articles/18232924) 同样处于 beta 阶段。要开始设置，需由父组织旗下任一组织的一位管理员前往 admin.claude.com，提名父组织的管理员。其他组织的管理员进行审查并批准，最后一个批准完成即完成设置。设置无法撤销，因此请在开始前确定好你的父组织管理员。

通过 Admin API [将成员登出](https://support.claude.com/en/articles/13133750-manage-members-on-team-and-enterprise-plans#h_3cba7d14e5) 以及[自助式 IP allowlist](https://support.claude.com/en/articles/13200993-restrict-access-to-claude-with-ip-allowlisting) 处于 beta 阶段。Owner 可以在 Organization settings 中管理 [Claude Desktop 设置](https://support.claude.com/en/articles/12622667-enterprise-configuration-for-claude-desktop#h_21135034c8)，该功能同样处于 beta 阶段。

Cowork 中的[端点检测与响应](https://support.claude.com/en/articles/17828685-run-your-endpoint-detection-and-response-edr-sensor-in-claude-cowork-on-claude-desktop) 在 macOS 和 Windows 上处于 beta 阶段，面向 Claude Team 与 Enterprise，以及部署在 Amazon Bedrock、Google Cloud Vertex AI 和 Microsoft Foundry 上的 Claude 桌面应用，通过 MDM 为受支持的厂商进行部署。
