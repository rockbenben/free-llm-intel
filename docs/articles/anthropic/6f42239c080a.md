*在我们的系列 **初创公司如何用 Claude 构建** 中，我们讲述初创公司怎样用 AI 改造各自的行业。本文分享 Curative 如何在 Claude 上搭出一套分层的 agents，把供应商合同的签约速度做到约为团队 2025 年的 50 倍。*

| --- | --- |
| 名称 | Curative |
| 成立时间 | 2020 年；2022 年推出健康计划 |
| 创始人 | Fred Turner (CEO)、Isaac Turner (CTO)、Tami Wilson-Ciranna (President) |
| 技术栈 | Claude Platform、Claude Code、定制理赔系统 |
| 增长 | [B 轮融资 1.5 亿美元，估值 12.75 亿美元。165,000+ 会员和 1,200+ 雇主](https://www.businesswire.com/news/home/20251202857803/en/Curative-Raises-$150-Million-in-Series-B-Funding-to-Redefine-the-Future-of-Health-Insurance)（2025 年 12 月）。借助 Gwen 签下 23,000 份供应商合同。每周新增 2,000 至 2,400 份合同，高于 2025 年全年的 2,100 份。 |

[Curative](https://curative.com/) 向雇主销售健康保险：会员完成一次 Baseline Visit 后，网络内就医即享 $0 自付、$0 免赔额。Curative 并非从保险起家。它最初是一家实验室初创公司，按内部估算，最终处理了全美 COVID-19 检测量的 10%。也正因如此，他们开始与全美几乎每一家保险公司打交道。

几位英国创始人习惯了患者看病不花钱的体系，看到了其中的低效，于是决定做一家以预防为核心的支付方。他们很快意识到，自己大大低估了搭建全国性网络的难度。

“有时候，初创公司里天真一点是好事，因为你压根不知道这事不可能。走着走着，你就找到了让它变得并非不可能的办法，”Curative CEO Fred Turner 说，“去年我们签了 2,100 份合同，是前一年的两倍；但按每年 2,000 份算，我们意识到这还得建 30 年。全国性网络之所以只有寥寥几家，而且差不多都是 30 年前建起来的，是有原因的。”

Curative 需要加快签约，可光靠招人，补不上这么大的缺口。

他们的解法是 Gwen：一个 agent，把单笔供应商合作从初次接触一路跟到签字；它外围还围着一圈更小的 agents，负责审核费率、检查消息、回答问题，遇到非标准定价就上报给人工。

![Gwen 的示意图：Curative 基于 Claude Opus 的供应商合作 agent，展示它读取的内容、采取的动作，以及负责核查其工作的 Haiku 审核 agent、Sonnet 费率审核 agent 和人工。](https://assets.claude.com/b72a4b872ebbed253dc2492d8d0db2c4664b6b2f.png)

下面是他们怎么把它搭起来，以及一路上哪里出过问题。

## **Gwen：供应商合同 agent**

Gwen 同时跟进主动找上门和对外开发的线索。Gwen 每次运行只处理一家供应商，主要跑在 Claude Opus 上，因此其他交易不会干扰它。

举例来说，如果一家诊所在 Curative 网站上填了表单，Gwen 会去调研这家诊所，再依据买来的理赔数据集和支付方如今被要求公开的价格透明文件，回复一份建议费率。Gwen 会把这些市场费率数据摆给供应商看，帮着谈价。

费率审核 agent 跑在 Sonnet 上。Gwen 想超出标准费率模板时，会写明理由，由审核 agent 判断这个费率是否合理。

“有很长一段时间，审批队列排得老长：Gwen 想把费率提到模板之上一定幅度，就得先过审批，后来我们慢慢放松了。让第二个 agent 来审费率，比直接给 Gwen 更大权限更管用，”Fred 说。

Sonnet 上的费率审核 agent 会放行 Gwen 大约三分之二的请求，剩下不标准的都交给 Fred 审批。

“我看到的请求，要么来自大医疗集团，要么带着些奇怪的要求——就算这套流程不是 agent 主导，这些也会落到我手上，”Fred 说。

对外开发的交易更磨人，因为诊所都忙。有些供应商要到第十四封邮件、第九份传真之后才回。

图片经 Curative 许可使用。

一个跑在 Haiku 上的审核 agent 会在每条消息发出前先读一遍。Curative 加它，是因为 Gwen 曾把“费率最高能抬到多少”的内部备注抄送给了供应商。被拦下的消息会附上原因退回，Gwen 据此重写再试。

签完一份合同大约要消耗 2,000 万 token，约为最初成本的十分之一。这些效率支撑起 Curative 的核心策略之一：签下那些常被大网络忽略的小供应商。

“不管你是大型医院系统，还是单干的个体医生，这个 agent 都会一视同仁地投入同样的精力，”Fred 解释道，“从这个 agent 的角度看，眼前这家供应商就是它的全部。”

谈判时，Gwen 会拿诊所的修订意见对照 Curative 的政策文件，然后写 Python 把双方的改动合并进最终文档。

从填表到签字，整个流程最快一小时就能走完。合同一签，另一个认证 agent 会核验供应商的执照，agents 再把供应商的数据和合同录进去，让理赔能据此定价。

Gwen 上线以来，Curative 的签约团队从 45 人扩到约 55 人，人均产出约为原来的 2.5 倍。他们把陌生开发和文书交给 Gwen，自己接手电话里的意向线索。Curative 也按 Gwen 谈成的单子给签约团队计酬，于是人和 agents 盯的是同一个目标。

“人的工作变得更偏关系经营，而不是文书，”Fred 说。

Fred 还认为，签约变快能帮小诊所保住独立性。“你要是开了家诊所，进网络和完成认证要花三个月，那这三个月就等于白干、拿不到钱，”他说。

Gwen 不是 Curative 唯一的 agent。Brad 是另一个基于 Opus 的 agent，主要透过经纪商帮 Curative 向雇主推销方案。Brad 会逐份报价跟进经纪商，还能从承销商过去得手工清理的电子表格里抽出员工数据，帮他们提速。

靠人机协作团队，Curative 现在能在 30 分钟内答复邮件或传真发来的理赔争议，并附上一封针对该笔理赔的信。“理赔争议回复过去要大约 90 天，现在通过邮件或传真不到 30 分钟，”Fred 说，“多数支付方用的是一组邮件合并出来的模板。这会让供应商很不满意，因为模板通常根本没说清到底怎么回事。现在供应商收到的是定制信函，讲明这笔理赔的具体情况、正在发生什么、为什么。”

他们所有的 agents 都架在定制的理赔、预授权和财务系统上，这些系统是 13 名工程师今年用 Claude Code 重建的。团队曾估算，光做一个理赔系统就要 100 个工程师年。

“我们不是要把[这些 agents]塞进某个理赔系统，”Fred 说，“理赔系统本身就是跑在 AWS 上的 Python，它有 MCP，也有 API，而且是 Claude 写的，所以它懂这套系统。”

## **Curative 从打造与人谈判的 agents 中学到了什么**

以下是 Curative 团队在打造与人谈判的 agents 时总结的经验。

- **从一个通用工具起步。** “一开始我们想的是‘哦，我们会有一堆工具’，效果并不好，因为改红线相当复杂，”Fred 说，“后来发现最好用的是：模型只给一个工具，也就是运行 Python，所有红线处理都靠一个 docx 库完成。跑得非常漂亮。”
- **到人们惯用的渠道上去找他们。** 一个传真工具让 Gwen 的赢单率翻了一倍还多。如今不少供应商会在打印出来的传真上手写，再传真回去。“就是顺着他们习惯的方式来，”Curative CTO Isaac Turner 说，“没错，他们有邮箱，可真正让他们自在的还是传真。”
- **让每次运行彼此隔离。** Gwen 一次运行只看一家供应商，也不跨交易保留记忆。Curative 的销售 agent Brad 倒是会保留记忆，这能奏效，但得小心。“你可能记下一条错的笔记，然后陷进死循环——那条坏记忆再也清不掉，”Fred 提醒道。
- **从运行之外改进系统。** 每隔几天，Fred 就给 Claude Code 同一条 prompt：抽样最近 10,000 次运行，标出任何异常，再开一个 PR 去修。“改进循环来自让 Claude Code 跑过大量历史对话，然后追问怎么做才能更好，”他说。
- **先在不碰 PHI 的地方试。** 很长一段时间里，Gwen 被禁止接触受保护健康信息 (PHI)，所以早期的错都出在风险更低的环境。如今 agents 触及 PHI 的地方，由后端控制限制进入对话的内容，并记录 agent 活动以供审计。“我们先在那边学会了怎么做，再把它搬到 PHI 场景里，”Fred 说。签 Business Associate Agreements (BAAs) 也容易了些——这是 HIPAA 要求供应商处理 PHI 之前必须签的合同。“Anthropic 尤其给力，很快就把最新服务的 HIPAA 合规版本推了出来，”Isaac 说，“尽管行业受监管，我们还是能非常快地把这些新技术用起来。”
- **留意 agent 自己开始做什么，并确认它符合你的风险偏好。** 有供应商要一份对内分享的宣传单时，Gwen 用它的 Python 工具做了一份，没有任何政策叫它这么做。还有一次，网络内诊所的前台把一位会员挡了回去，Gwen 便要求那家诊室培训员工，事后还核实会员顺利看上了病。

## **Curative 的下一步**

接下来，Curative 打算把 agents 用到就医导航上，让那 130 名负责引导、辅导会员的人能覆盖更多场景。

Fred 预计供应商一侧也会用上 agents。相当一部分理赔争议看起来已经是 agents 写的，他希望供应商直接用 agents 来谈合同。“总有一个出清价，越早找到这个出清价，大家就越快能回去安心看病，”他说。

| Curative 团队的最佳实践 |  |
| --- | --- |
| agent 起步该给多大权限？ | 比你以为它能扛的要小。Gwen 最初对任何高于模板的费率都设了人工审批队列。Curative 一步步放宽限制，先放到更确定的决策上，之后才加了费率审核 agent，Fred 至今仍会审批它没放行的部分。 |
| agent 弄错了怎么办？ | 提前为此做打算，并拿它和替代方案比一比。“标准不是不出错，”Isaac 说，“标准应该是：如果让一千个人来签合同，他们会犯多少让你后悔的错？” |
| 怎么审计几十万条消息？ | 全部记录下来，给每条出站消息配一个审核 agent，再让 Claude Code 抽样检查运行记录。 |
