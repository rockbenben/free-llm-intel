*在我们的系列“**初创公司如何与 Claude 一起构建**”中，我们重点介绍了初创公司如何利用人工智能改变其行业。在本文中，我们将分享 Curative 如何在 Claude 上构建代理层次结构，以比其团队在 2025 年签署供应商合同的速度快约 50 倍。*

[Curative](https://curative.com/) 向雇主出售健康保险，一旦会员完成基线就诊，网络内护理的自付费用为 0 美元，免赔额为 0 美元。 Curative 并不是从保险开始的。它最初是一家实验室初创公司，根据内部估计，最终处理了美国所有 COVID-19 测试的 10%。因此，他们开始与该国几乎所有保险公司合作。

该公司的英国创始人习惯了患者不支付医疗费用的系统，发现效率低下，并着手建立一个专注于预防的付款人。他们意识到自己大大低估了建设全国网络的难度。

Curative 首席执行官弗雷德·特纳 (Fred Turner) 表示：“有时，天真对于初创公司来说是件好事，因为你不知道这是不可能的。然后一路走来，你就会找到一种方法，让它变得不可能。” “去年我们签署了 2,100 份合同，是前一年的两倍，但每年签订 2,000 份合同，我们意识到这仍然是一个 30 年的建设。全国性网络只有少数，而且都是大约 30 年前建成的，这是有原因的。”

Curative 需要加快合同签署速度，但仅靠招聘无法缩小如此大的差距。

他们的解决方案是：格温（Gwen）是一名代理，负责从最初的联系到签署一项提供商的交易，周围是较小的代理，这些代理会审查其费率、检查其消息、回答其问题，并将非标准定价升级给人工。

以下是他们如何构建它以及在此过程中出现的问题。

## **Gwen：提供商合同代理**

格温负责入站和出站线索。 Gwen 的每次运行都处理一个提供商，主要是在 Claude Opus 上，因此其他交易不会影响它。

例如，如果一家诊所填写了 Curative 网站上的表格，格温将研究该诊所，并根据购买的理赔数据集和付款人现在需要发布的价格透明度文件回复建议费率。格温将向供应商展示这些市场费率数据以帮助谈判。

The rate reviewer runs on Sonnet.当 Gwen 想要超出其标准费率模板时，它会写出原因，然后审阅者决定该费率是否合理。

“很长一段时间以来，审批队列很长，如果格温想要超出模板一定的金额，就必须获得费率批准，但随着时间的推移，我们放松了。拥有第二个代理审核费率比仅仅给予格温更多权力更有效，”弗雷德说。

Sonnet 评级审核员批准了格温大约三分之二的请求，然后任何不标准的内容都会交给弗雷德批准。

弗雷德说：“我看到的请求来自一个大型医疗团体，或者某个提出奇怪请求的人，即使这不是特工主导的动议，也会向我提出。”

对外交易需要更多的坚持，因为实践很忙。一些提供商在第十四封电子邮件和第九封传真之后回复。

图片的使用已获得 Curative 的许可。

法官在Haiku上运行，在发送之前阅读每条通信。 Curative 在 Gwen 向供应商复制了有关其可能上涨的内部注释后添加了它。被阻止的消息会返回并附有原因，因此 Gwen 可以重写它并重试。

每个合约大约需要 2000 万个代币才能完成，大约是原始成本的十分之一。这些效率实现了 Curative 的核心战略之一：与经常被大型网络忽视的小型提供商签约。

“无论您是大型医院系统还是独立提供者，代理都会很乐意为您提供同等程度的关注，”弗雷德解释道。 “从该代理商的角度来看，该提供商是其唯一的焦点。”

在谈判期间，Gwen 根据 Curative 的政策文件检查实践红线，然后编写 Python 将双方的更改合并到最终文件中。

从表格到签名，整个过程最快只需一个小时。合同签署后，一个单独的认证代理会检查提供商的许可证，代理会加载提供商的数据和合同，以便索赔可以根据其定价。

自 Gwen 推出以来，Curative 的签约团队已从 45 人增加到约 55 人，每个人的生产力提高了约 2.5 倍。他们向格温提供冷冰冰的外展服务和文书工作，并通过电话接听热情的线索。 Curative 也根据 Gwen 的交易向其签约团队支付费用，因此人员和代理商有一个共同的目标。

“人们的工作更多地是关于关系，而不是文书工作，”弗雷德说。

弗雷德还认为，更快的签约有助于小型诊所保持独立。 “如果你开始从事医疗实践，需要三个月的时间才能进入网络并获得资格，那么你将在三个月内得不到报酬，”他说。

格温并不是 Curative 的唯一经纪人。 Brad 是 Opus 的另一位代理人，主要通过经纪人帮助向雇主推销 Curative 的计划。布拉德会跟进经纪人的每一次报价，并通过从承销商用于手动清理的电子表格中提取员工数据来帮助承销商更快地采取行动。

通过人工代理团队，Curative 现在可以在 30 分钟内回复通过电子邮件或传真发送的索赔纠纷，并附上专门针对该索赔的信件。 “过去，索赔纠纷回复需要大约 90 天的时间，现在通过电子邮件或传真只需不到 30 分钟，”Fred 说。 “大多数付款人使用一组通过邮件合并在一起的模板。这让提供商深感不满，因为通常模板实际上并没有解释正在发生的事情。现在，提供商会收到一封定制的信件，解释个人索赔的具体情况、发生的情况以及原因。”

他们所有的代理人都依赖于定制的索赔、事先授权和财务系统，这些系统是 13 名工程师今年用 Claude Code 重建的。该团队曾经将单独构建一个索赔系统的规模确定为 100 个工程师年。

“我们并不是试图将[这些代理]插入索赔系统，”弗雷德说。 “索赔系统是在 AWS 中运行的 Python，它有一个 MCP，它有一个 API，Claude 编写了它，所以它可以理解它。”

## **Curative 从与人谈判的建筑代理商那里学到了什么**

以下是 Curative 团队学到的关于如何建立与人谈判的代理的知识。

- **从一个通用工具开始。** “我们一开始就说，‘哦，我们会有工具’，但这效果不太好，因为红线相当复杂，”弗雷德说。 “我们发现效果最好的是该模型只有一个工具，运行 Python，并且它使用 docx 库完成所有红线处理。它工作得非常好。”
- **在他们的频道上认识人们。** 传真工具使格温的获胜率提高了一倍多。许多提供商现在在打印的传真上手写并传真回来。 Curative 首席技术官艾萨克·特纳 (Isaac Turner) 表示：“这是在人们所在的地方与他们会面。” “是的，他们有电子邮件，但实际上他们更喜欢传真。”
- **保持每次运行隔离。** 一次 Gwen 运行会看到一个提供商，并且不会保留跨交易的记忆。 Curative 的销售代理 Brad 确实保留了记忆，这很管用，但需要小心谨慎。 “你最终可能会记下错误的笔记，然后陷入这些厄运循环，其中的坏记忆永远无法清除，”弗雷德指出。
- **从运行外部改进系统。** 每隔几天，Fred 都会向 Claude Code 发出相同的提示：对最近 10,000 次运行进行采样，标记任何奇怪的内容，然后打开 PR 来修复它。 “改进循环来自于在大量历史对话中运行Claude Code并询问如何才能变得更好，”他说。
- **首先进行远离 PHI 的实验。** 很长一段时间以来，Gwen 都被禁止获取受保护的健康信息 (PHI)，因此早期的错误都是在风险较低的环境中发生的。现在，在座席接触 PHI 的情况下，后端控制会限制进入对话的内容，并记录座席活动以供审核。 “我们在那里学会了如何做，然后将其转移到 PHI 土地上，”弗雷德说。签署业务伙伴协议 (BAA)（HIPAA 要求供应商在处理 PHI 之前签订的合同）也变得更加容易。 “Anthropic 尤其擅长快速推出符合 HIPAA 的最新服务版本，”Isaac 说。 “尽管这些新技术受到监管，但我们仍然能够非常快速地采用这些新技术。”
- **观察代理开始自行做什么，并确保它符合您的风险状况。** 当提供商要求提供一份传单在内部共享时，Gwen 使用其 Python 工具制作了一份传单，没有任何政策要求。当前台在网络内诊所拒绝一名会员时，格温要求办公室培训其员工，然后检查该会员是否进入。

## **Curative 的下一步发展**

接下来，Curative 计划让代理负责导航，扩大指导和指导其会员的 130 名人员的影响范围。

Fred 希望提供商方面也有代理。很大一部分索赔纠纷似乎已经由代理人撰写，他希望提供商能够使用代理人来谈判合同。 “有一个清算价格，你越快找到清算价格，每个人都可以继续提供护理，”他说。
