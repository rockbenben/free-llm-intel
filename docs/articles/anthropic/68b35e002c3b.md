# Claude in Chrome 正式发布

在你的浏览器里交给 Claude 一个任务，跨标签页工作，并在桌面、移动和网页应用里延续对话。

- 类别：[产品公告](https://claude.com/blog/category/announcements)
- 产品：[Claude Cowork](https://claude.com/product/cowork)、Claude 应用
- 日期：2026 年 8 月 26 日
- 阅读时长：5 分钟

Claude in Chrome 现已在所有付费 Claude 套餐上正式发布。Claude 如今也能在浏览器里自主采取行动，而不需要每一步都获批准。一个安全分类器会在每个动作执行前验证它，确保它是安全的、且与你的请求相符。

你每天用的许多工具都[能连到 Claude](http://claude.com/connectors)。但许多其他的不行，比如内部仪表盘、遗留系统和供应商门户。Claude in Chrome 让 Claude 能访问那些。它能看到你所在的页面，并用你现有的登录采取行动，例如阅读和输入文本、点击链接、在页面之间导航、填写表单。

我们去年首先以试点形式宣布了 Claude in Chrome，以便我们在测试它的同时，加强对 [prompt 注入](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/mitigate-jailbreaks) 的防御——即藏在网站、邮件或文档里、试图诱骗 AI agent 违背用户意愿行事的恶意指令。下面所述的这些防御，让我们有信心让 Claude in Chrome 正式发布。

## 防范 prompt 注入

正如我们在宣布试点时[概述的](https://claude.com/blog/claude-for-chrome)，一个在你浏览器中工作的 AI agent 也容易受 prompt 注入。所以在更广泛地发布 Claude in Chrome 之前，我们一直在改进我们的防护。

在一次 prompt 注入攻击中，恶意行为者把指令藏在网页内容里，例如一个网页、一封邮件或一个表单字段。你可能永远看不到它们，但这些指令能把 agent 引去做一件你从未要求的事。例如，如果你已经请 Claude 起草对你邮件的回复，一封消息里的一条隐藏指令可能告诉 Claude 反而把你的其他邮件转发给攻击者。

在发布时，我们描述了我们如何测试 Claude 对这些攻击的防御、以及当时我们所部署的防护；我们后来发布了关于[浏览器使用防护](https://www.anthropic.com/research/prompt-injection-defenses) 的更详细描述。自那以后，我们改进了对模型和我们[探针（probes）](https://www.anthropic.com/research/next-generation-constitutional-classifiers) 的训练方式，并新增了一整套分类器，使 Claude 能在 Chrome 中安全地采取更多自主行动。下一节，我们讨论我们评测的结果，它们展示了这些防护的效力。

**Claude 能认出更多攻击。** 我们针对一个不断增长的 prompt 注入攻击库来训练 Claude，这些攻击来自我们内部的自动化攻击者、外部红队以及真实世界的监控。当一个新攻击对当前模型成功时，它就被加入库中，用来指导未来模型以及我们已部署防护的训练，从而让它们学会认出它。自我们 2025 年 11 月首次撰写关于[浏览器使用的 prompt 注入防御](https://www.anthropic.com/research/prompt-injection-defenses) 以来，我们已让 Claude 对这些攻击的抵抗力显著增强。

**探针在 Claude 依据网页内容行动前先筛查它。** 网页内容通过工具结果到达 Claude。要执行一个动作，比如阅读一个页面或打开一封邮件，模型会发起一次工具调用；工具结果让模型读取输出（在本例中即页面的内容或邮件的内容）。我们训练探针去扫描这些结果、寻找潜在的 prompt 注入。当探针检测到一个可能的攻击时，Claude 会被警告要怀疑地对待该内容，并在需要时先与你确认再行动。我们首先在 Claude Opus 4.5 上部署这些探针，此后又扩展了它们所覆盖的攻击类型。

**行动在运行前先被核验**。在 Claude in Chrome 中，Claude 现在会自动批准它判定为安全的行动，使用与 Claude Code 中 [auto 模式](https://claude.com/blog/auto-mode-default-in-claude-code) 相同的机制。（如果你宁愿继续手动批准 Claude 的行动，可以在设置里关掉这一点。）一个分类器审阅 Claude 即将采取的行动，例如导航到一个新网站或在页面里输入文本，并对照你最初的要求检查它们。如果行动与你的请求不符，它就被拦截。

## 度量 Claude 对 prompt 注入的稳健性

我们测试了这些防护，以确保 Claude in Chrome 用于浏览器工作足够安全。这里，我们报告我们最新评测的结果。

在我们测试 Claude Cowork 对 prompt 注入攻击韧性的[初始评测](https://claude.com/blog/claude-for-chrome)（首次开发于我们发布 Claude in Chrome 试点之时）上，没有任何攻击在 [Cowork harness](https://claude.com/blog/cowork-chrome-side-panel) 里对 Claude Fable 5、Claude Opus 5 或 Claude Sonnet 5 成功，即便没有上述探针和分类器。

针对 Claude Opus 4.5、Sonnet 5、Opus 5 和 Fable 5 的 prompt 注入攻击成功率。Opus 4.5 以扩展思考运行，因为它不支持我们较新的自适应思考默认设置。其他所有模型以自适应思考、medium effort 作为默认运行。我们 2025 年 11 月博客文章中讨论的结果，是在未启用扩展思考的情况下运行的；但由于 Fable 5 无法禁用思考，我们在此报告启用思考的结果。11 月所用的评分模型也已不再可用，于是我们转向一套更强的评分流水线，并结合对成功攻击的人工复核，这产生了更少的误报。

因为我们把那份评测跑到了饱和（0% 的成功率即为证据），我们决定把它退役。在我们[当前的评测](https://www-cdn.anthropic.com/b514064af1408018e64b1ad24e7d5e75850b4ffd/Claude%20Opus%205%20System%20Card.pdf#page=76.73)中——它使用由职业红队者获取的更强攻击——在施加任何额外防护之前，抵达模型的攻击对 Opus 4.5 有 17.6% 的成功率，对 Opus 5 有 3.8%。使用 2025 年 11 月可用的最强防护时，针对带探针运行的 Opus 4.5 的攻击成功率为 16.7%。针对 Opus 4.8 及以后的每一款模型，当带探针和安全分类器运行时，没有任何攻击对 Claude Sonnet 5、Claude Opus 5 或 Claude Mythos 5 成功。我们看到对 Fable 5 有 0.3% 的攻击成功率。我们已人工验证所有成功突破都发生在低严重性场景中，并正在努力缓解它们。

在探针加上自动批准的安全分类器下，没有任何攻击对 Claude Sonnet 5 或 Opus 5 成功，而 0.3% 的攻击对 Fable 5 成功。Opus 4.5 的模型行为导致抵达模型的攻击数量更少，但它的攻击成功率百分比仍是最高的。

Prompt 注入仍是一个不断移动的目标。虽然这一方法能防御当前的攻击，我们也需要确保我们的防护保持在攻击者不断演进手法的前面。随着每一次模型发布，我们持续投资于开发更精密的自动化系统用于攻击发现、红队，以及构建更强的分类器。

## 如何开始

要开始使用 Claude in Chrome，请从 [Chrome 应用商店](https://chromewebstore.google.com/detail/claude/fcoeoabgfenejglbffodgkkbkcdhcgfn) 安装它。在企业套餐上，管理员可在组织设置中管理它，并将其限制到获批准的域名。参见[管理员设置指南](https://support.claude.com/en/articles/13065128-claude-in-chrome-admin-controls#h_bdb63199e1)。

要与计算机上的文件或其他应用协作，你仍需使用 Claude 桌面应用。Claude in Chrome 目前还不支持其他 Chromium 浏览器或移动端。

*¹ 并非所有攻击都能抵达——即被看到——模型。在某些情况下，Claude 采取的行动使它根本不会遇到那些恶意指令。*
