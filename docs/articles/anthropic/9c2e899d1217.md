# Claude Security 现支持持续扫描与修复跟踪

自 [Claude Security](https://claude.com/product/claude-security) 于 4 月进入公开测试版以来，已有数千家组织用它发现了超过 100 万个漏洞。

Claude Security 不再等着某个人来发起扫描，而是随着你的代码变化持续跟进你的代码仓库，记录哪些发现项得到了修复，并用你的团队告诉它的环境情况来判断什么才重要。Claude Security 由我们完整的模型家族驱动，其中包括 Claude Mythos，无需 Cyber Verification Program 访问权限。

Claude Security 的最新版本今日以公开测试版向 Claude Enterprise 客户开放。组织每月可获得 $25,000 的免费用量额度，持续两个月。该优惠适用于 2026 年 12 月 31 日及之前的用量。完整条款可在 [Help Center](https://support.claude.com/en/articles/14661296-use-claude-security) 查看。

## **持续监控跟得上你的代码**

一次扫描只捕捉某一个时刻，而代码每天都在变。团队告诉我们，他们希望覆盖范围能一直保持最新，而不需要任何人去排期扫描。

创建一个项目，通过 Claude GitHub app（包括 GitHub Enterprise Server）连接你的代码仓库，或者使用 GitLab 及其他 Git 服务商提供的 access token 连接，并为每个仓库选择分支和范围。Claude 会先运行一次深度基线扫描，然后根据变更的风险与复杂度定期扫描，让你的发现项清单始终贴近代码的当前状态。

一个项目可以容纳多个代码仓库，因此 Claude 能抓到那些存在于服务之间的问题，比如后端信任了本该由客户端校验的输入。

![Claude Security 界面](https://assets.claude.com/fe39204ec42e8d48c853bf16bb08bdb19bf99a22.png)

## **修复上线时，发现项就被标记为已修复**

大多数修复并不在发现该问题的那个工具里完成。Claude Security 会把尚未解决的发现项与发生变化的代码做比对，并在修复落地时把它们标记为已修复，不管你的团队是在 Claude Code 里改的、还是在另一套流程里改的。如果 Claude Security 之后再次发现同一个问题，该发现项会自动重新打开。

![Claude Security 界面](https://assets.claude.com/579a7fb43c95d281cf38ba2dafca75eea40a7058.png)

## **你团队的知识会塑造扫描**

每个环境都有一些控制措施是扫描器仅凭代码看不到的。团队希望有一种办法，能把这些控制措施告诉 Claude Security，并让它横穿相互依赖的服务一起查看。现在，每个项目都带一个知识库，你可以在里面描述你的代码是如何部署的、哪些安全政策适用，以及你团队里新来的安全工程师需要知道的一切。

![Claude Security 界面](https://assets.claude.com/440f4c1037a629695ec66eb0a17c218782b51d35.png)

Claude Security 还会根据你的代码生成一份威胁模型，供你的团队审阅和编辑。后续的扫描会利用这些威胁模型来决定什么值得标记出来。补充的上下文也能帮助 Claude Security 跳过你的环境已经处理掉的风险。

## **每个发现项都带严重度与利用路径**

每个发现项都附带一个严重度评级——依据你项目的威胁模型判定——以及一段说明，解释攻击者如何能够触达存在漏洞的代码，好让团队先修复真正可达的问题。发现项可以包含攻击路径示意图。

![Claude Security 界面](https://assets.claude.com/58c85ec0105dd3b16b367ae71e70c14db55e6d4f.png)

## **发现项直达你的工具，并为更大范围推广提供管控**

新的 API 让你把 Claude Security 集成进已有的工作流。你可以列出并读取项目和发现项、把发现项标记为解决或重新打开，也可以创建和管理项目及其代码仓库。用户可以在 Claude Security 设置里创建 personal access token，它只能看到和改动该用户本身能看到与能改的内容。Webhook 也能在有新的发现项产生时通知你的系统。

Claude Security 还以 MCP connector 的形式提供，可用于 [Claude.ai](http://claude.ai) 和 Claude Code。工程师可以在同一个 session 里调出一个发现项、向 Claude 询问它、着手修复，并把它标记为已解决。

新增的基于角色的访问控制让管理员可以决定谁能查看项目、谁能为发现项做分诊、谁能创建项目。组织可以把 Claude Security 开放给更多真正负责这些代码的团队，而不必给每个人创建项目的权限。

## **开始使用**

从今天起，[Claude Security](http://claude.ai/security) 的最新版本以公开测试版向 Claude Enterprise 客户开放。管理员可以在管理控制台中启用它，并设置团队里谁能访问。

使用[入门指南](https://academy.claude.com/tutorials/getting-started-with-claude-security)来设置你的第一个项目，并访问 [Help Center](https://support.claude.com/en/articles/14661296-use-claude-security) 了解更多细节。
