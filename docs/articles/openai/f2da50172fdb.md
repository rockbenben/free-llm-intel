# 通过一次演示学习《Montezuma's Revenge》

View code

(opens in a new window)


我们训练出一个智能体，仅凭一次人类演示就在 [Montezuma's Revenge⁠(opens in a new window)](https://www.retrogames.cz/play_124-Atari2600.php?language=EN) 上拿到 74,500 的高分，超过此前任何已发表的结果。我们的算法很简单：智能体从演示中精心挑选的状态出发玩一系列对局，并通过用 [PPO⁠(opens in a new window)](https://blog.openai.com/openai-baselines-ppo/) 优化游戏分数来学习——这正是支撑 [OpenAI Five⁠(opens in a new window)](https://blog.openai.com/openai-five/) 的同一种强化学习算法。


## 探索与学习

要在一个强化学习问题上成功，AI 需要做两件事：

- 找到一条能带来正向奖励的动作序列。这是*探索*问题。
- 记住该执行的动作序列，并泛化到相关但略有不同的情形。这是*学习*问题。

在 Montezuma's Revenge 上，探索问题在很大程度上可以绕过：每次 RL 回合都从演示中的某个状态重置开始。从演示状态起步，智能体相比每次从游戏开头开始时需要进行的探索少得多。这样我们就能把探索和学习解耦。我们的结果表明，对 Montezuma's Revenge 以及 PrivateEye 这类相似的 Atari 游戏来说，探索是两个难题中更难的那一个。

## 为什么探索很难

策略梯度、Q-learning 等 model-free RL 方法靠随机尝试动作来探索。如果随机动作碰巧带来了奖励，它们就会被*强化*，智能体未来就更可能采取这些有益动作。这在奖励足够密集、随机动作有合理概率拿到奖励时很有效。然而，许多更复杂的游戏需要一长串非常具体的动作才能见到任何奖励，而这样的序列几乎不可能随机出现。


考虑一个游戏：需要精确的 N 个动作序列才能拿到第一个奖励。如果每个动作都以固定概率被选中，随机智能体要先玩上 exp(N) 量级的时长，才能盼来第一次奖励。

以 Montezuma's Revenge 为例，拿到第一把钥匙的概率可以分解为

p(get key) = p(get down ladder 1) * p(get down rope) * p(get down ladder 2) * p(jump over skull) * p(get up ladder 3).

N 个这样的概率相乘，得到的 p(get key) 会比任何一个单项输入概率都小上指数级。具有指数规模效应的算法在问题一变难就迅速崩溃，这限制了当前强化学习技术能解决的任务。

## 用演示简化探索

虽然 model-free RL 方法难以找到长动作序列，但处理较短序列表现不错。我们的核心洞察是：可以把任务分解成一组只需短动作序列的子任务课程（curriculum），从而让它更容易求解；我们构造这组课程的方式，是让每个 RL 回合都从一个演示状态开始。类似的思路最近也被用于 [robotics 的反向课程生成⁠(opens in a new window)](http://bair.berkeley.edu/blog/2017-12-20/reverse-curriculum/)——那里通过用随机动作反复扰动一组起始状态、挑选难度适中的新状态来构造课程。

我们的做法是让每个 RL 回合从先前录制的演示中的某个状态开始。训练早期，智能体每一局都从演示末尾附近起步。一旦智能体能在剩余游戏部分至少 20% 的 rollout 中追平或超过演示者的分数，我们就缓慢地把起点往回移。如此反复，直到智能体从头开始玩游戏、完全不用演示——此时我们就得到了一个 RL 训练出来的、在整局游戏中追平或超过人类专家的智能体。

通过把起始状态从演示末尾缓慢移回开头，我们保证智能体在任何阶段面对的都是一个它很可能解决的简单探索问题，因为它已经学会了通关剩余的大部分游戏。可以认为以这种方式求解 RL 问题是一种 [动态规划⁠(opens in a new window)](http://papers.nips.cc/paper/2378-policy-search-by-dynamic-programming.pdf)。如果拿到奖励需要一串 N 个特定动作，现在学习这串动作所需的时间与 N 成线性关系，而非指数。

从演示状态重置来开始回合的思路此前已被 [提出⁠(opens in a new window)](https://arxiv.org/abs/1607.05077v1)，但没有构造一个把起点从演示末尾逐步移回开头的课程。当与模仿学习（imitation learning）结合时，[若干⁠(opens in a new window)](https://arxiv.org/abs/1804.02717) [研究者⁠(opens in a new window)](https://arxiv.org/abs/1709.10089) 报告了这条路的好处。在我们的场景里，我们发现这样的课程对于从演示中获益至关重要。

下面展示我们的智能体如何用 RL、从演示状态开始每一局，学会在 Montezuma's Revenge 中拿到第一把钥匙。智能体开始玩游戏时，我们把它直接放在钥匙跟前，它只需要跳一下就能成功。等它稳定学会这一步，我们就缓慢把起点往回移。接下来它可能发现自己位于通往钥匙的梯子上半程。等它学会从这里爬完梯子，就让它从需要跳过骷髅的位置起步。学会之后，再让它从通往房间的绳索处起步，依此类推。最终，智能体从游戏原始起点出发，完全靠自己就能拿到钥匙。

## 与基于模仿的方法比较

最近，DeepMind 展示了通过模仿学习从演示学会 Montezuma's Revenge 的智能体：[一种方法⁠(opens in a new window)](https://arxiv.org/abs/1805.11592v1) 训练智能体复现 Montezuma's Revenge YouTube 视频中出现过的状态，[另一种技术⁠(opens in a new window)](https://arxiv.org/abs/1805.11593v1) 把复杂版的 Q-learning 与最大化演示动作似然结合起来。这些方法的优势是对环境的控制要求没有我们的技术那么高：它们不需要把环境重置到游戏起点以外的状态，也不假设能访问演示中遇到的完整游戏状态。我们的方法不同在于直接优化我们在乎的东西——游戏分数，而不是让智能体模仿演示；因此我们的方法不会过拟合一个可能次优的演示，并且在多人游戏里有潜在好处——在那里我们想要优化的对手不止演示中那一个。

## 遗留的挑战

虽然我们的智能体这种一步一步的学习比从零学起简单得多，但离"容易"还差得远。RL 智能体面临的一个挑战是：当它从较早的状态起步时，通常无法精确到达演示中后期的那个确切状态。一部分原因是智能体玩游戏用的 frameskip 与我们录制演示时不同，另一部分原因是动作中的随机性使得精确复现任何特定动作序列的可能性极低。因此智能体必须能在非常相似但不完全相同的状态之间泛化。我们发现这在 Montezuma's Revenge 上效果很好，但在我们尝试的其他一些 Atari 游戏（如 Gravitar 和 Pitfall）上就差得多。一个可能的原因是这些游戏需要解决更难的视觉问题：我们自己从下采样的屏幕也很难玩这些游戏，而在使用更大更深的神经网络策略后确实看到了一些改进。

我们遇到的另一个挑战是：像策略梯度这样的标准 RL 算法需要在探索与利用之间小心平衡：动作太随机，错误就多，从游戏开头永远到不了所需分数；动作太确定，智能体停止学习，因为它不再探索替代动作。因此，要在 Montezuma's Revenge 上取得报告中的结果，需要仔细调校 PPO 中熵奖励系数，并配合学习率、奖励缩放等其他超参数。对 Gravitar、Pitfall 等其他一些游戏，我们没能找到能训完整套课程的超参数。算法在多次运行之间仍有很大的随机波动，个别 Montezuma's Revenge 的运行不会收敛。我们希望未来的 RL 进展能带来对随机噪声和超参数选择更稳健的算法。

最后，与强化学习中的常见情况一样，我们发现训练出的神经网络策略在泛化能力上还达不到人类玩家的水平。[一种⁠(opens in a new window)](https://arxiv.org/abs/1709.06009v2) 测试泛化能力的方法是扰动策略：让动作变"粘"，即每一帧以 0.25 的概率重复上一个动作。用这种评估方式，我们训练的策略在 Montezuma's Revenge 上平均得分为 10,000。另一种做法是以 0.01 的概率采取随机动作（在 4 个 frameskip 步内重复），此时我们策略的平均得分为 8,400。根据我们的观察，同样的扰动也会显著降低人类玩家在 Montezuma's Revenge 上的得分，但幅度小一些。据我们所知，使用扰动策略后我们的结果仍然优于此前所有已发表的结果。用 0 到 30 个随机空操作开局来扰动学到的策略对结果没有明显损害，大多数 rollout 仍能拿到我们演示中的最终分数。

此前大多数从演示学习的工作聚焦于*模仿*——鼓励与演示中一致的行为；我们已经证明，直接优化回报也能取得好结果。这让智能体可以偏离演示行为，找到人类演示者可能没想过的新奇解法。通过在由"从演示状态重置"构造的子任务课程上训练，我们用这一技术解决了一个需要长动作序列的困难强化学习问题。
