# Wasmer 如何使用 Codex 构建面向边缘计算的 Node.js 运行时

团队结合 Codex 和 GPT‑5.5，承担更具雄心的项目，并以 10 到 20 倍的速度完成。

Wasmer 的工程师今年取得突破：他们找到了如何在 WebAssembly 沙盒中运行 Node.js 工作负载的方法，让开发者无需 Docker 就能运行 JavaScript 应用、MCP 和智能体。如果没有 Codex，这项工作原本需要一年；但有了 Codex，只用了两周。如今，他们成为首家在边缘层提供完整 Node.js 的云主机服务商。

> “我们实际上正在离开 IDE 本身。我们不再那么多地直接接触代码，而只是引导它朝我们希望的方向发展。”

## 以全新雄心构建

Wasmer 是一家年轻公司，团队规模不大，却有一个宏大目标：打造一个不受平台限制、可跨本地和全球环境扩展的边缘计算平台。

“我们承接的项目都极其雄心勃勃；如果没有 AI，这些项目会耗费我们漫长的时间，”创始人兼首席执行官 Syrus Akbary Nieto 说。“现在，事情变得简单、快速得多。”

这种简单性和速度直接转化为一个开创性项目：[Edge.js⁠（在新窗口中打开）](https://wasmer.io/posts/edgejs-safe-nodejs-using-wasm-sandbox)，这是一个可为 AI 和边缘计算运行 Node.js 工作负载的 JavaScript 运行时。

这是团队长期想要推进的项目，但他们并非一直拥有实现它的资源。“这里每个人都非常非常懂技术，但我们就是没有时间投入这些项目。而现在，我们可以推出以前不可能实现的新产品，”Nieto 解释道。

有了 Codex，Wasmer 工程师可以放大他们的工作成果。“我们的开发速度至少提升了 10 倍到 20 倍，”Nieto 说。

> “我们仅用两周就创建了一个 JavaScript 运行时。如果没有 AI、没有 Codex，我们很可能需要整整一年。”

—Syrus Akbary Nieto，创始人兼首席执行官

## 跨语言和代码层级进行推理

和许多团队一样，Wasmer 工程师起初对 AI 持怀疑态度。“一开始，我们并不太信任 AI 的输出，”Nieto 解释道。但当团队开始实验时，结果超出了他们的预期。“过去一年，尤其是过去几个月，我们一直在使用 Codex，结果真的非常非常好。”

随着 Codex 的推理能力不断发展，Wasmer 工程师花在手把手指导上的时间越来越少。“我们实际上正在离开 IDE 本身，也不再那么多地直接接触代码。我们只是引导它朝我们希望的方向发展，”Nieto 说。

团队从项目伊始到最终完成都使用 Codex，从构建最初的架构构件到打磨最终产品。在整个过程中，Codex 帮助团队发现缺陷并找出其根本原因。

“有些缺陷是我们没想到会遇到的；一开始发现它们，Codex 就直接进入调试，”Nieto 说。“令我们印象深刻的是，它从调试到找到根本原因并确定解决方案的速度非常快。”

Nieto 解释说，通常情况下，开发者需要具备专门知识才能发现其中许多缺陷。但 Nieto 表示，Codex “能够熟练使用控制台日志来跟踪调用，也能掌握像 LLD 这样访问汇编层内容的低层调试器。Codex 可以深入到非常底层，看到代码之下正在发生什么。”

> “有些细微之处我们并不了解，因为我们不是 C++ 专家。Codex 很早就发现了它们。”

—Syrus Akbary Nieto，创始人兼首席执行官

## 让不可能变得可行

Nieto 解释说，在 Edge.js 之前，无法在边缘运行 JavaScript 运行时。而在 Codex 之前，Wasmer 团队不可能在这样的时间表内承担如此雄心勃勃的项目。

“Codex 让一家小公司能够实现过去只有大公司才能做到的事情。如果没有它，这个项目确实不可能完成，”Nieto 说。

雄心更加坚定后，Wasmer 团队正着眼于更大的项目。“现在，我们手中已经有了以前无法实现的东西。我们需要关注更具挑战性的问题，”Nieto 说。
