# ChatGPT 插件

*注：ChatGPT 可用插件的[完整列表](https://openai.com/business/plugins/)见此处。*

我们已在 ChatGPT 中实现了对插件的初步支持。插件是专为语言模型设计的工具，以安全为核心原则，可帮助 ChatGPT 获取最新信息、执行计算或使用第三方服务。

按照我们的[渐进式部署](https://openai.com/index/language-model-safety-and-misuse/)理念，我们在 ChatGPT 中逐步推出插件，以便研究它们在真实世界的使用、影响以及[安全与对齐](https://openai.com/index/our-approach-to-alignment-research/)挑战——要实现[我们的使命](https://openai.com/index/planning-for-agi-and-beyond/)，这些都必须做对。

自 ChatGPT 发布起，用户就一直向我们索要插件（许多开发者也在用[类似的](https://arxiv.org/abs/2302.07842)[想法](https://www.adept.ai/act)[做](https://arxiv.org/abs/2302.04761)[实验](https://langchain.readthedocs.io/)），因为插件能解锁海量用例。我们从小范围用户开始，计划随着认识加深逐步扩大开放（面向插件开发者、ChatGPT 用户，以及在 alpha 阶段之后希望把插件集成进自己产品的 API 用户）。我们很高兴与社区一起塑造人机交互范式的未来。

获邀走出候补名单的插件开发者可以使用我们的[文档](http://platform.openai.com/docs/plugins/introduction)为 ChatGPT 构建插件；启用后，插件的清单会连同指导模型如何使用每个插件的文档一起出现在提示给语言模型的提示词中。首批插件由 [Expedia](https://www.expedia.com/)、[FiscalNote](https://fiscalnote.com/)、[Instacart](https://www.instacart.com/)、[KAYAK](https://www.kayak.com/)、[Klarna](https://www.klarna.com/)、[Milo](https://www.joinmilo.com/)、[OpenTable](https://www.opentable.com/)、[Shopify](https://www.shopify.com/)、[Slack](https://slack.com/)、[Speak](https://www.speak.com/)、[Wolfram](http://wolfram.com/) 和 [Zapier](https://zapier.com/) 创建。

我们自己还托管了两个插件：[网页浏览器](https://openai.com/index/chatgpt-plugins/#browsing)和[代码解释器](https://openai.com/index/chatgpt-plugins/#code-interpreter)。我们也开源了一个知识库[检索插件](https://github.com/openai/chatgpt-retrieval-plugin)的代码，任何开发者都可以自托管，用它希望补充给 ChatGPT 的信息来增强 ChatGPT。

今天，我们开始把插件 alpha 资格扩展到我们[候补名单](https://openai.com/waitlist/plugins/)上的用户和开发者。初期我们会优先少量开发者和 ChatGPT Plus 用户，但计划随时间逐步扩大开放。

## 概览

如今的语言模型虽然对多种任务都有用，但仍有局限。它们能学习的唯一信息就是训练数据。这些信息可能过时，且对所有应用一刀切。此外，语言模型开箱即用的唯一能力是输出文本。文本可以包含有用的指令，但要真正执行这些指令，还需要另一个过程。

插件之于语言模型，虽不完全贴切，但可以比作"眼睛和耳朵"，让它们获得太新、太私人或太具体而无法进入训练数据的信息。根据用户的显式请求，插件还可以让语言模型代表用户执行安全、受限的动作，从整体上提升系统的有用性。

我们预期会出现统一应用如何暴露"面向 AI 接口"的开放标准。我们正在对这样的标准可能长什么样做早期尝试，并寻找有意与我们共建的开发者提供反馈。

今天，我们开始逐步为 ChatGPT 用户启用早期协作者的既有插件，首先面向 ChatGPT Plus 订阅者。我们也开始向开发者开放为 ChatGPT 创建自己的插件的能力。

未来几个月，随着我们从部署中学习、持续改进安全系统，我们将迭代这一协议；并计划让使用 OpenAI 模型的开发者把插件集成到 ChatGPT 之外的自有应用中。

## 安全与更广泛的影响

把语言模型与外部工具连接，既带来新机会，也带来重大[新风险](https://cdn.openai.com/papers/gpt-4-system-card.pdf)。

插件有潜力应对大语言模型的诸多挑战，包括"幻觉"、跟上近期事件、以及（经授权）访问专有信息源。通过显式整合外部数据——如在线最新信息、基于代码的计算、或自定义插件检索的信息——语言模型可以用有据可查的引用强化其回答。

这些引用不仅提升了模型的实用性，也让用户能够评估模型输出的可信度、复核其准确性，从而可能缓解我们近期 GPT-4 [系统卡](https://cdn.openai.com/papers/gpt-4-system-card.pdf)中讨论过的过度依赖风险。最后，插件的价值可能远超弥补既有局限——它可以帮助用户处理从浏览商品目录、订票到点餐等各种新用例。

同时，也存在风险：插件可能因执行有害或意外动作、增强意图欺诈、误导或伤害他人的坏人的能力，而加大安全挑战。随着应用范围扩大，模型在新领域中因错误或未对齐行动造成负面后果的风险也会上升。从第一天起，这些因素就一直指导着我们插件平台的开发，我们已实施多道防护。

> "从第一天起，这些因素就一直指导着我们插件平台的开发，我们已实施多道防护。"

我们内外部都开展了红队演练，揭示了不少值得警惕的可能场景。例如，我们的红队发现：如果插件不加防护地发布，可以被用来执行精密的提示词注入（prompt injection）、发送欺诈与垃圾邮件、绕过安全限制、或滥用发给插件的信息。我们正利用这些发现指导"安全内建"（safety-by-design）的缓解措施，限制高风险插件行为、提高插件在用户体验中"何时、如何"运行的透明度。我们也用这些发现指导对插件访问权逐步部署的决策。

如果你是希望研究该领域安全风险或缓解手段的研究者，我们鼓励你使用我们的[研究者访问计划](https://openai.com/form/researcher-access-program/)。我们也欢迎开发者和研究者把插件相关的安全与能力评估提交到我们刚开源的 [Evals 框架](https://github.com/openai/evals)中。

插件很可能产生广泛的社会影响。例如，我们最近发布的一篇[工作论文](https://arxiv.org/abs/2303.10130)发现，能使用工具的语言模型带来的经济影响很可能远大于不能使用者；更一般地，与[其他](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=4350925)[研究者](https://arxiv.org/abs/2302.06590)的发现一致，我们预期本轮 AI 技术将极大影响职业转型、替代与创造的速度。我们期待与外部[研究者](https://share.hsforms.com/1NeBQeLgkS2SZPE3lQ6oNRQ4sk30)和[客户](https://share.hsforms.com/1dxauGUqlTsKdqFriJjriDA4sk30)合作研究这些影响。

### 浏览

受既有工作启发（我们自己的 [WebGPT](https://openai.com/index/webgpt/)，以及 [GopherCite](https://arxiv.org/abs/2203.11147)、[BlenderBot2](https://parl.ai/projects/blenderbot2/)、[LaMDA2](https://ai.googleblog.com/2022/01/lamda-towards-safe-grounded-and-high.html)[等](https://arxiv.org/pdf/2209.14375.pdf)），让语言模型从互联网读取信息，严格拓展了它们能讨论的内容量——从训练语料延伸到当下的新鲜信息。

这里举一个浏览为 ChatGPT 用户打开的体验例子：此前，模型只能礼貌地指出其训练数据不包含足够信息来回答。这个例子中，ChatGPT 检索了关于最新一届奥斯卡的近况，然后表演了大家熟悉的 ChatGPT 作诗技能——浏览作为增量体验的一种方式。

除了给终端用户显而易见的效用，我们认为让语言和对话模型做彻底、可解释的研究，对[可扩展对齐](https://openai.com/index/our-approach-to-alignment-research/)也有令人兴奋的前景。

#### 安全考量

我们打造的网页浏览插件让语言模型可以访问浏览器，其设计把安全与"做网络好公民"放在优先位置。插件的基于文本的浏览器只被允许发起 GET 请求，这减少了（但并未消除）某些类别的安全风险。这将浏览插件的用途限定在检索信息，排除了表单提交这类具有更大安全与风险面的"交易型"操作。

浏览通过 Bing 搜索 API 从网络获取内容。因此，我们继承了微软在两方面的大量工作：（1）信息源的可靠性与真实性；（2）防止检索问题内容的"安全模式"。插件运行在一个隔离服务中，ChatGPT 的浏览活动与我们其余基础设施相隔离。

为尊重内容创作者、遵守网络惯例，我们浏览器插件的 user-agent 标识是 [ChatGPT-User](https://openai.com/bot/)，并被配置为遵守网站各自的 robots.txt。这偶尔会导致"点击失败"的提示，意味着插件正在遵从网站不抓取它的指示。该 user-agent 只会用于代表 ChatGPT 用户采取直接行动，绝不以任何自动方式抓取网络。我们也公布了 [IP 出口范围](https://platform.openai.com/docs/plugins/production/ip-egress-ranges)。此外，我们实施了限流措施，避免向网站发送过量请求。

我们的浏览插件会展示访问过的网站，并在 ChatGPT 的回答中标注引用来源。这层额外的透明度帮助用户验证模型回答的准确性，也把功劳还给内容创作者。我们明白这是一种与网络互动的新方式，欢迎就"如何更好地把流量导回信息源、增进生态整体健康"提出反馈。

### 代码解释器

我们为模型提供一个可用的 Python 解释器，运行在沙箱化、防火墙隔离的执行环境中，并附带一些临时磁盘空间。解释器插件运行的代码在一个持久会话中执行，该会话在一次聊天对话期间保持存活（有超时上限），后续调用可以在彼此基础上继续。我们支持把文件上传到当前对话工作区，也支持下载你的成果。

我们希望模型能用它们的[编程](https://arxiv.org/abs/2107.03374)[技能](https://arxiv.org/abs/2303.08774)，为计算机大多数基础能力提供更自然的接口。相当于身边有一位随叫随到、以你的指尖速度干活的初级程序员，全新的工作流可以毫不费力、高效运转，也让编程的好处惠及新的人群。

从初步的用户研究中，我们识别出代码解释器特别有用的用例：

- 求解数学问题，包括定量与定性
- 做数据分析与可视化
- 文件格式之间的转换

邀请用户试用代码解释器集成，发现更多有用的任务。

#### 安全考量

把模型接到编程语言解释器的首要考量，是恰当地沙箱化执行，使 AI 生成的代码在现实世界不产生意外副作用。我们在加固环境中执行代码，并使用严格的网络控制防止被执行代码访问外部互联网。此外，我们为每个会话设置了资源上限。禁用网络访问限制了代码沙箱的功能，但我们相信这是正确的初期权衡。[第三方插件](https://openai.com/index/chatgpt-plugins/#third-party-plugins)正是作为"安全第一"的方式，被设计来把我们的模型与外部世界连接。

## 检索

开源的检索插件让 ChatGPT（经授权）访问个人或组织的信息源。它允许用户获取其数据源中最相关的文档片段——如文件、笔记、邮件或公开文档——方式就是用自然语言提问或表达需求。

作为开源、自托管的方案，开发者可以部署自己的插件版本并向 ChatGPT 注册。该插件使用 [OpenAI embeddings](https://platform.openai.com/docs/guides/embeddings)，允许开发者选择一种向量数据库（[Milvus](https://milvus.io/)、[Pinecone](https://www.pinecone.io/)、[Qdrant](https://qdrant.tech/)、[Redis](https://redis.io/docs/stack/search/reference/vectors/)、[Weaviate](https://weaviate.io/) 或 [Zilliz](https://zilliz.com/)）来索引与检索文档。信息源可以通过 webhook 与数据库同步。

要开始使用，请访问[检索插件仓库](https://github.com/openai/chatgpt-retrieval-plugin)。

### 安全考量

检索插件让 ChatGPT 可以在内容的向量数据库中搜索，并把最佳结果加入 ChatGPT 会话。这意味着它没有任何外部副作用，主要风险在于数据授权与隐私。开发者只应把他们有权使用、且可以在用户的 ChatGPT 会话中共享的内容加入检索插件。

## 第三方插件

第三方插件由一个[清单文件](https://platform.openai.com/docs/plugins/getting-started/)描述，其中包含对插件能力及调用方式的机器可读描述，以及面向用户的文档。

#### JSON

```
1{2  "schema_version": "v1",3  "name_for_human": "TODO Manager",4  "name_for_model": "todo_manager",5  "description_for_human": "Manages your TODOs!",6  "description_for_model": "An app for managing a user's TODOs",7  "api": { "url": "/openapi.json" },8  "auth": { "type": "none" },9  "logo_url": "https://example.com/logo.png",10  "legal_info_url": "http://example.com",11  "contact_email": "hello@example.com"12}
```

*一个待办事项管理插件的清单文件示例*

创建插件的步骤是：

- 构建一个 API，包含你希望语言模型调用的端点（可以是新 API、现有 API，或专为 LLM 设计的对现有 API 的包装）。
- 编写记录你的 API 的 OpenAPI 规范，以及一个清单文件——它链接到 OpenAPI 规范，并包含一些插件专有的元数据。

在 [chatgpt.com](https://chatgpt.com/) 开始对话时，用户可以选择启用哪些第三方插件。已启用插件的文档会作为对话上下文的一部分呈现给语言模型，使模型能够按需调用相应的插件 API 来满足用户意图。目前插件为调用后端 API 而设计，但我们也在探索可调用客户端 API 的插件。
