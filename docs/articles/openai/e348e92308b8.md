# GPT-4 API 全面可用及 Completions API 旧模型弃用

***2024 年 4 月 24 日更新：ChatGPT API 这一名称已停用。本博客中提及的 ChatGPT API 均指 GPT‑3.5 Turbo API。***

从今天起，所有付费 API 客户都能访问 GPT‑4。三月我们[推出了 OpenAI API⁠](https://openai.com/index/introducing-chatgpt-and-whisper-apis/)，本月早些时候我们[发布了首批更新⁠](https://openai.com/index/function-calling-and-other-api-updates/)，面向对话型模型。我们设想的未来是：对话型模型能够支撑任何用例。今天我们宣布对 Completions API 的旧模型进行弃用，并建议用户采用 Chat Completions API。

## GPT-4 API 全面可用

GPT‑4 是我们能力最强的模型。自三月以来，已有数百万开发者申请访问 GPT‑4 API，而借助 GPT‑4 打造的[创新产品⁠](https://openai.com/stories/)范围每天都在扩大。今天，所有有过成功付款记录现有 API 开发者都能访问具备 8K 上下文的 GPT‑4 API。我们计划在本月底前向新开发者开放访问权限，此后视算力情况逐步提高速率限制。

基于这些模型面向生产规模使用的稳定性和成熟度，我们也一并让 GPT‑3.5 Turbo、DALL·E 和 Whisper API 全面可用。我们正在安全地为 GPT‑4 和 GPT‑3.5 Turbo 启用微调，预计该功能将于今年晚些时候上线。

## 从文本补全转向对话补全

我们在三月推出了 [Chat Completions API⁠(在新窗口打开)](https://platform.openai.com/docs/guides/gpt/chat-completions-api)，它如今已占我们 API GPT 用量的 97%。

最初的 Completions API 于 2020 年 6 月推出，用来提供一个自由文本提示词，以便与我们的语言模型交互。此后我们认识到，通过更结构化的提示词接口我们往往能提供更好的结果。对话范式已被证明十分强大，既能处理绝大多数既往用例和新的会话需求，又提供了更高的灵活性与精确度。特别是 Chat Completions API 的结构化接口（如系统消息、函数调用）和多轮对话能力，让开发者能够构建会话体验并完成各种补全任务。它还有助于降低提示词注入攻击的风险，因为用户提供的内容可以在结构上与指令分离。

我们计划继续把大部分平台投入放在这一方向上，因为我们相信它会为开发者提供越来越强大且易用的体验。我们正在快速补齐 Chat Completions API 剩下的几处缺口，例如补全 token 的对数概率，以及增强的可控性以降低回答的“话痨”程度。

## Completions API 旧模型弃用

随着我们对 Chat Completions API 投入的增加以及优化算力的努力，我们将在 6 个月后退役部分使用 Completions API 的旧模型。虽然该 API 仍可访问，但我们从今天起会在开发者文档中把它标注为“legacy”（遗留）。我们计划让未来的模型和产品改进都聚焦在 Chat Completions API 上，并且没有计划公开发布使用 Completions API 的新模型。

从 2024 年 1 月 4 日起，[较旧的补全模型⁠(在新窗口打开)](https://platform.openai.com/docs/deprecations)将不再可用，并由以下模型替代：

| **旧模型** | **新模型** |
| --- | --- |
| ada | babbage-002 |
| babbage | babbage-002 |
| curie | davinci-002 |
| davinci | davinci-002 |
| davinci-instruct-beta | gpt-3.5-turbo-instruct |
| curie-instruct-beta | gpt-3.5-turbo-instruct |
| text-ada-001 | gpt-3.5-turbo-instruct |
| text-babbage-001 | gpt-3.5-turbo-instruct |
| text-curie-001 | gpt-3.5-turbo-instruct |
| text-davinci-001 | gpt-3.5-turbo-instruct |
| text-davinci-002 | gpt-3.5-turbo-instruct |
| text-davinci-003 | gpt-3.5-turbo-instruct |

使用基础 GPT‑3 模型稳定名称（`ada`、`babbage`、`curie`、`davinci`）的应用将在 2024 年 1 月 4 日自动升级到上面列出的新模型。在接下来几周内，这些新模型也将可通过在 API 调用中指定以下模型名称（`babbage-002`、`davinci-002`）来供早期测试使用。

使用其他较旧补全模型（如 `text-davinci-003`）的开发者需要在 2024 年 1 月 4 日前手动升级其集成，在 API 请求的“model”参数中指定 `gpt-3.5-turbo-instruct`。`gpt-3.5-turbo-instruct` 是一个 InstructGPT 风格的模型，训练方式与 `text-davinci-003` 类似。这一新模型是 Completions API 中可直接替换的选项，并将在接下来几周内可供早期测试。

希望在 2024 年 1 月 4 日之后继续使用其微调模型的开发者，需要在新的基础 GPT‑3 模型（`babbage-002`、`davinci-002`）或更新模型（`gpt-3.5-turbo`、`gpt-4`）之上重新微调替代模型。一旦该功能在今年晚些时候可用，我们将优先向此前微调过旧模型的用户开放 GPT‑3.5 Turbo 和 GPT‑4 微调。我们明白，从基于自有数据微调的模型上迁移出来是充满挑战的。我们将为此前微调过模型的用户提供支持，让这一过渡尽可能顺畅。

在接下来几周，我们会联系近期使用过这些旧模型的开发者，并会在新的补全模型可供早期测试时提供更多信息。

## 旧嵌入模型弃用

旧嵌入模型（如 `text-search-davinci-doc-001`）的用户需要在 2024 年 1 月 4 日前迁移到 `text-embedding-ada-002`。我们于 2022 年 12 月发布了 `text-embedding-ada-002`，并发现它比之前的模型更强大也更划算。如今 `text-embedding-ada-002` 已占所有嵌入 API 用量的 99.9%。

我们意识到，对于使用这些旧模型的开发者来说这是一个重大变化。关停这些模型并非我们轻率做出的决定。我们将承担用户使用这些新模型重新嵌入内容的费用。未来几天我们会与受影响的用户取得联系。

## Edits API 弃用

Edits API 及其相关模型（如 `text-davinci-edit-001` 或 `code-davinci-edit-001`）的用户需要在 2024 年 1 月 4 日前迁移到 GPT‑3.5 Turbo。Edits API beta 是一个早期的探索性 API，旨在让开发者根据指令返回提示词的编辑版本。我们在开发 `gpt-3.5-turbo` 和 Chat Completions API 时充分考虑了来自 Edits API 的反馈，后者现在可用于同样的目的：

- [ChatGPT](https://openai.com/news/?tags=chatgpt)
- [API 平台](https://openai.com/news/?tags=api-platform)
- [2024](https://openai.com/news/?tags=2024)
