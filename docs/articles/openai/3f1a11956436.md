# 以一致标准推动广泛使用


过去几个月，我们与客户和合作伙伴携手，推动提供我们模型的各项服务采用一致的安全政策。我们也在更新使用政策，让这些要求更清晰，更便于开发者遵循。

GPT‑6 Astra 等模型拓展了开发者和企业能够构建的应用范围。随着这些能力不断增强，我们正努力确保安全防护措施持续有效，并在提供我们模型的各项服务中得到一致落实。

## 责任从我们自身做起

在部署模型之前，我们会评估其能力和风险，通过训练使其遵循安全要求，并测试在有人蓄意绕过安全防护措施时，这些措施是否仍然有效。正如我们在[安全与对齐方法](https://openai.com/safety/how-we-think-about-safety-alignment/)中所述，我们将多种安全防护措施结合使用，使其相互增强。

部署后，我们会监测潜在的滥用行为，并调查可能存在的问题。例如，为了[减少网络滥用](https://openai.com/index/strengthening-cyber-resilience/)，我们会训练模型拒绝有害请求，并利用系统在多次交互中识别可疑模式，以确定如何应对。可信访问计划提供了另一层保护，并为使用我们最强大的能力设定资格要求和访问条件。

有些安全防护措施内置于模型之中，另一些则依赖于模型周边的系统和人员。无论用户直接访问我们的模型，还是通过合作伙伴访问，这两类措施都必须有效。

## 各项服务采用一致标准

开发者和企业应当能够自由选择通过哪些服务访问我们的模型，同时享有一致的安全防护。我们制定了相关政策，以统一各服务提供商的安全防护措施，并正与每一家合作伙伴携手，确保其实施情况达到或超过我们的安全标准。无论用户直接通过 OpenAI、托管模型的合作伙伴，还是通过转售合作伙伴访问我们的模型，这些政策都适用。

这些政策要求提供 OpenAI 模型访问服务的合作伙伴维持与我们一致的安全防护措施，调查潜在违规行为，并在发现问题时采取适当行动。这也包括协同执行政策，确保限制措施在提供我们模型访问服务的各个平台上持续有效。

要将这些要求落到实处，就需要考虑不同服务的运作方式以及客户的使用方式。我们与客户及合作伙伴在[私密安全处理](https://openai.com/index/offering-zero-data-retention-for-frontier-models/)方面的合作就是一个例子：我们既能制定有效的安全防护措施，也能让客户在处理敏感数据时拥有更多选择和控制权。

## 清晰的政策与可预期的执行

我们也在更新[使用政策](https://openai.com/policies/usage-policies/)，进一步明确安全开发模型以及在敏感场景中使用 AI 的规则。新版政策将于 2026 年 11 月 20 日生效。在上述工作的基础上，更新后的使用政策要求模型路由器、AI 网关等直接提供我们模型访问能力的服务，在提供此类访问之前，必须获得我们的审核与批准。

我们将持续说明哪些行为被允许、哪些行为受到限制，以及客户和合作伙伴如何提出问题或解决合规疑虑。

随着模型能力不断增强，我们将持续改进检测、调查和应对滥用行为的方式。客户可能因终端用户的行为、账户遭入侵或 API 密钥泄露而面临滥用问题，我们会与他们合作，了解并解决这些问题。

我们还在与客户合作引入 SafetyIDs。客户可以提供这些标识，帮助我们在调查中区分不同的终端用户，而无需让 OpenAI 知晓这些用户的身份。借助 SafetyIDs，我们可以更精准地应对潜在滥用，同时减少对其他用户的影响。

我们根据有记录可查的行为和风险作出政策执行决定，一致地应用规则，并采取与具体情况相称的应对措施。在限制访问后，如果相关方在行为、承诺或安全防护措施上作出实质性改变，解决了导致我们作出该决定的问题，我们就会重新评估这些限制。

我们希望让更多人从 AI 中受益。清晰的规则和一致的安全防护措施，应当让开发者和企业更轻松地构建应用、参与竞争，并选择最适合自己的服务。
