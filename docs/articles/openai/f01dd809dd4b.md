## 提示（Prompting）总览

提示就是你告诉 ChatGPT 想了解什么、想做什么、想改什么的方式。一条提示可以是一个问题、一条指令或一个目标。你不需要技术性的语法，也不需要死板的公式。用你自己的话开始，审阅回答，再用后续消息打磨结果。

简短的提示往往就够了。对更大或更重要的任务，把真正要紧的部分写进去：

- **目标（Goal）：** ChatGPT 应该做什么？
- **上下文（Context）：** 哪些信息或来源会有帮助？
- **输出（Output）：** 你需要什么格式、长度、详细程度？
- **边界（Boundaries）：** 什么必须保持不变？ChatGPT 应该避免什么，或在做之前该先跟你确认什么？

只用有帮助的部分。不必每一项都填满，也不必遵循固定格式。

## 描述你需要的结果

从结果说起，而不是一步步的详细清单。当受众或格式会改变 ChatGPT 该产出的内容时，就把这些细节写进去。

```
把这些会议笔记变成一份给项目团队的简短更新。
把决策和下一步放在最前面。
```

这条提示说清了要创建什么、给谁看。只有当过程本身重要时才描述过程；否则，给 ChatGPT 留出搜索、比较信息和调整方法的空间。

## 添加有用的上下文

分享可能改变结果的信息。只提供真正重要的来源，并说明 ChatGPT 该从每个来源里取什么。

- 当你想让 ChatGPT 总结、比较、转换或 [创建供审阅的文件](https://learn.chatgpt.com/codex/artifacts-viewer) 时，附上文档、表格、演示文稿或 PDF 文件。
- 当任务依赖视觉上下文时，添加截图、图表或其他 [图像输入](https://learn.chatgpt.com/codex/image-inputs)，并指出重点区域，不要只扔一张图。
- 当答案取决于最新信息时，要求 ChatGPT 使用 [网页搜索](https://learn.chatgpt.com/codex/web-search)；当你需要核对结果时，要求给出来源。
- 当一组相关聊天需要共享文件、来源或本地文件夹时，使用 [项目（project）](https://learn.chatgpt.com/codex/projects)。

### 使用连接的数据源

当 ChatGPT 能访问连接的数据源（connected sources）时，告诉它该去哪里找、该找到什么。不必把它要执行的每次搜索都描述一遍。

```
使用 Drive 里最新版本的项目计划，以及该项目 Slack 频道里的相关决策和动态，
准备一份状态更新。
```

连接数据源需要安装对应的插件（plugin），可用性取决于你的套餐和工作区设置。

### 使用插件

插件为 ChatGPT 和 Codex 提供可复用的指令，以及与 Google Drive、Gmail、Slack、GitHub 等工具的连接。两个产品共用同一个通用目录来获取公开插件。直接说出你需要的结果，让当前所在的产品界面从它可用的工具里自行选择。在 ChatGPT 中，在输入框里输入 `@` 可以选择特定插件。

Learn about plugins

Find, install, and use plugins in ChatGPT and Codex.

### 个性化 ChatGPT

把应跨聊天生效的偏好放进 **Settings > Personalization**（设置 > 个性化）作为自定义指令。只对当前聊天有意义的细节则留在提示里。

Review personalization settings

Set a default personality, custom instructions, and other app preferences.

## 设好边界，防住真实的问题

边界就是那几条让 ChatGPT 避免制造额外工作或执行你并未打算的操作的指令。当改错细节会让结果不可用，或者你想在影响他人之前先审一遍时，就加一条边界。

- 已批准的日期和预算数字保持不变。
- 只使用提供的来源；缺信息就标记出来，不要猜。
- 建议保持在既定预算范围内。
- 把消息做成草稿，不要发送。

盯住最重要的一两条边界即可，不必控制 ChatGPT 的每一步。

## 让结果开箱即用

告诉 ChatGPT 你打算怎么用这个结果。这能帮它选对长度、详细程度和组织方式。

- 做成一页纸摘要，让总监在会前能快速扫完。决策和下一步放最前面。
- 把这些笔记变成一封跟进邮件，包含决策、负责人和截止日期。
- 做一张计划支出与实际支出的对照表，突出所有差异超过 10% 的行。

对重要工作，让 ChatGPT 做最后检查，比如确认每个行动项都有负责人和截止日期，或标记出它无法核实的信息。然后在你使用或分享之前自己再过一遍。

## 用后续消息改进结果

第一条提示不需要完美。看过结果之后，直接提出你要的具体改动。

```
开头更直接一些，论据保留，把建议挪到背景部分之前。
```

你可以补一个缺失的来源、纠正方向、要求换一种方案、调整详略程度——都不用从头再来。

### 转向（Steer）与排队（Queue）

当 Codex 正在工作时，你可以不等当前这轮跑完就发下一条消息：

- **Steer（转向）** 把消息加入当前这轮运行。用它来改变方向、补充遗漏的细节或分享新信息。
- **Queue（排队）** 把消息存到下一轮。用在那种应该等当前工作结束后再处理的后续请求上。

在 ChatGPT 桌面应用中，可在 [**Settings > General > Follow-up behavior**](https://learn.chatgpt.com/codex/app/settings#general)（设置 > 通用 > 后续消息行为）选择默认方式。排队的消息会显示在输入框上方，你可以编辑、重新排序、发送或删除。该设置还会显示单条消息临时使用另一种行为的快捷键。

在 Codex CLI 中，Codex 工作时按 Enter 可以给当前轮转向，按 Tab 则把消息排到下一轮。详见 [交互式快捷键](https://learn.chatgpt.com/codex/developer-commands?surface=cli#cli-interactive-shortcuts)。

## 把各部分拼在一起

对于使用连接数据源的项目更新，一条完整的提示可能长这样：

```
为周一的管理层会议准备一页纸的项目状态更新。使用 Drive 里最新版本的
项目计划，以及该项目 Slack 频道里的相关决策和动态。

把管理层需要做的决策和下一步放在最前面。总结进展、风险、负责人和
截止日期。已批准的日期和预算数字保持不变。标记任何冲突或缺失的信息，
不要发送或发布任何内容。

收尾前，检查每个下一步是否都有负责人和截止日期。
```

这条提示覆盖了**目标**、**上下文**、**输出**和**边界**，并要求做最后检查——但没有把每一步都写死。

## 聊天（Chat）提示示例

用 Chat 处理提问、想法、草稿和日常决策。从你想要的结果开始，只在细节会改变答案时再补充。

### 理解一个主题

```
向一个从未投资过的人解释复利是如何运作的。
用一个具体的例子，并定义你引入的所有金融术语。
```

### 起草并打磨写作

```
起草一封友好的邮件，婉拒这个邀请，理由是我将要出差。
控制在 120 词以内，并为以后的活动留下余地。
```

### 比较选项

```
从一个每年国际旅行两次的人的角度比较这两个手机套餐。
用表格列出重要差异，然后推荐一个并说明取舍。
```

### 制定实用计划

```
规划五道 30 分钟内能完成的工作日晚餐。避免花生，
各餐之间复用食材，最后给出一张合并的采购清单。
```

## ChatGPT Work 的提示方式

快速提问、简短改写、头脑风暴、轻量草稿用 Chat 即可。当任务需要调用多个来源或工具、包含一连串步骤、要做修改，或产出较大的交付物时，用 ChatGPT Work。

在 ChatGPT Work 里，描述你需要的结果、提供源材料、指明受众，并说明你会如何审阅产出。要求 ChatGPT 先规划、收集所需信息、创建文件，并在结束前自行检查。

### 高效使用 ChatGPT Work

ChatGPT Work 适合耗时或重复性任务，也适合产出可复用的成品文件。一个消耗更多积分（credits）的任务，只要它能节省时间、提升质量或帮你做出重要决策，依然是值得的。

从一个你能审阅的结果开始：

- 只包含相关的来源，必要时限定日期范围。
- 定义受众、输出格式和期望长度。
- 把必须完成的工作与可选的改进、润色分开。
- 当方法本身重要时，要求先给出计划。在 ChatGPT 发送、发布或修改他人依赖的信息之前，要求先获得你的批准。
- 如果任务开始做你已经不需要的活儿，缩小范围或直接停止。

审阅第一版结果，完善指令，之后复用这套跑通的工作流。

### 把源材料变成成品文件

```
使用附件中的季度报告，创建一份管理层简报和一个六页的演示文稿。

受众是高管团队。把他们需要做的三个决策放在最前面，区分开报告中的
事实与你的分析，为每个数字标注来源文件，并在完成前检查简报和幻灯片
是否一致。
```

### 研究一个决策

```
为一家 50 人的公司研究三个客户支持平台。使用最新来源比较价格、
安全性、集成和迁移工作量。交付一份推荐备忘录，附链接、假设，以及
我们在签约前应该回答的问题。
```

### 协调一次发布

```
根据附件中的产品简介制定一份发布计划。包含时间线、负责人、依赖项、
风险、公告草稿、客户 FAQ，以及发布当天的核对清单。在生成最终文件之前，
标记所有尚未做出的决策。
```

对于重复性工作，先在普通聊天里把提示打磨好。输出稳定可靠后，[在该聊天内定时任务](https://learn.chatgpt.com/codex/automations#schedule-a-task-inside-a-chat)。如果希望每次定时运行都开一个新聊天，就改为创建独立的定时任务。

## Codex 的提示方式

当你想让 ChatGPT 处理代码、代码库或开发者工具时，用 Codex。一条有用的 Codex 提示会说明你想要的行为、指向相关的代码或复现步骤、保留重要约束，并写明如何验证改动。

对于多步任务，当你想让 Codex 先调查、先提出方案再动手编辑时，在应用输入框里输入 `/plan`。当 [Goal mode](https://learn.chatgpt.com/codex/long-running-work)（目标模式）可用时，计划之后用 `/goal` 设定一个持久目标。当前命令列表见 [应用斜杠命令](https://learn.chatgpt.com/codex/reference/slash-commands)。

### 如何阅读这些示例

每个工作流都包含：

- **什么时候用**，以及哪种 Codex 界面最合适（IDE、CLI 还是云端）。
- **步骤**，附示例用户提示。
- **上下文说明**：Codex 能自动看到什么，vs 你需要手动附加什么。
- **验证**：如何检查产出。

> 注：IDE 扩展会自动把你打开的文件作为上下文。在 CLI 中，请明确写出路径，或用 /mention 和 @ 路径自动补全来附加文件。

Codex 在一个 [沙箱](https://learn.chatgpt.com/codex/sandboxing)（sandbox）内运行本地命令，文件和访问网络都受限。如果任务需要跨越这条边界，Codex 会先按照你的审批策略请求许可再继续。

### 解读代码库

适用于：入职新团队、接手一个服务，或想弄清某个协议、数据模型、请求流程。

#### IDE 扩展工作流（本地探索最快）

- 打开最相关的文件。
- 选中你关心的代码（可选，但推荐）。
- 提示 Codex：`解释请求如何在所选代码中流转。包括：- 每个涉及模块职责的简短总结 - 数据在哪里被校验 - 修改这块代码时要注意的一两个"坑"`

验证：

- 让它输出一张你可以核对的图或清单：

```
用编号列表总结请求流转的步骤，然后列出涉及的文件。
```

#### CLI 工作流（适合想要完整记录 + shell 命令的场景）

- 启动交互式会话：`codex`
- 附加文件（可选）并提示：`我需要理解这个服务使用的协议。读取 @foo.ts @schema.ts，解释 schema 和请求/响应流程。重点是必填与可选字段，以及向后兼容规则。`

上下文说明：

- 你可以在输入框用 `@` 插入工作区里的文件路径，或用 `/mention` 附加特定文件。

### 修一个 bug

适用于：你有一个能在本地复现的失败行为。

#### CLI 工作流（复现 + 验证的紧凑循环）

- 在仓库根目录启动 Codex：`codex`
- 给 Codex 一份复现配方，加上你怀疑的文件：`Bug：在设置页点击 "Save" 有时会显示 "Saved" 但改动并未持久化。 复现：1) 启动应用：npm run dev 2) 进入 /settings 3) 切换 "Enable alerts" 4) 点击 Save 5) 刷新页面：开关被重置。 约束：- 不要改动 API 的形状。- 修复保持最小化，可行的话加一个回归测试。 先在本地复现这个 bug，然后提出补丁并运行检查。`

上下文说明：

- 由你提供：复现步骤和约束（这比笼统的描述重要得多）。
- 由 Codex 提供：命令输出、它发现的调用点，以及它触发的堆栈跟踪。

验证：

- Codex 应在修复后重新跑一遍复现步骤。
- 如果你有标准的检查流水线，让它跑起来：

```
修复之后，运行 lint 加最小范围的相关测试套件。报告命令和结果。
```

#### IDE 扩展工作流

- 打开你认为 bug 所在的文件，以及最近的调用方。
- 提示 Codex：`找出导致显示 "Saved" 但改动未持久化的 bug。提出修复后，告诉我在 UI 里如何验证。`

### 写一个测试

适用于：你想精确定义测试范围。

#### IDE 扩展工作流（基于选区）

- 打开包含该函数的文件。
- 选中定义函数的行，通过命令面板选择 "Add to Codex Thread" 把这些行加入上下文。
- 提示 Codex：`为这个函数写一个单元测试。遵循其他测试使用的约定。`

上下文说明：

- 由 "Add to Codex Thread" 命令提供：选中的行（这就是"行号"范围），加上打开的文件。

#### CLI 工作流（在提示中描述路径 + 行范围）

- 启动 Codex：`codex`
- 用函数名提示：`为 @transform.ts 中的 invert_list 函数添加测试。覆盖正常路径以及各种边界情况。`

### 从截图做原型

适用于：你想把设计稿、截图或 UI 参考变成可运行的原型。

#### CLI 工作流（图像 + 提示）

- 把截图保存到本地（例如 `./specs/ui.png`）。
- 运行 Codex：`codex`
- 把图片文件拖进终端，附加到提示里。
- 再补上约束和结构：`基于这张图创建一个新仪表盘。 约束：- 使用 react、vite 和 tailwind，用 typescript 写代码。- 尽可能贴合间距、排版和布局。 产出：- 一个渲染该 UI 的新路由/页面 - 所需的小型组件 - 一份 README.md，写明本地运行步骤`

上下文说明：

- 图片提供了视觉需求，但实现约束（框架、路由、组件风格）仍需你自己指定。
- 图片表现不出来的行为用文字补充，例如悬停状态、校验规则或键盘交互。

验证：

- 让 Codex 启动开发服务器（在允许的情况下），并告诉你具体看哪里：

```
启动开发服务器，告诉我查看原型的本地 URL/路由。
```

#### IDE 扩展工作流（图像 + 现有文件）

- 在 Codex 聊天中附加图片（拖放或粘贴）。
- 提示 Codex：`创建一个新设置页。以附上的截图为目标 UI。遵循本项目其他文件的设计与视觉模式。`

### 用实时刷新迭代 UI

适用于：你想要"设计 → 微调 → 刷新 → 再微调"的紧凑循环，由 Codex 边改代码。

#### CLI 工作流（跑 Vite，用小提示迭代）

- 启动 Codex：`codex`
- 在另一个终端窗口启动开发服务器：`npm run dev`
- 提示 Codex 做改动：`为落地页提出 2-3 个样式改进方案。`
- 选定一个方向，用小而具体的提示迭代：`用方案 2。只改头部：- 排版更偏杂志风 - 增大留白 - 确保在移动端依然好看`
- 继续提出聚焦的请求：`下一轮：减少视觉噪音。保留布局，但简化颜色，去掉多余边框。`

验证：

- Codex 更新代码时，你在浏览器里查看变化。
- 喜欢的改动就提交，不喜欢的就回滚。
- 如果你回滚或修改了某处编辑，告诉 Codex，免得它处理下一条提示时覆盖你的改动。

### 把重构委派给云端

适用于：你想带着本地上下文先设计方案，再把冗长的实现交给可以并行运行的云端聊天。

#### 本地规划（IDE）

- 确保当前的工作已提交、至少已 stash，以便干净地比较改动。
- 让 Codex 产出一份重构计划。如果你有 `$plan` 技能可用，就显式调用：`$plan 我们需要重构 auth 子系统：- 拆分职责（token 解析 vs 会话加载 vs 权限）- 减少循环导入 - 提升可测试性。 约束：- 不改变用户可见的行为 - 保持公共 API 稳定 - 包含一份分步迁移计划`
- 审阅计划并协商修改：`修订计划：- 明确写出每个里程碑具体哪些文件移动 - 加入回滚策略`

上下文说明：

- 当 Codex 能在本地扫描当前代码（入口点、模块边界、依赖图线索）时，规划效果最好。

#### 云端委派（IDE → Cloud）

- 如果还没有，先设置一个 [Codex 云环境](https://learn.chatgpt.com/codex/environments/cloud-environment)。
- 点击输入框下方的云图标，选择你的云环境。
- 输入下一条提示时，Codex 会在云端创建一个新聊天，并带上现有聊天的上下文（包括计划和任何本地源码改动）。`实现计划中的里程碑 1。`
- 审阅云端 diff，需要就迭代。
- 直接从云端创建 PR，或把改动拉回本地测试收尾。
- 继续实现计划的后续里程碑。

委派到云端的任务运行在隔离环境中。除非你为该环境开启了互联网访问，否则 agent 阶段默认断网。了解更多见 [云端互联网访问](https://learn.chatgpt.com/codex/cloud/internet-access)。

### 做一次本地代码评审

适用于：提交或创建 PR 之前，想有"第二双眼睛"把把关。

#### CLI 工作流（评审你的工作区）

- 启动 Codex：`codex`
- 运行评审命令：`/review`
- 可选：给出聚焦指令：`/review 重点关注边界情况和安全问题`

验证：

- 按评审意见应用修复，然后重新运行 `/review` 确认问题已解决。

### 评审一个 GitHub PR

适用于：不想把分支拉到本地就能获得评审反馈。

使用前，请先在你的仓库上启用 Codex **Code review**（代码评审）。见 [Code review](https://learn.chatgpt.com/codex/third-party/github)。

#### GitHub 工作流（评论驱动）

- 在 GitHub 上打开这个 pull request。
- 留下一条 @Codex 并写明关注重点的评论：`@codex review`
- 可选：提供更明确的指令。`@codex review 安全漏洞和安全隐患`

### 更新文档

适用于：你需要一次准确、清晰的文档改动。

#### IDE 或 CLI 工作流（本地编辑 + 本地校验）

- 确定要改的文档文件，打开它们（IDE）或用 `@` 提及（IDE 或 CLI）。
- 用范围与校验要求提示 Codex：`更新 "advanced features" 文档，补充身份验证排障指引。确保所有链接有效。`
- Codex 起草完改动后，审阅文档并按需迭代。

验证：

- 阅读渲染后的页面。
