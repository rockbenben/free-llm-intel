# Procgen Benchmark

我们发布 Procgen Benchmark——16 个简单易用的程序化生成环境，可直接度量强化学习 agent 学会可泛化技能的速度。

## 快速上手

#### Bash

```
1$ pip install procgen # install2$ python -m procgen.interactive --env-name starpilot # human3$ python &lt;&lt;EOF # random AI agent4import gym5env = gym.make('procgen:procgen-coinrun-v0')6obs = env.reset()7while True:8    obs, rew, done, info = env.step(env.action_space.sample())9    env.render()10    if done:11        break12EOF
```

我们发现，所有 Procgen 环境都需要在 500–1000 个不同关卡上训练后才能泛化到新关卡，这说明标准 RL 基准在每个环境内需要多得多的多样性。Procgen Benchmark 已成为 OpenAI RL 团队的标准研究平台，希望它能加速社区创造更好的 RL 算法。

## 环境多样性是关键

在[多个](https://arxiv.org/abs/1804.06893) [环境中⁠](https://openai.com/index/quantifying-generalization-in-reinforcement-learning/)https://arxiv.org/abs/1806.10729，人们观察到 agent 会对异常庞大的训练集过拟合。这一证据提出了一个可能性：过拟合普遍存在于如[街机学习环境](https://arxiv.org/abs/1207.4708)这类经典基准中——它长期以来一直被视为强化学习（RL）的黄金标准。不同游戏之间的多样性是 ALE 最大的优点之一，但对泛化的低强调是它的重大缺陷。在每个游戏里都必须问：agent 是在稳健地学习相关技能，还是在近似地记忆特定轨迹？

[CoinRun⁠](https://openai.com/index/quantifying-generalization-in-reinforcement-learning/) 正是为回应这一问题而设计：用程序化生成构造互不相同的训练关卡集与测试关卡集。CoinRun 帮助我们更好地量化了 RL 中的泛化，但它仍只是单一环境，未必能全面代表 RL agent 必须面对的诸多挑战。我们想要两全其美：一个由众多多样环境组成、且每个环境在根本要求上都离不开泛化的基准。为满足这一需求，我们创建了 Procgen Benchmark。CoinRun 如今是 Procgen Benchmark 的开篇环境，把自己的多样性汇入更大的整体。

包括 [Obstacle Tower Challenge](https://arxiv.org/abs/1902.01378) 和 [通用电子游戏 AI 框架](https://arxiv.org/abs/1802.10363)在内的先前工作，也倡导用程序化生成更好地评估 RL 泛化。我们以相似精神设计环境，其中两个 Procgen 环境直接汲取了 [GVGAI 相关工作](https://arxiv.org/abs/1806.10729)的灵感。Dota、StarCraft 等环境也提供大量单环境复杂度，但难以快速迭代实验（同时使用多个这样的环境更是难上加难）。通过 Procgen Benchmark，我们力求同时做到：实验便利性、环境内高多样性、环境间高多样性。

## Procgen Benchmark

Procgen Benchmark 由 16 个独特环境组成，旨在度量强化学习的样本效率与泛化能力。由于每个环境都能生成互异的训练集与测试集，该基准非常适合评估泛化；而所有环境对 RL agent 都构成多样且引人入胜的挑战，因此它也适合评估样本效率。环境固有的多样性要求 agent 学习鲁棒策略——对状态空间狭窄区域的过拟合不再奏效。换个说法：当 agent 面对不断变化的关卡时，泛化能力成为成功的内在组成部分。

## 设计原则

我们设计所有 Procgen 环境时满足以下标准：

- **高多样性**：在基本设计约束下，给予环境生成逻辑最大自由度。由此产生的关卡分布多样性为 agent 提供有意义的泛化挑战。
- **快速评估**：环境难度经过校准，基线 agent 训练 2 亿时间步后即可取得明显进展。此外，环境经过优化，单核 CPU 上可每秒运行数千步，支撑快速实验管线。
- **可调难度**：所有环境支持两档校准良好的难度：easy 与 hard。我们报告的实验结果使用 hard 难度，但也提供 easy 难度给算力有限的人。easy 环境所需训练资源约为八分之一。
- **强调视觉识别与运动控制**：遵循先例，环境模仿许多 Atari 和 Gym Retro 游戏的风格。表现好坏主要取决于识别观测空间中的关键素材并做出恰当的低层运动反应。

## 评估泛化

我们在举办 [Retro Contest⁠](https://openai.com/index/first-retro-contest-retrospective/) 期间深刻体会到 RL 泛化有多难——agent 持续无法从训练集的有限数据中泛化。之后，我们的 CoinRun 实验更清晰地呈现了 agent 泛化之困。现在我们在那些结果上做了扩展，用 Procgen Benchmark 的全部 16 个环境开展了迄今最全面的 RL 泛化研究。

我们首先测量训练集规模对泛化的影响。在每个环境中，我们生成规模从 100 到 100,000 个关卡不等的训练集，使用[近端策略优化⁠](https://openai.com/index/openai-baselines-ppo/)在这些关卡上训练 agent 2 亿时间步，并测量其在未见测试关卡上的表现。

我们发现，agent 在几乎所有环境中都强烈过拟合于小训练集。某些情况下，agent 需要多达 10,000 个关卡才能弥合泛化差距。我们还在许多环境中看到一个奇特的趋势：越过某个阈值后，训练集越大，训练表现反而越好！这与监督学习中常见的"训练集越大训练表现越差"的趋势相反。我们认为训练表现的提升来自多样关卡集提供的隐式课程：如果 agent 学会*甚至在训练集内部关卡之间*泛化，更大的训练集就能提升训练表现。我们此前在 CoinRun 中就注意到这一效应，现在发现它在许多 Procgen 环境中同样经常出现。

## 确定性关卡消融实验

在测试时，我们去除关卡序列的确定性，改为随机选择关卡序列。我们发现 agent 在多数游戏的前几个训练关卡上变得熟练，营造出取得实质进展的假象；然而测试表现说明，agent 实际上对底层关卡分布几乎一无所获。我们认为训练与测试表现之间的巨大鸿沟值得强调。它揭示了在固定关卡序列环境上训练的一个关键隐藏缺陷。这些结果表明，在训练和评估 RL agent 时使用多样化的环境分布多么必要。
