# SweetSpecter：中国关联的网络活动

OpenAI 封禁了疑似属于被追踪为 SweetSpecter 的疑似中国背景对手的账号——其用 AI 研究漏洞、编写代码并支持鱼叉式钓鱼活动。

*本案例研究最初发表于 OpenAI [2024 年 10 月](https://cdn.openai.com/threat-intelligence-reports/influence-and-cyber-operations-an-update_October-2024.pdf)报告。*

## 行为者

我们识别并封禁了一批账号。根据可信来源的评估，它们很可能属于一个疑似中国背景的对手：该对手一边试图用我们的模型支持其进攻性网络行动，一边对我们员工和全球各国政府发动鱼叉式钓鱼攻击。该对手被公开追踪为 SweetSpecter，2023 年出现。据我们了解，这是其攻击目标首次被公开认定包括一家美国 AI 公司；此前其活动被报道聚焦中东、非洲和亚洲的政治实体。

## 行为

2024 年 5 月，我们收到可信来源线索：其安全团队观察到 SweetSpecter 向部分员工的公务与私人邮箱发送带恶意附件的鱼叉式钓鱼邮件。

*SweetSpecter 发给少数员工的邮件（已脱敏）。这些邮件被我们的安全系统拦截。图片由 Proofpoint 提供。*

在这些邮件中，SweetSpecter 假扮 ChatGPT 用户，向目标员工寻求支持。邮件包含名为"some problems.zip"的恶意附件，内含一个 LNK 文件。该文件包含的代码一旦被打开，会向用户展示一个 DOCX 文件，罗列各种看似 ChatGPT 的错误与服务提示；后台则会解密并执行一种名为 SugarGh0st RAT 的 Windows 恶意软件。该恶意软件旨在让 SweetSpecter 获得对失陷机器的控制，可执行任意命令、截屏并外泄数据。

OpenAI 安全团队联系了疑似被这一鱼叉式钓鱼行动锁定的员工，确认现有安全控制措施使这些邮件从未到达其企业邮箱。

*已分析的一个恶意 LNK 文件中的诱饵内容——执行后即显示。*

在整个过程中，我们与行业伙伴的协作在识别这些针对员工账号的失败攻击尝试上发挥了关键作用。这凸显了在 AI 时代，为领先于高水准对手，威胁情报共享与协作多么重要。借助共享的洞见与集体专长，我们能更好地保护资产，并挫败与此类活动相关的平台内账号。

## 生成内容

在分析支撑这一行动的更广泛基础设施时，我们发现并挫败了一簇 ChatGPT 账号：它们使用相同基础设施来回答问题、完成脚本与漏洞研究任务。我们把这些交互映射到微软今年早些时候提出、建议并入 MITRE ATT&CK® 框架的"LLM 主题"战术、技术与流程（TTP）。MITRE 框架记录网络对手在现实中使用的战术与技术；列出这些映射，旨在向更广泛的网络安全社区通报观察到的 TTP，帮助提升网络防御效能。

SweetSpecter 符合这些 TTP 的部分活动示例如下：

| 活动 | LLM ATT&CK 框架类别 |
| --- | --- |
| 询问各类应用中的漏洞 | 借助 LLM 的侦察 |
| 询问如何搜索易受严重 RCE 漏洞 Log4Shell 影响的特定版本 Log4j | 借助 LLM 的侦察 |
| 询问国外常用的内容管理系统 | 借助 LLM 的侦察 |
| 询问特定 CVE 编号的信息 | 借助 LLM 的侦察 |
| 询问全网扫描器是如何制作的 | 借助 LLM 的侦察 |
| 询问如何用 sqlmap 向目标服务器上传潜在 webshell | LLM 辅助的漏洞研究 |
| 请求帮助寻找利用某知名汽车制造商基础设施的方法 | LLM 辅助的漏洞研究 |
| 提供代码并请求进一步帮助，使用通信服务以编程方式发送短信 | LLM 增强的脚本技术 |
| 请求帮助调试某网络安全工具扩展的开发 | LLM 增强的脚本技术 |
| 请求帮助调试代码——该代码属于一个以编程方式向攻击者指定号码群发短信的更大框架 | LLM 辅助的开发 |
| 询问政府部门员工感兴趣的话题，以及附件取什么名字可避免被拦截 | LLM 支持的社会工程 |
| 请求改写攻击者提供的招聘消息的多个版本 | LLM 支持的社会工程 |

在整个调查中，我们的安全团队借助 ChatGPT 分析、归类、翻译并总结对手账号的交互记录。这使我们能够快速从大型数据集提炼洞见，同时尽量降低这项工作所需资源。随着模型更先进，我们预期还能用 ChatGPT 对发给员工的恶意附件进行逆向与分析。

## 影响

与我们在首份威胁报告中的观察一致，操作者对我们模型的使用并未为他们带来公开渠道无法获取的新能力或新方向。我们的安全机制在恶意邮件到达员工收件箱前就将其拦截。
