# GPT‑6.1 Sol 帮助 CodeRabbit 在复杂代码库中强化安全性


随着 AI 加快软件开发，工程团队与应用安全团队需要一些办法来调查代码改动、处理漏洞，同时让人始终掌握主导权。CodeRabbit 正把 [GPT‑6.1 Sol](https://openai.com/index/introducing-gpt-6-1-sol/) 用作其安全 agent 的主力模型，把审查范围扩展到单次改动之外，并帮助开发者理解复杂代码库中的风险。

一次 pull request 的改动可能影响应用别处的共享库、依赖项和安全防护。GPT‑6.1 Sol 帮助 CodeRabbit 把跨文件、跨组件的行为关联起来，从而暴露潜在的安全问题。CodeRabbit 的审查独立于编写代码的那个 agent，并且与既有扫描工具形成互补。它的系统还会使用其他前沿模型和安全工具。

在 pull request 审查过程中，Sol 会在开发者工作的同时帮助分析改动。在 Deep Scan 中，它支持跨仓库的更广泛调查，包括依赖项以及各组件之间的交互。CodeRabbit Secure 把这类调查扩展到关联仓库（例如一个共享的认证库），帮助团队理解某个弱点会如何影响更大的系统。

CodeRabbit 称，他们借助 GPT‑6.1 Sol 在数千个仓库和组织中标记出与安全相关的问题。这些发现会进入开发者已经在使用的 pull request 工作流，供其审查并改进代码。

CodeRabbit Secure 把调查与修复连接起来。对于用户选定的发现，它可以在隔离的 sandbox 中尝试验证漏洞利用，而不去测试生产系统。对于支持的问题类型，它可以起草一个 pull request，给出建议的修复方案，交由人来审查和批准。

这项工作展示了前沿推理可以如何支撑软件安全：理解单次改动之外的风险，帮助验证各项发现，并把发现转化为建议的修复方案。最终决定发布哪些改动，仍然由人工评审负责。
