# Function calling 及其他 API 更新

我们发布一系列更新，包括更可控的 API 模型、function calling 能力、更长的上下文以及更低的价格。

*2023 年 7 月 20 日更新：*

我们此前曾告知开发者，`gpt-3.5-turbo-0301`、`gpt-4-0314` 和 `gpt-4-32k-0314` 模型计划于 2023 年 9 月 13 日退役。在审阅了客户和社区的反馈后，我们将这些模型的支持期延长至至少 2024 年 6 月 13 日。

每当我们发布新模型版本，首要目标是让更新的模型在整体上更聪明。我们在大量维度上追求改进，例如指令遵循、事实准确性和拒绝行为。例如，上个月推出的 `gpt-4-0613` 模型在 function calling 上带来了显著提升。

我们会查看大量评估指标来决定是否发布新模型。虽然多数指标有所改进，但某些任务的表现可能变差。这就是我们允许 API 用户锁定模型版本的原因。例如，你可以使用 `gpt-4-0314` 而非泛指的 `gpt-4`（后者指向最新模型版本）。每个单独锁定的模型都是稳定的，意味着我们不会做出影响其输出的改动。

我们正努力确保每个新版本在全面的任务范围内带来改进。同时也承认，我们的评估方法论并不完美，并在持续改进。帮助我们确保新模型在你关心的领域越变越好的一个方式，是向 [OpenAI Evals 库⁠（在新窗口打开）](https://github.com/openai/evals/tree/main) 贡献内容，报告我们模型的不足。

我们理解模型升级和行为变化可能对你的应用造成干扰。我们正在为开发者提供更多稳定性和可见性，让他们了解我们如何发布和弃用模型。

我们今年早些时候发布了 `gpt-3.5-turbo` 和 `gpt-4`，短短几个月内，就见证了开发者在这些模型之上构建的 [惊人应用⁠](https://openai.com/stories/)。

今天，我们带来一些激动人心的更新：

- Chat Completions API 中新增 function calling 能力
- 更新且更可控的 `gpt-4` 与 `gpt-3.5-turbo` 版本
- `gpt-3.5-turbo` 的新 16k 上下文版本（相比标准 4k 版本）
- 我们最先进嵌入模型的降价 75%
- `gpt-3.5-turbo` 输入 token 降价 25%
- 宣布 `gpt-3.5-turbo-0301` 和 `gpt-4-0314` 模型的弃用时间表

所有这些模型都沿用我们 3 月 1 日引入的数据隐私与安全保证——客户拥有其请求生成的全部输出，且其 API 数据不会被用于训练。

## Function calling

开发者现在可以向 `gpt-4-0613` 和 `gpt-3.5-turbo-0613` 描述函数，模型会智能地选择输出一个包含调用这些函数所需参数的 JSON 对象。这是把 GPT 的能力与外部工具和 API 更可靠连接的新方式。

这些模型经过微调，既能检测何时需要调用函数（取决于用户输入），也能以遵循函数签名的 JSON 作出响应。Function calling 让开发者能更可靠地从模型获得结构化数据。例如，开发者可以：

- 创建通过调用外部工具回答问题（类似 ChatGPT Plugins）的聊天机器人

把“给 Anya 发邮件，问她下周五要不要一起喝咖啡”这样的请求转换为 `send_email(to: string, body: string)` 这样的函数调用，或把“波士顿天气怎么样？”转换为 `get_current_weather(location: string, unit: 'celsius' | 'fahrenheit')`。

- 把自然语言转换为 API 调用或数据库查询

把“本月我排名前十的客户是谁？”转换为内部 API 调用，如 `get_customers_by_revenue(start_date: string, end_date: string, limit: int)`，或把“Acme, Inc. 上个月下了多少订单？”通过 `sql_query(query: string)` 转换为 SQL 查询。

- 从文本中抽取结构化数据

定义一个名为 `extract_people_data(people: [{name: string, birthday: string, location: string}])` 的函数，用于抽取一篇维基百科文章中提到的所有人物信息。

这些用例得益于 `/v1/chat/completions` 端点中的新 API 参数 `functions` 和 `function_call`：开发者可通过 JSON Schema 向模型描述函数，并可选择要求它调用特定函数。请查阅我们的 [开发者文档⁠（在新窗口打开）](https://platform.openai.com/docs/guides/gpt/function-calling) 开始使用；如果你发现 function calling 有待改进的场景，欢迎 [添加 evals⁠（在新窗口打开）](https://github.com/openai/evals)。

自 ChatGPT plugins 阿尔法版本以来，我们对如何让工具与语言模型安全协作学到了很多。但仍有开放的研究问题。例如，一个概念验证攻击展示了工具输出中的不可信数据如何指示模型执行非预期操作。我们正在努力缓解这些及其他风险。开发者可以保护其应用：只消费来自可信工具的信息，并在执行有现实影响的操作（如发送邮件、在线发布或进行购买）前加入用户确认步骤。

## 新模型

### GPT-4

`gpt-4-0613` 包含更新、改进的模型，支持 function calling。

`gpt-4-32k-0613` 包含与 `gpt-4-0613` 相同的改进，并提供扩展的上下文长度，以更好理解更长的文本。

借助这些更新，未来几周我们将邀请 [等候名单⁠](https://openai.com/waitlist/gpt-4-api/) 上更多用户试用 GPT-4，目标是让该模型彻底取消等候名单。感谢每一位耐心等待的用户，我们很期待看到你用 GPT-4 构建什么！

### GPT-3.5 Turbo

`gpt-3.5-turbo-0613` 提供与 GPT-4 相同的 function calling，以及通过 system message 实现更可靠的可控性——这两个特性能让开发者更有效地引导模型响应。

`gpt-3.5-turbo-16k` 提供 `gpt-3.5-turbo` 四倍的上下文长度，价格为两倍：每 1K 输入 token 0.003 美元，每 1K 输出 token 0.004 美元。16k 上下文意味着模型现在可以在单次请求中支持约 20 页文本。

### 模型弃用

今天，我们启动对 [三月⁠](https://openai.com/index/introducing-chatgpt-and-whisper-apis/#:~:text=Chat%20guide.-,ChatGPT%20upgrades,-We%20are%20constantly) 宣布的 `gpt-4` 和 `gpt-3.5-turbo` 最初版本的升级与弃用流程。使用稳定模型名（`gpt-3.5-turbo`、`gpt-4` 和 `gpt-4-32k`）的应用将于 6 月 27 日自动升级到上述新模型。如需比较版本间的模型表现，我们的 [Evals 库⁠（在新窗口打开）](https://github.com/openai/evals) 支持公开和私有 evals，以展示模型变化将如何影响你的用例。

需要更多时间过渡的开发者可以继续通过在 API 请求的 'model' 参数中指定 `gpt-3.5-turbo-0301`、`gpt-4-0314` 或 `gpt-4-32k-0314` 使用旧模型。这些旧模型将可用至 2024 年 6 月 13 日，此后指定这些模型名的请求将失败。你可以通过我们的 [模型弃用页面⁠（在新窗口打开）](https://platform.openai.com/docs/deprecations/) 及时了解模型弃用动态。这是这些模型的首次更新；因此，我们热切欢迎 [开发者反馈⁠（在新窗口打开）](https://community.openai.com/)，帮助我们确保平稳过渡。

## 更低价格

我们持续让系统更高效，并自今天起把这些节省回馈给开发者。

### Embeddings

`text-embedding-ada-002` 是我们最受欢迎的嵌入模型。今天我们将其成本降低 75%，至每 1K token 0.0001 美元。

### GPT-3.5 Turbo

`gpt-3.5-turbo` 是我们最受欢迎的对话模型，支撑着数百万用户使用的 ChatGPT。今天我们将其输入 token 成本降低 25%。开发者现在只需每 1K 输入 token 0.0015 美元、每 1K 输出 token 0.002 美元即可使用该模型，大约相当于每美元 700 页文本。

`gpt-3.5-turbo-16k` 定价为每 1K 输入 token 0.003 美元、每 1K 输出 token 0.004 美元。

开发者反馈是我们平台演进的基石，我们将继续根据听到的建议做出改进。我们很期待看到开发者如何在应用中使用这些最新模型和新特性。
