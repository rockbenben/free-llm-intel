# 推出文本和代码嵌入

我们推出嵌入（embeddings），这是 OpenAI API 中一个新端点，让执行自然语言和代码任务变得容易，例如语义搜索、聚类、主题建模和分类。

阅读文档· 阅读论文

嵌入是把概念转换成数字序列后的数值表示，它让计算机容易理解这些概念之间的关系。我们的嵌入在 3 个标准基准上超越了顶尖模型，其中包括在代码搜索上取得 20% 的相对提升。

嵌入对处理自然语言和代码很有用，因为它们可以被其他机器学习模型和算法（如聚类或搜索）直接消费和比较。

数值上相近的嵌入在语义上也是相近的。例如，“canine companions say”（犬类伙伴会说）的嵌入向量与 “woof”（汪）的嵌入向量的相似度，会高于与 “meow”（喵）的相似度。

新端点使用作为 GPT‑3 后代的神经网络模型，把文本和代码映射到一个向量表示——即在*高维空间*中为它们做“嵌入”。每个维度都捕捉输入的某个方面。

[OpenAI API](https://beta.openai.com/) 中新的 [/embeddings](https://beta.openai.com/docs/api-reference/embeddings) 端点只需几行代码就能提供文本和代码嵌入：

我们发布三个系列的嵌入模型，每个系列都针对不同的功能调优以取得良好表现：文本相似度、文本搜索和代码搜索。这些模型接受文本或代码作为输入，并返回一个嵌入向量。

|  | 模型 | 用例 |
| --- | --- | --- |
| 文本相似度：捕捉文本片段之间的语义相似性。 | text-similarity-{ada, babbage, curie, davinci}-001 | 聚类、回归、异常检测、可视化 |
| 文本搜索：在文档上进行语义信息检索。 | text-search-{ada, babbage, curie, davinci}-{query, doc}-001 | 搜索、上下文相关性、信息检索 |
| 代码搜索：用自然语言查询找到相关代码。 | code-search-{ada, babbage}-{code, text}-001 | 代码搜索与相关性 |

## 文本相似度模型

文本相似度模型提供能够捕捉文本片段语义相似性的嵌入。这些模型对许多任务都很有用，包括[聚类](https://beta.openai.com/docs/guides/embeddings/clustering)、[数据可视化](https://beta.openai.com/docs/guides/embeddings/data-visualization-in-2d) 和[分类](https://beta.openai.com/docs/guides/embeddings/classification-using-the-embedding-features)。

下面的交互式可视化展示了来自 DBpedia 数据集文本样本的嵌入：

要比较两段文本的相似度，你只需对文本嵌入使用[点积](https://en.wikipedia.org/wiki/Dot_product)。结果是一个介于 –1 和 1 之间的“相似度分数”，有时也称“[余弦相似度](https://en.wikipedia.org/wiki/Dot_product#Application_to_the_law_of_cosines)”，数值越高表示越相似。在大多数应用中，嵌入可以预先计算，然后点积比较执行起来极快。

嵌入的一个常见用途是把它当作机器学习任务（如分类）中的特征。在机器学习文献中，当使用线性分类器时，这种分类任务被称为“线性探针”（linear probe）。我们的文本相似度模型在 [SentEval](https://github.com/facebookresearch/SentEval)（[Conneau et al., 2018](https://arxiv.org/abs/1803.05449)）的线性探针分类上取得了新的最先进结果，SentEval 是一个常用于评估嵌入质量的基准。

## 文本搜索模型

文本搜索模型提供的嵌入能够支撑大规模搜索任务，例如给定文本查询，在一堆文档中找到相关文档。文档和查询的嵌入分别生成，然后用余弦相似度比较查询与每个文档之间的相似度。

基于嵌入的搜索比经典关键词搜索中使用的词重叠技术泛化能力更好，因为它捕捉文本的语义，且对确切短语或词不那么敏感。我们在 [BEIR](https://github.com/UKPLab/beir)（[Thakur, et al. 2021](https://arxiv.org/abs/2104.08663)）搜索评估套件上评估文本搜索模型的性能，得到了优于以往方法的搜索表现。我们的[文本搜索指南](https://beta.openai.com/docs/guides/embeddings/text-search-using-embeddings)对如何用嵌入做搜索任务提供了更多细节。

## 代码搜索模型

代码搜索模型为代码搜索任务提供代码和文本嵌入。给定一堆代码块，任务是为一个自然语言查询找到相关代码块。我们在 [CodeSearchNet](https://github.com/github/CodeSearchNet)（[Husain et al., 2019](https://arxiv.org/abs/1909.09436)）评估套件上评估代码搜索模型，我们的嵌入取得了显著优于以往方法的结果。查看[代码搜索指南](https://beta.openai.com/docs/guides/embeddings/code-search-using-embeddings)以用嵌入做代码搜索。

## 嵌入 API 的实际应用示例

### JetBrains Research

JetBrains Research 的[天体粒子物理实验室](https://research.jetbrains.org/groups/astroparticle-physics/)分析诸如[天文学家电报](https://en.wikipedia.org/wiki/The_Astronomer%27s_Telegram)和 NASA 的 [GCN Circulars](https://gcn.gsfc.nasa.gov/)这类数据，这些报告包含传统算法无法解析的天文事件。

借助 OpenAI 对这些天文报告的嵌入，研究人员现在能够跨多个数据库和出版物搜索诸如“crab pulsar bursts”（蟹状星云脉冲星爆发）之类的事件。嵌入还通过 k-means 聚类在数据源分类上达到了 99.85% 的准确率。

### FineTune Learning

[FineTune Learning](https://finetunelearning.com/) 是一家为学习构建人机混合解决方案的公司，例如帮助学生达到学术标准的[自适应学习循环](https://en.wikipedia.org/wiki/Adaptive_learning)。

OpenAI 的嵌入显著改善了根据学习目标查找教材内容的任务。OpenAI 的 text-search-curie 嵌入模型取得了 89.1% 的 top-5 准确率，超越了 Sentence-BERT（64.5%）等以往方法。虽然人类专家仍然更强，但 FineTune 团队现在能在几秒内为整本教材打标签，而专家过去要花费数小时。

### Fabius

[Fabius](https://www.fabius.io/) 帮助公司把客户对话转化为用于规划和优先级排序的结构化洞察。OpenAI 的嵌入让公司更容易找到并标记包含功能请求的客户通话记录。

例如，客户可能用“automated”（自动化）或“easy to use”（易用）之类的词来请求一个更好的自助服务平台。此前，Fabius 使用模糊关键词搜索来尝试把这些记录标记为自助服务平台标签。有了 OpenAI 的嵌入，他们现在总体上能找到 2 倍的样本，而对于那些没有明确关键词可供客户使用、用例抽象的功能，能找到 6 到 10 倍的样本。

所有 API 客户都可以通过[嵌入文档](https://beta.openai.com/docs/guides/embeddings)开始在其应用中使用嵌入。
