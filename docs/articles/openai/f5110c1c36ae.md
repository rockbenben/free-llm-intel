# 部署语言模型的最佳实践

Cohere、OpenAI 和 AI21 Labs 共同制定了一套初步的最佳实践，适用于任何开发或部署大语言模型的组织。

会读会写的计算机已经到来，它们有潜力从根本上改变日常生活。人机交互的未来充满可能与前景，但任何强大的技术都需要谨慎部署。

Cohere、OpenAI 和 AI21 Labs 共同制定了一套初步的最佳实践，适用于任何开发或部署大语言模型的组织。下面的联合声明是迈向构建一个共同体以应对 AI 进展带来的全球性挑战的一步，我们欢迎希望参与的其他组织与我们联络。

## 关于语言模型部署的联合建议

我们建议若干关键原则，帮助大语言模型（LLM）提供者缓解这项技术的风险，从而实现其"增强人类能力"的全部潜力。

这些原则虽然基于我们通过 API 提供 LLM 的经验专门制定，但我们希望无论采取何种发布策略（如开源或公司内部使用），它们都能有所助益。由于 LLM 的商业用途和相关安全考量都是崭新且不断演进的，我们预期这些建议会随时间发生显著变化。我们正在积极认识并应对 LLM 的局限与滥用途径，并将随时间推移、与更广泛的社区协作更新这些原则与实践。

分享这些原则，是希望其他 LLM 提供者能够借鉴并采纳，同时推进关于 LLM 开发与部署的公共讨论。

### 禁止滥用

**公布使用指南与使用条款**，明确禁止对个人、社区和社会造成实质伤害的用法，如垃圾信息、欺诈或水军造势（astroturfing）。使用指南还应指明需要额外审查的 LLM 使用领域，并禁止不相称的高风险用例，例如依据受保护特征对人进行分类。

**构建系统与基础设施来执行使用指南**。这可以包括速率限制、内容过滤、接入生产环境前的应用审批、异常活动监测及其他缓解措施。

### 缓解无意伤害

**主动缓解有害的模型行为**。最佳实践包括：全面的模型评估以恰当认识局限、最大限度减少训练语料中潜在的偏差来源，以及通过人类反馈学习等技术最大限度减少不安全行为。

**记录已知的弱点与漏洞**，例如偏差或生成不安全代码的能力——因为在某些情况下，任何程度的预防措施都无法完全消除无意伤害的可能。文档还应包括针对模型和具体用例的安全最佳实践。

### 与利益相关方审慎协作

**组建背景多元的团队**并广泛征集意见。要刻画并解决语言模型在真实世界的多样性中如何运作，需要多元的视角——若不加约束，模型可能强化偏见，或对一些群体不适用。

**公开披露关于 LLM 安全与滥用的经验教训**，以促进广泛采纳，帮助各行业在最佳实践上相互迭代。

**尊重语言模型供应链中的每一份劳动**。例如，提供者应对内部审阅模型输出人员的工作条件持高标准，并要求供应商满足明确规定的标准（如确保标注员可以选择退出某项任务）。

作为 LLM 提供者，公布这些原则是以协作方式引导更安全的大语言模型开发与部署的第一步。我们期待继续与彼此及其他各方合作，找出更多机会，减少语言模型的无意伤害并防止其恶意使用。

## 其他组织的支持

> "随着大语言模型（LLM）变得日益强大和富有表现力，风险缓解变得愈发重要。我们欢迎这些及其他主动缓解危害、向用户提示需要格外审慎领域的努力。这里阐述的原则是对全球对话的重要贡献。"——John Bansemer，CyberAI 项目主任、安全与新兴技术中心（CSET）高级研究员

> "谷歌认同通过全面策略分析模型与训练数据以缓解伤害、偏见和失实表述风险的重要性。这些 AI 提供者推动相关原则与文档建设以促进 AI 安全，是深思熟虑的一步。"——Google

> "要实现大语言模型的承诺，我们必须继续作为行业协作，分享如何负责任地开发与部署、同时缓解潜在风险的最佳实践。我们欢迎这些推动行业开展审慎而务实行动的努力，并向学术界、公民社会和政府的关键利益相关方学习、与之合作。"——Microsoft
