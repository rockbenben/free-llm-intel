# 在 Amazon Bedrock 中推出面向智能体的“有状态运行时环境”


AI 智能体擅长推理。但更难的部分在于运营：如何跨越实际工具与系统，在具备正确控制措施的情况下，长期可靠地运行多步工作流。

通过与亚马逊深度合作，我们为客户降低了这一门槛：**在 Amazon Bedrock 中原生提供全新的有状态运行时环境 (Stateful Runtime Environment)**。AWS 客户将可以使用这一由 OpenAI 模型驱动、针对 AWS 基础设施优化并专为智能体工作流定制的运行时环境，它具备生产级任务所需的上下文状态、可靠性和治理能力。

#### 简化智能体的生产部署

许多基于无状态 (Stateless) API 的智能体原型只能处理简单用例：一次提示、一个答案，或许再加上一次工具调用。但生产环境下的任务截然不同。真实的工作流涉及多个步骤，需要前序操作的上下文，依赖多个工具的输出、审批和系统状态，并且需要在安全环境中建立可靠的护栏。

无状态 API 要求开发者自行构建底层的编排层。开发团队不得不背负沉重负担，去研究如何存储状态、如何调用工具、如何处理错误，以及如何让长周期任务安全恢复。

“有状态运行时环境”旨在减轻这一负担。它在**你的 AWS 环境内**运行，并针对 AWS 服务进行了优化。现在，智能体无需手动拼接断开的请求，即可自动执行复杂的步骤，并携带包含记忆/历史记录、工具与工作流状态、环境占用以及身份/权限边界的“工作上下文”。

#### 核心价值

现在，交付多系统客户支持、销售运营工作流、内部 IT 自动化以及包含审批与审计的财务流程等解决方案，比以往任何时候都更加容易。

#### 加速多步工作流的上线进程

当运行时环境能够处理跨步骤的持久化编排和状态管理时，团队可以专注于业务逻辑，而非底层脚手架的搭建。

#### 更适合长周期任务

有状态任务旨在长期可靠运行，能够承载多步执行所需的上下文和控制边界。

#### AWS 原生部署与治理

该运行时环境设计为在客户的 AWS 环境内运行，能够轻松遵循现有的安全态势、工具集成和治理规则。
