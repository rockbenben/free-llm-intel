# Greptile 用 GPT‑6 Astra 把 bug 检测带到代码审查之外

Greptile 如何用 GPT‑6 Astra 测试用户工作流、用 Daybreak 强化安全、用 Codex 减少返工。

[开始使用 OpenAI 构建](https://openai.com/startups/)

公司规模：初创公司

区域：北美

行业：科技

产品：API, Codex


[Greptile](https://www.greptile.com/) 构建 AI agent，在完整的代码库上下文里审查并测试代码改动。联合创始人兼 CEO Daksh Gupta 说：“我们做的就是减少 bug、让全世界的软件更可靠。”

对 Daksh 来说，这一使命要求既测试应用的行为、也阅读它的代码，而 GPT‑6 Astra 的 computer use 让 Greptile 有办法把测试规模化自动化。

> “有史以来第一次，computer use 到了这样一个阶段：你可以把「用户试着搞坏你的应用」这种体验自动化，也让大公司发布产品时更有底气。”

—Daksh Gupta，Greptile 联合创始人兼 CEO

## 用 GPT‑6 Astra 规模化测试应用

验证一个 pull request，意味着要检查代码在逻辑上是否正确、是否实现了开发者的本意、是否安全，以及会不会破坏既有功能。其中一部分测试需要真正把应用跑起来，因为只读代码可能发现不了问题。

Daksh 举的例子是：某个网站在 iPhone 上浏览时，一个按钮消失了。有了 GPT‑6 Astra，Greptile 可以为一个 pull request 启动开发服务器、把浏览器调整到 iPhone 尺寸的视口，并模拟用户在应用中的操作。模型的视觉理解能力让它能够检查屏幕并发现那个消失的按钮。

“考虑到我们用这些模型发布代码的速度，请一家 QA 公司来测试你所有的改动，实际上慢到不现实，”他说。有了 GPT‑6 Astra，Greptile 可以把这类应用测试规模化自动化。

## 用 Daybreak 强化客户的防御

Daksh 说，更强的模型也让攻击者更容易利用应用，把公司置于风险之中——即便这些公司此前并不是典型的攻击目标。

“我们希望即便是初创公司，也能非常轻松地保障自己的系统安全，”Daksh 说，“有了 Daybreak，我们能以一种非常安全的方式做到这一点，也能确保我们的客户拥有比攻击者的进攻手段更精密的防御机制。”

## 用 Codex 减少 bug 和返工

Greptile 的 Knowledge Base 会为一家公司的代码库建立索引，并以人和 agent 都能读懂的形式记录它的运作方式。该公司通过一个 Model Context Protocol（MCP）服务器把这些文档提供给 Codex。

据 Daksh 介绍，这让 Codex 能够写出符合客户既有风格的代码，已有数千家客户把 Codex 接入了 Greptile 的 Knowledge Base。

为了衡量影响，团队会统计 AI 生成的代码被回退的频率。Daksh 说：“当我们为 agent 提供上下文时，回退会变少，客户既省时间，也省下推理开销。”客户可以把这些省下来的投入用在新的工作上，而不是反复返工同样的改动。

Greptile 还用 Codex 来构建自己的软件和 agent。Daksh 说：“我们是 Codex 的重度用户。”“我们在每一个职能上都有非常大的使用量，工程方面尤其如此。”

## 展望更快的开发：Ultrafast

Daksh 解释说，对 Greptile 而言，唯一真正的瓶颈是团队把想法变成可运行软件的速度。他说模型的智能水平对许多任务已经够用，因此他把 Ultrafast 视为加速开发的一种方式。

> “我最期待的就是 Ultrafast：它给了我们一个杠杆，让我们能以想出好点子的最快速度向前推进。”

—Daksh Gupta，Greptile 联合创始人兼 CEO

他更长期的目标，是让改动并发布关键的企业软件像发布一个业余项目一样轻松，而 OpenAI 会帮助 Greptile 构建这套所需的验证能力。
