# Greptile 使用 GPT-6 Astra 使错误检测超越代码审查

Greptile 如何使用 GPT-6 Astra 来测试用户工作流程、Daybreak 来增强安全性以及 Codex 来减少返工。

[开始使用 OpenAI 构建](https://openai.com/startups/)

公司规模：初创公司

地区： 北美

行业：科技

产品：API、Codex

[Greptile](https://www.greptile.com/) 构建 AI 代理，利用代码库的完整上下文来审查和测试代码更改。 “我们致力于减少错误并使世界软件更加可靠，”联合创始人兼首席执行官达克什·古普塔 (Daksh Gupta) 说道。

对于 Daksh 来说，该任务需要测试应用程序的行为并读取其代码，而 GPT-6 Astra 的计算机使用为 Greptile 提供了一种大规模自动化测试的方法。

> “有史以来第一次，计算机的使用让你可以自动化用户尝试破坏你的应用程序的体验，并让大公司更加自信地交付产品。”

——Daksh Gupta，Greptile 联合创始人兼首席执行官

## 使用 GPT‑6 Astra 大规模测试应用程序

验证拉取请求涉及检查代码在逻辑上是否正确、是否符合开发人员的意图、是否安全并避免破坏现有功能。对于某些测试，您需要实际运行应用程序，因为单独阅读代码可能无法揭示问题。

Daksh 举了一个在 iPhone 上查看网站时消失的按钮的示例。借助 GPT‑6 Astra，Greptile 可以启动拉取请求的开发服务器，将浏览器大小调整为 iPhone 大小的视口，并模拟用户在应用程序中移动。模型的视觉理解能力使其能够检查屏幕并发现隐藏的按钮。

“考虑到我们使用这些模型交付代码的速度，质量保证公司测试所有更改的速度实在是太慢了，”他说。借助 GPT‑6 Astra，Greptile 可以大规模自动化此类应用程序测试。

## 通过 Daybreak 加强客户防御

达克什表示，更强大的模型也使攻击者更容易利用应用程序，使公司面临风险，甚至是那些以前不会成为典型目标的公司。

“我们希望即使是初创公司也能轻松保护其系统，”Daksh 说。 “通过 Daybreak，我们能够以非常安全的方式做到这一点，并且我们可以确保我们的客户拥有比对手的攻击机制更复杂的防御机制。”

## 使用 Codex 减少错误和返工

Greptile 的知识库对公司的代码库进行索引，并以人们和代理可以阅读的形式记录其工作原理。该公司通过模型上下文协议 (MCP) 服务器向 Codex 提供该文档。

Daksh 表示，这使得 Codex 能够编写遵循客户现有模式的代码，并且数千名客户已将 Codex 连接到 Greptile 的知识库。

为了衡量影响，团队跟踪了人工智能生成的代码被恢复的频率。 “当我们为代理提供上下文时，发生的回复就会减少，客户也可以节省时间并节省推理，”Daksh 说。客户可以将这些节省的资金用于新的工作，而不是重复相同的更改。

Greptile 还使用 Codex 构建自己的软件和代理。 “我们是 Codex 的大量用户，”Daksh 说。 “我们在每个功能上都有大量的使用，特别是工程。”

## 期待使用 Ultrafast 实现更快的开发

Daksh 解释说，对于 Greptile 来说，唯一真正的瓶颈是团队将想法转化为可用软件的速度。他表示，模型智能已经足以完成许多任务，因此他将 Ultrafast 视为加速开发的一种方式。

> “最令我兴奋的是 Ultrafast 可以作为我们的杠杆，让我们能够尽可能快地提出好想法。”

——Daksh Gupta，Greptile 联合创始人兼首席执行官

他的长期目标是通过 OpenAI 帮助 Greptile 构建所需的验证，使更改和交付关键企业软件像交付一个副项目一样简单。
