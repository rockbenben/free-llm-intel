# DevDay 上发布的全新模型与开发者产品

带 128K 上下文、价格更低的 GPT‑4 Turbo，全新的 Assistants API，带视觉能力的 GPT‑4 Turbo，DALL·E 3 API，以及更多。

*更新：我们此前曾声明，使用 `gpt-3.5-turbo` 名称的应用将在 12 月 11 日自动升级到新模型版本。我们已编辑本文删除了这一说法，因为这不再会发生。*

今天，我们分享了数十项新增内容和改进，并在平台多处下调了价格。其中包括：

- 新的 GPT‑4 Turbo 模型，能力更强、价格更低，并支持 128K 上下文窗口
- 新的 Assistants API，让开发者更轻松地构建自己的辅助型 AI 应用，这些应用有目标、能调用模型和工具
- 平台上新的多模态能力，包括视觉、图像创建（DALL·E 3）和文本转语音（TTS）

我们从今天下午 1 点（太平洋时间）起开始向 OpenAI 客户推送新功能。

*了解[*OpenAI DevDay 面向 ChatGPT 的公告*⁠](https://openai.com/index/introducing-gpts/)*的更多信息。*

## 带 128K 上下文的 GPT-4 Turbo

我们在三月发布了 GPT‑4 的第一个版本，并在七月让 GPT‑4 对所有开发者全面可用。今天我们推出下一代该模型的预览版，[GPT‑4 Turbo](https://platform.openai.com/docs/models/gpt-4-and-gpt-4-turbo)。

GPT‑4 Turbo 能力更强，掌握截至 2023 年 4 月的世界事件。它有 128k 上下文窗口，因此能在单个提示词里容纳相当于 300 多页文本的内容。我们还优化了它的性能，使得相比 GPT‑4，我们能以输入 token 便宜 3 倍、[输出 token 便宜 2 倍的价格⁠](https://openai.com/pricing/#gpt-4-turbo)提供 GPT‑4 Turbo。

GPT‑4 Turbo 已对所有付费开发者开放试用，在 API 中传入 `gpt-4-1106-preview` 即可，我们计划在未来几周发布稳定的、可用于生产的版本。

### 函数调用更新

[函数调用](https://platform.openai.com/docs/guides/function-calling)让你能向模型描述你的应用或外部 API 的函数，并让模型智能地选择输出一个包含参数、用以调用这些函数的 JSON 对象。今天我们发布若干改进，包括在单条消息中调用多个函数的能力：用户可以发一条消息请求多个动作，例如“打开车窗并关掉空调”，而这在过去需要与模型多次往返([了解更多](https://platform.openai.com/docs/guides/function-calling/parallel-function-calling))。我们也在提升函数调用的准确度：GPT‑4 Turbo 更可能返回正确的函数参数。

### 改进的指令遵循与 JSON mode

GPT‑4 Turbo 在需要严格遵循指令的任务上比我们先前的模型表现更好，例如生成特定格式（如“始终用 XML 作答”）。它也支持我们新的 [JSON mode](https://platform.openai.com/docs/guides/text-generation/json-mode)，确保模型以有效的 JSON 响应。新的 API 参数 `response_format` 让模型能把输出约束为一个语法正确的 JSON 对象。JSON mode 对开发者在函数调用之外、于 Chat Completions API 中生成 JSON 很有用。

### 可复现输出与对数概率

新的 `seed` 参数通过让模型在大多数时间返回一致的补全来实现**可复现输出**。这一 beta 功能对诸如重放请求以便调试、编写更全面的单元测试、以及对模型行为有更高程度控制等用例很有用。我们 OpenAI 内部一直在用它做单元测试，觉得它价值极大。我们很期待看到开发者如何使用它。[了解更多](https://platform.openai.com/docs/guides/text-generation/reproducible-outputs)。

我们还在未来几周推出一个功能，用于返回由 GPT‑4 Turbo 和 GPT‑3.5 Turbo 生成的最可能输出 token 的**对数概率**，这对构建诸如搜索体验中的自动补全等功能很有用。

### 更新的 GPT-3.5 Turbo

除了 GPT‑4 Turbo，我们还发布了一个新的 GPT‑3.5 Turbo 版本，默认支持 16K 上下文窗口。新的 3.5 Turbo 支持改进的指令遵循、JSON mode 和并行函数调用。例如，我们的内部评测在诸如生成 JSON、XML 和 YAML 的格式遵循任务上显示出 38% 的提升。开发者可以在 API 中调用 `gpt-3.5-turbo-1106` 来使用这一新模型。旧模型将继续可通过在 API 中传入 `gpt-3.5-turbo-0613` 访问，直至 2024 年 6 月 13 日。[了解更多](https://platform.openai.com/docs/models/gpt-3-5)。

## Assistants API、检索与代码解释器

今天我们发布 [Assistants API](https://platform.openai.com/docs/assistants/overview)，这是我们帮助开发者在自己应用内构建类智能体体验的第一步。assistant 是一个专为特定目的打造的 AI，它有具体指令、利用额外知识，并能调用模型和工具来执行任务。新的 Assistants API 提供了诸如代码解释器和检索以及函数调用等新能力，来处理过去你得亲自做的大量繁重工作，让你能构建高质量的 AI 应用。

该 API 为灵活性而设计，用例范围涵盖一个基于自然语言的数据分析应用、一个编程助手、一个 AI 驱动的度假规划师、一个语音控制的 DJ、一个智能视觉画布——不胜枚举。Assistants API 建立在驱动[我们新的 GPTs 产品⁠](https://openai.com/index/introducing-gpts/)的同一批能力之上：自定义指令，以及代码解释器、检索和函数调用等工具。

该 API 引入的一个关键变化是**持久、无限长的线程（thread）**，它让开发者能够把线程状态管理交给 OpenAI，从而绕过上下文窗口的限制。有了 Assistants API，你只需把每条新消息添加到一个已有的 `thread` 即可。

assistant 还可以按需调用新工具，包括：

- **代码解释器（Code Interpreter）**：在一个沙箱执行环境中编写并运行 Python 代码，能生成图形和图表，并处理具有多样数据和格式的文件。它让你的 assistant 能迭代地运行代码来解决棘手的代码和数学问题，以及更多。
- **检索（Retrieval）**：用我们模型之外的知识来增强 assistant，例如专有领域数据、产品信息，或你的用户提供的文档。这意味着你不必为文档计算和存储嵌入，也不必实现分块和搜索算法。Assistants API 会基于我们在 ChatGPT 中构建知识检索的经验，来优化采用哪种检索技术。
- **函数调用（Function calling）**：让 assistant 能够调用你定义的函数，并把函数响应纳入其消息中。

与平台的其余部分一样，传给 OpenAI API 的数据和文件[绝不会被用于训练我们的模型⁠](https://openai.com/enterprise-privacy/)，开发者可以在认为合适时删除数据。

你可以在不写任何代码的情况下试用 Assistants API beta——前往 [Assistants playground](https://platform.openai.com/playground?mode=assistant)。

Assistants API 处于 beta 阶段，从今天起对所有开发者开放。请与我们分享你构建的成果（[@OpenAI](https://twitter.com/OpenAI)）以及你的反馈，我们会在接下来几周持续构建时将其纳入。Assistants API 及其工具的定价见[我们的价格页面⁠](https://openai.com/api/pricing/)。

## API 中的新模态

### 带视觉能力的 GPT-4 Turbo

GPT‑4 Turbo 能在 Chat Completions API 中接受图像作为输入，从而实现诸如生成字幕、细致分析现实世界图像、读取带图表的文档等用例。例如，BeMyEyes 就用这项技术帮助盲人或低视力人群完成日常任务，比如识别商品或在商店中导航。开发者可以在 API 中使用 `gpt-4-vision-preview` 来访问这一功能。我们计划在该主 GPT‑4 Turbo 模型稳定发布时把视觉支持纳入其中。[定价⁠](https://openai.com/api/pricing/)取决于输入图像的大小。例如，向 GPT‑4 Turbo 传入一张 1080×1080 像素的图像花费 0.00765 美元。查看[我们的视觉指南](https://platform.openai.com/docs/guides/vision)。

### DALL·E 3

开发者可以通过在 Images API 中指定 `dall-e-3` 作为模型，把 DALL·E 3——我们[最近向 ChatGPT Plus 和 Enterprise 用户推出⁠](https://openai.com/index/dall-e-3-is-now-available-in-chatgpt-plus-and-enterprise/)——直接集成进他们的应用和产品。像 Snap、可口可乐和 Shutterstock 这样的公司已用 DALL·E 3 为其客户和活动以编程方式生成图像与设计。与前一版 DALL·E 类似，该 API 内置了审核，以帮助开发者保护其应用免遭滥用。我们提供不同的格式和质量选项，价格从每张生成图像 0.04 美元起。查看我们的[API 中使用 DALL·E 3 入门](https://platform.openai.com/docs/guides/images)指南。

### 文本转语音（TTS）

开发者现在可以通过文本转语音 API 从文本生成人品质的语音。我们新的 TTS 模型提供六种预设语音可供选择，以及两个模型变体 `tts-1` 和 `tts-1-hd`。`tts` 针对实时用例优化，`tts-1-hd` 针对质量优化。价格从每 1000 个输入字符 0.015 美元起。查看我们的[TTS 指南](https://platform.openai.com/docs/guides/text-to-speech)开始使用。

## 模型定制

### GPT-4 微调实验性访问

我们正在为 **GPT‑4 微调**创建一个实验性访问计划。初步结果表明，相比 GPT‑3.5 微调所能带来的大幅收益，GPT‑4 微调需要更多努力才能相对基础模型取得有意义的提升。随着 GPT‑4 微调的质量和安全性不断改进，正在积极使用 GPT‑3.5 微调的开发者将在其[微调控制台](https://platform.openai.com/finetune)里被提供一个申请 GPT‑4 计划的选项。

### 定制模型

对于那些需要超越微调所能提供的更多定制的组织（尤其适用于拥有极大数据集的领域——至少数十亿 token），我们还推出一个**定制模型计划（Custom Models program）**，给予被选中的组织一个机会，与一组专门的 OpenAI 研究人员合作，针对其特定领域训练定制的 GPT‑4。这包括修改模型训练过程的每一步，从做额外的领域特定预训练，到运行一个针对该特定领域定制的 RL 后训练流程。组织将对他们的定制模型拥有独占访问权。按照我们现有的企业隐私政策，定制模型不会被提供给其他客户或与他们共享，也不会被用于训练其他模型。此外，提供给 OpenAI 用于训练定制模型的专有数据不会在任何其他情境下被复用。起步阶段这将是一个非常有限（且昂贵）的计划——有兴趣的组织可以[在此申请⁠](https://openai.com/form/custom-models/)。

## 更低价格与更高速率限制

### 更低价格

我们在平台上下调了[若干价格⁠](https://openai.com/api/pricing/)，把节省让利给开发者（以下所有价格均以每 1000 token 计）：

- GPT‑4 Turbo 输入 token 相比 GPT‑4 便宜 3 倍，为 0.01 美元；输出 token 便宜 2 倍，为 0.03 美元。
- GPT‑3.5 Turbo 输入 token 相比上一个 16K 模型便宜 3 倍，为 0.001 美元；输出 token 便宜 2 倍，为 0.002 美元。此前使用 GPT‑3.5 Turbo 4K 的开发者，在输入 token 上享受 33% 的降幅，为 0.001 美元。这些低价仅适用于今天推出的新 GPT‑3.5 Turbo。
- 微调后的 GPT‑3.5 Turbo 4K 模型输入 token 降低 4 倍，为 0.003 美元；输出 token 便宜 2.7 倍，为 0.006 美元。使用新 GPT‑3.5 Turbo 模型时，微调也以与 4K 相同的价格支持 16K 上下文。这些新价格同样适用于微调后的 `gpt-3.5-turbo-0613` 模型。

### 更高速率限制

为帮助你扩展应用，我们为所有付费 GPT‑4 客户把每分钟 token 数限制翻倍。你可以在你的[速率限制页面](https://platform.openai.com/account/rate-limits)查看新的速率限制。我们也发布了决定自动速率限制提升的[用量层级](https://platform.openai.com/docs/guides/rate-limits/usage-tiers)，让你知道你的用量限制将如何自动扩展。你现在可以从[账户设置](https://platform.openai.com/account/rate-limits)申请提升用量限制。

## 版权盾牌（Copyright Shield）

OpenAI 致力于通过我们系统中内置的版权防护来保护客户。今天，我们更进一步，推出 Copyright Shield——当你在版权侵权相关的法律索赔中面临麻烦时，我们将介入并为我们的客户辩护、承担所产生的费用。这适用于 ChatGPT Enterprise 和我们开发者平台的全面可用功能。

## Whisper v3 与 Consistency Decoder

我们发布 [Whisper large-v3](https://github.com/openai/whisper)，即我们开源自动语音识别模型（ASR）的下一版本，它在各语言上性能都有提升。我们也计划在不久的将来在 API 中支持 Whisper v3。

我们还开源了 [Consistency Decoder](https://github.com/openai/consistencydecoder)，它是 Stable Diffusion VAE 解码器的一个可直接替换项。这款解码器改进了所有兼容 Stable Diffusion 1.0+ VAE 的图像，在文字、人脸和直线上都有显著提升。
