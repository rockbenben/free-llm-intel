# 我们的第一阶段嵌入式评估

我们已与四家独立评估机构——Apollo Research、METR、Transluce 和 Goodfire——签署协议，开展第一阶段的嵌入式评估。随着 AI 能力快速发展、潜在风险不断增加，独立评估的公开报告可以让公众更清楚地了解各实验室如何评估和管理这些风险。

嵌入式评估让独立专家能够深入访问实验室的内部模型和系统，在较长时间内评估模型对齐情况和安全防护措施的有效性，尤其关注与我们的安全论证相关的方面。根据每项评估的需要，评估机构可访问我们研究人员使用的部分内部资源，包括模型检查点、源代码、训练和评估数据、监测系统及技术文档，还可以与负责相关工作的研究人员和工程师交流。这些访问权限为评估机构提供了开展独立评估所需的证据和背景信息，帮助他们发现我们可能未曾预料到的失效问题。

我们的初期评估聚焦于模型在训练和内部使用期间的对齐情况与安全防护措施，为我们的[安全论证](https://openai.com/index/towards-safety-cases-for-frontier-ai-training/)提供补充。这些评估以我们的[第三方评估优先事项和原则](https://openai.com/index/priorities-principles-third-party-assessments/)，以及多年来与[第三方评估机构](https://openai.com/index/strengthening-safety-with-external-testing/)的合作为基础。这些合作包括近期在提供深入内部访问权限的情况下，对[我们的内部监测系统](https://metr.org/blog/2026-10-22-red-teaming-openai-agent-monitoring/)开展的试点评估，以及对 [Hugging Face 事件](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/)的调查。未来几个月，我们将利用从中获得的经验，深化与独立专家的合作。这些工作也有助于落实我们在《白宫超级智能协议》下作出的承诺，其中包括同意对我们的安全控制措施开展独立评估。这些合作有助于推动全行业建立更完善的独立评估与公开透明共同标准。

## 参与嵌入式评估试点的机构

### Apollo Research

在本次试点评估中，[Apollo Research](https://www.apolloresearch.ai/) 将评估模型是否可能暗中采取违背开发者意图的行动，以及我们的安全防护措施能否检测到此类行为。评估将以训练、安全测试和内部使用中获得的证据为依据。Apollo 将分两个阶段评估以下四项主张：

- 训练未激励颠覆性行为。
- 高强度评估和红队测试未能诱发颠覆性行为。
- 模型在内部使用期间未曾试图实施颠覆性行为。
- 颠覆性行为背后的推理过程能够被检测到。

在 Apollo 评估的第一阶段，我们将提供对部分已公开和未发布模型及训练检查点、相关训练数据和评估结果、训练干预记录、监测系统及其标记的行为的访问权限，并安排可提供背景信息的研究人员与其交流，同时提供开展独立测试所需的工具和算力。

### Goodfire

[Goodfire](https://www.goodfire.com/) 将派驻可解释性研究人员，并使用 Goodfire 平台分析模型内部机制。其评估的主要目标是训练过程监测、调试和对齐。这些评估主要面向 OpenAI 内部研究人员，他们将利用评估发现来改进安全性。随着合作推进，Goodfire 也将发布从中获得的经验和发现。

### METR

我们计划与 [METR](https://metr.org/) 开展两项评估，聚焦于模型对齐和监测：

- **对齐评估：**在第一阶段，METR 将评估我们迄今为止规模最大的一次强化学习训练中的不对齐行为，包括现有测试和监测器可能遗漏的失效问题。针对选定的训练任务，在商定的访问权限、资源和安全安排范围内，METR 将独立确定评估优先事项，并迭代开展搜寻、分析和引导式提取实验。访问权限将包括使用相关检查点进行采样，以及查阅本次训练任务的训练与评估运行轨迹和不对齐行为监测记录。第一阶段的评估将聚焦于我们规模最大的一次前沿模型强化学习训练。[1](https://openai.com/zh-Hans-CN/index/our-first-phase-of-embedded-assessments/#citation-bottom-1)
- **监测器评估：**我们近期与 METR 合作开展了一次监测器压力测试演练[2](https://openai.com/zh-Hans-CN/index/our-first-phase-of-embedded-assessments/#citation-bottom-2)。我们已初步同意开展另一项[监测器评估](https://metr.org/blog/2026-10-14-control-assessment-proposal/)，并希望扩大评估范围，但仍需双方就评估范围达成一致。

### Transluce

[Transluce](https://transluce.org/) 将对我们的后训练对齐评测开展初步评估，审视其质量和覆盖范围。在初步评估中，我们将向 Transluce 提供对部分已公开和未发布模型、我们的后训练对齐评测及相关结果、配套的模型行为数据和安全论证文档的访问权限，并安排可提供背景信息的研究人员与其交流，同时提供开展独立测试所需的工具和算力。

OpenAI 和 Transluce 也有意在 2027 年初开展为期约八周的后续评估，届时将扩大访问权限，涵盖更多模型，允许更深入地访问我们的对齐评测，并提供有关评测结果如何影响模型发布决策的信息。

## 嵌入式评估规程

我们参考评估机构的意见制定了规程和流程，在提供深入访问权限的同时，兼顾安全、保密、监督以及评估的独立性和公正性。我们公开这些规程和流程，是为了说明我们将如何与嵌入式评估机构合作，并推动关于嵌入式评估规范的讨论——这类评估目前尚无统一标准。我们预计，随着对如何最佳开展此类评估的认识不断加深，这些规程和流程也需要持续完善。尤其在嵌入式评估的早期阶段，我们预计会遇到技术访问难题、场地限制、安全规程变化及其他意外问题。我们希望与嵌入式评估机构携手应对这些挑战，并分享从中获得的经验。

### 范围界定与迭代

每次合作开始时，双方都会商定评估范围，以及开展严谨评估所需的访问权限、资源和安全安排。有些评估检验特定的安全主张；另一些则让评估机构有空间在指定系统或训练任务中发现意料之外的失效模式。无论哪种情况，评估机构都需要有充分的自由，沿着证据线索继续调查、改进方法，并在评估发现有此必要时提出进一步评估的建议。我们也建立了相应流程，以应对评估推进过程中新增的访问需求。当直接访问可能暴露我们最敏感的知识产权（如模型权重或架构）时，我们会考虑替代方案，包括安排评估人员与 OpenAI 研究人员结对开展分析。

### 安全的现场工作环境

需要访问敏感机密信息的评估人员将在 OpenAI 办公场所现场工作，并使用 OpenAI 提供的设备开展工作。这样做的主要目的是保障他们所访问信息的安全。现场工作也让评估人员有机会与专门负责支持的工作人员交流，后者可以协助他们使用访问权限，并为评估提供背景信息。我们还要求嵌入式评估人员在开展实验和评估时，至少[3](https://openai.com/zh-Hans-CN/index/our-first-phase-of-embedded-assessments/#citation-bottom-3)遵守与 OpenAI 员工相同的安全标准。

### 监督与争议解决

我们的安全与安保委员会是 OpenAI Foundation 董事会下设的独立监督委员会，将有权了解嵌入式评估情况，并能够在评估开始前、进行中和结束时履行监督职责。安全与安保委员会将收到未经删节的报告，评估机构与委员会在评估期间也可以相互交流，包括私下交流。OpenAI 与任何评估机构之间的分歧，都将提交安全咨询小组和 OpenAI 高管处理，并须在规定期限内解决；分歧提交时，也将及时通知安全与安保委员会。如果分歧仍未解决，将提交安全与安保委员会处理。

### 员工交流与正式确认

与员工交流有助于评估人员了解内部信息及相关工作的背景。OpenAI 将授权相关员工与评估人员交流，并提供指导；评估人员也可根据需要请求与其他员工交流。为鼓励开放、坦诚的交流并保护员工隐私，这些讨论内容不得对外引用：它们可以为评估提供参考，但不能公开，也不能归于具体员工名下。评估机构可以通过单独的正式确认渠道，请求 OpenAI 出具经其确认的声明，对评估人员在与员工交流中了解到的内容予以核实、更正或澄清。这些声明不归于任何个人名下，也不用于表述个人观点。评估机构可以发布经 OpenAI 正式确认的声明，也可以披露 OpenAI 拒绝确认某项声明的情况。

### 利益冲突披露与冷却期

清晰、透明地管理利益冲突，包括涉及个人关系、经济利益[4](https://openai.com/zh-Hans-CN/index/our-first-phase-of-embedded-assessments/#citation-bottom-4)及其他方面的冲突，对评估的公正性和独立性至关重要。冷却期[5](https://openai.com/zh-Hans-CN/index/our-first-phase-of-embedded-assessments/#citation-bottom-5)也需要审慎设计，让评估人员能够负责任地为不同实验室开展工作，同时谨慎处理涉及竞争的信息。我们正与评估机构合作，为利益冲突和冷却期制定明确的流程，包括允许灵活采取缓解措施，并确保要求回避的决定透明公开。

### 报告发布与负责任披露期限

评估机构在发布评估报告时保持独立性，但我们将保留删去机密信息的权利，这与以往的第三方合作安排一致。出于负责任披露的考虑，我们也可能请求延后公开，以留出时间处理可能带来安保或安全风险的评估发现，并修复尚存的问题。

公开报告将帮助公众了解评估发现及其局限，而更详细的保密报告则为监督机构提供采取行动所需的证据。我们希望这些评估能够改进我们识别和应对风险的方式，并为公众判断我们的安全工作提供更清晰的依据。

## 展望未来

这些评估为我们持续开展的对齐与安全工作带来了独立视角。公开报告评估发现，将提高这些工作的透明度，并让公众更有信心了解风险是如何被识别和应对的。我们期待第一阶段的评估逐步促成长效、稳定的嵌入式合作，持续为我们最关键的安全主张和安全论证提供第三方安全信息与改进建议。

我们将继续与多家独立第三方机构合作，助力建立汇集多元专业知识和方法的健康评估生态。有些调查需要持续在现场接触敏感系统；另一些则主要评估已部署或即将部署的模型，或审阅公开文档。

未来几个月，我们将支持针对更多安全问题开展外部评估。我们也在探索未来开展嵌入式评估的可能性，以审查我们对安全框架的遵守情况，以及我们的组织文化和流程。我们致力于拓展这项工作，并帮助建立使其持续开展所需的能力和共同标准。
