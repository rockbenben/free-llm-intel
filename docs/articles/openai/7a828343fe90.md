# GPT-3 新能力：编辑与插入

我们发布了 GPT-3 和 Codex 的新版本，它们可以编辑或在现有文本中插入内容，而不只是续写现有文本。

***2025 年 5 月 16 日更新：*** 我们推出了 Codex，一个能在并行处理大量任务的云端软件工程 agent。[了解更多⁠](https://openai.com/index/introducing-codex/)*。*

我们发布了 [GPT-3](https://beta.openai.com/docs/engines/gpt-3) 和 [Codex](https://beta.openai.com/docs/engines/codex-series-private-beta) 的新版本，它们可以编辑或在现有文本中插入内容，而不只是续写现有文本。这些新能力让使用 [OpenAI API](https://beta.openai.com/) 修改既有内容变得切实可行，例如重写一段文字或重构代码。这解锁了新用例并改进已有用例；例如，插入功能已在 [GitHub Copilot](https://copilot.github.com/) 中试点，早期结果令人鼓舞。

- [阅读 edit 文档](https://beta.openai.com/docs/api-reference/edits)
- [阅读 insert 文档](https://beta.openai.com/docs/guides/comp)

GPT-3 和 Codex 传统上只是根据前文在既有内容末尾追加文本。无论处理文本还是代码，写作都不仅是追加——它是一个对既有文本不断修订的迭代过程。GPT-3 和 Codex 现在能够编辑文本：修改现有内容，或在内容中间插入文本。

## 在文本中间插入

新的 [insert](https://beta.openai.com/docs/guides/completion/inserting-text)[能力](https://beta.openai.com/docs/guides/code/inserting-code) 会在既有内容中间添加与上下文相关的文本。为模型提供“未来上下文”可以提升续写质量，适用于撰写长文、段落间过渡、遵循提纲，或引导模型走向某个结尾等应用。

在上面的例子中，目标是填写大纲中两个小标题之间的文字。缺少后续章节的上下文时，模型生成的内容与第二个章节无关；把后续章节的上下文纳入考虑后，模型生成的内容能将两个章节衔接起来。

insert 对写代码尤其有用。事实上，开发这一能力的最初动机正是 Codex——软件开发中，我们通常把代码加在既有文件的中间，续写点前后都有代码。在上面的例子中，模型成功补全了缺失的函数 `prune`，并与已写好的代码衔接。我们还补上了 docstring 和缺失的 import——若不知道后续代码，这是做不到的。在 GitHub Copilot 中，Insert 目前正在试点，早期结果令人鼓舞。

insert 能力今天已在 API 的 beta 中提供，入口是 [completions 端点](https://beta.openai.com/docs/guides/completion/introduction) 以及 [Playground](https://beta.openai.com/playground) 的新界面。该能力可与 GPT-3 和 Codex 的最新版本 `text-davinci-002` 和 `code-davinci-002` 一起使用。[定价⁠](https://openai.com/api/pricing/)与之前的 Davinci 版本相同。

## 编辑现有文本

写文本和代码的相当一部分时间花在编辑既有内容上。我们在 beta 中发布了一个名为 [edits](https://beta.openai.com/docs/api-reference/edits) 的新端点，通过指令来修改现有文本，而不是续写它。

edit 的用法是指定现有文本作为 prompt，并附上如何修改它的指令。edits 端点可以改变文本的语气或结构，也可以做定点修改，例如纠正拼写。我们还观察到 edits 在空 prompt 上同样表现出色，从而实现类似 [completions 端点](https://beta.openai.com/docs/guides/completion/introduction) 的文本生成。在上面的例子中，我们用 edits 依次：（1）添加一首诗，（2）把诗改成第一人称，（3）把诗转成一封带有恰当称呼和落款的信。

edits 端点对写代码特别有用。它在重构、添加文档、编程语言间转换、修改编码风格等任务上表现出色。上面的例子从包含按人口排名城市的 JSON 输入开始。第一次 edit 中，Codex 移除了 JSON 中的 rank 字段，并把州缩写改成全称；第二次 edit 把 JSON 文件转换为某个函数返回的 YAML。

Editing 作为 API 中的[专用端点](https://beta.openai.com/docs/api-reference/edits) 以及 [Playground](https://beta.openai.com/playground) 的新界面无提供，由模型 `text-davinci-edit-001` 和 `code-davinci-edit-001` 支持。edits 端点目前[免费使用⁠](https://openai.com/api/pricing/)，并以 beta 形式公开开放。
