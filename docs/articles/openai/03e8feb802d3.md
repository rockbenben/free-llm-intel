# 推出 Triton：面向神经网络的开源 GPU 编程

我们发布 Triton 1.0——一门开源的类 Python 编程语言，让没有 CUDA 经验的研究者也能编写高度高效的 GPU 代码，而且大多数时候能达到与专家水准相当的水平。

## 为何重要

Triton 让以最相对少的努力触及硬件峰值性能成为可能；例如，用它可以在不到 25 行代码内写出性能与 cuBLAS 相当的 FP16 矩阵乘法内核——而这很多 GPU 程序员做不到。我们的研究者已经用它产出比等效 Torch 实现高效达 2 倍的内核，我们也期待与社区协作，让 GPU 编程对所有人都更容易接触。

深度学习领域的新研究想法通常用原生框架算子的组合来实现。虽然方便，但这种方式往往需要创建（和/或搬运）大量临时张量，从而损害大规模神经网络的性能。编写专用 GPU 内核可以缓解这些问题，但做起来出奇地困难——GPU 编程有太多精微之处[1](https://openai.com/index/triton/#citation-bottom-1)、[2](https://openai.com/index/triton/#citation-bottom-2)、[3](https://openai.com/index/triton/#citation-bottom-3)。而且，尽管近来涌现了多种系统[4](https://openai.com/index/triton/#citation-bottom-4)、[5](https://openai.com/index/triton/#citation-bottom-5)试图简化这一流程，我们发现它们要么太啰嗦、要么欠灵活，或生成的代码明显慢于我们手工调优的基线。这促使我们扩展并改进 Triton[6](https://openai.com/index/triton/#citation-bottom-6)——一门较新的语言与编译器，其原创作者如今在 OpenAI 工作。

## GPU 编程的挑战

现代 GPU 的架构大致可分为三大部件——DRAM、SRAM 和 ALU——优化 CUDA 代码时每一个都必须考虑：

- 来自 DRAM 的内存传输必须*合并（coalesce）*为大事务，以利用现代内存接口的大总线宽度。
- 数据在复用前必须手动缓存到 SRAM，并且要管理好取回时的共享内存组（bank）冲突。
- 计算必须跨流多处理器（SM）以及在 SM 内部仔细划分与调度，以促进指令/线程级并行并利用专用 ALU（如 tensor core）。

GPU 的基本架构。

对这些因素全部加以权衡极具挑战，即便对身经百战、拥有多年经验的 CUDA 程序员也是如此。Triton 的目的就是将这些优化完全自动化，让开发者更好地专注于并行代码的高层逻辑。Triton 追求广泛适用，因此不会自动跨 SM 调度工作——把一些重要的算法考量（如分块 tiling、SM 间同步）留给开发者自行决定。

|  | **CUDA** | **TRITON** |
| --- | --- | --- |
| 内存合并 | 手动 | 自动 |
| 共享内存管理 | 手动 | 自动 |
| 调度（SM 内部） | 手动 | 自动 |
| 调度（跨 SM） | 手动 | 手动 |

## 编程模型

在众多领域专用语言与 JIT 编译器中，Triton 可能与 Numba 最相似：内核以装饰过的 Python 函数定义，并在一个由所谓*实例（instance）*构成的网格上以不同 `program_id` 并发启动。但如下方代码片段所示，相似之处仅此而已：Triton 通过作用于*块（block）*——维度为 2 的幂的小数组——的操作来暴露实例内并行，而非单指令多线程（SIMT）[7](https://openai.com/index/triton/#citation-bottom-7)执行模型。如此一来，Triton 实际上抽象掉了 CUDA 线程块*内部*与并发相关的一切问题（如内存合并、共享内存同步/冲突、tensor core 调度）。


这对易于并行（即逐元素）的计算也许帮助不大，但能极大简化更复杂 GPU 程序的开发。

以融合（fused）softmax 内核为例（见下文），每个实例对给定输入张量 *X_∈R_M_×_N* 的不同行做归一化。这种并行策略的标准 CUDA 实现可能很难写：线程在并发归约 *X* 的同一行时必须显式同步。而在 Triton 中，这些复杂性大部分消失了——每个内核实例加载感兴趣的行，用类 NumPy 的原语顺序地归一化。

#### Python

```
1import triton2import triton.language as tl34@triton.jit5def softmax(Y, stride_ym, stride_yn, X, stride_xm, stride_xn, M, N):6    # row index7    m = tl.program_id(0)8    # col indices9    # this specific kernel only works for matrices that 10    # have less than BLOCK_SIZE columns11    BLOCK_SIZE = 102412    n = tl.arange(0, BLOCK_SIZE)13    # the memory address of all the elements14    # that we want to load can be computed as follows15    X = X + m * stride_xm + n * stride_xn16    # load input data; pad out-of-bounds elements with 0 17    x = tl.load(X, mask=n < N, other=-float('inf'))18    # compute numerically-stable softmax19    z = x - tl.max(x, axis=0)20    num = tl.exp(z)21    denom = tl.sum(num, axis=0)22    y = num / denom23    # write back to Y24    Y = Y + m * stride_ym + n * stride_yn25    tl.store(Y, y, mask=n < N)2627import torch28# Allocate input/output tensors29X = torch.normal(0, 1, size=(583, 931), device='cuda')30Y = torch.empty_like(X)31# SPMD launch grid32grid = (X.shape[0], )33# enqueue GPU kernel34softmax[grid](Y, Y.stride(0), Y.stride(1), 35              X, X.stride(0), X.stride(1),36              X.shape[0]    , X.shape[1])
```

注意，Triton JIT 把 X 和 Y 视为*指针*而非张量；我们认为保留对内存访问的低层控制很重要，以便处理更复杂的数据结构（如块稀疏张量）。

至关重要的是，这个特定的 softmax 实现会在整个归一化过程中把 *X* 的行保留在 SRAM 中，从而在适用时（约 <32K 列）最大化数据复用。这与 PyTorch 内部的 CUDA 代码不同——后者使用临时内存，虽更通用但显著更慢（见下文）。这里的结论不是 Triton 天然更好，而是它简化了专用内核的开发——这些内核可以比通用库中的实现快得多。


Torch（v1.9）JIT 较低的性能，凸显了从高层张量操作序列自动生成 CUDA 代码的困难。

#### Python

```
1@torch.jit.script2def softmax(x):3    x_max = x.max(dim=1)[0]4    z = x - x_max[:, None]5    numerator = torch.exp(x)6    denominator = numerator.sum(dim=1)7    return numerator / denominator[:, None]
```

## 矩阵乘法

能为逐元素操作与归约编写融合内核很重要，但鉴于矩阵乘法任务在神经网络中的核心地位，这还不够。事实证明，Triton 处理矩阵乘法同样出色——仅用约 25 行 Python 代码即可达到峰值性能。另一方面，在 CUDA 中实现类似的东西要[费力得多](https://github.com/openai/blocksparse/blob/master/src/matmul_op_gpu.cu)，甚至可能性能更低。

#### Python

```
1@triton.jit2def matmul(A, B, C, M, N, K, stride_am, stride_ak, 3            stride_bk, stride_bn, stride_cm, stride_cn,4            **META):5    # extract metaparameters6    BLOCK_M, GROUP_M = META['BLOCK_M'], META['GROUP_M']7    BLOCK_N = META['BLOCK_N']8    BLOCK_K = META['BLOCK_K']9    # programs are grouped together to improve L2 hit rate10    _pid_m = tl.program_id(0)11    _pid_n = tl.program_id(1)12    pid_m = _pid_m // GROUP_M13    pid_n = (_pid_n * GROUP_M) + (_pid_m % GROUP_M)14    # rm (resp. rn) denotes a range of indices15    # for rows (resp. col) of C16    rm = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)17    rn = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)18    # rk denotes a range of indices for columns 19    # (resp. rows) of A (resp. B)20    rk = tl.arange(0, BLOCK_K)21    # the memory addresses of elements in the first block of22    # A and B can be computed using numpy-style broadcasting23    A = A + (rm[:, None] * stride_am + rk[None, :] * stride_ak)24    B = B + (rk [:, None] * stride_bk  + rn[None, :] * stride_bn)25    # initialize and iteratively update accumulator26    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)27    for k in range(K, 0, -BLOCK_K):28        a = tl.load(A)29        b = tl.load(B)30        # block level matrix multiplication31        acc += tl.dot(a, b)32        # increment pointers so that the next blocks of A and B33        # are loaded during the next iteration34        A += BLOCK_K * stride_ak35        B += BLOCK_K * stride_bk36    # fuse leaky ReLU if desired37    # acc = tl.where(acc >= 0, acc, alpha * acc)38    # write back result39    C = C + (rm[:, None] * stride_cm + rn[None, :] * stride_cn)40    mask = (rm[:, None] < M) & (rn[None, :] < N)41    tl.store(C, acc, mask=mask)
```

Triton 中的矩阵乘法。

手写矩阵乘法内核的一个重要优势，是可以按需定制，融合处理输入（如切片）和输出（如 Leaky ReLU）的变换。没有 Triton 这样的系统，对矩阵乘法内核做非平凡的修改，是只有具备卓越 GPU 编程造诣的开发者才能驾驭的事。


## 高层系统架构

Triton 的良好性能来自围绕 Triton-IR 构建的模块化系统架构——这是一种基于 LLVM 的中间表示，其中多维值块是一等公民。


`@triton.jit` 装饰器的工作方式是遍历所提供 Python 函数的抽象语法树（AST），使用通用的 SSA 构造算法即时生成 Triton-IR。[8](https://openai.com/index/triton/#citation-bottom-8) 生成的 IR 代码随后由我们的编译器后端进行简化、优化和自动并行化，再转换为高质量的 LLVM-IR——最终转为 PTX——以在较新的 NVIDIA GPU 上执行。目前不支持 CPU 和 AMD GPU，我们欢迎社区为解决这一限制作出贡献。

## 编译器后端

我们发现，通过 Triton-IR 使用分块程序表示，让编译器能够自动执行大量重要的程序优化。例如，只需查看计算密集的分块级操作（如 `tl.dot`）的操作数，就能自动把数据缓存到共享内存——并用标准的活跃性分析技术完成分配与同步。


另一方面，Triton 程序可以被高效地自动并行化：（1）通过并发执行不同内核实例跨 SM 并行；（2）通过分析每个分块级操作的迭代空间并在不同 SIMD 单元间恰当划分，实现 SM 内并行，如下图所示。
