# Qodo 借助 Codex 把上下文带进 AI 代码评审

Qodo 把组织上下文与代码库标准带进 Codex，帮助开发者跨仓库揪出 P0 问题。

[开始构建](https://openai.com/startups)

公司规模：初创公司

地区：北美

行业：科技

产品：API、Codex


[Qodo](https://www.qodo.ai/) 为代码评审和软件质量构建 AI 工具，给 coding agents 提供它们理解自己所改动代码时需要的组织知识。联合创始人兼 CEO Itamar Friedman 把它称作「coding agent 最好的朋友」。

Qodo 使用包括 GPT-6 Astra 在内的 OpenAI 模型来收集工程知识、评审代码并监控软件质量。它的 Codex 插件把这份上下文和评审能力带进了开发者的编码会话。

> 「我们很喜欢 OpenAI 的模型。我们想要前沿的、最好的推理模型，也想要真正快的模型。」

—Itamar Friedman，Qodo 联合创始人兼 CEO

## 用 Codex 跨仓库找出 P0 bug

Itamar 谈到，客户的环境动辄横跨 10,000 个甚至更多仓库，一处本地代码改动就可能弄坏下游服务，哪怕它单独看起来完全正确。Qodo 针对这一点在 Codex 应用市场里做了一个插件。

「Codex 非常擅长接下一个本地任务，并用高效的方式把它完成，」Itamar 说。Qodo 的插件让 Codex 能够访问代码库知识、组织规则，并通过 Qodo 的 Agentic Toolbox 获得独立评审。

有了上下文，Codex 就能把跨仓库的依赖关系一并考虑进去，包括那些托管在不同 Git provider 上的仓库，以及通过 Kafka 连接起来的服务。「Qodo 会把这条连接搭起来，帮 Codex 把软件当成一个整体来看，从而不会漏掉那些 P0 bug，」Itamar 说。

## 自动化评审，同时保留人的判断

在 Codex 开始写代码之前，它可以先用 Qodo 的插件取回相关的代码库规则，以及 pull request 的历史和模式。Codex 改完之后，Qodo 会对这些改动做评审，并在同一个会话里把发现的问题直接返回给 Codex——赶在开发者开出 pull request 之前。

Qodo 的 AI Developer Relations Lead Nnenna Ndukwe 看到，开发者正在用这套工作流，在 Codex 里配合 GPT-6 模型开发功能、处理技术债。他们把 Codex 的编码工作与 Qodo 的独立评审之间的交接自动化了。「这正是我看到开发者在做的事，非常令人兴奋，因为 GPT-6 的能力极强，」Nnenna 说。

Itamar 把编码 agents 和评审 agents 形容为「yin and yang」：一个产出代码，另一个质疑代码。每个角色都需要自己的配置和上下文，也可能涉及多个 agents。他的设想是让 agents 彼此讨论各自的发现，只把「自己不接受的部分」摆出来交给人评审。开发者由此成为规划者和评审者，可以连同 agents 的讨论、上下文以及以往开发者的决策一起，查看那些尚未解决的问题。

「信任就是这么建立起来的，」Itamar 说。「我认为这让整个流程总体上更高效，」Nnenna 补充道。「我们得以把自己专业能力里最好的部分发挥出来。」

## 让 Codex 参与每天的工作

在 Qodo 内部，Nnenna 已经在自己的自动化开发工作流和知识型工作中使用 GPT-6 Astra 的 Extra High 与 Ultra effort 档位。

> 「有什么是 Codex 做不到的？Codex 做的每一件事我都喜欢。我喜欢把 AI 和自动化结合起来这个思路。」

—Nnenna Ndukwe，Qodo AI Developer Relations Lead

Nnenna 给 Codex 排了定时任务，让它汇报这一周她完成了什么、接下来可以在哪些方向上聚焦或改进。她也用它去研究社交平台上关于 agentic engineering 的讨论，并为开发者内容提出选题。涉及她自己的代码改动时，她会让 Codex 定时分析她的工作，并建议该创建或打磨哪些 agent skills。

## 用 Decisions API 决定哪些编码规则适用

Itamar 看到一个机会：用 OpenAI 近期推出的 Decisions API 来选择开发每个阶段该适用哪些规则和 agent skills，而不是把每一个决定都交给语言模型。

他举了一个例子：Decisions API 先从 200 条规则里挑出哪些需要检查，再让语言模型对这些相关规则做推理，这样选择更快、成本更低，同时还能提升评审质量。「Decisions API 对我们来说是一个巨大的机会，它能让整个流程更可信，」Itamar 说。

## 构建客户可以自己拥有的软件工厂

Qodo 的做法是「把人工智能最好的一面，和传统软件工程和脚本最好的一面结合起来」，Nnenna 说。公司知识为 coding agents 指引方向，独立评审检查它们的成果，人的专业判断则来解决剩下的问题。

这打下了 Itamar 所说的软件工厂的基础：一套客户可以自行组装、自行拥有的系统，把编码 agents 和评审 agents 聚到一起，并带着对软件在生产环境中如何变化的理解。

Qodo 正与 OpenAI 一起构建这样一个未来：coding agents 把一家公司积累的经验更多地调动起来，而开发者可以把自己的判断力集中在最要紧的地方。
