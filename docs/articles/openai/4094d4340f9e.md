# Qodo 使用 Codex 将上下文构建到 AI 代码审查中

Qodo 将组织环境和代码库标准引入 Codex，帮助开发人员跨存储库捕获 P0 问题。

[开始构建](https://openai.com/startups)

公司规模：初创公司

地区： 北美

行业：科技

产品：API、Codex

[Qodo](https://www.qodo.ai/) 构建用于代码审查和软件质量的人工智能工具，为编码代理提供理解他们更改的代码所需的组织知识。联合创始人兼首席执行官 Itamar Friedman 称其为“编码代理最好的朋友”。

Qodo 使用包括 GPT‑6 Astra 在内的 OpenAI 模型来收集工程知识、审查代码和监控软件质量。它的 Codex 插件将上下文和审查带入开发人员的编码会话中。

> “我们喜欢 OpenAI 模型。我们想要前沿的、最好的推理模型，但也想要那些非常快的模型。”

——Itamar Friedman，Qodo 联合创始人兼首席执行官

## 使用 Codex 跨存储库查找 P0 错误

Itamar 描述了可以跨越 10,000 个或更多存储库的客户环境，其中本地代码更改可能会破坏下游服务，即使它本身看起来是正确的。 Qodo 在 Codex 市场中构建了一个插件来解决这个问题。

“Codex 非常擅长承担本地任务并以有效的方式完成它，”Itamar 说。 Qodo 的插件使 Codex 能够通过 Qodo 的 Agentic Toolbox 访问代码库知识、组织规则和独立审查。

通过上下文，Codex 可以解释存储库之间的依赖关系，包括由不同 Git 提供商托管的存储库或通过 Kafka 连接的服务。 “Qodo 将建立这种联系，并帮助 Codex 从整体上看待软件，而不会错过那些 P0 错误，”Itamar 说。

## 自动审查，同时保留人工判断

在 Codex 开始编写代码之前，它可以使用 Qodo 的插件检索相关的代码库规则并拉取请求历史记录和模式。 Codex 进行更改后，Qodo 会对其进行审核，并在开发人员打开拉取请求之前，在同一会话中将其结果直接返回给 Codex。

Qodo 的 AI 开发者关系主管 Nnenna Ndukwe 看到开发者使用此工作流程来构建功能并利用 Codex 中的 GPT-6 模型解决技术债务。他们正在自动化 Codex 的编码工作和 Qodo 的独立审查之间的交接。 “这就是我看到开发人员所做的事情，这真的很令人兴奋，因为 GPT-6 功能非常强大，”Nnenna 说。

Itamar 将编码和审查代理描述为“阴阳”：一个创建代码，另一个挑战代码。每个角色都需要自己的设置和上下文，并且可能涉及多个代理。他的愿景是让特工讨论调查结果，并“只提出他们不接受的内容”以供人工审查。开发人员将成为规划者和审查者，能够检查未解决的问题以及代理的讨论、背景和先前的开发人员决策。

“这就是建立信任的方式，”伊塔马尔说。 “我认为这使得整个过程整体更加高效，”Nnenna 补充道。 “我们可以利用我们专业知识中最好的部分。”

## 让 Codex 每天发挥作用

Internally at Qodo, Nnenna has been using GPT‑6 Astra’s Extra High and Ultra effort settings in her own automated development workflows as well as knowledge work.

> “Codex 不做什么？我喜欢 Codex 所做的一切。我喜欢将人工智能和自动化相结合的想法。”

—Nnenna Ndukwe，Qodo 人工智能开发者关系主管

Nnenna 安排 Codex 报告她在一周内完成的工作以及下一步可以重点关注或改进的地方。她还用它来研究社交平台上有关代理工程的对话，并为开发人员内容提出建议。当涉及到她自己的代码更改时，她安排 Codex 来分析她的工作并建议创建或改进的代理技能。

## 选择决策 API 所应用的编码规则

Itamar sees an opportunity to use OpenAI’s recently launched Decisions API to choose which rules and agent skills apply at each stage of development, rather than rely on language models for every decision.

他举了一个例子，决策 API 可以在语言模型通过相关规则进行推理之前，从 200 条规则中选择需要检查的规则，从而有助于更快、更便宜地进行选择，同时提高审核质量。 “Decisions API 为我们提供了一个巨大的机会，可以让我们对流程产生更多信任，”Itamar 说道。

## 构建客户可以拥有的软件工厂

Nnenna 表示，Qodo 的方法结合了“人工智能的最佳方面以及传统软件工程和脚本编写的最佳方面”。公司知识指导编码代理，独立审查检查他们的工作，人类专业知识解决仍然存在的问题。

这为 Itamar 所描述的软件工厂奠定了基础：客户可以组装和拥有的系统，将编码和审查代理结合在一起，并了解软件在生产中如何变化。

通过 OpenAI，Qodo 正在构建一个未来，编码代理可以将更多公司的经验运用到工作中，而开发人员可以将他们的判断集中在最重要的地方。
