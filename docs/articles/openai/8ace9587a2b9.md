# 学习日

在 OpenAI，每个星期四都是学习日：员工可以选择自学那些能让他们工作更出色、但日常工作中学不到的技术技能。

Illustration: Ben Barry


我们发现，OpenAI 最大的贡献来自跨职能专家，所以我们要么把他们招进来，要么在内部培养。在学习日出现之前，我们很少看到员工跨职能成长——例如，软件背景的员工很少会去学机器学习（在其他组织除了学术界同样罕见）。自打学习日以来，这种成长变得非常普遍。

在一个典型的学习日，人们会做这些事：

- 重新实现论文。
- 跟深度学习教程。
- 折腾集群管理、编译、虚拟世界生成或编程范式的新工具。
- 学习如何在小块问题上做研究。
- 阅读 AI 中看似无关领域的新进展。

我们认为学习日可能对其他组织也有用，所以想分享它在 OpenAI 是怎么起步、怎么运作的。

## 如何长期坚持

学习日的影响来自对使用方式的严格要求。它不是休闲日，而是某种特定硬功夫的日子。我们看到并试图对抗以下几种失败模式，以便长期坚持：

**学习日可能被用来干本职活**。学习日可能变成普通工作日，因为人们可能想更快推进自己的主项目（由于内部或外部压力）。我们防止的办法是让所有团队在同一天过学习日。这形成了正向的同侪压力，鼓励每个人好好利用学习日。

**学习日可能扩展到非学习日**。我们实际上还没观察到这种情况发生。基于我们在其他组织看到的经验，我们认为这最可能说明这个人对主项目不够有热情，是给他的主管的一个信号：此人应该换团队或换项目。

**学习日可能被用来摸鱼**。我们的解法是每位团队成员通过 [Geekbot⁠(opens in a new window)](https://geekbot.com/) 在 Slack 上分享进展。这能保持兴奋度，也提供了一个问责机制。

## 走出机器人团队的学习日

我们最近把学习日从技术团队的一部分扩展到了全公司。它已经成为一种文化标志——在最新一次内部调研中，学习日是人们谈论最多的文化方面。我们很期待看到它的影响，并将继续演进和支持学习日。
