# 推进面向医疗团队的 computer-use agent

医疗行业是碎片化的：在患者真正获得诊疗之前，团队往往需要手动在系统之间搬运信息。比如，当临床医生建议做一次 MRI 时，保险公司所需的信息可能就在患者的病历里，但仍然需要团队成员把它取出来，再录入另一个独立门户，才能完成授权申请。

computer-use agent 通过点击、输入和在应用之间切换来完成多步骤工作流。在医疗领域，这让 AI 能够在团队已经在用的软件中协助处理重复性工作流。

今天，我们分享一组衡量模型在临床与行政工作流中表现、安全性和成本的新结果。我们也会介绍与 Abridge、Ambience、Cigna Healthcare、CVS Health 等领先医疗机构合作的方式，共同推进并应用 computer use，覆盖授权申请、转诊、出院规划以及就诊间隔期的随访。

医疗团队、开发者和个体临床医生现在就可以通过 OpenAI API、ChatGPT for Healthcare 和 ChatGPT for Clinicians 使用这些能力。机构可以支持符合 HIPAA 要求的工作流，配置审批与 agent 访问权限，并记录审计日志，以实现安全部署。

## 从患者的一条消息到一次 MRI 授权申请

为了展示 computer-use agent 如何帮助临床医生和授权专员处理同一个 MRI 申请，我们用合成患者数据搭建了一个演示。一位患者就下背痛给自己的临床医生发消息。computer-use agent 会查阅 EHR 中该患者的就诊记录、物理治疗记录和既往影像，起草一份 MRI 医嘱、一份就诊记录以及给患者的回复，交由临床医生审核。随后，agent 用同一批记录在保险公司门户中准备一份事先授权申请，供授权专员审核。

## 评估有用性、安全性和成本

我们在临床医生于 EHR 收件箱中处理的任务上评估了 GPT‑6 Astra。这些任务由医生参与设计，要求 Astra 执行多步骤工作流，既考察它基于纵向患者上下文进行临床推理，也考察它在复杂界面中导航的能力。评审人员把模型的操作与它产出的记录、医嘱和患者消息放在一起查看，判断这些工作在具体任务情境下是否有帮助、在临床上是否安全。

临床安全性的评估方式，是判断模型工作结果中的不准确、遗漏或操作是否有可能导致患者受到伤害。总体来看，325 项被评审的任务中有 99% 被评为安全。医生用五分制评价有用性，在 646 次评估中有 93% 选择了“非常有帮助”或“极有帮助”。

#### 行政工作流的表现与成本

在 Stanford 研究人员发布的独立 benchmark [HealthAdminBench](https://som-shahlab.github.io/health-admin-bench-website/) 上——它衡量模型在常见行政工作流上的表现——GPT‑6 Astra 拿到了可用评分细则分数的 94.3%，GPT‑6 Luna 拿到 91.8%，而每项任务成本为 8.5 美分，便宜了 98%。两个模型都在最高 reasoning effort 下评估。这些结果表明，面向高频行政工作流、既有能力又负担得起的 agent 正在取得进展。

## 与医疗机构共同开发 computer use

我们的合作伙伴构建的软件被数百个医疗系统使用，在全球范围内协调会员的照护，并为数亿患者提供医疗服务。下面的例子展示了这些机构如何开发、试点和部署 computer-use 应用，以节省时间、解决关键问题并改善患者照护。

### CVS Health：跨临床系统完成行政工作

CVS Health 正在使用 OpenAI 的 computer-use 能力，把跨临床系统的重复性工作自动化，包括发送文档、处理转诊以及支持专科会诊。这些 agent 会操作现有应用，补上 API 无法完全覆盖的步骤。

在一个生产工作流中，一个 agent 用一个周末清掉了一批积压数月的待发文档。另一个 agent 每天为数万次会诊处理系统操作步骤，帮助团队成员把精力放在需要其专业判断的工作上。CVS Health 采用校验检查和人工监督，用截图和操作记录核实动作与应用状态。CVS Health 正在开源其 [Agent Kit](https://github.com/cvs-health/cua-agent-kit)，它基于 OpenAI 的 Agents SDK 构建，把这一做法打包成可复用的流程，供更广泛地使用。

> “行政事务上少花一点时间，照护上就多一点时间。这对我们的团队和我们服务的每一个人都是好事。”

——Lagan Khare，CVS Health 工程部执行总监

数据始终留在 CVS Health 企业管控的基础设施内，由其企业 AI Governance 团队和既有的负责任 AI 政策管理。生产数据不会用于训练基础模型。

### Abridge：在照护的每个环节跨系统协同

Abridge 正在开发 computer-use agent，帮助临床医生在他们日常使用的各种场景和应用中执行照护计划，包括那些没有 API 的应用。其规划中的住院场景建立在临床对话之上，加入 EHR 信息以及护士和临床医生的上下文，用来判断哪些地方需要关注、下一步该如何协调。

举例来说，临床医生可以让 Abridge Assistant 协助解决某位患者的出院障碍。agent 可以并行处理用药获取和居家医疗协调，在打电话、发消息的同时操作电脑界面。临床医生始终保持专注于患者，只在需要临床判断的决策上被请进来。

### Cigna：让照护经理做好会员触达准备

作为 The Cigna Group 与 OpenAI 更广泛合作的一部分，Cigna Healthcare 正在把 OpenAI 的前沿模型与自身的临床专业能力结合，汇总跨系统的相关信息，让照护团队对每位会员的需求和经历有更完整的了解。这些信息可能包括福利与保障范围、服务提供方、预约和既往互动，帮助照护团队围绕由治疗医生制定的照护计划更好地支持会员。

在此之前，Cigna Healthcare 的个案管理员必须在 10 多个相互独立的临床和行政系统之间来回查找，才能收集到这些上下文。现在 computer use 可以协助在这些系统中导航，在几秒内把相关信息汇总到一起，减少查找信息的时间——最终让个案管理员有更多时间去支持会员。

> “不到八周就从概念走到部署，这说明当我们把 AI、我们在照护管理上的专业能力，以及负责任使用所需的适当护栏结合起来，能做成什么样的事。更重要的是，这意味着我们的个案管理员能更快拿到更好、更完整的洞察，从而把时间放在最重要的事上：以个性化、有温度的照护支持患者。”

——Madhu Nutakki，Cigna Healthcare CIO

### Ambience：让 computer use 在医疗领域可治理

computer use 让 agent 能在 API 触及不到的 EHR 和支付方门户中完成任务。在医疗领域，只有当每一个动作都可控、可审计时，这种能力才用得上。Ambience 额外构建了控制措施来支撑这种监督。

在这次演示中，Ambience 使用患者病历中的证据，在保险公司网站上准备事先授权申请。当记录存在歧义时，agent 会停下来询问临床医生，然后在提交前等待批准。医疗系统可以设定 agent 能执行哪些动作，随时暂停它，并获得逐步日志用于审计。

医疗初创公司正在把 computer use 的进步转化为支持照护团队的新方式。这五家公司把 AI agent 与医疗专业知识结合起来，帮助团队在系统中导航、协调下一步行动，推动照护向前走。

## 患者数据安全与 agent 控制

在医疗领域使用 computer-use agent，需要评估临床安全性、保护患者信息，并明确限定 agent 在没有人复核的情况下可以做什么。

ChatGPT for Healthcare 提供基于角色的访问控制和审计日志，以支撑监督。机构可以在自己的工作流中加入额外的复核与审批步骤，并配置 agent 使用的应用和环境，把访问范围限定在每项任务所需的记录和操作上。机构数据不会用于训练 OpenAI 的基础模型。

为支持涉及受保护健康信息的、符合 HIPAA 要求的工作流，机构必须使用其与 OpenAI 签署的 Business Associate Agreement 所覆盖的合格服务，并采用必要的安全与保留设置。

## 开始使用 computer-use agent

面向医疗的 computer-use agent 现已在 ChatGPT for Healthcare、ChatGPT for Clinicians 和 OpenAI API 中提供。以下是医疗机构、临床医生和开发者上手的方式。

- **医疗机构：** [联系我们的销售团队](https://openai.com/contact-sales/)，讨论如何在你的临床和行政工作流中使用 AI。现有客户可以请工作区管理员在 ChatGPT Work 和 Codex 中启用 computer use。
- **个体临床医生：** 美国临床医生可以[立即注册免费的 ChatGPT for Clinicians 账户](https://chatgpt.com/plans/clinicians/)，在 ChatGPT Work 和 Codex 中体验 computer use。
- **开发者：** 用 [OpenAI API](https://developers.openai.com/api/docs/quickstart) 构建医疗应用，并查阅我们的 [computer use 指南](https://developers.openai.com/api/docs/guides/tools-computer-use)，构建能在现有软件中工作的 agent。

我们希望这些进展能让医疗团队少花些时间在系统之间搬运信息，多花些时间照护患者。
