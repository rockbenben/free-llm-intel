# Unify 为每项任务匹配最合适的模型，让工程化增长走向统一

通过把每个 OpenAI 模型匹配到最适合的任务，Unify 规模化精准触达，并多带来 30% 的销售管道。

[Unify⁠（在新窗口中打开）](http://unifygtm.com/) 是一套“行动系统”，旨在以合适的信息、在合适的时间、规模化地触达合适的客户。平台通过智能获客线索挖掘、超个性化信息和可复制的全天候工作流来实现这一点——把行之有效的环节自动化。

Unify 从地基起就用 AI 构建其系统。团队认为销售增长应被当作一个工程问题：可观测、可度量、可快速迭代。Unify 使用 OpenAI o3、GPT‑4.1 和 Computer-Using Agent（CUA），配合持续的模型基准测试，设计出一套系统，帮助市场进入（GTM）团队以极少的人工工作创造数百万美元的管道——如今这套系统贡献了它自己 30% 的管道。

“人与人之间的互动有一些真正特别的东西，这不会消失，”联合创始人 Connor Heggie 说。“我们用 AI 自动化琐碎工作，让团队有余力把时间花在最要紧的地方：与客户交谈、做出及时的决策。”

## 把市场进入变成一个搜索问题，并用 AI 解决

GTM 团队的工作，是找到那些存在问题、而你的产品能独特解决的公司和人，并出现在他们面前。许多人把这看作获客问题，Unify 则把它看作对海量非结构化、语义丰富数据的搜索问题。

过去，解决这一问题意味着雇佣庞大的销售团队手动研究潜在客户、翻找网站、从零撰写触达内容。有了 OpenAI 的模型与 Unify 的 agentic 架构，团队如今可以在规模化的同时保持一致性、上下文与速度地执行这场“搜索”。

Unify 的 AI 产品栈包括三个核心组件：

- **观察模型（Observation Model）**：在后台运行，持续研究客户总可达市场（TAM）中的公司。它由 OpenAI o3 驱动，从公开来源中侦测高信号事件（如新招聘、技术栈变动），并用多 agent 工作流浮现战略洞见。
- **研究 agent**：帮助用户回答开放性问题并生成外呼文案，例如标记某公司最近是否扩张到新区域。它用 GPT‑4.1 做规划、CUA 做动态浏览、GPT‑4o 做综合。
- **文案撰写**：由 agentic 研究与 GPT‑4o 驱动，把平台浮现的相关数据转化为超个性化邮件的草稿，细节按每个线索定制。

## 把 OpenAI o3、GPT‑4.1 与 CUA 匹配给合适的任务

Unify 构建平台时，就预期模型在推理、工具使用与交互方面会大幅进化。这一远见让他们得以提前投入——在支撑观察模型的模型发布之前就把其范围界定好。

OpenAI o3 可用时，Unify 已经构建并测试好了评估，以确定它能否对复杂的上游决策进行推理。一经验证，团队就立即把 o3 部署进工作流，改善了信号侦测，并让整个系统更加 agentic。

类似地，GPT‑4.1 和 CUA 解锁了前所未有的研究与规划任务，并被直接集成进产品的决策层。

## 评估每个模型的推理质量

Unify 不只以准确性或延迟评估模型，而是为真实 GTM 场景中的推理质量构建了结构化测试。这些评估在信号分类、指令规划等上游阶段至关重要——模型输出在那里决定后续的一切。

“搜索问题最难的部分之一是识别正确的信号，”Unify 软件工程师 Kunal Rai 指出。“早期步骤中推理质量极为关键，我们需要接近人类水平推理、理解细微差别、并能适配多样用例的模型。”

团队将 OpenAI o3 与其他开源模型对比评估。o3 凭借两到三轮的推理脱颖而出，为 Unify 观察模型的早期阶段逻辑提供了动力。GPT‑4o 由于其结构化输出与流畅度，成为综合与回复分类的默认选择。CUA 则解锁了静态抓取无法支撑的复杂研究任务，包括界面层面的操作，如浏览评价站或信任与安全页面。

## 围绕产品契合重塑市场进入

Unify 的使命是帮助最好的产品胜出。通过围绕 AI agent 与任务专属模型设计平台，Unify 把增长变成一门科学——浮现高意图信号，驱动及时、贴题的触达。

如今，这套系统支撑着 Unify 自身 30% 的销售管道，并每年为客户支撑数亿美元量级的管道。随着模型能力持续演进，Unify 计划把更多增长工作流推进到 agentic、全天候的系统，让 GTM 团队拥有更全面的视野、更大的杠杆和更多时间投入有意义的对话。

“我们正在创造一个由产品质量和客户契合度决定成败的世界，”Heggie 说。“我们构建这套系统，是为了让人能专注于最重要的事。而 OpenAI 的模型让这成为可能。”
