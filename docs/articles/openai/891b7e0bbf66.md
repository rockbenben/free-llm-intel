# 用 Decisions API 构建响应更快的应用

为任何应用提供快速、聚焦、低成本的决策。

应用和 agent 在一整套工作流中会做出许多小决策：如何对输入做分类、把请求路由到哪里、下一步该执行哪个动作。单个来看它们很简单。一旦上了规模，它们的延迟和成本就会累积起来。

今天，我们宣布 Decisions API 正式全面可用。Decisions API 基于 [GPT‑6 Luna](https://openai.com/index/introducing-gpt-6-sol-and-luna/) 构建，它把 Luna 的智能聚焦在答案有界的问题上，帮助应用和 agent 针对文本、图像和结构化输入做出接近实时的决策，比通过 Responses API 使用 GPT‑6 Luna 快至多 10 倍。

自公开测试版以来，我们新增了原生的 GPT‑Live 集成、用于复用上下文的 prompt caching，以及在美国和 EU 的推理驻留。开发者还可以传入原生 JSON 输入、在问题指令里包含图像，并在单次请求中提出最多 400 个问题，是此前上限的两倍。我们也持续改进延迟，包括在亚洲若干区域补充了算力容量。

## 选择你的应用所需要的决策类型

使用 Decisions API 很简单：开发者先定义一个问题以及它允许的答案，再以文本、图像或原生 JSON 的形式提供上下文。API 会返回三种受支持的答复类型之一——一个概率、一个选择，或一个评分——应用可以据此决定接下来做什么。答复类型的多样性让 Decisions 能够适用于非常广泛的各种用例。

Decisions API 支持三种答复类型：

| 类型 | 用它来 | 主要结果 |
| --- | --- | --- |
| predicate | 估计某个条件为真的概率，例如产品是否存在可见损伤。 | probability：对该条件为真的 0 到 1 的估计值。 |
| choice | 从你预先定义的选项中选一个，例如 agent 应该继续、重试，还是请求澄清。 | choice：你所提供的取值之一。响应中还会包含概率和置信度。 |
| score | 依照评分标准里有序的等级给一个输入评级，例如损伤的严重程度。 | score：各等级索引按概率加权后的平均值。 |

## 用 Decisions API 和 GPT‑Live 构建实时语音体验

借助 [GPT‑Live](https://openai.com/index/introducing-gpt-live-1-in-the-api/)，你可以为语音应用带来自然、富有表现力的对话，并由顺畅的打断处理让对话保持连贯。Decisions API 如今已[原生集成 GPT‑Live](https://developers.openai.com/api/docs/guides/decisions-voice)，帮助应用在实时对话过程中做出快速、聚焦的决策。客服 agent 可以决定是提出一个澄清问题、路由一个请求，还是升级一个问题。avatar 可以在用户对它说话时调整自己的面部表情，并根据用户说的话以眨眼或微笑回应，营造更有互动感的体验。

下面的示例用 transcript 更新来选择 avatar 的表情。把这段配置添加到已有 GPT‑Live 会话的 `session.triggers` 中。

#### JSON

```
1{2  "type": "decisions",3  "event_type": "session.input_transcript.delta",4  "decisions": {5    "questions": [{6      "type": "choice",7      "name": "reaction",8      "instructions": "Choose an appropriate reaction for the avatar based on the user's latest message.",9      "choices": [10        { "value": "neutral" },11        { "value": "happy" },12        { "value": "sad" },13        { "value": "concerned" }14      ]15    }]16  }17}
```

Live 会发出一个 `decision.event`；应用读取选中的 `reaction`，并据此让角色做出相应动画。[了解更多关于把语音接入 Decisions API 的内容。](https://developers.openai.com/api/docs/guides/decisions-voice)

## 构建并评估你的第一个决策

Decisions API 今天起通过专用的 Decisions endpoint 全面可用，使用的模型是 GPT‑6 Luna。当前的费率与缓存详情请参阅[定价与可用性指南](https://developers.openai.com/api/docs/guides/decisions#pricing-and-availability)。

先从你的应用经常反复做出的某一个决策开始。定义这个问题、可能的答案，以及区分这些答案所需的上下文。用能反映真实使用情况的示例来测试它——在 [Decisions Playground](https://platform.openai.com/decisions) 里用你自己的文本或图像，或者按照[开发者指南](https://developers.openai.com/api/docs/guides/decisions)发出你的第一个请求。

Decisions API 的费用是每 100 万输入 token $0.10。缓存输入为每 100 万 token $0.01。关于 30 分钟和 12 小时的缓存写入，[请阅读我们的定价指南。](https://developers.openai.com/api/docs/pricing?utm_source=chatgpt.com)你只需为输入 token 付费：不收输出 token 的费用。区域化处理在美国和 EU 可用，[Zero Data Retention](https://developers.openai.com/api/docs/guides/your-data)面向符合条件的客户提供。详情请查看[定价与缓存](https://developers.openai.com/api/docs/guides/decisions#pricing-and-availability)和[数据控制](https://developers.openai.com/api/docs/guides/your-data)。
