# OpenAI o1 与面向开发者的新工具

介绍 OpenAI o1、Realtime API 改进、一种新的微调方法等面向开发者的更新。

今天，我们为使用 AI 构建产品的开发者带来更多能力更强的模型、新的定制工具，以及提升性能、灵活性与成本效益的升级。包括：

- [**API 中的 OpenAI o1**⁠（在新窗口中打开）](https://platform.openai.com/docs/models#o1)，支持 function calling、developer messages、Structured Outputs 和视觉能力。
- [**Realtime API 更新**⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/realtime)，包括简单的 WebRTC 集成、GPT‑4o 音频降价 60%，以及以先前音频价格十分之一支持 GPT‑4o mini。
- [**偏好微调（Preference Fine-Tuning）**⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/fine-tuning#preference)，一种新的模型定制技术，让基于用户与开发者偏好的模型定制更容易。
- [**全新的 Go 和 Java SDK**⁠（在新窗口中打开）](https://platform.openai.com/docs/libraries) beta 上线。

## API 中的 OpenAI o1

[**OpenAI o1**⁠](https://openai.com/o1/) 是我们以高级准确性应对复杂多步任务的推理模型，现正向 API 中 [usage tier 5⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/rate-limits/usage-tiers#usage-tiers) 的开发者推送。o1 是 OpenAI [o1‑preview⁠](https://openai.com/index/introducing-openai-o1-preview/) 的继任者；开发者已用 o1‑preview 构建了 agentic 应用，用于简化客户支持、优化供应链决策、预测复杂财务趋势。

o1 已具备生产可用性，支持真实场景的关键特性包括：

- [**Function calling**⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/function-calling)：将 o1 与外部数据和 API 无缝连接。
- [**Structured Outputs**⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/structured-outputs)：生成可靠遵循自定义 JSON Schema 的回答。
- **Developer messages**：为模型指定要遵循的指令或上下文，如定义语气、风格及其他行为引导。
- **视觉能力**：对图像进行推理，在科学、制造或编程等视觉输入重要的领域解锁更多应用。
- **更低延迟**：对同一请求，o1 平均比 o1‑preview 少用 60% 的推理 token。
- 新的 `**reasoning_effort**` API 参数，让你控制模型在作答前"思考"多久。

我们今天发布的 o1 快照 `o1‑2024‑12‑17`，是对两周前我们在 ChatGPT 中发布模型的新后训练版本。它基于反馈改进了模型行为的若干方面，同时保持我们在 [o1 System Card⁠](https://openai.com/index/openai-o1-system-card/) 中评估的前沿能力。我们很快也会把 ChatGPT 中的 o1 更新到此版本。下文分享的评估反映的就是这个新快照的表现，确保开发者拿到的是该版本的最新基准。

## Realtime API 的改进

[Realtime API⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/realtime)让开发者构建低延迟、自然的对话体验。它非常适合语音助手、实时翻译工具、虚拟导师、交互式客服系统，甚至你自己的虚拟[圣诞老人⁠（在新窗口中打开）](https://x.com/jillian_khoo/status/1867275291510383049)。今天我们发布的改动回应了开发者最常见的几个诉求：直接的 WebRTC 集成、降价，以及对响应更多的控制。

###### WebRTC 支持

我们为 Realtime API 引入 [WebRTC⁠（在新窗口中打开）](https://webrtc.org/) 支持。WebRTC 是一项开放标准，让跨平台构建和扩展实时语音产品更容易——无论是浏览器应用、移动客户端、IoT 设备，还是服务器到服务器的直连场景。

我们的 WebRTC 集成专为现实条件下的顺畅、灵敏交互而设计，即便网络质量波动也能应对。它负责音频编解码、流式传输、噪声抑制和拥塞控制。

有了 WebRTC，现在只需几行 JavaScript 就能加入 Realtime 能力：

#### JavaScript


关于我们的 WebRTC 集成，更多信息见 [API 文档⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/realtime-webrtc)。

## 成本更低的全新 GPT-4o 与 GPT-4o mini realtime 快照

我们在 Realtime API beta 中发布 `gpt-4o-realtime-preview-2024-12-17`，带来更好的音质、更可靠的输入（尤其是口述数字），以及更低的成本。得益于效率改进，我们将音频 token 价格下调 60%：每百万输入 token 40 美元、每百万输出 token 80 美元。缓存音频输入成本下降 87.5%，为每百万输入 token 2.50 美元。

我们还将 GPT‑4o mini 以 `gpt-4o-mini-realtime-preview-2024-12-17` 带入 Realtime API beta。GPT‑4o mini 是我们最具成本效益的小模型，为 Realtime API 带来与 GPT‑4o 同样丰富的语音体验。GPT‑4o mini 音频价格为每百万输入 token 10 美元、每百万输出 token 20 美元；文本 token 为每百万输入 0.60 美元、每百万输出 2.40 美元；缓存音频和文本均为每百万 token 0.30 美元。

这些快照可在 [Realtime API⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/realtime) 使用，也可在 [Chat Completions API⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/text-generation) 中以 `gpt-4o-audio-preview-2024-12-17` 和 `gpt-4o-mini-audio-preview-2024-12-17` 使用。

## 对响应更强的控制

我们为 Realtime API 上线以下功能，让打造卓越语音体验更容易：

- [**并发带外响应（Concurrent out-of-band responses）**⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/realtime-model-capabilities#create-responses-outside-the-default-conversation)：让内容审核或分类等后台任务在不打断用户语音交互的情况下运行。
- [**自定义输入上下文（Custom input context）**⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/realtime-model-capabilities#create-a-custom-context-for-responses)：指定将哪些对话条目作为模型输入。例如，仅对用户最后一句话做审核检查，或复用此前的回答而不永久改变会话状态。
- [**响应时机控制（Controlled response timing）**⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/realtime-model-capabilities#keep-vad-but-disable-automatic-responses)：使用服务端语音活动检测（VAD）但不自动触发响应。例如先收集账户详情等必要数据、加入模型上下文，再手动发起语音回复，对时机与准确性有更多控制。
- [**最大会话时长**⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/realtime-model-capabilities#session-lifecycle-events)从 15 分钟提升到 30 分钟。

## 偏好微调（Preference Fine-Tuning）

微调 API 现已支持[偏好微调⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/fine-tuning#preference)，让基于用户与开发者偏好的模型定制变得简单。该方法使用[直接偏好优化（DPO）⁠（在新窗口中打开）](https://arxiv.org/abs/2305.18290)比较成对的模型回答，教会模型区分被偏好与不被偏好的输出。通过从成对比较而非固定目标中学习，偏好微调在语气、风格和创造力重要的主观任务上尤其有效。

偏好微调与监督式微调（Supervised Fine-Tuning）存在一些关键差异，如下表所示。

|  | **监督式微调（SFT）** | **偏好微调（PFT）** |
| --- | --- | --- |
| **目标** | 通过复刻带标签的输出，促使模型生成正确输出 | 通过强化被偏好的回答、降低不被偏好回答的概率，优化模型偏向期望行为 |
| **训练数据** | 精确的输入-输出对 | 被偏好与不被偏好的模型输出对，来源可以是人工标注、A/B 测试或合成数据生成 |
| **适用场景** | 理想输出易于准备、且要求严格正确性的任务，如定制代码格式 | 在"更好"回答见仁见智的任务上有效，如创意写作或摘要。 |

我们与可信合作伙伴一起开始测试偏好微调，迄今已见到可观的结果。例如，[Rogo AI⁠（在新窗口中打开）](https://rogo.ai/) 正在为金融分析师构建一款把复杂查询拆解为子查询的 AI 助手。使用其专家构建的基准 Rogo-Golden，他们发现：监督式微调在处理分布外查询扩展时遇到困难——比如对"X 公司增长有多快"这类查询会漏掉 ARR 等指标——而偏好微调解决了这些问题，把准确率从基座模型的 75% 提升到 80% 以上。

偏好微调今日面向 `gpt-4o-2024-08-06` 推出，并很快支持 `gpt-4o-mini-2024-07-18`。每个训练 token 的价格与监督式微调相同，对我们最新模型的支持将于明年初推出。更多信息见 API 文档中的[微调指南⁠（在新窗口中打开）](https://platform.openai.com/docs/guides/fine-tuning)。

## Go 和 Java SDK beta

最后，我们推出两款新的官方 SDK：[Go⁠（在新窗口中打开）](https://github.com/openai/openai-go?tab=readme-ov-file#openai-go-api-library) 和 [Java⁠（在新窗口中打开）](https://github.com/openai/openai-java?tab=readme-ov-file#openai-java-api-library)（beta），与[现有的官方 Python、Node.js 和 .NET 库⁠（在新窗口中打开）](https://platform.openai.com/docs/libraries) 并列。我们的目标是：无论你选择什么编程语言，OpenAI API 都好用。

Go 是一种静态类型语言，特别适合处理并发、构建可伸缩的 API 与后端系统。OpenAI Go SDK 让你在 Go 代码中轻松调用 OpenAI 模型。
