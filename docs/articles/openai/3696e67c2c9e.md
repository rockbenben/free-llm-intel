# Patch the Planet：Daybreak 支持开源维护者的计划

我们推出 Patch the Planet——一个与 Trail of Bits 共建的 [Daybreak⁠](https://openai.com/daybreak/) 计划，帮助维护者强化全世界赖以运转的关键开源软件。我们把使用最强网络安全模型、由 AI 辅助的安全研究与专业人工审核结合起来——不仅发现漏洞，还帮助修复漏洞。

AI 正在加速漏洞发现，但仅仅发现并不能保护用户。许多维护者已经被要求在同样的有限时间与资源下，更快甄别越来越多的报告。Patch the Planet 的设计目标是减轻这一负担，而非加重它：安全工程师在发现到达维护者之前先行审核，与项目合作开发补丁和测试，并构建可复用的工作流，帮助团队在首批修复落地之后持续改进安全。

作为初始冲刺，[Trail of Bits 已把其整个安全研究组织投入这项工作⁠（在新窗口中打开）](https://blog.trailofbits.com/2026-06-22/introducing-patch-the-planet)。他们与维护者直接合作，调查并确认漏洞、开发和测试补丁，并协调漏洞披露。

此外，我们还将与 HackerOne 和 Calif 合作，借助他们在漏洞分诊、协调披露以及额外针对性漏洞发现方面的能力，把这项工作推向更远。

## Patch the Planet 如何运作

Patch the Planet 下的每次合作都从与维护者协商开始。在每次协作中，安全工程师与维护者共同了解每个项目的需求、偏好，以及额外安全投入在哪里最有用：漏洞确认、补丁开发、CI/CD 改进，或更长期的安全工程。达成一致后，研究人员调查潜在漏洞、确认有意义的问题、开发或完善补丁、支持测试，并通过项目既有渠道协调披露。

首批参与项目包括 cURL、NATS Server、pyca/cryptography、Sigstore、aiohttp、Go 项目、freenginx、Python 和 python.org。这些项目支撑着广泛使用的网络、加密、软件供应链和语言基础设施，它们的安全增强能惠及其下游海量产品与服务。未来几轮还将有更多项目加入。

安全研究人员配备我们的前沿模型以及 [Codex Security⁠（在新窗口中打开）](https://developers.openai.com/codex/security)，用于支持分析、补丁开发、测试和文档撰写。参与项目可获得 ChatGPT Pro 使用权、有条件的 Codex Security 使用权，用于核心开源开发、维护者自动化和发布工作流的 API 额度。Trail of Bits 已开发了 AI 辅助的去重、分诊和补丁工作流，项目可依托这些支持直接运行。

## 一线记录与开发者发现

Trail of Bits 投入了专职安全工程师，在 19 个开源项目中全职使用 Codex 和 GPT‑5.5‑Cyber 工作，已经识别出数百个安全问题、合并了数十个补丁，还有更多正处于协调披露流程中。

初始冲刺还产出了可复用的安全基础设施：模糊测试（fuzzing）挂具、历史 CVE 分析管线、差分测试系统、威胁模型、扩充的测试套件，以及用于去重、假阳性过滤、严重性修正和补丁生成的工作流。部分项目细节将随测试、修复和协调披露的推进稍后公开。几个早期例子展示了团队能够构建和发现了什么：

**不到一天建成的模糊测试实验室。**Trail of Bits 工程师用 GPT‑5.5‑Cyber 反复执行 Codex /goal，构建了覆盖数十个入口点、多平台变体构建和新型测试种子的完整模糊测试实验室。工程师设定目标并打磨提示词；系统随后利用覆盖率反馈不断扩展到新界面、针对边界用例、过滤弱或无效候选。

Trail of Bits 工程师发现，在有限指导下，GPT‑5.5‑Cyber 对向哪里扩展覆盖率、探测哪些构建和入口点、哪些候选太弱不值得追，都能做出有用的判断。整套环境搭建不到一天完成。Trail of Bits 估算，若手工搭建同样的实验室，通常至少需要数周。

**查找已知漏洞变体的可复用管线。**团队构建了端到端系统：摄取历史 CVE、提取相关漏洞模式、在目标代码库中搜索同类缺陷，并把候选发现送入专门的评判 agent。管线对结果去重、过滤可能的假阳性，并把最强证据交给安全工程师人工确认。

这把多年公开的漏洞历史转化为可在各项目间复用的可重复搜索策略。Trail of Bits 发现模型尤其擅长这类变体分析，在受审代码库中额外挖出了许多问题。

**数天完成过去需数周或数月的差分测试。**同一协议的不同实现，面对相同输入通常应当行为一致；一旦分歧，其中一方可能含 bug。规模化应用这一思路向来困难，因为工程师必须编写定制 shim 和胶水代码，把每个实现接入同一测试挂具。

Codex 生成并迭代这些代码，让多个实现可以相互模糊测试、研究其行为差异。工作流过滤掉大量弱或无效结果，产出了信号相当高的一批候选，供专家评审。团队在数天内达到这一结果，压缩了过去耗时数周甚至数月的工作。Trail of Bits 正在继续扩展和完善这些测试，之后再发布项目细节。

**用规格承诺的行为来检验软件。**团队用 Codex 基于项目规格与 RFC 开发威胁模型、攻击分类、不变量测试和基于属性的测试。这些方法揭示了预期行为与实际行为之间值得注意的差异，同时让项目获得更广的测试覆盖、更强的文档，以及 CI/CD 与软件供应链工具的改进。

**每一项发现在送达维护者前都经过安全工程师审核。**Trail of Bits 工程师在提交给维护者之前对每个安全问题进行人工审核，这一步的附加价值怎么强调都不为过。虽然前沿 AI 模型非常擅长发现并修补漏洞，它们也会产出大量假阳性，加剧维护者本已不堪重负的积压。Patch the Planet 的解法是：由 Trail of Bits 专职研究人员复现证据、对照项目文档与威胁模型核查发现、去除重复、重新评估严重性，并为已确认的漏洞排定修复优先级。他们还按照维护者的偏好开发并提交补丁。部署哪些补丁、如何披露，主导权始终在维护者手中。

## OpenAI Daybreak 已经发现了什么

Patch the Planet 建立在更广泛的 Daybreak 工作之上——这些工作展示了前沿模型如何帮助防守方在广泛使用的软件中发现、确认并修复严重漏洞。

这里分享几个早期亮点；对于披露仍在进行中的内容，我们隐去利用手法细节和项目特定信息。随着修复落地、协调披露完成，我们计划发布更深入的技术报告，逐项讲解具体发现、研究方法、验证工作流，以及其他防守方可借鉴的经验。

我们的发现遍及软件栈的每一层，还有更多处于披露流程中。

### 操作系统

- **Linux 内核：**GPT‑5.5‑Cyber 在超过 3000 万行代码中识别出与安全相关的组件，标记潜在安全问题，随后动态验证它们，生成了 8 个内核指针信息泄露 PoC（概念验证）和 24 个本地提权利用。需要说明：被识别的问题有数百个，这里只是自动生成 PoC 的那部分。
- **OpenBSD：**我们的模型在 OpenBSD 内核 System V 信号量实现中发现了一个存在 23 年的[释放后使用⁠（在新窗口中打开）](https://github.com/openbsd/src/commit/1957873d2063db11dab780eca75b5e629d1e838d)漏洞。OpenAI 研究人员复现了该问题，并确认它可让无特权本地用户提权至 root。
- **FreeBSD：**Calif 的安全研究人员用 Codex 在 [FreeBSD⁠（在新窗口中打开）](https://www.freebsd.org/security/advisories/FreeBSD-SA-26:19.file.asc) 中发现并验证了[数个⁠（在新窗口中打开）](https://www.freebsd.org/security/advisories/FreeBSD-SA-26:18.setcred.asc)[本地提权漏洞⁠（在新窗口中打开）](https://www.freebsd.org/security/advisories/FreeBSD-SA-26:21.ptrace.asc)的利用 PoC。在更大范围的 FreeBSD 战役中，OpenAI 研究人员确认了 34 个漏洞，产出 7 个本地提权 PoC。

### 网络

- **dnsmasq**：Codex Security 独立识别出与后来在 `2.92rel2` 中修复的六个 dnsmasq CVE 里四个相对应的脆弱模式：[CVE-2026-4890⁠（在新窗口中打开）](https://www.cve.org/CVERecord?id=CVE-2026-4890)、[CVE-2026-4891⁠（在新窗口中打开）](https://www.cve.org/CVERecord?id=CVE-2026-4891)、[CVE-2026-4892⁠（在新窗口中打开）](https://www.cve.org/CVERecord?id=CVE-2026-4892) 和 [CVE-2026-5172⁠（在新窗口中打开）](https://www.cve.org/CVERecord?id=CVE-2026-5172)。
- **HTTP/2 Bomb**：Calif 用 Codex 识别出 "[HTTP/2 Bomb⁠（在新窗口中打开）](https://blog.calif.io/p/codex-discovered-a-hidden-http2-bomb)"——一种影响主流 HTTP/2 实现（包括 NGINX、Apache、IIS 和 Pingora）的拒绝服务技术。Calif 的分析表明，超过 88 万个面向互联网的网站运行着启用 HTTP/2 的受影响服务器软件。

### 浏览器

- **Chrome**：OpenAI 研究人员在 Chrome 的 V8 JavaScript 引擎中发现并上报了 5 个可被利用的漏洞，其中 3 个在引入后数天内即被发现并修复。
- **Safari**：在大约一周针对 WebKit 的集中工作中，发现并上报了超过 10 个可被利用的 Safari 漏洞。
- **Firefox**：OpenAI Preparedness 团队在[安全评估⁠（在新窗口中打开）](https://deploymentsafety.openai.com/gpt-5-5/vulnlmp)期间用 GPT‑5.5 发现了一个 WebAssembly 漏洞（[CVE-2026-8390⁠（在新窗口中打开）](https://nvd.nist.gov/vuln/detail/CVE-2026-8390)），Mozilla 在 Pwn2Own 柏林赛前两天完成修补，导致六支已报名的 Firefox 参赛队中的五支退赛。比赛中没有 Firefox 利用被成功演示。

## 共享的基础设施，共同的防御

开源软件是共享的基础设施，保护它也应是一项共同的事业。AI 正在改变漏洞发现的节奏，而眼下的工作，是确保红利抵达最需要的维护者和用户。

Patch the Planet 的设计，是把完整的防御闭环——发现、验证、严重性评审、披露、补丁开发、测试和部署——交到维护者手中。前沿模型可以让闭环的某些环节更快，但目标是让负责共享基础设施的人拥有更好的工具和更多的能力，同时保留他们对变更如何落地的主导权。

这第一次冲刺展示了维护者、安全工程师与 AI 辅助工作流持续协作能产出什么：即刻的修复、更强的项目基础设施，以及能随时间持续改进开源软件的可复用安全工作。

这只是开始。随着更多修复落地、协调披露完成，我们计划发布更深入的技术报告，涵盖精选发现、用于发现和验证它们的方法，以及防守方可借鉴、用于保护人人依赖之软件的工作流。如果你是维护者，可以在[这里⁠（在新窗口中打开）](https://trailofbits.com/patch-the-planet)申请加入 Patch the Planet。
