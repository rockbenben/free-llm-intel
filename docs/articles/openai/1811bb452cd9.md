# 3 月 20 日 ChatGPT 故障：到底发生了什么

关于我们发现的问题、采取的措施以及该 bug 技术细节的更新。

本周早些时候，由于一个开源库中的 bug，部分用户得以看到另一位在线用户聊天记录标题，我们因此将 ChatGPT 下线。如果两个用户在相近时间都活跃，新建对话的第一条消息也有可能出现在其他人的聊天记录中。

该 bug 现已修复。我们恢复了 ChatGPT 服务，随后也恢复了聊天记录功能，仅有几个小时的记录未能保留。如我们此前承诺，下面公布这一问题的更多[技术细节⁠](https://openai.com/index/march-20-chatgpt-outage/#technical-details)。

经更深入调查，我们还发现同一 bug 可能在某个特定九小时窗口内，导致 1.2% 在该窗口内**活跃的** ChatGPT Plus 订阅用户的支付相关信息被意外暴露。在周一我们下线 ChatGPT 之前的几个小时里，部分用户有可能看到另一位**活跃**用户的姓名、邮箱地址、账单地址、信用卡类型、卡号后四位（仅此四位）以及信用卡有效期。任何时间都未泄露完整信用卡号。

我们相信实际导致数据被他用户看到的人数极低。要接触到这些信息，ChatGPT Plus 订阅用户必须恰好做了以下操作之一：

- 打开 3 月 20 日周一太平洋时间凌晨 1 点至上午 10 点之间发送的订阅确认邮件。由于该 bug，该窗口内生成的部分订阅确认邮件被发送给了错误的用户。这些邮件包含另一位用户的信用卡类型和卡号后四位，但不包含完整卡号。在 3 月 20 日之前也可能有极少数订阅确认邮件发错对象，但我们未确认存在此类情况。
- 在 3 月 20 日周一太平洋时间凌晨 1 点至上午 10 点之间，在 ChatGPT 中点击“我的账户”（My account），再点击“管理我的订阅”（Manage my subscription）。在该窗口内，另一位**活跃** ChatGPT Plus 用户的姓名、邮箱地址、账单地址、信用卡类型和卡号后四位（仅此四位）以及信用卡有效期可能被看到。3 月 20 日之前也可能发生过同样情况，但我们未确认任何实例。

我们已向受影响用户发出通知，告知其支付信息可能已被暴露。我们有信心，用户数据不存在持续风险。

OpenAI 每个人都致力于保护用户隐私、保障其数据安全，这是一份我们极度严肃对待的责任。遗憾的是，本周我们未能兑现这一承诺，也辜负了用户的期待。我们再次向用户和整个 ChatGPT 社区致歉，并将努力重建信任。

## 技术细节

该 bug 位于 Redis 客户端开源库 redis-py 中。发现 bug 后，我们立即联系了 Redis 维护者并提供修复补丁。bug 的工作机制如下：

- 我们用 Redis 在服务端缓存用户信息，避免每个请求都查数据库。
- 我们使用 Redis Cluster 将负载分散到多个 Redis 实例上。
- 我们用 redis-py 库从基于 Asyncio 运行的 Python 服务端连接 Redis。
- 该库在服务端与集群之间维护一个共享连接池，连接在一次请求完成后会被回收用于下一个请求。
- 在使用 Asyncio 时，redis-py 的请求与响应表现为两个队列：调用方把请求推入入向队列，从出向队列弹出响应，然后把连接归还连接池。
- 如果请求在被推入入向队列之后、响应从出向队列弹出之前被取消，就会出现我们的 bug：连接因此被污染，下一个无关请求从队列中取到的响应，可能拿到遗留在连接中的数据。
- 大多数情况下，这会导致不可恢复的服务端错误，用户需要重试其请求。
- 但在某些情况下，被污染的数据恰好与请求方预期的数据类型一致，于是从缓存返回的内容看起来是有效的——哪怕它属于另一个用户。
- 3 月 20 日周一太平洋时间凌晨 1 点，我们无意间上线了一项服务端变更，导致 Redis 请求取消量激增。这使每个连接返回错误数据的概率虽小但非零。

该 bug 仅出现在面向 Redis Cluster 的 Asyncio redis-py 客户端中，现已修复。

## 我们采取的措施

随着调查收尾，支持与告知用户仍是我们的首要任务。

我们采取了以下行动改进系统：

- 对底层 bug 的修复进行了充分测试。
- 增加冗余校验，确保 Redis 缓存返回的数据与请求用户匹配。
- 以程序化方式检查日志，确保所有消息只对正确的用户可见。
- 关联多个数据源，精确识别受影响用户以进行通知。
- 改进日志，以便识别该现象是否发生并完全确认其已停止。
- 提升 Redis 集群的健壮性与规模，降低极端负载下连接出错的概率。

## 未来怎么走

Redis 开源维护者们是非常出色的协作者，迅速处理了该 bug 并发出了补丁。Redis 与其他开源软件一样，在我们的研究工作中扮演着关键角色。其重要性怎样强调都不为过——没有 Redis，我们无法完成 ChatGPT 的规模化。我们致力于持续支持 Redis 社区并作出贡献。
