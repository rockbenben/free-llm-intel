人和 AI 智能体都需要上下文才能把事情做完，但上下文通常散落在各个系统里，从 Slack 到 Google Docs 都有。要把它们找齐、并理解它们如何拼合成一个整体，可能是一件棘手的事。

正因如此，[Stack Overflow](https://stackoverflow.co/) 正在构建一个知识智能平台，把这些来源统一起来，把原始上下文变成经过验证的知识，让它们在人与智能体工作的任何地方都能被取用。

GPT‑6 Astra 和 GPT‑6 Sol 这类 OpenAI 模型为平台的 AI 提供动力，任务会依据所需的推理程度与成本路由到不同模型。Codex 帮助公司工程师构建这些产品，而一个 ChatGPT plugin 让他们较新的智能体产品 Stack Overflow for Agents 更容易被发现和使用。

> “我们为 Stack Overflow for Agents 做了一个 ChatGPT plugin，注册量一夜之间增至三倍。”

—Alexandra Lato，Stack Overflow 产品副总裁

## 两名工程师用 Codex 在几周内交付一个全新产品

Stack Overflow for Agents 把 Stack 的智能层延伸到智能体身上，它始于一个假设和两名使用 Codex 的工程师。工程师们给 Codex 一个开发环境和一份计划，然后与它一起把产品做了出来。Alex 说，几周之内他们就有了一款完整成型的产品。

“所以它真的让那个团队觉得自己变大了，”Alex 说。“他们能够把一个容器丢给它，然后说：‘这是我们的计划，帮我们把它建起来。’”

## 用 Codex 开发 connector：要几天，而不是几周

Stack Internal 是 Stack Overflow 的企业级产品，需要接入各个组织存放自己知识的所有系统。构建这种能力，比 Stack Overflow for Agents 背后那两名工程师的投入需要更多人的参与，但 Codex 也在加速这部分工作。

Alex 描述了如何用 Codex 为企业产品走出一条短得多的上市路径：三个月，而不是一年。构建 connector 就是一个具体的例子。

> “平均而言，构建一个 connector 要我们 3 到 6 周。有了 Codex，我们能在 4 天之内做出来。”

—Alexandra Lato，Stack Overflow 产品副总裁

最近，团队在一天之内就做出了一个 connector。通过加快 connector 的开发，Codex 帮助 Stack Overflow 把企业产品更快地推向市场。

## 用 ChatGPT plugin 提升智能体创建量与注册量

Stack Overflow for Agents 具备分发条件之后，团队需要一条把它送进人们工作流的途径。它做了一个 ChatGPT plugin，让用户可以在 ChatGPT 里发现并完成该产品的设置，步骤比传统的 Model Context Protocol（MCP）配置更少。

> “一旦有了 plugin，与 ChatGPT 的搭建就成了无摩擦的过程。”

—Alexandra Lato，Stack Overflow 产品副总裁

Alex 说，这个 plugin 让注册量增至三倍，也加速了智能体的创建：“上次我查看的时候，记得已经涨到 10X 了。”

## 用 Decisions API 减少配置工作

Stack Overflow 自己管理模型路由与配置，但 Alex 希望探索使用 Decisions API，来减少其中一部分工作，把更多工程产能投到产品上。

Alex 说：“如果我们能够直接通过 OpenAI 把它自动化，就能省下大量时间和金钱，让我们更专注于真正在构建的产品本身，而不是围着它的那些护栏。”

## 扩展到完整的知识生命周期

Stack Overflow 同时也在扩展它的知识产品，让人们学到的东西能够被分享。迄今为止，它的重点一直是把信息拉进来。现在，Alex 正在闭合这个循环：与开发者或工程之外的同事进行一对一交流时获得的知识，同样能够帮助其他人。

Alex 说：“当我在学习的时候，我怎么确保组织里其余的人也在跟我一起学习？我真的很期待做出一款能够支撑那整个知识生命周期的产品。”
