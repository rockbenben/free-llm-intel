Cloudflare 运营着全球最大的网络之一，为约 20% 的 Web 流量提供代理服务。众多组织依靠这一网络，确保其应用和服务安全、快速、可靠。

Cloudflare 在[漏洞发现与修复](https://www.cloudflare.net/news/news-details/2026/Cloudflare-Partners-with-OpenAI-Daybreak-Models-to-Redefine-Vulnerability-Management-with-AI-Powered-Edge-Defense/default.aspx)服务中，将通过 Daybreak 访问的 OpenAI 模型与其全球网络及威胁背景信息相结合。这项抢先体验版服务由 Cloudflare Managed Defense 提供。这些模型负责调查代码，评估潜在漏洞。Cloudflare 则结合实时流量数据、安全信号和验证结果，确定所发现问题的优先级，并拟定缓解措施和补丁，供客户审核。

Codex 进一步拓展了 OpenAI 在 Cloudflare 整个工程团队中的作用，开发者用它来提高产出、改善代码质量。

> “Daybreak 和 Codex 提供的自动化能力，妙就妙在可以让机器承担繁重琐碎的工作，让人们把判断力用在最重要的工程和安全决策上。”

—Mark Anderson，Cloudflare 营收业务总裁

## 借助 Daybreak 扩展安全分析能力

安全团队每天都要面对源源不断的漏洞信息和告警。手动筛查这些数据耗时耗力，挤占了团队调查和处理关键问题的精力。“传统安全团队掌握着大量有用的数据。他们只是没有足够的人手和时间来处理。”Anderson 说。

Cloudflare 的做法是将源代码中的漏洞与生产环境的实际情况关联起来。受影响的路由是否正在使用？是否有可疑流量访问该路由？现有的安全控制措施是否已经在保护它？这些信号为安全团队提供了更多背景信息，帮助他们决定优先调查哪些问题。

在[漏洞发现与修复](https://blog.cloudflare.com/vulnerability-discovery-remediation/)服务中，Cloudflare 使用通过 Daybreak 访问的 OpenAI 模型，调查客户授权的代码、识别潜在漏洞，并核查支持每项发现的证据。该服务会拟定代码补丁，并在适用时提供自定义 Web 应用防火墙规则，以便在开发者审核修复方案期间降低风险暴露。Cloudflare 会对这些方案进行自动化检查，并由其团队审核后再提供给客户。

对 Cloudflare 客户而言，这意味着从识别漏洞到保护受影响的应用，有了一条清晰的路径。该服务提供用于确定漏洞优先级的证据、降低风险暴露的边缘防护建议，以及可供审核的代码修复方案，而具体实施哪些变更，仍由客户决定。

## 借助 Codex，3 天重建一款产品

应用防护也离不开团队编写和维护的代码。Anderson 表示，Cloudflare 使用 Codex 后，开发者的生产力得到了提升，代码质量有所改善，开发过程中引入的缺陷也更少了。

> “在 Cloudflare，公司三分之一的员工是软件开发者，负责为我们的平台构建服务和功能。他们无一例外都在使用 Codex 提高产出，交付更优质的代码。”

—Mark Anderson，Cloudflare 营收业务总裁

Anderson 讲述了团队最近完成的一项重建工作，这项工作此前曾被推迟。“我们一直推迟开发，因为没有足够的人手。”他说。随着 Codex 大幅提升开发者的生产力，问题从“我们有能力接下这个项目吗？”变成了“为什么不试试呢？”

Anderson 估计，这项工作原本需要数月时间分阶段推进，而且“可能需要十倍的开发人员”。借助 Codex，Cloudflare 一支由四名开发者组成的团队承担了这项开发工作。“我们三天就完成了开发，上线并进行了测试，Token 费用花了 1,100 美元。”他说。

## 结合 AI 与人类判断力，构建网络防御

在 Anderson 看来，让 AI 融入日常工程工作，意味着“重塑内部流程，在技术开发中充分考虑机器的作用，不把它当作独立的环节，而是将其融入整个开发过程”。

Cloudflare 的抢先体验版安全服务将代码调查、生产环境中的证据以及供客户审核的行动建议相结合，让这一理念落地。其目标是为安全团队提供所需信息，帮助他们确定应优先处理哪些漏洞，以及如何保护和修复受影响的应用，同时确保客户保有对变更的控制权。
