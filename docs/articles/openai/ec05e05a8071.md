# API 中的提示词缓存

对模型近期已见过的输入自动提供折扣

许多开发者在构建 AI 应用时，会在多次 API 调用中重复使用同样的上下文，例如对一个代码库反复做修改，或与聊天机器人进行长程多轮对话。今天，我们推出 Prompt Caching（提示词缓存），帮助开发者降低成本与延迟。通过复用近期已见过的输入 token，开发者可获得 50% 的折扣和更快的提示词处理速度。

## 可用性与定价

从今天起，Prompt Caching 将自动应用于 GPT-4o、GPT-4o mini、o1-preview 和 o1-mini 的最新版本，以及这些模型的微调版本。缓存命中的提示词相比未缓存的提示词享有折扣。

## 监控缓存使用

对受支持模型的 API 调用，超过 1,024 个 token 的提示词将自动受益于 Prompt Caching。API 会缓存此前已计算过的提示词最长前缀，从 1,024 token 起，以 128 token 为增量增长。如果你复用的提示词有共同前缀，我们会自动应用 Prompt Caching 折扣，无需你对 API 集成做任何改动。

使用 Prompt Caching 的请求，会在 API 响应的 `usage` 字段中带有 `cached_tokens` 值：

#### JavaScript

```
1usage: {2  total_tokens: 2306,3  prompt_tokens: 2006,4  completion_tokens: 300,5  6  prompt_tokens_details: {7    cached_tokens: 1920,8    audio_tokens: 0,9  },10  completion_tokens_details: {11    reasoning_tokens: 0,12    audio_tokens: 0,13  }14}
```

缓存在闲置 5–10 分钟后通常会被清除，且最迟在缓存最后一次使用一小时内移除。与其他 API 服务一样，Prompt Caching 遵守我们的[企业隐私承诺](https://openai.com/enterprise-privacy/)。不同组织之间的提示词缓存互不共享。

Prompt Caching 是开发者在生产环境扩展应用、平衡性能、成本与延迟的众多工具之一。更多信息请查阅 [Prompt Caching 文档](https://platform.openai.com/docs/guides/prompt-caching)。
