# 训练大型神经网络的技巧

大型神经网络是近期许多 AI 进展的核心，但训练它们是一项艰巨的工程与研究挑战：需要协调一个 GPU 集群来执行一次同步计算。

随着集群和模型规模的增长，机器学习实践者发展出越来越多的技术，把模型训练并行到许多 GPU 上。乍看之下，理解这些并行技术似乎令人生畏，但只要对计算结构做少数几个假设，这些技术就会清晰许多——到了那一步，你不过是在像网络交换机搬运数据包一样，把不透明的比特从 A 搬到 B。

## 无并行

训练神经网络是一个迭代过程。每次迭代中，我们沿模型的[各层](https://developer.nvidia.com/blog/deep-learning-nutshell-core-concepts/#layer)做一次前向传播，为一批数据中的每个训练样本计算输出。然后另一次传播沿各层[反向](https://youtu.be/Ilg3gGewQ5U)进行：通过计算关于每个参数的[梯度](https://youtu.be/IHZwWFHWa-w)，传播每个参数对最终输出的影响程度。整批的平均梯度、参数以及每参数的优化状态，会被传给一个优化算法——例如 [Adam](https://arxiv.org/abs/1412.6980)——计算出下一次迭代的参数（它们在数据上应略有改进）和新的每参数优化状态。随着训练在一批批数据上迭代，模型不断进化，输出越来越准确。

各种并行技术从不同维度切分这一训练过程，包括：

- 数据并行（Data parallelism）——在不同 GPU 上运行 batch 的不同子集；
- 流水线并行（Pipeline parallelism）——在不同 GPU 上运行模型的不同层；
- 张量并行（Tensor parallelism）——把单个运算（如矩阵乘法）的数学拆分到多个 GPU 上；
- 专家混合（Mixture-of-Experts）——每个样本只由每层的一小部分来处理。

（本文中我们假设你用 GPU 训练神经网络，但同样的思想适用于任何[神经网络加速器](https://www.synopsys.com/ai/what-is-an-ai-accelerator.html)。）

## 数据并行

*数据并行*训练指把相同参数复制到多个 GPU（常称为“worker”），并给每个 GPU 分配不同的样本同时处理。仅有数据并行仍要求模型能装进单张 GPU 的显存，但它让你用“存储多份参数副本”为代价，利用许多 GPU 的算力。话虽如此，也有策略能增加 GPU 的有效可用内存，例如在使用间隙把参数临时卸载到 CPU 内存。

每个数据并行 worker 更新自己的参数副本时，需要彼此协调以确保各 worker 的参数保持接近。最简单的做法是在 worker 之间引入阻塞式通信：(1) 每个 worker 独立计算梯度；(2) [跨 worker 对梯度取平均](https://tech.preferred.jp/en/blog/technologies-behind-distributed-deep-learning-allreduce/)；(3) 每个 worker 独立计算出一份相同的新参数。第 (2) 步是一个阻塞式平均，需要传输大量数据（与 worker 数量乘以参数规模成正比），可能拖累训练吞吐。人们提出过各种[异步同步方案](https://arxiv.org/abs/1106.5730)来消除这一开销，但会损害学习效率；实践中大家一般坚持同步方案。

## 流水线并行

*流水线并行*训练把模型按顺序分块切给各 GPU。每张 GPU 只持有一部分参数，因而同一模型每 GPU 的内存占用成比例降低。

把大模型按连续层切块很直观。但层的输入输出之间存在顺序依赖，朴素实现会造成大量空闲时间——worker 要等待上一台机器的输出作为自己的输入。这些等待时段被称为“气泡”（bubbles），浪费了本可由空闲机器完成的计算。

我们可以复用数据并行的思想来降低气泡成本：让每个 worker 一次只处理数据的一部分，从而巧妙地把新计算与等待时间重叠。核心思路是把一个 batch 拆成多个 microbatch；每个 microbatch 的处理时间成比例更短，worker 处理完一个便立即开始下一个，从而加快流水线运转。microbatch 足够多时，worker 大部分时间都能保持忙碌，仅在步骤的首尾留下最小气泡。梯度在 microbatch 间取平均，且只有全部 microbatch 完成后才更新参数。

模型被切分到的 worker 数量通常称为*流水线深度（pipeline depth）*。

前向传播时，worker 只需把自己那层块的输出（称为激活值）发给下一个 worker；反向传播时，只需把这些激活的梯度发给上一个 worker。如何调度这些传播、如何在 microbatch 之间聚合梯度，存在很大的设计空间。[GPipe](https://arxiv.org/abs/1811.06965) 让每个 worker 依次完成前向和反向传播，最后在末尾同步聚合多个 microbatch 的梯度。[PipeDream](https://cs.stanford.edu/~matei/papers/2019/sosp_pipedream.pdf) 则调度每个 worker 交替执行前向与反向传播。

## 张量并行

流水线并行是按层把模型“竖切”。也可以把一层内的某些运算“横切”，通常称为*张量并行*训练。对许多现代模型（如 [Transformer](https://jalammar.github.io/illustrated-transformer/)），计算瓶颈是激活 batch 矩阵与大权重矩阵的乘法。[矩阵乘法](https://en.wikipedia.org/wiki/Matrix_multiplication)可以看作行与列之间的点积；可以在不同 GPU 上计算相互独立的点积，也可以在不同 GPU 上计算每个点积的一部分再求和。两种策略都可以把权重矩阵切成等大的“分片（shards）”，每个分片驻留一张 GPU，用它计算整体矩阵乘积中相关的部分，然后再通信合并结果。

一个例子是 [Megatron-LM](https://nv-adlr.github.io/MegatronLM)，它并行化 Transformer 自注意力和 MLP 层内的矩阵乘法。[PTD-P](https://arxiv.org/abs/2104.04473) 同时使用张量、数据和流水线并行；其流水线调度给每个设备分配多个不连续的层，以减少气泡开销，代价是更多的网络通信。

有时，网络的输入可以在并行计算量相对于跨卡通信很高的维度上做并行切分。[序列并行](https://arxiv.org/abs/2205.05198) 就是这样一个想法：把输入序列沿时间拆成多个子样本，让计算以粒度更小的样本推进，从而成比例降低峰值内存消耗。

## 专家混合（MoE）

采用 [专家混合（Mixture-of-Experts，MoE）](https://arxiv.org/abs/1701.06538) 方法时，对任何一个输入，网络只有一小部分被用于计算输出。一种做法是持有很多套权重，推理时由门控机制选择使用哪一套。这能在不增加计算成本的前提下容纳多得多的参数。每套权重被称为一个“专家（expert)”，寄望网络学会把专门的计算与技能分配给各专家。不同的专家可以驻留在不同 GPU 上，为扩大模型所用 GPU 数量提供了清晰路径。

专家混合（MoE）层示意图。门控网络只从 *n* 个专家中选择 2 个。（图片改写自：[Shazeer et al., 2017](https://arxiv.org/abs/1701.06538)）

[GShard](https://arxiv.org/abs/2006.16668) 用一个方案把 MoE Transformer 扩展到 6,000 亿参数：只有 MoE 层跨多个 TPU 设备切分，其余层完全复制。[Switch Transformer](https://arxiv.org/abs/2101.03961) 通过把一个输入只路由给单个专家、以更高的稀疏度，把模型规模扩展到万亿参数。

## 其他节省内存的设计

还有许多计算策略能让训练越来越大的神经网络更可行。例如：

- 计算梯度时需要保留原始激活值，这会消耗大量设备内存。[*Checkpointing*](https://arxiv.org/abs/1604.06174)（又称激活重计算）只存储激活值的任意子集，在反向传播时即时重算中间值。这以最多额外一次完整前向传播的计算代价，省下大量内存。还可以通过[选择性激活重计算](https://arxiv.org/abs/2205.05198)持续在计算与内存成本之间取舍——即只对那些存储代价高、重算代价低的激活子集做 checkpoint。
- [*混合精度训练*](https://arxiv.org/abs/1710.03740)是用低精度数（最常见是 [FP16](https://en.wikipedia.org/wiki/Half-precision_floating-point_format)）训练模型。现代加速器用低精度数可达高得多的 FLOPS，同时还能节省设备内存。只要处理得当，最终模型几乎不损失精度。
- *卸载（Offloading）*指把暂时不用的数据临时卸载到 CPU 或在不同设备之间挪移，需要时再读回。朴素的实现会大幅拖慢训练，而精巧的实现会预取数据，让设备永远不必等待。这一思想的一个实现是 [ZeRO](https://arxiv.org/abs/1910.02054)：把参数、梯度和优化器状态切分到所有可用硬件上，按需再物化。
- 人们提出了*内存高效优化器*来减少优化器维护的运行时状态的内存占用，如 [Adafactor](https://arxiv.org/abs/1804.04235)。
- *压缩*也可用于存储网络中的中间结果。例如，[Gist](https://www.microsoft.com/en-us/research/uploads/prod/2018/04/fiddle-gist-isca18.pdf) 压缩为反向传播保存的激活值；[DALL·E⁠](https://openai.com/index/dall-e/) 在同步梯度之前对其进行压缩。
