# Endava 如何借助 Codex 打造智能体组织

Endava 使用 Codex，将资深工程经验扩展到其完整交付生命周期。

Endava 是一家全球软件承包公司，工程师遍布欧洲、美洲和亚洲，也是 Codex 的早期采用者。对于一家以为银行、保险公司、零售商和媒体公司交付高质量软件为核心业务的企业来说，这些改进非常显著。

“我们过去需要自己编写大量代码，而现在更多是在监督 Codex 产出的工作，”Endava 欧洲区 CTO Joe Dunleavy 说。“输出质量几乎呈指数级提升。”

Endava 现在将自己称为*智能体组织*：一家把资深专家经验编码进智能体、让其在从需求接收到创意构思再到最终交付的整个客户合作生命周期中与团队并肩工作的公司。

> “Codex 真正帮助我们做到的是，让小团队在极短时间内交付巨大价值。”

—Joe Dunleavy，Endava 欧洲区 CTO

## 放大团队中的每一项技能

Endava 智能体架构全球高级副总裁 Mike Krolnik 表示，Codex 改变了资深工程师与初级工程师的协作方式。“像我这样的资深架构师，来自复杂环境，能够清楚表达我们的目标，而 Codex 会把这些转化为团队中更初级成员也能理解的信息。从初级成员的角度看，他们能够采用这个工具，产出资深、成熟水准的成果。”

在实践中，这意味着把通常只会交给资深工程师的工作交给初级开发者，同时由 Codex 在最佳实践和架构决策上充当指导者。“我可以把自己的观点交给 Codex，当他们工作时，它会帮助他们理解这种观点，”Krolnik 解释道。“他们可以就自己不理解的事情提问。作为开发过程中的学习工具，我能够把自己的经验编码进去，让 Codex 与团队协作，教他们更好的软件架构和开发实践。”

这种知识传递最终成为智能体组织的核心价值和优势之一。原本需要通过多年结对编程、代码审查和指导才能形成的资深判断，如今变成了团队可以实时协作的能力。这改变了组织中初级开发者获得指导的方式。一位资深人员的视角一旦被编码进 Codex，就能并行指导多个经验较少的团队。

> “Codex 已经发展成一款成熟工具。我们将它用于需求分析、设计、规格制定、开发和运维；它是贯穿我们整个生命周期的通用桌面智能体。”

—Mike Krolnik，Endava 智能体架构全球高级副总裁

## 将数周工作压缩到数天

当资深判断始终可用时，交付的每一步都能得到改进。Endava 不再把分析、设计和构建视为在专家之间依次交接的顺序阶段。“这些阶段过去每一个都要花上数天或数周来分析，”Krolnik 说。“现在，Codex 将分析、设计和构建打包在一起，我们可以把它作为一个统一工具来完成。”

最近一次跨团队合作展示了这在实践中的样子。Endava 的法务团队向工程团队提出了一个复杂问题：要依据一套特定标准审查数千页合同。把律师的需求转化为工程团队可据以构建的内容，通常需要数周反复沟通。但 Krolnik 的团队改为录制了一场与法务相关方进行的两小时深度会议，将转录内容输入 Codex，并用它生成了一份可用的需求规格说明。原本可能需要一到两周反复修订的工作，被压缩成两场一小时会议，并产出了一份可用规格。

同样的时间节省也出现在客户项目中。Endava 的团队如今会在客户会议中实时生成设计文档、图表和规格说明，以展示想法。“你可以让它绘制拟议软件架构的图表，这样客户更容易理解，”Krolnik 说。“它大幅加快了来回沟通，也确实打开了很多机会。”

## 领导力启示

- **把资深人员经验编码化。**最大的杠杆来自将资深架构师的判断沉淀进 Codex，让初级团队成员在执行时获得资深指导。
- **把 Codex 视为桌面智能体，而不是编码助手。**Endava 最大的突破来自将 Codex 应用于需求、设计、客户沟通和运维，而不只是代码。
- **别只停留在思考上，真正去试！**“第一条建议是，不要只想着你想做什么，而是要真正上手去试，”Dunleavy 说。Endava 给刚起步团队的建议是：先选择一个非编码工作流，例如需求分析、设计文档或客户沟通。要最快看到 Codex 的全部价值，最好的方式是在团队过去从未使用编码工具的场景中使用它。

> “Codex 会放大我的每一项技能，而每个学会使用它的人，其拥有的每一项技能也都会被放大。”

—Mike Krolnik，Endava 智能体架构全球高级副总裁
