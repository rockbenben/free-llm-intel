# 在 API 中推出新模型，推进语音智能

新一代实时语音模型，能在人们说话的同时进行推理、翻译和转写。

我们在 API 中推出三个音频模型，为开发者解锁一整类新的语音应用。借助这些模型，开发者可以构建更自然、响应更智能、并能实时采取行动的语音体验：

- **GPT-Realtime-2**：我们首个具备 GPT-5 级推理能力的语音模型，可以处理更复杂的请求，并自然地推动对话继续。
- **GPT-Realtime-Translate**：新的实时翻译模型，可将 70 多种输入语言的语音翻译成 13 种输出语言，同时紧跟说话者的节奏。
- **GPT-Realtime-Whisper**：新的流式语音转文本模型，在说话者讲话的同时实时转写。

语音正在成为人们使用软件最自然的方式之一。它让人们可以在开车时请求帮助、在走过机场时更改行程、用自己偏好的语言获得支持，或者不停下来打字就能推进一项任务。

但构建有用的语音产品，光有快速的轮换应答或听起来自然的嗓音是不够的。一个语音 agent 需要理解说话人的意思、跟踪上下文、在请求变化时自我纠正、在对话继续的同时调用工具，并以契合当下情境的方式回应。

我们发布的这些模型共同把实时音频从简单的“一问一答”推进到真正能干活的语音界面：在对话展开的过程中倾听、推理、翻译、转写并采取行动。

## 作为人与产品之间界面的语音

随着语音成为更自然的使用软件的方式，我们看到开发者正围绕语音 AI 的三种新兴模式进行构建：

- **语音到行动（Voice-to-action）**：人们描述自己的需求，系统对请求进行推理、调用工具并完成任务。例如，Zillow 正在构建一个能够倾听、推理并执行如下请求的助手：“在我的可负担范围内找房，避开繁忙街道，并预约周六看房。”
- **系统到语音（Systems-to-voice）**：软件把上下文转化为实时的语音指引。例如，旅行应用可以主动告诉旅客：“您的去程航班延误了，但您仍能赶上转机。我已找到新的登机口，规划了穿过航站楼的最快路线，您的行李预计仍会转运。”
- **语音到语音（Voice-to-voice）**：AI 帮助跨语言、跨任务、情境不断变化的实时对话继续进行。例如，德国电信（Deutsche Telekom）正在构建语音支持体验，客户可以用自己最习惯的语言交谈，模型实时翻译对话。

这些模式也可以组合使用。Priceline 正在朝向一个旅客可全程用语音管理行程的未来：以对话方式搜索机票和酒店、处理变更（如航班延误后调整酒店预订、获取 TSA 排队时长的实时更新），并在旅客抵达目的地后进行对话翻译。

## 实时语音：帮助语音模型推理与行动

GPT-Realtime-2 为实时语音交互而生：模型在保持对话流动的同时对请求进行推理、调用工具、处理纠正或打断，并以契合当下情境的方式回应。

- **前导语（Preambles）**：开发者可以启用主回答前的简短话语，如“我来查一下”或“请稍等，我看一下”，让用户知道 agent 正在处理请求。
- **并行工具调用与工具透明化**：模型可以同时调用多个工具，并用“正在查看您的日历”“马上为您查询”这类话语让动作可闻，帮助 agent 在完成的任务的同时保持响应。
- **更强的恢复行为**：模型可以更体面地恢复，例如说“我暂时在这方面遇到了点问题”，而不是无声失败或中断对话。
- **面向 agentic 工作流的更长上下文**：我们把上下文窗口从 32K 提升到 128K，以支持更长、更连贯的会话和更复杂的任务流。
- **更强的领域理解**：模型能更好地保留专业术语、专有名词、医疗健康词汇以及其他在生产环境中重要的词汇。
- **更可控的语气与表达**：模型能更好地调整语气——解决问题时保持镇定，用户沮丧时表达共情，确认操作成功时轻快积极。
- **可调的推理强度**：开发者现在可以在 **minimal、low、medium、high 和 xhigh** 推理等级中选择，**默认是 low**，在简单交互的低延迟与复杂请求的深思熟虑之间取得平衡。

这些提升在与生产语音 agent 高度对应的音频评测上有所体现：在音频智能评测 Big Bench Audio 上，GPT-Realtime-2（high）比 GPT-Realtime-1.5 得分高 15.2%；在指令遵循评测 Audio MultiChallenge 上，GPT-Realtime-2（xhigh）得分高 13.8%，相对 GPT-Realtime-1.5 展现出实时对话中更强的推理、上下文管理与控制能力。

[Big Bench Audio](https://artificialanalysis.ai/methodology/speech-to-speech-benchmarking) 评估支持音频输入的语言模型在高难度推理能力方面的表现。[Audio MultiChallenge](https://labs.scale.com/leaderboard/audiomc-audio) 评估口语对话系统在多轮对话中的智能表现，包括指令遵循、上下文整合、自洽性以及处理自然语音修正的能力。

## 实时翻译：构建多语言实时语音体验

GPT-Realtime-Translate 帮助开发者构建多语言实时语音体验：每个人用自己的偏好语言说话，实时听到翻译后的对话并阅读实时转写。它支持 70 多种输入语言和 13 种输出语言，适用于客户支持、跨境销售、教育、活动、媒体，以及服务全球受众的创作者平台。

对开发者而言，实时翻译必须在跟上说话者节奏的同时保全语义——即便人们说话自然随意、切换语境，或使用地区口音和领域专有词汇。例如，德国电信正在多语言语音交互中测试该模型，更低的延迟和更强的流畅度能让跨语言对话更自然。

在这段视频中，Vimeo 展示了 GPT-Realtime-Translate 如何在产品教学视频播放时实时翻译，让全球客户用自己的偏好语言听到更新内容，而不必等待另行制作的版本。

## 实时转写：构建低延迟转写体验

GPT-Realtime-Whisper 是新的流式转写模型，为低延迟语音转文本而生。它在人们说话的同时转写音频，让实时产品感觉更快、更跟手、更自然——从即时出现的字幕，到能跟上对话节奏的会议记录。

该模型让现场语音即时可用于业务流程。团队可以为会议、课堂、直播和活动提供字幕；在对话进行中的同时生成笔记与摘要；构建需要持续理解用户的语音 agent；并为客户支持、医疗、销售、招聘等高流量口语交互场景创建更快的后续工作流。

## 安全

Realtime API 内置多层防护与缓解措施以防止滥用。我们对 Realtime API 会话采用主动分类器，意味着某些对话若被检测到违反我们的有害内容准则，可能会被中止。开发者也可以通过 [Agents SDK](https://openai.github.io/openai-agents-js/guides/guardrails/) 轻松添加自己的额外安全护栏。

我们的[使用政策](https://openai.com/policies/usage-policies/)⁠禁止将我们服务的输出重新用于垃圾信息、欺骗或其他有害目的。开发者还必须让最终用户清楚知道他们正在与 AI 互动，除非从情境中已不言而喻。

Realtime API 全面支持面向欧盟应用的 [EU Data Residency](https://platform.openai.com/docs/guides/your-data#data-residency-controls)，并受我们的[企业隐私承诺](https://openai.com/enterprise-privacy/)保护。

## 定价与可用性

GPT-Realtime-2、GPT-Realtime-Translate 和 GPT-Realtime-Whisper 已在 Realtime API 中提供。GPT-Realtime-2 定价为每 100 万音频输入 token 32 美元（缓存输入 token 每 100 万 0.40 美元），每 100 万音频输出 token 64 美元。GPT-Realtime-Translate 定价为每分钟 0.034 美元。GPT-Realtime-Whisper 定价为每分钟 0.017 美元。
