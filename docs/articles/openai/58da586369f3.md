# 研究加速：参差不齐的前沿

## 引言

今年以来，AI 系统的能力不断增强，它们自身参与 AI 研究与开发的能力也可能随之提升。今天我们发布一份关于 OpenAI 内部研究加速现状的更新，其依据是我们对 coding agent 如何加速并改变 AI 开发周期的内部测量。

## 我们的主要结论：

- **Agent 现在能独立完成近一半需要两到四小时的研究任务，但人类在 AI 开发中依然处于核心位置。** 从 3 月到 10 月，对估计需要两到四小时人工的任务，估计成功率从 23% 升至 46%；对估计需要四到八小时的任务，成功率从 13% 升至 35%。不过任务的类型很关键。例如按任务细项拆分，自主 agent 在监控训练运行上的成功率为 79%，在启动训练运行上为 35%，在为推理与服务栈编写代码上为 25%。总体来看，提升幅度参差不齐，人类仍是 AI 研究闭环中的核心一环。
- **Agent 的使用量正在激增，用得最狠的那批人正把差距越拉越大。** 按 API 标价计算，10 月中位研究员每天的使用额达到 2,400 美元，比 9 月增长 62%；第 90 百分位达到 23,000 美元，比 9 月增长 105%。一项问卷从另一个侧面反映了研究员对这类工具的看重程度。当被问到愿意用什么来换取继续使用前沿 coding agent 三个月时，答案的中位数是团队 30% 的算力；在另一个单独的问题中，则是团队 40% 的人头。
- **研究员正把越来越多的人力投入到 Safety and Alignment**，在 OpenAI 所有主要研究领域中，该方向有记录的研究投入绝对增幅最大。从 1 月到 9 月，Safety and Alignment 有记录的工作周数增长了 77%，这既来自新招聘，也来自现有研究员向这些工作流的转移。2026 年 7 月我们对 [Hugging Face 事件](https://openai.com/index/hugging-face-incident-and-the-road-ahead/) 作出回应之后，增长明显加快。

本报告接续我们 9 月那篇关于 [OpenAI 内部研究加速](https://openai.com/index/research-acceleration-view-inside-openai/) 的博客文章，新增了两方面的定量与定性衡量：(1) 各研究领域中 AI 带来的提升（uplift），以及 (2) 人类如何继续参与研究过程。总体而言，我们认为这次更新提供了一个更广、但依然不完整的视角，用来看清 OpenAI 的研究正在如何变化。

我们公开这项工作，是因为正如我们在 [frontier policy blueprint](https://openai.com/index/frontier-safety-blueprint/) 中所写、并在第一份 [研究加速报告](https://openai.com/index/research-acceleration-view-inside-openai/) 中重申的那样：我们认为应当要求 AI 实验室追踪并公开报告递归自我改进（RSI）的指标——也就是 AI 加速未来 AI 系统开发的过程。

随着能力提升、剧烈的 AI 驱动研究加速越来越可能发生，我们将需要解决全新的技术与治理问题，以维持人类监督并 [安全地扩展 AI 系统](https://openai.com/index/an-alien-mind/)。因此，公开 RSI 指标的透明度，对于一场关于日益强大的 AI 的能力、风险与必要防护措施的公众讨论至关重要；不过，我们的报告不应被解读为有意追求完全的 RSI。令人鼓舞的是，近来已有若干其他机构为不断壮大的 AI R&D 加速测量工作作出贡献[1](https://openai.com/index/research-acceleration-jagged-frontier/#user-content-fn-1)。我们希望这份扩充后的报告有助于维持并推进业界这些共同的测量规范。

本报告分为三个部分，每部分聚焦 AI 研究的不同侧面：

- AI 研究的**投入**（我们聚焦 coding agent；其他投入包括数据、人力与算力）
- 研究员把这些投入转化为模型能力的**过程**（即 AI 研究）
- 我们从 AI 研究过程中看到的**产出**（模型能力的提升）。

我们认为，按这种方式组织结果，可以为思考 AI 如何在研究中被使用、以及这种使用如何可能推动模型能力提升，提供一个有用的框架。

## 投入

AI 研究使用多种投入，包括数据、AI 工具（例如 coding agent）、人力与算力。本报告聚焦作为研究投入的 AI 工具，具体记录 coding agent 的使用强度在不同团队之间如何差异、随时间如何变化。此外，虽然我们不直接报告人力成本的变化，但会考察研究人力支出相对于其他要素支出的占比随时间如何变化。

### 内部 agent 使用情况

自 [我们的第一份报告](https://openai.com/index/research-acceleration-view-inside-openai/) 以来，研究组织内部的 agentic AI 使用量持续指数级增长。按 API 标价计算，中位研究员现在每天在 agentic AI 工具上花费约 2,400 美元，第 90 百分位的研究员每天约 23,000 美元，相比 9 月的 1,500 美元和 11,000 美元分别增长 62% 和 105%。[2](https://openai.com/index/research-acceleration-jagged-frontier/#user-content-fn-2) 这种 agentic 使用量上升的趋势涵盖多种变化，包括活动变多、转向更贵的模型，以及模型行为与 agentic harness 的变化。

#### Agent 工作日

接下来看每位研究员每天平均的“agent 工作日”数，我们把 agent 每使用八小时定义为一个 agent 工作日。与 agentic 支出不同，agent 工作日更能反映 agent 实际在干活上花掉的“墙上时钟时间”，但不反映模型能力或价格的变化。

总体来看，每位研究员的 agent 工作日从 0.5 个升至 5.7 个，增长十一倍，其中以预训练与后训练团队增幅最大。在这些团队，每位研究员每个自然日的 agent 运行时长平均约为八个工作日；在 scaling 与基础设施方向，平均约为四个。需要说明的是，这一工作日指标通常只包含交互式使用，因此可能低估了自动化部分。

#### 并发 agent 使用

我们的 [9 月分析](https://openai.com/index/research-acceleration-view-inside-openai/) 指出，研究员越来越多地并发使用 agent，包括 subagent 与多会话。我们把这项分析在时间上进一步延伸，并给出更细的分桶。到 10 月中旬，纳入统计的研究员中有超过三分之二日均峰值至少有四个 agent 同时工作，超过 10% 的人日均至少有十六个并发 agent。

### 内部 agent 使用相对于人力成本

接下来我们把每月按 API 折算的 agentic AI 使用支出，与人类研究员的每月非股权薪酬作比较。我们追踪这一比值，观察随着模型能力提升，agent 与人力之间的投入配比如何变化。尽管我们报告的比值不含股权——在 OpenAI，股权通常占研究员目标薪酬的 70% 至 80%——我们认为它仍然能为这种支出配置提供一个不完整但有参考价值的视角。

截至 2026 年 9 月，OpenAI 研究组织中 agentic AI 使用的 API 折算价值约为其非股权薪酬的两倍，预训练与后训练的比值高于研究组织的其他部分。尽管如此，内部部署（合并内部 Codex、ChatGPT 与 API 使用）只占研究总算力的 2%。

人力成本包括薪资、加班费、奖金、福利与雇主承担的税费。股权不计入其中，在研究员的目标薪酬里股权通常占 70% 至 80%。

### 研究员把时间投向何处

最后，我们考察研究员如何在各研究领域之间分配时间。我们首先收集了 2026 年 1 月至 9 月研究员个人层面的贡献，形式包括公司内公开可见的 Slack 帖子、pull request 与内部文档。随后我们用分类器把这些贡献归入各研究领域，每个“研究员-周”按该研究员当周经核实的项目平均分摊。这为研究员的注意力投向提供了一个代理指标。

需要强调的是，与我们的其他分析不同，**我们在此划分的“研究领域”并不对应正式的汇报关系**。例如，一位后训练团队的研究员若把一半时间用于基础设施改进，就会被估算为向 Scaling / Infrastructure Contributions 贡献半个工作周、向后训练贡献半个工作周。这样一来，即便研究员并未正式转岗，我们也能稳健地测量出他们实际把时间花在哪里。

我们发现，投入我们所识别的每个领域的研究员时间，在 2026 年都有增长。值得注意的是，用这套方法，我们发现 Safety & Alignment 在所有研究领域中绝对增幅最大：自年初以来，其有记录的工作周贡献几乎翻倍，原因既包括新招聘，也包括现有研究员把重心转向安全项目。该研究领域涵盖 alignment evals、monitorability 与 reward hacking 研究等工作流。我们测到 Safety & Alignment 增长中的一个明显拐点，与 7 月 [Hugging Face 事件](https://openai.com/index/hugging-face-model-evaluation-security-incident/) 之后的情形，以及 OpenAI 随后 [为前沿 AI 训练开发并改进 safety case](https://openai.com/index/towards-safety-cases-for-frontier-ai-training/) 的工作相吻合。

我们说明一下，研究领域之间的界线——尤其是后训练与 safety and alignment 之间的界线——并不容易划清，我们可能会随时间迭代这一定义。下文的方法部分给出了高层工作流的示例。

## 过程

为了更好地理解 agent 的使用可能如何影响研究生产力，我们接着考察 OpenAI 开展 AI 研究的过程正在如何变化。新技术带来的生产力增益，部分取决于工作如何围绕它被重新组织。随着 agent 变强，研究员可能改变把哪些任务交给 AI、如何监督与协调 agent 的工作，以及推进哪些项目。下面我们同时给出定量与定性的衡量，说明 AI 正在如何改变 OpenAI 开展 AI 研究的过程。这些不同类型的数据合在一起，构成一个（不完整的）视角，用来看研究员如何围绕 agent 重组工作，以及今天研究员如何仍留在闭环之中。

### 研究活动的衡量

#### 交给模型的任务与成功率

我们的 [9 月分析](https://openai.com/index/research-acceleration-view-inside-openai/) 显示，agent 越来越有可能在无人干预的情况下成功完成任务，包括估计需要数小时人工的任务。采用更新后的方法（见下文方法部分），我们发现这一趋势总体延续。需要强调的是，随着 agent 能力提升，研究员在每个时长档内交出的任务类型也可能变了。因此，各档内“零干预成功率”的变化，可能同时反映能力进步与研究员对何时、如何使用 agent 的选择变化。

除了按估计时长的这些趋势，我们还考察成功率在研究员可能选择交出的不同类型任务之间如何变化。我们按类别与任务报告估计成功率，采用 Epoch AI 开发的 [O*NET AI R&D taxonomy](https://epoch.ai/gradient-updates/toward-an-onet-for-ai-rnd)。不出意料，我们的结果说明模型并非在所有任务类别上都一样好：例如 2026 年 8 月 1 日至 10 月 18 日期间，无人干预的估计成功率在 Communicate（69%）与 Analyze（58%）上高于 Build（43%）。同样在任务层面，诸如排查训练运行中的问题（79%）、回答技术问题（72%）这类任务的估计成功率更高，而为推理与服务栈编写代码（25%）、搭建评估、强化学习与 agent 环境（29%）则更低。只要模型在 AI R&D 相关任务上的表现是不均衡的，表现较差的类别与任务就可能成为整体提升的瓶颈。

#### 研究员用 agent 做什么任务

我们的 [9 月分析](https://openai.com/index/research-acceleration-view-inside-openai/) 用同一套 [O*NET AI R&D taxonomy](https://epoch.ai/gradient-updates/toward-an-onet-for-ai-rnd) 报告了研究员工的 AI 使用如何在 output token 上分布。下面我们报告研究员在各项任务上使用 coding agent 的频次。相比启动并监控一次训练运行、实现一个复杂功能这类 token 密集型任务，这会相对更看重回答技术问题这类短任务。

### 研究员对 AI 使用的看法

接下来看研究员自己如何评估 AI 对其工作的改变。通过问卷与访谈，我们考察研究员如何评估 coding agent 的价值、他们如何产生研究想法，以及他们如何调整自己的工作流。

#### 自报的 coding agent 价值

2026 年 8 月下旬至 9 月上旬，我们对 101 名研究员工做了一次问卷，以了解 AI 带来的提升，核心是这样一个假设：“假设未来 3 个月内，你的团队被收回所有优于 GPT-5.2 的 coding agent 的使用权。你愿意拿什么来换回前沿 coding agent？”中位研究员表示愿意拿出：

- 团队 40% 的人头
- 当前团队 30% 的算力
- 如果这个问题是在 2027 年 1 月提出，则是团队 50% 的算力（依据他们对模型到 2027 年会有多大改进的预期）

研究员还表示，如果不允许使用 coding agent（即只允许使用 GitHub Copilot + ChatGPT），其团队要完成与上个月等值的工作，中位需要三个月。虽然必须指出自报数据在准确性上可能有问题、我们的问卷抽样策略也属临时安排，但这些结果与“研究员认为 AI 带来的提升在其工作中价值可观”这一判断是一致的。

柱形表示各区间答案的加权占比。虚线标记加权中位数。

在 10 月下旬的另一份问卷中，我们还问了受访者：在日常工作中，是用我们最新的内部模型更有产出，还是由一位处于职业中期的真人研究工程师再加上 o1-preview 这类 2024 年的模型来协助更有产出。28 位受访者中有 27 位选择或倾向于最新的内部模型。余下那位没有在所给的两个选项之间作选择，而是说自己会选 GPT-6 Astra，而不是带人类协助的那个选项。

#### 大想法从哪来

我们也想追踪 AI 驱动想法生成的进展，因为提出并甄别概念性研究想法的能力（research taste）可能是递归自我改进的瓶颈。为衡量这一点，我们在三个领域（预训练、后训练与安全监控）各找了一到四位做出关键贡献的研究员，请他们各举出一到三个自认为对 GPT-6 Astra 与 GPT-6.2 Astra 两次发布最重要的想法。随后我们询问这些想法从何而来，以及 AI 在形成它们的过程中是否起了作用、起了什么作用。

对这两次发布，后训练与安全监控的研究员都表示，据他们所知，自己举出的所有想法都是人想出来的，模型只是帮助实现。预训练研究员同样把他们在 GPT-6 Astra 中举出的想法完全归功于人。

在 GPT-6.2 Astra 上，预训练研究员描述了在与 Codex 的对话中形成想法的过程。其中一位认为，在他们一起推敲某个想法的过程中，Codex 找出了关键洞见。另一位说主要想法是自己的，但要等 Codex 建议做一处改动之后才真正好用起来。

#### 研究工作流的变化

最后，为取得工作流变化的定性证据，我们还访谈了十位分别来自预训练、后训练与安全方向的研究员，了解他们如何使用 agent。这些访谈中浮现出五个主要主题，总结如下：

- **研究员用 agent 写代码、调 bug、监督实验：**  “我以前移植过一个开源 eval，要围绕『这个 eval 好不好』做研究和消融，工作量要大得多。可能得花一周半到两周，才真正走到『我们到底能不能用它』这一步。而现在，取决于具体的 eval，从零到跑起来是一天，也许几天。”
 *—研究者 7，安全方向，从事评估工作*
- **Agent 在研究想法、代码质量、数据质量与写作上的品味很差：**  “模型通常无法一次就想出一个提法良好、且它自己解不出来的问题。而且如果你让模型生成同一个数据点一百次，它每次生成的都会是相似的数据点。”
 *—研究者 2，安全方向，从事强化学习环境工作*
- **工作流需要人紧密参与，才能避免低质量产出与空转的循环：** agent 难以高效地启动实验，会在不必要的步骤上钻牛角尖，写出“AI slop”式的 PR，产出不可用的数据产物，还会做出无效的分析假设。  “我试过说『把这个任务照着那个任务做』，结果被坑了太多次——做得不太对，我还得自己改。所以现在我改成说『你先做一个。我来评审和修改。然后再把剩下的都做了。』”
 *—研究者 1，后训练方向，从事评估工作*
- **研究员预期当前瓶颈领域会有显著改进：**  “我确实认为在想法上我更有品味。但我没信心这还能在很长一段时间内继续成立。”
 *—研究者 8，预训练方向，从事架构与数据工作*
- **研究员从大规模扫描与生成内容中获得很大提升：** 研究员用模型扫描数千个样本，以诊断实验中的问题、标记模型行为中值得警惕的实例，以及构建并质检新的数据集。  “我最近做的一件事是把我们所有数据过了一遍……我让它跑了几轮，并对它给出的结果做校准。……它给了我一张很大的表，整理得特别好。……没有 AI，这事会痛苦得难以想象。”
 *—研究者 3，后训练方向，从事数据质量工作*

## 产出

除了研究投入与工作流的变化，我们还想知道 AI 的使用是否在加速研究进展。为回答这个问题，我们给出三项衡量。其中两项——代码行数与研究实验数——已包含在 [9 月分析](https://openai.com/index/research-acceleration-view-inside-openai/) 中。这两项容易追踪，但研究活动的这些指标上升，并不必然意味着研究进展变快。因此我们还引入 OpenAI ECI，即 Epoch Capabilities Index 的 OpenAI 内部专用版本，它是追踪模型能力变化的一种方法，可作为衡量研究结果的更直接指标。

### 代码变更行数

我们首先报告每位活跃贡献者随时间的人均代码变更行数。相对于 2025 年之前的平均值，这项指标在 2026 年继续大幅上升。需要说明，自 [9 月分析](https://openai.com/index/research-acceleration-view-inside-openai/) 以来我们做了若干方法上的更新。现在我们展示 28 天滚动平均，而不是季度平均，从而更细致地呈现随时间的变化。我们还修订了纳入统计的代码变更标准（特别是排除测试），详见方法部分。

### 研究实验

与 [9 月报告](https://openai.com/index/research-acceleration-view-inside-openai/) 一样，我们也追踪每位活跃实验者随时间运行的实验数量。在截至 10 月 18 日的四周内，每位活跃实验者的人均有记录实验数为 2025 年基线的 1.68 倍。

### OpenAI ECI

最后，我们报告一项旨在刻画模型能力进步的指标。[Epoch Capabilities Index](https://epoch.ai/eci?view=graph&tab=release-date) 被广泛用于衡量通用 AI 能力的进展趋势。OpenAI ECI（OECI）背后的方法与 Epoch 的方法非常接近，区别在于 OECI 同时使用公开 benchmark 与 OpenAI 内部 benchmark。这里我们绘制了 20 个已公开发布的 OpenAI 模型与 28 个其他模型的 OECI。

我们发现，自 2025 年 8 月以来，OpenAI 模型的 OECI 前沿以每年 16.4 点的速度上升，而 Epoch 观测到的自 2024 年末以来的趋势是 [每年 14 点](https://epoch.ai/data-insights/eci-frontier-trend)。需要注意，OpenAI 模型在 OECI 上相对于竞争对手的得分，高于它们在 Epoch 的 ECI 上的表现，原因很可能是 benchmark 组合不同。

我们计划继续监测 OpenAI ECI 与其他顶层能力指标，以判断能力进步是否因 RSI 而加速。

竖线为 90% bootstrap 置信区间。趋势线拟合于 9 次创纪录的 OpenAI 发布。

## 结论

总体而言，我们的发现延伸了 [9 月报告](https://openai.com/index/research-acceleration-view-inside-openai/) 的图景：研究员使用 agent 更密集、交出去的工作更多，并围绕模型的能力与局限调整自己的工作流。然而，这种提升在所有研究工作流上并不均匀，今天的 agent 也仍有明显缺陷。

我们说明一下，我们所报告的历史趋势与指标（其中包含大量人机协作）未必能预测未来由 AI 驱动的进展。例如，近来我们看到了前沿模型在 [数学](https://openai.com/index/sharing-ai-progress-in-mathematics/) 上突然而迅速的突破。随着我们的模型在研究上越来越自主、越来越有能力，我们也在留意深度学习中是否会出现同样迅速的突破。

更重要的是，随着 AI 越来越擅长改进自身，竞争压力与治理挑战都会上升，而一项 [关键任务](https://openai.com/index/an-alien-mind/) 是确保人类始终留在这一过程之中。我们希望公开这些数据，能为关于模型能力节奏与递归自我改进治理的讨论提供依据。

今后，我们将继续改进本文所报指标背后的方法。我们也希望在若干领域扩展报告内容、提供更多信息，包括但不限于：

- 能力研究与安全研究的加速差异
- 研究加速的先行指标（即无需走完一整轮模型开发与评估，就能检测到提升的上升）
- 整体能力随时间变化的趋势，以及 AI 对研究的加速对这些趋势的影响
