# MuseNet

配图：Ben Barry

我们创造了 MuseNet，一个深度神经网络，能用 10 种不同乐器生成 4 分钟的乐曲，并把从乡村音乐到莫扎特再到披头士的风格混合起来。MuseNet 并非依据我们对音乐的理解被显式编程，而是通过学习预测数十万个 MIDI 文件中下一个 token，自行发现了和声、节奏和风格的规律。MuseNet 使用的是与 [GPT‑2⁠](https://openai.com/index/better-language-models/) 相同的通用无监督技术——一个大规模 [transformer](https://arxiv.org/abs/1706.03762) 模型，被训练去预测序列中的下一个 token，无论是音频还是文本。

在*简单模式*（默认显示）下，你会听到我们预生成的、随机未筛选的样本。选择一个作曲家和风格，可选一段名曲的开头，然后开始生成。这让你得以探索模型能创作的音乐风格的多样性。在*高级模式*下，你可以直接与模型交互。生成会更耗时，但你创作的将是一首全新的曲子。

MuseNet 的一些局限包括：

- 你指定的乐器是强烈建议，而非硬性要求。MuseNet 通过计算所有可能音符和乐器上的概率来生成每个音符。模型会向让你选择的乐器更可能出现的方向调整，但总有它会选到别的东西的可能。
- 对于风格和乐器的怪异搭配（如肖邦配贝斯和鼓），MuseNet 处理起来更吃力。如果你挑选接近作曲家或乐队惯常风格的乐器，生成会更自然。

## 作曲家与配器 token

我们创建了作曲家 token 和配器 token，以便对 MuseNet 生成的样本类型有更多控制。在训练阶段，这些作曲家和配器 token 被前置到每个样本之前，好让模型学会利用这些信息来做音符预测。在生成阶段，我们就可以通过以诸如“拉赫玛尼诺夫钢琴开头”这样的提示词起始，把模型条件化为按所选风格创建样本：

## 长期结构

MuseNet 使用了 [Sparse Transformer⁠](https://openai.com/index/sparse-transformer/) 的重算与优化 kernel，训练了一个 72 层、24 个注意力头的网络——在 4096 个 token 的上下文上做完整注意力。这样长的上下文或许就是它能记住乐曲中长期结构的原因之一，如下面这段模仿肖邦的样本：

它也能创造音乐性的旋律结构，如下面这段模仿莫扎特的样本：

音乐生成是检验 Sparse Transformer 的一个有用领域，因为它处在文本与图像之间的中间地带。它拥有文本般流动的 token 结构（在图像中你可以往回看 N 个 token 找到上一行，而在音乐中并没有一个固定的回溯量来找到上一小节）。然而我们很容易听出模型是否在捕捉数以百计乃至数以千计 token 尺度上的长期结构。如果一个音乐模型通过改变节奏把结构搞砸，那会比对一个文本模型短暂跑偏更明显。

## 数据集

我们从许多不同来源为 MuseNet 收集训练数据。[ClassicalArchives](https://www.classicalarchives.com/) 和 [BitMidi](https://bitmidi.com/) 为本项目捐赠了它们庞大的 MIDI 文件收藏，我们也在网上找到了若干收藏，涵盖爵士、流行、非洲、印度和阿拉伯等风格。此外我们还使用了 [MAESTRO 数据集](https://arxiv.org/abs/1810.12247)。

transformer 在序列数据上训练：给定一组音符，我们请它预测下一个音符。我们尝试了把 MIDI 文件编码成适合该任务的 token 的几种不同方式。第一种是按和弦（chordwise）的方式，把同一时刻响起的音符的每种组合视为一个独立的“和弦”，并为每个和弦分配一个 token。第二种，我们尝试只聚焦音符的起始来浓缩音乐模式，并进一步用一个字节对编码（byte pair encoding）方案来压缩它。

我们也尝试了两种标记时间流逝的不同方法：一种是根据乐曲速度缩放的 token（使 token 表示一个音乐节拍或节拍的一部分），另一种是以秒为单位的绝对时间标记的 token。我们最终选定了一种兼顾表现力与简洁性的编码：把音高、音量和乐器信息合成为一个 token。

#### 纯文本

```
1bach piano_strings start tempo90 piano:v72:G1 piano:v72:G2 piano:v72:B4 piano:v72:D4 violin:v80:G4 piano:v72:G4 piano:v72:B5 piano:v72:D5 wait:12 piano:v0:B5 wait:5 piano:v72:D5 wait:12 piano:v0:D5 wait:4 piano:v0:G1 piano:v0:G2 piano:v0:B4 piano:v0:D4 violin:v0:G4 piano:v0:G4 wait:1 piano:v72:G5 wait:12 piano:v0:G5 wait:5 piano:v72:D5 wait:12 piano:v0:D5 wait:5 piano:v72:B5 wait:12
```

结合了音高、音量和乐器的示例编码。

在训练期间，我们：

- 通过升高和降低音高来移调音符（在训练后期，我们减少移调幅度，使生成保持在各乐器的音域之内）。
- 增广音量，调高或调低各个样本的整体音量。
- 增广时值（在使用以秒为单位的绝对时间编码时），等效于略微放慢或加快乐曲。
- 在 token 嵌入空间上使用 [mixup](https://arxiv.org/abs/1710.09412)

我们还构建了一个内部批评者（inner critic）：在训练阶段，模型被要求预测给定样本究竟是真的来自数据集，还是模型自己以往生成的作品之一。这个分数在生成阶段用于挑选样本。

## 嵌入

我们加入了若干种不同的嵌入，为模型提供更多结构上下文。除了标准的位置嵌入，我们还加入了一个学习型嵌入，用来追踪给定样本中的时间流逝。这样一来，所有同一时间响起的音符都被赋予相同的时值嵌入。然后我们为和弦中的每个音符加入一个嵌入（这模拟了相对注意力，因为模型更容易学到音符 4 需要回看音符 3，或者回看上一个和弦的音符 4）。最后，我们加入两个结构嵌入，用来告诉模型某段音乐样本在更大乐曲中的位置。一个嵌入把更大的乐曲分成 128 段，而第二个编码是当模型临近 (end) token 时从 127 倒数到 0。
