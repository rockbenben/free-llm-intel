# 1Password 借助 Codex 将工程生产力提升 21%

1Password 预估通过提升工程产能，可获得 553% 的投资回报率 (ROI)。借助 Codex，他们能够更快构建可用于生产的功能和内部工具，同时严格遵守安全政策。

1Password 已将 Codex 融入整个软件交付生命周期，缩短从规划到生产的周期，从而快速构建新功能。1Password 团队将 pull request 周期中位数缩短了近 11%，并使核心用户群体的工程生产力提升了近 21%。

基于工程团队取得的成果，1Password 管理层正将 Codex 的使用范围扩展至其他职能部门，让财务和营销等团队也能自行构建工具和功能。在此过程中，1Password 始终坚持严格的安全标准，确保提升速度不以牺牲数据安全为代价。

> “从规划到面向生产环境发布功能，整个生命周期大幅缩短，这的确让我们的许多工程师大开眼界。”

— Nancy Wang，1Password 首席技术官

## 借助 Codex 一次构建新功能

1Password 正利用 Codex 加快从构想到实施的进程，帮助工程师将定义清晰的用户案例转化为可用功能。

“过去，接手一个项目后，你需要考虑如何将它拆分为不同的迭代周期，再把各个迭代周期分配给工程 Scrum 团队。”1Password 首席技术官 (CTO) Nancy Wang 解释道，“有了 Codex，你确实可以一步到位，完成从构想到原型的过程，最终构建可全面投入生产的功能。”

Wang 表示：“在我们的工作流中，只需向 Codex 提供用户案例以及我们希望用户获得何种体验的指令，就能更快、更轻松地一次构建出功能，减少工程评审前所需的迭代。”

这项工作催生了众多新功能，既包括内部工具，也包括面向客户的产品。Knox 就是其中一例。这是一套完全由智能体驱动的前端设计系统，可帮助 1Password 的团队构建新界面。其他案例还包括内部 AI 站点可靠性工程 (SRE) 智能体和 AI 支出管理工具。

1Password 让 Codex 在明确界定的工程和安全边界内自主开展工作。Wang 表示：“Codex 会将所需功能拆解为功能规范，并构建接近最终版本的原型，然后交由系统工程师接入我们的后端。”这种方法缩短了交接时间，并提升了工程生产力。工程师编写代码的速度更快，在规划、实施与评审各环节之间的交接上花费的时间也更少。

## 贯穿软件交付生命周期的 Codex

Codex 覆盖从规划到生产的每一个环节：

- 规划与技术设计：将需求转化为规范、依赖项检查和工作项。
- 跨技术栈实施：通过 CLI 帮助工程师理解不熟悉的 Rust 和 TypeScript 代码；利用并行工作树同时执行多项任务。
- pull request 评审：在人工评审前检查变更，标记逻辑问题和缺失的上下文。
- 测试与发布准备：在开展其他工作的同时，并行验证验收标准并运行自动化测试。
- 安全与访问：接入 1Password 的内部 AppSec 执行框架；通过密钥引用，避免明文凭据进入模型上下文。
- 生产问题调查：从事件管理、遥测、源代码管理、寻呼系统和功能开关中提取证据。

## 成果一览

建模估算的年度工程产能价值：783,750 美元。计算依据为 50 名持续活跃的 Codex 开发者、每名开发者每年 25 万美元的全口径成本、实测生产力提升 20.9%、方向性估算 Codex 贡献率为 40%，生产产能实现率则为 75%。

随着 1Password 将 Codex 融入整个软件开发生命周期，工程团队的生产力提升了 20.9%，pull request 周期中位数缩短了 10.9%。一名工程师跳出自己熟悉的技术栈开发工作范式，将通常需要三天才能完成的合并工作缩短至一天；另一个面临固定测试版发布日期的团队完成了四个发布关键工单，而按以往预期只能完成两个左右。

对于一个涉及 10 多项微服务的缺陷，调查时间从约两小时缩短至 5–20 分钟。以 50 名 Codex 用户组成的建模群体计算，1Password 估计每年可释放价值约 78.4 万美元的工程产能，投资回报率达 553%；这些产能将重新投入产品开发和内部创新。若稳定用户达到 100 名，并假设 Codex 在实测生产力增益中贡献了更大份额，建模估算的年度产能价值可达 310 万美元左右。

> “如果我们确实能加快从获取客户反馈到迅速调整 UI 的反馈闭环，就能为业务解锁更多可能。”

— Nancy Wang，1Password 首席技术官

## 在开发提速的同时保障安全

1Password 还在财务、营销和其他团队中推广 OpenAI 工具，而这些团队早已习惯通过聊天界面开展工作。

对 1Password 而言，其安全模型是采用相关工具时必须满足的设计要求，而不是等使用范围扩大后另行添加的管控措施。Wang 表示：“我们在产品开发方面设有极为严格的安全策略。”例如，任何涉及凭据或密钥的产品都必须遵循零知识架构，确保只有客户能够解密和访问自己的敏感数据。

1Password 通过在代码仓库中存放密钥引用而非凭据来贯彻这一原则。当 Codex 调用获批的内部工具时，1Password 会在执行操作时解析并注入凭据，因此明文值绝不会进入模型上下文。

为进一步加强安全性，1Password 的工程师还将公司的安全策略“融入可复用的 AppSec 技能”，让公司的标准始终贯穿开发工作流。Wang 解释道，“这促成了质的改变。”

## 未来展望

Wang 和 1Password 团队认为，在不久的将来，“构建民主化”将推动软件生产进一步普及：越来越多的人员都能参与构建软件。Wang 表示，如果第一波浪潮是工程师成为 AI 辅助的构建者，那么“我们现在已迎来第二波浪潮。产品、设计、研究和开发领域的每个人都已成为构建者。产品经理开始交付产品，设计师也开始交付前端代码。”

Wang 预计这一趋势将扩展到所有岗位。她表示：“我认为，最后一步其实是让公司里的每个人都能参与构建。未来 12 个月，我们将看到，那些过去不负责编写代码或认为自己并非构建者的人，会越来越熟练地使用 AI 工具，最终能够充满信心地交付代码。”
