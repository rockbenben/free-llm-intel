# 用 GPT-4 找出 GPT-4 的错误

CriticGPT 是一个基于 GPT-4 的模型，它为 ChatGPT 的回答撰写批评意见，帮助人类训练员在 RLHF 期间发现错误。

阅读论文

我们训练了一个名为 CriticGPT 的模型（基于 GPT-4），用于捕捉 ChatGPT 代码输出中的错误。我们发现，当人们借助 CriticGPT 审查 ChatGPT 的代码时，其表现有 60% 的次数优于没有帮助的人。我们已开始着手将类 CriticGPT 模型整合进 RLHF 标注流水线，为训练员提供明确的 AI 辅助。这是朝“能够评估高级 AI 系统的输出”迈出的一步——若没有更好的工具，这类输出对人类来说可能难以评价。

为 ChatGPT 提供动力的 GPT-4 系列模型，通过“人类反馈强化学习”[（RLHF⁠](https://openai.com/index/chatgpt/)）被对齐为有帮助、可交互的形态。RLHF 的一个关键环节是收集比较数据：由被称为 AI 训练员的人对 ChatGPT 的多个回答相互评级。

随着我们在推理和模型行为上不断进步，ChatGPT 变得更准确，其错误也变得更隐蔽。这会令 AI 训练员在错误真的发生时难以察觉，从而使支撑 RLHF 的比较任务难度大得多。这是 RLHF 的根本性局限：随着模型逐渐比任何能提供反馈的人知识更丰富，对齐模型可能会愈发困难。

为应对这一挑战，我们训练了 **CriticGPT** 来撰写批评意见，指出 ChatGPT 回答中的不准确之处。

## CriticGPT

Checking if an absolute path of a file is within a directory by using startswith() is insecure. Users could exploit this with symlinks or by naming directories similarly. Using os.path.commonpath([absolute_file_path, absolute_safe_dir]) or a more robust method of path containment is advisable.

CriticGPT 的建议并不总是正确，但我们发现它们能帮助训练员发现模型所写回答中的更多问题——没有 AI 帮助时他们发现不了这么多。而且，当人们使用 CriticGPT 时，AI 会增强他们的能力：产出的批评比纯人工更全面，产生的幻觉 bug 也比纯模型更少。在我们的实验中，第二位随机抽取的训练员在超过 60% 的情况下更偏爱“人类+CriticGPT”团队的批评，而非无辅助个人的批评。

CriticGPT 帮助训练员写出比无辅助时更全面的批评，同时产生的幻觉比仅靠模型的批评更少。

## 方法

CriticGPT 同样使用 RLHF 训练，与 ChatGPT 类似。但与 ChatGPT 不同的是，它看到了大量含有错误的输入，并需要对它们进行批评。我们请 AI 训练员手动把错误插入 ChatGPT 编写的代码中，然后撰写示例反馈——*假装*他们刚刚发现了自己插入的那个 bug。同一个人随后对修改后代码的多条批评进行比较，从而能轻松判断某条批评是否抓住了自己插入的 bug。在实验中，我们既研究 CriticGPT 能否发现插入的 bug，也研究它能否发现由先前某位训练员抓到的“自然发生”的 ChatGPT bug。我们发现在自然发生的 bug 上，训练员在 63% 的情况下更偏爱 CriticGPT 的批评而非 ChatGPT 的批评，部分原因是新的批评模型产生更少的“挑刺”（nitpicks，即无益的小抱怨），也更少幻觉出问题。

我们还发现，通过对批评奖励模型进行额外的测试时搜索，可以生成更长、更全面的批评。这一搜索过程让我们能够平衡在代码中查找问题的激进程度，并配置幻觉与检出 bug 数量之间的精确率-召回率权衡。这意味着我们可以生成对 RLHF 尽可能有帮助的批评。更多细节见我们的研究论文。

## 局限

- 我们在相当短的 ChatGPT 回答上训练了 CriticGPT。要监督未来的 agent，我们需要开发能帮助训练员理解长而复杂任务的方法。
- 模型仍会产生幻觉，而且训练员在看到这些幻觉后有时也会犯标注错误。
- 有时现实中的错误会散布在回答的多个部分。我们的工作聚焦于可以在一处指出的错误，但未来还需要处理分散的错误。
- CriticGPT 的帮助是有限的：如果任务或回答极其复杂，即使是获得模型帮助的专家也可能无法正确评估它。

## 下一步

要对齐日益复杂的 AI 系统，我们需要更好的工具。在 CriticGPT 的研究中我们发现，把 RLHF 应用于 GPT-4 有潜力帮助人类为 GPT-4 产出更优质的 RLHF 数据。我们计划进一步扩大这项工作并付诸实践。
