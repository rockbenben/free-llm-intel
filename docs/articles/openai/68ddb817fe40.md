# 用 OpenAI 模型推动芯片设计进步

OpenAI 的模型正在快速改进支撑 AI 运行的芯片。[8 月，我们分享了⁠](https://openai.com/zh-Hans-CN/index/jalapeno-first-results/) OpenAI 工程师如何利用我们的前沿模型，加速首款定制推理芯片 Jalapeño 的开发。本文将深入介绍 Jalapeño 性能提升背后的专家级设计改进，以及我们如何与 AMD 合作，将同样的方法用于第三方硬件，实现显著提升。

为衡量模型执行端到端芯片设计任务的能力，我们在两种开源处理器设计上评估了多代模型，得到了一些有趣的发现。此外，为让模型能力的发展有可靠的评估依据，我们正与 Synopsys 合作，将前沿智能融入工程师已在使用的电子设计自动化（EDA）工具，帮助他们设计和验证芯片。

## 改进 Jalapeño 的计算模块

2025 年初，我们开始使用 GPT‑4o 辅助设计 Jalapeño。即使是这款早期模型，也找到了显著改善功耗、性能和面积（PPA）的方法，例如：

**在矢量单元中**，这个负责管理和执行并行计算任务的模块通过优化浮点加法器和乘法器、转换函数、归约逻辑及特殊函数单元，实现了资源节省。模型探索了不同的逻辑实现方式，以及如何将计算划分到各个流水线阶段，从而找到了共享硬件和减少中间存储的机会。

**在矩阵单元中**，对浮点加法器、乘法器和低精度点积电路的改进，逐步提升了这一运算模块的整体表现。其中一项乘法器重设计方案，在综合后的单元面积上节省了约 15%，同时将延迟从两个时钟周期降至一个。另一项加法器重设计方案在保持两个时钟周期延迟的同时，将单元面积减少了约 15%。对点积逻辑和流水线组织方式的进一步改进，也为整个模块带来了额外的资源节省。

纵观 Jalapeño 的整体设计工作，团队估计，模型提出的改动使矢量单元的标准单元面积减少了约 13%，矩阵单元减少了约 10%。这些优化已在 [Jalapeño 的芯片初始调试⁠](https://openai.com/zh-Hans-CN/index/jalapeno-first-results/)期间通过实硅验证。

## 我们与 AMD 的合作

我们与 AMD 合作改进 PPA，在其旗舰 GPU IP 上，相较于经过深度优化的基线，实现了最高 14% 的提升。我们的模型通过重写描述芯片电路的代码（SystemVerilog RTL），找到了进一步改进的空间。这相当于在不到 5 个月的时间里取得了约一年的进展，在芯片设计前沿领域实现了前所未有的成果。AMD 已将其中部分改动纳入最近送交制造的一项设计，并将其他改动加入量产设计文件，供未来版本使用。

我们观察到，模型对 RTL 的推理能力已达到微架构设计专家的水平。模型能够重写负责计算、控制操作或传输数据的电路。它利用 Synopsys 工具验证每次重写是否保持了模块原有的行为，并评估功耗、性能和面积之间的权衡。

AMD 还验证，在其即将推出的下一代旗舰 CPU 的多个关键模块中，采用我们的模型编写的设计，能够实现个位数百分比的 PPA 提升。展望未来，我们预计，即使以优化最充分的设计为基线，GPU 和 CPU 的 PPA 仍能进一步提升。

## 优化 RISC-V 内核

我们在 Jalapeño 和 AMD 芯片上取得的成果表明，模型能够改进量产设计。为衡量芯片设计能力如何随模型代际演进而提升，我们在两种开源 32 位 RISC-V 内核上测试了各个模型。PicoRV32 是一种紧凑型内核，专为 FPGA 这类可重复编程芯片设计。OpenTitan 在其安全芯片中采用 Ibex 作为嵌入式处理器。两者都是完整的处理器内核，面向嵌入式微控制器级工作负载。

我们向每个模型提供了各内核的原始硬件描述，并要求其提高吞吐量，即内核每秒可执行的指令数。例如，某项改动可能让内核用更少的时钟周期完成一条指令，却使每个周期耗时更长。衡量吞吐量可以同时反映这两种影响。

我们通过仿真检查了每项设计的输出。如果设计未通过某项检查，或使用的面积超过原始内核的 16 倍，则记为零分。对于通过检查的设计，我们使用未向模型公开的工作负载，测量其每个时钟周期执行的指令数。我们取这些工作负载测量结果的几何平均值，再乘以通过 Yosys 估算的最高时钟频率。由此得到每秒执行指令数的估计值。对于每种内核，我们将相同约束条件下观察到的最高吞吐量对应的分数设为 1.0。图表展示了各次运行的平均分，其中也包括得分为零的运行。

在每次运行约 112,000 个 Token 的可比预算下，GPT‑6.2 Astra 在两种内核上均获得了最高平均分。GPT‑6.1 Sol 在两种内核上的得分也都高于 GPT‑5.6 Sol。

*在优化现有 PicoRV32 内核时，GPT‑6.2 Astra 在较高的可比预算下获得了最高平均分。在约 112,000 个 Token 的预算下，其得分约为 GPT‑6 Astra 的两倍。*

*在优化现有 Ibex 内核时，随着预算进一步增加，GPT‑6.2 Astra 的平均分持续攀升。GPT‑6 Astra 与 GPT‑6.1 Sol 的得分则较为接近。*

## 根据规格设计 RISC-V 内核

在第二项任务中，我们向每个模型提供了书面需求，以及来自开源代码的模板，说明内核如何与系统的其余部分连接。模型自行决定数据在内核中的传输方式，以及如何将处理工作划分为多个阶段。对于每种内核，我们采用了与 RTL 优化任务相同的正确性检查、内存和缓存设置，以及吞吐量目标。

在每次运行约 112,000 个 Token 时，全部五个模型根据书面需求设计内核时的得分，都高于尝试改进现有设计时的得分。这一结论在 PicoRV32 和 Ibex 上均成立。GPT‑6.2 Astra 在 Ibex 上的得分明显高于在 PicoRV32 上的得分。完整评估共包含 9,881 次计分运行，涵盖两项任务、两种内核和所有 Token 预算档位。

*以 PicoRV32 规格为出发点时，GPT‑6.2 Astra 在接近 112,000 个 Token 时的平均分超过 0.7，在随后两个受测的预算档位上则取得了更高分数。*

*在 Ibex 上，以规格为设计出发点时，GPT‑6.2 Astra 在接近 112,000 个 Token 时的平均分约为 0.75。在各模型共同测试的更高预算下，其得分曲线仍高于其他模型。*

从书面需求出发，让模型省略原始内核中的某些功能，例如性能计数器和附加指令。这些功能对测试工作负载的吞吐量可能贡献不大，这或许能解释部分得分的优势。如果要求保留这些功能、对电路面积施加更严格的限制，并在物理综合后检查时序，就能让测试更贴近量产芯片设计。

## 下一步

我们已证明，模型能够在 RISC-V 评估中探索新的处理器架构，也能在 Jalapeño 及 AMD 下一代旗舰 GPU 和 CPU 等复杂成熟的量产设计基础上，做出新的实质性改进。为了以可靠的评估依据推动模型开发进程，并应对一系列设计挑战，我们正与 Synopsys 合作训练新模型 [GPT‑Synopsys](https://investor.synopsys.com/news/news-details/2026/OpenAI-and-Synopsys-Announce-GPT-Synopsys-Frontier-Intelligence-to-Revolutionize-Chip-Design/default.aspx)，使其能够像专业芯片设计师一样使用 Synopsys 的电子设计自动化 (EDA) 工具。
