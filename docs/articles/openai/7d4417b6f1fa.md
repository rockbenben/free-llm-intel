# OpenAI Baselines：ACKTR 与 A2C

插图：Ben Barry

我们发布两个新的 OpenAI Baselines 实现：ACKTR 和 A2C。A2C 是异步优势演员-评论家（A3C）的同步、确定性变体，我们发现两者表现相当。ACKTR 是比 TRPO 和 A2C 样本效率更高的强化学习算法，每次更新只比 A2C 多耗费一点点计算。

ACKTR（读音同 “actor”）——Actor Critic using Kronecker-factored Trust Region（使用 Kronecker 分解置信域的智能体-评论家）——由多伦多大学和纽约大学的研究者开发，我们 OpenAI 与他们合作发布了这个 Baselines 实现。作者们[用⁠（在新窗口打开）](https://arxiv.org/abs/1708.05144) ACKTR 学习仿真机器人的控制策略（像素输入、连续动作空间）和 Atari 智能体（像素输入、离散动作空间）。

ACKTR 结合了三种不同技术：[演员-评论家方法⁠（在新窗口打开）](https://arxiv.org/abs/1602.01783)、用于更稳定改进的[置信域优化⁠（在新窗口打开）](https://arxiv.org/abs/1502.05477)，以及用于提升样本效率与可扩展性的[分布式⁠（在新窗口打开）](https://jimmylba.github.io/papers/nsync.pdf)[Kronecker⁠（在新窗口打开）](https://arxiv.org/abs/1503.05671)[分解⁠（在新窗口打开）](https://arxiv.org/abs/1602.01407)。

## 样本与计算效率

对机器学习算法而言，有两类成本需要考虑：样本复杂度和计算复杂度。样本复杂度指智能体与环境交互的时间步数，计算复杂度指必须执行的数值运算量。

ACKTR 的样本复杂度优于 A2C 等一阶方法，因为它沿*自然梯度*方向（而非梯度方向，也不是 ADAM 那样的缩放版本）迈步。自然梯度给出参数空间中这样的方向：以 KL 散度衡量，在网络输出分布单位变化内实现目标函数（瞬时）最大改进。通过限制 KL 散度，我们确保新策略的行为不会与旧策略截然不同——后者可能导致性能崩塌。

至于计算复杂度，ACKTR 使用的 KFAC 更新每步只比标准梯度更新贵 10–25%。这与 TRPO（即无 Hessian 优化）等方法形成对比——后者需要更昂贵的共轭梯度计算。

在下面的视频中，你可以看到用 ACKTR 训练以解决 Q-Bert 游戏的智能体与用 A2C 训练的智能体在不同时间步的对比。ACKTR 智能体得分高于 A2C 训练的。

## 基线与基准

本次发布包含 ACKTR 的 OpenAI baseline 实现，以及 A2C 的实现。

我们还发布了[基准⁠（在新窗口打开）](https://github.com/openai/baselines-results)，在一系列任务上将 ACKTR 与 A2C、[PPO⁠（在新窗口打开）](https://arxiv.org/abs/1707.06347) 和 [ACER⁠（在新窗口打开）](https://arxiv.org/abs/1611.01224) 进行对比评估。下图中展示了 ACKTR 在 49 款 Atari 游戏上与其他算法（A2C、PPO、ACER）的表现对比。ACKTR 的超参数由 ACKTR 作者仅在一款游戏 Breakout 上独立调优。

ACKTR 的表现随 batch size 扩展得很好，因为它不仅从每个 batch 的信息中导出梯度估计，还用这些信息近似参数空间中的局部曲率。这一特性对使用大 batch size 的分布式大规模训练特别有利。

## A2C 与 A3C

异步优势演员-评论家方法（A3C）自[论文⁠（在新窗口打开）](https://arxiv.org/abs/1602.01783)发表以来影响巨大。该算法结合了几个关键思想：

- 一种更新机制，在固定长度的经验片段（比如 20 个时间步）上操作，用这些片段计算回报和优势函数的估计。
- 策略函数与价值函数共享层的架构。
- 异步更新。

读完论文后，AI 研究者们想知道：异步性是否带来了性能提升（例如“额外的噪声是否提供了某种正则化或探索？”），还是它只是一个让 CPU 实现训练更快的工程细节。

作为异步实现的替代，研究者发现你可以写一个同步、确定性的实现：等待每个 actor 完成其经验片段后再执行更新，并对所有 actor 取平均。这种方法的一个优势是能更高效地利用 GPU——GPU 在大 batch size 下表现最好。这个算法顺理成章地叫 A2C，即 advantage actor critic 的缩写。（该词已在[多篇论文⁠（在新窗口打开）](https://arxiv.org/abs/1611.05763)中使用。）

我们的同步 A2C 实现比异步实现表现更好——我们没有看到任何证据表明异步引入噪声能带来性能收益。在使用单 GPU 机器时，A2C 实现比 A3C 更具成本效益；在使用较大策略时，它比纯 CPU 的 A3C 实现更快。

我们在 Baselines 中包含了用 A2C 在 Atari 基准上训练前馈卷积网络和 LSTM 的代码。
