# OpenAI 与 Cisco 推出 Shirudo

一个开源运行时，无需等待补丁上线或重启服务，就能帮助运维人员保护运行中的 Linux 系统

![橙色渐变背景上的 Shirudo 标志。](https://images.ctfassets.net/kftzwdyauwt9/5K7gFDr3r8vgjdIcsW6RVY/aba5325ce7902e5d1499b907f8e78f0b/shirudo-partner-logos-landscape-2x.png?w=3840&q=90&fm=webp)

OpenAI 与 Cisco 推出开源运行时 Shirudo，帮助团队在逐步部署补丁期间保护 Linux 系统。在一项[受控测试](https://isovalent.com/blog/post/cisco-openai-shirudo/)中，由 Codex 生成的一项防护规则阻止了针对运行中 Elasticsearch 服务的 Java4Shell 漏洞利用尝试，整个过程无需重启。

我们邀请业界的开发者、安全研究人员和基础设施运维人员一起完善这个项目。项目结合 OpenAI 在前沿 AI、安全和基础设施方面的研究，以及 Cisco 在基础设施和安全方面的经验，帮助保护人们每天依赖的系统。

测试和部署补丁仍可能需要数天甚至数周。这段时间内保护服务并不容易，因为漏洞利用和正常请求可能依赖同一种 Linux 操作。把该操作一律拦截，可能导致服务中断。

Shirudo 在日语中意为“盾”，旨在帮助安全团队处理这一取舍。团队可以先测试某条临时防护规则（shield）能否阻断使漏洞可被利用的行为，同时放行合法请求。运维人员审批后，即可在服务继续运行的同时部署这条规则。

> “我们在为防御方提供更好的模型和工具，帮助他们更快地发现并修复漏洞。今天发现一个缺陷，往往来不及在明天给所有系统打好补丁。我们正与 Cisco 密切合作开发 Shirudo，帮助团队在编写和部署修复方案期间保护必须持续运行的系统。许多团队都依赖同样的软件，很适合以开放方式开发这些工具。这样一来，当某个团队发现了更好的系统防护方法，其他团队就可以直接借鉴。”

Greg Brockman，OpenAI 总裁兼联合创始人

## Shirudo 的工作原理

Shirudo 使用的 eBPF 是一项 Linux 技术，允许小型程序在操作系统内部的特定位置运行。借此，Shirudo 可以观察可疑活动，并为运行中的系统实施有针对性的安全防护。

![防护 agent 通过 eBPF 观测机制查看内核与网络活动，并通过 eBPF 控制机制施加针对性防护。](https://images.ctfassets.net/kftzwdyauwt9/bScTLq9smNJq5XAlaHIQW/fab0e70b1aab8ca8dffb70a747056fd7/guardian-agent-desktop-light.png?w=3840&q=90&fm=webp)

防护 agent 如何通过 eBPF 观测和保护运行中的系统。

OpenAI 和 Cisco 围绕四项核心能力设计 Shirudo：

- **在线防护**：eBPF 防护规则可以在无需重启系统的情况下阻断存在漏洞的代码路径。安全团队可在正式启用前观察拟部署规则对应用程序的影响。
- **以机器速度开展防御**：OpenAI 和 Cisco 正为 Shirudo 设计可编程的控制机制，让 agent 能调查漏洞、编写有针对性的防护规则，并验证规则对漏洞利用与真实工作负载的效果。实际部署哪些规则由安全团队决定。
- **可信部署**：防护规则加载前须经加密签名和验证。Linux eBPF 验证器按安全规则检查 eBPF 程序，内核安全机制限制未经授权的变更。
- **硬件支持的验证**：Shirudo 使用可信平台模块（TPM），为防护规则的加载与移除提供可验证记录。运维人员可以根据这些证据确认系统是否符合安全要求。

Linux Plumbers Conference 的 [Shirudo 技术演示](https://lpc.events/event/20/contributions/2437/)展示了如何[在目标主机上应用并验证防护规则](https://www.youtube.com/watch?v=4v2xA_NJHt0)。Java4Shell 漏洞也说明了在永久补丁准备期间，针对性的防护规则如何保护运行中的应用。团队用 OpenAI 的 Codex 生成了一条防护规则，为 Java 的 Base64 解码器增加输入检查，并将规则直接挂接到运行中的 Elasticsearch 进程。测试人员尝试利用漏洞时，规则拒绝了恶意输入，阻止了攻击，Elasticsearch 同时保持运行。更多细节见[测试说明](https://isovalent.com/blog/post/cisco-openai-shirudo/)。

## 重新思考基础设施

Shirudo 是迈向一种既能适应新出现的威胁、又能保持可靠性的基础设施的第一步。我们希望加强大规模部署此类防护所需要的操作系统基础，包括加固内核和核心服务、限制工作负载的权限，并提升更新和恢复的安全性。

我们的长期目标是让防御方和 AI agent 能迅速识别受影响的系统、验证防护措施，并部署可阻止漏洞利用且不干扰工作负载的 eBPF 防护规则。应用应当只持有运行所需的权限，由自动生成并维护的策略约束。

我们将把前沿 AI 与安全和基础设施研究结合起来，发现漏洞并用贴近实际的攻击场景检验防御措施。我们的目标是让运维人员更容易发现并遏制入侵，防止攻击者在不同系统之间横向移动，并将服务恢复到经验证的已知良好状态。即使个别系统失陷，硬件支持的证明机制和独立的网络控制也能提供额外保障。

## 公开开发

OpenAI 与 Cisco 正在开源 [Shirudo](https://github.com/shirudo-dev/shirudo)，让开发者、安全研究人员和基础设施运维人员可以审查代码、测试防护措施并参与开发。Shirudo 使用 BSD 2-Clause 许可证，其 BPF 程序采用 BSD 与 GPL 双重许可。

我们的目标是在披露漏洞的同时提供经过测试的防护规则，让运维人员在准备永久补丁期间能够评估和部署临时防护。

- **试用 Shirudo**：按[虚拟机快速入门指南](https://docs.shirudo.dev/start/quickstart.html)签名、加载和验证一条测试规则。
- **动手体验**：通过 [Isovalent 的自助实验](https://labs.isovalent.com/#/lab/shirudo-getting-started)了解 Shirudo。
- **深入了解技术**：报名参加 [12 月 15 日的线上研讨会](https://isovalent.site/4t8Pjxc)。

我们正与开发、运行和保护 Linux 系统的人一起公开开发 Shirudo。欢迎大家为运行时、新的防护规则以及 Linux 和 eBPF 的改进作出贡献。如果你想参与，欢迎查看 [GitHub 上的代码](https://github.com/shirudo-dev/shirudo)，阅读[文档](https://docs.shirudo.dev/index.html)，并[向我们反馈你的发现](https://docs.shirudo.dev/contribute/support.html)。
