# OpenAI 与 Cisco 推出 Shirudo

一个开源运行时，帮助运维人员保护正在运行的 Linux 系统，而无需等待补丁或重启

![橙色渐变背景上的 Shirudo 标志。](https://images.ctfassets.net/kftzwdyauwt9/5K7gFDr3r8vgjdIcsW6RVY/aba5325ce7902e5d1499b907f8e78f0b/shirudo-partner-logos-landscape-2x.png?w=3840&q=90&fm=webp)

OpenAI 与 Cisco 正在推出 Shirudo，这是一个开源运行时，可帮助团队在逐步推出补丁期间保护 Linux 系统。在一项[受控测试](https://isovalent.com/blog/post/cisco-openai-shirudo/)中，由 Codex 生成的 shield 阻止了针对正在运行的 Elasticsearch 服务的 Java4Shell 漏洞利用尝试，且无需重启。

我们邀请整个行业的开发者、安全研究人员和基础设施运维人员帮助进一步发展该项目。该项目汇集了 OpenAI 的前沿 AI、安全与基础设施研究，以及 Cisco 的基础设施和安全专业知识，以帮助保护人们每天依赖的系统。

测试和部署补丁仍可能需要数天或数周。在此期间保护服务可能颇具挑战，因为漏洞利用和合法请求可能依赖相同的 Linux 操作。完全阻止该操作可能会导致服务离线。

Shirudo（日语意为“盾牌”）旨在帮助安全团队权衡这一取舍。团队可以测试一种称为 shield 的临时防护措施是否能阻止暴露漏洞的行为，同时允许合法请求通过。一旦运维人员批准该 shield，就可以在服务继续运行的同时部署它。

> “我们正在为防御者提供更好的模型和工具，以更快地发现和修复漏洞，但今天发现一个 bug 并不意味着明天就能给每个系统打上补丁。我们正与 Cisco 在 Shirudo 上紧密合作，帮助团队在构建和推出修复程序期间保护那些必须保持运行的系统。如此多的团队依赖相同的软件，因此以开放方式构建这些工具是合理的。现在，当一个团队找到更好的系统保护方法时，其他团队不必从零开始。”

OpenAI 总裁兼联合创始人 Greg Brockman

## Shirudo 的工作原理

Shirudo 使用 eBPF，这是一种 Linux 技术，允许小型程序在操作系统内部的特定位置运行。这使得可以观察可疑活动，并对正在运行的系统应用有针对性的安全防护。

![guardian agent 使用 eBPF 探针观察内核和网络活动，并使用 eBPF 控制措施应用有针对性的防护。](https://images.ctfassets.net/kftzwdyauwt9/bScTLq9smNJq5XAlaHIQW/fab0e70b1aab8ca8dffb70a747056fd7/guardian-agent-desktop-light.png?w=3840&q=90&fm=webp)

guardian agent 如何使用 eBPF 观察并保护正在运行的系统。

OpenAI 与 Cisco 围绕四项核心能力设计 Shirudo：

- **实时防护：** eBPF shields 可以阻止易受攻击的代码路径，而无需重启系统。安全团队可以在强制执行拟议的 shield 之前，监控它会对应用程序产生什么影响。
- **以机器速度防御：** OpenAI 与 Cisco 正设计 Shirudo，使 agents 具备可编程控制能力，以调查漏洞、开发有针对性的 shields，并针对漏洞利用和真实工作负载验证其有效性。由安全团队控制部署内容。
- **可信部署：** Shields 在加载前会经过加密签名和验证。Linux 的 eBPF 验证器会依据其安全规则检查 eBPF 程序，而内核安全控制会限制未经授权的更改。
- **硬件支持的验证：** Shirudo 使用 Trusted Platform Module（TPM）来支持对防护措施的加载或移除进行可验证记录。运维人员可以使用这些证据来检查系统是否满足其安全要求。

来自 Linux Plumbers Conference 的 [Shirudo 技术演示](https://lpc.events/event/20/contributions/2437/)展示了如何[应用 shield 并在目标主机上验证它](https://www.youtube.com/watch?v=4v2xA_NJHt0)。Java4Shell 漏洞是另一个示例，说明有针对性的 shield 如何在准备永久补丁期间保护正在运行的应用程序。使用 OpenAI 的 Codex，团队生成了一个 shield，它向 Java 的 Base64 解码器添加了输入检查，并将其直接附加到正在运行的 Elasticsearch 进程。当尝试利用该漏洞时，shield 拒绝了恶意输入，阻止了攻击，同时 Elasticsearch 继续运行。你可以[在此处](https://isovalent.com/blog/post/cisco-openai-shirudo/)了解更多信息。

## 重新思考基础设施

Shirudo 是迈向能够适应新兴威胁同时保持可靠性的基础设施的第一步。我们希望强化大规模部署这些防护所需的操作系统基础，包括加固内核和核心服务、限制工作负载权限，以及让更新和恢复更安全。

我们的长期目标是使防御者和 AI agents 能够快速识别受影响的系统、验证防护措施，并部署阻止漏洞利用而不干扰工作负载的 eBPF shields。应用程序应仅以所需的权限运行，并由自动生成和维护的策略进行治理。

我们将把前沿 AI 与安全及基础设施研究结合起来，以发现漏洞并针对现实攻击测试防御措施。我们旨在让运维人员更容易检测和遏制入侵，防止攻击者在系统间移动，并将服务恢复到经过验证的已知良好状态。即使个别系统被攻陷，硬件支持的证明和独立网络控制也能提供额外保障。

## 开放构建

OpenAI 与 Cisco 正在开源 [Shirudo](https://github.com/shirudo-dev/shirudo)，以便开发者、安全研究人员和基础设施运维人员检查代码、测试防护措施并为其开发做出贡献。Shirudo 采用 BSD 2-Clause 许可证，其 BPF 程序采用 BSD 和 GPL 双许可证。

我们的目标是在披露漏洞的同时提供经过测试的 shields，让运维人员在准备永久补丁期间有办法评估和部署临时防护措施。

- **试用 Shirudo：** 按照 [VM 快速入门](https://docs.shirudo.dev/start/quickstart.html)签名、加载并验证一项测试防护。
- **动手实践：** 通过 [Isovalent 的自助实验室](https://labs.isovalent.com/#/lab/shirudo-getting-started)探索 Shirudo。
- **参加技术深入探讨：** 注册 [December 15 网络研讨会](https://isovalent.site/4t8Pjxc)。

我们正与构建、运行和保护 Linux 系统的人们一起公开构建 Shirudo。我们欢迎对运行时和新 shields 的贡献，也欢迎对 Linux 和 eBPF 的改进。如果你想参与，请查看 [GitHub 上的代码](https://github.com/shirudo-dev/shirudo)，阅读[文档](https://docs.shirudo.dev/index.html)，并[告诉我们你的发现](https://docs.shirudo.dev/contribute/support.html)。
