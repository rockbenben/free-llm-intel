# 推出适用于“ChatGPT 工作”和 Codex 的管理员插件

在同一对话中了解工作空间活动、管理访问权和用量，并执行受支持的管理操作

我们现推出适用于[“ChatGPT 工作”⁠（在新窗口中打开）](https://chatgpt.com/?openaicom_referred=true)和 [Codex⁠（在新窗口中打开）](https://chatgpt.com/codex/?openaicom_referred=true) 的管理员插件，让你能更快捷、更轻松地分析工作空间信息、更新设置并处理请求。管理员可以在同一对话中提出问题、深入了解详情、执行获授权的更改并确认结果，无需编写复杂的提示词，也无需在不同工具之间切换。

管理不断扩大的工作空间，往往需要在分析、设置和报告之间反复切换，才能了解问题并采取行动。这会拖慢日常管理工作，也使其更难始终如一地完成。管理员插件将管理分析与受支持的操作整合起来，帮助团队在工作空间不断扩大的同时，确保其安全、高效且不超预算。

## 帮助管理员管理不断扩大的工作空间

借助管理员插件，管理员可以直接通过“ChatGPT 工作”和 Codex 完成日常任务，包括但不限于：

- **了解采用情况和使用情况。**查看“ChatGPT 工作”和 Codex 的活动与额度使用情况，识别哪些方面可能需要进一步提供支持，以及成员或群组何时接近额度上限。
- **管理成员和群组。**添加或移除成员、更新群组，并完成常规的入职、离职和团队变更。
- **管理访问权和权限。**查看实际权限、诊断访问问题，并按角色或群组控制功能或模型的访问权。
- **管理用量上限和支出请求。**调整成员、群组和工作空间的上限，结合当前使用情况审核请求，并根据相关信息批准或拒绝请求。

## 自动执行重复性管理工作流程

管理员还可以使用管理员插件自动执行重复性检查和大量请求，无需定制开发。这些自动化功能可以减少人工监控，更一致地执行政策，让管理员专注于需要其判断的决策。

例如，该插件可以将待处理的用量请求转发到 Slack 或 Microsoft Teams，让获授权的审核人员直接在日常使用的工具中批准或拒绝请求。它还可以监控功能访问请求，在请求符合预设条件时自动授予访问权，同时将例外情况转交审核。管理员始终掌控全程，每个工作流程都会在所请求的更改应用后发出确认。

## 利用现有控制机制扩展管理规模

管理员插件在每位用户现有的角色和权限范围内运行，不会授予更广泛的访问权。处理每项请求时，插件会将管理员的指令映射到适当且受支持的读取或写入操作，并返回结构化结果。它将管理控制台的功能以权限感知型工具的形式提供给“ChatGPT 工作”和 Codex，同时遵循工作空间政策和审批要求。

对于每项更改，管理员都可以查看自己提出了什么请求、操作是否完成以及具体发生了哪些变化。影响范围较广的操作可在应用前由管理员审核。

## OpenAI IT 团队如何使用“ChatGPT 工作”和 Codex

管理员插件改变了 OpenAI IT 团队着手管理工作空间的方式。借助该插件，团队只需提出问题，即可深入分析数据并生成报告和洞察。

> “它的价值远不止加快报告生成。管理员插件将问题与下一步受支持的操作衔接起来，无论是检查某人的实际权限、更新群组、更改用量上限，还是审核支出请求。它让管理员能够更快了解情况并采取行动，同时保留我们现有的权限和控制机制。”

— Kunal Malik，OpenAI 全球 IT 负责人

管理员插件体现了 OpenAI IT 团队使用“ChatGPT 工作”和 Codex 的方式正在发生更广泛的转变。OpenAI IT 团队利用这些工具，将相关上下文和工作流程汇集到一处。

- 在 Slack 中，“ChatGPT 工作”智能体负责处理员工的 IT 请求、分流并处理支持工单、检索上下文、核查已批准的政策、完成受支持的任务，并上报例外情况。截至报告发布时，已部署的工作流程解决了约 45% 的工单
- “ChatGPT 工作”可将支持工单数据和历史记录转化为运营状况仪表板，让 IT 团队持续掌握服务表现。这种可见性帮助团队清除了积压工单，也改变了团队的工作方式。即使支持请求量大约翻了一番，团队也不再被动应对服务问题，而是利用实时数据确定优先级并根据需求进行规划。

## 安装适用于“ChatGPT 工作”的管理员插件

只需几个简单步骤即可开始使用该插件。首先在 ChatGPT 工作空间设置中启用该插件，然后从“ChatGPT 工作”网页版或桌面应用的“插件”目录中安装该插件。安装后，管理员可以更快速、更一致地处理日常工作空间任务。
