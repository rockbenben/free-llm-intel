# Braintrust 如何借助 Codex 将客户请求转化为代码

Braintrust 工程师结合使用 Codex 和 GPT‑5.5，在几分钟内将客户功能请求转化为预览分支，并拓展工程实验范围。

**Braintrust 是用于交付高质量 AI 产品的可观测性与评测平台。**

借助 Codex，其工程师现在可以接收客户功能请求，并创建预览分支，在几分钟内向客户展示可运行的想法。

一个月内，Braintrust 团队有一半成员转向使用 Codex。对于创始人兼首席执行官 Ankur Goyal 来说，最大的变化不只是编码更快。而是与客户之间更快的反馈循环。

“这听起来很简单，但 Codex 确实可以在终端中输出更多文本而不会变慢，其他模型就是无法复制这一点，”Goyal 说。

> “最大的提升是速度。”

—Ankur Goyal，创始人兼首席执行官

## 在几分钟内将客户请求转化为预览

速度常被视为工具的一项属性，仿佛它独立于核心功能之外，但对 Goyal 来说，这种速度差异“改变了我与 Codex 互动的方式，相比其他模型完全不同”。

借助 Codex，Braintrust 团队可以将迭代融入开发工作流，而不是让请求搁置等待。“Codex 让我们能够实时尝试客户的功能请求，”Goyal 说。“过去，如果有人向我们提出功能请求，它会进入待办事项列表，之后再进行优先级排序。”

现在，团队可以将请求复制粘贴到 Codex 中，创建预览分支，并在几分钟内向客户展示已完成的请求。“Codex 真正酷的地方在于，我们可以与客户实时围绕功能请求进行迭代和构思，”Goyal 说。

> “我们写的代码越多，就能解决越多客户问题，而 Codex 是目前实现这一点最有效的方式。”

—Ankur Goyal，创始人兼首席执行官

## 速度让自主解决问题成为可能

对 Goyal 来说，Codex 改变了尝试新想法所需的准备工作量。“使用其他模型时，我必须尝试通过提示让模型解决某个具体问题，”他说。速度较慢的工具需要更多人工指导，这会提高实验成本。

“使用 Codex 后，我转而编写一个能展示问题的测试，创建沙盒环境，然后让 Codex 在该环境中运行，”Goyal 说。“这对我来说是一个新的用例，而我能够因为速度而开展实验。”

这种速度给了 Braintrust 团队更多实验空间。工程师不再需要一步步提示，而是可以定义问题，让 Codex 在受控环境中工作，并更快地从想法推进到可运行的解决方案。

> “Codex 真正酷的地方在于，我们可以与客户实时围绕功能请求进行迭代和构思。”

—Ankur Goyal，创始人兼首席执行官
