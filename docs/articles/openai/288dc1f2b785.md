# 用稀疏 Transformer 做生成建模

我们开发了稀疏 Transformer（Sparse Transformer）——一种深度神经网络，在预测序列中的下一个元素（无论文本、图像还是声音）上创下新纪录。它用*注意力*机制的算法改进，从比此前可能长度大 30 倍的序列中提取模式。

AI 研究的一个既有挑战，是对图像、视频、声音等复杂数据中长程、微妙相互依赖关系的建模。稀疏 Transformer 将 [Transformer⁠（在新窗口中打开）](https://ai.googleblog.com/2017/08/transformer-novel-neural-network.html)自注意力机制从 O(N²) 重构为 O(N√N)，并加上若干其他改进，使其能直接应用于这些丰富的数据类型。此前用于这类数据的模型要么为单一领域专门打造，要么难以扩展到几千个元素以上的序列。相比之下，我们的模型能用数百层对数以万计元素的序列建模，在多个领域取得最先进性能。在 OpenAI，我们正用它帮助构建具有更强世界理解能力的 AI 系统。

## 深层注意力

在 Transformer 中，每个输出元素都连接到每个输入元素，它们之间的权重根据情境动态计算，这一过程称为*注意力*。虽然相信这使 Transformer 比固定连接模式的模型更灵活，但实践中它需要为每一层、每个注意力头创建一个 N×N 的*注意力矩阵*，用在图像或原始音频这类元素很多的数据类型上会消耗大量内存。

| **数据类型** | **存储** | **重算** |
| --- | --- | --- |
| 1024 text tokens (several paragraphs) | 1.0 GB | 16 MB |
| 32x32x3 pixels (CIFAR-10 image) | 9.6 GB | 151 MB |
| 64x64x3 pixels (Imagenet 64 image) | 154 GB | 2.4 GB |
| 24,000 samples (~2 seconds of 12 kHz audio) | 590 GB | 9.2GB |

*深层 Transformer（64 层、4 头）在矩阵存储于内存中、或反向传播时重算两种情况下的注意力内存占用。作为参照，用于深度学习的标准 GPU 内存通常只有 12–32 GB。*

降低占用的一种方式，是在反向传播期间从*检查点*重算注意力矩阵——这是深度学习中以更多计算换更少内存的成熟技术。对 Transformer 的注意力矩阵这样做之后，最大内存开销便与层数无关，让我们能训练比以往深得多的网络。实践中，我们发现深达 128 层的 Transformer 在 CIFAR-10 等基准任务上优于较浅的网络。

为训练这些深度增加的模型，我们对 Transformer 中运算顺序做了若干调整，并修改了初始化方案。完整细节见论文。

## 稀疏注意力

不过，即使只计算单个注意力矩阵，对超大输入也可能不可行。我们改用稀疏注意力模式：每个输出位置只从输入位置的一个子集计算权重。当子集相对全体输入很小（比如取 √N 个元素而不是 N 个），所得的注意力计算即便对超长序列也变得可行，算法复杂度从 O(N²) 降为 O(N√N)。

为评估该方法的可行性，我们首先可视化了深层 Transformer 在图像上学到的注意力模式，发现许多模式呈现可解释、结构化的稀疏形态。下面每张图展示某个注意力头为预测图像中的下一个值而关注哪些输入像素（高亮为白色）。当输入部分聚焦于小子集并呈现高度规律时，该层适合稀疏化。以下是 CIFAR-10 图像上一个 128 层模型的部分抽样：

虽然许多层呈现稀疏结构，也有些层明显表现出覆盖整张图像的动态注意力。为保留网络学习这类模式的能力，我们实现了注意力矩阵的二维分解：通过两步稀疏注意力，网络可以关注所有位置。

第一种形式*strided*（步进）注意力，大致等价于每个位置关注自己所在行和列，与上面网络学到的注意力模式相似。（列注意力可以等价地表述为关注转置矩阵的行。）第二种形式*fixed*（固定）注意力，关注某一固定列以及最新列元素之后的元素，我们发现这种模式在数据不适合二维结构（如文本）时很有用。更多细节请读者参阅论文。

## 实验结果

稀疏 Transformer 在 CIFAR-10、Enwik8 和 Imagenet 64 的密度估计上创出新的最先进成绩。

| **CIFAR10** | **Bits per dim** |
| --- | --- |
| PixelCNN++ (Salimans et al, 2017) | 2.92 |
| Image Transformer (Parmar et. al, 2018) | 2.90 |
| PixelSNAIL (Chen et al., 2017) | 2.85 |
| Sparse Transformer 59M (256W, 128L, 2H) | 2.80 |

| **Enwik8** | **Bits per byte** |
| --- | --- |
| Deeper Self-Attention (Al-Rfou et al, 2018) | 1.06 |
| Transformer-XL 88M (Dai et al., 2018) | 1.03 |
| Transformer-XL 277M (Dai et al., 2018) | 0.99 |
| Sparse Transformer 95M (512W, 30L, 8H) | 0.99 |

| **ImageNet 64x64** | **Bits per dim** |
| --- | --- |
| Gated PixelCNN (van den Oord et al, 2016) | 3.57 |
| Parallel Multiscale (Reed et al, 2017) | 3.7 |
| SPN 150M (Menick & Kalchbrenner, 2018) | 3.52 |
| Sparse Transformer 152M (512W, 48L, 16H) | 3.44 |

*各类基准数据集上以每字节（或每维）比特计数的密度建模性能。M 表示网络参数百万数，W 为网络宽度，L 为层数，H 为头数。*

我们还发现，稀疏注意力不仅显著更快，损失也低于全注意力（对比见论文）。这可能说明我们的稀疏模式带来了有用的归纳偏置，或稠密注意力存在潜在的优化问题。

## 代码发布

通常，实现稀疏注意力需要对 query 和 key 矩阵按块切片。为便于实验，我们实现了一组[分块稀疏 kernel⁠](https://openai.com/index/block-sparse-gpu-kernels/)，在 GPU 上高效执行这些运算。我们开源这些 kernel，并在[该仓库⁠（在新窗口中打开）](https://github.com/openai/sparse_attention)提供稀疏注意力示例函数。

## 未来工作与局限

- 我们引入的稀疏注意力模式，只是朝高效长序列建模方向迈出的初步步骤。我们认为探索不同的稀疏模式及其组合很有价值，而学习稀疏模式是下一代神经网络架构研究中特别有前景的方向。
- 即使有上述改进，对超高分辨率图像或视频，自回归序列生成似乎仍不实际。不过我们引入的优化注意力运算，或许是有用的构件，可与多尺度方法等其他高维数据建模思路结合。
