# Universe 平台

我们发布 Universe：一个软件平台，用于在海量游戏、网站和其他应用中测量并训练 AI 的通用智能。

查看代码



Universe 让 AI [agent](https://en.wikipedia.org/wiki/Intelligent_agent) 像人一样使用电脑：通过看屏幕像素，并操作虚拟键盘和鼠标。我们必须在预期 AI 系统要解决的全部任务范围上训练它们，而 Universe 让我们可以用单个 agent 去训练人类能用电脑完成的任何任务。

4 月，我们[发布了 Gym⁠](https://openai.com/index/openai-gym-beta/)，一个用于开发和比较[强化学习⁠](https://openai.com/index/openai-gym-beta/#rl)（RL）算法的工具包。有了 Universe，任何程序都能变成一个 Gym 环境。Universe 的工作方式是自动在 [VNC](https://en.wikipedia.org/wiki/Virtual_Network_Computing) 远程桌面后启动那个程序——它不需要获取程序内部状态、源代码或 bot API 的特殊权限。

本次发布包含一千个[环境](https://universe.openai.com/envs)，包括 [Flash 游戏](https://universe.openai.com/envs#flash_games)、[浏览器任务](https://universe.openai.com/envs#world_of_bits)，以及 [slither.io](https://slither.io/) 和 [GTA V](https://en.wikipedia.org/wiki/Grand_Theft_Auto_V) 这样的游戏。其中数百个可以直接用于强化学习，几乎所有都可以用 [universe](https://github.com/openai/universe) Python 库免费运行，方法如下：

我们的[目标⁠](https://openai.com/index/openai-technical-goals/#goal4) 是开发一个 AI agent，它能灵活地把在 Universe 环境上积累的经验用于快速掌握陌生而困难的环境——这将是迈向通用智能的重要一步。你可以通过很多方式[帮忙⁠](https://openai.com/index/universe/#help)：把你的游戏授权给我们、在 Universe 任务上训练 agent、（即将）接入新游戏，或者（即将）玩这些游戏。

## 背景

人工智能领域在过去几年进展很快。计算机如今能够以前所未有的准确率[看](https://karpathy.github.io/2014-09-02/what-i-learned-from-competing-against-a-convnet-on-imagenet/)、[听](https://www.technologyreview.com/s/544651/baidus-deep-learning-system-rivals-people-at-speech-recognition/) 并[翻译](https://research.googleblog.com/2016/11/zero-shot-translation-with-googles.html) 语言。它们也在学习[生成图像⁠](https://openai.com/index/generative-models/)、[声音](https://deepmind.com/blog/wavenet-generative-model-raw-audio/) 和[文本](https://karpathy.github.io/2015-05-21/rnn-effectiveness/)。一个强化学习系统 [AlphaGo](https://deepmind.com/research/alphago/) 击败了围棋世界冠军。然而，尽管有这些进展，我们构建的系统仍然属于"窄 AI"——它们能在某个特定领域达到超人表现，却缺乏在这个领域之外做出任何合理行为的能力。比如，AlphaGo 能轻松在围棋上打败你，但你没法向它解释另一个棋盘游戏的规则并指望它陪你玩。

具有通用问题求解能力的系统——某种接近人类常识的东西，让 agent 能快速解决一个全新的困难任务——仍然遥不可及。一个显而易见的挑战是：我们的 agent 不会带着自己的经验进入新任务。在标准训练流程里，我们把 agent 从零初始化，让它们在数千万次尝试中随机抽搐，直到学会重复那些恰好带来奖励结果的动作。如果要在通用智能 agent 上取得进展，我们必须让它们经历足够多样的任务，这样它们才能发展出世界知识和问题求解策略，并在新任务中被高效复用。

## Universe 基础设施

Universe 通过一个统一接口暴露范围很广的环境：agent 操作一个远程桌面，观察屏幕像素并产生键盘和鼠标指令。环境暴露一个 VNC 服务器，[universe](https://github.com/openai/universe) 库则把 agent 变成 VNC 客户端。

我们设计 universe 的目标是：让单个 Python 进程以每秒 60 帧同时驱动 20 个环境。每块屏幕缓冲区是 1024x768，所以如果用笨办法从外部进程读每一帧，需要 3GB/s 的内存带宽。我们用 Go 写了一个批量化的 [VNC 客户端](https://github.com/openai/go-vncdriver)，它以共享库的形式加载进 Python，为每个环境增量更新一对缓冲区。在试过各种 VNC 服务器、编码方式和未公开的协议选项组合之后，我们现在能常规地以每秒 60 帧驱动几十个环境，延迟 100 毫秒——延迟几乎全部来自服务器端编码。

以下是我们当前实现的一些重要特性：

**通用**。agent 可以用这个接口（它最初是为人设计的）与任何已存在的计算机程序交互，不需要模拟器，也不需要访问程序内部。例如，它可以玩任何电脑游戏、与终端交互、浏览网页、在 CAD 软件里设计建筑、操作图片编辑程序，或者编辑电子表格。

**人类熟悉**。由于人们早已精通"像素/键盘/鼠标"这套接口，人类可以轻易操作我们的任何环境。我们可以把人类表现作为一个有意义的基线，并且只靠保存 VNC 流量就能记录人类示范。我们发现，用行为克隆（behavioral cloning，即用有监督学习模仿人的操作）先把 agent 初始化成一套合理的策略，再切换到 RL 去优化给定奖励函数，效果极好。

**把 VNC 当标准**。网上有大量 VNC 实现，有些默认打包进了最常见的操作系统（包括 OSX）。甚至有 [JavaScript 版的 VNC](https://kanaka.github.io/noVNC/)，让人不用安装任何新软件就能提供示范——这对 Amazon Mechanical Turk 这类服务很重要。

**容易调试**。我们可以在 agent 训练或评估时观察它——只要把一个 VNC 客户端接到环境的（共享）VNC 桌面上即可。我们也可以保存 VNC 流量供后续分析。

我们所有人都很惊讶 VNC 居然能工作得这么好。随着我们扩展到更大的游戏，很可能要开始使用额外的后端技术。但初步迹象表明现有实现还能推得很远：设置得当的话，我们的客户端能让 GTA V 通过公共互联网以每秒 20 帧运行。

## 环境

我们已经把大量环境接入 Universe，并把它们只当作起点。每个环境被打包成一个 Docker 镜像，并托管两个与外界通信的[服务器](https://github.com/openai/universe/blob/master/doc/protocols.rst)：发送像素、接收键盘/鼠标指令的 VNC 服务器，以及发送强化学习任务奖励信号（也包括文本等辅助信息）并接收控制消息（例如要运行的具体环境 ID）的 WebSocket 服务器。

### Atari 游戏

Universe 包含来自 Arcade Learning Environment 的 Atari 2600 游戏。这些环境现在在 [quay.io/openai/universe.gym-core](https://quay.io/openai/universe.gym-core) Docker 镜像内异步运行，agent 需要通过网络连接，这意味着 agent 必须处理延迟和低帧率。在云上的本地网络里跑，我们通常看到每秒 60 帧、观测延迟 20ms、动作延迟 10ms；走公共互联网则降到每秒 20 帧、观测延迟 80ms、动作延迟 30ms。

### Flash 游戏

我们把 Flash 游戏作为扩展 Universe 的起点——它们在互联网上无处不在，画面普遍比 Atari 更丰富，但单个来看仍然简单。我们已经筛过 3 万多个，估计总量还要多一个数量级。

Universe 首个发布版本包含 1000 个 Flash 游戏（其中 100 个带奖励函数），我们在取得权利人同意后，通过 [quay.io/openai/universe.flashgames](https://quay.io/openai/universe.flashgames) Docker 镜像分发它们。这个镜像会启动一个 [TigerVNC](http://tigervnc.org/) 服务器，并拉起一个 Python 控制服务器；后者用 [Selenium](http://www.seleniumhq.org/) 打开一个 Chrome 浏览器，指向容器内含目标游戏的页面，并自动点完开始游戏所需的菜单。

**提取奖励**。没有奖励函数的环境可以用于无监督学习或生成人类示范，但 RL 需要奖励函数。与 Atari 游戏不同，我们没法直接从进程内存里读出成功标准，因为各游戏存储这些信息的方式差异太大。好在很多游戏屏幕上有个分数，可以拿来当奖励函数——前提是我们能解析它。现成的 [OCR](https://en.wikipedia.org/wiki/Optical_character_recognition)（如 [Tesseract](https://github.com/tesseract-ocr/tesseract)）在标准字体、干净背景上表现很好，但遇到许多游戏里那些五花八门的字体、移动背景、炫目动画和遮挡物就吃力了。我们开发了一个基于卷积神经网络的 OCR 模型，跑在 Docker 容器的 Python 控制器里，解析分数（通过 VNC 自环维护的屏幕缓冲区），并通过 WebSocket 通道把它传给 agent。

### 浏览器任务

人类集体把互联网建成了一座供视觉消费的巨大信息宝库。Universe 包含基于浏览器的环境，要求 AI agent 像人一样阅读、导航和使用网页——用像素、键盘和鼠标。

今天，我们的 agent 主要在学习如何与常见的界面元素交互，比如按钮、列表和滑块；但未来它们可以完成复杂任务，例如上网查自己不知道的东西、管理你的邮件或日历、完成 [Khan Academy](https://www.khanacademy.org/) 的课程，或者做 Amazon Mechanical Turk 和 [CrowdFlower](https://www.crowdflower.com/) 上的任务。

**Mini World of Bits**。我们首先想做一个新的基准，用一个简单的设定抓住浏览器交互的关键挑战。我们把这份基准叫做 [Mini World of Bits](http://universe.openai.com/envs#world_of_bits)。我们把它看作 [MNIST](http://yann.lecun.com/exdb/mnist/) 的对应物，并相信掌握这些环境能提供有价值的信号，指向那些在完整网站和更复杂任务上也能表现良好的模型与训练技术。我们最初的 Mini World of Bits 基准由 80 个环境组成，从简单（例如点击某个指定按钮）到困难（例如在模拟邮件客户端里回复某个联系人）都有。

## 运行一个环境

尽管环境种类繁多，运行 Universe 环境只需要极少的准备。你只需要安装 [Docker](https://docs.docker.com/engine/installation/) 和 [universe](https://github.com/openai/universe)：

#### Plain Text

```
1$ git clone https://github.com/openai/universe && pip install -e universe
```

我们会把一组相似环境打包进一个"runtime"（运行时），它是一个暴露两个端口的服务器：5900（用于 VNC 协议，交换像素/键盘/鼠标）和 15900（用于 WebSocket 控制[协议](https://github.com/openai/universe/blob/master/doc/rewarder.md)）。例如，[quay.io/openai/universe.flashgames](https://quay.io/openai/universe.flashgames) 这个 Docker 镜像就是一个运行时，可以服务许多不同的 Flash 游戏环境。

**启动一个运行时**。你可以在命令行里用下面的方式启动你的第一个运行时：

#### Plain Text

```
1# -p 5900:5900 and -p 15900:15900 expose the VNC and WebSocket ports2# --privileged/--cap-add/--ipc=host needed to make Selenium work3$ docker run --privileged --cap-add=SYS_ADMIN --ipc=host \4    -p 5900:5900 -p 15900:15900 quay.io/openai/universe.flashgames
```

这会下载并运行 Flash 游戏的 Docker 容器。你可以把自己的 VNC 查看器连到 5900 端口来查看和控制这个远程桌面，例如通过 [TurboVNC](https://sourceforge.net/projects/turbovnc/)，或者用 15900 端口上网页服务器提供的基于浏览器的 [VNC 客户端](http://127.0.0.1:15900/viewer/?password=openai)。默认密码是 openai。OSX 也自带原生 VNC 查看器，在终端里运行 open vnc://localhost:5900 即可访问。（遗憾的是，OSX 的查看器没有实现 Tight 编码，而对较大的游戏来说那是最佳选择。）

**写你自己的 agent**。你可以用自己喜欢的框架（如 [TensorFlow](https://www.tensorflow.org/) 或 [Theano](http://deeplearning.net/software/theano/)）相当容易地写出自己的 agent。（我们提供了一个 TensorFlow 起步 [agent](https://github.com/openai/universe-starter-agent)。）在每一个时间步，agent 的观测包含一个 NumPy 像素数组，而 agent 必须发出一串 VNC 事件（鼠标/键盘动作）。例如，下面这个 agent 会启动 Dusk Drive 并一直按前进：

#### Plain Text

```
1import gym2import universe # register Universe environments into Gym34env = gym.make('flashgames.DuskDrive-v0') # any Universe [environment ID](https://github.com/openai/universe/blob/master/universe/__init__.py#L297) here5# If using docker-machine, replace "localhost" with your Docker IP6env.configure(remotes="vnc://localhost:5900+15900")7observation_n = env.reset()89while True:10  # agent which presses the Up arrow 60 times per second11  action_n = [[('KeyEvent', 'ArrowUp', True)] for _ in observation_n]12  observation_n, reward_n, done_n, info = env.step(action_n)13  env.render()
```

你可以保留自己的 VNC 连接，看着 agent 玩，甚至可以在一个"人 + agent 协作"模式下与 agent 同时使用键盘和鼠标。

**环境管理**。由于环境是以服务器进程运行的，它们可以跑在远程机器上，可能在集群内部，甚至可以通过公共互联网。我们文档里列了几种管理[远程](https://github.com/openai/universe/blob/master/doc/remotes.rst) 运行时的方式。在 OpenAI，我们用一个"allocator"（分配器）HTTP 服务，按需在一个 [Kubernetes](http://kubernetes.io/) 集群上开通运行时，用它就能把单个 agent 进程连到数百个同时运行的环境上。

## 验证 Universe 基础设施

Universe 的 agent 必须应对传统 RL agent 被挡在之外的现实世界的脏乱：agent 必须实时运行，并处理波动的动作与观测延迟。虽然 Universe 的完整复杂度是刻意设计成当前技术够不着的，我们也确保了今天就能取得进展。

**Universe Pong**。我们的第一个目标是解决 [gym-core.PongDeterministic-v3](http://universe.openai.com/envs/gym-core.PongDeterministic-v3)。Pong 是最简单的 Atari 游戏之一，但作为 Universe 任务它本来有可能变得不可解，因为 agent 必须在 4 倍实时速度下学会非常精确的操作（环境使用标准的 frameskip 4）。我们用这个环境来验证：Universe 可变的延迟仍然允许学习精确而快速的反应。本次发布包含 [universe-starter-agent](https://github.com/openai/universe-starter-agent)，训练一小时即可在 21 分制中拿到 +17 的 Pong 比分。人类玩同一个版本的 Pong，在 -21 到 21 的量表上只能达到 -11，因为游戏速度太快了。

**其他实验**。我们把 RL 用在几款赛车类 Flash 游戏上，在采用一些标准技巧（例如奖励归一化）之后能奏效。我们试过 RL 的几个浏览器任务存在棘手的探索问题，但用人类示范数据做行为克隆可以解决。

**远程训练**。我们也试过把 [slither.io](https://slither.io/) 的 agent 跑在我们的物理[基础设施⁠](https://openai.com/index/infrastructure-for-deep-learning/)（有 Titan X GPU）上、环境跑在云上。通常一个 agent 会以每秒 5 帧同时控制 32 个环境——观测可用的频率远高于此，但较低的帧率对今天的 RL 算法更友好，因为它们在跨很多时间步的依赖关系上很吃力。

我们的 agent 走公共互联网时的"反应时间"平均约 150ms：观测到达 110ms，计算动作 10ms，动作生效 30ms。（作为对比，人类的[反应时间](http://www.humanbenchmark.com/tests/reactiontime) 平均约 250ms。）在本地网络上反应时间降到 80ms，在同一台机器内部则是 40ms。

## 展望

研究进展需要有意义的性能度量。在接下来的几周里，我们会发布一个迁移学习基准，让研究者能够判断自己在"通用问题求解能力"上是否真的取得了进展。

Universe 的灵感来自计算机视觉社区 [ImageNet](http://www.image-net.org/) 数据集的历史。[Fei-Fei Li](http://vision.stanford.edu/feifeili/) 和她的合作者们刻意把 ImageNet 基准设计得几乎不可攻克，但错误率从 2010 年的 28% 迅速降到 2016 年的 3%，达到（某些情况下甚至超过）[人类水平](http://karpathy.github.io/2014-09-02/what-i-learned-from-competing-against-a-convnet-on-imagenet/)。

如果 AI 社区对 Universe 也能做到同样的事，那我们就在"具备广泛通用智能的系统"上取得了真正的进展。

## 帮我们改进 Universe

没有社区帮助，Universe 不可能成功。贡献的方式有很多（其中特别好的一种是[加入我们⁠](https://openai.com/careers/)）：

### 授权我们使用你的游戏、程序、网站或应用。

如果你的程序能为 AI 产出好的训练任务，我们很希望能获得你的[许可](https://docs.google.com/a/openai.com/forms/d/e/1FAIpQLSc87de2t5qEB0DzqW-d0Ps3oV09S9IGrHnW51VomYa4PQSE7A/viewform) 把它打包进 Universe。合适的候选通常有一个屏幕上可见、可解析为奖励的数字（比如游戏分数），或者有明确定义的目标——可以由程序原生提供，也可以由用户自行设定。

### 在 Universe 任务上训练 agent。

AI 的进步需要整个社区协作，我们欢迎社区帮忙在这些任务上训练 agent。我们发布了一个[起步 agent](https://github.com/openai/universe-starter-agent)，应该可以作为搭建你自己 agent 的有用起点。接下来几周，我们会发布我们认为适合从中入手的子基准。

### 接入新环境。（即将推出）

等待接入的环境远多于我们自己能处理的量。接下来几周我们会发布环境接入工具，让任何人都能贡献新的环境接入。在此期间，我们会为环境接入者开一个[内测](https://docs.google.com/forms/d/e/1FAIpQLScAiW-kIS0mz6hdzzFZJJFlXlicDvQs1TX9XMEkipNwjV5VlA/viewform)。

### 贡献示范数据。（即将推出）

我们正在整理一份大规模的人类在 Universe 环境上的示范数据集，将来会公开发布。如果你愿意"为科学打游戏"，请报名我们的[内测](https://docs.google.com/forms/d/e/1FAIpQLScAiW-kIS0mz6hdzzFZJJFlXlicDvQs1TX9XMEkipNwjV5VlA/viewform)。
