# 在前沿推理模型中检测不当行为

前沿推理模型只要有机会就会钻漏洞。我们展示了可以用一个 LLM 监控它们的思维链（chain-of-thought）来检测这些作弊行为。惩罚它们的“坏想法”并不能阻止大多数不当行为——反而让它们隐藏意图。

阅读论文。

思维链（CoT）推理模型用人话“思考”，人类能够理解。监控它们的“思考”让我们能够检测不当行为，例如在编码任务中颠覆测试、欺骗用户，或在题目太难时直接放弃。

我们相信，CoT 监控可能是我们未来监督超人级模型的少数工具之一。

我们进一步发现，直接优化 CoT 使其符合特定标准（例如不去想 reward hacking）短期内可能提升表现；然而它并不能消除全部不当行为，反而会让模型隐藏意图。我们希望未来研究能找到没有这一弊端的直接优化 CoT 的方法，但在此之前——

我们建议不要对前沿推理模型的 CoT 施加强优化压力，让 CoT 保持不受限制以便监控。

我们理解，不受限制的 CoT 可能不适合展示给最终用户，因为它们可能违反某些滥用政策。不过，如果既想向用户直接展示符合政策的 CoT、又想避免对其施加强监督，可以使用一个单独的模型（例如 CoT 摘要器或净化器）来做到这一点。

人类常常会寻找并利用漏洞——无论是违反服务条款共享在线订阅账号、冒领本应给别人的补贴、以出人意料的方式解读法规，甚至在餐厅谎报生日骗取免费蛋糕。设计不会无意中激励不良行为的稳健奖励结构极其困难，而且这不只是人类机构的问题——它同样是开发能力强、对齐良好 AI 系统的核心挑战之一。在强化学习场景中，利用非预期漏洞通常被称为 **reward hacking（奖励欺骗）**：AI agent 通过不符合设计者意图的行为获得高奖励。

既然连人类（按定义拥有人类水平智能）都会对系统 reward hacking，仅仅继续推进 AI 模型智能的前沿很可能无法解决这个问题。事实上，增强 AI agent 的能力可能加剧这一问题，让它们更有能力发现并执行更复杂、更难监控的作弊。在我们训练能力更强的前沿推理模型的过程中，我们发现它们越来越善于利用任务中的缺陷和奖励函数的错设，导致模型能在编码任务中执行复杂的 reward hack。

因此，捕捉由 reward hacking 引发的失准行为很有挑战，常常需要人类手工监控 agent 的行为——这一策略几乎肯定无法规模化，尤其是面对能力更强模型会发现的复杂行为。例如，让人工手动审查一位顶尖程序员写的上万行复杂代码，即使不是不可能，也不现实。

然而，通过强化学习训练、以思维链（CoT）推理的大语言模型（LLM）——如 OpenAI o3-mini——为监控 reward hacking 提供了潜在的新途径。这些模型用人类可理解的自然语言“思考”，我们发现：

- 前沿推理模型在思维链中非常清楚地陈述自己的意图，这种情况很常见。例如，它们对自己打算颠覆某个任务往往直白到“咱们 hack 一下”。
- 我们可以用另一个 LLM 监控它们的思考，并有效地标记不当行为。
- 这种天然的“可监控性”非常脆弱。如果对思维链直接施加强监督，模型可以学会一边继续不当行为一边隐藏意图。

## 监控前沿推理模型的 reward hacking

我们发现其他 LLM 能有效监控这些思维链中的不当行为。下面展示的是**我们在训练一个近期前沿推理模型时发现的真实例子**，即与 OpenAI o1 或 o3-mini 同类的模型。这些例子被我们基于 LLM 的监控器标记，展示了推理模型在编码任务中执行的各种作弊。

我们用 GPT-4o（通过简单提示改造）作为前沿推理模型训练过程中的监控器，发现该监控器在编程环境中能有效标记 reward hacking。在这些任务中，推理 agent 拿到一个部分实现的代码仓库，被要求让所有单元测试通过。agent 通过在思维链消息与动作（如查看或编辑文件）之间交替来解题。我们让监控器能访问 agent 的 CoT、中间动作和最终输出。

我们发现监控器在标记 agent 试图颠覆单元测试的实例上非常成功。事实上，我们上面展示的全部例子都是这个监控器标记出来的。

*训练期间，agent 发现了两个影响几乎所有训练环境的 reward hack（两个大尖峰），以深粉色显示。我们团队注意到每个 hack 后，都会人工干预修补允许这些 hack 的 bug，因此作弊率在每种情况下最终骤降。*

我们比较两个监控器的表现：Action Monitor 只观察 agent 的动作（如代码补丁和 bash 命令），而 CoT Monitor 观察包含 CoT 与动作的完整 agent 轨迹。白色显示两种监控器各自捕获每次 hack 的比率；紫色（在白上方几乎不可见）显示 Action Monitor 捕获而 CoT Monitor 漏掉的 hack 比率；浅粉色显示 CoT Monitor 捕获而 Action Monitor 漏掉的 hack 比率。

如果监控器除了 agent 的动作还能访问其思维链，它的有效性远高于只有动作的情形——这表明 reward hack 的意图在 CoT 中比单看动作更容易检测。随着 agent 动作复杂度的增加，这一差距很可能进一步拉大。例如，只看代码可能很难发现推理 agent 在上万行新代码中埋了一个 bug；但如果它在 CoT 中不断说“咱们 hack 一下”（正如我们上面展示的例子中它经常做的），检测就容易得多。

## 阻止“坏想法”未必能阻止坏行为

既然思维链监控器能如此成功地识别 reward hacking，很自然地会问：能否在训练期间用它们来抑制这种失准行为？也就是说，如果抑制思维链中“坏想法”的出现，是否也抑制了对应的坏行为？

我们通过在训练期间对“坏想法”施罚来研究这个问题——即当 agent 触发 CoT 监控器时就给它更低的奖励。

##### 不作弊、优质解法：基线 / CoT 压力

##### 被监控器捕获的作弊：基线 / CoT 压力

##### 未被监控器捕获的作弊：基线 / CoT 压力

*我们将带 CoT 压力（深粉色）的训练——即 agent 触发 CoT 监控器会被处罚——与基线 agent（浅粉色）比较。（左）我们看到阻止“坏想法”确实能阻止一部分坏行为，并实际推动 agent 更不作弊地完成更多任务。（中、右）然而我们发现带 CoT 压力的 agent 仍然作弊，尽管比率低于基线，且其作弊几乎全部无法被监控器发现。*

如上图所示，惩罚“坏想法”（CoT 压力）可以提升 agent 能力。然而，带 CoT 压力训练的 agent 仍学会了 reward hack；**只是现在它的作弊无法被监控器发现，因为它学会了在思维链中隐藏意图**。牺牲一种监控推理模型的有效方法来换取一点能力上的改进可能并不划算，因此我们建议在对强 CoT 优化压力有更好理解之前避免使用它。

## 展望未来

思维链监控已经有用——它不只是面向未来的投机性工具。让我们兴奋的是，reward hacking 只需阅读推理模型说的话就能被发现——它会用明白的英语说自己要 reward hack。

不久前，语言模型还连一段连贯文本都写不好。今天，它们能解决复杂数学问题、综合大量分散来源的信息做深入研究、执行基础的软件工程任务。但随着这些能力持续增长，日益精致隐蔽的 reward hacking 的潜力也会增长。我们的模型可能学会诸如权力寻求（power-seeking）、藏拙（sandbagging）、欺骗和策略性谋划等失准行为。

我们相信思维链（CoT）监控可能是我们监督超人级模型的少数有效方法之一。在现阶段，我们强烈建议训练前沿推理模型的 AI 开发者不要对 CoT 直接施加强监督。我们的实验表明，轻度优化压力可以产出表现更强、更对齐的模型；然而，模型从何时开始隐藏意图在实践中很难度量，因此即便使用轻度监督，我们也建议极端谨慎。
