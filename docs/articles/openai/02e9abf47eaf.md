# CodeRabbit 扩大智能体软件开发规模，将交付量提升至 20 倍

CodeRabbit 使用 OpenAI 模型治理 AI 生成的代码并建立对代码的信任，借助 Codex，在工程团队规模不变的情况下，将软件交付量提升至原来的 20 倍。

[开始使用 OpenAI 构建应用](https://openai.com/startups/)

公司规模: 初创企业

区域: 北美

行业: 科技

产品: API, Codex, Daybreak

在 [CodeRabbit](https://www.coderabbit.ai/) 联合创始人兼首席执行官 Harjot Gill 看来，面对日益增多的 AI 生成成果，验证智能体生成的代码并判断其是否可信，正成为团队发挥判断力的关键环节。Harjot 说：“任何公司一旦采用编程智能体，遇到的第一个瓶颈都是代码审查。”

CodeRabbit 构建了一个 AI 驱动的治理与管控平台，旨在验证 AI 生成的代码，并帮助团队建立对这些代码的信任。超过 20,000 家组织和 150,000 个开源项目正在使用 CodeRabbit。它帮助团队理解和审查 AI 智能体生成的代码，保障代码安全，并判断哪些代码已达到交付标准。

据 CodeRabbit 介绍，OpenAI 更高的性价比使其能够在审查中引入更多 AI 智能体，并让客户受益；而 [Codex⁠](https://openai.com/codex/) 则帮助同一支工程团队将软件交付量提升至原来的 20 倍。公司还使用 [Daybreak⁠](https://openai.com/daybreak/) 来保障自身技术栈和客户代码的安全。其最新产品 CodeRabbit Secure 将 Daybreak 与 Codex 模型结合，通过专注于安全的智能体发现并修复漏洞。

> “每次 OpenAI 发布新模型，尤其是推理模型，我们产品大规模发现问题的能力都会显著提升。”

– Harjot Gill，CodeRabbit 联合创始人兼首席执行官

## 利用 OpenAI 推理模型改进代码审查

CodeRabbit 使用 GPT‑3.5 Turbo 构建了首款产品。Harjot 表示，GPT‑4 的问世让这款产品能够有效地审查代码。此后，公司又率先采用了 OpenAI o1 和 OpenAI o3。由于代码审查在云端异步运行，CodeRabbit 可以使用需要更长推理时间的模型，以换取更强的分析能力。

团队基于已知问题建立了自己的基准测试，用于评估新模型。在采访时，Harjot 估计 [GPT‑6 Astra⁠](https://openai.com/index/gpt-6-astra/) 能发现该数据集中 50% 的问题，在参与这项基准测试的模型中位居首位。

随着智能体引入不同类型的错误，以及修复过程暴露出此前审查遗漏的问题，这项基准测试也在持续更新。Harjot 说：“错误的类型在不断变化，而随着模型能力提升，我们的基准测试也在不断更新。”

## 让更强大的智能体也能以经济的成本部署

OpenAI 模型性价比的提升，帮助 CodeRabbit 将研究阶段的能力落地到产品中。Harjot 指出，模型定价和缓存机制的改进，让公司得以更广泛地使用 AI、增加子智能体，并将这些收益惠及客户。

CodeRabbit 起步时，只使用一两个子智能体来定位和浏览代码。如今，GPT‑6 Luna 等成本更低的模型支撑着整个平台上更多的子智能体，而 GPT‑6 Astra 等模型则负责规划与编排。

Harjot 说：“现在，我们在各种场景中都用上了智能体，而这些场景的成本过去根本负担不起。”这扩大了 CodeRabbit 的验证范围，也丰富了它能向开发者提供的解释，帮助他们理解并信任那些并非自己编写的代码变更。

## 借助 Codex 将软件交付量提升至 20 倍

Harjot 表示，通过使用 Codex，公司在过去 6 个月里没有增加工程师人数，却将软件交付量提升至原来的约 20 倍。他估计，在采访前的 30 天里，自己提交了 2,500 到 3,000 个 pull request。

要做到这一点，仅仅采用 Codex 还不够。同时运行多个智能体，暴露了开发流程各个环节的限制，包括笔记本电脑的内存和算力、测试、软件编译与打包工具，以及依赖项。

团队精简了发布流程，重新考虑哪些环节需要人工审批，同时使用 CodeRabbit 自动交付无需人工干预的低风险变更。Harjot 说：“我们不得不彻底重新思考整个软件交付流程。”

公司还构建了一个由 Codex 驱动的 Slack 机器人，用于对生产环境事故、Slack 消息和支持工单进行分类与初步处理。它可以返回一个 pull request，供团队审查和合并。Harjot 认为，云端开发可以减少本地计算机的限制，让团队更好地管控访问权限和审计流程。

## 用代码管理 CodeRabbit 的更多业务

CodeRabbit 也将 Codex 用于工程开发以外的工作，包括通过代码管理营销和运营任务。Harjot 说：“我们正在尽可能用代码来运营公司。”

在营销方面，公司通过 pull request 管理 Google Ads。团队创建并合并请求，即可投放广告。公司还使用了一个内容工作室代码仓库，Codex 在其中创建演示文稿和面向客户的文档。Harjot 说：“如果你能把营销问题转化为代码问题，工作速度就能提升到原来的 10 倍。”

## 借助 Daybreak 保障应用代码安全

自 2023 年起，CodeRabbit 就开始在沙盒环境中运行智能体，克隆代码仓库，并让智能体编写代码来辅助审查。近期，CodeRabbit 通过 Daybreak 使用 OpenAI 的 Cyber 模型来测试自身平台，并保障其安全。

团队使用该模型进行内部渗透测试，探查攻击者可能入侵自身平台的途径。Harjot 表示，提前获得使用权限帮助 CodeRabbit 加固了自身技术栈的安全。Harjot 说：“我们发现了多个漏洞，以及一些连我们都想不到的高级攻击手法。”

此后，公司将这些能力推向市场，通过最新产品 CodeRabbit Secure 帮助保障客户的代码安全。过去两周，公司开展了一项促销活动，为用户提供总价值 100 万美元的免费深度扫描。在全部由 Codex 模型驱动的 13,000 次深度扫描中，公司发现了超过 43,000 个安全漏洞。客户已经修复了其中数千个漏洞，提高了代码安全性。

## 让开发者始终掌控智能体生成的代码

随着后台智能体开始响应告警和事故，不再需要人工逐项发起任务，Harjot 预计，团队将需要更多帮助，才能判断哪些变更值得推进到最终交付。

展望未来，CodeRabbit 正在向智能体驱动的软件开发拓展，帮助团队大规模验证智能体生成的代码变更，确定其优先级、解释其内容、保障其安全并核验结果。

随着智能体承担更多开发工作，新的机遇在于让验证、解释和维护跟上代码生成的速度，帮助开发者始终掌握控制权。
