# Ultrafast 如何把 OpenAI 的故障排查从几小时缩短到几分钟


*这是我们系列文章的一部分，介绍 OpenAI 如何在内部使用自己的技术与 API 的实例。这些工具正在 OpenAI 内部使用，此处作为示例分享，说明前沿 AI 如何支持我们各个团队的用例。*

Ultrafast 是 Codex 中的一种高速模式，对 OpenAI 的工程师来说，它已经成为故障响应的默认选择。出现故障时，工程师往往没有时间一边等答案，一边让问题继续恶化。有了 Ultrafast，他们可以同时排查多个可能的原因，并在不分散注意力的情况下拿到答案。

> “如果你有两个同样聪明的人，一个一小时后回复你，另一个一分钟后回复你，第二个人显然强得多。跟响应更快的人一起，你能完成的事情也多得多。”

—Adam Perry，OpenAI 技术员工

## 大海捞针

Aaron Friel 是 OpenAI 的技术员工，通常由他牵头处理故障。他会为故障响应开一个 Slack 频道，然后让 Codex 盯着这个问题，要求它持续监控、调查，并随时回答新冒出来的问题。他说：“在任何一次故障中，通常都有一连串可能的出错环节，而要在正确的干草堆里找到那根正确的针，正是这个频道上的人最主要的活儿。”“有了 Ultrafast，我基本上能同时搜索所有这些干草堆，对故障的响应也快得多。”

AJ Trbojevic 是技术员工兼数据中心安全架构师，他说过去调查安全问题往往要花一两个小时，才能把结构化和非结构化的数据汇总到一起、做规范化，并补齐上下文以便做出决策。“现在这件事 10 到 15 分钟就能完成，”他说，“有时还接近实时。”

Adam Perry 和 Sayan Sisodiya 都在核心 agent 团队工作，负责构建让 Codex 能够执行操作、运行命令、使用工具的代码。Ultrafast 改变了他们在安全事件中的工作方式。Adam 说：“以前，我会让 Codex 去查一件事，同时自己也去查，因为我清楚它不够快，光等着是来不及的。”“现在有了 Ultrafast，Codex 快到我可以专心做一件事，而不用再分心。”

Sayan 很看重 Ultrafast 让他从多个数据源立刻拿到答案的能力：“在故障中不只是翻日志，我还会用 Codex 去翻 Slack，看看有没有指向可疑改动的引用，或者别处有人在讨论类似的症状，”他说。

## 30 秒内给出快速回应

如果用 AI 找答案要超过 30 秒，Jeff Niu（另一位技术员工）说他会去看看 Slack 或者找同事聊。但现在借助 Ultrafast，他的大部分工作都不超过这个门槛。过去他会让 Codex 回答一个问题，然后切到别的事情上去，等它想完再回来，回来时思路已经断了。现在这段对话是实时发生的；这有助于他专注于手头的任务。

Ultrafast 也让 Jeff 更愿意动手做大规模重构，因为改造既有代码所需的时间变少了。“技术债现在比以往任何时候都更容易还清，”他说。“代码很便宜，现在产出代码也快得多。以前代价很高的一次重构，现在几乎瞬间就完成。”

## 像副手一样协作

Adam 一直开着一个 Codex 会话，把它叫作自己的幕僚长。每天早上，它会告诉他当天有哪些会议，以及哪些消息他可能忘了回复。“它已经看过所有数据才写出那份摘要，所以我追问时，它不用再等着去取更多数据，”他说。“我可以像对真正的幕僚长那样，在同一段对话里一直问下去。”

Sayan 用 Codex 去做浏览器里那些繁琐的手工活，比如填写表单——以前他嫌太慢，不愿意做。“它会打开浏览器，在那儿想五秒钟，点一下，再在那儿等着，”他说。随着最新模型在 computer use 上的改进，他更放心把这些活交给 Codex 干了。“现在我完全放心让它在浏览器里一路点下去，而且它够快，我不做也不会浪费时间。”

在故障响应、日常规划和重构中，Ultrafast 让 OpenAI 的技术员工能以自己提问的节奏与 Codex 协作。他们可以追问答案、换一种做法，并继续工作而不打断思路。这段更短的等待也改变了他们愿意承担的工作——从原本会一拖再拖的重构，到终于值得委派出去的日常任务。
