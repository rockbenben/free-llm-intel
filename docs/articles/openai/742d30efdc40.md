# Ultrafast 如何将 OpenAI 的事件调查时间从几小时缩短为几分钟

*这是我们分享 OpenAI 如何使用自己的技术和 API 的内部示例系列的一部分。这些工具正在 OpenAI 内部使用，并在此作为前沿 AI 如何支持我们团队中的用例的说明性示例进行共享。*

Ultrafast 是 Codex 中的一种高速模式，对于 OpenAI 的工程师来说，它已成为事件响应的默认模式。当出现问题时，工程师通常没有时间等待几分钟才能得到答案，而问题却变得更加复杂。借助 Ultrafast，他们可以同时调查多个潜在原因并获得答案，而无需分散注意力。

> “如果你有两个同样聪明的人，其中一个在一小时内回复你，一个在一分钟内回复你，那么第二个人会更好。与反应更快的人一起，你会做得更多。”

—Adam Perry，OpenAI 技术人员

## 大海捞针

Aaron Friel 是 OpenAI 的技术人员，通常是事件的关键点。他启动了一个用于事件响应的 Slack 频道，然后向 Codex 指出问题所在，要求 Codex 监控、调查并回答出现的任何问题。“在任何事件中，通常都会有很多可能出错的地方，而大海捞针确实是该频道人员的主要工作，”他说。 “使用 Ultrafast，我基本上能够同时搜索所有这些干草堆，并更快地响应事件。”

技术人员兼数据中心安全架构师 AJ Trbojevic 表示，对安全问题的调查过去需要一两个小时才能将结构化和非结构化数据整合在一起，对其进行规范化，并提供做出决策的背景。 “现在 10 到 15 分钟内就会发生，”他说。 “有时它接近实时。”

Adam Perry 和 Sayan Sisodiya 都在核心代理团队工作，负责构建让 Codex 采取行动、运行命令和使用工具的代码。超快改变了他们在安全事件期间的运作方式。 “以前，我会要求 Codex 调查一些事情，然后我自己也去调查，因为我知道只是等待的速度不够快，”Adam 说。 “现在有了 Ultrafast，Codex 的速度足够快，我可以保持专注，而不是分散注意力。”

Sayan 很欣赏 Ultrafast 如何让他从多个数据源立即得到答案：“除了挖掘事件中的日志之外，我还使用 Codex 挖掘 Slack，看看是否有可能可疑的更改的引用，或者人们在 Slack 的其他地方谈论类似的症状，”他说。

## 30 秒内快速响应

另一位技术人员 Jeff Niu 表示，如果人工智能需要超过 30 秒才能找到答案，他会查看 Slack 或与同事聊天。但现在他的大部分工作都在 Ultrafast 的阈值之下。他常常向 Codex 提出一个问题，当 Codex 思考时就转向其他问题，然后回来时就失去了思路。现在对话是实时进行的；这有助于他专注于手头的任务。

超快还使杰夫更愿意处理大型重构，因为重构现有代码需要更少的时间。 “技术债务现在比以前更容易偿还，”他说。 “代码很便宜，而且现在生成速度非常快。过去花费大量成本的重构几乎立即发生。”

## 担任副驾驶

Adam 保持着一条正在运行的 Codex 线程，他称之为他的参谋长。每天早上它都会告诉他他有哪些会议以及他可能忘记回复哪些消息。 “它已经查看了所有数据来撰写摘要，因此当我询问后续情况时，它不会等待去获取更多数据，”他说。 “我可以像真正的幕僚长一样在同一次谈话中不断提问。”

Sayan 使用 Codex 在浏览器中完成繁琐的手动工作，例如填写表格 - 他以前避免这样做，因为速度太慢。 “它会打开一个浏览器，坐在那里思考五秒钟，点击一些东西，然后再坐在那里，”他说。随着最新型号在计算机使用方面的改进，他更愿意让 Codex 来处理这项工作。 “现在我完全可以让它在浏览器中点击，而且速度足够快，我不会因为不自己做而浪费时间。”

在事件响应、日常规划和重构方面，Ultrafast 让 OpenAI 的技术人员能够按照 Codex 提出问题的速度进行工作。他们可以跟进答案，尝试另一种方法，并继续工作而不会失去思路。较短的等待时间也改变了他们愿意承担的事情，从他们推迟的重构变成了最终值得委派的例行任务。
