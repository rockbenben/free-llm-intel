# 全新的嵌入模型和 API 更新

阅读文档

我们发布新模型、下调 GPT‑3.5 Turbo 的价格，并为开发者引入管理 API 密钥和理解 API 用量的新方式。新模型包括：

- 两个新的嵌入模型
- 一个更新的 GPT‑4 Turbo 预览模型
- 一个更新的 GPT‑3.5 Turbo 模型
- 一个更新的文本审核模型

默认情况下，发送到 OpenAI API 的数据不会被用于训练或改进 OpenAI 模型。

## 定价更低的新嵌入模型

我们推出两个新的嵌入模型：一个更小、高效的 `text-embedding-3-small`，以及一个更大、更强大的 `text-embedding-3-large`。

[嵌入⁠](https://openai.com/index/introducing-text-and-code-embeddings/)是一串数字，用来表示自然语言或代码等内容中的概念。嵌入让机器学习模型和其他算法容易理解内容之间的关系，并执行诸如聚类或检索之类的任务。它们支撑着 ChatGPT 和 Assistants API 中的知识检索，以及许多检索增强生成（RAG）开发者工具。

### 一个新的小型文本嵌入模型

`text-embedding-3-small` 是我们全新的高效嵌入模型，相较它的前代——[2022 年 12 月⁠](https://openai.com/index/new-and-improved-embedding-model/)发布的 `text-embedding-ada-002`——有显著提升。

**更强的性能。** 把 `text-embedding-ada-002` 与 `text-embedding-3-small` 对比，在多语言检索的常用基准（[MIRACL](https://github.com/project-miracl/miracl)）上的平均分从 31.4% 升到 44.0%，同时在英语任务常用基准（[MTEB](https://github.com/embeddings-benchmark/mteb)）上的平均分从 61.0% 升到 62.3%。

**更低的价格。** `text-embedding-3-small` 也比我们上一代 `text-embedding-ada-002` 模型高效得多。因此 `text-embedding-3-small` 的价格相比 `text-embedding-ada-002` 降了 5 倍，每 1k token 的价格从 0.0001 美元降到 0.00002 美元。

我们不会弃用 `text-embedding-ada-002`，所以我们推荐新模型的同时，也欢迎客户继续使用上一代模型。

一个新的大型文本嵌入模型：`text-embedding-3-large`

`text-embedding-3-large` 是我们下一代更大的嵌入模型，能创建维度最高达 3072 的嵌入。

**更强的性能。** `text-embedding-3-large` 是我们性能最好的新模型。把 `text-embedding-ada-002` 与 `text-embedding-3-large` 对比：在 MIRACL 上，平均分从 31.4% 升到 54.9%；在 MTEB 上，平均分从 61.0% 升到 64.6%。

| 评估基准 | ada v2 | text-embedding-3-small | text-embedding-3-large |
| --- | --- | --- | --- |
| MIRACL 平均 | 31.4 | 44.0 | 54.9 |
| MTEB 平均 | 61.0 | 62.3 | 64.6 |

`text-embedding-3-large` 的定价为每 1k token 0.00013 美元。

你可以在我们的[嵌入指南](https://platform.openai.com/docs/guides/embeddings)中了解如何使用新嵌入模型。

### 对缩短嵌入的原生支持

使用更大的嵌入，例如把它们存入向量库以供检索，通常比使用更小的嵌入耗费更多成本、算力和内存与存储。

我们的两个新嵌入模型都用了这样一种技术[A](https://openai.com/index/new-embedding-models-and-api-updates/#citation-bottom-A)训练，让开发者能够在嵌入的性能和使用成本之间做权衡。具体来说，开发者可以缩短嵌入（即从序列末尾去掉一些数字），而无需让嵌入失去其表示概念的能力——只需传入 `dimensions` API 参数即可。例如，在 MTEB 基准上，一个 `text-embedding-3-large` 嵌入可以被缩短到 256 的大小，仍然胜过未缩短、大小为 1536 的 `text-embedding-ada-002` 嵌入。

这带来了极其灵活的用法。例如，当使用一个只支持最长 1024 维嵌入的向量数据存储时，开发者仍然可以使用我们最好的嵌入模型 `text-embedding-3-large`，并为 `dimensions` API 参数指定 1024，这会把嵌入从 3072 维缩短，用一部分准确度换取更小的向量尺寸。

## 其他新模型与更低的定价

### 更新的 GPT-3.5 Turbo 模型与更低定价

下周我们将推出一款新的 GPT‑3.5 Turbo 模型 `gpt-3.5-turbo-0125`，并且在过去一年中第三次下调 GPT‑3.5 Turbo 的价格，以帮助客户扩展规模。新模型的输入价格下调 50%，为每 1K token 0.0005 美元；输出价格下调 25%，为每 1K token 0.0015 美元。该模型还将有各种改进，包括在按所请求格式作答方面更高的准确度，以及修复了一个[导致非英语语言函数调用出现文本编码问题的 bug](https://community.openai.com/t/gpt-4-1106-preview-is-not-generating-utf-8/482839)。

使用未锁定 `gpt-3.5-turbo` 模型别名的客户，将在本模型发布两周后自动从 `gpt-3.5-turbo-0613` 升级到 `gpt-3.5-turbo-0125`。

### 更新的 GPT-4 Turbo 预览

自发布以来，GPT‑4 API 客户超过 70% 的请求已转向 GPT‑4 Turbo，因为开发者享受到了它更新的知识截止时间、更大的 128k 上下文窗口和更低的价格。

今天，我们发布一个更新的 GPT‑4 Turbo 预览模型 `gpt-4-0125-preview`。该模型比上一个预览模型更完整地完成任务（如代码生成），并旨在减少模型不完成任务的“偷懒”情形。新模型也包含了针对影响非英语 UTF-8 生成的那个 bug 的修复。

对于希望自动升级到新版 GPT‑4 Turbo 预览的用户，我们还引入了一个新的 `gpt-4-turbo-preview` 模型名别名，它始终指向我们最新的 GPT‑4 Turbo 预览模型。

我们计划在未来几个月内让带视觉能力的 GPT‑4 Turbo 全面可用。

### 更新的审核模型

免费的 Moderation API 让开发者能够识别潜在的有害文本。作为我们持续安全工作的一部分，我们发布 `text-moderation-007`——我们有史以来最稳健的审核模型。`text-moderation-latest` 和 `text-moderation-stable` 别名已更新为指向它。你可以通过我们的[安全最佳实践指南](https://platform.openai.com/docs/guides/safety-best-practices)了解更多关于构建安全 AI 系统的信息。

## 理解 API 用量和管理 API 密钥的新方式

我们推出两项平台改进，让开发者对自己的用量有更清晰的可见性、对 API 密钥有更充分的控制。

首先，开发者现在可以在 [API 密钥页面](https://platform.openai.com/api-keys)为 API 密钥分配权限。例如，一个密钥可以被分配只读权限来驱动一个内部追踪仪表盘，或被限制为只能访问某些端点。

其次，用量仪表盘和用量导出功能现在在[开启追踪](https://platform.openai.com/api-keys)后，会以 API 密钥为单位暴露指标。这使得按功能、团队、产品或项目维度查看用量变得简单——只需为每一类单独使用不同的 API 密钥即可。

在未来几个月，我们计划进一步提升开发者查看 API 用量和管理 API 密钥的能力，尤其是在大型组织中。

要获取 OpenAI API 的最新动态，请在 X 上关注我们的 [@OpenAIDevs](https://twitter.com/OpenAIDevs)。
