# Nextdoor 工程师如何用 Codex 无界构建

在 Nextdoor 的核心平台团队中，Codex 负责调查问题，并让产品工程师掌握主导权。











像 Nextdoor 这样服务于 11 个国家/地区超过 1.1 亿用户的产品，会对平台团队提出许多要求。对工程负责人 Cory Dolphin 来说，Codex 代表着一种关键转变：“从反复提示智能体，转向成果工程；工程师开始思考自己希望看到的结果，并与智能体协作来实现该结果。”

这意味着每位工程师都能向技术栈上层移动——不再被限定为某个系统或框架的专家，而是能够或多或少端到端地负责产品体验，甚至跨多个平台负责。生产力提升得如此之快，以至于瓶颈不再是工程，而是关于接下来构建什么的艰难战略问题。

> “Codex 从根本上改变了我们对工程的思考方式，以至于我们甚至无法想象没有它的工程会是什么样。”

—Cory Dolphin，Nextdoor 工程负责人

## 产品工程师可以专注于产品

借助 Codex，“工程师不必再花大量时间思考究竟要*如何*构建，而是能把更多时间用于思考成果，”Dolphin 解释道。这种成果可以是智能体据以构建的截图或视频、某个性能或测试结果，也可以是一个全新的功能想法。

Nextdoor 最近发布了 Opportunity Alerts，让人们能够找到附近的服务提供商；借助 Codex，工程师正在推动产品体验和路线图。例如，一位负责提醒功能的工程师意识到，在地图上显示服务提供商会很有帮助。在过去，这类功能需要移动端、前端和后端工程三个团队协作，而且可能永远无法从待办事项中走出来。

但借助 Codex，“我们能够让一名工程师端到端完成构建，”Dolphin 解释道，“这不仅意味着他们能更快推动产品，也能更好地理解实际的产品体验，以及什么才是应该发布的正确内容。”

> “随着工程师开始向技术栈上层转移，他们会对自己构建的产品承担更多责任。你真的会看到每位工程师开始推动产品发展。”

—Cory Dolphin，Nextdoor 工程负责人

## 压缩软件工程时间

在处理嵌入式 Rust 数据库和竞态条件严格的系统时，Nextdoor 会借助 Codex 来调试最难复现的问题。团队为智能体提供干净的环境和用于调查的测试工具，然后用它处理各种任务：从弄清 Kubernetes pod 为何无法启动，到在数据分析中找到正确的趋势线。

“使用 GPT‑5.4 和 5.5 后，升级效果非常令人印象深刻。我们看到 Codex 非常擅长坚持不懈地寻找正确解决方案，深入研究一些看似晦涩的技术细节，最终找到根本原因，”Dolphin 解释道。

谈到 Codex 和 GPT‑5.5 的 Fast Mode，Dolphin 表示：“说实话，团队里很多人都对它着迷。当你处理的问题能形成快速反馈循环时，作为工程师，那种感觉令人振奋。”

工程工作变得如此之快，以至于 Dolphin 已经看到组织不同部分所承受的压力发生了变化。“我们的推进速度快了很多，瓶颈已经不在工程环节。现在真正的问题是，我们如何识别出正确的构建对象和正确的战略——而不是我们实际如何构建它。”
