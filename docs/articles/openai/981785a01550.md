# DevRev 借助 GPT‑6.1 Sol 构建自主自助服务

DevRev 使用 GPT‑6.1 Sol 驱动 Computer 和 Operator，在企业服务中兼顾推理能力、速度与成本。

[开始使用 OpenAI 构建应用](https://openai.com/startups/)

公司规模: 初创企业

区域: 北美

行业: 科技

产品: API, Codex

[DevRev](https://devrev.ai/) 打造了 Computer 和 Operator ，帮助服务与运营团队全程跟进并处理客户和员工的请求，即使是最棘手的请求也不例外。Computer 和 Operator 能够整合实时数据进行推理。DevRev 首席技术官 Ahmed Bashir 解释说，操作可以撤销，答案也能追溯到来源。

DevRev 将 GPT‑6 Astra 和 GPT‑6.1 Sol 等 OpenAI 模型与自身的执行框架相结合，接入企业知识，并让团队能够管控智能体可执行的操作。在 DevRev 看来，OpenAI 模型既具备推理能力和可靠性，也能满足为客户和员工提供服务时对速度与成本的要求。

> “它需要兼具恰当的推理能力、可信赖性和高度对齐性，而最重要的是，响应延迟必须满足实际需求。”

— Ahmed Bashir，DevRev 首席技术官

## 让 AI 结合企业背景信息开展工作

Computer 和 Operator 的推理、规划及工具选择能力均由 OpenAI 模型驱动。在 DevRev 的 Agent Studio 中，用户可以通过与 AI 对话来描述期望工具如何运作，也可以用固定规则定义工具的部分行为。

DevRev 将模型与配套软件一起测试，这些软件负责提供企业背景信息、实施权限管理并管控操作。其 Enterprise-Bench 基准测试用于评估模型与软件在以下情境中的协同表现：数据存在多个版本、信息分散在不同系统中，以及访问权限取决于用户角色。

Ahmed 表示，GPT‑6.1 Sol 在这些评估中表现出色。当客户或员工与 AI 智能体交互时，模型需要理解请求中的细微差别，并以企业可持续承担的成本快速响应。Ahmed 说：“我认为它在这些方面实现了完美的平衡。”

## 使用 Codex 开发软件和制作销售演示

在 DevRev 内部，工程师们对最佳开发方式已有明确的选择。Ahmed 说：“我们整个团队都在使用 Codex。”工程师们尝试了多种编程工具后，便开始在团队中自发推广 Codex。截至访谈时，DevRev 已全面转向 Codex，不再订阅 Cursor 许可证。

在 Ahmed 看来，这反映了开发者真正看重的东西：“开发者其实就是在寻找最好的工具，你骗不了他们。”他手下的工程师都明确表示，希望继续使用 Codex。

> “我们认为，Codex 的使用体验无疑是最好的，远超其他工具。”

— Ahmed Bashir，DevRev 首席技术官

DevRev 的销售工程师也使用 GPT‑6 Astra 为公司在国际会议上的展台制作演示。

## 更快响应客户和员工的需求

当客户或员工寻求帮助时，Operator 可能需要理解问题、执行获准操作，或将请求转交给 Computer，由它帮助合适的人员做好准备以便采取相应行动。Ahmed 认为，Decisions API 和 Ultrafast 有望帮助这些工作流快速完成，而不必在每一步都进行深度推理。

其中一些决策很难用固定规则定义，成本也很高，尤其是当决策所依赖的信息持续变化时。Ahmed 希望开发者能通过对话描述更多这类逻辑，并为每项任务选择合适的智能能力。他说：“这些流程必须能够在几秒内自行运行并完成，而不是几分钟。”

## 兑现自助服务的承诺

DevRev 的下一个目标是让 Operator 承担流程更长、要求更高的客户和员工请求，同时确保操作可追溯、受权限管控且可撤销。

在 Ahmed 看来，从知识库中查找答案、升级套餐或申请退款等常见支持任务，仅仅是个开始。他说：“我们希望真正兑现自助服务的承诺。”

借助 OpenAI 的前沿智能能力，DevRev 正致力于让 Computer 和 Operator 依托企业知识和管控机制，代表用户执行操作，全程跟进并处理更复杂的请求。
