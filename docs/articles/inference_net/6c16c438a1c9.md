# 逻辑：通过对数概率验证进行不可信推理

A

Amar Singh

## **引言**

我们推出 LOGIC，一种在去中心化 GPU 网络中验证推理的实用方法。LOGIC 利用压缩后的 token 级对数概率与统计检验，以极高的准确率识别不诚实的 GPU 运营方，同时带来的开销极小，并能与现有推理引擎（如 vLLM、SGLang）无缝集成。

该系统能抵御 decode 期的伪装攻击——对无需许可的网络而言这是一个关键部件，因为在经济激励下，GPU 运营方可能在生成阶段改用更小或经过量化的模型。以每 10k tokens 仅约 250-313 KB 的载荷体积、验证只需 10 次单 token 重算的代价，LOGIC 为无需信任的推理提供了一个可上生产、且经过实战检验的解决方案。

关键在于，LOGIC 不需要修改底层推理引擎，并且能与标准的 OpenAI 风格 API 天然集成，因此在绝大多数生产环境中都能即刻部署。

## **无需许可推理网络中的信任**

过去 18 个月里，Inference.net 一直运营着一个全球去中心化的 AI 推理网络，最多时有 10,000 块异构 GPU，从笔记本电脑里的消费级显卡，到上市公司运营的 Tier 3 机房里的数据中心硬件都有。这个网络在设计上就是无需许可的：任何 GPU 持有者都可以下载我们的客户端软件，立刻开始对外服务推理请求。

这种开放性带来了一个根本性挑战：**我们如何验证 GPU 运营方确实在运行他们所声称的那些模型？**

在一个带有经济激励的无需许可环境里，恶意行为者有多条路径可以实施不诚实行为：

- **模型替换：** 运行更小、更便宜的模型（例如把 70B 模型换成 8B 模型）
- **量化伪装：** 使用精度更低的量化模型来降低算力成本
- **推测解码攻击：** 用所声称的模型做 prefill，却用更小的模型做 decode，以节省生成成本
- **返回伪造文本：** 根本不运行推理，凭空编造响应

传统验证机制力有不逮。逐字复现响应代价高昂，而且常因非确定性与 temperature 设置而失败。零知识证明这类密码学方法，对现代 LLM 推理来说要慢上几个数量级、也贵上几个数量级。基于激活值的方法则需要对推理引擎做大量插桩，并且对硬件非确定性很敏感。

**最关键的是，许多现有验证方法只校验 prefill 阶段。** 在参与者有经济动机把成本压到最低的无需许可网络里，decode 期的伪装就成了首要攻击向量。某个运营方可以用正确的模型诚实地做 pre-fill，却偷偷切换到更便宜的模型来做生成——而生成恰恰是算力成本最高的环节。

## **通过对数概率分布进行验证**

LOGIC 走的是一条根本不同的路子：不去尝试复现精确的激活值或 token 序列，而是验证模型输出的*统计分布*是否与我们对所声称模型的预期相符。

核心洞见在于：每个语言模型都会在自己的 token 级对数概率分布中留下一枚独特的“指纹”。不同的模型、不同的量化方案、不同的架构改动，都会在每一个位置上产生可测量地不同的词表分布。

它是这样工作的：

### **推理阶段（运营方侧）**

对每个生成的 token，不受信任的 GPU 计算 top-k token 的对数概率——也就是最可能的下几个 token 及其概率。这些数据被压缩后，随生成的文本一起返回。

压缩管线是为效率精心设计的：

- **millilog 量化：** 把对数概率四舍五入到最接近的 0.001
- **增量编码：** 存储排序后的对数概率之间的差值
- **高效打包：** token ID 用变长整数、增量用 int16
- **Gzip 压缩：** 对最终字节流做压缩

这带来了惊人的效率：k=20 时，我们观察到压缩后每个 token 仅约 25-31 字节，也就是 10,000 个 token 约 250-313 KB。

*图 1：压缩流程概览，展示从 top-k logprobs 经过排序、量化、增量编码到 gzip 压缩的流程。*

*图 2：不同序列长度下的压缩表现，外推到 10k tokens 约为 300 KB。*

### **验证阶段（验证方侧）**

验证方不需要重新生成整个序列。它从 decode 阶段随机抽取 S 个位置（默认 10 个），只借助 KV-cache 优化重算那些单 token 分布。

对每个被抽到的位置 t，我们：

- 使用精确的上下文重算 top-k 对数概率
- 取交集来与运营方的 top-k 对齐：ℐₜ = Sₜʷ ∩ Sₜᵛ
- 记录重叠大小 mₜ = |ℐₜ| 与 Jaccard 相似度 Jₜ = mₜ/(2k - mₜ)

随后我们把对齐后的对数概率聚合起来：

- 运营方集合：`Lʷ = ⋃ₜ∈𝒯 {ℓₜ,ⱼʷ : j ∈ ℐₜ}`
- 验证方集合：`Lᵛ = ⋃ₜ∈𝒯 {ℓₜ,ⱼᵛ : j ∈ ℐₜ}`

通常情况下，这给出 n₁ = n₂ ≈ S × m 个样本，其中 m ≈ 10-20 是平均重叠数。

### **统计检验**

拿到两组对数概率样本后，我们使用 **Kolmogorov-Smirnov（KS）双样本检验**。这一非参数检验比较累积分布函数：

**Dₙ₁,ₙ₂ = sup_x |Fₙ₁(x) - Gₙ₂(x)|**

其中有效样本量为 nₑff = (n₁ × n₂)/(n₁ + n₂)。

KS 检验给出一个 p 值 pₖₛ。

当运营方是诚实的、运行的就是所声称的模型时，两个分布吻合，pₖₛ ≈ 1。

当运营方不诚实——换用别的模型、别的量化方案或某种伪装策略——分布就会分离，pₖₛ 急剧下降。

我们设定阈值 pₘᵢₙ = 0.95：pₖₛ ≥ pₘᵢₙ 的运营方被接受为诚实。

*图 3：完整的验证流程，展示客户端请求、运营方推理并返回压缩 logprobs、验证方抽样与重算，以及信任记录的更新。*

## **抵御 decode 期伪装**

许多验证方案的一个致命弱点是**推测解码攻击**：不诚实的运营方用昂贵的、所声称的模型 M 做 prefill，却在 decode 时切到更便宜的模型 M' 以把生成成本压到最低。由于在长序列里生成通常占了算力的大头，这种攻击给恶意行为者带来可观的经济收益。

只校验 prefill 的验证方法（包括 TOPLOC）无法发现这种攻击，因为它们只验证最初的上下文处理。一旦验证通过，运营方就可以随意用任何模型来生成。

**LOGIC 专门从 decode 位置采样**，这让该攻击立刻可被察觉。如果某个运营方用 M 做 prefill、用 M' 做 decode，那么在被抽到的 decode 位置 t 上：

- 运营方的对数概率：ℓₜ,ⱼʷ = log p_M'(iⱼᵗ | context_t)
- 验证方的对数概率：ℓₜ,ⱼᵛ = log p_M(iⱼᵗ | context_t)

这两者来自不同的条件分布，会产生系统性差异，而 KS 检验能可靠地检出。对于经济激励天然鼓励 decode 期伪装的无需许可网络来说，这一性质至关重要。

## **跨硬件与配置的稳健性**

与依赖精确激活值匹配的方法不同，LOGIC 对硬件非确定性天生稳健。不同的 GPU、CUDA 版本与数值精度差异都会影响中间激活值的确切数值，但对 top-k 对数概率分布的*形状*影响极小。

我们通过同时跟踪 KS p 值与对数概率对的 Pearson 相关系数来验证这种稳健性。假设存在小幅数值漂移 ε，且 E[ε] = 0、Var(ε) = σ²，则相关系数

**r ≈ Var(ℓʷ) / √(Var(ℓʷ)(Var(ℓʷ) + σ²)) → 1**

当 σ² → 0 时成立。这种双指标做法（KS + 相关性）即使存在轻微数值波动也能稳健检测。

## **与现有推理引擎集成**

LOGIC 的关键优势之一，是它与现有推理引擎的**零修改集成**。由于大多数引擎在采样过程中本来就会计算 top-k token 的对数概率，LOGIC 只需捕获并压缩这些已有的数据。

任何支持返回 logprops 的 OpenAI 兼容 API，LOGIC 都能无缝对接：

- **vLLM：** 通过标准 API 直接集成
- **SGLang：** 与现有工作流原生兼容

这种可移植性意味着 LOGIC 可以部署在异构 GPU 网络上，而不要求运营方运行定制修改过的推理软件。推理客户端只需在平时的文本响应旁边，额外返回一段压缩载荷。

验证服务器同样简单直白：它开启 KV-caching 跑标准的单 token 推理调用，于是验证速度随被抽样位置的数量线性扩展。

*图 4：有 KV caching 与无 KV caching 时，验证延迟与采样数量的关系。KV caching 带来平均 1.46 倍加速。*

## **实验验证**

我们在已部署的去中心化网络上对 LOGIC 做了严格测试，使用 10,000 条覆盖编码、推理、创意写作与问答的多样化提示词。

### **设置**

- **基座模型：** Llama-3.2-3B-Instruct（BF16）
- **不诚实基线：**   Llama-3.2-1B-Instruct（不同的模型规模）   Llama-3.2-3B-Instruct 量化到 FP8
- **硬件：** H100、RTX 4090
- **设置：** k=10，采样 S ∈ 40

### **结果**

**诚实运营方被可靠地接受：** 运行正确模型的 H100 与 RTX 4090 运营方都给出 pₖₛ > 0.999，远高于我们 0.95 的阈值。

**不诚实运营方被可靠地拒绝：**

- 运行 Llama-3.2-1B-Instruct 的运营方给出 pₖₛ ≈ 0.006
- 运行 FP8 量化变体的运营方给出 pₖₛ ≈ 0.150

两种不诚实策略都能与诚实行为清晰地区分开。

*图 5：诚实运营方（H100、4090）与不诚实运营方（FP8 量化、1B 模型伪装）的 KS p 值分布。清晰的分离使可靠检测成为可能。*

### **效率指标**

- **载荷大小：** 每 10k tokens 250-313 KB（k=20）
- **验证延迟：** 带 KV caching 时，10 个样本耗时 0.98 秒
- **验证算力：** 只需 S 次单 token 前向传播（与完整生成相比可忽略不计）
- **检测准确率：** 在我们的实验中，诚实与不诚实运营方之间达到 100% 分离

## **与其他验证方法的比较**

推理验证方法这一版图，反映的是安全保障、计算开销与实际可部署性之间的不同权衡。

### **TOPLOC**

TOPLOC 用多项式编码压缩 top-k 的最后一层激活值，达到了惊人的 1000 倍内存效率与 100 倍验证加速。然而在无需许可的场景中：

- **只校验 prefill** 使系统容易受推测解码攻击
- GPU 运营方可以用所声称的模型诚实地 prefill，却用更便宜的模型 decode
- 在受经济动机驱动的网络里，这就是首要攻击向量
- 通常需要对底层推理引擎做修改

### **I/O 指纹**

对中间激活值做哈希的方法有很强的检测能力，但面临若干挑战：

- 需要对推理引擎做**大量插桩**，并伴随 GPU 到 CPU 的数据搬运
- 对**不同 GPU 与 CUDA 版本之间的硬件非确定性**很敏感
- 通常只校验 **prefill**，漏掉 decode 期的伪装攻击
- 在生产推理框架中的原生支持有限

### **零知识证明**

zkSNARKs 这类密码学方法提供最强的理论保证，但对现代 LLM 推理而言仍然**慢几个数量级、贵几个数量级**。即便按乐观估计，生成 ZK 证明的成本也要比原始推理高 100 倍，这使其在生产部署上不切实际。

### **LOGIC**

LOGIC 把**在无需许可环境中的实际可部署性**放在优先位置：

- **抗 decode 期伪装：** 从生成阶段采样，而那里正是作弊的经济激励最强之处
- **零修改集成：** 开箱即用地支持所有主流推理引擎
- **硬件无关：** 在不同 GPU 类型、CUDA 版本与数值精度下都保持稳健
- **开销极低：** 每 10k tokens 约 250-313 KB，验证算力可忽略不计
- **统计保证：** 分布极为接近的学生模型可能需要更高的 k、更大的 S，或多提示词挑战

对于参与者有强烈经济动机压低成本的系统，decode 期的验证不是可选项。LOGIC 的设计正面应对了这一威胁模型，同时保持了实用的效率。

## **挑战与未来方向**

尽管 LOGIC 为去中心化推理验证提供了可上生产的方案，仍有若干领域值得进一步发展：

### **区分分布接近的学生模型**

蒸馏得极好、紧密复刻教师模型对数概率分布的学生模型，可能更难被区分。不过，如果某个学生模型在被评测的样本切片上产出统计上无法区分的分布，那么对那些上下文而言它的行为实际上就是等价的。缓解策略包括：

- 增大 k（每个位置取更多 token）
- 增大 S（抽取更多位置）
- 用多样化上下文做多提示词挑战
- 基于运营方历史的自适应采样

### **量化与压缩变体**

不同的量化方案（INT8、FP8、W8A8 等）与 KV-cache 压缩方法，可能需要对阈值做经验性调优。我们当前的实验覆盖了 FP8 量化，但优化技术的生态仍在持续演化。

### **自适应采样与重新验证**

网络模式、CUDA 版本差异、GPU 缺陷或其他环境因素，偶尔可能造成正当的数值漂移。自适应采样策略可以：

- 对 p 值处于边界的运营方提高采样密度
- 在做出最终信任决定之前，重新验证可疑样本
- 建立纵向的信任画像，而不是单条请求的一次性裁决

### **扩展到其他模态**

LOGIC 目前聚焦于文本型 LLM 推理，但其底层原则（验证输出分布而非精确数值）可以扩展到其他领域。多模态语言模型与基于 diffusion 的图像生成都产生输出分布，都可以用类似方式验证。

## **向前推进**

LOGIC 为可验证的去中心化推理提供了一条可上生产的路径。通过利用推理引擎本就在计算的对数概率分布，我们在算力和网络开销极小、且无需修改引擎的情况下，达成了强验证保证。

该方法对 decode 期伪装的抵御能力，使它特别适合那些经济激励天然鼓励压成本攻击的无需许可网络。

随着 AI 推理日益走向去中心化架构，LOGIC 这类实用的验证方法正在成为不可或缺的基础设施。我们希望这项工作有助于为开放推理网络中的信任机制建立标准，并支撑下一代无需许可的算力协议。
