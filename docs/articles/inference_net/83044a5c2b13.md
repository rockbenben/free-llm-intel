# 推理平台简介：监控、训练和部署自我改进的 AI 模型

S

Sam Hogan

## 引言

今天我们推出 [Inference platform](https://inference.net/register)，一个用于构建持续自我改进的 AI 模型的平台。

Inference platform 是一个全栈平台，把监控、评估、训练和部署合并进单一产品。它专门为那些想要优化生产环境 AI 应用的团队而构建，它不是通用目的的 AI 研究工具。

核心思路很简单：不去搭建那些试图逼近现实的合成环境，Inference platform 从你的应用里采样生产流量，并用它通过有监督微调来训练模型。你的生产数据就是你的训练环境。

今天，Inference platform 已经能够训练出 Specialized Language Models，它们能在成本低多达 95% 的情况下追平甚至超过前沿质量。

LLM-as-a-judge：各模型的平均质量得分

## Inference platform 如何工作

Inference platform 像一款普通的 LLM tracing 工具一样装进你的代码仓库。它能与现有的 OpenAI 兼容和 Anthropic 兼容的 provider 一起工作——只需要换掉你的 base URL 并加上几个请求头。Inference Gateway 位于你的应用与你的模型 provider 之间，负责记录、分析并存储生产流量。

用一条命令就能把 Inference platform 加到你的项目里。在你的项目根目录执行：

```
npm install -g @inference/cli && inf instrument
```

```
npm install -g @inference/cli && inf instrument
```

这条命令会使用一个 AI coding agent 来分析你的代码库，并完成必要的改动，让请求带上正确的元数据经由 Inference platform 路由。之后你照常运行你的应用。每一次 LLM 调用都会被捕获，并出现在 Inference.net 的控制台里。

```
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://api.inference.net/v1",
    api_key=os.environ["INFERENCE_API_KEY"],
    default_headers={
        "x-inference-provider-api-key": os.environ["OPENAI_API_KEY"],
        "x-inference-provider": "openai",
    },
)

response = client.chat.completions.create(
    model="gpt-4.1",
    messages=[{"role": "user", "content": "Hello, world!"}],
)

print(response.choices[0].message.content)
```

## Inference platform 的工作流

一旦流量开始流动，工作流就相当简单：

**从流量构建数据集。** Inference platform 把你录制下来的 LLM 调用变成训练数据集和评估数据集。真实流量意味着你的训练数据与你的模型实际会遇到的场景分布相匹配。

**用 LLM-as-judge 做评估。** 无法度量的东西就无法改进。Inference platform 帮你从已经拥有的数据出发搭建评估套件。你先为当前模型建立一个性能基线，然后以此为参照来衡量随后的每一次训练。

**训练。** Inference platform 的 Recipes 提供预先配置好的训练规则，包含一个基础模型、优化过的参数以及算力资源。平台负责基础模型选择、超参数和训练基础设施。评估会在训练之前、训练之中和训练之后自动运行，用来衡量质量。

**部署。** 训练好的模型部署到专属的 GPU 基础设施上。把应用切换到一个自定义模型只需要改一行代码。模型权重完全归你所有；可以在我们的基础设施上部署，也可以托管在你自己的私有 VPS 里。

Inference platform 的自我改进飞轮

从这里开始循环继续运转，由 Inference platform 管理整个训练循环。它摄取新的生产数据，生成训练与评估数据集，运行训练任务，并把产出的模型与生产基线做比较。新模型就绪之后，会被暂存起来等待最终评审与部署。

## 生产环境中的 Inference platform

Inference platform 的训练循环成本并不固定，取决于你所训练的基础模型规模以及训练所需的数据量。单次训练的费用从 25 美元一直到数千美元不等。Inference platform 已经在为生产环境里的自定义模型提供支撑：

- 面向专有编程语言的自我改进 coding 模型，已被一家公开上市的金融机构的数百名工程师使用
- 数据抽取模型，性能追平 Opus 4.6，端到端延迟 p50 为 150ms，成本只有它的 5%
- 卡路里估算模型，在质量、延迟和成本上都胜过前沿模型
- HTML-to-JSON 抽取模型，例如 [Schematron-8b](https://huggingface.co/inference-net/Schematron-8B)，被世界上一些最大的网页抓取公司使用
- deep research agent，在成本与准确率的 Pareto 前沿上超越了当前水平。

## Inference platform 与 RL 的对比

如今占据主流的后训练叙事，起步的地方就错了。你先花几周时间搭建一个环境，试图模拟你的模型部署之后要面对的真实工作。然后你花更多时间制定评分标准、加固 evals，并设法阻止模型学到错误的经验。训练结束之后你才发现，模型找到了某种办法去优化分数而不是优化工作本身，于是整个过程重新开始。

这很昂贵，很慢，而且恰恰脆弱在工程师最讨厌的那种方式上：你可以在沙箱里把每件事都做对，却仍然几乎学不到任何东西来说明系统一旦上了生产会如何表现。AI 系统不可能在真空中被优化。如果目标是改进一个生产系统，那么事实的来源就应该是生产本身。

我们构建 Inference platform，是因为我们认为 RL 当前所推崇的那些范式难得没有必要、产出很低，而且对大多数团队来说遥不可及。如果你正在生产环境里运行一个 AI 应用，你就已经在生成训练一个面向你的系统的前沿质量模型所需的数据了。而不用搭建 RL 环境就能捕获这些数据、进行评估并基于它训练的工具，在今天之前从来没有在单一地点同时存在过。

## 今天即可使用

Inference platform 今天以 public beta 形式开放。beta 期间由我们来承担训练与部署成本，所以如果你已经在生产环境里运行着一个应用或 agent，你就能免费体验完整的 observe-train-deploy 循环。

我们为 Inference platform 准备了很多东西。随着时间推移，Inference platform 会承担改进循环中更多的部分，缩短从真实流量到一个更好模型之间的距离。如果你的 AI 系统已经在生产环境里，你手上已有的就足够开始了。
