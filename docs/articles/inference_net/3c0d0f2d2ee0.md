现在是 2026 年夏天。几乎每个月都会发布一个新的前沿模型。每个模型都带着一组新的基准数字、一些 X 上的炒作，以及对在生产环境里跑 LLM 的团队来说那个挥之不去的老问题：我们该换吗？

大多数团队从来没有真正回答过它。诚实地回答意味着：构建一个能代表你真实流量的数据集，为你想要测试的每一家提供商打通 API 访问，写一份 rubric，搭起评判基础设施，烧掉 token 把它整个跑一遍，然后再解读结果。这是一周的工作量，每个模型、每个任务、每次有新东西发布都要来一遍。于是这个问题被搁置。几个月前基于一个价格点和感觉选定的模型继续跑着，因为在生产环境里换模型既*困难*又有风险。

而且风险是真实的。基准是别人任务上的平均值。一个模型可以霸榜，却依然在你的工具 schema、你的输出格式、你的边界情况上栽跟头。唯一真正重要的基准是你自己的流量，而在此之前，没有人有时间去跑它。

## 真实的生产流量才是最好的基准

AutoEvals 的设计目标是帮开发者找到适合某个任务或 agent 的*最佳模型*。不是某个你从没听说过的公开基准上的最佳——而是在你的用户上周发来的那些确切请求上表现更好。

接入 [Inference Gateway](https://docs.inference.net/get-started/record-first-call?utm_source=blog-introducing-autoevals&utm_medium=blog&utm_campaign=introducing-autoevals&utm_content=body-inference-gateway)（2 分钟即可），收集数据，在仪表盘上点一个按钮，几分钟后你就能得到一个明确的答案：你该用哪个模型，并附上质量、成本和延迟差异的真实数字。

**每次模型发布都变成白捡的增益，而不是家庭作业。** 当有新东西发布时，你不用再拿公告和一周的评测工作去权衡。午饭时跑一次对比，到下午就知道它对你有没有意义。

**切换不再可怕。** 推荐结果不是排行榜名次。它是你自己的流量，被重放、被打分，每个样本都可以翻看。在任何一个生产请求碰到新模型之前，你就能确切了解新模型相对于当前模型会如何处理请求。

**你不再为用不上的智能付费。** 大量任务正在被昂贵的模型悄悄过度服务。AutoEvals 为你展示针对你具体任务的质量-成本前沿，让你看清什么时候一个更便宜的模型也能给出同等水平的准确度。

## AutoEvals 在实践中如何运作

一次 AutoEval 分三步运行。它先对你的近期生产流量采样，再由一组候选模型重放这些请求。之后，LLM 评判器会为每个输出打两项分：质量，即模型完成该任务的好坏；相似度，即它的行为与你当前运行的模型有多接近。最后它把这些结果汇总成一个模型结论、关键发现和各模型摘要。

这两项分数合起来能告诉你切换有多安全。高质量加高相似度，就是可以直接换上就用的升级。高质量加低相似度，说明模型不错但行为不同，值得先仔细看一眼。当你确实想逐个检查输出时，Sample Viewer 会给你并排的模型回复，以及评判器为每个分数给出的理由。

![Sample Viewer 展示并排的模型回复，以及评判器对每个分数的理由](https://inference.net/assets/sample-viewer-BJ8XdMxg.png)

Sample Viewer：并排的模型回复，以及评判器对每个分数的理由

把你的流量送进 Inference 平台是唯一的准备工作，而且只是一次集成：把你的 LLM 调用通过我们的 Gateway 路由（我们的 CLI 可以自动为你的项目埋点），或者用我们的 tracing SDK 上报 trace。从此以后，比较模型就是一个按钮，切换就是一行改动。

## 在我们自己的 agent 上运行

我们在为别人构建 AutoEvals 之前，先为我们自己的 agent 构建了它，其中有两个发现真正改变了我们对模型选择的看法。

**模型代际之间的差距比你想象的大。** 我们的一个 GTM agent 已经在同一个口碑不错的模型上跑了好几个月。感觉挺好，直到我们对它跑了一次 AutoEval。成本只有零头的模型把它彻底碾压了：长程轨迹更好、对工具 schema 的遵循更严格、结果整体更精确。只因为我们没去看，就把更好的结果留在了桌上。

**有些任务存在能力天花板。** 在同一个任务上，最顶尖的前沿模型拿到了完全相同的质量分。越过某个能力水平之后，它们都只是在采取正确的动作，多付钱什么也买不到。一旦你能看见天花板，模型的选择就自己有了答案，而且它很少是最贵的那个选项。

![质量与成本的散点图，显示顶级模型以差别很大的价格收敛到相同的质量分](https://inference.net/assets/quality-cost-frontier-DV5SGtmK.png)

越过某个能力水平后，质量趋于收敛——多付钱什么也买不到

把这两个发现放在一起，结论就很难回避：如果你在用 LLM 构建应用，仅仅凭借模型发布的速度，你的应用本就该随着时间变得更准确*并且*更便宜。能抓住这种复利优势的团队，将是那些让评测变得毫不费力的团队。这就是我们做的东西。
