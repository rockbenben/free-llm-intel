AutoEvals 旨在帮助开发人员找到针对给定任务或代理的“最佳模型”。不是您从未听说过的公共基准测试中最好的 - 更好的是您的用户上周发送的确切请求。

**切换不再可怕。** 该推荐不是排行榜排名。这是您自己的流量，经过重播和判断，每个样本都可以检查。在单个生产请求触及新模型之前，您可以准确了解新模型与当前模型相比如何处理请求。

**您不再为不需要的智能付费。** 昂贵的模型悄悄地过度服务了许多任务。 AutoEvals 向您显示特定任务的质量成本边界，以便您可以了解何时更实惠的模型可以提供相同水平的精度。

## AutoEvals 在实践中如何工作

AutoEval 分三步运行。它首先对最近的生产流量进行采样，然后由一组候选模型重播。之后，LLM评委会对每个输出的质量（即模型完成任务的程度）和相似度（即其行为与您今天运行的模型的相似程度）进行评分。然后，它将这些结果总结为模型结论、主要发现和每个模型的摘要。

这两个分数一起告诉您开关的安全程度。高品质和高相似度是直接升级。高质量和低相似度意味着模型很好，但行为不同，因此首先需要仔细观察。当您确实想单独检查输出时，样本查看器会为您提供并排的模型响应以及法官对每个分数的推理。

在推理平台前获取流量是唯一的设置，也是一次集成：通过我们的网关路由您的 LLM 调用（我们的 CLI 可以自动检测您的项目），或使用我们的跟踪 SDK 报告跟踪。从此，比较型号就是一个按钮，切换就是单行更改。

## 在我们自己的代理上运行

在为其他人构建 AutoEvals 之前，我们先为自己的代理构建了 AutoEvals，两项发现真正改变了我们对模型选择的看法。

**模型代之间的差距比您想象的要大。**我们的一位 GTM 代理已经在同一个备受推崇的模型上运行了几个月。感觉很好，直到我们对其运行 AutoEval。模型的成本只是其一小部分，但它具有更好的长期轨迹、更严格的工具模式依从性以及更精确的全面结果。因为我们没有观察，所以我们留下了更好的结果。

**有些任务有技能上限。** 在同一任务中，顶级前沿模型获得了相同的质量分数。超过一定的能力水平后，他们都只是采取了正确的行动，付出更多的钱什么也买不到。一旦你看到了上限，模型的决定就会自行决定，而且它很少是最昂贵的选择。

![质量与成本散点图显示顶级模型以截然不同的价格收敛于相同的质量得分](https://inference.net/assets/quality-cost-frontier-DV5SGtmK.png)

超过一定的能力水平后，质量趋于一致——付出更多却买不到什么

将这两个发现放在一起，结论就很难回避：如果您使用LLM进行构建，随着时间的推移，您的应用程序应该变得更加准确*并且*便宜，仅从模型发布的速度来看。获得复合优势的团队将是那些可以毫不费力地进行评估的团队。这就是我们建造的。
