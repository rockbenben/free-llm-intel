# 专业LLM：您需要的模型尚不存在

S

Sam Hogan

## 引言

就在此刻，增长最快的那批 AI 原生公司内部正上演着一场静悄悄的变革。

不久前，Cursor、Harvey、Decagon、Cal AI 这样的公司还被轻视地归为「GPT 套壳」（GPT-wrappers）——它们的产品如此依赖 OpenAI 这类前沿实验室提供的模型，以至于很多人认为它们永远无法成为站得住脚的独立生意。某种程度上这说法是成立的：如果模型提供了这些产品赖以存在的能力，那产生出来的大部分价值，不正应当以某种方式回流到前沿实验室手里吗？

这种心态低估了这些公司想明白真相的速度：真正的资产不是模型，而是它们的用户正在生成的数据。如今，上面提到的每家公司都已经摆脱了对前沿实验室的依赖，训练出自己的语言模型，并用它们来驱动产品内部的核心功能。它们正在投入自有的团队和系统，为未来长期地提升模型能力。

这就是我们在 Inference.net 看到的未来。2026 年及以后，会有更多公司意识到，小型的、定制化的 LLM 只需花一小部分成本就能追平前沿水准。租用能力的日子已经进入倒计时。想要长期可防御性的公司，会拥有自己的模型，以及驱动这些模型的数据飞轮。

## Big Token

Opus 4.5、GPT-5.2、Gemini 3 这样的模型提供了横跨大量任务的惊人能力。这些巨无霸能写代码、解开几十年悬而未决的数学难题，还能用诗一般的语言谈论人类意识的本质。它们无疑正在以新奇而有趣的方式改变世界，这些模型带来的杠杆感几乎看不到上限——只有一个小约束：访问权限被「Big Token」——Anthropic、OpenAI 和 Google 的付费墙与政策挡在门外。

眼下你可以使用它们，只要付费。只要在它们的创造者眼里你表现得规矩，它们就乐意把这些精彩的能力按计量租给你。

做这些公司的客户，是个根基不稳的位置。如果你在它们的 API 上构建产品，你就落在了世界上某些最激进、最渴求增长的组织手里。它们的野心没有上限，没人知道模型性能什么时候会毫无征兆地退化，而你无处可去，只能投进它们竞争对手的爪牙之中。

这个陷阱有三重：

- 性能。模型会在悄无声息中改变。你调试好几天才意识到问题不在你的代码。没人知道模型性能什么时候会毫无征兆地退化。
- 价格。你的单位经济效益被它们的定价决策挟持。每周都会有一大笔比例的营收从你家大门被抬出去。
- 政策。服务条款毫无征兆地变更。本地（on-prem）部署要花费数千万，而且只对世界上最大的公司开放。

你在喂养它们的飞轮。你通过 OpenAI 或 Anthropic 发出的每一个请求，都是你白白交出去的宝贵数据。它们会用它来改进自己的模型。你的竞争对手同样在用这些 API，也从中受益。

这些数据不只是让它们把自己的模型做大，还让它们在属于你的领域里做专。它们看得清哪些垂直行业在产生最多的价值、哪些用例足够黏着、哪些市场值得进入。

这就是 Big Token 希望你生活在其中的世界：永远租用它们的模型，按 token 付费，然后祈祷它们别看上你的市场。

## DeepSeek 这场异端

这一切在 2024 年 12 月发生了变化。

开源 LLM，比如 DeepSeek V3 以及随后的 DeepSeek R1，对 Big Token 能够合理向客户收取的价格形成了巨大的下行压力。作为第一个真正可用的闭源前沿模型替代品，DeepSeek 给了有野心的公司一条现实路径，让它们能在生产环境里对自己产品所依赖的模型做到精细控制。

创业公司只需改动两行代码，就能把 OpenAI 的用量切换到开源模型上。规模更大的公司开始直接租用自家的 GPU，把这些模型部署在 vLLM 或 SGLang 上，扩大对自家 AI 基础设施的控制权。

DeepSeek 让开发者尝到了一点自由的滋味。

但它也带来了新问题。到 2025 年春天，Big Token 拿出了能力明显更强的模型。DeepSeek 更便宜，但在规模化之后仍然昂贵。而无服务器（serverless）推理提供商则开始强力推动团队签下为期一年的合同，仅仅是为了拿到运行一个生产级应用所必需的速率限制。

自己做选择：要么为最好的模型支付溢价；要么用更便宜的模型、承受质量下滑，然后祈祷你的客户不会跑去做第一个选项的那家竞争对手那边。要么付钱给收账人，要么让你的产品被划成 B 档。

又或者领悟到，质量不在底层模型里，而在底层数据里。在你的数据里。

## 构建你的模型护城河

2026 年将是小型、专用、前沿质量的 LLM 的一年。你会用几十年来软件被造出来的同样方式去构建它：从用户身上观察，然后不知疲倦地迭代。

这就是我们所说的飞轮。核心循环是这样运转的：

- 你从一个通用模型起步，由它驱动你的产品。
- 用户与它交互。
- 这些交互产生数据。
- 你用这些数据训练一个专用模型。
- 专用模型表现更好。
- 更好的表现吸引并留住用户。
- 更多用户，更多数据。循环加速。

这是一条护城河。不是靠品牌认知、网络效应或监管俘获堆起来的护城河，而是靠数据筑成的护城河——没有你的应用和你的用户，这些数据根本无法被重新创造出来。

竞争对手明天就能从同一个基础模型起步，也能融到比你更多的钱。但他们变不出你靠几个月的生产流量和用户反馈积累起来的那个数据集。而如果你的改进速度比他们追赶的速度更快，差距只会越拉越大。

这里有一点是大多数团队没意识到的：只要有用户，你就已经在生成这些数据了。这是容易的部分。更难的部分是用这些数据建起一个真正有效的飞轮，让它随时间把价值以复利的方式回注到你的公司里。

## 作为产品哲学的飞轮

构建飞轮不只是一个技术决策，它是一整套产品哲学。两个问题应当指导每一个决策：

- 你如何设计功能，让高质量数据作为使用过程的自然副产品被生成出来？
- 你如何激励高价值用户提供高质量的反馈？

每一次交互都成了一次学习的机会：

| 产品类型 | 捕获的信号 | 工作原理 |
| --- | --- | --- |
| 卡路里记录应用 | 带标签的纠正样本 | 用户修正 AI 的估算，为再训练创造出一份真值（ground truth）数据 |
| 编码助手 | 接受/拒绝的模式 | 追踪哪些建议被开发者接受、修改或拒绝 |
| 客服机器人 | 解决率指标 | 统计哪些回复解决了问题、哪些触发了向人工的升级 |

每一条被接受或被拒绝的代码建议。每一张被解决或被升级的客服工单。每一次被修正的卡路里估算。全是信号。都是给你的。

并非所有用户反馈都同样有价值。一位注册营养师在修正卡路里估算，比一个随手瞎猜的普通用户更值钱。资深工程师的代码改动，比一个刚开始学编程的人提供的信号更多。

你的工作有一部分是搞清楚谁是你的高价值用户，并设计出既不招人烦又能收到他们输入的反馈机制。卡路里修正流程应当让人觉得像一个功能，而不是一份问卷。代码接受信号应当是隐式的，而不是弹一个「这个有用吗？」的弹窗。

你的产品就是飞轮。每一个设计决策，要么在产生有价值的数据，要么就没有。下一个问题是，一旦你拿到了这些数据，你要拿它做什么。

## 后训练就是你所需的一切

多年来，前沿实验室成功地推广了一种叙事：训练模型难得不可能。你需要一支博士团队、数月乃至数年的迭代，以及数百万美元的 GPU 算力。

一个很方便的故事。却越来越不符实。

### 后训练到底意味着什么

「后训练」（post-training）这个术语指的是一整套用于增强既有模型能力的技术。你拿一个现成的开源基础模型，比如 DeepSeek、Nemotron 或 Gemma，教它新把戏。两种最流行的技术是有监督微调（SFT），也就是给模型展示你想要的样例；以及强化学习（RLFT），也就是对好的输出给予奖励。通常两者都会用上。

最常见的模式是：先用 SFT，把知识从一个像 GPT-5 这样的前沿通用模型，蒸馏进一个像 Nemotron 9B 这样的小模型。GPT-5 挺懂得怎么把你的任务做好。你用 GPT-5 生成上千个样例，然后训练 Nemotron 去模仿这些输出。一个 9B 参数的模型，用高质量蒸馏数据做 SFT，在一个具体任务上能够追平 GPT-5 的质量。

得到的是一个专用模型。不是那种能写诗、调试代码、还能替你规划假期的通用助手，只是一个把一件事做得非常好的模型。也许它从发票里抽取结构化数据，也许它给医学影像写描述，也许它根据邮件往来给销售线索打分。

接下来你可以用 RLFT——这是训练一个模型、让它超出前沿模型能力的最可行路径。用 SFT 时，你的上限从根本上被训练样例的质量封住：学生只能和教它的老师一样好。但用 RLFT，你奖励的是结果，而不是让它模仿示范。模型学会直接为你真正在意的东西做优化，而不是学会听起来像一个在为你在意的东西做优化。

### 经济性

你可以在大约一小时内、花几百美元训练出一个专用模型，这里面包含了数据生成、算力和评测的成本。要拥有驱动你产品的核心能力，这就是你需要的全部。

所谓拥有，指的是：

- 权重存放在你的基础设施上
- 你想怎么改它们就怎么改
- 你不受任何人的服务条款约束
- 模型是你的资产，归你所有。

### 为什么是现在？

这件事几年前就已经可行，只是直到最近，进入门槛才低到大多数团队都能采纳的程度。此前缺了几样东西。

评测。LLM 评测是真难。你怎么知道自己的定制模型到底好不好？几十年来，这只是研究者才会操心的问题。工具和最佳实践花了一段时间才跟上。今天，大多数团队会组合使用 LLM-as-judge（由一个前沿模型给你的模型输出打分）和黄金数据集（golden dataset，人工精心整理、你确信正确的一组样例）。第一种方式能扩展规模，第二种提供真值（ground truth）。两者你都需要。

数据生成。训练专用模型有很大一部分工作，是从前沿模型创造出训练数据。跑几十万次推理调用，意味着要搭 GPU、管理推理批次、自建推理 API 或与推理 API 集成，还要把数据整理成训练需要的格式。而就算做完了这一切，你怎么知道你的合成数据真的代表了你正在训练的那个任务？GPT-5、Claude、Kimi K2 以及其他模型近期的进步，给了我们一个可靠的方法，为各种各样的任务生成训练数据。老师变强了，学生也就能够跟上。

心智模型。团队把模型当成静态资产：训练一次、部署、然后走人。但产品在演化，用户在变，功能在不断加入。你的模型在第六个月看到的请求分布，跟第一个月完全不是一个样子。模型在慢慢退化，直到客户开始抱怨才有人注意到。

新的心智模型是持续改进。你监控生产流量，把模型正在看到的东西与它被训练时的数据做对比。当分布发生漂移，你就生成新数据并再训练。模型成了你系统里一个活着的部分，而不是一件冻结的产物。

## 构建你的模型飞轮

你想把数据飞轮收在自己手里，而不是把它捐给 Big Token。具体要怎么做？

核心要求是：你的训练流水线需要能够访问生产数据。推理和训练不必位于同一个系统里，但放在一起有帮助。当生产日志直接流进训练基础设施，你就消掉了搬移数据、重新格式化、维持各处同步的这些摩擦。循环越紧，你迭代得越快。

你需要一些能自动监控并分析生产流量的子系统：

- 分布漂移，即你的模型看到的请求开始与它被训练时的数据变得不同
- 值得深入排查的离群样本
- 用户给出的高价值修正

这些系统应当标记出问题、浮现出机会，而不需要有人去手工复核每一个数据点。有一些人工监督没问题。但如果这个循环需要人时刻盯着，它撑不过与现实的接触。

再训练的节奏取决于你的应用和数据量，可以是每天、每周或每月。要点在于它是一个过程，不是一个事件。你不是在训练一个模型，而是在运营一个模型。

## 你准备好拥有自己的模型了吗？

如果你在构建一个 AI 原生产品，却没有在考虑模型归属这件事，那你就是把价值留在了桌上。

那些身处增长最快公司里的顶尖团队，已经在训练专用模型来驱动自己的核心工作流。这并不意味着彻底抛弃前沿模型。大多数公司会把专用模型和通用模型并行运行：专用模型负责那些范围受限、量又大、成功标准能被清晰定义的任务；通用模型负责编排、边界情况，以及任何需要广博世界知识的活儿。

冷启动的路径很直接。从通用模型开始，验证你的产品想法，生成最初的训练数据。当你在 API 调用上每月花到 1,000 美元，你的量就已经足够可以考虑你的第一个专用模型了。

你不需要把整片海烧开。挑出你量最大、约束最明确的那个任务，从它开始。这就是你筑起自己护城河的地方。

## 我们学到了什么

我们不是靠抽象推演得出这些信念的。过去这一年，我们在为 Profound、Cal AI 这样的公司训练专用模型，学着什么有效、什么无效。上面描述的这些模式，是从运营真实的生产系统、每月处理数万亿 token 之中提炼出来的。

我们见过一个卡路里记录应用把推理成本降低 80%，同时准确率提升 15%，因为用户的修正被直接喂进了模型改进里。我们看着一个编码助手在三轮再训练之后，从「偶尔有点用」变成「70% 的情况下会被接受」。飞轮是真的，经济性也是真的。
