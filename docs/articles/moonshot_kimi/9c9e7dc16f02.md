# Kimi K2：开放的 agentic 智能

**更新（0905）**：我们更新了权重，增强了 **agentic 编程** 能力并支持 **256K 上下文**，[点此查看](https://huggingface.co/moonshotai/Kimi-K2-Instruct-0905)

Kimi K2 是我们最新的 Mixture-of-Experts 模型，激活参数 320 亿，总参数 1 万亿。在非思考型模型中，它在前沿知识、数学和编程上都达到业界领先水平。但它走得更远——围绕 agentic 任务做了细致优化，Kimi K2 不只是回答问题，它还会动手做事。

而现在，它已经触手可及。今天我们开源：

- **Kimi-K2-Base：** 基础模型，适合希望完全掌控 fine-tuning 与定制方案的研究者和构建者，是一个很强的起点。
- **Kimi-K2-Instruct：** 后训练模型，最适合即插即用的通用聊天和 agentic 体验。它是一个无需长时间思考的反射级模型。

有了 Kimi K2，先进的 agentic 智能比以往更开放、更易得。我们很期待看到你做出什么。

### 用例

把工具交给 Kimi K2，再描述你的任务。

它会自动理解怎么使用这些工具并完成任务。你不需要为 agentic 应用编写任何复杂的工作流。

想象一下用 Kimi K2 通过 Salary Data Analysis 示例来调研远程办公薪资：16 次 IPython 调用生成了统计数据、可视化图表，以及一个可交互的洞察网页。深入 Stanford NLP Genealogy，让 Kimi K2 生成一个交互式站点，整个过程经过 5 次网页搜索、4 次浏览、3 次点击、5 次滚动、6 次编辑和 2 次部署。或者用它规划你梦想中的 2025 年伦敦 Coldplay 巡演，它通过 17 次无缝衔接的工具调用，串起搜索、日历、Gmail、航班、Airbnb 和餐厅预订，把计划做了出来。

把 Kimi K2 带进你的命令行。它会编辑文件，也会执行命令。

Kimi K2 理解你的环境，判断该做什么，然后顺畅地执行。

需要说明的是，终端只展示每条轨迹的摘要。在每一个示例中，Kimi K2 都在幕后调度多个工具和命令来完成复杂目标。例如，Kimi K2 能用 JavaScript 自动化 Minecraft 开发：它管理渲染，运行并调试测试用例，在失败时抓取日志，并不断改进代码直到所有测试通过。做前/后范数分析时，Kimi K2 使用 Weights & Biases（wandb）数据读取器从语言模型实验中提取洞察，并生成一份打磨完善的分析报告。把 Flask 项目迁移到 Rust 时，Kimi K2 会系统地重构代码库，并运行性能基准测试，以确保结果稳健。

### Kimi K2 基准测试

### 开放的 agentic 智能

预训练是 [Agentic Intelligence](https://ysymyth.github.io/The-Second-Half/) 的关键基础，它建立起先验，让强化学习（RL）的探索变得可处理、高效且可泛化。然而，正如 Ilya Sutskever 也观察到的，人类数据是一种有限的「化石燃料」，其增长速度远远落后于算力的增长。这让预训练阶段的 **token 效率** 成为 AI 缩放定律中的一个新的关键系数。

后训练在「[经验时代](https://storage.googleapis.com/deepmind-media/Era-of-Experience%20/The%20Era%20of%20Experience%20Paper.pdf)」（David Silver、Richard Sutton，2025）中举足轻重。在这个时代，LLM 越来越多地从自身生成的交互中学习，获得的奖励使它们摆脱人类数据的限制，从而超越人类能力。

Kimi K2 正是由这些洞见锻造而来。

#### MuonClip 优化器

严谨地说，在预训练数据量近似有限、模型配置固定的前提下，token 效率更高的优化器能产生更多智能。我们此前的工作 [Moonlight](https://github.com/MoonshotAI/Moonlight) 已经证明，[Muon](https://kellerjordan.github.io/posts/muon/) 优化器在 LLM 训练中显著优于广泛使用的 AdamW。

Kimi K2 的目标是把 Moonlight 进一步做大，后者采用了与 DeepSeek-V3 相似的架构。基于缩放定律分析，我们减少了 head 数量以提升长上下文效率，并提高 MoE 稀疏度以获得更高的 token 效率。在扩大规模的过程中，我们遇到一个持续的难题：注意力 logit 爆炸导致的训练不稳定。在我们的实验里，这个问题在 Muon 上更频繁，在 AdamW 上则较少。已有的方案，例如 logit soft-capping 和 query-key normalization，都不够用。

为此，我们引入 MuonClip 优化器，用我们提出的 qk-clip 技术改进 Muon。具体来说，qk-clip 在 Muon 更新之后直接重新缩放 query 和 key 投影的权重矩阵，从源头控制注意力 logit 的量级，从而稳定训练。query 和 key 投影的缩放方式如下：

$q_i = \eta^{\alpha} W_q x_i$

$k_i = \eta^{1-\alpha} W_k x_i$

其中 $\alpha$ 是平衡超参数，于是注意力 logit 变为：

$(\eta^{\alpha} q_i)^\top (\eta^{1-\alpha} k_j) = \eta\, q_i^\top k_j$

自适应因子 $\eta$（阈值为 $t$）在每一步之后根据该步的最大注意力 logit 设定：

$\eta = \min(\frac{t}{\displaystyle\max_{i,j}\bigl(q_i^\top k_j\bigr)}, 1)$

其中 $t$ 是预先设定的阈值。这是一项通用技术，或许也能用于其他需要稳定化的场景。

实验表明，MuonClip 能有效防止 logit 爆炸，同时保持下游任务表现。实践中，Kimi K2 用 MuonClip 在 15.5T token 上完成预训练，训练全程零 spike，说明 MuonClip 是稳定开展大规模 LLM 训练的可靠方案。

#### Agentic 能力

Kimi K2 增强的 agentic 能力来自两个重要方面——大规模 agentic 数据合成与通用强化学习。

**面向工具使用学习的大规模 agentic 数据合成：** 为了让模型掌握复杂的工具使用能力，我们搭建了一条受 ACEBench 启发的完整流水线，可规模化地模拟真实世界的工具使用场景。我们的方法系统地演化出数百个包含数千个工具的领域——既有真实的 MCP（Model Context Protocol）工具，也有合成工具——然后生成数百个拥有不同工具集的 agent。

所有任务都基于 rubric，因而评测可以保持一致。agent 与模拟环境和用户 agent 交互，构造出贴近真实的多轮工具使用场景。由 LLM 担任评委，按任务 rubric 评估仿真结果，筛出高质量训练数据。这条可扩展的流水线产出多样且高质量的数据，为大规模拒绝采样和强化学习铺平了道路。

![Kimi K2 agentic 数据合成流程](https://kimi-file.kimi.ai/prod-chat-kimi/kfs/4/4/2026-07-13/d9af7svf2ena62011o3g?x-tos-process=image%2Fauto-orient%2C1%2Fstrip%2Fignore-error%2C1)

**通用强化学习：** 关键难题在于把 RL 用到既有可验证奖励、又有不可验证奖励的任务上。可验证任务的典型例子是数学和竞赛编程，而撰写研究报告通常被视为不可验证。我们的通用 RL 系统不局限于可验证奖励，而是采用自我评判机制：模型充当自己的批评者，为不可验证任务提供可扩展、基于 rubric 的反馈。

与此同时，我们用在策略 rollout（on-policy rollout）配合可验证奖励，持续更新 critic，让 critic 对最新策略的评估准确度不断提升。这可以看作是用可验证奖励来改进对不可验证奖励的估计。

### Kimi K2 快速上手

#### 在 [kimi.com](https://www.kimi.com/en) 上试用 Kimi K2

从今天起，Kimi 的网页端和移动端用户都可以免费选用新的 Kimi K2 模型。目前，网页端和应用端的 MCP 功能仍在开发中，我们希望在未来几周内开始逐步开放。在此期间，欢迎你试用我们的 Researcher，抢先感受它的 agentic 能力。请注意，Kimi K2 目前还不支持视觉功能。

#### 通过 API 使用 Kimi K2

Kimi 平台提供兼容 OpenAI/Anthropic 的接口，可以很方便地把现有应用迁移到 Kimi K2。我们鼓励开发者探索我们的工具调用 API 来构建 agent 应用。详细信息请访问 [platform.kimi.com](https://platform.kimi.com/)。

#### 自行部署 Kimi K2

我们建议在以下推理引擎之一上运行 Kimi K2：vLLM、SGLang、KTransformers 或 TensorRT-LLM。详细部署说明请参阅我们的 [GitHub 仓库](https://github.com/MoonshotAI/Kimi-K2?tab=readme-ov-file#4-deployment)。

#### 下一步计划

Kimi K2 为开放的 agentic 智能打下了坚实基础，但通用 agent 还需要更高级的能力，例如思考和视觉理解。我们计划在未来为 Kimi K2 补上这些能力。

#### 局限

在内部测试中，我们发现当前 Kimi K2 模型存在一些局限。面对高难度推理任务或工具定义不清晰时，模型可能生成过多 token，有时会导致输出被截断或工具调用不完整。此外，启用工具使用后，模型在某些任务上的表现可能下降。构建完整软件项目时，一次性提示的效果不如在 agentic 框架下使用 K2。我们正在后续版本中着手解决这些问题，也期待收到更多反馈。
