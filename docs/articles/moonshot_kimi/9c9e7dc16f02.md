# Kimi K2：开放代理智能

**更新(0905)**：我们更新了权重，增强了**代理编码**并支持**256K上下文**，[参见此处](https://huggingface.co/moonshotai/Kimi-K2-Instruct-0905)

Kimi K2 是我们最新的 Mixture-of-Experts 模型，拥有 320 亿个激活参数和 1 万亿个总参数。它在非思维模型的前沿知识、数学和编码方面实现了最先进的性能。但它更进一步——针对代理任务进行了精心优化，Kimi K2 不仅仅是回答；它起作用了。

现在，它触手可及。今天，我们开源：

- **Kimi-K2-Base：** 基础模型，对于想要完全控制微调和定制解决方案的研究人员和构建者来说是一个良好的开端。
- **Kimi-K2-Instruct：** 经过训​​练的模型最适合即插即用、通用聊天和代理体验。这是一款无需长时间思考的反射级模型。

借助 Kimi K2，先进的代理智能比以往任何时候都更加开放和易于访问。我们迫不及待地想看看您构建了什么。

### 用例

为 Kimi K2 提供您的工具并描述您的任务。

它会自动理解如何使用工具并完成工作。您不必为代理应用程序编写任何复杂的工作流程。

想象一下，使用 Kimi K2 通过薪资数据分析示例来探索远程工作薪资，其中 16 个 IPython 调用生成统计数据、可视化和洞察的交互式网页。深入研究斯坦福 NLP 谱系，让 Kimi K2 通过 5 次网络搜索、4 次浏览、3 次点击、5 次滚动、6 次编辑和 2 次部署来生成一个交互式网站。或者使用 Kimi K2 计划您梦想的 2025 年伦敦酷玩巡回演唱会，它通过 17 个无缝工具调用（涵盖搜索、日历、Gmail、航班、Airbnb 和餐厅预订）为您制定计划。

将 Kimi K2 添加到命令行。它编辑文件。它运行命令。

Kimi K2 了解您的环境，决定采取哪些行动，并无缝执行它们。

为了清楚起见，终端仅显示每个轨迹的摘要。在每个示例中，Kimi K2 在幕后编排多个工具和命令来完成复杂的目标。例如，Kimi K2 可以用 JavaScript 自动化 Minecraft 开发：它管理渲染、运行和调试测试用例、捕获失败日志，并迭代改进代码，直到所有测试成功。对于前/后范数分析，Kimi K2 使用权重和偏差 (wandb) 数据读取器从语言模型实验中提取见解并生成完善的分析报告。当将 Flask 项目转换为 Rust 时，Kimi K2 系统地重构了代码库并运行性能基准测试以确保稳健的结果。

### 开放代理情报

预训练是[代理智能](https://ysymyth.github.io/The-Second-Half/) 的重要基础，它建立了使强化学习 (RL) 探索易于处理、高效且可推广的先验。然而，正如 Ilya Sutskever 也观察到的那样，人类数据是一种有限的“化石燃料”，其增长远远落后于计算的速度。这使得预训练期间的**代币效率**成为人工智能缩放法则中的新关键系数。

后期培训在“[体验时代](https://storage.googleapis.com/deepmind-media/Era-of-Experience%20/The%20Era%20of%20Experience%20Paper.pdf)”中至关重要（David Silver、Richard Sutton，2025）。在这个时代，LLM越来越多地从自己产生的互动中学习，获得奖励，使他们摆脱人类数据的限制，并使他们超越人类的能力。

Kimi K2 正是基于这些见解而打造的。

#### MuonClip 优化器

如果没有严格的要求，给定一个近似有限的预训练数据集和一个固定的模型配置，一个更高效的优化器会产生更多的智能。我们之前的工作 [Moonlight](https://github.com/MoonshotAI/Moonlight) 已经证明，[Muon](https://kellerjordan.github.io/posts/muon/) 优化器在 LLM 训练方面远远优于广泛使用的 AdamW 优化器。

Kimi K2 旨在进一步扩展 Moonlight，它采用类似于 DeepSeek-V3 的架构。基于缩放定律分析，我们减少了头的数量以提高长上下文效率，并增加 MoE 稀疏性以提高令牌效率。在扩大规模的过程中，我们遇到了一个持续的挑战：由于注意力逻辑爆炸导致训练不稳定，在我们的实验中，Muon 更频繁地出现这个问题，而 AdamW 则较少出现这个问题。现有的解决方案（例如 logit 软上限和查询键规范化）被发现不足。

为了解决这个问题，我们引入了 MuonClip 优化器，它通过我们提出的 qk-clip 技术改进了 Muon。具体来说，qk-clip 通过在 Muon 更新后直接重新调整查询和关键投影的权重矩阵来稳定训练，从而在源头控制注意力逻辑的规模。具体来说，查询和关键投影的缩放比例如下：

$q_i = \eta^{\alpha} W_q x_i$

$k_i = \eta^{1-\alpha} W_k x_i$

其中 $\alpha$ 是平衡超参数，因此注意力 logit 变为：

$(\eta^{\alpha} q_i)^\top (\eta^{1-\alpha} k_j) = \eta\, q_i^\top k_j$

自适应因子$\eta$（阈值$t$）在每一步之后根据该步骤中的最大注意力logit设置：

$\eta = \min(\frac{t}{\displaystyle\max_{i,j}\bigl(q_i^\top k_j\bigr)}, 1)$

其中$t$是预先设定的阈值。这是一种通用技术，可以应用于其他稳定用例。

我们的实验表明，MuonClip 可以有效防止 logit 爆炸，同时保持下游任务性能。在实践中，Kimi K2 使用 MuonClip 在 15.5T 令牌上进行了零训练峰值的预训练，证明 MuonClip 是稳定、大规模 LLM 训练的稳健解决方案。

#### 代理能力

Kimi K2增强的代理能力源于两个重要方面——大规模代理数据合成和通用强化学习。

**用于工具使用学习的大规模代理数据合成：** 为了教授模型复杂的工具使用功能，我们开发了一个受 ACEBench 启发的综合管道，可大规模模拟真实世界的工具使用场景。我们的方法系统地发展了数百个包含数千种工具的领域——包括真正的 MCP（模型上下文协议）工具和合成工具——然后生成数百个具有不同工具集的代理。

所有任务均基于评估标准，从而实现一致的评估。代理与模拟环境和用户代理交互，创建真实的多回合工具使用场景。LLM评委根据任务标准评估模拟结果，筛选高质量的训练数据。这种可扩展的管道生成多样化的高质量数据，为大规模拒绝采样和强化学习铺平了道路。

![Kimi K2 代理数据合成工作流程](https://kimi-file.kimi.ai/prod-chat-kimi/kfs/4/4/2026-07-13/d9af7svf2ena62011o3g?x-tos-process=image%2Fauto-orient%2C1%2Fstrip%2Fignore-error%2C1)

**一般强化学习：** 关键挑战是将强化学习应用于具有可验证和不可验证奖励的任务；可验证任务的典型例子是数学和竞赛编码，而撰写研究报告通常被视为不可验证。除了可验证的奖励之外，我们的通用强化学习系统还使用一种自我判断机制，其中模型充当自己的批评者，为不可验证的任务提供可扩展的、基于规则的反馈。

同时，通过具有可验​​证奖励的on-policy rollout来不断更新critic，使critic不断提高对最新政策的评估准确性。这可以被视为使用可验证奖励来改进对不可验证奖励的估计的一种方式。

### Kimi K2 入门

#### 在 [kimi.com](https://www.kimi.com/en) 上尝试 Kimi K2

从今天开始，Kimi 网络和移动用户可以免费选择和使用新的 Kimi K2 型号。目前，我们的 Web 和应用程序 MCP 功能仍在开发中。我们希望在未来几周内开始推出它们。同时，欢迎您尝试我们的研究人员，以尽早了解其代理功能。请注意，Kimi K2 尚不支持视觉功能。

#### 通过 API 使用 Kimi K2

Kimi 平台提供 OpenAI/Anthropic 兼容接口，可让您的现有应用程序轻松适应 Kimi K2。我们鼓励开发人员探索我们的工具调用 API 来构建代理应用程序。详细信息请访问[platform.kimi.com](https://platform.kimi.com/)。

#### 自行服务 Kimi K2

我们建议在以下推理引擎之一上运行 Kimi K2：vLLM、SGLang、KTransformers 或 TensorRT-LLM。有关详细的部署说明，请参阅我们的 [GitHub 存储库](https://github.com/MoonshotAI/Kimi-K2?tab=readme-ov-file#4-deployment)。

#### 接下来是什么

Kimi K2 是开放代理智能的坚实基础，而总代理则使用更高级的功能，例如思维和视觉理解。我们计划将来将这些添加到 Kimi K2 中。

#### 限制

在我们的内部测试中，我们发现了当前 Kimi K2 型号的一些局限性。当处理困难的推理任务或不明确的工具定义时，模型可能会生成过多的标记，有时会导致输出被截断或工具调用不完整。此外，如果启用工具使用，某些任务的性能可能会下降。构建完整的软件项目时，与在代理框架下使用 K2 相比，一次性提示会导致性能下降。我们正在努力在未来的版本中解决这些问题，并期待更多反馈。
