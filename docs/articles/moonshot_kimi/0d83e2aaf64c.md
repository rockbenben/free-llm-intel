[试用 Kimi K3](https://www.kimi.com/en)

今天，我们发布 Kimi K3——这是我们能力最强的模型。Kimi K3 是一个 2.8 万亿参数的模型，构建在 Kimi Delta Attention 与 Attention Residuals 之上，具备原生视觉能力和 100 万 token 的上下文窗口。它是全球首个开放的 3T 级模型，面向长程编程、知识工作与推理的前沿智能而设计。

虽然整体表现仍落后于最强的闭源模型 Claude Fable 5 和 GPT 5.6 Sol，但 Kimi K3 在我们的评测套件中展现出前沿水平，且始终优于其他受测模型。

Kimi K3 现已在 [Kimi.com](https://www.kimi.com/en)、[Kimi Work](https://www.kimi.com/en/products/kimi-work)、[Kimi Code](https://www.kimi.com/code/en) 和 [Kimi API](https://platform.kimi.com/) 上线。发布时，Kimi K3 默认使用最大思考强度，低强度和高强度模式将在后续更新中推出。我们正与推理合作伙伴和开源维护者紧密协作，对齐技术细节，确保在整个生态中可靠上线。完整模型权重将于 2026 年 7 月 27 日前发布。关于架构、训练和评测的更多细节，将随 Kimi K3 技术报告一同发布。

## 开放的 3T 级模型

Kimi K3 是首个参数规模达到 2.8 万亿的开放模型。它标志着 Kimi 在规模前沿持续冲刺的最新一步：过去 12 个月中有 9 个月，Kimi 的模型都占据着开放模型规模的上限。

Kimi K3 构建在 Kimi Delta Attention（KDA）与 Attention Residuals（AttnRes）之上，这两项架构更新旨在改善信息在序列长度和模型深度上的流动方式。我们还提高了 Mixture of Experts（MoE）的稀疏度，配合 Stable LatentMoE 框架，896 个专家中实际激活 16 个。再加上精炼过的训练与数据配方，这些结构改动使整体扩展效率相比 Kimi K2 提升约 2.5 倍，让模型能更有效地把算力转化为智能。

## 编程

Kimi K3 具备很强的长程编程能力。它只需极少的人工监督，就能维持长时间的工程会话、在庞大的代码库中穿行，并调度终端工具。

Kimi K3 同样擅长融合软件工程与视觉推理的任务——它利用截图和视觉信息来优化游戏开发、前端和 CAD 工作。

下面的案例研究展示了 Kimi K3 的编程能力如何转化为开放式软件创作与科学研究。

### 内核优化

我们测试了各模型优化 GPU kernel 的能力。每个模型在完全相同的沙箱中独立工作，最多有 24 小时对四项任务做 profile、重写和基准测试，这些任务涵盖 AttnRes、KDA，以及一个 512 head 维度的 MLA kernel，运行环境包括 NVIDIA Hopper GPU 和来自另一家厂商的 GPGPU。Kimi K3 的表现与 Fable 5（带 fallback）相当，并大幅优于 Opus 4.8、GPT 5.6 Sol 和 GPT 5.5。

Claude Fable 5 由第三方评测，其结果可能包含 fallback 行为。在大多数模型上，部分轨迹包含一些小的、可接受的精度取巧，仍在我们允许的数值误差范围内。GPGPU 指用于图形渲染之外计算任务的通用 GPU。

在 Kimi K3 开发的后期，团队大部分 kernel 优化工作都是由 Kimi K3 的一个早期版本完成的。

### GPU 编译器开发

我们进一步测试了 Kimi K3 能否从零构建一套 GPU 编程系统。Kimi K3 开发出 MiniTriton——一个紧凑的、类 Triton 的编译器，在 MLIR 之上有自己的 tile 级 IR 层、优化 pass 以及 PTX 代码生成流水线。在受支持的 roofline 基准上，MiniTriton 的性能与 Triton 和 torch.compile 持平甚至更好——在部分工作负载上胜过 Triton。除微基准之外，MiniTriton 还能支撑端到端的 nanoGPT 训练并稳定收敛，损失曲线紧贴参考曲线，仅有很小的偏差——在真实负载上验证了整条流水线。这些结果表明，Kimi K3 能构建一个连贯的端到端编译器——从 DSL 前端、IR pass 一直到 PTX 代码生成和运行时——而不是零散的内核；它从零实现的 Tensor Core 路径已经可以与 Triton 经过大量优化的技术栈相比肩。

### 游戏开发与数字创作

Kimi K3 把强大的 3D 推理、编程和视觉能力结合起来，把概念、图像和视频变成可完整游玩的交互体验。Kimi K3 在代码与实时截图之间无缝迭代，实现了真正的「视觉在环」——即时看到并改进输出。

### 芯片设计

作为早期的概念验证，Kimi K3 设计了一颗芯片，用来运行基于它自身架构构建的 nano 模型。在一次 48 小时的自主运行中，K3 在 Nangate 45nm 库上使用开源 EDA 工具完成了这颗芯片的构建、优化和验证。在 4 mm² 的面积内，该芯片以 100 MHz 收敛时序，在仿真中维持超过 8,700 tokens/s 的解码吞吐，容纳 146 万个标准单元、0.277 MB SRAM，以及一个带融合反量化的 INT4 MAC 阵列。一颗由模型设计、为模型服务的芯片，体现了 K3 的长程 agentic 能力。

### 面向科研的编程

Kimi K3 打通了科学文献与可执行代码，能自主实现、验证并分析复杂的计算研究工作流。

在一个案例中，Kimi K3 用大约两小时完成了资深研究者通常需要一到两周的工作。为复现计算天体物理中的 I–Love–Q 普适关系，它审阅并交叉验证了 20 多篇论文，实现了完整的数值流水线，评估了 300 多个状态方程，找出了已发表公式中的不一致之处，生成了 3,000 多行 Python 代码，并产出一个可交互的 HTML dashboard 用于探索结果。

### Widgets 与 Dashboard

在 Kimi Work 中，我们推出两项新功能——Widgets 和 Dashboard——让与 Kimi K3 的交互更可视化、更持久。Widgets 让你直接在对话中生成可交互组件，并可连接本地数据或外部插件实现持续更新。Dashboard 则把你最关心的 widget 汇聚到一个持久、个性化的视图中，按主题、项目或目标组织起来。

### 视频编辑

Kimi K3 擅长动效设计、动画和视频剪辑，因为它的原生多模态架构能在同一个模型内理解文本、图像和视频。

在一个例子中，K3 为自己架构制作了一支 3Blue1Brown 风格的动效解说视频，把技术思路转化为动画示意图和转场。

### 架构与基础设施

Kimi K3 构建在 Kimi Delta Attention（KDA）与 Attention Residuals（AttnRes）之上。KDA 为扩展注意力提供了高效的基础，AttnRes 则在深度方向上按需检索表示，而不是统一累加。两者共同构成这个模型的架构主干，使其可扩展性远超万亿参数级。

Kimi K3 采用 Stable LatentMoE，896 个专家中实际激活 16 个。在这样高的稀疏度下，路由与优化成了首要难题。Quantile Balancing 直接从 router 分数的分位数推导专家分配，省去了启发式更新和一个敏感的平衡超参数；Per-Head Muon 则通过独立优化各个注意力 head 来扩展 Muon，在大规模训练中实现更自适应的学习。Sigmoid Tanh Unit（SiTU）和 Gated MLA 分别改善了激活控制与注意力选择性。这些进展共同支撑起 2.8 万亿参数规模下稳定而高效的训练。

Kimi K3 从 SFT 阶段起就采用量化感知训练，权重使用 MXFP4、激活使用 MXFP8，以获得广泛的硬件兼容性。为避免专家不均衡在大规模专家并行下拖累吞吐，我们引入了一种完全均衡的专家并行训练方法，形状静态化，且关键路径上没有 host 同步。由于推理效率同样受益于更大的高带宽通信域，我们建议在配备 64 个及以上加速器的超节点配置上部署 Kimi K3。最后，由于 KDA 给传统 prefix caching 带来了新挑战，我们已向 vLLM 社区贡献了相应实现，将随模型一同发布。借助带 prefill cache 的 KDA，尽管模型规模庞大、上下文很长，我们仍能以极具竞争力的 token 价格提供 Kimi K3 服务。

更多技术细节将在我们即将发布的技术报告中提供。

### 编程基准

- **DeepSWE。** Kimi K3 使用 Kimi Code harness 评测。GLM-5.2 的分数取自 GLM-5.2 发布博客（[https://z.ai/blog/glm-5.2](https://z.ai/blog/glm-5.2)）；其余分数均来自官方 DeepSWE 排行榜（[https://deepswe.datacurve.ai/](https://deepswe.datacurve.ai/)），在该榜上 Kimi K3 使用 mini-SWE-agent harness 取得 67.3。我们报告的是 DeepSWE v1.1 任务。
- **Terminal-Bench 2.1。** Kimi K3 使用 Kimi Code harness 评测。对于其他所有模型，我们报告其在各 harness 中的最佳成绩：GLM-5.2 使用 Claude Code（[https://z.ai/blog/glm-5.2](https://z.ai/blog/glm-5.2)）；Claude Opus 4.8 和 Claude Fable 5 使用 Terminus 2（[https://artificialanalysis.ai/evaluations/terminalbench-v2-1](https://artificialanalysis.ai/evaluations/terminalbench-v2-1)）；GPT 5.5 和 GPT 5.6 Sol 使用 Codex（[https://openai.com/index/previewing-gpt-5-6-sol/](https://openai.com/index/previewing-gpt-5-6-sol/)）。
- **Program Bench。** Kimi K3 使用 Kimi Code harness 评测。GLM-5.2 的分数来自 [https://z.ai/blog/glm-5.2](https://z.ai/blog/glm-5.2)；其余分数来自 [https://www.vals.ai/benchmarks/programbench](https://www.vals.ai/benchmarks/programbench)。
- **SWE Marathon。** Kimi K3、Claude Opus 4.8 和 Claude Fable 5 使用 Claude Code harness 评测；GPT-5.6 Sol 使用 Codex harness 评测。GLM-5.2 的分数来自 [https://z.ai/blog/glm-5.2](https://z.ai/blog/glm-5.2)。我们的评测基于官方 v1.1 任务的 H20 校准分支（[https://www.swe-marathon.org/](https://www.swe-marathon.org/)）：GPU 任务的 Docker 镜像、性能门槛和参考 oracle 已按 H20 重新校准，而正确性与反作弊校验器保持不变。此外，在我们的评测中，Claude Fable 5 有 35% 的任务触发了 fallback，这可能对其测得的性能产生了负面影响。
- **FrontierSWE。** Kimi K3 使用 Kimi Code harness 评测，GPT-5.6 Sol 使用 Codex harness 评测；其余结果均来自 [https://www.frontierswe.com/](https://www.frontierswe.com/)。Dominance 分数是用官方评测脚本从原始分数重算得到的，截至 2026 年 7 月 16 日。
- **PostTrain Bench。** GLM-5.2、GPT-5.5 和 Claude Opus 4.8 的分数沿用官方 PostTrainBench（[https://posttrainbench.com/](https://posttrainbench.com/)）的结果。Kimi K3、Claude Fable 5 和 GPT-5.6 Sol 使用官方 Harbor 实现、以最大推理强度评测，在 H20 GPU（而非官方设置中的 H100）上取三次运行的平均值——其中 Kimi K3 和 Claude Fable 5 使用 Claude Code harness，GPT-5.6 Sol 使用 Codex harness。
- **MLS Bench Lite。** Kimi K3 使用 Kimi Code harness 评测；GLM-5.2 和各 Claude 模型使用 Claude Code harness；GPT-5.5 和 GPT-5.6 Sol 使用 Codex harness。
- **KCB 2.0。** Kimi K3 同时使用 Kimi Code 和 Claude Code harness 评测；GLM-5.2、Claude Opus 4.8 和 Claude Fable 5 使用 Claude Code harness；GPT-5.5 和 GPT-5.6 Sol 使用 Codex harness。除 GPT-5.5 使用「xhigh」设置外，所有模型都在最大推理强度下评测。另需说明，在这项自研基准上，有 10% 的任务触发了 GPT-5.6 Sol 的 cyber guard。

- **PerceptionBench。** PerceptionBench（[https://www.kimi.com/blog/perception-bench](https://www.kimi.com/en/blog/perception-bench)）是一项聚焦原子级视觉感知能力的基准。

## 局限

- **对思考历史的敏感。** K3 在保留思考历史的模式下训练。如果 agent harness 未能按要求回传全部历史思考内容，或者把一个正在进行的、使用其他模型的会话切换到 K3，生成质量可能变得非常不稳定。我们建议使用已验证兼容的 harness，例如 Kimi Code，并避免在会话中途切换到 K3。
- **主动性过强。** K3 的训练格外强调长程、高难任务。因此，当它在执行任务途中遇到小问题或用户意图不明确时，可能替用户做出意料之外的决定。如果你的应用要求 agent 在明确边界内运作、不要过度即兴发挥，请在 system prompt 或 `AGENTS.md` 中对 K3 施加更明确的行为约束。
- 尽管 K3 整体上是一款极具竞争力的模型，但与 Claude Fable 5 和 GPT 5.6 Sol 相比，它在用户体验上仍有明显差距。
