# Kimi K2.5：视觉 agentic 智能

今天，我们发布 Kimi K2.5——迄今为止最强大的开源模型。

Kimi K2.5 在 Kimi K2 的基础上继续预训练，用了约 15T 视觉与文本混合 token。作为原生多模态模型，K2.5 在**编码与视觉**两方面都达到业界领先水平，并带来自主调度的 **agent swarm** 范式。

面对复杂任务，Kimi K2.5 可以自主调度一个由最多 100 个子 agent 组成的 **agent swarm**，在最多 **1,500** **次工具调用**中并行执行工作流。与单 agent 配置相比，执行时间最多缩短 **4.5 倍**。这个 agent swarm 由 Kimi K2.5 自动创建并编排，不需要任何预定义的子 agent 或工作流。

Kimi K2.5 可通过 **[Kimi.com](https://www.kimi.com/en)、Kimi App、[API](https://platform.kimi.com/) 与 [Kimi Code](https://www.kimi.com/code/en)** 使用。Kimi.com 与 Kimi App 现支持 4 种模式：K2.5 Instant、K2.5 Thinking、K2.5 Agent 和 K2.5 Agent Swarm（Beta）。Agent Swarm 目前在 Kimi.com 上处于 beta，高等级付费用户可获得免费额度。

## 2. Agent Swarm

**向外扩，而不只是往上堆。** 我们以研究预览形式发布 **[K2.5 Agent Swarm](https://www.kimi.com/en/agent-swarm)**，标志着从单 agent 扩展转向自主调度、协同的群体式执行。

K2.5 使用 Parallel-Agent Reinforcement Learning（PARL）训练，学会自主调度由最多 **100 个子 agent** 组成的 agent swarm，在**最多 1,500 个协同步骤**中执行并行工作流，且不需要预定义角色或手工编排的工作流。

PARL 用一个***可训练的 orchestrator agent*** 把任务拆成可并行的子任务，每个子任务由动态实例化的***冻结子 agent*** 执行。与串行 agent 执行相比，并发运行这些子任务能显著降低端到端延迟。

训练一个可靠的并行 orchestrator 并不容易，因为各子 agent 独立运行，反馈是延迟的、稀疏的、非平稳的。一种常见的失败模式是**串行坍缩**：orchestrator 明明有并行能力，却退化为单 agent 执行。为此，PARL 采用*分阶段奖励塑造*，在训练早期鼓励并行，随后逐步把重点转向任务成功。

我们把奖励定义为

$r_{\mathrm{PARL}}(x, y) = \lambda_1 \cdot \mkern-26mu \underbrace{r_{\text{parallel}}}_{\text{instantiation reward}} \mkern-9mu + \mkern18mu\lambda_2 \cdot \mkern-32mu\underbrace{r_{\text{finish}}}_{\text{sub-agent finish rate}} +
\underbrace{r_{\text{perf}}(x, y)}_{\text{task-level outcome}}
\, .$

性能奖励 $r_{\text{perf}}$ 衡量在给定任务 $x$ 上解决方案 $y$ 的整体成功度与质量。在此基础上再加两个辅助奖励，各自针对学习并行编排中的一项不同难题。奖励 $r_{\text{parallel}}$ 用来缓解*串行坍缩*——即 orchestrator 退化为单 agent 执行的那个局部最优。通过激励子 agent 实例化，这一项鼓励模型探索并发的调度空间。$r_{\text{finish}}$ 奖励关注被分配的子任务是否成功完成，用来防止*虚假并行*：这是一种 reward hacking 行为，orchestrator 通过大量派生 subagent、却不做有意义的任务拆解，把并行指标迅速刷高。通过奖励已完成的子任务，$r_{\text{finish}}$ 约束了可行性，并把策略引向有效且真正可用的拆解。超参数 $\lambda_1$ 与 $\lambda_2$ 在训练过程中退火到零。

为了进一步逼出并行策略，我们引入一个计算瓶颈，让串行执行变得不切实际。我们不再统计总步数，而是用**关键步数（Critical Steps）**衡量性能——这是一个面向延迟的指标，灵感来自并行计算中的关键路径：

$\text{CriticalSteps} = \sum_{t=1}^{T} \left( S_{\text{main}}^{(t)} + \max_{i} S_{\text{sub},i}^{(t)} \right)$

$S_{\text{main}}^{(t)}$捕捉编排开销，而 $\max_{i} S_{\text{sub},i}^{(t)}$ 反映每个阶段最慢的子 agent。在这个指标下，派生更多子任务只有在缩短关键路径时才有帮助。

![Kimi K2.5 Agent Swarm 架构图：Orchestrator 动态创建任务并分派给专用子 agent 并行执行](https://statics.kimi.ai/blogs/k2-5/orchestrator-1.png)

> agent swarm 中有一个 orchestrator，它动态创建专用 subagent（例如 AI Researcher、Physics Researcher、Fact Checker），并把复杂任务拆成可并行的子任务，以实现高效的分布式执行。

![Kimi K2.5 的训练指标：在强化学习过程中，Training Accuracy 与 Average Parallelism 随 RL flops 稳步上升](https://statics.kimi.ai/blogs/k2-5/20260126-225846.png)

## 3. 办公生产力

Kimi K2.5 把 agentic 智能带进**真实世界的知识工作**。

**[K2.5 Agent](https://www.kimi.com/en)** 能**端到端处理高密度、大规模的办公工作**。它对体量大、密度高的输入做推理，协调多步工具调用，直接通过对话交付专家级产出：文档、电子表格、PDF 和幻灯片。

围绕真实职业任务，我们设计了两套**内部专家生产力基准**。**AI Office Benchmark** 评估端到端的 Office 产出质量，**General** **Agent Benchmark** 则对照人类专家表现，衡量多步、生产级工作流。在这两套基准上，**K2.5 相对 K2 Thinking 分别提升 59.3% 与 24.3%**，体现出在真实任务上更强的端到端表现。

## 脚注

**1. 通用测试细节**

- Kimi K2.5 与 DeepSeek-V3.2 开启 thinking 模式，Claude Opus 4.5 开启 extended thinking 模式，GPT-5.2 使用 xhigh reasoning effort，Gemini 3 Pro 使用 high thinking level，以上为报告的结果。视觉基准上，我们额外报告 Qwen3-VL-235B-A22B-Thinking 的结果。
- 除另有说明，Kimi K2.5 的所有实验均使用 temperature = 1.0、top-p = 0.95、上下文长度 256k token。
- 没有公开分数的基准，在与 Kimi K2.5 相同的条件下重新评测，并以星号（*）标注。
- 受服务稳定性问题影响，我们无法在所有基准上评测 GPT-5.2 xhigh。未测试的基准标记为“-”。

**2.** **文本与推理**

- HLE、AIME 2025、HMMT 2025（2 月）、GPQA-Diamond 和 IMO-AnswerBench 的评测使用 96k token 的最大完成预算。
- AIME 与 HMMT 的结果为 32 次运行的平均（avg@32）；GPQA-Diamond 为 8 次运行的平均（avg@8）。
- HLE 我们报告全集（文本与图像）上的分数。Kimi K2.5 在不使用工具时得 31.5（文本）和 21.3（图像），使用工具时得 51.8（文本）和 39.8（图像）。DeepSeek-V3.2 的分数对应其纯文本子集（以 † 标注）。为防止潜在的数据泄漏，Hugging Face 的访问被屏蔽。带工具的 HLE 使用简单的上下文管理：上下文一旦超过阈值，只保留最近一轮工具消息。

**3.** **工具增强 / agentic 搜索**

- 在带工具的 HLE 以及所有 agentic 搜索基准中，Kimi K2.5 配备了 search、code-interpreter 和 web-browsing 工具。
- 除 BrowseComp（K2.5 与 DeepSeek-V3.2 采用 discard-all 策略）外，未施加任何上下文管理，超出支持上下文长度的任务直接计为失败。
- 测试用的 system prompt 强调深入、主动地使用工具，要求模型仔细推理、善用工具、对不确定的信息做核验。完整 prompt 将在技术报告中提供。
- Seal-0 与 WideSearch 的结果为四次运行的平均（avg@4）。

**4.** **视觉基准**

- Max-tokens = 64k，取三次运行的平均（avg@3）。
- ZeroBench（带工具）使用 max-tokens-per-step = 24k、max-steps = 30 进行多步推理。
- MMMU-Pro 遵循官方协议，保留输入顺序并将图像前置。
- GPT-5.2-xhigh 约有 10% 的失败率（重试 3 次仍无输出），按错误处理；因此报告分数很可能低估了真实表现。
- WorldVQA 是一个用于评测以视觉为中心的原子级世界知识的基准。访问地址：[https://github.com/MoonshotAI/WorldVQA](https://github.com/MoonshotAI/WorldVQA)。
- OmniDocBench 分数按（1 − 归一化 Levenshtein 距离）× 100 计算，分数越高表示准确度越好。

**5.** **编码任务**

- Terminal-Bench 2.0 的分数使用默认 agent 框架（Terminus-2）和随附的 JSON 解析器获得。在我们的实现中，Terminal-Bench 2.0 是在 non-thinking 模式下评测的；这样选择是因为我们当前针对 thinking 模式的上下文管理策略与 Terminus-2 不兼容。
- 对于 SWE-Bench 系列评测（含 verified、multilingual 和 pro），我们使用了内部开发的评测框架。该框架包含一组最小工具——bash 工具、createfile 工具、insert 工具、view 工具、strreplace 工具和 submit 工具——以及针对任务定制的 system prompt。最高分在 non-thinking 模式下取得。
- Claude Opus 4.5 在 CyberGym 上的分数是在 non-thinking 设置下报告的。
- 编码任务的所有报告分数均为 5 次独立运行的平均。

**6.** **长上下文基准**

- AA-LCR：分数取三次运行的平均（avg@3）。
- LongBench-V2：使用相同的 prompt，输入上下文统一为约 128k token。

**7.** **Agent Swarm**

- BrowseComp（Swarm 模式）：主 agent 最多 15 步；子 agent 最多 100 步。
- WideSearch（Swarm 模式）：主 agent 与子 agent 最多 100 步。
