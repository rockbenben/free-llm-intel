## Agent Swarm，再进一步

**向外扩，而不只是往上堆。** Agent Swarm 把任务动态拆成异构子任务，由它自己创建的领域专用 agent 并发执行。

在 K2.5 Agent Swarm 研究预览的基础上，[Kimi K2.6 Agent Swarm](https://www.kimi.com/en/agent-swarm) 在 agent swarm 体验上实现了**质变**。它无缝协调异构 agent，把互补的能力组合起来：广度搜索叠加深度研究，大规模文档分析与长文写作融合，多格式内容生成并行推进。这种组合式智能让 swarm 在一次自主运行中就能交付端到端产出——涵盖文档、网站、幻灯片和电子表格。

该架构可横向扩展到 **300 个子 agent，同时跨越 4,000 个协同步骤执行**，相比 K2.5 的 100 个子 agent 和 1,500 个步骤是一次大幅扩张。这种大规模并行从根本上降低了端到端延迟，同时显著提升产出质量，并拓展了 agent swarm 的运行边界。

它还能把 PDF、电子表格、幻灯片和 Word 文档等任何高质量文件转成 **Skills**。Kimi K2.6 会捕捉并保留文档的结构与风格“DNA”，让你在后续任务中复现同样的质量与格式。

## 自带你的 agent

在 Kimi K2.6 强大的编排能力之上，我们以研究预览形式把你的主动型 agent 扩展到 **Claw Groups**——这是 Agent Swarm 架构的一种新实例。

Claw Groups 拥抱开放、异构的生态：多个 agent 与人类作为真正的协作者一起工作。用户可以从任何设备接入 agent、运行任何模型，每个 agent 都带着自己的专用工具集、skills 和持久记忆上下文。无论部署在本地笔记本、移动设备还是云实例上，这些各不相同的 agent 都能无缝融入同一个共享操作空间。

在这个 swarm 的中心，Kimi K2.6 充当自适应的协调者。它依据各 agent 具体的技能画像和可用工具，动态地把任务匹配给合适的 agent，以能力契合度做优化。当某个 agent 失败或卡住时，协调者能察觉这次中断，自动重新分配任务或重新生成子任务，并主动管理交付物的整个生命周期——从启动、校验直到完成。

我们也要感谢 Claw Groups 中由 K2.6 驱动的那些 agent——我们一直在实践中打磨人机协作流程，把自己那支 agent 营销团队当作试验田。借助 Claw Groups，我们跑端到端的内容生产与发布活动，由 Demo Makers、Benchmark Makers、Social Media Agents、Video Makers 等专用 agent 协同工作。K2.6 协调整个流程，让 agent 之间共享中间结果，把想法变成一致的、完整打包的交付物。

我们正在走出“向 AI 提一个问题”或“给 AI 派一个任务”的阶段，进入人与 AI 作为真正伙伴协作的时期——把各自的长处合起来共同解决问题。Claw Groups 是我们为实现这样一个未来所做的最新努力：在那里，“我的 agent”“你的 agent”与“我们的团队”之间的边界会自然地融进同一个协作系统。

**2. 推理基准**

**3. 工具增强 / agentic 任务**

- 在带工具的 HLE、BrowseComp、DeepSearchQA 和 WideSearch 中，Kimi K2.6 配备了 search、code-interpreter 和 web-browsing 工具。
- 带工具的 HLE-Full 最大生成长度为 262,144 token，单步上限 49,152 token。我们采用简单的上下文管理策略：一旦上下文窗口超过阈值，只保留最近一轮与工具相关的消息。
- BrowseComp 报告的是在上下文管理下取得的分数，采用与 Kimi K2.5、DeepSeek-V3.2 相同的 discard-all 策略。
- DeepSearchQA 上，Kimi K2.6 的测试未施加任何上下文管理，超出支持上下文长度的任务直接计为失败。Claude Opus 4.6、GPT-5.4 和 Gemini 3.1 Pro 在 DeepSearchQA 上的分数引自 [Claude Opus 4.7 System Card](https://cdn.sanity.io/files/4zrzovbb/website/037f06850df7fbe871e206dad004c3db5fd50340.pdf)。
- WideSearch 报告的是“hide tool result”上下文管理设置下的结果。一旦上下文窗口超过阈值，只保留最近一轮与工具相关的消息。
- 测试用的 system prompt 与 [Kimi K2.5 technical report](https://arxiv.org/pdf/2602.02276) 中使用的完全相同。
- Claw Eval 使用 1.1 版进行，max-tokens-per-step = 16384。

**4. 编码任务**

- Terminal-Bench 2.0 的分数使用默认 agent 框架（Terminus-2）和随附的 JSON 解析器获得，运行在 preserve thinking 模式下。
- 对于 SWE-Bench 系列评测（含 Verified、Multilingual 和 Pro），我们使用了从 SWE-agent 改造而来的内部评测框架。该框架包含一组最小工具——bash 工具、createfile 工具、insert 工具、view 工具、strreplace 工具和 submit 工具。
- 编码任务的所有报告分数均为 10 次独立运行的平均。
