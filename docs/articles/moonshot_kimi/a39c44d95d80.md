# 介绍 Kimi K3.1 Pro

我们正在推出 **Kimi K3.1 Pro**，这是我们新 K3.1 系列中的第一个模型，也是我们迄今为止功能最强大的 3T 级开放重量模型，具有 100 万代币上下文窗口。它在编码、3D 创建、金融研究和其他代理功能方面提供了重大改进。

我们还发布了 **Kimi K3.1 Pro Highspeed**，其速度是 K3.1 Pro 的 2-3 倍，可实现更灵敏的交互。

Kimi K3.1 Pro 和 Kimi K3.1 Pro Highspeed 现已在 [Kimi.com](https://www.kimi.com/en)、[Kimi Work](https://www.kimi.com/en/products/kimi-work)、[Kimi Code](https://www.kimi.com/code/en) 和 [Kimi API](https://platform.kimi.com/) 上提供。完整的模型重量将于 11 月 4 日发布。

## 推进开放智能前沿

Kimi K3.1 Pro 是 Kimi K3 的后训练版本，具有更大的后训练计算量。为了实现跨**数百个下游域**的大规模联合强化学习，我们优化了堆栈的每一层——强化学习框架、长上下文推理、训练效率、沙箱基础设施、部署调度和用于环境质量检查的共享平台——以便强化学习计算的每次增量都能提供稳定、可预测的回报。因此，K3.1 Pro 在各个领域都取得了一致的收益。

在编码、代理和知识基准方面，K3.1 Pro 匹配或接近最强的专有模型。 **Terminal-Bench 4.0** 使用严格的特定任务测试来评估实际的、资源受限的终端任务上的编码代理，**K3.1 Pro 得分为 65.7%，领先于 GPT-6 Astra (58.2%)，并以微弱优势落后于 Claude Opus 5.5 (66.4%)**。在 **Kimi Code Bench 3.0 Long-horizo​​n**（我们的内部基准测试，测试编码代理跨不同工程领域的多步骤执行、工具使用和端到端问题解决）上，K3.1 Pro 得分 **61.2%**，高于 K3 的 **55.95%**。

## 网络安全

随着 K3.1 Pro 的能力变得越来越强大，我们相应地投入了更多的精力来了解网络能力从何而来，以及我们可以控制多少。因此，我们分析和评估了K3.1 Pro的漏洞研究能力，并在训练过程中进行了有针对性的控制，以减少潜在的误用风险，同时保持通用性。

**识别和删除网络相关数据。** 在开发过程中，我们观察到漏洞研究性能随着训练后规模的扩大而稳步提高。追踪这一趋势的根源，我们发现网络相关内容嵌入在一般的中期训练语料库中，而网络相关任务则存在于 RL 环境组合中——这是广泛数据训练的自然副产品。在内部模型的初步实验中，我们发现，如果在训练中期或强化学习阶段不删除数据，下游网络能力将大幅增强。这些发现为我们提供了具体的控制杠杆。对于 K3.1 Pro 的开放权重版本，我们从两个训练阶段识别并删除了网络相关数据，同时保留了模型实用性所需的通用编码任务。我们将继续在每个培训阶段应用适当的控制，其中与网络相关的数据识别和限制就是一个例子。

**评估和结果。** 数据清理后，我们在 xdev-bench-hard 上评估了 K3.1 Pro，xdev-bench-hard 是我们专家策划的、基于源代码的漏洞发现和利用任务的内部基准，经过校准以在我们当前的能力水平上提供有意义的差异化。大多数任务忠实地重现了最近披露的 Linux 内核、Node.js、JavaScriptCore、Exim 和 VirGL 等软件中的漏洞，并启用了缓解措施。每个任务都提供易受攻击的源代码、简短的错误提示以及相应的二进制文件；代理必须开发漏洞，在单独的沙箱中实现任意代码执行，并检索秘密字符串以进行自动验证。我们在运行的随机子集上报告 pass@3，没有硬超时或输出令牌限制。

![内部xdev-bench-hard（pass@3）结果：GPT-5.6 Sol（第三方评估）解决了100个问题，无网络风险降低的Kimi模型90.5，DeepSeek-V4.1-Flash 85.7，Kimi K3.1 Pro 81.0，GLM-5.3 57.1和Kimi K3 33.3，平均成功率和每次成功的平均代币每个的轨迹](https://statics.kimi.ai/kimi-blogs/kimi-k3-1/20261023/xdev-bench-hard-results.webp)![](https://statics.kimi.ai/kimi-blogs/kimi-k3-1/20261023/xdev-bench-hard-results.webp)

在 xdev-bench-hard 上，没有这些风险降低措施的检查点（在训练中期没有删除与网络相关的数据，也没有与网络相关的 RL 环境过滤）在 pass@3 时解决了 90.5% 的问题；最终K3.1 Pro达到81.0%。比较表明，相对于相同训练管道原本产生的能力，数据删除会显着降低网络能力。与此同时，K3.1 Pro 比其前身有了很大改进，这表明即使在有针对性的数据删除之后，更强大的通用编码和长期调试能力也适用于网络任务。 K3.1 Pro的网络能力仍然落后于已公开发布至少三个月的前沿专有型号。我们将不断发展我们的内部基准，以便随着模型功能的不断进步，评估仍能提供丰富的信息。

**开放重量原则。** 这些评估构成了我们的开放重量发布决策。首先，我们的目标是不发布会扩展网络能力绝对边界的开放权重。从设计上来说，K3.1 Pro 的进攻性网络能力低于我们的管道所能产生的能力，并且仍然落后于前沿专有模型。其次，我们打算逐步提高开放权重中可用的网络能力。我们相信，以非歧视的方式提供 K3.1 Pro 将使那些需要双重用途功能用于防御目的的人们受益。当一个有能力的模型开放并在用户控制的基础设施上运行时，更多的团队可以获得审核他们维护的代码的方法——包括很少接受专门安全审查的遗留系统。我们相信，让这种能力逐渐扩散——而不是将其集中在几个专有系统中——最终会让所有软件变得更加安全。
